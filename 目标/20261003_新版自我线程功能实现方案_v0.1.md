## 1. 目标和实施原则

让 `新_自我线程类` 在现有初始化与常驻线程基础上，通过处理消息完成需求复核、需求治理决策、任务交接、执行前判断、结果处理和持续治理。

自我线程自身能力是内部治理闭环的一部分。线程负责调用服务、核验返回、形成决策和交接；需求、任务、方法、世界事实的结构操作由相应服务完成。任务管理线程推进任务、安排工作；工作线程执行方法。各部分的实现和验收分别说明。

实施顺序遵循用户确定的方式：

```text
先写一个上层业务处理函数
→ 遇到实际需要的下层能力
→ 已有则复用，缺少则补该直接依赖
→ 回到原处理函数完成成功和失败分支
→ 核验本条链
→ 再处理下一项能力
```

不要求先建完所有下层服务再编写 self。确实需要占位时，函数前标注“待实现”，返回明确的缺依赖结果；占位不能使初始化、需求判断或任务执行被报告为成功。

本方案的近期可用结果是“消息进入新版 self，self 重新读取需求与当前值并给出可取得的处理结果”；后续再接通任务管理。初始化后首次复核是线程内部启动步骤，不伪造一条“开始需求复核”业务消息。

## 2. 采用的口径及旧材料取舍

| 项目 | 新版采用的口径 |
| --- | --- |
| 自我身份 | 世界树中的唯一存在节点；节点稳定编码就是身份，不增加 self 运行代次或逻辑身份 |
| 初始化 | 在 `新_自我线程类::初始化()` 中编排世界根、自我所在场景、自我存在、需求树、安全/服务双根和方法根；具体结构调用服务建立 |
| 初始化与 OS 线程 | 当前 `初始化()` 在调用线程中完成，随后 `启动()` 创建 OS 线程；“自我线程类负责初始化”不表示已经在 OS 工作线程内执行初始化 |
| 独立根 | 需求树、方法组织根独立存在，不挂入世界树；安全/服务根需求不绑定物理持有者 |
| 需求与任务 | 一个任务对应一个需求；需求表达一个目标状态改变，允许目标是复合状态；任务分解通过子需求表达 |
| 任务组织 | 使用新版扁平任务集合和任务虚拟存在的状态特征；不建立任务父子树，不恢复任务轮次或筹办轮次 |
| 方法 | 沿用新版本能/组合、内部治理/普通方法及条件结果分支结构；组合方法允许按已确认规则循环 |
| 参数场景 | 调用期只读引用容器，读取世界节点当前信息；不改成旧方案的持久参数快照 |
| 消息 | 按实际用途分类并交给对应函数；不因安全/服务单根或双根拆成复杂消息协议；一个结果可触发多个受影响需求的复核 |
| 退出 | 独立、仅进程内的控制信号，不占治理邮箱容量 |
| 当前读取 | 按业务所需完整范围读取当前信息；不恢复事实代次、历史 H 读取、合同版本或底层数量预算 |
| 调度 | 需求权重来自需求服务；任务优先级及工作调度归任务管理线程，不在 self 重建第二调度器 |
| 旧技术结构 | 旧不可变任务初始化包、三轮次冻结和完成结算不能原样作为新版默认前置；需要保留的业务目的须在实际接入时用新版结构表达 |

保留旧规范中有益的职责：消息只作定位、读取当前事实、失败不伪装业务成功、重复通知不重做动作、任务完成与需求满足分开、安全硬否决不能被收益抵销。

旧方案中的具体初始化顺序、轮次字段、历史恢复和单根/双根消息分支已经与后续用户裁决不一致，不能用于重新引入已取消机制。旧材料是职责和风险来源，不是新版接口清单。

## 4. 职责及函数组织

以下函数名是建议的私有职责划分，不是已经存在的公开 C++ 签名。仅在施工到对应阶段时确定必要 DTO 和最小公开入口。

| self 职责/建议函数 | 输入来源 | 输出与边界 |
| --- | --- | --- |
| `提交消息`、`分派消息` | 已建立来源的业务通知、任务管理请求 | 接收回执；按类型调用唯一处理函数 |
| `复核当前需求` | 需求节点与当前世界信息 | 满足、不满足及差异、缺材料或错误；不凭消息自带值判断 |
| `处理事实变化通知` | 世界服务已完成更新后的定位 | 查找受影响需求并逐项重读；不把原始外设数据直接写入世界 |
| `形成任务承接意图` | 一个当前有效且需要治理的具体需求 | 向 manager 提交该需求的承接意图；入队不等于任务建立 |
| `处理任务材料通知` | 任务、方法条件或缺口定位 | 无需新目标、等待、结构缺口、独立必要目标；不把技术失败生成需求 |
| `确认并建立后继需求` | 父任务、父需求、具体新目标 | 调用新版任务/需求服务发布并读回；来源形式先解决当前占位缺口 |
| `处理执行前判断请求` | 任务管理发出的任务、执行方法与必要材料定位 | 允许、暂缓、拒绝、重新判断或缺依赖；不在 self 查找并执行方法 |
| `处理任务结果通知` | 任务状态、执行实例及影响评估定位 | 读取实际变化，复核受影响需求，形成必要后继意图 |
| `决定未完成任务后继` | 当前需求、任务状态、实际结果与等待条件 | 继续、等待、挂起或取消意图；manager调用领域服务推进状态 |
| `复核安全与服务需求` | 当前特征、目标和已具备的安全业务规则 | 复核与调用适用治理服务；不从线程循环次数生成数值 |
| `恢复未完成交接` | 原消息、原操作及已经读回的结果 | 补交/查询尚未完成步骤；不重复创建任务或执行动作 |

物理位置建议：

- `海中鱼巣/线程/新_自我线程类.h/.cpp`：生命周期、邮箱、分派及 self 判断编排。
- `海中鱼巣/业务/新_世界树类.h/.cpp`：扩展实际需要的综合语义读取/复核入口，结构树仍保持各自独立。
- `海中鱼巣/领域/新_需求类.h/.cpp`：需求目标、当前满足、权重、活动状态、普通需求来源和建立。
- `海中鱼巣/领域/新_任务类.h/.cpp`：任务数据、状态操作、方法执行信息、影响评估和子需求调用。
- `海中鱼巣/领域/新_方法类.h/.cpp`及既有方法文件：方法结构、条件结果、实际参数及相应能力。
- 新版任务管理接入位置、生产宿主持有关系：进入任务交接阶段时依据现存线程与装配确定，不提前恢复旧 ABI 或创建空壳线程。

self不直接操作基础数据集节点、关系和值，不复制需求/任务事实。上层先出现真实调用需要，下层才增加对应函数；本方案不要求为所有远期职责预先建立接口。

## 5. 消息和单次处理合同

### 5.1 业务消息候选

| 用途 | 来源与发送方 | 接收处理 | 处理结果 |
| --- | --- | --- | --- |
| 事实变化通知 | 真实世界更新已完成后，由负责更新的上层调用链发送 | self重新读当前信息、定位受影响需求 | 逐需求复核结果和必要意图 |
| 任务材料/缺口通知 | manager读取任务服务材料后发送 | self判断是否需要独立后继目标 | 无需、等待、结构缺口或确认目标 |
| 执行前判断请求 | manager准备推进具体方法执行时发送 | self核验当前目标、对象、影响及可用规则 | 判断结果及依据 |
| 任务结果/状态通知 | manager完成任务结果处理后发送 | self重读任务、执行实例和影响评估 | 受影响需求复核、后继决议或终结处理 |

这些是业务用途划分；精确类型只随真实生产者接入，不先创建全部空消息。首个具名消息建议选择事实变化通知，先接通自我安全/服务特征变化后的需求复核。任务完成可能同时影响安全和服务，不按根数量拆消息，也不限定只处理任务原目标涉及的特征。

外部“要求复核”的控制入口如确有调用者可以单独设计，不能为驱动循环而制造没有来源的业务消息。线程健康、启动、停止等属于工程控制；原始外设报告先由其业务入口处理。

### 5.2 邮箱与结果交接

1. 消息只保存类型、必要来源定位和关联请求，不携带另一份权威需求或任务状态。
2. 接纳、处理中、延后重试和等待依赖的活动消息合计不超过配置容量；同一消息只计一次。容量和等待时限来自普通应用具名运行配置，不是数据查询预算。
3. 在队列锁内取出工作，锁外调用服务。活动消息只有一个推进位置，重试不重新计作新接纳。
4. 同身份同内容重投不重复推进；同身份异义拒绝新输入，不能删除原来合法接纳的消息。终结后的重复处理依靠领域当前结果与相应幂等能力，不承诺无限缓存全部消息身份。
5. 接收回执与处理终结结果分别提供。处理结果绑定原消息，可由调用者取得；建议使用有界进程内结果通道。结果未交付时的容量占用、确认回收和投递失败处理须与首个消息入口一起闭合，不能只覆盖“最近错误”。
6. 一次处理只按顺序尝试必要步骤一次。遇到非成功立即返回分类结果；已完成前段保存定位，下一次继续剩余步骤。
7. 单纯等待、超时或伪唤醒不证明业务就绪。依赖唤醒使用受锁保护的条件，通知先于等待也能被观察到。

### 5.3 非成功分流

| 情况 | 行为 |
| --- | --- |
| 已处理/领域精确重复 | 交付结果，按结果通道约定回收本条活动容量 |
| 资源暂不可用 | 保留原请求和进度，等待可中断重试；不在处理函数内无限循环 |
| 依赖未就绪 | 保留材料，等待有明确生产者的唤醒并重新读取 |
| 依赖未实现 | 返回具名缺口；定时器不能把缺失函数变成成功 |
| 输入非法或异义冲突 | 拒绝该输入并反馈，不永久放回队首 |
| 已完成前段、后段失败 | 如实返回阶段结果；不宣称整条链零写入，不删除已成立事实 |
| 下层结果不确定 | 只在下层具有查询合同的范围按原请求核对；无查询能力则报告缺口，不换请求重新执行 |
| 内部结构不一致 | 停止受影响分支；线程共享控制状态不可信时终止线程并保留退出能力 |

停止期间关闭新业务接纳，唤醒可中断等待，处理已接纳消息的明确终结/交接。同步服务只能在其合同允许时返回或取消，不能承诺强行打断。加入 manager 双向通道时重新确定关闭顺序，保证接收者和服务依赖活到最后一次回传及 join 完成。

## 6. 分阶段实现与完成条件

各阶段是本方案的实现顺序，不是已登记的可执行计划；远期阶段只在当前真实调用需要时细化。

| 阶段 | 交付内容 | 完成条件与直接依赖 |
| --- | --- | --- |
| S0 复用既有初始化 | 保留已实现初始化和生命周期，核验新版根引用与运行配置来源 | 已有结果不倒退；明确普通应用尚未接线及未完成初始化分支 |
| S1 消息消费与首次需求复核 | 邮箱、一个真实消息分支、分派、结果交接、单次处理及需求复核；启动首次复核作为内部步骤 | 可从真实更新入口触发并取得两根各自复核结果；满足/未满足/缺值/错误/重复/队满/停止正确，不要求已有任务执行 |
| S2 具体需求到任务管理 | self发送一个需求意图，manager调用新版任务建立/查询并回传 | 精确重复不建立第二任务；入队、任务建立、任务开始执行分别表述；不引入旧初始化包 |
| S3 任务材料与子需求 | 消费具名筹办材料、判断后继目标、补齐来源核验、调用需求服务建立 | 解除 `任务来源未接通`；明确等待与技术缺口；普通目标可建立，复合目标待表达合同闭合后覆盖 |
| S4 执行前判断 | 对具体待执行活动核验目标、参数引用、方法预计影响及安全规则 | 当前条件变化时重判；材料缺失不默认允许；判断到实际执行之间由对应服务/manager再次核验，不靠旧判断永久许可 |
| S5 结果与后继 | 消费执行实例和影响评估，复核所有受影响需求，发送后继意图 | 不只检查原任务目标；每个需求实际使用时重读当前值；迟到通知不回退任务；已发生动作不重做 |
| S6 持续治理与生产接入 | 具名安全治理、可恢复交接、生产宿主装配和连续消息处理 | 依赖唯一持有、线程安全退出、真实入口可达；跨进程恢复在底座持久化及动作恢复合同具备后单独验收 |

S1建议的业务调用顺序：

```text
初始化成功，启动工作线程
→ 内部执行首次当前需求复核
→ 等待事实变化消息或独立停止控制
→ 校验消息来源和所指节点
→ 经上层服务定位受影响需求
→ 调用新_需求类::复核当前满足
→ 保留每个需求的真实结果
→ 交付消息处理结果
→ 回到等待
```

S1中即使需求未满足，也不能假装任务意图已被 manager 消费。只有 S2 的真实交接具备后，才在该分支继续调用任务承接。单条消息可导致两个根都被复核，各自结果独立保留，不把前一个成功当成整个消息成功。

## 7. 需在对应调用点解决的问题
