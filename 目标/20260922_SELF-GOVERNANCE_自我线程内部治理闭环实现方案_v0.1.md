## 1. 结论与目标

以self、manager、worker及各领域owner的真实上层消费反推服务需求。自我线程自身能力单独按消息处理分支实现；每个服务能力都必须对应一个具名调用者、一处调用时机、一个正式事实来源和一个可验证使用结果，不先建设无消费者的通用能力。

目标主链：

```text
合法启动与运行门开放
→ 等待消息或正式治理触发
→ 校验消息并定位正式来源
→ 经公开数据服务重新读取事实
→ 复核需求和整体控制条件
→ 确认必要后继目标 / 形成具体任务意图
→ 冻结后的执行前综合判断
→ 接收并独立核验正式结果
→ 完成任务结算或未完成后继处理
→ 再读当前需求
→ 返回等待
```

自我线程是唯一self决策与需求治理编排载体，不是全部内部治理的唯一编排载体，也不是新的数据存储层。manager负责任务状态推进编排，worker执行单个工作包；正式事实经各领域公开服务发布，需求事实归需求域，任务记录与完成结算归任务域，自我现实执行授权归自我业务域，安全变化归对应安全治理入口。

**硬边界：自我线程及其治理编排实现，不直接调用 DATA-L1、DATA-L2 服务函数，不获得可下钻的底层服务对象，不直接读写底层仓库、内部事务、SQL或可变节点。**

该限制不禁止合法上层服务在内部调用其正式下层公开接口；否则不能实现分层。限制的是自我消费者不能跨越公开服务边界，也不能用一个仅返回底层对象的 getter 掩盖越层调用。

实施采用自顶向下方式：先写自我线程上层当前步骤，由实际调用点反推最小下层能力。现有具名上层公开服务可以直接复用；缺少提供者时固定该调用的最小输入、输出、时机、事实来源和读回要求，建立所属下层的最小提供者目标，完成后回到原调用点继续。不得脱离已出现的上层消费者提前建设同类能力库存。

“先写上层”不等于编造底层机器语义。确需为了链接保留占位时，必须显式标注`待实现`、返回结构化未实现并保持零机器事实写入；需要真实成功才能开放的治理门不得由占位、默认值或伪成功绕过。

依据：8000 §§1—4；8100 §§2—3；8200 §§1—2；层级命名空间规则。[S1][S2][S3][S4]

## 3. 对原能力清单的必要完善

### 3.1 需求“判断”与“正式发布”分开

自我负责组织当前事实读取、确认后继目标和作治理决议。需求当前满足应调用需求域的正式应用入口，按目标合同和同一事实截止的当前值比较，必要时由需求域发布结论。DATA纯结构层不判断业务满足性。

需求目标值、方向、算法和当前采用的特征事实必须有正式来源。历史满足、任务完成、函数成功、消息中的值都不能替代当前满足。

### 3.2 后继需求不能脱离父任务材料

合法链路是：

```text
父需求与父任务正式材料
→ self重新判断并确认独立必要目标
→ task owner记录并发布self确认的子目标承接材料
→ 独立读回该材料
→ 需求owner独立读取并精确查重
→ 发布新D或精确复用D
→ 再读D、父关系、来源和目标合同
```

因此，完整需求治理依赖任务域的最小材料读取与确认记录服务。可以后接任务执行，但不能为保持分期表面整齐而删除这一依赖。仅有根扫描和比较时，只能称“根需求复核闭环”。

### 3.3 首阶段不恢复任何服务值自动规则

服务根用于读取当前值及目标比较，不自动增加、扣减、衰减，不建立服务合同、账户、额度、预支或服务值对安全值的联动。完成任务结算也不自动产生服务值或安全值。

### 3.4 现实执行授权与综合判断分开

凡正式任务进入方法执行，都需在冻结后经self综合判断；纯内部方法和无副作用观察也不能跳过这一步。只有含现实改变的冻结才产生一份正式现实执行授权。不得再添加第二正向“任务授权”或审批任务。

### 3.5 任务完成、完成结算与需求当前满足三者分账

正式完成的同一任务T只产生一次任务完成结算。需求之后再次不满足不能重开T，也不能重复结算T。失败、取消、等待和一次尝试收束不触发任务完成结算。

### 3.6 安全维护可逐步接入，安全控制门不能后补

启动和普通治理资格要读取有效安全控制来源；现实动作派发之前必须接入安全硬门。高级安全维护可以后续完善，但不能先开放现实执行、再以最后一个阶段补安全。

### 3.7 “owner”必须分清业务责任和DATA内部结构分区

DATA不根据调用者角色裁决业务权限。来源角色、自我身份、业务资格与授权由业务/治理层核验；DATA内部owner承担确定路由、结构闭包和唯一事实来源，不成为第二套业务权限系统。

依据：8000 §§5—9、8100 §3、8200 §§5、7—13及规范目录共同解释。[S1][S2][S3][S10]

## 4. 合法调用架构

### 4.1 允许的依赖

```text
自我线程：等待、停止、批次调度、调用治理函数
  │
  ├─ 自我/世界上下文公开读取服务
  ├─ 世界树公开应用/聚合服务：当前事实与所需关系读取
  ├─ 需求域公开服务：查询、目标、当前满足、发布/复用及读回
  ├─ 任务域公开服务：正式材料、self确认记录、状态/结果、完成结算
  ├─ 方法域公开只读服务：冻结引用对应的完整方法事实
  ├─ 自我业务公开服务：具名决议承接、现实执行授权及读回
  └─ 安全治理公开服务：控制态、硬门、正式维护和读回

这些上层服务内部
  → 各自合法的公开结构服务
  → 由所属结构提供者操作事实基座
```

自我与任务管理之间只通过既定异步意图/消息边界交接。自我不跨线程直接调用manager的筹办、状态推进或工作包执行函数。

世界信息经世界树公开服务组合；需求、任务、方法通过各自`ARCH-L4`服务承接，不塞进世界快照，不统一下沉至`DATA-L3`。不定义`DATA-L4/DATA-L5`。旧代码中`L2需求/L2任务/L2方法`可能是`ARCH-L4`兼容身份，但本方案仍不让自我消费者直接暴露或依赖这些兼容结构API。

### 4.2 不允许的伪分层

```text
自我线程 → 普通应用全量上下文 → 取得L2特征服务() → 底层读取
自我线程 → 世界树getter → 返回L2服务引用 → 直接调用
自我线程 → 私有包装函数 → 直接读L1关系或构造写集
自我线程 → 万能JSON/字段路径接口 → 修改Vt、安全值或需求
```

将代码搬到另一个文件不能改变调用职责。公开服务必须提供完整具名操作，而不是把内部仓库、节点指针、事务写端口或可变对象交给线程。

### 4.3 数据操作与业务操作不能混名

| 操作类别 | 责任 |
| --- | --- |
| 公开数据读取/查询 | 返回身份、关系、当前值、版本、事实截止、完整覆盖与正式来源 |
| 领域应用操作 | 依据规范判定满足、确认材料是否合法、是否允许结算等 |
| 领域记录发布 | 机械核对结构、引用、版本、唯一性和幂等后提交正式事实 |
| 工程线程/消息操作 | 生命周期、投递、等待、资源预算；不形成业务结论 |

“需求服务判定当前满足”是需求域应用操作，不是让DATA基础结构服务承担需求语义；“提交已确认子目标”也不等于task owner替self产生需求。

依据：[S1][S3][S4][S10][S11]。

| C06 | 执行具名合法安全维护 | 6100/6140各自准入的证据、时间、原请求 | 该入口允许的维护结果或无准入/技术非成功 | 对应安全服务写并读回；不由线程算变化量 |
| Q12 | 有界恢复与漏通知发现 | self/任务范围、原请求定位、正式覆盖/游标 | 完成未结算、未收口结果、未知发布等实际来源 | 从原owner事实推导；不新增持久“已处理”业务账 |

任务建立、筹办、状态迁移、方法选择冻结和工作包派发的数据写入口不授予self消费者；由manager与任务应用按自身合同调用。上表只列self确有使用路径的能力。

### 6.1 每项公开操作的共同合同

- 只携带本操作必需身份，不设计万能上下文；零动作不伪填执行身份。
- 成功业务载荷与技术状态分开。技术非成功不附带可消费的成功决议。
- 对当前读取明确非零G0、真实读取截止、内容版本和引用闭包；历史读取明确历史来源。
- 独立声明扫描对象数、节点/关系数、比较次数、消息数、材料量和操作期限预算，不临时发明全项目统一常量。
- 发布前核验失败零业务变化；发布未知保留原完整请求及幂等身份。
- 跨owner按合法段分别发布和读回，不把多步业务链伪装成整体原子事务。
- 读取结果只在其版本/截止范围内有效；不能转为线程持久权威。
- 不因预算变化随意更换业务请求身份；具体幂等字段以所属正式合同为准。

## 7. 线程生命周期、并发与资源

### 7.1 生产启动顺序

```text
普通应用宿主按8120装配正式服务
→ 建立/恢复并独立读回唯一self及必要根
→ 依8121完成本能根运行锚点发布/恢复与完整读回
→ 把锁定锚点及窄公开服务引用交给线程创建入口
→ 创建唯一自我线程，治理门关闭
→ 其余必要生产消费端就绪
→ 在新截止核验self与角色闭包
→ 独立开放运行门
→ 首轮治理
```

创建前必要锚点非成功，不创建线程；创建后的依赖失败或当前性漂移，不开门并进入正式回收路径。骨架的隔离测试可以先做，但不能把测试替身当生产启动前置已满足。

### 7.2 唯一性与停止

线程唯一性属于宿主生命周期责任。创建、开门与停止必须防竞态，已进入停止的实例不能再次开门，旧实例未join不能创建重叠治理实例。

停止先关闭新增普通治理和派发资格，再按宿主既定顺序处理在途结果、证明停止或保留原正式恢复定位，最后退出与join。自我线程本身不替manager取消任务，不把停止线程解释为安全值归零或任务失败。

停止信号走工程生命周期控制机制，不能因普通业务邮箱满而失效。join超期只报告尚未完成停止，不detach、不销毁仍被线程使用的服务、不伪报已停止。具体停止时限必须由实现合同和实测确定，本方案不承诺未经验证的数值。

### 7.3 实时性与线程分工

self线程每轮执行有界治理，不同步等待任务执行、不在其循环内找方法或跑工作包。重任务仍由任务工作线程承接，消息回接后self按正式来源裁决；数据服务自身不为本方案另建线程。

队列取出/冻结批次后释放队列锁，再调用数据服务。服务发布完成后再通知，不能拿着领域写锁等待对端消息或join。线程内只保留工程句柄、不可变定位、有限批次与本轮临时投影，不保存另一份需求/任务状态机。

服务和邮箱由宿主按明确所有权装配；生命周期覆盖全部使用它们的线程，停机回收顺序与消息生产者一致。不得以强行终止线程补偿未设计的锁顺序。

## 8. 消息与一轮治理算法

### 8.1 消息合同

共同信封定位来源角色、运行代次、不可变消息身份、操作种类和原请求关联。业务字段按任务承接、筹办缺口、冻结判断、执行结果、状态结果、结算定位和后继决议分别限定。

worker的筹办/执行原始结果发给manager；self主要消费manager独立读回后的正式状态、缺口或判断请求。生命周期观察消息不进入业务治理；退出控制不等同普通任务结果。

处理规则：

| 情况 | 处理 |
| --- | --- |
| 精确重复 | 读取所属服务既有结果，不重复发布或执行 |
| 同身份异义 | 拒绝并隔离该消息，记录冲突定位 |
| 旧运行代次 | 不据此取得执行权；实际已经发生的结果从正式恢复来源发现和处理 |
| 乱序或迟到 | 读当前状态及具名历史来源，不回退现行状态 |
| 邮箱满或投递失败 | 技术交接未完成；按既定原请求重投/查询，不变成业务等待 |
| 普通事实变化通知 | 可在不损失必要语义且有正式补扫保障时合并唤醒；不可丢失来源后伪报处理完成 |
| 无通知但有未结算完成T | 从任务服务有界查询重新发现；邮箱空不证明工作清零 |

### 8.2 一轮治理顺序

1. 响应停止控制；冻结本轮消息批次和覆盖预算，新消息留待后续批次。
2. 校验消息定位，经所属公开服务独立读回，优先处理已发生动作、结果恢复、停止材料和准入安全事实。
3. 使用正式时间/安全来源执行适用维护，读取控制态；A=0仅正式恢复/重建和停止，A=1仅具名最小治理，A>1才进入普通派发判断。
4. 在共同新G0读取双根D、目标、当前采用F与值、必要活动关系；分别调用需求当前满足/差距入口。
5. 对完整可判定范围形成主需求/根治理意图；没有正式排序依据、范围未覆盖或不可比时不伪造最终选择。
6. 消费合法父任务材料，区分无需后继、等待、结构缺口和确认新目标；需发布时执行C01→读回→C02→读回。
7. 对具体D发任务承接意图；冻结判断与状态结果按各自绑定处理，不强行共用前面已过期的G0。
8. 完成任务走同T结算；失败/取消只处理；未完成走正式后继。发布后依实际截止重新读取相关事实。
9. 用剩余明确预算进行恢复补扫或合法自检；无即时工作则等待下一消息或复核触发，不用循环次数生成收益。

预算耗尽时保存的仅是工程继续定位，下一批次需要重新核验当前性。不能把跨批次、跨截止的局部读取拼成一次完整当前成功。

### 8.3 逻辑伪代码

以下展示调用边界，不是可编译代码，也不声明仓库已有这些同名API。


## 9. 执行、结果与结算的关键合同

### 9.1 冻结后的综合判断

self通过任务服务读回同一T、需求来源、轮次、路径、实例、冻结与结果规格；通过方法只读服务核对冻结引用的方法内容版本；从世界事实与安全服务取得当前条件、目标、资源、时间和正式成本来源。

应用层分开得出执行、暂缓、拒绝、重判以及技术非成功。安全硬否决不参加可被收益抵销的加权总分。没有成本算法或并列裁决合同，不自行用稳定编码、队列顺序、名称或默认权重决胜。

现实改变时调用自我授权入口并独立读回；无副作用内部/观察任务保留综合判断，不创建现实授权。manager接收后再次核对冻结、当前性和硬门，worker临近动作再核对所需条件。失效则停止受影响调用，不能沿用旧判断继续。

### 9.2 结果两条来源

执行报告与独立实际观察必须分开。manager及任务应用按正式合同把预测符合、固定目标、禁止结果/副作用和必要归因分别验证，再经task owner发布状态；self只读回结果与状态，不从worker自报直接宣布完成。

零动作完成仅适用于正式合同允许且有目标比较/验证来源的分支，不补造执行轮次、冻结或授权。管理性任务没有方法执行时不伪造方法结构；其完成依旧遵守同T结算。

### 9.3 完成结算恢复

```text
读T状态和正式完成来源
→ 非完成：拒绝任务完成结算
→ 已结算：精确读回既有结果
→ 已完成未结算：读取结果闭包，调用task owner结算
→ 发布未知：原请求查询与恢复
→ 独立读回正式结算
→ 另行重新判断当前需求
```

同T换消息号或工程幂等键不能产生第二份业务结算；异义请求冲突。结算技术失败不回退完成状态，不重新执行动作，不自动创建补偿任务。

失败/取消仍要保存和交接实际结果、损失、风险与合法学习材料；没有任务完成结算不意味着这些后续处理取消。方法学习独立评审，不堵塞结果收束，不自动更新方法知识或服务值。

依据：8000 §§6—9；8200 §§7—11。[S1][S3]

## 10. 八个子目标与实际施工顺序

保留原八组子目标，但把安全最小门和恢复合同前置；将需求闭环中的最小任务依赖显式拉入，避免“先做需求、却没有合法需求来源”的循环依赖。

### G0：施工前合同闭合（前置工作，不新增业务能力）

固定本方案基线，核对活动切片与现行接口。先为M1-A上层当前步骤建立“治理步骤→公开服务完整签名→当前实现→装配→消费者→读回→验证”的窄映射。每项分为可复用、需扩展、缺提供者、失效旧接口、未验证，不用笼统“数据服务不足”，也不提前映射尚未进入施工的全部远期能力。

先形成自我线程上层首包计划；施工到本能根运行锚点或其它真实调用缺口时，再恢复/建立对应最小提供者目标，不恢复旧v0.1。最早复杂缺口形成一份完整计划，同链至多一个合同已冻结的紧邻后继，其余保留路线输入。

### G1：线程运行骨架

在现行`线程_自我.h/.cpp`承载唯一线程、停门等待、工程唤醒、停止和join。生产创建必须具备启动锚点；锚点提供者未就绪时只能完成隔离生命周期验证，不开放普通应用治理。

验收：并发/重复创建不能产生双self，停门零业务写入，停止可唤醒等待，停止与开门竞态不重新开门，join后才能销毁依赖。

### G2：自我上下文正式读回

闭合Q01/Q02和必要根查询的上层公开提供者与生产装配。首轮用新截止重读锚点，后续按操作所需读取，不强迫每条消息读取全世界。

验收：缺根、多根、错误角色、非同截止、引用缺口或提供者失败不能开门；真实根值变化通过服务读回可见。

### G3：治理消息循环

建立与现行逻辑消息方向一致的强类型分支、有界邮箱、冻结批次、来源校验、原请求关联和正式结果读回。工程停止通道不被邮箱容量限制。旧业务消息实现只经当前性复核后复用。

验收：重复、乱序、旧代次、同身份异义、消息丢失、队满、读回漂移分别有确定结果；无持久旁账。

### G4：需求治理闭环

**G4-A根需求复核：** 双根扫描→当前目标和当前采用F读取→正式比较→合法根治理意图或待机→重新等待。当前满足与技术非成功分开。

**G4-B需求正式发布：** 在具备合法父任务正式材料及最小任务服务后完成Q05→C01→确认读回→C02→需求读回。不能用聊天消息、外部请求或测试回调充当父任务正式事实。

验收：满足需求不删除；重复确认精确收敛；发布未知不另建D；输入缺口不自动转需求；首次运行没有父任务材料时明确只达到G4-A。

### G5：任务管理交接闭环

接通具体D意图→manager独立读回→任务域按列表项L查询0..1当前同目标T→建立或显式承接→Vt状态读回→筹办消息→self缺口/后继决议。

**其中产生G4-B所需父任务材料的最小承接、记录和读回片段，是G4-B的前置依赖，不等G5全部完成后才建设。** 重筹办、生命周期和完整后继仍在G5完善。

验收：一个具体D不会自动承接列表其它D；多当前T不任选；worker筹办结果不能直接推进状态；完成/失败/取消T不能被旧继续消息重开。

### G6：执行前判断闭环

接入Q08/Q09/Q11、C03/C04及独立读回；manager和worker具备相应复核。启用前必须有正式安全控制与硬门提供者；不得等到G8。

验收：冻结后事实漂移、方法撤销、安全否决、成本不可比、资源失败不产生可消费执行资格；纯观察有综合判断而无现实授权；现实动作授权与当前冻结唯一绑定。

### G7：结果与结算闭环

接通两路线结果、验证/停止、正式完成通知、Q10/C05、未完成后继和按T恢复查询。逐个发布点注入故障，验证通知失败不重执行、结算未知不重复结算。

验收：完成T恰一结算；失败/取消/等待零完成结算；零动作合法分支不伪造执行事实；需求后来不满足不重开T。

### G8：安全、服务与持续治理闭环

完善6100/6140/6150各自适用的来源、时间、维护与读回链；服务根仅查询/比较。6100当前来源规则版本1生产方法集合为空，不将普通任务成功注册为新来源，也不以假事件跑出“安全收益”。

验收：无合法来源零自动写入；正式维护仅按对应合同变化；循环次数、超时、消息量对安全/服务值不产生业务增减；休眠/终止控制仍保留具名收口和停止边界。
