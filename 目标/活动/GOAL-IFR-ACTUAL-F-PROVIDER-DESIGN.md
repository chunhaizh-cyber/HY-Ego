## 2. 目标结果与完成条件

为8121阶段21形成唯一、可实施的上游 provider 合同：它仅在存在 owner 已冻结的边界内处理“按存在持有特征变更并返回实际F”，并明确输入、输出、实际F来源、当前采用、IF/R、FCv、幂等、读回、失败、所有权与验证边界。

完成条件：现行规范、当前代码与必要设计材料足以唯一裁决该 provider 的机器语义、物理位置、公开合同、事务、生命周期、失败与验证矩阵，并形成可执行计划。若发现现行材料不能唯一裁决，会改变真实观察或当前采用事实的缺口，必须保持本目标为阻断并记录具名阻断；不得以当前 IF/R 观察或R代表值冒充实际F。

- 目标问题：8121阶段21只能消费实际 F；当前实现只具备 IF/R 观察、I64 F 出生和当前采用的分散能力，尚无该组合 provider 的冻结合同。
- 优先级理由：它是阶段21、本能运行锚点、后续线程与集成验收的唯一直接上游；在它闭合前推进阶段21会绕过存在 owner 或伪造实际 F。
- 设计承载方式：按世界树根的“固定原请求形成/恢复→正式读回→按同一底座受保护发布非权威内存投影”模式，先在本目标中闭合根特征定义 provider；随后在目标计划中直接承载实际 F provider 的完整机器合同，不重复建立独立详细设计文件。

## 3. 范围、依赖与下一动作

- 依据：4115 v0.9、6120 §2.1、6130 §2—§3/§7/§13、7150 §2.1、8121 §2—§5、4110、7160以及当前`数据服务.特征类.*`、`数据服务.存在类.h`、`应用服务.特征概念类.*`。
- 已核对事实：4115已冻结IF/R、R归组与按需概念抽象；现有`特征概念应用服务::处理实例特征R观察`只在`形成新R`时调用 I64 准确 F 出生并提交 IF/R，唯一命中只更新 R 材料。它不调用`存在类数据服务::变更当前采用`、不返回当前采用后的 F，且非 I64 直接返回`比较未启用`。
- 已核对根值：6120 §2.1与6130 §3已经冻结安全/服务根的首次当前值分别为`I64_MAX / 2 = 4611686018427387903`，根目标均为`I64_MAX`；8121“阶段21不得预设首值”仅限制阶段21本身，不否定上游 provider 消费这些已冻结输入。
- 明确排除：阶段21、根材料、线程、启动、普通应用接线、FCr自动汇聚、任意代码修改和把R代表值替代准确F。
- 依赖：双根抽象特征定义的形成/恢复合同是本 provider 所需正式 FT、定义身份及比较规则的唯一来源。当前采用、IF/R 与 F 出生能力均已存在，但只能在该上游输入可读后组合。
- 已裁决的形成模式：用户确认根特征定义与世界树根同样处理。该口径冻结为：两根各以固定、版本化、互不相同的完整原请求形成或恢复持久定义事实；每次调用必须按原请求与首次写入材料收敛，并正式读回 FT、规格、比较规则和首次 H；仅在读回成功后，普通应用才可按同一 L1 底座发布带互斥保护的值式全局投影。投影只加速同进程导航，不是第二身份、第二当前值、跨进程恢复来源或需求 owner。
- 待本目标闭合的设计项：6130 §3 已冻结 `单位`、`维度`、`分量角色`均绑定各自根定义身份，缩放为 `1/1`、值域为 `0..I64_MAX`、首次当前值与目标也已冻结；不得再把这些字段说成未定义。现行`创建先天I64特征类型`仍只支持每次新建且强制一个已存在的`外设提供者`，因此根定义 provider 必须在不伪造外设、不把投影当持久事实的前提下，明确该旧字段的兼容/替代合同、固定原请求、首次材料、幂等重放、跨进程恢复和正式读回。该 API/合同设计工作属于本设计目标，不再构成等待用户裁决的停工理由。
- 下一动作：按上述世界树根模式，形成并审查“双根抽象特征定义 provider”合同；合同必须唯一裁决 owner、两组业务幂等身份、`外设提供者`字段的合法语义、规格映射、创建/恢复/读回、按底座绑定的全局投影、失败与验证矩阵。合同闭合后，建立实际 F provider 的可执行计划；不得提前实施阶段21、建立根 D，或以 R 代表值替代实际 F。
