## 1. 目标和实施方式

实现新版任务工作线程，使其接收任务管理线程派发的具体工作，调用相应业务服务完成筹办或方法执行，保存应由领域服务保存的信息，并可靠地回传结果。工作线程是执行载体，不是另一份任务集合、任务状态机或世界事实来源。

最近目标是完成一条真实的“manager派发查找方法工作 → worker调用筹办服务 → 发布候选材料 → manager独立读回并处理”链路。随后补齐检查条件、参数绑定、真实方法执行和结果处理；不先建立全部远期支撑。

按已经确定的自上而下方式施工：先写上层工作处理函数，遇到下层能力需求时检查现有入口，能复用则复用，缺少则补该直接依赖，再回到上层。不在线程循环里复制节点操作、方法匹配、组合方法运行或状态生成算法。

确需占位的函数前标注“待实现”，明确返回缺依赖，不把默认成功或空候选伪装成真实工作结果。功能清单中的建议函数名不是现有接口，也不是本轮已冻结的C++签名。

## 2. 线程和服务的职责

| 对象 | 负责 | 不负责 |
| --- | --- | --- |
| 自我线程 | 产生并确认需求，作执行前综合判断，消费实际结果并决定后继 | 不直接运行筹办或方法，不替manager安排工作资源 |
| 任务管理线程 | 接纳需求、组织任务、排序、派发工作、独立读取回传材料、调用服务推进任务状态 | 不在管理循环中执行耗时筹办或现实动作，不直接判定需求满足 |
| 任务工作线程 | 接收一次具名工作，调用业务函数，交付结果，处理本次工程等待和停止 | 不自行创建需求或任务，不决定任务优先级，不自行批准现实动作 |
| 筹办及方法执行服务 | 查找方法、核验条件、匹配实际对象和参数、执行方法及组织执行材料 | 不因承担算法就另建线程，不越过自我和manager的决策边界 |
| 领域和综合数据服务 | 保存、读取任务、方法、特征、状态、动态及相应结果材料 | 不用线程缓存代替正式信息，不替worker决定调度 |

同一套工作线程处理筹办和执行，不另建专用筹办线程，也不要求每个任务固定拥有一个线程。当前已有共享10槽工作池；并发数量、队列容量和资源配置由普通应用提供，任务优先级和资源分配由manager组织。原单worker起步顺序只属历史，不重复建设。

manager对同一任务的一次推进保持唯一工作占用；不同任务是否允许并行还需检查实际资源与作用对象。不同任务编号本身不能证明两个现实动作互不冲突。工作占用是工程控制材料，不是任务业务状态或任务轮次。

## 3. 新版语义和旧材料取舍

采用以下已明确口径：

1. 一个任务对应一个需求，任务集合扁平；任务本身不是任务虚拟存在。任务状态由任务虚拟存在中的状态特征表达。
2. 不恢复任务轮次、筹办轮次、事实代次、共同历史截止、初始化幂等包、任务树、多需求任务或轮次调用槽。实际方法调用的执行实例只记录该次调用，不解释为旧轮次。
3. 消息按用途分型，定位实际任务和工作，不按安全根、服务根或根数量拆协议。
4. 参数场景是调用期绑定只读的有序引用容器，不进入世界树，不持久保存，不复制永久当前值；引用信息按声明及正式owner合同读写，模拟实例隔离。跨多个读取不自动获得共同快照。
5. 方法头用于索引召回，不默认是AND关系。是否满足条件、产生哪些结果，按具体条件结果项判断。
6. 本能方法通过函数完成动作；方法配对树按现行3300组织同一动作下的条件—结果知识，不是步骤树。旧结果转移布局不得自动作为当前运行结构，组合执行后继按精确合同闭合。
7. 原组合循环的无变化/反向停止目的可保留为设计输入，但多特征进展、分支、循环及停止必须在组合执行合同中明确；不能仅凭旧建议宣称当前运行器已具备这些能力。
8. 普通目标可以要求增加或减少特征值。不能把数值减少或负差统一解释为失败。
9. 方法可能影响多个特征，必须保留计划内、计划外及部分发生的变化，不能只关注任务目标涉及的特征。
10. 停止信号是独立的进程内线程控制，不依赖业务邮箱还有空间；停止线程不等于取消任务、撤销动作或需求满足。

旧规范保留的核心目的包括：筹办和执行分开、独立正式读回、执行前检查、方法自报与实际效果分开、禁止重复现实动作、保留部分结果以及安全回收。旧文件中的版本、冻结授权结构、持久恢复、结算及完整事务承诺不直接移植；需要时按新版真实调用重新设计。

## 5. 工作处理能力

### 5.1 接收与分派

接收manager给出的具体任务和工作种类，校验必要定位、重复请求及工程占用，返回接纳或拒绝回执。接纳只说明工作进入处理，不证明筹办成功、方法已运行或任务完成。

筹办与执行为不同载荷；筹办至少区分查找方法和检查条件，不能给所有消息塞入无用途的执行参数。精确字段随真实发送方、消费者一起闭合。

### 5.2 查找方法

读取任务及其需求目标，形成明确的查询范围，调用方法服务取得候选；完整查找结束后，经任务服务保存对应任务的候选材料，再回传定位。候选列表不依赖线程存活，也不另建永久候选账。

区分找到候选、完整零候选、查找未完成、结构错误和资源失败。部分结果不能宣称全范围无候选；缺少查询转换、结果承载或完整性表达时，先补直接支撑，不以空列表绕过。

不按方法名称判断功能，不因首个候选命中就声称全部查找完成。方法头的三个集合只用于召回，不能替代配对条件和效果判断。worker不因无候选自动建立方法、需求或子任务。

现有候选查询即使返回“已找到”，候选组也可能为空；应同时读取状态和载荷。结果按稳定编码排序仅便于确定输出顺序，不代表业务优先级，不能取首个节点冒充最优方法。

### 5.3 检查条件与参数

按候选方法自己的条件结果配对和参数规格，查询合适场景中的实际存在、特征类型及当前值。保持每个条件与对应结果、参数角色的关系，不能跨配对拼接有利条件和结果。

查找实际对象、比较概念和值域、组合条件求值由对应业务函数承担。参数角色满足后调用现有`建立参数场景`，形成一次调用的只读引用视图。

输出应区分条件具备、不具备、材料未到、参数缺失、结构缺口和技术错误。显式空条件与缺少条件结构不是同一情况。全部候选核验完成与只检查一个候选也必须区分。

worker执行查找和核验，不自行排序全局任务或批准执行。候选方法比较、预计影响准备和最终采用由任务业务编排及自我判断路径负责；复杂算法如需异步承载，应另有具名工作用途，不塞进无关筹办消息。

### 5.4 执行前复核

接到manager派发的执行工作后，在实际动作前重新核对任务、方法启用状态、绑定对象、参数、必要条件及执行范围；涉及现实动作还要核对可消费的自我判断和安全、资源条件。

关键材料改变时返回重判或缺口，不自行替换方法、扩大动作范围、补造参数或沿用已经失效的旧判断。方法结构不完整不能在动作执行阶段偷偷补齐。

### 5.5 方法调用

工作线程调用统一方法执行服务，而不是将登记名当作可直接执行的字符串命令，也不保存可持久化函数地址。

本能方法由正式注册解析器取得函数入口，以参数场景为唯一输入，按内部治理或普通方法职责完成工作。后继组合执行若需要运行器，应按已冻结的组合合同组织实际分支与停止，不将配对知识树直接当步骤树，也不在线程循环重写方法算法。

区分尚未动作、已经开始、部分执行、异步已受理、按函数合同返回、拒绝、错误与结果未知。普通方法发出命令后，只有取得关联的实际变化或合法观察，才进入实际效果判断。等待观察不能要求所有worker持续占用线程阻塞；异步续办方式在相应阶段明确。

### 5.6 实际材料和反馈

动作报告、动作前已有预测和实际观察分别保存来源。没有预测就明确无预测，不能事后用实际值改写预测；没有观察不能补造状态、动态或效果成功。

当前特征变化通过新版世界树及领域服务形成状态和动态，worker引用其正式定位，不重复生成一套变化事实。是否由该动作导致，还需要同次执行和作用范围关联；时间接近不等于因果成立。

现有影响评估中的“符合预测状态组”尚未核验全部变化关系和值域，不能用该组非空作为组合方法结果分支成立的判断；分支必须经对应的实际结果比较函数确认。

回传包含原工作定位、执行进度、已形成材料及非成功原因。manager独立读取材料，再调用服务组织影响评估、任务状态推进和self通知。worker不得直接宣告任务完成或需求满足。

## 6. 消息和可靠交接

| 方向 | 用途 | 应表达的内容 |
| --- | --- | --- |
| manager到worker | 查找方法 | 任务、工作关联、必要的查询范围依据 |
| manager到worker | 检查条件 | 任务、工作关联、待核验的候选和条件材料定位 |
| manager到worker | 执行方法 | 任务、工作关联、本次采用方法、参数引用及必要判断材料 |
| worker到manager | 筹办结果 | 原工作关联、已发布材料定位、完成范围和结果类别 |
| worker到manager | 执行结果 | 原工作及执行关联、实际进度、已有结果定位和记录缺口 |
| 运行控制到worker | 停止或取消控制 | 工程停止或具名工作取消；不能由此直接改任务状态 |

只实现当前阶段有真实用途的消息，不提前堆积远期DTO。线程容量覆盖排队、处理中、重试及尚需交接的活动项；同一工作只计算一次。已交付结果由接收者持有后，线程才能释放对应活动资源。

同一活动请求的精确重复复用原结果；异义冲突只拒绝新输入。具体工作号由谁分配、如何与任务及执行实例绑定、结果通道是否使用共享future、何时确认交付，需要在首次接线前明确。不能仅复制M1的“活动窗口去重”就声称现实动作可安全重试。

工作处理每次只推进必要阶段，遇到非成功返回控制层。已经发布筹办材料或执行过动作后，回传失败只重试同一结果交接，不重跑成功阶段。动作是否已发生未知时保留原工作和执行定位，只查询或等待合法确认，不能换消息号再执行。

## 7. 生命周期和失败处理

拟提供启动、提交工作、请求停止、等待停止及只读工程快照。配置由宿主提供，依赖对象必须存活到所有使用线程回收之后。队列锁只保护工程状态，调用领域服务、等待外设和join时不持有该锁。

关闭时，manager先停止新增派发，worker停止接纳并处理未开始和已经开始工作的不同分支；manager结果接收通道保持可用，直到在途结果已交接或有明确保留方式。然后join工作线程，最后销毁对应服务。具体宿主关闭次序与self/manager已有生命周期一起闭合。

| 情形 | 后继处理 | 禁止 |
| --- | --- | --- |
| 队满、尚未接纳 | 返回未接纳，manager保留原工作并按配置重试 | 把队满变成任务失败或条件不具备 |
| 条件或参数不足 | 返回具体缺口或有生产者的等待材料 | 默认参数、自动建需求、定时空转 |
| 服务未实现 | 明确缺依赖，结束本次技术尝试 | 持续重试并期待空函数变成功 |
| 写入前资源失败 | 明确无副作用时可重试 | 无条件重放所有错误 |
| 部分写入、发布未知 | 保留阶段与原定位，读取核对或报告需核查 | 假定全回滚或换键重新建立 |
| 动作后记录或发送失败 | 保留已发生动作，只补记录或重发结果 | 为补消息重复动作 |
| 未开始工作收到停止 | 取消工程待办，反馈未开始 | 宣布对应任务业务取消 |
| 已开始工作收到停止 | 按方法停止能力处理，保留部分结果或未收束状态 | 强行杀线程、伪报零动作 |
| join超时 | 返回尚未回收，依赖继续存活 | detach后销毁资源或报告已停止 |

当前底座没有在本链证明跨进程持久恢复或多步骤原子性，近期仅承诺经验证的进程内行为。恢复能力不能通过一个工作号、重试次数或日志自行取得。

## 8. 物理组织建议

建议新增：

- `海中鱼巣/线程/新_任务工作线程类.h`：工作种类、接纳/处理结果、运行配置、生命周期及线程公开入口。
- `海中鱼巣/线程/新_任务工作线程类.cpp`：邮箱、单次分派、结果交付、停止与join。

manager负责接线、占用和结果消费；综合语义入口结合现有`新_世界树类`承载，不公开其内部可变领域服务，也不让线程直达基础数据集。独立任务集合、需求树、方法根不因综合服务持有而挂入世界场景树。

筹办函数、参数匹配和方法执行器属于业务算法。职责简单且匹配时扩展既有业务入口；复杂算法拆成独立业务文件，再由综合入口组合。准确文件名和签名在首次需要时冻结，本方案不预建空模块。

工程登记必须同步头/源与Visual Studio筛选器。新增验证只消费真实公开入口，不为通过测试加入生产假成功或第二执行通道。

## 9. 分阶段实施

阶段是目标路线，不是计划索引状态。W1与任务管理方案M2的前半段衔接，manager自身的必要修改必须包含在同一交接闭环内。

| 阶段 | 交付 | 完成条件 |
| --- | --- | --- |
| W1 查找方法工作闭环 | worker生命周期、查找消息、manager派发及结果读回、最小真实筹办函数和任务候选承载 | 已存在任务取得可独立读回的查询结果；完整无候选和失败分开；重复不重复发布；停止可回收 |
| W2 条件和参数筹办 | 实际对象查找、条件求值、角色绑定、只读参数场景、缺口反馈 | 所有必要条件和参数有来源；不伪造条件具备，不直接执行动作或建立子需求 |
| W3 本能方法执行 | 注册解析、调用合同、执行前检查、单个真实本能函数、执行实例及报告 | 前置失败零动作；开始记录与真正调用分开；同一已执行工作不会因回传失败重做 |
| W4 组合执行后继设计输入 | 结果分支、步骤参数绑定、循环变化检查和部分结果 | 先闭合组合层与配对知识树的边界；实际结果决定后继，不能按旧结果节点布局直接开工，不把方法头当AND合同 |
| W5 观察与结果闭环 | 实际变化回接、预计影响完整验证、manager读取并通知self | 函数报告与效果证据分开；计划外变化保留；无观察、无预测和未知分开处理 |
| W6 多worker和生产装配 | 资源协调、真实宿主、异步续办及完整关闭 | 同任务唯一推进，不同任务不越资源边界；连续工作无丢结果、重复动作或空转 |

W1不要求先实现全部执行器，也不能只新建空线程就宣称查找闭环完成。只找到候选不表示方法可执行。W3的单函数具名验证不证明组合方法、外设效果或普通宿主已经可用。

## 11. 验证和完成声明

本轮文档只做内容、链接和差异检查，不构建、不运行代码。后续施工至少覆盖以下与阶段相应的用例：

- 工作接收：非法任务、错误工作类型、精确重复、异义冲突、队满、处理中重复、不同消息号试图重复推进同一任务。
- 筹办：合法候选、完整零候选、范围不完整、读取失败、方法结构缺失、条件不具备、参数错配及明确缺材料。
- 正式读回：manager不依赖worker自报成功；材料丢失、任务状态改变、迟到结果不得继续错误推进。
- 执行：未登记入口、绑定失效、前置拒绝零动作、异步受理不当完成、部分执行、动作后记录失败、结果发送失败不重做。
- 组合：不同结果走不同分支、循环无变化停止、方向不符合停止、多步骤部分失败保留结果。
- 效果：预测与实际分离、无预测、无观察、未发生的预计变化、计划外变化、错误执行关联、多个特征变化。
- 关闭：独立停止不被满邮箱阻塞、未开始与在途分开、结果接收端退出、重复join、超时后依赖不提前销毁。
- 生产：真实manager/worker装配和长期运行单列，跨进程恢复另列，不由隔离用例推断。

完成报告分别说明文档保存、代码实现、编译、具名运行、生产接线及持续治理的证据。不得把线程骨架、候选查询或方法记录函数称为完整任务执行能力。
