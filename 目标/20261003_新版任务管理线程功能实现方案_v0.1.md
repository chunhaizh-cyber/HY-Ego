## 1. 目标和实施原则

实现新版任务管理线程，使其通过消息接收自我已经确认的具体需求，调用新版数据服务建立或取得任务，组织筹办、安排执行、推进任务状态、处理实际结果，并向自我反馈。

任务管理线程是内部治理闭环的一部分，不承担需求产生、完整自我决策或实际方法算法的全部职责。近期先交付“一个具体需求进入、一个任务建立或复用、正式读回并反馈”的最小链；远期再接通筹办、工作线程和真实方法执行。

施工采用已经确定的自上而下方式：先实现一个上层处理函数，遇到下层需求时核对既有能力，缺少则补该直接依赖，完成后回到上层。不要先建设全部远期服务；不复制下层节点操作或在调度循环中重写领域算法。

确需占位的函数在前面标注“待实现”，返回具名缺依赖，不以空结果或默认成功推动任务。本文中的建议函数名和物理位置不代表已存在接口；各阶段开工前再闭合最小公开合同。

## 2. 三种线程的职责

| 对象 | 应承担的职责 | 不应承担的职责 |
| --- | --- | --- |
| 自我线程 | 确认需求和后继目标，作执行前综合判断，消费结果并决定未完成任务后继 | 不代替管理线程派发工作，不直接运行方法，不裸写任务状态 |
| 任务管理线程 | 接纳具体需求、组织任务、选择待推进任务、派发工作、核验回传、调用服务推进状态、通知自我 | 不自行产生需求，不以消息或队列位置替代事实，不在主循环执行长时间筹办或动作 |
| 工作线程 | 消费一次具名筹办或执行工作，调用相应业务函数，交付结果定位 | 不自行宣告需求满足，不决定新的需求，不将函数返回直接当作任务完成 |
| 数据及业务服务 | 提供任务、需求、方法、参数、状态、影响评估等能力，保存各自信息 | 不因被线程调用而转移数据职责，不替调度器另建线程 |

优先级分成两层：自我负责需求与治理方向；任务管理负责具体任务的运行期排序和资源安排。旧规范“自我管优先做什么”不能再解释为让自我实现全部任务调度。

## 3. 采用的新版口径

1. 一个任务恰好对应一个需求，当前任务类对一个需求最多建立一个任务。任务集合是扁平集合，不是任务树。
2. 任务本身不是任务虚拟存在。任务虚拟存在是任务信息的一部分，任务状态由其状态特征当前值表达。
3. 不建立任务轮次或筹办轮次。每次实际方法调用的执行实例用于记录该次执行，不解释为旧轮次。
4. 分解任务所需的新目标以子需求表达；是否需要独立目标由自我判断，管理线程只组织材料和消费确认结果。
5. 消息按用途分型，不以安全根、服务根或根数量拆成复杂协议；消息定位事实，接收方读取当前信息。
6. 方法参数场景是调用期只读节点引用容器，不持久化，也不复制一份当前值。保存长期材料由方法、任务相应结构负责。
7. 任务优先级在管理线程需要选择时计算，不写回任务作为永久权威字段。需求权重仍由需求服务提供。
8. 普通目标可以要求增加或减少某个特征值，不能把“需减少”普遍判为错误。
9. 方法可能改变多个特征，结果报告应包含计划内和计划外变化，不能只检查任务目标涉及的类型。
10. 退出采用独立进程内控制信号；邮箱容量、等待时限及工作资源配置由普通应用具名运行配置提供，不恢复底层读取预算。

旧材料保留异步交接、正式读回、执行前判断、真实结果验证、安全硬限制和避免重复动作等目的。不原样搬回初始化幂等包、事实代次、历史截止、任务树、多需求任务、轮次调用槽以及旧冻结授权结算记录。组合方法按新版结果分支组织步骤，不能照搬旧“方法配对树绝不组织执行步骤”的解释。

## 4. 当前能力及复用判断

“已有”仅表示当前源码具备相应实现，不表示从新版管理线程或普通应用入口接通。

| 能力 | 当前入口或证据 | 复用及限制 |
| --- | --- | --- |
| 任务建立或复用 | `新_任务类::建立或取得任务` | 直接复用一需求一任务检查；多个已有任务返回冲突，不任选 |
| 任务读取 | `获取任务`、`获取任务虚拟存在` | 作为承接及状态推进的正式读回，不用队列副本代替 |
| 任务列表 | `查询全部任务`、`查询活动任务`、`查询指定状态任务` | 可组织调度视图；现有稳定编码排序不是业务优先级 |
| 任务状态 | `修改任务状态`及合法迁移检查 | 状态通过服务改变；管理线程不直接改基础字段 |
| 需求当前信息 | `新_需求类::获取需求`、`查询需求权重`、`复核当前满足` | 用于目标、权重和当前判断；不可把已保存评估当作永久当前结论 |
| 方法信息与召回 | `新_方法类::获取方法`、`是方法节点`、`查询候选方法` | 已有身份及按方法头集合等筛选，不等于完整条件、目标效果与成本判断 |
| 参数场景 | `新_方法类::建立参数场景` | 已有角色和实际节点绑定及部分校验，未覆盖完整条件结果求值 |
| 方法执行记录 | `新_任务类::开始方法执行`、`结束方法执行` | 记录执行实例及正式状态；开始记录并不调用本能函数或执行组合步骤 |
| 实际影响评估 | `评估方法执行影响`、`获取影响评估` | 已按对象、类型、时间阶段分类；尚未完整核验关系、值域、方向、幅度及因果归属 |
| 子需求 | `新_任务类::建立子需求` | 当前转交需求服务后返回“任务来源未接通”，不能视为可用发布能力 |
| 新版自我线程 | 当前消息消费与双根需求复核 | 已有基础消息和反馈能力；尚无新版任务承接/结果消息分支 |
| 旧任务管理线程 | `线程_任务管理.h/.cpp` | 当前主要围绕旧本能根承接和初始化包；不是本方案完整实现，不做机械兼容转发 |

新版任务文档自身仍为未登记草案，其中“正式方法身份尚未具备”的旧缺口已落后于当前方法代码。应以“已有方法身份、召回和参数绑定基础，尚缺完整匹配、预计影响提供及真实执行接线”理解当前缺口。

## 5. 功能组织

以下为建议职责划分，不冻结 C++ 签名。

| 能力与建议处理函数 | 输入和主要处理 | 输出及边界 |
| --- | --- | --- |
| `接收消息`、`分派消息` | 校验用途、必要定位、活动重复及容量，按类型分派 | 接收回执与处理结果分开；拒绝新冲突输入而保留原消息 |
| `处理任务承接` | 读取具体需求，调用建立/取得任务，读回任务、唯一需求引用和虚拟存在 | 已建立、已复用、既有终结、拒绝或错误；不连带承接其它需求 |
| `读取待推进任务` | 从任务服务取得活动任务及正式状态，形成运行期视图 | 队列不是第二任务集合或第二状态源 |
| `选择下一工作` | 读取权重、可执行性、成本、资源、安全限制和等待条件 | 选择合法待推进项；无公式或关键材料时不虚构分数 |
| `安排任务筹办` | 按当前状态派发查方法或检查条件工作 | 不在管理主循环同步运行长任务；缺方法不自动创建方法或需求 |
| `处理筹办回传` | 读回完整候选与条件结果，调用任务服务推进或向自我报告缺口 | 不因消息重投重跑已成功工作；完整无候选与查询失败分开 |
| `准备执行判断材料` | 调用业务服务核对方法效果、参数与预计影响，形成执行前材料 | 交自我判断；管理线程不自批执行资格 |
| `处理执行判断结果` | 核对当前任务、方法、参数及安全和资源条件 | 允许派发、暂缓、拒绝或重判；旧判断不得授权已变化的活动 |
| `派发工作` | 取得同任务唯一工作占用，派发一次筹办或执行工作 | 投递失败释放未开始占用；动作未知不得盲目重发执行 |
| `处理执行结果` | 核验实际状态来源，调用执行记录和影响评估服务 | 保存实际发生部分、预计缺失和计划外变化，结果定位交自我 |
| `处理自我后继决议` | 读取现状并消费继续、等待、终结或取消决定 | 经任务服务合法迁移；不因未完成自动启动下一次动作 |
| `处理条件变化`、`请求停止` | 重新检查依赖；停止新增派发，收回工作和反馈结果 | 等待可唤醒，停止不伪装任务失败；依赖活到线程回收完成 |

物理组织建议：新增 `海中鱼巣/线程/新_任务管理线程类.h/.cpp` 承担消息、生命周期和调度编排；数据操作复用 `新_任务类`、`新_需求类`、`新_方法类`。自我通过异步边界交接，不跨线程直接调用筹办或执行逻辑。

综合业务入口优先结合用户确定的 `新_世界树类` 语义服务承载方式核对，但这不表示把独立需求树、任务集合或方法根挂入世界树。任务服务实例的实际持有、对管理线程提供的窄入口及工作线程承载位置，应在首个调用点确定，避免公开可变服务对象或重复初始化。

## 6. 消息与一次推进

### 消息用途

| 发送方与接收方 | 消息用途 | 应携带的材料性质 |
| --- | --- | --- |
| 自我到管理 | 承接一个需求 | 具体需求稳定编码、消息关联；不传旧任务初始化包 |
| 管理到自我 | 承接结果 | 原消息关联、需求、任务及结果类别；入队与任务已建立分开 |
| 管理到工作线程 | 筹办或执行请求 | 任务、工作种类和该次实际需要的只读定位；两类工作不混载 |
| 工作线程到管理 | 工作结果 | 原工作关联及已形成材料定位，不能自报需求满足 |
| 管理到自我 | 缺口、执行前判断、实际结果 | 对应任务、方法、参数或评估定位，按用途携带必要内容 |
| 自我到管理 | 执行判断或后继决议 | 对原请求的关联及适用对象；消费前重新读回 |
| 明确依赖生产者到管理 | 条件变化 | 受影响任务及依赖定位，用于重新检查，不自证依赖成立 |

精确 DTO、跨线程绑定关系、结果通道、队满处理及关闭顺序随对应生产者接入一起闭合，不预建没有用途的消息。

### 单次处理和非成功

每个处理函数本次只尝试一遍必要阶段，前一步未完成就不调用下一步。保留已完成阶段的结果定位，消息失败不撤销已经成立的任务或实际动作。

- 资源暂不可用：保留必要材料并进行可中断重试，避免阻塞其它可推进任务。
- 依赖未就绪：明确生产者和唤醒条件，不因邮箱非空或定时到达反复空转。
- 依赖未实现：返回具体缺口，不使用重试冒充业务等待。
- 消息重复或异义：重复不重复建任务或动作，异义只拒绝冲突输入。
- 状态改变或迟到消息：重新读取，不能回退任务或重开终结任务。
- 部分写入、执行结果未知：如实反馈阶段；只使用现有查询能力核对，不承诺底座尚无的原子性和跨进程恢复。
- 技术错误：停止受影响推进，不直接生成业务失败、子需求或学习结论。

活动容量包括排队、处理中、资源重试和依赖等待项。结果不能只覆盖“最近错误”；需绑定原请求供接收者取得。锁内只管理工程状态，锁外调用业务服务。工作完成、回传完成与任务完成分别判断。

## 7. 状态和结果边界

当前新版任务已有状态：已建立、待查找方法、待检查条件、待执行、执行中、待影响评估、等待自我决议、等待条件，以及已完成、已失败、已取消三个终结状态。

正常执行的参考路径是：

```text
承接需求并取得任务
→ 待查找方法 → 待检查条件
→ 准备方法与参数，取得自我执行判断
→ 待执行 → 执行中
→ 待影响评估 → 等待自我决议
→ 根据当前事实和合法决议继续、等待或终结
```

这只是业务路线，不替代当前代码的逐项合法迁移检查，也不要求提前增设“等待执行判断”等持久状态。技术工作占用与任务业务状态分开。

当前执行中只允许转入待影响评估，没有直接取消迁移。因此取消执行中的任务必须先证明动作停止或取得实际结果，具体取消收束入口仍需实现；不能直接调用状态修改跳到已取消。

影响评估目前会进入等待自我决议，不自动标记完成。管理线程负责调用评估并反馈，自我消费后重新读取需求和结果。以后是否补正式任务完成结算，应按新版实际需求单独闭合，不为迁就旧文档预造结算账。

## 8. 分阶段交付

阶段只是实施路线，不是计划索引状态。先闭合最近调用需要，远期缺口不要求全部提前解决。

| 阶段 | 交付内容 | 完成条件 |
| --- | --- | --- |
| M1 需求承接与反馈 | 新管理线程生命周期、一种承接消息、任务建立/复用、正式读回、自我反馈分支 | 一个具体需求得到一个可读任务；重复不多建，终结任务不重启；接收/建立/反馈状态分开；停止安全 |
| M2 活动任务与筹办组织 | 从任务状态生成筹办工作，接通工作结果回传和状态推进 | 单任务无重复工作；完整无候选与读取失败分开；缺口交自我；不执行现实动作 |
| M3 方法准备与执行判断 | 完整条件和目标匹配、参数场景、预计影响、候选比较、自我判断往返 | 真实材料支持选择；未知不默认可执行；条件改变后旧判断失效 |
| M4 调度与真实执行 | 动态优先级、资源互斥、工作派发、方法执行接线 | 只执行有资格的任务；同任务唯一推进；重复消息不重复动作；安全禁止优先 |
| M5 结果与后继 | 状态收集、完整影响评估、自我通知、继续/等待/终结/取消 | 覆盖计划外变化；实际发生部分不丢；不以函数返回代替效果；每个需求使用时读当前值 |
| M6 生产装配与持续运行 | 普通宿主、self/manager/worker完整关闭顺序、连续任务及依赖唤醒 | 真实入口可达，持续运行无空转或任务风暴；未接通的跨进程恢复独立说明 |

M1与自我线程方案的S2相接。自我已有S1核心消息能力，但依赖唤醒续办、普通应用事实发送方仍未完整接通。M1可以先完成具名隔离交接，不能由此宣布两份方案或生产治理闭环全部完成。

M2不要求先实现复杂综合排序；可以先验证单个可推进任务的筹办链。多个竞争任务进入真实执行前，M4排序和资源规则必须确定，不能把“暂按编码遍历”升级为业务优先级算法。

## 9. 待明确和直接依赖

| 问题 | 当前事实和限制 | 处理时点 |
| --- | --- | --- |
| 消息及服务装配 | self尚无任务消息分支，世界树未持有新版任务服务；端口及生命周期未冻结 | M1开工前闭合最小接口、服务持有、结果回传及关闭顺序 |
| 长期需求再次不满足 | 任务建立入口始终复用该需求已有任务，包括终结任务；终结状态不可重开 | M1明确反馈既有终结而不执行；进入周期治理前由用户裁决后继模型，不暗中新增第二任务 |
| 筹办结果载体 | 已有方法召回和绑定，不具备完整新版筹办协议 | M2按实际候选/条件读取需要补业务服务，不复制旧轮次或持久筹办回执 |
| 任务和方法排序 | 权重可读，但成本、并列、资源竞争及完整优先级算法未定 | 候选方法选择和M4前分别闭合，两者不是同一个排序问题 |
| 预计影响与真实执行 | 任务类接收预计变化，开始执行仅写记录；缺完整方法影响绑定及执行链 | M3—M4补所需提供者和真实调用，不将记录成功视为动作已发生 |
| 自我执行判断与安全 | 新版判定材料和相关业务规则尚未完整接入 | 实际执行前明确条件变化重判、允许/暂缓/拒绝、资源与安全门，不硬套旧常量策略 |
| 子需求来源与复合目标 | 普通需求仍返回任务来源未接通，目标尚为单特征三元组 | 首次需要任务分解或复合目标时补齐，不把缺口无条件变为新需求 |
| 结果充分性 | 当前评估只做对象、类型和阶段时间匹配 | M5前补实际需要的方向、值域、幅度及必要归因，不夸大“符合预测” |
| 执行中取消 | 无直接取消迁移，也无已证明可强制中断任意方法的入口 | M4—M5明确动作停止、部分结果和资源释放顺序 |
| 持久化及未知恢复 | 新底座缺已证明的跨进程保存/恢复和多节点原子事务 | 首次需要跨启动恢复时独立闭合；本方案近期只承诺进程内行为 |

上述问题不表示无法实现；它们区分了可复用代码、待补接口和仍需业务裁决的规则。不要为解决远期问题阻断已有依据的最近阶段，也不要用默认成功越过真实缺口。
