# 4220 子规范 动作来源与动态因果边界

编号：4220
日期：20261112
版本：v2.5
状态：正式子规范

直接上级规范：1170。
直接依赖规范：3200、4211。
相关边界规范：1190、3300、4310、5260、5350、5360、6330、8210。

## 1. 定位

本规范规定动作动态的来源、怎样先行发布、真实结果怎样显式关联，以及动态何时可以作为因果归因材料。动作动态与原子/复合结果动态分账：前者证明一次执行动作已经发生，后者证明实际变化已经发生，两者不是重复变化记录。字段与流程见4211。

## 2. 动作来源

1. 动作来源有两类，每个动作动态恰有一个来源：
   - 执行实例X：每个X在动作开始时形成恰一动作动态，唯一来源为该X（3200）；动作定义为本能方法登记形成的动作概念。
   - 内部治理迁移：任务筹办与执行中的每次任务状态迁移形成恰一治理动作动态，来源为本次迁移的治理迁移记录，经贡献阶段完成的迁移以该贡献阶段为来源（5260第4.2节）；执行主体为自我（服务根目标存在），动作定义为该迁移“前状态→后状态”配对的迁移定义，一对一个定义，其动作概念由动作方法投影形成。方法状态的变化同属内部治理迁移：方法owner经统一入口完成学习发布配对或启用修改、方法虚拟存在特征值确实变化时，形成恰一治理动作动态，来源为本次学习记录（5350第6.3节）；执行主体为自我，动作定义为“学习种类×改变的特征”定义；值未变不形成。

   动作动态保存执行主体、动作定义（动作概念）、唯一来源、目标存在、可选目标特征和动作时间。线程、消息、日志、界面显示和调用成功码均不是动作来源。
2. 本能方法的执行和第1项的内部治理迁移形成动作动态。其它内部治理函数不是本能方法，不经X，不形成动作动态；其“被动动作”只存在于因果定义中（1190）。内部治理迁移形成治理动作不使其成为本能方法，不进方法树，不经X或现实执行授权。
3. 改变型动作与结果动态使用“导致变化”关系；观察型动作与结果动态使用“观察取得”关系。观察关系只说明本次观察取得该结果，不说明观察导致被观察事实；被观察事实的发生时间可以早于本次动作，本次取得时间不早于动作时间（3200）。
4. 未知第三方行为、环境变化或没有显式动作身份的变化保持无动作来源；不得修改结果动态的主题、端点或成员，也不得复制同内容动态冒充动作结果。
5. 同一X只能精确重放同一动作动态；同一X出现不同主体、定义、目标或时间时拒绝。结果关联必须由持有该X的调用方显式传入动作节点，禁止扫描动态列表、按“最近动作”、时间邻近或单纯同场景猜测来源。
6. 感知方法只能记录观察行为产生的材料和事实刷新，不得把外界对象自身的变化伪装为自我造成的变化；作用方法的执行材料（来源任务与方法、作用外设、目标与作用范围、动作前状态、计划输出与允许误差、副作用门限、执行时间与方法结果、所需感知验证）是运行材料，不是动作动态的追加字段。

## 3. 因果边界

动态证明变化发生，不证明某个动作导致变化。每个动态都是某个因果概念的一次实例（1170、1190）：

1. 未知动作因果以动态本身作为实例，不要求动作事实。
2. 已知动作因果的归因至少需要：真实动作动态（来源X或第2节的内部治理迁移）及其与结果的显式关系、动作作用对象与动态主题一致或存在合法作用关系、动作时间与动态时间可解释、无相反证据或明确记录证据不足。
3. 动作成功、失败或返回码只属于运行结果材料。未达到目标仍可保留真实动作和真实变化；缺少变化时不能仅凭动作调用建立变化事实。
4. 同一动态可以被多个因果概念引用；任何来源关联都不自动升级为确定因果。因果判定、竞争原因和可靠性治理由1190及4310—4340处理。

## 4. 发布和生命周期

1. 动作动态先建立并挂接：本能方法的现实动作挂入执行主体所在场景，挂接时只核验执行主体属于该场景；内部治理动作挂在其目标所属的内部治理场景（任务治理场景、方法治理场景），执行主体（自我）只以引用记录，不要求是该场景成员（4211第4节第3项）；目标信息节点可在其它场景或其它世界，目标引用与结果关系可以跨世界，跨世界只禁止父子关系与成员关系。随后才执行真实改变或观察。真实结果由对应事实owner独立发布并读回，再由持有本次X的调用方建立强类型关系。
2. 跨owner操作分阶段返回真实结果。动作已建立而执行、结果发布或关联失败时保留动作并报告部分完成，不得为补记录自动重做真实动作；结果已成立但关联失败时同样保留结果。
3. 动作动态与结果动态按定期、定量规则删除（0050 §1.5、4211 §8）；被因果概念采纳为代表实例的动作动态、结果动态及其状态受保护；动作动态存在期间，其唯一来源X受保护。X/A本身不作为因果代表实例被采纳。删除动作动态时解除结果关系和相应引用，不因此取得结果动态删除所有权。

## 5. 禁止事项

- 动作动态不得复制结果变化内容或伪装成第二结果动态。
- 动作结果关系必须以“导致变化”或“观察取得”强类型表达，不以裸数值角色代替。
- 动态允许没有动作来源；不得为填满字段补造来源。
- 除第2节的内部治理迁移外，禁止为内部治理函数调用补造动作动态；内部治理迁移不得以线程、消息或调用成功码代替治理迁移记录、贡献阶段或学习记录作来源。
- 不从动态概念命中、时间先后或重复出现直接推出因果。
- 任务结算只按第2节以状态迁移的治理动作形成动态并交付因果，不另建证明型动态或因果事实。
