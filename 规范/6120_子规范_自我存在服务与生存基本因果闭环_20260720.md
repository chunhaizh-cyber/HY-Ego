## 1. 定位

本规范规定自我存在、安全轴、服务轴、生存闭环、直接服务、需求准入、方法能力边界和下一轮状态回写。

直接上级规范：1140、1190、3100

直接依赖规范：5110、6100、6110

相关边界规范：1120、1160、1170、3200、3300、6140—6150、7130

## 2. 自我觉醒坐标

自我觉醒不是神秘状态，也不等于自我节点初始化。它表示系统内部的需求、价值、任务、服务和生存因果取得共同根坐标。

自我存在定义只建立自我、根特征、抽象定义和根闭环因果坐标，不直接建立需求。唯一自我正式形成并独立读回后，冷启动治理再经需求正式入口建立或幂等收敛安全根需求与服务根需求；运行期具体活动需求只能由两个根及其后继父需求的任务形成正式子目标承接记录后建立。不得从定义词条、固定节点清单、初始化字段、显示、方法首、外部请求或其它材料直接生成具体活动需求。

### 2.1 双根闭环起点

正式起点固定为：

1. 唯一自我正式形成并读回；
2. 冷启动治理建立或收敛安全根需求角色与服务根需求角色；
3. 两个角色分别绑定一个普通根需求 D；
4. 每轮冻结同一 G0；
5. 分别读取目标合同与当前值；
6. 分别形成当前满足、正差距、方向相反、不可比较、材料不足、当前性漂移或内部不一致；
7. 正差距或新到达的合法父任务材料允许建立、唤醒或复用对应根需求的治理任务；材料触发只授权 fresh 重判与裁决，不等同正差距，不改变根当前值，也不直接创建需求。治理任务把已正式选择且当前有效的父目标实现路径所必需、并可独立验证的目标形成正式子目标承接记录后，需求域建立或复用子需求。

两个根角色、目标、树、当前满足和来源必须独立。安全根当前值和服务根当前值不能压成综合分数。根需求长期存在，当前满足只关闭本轮差距展开，不触发永久退役。

两个根共用以下冷启动刻度合同，但不共用身份或账：

```text
M = I64_MAX = 9,223,372,036,854,775,807
A0 = V0 = M / 2 = 4,611,686,018,427,387,903
M % 2 = 1，非负整数除法余数舍弃
安全根目标合同：A == M
服务根目标合同：V == M
```

`A0`、`V0` 分别作为安全值和服务值的首次正式当前值，与各自初始状态共同发布且不形成动态。每轮在同一 G0 验证 `0 <= A <= M`、`0 <= V <= M` 后，才可按已登记的二次特征概念即时形成 `Δsafe = M - A` 和 `Δservice = M - V`；两个差值只供本轮使用并立即丢弃，不持久化、不相加、不直接形成优先级、具体需求、任务或现实行动。非法值或公式不一致属于内部不一致，不得钳制后继续运行。

根值比较属于 DATA 外治理，不为每次读取建立任务；但具体子目标展开必须发生在父需求治理任务的筹办中。父任务只能把已正式选择且当前有效的父目标实现路径所必需、可独立验证的目标形成正式子目标承接记录，需求域消费该记录建立或复用子需求。首版不要求多步因果反推；后继能力可以消费正式因果材料提高展开精度，但不得改变双根起点或父任务唯一衍生入口。

## 3. 基础信息语法

安全和服务不得只由自然语言定义。正式语义至少由以下结构共同表达：

```text
自我存在稳定身份
+ 抽象根特征定义和值域
+ 自我实例特征槽、唯一当前属性槽和当前值事实
+ 场景、参与存在和适用范围
+ 状态、前后状态动态及来源证据
+ 二次特征比较
+ 因果信息和根闭环位置
```

特征当前值承载“现在是什么”的业务权威事实；目标状态合同规定参与特征、目标值、比较关系和组合规则。状态只记录某个强时间下的特征值，动态只记录观察、动作、任务推进和结算等变化的前后状态及来源。状态 / 动态可以成为安全或服务证据、触发和审计材料，但不得替代当前值参加目标比较。

任何正式特征当前值变化都由业务规则先裁决新值，再经统一变化入口切换当前值并同步记录状态 / 动态。即使工程上原子发布，权威顺序仍是“业务新值 → 当前值事实 → 状态记录 → 动态记录”，不得反向由状态或动态决定当前值。

## 4. 安全轴

本节定义自我的生存安全根轴。该根轴同时承担“真实安全事实结算后的生存控制值”和主动运行 / 休眠控制，不是物理状态的副本或显示分数。机器值使用有符号 I64，当前 v2 值域为 `0..I64_MAX`：

- `0`：自我存在循环不可维持或关键循环不可恢复的终止控制态；
- `1`：只开放具名恢复、重建和事实接收入口的受限控制态；
- `>1`：允许主动运行。

`0` 和 `1` 都不允许普通任务进入执行竞争：终止态只保留正式恢复 / 重建与停止控制入口；受限态只保留具名治理材料接收、安全事实接收、正式恢复 / 重建和停止控制入口。只有 `A>1` 才允许普通任务进入一般调度；安全任务在一般调度内继续消费 6150 的安全调度倍率和硬否决。这些最小入口不是普通任务调度资格，不得被来源存在分类、任务名称、队列或线程状态扩大。

根定义必须具备 `1 < 低位阈值 < 高位阈值 <= I64_MAX`、定义版本和主动安全结算规则版本。阈值不由线程、服务请求、任务调度或显示层临时配置。

生产定义版本 1 使用有理比例规则而不是二进制浮点数：`M=I64_MAX`，`L=floor(M*30/100)=2,767,011,611,056,432,742`，`H=floor(M*80/100)=7,378,697,629,483,820,645`。实现必须用经溢出证明的整数分解、足够宽的整数中间值或等价安全算法计算；禁止先在 I64 内直接执行 `M*30` / `M*80`，禁止 `float` / `double`，也禁止以 `UINT64_MAX` 代替本根值域上界。阈值随安全根定义版本变化而变化；同一定义版本内是不可变正式事实，不因进程启动、线程、任务或服务请求浮动。

生产定义版本 1 绑定主动安全结算规则版本 1。该版本绑定只声明定义期望的规则合同，不证明对应生产 provider 已经存在；缺少正式主动安全事实完整性见证时继续 fail-closed。

物理状态、能力保留、风险余量和场景影响分别作为状态、动态和因果事实进入主动安全结算。不得按固定因素配额、简单加权平均、单一最低值或无来源显示百分比直接写根值；并联冗余先在对应因素内部形成当前事实，同源观察不得重复计入。真实安全事件、恢复和处置结果独立改变根值，并保留前后状态、来源动作、场景、因果和结算版本。

生存安全根值不再根据服务根当前值、完整秒、服务请求或任务数量被动回归。`A=0/1` 只能由独立正式安全事实和 6100 的主动安全结算改变；外部请求、服务结果、线程唤醒和普通任务结果不得直接把它写成主动运行。

6140 的分层安全值是某一来源因果信息相对于具体安全结果的安全满足度，使用独立的 I64 定点刻度和低 / 高阈值；它不是本节生存安全根轴的第二份副本。生存安全根值、分层安全值、服务根当前值和 6150 任务执行调度倍率必须使用不同的强类型记录、规则版本和写入入口，不得因数值都为 I64 而互换。

风险安全必须有上级风险因果，并能接到未来物理安全下降或服务能力下降目标。有效上游风险可以在直接伤害尚未发生时沿正式因果链形成预防子目标候选材料和对应低层调度倍率；能够阻断该路径的上游方法可以成为父任务的路径候选，但不能靠方法或任务名称绕过正式来源需求关系、调度门控或安全硬否决。没有上级风险因果时，只能形成缺事实、缺比较、缺搜索或缺因果的父任务材料，不能猜测风险。

安全根缺口链至少能追溯：安全控制态、服务物理候选、必要物理因素、风险余量、场景影响、已确认存在、目标特征当前值及其状态 / 动态证据。未知事实不得默认满足；只有按证据搜索规则完成搜索且未发现负向证据时，才可提交有范围、来源、有效期和搜索完整状态的“无负向证据”结果，它不是永久安全事实。

## 5. 服务轴

服务闭环的直接链为：

```text
外部存在发出的服务请求由原来源领域正式承接
-> 请求作为服务根治理任务材料
-> 服务对象、服务目标和目标涉及的当前特征值明确
-> 服务根任务把已选当前有效路径所必需且可独立验证的目标形成正式子目标承接记录
-> 需求域建立或复用属于唯一自我的服务子需求
-> 经普通任务筹办、方法选择、执行冻结与适用安全门禁
-> 自我服务动作执行
-> 后状态和实际改善可验证
-> 改善可归因于自我动作
-> 形成普通正式结果及状态 / 动态 / 因果
-> 回写下一轮服务状态
```

没有直接服务触发事实时，只能形成监听触发、检查服务机会、校准服务能力和服务根缺口检查等服务根父任务材料。不得虚构当前服务对象、目标、结果或任何服务值入账。

直接服务触发已经存在，且某个上下文缺口会阻断行动、验证、归因或回写时，只能把该缺口作为服务父任务的筹办材料；父任务裁决为已选当前有效路径所必需且可独立验证的子目标并形成正式子目标承接记录后，才可通过需求统一入口建立或复用子需求。

服务对象所需信息和反馈信息只能从真实服务尝试、表达、确认、生效回执、外在状态变化和来源动作动态中形成。服务前状态未知不能计算改善方向，服务后状态未知不能验证结果。

## 6. 直接服务与能力准备

直接服务必须落到真实来源存在、正式请求材料、具体目标、属于唯一自我的服务子需求、状态变化、验证和归因，并按普通需求、任务、方法和正式结果规则闭合。能力准备只维护和形成可用于服务的新能力或材料，不能证明服务对象已经受益，也不产生独立服务账或根值补回。

安全链在完成证据搜索后可以形成限定范围的无负向证据候选；服务链不能因无正向证据而默认很好。对象明确接受且反馈窗口内无负反馈，最多形成可接受候选。

## 7. 生存和服务闭环成立条件

生存闭环至少具备自我根安全定义、当前场景、自我目标特征当前值、状态 / 动态证据、影响因果、可执行 / 可等待处置、动作或观察结果、验证和下一轮回写。

服务闭环至少具备真实来源存在、正式请求材料、服务根父任务、正式子目标承接记录、属于唯一自我的普通服务子需求、服务对象、目标、权限、服务前后状态、实际交付、外在改善、验证、归因、正式结果和下一轮回写。

候选视图、风险线索、场景评估、任务轮次结论或任务轮次收束不得绕过根控制、因果归因和 6100 主动安全结算入口写生存安全根值。6140 的被动维护只允许修改对应分层安全值。

## 8. 服务根无记账边界

服务根当前值只保留为普通根特征的当前事实和逐轮比较坐标，不是奖励、信用、余额或合同账户。本次退役不建立新的自动生产者：合同、支付比例、到期、准备、任务数量、方法次数、等待时间、完整秒和服务结果都不得自动增加或降低它。

服务动作的真实效果由服务对象目标涉及的当前值、正式结果、状态、动态和因果表达。服务根正差距或新到达的合法父任务材料可以建立、唤醒或复用根治理任务；监听、机会检查、能力校准和外部服务请求都只能成为该任务材料，材料触发只授权 fresh 重判与裁决，不等同正差距，也不改变根值。父任务形成已选当前有效路径所必需且可独立验证的正式子目标承接记录后，才经普通需求入口建立或复用具体服务子需求。

服务根当前值不得改变生存安全根值，也不产生安全 / 服务任务根配额。未来若需要改变服务根当前值，必须另行建立独立、直接、非记账式的机器语义和唯一写入 owner；在此之前保持无新写入授权。

## 9. 缺口到需求

任务筹办或自检只能从已有因果信息、安全风险树和服务根闭环读取缺口报告。缺口报告、外部请求和其它材料只能进入对应父需求任务；没有活动任务时可以幂等建立、唤醒或复用该父需求治理任务，但只用于 fresh 重判与材料裁决。父任务形成已选当前有效路径所必需且可独立验证的正式子目标承接记录后，正式子需求才经统一入口建立或复用，并满足目标宿主、目标特征、非零事实截止、同截止当前特征值完整投影、目标状态合同、满足关系、父链和证据准入。状态、动态和因果材料只能作为历史、变化与来源证据，不得替代当前值。安全子需求还必须保留相对于具体安全结果的动态因果层投影；无有效路径时保持尚未归层，禁止按固定类别补层。能够直接解除自我安全问题的外部材料按真实因果进入安全父任务筹办，但不直接取得需求身份，也不建立服务合同或服务值结算身份。

AND、OR、因果子链和方法路径由关系、路径视图和提交规则承载，不新增需求自由字段。

单次因果补完可以只补足具备证据的部分因果链，但不能为了凑完整链伪造服务节点、观察样本、方法、动作动态或反馈。

## 10. 方法能力边界

有目标不等于可以自动创建方法首。现行规则为：

1. 已有因果链必须证明目标需要自我动作能力。
2. 只能召回和复用已经正式登记、规格闭合的方法。
3. 无候选方法时返回具名能力缺口、路径缺口或等待外部输入，不自动创建方法首。
4. 通用特征写入、内核原语和方法名称匹配不得兜底成为业务方法。
5. 方法执行仍由任务选择和执行冻结约束；含现实改变步骤时还必须读回该冻结唯一自我现实执行授权，安全硬否决保持独立，线程不是动作来源。

## 11. 当前交互者和权限者

交互者、服务对象、授权者和权限者是不同角色。只有服务事件确实需要身份、授权、责任或冲突判断时，这些事实才进入链条。

没有服务事件、目标、外部输入或权限冲突时，当前交互者状态只能是上下文为空或等待材料，不得自动生成主动需求。身份和权限事实必须由稳定句柄、关系和有版本状态承载，不由文本标签裁决。

## 12. 写入与验证

自我治理编排只读根定义和当前事实，形成强类型缺口候选；需求、任务、方法、状态、动态、因果、正式结果和主动安全结算服务分别负责正式写入。根闭环必须以稳定句柄贯穿自我、根特征、需求、任务、方法、动作动态、结果状态和下一轮回写。

验证覆盖定义不直接生需、安全与服务双轴、生存安全根值 / 分层安全值 / 服务根当前值分账、有效上游风险的预防投影、普通服务请求链、服务合同与服务值账零生产、受限态请求不自动授权、无负证据边界、无候选方法、交互者 / 权限者分离和下一轮回写。
