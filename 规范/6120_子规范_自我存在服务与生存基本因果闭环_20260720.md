## 1. 定位

本规范规定自我存在、安全轴、服务轴、生存闭环、直接服务、需求准入、方法能力边界和下一轮状态回写。

直接上级规范：1140、1190、3100

直接依赖规范：3200、5260、6100、6110、6190

相关边界规范：1120、1160、1170、3200、3300、6140—6150、7130

## 2. 自我觉醒坐标

自我觉醒不是神秘状态，也不等于自我节点初始化。它表示系统内部的需求、价值、任务、服务和生存因果取得共同根坐标。

自我存在定义只建立自我、根特征、抽象定义和根闭环因果坐标，不直接建立普通需求。安全根需求和服务根需求由self固有地产生并确认；唯一自我正式形成并独立读回后，冷启动治理经需求类初始化入口共同建立或精确复用这两个根需求。运行期具体活动需求只能由self依据两个根及其后继父需求的正式材料产生并确认，再由需求类建立或复用。不得从定义词条、固定节点清单、初始化字段、显示、方法首、外部请求或其它材料直接生成具体活动需求。

### 2.1 双根闭环起点

正式起点固定为：

1. 唯一自我正式形成并读回；
2. 冷启动治理发布或收敛 self 固有且已确认的安全根需求角色与服务根需求角色；
3. 两个角色分别绑定一个普通根需求 D；
4. 安全根和服务根都按目标存在与目标特征类型current-only读取唯一自我的对应实例特征；
5. 分别形成当前满足、正差距、不可比较、材料不足或内部不一致；
6. 正差距或新到达的合法父需求治理材料允许建立、重新启用或复用对应根需求的治理任务；材料触发只授权fresh重判与裁决，不等同正差距，不改变根当前值，也不直接创建需求。self fresh产生并确认目标独立、必要、父域合法且可由自身目标状态合同最终判定后，由需求类建立或复用子需求。

两个根角色、目标、树、当前满足和来源必须独立。安全根当前值和服务根当前值不能压成综合分数。根需求长期存在，当前满足只关闭本轮差距展开，不触发永久退役。

两个根共用以下数值边界，但不共用承载、身份或账：

```text
M = I64_MAX = 9,223,372,036,854,775,807
A0 = V0 = M / 2 = 4,611,686,018,427,387,903
M % 2 = 1，非负整数除法余数舍弃
安全根目标合同：A == M
服务根目标合同：V == M
```

`A0`和`V0`分别作为唯一自我的安全值、服务值实例特征首次当前值，与各自初始状态共同发布且不形成变化动态。每次分别fresh读取并验证`0 <= A <= M`、`0 <= V <= M`后，才可即时形成`Δsafe = M - A`和`Δservice = M - V`；两个差值只供本次判断使用并立即丢弃，不持久化、不相加、不直接形成优先级、具体需求、任务或现实行动。非法值或公式不一致属于内部不一致，不得钳制后继续运行。

双根合法值域内`Δ=M-current`只能为正或零，分别对应需增加的正差距和当前满足。任何负差均证明目标值、当前值、根角色/来源绑定或公式不一致，必须按内部不一致或不可比较等技术非成功处理，不得触发根治理任务。根值真实下降是合法变化事实，但不改变双根固定增向目标，只会扩大下一轮正差距。该限制只适用于安全根、服务根；普通需求按自身目标状态合同形成需增加、需减少或其它具名结果，合法需减少不得称为异常。

根值比较属于DATA外治理，不为每次读取建立任务；具体目标提议先作为父需求治理材料。self fresh产生并确认目标独立、必要、父域合法且可由自身目标状态合同最终判定后，由需求类发布或复用子需求。首版不要求多步因果反推；后继能力可以消费正式因果材料提高展开精度，但不得改变双根起点。

## 3. 基础信息语法

安全和服务不得只由自然语言定义。正式语义至少由以下结构共同表达：

```text
自我存在稳定身份
+ 抽象根特征定义和值域
+ 自我引用的独立特征信息节点及准确当前观察值
+ 场景、参与存在和适用范围
+ 状态、前后状态动态及来源证据
+ 二次特征比较
+ 因果信息和根闭环位置
```

实例特征当前值承载“现在是什么”的权威事实；安全根和服务根都读取唯一自我的对应实例特征。每个需求只规定一个目标存在上的一个目标特征，并以值/值域加比较关系或变化方向二选一表达。状态记录某个强时间下的特征值，动态记录已经发生的变化；任务推进和服务结算属于内部治理事实，但服务值实例特征的真实变化仍由特征owner自动形成相应状态、动态和认知材料。状态/动态可以成为服务结算证据、触发和审计材料，但不得替代实例特征当前值参加根比较。

业务规则先裁决新值，再按特征信息节点提交准确观察值。1130、4110 的字段操作不自动建立状态或动态；本规范的冷启动、安全结算及其它专属治理流程需要记录证据时，仍按各自合同形成状态 / 动态。记录只保存该流程已经取得的准确值，不得反向决定特征当前值；内联 I64 不要求独立值事实身份。

## 4. 安全轴

本节定义自我的生存安全根轴。该根轴同时承担“真实安全事实结算后的生存控制值”和主动运行 / 休眠控制，不是物理状态的副本或显示分数。机器值使用有符号 I64，当前 v2 值域为 `0..I64_MAX`：

- `0`：自我存在循环不可维持或关键循环不可恢复的终止控制态；
- `1`：只开放具名恢复、重建和事实接收入口的受限控制态；
- `>1`：允许主动运行。

`0` 和 `1` 都不允许普通任务进入执行竞争：终止态只保留正式恢复 / 重建与停止控制入口；受限态只保留具名治理材料接收、安全事实接收、正式恢复 / 重建和停止控制入口。只有 `A>1` 才允许普通任务进入一般调度；安全任务在一般调度内继续消费 6150 的安全调度倍率和硬否决。这些最小入口不是普通任务调度资格，不得被来源存在分类、任务名称、队列或线程状态扩大。

根定义必须具备 `1 < 低位阈值 < 高位阈值 <= I64_MAX`、定义版本和主动安全结算规则版本。阈值不由线程、服务请求、任务调度或显示层临时配置。

生产定义版本 1 使用有理比例规则而不是二进制浮点数：`M=I64_MAX`，`L=floor(M*30/100)=2,767,011,611,056,432,742`，`H=floor(M*80/100)=7,378,697,629,483,820,645`。实现必须用经溢出证明的整数分解、足够宽的整数中间值或等价安全算法计算；禁止先在 I64 内直接执行 `M*30` / `M*80`，禁止 `float` / `double`，也禁止以 `UINT64_MAX` 代替本根值域上界。阈值随安全根定义版本变化而变化；同一定义版本内是不可变正式事实，不因进程启动、线程、任务或服务请求浮动。

生产定义版本 1 绑定主动安全结算规则版本 1。该版本绑定只声明定义期望的规则合同，不证明对应生产 provider 已经存在；缺少正式主动安全事实完整性见证时继续 fail-closed。

物理状态、能力保留、风险余量和场景影响分别作为状态、动态和因果事实进入主动安全结算。不得按固定因素配额、简单加权平均、单一最低值或无来源显示百分比直接写根值；并联冗余先在对应因素内部形成当前事实，同源观察不得重复计入。真实安全事件、恢复和处置结果独立改变根值，并保留前后状态、来源动作、场景、因果和结算版本。

生存安全根值不再根据服务根当前值、完整秒、服务请求或任务数量被动回归。`A=0/1` 只能由独立正式安全事实和 6100 的主动安全结算改变；外部请求、服务结果、线程唤醒和普通任务结果不得直接把它写成主动运行。

6140 的分层安全值是某一来源因果信息相对于具体安全结果的安全满足度，使用独立的 I64 定点刻度和低 / 高阈值；它不是本节生存安全根轴的第二份副本。生存安全根值、分层安全值、服务根当前值和 6150 任务执行调度倍率必须使用不同的强类型记录、规则版本和写入入口，不得因数值都为 I64 而互换。

风险安全必须有上级风险因果，并能接到未来物理安全下降或服务能力下降目标。有效上游风险可以在直接伤害尚未发生时沿正式因果链形成预防目标提议材料和对应低层调度倍率；能够阻断该路径的上游方法可以成为父需求的治理路径候选，但不能靠方法或任务名称绕过正式来源需求关系、调度门控或安全硬否决。没有上级风险因果时，只能形成缺事实、缺比较、缺搜索或缺因果的父需求治理材料，不能猜测风险。

安全根缺口链至少能追溯：安全控制态、服务物理候选、必要物理因素、风险余量、场景影响、已确认存在、目标特征当前值及其状态 / 动态证据。未知事实不得默认满足；只有按证据搜索规则完成搜索且未发现负向证据时，才可提交有范围、来源、有效期和搜索完整状态的“无负向证据”结果，它不是永久安全事实。

## 5. 服务轴

服务闭环的直接链为：

```text
已确认的人类存在发出的服务请求由原来源领域正式承接
-> 请求作为服务根治理材料
-> 服务对象、服务目标和目标涉及的当前特征值明确
-> self fresh产生并确认独立必要目标
-> 需求类建立或复用属于唯一自我的服务子需求
-> 经普通任务筹办、方法选择、执行冻结与适用安全门禁
-> 自我服务动作执行
-> 后状态和实际改善可验证
-> 改善可归因于自我动作
-> 形成普通正式结果及状态 / 动态 / 因果
-> 满足6190的人类服务、观察验证、改善证明和归因门禁时提交服务值结算
-> 更新唯一自我服务值实例特征并在下一轮fresh复核服务根
```

没有直接服务触发事实时，只能形成监听触发、检查服务机会、校准服务能力和服务根缺口检查等服务根父需求治理材料。不得虚构当前服务对象、目标、结果或任何服务值入账。

直接服务触发已经存在，且某个上下文缺口会阻断行动、验证、归因或回写时，只能把该缺口作为服务父需求治理材料；self fresh产生并确认其目标独立、必要、父域合法且可最终判定后，需求类才可通过统一入口建立或复用子需求。

服务对象所需信息和反馈信息只能从真实服务尝试、表达、确认、生效回执、外在状态变化和来源动作动态中形成。服务前状态未知不能计算改善方向，服务后状态未知不能验证结果。

## 6. 直接服务与能力准备

直接服务必须落到真实来源存在、正式请求材料、具体目标、属于唯一自我的服务子需求、状态变化、验证和归因，并按普通需求、任务、方法和正式结果规则闭合。能力准备只维护和形成可用于服务的新能力或材料，不能证明服务对象已经受益，也不产生独立服务账或根值补回。

安全链在完成证据搜索后可以形成限定范围的无负向证据候选；服务链不能因无正向证据而默认很好。对象明确接受且反馈窗口内无负反馈，最多形成可接受候选。

## 7. 生存和服务闭环成立条件

生存闭环至少具备自我根安全定义、当前场景、自我目标特征当前值、状态 / 动态证据、影响因果、可执行 / 可等待处置、动作或观察结果、验证和下一轮回写。

服务闭环至少具备已确认的人类来源存在、正式请求材料、服务根、属于唯一自我的普通服务子需求、服务对象、目标、权限、服务前后事实、实际交付、外在改善、观察验证、归因、正式结果、6190服务值结算结果和下一次current-only重判。非人类来源或人类未确认需求可以形成其它普通业务材料，但不得进入服务值增加结算。

候选视图、风险线索、场景评估、执行实例结论或任务状态不得绕过根控制、因果归因和6100主动安全结算入口写生存安全根值。6140的被动维护只允许修改对应分层安全值。

## 8. 服务根与服务值实例特征

服务根当前值由唯一自我的服务值实例特征提供。旧合同、支付比例、预支、到期、准备、任务数量、方法次数和旧完整秒体系继续不能改变它；合法人类服务经结果观察、改善验证和归因后可以按6190结算增加，后续冻结的合法时间衰减规则可以降低它。

服务动作的真实效果由服务对象目标涉及的当前值、正式结果、状态、动态和因果表达。任务完成或方法返回不直接改变服务值；只有6190唯一owner可以消费完整服务证据结算。服务根正差距或新到达的合法材料可以建立、重新启用或复用根治理任务；监听、机会检查、能力校准和外部服务请求都只能成为self重判材料，不等同正差距，也不改变根值。self fresh产生并确认独立必要目标后，由需求类通过普通需求入口发布或复用具体服务子需求。

服务根当前值不得改变生存安全根值，也不产生安全/服务任务根配额。服务值变化属于内部治理结算和时间维护，不取得现实执行授权；达到`M`只表示当前满足，后续衰减可以再次形成正差距。没有合法人类需求时不得为了抵消衰减而强行服务或制造服务对象需求。

## 9. 缺口到需求

任务筹办或自检只能从已有因果信息、安全风险树和服务根闭环读取缺失材料。缺失、外部请求和其它材料只能进入对应父需求的治理材料；没有活动任务时可以建立、重新启用或复用该父需求治理任务，但只用于fresh重判与材料裁决。self fresh产生并确认目标独立、必要、父域合法且可最终判定后，正式子需求才由需求类统一入口发布或复用，并满足目标存在、单一目标特征、值/方向目标、父链和证据准入。状态、动态和因果材料只能作为变化与来源证据；值目标依赖当前值，方向目标依赖同一执行实例的动作前值与观察后值。安全子需求还必须保留相对于具体安全结果的动态因果层投影；无有效路径时保持尚未归层，禁止按固定类别补层。能够直接解除自我安全问题的外部材料按真实因果进入安全父需求材料，但不直接取得需求身份；能够证明人类服务实际满足的完整材料只能提交6190服务值治理入口裁决，不能由任务、方法或self自行入账。

AND、OR、因果子链和方法路径由关系、路径视图和提交规则承载，不新增需求自由字段。

单次因果补完可以只补足具备证据的部分因果链，但不能为了凑完整链伪造服务节点、观察样本、方法、动作动态或反馈。

## 10. 方法能力边界

有目标不等于可以自动创建方法首。现行规则为：

1. 已有因果链必须证明目标需要自我动作能力。
2. 只能召回和复用已经正式登记、规格闭合的方法。
3. 无候选方法时返回具名能力缺口、路径缺口或等待外部输入，不自动创建方法首。
4. 通用特征写入、内核原语和方法名称匹配不得兜底成为业务方法。
5. 方法执行仍由任务选择和执行冻结约束；含现实改变步骤时还必须读回该冻结唯一自我现实执行授权，安全硬否决保持独立，线程不是动作来源。

## 11. 当前交互者和权限者

交互者、服务对象、授权者和权限者是不同角色。只有服务事件确实需要身份、授权、责任或冲突判断时，这些事实才进入链条。

没有服务事件、目标、外部输入或权限冲突时，当前交互者状态只能是上下文为空或等待材料，不得自动生成主动需求。身份和权限事实必须由稳定句柄、关系和有版本状态承载，不由文本标签裁决。

## 12. 写入与验证

自我治理编排只读根定义和当前事实，形成强类型缺口候选；需求、任务、方法、状态、动态、因果、正式结果、主动安全结算和6190服务值治理入口分别负责正式写入。根闭环必须以稳定身份贯穿自我、安全值/服务值实例特征、需求、任务、方法、现实动作、观察结果、影响评估、结算和下一轮回写。

验证覆盖定义不直接生需、安全与服务双轴、生存安全根值/分层安全值/服务值实例特征分账、有效上游风险的预防投影、人类服务请求链、旧服务合同零生产、合法服务结算、时间衰减、受限态请求不自动授权、无负证据边界、无候选方法、交互者/权限者分离和下一轮回写。

## 13. 外部服务请求的最小承接合同

外部服务请求只作为self的输入材料，不取得需求身份、服务合同或服务值增加资格。首版适配入口接收并独立读回：

```text
来源存在 E（L2存在身份）
+ 不可变材料 M（不可变材料身份）
+ 服务根需求D_service
+ 不可变消息身份与原请求身份
```

材料服务读回的`材料.来源节点`必须与E的稳定值相等，并通过存在类确认E当前存在；只比较非零编码、路径、摘要或缓存均不成立。适配器只负责把材料交给self，不得自行决定目标、对象、权限、方法或结果。

通过互证后，self读取服务对象、目标存在、单一目标特征、目标值/值域或变化方向、权限、安全边界和合理性；材料不足时等待或请求补充，不能猜测。只有self决定承接时，才由需求类建立或复用具体服务D，再由manager建立或复用该D的唯一T。不得建立专用请求账、来源registry、真实性provider、游标或平行任务事实。

manager按T当前状态确定`找方法`或`查条件`步骤，并交给同一worker、队列和结果通道；不得为服务请求插入第二transport、线程、队列、端口、请求账或结果账。后续执行、结果获取、影响评估和self决议统一服从5090/5260/8200。

筹办工作包以消息类型和任务状态区分本次工作；每个已消费工作包只调用对应函数一次。服务请求适配器不消费、不生产执行前选择；执行前入口fresh读回任务信息和当前事实。只有self产生并确认后，需求类才能发布或复用具体需求。

入口拒绝、来源互证失败、身份冲突和资源失败均返回结构化非成功并保持零业务写入；发布未知只按原消息和原请求查询收敛。服务请求到达不自动改变服务根当前值、安全值、需求满足、结算或现实世界。
