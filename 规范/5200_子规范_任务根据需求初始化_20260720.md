# 5200 子规范 任务根据需求初始化

编号：5200
日期：20260824
版本：v0.9
状态：正式子规范
权威等级：正式规范

## 1. 定位

本规范定义任务承接需求时必须形成的结构锚点、任务特征来源、固定任务特征类型、方法开放特征角色和初始化顺序。

直接上级规范：3200。

直接依赖规范：0500、3100、3300。

相关边界规范：5210、5230、5240、6140、6150。

## 2. 结构锚点不是任务特征

以下事实由本项目节点和关系结构承载，不得再复制成并列权威特征：

| 结构事实 | 权威承载 |
| --- | --- |
| 任务身份 | 任务节点及稳定句柄 |
| 同类任务查询锚点 | 任务—需求列表项正式关系；只负责查询 / 防重，不提供目标或来源集合 |
| 来源需求关系组 | 一条或多条 `T→D` 正式关系；只有逐次承接输入可以新增 |
| 任务虚拟存在 | 任务—唯一任务虚拟存在关系 |
| 目标宿主、目标特征和目标状态 | 通过当前 `T→D` 关系组中的具体需求逐项联合回读；任一来源目标不等价即拒绝 |
| 当前生命周期 | 任务生命周期状态关系及版本 |
| 候选方法 | 本轮候选集合及其来源记录 |
| 当前方法 | 任务方法选择记录及当前发布关系 |
| 实际结果状态 | 任务—实际结果状态关系 |

这些结构事实参与任务状态判断，但不属于第 4 章的可特征化任务特征类型。

## 3. 任务特征集合来源

```text
任务特征集合
= 任务领域固定治理特征集合
∪ 各来源需求锚定特征集合
∪ 当前激活方法声明的任务业务特征集合
∪ 当前激活组合方法声明的协作特征集合
```

任务领域固定治理特征只能由任务领域规范定义。每项来源需求锚定特征必须能够回到具名 `T→D` 关系、具体需求或活动路径；多来源不得压成一条无来源汇总。方法业务特征和组合协作特征必须由对应方法正式声明。

任务不得因为“本轮需要”而直接创建新业务特征类型。需要新增特征时，必须先由合法方法或任务上级规范声明，再按 0500 完成特征类型准入。

## 4. 固定任务特征类型总表

### 4.1 承接、路径、权重和调度输入

| 特征类型 | 值语义 | 合法来源 |
| --- | --- | --- |
| 任务承接角色 | 管理、执行、聚合、逻辑组织等具名角色；不得由有无子节点单独决定 | 来源需求语义、活动路径和任务领域裁决 |
| 目标当前性 | 当前、已过期、待复核等强类型值 | 来源需求目标及相关版本 |
| 活动 OR 路径状态 | 所属替代路径及其当前性 | 来源需求的活动 OR 路径 |
| 所属 AND 组状态 | 所属共同成立组及其当前性 | 当前 OR 路径内的 AND 组 |
| 继承父权重 | 当前 OR 路径继承的完整父权重 | 来源需求权重版本 |
| AND 任务份额 | 当前 AND 组内分配给本任务的份额 | AND 成员数量和分配版本 |
| 冻结结算预算 | 本任务本轮最多可结算预算 | 路径权重、AND 份额和冻结版本 |
| 任务基础优先级 | 不含安全层调度配额的 I64 基础排序值 | 来源需求优先级和任务治理规则 |
| 时限状态 | 未到期、临近、到期、无时限等强类型值 | 来源需求时限与当前时间事实 |
| 当前业务状态段 | 当前完整状态特征集合的状态段身份 | 任务领域状态裁决 |
| 状态段当前性 | 当前、历史、失效 | 状态段版本与当前发布关系 |

来源需求活动资格、安全因果图、安全阈值、调度规则和适用性分类规则均不是任务初始化事实。6150 / 6170 调度配额只在执行冻结完成后按当前正式输入形成排序材料；任务结构只长期保留 `T→D` 关系、任务基础优先级及本次调度实际消费投影的不可变证据引用，不保存可冒充“当前执行授权”的第二份值。配额为零不阻断承接、筹办或执行冻结；全局控制态与安全硬否决独立门控。初始化、筹办和冻结属于内部治理，不需要现实执行授权。

### 4.4 等待与重新触发

| 特征类型 | 值语义 | 合法来源 |
| --- | --- | --- |
| 等待类型 | 等待子目标、方法补齐、条件、输入、外部事实或时间 | 筹办闭合结果或执行后合法变化 |
| 等待条件当前性 | 未满足、已满足、已失效、待复核 | 等待条件及其合法生产者 |
| 重新触发状态 | 未触发、已触发、触发失效 | 正式子结果、状态动态或来源 / 方法事实变化 |

| 特征类型 | 值语义 | 合法来源 |
| --- | --- | --- |
| 执行轮次 | 单调递增的本任务执行轮次 | 合法执行开始入口 |
| 执行输入当前性 | 当前、过期、冲突、待复核 | 冻结输入和执行前重读 |
| 方法运行当前性 | 未开始、运行中、已结束、已失效 | 当前方法运行事实 |

| 目标达成裁决 | 未裁决、未达成、已达成、证据不足 | 实际结果与任务目标比较 |

| 剩余差距 | 与目标值域一致的有量纲差距 | 当前实际状态与目标状态比较 |
| 验证裁决 | 未验证、验证通过、验证不通过、证据不足 | 方法验证特征和实际证据 |
| 归因状态 | 已归因、待归因、多来源、证据不足 | 方法、动作动态和因果证据 |
| 禁止结果状态 | 未出现、已出现、待复核 | 禁止结果集合与实际结果比较 |
| 附带结果路由状态 | 无附带结果、待路由、已路由、路由拒绝 | 非当前目标的有效结果及对应需求 |
| 结果当前性 | 当前、已被后续事实替代、已失效 | 实际结果版本和世界状态版本 |
| 目标达成比例 | 有边界的目标满足比例，不得替代逐项证据 | 目标特征集合与实际结果集合比较 |
| 完成当前性 | 未完成、当前完成、完成证据失效 | 目标达成、验证和结果当前性联合裁决 |
| 结算候选状态 | 未形成、已形成、已提交、已拒绝 | 合法完成事实和路径预算 |

`需求满足记录投影` 和 `价值结算投影` 都是任务领域按上游权威事实形成的读取投影，不是任务专有的第二份结算记录。需求正式结算记录只允许 5160 定义的 `已满足` 结论；“部分入账”只描述 4320 的独立价值预算消费，不得写成部分满足、部分完成或另一种需求正式结论。投影清空或重建不得改变需求满足记录、价值结算事实、冻结预算或防重复领取事实，任务领域也不得反向改写这些上游结构。

### 4.6 失败、取消和终止

| 特征类型 | 值语义 | 合法来源 |
| --- | --- | --- |
| 业务失败分类 | 合法失败条件的具名强类型分类 | 方法失败条件、禁止结果、技术能力 / 资源访问许可结果或安全硬否决 |
| 失败证据当前性 | 当前、失效、待复核 | 实际结果、动态和失败条件版本 |
| 取消当前性 | 未取消、已授权取消、取消完成 | 取消授权关系及版本 |
| 动作停止确认 | 无动作需停止、停止中、已停止、停止证据不足 | 执行动作和停止动态 |
| 终止版本 | 失败或取消终止事实版本 | 任务领域终止提交入口 |

内部逻辑错误不属于业务失败分类，禁止通过这些特征写成任务失败。

## 5. 方法声明的开放任务特征

方法可以声明任务专有业务特征，但必须给每个特征指定以下角色之一：

```text
输入
输出
验证
归因
具名许可与风险
失败处理
结算支撑
组合协调
```

开放特征不进入固定全局枚举。任务只挂载当前选择方法或组合方法正式声明的特征类型。

每条方法特征挂载记录至少包含：

```text
任务身份
特征类型身份
来源方法身份
来源方法内容版本
特征角色
激活原因
筹办轮次
是否必需
是否已填值
是否已验证
当前性
```

## 6. 初始化顺序

任务根据需求初始化时按以下顺序形成：

1. 每次承接输入携带一个当前具体需求 D、准备幂等身份和存在建立 / 任务核心建立 / 阶段特征实例建立 / 首态建立 / P1 建立 / 首迁移六阶段幂等身份组，并读取 D 所属需求列表项 L。六阶段键由原业务请求一次性分配，不是初始化中间步骤的临时派生值。
2. 按 L 查询 0..1 个当前任务；无任务时先经存在 owner 创建任务专属正式存在 E，再由 task owner 原子创建 T、`T→L`、`T→D`、`T→E`、首个任务轮次 R1 及各自初始生命周期，有任务时验证同锚点和同目标后幂等新增 `T→D`。
3. 不自动承接 L 的其它成员；逐项校验当前来源需求目标等价并形成值式单目标投影，不建立任务目标第二权威。
4. 初始化第 4.1 节中能够由本次显式来源确定的持久治理特征；不得在初始化阶段建立现实执行授权或当前调度配额投影。
5. 初始化具名来源需求锚定特征，且不得用任务默认值覆盖来源需求明确值；正常调度配额只在执行冻结后按 6150 / 6170 形成，含现实改变步骤的冻结另在任务进入执行阶段前读取一份自我现实执行授权。
6. 当前方法尚未选择前，不挂载方法开放特征，不创建无来源的独有特征槽。
7. 方法选择后，按第 5 章建立挂载记录并激活方法声明特征。

## 7. 方法切换

方法切换必须保留旧方法选择记录、旧挂载记录、旧特征和值、方法运行引用、验证和归因证据。旧特征标记为历史或失效，新方法特征完整挂载并验证后才成为当前集合。

不得原地覆盖方法版本，不得把旧方法业务特征继续当作新方法的无来源当前特征。

## 8. 首态、P1 与第一动态初始化

新任务核心读回后，初始化方必须经 ARCH-L2 特征公开面取得全局唯一“任务主阶段 / 业务状态段”基础定义，并为 E 建立唯一实例。状态值使用强类型有序 I64 材料：`{筹办=1, 待初次筹办=1}`为无动态首态，`{筹办=1, 筹办中=2}`为后态。首态和后态绑定同一 E、同一特征实例。

初始化顺序固定为“首态 -> P1/A1 -> 首态到筹办中的迁移”。P1 由 task owner 保存对 T、R1、E、特征实例和首态的强类型引用，并与版本化初次筹办推进治理动作调用事实 A1 同次建立；第一状态变化以 A1 为来源，由状态 / 动态两个 owner 的既有原子 provider 形成第一动态。P1、函数名、日志或固定魔数不得冒充 A1。各 owner 事实代次分别回显并独立读回，不得把初始化写成跨全部 owner 的一笔事务。

六阶段幂等身份全部非零且两两不同，逐字段进入请求、首次记录和精确重复比较。准备幂等身份固定等于 P1 建立键，以维持首次记录定位；全局阶段特征定义继续使用固定 `TASKSTAG` 键，不占用六阶段键。初始化、重试或回流重判不得根据时间、运行代次、哈希、需求 / 任务 / 回流记录身份或某一阶段结果补造其它阶段键。

首次记录保存版本 2 原完整请求、六阶段键、治理函数合同版本和规则版本。发布未知只能以历史保存的原键逐段收敛；历史版本 1 记录因缺少六阶段键，只能返回`初次请求版本待迁移`并零写，不得升级原记录或猜测缺失键。任务子目标回流触发新初次筹办时，P1 键与回流记录稳定编码相同，其余五键必须由回流请求的上游原信封提供。

`L2任务虚拟存在身份`只作新任务 E 的兼容引用投影；正式资格来自 `T→E` 和存在身份来源。旧私有存在、字符串阶段、任务枚举字段、缓存或日志不得用于补齐本节初始化。

## ARCH-L4 初始化边界（20260824）

任务初始化属于 ARCH-L4。初始化可建立业务任务身份与对 D/L/E 的关系，并请求唯一 `L2存在结构服务`创建任务专属 E；兼容虚拟存在字段只包装 E 的稳定编码。任务初始化不得直接建立 task-owner 私有状态 / 动态权威，也不得把列表成员自动提升为来源需求。
