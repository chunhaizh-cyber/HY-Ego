# 内部治理闭环与价值回流规范

编号：内部治理-价值回流-001
日期：20260821
版本：v0.2 修订稿
状态：待确认规范

## 1. 定位

本规范定义内部治理、安全、服务、需求、任务、方法、学习、结算和价值回流之间的职责边界。它是整体关系设计输入，不替代 5090、5160、6100—6170、5230、5250 等对象专门规范，也不把统计值、判断结果或学习材料提升为持久化对象。

现行总链为：

```text
安全 / 服务状态变化
-> 内部治理读取并形成被动动态与治理过程材料
-> 需求或未闭合学习需求承接
-> 唯一活动任务
-> 唯一当前方法路径
-> 实例方法
-> 正式任务实际结果
-> 任务目标达成裁决
-> 任务生命周期完成
-> 各承接需求目标满足裁决
-> 需求唯一正式结算
-> 普通任务现实影响 / 服务合同绑定
-> 价值结算
-> 安全值 / 服务值变化
-> 下一轮内部治理
```

内部治理、学习、普通任务和价值回流分别拥有不同的事实边界：

| 领域 | 只负责 | 不负责 |
| --- | --- | --- |
| 内部治理 | 被动动态、治理过程材料、需求承接触发 | 直接改变现实目标、安全值或服务值 |
| 学习 | 改变自我内部虚拟数据，形成方法能力变化材料和候选 | 直接改变安全值、服务值或现实目标 |
| 普通任务 | 改变现实世界在自我内部的投影，并发布正式实际结果 | 直接写需求结算或价值状态 |
| 普通任务结算 / 价值回流 | 经需求结算和服务合同规则形成可控价值变化 | 用日志、压力值或方法成功替代正式结算 |

## 2. 三类核心值

### 2.1 安全值

安全值表示自我持续存在能力的正式状态。安全值变化只能来自被动变化系统或具备正式资格的任务 / 服务价值结算事务；学习任务、内部治理和压力值不能直接写入安全值。

### 2.2 服务值

服务值表示自我对外提供服务形成的价值状态。服务值变化由服务合同结算和服务值时间维护规则承接；学习任务、内部治理和压力值不能直接写入服务值。

### 2.3 压力值

压力值是独立统计特征，只表示当前未闭合事项造成的治理负载。它不是价值、资格、完成性或安全事实。

压力来源只能是可重建的值式计数或状态投影：

- 待完成任务数量；
- 待学习方法数量；
- 无可执行方法的未闭合学习需求数量；
- 待验证方法候选数量；
- 待处理治理事项数量；
- 带合法生产者和回流条件的阻塞事项数量。

上述计数不得通过建立“能力缺口”节点取得。压力值只参与任务优先级和调度排序，不直接改变安全值、服务值或需求结论。

## 3. 内部治理职责

内部治理负责读取当前事实，形成被动动态、治理过程材料和结构化需求承接输入：

```text
读取当前事实
-> 识别未闭合事项和目标变化
-> 读取方法六项静态能力描述并形成匹配判断
-> 形成需求、学习需求承接或合法等待材料
-> 交由正式需求入口和任务治理处理
```

内部治理产生：

- 被动动态；
- 治理过程材料；
- 需求或学习需求承接材料。

内部治理不得直接创建任务、方法、能力缺失节点、能力缺口对象、任务完成事实、需求结算记录或价值状态。

能力缺失只表示：

```text
目标变化
-> 六项静态能力描述全量匹配为空
-> 形成“无可执行方法”的判断结果
```

该判断结果不是节点、候选对象、压力实体或任务 owner。它只能沿需求统一入口形成未闭合学习需求承接，或在有合法生产者和回流条件时形成合法等待。

## 4. 普通任务职责

普通任务是现实影响过程的组织单位，主链为：

```text
需求列表项
-> 唯一活动任务
-> 唯一当前活动方法路径
-> 实例方法
-> 正式任务实际结果
-> 任务目标达成裁决
-> 任务生命周期完成
```

任务完成表示任务生命周期已经按 5210 的目标达成、验证、结果当前性、完成来源和版本条件收束。任务完成不等于需求满足、服务成功、安全提升或价值结算。

任务实际结果必须绑定任务、实例方法、执行轮次和正式结果身份；方法返回、日志、回执文本、压力值或缓存命中不能替代正式结果和独立读回。

## 5. 方法职责

方法负责改变任务目标所指向的现实状态。方法执行可以产生动作、实际状态、动态和任务结果材料，但方法成功不直接表示：

- 任务完成；
- 需求满足；
- 需求已正式结算；
- 价值增加；
- 安全值或服务值变化。

候选方法可以有多个，但当前活动路径每轮只能一条。方法能力变化由学习形成材料，由方法系统封装并发布后继方法版本；不建立能力缺口对象。

## 6. 任务完成、需求满足与价值结算分层

三者必须分开：

### 6.1 任务完成

```text
正式任务实际结果
-> 任务目标达成裁决
-> 任务生命周期完成
```

目标未达成进入 `目标未达成待重筹办`，不写任务失败，不写需求结算。

### 6.2 需求目标满足

任务完成后，需求领域逐项读取当前承接需求成员的目标合同、实际状态、必要动态和结果身份，形成每个需求身份的目标满足裁决。需求列表项只提供聚合入口，不替代需求身份。

### 6.3 需求唯一正式结算

只有单个需求目标满足裁决为已满足，且来源任务完成、正式结果身份、实例方法身份、执行轮次和同源材料一致时，才可由 5160 发布该需求唯一正式结算记录。

结算失败或暂不可执行时，需求结算结构零变化，不回滚任务完成，不把未结算写成未满足终态。

## 7. 学习与方法能力变化

学习改变自我内部虚拟数据，不直接改变现实世界或价值状态。学习输入来自任务运行事实、目标达成裁决和方法分析材料。

学习触发采用以下值式链：

```text
目标变化未匹配到可执行方法的判断结果
-> 无可执行方法的未闭合学习需求
-> 学习任务或合法学习承接
-> 练习 / 尝试 / 因果反推
-> 方法能力变化材料
-> 待验证方法候选
-> 方法系统封装与发布新版本
```

上述“未闭合学习需求”“待验证方法候选”和“待学习方法数量”都是可重建值式材料或正式需求 / 方法对象，不是能力缺口对象的替代命名。任何学习分流不得建立能力缺口节点、能力缺口关系或独立缺口 owner。

因果反推可以作为学习获取方式，把客观规律转换为可控制的候选方法能力；它只能形成分析材料和候选，不直接发布方法或修改价值状态。

## 8. 普通任务现实影响与价值回流

普通任务的现实影响必须经过以下顺序：

```text
现实变化
-> 正式任务实际结果
-> 任务目标达成裁决与任务完成
-> 各需求目标满足裁决
-> 需求唯一正式结算
-> 读取当前服务合同或服务准备
-> 形成服务生存聚合输入
-> 价值结算
-> 安全值 / 服务值变化
```

需求已满足不等于服务合同已完成，服务合同绑定不等于价值已入账，服务聚合输入也不等于安全值或服务值变化。价值变化只能由对应服务生存事务按安全、服务、预算、完整时间和归因合同一次发布。

任何中间材料，包括日志、回执、方法成功、学习完成、压力值、未闭合学习需求或候选方法，都不能直接作为价值变化依据。

## 9. 禁止事项

禁止：

1. 内部治理直接修改现实目标、安全值、服务值或任务完成事实；
2. 方法成功直接增加服务值或安全值；
3. 学习完成直接增加服务值或安全值；
4. 压力值直接改变安全值、服务值、需求满足或结算结论；
5. 需求满足直接等同价值结算；
6. 把任务完成、需求满足、需求结算和价值变化压进同一个 004-06 函数；
7. 建立能力缺口节点、能力缺口关系、能力缺口 owner 或能力缺口数量事实；
8. 把“无可执行方法”的判断结果持久化成能力对象；
9. 用历史结算直接证明当前状态；
10. 用显示、日志、缓存、普通布尔值或计数器替代权威结构化事实。

## 10. 当前完成边界

本规范冻结：

- 内部治理只产生被动动态和治理过程材料；
- 学习只改变自我内部虚拟数据；
- 普通任务改变现实世界在自我内部的投影；
- 任务完成、需求满足、需求结算和价值变化分层；
- 压力值只参与优先级；
- 能力缺失是方法匹配判断结果，不形成能力缺口对象；
- 三项学习压力来源改为待学习方法数量、无可执行方法的未闭合学习需求数量、待验证方法候选数量。

本规范不证明：

- 任务完成代码已经接通；
- 学习任务代码已经接通；
- 压力值计算已经实现；
- 004-06 已完成重构；
- 需求结算、价值结算、安全值或服务值变化已经形成完整生产闭环；
- 完整内部治理循环或跨进程恢复已经完成。
