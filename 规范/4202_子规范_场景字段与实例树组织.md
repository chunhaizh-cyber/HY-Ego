## 1. 范围与七字段

本规范展开1150的七项逻辑字段，不额外增设本体字段。底层仍为L1节点、关系和值；实际根是有稳定身份、可独立读回的组织节点，实例树是根与正式组织父子关系形成的结构，不是SQL专表、查询入口或缓存树。本版冻结目标机器语义，不冻结新C++类、DTO、关系数值编码、角色启用载荷、跨分区提交函数或存量转换算法。

| 字段 | 基数与读取要求 |
| --- | --- |
| 场景节点身份 | 一个稳定节点；场景/存在视角不产生不同对象编码。 |
| 特征根 | 恰一实际节点，组织本场景作为存在时的自身准确特征。 |
| 状态根 | 恰一实际节点，组织状态实例；内部具体状态视图须按第3.2节完整绑定发生场景、被描述存在和状态引用，区分本树内容与外部复用。 |
| 动态根 | 恰一实际节点，组织该场景发生的动态实例；实际内容按4210。 |
| 关系根 | 恰一实际节点，组织内部存在间的关系描述实例；根存在不证明关系事实成立。 |
| 存在列表 | 0..N个直接场景成员引用，不把后代或组成子存在伪装成直接场景成员。 |
| 直接子场景集合 | 0..N个直接子场景关系，递归展开相同结构；与存在视角读取不重复建包含事实。 |

四个根身份互异，每根只绑定一个场景和一种组织角色；不能共用一个根再用索引区分四类，也不能共用概念根。场景与根、根与树内实例之间使用正式具名关系，不要求场景行保存数组。新完整场景即使尚无实例，也须能读回四个空根；缺根、重根、错根和未启用场景视角必须与合法空树分账。

普通存在可暂不具有场景四根。按需要启用场景视角时，在同一稳定节点建立组织结构，完整提交前不能宣称场景可用；读取不得自动启用。已有特征及引用按原事实复用，不改准确值、不复制存在。名称不新增为第八字段，沿该对象的适用存在概念及名称关系取得，允许无名称。场景作为其它对象的特征材料继续服从7120，不能直接强转为1130准确F身份。

## 2. 同节点视角与递归包含

1. 同一对象的存在和场景视角共享稳定身份；视角成立须由正式结构读回证明，不因名称、位置或字段外观猜测，不在L1改写节点类型、重复注册旧族身份或另建镜像对象。
2. 普通存在可先有特征或组成子存在，再按需要启用场景视角；未启用不限制存在正常使用。启用不改变原直接归属，也不让对象成为自身成员。
3. 对同一对象，直接组成父、直接场景成员归属和直接子场景归属合计至多一项。兼具场景角色的对象不能以子场景身份归甲、又以存在身份归乙；同一父下也不能重复建立两种包含事实。
4. 同一直接包含事实可有不同读取视角：子场景在“把场景看作存在”的查询中出现，只是原关系的角色投影，不另建成员边。已有成员或组成归属的普通存在启用场景视角后，子场景遍历依据该包含链及角色读回，不再补第二条场景父边。
5. 直接场景成员、组成子存在及子场景来源分别标识。内部完整存在视图可组合这些来源并按稳定身份去重，但不保存第二权威列表；发动机组成汽车、乘客属于车内范围，不能因同处内部视图就认作同类组成。
6. 父场景间接包含子场景内的存在，通过递归查询取得，不保存越级直接归属。对象包含的全部关系联合无环；角色展开不新增自身到自身的边。没有已知子关系只表示当前粒度不再展开，不证明客观不可分。
7. 世界树从场景根沿子场景/已启用场景视角的合法包含链递归。根归属和现实世界选择仍须正式证明；不从无父、缓存或位置猜测根。跨世界隔离继续服从0050。

## 3. 实例组织树与跨树引用

```text
场景节点（同一对象也可作为存在）
├─ 特征根 ── 自身特征实例组织树
├─ 状态根 ── 内部状态实例组织树
├─ 动态根 ── 内部动态实例组织树
├─ 关系根 ── 内部关系描述实例组织树
├─ 存在列表 ── 直接成员引用
└─ 直接子场景集合 ── 递归相同结构
```

每棵树有一个实际根。实例在组织关系下至多有一个组织父，沿组织边可回查唯一归根路径，禁止组织自环、重复组织父及跨根组织拼接。树可只有根和一层叶子；没有有意义的细分时不强制新建中间分类节点。实例内容、组成及来源是否可复合仍由该实例合同确定。

对象包含边、实例组织边、内容/来源引用边是三种不同关系角色，分别校验。动态D2和D3都可引用D1为组成来源，这不使D1取得两个组织父；状态引用F也不把F挂入状态组织树。跨树引用不用于遍历组织父链，也不能冒充包含边规避无环约束。

准确F允许无宿主、无归树地独立成立。纳入某场景组织时，未归树实例可在合法合同下取得组织归属；已经归其它树的F只复用引用，不移动原节点、不建立第二组织父，也不为树形复制准确内容。本场景特征根的完整使用视图须区分本树组织实例和外部复用引用。

已知特征与当前采用继续按7150由存在类唯一维护，特征根不是第二份已知集合或当前值表。组织归属回答“实例在哪里组织”，已知引用回答“对象具有哪些特征”，采用回答“此刻采用哪个F”；不得保存两份同义权威边。特征根不得把内部全部成员特征算作场景自身特征，也不得恢复F内值域积累、三次命中或特征分裂树。

实例根与概念根严格分开：本规范动态根是每场景的动态实例根；7190的动态概念本体根由唯一概念owner承载，多父DAG规则不移入实例树。概念引用实例作为来源，不改实例组织归属。

### 3.1 整体观察与内部递归

场景负责组织，存在是被描述对象。把对象作为一个整体观察时，其自身状态和整体变化由发生所在的场景组织；把对象的组成部分或内部成员作为独立存在观察时，按需要启用该对象的同节点场景视角，内部状态和动态仍由这个场景组织。继续展开子存在时重复同一规则，不另设“存在内部状态仓”。

- 道路中的汽车：汽车整体位置状态及移动动态归道路场景；汽车作为场景时，车轮、发动机等内部存在的状态及动态归汽车场景；发动机进一步展开时同理。对象身份不变，不建立自身成员边。
- 更精确地测量汽车颜色或整体轮廓，仍可能是在描述汽车自身，不因精度提高、画面放大或特征增多就强制启用内部场景。只有转为描述独立的内部存在，才按其合法包含关系选择对应场景视角。
- 场景不是相机画面或观察者位置。一个画面覆盖多个场景不把它们自动合并，观察者位于甲场景也不使被观察的乙场景事实归甲；记录须有被描述对象及发生范围的依据。
- 外层可以经合法引用及分层提供者读取内部事实，但查询可达不改变原主体或归属，不把全部后代状态重复组织到每个祖先根。由内部变化形成整体动态须按4210保留组成及来源，不能直接把子存在状态改称整体状态。

未知发生范围、缺少场景视角或无法定位主体时，可以保留合法中性内容或待处理输入，但不得猜挂最近场景、世界根或对象自身并返回完整场景事实。后续深入观察不把先前整体记录迁入内部，也不倒推先前已经观察到内部细节。

### 3.2 中性状态内容与具体使用绑定

1160状态内容仍为中性的类型、准确值和时间，允许独立形成、读取及共享；“场景内某存在的状态”则必须具有下列完整使用绑定：

```text
发生场景 C + 被描述存在 E + 中性状态 S
```

这是引用关系组的逻辑合同，不是新增状态本体字段、节点族、事件仓或独立CRUD服务。C回答本条具体描述发生在哪个场景层级，E回答描述谁，S提供正式特征类型FT、当时的固定准确值和强时间；来源另沿合法关系核验。被描述特征由E与S内正式FT共同确定，不另设属性身份或保存FT副本。现行存在当前采用仍按7150的E/FT合同至多一项；同一对象的不同部位须以子存在区分，不同特征语义须以不同正式FT区分，不把来源或传感器编号当作第二个属性键。

1. 每组恰绑定一个C、一个E和一个S。组成关系须有可正式读回的共同关联，不能按共享S把互不关联的场景边、主体边和状态引用做笛卡尔连接。FT只从S内容读回并与准确来源核验；同FT、同F、同值或同一根都不自动证明同一主体或一次观察。同E同FT用于归入同一被描述特征的观察序列，不用于合并不同观察。
2. 状态内容的唯一组织归属与使用绑定的发生场景分账。S已组织于C1时，C2只能合法复用引用，不能给S增加第二组织父；若C2确有自己的观察依据，可以建立完整的(C2,E2,S)绑定，其发生场景不从S的C1归根路径推导。C2仅查看C1的记录时，保留原绑定，不因此生成C2发生记录。
3. 例如甲在房间一、乙在房间二，同一时刻温度均为20，可共享正式FT为温度的同一中性S，但必须分别核验(房间一,甲,S)和(房间二,乙,S)，不能生成另两种交叉配对。共享S不是同一次观察；同一C/E/S也不强制合并不同来源的观察，一次发生被多处引用则不能重复计数，须按真实来源识别。
4. 场景状态完整视图读取绑定组、S内容、本地状态根以及本树组织或外部复用路径，在同一一致性范围逐项互证。E在发生时的直接或合法分层包含依据必须可核验，不用当前成员关系补历史。只有中性S读回成功或根中有S，不构成具体状态读取成功；缺绑定与合法空树分别返回。
5. 状态类唯一写中性内容；场景类按其既有组织/使用关系职责唯一维护本场景绑定，不复制S内容，不写存在当前采用。应用负责取得来源和解释观察，DATA只核验结构。完整绑定的必要关联共同成立后才能作为一组公开，禁止半组读取或后续补边时暂时串配；物理分组及参与分区的精确合同仍须按第8节冻结。
6. 普通流程先发布并读回S，再建立完整绑定及所需组织/复用关系，最后共同读回；中性S创建不以未建立的场景绑定为循环前置。后一步失败如实保留已发布内容及原请求，不假称整体回滚或换身份重造。绑定中的C/E/S不原地改写，修正另建合法绑定；退出使用不隐式删共享S，也不改写已发生描述。保留、受保护删除及清理按第7节，不新增永久保存承诺。

## 4. 固定归属、移动与历史

“根内信息固定”指既有准确内容和发生归属不被后续成员迁移改写，不是根不能增长、成员数量固定或实例永久不清理。

- 场景内移动：直接成员关系保持，按实际变化更新存在采用，必要状态/动态及新关系描述进入相应实例树。
- 存在跨场景移动：同一节点原直接归属被目标归属原子替换；旧状态、动态和关系事实留在原组织中，父场景间接包含由新链推导。
- 兼具场景视角的存在移动：四根仍绑定该对象，不重挂到目标场景四根下；原外部场景的记录不随其移动。组织绑定固定不等于空间位置不变。
- 旧“甲在乙上方”等关系只表达原上下文事实；成员移动后须按当前材料重新求值，不能因旧节点可读就当作当前关系。

跨场景动态片段及边界不明按4210，不凭当前成员列表补造历史归属。事件时间、当前采用、当前成员和组织归属分别读取，不给四根增加通用“当前/历史”“事实代次”业务字段。

## 5. 关系根用途与准入

关系根只组织内部存在之间上下、内外、远近及多维条件组合等关系描述。实际参与方、准确来源、结果和概念定义分账；比较/求值由4150/4151等应用完成，场景数据类不自动穷举、计算、命名或判断关系真伪。

关系根不等于L1关系表，不组织组成/归属管理边，不建立新关系概念本体根或独立内容owner。只有内容与持久准入合同已正式成立的关系描述才能组织，空根合法。

0300 C038保持未决，本规范不授权新增持久二次实例，不把调用期I64结果变成可恢复事实，也不以普通关系边、自由文本或新包装节点绕过限制。既有合法概念及临时求值可继续使用，但不因此填充持久关系实例树。

## 6. 数据操作与完整发布

下列是必须提供的操作语义，不冒充已实现函数：

| 能力 | 责任与结果 |
| --- | --- |
| 建立/读取场景，启用已有存在场景视角 | 场景类组织完整角色及四根；身份不变，缺根不返回完整成功。 |
| 按场景及根角色读取根、读取实例树 | 场景类维护根绑定和组织关系；返回正式节点、关系、归根路径，读取不补建。 |
| 组织实例、建立/解除使用引用 | 先由所属数据类核验正式事实，再由具名场景结构入口组织；引用不冒充组织归属。 |
| 存在列表/子场景的增、删、改、查 | 场景类处理场景关系，组成边由存在类负责，联合校验唯一归属及无环。 |
| 已知特征与当前采用读写 | 存在类按7150唯一维护，场景应用组合读取，不复制setter或权威集合。 |
| 正反向、直接及递归查询 | 读取同一事实，声明范围、关系类别和有限预算；去重/递归投影不写回。 |
| 退出场景视角、删除根或场景对象 | 明确目标并闭合根、成员、实例及跨树引用保护；不隐式删除共享对象或整棵子树。 |

场景类只写本类角色、根和组织/场景关系，包括第3.2节本场景的完整状态使用绑定；F、状态、动态及合法关系内容仍由所属唯一数据服务写入，动态组成/来源关系不转移给场景类。不存在新L1领域入口、新事实仓或调用方自选owner。跨既有分区协调须经正式强类型合同，不泄露写集和端口。

新完整场景或角色启用所需根绑定及完整性须在一个可靠提交边界共同成立；发布前失败不暴露半场景。归属替换及联合守卫也须原子闭合，不用两次CRUD先删后加。已确认发布后读回失败不伪装回滚，按原请求及L1可靠性合同收敛。

读取在同一明确一致性范围证明身份、场景视角、四根互异且归属正确、组织边完整、实例引用合法及直接关系唯一。预算不足、目标缺失/退出/已清理、错角色、引用冲突、读取漂移及内部不一致与合法空结果分账；非成功不返回假完整树。索引命中后仍须正式读回。

## 7. 保留、退出与恢复

解除成员/使用引用不删除目标。退出场景视角不同于删除同一对象存在身份；其它角色、成员、需求、特征和历史引用仍受保护。根仍有受保护组织内容或外部引用时，不得直接删除、换根或跨场景迁移整个历史树。

状态/动态有限TTL、数量上限、墓碑及引用闭包继续按0050/1160/4230；场景根不授予永久保留资格。清理须处理受影响组织关系和活动来源引用，清理后读取明确返回已清理/不完整，不凭残留目录补造实例，也不级联清除受保护内容。根不是状态/动态实例，不按成员TTL直接清理。

状态使用绑定及动态对该绑定的来源引用须纳入依赖与清理闭包；解除绑定不允许仍依赖它的消费者读成完整发生事实。允许保留的过期普通引用须明确返回已清理或不完整，不利用残余C/E/S引用重建发生。恢复须恢复并互证实际根、完整使用绑定和组织关系；只能重建投影/索引，不能猜造缺根或补配主体。可靠性记录仍留在L1及具名合同边界，不复制到七字段。

## 8. 实施边界

后继实施须具名冻结同节点身份映射、唯一写入分工、关系类型、根创建/挂接、当前/历史读回、失败、清理、恢复和存量转换；现行结构与被替代生产结构不能长期双写。本文不删除代码或存量事实，不改变无关启动、动作、安全和概念合同。

第3.2节C/E/S状态使用绑定的物理身份、强类型引用、关系角色、请求/结果、共同发布、独立读回、失败重试和存量材料转换尚须由后继物理合同冻结；绑定不当然要求新增节点或owner，FT仍从S取得。既有普通引用、状态当前选择或主体关系不能直接重释为完整绑定。动态类只能依赖该后继合同提供的窄只读绑定提供者，不能散装拼接C/E/S或反向持有完整场景类。

任何被替代的场景DTO、宿主绑定、目录投影、关系编号、解析分支和过程材料均不取得现行机器语义，也不得形成兼容写入口。L1依法保留的历史材料继续受可靠性合同保护，但不能被新场景类猜测转换或直接作为完整七字段场景、四根、使用绑定或组织关系读回。

## 9. 最低验证矩阵

| 情形 | 必须成立 |
| --- | --- |
| 新空场景 | 同一对象身份，四个互异实际空根，成员/子场景为空。 |
| 既有存在启用场景视角 | 原身份、准确特征、采用和直接归属不变，不新增宿主对象或自包含。 |
| 缺根、重根、错根 | 不返回完整场景，不用缓存修复。 |
| 两场景共享F | 同一F至多一个组织父，第二处仅引用，各自采用独立。 |
| 两场景/两主体共享中性S | 两个完整绑定分别可核验；无交叉配对，无第二组织父，不把内容归根当作另一绑定的发生场景。 |
| 同E同FT多次观察或多来源观察 | 保留可核验的真实来源，不按E/FT、相同S或相同C/E/S强制合并；同一次发生的多引用不重复计数。 |
| 不同部位或不同特征语义 | 分别由子存在或不同正式FT区分；不新增独立属性身份，不放宽同E同FT当前采用唯一性。 |
| 整体、子存在及更高精度观察 | 按被描述对象递归选择场景；不因看得细强制展开，不复制或迁移旧记录。 |
| 画面跨场景、观察者位于外部 | 不按画面或观察者位置合并场景、改发生归属。 |
| 中性内容成功但绑定缺失/半组 | 只返回内容结果，具体状态视图不成功；原请求收敛，不猜边补齐。 |
| 当前成员变化或内部后补认知 | 原绑定及观察粒度不改写，不补越级直接归属或虚构先前内部观察。 |
| D2/D3都引用D1 | 合法组成引用不形成多组织父，不复制D1。 |
| 子场景/存在角色混用 | 双父及重复归属拒绝，同事实角色投影不另建边。 |
| 递归与混合包含 | 祖先能查到后代但直接列表不补后代，混合环拒绝。 |
| 场景内/跨场景移动 | 前者不改归属，后者原子换归属；旧内部事实不搬迁、不当作当前关系。 |
| 可移动存在的场景视角 | 四根仍绑定原对象，空间变化不构成结构非法。 |
| 关系根与临时求值 | 空根合法，C038未裁决时不新增持久二次实例。 |
| 并发、失败、超预算 | 无半场景、双父或假完整，发布后不伪装回滚。 |
| 删除、TTL与恢复 | 保护引用，清理如实返回，恢复互证根而不是只重建索引。 |
