# 1130 根规范 特征节点

编号：1130

版本：v3.4
状态：正式根规范

直接上级规范：0050。

直接依赖规范：2100。

相关边界规范：1120、1140、1160、1170、1180、4015、4110、4115、4180、4181、5170、7160。

## 1. 权威边界

本规范是实例特征的根合同。实例特征以实际值为事实来源；特征概念值域只负责分类、单位和规则选择，不作为实例写入准入域，不得据此拒绝材料类型正确的实际值。

本文中的历史值只指某个实例特征实际出现过的去重准确值及其命中次数，不是底层操作历史、事实代次、事务日志或审计账。

## 2. 对象定位与持有关系

实例特征是由一个既有节点持有的实例特征节点，通过外部父子关系挂在持有节点下。持有节点可以是存在（含任务、方法、词条、语言材料范围、指代实例、代词概念等信息存在，0050第1.4节）、需求（其F更新不生成状态，0050第1.4节）、场景、状态、动态或其它特征节点；二次特征可以作为状态、动态的实例特征被其持有。特征owner只核验节点和关系，不解释持有者的业务类别。

规则：

1. 每个可读回实例特征恰有一个外部父节点。
2. 同一持有节点下，每个特征类型根至多一个直接实例特征。唯一例外是二次特征（1180）：同一持有者的同类型二次特征按结果方向（大于零、等于零、小于零、大于等于零、小于等于零）区分，同类型同结果方向至多一项，不得重复。
3. 归组子特征仍是普通实例特征，由父特征持有并带归组子特征标记。

## 3. 准确值承载

1. I64标量直接保存在实例特征中。
2. U64数组、I64数组、UTF-8字符串、二维二值格和三维二值格先由特征值owner（2100）保存，再引用特征值节点；不得复制为实例节点内部的裸数组或字符串。
3. 写入、读回和比较非I64原始材料时，必须确认特征值节点存在、可完整读回且材料物理类型一致。直接信息节点引用按第3.1节处理，不送入原始材料读取路径。

### 3.1 信息引用型特征

引用型特征的准确值引用其它正式信息节点（方法M、需求D、任务T、存在等），由正式特征类型决定它是单引用还是完整集合，并限定成员类别。

1. 引用只保存成员身份，不复制成员内容，不改造成普通存在，不增加组织父节点，不移动原树归属，不授予执行、承接或修改内容的权限。
2. 集合是一个完整准确值：无顺序语义、无重复；零成员是已知空集，一个成员仍为单元素集合；尚未取得当前值不等于空集。不得按数量在单值与集合间切换，也不用多个同类型单值特征实例表达多项。
3. 集合变化与成员内容变化分别处理；集合未变不能推定成员内容未变，读取须经成员原owner。需要一个成员时须核验选择条件及唯一性，不能任选首项或按编码大小猜测。
4. 成员类别由特征类型限定：方法集合不得接收Vm、C、R或缺失方法头，任务集合不得接收Vt、X、A，需求集合成员必须是正式D。不能凭非零编码、名称或字段形状猜类别。
5. 需求引用遵守主体合同：宿主与目标的业务关系须明确，类别正确不证明关系成立；引用不改变T与D的一对一约束。
6. 服务对象需求特征为具名单引用，当前值引用一个正式被认知需求D；其发生、历史D及来源合同由5170唯一展开。

### 3.2 引用保护与失败边界

1. 写入和读回必须经目标owner证明节点类别正确、身份有效、所需结构可读，并核验具名宿主关系。目标类别和结构有效性是类型及身份约束，不是概念值域准入。
2. 引用正式发布前须建立可阻止目标身份失效的保护，保护与目标退出按同一发布边界竞争；当前值、标准值、历史值、有限值域、集合材料及状态仍保留引用时，保护不得提前解除。保护只保护身份和必需可读结构，不冻结目标的合法内容更新。
3. 解除引用只解除指定来源的关联，不自动删除被引用目标；目标退出仍由原owner证明全部正式引用已退出。
4. 明确未找到、目标已变化、类型不相容、读取故障、资源失败和发布未知须区分；工程故障按工程诊断链处理，不转成业务“不符合”或合法空集合。

## 4. 实例特征信息

| 信息 | 基数 | 含义 |
| --- | --- | --- |
| 持有节点 | 恰一 | 由外部父子关系确定 |
| 正式特征概念 | 恰一 | 当前用于分类、单位及规则选择的特征概念 |
| 实例单位 | 至多一 | 建立实例时从模板概念复制 |
| 当前值 | 至多一 | 最近一次成功写入的准确值 |
| 标准值 | 至多一 | 历史值中命中次数最高的稳定代表值 |
| 历史值命中记录 | 零到多 | 每项保存准确值、命中次数和所属实例 |
| 实例历史聚合值域 | 至多一 | 完整历史值按概念聚合规则计算的当前值域 |

历史不同值由命中记录唯一得出，不建立第二套重复历史事实。比较和聚合规则只由正式特征概念提供，实例不复制规则。

## 5. 写入与概念同步原则

1. 实际值不受当前概念值域限制；概念值域未包含新值时写入仍可成立，随后由历史聚合和概念同步处理分类变化。
2. 每次写入都增加该值的命中次数；只有当前值、历史集合、命中次数、标准值、子特征、聚合域和概念同步均无变化时，才可报告无变化。
3. 实例所属概念由特征owner按实际历史自动同步，可以复用、细分、扩展或改挂概念；这是认知漂移的正常形式，概念修订若与已有概念相同则直接复用。
4. 一次业务变化（当前值、历史、标准值、聚合、归组与概念同步）整体发布；不得把已成立的准确值事实回滚为零写入。
5. 特征当前值实际改变时，由持有者owner在同一发布中生成状态（1160）。持有者为状态或动态的二次特征建立后固定，不生成状态。

建立、取得、添加值、归组、聚合与概念同步的步骤和算法由4110、4115、7160规定；比较算法由4180、4181规定。I64有向差值溢出按4180第8节统一饱和并携带“已饱和”标记，需求目标判定按3100第6.2节；不能比较时返回规则不支持，不得伪装成完全不同。

## 6. 一致性不变量

任一成功读回的实例特征必须满足：

1. 节点类型指向实例特征节点类型；外部上位父子关系恰一。
2. 正式特征概念恰一且目标概念可完整读回。
3. 实例单位、当前值、标准值和历史聚合值域各至多一项。
4. 历史值命中记录准确指回本实例，命中次数为正，历史准确值在概念比较规则下两两不等价。
5. 标准值等价于一项历史值，没有其它历史值的命中次数严格超过它。
6. 当前值存在时，等价于一项历史值。
7. 对外报告的历史聚合值域等于完整历史不同值按当前概念聚合规则的结果；缺失时不得伪造。

## 7. 生命周期与职责边界

实例特征随持有者存在；不提供变更持有者、删除历史值或直接写聚合域的公开能力，实例所属概念只由内部同步改变。持有者被清理时，其实例特征一并清理；被引用的特征值节点按2100回收规则处理。

特征owner负责实例特征字段、建立与读回、当前值/历史/标准值/聚合维护、子特征归组、按实际历史同步概念、维护概念直接实例引用数量和同类型比较。特征owner不负责非I64原始材料保存、创建全新特征类型根、主动共同上位归纳、概念树修剪、多特征组合概念比较、名称关系，以及存在、场景、状态、动态、因果、需求、任务或方法治理。
