## 1. 目标与不变边界

本规范冻结场景特征根首次可用的准确F实例组织物理合同。它只回答“准确特征实例F在场景C的特征实例树中由哪个父P组织”，不写F内容，不建立或退出C的已知特征，不修改当前采用，不解释特征业务含义，也不形成第二个特征owner、存在owner或事实仓。

4204协议v2保持不变：`场景角色组织合同版本=2`、既有六编码交付、登记固定键1、C角色/B/状态/动态请求结果、稳定状态数值和现有关系类型含义全部不得改义。特征组织采用协议v1的独立扩展登记；不得把第七编码塞入`场景角色结构交付`，不得重放键1形成七节点异写集。

本首切片只追加一个未组织新叶F。没有删边、解除组织、换父、重挂、跨树迁移、级联清空或历史改写入口；后继若开放这些能力，须同次冻结引用保护、退出集合、幂等重放和索引失效。

## 2. 所有权与物理关系

特征组织关系类型由场景owner独占，登记为一个普通无属性节点，只承担关系类型角色。组织边同样由场景owner写入：

```text
P --场景特征组织关系类型/角色1--> F
```

`C`与`F`是既有跨owner端点：C本体属于存在owner，F内容属于特征owner；P若为根则属于场景owner，P若为父F则属于特征owner。场景服务只能写自己的关系类型和组织边。关系创建不复制、不修改端点内容或生命周期。

场景特征组织扩展登记使用场景owner全局幂等域的保留常量：

```cpp
inline constexpr L1所有者范围写入幂等身份 场景特征组织扩展登记固定幂等身份{
    0x5343'454E'4546'4F52ULL
};
```

该值仅用于一节点固定登记。普通场景写请求和既有4204入口必须显式拒绝该保留值；4204键1仍只表示原六节点写集。登记成功后以首次材料、确定映射、owner、节点形状和当前/历史事实真实读回恢复同一关系类型；定位缓存丢失不得扫描或补造第二类型。

## 3. 准入语义

组织请求显式携带`C/P/F`、G0、幂等身份和最大路径长度，顺序固定：

1. 校验协议v1、非零G0、非保留普通幂等身份、有效且互异的C/P/F、预算1..4096。
2. 经4204同一场景服务确认C在G0为当前有效场景角色，并取得其精确特征根。
3. 场景服务经其既有`存在结构身份只读提供者`引用，以`Gread=H=G0`调用4203新增的组合窄读；存在类内部调用同L1特征服务既有`读取有界准确特征事实`，同时确认F当前为合法准确特征及C已有恰一条指向F的7150特征成员引用。不得以owner相同、普通节点形状、名称、编码相等、同FT、当前采用或调用方DTO代替。
4. P只能是C的精确特征根，或经本合同历史路径入口在`Gread=H=G0`证明已位于同一C特征树中的父F。父F还须经同一组合窄读证明当前为合法准确特征且C已知P。不得接受仅有入边但未唯一归根的P。
5. 在场景owner全部当前特征组织关系中核验F无入边且无出边。F已有同请求合法父时，仅原幂等键原完整请求可收敛为精确重复；其它键返回实例已组织，跨C/跨根、多父、环、错类型、断路径及“无父但有子”的孤立子树返回引用冲突或内部不一致，不接入整棵子树。
6. 父深度加一不得超过预算。提交严格G0的一条P到F边，角色1；发布成功后独立读回新边、C特征根、P路径、F准确身份与C已知F关系，并再次核验Gread。任何发布后不确定返回已可能发布。

由于目标F在提交前没有本关系类型的任何入边或出边，且P已经唯一归根于C、P不等于F，新边保持全局单父、无环和唯一归根。不得用局部锁、缓存或“同C”猜测替代L1同G0守卫；调用特征或存在服务时不持场景写锁或L1仓库锁。

## 4. 精确C++合同

下列类型追加到`海中鱼巣.领域.合同.场景角色组织`，不修改既有v2类型字段或枚举值：

```cpp
inline constexpr std::uint32_t 场景特征组织合同版本=1;

struct 场景特征组织扩展结构交付 final { 稳定编码 特征组织关系类型; };
struct 场景特征组织扩展登记请求 final { std::uint32_t 版本=1; std::uint64_t G0=0; };
struct 场景特征组织扩展登记结果 final {
    std::uint32_t 版本=1;
    场景角色数据状态 状态=场景角色数据状态::入口拒绝;
    std::uint64_t Gread=0,首次发布代次=0;
    std::optional<场景特征组织扩展结构交付> 交付;
    bool 成功(const 场景特征组织扩展登记请求&) const noexcept;
};

struct 场景特征组织请求 final {
    std::uint32_t 版本=1; std::uint64_t G0=0;
    L1所有者范围写入幂等身份 幂等身份;
    稳定编码 场景,组织父; 特征信息身份 特征;
    std::uint64_t 最大路径长度=0;
};
struct 场景特征组织历史请求 final {
    std::uint32_t 版本=1; std::uint64_t Gread=0,H=0;
    特征信息身份 特征; std::uint64_t 最大路径长度=0;
};
using 场景特征组织事实=场景实例组织事实;
struct 场景特征组织历史结果 final {
    std::uint32_t 版本=1; 场景角色数据状态 状态=场景角色数据状态::入口拒绝;
    std::uint64_t Gread=0,H=0; std::optional<场景特征组织事实> 组织;
    bool 成功(const 场景特征组织历史请求&) const noexcept;
};
struct 场景特征组织写结果_v1 final {
    std::uint32_t 版本=1; 场景角色数据状态 状态=场景角色数据状态::入口拒绝;
    std::uint64_t Gread=0,首次发布代次=0;
    std::optional<场景实例组织回执_v2> 组织;
    bool 成功(const 场景特征组织请求&) const noexcept;
};
```

F资格与C已知F统一采用4203的`存在已知准确特征当前请求/历史请求/读取结果`。场景类以稳定编码C/F调用既有`存在结构身份只读提供者`；结果必须逐字段回显`Gread/H/C/F`，见证返回唯一已知关系编码及F生命周期并满足成功谓词。当前请求等价`Gread=H=G0`；当前采用组不参与该裁决。非成功optional为空，不返回部分路径。准确F完整内容及已知关系生命周期仍由存在类内部调用特征服务和自身历史读取证明，场景类不复制保存或展开解释。

`场景特征组织历史结果`复用既有路径事实形状，但固定`场景根角色::特征`；既有`场景组织历史请求/结果`仍只接受状态/动态，不扩张v2含义。完整路径须从C特征根到F，节点数=边数+1，全部边使用扩展关系类型/角色1并在H有效，逐步唯一入边、节点边无重复、长度不超预算。

- `数据服务.特征类.ixx`：零修改。由已有`存在类数据服务`内部继续持有并调用，不形成特征类到场景合同或存在小合同的反向依赖。

- `数据服务.场景类.ixx`：不import存在类或特征类，不持有具体特征服务和独立已知provider；复用现有`const 存在结构身份只读提供者&`完成F与父F的组合准入。本切片新增场景特征方法/helper继续按既有场景IFC组织方式在本文件内定义；C退出保护追加特征组织边查询，不改变既有函数物理归属。不得新建第二场景服务。
- 物理删除未发布候选`数据服务.场景已知特征读取桥.ixx`、`数据服务.场景已知特征读取桥.impl.cpp`和`数据服务.场景类.impl.cpp`；删除其工程登记，不保留空文件、兼容别名、转发或回退入口。

构造不写事实；扩展登记在服务构造前显式执行。存在提供者、场景端口和场景服务必须绑定同一L1。依赖方向固定为`存在类 -> {存在小合同,特征类}`、`场景类 -> {场景角色组织合同,场景状态使用绑定合同 -> 存在小合同}`；场景类不import完整存在类或特征类，存在类不import场景合同或场景类。工程只删除三个未发布候选登记，不增加生产文件。

## 6. 幂等、发布未知、退出与恢复

扩展登记以固定保留键和固定一节点写集收敛。组织使用调用方非零且不等于1、不等于扩展保留键的幂等身份；同键同规范化C/P/F和同原G0收敛首次结果，同键异义幂等冲突。预算不进入持久语义比较。

发布前入口拒绝、未找到、目标已退出、实例未组织、实例已组织、引用冲突、漂移、预算不足、资源失败和内部不一致均零写。L1明确成功/精确重复后必须在实际当前Gread做独立读回；结果头、映射或读回不确定返回已可能发布。已可能发布只能原键原C/P/F重放，不回滚、不换键、不在内存索引先行承认。

4204场景角色退出必须查询本关系类型并保护特征根及全部归根组织边；存在活动边时引用冲突，不级联删除。F内容退出/清理继续受L1当前关系引用保护；本版没有解除组织，所以已组织F不得通过场景入口清理关系。恢复只恢复L1事实，再从扩展固定首次材料恢复关系类型，清空非权威索引并按请求重建；不得扫描猜测、补边、改父或把残留已知关系解释为组织关系。

## 7. 状态映射与最低验证

存在已知准确特征组合窄读的入口拒绝、未找到、目标已退出、历史材料已清理、事实代次漂移、数量预算不足、资源失败和内部不一致映射同名场景状态；provider未实现及未知枚举值映射场景内部不一致；成功谓词与回显矛盾为内部不一致。已知成员缺失返回未找到；重复目标或坏形状为内部不一致，不把当前采用代替已知。

最低验证必须覆盖：

1. 4204六编码及固定键1逐字段零变化，扩展固定键独立形成唯一关系类型，恢复后编码稳定。
2. 直接根父、一层父F、两层路径组织成功；写回执轻量，显式当前/历史路径完整。
3. F未知/退出、C未知F、仅当前采用、错C、错根、跨C、多父、环、孤立子树、预算不足全部零写拒绝。
4. 同键同义精确重复、异义冲突、并发同G0只有一次发布、发布后读回失败为已可能发布并可原请求收敛。
5. 组织不改变F内容、C已知组和当前采用；特征/存在服务没有新增写边，场景服务没有写端点本体。
6. C有特征组织边时退出拒绝；无组织边时既有4204退出语义不变。恢复清空索引后当前/历史读回一致。
7. Debug/Release目标模块、专项探针及静态禁止项通过；根工程结果单列，不以编译或专项替代数据库恢复、正式集成验收和业务闭环。
