# 4010 子规范 通用稳定身份、关系与索引边界

编号：4010
日期：20261105
版本：v2.0
状态：正式子规范

直接上级规范：0050。

直接依赖规范：4015。

相关边界规范：4030、4040、4050、4060、4070、4080。

## 1. 定位

本规范规定基础数据集（4015）之上的通用稳定编码、关系和非权威索引边界，是4015第3、4、7、10节在身份、关系与索引方面的补充约束，不另建第二套数据模型。

基础数据集采用current-only模型（0050第1.1、1.2节）：节点、外部关系、字段关系和直接值只保存当前结构必需内容，不保存事实代次、合同版本、截止、历史或墓碑。单次读取一致性由一次共享锁保证；写集与跨结构组合的原子性由4015第14节组合变化集在一次独占锁内一次发布保证。

## 2. 稳定编码

1. 节点、外部关系和字段关系共用4015第3节的同一不透明、非零、不复用稳定编码空间；内部产生、外部接纳和恢复接纳分开准入。
2. 调用方不能指定内部编码，不能从名称、表列、内存地址、句柄值、索引键或材料摘要推导编码。
3. 未发布的组合候选不是事实，不得外泄其编码。已删除对象的编码不得重新分配（4015第3.1节第6项）；发布结果未知时不得生成第二编码，只能按4015第14节用原请求查询或恢复。
4. 编码只证明业务中性对象存在。节点类型由上层以类型字段表达（4015第4.1节）；业务资格和授权由DATA外业务或治理层裁决。

## 3. 类型与修改

1. 节点、关系和直接值不持有身份版本、对象版本、关系版本或值记录版本。
2. 底层记录允许原地修改外部关系和字段内容（4015第12节）；上层对象是否不可变、修改是否建立新节点、旧引用是否先退出，由上层数据类合同决定。
3. 不得原地更换对象身份或从名称、形状、关系数量和本地键反推对象类别。

## 4. 关系

1. 外部关系与字段关系的字段集合以4015第4.2、4.3节为准。正式关系是拓扑、归属、组成、来源、当前值和引用的唯一运行期表达；便利字段、SQL行和缓存不得形成平行事实。
2. 关系类型、方向、角色和基数由对应结构规范裁决；业务语义由DATA外业务规范裁决。基础数据集只验证端点、类型、唯一键和引用闭合。
3. 通用单父、重挂、自动反向边或名称匹配不作为默认规则。
4. 跨结构端点只表示引用，不转移端点写权；引用仍未闭合时删除端点返回`节点仍被引用`（4015第13节）。

## 5. 索引

1. 索引只保存从查询键到稳定编码候选的可重建映射；物理键不进入公开业务接口。
2. 索引命中后必须在同一共享锁内回读正式对象。
3. 索引未命中只表示候选未召回，除非查询合同明确声明索引覆盖完整键空间并在同一共享锁内确认，才可判定“未找到”。SQL不得作为普通运行期权威补判。
4. 索引可清空、失效和从锁内当前权威状态确定重建（4015第10、15节）。

## 6. 写入与读取

1. 只有正式登记数据结构的唯一服务可以提出结构合法写请求；基础数据集只接收已中性化的节点、关系和字段变化（4015第6—8、14节）。
2. 调用方不得取得内部容器、SQL表名、列名、主键、事务令牌、锁、候选确认或撤销入口。
3. 读取返回调用方自有的不可变值式副本，只表示当前结构；不提供历史、审计或墓碑类别。

### 6.1 一次共享锁内的多结构读取投影

当一个领域事实必须同时核对根节点、第一跳关系、中间节点全部同类型相关关系及关系目标的当前字段值时，基础数据集可以提供业务中性的组合读取函数。该函数必须：

1. 只接受强类型值式请求，具名给出必须存在的节点编码、第一跳根节点子集、关系类型、角色和字段目标；不接受领域名、内部对象、句柄、锁、回调或谓词。
2. 在一次共享锁内重新解析全部请求见证并完成全部读取；禁止连续调用多个独立读取后拼接为一致结果。
3. 返回调用方拥有的不可变副本：必须节点、第一跳关系、中间节点同类型全部当前关系、目标节点当前字段值和可选未满足请求见证；不返回内部句柄或锁。
4. 只做稳定编码、存在性、端点、类型、关系类型、角色和字段完整性检查，不解释特征、状态、动态或其它领域语义；领域服务在该材料上继续裁决角色基数、业务唯一性和值域。
5. 全部必须节点存在但没有匹配第一跳关系时返回成功与空业务组。节点不存在返回未找到；类型不匹配返回对象类别不符；悬空端点、同稳定编码异内容或字段矛盾返回内部不一致。
6. 非成功不得返回部分节点、关系或值；只有未找到可以携带稳定排序后的第一个未满足请求见证。
7. 输出按稳定编码排序；同一编码重复且内容完全相同只保留一项，内容不同属于内部不一致。容器顺序、内部编号、句柄、SQL行序、名称或时间戳不得参与排序和去重。

### 6.2 引用与删除

删除前的引用证明以4015第10.1节引用闭包查询为唯一权威；上层对象保存的引用计数只做快速判定，与闭包查询不一致按结构不一致处理，以闭包为准（0300 R39）。删除是物理删除，不保留墓碑或历史（4015第12节）。

## 7. 结构化结果

结果分类以4015第13节为准。除成功或具名读取成功外不得返回可用对象。旧`许可拒绝`、`事实代次漂移`、`已退出`、`仅历史占用`等状态退出现行入口，不得新产生。调用权限由DATA外业务或治理层在调用前裁决；内部结构分区不表示调用资格。

## 8. 退出的旧口径

旧L1的owner与写端口、所有者范围事实、合同版本、事实代次与截止读取、当前/历史/审计类别、历史关系、墓碑与编码占用账、幂等命名空间，按4015第18节退出正向机器语义，只作代码与数据迁移定位。
