# 4010 子规范 通用稳定身份、关系与索引边界

编号：4010
日期：20260812
状态：正式子规范

直接上级规范：0050。

相关边界规范：0500、4020—4070。

## 1. 定位

本规范规定 L1 通用稳定编码、关系和非权威索引边界。原文件名为兼容现有引用保留；标题和正文已经退出“运行期统一仓库、固定句柄、固定节点 / 关系编号 ABI”口径。

## 2. 稳定编码

1. 节点、关系、值和 L1 结构所有者事实共用同一不透明、非零、不可复用的稳定编码空间；内部产生、外部接纳和恢复接纳必须分开准入。
2. 调用方不能指定内部编码，不能从名称、表列、内存地址、节点号、关系号、句柄值或索引键推导编码。
3. 未进入内存已发布事实代次的候选不是事实，不得外泄。已发布或已退出编码永久占用；未知发布结果不得生成第二编码。
4. 通用编码只证明业务中性事实存在。节点类型由正式结构合同定义；业务资格和业务授权由 L5 之外业务层裁决，不进入 L1 owner 或普通事实。

## 3. 类型与生命周期

1. 节点具有节点类型；值具有属性类型节点。未知、停止新写或已退出类型不得用于普通新写。
2. 节点、关系和值不持有身份版本、对象版本、关系版本或值记录版本。类型解释不兼容时建立新类型节点，并用显式有向兼容关系表达允许操作。
3. 已发布事实不可变；当前属性替换必须使新值建立、旧值退出和属性槽指向变化在同一内存事实事务与代次发布中成立。
4. 节点、关系和值一经发布，其写入所有者与稳定编码、类型、端点 / 材料和创建代次共同不可变；不得原地换 owner、复制 owner 或从名称、形状、关系数量和本地键反推 owner。

## 4. 关系事实

完整关系至少包含：

```text
关系稳定编码
+ 关系类型
+ 源节点编码
+ 目标节点编码
+ 角色 / 顺序
+ 写入所有者
+ 创建 / 退出事实代次和发布证据
```

1. 内存已发布代次中的关系是拓扑、归属、组成、来源、当前值和引用的运行期权威表达；便利字段、SQL 行和缓存不得形成平行运行期事实。
2. 关系类型、方向、角色和基数由对应结构规范裁决；业务语义由 L5 之外业务规范裁决。L1 只验证端点、类型、唯一键、owner 和通用生命周期。
3. 关系替换、退出和退役保留历史，不得原地重写端点或复用编码。
4. 通用单父、重挂、自动反向边或名称匹配不作为默认规则。
5. 所有者范围写入口创建关系时，关系事实与关系类型节点必须由同一端口 owner 拥有；源 / 目标节点允许跨 owner，仅表示引用，不转移端点所有权或授予写权。

## 5. 索引

1. 索引只保存从查询键到稳定编码候选的可重建映射；物理键不进入公开业务接口。
2. 索引命中后必须回读同一内存已发布事实代次的节点、关系和值及其生命周期。
3. 索引未命中只能表示候选未召回，除非查询合同明确声明索引覆盖该内存代次及完整键空间，因而可以确认“未找到”。SQL 查询不得作为普通运行期权威补判。
4. 索引可清空、失效和确定重建；重建来源唯一为指定内存已发布代次。

## 6. 写入与读取

1. 只有正式登记数据结构的唯一服务可以提出结构合法写请求；L1 接收已经中性化的节点、关系、值、属性槽和事实代次前置写项。
2. 调用方不得取得内存仓库可变对象、SQL 表名、列名、主键、事务令牌、锁、候选确认或撤销入口。
3. 读取返回不可变值式快照，并明确当前 / 历史 / 审计 / 恢复候选类别。

### 6.1 同许可多结构读取投影

当一个领域事实必须同时核对根节点、第一跳关系、中间节点全部同类型相关关系及关系目标的当前类型化值时，L1 可以提供一个业务中性的组合读取函数。该函数必须：

1. 只接受强类型值式请求，具名给出必须存在的节点编码、第一跳根节点子集、关系类型、第一跳角色和属性类型目标槽；不接受领域名、仓库对象、内部句柄、许可、回调或谓词。
2. 在一次事务域共享读取许可内重新解析全部请求见证，并完成全部节点、关系和类型化值读取；结果只携带一个非零事实截止代次。禁止连续调用多个独立许可函数后比较代次并拼接为同代次结果。
3. 返回调用方拥有的不可变值式副本：已重新解析的必须节点、第一跳关系、中间节点同类型全部当前相关关系、目标节点全部当前类型化值和可选未满足请求见证；不得返回内部句柄、仓库记录、锁或许可。
4. 只做稳定编码、当前性、端点、类型、关系类型、角色筛选和属性槽 / 值完整性检查，不解释特征、状态、动态或其它领域语义。领域服务必须在该值式材料上继续裁决角色基数、业务唯一性和值域。
5. 全部必须节点有效但没有匹配第一跳关系时返回成功、同次非零事实截止和空业务组。节点未占用 / 仅历史占用返回未找到；类型不匹配或首末事实截止不一致返回事实代次漂移；悬空端点、同稳定编码异内容或属性槽矛盾返回内部不一致。
6. 非成功不得返回部分节点、关系或值。只有未找到和事实代次漂移可以携带同次非零事实截止及稳定排序后的第一个未满足请求见证；入口拒绝、许可拒绝、资源失败和内部不一致的业务载荷必须为空。
7. 输出按稳定编码排序；同一稳定编码重复且内容完全相同只保留一项，内容不同属于内部不一致。容器顺序、内部编号、句柄、SQL行序、名称或时间戳不得参与排序和去重。

### 6.2 L1 技术所有者与写能力

1. `L1结构所有者身份` 只承载同一 L1 稳定编码空间中的非零编码；`L1所有者范围种类` 只允许 `旧共享范围=1` 与 `独占结构范围=2`。`L1结构所有者事实` 保存所有者身份、范围种类、创建事实代次和可选退出事实代次。
2. 所有者事实与节点、关系和值共用同一 `仓库.L1事实基座`、同一事实代次、同一事务和最后发布点；它不是节点、关系、值、业务主体、业务资格、服务名称、缓存、第二仓或运行期 token。
3. 节点、关系和值事实各保存一个非零 `写入所有者`。属性槽不建立第二 owner 字段或第二槽表，其 owner 唯一继承所属节点；所属节点、属性类型和新当前值必须属于同一 owner。
4. 新具名 `L1所有者范围CRUD合同版本=2` 的写请求不携带 owner；精确 L1 实例绑定且不可复制的 raw 写端口隐式注入 owner。普通稳定编码、owner 编码、枚举、关系类型、名称、本地键和普通 L1 读取服务引用都不能换取、复制或重签端口。
5. 当前 / 历史 owner-aware 读取必须回显所有者事实和三类事实的不可变 owner；旧 v1 读取 DTO 保持原字段形状，只能作为 legacy 投影，不能证明独占 owner。
6. 所有权校验与引用闭包分账。只有端口 owner 可以修改或退出其事实；端点跨 owner 引用不授权修改端点，引用仍未闭合时才在 owner 校验通过后进入引用冲突。

## 7. 结构化结果

必须区分成功、精确重复、未找到、已退出、入口拒绝、许可拒绝、事实代次漂移、类型 / 格式不支持、同键异义、引用 / 并发冲突、外部资源失败和内部不一致。除成功、精确重复或具名读取成功外不得返回可用事实。

## 8. 20260827 内部结构分区与无权限结果

本节取代前文把 owner 或写端口解释为调用资格、把 `许可拒绝` 解释为现行 DATA 结果的条款。

1. 既有 `L1结构所有者身份`、`所有者事实`、`写入所有者` 和 `owner` 仅为调用者不可选择的内部结构分区。分区用于幂等命名空间、结构闭包和旧事实兼容，不表示业务主体、数据归属或调用资格。
2. 写请求不携带分区；内部端口只负责实例到分区的确定路由。L2 公开身份、请求、结果和成功谓词不得包含 L1 owner、端口或分区证明。
3. 跨分区端点仍可形成普通引用。分区不一致以 `引用冲突` 表达；端口失效、跨实例或装配遗漏以 `内部不一致` 表达；锁或资源暂不可用以 `资源失败` 表达。
4. `许可拒绝` 数值只用于旧结果解码，现行入口不得产生。调用权限由 DATA 外业务 / 治理层在调用前裁决。
5. 已清理实例状态 / 动态的稳定身份不得复用；最小墓碑保持编码占用，索引命中后不得补造原事实。
