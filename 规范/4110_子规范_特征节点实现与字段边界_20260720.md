# 4110 子规范 特征节点实现与字段边界

编号：4110
日期：20260729
状态：正式子规范

## 1. 定位

本规范展开抽象特征定义、实例特征槽、当前值、细化、组合、重叠和兼容入口的结构边界。

### 1.1 20260731 权威模型裁决

特征事实由 SQL 已发布宿主身份、特征类型合同、定义版本、实例身份、唯一当前值关系、历史值关系和发布证据共同成立。固定关系编号 22、固定准入表下标、节点类型数值和运行期完整句柄只保留为旧实现证据，不再是公开机器语义或新施工接口。

本规范继续保留“同宿主同类型唯一当前、换代保留历史、领域服务唯一写入和写前基数复核”的业务意图；其物理合同统一服从 4010—4040 与 4190。

直接上级规范：1120、1130、2100。

直接依赖规范：4010、4020、4160。

相关边界规范：4120、4140、4170、4180。

## 2. 抽象与实例分离

1. 正式特征类型必须是抽象特征定义节点，不是语素、文本或硬编码枚举。
2. 创建实例特征前必须存在对应抽象特征定义。
3. 实例特征由宿主归属、定义模板和当前值关系承载；写当前值入口只接受实例特征槽。
4. 实例化不深复制抽象特征子树。需要细化特征时，在同一宿主下按抽象定义懒创建独立实例槽。
5. 实例当前值必须回到抽象值域解释；无命中保留为观察和定义缺口，多命中记录重叠事实。

## 2.1 特征实例角色关系

全部合法宿主的实例特征结构统一使用关系类型 22；不得为自我、任务、方法或其它宿主另建平行槽位关系。顺序号、角色、端点和当前基数固定为：

| 顺序号 | 角色 | 源节点类型 | 目标节点类型 | 当前基数 |
| --- | --- | --- | --- | --- |
| 1 | 宿主槽 | 存在、场景、需求、任务或方法 | 特征（实例槽） | 每个宿主零到多；每个实例槽反向恰一宿主 |
| 2 | 定义模板 | 特征（实例槽） | 特征（抽象定义） | 每个实例槽恰一 |
| 3 | 当前值 | 特征（实例槽） | 特征值 | 每个实例槽恰一当前关系 |

角色 1 的有效唯一键是“关系类型 + 完整宿主句柄 + 顺序号 + 完整实例槽句柄”；角色 2、3 的有效唯一键是“关系类型 + 完整源槽句柄 + 顺序号”。同一宿主和同一抽象定义在同一当前版本下只能形成一个有效实例槽，该唯一性必须同时回读角色 1、2，而不能靠索引或名称裁决。

当前值换代必须创建新角色 3 关系并使旧当前关系正式失效；旧关系、旧值和原始值版本继续保留审计，不得原地改目标或用第二份当前值表覆盖。未知角色、非法宿主类型、抽象定义 / 实例槽身份混淆、槽位多宿主、多模板或多当前值必须写前拒绝；前置通过后的基数异常属于内部逻辑错误。

关系仓库的通用“按关系类型限制基数”能力不能表达本表三个角色的不同方向和基数；特征领域数据操作是关系 22 逐角色准入与基数复核的唯一事实所有者。它必须在第一次写入前以及结构写入独占许可内，按完整关系记录分别核对：

```text
角色 1：指定宿主到指定实例槽；反向宿主数量恰一
角色 2：指定实例槽到抽象定义；当前数量恰一
角色 3：指定实例槽到当前值；当前数量恰一
```

核心关系仓库只执行通用端点、句柄、状态、版本和候选发布，不得被解释为已经完成关系 22 业务准入。关系 22 的创建、失效或读取不得绕过特征领域数据操作直接开放给其它领域服务。

### 2.2 关系 22 核心准入项

关系 22 在核心 `完整正式关系准入表` 中必须有且只有一个具名项；该项只完成端点类型和顺序号的粗准入，不替代 2.1 的逐角色基数与“宿主 + 抽象定义”唯一性：

```text
授权身份 = 0x4E54503241523232
规则版本 = 1
允许同源多目标 = true
允许同目标多来源 = true
允许重挂 = false

顺序号 1：
  源类型属于 存在/场景/需求/任务/方法
  目标类型 = 特征
顺序号 2：
  源类型 = 特征
  目标类型 = 特征
顺序号 3：
  源类型 = 特征
  目标类型 = 特征值
其它组合拒绝
```

两个全局多重性布尔值必须为 true，因为核心同一关系类型同时承载三个方向不同的角色；角色级基数只能由特征领域数据操作在第一次写前和独占许可内复核。统一运行期装配必须把本项放入准入表下标 22；缺项、重复项、字段不同或裁决函数不同均为配置漂移。

## 3. 细化和补位

读取和使用时优先选择满足目标语义的最细当前子特征；子特征缺失、无当前值或不可比较时，才允许父特征粗略补位，并记录实际采用口径。

父特征补位不能伪装成子特征精确值。多个子特征同时可用时，必须由目标、方法输入或正式组合规则选择。

## 4. 值类型和比较边界

1. I64 进入正式区间和值域比较；U64 必须先有明确、可逆或有版本的 I64 映射/量化合同。
2. VecI64、VecU64 只保存原始材料；坐标、句柄组和其它业务解释由特征类型专用读取规则处理。需要比较或形成差异时，该专用规则必须通过 4180 登记特征定义、比较用途、算法族、单位、维度、左右角色、误差和版本，不得按向量形状猜测算法。
3. 引用/句柄不做地址区间比较；按稳定身份相等、集合关系或专用二次特征比较。
4. “不等于零”是两个区间或组合规则，不能伪造为一个连续区间。
5. 不得为业务解释向特征值类型化原始记录新增业务类型或编码字段。
6. 批次身份、规则版本、项目顺序、来源版本和换代证据不得写入特征值原始记录、实例槽位、宿主或来源对象的领域记录；需要历史重放时使用 4170 的专用不可变批次发布记录。

## 5. 区间重叠和个体覆盖

同层抽象区间允许重叠。实例值同时命中多个区间时必须记录涉及定义、次数、时间和来源，不得强行只留一个。

重叠长期稳定时由特征治理决定细分、合并或保留。实例宿主可有具名局部值域覆盖，但必须关联抽象定义、宿主、来源和版本，不能改写全局定义。

## 6. 组合特征

组合特征由有向无环的输入定义关系和收束规则形成，不把输入关系混入普通细化父子链。求值时按输入定义找到同一宿主上的实例槽，执行缺失策略和收束规则，再把输出写入组合特征实例槽。

长期语义字段、枚举、状态和嵌套结构应逐步转为抽象特征定义、实例值和组合规则；DTO 只作本轮传递。

## 7. 能力和类型入口

自我能力等枚举型特征使用正式枚举定义和值域；任务和方法按特征引用或稳定主键表达，不按动作名或显示文本。

`_按类型`、按语素或按字符串入口只能作为兼容/初始化入口，必须先解析到已理解抽象特征，再创建或读取实例槽。没有抽象定义和值域的兼容特征不得进入需求、方法、因果或结算主链。

## 8. 写入与验证

特征服务是实例槽、当前值关系、定义模板和命中事实的唯一公开写入方；特征值服务仅为其内部参与者。

验证覆盖唯一宿主、唯一定义、当前值唯一性、无命中、多命中、父补位、局部覆盖、组合 DAG 和兼容入口解析。
