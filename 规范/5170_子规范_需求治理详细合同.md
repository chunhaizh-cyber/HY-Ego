# 5170 子规范 需求治理详细合同

编号：5170
日期：20261008
版本：v2.0
状态：正式子规范

直接上级规范：3100。
直接依赖规范：1130、1140、1160、3200、7160。
相关边界规范：5090、5260、6100—6150、8000、8100、8200。

## 1. 适用范围

本规范展开需求建立、树/列表组织、值目标current-only复核、方向目标执行前后复核、权重、来源和生命周期。需求结构全集与公开函数以3100为准。

## 2. 建立资格

所有需求都必须具有合法目标存在、唯一目标特征类型及严格二选一的目标形式。

值目标必须同时具有同类型目标值域和适用比较关系，且不得具有方向；方向目标必须具有增加或减少方向，且不得具有目标值域或比较关系。任何混合、空载荷或非法枚举都在建立节点前拒绝。

普通需求必须具有恰一父需求和合法来源。本能固定定义可以在初始化中形成明确初始子需求；任务筹办或执行中新发现的子需求必须绑定来源任务。需求类负责精确查重、建立需求、父子关系、列表成员和权重，不让消息、候选材料或任意节点冒充来源。

双根是初始化例外：它们没有父需求和来源任务，但仍必须具有目标存在和完整值目标。两个根的目标存在均为唯一自我，目标特征类型分别为安全值和服务值，目标为`INT64_MAX`。

## 3. 树、列表和查重

需求树只保存目标分解父子关系。需求列表完整键为`目标存在 + 目标特征类型 + 目标形式 + 对应载荷`，只提供查询和防重，不形成第二需求事实。

同一完整目标可以因父路径或来源不同形成多个需求节点，并进入同一列表项。建立前必须检查：

1. 同完整键最多一个列表项；
2. 列表成员均可完整读回；
3. 同父、同来源、同完整目标只能有一个需求节点；
4. 新父子边不会形成环；
5. 发布后需求、列表、成员和父子关系能够相互读回。

## 4. 满足复核

### 4.1 共同定位

需求类每次从目标存在的当前特征组按目标特征类型根定位唯一实际特征。缺失、复义、错误类型或读回失败均不得继续比较。

### 4.2 值目标

值目标读取实际特征current-only当前值，按目标值域和比较关系产生已满足、需增加、需减少、无有向差值或结构化非成功。I64差值饱和到`INT64_MAX/INT64_MIN`。

双根只允许已满足或需增加。根当前值下降只扩大需增加差距；出现需减少表示定义、绑定或数据错误。

### 4.3 方向目标

方向目标的单点复核只返回`需要执行前后比较`，不能返回已满足。任务执行实例必须冻结同一实际特征的动作前值A，并由已声明结果渠道取得观察后值B；影响评估调用特征比较能力计算`B 相对 A`的有向差值。

```text
目标增加且 B-A > 0 -> 本执行方向通过
目标减少且 B-A < 0 -> 本执行方向通过
符号相反或为0       -> 本执行方向不通过
无法比较或材料缺失   -> 未验证/结构化非成功
```

本次方向通过只进入该执行实例的影响评估和self后继决议，不写回需求节点为永久满足值。

## 5. 权重与任务

双根权重由具名配置提供且非负。普通需求权重由父需求在非失活直接子需求间平分，余数按稳定编码升序分配；失活子需求为0。跨入或退出失活时递归重算受影响子树。

一个需求最多对应一个任务。任务完成、失败、取消或结算都不删除需求，也不永久证明值目标或方向目标满足。需求后来仍需治理时，self可以请求重新启用原任务。

任务候选方法材料必须完整复制目标形式和对应载荷；不得把方向目标降格为伪值域或只保存特征类型。

## 6. 结算分账

需求当前复核、执行影响评估、任务完成、任务完成结算、需求结算和安全/服务值变化互不替代。任务结果只提供重检材料；self形成后继决议时：

- 值目标fresh读取当前值；
- 方向目标读取同一执行实例的A/B方向验证；
- 任何缺失渠道、未验证、冲突或结构错误均不得判完成。

## 7. 写入与失败

需求类使用共享基础数据集，不建立owner分区、事实代次、历史读回或墓碑。多节点发布失败时尽力回滚本次结构；回滚失败返回`结构不一致`。

至少区分需求不存在、父需求不存在、目标存在/特征/形式/值域/关系/方向不合法、目标重复、形成环、权重不合法、任务来源未接通、结构不一致和资源失败。技术非成功不能改写为需求失活或任务失败。

## 8. 验证边界

最低验证覆盖3100第10节，并额外覆盖候选材料两种目标的持久往返、方向目标执行前后值绑定、影响评估与self后继决议，以及值目标需减少和方向减少能够进入合法任务路径。

规范发布不证明普通需求任务来源、原子组合发布、正式需求结算或完整内部治理运行闭环已经实现。
