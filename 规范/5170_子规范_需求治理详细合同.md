# 5170 子规范 需求治理详细合同

编号：5170
日期：20261103
版本：v2.12
状态：正式子规范

直接上级规范：3100。
直接依赖规范：1130、1140、1160、3200、7160。
相关边界规范：5090、5260、6100—6150、8000、8100、8200。

## 1. 适用范围

本规范展开需求建立、树/列表组织、值目标current-only复核、方向目标执行前后复核、权重、来源和生命周期。需求结构全集与公开函数以3100为准。

第2—6节的父需求、双根、树/列表、权重及任务推进仅用于自我执行域；服务对象需求记录和单D引用发布按第2.1节，不借自我父链包装对方需求。

## 2. 建立资格

普通需求都必须具有合法目标存在、唯一目标特征类型及严格二选一的目标形式。**词条归类**与**原文范围分界澄清**按第2.2、2.3节各自的专属目标准入，不适用普通目标形状。

值目标必须同时具有同类型目标值域和适用比较关系，且不得具有方向；方向目标必须具有增加或减少方向，且不得具有目标值域或比较关系。任何混合、空载荷或非法枚举都在建立完整目标前拒绝。该恰一/二选一约束用于准备发布到服务对象需求特征的完整需求；字段补齐发生在单D引用发布之前，不因新发生S放宽准入。

除双根外，自我执行需求（包括已批准的专属种类）必须具有恰一父需求和合法治理来源。本能固定定义可以在初始化中形成明确初始子需求；任务筹办或执行中新发现的子需求必须绑定来源任务。需求类负责精确查重、建立需求、父子关系、列表成员和权重，不让消息、候选材料或任意节点冒充治理来源。

双根是初始化例外：它们没有父需求和来源任务，但仍必须具有目标存在和完整值目标；种类固定为普通值目标，**不适用**词条归类或分界澄清专属形状。两个根的目标存在均为唯一自我，目标特征类型分别为安全值和服务值，目标为`INT64_MAX`。具名专属种类按第2.2、2.3节，与双根例外分列，不得互相冒充。

### 2.1 服务对象的被认知需求与需求特征

服务对象H已建立的需求特征为唯一F，当前值直接引用一个主体为H且满足既有完整准入及来源合同的正式被认知需求D，历史按1130保存实际出现过的去重D及命中信息，不建立H需求树；尚未建立F或尚无当前值保持未知，不新加空F初始化。D身份、需求发生、内容完善、内容确认、实际满足及自我承接分别成立；新需求发生状态不替代fresh完整判断，不把未知消息或任意非零编码当作D。D在F发布前可以待完善，补齐及确认仍沿原D；本规则不扩大待完善D进入F的资格，更不使其进入自我执行树或配任务。

F的当前值只在两种业务发生时更新：产生一个新D；已满足D经合法来源明确再次需要。后者可切回历史D，也可在F当前仍引用同D时再次发生。每次真实发生由特征/存在/世界原owner的组合路径自动生成一份新的正式需求状态S；同D不复制D，同值不补造1170原子变化动态。同一正式发生来源重复处理只复用原S，不以调用次数、当前时间或新工程请求号制造再次发生。普通读取、字段补充、内容确认补齐、重复处理及迁移恢复不生成新的需求发生S；任意切换旧D不再是合法更新分支。

“获取服务对象需求信息”在需要判断是否有新需求发生时读取本次相关正式状态，确认其H、精确F、实际D及发生来源；不保存需求集合B，不新增数量FT，也不以第一次出现某D代替发生判断。D的必需字段经原owner单独读取；不足时由通用筹办提议完整的补问、归类或指代澄清子需求交self确认，父方法不执行。补齐后重读同一D，不要求再造需求状态才重新取得处理资格。任务/消息只保存既有治理所需的S定位与原请求身份，不能把一次读回当作永久满足或原消息理解完成。

再次需要须具有可读的既有D、已有满足依据和明确执行该D再次需要操作的真实业务来源。self/任务等合法调用者决定本次为何需要；专用再次需要入口核验条件并执行该命令，不替调用者推断人类意图，也不额外要求新M/U、交互确认或新句式。当前不满足、旧来源仍存在、普通读取/重试或随意新造工程请求号本身不构成再次需要操作。H的同D新发生与self Ds、唯一T及完成结算分别治理，不强制同Ds/T；按本次实际业务来源经既有合法治理路由判定承接，同次来源重投精确复用，不强套行动请求。旧已结算T及既有结算不在本规则中重开或改义。原owner保存同次真实操作来源、A与S的关联，重复操作来源只复用原S；缺真实来源时不生成S，不把工程故障转成业务无新需求。

待完善的被认知D本身不进F、不进自我执行树、不建任务。字段不足时由「获取服务对象需求信息」经通用筹办提出完整补问子需求；该子需求可进入任务链，不能把原待完善D送进查找方法。补齐沿原D，发布前不预造需求发生S；已有S不替代后来对D内容及确认的fresh复核。不能因旧通知已经被读过或当前F已指向另一D而丢弃尚待补齐的具名治理工作。

口径补充（20261102 自然语言学习，不改上段必要条件集合）：「必需字段有确定值」中的**确定值**指字段中的词条已有对应的**概念信息节点**。不新增前提条件；新词条对不上概念节点，即该条件不满足。此时通用筹办在同一父方法下另提**归类子需求**（每个新词条一条），与补问子需求同级，均为完整需求，经自我确认后进任务链。归类目标形状、询问/写回本能与原句重述确认见[7250](7250_子规范_最小汉语知识与语言学习.md)及[LANGUAGE-LEMMA-CLASSIFY](详细设计/20261102_LANGUAGE-LEMMA-CLASSIFY_词条归类学习与本能详细设计_v0.1.md)；学到的信息进语言知识模块，不直接进自我内部世界。

口径补充（20261102 代词指代，不改上段必要条件集合的普通词条规则）：字段词条若为**代词用法**，不得因其已有概念名称关系／代词概念定义即视为「确定值」。须先完成指代消解，落到**自然语言场景**中的目标信息节点（或合法有界成员组）；未决则条件不满足。代词词条**不建归类子需求**。此时通用筹办在同一父方法下另提**指代澄清补问子需求**（例如「你说的『它』是哪个？」），与补问子需求、归类子需求同级，均为完整需求，经自我确认后进任务链；目标＝**指代实例**，满足条件＝**指代已消解**；消息种类另立「指代澄清」；多候选不得取首项；澄清候选池只含自然语言场景已提对象。详细见[1110](1110_根规范_指代_20260720.md)及[LANGUAGE-PRONOUN-RESOLUTION](详细设计/20261102_LANGUAGE-PRONOUN-RESOLUTION_代词指代消解与澄清详细设计_v0.1.md)。

口径补充（20261103 未知词面准入，不改上段确定值与归类／指代规则）：归类目标仍为正式词条，纯读取缺口不写词条。在缺口外按[7250第3.3.1节](7250_子规范_最小汉语知识与语言学习.md#331-未知词面显式准入与归类衔接)确认词边界及规范化材料后，经词条owner建立或取得并读回，重新解释／读取缺口，再按本次用法判断归类。边界未定时允许先询问分界，采用第2.3节已批准的固定原文＋范围专属目标；它不是词条归类或指代澄清目标，不能强塞入这两类旧载荷。提议／任务／消息及回答关联的实际API仍须后续设计冻结，不据本条直接扩展旧DTO。功能词与代词不归类但可有词条身份。步骤和未冻结本能合同见[LANGUAGE-LEMMA-CREATE-FROM-FRAGMENT](详细设计/20261103_LANGUAGE-LEMMA-CREATE-FROM-FRAGMENT_未登记片段建立词条详细设计_v0.1.md)。


### 2.2 词条归类需求专属种类（20261102）

词条归类完整需求是具名专属种类，目标为**正式词条身份**，满足条件为「该词条已通过概念名称关系挂到存在／特征／动态根树下某概念节点」。

- **建立**：核验父需求、来源、无环、种类标记与合法词条身份；**不**核验合法世界存在、特征类型根、值域或方向载荷。
- **查重／列表键**：完整键为`种类(=词条归类) + 目标词条`；不得落入普通`目标存在+FT+形式+载荷`键空间。
- **复核**：每次 fresh 读取名称关系；已挂接则已满足，否则未满足／结构化非成功。不走第4节普通共同定位与特征值比较。
- **信息字段**：需求信息与列表项携带种类标记；旧普通请求缺省行为保持，专属种类须显式识别，不识别则拒绝或停用受影响路径，不得按普通解释为缺目标存在。
- **禁止**：词条伪装成存在；布尔镜像特征；把本种类改写进普通值目标字段再套 I64／特征合同；套用双根初始化例外。

细则与生命周期见[LANGUAGE-LEMMA-CLASSIFY](详细设计/20261102_LANGUAGE-LEMMA-CLASSIFY_词条归类学习与本能详细设计_v0.1.md) §2／§2.1；根规范例外见3100 §5.1／§6.4。除本种类外，普通需求建立与复核合同不变。

需求主体、理解来源及完整目标用于复用核验；同来源重投不得建重复节点，同来源不同内容须重新确认而非覆盖原目标。已有D身份复用不等于新的需求发生；已满足D明确再次需要按第2.1节形成新S而非复制H侧D，其首次来源保持。不同主体或不同请求不因目标相同擅自合并；明确针对既有H D的再需要是本次具名身份复用例外，不据相同目标猜测该例外。类型、主体、内容与本次来源由需求owner核验，编码或材料相等不能替代这些判定。

D建立、F引用落实、需求发生S正式生成与内容完整各有独立完成边界；前者完成不代表后者完成。发布中断保留实际身份及已发生事实，按同一来源读回复用，不盲目重放。F当前/历史引用与来源由原owner按组合变化合同发布；S挂接发生场景，迁移映射只证明恢复来源，不升级为现实新发生。按需新增识别只返回真实S/D/来源及必要保护，不另建新需求账，不以临时返回值代替正式读回。

内容确认、求助、自我承接分账。承接后另建或复用自我执行需求并引用原需求；原节点仍属对方，不进入自我树或任务扫描。已发布记录后来需重新确认时，不伪造当前有效确认或抹去原事实；后继确认及待确认承载仍需具体合同。旧记录主体或来源不可追溯时保留并报告，不猜测迁移。

### 2.3 原文范围分界澄清专属种类（20261103）

这是自我理解语言输入所需的完整自我执行需求，不把未理解原话或待完善被认知需求直接交任务承接。目标准入及字段见[3100第5.2节](3100_根规范_需求.md#52-原文范围分界澄清需求专属例外20261103)，分界材料见[7230第2.4节](7230_子规范_语言材料知识与交互字段.md#24-原文范围分界结果材料)。

- **定位／键**：`种类(=原文范围分界澄清) + 来源出现定位 + 固定文本材料身份 + 非空Unicode标量范围[start,end)`。网页来源按接收M、原理解根范围和根出现路径；U、解析版本、候选及后续D不进键。相同材料的不同消息／出现／范围不得合并；根出现必须有正式定位，不能从候选数组猜路径。
- **准入**：父需求、合法治理来源、父链无环、自我确认和D-T唯一关联沿原合同；目标来源、固定材料及范围可读且相符，不要求先有词条、完整含义U、被认知D或分界结果。不校验普通存在／FT／值域字段，不造布尔镜像FT或指代实例。
- **满足**：每次经语言owner按完整目标fresh读取唯一当前有效采用；结果范围完整、有序覆盖且依据仍适用才满足。规则或明确关联回答可分别提供依据，不强制两者同时成立。未答、部分、多候选未采用均不能判满足；互斥当前采用、损坏引用及工程失败不得伪装正常未满足。
- **治理与接续**：通用筹办提议，self确认、需求owner建立／复用、manager承接；询问、生成、发送、回答写回和父工作重读分账。重解释不因新U重建同问题；已有原待完善D继续关联原D，没有D不伪造。完整步骤见CREATE-FROM-FRAGMENT第6节，非网页前置入口与实际公开DTO不由本条新增。

## 3. 树、列表和查重

需求树只保存目标分解父子关系。需求列表完整键按种类分支：普通为`种类(=普通) + 目标存在 + 目标特征类型 + 目标形式 + 对应载荷`；词条归类为`种类(=词条归类) + 目标词条`；原文范围分界澄清按第2.3节完整键。列表只提供查询和防重，不形成第二需求事实。

同一完整目标可以因父路径或来源不同形成多个需求节点，并进入同一列表项。建立前必须检查：

1. 同完整键最多一个列表项（键比较含种类，跨种类不冲突也不合并）；
2. 列表成员均可完整读回，且种类与键一致；
3. 同父、同来源、同完整目标只能有一个需求节点；
4. 新父子边不会形成环；
5. 发布后需求、列表、成员和父子关系能够相互读回。

## 4. 满足复核

词条归类按第2.2节与 LANGUAGE-LEMMA-CLASSIFY §2.1复核；原文范围分界澄清按第2.3节与3100第6.5节复核。二者均不适用下列4.1—4.3的普通存在特征定位与当前值比较。

### 4.1 共同定位

需求类每次从目标存在的当前特征组按目标特征类型根定位唯一实际特征。缺失、复义、错误类型或读回失败均不得继续比较。

### 4.2 值目标

值目标读取实际特征current-only当前值，按目标值域和比较关系产生已满足、需增加、需减少、无有向差值或结构化非成功。I64差值饱和到`INT64_MAX/INT64_MIN`。

双根只允许已满足或需增加。根当前值下降只扩大需增加差距；出现需减少表示定义、绑定或数据错误。

### 4.3 方向目标

方向目标的单点复核只返回`需要执行前后比较`，不能返回已满足。任务执行实例必须冻结同一实际特征的动作前值A，并由已声明结果渠道取得观察后值B；影响评估调用特征比较能力计算`B 相对 A`的有向差值。

```text
目标增加且 B-A > 0 -> 本执行方向通过
目标减少且 B-A < 0 -> 本执行方向通过
符号相反或为0       -> 本执行方向不通过
无法比较或材料缺失   -> 未验证/结构化非成功
```

本次方向通过只进入该执行实例的影响评估和self后继决议，不写回需求节点为永久满足值。

## 5. 权重与任务

双根权重由具名配置提供且非负。非根自我执行需求（包括已批准的专属种类）权重由父需求在非失活直接子需求间平分，余数按稳定编码升序分配；失活子需求为0。跨入或退出失活时递归重算受影响子树。

一个需求最多对应一个任务。任务完成、失败、取消或结算都不删除需求，也不永久证明值目标或方向目标满足。需求后来仍需治理时，self可以请求重新启用原任务。

任务候选方法材料必须按种类完整复制目标载荷；普通需求不得把方向目标降格为伪值域或只保存特征类型，专属种类不得被降为普通FT或丢失其来源／范围。

## 6. 结算分账

需求当前复核、执行影响评估、任务完成、任务完成结算、需求结算和安全/服务值变化互不替代。任务结果只提供重检材料；self形成后继决议时：

- 值目标fresh读取当前值；
- 方向目标读取同一执行实例的A/B方向验证；
- 原文范围分界澄清按语言owner当前有效分界结果复核，词条归类按当前名称关系复核；
- 任何缺失渠道、未验证、冲突或结构错误均不得判完成。

## 7. 写入与失败

需求类使用共享基础数据集，不建立owner分区、事实代次、历史读回或墓碑。同次多节点发布采用组合变化；跨次已成立事实不得伪报回滚。工程中断保留完成边界，不让半成品或局部返回冒充集合更新成功。

词条归类写回成功后的重读与失败分账按普通写回惯例（见 LANGUAGE-LEMMA-CLASSIFY §5.3）：正式 owner 发布后必须 fresh 读回互证；写回回执不得代替父方法「获取服务对象需求信息」对确定值／名称关系的重读；读回失败保留已发布事实并返回结构化非成功，按来源复用重试，不伪造已满足。

至少区分需求不存在、父需求不存在、目标存在/特征/形式/值域/关系/方向不合法、目标重复、形成环、权重不合法、任务来源未接通、结构不一致和资源失败。技术非成功不能改写为需求失活或任务失败。

## 8. 验证边界
