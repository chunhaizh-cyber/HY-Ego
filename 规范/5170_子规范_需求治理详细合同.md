# 5170 子规范 需求治理详细合同

编号：5170
日期：20260903
版本：v0.1
状态：正式子规范 v0.1

直接上级规范：3100。

直接依赖规范：1190、3200、3300、4320、5350、6150。

相关边界规范：5090、5260、5350、6100、6110、6120、6130、6180、8100、8200。

## 1. 适用范围

本规范展开3100已经固定的需求治理细节，统一承接原来堆放在根规范中的流程顺序、合法分支、错误分类、事务和验证合同。它不建立第二套需求语义，也不恢复已删除的4250与5100—5160。

任务承接、任务状态和筹办的详细合同读取5260；执行前方法选择与执行规则、学习准入与方法代际读取5350；因果预算与安全调度读取4320和6150。本规范只固定这些相邻过程与需求成立、组织和生命周期之间的边界，不复制其内部状态机。

---

## 2. 核心结构与不可变合同

需求核心事实至少稳定证明：

```text
需求身份
所属存在
目标宿主
目标特征
目标状态合同
生命周期
```

所属存在创建时必须明确且非空，不得由当前线程、名称、自我缓存、任务身份、父需求或显示文本反推。所属存在、目标宿主和目标特征必须使用正式强类型身份；不得使用名称、文本、缓存键、本地地址、任务虚拟存在或方法虚拟存在替代。目标状态合同必须表达目标值或集合、方向或区间、比较关系和规则版本，不得用裸 I64、实例状态身份、文本或 bool 替代。

需求核心契约和需求列表精确聚合键均为：

```text
所属存在 + 目标宿主 + 目标特征 + 目标状态合同
```

任一核心语义改变时建立新需求，旧需求及其来源、关系和历史继续保留。

## 3. 当前满足裁决

当前满足必须执行：

```text
读取需求及完整目标合同
+ 冻结非零事实截止 G0
+ 在 G0 读取目标涉及的当前特征值完整投影
+ 按目标合同完成正式比较或判断
= 当前满足裁决
```

复合目标必须在同一 G0 读取完整成员集合。当前满足结果至少携带需求身份、目标合同、当前值投影、来源、G0、规则版本和比较证据；状态 / 动态引用只能作为可选证据。

必须保持：历史上满足、方法成功、任务轮次结算完成、任务生命周期结束、历史正式结算，均不等于当前满足。

---

## 4. 需求树、需求列表与聚合

需求树保存父子位置、目标分解路径、来源、当前性，以及成员自己的权重、活动资格、预算和结算来源。需求列表项保存稳定列表身份、精确聚合键、成员需求集合和生命周期，用作当前需求枚举、同类查询、权重查询、任务查询和防重锚点。

需求发布前或同一治理事务中必须查询精确聚合键：已有唯一当前列表项时加入该项；没有时建立列表项再加入；出现多个当前列表项、重复成员、键与成员不一致或一个需求属于多个当前列表项，均为内部不一致。

列表项不保存或替代成员独有的父子位置、来源、路径、当前性、权重、资格、预算和结算身份。当前成员归零后，列表项可以保留稳定聚合身份和历史，是否退役由独立管理合同裁决。

## 5. self产生确认与子目标准入

自检、身体反馈、观察、外部输入、任务发现、方法或条件缺失、因果反推、临时因果视图和结算后继都只能先成为父任务的强类型材料。

self 必须 fresh 读取父需求、目标合同、来源任务与轮次、筹办轮次、候选方法、条件组和共同事实截止，然后区分：

```text
等待或重触发
当前任务结构缺口
普通独立后继目标
符合5350门槛的学习目标
```

只有同时满足以下条件的目标才可形成子需求：

1. 拥有独立且明确、最终可判定的目标三元组；
2. 对父需求后继确属必要；
3. 严格缩小父需求及全部祖先尚未闭合范围；
4. 与父需求属于同一所属存在；
5. 由 self 产生并确认；
6. 由 task owner 形成并独立读回正式任务子目标承接记录。

承接记录必须绑定父需求、任务、任务轮次、筹办轮次、self 确认来源、共同事实截止、规范化目标和幂等身份。需求 owner 只消费该记录，原子建立或复用子需求、列表成员、父子关系和来源关系；task owner 随后按原记录幂等绑定子需求。

消息、日志、外部请求、观察、自检、方法 / 条件缺失或普通任务失败不能替代承接记录。只有具名业务条件尚未满足且存在正式生产者或重触发事实时，才可形成任务材料或合法等待；截止 / 版本漂移、投递或发布未知、ABI / 引用 / 断言 / 结构不变量和内部错误按5260的技术非成功合同收敛，均不得包装成业务等待或递归改名建需。

任务子目标承接记录及其到需求 owner 的专用来源关系是唯一来源链。不得另建第二需求入口、通用请求节点、来源事实 `S`、通用 `R→D`、来源 registry、真实性 provider、持久 outbox、请求专用恢复账或第二结果账。

同一父需求下目标三元组和满足关系相同的活动子需求应复用或合并；不同请求、文本、材料或提出者不自动制造第二个需求。子需求发布后，后继任务已存在、目标已满足、合法等待或资源失败都不能倒推为子目标准入失败，也不能撤销该需求。

父子拓扑只证明目标分解关系，不证明 AND / OR、执行顺序、当前活动路径、方法路径、权重或优先级。历史路径不能冒充当前路径。

## 6. 当前自我双根治理

唯一自我正式形成并独立读回后，ARCH-L4 冷启动治理必须幂等建立安全根、服务根两个角色及其各自唯一绑定的普通需求 D。成功顺序为：

1. 读回唯一自我；
2. 读取两个根角色绑定；
3. 对缺失角色经需求正式入口建立普通根需求并发布绑定；
4. 同义重复读回原角色和原 D；
5. 两个角色、两个 D、各自目标合同和初始化版本全部读回后才成功。

两个根分别拥有独立身份、目标合同、当前满足、来源、父子树、结算引用和生命周期。安全值与服务值不得压成综合分数；任一侧失败不得替代另一侧裁决。

每轮双根治理必须在同一非零事实截止 G0 分别读取两个根角色、两个需求、两个完整目标合同和各自当前值，并分别形成当前满足、正差距、方向相反、不可比较、材料不足、当前性漂移或内部不一致。比较结果没有数值差时不得伪造数值差。正差距或新到达的合法父任务材料只能建立、唤醒或复用根需求治理任务；材料触发只授权 fresh 重判，不等同正差距，也不直接创建子需求。

每个运行期子需求必须具有一个当前父需求，同属一个 `E_owner`，父链无环并有限回溯到其中一个根。安全树与服务树中目标三元组相同的需求仍保留两个独立 D，但可以进入同一列表项；不得恢复结果容量、消费分配、剩余量或结果争用模型。

外部存在的请求先由原来源 owner 正式承接，再成为服务根任务材料。人类只是来源存在的一种可选分类。来源存在、目标宿主和需求所属存在是三个不同角色；外部材料不得改变需求仍属于唯一自我的事实。

根需求长期存在。当前满足只表示本轮无根值正差距；新材料仍可触发 fresh 重判。根需求及其任务不因材料直接执行现实动作，现实动作必须进入具体子需求后继任务并经过执行前选择、方法冻结和安全门禁。

## 7. 学习需求统一结构

学习需求继续使用普通需求结构，其所属存在和目标宿主通常都是当前自我，目标特征是待获得、补全或稳定的能力特征，目标状态合同描述能力达到可用、完整、稳定或指定范围。

方法虚拟存在、方法候选、因果材料和练习材料只能作为来源或后继方法治理材料，不能成为需求目标宿主。学习目标仍须由 self 产生并确认，具体准入全部读取5350；预算不足、漂移、概念待形成、结构待补齐、多候选、条件未满足或合法等待不得自动改写为学习需求。

学习结果先进入学习材料、方法候选或方法新代际治理。学习需求及其任务不直接增加安全值、服务值，也不证明现实目标已经改变；后续普通任务实际使用新能力并形成正式现实结果后，才可能进入价值结算。

## 8. 权重、活动资格与预算

列表项可作为查询入口，但当前聚合投影必须逐成员保留需求身份、来源、路径、当前性、权重、活动资格、预算、规则版本和共同事实截止。不得形成无法回溯成员的总权重、总资格或总预算。

活动资格只决定需求是否参与当前选择、任务承接或结算，不授权现实动作。父权重不得在路径展开中丢失；具体因果与价值预算读取4320，安全调度读取6150。

---

## 9. 任务与方法的需求边界

任务承接、任务状态、筹办、执行前选择和执行轮次的完整任务合同读取5260，方法采用与执行规则读取5350；本规范不复制其状态机、结果分类或错误出口。

上述过程共同遵守需求边界：任务只显式承接具体需求，列表项只作查询 / 防重锚点，不能自动吞并其它成员或成为任务目标权威；筹办、选择、执行及其任何业务材料或技术非成功都不得改变需求核心、直接产生需求、建立长期能力缺口节点或绕过第5节 self 产生确认门。

## 10. 正式结算

正式结算以具体需求节点为基本身份单位。即使多个成员目标完全相同，每个成员仍独立保留来源、父子位置、路径、当前性、权重、活动资格、预算、结算来源和正式结算记录。

同一当前世界比较结果可以被多个同目标成员消费，但成员资格、可用预算、来源当前性和最终结论必须逐成员裁决。列表项只作成员和任务查询锚点，不得直接生成总结合算结果。

正式结算至少可追溯：需求身份、目标合同、当前性、来源路径、任务及轮次、实例方法或动作证据、同截止当前值完整投影、可选状态 / 动态 / 因果证据、归因、权重 / 资格 / 预算来源、规则版本、事实截止、结论、幂等身份和生命周期。

正式结算是历史治理事实，不替代当前满足，也不删除需求。因果归因与价值算法读取4320及其下位规范。

## 11. 写入流程、事务与错误

需求业务统一入口依次完成：来源校验、目标完整性、所属存在、父域与路径校验、精确聚合查询、复用或新建裁决、原子入树及成员关系建立、正式读回。线程、任务管理器、方法执行体、候选生成器、观察中间层和显示层不得直接写需求结构。

正式需求不得以只入树未入列表的半结构存在。需求节点、核心关系、列表成员关系和可选父关系必须同代原子发布；父关系换代时退出旧关系、建立新关系并保留历史。当前组合读取共享事实截止，历史读取显式使用历史截止。

当前满足、等待、失活和恢复是互不替代的治理状态。路径失活不删除需求历史；满足或结算不自动退出需求；列表视图变化不得改变需求身份和目标合同。

至少区分：业务入口拒绝、引用冲突、证据不足、目标不完整、所属存在非法、父域非法、当前性失效、幂等冲突、事实代次漂移、资源失败和内部不一致。内部逻辑错误不得伪装成普通拒绝。

同幂等身份与同完整请求必须精确重复；同幂等身份与不同请求必须冲突；事实代次漂移零变化；发布未知只用原幂等身份和原请求收敛。不得用空值、默认值、缓存或线程上下文补齐坏目标。子需求写入幂等身份由任务子目标记录身份、父需求、筹办轮次和规范化目标语义在固定命名域稳定形成。

写入幂等身份只证明工程请求重试的一致性，不是业务请求、服务合同、账户或需求身份。

既有需求结构历史读取只按显式观察代次和历史截止读取需求、列表项和成员关系，不得包装成请求专用恢复账。任务子目标记录已有当前 / 历史读回和专用来源关系；消费者必须复用该合同，不得建立平行来源或恢复体系。

## 12. 验证合同与完成边界

设计与实现验证至少覆盖：

- 核心契约强类型、单目标和不可变；
- 当前满足使用同截止当前值，历史证据不能替代；
- 树 / 列表原子发布、唯一成员和精确聚合；
- self 产生确认、task owner 记录、需求 owner 发布的职责链；
- 双根唯一绑定、同所属存在父链、无环及跨树禁止；
- 方法 / 条件缺失只形成材料；
- 任务逐需求显式承接且列表不自动扩张来源；
- 成员独立结算和需求持续存在；
- 幂等、漂移、发布未知、普通拒绝和内部不一致分流；
- 当前与历史读回均不跨代拼装。

本规范生效只证明详细机器合同已从3100下沉并保持正式承载，不证明 DTO、接口、代码、运行闭环或验收已经实现。精确 ABI 仍须读取对应结构合同；不得用万能参数、自由属性槽、裸整数、文本或临时 bool 补造公开合同。
