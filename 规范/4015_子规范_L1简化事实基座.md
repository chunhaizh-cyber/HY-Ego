## 1. 定位与生效边界

L1 的目标实现是一套通用事实基座，只保存技术结构所有者事实、节点、关系和值三类普通事实及其原子发布状态。它不因承载世界树、语素树、需求树、任务树或其它逻辑图而改变结构或取得领域语义。

现有“旧四仓库”和“节点直接五仓”都是已退出目标结构，不得继续扩展为第三套并列数据基座。新的 L1 计划必须从本规范的三类事实模型建立；已经发布、但直接消费旧对象版本 DTO 的计划保持待激活，直到按本规范重做设计和 S0。

本规范不允许以 SQL、材料、缓存、索引、日志或界面代替内存已发布事实；0050、4040、4070 的运行期权威、原子发布和恢复边界继续有效。

L1 是业务中性数据层。普通公开合同只处理技术结构 owner、节点、关系、值、稳定编码、创建 / 退出事实代次、属性槽、通用原子提交、最小幂等和中性错误。技术 owner 只证明写入来源，不解释业务。业务过程、资格、操作标签、意图组、业务结果解释和执行证据统一位于 L5 之外，不得进入 L1—L5 任一数据服务的普通读写请求或结果。

## 2. 稳定编码与事实代次

1. 节点、关系、值和 `L1结构所有者事实` 共用一个非零、不透明、全局不可复用的稳定编码空间。编码不含类型、名称、地址、仓库号、容器位置、服务枚举或对象版本。
2. 节点、关系和值不持有独立身份版本、关系版本或值记录版本。替换一项关系或值时，旧事实退出，新事实使用新编码；不得修改旧事实端点、材料、类型、来源或写入所有者。
3. 每次成功写集只推进一个全局事实代次。事实代次是原子发布、写前并发校验、快照一致性和恢复互证的唯一技术代次，不是对象身份的一部分。
4. 每项事实保留创建事实代次和可选退出事实代次。业务时间必须作为具名类型化值表达；不得把系统发布时间、线程时钟或日志时间冒充观察、状态、动作或安全时间。
5. 一种类型的解释、值域或兼容规则发生不兼容变化时，建立新的属性类型节点编码；兼容关系必须显式、有向且可审计，不使用递增合同版本字段推断兼容。

## 3. 三类事实

### 3.1 节点

节点是可独立存在、可被关系连接、可拥有属性值的通用对象。节点至少包含稳定编码、节点类型、写入所有者、创建/退出事实代次和当前属性槽表。节点类型只分类结构能力，不自动授予任何领域资格。

节点可以拥有多个子节点和多个值，但表达方式不同：节点到节点一律通过关系；普通属性通过本节点唯一属性槽直接指向值。不得把关系成员再复制进节点子列表。

### 3.2 关系

关系是两个节点之间的有向事实，至少包含稳定编码、关系类型、源节点编码、目标节点编码、角色/顺序、写入所有者和创建/退出事实代次。组成、归属、来源、引用、当前值以外的拓扑和图结构均由关系承载。关系退出不删除端点；端点退出不自动推导关系退出。

退出节点时，调用方必须在同一中性写集中显式退出所有仍以该节点作为源端、目标端或关系类型的当前关系，以及所有仍以该节点作为所属节点、属性类型、来源或独立材料引用的当前值；否则整笔写集拒绝且当前状态零变化。L1 只检查当前结构引用闭包，不按业务名称或关系含义选择要退出的事实，也不自动补造关系或值退出项。

### 3.3 值与属性槽

值是不可变类型化载荷，至少包含稳定编码、所属节点编码、属性类型节点编码、材料、来源编码、写入所有者和创建/退出事实代次。每个节点对同一属性类型至多有一个当前属性槽；槽替换与新值发布、旧值退出必须在同一事实事务中完成。

需要独立关系、独立来源角色、独立生命周期或被其它节点引用的“值”必须提升为节点后以关系表达。特征定义、特征槽、状态、动态、需求、任务和方法都是节点；标量、区间、有序组和独立材料引用通常是值。

### 3.4 结构所有者事实与逐项所有权

L1 新增以下技术治理事实：

```text
L1结构所有者身份：一个非零稳定编码

L1所有者范围种类：
  旧共享范围=1
  独占结构范围=2

L1结构所有者事实：
  所有者身份
  范围种类
  创建事实代次
  可选退出事实代次
```

所有者事实与节点、关系和值共用同一 `仓库.L1事实基座`、同一稳定编码空间、同一全局事实代次、同一事务和最后发布点。它不是节点、关系或值，不取得业务对象解释，也不是业务主体、业务资格、服务名称、模块身份、缓存、SQL 权威或运行期 token。

owner-aware 节点、关系和值事实都保存一个非零 `写入所有者`。属性槽不保存第二 owner，唯一继承所属节点。所有者与稳定编码、类型、端点 / 材料和创建代次共同不可变；不得原地换 owner、复活 owner、把一个 owner 的事实重新标为另一 owner，或从名称、形状、本地键、旧模块和类型编码猜 owner。

`L1所有者范围写端口` 提交五类写项时，仓库必须在第一笔候选前按同一当前代次逐项校验：

1. 新节点的 `写入所有者=端口 owner`；普通写请求不得创建所有者事实。
2. 新关系及其关系类型节点必须属于端口 owner；源 / 目标节点可以跨 owner，只形成引用，不转移端点所有权。
3. 新值、所属节点和属性类型节点必须属于端口 owner；来源节点可以跨 owner，只形成来源引用。
4. 属性槽的所属节点、属性类型和新当前值必须属于端口 owner。
5. 每个退出节点、关系和值必须属于端口 owner；混 owner、owner 不符或夹带所有者事实固定许可拒绝、零候选。

引用闭包在所有权校验通过后独立裁决。端口无权修改或退出其它 owner 事实，即使结构引用闭包完整；同 owner 的事实仍被当前关系或值引用且未在同一合法写集中闭合时才返回引用冲突。

## 4. 事务、读取与恢复

1. 普通写请求只给出合同版本、期望基线事实代次、不透明稳定幂等编码，以及由节点 / 关系 / 值新建项、属性槽变更项和事实退出项组成的完整不可变中性写集；基线漂移、同键异义、类型不匹配或槽 / 关系矛盾在第一笔候选前拒绝。请求不得携带业务操作标签、意图组、领域意图凭证、请求意图摘要、执行证据摘要或材料、提供者见证、领域结果见证。
2. 同幂等编码且规范化中性写集逐字段完全相同返回原结果；同编码而写集不同返回冲突。内部摘要只可优化查找，摘要相同仍必须比较完整写集。候选、确认、逆序撤销、最后事实代次发布和发布后精确读回继续服从 4040；普通提交不以预探测或全仓扫描为前置。
3. 当前读取、历史读取、审计读取和恢复候选读取显式分离。四类入口不得共享一个含糊的“读取全部”结果，也不得用当前读取返回历史或审计材料。组合当前读取必须在首末事实代次相同后才返回成功；一次完整重试仍漂移时返回事实代次漂移，不返回混代材料。
4. 恢复以 owner 事实、三类普通事实、全局编码永久占用、属性槽一致性、关系端点、幂等账和事实代次证据形成隔离候选；不得从索引、SQL 行或材料补造 owner、节点、关系和值。

### 4.1 所有者范围 v2 写合同

现行 `L1中性CRUD合同版本=1` 的 DTO、函数名、幂等域和原成功行为保持不变，不得把旧 DTO 静默递增版本猜测兼容。新的不兼容合同使用独立身份：

```text
L1所有者范围CRUD合同版本=2
L1所有者范围一致当前读取合同版本=2
L1所有者范围一致关系类型闭包读取合同版本=1
```

`L1所有者范围写集请求` 只包含合同版本、期望事实代次、`L1所有者范围写入幂等身份` 和节点 / 关系 / 值新建项、属性槽变更项、退出事实项；不得包含 owner 编码、端口、业务标签、领域见证、服务枚举、名称、权限 bool、nonce 或 token。owner 只由调用该函数的实例绑定写端口隐式注入：

```cpp
L1所有者范围写入结果 L1所有者范围写端口::提交所有者范围中性写集(
    const L1所有者范围写集请求& 请求);
```

写结果回显 owner 身份、幂等身份、结构化状态、事实代次、是否发布、可重试边界和确定新编码映射。普通 owner 写的幂等域固定为 `(L1实例内部身份, owner稳定身份, L1所有者范围写入幂等身份)`：同 owner 同键同完整写集返回首次结果，同 owner 同键异写集返回幂等冲突，不同 owner 的相同数值键互不复用。端口、租约、nonce 和地址不进入幂等语义；恢复后同 owner 的新合法端口可以用原请求收敛未知发布。

所有者建立使用独立的 `L1所有者范围建立幂等身份`。同一实例签发器同键同义只建立一个 owner；已有活动端口时回显 owner 事实并许可拒绝，不交付第二端口。同键异义返回幂等冲突；另一 L1 实例的相同数值键只属于另一实例。

### 4.2 统一原始值材料

值事实的原始材料只有以下四种强类型形状：

```text
I64：一个有符号 64 位整数
I64组：有序有符号 64 位整数数组
U64组：有序无符号 64 位整数数组
独立材料引用：一个非零稳定编码，指向已发布的独立材料节点
```

空材料、裸字节、字符串拼接、通用 `I64` 槽位和调用方未声明的变体均在写前拒绝。材料形状必须与属性类型节点的 `值表示种类` 一致；L1 不解释单位、坐标、轮廓、业务值域或材料内容。

### 4.3 读取 DTO 与状态

现行 v1 兼容面必须唯一保留以下中性入口；不得再建立同义 v1 读取门面、整库读取入口或验收专用入口。owner-scoped v2 使用第 4.3.1 节的新具名入口，不与该集合互相替换：

```text
提交中性写集
读取中性当前节点
读取中性当前关系
读取中性当前值
读取中性当前属性
读取中性当前源关系组
读取中性当前目标关系组
读取中性历史事实
读取中性当前事实代次
尝试读取中性一致当前投影
```

上述入口使用值式请求和结果。源 / 目标关系组按已知端点与关系类型读取当前关系，结果按稳定编码确定排序并携带同一次读取的事实代次；既有一致当前投影继续只组合节点、关系、值、属性值及源 / 目标关系组，漂移时不返回混代材料。需要在关系端点尚未知时取得完整动态结构的调用方使用独立具名关系类型闭包投影：按一个已知入口关系类型枚举全部当前关系，并在同一仓库共享锁内为每个成员携带完整关系、源 / 目标节点、调用方明确选择的两端当前属性值及两端一跳源 / 目标关系组。该合同只扩展业务中性的有界动态结构读取，不成为整库、全 owner、递归图遍历、领域根或缓存入口；既有一致当前 v2 请求 / 结果、函数和行为保持不变，不以版本递增猜测兼容。

`L1所有者范围一致当前读取请求.期望事实代次=0` 是唯一的原子“选择锁内最新当前快照”模式：仓库取得同一次共享锁后才读取当前事实代次并完成全部投影，成功结果保留 `期望事实代次=0`、以 `读取事实代次` 回显实际所选截止，不得用“先读当前代次、再发起非零投影”的两次调用替代；非零值仍是严格乐观守卫，不匹配返回零载荷事实代次漂移。零模式不改变各项目未找到 / 已退出 / 属性未设置状态，也不形成自动重试、等待、写入或领域语义。空库尚无任何已发布事实时，零模式成功的读取事实代次可以为 0；一旦存在已发布事实，所选读取代次必须非零。要求非零截止的 L2—L5 服务必须在自身成功形状中拒绝空库代次 0，不得由 L1 伪造代次。审计、完整快照和恢复结果只在 4070 管理面重新进入实施范围时建立，不是当前生产目标必须保留的接口：

```text
当前事实结果：状态 + 读取事实代次 + 节点 / 关系 / 值三者之一
当前属性结果：状态 + 读取事实代次 + 节点编码 + 属性类型编码 + 当前值编码
源 / 目标关系组结果：状态 + 读取事实代次 + 端点编码 + 关系类型编码 + 有序当前关系组
历史事实结果：状态 + 被查询稳定编码 + 一条完整节点 / 关系 / 值历史记录
一致当前投影结果：状态 + 期望 / 读取事实代次 + 节点 / 关系 / 值 / 属性值 / 源关系组 / 目标关系组
一致关系类型闭包投影结果：状态 + 期望 / 读取事实代次 + 节点 / 关系 / 值 / 属性值 / 源关系组 / 目标关系组 / 关系类型闭包
  审计结果：状态 + 被查询写集幂等编码 + 有序不可变审计记录组
完整快照结果：状态 + 当前事实代次 + 当前节点 / 关系 / 值 + 当前属性槽 + 永久编码占用
恢复结果：恢复状态 + 目标事实代次；非成功不带业务材料
  ```

`L1审计读取结果` 必须显式携带调用方传入的 `写集幂等键`；记录组为空或读取未命中时也不得从记录首项反推该键。成功记录组中的每项记录幂等键必须与结果幂等键相同，并按事件序号严格升序返回。完整快照中的当前属性槽唯一由各 `节点事实.当前属性` 承载，不建立第二份顶层槽表。

当前读取只返回仍可读的当前事实；输入编码已退出时返回 `已退出` 且不返回当前事实副本；不存在返回 `未找到`。属性槽不存在返回 `属性未设置`。历史读取可以返回当前或已退出的一条完整记录，但不返回当前槽表、审计或恢复材料。审计读取只返回审计记录，不返回事实副本。

### 4.4 恢复材料和两阶段发布

本节只冻结未来恢复管理面的语义边界，不要求当前生产目标保留已有恢复 DTO、候选、审计账、整库快照或恢复实现。当前阶段可以物理删除这些旧实现；未来重新纳入崩溃、重启或跨进程恢复时，必须按本节和 4070 从当时的中性 CRUD 合同重新设计，不得恢复旧兼容面。

恢复入口接收 `L1恢复材料`，而不是把当前快照冒充全部恢复证据。材料必须明确分账：

```text
当前快照：当前事实代次、当前 owner、当前节点 / 关系 / 值及其 owner、当前属性槽、永久编码占用
历史事实：已退出 owner、节点 / 关系 / 值的完整记录组，不重复当前快照
审计记录：不可变幂等审计记录组，按写集幂等编码和事件序号有序
幂等账：v1 legacy 与 owner-scoped 两套已发布写集的完整规范化写集、owner 域及首次结果
```

`建立恢复候选` 只在隔离副本中校验材料，不改变当前状态；校验包括 owner 与三类事实完整性、全局编码不重复且均在永久占用内、每项事实 owner 在创建截止有效、独占 / legacy 范围合法、关系类型与关系 owner 一致、节点槽 / 值 owner 一致、退出不跨 owner、当前槽唯一、关系端点存在、值材料与属性类型匹配、生命周期代次有序、审计与两套幂等账可互证。校验失败返回结构化拒绝，候选不存在；不得默认补成 legacy owner。

`确认恢复候选` 在同一独占事务内再次比较调用方期望基线事实代次；漂移则丢弃候选并返回事实代次漂移。通过后一次替换当前状态，发布目标事实代次为确认时当前代次加一，并保留材料中的历史代次作为记录生命周期证据。发布后必须按新代次读回；任何矛盾都返回内部不一致并进入隔离，不得逐项回填。

`撤销恢复候选` 是拒绝发布入口，只丢弃隔离候选，不修改当前事实代次；无候选时返回无候选。SQL、索引、材料文件或审计旁路不能单独确认恢复成功。

恢复结果中的 `事实代次` 始终表示结果形成时安全取得的权威当前事实代次：候选建立、候选撤销、无候选、入口拒绝、材料不完整、事实代次漂移和资源失败均不得返回预计的当前代次加一；只有恢复已发布返回一次替换并读回后的新当前代次。锁前或状态读取前无法安全取得代次时返回零；发布后读回矛盾返回已经发布的新当前代次并进入隔离。

恢复错误必须按来源分账：调用方材料缺项、编码/生命周期/槽/端点/类型/材料/幂等账/审计互证不满足 4015 的，返回 `材料不完整`，候选不存在且当前状态零变化；仓库已有状态不变量破坏、通过材料校验后的候选构造矛盾、交换后读回矛盾或不能归因于材料的未知异常，返回 `内部不一致`。发布后内部不一致保留已发布代次，当前读取、普通提交和恢复确认均进入隔离拒绝路径。

运行期写端口、签发器内部租约、nonce、地址、进程 / 线程身份、模块名和服务枚举不进入事实、DTO、幂等账、审计、SQL、恢复材料、日志或界面。恢复只持久化 owner 事实与事实 owner；发布后由新 L1 运行包的唯一签发器按具名重入门重新签发能力，旧 token 永久无效。

## 5. 索引与服务边界

索引只保存可重建的编码候选。命中后必须回读同一事实代次内的 owner、节点、关系和值；索引、缓存和统计不得保存第二份 owner、当前属性槽、关系成员或生命周期权威。

L1 普通 CRUD 只接受调用方已经形成的三类中性事实新建项、属性槽变更和退出项，只返回不可变值式快照；owner 建立 / 重入 / 退出只经签发管理面。L2—L5 数据结构服务及 L5 之外业务调用方均不得取得可变仓、锁、事务令牌、候选或撤销能力；组合服务不得直连 L1 仓库、SQL、缓存或材料。

普通 CRUD 只按请求中稳定编码及必要索引访问受影响事实，不得固定执行完整快照、全仓扫描、审计材料组装或恢复材料生成。完整快照、审计和恢复属于未来分离的诊断 / 管理合同；当前不实施时不保留空壳、候选状态或旧数据结构。它们不得被普通 CRUD 的成功合同隐式调用。迁移期间既有携带业务标签、意图、执行证据或领域见证的旧入口只作待退出代码，不得新增消费者，并与新中性合同共用同一事实仓、同一事实代次和同一稳定编码空间，不得形成第二事实基座。

### 5.1 实例绑定签发信任根

后继实现必须由唯一工厂建立一个 move-only 运行包：

```cpp
L1事实基座运行包 建立L1事实基座运行包();

    const L1所有者范围建立请求& 请求);

L1所有者范围退出结果 L1所有者范围签发器::退出所有者范围(
    const L1所有者范围退出请求& 请求);

```

每个 `L1事实基座运行包` 只有一个全新 L1 实例和一个与该实例内部状态绑定的 `L1所有者范围签发器`。`L1事实基座服务` 不允许 public 默认构造；普通服务引用不能创建或取得签发器。另一工厂结果不能给既有实例签发端口。每个正式登记的独占结构范围只取得 const L1 读取服务和一份移动注入的端口；同一个上层公开服务只有在目标结构规范明确登记多个互不重叠的结构范围时，才可为每个范围分别持有一份端口。多端口不得共享 owner、合并为可任选 owner 的通用端口、形成混 owner 写集或让一个端口写另一范围；`L1事实基座服务` 只公开 const owner-aware 读取与现行 v1 兼容入口，不公开按 owner 取得端口。

签发器和 raw `L1所有者范围写端口` 都不可复制。端口绑定精确实例、owner 和不可公开构造的运行期租约，只能移动注入该 owner 的唯一结构所有者；移动源、析构、owner 退出、跨实例使用或 L1 实例销毁后失效。服务不得返回、借用、复制、转签或在多个结构范围之间交换端口；同一实例同一 owner 至多一个活动端口，重复签发许可拒绝。

签发器只负责：同事务建立一个独占 owner 事实并交付唯一端口；在恢复 / 明确重入、owner 当前且无活动端口时重新签发；端口失效、owner 当前事实归零、幂等提交收敛且恢复 / 审计引用闭合后退出 owner。owner 退出保留历史，稳定编码永久占用且不得复活或交给另一服务。

“raw 端口不可伪造”不禁止普通外部调用者通过对应 L2 公开工厂取得合法服务并调用其公开 CRUD。各族工厂只能返回已由装配面绑定正确 owner 端口的唯一服务实例；重复取得只能返回同一服务实例 / 引用或结构化拒绝，不能建立第二 owner、第二服务所有者或第二端口。raw 端口、owner 选择、签发器和按 owner 重建服务入口不得导出。L1 核心不得 import 或 friend 六类 L2 数据 / 服务，不按 L2 枚举分支；owner 与公开服务工厂的绑定由上层 provider / 装配负责。

### 5.2 v1 legacy 隔离与迁移

现行 `提交中性写集(v1)` 暂时保留原 DTO、函数名、幂等和成功行为。全部 v1 新事实由仓库隐式绑定同一 `旧共享范围` owner；该 owner 首次需要时与首笔 v1 数据在同一代次建立，v1 不返回、指定或控制其编码。

v1 只能创建、修改和退出 legacy owner 的节点、关系、值与属性槽，只能使用 legacy owner 的关系类型 / 属性类型。任一独占 owner 事实、类型或退出项进入 v1 写集，在候选前固定 `入口拒绝`、零变化；即使调用方知道独占关系类型编码，也不能用它创建关系。v1 读取 DTO 不含 owner，不能作为新 owner 证明；owner-aware 读取如实回显 `旧共享范围`，要求唯一写入方的 provider 固定拒绝。

legacy 事实不原地 adoption：禁止扫描全仓按形状、名称、本地键、历史调用模块、关系类型编码或缓存猜 owner，禁止修改原稳定编码、创建 / 退出代次或幂等账。默认迁移由新 provider 经 owner-scoped 入口重建新事实和新稳定编码，再由具名 legacy 退出计划显式闭合旧事实。确需保码时必须另立 owner adoption 正式合同与可审计原写入方证据；形成前一律拒绝。

## 6. 公开结构验证与退出条件

L1 不在生产程序内自检或自判通过。生产代码之外的验证者可以直接通过正式 L1 公开入口输入受控强类型数据结构，消费结构化结果并从正式读取入口核对最终当前 / 历史状态；不要求等待 L2—L5 或具名业务消费者完成，也不得取得私有仓、锁、候选或事务权限。

L1 完整结构验证至少覆盖：

1. 一个节点拥有多个直接属性值和多个关系子节点，且两类成员不重复记账；
2. 属性替换和关系替换的旧退出、新发布、幂等读回和同键异义；
3. 候选失败、逆序撤销、发布后精确读回、事实代次漂移，以及同键同中性写集精确重复 / 同键异中性写集冲突；
4. 创建、精确当前读取、更新时新事实发布并退出旧事实、退出、历史读取的公开往返；已退出事实只能从历史入口得到；
5. 全局编码不可复用、类型节点兼容显式化，以及普通 CRUD 不触发全仓扫描、执行证据、领域见证或恢复材料固定成本；
6. 所有采用新基座的生产代码不再 import 旧四仓库、节点直接五仓、旧句柄或对象版本 DTO。

所有者范围 v2 的生产外公开接口矩阵还必须证明：

1. 一个运行包只有一个 L1 实例和签发器；另一运行包、普通 L1 服务引用或公开 owner 编码不能取得该实例端口。
2. 两个独占 owner 取得不同稳定编码；同 owner 至多一个活动端口，端口不可复制，移动源 / 跨实例 / 析构后 / owner 退出后提交均许可拒绝且零推进。
3. 请求 DTO 不存在可篡改 owner 字段；节点 owner 自动绑定，关系类型 owner 与关系 owner 相同，源 / 目标可跨 owner，值的所属节点 / 属性类型 / 新值 owner 相同且来源可跨 owner。
4. 属性槽和退出的混 owner 写集在候选前拒绝；同 owner 但外部引用未闭合才进入引用冲突。
5. owner-scoped 同键同写集精确重复、同键异写集冲突、不同 owner 同数值键互不复用；未知发布可由同 owner 新合法端口用原请求收敛。
6. owner 当前 / 历史、三类事实当前 / 历史、关系组、属性值组和一致投影全部回显同截止 owner；owner 缺失、复义或读回变化属于内部不一致。
7. v1 代表性创建 / 关系 / 值 / 属性 / 退出保持原 DTO 和行为且只落 legacy owner；v1 无法制造、修改或退出任何会被独占 owner provider 接受的事实。
8. legacy 事实不能经新端口原地改 owner；没有具名 adoption 合同时保码迁移拒绝。
9. owner 退出要求端口失效、当前事实归零、幂等与引用闭合；历史仍可读，owner 不复活。
10. L1 核心零六类 L2 反向 import / friend / 枚举分支；代表性 L2 公开工厂可向普通调用者交付合法服务，但调用者不能取得 raw 端口、指定 owner、重复领端口或绕过服务制造该族接受的事实。一个公开服务依正式上层规范持有多个端口时，还必须证明 owner 两两不同、每个写函数到端口的路由唯一、跨端口混写在候选前拒绝，且任一端口都不能制造另一范围公开读取接受的事实。

单条成功路径只证明实际覆盖部分。只有增、查、改、退 / 历史读取及正式合同要求的幂等、原子性、并发和非法请求零变化全部经公开接口黑盒验证，才能声明 L1 数据结构服务完整通过。该结论只覆盖现行合同，不无限外推未来结构需求。

并发竞争、原子可见性和发布后读回作为对应 CRUD 的附属结构条件验证。允许建立生产代码之外的 L1 黑盒验证驱动，但该驱动只能使用公开 DTO 和正式入口，不能编译进生产目标、建立双目标或业务场景、解析日志、访问内部仓或形成第二套权威事实。

当前阶段不考虑崩溃、重启、断电或跨进程恢复；4070 只保留独立管理面合同，不得成为普通 CRUD 的实施或完成门。旧状态矩阵、双目标自检、完整执行证据闭环和专项复验只作历史证据，不能证明本规范下的新数据层正确。生产程序返回结构化数据结果，不自判验收 PASS、不包含验收运行器。日志只报告已经发生的调用、结构化状态和必要诊断，不是机器事实、结构化结果或精确读回的替代品。

旧基座通常只在全部生产调用者改用新基座、Debug / Release 构建通过，且新基座完成本节公开结构黑盒矩阵后删除。若用户明确裁决旧业务能力整体退场，而不是要求保留原行为，则允许把旧基座及其反向依赖闭包作为一个退役切片直接物理删除；该切片必须保留程序入口、未依赖旧基座的线程基础模块和新 L1，实现只含新 L1 的最小空装配，并对已经退出的启动模式返回结构化非成功，禁止用空成功、兼容壳或默认事实冒充原业务仍可用。编译链接只证明退役后静态闭合，不证明新 L1 数据逻辑、业务能力或消费者已经改接。

生产内自检、日志、骨架返回、单次编译或单个 CRUD 成功均不构成数据层正确性门禁。生产外公开接口验证是合法证据，不得因其独立于业务消费者而排除。
