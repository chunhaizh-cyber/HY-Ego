# 4015 子规范 L1简化事实基座

编号：4015
日期：20260809
状态：正式子规范

直接上级规范：0050。

直接依赖规范：4010、4020。

相关边界规范：4030—4070、4110、4170、4200。

## 1. 定位与生效边界

L1 的目标实现是一套通用事实基座，只保存节点、关系和值三类事实及其原子发布状态。它不因承载世界树、语素树、需求树、任务树或其它逻辑图而改变结构或取得领域语义。

现有“旧四仓库”和“节点直接五仓”都是已退出目标结构，不得继续扩展为第三套并列数据基座。新的 L1 计划必须从本规范的三类事实模型建立；已经发布、但直接消费旧对象版本 DTO 的计划保持待激活，直到按本规范重做设计和 S0。

本规范不允许以 SQL、材料、缓存、索引、日志或界面代替内存已发布事实；0050、4040、4070 的运行期权威、原子发布和恢复边界继续有效。

L1 是业务中性数据层。普通公开合同只处理节点、关系、值、稳定编码、创建 / 退出事实代次、属性槽、通用原子提交、最小幂等和中性错误。业务过程、资格、操作标签、意图组、业务结果解释和执行证据统一位于 L5 之外，不得进入 L1—L5 任一数据服务的普通读写请求或结果。

## 2. 稳定编码与事实代次

1. 节点、关系和值共用一个非零、不透明、全局不可复用的稳定编码。编码不含类型、名称、地址、仓库号、容器位置或对象版本。
2. 节点、关系和值不持有独立身份版本、关系版本或值记录版本。替换一项关系或值时，旧事实退出，新事实使用新编码；不得修改旧事实端点、材料、类型或来源。
3. 每次成功写集只推进一个全局事实代次。事实代次是原子发布、写前并发校验、快照一致性和恢复互证的唯一技术代次，不是对象身份的一部分。
4. 每项事实保留创建事实代次和可选退出事实代次。业务时间必须作为具名类型化值表达；不得把系统发布时间、线程时钟或日志时间冒充观察、状态、动作或安全时间。
5. 一种类型的解释、值域或兼容规则发生不兼容变化时，建立新的属性类型节点编码；兼容关系必须显式、有向且可审计，不使用递增合同版本字段推断兼容。

## 3. 三类事实

### 3.1 节点

节点是可独立存在、可被关系连接、可拥有属性值的通用对象。节点至少包含稳定编码、节点类型、创建/退出事实代次和当前属性槽表。节点类型只分类结构能力，不自动授予任何领域资格。

节点可以拥有多个子节点和多个值，但表达方式不同：节点到节点一律通过关系；普通属性通过本节点唯一属性槽直接指向值。不得把关系成员再复制进节点子列表。

### 3.2 关系

关系是两个节点之间的有向事实，至少包含稳定编码、关系类型、源节点编码、目标节点编码、角色/顺序和创建/退出事实代次。组成、归属、来源、引用、当前值以外的拓扑和图结构均由关系承载。关系退出不删除端点；端点退出不自动推导关系退出。

### 3.3 值与属性槽

值是不可变类型化载荷，至少包含稳定编码、所属节点编码、属性类型节点编码、材料、来源编码和创建/退出事实代次。每个节点对同一属性类型至多有一个当前属性槽；槽替换与新值发布、旧值退出必须在同一事实事务中完成。

需要独立关系、独立来源角色、独立生命周期或被其它节点引用的“值”必须提升为节点后以关系表达。特征定义、特征槽、状态、动态、需求、任务和方法都是节点；标量、区间、有序组和独立材料引用通常是值。

## 4. 事务、读取与恢复

1. 普通写请求只给出合同版本、期望基线事实代次、不透明稳定幂等编码，以及由节点 / 关系 / 值新建项、属性槽变更项和事实退出项组成的完整不可变中性写集；基线漂移、同键异义、类型不匹配或槽 / 关系矛盾在第一笔候选前拒绝。请求不得携带业务操作标签、意图组、领域意图凭证、请求意图摘要、执行证据摘要或材料、提供者见证、领域结果见证。
2. 同幂等编码且规范化中性写集逐字段完全相同返回原结果；同编码而写集不同返回冲突。内部摘要只可优化查找，摘要相同仍必须比较完整写集。候选、确认、逆序撤销、最后事实代次发布和发布后精确读回继续服从 4040；普通提交不以预探测或全仓扫描为前置。
3. 当前读取、历史读取、审计读取和恢复候选读取显式分离。四类入口不得共享一个含糊的“读取全部”结果，也不得用当前读取返回历史或审计材料。组合当前读取必须在首末事实代次相同后才返回成功；一次完整重试仍漂移时返回事实代次漂移，不返回混代材料。
4. 恢复以三类事实、全局编码永久占用、属性槽一致性、关系端点、幂等账和事实代次证据形成隔离候选；不得从索引、SQL 行或材料补造节点、关系和值。

### 4.1 统一原始值材料

值事实的原始材料只有以下四种强类型形状：

```text
I64：一个有符号 64 位整数
I64组：有序有符号 64 位整数数组
U64组：有序无符号 64 位整数数组
独立材料引用：一个非零稳定编码，指向已发布的独立材料节点
```

空材料、裸字节、字符串拼接、通用 `I64` 槽位和调用方未声明的变体均在写前拒绝。材料形状必须与属性类型节点的 `值表示种类` 一致；L1 不解释单位、坐标、轮廓、业务值域或材料内容。

### 4.2 读取 DTO 与状态

当前普通 CRUD 实现必须唯一拥有并公开当前事实、当前属性、历史事实和事实代次等值式结果。审计、完整快照和恢复结果只在 4070 管理面重新进入实施范围时建立，不是当前生产目标必须保留的接口：

```text
当前事实结果：状态 + 读取事实代次 + 节点 / 关系 / 值三者之一
当前属性结果：状态 + 读取事实代次 + 节点编码 + 属性类型编码 + 当前值编码
历史事实结果：状态 + 被查询稳定编码 + 一条完整节点 / 关系 / 值历史记录
  审计结果：状态 + 被查询写集幂等编码 + 有序不可变审计记录组
完整快照结果：状态 + 当前事实代次 + 当前节点 / 关系 / 值 + 当前属性槽 + 永久编码占用
恢复结果：恢复状态 + 目标事实代次；非成功不带业务材料
  ```

`L1审计读取结果` 必须显式携带调用方传入的 `写集幂等键`；记录组为空或读取未命中时也不得从记录首项反推该键。成功记录组中的每项记录幂等键必须与结果幂等键相同，并按事件序号严格升序返回。完整快照中的当前属性槽唯一由各 `节点事实.当前属性` 承载，不建立第二份顶层槽表。

当前读取只返回仍可读的当前事实；输入编码已退出时返回 `已退出` 且不返回当前事实副本；不存在返回 `未找到`。属性槽不存在返回 `属性未设置`。历史读取可以返回当前或已退出的一条完整记录，但不返回当前槽表、审计或恢复材料。审计读取只返回审计记录，不返回事实副本。

### 4.3 恢复材料和两阶段发布

本节只冻结未来恢复管理面的语义边界，不要求当前生产目标保留已有恢复 DTO、候选、审计账、整库快照或恢复实现。当前阶段可以物理删除这些旧实现；未来重新纳入崩溃、重启或跨进程恢复时，必须按本节和 4070 从当时的中性 CRUD 合同重新设计，不得恢复旧兼容面。

恢复入口接收 `L1恢复材料`，而不是把当前快照冒充全部恢复证据。材料必须明确分账：

```text
当前快照：当前事实代次、当前节点 / 关系 / 值、当前属性槽、永久编码占用
历史事实：已退出节点 / 关系 / 值的完整记录组，不重复当前快照
审计记录：不可变幂等审计记录组，按写集幂等编码和事件序号有序
幂等账：已发布写集的完整规范化写集及首次结果
```

`建立恢复候选` 只在隔离副本中校验材料，不改变当前状态；校验包括三类事实完整性、全局编码不重复且均在永久占用内、当前槽唯一、关系端点存在、值材料与属性类型匹配、生命周期代次有序、审计与幂等账可互证。校验失败返回结构化拒绝，候选不存在。

`确认恢复候选` 在同一独占事务内再次比较调用方期望基线事实代次；漂移则丢弃候选并返回事实代次漂移。通过后一次替换当前状态，发布目标事实代次为确认时当前代次加一，并保留材料中的历史代次作为记录生命周期证据。发布后必须按新代次读回；任何矛盾都返回内部不一致并进入隔离，不得逐项回填。

`撤销恢复候选` 是拒绝发布入口，只丢弃隔离候选，不修改当前事实代次；无候选时返回无候选。SQL、索引、材料文件或审计旁路不能单独确认恢复成功。

恢复结果中的 `事实代次` 始终表示结果形成时安全取得的权威当前事实代次：候选建立、候选撤销、无候选、入口拒绝、材料不完整、事实代次漂移和资源失败均不得返回预计的当前代次加一；只有恢复已发布返回一次替换并读回后的新当前代次。锁前或状态读取前无法安全取得代次时返回零；发布后读回矛盾返回已经发布的新当前代次并进入隔离。

恢复错误必须按来源分账：调用方材料缺项、编码/生命周期/槽/端点/类型/材料/幂等账/审计互证不满足 4015 的，返回 `材料不完整`，候选不存在且当前状态零变化；仓库已有状态不变量破坏、通过材料校验后的候选构造矛盾、交换后读回矛盾或不能归因于材料的未知异常，返回 `内部不一致`。发布后内部不一致保留已发布代次，当前读取、普通提交和恢复确认均进入隔离拒绝路径。

## 5. 索引与服务边界

索引只保存可重建的编码候选。命中后必须回读同一事实代次内的节点、关系和值；索引、缓存和统计不得保存第二份当前属性槽、关系成员或生命周期权威。

L1 只接受调用方已经形成的三类中性写项，只返回不可变值式快照。L2—L5 数据结构服务及 L5 之外业务调用方均不得取得可变仓、锁、事务令牌、候选或撤销能力；组合服务不得直连 L1 仓库、SQL、缓存或材料。

普通 CRUD 只按请求中稳定编码及必要索引访问受影响事实，不得固定执行完整快照、全仓扫描、审计材料组装或恢复材料生成。完整快照、审计和恢复属于未来分离的诊断 / 管理合同；当前不实施时不保留空壳、候选状态或旧数据结构。它们不得被普通 CRUD 的成功合同隐式调用。迁移期间既有携带业务标签、意图、执行证据或领域见证的旧入口只作待退出代码，不得新增消费者，并与新中性合同共用同一事实仓、同一事实代次和同一稳定编码空间，不得形成第二事实基座。

## 6. 公开结构验证与退出条件

L1 不在生产程序内自检或自判通过。生产代码之外的验证者可以直接通过正式 L1 公开入口输入受控强类型数据结构，消费结构化结果并从正式读取入口核对最终当前 / 历史状态；不要求等待 L2—L5 或具名业务消费者完成，也不得取得私有仓、锁、候选或事务权限。

L1 完整结构验证至少覆盖：

1. 一个节点拥有多个直接属性值和多个关系子节点，且两类成员不重复记账；
2. 属性替换和关系替换的旧退出、新发布、幂等读回和同键异义；
3. 候选失败、逆序撤销、发布后精确读回、事实代次漂移，以及同键同中性写集精确重复 / 同键异中性写集冲突；
4. 创建、精确当前读取、更新时新事实发布并退出旧事实、退出、历史读取的公开往返；已退出事实只能从历史入口得到；
5. 全局编码不可复用、类型节点兼容显式化，以及普通 CRUD 不触发全仓扫描、执行证据、领域见证或恢复材料固定成本；
6. 所有采用新基座的生产代码不再 import 旧四仓库、节点直接五仓、旧句柄或对象版本 DTO。

单条成功路径只证明实际覆盖部分。只有增、查、改、退 / 历史读取及正式合同要求的幂等、原子性、并发和非法请求零变化全部经公开接口黑盒验证，才能声明 L1 数据结构服务完整通过。该结论只覆盖现行合同，不无限外推未来结构需求。

并发竞争、原子可见性和发布后读回作为对应 CRUD 的附属结构条件验证。允许建立生产代码之外的 L1 黑盒验证驱动，但该驱动只能使用公开 DTO 和正式入口，不能编译进生产目标、建立双目标或业务场景、解析日志、访问内部仓或形成第二套权威事实。

当前阶段不考虑崩溃、重启、断电或跨进程恢复；4070 只保留独立管理面合同，不得成为普通 CRUD 的实施或完成门。旧状态矩阵、双目标自检、完整执行证据闭环和专项复验只作历史证据，不能证明本规范下的新数据层正确。生产程序返回结构化数据结果，不自判验收 PASS、不包含验收运行器。日志只报告已经发生的调用、结构化状态和必要诊断，不是机器事实、结构化结果或精确读回的替代品。

旧基座只能在全部生产调用者改用新基座、Debug / Release 构建通过，且新基座完成本节公开结构黑盒矩阵后删除；生产内自检、日志、骨架返回、单次编译或单个 CRUD 成功均不构成删除门禁。生产外公开接口验证是合法证据，不得因其独立于业务消费者而排除。

## 7. 旧数据层验收体系退出边界

规范正式生效后，旧数据层验收体系专用代码必须通过独立代码切片物理删除，不得迁移、改名或重组为另一套双目标、状态矩阵、执行证据矩阵或专项复验：

1. 删除旧 L1 核心专项自检模块 `海中鱼巣/核心/自检.L1事实基座.ixx` 和 `海中鱼巣/核心/自检.L1可重建索引.ixx`；若实现扫描发现其它文件只服务于旧 L1 验收矩阵，必须具名回到计划支撑裁决，不能按名称批量删除领域自检。
2. 删除 `海中鱼巣/启动.应用程序.ixx` 中对上述模块和运行期旧 L1 验收块的 import、包装函数、自检登记与固定编号；生产入口不保留自检运行器或验收模式。其它领域是否属于生产维护能力按 ACCEPTANCE-01 和 8120 逐项裁决，不按 `L1` 名称批量删除。
3. 删除 `海中鱼巣.vcxproj` 与 `海中鱼巣.vcxproj.filters` 对已删除专项模块、自检运行器和验收专用模块的编译引用，不建立替代生产工程目标、第二 exe 或独立自检目标。
4. 从 `海中鱼巣/自检.运行期上下文.ixx` 删除直接构造旧仓、直接读取旧 L1 内部对象和以旧双目标 / 旧服务所有权证明数据层正确的验收块；文件内与旧 L1 验收无关的运行期上下文检查保留。
5. 历史施工记录、验证记录和集成验收记录原样保留，继续只说明旧实现历史；不得删除、覆盖或改写为新合同成功证据。

生产服务、具名人读日志和具名生产维护能力不因本节机械删除。生产初始化后置条件检查、SQL 审计投影、性能遥测、D455 生产采集 / 材料入口、运行期健康检查等若由公开生产合同拥有，属于保留候选，不得因文件或函数名含“检查”“专项”或“D455”直接删除；它们不能登记到自检运行器，也不能返回验收 PASS。生产热路径中的业务操作标签、意图组、执行证据和领域见证属于 legacy 生产合同迁移，必须由后续中性 CRUD 接口替代计划在保持调用链可编译、可运行的前提下逐步退出；不得借“删除验收代码”直接移除 DTO、服务逻辑或调用点而破坏现有生产链。

旧验收代码删除只证明旧验证入口退出，不证明中性 CRUD 已实现或 L1 已完善。新数据层必须由生产代码之外的验证者经正式公开入口输入受控数据结构，并以结构化结果和最终当前 / 历史状态读回完成增删改查矩阵；不需要等待业务消费者，生产日志只供人读，不承担机器判定。
