## 1. 权威边界

本规范是基础数据集的现行机器合同，取代旧L1事实基座在节点、关系、字段、直接值、owner分区、事实代次和历史读取上的冲突定义。基础数据集统一采用current-only模型，不保存操作历史、事实代次、业务合同版本或调用者可选择的写入owner。

规范正式成立不证明当前代码、持久化、恢复、迁移或消费者切换已经完成；实现差距只表示后继施工义务，不削弱本规范的目标语义。

## 2. 根定位

基础数据集是无业务语义的最小通用数据底座。它只负责保存和操作：

```text
节点
外部关系
字段关系
字段直接值
```

它不知道节点属于特征值、特征、存在、场景、状态、动态、因果、概念、需求、任务或方法。业务节点类型、字段清单、字段基数、关系含义、树或图约束、材料格式和生命周期均由上层数据类定义和校验。

基础数据集不是历史账、事件流、操作日志、业务对象仓库或概念推理服务。它不得根据字段名称、关系形状、直接值内容或调用路径推断业务语义。

## 3. 统一稳定编码

### 3.1 编码形式

节点、外部关系和字段关系共用一种稳定编码：

```cpp
struct 稳定编码 final {
    std::uint64_t 值 = 0;
};
```

规则如下：

1. `0` 是空编码，不标识任何已建立对象。
2. 非零编码由基础数据集分配，调用方不得自行指定、复用或从材料摘要推导。
3. 同一个基础数据集身份空间内，节点、外部关系和字段关系的编码全局互异。
4. 编码只表示对象身份，不携带对象类别、业务类型、层级、创建时间或值内容。
5. 调用方必须通过对应查询入口确认编码实际指向节点、外部关系还是字段关系。
6. 删除对象后不得把其编码重新分配给另一个对象。

### 3.2 当前实现边界

当前实现使用进程内单调递增计数器，从 `1` 开始分配编码且不回收。但它没有磁盘持久化、数据集身份和启动恢复，因此目前只能保证：

```text
同一个基础数据集对象
并且仅在该对象存活期间
```

的编码唯一和稳定。不同基础数据集对象可以产生相同数值编码；程序重启后也会重新从 `1` 开始。调用方不得把一个数据集对象产生的编码提交给另一个数据集对象；当前编码本身不携带数据集身份，底座也无法识别这种跨实例误用。正式使用“长期稳定编码”前必须补齐第 15 节的持久化与恢复合同。

## 4. 数据对象封闭集合

### 4.1 基础节点

基础节点固定只有一个底层字段：

| 字段 | 类型 | 基数 | 含义 |
| --- | --- | --- | --- |
| 编码 | 稳定编码 | 恰一 | 节点在当前基础数据集身份空间中的身份。 |

基础节点本身不保存节点类型、名称、父节点、业务字段、版本或历史。上层需要确认节点类型时，必须建立统一的类型字段节点，并以字段关系把业务实例节点指向共享类型节点。

`L1公共事实.数据.h` 中现有 `节点种类` 枚举没有进入 `基础节点`，也没有被基础数据集读写。未另行纳入本规范前，不得把它视为新版基础数据集已经保存或校验的节点字段。

### 4.2 基础外部关系

基础外部关系固定包含：

| 字段 | 类型 | 基数 | 含义 |
| --- | --- | --- | --- |
| 编码 | 稳定编码 | 恰一 | 关系身份。 |
| 源节点 | 稳定编码 | 恰一 | 已存在节点。 |
| 目标节点 | 稳定编码 | 恰一 | 已存在节点。 |
| 类型 | 基础外部关系类型 | 恰一 | `父子`或`兄弟`。 |
| 角色或顺序 | I64 | 恰一 | 由上层解释；默认值为0。 |

外部关系类型的封闭集合为：

```cpp
enum class 基础外部关系类型 : std::uint8_t {
    父子 = 1,
    兄弟 = 2
};
```

方向规定：

```text
父子：源节点是父节点，目标节点是子节点
兄弟：源节点和目标节点构成一条有方向的兄弟记录
```

基础数据集不自动建立反向关系，不从共同父节点推导兄弟关系，也不把兄弟关系解释为无向边。若某上层结构要求双向兄弟关系、唯一顺序、共同父节点或对称读回，必须由该上层结构合同明确形成和校验。

基础数据集允许同端点、同类型、同角色的多条关系；不校验自环、父子环、跨树、重复边或角色唯一性。上层数据类必须在写入前校验其结构约束。

### 4.3 基础字段关系

基础字段关系用于表达某个节点包含的字段：

| 字段 | 类型 | 基数 | 含义 |
| --- | --- | --- | --- |
| 编码 | 稳定编码 | 恰一 | 字段关系身份。 |
| 所属节点 | 稳定编码 | 恰一 | 包含该字段的节点。 |
| 字段节点 | 稳定编码 | 恰一 | 说明字段角色的共享节点。 |
| 内容 | 基础字段内容 | 恰一 | 直接值或另一个节点的稳定编码。 |

字段内容的封闭联合为：

```cpp
using 基础字段内容 = std::variant<基础值, 稳定编码>;
```

因此，同一字段可以采用两种物理形态：

```text
所属节点 --字段节点--> 直接值
所属节点 --字段节点--> 目标节点
```

字段节点只是由上层赋予含义的普通节点。基础数据集不维护内建字段枚举，也不判断字段节点是否适用于所属节点。

同一“所属节点 + 字段节点”允许存在零项、一项或多项字段关系。恰一、可选、多值、有序或互斥等基数要求全部由上层数据类校验。

## 5. 直接值

直接值是字段末端的原始材料，不取得独立稳定编码：

```cpp
using 基础原始值 = std::variant<
    std::int64_t,
    std::vector<std::int64_t>,
    std::vector<std::uint64_t>,
    std::string>;
```

规则如下：

1. 向量整体是一个直接值；顺序和重复元素必须原样保留。
2. 字符串按完整字节序列保存和比较；基础数据集不验证 UTF-8，不执行大小写折叠、Unicode 归一化或语言解释。
3. 直接值不具有独立编码、独立关系、独立生命周期或可被其它字段直接引用的身份。
4. 需要独立身份、共享引用、独立关系或独立生命周期的材料必须由上层建立普通节点，并通过字段组织其内容。
5. 基础数据集不根据向量长度或内容判断坐标、轮廓、体素、颜色、区间或节点编码集合。
6. `稳定编码`只能作为节点引用分支使用，不能混入直接值冒充普通无符号整数。

本版不支持 `uint64_t`标量、浮点数、布尔值、字节数组、空值标记或任意嵌套对象。需要新增直接值物理类型时，必须先修订本规范和公开联合类型，不能由上层私自编码后宣称底座原生支持。

## 6. 节点操作

新版基础数据集至少提供：

```cpp
稳定编码 新建节点() noexcept;
稳定编码 新建节点(稳定编码 上级节点) noexcept;
bool 删除节点(稳定编码 节点) noexcept;
std::optional<基础节点> 查询节点(稳定编码 节点) const noexcept;
```

语义如下：

### 6.1 无上级节点新建

`新建节点()`只建立一个独立节点并返回其编码，不自动增加类型、名称、字段或外部关系。

### 6.2 有上级节点新建

`新建节点(上级节点)`必须先确认上级节点存在，然后在同一次函数调用中：

```text
建立新节点
-> 建立“上级节点为源、新节点为目标”的父子关系
-> 两者都成功后返回新节点编码
```

任一步失败不得留下只有节点而没有父子关系的公开成功结果。该函数只返回新节点编码；需要关系编码时，调用方通过关系查询取得。

### 6.3 删除

节点只有在没有任何引用时才允许删除。引用至少包括：

- 任一外部关系的源节点或目标节点；
- 任一字段关系的所属节点；
- 任一字段关系的字段节点；
- 任一节点引用型字段内容。

节点删除不级联删除关系、字段或子节点。调用方必须先按自身结构合同安全解除全部引用。基础数据集不判断业务对象是否允许退出，也不保存墓碑或历史。

## 7. 外部关系操作

新版基础数据集至少提供：

```cpp
稳定编码 添加关系(
    稳定编码 源节点,
    稳定编码 目标节点,
    基础外部关系类型 类型,
    std::int64_t 角色或顺序 = 0) noexcept;

bool 修改关系(
    稳定编码 关系,
    稳定编码 源节点,
    稳定编码 目标节点,
    基础外部关系类型 类型,
    std::int64_t 角色或顺序 = 0) noexcept;

bool 删除关系(稳定编码 关系) noexcept;
std::optional<基础外部关系> 查询关系(稳定编码 关系) const noexcept;

std::vector<基础外部关系> 查询源关系(
    稳定编码 源节点,
    基础外部关系类型 类型) const;

std::vector<基础外部关系> 查询目标关系(
    稳定编码 目标节点,
    基础外部关系类型 类型) const;
```

添加和修改必须核验两个端点存在且关系类型受支持。修改保持关系编码不变，可以替换端点、类型和角色或顺序。删除只删除具名关系，不删除任一端点。

查询源关系和查询目标关系返回关系记录副本。返回顺序当前由编码有序容器的遍历结果形成，但除非上层显式按`角色或顺序`或关系编码排序，否则不得把容器遍历顺序解释为业务顺序。

## 8. 字段操作

新版基础数据集至少提供：

```cpp
稳定编码 添加字段值(
    稳定编码 节点,
    稳定编码 字段节点,
    基础值 值) noexcept;

稳定编码 添加字段节点(
    稳定编码 节点,
    稳定编码 字段节点,
    稳定编码 目标节点) noexcept;

bool 修改字段值(
    稳定编码 字段关系,
    基础值 值) noexcept;

bool 修改字段节点(
    稳定编码 字段关系,
    稳定编码 目标节点) noexcept;

bool 删除字段(稳定编码 字段关系) noexcept;

std::optional<基础字段关系> 查询字段关系(
    稳定编码 字段关系) const noexcept;

std::vector<基础字段关系> 查询字段(
    稳定编码 节点,
    稳定编码 字段节点) const;
```

添加字段时，所属节点和字段节点必须存在；节点引用型内容的目标节点也必须存在。修改字段保持字段关系编码、所属节点和字段节点不变，只替换内容；允许在直接值与节点引用之间切换，但是否允许切换由上层结构合同决定。

`查询字段(节点, 字段节点)`返回所有匹配字段关系，不提供“默认取第一项”的语义。上层要求恰一字段时必须明确检查结果数量等于1；多项是上层结构不一致，不能静默选择首项。

## 9. 基础不变量

新版基础数据集必须始终保持：

1. 所有公开对象编码非零且在同一数据集身份空间内互异。
2. 任一外部关系的源节点和目标节点都指向现存节点。
3. 任一字段关系的所属节点和字段节点都指向现存节点。
4. 节点引用型字段内容指向现存节点。
5. 删除节点不会留下悬空外部关系或字段引用。
6. 查询返回调用方自有副本，不向外暴露内部容器、锁、迭代器或可变对象。
7. 失败不得返回看似有效但无法读回的对象编码。

基础数据集不承诺：

- 父子无环；
- 一个子节点只有一个父节点；
- 兄弟关系对称；
- 关系或字段唯一；
- 字段基数正确；
- 节点类型正确；
- 业务对象完整；
- 材料格式合法；
- 同内容对象全局唯一。

这些约束必须由拥有对应结构语义的上层数据类负责。

## 10. 查询与索引

基础查询只按已知稳定编码或明确结构条件执行：

```text
节点编码
关系编码
字段关系编码
源节点 + 外部关系类型
目标节点 + 外部关系类型
所属节点 + 字段节点
```

本版不提供：

- 按直接值内容全局查询；
- 按字段目标节点反查所有引用；
- 按业务节点类型查询；
- 全部节点、全部关系或全部字段的公开列举；
- 递归父子遍历；
- 兄弟推导；
- 路径查询、全文检索或相似检索。

当前实现对源关系、目标关系和字段查询使用容器全扫描，功能正确性不等于已经具备大规模查询性能。后续可以建立非权威索引，但索引命中必须回读正式对象；索引缺失、损坏或重建不得改变正式数据语义。

上层如果需要按字段值、字段目标、节点类型或固定根高效查找，应先形成明确通用查询合同，再扩展基础数据集；不得由各数据类分别读取其私有容器或复制第二事实仓。

## 11. 并发与对象生命周期

### 11.1 线程安全

同一个基础数据集对象的公开操作必须支持多线程调用：

- 写操作独占数据集写锁；
- 读操作持有共享读锁；
- 单个公开函数完成期间，其读取或修改不可被同一对象的其它调用观察为半步状态。

线程安全只覆盖单个基础数据集对象。不同数据集对象没有共同锁、共同编码空间或一致性保证。

### 11.2 单函数与多函数边界

普通单对象增删改查以单次函数调用为最小同步边界。除`新建节点(上级节点)`明确同时建立节点和父子关系外，多个公开调用组成的上层操作不是原子事务。

例如：

```text
建立业务节点
-> 写节点类型字段
-> 写多个业务字段
-> 建立父子关系
```

当前可能在中间失败并留下部分结构。上层不得把第一步成功直接报告为完整业务对象成功。

### 11.3 基础数据集对象生命周期

当前构造函数建立空数据集，对象析构后全部内存数据消失。调用方必须保证基础数据集对象在所有使用它的上层数据类之后析构。当前实现不提供可移动、可复制、共享恢复或热替换语义。

## 12. 修改与删除语义

基础数据集当前允许原地修改外部关系和字段内容。该能力只表示底层记录可修改，不意味着任何上层业务对象都允许原地修改。

上层必须自行决定：

```text
对象是否不可变
修改是否建立新节点
字段关系编码是否保留
旧引用是否先退出
是否需要组合原子发布
是否允许删除
```

删除是物理删除，不保留历史、墓碑、退出原因或旧内容。需要历史、审计或可恢复退出的上层结构不得直接把基础删除当作完整业务退出合同。

## 13. 非成功与诊断

基础数据集的正式目标至少需要区分：

```text
入口非法
空编码
对象不存在
对象类别不符
关系类型不受支持
引用目标不存在
节点仍被引用
重复或基数冲突
编码耗尽
资源失败
并发冲突
发布结果未知
内部不一致
```

当前接口只使用空编码、`false`、空`optional`或空`vector`，会把多种原因合并。例如空查询结果不能区分“确实没有匹配项”“输入节点不存在”和“资源失败”。因此当前接口只能作为初版原型接口，不能满足需要可靠诊断、重试、恢复或冲突处理的正式治理链。

当前`查询源关系`、`查询目标关系`和`查询字段`没有声明`noexcept`，结果容器分配失败时仍可能向调用方抛出异常；其它捕获全部异常的入口则把异常压缩为空结果。两类失败形态尚未统一。

在结构化结果实现前，上层不得：

- 把空结果一律解释为不存在；
- 把`false`一律解释为业务拒绝；
- 在失败原因未知时自动改用新请求或新编码重试；
- 把异常被捕获后的空返回解释为安全零变化已经得到证明。

## 14. 组合原子发布

正式新版底座必须提供通用、无业务语义的组合变化能力，使上层能够一次提交由下列项目组成的变化集：

```text
新增节点
新增、修改或删除外部关系
新增、修改或删除字段关系
必要的引用与唯一性前置条件
```

组合提交必须满足：

1. 交换前验证失败时零公开变化；
2. 提交成功时全部变化同时可读；
3. 不得让其它线程观察到字段不完整的正式业务节点；
4. 结果未知时允许用同一原请求查询或恢复，不得重新分配身份制造重复结构；
5. 变化集仍然只表达通用节点、关系和值，不含业务资格或领域判断。

当前代码没有组合变化集、条件写、发布结果查询或回滚日志。上层逐步补偿只能降低局部残留风险，不能证明原子发布。

## 15. 持久化与恢复

正式新版基础数据集必须把以下信息持久保存：

- 数据集身份；
- 下一个可分配编码或等价的不复用保证；
- 全部现存节点；
- 全部现存外部关系；
- 全部现存字段关系及直接值；
- 完成组合原子发布和结果未知收敛所需的最小技术材料。

启动恢复必须：

```text
读取同一数据集身份
-> 恢复全部对象
-> 校验编码互异和非零
-> 校验所有引用闭合
-> 校验分配器不会复用既有或已删除编码
-> 重建非权威索引
-> 完整读回后开放写入
```

恢复失败时不得建立一套新的空数据集并冒充原数据集继续运行。持久介质、文件格式、提交协议、校验和、备份与损坏处理尚未冻结，属于后续精确合同，不得由当前内存实现反向推定。

## 16. 与上层数据类的边界

### 16.1 基础数据集负责

- 分配通用稳定编码；
- 保存节点、外部关系、字段关系和直接值；
- 维护底层引用闭合；
- 提供通用增删改查；
- 保证单函数并发安全；
- 后续提供组合原子发布、持久化、恢复和结构化错误。

### 16.2 上层数据类负责

- 建立共享节点类型和字段节点；
- 决定某类业务节点的固定字段、字段类型和基数；
- 决定外部关系的业务含义、方向、唯一性、顺序和无环要求；
- 校验材料格式和业务值类型；
- 决定对象创建、修改、退出、永久保留和引用规则；
- 使用基础数据集组合能力形成完整业务对象；
- 对完整业务结构进行独立读回；
- 提供业务查询、比较、概念、状态、动态和治理能力。

### 16.3 禁止反向依赖

基础数据集不得包含：

```text
特征值类型节点、存在类型节点、场景类型节点等具体共享节点
特征、存在、场景、状态、动态、因果或概念枚举
业务字段编号
业务树根
业务格式解析器
需求、任务、方法或自我治理逻辑
上层服务类引用
```

共享业务结构节点由对应上层数据类建立或恢复，基础数据集只保存它们。

## 17. 与2100特征值规范的接口

新版特征值类只可通过本规范公开的基础函数操作数据：

- 用普通节点建立特征值节点、字段节点、类型节点和压缩层节点；
- 用字段节点关系保存节点类型及其它节点引用；
- 用字段直接值保存材料物理类型和原始材料；
- 用父子关系组织粗层到细层的压缩树；
- 用查询节点、查询字段、查询源关系和查询目标关系完成读回。

特征值类不得访问基础数据集内部容器、编码计数器或锁。基础数据集也不得识别特征值、二维格、三维格、全零描述或压缩算法。

2100要求的跨启动结构恢复、全局精确复用、组合原子发布、结构化失败和可靠索引，目前均依赖本规范第10、13、14、15节的后续实现。

## 18. 旧L1替代范围

| 项目 | 已退出旧L1口径 | 现行基础数据集口径 |
| --- | --- | --- |
| 核心事实 | 节点事实、关系事实和值事实及其正式技术合同 | 节点、外部关系、字段关系和字段直接值。 |
| 值身份 | 值事实具有稳定值身份 | 直接值没有独立身份；需要身份时由上层建立节点。 |
| 所有者 | 独立结构 owner 与写端口隔离 | 当前没有 owner、写端口或结构范围隔离。 |
| 合同版本与事实代次 | 旧合同版本、事实代次与截止读取 | 不使用合同版本或事实代次。 |
| 历史 | 旧历史、墓碑和退出后读回 | 不保存历史；当前原地修改和物理删除。 |
| 幂等 | 现行写入具备幂等和异请求冲突合同 | 当前没有幂等键、请求记录或重复提交判定。 |
| 原子性 | 支持结构写集和具名组合事务 | 当前仅单函数加锁；只有“新节点+父子关系”是局部组合。 |
| 持久化 | 现行规范要求可靠发布、持久和恢复 | 当前仅进程内`std::map`。 |
| 错误 | 结构化区分失败、漂移、未知发布和不一致 | 当前以空编码、布尔值或空容器合并失败。 |
| 查询 | 现行合同包含owner和一致性边界下的组合读取 | 当前只有已知编码和少量条件查询。 |
| 关系类型 | 由通用关系事实及正式结构合同承载 | 底座直接固定父子、兄弟两种外部关系。 |

上述旧口径已经退出正向机器语义，只保留为代码和数据迁移定位。迁移必须逐项证明保留、转换或退出，不能在同一生产路径并行写两套事实。

## 19. 非权威实现符合性

截至本规范形成时，`基础数据集.h/.cpp`已经实现：

- 单一进程内编码分配器；
- 节点增删查；
- 有上级节点的新节点与父子关系联合建立；
- 父子、兄弟外部关系增删改查；
- 直接值和节点引用字段增删改查；
- 删除节点前的全引用扫描保护；
- 同一数据集对象内的共享读锁和独占写锁；
- 查询结果按值复制，不暴露内部容器。

尚未实现或尚未证明：

- 数据集身份和跨启动稳定编码；
- 磁盘持久化、启动恢复和损坏处理；
- 多调用组合原子变化集；
- 幂等、条件写、唯一创建和发布未知收敛；
- 结构化非成功结果；
- 按字段内容、字段目标或节点类型的正式索引；
- 跨数据集实例一致性；
- 关系去重、无环、单父或字段基数约束；
- 历史、墓碑、审计和可恢复退出；
- 正式业务消费者接线、运行和恢复验证。

当前实现中的关系和字段查询采用全扫描；空结果合并了无命中和部分失败；字符串未验证UTF-8；多个上层调用发生中途失败时可能留下部分结构。因此只能声明它是可供新版数据类继续开发的单进程基础原型，不能声明为生产持久事实基座。

## 20. 验证要求

后续实现至少验证：

1. 节点、外部关系和字段关系在同一身份空间编码互异且非零；
2. 编码单调分配，删除后不复用；
3. 无上级新节点不产生附加关系；
4. 有上级新节点同时形成准确父子关系，中途失败不暴露半结构；
5. 外部关系添加和修改拒绝不存在端点及未知类型；
6. 字段添加拒绝不存在的所属节点、字段节点和节点引用目标；
7. 同一字段多项完整返回，不静默压成单项；
8. 直接值向量保持顺序和重复，字符串保持完整字节；
9. 删除任一被外部关系或字段关系引用的节点必须失败；
10. 删除关系或字段不删除端点节点；
11. 并发读取不观察到单函数写入的半步状态；
12. 多函数业务发布通过组合变化集实现零变化失败或完整成功；
13. 资源失败、无命中、引用冲突、编码耗尽和内部不一致可以区分；
14. 重启后恢复相同数据集身份、对象编码、内容和引用关系；
15. 恢复后的编码分配不复用任何既有或已删除编码；
16. 索引重建前后查询结果一致，索引不能成为第二事实仓；
17. 基础数据集不出现任何具体业务节点、字段或材料格式分支；
18. 新版特征值类只通过公开基础函数完成保存、查询和读回。
