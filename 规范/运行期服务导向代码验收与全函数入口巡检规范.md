# 运行期服务导向代码验收与全函数入口巡检规范

工程治理标识：ACCEPTANCE-01

日期：2026-08-07

状态：现行施工规范
规范类别：施工规范

## 1. 目标与边界

本规范规定生产代码之外的代码检查、公开入口黑盒验收和最终权威状态核对。黑盒驱动、入口调用器、巡检器、夹具和结果聚合器必须运行在生产二进制之外，且不得链接为生产目标的模块或启动模式。本规范只定义验收施工方法，不产生业务机器语义，也不允许为了验收向生产程序加入自检运行器、验收模式、验收专用模块、私有探针或第二套结果事实。

生产程序只实现正式生产合同、返回结构化业务结果并输出可选具名人读日志；它不自判验收 PASS。人可以通过具名日志观察运行是否符合预期，但验收者必须从生产二进制之外，通过正式公开入口构造受控请求、消费结构化结果，并按逻辑规范规定的公开读取入口核对最终权威状态。日志、PASS 文本、退出码累计、覆盖率和历史记录均不是机器事实或自动通过条件。

## 2. 验收结论

| 层级 | 结论 | 最小成立条件 | 不证明 |
| --- | --- | --- | --- |
| L0 | `编译接入通过` | 目标生产函数的声明、定义、工程接入、编译和链接成立 | 入口被调用、业务正确 |
| L1 | `公开入口可调用` | L0 成立；外部验收者经正式公开入口取得合同内结构化结果 | 副作用或最终权威状态成立 |
| L2 | `公开黑盒局部通过` | L1 成立；成功、合法非成功、非法请求零变化及适用最终状态读回符合合同 | 生产消费者接线和完整服务闭环 |
| L3 | `服务验收通过` | 合法生产消费者经正式入口取得结果，且适用权威终态、独立公开读回和失败边界成立 | 其它服务或项目整体完成 |

较高层只包含逻辑规范明确适用的较低门禁。崩溃、重启、断电、跨进程恢复、并发或外部资源故障只有被目标逻辑规范和具名验收范围明确纳入时才适用；不得从历史矩阵机械继承。

## 3. 生产目标零验收代码

生产工程和生产程序必须删除并禁止新增：

```text
完整自检、数据库自检、性能自检、D455真实样本自检等验收启动模式
自检运行器、自检登记表、固定验收编号和验收包装函数
只为验收构造隔离世界、双目标、状态矩阵或执行证据矩阵的模块
验收专用 import、工程 / filters 编译项、宏、私有探针和第二 exe
通过日志文本、PASS 计数或退出码累计自动裁决业务正确的代码
```

生产入口解析上述旧 flag 时按未知参数结构化拒绝，不能保留兼容转发。验收工具不编译进生产目标，也不得取得私有仓、锁、事务令牌、候选、内部句柄或绕过领域服务的权限。

## 4. 生产维护能力保留裁决

下列能力在具有正式生产合同、被生产运行真实消费且不返回验收结论时属于保留候选：

- 生产初始化函数为保证自身后置条件执行的结构化检查和写后读回；
- 运行期健康 / 就绪状态、故障隔离和结构化诊断；
- SQL 审计投影及其生产适配器，不含数据库自检驱动和 PASS 聚合；
- 性能遥测、限流和运行指标，不含性能自检启动模式或基准验收器；
- D455 生产采集、真实材料接收和正式领域入口，不含真实样本自检模式、夹具和验收包装；
- 具名人读日志以及日志系统自身的无业务副作用设施。

文件或函数名含“检查”“诊断”“专项”“性能”或“D455”不足以决定删除。无法从正式生产调用和公开合同证明其维护职责时，必须具名列为待裁决，不能机械保留或删除。

## 5. 范围与静态检查

每次验收绑定精确提交和具名生产服务范围。新增或修改的生产函数必须核对声明 / 定义身份、模块所有者、工程接入、诊断责任、公开可达性和未授权默认成功。私有辅助函数只做静态检查和代码审查，不为了覆盖率建立生产调用入口或验收探针。

全函数清单可以用于静态编译接入审计，但不得驱动“逐函数运行一次”。函数数、入口覆盖率、日志数量或无异常文本不能推导服务正确。

## 6. 公开黑盒验收

生产二进制之外的验收驱动只允许：

```text
外部调用正式公开生产入口
使用合同允许的强类型请求
消费结构化成功与非成功结果
通过正式公开读取入口核对最终权威状态
在受控环境比较非法请求前后的权威状态零变化
保存外部验收记录和命令证据
```

普通 CRUD 至少覆盖创建、读取、更新、退出 / 历史读取、精确重复、幂等冲突和非法请求零变化。其它服务按自身逻辑规范选择最小充分矩阵。不得要求普通调用固定生成完整执行证据、领域见证、全仓扫描或恢复材料。

无法通过公开入口安全触达的私有分支不能靠验收专用入口补造；它只能保留静态检查，或先由设计治理决定是否应形成正式生产能力。

## 7. 日志与记录

生产日志只记录具名入口、结构化状态和必要诊断的人读投影。日志关闭、缺失或写入失败不得改变业务结果；日志内容不得被验收程序解析为机器事实、自动通过条件或最终状态。

验收记录保存在生产代码之外，至少绑定精确提交、公开入口、请求类别、结构化结果、最终公开读回、非法请求零变化、实际结论和未覆盖范围。历史施工、验证和集成验收记录原样保留，不因验收体系退出而删除或改写；它们也不得自动证明新合同。

## 8. 禁止事项

禁止：

```text
把自检运行器或验收专用模块编译进生产程序
保留完整 / 数据库 / 性能 / D455 自检启动模式或兼容 flag
用第二 exe、私有入口或内部仓权限绕过正式生产边界
把日志、PASS 文本、失败计数、退出码或覆盖率当机器事实
把编译通过、公开入口可调用或旧验收历史升级为服务正确
为了验收修改业务变量、锁竞争、随机序列、状态机或事务结果
把生产维护能力仅因名称相似机械删除
把旧双目标、状态矩阵或执行证据矩阵换名迁移
```

## 9. 完成边界

旧验收代码退出必须等待本规范发布并由后续精确删除计划施工。规范发布只冻结删除与保留边界，不证明代码已经删除。删除完成只证明生产目标不再携带旧验收体系；新服务仍须经外部公开黑盒验收取得相应结论。
