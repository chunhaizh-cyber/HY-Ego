## 1. 权威边界

本文件记录新版状态信息的当前代码合同，并吸收本轮对话中与代码一致的状态口径。它尚未登记到`规范/规范目录.md`，不覆盖现行正式状态规范，不授权旧实现迁移、删除或生产切换。

状态是某个存在的一项实例特征在一个强时间点上的固定当前值事实。状态不是特征历史容器，不保存场景、动态或因果的上下文副本。

### 1.1 与现行正式规范的差异

本草案不能直接登记为现行规范。当前新版代码至少与正式合同存在以下差异：

1. `0050`、`1160`规定中性状态本体只包含身份、正式特征类型、固定准确值和强时间，主体存在与发生场景由C/E/S完整使用绑定表达；新版状态节点把`被描述存在节点`直接保存为本体字段，并没有独立C/E/S绑定。
2. 正式状态添加要求显式提交发生场景和状态组织父，在同一发布中闭合绑定与组织；新版代码先由存在类从实例特征当前值建立零引用状态，再由场景类后续挂接。
3. 正式合同明确不能以“读取某个实例特征当前值”代替提交固定状态内容；新版代码恰好从实例特征当前值读回并形成状态。
4. 正式状态保留、退出、TTL、数量上限和墓碑合同在新版代码中没有实现；新版代码改用引用计数归零删除。

这些是待治理的机器语义差异。本文只描述新版代码和对话口径，不能据此宣称现行状态合同已经被替换。

## 2. 生成条件

状态由实例特征当前值被动生成：

1. 普通存在建立并写入初始特征值时，为每项初始特征生成状态。
2. 向既有存在添加一个新特征类型并写入初始值时生成状态。
3. 更新既有实例特征时，只有当前值实际改变才生成新状态。
4. 同一准确值再次命中、但当前值未改变时，不生成重复状态。

状态只能由存在类、场景类或动态类通过私有友元入口建立。普通调用方不能提交一份脱离实例特征的裸状态内容。

## 3. 状态固定信息

```cpp
struct 新状态信息 {
    稳定编码 节点;
    稳定编码 被描述存在节点;
    稳定编码 特征类型概念节点;
    新特征准确值 固定准确值;
    新状态强时间 强时间;
    std::int64_t 被引用次数;
};
```

字段含义：

| 信息 | 基数 | 含义 |
| --- | --- | --- |
| 节点 | 恰一 | 状态节点稳定编码。 |
| 被描述存在 | 恰一 | 发生该状态的存在或场景节点。 |
| 特征概念 | 恰一 | 建立状态时实例特征当前所属的特征概念节点。 |
| 固定准确值 | 恰一 | 建立状态时实例特征的当前准确值。 |
| 强时间 | 恰一 | 状态发生的强时间。 |
| 被引用次数 | 恰一 | 场景列表、动态端点及其它正式引用的总数。 |

当前结构字段名是`特征类型概念节点`，但当前代码写入的是实例特征当时的`特征概念节点`，它可能是类型根下的具体值域概念，而不保证已经规范化为特征类型根。本文按实际代码称为“特征概念”；若后续要求稳定保存类型根和具体概念两种身份，必须另行修改数据结构，不能只改名称解释。

## 4. 准确值

状态准确值沿用新版特征准确值：

```cpp
std::variant<std::int64_t, 稳定编码>
```

- I64标量直接写入状态字段。
- 非I64材料保存特征值节点稳定编码引用。
- 状态不复制数组、字符串、轮廓或体素材料。
- 被引用的特征值节点必须存在；状态本身不承担材料压缩或解析。

状态冻结建立时的准确值。实例特征后续改变，不修改既有状态。

## 5. 强时间

```cpp
enum class 新状态时间语义 : std::int64_t {
    实例绝对UTC = 1,
    抽象相对 = 2
};
```

`新状态强时间`由时间语义和纳秒值组成。当前实例状态建立入口只接受非负的`实例绝对UTC`；`抽象相对`为概念和后续抽象保留，不允许冒充实例发生时刻。

强时间用于状态排序、原子动态前后判定和跨特征时间比较。它不是事实代次、合同版本、运行代次或历史操作序号。

## 6. 建立流程

私有建立入口：

```cpp
新状态建立结果 建立状态(
    稳定编码 被描述存在节点,
    稳定编码 特征节点,
    const 新状态强时间& 强时间) noexcept;
```

流程为：

```text
核验存在节点、特征节点和实例绝对UTC时间
-> 完整读回实例特征
-> 要求当前值存在
-> 建立状态节点
-> 写入节点类型、被描述存在、当前特征概念、固定准确值、强时间
-> 被引用次数初始化为0
-> 完整读回核验
```

调用方不能指定与实例特征不一致的特征概念或准确值。建立本身不查重；即使存在完全相同的状态，显式再次建立仍会产生新节点。需要避免重复的上层必须先调用完全相同状态查询或依照特征当前值变化条件控制建立。

## 7. 场景组织

状态建立后应由发生场景的状态列表持有引用。状态内容中不重复保存场景节点；发生场景由场景状态列表反向确定。

状态挂接场景必须满足被描述存在属于该场景范围，或被描述存在就是该场景节点。实时相对坐标刷新不生成状态；只有持久定位坐标作为实例特征发生变化时，才按普通特征变化生成状态。

当前存在类的公开特征写入口能够建立状态但不能自行确定发生场景；场景类包装入口会完成挂接。绕过场景类时，调用方必须使用返回的状态节点补齐场景挂接，否则该状态保持零引用且没有发生场景组织位置。

## 8. 查询能力

当前公开查询包括：

```cpp
std::optional<新状态信息> 获取状态(...) const noexcept;
bool 是状态节点(...) const noexcept;
std::vector<稳定编码> 按存在查询状态(...) const noexcept;
std::vector<稳定编码> 按特征类型查询状态(...) const noexcept;
std::vector<稳定编码> 按准确值查询状态(...) const noexcept;
std::vector<稳定编码> 按强时间查询状态(...) const noexcept;
std::vector<稳定编码> 查找完全相同状态(...) const noexcept;
```

`按特征类型查询状态`按当前存储字段做稳定编码相等匹配。由于该字段当前可能保存具体特征概念，它不能证明“查询类型根时自动包含所有下位概念”。

当前查询通过扫描全部状态节点再筛选实现。功能合同存在，但没有大规模索引或性能证明。

## 9. 不可变性

状态建立成功后，其被描述存在、特征概念、准确值和强时间不可修改。合法变化只能是引用次数增减。

需要表达新的特征当前值时建立新状态，不得原地改写旧状态。状态不可变性只针对状态内容，不代表底层基础数据集已经提供跨进程不可变存储或防篡改机制。

## 10. 引用计数

引用计数由正式引用所有者成对维护：

```cpp
增加引用(状态节点);
撤销增加引用(状态节点);
减少引用(状态节点);
```

规则如下：

1. 新状态引用次数为零，但新建时的零不触发删除。
2. 场景列表、原子动态端点等每建立一项正式引用必须增加一次。
3. 正式引用退出时减少一次。
4. 只有一次正式减法使计数从正数变为零时，才自动尝试删除状态。
5. `撤销增加引用`只用于同一上层写入尚未发布时的回滚；即使恢复为零也不触发删除。
6. 负数、溢出、字段缺失或计数与实际引用不一致均属于结构错误。

引用次数是生命周期控制材料，不是状态出现次数、特征值命中次数或业务权重。

## 11. 删除

公开删除入口：

```cpp
新状态操作状态 删除状态(稳定编码 状态节点) noexcept;
```

只有引用次数为零时允许删除。删除流程先核验并移除全部固定字段，再删除状态节点。基础数据集仍检测到其它引用而节点删除失败时，代码尽力恢复状态字段并返回仍被引用或结构不一致。

调用方不得先物理删除状态节点再清理场景或动态引用。

## 12. 一致性不变量

任一成功读回的状态必须满足：

1. 节点类型恰一且指向状态节点类型。
2. 被描述存在、特征概念、准确值和强时间字段各恰一。
3. 被描述存在和被引用的非I64特征值节点仍存在。
4. 实例状态使用非负实例绝对UTC时间。
5. 被引用次数非负。
6. 内容字段建立后不修改。
7. 场景和动态的实际引用总数应与引用计数一致。

当前代码不能仅靠引用计数字段独立证明第7项，仍需引用方联合检查。

## 13. 非成功和发布边界

状态操作区分入口拒绝、存在不存在、特征不存在、当前值不存在、时间不合法、状态不存在、仍被引用、引用溢出、结构不一致和资源失败。

状态建立在完整读回前失败时尽力删除已写字段和节点。上层特征事实可能已经成立；因此状态建立失败不表示特征写入失败，存在类和场景类必须返回对应部分完成结果。

## 14. 当前实现差距和待实现能力

当前尚未闭合：

- 特征类型根和具体特征概念两种身份的独立冻结；
- 按类型根包含所有下位具体概念的查询；
- 状态查询索引、时间范围查询和大规模性能保证；
- 场景、动态和其它引用与引用计数的全局一致性审计；
- 防止存在类公开写入口产生未挂接场景的零引用状态；
- 持久化、跨启动恢复和生产装配；
- 状态到动态、因果和高级概念的完整应用验收。

本规范不恢复事实代次、合同版本、历史操作账或状态可变版本。

## 15. 验证边界

后续验证至少覆盖：

- 初始特征和当前值改变生成状态；
- 同值命中不生成状态；
- 非法时间、无当前值和错误存在拒绝；
- I64与特征值节点两种准确值完整读回；
- 内容不可修改；
- 场景和动态引用成对增加、撤销和减少；
- 只有正式减法归零触发删除；
- 完全相同状态查询与“建立不自动复用”的区别；
- 部分完成时不回滚已成立的特征事实。
