# 8100 子规范 自我线程与任务管理线程权责边界

编号：8100
日期：20260901
版本：v1.4
状态：正式子规范

## 1. 定位

本规范规定自我线程、任务管理界面、任务工作线程、需求域、任务域和方法域之间的编排与写入权边界。

直接上级规范：1170、3100—3300。

直接依赖规范：5090、5100—5330、6100、6120、6340。

相关边界规范：6140—6150、8110、8200。

## 2. 总原则

```text
自我线程
-> 管“为什么做、做哪个、优先做什么”

任务管理线程
-> 管“任务按什么正式状态合同推进到哪一步”

任务工作线程
-> 执行一个任务工作包，不拥有业务事实写入权

领域服务和方法动作入口
-> 提交需求、任务、方法和世界事实
```

线程是执行载体和调度者，不是动作来源。主动方法执行或领域正式提交才是动作动态的来源候选。纯消息搬运、回执整理和线程调度属于非业务派生处理，不登记为方法，不生成主链动作动态。

## 3. 自我线程职责

应用程序启动编排必须在创建自我线程前独立读回唯一自我，再调用本能根运行初始化提供者建立或幂等收敛安全根需求、服务根需求及其角色绑定，完成同一最终截止的本能根运行锚点读回后，才把值式锚点写入自我线程创建请求。需求领域服务仍是普通 D 的正式写入者；应用启动提供者只负责编排和消费结构化结果。该初始化不得塞入唯一自我形成事务，不得为初始化步骤创建任务，也不得在任一非成功后创建或开放自我线程。

自我线程只从锁定的创建请求取得本能根运行锚点，不重新建立、按顺序猜测或从缓存恢复根。开始首次普通治理循环前必须以新的当前截止重新读回唯一自我、两个根角色和锚点身份闭包；后续每轮在同一 G0 分别读取两个根 D、目标合同和当前值，按已登记二次特征概念即时计算两个差值并在本轮使用后丢弃。正差距或新到达的合法父任务材料允许建立、唤醒或复用对应根需求治理任务；材料触发只授权 fresh 重判与裁决，不等同正差距，不改变根值，也不直接创建需求。具体子需求只能由该父任务的正式子目标承接记录形成。当前满足、不可比较、材料不足、漂移和内部不一致都有各自非成功或等待回路，不得自动创建子需求。

状态或动态通知只能唤醒 / 定位需要复核的特征。自我线程收到通知后必须冻结 G0，经特征服务重新读取当前值，再读取根需求目标合同；不得用消息、状态载荷、动态后状态或最后写入顺序直接裁决需求。

自我线程可以：

- 扫描和整理需求；
- 读取根特征定义、目标状态合同和同一事实截止的自我当前特征值完整投影；
- 生成、估权和选择当前主需求；
- 接收已由原领域承接的具名请求、观察、自检或其它材料定位，复核来源后把材料路由给安全根、服务根或其后继父需求的治理任务；不得直接据此创建需求；
- 形成任务承接、调度、取消、挂起和权重调整意图；任务轮次收束后，依据需求和当前整体事实形成继续、结束、等待或取消后继决议；
- 对含现实改变步骤且已经完成执行冻结的任务执行尝试，调用自我领域授权入口发布一份自我现实执行授权；
- 从任务结果定位消息独立读取正式任务结果和来源需求当前结算前事实，另行冻结事实截止、读取该需求目标状态合同及目标涉及的当前特征值完整投影，再由需求域入口重新比较和提交唯一需求满足结论；
- 触发合法结算和下一轮需求重判。
- 按正式触发条件调用主动安全结算和分层安全维护入口，并把安全根当前值、调度倍率和安全硬否决材料交给后继调度。

自我线程调用不等于安全值变化。主动安全根结算只由 6100 裁决，分层安全值只由 6140 裁决；线程循环次数、等待超时、消息数量、服务请求和普通任务结果都不得成为安全值变化量。服务根当前值只保留为长期普通需求的根特征坐标，当前不授权任何自动写入，不影响安全根，也不产生任务根配额。自我线程不得直接写安全值、服务根当前值、阈值、调度倍率、任务状态、当前方法、候选集合、执行冻结、任务运行态治理存在或任务结果。自我线程发送的是事件、意图、材料、授权请求编排或后继决议，不是目标任务阶段值。自我线程是编排载体；自我现实执行授权必须由自我业务 owner 的正式领域入口发布并独立读回，不能由线程字段、消息或布尔返回代替。

扫描、比较、形成需求、创建或复用任务、筹办、结算、状态推进、学习承接和形成后继决议都属于内部治理，相当于“想”，不需要业务授权。纯读取现实事实且不产生现实副作用的观察也不需要该授权；主动探测、设备运动、发射、外部通信、写外部系统或其它现实副作用步骤按现实改变处理。

有效外部服务请求只作为服务根治理任务的正式材料，不能直接成为需求。服务根任务在筹办中形成正式子目标承接记录后，才由需求域建立或复用属于唯一自我的服务子需求，并沿既有需求、任务、方法、正式结果和需求满足规则推进。不得建立服务合同、预支、余款、服务进展账、服务准备账或第二套请求入口。

## 4. 任务管理职责

任务管理界面和任务调度层负责：

1. 从任务治理输入边界独立取出并复核自我线程发布的不可变任务发起意图组，只有输入信封、绑定事实、运行代次、事实截止和幂等身份一致后，才请求任务领域建立或复用对应需求的唯一任务树；
2. 维护任务工作包、调度队列和工作项身份；
3. 按任务正式状态合同触发本轮筹办、执行、结算和轮次收束；同一未收束任务轮次内可按筹办合同重判，轮次收束后只能消费自我后继决议合法开启新轮次、结束、等待或取消；
4. 调用任务领域提交入口推进任务状态；
5. 把任务结果身份、结果版本和路由身份组成的定位消息，以及具名缺口、合法等待、自我现实执行授权请求和任务轮次结算定位上报自我线程；不得在任务管理线程判断、生成或上报需求满足结论，也不得自行决定目标未达成后继续下一轮；
6. 按 6340 已承接材料合同，把任务域消费入口返回的材料引用纳入对应既有任务或工作项；普通无命中、重复或过期报告按正式策略舍弃或保留摘要，不可舍弃但无匹配项的报告只形成结构化缺口定位并交自我线程后继治理，不得由任务管理线程直接创建需求或任务；
7. 在任务进入正常执行竞争前直接读取安全根当前值 `A`；`A=0/1` 时不开放普通任务竞争，只保留终止 / 休眠各自具名最小入口；`A>1` 时进入一般任务调度，安全任务再读取 6150 的当前五级调度倍率快照，排除零调度资格候选，按来源最高有效倍率和确定性比较合同选择；服务根当前值不参与调度资格或配额计算，任何安全硬否决独立阻止现实动作；
8. 把纯线程生命周期材料发送到控制面板线程信息模块；控制面板按显示范围读取正式领域只读投影，不接收自我治理快照副本，也不反写业务事实。

任务管理线程不得直接写需求、存在、场景、特征、状态、动态、因果或价值事实，也不得成为任务状态动作动态的来源。外设报告队列的唯一消费权、匹配和已承接材料边界由 6340 唯一规定；任务管理层只调度其正式返回，不复制报告或另行裁决世界事实。

任务管理线程只消费安全根控制态和安全调度倍率，不计算主动安全根值或分层安全值，不改变阈值、服务根当前值或安全事实，也不因工作线程数量、任务积压或执行资源紧张反向修改其来源。安全调度倍率不是正向授权；值为零只排除本次安全来源排序，不能被解释为“未授权”。

自我线程到任务管理线程的交接是异步消息边界，不是跨线程直接函数调用。发送方只冻结并发布不可变治理意图；接收方必须独立取出、复核并回读绑定事实。消息发布、日志和发送方自报都不能证明任务已经建立、复用或推进。

## 5. 任务工作线程职责

任务工作线程每次只推进一个绑定任务和工作项的闭合工作包。它可以调用任务筹办、方法动作入口、动作完成消息发布与独立验真、动作后当前特征值正式读回及状态 / 动态记录校准发布入口，并返回只用于定位的结构化工作结果。任务工作线程不得提交正式任务轮次结算、轮次收束、任务生命周期结束或需求满足；任务管理线程必须在收到工作结果定位后独立回读正式事实，再调用任务领域提交入口。工作包需要外设材料时，只能接收符合 6340 合同的已承接材料引用，不得自行轮询外设高频流或报告队列。

方法动作结束后，固定顺序为“形成预计动态 -> 发布同一不可变动作完成消息 -> 独立验真消息与动作运行绑定 -> 冻结事实截止并从特征权威所有者读取动作后当前特征值完整投影 -> 经统一变化入口校准并发布可证明的状态记录、状态动态和动作致变动态 -> 形成任务工作结果定位”。预计动态、方法返回和完成消息都不是正式事实。完成消息发布失败只能重发同一消息，不得重新执行动作；当前特征值已经变化但动作归因不足时必须保留真实当前值和已能证明的状态记录，并把归因缺口作为结构化非成功结果，不得冒充任务轮次结算或收束。状态记录、动态后状态和任务结果均不得反向决定或替代当前特征值。

工作线程不得裸写任务状态、需求树或世界事实，不得把线程运行、堵塞、暂停和退出映射为任务业务状态，也不得以自身线程编号表达任务筹办或执行占用。

## 6. 任务筹办和执行

任务筹办是任务领域内建最小方法，不进入普通方法候选，也不建立独立持久化筹办回执。它在取得任务稳定身份下唯一筹办执行权后直接形成闭合结果；未取得者必须在召回前拒绝。

筹办只按需求目标、活动路径、因果、方法条件、条件结果对、方法作用范围、现实副作用、任务特征和当前事实找路径、找方法、找条件。不得把安全、服务、观察、外设或学习领域规则硬编码进筹办器。

无候选方法时不得自动创建方法首。筹办必须形成合法等待、子目标、能力缺口、目标已完成或可执行冻结等闭合结果。现实执行授权在冻结完成后才请求，不得作为筹办条件或筹办闭合结果。

执行只能消费当前冻结。执行期发现冻结前已存在的方法结构缺口属于筹办漏检和内部逻辑错误。

## 7. 现实执行授权与安全硬否决

任务执行冻结完成后，任务管理读取冻结的方法作用范围。若冻结仅包含内部治理或无现实副作用的纯现实观察，不请求业务授权；若包含现实改变步骤，任务管理必须在任务进入执行阶段前向自我线程提交自我现实执行授权请求，由自我线程调用自我业务 owner 的正式领域入口发布或读回唯一授权事实。

一份正向授权必须同时绑定任务、任务轮次、筹办轮次、执行轮次、执行冻结、实例方法、现实动作范围、事实截止、授权规则版本和有效期。它同时覆盖本次任务执行与其中实例方法的已冻结现实动作，不再建立“任务授权”和“方法授权”两份事实。同一冻结的同义重复请求只读回既有授权；拒绝、等待、撤回和安全硬否决是请求或门控结果，不是另一份正向授权。

冻结、实例方法、现实动作范围、事实截止、授权规则或有效期任一变化都使旧授权失效；冻结变化必然使授权失效，授权失效不必然改写冻结。授权只决定本执行尝试能否开始冻结内现实改变，不裁决筹办、排队、等待、轮次结算、后继继续 / 结束 / 等待 / 取消或需求满足。

安全服务可以提供事实、调度材料和硬否决。安全硬否决可以阻止已经取得自我授权的现实动作，自我授权不得绕过；安全服务不得发布第二份正向授权。技术能力许可、结构写许可、需求活动资格、方法准入和调度配额也都不是自我现实执行授权。

## 8. 任务和需求状态分离

任务轮次结算与收束属于任务域；需求满足属于需求域；是否继续属于自我后继决议。标准链：

```text
任务工作线程形成并发布实际结果定位
-> 任务管理独立读取正式实际结果并调用任务域提交本轮结果
-> 任务域收口本轮验证 / 归因、停止和冻结材料，形成轮次结算并迁移为轮次已收束
-> 任务管理按子任务轮次独立读取 0..1 条正式发起调用
-> 恰一条时发布 / 重放调用返回并由 task owner 幂等结算唯一上级调用槽；零条按根任务收口
-> 上级任务被唤醒后 fresh 读取自己的目标 / 方法条件；其它任务不在此时批量结算
-> 各需求只在实际调度 / 使用时由需求域冻结事实截止，读取自己的目标状态合同与目标涉及的当前特征值完整投影；价值、安全、服务、风险和学习结果继续分账
-> 自我独立形成继续 / 结束 / 等待 / 取消后继决议
-> 只有继续决议经任务管理复核后建立新任务轮次并重新筹办
```

方法返回成功、任务轮次结算回执、调用槽已返回、任务结果定位消息或线程退出都不能直接写需求已满足。任务管理不得从 `T→D`、需求树、队列或线程缓存补造上级调用，也不得预读既有需求满足结论来补造本轮证据；需求满足只能由需求领域冻结新的事实截止，读取固定目标状态合同和目标涉及的当前特征值完整投影后重新比较并发布。状态记录、动态后状态、状态当前选择和结果缓存均不能代替本次当前值读回。本轮目标未达成不得自动生成下一筹办工作包。

## 9. 消息边界

自我到任务管理的合法消息包括任务承接、调度、取消、挂起、权重调整、事实更新唤醒、等待条件变化、结算完成、自我现实执行授权定位、自我后继决议和带来源版本的安全调度材料。任务承接和调度材料必须冻结为不可变治理意图组，经异步消息边界发布；任务管理独立取出并复核后才能消费。

任务管理到自我的合法消息必须绑定具体需求、任务、任务轮次、工作项或执行尝试，包括任务创建结果、任务结果定位、任务缺口、合法等待、结构化事实或能力缺口定位、正式任务子目标承接记录定位、现实执行授权请求和任务轮次结算定位。任务结果定位只携带稳定身份、版本和路由材料，不携带任务管理线程判断的需求满足结论。

外设报告到达本身不是自我治理消息。命中既有任务或工作项的报告只唤醒原任务阶段重判；不可舍弃但无匹配项的报告只能形成结构化缺口定位；普通无命中、重复或过期报告按正式策略舍弃或保留摘要。只有 6340 已承接材料经正式领域处理后形成的任务结果、结构化缺口、派生需求三件套或事实提交结果，才可以按对应消息合同进入自我线程。任务管理不得因无匹配报告直接创建需求或任务。

纯线程创建、运行、堵塞、暂停、恢复、退出和健康状态只能进入控制面板线程信息模块，不得进入自我治理邮箱。

控制面板线程只按显示范围读取正式领域只读投影；支持旁路可以消费所有合规已发布业务批次、事件动态和运行事件，不局限于自我治理或任务结果节点。写前持久证据属于对应业务事务的内部门禁，不属于普通发布后支持旁路。显示、日志、缓存统计、普通 SQL 审计和持久证据读取都不得反写业务事实或成为主链完成依据。

## 10. 写入权矩阵

| 领域 | 编排者 | 正式写入者 | 禁止跨写 |
| --- | --- | --- | --- |
| 需求 | 自我线程 | 需求领域服务和正式提交方法 | 任务管理不得写需求树 |
| 任务 | 任务管理线程 | 任务领域服务和状态提交入口 | 自我、工作线程不得裸写 |
| 方法 | 方法治理与学习流程 | 方法领域服务和动作入口 | 任务不得改方法能力事实 |
| 世界事实 | 具体业务方法与世界聚合 | 对应基础信息领域服务 | 线程和消息不得写事实 |
| 分层安全维护 | 自我线程只调用 | 6140 安全维护领域服务和专用数据操作 | 线程、调度器、任务和显示层不得写安全值或阈值 |
| 安全调度倍率 | 任务管理只读消费 | 6150 确定性投影；任务域只冻结来源版本 | 调度资源不得反向改安全值或倍率；倍率不是授权 |
| 服务根普通坐标 | 自我线程只读消费 | 需求和特征既有权威；当前无新的自动写入者 | 不得建立合同账户、余额、奖励、时间衰减、安全根调节或任务配额 |

## 11. 禁止规则

1. 自我线程不得直接指定或写入新任务状态。
2. 任务管理不得直接写需求或世界事实。
3. 任务工作线程不得用自身状态代替任务状态。
4. 任务筹办不得直接写需求或硬编码领域前置关系。
5. 线程、队列、调度器和回执整理不得成为动作来源。
6. 纯线程状态不得成为自我治理事实。
7. 任务工作结果、动作完成消息和任务结果定位不得成为需求满足证据或第二事实源。

## 12. 验证边界

验证至少覆盖全部非根需求沿父关系回溯到安全根或服务根、外部服务请求只进入服务根治理任务且不得直接创建 D、子需求只消费父任务正式子目标承接记录、主动安全结算和分层安全维护不受线程循环次数或普通结果驱动、`A=0/1/>1` 直接门控、根治理任务只筹办子目标而不直接执行现实动作、五级安全来源确定排序、任务治理意图不可变异步交接和接收方独立复核、任务创建、唯一筹办占用、内部治理与纯观察零授权、现实改变冻结后一份自我授权、同冻结幂等、冻结变化失效、安全硬否决优先、工作项单次派发、逐需求独立核算、轮次收束后自我后继决议、任务结果只上报定位、外设三路分流、控制面板只读投影、支持旁路不反写和线程信息隔离。
