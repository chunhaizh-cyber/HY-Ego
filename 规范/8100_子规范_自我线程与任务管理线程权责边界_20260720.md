# 8100 子规范 自我线程与任务管理线程权责边界

编号：8100
日期：20260804
状态：正式子规范

## 1. 定位

本规范规定自我线程、任务管理界面、任务工作线程、需求域、任务域和方法域之间的编排与写入权边界。

直接上级规范：1170、3100—3300。

直接依赖规范：5090、5100—5330、6160、6170、6340。

相关边界规范：6140—6150、8110、8200。

## 2. 总原则

```text
自我线程
-> 管“为什么做、做哪个、优先做什么”

任务管理线程
-> 管“任务按什么正式状态合同推进到哪一步”

任务工作线程
-> 执行一个任务工作包，不拥有业务事实写入权

领域服务和方法动作入口
-> 提交需求、任务、方法和世界事实
```

线程是执行载体和调度者，不是动作来源。主动方法执行或领域正式提交才是动作动态的来源候选。纯消息搬运、回执整理和线程调度属于非业务派生处理，不登记为方法，不生成主链动作动态。

## 3. 自我线程职责

自我线程可以：

- 扫描和整理需求；
- 读取根特征和自我当前状态；
- 生成、估权和选择当前主需求；
- 复核人类服务需求的提出者、有效期、法规和生存控制前置，并调用 6160 服务合同领域入口建立唯一合同和结算 30% 预支；
- 形成任务发起、调度、取消、挂起、重筹办和权重调整意图；
- 对真实外部动作工作项给出一次性执行许可；
- 从任务结果定位消息独立读取正式任务结果、来源需求当前结算前事实和当前目标事实，并由需求域入口重新比较和提交唯一需求满足结论；
- 触发合法结算和下一轮需求重判。
- 每个治理循环调用一次正式安全 / 服务维护评估入口，并把值式维护结果和权限投影交给后继调度。

自我线程每轮调用不等于安全值或服务值每轮变化。分层安全值只由 6140 裁决；服务合同、完整秒服务维护和生存安全根被动回归只由 6160、6170 裁决。线程循环次数、等待超时和消息数量不得成为变化量。自我线程不得直接写安全值、服务值、合同、阈值、执行权限、任务状态、当前方法、候选集合、执行冻结、任务运行态治理存在或任务结果。自我线程发送的是事件、意图、材料或许可，不是目标任务阶段值。

有效人类服务需求必须先由 6160 入口完成唯一合同和 30% 预支的原子发布与读回，再允许自我线程形成对应任务治理意图。准入拒绝、合法等待、版本漂移或内部不一致不得继续进入任务链；同一来源需求有效期内的重复输入只能读回既有合同，不得重复预支。具体预算、有效期和结算算法仍由 6160 唯一规定。

## 4. 任务管理职责

任务管理界面和任务调度层负责：

1. 从任务治理输入边界独立取出并复核自我线程发布的不可变任务发起意图组，只有输入信封、绑定事实、运行代次、事实截止和幂等身份一致后，才请求任务领域建立或复用对应需求的唯一任务树；
2. 维护任务工作包、调度队列和工作项身份；
3. 按任务正式状态合同触发筹办、执行、等待、重筹办、取消和结果验证；
4. 调用任务领域提交入口推进任务状态；
5. 把任务结果身份、结果版本和路由身份组成的定位消息，以及具名缺口、合法等待和执行许可请求上报自我线程；不得在任务管理线程判断、生成或上报需求满足结论；
6. 按 6340 已承接材料合同，把任务域消费入口返回的材料引用纳入对应既有任务或工作项；普通无命中、重复或过期报告按正式策略舍弃或保留摘要，不可舍弃但无匹配项的报告只形成结构化缺口定位并交自我线程后继治理，不得由任务管理线程直接创建需求或任务；
7. 在任务进入正常执行竞争前先读取 6170 的生存控制态；`A=0/1` 时普通任务根权限全部为零，只保留终止 / 休眠各自具名最小入口；只有 `A>1` 才读取安全 / 服务根权限，并对安全任务继续读取 6150 的当前五级权限快照，排除零权限候选，按来源最高有效权限和确定性比较合同选择；
8. 把纯线程生命周期材料发送到控制面板线程信息模块；控制面板按显示范围读取正式领域只读投影，不接收自我治理快照副本，也不反写业务事实。

任务管理线程不得直接写需求、存在、场景、特征、状态、动态、因果或价值事实，也不得成为任务状态动作动态的来源。外设报告队列的唯一消费权、匹配和已承接材料边界由 6340 唯一规定；任务管理层只调度其正式返回，不复制报告或另行裁决世界事实。

任务管理线程只消费安全 / 服务执行优先级权限，不计算分层安全值、生存安全根值或服务值，不改变阈值、合同或时间游标，也不因工作线程数量、任务积压或执行资源紧张反向修改权限来源。

自我线程到任务管理线程的交接是异步消息边界，不是跨线程直接函数调用。发送方只冻结并发布不可变治理意图；接收方必须独立取出、复核并回读绑定事实。消息发布、日志和发送方自报都不能证明任务已经建立、复用或推进。

## 5. 任务工作线程职责

任务工作线程每次只推进一个绑定任务和工作项的闭合工作包。它可以调用任务筹办、方法动作入口、动作完成消息发布与独立验真、权威实际状态读取及校准发布入口，并返回只用于定位的结构化工作结果。任务工作线程不得提交正式任务完成或需求满足；任务管理线程必须在收到工作结果定位后独立回读正式事实，再调用任务领域提交入口。工作包需要外设材料时，只能接收符合 6340 合同的已承接材料引用，不得自行轮询外设高频流或报告队列。

方法动作结束后，固定顺序为“形成预计动态 -> 发布同一不可变动作完成消息 -> 独立验真消息与动作运行绑定 -> 从权威所有者读取动作后实际状态 -> 校准并发布可证明的状态动态和动作致变动态 -> 形成任务工作结果定位”。预计动态、方法返回和完成消息都不是正式事实。完成消息发布失败只能重发同一消息，不得重新执行动作；实际状态已经变化但动作归因不足时必须保留真实状态，并把归因缺口作为结构化非成功结果，不得冒充任务完成。

工作线程不得裸写任务状态、需求树或世界事实，不得把线程运行、堵塞、暂停和退出映射为任务业务状态，也不得以自身线程编号表达任务筹办或执行占用。

## 6. 任务筹办和执行

任务筹办是任务领域内建最小方法，不进入普通方法候选，也不建立独立持久化筹办回执。它在取得任务稳定身份下唯一筹办执行权后直接形成闭合结果；未取得者必须在召回前拒绝。

筹办只按需求目标、活动路径、因果、方法条件、条件结果对、授权、任务特征和当前事实找路径、找方法、找条件。不得把安全、服务、观察、外设或学习领域规则硬编码进筹办器。

无候选方法时不得自动创建方法首。筹办必须形成合法等待、子目标、能力缺口、目标已完成或授权失效等闭合结果。

执行只能消费当前冻结。执行期发现冻结前已存在的方法结构缺口属于筹办漏检和内部逻辑错误。

## 7. 执行前许可

任务管理准备派发真实外部动作时，向自我线程提交绑定工作项的执行许可请求。自我线程返回允许、禁止或挂起等待。

同一工作项未结束前不得重复申请。许可只决定本工作项能否开始真实动作，不裁决筹办、排队、等待、重筹办、完成、失败、取消或结算状态，也不替代任务授权和执行冻结。

## 8. 任务和需求状态分离

任务完成属于任务域；需求满足属于需求域。标准链：

```text
任务工作线程形成并发布实际结果定位
-> 任务管理独立读取正式实际结果并调用任务域验证任务目标、提交任务结果
-> 任务管理只上报任务结果身份、版本和路由定位
-> 自我线程在新治理批次独立读取正式任务结果、来源需求当前结算前事实和当前目标事实
-> 自我线程请求需求域重新比较目标
-> 需求域提交唯一已满足结论，或零写入并保持未满足
-> 合法结算入口处理价值
```

方法返回成功、任务完成回执、任务结果定位消息或线程退出都不能直接写需求已满足。任务管理不得预读既有需求满足结论来补造本轮证据；需求满足只能由需求领域在固定目标合同、来源任务结果和当前实际状态下重新比较后发布。

## 9. 消息边界

自我到任务管理的合法消息包括任务发起、调度、取消、挂起、重筹办、权重调整、事实更新唤醒、父任务等待条件变化、结算完成、执行许可结果和带来源版本的安全执行权限刷新材料。任务发起和调度材料必须冻结为不可变治理意图组，经异步消息边界发布；任务管理独立取出并复核后才能消费。

任务管理到自我的合法消息必须绑定具体需求、任务、工作项或执行尝试，包括任务创建结果、任务结果定位、任务缺口、合法等待、结构化事实或能力缺口定位、派生需求三件套和执行许可请求。任务结果定位只携带稳定身份、版本和路由材料，不携带任务管理线程判断的需求满足结论。

外设报告到达本身不是自我治理消息。命中既有任务或工作项的报告只唤醒原任务阶段重判；不可舍弃但无匹配项的报告只能形成结构化缺口定位；普通无命中、重复或过期报告按正式策略舍弃或保留摘要。只有 6340 已承接材料经正式领域处理后形成的任务结果、结构化缺口、派生需求三件套或事实提交结果，才可以按对应消息合同进入自我线程。任务管理不得因无匹配报告直接创建需求或任务。

纯线程创建、运行、堵塞、暂停、恢复、退出和健康状态只能进入控制面板线程信息模块，不得进入自我治理邮箱。

控制面板线程只按显示范围读取正式领域只读投影；支持旁路可以消费所有合规已发布业务批次、事件动态和运行事件，不局限于自我治理或任务结果节点。写前持久证据属于对应业务事务的内部门禁，不属于普通发布后支持旁路。显示、日志、缓存统计、普通 SQL 审计和持久证据读取都不得反写业务事实或成为主链完成依据。

## 10. 写入权矩阵

| 领域 | 编排者 | 正式写入者 | 禁止跨写 |
| --- | --- | --- | --- |
| 需求 | 自我线程 | 需求领域服务和正式提交方法 | 任务管理不得写需求树 |
| 任务 | 任务管理线程 | 任务领域服务和状态提交入口 | 自我、工作线程不得裸写 |
| 方法 | 方法治理与学习流程 | 方法领域服务和动作入口 | 任务不得改方法能力事实 |
| 世界事实 | 具体业务方法与世界聚合 | 对应基础信息领域服务 | 线程和消息不得写事实 |
| 分层安全维护 | 自我线程只调用 | 6140 安全维护领域服务和专用数据操作 | 线程、调度器、任务和显示层不得写安全值或阈值 |
| 执行优先级权限 | 任务管理只读消费 | 6150 确定性投影；任务域只冻结来源版本 | 调度资源不得反向改安全值或权限 |
| 服务合同与服务值维护 | 自我线程只调用 | 6160 / 6170 服务领域服务和专用数据操作 | 线程、调度器、任务和显示层不得写合同、服务值、完整秒或准备补回 |
| 生存控制态与安全 / 服务根权限 | 任务管理只读消费 | 6170 值式投影；`A=0/1` 普通任务权限全零，`A>1` 的安全来源再消费 6150 | 最小唤醒 / 恢复入口不得混入普通任务竞争；调度资源不得反向改安全值、服务值、阈值或合同 |
| 控制面板与支持旁路 | 控制面板和支持线程只读消费 | 各正式领域和业务事务按自身合同发布 | 显示、日志、缓存、SQL 审计和持久证据读取不得反写事实或成为完成依据 |

## 11. 禁止规则

1. 自我线程不得直接指定或写入新任务状态。
2. 任务管理不得直接写需求或世界事实。
3. 任务工作线程不得用自身状态代替任务状态。
4. 任务筹办不得直接写需求或硬编码领域前置关系。
5. 线程、队列、调度器和回执整理不得成为动作来源。
6. 纯线程状态不得成为自我治理事实。
7. 任务工作结果、动作完成消息和任务结果定位不得成为需求满足证据或第二事实源。

## 12. 验证边界

验证至少覆盖每轮只调用一次但允许零变化的安全 / 服务维护、循环次数不参与数值、完整秒批量等价、人类服务需求准入与唯一合同 30% 预支、任务治理意图不可变异步交接和接收方独立复核、任务创建、唯一筹办占用、安全 / 服务零权限不派发、五级确定排序、执行许可、工作项单次派发、任务结果只上报定位、自我线程独立读取后由需求域重新比较、外设三路分流、控制面板只读投影、支持旁路不反写和线程信息隔离。
