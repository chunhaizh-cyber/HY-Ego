# 4150 子规范 二次特征边界与承载规则

编号：4150
日期：20260908
版本：v0.11
状态：正式子规范

## 1. 定位

本规范定义二次特征的用途、二次特征类应承接的逻辑能力、特征与关系输入、准确计算、关系求值、动态变化派生及与概念应用的协作边界。本规范不冻结C++函数名、DTO布局或新ABI；能力要求不等于已有代码已经提供。

直接上级规范：1180。

直接依赖规范：4130、4180。

相关边界规范：1120、1190、2220、7170、4210、4310、7140、7180。

### 1.1 二次特征用来做什么

二次特征把已有准确事实中需要计算才能取得的比较结果显式提供给使用方。用途不是字段，不为每项用途建立一个节点族或独立数据服务。

| 用途 | 输入与产物 | 不得自动升级的结论 |
| --- | --- | --- |
| 识别、区分及相似性判断 | 准确F及类型允许的比较规则，形成具名差异、距离或关系结果；可供存在识别和特征域匹配使用。 | 相似不等于同一存在；同域不等于准确值相同；最终身份确认由识别应用负责。 |
| 变化分析 | 同一主体、同一特征类型在明确前后时点的准确来源，形成增减、幅度或已注册变化率材料；可以继续比较变化量。 | 非零差值不自动发布动态，零差值也不代替注册容差下的等价判断；比较变化不证明因果。 |
| 场景关系描述与条件判断 | 同一场景比较上下文中的有序A/B，逐维比较坐标、尺寸、端点等，形成上下、内外、偏移等关系求值材料。 | 单一坐标差不证明支撑、接触或任意形状包含；存在自身的子存在比较由内部场景应用组织。 |
| 目标差距、筛选和选择 | 当前采用与具名目标/约束输入，形成准确差距、排序或条件材料。 | 差异存在不等于与目标相关，也不自动证明需求满足、任务完成、方法有效或现实执行获准。 |
| 概念形成、复用及语言关联的材料供给 | 准确输入、规则、结果及适用上下文供7180形成/应用RC；语言服务由已成立RC取得名称和表达。 | 一次计算或一次命中不等于概念已建立、已命名或产生一次真实用途；二次特征不只是语言标签。 |

两类主要输入组织必须分开：场景关系比较通常绑定不同存在在相容观察上下文中的特征；变化比较绑定同一主体同类型的前后时点。当前与目标比较则采用自己的目标角色合同。时间和存在不是所有算子的强制输入字段，但涉及这些语义时必须提供真实上下文，不从类名或参数位置猜测。

三人或多人比较由上层组织多个具名有序对象对；不同对象对可以共同供一次筛选，却不能被合并成同一A/B的复合RC。比较两个已形成差距可成为更高阶派生；直接来源保留两项完整上游计算及各自参与者，不伪装为同一个原始对象对。

### 1.2 类能力与结构所有权分层

“二次特征类”在本规范中指二次特征计算与应用能力边界，不等于新增DATA-L2结构owner，也不要求全部能力塞入现有同名C++数据服务。

| 责任方 | 必须承接 | 不承担 |
| --- | --- | --- |
| 二次特征应用（DATA之外） | 第9节的输入绑定、合法计算、来源复算、结果域归类、已成立RC具体求值和概念来源供给。 | 不写第二份特征仓，不决定需求成立、存在身份、动态发布或因果。 |
| 4180比较提供者 | 读取唯一注册路由，执行类型、单位、坐标、量化、溢出等算法合同。 | 不创建结果类型、RC、名称或世界事实，不按调用方猜测回退算法。 |
| 既有特征结构owner | 按正式合同保存/读取/查询/受保护退出已裁决特征定义、派生规则及来源关系；准确F仍按1130/4110。 | 不从CRUD触发计算、学习、域积累或全场搜索；不因定义写入能力而取得持久二次准确值权限。 |
| 概念应用与唯一概念结构owner | 概念应用按7170/7180裁决通用约束、完整定义、同义查重、形成、复合定义和用途治理；概念结构owner保存、读回和保护定义。 | 不以准确差值替代RC定义，不把读取派生来源函数当作RC读取/形成。 |
| 存在、场景、状态/动态、需求及语言等应用 | 选取各自合法来源和目标，组织搜索/采用，按自身合同发布结论或名称。 | 不把二次计算成功当作自身业务完成；不绕过结构owner拼接持久事实。 |

依赖从应用指向结构和比较提供者，数据CRUD不得反向调用概念形成应用。已有数据门面可以委托原owner，不能因此成为第二公开写入权威；其建立、读取、退出派生定义的行为与本次准确计算、RC操作必须分别命名和回执。可靠性材料仍在所属数据合同，不成为二次特征的新业务字段。

## 2. 生成触发与分流

二次特征生成前必须有一个当前比较、判断或区分需求及其所需结果形状。业务先读取当前可用特征和关系，并按以下分流：

```text
已有特征或关系足够 -> 直接使用；新增对外比较结果仍类型化
原始事实缺失 -> 继续观察或读取
事实冲突或目标优先级缺失 -> 保留冲突并交对应业务裁决
事实完整但缺少能够显式形成所需差异的派生结构 -> 生成最小候选
全部可用事实确实相同且无可派生差异 -> 返回当前不可区分
```

候选搜索只能使用与当前正式需求目标或供 self 裁决的目标提议材料有关的事实，按输入数量少、运算层数低、实际阶次低的顺序推进；一个候选解决当前需求后停止继续组合。不得为了未来可能用途扫描全世界并穷举全部特征和关系组合。

本节约束应用的触发和搜索，不要求低层每次计算先创建一个需求、任务或宿主节点。计算入口接收已明确的比较目的、来源与合同；观察、目标裁决和搜索调度由调用应用负责。已有材料足够但使用方仍需要新的准确差值或关系量时可以直接计算，不必先声称原始特征“无法区分”。现场有限枚举路线仍按7180第6.2节，完整调度合同未冻结前不开放新的批量搜索权限。

## 3. 比较与关系合同

二次特征的排序方向必须来自 4130 的有符号比较量及允许方向 / 方向区间；变化方向和幅度必须来自 4180 中与特征定义、比较用途、单位和版本一致的差异材料。两者不得互换，不持久化“促进、抑制、改善”等解释枚举。

不同特征类型只有在关系类型已登记、模板明确允许、单位合同成立且 4180 注册项明确允许该跨类型用途时才能比较。不得任意跨类型计算，也不得由二次特征调用点自行选择比较算法。

RC引用的K用于确定或校验比较合同，不覆盖4180按特征定义与用途确定的唯一合法路由。路由与固定定义不一致时报告漂移/不兼容，不任选算法、不改RC含义，也不把历史规则偷偷换成当前规则。

零概念启动只依赖已发布结构身份和基础算子：对象身份、特征类型身份、关系类型身份、时间顺序、值式相等 / 排序 / 差异能力、来源引用和规则注册。它们是前概念机器合同，不等于速度、温度、远近或用途等后天概念。

对同类动态的首次严格分组可以使用相同宿主类型及相同变化特征类型签名；关系输入使用相同关系类型、方向角色和目标角色签名。值缺失不得解释为相同或不同，未注册操作不得解释为不可区分。

### 3.1 具名标量结果与共同来源

全部正式二次至 n 次实例值只允许 `int64`，业务比较的每个最终输出都属于其中。一个二维或三维比较若有多个分量，必须输出多个具名特征类型的标量实例，保留同一计算关联、全部直接输入、方向、规则版本及所需时空关联。结果集合只组织共同来源，不是新的向量特征或第二 owner。三态和关系编码必须在各自类型中固定合法值及解释；数值相同不表示不同结果类型相同。

基础输入必须按真实特征信息节点读回特征类型和准确观察值：内联 I64 使用该节点的完整准确内容，值身份引用经2100读回完整值材料。派生输入使用具名上游输出及可复算的直接来源链，不要求每个任务局部中间结果先发布为F；同轮值式结果须带完整计算见证并核验至真实基础来源，跨轮不得直接沿用旧裸值。不得用无关I64值事实替代原向量或结构特征，不得为内联值或临时派生结果补造独立值身份。没有可回查输入或超过有限预算时失败，无部分成功结果。一次向量与结构材料依2100整体保存，未注册的轮廓、体素解析或比较不能由本节默认为已实现。

具名二次特征类型的实例值仍为I64，多个输出保持类型分立，不打包为一个整数。单个准确输出的值域概括按7160；表达比较关系的二次特征概念改由7170/7180承接共享结果域、FC/EC约束及同A/B多维AND，不以一个标量区间穷尽其定义。复合关系不改变每项准确输出的表示，本节不另建概念形成算法。

## 4. 动态派生与实际阶次

第一阶段二元变化模板只包含一个基准变化项和一个响应变化项。每项至少关联宿主、特征类型、前后状态、变化方向、量纲、时间和来源动态。

多基准、多响应和复杂协同不得塞入单个二元模板；使用多个二次特征、关系集合、动态聚合或因果结构表达。

多步变化不得自动折算为单位步长规律。只有存在可分解、同单位和逐步证据时，才形成单位样本。

同条件下响应方向冲突时必须补条件或分裂分支；方向相同但幅度漂移可调整候选区间。矛盾不得被平均后吞入一个模板。

动态至少提供时间范围和一个发生变化的非时间特征。相同控制特征变化量下比较另一特征变化量，可以形成任务局部次序候选；只有注册算法能够从不同时长 / 幅度材料确定归一化关系时，才可形成变化率候选。

“速度”属于位置变化量相对于时间变化量形成的动态派生二次特征。相同时间下比较位置变化只能作为发现和验证材料，不能单独替代速度的完整派生规则。速度变化相对于时间形成的加速度实际阶次更高，但仍统一归入二次特征。

新派生特征实际阶次固定为输入特征最高实际阶次加一；输入中只有一阶特征时结果为实际二次，含实际二次输入时结果至少为实际三次。全部阶次复用同一特征身份与节点族；所有输入、直接来源特征关系和规则必须可回查，禁止按阶次建立平行节点族，也禁止把 n 次链压平为无法复算的裸值。

4125 的静态一次特征事实集合只把若干已经成立的一次特征事实保存为一个版本化成员结构，不计算新的值，不形成比较、方向、变化率或评分；因此不适用本节阶次递增公式，也不得被二次特征生成 / 计算入口接受。消费者对集合成员执行比较并形成新结果时，该结果重新适用本规范；原始材料准备或观测结构提取按 1180 第 1.1 节分流。

## 5. 任务局部候选、事实与概念

当前需求首次形成的派生结果默认为任务局部候选。候选至少携带需求 / 判断来源、候选对象、输入事实、关系事实、规则身份、实际阶次、结果和事实截止；它没有正式概念身份，不得以临时结果冒充名称目标或概念索引身份。其合法来源和规则可以按7180支持完整概念定义，不要求先将临时结果发布为世界事实。

候选解决当前需求后可以作为本轮值式特征使用。只有跨轮回查、任务 / 方法 / 因果证据或审计需要时，才按1180讨论实例保存；该条款与0050的持久化限制存在独立争议，见0300 C038，概念及用途/能力修订不授予持久实例写入权限。概念业务按7170/7180形成完整条件定义、规范化查重，经2220准入后建立或复用RC，不另设成熟次数门槛。

一个正式二次特征概念用于存在、动态或其它宿主时复用同一概念身份；具体特征信息由独立节点承载，宿主通过关系引用，时间 / 场景范围、来源动态和证据保存在相应关联中。不得按宿主类别复制“存在速度概念”“动态速度概念”等第二身份，也不得把关联信息追加为特征内部字段。

## 6. 世界事实支持概念

“具体世界事实支持某独立概念”等可追溯归类材料可以由二次特征承载，但权威归类必须使用 2220、7140 的世界事实支持概念关系，并关联来源、证据、当前性和冲突状态。概念集合只作查询缓存，不能替代支持关系和证据链。

不得为归类新增世界存在本体字段，不得让世界存在节点兼任概念，也不得把置信或来源写入概念本体。

## 7. 因果边界

二元变化对应只是关系候选。缺动作、条件或复现时不能称为完整因果，只能作为因果补完材料。二次特征不保存任务回执、方法运行账或因果账本。

## 8. 保存边界

本节第1、2、4项中涉及持久二次具体实例的旧分支受0300 C038冻结，列出承载与必要条件不表示取得新增写入/迁移许可。当前准确结果按0050第7节第12—13项作为本次值式材料使用；合法定义、RC及真实来源仍按各自合同保存。索引不能绕过该限制使临时结果取得持久身份。

1. 派生 / 比较特征复用独立特征信息节点，保留真实阶次和直接来源的正式关联。属于某存在自身的高阶特征由该存在通过关系引用；该采用关系不是特征节点独立创建和字段操作的前置。
2. 场景内多个存在之间的关系事实进入场景事实目录或二次特征索引，不进入场景普通成员子链。
3. 即时筛选、排序、评分或单轮推导材料默认生成即弃。
4. 只有需要跨轮次回查、作为因果/任务/方法证据、跨场景比较或审计投影时才持久化。

## 9. 二次特征类必须提供的逻辑能力

下列是二次特征应用应具备的能力合同，可以组合已有提供者完成，不要求每行对应一个新公开函数。结构操作仍由第1.2节的owner承接；不扩张DATA-L1操作集。

| 能力 | 必需行为 | 结果与边界 |
| --- | --- | --- |
| 读取/核对派生定义和来源 | 经特征结构服务取得完整定义、输出类型、角色及直接来源；需要RC时经概念服务读取RC完整固定定义。 | 两种读取分别回显，不把“读取概念材料”名称当作已经读到RC；读取不生成概念或计算新事实。 |
| 输入绑定与适用校验 | 绑定准确F或可复算上游输出；核对所需A/B角色、FT、FC/EC限制、单位、坐标/参照、观察/时间范围。 | 基础合法计算不要求先有普通RC；无RC路径不伪造FC/EC，已有RC路径则不得省略其限制。 |
| 具名准确计算 | 按4180已成立类型和唯一注册路由取得排序、具名关系或差异；完整读取节点引用内容。 | 每个对外派生值为独立FT的I64；节点编码不可相减，结果类型缺失不在计算中自动创建。 |
| 结果和来源读回 | 返回每项准确值、类型、结果角色、规则身份及解释合同、直接输入及其完整见证、真实阶次和适用范围。 | 单次只读计算的回执，不是L1发布回执；结果不得只剩一个整数或只剩域。 |
| 有界高阶复算 | 沿直接来源检查无环和预算，按依赖顺序复算；阶次取最高输入阶次加一。 | 可以比较差距、变化量等；不按概念层数计阶，不把上游结果压平为一次特征，不保留跨轮隐式缓存权威。 |
| 基础结果域归类 | 对成功、可表示且适用的准确判定量按7180读取共享负/零/正域，保留准确值和具名规则。 | 只得到D，不自动得到“高/矮/内部”等RC；关系枚举码不得减零解释。 |
| 已成立原子RC求值 | 读取RC固定D/FC/EC及可回读K，将具体输入按定义绑定、计算并检验全部适用限制与域。 | 返回有依据的本次满足/不满足或非成功；不修改RC含义，不以求值代替概念查重。 |
| 已成立复合RC求值 | 展开或读取完整AND条件，保持同一有序A/B和相容参照，逐项计算并核验全部角色化限制。 | 不丢子RC的FC/EC或参照限制，不混用不同对象对；仅在完整合同求值后报告复合结论。 |
| 供给概念形成材料 | 向概念应用提供真实输入、K、准确结果、D和适用上下文；支持已有概念应用和合法缺失时的首次形成路线。 | 通用约束选择、定义规范化、查重、新建、上下位/复合定义、名称及用途治理仍走7170/7180和7140，不由普通计算自动完成。 |
| 非成功与资源收口 | 区分缺源、不可比、未注册/未实现、冲突、漂移、预算不足、资源失败和内部不一致；释放本次临时材料。 | 不填0、不返回默认关系、不把失败当作查无概念或条件不满足；不在失败后偷偷观察、写节点或无限重试。 |

准确计算与条件求值是两种结果：前者形成具名I64派生值，后者给出是否满足既有定义的结构化执行结论及依据。求值状态、错误码和AND组成不是新的I64特征，也不是新的持久节点。若上层确需再对外给出一个业务比较特征，应另按其具名输出类型和算法合同形成，不能把内部bool或状态码直接登记为特征事实。

### 9.1 输入与返回的最小逻辑信息

这些信息可以通过节点、关系、固定定义和调用期材料共同表达；不要求堆入特征对象内联字段。

```text
输入：比较目的/待求值定义
    + 有序来源（准确F，或带来源闭包的上游具名输出）
    + 可确定的输入/输出类型与比较规则
    + 本次适用的参与者、取值角色、时间及参照上下文
    + 所需结果及有限读取/计算预算

成功准确结果：各具名FT的准确I64值
            + 各自角色、规则、真实阶次及完整来源回执
            + 适用范围和所需解释合同

成功条件求值：被求值RC固定定义及具体有序绑定
            + 全部必要条件的准确结果/判定依据
            + 本次满足或不满足

非成功：具名状态、缺口/原因及已确认的诊断信息；不提供伪成功值
```

算法及解释合同需要可回查，不等于给2100的值或1130的准确F新增版本、幂等、批次、当前/历史和生命周期字段。读取一致性沿用来源服务合同；当前判断读取存在本次采用，历史判断读取具名时点及状态来源，不拼接多次“最新”读取。换取值角色、观察范围或规则后的结果必须重新计算。

### 9.2 调用顺序与概念协作

1. 使用方给出当前目的及合法范围，先读已有准确特征/关系，按第2节分流；缺世界事实先走观察，不由二次类补造。
2. 已有RC路径先读完整定义及全部限制；首次基础计算路径从已成立FT和K启动，不要求先有待生成RC。需要形成RC时，FC/EC准入及通用选择由7180的概念应用完成。
3. 绑定全部来源与所需上下文，核验解析、注册和预算，复算上游材料后计算本项；多维输出分项具名。
4. 需要判断既有关系时，按完整原子或AND定义求值，保留准确值与域配对。只做准确计算的请求到此可以直接返回，不必进入概念查重。
5. 需要形成/复用或命名概念时，把本次材料交概念应用；同义复用、合法缺失才新建，发布与名称阶段分别返回真实结果。此协作不在DATA CRUD内部自动触发。
6. 使用方按识别、场景、动态、需求或语言合同消费；需计量真实用途时由概念应用处理。计算、扫描、重复命中或技术重放本身不产生用途。
7. 本轮值式结果用毕释放。再次当前判断重新读取和计算，不从上轮结果恢复当前值；后续持久化裁决不由本流程授予。

### 9.3 非成功与完整性

| 情况 | 必须返回/行为 |
| --- | --- |
| 计算成功且准确为0 | 保留真实0和来源；仅按K判断零域/等价含义。 |
| 完整合法输入不满足RC | 结构化报告本次不满足及依据；不退役RC、不更改其定义。 |
| 实例不符合FC/EC或参照前置 | 报适用范围不成立，不能冒充同一合法比较量落在反域。 |
| 缺值、事实冲突、读取漂移或读取失败 | 分别回显，不解释成相同、不同、不可区分或合法未命中。 |
| 类型、单位、角色或算法缺口 | 拒绝或未实现；不按单位相同任意跨类型，不以默认减法回退。 |
| 溢出或预算耗尽 | 本次请求无成功计算载荷；不截断、打包、饱和或只返回部分所需结果。 |
| 必需AND项未完成 | 不返回完整满足/不满足；不得以某项已有结果覆盖其它项的缺口。 |
| RC形成或名称阶段失败 | 计算成功、RC已发布和名称失败分别报告；不假回滚，不重建已发布同义RC。 |

一个计算请求的多结果完整性遵守4180：任一所需项失败则该请求不携带部分成功值。多个独立请求可各自报告真实结果，但失败的复合求值只回显各项诊断和缺口，不作为一个成功二次结果使用；7180允许的逐维状态报告不改变该边界。基础派生图有环、注册不唯一或已经校验通过后出现结构矛盾属于内部不一致，不是普通“不满足”。
