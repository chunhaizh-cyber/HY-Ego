# 4150 子规范 二次特征边界与承载规则

编号：4150
日期：20260815
状态：正式子规范

## 1. 定位

本规范定义需求触发的二次特征候选、特征与关系输入、动态变化派生、任务验证、概念归类和持久化边界。

直接上级规范：1180。

直接依赖规范：4130、4180。

相关边界规范：1120、1190、2220、4210、4310、7140。

## 2. 生成触发与分流

二次特征生成前必须有一个当前比较、判断或区分需求及其所需结果形状。业务先读取当前可用特征和关系，并按以下分流：

```text
已有特征或关系足够 -> 直接完成
原始事实缺失 -> 继续观察或读取
事实冲突或目标优先级缺失 -> 保留冲突并交对应业务裁决
事实完整但缺少能够显式形成所需差异的派生结构 -> 生成最小候选
全部可用事实确实相同且无可派生差异 -> 返回当前不可区分
```

候选搜索只能使用与当前需求候选对象有关的事实，按输入数量少、运算层数低、实际阶次低的顺序推进；一个候选解决当前需求后停止继续组合。不得为了未来可能用途扫描全世界并穷举全部特征和关系组合。

## 3. 比较与关系合同

二次特征的排序方向必须来自 4130 的有符号比较量及允许方向 / 方向区间；变化方向和幅度必须来自 4180 中与特征定义、比较用途、单位和版本一致的差异材料。两者不得互换，不持久化“促进、抑制、改善”等解释枚举。

不同特征类型只有在关系类型已登记、模板明确允许、单位合同成立且 4180 注册项明确允许该跨类型用途时才能比较。不得任意跨类型计算，也不得由二次特征调用点自行选择比较算法。

零概念启动只依赖已发布结构身份和基础算子：对象身份、特征类型身份、关系类型身份、时间顺序、值式相等 / 排序 / 差异能力、来源引用和规则注册。它们是前概念机器合同，不等于速度、温度、远近或用途等后天概念。

对同类动态的首次严格分组可以使用相同宿主类型及相同变化特征类型签名；关系输入使用相同关系类型、方向角色和目标角色签名。值缺失不得解释为相同或不同，未注册操作不得解释为不可区分。

## 4. 动态派生与实际阶次

第一阶段二元变化模板只包含一个基准变化项和一个响应变化项。每项至少关联宿主、特征类型、前后状态、变化方向、量纲、时间和来源动态。

多基准、多响应和复杂协同不得塞入单个二元模板；使用多个二次特征、关系集合、动态聚合或因果结构表达。

多步变化不得自动折算为单位步长规律。只有存在可分解、同单位和逐步证据时，才形成单位样本。

同条件下响应方向冲突时必须补条件或分裂分支；方向相同但幅度漂移可调整候选区间。矛盾不得被平均后吞入一个模板。

动态至少提供时间范围和一个发生变化的非时间特征。相同控制特征变化量下比较另一特征变化量，可以形成任务局部次序候选；只有注册算法能够从不同时长 / 幅度材料确定归一化关系时，才可形成变化率候选。

“速度”属于位置变化量相对于时间变化量形成的动态派生二次特征。相同时间下比较位置变化只能作为发现和验证材料，不能单独替代速度的完整派生规则。速度变化相对于时间形成的加速度实际阶次更高，但仍统一归入二次特征。

新派生特征实际阶次固定为输入特征最高实际阶次加一；输入中只有一阶特征时结果为实际二次，含实际二次输入时结果至少为实际三次。全部阶次复用同一特征身份与节点族；所有输入、直接来源特征关系和规则必须可回查，禁止按阶次建立平行节点族，也禁止把 n 次链压平为无法复算的裸值。

## 5. 任务局部候选、事实与概念

当前需求首次形成的派生结果默认为任务局部候选。候选至少携带需求 / 判断来源、候选对象、输入事实、关系事实、规则身份、实际阶次、结果和事实截止；它没有正式概念身份，不得进入名称关系或概念索引。

候选解决当前需求后可以作为本轮值式特征使用。只有跨轮回查、任务 / 方法 / 因果证据或审计需要时，才按 1180 请求 `DATA-L2` 特征结构服务持久化带真实阶次与直接来源关系的高阶特征事实。只有 `DATA` 之外概念业务证明同一派生结构可复用并完成 2220 准入，才建立特征概念根下的二次特征概念。

一个正式二次特征概念用于存在、动态或其它宿主时复用同一概念身份；每个具体值仍分别保存宿主、时间 / 场景范围、来源动态和证据。不得按宿主类别复制“存在速度概念”“动态速度概念”等第二身份。

## 6. 世界事实支持概念

“具体世界事实支持某独立概念”等可追溯归类材料可以由二次特征承载，但权威归类必须使用 2220、7140 的世界事实支持概念关系，并关联来源、证据、当前性和冲突状态。概念集合只作查询缓存，不能替代支持关系和证据链。

不得为归类新增世界存在本体字段，不得让世界存在节点兼任概念，也不得把置信或来源写入概念本体。

## 7. 因果边界

二元变化对应只是关系候选。缺动作、条件或复现时不能称为完整因果，只能作为因果补完材料。二次特征不保存任务回执、方法运行账或因果账本。

## 8. 保存边界

1. 属于某存在自身的派生 / 比较特征可作为该存在的高阶特征实例，但必须复用特征节点族并具有正式宿主关系、真实阶次和直接来源关系。
2. 场景内多个存在之间的关系事实进入场景事实目录或二次特征索引，不进入场景普通成员子链。
3. 即时筛选、排序、评分或单轮推导材料默认生成即弃。
4. 只有需要跨轮次回查、作为因果/任务/方法证据、跨场景比较或审计投影时才持久化。

## 9. 验证

验证必须覆盖需求存在、已有特征 / 关系先行、缺事实分流、当前不可区分、最小候选停止、类型与关系签名、算法注册唯一性、单位、维度、时序、左右角色、真实阶次、速度 / 加速度递归样例、排序 / 差异方向不混用、响应冲突、任务局部材料不落盘、持久材料来源关系、同一概念跨宿主复用和概念归类可撤销性。
