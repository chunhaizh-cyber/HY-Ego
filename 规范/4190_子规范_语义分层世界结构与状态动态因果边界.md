# 4190 子规范 数据结构分层与世界状态因果记录边界

编号：4190
日期：20260909
版本：v0.16
状态：正式子规范

直接上级规范：0050。

## 1. 定位

本规范纠正旧“语义分层”和“五层同质 CRUD”口径。`DATA-L1` 是纯事实内核，`DATA-L2` 保存带结构类型语义的世界、语言、概念和治理记录，`DATA-L3` 只聚合世界树与概念空间；三层均不取得业务真实性、资格或结果解释权。

## 2. 分层规则

1. `DATA-L1` 只拥有节点、关系、值及其事务、代次、owner 和当前 / 历史事实能力，不认识上层结构族。
2. `DATA-L2` 按正式登记结构族提供强类型 CRUD，并校验字段、端点、基数、顺序、生命周期和结构引用；这称为结构类型语义，不是业务解释。
3. `DATA-L3` 只能经 `DATA-L2` 公开合同形成世界树和概念空间聚合，不形成第二事实仓或第二写入口。
4. 层号只表示结构组合和依赖，不表示世界语义、认知阶段、自我治理阶段或语言成熟度。
5. 任何业务名称、资格、目标、动作和结果解释均由 `DATA` 之外业务层拥有。
6. `DATA-L4`、`DATA-L5` 当前未定义；任何按旧五层为其分配治理、语言、业务或转发职责的合同或实现均不取得分层授权。

## 3. 世界与树结构

1. 数据服务可以保存树、图、节点、关系、值、根标记、父子关系、成员关系和结构版本等强类型记录。
2. 树结构服务可以强制单根、单父、无环、端点存在、关系类型匹配、顺序稳定和同截止读取；这些都是结构不变量。
3. `DATA-L2` 可以知道某关系是正式场景父子、成员或根标记结构并校验其结构不变量，但不得判断某棵树是否为现实世界、某节点是否为自我或某位置是否满足业务资格。
4. 创建、移动和退出只表示结构记录的增加、关系替换和生命周期退出；是否应该执行由 `DATA` 之外业务层先行裁决。

场景七字段及同节点存在/场景视角由1150/4202固定。四个实例根和组织边是正式事实，不是仅可重建的查询树；组织父、对象直接归属与跨树引用分别校验。该目标不重编号既有owner、不强转旧场景/存在ABI，也不把根节点引入为新的独立事实仓。

## 4. 特征、状态和动态记录

1. 特征类型、独立特征信息节点、值、状态和动态可以作为强类型数据结构保存；其字段、端点、值域、顺序和适用生命周期由各自结构合同冻结。宿主通过关系引用特征节点，字段数据操作以特征节点为定位依据。
2. 数据服务不得判断某值是否安全、某状态是否真实、某变化是否重要，也不得根据两个状态自动生成业务动态。
3. 若上层已经形成一个动态记录请求，数据服务只验证请求结构并执行 CRUD；无请求时不得自行扫描状态并补造动态。
4. 特征信息按 1130 / 4110 保存固定准确值及可选概念名称引用；存在按 7150 维护已知特征和当前采用，类型共享积累按 7160，不再在 F 内保存历史或域。内联 I64 不伪造值身份；L1 可靠更新和技术历史不成为特征当前值改写或状态 / 动态通用联写依据。

## 5. 因果记录

1. 因果记录只承载1190已经由业务确认的概念化规律，不承载某次具体发生，也不建立因果实例类。
2. 参与者、条件、动作和结果中的对象类别引用必须指向正式概念节点；具体存在、状态、动态和动作实例只能经独立形成证据关系引用，不进入因果本体。
3. 主动因果必须具有归入动态概念根的动作概念项；被动因果的动作项为空，不建立独立动作概念根。数据服务只校验类型与结构一致，不判断因果真实、必然或应归入哪一类。
4. 数据服务校验角色、顺序、基数、概念引用、值/值域约束、相对时序、规范化唯一和结构生命周期；不扫描历史、不形成候选、不执行反例筛选或场景复现。
5. 信息不足时不生成记录；不得以默认值、具体状态身份、相邻动态、名称、统计、版本或哈希补造因果定义。

## 6. 自我、需求、任务、方法和语言记录

1. 需求、任务、方法、语言和词条由 `DATA-L2` 以彼此独立的强类型结构承载。语素与词性当前只允许作为绑定语言位置和解析版本的任务局部候选材料，不取得稳定身份、生命周期或 CRUD。
2. 自我资格位于 `DATA` 之外；数据服务不得判断当前自我是否存在、需求是否成立、任务是否完成、方法是否有效、词义是否正确、词性判断是否正确或语言表达是否真实。词条所指目标的类型只能从目标对象的正式强类型结构读取。
3. 上层业务可以提交这些结构的 CRUD 请求，并自行消费结构化结果；数据层成功不构成任何业务结论。

## 7. 结构服务与事务

1. 每类结构只有一个写入所有者；组合写由一个具名结构发布者形成完整写集。
2. 原子性、幂等、期望代次、关系替换、值槽切换、退出和历史读取属于数据结构合同。
3. 当前、历史、审计和恢复读取均返回不可变结构材料；投影和缓存不得反写权威数据。
4. SQL、材料和缓存不得替代运行期已发布数据结构权威。

## 8. 验证

1. 合法消费者在实际使用时直接提交场景、特征、状态、动态、因果或其它目标结构请求，并以结构化结果和权威读回判断当前所需能力是否可用。
2. 施工检查只核对结构输入、结构化结果、最终当前状态、历史状态和非法请求零变化；不建立替代实际消费的专门验收阶段。
3. 检查材料不得指定“真实世界”“当前自我”“安全目标”“业务动作”或“真实因果”；测试名称不得取得业务事实权。
4. 一次实际使用或施工检查只证明已发生的合同范围，不证明上层业务或未发生分支正确。

## 8.1 概念空间根视图结构读取

概念空间根视图属于 `DATA-L3` 只读聚合。它可以在同一个共同事实截止 `G0` 下组合公开的 L2 概念根、普通概念、直接上位边和概念—世界事实支持关系；不得新建概念事实、复制世界事实或保存根视图快照。

根视图合同至少固定：

1. 请求的 L2 结构请求头、当前 / 历史类别、历史截止、四根闭集、叶级支持关系开关和根 / 概念 / 边 / 支持关系 / 负载预算；零预算或超过硬上限必须在入口返回 `数量预算不足`。
2. L2 上游公开的有界概念图读取结果必须同时给出实际截止、根身份、本体根归属、普通概念身份和完整直接边。L3 不得调用 L2 私有 `读取当前概念图` 辅助函数；若该能力尚未公开，执行计划必须先闭合 L2 纯结构读取提供者。
3. L3 对概念身份去重并按稳定编码排序，对直接边保留所有合法多父边；不生成传递闭包、单父边、层级高度或显示路径。叶级支持结果只携带概念身份、L2世界事实强类型引用和支持关系稳定编码，不复制世界节点、值或材料事实。
4. 四根缺失 / 重复、普通概念未归根、直接边端点缺失或跨根、支持关系端点不一致、同一截止互证失败和任何闭包失败均为 `内部不一致`；所有非成功结果都返回零投影载荷。

根视图的 `L3` DTO 与服务不得改变 L2 结构合同版本 `1`，不得持有业务资格、抽象正确性、语言解释、世界真实性或 L4 结果。四本体根初始化只能以正式根组读回为权威；任何缓存仅可用于重放证据，缓存与正式读回冲突时返回结构化内部不一致。

## 9. 迁移门禁

1. 4200、4201 及其它规范中仍要求数据层执行业务准入、业务结果解释、状态自动整理、动态自动生成、因果真伪判断或自我资格证明的条款全部由本版冻结，须按当前三层结构边界重新发布后才能施工。
2. 已发布代码中的纯结构 CRUD 可以保留；含业务裁决的入口不得因已有实现而继续取得规范授权。
3. 任何相关计划在重新分类前保持待激活或退出，不得以编译、运行日志或旧验收记录恢复代码实施资格。这里的代码实施资格属于项目施工治理，不是自我现实执行授权。

## 10. 状态、动态、时间与保留边界

1. 状态本体按1160保存正式特征类型、固定准确值和强时间；具体发生主体及场景由4202的C/E/S完整使用绑定确定，被描述特征由E与S内正式FT确定，不另设属性身份。
2. 动态本体按1170保存动态身份、主体存在和变化内容；名称概念由概念结构owner独立管理，不进入动态数据服务载荷。
3. 原子动态只引用前后两个完整状态使用端点；组合动态只引用直接子动态。两种变化内容互斥，精确结构、关系、基数和来源闭包按4211。
4. 状态或直接子动态必须先独立形成并完成正式读回，动态随后发布。发布不得隐式改写、删除、压缩或补造来源材料。
5. 动态只记录具体发生，实际时间从原子端点或组合成员派生，不保存可独立漂移的发生时间字段，并使用非负 UTC Unix epoch 纳秒。抽象相对时间只属于抽象状态或动态概念条件。
6. 场景类在动态发布并读回后，按4202把动态组织到发生场景的动态实例树；动态内容与场景组织是两个owner、两个发布阶段。
7. 实例状态 / 动态分别受非零有限 TTL 和非零数量上限约束。清理先退出受影响动态，再清理不再被活动动态引用的状态；父子动态依赖纳入同一清理闭包。
8. 当前选择指向被清理状态时同代退出且不回退；普通引用允许过期。清理推进新代次并保留最小墓碑和紧凑幂等记录；抽象状态不适用实例保留上限。
9. DATA 不判断调用权限、变化重要性或动态真实性；动态生成与聚合应用只提交已经形成的结构请求。
