# 4190 子规范 语义分层、世界结构与状态动态因果边界

直接上级规范：0050。

直接依赖规范：4010、4020、4030、4040。

相关边界规范：1120—1190、2100、4110—4180、4210—4330、6220、7130。

## 1. 定位

本规范把经本项目冲突裁决后的 L0—L5 语义分层、世界结构、状态、动态和因果口径固定为海中鱼巣正式规则。它只冻结业务结构和服务权力，不把参考项目文件、代码目录、C++ 接口、SQL 表、材料格式或算法实现升级为机器语义。

## 2. L0—L5 分层

1. L0 是 SQL Server、独立材料文件及其完整性、持久化、应急和交互投影等物理能力；L0 不拥有运行期业务事实裁决权。L1 是业务中性的通用数据基座，内存已发布代次承载唯一运行期权威。
2. L2 负责特征值、特征、存在、场景、状态、动态、因果和世界组合。
3. L3 独立负责抽象概念、稳定词身份、词面和映射；节点编码而非词面文本承担机器身份。
4. L4 负责需求、任务、方法和自我治理；不得把治理语义倒灌至 L1。
5. L5 语言信息暂缓。恢复时必须消费 L3 稳定词身份，不建立第二词身份。
6. 分层不是代码目录、物理模块、部署单元或强制实施顺序。各领域在依赖合同闭合后可独立形成设计和实现。
7. 每层只能通过具名、版本化、强类型服务合同约束的公开服务函数消费其它事实所有者；不强制逐级转发，按真实依赖直接调用具名提供者。无事实责任的中间层不得代理或重解释。
8. 服务返回调用方拥有的不可变完整投影，不泄漏仓库、SQL、材料路径、锁、事务、缓存、内部写集或候选控制权。合同兼容时本层内部实现可独立替换；合同语义改变时必须新版本并明确迁移或拒绝。

## 3. 特征值与特征

1. 特征值由独立领域服务管理。已发布值的载荷不可原地修改；换代形成新值或新版本并保留历史。
2. 特征值承载类别至少包括：标量 `int64`、`int64` 区间、已发布特征值身份集合、其它存在身份以及其它特征集合。精确物理表示由类型合同另行规定。
3. 特征由宿主身份、特征类型身份、定义版本、唯一当前值关系和历史值集合共同成立。
4. 同一宿主同一特征类型最多一个当前实例和一个当前值。换代必须使新当前和旧当前退出在同一内存事实事务与代次发布中成立。
5. 世界组合、需求、任务和方法只能通过特征领域服务读取或提交值，不得直接写 L1。

## 4. 存在、场景和世界

1. 存在具有独立稳定身份；实际存在与治理虚拟存在由不同领域资格建立，不能只靠名称或来源类型混同。
2. 内部场景按需建立：只有一个存在被作为场景观察时，才为其建立内部场景。
3. 场景树必须单根、单父、无环；同一存在在同一棵树中只有一个当前直接位置。
4. 可以有多棵逻辑场景树，但现实世界树有且只有一棵。自我当前所在场景必须属于现实世界树。
5. 每个世界拥有独立逻辑序列；世界身份、关系、状态、动态、因果、版本和缓存命名空间不得跨世界混用。
6. 世界服务是组合服务，只协调存在、场景、特征、状态和动态等领域服务，不拥有 L1 写权。
7. 运行期可以缓存世界根、自我和当前场景等常用身份，但缓存句柄不是持久事实。

## 5. 二次特征

1. 二次特征由左、右一个或一组有序特征组成，保存组成角色、比较规则、规则版本、来源、值域和适用范围。
2. 比较结果可以表达相对某个值的大于、小于、等于或其它已登记关系；不可比必须是具名结果。
3. 二次特征作为特征使用时，其值域可以进入状态；二次特征不会自动再次抽象，只有与其它特征按正式合同组合后才形成新的输入。
4. 临时比较默认值式使用后丢弃；只有需要被状态、因果、任务或审计回查时才发布稳定事实。

## 6. 状态

1. 原子状态是“同一主体的一个特征精确版本 + 一个值精确版本 + 时间戳 + 场景与来源”。同一状态采样位置只记录一个特征。
2. 第一个状态只建立状态事实，不生成动态。
3. 多个原子状态只能在明确时间段、成员身份和组合规则下形成复合状态。复合状态成员必须分别发生变化；无变化成员不能用于伪造变化型复合状态。
4. 每个状态发布后触发一次幂等整理。整理成功可以产生零个或多个后继事实；“已整理”不等于“必然产生动态”。
5. 当前状态由明确主体、特征、时间、事实截止和版本选择，不能覆写历史状态或依赖缓存顺序。

## 7. 动态

1. 原子动态由相邻、同主体、同特征类型且值发生变化的前后状态形成；无变化读取不生成动态。
2. 原子动态保存前后状态、时间范围、场景、来源和稳定身份。重复动态可以形成动态链和稳定复杂动态候选。
3. 动态链只在其场景范围内有效。跨场景使用必须形成新的外层动态并保留来源动态身份，不能改写原动态的场景或身份。
4. 内部场景每发布一个状态就执行一次连续整理；形成的内部动态先在内部场景成立，再由动态服务发布到该存在所在场景。
5. 动态领域服务不得创建缺失状态来补齐端点，也不得把线程、日志、消息或预期输出作为动作证据。

## 8. 因果

1. 因果事实由条件、动作、结果、动态证据、适用范围和版本组成。条件与结果都是状态；动作可以引用方法执行事实。
2. 有合法动作执行证据的因果属于主动因果；没有动作执行证据但条件必然导向结果的属于被动因果。
3. 一次完整、角色闭合且可回查的证据可以形成一个实例因果。重复证据用于统计、稳定度、抽象和换代，不是实例因果的最低次数门槛。
4. 因果是对动态证据的角色化解释，不改变或删除原动态。
5. 持久图只保存直接因果。间接因果、最短路径、目标层级和优先级深度均按当前图、当前版本和值式规则计算。

## 9. 服务和事务

1. 特征值、特征、存在、场景、状态、动态和因果各有唯一领域写入服务。
2. 组合服务不得越过这些领域服务直达 L1。
3. 跨领域一次业务意图只有在发布者、写集、幂等身份、候选确认、逆序撤销和内存代次原子发布合同明确后才能实施；本规范不替未决合同选择一个万能关系服务。
4. 当前、历史、审计和恢复读取均返回不可变值式材料；投影和缓存不得反写事实。

## 10. 未决门禁

4200 已在世界树目标范围内裁决归属创建、移动、移除和状态发布后动态整理的发布者与事务边界。其它跨领域关系的精确发布者、世界—概念和概念—词映射基数、六类特征值的物理编码、复合状态与复杂动态算法、动态概念合同以及其它跨领域组合事务接口仍须后续规范裁决。
