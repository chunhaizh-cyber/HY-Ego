# 4190 子规范 数据结构分层与世界状态因果记录边界

编号：4190
日期：20260809
状态：正式子规范

直接上级规范：0050。

## 1. 定位

本规范纠正旧“语义分层”口径。L1—L5 全部是基础数据服务；世界、特征、存在、场景、状态、动态和因果在这些层中只能作为数据结构记录，不取得业务真实性、资格或解释权。

## 2. 分层规则

1. 每层拥有正式登记的数据结构族及其增、删、改、查合同。
2. 层号只表示结构组合和依赖，不表示世界语义、认知阶段、自我治理阶段或语言成熟度。
3. 较高层可以组合较低层结构，但只能形成新的结构投影或结构记录；不得据此推出业务事实。
4. 任何业务名称、资格、目标、动作和结果解释均由 L5 之外业务层拥有。
5. 任何把 L2 称为世界语义、L3 称为概念语义、L4 称为治理语义、L5 称为语言语义的合同或实现均不取得分层授权，必须重新分类。

## 3. 世界与树结构

1. 数据服务可以保存树、图、节点、关系、值、根标记、父子关系、成员关系和结构版本等强类型记录。
2. 树结构服务可以强制单根、单父、无环、端点存在、关系类型匹配、顺序稳定和同截止读取；这些都是结构不变量。
3. 数据服务不得判断某棵树是否为现实世界、某节点是否为自我、某关系是否代表归属、某位置是否满足业务资格。
4. 创建、移动和退出只表示结构记录的增加、关系替换和生命周期退出；是否应该执行由 L5 之外业务层先行裁决。

## 4. 特征、状态和动态记录

1. 特征定义、实例槽、值、状态和动态可以作为强类型数据结构保存；其字段、端点、值域、顺序和生命周期由结构合同冻结。
2. 数据服务不得判断某值是否安全、某状态是否真实、某变化是否重要，也不得根据两个状态自动生成业务动态。
3. 若上层已经形成一个动态记录请求，数据服务只验证请求结构并执行 CRUD；无请求时不得自行扫描状态并补造动态。
4. 当前值更新以新值记录和旧值退出表达；历史值保留。该规则不解释变化的业务原因或结果。

## 5. 因果记录

1. 因果记录是调用方提交的有序数据结构，可以包含条件引用、动作引用、结果引用、时间顺序和来源材料引用。
2. 数据服务只校验引用存在、角色形状、顺序、类型和生命周期，不判断因果是否真实、是否必然、是否主动或被动。
3. 无动作的因果记录可以具有空动作字段；数据服务不得因空动作拒绝，也不得替调用方推断动作。
4. 因果记录按时间顺序创建，不要求数据层执行无环证明。即使出现先后记录相互指向，也只按各自创建时间保存；真实性由后续业务应用另行确认。
5. 信息不足时不生成记录；数据服务也不得以默认值、相邻状态或历史统计补造因果。

## 6. 自我、需求、任务、方法和语言记录

1. 自我结构、需求结构、任务树、方法结构、词身份、词面和映射若由 L1—L5 承载，只是数据结构。
2. 数据服务不得判断当前自我是否存在、需求是否成立、任务是否完成、方法是否有效、词义是否正确或语言表达是否真实。
3. 上层业务可以提交这些结构的 CRUD 请求，并自行消费结构化结果；数据层成功不构成任何业务结论。

## 7. 结构服务与事务

1. 每类结构只有一个写入所有者；组合写由一个具名结构发布者形成完整写集。
2. 原子性、幂等、期望代次、关系替换、值槽切换、退出和历史读取属于数据结构合同。
3. 当前、历史、审计和恢复读取均返回不可变结构材料；投影和缓存不得反写权威数据。
4. SQL、材料和缓存不得替代运行期已发布数据结构权威。

## 8. 验证

1. 验证者直接构造世界树、特征、状态、动态、因果或其它目标结构请求，经公开入口执行 CRUD。
2. 验证只核对结构输入、结构化结果、最终当前状态、历史状态和非法请求零变化。
3. 不为验证指定“真实世界”“当前自我”“安全目标”“业务动作”或“真实因果”；测试名称不得取得业务事实权。
4. 数据层验证通过只证明结构服务合同，不证明上层业务正确。

## 9. 迁移门禁

1. 4200、4201 及其它规范中仍要求 L1—L5 执行业务准入、业务结果解释、状态自动整理、动态自动生成、因果真伪判断或自我资格证明的条款全部由本版冻结，须按结构 CRUD 重新发布后才能施工。
2. 已发布代码中的纯结构 CRUD 可以保留；含业务裁决的入口不得因已有实现而继续取得规范授权。
3. 任何相关计划在重新分类前保持待激活或退出，不得以编译、运行日志或旧验收记录恢复执行许可。
