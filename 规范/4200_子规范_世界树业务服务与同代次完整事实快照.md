# 4200 子规范 世界树业务服务与同代次完整事实快照

编号：4200
日期：20260807
状态：正式子规范

直接上级规范：0050。

直接依赖规范：1130—1170、4010—4050、4110、4170—4190、4210。

相关边界规范：4060、4070、6220、7130、7140。

## 1. 定位

本规范建立 L2 的 `世界树业务服务` 统一门面，冻结世界树结构操作、存在当前特征操作、状态动态整理和同代次完整事实快照合同。统一门面只编排具名领域服务，不取得存在、场景、特征、状态、动态、L1 或 L0 的事实所有权。

本规范服从 0050、4030 的 L1—L5 分层：跨层以及同层不同事实所有者之间，只允许通过具名、版本化、强类型公开服务函数交互。这里的“只经服务函数”不是强制逐层转发；消费者按真实依赖直接调用唯一事实所有者，内部实现可在不改变公开合同、事实所有权和结果语义的前提下独立替换。

正式运行期不得存在旧 `世界服务.h`、其四个旧入口或兼容转发壳。世界根、场景、自我存在和坐标事实的消费者必须调用各自事实所有者的稳定身份服务，不得接收旧初始化裸句柄。`运行期业务操作组合器` 和 `运行期只读查询组合器` 只保留对新门面的强类型委托，不保留重复世界树入口。

## 2. 服务身份和依赖方向

正式服务身份为 `世界树业务服务`，合同版本从 `1` 开始。它属于 L2 世界组合服务，公开函数只接受强类型值式请求并返回调用方拥有的不可变值式结果。

允许依赖：

```text
世界树业务服务
-> 存在业务服务
-> 场景业务服务
-> 特征业务服务
-> 状态业务服务 / 动态业务服务的正式原子组合入口
-> 世界树快照读取服务
```

上述箭头表示门面可直接依赖这些具名服务，不表示前一服务拥有或转发后一服务的全部能力。门面不得保存领域仓库、内部数据操作对象或可写引用；领域服务不得反向依赖世界树门面。

禁止依赖：

```text
世界树业务服务 -X-> 仓库、SQL、材料文件、锁、令牌、事务、会话、索引或缓存
世界树业务服务 -X-> 旧世界服务兼容写入口
普通调用方 -X-> 绕过世界树门面直接拼接世界树跨领域业务结果
L2 服务 -X-> 向 L1 传参与者指针、回调、事务视图、会话、许可或锁
```

原子领域函数仍可被具有真实单领域依赖的调用方直接使用；统一门面不强制所有 L2 调用经过自己，也不重解释原子领域结果。

## 3. 世界树身份、结构和成员

1. 一次世界树操作必须具名提供世界根场景稳定身份见证和世界规则版本。根必须是当前有效场景，且不得在操作中改变身份。
2. 启动期必须先经新 L1 的 4070 恢复成功，或由持久安装证据确认该安装实例从未发布任何事实后，才可首次建立世界；SQL/材料不可用、证据缺失或损坏不得冒充全新实例。首次建立以当前完整快照的精确事实代次为基线，在一个 L1 写集中原子发布服务身份节点、场景标记属性类型节点、直接父场景关系类型节点、直接存在成员关系类型节点、世界根场景节点及其值为 `1` 的场景标记；不得另设“治理代次一”或依赖预期代次零例外。世界根自身必须是带有效场景标记的普通节点，不得以基础信息节点、显示名称、配置或裸句柄代替。

首次建立成功后，世界结构登记服务唯一保存并返回不可变 `世界结构登记`：服务身份、场景标记属性类型、直接父关系类型、直接成员关系类型和世界根的稳定编码，以及首次写集幂等键与已验证事实代次。登记只是 L2 对 L1 已发布事实的值式定位材料，不是第二数据仓或运行期权威；新服务实例未取得经恢复验证的登记时必须返回 `登记未加载`，不得扫描、按名称猜测或从 SQL / 缓存补造世界根。
3. 公开节点身份见证固定包含 `节点稳定编码 + 节点类型`；公开关系身份见证固定包含 `关系稳定编码 + 关系类型 + 源端节点身份见证 + 目标端节点身份见证 + 角色/顺序`。稳定编码不为零、类型已定义、字段互相匹配且能在同一事实截止内解析为唯一当前事实时才成立；节点、关系和值没有独立版本字段。
4. `节点句柄`、`关系句柄`、仓库编号、节点编号和关系编号只允许作为 L1 服务内部一次许可存续期间的调用期投影；不得进入 L1 公开服务合同、L2 请求/结果、幂等语义、持久证据身份或跨合同 ABI。L1 服务在取得许可后按稳定编码解析当前内部句柄，并在使用前后复核类型和当前性；许可释放后不得保存或返回该投影，L2 数据操作、领域服务和组合服务不得接触许可、仓库或句柄。
5. 关系稳定编码由 L1 在写集发布时分配；世界结构登记服务只保存并验证其已发布编码，不从内部关系号、容器位置或旧版本字段推导或包装关系身份。
6. 场景树只保存直接结构关系。每个非根场景在同一世界中恰有一个当前直接父场景；每个存在在同一世界中恰有一个当前直接场景。根无父场景。
7. 直接场景边固定使用登记中的直接父场景关系类型、方向 `父场景 -> 子场景`、顺序号 `0`；直接存在成员边固定使用登记中的直接成员关系类型、方向 `场景 -> 存在`、顺序号 `0`。两类关系的业务准入和写入方唯一为 L2 场景业务服务；L1 只执行端点、当前性和中性候选事务校验。禁止同时用两种关系表达同一成员边。
8. 场景子成员只允许场景或存在。状态、动态、特征定义、特征槽和值不是场景普通子成员。
9. 调整场景结构包括：移动存在到另一场景、移动非根子场景到另一场景、从场景移除存在。第一版不提供移除非根场景、删除场景、删除存在或物理回收。
10. 移动必须在写前验证旧父、目标父、当前关系稳定编码、请求的期望事实代次、世界归属、单父和无环；旧关系失效与新关系发布在同一内存事实事务和同一发布代次成立。
11. 移除存在只使当前归属关系退出，不退役或删除存在，不删除其特征、状态、动态或历史关系。存在没有当前场景时不得出现在普通世界树快照中，但仍可由其事实所有者审计读取。

## 4. 公开业务能力

合同版本 1 至少提供：

| 能力 | 唯一语义 |
| --- | --- |
| 查询存在完整事实 | 在一个世界和一个事实截止内返回存在身份、当前场景、全部当前特征槽和值、相关状态和动态 |
| 查询场景完整事实 | 返回场景身份、直接父场景、直接子场景、直接存在成员及成员完整事实 |
| 读取完整世界事实快照 | 从根递归返回整棵当前场景树及全部成员事实 |
| 创建存在并接纳到场景 | 同一事务创建实际存在身份和唯一当前场景归属；同键同义幂等读回 |
| 发布存在初始特征 | 只接受完整初始特征批次；全部项目同一批次发布 |
| 更新存在已有特征 | 只接受完整换代批次；旧当前退出和新当前发布同事务成立 |
| 发布状态并整理动态 | 发布状态后同一业务入口执行一次幂等动态整理；首状态或值未变允许成功且无新动态 |
| 移动世界树成员 | 原子失效旧直接关系并发布新直接关系，保持单根、单父、无环 |
| 移除世界树存在 | 原子失效存在当前直接归属，不删除存在本体 |

初始特征和已有特征更新均复用 4170 的特征批次身份、完整有序项目组和幂等账，不建立逐项旁路。状态动态入口复用状态和动态领域的类型化请求、状态身份、时间和被改变目标合同；v1 只形成状态迁移动能，不接受来源动作。动作致变动态由 4220 的独立入口形成并引用已发布迁移动能，不在本入口顺带创建。

## 5. 同代次完整世界事实快照

### 5.1 一致性

1. 每个存在/场景、特征、状态和动态读取必须通过其具名版本化服务函数完成；每个服务结果携带该服务内部一次 try-lock 共享许可下读取的非零 `事实截止代次`。许可只在该函数内部存续，不得跨服务传递。
2. 世界树快照读取服务先读取世界结构及代次，再读取特征、状态和动态，最后再次调用世界结构读取服务的 `读取当前事实代次`。只有全部结果代次与首、末代次完全相等时才发布快照；任一不等时丢弃本轮全部材料并完整重试一次，第二次仍漂移返回 `版本漂移`，不返回部分结果。
3. 禁止通过无代次的普通读取、SQL 查询、材料文件、缓存命中或界面投影拼接并宣称同代次快照。L2 不得为了同代次而取得或传递 L1 锁、许可、令牌、仓库或会话。
4. 若当前实现尚无可读的内存发布代次，必须先补齐 L1 代次见证提供者；不得用运行期纪元、许可序号、仓库高水位或时间戳冒充发布代次。
5. 任一服务许可竞争时立即返回 `许可拒绝`，不等待、不 sleep、不隐式循环，也不计入代次漂移重试。只有所有服务读取均成功而代次不等时，才允许丢弃整轮并完整重试一次。

### 5.2 完整字段

完整快照至少包含：

```text
合同版本、世界规则版本、世界根、事实截止代次
场景组：场景身份、直接父关系、直接子场景关系、直接存在成员关系
存在组：存在身份、当前场景和归属关系
宿主特征组：宿主、实例槽、特征定义、当前值关系、当前值、原始材料形状和来源
状态组：场景、主体、特征、值、发生时间和状态身份
动态组：前状态、后状态、被改变目标、来源动作、场景和动态身份
完整性状态和稳定排序规则版本
```

场景和存在按节点稳定编码升序；关系按关系稳定编码升序；特征按宿主、特征定义、槽位三者的稳定编码排序；状态按场景、主体、特征、发生时间、状态稳定编码排序；动态按场景、后状态时间、动态稳定编码排序。禁止按内部句柄、容器迭代顺序、SQL 行序、显示名称或已退出事实的创建顺序排序。

### 5.3 完整性和范围

1. 普通完整快照只包含从指定根沿当前有效直接场景关系可达的场景，以及这些场景的当前直接存在成员。
2. 每个纳入宿主必须列出全部当前实例特征槽；有槽无当前值、重复槽、重复当前值、悬空定义或跨宿主关系均为内部不一致，不能省略后返回成功。
3. 状态和动态只纳入其场景属于本树且主体或被改变目标属于本树成员的当前已发布材料；历史和审计读取另设接口，不混入普通快照。
4. 空世界根、根有父、成员多父、场景成环、跨世界引用、状态动态端点不完整或事实截止变化均返回具名非成功，不返回部分成功快照。
5. `缺项组` 属于读取结果在 `内部不一致` 分支下的稳定诊断载荷，不属于成功快照；成功快照 `完整=true` 且结果缺项组为空。

### 5.4 状态与动态的类型化事实证据

1. 状态和动态公开事实中的发生时间、动态种类和聚合规则身份不能只保留裸数值；每个值必须同时携带属性类型节点稳定编码、值事实稳定编码、可选前一值事实稳定编码、强类型来源、创建事实代次和当前状态发布代次。对象版本字段不得作为身份、排序、兼容或当前性依据。
2. 状态事实固定携带状态、场景、主体、特征、特征值、来源存在六个当前节点见证，以及主体、场景、特征、值、来源存在五条关系见证。发生时间使用 U64 类型化事实。
3. 动态事实必须逐项携带关系20的九类角色见证及其端点。状态迁移动能只允许角色1—5和9有值，角色6—8为空；动态种类值固定等于强类型枚举 `状态迁移`，聚合规则版本值固定为0。强类型枚举与类型化数值不相等时属于内部不一致。
4. SQL行、显示名称、调用时钟、请求回显或当前容器顺序不得补造上述身份、来源或发布代次证据。

## 6. 请求、结果和状态分类

公开结果状态稳定值为：

```text
已提交=1
幂等读回=2
已读取=3
未找到=4
入口拒绝=5
幂等冲突=6
版本漂移=7
许可拒绝=8
资源失败=9
内部不一致=10
```

`已提交` 和 `幂等读回` 只用于写入口；`已读取` 和 `未找到` 只用于读入口。调用方不得把未找到、部分材料或内部不一致降级成空成功。

合法世界根、场景和主体已经唯一解析，但当前尚无任何状态或动态时，状态动态查询必须返回 `已读取`、同次非零事实截止代次和两个空组；`未找到` 只用于请求中的根、场景、主体或其它必需身份不能解析。快照服务不得把合法零状态误判为对象缺失。

状态动态查询使用其 L2 事实所有者专属的 `节点直接状态动态读取状态`，完整稳定值为 `已读取=1、未找到=2、入口拒绝=3、版本漂移=4、许可拒绝=5、资源失败=6、内部不一致=7、未实现=8`；不得复用 L1 `节点直接结构服务状态`。`未实现` 固定携带代次0、状态组空、动态组空和缺项组空，绝不是合法零成功。

所有写请求至少携带合同版本、世界规则版本、世界根稳定身份见证、稳定幂等身份、期望事实代次和所需当前事实稳定编码。所有读请求至少携带合同版本、世界规则版本和世界根稳定身份见证；读取单个存在或场景时再携带目标稳定身份见证。

## 7. 写入原子性、幂等和读回

1. 可判定的合同版本、身份、类型、世界归属、预期当前关系、特征批次和状态动态端点必须在第一笔写入前拒绝。
2. 同键同义返回原结果；同键异义返回幂等冲突。移动的幂等语义包含世界根、成员、旧父、新父、旧关系和世界规则版本。
3. 跨存在与场景、状态与动态的业务入口只能消费事实所有者形成的不可变写入规格；最终写集由一个具名发布者在一个事务中确认、逆序撤销并最后发布。
4. L1 具名提交服务的公开合同只接受版本化纯值式强类型写集并返回纯值结果。服务经唯一数据操作形成中性规格，固定执行器完成类型合同、节点、类型化值、关系、索引、删除和幂等记录的参与者顺序；L2 不得提供参与者、回调、事务视图、会话或锁，也不得调用数据操作或执行器。禁止任意 JSON、无类型字节包或万能值写集。
5. 类型合同读回必须携带命名空间、所有者、生命周期、直接兼容声明、创建事实代次和当前状态发布代次；类型化值读回必须携带强类型来源、前一值事实稳定编码、创建事实代次和当前状态发布代次。来源只能是已发布节点见证，或签发系统资格且等于该类型合同所有者的服务稳定身份；世界根 / 初始场景资格来源固定为世界结构服务，实际存在资格来源固定为存在服务。不得以空值、自引用新节点、父场景、SQL 行时间、默认版本、显示名或当前容器位置补造来源和发布证据。
6. 世界领域在 L2 自行定义公开业务幂等身份、请求同义 / 异义和必要执行材料；向 L1 提交时只传不透明幂等键、期望事实代次和完整中性写集。L1 不接收请求意图摘要、执行证据摘要、提供者见证或领域结果见证，也不查询 SQL 或扫描全仓裁决同义。世界领域如需持久准备、恢复互证或双摘要，必须建立独立领域 / 管理合同，不得成为普通 L1 CRUD 固定成本。恢复入口不能由普通 L2 写请求指定待恢复的既有稳定编码。
7. 发布前失败必须零普通可读变化。写前持久准备已经成立而内存候选或确认失败时，只有全部候选逆序撤销并由同一持久端口明确见证“本次尝试未发布”后才可释放事务域；撤销或未发布见证失败/未知时必须隔离，禁止继续分配或复用本次计划身份。撤销无法证明前态时同样隔离。发布成功后在代次推进后、独占许可释放前，L1 按通用对象种类、稳定编码、期望事实代次和当前/已退出状态形成值式读回，L2 事实所有者再映射为操作专属读回；权威读回不一致属于内部不一致，必须隔离事务域并写失败见证，不得二次改写已发布幂等记录、再次写入补救或用事务释放后的普通快照证明原提交。
8. `世界树状态动态请求` 只允许调用方提供合同、世界请求头、完整后状态和整理幂等身份；不得提供前状态、动态稳定身份、来源动作、比较算法或注册身份、事实截止代次、L1局部身份、许可、事务或参与者。
9. 状态动态写入固定分为：无前状态只发布首个基准状态；前后等价只发布后状态；存在合法差异时同事务发布后状态和一条状态迁移动能。比较提供者必须在一次请求中同时返回具名关系和差异材料；`未实现` 不得映射为比较未注册、不可比、空成功或默认基准状态。

## 8. SQL、持久证据和恢复

1. 世界树普通读写只裁决当前内存已发布代次。SQL 数据只用于已发布代次的持久证据、隔离恢复输入、应急审计和人机交互投影。
2. SQL 查询、控制面板和导出材料不得成为世界根、成员、特征当前值、状态、动态、关系当前性或完成结论的运行期权威。
3. 恢复必须先形成隔离候选，验证整个世界结构和全部类型化记录，再原子发布新的内存代次；禁止以 SQL 当前行覆盖已发布内存事实。
4. 世界领域或部署策略若要求持久证据，必须通过独立具名合同冻结写前准备、发布前失败未发布见证、发布后见证、尝试序号和未知收敛；未启用时普通 L1 CRUD 不生成或返回这些材料。该策略不得改变内存已发布代次的权威身份，也不得把领域持久证据字段塞入 L1 中性请求。启动恢复遇到准备、发布、撤销或多发布见证无法唯一裁决时仍须隔离并保持相关普通入口关闭。
5. SQL 中的“当前行”、视图、存储过程结果和控制面板查询均不是运行期回源；不得在内存未找到、版本漂移、许可拒绝或内部不一致时查询 SQL 补判成功。进程启动恢复完成前普通世界树服务保持关闭；恢复一次发布完成后，SQL 恢复材料立即退回非权威证据身份。

## 9. 验证合同

至少验证：

1. 根、单父、无环、存在单位置和跨世界拒绝。
2. 创建并接纳的原子性、幂等读回和异义冲突。
3. 初始特征批次、换代批次、旧当前退出和完整当前读回。
4. 首状态、无变化状态和有变化状态三类整理结果；状态迁移动能的来源动作必须为空。另验证已由 4220 入口发布的动作致变动态可在快照中保留来源动作，但本入口不创建它。
5. 存在移动、子场景移动、移除存在、旧关系失效、新关系发布和失败逆序撤销。
6. 全部具名服务结果的同代次组合、稳定排序、首末代次复核以及并发写导致整轮重试/漂移而非混代成功。
7. 缺值、多父、成环、悬空端点、版本漂移、许可拒绝、资源失败、写前准备后候选失败的明确未发布见证/见证未知隔离，以及发布后内部不一致。
8. SQL 不可用或内容落后时，已发布内存世界事实读取不被替换或改写。
9. 正式运行期代码中 `世界服务.h`、其 include、类型、成员、构造和工程登记均为零；语素基础信息只能调用基础信息事实所有者服务，不允许兼容转发壳。

## 10. 非目标

- L1 提供受限、强类型、业务中性的 CRUD；普通业务调用方不得绕过具名领域服务直连。它不是任意关系编辑器或无类型值仓。
- 不删除、退役或物理回收存在和场景。
- 不把状态、动态或特征值挂成普通场景成员。
- 不重建世界—概念、概念—词或复杂动态算法。
- 不要求所有单领域调用都经世界树业务服务转发。
