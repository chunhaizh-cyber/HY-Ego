# 4200 子规范 世界树数据结构 CRUD 与同截止一致读取

编号：4200
日期：20260909

状态：正式子规范

## 1. 定位

本规范只定义世界树作为一种强类型树 / 图数据结构的创建、读取、更新和退出。它不定义“现实世界”“自我”“存在”“场景”“资格”“状态”“动态”“因果”等业务含义；旧世界树业务门面和领域见证口径自本版起退出。

### 1.1 世界树应用语义与数据操作的边界

`DATA-L3` 世界树结构聚合只组合 `DATA-L2` 公开能力，不取得第二写入权。面向现实世界的应用入口可以按已经裁决的业务目标组织跨对象操作和完整读取；其“语义”表示明确操作目的、关系范围、步骤及成功条件，不表示数据聚合层自行裁决现实世界资格、需求、任务或方法业务结果。现实根的选择由 DATA 之外的应用装配显式提交，并通过正式场景树合同读回，不能从无父节点、名称或缓存猜测。

各数据类保留本类结构操作，世界树应用入口只组合所需公开合同：

| 操作范围 | 唯一承接边界 |
| --- | --- |
| 场景角色、四个实际根、实例组织、场景父子及成员关系 | 场景类按1150/4202提供具名入口；旧宿主关系仅兼容待迁移 |
| 存在特征引用、组成及其它本类具名关系 | 存在类承接；特征内容由特征类、场景角色及场景成员由场景类承接，不新增存在类的反向依赖 |
| 特征身份、类型、值及静态一次特征事实集合 | 特征类；集合按 4125，不产生概念归类或派生值 |
| 状态、动态、因果事实 | 对应数据类；只按各自正式输入合同发布和读取 |
| 创建对象并接纳、跨对象移动、完整现实世界读取 | 世界树应用入口组织，实际写入留在上述提供者 |

世界树不复制各数据类CRUD、直达L1或建立第二权威关系。同一对象的组成、场景成员及子场景归属按4202/7150合计至多一项，场景/存在视角复用同一节点；组成展开与角色投影不补第二条归属，也不从全部内部成员反推组成。需求/任务及Vm/Vt仍属于独立ARCH-L4，不进入场景成员或完整世界事实快照。

同一 owner 可闭合的创建接纳、关系替换由相应数据类原子提交，世界树不拆成两次写。存在跨场景 / 组成类别的直接归属移动必须遵守 7150 的联合守卫及原子替换；没有提供者时是能力待实现，不允许分步成功。其它确允许分阶段的跨 owner 多步骤入口，只有具名合同明确支持时才可宣称原子；否则必须显式返回已发布阶段、待继续或结果未知，保留原请求供续跑，不补偿删除、不以局部成功宣称整体成功。完整聚合读取只有全部子读成功、同一一致性边界、引用闭包完整且预算足够才返回完整载荷。

本边界不恢复旧世界树业务门面，也不证明新应用入口已经实现。字段、ABI、分步恢复和实际消费者仍须由具名设计与验证闭合；记录面函数存在不等于应用服务可用。

## 2. 数据结构

世界树聚合读取下列结构事实，不另行规定存在或特征的本体布局：

```text
树身份
节点记录
有向关系记录
各对象合同允许的类型化值与特征引用
根标记或根关系
```

存在字段按1140/7150，特征按1130/4110，值对象按2100，场景七字段与实例根按1150/4202；4230承接旧ABI隔离。实际根和组织边不能以索引替代，不给对象补回旧宿主槽、固定属性组或技术封套。可靠性留在L1及具名接口边界；名称、显示文本、业务资格不成为结构成立条件。

## 3. 结构不变量

1. 稳定编码非零、不可复用；关系端点必须引用已发布或同写集建立的合法节点。
2. 树合同要求单根时恰有一个当前根；要求单父时每个非根节点最多一个当前直接父关系。
3. 直接父关系不得形成结构环；存在组成、场景成员、子场景及同节点角色展开按7150/4202联合检查，角色视图不补第二条边，其它引用是否允许成环由其合同决定。
4. 存在允许引用同类型多个准确F；4110只维护固定准确内容，7150维护存在已知与当前采用，7160维护共享概念域。场景特征实例树按4202，不恢复F内当前/历史和值域，也不因采用新值删除旧F或合法引用。
5. 当前关系替换建立新关系并使旧关系退出；历史记录不可原地覆写。
6. 同一组合读取的节点、关系和值必须在一致读取边界内相互对应；不能把不同时点的局部读取拼成完整当前结构。

### 3.1 既有R1具名树的旧物理合同（兼容待迁移）

以下六项只解释4230既有R1独立场景节点族格式及其合法读回/恢复，不能作为1150/4202同节点场景视角的新物理合同。尤其非根独立场景父关系、旧创建写集不能迫使已归属存在再建第二边；新模型所需身份/角色映射、四根和原子启用须另行闭合，不静默重释旧ABI。

1. `L2场景树身份` 是根场景稳定编码的强类型包装，不是独立节点族、第二场景节点或第二 owner；一个场景 owner 底座可以同时承载多棵具名树。
2. 每棵具名树恰有一个当前根。根以“根场景指向场景 owner 内不可变树登记锚点”的唯一当前根标记关系成立；非根场景以“场景指向该树根”的唯一当前树归属关系成立。根不建立指向自身的归属自环。
3. 每个已登记场景恰好由根标记或树归属二者之一证明属于一棵树，不得同时成为根和非根，不得同时属于多棵树。没有当前父关系只表示结构根候选，不构成根标记、树归属或现实世界资格。
4. 根没有当前直接父关系；每个当前非根场景恰有一个同树当前直接父场景。父子新增或替换必须在写前证明两端树身份相同；跨树父子固定拒绝。
5. 场景成员关系、固定属性、名称、缓存、函数参数和调用方选择均不能建立或替代树身份、根标记或树归属。
6. 根场景、场景族归属、根标记和后继非根场景的场景族归属、树归属及直接父关系，分别由场景唯一 owner 在各自创建请求的一笔 owner-scoped 中性事务中原子发布。不得先创建裸场景再补根标记或树归属。

场景数据服务只保证上述纯结构唯一性。项目把哪棵树解释为唯一现实世界树属于 DATA 之外业务调用方的选择，不得登记为 DATA-L2 根资格。

## 4. 创建

1. 调用方按各数据类合同提交完整强类型创建请求，明确本次需要的节点、关系和值。建立新根的请求明确“建立一棵新树”，成功后以新根稳定编码形成树身份；新增非根场景须明确既有树身份和直接父场景。存在可以按 7150 先独立建立，再按明确操作建立归属，不能把场景树父关系前置套到所有存在创建。空集合与可选引用按各对象合同表达，不以默认值补齐。
2. 服务只校验结构形状、类型、端点、基数、顺序和可靠提交条件，不判断节点代表什么业务对象。具名技术接口所需的期望代次与幂等按其合同处理，不反向成为存在或特征的普通字段。
3. 同一 owner 的组合创建在一个中性事务中原子发布；发布前失败零公开可读变化。跨 owner 应用组合服从第 1.1 节，不能仅因一个应用函数包装多个调用就宣称单事务。
4. 同键同结构返回原结果，同键异结构返回幂等冲突。

## 5. 读取

1. 支持按稳定编码读取当前或历史节点、关系和值。
2. 支持按树身份、根、源端、目标端、关系类型及正式值 / 特征索引条件读取结构投影，不要求先定位旧宿主实例槽。
3. 组合读取返回明确截止代次、稳定顺序和逐项完整记录；不得以空编码、默认值或其它代次记录补齐。
4. 未找到、已退出、版本漂移、结构入口拒绝、资源失败和内部不一致必须分账。旧许可拒绝仅供历史解码，现行 DATA 入口不产生调用者业务许可结论。

## 6. 更新

1. 节点不可变字段不得原地改写；需要变化时建立新记录或按专门合同替换引用。
2. 移动表示直接归属替换：调用方明确旧关系和新归属端，服务联合校验后同事务退出旧关系并建立新关系。存在的新归属端可以是场景或父存在；四种类别组合均按 7150 保持唯一性、无环和原节点身份。
3. 新准确内容由特征类建立或复用另一个固定F，存在类改变已知/采用关联；不原地改写准确内容。世界树不复制setter、宿主槽或概念积累；数据服务不因差值擅自生成状态、动态、动作或因果。
4. 更新成功后通过正式读取入口核对新当前记录和旧历史记录。

## 7. 退出

1. 删除表现为结构记录退出。当前入口不再返回已退出记录，历史入口仍可读取其完整生命周期。
2. 退出节点前必须按合同处理当前引用：拒绝悬空、同事务退出允许的附属关系，或由调用方先行移除引用；数据服务不得按业务意义选择策略。
3. 物理回收不属于普通 CRUD；只有独立管理合同证明当前、历史、审计和恢复引用均不再需要时才能执行。

## 8. 状态、动态和因果数据

1. 状态、动态和因果若作为记录挂接到世界树，只能由调用方提交完整结构请求。
2. 世界树数据服务不得从当前值自动形成状态，不得从前后状态自动形成动态，也不得判断或生成因果。
3. 空动作因果、相互引用因果或尚未确认真实性的因果，只要满足其结构合同即可保存；业务真实性由 DATA 之外业务层负责。

## 9. 验证

验证者在生产代码之外直接输入受控世界树结构并至少覆盖：

1. 创建根、节点、关系及各对象允许的值后逐字段读回一致；
2. 按编码、关系条件、值 / 特征索引和组合投影查询完整且不混代，不补旧宿主实例槽；
3. 四类直接归属替换保持同一存在身份，特征引用变化不误删特征或值；历史读回按适用合同保持可追溯；
4. 关系或节点退出后当前不可见、历史仍可查；
5. 重复创建、异结构冲突、成环、多父、悬空端点、旧期望代次和非法请求零变化；
6. 适用组合写的原子性。

验证不得构造自我、资格、安全目标、服务目标、业务状态整理或因果真伪剧本。通过只证明世界树数据结构服务，不证明任何业务系统。

## 10. 迁移与非目标

1. 旧接口中纯结构 CRUD、同截止读取、稳定编码、生命周期、幂等和事务能力可以复用。
2. 旧接口中的世界资格、实际存在资格、场景业务准入、状态自动整理、动态生成、领域意图、执行证据和结果见证的业务解释必须迁出 DATA 数据服务；具名状态 / 动态结构发布仍服从 0050 及对应事实规范。
3. 未重新分类的旧世界树计划保持冻结；代码已经存在、编译或运行不恢复其业务语义授权。
4. 本规范不定义上层业务如何命名、选择或解释树中对象。
5. 旧普通场景、旧世界登记、旧 P1B / P1A3、旧世界树业务门面和旧状态 / 动态登记都不能自动迁成具名树。非空旧域缺少合法根标记或树归属时，R1 全部正式场景入口拒绝，不得扫描、猜测、按无父关系认领或补写；未来的读取、清退或保码迁移必须另立独立 legacy 退役合同，不能借 R1 普通 CRUD 实施。

## 10.1 作为概念空间叶级读源

概念空间根视图可以把世界树公开的 `L2世界事实引用` 和概念—世界事实支持关系作为叶级引用读源，但不得把世界树节点、属性值、状态、动态或关系材料复制进 L3 投影。叶级读取必须与概念根、普通概念和直接边使用同一 `G0` 截止，并在支持关系端点、关系生命周期和世界事实引用无法互证时返回 `内部不一致` 和零载荷。

世界树服务只提供正式结构读回：按稳定世界事实引用读取、按支持关系端点有界读取、当前 / 历史类别、实际截止和结构化失败状态。它不负责选择四本体根、不判断概念是否成立、不生成叶级支持关系，也不把世界事实支持关系解释为业务资格。L3 只能调用其公开结构合同；不得访问世界树内部仓库或用无父节点、名称、缓存和显示顺序补齐叶级引用。

概念空间根视图的根组正式读回仍由 L2 概念结构服务负责。世界树读回与根组读回的实际截止不一致时，L3 不得自行升级或降级截止，必须返回 `事实代次漂移` 或 `内部不一致`（按上游结果分账）并清空投影。
