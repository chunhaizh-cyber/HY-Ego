# 5210 子规范 任务状态特征集合与阶段关联

编号：5210
日期：20260824
版本：v0.9
状态：正式子规范
权威等级：正式规范

## 1. 定位

本规范把 5200 定义的任务特征类型与任务生命周期阶段关联，规定每个阶段的最低结构前提、必需特征、可选特征和禁止激活特征。

生命周期阶段只是路由投影。本表是最低合同，不是用阶段枚举代替完整任务状态。

直接上级规范：3200。

直接依赖规范：4010、5200。

相关边界规范：5220、5230、6140、6150。

## 2. 所有阶段共同前提

除入口拒绝外，任何有效任务阶段都必须能够回读：

```text
当前任务身份
唯一绑定的同类任务查询锚点身份
当前任务来源需求关系组
至少一项当前有效具体需求及其互证单目标投影（形成目标时）
本轮实际消费的来源需求关系与需求版本快照（如本轮需要）
唯一任务虚拟存在
当前生命周期关系、版本和发生时间
任务承接角色
目标当前性
当前业务状态段
状态段当前性
```

其中任一结构锚点缺失、重复或版本不一致，都属于结构不完整或内部逻辑错误，不得通过补写阶段枚举兜底。

本规范中的“当前方法选择记录”只有在 5230 的任务方法选择记录节点、领域类型化记录、关系 16 角色 30—34、全部已声明角色 40、关系 14 / 23 历史互证、筹办轮次和选中方法内容版本联合读回完整时才成立。候选数量、普通任务到方法引用、索引命中、排序摘要、日志或缓存不得替代该完整性；方法生命周期或内容版本变化时旧选择退出当前执行资格并触发新筹办，但旧选择历史不得改写。

## 4. 正式业务状态段

生命周期阶段之下至少区分以下业务状态段。状态段身份必须和表中区分特征同时成立；只写状态段名称仍不构成完整任务状态。

当前任务完成裁决直接复用本规范既有状态段：`执行结果待验证` 表示实际结果已形成但目标达成、推进和验证尚未全部收束；只有目标达成、验证、结果当前性和完成来源联合成立时才进入 `任务完成`；目标未达成且旧冻结失效时进入 `目标未达成待重筹办`。本次修订不新增任务完成节点或第二套状态机。

| 业务状态段 | 生命周期投影 | 区分该状态段的必需特征 | 禁止同时成立 |
| --- | --- | --- | --- |
| 承接初态 | 已创建 | 承接角色已形成；目标当前；状态段当前 | 筹办轮次、有效筹办占用、当前方法、执行冻结 |
| 待初次筹办 | 已承接 | 同类任务查询锚点、至少一条当前 `T→D` 关系、来源需求互证目标和初次承接触发已形成 | 通用授权安全事实、有效筹办占用、当前方法、执行冻结 |
| 筹办权已取得 | 筹办中 | 新筹办轮次；有效筹办占用；筹办读取当前性=当前；候选集合完备状态=未开始 | 运行中方法、当前执行冻结、另一有效筹办占用 |
| 路径形成中 | 筹办中 | 筹办权已取得全部；路径查找状态=形成中或需补齐；候选集合尚未完整 | 当前方法选择、当前执行冻结 |
| 候选形成中 | 筹办中 | 路径查找已得到可召回方向；候选集合完备状态=形成中 | 当前方法选择、当前执行冻结 |
| 候选已形成待选择 | 筹办中 | 候选集合完备状态=已完整；候选来源记录和版本当前；方法选择当前性=未选择 | 当前方法发布关系、执行冻结 |
| 方法已选择待契约复核 | 筹办中 | 当前方法选择记录当前；方法特征契约当前性=未挂载或待验证 | 执行就绪=已就绪、当前执行冻结 |
| 方法契约复核中 | 筹办中 | 方法特征已挂载；条件、输入、参数、禁止项、验证和归因合同逐项形成 | 当前执行冻结；未验证合同不得进入排队 |
| 等待子目标 | 等待中 | 筹办结果类型=子目标承接；等待类型=等待子目标；子目标、合法生产者和回流触发关系完整 | 有效筹办占用、当前执行冻结、运行中方法 |
| 等待方法补齐 | 等待中 | 筹办结果类型=方法补齐承接；等待类型=方法结构补齐；候选方法、具体缺失结构、合法补齐处理方和回流触发完整 | 自动创建的方法首、独立能力缺口节点、当前执行冻结 |
| 等待条件或输入 | 等待中 | 等待类型=条件或输入；未满足条件/缺失输入集合、合法生产者、重新触发条件和等待版本完整 | 把目标语义不完整、缺方法入口等内部结构问题包装成等待 |
| 等待外部事实或时间 | 等待中 | 等待类型=外部事实或时间；等待对象、来源、合法生产者、重新触发条件完整 | 自我臆测外部存在内在状态、通用授权材料缺失等待、当前执行冻结 |
| 可执行已冻结 | 排队中 | 方法选择、方法契约、条件、输入、参数、禁止项、验证、归因全部通过；执行就绪=已就绪；执行冻结=当前 | 把调度投影误作持续当前权限、有效筹办占用、未满足等待条件、结构缺口；冻结后权限为零或全局控制态禁止时不得真实派发 |

| 执行结果待验证 | 执行中 | 方法运行已结束；实际结果已形成且当前；执行结果类型已确定；目标达成、推进和验证裁决尚未全部收束 | 任务完成、结算提交、用动作成功代替目标达成 |
| 目标未达成待重筹办 | 待重筹办 | 目标达成裁决=未达成；结果当前；上一执行轮次引用；重新触发状态=已触发；旧冻结失效 | 继续执行旧方法运行、把未达成直接写成失败 |
| 当前性失效待重筹办 | 待重筹办 | 来源需求、目标、路径、方法、输入或世界事实至少一项当前性失效；触发来源明确；旧冻结失效 | 继续使用旧冻结、覆盖上一筹办轮次 |
| 任务完成 | 已完成 | 目标达成=已达成；验证通过；实际结果当前；完成当前性=当前；目标达成比例和完成来源完整 | 有效等待、待重筹办、运行中方法、当前执行冻结 |
| 业务失败终止 | 失败 | 合法业务失败分类；当前失败证据；终止版本；方法运行已结束 | 内部逻辑错误、无候选、筹办漏检、普通等待 |
| 授权取消终止 | 取消 | 合法取消授权；取消完成；终止版本；执行过则动作停止已确认 | 无授权取消、未停止动作、有效筹办占用 |

同一业务状态段仍可由方法开放特征继续细分。例如两个任务都处于“方法契约复核中”，但所需输入、验证或安全特征类型不同，它们是不同完整状态；状态段名称只负责路由共同处理逻辑。

## 5. 筹办闭合结果与阶段去向

| 本轮筹办结果 | 必须同时形成 | 阶段去向 |
| --- | --- | --- |
| 可执行冻结 | 当前方法选择、方法特征挂载、输入/条件/参数/禁止项/验证合同完整和当前冻结 | 排队中 |
| 子目标承接 | 明确子目标、承接关系、合法生产者和回流触发 | 等待中 |
| 学习需求承接 | 目标状态解析结果、无匹配方法事实、学习需求所需目标条件和合法学习任务生产者 | 等待中 |
| 方法补齐承接 | 已有候选方法、具体结构化缺失、合法补齐处理方和回流触发 | 等待中 |
| 合法等待 | 等待对象、等待条件、合法生产者、重新触发条件和等待版本 | 等待中 |
| 目标已完成 | 当前实际结果、逐项满足证据和验证通过 | 已完成 |

候选方法为空只能形成“学习需求承接”或“合法等待”，不得建立独立能力缺口节点，不得自动创建方法首，不得进入失败，也不得返回无结构的上层回退。已有候选但动作入口、条件结果对、输入参数、禁止项、验证或归因合同存在具体结构化缺失时，只能形成“方法补齐承接”或带生产者和回流条件的合法等待。

## 6. 重复筹办

以下事实可以触发新筹办轮次：

```text
子任务或子目标回流
等待条件满足
执行后目标仍未达成
当前方法、条件、参数或输入版本变化
活动路径或权重变化
当前 `T→D` 关系组、来源需求当前性、目标、方法适用性或已有执行冻结变化
世界状态变化使旧冻结失效
```

新一轮必须增加筹办轮次，建立新的筹办占用和读取版本，并把上一轮状态段、候选、方法选择和冻结保留为历史。不得覆盖上一轮记录。

冻结后正常调度资格、优先级投影、具名方法许可或全局控制态单独变化时，只影响派发资格并触发重新读取 / 排序；它们不自动建立新筹办轮次，也不改写运行中任务状态。只有来源需求、目标、方法适用性或既有执行冻结本身失效时，才按上述具名来源进入新筹办。

## 7. 特征一致性规则

1. 阶段迁移前必须验证目标阶段的必需特征全部存在且取值合法。
2. 目标阶段禁止激活的特征仍为当前时，不得迁移阶段。
3. 方法开放特征可以增加业务状态细分，但不得取消本表最低必需特征。
4. 相同阶段下，方法开放特征、值、来源或版本不同，属于不同业务状态段。
5. 生命周期枚举、状态节点、控制面板显示和日志不得替代本表的特征集合复核。
6. 筹办占用是运行治理事实，只在筹办中允许有效；它不替代任务业务状态，也不以线程编号表达。

## 8. 任务生命周期与迁移证据专用关系

任务生命周期使用 4010 锁定的关系类型 14。源必须是任务，目标必须是具备主体、场景、发生时间和当前性的实例状态；同一任务恰有一条有效当前关系。顺序号从 1 连续递增并只表达生命周期版本；迁移时旧关系失效并保留审计，新关系成为唯一当前投影。ARCH-L4 任务生命周期 provider 是该关系的唯一业务解释方；ARCH-L2 状态结构 owner 只执行已经裁决的强类型结构写入和读回，生命周期阶段名称不得脱离本规范的特征集合单独裁决任务状态。

任务生命周期迁移证据使用关系类型 15，源必须是本次迁移形成的目标实例状态。顺序号、角色和允许目标固定为：

| 顺序号 | 证据角色 | 允许目标节点类型 |
| --- | --- | --- |
| 40 | 来源任务 | 任务 |
| 41 | 来源方法 | 方法 |
| 42 | 来源动作 | 方法；动作入口角色另由方法规范复核 |
| 43 | 来源状态 | 状态 |
| 44 | 来源动态 | 动态 |
| 45 | 取消授权来源 | 任务或方法 |
| 46 | 动作停止证据 | 状态或动态 |

各角色是否必需由具体迁移边规定；每个要求非空的角色必须恰有一条有效关系。有效唯一键是“关系类型 15 + 完整源状态句柄 + 顺序号”：同源同角色不得出现第二条有效关系，同一目标可以合法承担不同角色。未知顺序号、错误目标类型、同角色重复或缺少该迁移边要求的角色必须在写前拒绝；前置通过后的结构异常属于内部逻辑错误。ARCH-L2 状态服务只形成通用状态事实，不解释业务结果；迁移证据由 ARCH-L4 provider 提交结构请求。

精确重复迁移必须从完整生命周期历史逐项复核前驱关系、目标阶段、发生时间和全部证据角色；同义重复读回既有迁移，不新增关系或推进版本，异义重复按冲突收口。不得用时间戳、生命周期版本、摘要、日志或普通布尔值单独裁决幂等。
