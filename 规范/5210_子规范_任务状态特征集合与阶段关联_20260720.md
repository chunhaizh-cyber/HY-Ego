# 5210 子规范 任务状态特征集合与阶段关联

编号：5210
日期：20260903
版本：v1.4
状态：正式子规范
权威等级：正式规范

## 1. 定位

本规范把 5200 定义的任务特征类型与任务生命周期阶段关联，规定每个阶段的最低结构前提、必需特征、可选特征和禁止激活特征。

生命周期阶段只是路由投影。本表是最低合同，不是用阶段枚举代替完整任务状态。

直接上级规范：3200。

直接依赖规范：4010、5200。

相关边界规范：5220、5230、6140、6150。

## 2. 所有阶段共同前提

除入口拒绝外，任何有效任务阶段都必须能够回读：

```text
当前任务身份
唯一绑定的同类任务查询锚点身份
当前任务来源需求关系组
至少一项当前有效具体需求及其互证单目标投影（形成目标时）
本轮实际消费的来源需求关系与需求版本快照（如本轮需要）
唯一任务虚拟存在
当前生命周期关系、版本和发生时间
任务承接角色
目标当前性
当前业务状态段
状态段当前性
```

其中任一结构锚点缺失、重复或版本不一致，都属于结构不完整或内部逻辑错误，不得通过补写阶段枚举兜底。

本规范中的“当前方法选择记录”只有在 5230 的任务方法选择记录节点、领域类型化记录、关系 16 角色 30—34、全部已声明角色 40、关系 14 / 23 历史互证、筹办轮次和选中方法内容版本联合读回完整时才成立。候选数量、普通任务到方法引用、索引命中、排序摘要、日志或缓存不得替代该完整性；方法生命周期或内容版本变化时旧选择退出当前执行资格并触发新筹办，但旧选择历史不得改写。

## 3. 任务生命周期、任务轮次和主阶段分账

任务生命周期只表达`当前 / 正式结束 / 取消收口 / 历史`。任务运行状态另由以下字段共同成立：

```text
任务轮次身份与序号
任务轮次主阶段
筹办轮次身份与序号
执行轮次身份与序号（进入执行时）
任务轮次结论（结算时）
自我后继决议（轮次收束后）
```

主阶段固定为：

| 主阶段 | 最低必需特征 | 禁止同时成立 |
| --- | --- | --- |
| 筹办 | 当前任务轮次、当前筹办轮次、当前筹办业务状态、唯一有效筹办占用、目标和来源需求当前性 | 运行中实例方法、已发布本轮结算结果 |
| 执行 | 当前任务轮次、执行轮次、实例方法、当前执行冻结；含现实改变步骤时还需当前自我现实执行授权 | 有效筹办占用、第二运行实例、失效冻结；纯内部治理或纯观察不得伪造授权 |
| 结算 | 当前任务轮次、正式实际结果或合法无执行短路结果、结果治理输入 | 运行中实例方法、自动开启下一任务轮次 |
| 轮次已收束 | 任务轮次结论、每个要求核算的 `T→D` 独立结果、任务轮次结算结果、运行已停止 | 当前执行冻结、运行中实例、自动重筹办 |

目标未达成是`任务轮次结论`，不是主阶段，也不是“待重筹办”状态。`轮次已收束`是停驻状态，不是第四种任务治理方法，也不等于任务生命周期已经结束。

## 4. 筹办阶段业务状态段

任务管理线程只按当前权威状态推进；消息到达本身不增加业务状态。筹办阶段至少区分：

| 业务状态段 | 必需特征 | 合法后继 |
| --- | --- | --- |
| 待初次筹办 | 当前任务轮次已建立，尚无筹办轮次 | 建立 P1，进入待找方法 |
| 待找方法 / 继续找方法 | 当前筹办轮次、唯一占用、任务信息版本、方法查找范围、已覆盖 / 剩余范围 | 继续找方法；完整覆盖且有候选时待查条件；完整覆盖且无候选时方法缺失 / 等待方法处理 |
| 待查条件 / 继续查条件 | 已登记全部候选方法及内容版本、逐方法条件组待核验范围、已覆盖 / 剩余范围 | 继续查条件；全部核验后进入待执行前选择或条件缺失 / 等待条件 |
| 方法缺失 / 等待方法处理 | 完整方法查找范围、零候选结论、具名后继处理或重触发条件 | 条件变化或新方法发布后重新进入找方法 |
| 条件缺失 / 等待条件 | 全部候选与条件组核验完成、零具备条件组结论、具名条件生产者或重触发条件 | 条件变化后重新进入查条件 |
| 待执行前选择 | 全部候选条件核验完成，至少一组当前具备；尚无选择、路径、实例或冻结 | fresh 执行前选择 |
| 可执行已冻结 | 已选单一执行选项、当前选择记录、实例、完整冻结和作用范围 | 既有授权 / 安全 / 调度门控后进入执行 |
| 待自我现实执行授权 | 冻结含现实改变步骤；授权请求绑定任务、三类轮次、冻结、实例和动作范围 | 授权成立后进入执行；拒绝 / 等待保持非执行状态 |

找方法与查条件是先后两个状态族。不得在方法范围尚未完整覆盖时查条件；不得在全部候选条件组尚未核验时进入执行前选择。方法 / 条件缺失只保存为当前任务材料；若需要独立后继需求，必须另经 self 确认和需求领域写入。

## 5. 执行、结算和收束状态段

| 业务状态段 | 必需特征 | 后继 |
| --- | --- | --- |
| 执行动作中 | 执行轮次、实例方法、当前冻结；含现实改变时有当前授权且安全硬否决未命中 | 正式结果形成后进入结算 |
| 执行结果待结算 | 方法运行已结束、实际结果当前、执行结果类型确定 | 目标 / 验证 / 归因和本轮停止收口 |
| 任务轮次结算中 | 正式结果、验证 / 归因、停止证据和适用后继结果正在形成 | 形成任务轮次结算结果；不等待全部 `T→D` |
| 轮次已收束待自我决议 | 本轮结论和轮次结算结果完整；0..1 上级调用返回可独立重试 | 调用槽结算及继续 / 结束 / 等待 / 取消 |

目标已达成、目标未达成、业务失败和取消是轮次结论，不得压成主阶段。方法成功、动作发生或单个需求满足都不能直接形成轮次收束。

## 6. 同任务轮次重新筹办与新任务轮次

只有任务仍在筹办阶段且尚未开始实例执行时，等待回流、来源 / 目标 / 方法 / 条件 / 输入 / 冻结当前性变化才可结束旧筹办轮次并建立同一任务轮次内的新筹办轮次。旧候选、选择、实例、冻结和授权引用保留历史。

任务进入执行或形成正式实际结果后，任何结果都先进入结算，不得自动重筹办。轮次收束后，只有自我`继续`后继决议才能建立新任务轮次；新任务轮次从新筹办轮次开始，并重新实例化、冻结和按作用范围判断是否需要新授权。目标未达成、方法新代际、需求仍未满足和安全事实变化都只是自我后继决议输入。

## 7. 特征一致性规则

1. 阶段迁移前必须验证目标阶段的必需特征全部存在且取值合法。
2. 目标阶段禁止激活的特征仍为当前时，不得迁移阶段。
3. 方法开放特征可以增加业务状态细分，但不得取消本表最低必需特征。
4. 相同阶段下，方法开放特征、值、来源或版本不同，属于不同业务状态段。
5. 生命周期枚举、状态节点、控制面板显示和日志不得替代本表的特征集合复核。
6. 筹办占用是运行治理事实，只在筹办中允许有效；它不替代任务业务状态，也不以线程编号表达。

## 8. 任务生命周期与迁移证据专用关系

任务生命周期使用 4010 锁定的关系类型 14。源必须是任务，目标必须是具备主体、场景、发生时间和当前性的实例状态；同一任务恰有一条有效当前关系。顺序号从 1 连续递增并只表达生命周期版本；迁移时旧关系失效并保留审计，新关系成为唯一当前投影。ARCH-L4 任务生命周期 provider 是该关系的唯一业务解释方；ARCH-L2 状态结构 owner 只执行已经裁决的强类型结构写入和读回，生命周期阶段名称不得脱离本规范的特征集合单独裁决任务状态。

任务生命周期迁移证据使用关系类型 15，源必须是本次迁移形成的目标实例状态。顺序号、角色和允许目标固定为：

| 顺序号 | 证据角色 | 允许目标节点类型 |
| --- | --- | --- |
| 40 | 来源任务 | 任务 |
| 41 | 来源方法 | 方法 |
| 42 | 来源动作 | 方法；动作入口角色另由方法规范复核 |
| 43 | 来源状态 | 状态 |
| 44 | 来源动态 | 动态 |
| 45 | 自我取消后继决议来源 | 自我治理决议或其正式结构引用 |
| 46 | 动作停止证据 | 状态或动态 |

各角色是否必需由具体迁移边规定；每个要求非空的角色必须恰有一条有效关系。有效唯一键是“关系类型 15 + 完整源状态句柄 + 顺序号”：同源同角色不得出现第二条有效关系，同一目标可以合法承担不同角色。未知顺序号、错误目标类型、同角色重复或缺少该迁移边要求的角色必须在写前拒绝；前置通过后的结构异常属于内部逻辑错误。ARCH-L2 状态服务只形成通用状态事实，不解释业务结果；迁移证据由 ARCH-L4 provider 提交结构请求。

精确重复迁移必须从完整生命周期历史逐项复核前驱关系、目标阶段、发生时间和全部证据角色；同义重复读回既有迁移，不新增关系或推进版本，异义重复按冲突收口。不得用时间戳、生命周期版本、摘要、日志或普通布尔值单独裁决幂等。

## 9. 首个任务轮次的状态发布

R1 建立后，全局“任务主阶段 / 业务状态段”基础特征定义只建立一次，每个 E 建立唯一阶段特征实例。状态 owner 先建立并读回无动态首态`{筹办, 待初次筹办}`。task owner 随后建立并读回 P1；P1 只是首个筹办轮次、幂等重试和恢复锚点，绑定 T、R1、轮次序号、来源截止和生命周期，不证明“任务筹办需要发生”，也不建立独立治理动作调用事实。

manager fresh 读回首态与 P1 后，依据当前状态经任务状态正式提交入口迁移为`{筹办, 待找方法}`；状态 / 动态 owner 按各自通用合同保存状态变化。无需、也不得为此次迁移建立额外证明节点、调用事实、来源账或专用动作身份。各 owner 分别保留自身幂等、发布未知收敛和独立读回；未确认前不得进入下一状态。精确重复不得形成第二首态、第二 P1、第二后态或第二动态。

## ARCH-L2 状态唯一权威迁移说明（20260824）

本规范的任务状态枚举和阶段关系是 ARCH-L4 业务状态解释 / 迁移输入，现有任务治理状态事实保留为兼容历史。通用存在、特征、状态和动态的结构唯一权威属于 ARCH-L2；任务 owner 不得继续建立第二存在或状态服务。首态由状态 owner 单独建立后再独立设置中性当前选择且无动态；后继依次新增目标中性状态、以旧 / 新状态新增中性动态、替换中性当前选择并分别读回。ARCH-L4 只形成业务前提、调用顺序与外层组合互证，不调用旧 v2、创建任务专属低层 provider、要求同代持久化或声称原子回滚。本条不提前实现任务完成或目标裁决。
