## 1. 定位

本规范定义唯一自我消费现实世界树根的输入边界，以及自我内部世界成员、实例特征槽、状态 / 动态读取投影和普通退役原则。它不定义现实世界树根建立，不恢复旧完整自我发布闭包，也不在自我初始化中建立、扫描、猜测或补写根。

直接上级规范：1130、1140、1150。

直接依赖规范：0050、4010、4020、4030、4040、4200、4230、8120。

相关边界规范：1160、1170、4070、6120、6130、6180、6220、6230。

## 2. 现实世界树根输入与唯一自我分账

现实世界树根和自我是两个不同事实：

```text
现实世界树根 = R1 场景 owner 中的根标记、树归属和场景结构事实
唯一自我       = L5 之外自我业务的稳定存在身份及其后继正式结构
```

系统先按 8120 由 I1 建立或同请求收敛项目具名场景树根，并正式 `读取场景树` 发布调用方拥有的值式根材料。自我初始化只能在 I1 成功后消费该材料；I1 请求、幂等身份、返回值、普通应用保存值和自我消费结果都不是根事实。

自我根消费适配每次成功前必须经 A1 透明取得同一个 R1 场景服务，重新读取当前场景树结构登记，并以 I1 材料中的树身份正式 `读取场景树`。成功只在以下内容逐字段互证时成立：

1. 项目树选择、首次根建立请求、树身份、根场景和首次根标记与 I1 已发布材料一致；
2. 正式树读回的树身份等于根场景编码，根位于场景组，根标记端点、类别和首次建立生命周期不变；
3. 根无父，整树投影完整，读取类别为当前且事实截止非零；
4. 本轮材料全部来自同一次正式 R1 当前读取，不用旧截止、缓存或参数补齐。

任一不一致都不得进入自我形成、方法根、概念、投影、线程或宿主。A1 只透明提供原六服务，零根写、零自我写、零结果解释。

自我是项目唯一世界存在，由唯一稳定存在身份直接承载；不得从多个存在中按名称、配置、位置、顺序、线程、缓存、日志或 I1 根场景选择一个冒充自我。根场景本身不得兼任自我存在、概念或任何概念本体根。自我尚未由后继正式提供者建立时，根消费适配成功只证明世界输入可用，不证明自我已经存在或初始化完成。

## 3. 自我所在场景、内部世界与成员

自我所在场景、自我内部世界场景和自我存在必须使用各自正式 L2 结构身份，不得复用根场景、参数身份或缓存对象。三者的创建、关系和同树归属由后继具名自我形成合同冻结，并通过场景 / 存在唯一 owner 的正式公开服务完成；I2 根消费适配不创建这些对象。

后继自我形成至少必须满足：

- 自我所在场景和自我内部世界场景都属于 I2 本轮正式读回证明的同一现实世界树；
- 自我当前所在场景归属、自我持有内部世界以及内部世界成员分别由正式关系事实表达，不复制成数组、缓存或显示树；
- 自我不得成为自身内部世界成员，不得通过父子、成员或持有关系形成自包含环；
- 普通被观察存在可以按 6230 在需求成立后懒创建内部世界，但该规则不能替代唯一自我初始化合同。

后继实现固定拆成三个责任叶：存在服务先提供业务中性的单例角色结构，场景服务再提供业务中性的场景宿主存在关系，最后由 L5 之外真实自我形成提供者把一个项目固定角色解释为唯一自我并组合正式 L2 接口。存在单例角色关系是“角色登记锚点 -> 自我存在”；自我当前位置是“自我所在场景 -> 自我存在”的场景成员关系；内部世界持有是“自我内部世界场景 -> 自我存在”的场景宿主关系。后两条关系语义不同，必须分别存在且不得互相替代、反向或双写成第二权威。

真实自我形成使用同一现实世界树，固定拓扑为“根场景 -> 自我所在场景 -> 自我内部世界场景”。由于存在 owner 与场景 owner 不能组成跨 owner 原子写集，提供者必须按固定幂等步骤建立：原子建立角色化存在、建立所在场景、建立所在场景成员关系、建立内部世界场景、建立内部世界宿主关系。任一步已发布后失败不得回滚或换键重建；同请求重试逐步精确收敛。只有全部步骤完成并在一个共同当前事实截止下重新从存在角色、存在、场景树、成员和宿主正式读取互证，才能发布“真实自我已形成”值式材料。中间事实可以由其结构 owner 正常读取，但不得被启动、自我线程、概念或其它业务解释为自我形成成功。

任务执行的共同作用场景与“自我当前位置”分账。自我当前位置只证明自我存在是某场景的当前成员，不单独决定任务动作、作用主体或结果主体。目标合同、方法条件 / 动作适用合同、当前路径选择和执行绑定冻结材料必须共同冻结一次执行的唯一共同作用场景，并由场景 owner 在同一事实截止证明自我、各直接作用主体和各预计结果主体都是该场景的当前成员。控制室、车间与自我在该观察分辨率下可以是同一场景中的三个存在；自我改变控制室特征并经正式因果链影响车间状态时，控制室是直接作用主体、车间是间接结果主体，二者都不是第二动作场景。不得从自我当前位置、首动作、缺省值、对象名称、公共祖先或场景成员缓存补造共同作用场景，也不得以自我成员关系补造直接或间接结果事实。

当前唯一自我普通不可退役。真实自我提供者不恢复旧关系 21、自我结构登记服务、旧完整自我 DTO / 五身份五关系写集、资格属性或世界根内部世界场景；这些历史结构不能参与收敛或正式读回。

旧“基础信息身份世界根 + 世界根内部世界场景 + 自我所在场景 + 自我存在 + 自我内部世界场景”的五身份、五固定关系和一次全新系统角色发布写集退出现行授权。不得恢复旧 `完整自我发布请求`、`完整自我当前事实`、世界登记输入、固定本地键 1—14、旧关系 0 / 1 / 21 组合器或其兼容壳。未来自我形成必须按最终 R1 / A1 / L2 ABI 另立提供者设计和计划。

## 4. 自我实例特征槽

自我直接拥有的实例特征槽表示自我存在到槽位的正式宿主归属。每个有效槽位必须具备到抽象特征定义的唯一关系；已设置当前值时，还必须由唯一当前属性槽指向一个稳定值事实，统一服从 4110 和最终 L2 特征服务合同。

不得在自我节点、根消费材料或自我消费结果中建立槽位数组、当前值表或普通子节点列表。所谓“自我特征列表”只能由正式宿主归属和当前值事实形成值式读取投影；投影清空、裁剪或重建不得改变机器事实。

## 5. 自我状态与动态读取投影

自我状态读取投影只由正式状态结构中主体指向唯一自我存在的当前 / 历史事实形成；自我动态读取投影只由正式动态结构中被改变目标或主体指向唯一自我的事实形成。每项还必须符合 1160、1170、4020、4210 和 4220 的场景、特征、值、来源、时间和生命周期合同。

两类投影都不是普通子节点数组、根事实或第二权威列表，不得被外部调用方反向写入。当前投影可以裁剪可见引用，但历史状态、动态和退出事实不得因此删除。

## 6. 根消费适配合同

### 6.1 输入与调用者

I2 使用版本化值式 `自我世界树根消费请求`。请求只携带从 I1 成功结果逐字段复制的项目树选择、首次根建立请求、树身份、根场景和首次根标记；不携带 owner、写端口、锁、仓库、缓存、SQL、恢复材料、自我身份、成员、概念或需求。

正式生产调用者唯一为 `运行普通程序`：它在同一次 I1 成功结果上形成 I2 请求并立即调用根消费适配。生产外验证者可以直接构造合法 / 非法值式请求验证公开合同，但不得取得生产私有写面。

正式调用方只从同一次 I1 成功结果的 `已发布根` 逐字段形成请求；I2 不读取普通应用的 I1 getter，也不持有 I1 引用。请求只用于约束本次消费目标。完整请求值式相同才是同参数；已发布后异参数固定冲突，不改写既有材料，也不选择第二棵树。任何请求字段、结果字段或上下文副本都不得成为根身份来源。

### 6.2 正式再读回与发布

每次合法消费按固定顺序执行：

```text
调用方从同一次 I1 成功结果形成值式请求
-> I2 核对请求内在不变量
-> 经 A1 取得同一个 R1 场景服务
-> 正式读取当前场景树结构登记
-> 正式读取请求树
-> 逐字段验证根与整树
-> 局部完整形成值式自我根消费材料
-> 无抛出交换发布到普通应用上下文
```

首次成功返回 `已发布`；同请求重复仍执行本轮两次正式 R1 读取，成功后返回 `精确重复` 并刷新值式材料。重复不是缓存命中。异请求在 R1 调用前返回冲突。失败不得清空或半更新既有发布值；R1 事实不因 I2 失败撤销。

I2 对 R1、A1 和六服务零写，对自我、场景、存在、特征、状态、动态、因果、需求、方法和概念零写。它不持有服务所有权，不返回内部引用，不让上下文析构退出根。

### 6.3 并发、生命周期和异常

I2 适配器用独立发布锁保护请求选择和值式材料。正式调用方在进入 I2 前已经持有 I1 成功结果的局部副本；I2 不调用 I1 getter、不取得 I1 私有锁，也不持有 I1 引用，因而不存在 I1 / I2 双锁。I1 与 I2 的生产调用顺序由 8120 串行固定。

同一上下文并发同请求由 I2 锁串行，每次实际进入者仍正式再读回；异请求在已发布选择存在时冲突。锁、线程号和调用顺序不是机器事实或幂等身份。

值式材料生命周期不超过普通应用上下文，根事实生命周期仍由 R1 owner 管理。分配失败映射资源失败，其它异常映射内部不一致；发布必须采用局部完整构造和不抛出交换，异常时保留旧发布值。

## 7. 启动短路与后继自我形成门禁

I1 未成功时不得调用 I2。I1 成功后调用 I2：

- I2 失败按 8120 的 `自我世界树根消费 = 16` 短路；
- I2 成功证明根消费适配完成，删除 I1 引入的临时 `自我初始化待适配 = 15` 枚举和无条件短路，但数值 15 永久不复用；
- 在真实自我形成提供者尚未实现并正式接线的基线上，I2 叶必须随后以 `自我初始化能力未实现 = 17` 结构化短路；不得进入方法根、自我线程、概念、投影、信号或宿主；
- 只有后继自我形成计划实现、验证并正式接通后，才能把阶段 17 改为真实形成失败，并在 SELF-FORM 成功时仅开放阶段 18 的控制门。I2 与真实自我值式材料不成为阶段 18 四本体根请求内容，保留给阶段 18 之后的自我线程等具名后继。

阶段 15 退役只证明旧世界根输入已由 I2 适配，不证明自我已建立。在真实 provider 尚未接线的基线上，阶段 17 是能力缺口；接线后阶段 17 是 SELF-FORM 真实失败。两种情况下都不得以空 provider、固定成功、旧完整自我结果、缓存或历史记录解除。

## 8. 恢复、旧字段与兼容边界

I2 不提供跨进程恢复。进程结束后 I1 / I2 值式材料随上下文消失；新进程必须按 8120 重新由 I1 形成当前运行期根，再由 I2 正式再读回。SQL、材料目录、历史临时构建目录、历史验证输出和旧上下文快照不得回填。

以下旧输入和字段保持物理退役，不提供兼容转换：

```text
世界结构登记 / 世界根场景 / 基础信息身份世界根
完整自我发布请求 / 完整自我当前事实 / 完整自我结果
世界根内部世界场景及其旧标记、父子、成员字段
旧世界树初始化结果或自我线程世界树快照
固定本地键、旧世界登记服务、旧完整自我准入 / 发布 / 组合入口
```

若历史调用者仍引用这些类型或字段，实施必须具名拒绝或删除调用，不得新增别名、适配构造、双写、扫描迁移或“先旧后新”回退。未来跨进程恢复必须先由 4070 路线把合法 R1 owner / 根事实发布成新的内存代次，再由独立恢复适配调用 I2；不得恢复 I2 值式缓存本身。

## 9. 读取、退役与验证

后继完整自我聚合读取必须从正式自我存在、所在场景、内部世界、成员、实例槽、状态和动态服务形成调用方拥有的值式投影，并在同一声明的一致性边界内拒绝漂移或部分材料。I2 根消费材料只作为其世界范围输入，不替代这些事实的正式读取。

当前唯一自我不得普通退役。未来历史自我退役必须另有具名授权、引用闭包、事务和读回合同；I2 不冻结或恢复旧关系 21 历史谱系退役实现。

I2 专项验证至少覆盖：

1. 无 I1 发布值、请求无效、请求与 I1 不变量不一致均在 R1 写前失败；
2. 首次消费必须完成当前登记读取和正式整树读取后才发布；
3. 同请求重复每次重新正式读取，异请求零 R1 调用且不覆盖旧值；
4. 根身份、根标记、首次生命周期、无父或树完整性漂移整体失败；
5. 发布材料为值式副本，修改调用方副本不改变上下文或 R1；
6. A1 getter、普通应用直接场景 getter、I1 和 I2 使用同一 R1 服务实例，A1 / I2 零写；
7. 并发同请求串行收敛，异请求冲突，不死锁、不半发布；
8. I1 失败不调用 I2；I2 失败映射阶段 16；provider 未接线时 I2 成功固定映射阶段 17；provider 接线后 SELF-FORM 失败映射阶段 17、成功只开放阶段 18 控制门；阶段 15 永久缺号，任一失败路都不进入后继初始化或宿主；
9. 扫描确认旧世界登记、旧完整自我 DTO / 模块、基础信息世界根、缓存、SQL 和恢复入口未恢复；
10. 根正式读回通过不升级为自我存在、自我初始化或完整系统闭环通过。
