# 4040 子规范 SQL 事实事务、幂等与唯一提交发布

编号：4040
日期：20260731
状态：正式子规范

直接上级规范：0050。

直接依赖规范：4010—4030。

相关边界规范：4050、4070。

## 1. 定位

本规范规定一次事实写集的准备、SQL 事务、幂等、并发、未知提交和发布后读回。原文件名为兼容引用保留；内存候选确认 / 撤销、运行期域身份、锁释放或上下文切换不再是发布点。

## 2. 写集

完整写集包括当前业务意图需要共同成立的全部身份、类型化值、关系、旧当前退出、新版本、材料引用和发布证据。写集必须在事务前冻结为不可变请求语义，不得在事务中临时补默认字段。

## 3. 材料准备

独立材料文件可以在 SQL 事务前写入临时位置并完成格式、长度和摘要校验。准备成功只产生未被引用材料，不产生业务事实；事务拒绝或失败后按回收合同处理。

## 4. 写前拒绝

身份、类型合同、业务授权、版本、幂等语义、关系端点和材料完整性等可判定条件必须在第一笔 SQL 业务写入前拒绝。拒绝保证零业务写入、零当前性变化和零发布证据。

## 5. SQL 事务与发布

1. 一次事实写集在一个 SQL 事务中完成。
2. 事务内先写候选记录和关系，再闭合版本、旧当前退出、新当前和发布证据。
3. SQL 提交是唯一事实线性化点。提交前普通查询不可见，提交后不得用内存撤销伪装回滚。
4. 提交后必须按原稳定身份和幂等身份读回；不一致属于内部不一致。

## 6. 幂等

1. 每个写请求具有稳定幂等身份和完整语义摘要。
2. 同键同义返回原已发布结果，不推进版本、不重复引用材料。
3. 同键异义返回冲突，不能选择旧成功或覆盖当前事实。
4. “记录存在”“摘要碰撞”“名称相同”或“结果看起来相同”都不足以证明同义。

## 7. 并发与未知提交

1. 预期版本和唯一约束在 SQL 事务内最终复核；失败返回版本或并发冲突。
2. 同义竞争至多提交一次，其余回读同一结果；异义竞争至多一个合法提交，其余冲突。
3. 网络或进程异常导致提交结果未知时，只能使用原幂等身份回读收敛。未证明未提交前不得生成新身份、重放异义请求或删除材料。

## 8. 分支矩阵

| 分支 | SQL 事实 | 材料 | 后继 |
| --- | --- | --- | --- |
| 写前拒绝 | 不变 | 未引用候选可回收 | 修正请求 |
| 精确重复 | 原事实不变 | 不重复写 | 返回原结果 |
| 事务失败 / 回滚 | 不变 | 按回收合同 | 可重试或失败 |
| 提交成功 | 原子可见 | 由 SQL 引用成为事实材料 | 读回 |
| 提交未知 | 未裁决 | 保留 | 原幂等身份回读 |
| 提交后读回矛盾 | 可能已发布 | 保留 | 审计 / 恢复 |
