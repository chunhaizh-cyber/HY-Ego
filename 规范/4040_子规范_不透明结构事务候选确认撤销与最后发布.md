# 4040 子规范 内存事实事务、幂等与原子代次发布

编号：4040
日期：20260812
状态：正式子规范

直接上级规范：0050。

直接依赖规范：4010—4030。

相关边界规范：4050、4070。

## 1. 定位

本规范规定一次业务中性运行期事实写集的候选准备、内部参与者确认、逆序撤销、内存代次原子发布、最小幂等、并发和发布后读回。持久证据与恢复是可分离管理能力，不是普通 CRUD 固定参与者。原文件名为兼容引用保留；SQL 提交、材料写入、锁释放或普通函数返回均不是运行期事实发布点。

## 2. 写集

完整中性写集只包括需要共同成立的节点、关系、值、属性槽和旧当前退出项。独立材料引用仅作为值材料中的稳定编码，不赋予 L1 解释材料内容的职责。业务意图、操作标签、资格、领域参与者、领域结果见证、执行证据和持久发布证据不属于普通 L1 写集。写集必须在事务前冻结，不得在事务中临时补默认字段。

owner-scoped v2 写集仍只有上述五类普通写项；请求不得携带 owner。owner 由精确实例绑定的 `L1所有者范围写端口` 隐式注入。owner 建立 / 退出是签发管理面的具名事务，不得伪装成普通节点新建或退出项。

## 3. 材料准备

独立材料文件或 SQL 持久记录可以在内存代次发布前形成候选并完成格式、长度、摘要和类型校验。准备成功只产生未被当前权威引用的恢复材料，不产生运行期业务事实；事务拒绝或失败后按回收合同处理。

## 4. 写前拒绝

编码占用、节点 / 属性类型、期望事实代次、幂等语义、属性槽 / 关系端点和中性材料形状等可判定条件必须在第一笔内存候选写入前拒绝。业务授权和资格由 L5 之外业务层裁决，不得由 L1 操作标签白名单补判。owner-scoped 写还必须在取得事务域独占许可后、第一笔候选前针对同一代次复核：端口属于本 L1 实例且有效、owner 当前、关系类型 owner、所属节点 / 属性类型 / 新值 owner、退出事实 owner 及活动端口唯一性。任一失败零候选、零代次推进。

## 5. 内存事实事务与发布

1. 一次事实写集在一个内存事实事务中完成，事务域取得独占许可；L1 内部仓库参与者管理锁，上层不得接触锁、许可、会话或候选。
2. 事务内只形成 owner 管理事实或节点、关系、值、属性槽和退出项的中性候选，按确定登记顺序完成准备与完整候选读回，再按确定顺序确认待发布；任一失败按依赖逆序撤销全部已准备的 L1 内部参与者。上层服务或回调不得作为 L1 事务参与者。owner 与数据事实共用同一仓库参与者、候选 / 确认 / 撤销和最后发布点，不建立旁路 owner 表提交。
3. 全部参与者确认后，在同一最后发布区关闭撤销能力并原子切换到新的内存已发布代次。该切换是唯一运行期事实线性化点；发布前普通查询不可见，发布后不得用撤销、SQL 旧行或材料覆盖伪装回滚。
4. 发布后必须按原稳定身份、幂等身份和代次见证从内存权威读回；不一致属于内部不一致。
5. 线程队列私有锁只保护队列，不得在持有队列锁时执行完整结构事务；事务域许可和内部仓库锁顺序必须由实现合同唯一冻结。

## 6. 幂等

1. 每个普通写请求具有调用方给出的非零不透明稳定幂等键；L1 不从业务字段、名称、标签或领域结果推导该键。
2. 同键且规范化完整中性写集逐字段相同返回原已发布结果，不推进事实代次、不重复引用材料。
3. 同键而规范化完整中性写集不同返回冲突，不能选择旧成功或覆盖当前事实。
4. 内部摘要只可作查找优化；摘要碰撞后必须比较完整写集。“记录存在”“名称相同”或“结果看起来相同”都不足以证明同义。

owner-scoped 普通写的规范化幂等身份是 `(L1实例内部身份, owner稳定身份, L1所有者范围写入幂等身份)`。同 owner 同键同完整写集返回首次结果；同 owner 同键异写集冲突；不同 owner 的相同数值键互不复用。端口、租约、nonce 和地址不进入幂等语义，因而恢复后同 owner 新合法端口可以用原请求收敛未知发布。v1 幂等账保持原身份域，与 v2 不碰撞或互返精确重复。

owner 建立另有独立幂等域。同一实例签发器同键同义返回同一 owner 事实；已有活动端口时许可拒绝且不交付第二端口；同键异义冲突。owner 退出要求端口已失效、该 owner 当前事实归零、当前幂等提交已收敛且恢复 / 审计引用闭合，退出与历史保留在同一事实事务。

## 7. 并发与未知提交

1. 期望事实代次、编码永久占用和唯一约束必须在取得内存事务域独占许可后、第一笔候选写入前针对同一已发布代次最终复核；失败返回事实代次漂移、幂等冲突或内部不一致，并保证零普通可读写入。SQL 只保存持久证据，不参与本次运行期裁决。
2. 同义竞争至多提交一次，其余回读同一结果；异义竞争至多一个合法提交，其余冲突。
3. 进程或内部异常导致内存代次发布结果未知时，只能使用原幂等身份、owner 域和发布见证回读收敛。未证明未发布前不得生成新身份、换 owner、重放异义请求或删除材料。

## 8. 持久证据顺序与状态

本节只约束选择启用持久证据或恢复能力的具名管理合同，不要求普通 CRUD 固定准备、写入或返回持久证据。未启用管理策略时普通 CRUD 的持久证据状态为不适用，不得因此触发 SQL、文件、日志或全仓扫描。

1. 每类事实必须由详细合同冻结持久证据是在内存发布前准备、发布后追写，还是通过可证明一致的日志 / 快照协议衔接；任何策略都不得形成 SQL 对运行期事实的第二裁决权。
2. 持久证据至少区分 `已与内存代次一致`、`待持久化`、`持久化结果未知`、`持久证据落后`、`持久证据损坏` 和 `不适用`。具名状态必须绑定内存代次、请求 / 幂等身份和可重试后继。
3. SQL 成功只能证明对应持久证据已保存，不能证明内存事实发布成功；SQL 失败也不得静默撤销、覆盖或降级读取已发布内存事实。
4. 若业务合同要求“无可验证持久证据不得继续发布”，必须在发布前具名拒绝或停止后继；不得在发布后把 SQL 失败伪装成业务事实未发生。
5. 崩溃窗口必须由 4070 的恢复协议收敛：恢复材料与发布证据不能证明一个完整代次时整批拒绝或隔离，不得拼接半结构。
6. 写前持久准备已经成立、但内存候选或确认随后失败时，只有全部参与者完成逆序撤销且持久端明确写入“本次尝试未发布”见证后，才可释放事务域并允许后继重试；未发布见证失败或结果未知时必须隔离。恢复可忽略已验证未发布尝试的业务材料但必须保留审计，不得把仍为已准备或结果未知的尝试当作未发布。

## 9. 分支矩阵

| 分支 | 内存运行期事实 | SQL / 材料 | 后继 |
| --- | --- | --- | --- |
| 写前拒绝 | 不变 | 未引用候选可回收 | 修正请求 |
| owner / 端口许可拒绝 | 不变；零候选 | 不产生能力材料 | 经合法签发 / 重入路径修正 |
| 精确重复 | 原事实不变 | 不重复持久化或回读原状态 | 返回原结果 |
| 候选 / 确认失败 | 不变；逆序撤销 | 按回收合同 | 可重试或失败 |
| 内存代次发布成功 | 新代次原子可见 | 记录具名持久证据状态 | 内存权威读回 |
| 内存发布未知 | 未裁决 | 保留 | 原幂等身份和发布见证回读 |
| 持久化失败 / 未知 | 已发布代次不被静默改写 | 保留并标记状态 | 按持久策略重试、降级或停止后继 |
| 发布后读回矛盾 | 可能已发布 | 保留 | 审计 / 恢复 |

## 8. 20260827 分区事务与实例材料清理

本节取代前文候选前“许可复核”与 owner 权限解释。

1. 事务不复核业务权限；L1 候选只验证合同、代次、幂等、类型、槽、端点、内部结构分区、引用闭包和资源。
2. owner 只作内部幂等命名空间。端口异常映射 `内部不一致`，结构分区不一致映射 `引用冲突`，事务锁或资源暂不可用映射 `资源失败`；旧 `许可拒绝` 不再产生。
3. 状态创建事务不得包含新动态；动态创建事务的成员状态必须事前正式存在并读回。
4. 实例材料清理原子退出动态及其关系、当前选择、孤立状态，并同代建立墓碑与紧凑幂等记录；任一闭包失败整笔零变化。
5. 清理发布后的未知读回只能用原键读取墓碑收敛，不得恢复完整载荷或生成第二身份。
