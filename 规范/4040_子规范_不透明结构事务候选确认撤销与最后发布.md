# 4040 子规范 内存事实事务、幂等与原子代次发布

编号：4040
日期：20260802
状态：正式子规范

直接上级规范：0050。

直接依赖规范：4010—4030。

相关边界规范：4050、4070。

## 1. 定位

本规范规定一次运行期事实写集的候选准备、参与者确认、逆序撤销、内存代次原子发布、幂等、并发、持久证据状态和发布后读回。原文件名为兼容引用保留；SQL 提交、材料写入、锁释放或普通函数返回均不是运行期事实发布点。

## 2. 写集

完整写集包括当前业务意图需要共同成立的全部身份、类型化值、关系、旧当前退出、新版本、材料引用和发布证据。写集必须在事务前冻结为不可变请求语义，不得在事务中临时补默认字段。

## 3. 材料准备

独立材料文件或 SQL 持久记录可以在内存代次发布前形成候选并完成格式、长度、摘要和版本校验。准备成功只产生未被当前权威引用的恢复材料，不产生运行期业务事实；事务拒绝或失败后按回收合同处理。

## 4. 写前拒绝

身份、类型合同、业务授权、版本、幂等语义、关系端点和材料完整性等可判定条件必须在第一笔内存候选写入前拒绝。拒绝保证零普通业务可读写入、零当前性变化和零运行期发布证据。

## 5. 内存事实事务与发布

1. 一次事实写集在一个内存事实事务中完成，事务域取得独占许可；仓库和领域参与者内部管理锁，上层不得接触锁、许可或会话。
2. 事务内先形成结构和领域类型化记录候选，按确定登记顺序完成准备与完整候选读回，再按确定顺序确认待发布；任一失败按依赖逆序撤销全部已准备参与者和结构写集。
3. 全部参与者确认后，在同一最后发布区关闭撤销能力并原子切换到新的内存已发布代次。该切换是唯一运行期事实线性化点；发布前普通查询不可见，发布后不得用撤销、SQL 旧行或材料覆盖伪装回滚。
4. 发布后必须按原稳定身份、幂等身份和代次见证从内存权威读回；不一致属于内部不一致。
5. 线程队列私有锁只保护队列，不得在持有队列锁时执行完整结构事务；事务域许可和内部仓库锁顺序必须由实现合同唯一冻结。

## 6. 幂等

1. 每个写请求具有稳定幂等身份和完整语义摘要。
2. 同键同义返回原已发布结果，不推进版本、不重复引用材料。
3. 同键异义返回冲突，不能选择旧成功或覆盖当前事实。
4. “记录存在”“摘要碰撞”“名称相同”或“结果看起来相同”都不足以证明同义。

## 7. 并发与未知提交

1. 预期版本、身份永久占用和唯一约束必须在取得内存事务域独占许可后、第一笔候选写入前针对同一已发布代次最终复核；失败返回版本漂移、幂等冲突或内部不一致，并保证零普通可读写入。SQL 只保存持久证据，不参与本次运行期裁决。
2. 同义竞争至多提交一次，其余回读同一结果；异义竞争至多一个合法提交，其余冲突。
3. 进程或内部异常导致内存代次发布结果未知时，只能使用原幂等身份和发布见证回读收敛。未证明未发布前不得生成新身份、重放异义请求或删除材料。

## 8. 持久证据顺序与状态

1. 每类事实必须由详细合同冻结持久证据是在内存发布前准备、发布后追写，还是通过可证明一致的日志 / 快照协议衔接；任何策略都不得形成 SQL 对运行期事实的第二裁决权。
2. 持久证据至少区分 `已与内存代次一致`、`待持久化`、`持久化结果未知`、`持久证据落后`、`持久证据损坏` 和 `不适用`。具名状态必须绑定内存代次、请求 / 幂等身份和可重试后继。
3. SQL 成功只能证明对应持久证据已保存，不能证明内存事实发布成功；SQL 失败也不得静默撤销、覆盖或降级读取已发布内存事实。
4. 若业务合同要求“无可验证持久证据不得继续发布”，必须在发布前具名拒绝或停止后继；不得在发布后把 SQL 失败伪装成业务事实未发生。
5. 崩溃窗口必须由 4070 的恢复协议收敛：恢复材料与发布证据不能证明一个完整代次时整批拒绝或隔离，不得拼接半结构。

## 9. 分支矩阵

| 分支 | 内存运行期事实 | SQL / 材料 | 后继 |
| --- | --- | --- | --- |
| 写前拒绝 | 不变 | 未引用候选可回收 | 修正请求 |
| 精确重复 | 原事实不变 | 不重复持久化或回读原状态 | 返回原结果 |
| 候选 / 确认失败 | 不变；逆序撤销 | 按回收合同 | 可重试或失败 |
| 内存代次发布成功 | 新代次原子可见 | 记录具名持久证据状态 | 内存权威读回 |
| 内存发布未知 | 未裁决 | 保留 | 原幂等身份和发布见证回读 |
| 持久化失败 / 未知 | 已发布代次不被静默改写 | 保留并标记状态 | 按持久策略重试、降级或停止后继 |
| 发布后读回矛盾 | 可能已发布 | 保留 | 审计 / 恢复 |
