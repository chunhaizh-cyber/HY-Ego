## 1. 本轮统一裁决

本轮固定以下新口径：

```text
需求节点
    = 某个存在的一个确定目标契约

需求树
    = 目标分解与来源上下文的唯一权威树

需求列表
    = 按精确目标聚合需求树中分散节点的正式聚合结构
    = 权重查询入口
    = 任务查询入口
    = 保存对应需求树节点成员集合

任务
    = 对一个需求列表项所代表的确定目标组织一次有身份活动

任务方法路径
    = 同一目标在当前筹办轮次可选择的 0..N 条达成路径

当前实例方法
    = 一轮执行实际选择的唯一具体执行快照

任务虚拟存在
    = 任务运行状态的唯一承载体
```

## 2. 双态一体

需求信息不是两套事实，而是同一批需求节点的两种正式组织状态：

```text
需求树态：
    保留父子分解、来源、路径、权重和上下文

需求列表态：
    按 所属存在 + 目标宿主 + 目标特征 + 目标状态合同 精确聚合
    保存成员需求节点集合
    作为权重和任务查询入口
```

列表项不删除、覆盖或合并树节点。树节点仍分别保留自己的路径、权重、授权、预算、来源和结算身份。

## 3. 任务承接模型

旧：

```text
多个等价需求 -> 直接共同授权任务
```

新：

```text
D1 ─┐
D2 ─┼─> 需求列表项 L -> 当前任务 T
D3 ─┘
```

任务核心不复制目标。任务目标由列表项的精确聚合目标确定，并可追溯到全部成员需求。

## 4. 权重模型

需求列表项是权重查询入口，但不保存一个不可审计的“总权重”作为第二权威。

```text
列表项
-> 当前成员需求集合
-> 各成员路径 / 当前性 / 权重 / 授权 / 预算
-> 业务层形成当前权重与权限投影
```

聚合结果必须保留成员来源明细。

## 5. 方法路径与目标分解

```text
同一目标多个方法
    -> 任务方法路径集合
    -> 不生成需求

独立前置目标
    -> 子需求
    -> 进入需求树
    -> 子需求经列表聚合后取得自己的任务
```
