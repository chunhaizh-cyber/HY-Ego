# 5090 子规范 需求、任务、方法运行闭环与独立结果回读

直接依赖规范：3100、3200、3300、4050、4190。

相关边界规范：5100—5340、6100—6180、8100、8200、8210。

## 1. 定位

本规范承接海鱼 3020 已确认的需求—任务—方法运行闭环，统一裁决三类对象的身份分离、线程责任、筹办 / 执行节奏、独立结果回读、学习快照和生命周期顺序。

## 2. 总闭环

```text
自我读取当前事实并确认需求
-> 自我维护需求和需求权重
-> 已确认需求通过稳定引用交给任务管理
-> 同一有效需求复用唯一任务树
-> 任务管理创建或查找任务、计算优先级并派发
-> 一个筹办回合实例化最多三个可能达成目标的方法
-> 一轮任务执行只运行一个实例方法
-> 方法只声明预期变化
-> 通过独立领域读取取得实际当前值
-> 形成本轮实例方法树、结果材料和因果证据
-> 按实际事实裁决成功、失败、继续、改选或重新筹办
-> 学习旁路只读消费快照并形成抽象方法新版本
-> 结果返回自我重新确认需求
```

## 3. 需求责任

1. 只有自我可以形成和确认需求；场景、世界、任务、方法、日志和异常不能自行建立需求。
2. 自我线程负责复核合法差距、更新权重并派发已确认需求。
3. 上级需求权重平均分给当前有效直接子需求；精确维度、舍入和无有效子需求分支仍待子规范裁决。
4. 条件不足、无可达方法、执行异常或其它缺口只能返回结构化事实。是否形成准备、学习、结构补齐或实现修复需求由自我后续裁决。
5. 暂时满足、失效、恢复有效和永久退役分离：前两者保留身份和历史；恢复复用原需求及任务树；永久退役先任务树后需求。

## 4. 任务责任

1. 需求树、任务树和方法列表是独立结构。任务首节点保存来源需求稳定引用，需求节点不是任务树根。
2. 同一有效来源需求只能有一个当前任务树；重复派发必须复用，不得建立平行任务根。
3. 任务管理负责创建 / 查找任务、读取状态、计算和更新优先级、派发筹办或执行。
4. 优先级只影响尚未派发工作的顺序，不抢占或中断已运行工作。每次派发前重新计算，结果未变时不得写入假更新。
5. 不同任务可以并行；同一任务同一时刻最多一个工作线程。筹办、重筹办和执行不得并发修改同一任务。
6. 每个实例方法执行并形成结果后，本轮工作结束并归还调度权，再由任务管理重新判断。
7. 筹办和任务执行是治理内建动作，不进入统一方法列表、不拥有方法虚拟存在，也不成为任务候选方法。

## 5. 方法、筹办和实例化

1. 内部方法与外部方法进入同一方法列表，但一个代码方法功能单一，只能属于一种直接作用类别。
2. 复杂方法可以组合多个内部 / 外部方法，并保存正式组成、条件、结果、版本和终止条件。
3. 一个筹办回合最多实例化三个可能达成目标的方法；候选不足可以少于三个，不得补造。
4. 实例方法是本任务、本回合对抽象方法版本的不可变快照。抽象方法后续换代不修改已实例化方法。
5. 一轮执行只运行一个实例方法；方法的函数返回只证明调用结果，不证明目标状态已经实际发生。

## 6. 结果和独立回读

1. 实际结果必须通过与方法自报分离的领域读取路径，取得目标特征当前值、版本、场景和事实截止。
2. 每轮必须保存预期输入 / 输出、实际回读、比较结果、执行证据和因果材料；结果节点不得承担任务完成、需求满足或价值结算的第二权威状态。
3. 任务只按实际当前事实裁决方向和进度。未知、漂移、损坏或不可比较必须保持具名结果，不能默认成功或失败。
4. 方法执行成功、日志成功、预期输出匹配或子步骤完成都不能单独证明任务完成。

## 7. 学习和版本

1. 学习旁路只读消费实例方法树和结果材料，不阻塞、不恢复、不修改运行中任务树。
2. 学习按条件—结果材料形成抽象方法新版本；运行中任务继续使用既有实例快照，新版本只供后继筹办回合选择。
3. 单次异常或单次未达预期不自动建立学习需求。原因、重复程度和可能原因模拟的精确准入仍待后续规范。
4. 退出当前执行集合的实例方法树进入独立待学习历史区域，直到保留与删除合同允许回收。

## 8. 禁止绕过

- 自我不得把需求直接交给世界结构执行。
- 任务管理不得绕过筹办 / 执行直接伪造任务状态。
- 任务或方法不得直接修改需求满足状态。
- 方法不得以返回值、日志、预期值或缓存命中冒充实际结果。
- 学习不得反向改写已实例化方法或运行中任务。
- 名称、列表位置、缓存键和函数地址不得替代需求、任务、方法及其版本身份。

## 9. 未决门禁

需求权重完整算法、任务状态全集、条件满足度、多个实例的实时选择、超时 / 预算、结果未知的最终终止、复杂方法循环终止、学习分流和历史保留期继续由相邻规范裁决。
