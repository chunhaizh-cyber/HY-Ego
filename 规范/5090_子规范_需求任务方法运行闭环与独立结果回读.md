## 1. 定位

本规范是需求、任务、方法运行闭环及独立结果回读的总规范。它只裁决各对象如何沿当前公开结构和结果合同衔接，不把需求树、任务、方法、实际结果、需求结算或学习分析合并成一个对象。

本规范采用的现行主链为：

```text
具体需求 D
-> 所属需求列表项 L（同类任务查询 / 防重锚点）
-> 唯一活动任务
-> T→D 正式承接关系
-> 当前任务轮次 / 筹办轮次
-> manager 按状态多次派发筹办：先完整找方法，再完整查条件
-> 每次筹办补全 task owner 信息并发送唯一消息，manager 独立读回后推进状态
-> 执行前选择形成唯一当前路径、实例方法和冻结
-> 作用范围分流；含现实改变时取得一份自我现实执行授权
-> 正式任务实际结果
-> 收束本任务轮次
-> 有唯一轮次级发起调用时返回并结算该上级调用槽；根任务无调用槽
-> 其它需求 / 任务在实际使用时 fresh 复核自己的目标或条件
-> 自我后继决议
```

这条主链中的每个箭头都是稳定身份、公开读取和共同事实截止上的结构引用。任何聊天、日志、缓存、函数返回值或旧任务树投影都不能替代这些事实。

本规范只裁决总运行链；对象字段和专用接口仍由 4250、4260、5250、5160 等相邻规范承接。相邻规范或旧设计材料中仍出现的需求树直接派发、列表成员即来源主链、能力缺口节点、多条当前路径或旧结果结算边界，均属于待同步历史文字，不得反向恢复本规范已经删除的主链。

## 2. 对象职责和主链

### 2.1 具体需求是任务承接与目标权威入口

1. 需求树负责目标分解、父子位置和需求生命周期；需求列表负责按精确目标聚合当前需求成员。
2. 每次任务承接输入必须携带一个当前具体需求 D。任务管理先读取 D 所属列表项 L，再以 L 作为同类任务查询 / 防重锚点查询 0..1 个当前任务；L 不是任务目标或来源集合。
3. 无当前任务时，由 task owner 原子建立 T、唯一任务虚拟存在 Vt、`T→L`、`T→D` 和首个任务轮次 R1；已有任务时机械验证其查询锚点及既有来源目标与 D 相同，再幂等新增 `T→D`。Vt 是任务特征、状态和迁移记录的唯一宿主，不是世界存在；列表项其它成员不得自动成为任务来源。
4. 任务不得复制目标宿主、目标特征、目标状态合同或需求事实。任务目标只从当前 `T→D` 关系组中的具体需求逐项互证；筹办、调度和执行只冻结本轮实际消费的关系、需求版本和共同事实截止。
5. 方法 / 条件缺失等筹办材料不能直接扩张需求树。self fresh 读取后独立产生并确认必要、父域合法且可最终判定的后继需求目标；task owner 只形成正式任务子目标承接记录，需求 owner 只消费该记录发布或复用合法子需求及其列表项。

### 2.2 唯一活动任务

1. 对同一当前查询锚点，当前最多存在一个活动任务。后续同目标具体需求必须读取并复用该任务、显式新增来源关系，不得建立平行任务或第二任务树。允许的父子信息只是一条轮次级、不可变、唯一发起者调用关系，不表达目标分解、任务所有权或永久父子层级。
2. 任务负责承载一次目标活动的身份、来源需求承接关系、任务轮次、筹办轮次、执行轮次、调度状态、当前路径引用和当前实例方法引用；它不负责复制需求事实、保存需求树关系或代写需求 / 价值 owner 的结算事实。
3. 同一任务同一时刻最多一个工作线程。各次筹办、排队和执行不得并发写同一任务；不同任务可以并行。
4. 优先级只影响尚未派发工作的顺序。每次派发前重新计算，值未变不得写入假更新；已运行工作不因优先级变化被抢占或伪造中断。
5. 当前任务退出、恢复和历史读取必须保留任务身份及正式事实截止；退出不级联删除需求列表项、需求成员或历史实际结果。

### 2.3 唯一当前活动方法路径

1. 一个筹办轮次可以产生零个、一个或多个候选方法，但候选集只是召回和就绪复判输入，不是当前活动路径。
2. 筹办不形成当前活动方法路径。任务信息完成后，执行前选择至多形成一条当前活动方法路径；未选候选、历史路径和替代路径不得并列标记为当前路径，也不得同时执行。
3. 当前路径必须绑定任务、筹办轮次、被选方法、方法内容版本和就绪合同。路径换代保留旧路径历史，不能原地改写已发布路径。
4. 目标当前未完成时，筹办先在有界范围内完整查找方法；完整且有候选后，再逐候选查找和核验全部条件组。适用性、实际采用和总代价比较均留到执行前。方法 / 条件缺失只作当前父任务材料，是否形成后继需求必须另经 self 确认和需求领域写入。
5. 方法名称、动作名称、函数名、标签和固定编号只能作为非权威辅助索引，不得参与语义命中或替代方法身份。

### 2.4 实例方法

1. 实例方法是本任务、本筹办轮次对一个抽象方法及其内容版本、输入、参数、条件和禁止项的不可变快照。
2. 同一任务轮次至多建立一个执行轮次，一个执行轮次最多运行一个实例方法。每个已开始的执行轮次结束后必须进入结算阶段并恰好形成一个绑定该执行轮次的任务轮次结算结果；任务管理不得依据正式结果自行决定继续、重新筹办、改选、等待或退出。
3. 抽象方法后续换代不改写既有实例方法；新筹办轮次必须重新完成方法 / 条件信息补全，再由执行前选择重新复判和实例化。
4. 方法函数返回只证明调用结果，不能证明目标状态已经发生、任务已经完成或需求已经满足。

### 2.5 C031 筹办、确认、选择的运行顺序

第 2.1—2.4 和第 3 节中“筹办正式采用路径 / 子目标 / 冻结”的旧时序，以本小节为准。筹办由任务状态驱动并可多次调用：找方法完成后才查条件，全部候选条件核验完成后才进入执行前选择。目标当前满足由独立目标比较和轮次收束处理，不是筹办结果。

每次筹办经 task owner 补全任务信息并发送唯一消息；manager 独立读回和校验任务、轮次、状态、版本、覆盖范围后，提交状态迁移。方法 / 条件缺失可以定位给 self；self fresh 读取材料并产生、确认必要的独立目标后，task owner 只能记录正式子目标承接，需求 owner 据此在发布前精确匹配并发布或复用子需求。

执行前选择 fresh 复核每个`方法 + 内容版本 + 条件组 + 输入 / 参数 + 动作范围`的可用性和安全硬门，并从可比较候选中选择综合代价最小的一项。仅胜出选项可形成路径、实例、选择记录和冻结；未知、不可比或并列最优不选择。

## 3. 任务运行顺序

```text
需求领域形成并发布具体需求 D 及其列表成员关系
-> 任务管理读取 D 所属列表项 L
-> 按 L 查询 0..1 个当前任务
-> 不存在时原子建立 T + T→L + T→D + 任务虚拟存在，存在时幂等新增 T→D
-> manager 根据任务状态派发统一筹办工作包；待找方法 / 继续找方法阶段只累计候选方法和覆盖范围
-> 方法范围完整且有候选后进入待查条件；范围完整且零候选形成方法缺失材料
-> 待查条件 / 继续查条件阶段逐候选、逐条件组读取并核验，未覆盖全部候选不得提前结束
-> 全部核验且至少一组具备后进入待执行前选择；全部不具备形成条件缺失材料
-> 每次筹办只经 task owner 唯一入口补全任务信息并发送一条结果消息；manager 独立读回状态、轮次、版本和覆盖范围后才迁移状态
-> 方法 / 条件缺失需要新目标时，self fresh 读取材料并产生、确认独立、必要、父域合法且目标状态可最终判定的目标，task owner 才形成正式子目标承接记录，需求 owner 再于发布前精确匹配并发布或复用需求
-> 执行前 fresh 复核适用性、当前可用性、安全硬门和正式成本，从可比较候选中选择综合代价最小的方法
-> task owner 唯一组合入口形成选择记录、当前路径、实例方法和执行冻结
-> 读取方法作用范围与现实副作用；含现实改变步骤时在任务进入执行阶段前取得一份自我现实执行授权
-> 执行线程运行该实例方法并记录执行轮次
-> 任务服务登记正式任务实际结果
-> 通过公开领域读取独立读回目标事实和共同截止
-> 形成正式结果快照或具名非成功状态
-> 以正式实际结果身份绑定任务结果治理后继输入
-> 形成任务轮次结算结果并立即收束本轮；不等待全部 T→D 或其它受益任务
-> 按子任务轮次读取 0..1 条正式发起调用
-> 恰一条时返回正式结果并幂等结算上级调用槽；零条按根任务收口；多条引用冲突
-> 上级调用返回只提供重触发材料；上级轮次尚未收束且仍处筹办阶段时，由 manager 按状态派发查条件工作包并经筹办补齐条件信息；已收束时等待 self 后继决议
-> 等待自我继续 / 结束 / 等待 / 取消后继决议
```

筹办和执行是任务治理内建动作，不进入统一方法列表，不拥有方法虚拟存在，也不作为候选方法。没有当前路径时不得虚构实例方法；没有正式结果时不得虚构治理后继输入。

## 4. 正式任务实际结果与独立回读

### 4.1 正式结果是独立事实

1. 任务服务通过正式公开入口登记任务实际结果；结果至少绑定：任务身份、实例方法身份、执行轮次、正式实际结果身份和形成时的事实截止。
2. 同一结果幂等身份的同轮同义请求返回精确重复；同轮异义请求返回引用冲突并保持零载荷。执行轮次不得用来源任务序号或路径序号冒充。
3. 结果记录描述本轮实际结果及其当前 / 历史生命周期，不直接改写需求满足、任务轮次收束、任务生命周期结束、方法能力或价值结算状态。

### 4.2 独立读回

1. 实际结果必须通过与方法自报分离的正式领域读取路径回读目标事实，包括目标当前值、相关版本 / 场景和共同事实截止；不得以返回值、日志、缓存命中、预期输出或子步骤完成替代回读。
2. 任务结果独立读回必须按任务、实例方法、路径、来源需求关系组及具体需求目标结构逐层校验引用和共同截止。任何当前性漂移、轮次不匹配、引用冲突、请求拒绝、资源失败、数量预算不足或内部不一致都必须保持具名状态，不能折成成功或静默吞掉。
3. 读回成功只证明在指定截止上取得了与结果绑定的事实快照；它不单独证明任务轮次收束、任务生命周期结束、需求满足或整个业务目标完成。
4. 读回失败、未知或截止漂移只能作为结构化结果供任务治理继续裁决，不得由日志或显示文本重分类为成功 / 失败。

### 4.3 结果材料与辅助证据

实际结果和独立读回是机器事实。执行日志、因果材料、比较说明和其它执行证据只能作为具名辅助材料，是否保存及其生命周期由相邻规范裁决；它们不是第二结果权威，也不是普通结果登记必须建立的业务见证矩阵。

## 5. 任务结果治理后继、需求结算与学习分账

### 5.1 任务结果治理后继

1. 任务结果治理后继输入必须绑定正式任务实际结果身份、实例方法、执行轮次和共同事实截止，不得仅以任务序号、来源需求集合或路径名称定位结果。
2. 后继输入只消费正式结果及其独立读回状态，负责后续治理编排、重复 / 冲突 / 漂移分账和合法后继触发；不得回写已经实例化的方法快照或伪造结果。
3. 后继尚未形成、当前性漂移或资源失败时，必须保留对应具名状态和零载荷边界；不得用空成功、日志 PASS 或旧任务结果结构补齐缺口。

### 5.2 需求正式结算

需求是否满足、是否未满足、是否等待、是否失活和是否恢复属于需求治理与正式结算合同，由 5160 等需求规范承接。需求身份与目标合同持续存在，不得因这些状态删除或退出。需求结算可以读取正式任务实际结果和治理后继输入，但不得把结算结论写回任务实际结果，不能把任务结果节点当作结算节点。

任务结果不是可消费、可分割、可独占领取或需要成员分配的资源。不得建立通用结果容量、结果共用 / 争用、成员分配优先级、消费分配记录、最低 / 期望分配单位、剩余量、未获分配或结果耗尽语义。稀缺数量、所有权和独占机会必须在动作执行前由真实事实 owner 的 fresh 读回、授权、安全检查和原子事务裁决。

每个需求在自身实际调度、筹办、继续执行或显式复核时，必须冻结非零事实截止，读取自己的目标状态合同和目标涉及的当前特征值完整投影后独立核算。当前特征值按合同已满足时零动作形成自己的结论；未满足时，任务仍须先经筹办补齐候选方法及其正式条件组和核验信息，达到`待执行前选择`后，才可继续执行前适用性、授权、安全、fresh 可用性和代价选择。一个状态变化可以自然满足多个需求，但状态记录、动态后状态和任务结果都不能替代本次当前值读回；需求身份不合并，价值、预算、奖励和归因仍分别防重结算。

### 5.3 学习分析和方法版本

1. 学习分析只读消费正式任务实际结果、独立读回和治理后继输入；它不直接修改运行中任务、当前路径或实例方法。
2. 学习分析可以形成方法能力变化材料和后继方法候选。方法系统负责将候选封装为正式方法并发布新版本；学习不得直接建立方法首、能力缺口节点或替代任务路径。
3. 运行中的任务继续使用已冻结实例方法；新方法版本只供后继筹办轮次重新召回并补全条件信息，实际选择仍在执行前进行。

### 5.4 任务轮次结算与自我后继决议

1. 任务轮次结算只消费本轮正式任务实际结果或合法无执行短路结果、验证 / 归因、运行停止和阶段 / 冻结 / 授权消费收口；不消费结果分配、全部 `T→D` 核算组、价值结算或学习后继结果。每个已开始的执行轮次恰好对应一个任务轮次结算结果，同一执行轮次不得重复结算；必要材料完整后本任务轮次即可收束。
2. 每个子任务轮次最多有一条正式发起调用；根任务轮次允许没有。子任务收束后，manager 按正式调用身份返回结果，上级任务 owner 只幂等结算该调用槽；调用槽已返回不等于上级目标满足。
3. 上级任务收到返回后只取得重触发材料。上级轮次尚未收束且仍处筹办阶段时，manager 按权威状态派发对应查条件工作包，由任务筹办补齐条件核验信息后再推进；上级轮次已收束时只能等待 self 后继决议。其它关联、受益或依赖该状态的任务不在子任务收束时批量结算，只在自身实际使用时复核。
4. 目标已达成、目标未达成、材料不足、禁止结果或其它具名结论都只描述各自核算。任务轮次收束不得自动建立下一筹办工作包。
5. 轮次已收束后，需求本体仍持续存在。self 依据需求当前满足状态、活动资格、等待条件、当前整体事实、调度优先级和安全硬否决，独立形成`继续 / 结束 / 等待 / 取消`后继决议。该决议属于内部治理，不是现实执行授权。
6. 只有`继续`决议经任务管理合法复核后，才建立新的任务轮次并从筹办阶段开始；旧路径、实例方法、执行冻结和现实执行授权不得跨轮复用。

## 6. 身份、当前性和生命周期边界

1. 需求列表项、任务、任务轮次发起调用、上级调用槽、方法路径、实例方法、正式实际结果和治理后继输入必须使用各自强类型身份；名称、列表位置、缓存键、函数地址和显示摘要不得替代身份。
2. 所有当前读取返回共同事实截止；历史读取显式指定历史截止。读回材料不得跨截止拼接成“当前成功”。
3. 当前活动任务、当前路径、当前实例方法和正式结果均保留历史；退出或换代不删除历史，不把历史对象重新标记为当前。
4. 任务树不是需求树的副本，也不是业务关系总表。需求父子关系由需求领域承接；任务领域只保存轮次级、0..1 发起者的不可变调用关系及其返回 / 槽结算，不据此形成目标树或永久任务所有权；方法替代关系由方法路径承接。

## 7. 禁止绕过

- 不得仅凭需求树目标或列表项聚合键创建任务；承接输入必须携带具体需求。
- 不得为同一查询锚点建立第二个当前任务或第二棵任务树。
- 不得把多个候选方法同时写成当前活动路径或同时执行。
- 不得把列表全部成员、任务树关系或旧结果结构当作当前任务来源；当前来源只由 `T→D` 正式关系组给出。
- 不得以方法返回值、日志、预期值、缓存或显示摘要冒充正式实际结果和独立读回。
- 不得把任务结果、需求结算、学习能力变化或领域结果见证混成同一权威节点。
- 不得把 `T→D`、需求树、队列、线程缓存或任务名称猜成父任务调用来源。
- 不得把任务结果解释为容量，或建立共用 / 争用、成员优先级、消费分配、剩余量和结果耗尽生产路径。
- 不得因一个子任务结果形成而批量结算所有关联 / 受益任务，或把调用槽已返回写成上级目标满足。
- 不得由学习分析反向改写运行中任务、当前路径或实例方法。
- 不得把本轮目标未达成直接解释为继续任务、待重筹办或下一筹办工作包。
- 不得把自我后继决议解释为现实执行授权，或把一次现实执行授权跨冻结、跨执行轮次、跨任务轮次复用。

## 8. 当前不在本规范内的裁决

需求权重的完整算法、任务状态全集、条件满足度、超时 / 预算、未知结果的最终终止、复杂方法循环终止、结算唯一结论、学习分析准入和历史保留期由相邻规范裁决。本规范不为这些领域另造第二套状态或结算模型。

## 9. 与相邻规范的同步要求

1. 4250 负责需求树、需求列表和成员关系；5090 消费具体需求及其所属列表项，列表项只作查询锚点，不复制目标或成员集合。
2. 4260 负责任务核心、`T→D` 来源关系、轮次级唯一发起调用与返回 / 槽结算、路径、实例方法和任务虚拟存在；5090 只在总闭环中串接这些对象，不恢复任务父子树、列表成员即来源或多条当前路径。
3. 5250 负责状态驱动的候选方法查找、逐候选条件组查找与当前具备性核验；对象 / 方向 / 结果适用性、当前可用性、代价比较和采用属于执行前选择。5090 不建立能力缺口节点，也不把候选方法或条件具备结果当作当前路径。
4. 5160 负责需求正式结算；5090 的任务实际结果和治理后继输入不是结算替身。
5. 5300—5340 负责方法登记、执行和学习版本；5090 不新增方法入口或第二 owner。

## 10. 首轮初始化的分阶段闭环

首轮初始化的业务检查点固定为：

```text
T / Vt / R1
-> Vt 上“筹办 / 待初次筹办”首态
-> P1
-> “筹办 / 待找方法”后态和第一动态
```

Vt 由 task owner 随任务核心同代建立，并承载唯一任务阶段特征和首态。task owner 在首态正式读回后建立 P1；P1 只作首轮、幂等重试和恢复锚点。manager 读回 P1 和首态后经任务状态入口推进到待找方法，不建立额外调用证明；发布未知只能按原键读回收敛，未确认前不得越段。

世界存在、并列任务状态字段、日志或缓存均不能替代正式 Vt 及其任务状态事实。本节只闭合首轮初始化，不表示方法筹办、执行、结果或结算已经完成。
