直接依赖规范：4250、4260、4270、5230、5250。

## 1. 定位

本规范是需求、任务、方法运行闭环及独立结果回读的总规范。它只裁决各对象如何沿当前公开结构和结果合同衔接，不把需求树、任务、方法、实际结果、需求结算或学习分析合并成一个对象。

本规范采用的现行主链为：

```text
具体需求 D
-> 所属需求列表项 L（同类任务查询 / 防重锚点）
-> 唯一活动任务
-> T→D 正式承接关系
-> 唯一当前活动方法路径
-> 实例方法
-> 正式任务实际结果
-> 任务结果治理后继输入
```

这条主链中的每个箭头都是稳定身份、公开读取和共同事实截止上的结构引用。任何聊天、日志、缓存、函数返回值或旧任务树投影都不能替代这些事实。

本规范只裁决总运行链；对象字段和专用接口仍由 4250、4260、5250、5160 等相邻规范承接。相邻规范或旧设计材料中仍出现的需求树直接派发、列表成员即来源主链、能力缺口节点、多条当前路径或旧结果结算边界，均属于待同步历史文字，不得反向恢复本规范已经删除的主链。

## 2. 对象职责和主链

### 2.1 具体需求是任务承接与目标权威入口

1. 需求树负责目标分解、父子位置和需求生命周期；需求列表负责按精确目标聚合当前需求成员。
2. 每次任务承接输入必须携带一个当前具体需求 D。任务管理先读取 D 所属列表项 L，再以 L 作为同类任务查询 / 防重锚点查询 0..1 个当前任务；L 不是任务目标或来源集合。
3. 无当前任务时原子建立 T、`T→L`、`T→D` 和任务虚拟存在；已有任务时机械验证其查询锚点及既有来源目标与 D 相同，再幂等新增 `T→D`。列表项其它成员不得自动成为任务来源。
4. 任务不得复制目标宿主、目标特征、目标状态合同或需求事实。任务目标只从当前 `T→D` 关系组中的具体需求逐项互证；筹办、调度和执行只冻结本轮实际消费的关系、需求版本和共同事实截止。
5. 任务发现必须独立达成的子目标时，先经需求统一入口形成合法子需求及其列表项，再以具体子需求承接 / 复用任务。替代方法、失败结果和学习分析不得直接扩张需求树。

### 2.2 唯一活动任务

1. 对同一当前查询锚点，当前最多存在一个活动任务。后续同目标具体需求必须读取并复用该任务、显式新增来源关系，不得建立平行任务、第二任务树或任务父子业务关系。
2. 任务负责承载一次目标活动的身份、来源需求承接关系、调度状态、筹办轮次、执行轮次、当前路径引用和当前实例方法引用；它不负责复制需求事实、保存需求树关系、领域结果解释或价值结算。
3. 同一任务同一时刻最多一个工作线程。筹办、重筹办、排队和执行不得并发写同一任务；不同任务可以并行。
4. 优先级只影响尚未派发工作的顺序。每次派发前重新计算，值未变不得写入假更新；已运行工作不因优先级变化被抢占或伪造中断。
5. 当前任务退出、恢复和历史读取必须保留任务身份及正式事实截止；退出不级联删除需求列表项、需求成员或历史实际结果。

### 2.3 唯一当前活动方法路径

1. 一个筹办轮次可以产生零个、一个或多个候选方法，但候选集只是召回和就绪复判输入，不是当前活动路径。
2. 每个任务每个筹办轮次只能形成一条当前活动方法路径；未选候选、历史路径和替代路径不得并列标记为当前路径，也不得同时执行。
3. 当前路径必须绑定任务、筹办轮次、被选方法、方法内容版本和就绪合同。路径换代保留旧路径历史，不能原地改写已发布路径。
4. 目标当前未完成时，先按目标特征完整粗召回，再按对象概念、所需方向和结果能力判断适用性。粗召回完整为空先形成`方法能力缺失`判断材料，只有 3100 / 3200 / 5250 正式学习门禁全部满足时才可进入学习需求候选，否则合法等待；粗召回非空但完整适用判断后没有当前适用方法形成`当前无适用方法`并只进入合法等待。适用候选唯一后只评估该采用方法自己的条件、输入和限制；条件缺失形成条件草案，已有方法的结构、动作入口、条件结果对、参数或其它就绪问题形成方法补齐承接或合法等待，均不得伪装成无方法或当前路径。
5. 方法名称、动作名称、函数名、标签和固定编号只能作为非权威辅助索引，不得参与语义命中或替代方法身份。

### 2.4 实例方法

1. 实例方法是本任务、本筹办轮次对一个抽象方法及其内容版本、输入、参数、条件和禁止项的不可变快照。
2. 一个执行轮次最多运行一个实例方法。实例方法执行结束后，本轮归还调度权；任务管理依据正式结果决定继续、重新筹办、改选、等待或退出。
3. 抽象方法后续换代不改写既有实例方法；新筹办轮次必须重新召回、复判和实例化。
4. 方法函数返回只证明调用结果，不能证明目标状态已经发生、任务已经完成或需求已经满足。

## 3. 任务运行顺序

```text
需求领域形成并发布具体需求 D 及其列表成员关系
-> 任务管理读取 D 所属列表项 L
-> 按 L 查询 0..1 个当前任务
-> 不存在时原子建立 T + T→L + T→D + 任务虚拟存在，存在时幂等新增 T→D
-> 筹办读取当前 T→D 关系组，逐项复核 D 当前性并互证单目标
-> 全部关联 D 失活时显式等待、结束或重判，不以 L 聚合键兜底
-> 按目标特征类型有界完整粗召回，再按对象概念、所需方向和结果能力判断适用
-> 粗召回完整为空时形成方法能力缺失；粗召回非空但适用判断全部不兼容时形成当前无适用方法，并保留完整粗召回与逐候选证据
-> 只有方法能力缺失判断材料在正式学习门禁全部满足时可进入学习需求承接，否则合法等待；当前无适用方法只进入合法等待
-> 结构缺口、多候选待选择、采用方法条件未满足或输入限制待绑定只进入方法补齐承接、选择等待或条件等待
-> 唯一采用后读取该方法自己的条件、输入规格和限制并执行后继当前就绪复判
-> 形成零或一条当前活动方法路径，或收束为具名方法补齐承接、选择等待、条件等待或学习需求承接
-> 以当前路径实例化一个实例方法
-> 执行线程运行该实例方法并记录执行轮次
-> 任务服务登记正式任务实际结果
-> 通过公开领域读取独立读回目标事实和共同截止
-> 形成正式结果快照或具名非成功状态
-> 以正式实际结果身份绑定任务结果治理后继输入
```

筹办和执行是任务治理内建动作，不进入统一方法列表，不拥有方法虚拟存在，也不作为候选方法。没有当前路径时不得虚构实例方法；没有正式结果时不得虚构治理后继输入。

## 4. 正式任务实际结果与独立回读

### 4.1 正式结果是独立事实

1. 任务服务通过正式公开入口登记任务实际结果；结果至少绑定：任务身份、实例方法身份、执行轮次、正式实际结果身份和形成时的事实截止。
2. 同一结果幂等身份的同轮同义请求返回精确重复；同轮异义请求返回引用冲突并保持零载荷。执行轮次不得用来源任务序号或路径序号冒充。
3. 结果记录描述本轮实际结果及其当前 / 历史生命周期，不直接改写需求满足、任务完成、方法能力或价值结算状态。

### 4.2 独立读回

1. 实际结果必须通过与方法自报分离的正式领域读取路径回读目标事实，包括目标当前值、相关版本 / 场景和共同事实截止；不得以返回值、日志、缓存命中、预期输出或子步骤完成替代回读。
2. 任务结果独立读回必须按任务、实例方法、路径、来源需求关系组及具体需求目标结构逐层校验引用和共同截止。任何当前性漂移、轮次不匹配、引用冲突、请求拒绝、资源失败、数量预算不足或内部不一致都必须保持具名状态，不能折成成功或静默吞掉。
3. 读回成功只证明在指定截止上取得了与结果绑定的事实快照；它不单独证明任务完成、需求满足或整个业务目标完成。
4. 读回失败、未知或截止漂移只能作为结构化结果供任务治理继续裁决，不得由日志或显示文本重分类为成功 / 失败。

### 4.3 结果材料与辅助证据

实际结果和独立读回是机器事实。执行日志、因果材料、比较说明和其它执行证据只能作为具名辅助材料，是否保存及其生命周期由相邻规范裁决；它们不是第二结果权威，也不是普通结果登记必须建立的业务见证矩阵。

## 5. 任务结果治理后继、需求结算与学习分账

### 5.1 任务结果治理后继

1. 任务结果治理后继输入必须绑定正式任务实际结果身份、实例方法、执行轮次和共同事实截止，不得仅以任务序号、来源需求集合或路径名称定位结果。
2. 后继输入只消费正式结果及其独立读回状态，负责后续治理编排、重复 / 冲突 / 漂移分账和合法后继触发；不得回写已经实例化的方法快照或伪造结果。
3. 后继尚未形成、当前性漂移或资源失败时，必须保留对应具名状态和零载荷边界；不得用空成功、日志 PASS 或旧任务结果结构补齐缺口。

### 5.2 需求正式结算

需求是否满足、是否暂时满足、是否失效、是否恢复有效和是否永久退役属于需求正式结算合同，由 5160 等需求规范承接。需求结算可以读取正式任务实际结果和治理后继输入，但不得把结算结论写回任务实际结果，不能把任务结果节点当作结算节点。

一个任务结果面向该任务当前显式关联的合格来源需求进入逐需求核算前，必须先在正式结果、冻结合格来源需求集合、消费合同、规则版本和共同事实截止上裁决结果消费关系。`可共用`关系不进入优先级排队，每个需求分别重读、裁决和结算；`争用`关系才冻结正式成员分配优先级证据并按序逐项分配，每次分配后扣减剩余。关系不可裁决或正式成员分配优先级 provider 缺失时保持零分配、零结算，不得以任务执行优先级、队列顺序、需求权重、预算、创建时间或稳定编码补默认顺序。结果共用 / 争用与正式分配属于任务完成后的独立路线，不是任务承接、筹办或执行冻结前置。

可共用只表示同一结果或共同事实可同时支持多个需求，不合并需求身份、目标裁决或正式结算，也不允许价值、预算和归因重复领取。争用成员未获分配或结果耗尽是分配结果，不得改写为任务执行失败或需求目标未满足。

### 5.3 学习分析和方法版本

1. 学习分析只读消费正式任务实际结果、独立读回和治理后继输入；它不直接修改运行中任务、当前路径或实例方法。
2. 学习分析可以形成方法能力变化材料和后继方法候选。方法系统负责将候选封装为正式方法并发布新版本；学习不得直接建立方法首、能力缺口节点或替代任务路径。
3. 运行中的任务继续使用已冻结实例方法；新方法版本只供后继筹办轮次重新召回和选择。

## 6. 身份、当前性和生命周期边界

1. 需求列表项、任务、方法路径、实例方法、正式实际结果和治理后继输入必须使用各自强类型身份；名称、列表位置、缓存键、函数地址和显示摘要不得替代身份。
2. 所有当前读取返回共同事实截止；历史读取显式指定历史截止。读回材料不得跨截止拼接成“当前成功”。
3. 当前活动任务、当前路径、当前实例方法和正式结果均保留历史；退出或换代不删除历史，不把历史对象重新标记为当前。
4. 任务树不是需求树的副本，也不是业务关系总表。需求父子关系由需求领域承接，方法替代关系由方法路径承接，结果治理后继关系由结果治理承接。

## 7. 禁止绕过

- 不得仅凭需求树目标或列表项聚合键创建任务；承接输入必须携带具体需求。
- 不得为同一查询锚点建立第二个当前任务或第二棵任务树。
- 不得把多个候选方法同时写成当前活动路径或同时执行。
- 不得把列表全部成员、任务树关系或旧结果结构当作当前任务来源；当前来源只由 `T→D` 正式关系组给出。
- 不得以方法返回值、日志、预期值、缓存或显示摘要冒充正式实际结果和独立读回。
- 不得把任务结果、需求结算、学习能力变化或领域结果见证混成同一权威节点。
- 不得由学习分析反向改写运行中任务、当前路径或实例方法。

## 8. 当前不在本规范内的裁决

需求权重的完整算法、任务状态全集、条件满足度、超时 / 预算、未知结果的最终终止、复杂方法循环终止、结算唯一结论、学习分析准入和历史保留期由相邻规范裁决。本规范不为这些领域另造第二套状态或结算模型。

## 9. 与相邻规范的同步要求

1. 4250 负责需求树、需求列表和成员关系；5090 消费具体需求及其所属列表项，列表项只作查询锚点，不复制目标或成员集合。
2. 4260 负责任务核心、`T→D` 来源关系、路径、实例方法和任务虚拟存在；5090 只在总闭环中串接这些对象，不恢复任务父子树、列表成员即来源或多条当前路径。
3. 5250 负责目标特征粗召回、对象 / 方向 / 结果适用判断、采用方法自身条件提议及后继当前就绪 / 无方法分流；5090 不建立能力缺口节点，不把粗召回、适用候选或采用方案当当前路径。
4. 5160 负责需求正式结算；5090 的任务实际结果和治理后继输入不是结算替身。
5. 5300—5340 负责方法登记、执行和学习版本；5090 不新增方法入口或第二 owner。

## ARCH 五层映射（20260824）

需求/任务/方法运行闭环属于 ARCH-L4；实际结果读回必须消费 ARCH-L2 的通用状态、动态、特征与事实截止，不在任务或方法服务内复制第二状态权威。DATA-L2 只返回结构化读回，任务完成、需求满足和结算仍由 ARCH-L4 分立业务裁决。
