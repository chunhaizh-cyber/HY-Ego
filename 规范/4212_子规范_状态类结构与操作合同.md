## 1. 定位与封闭范围

本规范冻结 `海中鱼巣.领域.数据服务.状态类` 的精确 C++ 公开合同和 L1 物理映射。状态类只拥有1160规定的中性四字段：状态身份、正式特征类型、固定准确值和强时间。状态类不得保存主体、场景、独立属性身份、来源、用途、当前标志、历史列表或业务 owner。

场景中的具体状态使用是4202规定的 `C/E/S` 完整绑定，FT从S内容取得。绑定由场景类按其既有职责维护，物理身份、强类型引用及完整读写合同仍待后继冻结，不当然新增节点或owner；本规范不设计、建立、读取、退出或迁移它，也不允许状态类把三个散装引用拼成绑定。当前选择是引用上下文的独立关系，不是状态字段，也不是本状态类内容 ABI。动态内容、场景动态组织、动作来源、动态概念和因果全部禁止进入本次状态实现。

状态内容发布成功只证明中性四字段成立。后继顺序固定为：状态使用绑定物理合同 → 本规范状态读取接口被其消费 → 动态数据 → 场景动态组织 → 动作来源 → 动态概念 → 因果。本规范不以前置实现这些后继为条件，也不伪造其能力。

## 2. 公共类型和固定枚举

公开合同版本固定为 `状态类数据合同版本 = 2`。旧版本1不得被同名入口继续接受。

```cpp
struct 状态信息身份 final {
    稳定编码 编码{};
    friend bool operator==(const 状态信息身份&, const 状态信息身份&) = default;
};

enum class 状态强时间语义 : std::uint8_t {
    实例绝对UTC纳秒 = 1,
    抽象相对纳秒 = 2
};

struct 状态强时间 final {
    状态强时间语义 语义 = 状态强时间语义::实例绝对UTC纳秒;
    std::int64_t 纳秒 = 0;
    friend bool operator==(const 状态强时间&, const 状态强时间&) = default;
};

using 状态固定准确值 = 特征准确值;

struct 状态信息 final {
    状态信息身份 身份;
    特征类型身份 正式特征类型;
    状态固定准确值 固定准确值;
    状态强时间 强时间;
    friend bool operator==(const 状态信息&, const 状态信息&) = default;
};
```

`状态信息` 是唯一四字段内容 DTO，不继承或嵌套生命周期公共头。合法整数 `0` 在两种时间语义和内联 I64 值中均有效；负时间、未知时间语义、无效 FT、空值身份或 valueless variant 非法。

状态枚举固定为：

```cpp
enum class 状态类数据状态 : std::uint8_t {
    已创建 = 1, 精确重复 = 2, 已读取 = 3, 已退出 = 4, 已清理 = 5,
    入口拒绝 = 6, 未找到 = 7, 目标已退出 = 8,
    正式特征类型未找到 = 9, 正式特征类型已退出 = 10,
    准确值不相容 = 11, 旧格式不支持 = 12,
    事实代次漂移 = 13, 幂等冲突 = 14, 引用冲突 = 15,
    数量预算不足 = 16, 历史材料已清理 = 17,
    资源失败 = 18, 内部不一致 = 19
};
```

现行入口不得产生 `许可拒绝`。未知枚举、L1 旧许可值、异常、载荷与头矛盾均映射为 `内部不一致`；内存分配与长度资源失败映射为 `资源失败`。

## 3. L1 物理结构交付

状态类构造接收一个状态 owner 写端口和以下值式结构交付；全部身份必须非零、两两不同、当前存在、绑定同一 L1 实例并属于该状态 owner：

```cpp
struct 状态类结构交付 final {
    稳定编码 状态族锚点;
    稳定编码 状态族归属关系类型;
    稳定编码 正式特征类型关系类型;
    稳定编码 内联准确值属性类型;       // I64
    稳定编码 引用准确值属性类型;       // U64组，长度恰一
    稳定编码 实例绝对时间属性类型;     // I64
    稳定编码 抽象相对时间属性类型;     // I64
    稳定编码 首次形成UTC属性类型;      // I64，技术保留材料
};

struct 状态类保留策略 final {
    std::uint64_t 实例状态TTL纳秒 = 604800000000000ULL;
    std::uint64_t 实例状态数量上限 = 1000000;
};
```

一份新状态的首次写集固定包含：

1. 一个普通状态节点；
2. 一条“状态节点 → 状态族锚点”的族归属关系；
3. 一条“状态节点 → FT节点”的正式特征类型关系；
4. 恰一个准确值事实及对应属性槽：内联分支为 I64；引用分支为长度恰一的 U64 组，唯一元素是 `特征值身份.编码.值`；
5. 恰一个强时间事实及对应属性槽：按语义使用实例绝对或抽象相对属性类型，材料为非负 I64 纳秒；
6. 一个首次形成 UTC I64 事实及属性槽，由服务在首次请求处理时从系统 UTC 时钟取得，非负且只用于 TTL / 排序。

以上节点、两条关系和三个值必须由状态 owner 在一个 L1 所有者范围写集内共同发布。族锚点、关系类型和属性类型是共享结构材料，不重复创建。首次形成 UTC、关系/值稳定编码、创建/退出代次、幂等材料和墓碑属于可靠性或生命周期材料，不是第五个状态字段。

状态类不能把 FT 编码或值身份装进无类型 U64 汇总数组，不能保存特征节点 F 或多特征快照，不能用两个时间属性同时表达一份状态，也不能用属性类型名称、容器次序或旧本地键猜测字段角色。

## 4. FT 与准确值核验提供者

状态创建不得要求某个准确特征 F 已存在，但必须由特征类在同一 `Gread/H` 核验 FT 与准确值相容。为此，特征类增加唯一窄只读提供者：

```cpp
struct 特征类型准确值核验请求 final {
    std::uint32_t 合同版本 = 1;
    std::uint64_t Gread = 0;
    std::uint64_t H = 0;
    特征类型身份 正式特征类型;
    特征准确值 准确值;
};

struct 特征类型准确值核验事实 final {
    std::uint64_t Gread = 0;
    std::uint64_t H = 0;
    特征类型身份 正式特征类型;
    特征准确值 准确值;
};

enum class 特征类型准确值核验状态 : std::uint8_t {
    已核验 = 1, 入口拒绝 = 2,
    正式特征类型未找到 = 3, 正式特征类型已退出 = 4,
    准确值未找到 = 5, 准确值已退出 = 6, 准确值不相容 = 7,
    历史材料不可用 = 8, 事实代次漂移 = 9,
    资源失败 = 10, 内部不一致 = 11
};

struct 特征类型准确值核验结果 final {
    std::uint32_t 合同版本 = 1;
    特征类型准确值核验状态 状态 = 特征类型准确值核验状态::入口拒绝;
    std::optional<特征类型准确值核验事实> 事实;
    bool 成功() const noexcept;
};

特征类型准确值核验结果
特征类数据服务::核验正式特征类型准确值(
    const 特征类型准确值核验请求&) const;
```

成功必须仅为 `已核验`、事实存在，且证明请求 FT 在 H 正式有效；值表示符合该 FT；内联值或值身份经现有特征值提供者读回完整内容后满足 FT 值域；结果精确回显 `Gread/H/FT/准确值`。非成功事实为空。提供者必须保留失败来源：读 FT 得到的未找到/已退出分别返回 `正式特征类型未找到/已退出`；解析引用准确值时值节点未找到/已退出分别返回 `准确值未找到/已退出`；值表示或值域不相容返回 `准确值不相容`。入口、历史材料、代次、资源和内部错误按同名状态返回，不得把值来源失败冒充 FT 失败。该函数零写入、零创建 F、零概念操作。状态类不得绕过它直接从 L1 重演 FT 或值资格。

## 6. 公开函数全集与成功谓词

`状态类数据服务` 的内容、共同身份和维护公开面固定如下：

```cpp
bool 绑定于(const L1事实基座服务&) const noexcept;
状态创建结果 创建状态(const 状态创建请求&);
状态读取结果 读取当前状态(const 状态当前读取请求&) const;
状态读取结果 读取状态历史内容(const 状态历史读取请求&) const;
状态组查询结果 按正式特征类型查询当前状态组(const 状态按正式特征类型查询请求&) const;
状态组查询结果 按固定准确值查询当前状态组(const 状态按固定准确值查询请求&) const;
状态组查询结果 按强时间范围查询当前状态组(const 状态按强时间范围查询请求&) const;
状态退出结果 退出状态(const 状态退出请求&);
状态同步清理结果 同步清理实例状态材料(const 状态同步清理请求&);
状态类结果头 确认当前状态结构身份(const 状态当前身份确认请求&) const;
状态身份来源历史见证读取结果 读取状态身份来源历史见证(const 状态身份来源历史见证读取请求&) const;
```

成功谓词固定为：

- 创建：状态为 `已创建` 或 `精确重复`，截止和变更代次同为非零，完整内容存在且 `Gread==H==变更事实代次==截止`。
- 当前/历史读取：状态为 `已读取`、变更代次为空、内容完整；当前截止等于 G0，历史截止和内容 `Gread` 等于请求 Gread、内容 H 等于请求 H。
- 三个组查询：状态为 `已读取`、变更代次为空、截止等于 G0；空组合法；非空项均为同一 G0/H 的完整当前内容，按状态身份升序，无重复。
- 退出：状态为 `已退出` 或 `精确重复`，变更代次非零且等于截止 `Gexit`，`Gexit>1`；已退出内容的 `Gread==Gexit`、`H==Gexit-1`，全部自有事实在 H 完整有效并回显共同 `退出事实代次==Gexit`。不得要求内容在 Gexit 仍有效。
- 同步清理：`已清理`、`精确重复` 或首次扫描确无候选时的 `已读取`；前两者须有非空完整墓碑，截止与变更代次均等于 L1 首次物理清理代次，`已清理` 对应 L1 首次发布，`精确重复` 对应 L1 同键同完整请求重放；无候选须零变化和空墓碑，只允许在退出幂等身份没有首次写入材料时成立，且本次不绑定退出身份、不调用或绑定清理身份。
- 当前身份确认：直接返回 `状态类结果头`；成功仅为 `已读取`、合同版本2、截止精确等于 G0、变更为空，不返回内容、身份或当前选择。
- 历史身份见证：状态 `已读取`、变更为空、结果 H 与请求 H、截止与 Gread 精确相等，见证完整且证明状态身份在 H 属于状态族。

任何非成功内容、状态组、见证和墓碑均为空；已经完成入口形状检查的历史见证失败仍回显请求 H，否则 H 为0。读取或见证遇到墓碑时返回 `历史材料已清理`；墓碑本身不是成功内容或成功见证。

## 7. 操作语义

1. 创建先在 G0 调用第4节核验提供者，再形成一次状态 owner 写集；提交后按发布截止独立读回。状态内容不可原地修改，不提供类型、值或时间 setter。
2. 当前与历史读取必须同时核对状态节点、族归属、FT关系、互斥准确值、互斥强时间、首次形成 UTC 及生命周期；缺项、多项、跨 owner、角色错误或新旧混合均不返回部分内容。
3. 三项字段查询只召回候选，再在同一 G0 完整读回；结果按身份排序。查询 FT 使用指向该 FT 的关系组，并先核对召回关系由状态 owner 写入、关系类型精确等于结构交付的 FT 关系类型、目标精确等于请求 FT，随后仅以关系源端作为候选状态身份；不得接受其它 owner 或同目标异关系类型命中。查询准确值使用对应属性类型值组；查询强时间使用对应语义的时间属性类型值组。全部候选最终仍须同G完整读回，预算不足不得返回截断结果。
4. 退出只退出该状态节点、族归属、FT关系和三个自有值事实；不退出 FT、特征值、状态使用绑定、动态、场景组织、当前选择或其它外部引用。存在活动引用时返回 `引用冲突`，零变化。
5. `确认当前状态结构身份` 只确认节点及唯一族归属当前，不读取四字段，不替代完整内容读取。
6. 历史身份见证只提供共同身份来源，不替代状态内容，不解释发生场景或主体。

## 8. 幂等、失败与提交后读回

创建和退出的幂等身份按完整规范化请求绑定。已绑定同键同请求返回首次结果并按首次发布截止读回；同键异请求返回 `幂等冲突`。同步清理的两个身份分时绑定，不得在状态层合并为第二套 pair 记账：退出幂等身份在状态 owner 逻辑退出首次成功时绑定规范化退出事实集合和首次退出结果；清理幂等身份只在 L1 接受完整物理清理请求、形成物理清理幂等账并发布墓碑时由 L1 绑定。在 L1 绑定前返回的 `事实代次漂移` 、 `引用冲突` 、 `资源失败` 或其它未证明物理发布的非成功均不绑定该清理身份；后续调用可保留或更换非零清理身份，但必须从原退出首次材料恢复同一首次退出代次和同一有序事实身份组，不得重扫、扩大或换集合。当前UTC与扫描预算只参与退出身份尚未形成时的首次候选选择，不进入已形成退出事实的二次解释。L1 一旦形成清理幂等账，同键只能用首次完整 L1 请求精确重放，同键异请求或异键对已清理集合均返回 `幂等冲突`。提交已确认而独立读回失败必须保留已形成事实和原键，返回 `内部不一致`，只能用原完整请求与原身份收敛。

字段查询与读取均为 const 零写操作。特征窄核验映射固定为：`正式特征类型未找到/已退出` → 状态同名状态；`准确值未找到/已退出/不相容` → `准确值不相容`；入口拒绝 → `入口拒绝`；历史材料不可用 → `历史材料已清理`；事实代次漂移、资源失败、内部不一致 → 状态同名状态。未知核验状态或成功形状/回显矛盾统一为 `内部不一致`。不得把值0、空身份或名称命中当作默认成功。

owner 写结果和 L1 物理清理结果必须逐项核对合同版本、幂等身份、状态、发布代次、发布确定性及稳定编码映射/墓碑数量和身份。L1 `事实代次漂移` 映射状态同名状态，`同键冲突` 映射 `幂等冲突`，`引用冲突` 映射同名状态，`资源失败` 映射同名状态；对计划已验证的请求，L1 `入口拒绝/未找到/尚未退出/内部错误` 及任何回显矛盾均映射 `内部不一致`。不得把底层错误当作成功或部分载荷返回。

## 9. 实例状态同步清理

同步清理只处理实例绝对时间状态，抽象状态不参与。对尚无退出首次材料的新身份对，服务按 `首次形成UTC属性类型` 有界读取全部当前候选，以“首次形成 UTC 纳秒、状态身份”升序确定 TTL 与数量超限的并集；扫描预算不能证明全量时返回 `数量预算不足` 且零变化。

每次调用必须先以 `退出幂等身份` 读取 owner 首次写入材料，再决定是否扫描当前候选：

1. 未找到退出首次材料时，才按上一段扫描并选择候选；无候选返回 `已读取`。有候选则以该退出身份在一个状态 owner 写集逻辑退出全部候选自有事实，再核验 owner 结果回显。
2. 已有退出首次材料时，不再扫描当前候选，也不因材料已物理清理而返回无候选。必须从首次规范化退出写集与首次结果重建原有序事实身份组和首次退出代次；写集中只能包含一组或多组完整状态的节点、两条关系和三个值的退出，出现其它写项、重复/缺失身份或回显矛盾均为 `内部不一致`。
3. 从首次材料恢复的退出代次只用于证明原退出结果和固定清理集合；调用 L1 时以本次请求 `G0` 作为 `期望事实代次`，且必须有 `G0 >= 首次退出代次`，以本次 `清理幂等身份` 和恢复的同一有序事实身份组调用 `执行L1物理清理`。L1 在查看当前代次前先按自己的幂等账收敛精确重复，因此已绑定清理键只能使用首次完整 L1 请求；未绑定时遇 `事实代次漂移` 则零变化，后续可以新 G0 与原集合重试。
4. L1 尚未形成对任一清理键的物理清理幂等账时，同一退出身份改用另一非零清理身份可以对原集合重试，不属于幂等冲突。一旦对应事实出现物理清理墓碑，只有已绑定原清理键和首次完整 L1 请求可精确重放；异键返回 `幂等冲突`，不得把 L1 `未找到` 降格为“无候选成功”。状态层不持久化清理键或 pair，也不建内存伪账；绑定与冲突以 L1 幂等账和墓碑为唯一事实。

L1 清理集合必须精确包含每个候选的状态节点、两条自有关系和三个自有值事实。活动动态、状态使用绑定、场景组织、当前选择或其它引用尚未闭合时，退出或清理返回 `引用冲突`；状态类不级联修改外部 owner，也不跳过有引用候选形成部分成功。

普通应用的“先动态后状态”周期编排属于后继装配；本入口只提供同步状态阶段。当前 UTC 为非负技术输入，不进入状态内容；`当前UTC < 首次形成UTC` 属于内部不一致。资源失败保留原完整请求；G0 漂移由调用方按1160规则在同周期最多重组一次。

物理清理后，当前/内容读取返回 `历史材料已清理` 且不伪造内容。L1墓碑只保留事实种类、owner和创建/退出/清理代次，不保留关系端点及关系类型，因而身份历史见证也只能返回 `历史材料已清理` 和空见证；不得用节点/关系墓碑拼造状态族归属或四字段。稳定身份永不复用。

## 10. 旧格式与消费者迁移

现行 `数据服务.状态类.ixx` 版本1的“时间 + 多特征快照”、严格 `时间>0`、快照 U64 交替编码及其查询入口全部退出生产。版本2不得接受版本1请求、不得解析快照属性、不得把快照首项重释为 FT/值，也不得保留旧 overload、别名、回退或双写。

存量版本1材料不自动删除或改义。新读取遇到缺少族归属、FT关系、三项新值角色或存在旧快照形状时返回 `旧格式不支持`；L1 继续保护原事实和引用。由于当前生产源码没有状态服务构造点，且没有能够无歧义把任意多特征快照转换为单一四字段状态的规则，本次不建立数据转换程序。未来确需迁移时必须另定来源选择和引用迁移合同。

现有存在、场景、因果消费者均不属于本状态本体计划的迁移范围，不得为适配本规范而同次修改。场景对状态的合法使用必须先由4202后继冻结 `C/E/S` 状态使用绑定物理合同，再依据该合同重新扫描并选择本规范的完整读取或窄身份接口；存在和因果也必须依据各自届时正式合同重新扫描状态读取 ABI。本规范不预判消费者应采用身份确认、完整读取或不再依赖状态类。任何需要C/E/S完整绑定或动态端点内容的后继不得以身份确认冒充完整读取。

## 11. 构造与依赖方向

构造函数固定为：

```cpp
状态类数据服务(L1事实基座服务&,
    const 特征类数据服务&,
    L1所有者范围写端口&&,
    const 状态类结构交付&,
    状态类保留策略 = {});
```

状态服务保存 `L1事实基座服务&`，不得降为 `const L1事实基座服务&`，也不得使用 `const_cast`。原因是现行唯一 `L1事实基座服务::执行L1物理清理` 是非 const 写入口；`同步清理实例状态材料` 必须在逻辑退出提交成功后通过同一 L1 实例调用该入口。普通状态写入仍只能经过构造时取得的状态 owner `L1所有者范围写端口`；非 const L1 引用不替代 owner 写端口，也不得用于状态创建、退出或其它中性写入口。读取函数继续只调用 L1 的 const 读取面。

构造必须同时核对写端口和特征服务均绑定于该非 const L1 引用。状态模块保持 `export import 海中鱼巣.领域.数据服务.特征类`；依赖方向仅为状态类 → 特征类窄只读核验 + L1。状态类不依赖存在类、场景类、动态类、概念类或因果类。4202后继绑定服务可依赖状态完整读取；不得让状态类反向持有绑定服务。

## 12. 验证与完成边界

最低矩阵必须覆盖：四字段两种值表示、两种时间语义及0；FT与引用值各自未找到/已退出的来源分离和状态映射；负时间/未知语义；FT和值不相容；创建首次/精确重放/同键异请求；当前和历史完整读回，尤其 `H<退出G<=Gread` 成功及 `退出G<=H` 拒绝；三项字段查询空组/多项/预算不足及FT召回owner过滤；退出首次/重复和 `Gexit-1` 内容见证；实例TTL/数量选择、抽象排除、首次无候选、退出后清理、清理后原双键精确重放、L1接受前同清理键换G0重试、L1接受前改清理键但严格保持原退出集合/Gexit、L1接受后同键精确重放与异键冲突、墓碑不伪造身份见证；owner/L1结果回显矛盾；提交后读回失败；旧版本请求和旧快照零解析；状态服务通过非 const L1 服务引用调用物理清理且零 `const_cast`；状态模块不持久化清理键/pair、不建内存伪账，也不依赖C/E/S绑定、动态、动作、概念和因果服务。存在、场景与因果的消费者迁移、旧调用和编译状态均不属于本版验证范围。

本规范与对应代码计划可证明状态四字段 C++ 合同可机械施工；不证明代码已经实现、编译、运行、存量迁移、状态使用绑定、动态、周期装配或业务验收完成。
