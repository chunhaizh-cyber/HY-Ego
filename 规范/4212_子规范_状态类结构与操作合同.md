# 4212 子规范 状态类结构与操作合同

编号：4212
日期：20261106
版本：v1.3
状态：正式子规范

直接上级规范：1160。
直接依赖规范：1130、1150、2100。
相关边界规范：4190、4202、4211、5170。

## 1. 定位

本规范展开1160状态信息的字段、建立、查询、生命周期、删除与非成功合同。状态是实例特征F的一次值变化记录，由发生场景的状态列表持有和存储。状态owner只维护状态内容与生命周期材料；F及其当前值归特征owner，发生场景组织归场景owner，引用状态的动态归动态owner。

本规范替代旧版“状态四字段（保存FT而不保存F）+C/E/S状态使用绑定”模型；旧正文整体退役，不保留为附录。

## 2. 状态字段

| 字段 | 基数 | 含义 |
| --- | --- | --- |
| 节点 | 恰一 | 状态节点稳定编码。 |
| 实例特征F | 恰一 | 发生值变化的实例特征。 |
| 固定准确值 | 至多一 | 变化后的准确值，建立后不可修改；无值表示当前值变为未知（未知状态），不以任何值代替。 |
| 强时间 | 恰一 | 事实发生时间。 |
| 生命周期控制材料 | 恰一组 | 正式引用计数与首次形成UTC；首次形成UTC只用于定期、定量删除的排序和计时。 |

状态不保存具体特征概念、被描述存在或场景：

1. 所属特征概念在读取时按F当前所属概念及当前概念树归类，随认知漂移。
2. 被描述存在沿F的持有链上溯，取第一个遇到的存在或场景节点。F可由存在（含任务、方法、词条、语言材料范围、指代实例等信息存在）、场景、父特征（归组子特征）持有；持有链未能到达存在或场景时，不得建立状态；需求持有的F不建立状态（0050第1.4节）。信息存在的F状态挂入其所在内部治理世界或自然语言世界场景的状态列表。
3. 发生场景由持有该状态的场景状态列表确定。

### 2.1 准确值

准确值沿用特征准确值表示：

1. I64标量直接保存。
2. 普通特征值节点引用（2100），状态不复制数组、字符串、轮廓或体素材料，不承担材料压缩或解析。
3. 由F的特征类型限定类别的正式信息节点引用（存在、场景、需求、任务、方法、二次特征定义或实例等，1130）。引用身份与读取被引用节点的内容分开；引用二次特征定义与引用具体二次特征实例必须可区分。

被引用的特征值节点或信息节点必须当前存在且类别符合F的特征类型。

### 2.2 强时间

强时间由时间语义和纳秒值组成，时间语义只有两类：

1. 实例绝对UTC：实例状态唯一允许的时间语义，值非负。
2. 抽象相对：只供概念和抽象使用，不得冒充实例发生时刻，不参与定期、定量删除。

强时间是事实发生时间，用于状态排序、原子动态前后判定和跨特征时间比较；它与本次观察取得时间（3200）分开，不是事实代次、合同版本、运行代次或操作序号。

## 3. 建立

状态只能由存在、场景或动态owner在其组合发布中通过私有入口建立，普通调用方不能提交脱离实例特征的裸状态。建立流程：

```text
核验F可读、强时间合法
-> 读回F当前值并要求当前值存在
-> 沿F持有链确定被描述存在或场景
-> 建立状态节点，写入F、固定准确值、强时间及首次形成UTC，引用计数为零
-> 在同一组合发布内挂入发生场景状态列表（场景owner增加引用）
-> 完整读回核验
```

1. 调用方不能指定与F当前值不一致的准确值。
2. 建立本身不查重；是否生成由上层按“F当前值实际改变”控制（同值再次命中不生成）。服务对象需求特征的需求发生特例由5170规定。
3. 由状态或动态持有的二次特征在建立时一次确定，此后不再变化，不生成状态。
4. 存在owner（含信息存在owner）写特征时以其唯一直接场景在同次发布中挂入状态（1140），不得留下未挂接的零引用状态。
6. 存在离开场景：先由相关owner删除或修改该存在与原场景相关的关系信息（成员关系等），再将其绝对坐标F置空，置空形成的状态挂入原场景（形成“离开”）；随后迁移，在新场景写入坐标，形成的状态挂入新场景（形成“进入”，即发现）。两次都是F当前值的实际改变，不另设同值状态例外（4202、6260）。
5. 一次业务变化整体发布；原子发布实现前，状态建立失败不表示特征写入失败，上层返回具名部分完成，不回滚已成立的特征事实。

## 4. 查询

1. 获取状态、是状态节点。
2. 按F查询。
3. 按存在查询：经F持有链定位属于该存在的F后查询。
4. 按特征类型查询：经F取得类型根，不因具体概念漂移而遗漏。
5. 按准确值查询、按强时间查询、查找完全相同状态。

查询结果按稳定编码排序去重；合法空集与读取失败分别返回，不以空集代替结构化错误。

## 5. 生命周期与删除

### 5.1 引用计数

1. 新建状态引用计数为零，新建时的零不触发删除。
2. 场景状态列表、原子动态端点及其它正式引用每建立一项增加一次，退出时减少一次。
3. “撤销增加引用”只用于同一上层写入尚未发布时的回滚，恢复为零也不触发删除。
4. 负数、溢出、字段缺失或计数与实际引用不一致属于结构不一致。
5. 引用计数是生命周期控制材料，不是出现次数、命中次数或业务权重。
6. 引用计数只做快速判定；是否仍被引用以4015第10.1节引用闭包查询为准。计数与闭包结果不一致属于结构不一致，以闭包为准。

### 5.2 定期、定量删除

状态的主删除机制是定期、定量规则（0050 §1.5）：

1. 状态类只提供同步清理入口，由运行宿主的维护周期调用，不自建后台线程或特殊清理身份。
2. TTL自首次形成UTC起算；数量按每个场景各自的状态列表计数，超过该列表上限时最旧的先删。默认阈值与按世界类型的配置集中由4190规定，场景列表层的清理组织由4202规定。
3. 抽象相对时间的状态不参与。
4. 受保护、本轮不删除的状态：仍被存在的动态引用（端点、条件或结果）；被因果概念或动态概念以正式引用采纳为代表实例；被他人特征、需求、任务、方法或因果的正式引用。“被采纳”只以正式引用表达，被引用即受保护，不另设保留标记。概念的世界事实支持、投影和索引引用不具保护力，删除时由删除方解除并通知其owner。
5. 同一轮清理中先删动态、后删状态；被描述存在硬删除（1140）时，其自身状态随之进入清理，仍被他方正式引用的跳过。

### 5.3 删除步骤

删除前以引用闭包查询证明无保护性引用（引用计数为零只是快速判定）；先由引用方解除场景列表及动态等全部引用，再移除状态固定字段并删除节点。底层仍检测到引用而删除失败时恢复字段并返回仍被引用或结构不一致。不得先物理删除节点再清理引用。

## 6. 不可变性与一致性

1. 状态建立后F、准确值和强时间不可修改；需要表达新值时建立新状态。
2. 任一成功读回的状态：F、强时间各恰一，准确值至多一（未知状态无准确值），F当前可读；被引用节点存在且类别合法；实例状态使用合法实例绝对UTC；引用计数非负且与实际正式引用一致。
3. 状态只属于一个发生场景，不迁移、不重复挂接；父场景形成融合动态时以场景范围包含引用该状态，不搬迁、不复制（1150、1170）。

## 7. 非成功分类

入口拒绝、存在不存在、特征不存在、F不可读、持有链未达存在或场景、当前值不存在、时间不合法、准确值类别不合法、状态不存在、仍被引用、引用溢出、结构不一致、资源失败。工程故障按4050与日志规范处理，不改写为业务否定。

## 8. 最低验证

1. 初始特征与当前值改变生成状态；同值再次命中不生成。
2. 非法时间、无当前值、持有链未达存在拒绝。
3. I64、特征值节点引用和信息节点引用三类准确值及未知状态完整读回；有值入口遇F无当前值仍拒绝，未知入口遇F有当前值拒绝。
4. 状态内容不可修改；按特征类型查询不因概念漂移遗漏。
5. 场景与动态引用成对维护；只有正式减法使计数归零才可删除。
6. 定期、定量删除不删除被采纳代表实例、被动态引用或被其它正式引用的状态；先删动态后删状态。
7. 部分完成不回滚已成立的特征事实。
