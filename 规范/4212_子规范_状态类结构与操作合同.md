## 1. 定位与封闭范围

本规范冻结 `海中鱼巣.领域.数据服务.状态类` 的精确 C++ 公开合同和 L1 物理映射。状态类只拥有1160规定的中性四字段：状态身份、正式特征类型、固定准确值和强时间。状态类不得保存主体、场景、属性上下文、来源、用途、当前标志、历史列表或业务 owner。

场景中的具体状态使用是4202规定的 `C/E/P/S` 完整绑定。该绑定具有独立物理身份和 owner；本规范不设计、建立、读取、退出或迁移它，也不允许状态类把四个散装引用拼成绑定。当前选择是引用上下文的独立关系，不是状态字段，也不是本状态类内容 ABI。动态内容、场景动态组织、动作来源、动态概念和因果全部禁止进入本次状态实现。

状态内容发布成功只证明中性四字段成立。后继顺序固定为：状态使用绑定物理合同 → 本规范状态读取接口被其消费 → 动态数据 → 场景动态组织 → 动作来源 → 动态概念 → 因果。本规范不以前置实现这些后继为条件，也不伪造其能力。

## 2. 公共类型和固定枚举

公开合同版本固定为 `状态类数据合同版本 = 2`。旧版本1不得被同名入口继续接受。

```cpp
struct 状态信息身份 final {
    稳定编码 编码{};
    friend bool operator==(const 状态信息身份&, const 状态信息身份&) = default;
};

enum class 状态强时间语义 : std::uint8_t {
    实例绝对UTC纳秒 = 1,
    抽象相对纳秒 = 2
};

struct 状态强时间 final {
    状态强时间语义 语义 = 状态强时间语义::实例绝对UTC纳秒;
    std::int64_t 纳秒 = 0;
    friend bool operator==(const 状态强时间&, const 状态强时间&) = default;
};

using 状态固定准确值 = 特征准确值;

struct 状态信息 final {
    状态信息身份 身份;
    特征类型身份 正式特征类型;
    状态固定准确值 固定准确值;
    状态强时间 强时间;
    friend bool operator==(const 状态信息&, const 状态信息&) = default;
};
```

`状态信息` 是唯一四字段内容 DTO，不继承或嵌套生命周期公共头。合法整数 `0` 在两种时间语义和内联 I64 值中均有效；负时间、未知时间语义、无效 FT、空值身份或 valueless variant 非法。

状态枚举固定为：

```cpp
enum class 状态类数据状态 : std::uint8_t {
    已创建 = 1, 精确重复 = 2, 已读取 = 3, 已退出 = 4, 已清理 = 5,
    入口拒绝 = 6, 未找到 = 7, 目标已退出 = 8,
    正式特征类型未找到 = 9, 正式特征类型已退出 = 10,
    准确值不相容 = 11, 旧格式不支持 = 12,
    事实代次漂移 = 13, 幂等冲突 = 14, 引用冲突 = 15,
    数量预算不足 = 16, 历史材料已清理 = 17,
    资源失败 = 18, 内部不一致 = 19
};
```

现行入口不得产生 `许可拒绝`。未知枚举、L1 旧许可值、异常、载荷与头矛盾均映射为 `内部不一致`；内存分配与长度资源失败映射为 `资源失败`。

## 3. L1 物理结构交付

状态类构造接收一个状态 owner 写端口和以下值式结构交付；全部身份必须非零、两两不同、当前存在、绑定同一 L1 实例并属于该状态 owner：

```cpp
struct 状态类结构交付 final {
    稳定编码 状态族锚点;
    稳定编码 状态族归属关系类型;
    稳定编码 正式特征类型关系类型;
    稳定编码 内联准确值属性类型;       // I64
    稳定编码 引用准确值属性类型;       // U64组，长度恰一
    稳定编码 实例绝对时间属性类型;     // I64
    稳定编码 抽象相对时间属性类型;     // I64
    稳定编码 首次形成UTC属性类型;      // I64，技术保留材料
};

struct 状态类保留策略 final {
    std::uint64_t 实例状态TTL纳秒 = 604800000000000ULL;
    std::uint64_t 实例状态数量上限 = 1000000;
};
```

一份新状态的首次写集固定包含：

1. 一个普通状态节点；
2. 一条“状态节点 → 状态族锚点”的族归属关系；
3. 一条“状态节点 → FT节点”的正式特征类型关系；
4. 恰一个准确值事实及对应属性槽：内联分支为 I64；引用分支为长度恰一的 U64 组，唯一元素是 `特征值身份.编码.值`；
5. 恰一个强时间事实及对应属性槽：按语义使用实例绝对或抽象相对属性类型，材料为非负 I64 纳秒；
6. 一个首次形成 UTC I64 事实及属性槽，由服务在首次请求处理时从系统 UTC 时钟取得，非负且只用于 TTL / 排序。

以上节点、两条关系和三个值必须由状态 owner 在一个 L1 所有者范围写集内共同发布。族锚点、关系类型和属性类型是共享结构材料，不重复创建。首次形成 UTC、关系/值稳定编码、创建/退出代次、幂等材料和墓碑属于可靠性或生命周期材料，不是第五个状态字段。

状态类不能把 FT 编码或值身份装进无类型 U64 汇总数组，不能保存特征节点 F 或多特征快照，不能用两个时间属性同时表达一份状态，也不能用属性类型名称、容器次序或旧本地键猜测字段角色。

## 4. FT 与准确值核验提供者

状态创建不得要求某个准确特征 F 已存在，但必须由特征类在同一 `Gread/H` 核验 FT 与准确值相容。为此，特征类增加唯一窄只读提供者：

```cpp
struct 特征类型准确值核验请求 final {
    std::uint32_t 合同版本 = 1;
    std::uint64_t Gread = 0;
    std::uint64_t H = 0;
    特征类型身份 正式特征类型;
    特征准确值 准确值;
};

struct 特征类型准确值核验事实 final {
    std::uint64_t Gread = 0;
    std::uint64_t H = 0;
    特征类型身份 正式特征类型;
    特征准确值 准确值;
};

特征数据结果<特征类型准确值核验事实>
特征类数据服务::核验正式特征类型准确值(
    const 特征类型准确值核验请求&) const;
```

成功必须证明：请求 FT 在 H 正式有效；值表示符合该 FT；内联值或值身份经现有特征值提供者读回完整内容后满足 FT 值域；结果精确回显 `Gread/H/FT/准确值`。该函数零写入、零创建 F、零概念操作。未找到、已退出、类型不相容、历史材料不可用、代次漂移、资源失败及内部不一致沿现有 `特征数据错误` 精确返回。状态类不得绕过它直接从 L1 重演 FT 或值资格。

## 6. 公开函数全集与成功谓词

`状态类数据服务` 的内容、共同身份和维护公开面固定如下：

```cpp
bool 绑定于(const L1事实基座服务&) const noexcept;
状态创建结果 创建状态(const 状态创建请求&);
状态读取结果 读取当前状态(const 状态当前读取请求&) const;
状态读取结果 读取状态历史内容(const 状态历史读取请求&) const;
状态组查询结果 按正式特征类型查询当前状态组(const 状态按正式特征类型查询请求&) const;
状态组查询结果 按固定准确值查询当前状态组(const 状态按固定准确值查询请求&) const;
状态组查询结果 按强时间范围查询当前状态组(const 状态按强时间范围查询请求&) const;
状态退出结果 退出状态(const 状态退出请求&);
状态同步清理结果 同步清理实例状态材料(const 状态同步清理请求&);
状态类结果头 确认当前状态结构身份(const 状态当前身份确认请求&) const;
状态身份来源历史见证读取结果 读取状态身份来源历史见证(const 状态身份来源历史见证读取请求&) const;
```

成功谓词固定为：

- 创建：状态为 `已创建` 或 `精确重复`，截止和变更代次同为非零，完整内容存在且 `Gread==H==变更事实代次==截止`。
- 当前/历史读取：状态为 `已读取`、变更代次为空、内容完整；当前截止等于 G0，历史截止和内容 `Gread` 等于请求 Gread、内容 H 等于请求 H。
- 三个组查询：状态为 `已读取`、变更代次为空、截止等于 G0；空组合法；非空项均为同一 G0/H 的完整当前内容，按状态身份升序，无重复。
- 退出：状态为 `已退出` 或 `精确重复`，变更代次非零且等于截止，已退出内容在该截止可历史读回并回显退出代次。
- 同步清理：`已清理`、`精确重复` 或无候选时的 `已读取`；前两者须有非空完整墓碑并回显清理代次，无候选须零变化和空墓碑。
- 当前身份确认：直接返回 `状态类结果头`；成功仅为 `已读取`、合同版本2、截止精确等于 G0、变更为空，不返回内容、身份或当前选择。
- 历史身份见证：状态 `已读取`、变更为空、结果 H 与请求 H、截止与 Gread 精确相等，见证完整且证明状态身份在 H 属于状态族。

任何非成功内容、状态组、见证和墓碑均为空；已经完成入口形状检查的历史见证失败仍回显请求 H，否则 H 为0。

## 7. 操作语义

1. 创建先在 G0 调用第4节核验提供者，再形成一次状态 owner 写集；提交后按发布截止独立读回。状态内容不可原地修改，不提供类型、值或时间 setter。
2. 当前与历史读取必须同时核对状态节点、族归属、FT关系、互斥准确值、互斥强时间、首次形成 UTC 及生命周期；缺项、多项、跨 owner、角色错误或新旧混合均不返回部分内容。
3. 三项字段查询只召回候选，再在同一 G0 完整读回；结果按身份排序。查询 FT 使用指向该 FT 的关系组；查询准确值使用对应属性类型值组；查询强时间使用对应语义的时间属性类型值组。预算不足不得返回截断结果。
4. 退出只退出该状态节点、族归属、FT关系和三个自有值事实；不退出 FT、特征值、状态使用绑定、动态、场景组织、当前选择或其它外部引用。存在活动引用时返回 `引用冲突`，零变化。
5. `确认当前状态结构身份` 只确认节点及唯一族归属当前，不读取四字段，不替代完整内容读取。
6. 历史身份见证只提供共同身份来源，不替代状态内容，不解释发生场景或主体。

## 8. 幂等、失败与提交后读回

创建和退出的幂等身份按完整规范化请求绑定。已绑定同键同请求返回首次结果并按首次发布截止读回；同键异请求返回 `幂等冲突`。事实代次漂移只允许在交换前返回，零变化且不绑定身份。资源失败在交换前零变化；提交已确认而独立读回失败必须保留已形成事实和原键，返回 `内部不一致`，调用方用原完整请求收敛，不能换键补写。

字段查询与读取均为 const 零写操作。FT和值提供者的未找到/退出/类型不相容分别映射，不把值0、空身份或名称命中当作默认成功。

## 9. 实例状态同步清理

同步清理只处理实例绝对时间状态，抽象状态不参与。服务按 `首次形成UTC属性类型` 有界读取全部当前候选，以“首次形成 UTC 纳秒、状态身份”升序确定 TTL 与数量超限的并集；扫描预算不能证明全量时返回 `数量预算不足` 且零变化。

一次调用先以 `退出幂等身份` 在同一状态 owner 写集逻辑退出全部候选自有事实，再以退出提交产生的新截止和 `清理幂等身份` 调用 L1 物理清理。L1 清理集合必须精确包含每个候选的状态节点、两条自有关系和三个自有值事实。活动动态、状态使用绑定、场景组织、当前选择或其它引用尚未闭合时，退出或清理返回 `引用冲突`；状态类不级联修改外部 owner，也不跳过有引用候选形成部分成功。

普通应用的“先动态后状态”周期编排属于后继装配；本入口只提供同步状态阶段。当前 UTC 为非负技术输入，不进入状态内容；`当前UTC < 首次形成UTC` 属于内部不一致。资源失败保留原完整请求；G0 漂移由调用方按1160规则在同周期最多重组一次。

物理清理后，当前/内容读取返回 `历史材料已清理` 且不伪造内容；身份历史读取只可返回 L1 允许的紧凑墓碑投影，不能用墓碑重建四字段。稳定身份永不复用。

## 10. 旧格式与消费者迁移

现行 `数据服务.状态类.ixx` 版本1的“时间 + 多特征快照”、严格 `时间>0`、快照 U64 交替编码及其查询入口全部退出生产。版本2不得接受版本1请求、不得解析快照属性、不得把快照首项重释为 FT/值，也不得保留旧 overload、别名、回退或双写。

存量版本1材料不自动删除或改义。新读取遇到缺少族归属、FT关系、三项新值角色或存在旧快照形状时返回 `旧格式不支持`；L1 继续保护原事实和引用。由于当前生产源码没有状态服务构造点，且没有能够无歧义把任意多特征快照转换为单一四字段状态的规则，本次不建立数据转换程序。未来确需迁移时必须另定来源选择和引用迁移合同。

当前场景类、存在类、因果类只为核验状态身份调用旧 `查询状态`。它们必须同次迁移为 `确认当前状态结构身份`，只检查结果头，不读取状态内容。任何需要 C/E/P/S 或动态端点内容的后继不得以该身份确认冒充完整读取。

## 11. 构造与依赖方向

构造函数固定为：

```cpp
状态类数据服务(const L1事实基座服务&,
    const 特征类数据服务&,
    L1所有者范围写端口&&,
    const 状态类结构交付&,
    状态类保留策略 = {});
```

状态模块保持 `export import 海中鱼巣.领域.数据服务.特征类`；依赖方向仅为状态类 → 特征类窄只读核验 + L1。状态类不依赖存在类、场景类、动态类、概念类或因果类。4202后继绑定服务可依赖状态完整读取；不得让状态类反向持有绑定服务。

## 12. 验证与完成边界

最低矩阵必须覆盖：四字段两种值表示、两种时间语义及0；负时间/未知语义；FT和值不相容；创建首次/精确重放/同键异请求；当前和历史完整读回；三项字段查询空组/多项/预算不足；退出与外部引用保护；实例TTL/数量选择、抽象排除、无候选、退出后清理及墓碑；提交后读回失败；旧版本请求和旧快照零解析；三个直接消费者零旧 `查询状态`；状态模块零 C/E/P/S、动态、动作、概念和因果依赖。

本规范与对应代码计划可证明状态四字段 C++ 合同可机械施工；不证明代码已经实现、编译、运行、存量迁移、状态使用绑定、动态、周期装配或业务验收完成。
