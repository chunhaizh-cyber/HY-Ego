## 条款 1：集合条件概念

- 原出处：2220 v1.28 §2.1“集合条件概念”。
- 建议并入位置：7165 中“专用定义形状”相关章节（与代词约束定义并列）。
- 并入时须修订：删去“定义版本”及规则名后的“/v1”版本后缀（本轮裁决：定义按当前认知维护，不保留版本）；需求/任务所有权引用按新版 3100/3200。

原文要点（保留语义）：

集合条件概念是一种可复用的专用定义，类别为“集合条件”；沿用概念的独立身份和唯一写入方，不按“有事”等词面另建概念类别、总根或存储 owner。它描述一个有类型主体所关联集合的成员数量条件，不保存某次集合的成员、具体主体或陈述者。完整规范化签名恰由以下五项组成：

```text
适用主体的强类型类别及角色
+ 集合元素的强类型类别
+ 主体—元素成员关系的固定定义引用及角色方向
+ 有类型的元素筛选规则固定引用及其时间/作用域规则
+ 非负整数基数条件
```

成员关系定义只规定“哪些元素算作该主体的集合成员”，不因概念发布而产生任何成员关系。关系、筛选和时间规则均以可读的固定定义身份与参数参与签名，不用显示名、自由文本或当次查询函数地址代替。没有实际枚举提供者不影响定义成立，但不能宣称条件已被现实证实。筛选条件必须有明确可判定含义；未知、未查询或来源不可读不等于筛选不成立。基数条件采用类型化非负整数比较，至少区分 `=0`、`>=1` 等不同定义，不能把“集合未知”按空集处理。同一完整签名只复用一个概念；具体主体、任务身份、任务列表、语言来源与当次求值结果均不进入签名。无具名蕴含规则时，该类别概念的上位为其所属根（按新版 2220：普通概念必须有上位链通到根）。

“`A 有事`”的固定定义：

| 签名项 | 固定定义 |
| --- | --- |
| 主体与元素 | 主体为任意存在 `E`，元素为任务信息 `T`；概念定义不要求已有某个 `T` |
| 成员关系 | `主体承担任务`，方向为 `T→E`：`T` 是 `E` 需要处理或完成的任务；这是描述对象的承担角色，不把 `E` 变成正式任务 owner |
| 筛选与时间 | `参照时刻活动任务` 与 `当前陈述参照`：在陈述所指的当前时刻，`T` 未处于已完成、已失败、已取消的收束状态；直接陈述取其表达时刻，引述取引述内可确定的表达时刻，无法确定时刻则保留主张但不得求值 |
| 基数 | 经过上述成员关系与筛选的任务数 `>=1` |

对自我的正式任务实际求值时，成员和活动状态须遵守 3200 的正式任务集合及当前状态；本定义不改写 3100/3200 中自我正式需求与正式任务的所有权。非自我对象没有对应的有类型任务成员及状态提供者时，实际求值为未知，不因此拒绝保存有来源的语言主张；不能把非自我的描述性任务写入 3200 的正式任务集合。

概念定义与“某个 `A` 满足该概念”的当次主张分账。听到“`A 有事`”可在语言场景中保存具名主体、概念、来源和作用域的归类主张，不先核查真实任务集合，不凭话语建立任务、任务归属事实、现实存在的实例特征或概念支持边。后来取得任务证据时由相应领域另行核验并形成事实。
