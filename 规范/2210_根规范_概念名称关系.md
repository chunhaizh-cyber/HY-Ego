# 2210 根规范 概念名称关系

编号：2210
日期：20261105
版本：v2.2
状态：正式根规范

直接上级规范：0050。

直接依赖规范：2200、2220。

相关边界规范：1100、4240、7140、7200、7210、7220。

## 1. 根定位

概念名称关系是 2220 独立概念身份把词条作为名称成员的权威有向关系事实。它具有关系稳定身份和生命周期，但不建立独立“语素入口”、语素或信息入口类型节点；本关系的权威结构只有词条、独立概念和两者之间的具名名称关系。

```text
词面输入
-> 非权威词索引召回词条
-> 反查当前概念名称关系
-> 得到零个、一个或多个候选概念
-> DATA 之外业务层按上下文裁决
```

## 2. 概念唯一性边界

1. 每个概念具有独立稳定身份；同一本体根、同一签名规则和同一完整抽象签名不得同时存在两个当前概念。
2. 概念唯一性只由 2220 / 7140 的本体根、抽象签名、直接上下位关系和定义约束共同裁决，不由名称、词条、解析标签、索引、显示文本或首次命中裁决。
3. 名称相同不等于概念相同；名称不同也不等于概念不同。
4. 名称关系只挂在存在、特征、动态三类根树下的概念上；四本体根的布局、根不另建词条及功能词不进概念树，唯一出处为 [2220](2220_根规范_概念空间.md) 第1、9节，本规范不重复。

## 3. 正式结构

概念名称关系从概念指向词条，至少具有：

```text
关系稳定身份
源概念身份
目标词条身份
名称角色：首选名称 / 别名 / 简称
适用语言
来源与生命周期
```

约束如下：

1. 同一概念可以有多个当前名称，同一词条可以命名多个概念，整体是多对多关系。
2. 同一概念、同一语言最多一个当前首选名称；别名和简称允许多个。
3. 同一概念、词条、名称角色和语言的当前关系不得重复；重复同义请求必须幂等读回。
4. 退出名称关系不退出概念或词条；退出概念或词条时必须按引用闭包处理仍有效的名称关系。概念被合并复用时（2220 第6节），名称关系随其它引用一并改接到复用的概念。
5. 名称关系只证明该词条当前可以作为该概念的名称，不证明输入上下文当前采用该概念。
6. 词条持有“概念名称挂接”实例特征F，其当前值为该词条当前挂接的概念引用集合；名称关系的建立或退出与该F的更新在同一次组合发布中完成，二者不一致属于结构不一致。F的值变化按普通特征生成状态和动态（3100方案A），状态挂入词条在自然语言世界的所属场景（0050第1.4节）。
7. 词条所指类型已知而定义未知时，不新建概念，名称关系及“概念名称挂接”F直接指向已知的上位概念Y；以后定义补齐且确与Y不同时，再在Y下派生新概念并把名称改挂过去（2220第7节、7250）。

## 3.1 多语种表达与名称读音适用

实例信息到概念的名称字段节点引用，与本规范概念到词条的自然语言名称分别成立。概念可以无语言名称使用；各语种名称和读音变化不改变概念定义、身份或上下位。名称适用语言必须与目标词条正式语言一致，不得靠一条关系把同一词条改解释为其它语言。

词条读音由 2200 及 4240 的词条结构服务承载；名称确需限定读音时，由名称关系服务保存名称关系到其目标词条读音关联的具名适用关系，完整规则见 7220。该关系有自身身份、来源和生命周期，不加入概念签名，不更改原名称角色或词条唯一键。退出前核验适用引用，不能让名称指向另一词条的读音，或把同形多音词的全部概念与全部读音无条件组合。

## 4. 一词多义与一义多名

```text
同一词条 -> 多个概念候选        一词多义
同一概念 -> 多个词条名称        一义多名
```

候选数大于一时，数据服务返回确定排序的完整集合，不得猜选首项；候选数为一也只证明名称关系唯一命中，不自动证明语境理解、现实对象识别或业务结论。

名称结构服务始终返回未过滤的完整当前名称候选。`DATA` 外业务必须逐项读回候选概念的本体根和正式强类型材料，再结合本次语言位置、句法关系和上下文缩小或排序；没有类型材料或上下文不足时保持未理解或保留完整候选，不得根据词面、外部词性标签或首项猜选默认根、概念或对象类型。

## 5. 词索引边界

词索引唯一负责从 2200 规范键召回词条身份。概念反向名称索引可以从当前名称关系确定重建，用于从词条召回概念候选；两类索引均不是权威事实。

索引命中后必须回读词条、名称关系和概念身份。索引缺失、清空或重建不得改变任何词条、名称关系或概念事实；索引与权威结构矛盾时丢弃索引并回源，不得反写权威事实。

## 6. 写入权和层次

`DATA-L2` 中的词条和名称关系服务只校验稳定身份、关系形状、角色、语言、生命周期、幂等和引用完整性。是否接受某个名称、是否属于同一概念、当前语境选择哪个概念，由 `DATA` 之外的语言理解或概念业务服务裁决后形成强类型请求。

概念名称服务不得创建或改义目标概念，不得以名称关系替代概念签名；概念服务也不得把自由文本直接写成概念名称而绕过词条规范化。

## 7. 名称裁决依据与绑定边界

名称关系只能由 DATA 之外的概念名称绑定业务在取得具名、可核对的名称裁决材料后提交。裁决来源分为两种：既有名称候选的语境消歧；显式指定已发布概念的首次命名或新增译名。后者按 7220 核验概念、命名输入与来源，不要求新词先已有名称关系，不能由词面自动造概念。请求同时给出概念、词条、名称角色、适用语言、绑定幂等身份及完整裁决来源；没有依据、多义未解、上下文不足或端点未正式读回时，零名称变化。裁决材料为值式结果，不新建持久裁决证据节点。

绑定业务只调用具名语言、词条和概念名称结构公开入口；写入后必须按名称关系、按概念和按词条正式读回并互证。成功只证明一条已裁决名称关系在两端当前结构中闭合，不证明自然语言理解、对象真实性或概念唯一性；概念和词条均不得由名称绑定业务创建。

默认汉语及其它生产语言身份必须由语言结构服务的正式结果和按登记键、按身份读回形成。语言登记键、词面、名称、索引和进程内缓存均不是语言身份权威。

## 8. 禁止事项

- 禁止建立“语素入口节点”“词到语素入口组成关系”“语素对应信息关系”“语素概念追溯关系”或任何介于词条与概念之间的中间身份。
- 禁止以名称关系、索引或首项命中裁决概念唯一性或目标类型。
- 禁止旧“语素对应信息”“概念追溯”或通用对应关系参与名称绑定。
