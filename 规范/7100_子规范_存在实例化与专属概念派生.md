# 7100 子规范 存在实例化与专属概念派生

编号：7100
日期：20261105
版本：v3.1
状态：正式子规范

直接上级规范：1140。

直接依赖规范：1130、2220、7160。

相关边界规范：7110、7150、4200、4240、2210。

## 1. 定位

本规范展开1140第4节的前两步：普通存在如何实例化，以及有特征后如何派生并同步其专属存在概念。与既有中间层或抽象概念的匹配、归类和共同上位归纳属于7110，不是实例化前提。

存在根概念是先天建立的四本体根之一（2220），代表没有具体特征的存在。概念先于实例的要求由先天存在根天然满足，不要求为每次实例化另先匹配或建立概念。

## 2. 实例化

1. 普通存在由场景owner在明确的直接所属场景内建立（1140第2节）。
2. 建立时可以零特征。零特征存在的概念引用就是存在根本身，尚无专属存在概念；它只在“存在”层次可匹配、可归类。
3. 未知不等于明确缺失：不为补齐定义补零、补空项，也不以任何“通用存在”默认概念代替存在根。
4. 建立请求同时给出初始特征时，存在节点、实例特征、初始状态挂接和专属概念派生属于同一次业务变化，整体发布。

## 3. 派生专属概念

存在首次取得实例特征时，派生其专属存在概念：

1. 专属概念的直接上位为存在根；后续经7110归纳后可改挂到中间层概念之下。
2. 专属概念的定义由两组组成：
   - 自身特征组：该存在全部实例特征的当前确定值及其当前所属特征概念，以正式特征类型为键，同一类型至多一项；
   - 已知子存在概念组：该存在当前已知直接子存在各自的概念引用（专属概念或存在根）。
3. 专属概念只属于该存在，按所属存在维护。即使两个存在已记录的特征暂时完全相同，也不合并两个专属身份，不复用其它存在的专属概念，也不为区分而人为增加特征；同义复用只适用于可共享的类别概念（2220）。
4. 存在与其专属概念之间以唯一概念引用关联；该引用不等于父子存在组成边、概念上下位边或世界支持边。

关系类型、组成角色、关系端点、场景位置、实例编码、名称、缓存和日志都不进入专属概念定义。

## 4. 同步

1. 实例特征当前值或所属特征概念变化、新增或解除已知子存在、子存在概念变化时，原地更新专属概念的两组定义。
2. 更新后已不能包含该专属概念的上位关系解除，专属概念改挂到仍包含它的最近合法上位；没有时挂回存在根。
3. 同步与触发它的特征值更新、状态挂接属于同一次业务变化，整体发布（1140第5节）。
4. 专属概念同步不自动触发归纳；中间层归纳按7110。

## 5. 识别与归类边界

把一个存在归入已有中间层或抽象概念，是识别与归类步骤，按7110执行。识别时：

1. 只比较可共享的类别概念；候选必须完整读回定义，索引、名称、局部特征相同或相似度都不构成命中。
2. 候选匹配要求特征类型集合相同、每项实际值被候选值域包含，且子存在概念组相容。
3. 在全部匹配候选中选择全部互不包含的最具体者，分别建立上位边；存在概念图是多父无环图（1140、7110），一个存在同时属于两个互不包含的类别概念是合法多上位，不是内部不一致。零个匹配保持原上位。不得按编号或首项只取其一。

识别结果只改变专属概念的上位关系，不合并存在实例，也不改变存在的身份。

## 6. 不属于本路径的事项

本路径不得：

1. 扫描新增实例以外的世界存在寻找共同概念；
2. 由名称、显示分类、索引命中或关系角色生成概念；
3. 把父子存在组成边改写为概念上下位边，或由概念边补造实例；
4. 以未发布实例、未来子存在或缓存作为定义端点；
5. 以概念匹配代替存在身份识别或合并世界实例。

## 7. 验证语义

验证至少覆盖：

1. 零特征存在以存在根实例化、无专属概念；
2. 首次取得特征派生专属概念并以存在根为直接上位；
3. 专属概念包含当前确定值、当前所属概念及已知子存在概念组；
4. 两个存在特征暂同时专属概念不合并；
5. 特征或子存在变化时原地同步，失效上位边解除；
6. 识别得到多个互不包含的最具体候选时全部建立上位边，被其包含的较宽候选不建边；
7. 存在—专属概念引用不与组成边、上下位边或世界支持边混用。

## 8. 退役口径

下列口径退出新生产：

- “先完整匹配概念、再建立实例”的强制顺序；
- 多个实例复用同一具体存在概念作为各自概念；
- “通用存在／不预设特征”默认概念及“零约束不复用存在根”；
- 零上位概念构成“根链投影”而非挂在存在根下；
- 将组成角色、关系类型或参与角色作为存在概念定义。

旧路径名“存在概念首次形成与实例创建闭环”只作迁移定位。
