# 1170 根规范 动态节点

编号：1170
日期：20260828
版本：v0.4
状态：正式根规范

## 1. 根定位

动态节点承载状态迁移和动作致变事实，是抽象动态、状态迁移账和动作动态账的统一事实对象。“变化”是动态抽象的最高兜底根名，“抽象动态”是匹配、筹办和规范表达使用的有效抽象单元；不得另设并列“动态模板根”。

动态只记录已经发生的状态序列、来源及其业务引用，不承载特征当前值。特征实例唯一当前属性槽指向的当前值事实才是业务比较权威；不得把最后写入动态、动态后状态、动态时间或动态目录顺序解释为当前值。

## 2. 本项目承载

```text
动态节点及稳定句柄
+ 动态域类型化记录中的发生时间和必要非拓扑原始材料
+ 场景和主体关系
+ 被改变目标关系
+ 前状态和后状态关系
+ 可选来源动作关系
+ 来源低层动态、层级、聚合方式和路径签名
+ 场景事实目录关系与定位索引
```

上述动态事实关系的专用类型、角色和基础基数由 4210 规定；动作致变动态的来源动作和同源账基数由 4220 收紧。来源动作必须指向合法方法动作入口或领域服务动作事实。线程、调度器、外部输入、日志和界面不得成为来源动作。

## 3. 事实与边界

1. 动态本体必须保存有序状态引用、发生时间、材料类别和生命周期；主体、场景、被改变目标、用途及来源解释由独立强类型关系承载，不进入成员状态本体。动作致变动态还必须通过正式关系保存合法来源动作；没有动作证据的被动变化不得伪造方法动作。
2. 外部变化只能记录为观察动态或外部事件动态，不得伪装成自我方法动作。
3. 原子动态是零散事实切片，通过场景动态目录归属，不得挂入场景、存在、特征或状态普通子结构形成动态历史树。
4. 简单动态可以聚合成复杂动态，但聚合只能形成动态域内部的来源证据链，不改变原子动态的场景归属。
5. 基础事实池或索引登记不构成业务世界树层级或动态聚合层级。

## 4. 写入、读取与验证

DATA 之外的业务组合方负责裁决主体、场景、被改变目标和来源动作是否满足本次业务语义，再把规范化结构请求提交给唯一动态结构服务。动态结构服务只验证成员状态存在、顺序、时间语义、关系端点、基数、生命周期、代次和幂等，并发布动态节点、动态域类型化记录、关系和索引；不得在 DATA 内形成业务许可、目标满足或动作成功结论。

有效实例动态必须回读相同主体和场景下的前后状态、非零发生时间、被改变目标，以及与来源动作是否存在相一致的关系证据。内部结构缺口属于内部逻辑错误，不得包装成普通动态缺失。

动态可以触发或定位某个特征需要重新检查，但消费者必须先冻结非零事实截止，重新读取目标涉及的当前特征值和目标状态合同后比较。动态前值、后值及其状态记录只能作为历史、来源、变化解释和审计证据，不能直接形成自检、需求满足或目标差距结论。

## 5. 生命周期与当前性

动态事实创建后不可通过覆写改变历史。聚合版本、来源事实版本或动作身份变化时必须形成新版本或新聚合结果；旧动态仍可按稳定身份回查。动态索引裁剪只改变目录可见性，不删除动态事实。
