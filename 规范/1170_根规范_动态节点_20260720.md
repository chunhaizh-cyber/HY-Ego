# 1170 根规范 动态节点

编号：1170
日期：20260909
版本：v1.1
状态：正式根规范

## 1. 根定位

动态节点描述一个确定主体已经发生的一次变化或一组变化。动态只保存变化事实及其直接组成来源，不保存特征当前值，不承担变化识别、概念形成、因果判断或任务完成判断。

动态内容由唯一动态数据服务拥有；动态在何处发生、如何归入场景实例树，由场景数据服务维护。两类事实分别发布、分别读回并在应用层互证。

## 2. 固定字段

动态本体固定为以下四项逻辑信息：

| 字段 | 必要性 | 含义 |
| --- | --- | --- |
| 动态节点身份 | 必需，恰一 | 一次原子变化或一份组合变化的稳定身份。 |
| 主体存在 | 必需，恰一关系 | 本动态直接描述的存在；不是观察者、创建者或动作来源。 |
| 变化内容 | 必需，恰一分支 | 原子分支或组合分支，二者互斥。 |
| 名称概念引用 | 可选，至多一项 | 动态采用的动态概念名称；由概念结构 owner 管理，不由动态数据服务写入。 |

原子分支保存同一主体、同一属性上下文中的前状态、后状态及两端完整使用绑定。组合分支保存非空直接子动态集合及每个成员的组成角色，不另造总体前后状态。实际起止时间从原子端点或组合成员派生，不形成可独立改写的时间字段；场景根和组织归属不是动态字段。

## 3. 不变量

1. 原子动态恰有两个有向端点，前后状态不同，前时间严格早于后时间；两端必须在同一正式特征类型、同一主体、同一属性上下文和同一发生场景下形成完整使用绑定。
2. 组合动态至少有一个直接子动态。直接成员身份不得重复，组成来源图必须无环；成员的真实主体、端点、时间、间隔和场景事实保持不变。
3. 组合动态的主体必须能够由全部成员直接证明：成员与组合主体相同，或成员主体是组合主体的正式组成存在。不能仅凭同场景出现建立共同主体。
4. 动态主体、变化分支、端点、直接成员及组成角色一经发布不可原地修改。修正必须形成新动态。
5. 同一规范化内容允许按幂等合同精确复用；内容相同不证明是同一次发生，也不强制不同观察合并为同一身份。
6. 动态只记录已经发生且材料完整的变化。首态、无变化、时间冲突、绑定不完整或无法比较均不得伪造动态。

## 4. 数据服务边界

动态数据服务只负责：

- 创建原子动态和组合动态；
- 按身份读取当前或历史完整内容；
- 按主体、状态端点、直接子动态和组成来源执行有界反向查询；
- 有界展开组合来源；
- 退出动态和执行实例材料清理。

动态数据服务不负责相邻状态选择、数值比较、时间段归组、重复单元提取、概念形成、名称选择、动作归因、因果判断、场景挂接或当前值更新。上述业务由 DATA 之外的应用组合正式服务完成。

逻辑结构、操作语义和实施门禁唯一见4211；精确 C++ DTO、结果、失败枚举、关系编码和装配尚待后继物理合同冻结。动态生成、归组、递归组合和用途见4210；场景完整使用绑定及实例树组织见4202；动作来源扩展见4220；动态概念见7190。

## 5. 生命周期

动态只记录具体发生且内容不可覆写，服从有限TTL、数量上限、引用闭包、墓碑和历史已清理合同。可复用变化模式由7190形成动态概念。组合成员和状态端点仍被活动动态引用时不得先行物理清理。退出动态不删除主体、状态、子动态、概念或场景。

## 6. 禁止事项

- 变化内容只能采用本规范的原子或组合分支，不得增加并列分支。
- 实际时间只能从正式端点或成员派生，不得建立第二时间权威。
- 已发布动态内容不可修改；退出与清理不得级联删除来源。
- 场景身份、观察者、用途、版本、代次、幂等、批次和技术生命周期不得成为动态业务字段。
- 公开关系角色、DTO与操作的精确 C++ 合同不得由实现者从旧代码补造，须在4211所列实施门禁闭合后另行冻结。
