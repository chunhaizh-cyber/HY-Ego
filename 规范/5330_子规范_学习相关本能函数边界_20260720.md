# 5330 子规范 学习相关本能函数边界

编号：5330
日期：20260822
版本：v0.4
状态：正式子规范

## 1. 定位

学习不是独立的现实任务执行系统，也不是能力缺口对象管理器。学习从普通任务运行事实、已有因果事实和当前方法能力判断中提取材料，改变自我内部虚拟数据，形成方法能力变化材料和方法候选；正式方法仍由方法系统按 5340 的发布合同封装、授权和发布。

直接上级规范：3300。

直接依赖规范：3100、3200、5300、5310、5320。

相关边界规范：4310、4330、5090、5210、5230、5250、内部治理闭环与价值回流规范。

本规范只定义学习相关本能函数的职责、输入输出和分流边界，不证明学习代码、方法代际发布或完整治理闭环已经实现。

## 2. 学习与普通任务的关系

普通任务和学习任务不是同一类任务：

| 类型 | 主要目标 | 允许改变 | 不直接改变 |
| --- | --- | --- | --- |
| 普通任务 | 改变现实世界在自我内部的投影 | 目标投影、正式任务实际结果和运行事实 | 学习结论、方法正式版本、价值状态 |
| 学习任务 | 获取或整理自我内部方法能力材料 | 自我内部虚拟数据、学习分析材料和方法候选 | 现实目标、安全值、服务值和正式方法版本 |

普通任务执行天然具有练习功能。普通任务仍按自己的任务、方法、结果和结算合同运行；其运行事实可以被学习分析读取，形成练习材料，但普通任务成功不自动等于学习成功，学习也不回写普通任务完成或价值结算。

## 3. 学习主链与无方法分流

学习材料的主链为：

```text
普通任务运行事实 / 已通过正式学习门禁的方法能力缺失判断结果
-> 学习分析
-> 练习、尝试或因果反推材料
-> 方法能力变化材料
-> 待验证方法候选
-> 方法系统封装与发布新方法代际
```

只有以下完整判断和门禁可以作为无方法学习分流输入：

```text
目标特征类型有界粗召回完整为空
-> 方法能力缺失判断结果
-> 3100 / 3200 的正式学习门禁全部满足
-> 经需求统一入口形成无可执行方法的未闭合学习需求
-> 形成学习任务或合法学习承接
-> 练习、尝试或因果反推
```

粗召回非空但完整适用判断全不兼容形成的`当前无适用方法`、方法结构缺口、多候选待选择、预算不足、当前性漂移、对象概念待形成、采用方法条件未满足、输入规格或限制待绑定都不得形成学习需求，只能进入各自具名合法等待、补齐或非成功分支。

学习函数不得绕过需求统一入口直接创建正式任务、方法首或能力对象。候选可以有多个，但当前任务每个筹办轮次只能形成一条当前活动方法路径；学习候选不等于当前路径。

## 4. 三类学习本能函数

学习本能函数按缺少的信息类型分为：

1. 练习：已有方法可执行，但需要通过真实运行重复和整理提高稳定性、参数范围或条件结果可信度。
2. 尝试：已有动作或方法入口存在，但动作效果、参数范围、条件关系或适用边界尚未明确，通过受控改变输入探索结果关系。
3. 因果反推：任务已由通过正式学习门禁的`方法能力缺失`判断合法进入学习分析后，依据客观因果和自我可控制状态，反推出必要前置状态、可产生状态和可候选动作。

不得再把“定向学习”作为与上述三类并列的旧权责类别；外界观察、信息确认和未归因现象按实际缺失信息归入尝试或因果反推材料，不建立第四类学习 owner。

## 5. 练习本能函数

练习的输入至少包括：

- 已发布或已冻结的目标方法 / 实例方法身份；
- 本轮允许的动作入口、条件和参数边界；
- 普通任务或学习任务的正式运行事实；
- 目标状态、结果事实和共同截止。

练习可以输出：

- 重复运行观察；
- 稳定性和可靠范围材料；
- 条件—结果验证材料；
- 参数组合和新用途候选证据。

练习不得创建方法首、动作入口、正式方法版本、需求或能力缺口对象；不得把一次成功、次数统计或日志显示直接写成能力事实。练习材料进入学习分析和方法系统后，才可能由独立发布合同形成后继方法代际。

## 6. 尝试本能函数

尝试的输入至少包括：

- 已知动作或可调用方法入口；
- 尚未确定的条件、参数范围或执行环境；
- 明确的安全限制、实验边界和可观测结果。

尝试只能在受控范围内改变条件或参数并观察结果，输出条件—结果候选、参数范围候选、适用边界和结构化不确定性。它不得以随机动作代替方法，不得把结果名称反向当作动作身份，不得直接登记、覆盖或发布正式方法。

## 7. 因果反推本能函数

因果反推把目标变化需求连接到自我可控制的状态变化：

```text
目标特征变化需求
-> 客观因果关系
-> 必要前置状态
-> 自我可产生状态
-> 自我动作 / 工具 / 构造能力
-> 方法能力变化材料
-> 待验证方法候选
```

因果反推必须区分：

- 客观因果：世界中什么导致什么；
- 自我能力因果：自我什么动作可以改变什么特征；
- 方法能力：自我如何在条件和限制下稳定复现变化。

因果反推可以使用直接能力、工具能力或构造能力，但不得把客观因果直接当作自我能力，不得凭单条因果关系发布稳定方法，也不得直接生成正式方法或修改安全值、服务值。

## 8. 学习相关本能函数的统一边界

所有学习相关本能函数都必须先满足 5310 的自身方法环境合同，并通过正式方法召回和当前任务合同取得合法输入；不得按本能名称、编号、标签或固定动作键特判。

函数输出只能属于以下之一：

- 学习运行事实；
- 学习分析材料；
- 方法能力变化材料；
- 待验证方法候选；
- 无可执行方法的未闭合学习需求承接材料；
- 具名的合法等待或结构化非成功结果。

这些输出不得直接表示任务完成、需求满足、价值结算、安全值变化或正式方法发布。学习只改变自我内部虚拟数据；正式方法结构和代际由方法系统唯一发布，当前运行中的实例方法不得被学习原地改写。

学习侧可消费的“无可执行方法”只能来自任务目标当前未完成、目标特征粗召回完整为空的`方法能力缺失`判断，且 3100 / 3200 正式学习门禁已经全部通过。`当前无适用方法`、预算不足、当前性漂移、对象概念待形成、方法结构待补齐、多候选待选择证据以及采用方法的条件 / 输入 / 限制待形成或待绑定均不得进入学习。上述判断结果不是节点、关系、候选对象、owner、压力实体或持久化数量事实；任何学习分流不得建立能力缺口节点、能力缺口关系、能力缺口 owner 或“能力缺口数量”。

## 9. 验证与完成边界

规范级验证应覆盖：

- 普通任务运行事实可被学习分析读取且不改变普通任务结论；
- 练习、尝试和因果反推的输入分流与输出边界；
- `方法能力缺失`携带完整空粗召回证据并通过正式门禁后经需求统一入口形成学习需求 / 学习任务；`当前无适用方法`及其它等待或非成功分支不误入学习；
- 候选可以多条但当前活动方法路径每轮至多一条；
- 候选不得自证晋级，学习不得直接发布方法；
- 全流程不建立能力缺口节点、关系、owner 或数量事实；
- 学习不直接改变现实目标、安全值、服务值或价值结算。

本规范不证明：

- 学习相关本能函数已经实现或接入生产；
- 学习任务已经形成完整代码闭环；
- 方法能力变化材料已经发布为新方法代际；
- 普通任务、学习任务和价值回流已经完成跨域集成验收。
