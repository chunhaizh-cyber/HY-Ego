## 1. 定位

本规范冻结 `DATA-EXT-12` `L2需求结构服务` 的唯一所有权、共同 DTO、核心生命周期、依赖方向、事务、读取、父子结构和退出边界。现行 C++ `L2*` 类型与服务名称保持真实 ABI；已经由 `L2结构公共.数据.h` 冻结的 `L2需求身份`、`L2节点族::需求`、`L2结构请求头`、`L2结构结果头`、`L2结构幂等身份`、`L2生命周期` 和 `L2结构状态` 继续作为本合同共同基础。

需求结构不属于 4230 六类世界结构。需求、任务和方法属于 `DATA-L2` 的治理记录结构，不改写场景、存在、特征、状态、动态和因果六类世界结构服务的职责，也不形成第七个“世界”数据服务。

需求是**某一个存在拥有的长期目标契约**。只有存在可以拥有需求；`自我`在本结构层仍首先是一个 `L2存在身份`，是否具有当前自我资格由 `DATA` 之外业务层裁决。`L2需求结构服务`只保存“该需求属于哪个存在”的强类型结构事实，不判断某个存在是不是自我，也不建立“自我需求”第二节点族、第二 owner 或第二需求服务。

需求的核心目标保持单目标：

```text
所属存在
+ 目标宿主存在
+ 目标特征定义
+ 目标状态合同
```

其中：

- `所属存在`回答“这是谁的需求”；
- `目标宿主存在`回答“希望哪个存在发生目标变化”；
- `目标特征定义`回答“希望目标宿主的哪一方面变化”；
- `目标状态合同`回答“该特征应达到什么目标状态以及采用什么正式比较合同”。

`所属存在`与`目标宿主存在`是两个独立角色。二者允许相同，例如“自我要求自身安全特征达到目标状态”；也允许不同，例如“自我要求外部对象的位置特征达到目标状态”。不得把二者合并为一个字段或由调用语境猜测。

本规范只冻结需求的**纯结构层**：

```text
需求节点及稳定身份
+ 需求所属存在引用
+ 目标宿主存在引用
+ 目标特征定义引用
+ 目标状态合同引用
+ 需求父子关系
+ 生命周期
+ 身份来源
+ 当前 / 历史读取
+ 原子新增、引用替换、父子关系变更和退出
```

3100 中的来源证据、逻辑路径、路径当前性、权重、授权、满足动态和正式结算证据仍属于完整需求体系，但**不在本规范 v0.2 中提前冻结公开 DTO 或写入口**：

- 来源候选、来源归因、入树治理由 5100、5130—5150 及其后继结构合同承接；
- AND / OR 路径、当前性、权重、授权和任务化闸门由 5110 及其后继结构合同承接；
- 正式结算记录及唯一 `已满足` 结论由 5160 及其后继结构合同承接；
- 当前满足由 `DATA` 之外业务层读取当前事实与目标状态合同后实时裁决，不作为 `L2需求事实` 的永久字段。

本规范不建立第二需求数据服务、第二事实仓、第二目标解释、第二关系解释或兼容业务门面。

本规范不定义具体 CRUD 函数体、模块实现、骨架、装配或施工顺序。后继实现只能细化本规范已经冻结的合同；尚未由本规范或后继合同冻结最终 DTO 的能力不得先发布万能参数、临时结构或动态编号。

## 2. 需求事实形状

### 2.1 `L2需求事实`

`L2需求事实` 固定包含：

```text
L2需求身份 身份
L2存在身份 所属存在
L2存在身份 目标宿主存在
L2特征定义身份 目标特征定义
L2目标状态合同身份 目标状态合同
L2生命周期 生命周期
```

#### 2.1.1 所属存在

每个当前需求必须恰好属于一个当前有效 `L2存在身份`。

`所属存在`是需求身份语义的稳定组成部分：

- 需求创建时必须明确；
- 不允许为空；
- 不允许由名称、调用线程、当前自我缓存、任务身份或父需求反推；
- 普通更新不得把一个已存在需求改属于另一个存在；
- 若业务上需要另一个存在拥有同目标需求，应形成另一个需求身份，由上层需求治理决定其来源、授权和关系，不得原地替换所属存在。

`自我需求`不是独立结构类型。当 `DATA` 之外业务层已经正式确认某个 `L2存在身份` 为当前自我时，该存在拥有的需求可被上层解释为自我需求；L2需求结构服务不保存“是否自我”。

#### 2.1.2 目标宿主存在

目标宿主必须是合法 `L2存在身份`。需求服务必须经 `L2存在结构服务` 的公开身份来源或完整读取证明其属于正式存在节点族。

所属存在与目标宿主存在可以相同，也可以不同；两种角色不得互相替代。

#### 2.1.3 目标特征定义

目标特征必须是合法 `L2特征定义身份`。需求服务必须经 `L2特征结构服务` 的公开身份来源或完整读取证明其属于正式特征定义节点族。

需求服务不判断该目标特征在业务上是否值得追求，也不直接比较该特征的原始值。

#### 2.1.4 目标状态合同

目标状态必须使用独立 `L2目标状态合同身份`，不得由实例状态身份、裸 `I64`、枚举底值、显示文本或缓存值替代。

需求服务必须经 `L2状态结构服务` 的公开读取证明该目标状态合同身份合法。

目标状态合同内部已经冻结目标特征、比较注册、目标值、允许关系位、规则版本、来源和生命周期时，4250 不再建立第二个“需求级满足关系字段”。满足关系由目标状态合同和 `DATA` 外正式判断收束共同表达，避免双重权威。

#### 2.1.5 当前状态材料与目标场景

当前状态材料不是 `L2需求事实` 的永久当前值字段。需求当前是否满足必须由 `DATA` 外业务层在本次裁决时读取目标宿主、目标特征及其当前状态材料，并与目标状态合同比较。

需求创建时所使用的当前状态、目标场景或观察上下文若需要作为来源证据长期保留，必须由后继来源证据结构合同以具名关系或不可变材料引用保存；不得把“当前状态”复制进 `L2需求事实` 后长期冒充当前世界事实。

目标场景若业务目标明确要求固定场景约束，由后继需求上下文结构合同冻结；4250 v0.2 不用可空普通字段提前占位，也不允许调用方从当前宿主场景缓存隐式补齐。

### 2.2 需求所属存在关系事实

底层持久结构必须能够证明：

```text
需求 -> 所属存在
```

后继 DTO 至少应能值式回读：

```text
关系稳定编码
L2需求身份 需求
L2存在身份 所属存在
L2生命周期 生命周期
```

该关系与需求节点、需求族归属关系在需求新增时由需求 owner 的一个 owner-scoped 写集原子建立。

一个当前需求恰有一个当前所属存在关系。重复、缺失、错 owner、错端点、错类型或混代属于 `内部不一致`，不得降级为合法空、未找到或业务拒绝。

### 2.3 需求目标引用事实

底层持久结构必须分别证明：

```text
需求 -> 目标宿主存在
需求 -> 目标特征定义
需求 -> 目标状态合同
```

三种引用是彼此独立的强类型关系，不允许用一个普通引用关系混装后靠运行期标签解释。

每个当前需求：

- 恰有一个当前目标宿主引用；
- 恰有一个当前目标特征定义引用；
- 恰有一个当前目标状态合同引用。

任一引用缺失、重复、错端点、错 owner、错关系类型或混代均属于 `内部不一致`。

### 2.4 需求父子关系事实

`L2需求父子关系事实` 固定包含：

```text
稳定编码 关系稳定编码
L2需求身份 父需求
L2需求身份 子需求
std::uint64_t 顺序
L2生命周期 生命周期
```

结构不变量：

1. `父需求 != 子需求`；
2. `顺序 != 0`；
3. 一个当前子需求至多有一个当前直接父需求；
4. 同一父需求的当前直接子关系顺序不得重复；
5. 父子关系不得形成结构环；
6. 根候选只表示“当前没有父关系”，不因此取得管理需求、执行需求、主需求或其它业务资格；
7. 父子关系只表达需求结构展开，不决定 AND / OR、路径支撑、角色、任务化资格或满足关系；
8. 父子关系不改变父需求或子需求各自的所属存在。跨所属存在父子结构在本 DATA 合同中只按强类型端点和无环规则处理；其业务是否允许由 3100、5100、5110 或后继业务规则裁决，4250 不自行发明“跨存在委托”语义。

### 2.5 父子关系类型身份

需求 owner 内必须存在唯一不可变 `L2需求父子关系类型身份` 对应的正式关系类型节点。

父子关系固定为：

```text
源节点 = 父需求节点
目标节点 = 子需求节点
关系类型 = 需求父子关系类型
角色或顺序 = 非零顺序
关系 owner = 需求 owner
```

该关系类型与需求族归属关系类型严格分账，二者不得互相替代。

本规范不要求额外建立“父子关系锚点节点”。若后继实现需要登记父子关系类型，必须复用需求 owner 已冻结的结构类型登记机制；不得仅为定位关系类型增加没有独立结构职责的装饰性节点。

## 3. 唯一所有权与身份来源

### 3.1 需求 owner

唯一公开所有者为 `L2需求结构服务`，DTO 物理所有者为 `L2需求结构.数据.h`。

需求节点族使用独立 `DATA-L1` 技术 owner。需求 owner 只拥有需求节点、需求族归属证明、需求所属存在关系、三项单目标引用关系和需求父子关系等本合同授权结构。

需求 owner 内固定存在：

```text
需求族锚点节点
需求族归属关系类型节点
需求父子关系类型节点
需求所属存在关系类型节点
目标宿主关系类型节点
目标特征定义关系类型节点
目标状态合同关系类型节点
```

其中：

- 族锚点与族归属关系类型用于证明 `L2需求身份`；
- 其它关系类型只用于本规范授权的需求结构；
- 这些都是需求 owner 私有结构元数据，不是公开业务需求节点；
- 它们不得取得需求身份，也不得被普通需求读取入口当成需求返回。

每族初始化使用只属于需求 owner 的固定非零建立幂等身份和完整写集幂等身份；数值域不得与其它节点族复用。

一个需求 owner 当前只能有一组需求族来源登记和一组本规范关系类型登记。第二活动登记或同一结构角色出现不同当前关系类型属于 `内部不一致`。

### 3.2 族归属关系

每个公开需求节点创建必须在同一 owner-scoped 写集内同时建立唯一族归属关系：

```text
源节点 = 本次公开需求节点
目标节点 = 需求族锚点节点
关系类型 = 需求族归属关系类型节点
角色或顺序 = 1
关系 owner = 节点 owner = 关系类型 owner = 族锚点 owner = 需求 owner
```

该关系不是需求父子关系，不是业务拓扑、标签、索引、缓存或第二身份仓。

`L2需求身份`只有在以下材料共同成立时成立：

```text
精确需求 owner 事实
+ 公开需求节点
+ 指向精确需求族锚点的唯一归属关系
+ 精确需求族归属关系类型
+ 需求公开服务读回
```

普通稳定编码、强类型包装、节点种类、名称、本地键、属性 / 关系数量、缓存定位或 legacy 投影均不能单独证明需求身份。

### 3.3 身份来源读取

需求服务必须公开唯一需求身份来源读取：

```text
L2需求结构服务::读取需求身份来源
```

请求至少包含：

```text
L2结构请求头
L2读取类别
L2需求身份
历史截止事实代次（历史读取时非零）
```

结果至少包含：

```text
L2结构结果头
L2读取类别
历史截止事实代次
optional<L2节点族身份来源事实>
```

当前读取必须在一次 owner-aware 一致当前投影内核对：

```text
owner 事实
公开需求节点
需求族锚点
需求族归属关系类型
唯一需求族归属关系
```

全部材料共享请求的非零期望事实代次和同一事实截止。

历史读取以具名历史截止重建上述身份来源材料，隐藏晚于截止的未来退出；截止早于需求节点创建返回 `未找到`，截止达到创建后返回 `已读取` 和历史截止投影。已经在截止前退出的需求仍可通过历史入口携带完整退出生命周期。

当前入口对已退出编码固定返回 `已退出` 且空载荷，不补读历史判族。

对当前仍可读节点：

- 属于另一 owner；
- 属于需求 owner 但没有唯一需求族归属；
- 属于 legacy / 裸 L1 普通节点；
- 属于需求 owner 的内部锚点、关系类型节点或其它元数据节点；

固定返回 `入口拒绝`、空载荷、零变化。

归属关系重复、错 owner、错锚点、错类型、错角色或生命周期不闭合属于 `内部不一致`。

## 4. 操作合同

### 4.1 登记需求结构类型

需求服务必须能够幂等建立并正式读回：

```text
需求族锚点
需求族归属关系类型
需求父子关系类型
需求所属存在关系类型
目标宿主关系类型
目标特征定义关系类型
目标状态合同关系类型
```

所有类型均属于需求 owner 私有结构元数据。

同一固定幂等身份、同一完整登记请求返回 `精确重复` 和首次结果；同一固定身份对应不同写集返回 `幂等冲突`。

### 4.2 新增需求结构

请求固定包含：

```text
L2结构请求头
L2结构幂等身份
L2存在身份 所属存在
L2存在身份 目标宿主存在
L2特征定义身份 目标特征定义
L2目标状态合同身份 目标状态合同
optional<L2需求身份> 父需求
父子顺序（有父需求时非零）
```

不包含：

```text
需求合理性
主需求标志
当前满足标志
AND / OR 类型
路径权重
任务化资格
活动授权
正式结算结果
```

这些均不属于 4250 基础 DATA 结构新增判断。

写前必须使用同一期望事实代次分别经公开结构服务验证：

```text
所属存在 -> L2存在结构
目标宿主存在 -> L2存在结构
目标特征定义 -> L2特征结构
目标状态合同 -> L2状态结构
可选父需求 -> L2需求结构自身身份来源
```

如果存在父需求，还必须写前验证：

```text
父需求当前有效
新增父子边不形成结构环
同父当前顺序不重复
```

成功写集原子包含：

```text
需求节点
需求族归属关系
需求所属存在关系
目标宿主关系
目标特征定义关系
目标状态合同关系
可选父子关系
```

成功返回：

```text
已提交
或
精确重复
```

并携带：

```text
完整 L2需求事实
需求身份来源
optional<L2需求父子关系事实>
共同事实截止
```

幂等只按“同幂等身份 + 同完整结构请求”成立。

**L2需求结构服务不得按目标语义扫描既有需求并决定复用或合并。**  
5110 的同目标复用、合并、去重属于 `DATA` 之外需求治理。若上层决定复用既有需求，应直接读取和使用既有 `L2需求身份`，而不是让 4250 创建入口执行业务去重。

失败分账：

- 合同版本错误、零幂等身份、零或错类型强引用：`入口拒绝`；
- 目标引用不存在或已退出：按公开引用校验合同返回对应结构化非成功，不建立半结构；
- 父子成环、顺序冲突或违反单父：`引用冲突`；
- 同键异完整请求：`幂等冲突`；
- 期望代次变化：`事实代次漂移`；
- L1 资源分配或提交资源问题：`资源失败`；
- 发布后读回与已发布写集矛盾：`内部不一致`。

### 4.3 读取单需求

请求固定包含：

```text
L2结构请求头
L2读取类别
L2需求身份
历史截止事实代次（历史读取时非零）
```

成功返回：

```text
L2结构结果头
L2读取类别
历史截止事实代次
optional<L2需求事实>
optional<L2需求父子关系事实> 当前 / 截止父关系
optional<L2节点族身份来源事实> 需求身份来源
```

当前读取必须在同一 owner-aware 一致投影中闭合：

```text
需求身份来源
所属存在引用
目标宿主引用
目标特征定义引用
目标状态合同引用
父关系 optional
```

全部子材料共享同一非零事实截止。

历史读取只按具名历史截止重建，不得拿当前关系补历史缺项。

### 4.4 完整需求结构读取

完整读取是 4.3 的稳定值式组合，不扩张业务语义。

结果至少包含：

```text
L2需求事实
需求身份来源
父关系 optional
```

4250 v0.2 的“完整”只表示本规范负责的核心需求结构闭合，不包括：

```text
来源证据组
活动路径
AND / OR 组
权重
授权
任务承接
满足动态
正式结算证据
当前满足结论
子需求递归展开
祖先链
```

这些内容由各自后继合同独立读取，再由 DATA-L3 或 DATA 外业务在同一截止上组合。

### 4.5 按所属存在有界读取当前根需求结构组

L2基础入口命名固定面向结构角色：

```text
按所属存在有界读取当前根需求结构组
```

而不是“按自我读取”。

请求至少包含：

```text
L2结构请求头
L2存在身份 所属存在
数量预算
```

只支持当前读取。调用方若需要“当前自我根需求”，必须先在 `DATA` 之外获得已经正式确认的当前自我 `L2存在身份`，再把该存在身份作为普通所属存在传入本入口。

成功返回：

```text
已读取
稳定排序的完整当前根需求结构组
共同非零事实截止
```

根需求定义为：

```text
当前属于指定存在
且
当前没有父需求关系
```

排序按 `L2需求身份` 内部稳定编码升序。

合法空：

```text
没有任何匹配根需求
-> 已读取 + 空组
```

预算不足：

```text
匹配数量超过调用方非零预算
-> 数量预算不足 + 空载荷
```

`数量预算不足`必须先由共同 `L2结构状态` 正式合同冻结后使用；若上级公共合同尚未登记该状态，本规范不得单独定义第二枚举值。

### 4.6 读取父子关系

提供两类结构读取：

```text
按父需求读取当前直接子关系组
按子需求读取当前父关系
```

当前读取返回共同非零事实截止。

- 按父需求读取允许空组；
- 按子需求读取允许空 `optional`；
- 一个当前子需求读出多条父关系属于 `内部不一致`；
- 组结果稳定排序，优先按 `顺序`，顺序相同本就属于结构不一致。

历史父子读取必须显式使用 `L2读取类别::历史` 和非零历史截止。

### 4.7 替换目标引用

所属存在不可替换。

4250 v0.2 允许后继实现分别提供以下原子引用替换：

```text
替换目标宿主
替换目标特征定义
替换目标状态合同
```

每次替换请求必须包含：

```text
L2结构请求头
L2结构幂等身份
L2需求身份
旧关系稳定编码
旧目标身份
新目标强类型身份
```

写前验证新目标身份来源；成功时同一 owner-scoped 写集退出旧关系并建立新关系。

目标语义变化是否仍应保留同一需求身份属于 3100、5100 的业务规则。若上层业务规则要求目标变化建立新需求，业务层不得调用本结构替换入口。4250 只定义“若调用方已经有权请求结构替换时”的原子结构行为，不授予业务调用资格。

### 4.8 替换父需求

请求必须明确：

```text
L2结构请求头
L2结构幂等身份
L2需求身份 子需求
optional<旧父关系稳定编码>
optional<L2需求身份> 旧父需求
optional<L2需求身份> 新父需求
新顺序
```

合法操作包括：

```text
根 -> 非根
非根 -> 根
非根 -> 另一父需求
```

服务只校验结构：

```text
父子端点合法
单父
非零顺序
同父顺序不冲突
无环
期望代次
幂等
```

不判断为什么要转挂、是否应该转挂或转挂后的业务角色。

成功时旧父关系退出与新父关系建立同代原子发布。

### 4.9 退出需求

退出请求必须包含：

```text
L2结构请求头
L2结构幂等身份
L2需求身份
需求族归属关系稳定编码
所属存在关系稳定编码
目标宿主关系稳定编码
目标特征定义关系稳定编码
目标状态合同关系稳定编码
optional<当前父关系稳定编码>
```

第一版退出规则固定：

1. 当前需求存在任一当前直接子需求关系时，返回 `引用冲突`，整笔零变化；
2. 当前需求作为子需求存在当前父关系时，允许在同一退出写集中退出该父关系；
3. 当前需求所属存在、目标宿主、目标特征和目标状态合同引用必须与需求节点和族归属同代退出；
4. 族锚点、族归属关系类型和父子关系类型不随单个需求退出；
5. 需求已退出时，重复退出按首次幂等请求收敛；不同请求不得用“已经退出”冒充同义幂等；
6. 退出后当前读取返回 `已退出` 或对应当前不可见结果，历史入口仍可读取完整生命周期；
7. 本入口不得隐式把当前子需求转成根、转挂给其它父需求或同时退出子需求。若未来需要“父需求及其子树批量退出 / 转挂”，必须另立独立结构合同。

## 5. 后继结构合同边界

### 5.1 来源证据

4250 v0.2 不冻结 `来源证据（属性槽或关系引用）` 这种二选一占位。

需求来源必须由后继合同明确：

```text
具体 DTO
具体关系类型
具体端点类型
基数
顺序
生命周期
当前 / 历史读取
退出保护
```

在此之前，L2需求新增请求不得用自由属性槽或普通稳定编码临时承载来源证据。

业务层是否允许形成正式需求仍必须遵守 3100、5100、5110、5130—5150；4250 的纯结构新增成功不证明需求合理或来源业务有效。

### 5.2 路径、权重、当前性和授权

AND / OR 路径、路径当前性、权重、预算、授权、任务化闸门和路径领取由 5110 及其后继结构合同承接。

4250 不预留：

```text
bool 是否活动
bool 是否授权
I64 当前角色
I64 路径类型
自由权重字段
```

也不提供“读取活动路径”“发布活动事实”这种未冻结最终 DTO 的公开入口。

### 5.3 正式结算

5160 的正式结算需要需求、目标合同、来源任务、实际状态、动态证据和可选因果证据。

因此正式结算不得塞回基础 `L2需求结构服务` 形成反向依赖。

后继结算结构合同必须保持单向依赖，例如：

```text
L2需求结算结构
    -> L2需求结构
    -> L2任务结构
    -> L2状态结构
    -> L2动态结构
    -> L2因果结构
```

或按后继正式规范冻结的等价无环依赖。

`DATA` 外需求领域仍是正式结算业务提交方；数据结构服务只保存调用方已经形成的强类型结算记录，不判断需求是否满足。

## 6. 依赖方向

4250 基础需求结构依赖固定为：

```text
L2需求结构
    -> L2存在结构公开读取
        - 验证所属存在
        - 验证目标宿主存在

L2需求结构
    -> L2特征结构公开读取
        - 验证目标特征定义

L2需求结构
    -> L2状态结构公开读取
        - 验证目标状态合同

L2需求结构
    -> L1事实基座

DATA-L3 聚合
    -> L2需求结构公开面
        - 只读组合
        - 零写入所有权
```

禁止：

```text
L2需求结构 -> 场景服务
L2需求结构 -> 动态服务
L2需求结构 -> 因果服务
L2需求结构 -> 任务服务
L2需求结构 -> 方法服务
```

若某个后继需求相关结构需要任务、动态、因果或其它数据，只能建立新的单向后继结构合同，不能把依赖反塞回基础需求结构服务。

跨族身份验证必须调用目标族公开身份来源或完整读取；不得直达 L1 重演存在、特征或状态节点族证明。

---

## 7. 共同事务、幂等与读取

1. 每次新增、引用替换、父关系替换或退出由需求唯一 owner 形成一份不可变 owner-scoped L1 中性写集，并恰一次提交。
2. 需求节点创建、族归属、所属存在引用、目标宿主引用、目标特征引用、目标状态合同引用和可选父子关系必须同代原子发布，不允许先写裸需求节点再补关系。
3. 一份请求取得首次结果后，其 `L2结构幂等身份` 与逐字段完整请求绑定。后继完全相同请求返回 `精确重复` 和首次原结果；同一已绑定身份用于不同完整请求返回 `幂等冲突`，零变化。
4. 只有结构化 `事实代次漂移` 且明确零变化、无首次结果时，幂等身份保持未绑定；调用方正式重读后可以使用同一幂等身份形成新的完整请求。
5. 资源失败、异常或发布结果未知时只能以原幂等身份和原完整请求读回收敛，不得生成新身份、删减字段或重写语义后重试。
6. 跨族写前身份来源读取使用同一期望事实代次；其后本族提交仍以该代次为期望。期间任何权威发布由 L1 以 `事实代次漂移` 阻止混代提交。
7. 当前组合读取必须使用 L1 owner-aware 一致当前投影；需求节点、身份来源、所属存在引用、三项目标引用和父关系必须共享一个非零事实截止。
8. 历史读取必须显式使用 `L2读取类别::历史` 和非零历史截止；不得使用当前事实补历史缺项。
9. 当前入口严格区分 `未找到`、`已退出`、`属性未设置`、`许可拒绝`、`事实代次漂移`、`资源失败` 和 `内部不一致`；不得为了调用方便折叠为 bool。
10. 任一成功结果缺项、身份复义、同一结果混代、关系角色矛盾、重复单例引用或发布后读回矛盾均返回 `内部不一致`，停止依赖路径。
11. 条件查询和完整读取必须复用同一需求身份来源判断；禁止先在一个代次证明需求身份，再从另一代次拼装所属存在或目标引用。

---

## 8. 引用保护与退出

1. 退出请求必须显式处理 4250 本结构拥有的全部当前附属关系，不得按名称或业务含义自动推断需要退出的引用。
2. 当前存在直接子需求关系时，父需求退出固定返回 `引用冲突`；数据层不得自动把子需求提升为根。
3. 当前父关系允许与子需求自身退出同代闭合。
4. 后继来源证据、路径、任务承接或结算结构对需求形成引用时，引用保护由其各自结构合同和 L1 当前引用闭包共同承接；基础需求服务不得反向 import 全部后继消费者。
5. 退出成功只改变当前可见性并保留完整历史。物理回收、崩溃恢复和跨进程恢复不属于需求普通 CRUD。
6. 需求族锚点、需求族归属关系类型和需求父子关系类型不随单个需求退出。
7. 任何“父需求退出 + 子需求批量退出 / 转挂”“跨存在需求迁移”“需求 owner 改属”都不属于 4250 v0.2 普通退出合同。

## 9. 实际消费与施工检查边界

需求结构真实实现由合法消费者通过正式公开强类型入口、结构化结果和权威读回判断当前所需能力是否可用。

施工期间的临时专项至少覆盖：

1. 合法需求结构新增后完整当前读回；
2. 所属存在、目标宿主、目标特征、目标状态合同四个强类型引用完整且同截止；
3. 零身份、错类型、坏引用、旧期望代次等非法请求结构化非成功且权威状态零变化；
4. 同键同完整请求精确重复、同键异请求幂等冲突；
5. 当前 / 历史读取不混代；
6. 需求 owner 唯一，需求族身份来源完整；
7. wrong-family、同 owner 内部锚点、关系类型节点、 legacy 与裸 L1 普通节点均不能冒充需求身份；
8. 需求节点、族归属、所属存在、三项目标引用和可选父关系同代原子建立；
9. 父子关系单父、无环、非零顺序、同父顺序唯一；
10. 父关系替换后新关系当前、旧关系历史可读；
11. 有当前直接子需求时退出冲突且零变化；
12. 无当前子需求时退出需求及其本结构自有引用同代闭合，当前不可见、历史仍可查；
13. 按所属存在有界读取根需求组稳定排序、合法空组和预算不足分账；
14. 数据结构服务没有判断需求合理性、当前满足、主需求、任务化资格、AND / OR、权重、授权或正式结算。

临时检查驱动不得编译进生产目标，不得取得 L1 / L2 私有仓、锁、候选或事务权限，不得构造“真实自我”“安全需求已满足”“主需求已选中”等业务剧本。

构建、日志、自检、骨架、退出码和未观察到错误只证明相应工程事实，不替代合法消费者实际使用判断。

## 10. 完成边界与禁止事项

本规范生效只证明 `DATA-EXT-12` 需求核心结构的正式所有权、核心 DTO、身份来源、单目标引用、父子关系、依赖、事务、读取和退出边界已经冻结。

不证明：

```text
任一模块或函数已经实现
CRUD 已经完成
生产接线已经完成
需求治理入口已经实现
来源证据结构已经实现
需求树 AND / OR 已经实现
权重和授权已经实现
任务化已经实现
正式结算已经实现
当前满足已经成立
自我需求树已经运行
业务闭环已经完成
```

禁止：

- 在 `L2需求结构服务` 判断需求是否合理、是否应该创建、是否满足、是否为主需求、是否可任务化；
- 建立 `L2自我需求`、自我需求 owner、自我需求服务或其它第二需求体系；
- 让“当前自我”成为 L2需求结构的特殊节点类型；自我在本层只作为普通 `L2存在身份` 被上层传入；
- 把 `所属存在` 与 `目标宿主存在` 合并；
- 原地替换需求的 `所属存在`；
- 从特征、状态、日志、线程、任务缺口或外设输入自动形成正式需求；
- 让 L2需求结构按目标语义扫描并自动复用、合并或去重需求；
- 把当前满足、主需求、AND / OR、路径活动、授权或结算结论写成需求节点普通 bool / I64 字段；
- 在来源证据、路径、授权或结算最终 DTO 尚未冻结前，以“属性槽或关系引用”二选一占位发布公开 ABI；
- 让基础需求结构服务依赖任务、方法、动态、因果或场景服务；
- 直达目标族的 L1 私有仓、锁、事务、SQL、材料目录、缓存或内部写集重演跨族身份证明；
- 用节点到自身关系、普通节点形状、名称、本地键、强类型包装、缓存或 legacy 投影证明需求身份；
- 把目标状态合同身份替换为实例状态身份或裸值；
- 用编译、日志、单条成功路径或 `未实现` 宣称需求结构服务完成；
- 恢复旧需求业务门面、旧需求登记、旧需求查询口或第二事实仓。

## 11. 待同步上级公共合同

4250 使用共同 `L2结构状态`。

若当前正式 4230 文本仍只冻结至：

```text
内部不一致 = 14
```

而当前正式 C++ `L2结构公共.数据.h` 已存在：

```text
数量预算不足 = 15
```

则在 4250 正式登记前，必须先把 4230 的共同枚举同步为当前正式 ABI，或明确由更高优先级现行规范承接该值。4250 不单独重定义共同状态数值。
