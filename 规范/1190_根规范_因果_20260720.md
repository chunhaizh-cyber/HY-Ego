## 1. 定位与边界

因果信息描述已经多次出现的“条件和可选动作与结果状态之间的参考规律”。它用于预测、规避、探索和为复杂方法查找可尝试的本能方法，不保证结果必然发生。

因果信息不是以下对象：

- 不是一次具体发生本身；
- 不是状态、动态或动作事实的副本；
- 不是候选因果概念；
- 不是“已验证必然规律”；
- 不是方法执行结果或任务完成证明；
- 不是无需读回现实结果即可直接执行的授权。

现行模型不建立独立“因果实例类”和“概念_因果类”。每个正式因果节点本身就是可持续修正统计的抽象参考规律。

本规范取代旧因果实例、候选概念和必然规律模型。规范正式成立不声明生产装配、运行闭环或跨启动恢复已经完成。

## 2. 因果信息组织根

因果信息使用全局基础数据集中的独立组织根：

```cpp
extern 稳定编码 新因果信息图根节点;
```

所有正式因果节点以外部父子关系挂在该根下，关系角色固定为因果根成员。该根不属于世界树、需求树、任务集合或方法组织根。

因果根只组织正式因果节点。第一次发生保留的形成材料不建立节点，也不挂入因果根。

## 3. 因果类型

```cpp
enum class 新因果类型 : std::int64_t {
    未知动作 = 1,
    已知动作 = 2
};
```

### 3.1 未知动作因果

结构为：

```text
条件状态和/或条件动态
-> 结果状态
```

它说明某些条件与结果反复共同出现，但当前不知道、没有识别或不需要记录导致结果的动作。

未知动作因果可用于：

- 在条件出现后预测结果；
- 为规避某结果提前采取其它措施；
- 主动建立或等待条件并观察结果；
- 为后续动作探索提供参考。

未知动作因果不能直接提供可执行方法。

### 3.2 已知动作因果

结构为：

```text
条件状态和/或条件动态
+ 动作
-> 结果状态
```

已知动作因果必须保存动作概念和执行主体。作用部位、作用对象及本能方法只在确实已知时保存。

已知动作因果用于查找可尝试方法时，必须同时满足：

1. 目标结果状态相同；
2. 因果动作已经绑定本能方法节点；
3. 当前条件由上层另行检查；
4. 方法执行后重新读取现实状态并登记真实结果。

## 4. 因果定义

```cpp
struct 新因果定义 {
    新因果类型 类型;
    std::vector<新因果状态模式> 条件状态组;
    std::vector<新因果动态模式> 条件动态组;
    std::optional<新因果动作定义> 动作;
    新因果状态模式 结果状态;
};
```

因果定义至少包含一个条件状态或一个条件动态，并且恰好包含一个结果状态。

规则如下：

- 未知动作因果不得保存动作定义；
- 已知动作因果必须恰好保存一个动作定义；
- 条件状态组内部去重并按稳定内容排序；
- 条件动态组内部去重并按稳定内容排序；
- 因果建立后当前代码不自动扩大、缩小或重写定义；
- 新发生只会命中既有定义并更新统计，或者参与形成另一个正式因果。

## 5. 状态模式

```cpp
struct 新因果状态模式 {
    稳定编码 被描述存在节点;
    稳定编码 特征类型概念节点;
    新特征准确值 准确值;
};
```

状态模式从正式状态节点读回形成，固定保存：

- 发生该状态的实际存在节点；
- 状态保存的特征概念身份；
- 状态发生时的固定准确值。

当前状态模式是准确匹配，不自动执行以下抽象：

- 实际存在到存在概念的提升；
- 具体特征概念到类型根的提升；
- 准确值到值域概念的提升；
- 相似值或包含值域匹配。

因此，两个状态模式只有三个字段完全相同才属于同一个模式。后续若需要概念化状态模式，必须新增明确的抽象步骤，不能在读取时静默改变已经发布的因果定义。

## 6. 动态模式

```cpp
struct 新因果动态模式 {
    稳定编码 主题存在节点;
    稳定编码 动态概念节点;
};
```

动态模式从正式动态实例读回形成。动态实例必须已经引用动态概念；只保存主题存在和动态概念，不复制动态状态链、二次特征或时间材料。

两个动态模式只有主题存在和动态概念均相同才属于同一模式。动态概念的上下位包含、相似度或进一步抽象当前不参与因果形成匹配。

## 7. 动作定义与动作依赖

```cpp
struct 新因果动作定义 {
    稳定编码 动作概念节点;
    稳定编码 执行主体存在节点;
    std::optional<稳定编码> 作用部位存在节点;
    std::optional<稳定编码> 作用对象存在节点;
    std::optional<稳定编码> 本能方法节点;
};
```

动作必须具有：

- 一个动作概念节点；
- 一个执行主体存在节点。

可选信息包括：

- 执行动作的身体部位或其它作用部位；
- 动作作用对象；
- 自我可以实际调用的本能方法。

自我真实执行本能方法形成的动作事实，与根据外部存在动态推断出的动作，必须通过显式动作证据提供者接入：

```cpp
class 新因果动作证据提供者 {
public:
    virtual std::optional<新因果动作定义> 读取自我动作事实(...) const noexcept = 0;
    virtual std::optional<新因果动作定义> 推断外部动作(...) const noexcept = 0;
};
```

未装配动作证据提供者时，动作事实和外部动作路径必须返回`依赖未配置`，不得虚构动作、主体或方法。

## 8. 发生记录

```cpp
struct 新因果发生记录 {
    稳定编码 发生身份;
    稳定编码 场景节点;
    std::vector<稳定编码> 前置状态节点组;
    std::vector<稳定编码> 前置动态节点组;
    稳定编码 结果状态节点;
    std::optional<稳定编码> 结果动态节点;
    std::optional<稳定编码> 动作证据节点;
};
```

发生记录是一次处理调用的输入，不是正式因果节点。

### 8.1 发生身份

上层必须为同一次现实发生提供统一、非零且当前存在的节点身份。结果状态筛选、结果动态反向、动作事实反向和外部动作动态反向四条路径识别到同一次发生时，必须传入同一个发生身份。

正式因果保存已经计数的发生身份。相同身份再次提交返回`重复发生`，不重复增加任何统计。

当前因果类只验证发生身份节点存在，不验证它属于哪一种业务节点，也不自行判断两个不同节点是否代表同一次现实事件。发生身份的正式生产者和唯一性合同仍待上层实现。

### 8.2 场景

发生记录必须携带一个当前存在的场景节点，用于表明所有前置材料和结果来自同一场景语境。

当前代码只验证该节点存在，没有调用场景类核验前置状态、动态和结果是否真实属于该场景，也没有把场景写入因果定义。场景成员一致性属于当前明确缺口。

### 8.3 前置窗口

前置状态和前置动态由上层选择并传入。因果类不扫描场景列表，也不自行决定时间窗起点、终点、最大长度或噪声过滤规则。

结果状态本身会从前置状态组排除；结果动态会从前置动态组排除。任一前置节点无法完整读回时整次发生处理失败。

## 9. 四种形成来源

```cpp
enum class 新因果形成来源 {
    结果状态筛选,
    结果动态反向,
    动作事实反向,
    外部动作动态反向
};
```

### 9.1 结果状态筛选

当结果状态出现时，上层提交前置窗口。因果类按结果状态分组，对不同发生窗口求共同条件。

### 9.2 结果动态反向

从结果动态向前追溯。输入必须给出可读结果动态，并且结果状态必须是该动态包含的状态之一。

### 9.3 动作事实反向

自我本能方法真实执行后，由动作事实提供者读回动作定义，再与前置条件和结果状态共同参与因果形成。

### 9.4 外部动作动态反向

从外部存在的动作动态推断动作定义，再与前置条件和结果状态共同参与因果形成。推断得到的外部动作不冒充自我真实动作事实。

同一正式因果可以记录多个形成来源，但同一次发生不因多个来源而重复计数。

## 10. 两次发生形成算法

正式因果至少需要两个不同发生身份。

### 10.1 第一次发生

若没有既有正式因果匹配，也没有可与之形成共同条件的历史发生：

```text
规范化结果状态、动作、前置状态和前置动态
-> 保存为进程内待形成材料
-> 返回“已记录首例”
```

第一次发生不建立候选节点、不进入因果根、不建立候选概念，也不增加正式因果统计。

该材料只存在于当前进程内。发生身份节点消失时会被清理；进程结束后不会恢复。跨启动积累尚未实现。

### 10.2 同类发生分组

两次发生只有满足以下条件才进入同一形成分组：

- 结果状态模式完全相同；
- 动作定义完全相同，或者两次都没有动作。

条件集合本身不要求完全相同，因为形成算法需要从不同条件集合中提取共同部分。

### 10.3 求共同条件

```text
共同状态 = 第一次前置状态集合 ∩ 第二次前置状态集合
共同动态 = 第一次前置动态集合 ∩ 第二次前置动态集合
```

只要共同状态或共同动态至少有一项，即可发布正式因果。两者都为空时返回`无共同条件`，不强行建立因果。

当前交集使用准确模式相等，不使用相似度、值域包含、概念上下位或近似时间关系。

### 10.4 发布

正式发布一次建立：

- 因果节点及类型；
- 共同条件状态项；
- 共同条件动态项；
- 可选动作项；
- 唯一结果状态项；
- 一个或多个形成来源；
- 两个已计数发生身份；
- `符合出现次数 = 2`；
- 其它三个统计初始为零；
- 因果根成员关系。

任一步失败时逆序清理本次字段、关系和节点。完整读回成功后才返回`已建立`。

## 11. 既有因果匹配

一次新发生匹配既有因果需要：

- 结果状态完全相同；
- 动作定义完全相同；
- 既有因果的每个条件状态均存在于本次前置状态集合；
- 既有因果的每个条件动态均存在于本次前置动态集合。

本次发生可以含有额外条件。额外条件不自动加入既有因果定义。

若多个既有因果同时匹配，选择条件项总数最多的最具体因果；条件数量相同时选择稳定编码较小者。只更新这个因果，不同时更新所有匹配因果。

已有因果命中时增加符合出现次数，并按需补充新的形成来源。发生身份已经计数时返回`重复发生`。

## 12. 因果统计

```cpp
struct 新因果统计 {
    std::int64_t 符合出现次数;
    std::int64_t 不符合出现次数;
    std::int64_t 自我尝试次数;
    std::int64_t 自我尝试符合次数;
};
```

### 12.1 普通观察统计

`登记因果发生结果`登记一次新的普通观察：

- 符合时增加`符合出现次数`；
- 不符合时增加`不符合出现次数`；
- 无论哪一种结果都保存发生身份并参与去重。

### 12.2 自我尝试统计

`登记方法执行结果`只适用于具有已知动作且已经绑定本能方法的因果。每次合法登记：

- 总是增加`自我尝试次数`；
- 符合时增加`自我尝试符合次数`和`符合出现次数`；
- 不符合时增加`不符合出现次数`；
- 保存统一发生身份并参与去重。

四项统计只是经验材料，不自动产生概率、置信度、正确等级、验证状态或执行资格。

### 12.3 统计不变量

任一完整因果必须满足：

- 符合出现次数至少为2；
- 四项计数均非负；
- 自我尝试符合次数不大于自我尝试次数；
- 已计数发生身份数量等于符合出现次数与不符合出现次数之和；
- 所有计数增加都进行I64溢出保护。

## 13. 查询能力

当前公开查询包括：

```cpp
获取因果(...)
是因果节点(...)
根据结果状态查询(...)
根据条件状态查询(...)
根据动作概念查询(...)
为目标状态查询方法参考(...)
```

前三类业务查询均执行准确相等匹配，不自动包含上下位概念或相似模式。

`为目标状态查询方法参考`只返回：

- 结果状态完全等于目标状态；
- 动作定义存在；
- 本能方法节点存在。

结果按以下顺序排列：

```text
符合出现次数 - 不符合出现次数，降序
-> 因果稳定编码，升序
```

这只是当前简单排序，不是正式可信度公式。它不考虑样本总量比例、时间衰减、场景适用范围、损耗、安全限制或方法可执行性。

## 14. 方法使用边界

### 14.1 已知动作因果

上层可以按目标状态召回方法参考，但必须继续执行：

```text
读回因果定义
-> 检查当前条件
-> 检查方法和参数是否可执行
-> 执行本能或组合方法
-> 读回真实结果状态
-> 用统一发生身份登记符合或不符合
```

因果命中不是方法授权，也不证明结果已经发生。

### 14.2 未知动作因果

未知动作因果不返回方法节点。上层只能用它预测、规避、等待、建立条件或发起探索，不能伪造一个动作执行。

### 14.3 复杂方法形成

因果信息可以作为自我用本能方法形成复杂方法的参考材料，但当前因果类不自动建立、修改或发布组合方法，也不把因果节点直接当作方法步骤。

## 15. 读回一致性

任一成功读回的正式因果必须满足：

1. 因果节点在因果根下恰有一个成员关系。
2. 节点类型和因果类型各恰一。
3. 条件状态和条件动态至少有一项。
4. 结果状态恰一。
5. 未知动作没有动作项；已知动作恰有一个动作项。
6. 所有状态、动态模式项的类型和字段完整。
7. 所有被引用节点当前存在。
8. 形成来源非空、合法且无重复。
9. 四项统计满足第12.3节。
10. 已计数发生身份无重复且数量与普通统计总数相等。

任一项不成立时，不返回部分因果信息，按结构不一致处理。

## 16. 非成功状态

当前操作状态区分：

```text
已记录首例
已建立
已更新
已找到
无匹配
重复发生
入口拒绝
尚未初始化
状态不存在
动态不存在
动作证据不存在
依赖未配置
无共同条件
因果不存在
计数溢出
结构不一致
资源失败
```

`无共同条件`不表示系统错误，只表示当前两次结果发生无法提取共同前置材料。`重复发生`表示该发生身份已经参与正式计数或已经作为首例等待形成，不得再次计数。

资源失败、结构不一致、依赖未配置和入口拒绝不得伪装成“没有因果关系”。

## 17. 并发、事务和生命周期

新版因果类使用进程内递归互斥保护本类操作，并使用基础数据集的节点、字段和关系函数组织信息。

多步发布和统计更新采用尽力逆序恢复。当前没有：

- 跨进程事务；
- 崩溃原子性；
- 技术幂等请求键；
- 发布未知恢复；
- 跨启动待形成材料恢复；
- 因果删除、淘汰或统计衰减；
- 因果定义修订和旧定义迁移；
- 引用计数或外部引用保护。

正式因果一旦建立，当前代码不会删除。后续淘汰策略至少需要考虑使用情况、符合与不符合统计、最近使用时间、是否被方法引用及是否存在更具体替代因果；本规范当前不冻结算法。

## 18. 非权威实现能力

当前代码已经具备：

- 独立因果信息组织根；
- 未知动作和已知动作两种因果；
- 状态模式、动态模式、动作定义和结果状态的结构化保存；
- 四种形成来源入口；
- 第一次发生进程内暂存；
- 两个独立发生求共同条件并直接发布；
- 既有因果最具体匹配；
- 跨发现路径发生身份去重；
- 四项经验统计；
- 三类准确查询和方法参考查询；
- 动作依赖未装配时显式失败；
- 单翻译单元和隔离主工程构建通过。

## 19. 非权威实现缺口

当前尚未具备或没有证明：

- 上层自动选择结果之间的完整前置窗口；
- 场景成员、时间边界和前后关联的正式核验；
- 统一发生身份的正式生产者；
- 动作事实类、外部动作识别及动作证据提供者生产装配；
- 状态模式从实例身份和准确值向存在概念、特征类型根和值域概念抽象；
- 动态概念上下位包含参与因果匹配；
- 多于两次发生的集合交集持续修正；
- 已发布因果定义扩大、缩小、分裂、合并和分层抽象；
- 概率、置信度、时间衰减、场景适用范围和反例权重算法；
- 因果链、动作反转、反事实推演和自动复杂方法生成；
- 因果删除、淘汰、引用保护和跨启动恢复；
- 自我线程、任务线程、方法执行器与因果服务的生产接线；
- 运行测试、恢复测试和业务闭环验收。

## 20. 验证要求

后续专项验证至少覆盖：

1. 第一次发生只返回`已记录首例`且不建立因果节点。
2. 两个不同发生身份具有共同状态条件时建立未知动作因果。
3. 两个不同发生身份具有共同动态条件时建立因果。
4. 没有共同条件时不发布因果。
5. 相同发生身份经不同路径提交只计数一次。
6. 结果状态或动作定义不同不会错误归入同一形成分组。
7. 多个既有因果匹配时选择条件最多的最具体项。
8. 已知动作缺执行主体、节点失效或提供者未配置时明确失败。
9. 符合、不符合及自我尝试四项计数正确，重复发生不增加。
10. 计数溢出、字段缺失和引用节点失效返回具名错误。
11. 三类查询只返回完整因果，结构损坏时不返回部分结果。
12. 方法参考只返回绑定本能方法的已知动作因果并按当前排序规则排序。
13. 发布中途失败不留下可读的半因果节点。
14. 隔离主工程继续包含并成功编译三个新版因果文件。
