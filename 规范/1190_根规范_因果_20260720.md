## 1. 根定位

因果信息是系统依据已经发布的状态、动态、动作及场景事实，从多次相同或相似变化中筛选、确认并概念化得到的客观变化规律。它回答“在什么条件下，是否还需要什么动作，必然形成什么结果状态”，不保存某一次具体发生，不建立独立因果实例类，也不把时间先后、重复相邻或相关性直接冒充因果。

正式因果信息本身即为概念化规律。其本体结构引用存在概念、特征概念、动作概念及合法值/值域规则；动作概念是归入2220动态概念根的主动变化抽象，不建立独立动作概念根。具体存在、状态、动态和动作实例只能作为形成与验证证据，不能进入因果本体字段、完整定义或唯一性判断。

## 2. 两类因果

因果类型固定为：

| 类型 | 完整表达 | 含义 |
| --- | --- | --- |
| 主动因果 | 条件概念集合 + 动作概念 -> 必然结果状态模式集合 | 系统已经识别结果成立所需的主动动作；条件单独成立不足以产生结果 |
| 被动因果 | 已知条件概念集合 -> 稳定结果状态模式集合 | 系统尚未识别、无需在本次用途展开或已经简化掉动作/中间机制，但在已知适用范围内观察到稳定变化规律 |

“主动/被动因果”描述规律中动作部分是否显现；“被动发现/主动寻找”描述取得规律的方式，二者正交，不得混用。被动因果不声明自然界没有动作或机制，也不得把未知动作伪造为默认动作。

主动因果的“因”由条件与动作共同成立。被动因果只能在已知适用范围内表达稳定预测，不得因有限样本宣称无限范围的绝对必然。后继发现动作时建立与原被动因果有补完来源关系的主动因果，不改写原始事实证据。

## 3. 固定逻辑字段

正式因果信息固定由下列逻辑字段组成：

```text
因果信息身份
+ 因果类型
+ 参与者概念角色集合
+ 非空条件概念项集合
+ 可选动作概念项
+ 非空结果状态模式集合
+ 可选相对时序约束
+ 可选简化 / 补完来源因果引用
```

除此以外，不得把具体实例、样本计数、失败计数、置信度、成功率、用途、需求、任务、方法、名称、批次、幂等、事实代次、对象版本或生命周期复制为因果对象的业务字段。L1/L2内部可靠读写、发布和结构生命周期仍按0050及4230执行，但不改变上述因果逻辑字段。

### 3.1 参与者概念角色

参与者使用有序、具名角色槽表达；每个角色槽至少具有非零角色、确定顺序和一个存在概念约束。角色槽不是具体存在，也不得由名称代替。两个角色引用同一存在概念不表示它们是同一参与者；同一/不同参与者约束必须显式表达。

条件、动作和结果只能引用已经声明的角色槽。实际应用时由调用方把角色槽临时绑定到具体存在，绑定不形成持久因果实例。

### 3.2 条件概念项

每个条件项固定表达：

```text
参与者角色
+ 特征概念
+ 判断规则
+ 值 / 值域 / 关系约束
```

同一因果信息中的条件项默认按合取共同成立。互不等价的析取分支分别形成因果信息，不把任意布尔表达式、自由文本或具体状态身份装入一个条件字段。

### 3.3 动作概念项

主动因果必须且只允许一个直接动作概念项：

```text
动作概念（归入动态概念根）
+ 执行者角色
+ 可选作用对象角色
+ 可选参数约束
```

多个有序动作应先形成复合动作概念或由因果链、方法组织，不在一条直接因果内隐式保存动作序列。方法函数是动作的可执行描述；只有实际调用并发生作用才形成动作事实。因果规律引用动作概念，不引用某次函数调用、方法身份、流程名、日志或成功返回值。

被动因果不保存动作概念项。已知动作因用途简化而省略时，必须保留到原主动因果或原因果链的简化来源，不能伪装成已经解释完整的直接规律。

### 3.4 结果状态模式

每个结果状态模式固定表达：

```text
结果承担者角色
+ 特征概念
+ 结果值 / 值域 / 相对形成规则
+ 可选形成时限
```

状态不建立独立概念类型；因果结果以存在概念角色、特征概念和合法值式约束描述将形成的状态模式。固定值、规范化值域及可复算的相对形成规则均可使用。结果不得引用某次具体状态，也不得由预期结果直接补造世界事实。

因果信息保存当前证据支持的全部必然客观结果。哪些结果是自我需要、可忽略、副作用、风险或收益，只能由需求、方法、安全及其它业务应用在调用期判断，不得反写因果本体。

### 3.5 时序与来源

时序只保存因果成立不可缺少的相对约束，例如动作后、结果先后或形成时限；固定时间戳属于具体事实，不进入规律字段。

简化 / 补完来源只引用已经发布的因果信息或可回查因果链结构，用于说明中间动作、机制或链段为何被省略或后来补全。来源关系不改变原因果含义，不把间接因果冒充直接因果。

## 4. 事实证据与零因果实例

状态记录具体时点事实，动态记录具体存在已经发生的变化，动作事实记录某次实际主动作用。因果类在任务局部把这些事实按角色、场景和时间组织为候选材料，经重复筛选和确认后发布概念化因果信息。

项目不建立因果实例节点、因果样本节点、因果证据组节点或平行因果账。正式因果信息可以通过具名形成/支持关系引用具体状态、动态和动作事实；这些引用只证明规律的来源与支持，不使任何单次观察成为因果本体字段。需要复盘一次发生时，按证据锚点和事实截止回读原状态、动态、动作及场景，不复制成因果实例。

候选、角色绑定、场景复现、统计、排序、预测结果和方法材料均为调用方拥有的值式对象。未发布候选不得被查询为正式因果；预测状态只有被现实观察并经状态服务发布后才成为事实。

## 5. 形成、确认与可用边界

因果形成至少经过：

```text
读取已发布事实
-> 形成任务局部候选
-> 对齐概念角色、条件、动作和结果
-> 正反样本与反例筛选
-> 条件最小化和适用范围确认
-> 规范化完整定义并查重
-> 发布或复用因果信息
-> 关联来源证据并完整读回
```

单次观察、时间先后、名称相似、概念命中或统计阈值均不足以确认因果。主动因果优先通过同条件下执行/不执行动作的干预与对照确认；被动因果只能确认在当前已知范围内的稳定预测能力，并保留寻找动作和缺失条件的入口。

有限事实不能证明无限范围的绝对必然。出现反例时必须重新检查缺失条件、动作完整性、适用范围和结果观察；必要时形成更窄的新因果、补完主动因果或停止使用错误规律，不得删除或改写原始状态、动态和动作事实来维持规律。

形成、确认、主动历史寻找、场景复现和因果类能力由4310展开；证据关系、候选边界和旧观察账退役由4330展开。

## 6. 因果链与应用边界

因果链由一个或多个已发布因果信息按“上游结果状态模式能够满足下游条件概念项”有向连接。连接必须保存参与者角色映射并核验特征、值域、时序和适用范围；仅有时间相邻不能连接。

一条因果链可以混合主动因果与被动因果。主动因果条件满足后仍需实际动作，链本身不执行动作。因果链支持由因求果、由果查因、事实解释、风险传播和规律简化；方法根据信息需求选择因果链、检查自我能力并组织动作，因果链不替方法作目标、价值、安全或执行裁决。

稳定且可复用的链结构可以接入2220的因果链概念根；本次目标搜索得到的层次、路径、角色实例绑定和展开结果只作值式投影。持久结构不保存间接因果边、固定层号或查询路径。详细规则由4320展开。

## 7. 因果类操作边界

因果类的业务能力固定覆盖：

```text
被动发现因果候选
主动寻找历史因果候选
确认并发布 / 复用因果信息
读取完整因果信息及形成证据
临时绑定参与者角色并判断适用
由因求果
由果查因
简化 / 展开因果
补完被动因果
接收新事实并重新核验反例
```

DATA-L2因果结构服务只机械保存、读取和校验调用方已经裁决的完整强类型结构，不扫描世界事实、不判断规律真实、不形成候选、不执行动作、不创建状态、不选择方法。具体业务算法与数据结构owner必须分层；数据类公开C++ DTO、函数名、关系角色、事务顺序和迁移拒绝由4340冻结，不能从本根规范自行猜测；4310业务算法仍与数据ABI及依赖实现分账。

## 8. 禁止事项

1. 禁止建立独立因果实例类或把具体状态、动态、动作、存在身份写入因果本体字段。
2. 禁止把动态等同于最小因果；动态只说明变化，因果说明规律。
3. 禁止把时间先后、重复出现、共同出现或相关分数直接当作因果成立。
4. 禁止把被动因果解释为客观上不存在动作或机制。
5. 禁止把方法、任务、需求、用途、收益、副作用或自我价值判断写入因果本体。
6. 禁止把预测结果写成已经发生的状态事实。
7. 禁止用名称、字符串、JSON、哈希或版本号代替完整概念化定义。
8. 禁止持久化间接因果、固定链层号或调用期路径。
