## 1. 根定位

特征信息是以独立节点表达“正式特征类型 + 一个准确值”的事实对象。类型和值成立后固定，不随新的观察、宿主采用、概念生成或名称变化原地改写。名称是可完善的概念引用，不参与准确内容同一性。

准确特征新建必须明确自身绑定位置：场景C及组织父P；缺失或无效时入口拒绝，零身份分配、零F、零观察、零概念写。P为强类型场景、存在或父F三选一；物理源分别为C特征根、该E或父F，真实holder分别为C、该E或父F继承的holder。新F内容、holder已知F引用、P到F组织边及对已发布FC的使用引用必须共同发布，不暴露已成立的无父F；具体事务与存量承接由4110、4205展开。状态、动态及名称不是出生前置。相同准确内容可复用，但不得因此改父、移根或隐式复制；相似、同域或同名不证明准确相同。

## 2. 固定逻辑字段

| 字段 | 含义 |
| --- | --- |
| 特征节点身份 | 由 L1 分配的独立稳定节点身份；不是值身份、类型身份或概念身份。 |
| 特征类型 | 一个正式特征定义引用，确定准确值的表示与解释。 |
| 准确特征值 | 一个固定准确值，采用内联 I64 或 2100 类型化值身份引用；类型和完整内容按 4110 校验。 |
| 名称 | 可选的所采用特征概念引用，当前至多一个；不直接复制自然语言文字，不覆盖准确值。 |

前三项构成完整准确内容；新F还必须按明确C/P共同取得位置才能报告建点成立。位置由场景owner组织边唯一承载，不新增F本体父指针或场景字段。概念无词条名称不等于概念未完成；世界新F必须有适用的已发布FC使用引用，名称仍可为空。名称关联由概念结构服务保存；准确特征数据服务不因逻辑字段合并读回而取得概念或名称关系的写权。完整应用视图组合各自公开读取，不建立第二份名称事实。

节点类型沿用通用节点结构。当前观察值、历史值集合、值域集合、命中次数、细分子列表、成熟度以及版本、代次、幂等、批次和生命周期均不作为本对象新增字段。L1 可靠性、引用保护和必要恢复材料仍有效，不因字段简化而删除。

## 3. 当前采用、识别与抽象分工

存在通过自身已知特征引用集合保存已经确认的不同准确特征，通过独立当前采用关系表达本次采用哪个特征；两者按 1140 / 7150 操作。`IF(E,FT)`及R材料按4115组织F，不改变当前采用的唯一性或写入责任。新观察不改写旧特征内容，也不自动删除旧特征。状态可依据固定准确内容形成记录，但状态字段、保存与清理仍服从 1160，不由名称或概念反推准确事实。

同一正式类型的观察由 7160 的共享积累机制处理，不按存在分组；先天和后天类型采用相同机制。域形成、命中计量、概念细分、上下位、完善及淘汰不再属于准确特征数据类。特征分裂树退出，不与特征概念组织并行保留。

上述退出不禁止1150/4202的场景特征实例组织树：该根只管理实例组织，不承担值域分裂或概念分类。F必须有自身绑定位置并可被多方引用；组织父唯一不限制使用引用，不给F添加场景字段，其它使用位置不能冒充F自身位置。

特征概念以“类型 + 规范化值域”定义，特征以“类型 + 准确值”表达内容；即使概念为单点域，两者身份、引用用途与退出仍分开。同概念不证明同一存在，也不证明准确值未发生变化。

## 3.1 纯添加挂靠合同

特征类纯添加请求必须显式给出强类型直接挂靠：场景直接特征、存在内部特征或父特征子节点三选一，并同时给出所属场景语境、直接组织父、非零 G0 和预算。服务按同截止核验父类别、当前性、路径和唯一位置；缺父、父退出、类别不符、位置冲突或漂移均拒绝，禁止扫描或猜测父。相关概念由世界树在调用前通过概念树类查询或创建；特征类接收已经成立的概念身份，建立准确内容、挂靠及引用并完整读回，不生成概念。

## 4. 操作与名称形成

特征数据类按节点提供创建、读取、按类型与准确内容查询及受引用保护的删除；不提供原地修改已成立类型或准确值的普通接口。解除宿主或名称引用不等于删除特征。值引用的底层内容不得被可变缓存、域代表或概念替代。

世界树建立新特征时，先核验C/P和准确输入，再按完整域定义查询或创建相关特征概念，取得身份后才建立对应F及引用；定义或规则不足、概念读取失败不得转为无概念新建成功。已有准确F的观察积累、名称完善和概念图成长仍按7160处理，真实已发布F不因后续治理失败被否定或回滚。概念形成不由特征数据CRUD隐式执行。

## 5. 子规范与退役模型边界

1130 v1.0 之前的旧特征信息合同已退役，其中五字段、当前值改写、历史简化及三次命中特征建子均不得用于新生产；旧代码、数据及公开 ABI 不因本文发布自动成为新模型。实施须按 4110 完成具名迁移与旧入口退役，禁止原地重释旧记录或恢复宿主实例槽。

## 6. 完整结构后继

三父的真实上游场景与组织holder分账：未启用场景视角的E可以有内部F；其上游C从明确世界根下的唯一对象祖先链读取，不能把E编码冒充C。父F继承其真实holder及上游C，组织路径不建立第二对象包含边。类型采用2100四种正式表示，完整值和材料解释按4120/4180；同一FT不换表示。

F组织可按明确旧边和新父迁移，类型、准确值及概念身份不因移动改写；共享引用保持。删除只处理无子F且完整引用保护允许的叶F，不递归删其它owner事实。完整历史位置、四owner出生、迁移与退出的精确合同由本规范及相关边界合同承接，规范发布不等于实现完成。
