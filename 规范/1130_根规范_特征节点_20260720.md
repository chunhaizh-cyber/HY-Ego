## 1. 权威边界

本规范是实例特征的现行机器合同。实例特征以实际值为事实来源；特征概念值域只负责分类、单位和规则选择，不作为实例写入准入域。

旧稿中的“实例准入值域”退出，不得据此拒绝材料类型正确的实际值，也不得恢复第二份概念值域副本。

本文中的历史信息只指某个实例特征实际出现过的去重准确值及其命中次数，不是L1操作历史、事实代次、事务日志或审计账。

## 2. 对象定位与持有关系

新版特征信息是由一个既有节点持有的实例特征节点：

```text
持有节点 --父子关系--> 实例特征节点
```

持有节点可以是存在、场景或其它特征节点。特征类只核验节点和关系，不解释持有者的业务类别。

每个可读回实例特征必须恰有一个外部父节点。当前代码在建立和查询时按“持有节点＋具体特征概念节点”查重；尚未按“持有节点＋特征类型根”强制全类型唯一。该差异作为当前阶段限制保留，不得将其描述为已经实现同类型唯一。

## 3. 准确值承载

现有实现的准确值载体表示为（不据此限制下述逻辑引用类别）：

```cpp
std::variant<std::int64_t, 稳定编码>
```

规则如下：

1. I64标量直接保存在实例特征字段中。
2. U64数组、I64数组、UTF-8字符串、二维二值格和三维二值格先由新版特征值类保存，再引用特征值节点。
3. 非I64材料不得复制为实例节点内部的裸数组或字符串。
4. 写入、读回和比较上述非I64原始材料时，必须确认特征值节点存在、可完整读回且材料物理类型一致。直接信息节点引用按第3.1节处理，不送入原始材料读取路径。

### 3.1 方法、需求、任务的信息引用型特征

存在的方法、任务引用特征保持下述集合合同。服务对象H的需求特征是具名例外：H已建立的需求特征为唯一F，其当前准确值为一个满足既有准入及来源合同的正式被认知需求D引用；尚未建立F或尚无当前值均保持未知，不伪装为空需求或空集合，也不据本规则额外初始化空F。历史按本规范保留实际出现过的去重D及命中信息。D仍由需求owner维护，不复制其内容，不建立H需求树。F当前引用与D内容、完整性及满足性分别读取。

服务对象需求当前值仅在产生新D，或已满足D经正式来源明确再次需要时更新。后者可以切回历史D，也可以当前仍为同D；每次真实需求发生均由特征/存在/世界组合路径自动形成新的正式S，重复处理同一来源只复用原S。读取、字段补全、普通同值命中、任意切换历史D及迁移恢复不构成新的需求发生。完整生产、来源、失败和消费合同见[5170第2.1节](5170_子规范_需求治理详细合同.md#21-服务对象的被认知需求与需求特征)。该例外不赋予本能函数直接建立状态的权限。

除上述H需求特征例外，具名引用集合的准确值是一份完整的同类别节点引用集合；成员分别引用具体方法M、需求D或任务T，保持原稳定身份、内部结构和组织归属，不复制内容、不改造成普通存在。

```text
存在E ──持有──> 特征F ──当前完整集合──> {M1, M2, …} / {D1, D2, …} / {T1, T2, …}
```

对上述仍采用集合的类型，零成员是已知空集，一个成员仍为单元素集合；尚未取得当前值不等于空集。不得按数量在单值与集合间切换，也不通过多个同类型单值特征实例表达多项。现行查重规则不因此自动改变，不声称已实现全类型唯一。服务对象需求单D只适用本节明确的具名例外，其它类别已有的单节点引用能力不变。

每个集合由正式特征类型限定成员类别。方法集合不得接收Vm、C、R或仅在缺失方法列表中的头，任务集合不得接收Vt、X、A，需求集合成员必须是正式D。不能凭非零编码、名称或字段形状猜类别。合法但无条件结果知识的方法可以被引用，身份合法不证明可执行。

仍采用集合者的读取沿“E→F→当前完整集合→按明确条件选择成员→原领域owner”完成。需要一个成员时须核验选择条件及唯一性，不能任选首项或按编码大小猜测。H需求单D读取沿“H→唯一F→当前D→需求owner”完成，发生判断另读真实需求S。特征owner维护F及当前、历史、持有关系，方法、需求、任务owner分别维护M/D/T内容。引用不增加组织父节点，不移动原树归属，不自动授予执行、承接或修改内容的权限。

集合无顺序语义、无重复，规范化顺序仅用于保存和查重；普通U64数组本身不是强类型引用集合。完整集合是一个准确值，历史集合不取并集冒充当前集合。从{M1}变为{M2}表达替换，从{M1}变为{M1,M2}才表达保留原成员并新增。材料只保存成员引用，不复制成员内部结构。

集合变化与成员内容变化分别处理。T1由执行中变为完成时，当前集合可仍为{T1}，状态须经任务owner读取对应Vt；M1增加知识也不要求改变成员编码。集合未变不能推定内容未变，历史集合不冻结成员当时内容；执行冻结及所需快照继续由原领域合同维护。

需求引用遵守主体合同：甲希望水达到40℃，甲的需求特征引用D，D主体为甲、目标存在为水，不因此成为水的需求。各具名引用须明确宿主与目标的业务关系，类别正确不证明该关系成立；引用不改变T与D的一对一约束。

### 3.2 引用发布、生命周期与失败边界

写入和读回必须经目标owner证明节点类别正确、身份有效、该类别所需结构可读，并核验具名宿主关系。实际值不受当前较窄概念值域准入限制的原则保持；目标类别、结构有效性与引用关系合法性是类型及身份约束，不是概念值域准入。超出较窄域不得伪装成错误类别，也不能借实际值原则接收错误节点。

引用正式发布前须建立可阻止目标身份失效的保护，保护与目标退出必须按同一发布边界竞争；不得先清除身份内容再发现仍有引用。当前值、标准值、历史值、有限值域、集合材料及状态等仍保留引用时，相关保护不得提前解除。仅把当前引用替换或移除，不能视为所有来源都已退出。保护不冻结目标的合法内容更新；它保护身份和必需可读结构，不禁止正常任务状态推进或方法学习。

解除引用只解除指定来源的关联，不自动删除被引用M、D、T。目标退出仍由原owner证明全部正式引用已退出；仍被其它来源使用时拒绝破坏性清理。引用替换须在发布新引用时保证目标保护，发布失败不留下无保护引用或错误解除旧保护；发布未知先读回收敛，不能按失败盲目重做。

明确未找到、目标已变化、类型不相容、读取故障、资源失败和发布未知须区分；工程故障按工程诊断链处理，不转成业务“不符合”或合法空集合。底层字段引用或U64数组是否足以保护身份须由具体物理设计证明，规范不凭编码仍存在宣称保护已实现。

比较与范围的唯一详细合同见[7160第5.1、5.3节](7160_子规范_特征概念形成组织与名称关联.md#51-服务对象需求单节点引用)。本节不声明全部引用消费者、保护和迁移已实现。服务对象旧需求集合只依明确迁移合同恢复当前单D、历史D及真实来源，不把迁移派生S解释为新的现实需求发生；方法、任务的旧单引用仍须按明确合同转为单元素集合。不推定额外成员，不将旧ABI、数据或历史执行材料原地改义。

## 4. 实例特征固定信息

实例特征的有效信息为：

| 信息 | 基数 | 含义 |
| --- | --- | --- |
| 节点类型 | 恰一 | 指向共享实例特征节点类型。 |
| 持有节点 | 恰一 | 由外部父子关系确定。 |
| 正式特征概念 | 恰一 | 当前用于分类、单位及规则选择的特征概念。 |
| 实例单位 | 可选一 | 建立实例时从模板概念复制。 |
| 当前值 | 可选一 | 最近一次成功写入的准确值。 |
| 标准值 | 可选一 | 当前历史值中命中次数最高的稳定代表值。 |
| 历史值命中记录 | 零到多 | 每项保存准确值、命中次数和所属实例。 |
| 实例历史聚合值域 | 可选一 | 完整历史值按概念聚合规则计算的当前值域。 |

历史不同值由历史值命中记录中的准确值唯一得出，不建立第二套重复历史事实。比较规则和聚合规则只由正式特征概念提供，实例不复制规则。

归组子特征仍是普通实例特征节点，并额外保存归组子特征标记。它通过外部父子关系由父特征持有。

## 5. 建立或取得实例特征

公开入口：

```cpp
稳定编码 建立或取得特征(
    稳定编码 持有节点,
    稳定编码 特征概念节点,
    std::optional<新特征准确值> 实际值 = std::nullopt) noexcept;
```

流程为：

```text
核验持有节点和传入概念
-> 查找持有者下直接引用该概念的实例
-> 恰一则完整读回并复用，多项则拒绝
-> 可选原始材料值按物理类型核验；直接信息引用另按第3.1、3.2节核验类别、身份、结构与保护
-> 提供实际值时，在同一特征类型根下查找包含该值的最具体概念
-> 唯一找到则采用该概念；未找到或匹配冲突则采用特征类型根
-> 再次查找所选概念的已有实例
-> 建立节点类型、概念引用、可选单位和持有关系
-> 增加所选概念的当前实例引用数量
-> 返回实例节点
```

该函数不写入实际值。实例建立后，当前值、标准值、历史记录和历史聚合值域均为空。新建分支当前没有在返回前调用公开`获取特征()`完成一次独立整体读回，这属于已知工程边界。

## 6. 添加特征值

公开入口：

```cpp
新特征值添加结果 添加特征值(
    稳定编码 特征节点,
    const 新特征准确值& 新值) noexcept;
```

流程为：

```text
完整读回实例和当前概念
-> 原始材料核验物理类型；直接信息引用按第3.1、3.2节核验并保护目标
-> 使用概念比较规则查找等价历史值
-> 已有值增加命中次数；新值建立命中记录
-> 与当前值不等时更新当前值
-> 首个值成为标准值
-> 候选命中次数严格超过现标准值时替换；并列不替换
-> 尝试归组子特征
-> 用全部历史值执行聚合规则
-> 发布实例历史聚合值域
-> 同步正式所属概念
-> 返回结构化结果
```

实际值不受当前概念值域限制。概念值域未包含新值时，写入仍可成立，随后由历史聚合和概念同步处理分类变化。

每次调用都增加该值的命中次数；“当前值无变化”不等于整次调用无变化。只有当前值、历史集合、命中次数、标准值、子特征、聚合域和概念同步均无变化时，才可返回`无变化`。

## 7. 历史聚合与子特征归组

实例历史聚合值域由完整历史不同值重新计算，不使用当前概念值域冒充实例实际历史。

当前归组合同为：

1. 初始相似度阈值固定为`9000`，当前不动态调整。
2. I64标量按单维相对相似度并允许连续连接判断；其它支持类型按材料接近度判断。
3. 只有一个稳定区间时可以只保留父实例，不强制建立子特征。
4. 出现两个及以上差异区间时，建立或复用相应子概念和子实例特征。
5. 新值同时连接多个区间时，选择与各区间标准值相似度最高者；并列时按子特征稳定编码确定性选择。
6. 新值不得触发多个已有区间自动合并。
7. 每个归组子特征保存成员历史记录引用、当前值、标准值和自身历史聚合值域。

归组和后续概念同步是添加值调用链的一部分，不是独立的永久完成标记。

## 8. 实例所属概念自动同步

历史聚合值域成功形成后，特征类必须同步实例正式所属概念：

1. 查找当前特征类型根下能够包含完整历史域的最具体概念。
2. 有准确概念时复用并改挂实例。
3. 当前概念包含历史域但没有准确下位概念时，建立严格子概念。
4. 历史域扩大时，允许更新当前概念值域；必要时先调整其上位位置。
5. 根概念不能包含实际历史域时，允许扩展同表示的特征类型根，再建立或复用准确概念。
6. 当前概念与上位概念等值时，实例改挂上位概念。
7. 当前概念越过直接上位时，将其重新挂到最近合法祖先；没有合法祖先时先扩展类型根。
8. 概念变化后处理同父兄弟：等值时复用；包含时调整上下位；相交或分离时不自动合并。

实例改挂采用“新概念引用数加一→修改实例概念字段→原概念引用数减一”的顺序，并尽力恢复失败步骤。

## 9. 比较能力

### 9.1 准确值与实例比较

特征类分别提供：

```cpp
新特征比较结果 比较特征值(...);
新特征比较结果 比较特征(...);
```

I64标量返回饱和有向差值；溢出分别饱和为`INT64_MAX`或`INT64_MIN`。需要相似度的算法返回`0～10000`，没有适用量化算法时返回`-1`或`规则不支持`，不得把无法比较伪装成完全不同。

实例比较按以下顺序选择实际材料：

```text
双当前准确值
-> 一方当前准确值与另一方历史聚合值域
-> 双历史聚合值域
-> 仅剩概念时只报告概念关系，不产生实例数值相似度
```

### 9.2 已实现的材料算法

- I64标量：饱和有向差值。
- 结构化I64：先尝试最具体概念关系，再按逐维相对比例形成相似度兜底。
- RGB：按三个`0～255`通道形成相似度。
- 二维轮廓：从原始二值图直接生成各分辨率灰度层，由粗到细比较；任一层低于50%立即返回0，否则返回最细共同层相似度。
- 三维体素：生成XY、XZ、YZ三个正交轮廓投影，分别比较后等权汇总；不直接比较体素块。
- UTF-8字符串：完整字节内容相等返回`10000`，不相等返回`0`；不进行模糊、语言意义或Unicode规范化比较。
- 其它没有专用接近算法的不同材料：返回规则不支持。

### 9.3 特征概念值域比较

H需求单D采用7160第5.1节的独立需求身份精确规则，当前/历史均为D引用，新增需求发生由正式S读取，不从D判等或数量推导。旧服务对象需求集合及仍具独立集合合同的类型保留原7160第9.1节算法供具名调用/迁移：同集10000、异集0、条件包含1/0，均非有向差值；完整快照和并发旧值保护不变，不将该旧算法套到当前H需求独立FT。动态派生仍服从7170及1170。

特征类另提供：

```cpp
比较特征概念值域关系(...);
计算特征概念值域重叠度(...);
计算特征概念材料接近度(...);
```

三者分别表达集合关系、值域重叠比例和材料内容接近程度，不能互相替代。它们只处理同一特征类型根内的单特征概念，不处理存在概念或其它多特征组合概念。

存在引用集合按7160第5.2节采用独立存在身份核验与判等，同样保留完整当前快照、历史和旧值并发保护。自我交互对象F的读回按持有者与类型根定位唯一直接特征；多项或损坏不得任选或当作未建立。成员身份合法不证明人类、当前连接、服务关系或授权；集合提供者不得把旧单值服务对象或网页消息列表自动当作已连接成员。初始化仅写合法初始空集状态，不预造变化动态或业务动作。

本类型的U64成员须有正式引用保护，覆盖当前、历史、标准、域及状态所保留的完整材料。成员从当前值移除不等于历史引用退出，不能据此清理存在身份；材料或域仍保留时，成员保护不得提前解除。删除竞争必须在修改存在自身字段之前被阻止，具体保护与退出事务由对应领域owner实现。

## 10. 一致性不变量

任一成功读回的实例特征必须满足：

1. 节点类型字段恰一并指向实例特征节点类型。
2. 正式特征概念字段恰一且目标概念可完整读回。
3. 外部上位父子关系恰一。
4. 实例单位字段至多一项且目标存在。
5. 当前值、标准值和历史聚合值域字段各至多一项。
6. 历史值命中记录的所属特征必须准确指回本实例，命中次数为正。
7. 历史准确值在概念比较规则下两两不等价。
8. 标准值必须等价于一项历史值；没有其它历史值的命中次数严格超过它。
9. 当前值存在时，必须等价于一项历史值。
10. 对外报告的历史聚合值域必须等于完整历史不同值按当前概念聚合规则计算的结果；缺失或过期时不得伪造有效聚合域。

## 11. 公开能力

当前公开能力包括：

```cpp
bool 初始化() noexcept;
稳定编码 建立或取得特征(
    稳定编码 持有节点,
    稳定编码 特征概念节点,
    std::optional<新特征准确值> 实际值 = std::nullopt) noexcept;
std::optional<稳定编码> 查询特征(...) const noexcept;
std::optional<新特征信息> 获取特征(...) const noexcept;
bool 是特征节点(...) const noexcept;
新特征值添加结果 添加特征值(...) noexcept;
新特征比较结果 比较特征值(...) const noexcept;
新特征比较结果 比较特征(...) const noexcept;
新特征概念值域关系结果 比较特征概念值域关系(...) const noexcept;
新特征概念相似度结果 计算特征概念值域重叠度(...) const noexcept;
新特征概念相似度结果 计算特征概念材料接近度(...) const noexcept;
```

当前不提供实例特征主动删除、变更持有者、删除历史值或直接写聚合域的公开入口。实例所属概念只由内部同步链改变。

## 12. 写入结果与失败边界

添加值区分：

```text
已完成、无变化、入口拒绝、特征不存在、概念不存在、
材料类型不相容、结构不一致、值已更新但聚合未完成、资源失败
```

结果同时报告当前值、历史集合、命中次数、标准值是否变化，并可返回接收子特征和聚合结果。

基础数据集没有组合原子变化集。准确值或历史事实已经成立后，后续归组、聚合或概念同步失败不回滚已经成立的实际值，而返回`值已更新但聚合未完成`。调用方必须保留原实例并允许同值重试，不得重新分配实例或把该状态解释为零写入失败。

## 13. 职责边界

特征类负责：

- 初始化实例特征字段和类型结构；
- 建立、查找、读回实例特征；
- 更新当前值、历史命中次数、标准值和历史聚合值域；
- 自动归组子特征；
- 根据实际历史建立、复用、调整具体特征概念并同步实例所属概念；
- 维护概念直接实例引用数量；
- 比较准确值、实例特征和同类型单特征概念值域。

特征类不负责：

- 保存非I64原始材料和建立压缩树；
- 创建全新的特征类型根；
- 主动从多个同层概念提取共同点并形成新的共同上位概念；
- 概念树层级修剪；
- 多特征类型组合概念比较；
- 自然语言词条或名称关系建立；
- 推断持有者业务类型；
- 存在、场景、状态、动态、因果、需求、任务或方法治理。

## 14. 非权威实现完成边界

基于当前代码，以下能力已经具备并不再作为本阶段待完善项：

- 实例特征建立、查询和完整读回；
- I64直值及非I64特征值节点写入；
- 当前值、去重历史、命中次数和稳定标准值维护；
- 历史聚合、区间归组和子特征形成；
- 具体特征概念自动生成、复用、值域调整和实例改挂；
- 概念兄弟等值/包含整理；
- 准确值、实例、概念值域关系、重叠度和材料接近度比较。

以下事项属于当前阶段接受的边界，不因本规范更新宣称已经实现：

- 基础数据集持久化和跨启动身份恢复；
- 多步变化原子发布、发布未知和跨进程并发唯一性；
- 同一持有者按特征类型根唯一，而非按具体概念唯一；
- 实例特征主动删除及由此产生的概念引用减少；
- 动态归组阈值；
- 主动共同上位概念归纳和概念树修剪；
- 自然语言名称提供者；
- 生产消费者接线、根工程构建、跨进程恢复和集成验收。

当前基础数据集仍是进程内实现。已完成的独立编译和仓库外运行验证只证明新版特征切片的具名行为，不证明生产业务闭环。
