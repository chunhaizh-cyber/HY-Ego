## 1. 目的与核心原则

概念统一的首要目标，是建立自然语言与系统内部认知之间共享的语义表示。数据结构统一是基础，不是最终目的。物理对象、信息对象、特征、关系、需求、任务和方法，均应能够被语言指称、限定、组合、查询和表达。

语言理解的结果应直接对应系统认识、查询和操作所使用的正式概念、具体实例与关系，而不是先形成脱离对象含义的语言标签，再分别翻译成各业务模块的私有意义。领域服务仍可具有不同物理布局和接口；不同投影必须保持同一对象身份及含义，不形成第二权威。

语言生成从同一份概念化内容及实际取得的信息出发，保持主体、对象、目标、关系、条件、否定、时间、量词范围和不确定性，不为了语句流畅另造含义。

语言所表达的内容与系统已确认的事实分别管理。理解、陈述、提问、期望、条件、引述、内容确认、求助、承接及执行不是同一事实，也不相互自动授权。

## 2. 共享对象与身份

### 2.1 物理对象与信息对象

存在的语义范围不限于外部感官直接观察的物体。具体需求D、任务T、方法M等具有独立身份的信息对象，可以作为语言中的指称对象，具有自身的特征、内容和关系。

本条统一认知和指称能力，不把D/T/M编码自动认定为1140普通存在实例，不把对象搬入现实场景，不复制镜像存在，不合并D/T/M与Vt/Vm，也不改变原领域的合法读取、治理和写入职责。任务状态等实际承载仍从对应领域正式宿主读取。

方法、需求、任务作为存在的引用型特征时，当前值均为完整同类别引用集合，单成员仍为集合；唯一详细合同见[1130](1130_根规范_特征节点_20260720.md)与[7160](7160_子规范_特征概念形成组织与名称关联.md)。历史值不冒充当前成员，集合引用不变不表示成员内容未变。

### 2.2 必须区分的层次

特征类型、某对象持有的特征实例、特征实际内容、内容所引用的具体对象、限定内容的概念，以及关于内容的语言出现必须分别识别。

“方法”特征类型、方法类别概念、具体方法M、方法虚拟存在Vm和一次方法执行，不因同名或关联而共用身份。需求、任务同理。名称、词条、稳定编码和私有schema锚不能代替正式概念定义。

### 2.3 范围、分类与构成

“任意合法存在”表示明确语义范围，不表示任意非零节点、未知或空范围，也不要求建立所有概念必经的永久本体总根。通用范围必须有所属概念合同认可的完整定义及判定依据，不能把无定义的空专属概念当全域。

分类表示范围包含，保留现行多上位无环图合同；构成引用表示内容依赖，实例归类表示对象符合定义，三者不是同一关系。共享范围不复制定义，任务引用方法不表示方法是任务的下位类别。

## 3. 概念定义作为语言的语义依据

### 3.1 基础范围与结构范围

基础概念应具有直接可解释的材料范围或具名基础判定含义，明确材料类型、单位、参照与规则。只有名称而无判定内容，不构成可用范围。

结构型概念的共同逻辑形式为：

```text
概念C
  特征类型FT1 → 内容范围概念C1
  特征类型FT2 → 内容范围概念C2
  必要基数、顺序、互斥、分支和跨项关联约束
```

这是内容解释要求，不把全部领域字段、锁或缓存机械转换为普通实例特征，不冻结新的公开DTO或字段编码。具体概念类别及其存储、判定、形成仍由所属合同承接；提供者缺失须明确报告，不以私有字段表冒充实现。

概念限定“可以是什么”，实例保存“现在是什么”。具体对象引用和概念定义引用须有类型地区分：T对应具体D，不能填成需求类别概念；D目标范围可以引用正式特征概念，却不表示目标对象已取得该准确值。

### 3.2 完整性与关联

必需/可选、单项/集合/有序组、数量及位置必须明确。范围不等于基数；允许任意合法对象不代表可以缺项，允许空集合不代表当前集合已知为空。

同一必要分支的限制共同成立，可选分支分别组织。逐项类型合法不足以证明整体合法，还须核验所属、同一/不同、目标特征与范围相容、角色配对及共享变量等关联。不能用另一任务的完成状态补足本任务条件。

概念符合、当前事实成立、方法条件具备和操作资格分别判断。明确不符合、信息不足、未完成查询和工程读取失败不得混为否定。观察事实不得为迎合概念范围而截断或改写。

### 3.3 先天定义与后天归纳

需求、任务、方法的共同结构由所属领域合同先天规定，其类别的概念化定义不依赖伪造样例或运行经验。正式类别定义应能在没有具体D/T/M时完整形成；初始化按依赖准备、核验、发布并读回后才可使用。重复初始化复用同义定义，异义不能按名称覆盖。

先天固定字段含义、范围、组织与必要关系，不固定具体主体、目标、任务状态或方法条件结果知识。先天类别、具体实例投影、多实例共同点归纳分别成立，不把某任务当前完成写成全部任务必需状态。

相互引用定义须由所属提供者明确合法闭合和发布顺序，半定义不得交付。本规范不宣布已有跨领域原子初始化能力。递归引用不授权无限展开、否定循环或仅凭回访即判符合；缺少合法判定规则时报告未能判定。

## 4. 概念化内容的共同构成

以下内容按本次实际需要保留，不要求每句话填满全部字段；未使用、未知、待消歧和已绑定分别表示。

| 内容 | 要求 |
| --- | --- |
| 对象与概念 | 强类型具体引用、概念限定，或有来源的候选/变量；不以词面代身份。 |
| 角色与关系 | 谁作用于谁、属于谁、采用什么、目标是什么；保留方向和参数映射。 |
| 内容与范围 | 准确值、允许范围、单位、参照、数量和顺序；范围不是实际值。 |
| 作用域 | 否定、条件、量化、引述及嵌套内容的明确作用对象。 |
| 时间与立场 | 事件时间、表达时间及未知；谁说、谁知道、谁希望及其作用内容。 |
| 话语用途 | 陈述、提问、期望或行动请求等，不从一个词决定整句用途。 |
| 来源与完整性 | 原文出现、采用知识、指代依据、未决项、未覆盖范围及实际读取结果。 |

这不是新建通用语义仓或万能持久结构。出现、角色、作用域、变量、主张、知识和交互材料沿[7230](7230_子规范_语言材料知识与交互字段.md)承载，转换求值沿7240。概念共享定义，语言出现保留当次来源；两次出现不因同词或同概念被合并。

未知对象可以是受类型约束的查询变量或未决指代，不为填字段虚构现实存在。确定性指称仍有多个候选时保留歧义，不采用首项、self、焦点或当前窗口补齐。

## 5. 组合限定与关系查询

“采用这个方法的任务”组合任务类别、采用关系和已绑定方法M，限定任务范围；“完成这个任务的方法”限定能够实现目标的方法范围。不能因为都含任务和方法就互换关系方向或目标类别。

“采用M但尚未完成的任务”在同一任务变量上施加采用关系及状态限制。临时限定可形成调用期查询条件，不必为每个短语永久生成概念；确需复用或归纳时另交概念形成。

“你的方法还不能满足我的需求”须分别解释受话者的方法引用、说话者的需求引用，再表达两者能力或适用关系的否定/尚未成立；这是说话者的判断内容，不自动成为系统确认的能力结论。

“我知道你有一个尚未完成的任务”须保存知道者及嵌套内容，任务承担者与状态限制归属于同一任务，不把嵌套陈述提升为系统世界事实。

词语关联概念候选；句法、构式和上下文确定角色、关系及作用范围。不能简化为所有名词都是普通存在、所有动词都是可执行方法。“知道、希望、属于、执行”按实际关系解释，文本提及方法不取得调用权。

## 6. 同一查询骨架与领域读取

“这个杯子的温度是多少”和“这个任务的状态是什么”共享以下语义骨架：

```text
确定被谈论的对象或合法变量
→ 确定所询特征或关系
→ 按对象领域读取实际内容
→ 保留结果、缺口或不确定性
→ 从同一内容生成回答
```

共用语义不要求无类型CRUD入口。杯子经世界/特征服务读取，任务状态经任务及其正式状态承载读取，方法知识经方法服务读取。提供者缺失或读取失败不返回空集合、无对象或业务否定。

“你有哪些需求”“这个需求对应哪个任务”“这个任务采用什么方法”“这个方法需要什么条件”，沿正式引用和关系逐步查询，不靠名称猜关联或反射读私有内存。范围及完整性须明确，未查到与未查完分开。

方法条件回答须保留分支及分支内共同要求，不能摊平为全部必需项。能力查询不以函数存在、方法被引用或预测结果代替当前可用性裁决。

## 7. 需求理解、缺项与定向澄清

指代和单位知识具备时，“我希望这杯水达到四十摄氏度”可组织为需求表达：说话者为主体，已绑定水为目标存在，温度为目标特征，40℃为目标约束；值目标及比较关系仍按3100/5170解释，不在语言中另造需求格式。

主体与目标分离。服务对象需求属于对方，理解及内容确认不等于self承接。承接后自我需求及关联沿正式治理形成，不改对方原节点主体或直接纳入自我执行树。

先天结构提供完整性检查依据：必需字段、基数、互斥载荷、类型及跨项约束缺什么，须回传具体缺口。完整性按本次目标阶段判断；待补齐内容可以保留，不能冒充完整正式需求。

“把它调高一点”核对指代对象、被改变特征、方向及适用幅度含义。已有唯一上下文复用；没有依据不能补成温度、音量或固定增量。若方向目标无需幅度即可合法表达，不强加精确幅度字段；若所选含义或安全执行确需幅度而“一点”未定义，则针对该缺口澄清。

需求结构先天明确，不代表词义、句式、单位和语境自动已知。“希望、想、需要”等只在相应构式及角色约束下映射同一含义，由7250维护表达知识，不用触发词清单直接生成正式需求。不同表达不应合并不同主体或请求身份。

从内部理解生成重述，而非回显原文；服务对象确认须指向具体内容，内容变化重新确认。理解、确认、求助、承接及正式发布见7240第5.1节和5170，不把S09概念归类确认扩称为已实现需求确认能力。

## 8. 内容与事实地位

| 表达 | 必须保留的地位 |
| --- | --- |
| “任务完成了。” | 说话者的陈述；系统事实另由依据和领域治理决定。 |
| “我希望任务完成。” | 主体对完成内容的期望，不证明已经完成。 |
| “任务完成了吗？” | 查询完成状态，不新增完成事实。 |
| “如果任务完成，就通知我。” | 条件与后继要求、共享角色；不证明前件成立或通知已承接。 |
| “他说任务完成了。” | 带来源及引语作用域的转述，不等于系统或当前说话者确认。 |

共享概念不合并立场。否定须保留作用对象；没有观察到不等于不存在，尚未取得结果不等于执行失败，未找到可用方法不等于永远无法完成。未知、未查询、条件未具备、能力缺失与工程故障分别表达。

“每个任务都有一个方法”与“有一个方法可以处理所有任务”的变量绑定、量词作用域不同，不能由相同概念词集合判同义。数量须明确计数对象、单位和范围；当前成员数、历史不同值数、累计收发事件数不互换。开放范围不为理解而穷举，求值沿7240完整范围、未知及技术失败传播合同。

## 9. 双向转换与语义往返

流程为：自然语言→带角色、关系、范围和来源的概念化内容→只读查询/判断或领域提议→从实际内容生成自然语言。后继治理更新实际对象后重新读取，不用先前临时材料冒充当前状态。

生成后解析实际输出文字，比较关键对象及角色映射、目标约束、关系方向、否定、时间、条件、量词作用域和不确定性，不要求逐字相同。匿名角色或变量比较作用域及对应关系，不伪造答案或新现实身份。

省略仅限请求允许且语境可恢复的内容；不可恢复的主体、否定或限定不得略去。多义输出、来源失效、关键含义丢失或新增含义均不得算完整成功。

往返成功只证明本次语义保持，不证明内容为真、语言覆盖率充分、外部送达或对方理解。独立真实反馈与内部回读分别记录。

## 10. 先天概念与通用参数、学习

先天类别可为理解、查询和通用参数提供共同范围；具体方法参数数量、顺序、信息类型及范围仍按5350由本能函数自身首次登记，不因统一表示改写已生成规格。具体条件属于方法条件节点，实际引用属于本次参数场景，三者不合并。

模拟生成读取正式范围及联合约束：基础材料按值/域处理，信息引用须建立或映射合法隔离对象，不对编码取中点。能识别符合不等于能构造候选；生成依据不足报告缺口。结果只由实际方法写回取得，不按结构预造成功配对。

模拟单向复制所需信息，不反向写现实；临时对象释放后不得残留悬空知识引用。具体算法及发布沿5370，不按方法名称添加私有语言或学习分支。

## 11. 职责、生命周期与非成功

概念定义由合法唯一提供者形成维护；实例和业务状态由原领域维护；语言材料、含义对齐、来源及作用域由语言域维护。共享语义不增加第二仓、公共任意写端口或跨领域事务。

理解“完成任务”不授权直接将任务写成完成。状态推进、需求确认、方法采用、动作执行仍经原治理核验；纯理解和查询不因文中出现命令执行动作。

持久引用沿所属对象引用保护与删除合同；历史引用不自动冻结目标旧内容。定义不可读时不从名称或缓存猜回。结构迁移、Vm/Vt映射、恢复和物理删除另需精确设计，不由本文自动实施。

非成功按实际原因区分未知词、缺语言知识、指代未决、多义、必需内容不足、概念定义/读取提供者缺失、完整查询无匹配、引用失效、资源失败及内部不一致。工程失败进入诊断，不伪装业务否定、正常缺项或语言结论。
