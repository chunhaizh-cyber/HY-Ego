# 4030 子规范 通用数据服务分层与领域写授权

编号：4030
日期：20260808
状态：正式子规范

直接上级规范：0050。

直接依赖规范：4010、4020。

相关边界规范：4040—4070、4190、5090、6180。

## 1. 定位

本规范规定 L1 通用数据能力、领域服务和组合服务之间的唯一合法调用方向。旧服务名单、旧仓库对象和直接数据操作入口不再构成正式边界。

## 2. 语义层与服务职责

```text
L1 通用数据基座
  只处理业务中性身份、类型合同、值、关系、事务、查询、恢复和缓存

领域服务
  拥有某类业务事实的准入、业务不变量、唯一写入门和结构化结果

组合服务
  协调多个领域服务完成业务闭环；不拥有底层事实或原始写入口
```

L1—L5 是 0050、4190 定义的语义责任层，不是代码目录或必须逐级转发的调用栈。每个服务必须归属一个事实所有者和一个主要语义责任；组合服务的存在不改变原子事实所有权。

L1 的服务身份和合同版本只标识业务中性 CRUD / 管理能力；领域服务身份、领域规则版本、业务操作标签、意图组、资格和领域结果见证只存在于 L2—L5 合同，不得成为 L1 普通提交的固定输入、幂等组成或成功结果。

## 3. 调用方向

1. 普通调用方只能调用具名领域服务或正式组合服务的公开服务函数。
2. 领域服务在自身边界完成业务准入和结果解释，只把中性不可变写集、期望事实代次和不透明幂等键交给 L1；L1 不接收或解释业务名、业务资格、操作标签、意图组、领域规则、执行证据或治理算法。
3. 组合服务只能调用拥有所需事实的具名领域服务；不得直接调用 L1 原始写入口、SQL、材料文件、缓存或内部事务。
4. 读取服务返回值式快照；不得返回可变仓库对象、SQL 游标、锁、事务令牌或可直接写回的句柄。
5. 层间与同层服务间均按真实依赖直接调用具名提供者，不强制经过中间语义层转发。无事实责任的中间层不得代理、重解释或为调用授予权力。
6. 普通业务调用方不得直连 L1；具名领域事实所有者可在完成准入后使用受限中性 CRUD。读取所需事实应优先按稳定编码精确取得；完整快照、审计和恢复只能通过分离的诊断 / 管理入口调用。

## 3.1 服务合同最小形状

每个跨层或跨事实所有者服务合同至少冻结：

```text
服务稳定身份和合同正版本
+ 公开函数身份、请求类型、结果类型和全部字段语义
+ 采用的事实稳定身份、事实版本和规则版本
+ 一致性代次 / 截止与完整性边界
+ 成功、未找到、拒绝、漂移、资源失败和内部不一致
+ 输入输出所有权、生命周期、幂等和并发条件
```

1. 返回值必须是调用方拥有的不可变完整投影；不得泄漏提供者内部仓库、SQL、材料路径、锁、事务、缓存、可变对象、候选确认或撤销能力。
2. 提供者内部结构、算法、缓存或物理存储改变但合同仍兼容时，消费者无需修改；合同语义改变时必须发布新版本，并明确直接兼容、迁移或拒绝，禁止靠名称相同或字段形状相似推断兼容。
3. 消费者的推断、任务结论或方法返回不能反向成为提供者事实；需要建立提供者事实时，必须重新调用该事实的唯一发布服务。

## 4. 唯一写入方

1. 每一种业务事实必须有唯一领域写入服务；相邻服务只能消费其已发布结果。
2. 跨领域关系按语义所有权分配给具名领域服务，不建立万能关系服务代替未决裁决。
3. 一个组合事务只有在每个写项所有者、发布者、幂等身份、内存候选确认、逆序撤销和原子代次发布边界明确后才能实施。

## 5. 写前拒绝和错误

领域服务必须在第一笔业务写入前完成业务身份、资格、类型、权限、版本和前置条件拒绝。L1 发现结构矛盾、并发冲突或资源失败时返回中性结果；领域服务负责映射为业务结果，不得把内部不一致降级成普通拒绝。

## 5.1 下游数据服务运行与 L1 累计能力证据

1. L1 不建立独立自证服务、专用验收入口、专项外部驱动或独立通过结论。L2—L5 只为实现、验证和运行自身数据服务合同而调用正式 L1 公开入口；不得为补齐 L1 能力矩阵制造业务本来不需要的请求。
2. 每个消费者只需按自身合同处理 L1 结构化结果并通过适用公开读取入口核对最终权威数据状态。具名生产日志可以记录消费者、合同版本、实际入口、请求类别、结构化状态和必要诊断，供人观察实际运行；日志不承担机器判定，也不替代结构化结果或最终状态。
3. L1 是否已经完善到足以支撑本项目，只能由第二至第五层现行数据服务集合的实际运行判定：这些服务因自身业务需要使用的增、查、改、退 / 历史读取、幂等、原子性和非法请求零变化全部由 L1 正确支撑，且所有相关服务完成自身合同。单个消费者、单条成功路径、专用 L1 驱动、编译、日志或历史记录均不足以推出完整结论；未知未来需求不在当前完成声明内。
4. 第二至第五层可以测试和验收自身服务，但不得把证明 L1 作为独立目标，不得为覆盖矩阵修改 L1 中性请求 / 结果、注入业务标签 / 意图 / 领域见证、降低数据不变量，或取得仓、锁、候选和事务内部权限。尚未被真实业务需要的能力保持未证明，不得用专项补格或相邻消费者结果推断。

## 6. 禁止事项

- 不允许调用方直连仓库、SQL、材料或缓存。
- 不允许领域服务共享可变底层对象。
- 不允许组合服务临时补造身份、类型、关系或默认版本。
- 不允许服务成功自动推出相邻领域资格或能力完成。
- 不允许为满足层号顺序建立无语义责任的逐级转发服务。
- 不允许 SQL 查询、控制面板投影或交互输入绕过领域服务成为当前事实。
- 不允许 L1 用业务操作标签白名单、意图组、领域结果见证或完整执行证据替代领域服务所有权。
- 不允许为了普通 CRUD 固定执行全仓扫描、完整快照、持久证据组装或恢复材料生成。
- 不允许把已退出的旧 L1 专项验收迁移、改名或重组为新的双目标、状态矩阵、领域证据矩阵或普通 CRUD 固定成本。
