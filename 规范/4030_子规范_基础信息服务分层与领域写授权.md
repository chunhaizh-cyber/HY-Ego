# 4030 子规范 通用数据服务分层与结构写授权

编号：4030
日期：20260815
状态：正式子规范

直接上级规范：0050。

## 1. 定位

本规范规定 `DATA-L1`—`DATA-L3` 的唯一合法职责、调用方向、结构写入所有权和使用判定边界。数据层拥有事实或带结构类型语义的数据结构，不拥有业务真实性、有效性、完成性和成功性；旧“DATA-L1—L5 全部同质 CRUD”和“业务位于 DATA-L5 之外”的五层口径自本版起退出。

## 2. 三层职责

1. `DATA-L1` 是纯事实内核，只拥有节点、关系和值及其事务、幂等、事实代次、owner 隔离、当前 / 历史读取和恢复所需中性事实能力；它不知道某个节点是词条、需求、任务或方法。
2. `DATA-L2` 是带结构类型语义的强类型结构服务。它知道某个节点属于哪一正式结构族，并校验该族字段、关系、基数、顺序、生命周期、引用、期望代次、幂等和事务原子性。
3. `DATA-L2` 当前结构范围至少包括：

```text
世界结构：场景、存在、特征、状态、动态、因果
语言结构：语言、词条
概念结构：概念身份、四本体根、根内多父 DAG、事实支持、名称关系
治理记录结构：需求、任务、方法
```

4. `DATA-L3` 只聚合 `DATA-L2` 的公开结构能力，当前仅定义世界树结构聚合和概念空间结构聚合；它不复制 CRUD、owner、仓库或结构解释。世界树使用场景及相关世界结构形成聚合视图；概念空间以多父 DAG 为权威，“概念树”只作可重建投影。
5. `DATA-L4`、`DATA-L5` 当前未定义。缺少独立职责时不得建立占位层、转发壳或“更高层业务解释”。
6. 数据层不得判断名称所指业务、资格是否成立、目标是否正确、动作是否发生、状态是否真实、因果是否可信、词义或词性判断是否正确、需求是否有效、任务是否完成或方法是否成功。语素和词性当前不属于持久结构族。

### 2.1 ARCH 五层映射与兼容边界

`ARCH-L1`、`ARCH-L2`、`ARCH-L3` 分别映射 `DATA-L1`、`DATA-L2`、`DATA-L3`；`ARCH-L4`（需求、任务、方法业务治理）和 `ARCH-L5`（自然语言理解/表达与名称绑定）不是待补的 `DATA-L4`、`DATA-L5`。现有 `L2需求结构服务`、`L2任务结构服务`、`L2方法结构服务` 的名称和 ABI 保留为兼容身份，其业务记录只能作为 ARCH-L4 兼容实现；不得继续把它们的任务/方法虚拟存在、状态或动态解释为 DATA-L2 通用权威。

ARCH-L2 的通用虚拟存在、状态和动态各只有一个结构 owner，现实存在与虚拟调用者复用同一公开结构合同。ARCH-L3 只能消费 L2 公开服务形成世界树/概念空间投影，ARCH-L4 只能消费 L3/L2 公开服务形成业务治理，ARCH-L5 只能提交名称绑定请求。所有层均不得反向依赖或直达 L1 私有仓、锁、事务和写端口。
7. `DATA` 之外的业务层负责业务裁决，并把裁决结果转换为数据服务公开合同允许的强类型结构请求；数据服务只返回结构化数据结果。

## 3. 结构所有权与调用方向

1. 每类可写数据结构必须有唯一具名写入服务；其它服务只能经其公开合同读取或请求修改，不得建立第二仓、第二当前值、第二关系解释或兼容写壳。
2. `DATA-L2` 只经 `DATA-L1` 正式入口发布本族事实，`DATA-L3` 只经 `DATA-L2` 公开服务形成聚合；不存在结构依赖的中间层不得成为转发器。
3. 调用方不得取得仓库可变对象、锁、事务令牌、候选、撤销权、缓存写权、SQL 连接或材料内部路径。
4. 服务之间只传调用方拥有的不可变强类型请求和结果。公开合同至少冻结结构身份、字段、类型、顺序、所有权、生命周期、一致性截止和结构化非成功。
5. 公开合同不得包含业务操作标签、业务意图组、业务资格、领域规则版本、执行证据、领域结果见证或业务完成结论。

### 3.1 DATA-L1 结构写能力

1. L1 以同仓 `L1结构所有者事实` 记录技术写入来源，不把业务资格或领域见证放入 owner。一个独占 owner 只绑定一个正式登记结构范围及其唯一服务；同一公开服务拥有多个正式结构范围时，各范围必须使用互异 owner，不能以服务类名合并所有权。`旧共享范围` 只标记 v1 兼容入口，不证明唯一写入方。
2. 独占写权限由精确 L1 实例的唯一装配期签发器交付不可复制、可移动的 `L1所有者范围写端口`。owner 编码、服务枚举、类型编码、名称、本地键和普通 L1 服务引用都不是能力。
3. 结构服务只在装配或对应族工厂内部为每个正式登记结构范围移动取得一份端口并按范围私有保存，不得返回、借用、复制、转签、交换或按 owner 重建。只有目标结构规范明确登记一个公开服务拥有多个互不重叠范围时，该服务才可持有多个端口；每个写函数必须静态路由到唯一端口，不得接受 owner 选择、形成混 owner 写集或用一个端口制造另一范围读取接受的事实。外部调用者可以通过公开工厂合法取得对应唯一服务并调用公开 CRUD；重复取得只返回同一实例 / 引用或结构化拒绝，不能建立第二 owner / 端口。调用者不能取得 raw 端口、自选 owner 或绕过服务写出会被该族读取接受的事实。
4. 签发器只由 `L1事实基座运行包` 持有；普通应用后继只拥有一个运行包。`DATA-L1` 核心不得反向 import / friend 任一 `DATA-L2` 结构类型、按结构族枚举分支或提供具名领域构造入口；owner 与公开服务工厂的绑定属于上层 provider / 装配。既有 C++ `L1` / `L2` 名称按真实 ABI 保留，不改变这里的架构归属。
5. 所有权只裁决技术结构写入范围。关系端点和值来源可按正式结构合同跨 owner 引用；跨 owner 引用不转移所有权，不授予修改 / 退出权限，也不替代引用闭包。

## 4. 创建、读取、更新与退出

1. 创建只建立调用方明确提交且通过结构校验的新记录；数据服务不得依据名称、场景、目标或业务推断补造其它记录。
2. 读取按稳定编码、属性槽、关系条件、结构索引或正式组合投影返回完整不可变结果，并明确当前 / 历史类别和一致性截止。
3. 更新以新事实替换当前事实，旧事实进入历史；禁止原地改变不可变记录或用缓存覆盖权威结构。
4. 删除在本项目中表现为事实退出：当前入口不再返回，历史入口仍可按合同读取；物理回收由独立管理合同决定。
5. 组合结构写入需要原子性时，由唯一结构发布者形成完整中性写集并恰一次提交；失败必须零公开可读变化。

## 5. 幂等、并发和错误

1. 幂等只绑定数据结构请求本身：同键同结构返回原结果，同键异结构返回冲突；不得把业务同义判断塞入数据层。
2. 期望代次、引用当前性、唯一槽、关系端点或并发条件不符时返回结构化非成功，禁止覆盖当前结构。
3. 资源失败、许可拒绝、版本漂移、未找到、已退出、结构矛盾和内部不一致必须分账；数据服务不得映射为业务成功或业务拒绝。
4. `DATA` 之外业务层可以把数据结果解释为业务结果，但不得反向改变数据层状态值或让数据层拥有业务枚举。

## 6. 实际消费与施工检查

1. 数据服务是否满足当前需要，由合法消费者在实际使用时经正式公开入口、结构化结果和权威当前 / 历史读回判断；不另设一个能替代实际使用结论的专门验收阶段。
2. 施工期间可以运行与风险相称的构建、静态检查和临时专项，覆盖创建、读取、更新、退出、精确重复、异请求冲突、组合原子性、非法请求零变化和并发修改；这些证据只说明已检查的合同分支，不自动证明生产消费者可用。
3. 临时专项不得编译进生产目标，不得取得私有仓或内部事务权限；完成后按所属计划清理。生产日志、界面和“未观察到错误”只供人读，不能裁决数据事实。
4. 实际消费者成功使用一个入口，只证明该入口在已发生的参数、状态和依赖范围内可用；未发生分支保持未证明，不建立单独补格式验收工作。
5. 任一数据服务结果都不自动证明其它数据层、业务系统或项目整体完成。

## 7. 旧合同迁移

1. 现有数据服务合同或实现中包含业务准入、资格、目标、动作、因果真伪、领域结果解释的内容，统一视为待重分类，不得继续取得执行许可。
2. 可保留的纯结构 CRUD、稳定编码、类型、引用、生命周期、事务、幂等、当前 / 历史读取和中性错误合同，应在新设计中逐项复用，不得因业务部分退出而机械重写。
3. 业务解释迁移到 `DATA` 之外；若没有正式上层业务服务承载，保持未实现，不得暂存于数据服务。
4. 旧接口名称包含“世界”“存在”“自我”“状态”“动态”“因果”“需求”“任务”“方法”不能单独决定删除；必须检查其函数是否只做结构 CRUD。名称保留不授予业务裁决权。
5. 现行 L1 v1 中性写入口在迁移期只写 `旧共享范围`，不能使用、修改或退出独占 owner 的事实 / 类型；owner-aware provider 不接受 v1 无 owner 投影作为唯一写入方证明。
6. legacy 数据不得按名称、形状、本地键、旧模块或类型编码原地改 owner。默认由新 provider 重建新 owner-scoped 事实与新稳定编码，再由具名 legacy 退出计划闭合；保码 adoption 必须另立正式合同。

## 8. 禁止事项

- 不允许把业务对象名称当作数据结构资格。
- 不允许数据服务主动发现、推断或证明业务事实。
- 不允许为了验证数据层建立额外业务消费者或业务场景。
- 不允许把调用序列、日志、默认值或缓存命中解释为业务结果。
- 不允许较高数据层绕过唯一结构写入服务直达仓库。
- 不允许把结构写入成功推出自我、存在、场景、目标、需求、任务、方法或因果成立。
- 不允许把旧验收体系换名为数据结构服务内部自检。
- 不允许向普通调用者导出 raw owner 写端口、签发器、owner 选择或按 owner 领取 / 重建服务入口。
- 不允许 L1 反向依赖 L2 类型以识别服务族，或用 friend、模块名、枚举和名称替代实例绑定能力。
