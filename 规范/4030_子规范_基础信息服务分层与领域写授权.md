# 4030 子规范 通用数据服务分层与结构写边界

编号：4030
日期：20260903

状态：正式子规范

## 1. 定位

本规范规定 `DATA-L1`—`DATA-L3` 的唯一合法职责、调用方向、结构写入所有权和使用判定边界。数据层拥有事实或带结构类型语义的数据结构，不拥有业务真实性、有效性、完成性和成功性；旧“DATA-L1—L5 全部同质 CRUD”和“业务位于 DATA-L5 之外”的五层口径自本版起退出。

## 2. 三层职责

1. `DATA-L1` 是纯事实内核，只拥有节点、关系和值及其事务、幂等、事实代次、owner 隔离、当前 / 历史读取和恢复所需中性事实能力；它不知道某个节点是词条、需求、任务或方法。
2. `DATA-L2` 是带结构类型语义的强类型结构服务。它知道某个节点属于哪一正式结构族，并校验该族字段、关系、基数、顺序、生命周期、引用、期望代次、幂等和事务原子性。
3. `DATA-L2` 当前结构范围是以下穷尽闭集，收口单位是“独立结构 owner + 该 owner 的唯一公开服务面”：

```text
节点 owner：场景、存在、特征定义、特征实例、状态、动态、因果、语言、词条、概念、不可变材料
独立关系 owner：概念—词条名称关系
并入既有 owner：二次至 n 次特征、当前特征值、状态当前选择和各族内部关系
```

需求、任务和方法属于 `ARCH-L4`，现有 `L2需求结构服务`、`L2任务结构服务`、`L2方法结构服务` 只保留结构记录面兼容 C++ 身份，不是当前 DATA-L2 活跃结构 owner。世界树、概念树 / 概念空间聚合属于 `DATA-L3`；名称接受、表达和消歧裁决属于 `ARCH-L5`。新增结构 owner 必须先修订 0050、本规范及所属对象合同，不能从 C++ 前缀、枚举值或物理节点形状推导。

4. `DATA-L3` 只聚合 `DATA-L2` 的公开结构能力，当前仅定义世界树结构聚合和概念空间结构聚合；它不复制 CRUD、owner、仓库或结构解释。世界树使用场景及相关世界结构形成聚合视图；概念空间以多父 DAG 为权威，“概念树”只作可重建投影。
5. `DATA-L4`、`DATA-L5` 当前未定义。缺少独立职责时不得建立占位层、转发壳或“更高层业务解释”。
6. 数据层不得判断名称所指业务、资格是否成立、目标是否正确、动作是否发生、状态是否真实、因果是否可信、词义或词性判断是否正确、需求是否有效、任务是否完成或方法是否成功。语素和词性当前不属于持久结构族。

### 2.1 ARCH 五层映射与兼容边界

`ARCH-L1`、`ARCH-L2`、`ARCH-L3` 分别映射 `DATA-L1`、`DATA-L2`、`DATA-L3`；`ARCH-L4`（需求、任务、方法业务治理）和 `ARCH-L5`（自然语言理解/表达与名称绑定）不是待补的 `DATA-L4`、`DATA-L5`。现有 `L2需求结构服务`、`L2任务结构服务`、`L2方法结构服务` 的名称和 ABI 保留为 ARCH-L4 结构记录面兼容实现。任务正式虚拟存在 `Vt` 及其任务状态、状态迁移记录是 ARCH-L4 任务域正式治理结构，不是 DATA-L2 世界存在、世界状态或世界动态；不得把两者相互替代或解释为同一权威。

ARCH-L4 结构记录面只机械保存、读取和校验调用方已经裁决的身份、关系、生命周期、版本、幂等、事实代次、当前 / 历史、原子发布、引用闭合和结构索引。ARCH-L4 业务应用面负责需求成立 / 当前满足、任务目标达成 / 轮次结算 / 生命周期结束、方法适用 / 授权 / 执行成功，以及为什么建立、选择、推进、结束或判定。记录面不得从结构存在、结构写入成功、最后状态、动态、缓存、名称或默认值推出业务结论。

兼容记录面只允许既有消费者继续使用、计划内缺陷修复、恢复 / 读回补全和显式迁移；不得以 DATA-L2 名义新增 owner、新公开业务操作或业务事实语义。现有枚举编码和 ABI 的保留不等于其进入 DATA-L2 frozen manifest，未来实现退出也不得回收已发布编码。

ARCH-L2 的存在、状态和动态各只有一个世界结构 owner，现实世界存在与世界结构调用者复用同一公开结构合同；该唯一性只约束世界结构，不吞并 ARCH-L4 各业务域的正式治理身份和记录。任务域以 `Vt` 唯一承载任务特征、任务状态和状态迁移记录，`Vt` 不进入世界存在族或世界树，也不成为世界存在 / 状态 / 动态的第二 owner。ARCH-L3 只能消费 L2 公开服务形成世界树/概念空间投影，ARCH-L4 只能消费 L3/L2 公开服务取得所需世界材料并由本业务 owner 形成治理，ARCH-L5 只能提交名称绑定请求。所有层均不得反向依赖或直达 L1 私有仓、锁、事务和写端口。
7. `DATA` 之外的业务层负责业务裁决，并把裁决结果转换为数据服务公开合同允许的强类型结构请求；数据服务只返回结构化数据结果。

## 3. 结构所有权与调用方向

1. 每类可写数据结构必须有唯一具名写入服务；其它服务只能经其公开合同读取或请求修改，不得建立第二仓、第二当前值、第二关系解释或兼容写壳。
2. `DATA-L2` 只经 `DATA-L1` 正式入口发布本族事实，`DATA-L3` 只经 `DATA-L2` 公开服务形成聚合；不存在结构依赖的中间层不得成为转发器。
3. 调用方不得取得仓库可变对象、锁、事务令牌、候选、撤销权、缓存写权、SQL 连接或材料内部路径。
4. 服务之间只传调用方拥有的不可变强类型请求和结果。公开合同至少冻结结构身份、字段、类型、顺序、结构唯一写入服务约束、所需公开生命周期、一致性截止和结构化非成功；`L1结构所有者身份`及其生命周期只由服务内部用于结构分区校验，不是 `L2节点族身份来源事实`的公开合同字段。其它具名结构结果中的旧 owner 兼容材料由对应族 ABI 逐项迁移，不得反向把它们解释为身份或调用资格。
5. 公开合同不得包含业务操作标签、业务意图组、业务资格、领域规则版本、执行证据、领域结果见证或业务完成结论。
6. 4230 所属七个世界节点族的身份读取另有严格分流：当前固定为 `确认当前{族}结构身份(G0 + 本族身份) -> L2结构结果头`；成功只以 `已读取 + 截止 == G0 + 空变更事实代次`确认结构当前性，不回传任何身份、生命周期或内部 owner。服务在同一请求 `G0` 内部核对节点、族锚点、归属关系类型、唯一归属关系和内部 owner 均当前。适用的历史身份来源见证只接受本族身份、非零读守卫 `Gread` 与非零截止 `H <= Gread`，并固定使用 `L2{族}身份来源历史见证读取请求 / 结果`及`读取{族}身份来源历史见证`；结果回显 H，成功时 `H == 结果头.事实截止代次`且完整见证存在。请求、守卫和失败优先级只按 4230 第 2.4 节，不得由任一消费者、旧混合入口或语言 / ARCH-L4 合同重释。这两类合同不判断业务当前性或事实真实性；旧混合 `读取{族}身份来源`的类型、声明、定义和调用必须同次退役，不得做第二当前投影、转发或兼容开关。

### 3.1 DATA-L1 结构写能力

1. L1 以同仓 `L1结构所有者事实` 记录技术写入来源，不把业务资格或领域见证放入 owner。一个独占 owner 只绑定一个正式登记结构范围及其唯一服务；同一公开服务拥有多个正式结构范围时，各范围必须使用互异 owner，不能以服务类名合并所有权。`旧共享范围` 只标记 v1 兼容入口，不证明唯一写入方。
2. 独占写权限由精确 L1 实例的唯一装配期签发器交付不可复制、可移动的 `L1所有者范围写端口`。owner 编码、服务枚举、类型编码、名称、本地键和普通 L1 服务引用都不是能力。
3. 结构服务只在装配或对应族工厂内部为每个正式登记结构范围移动取得一份端口并按范围私有保存，不得返回、借用、复制、转签、交换或按 owner 重建。只有目标结构规范明确登记一个公开服务拥有多个互不重叠范围时，该服务才可持有多个端口；每个写函数必须静态路由到唯一端口，不得接受 owner 选择、形成混 owner 写集或用一个端口制造另一范围读取接受的事实。外部调用者可以通过公开工厂合法取得对应唯一服务并调用公开 CRUD；重复取得只返回同一实例 / 引用或结构化拒绝，不能建立第二 owner / 端口。调用者不能取得 raw 端口、自选 owner 或绕过服务写出会被该族读取接受的事实。
4. 签发器只由 `L1事实基座运行包` 持有；普通应用后继只拥有一个运行包。`DATA-L1` 核心不得反向 import / friend 任一 `DATA-L2` 结构类型、按结构族枚举分支或提供具名领域构造入口；owner 与公开服务工厂的绑定属于上层 provider / 装配。既有 C++ `L1` / `L2` 名称按真实 ABI 保留，不改变这里的架构归属。
5. 所有权只裁决技术结构写入范围。关系端点和值来源可按正式结构合同跨 owner 引用；跨 owner 引用不转移所有权，不授予修改 / 退出权限，也不替代引用闭包。

## 4. 创建、读取、更新与退出

1. 创建只建立调用方明确提交且通过结构校验的新记录；数据服务不得依据名称、场景、目标或业务推断补造其它记录。
2. 读取按稳定编码、属性槽、关系条件、结构索引或正式组合投影返回完整不可变结果，并明确当前 / 历史类别和一致性截止。
3. 更新以新事实替换当前事实，旧事实进入历史；禁止原地改变不可变记录或用缓存覆盖权威结构。
4. 删除在本项目中表现为事实退出：当前入口不再返回，历史入口仍可按合同读取；物理回收由独立管理合同决定。
5. 组合结构写入需要原子性时，由唯一结构发布者形成完整中性写集并恰一次提交；只有交换前验证或提交失败承诺整笔零公开可读变化。L1 已确认提交或精确重复后的独立读回失败不得撤销，事实、幂等账和代次保留，由原幂等键重放并经正式读回收束；该语义同时约束首态写入和状态—动态双 owner 原子迁移。
6. 七族当前结构身份只由当前合同读取，成功截止精确等于请求 `G0`；不能用历史读取、完整见证中的生命周期、退出时间或缓存补成当前。历史、退出、恢复和审计路径只有在各自合同要求时读取完整见证，且 H 与结果截止必须相等；普通退出结果不因本规则被强制采用共同见证形状。

## 5. 幂等、并发和错误

1. 幂等只绑定数据结构请求本身：同键同结构返回原结果，同键异结构返回冲突；不得把业务同义判断塞入数据层。
2. 期望代次、引用当前性、唯一槽、关系端点或并发条件不符时返回结构化非成功，禁止覆盖当前结构。
3. 资源失败、版本漂移、未找到、已退出、结构矛盾和内部不一致必须分账；旧 `许可拒绝` 仅供 legacy ABI / 持久结果解码，现行 DATA 路径不得产生。数据服务不得把结构状态映射为业务成功或业务拒绝。
4. `DATA` 之外业务层可以把数据结果解释为业务结果，但不得反向改变数据层状态值或让数据层拥有业务枚举。

## 6. 实际消费与施工检查

1. 数据服务是否满足当前需要，由合法消费者在实际使用时经正式公开入口、结构化结果和权威当前 / 历史读回判断；不另设一个能替代实际使用结论的专门验收阶段。
2. 施工期间可以运行与风险相称的构建、静态检查和临时专项，覆盖创建、读取、更新、退出、精确重复、异请求冲突、组合原子性、非法请求零变化和并发修改；这些证据只说明已检查的合同分支，不自动证明生产消费者可用。
3. 临时专项不得编译进生产目标，不得取得私有仓或内部事务权限；完成后按所属计划清理。生产日志、界面和“未观察到错误”只供人读，不能裁决数据事实。
4. 实际消费者成功使用一个入口，只证明该入口在已发生的参数、状态和依赖范围内可用；未发生分支保持未证明，不建立单独补格式验收工作。
5. 任一数据服务结果都不自动证明其它数据层、业务系统或项目整体完成。

## 7. 旧合同迁移

1. 现有数据服务合同或实现中包含业务准入、资格、目标、动作、因果真伪、领域结果解释的内容，统一视为待重分类，不得继续取得代码实施资格。这里的代码实施资格属于项目施工治理，不是自我现实执行授权。
2. 可保留的纯结构 CRUD、稳定编码、类型、引用、生命周期、事务、幂等、当前 / 历史读取和中性错误合同，应在新设计中逐项复用，不得因业务部分退出而机械重写。
3. 业务解释迁移到 `DATA` 之外；若没有正式上层业务服务承载，保持未实现，不得暂存于数据服务。
4. 旧接口名称包含“世界”“存在”“自我”“状态”“动态”“因果”“需求”“任务”“方法”不能单独决定删除；必须检查其函数是否只做结构 CRUD。名称保留不授予业务裁决权。
5. 现行 L1 v1 中性写入口在迁移期只写 `旧共享范围`，不能使用、修改或退出独占 owner 的事实 / 类型；owner-aware provider 不接受 v1 无 owner 投影作为唯一写入方证明。
6. legacy 数据不得按名称、形状、本地键、旧模块或类型编码原地改 owner。默认由新 provider 重建新 owner-scoped 事实与新稳定编码，再由具名 legacy 退出计划闭合；保码 adoption 必须另立正式合同。

## 8. 禁止事项

- 不允许把业务对象名称当作数据结构资格。
- 不允许数据服务主动发现、推断或证明业务事实。
- 不允许为了验证数据层建立额外业务消费者或业务场景。
- 不允许把调用序列、日志、默认值或缓存命中解释为业务结果。
- 不允许较高数据层绕过唯一结构写入服务直达仓库。
- 不允许把结构写入成功推出自我、存在、场景、目标、需求、任务、方法或因果成立。
- 不允许把旧验收体系换名为数据结构服务内部自检。
- 不允许向普通调用者导出 raw owner 写端口、签发器、owner 选择或按 owner 领取 / 重建服务入口。
- 不允许 L1 反向依赖 L2 类型以识别服务族，或用 friend、模块名、枚举和名称替代实例绑定能力。

## 9. 20260827 DATA 调用边界与临时结构材料

本节与前文“结构写授权”、owner 写能力、许可结果或状态—动态同事务语句冲突时优先。

1. DATA 不判断调用者是谁或是否有权 CRUD。业务 / 治理层先裁决，再把结构请求提交给唯一结构服务。
2. 唯一写入服务维持单一事实来源，不是授权者。L1 owner、其生命周期与写端口只作内部结构分区和确定路由，不进入 `L2节点族身份来源事实`公开合同；其它具名结果的旧兼容字段须按各自 ABI 清理，不能借此建立 owner 公开能力。
3. 旧 `许可拒绝` 不再产生。端口 / 装配错误、结构分区冲突、锁或资源暂不可用分别使用 `内部不一致`、`引用冲突`、`资源失败`。
4. 普通状态 / 动态写入仍按状态先独立形成读回、动态后续引用既有状态执行。特征当前值真实变化是唯一组合例外：业务规则先裁决新值，组合入口按新状态后新动态的逻辑顺序预形成，并把当前属性槽切换、新状态和新动态作为一个原子发布；首次赋值只带初始状态，无变化不造记录。该例外不恢复旧“状态当前选择决定特征当前值”口径。
5. 实例状态 / 动态分别按各自 TTL 与各自数量上限清理；TTL 只使用材料首次形成 UTC，不使用事件时间。清理推进新代次、先动态后孤立状态、退出当前选择且不回退，并保留墓碑与紧凑幂等记录。
6. 历史入口对已清理实例材料返回 `历史材料已清理`，不承诺完整历史。
7. DATA 服务不得启动维护线程。普通应用唯一宿主在数据上下文可用后立即维护一次，此后每 60 秒经公开清理入口维护；空运行宿主不绑定数据维护。
8. 周期资源失败保留同一完整请求；代次漂移换新 G0 和新身份且本周期最多重试一次；内部不一致或序列耗尽形成程序失败。维护身份固定使用 `0x4E43'0000'0000'0000` 前缀和进程内单调低 48 位，抽象完成不得使用该前缀。
9. 本节的中性状态、动态和当前选择公开入口只服务世界结构。任务阶段消费者必须退出旧状态 v2 / 原子迁移 v2，并改由 ARCH-L4 task owner 经任务域正式入口写入和读回 `Vt` 上的任务状态与状态迁移记录；不得以世界结构替代任务状态。
10. 业务比较唯一读取链是“特征实例完整读取 → 当前属性槽 → 当前值事实 → 目标状态合同”。状态、动态和状态当前选择只作记录、触发、定位及审计，禁止由最后动态或被选状态反推当前值。
