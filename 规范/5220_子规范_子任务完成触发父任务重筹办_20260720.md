# 5220 子规范 子任务完成返回上级调用槽与 fresh 重判

编号：5220
日期：20260903
版本：v0.5
状态：正式子规范

## 1. 定位

本规范定义子任务轮次完成后，如何向唯一正式发起上级调用槽返回结果，以及上级为何必须重新读取当前事实而不能把子任务成功直接解释为父任务或父需求完成。

直接上级规范：3200。

直接依赖规范：3100、4260、5090、5160、5210。

相关边界规范：5230。

## 2. 唯一合法调用来源

每个子任务轮次最多存在一条由 task owner 发布的轮次级发起调用事实；根任务轮次允许没有。该事实必须显式绑定调用身份、上级任务、上级任务轮次、上级调用槽、子任务、子任务轮次、结果验证合同和建立截止。

需求树、`T→D`、同类任务查询锚点、线程队列、历史等待合同和“谁创建了任务”的运行痕迹都不能证明调用来源。出现多条发起调用时属于引用冲突，禁止选择任意一条继续。

轮次级调用事实不建立第二任务树，不表达目标分解、永久父子层级或任务所有权。需求树仍是唯一目标分解树。

## 3. 子任务完成后的固定顺序

```text
发布并独立读回动作后状态 / 动态
-> 发布并独立读回正式任务实际结果
-> 若本轮发生执行，形成并独立读回绑定该执行轮次的唯一任务轮次结算结果；合法无执行短路形成该任务轮次自己的唯一结算结果
-> 收束子任务自己的任务轮次
-> 按子任务轮次读取 0..1 条正式发起调用
-> 0 条：根任务轮次正常收口
-> 1 条：按结果验证合同验证返回材料
-> 发布或精确重放调用返回
-> 上级 task owner 幂等结算该调用槽
-> 唤醒上级任务进行 fresh 重判
```

交付、消息或调用槽结算失败只重试同一返回链，不得重做已经完成的子任务动作。调用返回与调用槽结算都必须可以按原幂等身份独立读回。

## 4. 上级重判边界

上级调用槽已返回只证明该调用产生了正式结果，只能作为上级任务重新推进的输入材料；它既不证明上级目标满足，也不直接证明任何方法条件已经具备。上级被唤醒后必须：

1. 读取当前上级任务、绑定任务轮次和调用槽；
2. 读取调用返回及其正式结果、状态 / 动态引用；
3. fresh 读取上级自己的目标合同与任务状态；
4. 当前目标已满足时零动作形成上级自己的核算 / 轮次结论；
5. 当前目标未满足且该任务轮次尚未收束时，由 manager 根据任务状态派发新的找方法或查条件工作包；调用返回中携带的条件相关结果只能进入任务材料，候选方法及其正式条件组必须由任务筹办重新读取、核验和补齐；
6. 只有任务筹办已经补齐方法与条件、task owner 已提交相应任务信息且 manager 独立读回并把状态推进到待执行前选择后，才可进入上级自己的执行前选择、授权、安全和执行；不得复用旧冻结；
7. 材料不足、不可比较、引用冲突或当前性漂移时结构化停止。

若上级任务轮次已经收束，调用返回只完成该轮调用材料的归档并等待 self 的正式后继决议，不自动建立新任务轮次或筹办工作包。上级任务已经取消、换轮或调用槽失效时，迟到返回只形成调用失效 / 当前性漂移，不改写新的上级轮次。

## 5. 其它关联任务延后核算

除唯一正式发起上级调用槽外，其它关联、受益或依赖该状态的任务不在子任务完成时被批量发现、唤醒或结算。它们在自身实际调度、筹办或使用该状态时，只 fresh 读取自己的目标与任务状态；如需继续，方法与条件仍必须由任务筹办查找、核验并补齐，不能直接消费本次调用返回进入执行。

同一状态变化可以自然满足多个需求；每个需求形成自己的核算身份和结论。价值、预算、奖励和归因继续独立防重，不因多个满足结论重复领取。

## 6. 完成边界

任务轮次结算、子任务轮次收束、调用返回、调用槽结算、上级目标满足、需求正式满足和价值结算是七个分立事实。任何一个都不能替代其它事实。

子任务完成不等待同层全部子任务，也不等待全部 `T→D` 或全部受益任务。上级是否继续由上级 fresh 重判及其正式后继合同决定，不由调用返回入口自动建立新任务轮次或新筹办工作包。

## 7. 验证

验证必须覆盖：根任务零调用、唯一调用、多个调用冲突、同义返回精确重复、异义返回幂等冲突、上级取消 / 换轮后的迟到返回、交付重试不重复动作、每个已开始执行轮次恰一结算、上级目标已自然满足零动作、条件相关返回仍经筹办查条件后才进入执行前选择、其它关联任务延后 fresh 核算，以及价值 / 归因不重复领取。
