## 1. 定位

本规范定义需求在实际调度、筹办或使用结果时，如何依据自己的目标状态合同和同截止当前特征值完整投影形成独立核算与唯一正式满足结论；同时冻结需求结算与任务轮次发起调用返回之间的分账边界。

正式任务结果只证明某次方法执行及其动作后状态、动态和归因引用已经形成。它不是可消费、可分割、可独占领取或需要在多个需求之间分配的资源；不得为它建立通用容量、剩余量、成员分配、结果争用优先级或结果耗尽语义。

需求正式结算记录只证明某一需求在确定目标状态合同、事实截止、当前特征值完整投影和规则版本下形成了正式满足结论。它不是需求目标本身、当前特征值权威、任务轮次收束、父任务调用槽返回、任务生命周期结束、价值预算、动作成功回执或当前满足的永久布尔值。

状态、动态和因果构成认知证据；任务结果、调用槽结算和需求正式结算是具有独立业务作用的治理事实。结算可以引用认知证据和必要治理上下文，但不得为证明结算正确再建立用途观察、结算证据、目标裁决证据或其它同义生产节点 / 关系。G0 / G1、幂等、事务、发布读回和恢复材料只保证结算工程过程正确，不进入满足语义。

## 2. 两类结算对象必须分账

### 2.1 任务轮次发起调用槽结算

一个子任务轮次最多绑定一条正式发起调用；根任务轮次允许没有发起调用。子任务完成后，任务 owner 按 4260 的轮次级发起调用事实，把正式任务结果及状态 / 动态引用返回给唯一上级调用槽。该动作只把该调用槽结算为已返回，不发布需求满足，也不证明上级任务目标已经达成。

### 2.2 需求当前满足核算

每个需求只在自身实际调度、筹办、继续执行或显式复核时，冻结非零事实截止，读取自己的目标状态合同和目标涉及的当前特征值完整投影并独立核算。其它任务此前形成的正式结果、状态记录和动态信息可以作为来源、变化或归因引用，但不能代替当前特征值读回，也不能把其它需求的结论复制为本需求结论。

同一状态变化可以自然满足零个、一个或多个需求。各需求分别形成自己的核算结果，不合并需求身份；满足或未满足只改变治理状态，需求身份与目标合同持续存在。价值、预算、奖励、动作贡献和学习归因仍由各自 owner 独立防重和结算。

### 2.3 认知证据与治理上下文

结算引用的状态、动态和因果必须已经由各自正式 owner 发布并在本次截止独立读回。状态记录某时刻的特征事实，动态记录变化和来源，因果记录变化关系；三者可以解释来源、变化、归因、审计或触发，但不能替代特征当前值进入满足比较。

任务结果、发起调用、调用返回、方法选择、授权和结算记录只作治理上下文，不是第四类认知证据。日志、回执文本、显示摘要、缓存、工程见证和原始值不得补造当前特征值、认知证据或结算结论；认知或学习消费者也不得反写需求结算或把推断升级为当前事实。

## 3. 正式需求核算身份

一条需求核算结果的业务身份必须完整绑定：

```text
需求稳定身份
+ 本次需求核算身份 / 核算轮次
+ 当前目标合同及其版本
+ 本次 fresh 当前特征值事实截止
+ 本次当前特征值完整投影
+ 可选状态 / 动态证据引用
+ 零或一条来源任务实际结果引用
+ 零或一条轮次发起调用引用
+ 结算规则版本
```

来源任务结果和发起调用都是可选来源引用，不是需求核算身份的替代物。没有来源任务结果时，只要目标状态合同和同截止当前特征值完整，需求仍可独立核算；有来源任务结果时，也必须重新读取当前特征值。

物理节点、索引键、时间排序、日志编号、显示文本、摘要和工程水位不得替代需求核算身份，也不得因更晚写入而覆盖具有不同核算身份的历史记录。

同一核算身份只允许零或一条已发布结果。同键同义返回精确重复；同键异目标、异截止、异当前特征值投影、异来源引用或异结论为幂等冲突。不同核算身份可以形成历史序列，不得以最近时间覆盖旧记录。

## 4. 子任务结果的即时返回

子任务动作完成后的固定顺序为：

```text
发布正式状态 / 动态
-> 发布并独立读回正式任务实际结果
-> 形成并读回该子任务轮次的唯一结算结果，收束子任务自己的任务轮次
-> 读取 0..1 条轮次级正式发起调用
-> 0 条：按根任务轮次收口，不构造父调用
-> 1 条：验证调用、轮次、结果合同和当前性
-> 发布或重放调用返回
-> 上级任务 owner 幂等结算该调用槽
-> 唤醒上级任务冻结新截止并重新读取自己的目标状态合同和当前特征值
```

子任务轮次收束不等待所有 `T→D` 成员核算，不等待其它任务发现或使用该状态，也不等待全部受益需求结算。交付失败只重试同一调用返回和调用槽结算，不得重做已经完成的现实动作。

上级任务取消、换轮、调用槽已失效或调用关系当前性漂移时，迟到返回形成具名调用失效 / 当前性漂移；不得改写新的上级轮次。多个上级同时声称同一子任务轮次为自己发起时属于引用冲突，零结算并追根因。

## 5. 按实际使用时 fresh 核算

一个需求或任务即将判断目标是否满足时，固定执行：

```text
读取本需求目标状态合同
-> 冻结非零事实截止
-> 经特征服务 fresh 读取目标涉及的当前特征值完整投影
-> 当前特征值按合同已满足目标
   -> 零现实动作
   -> 发布本需求自己的已满足核算
-> 当前特征值按合同尚未满足目标
   -> 发布本轮未满足核算
   -> 继续方法选择、授权、安全复核和执行
-> 材料不足 / 不可比较 / 当前性漂移
   -> 结构化停止，不猜测结论
```

若另一个任务已经造成满足状态，本需求必须走零动作收束，不得因为此前排队、历史方法已选或旧冻结仍存在而继续执行。若该状态只满足方法前置条件而不满足需求目标，则只能证明方法条件当前成立，不能发布需求满足。

任务当前 `T→D` 关系组用于证明任务显式承接了哪些来源需求，不是父任务调用来源，也不是结果分配候选集合。一个任务有 0..N 条 `T→D` 时，各成员可以在实际需要时独立核算；不得要求“所有 T→D 全部核算”作为子任务轮次收束的前置条件。

## 6. 需求核算前置与比较收束

正式需求核算前必须依次验证：

1. 需求、目标合同及其版本在请求截止有效；
2. 本次 fresh 当前特征值完整投影具有合法宿主、特征、值域、材料、来源、生命周期和版本；
3. 读前 / 读后当前性守卫闭合，所有必要事实具有同一正式截止；
4. 若携带来源任务结果，结果、状态 / 动态证据引用和来源截止逐字段互证，但这些引用不成为当前值字段；
5. 若携带轮次发起调用，调用、返回和来源任务结果逐字段互证；
6. 声明动作贡献时，因果、动作致变动态、状态迁移动能和结果状态引用必须同源；该同源性只约束归因，不改变当前值独立比较结论；
7. 禁止结果、副作用以及价值 / 归因资格按各自规范独立审查，不与目标满足压成一个结论；
8. 当前特征值完整投影与目标状态合同交由特征及判断收束服务裁决；状态 / 动态服务不参与决定当前值。

需求服务不得直接比较裸 `I64`、枚举底值、显示值或缓存值。原始值只可作为当前特征值完整投影的一部分；类型、维度、单位、值域、版本和左右语义先由特征服务复核，再按 5100、4160 的目标判断规则形成具名裁决。状态记录和动态后状态即使携带同值，也只作证据，不得进入第二条比较路径。

固定值、区间、枚举集合、方向关系和复合目标分别按其正式目标状态与判断收束规则比较。不可比较、输入不足、版本过期或证据冲突不是“未满足”的同义词，必须单独返回具名结果。

## 7. 唯一正式结论与非成功分流

第一层正式结算结论只有：

```text
已满足
```

只有同截止当前特征值完整投影按目标状态合同明确命中，且身份、当前性和必要证据前置全部通过时，才允许发布该结论。禁止结果或副作用可以与目标满足同时成立，必须进入独立风险事实并约束价值结算，但不得抹去已经成立的目标比较，也不得被 `已满足` 掩盖。

| 判断结果 | 结算结构变化 | 后继 |
| --- | --- | --- |
| 当前目标已满足 | 发布或精确重放本需求 `已满足` 正式结算 | 本需求零动作；价值、预算和归因另行裁决 |
| 当前目标未满足 | 不建立正式满足记录 | 发布或返回具名 `本轮未满足` 核算；需要时继续本任务自己的筹办 / 执行 |
| 方法条件满足但需求目标未满足 | 不建立正式满足记录 | 只形成方法条件当前成立证据，继续授权、安全和执行 |
| 材料不足、过期或不可比较 | 零正式满足写入 | 返回具名材料缺口 / 当前性 / 不可比较 |
| 来源任务结果或调用返回错配 | 零正式满足写入 | 返回引用冲突，不以历史结果补齐 |
| 调用失效或迟到返回 | 不改写新上级轮次 | 由 task owner 形成调用失效 / 当前性漂移；需求可在后续使用时重新 fresh 核算 |
| 已发布材料自身矛盾或前置通过后内部写入、读回、发布异常 | 不得当作普通未满足 | 停止依赖路径并追根因 |

`本轮未满足`、等待、取消、任务失败和调用失效都不是需求正式满足结论。历史 `已满足` 记录不永久证明目标当前仍满足。

## 8. 幂等、冲突与历史

候选结果和既有结果必须分别先通过身份、结构、来源引用、当前性和结论合法性验证，随后才允许比较：

```text
同一核算身份 + 同一幂等键 + 同完整目标 / 当前特征值投影 / 来源引用 / 结论
    -> 精确重复，读回首次记录。

同一核算身份 + 同键异义、异目标、异截止、异当前特征值投影、异来源引用或异结论
    -> 幂等冲突，零结构变化。

不同核算身份
    -> 分别保留历史，不跨核算合并。
```

当前满足视图必须按需求、目标合同、fresh 截止和规则版本重建；最近结算时间、累计次数和显示摘要都是非权威投影。

## 9. 写入权与消费边界

需求领域服务是需求核算和正式满足结算的唯一业务提交方。任务、方法、学习、因果统计、线程、显示层和外部调用方只能提交材料或读取结果，不得直接改写需求结算事实。

task owner 是轮次级发起调用、调用返回引用和上级调用槽结算事实的唯一结构 owner；DATA 层只保存强类型关系、返回和生命周期，不判断父任务目标是否满足。manager 负责按正式结果和调用事实编排返回，不能从 `T→D`、需求树、队列、线程缓存或任务名称猜测调用来源。

稀缺数量、独占所有权、有效机会和冲突动作必须在动作执行前，由真实资源 / 所有权 owner 的 fresh 读回、资格授权、安全检查和原子事务裁决。动作完成后不得把任务结果重新解释成这些资源的容量。

价值、预算、奖励、动作贡献和学习归因分别由其正式 owner 结算；多个需求被同一状态满足不得自动重复领取。

## 10. 验证

验证至少覆盖：

- 子任务轮次存在 0 / 1 / >1 个发起调用时分别形成根任务收口、唯一返回和引用冲突；
- 子任务正式结果、状态 / 动态引用、调用身份、父子两轮次和调用槽逐字段互证；
- 子任务先收束自身轮次，再重试同一返回；返回重试不重复现实动作；
- 同调用同义返回精确重复、同调用异义冲突、父任务取消 / 换轮后的迟到返回零改写；
- 上级调用槽已返回不等于上级目标满足，上级继续前必须 fresh 读取；
- 其它需求在实际调度时 fresh 核算，已满足时零动作，未满足时继续自身执行；
- 0 / 1 / N 条 `T→D` 都不构成结果分配集合，也不阻塞子任务轮次收束；
- 固定值、区间、枚举集合、方向关系和复合判断均通过正式特征 / 状态 / 判断收束；
- 当前目标未满足、不可比较、证据不足、调用失效、引用冲突和内部不一致分别收口；
- 结果容量、结果共用 / 争用、成员分配优先级、消费分配记录、未获分配和结果耗尽的生产调用归零；
- 需求满足、任务轮次收束、调用槽结算、价值结算和归因结算保持独立裁决。
- 只有日志、回执、显示摘要、缓存、工程见证或动态后值时，不能补造当前值或正式满足；
- 没有任务结果但目标合同与同截止当前特征值完整时仍可独立核算；已有任务结果、状态或动态时仍必须 fresh 重读当前值；
- 认知或学习推断没有正式来源读回时不形成结算，归因相关因果 / 动态 / 状态引用错配时零满足写入且不污染当前值比较；
- 结算发布、精确重复和恢复成功只证明治理事实及工程过程成立，不生成用途观察、目标裁决证据或其它证明型生产事实。

## ARCH-L4 结算边界（20260826）

正式需求结算和任务调用槽结算属于两个分立的 ARCH-L4 业务裁决。二者引用 ARCH-L4 的任务、Vt、任务状态、任务轮次和正式结算事实；需要核对执行造成的世界结果时，再引用 ARCH-L2 世界状态、动态和特征材料。二者都不写入或解释 ARCH-L2 世界状态；安全值、服务值、价值和学习仍由各自后继 owner 承接。
