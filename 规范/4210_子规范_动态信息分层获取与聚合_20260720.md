# 4210 子规范 动态信息生成、组合与用途

编号：4210
日期：20260909
版本：v2.1
状态：正式子规范

直接上级规范：1170。
直接依赖规范：1130、1160、1180、2100、4150、4180、4202、4211。
相关边界规范：1150、4220、4230、7190。

## 1. 定位

本规范固定 DATA 外动态应用如何从状态事实生成最小动态、形成组合动态、处理重复和间断，并规定动态信息的用途。动态数据服务的逻辑结构、操作语义和实施门禁由4211规定；精确C++ ABI仍待后继物理合同。

## 2. 最小动态生成

1. 从4202的C/E/S完整状态使用绑定中选择同一发生场景C、同一主体E、同一正式特征类型FT的相邻已观察状态；FT分别从各S内容取得，不另存属性键。相邻只表示已知观察序列相邻，不证明现实中不存在未观察变化；同E同FT不自动合并不同来源或多次观察。
2. 历史比较读取状态保存的固定准确值，不以存在当前采用替换历史；引用值按2100完整读回。
3. 比较使用4180允许的类型、用途、单位、维度和算法。合法有向差异按“后值减前值”解释；不可比较不等于零差异。
4. 首次只有一个状态只建立观察基准；准确内容相同不形成动态。前后时间必须严格递增，同时间不同值且无法确定先后时返回冲突。
5. 确认变化后，应用向4211提交原子动态。最小动态不等待重复、动作识别或动态概念成立。

状态类、特征类和场景类均不得自行扫描生成动态；动态数据服务也不重新执行比较。

## 3. 时间段组合

同一主体的多个变化在一个明确有限时间段内可以形成组合动态。归组请求必须明确观察范围、纳入规则及窗口语义；端点落窗、整体落窗和窗口交叠不得混用。

组合保留直接成员和组成角色，实际顺序、同时、交叠、间隔及缺测从成员事实读回。不同成员可以描述不同正式FT的变化，但必须满足1170的组合主体证明。时间段共同出现不证明联动、共同动作或因果。

组合可以只有一个直接成员，用于形成合法的上位主体或层级摘要；不得为凑数量复制成员或加入无变化材料。

## 4. 场景与递归

原子动态按两端完整使用绑定确定发生场景。动态内容发布后，场景类将其组织到该场景动态实例根；内容成功不等于场景组织成功。

整体变化由外部场景组织；内部存在变化由把父存在展开为场景后的内部场景组织。需要把多个子存在变化概括为父存在整体变化时，另建以父存在为主体的组合动态，并以正式组成关系证明成员角色。

一个动态在场景实例树中至多一个组织父，但可被多个组合动态作为来源引用。组织父、组合来源和概念支持是不同关系。跨场景变化必须按可证明边界拆成原子片段后再组合；边界未知时保留待处理材料，不建立动态。

## 5. 重复、长序列和间断

动态可以表达两阶段、多阶段、并行或带间断组合。重复单元提取只形成新的组合或概念来源，不压缩、改写或删除原发生动态。

- 往复或周期必须同时证明单元内部变化、单元间连接和周期边界；单次往返不证明周期。
- 不连续片段只有在真实先后关系可证时才能组合，不能补造连续性。
- 首尾状态相同不消除中间变化。
- 相位等价、方向等价和停止性必须由正式规则判断，不按数组循环移位或名称相似默认成立。

## 6. 用途与职责

动态信息用于变化定位、场景过程回查、不同动态比较、动态概念形成、因果分析以及任务和方法结果解释。它只能触发当前值重检，不能用后状态替代存在的当前采用，也不能自行证明目标满足。

| 责任方 | 必须提供的能力 | 禁止事项 |
| --- | --- | --- |
| 动态数据服务 | 执行4211规定的结构创建、读取、查询、展开、退出和清理 | 不比较、不归组、不抽象、不写场景或概念事实 |
| 场景数据服务 | 维护动态实例根、组织关系和归根查询 | 不修改动态内容，不把挂根当作变化成立证明 |
| 动态应用 | 相邻配对、比较、时间段归组、递归组合、重复整理和内容/场景阶段协调 | 不复制CRUD，不把计算成功冒充持久发布 |
| 动态概念应用 | 按7190形成、匹配和治理可复用定义 | 不改来源动态，不创建第二概念owner |

动态二次特征按1180、4150和4180形成具名I64结果，必须绑定来源、角色、算法、量纲和参数。缺少正式取值或多来源运算提供者时返回不支持；不得伪造F、裸I64来源或持久二次实例。

## 7. 发布和非成功

普通发布固定分为：

1. 动态应用核验状态、绑定、比较或组合来源；
2. 动态数据服务完整发布动态内容并独立读回；
3. 场景数据服务建立唯一组织关系；
4. 应用在同一明确截止分别读回内容和组织路径，报告完整场景动态。

第二步成功、第三步失败时必须保留已发布动态身份并报告“内容已发布、场景未组织”；重试分别使用原请求及各自幂等合同。不得声称跨owner回滚，不得换身份重复创建，也不得设置持久意图字段。

首态、无变化和未匹配概念属于正常业务分支。缺来源、不可比较、绑定不完整、时间冲突、归属不足、预算不足、已清理、格式不支持、资源失败和发布结果未知必须区分。枚举、递归、展开、比较和读取均必须有界。

## 8. 验证合同

| 场景 | 必须结果 |
| --- | --- |
| 首态、同值或不同F但准确内容相同 | 不创建动态 |
| 同场景、同主体、同正式FT的相邻不同值 | 创建可完整读回的原子动态 |
| 主体、场景或正式FT不一致 | 拒绝原子配对 |
| 同时间不同值 | 返回时间冲突，不按身份排序 |
| 同主体不同正式FT的变化交叠 | 可组合并保留成员端点、间隔与交叠 |
| 子存在变化形成父存在组合 | 必须证明正式组成角色 |
| 重复、间断及首尾相同 | 不丢失、不重复计数、不伪造连续性 |
| 内容已发布而场景组织失败 | 返回真实阶段，原动态可独立读回 |
| 清理或预算不足 | 不返回部分完整结果，不留下成员缺失组合 |
