# 4210 子规范 动态信息分层获取与聚合

编号：4210

## 1. 定位

本规范固定动态信息的逻辑字段、场景归属、最小变化、时间段归组、递归组合、重复整理及用途。动态描述具体某一存在已经发生的变化；动态概念描述可跨发生实例复用的识别条件，后者唯一由7190展开。

直接上级规范：1150、1160、1170。

直接依赖规范：4000、4010、4020、4130、4180。

相关边界规范：1180、2220、4190、4220、4230、4240、7150、7190。

## 2. 动态信息的逻辑字段

下表是节点、关系和值共同形成的完整信息投影，不要求把所有字段内嵌为一个对象或独立数据表。

| 组成 | 必要性 | 内容及约束 |
| --- | --- | --- |
| 动态节点身份 | 必需 | 一次具体变化或具名组合的稳定身份，不复用概念身份 |
| 场景组织归属 | 必需组织上下文，非动态本体字段 | 由场景类按4202维护实际根到实例的组织关系并查询；不在动态本体重复保存场景，不能用当前场景改写历史 |
| 主体存在 | 必需关系 | 该份动态明确描述哪一个存在；不是创建者、观察者或来源动作 |
| 变化内容结构 | 必需 | 原子分支保存真实前后状态及同一被描述属性的绑定；组合分支保存直接子动态及必要组成角色，不摊平成状态数组 |
| 实际时间范围 | 必需读回项 | 原子由端点时间取得，组合由来源覆盖范围取得；可重建，不再保存独立可改的第二时间权威 |
| 名称概念引用 | 可选关系 | 本动态采用的动态概念名称引用，至多一项；概念再关联词条，不复制名称文本 |

变化内容必须能定位正式特征类型、前后准确值及其属性上下文。前后引用的固定准确特征F可以不同；同类型也不自动证明同一被描述属性。组合成员保留各自主体、属性、状态端点、实际时间与来源。原子/组合是内容结构分支，不增加并列节点族。

归组规则、观察覆盖、来源、必要动作证据和用途通过相应关系或具名材料表达；调用方选择的归组窗口不等于变化实际覆盖范围。多个适用概念及其支持关系不挤进单一名称字段。版本、代次、幂等、批次及技术生命周期不新增为本轮动态业务字段；已有可靠性和清理合同仍有效。

## 3. 最小动态生成

1. 取得同一主体、同一正式特征类型、同一被描述属性上下文的相邻已观察状态；“相邻”针对这条观察序列，不宣称现实没有未观察到的中间变化。
2. 前后状态保存当时准确类型、值和时间。当前观察先读7150存在采用，再读固定F；历史比较读取原状态内容，不重新取存在的当前值替换历史。内联I64不伪造值节点，引用值按2100完整读取。
3. 比较必须采用4180允许的类型、用途、单位、维度和算法口径。对合法有向标量差异，方向为新值减旧值；排序量、差异量、距离及容差判定不能混用，零的解释服从该算法合同。
4. 首次只有一个状态时建立基准，不生成最小动态；比较确认无变化时不伪造变化。不同F身份但准确内容相同也不是变化。不可比较、材料不完整和无法表示不等于零差异。
5. 确有变化且时间先后有据时，形成引用两个端点的最小动态，时间范围为`[T0,T1]`。同属性同时间却不同值且无法判定先后的材料应返回冲突或证据不足，不按ID大小强排；不同属性的同时间变化可以进入第4节组合。
6. 最小动态不等待重复出现、动作识别或普通动态概念成立。状态和特征数据CRUD不自行扫描生成动态；DATA外动态生成应用提交完整结构，唯一动态数据服务保存。

## 4. 同一时间段的动态组

1. 同一存在的不同特征在同一个明确时间段内发生变化，可以组合成该存在的动态组，不要求所有变化发生在同一时间点，也不要求端点完全重合。
2. 归组请求必须给出有限观察范围、时间段和明确纳入规则。端点落窗、整体落窗和与窗口交叠不能混用；本规范不暗设统一窗口宽度或自动补齐窗口边界状态。
3. 组保留直接成员及真实先后、同时、交叠和间隔。成员有各自前后状态，不为多特征组伪造两个涵盖全部属性的“总体状态”。派生读回可展开来源闭包，但不是第二组事实。
4. 同时段归组只表示共同发生范围，不证明成员存在联动、动作同一性或因果。组动态可以只有一个合法变化成员；不为凑数量制造重复或未变化成员。
5. 对已知观察间断须保留间断；“该窗口未读到动态”不证明没有变化。连续性、停止性判断须有对应观察覆盖和类型规则，缺测不等于停止。

## 5. 场景归属与递归组合

动态信息由1150/4202的场景动态根及组织边形成实际实例树，底层复用L1节点、关系和值；根和组织关系是事实，目录读回和主体反向索引才是投影。存在视角不增加自身动态历史集合，同节点场景视角组织其内部变化；自身相关动态按7150经引用定位。

组织父子与动态组成来源是不同关系角色。一个动态在实例组织树中至多一个组织父，多个组合动态可以引用它，不改原归属或复制实例；场景根与7190的动态概念本体根不共用。

父层只组合直接成员或直接子层正式提供的变化摘要，须引用来源动态及必要的层级路径与归组依据；层数和展开路径是可重建投影，不另存固定世界层号。递归展开止于不可再分的合法原子，来源图无环，不跨层绕过提供者直接抓取孙层原始事实。

子存在的动态放入父存在的内部场景时，仍描述原子存在。确需形成父存在整体动态时，另建以父存在为主体的组合，并保留各子存在的组成角色和来源；不能改写成员主体。内部场景可能包含非组成成员，场景成员身份不能自动当作部分—整体关系。只是收集多个无整体主体的成员动态时，返回场景目录投影，不伪造一个共同主体动态。

跨场景变化按发生时的归属及可证明的片段组织；另一场景的引用或查询投影不建立第二所属关系。只有边界状态和归属证据充足时才拆分事件片段；跨界时刻未知则保留未决组合材料，不虚构端点、归属或完整动态。存在现在离开场景不改写已发生动态的目录归属。

## 6. 重复、长序列与不连续组合

1. 动态可以是`AB`、`ABCD…`、并行结构或带间隔组合，不限于两阶段。这里字母表示示意状态/阶段/动态类型，具体使用须绑定到明确结构，不能直接把字母当机器编码。
2. `ABABAB → AB`表示提取可复用重复单元，不把原发生记录缩成两项。每次发生身份、次数、时间、间隔、差异和来源仍可按合法保留范围回查；不要求次数进入动态本体字段。
3. `AB、AC、BC → ABACBC`只在各片段实际顺序如此时成立。同名字母在此表示同类动态的不同次发生，不能把三份描述中共享的同一次发生复制计数。片段真实间隔和交叠保持，不补造连续过程。
4. `ABAB`和`BABA`可以是周期不同起点的观察。后续可依连续性、停止性及概念选择边界，但不能重排历史事实；同周期或同概念不是无条件结论。
5. `20→25→20`首尾相等仍有两次变化；不得用首尾差为零删除中间动态。概念按7190选择关键阶段，例如`ABCD → A…C`，也不改变原动态内容。

## 7. 用途与类能力分工

动态信息用于定位和解释变化、提供场景过程回查、供不同动态比较与识别、供动态概念形成，以及向因果分析、任务/方法结果解释提供来源材料。动态只触发当前目标重检，不能用后状态替代当前采用或以变化自证任务满足。

动态数据类承担实例内容、组成/来源关系的创建、读取和既有退出清理；实际场景根和实例组织关系由场景类按4202维护。旧动态目录ABI限于原格式，不据此形成第二组织写入口。动态应用负责相邻配对、时段归组、递归组合、重复整理和有界来源提取，不向L1增加走路、跑步等用途入口。

动态二次特征按1180/4150/4180计算，例如持续时长差、变化幅度差、周期和多来源节律差；每项准确派生结果仍为具名I64。须绑定来源状态/动态、输入角色、取值规则、量纲、算法及必要参数，不能仅保存一个脱离来源的差值。跨单元计算明确取哪些发生、什么窗口以及步/周期口径，不为步频等逐个增加顶层业务字段。

0300 C038未裁决前，这些准确二次结果只按合法调用期合同使用，不通过动态字段、状态或缓存取得新增持久实例资格。可持久引用合法来源与已有概念定义，不能把临时值伪装成已发布特征事实。

## 8. 动作与因果边界

同一次变化可分别具有状态迁移记录和有实际动作来源的动作致变记录。两者按4220保留同源关联和专属原子性，结算等消费者按同源组防重复；它们不因本规范的动态组而合成第二结果账。

动作致变须有真实方法动作、被改变主体和特征的端点证据；线程、消息、日志和方法调用过程不冒充来源动作或结果变化。后补合法动作来源时新建动作致变记录并引用既有变化，不改写旧类型和冻结内容。外部变化、未知第三方动作和纯派生整理不伪装成自我可执行动作。时序、重复和动态概念命中均不能单独成立因果。

## 9. 发布、读取、非成功与保留

创建前按正式一致读取合同核验身份、端点、类型、实际时间、场景归属、组成关系、规则及来源闭包；普通入口只消费已发布来源，具名专属组合的预形成顺序与原子边界不变。发布后经唯一owner独立读回节点、必要关系、成员和时间，不以名称、日志、缓存或索引命中当作成功。

首态、无变化、未匹配概念是正常业务分支；缺来源、不可比较、时间/归属不足、预算超限、已清理、格式不支持、资源失败和发布未知必须分别报告，不能跳过失败成员宣称完整组合。前置通过后出现半结构、错角色或来源矛盾属于内部不一致，停止依赖路径。枚举、递归、比较和读取都须有界，预算不足不宣称穷尽。

动态已发布内容不原地改写；修正组合选择另形成合法结果并保持旧记录语义。实例状态/动态继续按0050、1160、4230的有限TTL、数量上限、引用闭包、墓碑及历史已清理合同处理；不是永久保存承诺。组合新增引用必须纳入同一清理闭包，不能留下可读但成员缺失的假完整组。概念抽象和清理是不同操作，不因提取重复单元或关键条件就删除来源事实。

## 10. 旧合同与实施边界

本版替代旧版“同一F节点才能形成变化”“所有聚合均为单属性双端点”“不同特征不能组成动态组”以及“所有动态索引裁剪都不得清理事实”的通用解释，不恢复旧宿主实例槽。

1160/4190/4230既有中性有序状态入口仍只按其冻结的直接状态成员格式解释，不自动获得本版组合子动态的能力；能够保存一条中性序列不等于已经证明本版最小变化或场景归属。关系19/20的旧角色编号、旧结果及4220具名动作扩展不重排、不复义，保留合法历史/恢复和专属合同边界；旧“共同F”载荷不能当作新前后F配对，新结构也不得塞进旧单目标角色。

本版冻结逻辑组成与行为，不冻结新C++ DTO、函数名、关系数值编码或迁移步骤。新组合、目录/来源读回及清理闭包须由后继结构合同明确完整发布、失败、历史保护和兼容转换；合同未闭合前不冒称现有入口可承接。旧格式原文由Git历史追溯，不作为新模型的并列生产定义。

## 11. 验证合同

| 场景 | 必须成立的结果 |
| --- | --- |
| 首态、相同准确内容、不同F但同值 | 不伪造最小动态 |
| 同主体同属性的相邻不同准确内容 | 原端点、类型和有向比较可读，不要求F身份相同 |
| 同FT但主体或属性不同 | 不能直接配成一次最小变化 |
| 同时间不同属性、多特征交叠 | 合法归组，保留各端点且不推定因果 |
| 同属性同时间冲突、缺测或跨界未知 | 不排序造假、不推定停止、不补边界状态 |
| 多层组合及内部场景非组成成员 | 原主体与组成角色可追溯，无跨层绕过或成环 |
| 重复单元、共享发生、不连续拼组 | 不重复计数、不改实际顺序和间隔 |
| 首尾相等但中间变化、ABCD抽象 | 原始变化不丢失，概念选择不覆写事实 |
| 二次计算、同源动作记录 | I64及合法来源闭合，持久化门禁和同源防重复仍有效 |
| 清理、预算、格式或技术失败 | 明确非成功，不产生部分完整结果或假历史读回 |
| 创建及目录读取 | 唯一owner、必要关系齐全；场景索引不成为第二仓 |
