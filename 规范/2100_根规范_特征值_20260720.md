# 2100 根规范 特征值

编号：2100
日期：20260802
状态：正式根规范

## 1. 根定位

特征值是特征系统的原始值容器。它只承载原始值材料、原始类型、版本和必要的比较、序列化及索引统计，不承载业务解释。

### 1.1 20260802 权威模型裁决

特征值的运行期权威由内存已发布代次中的身份、类型合同、值记录、材料引用、版本和发布证据共同承载。已发布载荷不可原地改变；独立材料文件只有被内存已发布值记录引用后才参与运行期事实；SQL 只保存对应持久证据、恢复输入和交互投影。

关系 22、固定授权身份、固定下标、运行期会话候选和节点直接写入形状不构成跨层公开机器合同；与 0050 v0.5、4010—4040 或 4190 冲突时，以内存已发布类型化值、版本化关系和具名服务合同为准。

## 2. 本项目承载

```text
特征值节点及稳定句柄
+ 唯一非零稳定主键和当前节点句柄
+ 实例特征槽位到当前值的唯一关系
+ I64、VecI64 或 VecU64 之一的原始值材料
+ 原始值版本和容器版本
+ 非权威序列化、哈希和候选统计材料
```

向量原始材料可以由特征值服务的受控侧表承载，但侧表身份、版本和特征值节点必须一一对应；侧表不得成为绕过节点和关系的独立业务事实来源。

## 3. 事实与边界

1. 特征值可以保存原始值、必要序列化材料和底层精确比较能力。
2. 特征值不得保存业务类型、编码解释、坐标维度语义、轮廓解释、需求满足或任务完成结论。
3. 坐标、轮廓、颜色、体素及其它业务含义必须由特征定义、二次特征、状态或因果证据解释。
4. 哈希、序列化、恢复材料和值域候选都不是权威原始值本体；使用前必须回读节点、关系、原始值和版本。
5. 一个特征值节点同一版本只能有一种原始类型和一组自洽原始材料。

## 4. 写入、读取与验证

特征值服务只服务于特征系统，只有特征领域服务可以直接访问。需求、任务、方法及其它高级服务不得包含、接收或调用特征值服务。

特征领域服务负责实例槽位、值类型和值域准入；特征值服务及其事务参与者在同一写入会话中写入类型化原始材料。有效读回必须证明值节点直接身份、唯一槽位来源、原始类型、原始版本和原始材料完全一致。

### 4.1 节点直接写入合同

节点直接新域只支持以下三类公开写入：

1. 新实例槽和初始值共同发布；
2. 已有实例槽的当前值换代；
3. 由 4170 管理的多槽初始 / 换代混合批次。

新实例槽请求必须显式携带宿主完整句柄、抽象定义完整句柄、实例槽稳定主键、新特征值稳定主键、已发布来源完整句柄和唯一三态原始值。实例槽稳定主键必须属于 `实例特征槽身份` 命名域；抽象定义必须属于 `抽象特征定义身份` 命名域；两者即使节点类型都为特征也不得互换。初始原始值版本固定从 1 开始。

当前值换代请求必须显式携带实例槽、写前当前关系、写前当前值、写前原始值版本、新特征值稳定主键、已发布来源和新原始值。写前关系、值和版本必须在第一写前及独占许可内再次共同相等；换代形成新值节点和原始值版本 1，不在旧值节点上原地推进。

合法来源固定为一个在第一写前和独占许可内均可读、状态有效、完整句柄版本不漂移的已发布节点。每个新特征值必须形成一条 `因果来源` 关系：

```text
源节点 = 新特征值
目标节点 = 请求来源
顺序号 = 1
```

节点直接新域的这三类写入不接受同会话临时来源候选；需要同会话候选来源的其它业务必须另行建立正式合同，不能用空句柄、零版本或顺序号猜测补位。

### 4.2 非批次幂等身份

新实例槽请求的幂等身份是“实例槽稳定主键 + 新特征值稳定主键”。同一请求再次提交时，只有下列全部权威材料与请求同义才返回幂等读回：

```text
实例槽当前身份、宿主角色 1、定义角色 2、当前值角色 3
+ 新特征值当前身份、来源关系 1、类型化原始值记录
+ 宿主、抽象定义、来源、原始类型和完整原始值逐字段相等
```

任一主键已占用但不能证明上述完整同义结构时返回同键异义，零写入；不得把“节点存在”单独解释为幂等。

当前值换代请求的幂等身份是“实例槽完整句柄 + 新特征值稳定主键 + 写前三元组”。再次提交时，只有旧当前关系已经按请求失效、新角色 3 指向同一新值、来源关系和类型化记录与请求同义、写前三元组能在关系审计中完整找到时返回幂等读回。新值主键已占用但完整结构不同，或当前槽已推进到另一个值，均为同键异义或写前漂移，零写入。

### 4.3 写入结果与结构版本

单槽成功或幂等结果只返回目标实例槽的完整当前值式材料，不返回同宿主其它槽位。批次成功或幂等结果只返回请求项目，按请求顺序号稳定排序，不夹带宿主其它当前槽位。

节点直接特征投影结构版本唯一取自特征值类型化记录仓的已发布结构版本：初值为 1，每个真实提交且至少发布一条本域类型化记录的事务只推进一次；拒绝、幂等读回、撤销和内部错误不推进。关系 22 的唯一公开写入方只有本节三类入口，因此该版本可作为节点直接特征投影变更见证，但不能冒充核心节点、关系或全域代次。

## 5. 生命周期与当前性

原始值变化必须推进原始值版本或形成新值节点，不得静默覆写后继续沿用旧版本。序列化和恢复候选必须带仓库上下文、格式版本和值版本；恢复材料必须经特征服务重新准入并发布，不能直接成为运行期事实。

特征值退役材料必须覆盖该值在 4170 已发布批次账中的全部本域历史引用，而不只覆盖它作为“发布后新特征值”的引用。按值反查时，一个批次项目在下列任一且仅一角色命中即进入结果：

```text
项目.新特征值 == 待退役特征值
或
项目.写前当前值存在且 == 待退役特征值
```

同一项目同时命中两个角色属于批次账内部不一致。命中新值角色时以发布后原始值版本和发布后当前关系互证；命中写前角色时以写前当前关系完整句柄、写前当前值和写前原始值版本互证。退役读取不得遗漏“该值曾作为换代写前值被批次账引用”的删除影响面，也不得因同一项目的角色判断重复返回该项目。
