# 2100 根规范 特征值

编号：2100
日期：20260907
版本：v0.14
状态：正式根规范

## 1. 根定位

特征值是具有稳定值身份、明确表示类型和完整内容的原始数据。新 DATA-L2 特征值类只承载这三项逻辑字段，不负责说明该值是什么特征、属于哪个存在或场景、何时观察到、是否当前以及为什么产生。值身份不是节点身份，不通过节点关系冒充值身份。

本规范区分“DATA-L2 对外特征值对象”和“DATA-L1 内部值事实记录”。前者的字段清单由第 2 节封闭；后者继续服从 4010、4015、4020 及恢复合同，不得把内部事实封套直接当作前者的字段清单。本文不批量改写其它 L2 对象或既有具名 ABI。

### 1.1 运行期权威

保存后的值身份和内容以 L1 正式发布并可可靠读回的值事实为依据；调用方持有的值对象是自有读取结果，不是第二事实仓。已保存内容不可原地改变，同一值身份不得在后续读取中指代另一份内容。SQL、序列化、哈希、缓存和显示只作持久证据、恢复输入或非权威投影。

1130 / 4110 的准确特征固定引用其值内容；某存在当前采用哪个准确特征由其正式关联裁决，不成为值对象自身的“当前 / 历史”字段。同一存在的正面、侧面等不同观测材料可以分别保留，不能因为未被本次采用就判错或自动删除。

独立材料文件只有先经唯一不可变材料服务发布为强类型不可变材料身份，再被已发布值事实引用，才参与运行期事实。裸路径、摘要、长度、缓存键或任意节点编码均不能替代不可变材料身份。

## 2. 固定字段与值表示

保存后的特征值对象只包含以下三个逻辑字段；该清单是封闭清单，不设置预留字段或通用扩展包：

| 字段 | 固定含义 |
| --- | --- |
| 值身份 | L1 分配的唯一、稳定、非零值编码；不是节点编码，不是版本号，不由调用方猜测或以材料摘要替代。 |
| 值表示类型 | 只允许 `I64`、`I64组`、`U64组`、`独立材料引用` 四种原始表示，说明如何承载内容，不说明业务含义。 |
| 值内容 | 与值表示类型匹配的完整原始数据，或指向完整不可变材料的强类型稳定引用。 |

| 值表示类型 | 值内容 |
| --- | --- |
| I64 | 一个有符号 64 位整数。 |
| I64组 | 一个完整、有序的有符号 64 位整数向量。 |
| U64组 | 一个完整、有序的无符号 64 位整数向量。 |
| 独立材料引用 | 一个经正式不可变材料服务确认的强类型不可变材料身份；不保存裸路径作为身份。 |

表示类型与内容必须一一相容。采用 `std::variant` 等强类型联合时，活动分支可以直接承载表示类型，不要求另存一份可漂移的枚举，但对外必须能够明确取得表示类型。尚未保存的输入材料不伪造非零值身份；本节不据此另定创建请求或结果 DTO。

一个向量整体属于一个值，不为每个分量、采样点或可能取值建立节点。顺序、重复元素和完整内容必须原样保留，不自动排序、去重或解释成集合。范围、无序集合、浮点、字符串及业务专用类型不在本次表示清单内。

以下信息不进入值对象字段：特征类型、所属特征信息 / 存在 / 场景、来源、观察时间、当前 / 历史、版本、事实代次、幂等身份、批次、创建 / 退出生命周期，以及轮廓、3D 坐标、颜色等业务标志。不得通过继承公共头、嵌套对象、附加 DTO 或隐含字段绕过清单。

单位、维度、分量角色、坐标系、材料格式、解析与比较规则由特征类关联的正式特征定义及比较合同解释，不是值对象额外字段。完整材料必要的头部、坐标信息和原始载荷仍须保存在值内容或其引用的材料中；不解释业务不等于丢弃原始内容。

大型或需要独立引用的材料使用不可变材料身份承载完整载荷，值内容只保存稳定引用；不得用区间、摘要或长度替代准确材料。

### 2.1 完整结构观测与比较结果

二维轮廓、三维体素和二值图是特征定义及材料解释合同，不是新增值表示类型。完整结构与二值图的具体规则转由 4120 第 3.1—3.2 节承载，本节保留路由。特征阶次和比较输出按 1180、4180 裁决；“多项具名 I64 比较结果”不要求拆散原始向量或结构材料。

## 3. 值事实、节点和值域分账

1. 普通标量、向量和材料引用是值事实，不是节点。
2. 需要独立关系、独立来源角色、独立生命周期或被多个结构独立引用的材料对象必须先作为独立材料节点发布，再由值事实引用。
3. 区间、点集、允许目标集合和其它值域项描述某特征定义允许的取值集合；它们不是某次实际特征值，也不得替代实际观测材料。
4. 量化分箱、召回区间、容差和不确定性边界是具名合同或派生材料；除非对应领域服务重新准入，否则不成为原始特征值。
5. 同一值事实只能有一种值表示和一组自洽材料。材料发生变化必须形成新值事实；不得推进旧载荷后继续沿用旧事实身份。
6. 原始材料形状不产生业务解释。三个 I64 不自动成为坐标，I64 组不自动成为轮廓，U64 组不自动成为集合。

## 4. 特征定义准入

以下是特征类 / 特征定义的准入职责，不是特征值类字段或其普通数据操作的业务前置。每个叶子特征定义必须在允许具体值进入对应特征链路前冻结：

```text
允许的唯一原始值表示
内联材料或独立材料引用策略
适用时的单位、维度、分量角色和顺序
允许值域及值域版本
适用时的材料格式、解析合同和合同版本
来源类型与生命周期边界
```

同一当前特征定义不得同时允许多个相互替代的原始值表示。需要从 I64 改为向量、从内联向量改为独立材料或发生其它不兼容解释变化时，必须形成新的特征定义或新的明确兼容合同；调用方不得仅通过选择另一个材料变体改变机器语义。

向量值域不得默认压成一个标量区间。逐分量区间只表达轴对齐允许区域；不能表达分量相关性、方向、单位向量、旋转、拓扑或形状约束。需要这些约束时必须使用具名值域结构和版本化规则。

## 5. 数据操作与关联结构分工

特征值类的数据职责是校验值表示与内容的结构相容性、按合法服务边界保存和读取完整值。它不根据向量长度推断坐标、不根据内容识别轮廓、不判断是否属于某存在或是否发生业务变化。值的身份相等、内容精确相等与特征业务上的等价 / 变化是不同判断；后者由特征定义及比较规则负责。

特征类型、宿主、来源、观察时间和当前选择按各自正式结构关联或记录，不复制到值对象。组合写入时，L2 结构服务负责确定哪些节点、关系和值修改必须共同提交；L1 负责执行对应原子写入并可靠读回。不能让 L1 推断特征语义或选择需要共同提交的业务结构。

特征类按 1130 / 4110 组合独立特征节点、类型关系及已确认字段，底层复用 L1 通用节点、关系、属性槽和值事实。关联新增、切换或退出保持原子性和引用完整；读取值对象只投影第 2 节三字段，L1 必需的所属节点与发布证据留在内部记录，不以旧宿主实例槽作为新写入前置。不得从当前值反推已经丢失的历史材料。

独立材料引用必须经正式不可变材料服务强类型读回，不能只凭编码非零或节点存在认定其资格；该验证不授权值类解释轮廓、坐标或材料业务格式。

本次不冻结完整 CRUD ABI、独立无宿主值持久化方案、服务迁移或物理删除集合。现行 L1 值写入所需所属节点、属性类型和来源等合同继续有效；三字段公开对象不等于 L1 已提供任意无宿主值创建。后继实现若无法在合法内部组合中取得必需材料，必须报告具体合同缺口，不得添加公开字段、伪造宿主 / 来源或用默认值绕过。

## 6. 可靠性职责边界

版本、代次、幂等、批次和生命周期不是新特征值对象的业务数据，也不是其普通调用由调用方管理的默认前置。L1 已有的事务、可靠读写、内部幂等、并发校验、引用保护和恢复机制继续有效，存储事实所需的技术元数据不因三字段清单被删除。

内部形成的同一次调用重试必须保留同一调用身份和对应完整请求，不能每次重试重新分配身份而产生重复事实。不得以隐藏字段、固定占位身份、额外公开 DTO 或第二份 L2 专用可靠性账规避上述职责分层。跨调用或跨进程恢复能力仍以 L1 正式合同和实际实现为准，本次不宣称新增此能力。

已保存并被引用的值不得原地修改；新内容对应另一值身份。取消某个当前关联不等于删除值内容。物理删除或材料回收须服从现行引用保护与恢复合同，不能使其它合法引用悬空；值退出不自动删除其引用的独立材料。

4170 只保留退役特征批次材料的历史识别与引用保护，不授权旧槽或旧批次新生产，也不作为新值对象或普通值操作必须建立专用账的依据。旧记录不能冒充当前值；其引用保护与 L1 可靠性机制不因退役而停用。
