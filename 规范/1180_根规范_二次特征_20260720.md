# 1180 根规范 二次特征

编号：1180
日期：20260814
状态：正式根规范

## 1. 根定位

二次特征属于特征体系，是为了完成当前比较或判断需求，从已有特征、关系、动态或其它二次特征中经可复算限定、比较、组合或归一化形成的派生特征。它不是与特征并列的本体类别，也不得替代输入世界事实、状态、动态、关系、因果或任务结果。

“二次特征”是实际二次至 n 次特征的统一业务称呼。每个二次特征仍必须保存真实阶次；由一个或多个输入形成的新派生特征，其真实阶次固定为输入中最高特征阶次加一。没有特征阶次的关系、状态或动态只能作为具名来源和约束参加推导，不得靠调用顺序猜测阶次。

## 2. 需求驱动形成

主形成链固定为：

```text
当前需求需要比较、判断或区分
-> 依次使用已有特征事实和关系事实
-> 已有材料足够则直接完成，不生成二次特征
-> 原始事实缺失则继续观察或读取，不生成二次特征
-> 原始事实完整但缺少可表达所需差异的派生结构
-> 形成能够解决当前需求的最小任务局部二次特征候选
-> 以当前需求结果验证候选
-> 后续复用、持久化和概念沉淀分别裁决
```

“无法区分”至少区分已有值相同、输入缺失、类型不可比较、关系不足、事实冲突和确实无可派生差异。只有“已有合法事实可以经新派生结构显式形成所需差异”允许进入二次特征生成；不得用二次特征凭空补造缺失事实、目标优先级或因果。

对于只需证明两个对象不同的需求，任一当前可靠特征或关系差异均可成为依据。对于选择哪个对象更符合当前需求的判断，差异还必须经该需求结果验证；无关差异不得提前结束判断。

## 3. 本项目承载

```text
二次特征节点及稳定句柄
+ 唯一非零稳定主键和当前节点句柄
+ 有序且角色明确的组成项关系
+ 二次特征定义、比较规则和规则版本
+ 输入事实、来源动态和有效范围关系
+ 当前需求或判断目标的值式来源引用
+ 真实阶次和全部直接输入角色
+ 可选宿主归属或场景事实目录关系
```

当前组合入口使用有序 `引用` 关系承载组成项。顺序只表达结构角色，不得靠调用参数位置以外的临时约定解释业务语义。

## 4. 事实、概念与使用边界

1. 二次特征可以表达比较、方向、区间、覆盖、稳定性、变化率、关系投影、归属冲突和任务范围阈值等派生特征事实。
2. 二次特征不得替代一阶特征值、状态事实、动态事实或因果账本。
3. 自然语言关系理解结果不得直接写成权威二次特征。
4. 挂在存在特征结构中的二次特征表示该存在自身的派生或关系性实例特征；进入场景事实目录的二次特征通常表示场景中存在之间的关系事实。
5. 二次特征概念是 2220 特征概念根下的独立概念；二次特征事实是该概念在具体宿主、时间、场景或条件中的实例材料。二次特征服务只形成或保存事实和候选，不得自动建立、命名或晋升概念。
6. 同一二次特征概念可以作为存在、动态或其它适用对象的特征使用，必须复用同一概念身份；来源于动态的“速度”等概念用于存在时，不得复制或降级为另一份一阶概念。
7. 临时比较、筛选、评分、排序和一次性推导默认形成任务局部候选并在使用后丢弃。只有后续事实、证据、因果样本、需求任务方法输入或审计需要回查时才允许持久化。

## 5. 写入、读取与验证

L5 之外二次特征业务负责判定当前需求是否需要派生、选择最小输入与规则、验证是否解决当前判断，以及是否请求持久化。二次特征数据服务只校验组成项、角色、真实阶次、规则、来源、范围、幂等和结构完整性；数据操作层负责节点、二次特征域类型化记录、有序关系和索引的原子发布。普通调用方不得绕过业务和服务直接拼接关系形成权威二次特征。

验证必须证明组成项非空、稳定身份与允许重复角色合法、顺序连续、角色和值域合法、真实阶次正确、输入事实当前、规则版本可用、结果可从输入确定复算。判断型二次特征还必须满足 4160 的收束证据合同。

## 6. 生命周期与当前性

任务局部候选默认不进入权威事实仓库。持久二次特征必须声明适用范围、来源版本、实际阶次和失效条件；输入事实或规则版本变化后旧结论只能作为历史证据，不得继续作为当前结论。

使用次数少不自动删除权威事实或正式概念。用途、最近使用、需求贡献和可替代性只能形成后续生命周期候选；仍被世界事实、概念、因果、需求、任务或方法引用时必须保留历史和引用闭包。
