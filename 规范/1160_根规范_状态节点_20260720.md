# 1160 根规范 状态节点

编号：1160
日期：20260909
版本：v0.17
状态：正式根规范

## 1. 根定位

状态节点是中性的特征事实切片，唯一语义为“特征类型 + 特征值 + 时间”。状态本体不携带主体、场景、来源、业务 owner、许可或使用目的；谁引用状态，谁通过独立引用关系解释该状态对自己的意义。

中性内容成立不等于“某存在发生了该状态”已经成立。具体世界观察按4202第3节，由场景组织并通过完整使用绑定确定发生场景、被描述存在、属性上下文及状态；不能把几条互不关联的引用拼成发生事实。整体与内部子存在沿同节点场景递归组织，不为存在另建状态仓，不把场景根当作主体。

状态不直接承载变化、因果、当前性或业务判断。原子变化以状态端点为基础，多个变化可以组合；动态形成语义由1170/4210规定。因果、目标、需求、任务、方法、服务值和安全值继续由各自上层结构负责。

业务比较涉及存在时，先按其当前采用关联定位准确特征，再按 1130 / 4110 读取固定类型和值；内联 I64 使用准确内容，值引用按 2100 完整读回。状态记录某时点准确内容，动态记录已经发生的变化及其直接来源，二者及状态当前选择均不得反向决定存在当前采用。

## 2. 固定字段、分类与时间

### 2.1 状态本体的封闭字段

保存后的状态信息固定为以下四项逻辑字段，由节点、关系和值承载，不要求合成一行或复制被引用值的完整载荷：

| 字段 | 必要性 | 固定含义 |
| --- | --- | --- |
| 状态节点身份 | 必需，恰一 | 定位该状态内容的稳定节点身份；不是主体身份、场景身份或一次观察的身份。 |
| 正式特征类型 | 必需，恰一 | 引用正式特征定义，确定准确值的类型、单位、维度及合法表示；不以名称或概念身份替代。 |
| 固定准确值 | 必需，恰一 | 合法内联I64，或符合该特征定义的强类型稳定值引用；值引用按2100读回完整内容，不以任意节点编码、区间或摘要冒充。 |
| 强时间 | 必需，恰一 | 明确采用实例绝对UTC时间或抽象相对时间，并保存对应非负纳秒值；时间语义与时间值共同组成该字段。 |

同一状态的类型、准确值及强时间不可原地改写。实际值或时间不同须形成或复用另一份合法状态内容；内容相同不强制身份相同，也不证明同一次观察。内联值与值引用是准确值字段的表示分支，不要求为内联I64补造值身份；实例/抽象是强时间的语义分支，不另加可独立漂移的业务类别字段。

主体存在、发生场景及被描述属性上下文属于4202完整使用绑定，不进入上述四字段。特征节点F可以是取得准确内容的来源，但不是状态本体必需引用，不能以“读取某F的当前值”代替固定准确值。名称、状态概念、当前/历史标志、历史集合、版本、事实代次、幂等、批次及创建/退出生命周期均不新增为状态本体字段。

四字段清单不改变L1可靠性材料，也不撤销本规范第6节的实例保留、退出、清理或引用保护。材料类别、生命周期等承载与本体字段的区别由4230第10.2节说明；完整使用绑定仍由4202唯一展开，不复制到状态中。

### 2.2 实例、抽象与时间解释

1. 实例状态使用非负绝对 UTC 纳秒，纪元固定为 `1970-01-01T00:00:00Z`，精度固定为纳秒；零表示该纪元时刻，不是缺时间占位。此处与0050第11节、4230第10.2节一致，稳定身份和事实截止仍按各自合同非零。
2. 抽象状态使用非负相对纳秒，零表示抽象序列的相对起点。
3. 实例状态身份不得按抽象时间解释，抽象状态身份不得按绝对时间解释；时间语义是状态事实的强类型组成部分。
4. 状态特征类型必须引用正式特征定义；特征值必须满足该特征定义的值域和类型合同。
5. 状态允许被不同主体、场景、任务、方法或其它结构多次引用；复用不改变状态本体，也不产生共享写入权。

场景状态根按1150/4202实际组织状态实例树；唯一组织父与多方使用引用分账，不因被多个动态或场景引用而增加组织父，不把场景或根身份加进状态本体。共享内容的具体发生场景由各完整使用绑定确定，不从内容原归根路径推定，共享也不证明同一次观察。组织根固定不解除本规范实例保留与清理合同；抽象状态不因本项被要求绑定具体世界主体或发生场景。

## 3. 动态形成

1. 状态只能作为4211所定义原子动态的前端点或后端点，不作为组合动态的直接成员。
2. 原子动态的两个状态必须已经正式形成并完成独立读回；它们还须由4202完整使用绑定证明同场景、同主体、同属性上下文和同正式特征类型，且前端点时间严格早于后端点时间。
3. 组合动态只引用已经正式形成并完成独立读回的直接子动态；成员顺序、主体闭包、无重复、无环和来源展开按4211校验。
4. 动态只记录具体发生，只能使用实例绝对时间状态或已经成立的具体子动态；抽象相对时间状态只能进入动态概念条件。
5. 特征信息的普通字段操作不自动建立状态或动态，状态服务或动态服务不得从记录反推或改写当前特征值。
6. 动态创建不得隐式删除、压缩、补造或改写状态端点与子动态成员。来源缺失、已退出或已清理时整次创建失败，不得跳过来源形成另一条动态。

## 4. 引用与当前选择

1. 主体、场景、来源、用途、普通使用和当前选择全部由独立引用关系表达，不进入状态本体。动态的主体存在是1170/4211规定的本体必需关系；“状态中立”不能被外推为“动态无主体”。场景组织仍由4202维护，不进入动态本体。
2. 普通数据操作中的引用与当前选择只能指向已经正式存在的状态或动态；建立、替换和退出引用均是独立数据操作，不参与状态或动态创建。具名专属组合需要共同形成引用时，按其正式原子发布合同处理，不扩大普通入口。
3. 当前选择的唯一性由“引用方身份 + 引用角色”决定。替换当前选择只退出该引用方的旧当前选择并建立新引用，不退出旧状态。
4. 状态当前选择可以定位某引用上下文的当前记录或需要记录变化的业务流程所用前状态，但不具有特征当前值权威。读取目标、需求或自检不得沿该关系取得被选状态值作为当前特征值。
5. 引用方负责解释引用语义；基础数据服务只验证引用键、目标存在性、代次、幂等和关系闭包，不判断调用者是否有权建立、读取、修改或删除引用。
6. 普通引用指向已物理清理目标时返回结构化“已清理”；当前选择指向待清理目标时必须先退出，且不得自动回退到更早状态。

场景具体状态读取须按4202第3.2节同时核验使用绑定、状态内容和组织/复用路径；缺少主体或属性上下文时只可读取中性内容，不得返回完整发生记录。原子动态配对按4210/4211从完整绑定确定同主体、同属性及相邻时序。

### 4.1 当前值与变化记录读取

特征类按 1130 / 4110 保存固定准确内容，不维护当前观察、历史集合或域集合。存在当前采用由 7150 维护，概念积累由 7160 维护；本规范不要求每次特征操作联写状态或动态。具名业务需要记录时提交已取得的准确内容及正式请求；历史补录不修改 F 或存在当前采用。本轮只同步内容来源，不改变状态的类型、值、时间合同或既有清理边界。

动态通知只能说明目标值得重检。消费者须在一致读取范围内重新定位目标存在的当前采用，再读取所引用 F 的准确内容及目标合同；不得反复读取旧缓存 F 冒充当前值，也不得用动态前后值代替。内联 I64 不要求独立值身份。

## 5. 写入、读取与错误边界

1. DATA-L1/L2 只执行结构、类型、代次、幂等、引用和生命周期一致性检查，不裁决调用者的读写删改权限。
2. 新中性状态、动态和引用结果不得定义“许可拒绝”。未获业务授权的调用必须由 DATA 之外的调用链在进入基础数据入口前阻断。
3. 基础数据内部写会话无法取得、写入或交换时统一返回“内部错误”；不得把内部写会话解释为业务能力或权限。
4. 首次写入必须在提交后以正式读取入口独立读回；精确重复返回首次映射和首次形成代次，不产生新事实代次。
5. 同一幂等身份对应不同请求返回幂等冲突；G0 不等于当前事实代次返回事实代次漂移；引用目标不存在、已退出或已清理按具名状态返回，禁止默认值和假成功。
6. 当前读取只返回当前仍保留的完整材料。历史读取遇到已物理清理材料时返回“历史材料已清理”和墓碑，不伪造原内容。

## 6. 实例材料保留与物理清理

1. 实例状态和动态分别受本类 TTL 与本类数量上限约束：实例状态 TTL、动态 TTL、实例状态数量上限和动态数量上限四项均独立且非零；不得把状态数与动态数相加为共同容量。抽象状态不进入该策略。
2. TTL 从材料首次正式形成时记录的 UTC 纳秒开始计算，不使用状态描述的事件时间或动态成员事件时间计算保留期。
3. 清理顺序固定为：先逻辑退出并物理清理实例动态，再清理不再被任何活动动态成员关系引用的实例状态。4210组合的父子动态引用也必须纳入依赖闭包，先处理受影响的引用方；不能在子动态清理后仍把父组读成完整。物理清理仍受L1原生引用保护，不因此绕过历史端点约束。
4. 状态 TTL 或数量边界命中但仍被活动动态引用时，必须先把这些动态加入同一清理计划；普通引用不阻止清理，当前选择必须在状态清理前退出。
5. 同类材料超过自己的数量上限时，按“首次形成 UTC 纳秒升序，稳定身份升序”选择最旧材料，直到该类重新满足上限。
6. 抽象结果正式形成后，上层可用具名抽象结果见证显式调用清理入口，清理来源实例动态后只清理因此成为孤立的实例状态；抽象完成本身不会隐式触发 DATA 调用。
7. TTL 或数量边界先于抽象完成时，记录未及时抽象的清理原因并清理材料，不得补造抽象成功。
8. 物理清理不复用稳定身份。L1 必须保留紧凑墓碑：稳定编码、事实种类、内部结构分区、创建事实代次、可选退出事实代次、清理事实代次。
9. 物理清理后只保留用于同键收束的紧凑幂等账：规范化请求等价材料、首次稳定编码映射和首次事实代次；旧完整事实和旧写集不得作为恢复来源。
10. L1 根权威固定为 `L1物理清理事实身份`、`L1物理清理请求`、`L1物理清理墓碑` 和 `L1物理清理结果`；中性和 owner 读取只返回各自完整墓碑投影。L1 不引用 L2 类型，L2 再把已正式读回的投影解释为状态、动态或引用墓碑。
11. L2 状态与动态服务内部持有同一强类型保留策略。默认实例状态 / 动态 TTL 均为 7 天，默认实例状态数量上限为 1,000,000、实例动态数量上限为 250,000；显式替代策略四项均须非零。
12. DATA 状态与动态服务只提供同步清理入口，不自行创建线程、定时器或后台任务。普通应用唯一运行宿主在数据上下文可用后立即调用一次，此后每 60 秒调用一次；无数据上下文的空运行宿主不绑定维护回调。
13. 资源失败保留原 G0、幂等身份和完整请求到下一周期；事实代次漂移丢弃旧请求，读取新 G0、分配新身份并在同周期最多重试一次，第二次漂移等待下一周期。
14. 首次成功、精确重复或无须清理结束本周期。内部不一致或身份序列耗尽形成 `程序失败阶段::中性实例材料维护`，不得静默停维。
15. 周期维护身份使用 `0x4E43'0000'0000'0000` 前缀，低 48 位为进程内原子单调非零序列；资源失败续用同键，漂移重组换键，进程重启可重新开始。抽象完成调用不得使用该前缀。

## 7. 世界状态与任务状态分账

本规范只治理世界状态节点。任务首态和迁移由 ARCH-L4 task owner 经任务域正式入口写入并读回 `Vt` 上的任务状态和状态迁移记录，不得以世界状态、动态或当前选择替代。任务执行造成的世界特征变化仍按本规范及1170/4211独立记录。
