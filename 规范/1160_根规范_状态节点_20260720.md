# 1160 根规范 状态节点

编号：1160
日期：20260903
版本：v0.9
状态：正式根规范

## 1. 根定位

状态节点是中性的特征事实切片，唯一语义为“特征类型 + 特征值 + 时间”。状态本体不携带主体、场景、来源、业务 owner、许可或使用目的；谁引用状态，谁通过独立引用关系解释该状态对自己的意义。

状态不直接承载变化、因果、当前性或业务判断。至少两个状态的有序引用形成动态；因果、目标、需求、任务、方法、服务值和安全值继续由各自上层结构负责。

特征实例唯一当前属性槽指向的当前值事实才是业务比较权威。状态只记录某个时间点的特征值，动态只记录前后状态及来源；状态当前选择只表达引用上下文选中了哪条记录。三者均不得决定或替代特征当前值。

## 2. 状态分类与时间

1. 实例状态使用绝对 UTC 纳秒，纪元固定为 `1970-01-01T00:00:00Z`，精度固定为纳秒，值必须大于零。
2. 抽象状态使用非负相对纳秒，零表示抽象序列的相对起点。
3. 实例状态身份不得按抽象时间解释，抽象状态身份不得按绝对时间解释；时间语义是状态事实的强类型组成部分。
4. 状态特征类型必须引用正式特征定义；特征值必须满足该特征定义的值域和类型合同。
5. 状态允许被不同主体、场景、任务、方法或其它结构多次引用；复用不改变状态本体，也不产生共享写入权。

## 3. 动态形成

1. 动态由 `2..N` 个已经正式形成并完成独立读回的状态身份组成。
2. 动态成员物理顺序就是记录颗粒度；允许混合特征类型，允许从较早状态直接跳到较晚状态，不要求证明现实中不存在中间状态。
3. 同一动态内状态身份不得重复，时间语义必须一致，成员时间必须非递减；相同时间允许出现多个不同状态。
4. 实例动态只能引用实例绝对时间状态，抽象动态只能引用抽象相对时间状态，不得在同一动态中混合两种时间语义。
5. 普通动态形成仍要求成员状态先独立形成并正式读回，动态后形成。唯一例外是特征当前值统一变化入口：新值已经由业务规则独立裁决后，组合器先预形成新状态，再以既有前状态和该新状态预形成动态，最终与当前值切换原子发布。该例外不允许状态服务或动态服务从记录推导新值。
6. 动态创建不得隐式删除、压缩、补造或改写成员。成员缺失或已清理时整次动态创建失败，不得跳过该成员形成另一条动态。

## 4. 引用与当前选择

1. 主体、场景、来源、用途、普通使用和当前选择全部由独立引用关系表达，不进入状态或动态本体。
2. 普通引用与当前选择只能指向已经正式存在的状态或动态；建立、替换和退出引用均是独立数据操作，不参与状态或动态创建。
3. 当前选择的唯一性由“引用方身份 + 引用角色”决定。替换当前选择只退出该引用方的旧当前选择并建立新引用，不退出旧状态。
4. 状态当前选择可以定位某引用上下文的当前记录或统一变化入口的前状态，但不具有特征当前值权威。读取目标、需求或自检不得沿该关系取得被选状态值作为当前特征值。
5. 引用方负责解释引用语义；基础数据服务只验证引用键、目标存在性、代次、幂等和关系闭包，不判断调用者是否有权建立、读取、修改或删除引用。
6. 普通引用指向已物理清理目标时返回结构化“已清理”；当前选择指向待清理目标时必须先退出，且不得自动回退到更早状态。

### 4.1 当前值变化同步记录

统一变化入口必须按以下状态机处理：

1. 首次赋值：建立当前值事实、当前属性槽和一条初始状态；动态为空。
2. 真实变化：同截止读回旧当前值及其记录状态，裁决新值，预形成新状态，再形成前状态到新状态的动态，最后一次原子发布值切换和两类记录。
3. 无变化：新值等于旧值时零换代、零状态、零动态。
4. 历史补录：只新增历史记录，不切换当前属性槽，也不得因“最后写入”取得当前性。
5. 失败或未知发布：按统一请求幂等重放收束；未能证明全部公开事实时不得返回成功或部分载荷。

动态通知只能说明某特征值得重检。消费者收到通知后必须冻结 G0，重新读取当前属性槽和值事实，再读取目标合同；不得直接使用动态载荷中的前值或后值完成比较。

## 5. 写入、读取与错误边界

1. DATA-L1/L2 只执行结构、类型、代次、幂等、引用和生命周期一致性检查，不裁决调用者的读写删改权限。
2. 新中性状态、动态和引用结果不得定义“许可拒绝”。未获业务授权的调用必须由 DATA 之外的调用链在进入基础数据入口前阻断。
3. 基础数据内部写会话无法取得、写入或交换时统一返回“内部错误”；不得把内部写会话解释为业务能力或权限。
4. 首次写入必须在提交后以正式读取入口独立读回；精确重复返回首次映射和首次形成代次，不产生新事实代次。
5. 同一幂等身份对应不同请求返回幂等冲突；G0 不等于当前事实代次返回事实代次漂移；引用目标不存在、已退出或已清理按具名状态返回，禁止默认值和假成功。
6. 当前读取只返回当前仍保留的完整材料。历史读取遇到已物理清理材料时返回“历史材料已清理”和墓碑，不伪造原内容。

## 6. 实例材料保留与物理清理

1. 实例状态和实例动态分别受本类 TTL 与本类数量上限约束：实例状态 TTL、实例动态 TTL、实例状态数量上限和实例动态数量上限四项均独立且非零；不得把状态数与动态数相加为共同容量。抽象材料不进入该策略。
2. TTL 从材料首次正式形成时记录的 UTC 纳秒开始计算，不使用状态描述的事件时间或动态成员事件时间计算保留期。
3. 清理顺序固定为：先逻辑退出并物理清理实例动态，再清理不再被任何活动动态成员关系引用的实例状态。
4. 状态 TTL 或数量边界命中但仍被活动动态引用时，必须先把这些动态加入同一清理计划；普通引用不阻止清理，当前选择必须在状态清理前退出。
5. 同类材料超过自己的数量上限时，按“首次形成 UTC 纳秒升序，稳定身份升序”选择最旧材料，直到该类重新满足上限。
6. 抽象结果正式形成后，上层可用具名抽象结果见证显式调用清理入口，清理来源实例动态后只清理因此成为孤立的实例状态；抽象完成本身不会隐式触发 DATA 调用。
7. TTL 或数量边界先于抽象完成时，记录未及时抽象的清理原因并清理材料，不得补造抽象成功。
8. 物理清理不复用稳定身份。L1 必须保留紧凑墓碑：稳定编码、事实种类、内部结构分区、创建事实代次、可选退出事实代次、清理事实代次。
9. 物理清理后只保留用于同键收束的紧凑幂等账：规范化请求等价材料、首次稳定编码映射和首次事实代次；旧完整事实和旧写集不得作为恢复来源。
10. L1 根权威固定为 `L1物理清理事实身份`、`L1物理清理请求`、`L1物理清理墓碑` 和 `L1物理清理结果`；中性和 owner 读取只返回各自完整墓碑投影。L1 不引用 L2 类型，L2 再把已正式读回的投影解释为状态、动态或引用墓碑。
11. L2 状态与动态服务内部持有同一强类型保留策略。默认实例状态 / 动态 TTL 均为 7 天，默认实例状态数量上限为 1,000,000、实例动态数量上限为 250,000；显式替代策略四项均须非零。
12. DATA 状态与动态服务只提供同步清理入口，不自行创建线程、定时器或后台任务。普通应用唯一运行宿主在数据上下文可用后立即调用一次，此后每 60 秒调用一次；无数据上下文的空运行宿主不绑定维护回调。
13. 资源失败保留原 G0、幂等身份和完整请求到下一周期；事实代次漂移丢弃旧请求，读取新 G0、分配新身份并在同周期最多重试一次，第二次漂移等待下一周期。
14. 首次成功、精确重复或无须清理结束本周期。内部不一致或身份序列耗尽形成 `程序失败阶段::中性实例材料维护`，不得静默停维。
15. 周期维护身份使用 `0x4E43'0000'0000'0000` 前缀，低 48 位为进程内原子单调非零序列；资源失败续用同键，漂移重组换键，进程重启可重新开始。抽象完成调用不得使用该前缀。

## 7. 旧 ABI 退出

1. `新增状态_v2(const L2状态首态请求_v2&)` 固定为零写兼容拒绝，不再形成状态、主体关系、当前选择或任何新账。
2. `发布状态动态原子迁移_v2(const L2状态动态迁移请求_v2&)` 固定为零写兼容拒绝，不再形成新状态、动态、当前选择或跨 owner 原子事务。
3. 两类旧幂等账只读保留，用于历史诊断和旧响应解释；新中性 ABI 使用独立幂等域，不得命中或续写旧账。
4. 旧 v1 兼容拒绝入口继续保持零写；不得把新中性语义重新绑定到任何旧 DTO 名称。
5. 本规范只治理世界状态节点，不规定任务阶段状态的宿主或迁移入口。任务阶段消费者必须退出两类旧 v2 生产调用；任务首态和迁移由 ARCH-L4 task owner 经任务域正式入口写入并读回 `Vt` 上的任务状态和状态迁移记录，不得以本规范的世界状态、动态或当前选择替代。执行造成的世界变化仍可按世界状态 / 动态合同独立记录。
