# 7100 子规范 世界存在实例与概念支持闭环

编号：7100

日期：20260912

版本：v1.5

状态：正式子规范

直接上级规范：1140。

直接依赖规范：1120、1130、1150、1160、1170、1180、1190、2100、2200、2210、2220。

相关边界规范：7110、7140、7150、7160、7200。

## 1. 定位

本规范规定世界树存在实例的创建、未归类存在、世界事实支持概念、实例别名、概念定义对实例扩充和可追溯归类边界。概念身份、存在 / 特征 / 动态本体根和锥体结构唯一服从 2220；本规范不再建立“概念存在”或让世界存在节点兼任概念。

## 2. 世界存在身份

具体存在使用 1140 的世界存在身份，并通过场景成员、特征、状态、动态及其它世界关系形成完整事实。创建一个世界存在不要求已有概念：外设或内部观察可以先发布尚未识别的具体对象，再在证据充分时追加概念支持关系。

未归类只表示当前没有适用的世界事实支持概念关系，不是特殊节点类型、永久标签、默认概念或错误状态。

## 3. 概念支持

存在实例通过 7140 的世界事实支持概念关系接入概念空间：

```text
世界存在实例身份
-> 世界事实支持概念关系
-> 存在、特征或动态本体根中的独立概念身份
```

同一实例可以支持多个概念，也可以跨多个本体根支持概念；同一概念可以由多个实例支持。支持关系是概念树叶级引用，概念空间不得复制存在节点或拥有其生命周期。

按实例读取概念组和按概念读取实例组必须返回完整确定排序集合。不存在支持关系时返回合法空集合，不得猜测默认概念。

## 4. 已分类与未分类创建

未分类创建：

```text
明确一个已发布的直接所属场景、直接组成父存在或父场景绑定
-> 同次创建世界存在身份和唯一初始绑定关系
-> 有真实准确值依据时建立或复用F，并显式建立已知引用及本次采用；缺失时不补造
-> 完整读回世界事实
```

已分类创建：

```text
业务层取得一个或多个当前概念
-> 明确一个已发布的直接绑定节点及绑定种类
-> 同次创建世界存在身份和唯一初始绑定关系
-> 按真实依据建立特征引用，并显式扩充合同允许的缺失结构
-> 同截止读回实际采用、组成及关系，逐项核验概念约束
-> 仅为核验成立的项建立世界事实支持概念关系
-> 完整读回世界事实和概念支持组
```

两种创建流程的初始绑定均按1140 / 7150：直接所属场景、直接组成父存在或直接子场景的父场景三选一，不能为完成流程补造绑定节点，也不能先发布无绑定存在再补挂。未分类只表示尚无适用概念支持，不表示可以没有初始结构位置。请求缺少绑定或字段不可解释时返回结构化入口拒绝；绑定未找到、已退出、错类、错树、包含冲突、事实代次漂移、资源失败或历史不一致时保留精确非成功。所有失败均在零新身份、零写入前于最终责任边界触发一次统一调试诊断；诊断宏关闭后机器结果不变。固定系统锚点和本体根的具名初始化不走普通实例创建入口。

上述已分类闭环是 L5 之外业务组合，不是 L2 存在节点创建函数的隐式副作用。已有概念只是待核验的分类依据，不保证新实例满足；不得先发布支持，再靠补结构凑齐证据。不能满足的项不建立支持，资料不足或技术失败与确定不满足分开；未归类或部分归类及已发布阶段如实报告。已经合法发布的世界存在是否退出或保持未分类，由业务事务合同明确裁决，不由数据层猜造概念或撤销事实。

存在应用可以在未分类创建的世界事实完整读回后，自动执行 7110 的精确查找、新建、分割 / 分类聚合与层内组合形成，再逐项发布支持。该自动过程属于显式应用编排，不要求调用者手动列出每一个概念组合，也不进入世界数据服务 CRUD。世界事实已经发布而后续抽象失败时，返回已完成阶段并允许原键继续；不得把整个过程报告为零写失败。尚未具备组成、特征或关系见证时保持可说明的未归类状态。

## 5. 归类形成

为已有实例追加概念支持必须先由业务层：

1. 从存在、特征或动态本体根取得与当前归类需求有关的候选概念；
2. 在本次一致读取范围内回读实例和候选定义所需证据；涉及当前特征时先取7150当前采用再读取准确F，场景、组成、状态、动态及其它关系按实际约束读取，不把全部已知F当作同时观察；
3. 判断该具体世界事实是否支持候选抽象；
4. 提交强类型支持关系请求；
5. 发布后从实例和概念两个方向完整读回。

词条、名称、任务局部语言候选路由、显示分类、索引命中和相似度只能形成候选，不能直接建立支持关系。候选目标类型必须从正式目标结构读回，不能从词条或本次词性判断推断。

## 6. 实例别名与指代

概念名称由 2210 的概念—词条关系表达。实例长期别名由存在对象领域的实例—词条具名关系表达；一次语言位置指向实例使用 1110 指代。

```text
词条“飞机” -> 概念名称 -> 存在根概念“飞机”
词条“B-1234” -> 实例别名 -> 世界存在实例 B-1234
世界存在实例 B-1234 -> 支持概念 -> 概念“飞机”
```

一个实例可以有多个别名，同一语言最多一个当前首选别名。别名不得参与实例同一性或概念唯一性裁决。

## 7. 概念定义对实例的扩充

概念定义可以成为实例结构扩充的业务输入，但类型或概念值域本身不提供具体存在的准确值。只有真实准确值依据已成立时，才按1130 / 4110建立或复用F，并按7150显式维护本存在的已知引用及必要当前采用；不得取域中点、默认值或其它实例的观察补成事实。缺准确值时保留待补信息，不建立旧宿主实例槽或空值F。扩充必须显式授权并遵守：

1. 实例已有结构优先，不被概念默认材料覆盖；
2. 多概念冲突必须由业务规则裁决，不能按名称或遍历顺序静默取首项；
3. 只补合同明确允许的缺失结构；
4. 需求、任务、方法、能力、用途、运行统计和当前状态不得作为概念关系自动复制；
5. 每项扩充保留来源概念、定义角色和发布证据。

## 8. 生命周期与退出

退出支持关系不退出实例或概念。实例退出时，当前支持关系必须按引用保护合同闭合，但概念及其它实例支持保持不变。概念退役或退出遵守 7140，不得删除世界实例。

支持只证明对应证据范围内的满足。历史支持仍保留不证明本次仍归类；当前归类须重新核验本次采用及其它定义约束。采用切换不自动删除旧支持；需要退出已不适用于本次的支持时由业务经具名入口处理并保留历史，不改写旧关系目标或用新概念覆盖旧历史。

## 9. 禁止规则

1. 禁止让存在节点兼任概念节点或概念本体根。
2. 禁止强制所有新世界实例在创建时已有概念。
3. 禁止在世界数据服务创建实例时隐式创建概念；应用层在实例读回后按 7110 自动形成不受此项禁止。
4. 禁止把第一个概念投影升级为默认权威概念。
5. 禁止用实例名称、词性或索引命中建立概念支持。
6. 禁止由概念扩充覆盖实例已有事实或复制运行期结论。
7. 禁止因支持关系退出而删除实例或概念。

## 10. 验证合同

验证至少覆盖未分类实例合法绑定创建、已分类组合、多概念与跨根支持、双向完整读取、候选不落账、实例 / 概念 / 支持三类生命周期分离、显式扩充不覆盖和历史支持关系回查。还须覆盖三类初始绑定、缺失/无效/错类绑定诊断且零身份零写、直接组成创建不补造场景、系统初始化不能被普通请求冒用；有概念无准确值不猜造F；先核验再支持，部分归类与失败不伪报全成；已知历史F及保留支持不冒充当前采用或本次满足。
