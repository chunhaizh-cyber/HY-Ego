# 7100 子规范 存在概念首次形成、实例创建与支持闭环

编号：7100

日期：20260916

状态：正式子规范

直接上级规范：1140、2220。

直接依赖规范：1130、1140、1150、2100、2220、7140、7150、7160。

相关边界规范：7110、2210、4200、4230、4240。

## 1. 定位

本规范只闭合“一个拟建立的世界存在，如何先形成或复用其存在概念，再建立实例”的首次路径，以及实例建立后概念使用、支持和名称的分账边界。

存在概念的主动归纳、共同上位形成和归类由7110规定；存在类不生成概念，概念树类不建立世界存在。概念身份与世界存在身份始终独立。

## 2. 首次路径的输入与完整定义

普通世界存在的建点材料必须给出本次截止已经知道、允许参与存在概念定义的全部事实。它们由7110的三组抽象约束规范化：

```text
自身特征概念约束
+ 子存在组成概念和角色约束
+ 关系类型、参与角色及其概念约束
```

“全部”只指本次建点定义范围内已经知道的世界事实；未知不等于明确缺失。事实代次、幂等键、来源账、缓存、显示、日志、绝对时间、实例节点编码和仅描述本次发生的证据不进入概念签名。具体子存在、具体特征和具体关系端点只能作为形成或支持证据；定义中只保存其抽象约束和概念引用。

自然语言名称关系仍按2210保存，名称本身不直接决定概念同义。若正式特征类型已经把某种名称材料定义为可参与的特征约束，则按该特征类型和值域的完整语义参与定义，不能把原始词面或词条编码当作快捷身份。

### 2.1 完整定义提供者合同

概念树类须提供与旧`纯概念定义`相互独立的“完整存在概念定义”值式合同。它固定保存且只保存下列三组：

```text
完整性声明 = 本次定义范围已知事实完整
+ 自身特征概念约束（特征概念身份）
+ 组成约束（子存在概念身份、组成角色稳定编码）
+ 关系约束（关系类型稳定编码、从1连续的有序参与角色；每角色为存在概念身份约束）
```

完整性声明由调用方负责：它承诺已经把本次范围内已知、允许参与定义的事实完整交给提供者；提供者不扫描世界事实、缓存、索引或其它概念补齐，也不将未知解释为零项。

组成角色、关系类型是其既有正式合同已经裁决的非零 `稳定编码`，其公开语义固定为 `uint64_t`。完整定义提供者只拒绝零编码，并按其无符号值进行确定排序、精确相等与持久读回；它不从名称、显示、端点形状或局部关系猜测角色/类型含义，也不新增角色/关系类型验证或登记提供者。L1 当前只提供标量 `I64` 属性值，故这两类稳定编码的单值事实必须以 `std::bit_cast<int64_t>(uint64_t)` 无损写入，并以 `std::bit_cast<uint64_t>(int64_t)` 无损读回；不得用数值转换、符号解释或截断替代。参与角色顺序必须从1连续、无重复；同一关系约束内每一顺序只允许一个存在概念约束。

自身特征项须读回为当前特征类别概念；组成子概念及关系参与概念须读回为当前存在类别概念。三组分别按其完整字段确定排序并拒绝完全重复项；组成唯一性与排序只按 `(子存在概念身份, 组成角色稳定编码)`。空组三者均可合法存在，但完整性声明仍不得省略；`2220`的具名通用存在定义是三组均空的唯一例外规则，不得由漏填隐式获得。

提供者至少公开“规范化、精确查询、创建或复用、完整读回”四项操作。精确查询只能在完整规范化定义逐字段相同、类别为存在且概念未退役时命中；未确认不存在、发布未知或读回失败不得新建。创建或复用只发布概念身份、类别、完整定义记录、必要生命周期及零直接上位；不得建立E、真实特征/组成/关系事实、概念使用、支持、名称或概念上下位边。定义先发布而后续实例失败时按第3节保留该概念并以原完整定义重放查询。

## 3. 先概念后实例

世界树建立普通存在的顺序固定为：

```text
取得完整建点材料和显式世界挂靠
-> 规范化完整存在概念定义
-> 在存在类别中精确查询
   ├─ 命中：核验并复用概念
   └─ 确认不存在：创建概念并完整读回
-> 取得已发布概念身份
-> 调用存在类建立E、初始绑定、事实和对概念的必要使用引用
-> 完整读回世界存在和概念引用
```

首次查询只接受完整定义精确相同的命中。局部特征、相似名称、同一类型、索引首项、相似度、单个已有上位概念或读取不完整均不能复用。相同完整定义的多个世界存在可以合法复用同一概念；世界存在的稳定身份仍由各自E节点表达。

本路径中新创建的具体存在概念可以是零直接上位的顶层概念；不得为了挂入伪造存在概念总根、通用概念或未被请求证明的父概念。已有概念的直接上位保持其已经发布的结构。后续只有7110的主动归纳归类路径可以形成新的共同上位和调整必要的直接边。

概念定义先发布而世界存在建立失败时，保留真实已发布概念；重试必须用原完整定义先查询复用。概念发布未知或读回失败时不得继续建立世界存在；世界存在发布未知或读回失败时按原请求收敛，不能换键重建。

## 4. 实例事实、概念使用与支持

概念定义不能代替世界事实。世界存在建立时仍按1140、7150和相邻对象规范发布真实特征、组成、关系及唯一结构挂靠；不能从概念域中点、其它存在或名称补造准确事实。

建立后的E对概念的必要使用引用与“世界事实支持概念”关系分账：

- 使用引用使本次世界建点能够引用已发布概念，并按其专属合同保护该概念；
- 支持关系只在E及相关世界事实已经发布后，按实际证据证明其满足该概念定义时建立；
- 一个E可以支持多个存在、特征或动态概念；支持关系不改变E的世界身份、场景/组成归属或概念图的直接上下位。

后续发现新的概念定义事实时，不得改义旧概念。应用以扩充后的完整定义重新查询或创建更具体概念，并按具名合同更新相关使用、支持或归类关系；历史支持不因当前事实变化而被改写。

## 5. 不属于首次路径的事项

下列事项不得作为本规范的隐式副作用：

1. 扫描所有世界存在或顶层概念以尝试组合；
2. 因某个局部特征相同而自动建立类别概念；
3. 自动形成“母亲、女儿、教师”等角色概念；
4. 由名称、词性、显示分类或索引命中建立概念使用或支持；
5. 用未发布的待建实例、未来子存在或缓存当作概念定义或支持端点。

这些工作只能由业务/认知应用在有明确归纳需求时调用7110；无共同完整定义是正常的零写入结果。

## 6. 验证语义

验证至少覆盖：

1. 建点材料的全部概念定义事实参与规范化，未知不被补成缺失；
2. 同完整定义跨实例复用，局部相同不得误复用；
3. 概念先发布、实例后建立，任一阶段失败如实报告已发布阶段；
4. 新概念允许零直接上位，不建立存在概念总根或伪造父概念；
5. 实例事实、概念使用和世界事实支持关系分别读回；
6. 后续细化建立或复用新概念，不改义旧概念或覆盖历史支持；
7. 名称、缓存、来源、日志和技术字段不成为概念唯一性捷径。

## 7. 退役口径

下列旧口径退出新生产：

- 先建立未归类世界存在、再由概念应用补建首次概念；
- 把“未归类”作为普通存在创建的默认正常分支；
- 在存在数据服务CRUD内隐式生成概念；
- 用具体实例名称、实例编码或本次世界证据作为存在概念签名。

旧代码、持久格式和历史记录只按迁移/审计合同读取，不得恢复上述生产路径。
