## 1. 目的与适用范围

本规范定义海中鱼巣进程入口、启动选项、模式路由、普通应用装配、系统初始化、只读投影、审计投影和进程宿主的依赖方向。它不改变节点、关系、语素、需求、任务、方法、概念图或生产运行期的既有领域语义。

生产程序不再承载完整自检或专项验收启动模式、自检运行器和验收专用模块。验收由生产二进制之外的调用者按 ACCEPTANCE-01 经正式公开入口和权威状态读回完成；这一退出不删除或泛化本规范的生产机器合同。

## 2. 薄入口

`海中鱼巣/入口.cpp` 只允许：

1. 接收 `int 参数数量, char* 参数组[]`；
2. 调用具名启动选项解析与组合校验函数；
3. 在请求有效时调用唯一顶层程序函数；
4. 调用具名退出码映射函数并返回。

入口不得构造仓库、事务、领域服务、线程、数据库适配器、控制面板服务或窗口；不得创建、读取、删除或核对节点、关系、语素、需求、任务、方法、状态、动态或概念结构；不得包含自检 / 验收正文、验收登记、计时器、信号处理器、驻留循环、SQL 往返、控制面板投影或人读输出。

## 3. 启动模式

启动模式是强类型枚举，固定只保留：

```text
普通控制面板
无窗口常驻
生产运行期
```

无参数选择普通控制面板。下列两个字符串各选择一个非默认生产模式：

```text
--headless
--runtime-context
```

旧 `--self-test-exit`、`--database-self-test-exit`、`--warehouse-performance-self-test-exit`、`--d455-real-sample-exit` 不再是合法模式，按未知参数拒绝且不保留兼容转发。参数数量小于 1、参数数组为空、任一参数指针为空、未知字符串、重复 flag 或两个以上模式 flag 都是无结构变化的逻辑内拒绝。所有拒绝均由结构化解析结果承载，不依赖控制台、日志或弹窗。

## 4. 结构化结果与退出码

启动解析结果必须含解析状态、模式和拒绝参数索引。程序运行结果必须含模式、运行状态、失败阶段枚举以及适用生产结果；文本只允许作为非权威诊断材料。

退出码固定为：

```text
0：请求有效且所选生产模式成功完成；
1：请求已准入，但装配、初始化或运行宿主执行失败；
2：参数或模式组合被逻辑内拒绝。
```

日志写入成功、日志是否存在、启动耗时和人读文本不得改变上述状态或退出码。生产程序不使用退出码表达验收 PASS、失败项数量或覆盖率。

## 5. 普通应用装配和系统初始化

普通应用上下文在专用装配模块中拥有当前普通程序所需的唯一基础数据集、持久化与恢复服务、领域服务、6190服务值治理模块、自我线程、任务管理/工作线程、统计服务、显示服务和SQL审计适配器。成员声明顺序必须等于构造依赖顺序，析构顺序反向；引用成员不得长于其所有者。

普通应用具名运行配置至少提供非零治理邮箱容量、非零自我线程创建停门等待毫秒和非零启动失败回收诊断等待毫秒。它们只控制本次进程的工程资源和调用方等待，不进入 self 存在事实、创建请求的业务选择、治理消息、任务占用、业务幂等或持久恢复；配置相等也不证明业务事实相等。等待时限到不得 detach、覆盖或销毁仍为 joinable 的线程租约。

普通应用必须先按当前持久化合同取得同一受控数据根，完成合法空仓建立或current-only恢复，再构造唯一基础数据集和所需业务服务。默认受控根仍属于装配配置；生产外调用者可以经同一正式装配入口显式指定隔离绝对根，不增加验收模式、内存生产分支或失败后空仓回退。一次进程只选定一个有效配置，失败按同配置重试，不因再次调用无参入口改用另一根。

恢复只恢复current-only底座与其最小技术材料，不恢复旧端口、服务指针、事实代次、历史见证、运行锚点或初始化包。已合法发布的结构由各业务类按当前结构精确复用；旧格式、冲突或不完整材料不得换键、清库、猜造身份或回退空仓绕过。

系统初始化按固定顺序：

1. 普通应用构造并持有唯一基础数据集、持久化/恢复服务、业务服务、6190服务值治理模块和唯一自我线程对象；线程先停在关闭的治理运行门，邮箱容量与等待时限只来自具名运行配置。
2. self线程按8121初始化基础数据集、先天类型与概念根、世界树根场景、自我所在场景和唯一自我存在。根、自我和场景必须通过对应业务类完整读回，不能由名称、编码顺序、缓存、日志或旧阶段材料猜测。
3. 安全根侧形成或复用安全值FT、完整域概念、自我安全实例特征与当前采用。服务根侧不得建立服务值FT、特征概念、自我实例特征或当前采用；6190在唯一自我成立后建立或复用绑定该自我的唯一服务值账户。
4. self初始化需求树，并通过需求类建立或复用安全根与服务根。安全根引用自我安全实例特征，服务根引用6190账户；两根目标均为`I64_MAX`，冷启动首次当前值均为`I64_MAX / 2`，但当前值承载和写入方严格分离。
5. self初始化方法根和本能函数登记，随后完整读回世界树、自我、双根、服务值账户和方法根；任一必需结构、绑定、规则版本或读回非成功都保持停门，不能用线程已经创建、邮箱为空或部分成功替代。
6. 普通应用装配manager、worker、支持线程和必要外设/结果渠道；消费者和生产者均就绪后，self先完成双根首次fresh复核，再独立开放治理运行门。运行门开放前不得消费治理邮箱或派发现实动作。
7. 启动失败候选固定按“锁存停止 -> 唤醒关闭门等待 -> 等待完成见证 -> 完成后join -> 清除候选”回收。等待与诊断时限均来自普通应用具名运行配置；时限到不得detach、覆盖或遗失线程，普通应用上下文继续持有租约，顶层不得销毁仍含joinable候选的上下文并伪装成已安全返回。

旧方法登记根阶段、本能根运行锚点、阶段21初始化包、双FT/双实例特征和线程创建前先建立完整自我结构的路线不再是现行初始化合同。旧失败阶段数值可以保留为迁移诊断映射，但不得反向恢复旧顺序、旧对象或成功判定。

上述结构与账户读回都是当前正式事实或内部治理账户的值式投影，不是第二份身份来源。初始化函数为保证自身后置条件而执行的写后读回仍属于生产合同，不得误删，也不得包装成验收单元、登记到自检运行器或返回验收PASS。

## 6. 验收体系退出

原 v0.1 第 6 节的 14 项显式自检迁移合同整体退出，不迁移到其它生产模块。生产目标不得编译 `自检运行器`、`自检单元结果` 聚合、验收登记表、固定验收编号、验收包装函数、隔离验收上下文或 PASS 汇总。

若旧 14 项中某项同时描述生产初始化后置条件，只保留第 5 节生产函数自身已有的结构化检查与写后读回；不得保留其自检入口、夹具、负例、计数或人读验收输出。公开行为的验证改由生产二进制之外的验收驱动调用正式入口并核对权威状态。

## 7. 投影、审计与宿主

世界树、语言材料、依附世界树的存在 / 特征 / 动态概念图和独立因果链由控制面板只读投影模块生成，返回现有 `控制面板树结构材料`。概念投影中的叶级世界事实和直接因果引用只引用权威身份，不复制世界事实或因果事实；因果层次只按本次应用目标、范围、版本和展开截止值式展开。场景层级保持世界树投影，不生成场景概念树。投影不得写业务结构或裁决机器事实。

SQL 结构统计是非权威审计投影。普通模式允许执行一次最佳努力写入，失败只进入结构化审计结果并可记录诊断，不得使系统初始化失败。数据库验收模式已经退出；数据库读回不得成为领域初始化成功条件。外部验收如需核对 SQL 审计投影，必须经正式公开生产入口，不能恢复旧数据库自检驱动。

信号安装、控制面板窗口运行和无窗口等待由程序运行宿主模块负责。现有 `运行宿主线程` 是领域消息线程，不承载 Win32 窗口或进程信号职责。无窗口常驻模式在self线程完成8121初始化、停门并随后合法开门后接入既有 `运行无窗口宿主` 和同一停止信号租约，不建立第二运行宿主线程、自我专用宿主或并列驻留循环；宿主返回后必须请求停止、唤醒、等待完成并 join 唯一 self，再允许普通应用上下文退出。

普通控制面板宿主尚未接通真实窗口时，self初始化及开门成功后必须同样安全停止、唤醒、等待完成并 join 唯一 self，然后结构化返回 `程序运行状态::宿主失败 / 程序失败阶段::控制面板窗口(12)`。该临时真实返回只证明当前宿主缺口，不证明控制面板已运行。self初始化、停门或开门先发生的失败必须保持其真实失败阶段，不得被阶段12覆盖。

## 8. 生产运行期

生产运行期模式构造并持有 `生产运行期会话`，以 `生产运行期启动请求{生产运行期启动请求当前版本}` 调用：

```cpp
生产运行期启动结果 生产运行期会话::启动(
    const 生产运行期启动请求& 请求);
```

运行结果必须按 `生产运行期启动结果::成功()` 和状态映射，不得把结构体直接当作退出码。会话和其中的上下文租约必须覆盖该模式的完整运行函数。

## 9. 人读日志

旧 `HY_EGO_DEBUG_LOG_SELF_TEST_ENTRY_INITIALIZATION`、`HY_EGO_DEBUG_LOG_SELF_TEST_DATABASE`、`HY_EGO_DEBUG_LOG_SELF_TEST_WAREHOUSE_PERFORMANCE`、`HY_EGO_DEBUG_LOG_SELF_TEST_D455` 四个自检调试宏及 `SELF_TEST_ENTRY_INITIALIZATION`、`SELF_TEST_DATABASE`、`SELF_TEST_WAREHOUSE_PERFORMANCE`、`SELF_TEST_D455` 切片正式退出，不迁移成新的总宏、双目标矩阵或证据矩阵。

普通运行日志和逻辑错误日志继续遵守日志系统规范。生产业务仍返回结构化结果，生产程序不自判验收 PASS、不包含验收运行器；人只能通过具名日志观察运行是否符合预期。日志不是机器事实、自动通过条件、结构化结果或权威状态读回的替代品。

## 10. 生产维护能力分账

SQL 审计投影、性能遥测、D455 生产采集 / 真实材料入口、运行期健康与故障隔离，以及生产初始化后置条件检查，在具有正式生产所有者和调用路径时属于生产维护或业务能力，必须保留。数据库自检驱动、性能基准自检、D455 真实样本自检夹具、运行期验收块和验收包装不属于生产维护能力，必须退出。

文件或函数名含“检查”“专项”“性能”“数据库”或“D455”不足以决定删除。无法从正式生产合同和调用路径唯一证明职责的对象，后续删除计划必须具名退回设计裁决，不得机械删除。

## 11. 退出与完成边界

规范发布后的精确删除计划必须删除启动聚合中的旧自检 import、包装、登记和模式路由，自检运行器与验收专用模块，以及工程 / filters 编译引用；历史施工、验证和集成验收记录保留。代码删除不得提前混入本规范发布单元。

本规范只冻结生产合同保留项和验收体系退出项，不证明旧代码已删除、生产程序已构建、外部黑盒验收已执行或任何服务已通过。
