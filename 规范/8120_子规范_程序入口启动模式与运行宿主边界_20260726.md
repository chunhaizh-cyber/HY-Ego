# 8120 子规范 程序入口启动模式与运行宿主边界

编号：8120

版本：v0.11
状态：正式子规范

直接上级规范：8100。

直接依赖规范：0050、2220、4050、4240、7140、8110。

相关边界规范：1190、4310、4320、日志系统规范、ACCEPTANCE-01。

## 1. 目的与适用范围

本规范定义海中鱼巣进程入口、启动选项、模式路由、普通应用装配、系统初始化、只读投影、审计投影和进程宿主的依赖方向。它不改变节点、关系、语素、需求、任务、方法、概念图或生产运行期的既有领域语义。

生产程序不再承载完整自检或专项验收启动模式、自检运行器和验收专用模块。验收由生产二进制之外的调用者按 ACCEPTANCE-01 经正式公开入口和权威状态读回完成；这一退出不删除或泛化本规范的生产机器合同。

## 2. 薄入口

`海中鱼巣/入口.cpp` 只允许：

1. 接收 `int 参数数量, char* 参数组[]`；
2. 调用具名启动选项解析与组合校验函数；
3. 在请求有效时调用唯一顶层程序函数；
4. 调用具名退出码映射函数并返回。

入口不得构造仓库、事务、领域服务、线程、数据库适配器、控制面板服务或窗口；不得创建、读取、删除或核对节点、关系、语素、需求、任务、方法、状态、动态或概念结构；不得包含自检 / 验收正文、验收登记、计时器、信号处理器、驻留循环、SQL 往返、控制面板投影或人读输出。

## 3. 启动模式

启动模式是强类型枚举，固定只保留：

```text
普通控制面板
无窗口常驻
生产运行期
```

无参数选择普通控制面板。下列两个字符串各选择一个非默认生产模式：

```text
--headless
--runtime-context
```

旧 `--self-test-exit`、`--database-self-test-exit`、`--warehouse-performance-self-test-exit`、`--d455-real-sample-exit` 不再是合法模式，按未知参数拒绝且不保留兼容转发。参数数量小于 1、参数数组为空、任一参数指针为空、未知字符串、重复 flag 或两个以上模式 flag 都是无结构变化的逻辑内拒绝。所有拒绝均由结构化解析结果承载，不依赖控制台、日志或弹窗。

## 4. 结构化结果与退出码

启动解析结果必须含解析状态、模式和拒绝参数索引。程序运行结果必须含模式、运行状态、失败阶段枚举以及适用生产结果；文本只允许作为非权威诊断材料。

退出码固定为：

```text
0：请求有效且所选生产模式成功完成；
1：请求已准入，但装配、初始化或运行宿主执行失败；
2：参数或模式组合被逻辑内拒绝。
```

日志写入成功、日志是否存在、启动耗时和人读文本不得改变上述状态或退出码。生产程序不使用退出码表达验收 PASS、失败项数量或覆盖率。

## 5. 普通应用装配和系统初始化

普通应用上下文在专用装配模块中拥有旧式普通程序当前所需的仓库、领域服务、初始化服务、自我线程、统计服务、显示服务和 SQL 审计适配器。成员声明顺序必须等于构造依赖顺序，析构顺序反向；引用成员不得长于其所有者。

系统初始化按固定顺序：

1. L5 之外的系统初始化调用方提供一个非零不透明幂等身份，并在同一普通应用上下文生命周期内把它固定为项目树选择；正式 `运行普通程序` 使用项目默认固定值，经普通应用持有的唯一 A1 透明取得同一个 R1 场景服务；
2. 调用 R1 正式 `建立场景树根`，只接受首次提交或同请求精确重复，并立即以返回的 `L2场景树身份` 调用正式 `读取场景树`；只有根、根标记、树身份和同截止完整读回互证成功，才把调用方拥有的值式根读回发布到普通应用上下文；
3. 以同一次 I1 成功结果逐字段形成版本化 `自我世界树根消费请求`，调用唯一 I2 `自我世界树根消费适配器::消费`；I2 必须经 A1 取得同一个 R1 场景服务，重新读取当前场景树结构登记并正式 `读取场景树`，逐字段确认树身份、根场景、根标记、首次生命周期、根无父和整树完整后，才发布调用方拥有的自我根消费材料；I2 不建立、扫描、猜测、补写或从缓存恢复根，对 R1 / A1 和全部业务事实零写；
4. I1 成功而 I2 失败时以 `自我世界树根消费 = 16` 结构化短路。I2 真实实现、验证并接通后，删除 I1 叶引入的临时 `自我初始化待适配 = 15` 枚举和无条件短路，但数值 15 永久不复用；当前没有真实自我形成提供者，因此 I2 成功后固定以 `自我初始化能力未实现 = 17` 短路。阶段 17 不得用空 provider、固定成功、旧完整自我结果、缓存或历史记录解除；三路都不得调用方法根、自我线程、概念、投影、信号或宿主；
5. 后继自我形成按 7130 的三叶合同，以最终 R1 / A1 / L2 ABI 真实建立并正式读回唯一自我存在、自我所在场景、自我内部世界、当前位置成员和内部世界宿主；中性 L2 结构叶不能删除阶段 17。只有 L5 提供者完整成功并接通生产入口后，才删除阶段 17 的“能力未实现”无条件短路；真实形成失败仍以 `真实自我形成 = 17` 返回；
6. 真实自我形成成功后，当前后继缺口固定为“存在、特征、动态、因果链四个语言无关概念本体根生产初始化”，以 `概念本体根生产初始化能力未实现 = 18` 结构化短路。阶段 18 不读取或建立语言、词条、词性，不建立场景概念根，也不生成任何普通概念或具体二次特征概念；因果链根在本阶段只建立空根，不读取动态列表、不形成因果候选、不发布直接因果事实或普通因果链概念。4240 的概念结构 CRUD、计划、骨架或编译不能解除阶段 18；只有独立生产初始化提供者经同一概念结构服务正式建立或幂等收敛四个固定根，逐根正式读回并证明恰为四个、身份互异、根角色正确、永久活跃、无上位且零额外根后，才能继续；
7. 阶段 18 成功后必须先初始化并正式读回唯一方法登记根；能力缺失或任一非成功以 `方法登记根生产初始化 = 19` 结构化短路。生产调用方只能经普通应用唯一 `L2方法结构聚合服务` 取得同一 `L2方法结构服务`，按“零代次全组预读 -> 缺失时同幂等身份建立 / 发布未知原请求重放 -> 非零单根正式读回 -> 非零最终全组恰一根读回”收敛。正常重复预期零根写但不得省略正式读回。本叶不创建方法首、默认方法、治理虚拟存在、方法生命周期、条件、结果、动作入口、任务选择或线程；旧 `BIZ-L3-001-03-01` 及其 L4 不得复活、改名或改挂。只有方法登记根生产初始化真实成功并完成正式读回后，才允许进入本能根运行初始化。
8. 方法登记根生产初始化成功后的最早后继固定为“建立并完整读回本能根运行锚点”。应用启动提供者消费 SELF-FORM 唯一自我和同一普通应用上下文服务，按 0050、6120、6130 建立或幂等收敛安全 / 服务根特征定义、实例、下中点首次当前值与初始状态、`I64_MAX` 目标合同、普通根需求、列表项和两个固定根角色；二次特征只登记可复用概念信息，不形成差值实例或值。全部材料完成后必须在同一非零最终截止完整读回并形成值式锚点；首次、精确重复、部分恢复、冲突、漂移、资源失败和内部不一致均由结构化结果分账，任一非成功以 `本能根运行初始化 = 21` 短路，禁止创建自我线程。失败阶段数值只是稳定 ABI，不表示与阶段 20 的执行先后。
9. 本能根运行锚点完整成功后的最早后继固定为“创建唯一自我线程并使其停在关闭的治理运行门”。普通应用上下文必须先持有唯一自我线程对象，再把 I2 本轮正式再读回证明的根消费材料、SELF-FORM 正式读回的真实自我材料和完整本能根运行锚点作为值式业务输入；四本体根和方法登记根结果只作调用顺序门，不进入请求或线程缓存。成功必须由线程入口真实进入、完整创建请求锁定、内部停门见证、运行门仍关闭、治理邮箱已冻结批次数为零和上下文仍持有唯一租约共同证明；8110 生命周期消息只作投影，不能替代内部见证。创建失败、入口未进入、停门失败或启动候选不能在诊断时限内安全回收均映射 `自我线程创建并停门 = 20`。旧 `自我线程启动 = 4`、`自我线程初始化 = 5` 和已退役数值 15 均不得复用。
10. 启动失败候选固定按“锁存停止 -> 唤醒关闭门等待 -> 等待完成见证 -> 完成后 join -> 清除候选”回收。诊断时限到不得 detach、覆盖或遗失线程；普通应用上下文继续持有租约，顶层不得销毁仍含 joinable 候选的上下文并伪装成已安全返回。自我线程创建并停门成功后才允许继续支持线程、工作线程池、任务管理线程、外设线程等准备；只有这些消费者和生产者就绪后，才由 BIZ-L2-001-08 独立开放治理运行门。自我线程不得反向建立或选择根、自我、概念本体根、方法登记根或本能根锚点；运行门开放前不得消费治理邮箱。仅在具名抽象业务已经形成合法概念时，为自我世界存在建立对应事实支持概念关系；未形成概念时保持未归类，不猜造概念。

第 1—2 步只负责当前进程运行期的项目树选择、R1 原子建立或同请求幂等收敛及正式读回发布。请求参数、普通应用成员和返回值均不是根权威事实；根权威只存在于 R1 场景 owner 的根标记与树结构中。当前没有持久恢复发布能力时，不得把固定幂等身份解释成跨进程项目身份，也不得扫描非空旧域、按无父场景认领、选择第一棵树或采用缓存中的旧根。跨进程恢复、旧域迁移和多项目树选择必须分别由具名后继合同承接。

I2 的输入和输出是值式消费材料，不是根权威、自我事实或跨进程恢复状态。同一上下文同请求重复消费每次都必须重新正式读回；异请求在 R1 调用前冲突并保留旧发布值。正式调用方先从同一次 I1 成功结果形成局部请求，再进入 I2；I2 不调用 I1 getter、不取得 I1 私有锁，也不持有 I1 引用。锁和线程顺序不产生机器事实。

`写入事务` 空对象不属于上述合同。初始化不得执行重复启动、无效参数、额外实例、删除节点、错误类型、别名或重复初始化验收。初始化函数内部为保证自身后置条件而执行的写后读回仍属于生产合同，不得误删，也不得包装成验收单元、登记到自检运行器或返回验收 PASS。

## 6. 验收体系退出

原 v0.1 第 6 节的 14 项显式自检迁移合同整体退出，不迁移到其它生产模块。生产目标不得编译 `自检运行器`、`自检单元结果` 聚合、验收登记表、固定验收编号、验收包装函数、隔离验收上下文或 PASS 汇总。

若旧 14 项中某项同时描述生产初始化后置条件，只保留第 5 节生产函数自身已有的结构化检查与写后读回；不得保留其自检入口、夹具、负例、计数或人读验收输出。公开行为的验证改由生产二进制之外的验收驱动调用正式入口并核对权威状态。

## 7. 投影、审计与宿主

世界树、语言材料和存在 / 特征 / 动态 / 因果链四个概念本体锥体由控制面板只读投影模块生成，返回现有 `控制面板树结构材料`。概念投影中的叶级世界事实和直接因果引用只引用权威身份，不复制世界事实或因果事实；因果层次只按本次应用目标、范围、版本和展开截止值式展开。场景层级保持世界树投影，不生成场景概念树。投影不得写业务结构或裁决机器事实。

SQL 结构统计是非权威审计投影。普通模式允许执行一次最佳努力写入，失败只进入结构化审计结果并可记录诊断，不得使系统初始化失败。数据库验收模式已经退出；数据库读回不得成为领域初始化成功条件。外部验收如需核对 SQL 审计投影，必须经正式公开生产入口，不能恢复旧数据库自检驱动。

信号安装、控制面板窗口运行和无窗口等待由程序运行宿主模块负责。现有 `运行宿主线程` 是领域消息线程，不承载 Win32 窗口或进程信号职责。

## 8. 生产运行期

生产运行期模式构造并持有 `生产运行期会话`，以 `生产运行期启动请求{生产运行期启动请求当前版本}` 调用：

```cpp
生产运行期启动结果 生产运行期会话::启动(
    const 生产运行期启动请求& 请求);
```

运行结果必须按 `生产运行期启动结果::成功()` 和状态映射，不得把结构体直接当作退出码。会话和其中的上下文租约必须覆盖该模式的完整运行函数。

## 9. 人读日志

旧 `HY_EGO_DEBUG_LOG_SELF_TEST_ENTRY_INITIALIZATION`、`HY_EGO_DEBUG_LOG_SELF_TEST_DATABASE`、`HY_EGO_DEBUG_LOG_SELF_TEST_WAREHOUSE_PERFORMANCE`、`HY_EGO_DEBUG_LOG_SELF_TEST_D455` 四个自检调试宏及 `SELF_TEST_ENTRY_INITIALIZATION`、`SELF_TEST_DATABASE`、`SELF_TEST_WAREHOUSE_PERFORMANCE`、`SELF_TEST_D455` 切片正式退出，不迁移成新的总宏、双目标矩阵或证据矩阵。

普通运行日志和逻辑错误日志继续遵守日志系统规范。生产业务仍返回结构化结果，生产程序不自判验收 PASS、不包含验收运行器；人只能通过具名日志观察运行是否符合预期。日志不是机器事实、自动通过条件、结构化结果或权威状态读回的替代品。

## 10. 生产维护能力分账

SQL 审计投影、性能遥测、D455 生产采集 / 真实材料入口、运行期健康与故障隔离，以及生产初始化后置条件检查，在具有正式生产所有者和调用路径时属于生产维护或业务能力，必须保留。数据库自检驱动、性能基准自检、D455 真实样本自检夹具、运行期验收块和验收包装不属于生产维护能力，必须退出。

文件或函数名含“检查”“专项”“性能”“数据库”或“D455”不足以决定删除。无法从正式生产合同和调用路径唯一证明职责的对象，后续删除计划必须具名退回设计裁决，不得机械删除。

## 11. 退出与完成边界

规范发布后的精确删除计划必须删除启动聚合中的旧自检 import、包装、登记和模式路由，自检运行器与验收专用模块，以及工程 / filters 编译引用；历史施工、验证和集成验收记录保留。代码删除不得提前混入本规范发布单元。

本规范只冻结生产合同保留项和验收体系退出项，不证明旧代码已删除、生产程序已构建、外部黑盒验收已执行或任何服务已通过。
