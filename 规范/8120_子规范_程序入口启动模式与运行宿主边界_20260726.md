# 8120 子规范 程序入口启动模式与运行宿主边界

## 1. 目的与适用范围

本规范定义海中鱼巣进程入口、启动选项、模式路由、普通应用装配、系统初始化、显式自检、只读投影、审计投影和进程宿主的依赖方向。它不改变节点、关系、语素、需求、任务、方法、概念图或生产运行期的既有领域语义。

## 2. 薄入口

`海中鱼巣/入口.cpp` 只允许：

1. 接收 `int 参数数量, char* 参数组[]`；
2. 调用具名启动选项解析与组合校验函数；
3. 在请求有效时调用唯一顶层程序函数；
4. 调用具名退出码映射函数并返回。

入口不得构造仓库、事务、领域服务、线程、数据库适配器、控制面板服务或窗口；不得创建、读取、删除或核对节点、关系、语素、需求、任务、方法、状态、动态或概念结构；不得包含自检正文、计时器、信号处理器、驻留循环、SQL 往返、控制面板投影或人读输出。

## 3. 启动模式

启动模式是强类型枚举，固定为：

```text
普通控制面板
无窗口常驻
生产运行期
完整自检
数据库专项
关系仓库性能专项
D455 真实样本专项
```

无参数选择普通控制面板。下列六个字符串各选择一个非默认模式：

```text
--headless
--runtime-context
--self-test-exit
--database-self-test-exit
--warehouse-performance-self-test-exit
--d455-real-sample-exit
```

参数数量小于 1、参数数组为空、任一参数指针为空、未知字符串、重复 flag 或两个以上模式 flag 都是无结构变化的逻辑内拒绝。性能和 D455 不再隐式打开完整自检。编译时未启用相应能力的性能或 D455 请求是构建能力拒绝。所有拒绝均由结构化解析结果承载，不依赖控制台、日志或弹窗。

## 4. 结构化结果与退出码

启动解析结果必须含解析状态、模式和拒绝参数索引。程序运行结果必须含模式、运行状态、失败阶段枚举以及可选专项结构化结果；文本只允许作为非权威诊断材料。

退出码固定为：

```text
0：请求有效且所选模式成功完成；
1：请求已准入，但装配、初始化、运行宿主、显式自检或专项执行失败；
2：参数、模式组合或构建能力被逻辑内拒绝。
```

日志写入成功、日志是否存在、启动耗时和人读文本不得改变上述状态或退出码。

## 5. 普通应用装配和系统初始化

普通应用上下文在专用装配模块中拥有旧式普通程序当前所需的仓库、领域服务、初始化服务、自我线程、统计服务、显示服务和 SQL 审计适配器。成员声明顺序必须等于构造依赖顺序，析构顺序反向；引用成员不得长于其所有者。

系统初始化按固定顺序：

1. 初始化方法登记根并把 `方法登记根材料` 纳入结果；
2. 启动唯一自我线程；
3. 等待初始化完成并取得语素、世界树、两个根需求快照；
4. 初始化概念图四根；
5. 为自我存在节点建立正常存在根支持；
6. 完整复核结果后返回。

`写入事务` 空对象不属于上述合同。初始化不得执行重复启动、无效参数、额外实例、删除节点、错误类型、别名或重复初始化验收。初始化函数内部为保证自身后置条件而执行的写后读回仍属于生产合同，不得误删。

## 6. 显式自检

当前入口中的 14 个真实验证项必须迁入独立自检模块，每项一个具名函数并各自创建隔离上下文：

```text
概念图四根创建
概念图四根唯一
概念图非名称身份
概念图根名绑定
概念图重复初始化结构不变
自我存在实例根支持
多存在实例根支持
根作实例、错误类型和已删除实例拒绝
自我线程进入与初始化
语素与世界树快照读回
根需求稳定语义与特征定义
安全与服务根需求完整读回
自我线程重复启动结构不变
自我线程无效参数拒绝与生命周期收口
```

每项返回 `自检单元结果`，由现有 `自检运行器` 登记并执行。普通控制面板、无窗口、生产运行期、数据库、性能和 D455 模式均不得调用这些函数。性能、数据库和 D455 只运行各自专项。

## 7. 投影、审计与宿主

世界树、语素树和概念名称材料由控制面板只读投影模块生成，返回现有 `控制面板树结构材料`。投影不得写业务结构或裁决机器事实。

SQL 结构统计是非权威审计投影。普通模式允许执行一次最佳努力写入，失败只进入结构化审计结果并可记录诊断，不得使系统初始化失败。数据库专项必须执行写入和读回一致性核对，并由专项结构化结果裁决退出码。数据库读回不得成为领域初始化成功条件。

信号安装、控制面板窗口运行和无窗口等待由程序运行宿主模块负责。现有 `运行宿主线程` 是领域消息线程，不承载 Win32 窗口或进程信号职责。

## 8. 生产运行期

生产运行期模式构造并持有 `生产运行期会话`，以 `生产运行期启动请求{生产运行期启动请求当前版本}` 调用：

```cpp
生产运行期启动结果 生产运行期会话::启动(
    const 生产运行期启动请求& 请求);
```

运行结果必须按 `生产运行期启动结果::成功()` 和状态映射，不得把结构体直接当作退出码。会话和其中的上下文租约必须覆盖该模式的完整运行函数。

## 9. 人读日志宏

验收、自检、基准和专项的人读信息只能调用统一日志系统的具名调试切片，不得写入普通运行日志，并分别受下列具名宏控制：

```text
HY_EGO_DEBUG_LOG_SELF_TEST_ENTRY_INITIALIZATION
HY_EGO_DEBUG_LOG_SELF_TEST_DATABASE
HY_EGO_DEBUG_LOG_SELF_TEST_WAREHOUSE_PERFORMANCE
HY_EGO_DEBUG_LOG_SELF_TEST_D455
```

对应中文调用宏只调用 `记录调试日志`，调试切片名依次固定为 `SELF_TEST_ENTRY_INITIALIZATION`、`SELF_TEST_DATABASE`、`SELF_TEST_WAREHOUSE_PERFORMANCE`、`SELF_TEST_D455`。关闭时展开为 `do { } while (false)`，所有实参不求值。宏开关不得改变自检是否执行、结构化结果、失败计数、退出码、机器事实、SQL 操作或生产行为。stdout、stderr、`printf`、弹窗、界面文本和另建文件均不得作为上述过程信息旁路。

普通运行日志和逻辑错误日志继续遵守日志系统规范；日志成功不得成为验收裁决条件。
