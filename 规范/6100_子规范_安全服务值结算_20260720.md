# 6100 子规范 主动安全值结算

编号：6100
日期：20260901
版本：v0.7
状态：正式子规范

## 1. 定位

本规范只规定主动安全值结算的事实账 / 账务账分离、实际达成、贡献层级、预算、防重复、动作动态和写入边界。服务合同、服务预算、30% / 70%、到期、服务准备补回和服务值时间衰减已经退出，不再由本规范或其它现行规范建立替代账。

直接上级规范：3100、3200、3300

直接依赖规范：5110、5120

相关边界规范：1120、1160、1170、1190、6110—6150

## 2. 事实账与账务账分离

主动安全值结算不得把任务轮次结论、任务轮次收束、任务权重或方法成功直接换成安全根值。必须保持两类事实分离：

```text
现实事实：物理状态、动作、反馈、验证和归因
账务事实：安全值结算前值、结算后值、变化量和结算动态
```

安全根值的账务变化只能是本规范正式准入的主动安全结算结果，不能反过来证明物理安全改善、需求满足或任务完成成立。

6140 定义的分层安全值是针对“因果信息—目标安全结果—因果图版本”投影单元的安全满足度，不是 6120 的生存安全根值。它可以由有效未复发证据和残余风险维护形成被动变化，但不得借此改写生存安全根值、伪造现实改善或替代主动安全结算。

真实服务请求、服务动作和实际交付只形成普通需求、任务、方法、正式结果及状态 / 动态 / 因果；它们不再产生独立服务账，也不得直接换算安全根值。

## 3. 主动安全结算总链

```text
原子任务轮次形成正式实际结果
-> 来源需求满足
-> 父链能回到安全根目标
-> 世界事实和动作动态证明实际改变
-> 因果验收给出可结算建议
-> 判定结算贡献层级
-> 计算目标实际达成比例
-> 核对预算、结算令牌和同源去重键
-> 审查反向副作用
-> 经安全根控制规则
-> 写安全根当前值变化、结算动态和因果材料
```

任务、需求父链只证明治理归属，不能单独证明主动安全价值可以结算。缺世界事实、来源动作、验证或归因时，只能记录任务轮次结果、需求满足、方法改善、过程证据或结算候选。

### 3.1 主动安全结算来源方法完整集合

“某次安全根当前值变化来自主动安全结算”必须由版本化来源方法完整集合裁决，不能按方法名称、线程、调用点、日志、是否携带方法身份或变化方向猜测。该集合由安全根定义 owner 保存规则版本和完整有序 `L2方法身份` 引用；它不建立第二方法 owner，不复制方法内容、生命周期或可用性。非空成员在被消费时仍须按同一事实截止经方法结构 owner 独立读回。

来源规则版本从 `1` 连续递增；每版保存完整集合而不是增量补丁。集合允许显式 `0` 项，必须按方法身份稳定编码严格升序且无重复。精确重放零第二写入，同键异义、版本跳跃、当前复义或读回不完整均不得发布成功。安全根定义中的 `主动安全结算规则版本` 必须与同截止读回的来源规则版本一致。

当前生产规则版本 `1` 的来源方法完整集合显式为空，因为当前尚无已发布的主动安全结算生产方法。未来建立真实主动安全结算方法时，必须发布新的来源规则版本并由新的安全根定义版本显式绑定；不得原地改写版本 `1` 或仅更新代码常量。

## 4. 结算对象与防重复

1. 正式结算对象是原子任务轮次结果及对应具体安全需求在 fresh 当前值核算后成立的可结算价值。
2. 需求树父级、管理性或汇总性任务只归并结果，不得重复结算已由具体需求路径结算的同源部分。
3. 同一个同源变化证据组只允许结算一次；唯一键至少区分来源需求、目标特征、安全前后状态、来源任务和预算路径。
4. 同一任务轮次支撑多个需求时可以引用同一正式实际结果；每条 `T→D` 仍须分别核对满足事实、预算、AND / OR 归属和结算令牌。
5. 横向外溢只能在来源 owner 正式结算结果形成后发生，并使用候选需求自己的当前值、目标状态和预算重新计算。

## 5. 目标实际达成

结算必须读取 `before`、`target`、`actual` 和满足关系。

```text
增加型：
目标差距 = max(0, target - before)
实际推进 = max(0, actual - before)

降低型：
目标差距 = max(0, before - target)
实际推进 = max(0, before - actual)

达成比例 = clamp(实际推进 / 目标差距, 0, 1)
```

实际结果达到等值或进入区间时，达成比例为满比例；未达到时只有能够证明距离缩小时才按距离缩小计算，否则为零。结算前目标已满足或目标差距为零时不得重复结算。分段结算必须由独立目标、实际值、动作动态、预算和防重复键支持。

## 6. 贡献层级与整数计算

因果距离层级解释原因远近；结算贡献层级限定最大结算额度。二者不得直接互换。以 `DEN = I64_MAX` 作为比例满刻度：

```text
第 N 层贡献分子 = DEN * 9 / 10^N
层级额度 = W * 贡献分子 / DEN
实际结算值 = 层级额度 * 实际达成比例 / DEN
```

第一层、第二层、第三层分别对应最多 `90%W`、`9%W`、`0.9%W`。全部比例和乘法使用整数公式、至少 128 位中间值或等价安全乘除，默认向下取整。有效结果低于最小入账单位时记录为零，不得强行入账 1。

`DEN` 不是分层安全值、任务调度倍率或任何服务预算刻度。

## 7. 同层因素与物理安全边界

风险余量或主动安全贡献层级中的同级因素，先统一正向含义、因素集合版本和公式版本，再按定义因素总数平均。缺失因素不得让其它因素自动变重；有旧正式值时只能保守沿用且不得因本轮证据不足上调，无旧值时按零候选并标记未明确。

风险压力必须先转换为风险余量候选：

```text
风险安全子项值 = I64_MAX - 风险压力值
```

它仍不是生存安全根值。物理因素必须分别形成正式状态、动态和因果，并由版本化主动安全结算规则映射到 `0..I64_MAX` 根刻度；不得把旧百分比、因素配额、加权总分或简单最低值直接写入根值。

`0` 是循环不可维持的终止控制态；`1` 是受限恢复控制态；`>1` 允许主动运行。普通收益、风险平滑、服务请求、任务结果或候选值不得把根值写入 0，也不得把 `A=0/1` 自动改写为主动运行。控制态改变只能来自独立正式安全事实和本规范结算。

## 8. 权重、路径与预算

主动安全结算预算 `W` 只能来自来源需求压力或风险、根需求投影、父任务向叶子任务的正式分配，或有动作动态证据的权重调整方法。列表汇总权重只用于排序，方法结果不得临时写入或抬高 `W`。

1. 每条 OR 路径继承完整父权重。
2. AND 必须归属于确定的 OR 路径，并守恒分配该路径预算。
3. 同层不同 OR 是不同候选路径；同一互斥选择集合最终只有取得结算令牌的路径可消费父预算。
4. 未选择路径、父任务和已结算子任务不得重复消费同一预算。
5. 任务承接时固化预算来源、路径归属和版本；结算不在完成后重算有利值。

## 9. 安全结算层级

第一层直接改变安全目标特征或物理安全目标；第二层完成解决直接安全问题的叶子任务；第三层支撑安全任务的方法或学习能力改善。

方法状态改善默认只能是第三层候选。安全原子任务轮次的正式结果若直接命中安全目标，可判为第一层；否则属于第二层。层级不能证明时只记录潜在贡献或归因缺口。

## 10. 结算动态、因果与写入权

结算是原子任务轮次结算阶段适用时调用的内建被动后处理，不进入普通任务筹办或候选方法选择。合法结算被动因成立后，正式入口切换安全根当前值并生成 D2 结算动作动态；任务轮次结算结果只引用该 owner 正式结果，不复制价值账。

D2 必须保留来源 D0、任务 / 需求证据、结算前值、结算后值、变化量和方向。主动安全结算、分层安全被动维护和通用状态 / 动态 / 因果分别由自身 owner 写入；线程、显示、日志和普通任务结果不得成为第二写入方。

存在反向安全副作用时，必须分别计算正向贡献和反向损失、记录副作用因果并形成净值。

## 11. 验证合同

验证至少覆盖父链归因、实际达成、分段条件、AND / OR 预算、同源去重、安全整数、`0 / 1 / >1` 控制态、来源方法完整集合、版本漂移、副作用收口，以及主动安全结算、分层安全维护、任务调度倍率、自我现实执行授权和普通服务结果不混账。
