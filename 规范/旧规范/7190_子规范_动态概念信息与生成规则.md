## 1. 定位与核心用途

动态概念是对多组相同或类似动态的共同变化结构及关键识别条件的抽象。它回答“这次变化符合哪种模式、与另一模式有什么可判定差别”，不是具体发生记录、动作函数、名称字符串或因果结论。

动态信息由场景组织，动态概念信息按2220以不可变动态类别、完整定义和同类别多父DAG组织。不存在永久动态概念总根；顶层动态概念允许零直接上位，类别根链只是一致截止上的可重建投影。不得增加新根、新概念仓或第二写入owner，也不按场景或具体存在复制一棵权威概念树。

术语固定区分：1150/4202的“场景动态实例根”是每场景实际组织根，实例组织单父；动态概念没有物理总根，只以动态类别和同类概念边形成多父DAG。概念读取场景实例树中的来源，不改变其组织父或发生归属，也不得把场景实例组织根解释为概念根。

核心用途包括动态区分与识别、保存可复用的变化条件、用关键阶段简化过程描述、组织上下位分类和支持自然语言命名。动态二次特征是提取区分条件的重要材料，不是概念的全部内容。概念命中不证明动作已实际执行、任务满足、方法可调用或因果成立。

本专题的固定处理链为：取得已发布动态或首次建点材料；核验来源、声明范围、需求判定条件和形成目的；按主体、角色和正式特征组成槽位递归展开；逐位置执行正式二次比较；形成逐叶方向序列及跨序列时间关系；按目的构造完整原型、条件模式或足够区分定义，或读取既有定义；执行递归匹配及整体统一绑定；完成同义查重、复用或发布；世界树再携带已发布概念身份建立实例及引用。首次形成不得先要求未来父动态身份存在，既有实例识别不得丢弃原动态来源而改取当前采用值。

本版固定区分三种操作：实例满足已有概念、两个完整定义同义、一个概念定义包含另一个概念定义。一个实例同时命中多个概念不证明这些概念同义；命中较宽模式也不能代替本次形成目的所要求的完整定义同义查重。

## 2. 逻辑字段与关联结构

以下是完整概念信息的逻辑组成，不要求把全部关联内嵌为一个对象；对象联系用正式关系承载，必要非拓扑值用合法值或类型化定义材料承载。

| 组成 | 必要性 | 内容及边界 |
| --- | --- | --- |
| 概念节点身份 | 必需 | 独立稳定概念身份，不复用动态、存在、特征或词条身份 |
| 不可变类别及直接上位 | 类别必需；上位零或多项 | 类别固定为动态；顶层允许显式空父组，其余允许多个同类别合法直接上位；直接下位由边反查，不保存总根归属 |
| 主体与参与角色约束 | 必需定义 | 主体及必要子存在/参与角色由存在概念约束；通用优先，必要时收紧概念范围 |
| 关键变化条件集合 | 必需定义 | 可由状态/变化求值的特征概念、二次关系概念条件，或已成立的子动态概念；非根定义不得为空 |
| 组成及时间约束 | 必需定义 | 条件位置、角色绑定、先后/交叠/间隔以及必要重复要求；未限制之处明确为不要求，而非精确零 |
| 覆盖语义与组成槽位闭包 | 必需定义 | 明确区分完整范围型与条件模式型；复合FT按4120正式角色、顺序和基数保存组成范围，不沿派生来源、概念上下位或向量元素伪递归 |
| 必要取值/规则引用 | 条件必需 | 已有概念不能唯一解释输入提取、计算或时间量时补充合法规则和参数；不得由调用点猜公式 |
| 自然语言名称 | 可选关系 | 概念按2210关联词条和别名；名称不参与语义身份，也不参与模式是否满足的判断 |

形成来源、实例支持、上下位形成依据、用途及治理记录分别保存。它们只是概念定义的来源/支持关联和工程可读回材料，使形成过程、真实使用和淘汰有据；它们不独立生成、复制或升级状态、动态、因果认知事实，也不得被匹配、治理或因果应用当作第二认知权威。它们不把支持次数、创建者、具体人、具体场景或绝对时间加入通用定义签名。本轮不新增版本、代次、幂等、批次等业务字段；概念既有发布可靠性、固定定义引用和7140治理仍有效。

场景是来源事实上下文，不是普通动态概念必填的精确场景身份。确实影响识别的环境条件用合法存在/特征/关系概念及角色表达；没有场景概念根，不把场景ID冒充概念。通用优先意味着先用足够宽的可用概念；宽定义不能区分目标模式时才收紧，不机械强制所有约束取根概念。

## 3. 条件位置、叶条件与多来源比较

1. 每个定义内条件都有可区分的位置，位置不是世界实例槽或新增世界身份。引用相同概念的`A₁…A₂`是两个条件位置，不能按概念ID去重为一个A。
2. 匹配时把本次具体主体、子存在、源状态/动态发生绑定到定义角色与位置；实例绑定不回写定义。要求两次发生时不得让同一次发生同时满足两次重复要求。
3. 不同条件可合法引用同一动态来源中、同一E下不同正式FT对应的来源状态，仍须核验各状态的C/E/S完整使用绑定并符合定义；不能把一个中性S解释成多项特征。来源共享不增加发生次数，也不能绕过重复位置约束。
4. 最底层条件必须能由已成立状态、原子变化及其合法比较直接核验。可以引用已经成立的子动态概念，但不先要求待生成的普通动态概念存在；子概念展开、定义引用与上下位均不得自引用或成环。
5. 前后状态条件引用固定特征概念定义，不动态追随准确F后来的名称选择。来源值始终取原状态准确内容，不取目前的存在采用值替代。
6. 二次条件使用7170/7180概念及4150/4151合法求值材料。每项准确结果为具名I64；多个维度分别求值后组合，不把向量、文本或布尔命中冒充单项准确比较值。
7. 持续时间、周期、速度或步频等须明确输入角色、多个来源发生/条件位置或有限窗口，以及正式类型、单位、算法和参数。是否按单步或完整周期计数必须可回查，不仅保存一个无来源数值或自由文本公式。

第6—7项受4150/4151的输入提供者边界约束：来源联合不是任意状态/动态或裸时间计数入口。已有合法输入、取值和规则能完整承接时复用，否则保留明确的缺提供者/不支持，不临时创建F或持久二次实例填缝。实例范围的最早起点至最晚终点只是包络，不能直接当作持续运动、完整周期或实际观察覆盖。

每次识别或形成还须明确需求判定条件：比较主体与角色、关注FT、允许差异域、时间/阶段粒度、必须结果、停止条件及规则来源。需求只选择4180/4182固定算法结果怎样参与本次判断，不改写准确结果、单位、量化或材料证明能力；需求容差、测量不确定性、量化和预算分别处理，预算不足不得降低精度。在本次识别中把差异判为可忽略保持，不删除既有动态，也不修改动态出生条件。

同一FT的多次真实发生保留全部合法比较位置。原生位置来自真实原子动态的前后B；正式来源明确为连续链时只取相邻配对，不按时间排序跨未知缺口补边。首尾、峰值或基准点比较只能作为定义明确要求的补充位置，不能替代原生位置或增加发生次数。

合法B对的零比较可以成为复合父模式中的保持条件，但不建立零动态。零结果只证明这对端点在该规则下相等，不证明整个期间持续稳定；缺值、缺动态、规则不支持或读取失败均不能解释为零。全部比较均为保持且没有至少一项真实变化来源时，不形成普通动态概念实例原型。

## 4. 重复抽取与关键阶段抽象

默认完整原型保留本次声明范围的完整离散方向结构：不自动合并连续同向段，不插值，不启用动态时间规整，不循环平移相位，也不把不同叶序列排序后比较。绝对UTC和未声明的具体时长不进入普通原型身份；端点先后、相等、共享、交叠及由此确定的关系仍参与定义。定义明确要求时长、速度、周期或间隔时，相应正式条件必须保留并参与同义判定。

完整范围型要求声明范围内全部实际位置、槽位占用、衔接和时间关系可一一对应；条件模式型只要求其列出的非空条件，并允许未被禁止的其它阶段存在。该覆盖语义是固定定义的一部分，调用者不能临时切换。既有7191普通模式按条件模式解释，不因本次修订自动升级为完整范围型。

重复抽取与选择性抽象是两个不同操作：

| 输入与目标 | 概念含义 | 不允许的解释 |
| --- | --- | --- |
| `ABABAB → AB` | 提取重复结构；必要周期、间隔和重复条件另由定义保留 | 原实例只发生过一次AB，或删除其它发生 |
| `ABCD → A…C` | A和C及其必要关系是当前识别定义所需条件 | A/C自动紧邻、B/D被禁止或现实中不存在 |
| `ABCD / AECF / AGCH → A…C` | 不同细节可以满足同一关键结构 | 只要包含A/C就必然同类，不再核验主体/时间/其它必要条件 |
| `A₁…A₂` | 同类条件在两个所需发生位置出现 | 用同一次A重复引用来满足两次发生 |

允许任意长度、多特征并行、交叠及不连续模式，不能把所有概念限定为AB。省略阶段不等于省略其对时间约束的影响；若识别依赖间隔、连续性、停止性或相对顺序，就必须把相应约束留在定义内。

若定义要求周期/往复，`AB`重复单元之外还要表达B到下一次A的连接、周期边界及必要重复条件；仅有一次A到B不能命中该周期要求。`ABAB`与`BABA`只有在正式相位等价规则和真实来源均可核验时才可以按不同起点归为同类，不通过重排、反向或删除起止条件默认等价。

动态实例仍保留4211规定的真实成员顺序、发生身份和来源，间隔从正式端点或成员派生。概念不是可回填的原事实压缩文件；抽象掉的条件只能表示“不要求”，不自动表示“不发生”。缺测不证明停止或不存在某阶段，首尾相等也不消除中间变化。识别中可以忽略的阶段，在因果分析中仍可能重要。

## 5. 形成过程

形成请求必须明确目的：`完整原型`、`条件模式`或`复用足够区分定义`。完整来源及来源闭包始终保留；只有完整原型目的强制构造声明范围内逐段完整范围定义。条件模式只形成固定非空必要条件，复用足够区分定义则先查询能够满足本次区分要求的既有固定定义，只有不存在精确适用定义时才形成新定义。三种目的均不得默认压缩、隐式时间规整、改写旧动态、原地修改既有概念定义或以近似相似度代替完整定义查重。

### 5.1 收集与暂配

从一个或多个场景实际动态实例树读取多组动态，按4211完整读回动态内容和来源闭包，并在一致读取范围内互证4202组织路径，保留发生主体、派生时间、观察覆盖及合法来源。目录/索引仅用于定位；不能将内容已发布但组织未完成当作完整场景来源。最小动态和基本动态组先按4210成立，不等待重复或概念命名。

来源状态按4202第3.2节核验具体使用绑定；中性内容共享不等于同一主体、同一发生或多次重复证据。整体与内部成员的描述层级及角色按原来源保留，抽象不把内部成员状态直接改称整体状态。所需绑定已清理或不完整时，返回来源不足，不以当前成员、当前采用或其它场景共享内容补配。

尚无目标动态概念时，依据已成立的存在概念、特征/二次概念及可直接求值的变化条件进行暂配；可比较时间次序、幅度、节律、结构等。暂配只是可撤销的调用期候选，不生成“同类已被证明”事实，也不把相似样本的传递链自动视为整体同类。

### 5.2 提取候选条件

按同类或类似组对齐主体角色、条件位置和可比来源，提取共同结构及候选二次特征。区分稳定共现的条件与有实际区分作用的条件，尽量保留足以识别的简化结构，并保留必要适用范围。

候选至少有完整合法定义和真实来源依据。多组样本用于发现重复结构及检验可靠性；不引入固定三次命中、成熟度或观察天数作为发布门槛。2220允许一次完整来源形成可用定义，但一次来源不足以宣称已经证明跨实例可靠区分能力。

### 5.3 检验与反例

候选要在支持材料中逐项核验条件及角色，并尽可能与相近但不同的动态比较。仅把同一批数据按候选分组，再以该组命中率证明候选可靠，属于循环自证；后续独立发生材料和反例用于修正适用范围、补条件或淘汰。

删去B/D后，如果原来需区分的模式也普遍满足`A…C`，只能说明得到更宽概念；不能继续宣称保留原区分能力。增加或减少条件会改变定义，不原地覆盖旧概念含义。资料不足时保留候选及不足说明，不伪造验证成功。

### 5.4 查重、发布与支持

完整定义先规范化：主体/参与角色、条件位置及绑定、概念引用、组成关系、时间条件、取值规则和必要参数共同参与等价。位置标号本身不创造语义；角色重命名和存储顺序变化需按规范化合同消除，但不能合并重复发生位置或丢失先后条件。

在动态类别的全部当前普通概念中精确查重：本次目的要求的完整规范化定义同义则复用，不以名称相同、暂配相似或支持样本重叠判定同义。活跃/冷却概念可复用；退役命中按7140显式治理，不另造同义身份绕过；不可逆退出后的重新形成沿7140使用新身份。

业务准入通过后，经唯一概念树数据服务在同一owner写集中完整发布普通概念节点、不可变动态类别、规范化定义及显式完整父组。顶层概念允许空父组；非空父组的每条边必须连接同类别概念并有包含依据。形成来源按正式发布合同同时绑定所需依据；实例支持、名称及后续合法增补父边可按各自合同分步完成并独立读回。已有发布和支持不因后续一步失败而被伪称未发生；跨owner或多次调用不宣称全流程原子，不增设第二持久意图账。技术失败、同义缺失和业务候选不成立分别报告。

## 6. 组织、完善与治理

动态概念在不可变动态类别内以定义包含依据形成直接上下位。例如更细的`A-B-C-D`在主体、角色、时间条件均蕴含较宽`A…C`时可以作为其下位；单纯删列表元素不证明包含，收紧或改变时间条件还须核验。

允许从零上位顶层向下细分、由多组模式形成共同上位，以及在已有层级中插入中间概念。保留合法多父关系，概念父图、定义引用和来源形成链均须无环。没有非空合法约束时不创建普通概念，也不得以隐藏根或空定义占位。

完善可补充来源、支持、语言名称和不改义的关系。若改变关键条件、参与角色、适用范围或时间约束，形成新的规范化定义并查重，而不是修改原概念的含义；原实例及原引用继续按其固定定义解释。

用途与治理按7140单独记录。形成、后台积累、结构引用或匹配命中次数本身不自证有用；真实识别、区分等合法消费可按既有用途合同提供材料，支持后续保留、冷却、退役和淘汰。概念退出不删除来源动态，来源材料依法清理也不把已经完整保存的概念定义自动判成不存在。

| 动态概念形成与匹配 | DATA外动态概念应用：暂配、提取、抽象、验证、完整定义查重和实例绑定 | 逐条件匹配，返回匹配/不匹配/证据不足及技术失败的区别 |
| 概念定义与图 | 4240唯一概念树数据服务：保存不可变动态类别、完整定义、显式父组和合法关联 | 独立读回定义、关系、来源/支持；顶层空父合法，不在DATA内裁决识别正确 |
| 名称、用途与治理 | 既有概念/名称owner与7140业务路径 | 名称不代替定义，用途不混入签名，引用保护不绕过 |

动态概念类不是第二动态数据类，也不能复制概念CRUD。它应具备按模式召回候选、展开可求值条件、绑定实例角色、求值及区分、从多组来源形成候选、选择关键条件、规范化复用、组织上下位和提交合法治理材料的应用能力。

匹配结果可以有零个、一个或多个概念；多项成立不按名称或首项强选唯一。单名称采用是后续选择，不删除其它合法支持。展开和枚举均须有限预算，未展开、来源已清理、缺规则和资源失败不等于条件为假或不存在概念。

匹配采用满足、不满足、证据不足三态；入口非法、规则不支持、预算不足、事实截止漂移、发布结果未知和内部不一致属于独立操作状态。父级成功必须存在同一个整体角色、组成槽位、发生位置和端点时间映射，使全部必要叶条件同时成立；不得把各叶局部命中任意拼接，也不得用分数、平均或多数票替代必要条件合取。调用期返回的匹配绑定只用于复核本次判定，零持久身份、零生产事实权力；认知证据仍仅为0050规定的状态、动态和因果。

动态实例的单名称采用按4240独立更新关系，概念自身的语言名称按2210处理；两者都不改写动态主体、端点、组成或来源。名称未绑定不妨碍无名称识别，概念匹配成功也不自动改名。

## 8. 实施边界

动态概念定义与来源/支持必须分开存储：定义自身完整，来源事实按其引用保护合同保存；来源清理后需要原始载荷的审计、首次支持或恢复必须报告来源不足，墓碑不能代替完整动态。定义引用、父边、名称、来源和支持各按自己的生命周期处理，不批量释放。

本规范固定概念模型、逻辑字段、形成顺序与可验证边界。[7191](7191_子规范_动态概念精确结构与算法合同.md)冻结精确结构、发布、恢复和兼容；[7192](7192_子规范_动态概念来源范围与特征递归展开.md)冻结来源与槽位展开；[7193](7193_子规范_动态概念二次比较与方向序列.md)冻结方向及时间结构；[7194](7194_子规范_动态概念递归匹配与整体判定.md)冻结三态匹配；[7195](7195_子规范_动态概念形成查重与分类.md)冻结原型、同义和包含；[7196](7196_子规范_动态概念验收测试与完成声明.md)冻结目标验收合同。不得以字符串表达式或不完整DTO填补缺口。4240负责唯一概念结构承接，4151/4241/4242负责二次计算与RC合同，4204负责其明确范围内的场景组织提供者。各合同支持范围及未实现来源必须逐项遵守；精确合同存在不证明提供者、完整观察来源、生产接线或识别可靠性已经成立。

0300 C038继续限制持久二次准确实例、二次当前值以及由其补造状态或动态；动态概念定稿本身不授权相关实例写入或代码实施。
