## 1. 定位

本规范规定建立一个世界存在时，如何以本次已经取得的完整信息形成或复用其存在概念，再建立实例及其概念使用引用。

存在概念的定义只由两组信息组成：

```text
自身特征值域组
+ 已知子存在概念组
```

实例组织关系只承担读出这两组信息的物理路径。关系类型、参与角色、关系端点、场景位置、实例编码、名称、事实代次、幂等键、来源账、缓存、显示、日志、绝对时间和当次证据均不是第三组概念签名，禁止以它们补充、区分或复用存在概念。

本规范的首次路径与7110的主动归纳路径分离。概念树类不建立世界存在；存在类不生成概念；L3世界树只按顺序调用L2并逐项读回，不将多个L2写入伪装为全链原子事务。

## 2. 建点信息、递归前提与概念定义

普通世界存在的建点材料必须给出本次截止已经知道、且允许参与概念定义的全部自身特征和已知子存在。未知不等于明确缺失，不得补零、补空项或以默认通用概念代替。

每一自身特征必须能读回正式特征类型和实际特征值；概念候选中的同类型项保存的是特征值域。每一已知子存在都不是裸节点：在比较父存在前，必须先以该子存在自己的已知特征和已知子存在递归完成本规范的概念形成或复用，并取得已发布子存在概念身份。递归读取或形成失败时，父存在不得跳过该子存在继续匹配或新建。

概念定义中的两组均按对应稳定身份规范化、去重和确定排序：

- 自身特征组以正式特征类型为键；同一类型缺项、重复项或无法读回实际值属于逻辑错误。
- 子存在概念组保存已知子存在所关联的概念身份；它表达已知子存在的概念集合，不包含成员角色、关系类型或关系端点。若业务将来需要让数量、角色或关系成为概念语义，必须先另行修订正式规范，不能在本路径临时写入。

空组只在建点材料明确说明其为空时成立；普通存在的漏填、读取失败或递归未完成不得转换为空定义。

## 3. 完整匹配与唯一最具体选择

建立概念前，应用必须比较所有当前、类别为存在且定义可完整读回的候选概念。索引可用于缩小候选集，但每个保留候选仍必须作完整核验；索引首项、名称相同、局部特征相同或相似度均不得作为命中。

候选概念匹配拟建立存在，当且仅当：

1. 双方自身特征类型集合完全相同；
2. 对每个特征类型，实例实际值与候选值域精确相等，或被该候选的区间/枚举值域包含；比较使用该特征类型已经登记的比较合同，不能比较节点号、显示或摘要；
3. 双方已知子存在概念组完全相同；每一子存在概念身份都必须已发布并完整读回。

候选A比候选B更具体，当且仅当两者的特征类型集合相同，A的每个特征值域均被B对应值域包含，且至少一项严格更小。子存在概念组不同的候选不可互相比较为更具体。

在全部匹配候选中：

```text
零个                 -> 新建一个由本次两组完整信息定义的具体存在概念
唯一最具体           -> 复用该概念
两个以上并列最具体   -> 逻辑错误：零关联、零新建，并在最终责任边界记录异常与提示
```

“并列最具体”不是可随机选择、按编号选择或新建第三个概念的条件；它表示已经发布的概念定义或比较/归类逻辑发生低级不一致。读取不完整、候选退役、预算不足、发布未知或资源失败也不是“零候选”。

## 4. 先概念后实例

L3世界树的顺序固定为：

```text
取得显式世界挂靠和全部已知建点信息
-> 对每个已知子存在递归形成或复用其概念
-> 比较所有存在概念并选择复用或新建
-> 读回已发布概念身份与完整定义
-> 调用存在类建立E及显式初始挂靠
-> 调用相应L2写入真实特征和父子存在组织
-> 建立 E -> EC 概念使用引用
-> 逐项读回 E、真实事实、组织和概念使用引用
```

概念先发布而后续实例建立失败时，保留已发布概念；重试必须以原两组信息重新完整比较。概念发布未知或读回失败时不得建立E；E或任一后续事实发布未知/读回失败时按原请求收敛，不得换键制造新身份。

每个世界存在必须拥有一个 `E -> EC` 概念使用引用。该引用是实例与其概念的唯一正式关联，不等于父子实例边、概念上下位边或世界支持边；实例成员边仅记录 `父E -> 子E`。

## 5. 分层、归纳与概念根链投影

首次形成只解决当前实例应关联哪个最具体概念，不自动建立上位概念、上下位边或其它组合。7110的业务/认知应用在有明确归纳需要时，才从多个已发布概念的共同特征和值域形成上位概念。

没有直接上位的存在概念构成“存在概念根链”投影；它是概念图的零上位列表，不是持久概念总根、普通概念父节点或世界树组织节点。多个同层概念若没有可证明的共同特征和值域，保持并列是正常结果。

## 6. 不属于本路径的事项

本路径不得隐式：

1. 扫描新增实例之外的世界存在以寻找共同概念；
2. 由名称、词性、显示分类、索引命中或关系角色生成概念；
3. 把父子实例组织边改写为概念上下位边，或反向由概念边补造实例；
4. 以未发布的待建实例、未来子存在或缓存作为概念定义端点；
5. 以概念匹配代替存在身份识别；匹配只选择概念，不合并世界实例。

## 7. 验证语义

验证至少覆盖：

1. 全部已知自身特征和递归已知子存在均参与定义，未知不被补为缺失；
2. 特征类型集合不完全相同、值不相等/不被包含、子存在概念组不同，均不命中；
3. 唯一最具体匹配复用；零匹配新建；并列最具体产生逻辑错误且零写入；
4. 物理关系只用于读出特征和子存在，不进入签名；
5. 先概念后实例、逐项L2读回和失败阶段如实分账；
6. E到EC引用与父子E组织、概念上下位和世界支持关系不混用；
7. 顶层概念根链仅为投影，不产生持久总根。

## 8. 退役口径

下列口径退出新生产：

- 将“自身特征＋子存在组成角色＋关系约束”作为三组存在概念定义；
- D/O/R或任何等价的组成角色、关系类型、参与角色增量定义提供者；
- 以关系端点、实例编号、名称或场景位置作为概念签名；
- 局部精确查询后直接复用、任意选择并列候选，或把读取/预算失败当作不存在；
- 实例先建立、后补首次概念；以及建立实例后自动扫描全部概念组合。

旧代码、持久格式、历史计划和记录只可用于审计与迁移；不得恢复为新生产能力。
