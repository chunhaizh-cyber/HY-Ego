## 1. 权威边界

本规范是动态实例和动态概念图的现行机器合同。

本文严格区分：

```text
动态实例：实际发生的一段状态变化事实，或一次已经进入执行的动作事实
动态概念：对一个动态实例的概念投影，或多个动态概念的共同抽象
```

速度、加速度、周期、动作名称和循环意义不是先天变化语义。它们只能由后续思维能力基于已有动态和二次特征逐步形成。动作动态只记录某次具名执行已经发生、来源、目标和时间，不预设高级动作概念。

### 1.1 替代裁决

1. 原子动态直接引用两个状态节点；旧C/E/S状态使用绑定退出。
2. 动态类建立实例动态概念，场景类随后挂接动态；不再强制世界树先取得动态概念。
3. 动态实例允许保存由其成员状态计算得到的时间差、跨特征比较类型和结果值域。这些内容是动态内部字段，不取得独立二次特征实例身份；C038据此收口。
4. 动态生命周期采用引用计数和子成员关系，不再采用TTL、数量上限或墓碑。

规范要求原子动态的前后准确值必须实际变化；当前实现若只核验状态身份和时间，属于待修实现差距，不能反向放宽本条。

## 2. 动态种类

当前动态分三类：

```cpp
enum class 新动态种类 {
    原子 = 1,
    动作 = 2,
    复合 = 3
};
```

原子动态由恰好两个状态组成，描述一个存在的一种特征从前状态到后状态的最小变化。

动作动态描述一次已经进入执行的本能方法动作。它保存执行主体、动作定义、唯一动作来源、目标存在、可选目标特征和动作时间，不复制结果变化；零到多个结果动态通过强类型外部关系关联。

复合动态由至少两个原子动态作为外部子成员组成，描述一个主题存在及其子存在在同一时间段内跨多个特征类型的复杂变化。

不建立独立的“连续链”动态种类。场景动态列表只组织实例动态引用；连续性和时间顺序必须从原子成员端点及状态强时间计算，不能由列表位置推定。

## 3. 动态实例信息

```cpp
struct 新动态信息 {
    稳定编码 节点;
    新动态种类 种类;
    稳定编码 主题存在节点;
    std::vector<稳定编码> 状态节点组;
    std::vector<稳定编码> 成员动态节点组;
    std::vector<新动态跨特征时间项> 跨特征时间组;
    std::optional<稳定编码> 动作定义节点;
    std::optional<稳定编码> 动作来源节点;
    std::optional<稳定编码> 动作目标存在节点;
    std::optional<稳定编码> 动作目标特征节点;
    std::optional<新状态强时间> 动作时间;
    std::vector<新动作结果关联> 动作结果组;
    std::optional<稳定编码> 动态概念节点;
    std::int64_t 被引用次数;
};
```

字段规则：

- 原子动态直接保存两个状态引用，没有成员动态。
- 动作动态不保存状态、复合成员、跨特征时间或动态概念；动作来源在当前事实中唯一，相同来源只能精确重放同一动作。
- 动作结果关系只有`导致变化`和`观察取得`：前者要求动作时间落在结果变化端点之间，后者要求观察动作发生于被取得结果形成之后；两种关联都不自动成为确定因果。
- 复合动态通过外部父子关系保存原子成员；状态组由成员状态汇总、去重并按强时间读回。
- 成员集合没有一个跨全部特征的统一先后顺序。
- 复合动态保存已计算的跨特征状态时间二次特征。
- 每个原子/复合动态必须引用一个动态概念；动作动态不建立动态概念，也不进入动态概念识别或聚合。
- 被引用次数用于场景列表和上层复合动态等生命周期控制。

### 3.1 动作动态建立与结果关联

```cpp
新动态建立结果 建立动作动态(const 新动作动态建立请求&) noexcept;
新动态操作状态 关联动作结果(
    稳定编码 动作动态节点,
    稳定编码 结果动态节点,
    新动作结果关系类型 关系类型) noexcept;
```

动作必须先于真实改变或观察建立并挂入场景。结果发布后只能由持有本次动作身份的调用方显式传入动作节点建立关系；动态类不得扫描场景列表寻找“最近动作”。没有动作节点时结果动态照常成立但不关联。动作已经记录、结果改变已经成立而关联失败时保留双方事实并返回部分完成，禁止自动重复真实动作。

## 4. 原子动态

公开入口：

```cpp
新动态建立结果 建立原子动态(
    稳定编码 主题存在节点,
    稳定编码 前状态节点,
    稳定编码 后状态节点) noexcept;
```

建立条件：

1. 两个状态不同且均可完整读回。
2. 两个状态的被描述存在都等于主题存在。
3. 两个状态保存的特征概念身份相同。
4. 两个状态都使用实例绝对UTC时间。
5. 后状态时间严格大于前状态时间。

建立流程：

```text
核验两个状态
-> 建立动态节点和两个状态引用项
-> 分别增加状态引用次数
-> 建立新的实例动态概念
-> 写入动态概念字段
-> 完整读回
```

兼容入口`建立动态(主题, 状态组)`仍只接受恰好两个状态；它不再允许直接建立任意多状态动态。

## 5. 原子动态实例概念

每个原子动态立即建立一个新的实例动态概念，不按相同内容复用。实例概念将前后准确值定位到对应的特征概念值域，并保存：

- 特征概念身份；
- 前值域概念；
- 后值域概念；
- 准确相对时长。

当前原子建立链没有调用独立的动态特征抽取类，也没有把前后差异、相似度或方向作为`动态概念特征项`写入实例概念。前后值域和时长已经形成概念材料，但“原子动态自动抽取三类动态特征”尚不是当前实现能力。

## 6. 复合动态

```cpp
新动态建立结果 建立复合动态(
    稳定编码 主题存在节点,
    const std::vector<稳定编码>& 成员动态组) noexcept;
```

复合动态建立需要完整构造器配置存在服务和二次特征服务；只配置状态服务和动态概念服务的短构造器调用该入口时返回`依赖未配置`。

建立条件：

1. 至少两个不同成员。
2. 所有成员都是可完整读回的原子动态。
3. 主题存在可读回。
4. 每个成员主题是主题存在本身或其任意层子存在。
5. 每个原子成员自身满足同存在、同特征和时间递增条件。
6. 至少包含两个不同特征类型。

### 6.1 串行和并行

按“成员主题存在＋特征概念身份”形成串行通道。同一通道内的原子动态按前状态时间排序，相邻原子必须满足：

```text
前一原子的后状态节点 == 后一原子的前状态节点
```

不同特征类型通道之间是并行关系，不要求统一端点，也不强行形成一个交错状态序列。复合动态成员采用外部父子关系，当前关系角色为`新复合动态成员关系角色`。

### 6.2 跨特征时间二次特征

复合动态把全部唯一状态按强时间分组。当前算法比较：

- 同一时刻组中不同特征类型的状态对；
- 相邻两个时刻组之间不同特征类型的状态对。

每个比较结果保存前后状态、前后特征概念、二次特征类型概念、结果值域概念和准确时间差纳秒。当前代码不会比较所有任意远距离时刻组，也不会由时间差直接命名速度、周期或因果关系。

### 6.3 发布流程

```text
核验成员和主题存在树
-> 核验各同特征串行通道端点连续
-> 计算跨特征时间二次特征
-> 建立复合动态节点
-> 增加成员动态引用并建立成员外部关系
-> 建立复合实例动态概念
-> 写入动态概念字段
-> 完整读回
```

复合实例概念复制成员概念已经发布的状态变化材料，不永久依赖成员实例概念节点；这样成员后续采用聚合概念时，不会使复合概念形成悬空引用。

## 7. 动态概念信息

动态概念分为：

```text
实例动态概念：与一个具体动态实例一一对应
聚合动态概念：由至少两个来源动态概念抽象出的共享概念
```

动态概念节点保存：

| 信息 | 实例概念 | 聚合概念 |
| --- | --- | --- |
| 对应动态节点 | 恰一 | 无 |
| 状态变化槽位 | 一到多 | 一到多 |
| 前后值域概念 | 每槽位恰一 | 每槽位恰一 |
| 准确相对时间 | 实例保留 | 来源不一致时可不限定 |
| 动态特征槽位 | 零到多 | 零到多 |
| 准确二次特征结果 | 实例可保留 | 不保留 |
| 二次特征结果值域 | 每特征项恰一 | 每特征项恰一 |
| 上下位概念 | 零到多 | 零到多 |

动态概念保存特征值域引用，不复制特征概念的材料和值域内容。

## 8. 聚合动态概念

显式入口：

```cpp
动态概念聚合结果 聚合共同动态概念(
    const std::vector<稳定编码>& 来源概念组) noexcept;
```

规则如下：

1. 至少需要两个不同来源概念。
2. 各来源状态变化槽位数量、顺序和特征概念身份必须一致。
3. 每个前值域和后值域取得共同上位特征概念。
4. 准确相对时间一致时保留；不一致时上位概念不限定准确时长。
5. 动态特征槽位数量、位置和二次特征类型必须一致。
6. 准确二次特征结果的总体最小值至最大值形成或复用上位结果值域概念。
7. 没有合法共同结构时返回`无共同点`，不强行建立概念。
8. 相同聚合结构已经存在时复用，否则新建。
9. 聚合概念作为上位，来源概念作为下位，不得形成环。

聚合是显式按需要触发的归纳归类，不在每次实例动态建立后自动全图扫描。新实例概念建立成功不等于已经完成动态分层。

## 9. 动态概念识别和包含

当前可用的结构判定入口：

```cpp
动态概念包含结果 判断动态概念包含(
    稳定编码 上位概念节点,
    稳定编码 下位概念节点) const noexcept;
```

判断要求状态变化和动态特征槽位完整对齐，上位前后值域及二次特征结果值域逐项包含下位。由此可以表达：

```text
特征概念身份一致
-> 是否发生变化由前后值域关系体现
-> 变化方向和幅度由前后值域及二次特征结果逐步细化
-> 选择能够包含实例的最具体概念
```

但当前代码没有一个“输入新动态后自动遍历全部概念并返回唯一最具体匹配”的公开入口，也没有独立实现噪声过滤、代表性状态选择或不同长度序列相似度。

## 10. 采用聚合概念

只有上层已经确认聚合概念稳定且该聚合概念确实是当前实例概念的合法上位时，才能调用：

```cpp
新动态操作状态 采用聚合动态概念(
    稳定编码 动态节点,
    稳定编码 聚合动态概念节点) noexcept;
```

成功后，动态实例改为引用共享聚合概念，并删除原实例动态概念。动态实例本身、状态和成员关系不变。

该操作不是聚合算法的自动后处理；上层必须显式作出稳定采用决定。

## 11. 场景组织和查询

一个动态实例只能挂入一个发生场景。原子/复合动态的主题和全部状态必须与该场景一致；动作动态按执行主体、目标存在和动作时间校验，不要求状态端点。场景列表只保存引用并增加动态引用次数。

当前公开查询包括：

```cpp
std::optional<新动态信息> 获取动态(...) const noexcept;
bool 是动态节点(...) const noexcept;
std::vector<稳定编码> 按主题查询动态(...) const noexcept;
std::vector<稳定编码> 按状态查询动态(...) const noexcept;
std::vector<稳定编码> 按概念查询动态(...) const noexcept;
std::optional<动态概念信息> 获取动态概念(...) const noexcept;
std::vector<稳定编码> 查询全部动态概念() const noexcept;
std::vector<稳定编码> 查询上位动态概念(...) const noexcept;
std::vector<稳定编码> 查询下位动态概念(...) const noexcept;
```

场景动态列表和以上查询结果均不能替代时间轴对齐算法。

## 12. 生命周期和删除

动态引用次数由场景列表和上层复合动态等引用方成对维护。新建动态引用次数为零，但新建时的零不触发删除；只有一次正式减少使计数从正数变为零时才自动尝试删除。

删除动态必须满足：

1. 动态引用次数为零。
2. 已解除场景列表或上层复合动态引用。
3. 原子/复合动态的动态概念字段和种类结构完整；动作动态的动作字段及结果关系结构完整且没有动态概念字段。

删除原子动态时解除两个状态引用并减少状态引用次数，删除自己的实例概念或解除聚合概念引用。删除复合动态时解除成员关系、减少成员组成引用、清理跨特征时间项并处理自身概念。

删除动作动态时解除全部动作结果关系并减少结果动态的组成引用，再清理动作专有字段。结果动态的生命周期仍由其场景和其它正式引用共同决定，不能因动作退出直接取得结果删除所有权。

已经采用共享聚合概念的动态删除时，不得删除仍被其它动态使用的聚合概念。当前聚合动态概念没有完整的引用计数和自动淘汰机制。

## 13. 一致性不变量

任一成功读回的动态必须满足：

1. 节点类型、种类、主题存在和引用次数字段结构完整；原子/复合有动态概念，动作有完整动作字段且无动态概念。
2. 原子动态恰有两个不同状态；同主题、同特征概念、时间严格递增。
3. 复合动态至少有两个不同原子成员和两个不同特征类型。
4. 同主题同特征串行通道端点连续。
5. 跨特征成员并行，不伪造统一全局顺序。
6. 每个状态和成员动态的引用次数与正式引用相符。
7. 实例概念准确指回动态；聚合概念不得伪装成实例专属概念。
8. 场景列表只是发生位置引用，不是动态时间链。
9. 动作结果只能由显式动作身份强类型关联；场景位置和时间接近不能替代来源身份。

## 14. 非成功和发布边界

动态操作区分状态不足/不存在/重复、主题不一致、特征不一致、时间不合法、成员不足、不是原子动态、动作信息不合法、动作来源冲突、动作结果不匹配、动作关系冲突、端点不连续、跨特征不足、二次特征失败、依赖未配置、实例概念失败、概念不合法、形成环、引用阻止、结构不一致和资源失败。

基础数据集没有组合事务。建立失败时代码尽力逆序撤销状态/成员引用、字段、关系、实例概念和中间项；不能据此宣称跨进程原子发布或发布未知恢复已经实现。

## 15. 非权威实现差距

当前已有`新_动态特征抽取类.h/.cpp`并实现基础动态特征抽取，但下列高级口径尚未形成完整代码闭环：

- 原子动态自动抽取前后值差异或相似度、时间间隔和带时间二次特征；
- 按全部概念自动选择最具体匹配动态概念；
- 新概念形成后自动尝试更宽方向或幅度区间抽象；
- 从重复状态中识别首尾、方向改变、代表性状态和循环；
- 噪声过滤、不同长度动态的时间轴对齐、序列匹配和聚合比较；
- 从原子动态自动发现并组装业务有意义的复合动态；
- 速度、加速度、周期和动作等高级概念形成；
- 聚合动态概念引用计数、淘汰和图修剪；
- 持久化、恢复、生产装配和完整集成验收。

当前复合动态已经实现跨特征时间二次特征，但这不等于以上高级识别能力已经闭合。

## 16. 验证边界

后续验证至少覆盖：

- 原子动态双状态、同主题、同特征和严格时间顺序；
- 每个动态建立独立实例概念；
- 复合动态只接受原子成员，主题允许本存在及子存在；
- 同特征串行端点连续、跨特征并行；
- 同时刻组和相邻时刻组的跨特征时间比较；
- 短构造器明确返回依赖未配置；
- 聚合概念共同槽位、时间放宽、值域包含和无共同点；
- 采用聚合概念后删除原实例概念；
- 场景和复合成员引用成对维护；
- 动态删除对状态、成员和概念生命周期的正确处理。
- 动作先于结果、同源精确重放、异义来源拒绝、改变/观察时间规则和结果关系生命周期；
- 无动作结果正常成立且不关联，多个相近动作不得按“最近”误关联。
