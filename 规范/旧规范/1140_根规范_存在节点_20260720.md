## 1. 权威边界

本规范是存在实例和存在概念图的现行机器合同。

本文严格区分：

```text
存在实例：世界中的实际对象节点
存在概念：对一个存在完整特征投影或多个存在共同特征的概念节点
```

存在实例与存在概念不得混同。节点稳定编码是各自节点的物理身份；存在实例通过唯一字段引用自己的专属存在概念。

### 1.1 替代裁决

1. 普通存在先在明确场景内建立实例特征，再生成其专属存在概念；旧“概念前置后才允许建立存在”的强制顺序退出。
2. 场景成员归属和父存在组成是两种不同关系，可以同时存在；它们不再合并为唯一结构父。
3. 实例特征内部维护当前值与历史聚合；旧“已知特征/当前采用”双结构不再作为存在必需字段。

上述裁决只替代机器语义，不自动证明旧数据迁移、生产切换或应用装配已经完成。

## 2. 对象定位和场景归属

普通存在必须在建立时明确直接所属场景。公开建立入口由场景类提供：

```cpp
新场景成员建立结果 建立成员存在(
    稳定编码 场景节点,
    const 新存在建立请求& 请求,
    const 新状态强时间& 初始状态时间) noexcept;
```

场景类先建立普通节点并写入场景成员字段，再调用存在类的私有初始化入口。存在类不公开“脱离场景建立普通存在”的入口。

普通存在只能直接属于一个场景，并应归入当前能够明确的最小场景。场景迁移只改变场景成员字段，不改变存在稳定编码。

场景节点本身也具有存在身份，但场景由场景类建立；世界树根场景和普通场景允许以空特征初始化。普通成员存在当前必须至少带一项初始特征。

## 3. 存在实例信息

一个可完整读回的存在实例包含：

| 信息 | 基数 | 含义 |
| --- | --- | --- |
| 节点 | 恰一 | 存在实例稳定编码。 |
| 直接所属场景 | 普通存在恰一 | 由场景成员内部字段反向确定；不保存在存在信息DTO内。 |
| 父存在 | 至多一 | 存在组成关系中的直接父存在。 |
| 专属存在概念 | 恰一 | 只属于该实际存在的概念节点。 |
| 实例特征 | 零到多 | 由存在内部字段持有的实例特征节点。 |
| 子存在 | 零到多 | 通过外部父子关系组织的直接子存在。 |

特征是存在内部字段；子存在是独立存在节点之间的外部关系。不得把子存在复制成存在内部值，也不得用实例特征字段表达存在组成关系。

## 4. 建立存在

普通存在建立请求包含：

```cpp
struct 新存在建立请求 {
    std::optional<稳定编码> 父存在节点;
    std::vector<新存在初始特征> 初始特征组;
};
```

建立流程为：

```text
核验目标场景
-> 可选父存在必须直接属于同一场景
-> 建立普通节点并挂入场景成员字段
-> 核验初始特征概念、材料和值
-> 建立每个实例特征并写入初始值
-> 为每个初始特征建立初始状态
-> 用完整具体特征概念组建立新的专属存在概念
-> 将专属概念写入存在字段
-> 完整读回
-> 将初始状态挂入发生场景
```

初始特征按特征类型根唯一；同一存在不得在初始请求中重复同一特征类型。每个实际存在总是建立新的专属存在概念，即使它与已有存在具有完全相同的特征，也不复用其它存在的专属概念。

场景节点允许建立空专属存在概念。普通存在当前不允许以空特征建立。空专属概念只作为对应存在的概念承载节点，不参与匹配、共同点抽象或空概念复用。

## 5. 特征写入和状态生成

### 5.1 添加新特征类型

```cpp
新存在特征添加结果 添加特征(
    稳定编码 存在节点,
    稳定编码 特征概念节点,
    const 新特征准确值& 初始值,
    const 新状态强时间& 强时间) noexcept;
```

流程为：

```text
核验存在和实例绝对UTC时间
-> 以给定特征概念建立实例特征
-> 写入存在的实例特征字段
-> 写入初始准确值
-> 用全部实例特征当前所属概念更新专属存在概念
-> 建立初始状态
```

若同一特征类型已经存在，则专属概念更新拒绝重复类型，添加操作回滚本次新特征。

### 5.2 更新已有特征值

```cpp
新存在特征值更新结果 更新特征值(
    稳定编码 存在节点,
    稳定编码 特征节点,
    const 新特征准确值& 新值,
    const 新状态强时间& 强时间) noexcept;
```

只有该特征确实由目标存在持有时才允许更新。存在类调用特征类完成当前值、历史命中、聚合和值域概念同步；只有实例特征的当前值真正改变时才建立新状态。同值再次命中可以更新特征内部统计，但不生成重复状态。

随后，存在类重新读取该存在全部实例特征的当前所属概念，并同步同一个专属存在概念节点的完整特征投影。特征事实已经成立而状态或专属概念同步失败时，不回滚已成立的特征事实，必须返回部分完成状态。

`添加特征`和`更新特征值`当前是存在类公开入口，它们只建立状态，不知道发生场景，也不自动把状态挂入场景。正常场景业务必须通过场景类对应入口调用，或由调用方在同一编排中把返回的状态准确挂入所属场景；否则会留下引用次数为零的未组织状态。

## 6. 子存在关系

子存在采用外部父子关系，当前关系角色为`2`。规则如下：

1. 一个存在至多有一个直接父存在。
2. 一个父存在可以有多个直接子存在。
3. 不允许自指或形成存在组成环。
4. 添加已有的同一父子关系返回`无变化`。
5. 移除关系只解除组成关系，不删除父存在或子存在节点。
6. 当前普通建立入口要求可选父存在与新存在直接属于同一场景。

存在组成树只描述对象组成，不替代场景归属、概念上下位或实例特征持有关系。

## 7. 专属存在概念

每个实际存在恰有一个专属存在概念。专属概念信息为：

| 信息 | 基数 | 含义 |
| --- | --- | --- |
| 概念节点 | 恰一 | 专属存在概念稳定编码。 |
| 概念种类 | 恰一 | `专属`。 |
| 对应存在节点 | 恰一 | 准确指回唯一实际存在。 |
| 特征组 | 零到多 | 每项由特征类型根和当前具体特征概念组成。 |
| 上位概念 | 零到多 | 由显式抽象建立的共同上位概念。 |

专属概念保存实例当前完整特征概念投影，不复制实例准确值、历史值、单位、比较规则或聚合规则。特征概念自身承载值域和规则。

当实例特征所属的具体特征概念变化时，专属存在概念允许原地更新其特征投影。更新不会自动触发存在概念抽象；已经不再能包含该专属概念的上位关系会被解除。

## 8. 抽象存在概念和概念图

存在概念组织是图，不是强制单继承树。不同特征组合可以形成不同抽象概念，同一个专属概念可以同时属于多个合法上位概念。

显式抽象入口：

```cpp
存在概念抽象结果 抽象共同存在概念(
    const std::vector<稳定编码>& 来源概念组) noexcept;
```

规则如下：

1. 至少需要两个不同来源概念；单个存在不能单独证明共同抽象。
2. 按特征类型根对齐来源概念的特征项。
3. 对每个共同特征类型，取得各具体特征概念的共同上位特征概念。
4. 所有来源共同具有的最大特征集合形成抽象概念定义。
5. 没有共同特征时正常返回`无共同点`，不建立空抽象概念。
6. 已有完全相同特征组合的抽象概念时复用，否则新建。
7. 抽象概念作为上位，来源概念作为下位；必须满足包含关系且不得形成环。

层级越高通常包含的特征类型越少或值域越宽，但层级由实际包含关系决定，不由固定层数、名称或节点编号决定。

## 9. 查询能力

当前公开查询包括：

```cpp
std::optional<新存在信息> 获取存在(...) const noexcept;
bool 是存在节点(...) const noexcept;
std::vector<稳定编码> 查询全部特征(...) const noexcept;
std::optional<稳定编码> 查询专属存在概念(...) const noexcept;
std::vector<稳定编码> 查询直接子存在(...) const noexcept;
std::optional<存在概念信息> 获取存在概念(...) const noexcept;
std::vector<稳定编码> 查询上位存在概念(...) const noexcept;
std::vector<稳定编码> 查询下位存在概念(...) const noexcept;
```

当前不存在按名称、任意特征组合或全局相似度直接搜索实际存在的公开索引。存在概念抽象也不是自动全图扫描。

## 10. 生命周期和删除

普通存在删除由场景类编排。删除前必须满足：

1. 不是场景节点。
2. 没有直接子存在。
3. 没有状态引用。
4. 没有动态主题引用。
5. 没有任何场景边界引用。
6. 能够解除唯一场景成员字段。

存在类随后清理父存在关系、实例特征、专属概念字段和存在类型字段，最后由场景类删除节点。

场景节点的存在内容随空场景删除一并清理。根场景不可通过普通删除入口删除。

当前没有独立的公开“删除专属存在概念”入口；专属概念只随未发布建立回滚或存在清理处理。抽象存在概念尚无公开淘汰和删除能力。

## 11. 一致性不变量

任一成功读回的普通存在必须满足：

1. 节点存在且具有存在节点类型字段。
2. 恰有一个专属存在概念字段，且概念准确指回该存在。
3. 普通存在恰有一个直接所属场景；场景节点不使用普通成员字段表达自身归属。
4. 父存在关系至多一项，且目标不存在组成环。
5. 每个实例特征节点有效、顶层持有关系正确，同一特征类型不重复。
6. 专属概念特征组等于实例特征当前所属概念的完整投影。
7. 子存在关系、场景关系、概念关系和字段持有关系不得互相冒充。

## 12. 非成功和发布边界

存在操作区分入口拒绝、存在不存在、父存在不合法、特征不足、特征概念不合法、特征类型重复、概念失败、形成环、结构不一致、资源失败和外部引用阻止删除。

基础数据集没有组合事务。建立链在发布前尽力逆序回滚；但特征当前值已经发布后，后续状态生成或专属概念同步失败不撤销真实特征值，分别返回：

```text
特征已更新但状态未完成
特征已更新但专属概念未完成
```

调用方必须保留原存在和特征身份并继续补偿，不能把部分完成解释为零写入失败，也不能重新建立另一个存在来掩盖不一致。

## 13. 非权威实现差距

以下口径已讨论，但当前代码尚未完整实现：

- 按存在名称或自然语言关系检索存在；
- 新建存在时自动用全部已知特征、子存在及关系信息匹配可复用的抽象概念；
- 自动触发多存在共同点归纳、概念图修剪和概念淘汰；
- 将后续补充的子存在信息纳入专属概念完整投影；
- 从存在类公开特征写入口强制闭合发生场景状态挂接；
- 持久化、跨启动身份恢复和生产装配；
- 大规模存在/概念索引和性能证明。

当前代码为进程内全局基础数据集上的实现。本文不证明根工程编译、运行恢复、普通应用接线或集成验收完成。

## 14. 验证边界

本草案的后续验证至少应覆盖：

- 普通存在必须在合法场景中建立；
- 场景节点可空特征、普通存在拒绝空特征；
- 初始特征、专属概念和初始状态一致读回；
- 同类型特征重复拒绝；
- 当前值改变生成状态，同值命中不生成状态；
- 子存在单父、环拒绝和关系移除；
- 两个以上概念的共同特征抽象、复用、无共同点和多上位图；
- 状态、动态、边界和子存在引用对删除的阻止；
- 部分完成状态不回滚已经成立的特征事实。
