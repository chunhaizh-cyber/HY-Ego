# 4115 子规范 实例特征容器与区间材料

编号：4115
日期：20260920
版本：v0.9
状态：正式子规范

直接上级：1130、1140、2100。直接依赖：4015、4030、4040、4050、4110、4120、7150、7160。

## 1. 定位

实例特征容器 `IF` 是同一存在 `E` 对同一正式特征类型 `FT` 的唯一持久结构入口。它不是准确特征 `F`、特征值、概念或存在当前采用关系；一个 `IF(E,FT)` 可组织多个准确 `F` 和一组持久区间材料 `R`。同一 `(E,FT)` 至多一个当前 IF；不存在当前采用不妨碍 IF、F 或 R 存在。R 的区间材料是 FT 解释的实例归组摘要，不是2100实际值、准确 F 或特征概念允许域；它可按正式 FT 规则给出调用期代表值，但代表值不是实际观察的准确值。

F 仍按1130/4110具有一个固定准确值、明确 C/P 位置及一个已发布单值特征概念 `FCv` 的使用引用。IF 不是 F 的组织父 P；F 的 C/P、holder、已知引用和位置不因 IF 新增而改变。

## 2. 结构、写入者与读回

IF、R集合、R集合版本和R项均是存在 owner 按需建立的独立普通节点；不得预建空 IF/R 占位。存在 owner 唯一写入 IF、IF 到 F 成员、IF 到 R集合、R集合到当前版本、版本到 R项及 R项到形成 F 成员；它同时仍唯一写入 E 已知 F 与 `E+FT -> 当前采用F`。概念 owner 只写 FC、F 到 FC 使用和概念上下位；概念应用只组合已发布 IF/R 与概念事实，不取得第三个写 owner，也不保存汇聚回执。不得建立第二当前值、第二已知 F 列表或第二概念仓。

存在类初始化以固定初始化幂等身份登记并读回六个稳定关系类型，顺序固定为：`E→IF`、`IF→F成员`、`IF→R集合`、`R集合→版本`、`版本→R项`、`R项→F成员`；并登记一个表示为 `U64组` 的 `R项区间材料属性类型`。结果以值式`实例特征结构交付 v2`注入存在类构造；它不建立任何 IF/R 实例。首次 v2 初始化在尚无 v1 结构时共同建立七个节点；已存在已发布 v1 六关系结构时，v2 以独立固定幂等身份读回并核验原六项，只建立第七个属性类型节点，再交付七项 v2 结构。两条路径均须精确重放；异义键、类型数量/顺序/表示、退出、跨 L1/owner 或交付不完整必须分账。构造器拒绝非 v2、缺失、重复、相等、退出或未绑定于同一 L1/存在 owner 的交付。

每个 IF 在当前范围内至少有一个 F成员并从该成员读取唯一 FT；全部成员的正式 FT 必须相同。每个 IF 当前恰有一个 R集合，R集合当前恰有一个版本，版本至少有一个 R项；每个 R项都有一个非空、由 FT 解释的区间材料，并至少保留一个形成它的 F成员，相关成员均属于该 IF。R项的区间材料与其 F成员固定；漂移内候选值不形成 F，但使区间材料变化时，必须建立新 R项快照，不能原地改旧项。R集合版本更新时退出旧的`R集合→版本`当前关系、建立新版本及完整当前 R项组；**每个 R项仅属于一个版本，所有新版本的目标 R项均新建，禁止跨版本复用或修改旧项**。上述节点、关系、R项材料值事实、旧版本退出与新版本快照在存在 owner 的一次写集中发布，失败零 IF/R 发布或按原请求读回已可能发布结果。

每个 R项恰有一条当前 `R项区间材料` 值事实：其写入所有者是存在 owner，所属节点和来源节点均为该 R项，属性类型节点是初始化交付的 `R项区间材料属性类型`，材料是一个非空 `U64组`。该值事实仅是存在类内部结构材料，不产生 2100 特征值身份，也不进入特征值类专属值仓。其规范载荷固定为 `[格式版本, 材料类别, 载荷项数, 规范化U64载荷...]`：前三项均为 U64；`载荷项数` 必须等于其后元素数；格式版本和类别必须能恢复为受支持的 `特征R区间材料` 字段；空载荷、溢出、未知版本/类别、长度不符或其它解码失败均为具名非成功，禁止默认、截断或猜测。L1 只保存、按来源读取该中性 U64组，不解释 R 语义。

IF 成功读回必须同截止返回 `E、FT、成员F*、R集合当前版本、R项*及各自区间材料`，并回显六关系身份、各节点、关系和材料值事实的创建/退出事实代次；R 项按 R项节点编码和成员 F 编码稳定排序读回。存在类先按 R项来源读取有界当前值组，再只接受所属/来源均为该 R项、属性类型为交付项、写入所有者为存在 owner、表示为 U64组且恰一条的值事实；缺失、重复、其它属性类型混入、退出、引用损坏、预算不足、代次漂移和内部不一致分别返回，不能截断为完整成功。

### 2.1 IF/R 的 L2 读取与目标写入合同

存在类的 `读取IF/R结构` 请求只接受非零 `E、FT、Gread`，以及分别非零的 `F成员上限、R项上限、关系上限、材料值事实上限、单材料U64元素上限`；它不接受“首次”“后续”“结构异常”“观察”或任何业务阶段字段。成功以同一 `Gread` 返回完整 IF/R 当前投影及实际读取截止；任一上限不足必须返回预算不足，不能截断成员、R项、关系、值事实或材料后宣称完整成功。

存在类的 `提交IF/R目标结构` 请求必须同时携带：

```text
E、FT
+ 非零预期快照截止 G0
+ 预期 IF/R 完整当前快照
+ 规范化目标 R 项组（每项的形成 F 成员及区间材料）
+ 本次存在结构写入幂等身份
+ 成功完整读回所需的五项预算
```

预期快照在首次路径明确为 IF/R 均不存在；当前采用不属于该快照。在后续路径，快照明确包含当前 IF、成员 F、R集合、当前版本、R项、各 R项区间材料、六类关系及其当前性所需身份；L2 只核验该快照，不自行判定首次、后续、结构异常或当前采用。规范化目标 R 项组是一个非空、按每项最小形成 F 编码升序的序列；每项形成 F 成员编码严格升序、非空且全局不重复，区间材料按 FT 的正式规范化规则比较相等性。目标项组必须覆盖预期 IF 的全部成员；首次或后续新增的其它 F 必须在 G0 时已是 E 的已知同 FT 准确 F，L2 在本次写集中建立其 IF 成员关系。不能以裸值、概念、隐式当前采用、局部差异或调用方顺序代替。

L2 按预期快照和完整目标项组只进行中性结构核验、R项新建、旧版本退出和新版本原子发布；它不创建 F、FCv、FCr、当前采用或业务诊断。目标与当前规范化项组相同则成功读回既有版本且不建立新版本；不同才发布完整新版本，并为目标组的每项新建 R项及其唯一材料值事实。预期快照在交换前不符时返回漂移或引用冲突并零本次写，不重新分类或改写目标。幂等身份只在存在结构请求命名域内按**完整持久写入请求**绑定：它是 `E、FT、G0、预期快照与规范化目标R项组` 中实际决定规范化写集的部分；同键同写入请求读回原发布，不同写入请求返回幂等冲突。五项读回预算不进入幂等绑定、不写入L1首次材料，也不改变IF/R事实；重放仍按本次预算读回，预算不足返回预算不足而非幂等冲突。

读取与写入分别精确区分：请求非法、未找到、已退出、预算不足、漂移、引用冲突、幂等冲突、资源失败、发布未知和内部不一致。交换前非成功不产生本次 IF/R 事实；发布未知或发布后读回失败保留原幂等身份并按原请求读回收束，不得假称零写或回滚。

## 3. F 加入与 R 自动维护

候选新值先与该 IF 的全部当前 R项区间材料进行同截止、同 FT 的归组比较；存在当前采用 F 不得作为比较输入、默认基准或回退。R归组、区间更新和代表值规则均由正式特征类型定义 owner 持久保存、发布并按 FT 读取；FT 也可只读提供 R→FCr 归并规则，但 R 的建立、变化或版本发布不调用该规则。正式 FT 的 R归组规则必须返回唯一“命中 R项并给出更新后区间材料”、`形成新R`、`比较未启用`或具名非成功；同时命中多个 R项属于内部不一致，不能任选。命中唯一 R项时不建立或复制 F，只按规则给出的新区间材料发布新的 R项快照；新区间材料与原材料相等时零 IF/R 写入。形成新R时才建立/复用对应准确 F：应用按7160在该 FT 的全部适用 FC 中查找；没有匹配时仅可使用“准确输入加 FT 已冻结域规则”建立并读回首个 FC。不得以 R、裸值或未发布 F 建立 FC。随后 F 与其直接 FC 使用引用共同成立，并形成以该 F 为形成成员的兄弟 R项；新 F 不隐式改变存在当前采用。

I64 仍只按完整准确值相等归入同一 R；不同 I64 必须形成新单值 R，不使用 `值±误差`、相邻或重叠合并。非 I64 的 R归组、区间材料更新和代表值选择均只能调用 FT 的已发布规则；枚举、轮廓、体素等不具有天然中位值，不能默认把任一值、编码、向量分量或材料摘要当作代表值。需要单点计算时，应用可读取 FT 规则从完整 R区间材料导出的调用期代表值；该值不是准确 F、实际观察或存在当前采用，不能写入 F 或替代要求真实准确值的读取。

## 4. 按需概念抽象

实例转概念与概念继续抽象是两条独立路径：建立准确 F 时按7160形成或复用其单值 `FCv`；概念继续抽象只在上层出现比较、归类或抽象的明确需要时，由该上层发起独立请求。R 的建立、区间材料变化、R集合版本发布或未变化均不自动建立请求、调用 R→FCr 规则、写入 `FCr` 或创建概念上下位关系。

按需请求可以选择一组既有 `FCv` 作为归纳输入，并可读取指定 R集合版本作为材料；R版本本身不构成请求、任务、回执或恢复依据。归并规则是 FT 的正式、已发布且可读取的规则数据；它接收调用方已取得并核验的输入，返回零个或多个规范化 `FCr` 定义及各自的 `FCv*` 直接下位集合。没有适用规则、没有可表达的共同抽象或规则给出零定义时，调用成功零输出，不建立概念写入。`F→FCv` 的同截止读回、唯一性与有效性核验由概念 owner 完成；特征类型定义 owner 仅消费该已核验投影，不读取或核验 `F→FCv` 事实。实际建立 `FCr` 及其上位关系仍由概念 owner 按7140处理；不得替换 F 到 FCv 的直接使用引用，R/FCr 也不得充当 F 的名称字段。

按需抽象请求不保存 `(R集合身份,版本)` 回执、完成记录、自动重试任务或恢复游标。请求失败不改变既有 R；后续是否再次发起由新的明确需要决定。

## 5. 退出与禁止

移除成员、R 版本换代或 IF 退出须先核验当前采用、F 位置、概念使用及外部引用；历史版本和已退出关系按4015保留。不得原地改 F 的类型或准确值，不得将概念允许域、2100值对象、I64误差域或旧特征分裂树冒充 R。
