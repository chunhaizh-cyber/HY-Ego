## 1. 权威边界

本规范是任务身份、任务虚拟存在、执行实例和影响评估的现行机器合同。任务属于ARCH-L4业务治理，与需求树、世界树和特征概念树共用同一个基础数据集和稳定编码空间，但任务集合根独立存在，任务节点不挂入世界树。

本规范必须区分：

```text
任务 T：围绕一个需求推进一次有目标活动的长期治理身份
任务虚拟存在 Vt：该任务状态实例特征的唯一宿主
执行实例 X：一次已经开始的方法调用及其预计、实际和评估材料
影响评估 A：一次执行后预计变化、实际状态和需求当前满足的对照结果
```

任务、Vt、X和A不是同一个对象。X不是任务轮次，A也不是任务完成结算。

### 1.1 替代裁决

1. 一个任务恰好对应一个需求；每个正式需求最终恰有一个正式任务身份。任务处于活动、等待或终结状态都不改变唯一关联，终结后不得另建第二个任务。
2. 任务不建立任务轮次或筹办轮次；每次真实方法调用建立一个执行实例X。
3. 任务不保存基础优先级；任务管理线程根据需求权重、当前可执行性、预期损耗及正式调度规则动态排序。
4. 任务状态由Vt中的任务状态实例特征表达，由任务类作为task owner唯一发布。
5. 任务读取采用current-only fresh读回；事实截止、历史读回和业务历史退出。

### 1.2 与需求目标的关系

现行关系固定为：

```text
一个任务只对应一个需求
一个需求只针对一个目标存在的一个目标特征类型
目标是值/值域合同或变化方向，二者严格二选一
```

多特征目标通过父子需求或已经形成的复合特征类型表达，不得让一个任务承接多个需求绕过一任务一需求合同。

### 1.3 执行治理边界

执行前必须已经冻结至少一条明确、可实现的结果获取途径；没有结果途径时，普通、探索和试验任务一律零动作。W3拆为动作执行W3-A和结果获取W3-B：动作后允许延迟、异地或多渠道取得结果；渠道失效时保持“动作已发出、结果未知”，禁止判成功、完成、结算或盲目重做。

影响评估只说明实际发生了什么，不等于任务终态。manager只回流正式定位；self fresh读回需求、任务、执行和评估后决定完成、继续、重试、重新筹办、等待、失败或取消，manager复核后由task owner发布正式任务状态。只有正式完成任务可以结算一次。

## 2. 对象定位

任务回答“为了使这个需求目标成立，当前治理活动推进到了哪里”。任务从唯一需求获得目标，不复制需求为什么产生，也不把需求树变成任务树。

任务只关心：

- 唯一需求身份；
- 需求所指定的目标存在、唯一目标特征类型及值目标或变化方向；
- 当前任务状态；
- 本次采用的方法及其预计影响；
- 方法执行期间实际形成的状态；
- 方法影响是否符合预计以及需求当前是否满足。

任务不负责：

- 解释需求为什么产生；
- 保存需求父子层级；
- 保存任务父子层级；
- 定义方法知识；
- 直接修改世界特征；
- 计算或持久保存任务优先级；
- 代替自我线程决定任务后继；
- 代替需求类裁决需求当前满足。

## 3. 扁平任务集合

全局基础数据集中保存：

```cpp
稳定编码 任务集合根节点;
```

任务集合根只登记全部任务，用于全集查询，不表达任务之间的父子、先后、调用、依赖或优先级关系。

规则如下：

1. 每个任务节点在任务集合根下恰有一个成员字段。
2. 任务集合根不是需求树根、世界树根或任务业务对象。
3. 查询顺序按任务稳定编码排序，不以插入顺序表达调度顺序。
4. 任务分解不得在任务集合根下形成任务树。
5. 任务优先级变化不得改变任务集合成员关系。
6. 正式任务数量只计算任务集合根登记且可完整读回的任务T；不计算任务集合根、Vt、X、A、完成结算、候选材料或线程运行项。
7. 任务全集不得包含无正式需求的孤立T；同一D出现多个T是结构不一致，不能通过数量相等掩盖。

## 4. 任务与需求一对一

任务建立入口为：

```cpp
新任务建立结果 建立或取得任务(
    稳定编码 需求节点) noexcept;
```

当前规则：

1. 需求必须能由`新_需求类`完整读回。
2. 一个任务恰好引用一个需求。
3. 一个需求最多被一个新版任务引用。
4. 同一需求重复建立时返回既有任务和既有Vt。
5. 同一需求反查出多个任务时返回`需求已有多个任务`，不得任取一个。
6. 任务不另建需求目标事实；候选方法临时材料必须完整复制目标定义以防查询期间语义漂移，但不能替代需求节点。
7. 任务终结不会删除、修改或结算需求。
8. 需求目标语义发生变化时不得原地换成另一个任务目标；应由需求领域建立新的需求身份，再建立新的任务。

self全树扫描发现正式D没有T时，只发送“建立/复用唯一关联”的任务意图。manager调用任务owner补齐T-D关联，不把补齐本身解释为需求仍需执行。扫描补齐形成或并发复用到仍处于`已建立`的T时，统一先进入`等待条件`；已满足或已失活D同样不得推进。只有self后续fresh确认同一D需要治理，manager复核后才把该T唤醒到`待查找方法`。扫描期间已经存在的长期结算任务、普通任务和终结任务均按唯一D关联复用，不建立专用副本。

当前代码允许安全根、服务根或合法普通需求作为任务唯一需求；普通需求发布尚未接通，所以当前可达生产材料仍受需求类能力限制。

## 5. 任务虚拟存在与任务状态

每个任务独占一个Vt。Vt当前保存：

```text
Vt节点身份
+ 所属任务字段 -> T
+ 任务状态特征字段 -> 唯一任务状态实例特征
```

Vt是任务域内部节点，不是世界存在，不进入世界树，也不通过`新_存在类`建立。Vt节点稳定编码就是其身份。

任务状态由一个I64特征概念和每个Vt独占的实例特征表达。状态当前值是任务状态权威；特征类维护的历史不同值和命中信息只是该实例特征的通用材料，不形成任务轮次。

任务状态封闭为：

```cpp
已建立
待查找方法
待检查条件
待执行
执行中
待影响评估
等待自我决议
等待条件
已完成
已失败
已取消
```

不得从线程状态、消息、队列位置、日志、最近方法或最近执行字段反推任务状态。

## 6. 状态迁移

合法迁移固定为：

| 原状态 | 允许后继 |
| --- | --- |
| 已建立 | 待查找方法、等待条件、已取消 |
| 待查找方法 | 待检查条件、等待条件、已失败、已取消 |
| 待检查条件 | 待执行、待查找方法、等待条件、已失败、已取消 |
| 待执行 | 执行中、待查找方法、等待条件、已取消 |
| 执行中 | 待影响评估 |
| 待影响评估 | 等待自我决议 |
| 等待自我决议 | 待查找方法、待检查条件、待执行、等待条件、已完成、已失败、已取消 |
| 等待条件 | 待查找方法、待检查条件、待执行、已失败、已取消 |
| 已完成、已失败、已取消 | 待查找方法、等待条件 |

同状态写入返回`无变化`。收束状态只有在self fresh读取同一需求确认仍需或再次需要治理，并由manager复核该决议后，才可重新启用；重新启用必须从`待查找方法`或`等待条件`开始，不得直接进入`待执行`或`执行中`。旧消息、队列重放、线程恢复或单纯时间经过都不能重开任务。

状态修改只写Vt的唯一任务状态实例特征。底层特征写入若已经更新当前值但后续通用聚合失败，任务类必须立即精确读回当前状态：读回等于目标状态时，迁移按已生效收敛；否则返回结构不一致。不得在状态已经前进后回滚或删除与该状态对应的执行结构。

## 7. 任务信息与查询

任务公开信息为：

```cpp
struct 新任务信息 {
    稳定编码 节点;
    稳定编码 需求节点;
    稳定编码 任务虚拟存在节点;
    新任务状态 当前状态;
    std::optional<稳定编码> 最近方法节点;
    std::optional<稳定编码> 最近执行实例节点;
    std::vector<稳定编码> 影响评估节点组;
};
```

其中最近方法和最近执行只是当前任务的便捷定位，不删除旧执行实例，也不能代替执行实例完整读回。

当前查询包括：

```cpp
获取任务(...)
获取任务虚拟存在(...)
查询需求任务(...)
查询全部任务()
查询活动任务()
查询指定状态任务(...)
```

`建立需求任务关联(D)`只负责建立或复用唯一T并完成上述非执行收束；它与根据fresh需求推进、重新启用或调度T的入口分开。

活动任务指当前状态不属于`已完成、已失败、已取消`的任务。收束任务经正式重新启用后重新进入活动集合。查询结果按稳定编码排序。`查询需求任务()`在没有任务或出现多个任务时均不返回伪造身份；需要区分两种情况的调用方必须先读取需求并交叉检查任务全集。

## 8. 任务分解与子需求

任务不建立任务树。任务执行过程中发现独立子目标时，只能形成需求树中的子需求：

```text
父任务 T
-> 以T作为正式来源承接身份
-> 需求类在T唯一需求D下建立子需求Dchild
-> Dchild后续独立建立自己的任务Tchild
```

公开接缝为：

```cpp
新需求建立结果 建立子需求(
    稳定编码 任务节点,
    新普通需求建立请求 请求) noexcept;
```

当前入口只允许非终结任务发起，并要求请求父需求准确等于该任务的唯一需求。随后把任务节点作为来源承接节点交给需求服务。

但是，`新_需求类`尚未实现“来源节点确为正式任务”的强类型核验，普通需求入口仍返回`任务来源未接通`。因此当前接缝不发布子需求，不得把任意现存节点或任务稳定编码本身直接解释为已经具备正式来源资格。

## 9. 执行实例

任务类不解释方法知识。调用`开始方法执行()`以前，上层必须完成：

- 方法身份合法性核验；
- 预计影响读取；
- 抽象对象角色到本次实际作用对象的绑定；
- 预计变化阶段组织。

一次实际方法调用建立一个执行实例X：

```cpp
struct 新任务执行信息 {
    稳定编码 节点;
    稳定编码 任务节点;
    稳定编码 方法节点;
    新任务执行状态 状态;
    新状态强时间 开始时间;
    std::optional<新状态强时间> 结束时间;
    std::vector<新任务预计变化阶段> 预计变化阶段组;
    std::vector<稳定编码> 实际状态节点组;
    std::optional<稳定编码> 影响评估节点;
};
```

执行状态封闭为：

```text
执行中
已结束待评估
已评估
```

X不是任务轮次，不表达重新筹办次数、任务生命周期代次或线程工作次数。同一任务可以先后形成多个X，但只有任务处于`待执行`时才能开始新的X；任务类当前没有并行执行入口。

方法节点当前只要求是基础数据集中仍存在的节点。它是否为正式方法、是否可执行以及是否属于本任务，由上层方法服务和任务管理链负责核验。

## 10. 预计影响结构

预计影响采用“阶段串行、阶段内并行”的结构：

```cpp
struct 新任务预计变化阶段 {
    std::int64_t 顺序;
    std::vector<新任务预计特征变化> 变化组;
};

struct 新任务预计特征变化 {
    稳定编码 作用对象节点;
    稳定编码 特征类型概念节点;
    std::optional<稳定编码> 预期变化关系节点;
    std::optional<稳定编码> 预期值域概念节点;
    bool 必须出现;
};
```

规则如下：

1. 至少有一个阶段。
2. 阶段顺序从0开始连续递增。
3. 每个阶段至少有一个变化项。
4. 同阶段内，同一作用对象和同一特征类型不能重复。
5. 同阶段变化没有先后关系；不同阶段按顺序推进。
6. 作用对象、特征类型、可选变化关系和可选值域必须是当前存在的节点。
7. 预计项保存已经绑定的实际作用对象，不保存抽象角色。
8. `必须出现=false`表示该变化可以缺席；缺席时不进入预计缺失组。

当前实现保存预期变化关系和预期值域，但影响评估尚未调用对应求值提供者。它们不能被解释为已经完成方向和幅度验证。

## 11. 执行结束与实际状态

结束执行请求只接受已经由`新_状态类`正式建立的状态节点：

```cpp
struct 新任务执行结束请求 {
    稳定编码 任务节点;
    稳定编码 执行实例节点;
    新状态强时间 结束时间;
    std::vector<稳定编码> 状态节点组;
};
```

规则如下：

1. X必须属于请求任务。
2. 结束时间不得早于开始时间。
3. 每个状态都必须完整存在并使用合法实例绝对UTC强时间。
4. 每个状态时间必须位于`[开始时间, 结束时间]`闭区间。
5. 同一状态节点不得重复提交。
6. 状态按强时间升序排列；相同时间按状态稳定编码排序。
7. 合法结束后，X进入`已结束待评估`，任务进入`待影响评估`。
8. 同一结束时间和同一有序状态组的重复提交返回精确重复；异义重复拒绝。

状态节点由调用方提交。当前任务类只能证明状态是正式状态且位于执行时间窗内，不能证明该状态由本次方法执行造成。正式因果归属仍需要后续提供者或独立观察合同。

## 12. 方法影响评估

影响评估入口为：

```cpp
新任务影响评估结果 评估方法执行影响(
    稳定编码 任务节点,
    稳定编码 执行实例节点) noexcept;
```

评估只在X为`已结束待评估`且任务为`待影响评估`时进行。

### 12.1 预计与实际匹配

当前匹配键为：

```text
作用对象节点相同
+ 特征类型概念节点相同
+ 实际状态时间不早于当前阶段允许起点
```

处理规则：

1. 按阶段顺序处理。
2. 每个预计项选择尚未使用且满足键的最早实际状态；同一时间按状态稳定编码确定。
3. 同阶段内不要求预计项之间有时间顺序。
4. 本阶段至少命中一项时，下一阶段允许起点推进到本阶段全部命中的最晚时间。
5. 必须出现但没有命中的预计项进入`预计但未发生项组`。
6. 已命中的实际状态进入`符合预测状态组`。
7. 全部未被使用的实际状态进入`计划外状态组`。

当前算法没有核验预期变化关系、预期值域、变化方向、幅度或因果来源，所以“符合预测”目前只表示对象、特征类型和阶段时间顺序命中，不表示完整效果预测成立。

### 12.2 需求fresh复核

预计与实际分类后，任务类必须调用：

```cpp
需求服务.复核当前满足(任务.需求节点)
```

本次复核重新读取唯一需求的当前世界材料，不用执行开始时快照、方法返回、状态后值、历史评估或任务状态代替。

需求复核结果保存：

- 当前满足状态；
- 可选实际特征节点；
- 可选准确差异。

影响评估完成后，X进入`已评估`，任务进入`等待自我决议`。同一X重复评估时返回既有评估，不建立第二份。

## 13. 影响评估信息

```cpp
struct 新任务影响评估信息 {
    稳定编码 节点;
    稳定编码 任务节点;
    稳定编码 需求节点;
    稳定编码 执行实例节点;
    稳定编码 方法节点;
    新需求当前满足结果 目标需求结果;
    std::vector<稳定编码> 符合预测状态组;
    std::vector<稳定编码> 预计但未发生项组;
    std::vector<稳定编码> 计划外状态组;
};
```

三类集合含义：

- 符合预测组保存正式状态节点；
- 缺失组保存执行实例内的预计变化项节点；
- 计划外组保存正式状态节点。

影响评估是任务管理线程通知自我线程的正式定位材料，但消息接线尚未实现。评估节点不是任务结算、需求结算、方法知识更新、因果事实或自我后继决议。

## 14. 任务优先级边界

任务节点、Vt、X和A均不保存任务优先级。

任务优先级由后续任务管理线程在需要选择待推进任务时动态计算。可考虑的输入至少包括：

```text
唯一需求的当前权重
当前可执行性
预计损耗或成本
安全硬限制
资源可用性
等待条件
```

本草案不冻结具体公式、归一化方法或排序并列规则。未形成正式算法以前，任务管理线程不得把队列位置、等待时间、稳定编码或任意常数写回任务节点冒充优先级事实。

优先级只影响尚未开始工作的选择顺序，不改变需求权重、任务状态、执行实例事实或已经运行的动作。

## 15. 生命周期

任务从`已建立`开始，在合法状态机中推进，并可以到达`已完成`、`已失败`或`已取消`收束状态。只要对应长期需求身份仍然存在，self在fresh确认再次需要治理后可以重新启用同一任务；不另建第二任务，也不建立任务轮次。

当前新版任务类没有：

- 删除任务；
- 删除Vt；
- 删除执行实例或影响评估；
- 退出任务集合；
- 正式任务完成结算；
- 需求结算；
- 跨进程恢复。

收束状态停止普通执行推进，但允许按本规范第6节的正式重新启用路径回到方法查找或等待条件。重新启用不删除旧执行实例或评估，不撤销已经完成的任务结算，也不得让同一任务重复结算；尚未结算的失败或取消任务后续首次正式完成时仍可结算一次。任务收束、需求当前满足、需求失活、影响评估完成和正式任务结算必须分账。

## 16. 写入与失败边界

新版基础数据集没有多节点组合事务。任务类使用进程内递归互斥保护本类操作，并在多步建立失败时尽力逆序删除本次字段和节点。

这只能证明当前进程内的尽力收敛，不能证明：

- 跨线程以外的跨进程互斥；
- 崩溃原子性；
- 发布未知恢复；
- 技术幂等键；
- 持久化或重启后任务身份恢复。

任务操作区分尚未初始化、入口拒绝、需求不存在、需求已有多个任务、任务/Vt/方法/执行/状态不存在、状态不允许、预计影响不合法、时间不合法、材料不足、结构不一致、资源失败和依赖未实现。

资源失败、结构不一致、依赖未实现和入口拒绝不得改写成任务业务失败。业务失败只能通过合法状态迁移进入`已失败`，其业务依据由上层治理提供。

## 17. 一致性不变量

任一成功读回的任务必须满足：

1. T在扁平任务集合根下恰有一个成员引用。
2. T恰好引用一个可读需求D。
3. D最多被一个新版任务引用。
4. T恰好引用一个Vt，Vt准确反向引用T。
5. Vt恰好引用一个任务状态实例特征。
6. 状态特征使用任务状态特征概念，当前值属于封闭状态枚举。
7. 最近执行若存在，必须是正式执行实例并属于该任务。
8. 每个X恰好属于一个任务并引用一个方法节点。
9. X的阶段顺序连续，阶段非空，同阶段对象与特征类型键不重复。
10. X结束后具有完整结束时间；X已评估时恰有一个影响评估。
11. A的任务、需求、执行实例和方法与来源X及T一致。
12. 收束状态不能直接建立执行实例；只有self fresh决议和manager复核后才可迁移到`待查找方法`或`等待条件`，且不得重复任务结算。

当前代码完整读回会检查其中大部分结构，但还没有独立全仓一致性巡检或恢复修复入口。

## 19. 非权威实现完成边界

当前已经具备：

- 独立扁平任务集合根；
- T与D严格一对一建立和复用；
- 唯一Vt和唯一任务状态实例特征；
- 任务状态机和状态查询；
- 执行实例X；
- 阶段串行、阶段内并行的预计影响结构；
- 正式状态节点的有序绑定；
- 预计命中、预计缺失和计划外变化分类；
- 唯一需求的fresh当前满足复核；
- 影响评估保存、读回和重复评估收敛；
- 子需求入口接缝。

当前尚未具备或没有证明：

- 方向目标完整运行验证；
- 普通子需求正式发布；
- 正式方法身份和预计影响提供者；
- 预期变化关系和值域的实际求值；
- 实际状态与本次执行的因果归属；
- 方法查找、条件检查、选择、冻结和正式执行授权；
- 任务管理线程动态优先级算法和调度；
- 影响评估结果到自我线程的消息接线；
- 自我线程继续、等待、完成、失败或取消决议；
- 正式任务实际结果、完成结算和需求结算；
- 持久化、跨启动恢复和生产装配；
- 运行期、恢复及完整集成验收。

## 20. 验证边界

后续验证至少覆盖：

- 同一需求重复建立复用同一T和Vt；
- 同一需求出现多个任务时明确拒绝；
- Vt唯一状态特征和全部合法/非法状态迁移；
- 收束状态只有经self fresh决议和manager复核才可重新启用，且不能直接进入执行；
- 底层特征值已更新但聚合失败时按精确状态读回收敛；
- 阶段顺序连续、阶段内重复键拒绝和阶段间时间推进；
- 执行结束的时间窗、状态去重和稳定排序；
- 同义结束精确重复、异义结束拒绝；
- 预计命中、可选缺席、必须缺失和计划外状态分类；
- 影响评估后fresh复核唯一需求；
- 值目标使用fresh当前值，方向目标使用同一执行实例冻结的动作前值和观察后值；
- 同一X重复评估只读回原A；
- 子需求来源未接通时零需求写入；
- 任务优先级不进入T、Vt、X或A；
- 资源失败和结构错误不伪装业务失败；
- 其它所有者WIP、旧任务实现和正式规范不被新版任务旁路修改。
