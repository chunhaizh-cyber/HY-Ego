# 3200 根规范 任务

编号：3200  
日期：20260818  
版本：v0.5  
状态：正式根规范（待确认修订稿 v0.5）

直接上级规范：0050。

直接依赖规范：无。

相关边界规范：3100、3300、4250、4260、5110、5160、5200—5250、5300—5340、6150。

---

## 1. 根定位

任务是为使一个需求列表项所代表的确定目标成为事实，而组织方法路径、选择并执行具体实例方法、记录运行状态、收束实际结果并验证目标的一次有稳定身份活动。

任务是自我一切有目标活动的基本承载单位。

任务不是：

```text
需求本身
方法本身
世界存在
需求树节点的副本
目标副本
日志
显示摘要
永久完成布尔值
正式结算记录
```

任务核心回答：

```text
为什么做？
    -> 当前承接的需求列表项及其当前成员需求

做什么？
    -> 需求列表项的精确目标

有哪些办法？
    -> 0..N 条任务方法路径

这次用哪条？
    -> 当前选中路径 / 当前实例方法

现在进行到哪里？
    -> 任务虚拟存在中的运行状态

实际发生了什么？
    -> 本轮实际结果及其证据

目标是否达成？
    -> 实际结果 / 当前世界事实与列表项目标的正式比较和验证

这些结果支撑了哪些需求成员？
    -> 本轮冻结的成员需求身份、版本、路径、权重、授权、预算与结算来源
```

---

## 2. 任务核心结构

任务长期核心固定为：

```text
任务身份
需求列表项
任务虚拟存在
结构生命周期
```

其中：

```text
需求列表项
    = 本任务唯一目标入口

任务虚拟存在
    = 本任务运行状态唯一权威宿主
```

任务不复制：

```text
目标宿主
目标特征
目标状态
当前世界状态
需求成员集合
成员权重
成员授权
成员预算
```

需要这些信息时必须沿正式关系读取：

```text
任务
-> 需求列表项
-> 精确聚合目标

任务
-> 需求列表项
-> 当前成员需求组
-> 成员路径 / 当前性 / 权重 / 授权 / 预算 / 结算来源
```

任务不直接保存需求树父子关系，也不建立第二套持久化任务树。

---

## 3. 需求列表项承接

### 3.1 一个列表项至多一个当前任务

固定：

```text
一个当前需求列表项
    -> 0..1 个当前任务
```

同一列表项不得同时存在两个当前有效任务。

### 3.2 列表项包含多个需求树成员

一个需求列表项允许：

```text
0..N 个当前需求树成员
```

这些成员拥有完全相同的精确目标，但各自仍保留：

```text
需求身份
父子位置
来源
路径
当前性
权重
授权
预算
结算来源
正式结算身份
```

任务不得把这些成员压成一条失去来源的汇总事实。

### 3.3 任务不维护第二份“来源需求集合”

任务当前来源需求集合固定通过：

```text
任务
-> 需求列表项
-> 当前成员需求组
```

动态读取。

任务结构不得再持久化一份可以独立变化的“来源需求集合”，避免与需求列表成员关系形成第二权威。

### 3.4 本轮消费成员快照

筹办、排队、执行冻结、执行、验证和结果收束必须记录本轮实际消费的成员需求材料。

至少应能够回到：

```text
成员需求身份
成员版本 / 当前性版本
成员路径
成员权重
成员授权
成员预算
规则版本
共同事实截止
```

这些材料是：

```text
本轮运行冻结 / 审计证据
```

不是任务长期核心成员集合。

成员之后新增、退出、失活、权重变化或授权变化，不得反写并篡改历史冻结。

---

## 4. 任务目标

任务目标固定为：

```text
需求列表项精确聚合目标
```

即：

```text
所属存在
+ 目标宿主
+ 目标特征
+ 目标状态合同
```

由需求列表项提供。

任务结构不得重新保存第二份：

```text
目标宿主
目标特征
目标状态合同
```

需要目标时必须：

```text
任务
-> 需求列表项
-> 精确聚合目标
```

列表项目标发生身份变化时，不允许在原任务内偷偷替换目标语义；应遵守需求列表项和任务结构的正式生命周期、退出和重新承接规则。

---

## 5. 任务虚拟存在

### 5.1 定位

每个任务必须独占一个任务虚拟存在。

固定：

```text
任务 T
    -> 唯一任务虚拟存在 Vt
```

任务虚拟存在：

```text
不是世界 L2存在
不进入世界树
不取得现实存在资格
不与其它任务共享
```

不同任务即使：

```text
对应同类目标
使用相同方法
来源于同一根需求
```

也不得共享任务虚拟存在。

### 5.2 状态唯一权威宿主

任务运行状态统一由任务虚拟存在的：

```text
特征
状态
动态
```

体系表达。

至少包括：

```text
当前阶段 / 业务状态段
筹办轮次
筹办占用 / 当前性
候选形成状态
可达路径形成状态
当前选择状态
实例方法状态
等待状态
输入闭合状态
条件状态
执行冻结状态
执行轮次
执行状态
实际结果状态
目标达成状态
验证状态
归因状态
重新筹办状态
完成状态
失败状态
取消状态
```

精确特征和值域由 5200、5210、5230 及后继规范冻结。

### 5.3 生命周期不是单一业务状态

任务结构生命周期只表示：

```text
结构创建
当前存在
结构退出
历史可读
```

不等同于：

```text
筹办中
执行中
已完成
失败
取消
```

同一个生命周期阶段可以存在不同业务状态段。

不得用一个生命周期枚举代替完整任务状态体系。

## 6. 任务事实来源与当前性

任务当前治理事实只能来自：

```text
任务领域固定治理事实
需求列表项及其当前成员需求
成员当前授权 / 权重 / 预算 / 路径
当前目标
当前世界事实
当前有效任务方法路径
当前实例方法正式冻结
方法运行形成并经任务领域收束的结果证据
正式验证 / 归因材料
```

任务不得临时发明无来源业务特征。

已经由：

```text
任务节点
正式关系
任务虚拟存在
路径结构
实例方法
结果结构
```

承载的事实，不得再复制成第二套权威普通特征。

所有关键运行材料必须具有：

```text
来源
版本
当前性
事实截止
生命周期
```

## 7. 多方法路径

### 7.1 三层手段结构

任务的手段必须分成：

```text
候选方法
    ↓
任务方法路径
    ↓
当前选中路径 / 当前实例方法
```

三层不得混为一个字段。

### 7.2 候选方法

候选方法只表示：

```text
根据任务目标召回到的可能能力
```

候选不证明：

```text
条件成立
输入闭合
参数可绑定
当前可执行
当前被选中
```

### 7.3 任务方法路径

一个任务允许：

```text
0..N 条当前任务方法路径
```

路径是：

> 在某一筹办轮次和当前事实条件下，为达成当前列表项目标而形成的一条具体可达方案。

每条路径至少应能回到：

```text
任务
筹办轮次
来源方法
来源方法内容版本
条件绑定
输入绑定
参数绑定
动作入口
预期结果
验证合同
归因合同
路径当前性
生命周期
```

如为组合方法，还应能够回读：

```text
子方法组成
步骤顺序
终止条件
```

普通确定步骤仍属于路径 / 实例方法内部，不自动形成需求。

### 7.4 可达不等于选中

严格分账：

```text
候选
≠
可达

可达
≠
当前选中

当前选中
≠
已经执行

已经执行
≠
任务完成
```

L2数据结构服务不得自动：

```text
评分
排序
选第一条
按名称选择
认为最新路径最好
```

---

## 8. 当前选中路径与实例方法

任务当前允许：

```text
当前选中路径 = 0..1
当前实例方法 = 0..1
```

合法空可能表示：

```text
尚未筹办完成
没有可达路径
等待条件
需要重新筹办
尚未形成执行冻结
```

合法空不自动等于任务失败。

### 8.1 一轮执行单一路径

一次执行只能：

```text
选择 1 条当前路径
-> 形成 1 个当前实例方法
-> 建立本轮执行冻结
-> 执行
```

不得多路径同时执行同一任务的一轮实例。

### 8.2 实例方法是不可变执行快照

当前实例方法至少必须能够回到：

```text
所属任务
来源任务方法路径
来源方法
方法内容版本
筹办轮次
执行轮次
冻结输入
冻结参数
冻结条件
动作入口
预期结果
验证合同
归因合同
实例生命周期
```

重新筹办即使再次选择同一抽象方法，也必须形成新轮次的路径 / 实例历史，不覆盖旧实例。

---

## 9. 任务筹办

### 9.1 定位

任务筹办是任务领域内建治理行为。

它不：

```text
进入普通方法召回
创建为解决自身的子任务
建立独立第二任务树
用一个“筹办回执节点”替代正式结构结果
```

### 9.2 每轮权威重读

每一轮筹办必须权威读取：

```text
任务
需求列表项
当前成员需求集合
成员路径
成员权重
成员授权
成员预算
成员当前性
列表项目标
当前世界事实
候选方法
当前任务虚拟存在状态
当前事实版本
```

筹办不能沿用已经失效的上一轮缓存冒充当前事实。

### 9.3 筹办结果

筹办允许形成：

```text
0..N 条任务方法路径
```

然后：

```text
选择 0..1 条当前执行路径
形成 0..1 当前实例方法
建立执行冻结
```

无可达路径时：

```text
不得自动创建方法首
不得伪造一条“默认方法”
不得直接写任务失败
不得返回无结构的上层回退
```

必须按 5230 等正式规范形成具名结果、等待、缺口、重筹办条件或业务失败证据。

---

## 10. 筹办并发与执行权

旧正式根规范中仍然有效的并发原则保留：

```text
筹办并发隔离键 = 任务稳定身份
```

同一任务同一时刻：

```text
最多一个有效筹办执行权
```

不同任务允许并发筹办。

筹办执行权必须能够区分：

```text
取得
拒绝
占用
当前性
闭合
失效
重复请求
```

不得通过普通 bool 或线程局部变量冒充正式执行权。

执行权、冻结和队列锚点的精确数据合同由 5230 等下位规范冻结。

---

## 11. 目标分解与子需求

任务不建立持久化任务父子关系。

当任务发现必须独立达成的子目标时，固定流程为：

```text
任务
-> 当前需求列表项
-> 确定本轮实际来源成员 / 父需求上下文
-> 形成独立子目标候选
-> 提交需求业务
-> 合法时挂入对应需求树
-> 子需求进入自己的需求列表项
-> 该列表项取得自己的任务
```

任务层级由：

```text
需求树父子关系
+
需求列表成员关系
+
列表项当前任务关系
```

运行期推导。

禁止建立第二套：

```text
父任务 -> 子任务
```

权威树。

### 11.1 普通步骤不生成子需求

只有独立目标才进入需求树。

普通实例方法步骤继续留在：

```text
方法路径
或
实例方法
```

内部。

## 12. 执行冻结

执行只能使用当前有效执行冻结。

执行冻结至少必须证明本轮：

```text
任务
需求列表项
本轮消费成员需求及版本
当前选中路径
当前实例方法
方法内容版本
输入
参数
条件
授权
当前性
执行轮次
目标版本
必要世界事实截止
```

仍然匹配。

冻结后若以下材料发生导致合同失效的变化：

```text
方法代际
路径
授权
条件
输入
参数
目标
关键世界事实
成员当前性
```

则旧冻结失效，任务进入：

```text
等待
或
重新筹办
```

不得拿旧冻结继续执行。

---

## 13. 执行与结果事实

### 13.1 执行前置

执行至少要求：

```text
当前实例方法存在
执行冻结仍当前
任务虚拟存在允许执行
执行权成立
必要授权仍有效
```

### 13.2 执行结果

执行过程固定为：

```text
当前实例方法
-> 动作
-> 独立事实回读
-> 实际结果证据
-> 任务领域结果收束
-> 更新任务虚拟存在
```

方法返回：

```text
成功
```

只证明方法自身执行合同返回成功，不证明任务目标已经达成。

### 13.3 实际结果不得被日志替代

任务实际结果必须由正式结果结构和证据关系承载。

不得用：

```text
日志
弹窗
显示文本
函数返回 true
线程退出码
```

替代正式实际结果事实。

---

## 14. 任务完成

任务完成必须由以下材料联合证明：

```text
实际结果
+ 需求列表项精确目标
+ 当前世界事实
+ 正式比较
+ 必要验证
+ 当前性
```

不得用以下任一单项直接写任务完成：

```text
方法返回成功
动作已经发生
子需求已完成
子任务活动已结束
任一成员需求当前满足
日志显示成功
执行线程正常返回
```

任务完成是任务活动的运行结论，不是需求永久满足，也不是需求正式结算。

---

## 15. 筹办漏检与内部逻辑错误

旧正式根规范这一硬边界继续有效：

若执行期才发现冻结前已经存在且本应在筹办阶段发现的：

```text
方法缺失
动作入口缺失
规格缺失
目标缺失
授权缺失
输入缺失
条件缺失
任务结构缺失
当前性错误
```

则属于：

```text
筹办漏检
或
内部逻辑错误
```

不得伪装成：

```text
普通需求
普通等待
合法任务失败
方法业务失败
```

具体缺口分类和分流由 5230、5150 等规范冻结。

## 16. 重新筹办

合法触发至少包括：

```text
当前路径失效
当前实例方法失效
执行冻结失效
条件变化
输入变化
授权变化
成员当前性变化
子需求回流
目标未达成
执行结果要求换路
方法新代际可用
```

重新筹办必须：

```text
保留旧筹办轮次
保留旧路径历史
保留旧实例历史
保留旧冻结
保留旧结果
形成新筹办轮次
重新读取当前事实
重新生成路径集合
重新选择
```

不得覆盖上一轮历史。

---

## 17. 任务失败与取消

### 17.1 任务失败

任务失败只能表达：

```text
合法业务失败条件已经命中
+
存在正式终止证据
```

内部逻辑错误不得写成任务失败。

以下情况本身不自动等于任务失败：

```text
无候选方法
等待子需求
等待输入
等待授权
旧路径失效
需要重新筹办
内部不一致
筹办漏检
```

### 17.2 任务取消

任务取消必须有合法取消授权。

若任务已经进入动作执行，还必须具有：

```text
动作停止
或
安全停止
或
无法停止的具名证据
```

不得仅改状态枚举就宣称任务已经取消。

---

## 18. 安全权限与一般权重分账

任务通过需求列表项读取成员的：

```text
权重
授权
安全因果层投影
预算
当前性
```

这些材料不得丢失成员来源。

如果正式安全治理规则要求任务从多个当前成员继承执行优先级权限，则只能依据：

```text
每个成员正式安全因果层投影
+
当前有效权限
```

形成当前执行选择材料，并保留全部来源和版本。

任务不得根据：

```text
需求名称
任务名称
任务类型文本
任务自身普通字段
```

自行判断安全层级。

任务调度权重、执行优先级权限、结算预算必须分账：

```text
权重
≠
安全执行权限
≠
结算预算
≠
实际结算值
```

具体安全权限由 6150 等安全治理规范唯一冻结。

## 19. 任务结果与需求当前满足 / 正式结算

必须严格区分：

```text
任务实际结果
任务完成
需求当前满足
需求正式结算
```

### 19.1 一个任务结果可以支撑多个成员

同一需求列表项中的成员拥有同一个精确目标。

因此一次任务实际结果和一次当前世界事实验证可以作为多个当前成员需求的共同证据来源。

但它不能把多个成员压成一个结算身份。

每个成员仍独立保留：

```text
需求身份
路径
当前性
权重
授权
预算
结算来源
正式结算记录
```

### 19.2 任务只产生结算支撑材料 / 候选

任务领域可以正式形成：

```text
任务结果
验证材料
归因材料
本轮消费成员快照
结算候选 / 结算支撑证据
```

但正式需求结算由 3100、5160、4320 等需求 / 结算规范裁决。

不得：

```text
任务完成
-> 自动把全部成员需求结算成功

任务成功
-> 直接写列表项总结合算结果

方法成功
-> 直接写需求正式结算
```

### 19.3 结算不得丢失成员预算

若同一任务结果支持多个成员结算，任务必须能够提供：

```text
本轮实际消费成员身份
成员版本
成员路径
成员权重
成员授权
成员预算
规则版本
结果证据
共同事实截止
```

供正式结算逐成员裁决。

不得把多个成员预算在任务中压成不可回溯总值。

### 19.4 任务完成不等于需求当前满足

即使任务已经完成：

```text
仍必须由需求领域读取当前世界事实
+
目标状态合同
+
正式比较
```

才能裁决需求当前是否满足。

历史任务完成和历史正式结算都不能永久证明当前世界继续满足目标。

## 21. 事务、幂等、当前性与历史

所有下位任务结构合同必须遵守以下根原则：

1. 任务节点、需求列表项引用、任务虚拟存在必须同代原子建立；
2. 同一列表项当前至多一个任务；
3. 每任务当前恰一任务虚拟存在；
4. 每任务允许 0..N 条当前方法路径；
5. 当前选中路径为 0..1；
6. 当前实例方法为 0..1；
7. 路径、选择、实例、冻结、结果、状态换代必须保留历史；
8. 重新筹办不得覆盖前轮；
9. 当前组合读取必须共享共同事实截止；
10. 历史读取必须使用具名历史截止；
11. 同幂等身份 + 同完整请求返回精确重复和首次结果；
12. 同幂等身份 + 不同完整请求返回幂等冲突；
13. 事实代次漂移必须零变化；
14. 资源失败、异常或发布未知只能用原幂等身份和原完整请求收敛；
15. 不得用缓存、日志、线程上下文或默认值补齐坏结构；
16. 任一身份复义、单例关系重复、跨代拼装、发布后读回矛盾属于内部不一致；
17. 任务退出不得隐式删除或改写需求树、需求列表、需求结算历史。

## 23. 禁止事项

禁止：

- 任务直接绑定一个需求树成员后忽略需求列表项；
- 任务维护第二份可变来源需求集合；
- 任务复制列表项目标；
- 任务复制当前世界事实；
- 把成员权重、授权、预算压成不可审计单值；
- 从单个需求成员直接猜测唯一任务；
- 建立第二套持久任务父子树；
- 用世界 `L2存在身份` 充当任务虚拟存在；
- 多任务共享一个任务虚拟存在；
- 把候选方法当可达路径；
- 把可达路径当当前选中路径；
- 把当前选中路径当已执行方法；
- 同一执行轮次同时运行多个实例方法；
- 无可达路径时自动创建方法首；
- 无可达路径时直接写任务失败；
- 用方法返回成功直接写任务完成；
- 用动作发生直接写任务完成；
- 用子需求完成直接写父任务完成；
- 用任一成员满足直接写任务完成；
- 用任务完成直接写需求当前满足；
- 用任务完成直接写需求正式结算；
- 把多个成员正式结算压成任务级或列表项级不可回溯总结果；
- 把内部逻辑错误写成普通任务失败；
- 把筹办漏检包装成普通需求；
- 在旧冻结失效后继续执行；
- 取消执行中任务时没有动作停止证据；
- L2任务结构服务自动召回、评分、选择方法；
- L2任务结构服务自动生成子需求；
- L2任务结构服务自动判断任务完成；
- 需求、方法、线程、调度器、显示层直接改写任务结构；
- 用名称、文本、日志、缓存、线程状态证明任务身份或业务状态。

## 24. 代码生成根边界

本规范可直接作为任务体系代码生成的根级语义约束，但精确 DTO、关系类型、状态值域和函数签名必须继续服从对应子规范。

代码生成不得恢复旧模型：

```text
任务 -> 单个需求
任务自己保存多个来源需求关系作为第二权威
任务目标副本
任务运行场景作为长期目标核心副本
任务治理存在 = 世界 L2存在
持久任务父子树
替换任务目标宿主 / 目标特征 / 目标状态
按单需求读取唯一任务作为主入口
```

不得自行补造：

```text
任务完成 bool
任务失败 bool
任务取消 bool
任务已结算 bool
万能状态 I64
万能方法引用
万能执行权 bool
无来源总权重
无来源总结算
```

若下位规范尚未冻结精确 DTO、接口或状态：

```text
不得用万能参数
普通属性槽
自由关系
文本
裸 I64
临时 bool
动态编号
```

提前发布公开 ABI。
