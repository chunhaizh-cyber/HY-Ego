## 1. 根定位

任务是任务领域按具体需求承接输入建立或复用、为使其显式关联需求的同一确定目标成为事实，而组织方法路径、选择并执行具体实例方法、记录运行状态、收束实际结果并验证目标的一次有稳定身份活动。需求列表项只作为同类任务查询 / 防重锚点，不授权任务。

任务是需要进行方法筹办、执行、结果回读和目标验证的有目标活动承载单位。

任务不是所有内部处理动作的通用包装。

以下内部治理动作即使具有明确处理目标，也不因此建立任务：

```text
读取事实
治理输入分类
任务筹办编排
候选召回编排
状态比较
结果绑定复核
任务结果收束
任务生命周期推进
需求结算编排
价值结算编排
线程路由与消息处理
```

这些动作属于内部治理或领域服务职责。若把它们再次包装成任务，会形成“为筹办任务再筹办一个任务”的递归。

任务不是：

```text
需求本身
方法本身
世界存在
需求树节点的副本
目标副本
内部治理步骤
日志
显示摘要
永久完成布尔值
正式结算记录
```

任务核心回答：

```text
为什么做？
    → 当前显式关联的具体需求

做什么？
    → 至少一项当前关联需求逐项互证后的单目标投影

有哪些办法？
    → 0..N 条任务方法路径

这次用哪条？
    → 当前选中路径 / 当前实例方法

现在进行到哪里？
    → 任务虚拟存在中的运行状态

实际发生了什么？
    → 本轮正式任务实际结果及其证据

目标是否达成？
    → 正式结果与关联需求单目标投影的比较和验证

这些结果支撑了哪些需求成员？
    → 本轮冻结的显式关联需求身份、关系、版本、路径、权重、预算与结算来源
```

## 2. 任务核心结构

任务长期核心固定为：

```text
任务身份
同类任务查询锚点（其值为 L2需求列表项身份）
任务虚拟存在
结构生命周期
```

其中：

```text
同类任务查询锚点
    = 同精确目标当前任务查找和防重索引
    = 不是任务目标、授权或来源需求集合

任务虚拟存在
    = 本任务特征、运行状态与状态迁移记录的唯一正式宿主
```

任务另以逐项正式关系保存已经收到承接输入的具体来源需求。任务不复制：

```text
所属存在
目标宿主
目标特征
目标状态合同
当前特征值或其值式投影
需求目标
列表项全部成员集合
成员权重与预算
```

需要这些信息时必须沿正式关系读取：

```text
任务
→ 当前任务来源需求关系组
→ 至少一项当前有效具体需求
→ 逐项读取并机械验证相同目标三元组

任务
→ 当前任务来源需求关系组
→ 已显式关联需求的路径 / 当前性 / 权重 / 预算 / 结算来源
```

任务不直接保存需求树父子关系，也不建立第二套持久化任务树。

## 3. 具体需求承接与同类任务防重

### 3.1 同类任务查询锚点至多一个当前任务

固定：

```text
一个当前同类任务查询锚点
→ 0..1 个当前任务
```

同一查询锚点不得同时存在两个当前有效任务。该基数只防止精确同目标的重复当前任务，不把列表项升级为任务目标或授权。

### 3.2 任务逐项保存具体需求关联

一个当前任务允许：

```text
1..N 条当前任务来源需求关系
```

每条关系只能由一次携带具体需求身份的承接输入建立。全部当前关联需求必须拥有完全相同的需求核心契约，但各自仍保留：

```text
需求身份
父子位置
来源
路径
当前性
权重
预算
结算来源
正式结算身份
```

任务不得把这些需求压成一条失去来源的汇总事实，也不得因列表项新增成员而自动新增任务关系。

### 3.3 列表项不是来源需求集合

任务当前来源需求集合固定通过：

```text
任务
→ 当前任务来源需求关系组
→ 逐项读取具体需求
```

动态读取。任务—需求关系是承接关联事实，不复制需求目标，也不形成第二需求权威。列表项成员关系只属于需求列表派生视图；不得用它替代任务—需求关系。

### 3.4 本轮消费成员快照

筹办、排队、执行冻结、执行、验证和结果收束必须记录本轮实际消费的成员需求材料。

至少应能够回到：

```text
任务—需求关系身份
成员需求身份
成员版本 / 当前性版本
成员路径
成员权重
成员预算
规则版本
共同事实截止
```

这些材料是：

```text
本轮运行冻结 / 审计证据
```

不是任务长期核心成员集合。

成员之后新增、退出、失活、权重变化或活动资格变化，不得反写并篡改历史冻结。

## 4. 任务目标

任务需要达成的目标固定为当前显式关联需求逐项回读并验证相同的目标三元组：

```text
目标宿主
+ 目标特征
+ 目标状态合同
```

形成任务单目标投影至少需要一项当前有效且已显式关联的需求。全部关联需求处于非活动治理状态，或全部 `T→D` 关系均已退出当前时，不得读取同类任务查询锚点聚合键兜底；任务业务必须显式进入等待、结束或重新裁决。上述变化不删除或退出需求本体，需求身份与目标合同持续存在。

任务结构不得重新保存第二份：

```text
所属存在
目标宿主
目标特征
目标状态合同
```

需要目标时必须：

```text
任务
→ 当前任务来源需求关系组
→ 逐项读取当前具体需求
→ 机械验证目标完全相同
→ 形成单目标值式投影
```

同类任务查询锚点创建后不可替换。任一关联需求目标与既有任务目标不一致时拒绝关联；不得在原任务内替换目标语义。

## 5. 任务虚拟存在

### 5.1 定位

每个任务必须独占一个任务虚拟存在。

固定：

```text
任务 T
→ 唯一任务虚拟存在 Vt
```

任务虚拟存在：

```text
不是世界 L2存在
不进入世界树
不取得现实存在资格
不与其它任务共享
```

不同任务即使：

```text
对应同类目标
使用相同方法
来源于同一根需求
```

也不得共享任务虚拟存在。

### 5.2 状态唯一权威宿主

任务虚拟存在 Vt 是任务特征、运行状态和状态迁移记录的唯一宿主；这些记录属于 ARCH-L4 任务治理事实，由任务域经正式入口写入、换代和读回。Vt 不是世界 `L2存在身份`，不进入世界树，也不得另建 `T→E` 或并列任务状态权威。世界特征、状态和动态仍由 ARCH-L2 通用服务承载，二者不得互相冒充。

至少包括：

```text
当前阶段 / 业务状态段
筹办轮次
筹办占用 / 当前性
候选形成状态
可达路径形成状态
当前选择状态
实例方法状态
等待状态
输入闭合状态
条件状态
执行冻结状态
执行轮次
执行状态
实际结果状态
目标达成状态
验证状态
归因状态
重新筹办状态
完成状态
失败状态
取消状态
```

精确特征和值域由 5200、5210、5230 及后继规范冻结。

### 5.3 生命周期不是单一业务状态

任务结构生命周期只表示：

```text
结构创建
当前存在
结构退出
历史可读
```

不等同于：

```text
筹办中
执行中
已完成
失败
取消
```

同一个生命周期阶段可以存在不同业务状态段。

不得用一个生命周期枚举代替完整任务状态体系。

### 5.4 任务轮次、筹办轮次和执行轮次分账

任务的正常活动单元是`任务轮次`。每个任务轮次固定组织：

```text
筹办阶段
-> 执行阶段
-> 结算阶段
-> 轮次已收束
-> 等待自我后继决议
```

任务轮次、筹办轮次和执行轮次是三个不同身份：

```text
任务轮次
    = 一次从筹办到结算收束的完整业务活动

筹办轮次
    = 任务轮次筹办阶段的一组状态驱动信息补全过程；其中可以包含多次找方法和多次查条件调用，选择与冻结另属后续执行前选择

执行轮次
    = 任务轮次执行阶段内对一个实例方法的一次不可变执行身份
```

同一任务轮次至多建立一个执行轮次。每个已经开始的执行轮次在实际结果或具名非成功收口后必须恰好形成一个绑定该执行轮次的任务轮次结算结果，同一执行轮次不得第二次结算；没有执行轮次的合法零动作短路仍形成该任务轮次自己的唯一结算结果。

同一未收束任务轮次可以因等待解除、冻结前事实漂移或冻结失效而形成新的筹办轮次；旧筹办轮次必须保留。任务一旦形成正式实际结果，就进入结算阶段，不得由“目标未达成”自动开启新任务轮次或下一筹办轮次。

轮次已收束后任务停止自行推进。自我后继决议只能是`继续 / 结束 / 等待 / 取消`之一：继续由任务管理建立新任务轮次并重新进入筹办；结束使任务生命周期正式结束；等待保持停驻；取消进入取消收口。后继决议属于内部治理，不是现实执行授权。

## 6. 普通任务、学习任务与内部治理分账

### 6.1 统一任务结构

普通任务和学习任务复用同一任务结构：

```text
任务身份
需求列表项
任务虚拟存在
方法路径
实例方法
任务轮次
筹办轮次
执行轮次
正式结果
任务轮次结算结果
自我后继决议
```

不得建立：

```text
学习任务节点族
学习任务 owner
学习任务状态机
学习专用任务树
```

任务性质由所承接需求的目标语义和后继合同裁决，不得仅靠名称、文本标签或裸枚举成立。

### 6.2 普通任务

普通任务的目标是：

```text
使外在对象状态
或现实世界在自我内部的正式投影状态
达到目标状态
```

普通任务形成的正式现实结果只能成为需求当前满足、验证、归因和适用主动安全结算的来源材料；普通服务结果不形成服务合同账或服务值结算。

### 6.3 学习任务

学习任务的目标是：

```text
使自我内部某项能力达到可用、完整、稳定或指定范围
```

学习任务可以组织：

```text
尝试
因果反推
专门练习
观察与验证
方法候选形成
```

学习任务结果进入：

```text
学习材料
方法候选
方法补齐候选
方法代际治理
```

学习任务不直接：

```text
改变安全值
改变服务值
证明现实目标已改变
形成普通任务价值结算
```

### 6.4 内部治理不是任务类型

内部治理负责：

```text
读取事实
接收父需求任务材料并形成必要子目标承接记录
任务筹办
输入分类
方法匹配
结果复核
状态推进
结算编排
```

这些动作不因具有治理目标而建立任务。

内部治理可以产生被动状态和被动动态，但不直接改变现实目标状态，也不直接结算安全值或服务值。

## 7. 任务事实来源与当前性

任务当前治理事实只能来自：

```text
任务领域固定治理事实
当前任务来源需求关系及逐项当前需求
关联需求当前性 / 权重 / 预算 / 路径
当前目标三元组
当前世界事实
当前有效任务方法路径
当前实例方法正式冻结
方法运行形成并经任务领域收束的结果证据
正式验证 / 归因材料
```

任务不得临时发明无来源业务特征。

已经由以下结构承载的事实，不得再复制成第二套权威普通特征：

```text
任务节点
正式关系
任务虚拟存在
路径结构
实例方法
任务实际结果结构
```

所有关键运行材料必须具有：

```text
来源
版本
当前性
事实截止
生命周期
```

## 8. 方法路径、当前选择与实例方法

### 8.1 三层手段结构

任务手段必须分成：

```text
候选方法
↓
任务方法路径
↓
当前选中路径 / 当前实例方法
```

三层不得混为一个字段。

### 8.2 候选方法

候选方法只表示：

```text
根据任务目标和方法静态能力合同召回到的可能能力
```

候选不证明：

```text
条件成立
输入闭合
参数可绑定
当前可执行
当前被选中
```

### 8.3 任务方法路径

一个任务允许：

```text
0..N 条当前任务方法路径
```

路径是：

> 在执行前选择成功时，基于某一筹办发现、fresh 当前事实和当前关联需求单目标投影形成的一条具体已选方案。

每条路径至少应能回到：

```text
任务
筹办轮次
来源方法
来源方法内容版本
条件绑定
输入绑定
参数绑定
动作入口
预期结果
验证合同
归因合同
路径当前性
生命周期
```

如为组合方法，还应能够回读：

```text
子方法组成
步骤顺序
终止条件
```

普通确定步骤仍属于路径 / 实例方法内部，不自动形成需求。

### 8.4 可达不等于选中

严格分账：

```text
候选
≠
可达

可达
≠
当前选中

当前选中
≠
已经执行

已经执行
≠
任务轮次结算完成
```

DATA-L2结构服务不得自动：

```text
评分
排序
选第一条
按名称选择
认为最新路径最好
```

### 8.5 当前选择和实例方法

任务当前允许：

```text
当前选中路径 = 0..1
当前实例方法 = 0..1
```

合法空可能表示：

```text
尚未达到`待执行前选择`
没有可达路径
等待条件
需要重新筹办
尚未形成执行冻结
```

合法空不自动等于任务失败。

一次执行只能：

```text
选择 1 条当前路径
→ 形成 1 个当前实例方法
→ 建立本轮执行冻结
→ 执行
```

不得多路径同时执行同一任务的一轮实例。

实例方法是不可变执行快照，至少必须能够回到：

```text
所属任务
来源任务方法路径
来源方法
方法内容版本
筹办轮次
执行轮次
冻结输入
冻结参数
冻结条件
动作入口
预期结果
验证合同
归因合同
实例生命周期
```

新任务轮次重新筹办后，即使执行前选择再次采用同一长期方法，也必须形成新轮次的路径和实例历史，不覆盖旧实例。

## 9. 任务筹办

### 9.1 定位

任务筹办是任务领域内建治理行为。

它不：

```text
进入普通方法召回
创建为解决自身的子任务
建立独立第二任务树
用一个“筹办回执节点”替代正式结构结果
```

### 9.2 每轮权威重读

每一轮筹办必须权威读取：

```text
任务
同类任务查询锚点
当前任务来源需求关系组
已关联需求路径
已关联需求权重
已关联需求预算
已关联需求当前性
从至少一项当前关联需求形成的单目标投影
当前世界事实
候选方法
当前任务虚拟存在状态
当前事实版本
```

筹办不能沿用已经失效的上一轮缓存冒充当前事实。

### 9.3 特征召回、兼容判断与方法自身条件

普通可任务化原子目标先以需求目标三元组中的目标特征定义执行有界方法用途粗召回。粗召回回答“哪些当前方法声明能够影响该类型特征”，不要求任务预先形成方法输入条件、输入规格或限制条件，也不证明方法适用、就绪或可执行。

找方法阶段只按正式方法能力索引形成候选方法身份、内容版本和覆盖范围，不判断适用性或当前可用性。方法范围完整且有候选后，查条件阶段逐候选读取其全部条件组并核验当前具备性；任何候选或条件组尚未覆盖时都不得提前进入执行前选择。

目标当前是否已经命中目标状态合同，由任务目标比较或轮次结算链独立裁决，不是筹办结果。对象 / 方向 / 结果适用性、方法版本、动作入口、输入参数、禁止项、验证归因、作用范围、现实副作用、安全硬门和总代价统一在执行前选择中 fresh 复核。

### 9.4 每次筹办调用结果

每次筹办调用必须恰好形成一个与调用前任务状态一致的具名结果，并通过强类型筹办结果消息发送给任务管理线程。任务管理线程不得在自己的线程循环内直接调用筹办 provider 并同步消费返回值。

筹办结果消息是一次跨线程不可变交接，不是新的持久化业务账。消息至少绑定任务、任务轮次、筹办轮次、来源工作包、调用前状态、任务信息预期 / 结果版本、来源 / 结果截止、已覆盖 / 剩余范围和结果分支；任务管理线程必须按消息定位独立读回 task owner 当前信息并校验后，才经任务状态正式入口推进。

找方法与查条件各自只能形成以下阶段性信息补全结果：

```text
继续找方法 / 方法查找完整且有候选 / 方法缺失
继续查条件 / 条件核验完整且至少一组具备 / 条件缺失
```

方法 / 条件缺失只作当前任务材料。技术失败不属于这些业务结果：资源 / 投递 / 发布未知保持原业务状态并按原键收敛；截止漂移使本次结果失效并在同一子状态重派；ABI、引用、断言和内部代码错误停止受影响调用。

### 9.5 状态驱动筹办—执行前选择合同

本小节替代第 10、12、13 节中把适用性、正式采用、子目标承接或执行冻结归入筹办的旧文字。

筹办由任务当前状态驱动并可多次调用。`待找方法 / 继续找方法`只在明确范围内查找方法并累计覆盖；完整覆盖且有候选后，`待查条件 / 继续查条件`才逐个读取候选方法各自条件组并核验当前是否具备。方法查找未完成不得查条件，条件核验未覆盖全部候选不得进入执行前选择。

筹办通过 task owner 唯一入口补全当前任务信息和版本；一个工作包完成时只发送一条不可变结果消息，队满只重投同一消息。manager 独立读回并校验后提交状态迁移。消息与读回形成双线确认，但不建立第二候选账、条件账、结果账、线程或 outbox。

manager 不重跑筹办、不选择方法，也不直接写状态；它依据 task owner 已确认的信息，通过正式状态入口把任务推进为继续找方法、待查条件、继续查条件、方法 / 条件缺失或待执行前选择。

self 对方法 / 条件缺失定位 fresh 复核父需求、目标合同和正式材料。仅 self 产生并确认的独立必要目标可以由 task owner 幂等记录并读回为正式任务子目标承接，再由需求 owner 发布或复用子需求；缺失本身不能直接建立需求或子任务。

执行前选择以 fresh 事实截止重新复核全部选项的可用性和安全硬门，再在可比较候选中选择安全值 / 服务值收益与付出、时间和其它正式成本综合代价最小的一项。未知、不可比或并列最优时不选择。选择成功后才形成既有选择记录、当前路径、实例方法和执行冻结；已退出的服务合同 / 余额、队列长度和线程状态不得进入比较。

## 10. 方法与条件信息缺失的统一治理

任务筹办只补齐当前任务所需的候选方法身份、内容版本、各候选方法正式条件组及其当前核验信息。长期方法定义和正式条件关系仍由方法 owner 建立和维护，筹办不得创建、修改或补造方法合同。

方法缺失、方法结构缺失、条件缺失、输入未形成和外部事实未到只能形成具名任务材料，并保留已覆盖 / 剩余范围、合法生产者、重触发条件、当前版本和事实截止。manager 将材料定位给 self，但不得据缺失类型决定等待、学习或建立子需求。

self fresh 读取父需求、目标合同、当前任务材料和世界事实后，独立产生并确认等待、普通后继需求或学习需求。task owner 只记录该确认，需求 owner 只发布或复用；筹办、方法域和 manager 均不得直接形成需求或子任务。

对象、方向、结果适用性、当前可用性、安全硬门和代价比较统一属于执行前选择。多个候选必须在全部条件组核验完成且 manager 已迁移至`待执行前选择`后才可比较；未知、不可比或并列最优时不选择。

```text
取得
拒绝
占用
当前性
闭合
失效
重复请求
```

不得通过普通 bool 或线程局部变量冒充正式执行权。

## 12. 目标分解与子需求

任务不建立持久化任务父子树或父 / 子任务核心字段。

当 self 依据正式任务材料 fresh 产生并确认某个目标独立、必要、父域合法、严格缩小祖先范围且具有明确并最终可判定的自身目标合同时：

```text
任务
→ 当前任务来源需求关系
→ 确定本轮实际来源需求 / 父需求上下文
→ task owner 记录并读回正式任务子目标承接
→ 需求 owner 消费记录
→ 发布或复用合法子需求并挂入对应需求树
→ 子需求进入自己的需求列表项
→ 以具体子需求身份承接或复用自己的任务
→ 若本次确由当前任务轮次调用，则在子任务轮次执行前建立唯一轮次级发起调用事实
```

目标分解只由：

```text
需求树父子关系
+
任务来源需求关系
+
同类任务查询锚点当前任务关系
```

运行期推导。

任务之间的实际调用来源不从上述关系推导，只由 task owner 的轮次级发起调用事实证明。同一子任务轮次最多一条发起调用；根任务轮次允许零条。该事实不表达目标树、永久父子层级或任务所有权。

禁止建立第二套：

```text
父任务 → 子任务
```

权威树。

普通实例方法步骤继续留在方法路径或实例方法内部，不生成子需求。

## 14. 执行与正式结果事实

### 14.1 执行前置

执行至少要求：

```text
当前实例方法存在
执行冻结仍当前
任务虚拟存在允许执行
执行权成立
安全硬否决未命中
```

执行冻结形成后先读取实例方法逐动作作用范围。仅内部治理或纯现实观察的冻结不请求、不等待自我现实执行授权；含至少一个现实改变步骤的冻结，必须在任务进入执行阶段前读回一份当前`自我现实执行授权事实`，因而不得先执行其中的观察前缀或任何其它步骤。该唯一授权同时绑定任务、任务轮次、筹办轮次、执行轮次、冻结、实例方法和现实动作范围，不再分别检查任务授权与方法授权。

安全服务、生存控制态、操作系统 / 设备访问许可和结构写入许可只能形成事实、技术可达性或硬否决，不能代替自我正向授权；自我授权也不能越过硬否决。授权拒绝或等待时任务仍停在筹办阶段的冻结后状态，不得把拒绝写成任务失败。授权绑定事实变化时旧授权失效；冻结自身变化时必须形成新筹办轮次和新冻结。

### 14.2 执行过程

执行过程固定为：

```text
当前实例方法
→ 动作
→ 独立事实回读
→ 动作后当前特征值完整投影与状态 / 动态证据
→ 任务领域正式结果收束
→ 形成任务实际结果身份
→ 进入本任务轮次结算阶段
```

方法返回“成功”只证明方法自身执行合同返回成功，不证明任务目标已经达成。

### 14.3 结果不得被日志替代

任务实际结果必须由正式结果结构和证据关系承载。

不得用：

```text
日志
弹窗
显示文本
函数返回 true
线程退出码
工作线程回执本身
治理消息本身
```

替代正式任务实际结果事实。

普通任务不是学习任务，但普通任务执行已有实例方法时天然产生练习材料。

本轮运行事实至少可以提供：

```text
来源方法与内容版本
实例方法
成立条件
参数
动作入口
场景与上下文
动作后当前特征值完整投影
状态 / 动态证据
目标达成裁决
验证结果
失败或偏差材料
```

这些材料可以由学习旁路只读消费，形成：

```text
稳定性材料
可靠范围材料
条件结果复验材料
新用途候选
参数范围材料
```

固定：

```text
普通任务执行
=
现实目标实现过程
+
已有方法的一次练习样本
```

但不得：

```text
把普通任务改写成学习任务
阻塞普通任务结果治理
反向修改本轮实例方法
直接修改长期方法
因一次成功或失败形成稳定能力结论
```

## 16. 任务目标达成、验证与轮次结算

### 16.1 目标达成裁决

任务目标达成必须由以下材料联合证明：

```text
正式任务实际结果
+ 当前关联需求单目标投影
+ 当前世界事实
+ 正式比较
+ 当前性
```

目标达成只证明：

```text
本轮正式实际结果满足任务目标
```

不自动证明验证合同已经通过。

### 16.2 验证

任务轮次结算前必须执行当前实例方法冻结的验证合同；独立目标比较已经证明目标自然满足且没有执行实例时，使用该短路分支自己的正式验证合同。筹办本身不得产生目标已满足结论。

验证至少互证：

```text
任务
实例方法
执行轮次
任务实际结果
目标达成裁决
验证规则版本
验证证据
共同事实截止
```

### 16.3 任务轮次结算与收束

任务轮次收束至少依次闭合：

```text
正式任务实际结果
目标达成 / 未达成裁决
验证与归因
运行、冻结和授权消费收口
唯一任务轮次结算结果
```

每个 owner 保持自己的唯一写入权。任务轮次结算结果只引用正式任务结果、验证 / 归因和运行收口材料，不复制、代写或汇总成第二权威。价值结算、需求结算和学习后继结果保持独立，不作为本次任务轮次结算与收束前置。任务结果不是容量或分配对象；当前 `T→D` 全成员核算也不是任务轮次收束前置。

轮次收束必须同时具备：

```text
任务轮次结论
实际结果或合法无执行短路结果当前
验证 / 归因收口
任务轮次结算结果已发布并读回
任务运行已停止
当前执行冻结与授权消费已收束
```

任务轮次收束后，按子任务轮次读取 `0..1` 条正式发起调用：零条按根任务收口；一条时返回正式结果并幂等结算该上级调用槽；多条为引用冲突。返回交付失败只重试返回 / 槽结算，不重复现实动作。上级调用槽已返回不等于上级目标满足。

任务轮次结论可以是目标已达成、目标未达成、合法业务失败、取消或其它下位规范冻结的具名结论。目标未达成只是本轮结论，不等于任务失败，也不表示已经决定继续。

不得用方法返回成功、动作已经发生、子需求完成、任一需求满足、日志、线程返回或单独目标比较直接写轮次已收束。`轮次已收束`也不等于任务生命周期永久结束。

## 17. 同任务轮次重新筹办与自我后继决议

### 17.1 同一未收束任务轮次内重新筹办

任务仍在筹办阶段且尚未开始实例执行时，下列事实可以使当前筹办轮次失效并建立同一任务轮次内的新筹办轮次：

```text
当前路径、实例或执行冻结失效
条件、输入、目标或成员当前性变化
子需求 / 等待条件回流
方法新代际可用
现实执行授权绑定事实变化导致冻结必须重建
```

新筹办轮次必须保留旧路径、旧实例、旧冻结、旧裁决和历史授权引用，按状态重新补全方法与条件信息；进入执行前选择后才重新生成路径、选择并冻结。单纯授权拒绝或等待不改变冻结时，只保持等待或重新请求同一冻结的决议，不伪造新筹办轮次。

任务一旦开始执行或已经形成正式实际结果，就不得沿本节自动换路；必须先进入结算阶段并收束本任务轮次。

### 17.2 轮次收束后的自我后继决议

轮次已收束后，任务主阶段固定停驻并等待自我冻结新的事实截止，读取需求目标状态合同、目标涉及的当前特征值完整投影、任务轮次结算结果、整体优先级、安全事实和其它治理事实，形成：

```text
继续
结束
等待
取消
```

任务管理只能验证并执行该决议：

```text
继续 -> 建立新任务轮次，从新的筹办轮次开始
结束 -> 正式结束任务生命周期
等待 -> 保持轮次已收束停驻
取消 -> 进入取消收口
```

目标未达成、验证未通过、需求仍未满足、结果要求换路或新方法可用都只是自我形成后继决议的输入，不能由任务管理自动变成`继续`。自我后继决议是内部治理，不是现实执行授权；新任务轮次不得复用旧实例、旧冻结或旧授权。

## 19. 任务失败与取消

### 19.1 任务失败

任务失败只能表达：

```text
合法业务失败条件已经命中
+
存在正式终止证据
```

内部逻辑错误不得写成任务失败。

以下情况本身不自动等于任务失败：

```text
无候选方法
等待学习需求
等待子需求
等待输入
等待自我现实执行授权（仅冻结含现实改变步骤时）
旧路径失效
需要重新筹办
内部不一致
筹办漏检
```

### 19.2 任务取消

任务取消必须有自我形成的合法取消后继决议或紧急安全停止事实。取消决议属于内部治理，不是现实执行授权。

若任务已经进入动作执行，还必须具有：

```text
动作停止
或
安全停止
或
无法停止的具名证据
```

不得仅改状态枚举就宣称任务已经取消。

## 20. 权重、安全调度配额、压力与结算预算分账

```text
权重
安全因果层投影
预算
当前性
```

这些材料不得丢失成员来源。

任务不得根据：

```text
需求名称
任务名称
任务类型文本
任务自身普通字段
```

自行判断安全层级。

固定分账：

```text
任务调度权重
≠
安全执行优先级配额
≠
压力值
≠
结算预算
≠
实际结算值
```

压力是 DATA 外治理层根据待完成任务、待学习事项和阻塞事项形成的独立优先级材料，不直接改变安全值或服务值，也不写入任务核心作为价值事实。

## 21. 任务结果、需求满足与正式结算

必须严格区分：

```text
任务实际结果
任务目标达成
任务轮次结论与收束
需求当前满足
需求正式结算
价值结算
```

### 21.1 一个状态变化可以被多个需求独立观察

同一任务显式关联的需求必须拥有同一个核心契约。

因此一次状态变化可以使多个当前成员需求的目标自然成立，任务实际结果可以作为这些后继核算的来源线索。

但每个需求必须在自身实际使用时冻结事实截止，fresh 读取目标涉及的当前特征值完整投影并按目标状态合同裁决；不能把多个成员压成一个结算身份，也不能把任务结果、状态记录或动态后状态当作可消费资源或当前值替代物。

### 21.2 任务结算编排只引用各 owner 正式结果

任务领域可以正式形成：

```text
任务实际结果
目标达成裁决
验证材料
任务轮次结论
归因材料
轮次级发起调用、调用返回与调用槽结算引用
```

正式需求结算由需求和结算领域在需求实际调度、筹办或使用时逐需求裁决。任务结算编排不等待全部 `T→D`，不得代替需求 owner 比较目标或发布结论。若本轮有唯一上级发起调用，只向该调用槽返回结果；其它关联或受益任务不在此时结算。

不得：

```text
任务轮次收束 → 自动把全部成员需求结算成功
任务结果 → 建立容量、共用 / 争用或消费分配账
任务成功 → 直接写列表项总结合算结果
方法成功 → 直接写需求正式结算
学习任务轮次结算完成 → 直接写安全值或服务值
```

### 21.3 任务轮次结论不等于需求当前满足

即使任务目标已经达成，每个需求仍必须在自身实际使用时由需求领域读取当前世界事实和目标状态合同并执行正式比较，才能裁决该需求是否满足。

历史任务轮次结论和历史正式结算都不能永久证明当前世界继续满足目标。

## 23. 事务、幂等、当前性与历史

所有下位任务结构合同必须遵守以下根原则：

1. 新任务的任务节点、同类任务查询锚点引用、首条具体需求关系和任务虚拟存在必须同代原子建立；
2. 同一同类任务查询锚点当前至多一个任务；
3. 每任务当前恰一任务虚拟存在；
4. 每任务允许 0..N 条当前方法路径；
5. 当前选中路径为 0..1；
6. 当前实例方法为 0..1；
7. 路径、选择、实例、冻结、结果、裁决、验证、状态换代必须保留历史；
8. 重新筹办不得覆盖前轮；
9. 当前组合读取必须共享共同事实截止；
10. 历史读取必须使用具名历史截止；
11. 同幂等身份 + 同完整请求返回精确重复和首次结果；
12. 同幂等身份 + 不同完整请求返回幂等冲突；
13. 事实代次漂移必须零变化；
14. 资源失败、异常或发布未知只能用原幂等身份和原完整请求收敛；
15. 不得用缓存、日志、线程上下文或默认值补齐坏结构；
16. 任一身份复义、单例关系重复、跨代拼装、发布后读回矛盾属于内部不一致；
17. 任务退出不得隐式删除或改写需求树、需求列表、需求结算历史；
18. 精确重复任务工作结果不得形成第二正式结果、第二治理批次、第二目标裁决或第二生命周期迁移；
19. 任务轮次、筹办轮次和执行轮次不得互相替代；
20. 目标未达成不得自动形成新任务轮次、下一筹办工作包或自我`继续`决议；
21. 自我现实执行授权只绑定一个冻结，不得跨任务轮次、冻结或现实动作范围复用。

## 25. 禁止事项

禁止：

- 把所有有目标的内部治理动作都建立为任务；
- 任务绕过同类任务查询 / 防重锚点重复创建；
- 把列表项当作任务目标、自我现实执行授权或来源需求集合；
- 未收到具体需求承接输入就自动关联列表成员；
- 任务复制所属存在或目标三元组；
- 任务复制当前世界事实；
- 把成员权重和预算压成不可审计单值；
- 从单个需求成员直接猜测唯一任务；
- 建立第二套持久任务父子树；
- 从需求树、`T→D`、查询锚点、队列或线程缓存推导轮次发起调用；
- 同一子任务轮次建立多个发起调用，或把轮次级调用事实解释为永久父子层级；
- 建立第二套学习任务结构；
- 用世界 L2存在身份充当任务虚拟存在；
- 多任务共享一个任务虚拟存在；
- 把候选方法当可达路径；
- 把可达路径当当前选中路径；
- 把当前选中路径当已执行方法；
- 同一执行轮次同时运行多个实例方法；
- 无可达路径时自动创建方法首；
- 无可达路径时建立能力缺口节点；
- 无可达路径时直接写任务失败；
- 无方法时直接选择练习；
- 用方法返回成功直接写任务轮次结算完成；
- 用动作发生直接写任务轮次结算完成；
- 目标达成但未验证时直接写任务轮次结算完成；
- 用子需求完成直接写其它任务的轮次结论；
- 用调用槽已返回直接写上级目标满足，或用历史子任务结果、状态记录、动态后状态替代上级 fresh 当前特征值读回；
- 把任务结果解释为容量，或建立结果共用 / 争用、成员分配优先级、消费分配和剩余扣减；
- 用任一成员满足直接写任务轮次结算完成；
- 用任务轮次结算完成直接写需求当前满足；
- 用任务轮次结算完成直接写需求正式结算；
- 学习任务轮次结算完成直接改变安全值或服务值；
- 把普通任务产生练习材料解释为普通任务已变成学习任务；
- 把多个成员正式结算压成任务级或列表项级不可回溯总结果；
- 把内部逻辑错误写成普通任务失败；
- 把筹办漏检包装成普通需求或学习需求；
- 在旧冻结失效后继续执行；
- 目标未达成后由任务管理自动开启新任务轮次或生成下一筹办工作包；
- 把自我后继决议当现实执行授权，或把安全调度配额 / 控制态当第二正向授权；
- 为同一冻结分别建立任务授权和方法授权；
- 要求内部治理或纯现实观察取得自我现实执行授权；

## 28. 首个任务轮次与 Vt 首态

一个当前具体需求 D 首次形成任务时，业务完成检查点固定为：

```text
任务 T / 唯一任务虚拟存在 Vt / 首个任务轮次 R1
-> Vt 上首态：筹办 / 待初次筹办
-> 首个筹办轮次 P1
-> manager 读回 P1 后迁移到筹办 / 待找方法，并形成对应状态变化
```

需求列表项 L 只负责查询和防重；D 是首条正式 `T→D` 的来源。task owner 必须在同一任务核心写集中建立并保存唯一任务虚拟存在 Vt；Vt 不得跨任务共享，不得转换为世界 `L2存在身份`，也不得另建并列 `T→E`。

Vt 的首态与任务核心同代形成且没有迁移动作历史。P1 只有在 T、Vt、R1、`T→D`和 Vt 首态均已正式读回后才能建立。P1 只绑定首个筹办轮次、幂等重试和恢复材料，不证明筹办是否需要发生，也不伴随独立调用事实。manager 根据首态和 P1 经任务状态正式入口推进到`待找方法`。

任务主阶段 / 业务状态段必须由 Vt 上的 ARCH-L4 任务特征、状态和迁移记录承载。首态与后态绑定同一 Vt；字符串、缓存、日志和任何并列状态字段都不是该状态的当前权威。

## ARCH-L4/ARCH-L2 兼容边界（20260824）

任务、路径、实例、轮次、结果、任务虚拟存在及其任务特征 / 状态 / 迁移记录属于 `ARCH-L4`。Vt 是任务状态唯一宿主，但不是世界存在或世界状态的第二权威；ARCH-L2 通用存在、特征、状态和动态服务仍唯一承载世界结构。任务域不得把 Vt 解释为现实存在，也不得用世界状态反向替代任务状态。
