编号：3200

版本：v0.7
状态：正式根规范 v0.7

直接上级规范：0050。

直接依赖规范：无。

相关边界规范：3100、3300、4250、4260、5110、5160、5200—5250、5300—5340、6150、8100、8200。

## 1. 根定位

任务是由一个需求列表项授权，为使该列表项的确定目标成为事实，而组织方法路径、选择并执行具体实例方法、记录运行状态、收束实际结果并验证目标的一次有稳定身份活动。

任务是需要进行方法筹办、执行、结果回读和目标验证的有目标活动承载单位。

任务不是所有内部处理动作的通用包装。

以下内部治理动作即使具有明确处理目标，也不因此建立任务：

```text
读取事实
治理输入分类
任务筹办编排
候选召回编排
状态比较
结果绑定复核
任务结果收束
任务生命周期推进
需求结算编排
价值结算编排
线程路由与消息处理
```

这些动作属于内部治理或领域服务职责。若把它们再次包装成任务，会形成“为筹办任务再筹办一个任务”的递归。

任务不是：

```text
需求本身
方法本身
世界存在
需求树节点的副本
目标副本
内部治理步骤
日志
显示摘要
永久完成布尔值
正式结算记录
```

任务核心回答：

```text
为什么做？
    → 当前承接的需求列表项及其当前成员需求

做什么？
    → 需求列表项的目标三元组

有哪些办法？
    → 0..N 条任务方法路径

这次用哪条？
    → 当前选中路径 / 当前实例方法

现在进行到哪里？
    → 任务虚拟存在中的运行状态

实际发生了什么？
    → 本轮正式任务实际结果及其证据

目标是否达成？
    → 正式结果与列表项目标三元组的比较和验证

这些结果支撑了哪些需求成员？
    → 本轮冻结的成员需求身份、版本、路径、权重、授权、预算与结算来源
```

---

## 2. 任务核心结构

任务长期核心固定为：

```text
任务身份
需求列表项
任务虚拟存在
结构生命周期
```

其中：

```text
需求列表项
    = 本任务唯一目标入口和当前需求成员入口

任务虚拟存在
    = 本任务运行状态唯一权威宿主
```

任务不复制：

```text
所属存在
目标宿主
目标特征
目标状态合同
当前世界状态
需求成员集合
成员权重
成员授权
成员预算
```

需要这些信息时必须沿正式关系读取：

```text
任务
→ 需求列表项
→ 目标三元组

任务
→ 需求列表项
→ 当前成员需求组
→ 成员路径 / 当前性 / 权重 / 授权 / 预算 / 结算来源
```

任务不直接保存需求树父子关系，也不建立第二套持久化任务树。

---

## 3. 需求列表项承接

### 3.1 一个列表项至多一个当前任务

固定：

```text
一个当前需求列表项
→ 0..1 个当前任务
```

同一列表项不得同时存在两个当前有效任务。

### 3.2 列表项包含多个需求树成员

一个需求列表项允许：

```text
0..N 个当前需求树成员
```

这些成员拥有完全相同的需求核心契约，但各自仍保留：

```text
需求身份
父子位置
来源
路径
当前性
权重
授权
预算
结算来源
正式结算身份
```

任务不得把这些成员压成一条失去来源的汇总事实。

### 3.3 任务不维护第二份来源需求集合

任务当前来源需求集合固定通过：

```text
任务
→ 需求列表项
→ 当前成员需求组
```

动态读取。

任务结构不得再持久化一份可以独立变化的“来源需求集合”，避免与需求列表成员关系形成第二权威。

### 3.4 本轮消费成员快照

筹办、排队、执行冻结、执行、验证和结果收束必须记录本轮实际消费的成员需求材料。

至少应能够回到：

```text
成员需求身份
成员版本 / 当前性版本
成员路径
成员权重
成员授权
成员预算
规则版本
共同事实截止
```

这些材料是：

```text
本轮运行冻结 / 审计证据
```

不是任务长期核心成员集合。

成员之后新增、退出、失活、权重变化或授权变化，不得反写并篡改历史冻结。

---

## 4. 任务目标

任务需要达成的目标固定为需求列表项的目标三元组：

```text
目标宿主
+ 目标特征
+ 目标状态合同
```

所属存在通过列表项和成员需求读取，用于需求所有权、授权、权重、预算和来源上下文，不属于目标状态比较输入。

任务结构不得重新保存第二份：

```text
所属存在
目标宿主
目标特征
目标状态合同
```

需要目标时必须：

```text
任务
→ 需求列表项
→ 目标三元组
```

列表项核心契约发生身份变化时，不允许在原任务内偷偷替换目标语义；应遵守需求列表项和任务结构的正式生命周期、退出和重新承接规则。

---

## 5. 任务虚拟存在

### 5.1 定位

每个任务必须独占一个任务虚拟存在。

固定：

```text
任务 T
→ 唯一任务虚拟存在 Vt
```

任务虚拟存在：

```text
不是世界 L2存在
不进入世界树
不取得现实存在资格
不与其它任务共享
```

不同任务即使：

```text
对应同类目标
使用相同方法
来源于同一根需求
```

也不得共享任务虚拟存在。

### 5.2 状态唯一权威宿主

任务运行状态统一由任务 owner 的强类型任务治理特征、状态和动态记录表达，并由任务虚拟存在承载。

不得复用世界：

```text
L2存在身份
L2状态身份
L2动态身份
```

冒充任务治理事实。

至少包括：

```text
当前阶段 / 业务状态段
筹办轮次
筹办占用 / 当前性
候选形成状态
可达路径形成状态
当前选择状态
实例方法状态
等待状态
输入闭合状态
条件状态
执行冻结状态
执行轮次
执行状态
实际结果状态
目标达成状态
验证状态
归因状态
重新筹办状态
完成状态
失败状态
取消状态
```

精确特征和值域由 5200、5210、5230 及后继规范冻结。

### 5.3 生命周期不是单一业务状态

任务结构生命周期只表示：

```text
结构创建
当前存在
结构退出
历史可读
```

不等同于：

```text
筹办中
执行中
已完成
失败
取消
```

同一个生命周期阶段可以存在不同业务状态段。

不得用一个生命周期枚举代替完整任务状态体系。

## 6. 普通任务、学习任务与内部治理分账

### 6.1 统一任务结构

普通任务和学习任务复用同一任务结构：

```text
任务身份
需求列表项
任务虚拟存在
方法路径
实例方法
执行轮次
正式结果
目标达成与验证
```

不得建立：

```text
学习任务节点族
学习任务 owner
学习任务状态机
学习专用任务树
```

任务性质由所承接需求的目标语义和后继合同裁决，不得仅靠名称、文本标签或裸枚举成立。

### 6.2 普通任务

普通任务的目标是：

```text
使外在对象状态
或现实世界在自我内部的正式投影状态
达到目标状态
```

普通任务形成的正式现实结果，在需求满足、服务成功、归因和预算全部通过后，才可能进入安全值或服务值结算。

### 6.3 学习任务

学习任务的目标是：

```text
使自我内部某项能力达到可用、完整、稳定或指定范围
```

学习任务可以组织：

```text
尝试
因果反推
专门练习
观察与验证
方法候选形成
```

学习任务结果进入：

```text
学习材料
方法候选
方法补齐候选
方法代际治理
```

学习任务不直接：

```text
改变安全值
改变服务值
证明现实目标已改变
形成普通任务价值结算
```

### 6.4 内部治理不是任务类型

内部治理负责：

```text
读取事实
形成需求候选
任务筹办
输入分类
方法匹配
结果复核
状态推进
结算编排
```

这些动作不因具有治理目标而建立任务。

内部治理可以产生被动状态和被动动态，但不直接改变现实目标状态，也不直接结算安全值或服务值。

## 7. 任务事实来源与当前性

任务当前治理事实只能来自：

```text
任务领域固定治理事实
需求列表项及其当前成员需求
成员当前授权 / 权重 / 预算 / 路径
当前目标三元组
当前世界事实
当前有效任务方法路径
当前实例方法正式冻结
方法运行形成并经任务领域收束的结果证据
正式验证 / 归因材料
```

任务不得临时发明无来源业务特征。

已经由以下结构承载的事实，不得再复制成第二套权威普通特征：

```text
任务节点
正式关系
任务虚拟存在
路径结构
实例方法
任务实际结果结构
```

所有关键运行材料必须具有：

```text
来源
版本
当前性
事实截止
生命周期
```

## 8. 方法路径、当前选择与实例方法

### 8.1 三层手段结构

任务手段必须分成：

```text
候选方法
↓
任务方法路径
↓
当前选中路径 / 当前实例方法
```

三层不得混为一个字段。

### 8.2 候选方法

候选方法只表示：

```text
根据任务目标和方法静态能力合同召回到的可能能力
```

候选不证明：

```text
条件成立
输入闭合
参数可绑定
当前可执行
当前被选中
```

### 8.3 任务方法路径

一个任务允许：

```text
0..N 条当前任务方法路径
```

路径是：

> 在某一筹办轮次和当前事实条件下，为达成当前列表项目标而形成的一条具体可达方案。

每条路径至少应能回到：

```text
任务
筹办轮次
来源方法
来源方法内容版本
条件绑定
输入绑定
参数绑定
动作入口
预期结果
验证合同
归因合同
路径当前性
生命周期
```

如为组合方法，还应能够回读：

```text
子方法组成
步骤顺序
终止条件
```

普通确定步骤仍属于路径 / 实例方法内部，不自动形成需求。

### 8.4 可达不等于选中

严格分账：

```text
候选
≠
可达

可达
≠
当前选中

当前选中
≠
已经执行

已经执行
≠
任务完成
```

DATA-L2结构服务不得自动：

```text
评分
排序
选第一条
按名称选择
认为最新路径最好
```

### 8.5 当前选择和实例方法

任务当前允许：

```text
当前选中路径 = 0..1
当前实例方法 = 0..1
```

合法空可能表示：

```text
尚未筹办完成
没有可达路径
等待条件
需要重新筹办
尚未形成执行冻结
```

合法空不自动等于任务失败。

一次执行只能：

```text
选择 1 条当前路径
→ 形成 1 个当前实例方法
→ 建立本轮执行冻结
→ 执行
```

不得多路径同时执行同一任务的一轮实例。

实例方法是不可变执行快照，至少必须能够回到：

```text
所属任务
来源任务方法路径
来源方法
方法内容版本
筹办轮次
执行轮次
冻结输入
冻结参数
冻结条件
动作入口
预期结果
验证合同
归因合同
实例生命周期
```

重新筹办即使再次选择同一长期方法，也必须形成新轮次的路径和实例历史，不覆盖旧实例。

## 9. 任务筹办

### 9.1 定位

任务筹办是任务领域内建治理行为。

它不：

```text
进入普通方法召回
创建为解决自身的子任务
建立独立第二任务树
用一个“筹办回执节点”替代正式结构结果
```

### 9.2 每轮权威重读

每一轮筹办必须权威读取：

```text
任务
需求列表项
当前成员需求集合
成员路径
成员权重
成员授权
成员预算
成员当前性
列表项目标三元组
当前世界事实
候选方法
当前任务虚拟存在状态
当前事实版本
```

筹办不能沿用已经失效的上一轮缓存冒充当前事实。

### 9.3 特征召回、兼容判断与方法自身条件

普通可任务化原子目标先以需求目标三元组中的目标特征定义执行有界方法用途粗召回。粗召回回答“哪些当前方法声明能够影响该类型特征”，不要求任务预先形成方法输入条件、输入规格或限制条件，也不证明方法适用、就绪或可执行。

粗召回后按同一事实截止依次执行：

```text
目标宿主当前支持的全部合法存在概念
+ 当前值与目标状态合同正式比较形成的所需变化方向
+ 方法结果能力与目标状态合同的兼容性
→ 适用候选

适用候选
→ 读取候选方法自己的条件、输入规格、限制条件和条件结果关系
→ 评估条件是否已满足、可满足或缺少绑定
→ 只对本轮实际采用的一份方法方案形成缺失条件草案或合法等待
```

目标当前已经命中目标状态合同允许关系时直接形成`目标已完成`，不得继续召回。当前值与目标值必须使用目标状态合同绑定的正式比较注册在同一事实截止比较；不得由目标值、名称或默认方向推断。

一个目标宿主没有当前概念支持且适用性判断需要对象类型时形成合法等待，不猜默认概念。存在多个当前支持概念时保留全部合法兼容候选；不得按遍历顺序或稳定编码任选、合并成一个概念。稳定顺序只消除输出不确定性，不表达能力优劣。

方法六项静态能力投影继续作为方法自身的完整描述、结构缺口和后继就绪 / 学习证据；任务不得镜像一份六项查找请求，也不得把任务未知的输入条件或限制条件与方法投影逐项相等后才准入。

进入适用候选后仍必须复判：

```text
方法当前版本
动作入口
条件结果关系
输入
参数
禁止项
验证合同
归因合同
授权
当前性
```

### 9.4 筹办闭合结果

筹办只能形成具名闭合结果：

```text
可执行冻结
子目标承接
学习需求承接
方法补齐承接
合法等待
目标已完成
授权失效或取消
内部错误 / 入口拒绝 / 资源失败等结构化非成功
```

不得返回无结构“无法解决，退回上层”。

## 10. 无方法、方法补齐与等待分流

### 10.1 无当前适用方法

```text
按目标特征定义完成有界粗召回且没有方法用途
→ 方法能力缺失
+
不存在应先形成的独立子目标
+
不存在预算不足、当前性漂移、目标当前事实待形成、对象概念待形成、
方法结构待补齐、多候选待选择证据或只需等待的当前事实
→ 学习需求承接
```

若上述正式学习门禁任一项不满足，`方法能力缺失`只作为本轮具名判断材料并形成合法等待，不得直接升级为学习需求承接。

```text
粗召回非空且对象 / 方向 / 结果适用判断完整结束、全部项均不适用
→ 当前无适用方法
→ 保留完整粗召回与逐候选不兼容证据
→ 合法等待
```

`当前无适用方法`不得进入学习需求承接。

学习需求承接必须包含：

```text
目标宿主、目标特征和目标状态合同
当前比较关系与所需变化方向
方法能力缺失分支的完整空粗召回扫描证据
来源任务和事实截止
合法学习需求生产者
```

`方法能力缺失`不得包含粗召回非空分支；`当前无适用方法`不得丢弃粗召回项和不兼容原因，也不得进入学习需求承接。二者均不得建立长期能力缺口节点。

### 10.2 已有候选但结构不完整

已有特征粗召回项或适用候选，但存在：

```text
动作入口缺失
条件结果关系缺失
输入或参数未绑定
禁止项或规格缺失
验证或归因合同缺失
```

时形成：

```text
方法补齐承接
```

不得伪装成“完全没有方法”。

任务取得候选前不预造方法输入条件或限制条件。条件草案只能来自本轮实际采用方法与其目标结果具有正式条件结果关系的条件；草案交需求统一入口，任务筹办不得直接写需求树。条件回流后必须重新读取方法内容版本、目标当前事实和授权并开启新筹办轮次，不得沿用旧候选、旧条件判断或旧就绪结论。

多个适用候选只有在存在正式可比较选择证据时才能采用一份方案。当前就绪且可直接达成目标的方法优先；第一阶段尚未取得该证据时形成带完整候选组的合法等待，不为互斥候选同时提出条件草案。稳定编码只用于稳定输出，禁止作为能力优劣或选择理由。

### 10.3 当前条件或事实暂时不成立

以下情况形成合法等待或独立子目标候选：

```text
条件事实暂时未满足
输入尚未形成
授权尚未取得
外部事实尚未产生
时间条件尚未到达
```

等待必须携带：

```text
等待对象
合法生产者
重新触发条件
当前版本
事实截止
```

### 10.4 禁止分流

禁止：

```text
无方法时自动建立方法首
无方法时直接写任务失败
无方法时直接选择练习
把结构缺口包装成普通条件等待
把筹办漏检包装成新需求
```

---

## 11. 筹办并发与执行权

筹办并发隔离键固定为：

```text
任务稳定身份
```

同一任务同一时刻最多一个有效筹办执行权。

不同任务允许并发筹办。

筹办执行权必须能够区分：

```text
取得
拒绝
占用
当前性
闭合
失效
重复请求
```

不得通过普通 bool 或线程局部变量冒充正式执行权。

执行权、冻结和队列锚点的精确数据合同由 5230 等下位规范冻结。

---

## 12. 目标分解与子需求

任务不建立持久化任务父子关系。

当任务发现必须独立达成的子目标时：

```text
任务
→ 当前需求列表项
→ 确定本轮实际来源成员 / 父需求上下文
→ 形成独立子目标候选
→ 提交需求业务
→ 合法时挂入对应需求树
→ 子需求进入自己的需求列表项
→ 该列表项取得自己的任务
```

任务层级由：

```text
需求树父子关系
+
需求列表成员关系
+
列表项当前任务关系
```

运行期推导。

禁止建立第二套：

```text
父任务 → 子任务
```

权威树。

普通实例方法步骤继续留在方法路径或实例方法内部，不生成子需求。

---

## 13. 执行冻结

执行只能使用当前有效执行冻结。

执行冻结至少必须证明本轮：

```text
任务
需求列表项
本轮消费成员需求及版本
当前选中路径
当前实例方法
方法内容版本
输入
参数
条件
授权
当前性
执行轮次
目标版本
必要世界事实截止
验证合同
归因合同
```

仍然匹配。

冻结后若以下材料发生导致合同失效的变化：

```text
方法代际
路径
授权
条件
输入
参数
目标
关键世界事实
成员当前性
```

则旧冻结失效，任务进入等待或重新筹办，不得拿旧冻结继续执行。

---

## 14. 执行与正式结果事实

### 14.1 执行前置

执行至少要求：

```text
当前实例方法存在
执行冻结仍当前
任务虚拟存在允许执行
执行权成立
必要授权仍有效
```

### 14.2 执行过程

执行过程固定为：

```text
当前实例方法
→ 动作
→ 独立事实回读
→ 实际状态与动态证据
→ 任务领域正式结果收束
→ 形成任务实际结果身份
→ 进入任务结果治理
```

方法返回“成功”只证明方法自身执行合同返回成功，不证明任务目标已经达成。

### 14.3 结果不得被日志替代

任务实际结果必须由正式结果结构和证据关系承载。

不得用：

```text
日志
弹窗
显示文本
函数返回 true
线程退出码
工作线程回执本身
治理消息本身
```

替代正式任务实际结果事实。

---

## 15. 普通任务的练习旁路

普通任务不是学习任务，但普通任务执行已有实例方法时天然产生练习材料。

本轮运行事实至少可以提供：

```text
来源方法与内容版本
实例方法
成立条件
参数
动作入口
场景与上下文
实际状态
动态证据
目标达成裁决
验证结果
失败或偏差材料
```

这些材料可以由学习旁路只读消费，形成：

```text
稳定性材料
可靠范围材料
条件结果复验材料
新用途候选
参数范围材料
```

固定：

```text
普通任务执行
=
现实目标实现过程
+
已有方法的一次练习样本
```

但不得：

```text
把普通任务改写成学习任务
阻塞普通任务结果治理
反向修改本轮实例方法
直接修改长期方法
因一次成功或失败形成稳定能力结论
```

---

## 16. 任务目标达成、验证与完成

### 16.1 目标达成裁决

任务目标达成必须由以下材料联合证明：

```text
正式任务实际结果
+ 需求列表项目标三元组
+ 当前世界事实
+ 正式比较
+ 当前性
```

目标达成只证明：

```text
本轮正式实际结果满足任务目标
```

不自动证明验证合同已经通过。

### 16.2 验证

任务完成前必须执行当前实例方法冻结的验证合同。

验证至少互证：

```text
任务
实例方法
执行轮次
任务实际结果
目标达成裁决
验证规则版本
验证证据
共同事实截止
```

### 16.3 任务完成

任务完成必须同时具备：

```text
目标达成
验证通过
实际结果当前
完成来源
完成版本
任务运行已停止
当前执行冻结已收束
```

不得用以下任一单项直接写任务完成：

```text
方法返回成功
动作已经发生
子需求已完成
任一成员需求当前满足
日志显示成功
执行线程正常返回
仅有目标达成而尚未验证
```

任务完成是任务活动的运行结论，不是需求永久满足，也不是需求正式结算。

---

## 17. 重新筹办

合法触发至少包括：

```text
当前路径失效
当前实例方法失效
执行冻结失效
条件变化
输入变化
授权变化
成员当前性变化
子需求回流
目标未达成
验证未通过但允许换路
执行结果要求换路
方法新代际可用
```

重新筹办必须：

```text
保留旧筹办轮次
保留旧路径历史
保留旧实例历史
保留旧冻结
保留旧结果
保留旧裁决和验证
形成新筹办轮次
重新读取当前事实
重新生成路径集合
重新选择
```

不得覆盖上一轮历史。

目标未达成应进入：

```text
目标未达成待重筹办
```

不得直接写成任务失败。

## 18. 筹办漏检与内部逻辑错误

若执行期才发现冻结前已经存在且本应在筹办阶段发现的：

```text
方法缺失
动作入口缺失
规格缺失
目标缺失
授权缺失
输入缺失
条件缺失
任务结构缺失
当前性错误
```

则属于：

```text
筹办漏检
或
内部逻辑错误
```

不得伪装成：

```text
普通需求
普通等待
合法任务失败
方法业务失败
学习需求
```

具体缺口分类和分流由 5230、5250、5150 等规范冻结。

---

## 19. 任务失败与取消

### 19.1 任务失败

任务失败只能表达：

```text
合法业务失败条件已经命中
+
存在正式终止证据
```

内部逻辑错误不得写成任务失败。

以下情况本身不自动等于任务失败：

```text
无候选方法
等待学习需求
等待子需求
等待输入
等待授权
旧路径失效
需要重新筹办
内部不一致
筹办漏检
```

### 19.2 任务取消

任务取消必须有合法取消授权。

若任务已经进入动作执行，还必须具有：

```text
动作停止
或
安全停止
或
无法停止的具名证据
```

不得仅改状态枚举就宣称任务已经取消。

---

## 20. 权重、安全权限、压力与结算预算分账

任务通过需求列表项读取成员的：

```text
权重
授权
安全因果层投影
预算
当前性
```

这些材料不得丢失成员来源。

任务不得根据：

```text
需求名称
任务名称
任务类型文本
任务自身普通字段
```

自行判断安全层级。

固定分账：

```text
任务调度权重
≠
安全执行优先级权限
≠
压力值
≠
结算预算
≠
实际结算值
```

压力是 DATA 外治理层根据待完成任务、待学习事项和阻塞事项形成的独立优先级材料，不直接改变安全值或服务值，也不写入任务核心作为价值事实。

---

## 21. 任务结果、需求满足与正式结算

必须严格区分：

```text
任务实际结果
任务目标达成
任务完成
需求当前满足
需求正式结算
价值结算
```

### 21.1 一个任务结果可以支撑多个成员

同一需求列表项中的成员拥有同一个核心契约。

因此一次任务实际结果和一次当前世界事实验证可以作为多个当前成员需求的共同证据来源。

但它不能把多个成员压成一个结算身份。

### 21.2 任务只产生结算支撑材料

任务领域可以正式形成：

```text
任务实际结果
目标达成裁决
验证材料
任务完成事实
归因材料
本轮消费成员快照
结算候选 / 结算支撑证据
```

正式需求结算由需求和结算领域裁决。

不得：

```text
任务完成 → 自动把全部成员需求结算成功
任务成功 → 直接写列表项总结合算结果
方法成功 → 直接写需求正式结算
学习任务完成 → 直接写安全值或服务值
```

### 21.3 任务完成不等于需求当前满足

即使任务已经完成，仍必须由需求领域读取当前世界事实、目标状态合同并执行正式比较，才能裁决需求当前是否满足。

历史任务完成和历史正式结算都不能永久证明当前世界继续满足目标。

```text

当前路径选择
实例化
任务虚拟存在状态迁移
筹办执行权
执行冻结
实际结果收束
目标达成
验证
归因
重新筹办
完成
失败
取消
结算候选 / 支撑材料
结构退出
```

以下主体只能提交合法输入、候选或证据，不得直接改写任务结构：

```text
需求
方法
学习
线程
调度器
外设
观察中间层
显示层
外部调用方
```

自我线程只负责编排和冻结值式治理材料，不得裸写任务状态。

L2任务结构服务只执行已经裁决后的强类型结构操作，不负责业务判断。

## 23. 事务、幂等、当前性与历史

所有下位任务结构合同必须遵守以下根原则：

1. 任务节点、需求列表项引用、任务虚拟存在必须同代原子建立；
2. 同一列表项当前至多一个任务；
3. 每任务当前恰一任务虚拟存在；
4. 每任务允许 0..N 条当前方法路径；
5. 当前选中路径为 0..1；
6. 当前实例方法为 0..1；
7. 路径、选择、实例、冻结、结果、裁决、验证、状态换代必须保留历史；
8. 重新筹办不得覆盖前轮；
9. 当前组合读取必须共享共同事实截止；
10. 历史读取必须使用具名历史截止；
11. 同幂等身份 + 同完整请求返回精确重复和首次结果；
12. 同幂等身份 + 不同完整请求返回幂等冲突；
13. 事实代次漂移必须零变化；
14. 资源失败、异常或发布未知只能用原幂等身份和原完整请求收敛；
15. 不得用缓存、日志、线程上下文或默认值补齐坏结构；
16. 任一身份复义、单例关系重复、跨代拼装、发布后读回矛盾属于内部不一致；
17. 任务退出不得隐式删除或改写需求树、需求列表、需求结算历史；
18. 精确重复任务工作结果不得形成第二正式结果、第二治理批次、第二目标裁决或第二生命周期迁移。

## 25. 禁止事项

禁止：

- 把所有有目标的内部治理动作都建立为任务；
- 任务直接绑定一个需求树成员后忽略需求列表项；
- 任务维护第二份可变来源需求集合；
- 任务复制所属存在或目标三元组；
- 任务复制当前世界事实；
- 把成员权重、授权、预算压成不可审计单值；
- 从单个需求成员直接猜测唯一任务；
- 建立第二套持久任务父子树；
- 建立第二套学习任务结构；
- 用世界 L2存在身份充当任务虚拟存在；
- 多任务共享一个任务虚拟存在；
- 把候选方法当可达路径；
- 把可达路径当当前选中路径；
- 把当前选中路径当已执行方法；
- 同一执行轮次同时运行多个实例方法；
- 无可达路径时自动创建方法首；
- 无可达路径时建立能力缺口节点；
- 无可达路径时直接写任务失败；
- 无方法时直接选择练习；
- 用方法返回成功直接写任务完成；
- 用动作发生直接写任务完成；
- 目标达成但未验证时直接写任务完成；
- 用子需求完成直接写父任务完成；
- 用任一成员满足直接写任务完成；
- 用任务完成直接写需求当前满足；
- 用任务完成直接写需求正式结算；
- 学习任务完成直接改变安全值或服务值；
- 把普通任务产生练习材料解释为普通任务已变成学习任务；
- 把多个成员正式结算压成任务级或列表项级不可回溯总结果；
- 把内部逻辑错误写成普通任务失败；
- 把筹办漏检包装成普通需求或学习需求；
- 在旧冻结失效后继续执行；
- 取消执行中任务时没有动作停止证据；
- L2任务结构服务自动召回、评分、选择方法；
- L2任务结构服务自动生成子需求；
- L2任务结构服务自动判断任务完成；
- 需求、方法、线程、调度器、显示层直接改写任务结构；
- 用名称、文本、日志、缓存、线程状态证明任务身份或业务状态。

## 26. 代码生成根边界

本规范可直接作为任务体系代码生成的根级语义约束，但精确 DTO、关系类型、状态值域和函数签名必须继续服从对应子规范。

代码生成不得恢复旧模型：

```text
任务 → 单个需求
任务自己保存多个来源需求关系作为第二权威
任务目标副本
任务运行场景作为长期目标核心副本
任务治理存在 = 世界 L2存在
持久任务父子树
替换任务目标宿主 / 目标特征 / 目标状态
按单需求读取唯一任务作为主入口
学习任务第二结构
```

不得自行补造：

```text
任务完成 bool
任务失败 bool
任务取消 bool
任务已结算 bool
万能状态 I64
万能方法引用
万能执行权 bool
无来源总权重
无来源总结算
能力缺口节点
```

若下位规范尚未冻结精确 DTO、接口或状态：

```text
不得用万能参数
普通属性槽
自由关系
文本
裸 I64
临时 bool
动态编号
```

提前发布公开 ABI。
