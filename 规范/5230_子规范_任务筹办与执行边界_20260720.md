# 5230 子规范 任务筹办与执行边界

编号：5230
日期：20260901
版本：v2.1
状态：正式子规范

## 1. 定位

本规范定义任务领域内建筹办最小方法、任务级唯一筹办执行权、闭合筹办结果、重复筹办、执行冻结和执行期错误边界。

直接上级规范：3200。

直接依赖规范：3100、3300、4010、4020、5210、5300。

相关边界规范：5210、5240、5250、5340、6140、6150。

## 2. 筹办身份与执行权

1. 任务筹办是内部治理范围内的发现动作，由内部治理在读取需求后触发，不属于外部业务流程，也不作为普通方法进入召回。完整链路：内部治理 → 读取需求目标特征 → 按特征有界粗召回方法 → 对每个方法发现各自条件组与合同定位 → 不可变发现消息；适用性、需求确认、等待、选择和冻结均由后继 owner 处理。
2. 并发隔离键是任务稳定身份。同一任务同一时刻只能有一个有效筹办占用和执行权。
3. 执行权必须由任务结构中的唯一有效占用事实、轮次、版本和当前性裁决，不持久化裸线程编号。
4. 未取得执行权的路径必须在读取方法候选前正常拒绝，不得参与召回或发现消息形成。
5. 两条路径同时进入同一任务召回或发现形成，属于内部并发规则破坏；执行前选择的排他与幂等另按第 6.4 节及 task owner 合同处理。
6. 不同任务可以并发筹办，即使它们来源于同一根需求或选择同一方法。

## 3. 每轮筹办输入

每轮必须权威重读：

```text
任务身份与任务虚拟存在
当前 T→D 来源需求关系组、至少一项当前有效具体需求及互证单目标投影
任务角色与活动路径
本轮实际消费来源的权重与预算输入
活动子需求与等待合同
候选方法、方法内容版本和生命周期
方法条件、结果能力、动作入口和任务特征契约
当前世界状态、输入和禁止项
```

筹办可以重复进行。触发来源、轮次和读取版本必须单调、可追溯；旧冻结在相关事实变化后失效。

### 3.1 进程崩溃与跨重启占用

筹办占用是当前运行代次内的任务治理事实，不是可跨进程继承的线程租约。恢复候选必须保留原任务身份、筹办轮次、占用版本、来源运行代次和历史当前性，但旧运行代次的有效占用不得在新运行期直接恢复为执行权。

恢复过程必须在隔离候选中完成：

```text
重建任务、当前任务轮次、历史筹办轮次和占用记录
-> 证明旧运行代次已经终止且不存在仍可能继续的前轮动作
-> 原子失效旧占用及其旧冻结当前性
-> 发布新的恢复代次和筹办重判触发
-> 在同一尚未收束任务轮次中增加筹办轮次并重新取得唯一筹办执行权
```

不得按墙钟超时、裸进程号、线程号或“重启已经发生”直接删除占用历史，也不得沿用旧轮次继续召回、选择或冻结。若不能证明前轮真实外部动作已经停止或已经完成实际回读，只能形成带动作核验生产者和重新触发条件的合法等待；不得取得新执行冻结或重复发起外部动作。前置通过后出现两个恢复后当前占用、旧运行代次仍可写入或新轮次读回不一致，属于内部并发或恢复逻辑错误。

## 4. 闭合结果

任务管理线程把不可变筹办工作包交给任务工作线程；任务工作线程每次处理结束必须恰好形成一个闭合结果，并通过专用强类型筹办结果消息提交给任务管理线程。任务管理线程不得直接调用筹办提供者并同步消费返回值。复用既有任务工作线程和有界消息队列，不为筹办另建专用线程；筹办结果消息只承担跨线程交接，不建立独立持久化筹办回执、第二结果账、独立“能力缺口”节点或“目标变化材料”节点。

消息必须绑定任务、任务轮次、筹办轮次、来源工作包身份、来源事实截止、结果事实截止和唯一结果分支。任务管理线程消费消息时必须按其正式身份独立读回分支引用，不能把消息载荷、同步返回值、线程快照或队列顺序当作正式业务事实。结果只能是：

| 结果 | 必须同时形成的结构 |
| --- | --- |
| 可执行冻结 | 当前方法、条件与输入绑定、路径、方法版本、验证和归因合同（匹配成功→普通任务执行前冻结） |
| 子目标承接 | 本轮正式采用筹办方案所必需、严格缩小祖先尚未闭合范围、且具有明确并最终可判定自身目标状态合同的完整子目标；同时携带正式任务子目标承接记录、精确 `T→D_parent`、采用来源、合法生产者、等待合同和回流条件。当前可执行路径、实例方法和执行冻结允许为空，不得建立半成品路径 |
| 合法等待 | 等待对象、等待事实生产者、重新触发条件和当前状态 |
| 目标已完成 | 当前目标比较、验证结果及其已发布状态 / 动态 / 因果来源引用 |
| 结构化非成功 | 入口拒绝、当前性漂移、引用或幂等冲突、资源失败、内部错误及其零成功载荷 |

禁止返回无结构“无法解决、退回上层”。特征粗召回完整为空时不得自动创建方法首、不得用通用写入逻辑兜底；先形成`方法能力缺失`判断材料。只有正式学习门禁全部满足且学习目标确为本轮正式采用筹办方案所必需、严格缩小祖先范围并具有明确且最终可判定的自身目标状态合同时，才归入带学习子类的`子目标承接`并形成正式任务子目标承接记录，否则形成合法等待。粗召回非空但适用判断全部不兼容的`当前无适用方法`只形成合法等待。方法补齐同理：满足统一子目标准入时归入带方法补齐子类的`子目标承接`，否则留在当前任务或合法等待。二者均不建立长期能力缺口节点；目标状态解析只形成分析材料，不创建目标变化节点。

### 4.1 C031 筹办消息的当前合同

本小节替代本节表格和后续文字中“五类闭合业务结果”“筹办正式采用方案”的当前资格。每个已消费工作包仍只投递一条不可变强类型消息、队满只重投同一消息、manager 已接收或确认精确重复后该工作包才正常结束；这些工程边界不变。

正常消息分支固定为`筹办发现`：任务、任务 / 筹办轮次、工作包、来源 / 结果截止，及`方法身份 + 内容版本 -> 0..N 条件组`和逐项方法 / 条件 / 结构缺口的正式定位。条件组是值式投影，不是新节点、历史账或任务总条件表。入口拒绝、当前性漂移、引用 / 幂等冲突、资源失败和内部错误仍是结构化非成功。消息不产生目标完成、合法等待、子目标承接、路径、选择或冻结事实。

manager 必须独立读回消息定位的正式材料：发现可构成执行选项时只编排执行前选择工作项；发现有方法 / 条件 / 结构缺口时只向 self 发既有自我治理通道中的强类型定位；其它非成功按其合同收束。manager 不得同步调用 provider、重跑发现、依据队列状态形成等待，或写需求 / 子任务。

## 5. 路径和候选边界

1. 筹办先读取需求目标三元组，以目标状态合同绑定的正式比较注册在同一事实截止比较当前值与目标值；已满足直接形成目标已完成，未满足时形成所需变化方向。不能按名称、标签、默认方向或稳定编码决定任务形态。
2. 逻辑组织、管理和路径节点先执行展开、聚合或路径选择，不直接进入普通方法候选。
3. 普通可任务化原子任务先按目标特征定义有界粗召回方法用途，再以目标宿主全部当前合法概念、所需方向和目标状态结果能力判断适用候选；取得候选后才读取方法自身条件、输入规格、限制和条件结果关系。任务不得镜像方法六项签名或要求输入 / 限制逐项相等。
4. 筹办不直接写需求树、不建立能力缺口节点、不建立目标变化材料节点；只有本轮正式采用筹办方案所必需、严格缩小祖先尚未闭合范围、且具有明确并最终可判定自身目标状态合同的子目标才能形成正式任务子目标承接记录，需求领域统一入口只消费该记录建立或复用子需求。当前可执行路径可以为空；未采用方案和不满足统一门禁的方法补齐等材料保持在当前任务内处理或合法等待。
5. 被动、提交、结算和内部治理动作不进入主动候选集。
6. 缺失条件草案只来自本轮实际采用方法与目标结果正式关联的条件。条件回流后重新读取方法版本与当前事实并开启新筹办轮次，不沿用旧就绪结论。
7. 多候选没有正式可比较选择证据时只形成稳定候选组和合法等待，不为互斥候选同时提出条件；稳定编码不得充当能力优劣。

## 6. 执行冻结

冻结必须绑定任务、任务轮次、筹办轮次、计划执行轮次、方法、方法内容版本、动作入口、方法作用范围、逐动作现实副作用、逐动作直接作用主体、共同作用场景、条件、输入、路径、本轮实际消费的 `T→D` 关系与具体来源需求版本、禁止项、安全限制、验证、归因和失效条件。需求活动资格、安全因果图、安全阈值、调度配额规则、适用性分类规则及其 provider 不进入执行冻结，也不得形成“授权材料缺失等待”。执行冻结本身不包含正向现实执行授权。

完整有序冻结动作范围是执行期动作类别、直接作用主体、共同场景约束和现实副作用声明的唯一生产材料。当前执行中的全部具名作用主体、自我以及目标 / 结果主体在本次采用的观察分辨率下必须由场景 owner 在同一事实截止证明是同一共同场景的当前成员；现实改变动作的非空`作用场景`必须全部等于该共同场景。`作用主体`才是动作直接读取或改变的存在，`作用场景`只表达动作成立的共同上下文，不得把控制室、车间、设备等成员存在改判成多个直接作用场景。需要展开某个成员存在内部时，必须进入与该存在身份分离的内部场景后另行形成任务或执行，不得在一次执行中拼接多个场景层级。

正式任务方法选择记录是当前选择和历史选择的唯一权威。选择记录、关系族、关系角色和属性类型均由任务结构 owner 按 4010 的 owner 私有类型登记合同正式登记；不得依赖固定节点类型号、固定关系类型号、固定角色顺序号或世界状态节点作为公开、持久或跨模块 ABI。选择记录可以引用已存在的状态、动态、因果或必要治理来源事实，但不得为了保存选择理由、归因或同轮隔离而新建证据专用节点、证据关系或第二份业务事实。

每次已发布选择必须形成独立、不可变的任务方法选择记录，并形成下列强类型拓扑：

| 角色 | 源 | 目标 | 基数与边界 |
| --- | --- | --- | --- |
| 当前正式选择 | 任务 | 任务方法选择记录 | 同一任务至多一条当前有效关系；新轮次原子退出旧当前关系并建立新当前关系 |
| 选中方法 | 任务方法选择记录 | 方法 | 每个选择记录恰一；目标是本轮采用方法 |
| 具体任务方法路径 | 任务方法选择记录 | 任务方法路径 | 每个选择记录恰一；路径属于同一任务、同一筹办轮次和同一方法内容版本 |
| 来源需求 | 任务方法选择记录 | 需求 | 至少一项；必须来自任务当前 `T→D` 关系组并属于本轮实际消费集合，按关系身份与需求身份唯一 |
| 选择来源引用（现有 ABI 名称可暂保留“稳定选择证据”） | 任务方法选择记录 | 已经发布的状态、动态、因果或具有独立业务作用的任务 / 需求 / 方法治理事实 | 可为一项或多项；必须回到本任务轮次的筹办触发、等待回流或冻结失效来源；不得指向为证明选择而新建的证据节点；目标未达成与已收束轮次不得冒充新筹办来源；日志、哈希、文本和裸编码不得冒充 |
| 执行绑定冻结材料 | 任务方法选择记录 | 执行绑定冻结材料 | 每个选择记录恰一；完整承载当前就绪、来源需求、方法限制、验证和归因的强类型冻结结果，不得重复进入选择来源引用拓扑 |

`任务 -> 当前选中路径`只是在同一选择发布事务中形成的派生当前投影，不再拥有独立公开生产写入口，不能单独证明业务选择。历史选择路径只由`选择记录 -> 具体任务方法路径`恢复；普通`任务 -> 方法`引用若保留，也只能是可重建派生投影，不能成为第二选择权威。

任务领域类型化选择记录至少保存：记录合同版本、记录格式版本、记录版本、记录状态、强类型筹办来源幂等身份、任务轮次、筹办轮次、选择规则版本、召回规则版本、选中方法内容版本、完整任务身份来源事实，以及方法 owner 公开读回的完整强类型方法生命周期与作用范围事实。筹办来源幂等身份必须以判别联合区分任务轮次初次筹办来源和同一未收束任务轮次内的后继筹办来源，二者不得换算为同一无类型整数后比较。任务身份来源必须包含任务节点和任务族归属关系的结构生命周期见证；方法生命周期必须包含方法身份、生命周期版本、发生时间、来源稳定编码和结构生命周期。不得保存固定关系编号、关系端点拆分值、世界状态身份、普通模板关系、无类型槽或以稳定编码替代强类型身份。

正式选择发布必须由任务结构 owner 的同一公开组合入口在同一事实事务中完成新路径、新选择记录、完整选择拓扑、派生当前路径投影和任务侧当前实例关联。任务轮次初次筹办必须证明本任务轮次尚无选择、路径和实例，筹办轮次为 1；同任务轮次后继筹办必须证明任务仍在筹办阶段、尚未开始执行且旧选择 / 路径 / 实例已经失效或等待条件已回流，再原子退出其当前关系并建立新关系。执行轮次只在任务合法进入执行阶段时建立，不由筹办轮次递增冒充。旧选择记录、旧选择拓扑、旧路径和旧实例保留历史，不得覆盖、重挂或删除。路径 owner facade 不得建立第二存储、第二事务或第二当前选择入口。

任务结构 owner 的公开发布请求只能接收 DATA-L2 自有的规范化筹办来源判别联合和强类型冻结证据，不能直接接收线程工作包或内部治理 DTO。联合只能是以下两种互斥分支：

1. `任务轮次初次筹办来源`：逐项保存任务、任务轮次、来源需求、来源需求关系、同类任务查询锚点、首次目标比较共同事实截止、任务轮次建立事实代次、筹办轮次 1 和运行代次。owner 必须重新证明任务轮次处于筹办阶段，且本任务轮次当前选择、路径、实例均为空。
2. `同任务轮次后继筹办来源`：逐项保存任务、同一任务轮次、旧筹办轮次、旧路径、旧实例、等待回流或冻结失效事实、共同事实截止、新筹办轮次和运行代次。owner 必须证明任务仍处于筹办阶段、实例执行尚未开始且任务轮次尚未收束。正式实际结果、目标未达成结论、轮次已收束状态或自我后继决议不得冒充该来源。

内部治理 provider 只允许按所持来源分支机械映射，任务 owner 在写前以公开事实重新互证。两个分支不得以 optional 字段拼盘、全空旧事实、伪造旧结果或恢复独立当前路径发布入口相互冒充。DATA-L2 任务数据和服务不得反向依赖内部治理模块。

候选数量、索引发布版本、排序过程、完整有序候选元组和召回统计只属于可选审计材料，不单独裁决选择身份、当前性或同义。只有实际参与选择、归因或同轮隔离的既有来源事实才可以被选择记录引用；不得为了让引用“稳定”而生产新证据节点。来源不足时返回合法等待、材料不足或内部缺口，不得把日志、哈希、拆分句柄、无类型数组或新造证据身份塞入选择记录兜底。

现行 ABI 中的 `L2任务目标裁决证据身份`、`L2任务选择稳定证据类别`、`稳定选择证据` 等名称在替代读回合同完成前不得机械删除、重排或改义；兼容保留只允许历史读取和迁移收敛，现行生产必须停止创建目标裁决证据节点，并改为引用原状态、动态、因果及必要治理事实。不得以新增结构体、普通布尔字段或另一类证明节点完成迁移。

持久执行绑定冻结中的限制解释器必须使用 task owner 公开 DTO 中的具名强类型身份；限制当前事实证据必须使用强类型联合引用，联合分支即证据类别。不得保存裸`稳定编码`并由调用方或读回方临场解释，也不得形成类别与身份错配。

任务结构服务是选择记录、类型化记录、选择拓扑和派生当前投影的唯一业务写入与解释方。提交后必须以同一事实截止联合读回完整任务身份来源、强类型方法生命周期、新路径、新实例、当前正式选择、全部选择拓扑和派生当前路径投影；任一必需角色缺失、重复、错端点、错类型、来源需求不属于本轮实际消费集合、任务 / 方法 / 路径 / 轮次 / 内容版本不一致，均不得形成执行冻结。

同一强类型筹办来源幂等身份、同一来源联合分支、同一完整发布请求、同一任务、同一筹办轮次、同一任务身份来源、同一方法生命周期、等价来源需求 / 稳定证据集合、同一路径 / 实例冻结材料、相同方法内容版本和规则版本才允许幂等读回；任一项变化均为异义冲突。发布结果未知时只能使用原强类型来源幂等身份和原完整请求读取 owner 首次幂等账并收敛，不得换键、换联合分支或重写。重复筹办必须形成新轮次和新选择记录，即使再次选择同一方法，也不得覆盖前轮记录或把并发双筹办伪装成同义成功。

本轮如果实际采用因果候选或用途材料参与选择，必须在动作执行前把完整候选身份、方法内容版本和本轮选择一并冻结。执行结果形成后不得事后补配候选，也不得反写本轮冻结、选择、方法内容或动作入口；结果只能供后继筹办轮次重新召回和裁决。

执行开始前必须复核冻结当前性。任一绑定事实变化时，旧冻结失效；任务尚在筹办阶段时进入同一任务轮次的新筹办轮次，不得在旧冻结上就地修补。

### 6.4 C031 执行前选择是唯一冻结 producer

本节此前把“筹办完成”同时视为选择和冻结时点的文字，统一由本小节替代。筹办发现结束后，任务领域在真实动作前以 fresh 共同截止读取候选方法、内容版本、**该方法自身**条件组、输入 / 参数、动作范围、验证 / 归因、禁止和安全材料，构成值式执行选项。

先硬过滤目标 / 结果合同、生命周期与入口当前、条件组 / 输入 / 参数闭合、作用范围 / 验证 / 归因完整、结构拒绝、禁止项、安全硬否决和生存安全根控制态。安全门不可由服务收益、时间、资源或调度材料抵销；服务根当前值、服务合同 / 余额、队列 / 线程状态不得成为选择余额。再按 5240 和 5300 的分层规则在剩余的可比较选项中选择一项。未知、不可比或并列最优时不得选择，必须形成具名待裁决定位。

仅选择成功的同一组合入口才原子形成既有任务方法选择记录、具体任务方法路径、派生当前投影、实例方法和执行冻结；未选候选不得写入第二选择记录或被删除。冻结绑定的条件是已选条件组而非任务级条件总表，任一绑定事实变化均使选择 / 冻结失效。

### 6.1 冻结后作用范围分流

执行冻结完成后，任务管理先读取实例方法正式作用范围和逐动作现实副作用：

```text
仅内部治理
    -> 不请求自我现实执行授权

纯现实观察
    -> 不请求自我现实执行授权

包含现实改变步骤
    -> 形成一份绑定任务、任务轮次、筹办轮次、执行轮次、冻结、实例方法、有序现实改变动作主体、共同作用场景和预计因果后果的授权请求
    -> 在任务进入执行阶段前必须读回当前自我现实执行授权事实，不得先运行混合方法中的观察前缀
```

混合方法中的内部治理和纯观察步骤不因此分别申请授权，但不得借它们提前启动、预热或隐式触发已声明的现实改变步骤。主动探测、设备运动、发射、外部通信、外部系统写入及其它现实副作用按现实改变处理。

场景约束只回答动作在哪一个共同场景上下文中成立，不承担被改变对象、来源 / 目的角色或结果主体。内部治理动作的场景是治理适用上下文，纯现实观察动作的场景是只读观察上下文，现实改变动作则直接作用于其`作用主体`存在的具名特征。移动、进入 / 退出、容纳等动作需要多个存在角色时，由专属强类型动作合同冻结这些存在角色和原子性，但仍不得把角色存在改写成场景列表。

直接作用主体的状态变化可以经已冻结且在执行前仍当前有效的正式因果链影响同一共同场景中的其它存在。需求目标或预期结果可以位于该间接结果主体上；授权和安全复核必须覆盖直接动作及全部正式预计因果后果，但不得因此把间接结果主体改写成自我直接控制对象。动作完成后必须分别独立读回直接主体状态 / 动态和间接结果主体状态 / 动态；直接动作成功、返回候选或预计结果都不能证明间接结果已经发生。

### 6.2 自我唯一现实执行授权

自我是现实执行授权的唯一业务 owner；自我线程只提交决议材料，正式事实由自我领域入口发布。正向授权只有一份，同时覆盖该冻结的任务与实例方法，不建立第二份任务授权、方法授权、需求授权或安全授权。

授权至少绑定：

```text
自我身份
任务身份
任务轮次
筹办轮次
执行轮次
执行冻结身份与版本
实例方法身份与内容版本
有序现实改变动作范围
事实截止、规则版本和发生时间
```

同一请求同义幂等读回，异义冲突零发布。任一绑定事实变化、冻结退出或任务轮次收束使旧授权失效。拒绝、等待和撤回是授权请求的结构化决议结果，不构成正向授权，也不得写成任务失败。

### 6.3 调度材料、技术许可与安全硬否决

6150 输出的安全调度倍率只参与安全任务类内部的正常调度排序；倍率为零使安全任务本次不被普通调度选中，但不删除任务、来源关系、筹办历史、实例或冻结，也不构成授权拒绝。服务根不产生调度资格。任务承接多个需求时，安全调度投影必须保留本轮实际消费的 `T→D` 关系、需求身份、规则版本和共同事实截止。

生存控制态、安全限制与其它安全服务可以形成具名硬否决或停止要求；操作系统、设备和数据服务公开调用许可只证明技术访问资格。这些都不能正向授权现实动作，但任一硬否决可以阻止已经取得自我授权的动作开始或要求安全停止。自我授权不得绕过硬否决，调度配额、基础优先级、时限、队列顺序或线程优先级也不得绕过。

## 7. 执行边界

执行期允许的正常分流包括：条件突然变化、输入过期、外部事实变化、输出未达目标、验证证据不足、安全硬否决或副作用约束命中。它们必须形成强类型运行结果并进入本任务轮次结算；不得自动形成下一筹办工作包。

执行期才发现下列冻结前既有缺口，属于筹办漏检和内部逻辑错误：

```text
缺方法或方法已失效
缺动作入口
缺条件结果对或必要规格
目标语义不完整
任务结构或提交协议缺失
任务虚拟存在或写回入口损坏
```

不得将这些错误包装成普通需求、任务失败或合法等待，不得在执行期补造后继续。

## 8. 状态与动作来源

任务状态迁移由任务领域正式提交入口裁决。回执同步只属于非业务派生整理，不得改变任务状态、进入候选集或生成主链动作动态。

被动任务状态提交可生成动态证据，但动作语义是被动动作；线程和任务管理器不得裸生成动作动态。

## 9. 任务轮次结算、收束与后继边界

方法运行成功、动作发生、来源需求当前满足、子任务完成和输出存在都不能单独证明任务轮次已经收束。执行形成正式实际结果后必须进入结算阶段，由任务结算编排组织本轮目标裁决、验证、归因、停止 / 冻结收口及适用后继结果。

任务实际结果不是容量或成员分配对象。正式结果及本轮停止材料闭合后即可收束本任务轮次，不等待全部 `T→D` 或其它受益任务。若本轮有唯一轮次级上级发起调用，收束后只返回并结算该调用槽；根任务无调用槽。其它需求 / 任务在实际调度、筹办或使用时，按自己的目标或方法条件 fresh 读取当前事实。

稀缺数量、所有权、有效机会和冲突动作仍必须在执行前由真实事实 owner 的 fresh 读回、授权、安全检查和原子事务裁决，不能在动作完成后改写成“任务结果容量”。

结算完成后任务进入`轮次已收束`并等待自我后继决议。目标未达成只写入任务轮次结论；任务管理不得据此自动建立新任务轮次、新筹办轮次或`下一筹办工作包`。只有自我形成`继续`决议后，任务管理才建立新任务轮次并从筹办开始；新轮次必须重新选择、实例化、冻结和按作用范围取得新的现实执行授权。
