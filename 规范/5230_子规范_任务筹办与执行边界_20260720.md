# 5230 子规范 任务筹办与执行边界

编号：5230
日期：20260824
版本：v1.1
状态：正式子规范

## 1. 定位

本规范定义任务领域内建筹办最小方法、任务级唯一筹办执行权、闭合筹办结果、重复筹办、执行冻结和执行期错误边界。

直接上级规范：3200。

直接依赖规范：3100、3300、4010、4020、5210、5300。

相关边界规范：5210、5240、5250、5340、6140、6150。

## 2. 筹办身份与执行权

1. 任务筹办是内部治理范围内的规划动作，由内部治理在读取需求后触发，不属于外部业务流程，也不作为普通方法进入召回。完整链路：内部治理 → 读取需求目标特征 → 同截止目标比较 → 按特征查找方法 → 适用性与方法自身条件评估 → 普通任务 / 学习任务 / 等待分流。
2. 并发隔离键是任务稳定身份。同一任务同一时刻只能有一个有效筹办占用和执行权。
3. 执行权必须由任务结构中的唯一有效占用事实、轮次、版本和当前性裁决，不持久化裸线程编号。
4. 未取得执行权的路径必须在读取方法候选前正常拒绝，不得参与召回、选择或冻结。
5. 两条路径同时进入同一任务召回、选择或冻结，属于内部并发规则破坏；不得以同义选择幂等成功掩盖。
6. 不同任务可以并发筹办，即使它们来源于同一根需求或选择同一方法。

## 3. 每轮筹办输入

每轮必须权威重读：

```text
任务身份与任务虚拟存在
当前 T→D 来源需求关系组、至少一项当前有效具体需求及互证单目标投影
任务角色与活动路径
本轮实际消费来源的权重与预算输入
活动子需求与等待合同
候选方法、方法内容版本和生命周期
方法条件、结果能力、动作入口和任务特征契约
当前世界状态、输入和禁止项
```

筹办可以重复进行。触发来源、轮次和读取版本必须单调、可追溯；旧冻结在相关事实变化后失效。

### 3.1 进程崩溃与跨重启占用

筹办占用是当前运行代次内的任务治理事实，不是可跨进程继承的线程租约。恢复候选必须保留原任务身份、筹办轮次、占用版本、来源运行代次和历史当前性，但旧运行代次的有效占用不得在新运行期直接恢复为执行权。

恢复过程必须在隔离候选中完成：

```text
重建任务、历史筹办轮次和占用记录
-> 证明旧运行代次已经终止且不存在仍可能继续的前轮动作
-> 原子失效旧占用及其旧冻结当前性
-> 发布新的恢复代次和待重筹办触发
-> 新一轮增加筹办轮次并重新取得唯一筹办执行权
```

不得按墙钟超时、裸进程号、线程号或“重启已经发生”直接删除占用历史，也不得沿用旧轮次继续召回、选择或冻结。若不能证明前轮真实外部动作已经停止或已经完成实际回读，只能形成带动作核验生产者和重新触发条件的合法等待；不得取得新执行冻结或重复发起外部动作。前置通过后出现两个恢复后当前占用、旧运行代次仍可写入或新轮次读回不一致，属于内部并发或恢复逻辑错误。

## 4. 闭合结果

任务筹办直接返回并提交本轮闭合结果，不建立独立持久化筹办回执，也不建立独立“能力缺口”节点或“目标变化材料”节点。结果只能是：

| 结果 | 必须同时形成的结构 |
| --- | --- |
| 可执行冻结 | 当前方法、条件与输入绑定、路径、方法版本、验证和归因合同（匹配成功→普通任务执行前冻结） |
| 子目标承接 | 完整子目标草案、合法生产者、等待合同和回流条件 |
| 学习需求承接 | 目标宿主 / 特征 / 状态合同、当前比较与所需方向、特征粗召回完整为空的`方法能力缺失`证据、全部正式学习门禁通过证据，以及合法学习任务生产者；不得预造未知方法的输入条件或限制条件 |
| 方法补齐承接 | 已有方法候选但动作入口/条件结果对/输入参数/禁止项/验证归因合同存在具体结构化缺口，及其合法补齐处理方 |
| 合法等待 | 等待对象、等待事实生产者、重新触发条件和当前状态 |
| 目标已完成 | 当前目标比较、验证和结果证据 |

禁止返回无结构“无法解决、退回上层”。特征粗召回完整为空时不得自动创建方法首、不得用通用写入逻辑兜底；先形成`方法能力缺失`判断材料，只有正式学习门禁全部满足时才形成学习需求承接，否则合法等待，并由需求/治理入口统一生产学习需求。粗召回非空但适用判断全部不兼容的`当前无适用方法`只形成合法等待，不得进入学习需求承接。学习需求承接仅作为学习任务的前置材料，不建立长期能力缺口节点；目标状态解析只形成分析材料，不创建目标变化节点。

## 5. 路径和候选边界

1. 筹办先读取需求目标三元组，以目标状态合同绑定的正式比较注册在同一事实截止比较当前值与目标值；已满足直接形成目标已完成，未满足时形成所需变化方向。不能按名称、标签、默认方向或稳定编码决定任务形态。
2. 逻辑组织、管理和路径节点先执行展开、聚合或路径选择，不直接进入普通方法候选。
3. 普通可任务化原子任务先按目标特征定义有界粗召回方法用途，再以目标宿主全部当前合法概念、所需方向和目标状态结果能力判断适用候选；取得候选后才读取方法自身条件、输入规格、限制和条件结果关系。任务不得镜像方法六项签名或要求输入 / 限制逐项相等。
4. 筹办不直接写需求树、不建立能力缺口节点、不建立目标变化材料节点；子目标草案、方法补齐草案和学习需求草案均交需求领域统一入口。
5. 被动、提交、结算和内部治理动作不进入主动候选集。
6. 缺失条件草案只来自本轮实际采用方法与目标结果正式关联的条件。条件回流后重新读取方法版本与当前事实并开启新筹办轮次，不沿用旧就绪结论。
7. 多候选没有正式可比较选择证据时只形成稳定候选组和合法等待，不为互斥候选同时提出条件；稳定编码不得充当能力优劣。

## 6. 执行冻结

冻结必须绑定任务、筹办轮次、方法、方法内容版本、动作入口、条件、输入、路径、本轮实际消费的 `T→D` 关系与具体来源需求版本、禁止项、验证、归因和失效条件。通用来源需求授权、安全图、安全阈值、权限规则、适用性分类规则及其 provider 不进入执行冻结，也不得形成“材料缺失等待”。

正式任务方法选择记录是当前选择和历史选择的唯一权威。选择记录、关系族、关系角色和属性类型均由任务结构 owner 按 4010 的 owner 私有类型登记合同正式登记；不得依赖固定节点类型号、固定关系类型号、固定角色顺序号或世界状态节点作为公开、持久或跨模块 ABI。

每次已发布选择必须形成独立、不可变的任务方法选择记录，并形成下列强类型拓扑：

| 角色 | 源 | 目标 | 基数与边界 |
| --- | --- | --- | --- |
| 当前正式选择 | 任务 | 任务方法选择记录 | 同一任务至多一条当前有效关系；新轮次原子退出旧当前关系并建立新当前关系 |
| 选中方法 | 任务方法选择记录 | 方法 | 每个选择记录恰一；目标是本轮采用方法 |
| 具体任务方法路径 | 任务方法选择记录 | 任务方法路径 | 每个选择记录恰一；路径属于同一任务、同一筹办轮次和同一方法内容版本 |
| 来源需求 | 任务方法选择记录 | 需求 | 至少一项；必须来自任务当前 `T→D` 关系组并属于本轮实际消费集合，按关系身份与需求身份唯一 |
| 稳定选择证据 | 任务方法选择记录 | 对应主题正式允许的稳定证据 | 可为一项或多项；初次筹办只允许首次初次筹办准备记录，重筹办只允许目标裁决证据和任务治理状态，并按具名类别保存；日志、哈希、文本和裸编码不得冒充 |
| 执行绑定冻结材料 | 任务方法选择记录 | 执行绑定冻结材料 | 每个选择记录恰一；完整承载当前就绪、来源需求、方法限制、验证和归因的强类型冻结结果，不得重复进入稳定选择证据拓扑 |

`任务 -> 当前选中路径`只是在同一选择发布事务中形成的派生当前投影，不再拥有独立公开生产写入口，不能单独证明业务选择。历史选择路径只由`选择记录 -> 具体任务方法路径`恢复；普通`任务 -> 方法`引用若保留，也只能是可重建派生投影，不能成为第二选择权威。

任务领域类型化选择记录至少保存：记录合同版本、记录格式版本、记录版本、记录状态、强类型筹办来源幂等身份、筹办轮次、选择规则版本、召回规则版本、选中方法内容版本、完整任务身份来源事实，以及方法 owner 公开读回的完整强类型方法生命周期事实。筹办来源幂等身份必须以判别联合区分首次初次筹办准备记录身份和重筹办意图幂等身份，二者不得换算为同一无类型整数后比较。任务身份来源必须包含任务节点和任务族归属关系的结构生命周期见证；方法生命周期必须包含方法身份、生命周期版本、发生时间、来源稳定编码和结构生命周期。不得保存固定关系编号、关系端点拆分值、世界状态身份、普通模板关系、无类型槽或以稳定编码替代强类型身份。

正式选择发布必须由任务结构 owner 的同一公开组合入口在同一事实事务中完成新路径、新选择记录、完整选择拓扑、派生当前路径投影和任务侧当前实例关联。初次筹办模式必须证明当前选择、当前路径、当前实例均为空，筹办轮次和新执行轮次均为 1，不退出不存在的旧事实；重筹办模式必须原子退出旧当前选择、旧当前路径和旧当前实例，新执行轮次固定为旧执行轮次加一。旧选择记录、旧选择拓扑、旧路径和旧实例保留历史，不得覆盖、重挂或删除。路径 owner facade 不得建立第二存储、第二事务或第二当前选择入口。

任务结构 owner 的公开发布请求只能接收 DATA-L2 自有的规范化筹办来源判别联合和强类型冻结证据，不能直接接收`任务初次筹办工作包`、`下一筹办工作包`或内部治理 DTO。联合只能是以下两种互斥分支：

1. `初次筹办来源`：逐项保存首次初次筹办准备记录身份、任务、来源需求、来源需求关系、同类任务查询锚点、首次目标比较共同事实截止、任务建立事实代次、筹办轮次 1 和运行代次。owner 必须按准备记录公开读回完整首次请求、首次需求裁决、任务、任务身份来源、`T→D` 关系和任务虚拟存在，并在发布请求共同截止重新证明任务、来源需求关系与具体需求仍有效，且当前选择、当前路径、当前实例均为空；不得要求或伪造旧路径、旧实例、旧执行轮次、旧结果、目标未达成裁决或待重筹办治理状态。
2. `重筹办来源`：逐项保存原重筹办意图幂等身份、任务、旧路径、旧实例、旧执行轮次、旧结果、正式目标裁决、正式待重筹办治理状态、原共同事实截止、迁移后事实代次、新旧筹办轮次和运行代次，并保持现行目标未达成与待重筹办互证。

内部治理 provider 只允许按所持来源分支机械映射，任务 owner 在写前以公开事实重新互证。两个分支不得以 optional 字段拼盘、全空旧事实、伪造旧结果或恢复独立当前路径发布入口相互冒充。DATA-L2 任务数据和服务不得反向依赖内部治理模块。

候选数量、索引发布版本、排序过程、完整有序候选元组和召回统计只属于可选审计材料，不单独裁决选择身份、当前性或同义。只有实际改变选择理由、归因或同轮隔离的稳定来源证据才进入稳定选择证据拓扑；无法形成允许的稳定证据节点时不得把日志、哈希、拆分句柄或无类型数组塞入选择记录兜底。

持久执行绑定冻结中的限制解释器必须使用 task owner 公开 DTO 中的具名强类型身份；限制当前事实证据必须使用强类型联合引用，联合分支即证据类别。不得保存裸`稳定编码`并由调用方或读回方临场解释，也不得形成类别与身份错配。

任务结构服务是选择记录、类型化记录、选择拓扑和派生当前投影的唯一业务写入与解释方。提交后必须以同一事实截止联合读回完整任务身份来源、强类型方法生命周期、新路径、新实例、当前正式选择、全部选择拓扑和派生当前路径投影；任一必需角色缺失、重复、错端点、错类型、来源需求不属于本轮实际消费集合、任务 / 方法 / 路径 / 轮次 / 内容版本不一致，均不得形成执行冻结。

同一强类型筹办来源幂等身份、同一来源联合分支、同一完整发布请求、同一任务、同一筹办轮次、同一任务身份来源、同一方法生命周期、等价来源需求 / 稳定证据集合、同一路径 / 实例冻结材料、相同方法内容版本和规则版本才允许幂等读回；任一项变化均为异义冲突。发布结果未知时只能使用原强类型来源幂等身份和原完整请求读取 owner 首次幂等账并收敛，不得换键、换联合分支或重写。重复筹办必须形成新轮次和新选择记录，即使再次选择同一方法，也不得覆盖前轮记录或把并发双筹办伪装成同义成功。

本轮如果实际采用因果候选或用途材料参与选择，必须在动作执行前把完整候选身份、方法内容版本和本轮选择一并冻结。执行结果形成后不得事后补配候选，也不得反写本轮冻结、选择、方法内容或动作入口；结果只能供后继筹办轮次重新召回和裁决。

执行开始前必须复核冻结当前性。任一绑定事实变化时，旧冻结失效并进入新筹办轮次，不得在旧冻结上就地修补。

真实外部动作开始前如需治理许可，许可只表达本次动作是否可开始，不替代筹办结果、任务状态或完成裁决。

### 6.1 冻结后、派发前的权限与控制门控

执行冻结完成后、真实派发前，任务管理才读取 6150 / 6170 当前正式输入，形成正常调度资格与优先级投影。任务承接多个有效需求时，投影必须保留本轮实际消费的 `T→D` 关系、需求身份、规则版本和共同事实截止；不得从列表全部成员补输入。

权限值为零时，任务身份、来源关系、筹办历史、当前方法、执行冻结和排队状态都继续保留，但不得真实派发参加正常执行。任务基础优先级、时限、队列到达顺序和线程消息优先级都不得绕过零权限。全局控制态是独立派发门控，不与权限投影或来源需求混写。

只有具体方法涉及外部主体、受保护资源或受限能力时，方法合同才声明具名许可条件；该条件在真实派发前检查，不得扩张为所有任务共有的授权安全材料。

## 7. 执行边界

执行期允许的正常分流包括：条件突然变化、输入过期、外部事实变化、输出未达目标、验证证据不足或副作用约束命中。它们必须形成强类型运行结果并按任务状态合同收束。

执行期才发现下列冻结前既有缺口，属于筹办漏检和内部逻辑错误：

```text
缺方法或方法已失效
缺动作入口
缺条件结果对或必要规格
目标语义不完整
任务结构或提交协议缺失
任务虚拟存在或写回入口损坏
```

不得将这些错误包装成普通需求、任务失败或合法等待，不得在执行期补造后继续。

## 8. 状态与动作来源

任务状态迁移由任务领域正式提交入口裁决。回执同步只属于非业务派生整理，不得改变任务状态、进入候选集或生成主链动作动态。

被动任务状态提交可生成动态证据，但动作语义是被动动作；线程和任务管理器不得裸生成动作动态。

## 9. 完成边界

方法运行成功、动作发生、来源需求当前满足、子任务完成和输出存在都不能单独证明任务完成。完成必须由任务自身目标结果、验证、禁止结果、归因和当前性联合裁决。

任务完成后，对应每个当前显式关联且合格的来源需求仍必须分别读取其目标合同和当前事实进行核算。任务实际结果是否可由多个来源需求共同引用，或因容量、范围、所有权、有效性存在扣减而构成争用，只属于完成后的结果消费关系与分配阶段：可共用时不得建立业务优先级账，争用时才按正式成员分配优先级逐项满足并逐项扣减。本条不把结果分配优先级带回方法选择、执行冻结或本轮任务完成裁决。

## ARCH-L4 筹办边界（20260824）

任务筹办/冻结/派发属于 ARCH-L4。它只能读取 ARCH-L2 公开结构并提交已裁决的结构请求；不得让 DATA-L2 服务执行方法选择、目标比较、状态/动态自动生成或任务完成解释。Stage C 语义按本文件当前 WIP 执行，旧材料只作历史。
