# 5230 子规范 任务筹办与执行边界

编号：5230
日期：20260903
版本：v2.5
状态：正式子规范

## 1. 定位

本规范定义任务领域内部治理函数“任务筹办”、任务级唯一筹办执行权、由任务状态驱动的多次筹办、每次调用结果、任务管理校验迁移、执行前选择和执行期错误边界。

直接上级规范：3200。

直接依赖规范：3100、3300、4010、4020、4260、5210、5300。

相关边界规范：5210、5240、5250、5340、6140、6150。

## 2. 筹办身份与执行权

1. 任务筹办是任务领域的内部治理函数，不属于外部业务流程，也不作为普通方法进入召回。任务管理线程读取任务当前状态后决定是否派发筹办工作；筹办函数只完成该状态指定的一段信息补全，不能自行决定是否再次调用自己。
2. 并发隔离键是任务稳定身份。同一任务同一时刻只能有一个有效筹办占用和执行权。
3. 执行权必须由任务结构中的唯一有效占用事实、轮次、版本和当前性裁决，不持久化裸线程编号。
4. 未取得执行权的路径必须在读取或补写本次任务筹办信息前技术拒绝，不得形成业务筹办结果。
5. 两条路径同时进入同一任务的同一筹办轮次，属于内部并发规则破坏；执行前选择的排他与幂等另按第 6.4 节及 task owner 合同处理。
6. 不同任务可以并发筹办，即使它们来源于同一根需求或选择同一方法。

## 3. 状态驱动的多次筹办

筹办不是一次完成的“纯发现”，也不要求一次调用找完方法并查完条件。任务管理线程每次派发前必须 fresh 读取并互证任务、任务轮次、筹办轮次、当前业务状态段、任务信息版本和上次已覆盖 / 剩余范围，然后只派发与当前状态一致的工作包：

| 调用前业务状态 | 本次筹办工作 |
| --- | --- |
| 待找方法 / 继续找方法 | 在当前明确的有界范围内继续查找可用于完成任务目标的方法，写入方法身份、内容版本、查找范围和覆盖进度；不查条件，不判断适用性，不选择方法 |
| 待查条件 / 继续查条件 | 只对已登记候选方法逐项查找其执行条件组并核验条件当前是否具备，写入方法—版本—条件组、核验截止、结果、覆盖进度；不扩展方法查找，不选择方法 |

首次筹办从找方法开始。只有当前方法查找范围已经完整覆盖且至少有一个候选方法，manager 才能把任务迁移到待查条件；不得边找到第一条方法边进入条件阶段。只有当前全部候选方法的全部条件组都完成核验，manager 才能裁决进入待执行前选择或等待条件；不得因先发现一组条件具备而停止其余候选核验，因为未核验候选可能具有更低执行代价。

每次筹办调用只补全当前`任务 + 任务轮次 + 筹办轮次`的信息。它复用 task owner 唯一正式入口保存和读取方法、版本、各自条件组、核验结果、已覆盖范围、剩余范围及任务信息版本；不得建立第二候选账、条件账、结果账、线程或 outbox。

### 3.1 进程崩溃与跨重启占用

筹办占用是当前运行代次内的任务治理事实，不是可跨进程继承的线程租约。恢复候选必须保留原任务身份、筹办轮次、占用版本、来源运行代次和历史当前性，但旧运行代次的有效占用不得在新运行期直接恢复为执行权。

恢复过程必须在隔离候选中完成：

```text
重建任务、当前任务轮次、历史筹办轮次和占用记录
-> 证明旧运行代次已经终止且不存在仍可能继续的前轮动作
-> 原子失效旧占用及其旧冻结当前性
-> 发布新的恢复代次和筹办重判触发
-> 在同一尚未收束任务轮次中增加筹办轮次并重新取得唯一筹办执行权
```

不得按墙钟超时、裸进程号、线程号或“重启已经发生”直接删除占用历史，也不得沿用旧轮次继续召回、选择或冻结。若不能证明前轮真实外部动作已经停止或已经完成实际回读，只能形成带动作核验生产者和重新触发条件的合法等待；不得取得新执行冻结或重复发起外部动作。前置通过后出现两个恢复后当前占用、旧运行代次仍可写入或新轮次读回不一致，属于内部并发或恢复逻辑错误。

## 4. 每次筹办调用的结果与消息

任务管理线程把不可变筹办工作包交给既有任务工作线程；任务工作线程每次处理结束必须发送恰好一条强类型筹办结果消息。任务管理线程不得在自身循环中直接调用筹办 provider 并同步消费返回值。复用既有任务工作线程和有界消息队列，不为筹办另建专用线程；消息只承担本次调用结果的跨线程交接，不建立持久回执或第二结果权威。

一次调用的业务结果只描述当前阶段的信息补全进度：

| 调用前状态 | 本次成功结果 | manager 校验后的后继状态 |
| --- | --- | --- |
| 待找方法 / 继续找方法 | 当前有界查找尚未覆盖完，回显已覆盖和剩余范围 | 继续找方法 |
| 待找方法 / 继续找方法 | 当前查找范围已完整覆盖，存在一个或多个候选方法 | 待查条件 |
| 待找方法 / 继续找方法 | 当前查找范围已完整覆盖，没有候选方法 | 方法缺失 / 等待方法处理 |
| 待查条件 / 继续查条件 | 仍有候选方法或条件组未完成查找 / 核验 | 继续查条件 |
| 待查条件 / 继续查条件 | 全部候选与条件组已核验，至少一组条件当前具备 | 待执行前选择 |
| 待查条件 / 继续查条件 | 全部候选与条件组已核验，没有任何条件组当前具备 | 条件缺失 / 等待条件 |

`方法缺失`和`条件缺失`是当前任务材料，不是需求、子任务或任务终态。筹办结果中不存在“目标已完成、子目标承接、采用方法、当前路径、实例方法、执行冻结”等分支；这些分别属于目标比较 / 结算、自我—需求链或执行前选择。

消息必须绑定任务、任务轮次、筹办轮次、来源工作包、调用前状态、来源事实截止、结果事实截止、任务信息预期版本 / 结果版本、已覆盖范围、剩余范围和本次结果。manager 收到消息后必须独立读回 task owner 的当前任务信息，校验任务、轮次、状态、版本、覆盖范围和结果一致，再经正式 owner 提交状态迁移；消息、日志、线程状态和同步返回值均不是阶段权威。这是“筹办补全 + manager 独立确认”的双线确认，不是双重记账。

### 4.1 技术非成功与业务结果分账

- 资源失败、队列投递失败或发布结果未知：业务状态不前进；保持原工作包、原幂等身份和原完整请求重试 / 读回收敛，不重新调用已成功的 provider。
- 截止或版本漂移：本次结果失效，业务状态不前进；manager 在同一业务子状态基于新截止重新派发。
- ABI、引用、断言、结构不变量或内部代码错误：属于工程故障，停止受影响调用并交修复；不得伪装成方法缺失、条件缺失或等待。
- 输入与当前任务状态不一致：拒绝本次调用，保持权威业务状态；不得据拒绝消息自行迁移。

技术非成功不是筹办业务出口，不得与上表六个成功结果并列计数。

### 4.2 筹办工作包合同

找方法工作包和查条件工作包必须是强类型互斥分支，不能用 optional 拼盘。两者都携带当前任务状态和任务信息版本；找方法分支只携带方法查找范围 / 游标，查条件分支只携带已登记候选集合及待核验范围。工作包不得携带 manager 预设的业务结果，也不得作为执行前选择的规范化来源。

## 5. 路径和候选边界

1. 任务目标是否已满足由任务管理在决定筹办前调用目标比较 / 结算链裁决；筹办只消费已确认仍需推进的任务目标，不返回目标已完成。
2. 逻辑组织、管理和路径节点先执行展开、聚合或路径选择，不直接进入普通方法候选。
3. 找方法阶段按任务目标和正式方法能力索引完整查找候选；它不判断适用性，不查条件，不形成当前路径。查条件阶段只读取已登记候选各自的条件组并核验当前事实；任务不得把不同方法的条件摊平成任务总条件表。
4. 筹办不直接写需求树、不建立能力缺口节点、不建立目标变化材料节点。方法 / 条件缺失消息只能把正式任务材料定位给 self；只有 self 产生并确认独立必要后继需求目标，task owner 才记录为正式子目标承接记录，需求 owner 再发布或复用需求。
5. 被动、提交、结算和内部治理动作不进入主动候选集。
6. 查条件必须覆盖每个候选方法的全部条件组；条件回流后由 manager 根据权威状态决定在同一业务子状态重新核验，不沿用旧核验结论。
7. 多个方法和多组条件是正常筹办结果。筹办不比较候选代价，不按稳定编码选方法；真实执行前由第 6.4 节在 fresh 事实下选择可用且总代价最小的方法。

## 6. 执行冻结

冻结必须绑定任务、任务轮次、筹办轮次、计划执行轮次、方法、方法内容版本、动作入口、方法作用范围、逐动作现实副作用、逐动作直接作用主体、共同作用场景、条件、输入、路径、本轮实际消费的 `T→D` 关系与具体来源需求版本、禁止项、安全限制、验证、归因和失效条件。需求活动资格、安全因果图、安全阈值、调度配额规则、适用性分类规则及其 provider 不进入执行冻结，也不得形成“授权材料缺失等待”。执行冻结本身不包含正向现实执行授权。

完整有序冻结动作范围是执行期动作类别、直接作用主体、共同场景约束和现实副作用声明的唯一生产材料。当前执行中的全部具名作用主体、自我以及目标 / 结果主体在本次采用的观察分辨率下必须由场景 owner 在同一事实截止证明是同一共同场景的当前成员；现实改变动作的非空`作用场景`必须全部等于该共同场景。`作用主体`才是动作直接读取或改变的存在，`作用场景`只表达动作成立的共同上下文，不得把控制室、车间、设备等成员存在改判成多个直接作用场景。需要展开某个成员存在内部时，必须进入与该存在身份分离的内部场景后另行形成任务或执行，不得在一次执行中拼接多个场景层级。

正式任务方法选择记录是当前选择和历史选择的唯一权威。选择记录、关系族、关系角色和属性类型均由任务结构 owner 按 4010 的 owner 私有类型登记合同正式登记；不得依赖固定节点类型号、固定关系类型号、固定角色顺序号或世界状态节点作为公开、持久或跨模块 ABI。选择记录可以引用已存在的状态、动态、因果或必要治理来源事实，但不得为了保存选择理由、归因或同轮隔离而新建证据专用节点、证据关系或第二份业务事实。

每次已发布选择必须形成独立、不可变的任务方法选择记录，并形成下列强类型拓扑：

| 角色 | 源 | 目标 | 基数与边界 |
| --- | --- | --- | --- |
| 当前正式选择 | 任务 | 任务方法选择记录 | 同一任务至多一条当前有效关系；新轮次原子退出旧当前关系并建立新当前关系 |
| 选中方法 | 任务方法选择记录 | 方法 | 每个选择记录恰一；目标是本轮采用方法 |
| 具体任务方法路径 | 任务方法选择记录 | 任务方法路径 | 每个选择记录恰一；路径属于同一任务、同一筹办轮次和同一方法内容版本 |
| 来源需求 | 任务方法选择记录 | 需求 | 至少一项；必须来自任务当前 `T→D` 关系组并属于本轮实际消费集合，按关系身份与需求身份唯一 |
| 选择来源引用（现有 ABI 名称可暂保留“稳定选择证据”） | 任务方法选择记录 | 已经发布的状态、动态、因果或具有独立业务作用的任务 / 需求 / 方法治理事实 | 可为一项或多项；必须回到本任务轮次的筹办触发、等待回流或冻结失效来源；不得指向为证明选择而新建的证据节点；目标未达成与已收束轮次不得冒充新筹办来源；日志、哈希、文本和裸编码不得冒充 |
| 执行绑定冻结材料 | 任务方法选择记录 | 执行绑定冻结材料 | 每个选择记录恰一；完整承载当前就绪、来源需求、方法限制、验证和归因的强类型冻结结果，不得重复进入选择来源引用拓扑 |

`任务 -> 当前选中路径`只是在同一选择发布事务中形成的派生当前投影，不再拥有独立公开生产写入口，不能单独证明业务选择。历史选择路径只由`选择记录 -> 具体任务方法路径`恢复；普通`任务 -> 方法`引用若保留，也只能是可重建派生投影，不能成为第二选择权威。

任务领域类型化选择记录至少保存：记录合同版本、记录格式版本、记录版本、记录状态、强类型执行前选择幂等身份、任务轮次、筹办轮次、任务信息版本、选择规则版本、选中方法内容版本、完整任务身份来源事实，以及方法 owner 公开读回的完整强类型方法生命周期与作用范围事实。任务身份来源必须包含任务节点和任务族归属关系的结构生命周期见证；方法生命周期必须包含方法身份、生命周期版本、发生时间、来源稳定编码和结构生命周期。不得保存固定关系编号、关系端点拆分值、世界状态身份、普通模板关系、无类型槽或以稳定编码替代强类型身份。

正式选择发布必须由任务结构 owner 的同一公开组合入口在同一事实事务中完成新路径、新选择记录、完整选择拓扑、派生当前路径投影和任务侧当前实例关联。入口必须证明任务处于`待执行前选择`、本任务轮次尚未执行、所读任务信息版本当前且本次 fresh 复核成立；若存在旧选择 / 路径 / 实例，还必须先证明其已失效并原子退出当前关系。执行轮次只在任务合法进入执行阶段时建立，不由筹办轮次递增冒充。旧选择记录、旧选择拓扑、旧路径和旧实例保留历史，不得覆盖、重挂或删除。路径 owner facade 不得建立第二存储、第二事务或第二当前选择入口。

任务结构 owner 的公开发布请求只能接收 DATA-L2 自有的规范化执行前选择材料和强类型冻结证据，不能直接接收线程工作包、筹办结果消息或内部治理 DTO。选择材料逐项保存任务、任务轮次、筹办轮次、任务信息版本、来源需求关系、候选方法与条件组定位、fresh 复核截止、选择成本输入和执行前选择幂等身份。owner 必须重新证明任务处于`待执行前选择`、任务信息全部核验完成、本任务轮次尚未执行且当前选择 / 路径 / 实例满足发布前约束。

执行前入口只能按 task owner 当前任务信息和各领域正式事实 fresh 形成选择材料，任务 owner 写前再次互证。筹办工作包和结果消息不能生产、代替或直接传入选择材料，选择来源也不能反向派发工作包。这个分账不增加持久来源账、选择账或结果账；DATA-L2 任务数据和服务不得反向依赖内部治理模块。

候选数量、索引发布版本、排序过程、完整有序候选元组和召回统计只属于可选审计材料，不单独裁决选择身份、当前性或同义。只有实际参与选择、归因或同轮隔离的既有来源事实才可以被选择记录引用；不得为了让引用“稳定”而生产新证据节点。来源不足时返回合法等待、材料不足或内部缺口，不得把日志、哈希、拆分句柄、无类型数组或新造证据身份塞入选择记录兜底。

现行 ABI 中的 `L2任务目标裁决证据身份`、`L2任务选择稳定证据类别`、`稳定选择证据` 等名称在替代读回合同完成前不得机械删除、重排或改义；兼容保留只允许历史读取和迁移收敛，现行生产必须停止创建目标裁决证据节点，并改为引用原状态、动态、因果及必要治理事实。不得以新增结构体、普通布尔字段或另一类证明节点完成迁移。

持久执行绑定冻结中的限制解释器必须使用 task owner 公开 DTO 中的具名强类型身份；限制当前事实证据必须使用强类型联合引用，联合分支即证据类别。不得保存裸`稳定编码`并由调用方或读回方临场解释，也不得形成类别与身份错配。

任务结构服务是选择记录、类型化记录、选择拓扑和派生当前投影的唯一业务写入与解释方。提交后必须以同一事实截止联合读回完整任务身份来源、强类型方法生命周期、新路径、新实例、当前正式选择、全部选择拓扑和派生当前路径投影；任一必需角色缺失、重复、错端点、错类型、来源需求不属于本轮实际消费集合、任务 / 方法 / 路径 / 轮次 / 内容版本不一致，均不得形成执行冻结。

同一强类型执行前选择幂等身份、同一来源联合分支、同一完整发布请求、同一任务、同一筹办轮次、同一任务身份来源、同一方法生命周期、等价来源需求 / 稳定证据集合、同一路径 / 实例冻结材料、相同方法内容版本和规则版本才允许幂等读回；任一项变化均为异义冲突。发布结果未知时只能使用原强类型执行前选择幂等身份和原完整请求读取 owner 首次幂等账并收敛，不得换键、换联合分支或重写。新的执行前选择只能基于已经达到`待执行前选择`状态的筹办轮次形成新选择记录；即使再次选择同一方法，也不得覆盖前轮记录或把并发选择伪装成同义成功。

本轮如果实际采用因果候选或用途材料参与选择，必须在动作执行前把完整候选身份、方法内容版本和本轮选择一并冻结。执行结果形成后不得事后补配候选，也不得反写本轮冻结、选择、方法内容或动作入口；结果只能进入本轮任务结算和 self 后继决议。轮次收束后，只有 self 的正式`继续`决议才能建立新任务轮次，并重新经过筹办召回方法、补齐条件和执行前选择。

执行开始前必须复核冻结当前性。任一绑定事实变化时，旧冻结失效，不得在旧冻结上就地修补；manager 必须按任务当前状态经正式状态入口回到对应的找方法或查条件子状态，并重新派发筹办工作。

### 6.4 C031 执行前选择是唯一冻结 producer

本节此前把“筹办完成”同时视为选择和冻结时点的文字，统一由本小节替代。任务信息完整且任务进入`待执行前选择`后，任务领域在真实动作前以 fresh 共同截止读取候选方法、内容版本、**该方法自身**条件组、输入 / 参数、动作范围、验证 / 归因、禁止和安全材料，构成值式执行选项。

先硬过滤目标 / 结果合同、生命周期与入口当前、条件组 / 输入 / 参数闭合、作用范围 / 验证 / 归因完整、结构拒绝、禁止项、安全硬否决和生存安全根控制态。安全门不可由服务收益、时间、资源或调度材料抵销；服务根当前值、服务合同 / 余额、队列 / 线程状态不得成为选择余额。再按 5240 和 5300 的分层规则在剩余的可比较选项中选择一项。未知、不可比或并列最优时不得选择，必须形成具名待裁决定位。

仅选择成功的同一组合入口才原子形成既有任务方法选择记录、具体任务方法路径、派生当前投影、实例方法和执行冻结；未选候选不得写入第二选择记录或被删除。冻结绑定的条件是已选条件组而非任务级条件总表，任一绑定事实变化均使选择 / 冻结失效。

### 6.1 冻结后作用范围分流

执行冻结完成后，任务管理先读取实例方法正式作用范围和逐动作现实副作用：

```text
仅内部治理
    -> 不请求自我现实执行授权

纯现实观察
    -> 不请求自我现实执行授权

包含现实改变步骤
    -> 形成一份绑定任务、任务轮次、筹办轮次、执行轮次、冻结、实例方法、有序现实改变动作主体、共同作用场景和预计因果后果的授权请求
    -> 在任务进入执行阶段前必须读回当前自我现实执行授权事实，不得先运行混合方法中的观察前缀
```

混合方法中的内部治理和纯观察步骤不因此分别申请授权，但不得借它们提前启动、预热或隐式触发已声明的现实改变步骤。主动探测、设备运动、发射、外部通信、外部系统写入及其它现实副作用按现实改变处理。

场景约束只回答动作在哪一个共同场景上下文中成立，不承担被改变对象、来源 / 目的角色或结果主体。内部治理动作的场景是治理适用上下文，纯现实观察动作的场景是只读观察上下文，现实改变动作则直接作用于其`作用主体`存在的具名特征。移动、进入 / 退出、容纳等动作需要多个存在角色时，由专属强类型动作合同冻结这些存在角色和原子性，但仍不得把角色存在改写成场景列表。

直接作用主体的状态变化可以经已冻结且在执行前仍当前有效的正式因果链影响同一共同场景中的其它存在。需求目标或预期结果可以位于该间接结果主体上；授权和安全复核必须覆盖直接动作及全部正式预计因果后果，但不得因此把间接结果主体改写成自我直接控制对象。动作完成后必须分别独立读回直接主体状态 / 动态和间接结果主体状态 / 动态；直接动作成功、返回候选或预计结果都不能证明间接结果已经发生。

### 6.2 自我唯一现实执行授权

自我是现实执行授权的唯一业务 owner；自我线程只提交决议材料，正式事实由自我领域入口发布。正向授权只有一份，同时覆盖该冻结的任务与实例方法，不建立第二份任务授权、方法授权、需求授权或安全授权。

授权至少绑定：

```text
自我身份
任务身份
任务轮次
筹办轮次
执行轮次
执行冻结身份与版本
实例方法身份与内容版本
有序现实改变动作范围
事实截止、规则版本和发生时间
```

同一请求同义幂等读回，异义冲突零发布。任一绑定事实变化、冻结退出或任务轮次收束使旧授权失效。拒绝、等待和撤回是授权请求的结构化决议结果，不构成正向授权，也不得写成任务失败。

### 6.3 调度材料、技术许可与安全硬否决

6150 输出的安全调度倍率只参与安全任务类内部的正常调度排序；倍率为零使安全任务本次不被普通调度选中，但不删除任务、来源关系、筹办历史、实例或冻结，也不构成授权拒绝。服务根不产生调度资格。任务承接多个需求时，安全调度投影必须保留本轮实际消费的 `T→D` 关系、需求身份、规则版本和共同事实截止。

生存控制态、安全限制与其它安全服务可以形成具名硬否决或停止要求；操作系统、设备和数据服务公开调用许可只证明技术访问资格。这些都不能正向授权现实动作，但任一硬否决可以阻止已经取得自我授权的动作开始或要求安全停止。自我授权不得绕过硬否决，调度配额、基础优先级、时限、队列顺序或线程优先级也不得绕过。

## 7. 执行边界

执行期允许的正常分流包括：条件突然变化、输入过期、外部事实变化、输出未达目标、验证证据不足、安全硬否决或副作用约束命中。它们必须形成强类型运行结果并进入本任务轮次结算；不得自动形成筹办工作包。

执行期才发现下列冻结前既有缺口，属于筹办漏检和内部逻辑错误：

```text
缺方法或方法已失效
缺动作入口
缺条件结果对或必要规格
目标语义不完整
任务结构或提交协议缺失
任务虚拟存在或写回入口损坏
```

不得将这些错误包装成普通需求、任务失败或合法等待，不得在执行期补造后继续。

## 8. 状态与动作来源

任务状态迁移由任务领域正式提交入口裁决。回执同步只属于非业务派生整理，不得改变任务状态、进入候选集或生成主链动作动态。

被动任务状态提交可生成动态证据，但动作语义是被动动作；线程和任务管理器不得裸生成动作动态。

## 9. 任务轮次结算、收束与后继边界

方法运行成功、动作发生、来源需求当前满足、子任务完成和输出存在都不能单独证明任务轮次已经收束。执行形成正式实际结果后必须进入结算阶段；任务结算只组织本轮目标裁决、验证、归因、运行停止、冻结和授权消费收口，并形成唯一任务轮次结算结果。

任务实际结果不是容量或成员分配对象。每个已经开始的执行轮次必须在正式结果或具名非成功、验证 / 归因与本轮停止材料闭合后，恰好形成一个绑定该执行轮次的任务轮次结算结果；同一执行轮次不得重复结算。结算与收束不等待全部 `T→D`、价值结算、学习后继或其它受益任务。若本轮有唯一轮次级上级发起调用，收束后只返回并结算该调用槽；根任务无调用槽。

稀缺数量、所有权、有效机会和冲突动作仍必须在执行前由真实事实 owner 的 fresh 读回、授权、安全检查和原子事务裁决，不能在动作完成后改写成“任务结果容量”。

结算完成后任务进入`轮次已收束`并等待自我后继决议。目标未达成只写入任务轮次结论；任务管理不得据此自动建立新任务轮次、新筹办轮次或筹办工作包。只有自我形成`继续`决议后，任务管理才建立新任务轮次并从初次筹办开始。
