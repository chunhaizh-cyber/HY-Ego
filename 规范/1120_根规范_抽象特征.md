# 1120 根规范 抽象特征

编号：1120
日期：20261105
版本：v0.15
状态：正式根规范

直接上级规范：0050。

直接依赖规范：无。

相关边界规范：1130、1180、2220、4110、4115、4120、4125、4140、4150、4151、4160、4180、4181、4182、6130、6190、7160。

## 1. 根定位

抽象特征是特征类型、值域、叶子或复合形态以及抽象特征结构的权威本体。正式特征类型必须由稳定的特征定义身份及其结构关系表达，不是裸词面、名称词条、名称关系、硬编码枚举或显示文本。

状态抽象统一回到抽象特征结构；不得另建与抽象特征平行的权威抽象状态树。

## 2. 本项目承载

海中鱼巣以“特征定义节点”承载抽象特征：特征类型的定义节点及稳定句柄、唯一非零稳定主键、抽象特征之间的结构关系或具名组成关系、值域与模板条件的正式关系，以及用于定位的索引。

三种对象身份和结构角色分别成立：

| 对象 | 回答 |
| --- | --- |
| 特征类型FT（本规范） | 这是什么类型、值如何解释 |
| 实例特征F（1130） | 某持有者在该类型上的当前值、去重历史值及命中次数、标准值和聚合值域 |
| 特征概念（7160） | 该类型的一个规范化允许域 |

F引用FT；概念细分不产生新的类型定义。

词条只通过正式概念名称关系充当名称和查找材料；机器判断、需求匹配、方法能力匹配和特征值解释必须回读特征定义节点或目标概念的正式强类型身份。

## 3. 事实与边界

1. 抽象特征可以表达值域、复合组成、抽象上下位关系和状态模板条件。
2. 抽象特征定义不得承载具体准确值、存在当前采用、业务完成结论、安全或服务画像、运行期评估结果。
3. 叶子与复合形态必须由正式结构关系成立，不得由名称后缀、显示类型或注释推断。
4. 同一词条即使命中一个特征名称，也只证明名称关系成立；特征类型必须从目标概念和特征定义节点读回，不得把词条改成类型入口或在词条上保存类型。
5. 不得新增硬编码“特征类型总枚举”取代特征定义节点；默认初始化可以显式创建定义节点，但结果必须进入正式抽象特征结构。
6. 实例期把多个已经成立的一次特征事实组成一个静态事实集合，不新增抽象类别定义，也不改变成员的特征定义；该结构由1130的子规范4125治理。事实集合身份、成员关系或显示名称不得反向冒充抽象特征类型、概念或归类结论。

## 4. 写入、读取与验证

抽象特征只能由特征领域服务创建、绑定和修改；数据操作层在一次组合发布中完成节点、类型化记录、关系和索引。特征值服务、高级业务服务、外设、显示层和普通调用方不得直接创建或改写抽象特征。

读取方必须通过特征领域服务取得稳定定义身份、结构关系和值域材料。读回至少确认：节点当前有效、类型为特征、稳定主键唯一、定义角色成立、全部关系端点有效。

## 5. 生命周期与当前性

抽象特征身份长期存在，定义按当前状态维护，可以随认知原地修订；变化事实由状态和动态信息承载，定义本身不另外保留版本或历史内容。引用它的状态和其它事实按当前定义解释。名称关系变化、词索引重建或显示名称变化不改变抽象特征身份。

## 6. 类型来源与初始化

特征类型来源分为三类，均必须形成正式FT，不能用名称、代码枚举或缺少某条关系临时猜测来源：

1. **外设能够获取**：由外设提供真实输入，系统初始化时把其规格、解析和比较方式形成正式定义。空间坐标等原始特征值属于此类。
2. **先天定义**：由现行正式规范直接给出语义和值域，不要求也不得虚构外设提供者。
3. **后天派生**：由已成立类型、概念和正式生成规则派生，并保持可追溯来源。

安全值是先天定义FT，由唯一自我持有唯一非负I64实例特征，值域`0..I64_MAX`。服务值是先天定义FT，由唯一自我持有唯一有符号I64实例特征；6190只规定合法结算和衰减，不建立第二工程账户。两根每次按唯一自我和各自类型根fresh定位实例特征。

安全值与服务值初始化使用固定的完整请求材料；该材料只在同一次组合请求内部用于收敛重复请求，不构成公共请求账或合同版本。

先天定义FT的形成不产生外设、需求、当前F、状态、动态或其它实例事实。随后必须由概念唯一owner形成引用该FT完整允许域的普通特征概念，挂在特征根下；FT和完整域概念身份独立，初始化只有在两层均正式读回后才可交付。

类型来源、叶子 / 复合形态和1180阶次分别回答不同问题，不得互相替代。特征类型的完整允许域与特征概念的分类域分开；域形成参数由4120提供，按类型共享积累及概念细分由7160展开。准确F不维护域集合或分裂子节点。
