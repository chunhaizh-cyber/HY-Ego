# 0050 项目通用机器逻辑与禁止性规则总纲

编号：0050
日期：20260809
状态：正式上级规范

## 1. 定位

本规范规定海中鱼巣全部机器逻辑共同服从的原则性规则。本项目采用运行期内存已发布代次权威、SQL 持久恢复证据、类型化值、L1—L5 具名数据结构服务合同和位于 L5 之外的业务解释。SQL 行、查询结果、控制面板投影和恢复材料均不得直接裁决运行期事实。

具体对象字段、算法、接口和业务流程仍必须进入对应根规范或子规范；海鱼确认稿本身不直接成为本项目规范，也不授权代码实施。

## 2. 权威与事实分层

1. `规范/规范目录.md` 及其登记规范是本项目机器逻辑的唯一正式定义来源。
2. 程序行为、外部材料、候选稿、日志、界面、缓存和过程记录都不能越过本目录直接裁决本项目事实。
3. 机器事实必须同时具有稳定编码、确定类型、合法写入方、可追溯来源、创建 / 退出生命周期以及完整发布证据。事实代次只描述一次原子发布和快照边界，不是任何对象的身份版本。
4. 本项目采用以下权威分账：

```text
内存已发布当前事实代次    = 唯一运行期机器事实权威；承载节点、关系、值、创建 / 退出生命周期
SQL Server / 独立材料     = 已发布事实代次的持久证据、隔离恢复输入、应急审计材料和人机交互投影
内存缓存 / 索引 / 统计投影 = 从指定内存已发布代次确定重建的非权威加速结构
```

5. 一次运行期事实写集完成全部候选确认后原子发布新的内存代次，该原子代次发布是运行期事实的唯一线性化点。候选对象、SQL 行、材料文件、缓存命中、索引命中、函数返回和未发布内存对象均不等于事实已经发布。
6. 需要跨进程保存的事实必须由 SQL 和 / 或不可变材料保存足以验证已发布事实代次的编码、类型、载荷摘要、关系、创建 / 退出生命周期和发布证据；其内容只能经 4070 隔离恢复、完整校验和领域重新准入后形成新的内存已发布事实代次，普通业务不得直接以 SQL 查询结果作为当前事实。
7. 进程启动且尚未完成恢复发布时不存在运行期权威。恢复完成后，恢复服务原子发布的内存代次成为唯一运行期权威；SQL 原行及交互投影仍不取得运行期裁决权。

## 3. 数据服务分层与业务边界

L1—L5 全部属于基础数据服务。层号只区分所拥有的数据结构、组合层次和依赖方向，不授予任何业务含义：

```text
L0 物理存储：SQL Server、独立材料文件及其完整性能力
L1—L5 基础数据服务：按正式登记分别拥有原子或组合数据结构的增、删、改、查
L5 之外的业务层：构造数据结构请求，解释业务名称、资格、目标、动作和结果
```

1. 分层表示数据结构所有权和接口承接，不表示业务语义、代码目录、类、进程、部署单元、能力成熟度或必须按编号顺序实施。
2. L1—L5 均不得判断安全、服务、需求、任务、方法、自我、存在、场景、状态、动态、因果等业务含义；这些名称即使出现在兼容代码中，也只能作为待迁移标签，不能取得本层裁决权。
3. 每类数据结构必须有唯一写入服务。该服务只校验结构形状、类型、引用、生命周期、期望代次、幂等和事务条件，不校验业务资格、业务目标或业务结果。
4. 较高数据服务可以通过具名公开合同组合较低数据结构；不得直达仓库、SQL、材料文件或内部事务，也不得成为相同结构的第二解释者或第二写入者。
5. L5 之外的业务调用方负责把业务裁决转换为强类型数据结构请求，并解释返回结果；它不得取得原始 SQL 事务、锁、可变仓库对象、内部撤销权或缓存写权。
6. 一个物理底座可以承载多棵逻辑树和多张图；关系是事实，树 / 图 / 列表是值式投影，索引只是入口或候选召回。
7. L1—L5 之间以及同层不同结构所有者之间，只允许通过具名、强类型服务合同约束的公开服务函数交互。合同至少冻结服务身份、函数身份、请求 / 结果类型、稳定编码、期望事实代次、一致性边界、结构化非成功、所有权和生命周期；不得携带业务资格、业务操作标签、业务意图、领域见证或业务结果解释。
8. 不强制调用按层号逐级代理。消费者按真实结构依赖直接调用拥有所需数据结构的具名服务；不存在结构依赖的中间层不得成为转发壳、第二解释者或隐式授权者。
9. 服务只返回调用方拥有的不可变完整投影，不得泄漏仓库可变对象、SQL、材料路径、锁、事务、缓存、内部写集、候选确认或撤销能力。
10. 服务合同保持兼容时，提供者可以替换本层内部结构、算法、缓存和物理存储而不要求消费者修改；若字段语义、分支、所有权或一致性边界改变，必须建立新的具名合同 / DTO 身份并明确兼容、迁移或拒绝关系，禁止静默改变或用递增版本字段猜测兼容。

## 4. 稳定编码、类型化值与关系

1. 节点、关系和值共用不透明、非零、全局不可复用的稳定编码。固定仓库号、节点号、关系号、句柄数值、内存地址、线程号、路径、名称和显示顺序不得成为公开机器编码。
2. 内部编码候选在所属内存事实代次原子发布前不是事实；不得外泄、复用或被业务资格引用。已发布或已退出编码永久占用，不得复用。
3. 通用编码与业务解释分权：L1—L5 可以发布业务中性的数据结构；只有 L5 之外的业务层可以解释这些结构代表什么业务对象。任一数据层写入成功都不自动建立自我、需求、任务、方法、资格或范围对象。
4. 属性类型由具名类型节点表达，至少具有稳定编码、表示 / 值域、所有者声明、生命周期和显式兼容关系。类型解释发生不兼容变化时建立新的类型节点；兼容性只能按明确方向、操作和直接关系裁决，不因同名、版本号大小、结构相似或兼容链自动传递。
5. 禁止通用 JSON、主信息、万能 I64 槽、任意字节包或无类型联合容器承担跨领域权威值。
6. 值必须绑定所属节点编码、属性类型节点编码、不可变材料或材料引用、来源编码、创建 / 退出事实代次及发布证据；当前属性槽只能指向该节点该属性类型的一个当前值编码。
7. 对象拓扑、归属、组成、来源和引用由有向关系事实承载；关系替换使旧关系退出并以新编码建立新关系，历史事实不可原地覆写。当前值由节点属性槽与值事实承载，不复制为关系或子节点表。
8. 索引和便利字段不得成为节点属性槽或关系的第二权威表达；命中后必须回读同一内存已发布事实代次的节点、关系和值。

## 5. 事实发布、幂等与并发

1. 可判定的编码、类型、公开调用权限、期望事实代次和槽 / 关系一致性必须在第一笔数据写入前拒绝；业务前置不得进入 L1—L5 数据服务合同。
2. 一次数据结构写集必须在一个明确内存事实事务中形成候选、完成全部参与者确认，并原子发布一个新代次。材料文件或 SQL 持久证据如需准备，只能形成未取得运行期事实权的候选；失败时不得出现公开可读半结构。
3. 新当前值与旧值退出、关系替换、创建 / 退出事实代次和运行期发布证据必须在同一内存代次发布中闭合。
4. 幂等必须绑定稳定幂等身份和完整请求语义：同键同义返回原结果，同键异义返回冲突；不得以“记录存在”冒充幂等。
5. 期望事实代次或并发条件不符时不得覆盖当前事实。内存代次发布结果未知时只能使用原幂等身份和发布见证回读收敛，不得生成新编码或重放异义请求。
6. 内存代次发布前失败必须零普通业务可读事实；发布后不得用撤销、SQL 旧行或材料文件伪装回滚。发布后读回不一致属于内部不一致，进入审计 / 恢复路径。
7. SQL 持久化成功不等于运行期事实发布成功；SQL 持久化失败、结果未知、落后或损坏必须形成具名持久证据状态和后继策略，不得静默以 SQL 当前行替换、回退或覆盖内存已发布代次。

## 6. 查询、缓存、恢复与回收

1. 当前读取、历史读取、审计读取和恢复候选读取必须显式分离，结果均为调用方拥有的不可变值式快照。
2. 组合投影必须声明事实截止代次、读取类别和完整性；不得把默认值、空编码或隐式“最新”用于补齐缺失事实。
3. 缓存读取至少区分命中、确定未命中和缓存不可用。缓存不可用只触发回源或具名非成功，不能改变业务结果。
4. 缓存与索引的失效、清空和重建只能以指定内存已发布代次为来源；重建过程不得写业务事实。SQL 不得成为普通运行期缓存或索引的回源权威。
5. 恢复输入先进入隔离候选，按编码占用、类型、节点属性槽、关系端点、创建 / 退出生命周期、材料摘要和发布证据互证，再通过正常结构校验与内存事实事务一次原子发布。
6. 恢复不得从材料目录、SQL 或缓存补造缺失对象，不得复义身份、复活已退出合同或绕过业务授权；材料与当前内存事实冲突时必须具名拒绝，不能择优拼接。
7. 退役先在内存已发布代次中改变生命周期并保留历史和引用保护；持久证据同步与材料物理回收按专门合同后继执行，且不得破坏任何当前、历史、审计或恢复所需引用。

## 7. 特征、世界、状态、动态与因果

本节定义 L5 之外业务层可以采用的业务解释，不授予 L1—L5 自动生成、判断或验证这些业务含义的权力。L1—L5 若承载相关记录，只按其正式数据结构合同执行增、删、改、查。

1. 已发布特征值载荷不可原地改变；变化形成新的值事实编码并使旧值退出。特征的宿主、类型、唯一当前值和历史值必须分账。
2. 存在本体与内部场景分离；只有把一个存在作为场景观察时才按需建立内部场景，不要求所有存在预建内部世界。
3. 场景可以组成多棵单根、单父、无环逻辑树；同一存在在同一棵场景树中只有一个当前直接位置。现实世界树唯一，自我当前所在场景必须属于它。
4. 每个世界拥有独立逻辑序列，世界之间的节点、关系、状态、动态、因果和属性值严格隔离。
5. 原子状态是同一主体的一个特征精确快照加时间戳；同一采样位置只记录一个特征。多个状态只有在明确时间段和组成合同下形成复合状态。
6. 相邻同主体、同特征类型且值发生变化的状态形成原子动态；首个状态和无变化读取不产生动态。动态链只在其场景范围内有效。
7. 每个已发布状态触发一次幂等整理，但不保证必然产生动态。内部场景形成的动态保留内部证据，再由动态领域服务形成所在场景的新外层动态，不能改写内部身份。
8. 因果由条件、动作和结果的角色化事实组成；条件和结果是状态，动作可引用方法。无动作证据但条件必然导向结果时属于被动因果。
9. 一次完整证据可以形成实例因果；重复证据用于稳定性、统计和抽象，不是实例因果的最低准入次数。间接因果和目标层级只作当前图上的值式投影。

## 8. 自我、需求、任务与方法

本节全部属于 L5 之外的业务规则。L1—L5 只保存调用方提交的相关数据结构，不判断自我资格、目标正确性、需求成立、任务完成或方法有效。

1. 自我是项目根概念，由唯一稳定存在节点编码承载，不建立候选自我列表或运行期角色选择。自我结构变化以新的关系和值事实表达，不修改既有事实。
2. 名称、配置、路径、内存地址、线程、缓存键、场景位置、显示顺序和日志都不能建立或替代自我身份。
3. 项目根自我资格是承载存在节点的业务语义，不是第二身份。项目正式事实范围、范围节点和范围对象建立授权由具名领域责任裁决；授权接受不等于对象已经发布。
4. 安全目标和服务目标都使用各自独立的有符号 I64 根值域与 `I64_MAX` 目标；身份、事实、证据和治理路径分离。只有已证明严格正差距才能形成需求候选，零差距不得伪造需求。
5. 只有自我可以确认需求。需求、任务树和方法列表是三套独立结构，只通过正式引用和因果关系连接。
6. 同一有效来源需求复用唯一任务树。任务管理负责创建 / 查找任务、更新优先级和派发；优先级不抢占已经运行的工作。
7. 不同任务可以并行；同一任务同一时刻最多一个筹办或执行工作。每轮实例方法执行并形成结果后归还调度权。
8. 一个筹办回合最多实例化三个可能达成目标的方法；一次任务执行只运行一个实例方法。
9. 方法只声明预期状态变化，不能以返回值、日志或预期输出自证实际结果。实际结果必须通过独立权威回读、重新比较和因果材料成立。
10. 每轮结果形成新的实例方法树和结果材料；学习旁路只读消费其引用。抽象方法变化建立新的方法事实，不得反向修改已经实例化的方法，运行中任务继续使用原快照。
11. 任务完成、需求满足和价值结算保持独立裁决。需求暂时满足、失效、恢复有效和永久退役必须分开；永久退役按任务树后需求的顺序处理并保留必要历史证据。

## 9. 结构化非成功与内部不一致

1. 写前无效、未找到、已退出、事实代次漂移、格式不支持、公开调用权限不足等使用具名结构化结果，零数据写入；业务前置不满足由 L5 之外业务层返回，不得伪装成数据层状态。
2. 合法等待、候选为空、目标已满足和显式未实现属于协议内结果，不得压成裸失败。
3. 前置通过后出现身份复义、关系矛盾、内存发布读回不一致、半结构可见或事实链缺失，属于内部不一致；必须停止依赖路径并进入审计 / 恢复，不能包装成普通业务拒绝。
4. 日志、弹窗、扫描器和事后校验只能诊断，不能修复或改变机器事实。

## 10. 仍未裁决的边界

下列海鱼确认稿中明确保留为未决的内容不进入本次正式机器语义：

- L1—L5 各层具体拥有的数据结构族及旧业务命名接口的重分类、迁移或退出；
- 4200 旧世界树业务门面及相关业务资格、状态整理、动态生成合同迁出 L1—L5 后的上层业务接口；
- 各类型合同、特征值类别和材料的精确数据结构编码、C++ / SQL 接口与 ABI；
- 复合状态、动态聚合、复杂动态和因果抽象的精确算法；
- 需求权重完整维度、任务状态全集、方法实时选择算法、超时和资源预算；
- 方法缺口向准备、学习、结构补齐或实现修复的最终分流；
- 停机、休眠、终止、可唤醒等待和零差距保证机制的精确实现；
- 项目事实范围、资格规则、授权证据和范围事实替换的精确数据合同。

这些事项只能在对应子规范完成裁决后进入设计和实施，不得从旧代码或确认稿未决段落补造。
