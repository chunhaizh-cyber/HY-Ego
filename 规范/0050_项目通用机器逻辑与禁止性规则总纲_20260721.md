## 1. 定位

本规范规定海中鱼巣全部机器逻辑共同服从的原则性规则。本项目采用运行期内存已发布代次权威、SQL 持久恢复证据、类型化值、`DATA-L1`—`DATA-L3` 具名数据结构服务合同和位于 `DATA` 之外的业务解释。SQL 行、查询结果、控制面板投影和恢复材料均不得直接裁决运行期事实。

具体对象字段、算法、接口和业务流程仍必须进入对应根规范或子规范；海鱼确认稿本身不直接成为本项目规范，也不授权代码实施。

## 2. 权威与事实分层

1. `规范/规范目录.md` 及其登记规范是本项目机器逻辑的唯一正式定义来源。
2. 程序行为、外部材料、候选稿、日志、界面、缓存和过程记录都不能越过本目录直接裁决本项目事实。
3. 机器事实必须同时具有稳定编码、确定类型、合法写入方、可追溯来源、创建 / 退出生命周期以及完整发布证据。这是完整存储事实的成立条件，不要求每个 DATA-L2 公开对象复制全部事实元数据。事实代次只描述一次原子发布和快照边界，不是任何对象的身份版本。
4. 本项目采用以下权威分账：

```text
内存已发布当前事实代次    = 唯一运行期机器事实权威；承载节点、关系、值、创建 / 退出生命周期
SQL Server / 独立材料     = 已发布事实代次的持久证据、隔离恢复输入、应急审计材料和人机交互投影
内存缓存 / 索引 / 统计投影 = 从指定内存已发布代次确定重建的非权威加速结构
```

5. 一次运行期事实写集完成全部候选确认后原子发布新的内存代次，该原子代次发布是运行期事实的唯一线性化点。候选对象、SQL 行、材料文件、缓存命中、索引命中、函数返回和未发布内存对象均不等于事实已经发布。
6. 需要跨进程保存的事实必须由 SQL 和 / 或不可变材料保存足以验证已发布事实代次的编码、类型、载荷摘要、关系、创建 / 退出生命周期和发布证据；其内容只能经 4070 隔离恢复、完整校验和领域重新准入后形成新的内存已发布事实代次，普通业务不得直接以 SQL 查询结果作为当前事实。
7. 进程启动且尚未完成恢复发布时不存在运行期权威。恢复完成后，恢复服务原子发布的内存代次成为唯一运行期权威；SQL 原行及交互投影仍不取得运行期裁决权。
8. 七族当前结构身份确认与历史见证的公开合同分流不是 SQL、材料、消息或恢复格式版本。持久恢复只互证并重建 L1 中性节点、关系、值、生命周期和发布证据；恢复完成后，L2 消费者必须经届时有效的具名当前确认或历史见证合同重新读取，不得以旧共同当前入口、持久化 DTO 或格式兼容壳取得当前身份。

### 2.1 新特征值、特征信息对象与内部可靠性

新 DATA-L2 特征值对象的封闭字段以 2100 第 2 节为准；本规范关于发布证据、事实代次、幂等与生命周期的通用条款不使它们成为该对象字段或普通调用的默认公开参数。L2 决定结构组合及共同提交范围，L1 提供可靠读写和原子执行；既有节点、关系、值事实和其它具名 ABI 的可靠性约束仍在原适用范围有效。本项不改变状态、动态、任务等其它对象合同。

新 DATA-L2 特征信息按 1130 四逻辑字段表达：身份、正式类型、固定准确值和可选概念名称引用；4110 展开准确内容与操作，7160 展开按类型共享积累、概念形成和命名，4120 / 4180 提供类型与比较规则。当前采用和已知识别材料由存在关联表达，特征自身不维护当前 / 历史值集合、域或分裂。旧五字段与宿主实例槽不再取得新模型生产资格；L1 通用可靠性及已有合法引用仍保持。

## 3. 数据服务分层与业务边界

当前基础数据架构只定义三层：

```text
L0 物理持久层：SQL Server、独立材料文件及其完整性能力
DATA-L1 纯事实内核：节点、关系、值的增删改查，事务、幂等、事实代次、当前 / 历史读取和 owner 隔离
DATA-L2 强类型结构服务：保存并校验具名结构的字段、关系、基数、顺序、生命周期和结构引用
DATA-L3 结构聚合：组合 DATA-L2 公开能力形成世界树结构聚合与概念空间结构聚合
DATA 之外的业务层：构造结构请求，解释业务名称、资格、目标、动作和结果
```

`DATA-L4`、`DATA-L5` 当前只保留层号而不定义职责；禁止为了维持旧五层叙述发明转发、解释或聚合层。

### 3.1 全局 ARCH 五层命名空间映射（20260824）

本项目同时使用全局架构命名空间 `ARCH-L1`—`ARCH-L5`。它不是对 `DATA-L1`—`DATA-L5` 的改名，也不授权把现有 C++ 的 `L2` 名称直接解释为某一全局层：

```text
ARCH-L1 = 统一事实内核                         ↔ DATA-L1
ARCH-L2 = 通用基础结构（世界、语言、概念基础结构） ↔ DATA-L2
ARCH-L3 = 世界树、概念树/概念空间聚合            ↔ DATA-L3
ARCH-L4 = 需求、任务、方法及其业务治理            （不定义 DATA-L4）
ARCH-L5 = 自然语言理解/表达与名称绑定裁决         （不定义 DATA-L5）
```

`ARCH-L5 -> ARCH-L4/ARCH-L3/ARCH-L2`、`ARCH-L4 -> ARCH-L3/ARCH-L2`、`ARCH-L3 -> ARCH-L2 -> ARCH-L1` 是唯一依赖方向，禁止反向依赖。ARCH-L2 的存在、状态、动态和因果 owner 只治理世界结构。ARCH-L4 的需求、任务、方法具有各自正式业务治理身份和记录；其中任务正式虚拟存在 `Vt` 是任务特征、任务状态和状态迁移记录的唯一宿主，不进入世界存在族或世界树，也不构成 ARCH-L2 世界状态的第二权威。现有 `L2需求/任务/方法` 名称只作 ARCH-L4 结构记录面实现名。ARCH-L5 只能经下层公开服务提交词条、名称、别名、定义和表达绑定，不直接改写下层身份或字段。

概念身份语言无关，概念基础结构及概念—词条名称关系的结构 owner 归 ARCH-L2，概念树/空间聚合归 ARCH-L3，名称接受、表达和消歧裁决归 ARCH-L5；二次至 n 次特征复用同一特征身份、真实阶次和直接来源。该映射不改变 DATA 三层既有纯结构边界，具体 ABI、迁移顺序和原子 owner 由对应设计/计划冻结。

1. 分层表示数据结构所有权和接口承接，不表示业务语义、代码目录、类、进程、部署单元、能力成熟度或必须按编号顺序实施。
2. `DATA-L2` 具有“结构类型语义”：它可以知道某节点属于场景、词条、概念或不可变材料等当前基础结构族，并校验该族字段、关系、基数和生命周期；它不得判断词义是否正确、需求是否有效、任务是否完成、方法是否成功，也不得判断世界事实、状态、动态或因果的业务真实性。
3. `DATA-L2` 的当前穷尽范围以“独立结构 owner + 该 owner 的唯一公开服务面”为收口单位：节点 owner 固定为场景、存在、特征定义、特征实例、状态、动态、因果、语言、词条、概念、不可变材料十一项；独立关系 owner 固定为概念—词条名称关系一项。二次至 n 次特征、当前特征值、状态当前选择及各族内部关系并入其既有 owner，不独立计数。语素和词性不形成持久结构族；需求、任务、方法属于 `ARCH-L4` 业务治理，现有 `L2*` 名称仅作 `ARCH-L4` 结构记录面兼容实现名，不进入当前 `DATA-L2` 活跃范围；世界树和概念空间聚合属于 `DATA-L3`，名称接受、表达和消歧裁决属于 `ARCH-L5`。新增 DATA-L2 结构 owner 必须先修订本规范及对应子规范，不得由文件名、枚举追加或服务实现自行扩张。
4. `ARCH-L4` 内部必须分为结构记录面与业务应用面。结构记录面只机械保存、读取和校验调用方已经裁决的身份、关系、生命周期、版本、幂等、事实代次、当前 / 历史、原子发布、引用闭合和结构索引；业务应用面负责为什么建立、选择、推进、结束和判定，包括需求成立 / 当前满足、任务目标达成 / 任务完成结算 / 生命周期结束、方法适用 / 授权 / 执行成功。结构记录面不得替业务应用面作出这些判断。
5. 每类数据结构必须有唯一写入服务。该服务只校验结构形状、类型、引用、生命周期、期望代次、幂等和事务条件，不校验业务资格、业务目标或业务结果。
6. `DATA-L3` 只经 `DATA-L2` 具名公开合同聚合世界树和概念空间，不直达 `DATA-L1` 仓库、SQL、材料文件或内部事务，不复制 CRUD，不成为相同结构的第二解释者或第二写入者。概念的权威结构是多父 DAG；“概念树”只是在指定截止上的可重建值式投影。
7. `DATA` 之外的业务调用方负责把业务裁决转换为强类型数据结构请求，并解释返回结果；它不得取得原始 SQL 事务、锁、可变仓库对象、内部撤销权或缓存写权。
8. 一个物理底座可以承载多棵逻辑树和多张图。1150/4202场景四根及实例组织关系是实际节点和关系事实，不能以查询索引替代；读取形成的树/图/列表对象才是值式投影，索引只作入口或召回。实例组织树与概念多父图、跨树引用分账。
9. 数据服务之间以及同层不同结构所有者之间，只允许通过具名、强类型服务合同约束的公开服务函数交互。合同至少冻结服务身份、函数身份、请求 / 结果类型、稳定编码、期望事实代次、一致性边界、结构化非成功、结构唯一写入服务约束和所需公开生命周期；`L1结构所有者身份`及其生命周期只由提供者内部核对，不进入 各类公开身份来源见证及其读取成功谓词。其它具名 L2 结构结果中的旧 owner 兼容材料不得借本条重释，须由对应族 ABI 及 P04 / P08 后续裁决。不得携带业务资格、业务操作标签、业务意图、领域见证或业务结果解释。
10. 不强制调用按层号逐级代理。消费者按真实结构依赖直接调用拥有所需数据结构的具名服务；不存在结构依赖的中间层不得成为转发壳、第二解释者或隐式授权者。
11. 服务只返回调用方拥有的不可变完整投影，不得泄漏仓库可变对象、SQL、材料路径、锁、事务、缓存、内部写集、候选确认或撤销能力。
12. 服务合同保持兼容时，提供者可以替换本层内部结构、算法、缓存和物理存储而不要求消费者修改；若字段语义、分支、所有权或一致性边界改变，必须建立新的具名合同 / DTO 身份并明确兼容、迁移或拒绝关系，禁止静默改变或用递增版本字段猜测兼容。
13. 世界结构的当前身份确认与身份来源历史见证分开：当前只确认请求身份在同一读取截止有效，不回显身份来源载荷；历史返回该类合同所需的完整见证并明确证据截止。正常内容读取仍须返回完整内容。共同语义按4230，各类公开请求、结果、状态、成功谓词及Gread/H映射由专属子规范冻结，不要求恢复旧L2公共结果头、统一版本或七族函数模板；存在窄身份按4203，状态按4212。操作结果不是节点字段或第二事实。L1可靠性、引用保护、实例清理与其它专属合同不因公共协议退役删除。

准确特征信息新建以明确场景C和组织父P作为硬结构准入，缺失零身份/零F/零观察/零概念写；F内容、C已知引用及组织边共同发布，不暴露已成立无父F。唯一规则由1130、4110、4205承载，概念结果报告归7160；不增加F本体父字段、概念owner出生参与或L1领域语义。

## 4. 稳定编码、类型化值与关系

1. 节点、关系和值共用不透明、非零、全局不可复用的稳定编码。固定仓库号、节点号、关系号、句柄数值、内存地址、线程号、路径、名称和显示顺序不得成为公开机器编码。
2. 内部编码候选在所属内存事实代次原子发布前不是事实；不得外泄、复用或被业务资格引用。已发布或已退出编码永久占用，不得复用。
3. 通用编码与业务解释分权：数据层可以发布带结构类型语义的数据结构；只有 `DATA` 之外的业务层可以解释这些结构在当前业务中是否真实、有效、完成或成功。任一数据层写入成功都不自动建立自我、需求、任务、方法、资格或范围对象。
4. 属性类型由具名类型节点表达，至少具有稳定编码、表示 / 值域、所有者声明、生命周期和显式兼容关系。类型解释发生不兼容变化时建立新的类型节点；兼容性只能按明确方向、操作和直接关系裁决，不因同名、版本号大小、结构相似或兼容链自动传递。
5. 禁止通用 JSON、主信息、万能 I64 槽、任意字节包或无类型联合容器承担跨领域权威值。
6. 值必须绑定所属节点编码、属性类型节点编码、不可变材料或材料引用、来源编码、创建 / 退出事实代次及发布证据；当前属性槽只能指向该节点该属性类型的一个当前值编码。
7. 对象拓扑、归属、组成、来源和引用由有向关系事实承载；关系替换使旧关系退出并以新编码建立新关系，历史事实不可原地覆写。当前值由节点属性槽与值事实承载，不复制为关系或子节点表。
8. 索引和便利字段不得成为节点属性槽或关系的第二权威表达；命中后必须回读同一内存已发布事实代次的节点、关系和值。

## 5. 事实发布、幂等与并发

1. 可判定的编码、类型、合同版本、期望事实代次和槽 / 关系一致性必须在第一笔数据写入前拒绝；业务权限与其它业务前置不得进入数据服务合同。
2. 一次数据结构写集必须在一个明确内存事实事务中形成候选、完成全部参与者确认，并原子发布一个新代次。材料文件或 SQL 持久证据如需准备，只能形成未取得运行期事实权的候选；失败时不得出现公开可读半结构。
3. 新当前值与旧值退出、关系替换、创建 / 退出事实代次和运行期发布证据必须在同一内存代次发布中闭合。
4. 幂等必须绑定稳定幂等身份和完整请求语义：同键同义返回原结果，同键异义返回冲突；不得以“记录存在”冒充幂等。
5. 期望事实代次或并发条件不符时不得覆盖当前事实。内存代次发布结果未知时只能使用原幂等身份和发布见证回读收敛，不得生成新编码或重放异义请求。
6. 内存代次发布前失败必须零普通业务可读事实；发布后不得用撤销、SQL 旧行或材料文件伪装回滚。发布后读回不一致属于内部不一致，进入审计 / 恢复路径。
7. SQL 持久化成功不等于运行期事实发布成功；SQL 持久化失败、结果未知、落后或损坏必须形成具名持久证据状态和后继策略，不得静默以 SQL 当前行替换、回退或覆盖内存已发布代次。

## 6. 查询、缓存、恢复与回收

1. 当前读取、历史读取、审计读取和恢复候选读取必须显式分离，结果均为调用方拥有的不可变值式快照。
2. 组合投影必须声明事实截止代次、读取类别和完整性；不得把默认值、空编码或隐式“最新”用于补齐缺失事实。
3. 缓存读取至少区分命中、确定未命中和缓存不可用。缓存不可用只触发回源或具名非成功，不能改变业务结果。
4. 缓存与索引的失效、清空和重建只能以指定内存已发布代次为来源；重建过程不得写业务事实。SQL 不得成为普通运行期缓存或索引的回源权威。
5. 恢复输入先进入隔离候选，按编码占用、类型、节点属性槽、关系端点、创建 / 退出生命周期、材料摘要和发布证据互证，再通过正常结构校验与内存事实事务一次原子发布。
6. 恢复不得从材料目录、SQL 或缓存补造缺失对象，不得复义身份、复活已退出合同或绕过业务授权；材料与当前内存事实冲突时必须具名拒绝，不能择优拼接。
7. 退役先在内存已发布代次中改变生命周期并保留合同要求的历史和引用保护；实例状态 / 动态可以按具名保留策略进入物理清理，清理后只保留墓碑与紧凑幂等证据。其它持久证据同步与材料物理回收按专门合同后继执行，且不得破坏仍受合同保护的当前、历史、审计或恢复引用。

## 7. 特征、世界、状态、动态与因果

本节定义 `DATA` 之外业务层可以采用的业务解释，不授予数据层自动生成、判断或验证这些业务含义的权力。`DATA-L2` 若承载相关强类型结构，只按其正式结构合同执行增、删、改、查。

### 7.1 认知证据与工程正确性分界

1. 状态记录某一时间点的特征事实，动态记录已经发生的具体变化及其来源，因果记录由这些事实支持的概念化变化规律。三者构成本项目认知层可以引用的认知证据；“认知证据”不另设第四类生产事实、持久证明节点或专用证明关系。
2. 该口径不改变存在当前采用及准确特征读回的权威：状态是事实记录而不是当前属性槽，动态是变化记录而不是当前值，因果是规律而不是结果补造器。任何当前比较仍须按本规范第11节读取同一截止的当前值事实。
3. 需求、任务、方法、选择、执行冻结、现实执行授权、结算和后继决议可以作为具有独立业务作用、唯一 owner 和自身生命周期的治理事实存在；它们不是认知证据的新类别。治理事实需要解释判断来源时，可以引用同截止当前特征值完整投影、目标合同、已经发布的状态 / 动态 / 因果及必要既有治理上下文；当前特征值是比较权威而不是第四类认知证据，状态 / 动态不得替代它。不得为“证明该治理事实正确”再复制一套当前值、状态、动态、因果或建立证据专用节点 / 关系。
4. `G0 / G1`、期望事实代次、幂等身份与幂等账、事务候选 / 确认 / 发布、发布后读回、SQL 持久材料、恢复见证、消费水位、线程进入 / 完成条件、生命周期同步信号和检查摘要只服务工程正确性。它们可以保存在所属数据 / 恢复 / 审计内部边界，但不得解释为世界、认知、需求、任务或方法事实，也不得进入业务事实平面充当第二权威。
5. 工程正确性材料只回答“写入、读取、恢复和消费是否按合同完成”，不能回答系统“为什么这样判断”或“是否理解了该判断”。满足工程门禁不得自动生成状态、动态、因果、用途观察、裁决证据、授权证据或其它生产事实。

### 8.1 内部治理、现实观察与现实改变的授权边界（20260824）

项目必须先按实际动作效果区分：

```text
内部治理
    = 读取、比较、形成候选、选择、筹办、状态迁移、结果收束、结算编排和后继裁决等只改变内部治理事实的动作

现实观察
    = 以读取现实为目的，只把观察材料和认知事实带回内部，且不包含对外部对象、外部主体或受保护资源的可观察改变

现实改变
    = 预期或可能改变外部对象、外部主体、外部系统、物理环境或受保护资源状态的动作
```

内部治理相当于“想”，不需要自我现实执行授权；它仍必须遵守 owner、公开调用许可、结构写入许可、事务、幂等、当前性和数据安全合同。现实观察与现实改变不得混账：纯观察不需要自我现实执行授权；主动探测、设备运动、发射、外部通信、写外部系统或其它具有现实副作用的观察步骤，按现实改变步骤处理。

只有一份任务执行冻结中至少包含一个现实改变步骤时，才在任务已达到`待执行前选择`、执行前选择完成实例化与冻结后、任务进入执行阶段前取得一份正式`自我现实执行授权事实`；因此授权必然早于首个现实改变步骤。该事实由自我业务 owner 唯一裁决和发布，至少绑定自我、任务、任务轮次、筹办轮次、执行轮次、执行冻结身份与版本、实例方法及内容版本、被授权现实动作范围、事实截止、规则版本和发生时间。任一绑定材料变化使旧授权失效；同一授权不得扩张到新冻结、新任务轮次、未列动作或其它任务。

`自我现实执行授权事实`同时覆盖该冻结中的任务和实例方法，不再分别建立“任务授权”和“方法授权”。拒绝、等待、取消、任务后继决议、需求确认、方法发布准入、结构写许可、公开调用许可、调度优先级和安全硬否决都不是第二份正向执行授权。安全与生存服务只提供当前安全事实、调度材料和具名硬否决；它们不得正向授权现实动作，自我授权也不得绕过硬否决。

任务正常轮次固定为：

```text
筹办 -> 执行前选择和冻结 -> 自我综合判断 -> 合法派发与执行 -> 结果验证及尝试收束
-> 正式完成：通知自我，按任务身份结算一次
-> 尚未完成：由自我决定继续或等待；失败 / 取消只记录并处理结果
```

任务轮次、筹办轮次和执行轮次是三个不同身份。目标未达成是本轮验证结论，不触发任务结算，也不自动建立下一轮。尚未完成任务在轮次收束后，由自我形成继续、等待或结束 / 取消处理决议；结束不能把失败、取消或未知改写为完成。继续须建立新任务轮次并重新筹办、冻结和综合判断，含现实改变时重新取得唯一现实执行授权。已完成任务不再开启新轮次；需求后来未满足须按当前事实另行承接任务，不撤销或重复原任务结算。

### 8.2 状态驱动的任务筹办、需求确认与执行前选择（20260903）

1. 任务筹办是任务领域内部治理函数，由任务管理线程根据任务当前状态异步派发。一次调用只完成当前状态指定的一段工作：先多次找方法，方法范围完整覆盖后再多次查找并核验各候选方法的条件；它不采用方法，不形成路径、实例方法或执行冻结，也不建立需求、子需求或子任务。
2. 找方法阶段必须回显已覆盖 / 剩余范围和零个或多个`方法身份 + 内容版本`；查到第一条候选不等于完成。查条件阶段必须保留`方法身份 + 内容版本 -> 条件组 -> 核验结果`对应关系，并覆盖全部候选与条件组；不得摊平成任务级条件总表、按名称或哈希临时拼组，或因先发现一组具备就跳过其余候选。
3. 筹办通过 task owner 唯一入口补全当前`任务 + 任务轮次 + 筹办轮次`的信息和版本。每个已消费工作包只投递一条不可变强类型消息；任务管理独立读回任务、轮次、调用前状态、版本、已覆盖 / 剩余范围及本次结果后，才经正式 owner 提交状态迁移。消息交接与独立读回是双线确认，不是第二候选账、条件账、结果账、线程或 outbox。
4. 正常业务结果只描述找方法 / 查条件进度：继续找方法、方法完整且有候选、方法缺失、继续查条件、全部核验且至少一组具备、条件缺失。目标已完成、子目标承接、采用方法、路径、实例和冻结都不是筹办结果。
5. 资源 / 投递 / 发布未知时业务状态不前进，以原工作包和原幂等身份重试或读回；截止漂移使本次结果失效并在同一业务子状态重派；ABI、引用、断言和内部代码错误停止受影响调用。技术非成功不得伪装成方法缺失、条件缺失、等待或需求。
6. 方法 / 条件缺失只先成为当前任务材料。自我线程 fresh 读取父需求、目标合同、任务轮次和正式筹办材料后，独立产生并确认是否存在必要后继需求及其目标；task owner 只幂等记录并读回该 self 确认的正式任务子目标承接，需求 owner 只在独立读回后发布 / 复用子需求。筹办、manager、task owner 和需求 owner 均不得替代 self 产生或确认需求。
7. 适用性、实际采用、选择和冻结只在真实动作前的执行前选择入口进行。该入口 fresh 复核可用性和安全硬门，再在可比较候选中选择收益 / 付出综合代价最小的一项；代价可包含安全值或服务值收益 / 付出、时间成本及正式登记的其它成本。未知、不可比或并列最优不得任选。
8. 任何正式任务进入方法执行时，均在选择冻结后、真实派发前由自我作综合判断，读取当前需求活动资格、目标、收益 / 付出、资源冲突及安全材料。该内部治理决策不另造第二正向授权；只有含现实改变时才发布本规范第8.1节的唯一现实执行授权。筹办、结算、消息处理等内建函数不因此递归建立审批任务。
9. 安全硬否决和生存安全根控制态是不可抵销门槛。服务根只作为普通根需求坐标参与其正式需求收益判断；已退出的服务合同 / 余额、线程或队列状态不得伪装成选择余额。

## 9. 结构化非成功与内部不一致

1. 写前无效、未找到、已退出、事实代次漂移、格式不支持等使用具名结构化结果，零数据写入；业务权限或其它业务前置不满足由 `DATA` 之外业务层返回，不得伪装成数据层状态。
2. 合法等待、候选为空、目标已满足和显式未实现属于协议内结果，不得压成裸失败。
3. 前置通过后出现身份复义、关系矛盾、内存发布读回不一致、半结构可见或事实链缺失，属于内部不一致；必须停止依赖路径并进入审计 / 恢复，不能包装成普通业务拒绝。
4. 日志、弹窗、扫描器和事后校验只能诊断，不能修复或改变机器事实。

## 10. 仍未裁决的边界

下列海鱼确认稿中明确保留为未决的内容不进入本次正式机器语义：

- `DATA-L2` 各结构族的精确 CRUD 函数、DTO 版本、服务拆分和旧业务命名接口的重分类、迁移或退出；
- 4200 旧世界树业务门面及相关业务资格、状态整理、动态生成合同迁出数据层后的上层业务接口；
- 各类型合同、特征值类别和材料的精确数据结构编码、C++ / SQL 接口与 ABI；
- 复合状态、动态聚合、复杂动态和因果抽象的精确算法；
- 需求权重完整维度、任务状态全集、方法实时选择算法、超时和资源预算；
- 方法缺口向准备、学习、结构补齐或实现修复的最终分流；

- 项目事实范围、资格规则、准入证据和范围事实替换的精确数据合同。

这些事项只能在对应子规范完成裁决后进入设计和实施，不得从旧代码或确认稿未决段落补造。

## 11. DATA 无权限裁决与状态动态总则

1. `DATA-L1`—`DATA-L3` 不识别调用者业务身份，不判断谁有权读、写、改、删。业务 / 治理层必须在调用 DATA 前完成权限与资格裁决；DATA 请求和结果不得携带或生成业务许可结论。
2. 每类结构继续只有一个权威服务和事实来源。既有 L1 `owner`、所有者、`写入所有者`、其生命周期和写端口只表示调用者不可选择的内部结构分区，用于幂等命名空间、结构闭包、唯一事实来源和旧事实兼容，不表示数据归属、业务主体或调用资格，不进入 各类公开身份来源见证及其读取成功谓词。其它具名 L2 结构结果中的旧 owner 兼容材料须按对应族 ABI 逐项迁移，不能借其作为身份、资格或业务结果。
3. 旧 `许可拒绝` 数值只供旧 ABI、历史结果和持久材料解码，现行入口和新合同不得产生。内部端口 / 装配错误以 `内部不一致` 编码，结构分区冲突以 `引用冲突` 编码，锁或资源暂不可用以 `资源失败` 编码；三者均空载荷、零公开变化。
4. 状态本体只记录“特征类型 + 特征值 + 强时间”，不包含业务 owner、主体、场景、特征实例、任务、方法或用途；这些归属只通过强类型引用关系表达。具体世界观察必须按1160/4202完整绑定发生场景C、被描述存在E与状态S，被描述特征由E和S内正式FT确定，不另设属性身份或FT副本；场景组织及递归观察不以中性内容共享或孤立引用代替主体定位。状态不是特征当前值权威。
5. 涉及存在的业务比较先读取其当前采用，再按特征节点读取固定准确内容及目标合同；复合目标保持同截止完整读取。不能因旧 F 可读、名称相同、最后动态或被选状态而推定当前值；状态与动态仅作记录、触发、定位、历史追踪、解释和审计。
6. 实例状态与动态使用非负 UTC Unix epoch 纳秒绝对时间；抽象状态可以使用非负相对纳秒，一个状态身份只能采用一种时间语义。动态只记录具体发生，按1170/4211保存原子状态使用端点或直接子动态组合，两种变化内容互斥；实际时间从端点或成员派生，不另存发生时间字段。场景按4202组织动态实例，可复用变化模式只进入2220/7190的动态概念树。特征节点的数据操作不以创建状态 / 动态为前置；形成变化记录时遵循状态先独立发布并读回、动态后发布、场景再组织，首次记录不伪造无前状态动态，无变化不补造变化。按需二次特征值式投影不形成持久当前值、状态或动态。
7. 实例状态和实例动态是临时材料。保留策略必须分别提供非零有限的实例状态 TTL、实例动态 TTL、实例状态数量上限和实例动态数量上限；四项独立判断，不把两类数量相加为共同容量。TTL 一律从各材料首次正式形成时记录的 UTC 纳秒计算，不使用状态事件时间或动态成员事件时间；同类超量时按首次形成 UTC 纳秒、稳定身份升序确定最旧材料。
8. 清理先退出受影响实例动态，再退出不再被活动动态引用的实例状态；组合动态须把父子动态依赖纳入清理闭包，不返回成员缺失的假完整组。被清理状态的当前选择同代退出且不得回退旧状态；普通引用允许成为已过期引用。
9. 物理清理推进新事实代次，删除完整实例载荷，但保留最小墓碑和紧凑幂等记录。墓碑至少包含身份、结构类别、创建代次、清理代次、清理原因和原规范化请求摘要；历史读取命中墓碑时返回 `历史材料已清理` 和零完整载荷。
10. DATA 状态 / 动态服务只提供同步清理入口，不创建线程、定时器或后台任务。普通应用唯一运行宿主在数据上下文可用后立即维护一次，此后以 60 秒周期调用同一清理入口；无数据上下文的空运行宿主不绑定该回调。
11. 周期维护遇资源失败时保留原 G0、原幂等身份和原完整请求到下一周期；遇事实代次漂移时丢弃旧请求，正式读取新 G0、分配新幂等身份并在本周期最多重试一次，第二次漂移等待下一周期。内部不一致或维护身份序列耗尽形成结构化程序失败。
12. 周期维护幂等身份固定使用前缀 `0x4E43'0000'0000'0000`，低 48 位为进程生命周期内原子单调序列；当前存储未声明跨进程恢复该序列，进程重启可重新开始。抽象完成调用不得使用该前缀。
13. 任务阶段状态不属于本节世界状态 / 动态结构。任务首态和后继迁移必须经 ARCH-L4 task owner 的正式任务域入口写入并读回 `Vt` 上的任务状态和状态迁移记录，不得以世界状态、动态或当前选择替代 `Vt`。执行动作造成的世界特征变化仍按本节世界结构合同记录，与任务阶段状态分账。

## 7.2 世界主体、视角与概念依附补充裁决（20260912）

1. 世界树权威根是一个可正式读回的场景节点，进程普通应用只允许发布一个全局根引用；全局变量是权威根读回的受保护引用，不是第二根事实或调用方可改配置。
2. 世界树统一位置读取必须返回节点唯一结构父、父关系种类、父场景语境和世界根；根返回无父。场景视角和存在视角不得各自返回一套互相冲突的位置。
3. 场景四个实例组织锚继续按1150/4202存在。取消的是存在、特征、动态概念的独立本体总根，不是实例组织锚。
4. 概念挂接关系表达抽象身份所依据或适用的世界位置，不参与世界树单父和无环裁决；概念上下位仍保持多父无环，因果链按1190独立组织。
