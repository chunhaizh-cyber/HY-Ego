# 0050 项目通用机器逻辑与禁止性规则总纲

编号：0050
日期：20260802
状态：正式上级规范

## 1. 定位

本规范规定海中鱼巣全部机器逻辑共同服从的原则性规则。20260802 起，本项目采用已经完成冲突裁决的运行期内存已发布代次权威、SQL 持久恢复证据、类型化值、L1—L5 具名服务合同和业务闭环语义。SQL 行、查询结果、控制面板投影和恢复材料均不得直接裁决运行期业务事实。

具体对象字段、算法、接口和业务流程仍必须进入对应根规范或子规范；海鱼确认稿本身不直接成为本项目规范，也不授权代码实施。

## 2. 权威与事实分层

1. `规范/规范目录.md` 及其登记规范是本项目机器逻辑的唯一正式定义来源。
2. 程序行为、外部材料、候选稿、日志、界面、缓存和过程记录都不能越过本目录直接裁决本项目事实。
3. 机器事实必须同时具有稳定身份、确定类型、合法写入方、可追溯来源、版本 / 生命周期以及完整发布证据。
4. 本项目采用以下权威分账：

```text
内存已发布当前代次        = 唯一运行期机器事实权威；承载当前身份、类型化值、关系、版本和生命周期
SQL Server / 独立材料     = 已发布代次的持久证据、隔离恢复输入、应急审计材料和人机交互投影
内存缓存 / 索引 / 统计投影 = 从指定内存已发布代次确定重建的非权威加速结构
```

5. 一次运行期事实写集完成全部候选确认后原子发布新的内存代次，该原子代次发布是运行期事实的唯一线性化点。候选对象、SQL 行、材料文件、缓存命中、索引命中、函数返回和未发布内存对象均不等于事实已经发布。
6. 需要跨进程保存的事实必须由 SQL 和 / 或不可变材料保存足以验证已发布代次的身份、版本、摘要、关系、生命周期和发布证据；其内容只能经 4070 隔离恢复、完整校验和领域重新准入后形成新的内存已发布代次，普通业务不得直接以 SQL 查询结果作为当前事实。
7. 进程启动且尚未完成恢复发布时不存在运行期权威。恢复完成后，恢复服务原子发布的内存代次成为唯一运行期权威；SQL 原行及交互投影仍不取得运行期裁决权。

## 3. 语义分层与服务边界

本项目按语义责任分为：

```text
L0 物理存储：SQL Server、独立材料文件及其完整性能力
L1 通用数据基座：稳定身份、类型合同、类型化值、关系、事务、查询、恢复和缓存
L2 世界语义：特征值、特征、存在、场景、状态、动态、因果及世界组合
L3 抽象概念与稳定词身份、词面和映射
L4 需求、任务、方法与自我治理
L5 未来语言信息；当前暂缓，只能消费 L3 稳定词身份
```

1. 分层表示语义责任和接口承接，不表示代码目录、类、进程、部署单元、能力成熟度或 L2—L5 必须按编号顺序实施。
2. L1 必须业务中性，不得出现安全、服务、需求、任务、方法、自我资格或世界语义。
3. 每类业务事实必须有唯一领域写入服务。领域服务负责业务准入和语义；L1 只负责中性结构与事务。
4. 世界等组合服务只能调用具名领域服务，不得直达 L1 原始写入口、SQL、材料文件或内部事务。
5. 普通调用方、治理编排和显示层不得绕过领域服务。调用方不得取得原始 SQL 事务、锁、可变仓库对象、内部撤销权或缓存写权。
6. 一个物理底座可以承载多棵逻辑树和多张图；关系是事实，树 / 图 / 列表是值式投影，索引只是入口或候选召回。
7. L1—L5 之间以及同层不同事实所有者之间，只允许通过具名、版本化、强类型服务合同约束的公开服务函数交互。合同至少冻结服务身份、函数身份、合同版本、请求 / 结果类型、稳定身份、采用版本、一致性边界、结构化非成功、所有权和生命周期。
8. 不强制调用按 `L5 -> L4 -> L3 -> L2 -> L1` 逐级代理。消费者按真实依赖直接调用拥有所需事实的具名服务；不存在依赖的中间层不得成为转发壳、第二解释者或隐式授权者。
9. 服务只返回调用方拥有的不可变完整投影，不得泄漏仓库可变对象、SQL、材料路径、锁、事务、缓存、内部写集、候选确认或撤销能力。
10. 服务合同保持兼容时，提供者可以替换本层内部结构、算法、缓存和物理存储而不要求消费者修改；若字段语义、版本规则、分支、所有权或一致性边界改变，必须发布新合同版本并明确兼容、迁移或拒绝规则，禁止静默改变。

## 4. 稳定身份、类型化值与关系

1. 长期对象使用不透明稳定身份。固定仓库号、节点号、关系号、句柄数值、内存地址、线程号、路径、名称和显示顺序不得成为公开机器身份或跨版本 ABI。
2. 内部身份候选在所属内存事实代次原子发布前不是事实；不得外泄、复用或被业务资格引用。已发布或已退役身份永久占用，不得复用。
3. 通用身份与业务资格分权：L1 可以发布业务中性的身份，领域服务才可赋予具名业务对象语义。通用身份成功不自动建立自我、需求、任务、方法或范围对象。
4. 类型合同必须具有稳定身份、合同版本、值域 / 表示、所有者声明、状态和兼容声明。兼容性只能按明确方向、操作和直接声明裁决，不因同名、版本号大小、结构相似或兼容链自动传递。
5. 禁止通用 JSON、主信息、万能 I64 槽、任意字节包或无类型联合容器承担跨领域权威值。
6. 类型化值必须绑定所属稳定身份、类型合同身份和版本、值记录版本、当前性、材料或材料引用、来源及发布证据。
7. 对象拓扑、归属、组成、来源、当前值和引用由版本化关系事实承载；关系身份、版本和生命周期分离，历史版本不可原地覆写。
8. 索引和便利字段不得成为关系的第二权威表达；命中后必须回读同一内存已发布代次的身份、关系、值和版本。

## 5. 事实发布、幂等与并发

1. 可判定的身份、类型、权限、版本、关系和业务前置必须在第一笔业务写入前拒绝。
2. 一次业务事实写集必须在一个明确内存事实事务中形成候选、完成全部参与者确认，并原子发布一个新代次。材料文件或 SQL 持久证据如需准备，只能形成未取得运行期事实权的候选；失败时不得出现普通业务可读半结构。
3. 新当前与旧当前退出、关系换代、版本推进和运行期发布证据必须在同一内存代次发布中闭合。
4. 幂等必须绑定稳定幂等身份和完整请求语义：同键同义返回原结果，同键异义返回冲突；不得以“记录存在”冒充幂等。
5. 预期版本或并发条件不符时不得覆盖当前事实。内存代次发布结果未知时只能使用原幂等身份和发布见证回读收敛，不得生成新身份或重放异义请求。
6. 内存代次发布前失败必须零普通业务可读事实；发布后不得用撤销、SQL 旧行或材料文件伪装回滚。发布后读回不一致属于内部不一致，进入审计 / 恢复路径。
7. SQL 持久化成功不等于运行期事实发布成功；SQL 持久化失败、结果未知、落后或损坏必须形成具名持久证据状态和后继策略，不得静默以 SQL 当前行替换、回退或覆盖内存已发布代次。

## 6. 查询、缓存、恢复与回收

1. 当前读取、历史读取、审计读取和恢复候选读取必须显式分离，结果均为调用方拥有的不可变值式快照。
2. 组合投影必须声明事实截止、版本和完整性；不得把默认值、空身份或隐式“最新”用于补齐缺失事实。
3. 缓存读取至少区分命中、确定未命中和缓存不可用。缓存不可用只触发回源或具名非成功，不能改变业务结果。
4. 缓存与索引的失效、清空和重建只能以指定内存已发布代次为来源；重建过程不得写业务事实。SQL 不得成为普通运行期缓存或索引的回源权威。
5. 恢复输入先进入隔离候选，按身份、类型、关系、版本、生命周期、材料摘要和发布证据互证，再通过正常领域准入与内存事实事务一次原子发布。
6. 恢复不得从材料目录、SQL 或缓存补造缺失对象，不得复义身份、复活已退出合同或绕过业务授权；材料与当前内存事实冲突时必须具名拒绝，不能择优拼接。
7. 退役先在内存已发布代次中改变生命周期并保留历史和引用保护；持久证据同步与材料物理回收按专门合同后继执行，且不得破坏任何当前、历史、审计或恢复所需引用。

## 7. 特征、世界、状态、动态与因果

1. 已发布特征值载荷不可原地改变；变化形成新值记录或新版本并保留历史。特征的宿主、类型、唯一当前值和历史值必须分账。
2. 存在本体与内部场景分离；只有把一个存在作为场景观察时才按需建立内部场景，不要求所有存在预建内部世界。
3. 场景可以组成多棵单根、单父、无环逻辑树；同一存在在同一棵场景树中只有一个当前直接位置。现实世界树唯一，自我当前所在场景必须属于它。
4. 每个世界拥有独立逻辑序列，世界之间的身份、关系、状态、动态、因果和版本严格隔离。
5. 原子状态是同一主体的一个特征精确快照加时间戳；同一采样位置只记录一个特征。多个状态只有在明确时间段和组成合同下形成复合状态。
6. 相邻同主体、同特征类型且值发生变化的状态形成原子动态；首个状态和无变化读取不产生动态。动态链只在其场景范围内有效。
7. 每个已发布状态触发一次幂等整理，但不保证必然产生动态。内部场景形成的动态保留内部证据，再由动态领域服务形成所在场景的新外层动态，不能改写内部身份。
8. 因果由条件、动作和结果的角色化事实组成；条件和结果是状态，动作可引用方法。无动作证据但条件必然导向结果时属于被动因果。
9. 一次完整证据可以形成实例因果；重复证据用于稳定性、统计和抽象，不是实例因果的最低准入次数。间接因果和目标层级只作当前图上的值式投影。

## 8. 自我、需求、任务与方法

1. 自我是项目根概念，由唯一稳定存在身份承载，不建立候选自我列表或运行期角色选择。自我换代保持该存在身份，只形成新的自我结构版本。
2. 名称、配置、路径、内存地址、线程、缓存键、场景位置、显示顺序和日志都不能建立或替代自我身份。
3. 项目根自我资格是承载存在身份的业务语义，不是第二身份。项目正式事实范围、范围版本和范围对象建立授权由具名领域责任裁决；授权接受不等于对象已经发布。
4. 安全目标和服务目标都使用各自独立的有符号 I64 根值域与 `I64_MAX` 目标；身份、事实、证据和治理路径分离。只有已证明严格正差距才能形成需求候选，零差距不得伪造需求。
5. 只有自我可以确认需求。需求、任务树和方法列表是三套独立结构，只通过正式引用和因果关系连接。
6. 同一有效来源需求复用唯一任务树。任务管理负责创建 / 查找任务、更新优先级和派发；优先级不抢占已经运行的工作。
7. 不同任务可以并行；同一任务同一时刻最多一个筹办或执行工作。每轮实例方法执行并形成结果后归还调度权。
8. 一个筹办回合最多实例化三个可能达成目标的方法；一次任务执行只运行一个实例方法。
9. 方法只声明预期状态变化，不能以返回值、日志或预期输出自证实际结果。实际结果必须通过独立权威回读、重新比较和因果材料成立。
10. 每轮结果形成新的实例方法树和结果材料；学习旁路只读消费其引用。抽象方法新版本不得反向修改已经实例化的方法，运行中任务继续使用原快照。
11. 任务完成、需求满足和价值结算保持独立裁决。需求暂时满足、失效、恢复有效和永久退役必须分开；永久退役按任务树后需求的顺序处理并保留必要历史证据。

## 9. 结构化非成功与内部不一致

1. 写前无效、未找到、已退役、版本漂移、格式不支持、权限不足、业务前置不满足等使用具名结构化结果，零业务写入。
2. 合法等待、候选为空、目标已满足和显式未实现属于协议内结果，不得压成裸失败。
3. 前置通过后出现身份复义、关系矛盾、内存发布读回不一致、半结构可见或事实链缺失，属于内部不一致；必须停止依赖路径并进入审计 / 恢复，不能包装成普通业务拒绝。
4. 日志、弹窗、扫描器和事后校验只能诊断，不能修复或改变机器事实。

## 10. 仍未裁决的边界

下列海鱼确认稿中明确保留为未决的内容不进入本次正式机器语义：

- 除 4200 已裁决的世界树归属创建、移动、移除和状态发布后动态整理外，其它跨领域关系的精确发布者与跨多个领域服务组合写入的最终事务接口；
- 除 4200 为世界树新直接身份底座冻结的通用类型合同/类型化值 C++ DTO、确定性持久证据编码和 v1 SQL 证据表外，其它类型合同、六类特征值类别和材料的精确领域物理编码、C++ / SQL 接口与 ABI；
- 复合状态、动态聚合、复杂动态和因果抽象的精确算法；
- 需求权重完整维度、任务状态全集、方法实时选择算法、超时和资源预算；
- 方法缺口向准备、学习、结构补齐或实现修复的最终分流；
- 停机、休眠、终止、可唤醒等待和零差距保证机制的精确实现；
- 项目事实范围、资格规则版本、授权证据和范围换代的精确数据合同。

这些事项只能在对应子规范完成裁决后进入设计和实施，不得从旧代码或确认稿未决段落补造。
