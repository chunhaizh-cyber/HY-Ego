# 0050 项目通用机器逻辑与禁止性规则总纲

编号：0050

版本：v2.7
状态：正式上级规范

## 1. 定位

本规范规定海中鱼巣全部机器逻辑共同服从的原则性规则。本项目采用运行期内存已发布代次权威、SQL 持久恢复证据、类型化值、`DATA-L1`—`DATA-L3` 具名数据结构服务合同和位于 `DATA` 之外的业务解释。SQL 行、查询结果、控制面板投影和恢复材料均不得直接裁决运行期事实。

具体对象字段、算法、接口和业务流程仍必须进入对应根规范或子规范；海鱼确认稿本身不直接成为本项目规范，也不授权代码实施。

## 2. 权威与事实分层

1. `规范/规范目录.md` 及其登记规范是本项目机器逻辑的唯一正式定义来源。
2. 程序行为、外部材料、候选稿、日志、界面、缓存和过程记录都不能越过本目录直接裁决本项目事实。
3. 机器事实必须同时具有稳定编码、确定类型、合法写入方、可追溯来源、创建 / 退出生命周期以及完整发布证据。事实代次只描述一次原子发布和快照边界，不是任何对象的身份版本。
4. 本项目采用以下权威分账：

```text
内存已发布当前事实代次    = 唯一运行期机器事实权威；承载节点、关系、值、创建 / 退出生命周期
SQL Server / 独立材料     = 已发布事实代次的持久证据、隔离恢复输入、应急审计材料和人机交互投影
内存缓存 / 索引 / 统计投影 = 从指定内存已发布代次确定重建的非权威加速结构
```

5. 一次运行期事实写集完成全部候选确认后原子发布新的内存代次，该原子代次发布是运行期事实的唯一线性化点。候选对象、SQL 行、材料文件、缓存命中、索引命中、函数返回和未发布内存对象均不等于事实已经发布。
6. 需要跨进程保存的事实必须由 SQL 和 / 或不可变材料保存足以验证已发布事实代次的编码、类型、载荷摘要、关系、创建 / 退出生命周期和发布证据；其内容只能经 4070 隔离恢复、完整校验和领域重新准入后形成新的内存已发布事实代次，普通业务不得直接以 SQL 查询结果作为当前事实。
7. 进程启动且尚未完成恢复发布时不存在运行期权威。恢复完成后，恢复服务原子发布的内存代次成为唯一运行期权威；SQL 原行及交互投影仍不取得运行期裁决权。
8. 七族当前结构身份确认与历史见证的公开合同分流不是 SQL、材料、消息或恢复格式版本。持久恢复只互证并重建 L1 中性节点、关系、值、生命周期和发布证据；恢复完成后，L2 消费者必须经届时有效的具名当前确认或历史见证合同重新读取，不得以旧共同当前入口、持久化 DTO 或格式兼容壳取得当前身份。

## 3. 数据服务分层与业务边界

当前基础数据架构只定义三层：

```text
L0 物理持久层：SQL Server、独立材料文件及其完整性能力
DATA-L1 纯事实内核：节点、关系、值的增删改查，事务、幂等、事实代次、当前 / 历史读取和 owner 隔离
DATA-L2 强类型结构服务：保存并校验具名结构的字段、关系、基数、顺序、生命周期和结构引用
DATA-L3 结构聚合：组合 DATA-L2 公开能力形成世界树结构聚合与概念空间结构聚合
DATA 之外的业务层：构造结构请求，解释业务名称、资格、目标、动作和结果
```

`DATA-L4`、`DATA-L5` 当前只保留层号而不定义职责；禁止为了维持旧五层叙述发明转发、解释或聚合层。

### 3.1 全局 ARCH 五层命名空间映射（20260824）

本项目同时使用全局架构命名空间 `ARCH-L1`—`ARCH-L5`。它不是对 `DATA-L1`—`DATA-L5` 的改名，也不授权把现有 C++ 的 `L2` 名称直接解释为某一全局层：

```text
ARCH-L1 = 统一事实内核                         ↔ DATA-L1
ARCH-L2 = 通用基础结构（世界、语言、概念基础结构） ↔ DATA-L2
ARCH-L3 = 世界树、概念树/概念空间聚合            ↔ DATA-L3
ARCH-L4 = 需求、任务、方法及其业务治理            （不定义 DATA-L4）
ARCH-L5 = 自然语言理解/表达与名称绑定裁决         （不定义 DATA-L5）
```

`ARCH-L5 -> ARCH-L4/ARCH-L3/ARCH-L2`、`ARCH-L4 -> ARCH-L3/ARCH-L2`、`ARCH-L3 -> ARCH-L2 -> ARCH-L1` 是唯一依赖方向，禁止反向依赖。ARCH-L2 不区分现实与虚拟调用者；通用虚拟存在、状态、动态和因果的结构 owner 只有一份。ARCH-L4 的需求/任务/方法模块可以保留现有 ABI 作为结构记录面迁移兼容身份，但不得以其私有状态或动态形成第二权威。ARCH-L5 只能经下层公开服务提交词条、名称、别名、定义和表达绑定，不直接改写下层身份或字段。

概念身份语言无关，概念基础结构及概念—词条名称关系的结构 owner 归 ARCH-L2，概念树/空间聚合归 ARCH-L3，名称接受、表达和消歧裁决归 ARCH-L5；二次至 n 次特征复用同一特征身份、真实阶次和直接来源。该映射不改变 DATA 三层既有纯结构边界，具体 ABI、迁移顺序和原子 owner 由对应设计/计划冻结。

1. 分层表示数据结构所有权和接口承接，不表示业务语义、代码目录、类、进程、部署单元、能力成熟度或必须按编号顺序实施。
2. `DATA-L2` 具有“结构类型语义”：它可以知道某节点属于场景、词条、概念或不可变材料等当前基础结构族，并校验该族字段、关系、基数和生命周期；它不得判断词义是否正确、需求是否有效、任务是否完成、方法是否成功，也不得判断世界事实、状态、动态或因果的业务真实性。
3. `DATA-L2` 的当前穷尽范围以“独立结构 owner + 该 owner 的唯一公开服务面”为收口单位：节点 owner 固定为场景、存在、特征定义、特征实例、状态、动态、因果、语言、词条、概念、不可变材料十一项；独立关系 owner 固定为概念—词条名称关系一项。二次至 n 次特征、当前特征值、状态当前选择及各族内部关系并入其既有 owner，不独立计数。语素和词性不形成持久结构族；需求、任务、方法属于 `ARCH-L4` 业务治理，现有 `L2*` 名称仅作 `ARCH-L4` 结构记录面兼容实现名，不进入当前 `DATA-L2` 活跃范围；世界树和概念空间聚合属于 `DATA-L3`，名称接受、表达和消歧裁决属于 `ARCH-L5`。新增 DATA-L2 结构 owner 必须先修订本规范及对应子规范，不得由文件名、枚举追加或服务实现自行扩张。
4. `ARCH-L4` 内部必须分为结构记录面与业务应用面。结构记录面只机械保存、读取和校验调用方已经裁决的身份、关系、生命周期、版本、幂等、事实代次、当前 / 历史、原子发布、引用闭合和结构索引；业务应用面负责为什么建立、选择、推进、结束和判定，包括需求成立 / 当前满足、任务目标达成 / 轮次结算 / 生命周期结束、方法适用 / 授权 / 执行成功。结构记录面不得替业务应用面作出这些判断。
5. 每类数据结构必须有唯一写入服务。该服务只校验结构形状、类型、引用、生命周期、期望代次、幂等和事务条件，不校验业务资格、业务目标或业务结果。
6. `DATA-L3` 只经 `DATA-L2` 具名公开合同聚合世界树和概念空间，不直达 `DATA-L1` 仓库、SQL、材料文件或内部事务，不复制 CRUD，不成为相同结构的第二解释者或第二写入者。概念的权威结构是多父 DAG；“概念树”只是在指定截止上的可重建值式投影。
7. `DATA` 之外的业务调用方负责把业务裁决转换为强类型数据结构请求，并解释返回结果；它不得取得原始 SQL 事务、锁、可变仓库对象、内部撤销权或缓存写权。
8. 一个物理底座可以承载多棵逻辑树和多张图；关系是事实，树 / 图 / 列表是值式投影，索引只是入口或候选召回。
9. 数据服务之间以及同层不同结构所有者之间，只允许通过具名、强类型服务合同约束的公开服务函数交互。合同至少冻结服务身份、函数身份、请求 / 结果类型、稳定编码、期望事实代次、一致性边界、结构化非成功、结构唯一写入服务约束和所需公开生命周期；`L1结构所有者身份`及其生命周期只由提供者内部核对，不进入 `L2节点族身份来源事实`及其读取成功谓词。其它具名 L2 结构结果中的旧 owner 兼容材料不得借本条重释，须由对应族 ABI 及 P04 / P08 后续裁决。不得携带业务资格、业务操作标签、业务意图、领域见证或业务结果解释。
10. 不强制调用按层号逐级代理。消费者按真实结构依赖直接调用拥有所需数据结构的具名服务；不存在结构依赖的中间层不得成为转发壳、第二解释者或隐式授权者。
11. 服务只返回调用方拥有的不可变完整投影，不得泄漏仓库可变对象、SQL、材料路径、锁、事务、缓存、内部写集、候选确认或撤销能力。
12. 服务合同保持兼容时，提供者可以替换本层内部结构、算法、缓存和物理存储而不要求消费者修改；若字段语义、分支、所有权或一致性边界改变，必须建立新的具名合同 / DTO 身份并明确兼容、迁移或拒绝关系，禁止静默改变或用递增版本字段猜测兼容。
13. 场景、存在、特征定义、特征实例、状态、动态和因果七个世界节点族的身份读取必须把“当前结构身份确认”与“身份来源历史见证”分为不同的具名合同。当前固定为 `确认当前{族}结构身份(G0 + 本族身份) -> L2结构结果头`：成功仅以 `已读取 + 事实截止代次 == G0 + 空变更事实代次`确认该身份的结构当前性，不回显身份或任何节点、锚点、关系类型、归属关系、角色 / 顺序、生命周期或内部 owner。提供者必须在同一 `G0` 内部证明目标节点、族锚点、族归属关系类型、唯一归属关系及内部 owner 都仍当前，不能以结果头、最大代次或历史退出集合猜测当前性。历史见证合同保留 `L2结构请求头` 的读守卫，只接受非零 `H` 且 `H <= Gread`，在适用的历史、退出、恢复或审计路径返回完整 `L2节点族身份来源事实`，并要求 `H == 结果事实截止代次`；本条不规定其精确物理名字和失败优先级。任何公开源状态不得同时保留新当前确认与旧“当前 / 历史共用身份来源读取”的当前分支、转发壳、别名或长期双入口；消费者只能使用当前确认、历史见证合同或该族既有专属退出路径。状态 / 动态墓碑、TTL、清理、当前选择和其它旧 ABI 的精确处置仍由其独立 P08 口径承接，不得借身份合同分流改变。

## 4. 稳定编码、类型化值与关系

1. 节点、关系和值共用不透明、非零、全局不可复用的稳定编码。固定仓库号、节点号、关系号、句柄数值、内存地址、线程号、路径、名称和显示顺序不得成为公开机器编码。
2. 内部编码候选在所属内存事实代次原子发布前不是事实；不得外泄、复用或被业务资格引用。已发布或已退出编码永久占用，不得复用。
3. 通用编码与业务解释分权：数据层可以发布带结构类型语义的数据结构；只有 `DATA` 之外的业务层可以解释这些结构在当前业务中是否真实、有效、完成或成功。任一数据层写入成功都不自动建立自我、需求、任务、方法、资格或范围对象。
4. 属性类型由具名类型节点表达，至少具有稳定编码、表示 / 值域、所有者声明、生命周期和显式兼容关系。类型解释发生不兼容变化时建立新的类型节点；兼容性只能按明确方向、操作和直接关系裁决，不因同名、版本号大小、结构相似或兼容链自动传递。
5. 禁止通用 JSON、主信息、万能 I64 槽、任意字节包或无类型联合容器承担跨领域权威值。
6. 值必须绑定所属节点编码、属性类型节点编码、不可变材料或材料引用、来源编码、创建 / 退出事实代次及发布证据；当前属性槽只能指向该节点该属性类型的一个当前值编码。
7. 对象拓扑、归属、组成、来源和引用由有向关系事实承载；关系替换使旧关系退出并以新编码建立新关系，历史事实不可原地覆写。当前值由节点属性槽与值事实承载，不复制为关系或子节点表。
8. 索引和便利字段不得成为节点属性槽或关系的第二权威表达；命中后必须回读同一内存已发布事实代次的节点、关系和值。

## 5. 事实发布、幂等与并发

1. 可判定的编码、类型、合同版本、期望事实代次和槽 / 关系一致性必须在第一笔数据写入前拒绝；业务权限与其它业务前置不得进入数据服务合同。
2. 一次数据结构写集必须在一个明确内存事实事务中形成候选、完成全部参与者确认，并原子发布一个新代次。材料文件或 SQL 持久证据如需准备，只能形成未取得运行期事实权的候选；失败时不得出现公开可读半结构。
3. 新当前值与旧值退出、关系替换、创建 / 退出事实代次和运行期发布证据必须在同一内存代次发布中闭合。
4. 幂等必须绑定稳定幂等身份和完整请求语义：同键同义返回原结果，同键异义返回冲突；不得以“记录存在”冒充幂等。
5. 期望事实代次或并发条件不符时不得覆盖当前事实。内存代次发布结果未知时只能使用原幂等身份和发布见证回读收敛，不得生成新编码或重放异义请求。
6. 内存代次发布前失败必须零普通业务可读事实；发布后不得用撤销、SQL 旧行或材料文件伪装回滚。发布后读回不一致属于内部不一致，进入审计 / 恢复路径。
7. SQL 持久化成功不等于运行期事实发布成功；SQL 持久化失败、结果未知、落后或损坏必须形成具名持久证据状态和后继策略，不得静默以 SQL 当前行替换、回退或覆盖内存已发布代次。

## 6. 查询、缓存、恢复与回收

1. 当前读取、历史读取、审计读取和恢复候选读取必须显式分离，结果均为调用方拥有的不可变值式快照。
2. 组合投影必须声明事实截止代次、读取类别和完整性；不得把默认值、空编码或隐式“最新”用于补齐缺失事实。
3. 缓存读取至少区分命中、确定未命中和缓存不可用。缓存不可用只触发回源或具名非成功，不能改变业务结果。
4. 缓存与索引的失效、清空和重建只能以指定内存已发布代次为来源；重建过程不得写业务事实。SQL 不得成为普通运行期缓存或索引的回源权威。
5. 恢复输入先进入隔离候选，按编码占用、类型、节点属性槽、关系端点、创建 / 退出生命周期、材料摘要和发布证据互证，再通过正常结构校验与内存事实事务一次原子发布。
6. 恢复不得从材料目录、SQL 或缓存补造缺失对象，不得复义身份、复活已退出合同或绕过业务授权；材料与当前内存事实冲突时必须具名拒绝，不能择优拼接。
7. 退役先在内存已发布代次中改变生命周期并保留合同要求的历史和引用保护；实例状态 / 动态可以按具名保留策略进入物理清理，清理后只保留墓碑与紧凑幂等证据。其它持久证据同步与材料物理回收按专门合同后继执行，且不得破坏仍受合同保护的当前、历史、审计或恢复引用。

## 7. 特征、世界、状态、动态与因果

本节定义 `DATA` 之外业务层可以采用的业务解释，不授予数据层自动生成、判断或验证这些业务含义的权力。`DATA-L2` 若承载相关强类型结构，只按其正式结构合同执行增、删、改、查。

1. 已发布特征值载荷不可原地改变；变化形成新的值事实编码并使旧值退出。特征的宿主、类型、唯一当前值和历史值必须分账。
2. 存在本体与内部场景分离；在一次业务采用的观察分辨率下，控制室、车间、设备、自我等对象首先是同一共同场景中的存在，只有确需展开某个存在的内部结构时才按需建立与该存在身份分离的内部场景，不要求所有存在预建内部世界，也不得因对象具有空间含义就把它自动改判成并列场景。
3. 场景可以组成多棵单根、单父、无环逻辑树；同一存在在同一棵场景树中只有一个当前直接位置。现实世界树唯一，自我当前所在场景必须属于它。
4. 每个世界拥有独立逻辑序列，世界之间的节点、关系、状态、动态、因果和属性值严格隔离。
5. 原子状态是同一主体的一个特征精确快照加时间戳；同一采样位置只记录一个特征。多个状态只有在明确时间段和组成合同下形成复合状态。
6. 相邻同主体、同特征类型且值发生变化的状态形成原子动态；首个状态和无变化读取不产生动态。动态链只在其场景范围内有效。
7. 每个已发布状态触发一次幂等整理，但不保证必然产生动态。内部场景形成的动态保留内部证据，再由动态领域服务形成所在场景的新外层动态，不能改写内部身份。
8. 因果由条件、动作和结果的角色化事实组成；条件和结果是状态，动作可引用方法。动作直接改变的是共同场景中具名作用主体存在的特征，动作的场景只表达该动作成立的共同上下文，不是被改变对象或第二作用主体。无动作证据但条件必然导向结果时属于被动因果。
9. 一次完整证据可以形成实例因果；重复证据用于稳定性、统计和抽象，不是实例因果的最低准入次数。直接作用主体的状态变化可以经正式因果链影响同一共同场景中的其它结果主体；该间接结果必须独立读回，不能由动作成功、直接主体变化或预计结果补造。间接因果和目标层级只作当前图上的值式投影。
10. 概念空间以存在、特征、动态和因果链四个语言无关本体根组织抽象身份。因果链概念由独立概念身份、完整抽象签名以及对已发布直接因果事实的定义 / 支持关系共同成立；它不复制因果事实身份或因果账，因果层次只在应用给定目标、范围、版本和展开截止后从直接因果拓扑形成值式投影，不持久化固定层号、间接边或展开路径。场景保持世界树中的分层事实组织，不建立场景概念根，也不因场景身份或层级自动生成普通概念。零概念启动、阶段 18 和初始四个本体根形成不读取自然语言或词条，也不扫描动态、形成因果候选或生成普通因果链概念；概念抽象能力成立后，已发布语言事实可以作为语言结构概念的形成或支持材料。词条只承担名称和召回，候选类型必须从其名称目标的正式强类型结构读回；词性若后继需要，只能按本次词出现、候选目标类型、句法关系和上下文形成任务局部值式判断，不得决定本体根、概念身份或持久数据类型。
11. 二次至 n 次特征在概念本体上仍属于特征，不建立随阶次扩张的独立节点族。正式持久化的只有经概念准入的二次特征概念信息：统一复用特征概念身份，并记录非零真实阶次、直接来源角色、输入 / 输出类型、派生规则及版本和适用范围；“二次特征”只作为对阶次大于一的统称。
12. 二次特征具体值只在当前比较或判断确有需要时形成。调用方必须先冻结非零事实截止，正式读取概念版本与全部来源当前事实；来源缺失、范围非法、版本不兼容或读取漂移均不得形成部分结果。材料闭合后按概念公式形成任务局部值式投影，供本次调用立即使用。
13. 二次特征值式投影用完即弃，不取得 L2 身份、持久实例、当前值选择、状态、动态、幂等账或跨进程恢复资格，也不得经消息、缓存或上轮结果冒充新的当前值。需要持久审计的业务裁决只保存其正式来源事实、概念版本、事实截止和裁决结果，不把本次二次特征值登记为可继续读取的世界事实。
14. 项目默认自然语言是汉语。该默认值只用于概念形成之后的人类语言接收、词条、名称和表达选择；它不参与概念本体根、概念身份、二次特征阶次或阶段 18 初始化裁决，也不授权建立持久词性、信息入口类型或默认类型表。后继语言能力尚未正式建立汉语身份时必须返回结构化能力缺失，不得用默认字符串冒充语言事实。

### 7.1 认知证据与工程正确性分界

1. 状态记录某一时间点的特征事实，动态记录已经发生的状态变化及其来源，因果记录条件、可选动作与结果变化之间的直接关系。状态、动态和因果三者构成本项目认知层可以引用的认知证据；“认知证据”不另设第四类生产事实、持久证明节点或专用证明关系。
2. 该口径不改变特征实例当前值权威：状态是事实记录而不是当前属性槽，动态是变化记录而不是当前值，因果是变化关系而不是结果补造器。任何当前比较仍须按本规范第 11 节读取同一截止的当前值事实。
3. 需求、任务、方法、选择、执行冻结、现实执行授权、结算和后继决议可以作为具有独立业务作用、唯一 owner 和自身生命周期的治理事实存在；它们不是认知证据的新类别。治理事实需要解释判断来源时，可以引用同截止当前特征值完整投影、目标合同、已经发布的状态 / 动态 / 因果及必要既有治理上下文；当前特征值是比较权威而不是第四类认知证据，状态 / 动态不得替代它。不得为“证明该治理事实正确”再复制一套当前值、状态、动态、因果或建立证据专用节点 / 关系。
4. `G0 / G1`、期望事实代次、幂等身份与幂等账、事务候选 / 确认 / 发布、发布后读回、SQL 持久材料、恢复见证、消费水位、线程进入 / 完成条件、生命周期同步信号和检查摘要只服务工程正确性。它们可以保存在所属数据 / 恢复 / 审计内部边界，但不得解释为世界、认知、需求、任务或方法事实，也不得进入业务事实平面充当第二权威。
5. 工程正确性材料只回答“写入、读取、恢复和消费是否按合同完成”，不能回答系统“为什么这样判断”或“是否理解了该判断”。满足工程门禁不得自动生成状态、动态、因果、用途观察、裁决证据、授权证据或其它生产事实。
6. 一个记录若只有重复、见证、证明或审计另一已发布事实的用途，没有独立业务作用、独立生命周期和合法消费者，就不得进入生产事实平面；改由调用期值式材料、非权威可重建投影或所属工程内部账承载。名称含“证据”“见证”不是单独裁决依据，必须按写入方、事实权力、生命周期和消费效果判断。
7. 为兼容历史持久材料和既有公开 ABI，可以保留旧编码、旧结果分支和只读解码；保留不等于继续授权生产。旧证明型生产入口必须先冻结替代读回与迁移合同，再停止新建，禁止删除后复用旧数值或把旧编码改义为新事实。

## 8. 自我、需求、任务与方法

本节全部属于 `DATA` 之外的业务规则。需求、任务、方法等强类型治理记录属于 `ARCH-L4`；现有 `L2*` C++ 服务和枚举只作兼容实现 / ABI，不因此进入当前 `DATA-L2` 活跃结构范围。兼容实现只保存调用方已经裁决并提交的治理记录，不判断自我资格、目标正确性、需求成立、任务轮次结算 / 生命周期结束或方法有效。

1. 自我是项目唯一世界存在，由唯一稳定存在节点编码承载，不建立候选自我列表或运行期角色选择。自我可以通过世界事实支持概念关系进入存在、特征或动态本体根中的一个或多个概念，但不得自身兼任概念、本体根或概念树身份。自我结构变化以新的关系和值事实表达，不修改既有事实。
2. 名称、配置、路径、内存地址、线程、缓存键、场景位置、显示顺序和日志都不能建立或替代自我身份。
3. 项目根自我资格是承载存在节点的业务语义，不是第二身份。项目正式事实范围、范围节点和范围对象的建立准入由具名领域责任裁决；准入成立不等于对象已经发布，也不属于现实执行授权。
4. 安全目标和服务目标都使用各自独立的非负有符号 I64 根值域 `0..I64_MAX`，目标固定为 `M = I64_MAX`。冷启动首次值固定为该非负根值域的下中点 `M / 2 = 4,611,686,018,427,387,903`，使用非负整数除法并舍弃余数 `M % 2 = 1`；两个根的身份、事实、证据和治理路径分离。每轮差值只按第 7 节的二次特征值式投影计算为 `M - 当前值`，严格正差距才能进入需求候选形成，零差距不得伪造需求。
5. 只有自我可以确认需求。需求树是目标分解基准，需求列表是从需求树按精确同目标汇总的派生活动视图；任务和方法是独立结构，只通过正式引用和因果关系连接。
6. 任务根据需求树中的一个具体需求建立并引用其目标展开活动；任务建立时只以该需求所属列表项查询是否已有同目标当前任务，有则复用并新增 `T→D`，无则建立任务。列表项不是任务目标、授权主体或来源需求集合。
7. 不同任务可以并行；同一任务同一时刻最多一个工作线程。一个任务轮次按筹办、执行、结算、轮次已收束推进，正式实际结果形成后归还调度权并进入结算，不自动开启下一轮。
8. 一个筹办轮次可以召回零个、一个或多个候选方法，但只能形成零或一条当前活动路径和零或一个实例方法；一个执行轮次只运行一个实例方法。
9. 方法只声明预期状态变化，不能以返回值、日志或预期输出自证实际结果。方法的直接动作主体可以不同于需求目标或间接结果主体，但必须以共同场景和正式因果链绑定；实际结果必须分别通过直接主体与间接结果主体的独立权威回读、重新比较和因果材料成立。
10. 每个筹办 / 执行轮次形成自己的路径、实例方法、冻结和结果材料；学习旁路只读消费其引用。抽象方法变化建立新的方法事实，不得反向修改已经实例化的方法，运行中任务继续使用原快照。
11. 任务轮次收束、轮次级上级调用槽结算、需求满足和价值结算保持独立裁决。任务结果不是容量或成员分配对象；子任务收束自身轮次后只向 0..1 条正式发起调用返回并结算对应上级槽，其它需求 / 任务在实际使用时按自身目标或条件 fresh 读取当前事实。需求暂时满足、失效、恢复有效和永久退役必须分开并保留必要历史证据。

### 8.1 内部治理、现实观察与现实改变的授权边界（20260824）

项目必须先按实际动作效果区分：

```text
内部治理
    = 读取、比较、形成候选、选择、筹办、状态迁移、结果收束、结算编排和后继裁决等只改变内部治理事实的动作

现实观察
    = 以读取现实为目的，只把观察材料和认知事实带回内部，且不包含对外部对象、外部主体或受保护资源的可观察改变

现实改变
    = 预期或可能改变外部对象、外部主体、外部系统、物理环境或受保护资源状态的动作
```

内部治理相当于“想”，不需要自我现实执行授权；它仍必须遵守 owner、公开调用许可、结构写入许可、事务、幂等、当前性和数据安全合同。现实观察与现实改变不得混账：纯观察不需要自我现实执行授权；主动探测、设备运动、发射、外部通信、写外部系统或其它具有现实副作用的观察步骤，按现实改变步骤处理。

只有一份任务执行冻结中至少包含一个现实改变步骤时，才在筹办与执行冻结完成后、任务进入执行阶段前取得一份正式`自我现实执行授权事实`；因此授权必然早于首个现实改变步骤。该事实由自我业务 owner 唯一裁决和发布，至少绑定自我、任务、任务轮次、筹办轮次、执行轮次、执行冻结身份与版本、实例方法及内容版本、被授权现实动作范围、事实截止、规则版本和发生时间。任一绑定材料变化使旧授权失效；同一授权不得扩张到新冻结、新任务轮次、未列动作或其它任务。

`自我现实执行授权事实`同时覆盖该冻结中的任务和实例方法，不再分别建立“任务授权”和“方法授权”。拒绝、等待、取消、任务后继决议、需求确认、方法发布准入、结构写许可、公开调用许可、调度优先级和安全硬否决都不是第二份正向执行授权。安全与生存服务只提供当前安全事实、调度材料和具名硬否决；它们不得正向授权现实动作，自我授权也不得绕过硬否决。

任务正常轮次固定为：

```text
筹办阶段 -> 执行阶段 -> 结算阶段 -> 轮次已收束 -> 等待自我后继决议
```

任务轮次、筹办轮次和执行轮次是三个不同身份。目标未达成只是本轮结算结论，不自动建立下一筹办轮次。轮次已收束后，只有自我形成`继续 / 结束 / 等待 / 取消`之一的后继决议，任务管理才可按任务合同开启新任务轮次或结束生命周期；该后继决议属于内部治理，不是现实执行授权。继续时必须建立新任务轮次并重新筹办、重新冻结、按实际作用范围重新判断是否需要新的现实执行授权。

### 8.2 筹办发现、需求确认与执行前选择（20260902 C031）

1. 任务筹办只为既有任务发现候选方法，以及每个候选方法自己的条件组、输入 / 参数 / 限制、动作范围、验证和归因材料；它不作适用性判断，不采用方法，不形成路径、实例方法或执行冻结，也不建立需求、子需求或子任务。
2. 条件组是方法内容版本中已经声明的条件 / 条件结果关系及绑定材料的值式投影。候选必须保留`方法身份 + 内容版本 -> 条件组`对应关系；不得摊平成任务级条件总表、按名称或哈希临时拼组，或为它建立第二个持久账。现有方法合同不能强类型区分组或组合语义时，只能报告结构缺口，不得猜测组间可替代、可组合或优先关系。
3. 每个已消费筹办工作包仍只投递一条不可变强类型消息，容量不足只重投同一消息；正常载荷是`筹办发现`及其正式事实定位，结构化非成功仍须显式传递。`可执行冻结`、`子目标承接`、`合法等待`和`目标已完成`不再是筹办的业务结果分支，消息、线程返回值、日志和缓存都不产生正式需求、路径、选择或冻结事实。
4. 任务管理只在独立读回同一事实截止的任务、候选、条件组和缺口后路由：可进入执行前判断的发现交给任务领域的执行前选择入口；方法 / 条件 / 结构缺口定位交自我线程。任务管理不得重跑发现、选择方法、形成需求结论、建立子任务，或以队列状态伪造等待。
5. 自我线程对缺口定位 fresh 读取父需求、目标合同、任务轮次和正式方法材料后，才可确认是否需要后继治理。只有自我已确认、task owner 按正式来源联合发布或精确重放任务子目标承接记录、且需求领域服务独立读回并写入 / 复用后，子需求才成立；任何筹办发现、消息或条件缺失本身都不是需求。
6. 实际可用性判断、方法选择和冻结只在真实动作前的执行前选择入口进行。同一 fresh 截止先硬过滤目标 / 结果合同、版本和动作入口、该选项自身完整条件组、输入 / 参数、范围、验证 / 归因、禁止和安全硬否决；再仅在可比较的可用选项间按下位规范的分层规则选择一项，并原子形成既有选择记录、路径、实例方法和执行冻结。未知、不可比或并列最优不得按遍历顺序、编码、哈希或线程顺序任选。
7. 安全硬否决和生存安全根控制态是不可抵销门槛。安全实际值只沿其既有结算 / 维护链变化；服务根当前值、已退出的服务合同 / 余额、服务进展、线程或队列状态均不得伪装成通用方法代价或选择余额。

## 9. 结构化非成功与内部不一致

2. 合法等待、候选为空、目标已满足和显式未实现属于协议内结果，不得压成裸失败。
3. 前置通过后出现身份复义、关系矛盾、内存发布读回不一致、半结构可见或事实链缺失，属于内部不一致；必须停止依赖路径并进入审计 / 恢复，不能包装成普通业务拒绝。
4. 日志、弹窗、扫描器和事后校验只能诊断，不能修复或改变机器事实。

## 11. 20260827 DATA 无权限裁决与状态动态现行总则

本节是本规范当前最高优先级解释；与前文既有 owner、公开调用许可、结构写许可、状态永久历史或状态—动态同事务口径冲突时，以本节为准。

1. `DATA-L1`—`DATA-L3` 不识别调用者业务身份，不判断谁有权读、写、改、删。业务 / 治理层必须在调用 DATA 前完成权限与资格裁决；DATA 请求和结果不得携带或生成业务许可结论。
2. 每类结构继续只有一个权威服务和事实来源。既有 L1 `owner`、所有者、`写入所有者`、其生命周期和写端口只表示调用者不可选择的内部结构分区，用于幂等命名空间、结构闭包、唯一事实来源和旧事实兼容，不表示数据归属、业务主体或调用资格，不进入 `L2节点族身份来源事实`及其读取成功谓词。其它具名 L2 结构结果中的旧 owner 兼容材料须按对应族 ABI 逐项迁移，不能借其作为身份、资格或业务结果。
3. 旧 `许可拒绝` 数值只供旧 ABI、历史结果和持久材料解码，现行入口和新合同不得产生。内部端口 / 装配错误以 `内部不一致` 编码，结构分区冲突以 `引用冲突` 编码，锁或资源暂不可用以 `资源失败` 编码；三者均空载荷、零公开变化。
4. 状态本体只记录“特征类型 + 特征值 + 强时间”，不包含业务 owner、主体、场景、特征实例、任务、方法或用途；这些归属只通过强类型引用关系表达。状态不是特征当前值权威。
5. 特征实例唯一当前属性槽指向的当前值事实，是业务比较唯一权威。业务自检、需求满足和目标比较必须在同一事实截止读取目标涉及的当前特征值，再按目标状态合同比较。状态、动态及状态当前选择只能用于记录、触发、定位、历史追踪、变化解释和审计；禁止从最后写入动态、动态后状态、状态时间或状态当前选择反推特征当前值。复合目标读取同一截止的当前特征值集合；值式当前状态投影可重建但不是第二权威。
6. 强时间是闭合联合：实例状态 / 动态使用非负 UTC Unix epoch 纳秒绝对时间；抽象状态 / 动态使用非负相对纳秒。一个身份只能采用一种时间语义。普通动态仍只引用至少两个已正式存在并读回的状态。唯一例外是“特征当前值正式变化并同步记录”组合入口：业务规则先裁决新值，预形成顺序固定为新值、新状态、引用既有前状态形成新动态，最终原子发布当前属性槽切换、新状态和新动态；逻辑上仍是先状态后动态，不得从状态推导新值。首次赋值只发布当前值与初始状态，不伪造无前状态动态；新值等于旧值时不新增值、状态或动态；任一记录或交换失败时整次零公开变化。按需二次特征值式投影不是特征实例当前值，不形成状态或动态。
7. 实例状态和实例动态是临时材料。保留策略必须分别提供非零有限的实例状态 TTL、实例动态 TTL、实例状态数量上限和实例动态数量上限；四项独立判断，不把两类数量相加为共同容量。TTL 一律从各材料首次正式形成时记录的 UTC 纳秒计算，不使用状态事件时间或动态成员事件时间；同类超量时按首次形成 UTC 纳秒、稳定身份升序确定最旧材料。
8. 清理先退出受影响实例动态，再退出不再被活动动态引用的实例状态。被清理状态的当前选择同代退出且不得回退旧状态；普通引用允许成为已过期引用。
9. 物理清理推进新事实代次，删除完整实例载荷，但保留最小墓碑和紧凑幂等记录。墓碑至少包含身份、结构类别、创建代次、清理代次、清理原因和原规范化请求摘要；历史读取命中墓碑时返回 `历史材料已清理` 和零完整载荷。
10. DATA 状态 / 动态服务只提供同步清理入口，不创建线程、定时器或后台任务。普通应用唯一运行宿主在数据上下文可用后立即维护一次，此后以 60 秒周期调用同一清理入口；无数据上下文的空运行宿主不绑定该回调。
11. 周期维护遇资源失败时保留原 G0、原幂等身份和原完整请求到下一周期；遇事实代次漂移时丢弃旧请求，正式读取新 G0、分配新幂等身份并在本周期最多重试一次，第二次漂移等待下一周期。内部不一致或维护身份序列耗尽形成结构化程序失败。
12. 周期维护幂等身份固定使用前缀 `0x4E43'0000'0000'0000`，低 48 位为进程生命周期内原子单调序列；当前存储未声明跨进程恢复该序列，进程重启可重新开始。抽象完成调用不得使用该前缀。
13. 任务阶段消费者不得继续调用零写旧 `新增状态_v2` 或 `发布状态动态原子迁移_v2`。首态按“正式读取特征实例 -> 新增中性状态 -> 设置中性当前选择”执行；迁移按“读取旧中性当前选择 / 状态 -> 新增目标状态 -> 以旧 / 新状态形成中性动态 -> 替换当前选择”执行，各写入使用独立正式代次与证据。
