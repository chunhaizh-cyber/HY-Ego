## 1. 定位

本规范规定海中鱼巣全部机器逻辑共同服从的原则性规则。本项目采用锁保护的运行期内存当前事实权威、持久恢复证据、类型化值、`DATA-L1`—`DATA-L3` 具名强类型数据结构服务和位于 `DATA` 之外的业务解释。持久行、查询结果、控制面板投影和恢复材料均不得直接裁决运行期事实。

具体对象字段、算法、接口和业务流程仍必须进入对应根规范或子规范；海鱼确认稿本身不直接成为本项目规范，也不授权代码实施。

### 1.1 DATA-L1 current-only取消裁决

自v3.29起，DATA-L1只保存节点、外部关系、字段关系和字段直接值，以及组合原子发布、current-only持久化和恢复所需的最小技术材料。稳定编码由持久单调高水位分配，删除后永不复用；基础数据集不对外提供调用者可选择的owner、业务类型、业务历史、历史截止、退出后载荷、墓碑或公共请求账。

持久恢复只恢复最后完整发布的current-only状态。用于发布未知收敛的技术材料必须局限于同一组合请求的恢复，不构成业务历史查询、公共幂等账或调用权限。本规范后文以及规范目录内全部下层规范、流程和验收条款中与本节相悖的`Gread/H`双时态、历史owner、墓碑、退出后读回或公共历史查询要求立即失效，只作代码物理清理定位。

### 1.2 DATA-L1合同版本与事实代次整体取消裁决

自v3.27起，DATA-L1的进程内强类型公开请求、结果、函数和运行包不再携带或校验合同版本。不兼容变化直接修改当前具名强类型合同并同步迁移全部生产消费者，不用递增数字猜测兼容。持久清单、快照载荷及独立材料的`格式版本`只用于解码持久字节，不是服务合同版本，继续保留。

DATA-L1内部及其公开面整体取消全局事实代次，包括`G/G0/G1/Gread/H`、期望/读取/首次发布/创建/退出事实代次、代次漂移状态、代次持久字段及代次恢复互证。L1的运行期权威是锁保护下的完整当前状态：单次读取在一次共享锁内形成完整值式结果；单函数写入在一次独占锁内完成校验和修改，需要跨多个基础操作共同成立的上层结构必须提交一个组合变化集并一次发布。发布不再分配事实代次。

跨函数调用不提供共同代次快照保证，也不得由上层分步读取后用代次拼接完整材料。竞争写入按取得独占锁的顺序串行执行，后取得锁的请求以当时当前状态继续。结构缺失、端点不存在、引用未闭合、重复请求异义和内部不一致按各自结构化非成功处理；不得恢复owner不符或代次漂移分支。

持久恢复使用快照序号、活动槽、载荷格式版本、长度和摘要互证整份current-only状态，不保存、生成或恢复事实代次。本规范、目录中全部下层规范、详细设计、流程和验收条款中与本节相悖的合同版本和事实代次要求立即失效，只作物理清理定位。

### 1.3 基础数据与新版领域模型替代裁决

自v3.29起，4015、2100、1130、1140、1150、1160、1170、1190、3100、3200和7160共同构成现行基础数据与核心领域对象合同。下列规则优先于本规范后文及其它旧子规范中的冲突条款：

1. 基础数据集只保存节点、外部关系、字段关系和字段直接值；不识别业务类型，不对外提供调用者可选择owner，不保存业务历史、事实代次或合同版本。需要独立身份的材料由上层建立节点，字段直接值没有独立稳定身份。
2. 基础数据集必须最终具备组合原子发布、current-only持久化和恢复；当前实现未具备不改变正式目标合同。技术恢复材料只服务同一组合请求的发布未知收敛，不恢复公共历史查询或完整请求业务账。
3. 实例特征以实际值为准。特征概念值域负责分类、单位、比较和聚合，不限制合法实际值写入。实例保存当前值、去重历史值及命中次数、标准值和聚合值域。
4. 特征概念按特征类型独立成树；类型根是根链节点，具体值域从宽到窄形成单父层级。概念值域可随实例材料修订；引用减法后为零且无子概念时删除。
5. 普通存在必须明确直接所属场景。场景成员归属与父存在组成是两种关系，可以同时存在。存在先建立实例特征，再形成专属存在概念；多个存在的共同上位概念只在明确归纳需要且至少有两个输入时形成。
6. 世界树根就是根场景。场景本身也是存在，直接持有专属存在概念和实例特征；场景成员、边界、状态列表和动态列表直接保存引用。旧四个实例组织锚和C/E/S状态使用绑定退出。
7. 状态本体保存被描述存在、当时采用的特征概念、固定准确值和强时间。实例特征当前值实际改变时被动生成状态；场景列表补充发生场景组织位置。状态只在执行引用减法后变为零且无其它正式引用时删除。
8. 原子动态由同一主题、同一特征类型且准确值实际变化的两个状态构成；复合动态由至少两个原子动态按串行或并行外部关系组成。动态类可以建立实例动态概念并在需要时归纳上位概念，场景随后组织动态引用。
9. 二次至n次比较结果默认只作本次值式材料，不取得独立持久实例身份。动态可以把由自身正式状态成员确定计算出的时间差、比较类型和结果值域保存为动态内部字段；这不是独立二次特征实例，不授权其它宿主持久化任意高阶结果。
10. 因果节点是由至少两次独立发生形成、可持续修正统计的参考规律，不另建因果实例类或候选概念类。已知动作因果和未知动作因果分账；因果只提供方法形成与尝试参考，不证明必然结果或执行授权。
11. 所有需求都是自我的需求；一个需求恰好保存一个目标存在、一个目标特征类型，以及严格二选一的目标值/值域合同或目标变化方向。多特征目标通过父子需求或已经形成的复合特征类型表达，不在一个需求内保存多条件组。一个任务恰好对应一个需求，一个需求最多对应一个任务身份；任务收束后需要继续治理时重新启用同一任务，不建立第二任务。
12. 任务不建立任务轮次或筹办轮次；每次真实方法调用建立执行实例。已完成、已失败或已取消是当前收束状态，不是永久禁止重新启用；self fresh确认同一长期需求仍需或再次需要治理后，可以经manager复核把同一任务重新启用到方法查找或等待条件，但不得直接进入执行、撤销既有结算或重复结算同一任务。任务优先级由任务管理线程依据当前需求权重、可执行性、损耗及正式调度规则动态计算，不作为任务持久字段。
13. 执行前结果获取硬门、W3-A/W3-B分步、影响评估和self后继决议继续服从3200、5090、5260、8000、8100、8200和8210；去除任务轮次后，旧合同中以任务轮次或筹办轮次作为业务身份的字段改由任务、执行实例、工作包及原请求身份承担，不得重新引入轮次对象。

旧规范、详细设计、流程图和代码与本节冲突的内容只作为迁移定位，不再取得正向机器语义资格。本节正式化不证明代码迁移、持久化、生产装配或运行验收完成。

## 2. 权威与事实分层

1. `规范/规范目录.md` 及其登记规范是本项目机器逻辑的唯一正式定义来源。
2. 程序行为、外部材料、候选稿、日志、界面、缓存和过程记录都不能越过本目录直接裁决本项目事实。
3. 机器事实必须同时具有稳定编码、确定类型、合法写入方、可追溯来源、明确当前存在/删除边界以及完整锁内发布结果。这是完整存储事实的成立条件，不要求每个DATA-L2公开对象复制全部技术元数据。
4. 本项目采用以下权威分账：

```text
锁保护的内存当前事实 = 唯一运行期机器事实权威；承载节点、外部关系、字段关系和字段直接值
持久快照 / 独立材料     = 完整当前状态的恢复证据、隔离恢复输入、应急审计材料和人机交互投影
内存缓存 / 索引 / 统计投影 = 从锁内当前权威状态确定重建的非权威加速结构
```

5. 一次写集在独占锁内完成全部候选校验后一次交换正式当前状态，该交换是运行期事实的唯一线性化点。候选对象、持久行、材料文件、缓存命中、索引命中、函数返回和未交换内存对象均不等于事实已发布。
6. 需要跨进程保存的事实必须以完整current-only快照和必要不可变材料保存足以验证数据集身份、编码、载荷摘要和引用闭合的恢复证据；其内容只能经隔离恢复和完整校验后一次交换为内存当前权威，普通业务不得直接以持久查询结果作为当前事实。
7. 进程启动且尚未完成恢复交换时不存在运行期权威。恢复完成后，锁保护的完整内存当前状态成为唯一运行期权威；持久原材料及交互投影仍不取得运行期裁决权。
8. 持久恢复只重建基础数据集的节点、外部关系、字段关系、字段直接值和稳定编码分配状态。恢复完成后，上层数据类必须经当前公开查询重新读取，不得以旧DTO、历史见证、持久格式版本或兼容壳取得当前身份。

### 2.1 新特征值、特征信息对象与内部可靠性

新版特征值对象以2100的物理类型、分层材料和精确复用规则为准；基础数据集只保存其节点、字段和直接值，不猜测业务物理类型。需要共同成立的结构由上层数据类形成组合变化集，底座提供原子发布和current-only恢复。

新版实例特征按1130表达持有节点、特征概念、当前准确值、去重历史值及命中次数、标准值、聚合值域和子特征。准确值变化必须生成状态；聚合形成区间后按7160维护具体概念。旧固定四字段、宿主槽、概念前置共同出生及“特征自身不保存当前/历史值集合”全部退出。

## 3. 数据服务分层与业务边界

当前基础数据架构只定义三层：

```text
L0 持久介质：保存基础数据集完整current-only快照、不可变材料和最小恢复信息
DATA-L1 基础数据集：节点、外部关系、字段关系和字段直接值的当前增删改查、组合原子发布与恢复
DATA-L2 上层数据类：使用同一基础数据集表达并校验特征值、特征、存在、场景、状态、动态、因果、需求、任务、方法等具名结构
DATA-L3 综合语义应用：经上层数据类形成世界树、概念组织和跨对象业务操作
DATA 之外的业务层：构造结构请求，解释业务名称、资格、目标、动作和结果
```

`DATA-L4`、`DATA-L5` 当前只保留层号而不定义职责；禁止为了维持旧五层叙述发明转发、解释或聚合层。

### 3.1 全局 ARCH 五层命名空间映射（20260824）

本项目同时使用全局架构命名空间 `ARCH-L1`—`ARCH-L5`。它不是对 `DATA-L1`—`DATA-L5` 的改名，也不授权把现有 C++ 的 `L2` 名称直接解释为某一全局层：

```text
ARCH-L1 = 统一事实内核                         ↔ DATA-L1
ARCH-L2 = 通用基础结构（世界、语言、概念基础结构） ↔ DATA-L2
ARCH-L3 = 世界树应用、概念树/概念空间聚合        ↔ DATA-L3 / DATA 之外应用边界
ARCH-L4 = 需求、任务、方法及其业务治理            （不定义 DATA-L4）
ARCH-L5 = 自然语言理解/表达与名称绑定裁决         （不定义 DATA-L5）
```

`ARCH-L5 -> ARCH-L4/ARCH-L3/ARCH-L2`、`ARCH-L4 -> ARCH-L3/ARCH-L2`、`ARCH-L3 -> ARCH-L2 -> ARCH-L1`是依赖主方向，禁止底层反向依赖上层业务。ARCH-L4的需求、任务和方法具有独立逻辑根，其中任务虚拟存在`Vt`是任务状态宿主，不进入世界树，也不构成世界状态的第二权威。

概念身份语言无关。特征概念树、存在概念图和动态概念结构分别由对应概念类维护，自然语言类只建立名称关系；名称不得反向成为概念或世界节点身份。

1. 分层表示数据结构承接和依赖方向，不表示代码目录、进程、部署单元、能力成熟度或必须按编号顺序实施。
2. `DATA-L1`不识别任何业务结构类型；`DATA-L2`的各数据类负责自身字段、关系、基数、顺序和生命周期校验，不把业务语义下沉到底座。
3. 所有数据类共享一个全局基础数据集和稳定编码空间。每棵树或图以自己的根节点和字段关系组织，不建立owner分区或第二事实仓。
4. `ARCH-L4`的结构保存与业务判断分账：数据类保存需求、任务和方法结构，自我线程、任务管理线程和任务工作线程决定为什么建立、选择、推进、结束和判定。
5. 每类业务结构只通过本类公开函数建立、修改、删除和查询；函数调用基础数据集完成结构操作，不直接访问底座私有容器。
6. `DATA-L3`综合应用只经各数据类公开能力形成世界树、概念组织和跨对象流程，不复制底层CRUD或结构权威。
7. 业务调用方负责把业务决定转换为数据类请求并解释返回结果；不得取得持久介质事务、底座锁、可变内部容器或缓存写权。
8. 一个基础数据集可以承载多棵逻辑树和多张图。树根、概念根、需求根和方法根都是普通稳定节点；全局变量只保存这些根节点的受保护引用。
9. 新世界树类位于各领域数据类之上，从世界树根场景出发确定位置，再调用场景、存在、特征、状态、动态和因果类完成综合操作；不得复制底座数据。
10. 世界信息创建按各对象现行合同执行：存在先建立实例特征再建立专属存在概念；已有特征类型的新实例先查找同类型且最小包含实际值的特征概念，找不到属于逻辑错误；实例聚合形成新区间时再创建或修订子概念。
11. 数据类之间只通过具名、强类型公开函数交互。公开合同至少冻结请求、结果、稳定编码、单调用一致性、结构化非成功和删除边界，不携带业务许可结论。
12. 不强制按层号逐级代理。消费者按真实依赖直接调用所需数据类；不存在真实结构依赖的中间层不得成为转发壳或隐式授权者。
13. 服务只返回调用方拥有的值式结果，不泄漏基础数据集可变对象、持久介质、锁、事务、缓存或内部候选。
14. 本项目不以合同版本字段猜测兼容。不兼容变化直接修订当前具名强类型合同并同步迁移全部消费者；未迁消费者必须明确拒绝或停用。
15. 需要联合结构的一致读取必须由一个组合查询在同一共享锁内完成；多次独立调用不承诺共同快照，也不使用事实代次、历史见证或`Gread/H`拼接。

### 3.2 完整读取范围与资源失败

1. 业务或上层应用先按真实目标给出本次必须处理的完整语义范围；范围由目标身份、类型/关系条件、显式输入集合、必要闭包和业务明确要求的数量组成，不由底层资源额度反向裁剪。
2. 下层服务必须完整读取并返回该范围，或者返回具名非成功。节点数、关系数、值数、材料数、候选数、展开深度、计算步数及类似资源计数不得成为业务准入条件、成功上限或截断依据；不得返回部分结果并宣称完整成功。
3. 分批、分页、流式、缓存和内部并行只属于执行方式。中间批次不是业务成功载荷，最终结果仍须覆盖请求的完整语义范围，并保持完整性和确定顺序；需要原子一致范围时必须使用单个组合读取。
4. 锁、内存、存储、时间或其它执行资源不能完成完整范围时，返回`资源失败`并清空依赖完整性的业务载荷；不得返回`预算不足`、伪空组、伪未命中或截断成功。调用方可以在保持同一业务语义时重试，但不得通过缩小必要范围把失败改写为成功。
5. 结构基数不是资源预算。`0..1`、恰好两项、完整父组、请求明确的前N项或显式有限候选集合等若属于对象定义或业务查询范围，继续按各自合同校验；它们不能被复义为底层自选上限。
6. 实际用量、性能计数和诊断统计可以作为非权威观测返回，但不进入事实身份、幂等语义、业务成功谓词或跨服务总账。提供者之间不建立共享计量会话，不以计数相加证明完整读取。
7. 下级规范、详细设计和既有代码中以节点、关系、值、材料、候选、深度或步骤等底层资源预算限制必要读取范围的字段、状态和分支，统一降为旧ABI迁移识别。上层可以按业务目标主动缩小问题，但底层不得用极大数或隐式上限模拟无预算。

### 8.1 内部治理、现实观察与现实改变的授权边界（20260824）

项目必须先按实际动作效果区分：

```text
内部治理
    = 读取、比较、形成候选、选择、筹办、状态迁移、结果收束、安全 / 服务结算和后继裁决等只改变内部治理事实的动作

现实观察
    = 以读取现实为目的，只把观察材料和认知事实带回内部，且不包含对外部对象、外部主体或受保护资源的可观察改变

现实改变
    = 预期或可能改变外部对象、外部主体、外部系统、物理环境或受保护资源状态的动作
```

分类只看直接作用对象和实际效果，不看调用线程、使用目的或结果将被谁消费。读取内部正式owner事实通常只是服务调用，不因被任务使用就自动成为方法；改变任务虚拟存在、方法虚拟存在或自我的安全值/服务值内部实例特征属于内部治理。内部治理相当于“想”，不需要自我现实执行授权；它仍必须遵守公开调用、结构写入、原子发布、当前性和数据安全合同。现实观察与现实改变不得混账：纯观察不需要自我现实执行授权，观察结果供内部治理使用也不会因此变成内部治理方法；主动探测、设备运动、发射、外部通信、写外部系统或其它具有现实副作用的观察步骤，按现实改变步骤处理。

普通方法不得直接改写世界树当前值来自证成功。现实结果由合法观察渠道取得并由对应事实owner更新；状态、动态、因果和概念由各自owner根据正式事实变化自动形成或维护，不作为本能函数直接修改的目标。服务值结算按6190属于内部治理后处理，不能用普通方法返回值、任务完成状态或世界特征写入代替。

所有后继本能方法统一采用“动作先登记、结果后确认、显式关联”的执行套路。进入真实改变或观察前，调用方必须以本次执行来源身份建立动作动态并挂入发生场景；改变型方法把该动作显式关联为结果动态的`导致变化`来源，观察型方法把该动作显式关联为`观察取得`，不得把观察写成因果。真实结果仍由正式事实owner发布并重新读回；没有结果动态时允许动作独立存在，没有显式动作节点时结果动态正常成立但不建立动作关联。禁止扫描场景动态列表、按最近时间或调用成功码猜测动作来源。动作记录已成立而后续改变、观察、结果发布或关联失败时必须返回部分完成，不得为补记录自动重做动作。

只有任务冻结的执行方案中至少包含一个现实改变步骤时，才在执行实例建立、方法和参数冻结完成后、首个现实改变步骤之前取得一份正式`自我现实执行授权事实`。该事实至少绑定自我、任务、执行实例、采用方法及其完整内容、被授权现实动作范围、结果获取途径和发生时间；任一绑定材料变化使旧授权失效。同一授权不得扩张到新的执行实例、未列动作或其它任务。

`自我现实执行授权事实`同时覆盖该冻结中的任务、执行实例和采用方法，不再分别建立“任务授权”和“方法授权”。拒绝、等待、取消、任务后继决议、需求确认、方法发布准入、结构写许可、公开调用许可、调度优先级和安全硬否决都不是第二份正向执行授权。安全与生存服务只提供当前安全事实、调度材料和具名硬否决；它们不得正向授权现实动作，自我授权也不得绕过硬否决。

```text
-> 结果条件具备后派发W3-B获取真实结果 -> 影响评估及尝试收束 -> 待self后继决议
-> self决定完成 / 继续 / 重试 / 重新筹办 / 等待 / 失败 / 取消
-> manager复核后由task owner发布对应状态；正式完成按任务身份结算一次，失败 / 取消只记录并处理结果
```

任务不建立任务轮次或筹办轮次。每次真实方法调用只建立一个执行实例；目标未达成是该执行实例的验证结论，不触发任务结算。执行实例评估后任务先进入等待self决议，self独立读回正式结果、影响评估和当前需求后形成后继决议；manager、worker和影响评估都不得绕过self直接决定任务终态。继续、重试或重新筹办必须回到方法查找或等待条件，再建立新的执行实例并重新冻结；含现实改变时重新取得该执行实例的现实执行授权。

### 8.2 状态驱动的任务筹办、需求确认与执行前选择（20260903）

1. 任务筹办是任务领域内部治理函数，由任务管理线程根据任务当前状态异步派发。一次调用只完成当前状态指定的一段工作：先多次找方法，方法范围完整覆盖后再多次查找并核验各候选方法的条件；它不执行方法、不建立执行实例或执行冻结，也不建立需求、子需求或子任务。
2. 找方法阶段必须回显已覆盖 / 剩余范围和零个或多个`方法身份 + 内容版本`；查到第一条候选不等于完成。查条件阶段必须保留`方法身份 + 内容版本 -> 条件组 -> 核验结果`对应关系，并覆盖全部候选与条件组；不得摊平成任务级条件总表、按名称或哈希临时拼组，或因先发现一组具备就跳过其余候选。
3. 筹办通过任务服务补全当前任务的候选方法和条件核验材料，不建立任务轮次、筹办轮次或任务信息版本。每个已消费工作包只投递一条不可变强类型消息；任务管理独立读回任务、调用前状态、已覆盖 / 剩余范围及本次结果后，才提交状态迁移。消息交接与独立读回不是第二候选账、条件账、结果账、线程或outbox。
4. 正常业务结果只描述找方法 / 查条件进度：继续找方法、方法完整且有候选、方法缺失、继续查条件、全部核验且至少一组具备、条件缺失。目标已完成、子目标承接、采用方法、执行实例和冻结都不是筹办结果。
5. 资源、投递或发布未知时业务状态不前进，保留原工作包和原请求查询或恢复；当前材料已经变化时本次结果失效并在同一业务子状态重新读取。ABI、引用、断言和内部代码错误停止受影响调用；技术非成功不得伪装成方法缺失、条件缺失、等待或需求。
6. 方法或条件缺失只先成为当前任务材料。自我线程fresh读取父需求、目标合同和正式筹办材料后，独立产生并确认是否存在必要子需求；任务服务和需求服务只保存该正式决定，不得替代self产生或确认需求。
7. 适用性、实际采用、选择和冻结只在真实动作前的执行前选择入口进行。该入口 fresh 复核可用性和安全硬门，再在可比较候选中选择收益 / 付出综合代价最小的一项；代价可包含安全值或服务值收益 / 付出、时间成本及正式登记的其它成本。未知、不可比或并列最优不得任选。
8. 任何正式任务进入方法执行时，均在选择冻结后、真实派发前由自我作综合判断，读取当前需求活动资格、目标、收益 / 付出、资源冲突及安全材料。该内部治理决策不另造第二正向授权；只有含现实改变时才发布本规范第8.1节的唯一现实执行授权。筹办、结算、消息处理等内建函数不因此递归建立审批任务。
9. 安全硬否决和生存安全根控制态是不可抵销门槛。服务根只作为普通根需求坐标参与其正式需求收益判断；已退出的服务合同 / 余额、线程或队列状态不得伪装成选择余额。

## 9. 结构化非成功与内部不一致

1. 写前形状无效、未找到、引用冲突、重复请求异义、格式不支持等使用具名结构化结果，零数据写入；业务权限或其它业务前置不满足由`DATA`之外业务层返回，不得伪装成数据层状态。
2. 合法等待、候选为空、目标已满足和显式未实现属于协议内结果，不得压成裸失败。
3. 前置通过后出现身份复义、关系矛盾、内存发布读回不一致、半结构可见或事实链缺失，属于内部不一致；必须停止依赖路径并进入审计 / 恢复，不能包装成普通业务拒绝。
4. 日志、弹窗、扫描器和事后校验只能诊断，不能修复或改变机器事实。

## 11. DATA 无权限裁决与状态动态总则

1. `DATA-L1`—`DATA-L3` 不识别调用者业务身份，不判断谁有权读、写、改、删。业务或治理层必须在调用DATA前完成权限与资格裁决；DATA请求和结果不得携带或生成业务许可结论。
2. 基础数据集没有公开owner分区、`写入所有者`、业务类型、事实代次或公共幂等账。旧owner、代次、截止、TTL、墓碑和维护身份只用于迁移定位或旧材料拒绝，不得进入新版生产请求和结果。
3. 每类上层结构只有一个权威服务和事实来源。业务结构通过节点、外部关系、字段关系和字段直接值组合表达，不得复制第二仓或绕过基础数据集直接访问其内部容器。
4. 状态直接保存被描述存在、特征概念、固定准确值和强时间；场景只组织状态引用。状态不是实例特征当前值权威，C/E/S绑定、独立属性上下文和状态TTL不再是现行前置。
5. 原子动态直接引用两个状态；复合动态通过串行或并行外部关系引用原子动态。场景只组织动态引用，动态概念和动态实例分账；首次状态和无准确值变化都不得补造动态。
6. 状态、动态和概念节点的删除只按各自引用计数及子节点合同在真实引用减法后触发，不设置周期TTL清理、后台维护线程或特殊清理身份。底座删除前仍必须闭合全部当前引用。
7. 任务阶段状态属于ARCH-L4任务虚拟存在，不属于世界状态或动态。执行动作造成的世界特征变化按1130、1160和1170记录，与任务状态、执行实例和影响评估分账。

## 7.2 世界主体、视角与概念依附补充裁决（20260912）

1. 世界树权威根是根场景节点，进程普通应用只允许发布一个全局根引用；全局变量是对该节点的受保护引用，不是第二根事实或调用方可改配置。
2. 场景父子关系只组织场景层级；存在的场景成员归属与父存在组成分账，可以同时存在。位置读取必须分别返回这两类关系，不得压成唯一结构父。
3. 场景直接持有成员、边界存在组、状态和动态引用，不建立四个实例组织锚。场景作为存在时直接持有实例特征和专属存在概念。
4. 特征概念树、存在概念图和动态概念结构各自使用独立根或根链，并通过字段引用与世界实例关联；概念上下位不参与世界树场景归属或存在组成裁决，因果按1190独立组织。
