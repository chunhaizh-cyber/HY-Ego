# 6130 子规范 自我根特征抽象定义与自检缺口

编号：6130
日期：20260901
版本：v0.11
状态：正式子规范

## 1. 定位

本规范规定自我安全、服务等根特征的抽象定义、自我实例、自检读取、缺口候选、因果学习和需求准入边界。

直接上级规范：1120、1130、1140

直接依赖规范：5130、6100、6120

相关边界规范：1160、1170、1190、3100、6140、6150

## 2. 根特征定义

安全、服务和其它自我根特征必须先成为正式抽象特征定义，至少明确：

- 稳定特征身份、值域和比较规则；
- 根目标状态和合法生产者；
- 当前值、候选值、明确性、搜索完整性和有效期；
- 状态、动态、二次特征和因果如何组织；
- 缺口对应何种需求目标；
- 事实如何验证、归因和回写。

安全根定义还必须声明分层安全值定义模板：I64 值域、低位阈值、高位阈值、被动维护规则版本、对应目标安全结果和合法证据类型。具体安全层级不进入根定义固定表，而由来源因果信息相对于目标安全结果的当前直接因果图投影得到。

自然语言名称只用于人类定位。固定 C++ 函数表、字段名、显示阈值和日志不得成为根定义权威。

## 3. 不得硬编码安全或服务因素表

安全定义不得预置硬件、软件、资源、环境、权限、观察、风险或服务等固定必要因素表，也不得按固定配额分割物理安全区间。

正式影响因素来自抽象特征树、出生期因果假设和后天证据增强后的因果信息。安全层只按已正式成立、方向明确且版本有效的直接因果关系动态投影，不得预先列举某类需求或任务固定属于哪一层。字段名称可以存在于事实材料、对象方法输出或提交结果中，但不能因字段存在就自动生需或成为安全组成因。

服务根当前值定义保留 `0..I64_MAX` 值域，但不再携带合同、预算、有效期、预支、余款、到期、准备补回、时间衰减、服务比例或安全根回归规则。当前交互者、服务对象、反馈、验证和归因只有在具体服务触发和动作后才成为普通业务上下文事实。

安全根值与服务根值的冷启动首次当前值均固定为 `I64_MAX / 2 = 4,611,686,018,427,387,903`，非负整数除法的余数 1 舍弃；目标值均为 `I64_MAX`。首次当前值必须分别与初始状态共同形成且不产生动态，不得把“中位数”解释为包含负数的完整有符号 I64 类型中位数。

安全根值和服务根值都是由各自特征定义封闭解释的无外部物理单位标量。建立目标判断比较注册时，`单位`、`维度`、`分量角色` 三个稳定身份必须分别绑定对应根特征定义身份：同一身份在三个字段中分别表示“按该定义的刻度计量”“该特征自身的比较维度”和“该标量的完整分量”。三字段的字段语义不得互换；安全根与服务根因特征定义身份不同而不得交叉比较。禁止为此另建单位、维度或分量角色持久节点，也不得填入猜测编码。

双根冷启动角色不建立角色节点、角色关系、角色 owner、角色索引或第二需求账。安全根与服务根分别使用固定、版本化且互不相同的一组业务幂等身份形成或恢复其特征定义、实例、目标合同、根需求和列表项；启动提供者在同一非零事实截止逐项正式读回后，把结果写入 `本能根运行锚点_v1` 的具名安全字段和服务字段。该锚点只是不可变值式角色绑定与读回证明，不是持久事实或第二当前权威；固定幂等身份也不是节点、关系和值的稳定编码。后续自检只能使用锁定锚点中的具名身份 fresh 读回，不得按普通根组顺序、名称、创建顺序、编码大小或目标值猜测角色。

## 4. 自我实例和运行期视图

自我实例通过当前自我存在稳定句柄，关联根特征实例槽、唯一当前属性槽、当前值事实、状态 / 动态证据和根闭环因果坐标。运行期读取结果可以使用值式视图汇总：

```text
根特征定义身份
+ 自我实例槽
+ 同截止当前特征值完整投影
+ 状态 / 动态证据引用
+ 适用范围、来源和版本
+ 当前因果证据和缺口
```

值式视图是按需组合读取投影，不是新增持久字段或第二权威账。已有抽象定义、关系、状态、动态、二次特征和因果能表达时必须复用；自我实例结构服从 7130。

安全层读取投影可以追加来源因果、目标安全结果、因果图版本、全部有效路径、最短精确深度、五级调度组和当前层安全值规格，但这些项目必须分别回读正式因果、状态和领域类型化记录；间接因果、固定层号和汇总列表不得成为第二权威事实。

## 5. 证据与因果

状态和动态是安全 / 服务的历史与变化证据本体，但不是当前值权威。当前特征值通过宿主、特征定义、实例槽和当前属性槽取得业务语义；状态、动态、场景和因果关系进一步解释其来源、变化及安全 / 服务证据，不得要求先读取状态记录才能比较当前值。

历史直接伤害应先形成或更新负向安全因果信息，不另建历史伤害直查旁路。出生期因果只表达带来源动态证据或出生期假设标记的被动触发结构；主动动作能力来自本能方法和方法系统，不能由遗传因果直接伪造。

后天证据可以强化、削弱、分化或覆盖出生期被动因果。因果候选只保存稳定证据引用和候选归因，不表示存在本体自带安全度或伤害概率。

## 6. 安全评估视图

存在、场景和风险安全值均为按当前事实计算的候选视图，不是对象固有字段。若没有历史风险材料，历史值为零只表示没有材料，不表示安全。

完成正式搜索而未发现负向证据时，只能提交带范围、来源、有效期和搜索完整状态的无负向证据结果。未知不得写成危险，也不得用 `I64_MAX` 写成默认安全。

场景中多个已确认存在属于同层风险因素时，可以先按统一方向和版本聚合风险压力，再转换为风险余量候选；最低安全度存在只作诊断和处置线索，不单独裁决场景或自我安全值。

评估结果不能直接结算自我生存安全根值。它只能生成风险因子、处置需求候选、持续观察或降级保护候选；生存安全根值的变化仍经根控制、因果归因和 6100 主动安全结算。具备复发机会、有效感知覆盖、场景 / 因素身份可比和确认未复发证据时，评估结果可以提交给 6140 作为分层安全值被动维护材料，但不得直接写值。

## 7. 自检流程

```text
读取当前自我稳定身份
-> 读取根特征抽象定义和版本
-> 定位自我实例特征槽
-> 读取目标涉及的当前特征值、搜索完整性和有效期
-> 按目标状态合同比较当前特征值
-> 查询原因、可改变性、可验证性和回写路径
-> 形成当前满足 / 正差距 / 方向相反 / 不可比较 / 材料不足 / 当前性漂移 / 内部不一致
-> 交需求治理入口裁决
```

自检只读取权威结构并形成值式裁决或候选；不得直接写需求树、创建根需求、创建任务、创建方法首或修改根值。

### 7.1 双根逐轮比较

冷启动完成后，自检必须从 ARCH-L4 正式角色绑定取得安全根 D 和服务根 D，不得从普通根组顺序、名称或目标猜测角色。两个根在同一非零 G0 下分别读取完整目标合同与当前值；任一读取前后事实代次变化均为当前性漂移，不能返回部分成功。

根目标固定为 `M = I64_MAX`。当前值通过同 G0 正式读回且位于 `0..M` 时，使用无溢出的非负整数减法精确形成 `Δ = M - 当前值`：`Δ > 0` 表示正差距和当前需要提高，`Δ == 0` 表示当前满足并保持。合法根值不会产生方向相反；负值、坏类型、坏目标、公式不一致或无法证明同截止均为内部不一致、不可比较、材料不足或当前性漂移，不得钳制。差值是应用已登记概念形成的任务局部二次特征值式投影，使用后立即丢弃，不登记身份、实例、当前值、状态或动态。

当前满足只表示该根本轮不展开具体需求，不删除、失活或退役根 D。两根分别裁决，不得以一个根的状态代替另一个根，也不得形成综合分数后再判断。

状态和动态只提供历史、来源、变化解释及重检触发。即使自检由某条动态触发，也必须重新冻结 G0，读取当前特征值和目标合同后比较；不得直接使用动态后状态或最后状态记录。

## 8. 缺口候选合同

缺口候选至少包含自我身份、根特征定义、实例槽、事实截止、当前特征值完整投影、目标状态合同、比较关系、证据状态、可选状态 / 动态证据引用、来源因果、目标安全结果、因果图版本、闭环位置、可改变性、验证方式、建议需求类型和有效期。精确因果深度和五级调度组由正式投影服务计算；无有效路径时只标记尚未归层。

缺当前事实、搜索完整状态、归因、物理安全目标或服务能力目标时，只能形成材料缺口、风险候选或待补证据。

无直接服务触发事实时，服务根缺口只允许形成监听、机会检查、能力校准或服务根检查候选；不得写当前服务对象、目标、完成、合同或服务值账。

## 9. 第二层子需求

根缺口不固定展开第二层子需求。安全子需求必须来自安全因果风险树、具体负向触发事实和可推进路径，并按相对于具体安全结果的当前有效因果路径动态取得精确深度；具体服务子需求必须来自真实服务触发事实并经普通需求入口形成。

已满足条件不得同时生成需求。历史固定安全或服务子需求如果没有当前因果和事实支持，只能收束、清理或保持未触发，不得因名称仍存在而重激活。

## 10. 自检动作动态

只有明确登记并实际执行的自检方法可以成为自检动作动态来源。自检报告作为需求信息来源时，如果没有自检方法执行事实，不得把自我线程、任务管理线程或扫描循环当作动作来源。

自检发现问题不等于问题已解决，也不得结算安全值。后续处置必须另有任务、方法、结果动态、验证和归因。

## 11. 服务根特征边界

服务根保留为独立长期普通需求坐标。其定义与当前值不得携带合同、预算、有效期、预支、余款、到期、准备补回、时间衰减、服务比例或安全根回归规则。

在新的简化维护语义正式冻结前，服务根当前值不得由合同、时间、任务数量、方法次数、循环次数或服务结果推导，也不得驱动安全根变化、任务调度或现实执行授权。缺少合法维护来源时返回材料不足，不建立临时替代算法。

## 12. 方法和降级保护边界

无候选方法时不得自动创建方法首。自检只能报告缺动作能力、缺路径、缺事实或等待外部输入。方法能力必须由正式登记、规格和实际运行证据建立。

降级保护只在负向影响处置需求明确且安全影响因果明确时执行；默认良好、未知或单纯缺材料路径不得触发降级方法。

## 13. 写入与验证

抽象特征服务负责根定义；特征服务负责自我实例槽和当前值；状态、动态和因果服务负责事实与证据；自检编排只产生值式候选；需求服务是正式需求入树的唯一写入方。

验证覆盖根定义非文本化、无固定因素 / 层级表、实例槽和当前属性槽归属、同截止当前值读回、状态 / 动态仅作证据、动态触发后重新读取当前值、层值规格、因果路径投影、自检不直写、历史固定需求不重激活、服务根无记账 / 无时间推导边界、无候选方法和下一轮回写。
