# 6130 子规范 自我根特征抽象定义与自检缺口

编号：6130
日期：20261008
版本：v0.21

## 1. 定位

本规范规定自我安全根特征、自我服务根特征、双根自检读取、缺口材料、因果学习和需求准入边界。

直接上级规范：1120、1130、1140

直接依赖规范：3100、6100、6120、6190

相关边界规范：1160、1170、1190、3100、6140、6150

## 2. 根特征定义

安全和其它由自我存在持有的根特征必须先成为正式抽象特征定义，至少明确：

- 稳定特征身份、值域和比较规则；
- 根目标状态和合法生产者；
- 当前值、候选值、明确性、搜索完整性和有效期；
- 状态、动态、二次特征和因果如何组织；
- 缺口对应何种需求目标；
- 事实如何验证、归因和回写。

安全根定义还必须声明分层安全值定义模板：I64 值域、低位阈值、高位阈值、被动维护规则版本、对应目标安全结果和合法证据类型。具体安全层级不进入根定义固定表，而由来源因果信息相对于目标安全结果的当前直接因果图投影得到。

安全值是先天定义的正式特征类型，值为I64，值域为`[0,I64_MAX]`，没有外设提供者；安全FT必须具有独立的完整域顶层特征概念“安全值FT + `[0,I64_MAX]`”。安全FT/完整域概念初始化提供者建立或精确复用两层并以current-only方式完整读回；该初始化不形成根需求、当前F、当前采用、状态或动态。

服务值是与安全值分离的先天定义FT，具有独立类型根、`[0,I64_MAX]`完整域概念和唯一自我实例特征。目标`I64_MAX`，当前值从自我实例特征current-only读回；6190只通过特征owner执行合法结算和后续衰减，不建立第二账户。

自然语言名称只用于人类定位。固定 C++ 函数表、字段名、显示阈值和日志不得成为根定义权威。

## 3. 不得硬编码安全或服务因素表

安全定义不得预置硬件、软件、资源、环境、权限、观察、风险或服务等固定必要因素表，也不得按固定配额分割物理安全区间。

正式影响因素来自抽象特征树、出生期因果假设和后天证据增强后的因果信息。安全层只按已正式成立、方向明确且版本有效的直接因果关系动态投影，不得预先列举某类需求或任务固定属于哪一层。字段名称可以存在于事实材料、对象方法输出或提交结果中，但不能因字段存在就自动生需或成为安全组成因。

服务值实例特征使用`0..I64_MAX`值域，不携带旧合同、预算、预支、余款、到期、准备补回、服务比例或安全根回归规则。它只按6190消费经确认的人类服务、现实改善、观察验证和归因材料增加，并按后续冻结的可信时间规则衰减。当前交互者、服务对象、反馈、验证和归因只有在具体服务触发和动作后才成为普通业务上下文事实。

安全根值与服务根值的冷启动首次当前值均固定为 `I64_MAX / 2 = 4,611,686,018,427,387,903`，非负整数除法的余数1舍弃；目标值均为`I64_MAX`。两项首次值分别进入唯一自我的安全值、服务值实例特征，初始化形成初始状态但不形成变化动态。不得把“中位数”解释为包含负数的完整有符号I64类型中位数。

安全根值和服务根值分别由各自FT封闭解释；两者都是无外部物理单位的非负I64标量，但不共享类型、实例或当前值。两根目标判断都使用各自类型、单位、维度、分量角色、完整域概念和正式比较关系，不得交叉比较。

双根冷启动不建立角色节点、角色关系、底层owner分区、角色索引或第二需求账。系统先建立或复用安全值/服务值各自FT、完整域概念和唯一自我实例特征，再由需求类建立或复用两个目标存在均为唯一自我的根需求和固定列表项。self线程直接保存并读回两个具名根身份；后续自检按根角色取得需求，再按目标存在和目标特征类型fresh定位实例特征，不按顺序、名称、编码或目标值猜测角色。

安全值/服务值FT及完整域概念在系统初始化阶段建立或复用；双根初始化消费该交付，并按唯一自我建立或复用两个实例特征、当前采用、目标合同、根需求和列表项。不得以根需求反推类型来源，也不得建立根专用实际特征字段。

## 4. 双根运行期视图

两个根都保存目标存在与目标特征类型，并按该组合fresh定位唯一实例特征、读取准确当前值，关联状态/动态证据和根闭环因果坐标。运行期读取结果可以使用值式视图汇总：

```text
安全根：安全FT + 自我引用的安全特征节点 + current-only当前值 + 状态/动态证据
服务根：唯一自我 + 服务值类型根 + 服务值实例特征 + current-only当前值 + 目标值
+ 各自适用范围、来源、因果证据和缺口
```

值式视图是按需组合读取投影，不是新增持久字段或第二权威账。安全值和服务值都服从自我实例特征结构。服务动作造成的现实变化仍由正式世界事实、状态、动态和因果表达，它们只作为6190结算证据，不成为服务值第二权威。

安全层读取投影可以追加来源因果、目标安全结果、因果图版本、全部有效路径、最短精确深度、五级调度组和当前层安全值规格，但这些项目必须分别回读正式因果、状态和领域类型化记录；间接因果、固定层号和汇总列表不得成为第二权威事实。

## 5. 证据与因果

状态和动态是安全 / 服务的变化证据本体，但不是当前值权威。当前特征值按特征信息节点读取，并由正式特征类型解释；内联 I64 使用完整准确内容，值身份引用按 2100 完整读回，不为内联值补造值身份。状态、动态、场景和因果关系进一步解释其来源、变化及安全 / 服务证据，不得要求先读取状态记录才能比较当前值。

历史直接伤害应先形成或更新负向安全因果信息，不另建历史伤害直查旁路。出生期因果只表达带来源动态证据或出生期假设标记的被动触发结构；主动动作能力来自本能方法和方法系统，不能由遗传因果直接伪造。

后天证据可以强化、削弱、分化或覆盖出生期被动因果。因果候选只保存稳定证据引用和候选归因，不表示存在本体自带安全度或伤害概率。

## 6. 安全评估视图

存在、场景和风险安全值均为按当前事实计算的候选视图，不是对象固有字段。若没有历史风险材料，历史值为零只表示没有材料，不表示安全。

完成正式搜索而未发现负向证据时，只能提交带范围、来源、有效期和搜索完整状态的无负向证据结果。未知不得写成危险，也不得用 `I64_MAX` 写成默认安全。

场景中多个已确认存在属于同层风险因素时，可以先按统一方向和版本聚合风险压力，再转换为风险余量候选；最低安全度存在只作诊断和处置线索，不单独裁决场景或自我安全值。

评估结果不能直接结算自我生存安全根值。它只能生成风险因子、处置材料、持续观察材料或降级保护材料并交给self，同时绑定对应安全父需求；只有self fresh读取材料并产生、确认独立、必要、父域合法且能由自身目标状态合同最终判定的目标后，需求类才能建立或复用具体子需求。生存安全根值的变化仍经根控制、因果归因和 6100 主动安全结算。具备复发机会、有效感知覆盖、场景 / 因素身份可比和确认未复发证据时，评估结果可以提交给 6140 作为分层安全值被动维护材料，但不得直接写值。

## 7. 自检流程

```text
读取当前自我稳定身份
-> 按根角色读取目标存在与目标特征类型并fresh定位实例特征
-> 完整读取对应当前值、目标和来源材料
-> 按目标状态合同比较当前特征值
-> 查询原因、可改变性、可验证性和回写路径
-> 形成当前满足 / 需增加的正差距 / 不可比较 / 材料不足 / 当前输入变化 / 内部不一致
-> 交self作为对应安全根、服务根或其后继父需求的治理材料
-> 仅在self fresh读取材料并产生、确认独立、必要、父域合法且可最终判定的目标后
-> 由需求类在发布前精确匹配并建立或复用子需求
```

自检只读取权威结构并形成值式裁决或父需求治理材料；不得直接写需求树、创建根需求、创建任务、创建方法首或修改根值。

### 7.1 双根逐轮比较

冷启动完成后，自检必须通过需求类具名读取安全根D和服务根D，不得从普通根组顺序、名称或目标猜测角色。两个根都按目标存在和目标特征类型current-only读取唯一实例特征及目标合同。任一根读取不完整都返回结构化非成功，不能返回部分成功。

根目标固定为`M = I64_MAX`。当前值fresh读回且位于`0..M`时，使用非负整数减法精确形成`Δ = M - 当前值`：`Δ > 0`表示正差距和当前需要提高，`Δ == 0`表示当前满足并保持。固定公式下出现负差、坏类型、坏目标或公式不一致，均为内部不一致、不可比较或材料不足，不得钳制。根值实际下降可以是合法变化事实，但不把根目标变成减向；它只扩大下一次正差距。差值是即用即弃的值式判断，不登记独立身份、当前值、状态或动态。

当前满足只表示该根本轮不展开具体需求，不删除、失活或退役根 D。两根分别裁决，不得以一个根的状态代替另一个根，也不得形成综合分数后再判断。

安全状态和现实状态/动态只提供来源、变化解释及重检触发。即使自检由某条动态或服务结果触发，也必须按目标存在和目标特征类型fresh读取安全值或服务值实例特征的权威当前值及目标后比较；不得直接使用动态后状态、最后状态记录、任务完成状态或未结算服务结果。

## 8. 缺口材料合同

缺口材料至少包含自我身份、根特征定义、特征信息节点身份、当前特征值、目标状态合同、比较关系、证据状态、可选状态/动态证据引用、来源因果、目标安全结果、闭环位置、可改变性、验证方式、建议目标类型和有效期。精确因果深度和五级调度组由正式投影服务计算；无有效路径时只标记尚未归层。该材料不是需求，不取得需求身份，只能交给self裁决。

缺当前事实、搜索完整状态、归因、物理安全目标或服务能力目标时，只能形成材料缺口、风险候选或待补证据。

无直接服务触发事实时，服务根缺口只允许形成监听、机会检查、能力校准或服务根检查材料；不得写当前服务对象、目标、完成、合同或服务值账。

## 9. 第二层子需求

根缺口不固定展开第二层子需求。安全因果风险树、具体负向触发事实、可推进路径和真实服务触发事实都只能成为相应父需求的治理材料。只有self fresh读取材料并产生、确认某个目标独立、必要、父域合法且能由自身目标状态合同最终判定后，需求类才能在发布前精确匹配并建立或复用安全根或服务根子树中的具体子需求；安全子需求再按相对于具体安全结果的当前有效因果路径动态取得精确深度。

已满足条件不得触发新的需求产生。既有安全或服务子需求即使当前没有因果和事实支持，其身份与目标合同仍持续存在；只能更新为满足、等待、失活等治理状态，或退出相关活动关系和当前视图，不得删除、退出需求本体，也不得只因名称仍存在而重激活。

## 10. 自检动作动态

只有明确登记并实际执行的自检方法可以成为自检动作动态来源。自检报告作为父需求治理材料时，如果没有自检方法执行事实，不得把自我线程、任务管理线程或扫描循环当作动作来源；报告本身不成为需求来源关系。

自检发现问题不等于问题已解决，也不得结算安全值。后续处置必须另有任务、方法、结果动态、验证和归因。

## 11. 服务值边界

服务根保留为独立长期需求坐标。其当前值由唯一自我服务值实例特征提供。该特征不得携带旧服务合同、预算、预支、余款、到期、准备补回、服务比例或安全根回归规则；合法人类服务结算和后续时间衰减只按6190发生。

服务根当前值不得由任务数量、方法次数、循环次数、方法返回或任务完成直接推导，也不得驱动安全根变化或取得现实执行授权。只有已确认人类需求的实际满足、观察验证、改善证明和归因成立后，6190才可通过特征owner结算增加；时间衰减只消费可信单调时间与当前版本规则。缺少合法结算量、衰减参数、时间来源或防重复条件时返回材料不足，不能恢复旧算法或建立临时替代值。

## 12. 方法和降级保护边界

无候选方法时不得自动创建方法首。自检只能报告缺动作能力、缺路径、缺事实或等待外部输入。方法能力必须由正式登记、规格和实际运行证据建立。

降级保护只在负向影响处置需求明确且安全影响因果明确时执行；默认良好、未知或单纯缺材料路径不得触发降级方法。

## 13. 写入与验证

特征概念类和特征类负责安全值/服务值FT、概念及自我实例特征；6190负责结算和衰减业务门禁，并通过特征owner修改服务值。状态、动态和因果类负责现实事实与证据；自检编排只产生self可消费的值式材料。self fresh读取材料并确认目标后，由需求类在发布前精确匹配并建立或复用子需求。

验证覆盖双根定义非文本化、无固定因素/层级表、自我到两个实例特征的引用、两根分别读回权威当前值、状态/动态仅作证据、触发后重新读取当前值、层值规格、因果路径投影、自检不直写、收束任务只经self重新启用、合法人类服务结算、后续时间衰减、无候选方法和下一次重判。
