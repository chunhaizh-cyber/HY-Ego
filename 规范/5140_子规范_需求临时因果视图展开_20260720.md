# 5140 子规范 需求临时因果视图展开

编号：5140
日期：20260903
版本：v0.5
状态：正式子规范

## 1. 定位

临时因果视图是从一个完整需求目标向上游追溯条件、证据、促成路径、避免路径和方法就绪项的短生命周期解释结果。它不是新的权威需求树、因果树或机器账本。

直接上级规范：1190、3100。

直接依赖规范：4310、5110。

相关边界规范：5230、5250。

## 2. 输入准入

展开前必须具有目标宿主、目标特征、非零事实截止、同截止当前特征值完整投影、目标状态合同和满足关系。状态 / 动态只能作为历史、变化和因果证据附带，不得用状态记录或动态后状态补造当前值。缺失任一权威目标材料时，不得展开；应进入目标补齐、拒绝或开发诊断。

可读取的正式来源仅包括：完整因果及其动态证据、需求侧条件、方法条件、条件结果对、已入树子需求和当前世界事实。不得按安全、服务、观察、外设或学习等领域名称写死前置链。

## 3. 因果追溯

1. 主动动作致变因果可以支持可任务化路径或方法候选。
2. 被动、提交、结算和状态变化因果只能提供证据、等待、条件或上游缺口；必须继续追溯其来源动态、来源因果或条件事实。
3. 追溯只能在找到主动动作致变因果，或明确停在事实、条件、证据、方法、规范或诊断缺口时收束。
4. 单次共现、概率候选、状态变化线索和轻量因果引用不得被扩大为确定路径。

## 4. 允许输出

临时视图只能输出：

- 可继续任务化的路径建议；
- 促成、避免、条件、证据、方法就绪、副作用或学习缺口草案；
- 不可任务化原因、等待条件或诊断材料。

输出必须保留目标、来源因果或动态、适用范围、当前性、生成版本和截断原因。它只是当前父需求任务的材料；self fresh 确认其目标独立、必要、父域合法且能由自身目标状态合同最终判定后，由 task owner 形成正式子目标承接记录，需求领域统一入口才能据此校验、去重、合并并建立或复用子需求。筹办状态、候选方法和执行前选择均不能替代该确认。

## 5. 路径与方法边界

1. 临时视图属于任务筹办中的候选方法与条件关联分析材料，不替代任务级唯一筹办执行权和方法候选筹办。
2. 视图不得直接调用方法、创建任务、写需求树、改状态或提交结算。
3. 方法路径只说明某能力可能参与；真正候选必须按方法结果能力命中任务目标，并重新验证条件与动作入口。
4. 逻辑组织角色必须由目标特征定义和正式关系表达，不能按叶子/非叶子或显示名称猜测。
5. 子需求完成后仍要冻结新的事实截止，重新读取父目标涉及的当前特征值并按父目标状态合同裁决，不得由路径结束、子任务结果或历史状态直接宣称满足。

## 6. 安全、服务与观察边界

1. 未知场景不得直接解释为危险；安全路径必须有观察事实、风险因果和合法评估方法。
2. 服务根正差距允许建立或复用服务根治理任务；新到达的合法监听、机会检查、能力校准、外部请求或具体目标材料也可以建立、唤醒或复用该任务，但只授权 fresh 重判与材料裁决，不等同正差距，不改变服务根当前值，也不直接创建需求。只有 self fresh 确认独立必要目标并由 task owner 形成正式子目标承接记录后，需求领域才能建立或复用具体服务子需求。时间经过、无服务记录和普通服务结果都不得自动改变服务根、触发生存控制态变化或形成服务结算证据。
3. 服务不能使用“无负证据默认成功”；至少需要接收、反馈、外在状态改善、结果验证或因果归因。
4. 观察前置只能来自因果、需求条件或方法条件；相机预览、控制面板和只读快照不是需求满足证据。
5. 评估置信度、稳定度、优先级和成功率是临时推导，不能写成因果节点通用字段或平行权威记录。

## 7. 禁止事项

- 禁止持久化临时视图为并列权威树。
- 禁止生成不完整或仅含“改善、避免、明确”等口号的需求草案。
- 禁止任务管理侧自行指定层级权重；正式权重由需求领域按 5110 重算。
- 禁止把动作动态按成功/失败做根分类。
- 禁止把任务完成直接等于安全值、服务值或父需求变化。
- 禁止让未知、I64_MAX、无反馈或输出文本成为成功或满分证据。

## 8. 验证

验证必须覆盖主动因果、被动因果继续追溯、无因果路径、缺目标材料、缺同截止当前值、动态后状态不得替代当前值、路径截断、重复子需求合并、副作用并列输出以及草案未经提交不得成为正式需求。
