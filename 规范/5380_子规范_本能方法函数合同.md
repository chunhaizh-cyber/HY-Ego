## 1. 范围与职责

本规范逐个定义本能方法函数的合同：修改什么、为什么修改、达到什么目的，参数，各执行分支的必要条件，条件不足时的筹办去向，执行入口复核，正常结果，业务结果值域和工程故障边界。

所有本能共用的合同不在此重复：任务链是唯一调用路径（3300 §4.1），登记与动作动态（3300 §4.3、5360 §2），参数场景与运行隔离（3300 §5、5360 §3），本次运行条件—结果对（5360 §5），独立观察与任务验证（5360 §6），失败、重入与恢复（5360 §8）。

结算等内部治理函数不是本能方法（3300 §4.1），不在本规范范围。观察、识别、扫描、跟踪类本能由 6370、6380 规定，代码未实现，本稿不列。

## 2. 合同共同规则

### 2.1 合同条目

每个本能按 AGENTS §1.1 的顺序写出以下条目，缺一项即为合同不完整：

| 条目 | 内容 |
| --- | --- |
| 修改对象、原因、目的 | 修改虚拟存在还是现实世界的特征值；两类都改时分别写出各自的对象、原因和目的，不混写为一个动作 |
| 正常操作与结果 | 本函数实际取得或改变了什么；后续由谁使用；不得把下游治理的变化写成本函数的结果 |
| 参数 | 函数为完成正常操作必须拿到的对象 |
| 方法头 | 作用存在概念、涉及特征类型、可能结果 |
| 执行分支与必要条件 | 每个分支分别列出；每项写明声明位置 |
| 条件不足的筹办去向 | 可由行动满足的条件转成什么子需求；不可行动满足的条件由哪个替代方法承担 |
| 执行入口复核 | 只复核已声明的条件 |
| 业务结果值域 | 每种返回及触发条件 |
| 工程故障 | 哪些情况按工程异常路径处理 |

### 2.2 声明完整

1. 函数正常执行所依赖的每一项条件都必须写进方法声明。运行时只复核已经声明的条件。
2. 运行时核对了、声明里没有的条件，属于本能方法函数逻辑不完善。它会使筹办看不出缺什么、求解器无法收窄、失败无法形成学习信号，必须补进声明或删除。
3. 条件的声明位置：
   - 初始必要条件：只表达“参数属于某存在概念”或“参数具备某特征类型”；
   - 执行分支必要条件：值域、前态、数值区间等，每个分支分别声明；
   - 条件结果对：配对自身的条件与结果；
   - 参数关系：参数之间的关系。
4. 现有条件项与关系种类无法表达的条件，在本合同中写为“运行时复核（暂无可声明的条件项）”，并列入第4节缺口；不得把它包装成业务结果。

### 2.3 参数只取函数要用的对象

1. 参数是函数完成正常操作必须拿到的对象。
2. 由调用语境就能确定的东西不设参数让筹办去求解。例如询问时“问谁”由所用窗口决定，不设“受询者”参数。
3. 只为表达或判断而需要的信息，若能从已有参数读出，作为执行时材料读取，不另设参数；读取所依赖的条件仍须声明。

### 2.4 目标判定与执行条件分开

1. 函数目标已经达成（如被问字段已有值、自我已在目标场景），属于筹办阶段的目标判定，不作为执行条件，也不进入执行后再返回“已取得”。
2. 执行入口复核发现目标已达成时，零动作返回“目标已满足”，不报“已取得”。

### 2.5 结果状态一致

1. 进入动作之前的拒绝报“入口拒绝”；进入动作之后的中断报“动作结果未知 / 部分取得”，不得出现“已进入动作”而状态为“入口拒绝”。
2. 工程故障不得作为业务结果、业务值域或条件结果知识（AGENTS §1.1 第5项）。

### 2.6 一个本能内的两类修改

本能内同时修改内部记录与现实世界时，合同须分别写出两类修改；部分完成时按第2.5节报告实际阶段。

## 3. 各本能合同

各节为现行合同。合同与当前代码的差距不在本规范登记，见讨论稿差距分析（`讨论稿/5380_子规范_本能方法函数合同_讨论稿v0.1.md`）及相应施工计划；代码未达到本合同处按本合同施工。

### 3.1 进入场景（`builtin.self.enter_scene.v1`）

- 修改对象：内部世界树中自我的位置——自我“所在场景”特征值与场景成员关系（虚拟存在）。原因：目标要求自我处在某场景。目的：使自我所在场景为目标场景。不修改外设世界。
- 参数：1 自我｛所在场景｝；2 所在场景特征（所属1）；3 目标场景（通用存在）。
- 方法头：作用存在＝自我；可能结果＝所在场景。
- 执行分支（6220）：非空间进入、空间进入。

| 条件 | 分支 | 声明位置 |
| --- | --- | --- |
| 参数1属于自我概念 | 共用 | 初始必要条件 |
| 参数3可沿父场景链到达现实世界根 | 共用 | 运行时复核（暂无可声明的条件项） |
| 空间进入所需的坐标与边界条件 | 空间进入 | 执行分支必要条件（待6220细化） |

- 目标判定：自我当前已在参数3 → 目标已满足，不执行。
- 正常结果：自我“所在场景”＝参数3，世界树完成迁移。
- 业务结果值域：已取得；入口拒绝（条件不足、停止）；目标已满足。
- 工程故障：时间不可读、动作发布失败、写入或迁入失败、读回不符。

### 3.2 建立连接（`builtin.connection.establish.v4`，改为主动出站本能）

2026-11-10 用户裁决：
1. 保留建立连接，不再写交互者（同日早先裁决）。
2. 建立连接改为主动本能：交互者已打开窗口但没有消息发生时，自我主动发出一条打招呼的话；话语由建立连接调用自然语言相关函数生成，如“你好！”“嗨！”“请问有什么可以帮到你吗？”。

- 修改对象：
  1. 现实世界：经窗口向当前交互者说出一句打招呼的话（外设输出队列新增一条）。原因：交互者在窗口前但双方尚无消息往来。目的：引出对方回应，使双方开始互相收发。
  2. 内部记录：留档出站具体表达（语言场景），建立说话动作动态。
  不写“自我.交互者”，不迁移自我。
- 正常操作：组织打招呼的表达需求 → 表达组织知识 → 含义网 → 成文 → 建立动作 → 留档 → 入列；复用询问指定需求字段已有的出站时序（CONV-EXPR-STRUCT、CONV-EXPR-TEXT）。
- 参数：1 自我（自我范围概念）；2 窗口副本（通用存在｛外设场景标识｝）；3 外设场景标识特征（所属2）。受话者为自我当前交互者，作执行时材料读取，不设参数（第2.3节）。
- 方法头：作用存在＝通用存在；涉及特征类型＝外设场景标识；可能结果＝输出队列类型。
- 目标：与当前交互者已建立连接（双方已有往来）。目标判定：该窗口已收到当前交互者的消息 → 目标已满足，不执行（对方先开口时不需要打招呼）。
- 必要条件：

| 条件 | 声明位置 | 不满足时 |
| --- | --- | --- |
| 自我已取得交互者（参数1交互者值属于交互者类型值域） | 执行分支必要条件 | “有交互者”子需求，由获取交互者满足 |
| 参数2具备外设场景标识 | 初始必要条件 | 进入交互一类子需求 |
| 本次交互中尚未发出过招呼且未获回应（不重复打招呼） | 运行时复核（暂无可声明的条件项） | 任务等待对方回应 |
| 窗口副本对应现存外设窗口及输出队列 | 运行时复核（暂无可声明的条件项） | 零动作 |
| 打招呼所需语言知识齐备 | 运行时复核 | 零动作；后续语言学习子需求 |

- 先天被动结果：发出招呼后，等待对方消息出现；连接由对方回应后的场景信息判定达成，本函数不自证。对方消息到达时由场景信息唤醒等待中的任务（同 ASK-READ-SCENE 唤醒机制）。
- 话语选择：由表达组织知识按条件选取（如首次接触、再次接触），不随机、不把几种说法当作完全相同任选（“没有完全相同的存在”）。
- 业务结果值域：已入列；入口拒绝（窗口失效、缺知识、停止）；目标已满足；动作结果未知（已进入动作后留档或入列未完成）。
- 工程故障：投影身份不符、入列回执不全、留档读回不符。
- 依赖：
  1. 招呼按 7240 表达用途“招呼”（v2.6，R110）；带询问内容的说法按其内容为疑问。
  2. 表达组织知识需有招呼条目（施工时补入表达组织知识种子）。
  3. “请问有什么可以帮到你吗？”与补问方法族的“询问服务对象需求”“询问是否需要帮助”（CONV-INSTINCT §6.1，未实现）语义重叠，归属待裁决。
- 消费者：哪些目标以“已建立连接”为条件另行确定；获取服务对象新需求链路中，对方尚未开口时可经此引出对方说话。

### 3.3 获取交互者（`builtin.interactor.acquire.v1`）

- 修改对象：自我“交互者”特征值；必要时建立现实交互场景、窗口副本及交互对方的对应存在（内部世界模型）。原因：目标需要知道窗口前是谁。目的：自我“交互者”为窗口前的实际对象。外设世界只读。
- 参数：无（自我的交互者特征由函数按登记的自我读取）；或 1 自我｛交互者｝、2 交互者特征（所属1）。以施工时方法owner对零参数方法的支持为准。
- 方法头：作用存在＝自我；涉及特征类型＝交互者；可能结果＝交互者类型。
- 必要条件：外设世界中存在可交互的窗口——运行时复核（暂无可声明的条件项），列入第4节。
- 取值规则（2026-11-10 用户裁决）：
  1. 自我无法得知窗口前是谁、且会话已绑定登录人时，取登录绑定的人为交互者，不新建对应存在；
  2. 匿名会话时新建交互对方的对应存在；
  3. 有其它途径得知窗口前的实际对象时，按实际信息实时更新交互者；不改写已发生的陈述与已建需求（识别能力另行设计）。
- 目标判定：交互者已有当前值且与按上述规则应取的对象相同 → 目标已满足，不执行、不覆盖。
- 正常结果：自我“交互者”＝该对象；现实交互场景与窗口副本存在，该对象归入现实交互场景。
- 业务结果值域：已取得；入口拒绝（无可选窗口、停止）；目标已满足；动作结果未知（写入时前提变化）。
- 工程故障：对应存在等于自我、场景或副本建立失败、读回不符。

### 3.4 获取服务对象（`builtin.service_object.acquire.v4`）

- 修改对象：自我“服务对象”特征值（虚拟存在）。原因：服务链需要服务对象。目的：服务对象为当前交互者。
- 不修改概念（2026-11-10 用户裁决“移出本能，由概念自动维护”，AGENTS §1.5）：交互者归入“人类”上位概念、以实例共同特征完善“人类”，由概念owner依据“该存在属于人类”这一事实自动维护，不由本函数执行。
- 参数：1 自我｛交互者、服务对象｝；2 交互者特征（所属1）；3 服务对象特征（所属1）。
- 方法头：作用存在＝自我；可能结果＝服务对象类型。
- 必要条件：

| 条件 | 声明位置 | 不满足时 |
| --- | --- | --- |
| 参数2当前值属于交互者类型值域（有交互者） | 执行分支必要条件（已有） | 形成“有交互者”子需求，由获取交互者满足 |
| 交互者属于人类（只有人类能成为服务对象） | 执行分支必要条件，动作前按概念信息只读判定 | 不执行；无替代方法 |

- 正常结果：服务对象＝交互者。
- 业务结果值域：已取得；入口拒绝；动作结果未知。
- 工程故障：交互者等于自我、读回不符。
- 未决：“属于人类”的事实依据——“人类”概念为空时判定恒成立；已登录会话的绑定人为已知人类实例，匿名交互者的依据（观察识别、对方陈述等）另定（第6节）。

### 3.5 获取服务对象需求节点（`builtin.service_object.demand.acquire_node.v1`）

- 修改对象：服务对象“需求”特征当前引用被认知需求D（自我对对方需求的认知，虚拟存在）。原因：服务链要求服务对象有经确认的完整需求。目的：服务对象需求特征引用D。
- 不修改D的信息完善阶段（2026-11-10 用户裁决“移出由需求owner自动维护”）：完善阶段由需求owner在字段更新的同一次发布中按必需字段是否已全部确定自动维护（5170 §2.2）。
- 参数：1 人类｛对象需求类型｝；2 对象需求特征（所属1）；3 需求身份概念（D）。
- 方法头：作用存在＝人类；涉及特征类型＝对象需求类型；可能结果＝完整被认知需求概念。
- 必要条件（现行运行时核对的项应全部声明）：参数1属于人类（已声明）；参数2是参数1的特征；参数3为被认知需求、主体＝参数1；D来源为“旧理解确认”或“首次接收认知”；D信息完善阶段为已完善（各必需字段已有确定值，5170 §2.2，未完善时由补问链路补齐）；D内容确认为已确认（R106，未实现）。
- 正常结果：服务对象需求特征当前引用D。
- 业务结果值域：已取得；入口拒绝（材料待齐、需重新确认、前提已变化）；动作结果未知。
- 未决：“必要时为服务对象新建空需求特征”是否同样移出（服务对象的需求特征宜在服务对象成立时即具备）。

### 3.6 询问指定需求字段（`builtin.demand.field.ask.v1`）

依据 2026-11-10 用户裁决（CONV-INSTINCT §6.6、§6.7）。

- 修改对象：
  1. 现实世界：经窗口向对方说出一句询问（外设输出队列新增一条）。原因：补问需求Q的目标（D某字段有确定值）未满足，且只能由对方提供。目的：让对方说出该字段信息。
  2. 内部记录：留档出站具体表达（语言场景），建立说话动作动态。
- 本函数不关心问谁：只关心问什么（Q）和在哪说（窗口）；听的人由窗口所在交互决定；补问对象是自我当前交互者，不是“受询者”角色。
- 参数：1 补问需求Q（需求根概念）；2 自我（自我范围概念）；3 窗口副本（通用存在｛外设场景标识｝）；4 外设场景标识特征（所属3）。
- 方法头：作用存在＝通用存在；涉及特征类型＝外设场景标识；可能结果＝输出队列类型。
- 必要条件：

| 条件 | 声明位置 | 不满足时 |
| --- | --- | --- |
| 参数3具备外设场景标识 | 初始必要条件 | 进入交互、建立连接一类子需求 |
| 自我已取得交互者（参数2交互者值属于交互者类型值域） | 执行分支必要条件 | “有交互者”子需求 |
| 场景信息中尚无可取值陈述 | 执行分支必要条件（无法声明时在补问叶子方法选择中以同一读取判定实现） | 由“从场景信息取得需求字段值”承担 |
| Q引用D、路径为单个受支持字段 | 由补问叶子召回与参数1正式指定保证 | — |
| 窗口副本对应现存外设窗口及输出队列 | 运行时复核（暂无可声明的条件项） | 零动作 |
| 表达所需语言知识齐备 | 运行时复核 | 零动作；后续语言学习子需求 |

- 执行时材料：受话者＝参数2的交互者特征当前值；D主体是否等于受话者只决定成文用“你”还是第三方指代。
- 目标判定：D该字段已有值或不适用 → 目标已满足，不执行。
- 正常结果：已入列，附出站具体表达。Q不由本函数达成；先天被动结果表示“等待对方陈述”。
- 业务结果值域：已入列；入口拒绝（窗口失效、缺知识、缺名称、缺指称、多义、停止）；目标已满足；动作结果未知（已进入动作后留档或入列未完成）。
- 工程故障：投影身份不符、入列回执不全等。

### 3.7 从场景信息取得需求字段值（新，`builtin.demand_field.take_from_scene.v1` 拟）

依据 2026-11-10 用户裁决（不匹配问与答；收到信息转场景信息，自我读场景检查问题是否有答案）。

- 修改对象：被认知需求D的该字段（内部认知记录）。原因：Q目标未满足。目的：把对方已经说出的信息落为对D的认知。不修改场景信息与现实世界。
- 参数：1 补问需求Q；2 自我。
- 必要条件：存在可取值陈述——位于当前交互的语言场景；说话者为当前交互者；内容主体为D主体或待定；值属于被问字段值域；尚未被用作D任何字段的来源。
- 条件不足：不形成子需求，由询问方法承担。
- 执行入口复核：写入前重读该陈述与D该字段。
- 正常结果：经需求owner写入D该字段，内容来源记录指向该陈述。
- 业务结果值域：已取得；入口拒绝（复核不通过、需求owner拒绝）；目标已满足。多条陈述给出不同值时条件不成立（不取）。

### 3.8 网页对话三项（`builtin.web_dialog.read_messages/set_input_text/submit_message`）

已退役：无方法声明，生产代码无端口装配，普通应用按旧登记退役处理，永远返回“依赖未装配”。本规范不为其定义合同。代码清理：删除三个转发函数与登记名，或保留并在登记表注明退役；宿主异常返回“内部错误”而不工程终止的写法随之消失。

## 4. 跨本能缺口

1. **无法声明的条件**：外设世界事实（窗口存在、窗口对应外设对话框、外设有可选窗口）、语言知识齐备，目前没有可声明的条件项，只能运行时复核。需要设计一类“世界事实条件项”或等价机制。
2. **先天条件结果对**：上述本能大多没有条件结果对，召回与选择只能依赖方法头和隐含逻辑。建议每个本能登记时声明至少一条先天配对，写明本合同的正常结果（待裁决）。
3. **执行实例与任务状态核对**：服务对象族已核对方法节点、执行实例、任务状态，进入场景未核对；应作为所有本能的统一入口复核（宜并入5360）。
4. **目标判定位置**：各本能“目标已满足”的判定应统一在筹办阶段，入口复核只作兜底。

## 5. 与现行规范与设计的关系

2. CONV-INSTINCT 详细设计中已上升为本规范的内容（§4 出站本能统一形态中的合同部分、§6.6、§6.7 的合同部分）以本规范为准，详细设计只保留施工信息。
3. 已在规范目录登记，3300 §8 子规范路由已增加，0300 登记 R110。
