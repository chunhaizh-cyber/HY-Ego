# 8300 子规范 自我内部循环最小生命闭环验收

编号：8300
日期：20260903
版本：v1.4
状态：正式子规范

## 1. 定位

本规范规定自我觉醒根因果坐标启动后，内部循环从冷启动、需求层闭合到内部动作闭环和连续稳定的最低验收标准。

直接上级规范：8200、8210。

直接依赖规范：6100—6150。

相关边界规范：3100—3300。

## 2. 核心定义

自我没有外部输入时，不能用是否产生外部输入输出判断内部循环是否建立。验收链为：

```text
唯一自我正式形成并独立读回
-> 应用启动冷启动治理建立 / 收敛安全根与服务根角色
-> 同 Gform 完整读回本能根运行锚点并进入自我线程锁定请求
-> 同 G0 分别读取两个长期根 D、目标合同和当前值
-> 按需形成两个用后即弃的精确差值并分别裁决
-> 正差距或新到达合法父任务材料建立、唤醒或复用对应根需求治理任务；材料只触发 fresh 重判与裁决
-> self fresh 产生并确认独立必要目标，task owner 记录为正式子目标承接记录
-> 需求 owner 发布或复用具体子需求
-> 具体需求树、活动路径和当前主需求
-> 任务承接和筹办
-> 方法执行和实际回读
-> 任务本轮目标裁决
-> 任务轮次结算与轮次收束
-> 0..1 轮次级上级调用槽返回
-> 其它任务在实际使用时 fresh 独立核算
-> 自我后继决议
-> 下一轮状态与主需求重判
```

该链验收的是觉醒坐标启动后的内部循环，不得把自我节点、定义词条、根需求或方法首初始化解释为觉醒、苏醒或内部循环完成。

## 3. 三层验收

### 3.1 冷启动成立

至少能够读回唯一自我存在、自我内部世界、自我现实场景、安全和服务当前值及初始状态、根特征定义、目标合同、根需求入口、本能根运行锚点以及必要的先天方法登记。

安全根需求和服务根需求由 self 固有地产生并确认，必须在唯一自我正式读回后的应用启动冷启动治理阶段由需求 owner 发布或幂等收敛；两个固定角色各恰好绑定一个当前普通根 D。安全值与服务值首次当前值都必须等于 `I64_MAX / 2 = 4,611,686,018,427,387,903`，余数舍弃，并各有初始状态、零动态；两个目标合同分别绑定安全值与服务值且目标均为 `I64_MAX`。不得建立其它父空需求；任务根和方法根若按各自领域规范存在，也不是需求根或父空 D。重复冷启动不得产生新根，任一角色缺失、多义、只完成一侧、初值或目标不符、父关系非空、锚点未同截止完整读回都不合格。

冷启动只说明自我结构点火成功。

### 3.2 需求层闭合

自我能读取安全根和服务根的同截止当前值与目标合同，分别形成具名差距材料；正差距或新到达的合法父任务材料可以建立、唤醒或复用对应根治理任务，材料触发只授权 fresh 重判与裁决。self fresh 产生并确认目标独立、必要、父域合法且能由自身目标状态合同最终判定，并由 task owner 记录为正式任务子目标承接记录后，需求 owner 据此发布或复用双根子树中的普通子需求，随后形成活动 OR 路径和所属 AND 组、区分业务角色、选择当前主需求，并以正式结构投影当前治理状态。

管理和执行需求不能仅凭有无子节点判断。每条 OR 替代路径继承完整父权重；AND 只属于一个确定 OR，并在该 OR 内平分路径权重。

需求层闭合说明自我能感知自身不平衡，但还不证明任务和动作闭环。

### 3.3 内部动作闭环

当前主需求能由任务领域承接为唯一任务身份，任务在未收束轮次内能按状态多次筹办、逐步补全方法与条件信息，并由 manager 独立读回后推进；执行前选择能从可比较候选中冻结合法方法。内部治理与纯现实观察无需授权，现实改变在执行前取得一份自我授权；实际回读能验证任务本轮结果，任务轮次能结算并收束，唯一上级调用槽能收到返回，其它需求 / 任务能在实际使用时 fresh 独立核算，自我能据此决定继续、结束、等待或取消，下一轮判断受到上一轮结果影响。

达到本层才可称内部循环真正建立。

## 4. 十条硬标准

### 标准一：自我锚点稳定

唯一当前自我存在、自我内部世界和自我现实场景必须可读，且场景归属、治理虚拟存在和概念关系角色无冲突。

### 标准二：核心状态可读写

至少可读取生存安全根值、服务根当前值和分层安全值；生存安全根可由 6100 主动安全结算入口改变，分层安全值可由 6140 维护入口改变，服务根当前无新的自动写入入口。还须回读正式时间能力、安全低 / 高位阈值、6100 主动安全结算来源、6140 分层安全维护结果、6150 安全调度倍率与硬否决材料，以及 `A=0/1/>1` 生存控制态。

写入后必须按稳定身份、特征槽位、值、版本和关系完整读回。未设置和未知不得用满刻度值兜底。

### 标准三：根需求和需求树可生长

全部正式需求的身份和目标合同都必须持续存在；当前满足只改变本轮满足状态与活动治理，不删除、退出或永久退役需求，也不阻断对新到达合法材料的治理重判。安全根和服务根另须始终保留固定根角色绑定。正差距或新到达的合法父任务材料可以建立、唤醒或复用根治理任务；材料触发不等同正差距，不改变根值，也不直接创建需求。具体子需求必须由 self 产生并确认，再经该父任务的正式子目标承接记录发布。外部服务请求只能作为服务根治理任务的正式材料；无正式请求材料时不能证明已有服务对象、明确请求、目标或成功。

条件、方法能力和验证缺口必须形成父任务的具名任务材料；只有 self fresh 产生并确认独立必要目标、task owner 进一步记录为正式子目标承接记录后，需求 owner 才能发布或复用子需求。无候选方法不自动建立方法首。

同一父需求下发布前精确命中同目标需求时应复用既有 D，不能每轮重复创建；已发布需求身份不得合并、覆盖或删除，只能换代活动关系或治理状态。安全根与服务根下同目标的具体需求保留两个独立 D；同属唯一自我时可以进入同一 L，并由同一 T 逐次建立显式 T→D。

### 标准四：主需求选择有依据

安全和服务缺口必须按当前根状态、目标和因果路径分别比较。`A=0` 只保留正式恢复 / 重建与停止控制入口；`A=1` 只保留具名治理材料接收与正式承接、正式时间事实更新、安全事实接收、重新评估和停止控制入口；`A>1` 时普通任务才可进入派发门控。入口不按来源存在的人类分类开放。根治理任务只形成任务材料；子目标必须经 self fresh 产生并确认后由 task owner 记录承接。服务子需求的后继任务仍经普通需求、任务、方法和正式结果链以及同一控制态、安全倍率与硬否决门控。倍率不得成为任务承接、筹办权、方法冻结或正向授权前置。

### 标准五：需求可以任务化

当前可承接具体需求 D 必须能由自我线程作为承接输入发送；任务管理读取 D 所属列表项 L，以 L 查询 0..1 个当前任务，无任务时原子建立 T、`T→L`、`T→D` 和任务虚拟存在，有任务时同目标复核后幂等新增 `T→D`。自我线程不能直接创建或写任务，不能只发送列表项或通用授权包。

### 标准六：任务具有语义身份

任务必须能回读唯一查询锚点、1..N 条当前 `T→D` 关系、具体需求互证出的单目标投影、任务虚拟存在、状态特征集合、活动路径、权重预算和当前性。列表全部成员不得自动成为来源；全部关联 D 失活时必须等待、结束或重判，不能以 L 聚合键兜底。不能只依赖任务阶段枚举、名称或线程工作项。

### 标准七：方法和动作可执行

可执行原子任务必须证明任务管理按状态多次派发筹办：完整找方法后才查条件，全部候选条件核验后才进入执行前选择。执行前 fresh 复核可用性并选择综合代价最小的方法后才能冻结；无方法和条件不具备分别进入具名处理，技术失败不得冒充业务缺失。

### 标准八：执行结果能回写

动作后实际回读必须经验证进入自我内部世界、核心特征、任务结果、需求证据或结算事实。预测和执行报告不能替代实际回读。

### 标准九：需求能复核和结算

正式任务实际结果形成后，每个已开始执行轮次必须在验证 / 归因和停止材料闭合时恰好形成一个任务轮次结算并收束本任务轮次；重复结果只幂等读回首次结算，不得等待结果分配或全部 `T→D`。验收必须证明：根任务轮次没有发起调用时可收口；有唯一发起调用时只返回并结算对应上级调用槽；多个调用时引用冲突。上级和其它需求 / 任务必须在实际使用时 fresh 读取自己的目标与任务状态，需要继续时重新经过筹办补齐方法 / 条件，达到待执行前选择后才可执行；材料不足结构化停止。价值预算、已入账份额及防重复领取必须另从 4320 的价值结算事实读回。

普通服务请求必须先成为服务根治理任务材料，由 self 产生并确认服务需求目标、task owner 记录为正式子目标承接记录后，再由需求 owner 发布或复用服务子需求，并经后继任务、方法和正式结果闭合。服务对象外在状态改善只有经实际回读、验证和归因，并形成相应状态 / 动态 / 因果证据后，才可作为对应特征 owner 的当前值裁决材料；不得另建专用账务或把方法成功当作服务结果成立。

### 标准十：下一轮受上一轮影响

任务轮次结算后必须先进入`轮次已收束`，由自我形成继续、结束、等待或取消后继决议。只有继续决议才能建立新任务轮次并重新筹办；本轮目标未达成不得自动生成下一筹办工作包。上一轮事实必须改变下一轮状态、缺口、路径、权重、任务或待机判断。若每轮仅重复调用、重复建任务或输出相同日志，不构成循环。

## 5. 完成等级

| 等级 | 名称 | 最低标准 |
| --- | --- | --- |
| 0 | 未初始化 | 自我锚点或内部世界缺失 |
| 1 | 冷启动完成 | 自我锚点、核心状态和根需求入口可读 |
| 2 | 需求层闭合 | 能由自身状态生长需求并选择主需求 |
| 3 | 任务化可用 | 主需求能形成或复用任务 |
| 4 | 筹办和方法可用 | 多次筹办能按状态补全方法与条件信息，原子任务能在执行前选择后冻结方法 |
| 5 | 实际结果回写可用 | 方法执行有实际回读并提交事实 |
| 6 | 需求复核和轮次结算可用 | 任务结果能逐需求独立核算、形成任务轮次结算并等待自我后继决议 |
| 7 | 连续多轮稳定 | 无重复任务风暴、无限派生、空转和主链断裂 |

内部循环真正建立至少达到 6 级；工程验收达到 7 级。

## 6. 最小验收剧本

初始状态由正式抽象根特征定义、自我特征实例和下中点当前值构成：`A0 = V0 = I64_MAX / 2`，非负整数除法余数舍弃；首次赋值只有当前值与初始状态，没有动态。根目标合同均为 `当前值 == I64_MAX`。第一轮自检在同一 G0 读取当前值后按概念公式即时计算 `Δsafe`、`Δservice`，使用后丢弃，不验收任何持久差值实例、状态或动态。

第一轮根特征自检发现具名服务缺口，服务路径按权重参与主需求选择。存在直接服务触发事实时，也必须先建立或复用服务根治理任务，由 self 产生并确认服务目标、task owner 记录为正式子目标承接记录，再由需求 owner 发布或复用服务子需求；不存在时不得补造服务对象或请求。不得直接选择“提升服务值”通用动作。

第一轮任务形成正式实际结果后，完成本轮验证 / 归因、停止收口和唯一任务轮次结算并进入轮次已收束；若存在唯一发起调用，则完成返回和调用槽幂等结算。第二轮或其它任务实际使用该状态时先 fresh 读取当前目标与任务状态；需要继续时必须重新经过任务筹办补齐方法 / 条件并到达待执行前选择。只有自我下达继续决议时才为同一任务建立新任务轮次并从筹办开始，不重复创建未结束任务，也不自动复用旧冻结或旧授权。

后续轮次只有在服务子需求的正式结果被实际回读、验证并可归因后，才形成服务对象状态 / 动态 / 因果证据，并由对应特征 owner 按现行规则裁决当前值；缺口降低后可切换主需求。`A=0` 为终止态，`A=1` 为休眠态，`A>1` 为主动运行态；具名请求和服务事实在 `A=1` 时只进入正式材料承接并触发重新评估，不得直接创建 D 或写入主动运行态，`A>1` 正式读回前不得派发普通任务。

## 7. 不合格情况

只有初始化、只有根需求、只有需求没有任务、只有任务没有方法、只有执行没有实际回读、只有回写没有需求复核和结算、或上一轮不影响下一轮，都不构成内部循环完成。

## 8. 验证边界

验收必须提供每轮输入状态、需求、任务、每次筹办的任务信息版本 / 覆盖范围 / 结果消息、manager 独立读回与状态迁移、执行前选择、方法作用范围、适用时的唯一自我现实执行授权、安全硬否决、实际回读、任务轮次结算、轮次收束和自我后继决议证据。旧五类筹办结果和技术失败驱动业务迁移的生产调用必须为零。

## 9. 当前值权威专项验收

验收必须证明：

1. 根需求比较读取特征实例唯一当前属性槽和值事实，不读取状态 / 动态代替。
2. 动态触发后重新冻结 G0 并正式读取当前值；直接使用动态后状态判定不合格。
3. 当前值真实变化同步形成状态 / 动态；首次赋值无动态、无变化无新记录、失败无部分发布。
4. 历史补录或最后写入动态不改变当前值。
5. 复合目标读取同截止当前值集合，值式状态投影可重建且不持久化为第二权威。
