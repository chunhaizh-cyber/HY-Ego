# 8300 子规范 自我内部循环最小生命闭环验收

编号：8300
日期：20261004
版本：v2.0
状态：正式子规范

直接上级规范：8000、8200、8210。

直接依赖规范：3100—3300、5090、5170、5260、6100—6150。

相关边界规范：8100、8310、8320。

## 1. 定位

本规范规定新版内部治理从初始化、需求、任务、方法执行、结果获取、影响评估、self决议到任务完成结算的最低验收标准。

验收只接受新版current-only模型：一个任务一个需求、无任务/筹办/执行轮次、每次真实方法调用一个执行实例。旧多需求任务、初始化包、事实截止、历史重建、调用槽和旧任务版本入口不得作为验收要求或兼容成功依据。

## 2. 最小闭环

```text
初始化世界树、自我、双根和方法根
-> self fresh复核一个需求D
-> 建立/复用唯一任务T和Vt
-> 查找方法、核验条件并绑定结果获取方案
-> self执行前判断
-> 建立X并执行一次W3-A
-> W3-B取得正式结果
-> 结束X并形成A
-> self fresh决定任务后继
-> manager复核并发布状态
-> 正式完成时按T结算一次
```

任何中间函数可调用、编译通过或消息成功都不能替代这条业务闭环。

## 3. 初始化验收

必须读回：

- 唯一基础数据集；
- 世界树根场景；
- 自我所在场景和自我节点；
- 需求树、安全根和服务根；
- 方法根及至少一个正式登记的方法函数；
- self、manager、worker的运行配置和可停止状态。

任一必需结构缺失时保持停门。不得用线程创建、邮箱为空或默认零值宣称初始化成功。

## 4. 需求验收

必须证明：

- 双根目标为`INT64_MAX`并分别fresh读取当前值；
- 普通D只由self产生确认后经需求类建立或复用；
- 一个D表达一个可复合状态改变；
- 子需求形成需求树，权重在非失活直接子需求间平分；
- 每次满足判断读取当前特征值，不用状态后态、任务结果或历史满足结论；
- 双根正常分支只含已满足或需增加，需减少为结构/绑定错误；
- 需求列表只作查询投影，不作为任务承接目标。

## 5. 任务验收

必须证明：

- 一个D最多对应一个T，一个T恰好引用一个D；
- T具有唯一Vt和唯一当前任务状态特征；
- 状态迁移只经任务类公开入口；
- 多次找方法和查条件不建立筹办轮次；
- 每次真实方法调用建立一个X，不建立执行轮次；
- X结束后形成0..1个A；
- 已完成、已失败、已取消的T只能经self fresh确认和manager复核重新启用，且不能直接进入执行；
- 重新启用不撤销或重复既有完成结算。

## 6. 方法和执行前验收

必须至少登记一个可实际调用的方法，证明：

- 方法具有完整条件、参数、预计变化和结果确认要求；
- 任务根据自我当前感知能力绑定具体结果获取方案；
- 无方案时普通、探索和试验任务均零动作；
- self在动作前读取需求、资源、安全和冻结材料，形成执行/暂缓/拒绝/重判；
- 含现实改变时取得必要现实执行授权，内部固定治理和纯观察不伪造授权。

## 7. W3与实际结果验收

W3-A必须证明同一X最多调用一次动作。动作明确未发出、已发出、可能已发出分账；后两者发生消息丢失、超时或记录失败时不得重做。

W3-B必须覆盖：

- 即时结果；
- 延迟结果并释放worker；
- 异地或条件到达后的继续获取；
- 正式状态通知先到后登记等待时的主动补查；
- 多渠道任一/共同/优先/备用/冲突；
- 渠道失效后结果未知而不重做动作；
- 作用对象和精确实例特征身份核验；
- 请求材料与fresh读回材料一致。

## 8. 影响评估和self决议验收

A至少应覆盖预计命中、预计缺失、计划外变化、方向、幅度/值域、不可比较、多渠道冲突、禁止结果/副作用、归因和D当前满足材料。

未实现方向、幅度或值域算法时必须标记未验证，不能用对象/类型命中代替。

manager形成A后只把T、X、A和结果定位回流self。self fresh读回后形成完成、继续、重试、重新筹办、等待、失败或取消；manager复核后由任务类发布状态。必须证明manager、worker和A都不能绕过self决定后继。

## 9. 结算验收

必须证明：

- 只有正式`已完成`T可以完成结算；
- 同一T最多成功结算一次；
- manager在self确认结算前保留X、A和运行定位；
- 完成通知丢失后可以从current-only任务状态重新发现；
- 已有结算时按正式结算终结重复消息；
- 失败或取消没有完成结算；
- 任务结算不等于需求结算、安全值变化、服务值变化或方法学习。

## 10. 消息、容量、停止和恢复验收

消息按类型进入不同处理函数，接收回执和处理终结分开。活动消息容量覆盖待处理、处理中、延后和等待依赖，同一消息只计一次。

必须覆盖同义重复、异义冲突、乱序、队满、依赖未就绪、依赖未实现、发布未知和内部不一致。

停止验收包括等待可唤醒、同步调用返回前不销毁依赖、不detach、自身不join、重复join安全，以及停止时继续收口已发生动作和完成结算。

跨进程恢复尚未实现时必须明确标记未实现；不得用运行代次、事实截止或历史材料伪造恢复通过。

## 11. 证据与声明边界

验收记录必须列出：精确提交、装配入口、输入、结构化结果、最终current-only状态、独立读回、失败分支和未覆盖范围。

分层声明：

- 静态审查只证明规范/代码形状；
- 编译只证明目标配置可编译；
- 隔离桩只证明线程控制或分支；
- 真实运行才证明具体方法、网页端口和观察渠道接通；
- 跨进程恢复和组合方法必须另行验收。
