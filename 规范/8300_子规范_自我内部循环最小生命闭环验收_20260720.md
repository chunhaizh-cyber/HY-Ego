# 8300 子规范 自我内部循环最小生命闭环验收

编号：8300
日期：20260828
版本：v1.0
状态：正式子规范

## 1. 定位

本规范规定自我觉醒根因果坐标启动后，内部循环从冷启动、需求层闭合到内部动作闭环和连续稳定的最低验收标准。

直接上级规范：8200、8210。

直接依赖规范：6100—6130。

相关边界规范：3100—3300。

## 2. 核心定义

自我没有外部输入时，不能用是否产生外部输入输出判断内部循环是否建立。验收链为：

```text
唯一自我正式形成并独立读回
-> 应用启动冷启动治理建立 / 收敛安全根与服务根角色
-> 同 Gform 完整读回本能根运行锚点并进入自我线程锁定请求
-> 同 G0 分别读取两个长期根 D、目标合同和当前值
-> 按需形成两个用后即弃的精确差值并分别裁决
-> 仅正差距经内建治理方法展开具体需求
-> 具体需求树、活动路径和当前主需求
-> 任务承接和筹办
-> 方法执行和实际回读
-> 任务本轮目标裁决
-> 任务轮次结算与轮次收束
-> 0..1 轮次级上级调用槽返回
-> 其它任务在实际使用时 fresh 独立核算
-> 自我后继决议
-> 下一轮状态与主需求重判
```

该链验收的是觉醒坐标启动后的内部循环，不得把自我节点、定义词条、根需求或方法首初始化解释为觉醒、苏醒或内部循环完成。

## 3. 三层验收

### 3.1 冷启动成立

至少能够读回唯一自我存在、自我内部世界、自我现实场景、安全和服务当前值及初始状态、根特征定义、目标合同、根需求入口、本能根运行锚点以及必要的先天方法登记。

安全根需求和服务根需求必须在唯一自我正式读回后的应用启动冷启动治理阶段建立或幂等收敛；两个固定角色各恰好绑定一个当前普通根 D。安全值与服务值首次当前值都必须等于 `I64_MAX / 2 = 4,611,686,018,427,387,903`，余数舍弃，并各有初始状态、零动态；两个目标合同分别绑定安全值与服务值且目标均为 `I64_MAX`。其它一般需求根、任务根和方法根仍可按需建立。重复冷启动不得产生新根，任一角色缺失、多义、只完成一侧、初值或目标不符、父关系非空、锚点未同截止完整读回都不合格。

冷启动只说明自我结构点火成功。

### 3.2 需求层闭合

自我能读取安全、服务和其它根状态，计算具名缺口，生成或复用需求，形成活动 OR 路径和所属 AND 组，区分业务角色，选择当前主需求，并以正式结构投影当前治理状态。

管理和执行需求不能仅凭有无子节点判断。每条 OR 替代路径继承完整父权重；AND 只属于一个确定 OR，并在该 OR 内平分路径权重。

需求层闭合说明自我能感知自身不平衡，但还不证明任务和动作闭环。

### 3.3 内部动作闭环

当前主需求能由任务领域承接为唯一任务身份，任务在未收束轮次内能重复筹办并形成闭合结果，可执行原子任务能冻结合法方法；内部治理与纯现实观察无需授权，现实改变在执行前取得一份自我授权；实际回读能验证任务本轮结果，任务轮次能结算并收束，唯一上级调用槽能收到返回，其它需求 / 任务能在实际使用时 fresh 独立核算，自我能据此决定继续、结束、等待或取消，下一轮判断受到上一轮结果影响。

达到本层才可称内部循环真正建立。

## 4. 十条硬标准

### 标准一：自我锚点稳定

唯一当前自我存在、自我内部世界和自我现实场景必须可读，且场景归属、治理虚拟存在和概念关系角色无冲突。

### 标准二：核心状态可读写

至少可读取并由合法领域入口改变生存安全根值、服务值和分层安全值，回读安全低 / 高位阈值、服务合同、完整秒时间纪元、服务衰减段、到期未满足事件、任务调度倍率来源、待机与休眠控制态。

写入后必须按稳定身份、特征槽位、值、版本和关系完整读回。未设置和未知不得用满刻度值兜底。

### 标准三：根需求和需求树可生长

安全和服务根需求必须长期存在；当前满足只关闭本轮差距展开，不永久退役根。只有根需求的正差距可以经内建治理方法形成具体需求候选。直接服务子需求只有在直接服务触发事实和因果链上下文缺口通过准入后形成；无直接触发时只能形成监听触发、检查机会或校准能力等间接维护需求，不能证明已有服务对象、合同、目标或成功。

条件、方法能力和验证缺口必须形成具名需求材料并由统一入口承接。无候选方法不自动建立方法首。

同一父需求下的同目标需求应复用、合并或更新当前性，不能每轮重复创建。安全根与服务根下同目标的具体需求保留两个独立 D；同属唯一自我时可以进入同一 L，并由同一 T 逐次建立显式 T→D。

### 标准四：主需求选择有依据

安全和服务缺口必须按当前根状态、目标和因果路径比较。`A=0/1` 时只保留各控制态具名最小入口；`A>1 且 A<=L` 时服务任务根调度配额为零，`A>L` 后才按 6170 释放服务调度配额，安全任务继续消费 6150 的分层调度倍率。配额 / 倍率只在执行冻结后、真实派发前形成正常调度资格与优先级；不得成为任务承接、筹办权、方法冻结或正向授权前置，全局控制态独立门控。

### 标准五：需求可以任务化

当前可承接具体需求 D 必须能由自我线程作为承接输入发送；任务管理读取 D 所属列表项 L，以 L 查询 0..1 个当前任务，无任务时原子建立 T、`T→L`、`T→D` 和任务虚拟存在，有任务时同目标复核后幂等新增 `T→D`。自我线程不能直接创建或写任务，不能只发送列表项或通用授权包。

### 标准六：任务具有语义身份

任务必须能回读唯一查询锚点、1..N 条当前 `T→D` 关系、具体需求互证出的单目标投影、任务虚拟存在、状态特征集合、活动路径、权重预算和当前性。列表全部成员不得自动成为来源；全部关联 D 失活时必须等待、结束或重判，不能以 L 聚合键兜底。不能只依赖任务阶段枚举、名称或线程工作项。

### 标准七：方法和动作可执行

可执行原子任务至少能召回并冻结一个结构完整、条件满足、动作入口当前的方法，并逐动作声明作用范围与现实副作用。无候选、条件不足或方法结构缺口必须分别按学习需求承接、方法补齐承接或合法等待收口，不能用通用“提升值”动作兜底。冻结后还必须验证调度投影、独立控制态和安全硬否决；内部治理及无现实副作用的纯观察不得索要业务授权，含现实改变步骤时必须在任务进入执行阶段前独立读回一份绑定任务、三轮次、冻结、实例方法和动作范围的自我现实执行授权。安全服务、任务和方法不得另发正向授权。

### 标准八：执行结果能回写

动作后实际回读必须经验证进入自我内部世界、核心特征、任务结果、需求证据或结算事实。预测和执行报告不能替代实际回读。

### 标准九：需求能复核和结算

正式任务实际结果形成后，必须在验证 / 归因和停止材料闭合时收束本任务轮次，不得等待结果分配或全部 `T→D`。验收必须证明：根任务轮次没有发起调用时可收口；有唯一发起调用时只返回并结算对应上级调用槽；多个调用时引用冲突。上级和其它需求 / 任务必须在实际使用时 fresh 读取自己的目标与当前事实，已满足零动作、未满足继续自身执行、材料不足结构化停止。价值预算、已入账份额及防重复领取必须另从 4320 的价值结算事实读回。

服务对象外在状态改善只有经实际验证和归因后，才能支付服务合同完工余款；合同成立预支、准备补回和主动安全结算必须分账。

### 标准十：下一轮受上一轮影响

任务轮次结算后必须先进入`轮次已收束`，由自我形成继续、结束、等待或取消后继决议。只有继续决议才能建立新任务轮次并重新筹办；本轮目标未达成不得自动生成下一筹办工作包。上一轮事实必须改变下一轮状态、缺口、路径、权重、任务或待机判断。若每轮仅重复调用、重复建任务或输出相同日志，不构成循环。

## 5. 完成等级

| 等级 | 名称 | 最低标准 |
| --- | --- | --- |
| 0 | 未初始化 | 自我锚点或内部世界缺失 |
| 1 | 冷启动完成 | 自我锚点、核心状态和根需求入口可读 |
| 2 | 需求层闭合 | 能由自身状态生长需求并选择主需求 |
| 3 | 任务化可用 | 主需求能形成或复用任务 |
| 4 | 筹办和方法可用 | 筹办能闭合且原子任务能冻结方法 |
| 5 | 实际结果回写可用 | 方法执行有实际回读并提交事实 |
| 6 | 需求复核和轮次结算可用 | 任务结果能逐需求独立核算、形成任务轮次结算并等待自我后继决议 |
| 7 | 连续多轮稳定 | 无重复任务风暴、无限派生、空转和主链断裂 |

内部循环真正建立至少达到 6 级；工程验收达到 7 级。

## 6. 最小验收剧本

初始状态由正式抽象根特征定义、自我特征实例和下中点当前值构成：`A0 = V0 = I64_MAX / 2`，非负整数除法余数舍弃；首次赋值只有当前值与初始状态，没有动态。根目标合同均为 `当前值 == I64_MAX`。第一轮自检在同一 G0 读取当前值后按概念公式即时计算 `Δsafe`、`Δservice`，使用后丢弃，不验收任何持久差值实例、状态或动态。

第一轮根特征自检发现具名服务缺口，服务路径按权重参与主需求选择。存在直接服务触发事实时，只有通过上下文缺口准入才生成直接服务子需求；不存在时只允许间接维护需求。不得直接选择“提升服务值”通用动作。

第一轮任务形成正式实际结果后，完成本轮验证 / 归因、停止收口和任务轮次结算并进入轮次已收束；若存在唯一发起调用，则完成返回和调用槽幂等结算。第二轮或其它任务实际使用该状态时先 fresh 读取当前目标 / 条件；只有自我下达继续决议时才为同一任务建立新任务轮次并从筹办开始，不重复创建未结束任务，也不自动复用旧冻结或旧授权。

后续轮次只有在服务对象外在状态改善被实际验证并可归因后才支付合同完工余款；缺口降低后可切换主需求。服务值为零时，生存安全根值在没有同秒主动安全变化的完整秒收敛到 1 并进入可唤醒休眠；休眠期普通任务根调度配额全零。有效人类需求建立唯一合同、30% 预支发布且后续完整秒安全门禁通过后才形成主动运行唤醒候选；`A>1` 发布前不得派发普通任务。真实有效进展的服务活动在时间衰减中最低保护服务值 1。

## 7. 不合格情况

只有初始化、只有根需求、只有需求没有任务、只有任务没有方法、只有执行没有实际回读、只有回写没有需求复核和结算、或上一轮不影响下一轮，都不构成内部循环完成。

## 8. 验证边界

验收必须提供每轮输入状态、需求、任务、筹办闭合结果、方法作用范围、适用时的唯一自我现实执行授权、安全硬否决、实际回读、任务轮次结算、轮次收束、0..1 发起调用、返回 / 调用槽结算、其它任务按需 fresh 核算、自我后继决议和下一轮变化的结构证据。旧结果容量、共用 / 争用、成员优先级和消费分配生产调用必须为零。日志和控制面板只作人读互证。

## 9. 当前值权威专项验收

验收必须证明：

1. 根需求比较读取特征实例唯一当前属性槽和值事实，不读取状态 / 动态代替。
2. 动态触发后重新冻结 G0 并正式读取当前值；直接使用动态后状态判定不合格。
3. 当前值真实变化同步形成状态 / 动态；首次赋值无动态、无变化无新记录、失败无部分发布。
4. 历史补录或最后写入动态不改变当前值。
5. 复合目标读取同截止当前值集合，值式状态投影可重建且不持久化为第二权威。
