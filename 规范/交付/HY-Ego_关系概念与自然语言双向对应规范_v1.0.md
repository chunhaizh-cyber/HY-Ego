## 3. 模型职责与边界

### 3.1 四层不得串用

系统必须区分并分别核验：

1. **实现边/字段**：L1 或领域物理承载（父指针、字段值、容器成员等）。
2. **关系概念**：对上述承载的可复用组织形状抽象与表达绑定。
3. **一次具体事实**：某次读回确认的边/字段成立实例。
4. **语言层**：构式、词条、语序、形态、标点、含义网与场景材料。

不得把图中任意节点当作 world existence；不得把字段引用连接叙述成父子边；不得把关系概念登记当作一次事实已写入。

### 3.2 所有权

1. 边/字段的定义、合法性、读写与生命周期：**必须**由既有领域 owner 裁决（如存在组成归存在 owner，需求父子/目标存在归需求 owner）。
2. 关系概念登记：挂在自然语言组织根下、与概念名称关系根并列；**不得**建立第五世界根。
3. 语言知识、含义网、自然语言场景材料：归语言 owner；**不得**由解析器或关系陈述服务直接写入被认知需求或业务事实。
4. 任务选择哪个本能方法满足需求：归任务管理；应用入口**不得**写死唯一新方法而废弃既有可满足方法。

### 3.3 与二次关系概念（4241/4242）的边界

1. `4241`/`4242` 规定 RC 的定义结构、规范化、求值与发布；其「关系」指比较条件语义，不是世界组织形状。
2. 本规范的关系概念**不得**复用 RC 的规范键、域掩码、FC/EC/K 合同冒充组织边抽象。
3. 文档、代码注释与验收条目提到「关系概念」时，**必须**可判定所指为世界树关系概念或 RC；混称视为条款冲突（见附录 B）。

### 3.4 数据驱动与代码边界

1. 成句与理解的差异**必须**主要由关系定义与表达知识提供；**不得**为每一「关系种子×语言」增加专用成句/解析分支函数。
2. 「数据驱动」**不得**解释为「新领域操作永不需要代码」。领域提供者可以、且在必要时**应**以有限枚举类型与公开读取能力扩展；新增不可由现有 owner API 表达的连接种类时，**必须**先扩展领域读取合同，再登记关系概念。

## 4. 逻辑数据合同

> 本节为规范抽象。实现可用等价 C++ 结构承载；**不得**仅因当前头文件字段名不同而否定本抽象。下列「当前实现对照」仅说明符合性，不把实现细节升格为唯一合法物理布局。

### 4.1 关系概念定义（抽象）

关系概念定义**必须**包含：

| 抽象字段 | 约束 |
| --- | --- |
| 稳定种子键 | 非空；同键同义必须复用身份 |
| 端点组 | 至少两个端点；每端有角色键与对象种类 |
| 主连接 | 恰一个：外部边 **或** 字段引用 |
| 附加连接组 | 可为空；各项同主连接种类约束 |
| 名称组 | 每目标语言至多一套有效预置/采用名称关联（词条引用，不在定义上存裸词面权威） |
| 表达关联组 | 按目标语言；可含单段快捷或陈述段组 |

外部边连接**必须**能指明：owner 标识、边类型、角色或顺序、源角色键、目标角色键。  
字段引用连接**必须**能指明：owner 标识、字段键名、宿主角色键、目标角色键。

### 4.2 表达关联与槽（抽象）

1. 表达槽**必须**把端点角色绑定到语言含义参数，并声明取材投影。
2. 陈述段组非空时，成句内容**必须**按段组合；附加连接**不得**冒充陈述段。
3. 预置知识尾词与后天表达知识节点可以共存；后天覆盖规则见第 5、6 节。

### 4.3 入站材料（抽象）

入站材料**必须**可回读：自然语言场景、可选交互场景、关系种子键、固定原文、各角色的所指存在/场景实例/来源概念/未确定标志、所用知识节点组。  
状态**必须**如实区分：角色实例是否齐备、是否未确定；**不得**用缺省填充伪装齐全。

### 4.4 当前实现对照（非唯一物理合同）

对照 tip `f5917680` / `d070696f` 源码（固定 SHA 见附录 C）：

## 5. 初始化与版本演进

### 5.1 静态表初始化

1. 系统初始化**必须**能依据静态种子表建立关系概念信息及其预置表达关联。
2. 建立**必须**幂等：同稳定种子键再次初始化**必须**复用已有身份，不得产生第二活跃同义登记。
3. 初始化成功**必须**以正式读回证明（种子键、端点、连接、表达关联可逐项核对）；不得仅以日志关键字宣称成功。
4. 初始化路径**不得**调用「追加表达知识」去覆盖已有后天关联。

### 5.2 先天与后天分层

1. **先天种子**：随初始化材料发布的关系结构与预置表达；重启后仍可重建/复用同一稳定种子键。
2. **后天学得/纠正表达**：仅追加或修订**语言表达知识关联**；**不得**在重启初始化时静默覆盖后天表达。
3. 缺目标语言表达知识时，出站**必须**返回可区分的「缺语言知识」类失败；**不得**静默回退到另一语言或另一关系的成句。

### 5.3 演进区分

| 变更种类 | 允许条件 | 禁止 |
| --- | --- | --- |
| 结构变更 | 端点种类、连接种类/方向/字段、附加连接语义变化；须新种子或显式结构修订合同 | 用改对象显示名或改尾词假装新结构 |
| 表达变更 | 同结构下更换/追加知识尾词、陈述段、槽参数映射 | 用表达变更偷换领域边/字段含义 |
| 实例变更 | 具体存在/需求节点上的边或字段事实变化 | 把实例变化写成关系概念定义变化 |

纯数据扩展（同族结构、仅表达知识差异）可以用于验证统一转换；验收**必须**标明验证力度为「表达知识组合扩展」，**不得**宣称新领域结构类型已实现。

## 6. 修改时机准则

### 6.1 何时修改关系概念结构

仅当下列之一成立时，**应**修订关系概念结构（或新增种子）：

1. 领域 owner 已提供新的可公开读取的边/字段合同，且既有种子无法无损表达；或
2. 端点对象种类或角色集合变化导致旧定义读回无法表示同一组织形状。

结构修订**必须**保持稳定种子键策略明确（原地修订并查重，或新键并退役旧键）；**不得**留下两个活跃同义结构。

### 6.2 何时只改语言知识与实例

1. 仅需换词、换语序、换尾词、换陈述段组合、换目标语言表达时：**必须**只改表达关联/语言知识，不改连接与端点种类。
2. 仅世界中具体对象关系变化时：**必须**只改领域实例事实；关系概念定义保持不变。

### 6.3 何时不得改

1. 不得因某一出站用例失败，在应用入口写死新方法或专用成句分支代替补齐表达知识。
2. 不得因入站歧义，自动创建业务实例或任取同名对象「凑成功」。
3. 不得把本规范整理授权解释为批准附录待裁定项。

## 7. 出站合同

### 7.1 目标流水线

出站**必须**按下列顺序，不得跳步冒充成功：

```text
真实需求 / 本能表达意图
  → 正式领域材料读取（经 owner 公开入口）
  → 关系概念结构匹配与角色绑定
  → 目标语言表达知识选择
  → 含义/组织（与 7232/7240 表达组织分工）
  → 生成文本并满足原输出合同（含唯一回读要求）
```

### 7.2 关系概念不是语言语法

1. 关系概念提供组织形状与槽投影；词条、构式、语序、形态、标点由语言知识与 `7270` 结构概念承担。
2. 表达组织知识（`7232`）负责「正式表达需求 → 具体含义网」；关系陈述服务负责「关系绑定 + 表达关联 → 可回读单句/段组合」。二者**应**分工，不得互相吞并职责后丢失角色或作用域。

### 7.3 正式表达需求

1. 出站输入是任务链执行的本能所形成的正式表达需求（结构化目标），不是标准句模板。
2. 现行字段询问路径中，表达需求为调用内局部 DTO，**不得**仅因名称相似建立需求树正式 D（对齐 `7240` §3.3 与代码事实）。
3. 同一需求可有多个可满足本能方法时，**必须**由任务管理选择；应用**不得**在入口写死只调用新方法。

### 7.4 出站状态与错误（可验收）

实现对外状态可以命名不同，但**必须**能区分至少下列语义；不得合并为单一「失败」以致无法验收：

| 语义 | 要求 |
| --- | --- |
| 已生成且唯一回读 | 文本非空；结构回读与角色/方向/对象身份一致 |
| 缺关系概念 | 种子键无登记或不可读 |
| 端点不合法 | 绑定缺失、种类不符、或领域读取拒绝将该节点视为该种类端点 |
| 关系不成立 / 方向或角色错误 | 主连接或附加连接核验未通过；方向相反须可区分 |
| 缺语言知识 | 目标语言无表达关联；不得暗退 |
| 缺名称 | 所需显示名/词条不可读 |
| 范围未支持 | 连接种类或投影尚未接线 |
| 输入拒绝 | 请求形状不合法 |

生成成功**不等于**已入列、**不等于**对方已读、**不等于**业务字段已写回。

## 8. 入站合同

### 8.1 目标流水线

```text
自然语言材料
  → 解析（复用统一解释/含义图能力，不按种子键专用解析函数）
  → 写入自然语言场景供材料（关系陈述入站材料）
  → 自我结合已有交互场景消歧，并决定如何写入内部交互场景
  → （另步）业务采纳：仅经正式领域/任务合同，不得由解析器直接完成
```

### 8.2 硬性禁止

1. 解析器**不得**直接采纳业务事实、**不得**直接建立需求、**不得**直接写领域边/字段。
2. 同名对象**不得**任取；缺对象**不得**自动创建业务实例以消除歧义。
3. 未知/歧义**可以**用现有交互上下文消解；**不等同**必须向用户发问，也**不等同**可以静默猜唯一。

### 8.3 材料与状态

1. 入站材料**必须**带关系种子键、角色组与所用知识；角色实例齐或未齐**必须**如实状态化。
2. 入站成功仅证明「场景侧材料可回读」；**不得**宣称领域关系已写入。
3. 多义时**必须**保留候选或返回可区分多义/未决；不得按分支顺序取首条冒充唯一。

### 8.4 入站错误语义

至少区分：输入不合法、未找到匹配关系表达、多知识命中不任取、角色未确定、依赖未就绪、结构不一致。技术失败不得映射为「理解成功但空材料」。

## 9. 应用接入兼容性

1. 生产出站入口**应**经本能/任务链与统一关系陈述服务；验证夹具可以显式调用管理类执行，但**不得**把夹具入口宣称成生产选方法已实现。
2. 旧有字段询问等方法与新询问需求信息方法可以并存；登记召回验证通过**不得**冒充实任务调度已选择新方法。
3. 正式用户持久库验证与装配隔离数据验证**必须**分层记录；`formal_db=not_run` 时**不得**声称正式库验收通过。

## 10. 多语种与组合边界

### 10.1 多语种设计目标（非已证实全语种）

下列为**设计目标**，验收时只能对「已实现语言知识覆盖」计分：

1. 共享概念/对象/关系/语义身份跨语言稳定。
2. 词条、构式语序、语法/形态、分隔标点、单位呈现、指代等**知识化**；仅当缺通用执行能力时才扩展通用层。
3. 共享含义**必须**承载必要区别；**不得**承诺任意语句无损可逆。
4. 理解结果仍是场景材料，不是自动业务事实。
5. **应**先补通用能力再冻结纯数据实验；缺语言知识**不得**静默回退。

### 10.2 复杂句 / 段落 / 文章

1. 本规范只要求描述组合边界、必要语义作用域与篇章能力的**接口方向**（对齐 `7240` 含义网组合种类）。
2. **未实现**的篇章能力**不得**写成现行能力；本轮**不**新增实现。
3. 多陈述段组合仅覆盖关系概念表达关联已登记的段组；不得外推为任意段落理解。

## 11. 验收规范

### 11.1 总则

1. 验证**必须**基于独立结构读回：角色、方向、对象身份、作用域、未知角色保持、负例、旧回归、幂等保持。
2. **不得**以日志关键词匹配等价于语义正确。
3. 下列层级**必须**分开记账，禁止冒称：

| 层级 | 可证明内容 | 不得冒称 |
| --- | --- | --- |
| 生成单测 / 关系自检条目 | 夹具下成句/理解材料读回 | 生产选方法、正式库 |
| 登记召回 | 本能登记名可检查可用 | 任务已选该方法 |
| 显式本能执行 | 管理类/显式候选执行路径 | 真实调度策略 |
| 真实任务调度 / 队列 / 回答写回 | 端到端业务链 | 在未入列时宣称写回成功 |
| 正式用户库 | 正式持久库层 | `not_run` 时的「通过」 |

### 11.2 正例与负例最低集合

对每个已登记关系种子（或同族表达变体），验收**应**覆盖：

1. 正向成句 + 结构回读；
2. 方向错误或关系不成立；
3. 非法端点；
4. 缺目标语言知识不暗退；
5. 入站材料角色实例齐备性（若宣称入站）。

### 11.3 幂等

重复初始化同一种子表：**必须**复用身份；条目计数与关键读回稳定。
