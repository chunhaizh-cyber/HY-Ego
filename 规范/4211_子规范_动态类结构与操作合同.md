直接依赖规范：1160、1180、2100、3200、4212。

## 1. 定位

本规范展开1170动态实例的结构、建立、查询、生命周期、删除与非成功合同，并承接原4213的精确字段与流程；4213退役。动态owner唯一维护动态内容；动态概念归动态概念owner（7190—7195），场景组织归场景owner（1150、4202），状态内容归状态owner（4212），动作来源与因果边界见4220、1190。

动态有三种：原子、动作、复合。不另设“连续链”或第四种变化分支，不保存独立发生时间或可变当前值。

| 成员动态 | 无 | 无 | 至少两个原子动态，经外部父子关系 |
| 动作信息 | 无 | 动作定义（动作概念）、唯一来源X、目标信息节点、可选目标特征、动作时间、结果关系组 | 无 |
| 动态概念引用 | 恰一 | 无 | 恰一 |

种类编码：原子=1、动作=2、复合=3。

动态持有的二次特征（1180）是由自身正式状态成员确定计算的具名I64实例特征，如变化量、时间差、跨特征时间差；建立时一次确定，随动态存在和删除，不生成状态。同一动态持有的同一二次特征类型按结果方向（`>0`、`=0`、`<0`、`>=0`、`<=0`）区分，“类型＋结果方向”至多一项，不得重复（4180第9节）。

## 3. 原子动态

建立条件：

1. 两个状态不同且可完整读回，属于同一实例特征F。
2. 后态强时间严格晚于前态。
3. 两态准确值不同；准确值相同返回“准确值未变化”，不建立动态；任一态为未知状态（4212）时本版不建立原子动态，按入口拒绝处理。
4. 主题存在为沿F持有链确定的被描述存在（4212 §2）。
5. 挂接时两态均属于该动态的发生场景。

建立流程：

```text
核验两状态
-> 建立动态节点和两个状态引用项，分别增加状态引用
-> 建立实例动态概念（7191）并写入概念引用
-> 计算并写入本动态持有的二次特征（如有）
-> 在与后态同一组合发布内挂入发生场景
-> 完整读回
```

### 3.1 存在在两次状态之间迁移场景

状态不迁移、存在可迁移（1150）。同一F的前后状态分属不同场景时，不建立跨场景原子动态：

1. 存在离开原场景A时，先由相关owner删除或修改该存在与A相关的关系信息（成员关系等），再将其绝对坐标F置空；置空形成的状态挂入A，与A内该F的上一状态构成“离开A”原子动态。
2. 存在迁入场景B后写入坐标，B中生成该F的首个状态，即“被B发现”，不构成原子动态（4212第3节）。
3. “从A到B”的融合动态由A、B的共同上位场景按需形成：其成员以场景范围包含引用A、B中的状态与动态，原状态与动态不搬迁、不复制、不重复挂接（1150、1170）。

## 4. 动作动态

1. 每个执行实例X在动作开始时形成恰一动作动态，唯一来源为该X（3200）。同一X只能精确重放同一动作；同一X出现不同主体、动作定义、目标或时间时拒绝。
2. 动作定义引用动作概念。动作概念由本能方法登记形成并挂在动态根下（7190）；动作动态本身不建立实例动态概念，也不进入动态概念识别或聚合。
3. 动作动态先于真实改变或观察建立，并挂入执行主体所在场景；挂接时只核验执行主体属于该场景。目标信息节点可在其它场景或其它世界，以强类型引用记录，不阻止挂接；目标引用和结果关系可以跨世界，跨世界只禁止父子关系与成员关系（4200、4202）。
4. 结果关系只有“导致变化”和“观察取得”：前者要求动作时间落在结果变化端点之间；后者要求本次观察取得时间不早于动作时间，被观察事实可以早于动作形成（3200）。本次观察取得时间即该X读取动作的时间。读取未改变F当前值时不形成结果动态，也不建立“观察取得”关系；读到的材料作为该执行的返回材料交后续治理消费。
5. 结果动态由对应事实owner独立发布后，由持有该X的调用方显式建立结果关系；禁止扫描场景列表或按“最近动作”、时间邻近猜测。没有结果时动作动态可独立存在；没有动作时结果动态照常成立且不关联。
6. 动作已记录、结果已成立而关联失败时保留双方并返回部分完成，禁止为补记录自动重复真实动作。
7. 内部治理函数（如结算）不是本能方法，不形成动作动态（4220）。

## 5. 复合动态

建立条件：

1. 至少两个不同成员，均为可完整读回的原子动态。
2. 主题存在可读回；每个成员主题为主题存在本身或其当前任意层子存在。
3. 至少包含两个不同特征类型。
4. 串行通道按“成员主题＋F”形成；同一通道内按前态时间排序，相邻原子须满足前一原子的后态即后一原子的前态。不同通道之间为并行关系，不强行形成统一交错序列。
5. 需要存在服务与二次特征服务；依赖未配置时返回“依赖未配置”。

跨特征时间二次特征（动态持有二次特征的一种）：全部唯一状态按强时间分组，比较同一时刻组中不同特征类型的状态对及相邻时刻组之间不同特征类型的状态对，保存前后状态、前后F的特征类型、二次特征类型概念、结果值域概念和准确时间差；不比较任意远距离时刻组，不据此命名速度、周期或因果。有向差值溢出按统一口径饱和并带“已饱和”标记（4180）。

建立流程：

```text
核验成员与主题存在树
-> 核验各串行通道端点连续
-> 计算跨特征时间二次特征
-> 建立动态节点，增加成员引用并建立成员外部关系
-> 建立复合实例动态概念（复制成员概念已发布的状态变化材料，不永久依赖成员实例概念节点）
-> 挂入发生场景并完整读回
```

## 6. 采用聚合动态概念

只有上层确认聚合动态概念稳定且是该动态当前实例概念的合法上位时，才可采用：动态改为引用聚合概念，并删除原实例动态概念；动态实例、状态和成员关系不变。采用不是聚合算法的自动后处理。聚合与包含规则见7194、7195。

## 7. 查询

获取动态、是动态节点、按主题查询、按状态查询、按概念查询、按成员反查、按来源X查询动作动态，以及有界展开。执行资源不足时返回资源不足，不得截断冒充穷尽；合法空集与失败分账。场景动态列表与查询结果都不能替代时间轴对齐算法，时间顺序由状态强时间重建。

## 8. 生命周期与删除

1. 动态按定期、定量规则删除（0050 §1.5），动态类只提供同步清理入口，由运行宿主维护周期调用；TTL自首次形成UTC起算；数量按每个场景各自的动态列表计数，超量最旧先删；默认阈值由4190规定，场景列表层组织由4202规定。
2. 受保护、本轮不删除的动态：被因果概念或聚合动态概念以正式引用采纳为代表实例；仍被复合动态、结果关系引用；被他人特征、需求、任务、方法或因果正式引用。被引用即受保护，不另设保留标记。动作动态存在期间，其唯一来源X受保护（3200）。是否仍被引用以4015第10.1节引用闭包查询为准，引用计数只做快速判定，二者不一致为结构不一致。
3. 同一轮清理中先删动态、后删状态。
4. 删除原子动态：解除两个状态引用并减少状态引用计数，删除自身实例概念或解除聚合概念引用。删除复合动态：解除成员关系、减少成员引用、清理自身持有的二次特征并处理概念。删除动作动态：解除全部结果关系并减少结果动态的组成引用，再清理动作字段；不取得结果动态的删除所有权。
5. 已采用共享聚合概念的动态删除时，不删除仍被其它动态使用的聚合概念。
6. 删除顺序为先解除场景列表及全部正式引用，再删除节点。

## 9. 一致性不变量

1. 种类、主题与生命周期字段结构完整；原子、复合有动态概念，动作有完整动作字段且无动态概念。
2. 原子动态恰有两个不同状态，同一F、时间严格递增、准确值不同。
3. 复合动态至少两个不同原子成员和两个不同特征类型；同主题同F串行通道端点连续；跨特征成员并行，不伪造统一全局顺序。
4. 每个状态和成员动态的引用计数与正式引用相符。
5. 实例概念准确指回动态；聚合概念不得伪装为实例专属概念。
6. 动作动态的唯一来源为X；结果只能经显式强类型关系关联。
7. 每个动态只属于一个发生场景，不随存在迁移；场景列表只是发生位置引用，不是时间链。

## 10. 非成功分类

状态不足、状态不存在、状态重复、主题不一致、特征（F）不一致、准确值未变化、时间不合法、成员不足、不是原子动态、动作信息不合法、动作来源冲突、动作结果不匹配、动作关系冲突、端点不连续、跨特征不足、二次特征失败、依赖未配置、实例概念失败、概念不合法、形成环、引用阻止、结构不一致、资源失败。一次业务变化整体发布；原子发布实现前，后续步骤失败返回具名部分完成，不回滚已成立的事实。

## 11. 最低验证

1. 原子动态：同一F、严格时间顺序、准确值相同拒绝；每个原子动态建立独立实例概念。
2. 跨场景迁移：先删改关系信息，置空坐标在A内形成“离开A”，迁入B写入坐标只生成首个状态，融合动态由共同上位场景以范围包含引用形成。
2a. 动作动态目标在其它场景或其它世界时仍挂入执行主体所在场景；同一动态同类型同方向二次特征重复拒绝。
3. 动作动态：来源为X、先于结果建立、同源精确重放与异义拒绝、改变/观察时间规则、无结果正常成立且不关联、多个相近动作不按“最近”误关联、内部治理函数不形成动作动态。
4. 复合动态：只接受原子成员，主题允许本存在及子存在；串行端点连续、跨特征并行；同时刻组与相邻时刻组的跨特征时间比较；短构造器返回依赖未配置。
5. 采用聚合概念后删除原实例概念。
6. 场景与复合成员引用成对维护；定期、定量删除不删除被采纳代表实例与被引用动态，先删动态后删状态。
