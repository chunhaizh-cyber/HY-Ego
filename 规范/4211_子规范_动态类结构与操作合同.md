# 4211 子规范 动态类逻辑结构与操作合同

编号：4211
日期：20260909
版本：v1.5
状态：正式子规范

直接上级规范：1170。

直接依赖规范：0050、1160、2100、4010、4015、4202、4203、4230。

相关边界规范：4210、4220、7190。

## 1. 定位

本规范只冻结动态类的逻辑信息、操作语义、所有权和依赖边界，不冻结精确 C++ ABI。现阶段尚未冻结：公开类名、模块位置、构造依赖、请求与结果 DTO 字段布局、枚举数值、成功谓词、动态关系类型稳定编码及动态存量迁移算法。4202状态使用绑定的物理身份和窄只读接口已由4203冻结。

因此，本规范可以作为后继物理合同的机器语义依据，但不能单独授权直接编写或迁移动态类代码。任何实现不得从非现行动态代码、DTO、关系角色或持久格式反推缺失合同。

动态内容只有一个写入 owner。动态概念、场景组织、状态内容、状态使用绑定、动作来源和因果分别由各自唯一 owner 维护；不得因一次业务流程同时消费这些事实而建立第二动态仓或跨 owner 隐式写入。

## 2. 动态逻辑信息

每份动态固定包含：

```text
动态身份
+ 主体存在
+ 变化内容
```

变化内容只能二选一：

```text
原子变化 = 前状态使用绑定引用 + 后状态使用绑定引用
组合变化 = 非空直接成员集合
```

名称概念关系由唯一概念 owner 独立维护，不进入动态内容载荷。创建代次、退出代次、事实截止、幂等身份、清理标记和墓碑属于可靠性或生命周期材料，不是动态业务字段。实际起止时间只从原子端点或组合成员派生，不另存可独立改写的动态时间字段。

### 2.1 状态使用绑定引用

“状态使用绑定引用”是4203已经冻结的不透明强类型引用。它必须能够在指定历史截止唯一读回同一次具体使用的：

```text
发生场景 C
+ 被描述存在 E
+ 中性状态 S
+ 发生时有效的完整绑定依据
```

被描述特征由E与S内的正式特征类型FT共同确定，不增加独立属性身份或FT副本。同E同FT不证明同一次观察，完整绑定仍须保留真实发生依据。状态使用绑定的身份、发布、当前/历史读取、退出及恢复合同由4203冻结；动态类必须消费其不透明强类型身份和窄只读提供者，不能把C、E、S三项散装拼接后冒充一份完整绑定。

原子动态两端必须同场景C、同主体E、同一正式特征类型FT，且前时间严格早于后时间、准确值确有变化。FT从各端S读回核验；状态或F身份不同不能代替准确值变化。两端状态不得相同；缺绑定、绑定不可历史读回、类型不一致、时间冲突或未发生变化时均不得形成动态。

### 2.2 组合成员

每个直接成员固定包含：

```text
顺序
+ 成员角色
+ 子动态身份
+ 条件必需的组成关系历史依据
```

成员角色只有：

- 同主体成员：子动态主体与组合主体相同。
- 组成存在成员：子动态主体在该次发生时是组合主体的正式直接或递归组成存在。

“组成存在成员”不能用当前组成关系替代历史依据。后继物理合同必须提供可在成员发生截止核验的组成关系身份或等价完整历史见证；不存在合法历史依据时不得把同场景出现解释为组成变化。

同一组合内顺序从1连续递增，子动态身份不得重复，来源图必须无环。顺序只用于规范化和直接成员定位，不覆盖成员自身时间；并行、交叠、间隔、重复单元和摘要均从成员及应用规则派生，不是组合成员字段。

## 3. L1 物理承载边界

L1 关系只能连接两个节点，关系自身不能作为另一关系的端点，值也不能挂接到关系。动态物理映射必须遵守以下边界：

1. 动态主体使用动态节点指向存在节点的具名关系。
2. 两种组合成员角色使用两种不同的“动态节点→子动态节点”关系类型表达。
3. 成员顺序只使用4010关系事实自带的角色/顺序字段。
4. 原子端点只引用4203冻结的 `状态使用绑定身份`，并经其窄只读提供者读取完整C/E/S事实；不得散装保存或拼接三项目标。
5. 关系类型稳定编码、基数校验所需读取投影和跨 owner 引用方式必须由后继物理合同冻结，不能复用被替代关系数值或恢复并列变化分类。

## 4. 操作语义

动态类内容面固定为以下九项操作语义：

1. 新增原子动态。
2. 新增组合动态。
3. 按动态身份读取完整内容。
4. 按主体有界读取动态组。
5. 按状态使用绑定有界反查原子动态组。
6. 按直接子动态有界反查父动态组。
7. 有界展开动态直接或递归来源。
8. 普通退出动态。
9. 物理清理实例动态材料。

动态结构服务还须提供两项身份读取操作语义：

```text
确认当前动态结构身份
读取动态身份来源历史见证
```

身份读取与动态内容互不替代。逻辑能力为两项身份读取加九项内容操作；4230只规定当前确认无来源载荷和历史完整见证等共同语义，不再提供固定七族公共ABI。上述名称表达操作用途，不冻结函数签名；精确身份与内容合同须由同一动态专属物理合同共同固定，不能把九项内容操作或旧公共模板宣称为完整公开ABI。

本规范冻结操作语义，不冻结函数名、重载、请求/结果类型、状态枚举数值或 C++ 可见性。后继合同必须逐项冻结请求字段、结果完整载荷、合法空集、失败优先级和成功谓词，才能进入代码计划。

不得增加原地修改内容、替换主体、替换端点、替换成员、写场景组织、写状态绑定、写概念名称、自动比较、自动归组、动作归因、因果判断或级联删除操作。

## 5. 新写、幂等重放与读回

### 5.1 首次新写

首次新增必须在一个明确读取截止内完成全部来源核验。原子新增至少核验主体存在、两端C/E/S完整绑定及S中的正式特征类型、准确值与时间，以及应用提交的变化依据；组合新增至少核验全部直接子动态、成员角色、发生时组成依据、重复成员和无环性。动态类不重新执行特征比较算法，比较与确认变化由4210应用承担。

来源展开必须有非零最大深度和最大对象数量。任何预算不足、来源缺失、来源已退出、历史材料已清理、绑定不完整、组成依据不成立或读取漂移均在第一笔动态写入前失败，动态内容零变化。

动态节点、主体关系及当前变化分支的全部自有事实必须共同发布，不得先暴露裸动态节点再补关系。确认提交或精确重复后，必须按首次发布截止独立读回完整内容；已确认提交后的读回失败不得伪装回滚。

### 5.2 已绑定幂等身份

请求幂等身份已经绑定时，服务必须先读取首次规范化请求、首次结果和首次发布材料：

- 与首次请求完全一致时，返回首次结果并按原发布截止读回，不重新使用“当前”组成关系、当前绑定或当前来源否定已经成立的首次事实。
- 与首次请求不一致时返回幂等冲突，零新写。
- 首次材料不可互证时返回内部不一致或发布结果未知，不以新身份猜测重建。

首次新写与已绑定重放必须分流；不能每次都递归重验当前来源，否则历史事实会因后续成员移动、组成变化或来源退出而失去幂等收敛性。

## 6. 查询、展开与一致性

内容读取返回指定截止下的完整动态；组合读取还须返回每条直接成员的顺序、角色及必要历史组成依据。反向查询按请求维度返回完整动态集合，合法无匹配项与读取失败分账，结果按稳定身份确定排序。

递归展开必须显式给出最大深度和最大动态数量。预算不足不得返回截断结果冒充穷尽；无环核验与递归读取不能依赖无界递归、全仓扫描或忙重试。

动态类读取场景绑定，场景完整视图又会读取动态组织。后继装配必须使用只暴露状态使用绑定读取的窄只读提供者打断模块循环；动态类不得反向持有完整场景类，也不得取得场景组织写入口。

## 7. 分阶段发布

一次现实变化涉及的事实按 owner 分阶段发布并分别读回：

```text
状态内容
-> 状态使用绑定
-> 动态内容
-> 场景动态实例树组织
-> 可选动作来源
```

前一阶段成功是后一阶段的输入，不代表后续阶段已成功。动态内容发布与场景组织不构成一个隐式跨 owner 事务；场景挂接失败不得退出或重建已发布动态。动作来源只关联既有动态，不增加变化内容分支。

## 8. 普通退出与物理清理

普通退出只结束动态的当前可用性，必须保留完整历史内容、首次幂等材料和受保护引用，不形成“历史已清理”结论。普通退出不得删除主体、状态、状态使用绑定、子动态、概念、场景组织、动作来源或因果。

物理清理是与普通退出不同的具名操作。只有满足0050/4230的TTL、数量上限、引用闭包和确定候选顺序后，才可删除允许清理的动态载荷并形成最小墓碑。仍被父组合、场景组织、概念来源、动作来源或因果引用时必须先按各 owner 合同闭合引用；不得由动态类级联删除外部事实。

读取必须区分当前、已普通退出、可历史读回、历史材料已物理清理和内部不一致。墓碑只证明材料已按合同清理，不能用于重建内容。

## 9. 现行边界

动态只采用本规范的“具体原子变化/具体组合变化”模型。生产合同不得增加第三种变化分支、独立发生时间、可变当前值或把多项来源复制成并列业务字段。

重复整理、间断片段拼接、关键阶段提取和模式固化属于4210/7190应用与动态概念；动作来源属于4220；因果属于1190/4310。它们都不能扩写动态内容字段。

非现行代码、DTO、关系编号、持久格式和过程材料不得成为生产解析分支、兼容写入口或机器语义来源。后继迁移必须同次关闭被替代生产入口，不能长期双写；L1依法保留的历史材料仍按L1合同保护，不等于动态类继续解释非现行业务格式。

## 10. 实施门禁与验证要求

形成可执行代码计划前，必须另行冻结并互证：

1. 精确消费4203状态使用绑定身份、历史读取及退出/恢复合同，不复制其DTO或实现；
2. 状态内容精确读取 ABI；
3. 动态类公开模块、类名、构造依赖、全部请求/结果 DTO、枚举数值及成功谓词；
4. 原子端点、主体、两类组合成员关系的稳定物理角色；
5. 首次写入、幂等重放、来源预算、完整读回、普通退出和物理清理合同；
6. 动态类与场景类之间无环的窄只读装配；
7. 被替代生产入口、解析分支和存量持久材料的迁移/拒绝矩阵。

最低验证必须覆盖：原子/组合合法新增；两端C/E/正式FT不一致或时间不递增；不同状态或F身份但准确内容相同不生成动态；同E同FT多次真实观察不合并；组成历史依据；重复成员与成环；首次新写与幂等重放分流；十一项逻辑操作面的边界；合法空集；当前/普通退出/历史/已清理读取；预算不足零截断；提交后读回未知；分阶段场景组织失败；外部引用保护；非现行生产字段和入口零命中。

在上述物理合同未冻结前，只能声明“动态逻辑结构与操作语义已冻结”，不得声明“C++ ABI 已冻结”“可直接实现”或“动态类已经闭合”。
