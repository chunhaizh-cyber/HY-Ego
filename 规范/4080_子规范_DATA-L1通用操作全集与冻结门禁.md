# 4080 子规范 DATA-L1通用操作全集与冻结门禁

编号：4080
日期：20261105
版本：v3.0
状态：正式子规范

直接上级规范：0050。

直接依赖规范：4015、4010、4040。

相关边界规范：4030、4050、4060、4070、4190、4240、5350。

## 1. 定位

本规范规定基础数据集（4015）公开操作面的封闭范围和防扩张门禁。基础数据集是节点、外部关系、字段关系和直接值的业务中性current-only底座；公开面不含合同版本常量、事实代次字段、历史/墓碑/物理清理入口、幂等账或owner写端口。

本规范不证明代码、持久迁移或消费者切换已完成。旧L1公开面（owner-scoped读写、历史读取、物理清理、事实代次读取、v1/v2/v3版本化原子事务等）按4015第18节退出正向语义，只作删除清单和迁移定位；在代码完成迁移并通过新独立验收前，DATA底座整体能力不得声明为已冻结完成。

## 2. 数据变化原语

公开写入只允许4015规定的中性变化：

1. 节点新建（无上级、有上级）与删除（4015第6节）；
2. 外部关系新增、修改与删除（4015第7节）；
3. 字段关系及其直接值的新增、修改与删除（4015第8节）；
4. 由上述项目组成、一次发布的组合变化集（4015第14节、4040）。

删除是物理删除，不保留墓碑或历史；删除前以4015第10.1节引用闭包查询证明无保护性引用，引用计数只做快速判定（0300 R39）。

## 3. 公开操作全集

公开业务操作面封闭为以下类别，具体签名、DTO与结果以4015对应节为唯一正文：

| 类别 | 操作范围 | 依据 |
| --- | --- | --- |
| 节点 | 新建（无上级/有上级）、删除、按编码读取 | 4015第6、10节 |
| 外部关系 | 新增、修改、删除、按编码读取、按源/目标节点＋关系类型读取 | 4015第7、10节 |
| 字段 | 新增、修改、删除、按编码读取、按所属节点＋字段节点读取 | 4015第8、10节 |
| 引用闭包 | 按目标节点完整列举全部引用 | 4015第10.1节 |
| 组合发布 | 提交组合变化集，结果未知时按原请求查询或恢复 | 4015第14节、4040 |
| 一致投影 | 一次共享锁内的多结构读取投影 | 4010第6.1节 |
| 对象生命周期 | 构造空数据集、按持久化恢复 | 4015第11.3、15节 |

构造、析构、移动和比较等值类型语言操作不属于业务操作。结果辅助谓词不得把多种失败合并为布尔成功（4015第13节）。

上层唯一支持的源码入口由实施详细设计冻结；内部容器实现只属于服务实现，生产源码不得绕过公开面直接访问内部容器。

## 4. 明确排除的能力

基础数据集不提供、也不得新增：

1. 建立或解释存在、场景、特征、状态、动态、因果、需求、任务、方法、动作、安全或服务对象；
2. 判断两个对象是否同一业务存在、判断特征是否变化、自动从状态生成动态或从动态形成因果；
3. 领域准入、资格、真实性、有效性、完成性、成功性、授权和业务结果解释；
4. 任意深度递归遍历、全量扫描、按值内容全局查询、任意条件查询或把索引当作第二权威（4015第10节）；
5. 业务生命周期、定期定量删除调度、线程、日志或审计事实；
6. 为单个上层应用增加专用DTO、枚举、结果状态、快捷写入口、组合读入口或持久字段；
7. 历史读取、墓碑、事实代次、截止读取、合同版本、幂等账或owner分区。

上层需要的存在—特征、场景成员、当前值、状态—动态—因果、需求—任务—方法等结构，均由上层数据类使用节点、关系、字段、组合变化集和读取投影组合形成。

## 5. 公开标识符约束

基础数据集公开标识符不得出现`存在、场景、特征、状态、动态、因果、需求、任务、方法、动作、安全、服务`等领域专用词；通用结果字段中的“状态”只表示结构化操作结果。旧双参与者原子事务的`状态写集/动态写集`等领域命名及旧`许可拒绝`结果随旧L1退出，只作迁移解码定位，现行入口不得新产生。

## 6. 持久恢复边界

持久化与恢复以4015第15节和4070为准：恢复全部现存对象、校验编码互异与引用闭合、校验分配器不复用、重建非权威索引、完整读回后开放写入。快照不保存事实代次、历史或墓碑；持久格式版本属于工程格式轴，不是机器事实版本。

## 7. 防扩张门禁

1. 公开面增删改（操作、签名、DTO字段、枚举稳定值）必须先修订4015/本规范并经用户确认，不得由上层计划、调用点或性能便利先改代码后补规范。
2. 仓库应保留机器可读的公开面清单与检查器，至少核对：第3节类别与实际公开操作一致；第4、5节排除能力与禁止标识符为零；不存在事实代次字段、合同版本常量、历史/墓碑/物理清理/幂等入口；生产源码不绕过公开面。
3. 检查器不得依赖日志、生成缓存、编译产物或人工维护的第二份源码列表。

## 8. 完成矩阵

DATA底座迁移完成至少在一个不含未提交源码差异的精确提交树上，通过公开接口覆盖：

1. 节点、外部关系、字段的新建、读取、修改、物理删除与引用闭包拒绝；
2. 引用闭包查询区分无引用、目标不存在、资源失败与内部不一致；
3. 组合变化集交换前失败零变化、成功全部同时可读、结果未知按原请求查询收敛；
4. 一致投影一次共享锁内完整读取；
5. 持久化恢复与恢复失败不交付数据集；
6. 公开面检查器、Debug/Release完整构建与统一黑盒驱动通过。

构建通过、静态接口存在或单一成功路径不能替代上述矩阵；崩溃、断电、介质故障、资源耗尽和长时运行未实际覆盖时标为未运行，不升级对应可靠性声明。
