# 4080 子规范 DATA-L1通用操作全集与冻结门禁

编号：4080
日期：20260901
状态：正式子规范

直接上级规范：0050。

直接依赖规范：4010—4070。

相关边界规范：4190、4230—4270。

## 1. 定位与冻结状态

DATA-L1 是节点、关系、值和技术结构 owner 的纯事实内核。本规范冻结其通用操作全集、兼容例外、恢复管理面和可验证的接口防扩张门禁。

```text
DATA-L1 通用操作全集 / 目标公开合同状态 = FROZEN
DATA-L1 整体能力状态 = PENDING_ACCEPTANCE
```

`FROZEN` 在当前阶段只表示通用操作全集和目标公开合同已冻结：上层用途不得以存在、场景、特征、状态、动态、因果、需求、任务、方法、动作、安全、服务或其它领域需要为理由，向 L1 新增或改写公开入口、DTO 字段、结果状态、持久格式语义或事实解释。上层只能组合本规范冻结的目标能力。

`PENDING_ACCEPTANCE` 表示尚无绑定干净精确提交基线的统一黑盒与独立集成验收 `PASS`，因而不得声称 DATA-L1 整体能力已 `FROZEN`。操作合同冻结是实现和验收的目标，不是实现通过证明。

通用操作 / 公开合同的 `FROZEN` 不表示源码永久不可修改。以下维护仍然允许：

1. 不改变冻结操作集、DTO 语义和事实结果的缺陷修复；
2. 安全加固、平台适配和性能优化；
3. 对已冻结旧格式和旧 ABI 的兼容修复；
4. 为验证冻结合同而增加生产外检查器、固定样本和黑盒驱动。

上述维护必须回归本规范的机器检查和统一黑盒矩阵。确需新增基础原语时，必须由用户显式解除冻结、证明现有操作无法组合表达，并以新合同版本完成规范、兼容、迁移和验证裁决；上层计划、代码调用点或性能便利不能自行解除冻结。

## 2. 数据变化原语

L1 写集只允许以下五类中性变化：

1. 新建节点；
2. 新建关系；
3. 新建值；
4. 切换一个“节点 + 属性类型”的当前值槽；
5. 逻辑退出节点、关系或值。

物理清理是独立维护操作，只处理已经逻辑退出且引用闭合的节点、关系或值，并保留最小墓碑。L1 不提供节点、关系或值的原地改写：修改值必须新建值并切换槽，修改关系必须新建关系并退出旧关系，修改不可变节点结构必须形成新事实并显式退出旧事实。

## 3. 冻结公开操作全集

以下名称集合是 L1 唯一允许的公开业务操作面。构造、析构、移动、比较和 `成功()` 等值类型语言操作不属于业务操作，不据此扩展数据能力。

上层唯一支持的模块入口是 `海中鱼巣.核心.服务.L1事实基座`。`海中鱼巣.核心.仓库.L1事实基座` 即使因 C++ 模块组织仍可被机械 import，也只属于服务实现内部；除服务模块外的生产源码不得直接 import、构造或调用仓库，否则即为绕过写端口、签发器和冻结公开面的第二入口。

### 3.1 普通中性写入、维护与读回

```text
提交中性写集
读取中性写入首次结果
执行L1物理清理
读取中性当前节点
读取中性当前关系
读取中性当前值
读取中性当前属性
读取中性当前源关系组
读取中性当前目标关系组
读取中性历史关系组
读取中性历史属性值组
读取中性历史事实
读取中性当前事实代次
尝试读取中性一致当前投影
```

普通中性写入是旧共享范围兼容面。它继续保持既有合同、幂等和读回，不向调用方公开 owner；新的结构应用应使用 owner-scoped 能力，不得把普通中性入口扩展为第二套新合同。

### 3.2 owner-scoped读取

```text
读取所有者范围当前节点
读取所有者范围当前关系
读取所有者范围当前值
按来源读取所有者范围全部当前值
按属性类型读取所有者范围全部当前值
读取所有者范围当前源关系组
读取所有者范围当前目标关系组
读取所有者范围历史关系组
读取所有者范围历史属性值组
读取所有者范围历史事实
尝试读取所有者范围一致当前投影
尝试读取所有者范围一致关系类型闭包投影
读取当前结构所有者
读取历史结构所有者
```

这些入口只按已知 owner、稳定编码、关系端点、关系类型、来源、属性类型、数量预算和事实代次读取中性结构。它们不成为整库列举、任意递归图查询、全文检索或领域判断入口。

### 3.3 owner-scoped写端口与原子事务

```text
所有者身份
有效
绑定于
提交所有者范围中性写集
读取首次写入材料
提交跨所有者原子事务
提交三分区原子事务_v2
提交有限N分区原子事务_v3
```

`提交有限N分区原子事务_v3` 是新组合的通用多分区原子入口，支持 `2..255` 个互异 owner。三分区 v2 保留为已冻结通用兼容合同，不得被复义。双参与者 v1 的 `状态写集 / 动态写集` 是第 5 节唯一领域命名兼容例外。

### 3.4 owner管理、运行包与恢复

```text
建立所有者范围
重新签发所有者范围写端口
退出所有者范围
读取服务
所有者范围签发器
建立L1事实基座运行包
建立L1事实基座持久运行包_v1
```

无参数运行包只供生产外隔离测试。普通应用使用持久运行包；持久工厂只管理受控存储根、隔离恢复和运行包交付，不向普通 CRUD 增加磁盘回源或业务入口。

## 4. 明确排除的能力

L1 不提供、也不得新增以下能力：

1. 建立或解释存在、场景、特征、状态、动态、因果、需求、任务、方法、动作、安全或服务对象；
2. 判断两个事实是不是同一业务存在，判断特征是否变化，自动从状态生成动态或从动态形成因果；
3. 领域准入、资格、真实性、有效性、完成性、成功性、授权和业务结果解释；
4. 任意深度递归图遍历、跨 owner 全量扫描、任意条件查询或把索引当作第二权威；
5. 业务生命周期、业务事实截止、TTL、调度、线程、日志或审计事实；
6. 为单个上层应用增加专用 DTO、枚举、结果状态、快捷写入口、组合读入口或持久字段。

上层需要的存在—特征、场景成员、当前值、状态—动态—因果、需求—任务—方法等结构，均由 DATA-L2 / DATA-L3 或 DATA 外业务层使用节点、关系、值、属性槽、事实代次、通用事务和读取投影组合形成。

## 5. legacy领域命名兼容例外

双参与者 v1 原子事务保留以下既有领域命名：

```text
L1跨所有者原子事务参与者序号::状态
L1跨所有者原子事务参与者序号::动态
L1跨所有者原子事务请求.状态写集
L1跨所有者原子事务请求.动态写集
L1跨所有者原子事务结果.状态编码映射
L1跨所有者原子事务结果.动态编码映射
提交跨所有者原子事务
```

该集合只用于既有 ABI、既有调用者和权威载荷格式 1—3 的解码 / 幂等重放兼容。禁止新增消费者，禁止增加第三个领域角色，禁止把名称解释成 L1 拥有状态或动态语义，禁止复制为新的领域命名入口。新多分区组合统一使用中性参与者身份和 `提交有限N分区原子事务_v3`。

既有结果枚举中的 `许可拒绝` 只用于旧 ABI 和持久结果解码，现行入口不得新产生该结果。不得删除或重排其数值，也不得把它恢复为调用资格或 owner 权限裁决。

除上述精确例外外，L1 公开标识符不得新增 `存在、场景、特征、动态、因果、需求、任务、方法、动作、安全、服务` 等领域专用词。通用错误或结果字段中的“状态”只表示结构化操作结果，不属于状态对象语义。已冻结的技术类型 `L1事实基座服务`、操作 `读取服务` 及其签名中同名技术参数是“服务”词的精确技术例外；不得据此放开任意含“服务”的新标识符。

## 6. 持久恢复冻结边界

4070 持久恢复管理面保留，冻结为：独占受控存储会话、一个当前清单、两个轮换快照槽、SHA-256、完整权威状态编解码、非权威索引重建、全量结构互证、持久准备先于内存交换、结构化恢复结果和恢复后正式读回。

清单格式版本 1 与权威载荷格式版本 1 / 2 / 3 是两条独立版本轴。载荷编码只产生格式 3，解码接受 1 / 2 / 3；未知清单或载荷格式返回 `格式不支持`。三类事实、当前 / 历史、属性槽、墓碑、稳定编码占用和各代幂等账必须按格式能力完整恢复。

L1 内部不保存 128 条环形恢复审计账，不提供恢复审计 CRUD，诊断写入失败不阻断已经完整互证的恢复。恢复尝试的人读诊断归装配或日志层，不进入事实、快照或普通 CRUD。

## 7. 机器冻结门禁

仓库必须保留一份机器可读的冻结清单和一个检查器，并由正式规范严格检查入口调用。门禁至少同时验证：

1. 第 3 节公开操作名称、完整签名、重载数与公开模块实际操作完全相等，缺项、增项、改参数 / 返回类型 / `const` / `noexcept` 或增减重载都失败；
2. 四个公开数据面中的类型、字段顺序与类型、枚举项及稳定数值、别名、合同版本常量与公开辅助签名均属冻结合同；任一增删改都必须使合同指纹检查失败；
3. 第 5 节领域命名只出现在精确兼容例外位置，“服务”只出现在本规范已冻结的精确技术标识符中；其它 L1 公开标识符出现禁止领域词时失败；
4. 冻结清单的 `surface_contract_status=FROZEN`，规范编号、合同版本、合同指纹和 legacy / 技术例外集合与本规范一致；整体 `data_l1_status` 在独立验收前必须为 `PENDING_ACCEPTANCE`，不得由代码执行者改为 `FROZEN`；
5. 规范目录对 4015、4070、4080 和有限 N v3 实现状态的摘要一致；
6. 除 `服务.L1事实基座.ixx` 外的生产源码直接 import 仓库模块时失败；现行源码新增 `许可拒绝` 生产分支时失败；
7. 检查器不能依赖日志、生成缓存、编译产物或人工维护的第二份源码列表证明公开面。

为避免不完整 C++ 解析器遗漏同名重载、DTO、枚举、合同常量或重导出 callable，冻结清单必须同时对服务模块和四个公开数据面记录整文件 SHA-256（只规范行结束）。任一字节改动都先使 `FROZEN` 门禁失败。合同内缺陷、安全、平台、性能或兼容修复确需修改这些文件时，只能由具名 L1 维护计划证明冻结操作、公开签名 / DTO / 枚举 / 版本、legacy 例外和持久矩阵未扩张后更新指纹并全量回归；上层用途计划不得更新指纹。

任何上层计划要求修改冻结清单或放宽领域例外时必须立即停止，不得先改 L1 再补规范。

## 8. 统一黑盒完成矩阵

L1 最终收口至少在一个不含未提交源码差异的精确提交树上，通过公开 DTO、运行包、签发器、写端口和读取服务覆盖：

1. 节点、关系、值的创建、当前读取、替换、逻辑退出、历史读取和物理清理墓碑；
2. 属性槽切换、结构引用闭包、事实代次、精确重复、同键异义和失败零变化；
3. owner 建立、唯一端口、重新签发、退出、owner-scoped 当前 / 历史 / 组 / 一致投影；
4. 双参与者 v1、三分区 v2、有限 N v3 的兼容与共同代次原子发布；
5. 新格式 3 的三类事实、当前 / 历史、槽、墓碑与幂等账恢复；
6. 由权威载荷格式 1 的发布提交和格式 2 的发布提交经各自合法公开生产路径生成的固定样本，在新实现中恢复、正式读回并继续提交 v3；禁止手工拼装或由当前格式编码器伪造旧样本；
7. 未知清单格式和未知载荷格式返回 `格式不支持`，已知格式内损坏按摘要、材料、编码、owner、事实代次或内部不一致分账；
8. 清单缺失但槽存在、清单指向槽缺失、长度不符、摘要不符、已知格式未知标签、同根第二进程占用和非活动槽诱导均 fail-closed，失败不交付运行包；
9. 冻结公开面检查、领域接口防扩张检查、正式规范严格检查、Debug / Release 完整构建与同一统一黑盒驱动全部通过。

构建通过、静态接口存在、旧历史记录或单一成功路径不能替代上述矩阵。崩溃、断电、介质故障、资源耗尽和长时运行未实际覆盖时仍明确为 `NOT_RUN`，不阻止操作合同冻结，但不得升级对应可靠性声明。

代码执行者在精确提交树完成上述矩阵，只能产生“待独立验收的 DATA-L1 收口候选提交”。随后必须由集成验收与回归智能体以该已提交、已推送的精确 commit 为唯一基线，通过法定公开消费面、结构化结果、权威终态和独立读回完成具名验收。只有该独立验收结论为 `PASS`，且验收记录绑定同一精确 commit 后，规范 / 计划索引所有者才可进行第二次治理发布：将本节的 `DATA-L1 整体能力状态`、冻结清单 `data_l1_status` 和规范目录摘要一致升级为 `FROZEN`，登记验收 commit / 记录，并使本计划退出。任一验收失败、`NOT_RUN` 的必要项或基线漂移都保持 `PENDING_ACCEPTANCE`。
