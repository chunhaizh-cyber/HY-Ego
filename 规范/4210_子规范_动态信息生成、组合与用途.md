# 4210 子规范 动态信息生成、组合与用途

编号：4210
日期：20261105
版本：v3.0
状态：正式子规范

直接上级规范：1170。
直接依赖规范：1130、1160、1180、2100、4180、4202、4211、4212。
相关边界规范：0050、1150、4150、4151、4220、6140、7190、7191、7193。

## 1. 定位

本规范固定DATA外动态应用的生成与组合职责：何时由状态事实触发原子动态、如何按明确时间段与主题组合复合动态、跨场景与递归如何组织、重复与间断如何处理、动态信息的用途，以及多owner分阶段发布时的结果报告。动态的字段、建立条件、查询、生命周期与非成功分类由[4211](4211_子规范_动态类结构与操作合同.md)规定；动作动态与因果边界由[4220](4220_子规范_动作来源与动态因果边界.md)规定；重复结构、周期与方向等概念层规则由[7190](7190_子规范_动态概念信息与生成规则.md)—7195规定。本规范不重复这些合同。

## 2. 原子动态生成

1. 触发：状态owner在某场景状态列表中为实例特征F发布新状态后，动态应用取同一场景中该F的上一份状态，与新状态配对；配对只依据F身份、场景列表和强时间，不另存属性键，也不使用状态使用绑定或四锚定位。
2. 比较：读取两份状态各自所记准确值，引用值按2100完整读回；比较使用4180允许的类型、用途、单位、维度和算法，合法有向差异按“后值减前值”解释，不可比较不等于零差异。
3. 基准与无变化：该场景中F只有一份状态（含迁入后首次写入坐标即“被发现”）时只作基准，不形成原子动态。状态只在值变化时生成（1160），配对两态准确值相同属于结构不一致。
4. 时间：前后强时间必须严格递增；同时间不同值且无法确定先后时返回时间冲突，不按身份排序。
5. 相邻只表示已记录的状态序列相邻，不证明现实中不存在未观察的变化。前一份状态已按生命周期删除时，以场景中现存的上一份状态配对，不补造中间变化。
6. 确认变化后按4211建立原子动态：先建立动态实例，再由动态概念owner建立其实例动态概念（7190、7191），不以已发布的动态概念身份作为动态建立前置。

状态类、特征类和场景类均不得自行扫描生成动态；动态数据服务不重新执行比较。存在跨场景迁移时，按4211第3.1节分别形成“离开A”的原子动态与B中的首个状态，不建立跨场景原子动态。

## 3. 时间段组合

1. 同一主题存在的多个原子动态，可以在一个明确有限时间段内按4211第5节组合为复合动态。归组请求必须明确观察范围、纳入规则及窗口语义；端点落窗、整体落窗和窗口交叠不得混用。
2. 组合保留直接成员和组成角色；实际顺序、同时、交叠、间隔及缺测从成员状态强时间读回，不另存。时间段共同出现不证明联动、共同动作或因果。
3. 复合动态的成员数、特征类型数和串行通道连续性按4211第5节；不满足时不组合，不为凑数复制成员或加入无变化材料。

## 4. 场景与递归

1. 原子动态的发生场景是其两份状态所在场景（4211）；复合动态挂入其主题存在所在场景。每个场景只记录自身动态，动态不随存在迁移。
2. 整体变化由外部场景组织；内部存在的变化由把父存在展开为场景后的内部场景组织。需要把多个子存在变化概括为父存在整体变化时，建立以父存在为主题的复合动态，成员角色以正式组成关系及子存在的“所属整体”F证明（1140）。
3. 跨场景的融合动态只由共同上位场景按范围包含引用子场景的状态与动态形成；子场景不得建立涉及兄弟场景的融合动态（1150、1170）。
4. 一个动态可以被多个复合动态或融合动态作为来源引用；场景归属、复合来源和概念支持是不同关系。

## 5. 重复、长序列和间断

1. 动态可以表达两阶段、多阶段、并行或带间断组合。重复单元提取只形成新的复合动态或概念来源，不压缩、改写或删除原动态。
2. 往复或周期必须同时证明单元内部变化、单元间连接和周期边界；单次往返不证明周期（7190）。
3. 不连续片段只有在真实先后关系可证时才能组合，不能补造连续性；首尾状态相同不消除中间变化。
4. 相位等价、方向等价和停止性必须由正式规则判断，不按数组循环移位或名称相似默认成立。

## 6. 用途与职责

动态信息用于变化定位、场景过程回查、不同动态比较、动态概念形成、因果分析，以及任务和方法结果解释。动态只能触发对当前值的重新读取，不能用后状态替代F当前值，也不能自行证明需求满足。

| 责任方 | 必须提供的能力 | 禁止事项 |
| --- | --- | --- |
| 动态数据服务 | 执行4211规定的结构建立、读取、查询、展开、删除与清理 | 不比较、不归组、不抽象、不写场景或概念事实 |
| 场景数据服务 | 维护场景动态列表与组织关系 | 不修改动态内容，不把挂入列表当作变化成立证明 |
| 动态应用 | 相邻配对、比较、时间段归组、递归组合、重复整理及多owner阶段协调 | 不复制CRUD，不把计算成功冒充发布成功 |
| 动态概念应用 | 按7190—7195形成、匹配和治理动态概念 | 不改来源动态，不创建第二概念owner |

动态持有的二次特征按1180、4151和4180计算，为具名I64，建立时一次写入，同一动态上同类二次特征按结果方向（`>0`、`=0`、`<0`、`>=0`、`<=0`）区分、不得重复，建立后固定、不生成状态（4211）。缺少正式取值或多来源运算提供者时返回不支持；不得伪造F或裸I64来源。

## 7. 分阶段发布与非成功

一次原子或复合动态的完整形成跨越多个owner，固定顺序为：

1. 动态应用核验状态、比较或组合来源；
2. 动态数据服务建立动态实例并完整读回；
3. 动态概念owner建立实例动态概念并写入概念引用（7191）；
4. 场景数据服务将动态挂入发生场景列表；
5. 动态应用在一次current-only一致读取中读回内容、概念引用和场景组织，报告完整结果。

能在同一组合发布内完成的步骤按4015一次发布；跨owner的后续步骤失败时，保留已发布的部分并如实报告所在阶段（如“动态已建立、场景未组织”），重试沿原身份继续，不换身份重复创建，不声称跨owner回滚，也不设持久意图字段。

基准状态、无变化和未匹配概念属于正常业务分支。缺来源、不可比较、时间冲突、主题或组成证明不足、来源已删除、格式不支持、资源失败和发布结果未知必须分别报告。枚举、递归、展开、比较和读取必须处理请求声明的完整范围；无法完成时返回资源失败，不截断冒充完整。

## 8. 验证合同

| 场景 | 必须结果 |
| --- | --- |
| 场景中F只有一份状态，或迁入后首次写入坐标 | 只作基准，不创建动态 |
| 同场景同F的相邻两态，准确值不同 | 创建可完整读回的原子动态，先实例后实例概念 |
| 不同F，或两态不在同一场景 | 拒绝原子配对 |
| 同时间不同值 | 返回时间冲突，不按身份排序 |
| 同主题不同F的变化交叠 | 按4211组合并保留成员端点、间隔与交叠 |
| 子存在变化形成父存在复合动态 | 必须有正式组成关系及“所属整体”F证明 |
| 重复、间断及首尾相同 | 不丢失、不重复计数、不伪造连续性 |
| 动态已建立而场景组织失败 | 返回真实阶段，原动态可独立读回 |
| 来源已按生命周期删除或资源不足 | 不返回部分完整结果，不留下成员缺失的复合动态 |
