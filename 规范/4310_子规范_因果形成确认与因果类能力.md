# 4310 子规范 因果形成、确认与因果类能力

编号：4310
日期：20260909
版本：v1.0
状态：正式子规范

直接上级规范：1190。

直接依赖规范：4202、4210、4211、4220。

相关边界规范：1130、1140、1170、2220、4150、4190、4230、4240、4320、4330、5350、7140。

## 1. 定位

本规范定义因果类如何从已发布世界事实取得材料、形成候选、确认并发布概念化因果信息，以及如何读取、绑定、求值、补完和重新核验。它不定义独立因果实例，不授权DATA-L2结构服务判断因果真实性，也不把因果候选直接变成任务或方法。

## 2. 两种发现方式

### 2.1 被动发现

被动发现是随场景新增状态、动态和动作事实持续进行的后台筛选：

```text
按场景和时间段读取已发布动态
-> 按主体、特征概念、变化方向和值域归组
-> 选择重复变化并读取前后状态及动作来源
-> 建立正样本、负样本和反例集合
-> 提取共同条件、可选动作与稳定结果
-> 形成任务局部因果候选
```

被动发现可以得到主动因果候选，也可以得到动作未显现的被动因果候选。“被动发现”不决定因果类型。

### 2.2 主动寻找

主动寻找由目标状态、未知变化、方法缺口、预测失败或解释需求触发。调用方至少提供目标特征概念以及起始值/值域、目标值/值域或变化方向之一；存在概念、角色、场景和时间范围可以作为附加约束。

主动寻找按成本逐层扩大：

```text
相同特征概念与精确值域
-> 相同特征概念与相似 / 相邻值域
-> 从具体存在概念向合法上位概念扩展
-> 从当前场景向父场景、相似场景和全部历史场景扩展
-> 必要时复现历史场景视图并重新计算合法二次关系
```

命中索引后必须回读同一事实截止的正式状态、动态、动作来源和场景组织。不得以索引、名称、缓存或统计摘要代替来源事实。

## 3. 历史场景复现

因果类不拥有第二套场景仓。需要复现时调用场景、状态、动态、关系及动作来源的正式历史读取，形成调用方拥有的只读视图：

```text
指定历史截止下的场景组织
+ 当时的存在成员与子场景
+ 当时可回查的状态、动态和关系
+ 当时实际动作来源
+ 从上述事实可复算的二次特征
```

原始事实、复算结果和未知信息必须分栏。复算结果保留全部来源；当时未观察且现在无法推出的信息保持未知，不得补造。只有当前成员列表而没有历史归属、移动及关系事实时，不能声称已复现过去场景。

因果发现可以使用后来取得但能够证明指向该历史时段的事实进行事后复核；需要还原“当时自我知道什么”时，只能使用当时已经可用的认知事实。两种视图不得混用。

## 4. 候选组织

候选是任务局部值式DTO，不建立节点、关系、生命周期或恢复资格。每个候选至少包含1190固定字段的待确认值式表达，以及正样本锚点、负样本锚点、反例和材料不足项。

形成时必须：

1. 把具体存在映射为有序角色，并为角色选择证据能够覆盖的最通用存在概念；
2. 把前置具体状态归纳为角色化特征概念和值/值域条件；
3. 主动候选只使用能够回读的实际动作来源归纳归入动态概念根的动作概念；
4. 把动作后稳定形成的具体状态归纳为结果状态模式；
5. 排除动作前已经成立、全时段持续存在或正负组同样出现的背景项；
6. 保留共同原因、替代原因、分化条件和反例，不能求一个总交集后丢失合法分支。

不同析取条件、不同参与者角色、相反动作方向或不同结果模式形成不同候选。候选相似不等于同义，规范化查重必须比较完整字段。

## 5. 确认规则

### 5.1 共同检查

发布前至少确认：

- 角色、条件和结果非空且能够完整读回；
- 主动因果具有合法动作概念，被动因果无动作字段；
- 原因/动作在结果之前，时序不明不得冒充方向明确；
- 多次正样本结构一致，并存在能够区分背景项的负样本或等价反证检查；
- 同条件下结果未出现的反例已经解释为缺失条件、错误范围、动作未完成或规律不成立；
- 每个结果都在全部适用正样本中稳定形成，不把偶然副产物列为必然结果；
- 去掉某条件后出现反例时保留该条件，去掉后不影响规律时删除冗余条件；
- 概念范围不超过证据覆盖，不能因追求通用而把下级规律错误提升到根概念。

重复次数不是唯一确认依据，不设置一个适用于所有因果的固定次数。单次观察、零反例或概念名称一致均不能单独确认规律。

### 5.2 主动因果确认

主动因果优先使用同条件下“执行动作/不执行动作”的安全干预和对照，确认动作是结果成立的必要触发项。动作返回成功、方法结束、日志或预期输出都不能替代实际动作和结果状态读回。

### 5.3 被动因果确认

被动因果确认的是已知范围内稳定可复现的变化规律及预测价值，不宣称隐藏动作、完整机制或全部条件已经找到。其确认结果必须允许继续寻找动作、扩大反例范围及从原因果链展开被简化部分。

## 6. 发布与证据

确认业务只向唯一因果结构服务提交完整1190字段。数据服务在一个因果owner写集中机械校验强类型、角色、顺序、基数、引用、规范化唯一和结构完整性，发布或复用因果信息；业务确认与DATA结构发布分阶段，不伪装跨owner全局原子。

发布后再通过4330具名来源/支持关系关联实际状态、动态和动作证据，并分别读回因果完整定义及证据。证据关联失败不撤销已经发布的因果定义；调用方报告真实阶段并以原请求续行，不重复创建同义因果。

## 7. 因果类固定能力

因果业务类应提供下列语义能力；本规范不冻结C++函数名：

| 能力 | 输入 | 输出 |
| --- | --- | --- |
| 被动发现候选 | 场景、时间范围、读取预算 | 零至多个任务局部候选及不足原因 |
| 主动寻找候选 | 目标特征/变化、可选存在/场景/时间约束、预算 | 分层扩大范围后的候选、证据和未命中原因 |
| 确认并发布 | 完整候选、确认依据、期望截止 | 已复用、已发布、候选不足、反例未闭合、漂移或结构失败 |
| 读取完整因果 | 因果身份、事实截止、预算 | 完整概念化字段和来源状态 |
| 读取形成证据 | 因果身份、事实截止、预算 | 可回查事实锚点及完整/不足状态 |
| 绑定并判断适用 | 因果身份、具体角色绑定、当前事实截止 | 条件满足、条件缺失、角色不兼容、动作能力缺失或读取失败 |
| 由因求果 | 已适用因果、角色绑定、可选动作参数 | 预期结果状态模式的值式求值，不写世界事实 |
| 由果查因 | 目标状态模式、适用范围、预算 | 零至多条主动/被动因果候选及缺口 |
| 简化 / 展开 | 因果或因果链、目标范围 | 保留来源的值式简化结果或完整展开 |
| 补完被动因果 | 被动因果、动作证据 | 新主动因果候选及与原规律的补完来源 |
| 重新核验反例 | 因果身份、新事实范围 | 继续适用、需要缩小、需要补完或停止使用建议 |

候选、绑定、预测和建议不取得持久身份。因果类不得直接创建需求、任务、方法、动作、状态或动态。

## 8. 利用边界

由因求果用于预测、观察重点和风险传播；由果查因用于给方法形成提供动作与前置条件材料。因果类不评价结果对自我有利、有害、需要或可忽略。方法应用根据需求选择一条或多条因果链，检查自我“我能……”的动作能力，组织动作并独立观察实际结果。

被动因果可以用于预测、等待、回避、准备和继续寻找动作，但不能单独生成“调用未知动作”的执行步骤。主动因果可以成为方法候选材料，但只有自我或其它角色具备相应动作能力且当前条件满足时才可被方法采用。

## 9. 非成功与禁止事项

读取失败、预算耗尽、历史不足、场景无法复现、规则不支持、事实截止漂移、候选不足、反例未闭合和内部不一致必须分别返回。任何一项都不得伪装为正常未命中、默认条件满足或已确认因果。

禁止全库无界穷举；主动寻找必须按索引与逐层扩展执行并接受预算。禁止把当前场景组织回填成历史组织，禁止用后来形成的认知冒充当时已经知道，禁止让候选或预测结果反写原始事实。

## 10. 验证

验证至少覆盖两种发现方式与两类因果的四种组合、精确到扩展检索顺序、历史场景复现分栏、正负样本和反例、条件最小化、主动对照、被动范围限制、完整定义查重、分阶段发布/证据续行、角色绑定、由因求果、由果查因、补完及所有非成功零错误发布。
