# 4310 子规范 因果形成、确认与因果类能力

编号：4310
日期：20261105
版本：v2.2
状态：正式子规范

直接上级规范：1190。

直接依赖规范：1160、1170、4340。

相关边界规范：1130、1140、2220、4202、4211、4220、4320、4330、5350、6330、7140、7190。

## 1. 定位

本规范定义因果应用如何从仍然保留的世界事实（状态、动态及因果代表实例）取得材料、形成概念层因果、在新发生到来时登记统计并原地修订，以及如何读取、绑定、求值、补完和重新核验。因果定义结构、匹配规则、统计不变量和数据操作见4340；代表实例与淘汰见4330。本规范不定义独立因果实例，不授权数据结构服务判断因果真实性，也不把因果候选直接变成需求、任务或方法。

发现、筛选和扫描属于DATA之外的因果发现应用；因果数据类不扫描场景列表，只接收上层已选定的前置窗口（第4.1节）。

## 2. 两种发现方式

### 2.1 被动发现

被动发现随场景新增状态、动态和动作事实持续进行：

```text
按场景读取已挂接的动态（含父场景按范围包含引用的子场景动态，1150、1170）
-> 按结果承担者、结果特征类型、变化方向及动作概念归组
-> 选择同组的不同发生（动态）并读取前后状态、F及其持有者、动作来源
-> 按第4.2节由两次发生形成，或按第4.3节命中既有因果
```

被动发现可以得到主动或被动、已知或未知动作的因果；“被动发现”不决定因果的任一维度。

### 2.2 主动寻找

主动寻找由目标状态、未知变化、方法缺口、预测失败或解释需求触发。调用方至少提供目标特征类型以及起始值域、目标值域或变化方向之一；存在概念、角色、场景和时间范围可以作为附加约束。

主动寻找按成本逐层扩大：

```text
相同特征类型与精确值域概念
-> 相同特征类型与相邻 / 上位值域概念
-> 从具体存在概念向合法上位概念扩展（最宽至存在根）
-> 从当前场景向父场景及同一世界内其它场景扩展
-> 必要时对保留的状态、动态重新计算合法二次关系
```

命中索引后必须回读正式状态、动态、动作来源和场景组织。不得以索引、名称、缓存或统计摘要代替来源事实。

## 3. 复盘材料

因果类不拥有第二套场景仓。复盘只使用仍然保留的状态、动态（含已形成持久记忆者）及因果代表实例，形成调用方拥有的只读视图：

```text
保留的状态（记录F的值变化及强时间）
+ 保留的动态及其发生场景
+ 动作动态及其来源执行实例X
+ 从上述事实可复算的二次特征
```

原始事实、复算结果和未知信息必须分栏。已按生命周期删除的材料保持未知，不得补造；只有当前成员列表而没有对应状态、动态时，不能声称已复现过去场景。需要还原“当时自我知道什么”时，只能使用当时已经可用的认知事实，与事后复核视图不得混用。

## 4. 形成、命中与修订

### 4.1 发生与前置窗口

1. 一次发生就是一个动态（1170），发生身份即动态身份；发生场景取该动态挂接的场景，挂接时已核验成员一致性。
2. 前置状态与前置动态由上层选择并传入；因果数据类不扫描场景列表，不自行决定时间窗起点、终点、长度或噪声过滤规则。结果状态与结果动态从前置组中排除；任一前置节点无法读回时整次处理失败，返回具名非成功。
3. 发现路径为：结果状态筛选、结果动态反向、动作事实反向（自我动作事实来自执行实例X对应的动作动态）、外部动作动态反向。推断得到的外部动作不冒充自我真实动作事实；同一发生经多条路径提交只计数一次（去重见4340第7节）。

### 4.2 由两次发生形成

1. **分组键**：结果承担者角色、结果特征类型、结果方向（原子动态前后值所在值域概念的变化），以及动作概念（已知动作时）或“无动作”。
2. **角色取共同上位**：两次发生中对应角色的存在，各取其专属概念（尚无专属概念时为存在根），再取两者在存在概念图中的最具体共同上位（可能是中间层，也可能就是存在根）。角色概念只能是可共享的类别概念或存在根；共同上位落在专属投影（例如两次发生是同一只杯子）时，上移到该专属投影最近的类别概念上位，最宽至存在根。专属投影含当前确定值并随状态漂移，不得作为因果角色。
3. **条件取共同上位**：两次发生前置窗口中“同一角色、同一特征类型”都出现的状态，取两个准确值在该特征类型概念树中最具体的共同包含值域概念；只在一次中出现的条件不进入定义。前置动态条件取两次动态概念的最具体共同上位。条件只取前置窗口内的状态和动态：窗口内没有发生变化、因而没有状态的长期背景条件不计入因果定义，这是已接受的限制；不为补足背景条件保留各特征的最新状态，也不用特征当前值代替过去状态。
4. **结果取共同上位**：两次结果值的最具体共同包含值域概念，或相对关系概念（结果值相对基准条件值的方向关系）。
5. 共同条件为空时返回“无共同条件”，不强行建立因果。
6. 发布时统计初值为符合出现次数=2，两次发生登记为“形成来源”代表实例（4330）。两次正例即可发布为参考规律；第5节的确认清单只作为可靠性提升条件，不是发布门槛。
7. 发布前按4340做规范化查重；与既有因果同义时复用既有因果并登记本次发生，不新建。

### 4.3 命中既有因果

1. 按4340第5节匹配规则，取所有“条件满足且动作匹配”的因果中包含序上的极小者；有多个互不可比的极小者时全部更新（1190第5节），被它们包含的较宽者不更新。
2. 结果也满足时记为符合；结果不满足时记为不符合，并按4330更新“最近反例”代表实例。
3. 本次发生含有额外条件时，额外条件不自动加入定义。

### 4.4 原地修订

因果概念按当前认知原地修订（0050第1.5节）：

1. **扩大**：正例与某条件不符（结果仍出现）时，把该条件的值域概念放宽为两值的最具体共同包含概念；角色概念同理上移。
2. **缩小或分裂**：反例满足全部条件但结果未出现时，记入不符合统计及最近反例；不符合累计达到4330规定的阈值后，尝试从正例代表实例与反例的差异中补出区分条件，缩小原定义，或分裂为两条更具体的因果。
3. **合并**：修订后与既有因果同义时，复用既有因果，原因果的引用（方法、链、代表实例）以及动态一侧指向原因果的“已计入”关系在同一次修订中改接后退出；统计按4340第6、7节合并，同一动态不重复计数。
4. 修订后原有计数按当前定义继续解释，不追溯重算、不清零；因修订而不再满足当前定义的代表实例，在同一次修订中解除保护或改标。

## 5. 可靠性提升条件

下列检查不阻止发布，用于提升可靠性评价、选择最具体因果和确定是否需要缩小：

- 角色、条件和结果非空且能够完整读回；
- 已知动作因果具有合法动作概念（由本能方法登记形成，见4340第3节）；未知动作因果无动作项；
- 原因/动作在结果之前，时序不明不得冒充方向明确；
- 存在能够区分背景项的负样本或等价反证；
- 同条件下结果未出现的反例已解释为缺失条件、错误范围、动作未完成或规律不成立；
- 去掉某条件后出现反例时保留该条件，去掉后不影响规律时删除冗余条件；
- 概念范围不超过证据覆盖，不把下级规律错误提升到根概念。

主动使用方式的因果优先使用同条件下“执行动作/不执行动作”的安全干预和对照；动作返回成功、方法结束、日志或预期输出都不能替代实际动作和结果状态读回。被动使用方式的因果只宣称已知范围内稳定可复现的变化规律，不宣称隐藏动作、完整机制或全部条件已经找到。

### 5.1 作用动作归因核对

观察到目标变化，不足以证明某个作用动作导致该变化。把变化认定为某次作用动作导致（“导致变化”关联、已知动作因果的归因材料）之前，至少核对：动作时间与变化时间；作用范围与目标身份；动作前后特征；外设传感器与外部观察的一致性；其它可能来源和硬冲突；结果是否在预测误差范围内。未完成上述核对时只记录同时发生或待归因候选，不得作为已确认归因。

## 6. 发布与代表实例

形成或修订业务只向唯一因果结构服务提交完整的概念层定义；数据服务在一个因果owner写集中机械校验强类型、角色、基数、引用、规范化唯一和结构完整性，发布、复用或原地修订因果。代表实例的关联与保护按4330；关联失败不撤销已发布的定义，调用方报告真实阶段并以原请求续行，不重复创建同义因果。

## 7. 因果类固定能力

本规范不冻结C++函数名：

| 能力 | 输入 | 输出 |
| --- | --- | --- |
| 被动发现 | 场景、执行资源上限 | 新形成、命中更新或不足原因 |
| 主动寻找 | 目标特征/变化、可选存在/场景/时间约束、执行资源上限 | 分层扩大后的因果、代表实例和未命中原因 |
| 形成或修订并发布 | 两次发生或命中材料、前置窗口 | 已建立、已复用、已修订、无共同条件或具名非成功 |
| 登记发生 | 动态、命中因果、符合/不符合/自我尝试 | 统计更新或重复发生 |
| 读取完整因果 | 因果身份、执行资源上限 | 完整概念层定义、统计、代表实例 |
| 绑定并判断适用 | 因果身份、具体角色绑定 | 条件满足、条件缺失、角色不兼容、动作能力缺失或读取失败 |
| 由因求果 | 已适用因果、角色绑定、可选动作参数 | 预期结果的值式求值，不写世界事实 |
| 由果查因 | 目标特征与值域、适用范围、执行资源上限 | 零至多条因果及缺口 |
| 简化 / 展开 | 因果或因果链、目标范围 | 保留来源的值式简化结果或完整展开 |
| 补完被动因果 | 使用方式为被动或未知动作的因果、动作证据 | 已知动作因果及补完来源 |
| 重新核验反例 | 因果身份、新事实范围 | 继续适用、需要缩小、需要补完或建议淘汰 |

绑定、预测和建议不取得持久身份。因果类不得直接创建需求、任务、方法、动作、状态或动态。

## 8. 利用边界

由因求果用于预测、观察重点和风险传播；由果查因用于给方法形成提供动作与前置条件材料。因果类不评价结果对自我有利、有害、需要或可忽略。方法应用根据需求选择一条或多条因果链，检查自我的动作能力，组织动作并独立观察实际结果。

未知动作因果和被动使用方式的因果可以用于预测、等待、回避、准备和继续寻找动作，但不能单独生成“调用未知动作”的执行步骤。已知动作、主动使用方式的因果可以成为方法候选材料，但只有具备相应动作能力且当前条件满足时才可被方法采用。

## 9. 非成功与禁止事项

读取失败、执行资源用尽、复盘材料不足、规则不支持、无共同条件、候选不足、反例未闭合、计数溢出和内部不一致必须分别返回，不得伪装为正常未命中、默认条件满足或已确认因果。

禁止全库无界穷举；主动寻找必须按索引与逐层扩展执行并接受调用方给定的执行资源上限。禁止把当前场景组织冒充过去的组织，禁止用后来形成的认知冒充当时已经知道，禁止让预测结果反写原始事实，禁止把具体存在实例或准确值固化进通用定义。

## 10. 验证

验证至少覆盖：两种发现方式；已知/未知动作与主动/被动/尚未确定使用方式的组合；两次正例形成及共同上位求取（含角色上移至存在根）；无共同条件；命中多个互不可比极小因果时全部更新；扩大、缩小、分裂、合并四种原地修订；合并后统计相加与引用改接；代表实例随修订解除保护；同一动态多路径提交只计数一次；复盘只用保留材料；全部非成功零错误发布。
