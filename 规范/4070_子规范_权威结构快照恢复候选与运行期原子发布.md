# 4070 子规范 权威结构快照、恢复候选与运行期原子发布

编号：4070

日期：20261105

版本：v2.0

状态：正式子规范

直接上级规范：0050。

直接依赖规范：4010、4015、4030、4040、4050、4060。

相关边界规范：4080、8120、8121。

## 1. 定位

本规范规定基础数据集（4015第15节）current-only状态的持久快照、启动恢复的候选隔离与全量互证、内存一次原子发布和持久材料回收。快照、清单和其它持久材料都只是恢复输入，不是运行期权威。

持久化只保存最后完整发布的current-only状态（0050第1.1、1.2节）：不保存、生成或恢复事实代次、截止、历史事实、墓碑、owner分区或公共幂等账。

恢复、完整快照和材料回收属于独立管理面，不是普通CRUD的隐式前置、参与者或固定结果字段。普通CRUD不调用本规范入口；只有启动或运维策略、具名恢复请求才显式进入本规范。

本规范至少证明受控退出后的进程重启恢复；崩溃、断电、介质损坏和长期材料保留，只有经独立验证实际覆盖后才能声明。纯内存运行包可供仓库外隔离测试使用，不得用于普通应用生产装配；普通读取不访问磁盘。

## 2. 受控存储会话与快照

1. 持久运行包接收绝对且规范化的受控存储根；路径只属于装配配置，不进入普通CRUD请求、事实或公开读回。
2. 一个存储根同一时刻只允许一个进程持有操作系统级独占会话。不能取得时返回“存储占用”，不得退化为新空仓。
3. 固定材料只包括一个当前清单、两个轮换快照槽和一个会话锁。清单缺失且两个槽均不存在时才是合法空仓；清单缺失但任一槽存在、清单指向的槽缺失或摘要不符，都不得按空仓启动。
4. 当前清单固定记录：清单格式、单调快照序号、活动槽、载荷格式、载荷长度和SHA-256摘要。快照序号只标识哪一份快照是最新完整写入，不是事实代次，不进入公开结果。
5. 快照采用显式小端定长整数、长度前缀和稳定枚举标签；禁止直接写入C++对象布局、地址、`sizeof`填充、`variant::index()`、容器桶序或未冻结的类型哈希。
6. 写入先形成非活动槽的临时文件并刷新，再原子替换非活动槽；随后形成并刷新新清单，再原子替换当前清单。清单是持久材料的提交见证，不是运行期事实权威。
7. 当前清单有效时，未被它选择的完整槽只作上一轮回退材料，不得择新、择大或择优采用；当前清单无效时，也不得自行回退旧槽冒充恢复成功。

### 2.1 格式

清单格式与载荷格式是两条独立的解码轴，只用于解码持久字节，不是服务合同版本（0050第1.2节）。未知清单格式或未知载荷格式返回`格式不支持`并保留原材料。生产恢复入口不保留带事实代次旧格式的解码或迁移旁路；如需转换，由独立具名移转工具承担。

### 2.2 快照内容

完整载荷逐字段覆盖4015第15节要求的信息：

```text
数据集身份
+ 下一个可分配编码（不复用保证）
+ 全部现存节点
+ 全部现存外部关系
+ 全部现存字段关系及直接值
+ 同一组合请求发布未知收敛所需的最小技术材料
+ 完整性摘要
```

查询索引、缓存和统计投影都是非权威派生物，不进入快照，恢复时从已解码的权威字段确定重建（4060）。运行期锁、地址、端口、缓存和尚未发布的候选不得持久化。上层数据类的确认结果、读取DTO或其请求不是载荷字段；企图以它们作为恢复输入的材料按格式不支持或材料不完整拒绝。

## 3. 全量互证

恢复必须在隔离状态中验证：

```text
编码非零且互异，分配器不会复用既有编码
+ 全部节点、外部关系、字段关系的对象类别合法
+ 全部关系端点与字段内容引用闭合
+ 关系与字段的基数、唯一性约束成立
+ 快照序号、活动槽、载荷长度与摘要一致
```

缺项、编码复义、材料损坏、关系断裂或基数矛盾，均拒绝整批，不得默认补齐或发布半结构。数据层只验证中性结构完整性；业务不变量由数据层之外的业务层在业务入口重新开放前独立复核，恢复事务不得调用业务服务或接收业务回调。

## 4. 重新准入与发布

1. 恢复不得把快照记录直接放入当前视图；候选必须经过4015的中性结构准入。领域业务的重新准入是发布后的独立开放门禁，不是恢复事务参与者。
2. 启动恢复前不存在运行期权威。材料异义、缺项或损坏必须拒绝，不得择优拼接。
3. 完整候选以一次无抛出交换原子发布为内存权威；这是恢复的唯一运行期发布点。发布后完整读回，再从当前状态确定重建索引和缓存。
4. 持久运行包中每个成功的组合原子发布，必须先形成新快照与清单，持久准备成功后才执行无抛出的内存状态交换。持久准备失败时不交换内存状态、不返回新编码映射。
5. 进程在新清单提交后、内存交换前终止时，下一进程可以采用该完整候选；上一调用属于发布结果未知，按同一组合请求的技术材料收敛，禁止分配第二组编码。
6. 资源、磁盘空间或刷新失败映射为资源失败；编码器无法表达已验证状态、清单与载荷自相矛盾或持久成功后内存读回不一致，映射为内部不一致（4050）。
7. 只读和零变化操作不写新快照、不增加快照序号。

## 5. 启动与运行期

启动恢复必须在上层数据服务构造、真实自我与各根初始化（8120、8121）和普通业务入口开放之前完成。固定顺序为：取得独占存储会话，读取清单和活动槽，在隔离状态解码，重建非权威索引，执行全量互证，以一次无抛出交换发布内存状态，随后开放写入。合法空仓直接建立空数据集并绑定持久会话，不伪造恢复见证。

普通应用必须使用持久运行包；配置或恢复失败时装配失败，后续上层数据服务、自我、本体根、本能根和线程都不得形成。当前合同不提供运行期局部恢复入口。

## 6. 诊断边界

数据层不保存内部恢复审计账，不提供恢复审计CRUD，不把诊断记录写入载荷，也不因人读诊断记录失败而拒绝已经完整互证的恢复。恢复尝试的来源、结构化结果、拒绝类别和必要摘要，由装配或日志层按现行日志规范记录；这些记录只供人读回查，不能修复事实、替代清单与摘要，也不能替代结构化恢复结果。诊断不得记录可复用的端口、租约、nonce、地址或token。

## 7. 物理删除与材料回收

1. 对象删除是4015第12节的物理删除，在内存权威中一次完成，不保留历史、墓碑或旧内容；下一份快照不再包含被删对象。删除前由上层以引用闭包查询证明引用已解除（0300 R39）。
2. 被删对象的稳定编码不复用，由持久保存的分配高水位保证。
3. 旧快照槽和旧清单只在新清单提交成功后才可作为回退材料保留或覆盖；材料回收失败不反向改变内存当前状态，删除持久文件也不得改变内存权威。

## 8. 结构化结果

至少区分：建立空仓、恢复成功、入口拒绝、存储占用、材料不完整、格式不支持、摘要不一致、编码或关系或基数冲突、资源失败、发布结果未知和发布后内部不一致。材料缺项属于材料不完整；材料校验通过后出现复义、半发布或读回变化属于内部不一致。操作系统文件访问拒绝是技术存储失败，不是业务许可拒绝。业务入口是否重新开放由数据层之外独立裁决，不进入恢复结果状态。
