# 4070 子规范 持久证据恢复候选、内存原子发布、审计与材料回收

编号：4070
日期：20260802
状态：正式子规范

直接上级规范：0050。

直接依赖规范：4010—4060。

## 1. 定位

本规范规定启动和运行期恢复的候选隔离、全量互证、重新准入、内存代次原子发布、审计和材料回收。原文件名为兼容引用保留；SQL、快照、事件和材料文件都只是恢复输入或持久证据，不是恢复后的运行期权威。

## 2. 恢复候选

1. SQL 行、快照、事件、材料文件或外部数据库记录首先都是恢复材料，不是当前事实。
2. 每次恢复具有稳定恢复批次身份、来源、格式版本、目标事实范围和事实截止。
3. 候选在隔离区解析和互证，不得进入普通查询、缓存或领域当前视图。

## 3. 全量互证

恢复必须验证：

```text
稳定身份及不可复用
+ 类型合同身份、版本和状态
+ 类型化值及材料摘要
+ 全部关系端点、角色和版本
+ 当前 / 历史 / 退役生命周期
+ 幂等和发布证据
+ 领域业务不变量
```

缺项、混批、身份复义、版本回绕、材料损坏、关系断裂或业务不变量冲突均拒绝整批或按正式批次合同隔离，不得发布半结构。

## 4. 重新准入与发布

1. 恢复不得把 SQL 行、文件记录或外部对象直接放入当前视图；候选必须重新经过对应领域服务和 L1 准入。
2. 启动恢复前不存在运行期权威。恢复材料之间同义只说明可组成候选；异义、缺项、过期、退役复活或版本冲突必须拒绝或隔离，不得择优拼接。
3. 完整候选通过 4040 的内存事实事务一次原子发布；该内存代次切换是恢复的唯一运行期事实发布点。
4. 发布后按恢复批次、身份、版本和代次见证从内存权威读回；随后从该内存代次确定重建索引和缓存，并记录持久证据采用结果。

## 5. 启动与运行期

启动恢复必须在普通业务入口开放前完成所需范围的全量审计并原子发布首个内存权威代次。运行期恢复必须限制受影响事实范围，验证相对当前代次的并发与当前性，并通过新代次原子换代；不得原地覆盖当前内存，也不得让 SQL 当前行绕过恢复准入。

## 6. 审计

审计记录恢复批次、SQL / 文件等输入来源与摘要、判定版本、每类拒绝、内存代次发布结果、持久证据状态和发布后读回。审计材料只供回查，不能修复事实或替代内存发布证据。

## 7. 退役与回收

1. 退役先在内存已发布代次中改变生命周期并保留历史、引用和证据；SQL / 材料随后保存对应持久证据。
2. 材料只有在当前、历史、审计、恢复、法律保留和并发读者均不再引用时才可进入回收候选。
3. 回收失败不反向恢复业务当前性；删除 SQL 行或目录文件不得改变内存已发布事实。

## 8. 结构化结果

至少区分恢复成功、精确同义、材料不完整、格式不支持、身份冲突、版本漂移、关系矛盾、业务拒绝、资源失败、内存发布未知、持久证据未知和发布后内部不一致。
