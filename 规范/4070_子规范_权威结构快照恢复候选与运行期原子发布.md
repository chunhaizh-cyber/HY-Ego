# 4070 子规范 SQL 权威恢复候选、审计与材料回收

编号：4070
日期：20260731
状态：正式子规范

直接上级规范：0050。

直接依赖规范：4010—4060。

## 1. 定位

本规范规定启动和运行期恢复的候选隔离、全量互证、重新准入、SQL 发布、审计和材料回收。原文件名为兼容引用保留；运行期内存上下文不再是权威发布对象。

## 2. 恢复候选

1. 快照、事件、材料文件或外部数据库记录首先都是恢复材料，不是当前事实。
2. 每次恢复具有稳定恢复批次身份、来源、格式版本、目标事实范围和事实截止。
3. 候选在隔离区解析和互证，不得进入普通查询、缓存或领域当前视图。

## 3. 全量互证

恢复必须验证：

```text
稳定身份及不可复用
+ 类型合同身份、版本和状态
+ 类型化值及材料摘要
+ 全部关系端点、角色和版本
+ 当前 / 历史 / 退役生命周期
+ 幂等和发布证据
+ 领域业务不变量
```

缺项、混批、身份复义、版本回绕、材料损坏、关系断裂或业务不变量冲突均拒绝整批或按正式批次合同隔离，不得发布半结构。

## 4. 重新准入与发布

1. 恢复不得直接写当前表或内存对象；候选必须重新经过对应领域服务和 L1 准入。
2. 与当前 SQL 同义的事实幂等复用；异义、过期、退役复活或版本冲突拒绝。
3. 需要发布的新事实通过 4040 的 SQL 事务提交；SQL 提交是恢复的唯一事实发布点。
4. 提交后按恢复批次、身份和版本读回；随后从 SQL 确定重建索引和缓存。

## 5. 启动与运行期

启动恢复可以在普通业务入口开放前完成全量审计；运行期恢复必须限制受影响事实范围并遵守并发和当前性。两者都不能用内存上下文整体替换绕过 SQL 提交。

## 6. 审计

审计记录恢复批次、输入摘要、判定版本、每类拒绝、SQL 提交结果和发布后读回。审计材料只供回查，不能修复事实或替代发布证据。

## 7. 退役与回收

1. 退役先在 SQL 中改变生命周期并保留历史、引用和证据。
2. 材料只有在当前、历史、审计、恢复、法律保留和并发读者均不再引用时才可进入回收候选。
3. 回收失败不反向恢复业务当前性；删除目录文件不得改变 SQL 事实。

## 8. 结构化结果

至少区分恢复成功、精确同义、材料不完整、格式不支持、身份冲突、版本漂移、关系矛盾、业务拒绝、资源失败、提交未知和提交后内部不一致。
