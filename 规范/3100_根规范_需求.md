直接依赖规范：0050、1130、1140、1160、7160。

## 1. 定义

需求是自我希望某个目标存在的一种目标特征达到目标值，或在一次任务执行中按指定方向变化的治理目标。

```text
需求 = 自我希望
     + 目标存在
     + 一个目标特征类型
     +（目标值/值域及比较关系，或目标变化方向）
```

所有正式需求天然都是自我的需求，不再保存“所属存在”字段。需求中的存在只表达被改变或保持的对象，统一称为`目标存在`，不得再称为“目标宿主”。

一个需求只针对一个目标特征类型。多个特征目标必须拆成父子需求；若一个业务概念本身由多个特征组成，应先由特征领域形成一个复合特征类型，再作为需求的唯一目标特征，不在需求中保存多条件组。

需求不等于任务、方法、状态、动态、执行过程、结果或永久满足结论。一个任务恰好对应一个需求；每个正式需求最终必须且只能对应一个正式任务身份。任务终结或需求当前已满足都不释放该关联，也不得为同一需求另建第二个任务。

## 2. 需求结构全集

所有需求共同字段：

| 字段 | 基数 | 含义 |
| --- | --- | --- |
| 目标存在 | 恰一 | 目标特征所属的存在；场景具有存在身份，可以作为目标存在。 |
| 目标特征类型 | 恰一 | 需要改变或保持的唯一特征类型根概念。 |
| 目标形式 | 恰一 | `值`或`变化方向`。 |
| 目标值域 | 值目标恰一 | 目标特征应满足的值或值域概念。 |
| 目标比较关系 | 值目标恰一 | 当前值与目标值域怎样构成满足。 |
| 目标变化方向 | 方向目标恰一 | `增加`或`减少`。 |
| 权重 | 恰一 | 非负治理份额。 |
| 活动状态 | 恰一 | 活动、等待、已满足或失活。 |

目标形式必须严格二选一：

```text
值目标：有目标值域和目标比较关系，无目标变化方向
方向目标：有目标变化方向，无目标值域和目标比较关系
```

同时提供两种载荷、两种载荷都缺失、方向枚举非法或值目标合同不完整，均在写入前拒绝且零需求结构写入。

普通需求额外保存恰一父需求及合法来源。本能定义代码可以建立固定初始子需求；任务在筹办或执行中发现的新需求必须绑定来源任务。来源只解释为什么产生，不改变需求目标身份。

双根额外保存根角色；根没有父需求和来源。根同样必须保存目标存在和完整目标，不能再保存根专用“实际特征节点”。

## 3. 独立需求树与列表

需求树具有独立全局根，不属于世界树。安全根和服务根是需求树下两个长期根需求；它们的目标存在都是唯一自我，目标特征分别是自我安全值和自我服务值，目标形式都是值目标，目标固定为`INT64_MAX`。

需求树的父子关系表达目标分解。每个普通需求恰有一个父需求，父链无环并最终到达安全根或服务根。

需求列表是按完整目标键形成的查重和查询投影，不是第二事实账。完整目标键为：

```text
目标存在
+ 目标特征类型
+ 目标形式
+ 该形式的完整载荷
```

父路径和来源不进入列表键；同一完整目标可因父路径或来源不同形成不同需求节点，并进入同一列表项。列表项不能替代成员需求的父关系、来源、权重和活动状态。

正式需求数量只计算安全根、服务根及从双根父子链可达的全部普通需求；不计算需求树组织根、需求列表项、目标值域、来源节点、任务、评估或结算。需求owner必须提供结构化全集查询：从互异双根迭代遍历，逐节点完整读回，检查父回指、环、跨根重复、多父、坏子边和孤立需求类型节点；只有完整成功才返回按稳定编码排序去重的全集和可由其大小得到的数量。尚未初始化、结构不一致与资源失败不得折算为空集合。

需求与任务属于不同owner，建立需求后允许在消息交接完成前出现短暂数量差；该差异只能触发self的任务关联补齐，不形成第二需求账或第二任务账。

## 4. 双根

安全根和服务根共同建立或共同失败。重复调用只有在两个根的根角色、目标存在、完整目标和初始权重均与既有定义一致时返回`已复用`。

根的实际特征每次按`目标存在 + 目标特征类型`fresh定位，不保存第二个根专用定位字段。目标存在内同类型实例特征缺失返回`目标特征尚未形成`，多于一个返回`结构不一致`。

安全值和服务值都是唯一自我持有的非负I64实例特征。两个类型根、两个实例特征和两个需求根身份必须互异。首次当前值为`INT64_MAX / 2`，目标为`INT64_MAX`。

## 5. 普通需求准入

建立普通需求前必须确认：

1. 父需求存在且结构完整；
2. 目标存在是合法存在节点；
3. 目标特征类型是合法特征类型根；
4. 目标形式及其载荷严格二选一；
5. 值目标的值域属于该类型根，比较关系适用于该值域；
6. 方向目标只使用合法增加或减少方向；
7. 来源符合本能固定定义或任务子目标合同；
8. 新父子边不会形成环。

满足完整目标、父需求和来源均相同的重投必须精确复用；同键多列表项、同父同来源多成员或任何读回复义返回`结构不一致`。

## 6. 当前复核

### 6.1 共同定位

每次复核都从目标存在fresh读取特征组，并按目标特征类型根定位唯一实际特征。不得保存或消费根专用实际特征、旧快照、状态后态、动态后态、任务结果或最后一次结算代替当前实例特征。

### 6.2 值目标

值目标fresh读取实际特征当前值并按目标值域及比较关系裁决：

```text
已满足
需增加
需减少
未满足但无有向差值
不可比较或结构化非成功
```

I64准确差异为`目标边界 - 当前值`，溢出时饱和到`INT64_MAX/INT64_MIN`。双根只允许`已满足`或`需增加`；出现需减少是根定义或数据错误。

### 6.3 方向目标

方向目标不能由一个current-only当前值判定。`复核当前满足(D)`只负责确认目标存在、实际特征和动作前当前值可取得，然后返回`需要执行前后比较`。

真正裁决必须绑定同一个任务执行实例：

```text
A = 动作执行前冻结的目标特征准确值
B = 结果获取渠道观察到的同一目标特征准确值
比较(B, A)
```

增加要求有向差值大于0，减少要求有向差值小于0。A/B、执行实例、结果渠道、观察状态和归因属于任务执行及影响评估，不写入需求节点。缺少A、B、合法比较或执行绑定时不得宣称方向目标满足。

## 7. 权重与活动状态

双根权重由具名配置分别提供且必须非负。普通需求权重只由父需求分配：父权重在非失活直接子需求间平分，余数按稳定编码升序依次加一；失活子需求权重为0。权重递归传递。

活动、等待、已满足和失活是治理状态，不是永久世界事实。值目标下次使用仍须fresh复核；方向目标的某次执行满足只证明该次方向变化，不能形成永久单点满足事实。

任务完成、需求满足、任务完成结算、需求结算以及安全值/服务值变化互不替代。收束任务后来仍需治理时，由self复核后请求重新启用原任务。

## 8. 查询

公开查询至少包括：

```cpp
std::optional<新需求信息> 获取需求(...) const noexcept;
std::optional<新需求列表项信息> 获取需求列表项(...) const noexcept;
std::optional<稳定编码> 查询根需求(...) const noexcept;
新需求全集结果 查询全部需求() const noexcept;
std::vector<稳定编码> 查询直接子需求(...) const noexcept;
std::vector<稳定编码> 查询目标存在需求(...) const noexcept;
新需求精确查询结果 按完整目标查询(...) const noexcept;
新需求当前满足结果 复核当前满足(...) const noexcept;
std::optional<std::int64_t> 查询需求权重(...) const noexcept;
bool 是需求节点(...) const noexcept;
```

查询结果按稳定编码排序并去重。空集合不能代替结构化内部错误。

## 9. 生命周期、失败与发布

需求身份和核心目标建立后持续存在；当前不提供删除、原地改目标或重挂父需求入口。目标改变应形成另一个需求或由上层明确结束旧需求。

至少区分：尚未初始化、需求/父需求不存在、目标存在不合法、目标形式不合法、目标特征类型不合法、目标值域不合法、比较关系不合法、目标方向不合法、双根定义冲突、任务来源未接通、形成环、权重不合法、结构不一致和资源失败。

基础数据集不提供跨多个调用的事务。实现必须在发布前完整读回；失败时尽力回滚本次半结构，回滚失败返回`结构不一致`，不得返回成功。

## 10. 最低验证

- 双根共同建立、失败回滚和同定义复用；
- 全集查询覆盖双根、普通子需求、环/重复/多父/孤立节点和结构化非成功；
- 每个正式需求最终取得唯一任务身份，终结任务复用而不另建；
- 双根都保存目标存在和完整值目标，且无根实际特征字段；
- 值目标和方向目标分别建立、复用、列表查询和完整读回；
- 两种载荷同时存在或同时缺失时零写拒绝；
- 目标存在查询与完整目标查重；
- 值目标fresh满足、需增、需减、不可比较和I64饱和差；
- 方向目标单点复核不得伪造满足；
- 同一执行实例A/B对增加与减少方向的通过、不通过和缺材料；
- 任务候选材料完整保存并读回目标形式；
- 子需求权重平分、失活重算和父链无环；
- Debug/Release全工程构建与生产初始化读回。

规范发布、构建通过或局部运行均不单独证明完整内部治理业务闭环。
