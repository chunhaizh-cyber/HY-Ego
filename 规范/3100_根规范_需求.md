# 3100 根规范 需求

编号：3100
日期：20261103
版本：v4.10
状态：正式根规范

直接依赖规范：0050、1130、1140、1160、7160。
详细合同：5170。

## 1. 定义

普通需求表达某个需求主体希望目标存在的一种目标特征达到目标值或按指定方向变化。自我执行需求是自我的治理目标；服务对象的被认知需求是自我理解并记录的对方需求，不自动成为自我治理目标。

```text
普通需求 = 需求主体的期望
         + 目标存在
         + 一个目标特征类型
         +（目标值/值域及比较关系，或目标变化方向）
```

另有具名专属种类**词条归类**：目标为正式词条身份，满足条件为概念名称关系挂到存在／特征／动态根树概念；不走上列「目标存在＋目标特征类型＋特征值」形状。准入、查重键、复核见第3节／第5.1节／第6.4节及5170、LANGUAGE-LEMMA-CLASSIFY。双根仍属初始化例外，必须保存目标存在与完整值目标，不适用词条归类形状。

另有具名专属种类**原文范围分界澄清**：目标为固定原文材料及指定范围，保留其来源出现定位；满足条件为语言领域正式保存并可当前读回该目标的有效分界结果。它不是词条归类、指代消解或普通存在特征目标，不先造词条、指代实例或布尔镜像特征。准入和复核见第5.2、6.5节，材料合同见7230第2.4节。

需求保存需求主体及执行域（自我执行、被认知），普通需求不得用目标存在代替主体。例如某人需要水达到某温度，主体是该人，目标存在是水。服务对象没有需求树，只有一个需求特征保存当前单D引用与历史D；新D或已满足D明确再次需要时产生新的正式需求发生S，同D不复制。准入、来源及发布由5170展开。

需求作为服务对象的特征时直接引用独立D，不取消D身份和内容；当前单D、历史D、主体挂接及引用保护统一按[1130第3.1、3.2节](1130_根规范_特征节点_20260720.md#31-方法需求任务的信息引用型特征)及7160第5.1节。引用及新S不自动改变需求主体、执行域或树归属，不自动建立任务、承接或满足需求；D内容仍由需求owner发布。H侧同D的新发生与self需求来源身份分别判定，不以相同H D代替self来源查重。

一个普通需求只针对一个目标特征类型。自我执行域的多个特征目标通过父子需求分解；被认知多特征内容按单特征记录或已形成的复合特征表达，不为此建立对方父子需求树。复合特征必须先由特征领域形成，不在需求内保存多条件组或临时伪造复合类型；专属种类按各自具名目标，不放宽普通形状。

需求不等于任务、方法、状态、动态、执行过程、结果或永久满足结论。一个任务恰好对应一个自我执行需求；每个自我执行需求最终必须且只能对应一个正式任务身份。任务终结或需求当前已满足都不释放该关联。被认知需求不自动配任务；自我承接后另建或复用自我需求并关联对方原需求，不改其主体，不把对方节点挂成自我子需求。

## 2. 需求结构全集

所有需求共同字段：

| 字段 | 基数 | 含义 |
| --- | --- | --- |
| 需求主体 | 恰一 | 需求属于哪个存在；与普通目标存在、目标词条及分界目标来源分别表达。 |
| 执行域 | 恰一 | 自我执行或被认知；后者不取得任务承接资格。 |
| 需求种类 | 恰一 | `普通`、`词条归类`或`原文范围分界澄清`；缺省旧普通请求仍按普通解释，不把未知种类降为普通。 |
| 目标存在 | 普通恰一 | 目标特征所属的存在；场景具有存在身份，可以作为目标存在。专属种类不适用。 |
| 目标词条 | 词条归类恰一 | 待归类正式词条身份。普通种类不适用。 |
| 目标来源出现定位 | 分界澄清恰一 | 合法语言来源／接收消息及固定原理解根范围、出现路径；不依赖将来的完整含义U或需求D。 |
| 目标固定文本材料与范围 | 分界澄清恰一 | 固定文本材料引用及非空Unicode标量半开范围，位于原来源内；不以词条或正文哈希替代身份。 |
| 目标特征类型 | 普通恰一 | 需要改变或保持的唯一特征类型根概念。专属种类不适用。 |
| 目标形式 | 普通恰一 | `值`或`变化方向`。专属种类不携带普通值／方向载荷。 |
| 目标值域 | 普通值目标恰一 | 目标特征应满足的值或值域概念。 |
| 目标比较关系 | 普通值目标恰一 | 当前值与目标值域怎样构成满足。 |
| 目标变化方向 | 普通方向目标恰一 | `增加`或`减少`。 |
| 权重 | 恰一 | 非负治理份额。 |
| 活动状态 | 恰一 | 活动、等待、已满足或失活。 |

普通需求目标形式必须严格二选一：

```text
值目标：有目标值域和目标比较关系，无目标变化方向
方向目标：有目标变化方向，无目标值域和目标比较关系
```

同时提供两种载荷、两种载荷都缺失、方向枚举非法或值目标合同不完整，均在写入前拒绝且零需求结构写入。

上述「目标形式恰一、值/方向二选一、两载荷都缺或混用写入前拒绝」只约束**准备发布到服务对象需求特征的完整需求**。字段补齐发生在单D引用发布之前：服务对象侧字段不足时，不在本根规范另立「待完善」独立活动状态；按[5170第2.1节](5170_子规范_需求治理详细合同.md#21-服务对象的被认知需求与需求特征)，由「获取服务对象需求信息」经通用筹办提出补问子需求交自我确认（该子需求本身是完整需求），父方法不执行。待完善的被认知需求本身不进自我执行树、不发布为F当前引用、不建任务；新需求发生S不放宽该完整性准入。

除双根外，各种类自我执行需求额外保存恰一父需求及合法来源。本能定义代码可以建立固定初始子需求；任务发现的新自我子需求必须绑定来源任务。治理来源只解释为什么产生，不改变目标身份；分界目标自身的语言来源出现定位另按第3节保留。被认知需求保留理解及内容确认来源，不分配自我父需求、任务或父级权重。

双根额外保存根角色；根没有父需求和来源。双根是初始化例外：必须保存目标存在和完整值目标，不能再保存根专用“实际特征节点”，也不得改用任一专属目标形状。词条归类、原文范围分界澄清各有具名专属合同，不与双根混用。

## 3. 独立需求树与列表

本节及第4—7节的双根、父链、权重和任务治理仅针对自我执行域。被认知记录与自我执行树、列表及任务全集隔离；统一记录查询可以覆盖两域，但不得拿记录总数核对自我任务数量。

需求树具有独立全局根，不属于世界树。安全根和服务根是需求树下两个长期根需求；它们的目标存在都是唯一自我，目标特征分别是自我安全值和自我服务值，目标形式都是值目标，目标固定为`INT64_MAX`。

需求树的父子关系表达目标分解。除双根外，每个自我执行需求（包括已批准的专属种类）恰有一个父需求，父链无环并最终到达安全根或服务根。

需求列表是按完整目标键形成的查重和查询投影，不是第二事实账。完整目标键按需求种类分支：

```text
普通种类：
  种类(=普通)
  + 目标存在
  + 目标特征类型
  + 目标形式
  + 该形式的完整载荷

词条归类种类：
  种类(=词条归类)
  + 目标词条

原文范围分界澄清种类：
  种类(=原文范围分界澄清)
  + 来源出现定位
  + 固定文本材料身份
  + 待分界标量范围[start,end)
```

不同种类不得共用同一列表键空间；不得把词条或语言材料编码进普通「目标存在」槽冒充查重。父需求路径和治理来源任务不进入列表键；分界目标的语言来源出现定位是被处理对象身份，不是可省略的治理来源。语言选择从同来源正式读回一致，解释版本／U／后续D不进入分界目标键；同材料在不同消息／出现复用不合并，同源重新解释不改变问题键。相同完整目标仍可因父需求或治理来源不同形成不同D并进入同列表项，不取消原父关系、权重和活动状态。

自我执行需求数量只计算安全根、服务根及从双根父子链可达的全部自我执行需求，包括已批准的专属种类；不计算被认知需求、组织根、列表项、目标值域、来源节点、任务、评估或结算。需求owner必须提供结构化全集查询：从互异双根迭代遍历，逐节点按种类完整读回，检查父回指、环、跨根重复、多父、坏子边和孤立自我执行域需求节点；只有完整成功才返回按稳定编码排序去重的全集和数量。尚未初始化、结构不一致与资源失败不得折算为空集合。

需求与任务属于不同owner，建立需求后允许在消息交接完成前出现短暂数量差；该差异只能触发self的任务关联补齐，不形成第二需求账或第二任务账。

### 3.1 需求类别与结算父链

内部治理需求与外部需求按直接目标存在和目标特征的正式语义归属区分，不按根角色、任务名称、调用线程或最终受益对象猜测。针对任务/方法虚拟存在及自我安全值、服务值等内部治理特征的目标属于内部治理需求；以外部存在特征改变或保持为直接目标的属于外部需求。

服务需求派生链中的外部需求均属于服务需求，包括服务准备需求；内部治理需求仍是正式需求树成员，但不因位于服务根下而成为有固有服务贡献的叶子。安全根下的外部需求不因此自动改归服务。服务需求列表作为查询投影可以汇总服务及其准备需求，但其总数不能直接当作新增已确认人类要求数量或服务值。

任务的直接父子关系由需求的直接父子关系和D-T唯一关联确定，结算沿此关系逐级交接，不另设独立父树。服务贡献计值唯一读取6190，任务完成与交接读取3200、5260；需求权重不因结算值改变。

## 4. 双根

安全根和服务根共同建立或共同失败。重复调用只有在两个根的根角色、目标存在、完整目标和初始权重均与既有定义一致时返回`已复用`。双根种类固定为普通值目标，不适用词条归类或分界澄清专属例外。

根的实际特征每次按`目标存在 + 目标特征类型`fresh定位，不保存第二个根专用定位字段。目标存在内同类型实例特征缺失返回`目标特征尚未形成`，多于一个返回`结构不一致`。

安全值和服务值都是唯一自我持有的非负I64实例特征。两个类型根、两个实例特征和两个需求根身份必须互异。首次当前值为`INT64_MAX / 2`，目标为`INT64_MAX`。

## 5. 普通需求准入

建立普通需求前必须确认：

1. 父需求存在且结构完整；
2. 目标存在是合法存在节点；
3. 目标特征类型是合法特征类型根；
4. 目标形式及其载荷严格二选一；
5. 值目标的值域属于该类型根，比较关系适用于该值域；
6. 方向目标只使用合法增加或减少方向；
7. 来源符合本能固定定义或任务子目标合同；
8. 新父子边不会形成环。

满足完整目标、父需求和来源均相同的重投必须精确复用；同键多列表项、同父同来源多成员或任何读回复义返回`结构不一致`。

### 5.1 词条归类需求专属例外（20261102）

自然语言学习产生的**词条归类**完整需求是具名专属种类，**不**适用本节第2–6项的普通存在／特征／值域／方向校验。其准入改为：

1. 父需求存在且结构完整；来源合法；新父子边无环（仍适用第1、7、8项）；
2. 需求种类标记为词条归类；
3. 目标为合法**词条身份**（世界节点族之外的词条族；身份不转换为存在）；
4. 满足条件合同为「该词条经概念名称关系挂到存在／特征／动态根树下某概念」——详见[LANGUAGE-LEMMA-CLASSIFY](详细设计/20261102_LANGUAGE-LEMMA-CLASSIFY_词条归类学习与本能详细设计_v0.1.md) §2.1 与 5170；
5. 完整键／查重键为`种类(=词条归类) + 目标词条`（见第3节）。

禁止：把词条伪装成普通存在；为此新建虚拟存在或布尔镜像特征；放宽全部普通需求校验；把本种类套用双根初始化例外。除本种类外，普通需求准入不变。

### 5.2 原文范围分界澄清需求专属例外（20261103）

本种类用于自我理解语言材料所需的分界，不把服务对象原话直接当作自我已承接的服务需求。父需求、合法治理来源、父链无环、自我确认和D-T唯一关联沿既有合同；目标载荷替换普通准入第2—6项：

1. 目标来源出现及固定文本材料可读，原理解根范围和待分界范围非空、包含关系合法；出现路径按固定来源定位，根出现可用空路径，不由候选或数组首项猜定。
2. 完整键为第3节分界键，来源中的语言选择与原文一致；不要求词条、已确定边界结果、完整含义U或待完善D已经存在。
3. 不混入普通值／方向字段、目标词条或指代实例。目标载荷完整不代表该范围已经理解，也不将待完善的被认知材料直接送入任务链。
4. 同父、同治理来源、同完整键复用原需求；重新解释不因新U再建本问题需求。已有待完善D的关联继续使用原D，没有D时不伪造一个。

结构写入归需求owner，分界材料写入归语言owner；问句生成、发送、回答采纳和正式结果读回分别有完成边界。具体闭环由5170及CREATE-FROM-FRAGMENT展开，本条不宣称相应公开API已经实现。

## 6. 当前复核

本节先按需求种类分派；普通需求适用6.1—6.3，词条归类适用6.4，原文范围分界澄清适用6.5，不把专属目标缺少普通FT解释为结构损坏。

### 6.1 普通需求共同定位

每次复核都从目标存在fresh读取特征组，并按目标特征类型根定位唯一实际特征。不得保存或消费根专用实际特征、旧快照、状态后态、动态后态、任务结果或最后一次结算代替当前实例特征。

### 6.2 值目标

值目标fresh读取实际特征当前值并按目标值域及比较关系裁决：

```text
已满足
需增加
需减少
未满足但无有向差值
不可比较或结构化非成功
```

I64准确差异为`目标边界 - 当前值`，溢出时饱和到`INT64_MAX/INT64_MIN`。双根只允许`已满足`或`需增加`；出现需减少是根定义或数据错误。

### 6.3 方向目标

方向目标不能由一个current-only当前值判定。`复核当前满足(D)`只负责确认目标存在、实际特征和动作前当前值可取得，然后返回`需要执行前后比较`。

真正裁决必须绑定同一个任务执行实例：

```text
A = 动作执行前冻结的目标特征准确值
B = 结果获取渠道观察到的同一目标特征准确值
比较(B, A)
```

增加要求有向差值大于0，减少要求有向差值小于0。A/B、执行实例、结果渠道、观察状态和归因属于任务执行及影响评估，不写入需求节点。缺少A、B、合法比较或执行绑定时不得宣称方向目标满足。

### 6.4 词条归类需求复核

词条归类种类的`复核当前满足(D)`**不**从目标存在读取特征组，**不**定位实例特征当前值。每次复核必须 fresh 读取目标词条上的概念名称关系：存在合格当前挂接则`已满足`，否则`未满足`或结构化非成功（端点缺失、仅历史关系、读回失败等）。不得用建立时快照或镜像特征代替。细则见 LANGUAGE-LEMMA-CLASSIFY §2.1。

### 6.5 原文范围分界澄清需求复核

每次通过语言领域正式读口按完整目标定位读取当前有效分界结果。没有结果、尚无充分分界依据或仅有未采用的多候选时为未满足；正式读回的有效结果与来源、材料及范围一致，且能够确定本范围的有序分界时才为已满足。收到回复、发问成功、候选唯一、任务消息或建词条回执都不替代结果。

结果字段及采用唯一性由7230第2.4节规定；异常读取、损坏引用和资源故障不得伪装未满足或前提变化。满足只说明本范围分界已经确定，不证明词义、整句理解、需求内容完整或自我承接。

## 7. 权重与活动状态

双根权重由具名配置分别提供且必须非负。非根自我执行需求（包括已批准的专属种类）权重只由父需求分配：父权重在非失活直接子需求间平分，余数按稳定编码升序依次加一；失活子需求权重为0。权重递归传递。

活动、等待、已满足和失活是治理状态，不是永久世界事实。值目标及专属目标下次使用仍须按各自合同fresh复核；方向目标的某次执行满足只证明该次方向变化，不能形成永久单点满足事实。

任务完成、需求满足、任务完成结算、需求结算以及安全值/服务值变化互不替代。收束任务后来仍需治理时，由self复核后请求重新启用原任务。

## 8. 查询

公开查询至少包括：

```cpp
std::optional<新需求信息> 获取需求(...) const noexcept;
std::optional<新需求列表项信息> 获取需求列表项(...) const noexcept;
std::optional<稳定编码> 查询根需求(...) const noexcept;
新需求全集结果 查询全部需求() const noexcept;
std::vector<稳定编码> 查询直接子需求(...) const noexcept;
std::vector<稳定编码> 查询目标存在需求(...) const noexcept;           // 仅普通种类；旧接口保持
新需求精确查询结果 按完整目标查询(...) const noexcept;               // 按种类分派完整键；旧普通键调用保持
std::vector<稳定编码> 查询目标词条需求(...) const noexcept;           // 词条归类新增
新需求当前满足结果 复核当前满足(...) const noexcept;
std::optional<std::int64_t> 查询需求权重(...) const noexcept;
bool 是需求节点(...) const noexcept;
```

`新需求信息`／列表项须可读出**需求种类**；旧普通请求缺省行为仍为普通，但专属种类必须被消费者显式识别，不识别时拒绝或停用受影响路径，不能按缺省降为普通。`查询目标存在需求`与既有普通`按完整目标查询`签名与语义保持不变，不得因专属种类改写其过滤或键。查询结果按稳定编码排序并去重。空集合不能代替结构化内部错误。

分界种类的完整查询／信息读取须返回目标来源出现、固定文本材料及范围，并按第3节完整键查询；不进入普通目标存在或词条查询的结果集。具体新增强类型声明由实施计划冻结，旧消费者不得把本种类降为普通或词条归类。

## 9. 生命周期、失败与发布

需求身份和核心目标建立后持续存在；当前不提供删除、原地改目标或重挂父需求入口。目标改变应形成另一个需求或由上层明确结束旧需求。

至少区分：尚未初始化、需求/父需求不存在、目标存在不合法、目标形式不合法、目标特征类型不合法、目标值域不合法、比较关系不合法、目标方向不合法、双根定义冲突、任务来源未接通、形成环、权重不合法、结构不一致和资源失败。

跨多个独立调用不保证事务；同次结构发布按4015采用组合变化及预期核验。被认知需求已建立但未加入对象需求特征时，不宣称集合目标完成；保留可追溯记录，通过原来源复用重试，不伪造已发布或盲目重复建立。

## 10. 最低验证

- 双根共同建立、失败回滚和同定义复用；
- 全集查询覆盖双根、普通及已批准专属子需求、环/重复/多父/孤立节点和结构化非成功；
- 每个自我执行需求最终取得唯一任务身份，终结任务复用而不另建；被认知需求不进入任务扫描；
- 主体与目标存在不同、对方无需求树、集合引用及承接后保留原主体；
- 双根都保存目标存在和完整值目标，且无根实际特征字段；
- 值目标和方向目标分别建立、复用、列表查询和完整读回；
- 普通种类的值／方向载荷同时存在或同时缺失时零写拒绝；专属种类按各自完整目标，不按普通载荷拒绝；
- 目标存在查询与普通完整目标查重；词条归类按「种类+词条」查重；种类标记可读；旧查询接口语义不变；
- 双根仍为存在+值目标初始化例外，与词条归类／分界澄清例外分列；
- 分界目标按来源出现、固定材料和标量范围查重；同材料不同消息不合并，重解析不换问题键或已有D；分界未定不伪造词条、普通FT或指代实例；
- 分界结果fresh满足、未答／候选未定保持未满足，错误读回不降为业务否定；满足不冒充词义、完整需求或承接；
- 值目标fresh满足、需增、需减、不可比较和I64饱和差；
- 方向目标单点复核不得伪造满足；
- 同一执行实例A/B对增加与减少方向的通过、不通过和缺材料；
- 任务候选材料完整保存并读回目标形式；
- 子需求权重平分、失活重算和父链无环；
- Debug/Release全工程构建与生产初始化读回。

规范发布、构建通过或局部运行均不单独证明完整内部治理业务闭环。
