## 1. 权威边界

本规范是需求树、需求目标、权重和当前满足复核的现行机器合同。需求属于ARCH-L4业务治理，与世界树共用同一个基础数据集和稳定编码空间，但拥有独立需求树根；需求节点不挂入世界树。

需求读取统一采用current-only fresh读回，不再使用事实截止、历史投影或规则版本证明。准确差异是有符号I64：正数表示需增加，负数表示需减少，溢出以`INT64_MAX`或`INT64_MIN`饱和表示。普通需求权重由非失活直接子需求平分父权重。

规范正式成立不自动证明普通需求来源接线、持久恢复、生产装配或旧需求迁移已经完成。

## 2. 对象定位

需求表示一个存在希望某个目标宿主发生或保持一个确定目标状态改变的目标契约。需求不等于任务、方法、执行过程、状态、动态、消息、结果或永久满足结论。

普通需求的核心契约为：

```text
所属存在
+ 目标宿主
+ 一个目标状态条件组
+ 条件组的显式组合关系
```

其中：

- `所属存在`回答“这是谁的需求”；
- `目标宿主`回答“希望改变或保持谁”；
- 每个目标状态条件由特征类型概念、目标值域概念和目标比较关系概念组成；
- 条件组的显式组合关系回答多个条件怎样共同构成同一个复合目标状态。

一个需求只表达一个目标状态改变，但该目标状态可以包含一个或多个特征条件。只有一项条件时组合关系可以省略；多项条件时必须显式提供组合关系，不得默认解释为AND、OR或任意其它关系。一个任务只对应一个需求。

## 3. 独立需求树

全局基础数据集中保存：

```cpp
稳定编码 需求树根节点;
稳定编码 安全根需求节点;
稳定编码 服务根需求节点;
```

组织规则：

1. 需求树根只负责组织需求和需求列表项，不是世界场景或存在。
2. 安全根和服务根是两个独立需求节点，父为空。
3. 普通需求必须具有一个直接父需求。
4. 一个普通需求只能有一个直接父需求，父子关系不得形成环。
5. 每个普通需求的父链必须最终回溯到安全根或服务根之一。
6. 安全树和服务树不得相互反挂。

当前代码已经建立需求树物理根、双根登记字段和父子查询结构；由于普通需求尚不能发布，第3至第6项的运行闭环尚未形成可达验证。

## 4. 双根初始化例外

安全根和服务根不属于任何世界存在，也没有目标宿主、父需求或任务来源承接字段。安全根引用自我内部的安全实例特征；服务根引用6190定义的唯一服务值治理账户。服务值账户以唯一自我为语义主体，但不是自我存在持有的实例特征。

根定义为：

```text
安全根当前来源：自我安全实例特征节点
服务根当前来源：唯一服务值治理账户
两根目标：工程冻结的I64_MAX
两根比较：当前值与目标值的增向比较
两根初始权重：彼此独立的非负I64
```

上述是逻辑定义，不冻结新的C++联合DTO。现有只接受`实际特征节点`的双根初始化ABI不再足以表达服务根，代码实施前必须形成安全特征来源与服务账户来源的强类型物理合同，不得用零节点、伪造F或默认分支兼容。

双根建立要求：

1. 安全实例特征可从唯一自我完整读回，类型与安全目标合同一致。
2. 服务值治理账户可从6190唯一owner完整读回，自我绑定、当前值、目标值、维护时间和规则版本全部成立。
3. 两根目标均为`I64_MAX`，但安全根按实例特征合同解释，服务根按服务账户合同解释；两者不得交叉读取或互相替代。
4. 服务根不得补造服务实例特征、存在当前采用或世界状态来满足旧结构。
5. 两个初始权重均为非负I64；当前没有总和、比例或固定上限要求。
6. 两根当前值均须位于`0..INT64_MAX`，目标固定为`INT64_MAX`；安全目标值域继续由安全特征合同承载，服务目标由工程服务值账户合同承载。

首次调用同时建立两个根需求、两个固定根列表项及需求树根登记。任一侧失败时尽力回滚整次未发布材料，不允许只发布一个根。

重复调用只有在两个根都存在，且安全实例特征、服务值账户、自我绑定、目标、比较关系和初始权重与原定义完全一致时返回`已复用`。活动状态不属于双根不可变定义，后续活动状态变化不阻止同定义读回。

## 5. 普通需求信息

普通需求的完整信息为：

| 信息 | 基数 | 含义 |
| --- | --- | --- |
| 节点 | 恰一 | 需求稳定编码。 |
| 根角色 | 无 | 普通需求不是双根。 |
| 父需求 | 恰一 | 需求树中的直接父需求。 |
| 所属存在 | 恰一 | 拥有该需求的世界存在。 |
| 目标宿主 | 恰一 | 目标特征所属的存在或场景。 |
| 目标状态条件 | 一到多 | 每项包含根链特征类型概念、同类型目标值域概念和适用的目标比较关系概念。 |
| 条件组合关系 | 条件数大于一时恰一 | 定义多个条件如何组成同一个复合目标状态；不得缺省猜测。 |
| 来源承接 | 恰一 | 正式任务子目标承接节点。 |
| 权重 | 恰一 | 从父需求按活动子需求数量分配。 |
| 活动状态 | 恰一 | 当前治理活动状态。 |

所属存在和目标宿主可以相同，也可以不同。场景具有存在身份，因此可以作为目标宿主。

核心契约和来源建立后不得原地修改。目标语义变化必须建立另一个需求，不能改写旧节点。

- 父需求可完整读回；
- 所属存在和目标宿主都是合法存在节点；
- 每项目标特征类型和目标值域都是合法特征概念；
- 每项目标值域位于所给特征类型根下；

但是，基础数据集“节点存在”不能证明来源节点是task owner发布的正式子目标承接记录。新版任务类尚未提供强类型读取接口，因此当前入口在完成上述核验后固定返回：

## 7. 需求列表

需求列表是需求树的查询和防重投影，不是第二套需求事实。

### 7.1 双根列表项

安全根和服务根分别拥有固定列表项。每个根列表项保存根角色和唯一根需求成员，不使用普通需求聚合键，也不能把两个根合并到同一列表项。

### 7.2 普通需求列表项

普通需求按以下完整键聚合：

```text
所属存在
+ 目标宿主
+ 规范化后的完整目标状态条件组
+ 条件组的显式组合关系
```

一个列表项可以引用多个完整键相同、但父路径或来源承接不同的需求。列表项不覆盖成员自身的父关系、来源、权重或活动状态。

当前`按完整目标查询()`已经实现对需求树根下列表项的唯一精确查询；出现多个相同键列表项视为结构不一致。由于普通需求发布未接通，当前实际可读列表项只有双根固定列表项。

## 8. 活动状态

活动状态封闭为：

```cpp
活动、等待、已满足、失活
```

活动状态是治理状态，不是当前世界满足事实：

- `活动`表示参与当前治理；
- `等待`表示保留需求但暂不推进；
- `已满足`表示上层治理已记录一次满足状态；
- `失活`表示不参与权重分配和当前选择。

读取到`已满足`仍不能代替`复核当前满足()`。世界特征变化后必须重新读取当前值；历史满足、任务完成或活动状态字段都不能证明当前仍满足。

修改活动状态不改变目标合同、父关系、来源或列表成员关系。当前代码在普通需求跨入或退出`失活`时重新分配同父全部子需求权重；`活动`、`等待`、`已满足`之间互换不改变权重参与资格。

当前公开入口也允许修改双根活动状态；双根跨入`失活`不会把根权重清零，也不会触发下级重分配。这是当前代码事实，根失活的上层治理含义仍待自我线程和正式规范裁决。

## 9. 当前满足复核

公开入口：

```cpp
新需求当前满足结果 复核当前满足(
    稳定编码 需求节点) const noexcept;
```

### 9.1 实际特征定位

- 安全根直接使用根定义中的安全实例特征节点。
- 服务根通过6190唯一owner读取已经收敛到本次读取时点的服务值账户当前值；不得从自我实例特征、任务状态、最后一次结算或显示缓存读取。
- 普通需求逐条件从目标宿主的实例特征组中按该条件的目标特征类型根查找。
- 任一条件没有匹配特征返回该条件的`目标特征尚未形成`。
- 同一宿主对同一条件出现多个同类型实例特征返回`结构不一致`。
- 任一实际特征没有当前值返回该条件的`当前值不存在`。

每次调用都重新读取对应权威当前来源：安全根与普通需求读取实例特征当前值，服务根读取服务值治理账户当前值。不保存永久满足布尔值，也不使用状态、动态、任务结果或尚未结算的服务结果代替当前值。

### 9.2 值域定位

I64目标值域由一个或多个闭区间组成：

- 当前值命中任一闭区间：`命中`，准确差异为0；
- 低于全部区间：`低于`，差异为最近下界减当前值；
- 高于全部区间：`高于`，差异为最近上界减当前值；
- 位于两个不相邻区间之间：域外但没有单一方向，不返回准确差异。

I64差异采用饱和减法，溢出时返回`INT64_MAX`或`INT64_MIN`。

非I64目标当前支持：

- 全材料值域：任意同材料当前值均命中；
- 有限枚举值域：按特征值节点身份精确命中；
- 结构化I64值域：所有分量均命中对应闭区间才算命中。

非I64当前只返回命中或域外，不形成有向准确差异。

### 9.3 比较关系和结果

比较关系由二次特征概念的结果域种类表达，当前支持：

```text
小于、小于等于、等于、大于等于、大于、任意、
包含于参照值域、不包含于参照值域、
低于参照值域、高于参照值域
```

任一结果域接受当前位置即返回`已满足`。未满足时综合全部结果域要求形成：

```text
需增加
需减少
未满足但无有向差值
```

多个结果域要求方向冲突时，不任意选择方向。普通需求返回`未满足但无有向差值`。

双根只允许`已满足`或`需增加`作为正常业务结果；若比较得到需减少，返回`双根负差非法`。这表示根目标、当前值、比较关系或绑定结构有问题，不表示“减少根值”本身不可能发生。

### 9.4 复合目标状态组合

普通需求含多个条件时，先逐条件fresh读取并形成各自结果，再按需求保存的显式组合关系合成唯一需求结论。组合关系必须引用已注册、可求值的关系定义；不支持、缺失或产生歧义时返回结构化依赖缺失或结构不一致，不得默认按AND、OR、首项或多数票处理。

一个条件的有向差值只描述该条件，不得直接冒充整个复合状态的单一差值。只有显式组合规则定义了合法的整体方向和合成算法时才可以返回整体方向；否则复合需求未满足时返回`未满足但无有向差值`。

## 10. 权重分配

### 10.1 根权重

安全根和服务根权重由具名运行配置提供，彼此独立，必须非负。只有双根权重允许直接修改：

```cpp
新需求操作状态 修改根需求权重(
    稳定编码 根需求节点,
    std::int64_t 新权重) noexcept;
```

普通需求不能自行指定或直接修改权重。

权重只表示需求树内的相对治理份额，不是读取数量限制、循环次数上限、执行授权或现实资源预算。新版需求节点不保存底层读取预算；读取规模应由上层实际目标和合法查询路径决定。

### 10.2 子需求平分

父需求权重只在其直接非失活子需求之间平分：

```text
基础份额 = 父权重 / 非失活直接子需求数量
余数 = 父权重 % 非失活直接子需求数量
```

子需求按稳定编码升序排列。前`余数`个参与子需求各多得1，其余取得基础份额。失活子需求权重为0。

因此始终满足：

```text
所有非失活直接子需求权重之和 == 父需求权重
```

分配结果递归传到整棵下级需求树。`活动`、`等待`和`已满足`均参加分配，只有`失活`退出。

根权重修改或普通子需求跨入/退出失活状态时，代码先构建整棵受影响子树的权重修改集，再依次写入；写入失败时尽力恢复已修改字段。回滚失败返回`结构不一致`。

当前普通需求无法发布，因此这套子树权重算法已经编码，但尚没有合法普通子需求数据可完成生产路径验证。

## 11. 复合目标状态的逐条件重读

一个任务只承接一个需求。复合目标状态的结果使用和满足判断必须按目标条件逐项fresh读取：

```text
读取需求D的条件C1
-> fresh读取C1目标当前值
-> 判断C1
-> 若结果使用改变了世界事实
-> 读取条件C2时重新fresh读取C2目标当前值
-> 判断C2
-> 依次继续
```

不得用任务开始时的一份旧快照一次性替代全部条件复核，也不得因为前一个条件已经使用了结果，就把旧值直接用于后一个条件。最终按需求保存的显式组合关系合成一个需求满足结论。

当前实现若只支持单条件`复核当前满足()`，只能覆盖单条件需求；多条件目标状态和组合关系属于待实现差距，不能通过让一个任务承接多个需求来绕过。


查询结果按稳定编码排序并去重。当前没有按活动状态、父链全路径、权重范围或当前满足结果建立专用索引。

## 13. 生命周期

需求身份和核心目标合同建立后持续存在。当前新版代码没有需求删除、核心契约修改、重挂父需求或列表成员退出入口。

活动、等待、已满足和失活只改变治理活动状态，不删除需求节点。权重为0也不表示需求不存在或已经结算。

需求当前满足、任务完成、任务生命周期结束和需求正式结算必须分账；当前新版需求类尚未实现正式结算记录。

## 14. 一致性不变量

### 14.1 双根

1. 安全根和服务根必须同时存在或同时不存在。
2. 两个根角色不同，实际特征节点不同。
3. 根需求没有父需求、所属存在、目标宿主和来源承接字段。
4. 每个根恰有一个固定根列表项，列表项只包含该根需求。
5. 根目标特征类型、实际特征类型、目标值域和比较关系相容，目标值域为`INT64_MAX`单值域。

### 14.2 普通需求

1. 恰有一个父需求、所属存在、目标宿主和来源承接。
2. 没有根角色和根实际特征字段。
3. 具有一到多个合法目标状态条件，每项值域属于本项特征类型根，比较关系适用于本项类型和值域。
4. 条件多于一项时恰有一个可读、可求值的显式组合关系。
5. 恰属于一个完整键一致的需求列表项。
6. 父链无环并最终回溯到一个根。
7. 权重等于父级当前分配结果，失活时为0。

当前代码可以读回并检查部分结构，但普通需求尚未发布，因此不能宣称普通需求全部不变量已经运行证明。

## 15. 非成功和发布边界

需求操作区分尚未初始化、需求/父需求不存在、所属存在或目标宿主不合法、特征类型/值域/比较关系不合法、实际特征不合法、双根定义冲突、任务来源未接通、形成环、权重不合法、结构不一致和资源失败。

基础数据集没有组合事务。双根首次建立在返回前尽力回滚半结构；权重批量修改在失败时尽力恢复。当前没有跨进程原子发布、发布未知、原请求恢复或历史读回能力。

空查询结果不能区分“确实无成员”和内部异常；需要强失败语义的调用方应使用结构化结果入口或完整读回交叉核验。
