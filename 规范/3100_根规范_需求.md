## 1. 定义

需求表达某个需求主体希望某个目标信息节点的一种目标特征达到目标值，或按指定方向变化。自我执行需求是自我的治理目标；服务对象的被认知需求是自我理解并记录的对方需求，不自动成为自我治理目标。

```text
需求 = 需求主体的期望
     + 目标信息节点
     + 一个目标特征类型
     +（目标值/值域及比较关系，或目标变化方向）
```

目标信息节点是具有正式身份、由唯一owner维护并可读回的信息节点，包括存在（场景具有存在身份）、词条、语言材料范围、指代实例及其它已登记类型的信息节点。目标信息节点保持自身身份：词条仍是词条，语言材料范围仍是语言材料范围，不为成为需求目标而伪装为存在，也不新建虚拟存在；目标相关的关系以该节点持有的正式F表达，由owner在同一次发布中维护，不是旁路镜像。

目标特征类型一律是正式特征类型，目标与结果统一由目标信息节点持有的实例特征F承载。目标关心的关系也以F表达：例如词条持有“概念名称挂接”F、语言材料范围持有“有效分界结果”F，其当前值由该节点owner在关系变化的同一次组合发布中维护；关系结构与其F不一致属于结构不一致。F的值变化按普通特征生成状态和动态，复核方式与普通特征相同。全部需求采用同一形状，不另设专属需求种类；新增可作为目标的信息类型时，只需其owner为相关字段或关系登记正式特征类型并维护对应F，不修改本形状。

需求保存需求主体及执行域（自我执行、被认知），不得用目标信息节点代替主体。例如某人需要水达到某温度，主体是该人，目标信息节点是水。

一个需求只针对一个目标特征类型。自我执行域的多个特征目标通过父子需求分解；被认知多特征内容按单特征记录或已形成的复合特征表达，不为此建立对方父子需求树。复合特征必须先由特征领域形成，不在需求内保存多条件组或临时伪造复合类型。

需求不等于任务、方法、状态、动态、执行过程、结果或永久满足结论。一个任务恰好对应一个自我执行需求；每个自我执行需求最终必须且只能对应一个正式任务身份，任务终结或需求当前已满足都不释放该关联。被认知需求不自动配任务；自我承接后另建或复用自我需求并关联对方原需求，不改其主体，不把对方节点挂成自我子需求。

## 2. 需求结构

所有需求共同字段：

| 字段 | 基数 | 含义 |
| --- | --- | --- |
| 需求主体 | 恰一 | 需求属于哪个存在；与目标信息节点分别表达。 |
| 执行域 | 恰一 | 自我执行或被认知；后者不取得任务承接资格。 |
| 目标信息节点 | 恰一 | 目标特征所属的正式信息节点及其类型。 |
| 目标特征类型 | 恰一 | 需要改变或保持的唯一正式特征类型；关系型目标也以目标节点持有的F表达。 |
| 目标形式 | 完整需求恰一 | `值`或`变化方向`。 |
| 目标值域 | 值目标恰一 | 目标特征应满足的值或值域概念。 |
| 目标比较关系 | 值目标恰一 | 当前值与目标值域怎样构成满足。 |
| 目标变化方向 | 方向目标恰一 | `增加`或`减少`。 |
| 权重 | 恰一 | 非负治理份额。 |
| 活动状态 | 恰一 | 活动、等待、已满足或失活。 |

完整需求的目标形式严格二选一：

```text
值目标：有目标值域和目标比较关系，无目标变化方向
方向目标：有目标变化方向，无目标值域和目标比较关系
```

同时提供两种载荷、方向枚举非法或值目标合同不完整，均在写入前拒绝且零需求结构写入。

被认知需求允许处于待完善：已取得需求主体、目标信息节点和目标特征类型，但目标形式及其载荷尚未确定（仅特征）。待完善不是拒绝理由，也不是完整需求：它不进入自我执行树，不发布为服务对象需求特征的当前引用，不建任务。字段补齐经任务链补问取得：由合法筹办提出完整的补问子需求，其目标信息节点为该待完善需求D，目标特征为对应字段的“有确定值”F。待完善D建立时，需求owner即为每个必需字段建立“有确定值”F，初值为未确定；字段补齐写回与该F更新在同一次发布中完成，其值变化按普通特征生成状态。读取取得的字段材料由后续治理写回D，需求侧以该F的变化闭合，读取本身不需要另行闭合；经自我确认后由任务“查找方法→采用→执行”推进；自我不直接满足待完善需求。补问流程及服务对象需求特征细则由5170展开。

除双根外，自我执行需求额外保存恰一父需求及合法来源。本能定义代码可以建立固定初始子需求；任务发现的新自我子需求必须绑定来源任务。治理来源只解释为什么产生，不改变目标身份。被认知需求保留理解及内容确认来源，不分配自我父需求、任务或父级权重。

双根额外保存根角色；根没有父需求和来源。双根是初始化例外：目标信息节点为唯一自我，必须保存完整值目标，不保存根专用“实际特征节点”。

## 3. 服务对象的被认知需求

服务对象没有需求树。服务对象以一个需求特征直接引用独立的正式被认知需求D：当前值为单个D，历史保留实际出现过的D；新D出现或已满足D经正式来源明确再次需要时，产生新的正式需求发生状态，同D不复制。引用及需求发生不自动改变需求主体、执行域或树归属，不自动建立任务、承接或满足需求；D内容仍由需求owner发布。服务对象侧的需求发生与自我需求来源身份分别判定。引用合同见1130，准入、来源、发生及发布细则见5170。

## 4. 独立需求树与列表

本节及第5—8节的双根、父链、权重和任务治理仅针对自我执行域。被认知记录与自我执行树、列表及任务全集隔离；统一记录查询可以覆盖两域，但不得拿记录总数核对自我任务数量。

需求树具有独立全局根，组织结构独立，不属于现实世界树；需求作为信息存在在内部治理世界有所属场景，其F变化生成的状态挂入该场景（0050第1.4节）。安全根和服务根是需求树下两个长期根需求；它们的目标信息节点都是唯一自我，目标特征分别是自我安全值和自我服务值，目标形式都是值目标，目标固定为`INT64_MAX`。

需求树的父子关系表达目标分解。除双根外，每个自我执行需求恰有一个父需求，父链无环并最终到达安全根或服务根。

需求列表是按完整目标键形成的查重和查询投影，不是第二事实账。完整目标键为：

```text
目标信息节点（含其类型）
+ 目标特征类型
+ 目标形式
+ 该形式的完整载荷
```

父需求路径和治理来源任务不进入列表键。相同完整目标仍可因父需求或治理来源不同形成不同D并进入同一列表项，不取消原父关系、权重和活动状态。语言材料范围作为目标信息节点时，其来源出现定位属于该节点身份的一部分，由语言owner保证同材料在不同出现中不被合并。

自我执行需求数量只计算安全根、服务根及从双根父子链可达的全部自我执行需求；不计算被认知需求、组织根、列表项、目标值域、来源节点、任务、评估或结算。需求owner必须提供结构化全集查询：从互异双根遍历，逐节点完整读回，检查父回指、环、跨根重复、多父、坏子边和孤立自我执行域需求节点；只有完整成功才返回去重全集和数量。尚未初始化、结构不一致与资源失败不得折算为空集合。

需求与任务属于不同owner，建立需求后允许在消息交接完成前出现短暂数量差；该差异只能触发self的任务关联补齐，不形成第二需求账或第二任务账。

### 4.1 需求类别与结算父链

内部治理需求与外部需求按直接目标信息节点和目标特征的正式语义归属区分，不按根角色、任务名称、调用线程或最终受益对象猜测。针对任务/方法虚拟存在及自我安全值、服务值等内部治理特征的目标属于内部治理需求；以外部存在特征改变或保持为直接目标的属于外部需求。

服务需求派生链中的外部需求均属于服务需求，包括服务准备需求；内部治理需求仍是正式需求树成员，但不因位于服务根下而成为有固有服务贡献的叶子。安全根下的外部需求不因此自动改归服务。服务需求列表作为查询投影可以汇总服务及其准备需求，但其总数不能直接当作新增已确认人类要求数量或服务值。

任务的直接父子关系由需求的直接父子关系和D-T唯一关联确定，结算沿此关系逐级交接，不另设独立父树。服务贡献计值唯一读取6190，任务完成与交接读取3200、5260；需求权重不因结算值改变。

## 5. 双根

安全根和服务根共同建立或共同失败。重复调用只有在两个根的根角色、目标信息节点、完整目标和初始权重均与既有定义一致时返回`已复用`。

根的实际特征每次按`目标信息节点 + 目标特征类型`fresh定位，不保存第二个根专用定位字段。目标存在内同类型实例特征缺失返回`目标特征尚未形成`，多于一个返回`结构不一致`。

安全值是唯一自我持有的非负I64实例特征，取值域`0..INT64_MAX`；服务值是唯一自我持有的有符号I64实例特征，按6190合法结算和衰减，负值合法，不钳零。两个类型根、两个实例特征和两个需求根身份必须互异。两根冷启动首次当前值为`INT64_MAX / 2`，目标为`INT64_MAX`。

## 6. 需求准入

建立自我执行需求前必须确认：

1. 父需求存在且结构完整；
2. 目标信息节点是合法正式信息节点，并可经其owner读回；
3. 目标特征类型是合法特征类型根，包括由该节点owner登记、以F表达的关系型特征类型；
4. 目标形式及其载荷严格二选一；
5. 值目标的值域属于该类型，比较关系适用于该值域；
6. 方向目标只使用合法增加或减少方向，且该类型可按方向比较；
7. 来源符合本能固定定义或任务子目标合同；
8. 新父子边不会形成环。

满足完整目标、父需求和来源均相同的重投必须精确复用；同键多列表项、同父同来源多成员或任何读回异义返回`结构不一致`。

禁止为通过准入而把词条、语言材料或其它信息节点改造成普通存在，禁止新建布尔镜像特征，禁止按需求名称或词面放宽准入。

## 7. 当前复核

### 7.1 共同定位

每次复核都从目标信息节点经其owner fresh读取目标特征类型的当前值。不得保存或消费根专用实际特征、旧快照、状态后态、动态后态、任务结果或最后一次结算代替当前值。目标owner读取异常、引用损坏和资源故障返回结构化非成功，不得伪装为未满足或前提变化。

### 7.2 值目标

值目标fresh读取当前值并按目标值域及比较关系裁决：

```text
已满足
需增加
需减少
未满足但无有向差值
不可比较或结构化非成功
```

I64准确差异为`目标边界 - 当前值`，溢出时饱和到`INT64_MAX/INT64_MIN`。双根只允许`已满足`或`需增加`：服务值为负时`INT64_MAX - current`溢出，按饱和得到差异`INT64_MAX`并返回`需增加`；这是合法业务结果，不是工程故障。出现需减少是根定义或数据错误。

### 7.3 方向目标

方向目标不能由一个当前值判定。复核只负责确认目标信息节点、目标特征和动作前当前值可取得，然后返回`需要执行前后比较`。

真正裁决必须绑定同一个任务执行实例：

```text
A = 动作执行前冻结的目标特征准确值
B = 结果获取渠道观察到的同一目标特征准确值
比较(B, A)
```

增加要求有向差值大于0，减少要求有向差值小于0。A/B、执行实例、结果渠道、观察状态和归因属于任务执行及影响评估，不写入需求节点。缺少A、B、合法比较或执行绑定时不得宣称方向目标满足。

## 8. 权重与活动状态

双根权重由具名配置分别提供且必须非负。非根自我执行需求权重只由父需求分配：父权重在非失活直接子需求间平分，余数按稳定编码升序依次加一；失活子需求权重为0。权重递归传递。

活动、等待、已满足和失活是治理状态，不是永久世界事实。值目标下次使用仍须fresh复核；方向目标的某次执行满足只证明该次方向变化，不能形成永久单点满足事实。

任务完成、需求满足、任务完成结算、需求结算以及安全值/服务值变化互不替代。收束任务后来仍需治理时，由self复核后请求重新启用原任务。

## 9. 生命周期、失败与发布

需求核心目标建立后不原地修改，也不重挂父需求；目标改变应形成另一个需求或由上层明确结束旧需求。

需求按生命周期规则清理：已满足或已失活、对应任务已收束、结算已交接直接父任务，且没有被其它正式事实（子需求、被认知需求关联、因果代表实例、方法学习来源等）引用的叶子自我执行需求，可以连同其任务T及Vt按具名清理规则删除；以后再需要时作为新需求重新建立。双根及仍有子需求的需求不清理。被认知需求在服务对象需求特征当前值或历史仍引用期间不清理。清理阈值与时机由5170规定。

至少区分：尚未初始化、需求/父需求不存在、目标信息节点不合法、目标形式不合法、目标特征类型不合法、目标值域不合法、比较关系不合法、目标方向不合法、双根定义冲突、任务来源未接通、形成环、权重不合法、结构不一致和资源失败。

同次结构发布按4015采用组合变化整体发布。被认知需求已建立但未加入对象需求特征时，保留可追溯记录，通过原来源复用重试，不伪造已发布或盲目重复建立。
