# 1120 根规范 抽象特征

编号：1120
日期：20260907
版本：v0.7
状态：正式根规范

## 1. 根定位

抽象特征是特征类型、值域、叶子或复合形态以及抽象特征结构的权威本体。正式特征类型必须由稳定的特征定义身份及其结构关系表达，不是裸词面、名称词条、名称关系、硬编码枚举或显示文本。

状态抽象统一回到抽象特征结构；不得另建与抽象特征平行的权威抽象状态树。

## 2. 本项目承载

海中鱼巣以“特征定义节点”承载抽象特征：

```text
节点类型为特征的定义节点及稳定句柄
+ 唯一非零稳定主键和当前节点句柄
+ 抽象特征之间的普通结构关系或具名组成关系
+ 值域、模板条件和语义入口的正式关系
+ 用于定位的索引
```

特征定义节点规定“这是什么类型、值如何解释”，1130 的特征信息节点保存“该类型下的当前观察、历史与值域”。二者由正式身份和结构角色区分，可以复用通用特征节点类型，但不互相冒充；特征信息引用类型定义，不以宿主是否存在作为区分。其值域细分子节点仍属于原类型，不因成为子节点而取得类型定义身份。

词条只通过正式概念名称关系充当名称和查找材料；机器判断、需求匹配、方法能力匹配和特征值解释必须回读特征定义节点或目标概念的正式强类型身份。

## 3. 事实与边界

1. 抽象特征可以表达值域、复合组成、抽象上下位关系和状态模板条件。
2. 抽象特征不得承载具体信息节点的当前观察值、业务完成结论、安全或服务画像、运行期评估结果。
3. 叶子与复合形态必须由正式结构关系成立，不得由名称后缀、显示类型或注释推断。
4. 同一词条即使命中一个特征名称，也只证明名称关系成立；特征类型必须从目标概念和特征定义节点读回，不得把词条改成类型入口或在词条上保存类型。
5. 不得新增硬编码“特征类型总枚举”取代特征定义节点；默认初始化可以显式创建定义节点，但结果必须进入正式抽象特征结构。
6. 实例期把多个已经成立的一次特征事实组成一个静态事实集合，不新增抽象类别定义，也不改变成员的特征定义；该结构由 4125 治理。事实集合身份、成员关系或显示名称不得反向冒充抽象特征类型、概念或归类结论。

## 4. 写入、读取与验证

抽象特征只能由特征领域服务创建、绑定和修改；数据操作层在不透明结构写入会话中完成节点、特征域类型化记录、关系和索引的原子发布。特征值服务、高级业务服务、外设、显示层和普通调用方不得直接创建或改写抽象特征。

读取方必须通过特征领域服务取得稳定定义身份、结构关系和值域材料。验证至少回读：节点当前有效、类型为特征、稳定主键唯一、定义角色成立、全部关系端点、领域记录与版本当前。

## 5. 生命周期与当前性

抽象特征身份长期存在；定义内容变化必须保留版本和来源。名称关系变化、词索引重建或显示名称变化不得改变抽象特征身份。定义失效或替换后，引用它的特征信息和历史事实仍须能够回查原定义内容；技术版本与来源按 L1 和正式关联保护，不增加特征信息字段。

## 7. 类型来源与初始化

特征类型分为先天与后天两类。先天特征类型来自外设提供的特征类型，系统初始化时必须给出对应正式定义及值规格、解析和比较方式，包括空间坐标、轮廓、体素等基础类型；不能等普通数据操作时临时猜测。后天特征类型由对先天类型的综合应用形成，并保持可追溯的来源与生成规则。

上述分类属于特征类型定义，不新增特征信息的顶层字段。先天 / 后天说明类型来源，叶子 / 复合说明结构形态，1180 的阶次说明派生关系，三者不得直接互相替代。初始化如何声明规格与规则由 4120 展开。

特征类型的完整允许域与局部特征信息的值域分开。1130 / 4110 的三次命中细分只产生同类型信息子节点，不自动生成后天类型、共享概念或新的类型定义；父域继续保留。
