## 1. S0 与最早缺口

P53只冻结自我结构登记DTO、唯一投影和非阻塞读取，生产写函数为0。若未来登记发布者先提交L1，再在事务外赋值P53投影，会出现L1事实已发布但登记投影未确认或分配失败的可见窗口，也无法和P15发布后同锁读回、失败见证及隔离共同收口。

P37已经冻结业务中性的附属事务参与桥；P38→P39已证明“先有唯一账/读取，再有具体参与者，最后才有领域发布者”是合法依赖方向。自我结构登记同样需要一个具体参与者原位扩展P53投影。本叶因此早于登记业务发布者、完整自我结构规格和完整自我创建。

## 2. 目标与边界

原位扩展唯一`L1自我结构登记数据操作`，新增内部根：

```cpp
自我结构登记附属提交结果 提交带自我结构登记(
    const L1写集请求& 请求,
    const 自我结构登记草案& 草案);
```

该根只把调用方已形成的精确两节点L1写集和登记草案交给P37一次；私有参与者在同一事务内完成P53候选、确认、逆序撤销、同代次发布、P15读回后释放或失败隔离。

本叶不形成L1写集、不计算双摘要、不分配业务幂等身份、不公开发布入口、不创建完整自我、场景或关系，不建立安全/服务定义、实例槽、根值或根需求，不装配运行期、不恢复、不删旧栈。

## 3. 物理位置与依赖

原位修改P53三个目标代码文件；P37真实实现若使用显式friend白名单，只在`海中鱼巣/核心/服务.L1事实基座.ixx`追加`L1自我结构登记数据操作`这一项内部授权，不改公开`提交写集`或桥算法。工程、filters和启动只保持/扩展P53专项，不新增第二模块。

```text
后继自我结构登记发布服务
-> L1自我结构登记数据操作::提交带自我结构登记
   -> 私有自我结构登记参与者
      -> P37 提交写集_内部附属参与（恰一次）

-> P53 读取自我结构登记（签名和七状态保持）
```

参与者不读取L1、SQL、材料、旧系统角色或世界树门面；P37不解释登记字段。

## 5. 草案与写集一一对应

首次路径必须同时成立：

1. 三个合同/格式/规则版本精确为1，世界规则版本和登记身份非零；两个本地键非零且互异；
2. 规范化写集精确为两个新普通节点：服务身份、`自我结构角色`关系类型；节点组之外，关系、值、退出和属性槽变更均为空；
3. 两个本地键在P37映射中各恰一命中，稳定编码非零互异；解析后形成P53完整登记，发布代次等于P37待发布代次；
4. P15通用读回计划精确包含两个新节点的本次发布当前读回，不夹带其它业务对象；
5. P37写前见证的期望代次、幂等键、请求意图摘要和执行证据摘要与传入请求逐字段相等；参与者不重算摘要；
6. P53投影未加载、未隔离、无候选；已加载一律参与者幂等冲突。同键同义必须由P15在参与者调用前短路。

任何遗漏、重复、额外写项、错节点种类、错映射、错代次或坏读回计划均为内部不一致，发布前零普通可读变化。

## 6. 根函数流程

1. 回显登记身份和L1幂等键；只做草案版本/非零字段及L1 v2最小形状检查。
2. 同步栈构造私有参与者，只借用请求、草案和数据操作到本次调用结束。
3. 恰一次调用`L1_.提交写集_内部附属参与(请求, 单参与者span)`；不得先公开提交、不得二次提交。
4. 参与者失败见证无损映射许可拒绝、幂等冲突、资源失败或内部不一致；发布前无登记和映射。
5. 首次成功要求参与者已经发布并释放，返回完整登记、映射、新代次和`L1发布已存在=true`；坏成功为内部不一致。
6. P15精确重复时参与者回调必须0次；函数只读P53投影一次，互证首次L1键、首次意图摘要、登记身份及发布代次，成立才返回精确重复。不得解析本次草案或重算执行证据。
7. 其它L1结果逐类映射；零等待、零重试、零SQL/材料/旧账回源。

私有提交绑定保存首次L1幂等键、首次请求意图摘要和首次执行证据摘要，只供事务同源互证和精确重复收敛，不进入P53公开登记，不成为第二幂等账。

## 7. 私有参与者状态机

```text
已构造 -> 已复核持锁 -> 候选已准备 -> 已确认 -> 已关闭撤销
-> 已发布持锁 -> 已释放
或发布前 -> 已撤销
或撤销失败/发布后矛盾 -> 已隔离释放
```

- `第一写前复核`：核对写前见证；try-lock取得P53投影独占许可；检查未加载、未隔离、无候选。
- `准备候选`：解析两个本地键并逐项核对精确写集/读回计划，预分配完整登记和私有绑定；登记代次使用P37待发布代次。
- `确认待发布`：只核对阶段、候选和锁，切换已确认；`noexcept`。
- `完成撤销`：清空候选/绑定并释放许可；重复撤销幂等；`noexcept`。
- `关闭撤销能力`：只切换阶段；`noexcept`。
- `完成发布并保持许可`：代次精确相等时把候选移动到已发布投影，继续持锁；移动与状态切换必须无分配无失败；`noexcept`。
- `释放已发布许可`：P15同锁读回成功后释放；`noexcept`。
- `完成隔离并释放`：单调隔离，保留已发布证据，不撤销L1，不返回部分登记；`noexcept`。

P53的单项optional投影扩展为私有`候选optional + 已发布optional + 绑定optional + 阶段`；全部可能分配在准备候选阶段完成，最后发布区只做noexcept移动、枚举切换和解锁。P53公开读取签名、七状态、try-lock和深复制保持不变。

## 8. 并发、异常与权限

锁序固定为P37/L1独占域先于P53投影独占许可；普通P53读取只尝试共享许可。候选、已确认和已发布持锁阶段对普通读取均表现为许可拒绝，只有P15读回成功释放后可见。

允许分配/抛出的步骤只有根函数构造、第一写前复核和准备候选；桥捕获后逆序撤销。确认、撤销、关闭撤销、发布、释放、隔离和析构防御均noexcept。关闭撤销后不得出现新分配、失败注入或补写。

P37真实结果若使用显式friend，P54只追加一个精确friend；普通L2、世界树、自我治理和线程不得取得内部提交根、参与者类型或P37见证。
