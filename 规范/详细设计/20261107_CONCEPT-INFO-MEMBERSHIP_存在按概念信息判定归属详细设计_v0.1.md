# 存在按概念信息判定归属详细设计

标识：`CONCEPT-INFO-MEMBERSHIP`；版本：v0.6；日期：2026-11-07；状态：草案，待用户审查（含待裁决项 R-1、R-2）。

依据：
- 用户本窗口裁决（2026-11-07）：
  - 概念节点内部包含成为该概念所必须的信息。
  - 实例只要满足并覆盖概念的全部要求，就属于这个概念；实例可以有更多信息，也可以恰好相同。
  - 概念信息很少或为空时判定很宽，可以接受；人类概念的具体信息以后再完善。
  - 和概念进行比较必须有算法；算法要能把所有存在判为存在，也能把周春海判为人类、父亲或员工。
  - 判定逻辑要统一。
  - “枚举”应叫“概念的实例”。
  - 这个函数实现的是自然语言中“是”这个词的意义。
- 用户审计（2026-11-07，v0.5）五项修正：
  1. 实例关系与定义匹配是两条判定路径，不混为一类；
  2. 不能忽略已知子存在概念组；
  3. 未知不得被布尔接口吞成不属于；
  4. 缺少特征类型与特征没有值等情况要分开；
  5. 递归判定的依据保护要闭合。
- 规范：1140、7100 §3/§5、7110 §5、6120 §11.1。
- 代码基线：main `82f72fa1e`。

## 1. 目标与完成条件

1. **两条判定路径**：概念具有定义信息，并可关联已归属的实例。
   - 实例关系：E 已是 C 的实例。
   - 定义匹配：E 满足并覆盖 C 定义中的全部要求。

   任一路径成立，E 属于 C。
2. **唯一算法**：“存在概念信息比较”（§3）是判定存在属于存在概念的唯一实现。§2 表中全部判定点改为调用它，并逐点规定怎样消费三态结论（§4.2）。
3. **未知不当作否定**：缺少材料、比较能力未支持、递归受限、前提已变化，都不得被任何调用者解释为不属于、分离或冲突。
4. **依据可保护**：需要受保护发布的调用者，可以取得本次判定实际读取的材料保护，包括递归部分。
5. 实际项目编译、链接通过；完成声明只到“已编译、未运行测试”。

不在范围：
- 概念与概念之间的包含（以后再议）；
- 归类写入（7110 上位边）；
- 子存在约束的比较（本版判为未知，§3.2 第 6 步）；
- 建立人类的共同特征、父亲或员工等概念；
- 交互者身份识别等新本能。

## 3. 存在概念信息比较算法

用户裁决（2026-11-07）：**这个函数实现的是自然语言中“是”这个词的意义。** “X 是 Y”中，X 是一个存在、Y 是一个存在概念时，句子的真假就是本算法的结论。两种常见用法分别对应：

- “这个人是周春海”：Y 是某个存在的专属概念，走身份路径（§3.1）；
- “周春海是人类”“他是员工”：Y 是类别概念，走实例关系或定义匹配路径。

本算法的三态也就是“是”的三种回答：是、不是、不能确定（缺什么见依据）。

不在本设计范围的“是”：
- 概念与概念之间的“是”，例如语言初始化里“X 是一种 Y”（`业务/解释.初始化最小结构.cpp:41`），表达的是概念包含；
- 特征类型的“是”，例如“X 是整数”。

语言理解把“X 是 Y”接到本算法，属于后续语言工作，本设计不实现。

### 3.1 两条判定路径

- **实例关系**：E 的专属概念沿上位链能到达 C，即 E 已是 C 的实例。一切存在都是存在根的实例，包括尚无专属概念的零特征存在（1140 第 4 节）。概念已关联的其它实例不是 E 要满足的条件。
- **定义匹配**：C 是抽象概念，E 满足并覆盖 C 定义中的全部要求。本版能比较的要求是特征约束；子存在约束本版不比较，遇到即判为未知（§3.2 第 6 步）。

C 是另一个存在的专属概念时，它代表那个存在的身份，只按身份判定：E 不是那个存在就不属于。没有两个完全相同的存在，特征相同也不是同一身份（7100 §3 第 3 项）。

### 3.2 步骤

输入：存在 E、存在概念 C，以及是否需要依据保护。

输出（§4.1 结果类型）：
- 状态：已完成、入口拒绝或前提已变化；
- 归属：属于、不属于或未知；
- 依据：判定路径，以及按项分开的六组结果（§3.3）；
- 依据保护：需要时提供。

1. **入口**：E 不是存在节点，或 C 不是存在概念：入口拒绝。这是调用者错误，不是业务结论。
2. **实例关系**：C 是存在根，或 E 有专属概念 P 且 C = P 或 C 沿上位链包含 P：属于，判定路径为“实例关系”。
3. **身份**：C 是专属概念（且不是 P）：不属于，判定路径为“身份”。
4. **嵌套防护**：`正式嵌套判定防护(E, C)`。同一线程里同一对 (E, C) 重复出现，或嵌套超过 8 层时：未知，依据为“递归受限”。
5. **取材料**：E 没有专属概念时，E 的特征组按空处理，不调用采集。否则调用 `采集存在概念匹配材料(E, C)`。采集前后材料不一致时，状态为前提已变化，归属为未知。
6. **子存在约束**：C 的定义含子存在约束时，归属最高为未知，依据记入“子存在约束未支持”。当前代码中的定义没有这一组，本版不会出现。概念定义类型增加这一组时，必须同时在这里读取它。
7. **逐项比较特征约束**：对 C 的每一项必需特征（FT, K），结果只记入 §3.3 中的一组：
   1. E 没有类型根为 FT 的顶层特征：缺少特征类型。
   2. E 有该特征，但既无当前值也无实例区间值：材料不足。
   3. 否则按比较规则比较 E 的值与 K 的值域（`比较捕获特征值域`）：

      | 比较规则 | 做法 |
      | --- | --- |
      | I64 数值 | E 的值（单点或实例区间）与 K 的 I64 值域求关系 |
      | 完整材料精确 | 按材料身份与 K 的值域求关系 |
      | 存在身份精确（K 为存在引用值域） | E 的值是存在 X，对 (X, K 的存在概念) **递归调用本算法**：属于为满足；不属于为冲突；未知为递归未能判定 |
      | 存在集合身份判等（K 为存在集合值域） | E 的值是存在集合 S。按 K 的四项约束判定：必含存在节点组 ⊆ S；“至少一个存在”时 S 非空；含概念成员组中每个概念至少有一个 S 成员属于它；全部属于概念组中每个概念都包含 S 的全部成员。成员归属**递归调用本算法**，复用 `核验概念成员项`。成立为满足；不成立为冲突；未能判定为递归未能判定 |
      | 其它集合身份判等（服务任务、需求、消息） | 只支持 K 为全材料值域且 E 为空集合：满足；其余为比较未支持 |
      | 信息引用身份精确及其余 | 比较未支持 |

   4. 相等或“K 包含 E 的值”：满足。
   5. 分离，或 E 有当前值而关系为相交、E 包含 K：冲突。
   6. E 只有实例区间值，而关系为相交、E 包含 K：材料不足。
   7. 类型或单位不相容、规则不支持：比较未支持。
8. **合取**：
   - 有冲突项：不属于。
   - 否则有缺少特征类型、材料不足、比较未支持、递归未能判定或子存在约束未支持中的任何一项：未知。
   - 否则（包括 C 没有任何要求）：属于。

### 3.3 依据分组

| 组 | 含义 | 可否当作否定 |
| --- | --- | --- |
| 冲突特征类型组 | E 的值与要求明确不符 | 是（唯一的否定依据） |
| 缺少特征类型组 | E 没有这个类型的特征 | 否 |
| 材料不足特征类型组 | E 有这个特征，但值未知或只有区间不足以判定 | 否 |
| 比较未支持特征类型组 | 比较规则或材料形态本版不支持 | 否 |
| 递归未能判定特征类型组 | 被引用存在的归属为未知，或递归受限 | 否 |
| 子存在约束未支持 | 本版不比较子存在约束 | 否 |

前提已变化不进入分组，而是由状态表示，调用者照各自现有的重读路径处理。

### 3.4 依据保护

需要依据保护时，算法在持锁期间收集本次判定**实际读取**的结构节点，并在返回前用 `全局基础数据集.查询节点组完整结构` 取得快照：
- 实例关系路径：E，E 的专属概念，以及上位链遍历中实际访问到的概念节点。
- 定义匹配路径：E，E 的专属概念，C 及其特征项节点，比较中用到的 E 的顶层特征节点，以及 K 的定义节点。
- 递归：被引用存在的那次判定所收集的节点全部并入。

只收集必要材料，不扩展为全图核验。调用者把快照并入自己的保护集。之后核同时，参与判定的任何材料（包括递归部分）发生变化都会被核出。

### 3.6 被替代的旧口径

| 旧口径 | 当前裁决 |
| --- | --- |
| 各判定点只看上位链，或只比特征 | 统一为两条路径：实例关系或定义匹配 |
| 假值同时表示“不属于”和“没证明” | 布尔接口只表示“已证明属于”，假值不能用于证明不属于 |
| 集合成员判定对另一存在的专属概念也比特征 | 专属概念只按身份 |
| 没有特征、没有值、规则不支持都记为缺少 | 分为五组，只有冲突是否定依据 |
| 7100 §5 第 2 项：识别候选要求“特征类型集合相同” | 读取时判定只要求满足并覆盖，E 可以有更多特征或恰好相同。7100 §5 的归类写入不在本设计中修改 |

规范正文（7100 §5 等）待用户确认后另行修订，本设计不改规范文件。

## 4. 实现

### 4.1 算法入口（`领域/新_存在类.h/.cpp`）

```cpp
enum class 存在概念归属路径 : std::uint8_t { 无 = 0, 实例关系, 身份, 定义匹配 };
struct 存在概念信息比较结果 final {
    特征概念规则状态 状态 = 特征概念规则状态::入口拒绝; // 已完成 / 入口拒绝 / 前提已变化
    特征成员概念归属 归属 = 特征成员概念归属::未知;
    存在概念归属路径 路径 = 存在概念归属路径::无;
    std::vector<稳定编码> 冲突特征类型组, 缺少特征类型组, 材料不足特征类型组,
        比较未支持特征类型组, 递归未能判定特征类型组;
    bool 递归受限 = false, 子存在约束未支持 = false;
    std::vector<基础联合节点快照> 依据保护;          // 仅在请求时填充
    std::optional<新存在概念匹配采集结果> 采集;      // 第 5 步实际采集时携带
};
存在概念信息比较结果 比较存在与概念信息(稳定编码 E, 稳定编码 C, bool 需要依据保护 = false) const noexcept;
```

- `判定存在集合成员概念`：返回算法结果的状态与归属。
- `存在节点属于概念`：签名不变，含义改为“已证明属于”：状态为已完成且归属为属于时为真。注释写明假值不得用于证明不属于。
- `新_特征类::比较捕获特征值域`：存在引用分支改为取三态（属于为“K 包含 E 的值”，不属于为分离，未知或前提已变化为规则不支持）；在“动态域一律规则不支持”的拦截之前，新增存在集合值域分支。递归部分不经布尔接口。
- `比较存在匹配快照` 改为按 §3.3 分组输出，供算法使用。

## 5. 影响与风险

1. **人类判定暂时全部通过**：人类定义没有任何要求。交互者人类范围 15582 和两个本能的“是人类”条件都会通过。这只说明符合当前空约束，不表示识别出了真实人类身份。
2. **其它没有任何要求的抽象概念**同样全部匹配。目前已知只有人类；S0 再全仓核对一次。
3. **判定点 4、7、8 增加实例关系**：已归属的实例原来按特征可能判为未知或冲突，现在直接判属于。
4. **判定点 1、6、9 增加定义匹配**：参数候选可能变多，需求可能提前满足。S0 逐点写出预期变化。
5. **判定点 4 的缺少必需类型变窄**：只有真正没有该特征类型才算缺少；有特征但没有值的对象不再因此被排除。
6. **性能**：实例关系不成立时每次判定都要采集特征；请求依据保护时还要取快照。不加缓存，诊断运行时观察耗时。
