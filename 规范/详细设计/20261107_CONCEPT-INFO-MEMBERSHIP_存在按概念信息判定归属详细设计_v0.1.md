# 存在按概念信息判定归属详细设计

标识：`CONCEPT-INFO-MEMBERSHIP`；版本：v0.1；日期：2026-11-07；状态：草案，待用户审查。

依据：
- 用户本窗口裁决（2026-11-07）：
  - 概念节点内部包含成为该概念所必须的信息，可能是枚举，也可能是特征信息。
  - 判定根据概念中的信息进行：存在的信息包含概念中的全部信息，就判定它属于该概念。
  - 概念信息很少或为空时判定很宽，可以接受；人类概念的具体信息以后再完善。
- 规范：1140、7100 §5、7110 §5、6120 §11.1。
- 代码基线：main `82f72fa1e`。

## 1. 目标与完成条件

1. 存在 E 是否属于存在概念 C，按 C 中的信息判定：
   - 枚举或已归类：C 是 E 的专属概念，或 E 的专属概念沿上位链能到达 C；
   - 特征信息：C 是抽象概念，且 E 当前的顶层特征包含 C 的全部必需特征。
2. 单引用判定（`存在节点属于概念`）与集合成员判定（`判定存在集合成员概念`）使用同一规则，所有调用者自动继承。
3. 来源前驱筹办绑定人类 H 的路径（`新_任务类.cpp` 约 14211—14263）也按同一规则判定，并保护判定用到的材料。
4. 实际项目编译、链接通过；完成声明只到“已编译、未运行测试”。

不在范围：
- 归类写入：按 7110 建立上位边；本设计只在读取时判定，不写概念图。
- 从多个枚举人类中提取人类的共同特征（用户：以后再完善）。
- 交互者身份识别、登录信息等新本能。
- 集合成员判定的“未知”三态以外的语义变化。

## 3. 判定规则

存在 E 属于存在概念 C，当且仅当以下任一成立：

1. **枚举或已归类**：E 有专属概念 P，且 C = P 或 C 包含 P（沿上位链可达）。
2. **特征信息**：C 是抽象概念，且对 C 的每一项必需特征（特征类型 FT，具体特征概念 K）：E 有类型根为 FT 的顶层特征，当前值存在，且该值被 K 的值域包含。等价于 `比较存在匹配快照` 结果为“匹配”。C 的必需特征组为空时第 2 项成立。

补充约束：
- **专属概念只按身份判定**。C 是另一个存在的专属概念时，不按第 2 项判定。专属概念是单个存在的枚举；没有两个完全相同的存在，特征相同也不判为同一身份（7100 §3 第 3 项）。
- **零特征存在**（尚无专属概念，1140 第 4 节）：第 1 项不成立；第 2 项照常判定，C 的必需特征组为空时成立。
- **单引用判定的结果只有真假**：第 2 项为“材料不足”或“不符合”时为假，与现状相同。集合成员判定保持三态：材料不足为“未知”。

### 3.1 被替代的旧口径

| 旧口径 | 当前裁决 |
| --- | --- |
| 单引用判定只认上位链 | 上位链或概念特征信息被包含 |
| 7100 §5 第 2 项：识别候选要求“特征类型集合相同” | 本设计的读取时判定只要求 E 的特征包含 C 的全部必需特征，E 可以有多余特征。7100 §5 的归类写入（建立上位边）不在本设计中修改 |
| 集合成员判定对另一存在的专属概念也按特征比较 | 专属概念只按身份判定 |

规范正文（7100 §5、1140 第 4 节相关表述）待用户确认后另行修订，本设计不改规范文件。

## 4. 实现

### 4.1 `新_存在类`

1. 新增私有函数 `bool 按概念信息包含(稳定编码 E, 稳定编码 C) const`。调用前要求已持有存在特征互斥。
   - C 不是抽象存在概念时返回假；
   - 否则调用 `采集存在概念匹配材料(E, C)`：采集期间材料变化时返回假（调用者自行重读）；匹配状态为“匹配”时返回真；其余为假。
2. `存在节点属于概念`：保持原入口检查与异常处理。上位链成立时返回真；否则返回 `按概念信息包含(E, C)`。零特征存在（专属概念为空）同样进入第 2 步。
3. `判定存在集合成员概念`：在上位链判定之后、特征比较之前，增加专属概念检查。C 不是抽象概念时，归属为“不属于”，不再按特征比较。其余不变。

`采集存在概念匹配材料` 遇结构损坏时调用工程异常终止，与现有集合成员判定相同，不新增业务失败分支。

### 4.2 来源前驱绑定人类（`新_任务类.cpp` 约 14211—14263）

1. 现有受保护的上位链遍历保持不变。`已发现` 含人类概念时，按现状记入 `已验证人类组`。
2. 不含时，进一步按特征信息判定：
   1. 用已读取的人类概念定义（`普通概念(结果.配置.人类概念)` 的返回值，已带完整保护）判断它是不是抽象概念；
   2. 是抽象概念时，把交互者值存在的全部顶层特征节点加入 `交互者.完整保护`（`捕获因果节点保护`），再调用 `存在服务_.存在节点属于概念(人类节点, 人类概念)`；
   3. 结果为真时记入 `已验证人类组`。
3. 后续核同保护时，特征值或人类概念定义发生变化都会被核出，按现有“来源变化”路径重读。

### 4.3 不改的部分

- 概念之间的包含判定、归类写入、人类概念定义、新本能声明都不改。
- 不新增公开 DTO 或服务合同：`存在节点属于概念` 的签名不变，只改语义。

## 5. 影响与风险

1. **人类判定暂时全部通过**：人类概念必需特征为空，按第 2 项任何存在都属于人类。受影响的值域包括交互者人类范围 15582、获取服务对象的“参数3 是人类”、获取服务对象需求节点的“参数1 是人类”。用户已接受，等人类概念信息完善后自动收窄。
2. **其它必需特征为空的抽象概念**同样变为全部匹配。代码中建立抽象存在概念的入口：
   - `建立人工抽象存在概念` 只用于人类；
   - `抽象共同存在概念` 要求共同特征非空（`概念_存在类.cpp:823`）；
   - 现实交互场景类别概念带两项必需特征。

   施工 S0 须再全仓核对一次建立抽象存在概念的入口，发现其它空特征抽象概念时记入施工记录并报告。
3. **写入值域检查放宽**（`新_特征类.cpp:543`）：写入引用值时，特征匹配的存在也被接受。这与判定规则一致。
4. **性能**：上位链不成立时，每次判定都会采集一次特征。参数候选筛选等循环中调用次数会增加。本设计不加缓存，诊断运行时观察耗时。
5. **依赖“不属于”的现有分支**：例如参数候选过滤、需求满足判定，可能因判定变宽而多出候选或提前满足。S0 列出各调用点在空特征人类概念下的预期变化。
