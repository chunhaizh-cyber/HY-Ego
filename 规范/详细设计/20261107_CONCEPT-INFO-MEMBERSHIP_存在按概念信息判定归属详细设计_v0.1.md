## 3. 存在概念信息比较算法

### 3.1 规则

实例 E 属于概念 C，当且仅当 E 包含 C 中的所有信息。C 中的信息分两种：

- **枚举**：C 列出的成员，即 C 沿下位链到达的专属概念。E 的专属概念在其中，E 就包含这项信息。存在根枚举一切存在。
- **特征**：C 的必需特征组。E 对每一项必需特征都有同类型特征，且值落在该项值域内，E 就包含这项信息。

C 是另一个存在的专属概念时，它的信息就是那个存在的身份。E 不可能包含别人的身份，所以判为不属于。没有两个完全相同的存在，特征相同也不是同一身份（7100 §3 第 3 项）。

E 缺少 C 的某项信息时，不能说 E 属于 C。根据缺少还是冲突区分两种结论：
- **不属于**：E 的信息与 C 冲突（值落在值域外）；
- **未知**：E 没有冲突，但还缺某项信息，目前无法证明属于。

无论哪种，依据里都列出缺少和冲突的项，供调用者取得所缺信息（例如交给筹办形成子目标）。

### 3.2 步骤

输入：存在 E、存在概念 C。输出：结论（属于、不属于、未知）与依据（枚举命中；缺少的特征类型组；冲突的特征类型组；第 5 步的采集材料，如有）。

1. **入口**：E 不是存在节点，或 C 不是存在概念：入口拒绝。这是调用者错误，不是业务结论。
2. **枚举**：
   - C 是存在根：属于。包括没有专属概念的零特征存在（1140 第 4 节）。
   - E 有专属概念 P，且 C = P 或 C 沿上位链包含 P：属于，依据为枚举命中。
3. **身份**：C 是专属概念（且不是 P）：不属于。
4. **嵌套防护**：`正式嵌套判定防护(E, C)`。同一线程里同一对 (E, C) 重复出现，或嵌套超过 8 层时：未知。第 6 步会递归，防护用来防止循环引用导致无限递归。
5. **取材料**：E 没有专属概念（零特征存在）时，E 的特征组按空处理，不调用采集。否则调用 `采集存在概念匹配材料(E, C)`；采集前后材料不一致时为未知，状态为前提已变化，由调用者重读。
6. **逐项比较**：对 C 的每一项必需特征（FT, K）：
   1. E 没有类型根为 FT 的顶层特征，或该特征既无当前值也无实例区间值：缺少。
   2. 否则按比较规则比较 E 的值与 K 的值域（`比较捕获特征值域`）：

      | 比较规则 | 做法 |
      | --- | --- |
      | I64 数值 | E 的值（单点或实例区间）与 K 的 I64 值域求关系 |
      | 完整材料精确 | 按材料身份与 K 的值域求关系 |
      | 存在身份精确（K 为存在引用值域） | E 的值是存在 X，对 (X, K 的存在概念) **递归调用本算法**：属于为包含，不属于为分离，未知为规则不支持 |
      | 存在集合身份判等（K 为存在集合值域） | E 的值是存在集合 S。按 K 的四项约束判定：必含存在节点组 ⊆ S；“至少一个存在”时 S 非空；含概念成员组中每个概念至少有一个 S 成员属于它；全部属于概念组中每个概念都包含 S 的全部成员。成员归属**递归调用本算法**，复用 `概念_特征类` 的 `核验概念成员项`。成立为包含，不成立为分离，未能判定为规则不支持 |
      | 其它集合身份判等（服务任务、需求、消息） | 只支持 K 为全材料值域且 E 为空集合：包含；其余规则不支持 |
      | 信息引用身份精确及其余 | 规则不支持 |

   3. 相等或“K 包含 E 的值”：这项信息被包含。
   4. 分离，或 E 有当前值而关系为相交、E 包含 K：冲突。
   5. 规则不支持、类型或单位不相容，或 E 只有区间而关系为相交、E 包含 K：缺少。
7. **合取**：有冲突项为不属于；否则有缺少项为未知；否则（包括 C 没有必需特征）为属于。

### 3.3 示例

| 判定 | 概念中的信息 | 走到的步骤 | 结论 |
| --- | --- | --- | --- |
| 任一存在 ∈ 存在 | 存在根 | 第 2 步 | 属于 |
| 周春海 ∈ 人类 | 枚举：周春海的专属概念是人类的下位 | 第 2 步 | 属于 |
| 交互者副本 ∈ 人类 | 人类没有必需特征 | 第 6、7 步 | 属于（人类信息完善后收窄） |
| 周春海 ∈ 父亲 | 例如必需特征“子女”：存在集合值域，含概念成员组 = {人类} | 第 6 步存在集合 + 递归 | 有子女且其中有人类：属于；没有“子女”特征：未知 |
| 周春海 ∈ 员工 | 例如必需特征“雇主”：存在引用值域 = 组织 | 第 6 步存在引用 + 递归 | 雇主属于组织：属于；雇主不属于组织：不属于 |

## 4. 实现

### 4.1 算法入口（`领域/新_存在类.h/.cpp`）

1. 新增结果类型：

   ```cpp
   struct 存在概念信息比较结果 final {
       特征概念规则状态 状态 = 特征概念规则状态::入口拒绝; // 已完成 / 入口拒绝 / 前提已变化
       特征成员概念归属 归属 = 特征成员概念归属::未知;
       bool 枚举命中 = false;
       std::vector<稳定编码> 缺少特征类型组, 冲突特征类型组;
       std::optional<新存在概念匹配采集结果> 采集; // 第 5 步实际采集时携带
   };
   ```

2. 新增 `存在概念信息比较结果 比较存在与概念信息(稳定编码 E, 稳定编码 C) const noexcept`，按 §3.2 实现，持存在特征互斥。
3. `判定存在集合成员概念`：返回算法结果的状态与归属。
4. `存在节点属于概念`：签名不变，状态为已完成且归属为属于时返回真，否则为假。
5. `新_特征类::比较捕获特征值域`：
   - 存在引用分支（:3655）改为调用接口的 `判定存在集合成员概念`，按 §3.2 第 6 步的映射取三态；
   - 在“动态域一律规则不支持”的拦截之前，新增存在集合值域分支。

`采集存在概念匹配材料` 遇结构损坏时工程终止，与现状相同，不新增业务失败分支。

## 5. 影响与风险

1. **人类判定暂时全部通过**：人类概念没有必需特征。交互者人类范围 15582、获取服务对象“参数3是人类”、获取服务对象需求节点“参数1是人类”都会通过。用户已接受。
2. **其它必需特征为空的抽象概念**同样全部匹配。目前已知：`建立人工抽象存在概念` 只用于人类；`抽象共同存在概念` 要求共同特征非空；现实交互场景类别概念带两项必需特征。S0 再全仓核对一次。
3. **判定点 4、7、8 增加枚举**：已归类成员原来按特征可能判为未知或冲突，现在按枚举判属于。
4. **判定点 1、6、9 增加特征**：原来只认上位链，现在特征匹配也算属于。参数候选可能变多，需求可能提前满足。S0 逐点写出预期变化。
5. **性能**：枚举不成立时每次判定都要采集特征，循环中调用次数会增加。不加缓存，诊断运行时观察耗时。
