## 1. 目标与完成边界

本叶把现有 `L1实例特征服务` 的结构登记、`建立实际存在I64实例特征` 和 `读取实际存在I64实例特征` 原位迁移到 L1 业务中性 CRUD，并修通正式运行期租约到该具名第二层服务的完整依赖和 const 写边界。合法消费者只经生产会话、有效运行期租约和 const 实例特征服务完成业务调用；它不取得 L1、仓、锁、候选、可变上下文或验收专用入口。

登记形成四个中性节点。实例建立形成一个实例槽节点、两条角色关系、一个 I64 当前值和一个当前属性槽，并以中性精确读取重新形成结构化领域结果。实例服务负责宿主、定义、值域、来源和“同一实际存在宿主 + 同一抽象定义只允许一个当前实例槽”的第二层准入；L1 只负责完整中性写集的最小幂等、编码分配、原子提交和精确读回。

本叶不迁移初始场景宿主实例建立、当前值换代、退出 / 历史读取、批次、状态、动态、因果或恢复。它不建立关系条件查询、不调用完整快照、不把进程内定位索引升级为机器事实。当前不考虑崩溃、重启、断电和跨进程恢复。

## 4. 登记中性写集与读回

登记中性幂等键保持隔离域：

```text
登记键 = (0x05ULL << 56) | 请求.幂等身份.值
```

`建立登记` 固定形成四个节点、零关系、零值、零属性槽、零退出：

| 本地键 | 节点种类 | 领域解释 |
| --- | --- | --- |
| 1 | 普通 | 实例特征服务身份 |
| 2 | 普通 | 宿主槽关系类型 |
| 3 | 普通 | 定义模板关系类型 |
| 4 | 属性类型 / I64 | 当前 I64 值属性类型 |

函数只验证请求后恰一次调用 `提交中性写集`。L1 先按完整规范化中性写集裁决精确重复或同键异义，再对首次新键裁决期望事实代次。成功类结果必须回显四项完整唯一映射；服务从映射形成四编码定位，经起始事实代次、四个中性当前节点和结束事实代次完成同代次读回后，才保存定位。

`读取当前登记` 每次重新读取四节点。服务不保存 `实例特征结构登记` 权威副本；定位缺失返回登记未加载，节点缺失 / 退出、类型错误、混代或四编码复义返回具名非成功。

## 5. 实际存在实例写集与业务准入

实例中性幂等键保持隔离域：

```text
实例键 = (0x06ULL << 56) | 请求.幂等身份.值
```

首次新键路径固定读取并校准：

1. 当前实例特征登记；
2. `L1实际存在场景组合服务::读取实际存在` 返回的宿主完整事实；
3. `L1特征定义服务::读取I64特征定义` 返回的定义完整事实；
4. 请求来源节点的中性当前节点；
5. 起始和结束中性事实代次。

登记、宿主、定义、来源和首末代次必须等于请求期望事实代次。来源必须是未退出普通节点，初始值必须位于定义闭区间内。任一非成功在第一笔写入前返回并保持权威状态不变。

首次通过后形成固定中性写集：

| 本地键 | 写项 | 固定字段 |
| --- | --- | --- |
| 1 | 普通节点 | 新实例槽 |
| 2 | 关系 | 宿主存在 → 本地槽；登记宿主槽关系类型；角色 1 |
| 3 | 关系 | 本地槽 → 抽象定义；登记定义模板关系类型；角色 2 |
| 4 | I64 值 | 所属本地槽；登记当前值属性类型；请求初始值；请求来源 |
| — | 当前属性槽 | 本地槽 + 当前值属性类型 → 本地值 4 |

写集固定为 1 节点、2 关系、1 值、1 槽、0 退出；恰一次调用 `提交中性写集`。成功类结果必须回显本地键 1—4 的完整唯一映射，再使用与公开读取相同的权威精确读回形成领域结果。

## 6. 最小幂等与同宿主同定义唯一性

服务维护两份同锁、非权威定位：

```text
幂等身份 -> 宿主与定义组合、正式读取请求
宿主与定义组合 -> 幂等身份、正式读取请求
```

它们不保存节点、关系或值事实。当前阶段运行期上下文从空 L1 构造唯一长寿命实例服务，关系 22 等价结构只有本服务可以写入，且不考虑重启 / 恢复；因此本服务从第一次成功写入开始完整观察本进程全部实际存在实例写入。未来恢复或非空装配必须先建立独立索引重建合同，本叶不得以当前索引宣称跨进程完整。

顺序固定：

- 幂等身份已经定位：按请求重新形成中性写集并提交，让 L1 对完整请求返回精确重复或幂等冲突；不得由缓存直接返回首次结果。
- 幂等身份未定位、宿主 + 定义组合已由另一个身份定位：写前返回幂等冲突，L1 调用为零，防止第二实例槽。
- 两者均未定位：执行第 5 节首次准入和一次提交。
- 成功或精确重复后必须权威读回；仅在读回完整时更新两份定位。

不同幂等键不能绕过宿主 + 定义唯一性。同一幂等键改变宿主、定义、初始值、来源或期望代次会形成不同中性写集，由 L1 返回幂等冲突。精确重复不要求当前事实代次仍等于首次请求的期望代次；L1 必须在期望代次裁决前先识别完整请求精确重复。

## 7. 正式读取与状态映射

`读取实际存在I64实例特征` 固定过程：起始中性事实代次 → 当前登记 → 实际存在宿主 → I64 定义 → 实例槽节点 → 宿主关系 → 定义关系 → 当前属性槽 → 当前值 → 来源节点 → 结束中性事实代次。

全部提供者结果和中性读取结果必须具有同一非零截止。读回逐字段验证：

- 宿主关系源为实际存在、目标为实例槽、类型取登记、角色为 1；
- 定义关系源为实例槽、目标为抽象定义、类型取登记、角色为 2；
- 当前属性槽指向请求当前值；
- 当前值属于实例槽、类型取登记、来源为请求来源、材料为 I64 且未退出；
- 实例槽、两关系和值的创建代次相同且不晚于共同截止；首次提交读回时还必须等于写入首次发布代次。

任一缺失 / 已退出映射未找到；首末或提供者截止不一致映射事实代次漂移；资源失败原样映射；成功类材料矛盾映射内部不一致。不得返回部分事实，不调用完整快照、审计、历史、恢复或 legacy 读取。

中性写入状态显式映射：成功→已提交，精确重复→幂等读回，入口拒绝→入口拒绝，未找到 / 已退出→未找到，事实代次漂移→事实代次漂移，幂等冲突→幂等冲突，资源失败→资源失败，内部不一致→内部不一致。禁止裸枚举转换。
