# 外设独立收发模块详细设计

日期：2026-10-28

版本：v0.4，创建侧复核合同

基线：main `b72e3fb97ec1b36ed4058334500db38a6d522069`＋root保留联合WIP。

## 1. 目标及本次裁决

用户明确：外设类和外设世界构成独立运行模块，不能以筹办、因果链、连接本能或服务对象身份未成立挡住真实收发与事实录入。独立不要求新进程、新启动模式或调整现普通主程序整体启动顺序；允许依赖已初始化的通用world事实服务，但不依赖self、需求、任务、方法或服务认证。

本切片不实现本能函数。真实接收和完整写出由普通代码记录原文、更新外设F并形成S/D；不生成方法动作，不理解消息、不生成自我需求。排队不等于发送，完整HTTP写出不等于对方理解。

仅对本具名网页外设切片，6340第4/7节中把任务/需求绑定及任务消费当作一切外设事实录入前置的旧解释被本轮裁决替代；不外推到相机或其它外设。现world直接使用DATA-L1的架构债另案，不在此迁移。

## 3. world唯一输出身份

保持`新外设输出入列请求`布局和`输出入列(const 新外设输出入列请求&) noexcept`签名及非零要求。新增`新外设输出提交请求{新外设对话框定位 定位; std::string UTF8正文;}`和`新外设输出队列结果 提交输出(const 新外设输出提交请求&) noexcept`，由world分配序号。两入口共同调用私有`输出入列_已加锁(const 新外设输出入列请求&)`，它只在外设互斥内运行，不重复加锁。

分配在原`外设互斥`内，读取本目标全部正式输出记录最大号加一，不只读当前队列；身份域仍为公开宿主会话、对话框、输出方向、序号。已出列/取消/清空记录仍占用原身份，首号1，最大号已为UINT64_MAX则工程终止、不回绕。可以保留可重建缓存，但不能建立第二计数权威或公共账。本叶优先直接完整读取，不另开性能工程。

非零重试同目标同文：在列返回`已复用`，不在列返回`不在队列`且不重新排入；身份冲突工程终止。自动同文两次是两个消息。先完整核验，再建消息、更新队列并正式读回；工程失败保留已发生事实，不转成可重发的业务否定。

宿主头新增窄请求`网页输出入列请求{网页对话框目标 目标; std::string UTF8正文;}`，将`网页输出队列回调组::入列`固定为`std::function<网页输出队列回执(const 网页输出入列请求&)>`。适配模块调用world`提交输出`，回执必须带正式非零序号。`网页定向发送事实`始终只表示非零事实，不能拿它传0冒充自动分配请求。占用身份不进入world。

## 4. 宿主独立消费

删除`下一提交序号`及全部初始化、递增、穷尽判断。`提交网页对话框消息`保留现请求/结果签名和占用核验；向正式队列申请新身份，按回执登记已排队索引并返回该号。

`处理定向取件`仍持`队列操作互斥`，出列前预留索引空间。完整核验合法领取回执：目标匹配、非零序号与正式消息、非空合法正文。已有索引严格核对身份及`已排队`；没有索引则为合法正式消息直接建立`正在写出`项。重复索引、身份冲突、终态又被领取属于工程错误。私有索引是传输状态投影，不是入列或发送资格来源。

顺序固定：正式领取→正在写出→真实HTTP完整写出→发送完成回调发布外设事实→传输终态及显示投影。部分写出不调用完成回调，不加发送集合，不盲目重排；已出列后工程故障不伪装空队列。

宿主提交/领取/取消/停止仍由队列操作锁串行；world直接入列由自身互斥串行。出站占用只管正常宿主调用者的排他，不升级成world事实或队列消费前置。直接低层入列不能冒充连接本能业务许可。

## 5. 独立适配模块及完整签名

新建`海中鱼巣/装配.网页外设.h/.cpp`，类：

```cpp
class 网页外设运行模块 final {
public:
    explicit 网页外设运行模块(新_外设世界树类&);
    ~网页外设运行模块();
    新世界初始化结果 初始化() noexcept;
    网页外设运行回调组 取得运行回调();
    void 关闭() noexcept;
    网页外设运行模块(const 网页外设运行模块&) = delete;
    网页外设运行模块& operator=(const 网页外设运行模块&) = delete;
private:
    struct 实现;
    std::shared_ptr<实现> 实现_;
};
```

模块shared impl只借用一个外设world，另持私有互斥、就绪/关闭标志、可选活跃公开会话及目标目录。不建第二world事实仓。外层保证该world及其通用底座服务存活到模块`关闭`完成；初始化调用原外设world初始化，只依赖通用world已初始化。现外设静态根及消息服务绑定不迁移，不允许同时绑定不同基础world实例。

宿主头新增：

```cpp
struct 网页外设运行回调组 {
    std::function<bool(std::string_view)> 会话开始;
    std::function<void(std::string_view)> 会话结束;
    std::function<bool(const 网页对话框目标&)> 确认页面;
    std::function<bool(std::string_view, std::string_view,
        std::uint64_t, std::string_view)> 接收消息;
    std::function<void(const 网页定向发送事实&)> 发送完成;
    网页输出队列回调组 输出队列;
};
网页对话宿主结果 运行本地网页对话宿主(
    const volatile std::sig_atomic_t&,
    const 网页外设运行回调组&,
    const 网页服务输入回调组&,
    const 网页控制面板回调组&) noexcept;
```

全部闭包捕获impl的shared_ptr，不捕获普通应用、不取得普通上下文锁。impl互斥就是在途租约：回调先取锁、核验未关闭及借用有效，再完成整个world操作后解锁。`关闭`取得同锁即已等待在途结束，标记关闭、清空活跃控制状态并将world借用置空；之后旧闭包存活但不再接触world。未初始化取得回调是工程错误；关闭后取得回调返回空组。关闭幂等，析构调用关闭且不回调宿主；构造impl分配异常交外层原工程链，不改成业务状态。新宿主重载是唯一完整生产实现；全部旧重载经全仓核对无迁移后消费者则删除，不保留具名拒绝的假入口。普通组合调用同叶迁移。原公开C函数指针别名及事实回调组仅被宿主私有辅助函数使用，迁到cpp内部，内部改用`std::function`；辅助函数按const引用接收闭包，不以C函数指针排斥捕获模块的合法回调。

各闭包直接职责：

- 会话开始：合法非空标识，无活跃会话则建立；同会话重复幂等，不同活跃会话拒绝。只表示外设会话可用，不绑定人类。
- 确认页面：校验会话及UUID，world建立/复用场景，登记目标。不确认交互对象语义身份。
- 接收消息：校验当前会话、目标、来源序号和UTF8，建立/取得页面，取真实发布时间，经`更新接收`和读回成功才返回true。
- 发送完成：校验当前会话/目标/非零序号，经`更新发送`正式发布；发布未完成走工程错误，不回正常业务否定。
- 四个队列闭包：校验当前会话/页面，经world对应公开口操作并准确转换回执，不依赖服务认证。
- 会话结束：在宿主停止/清空且同步在途处理完结后，持模块互斥清除活跃会话和目标目录；只回收控制状态、不删事实。

边界固定：初始化在就绪时复用world原`无变化`结果；永久关闭后返回`依赖初始化失败`且零写。会话结束的同会话重复或当前无会话为幂等无操作，不同会话不得关闭当前会话。无当前会话的确认/接收通过各自bool明确拒绝；首次会话开始按前述分支建立。队列回调没有关闭状态枚举，关闭后被调用属于宿主寿命违约，走工程终止而非伪装空队列。正常宿主关闭必须在模块会话结束前完成队列清空。队列回调的来源序号/正式消息不合法同样工程终止，不扩大普通否定域。

模块不自建线程；宿主同步网络循环是其控制域。锁序为宿主队列操作锁→模块锁→world外设锁。宿主共享状态锁绝不跨外部回调；模块/world不得反调宿主。会话结束后无活跃会话操作拒绝；永久关闭后会话开始也拒绝。真实发送完成在无当前会话/模块关闭后到达属于寿命违约工程错误，不能吞掉写出事实；宿主保证完成回调先于会话结束和模块关闭。

## 6. 组合根、关闭及一次迁移

普通上下文保留原world和外设world成员；在外设world之后声明`网页外设运行模块 网页外设模块`并以外设world引用构造。原2518附近外设初始化调用改模块初始化，不调整产品整体启动顺序。上下文析构先停并join所有使用者，然后显式模块关闭，再进入成员逆序销毁；模块析构再关闭为幂等，外设world及底座晚于模块销毁。不在宿主同步回调尚未收束时关闭模块。

普通组合新增`网页外设运行回调组 取得普通应用网页外设运行回调() noexcept`，只在取得时定位已创建模块并调用factory，不以整份装配成功为准入；实际回调不再读取普通上下文或装配结果。模块可由任意正常组合根构造，不需要此普通应用入口。原外设包装若有其它现行消费者，仅forward模块，不复制事实逻辑；无消费者则删除。

迁出旧普通外设输出回调、确认页面、接收发送事实和接收网页消息实现；没有其它消费者则删除对应声明/定义。启动删除静态普通输入转交包装，改使用新宿主重载和模块回调组。服务输入的会话/认证函数仍留原业务，其生命周期不充当外设会话依据。连接函数继续可选地调用通用宿主提交入口，不改连接业务。

宿主开始：验证外设完整回调→建立网络/标识→外设会话开始→可选服务会话开始→浏览器及循环。任何后续失败按逆序结束已开始租约。关闭：停止接纳/领取→等待本次同步请求和写出返回→清空已登记页面正式待发队列/标已有排队索引取消→结束可选服务会话→结束外设会话→释放回调引用。保留所有锁及最终join，正常作用域回收模块和world，不退回静态析构。

清空不删消息历史/F/S/D。已经出列不重排。模块关闭后低层world仍是数据服务，低层直接入列不表示本次关闭会话复活；不承诺无边界外部生产者永远不再写数据。

## 7. 验证与声明边界

本叶包含DTO、模块、宿主、普通组合消费者和工程登记一个闭环，不分成无消费者提供者。无需新增用户机器语义裁决；主程序装配失败仍按既有产品行为退出，本叶不改变此策略。

默认实际项目`海中鱼巣.vcxproj` Debug/x64编译链接。新文件登记vcxproj及filters；不建专用程序/脚本/工程。root获用户真实测试指令后独占正常入口、端口日志。实际出站必须有正常调用者明确提供的内容；当前正常业务可能尚无出站，这是运行覆盖缺口，不阻止独立模块代码编译交付，不得添加回声、欢迎语、控制按钮或测试端口。

矩阵：自动/显式序号交错；出列/取消/清空后不复号；非宿主预建索引的合法输出可领取；身份冲突；部分写出零发送事实；重复正文独立接收；页面隔离；服务认证未绑定仍可录入/取件；关闭清空及自然退出。真实收发F/S/D须正式读回，网页显示单独不够。正常入口无法触发的项如实未验证，不以静态读回升级。

本设计不证明实现或运行完成；出站内容实际未出现时不得标顶层目标完成。独立模块能正常运转不等于具有自主语义内容生产能力。
