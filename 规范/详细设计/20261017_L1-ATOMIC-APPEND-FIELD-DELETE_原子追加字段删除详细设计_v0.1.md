# L1-ATOMIC-APPEND-FIELD-DELETE 原子追加字段删除详细设计

日期：2026-10-17；版本：v0.1；代码起点：`15e58ebfa1b1315376c8cafe540cecbcf9846de9`。

## 1. 目标与必要性

本切片只补齐DATA-L1原子组合的一项结构能力：新节点/新字段/字段替换/外部边追加可以与指定既有字段关系删除同次发布。依据0050§1.1—1.3及4015§14，不定义特征、消费资格或服务值业务语义。

直接需求来自服务值Q联合消费的feature提供者：当前合法I64历史允许旧直接历史值；新值命中旧值时，必须把旧直接字段转换为新命中记录节点，不能在原子提交之外先删或后删。feature提供者要支持当前合法结构，不把当前服务递增假定为所有特征永久单调。现有`原子追加节点组`不能删字段，`原子比较变更字段组`能删字段但不能建立节点；分两次调用无法形成同一线性化点。故扩展既有追加入口，而非建立第二事务引擎。

本叶不主动迁移数据，没有生产调用方提交非空删除组，不触发任何历史删除。调用方之后何时可删仍由各自owner合同控制。

## 2. 唯一接口与物理位置

只改`海中鱼巣/核心/基础数据集.h/.cpp`。在现有请求的**最后**追加一个成员，旧字段顺序不变：

```cpp
struct 基础节点组追加请求 final {
    // 原有六个成员按原顺序保留。
    std::vector<稳定编码> 删除字段关系组;
};
```

不改`基础数据集::原子追加节点组(const 基础节点组追加请求&) noexcept`签名、不新建入口、不新增状态枚举、不改变结果DTO。删除组默认空；既有聚合初始化和默认构造保持原行为。既有生产调用不新增非空删除请求。

私有实现可直接复用`原子比较变更字段组`已有删除校验与候选双索引处理逻辑，但不能调用它完成前半交易（会成为两次提交），也不把底座锁、候选表或可写引用交给上层。必要的小私有helper仍在原`.cpp`匿名命名空间/类实现中，不扩展公开ABI。

## 3. 请求合同

1. 删除目标是已经存在的字段关系编码，不是字段类型节点、所属节点、引用目标或外部关系编码。
2. 允许纯删除：其它写入组全空，只要删除组非空且完整预期成立，就执行删除；返回成功时三个新增身份组均空。所有写入组都空仍`入口拒绝`。
3. 允许混合：删除与新节点、新字段、其它字段替换、外部边追加一次发布。
4. 删除编码必须非零、组内无重复；同一编码不得同时出现在替换组。两者冲突不规定先删再改，直接`入口拒绝`、零写。
5. 每个待删字段必须出现在其所属节点的`预期联合节点组`完整字段快照中。只有`预期既有节点组`不够。不存在于任何提交联合快照的删除编码为`入口拒绝`，不猜调用者删除意图。
6. 若旧内容为节点引用，该旧目标节点也必须在`预期联合节点组`；直接值无此额外目标要求。字段类型节点照现有底座不变量核验存在，不额外要求它成为联合快照宿主（与已有字段组合删除一致）。
7. 删除组非空时，本请求对既有节点追加字段也必须使用联合快照宿主，沿用现有替换/外部边混合模式的严格规则，不允许在同一混合交易里以弱快照绕过受保护宿主。
8. 允许删除旧字段后追加相同“所属节点+字段节点”的新字段；新字段由追加组生成全新编码，旧编码永不复用。这不是对旧字段的替换，也不自动维持领域字段唯一性；领域基数由调用者负责。
9. 不删除任何节点或外部边，不级联删除引用目标。不改变其它未列入删除/替换组的字段，不添加墓碑或操作账。

## 4. 校验、非成功与一致性

新删除组的输入结构校验独立收集`删除字段码`及预期字段映射，在任何分配/候选修改前检查零码、重复、删除/替换交集、完整预期所属及节点引用端点。

| 情况 | 结果 |
| --- | --- |
| 空码、重复删除、删改冲突、删除码未在联合快照中、缺所属/旧引用目标联合快照 | `入口拒绝`；所有结果身份组为空。 |
| 已提交预期中的节点当前不存在 | 沿用`节点不存在`，零写。 |
| 预期字段原来存在但当前被删、内容/所属/关系已改变 | 所属完整快照不相等，`预期不符`，零写。不得把重放删除当作成功。 |
| 预期已证明与当前相等后，内部字段表/索引仍缺目标或不一致 | 底座内部不变量损坏，走既有工程异常终止链，不包装为成功或正常无字段。 |
| 其它新增引用缺失、原有请求非法 | 保持原有追加合同的对应返回。 |
| 候选构造/容器分配失败 | 沿用`资源失败`，零公开事实交换，结果身份组为空。 |

有多个错误同时存在时，不承诺跨既有路径的新错误优先级；冻结的是每个单独条件的语义。新删除组为空时，不改变原来各分支验证顺序和结果。

请求的联合快照比较仍在同一次独占锁内覆盖全部当前字段和入/出外部关系。不能仅比较待删字段值，不能在锁外先删再进入追加调用。第二次原请求重放因旧字段已退出而返回预期不符，不增加底座公共幂等账；上层用自身已发布身份判断同义结果。

## 5. 候选修改与唯一发布点

保留现有一次独占锁和完整候选交换结构：

```text
校验全部输入及联合预期
→ 核验待删字段现有双索引
→ 构造候选节点/字段/所属字段索引/目标字段索引
→ 在候选中删除指定字段及所属索引、必要目标索引
→ 完成其它原有替换与追加操作
→ 全部候选闭合后一次交换正式表和索引
```

删除候选字段时，所属索引必须恰删除一项；节点引用型旧内容的目标索引也必须恰删除一项；直接值不得伪造目标索引项。删除索引不完整为工程不一致。删除字段记录最后从候选字段表移除，不触碰正式表。

原有外部关系候选仅在追加外部边时复制；纯字段删除不增加关系表复制。分配器继续沿用原追加合同：失败前已经分配但未发布的编码可以消耗，不回退、不复用；零公开变化不是编码高水位回滚承诺。最终交换之后不再执行可能分配或失败的新增步骤。
