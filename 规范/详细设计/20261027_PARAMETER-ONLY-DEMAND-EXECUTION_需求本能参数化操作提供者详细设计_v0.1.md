# 需求本能参数化操作提供者详细设计

标识：PARAMETER-ONLY-DEMAND-EXECUTION；版本：v0.2；日期：2026-10-27。沿用原路径；本版具名替代v0.1中模拟writer、X工厂准入及动作后可重新进入核心的施工口径。

代码基线：main `eb8132384ea8064f45bd765d136d90ea02db5a36` 加 root 已保留的联合 WIP。本文只冻结本次施工合同，不证明实现。替代 SERVICE-DEMAND-CONTENT-HANDOFF v0.4 的后续施工入口；旧设计和计划只保留追溯，不与本合同并行施工。

## 1. 用户裁决和本叶边界

本能函数全部业务操作只能依赖参数场景所传信息，不读取真实当前任务 X、直接调用 K、固定自我、固定现实 owner，也不判断现实/模拟。第一次空参数调用生成方法头及固定规格的登记职责保留；登记配置中的正式概念不是运行业务实例。

本叶改变普通认知世界中服务对象 H 的“需求”特征 F：由参数材料存在 Em 的完整内容建立或复用被认知需求 D，再经正式特征路径把 D 纳入 F。原因是落实服务对象的新完整需求，目的为后续自我承接提供正式材料。D 主体 H，不入自我需求树，不建立任务，不增加自我服务任务。模拟同操作只改变本次样例。任务/方法虚拟存在不由本函数改变；动作、状态和动态属于外层执行和事实 owner 自动记录。

最早闭合代码叶收缩为：场景传入的需求操作提供者、普通世界 adapter、场景shared租约，以及“获取服务对象新需求”的无环境分支正常核心。模拟owner保持本轮前只读能力，不绑定未完成需求writer，不能声称普通/模拟操作均已实现。旧主动/被动获取服务需求的目标仍是自我服务任务增加，与新函数的 H.F 发布不同，不在本叶静默改写它们的目标、参数或方法身份；其隐式 X、self/manager 调用留作具名后续缺口。永久 C/R 内容路径 ABI 不施工，不能把本叶称为模拟学习全部完成。

直接依据：[5360](../5360_子规范_方法函数登记执行与任务反馈.md) 的唯一参数场景、外层治理、同一原函数执行；[5370](../5370_子规范_方法学习与知识形成.md) 的隔离和实际结果；[5170](../5170_子规范_需求治理详细合同.md) 的 U/C 来源及两阶段发布。当前窗口已裁决本具名新函数需求 F 当前值为单 D 稳定引用，旧值由特征类转为历史；不把旧集合规范外推来改本叶机器语义，不在线改 Vm。

## 2. 现状和复用裁决

- `新_本能函数集.cpp` 新入口查询 TLS 的 K，普通 runtime `读取材料` 再读 K.现实场景、配置 self 并检查同场景；它们不是三参数声明的业务输入，删除该依赖。
- `服务需求.本能运行服务.cpp` 新 runtime 还要求执行用途、现实材料 owner 地址相同，内部创建动作、读取 K、记录 K 材料。业务读取/写入迁入参数提供者；K 只可留在外层调用记录绑定中。
- 现 `新_需求类::建立或取得被认知需求` 深层核验真实 U/C/R；publisher 也核固定真实 owner，不能让模拟 adapter 调它们，不能只删除顶层 guard 后落入现实服务。
- 现模拟 world 已有本地需求/U/C/R/语言场景身份表、L1 重建读取、样例节点收集释放，但阶段动作硬定self参数位置2，无法用于本方法参数2=F；不能让H或Em冒充self。当前共享确认/二次语义也无完整只读桥，故本版不施工模拟writer。
- `模拟学习.服务.cpp` 对需求/U/C 内容、单需求引用 F 的永久 C/R 抽象仍明确拒绝；本叶保留该保护，不把本地临时 D 编码写入永久知识。

复用普通需求建立、publisher、特征类及世界组合更新；新增仅一个需求操作抽象和一个无环境分支核心 helper。模拟本地需求编解码适配留作路线，不建任务环境、不伪造 K/X 或以登记名分派专用学习算法。

## 3. 固定业务参数

| 位置 | 固定规格 | 实际来源及用途 |
| --- | --- | --- |
| 1 | 存在=人类 | 已明确服务对象 H |
| 2 | 特征=需求 | H 实际持有的 F；允许当前未知/无值，不能用历史冒充当前 |
| 3 | 存在=通用存在 | 内容 Em；沿其正式特征读取需求字段及 U/C 来源，C/U 进一步关联 R |

登记名 `builtin.service_object.demand.acquire_new.v1`、规格顺序、方法头、初始“F 属于 H”关系、必要人类条件全部保持。Em 不能替换为预建 D；H 与 Em 不额外要求同场景，自我与 H 同场景也不是业务条件。所有 Em 字段按现需求类型槽解释，不改变规格、不新增确认类型。

内容包括主体=H、目标存在、目标 FT、目标形式，值目标必须域+比较且无方向，方向目标必须方向且无域/比较；治理值为被认知/权重0/活动，Em 显式矛盾不得覆盖。U/C 必须是参数可达的完整实际材料，C 未失效，H/目标/目标语义/U/R 相互一致。模拟 U/C/R 只能来自本地映射；共享概念可读，实例不可回现实补取。没有材料返回待齐，不生成默认 U/C/R。

### 4.1 参数场景注入和租约

`新_方法参数场景.h/.cpp` 新增：

```cpp
新本能需求运行接口* 方法参数场景::获取需求运行接口() const noexcept;
// private 构造最后追加，默认空，不影响既有调用：
std::shared_ptr<新本能需求运行接口> 需求运行 = {};
```

场景保存共享租约，不另加第二入口参数。getter 只返回已注入能力；无能力返回 nullptr，不按用途回退注册全局服务。现 `新方法模拟运行接口` 增加默认返回空的虚函数 `virtual 新本能需求运行接口* 获取需求运行接口() noexcept { return nullptr; }`；scene 显式租约存在则使用它，否则从已拥有的模拟 owner 取得该能力，无现实 fallback。注入不能同时指定不同 owner；冲突在构造时工程拒绝。

`新_方法类::建立参数场景` 现签名末尾追加 `std::shared_ptr<新本能需求运行接口> 需求运行 = {}`，传入 private 场景构造。`建立模拟参数场景` 保持现签名，由其持有的同一个模拟 owner 提供能力。登记场景能力为空，登记阶段不执行核心。

真实 adapter 工厂归现 `服务对象新需求本能运行服务`：

```cpp
std::shared_ptr<新本能需求运行接口> 建立参数操作提供者(
    稳定编码 方法节点, const std::vector<新方法参数角色绑定>& 参数,
    稳定编码 动作场景, 稳定编码 动作主体, 稳定编码 动作来源);
新方法参数场景结果 建立执行参数场景(
    稳定编码 方法节点, std::vector<新方法参数角色绑定> 参数,
    稳定编码 动作场景, 稳定编码 动作主体, 稳定编码 动作来源);
```

本版真实工厂只接受外层正式direct K作为显式动作来源，不接受X，不新增任务owner依赖，不按L1字段猜X类别。工厂校验未收束且无既有A的fresh K、M与参数精确一致及动作记录元信息，创建每次调用唯一adapter租约；K已有A时拒绝新租约并保留原事实。动作主体仍为自我，动作场景取外层正式记录上下文；后面三个值仅用于动作/来源记录和原有安全范围，不用于查找、补齐或判断H/Em内容。不可将动作主体改成H或Em。外层创建/收束K，函数不知道K。未来X必须先有任务owner公开adapter合同，本叶不接入。

该公开API是纯参数绑定和记录能力创建，不要求TLS direct守卫或TLS任务守卫。工厂一次核验并捕获显式K的记录元信息后，真实adapter的`读取新需求材料/复核新需求材料`不得再把K是否当前、是否收束、是否同场景作为业务门。动作记录/取消/来源关联由外层原记录生命周期保护，不取得从K补取业务对象或参数的权限。工厂在动作前可用，不能作为旧A的重建/自动重试入口。

`建立执行参数场景` 是合法真实构造公开入口：在外层创建时先取得 adapter，再调用现方法owner的扩展工厂，将该能力绑定到同一次 M/参数场景。现没有生产业务调用者，不为接入该API新增任务/筹办调用或自动direct执行；交付可合法调用的构造能力即可。本能新入口运行阶段只 `scene.获取需求运行接口()` 并调用核心。方法头声明核对/首次登记可使用现只含正式概念的登记端口，不再调用该端口的固定现实 `执行`。旧新需求服务`执行(scene)`入口转为使用scene注入接口的共同核心，不保留K业务读取或固定owner旁路，不与旧主动/被动入口混同。

共享租约覆盖场景及在途调用；运行服务 close 拒绝创建新租约、等待现有活动租约释放后再销毁 owner。模拟接口由 scene 已持有的模拟 owner 保活，先结束调用读回，再释放样例，再销毁 owner。禁止裸栈对象注入或租约跨样例复用。

## 5. 唯一正常核心顺序

1. 从 scene 按1/2/3取 H/F/Em，完整核验数量、类型、范围与所属；通过注入接口读取材料；未齐/前提变化不建动作，也不派生子需求。
2. 条件侧只加入实际读到的三位置及 F 前值、Em 实际字段；不虚填未读值。
3. 动作前以同接口复核同一材料；相等范围包括请求、F当前/历史、Em字段及U/C/R语义，不能只比较节点编码。前提不再成立零动作返回。
4. 经接口开始动作，返回显式 A；外层 adapter 记录本次动作，核心不读取其来源身份。此前未开始执行不允许为了入队/登记而建动作。
5. 经同接口发布，返回实际需求引用与结果状态；动作已开始后变化/取消保留 A，部分结果不冒充正常完成。
6. 已发布/已复用只证明本函数合同操作完成；任务目标满足、自我需求建立/任务增加由后续治理决定。已发布但当前再变需保留此次已发生事实，不自动重做。

最小重入合同：原provider在A建立前允许按相同scene多次读取/复核；一旦A已建立，禁止经核心入口从头再次执行。public `读取新需求材料`（核心首个provider调用）此时必须按工程误用诊断并中止，不能返回材料不足/未进入动作，不能丢弃原A。`复核新需求材料`只服务动作前阶段。动作后`发布新需求`内部的fresh读取使用private helper，不调用被锁为动作前的public读取入口。原provider保存A及已知D进度，允许外层沿原A/D继续显式发布读回/提交，不再调用`开始本次需求动作`；不保证自动恢复调度。新合法外层调用可用fresh K按正式U/C来源复用已建D，它是新调用，不覆盖旧A或伪装原调用未执行。

运行返回状态映射：动作前材料不足/需重新确认→既有未进入动作+待取得；前提变化→既有入口拒绝，不学习为负结果；动作后尚未发布→动作结果未知+部分取得；已发布/已复用→已按合同返回+已取得并交付已形成状态。工程异常沿原工程终止链，不进入学习样本。

## 6. 普通世界 adapter：两阶段事务及恢复

adapter 私有实现在 `服务需求.本能运行服务.cpp`，复用现 runtime 的字段识别和确认语义核验；把 `call.现实场景`/`cfg.self` 业务读取移除，以参数引用的所属场景/持有关系经 world owner 获取定位。Em 的 U/C/R 全部沿参数闭包读，不能扫全世界找“最近确认”。对共享概念读取槽定义并保护是基础设施，不是偷偷补业务实例。

采用现 `新_需求类::建立或取得被认知需求` 完成 D 阶段，publisher 完成 H.F 阶段。两阶段不是全有全无：D 建好后 F 冲突保留 D，下次按相同主体/U/C/目标复用；同来源异内容重新确认，不同来源不能按目标擅自合并。F 发布必须经现特征/世界组合入口更新当前及历史并自动形成状态/变化；不得直接改基础字段或用返回 DTO 代替事实。

恢复临时材料归 adapter/外层调用管理，不按 K 存成第二需求账；不得把 K 当业务去重键。正式去重仍是现需求来源语义，F并发保护沿用既有CAS/组合预期。每次重试前重读参数；已开始动作不自动重发，动作及D/F读回可确定位置才继续记录收束。未知发布保留动作、D身份和既有owner恢复信息，不能谎报回滚。

并发边界：adapter动作前读取/复核F与后续publisher fresh读取F不是一个跨阶段原子截面。本版沿用publisher自身fresh捕获后的CAS/组合预期，不扩其公开事务合同，不承诺动作前F与D/F发布全程共同原子。窗口内F变化可能使publisher基于较新F发布或明确冲突；返回据实际publisher读回判断，不伪称旧F全程未变。该已知边界必须在施工报告中保留，不以新增锁或新事务偷偷扩大范围。

## 7. 执行退回和模拟writer路线（不施工）

v0.1错误地把现模拟动作和确认读回视为足够可复用。实际阶段动作要求位置2是self，本方法位置2是需求F；简单A仅method/H/F/time又缺严格读回必需的动作来源/概念/调用主动作及阶段关联。选H或Em作为self会造假记录，不能由执行者临场裁决。另本地U/C一致不代表当前共享目标FT/二次比较定义仍与固定语义一致。

因此v0.2不让`新_模拟世界类`继承或返回本次需求writer能力，不施工D建立或F写回。该owner只保留本轮前既有只读及其它已实现能力；本轮未完成新增由原模拟代码owner精确撤除，保留原WIP，不执行checkout/reset，不留下成功stub或现实fallback。scene可保留通用capability getter的默认空返回，它准确表示能力未装配，不是模拟已支持的假实现。
