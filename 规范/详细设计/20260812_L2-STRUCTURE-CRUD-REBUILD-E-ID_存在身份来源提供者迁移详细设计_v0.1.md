## 1. 目标、边界与完成定义

本叶把已发布的存在 owner-scoped 服务迁移到 G2 正式身份来源合同，完成以下一个闭环：

1. `L2结构公共.数据.h` 落下七族公共枚举和身份来源值式事实；
2. 存在 owner raw 交付先形成不可复制、可移动的 `L2存在所有者交付`，存在服务不再接收同型 raw 端口；
3. 存在服务构造期间以存在 owner 同写不可变族锚点和族归属关系类型，并保存只读非权威定位；
4. 每个新存在节点与一条 `节点 -> 存在族锚点` 的非自环归属关系在同一 owner-scoped 写集中发布；
5. 公开 `读取存在身份来源`，当前 / 历史完整读取、节点读取、固定属性前置和退出复用同一来源判定；
6. wrong-family、v1 legacy、裸 L1、同 owner 内部节点和旧未标记存在固定拒绝，malformed 来源固定内部不一致；
7. 存在退出显式闭合自身节点、族归属关系和当前固定属性值，节点与归属关系同代退出；
8. 普通应用继续只公开同一存在服务实例，普通调用者不能取得 raw owner、端口或来源初始化入口；
9. Debug / Release x64 根工程和生产外参数矩阵通过，三份临时验证文件在结果发布后以独立清理提交删除。

本叶不迁移特征定义 / 实例、场景、状态、动态或因果；不修改 T1 / DYN2 草稿；不建立 A1；不增加 L1 仓、L1 DTO、L1 API、第二身份仓、成员表、身份缓存或恢复入口。完成只证明 E-ID 代码切片通过本设计矩阵，不等于真实业务闭环或独立集成验收通过。

## 6. 来源初始化与非权威定位

存在服务内部常量固定为：

```text
存在身份来源登记幂等身份 = 0x4C32'4944'5352'4301ULL
存在族锚点本地键值       = 0x0202'1001U
存在族归属关系类型本地键值 = 0x0202'1002U
存在族归属关系本地键值     = 0x0202'1003U
```

前两个本地键只用于初始化写集；第三个只用于每次公开节点创建写集。它们不是稳定编码。所有存在公开写函数在提交前拒绝把固定来源登记幂等值当作公开 `L2结构幂等身份`，返回 `入口拒绝`、零变化，避免内部写集与调用方共用同一 owner 幂等域。

构造函数私有调用 `初始化存在身份来源()`：

1. 读取当前事实代次；
2. 使用固定来源登记幂等身份和该代次提交两个普通节点：族锚点、族归属关系类型；
3. 首次成功必须发布并回两个映射；精确重复必须不发布并回首次同两个映射；其它状态使构造失败；
4. 按写入首次事实代次读取 owner、锚点和类型历史事实，核对同 owner、普通节点、不同编码、同创建代次、未退出；
5. 形成不可变 `存在身份来源定位{owner, 锚点, 类型, 建立事实代次}`。

定位只用于构造精确 L1 选择项，不是接受权威；每次公开读写仍读回 owner / 锚点 / 类型。定位缺失、零值、被改写或 L1 读回矛盾固定 `内部不一致` 并停止写入。本叶不提供恢复、扫描或补登记入口。

## 7. 统一来源判定

### 7.1 当前来源

公开签名固定为：

```cpp
L2存在身份来源读取结果 读取存在身份来源(
    const L2存在身份来源读取请求& 请求) const;
```

当前读取形成一次 owner-aware 一致当前请求：

```text
owner = 存在 owner
nodes = 请求存在、存在族锚点、存在族归属关系类型
source relation group = 请求存在 + 精确存在族归属关系类型
expected generation = 请求头期望事实代次
```

若请求编码等于锚点 / 类型，直接 `入口拒绝`。顶层成功后按以下顺序裁决：

1. 目标节点 `未找到` -> `未找到`；目标节点 `已退出` -> `已退出`，空来源且不补历史判族；
2. 请求编码当前占用为关系 / 值而不是节点，或目标节点是属性类型形状 -> `入口拒绝`；当前目标节点存在但 owner 不是存在 owner -> `入口拒绝`；
3. 目标同 owner 但精确来源组为空 -> 旧未标记 / 裸内部节点，`入口拒绝`；
4. owner、锚点或类型缺失 / 退出 / 错 owner，精确来源组重复，或返回组成员的 owner、源、目标、类型、角色、生命周期矛盾 -> `内部不一致`；
5. 唯一关系必须 `源=目标节点`、`目标=存在族锚点`、`类型=存在族归属关系类型`、`角色=1`，关系 owner 与三节点 owner 精确相同；
6. owner 创建不晚于锚点 / 类型，锚点 / 类型创建不晚于公开节点，公开节点与归属关系同创建代次；全部项目当前且共享请求的非零截止。

精确类型组没有成员时不能猜测其它类型关系；它只证明“没有正式存在来源”，因此按旧未标记入口拒绝。若 L1 返回精确类型组成员但成员类型字段不符，属于仓库 / 索引矛盾并返回内部不一致。

### 7.2 历史来源

历史入口固定在一次前后当前代次夹取内完成：

1. 前代次必须等于请求头期望事实代次；
2. 读取历史 owner、目标节点、锚点和类型；
3. 目标未占用或创建晚于历史截止 -> `未找到`；目标 owner 错、等于内部锚点 / 类型或不具正式来源 -> `入口拒绝`；
4. 节点有退出时先要求退出代次严格晚于创建代次；关系判定截止固定为：节点尚未在请求截止退出时取请求历史截止；节点已在请求截止退出时取 `节点退出事实代次 - 1`。在该截止读取精确类型历史源关系组，要求唯一当前关系；这会发现请求截止的重复关系，又兼容 L1 `[创建, 退出)` 语义；
5. 判定截止组为空时，再只在节点创建事实代次读取一次精确类型组：仍为空表示从未具正式来源，返回 `入口拒绝`；能定位关系则说明来源曾建立但提前退出，按生命周期不闭合返回 `内部不一致`；
6. 按定位出的关系编码读取完整历史关系事实，再把 owner、三个节点和关系的晚于请求截止退出隐藏；
7. 复核关系和节点同创建代次、同 owner、关系退出与节点退出同代；owner、锚点和类型生命周期覆盖节点 / 关系；
8. 本闭环取得的 owner、具名事实和历史关系组结果均须回显等于请求头期望事实代次的读取事实代次；后代次仍须等于同一期望，否则 `事实代次漂移`。

节点已在历史截止前退出仍返回 `已读取` 和完整退出生命周期。判定截止与创建截止回退只用于从 L1 权威历史索引定位唯一关系，不保存关系编码，不形成第二成员表，也不会在节点退出后丢失关系。

### 7.3 状态映射

| 条件 | E-ID 状态 |
| --- | --- |
| 非法合同、类别、截止、零身份、内部保留幂等值 | `入口拒绝` |
| 编码未占用或历史截止早于节点创建 | `未找到` |
| 当前入口节点已退出 | `已退出`，优先遮蔽族判定 |
| 非节点事实编码、属性类型节点、目标节点自身 owner 不是存在 owner、legacy、同 owner 无正式来源、锚点 / 类型等内部节点 | `入口拒绝` |
| 目标节点属于存在 owner、但唯一正式关系被定位后出现重复、关系事实自身 owner 不是存在 owner、错锚点 / 类型 / 角色、混代或生命周期不闭合 | `内部不一致` |
| L1 期望代次不符 | `事实代次漂移` |
| L1 许可 / 资源失败 | 同名状态 |

所有非成功返回空来源和零普通事实变化。单族服务不扫描其它族；七 owner 互异和跨族双接受由后续 provider 集成矩阵证明。

## 8. 创建、完整读取、属性与退出

### 8.1 新增存在节点

`新增存在节点` 的一份 owner-scoped 写集固定包含：

```text
节点本地键 0x0202'0001 -> 普通存在节点
关系本地键 0x0202'1003 -> 源=该节点本地键、目标=定位锚点、类型=定位类型、角色=1
```

成功 / 精确重复必须恰有两个不同新编码映射，节点和关系创建代次等于首次写入代次。发布后按首次代次读取 owner、节点、锚点、类型和关系历史事实，复用历史来源验证核心；只回节点、只回关系、自环、错 owner、错端点、错类型、错角色或混代均 `内部不一致`。公开结果继续返回原 `L2存在事实`，但只有来源闭合后才成功。

### 8.2 当前和历史完整读取

当前完整读取保留“选择项发现 + 完整投影”两段：

- 第一段在同一期望代次读取 owner、目标、锚点、类型、精确来源组，用正式来源判定后取得目标当前属性槽选择项；
- 第二段仍用同一期望代次，把相同来源项目与全部属性值选择项放进一份 owner-aware 一致投影；
- 最终事实只从第二段形成，并复核两段节点槽和来源材料相同。任一漂移或矛盾零部分载荷。

历史完整读取把历史 owner、目标 / 锚点 / 类型、节点创建代次定位出的归属关系、历史属性值组放入同一个前后代次夹取闭环；属性与来源都按请求历史截止投影，禁止用当前来源补历史。

`读取存在节点` 继续委托完整读取：当前使用截止 0，历史兼容入口以请求头期望代次作为历史截止；因此旧入口也不能绕过来源。`L2存在事实` 的固定属性形状、排序和材料映射不改变。

### 8.3 固定属性

`新增存在固定属性` 和 `换代存在固定属性` 的前置一致投影增加 owner、锚点、类型和精确来源组；只有正式当前存在才能写属性。wrong-family / unmarked 不再仅凭普通节点形状通过。属性写集和结果形状保持 E2 合同，仍由同一个存在端口提交。

### 8.4 退出

退出前用同一期望代次的当前完整来源 + 属性投影取得唯一归属关系，并要求它等于请求显式 `族归属关系稳定编码`。退出写集固定为：

```text
存在节点
+ 唯一族归属关系
+ 调用方严格升序列出的全部当前固定属性值
```

零 / 错关系编码入口拒绝或引用冲突；漏属性、外部场景 / 特征等当前引用仍由 L1 返回引用冲突。首次 / 精确重复发布后按写入代次读取节点、关系和属性历史事实，节点与族归属关系必须同代退出，属性按现行 E2 规则同代闭合；锚点和类型保持当前。当前来源随后固定 `已退出`，历史在退出前、退出代次和退出后均可读，达到退出代次时携带节点 / 归属关系完整退出生命周期。

## 9. 生产外验证矩阵

临时驱动只使用公开 L1 DTO / 运行包、公开 E-ID DTO / 服务和普通应用 provider，不访问仓库私有状态、不解析日志、不建立测试友元。矩阵至少覆盖：

1. 正确 owner 首次形成；错误建立幂等身份、旧共享范围、跨实例服务、缺端口和错 owner 交付均形成失败；包装不可默认构造 / 复制，raw 端口不能调用新服务构造；
2. 来源初始化首次成功；销毁服务、释放端口、同 owner 精确重复签发并重构服务后锚点 / 类型编码不变；固定登记幂等身份同键异写集冲突且零变化；
3. provider 正常装配、重复 getter 地址相同，普通上下文不公开端口 / owner；
4. 新节点与非自环归属关系同写、同 owner、同创建代次；首次与精确重复回同一节点 / 关系；同键异义幂等冲突；
5. 当前 / 历史来源和完整读取共享截止；节点创建前未找到，创建后已读取；晚于截止退出隐藏；
6. 另一 owner 的目标节点、v1 legacy 节点、构造服务前在存在 owner 预置的裸节点、锚点、类型均在当前 / 历史返回入口拒绝、空载荷、零变化；
7. 通过公开 raw L1 验证路径在端口释放后，以存在 owner 注入精确类型组的重复关系、错锚点、错角色和不同创建代次，当前 / 历史固定内部不一致；提前退出关系由历史判定截止空组 + 创建截止回退定位后固定内部不一致；
8. 当前目标已退出优先返回已退出，不补历史判断 wrong-family；历史退出前 / 退出代次 / 退出后均返回截止投影；
9. 固定属性新增 / 换代只接受正式存在；wrong-family / unmarked 零写拒绝；现行属性顺序和历史材料保持；
10. 退出请求零关系入口拒绝、错关系引用冲突、漏属性引用冲突、外部引用未闭合引用冲突；完整闭合后节点 / 来源关系 / 属性同代退出，锚点 / 类型仍当前；
11. 来源登记保留幂等值用于全部公开写时入口拒绝且事实代次不变；
12. 有界并发下当前完整投影只允许已读取 / 事实代次漂移 / 许可拒绝，历史前后夹取不返回混代 / 部分载荷；
13. L1 核心无新增 L2 import / friend / 枚举分支，生产无缓存权威、第二仓、第二成员表、恢复扫描或测试实体；
14. 根工程 Debug / Release x64 Rebuild 和临时参数工程 Debug / Release 全部通过。

无法通过公开 L1 正常 API 注入的仓库私有索引与返回字段自相矛盾，包括“关系事实自身 owner 与正式归属类型 owner 不一致”，只保留结构化 `内部不一致` 合同并记 `NOT_RUN`，不把“未观察到”写成已验证。F-ID、S-ID、T1、DYN2、A1、业务消费者和正式集成验收不在本矩阵。
