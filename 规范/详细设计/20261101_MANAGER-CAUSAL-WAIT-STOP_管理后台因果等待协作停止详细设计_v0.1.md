| 现执行点 | 冻结迁移 |

### 4.2 `构造自身发布后因果请求`

原`std::unique_lock 锁(新任务互斥)`改复用可停止task锁；解锁投影后，重新获取也必须用`获取因果读取任务锁(停止)`，不能留下`锁.lock()`长等盲点。原完整保护、子D身份、同步owner、原集合材料及唯一自身T归一化算法不变。

内部精确迁移：身份核验走`核验因果子需求身份内部(basis,D,停止)`；两处来源判断显式token；task锁外`查询服务任务(排除需求,停止)`严格取正常结果；调用`构造因果筹办请求(...,停止,&保护)`；D→T查询在持有task锁时可保留原递归单读，调用前后检查且不得在锁外退回无token。每次保护/特征/值域/需求读取前后检查；原成员组、条件组、候选事实组及规范化逐T循环每单位检查，`count/find/none_of`等枚举的谓词也须按单位检查；排序/去重前后检查。保留完整性、唯一性、规则、候选条件及最后保护合并，不能提前打`成员枚举完整`。

内部控制异常向新承接入口展开，不由`nullopt`、来源变化signal或诊断catch吞掉。原无token许可路径默认参数行为不变。必要范围概念可能由原请求构造/提议链建立，已发生者保留；本区取消只说明尚未开始本函数的因果采用/关联/激活，不许称全调用零写。

## 5. 因果承接写区、实际回执及前缀

### 5.1 唯一控制门与不可拆区间

task锁内完成reader、保护、父子身份、approved、旧采用不改绑等全部原检查后，紧邻`因果子需求依据_.try_emplace`之前执行最后一次`检查因果读取停止(停止)`。随后进入不可取消尾段，直到返回本次实际承接结果：

```text
最后检查
-> 标记写入已尝试
-> 同路径依据登记/复用
-> 建立需求任务关联(D)及其原内部完整读回/等待条件收束
-> 原锁外子准备批、因果执行许可、当前满足复核
-> 原task锁内许可/准备保护核同
-> 按原状态需要时激活及任务读回
-> 返回真实结果
```

这里的“不可拆”只指**不插工程取消**，不是新建跨owner原子事务，更不承诺每段必然成功。依据map、关联及激活仍按原多个真实操作发表，资源失败/来源变化可留下合法前缀；不伪报整段回滚。明确不在依据登记后、关联返回后、子许可/复核间、状态写入和读回间或新token wrapper返回前再检查停止；不可取消尾段调用私有构造/提议等如有间接token参数必须用空token，防止下层控制异常越过真实写入。manager收到正常回执后才检查自己的stop。

这是本叶安全与范围取舍：避免引入新的写后取消载荷、事务回滚或恢复ABI，代价是**整个写后尾段（包括读保护、许可、provider及取锁）仍可能长时间跨停止**，不只单次底层写。本叶不承诺消除所有此类manager超时；如真实反例位于该区，root另据证据裁决最小后继，不能把本设计静态通过当反例必然解除。

### 5.2 累积真实回执，不再返回空refused覆盖事实

承接新重载在try外持有一份`新任务治理承接结果`**本次调用累积结果**，初值与原refused一致（D、`任务操作未完成`），并用局部`bool 承接写区已进入=false`区分控制门。该bool只作栈内工程控制，不是业务事实，不进身份/DTO。累积只覆盖本次实际关联返回及其后续操作，不承诺本次回执包含前次调用的所有材料；跨调用已证前缀由第6.2节独立保存，不能用`写入已尝试`判断新回执比旧回执完整。

| 已到达边界 | 必须保留的结果 |
| --- | --- |
| 写门之前拒绝/资源延后 | 原正常非成功及载荷；停止可返回独立tag。已有正式事实不删除。 |
| 尝试登记依据 | 先置`承接写区已进入=true`、`结果.写入已尝试=true`；依据已存在则严格同basis/target复用，不覆盖。true仅说明尝试，不证明依据或T实际已发表。 |
| 关联返回 | 用无异常move保存`建立需求任务关联`本次完整真实结果，再OR保留本层`写入已尝试=true`；D定位不变。不得仅摘T编码或用refused覆盖本次已取得的建立/Vt/状态。关联资源失败可比前次回执更少材料，即使写入已尝试仍true；该正常回执如实返回，绝不据此删除manager历史槽或从历史槽拼出“本次当前任务”。 |
| 子准备、许可或保护失效 | 设置累积结果状态`任务操作未完成`，其已有建立结果、T、Vt及实际当前复核原样保留；不冒充已激活。 |
| 既有终结/目标已满足 | 原终结/已满足语义及实际材料，不重开旧X/A/K/R/U。 |
| 激活调用返回 | 先保存实际`重新启用结果`；非修改/无变化则返回累积的`任务操作未完成`，不得抹掉关联或该返回。成功后先读入局部任务，核同T/D/Vt身份及实际`待查找方法`状态，成立才move更新结果任务并标已重新启用；空/不一致则保留早先真实任务副本及激活返回、标`读回不一致`。不能用目标状态替代读回，也不能用空读回抹掉原T。 |
| 来源变化signal | 写门前按原拒绝；写门后只改变累积结果为未完成并保留前缀，不返回独立取消tag。 |
| bad_alloc/length_error | 写门前保原资源表示；写门后`状态=资源失败`并保留实际建立/任务/复核/激活字段，不将已建立的`建立结果`覆盖成新“建立资源失败”。未知异常继续向上。 |

新重载的`catch(因果读取停止信号)`必须先于其他catch；只允许在`!承接写区已进入`时返回tag。若写区内错误出现此信号，说明实现违背不可取消门，应进入工程错误链，不能吞掉或伪装完成。新wrapper不可像只读重载那样在返回后再检查stop。

读回失败、未知写入效果不补造T或状态；已持有的旧任务副本仅为该次真实读回，不改成原子当前快照。`写入已尝试`不等于成功、也不等于零写。原`建立需求任务关联`内catch与一般getter历史错误合同不在本叶扩大重写，必须把此剩余限制如实报告。

重入同一D仍先执行原完整fresh/保护/同路径检查；存在`因果子需求依据_`时不能改绑。在再次进入关联前，以原`查询需求任务(D)`及`读回需求任务(D,T)`核当前唯一T（若存在），一致时才续用同D幂等owner入口；不存在按原当前事实分支，不从上次资源失败推断零发表并另建D/T。读回不一致走工程链。**该重入读回只用于本次前置核验，不是“以后资源失败也有完整新回执”的保底，不将其旧状态副本补入后续更少材料的新回执**；本次前置核验后仍可能变化或失败。跨调用前缀保存不依赖这次核验是否重读成功，而由manager持有先前不可变实际回执。不得凭历史槽跳过fresh、当前正式读回、激活许可或触发新执行。

在task cpp增加静态断言：`新任务治理承接结果`的move construction及move assignment均为nothrow；真实回执在函数/variant/manager槽之间移动，不对已完成大材料再分配拷贝。承接正常返回明确构造`新任务因果承接可停止结果{std::in_place_type<新任务治理承接结果>,std::move(结果)}`（包括所有写后catch/提前出口），不能把累积结果作为左值转换给variant而再copy；原诊断返回宏可机械适配此形状，退出观察保留。若当前类型不满足，不能删断言换copy，须带具体类型退回本包设计；不得扩大公开DTO。

## 6. 只读等待复核与manager消费

### 6.1 task等待复核

新token复核保持不新增因果采用、D→T关联或任务状态写入的原复核算法：入口及`复核任务需求(父T)`前后检查；原task锁换可停止获取，需求读取前后、结算候选每项及最终消费单getter前后检查；fresh走既有可停止提议，先提取完整正常分支再判断依据相等；每个正常返回前检查stop。原fresh链仍可能按现合同建立范围概念，已发生者保留，不能称物理零写。`复核任务需求`及`提取已核验任务最终消费`内部保持原同步合同，不宣称其内部可抢断。

精确停止signal在新token边界收为tag，先于bad_alloc/length_error；原资源延后及正常变化合同不改，不借取消触发`条件发生变化需重新筹办`。错误不是取消；取消结果不携带半fresh，manager不得据此清等待、写来源变化或准备重新筹办。

### 6.2 本次回执与历史已证前缀分离

manager cpp仅在`实现`内部、`因果等待记录`之前定义以下私有类型，不增加公开DTO、公开读口或持久账：

```cpp
struct 因果子需求承接进度 final {
    std::shared_ptr<const 新任务治理承接结果> 最近本次回执;
    std::shared_ptr<const 新任务治理承接结果> 写入尝试依据回执;
    std::optional<std::pair<稳定编码, 稳定编码>> 已证任务与虚拟存在; // T、Vt
    std::shared_ptr<const 新任务治理承接结果> 身份依据回执;
    std::shared_ptr<const 新任务治理承接结果> 任务副本依据回执;
    std::shared_ptr<const 新任务治理承接结果> 虚拟存在副本依据回执;
    std::shared_ptr<const 新任务治理承接结果> 激活尝试依据回执;
    std::shared_ptr<const 新任务治理承接结果> 激活生效依据回执;
};
// 因果等待记录尾追加：
std::vector<因果子需求承接进度> 子需求承接进度;
std::optional<std::pair<新任务调度定位, 新任务操作状态>> 重新筹办前缀;
```

`最近本次回执`总是保存最新一次正常返回的**整个原值**，包括资源失败/未完成/空T或Vt；它不从历史补字段，不因旧成功改写本次状态。另六个“依据回执”只在该槽为空且出现下列真实依据时置入，之后永不被更少或更多材料的新回执覆盖。它们引用完整原回执，不复制/合并其中DTO字段，不构造跨次“累计当前快照”。同一实际回执可被多个槽引用。尝试证据与已证身份/效果分开，前者只保存已进入操作的工程进度，不据此宣称发表或生效。

| 历史槽 | 唯一准入及冻结规则 |
| --- | --- |
| 写入尝试依据回执 | 回执D核同且本次`写入已尝试=true`、本槽为空时引用本次完整原回执。允许尚无T/Vt；只证明进入过本叶写门后的尝试，不证明任何新节点/依据已发表，不能填身份或打承接成功位。即使后来一次写门前拒绝或空材料，也保留这项未知发表边界，不伪报零写。 |
| 已证身份＋身份依据回执 | 回执需求节点必须等于本项D。有`建立结果`且其状态为`已建立/已复用`、T/Vt均有效时，取该实际建立回执的T/Vt；或有实际`任务`副本且其D等于本项D、T/Vt均有效时，取该副本的T/Vt。二者同时存在必须同一对。单独失败建立结果中的候选编码、`写入已尝试`、父T或空载荷不能证明已发表身份。首次合格时同时钉住身份对及完整原回执；以后只核同，不改身份或依据指针。 |
| 任务副本依据回执 | 已取得上述身份对，本次实际`任务`副本的T/D/Vt与该对及本项D相同，且本槽为空时，引用本次完整原回执。不依据旧task状态合成本次状态；只证明该回执曾返回此副本，不证明此刻状态、唯一关联读回已全部成功或任务可执行。 |
| 虚拟存在副本依据回执 | 身份已锚定，本次实际`虚拟存在`副本的节点=Vt、任务节点=T且本槽为空时，引用本次完整原回执。单独无D锚定的Vt不能建立本项身份。与任务副本来自不同次也不组成共同快照。 |
| 激活尝试依据回执 | 身份已锚定、本次实际任务副本核同身份、实际`重新启用结果`有值且本槽为空时引用本次完整原回执，包含资源失败/未完成的实际返回。它只保留激活调用尝试及未知效果，不能冒充已生效；后续空激活字段不删除它。 |
| 激活生效依据回执 | 身份已锚定，本次实际`任务`副本核同该身份、实际`重新启用结果`为`已修改/无变化`且本槽为空时，引用本次完整原回执；不能仅凭历史T给一份无本次任务定位的枚举回执猜定激活对象。这只保存原激活owner实际回执，不证明现在仍处待查找方法，也不替代成功状态独立读回。失败或对象未锚定的激活结果仍完整保存在最近本次回执，不升级为已生效。 |

**冲突核验先于历史槽增量。** 只比较稳定身份，不把历史任务状态、候选、X、方法等可变字段作为新旧冲突：本次有实际任务副本时，其D必须等于本项D、T/Vt必须有效；本次有成功建立回执时，其T/Vt必须有效且与任务副本一致；本次有Vt副本且存在历史或本次合格身份锚定时，其T/Vt必须与该锚定一致。无身份锚定的单独Vt只保留原载荷，不猜D绑定、不凭该Vt晋升身份/副本/激活槽；独立写入尝试仍按其本来准入判断。任何已出现的上述正式身份对与历史身份不同、同一回执内部身份不一致、成功四态缺必需任务/Vt或回执D错误，均是工程不变量故障。先保存本次原回执，再报告原工程链，历史六槽/原成功位不变，不改绑、不任选、不先删除旧证据。非成功建立结果携带的未确认编码只保留原载荷，不冒充正式身份；没有新的合格身份/字段只是材料减少，不是旧事实消失。保存后必须维持身份pair有值当且仅当身份依据指针非空，任务/Vt副本及两个激活历史指针非空则身份必已锚定；写入尝试指针可独立存在，不得拿它补造身份或留下半登记。

**预分配与不可变交接。** 唯一等待记录构造点`提交因果筹办裁决内部`在原`子需求已承接.resize`旁按同一D数量resize默认空进度，仍在正式node_handle采用之前。每次准备调用task承接时，先在manager锁外`std::make_shared<新任务治理承接结果>()`预分配一个私有候选节点，失败则尚未调用task，按原资源路径保留等待；再检查停止，才调用新重载。tag返回时弃候选，不改任何正式进度。正常返回时将原值nothrow move到候选对象一次，随后用move转换为`std::shared_ptr<const 新任务治理承接结果>`，销尽唯一可变shared_ptr，之后不得保留可变引用/裸指针或修改节点。此冻结不是新发布业务事实。

随后普通manager锁内先以noexcept指针赋值更新`最近本次回执`，核全部身份，最后仅向空历史槽复制同一`std::shared_ptr<const 新任务治理承接结果>`并写固定标量身份/成功位；指向const载荷的指针本身可赋值，复制不分配控制块，不copy大DTO。整个保存区不检查stop、不push_back/resize、不做跨owner读取，不为一轮多个D结束后再统一保存。必须静态断言`新任务治理承接结果`、上述shared_ptr、身份pair optional及重新筹办pair optional的所用move construction/assignment为nothrow，并断言上述shared_ptr copy construction/assignment为nothrow；现有结果析构及指针释放不得触发业务调用/I/O。断言不成立须具名退回，不能改成写后make_shared或copy。

每D最多保留最近本次节点及六个首次阶段节点，最多七个不同完整回执节点，不保存无限重试历史；替换最近本次时，旧节点若仍被任一历史槽引用就继续存活，否则正常释放。材料减少的新尝试只替换最近本次，旧T/Vt/激活依据、未知发表的尝试边界及其完整原回执都仍在，故不因资源错误丢已证前缀。历史槽从不用于生成新业务结果、判断当前状态或代替fresh/当前正式读回。它们与等待记录同寿命，无外部持有者；原组织正常退出等待时才一起释放，停止取消不清记录，最终manager和依赖对象仍活到join完成。`重新筹办前缀`只保存实际定位/返回，不证明新的筹办已执行。

### 6.3 `尝试复核因果等待`精确顺序

本函数入口取`const auto 停止令牌=停止源.get_token()`，整批使用同源token，不每轮新建stop_source。

1. 复制批次前检查token，用既有可停止manager锁；锁内仍核原`停止/已完成/下一因果复核时点`。每记录复制前后、每子D开始检查。批次仍用原值式记录类型，但只显式复制原`定位/回执/依据/子需求已承接/来源已变化`五字段，两个新进度字段置空，不复制或共享正式历史槽到批次；正式槽始终是已移交进度持有处。已有已承接位不重做。token到达只退出本次函数，不改生命周期或新设业务取消；原主循环随后处理原停止。
2. 每次承接先完成6.2节单回执节点预分配，再检查stop并调用新task重载。tag立即正常return，候选释放，原等待/本次槽/历史槽/承接位/来源变化字段不改，不进入continue重试或下一个D。正常分支**先冻结并处理真实返回，不先检查stop**。
3. 正常回执到达后，按6.2节move一次冻结原值，再在普通manager锁（此保存不能被stop取消）内定位原记录，核`任务值/定位/回执/D序列及索引`精确一致。先保存最近本次原回执，再核稳定身份，最后只增空历史槽；绝不能把写入已尝试当覆盖准则、用新空载荷清历史槽，或把历史字段补到本次回执。仅原成功四态、必需材料及身份核验通过才将`子需求已承接[i]=true`并按原方式调度/notify；资源失败/未完成等不打成功位、不冒充已采用。
4. 保存时只改正式record，局部bool同步成功位供本轮原all_of使用。可通过已冻结const节点读取该次实际状态/T等，不访问已move走的variant载荷，不重新copy大结果。当前源码等待组仅在本函数尾部erase、提交端只插入/精确重复，因此同一manager线程处理中原项不会被另一个正常路径移除。若上述记录身份不符，视工程不变量故障而非把回执接到新记录；正式owner事实不回滚，不静默丢弃后继续。
5. 保存后仍按原承接返回分流：资源/尚未初始化/未完成不当成功，真实需求不存在/读回不一致/未知状态进入原工程诊断；错误不能因stop被吞。然后检查stop，已停止立即return；不得再启动下个D、读边或复核。此前完成的成功位/回执始终留在原等待记录，部分未成功保留同D原来源，重入只经第5节同路径读回/幂等核验续接，不依据`写入已尝试`盲重建。
6. 达到原all_of条件后，零子D路径同样检查。第一次边读取改为`读取因果等待边内部(nullptr,停止令牌)`；task复核改新token重载；tag正常return，正常结果先判完整状态/工程错误再检查stop，不能将tag参与与旧依据比较。
7. 原“仍等条件/既有入账待收尾”等分支、`来源已变化`原值及原条件保留。需重新筹办时，`读取任务调度材料`前后检查；它仍是单次不可抢断旧getter。进入`准备等待任务重新筹办`紧前最后检查；该调用及其原内部写入/读回不加取消。返回后先在普通manager锁内按同一记录身份保存`重新筹办前缀={实际定位,实际返回}`（无分配），处理原状态/工程错误后再检查stop。停止只保留此进度并return，不为完成退出等待再启动新读取。
8. 第二次边读取也传token，取消不清等待。边正常且仍相同，在锁外为`当前满足`分支预建同allocator的局部`std::set<std::uint64_t>`节点（键为任务值），尚不插入正式`等待目标复核`；分配失败时原等待及前缀仍在。最后用可停止manager锁，复核原定位/回执/执行保护/最近筹办；最后一次停止检查后，确需登记目标复核且正式set尚无此键时，用预建node_handle无分配插入，再完整完成原最近筹办/反馈/自我裁决/阻塞及等待退出、调度标志/notify。不存在先改正式set再检查stop的半提交；不在该组织提交中抛取消，不跨manager锁调用task。信号在最后检查后到达可完成这次已进入的提交，不伪报未发生。

尾部`catch(const 新任务因果读取取消&)`在bad_alloc与catch-all前，正常结束本次复核。`读取因果等待边内部`使用的既有控制tag正是此类型；task内部私有停止signal不得越过task公开variant入口。bad_alloc仍保留原等待/已保存进度，最终catch-all仍经`工程异常终止`，不改新停止策略、不把工程故障变业务材料。

## 7. 锁、生命周期及具名残余

复用原task recursive_mutex与manager mutex及原helper停车方式；不改mutex类型、锁序、10ms内部重试粒度。manager锁只复制/保存/提交组织，全部task跨owner调用在锁外；停止广播先请求原源再取manager状态锁不变。task→需求及既有领域调用方向不增反向边；provider仍在原锁外，子准备批/许可/当前复核仍按原unlock/lock顺序。写门后原重锁不可取消，这是刻意保留的收口区，不得偷偷复用有token的获取而在写中展开。

原旧STOP已批准的局部停车只用于取得同一既有下序锁，不等于等待业务/线程/future完成；本叶复用而不添加锁参与者/共享等待对象/回调。正常诊断I/O仍在业务锁外；原宏块/默认关闭及工程致命链保持，不能靠日志宏承担取消检查。

所有token、局部候选随栈退出，无异步回调/裸token指针；私有等待回执随manager存活到join。线程、依赖、宿主、四停止回执、5000ms、最终join、退出码、采集和广播入口均不变。不得detach、删等待、强杀、清数据或延长超时。停止取消不产生动作/状态/动态/需求/因果/学习/结算，已实际发布的范围概念、D/T/Vt/状态及来源不删不重签。
