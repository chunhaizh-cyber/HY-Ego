# 具体表达结构成文详细设计

身份：`CONV-EXPR-TEXT`；版本 v0.3（v0.2按Codex审计1修订；v0.3增第3.5节招呼成文）；日期 2026-11-08（v0.3：2026-11-11）；上位：CONV-MODEL v0.4 计划2；后继：CONV-INSTINCT 批1。设计与施工：交互窗口（Claude）；审计：Codex。

## 1. 目标

任意受支持形状的具体含义网都能成文并整段回读，替代只认“询问需求字段”一种形状的过渡转换，使 CONV-INSTINCT 的出站本能（询问词条概念、询问指代所指、询问分界、请求确认需求内容、询问是否需要帮助、询问服务对象需求）只需新增表达组织知识与描述结构，即可出句。

## 2. 当前事实与范围调整

1. 旧生成器 `生成基础语言表达`（`业务/表达.基础语言.cpp:1020`）的图路径 `生成图表达` 已是通用模板对齐：实例旧含义图的“出现”与知识模板逐节点对齐，按结构有序项成文；与具体构式无关。
2. 解释器 `解释单句含义图` 与生成器共用同一批描述结构和同一旧含义图类型 `语言图含义材料`；整段回读（`转换.语言场景基础.cpp:1213` 起）依赖解释器产出旧图再比对；采用含义U及其下游（接收需求认知、需求owner）读旧图。
3. 因此 CONV-MODEL §11.1“计划2拆除旧表示”在不同时改写解释器（计划3内容）的前提下无法成立。**调整**：本计划保留旧含义图作为成文与回读的内部中间表示，只拆除过渡转换；旧表示与23条知识的整体退出移到 CONV-INPUT（解释器直接产出含义网之时）。这是施工顺序调整，不改变任何机器语义；含义网仍是唯一对外的具体表达结构（出站留档、组织知识、正式表达需求均已是新表示）。

## 3. 设计

### 3.1 含义网投影（新，替代 `表达.含义网过渡.*`）

`业务/表达.含义网投影.h/.cpp`：`含义网投影旧图(const 新语言含义网&, const 新含义网投影上下文&) -> 新含义网投影结果{状态, optional<语言图含义材料>}`。

按内容项递归，一项对应一个旧图节点及一个出现；未列入下表的形状返回“形状未支持”（零输出，不截断、不丢弃算子或角色）：

| 含义网 | 旧图节点 |
| --- | --- |
| 静态：主体 + 概念归属(概念) | 概念归类；主体按指称类别取“领域对象引用/概念引用”，归类概念取“概念引用” |
| 静态：特征值(FT, 类型化整数) | 特征描述，分支准确值 |
| 静态：特征值(FT, 概念条件) | 特征描述，分支概念条件 |
| 静态：特征值(FT, 值域) | 特征区间描述；须读值域端点，本切片暂不支持，随批2需求确认接入 |
| 静态：特征值(FT, 方向) | 特征方向描述 |
| 静态：特征值(FT, 疑问代词) | 特征描述，特征值角色为查询变量 |
| 静态：概念归属(疑问代词) | 概念归类，归类概念角色为查询变量（新，批1“X是什么”） |
| 静态：同一指认(疑问代词) | 对象指认，另一指称角色为查询变量（新，批1“它指哪个”） |
| 态度[询问]，确认范围=填项内容 | 信息请求，提问范围，填项内容；子含义边“被询内容” |
| 态度[询问]，确认范围=真值 | 信息请求，提问范围，主张成立与否；子含义边“被询内容” |
| 态度[需要]（持有者） | 需求描述；子含义边“需求目标” |
| 态度[请求达成]（受请求者、提出者） | 外层行动请求（受请求者），子含义边“期望目标”指向内层需求描述（主体＝提出者，需求目标范围），内层再以“需求目标”边指向内容（与S14模板一致，一项对应两个节点） |
| 态度[请求执行]（受请求者，内容为动作发生） | 行动请求，期望目标为动作（批2“需要我帮你……吗”；动作发生成文能力不足时返回形状未支持） |

### 3.1.1 支持边界（审计1后冻结）

1. 旧图没有位置的信息不得丢弃：询问算子的询问者、受询者必须恰为本次成文的说话者、受话者；疑问代词必须绑定到最近的外层询问算子（`询问内容`），其网内编号作为待求变量编号；类型化整数的值类型必须等于该特征类型。不满足即整体“形状未支持”。
2. 主体为正式信息节点（需求、任务、方法）时，只支持特征值＝疑问代词（S10）；整数、方向、概念条件只支持普通存在主体（S03、H、S11、S14 模板）。普通存在主体的特征询问没有模板，不支持。
3. 概念作主体（S02）需概念owner区分存在概念与特征概念，投影不读owner，暂不支持；组成描述（S05）不在投影表内。
4. 未引用内容项等结构非法由 `核验含义网结构` 作为工程错误抛出，不转成“形状未支持”；非法方向枚举同样走工程错误；“已投影但无图”是内部合同破坏，调用方按工程错误处理。

旧中间表示需要的扩展（本计划内完成，CONV-INPUT 时随含义网整体承接）：`新语言知识含义操作` 末尾追加“对象指认”；`新语言知识角色类别` 末尾追加“查询概念”“查询对象”；`新语言知识参数角色` 末尾追加“另一指称”；生成侧查询变量词面按类别取“什么／哪个”，解释侧对称识别。追加不改变原枚举数值。

作用域由所在位置决定：顶层用途为疑问时其子树取提问范围，祈使取请求范围，态度内容取需求目标范围，其余普通陈述——与23条知识现行作用域一一对应。指称映射：绑定指称 → 引用值（正式信息节点类别用于需求/任务/方法，存在用于存在，概念用于概念，特征类型用于特征类型）；类型化整数 → 整数值；疑问代词 → 待求值。

### 3.2 生成入口

### 3.5 招呼成文（v0.3，2026-11-11）

依据：7240 第2.1节表达用途“招呼”（发起、维持或结束交往；顶层内容可为招呼套语；输入侧只保存为场景信息）；5380 第3.2节建立连接的正常操作（组织打招呼的表达需求 → 表达组织知识 → 含义网 → 成文）。本节只提供语言侧的出句能力；动作、留档、入列和本能登记属于建立连接（INSTINCT-CONTRACT 阶段6），不在本节范围。

1. **含义网**：`新表达用途`末尾追加“招呼”；内容项末尾追加招呼含义单元，承载 7240 的“招呼套语”，种类为发起、维持、结束（`新招呼种类`）。核验：顶层用途为招呼，当且仅当顶层内容是招呼单元；招呼单元不得被其它内容项引用，也不引用其它项。顶层内容为空的招呼本节不支持（现有出句都用套语）。
2. **正式表达需求**：表达对象末尾追加`正式表达招呼{种类}`；表达需求类型的对象种类取其 variant 序号。
3. **组织器**：招呼对象按`{招呼, 招呼对象序号}`查询适用的表达组织知识；无适用条件、无取材步骤；模板为“顶层 招呼 内容1；1 招呼 种类=请求种类”。模板种类与请求种类不同时，该知识不成立。同一种类有多条成立知识时，返回“多规则待选”：选用哪种说法属于自我意识（5380 第1节），本节不规定。种子只放一条“发起”。
4. **投影**：招呼单元 → 旧图节点。种类由含义操作区分：`新语言知识含义操作`末尾追加“招呼发起”“招呼维持”“招呼结束”，作用域为普通陈述，零角色、零参数、无子含义，不改变旧图节点的存储字段。`新语言知识表达目的`末尾追加“招呼”。
5. **生成与回读**：旧生成器接受目的为招呼、根节点为招呼操作的零角色图，按描述结构的有序项（只含词项）成文；解释器对称识别，供整段回读使用。输入侧解释出招呼图时，下游按 7240 只保存为场景信息、不形成需求；现有下游若没有招呼分支，就按未理解处理（零输出），不得因此新建需求或抛出工程错误。
6. **种子**：`最小语言知识种子.txt`新增描述结构“S16招呼发起”（目的 招呼；图节点 1 招呼发起 普通陈述；项 0 词 你好；随附结构概念与模式行，格式与 S10 相同）；`表达组织知识种子.txt`新增组织知识“打招呼”（适用 招呼 招呼对象；模板 顶层 招呼 内容 1；1 招呼 种类=发起；缺材 必需不足）。载入器补对应的解析分支。
7. **语言服务**：新增`业务/招呼.语言服务.h/.cpp`，入口为`生成招呼话语(种类, 说话者, 受话者, 成文参数, 读取依赖)`，返回`{状态, 文本, 所用知识, 含义网, 所用组织知识}`，处理顺序为组织 → 投影 → `从基础信息生成可回读单句` → 结果映射，状态映射同第4节；只读，不写场景、不入列。接口类放在同名头文件中。装配和本能侧接入由建立连接施工（INSTINCT-CONTRACT 阶段6）完成，本节不改`装配.普通应用.cpp`。
8. **非成功**：同第4节。缺描述结构或缺组织知识时返回“缺知识”，对应 5380 第3.2节“打招呼所需语言知识齐备”运行时复核的零动作分支。
