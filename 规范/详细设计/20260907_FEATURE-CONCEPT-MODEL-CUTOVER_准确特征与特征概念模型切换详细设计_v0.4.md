## 1. 来源、继承与完成边界

本版本继承 v0.2 与 v0.3 未被明确改写的准确 F、I64 类型域、FT 共享观察、C / 多父 DAG、名称、用途及治理、旧 v1 派生审计、Gread/H 历史见证、旧 ABI 物理删除和 14 个源码白名单。本次仅修正下列关联设计缺口：

1. v0.3 在场景模块重复定义了与特征应用 owner 不同形状的 `特征概念观察请求`；
2. `特征概念应用预算`、`特征概念继续材料`、`存在当前采用请求_v2` 和其结果没有唯一 owner 或完整字段；
3. v0.3 场景结果仍引用即将物理删除的旧 `场景组合投影` / `共享特征实例事实`；
4. 完整场景原请求不能单独重建已经以特定 G 和幂等身份派发的 `存在当前采用写请求`；
5. `概念树存在扩展交付` 没有冻结精确构造接入面；
6. 名称有限读取的 8 项基础预算与特征概念专项预算未分账；
7. 特征概念多阶段应用的预算是否跨 provider 全局累计未裁决。

正式 0050 v3.6、7150 v0.3、7160 v0.2、1130 / 4110、7110 v1.5、7140 v1.6、4230 v0.34 与 4240 v0.24 足以在原目标内唯一裁决。完成条件仍是 14 个直接消费模块全部迁移，旧五字段、旧场景联合阶段机和旧概念流程物理删除，并通过隔离 Debug/Release x64 Rebuild。

## 3. 场景成员值式合同

### 3.1 公开 DTO

以下类型只定义在 `海中鱼巣/业务/应用服务.场景成员概念类.ixx` 的导出命名空间。所有字段顺序固定，不可追加阶段标志、临时键、隐式 self 位置或第二份 provider 请求。


`E` 当前采用的目标不由意图再传一份 F；它唯一等于本次特征应用确认的单一 F。这样新 F 在请求前尚未取得身份时仍可同次继续，也不会出现“传入 F 组后由应用选一项”的隐式裁决。`采用` 为空时只完成 F/C/名称和场景投影，不写 E；非空时使用 `存在关联已知并采用{已确认F, 原采用预期}`，由存在 owner 同笔保证已知引用和当前采用闭合。

### 3.2 成功谓词

`场景特征概念结果_v2::成功()` 只在下列全部成立时为真：版本 2；`处理.状态 == 特征概念处理状态::完成`；`0 < H <= Gread`；F/C/名称三项均存在；F 读回的 Gread/H 等于外层；处理结果中准确匹配只含该 F，概念与名称等于已确认项；F 的 FT 等于 C 的 FT；名称精确连接 F→C；C 和名称在 H 有效。服务设置完成前还必须在同 Gread/H 调用正式域命中能力证明 F 适用 C；纯值谓词不重做比较算法。

`场景组合投影_v2::完整()` 只核对版本 2、`Gread == H != 0`、S/E 和场景成员关系、F 完整读回、C 定义与生命周期、F→C 名称及可选 E/FT→F 采用是否逐项同截止有效。`场景成员概念结果_v2::成功()` 还要求总状态完成、特征子结果成功、无继续材料、最终投影完整且完全等于子结果的 F/C/名称；有采用结果时它自身成功且目标为同一 E/FT/F，投影必须含同一采用事实。应用只在请求未要求采用时生成无采用投影，因此“要求采用但结果缺失”不得置为完成。

### 3.3 公开入口与严格顺序

```cpp
场景成员概念结果_v2 处理场景成员概念(
    const 场景成员概念请求_v2&);
场景成员概念结果_v2 收敛场景成员概念(
    const 场景成员概念继续材料_v2&);
```

服务持有 `概念树类数据服务&`、`const 场景类数据服务&`、`存在类数据服务&`、`特征概念应用服务&` 和 `存在概念树应用服务&`。场景及概念根绑定继续校验；删除 `特征概念应用服务::使用存在服务` 及任何同义绑定调用。可写存在引用不取得 owner 端口。

处理顺序固定：

1. 在任何写入前验证 DTO 版本、S/E、`0 < H <= Gread`、所有非零预算、采用幂等身份及 provider 绑定；在请求 Gread/H 完整读取场景并证明 S 直接含 E。
2. `处理` 入口调用 `处理类型观察(请求.观察)`；`收敛` 按阶段先对结果中精确 `概念原请求` 调用 `收敛特征概念写入`，再调用 `收敛类型观察(原请求.观察)`。若特征 F 创建只存在应用实例内 pending，继续材料的阶段为“特征应用”且两个 provider 原请求均空；只允许同一 `特征概念应用服务` 实例收敛，跨进程或换实例返回不支持，不重建 F。
3. 特征结果完成后选择概念 owner 的当前 G，以该 G 作 Gread/H 完整读回 F、C、F→C 名称，并用正式域判定互证。多 F、多名称或多个不可唯一互证的 C 返回多义，不选首项。
4. 请求未携带采用意图时跳过 E 写入。携带时，以存在 owner 当前 G 形成唯一 `存在当前采用写请求{1,G,幂等身份,E,FT,存在关联已知并采用{F,原采用预期},关系预算}`；派发前先把该精确请求写入继续材料，失败只可以同一请求调用 `收敛当前采用`。
5. 取得最后当前 G 后，以 `Gread=H=G` 逐项读回 S→E 直接成员、F、C、F→C 名称和可选 E/FT→F 采用，才可生成最终投影。每个子结果保留自身真实 G/H；最终 G 不覆写任何子结果。

数据写入前的入口、场景成员、预算、历史或绑定失败零 F/C/E 写入。F/C/E 任一已发布后的后继失败保留真实事实和已确认子结果，返回对应继续材料；不声称跨 owner 回滚。

### 3.4 继续材料与恢复边界

继续材料是应用返回的非权威值，不是新数据字段、持久恢复账或第二写入入口。它必须保存完整场景原请求、明确阶段以及已派发 provider 的精确原请求；不得只保存“已到哪一步”或重算幂等键。

`概念写入` 阶段必须只有 `概念原请求`，`存在采用` 阶段必须只有 `采用原请求`，`最终读回` 两者均空；形状不符返回入口拒绝。同键异义、原 G 不同或原请求与场景请求无法逐字段互证时返回幂等冲突，不换键。只有特征 F 创建 pending 依赖原应用实例，此限制与 v0.2 一致；概念和存在写请求都可按精确 provider 原请求收敛。

## 4. 预算冻结

### 4.1 特征概念应用预算

`特征概念观察请求.预算` 是本次高层处理中每个专项 provider 公开调用的单次上限，不是跨 `读 F→登记观察→读图→建 C→登记命中→变更名称` 所有 provider 调用的全局共享计数器。各 provider 函数对自己实际读写的不同记录、区间、命中、名称和首次材料在该次调用内累计；不截断，超限零该次写入。

应用和场景继续不保存“剩余预算”，不从先前成功调用的计量中扣减下一 provider 调用。收敛仅重放继续材料中原请求的同一预算；provider 精确重放读回原结果，不因重放新增事实。不新增用量、剩余量或阶段累计 DTO。这是对 v0.2 “按实际不同记录累计”的调用边界明确，不改变 provider 内部的非零预算和零载荷失败语义。

### 4.2 场景和存在预算

`场景关系预算` 是每次场景历史/当前直接成员读取的独立上限；`存在当前采用意图_v2.关系预算` 是每次存在已知及采用组读写的独立上限。两者均非零，超限返回各 provider 的数量预算不足；读不返回伪完整投影，写不发布截断关系组。

## 5. 名称有限当前读取

v0.3 的两个请求名称、字段顺序、Gread/H 和函数签名保留，预算类型确认为 `概念树预算`。这两个新函数是独立窄读内核，禁止转发 `读取共享名称字段` 或为满足旧内核伪造 `特征概念预算` / `概念树共享预算`。

基础 8 项均按现有 `概念树预算` 合同校验非零；未用的项不虚假扣减。按 F 读取以 `最大世界成员数` 限制待核对 F 端点（固定消费 1），以 `最大关系数` 限制命中的当前 F→C 名称关系；数量大于 1 返回内部不一致且零载荷。按 C 读取以 `最大概念数` 限制 C 端点（固定消费 1），以 `最大关系数` 限制当前名称关系总数，以 `最大世界成员数` 限制不同 F 端点总数。任一不足返回数量预算不足和零载荷；成功按关系稳定编码升序。

两个读取都只校验指定 H 时有效的名称关系与两端身份；不读取区间、观察、命中、用途、形成依据或首次材料，不扣特征专项预算。每条返回真实生命周期，但不枚举 H 之前已退出关系。

## 6. EC 抽象依据交付的精确装配面

`概念树存在扩展交付` 字段保持 v0.3：

```cpp
struct 概念树存在扩展交付 final {
    稳定编码 抽象依据目标关系类型{};
    friend bool operator==(const 概念树存在扩展交付&,
                           const 概念树存在扩展交付&) = default;
};
```

它不并入基础、动态、旧共享或 `特征概念结构交付`，而是以最后一个非 optional 形参只新增下列两个构造重载：

```cpp
概念树类数据服务(const L1事实基座服务&, const 特征类数据服务&,
    const 存在类数据服务&, const 特征值类数据服务&,
    L1所有者范围写端口&&, const 概念树结构交付&,
    const 特征概念结构交付&, const 概念树存在扩展交付&);

概念树类数据服务(const L1事实基座服务&, const 特征类数据服务&,
    const 存在类数据服务&, const 特征值类数据服务&,
    L1所有者范围写端口&&, const 概念树结构交付&,
    const 场景类数据服务&, const 动态类数据服务&,
    const 概念树动态扩展交付&, const 特征概念结构交付&,
    const 概念树存在扩展交付&);
```

现有两个无存在扩展的新 24 角色构造重载保留，供 F/C 和其它无 EC→EC 依据的能力使用；这些实例的 EC 依据创建、读取、图展开、反向保护、退出、释放和原键恢复一律返回 `概念树数据状态::不支持`。基础、动态、旧共享四类构造面不新增此形参。

扩展构造先委托到对应的 24 角色构造，再保存和校验交付。`抽象依据目标关系类型` 必须非零、是当前合法关系类型，并且与基础/动态全部角色及 `特征概念结构交付.类型` 全部 24 项均不同。尤其，新 24 角色的一基序 16/17 仍唯一表示 C→形成依据记录/形成依据记录→FT|观察|并集来源 C；EC→EC 不得等于或借用其中任一角色。

合法装配可以显式把一个历史上曾用作旧 `shared_[15]` 的真实关系类型编码传入本独立字段，以保留存量 EC 物理布局；这只是显式交付同一真实节点，不允许服务从旧 shared 数组、编码位置或存量关系自动推断，也不将它重释为新 24 角色。

## 7. 迁移、删除与错误分账
