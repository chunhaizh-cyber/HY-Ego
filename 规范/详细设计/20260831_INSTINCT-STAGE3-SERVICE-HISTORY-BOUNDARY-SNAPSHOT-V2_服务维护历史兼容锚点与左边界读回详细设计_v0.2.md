# INSTINCT-STAGE3-SERVICE-HISTORY-BOUNDARY-SNAPSHOT-V2 服务维护历史兼容锚点与左边界读回详细设计 v0.2

日期：2026-08-31

状态：目标详细设计；代码实施以现行计划索引登记为准

## 1. 目标与问题

现有 `按事实代次范围读取服务维护历史事实完整组_v1` 只返回形成事实代次位于 `(Gstart,G0]` 的五类事实。若某个合同、合同状态、服务进展或服务准备在 `Gstart` 前已经当前，并在区间内退出，范围结果只包含后继；`G0` 当前集合也已经移除旧事实，后继组合器无法恢复左边界。

本设计在现有唯一 `服务合同事实权威服务` 内建立一个新的不可变兼容锚点，并提供 `Gstart` 左边界与区间变化的一次正式读回。它不建立第二业务事实 owner，不复制当前权威，不形成单调秒事实段。

完成边界：

```text
正式兼容锚点 Gseed
+ 锚点时当前四类事实
+ (Gseed,G0] 五类永久历史
-> 任意 Gstart in [Gseed,G0] 的左边界完整快照
+ (Gstart,G0] 完整变化
```

本入口位于维护工程边界，不建立认知证明体系：合同、合同状态、到期事件、进展和准备是业务治理事实；`Gseed/Gstart/G0`、预算、永久索引和集合完整性是保证这些事实不漏、不重、不混代次的工程材料。结果不得持久化为状态、动态或因果，不得进入根需求比较或自我学习。后继 maintenance composer 只能把成功快照收束成维护业务结论，不得把工程字段原样透传上层。

## 2. 正式依据与冻结裁决

依据：0050、4015、4040、4050、6160、6170，现有服务维护历史账详细设计 v0.1，以及当前 `服务合同事实权威.数据.h`、`服务.服务合同事实权威.ixx`。

冻结裁决：

1. 采用“显式新维护覆盖起点”而不是追溯猜测旧历史。v2 覆盖登记首次成功提交代次是 `Gseed`；本入口只接受 `Gstart >= Gseed`。
2. v2 登记形成前已经退出的事实不可恢复，也不伪造为合法空历史。后继激活必须把维护游标显式迁移到 `Gseed` 的新维护时间纪元；本叶不修改游标。
3. v2 登记把 `Gseed` 时当前的合同+状态、进展 v2、准备 v2 作为种子加入五类 v2 永久历史根。到期未满足事件是一次性区间事件，不进入左边界种子。
4. v2 历史成员永久保留目标节点，使种子 incumbent 后续退出时仍可读回；更新 writer 只退出旧当前关系，不再退出目标节点、载荷、业务引用和 v2 历史关系。
5. `Gseed` 后形成的五类事实同时进入现有 v1 和新增 v2 永久历史账。现有 v1 请求、结果、状态数值、成功谓词和 `(Gstart,G0]` 语义原样保留。
6. 左边界读取只回答事实代次历史，不把形成事实代次当成单调完整秒或同秒发布序；正式秒映射仍是后继独立门禁。
7. 当前生产固定值保持：值域 `0..INT64_MAX`，`L=2767011611056432742`，`H=7378697629483820645`，安全根定义版本 1，主动安全结算规则版本 1。
8. `G0` 终态互证是 owner provider 在返回 `已读取` 前必须完成的内部后置条件，不是公开 `成功()` 对任意值对象能够重新证明的来源真实性。快照不携带第二份 `G0` 当前集合或终态投影。

登记幂等身份：

```text

```

v2 种子成员按下列规范键严格升序；五根各自成员关系顺序恒 1：

```text

-> 事实身份稳定编码
-> 事实版本
-> 形成事实代次
-> 目标节点稳定编码
```

种子身份由首次规范写集中的五根成员关系和目标事实载荷共同重建；不另存第二份业务载荷。v2 历史根只承担永久成员索引，不参与当前选择。

## 4. 数据合同

### 4.1 module-private v2 历史成员

```cpp
inline constexpr std::uint32_t 服务维护历史边界合同版本_v2 = 2;
// 仅在服务实现 module 内定义，不从公开数据模块导出。
inline constexpr std::uint32_t 服务维护历史覆盖结构登记版本_v2 = 2;

struct 服务维护历史覆盖成员_v2 final {
    服务维护历史事实类别_v1 类别;
    稳定编码 目标事实节点;
    稳定编码 事实身份;
    std::uint64_t 事实版本;
    std::uint64_t 形成事实代次;
};
```

首次种子只允许类别：服务合同、合同状态、服务进展、服务准备。登记后的变化成员允许五类。

### 4.2 请求

```cpp
struct 服务维护历史边界读取请求_v2 final {
    std::uint32_t 合同版本 = 服务维护历史边界合同版本_v2;
    L2结构请求头 请求头;          // G0
    L2存在身份 自我;
    std::uint64_t 左边界事实代次; // Gstart
    std::uint64_t 左边界数量预算;
    std::uint64_t 变化数量预算;
};
```

请求有效性：共同请求头现行版本，`G0 != 0`，自我有效，`Gstart != 0`，`Gseed <= Gstart <= G0`，两个数量预算均非零。

### 4.3 左边界合同投影

```cpp
struct 服务维护历史左边界合同投影_v1 final {
    服务合同历史投影_v1 合同;
    服务合同状态历史投影_v1 当前状态;
};
```

合同与状态按合同身份一一对应。两项形成代次均不晚于 `Gstart`；若退出代次存在，必须大于 `Gstart` 且不晚于 `G0`。每个左边界合同在 `Gstart` 必须仍属于该 self 的当前有效未满足集合：`当前状态.事实.状态 == 服务合同当前状态_v1::有效未满足`，且 `已消费有效秒 <= 合同.事实.冻结有效总秒`。终态合同不得作为左边界当前合同返回；其在区间内形成的状态和到期事件只进入变化组。

### 4.4 维护工程完整范围快照

```cpp
struct 服务维护历史边界完整范围快照_v2 final {
    std::uint64_t v2覆盖登记事实代次; // Gseed
    L2存在身份 自我;
    std::uint64_t 左边界事实代次;   // Gstart
    std::uint64_t 包含结束事实代次; // G0
    std::uint64_t 声明左边界成员数;
    std::uint64_t 声明变化成员数;
    std::vector<服务维护历史成员身份_v1> 规范左边界成员身份组;
    std::vector<服务维护历史成员身份_v1> 规范变化成员身份组;

    std::vector<服务维护历史左边界合同投影_v1> 左边界合同组;
    std::vector<服务进展历史投影_v1> 左边界进展组;
    std::vector<服务准备历史投影_v1> 左边界准备组;
    std::vector<服务合同历史投影_v1> 合同变化组;
    std::vector<服务合同状态历史投影_v1> 合同状态变化组;
    std::vector<服务到期事件历史投影_v1> 到期事件变化组;
    std::vector<服务进展历史投影_v1> 服务进展变化组;
    std::vector<服务准备历史投影_v1> 服务准备变化组;
};
```

左边界成员组只列合同、合同状态、进展、准备；变化成员组允许五类。两组分别严格升序、无重叠，数量与八个向量承载的九类事实投影逐项一致。合同状态是服务合同的业务治理状态，不是 1160 状态节点，也不得进入特征当前值比较。

整个快照只允许承载请求 `自我` 的投影：合同、进展和准备事实自身的 `自我` 必须等于快照 `自我`；合同状态和到期事件不直接携带 self，必须通过“左边界合同组 + 合同变化组”的唯一合同身份表解析到同一 self，缺失、多义或跨 self 引用均不闭合。foreign self 的合法事实不进入载荷、声明成员或两个数量预算；但 owner 全局历史根自身损坏仍整体失败，不因 self 过滤而隐藏。

快照把范围绑定、成员身份和强类型载荷收束为一个不可拆分的低层工程结果，避免消费者把“已读取 + 空向量”误解释为合法空历史。它不携带第二份 `G0` 当前合同、当前状态、当前进展或当前准备投影；这些集合只在 provider 内与重放终态互证。它不是认知事实；maintenance composer 只允许调用 `结果.成功()`并逐字段绑定请求中的 self、`Gstart/G0`，不得复制 owner 的枚举、归组、排序、恢复或 `G0` 当前根互证算法。

### 4.5 状态与结果

```cpp
enum class 服务维护历史边界读取状态_v2 : std::uint8_t {
    已读取 = 1,
    入口拒绝 = 2,
    当前性漂移 = 3,
    v2历史账未登记 = 4,
    覆盖边界不可用 = 5,
    左边界不可恢复 = 6,
    左边界预算不足 = 7,
    变化预算不足 = 8,
    集合不闭合 = 9,
    引用冲突 = 10,
    版本漂移 = 11,
    资源失败 = 12,
    内部错误 = 13
};

struct 服务维护历史边界读取结果_v2 final {
    std::uint32_t 合同版本 = 服务维护历史边界合同版本_v2;
    服务维护历史边界读取状态_v2 状态 =
        服务维护历史边界读取状态_v2::入口拒绝;
    std::optional<服务维护历史边界完整范围快照_v2> 快照;
    std::uint64_t 本次正式读回截止 = 0;
    bool 成功() const noexcept;
};
```

只有 `已读取` 携带唯一完整范围快照，且 `本次正式读回截止 == 快照.包含结束事实代次 == 请求.G0`。全部非成功快照为空、截止 0。

公开 `成功()` 是纯值式载荷形状谓词，至少同时验证：状态唯一为已读取；快照存在；合同版本、self、`Gseed <= Gstart <= G0`和正式读回截止闭合；两个成员身份组分别规范有序、无重复、互不重叠；八个向量中的九类事实投影均完整且位于声明范围；两个声明数量与成员身份组、投影总数一致；每个声明成员在载荷中恰命中一次且每个载荷成员有且仅有一个声明身份；全部直接或经合同解析的 self 绑定闭合；左边界合同状态为有效未满足且消费秒不超过冻结总秒。合法空集只有在上述完整性全部成立且相应声明数为零时成立。

`成功()` 不读取 owner，也不验证任意调用方自行构造的值来自正式 provider，因此不承担 `G0` 权威来源证明。provider 只有在内部重放所得 `G0` 当前有效未满足合同及状态、当前进展、当前准备，分别与既有正式当前读回逐字段相等，且 `G0` 读后守卫成立时，才能返回 `已读取`；任一不等返回 `集合不闭合`、零快照、截止 0。到期未满足事件是区间事件，不属于 `G0` 当前根。

## 5. 构造、恢复与兼容更新

### 5.1 首次 v2 覆盖登记

构造顺序固定为：既有五类登记 -> v1 历史账登记 -> v2 覆盖登记。

首次锚定在一个 owner 写集前执行同 `G0` 完整读取：

```text
当前有效未满足合同及唯一当前状态
+ 当前进展 v2
+ 当前准备 v2
```

形成规范种子成员组后，同一写集创建 12 个登记资源与版本，并把四类种子分别加入对应 v2 永久历史根。提交代次固定为 `Gseed`；种子成员必须在 `Gseed-1` 当前，提交本身不改变业务当前关系。

### 5.2 精确恢复

恢复只接受首次幂等写集和当前投影逐项闭合：固定 owner、固定 12 键、版本 2、五根成员与目标事实逐项一致、目标载荷可解码、种子在首次提交前确为当前。任何部分建立、错 owner、错版本、漏成员、重复或成员异义使服务构造失败，不降级 v1 或空 v2 账。

v2 首次写集取决于首次提交时当前事实，恢复不得用恢复时当前集合重新构造首次写集；必须从首次规范写集 / 映射重建种子并验证其权威目标。

### 5.3 后继 writer

`发布服务进展事实_v2`、`发布服务准备事实_v2` 更新旧事实时增加分账：

```text
旧事实有唯一 v2 永久历史成员
-> 只退出旧当前成员关系
-> 保留旧目标节点、载荷、业务引用和 v2 历史关系

旧事实缺 v2 永久历史成员
-> 集合不闭合 / 内部错误，零新业务写
```

新事实同步加入 v1 与 v2 永久历史账。精确重复复用首次写集，v2 登记永不建立第二份种子。

合同、状态、到期事件当前没有生产 writer；本叶不新增第二 writer。未来 writer 必须执行同一 v2 历史分账后才能进入生产。

## 6. 读取算法

目标函数：

```cpp
服务维护历史边界读取结果_v2
服务合同事实权威服务::按事实代次边界读取服务维护历史完整快照_v2(
    const 服务维护历史边界读取请求_v2& 请求) const noexcept;
```

固定流程：

```text
请求与 G0 读前守卫
-> 读取并验证 v2 覆盖登记和五类 v2 永久历史根
-> Gstart < Gseed 时返回覆盖边界不可用
-> 先验证全局历史根结构，再只投影请求 self；foreign self 不计载荷和预算
-> 从 v2 种子建立 Gseed 当前四类状态
-> 按形成事实代次重放 (Gseed,Gstart] 五类历史
-> 每个退出必须有正式退出当前关系，每个后继必须有唯一流前驱
-> 得到 Gstart 左边界有效未满足合同+状态、进展、准备
-> 收集 (Gstart,G0] 请求 self 的五类变化
-> 在 provider 内以全部历史和 G0 正式当前四类读回互证重放终态
-> 分别执行左边界预算和变化预算
-> 规范排序并形成唯一完整范围快照
-> 运行公开载荷成功谓词与 G0 读后守卫
-> 返回成功或结构化非成功
```

本入口使用形成事实代次只重建 owner 当前版本连续性，不把它解释为业务发生完整秒。若无法确认某流的唯一前驱 / 后继、退出边界、self 归属或 provider-private `G0` 终态，返回`左边界不可恢复`、`引用冲突`或`集合不闭合`。

## 7. 验证矩阵

至少覆盖：

1. 空种子、1/N 合同+状态、1/N 进展、1/N 准备；
2. 种子成员在区间内退出并出现唯一后继；
3. 种子成员保持到 G0；区间内首次形成后退出；区间内形成并保持当前；
4. `Gstart=Gseed`、`Gstart=G0`、`Gstart<Gseed`；
5. G0 当前为空但左边界非空；左边界为空但区间有变化；
6. v2 历史成员关系永久保留，更新只退出当前关系；
7. v2 登记错 owner、错版本、漏 / 多 / 重成员、坏载荷、坏目标；
8. v1 历史漏项、重复、已退出历史关系、坏引用和版本连续冲突；
9. 总预算恰好、少 1、合法 0/N；
10. 读前 / 读中 / 读后漂移、资源失败、异常及全部非成功零载荷；
11. 精确恢复、持久恢复、首次写集异义；
12. 现有 v1 范围读取回归不变；
13. Debug / Release、外部 ABI consumer、strict、diff-check；
14. 两个 self 的事实交错形成和更新：读取 A/B 分别只返回本 self，foreign self 不进入载荷、声明成员或预算，全局根损坏仍整体失败；
15. 对成功快照逐项替换合同、进展或准备 self，或把状态 / 到期事件改绑另一 self 合同，公开 `成功()` 必须为 false；
16. 左边界合同状态改为任一终态，或消费秒超过合同冻结总秒，公开 `成功()` 必须为 false；终态合同不得留在左边界当前组；
17. 测试专用注入使历史重放所得 `G0` 与正式当前四类集合任一不等，provider 必须返回`集合不闭合`、零快照、截止 0；不得把第二份当前集合加入公开 DTO；
18. 静态确认无第二 owner、无生产 fixture、无 L/H 重算、无游标推进、无 composer 调用，且 module-private 键、结构版本、内部成员和登记幂等身份未从公开数据模块导出；
19. ABI consumer 只能取得低层工程请求 / 状态 / 快照 / 结果，快照没有第二份 `G0` 当前终态投影，且任何上层认知或自检结果均不含 `Gseed/Gstart/G0`、预算、成员身份组或完整性字段。

## 8. 后继与未证明范围

直接后继必须先完成维护游标对 `Gseed` 的显式激活 / 新纪元迁移；之后再冻结五类事实到“生效完整秒 + 同秒阶段 + 正式发布序”的映射。只有这两项完成，事实段 composer 才能消费本入口。

本设计不形成有效服务活动、低位回升安全因果门禁、合同财务结算、准备补回、正式秒序、有限事实段、批量候选、A/V 写入、状态 / 动态 / 因果、游标推进、普通应用接线或阶段三完成。它只建立低层维护工程输入的完整交付边界，不建立新的认知证据类型。

## 9. v0.2 修订说明

v0.2 裁决公开 `成功()` 与 provider 内部后置条件的边界：不新增 `G0` 终态投影，补齐跨 self 投影约束和左边界有效未满足合同形状，并增加相应验证门禁。v0.1 的 owner、键段、请求 / 结果字段、状态数值、持久结构、恢复和后继 writer 裁决不变。
