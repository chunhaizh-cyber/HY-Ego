# INSTINCT-STAGE3-SERVICE-CONTRACT-FACT-OWNER 服务合同事实权威与完整集合详细设计 v0.1

日期：2026-08-29

设计状态：现行目标设计；等待计划创建侧验证和登记后施工

## 1. 目标与完成边界

本设计为 `INSTINCT-ROUTE` 阶段三建立服务合同事实的唯一持久 owner，以及服务合同和到期未满足事件的同截止完整集合读回。它解决当前 `组合.运行期只读查询.ixx` 四次读取同一“按自我全部当前状态”而无法区分合同、准备、进展和到期事实、也无法证明全集完整的问题。

本切片完成后必须具备：

```text
唯一服务合同 owner 和结构登记
+ 当前有效未满足合同的同 G0 完整集合读回
+ 到期未满足事件的同 G0 完整集合读回
+ 合法空集合的机器见证
+ 非空、重复、损坏、漂移和资源失败的结构化结果
```

本切片明确不完成：

```text
服务需求准入
合同建立与 30% 预支的有限 N 原子发布
合同终态与 70% 余款
到期事件生产
服务准备、有效活动和主动安全门禁组合
服务值衰减、安全根回归、维护游标推进
生产人类请求接线
```

生产装配只建立 owner 与结构登记，不自动建立空合同、测试合同或到期事件。合法空集合来自唯一 owner 在 G0 的完整成员关系闭包确实为零，不来自“查询没有返回材料”。

## 2. 正式依据与当前事实

直接依据：0050 v2.1、6100 v0.5、6120 v0.10、6160 v0.4、6170 v0.6。

当前代码事实：

1. `运行期只读查询.数据.h` 仍以四组 `L2状态事实` 表示合同、准备、进展和到期；没有服务合同强类型身份、状态、到期事件或完整集合见证。
2. `组合.运行期只读查询.ixx` 对四组分别调用相同的 `按主体读取全部当前状态`，无法区分事实种类，也不能证明全量覆盖。
3. `服务.L2治理函数骨架.ixx` 的服务生存入口仍是结构化桩。
4. 当前没有服务合同 owner、合同建立生产者、到期事件生产者或有效活动 provider。
5. L1 已提供 owner 范围当前 / 历史读取、关系类型一致闭包和有限 N 分区原子事务 v3；本切片只复用 owner 范围写入完成结构登记和 fixture，生产合同写入留给后继有限 N 事务。
6. 安全根 L/H 是可随正式定义版本调整的 I64 阈值；当前生产定义版本 1 保持 `30% / 80%` 不变。本设计只读依赖版本事实，不定义或改变阈值。

### 4.2 完整集合见证

```cpp
struct 服务合同完整集合见证_v1 final {
    std::uint32_t 结构登记版本;
    std::uint64_t 声明成员数;
    std::vector<服务合同身份_v1> 规范成员身份组;
    std::uint64_t G0;
};

struct 服务到期事件完整集合见证_v1 final {
    std::uint32_t 结构登记版本;
    std::uint64_t 声明成员数;
    std::vector<服务到期未满足事件身份_v1> 规范成员身份组;
    std::uint64_t G0;
};
```

见证完整必须证明：

1. owner、登记锚点和入口关系类型在 G0 全部当前有效；
2. L1 一致关系类型闭包成功且读取截止精确等于 G0；
3. 成员身份严格升序、无重复，声明数等于身份组数；
4. 每个成员的节点、关系和载荷逐字段闭合；
5. 返回事实组的身份投影与见证身份组逐项相同；
6. 没有漏项、额外项、混合 owner、已退出成员或未知载荷版本。

成员数为零只有在上述 1—5 全部成立且关系闭包成员确为零时合法。裸空 vector、未找到、数量预算不足、读取失败或 owner 未登记都不是合法空集合。

### 4.3 读取请求和结果

```cpp
struct 服务合同完整集合读取请求_v1 final {
    std::uint32_t 合同版本;
    L2结构请求头 请求头; // G0
    L2存在身份 自我;
};

struct 服务到期事件完整集合读取请求_v1 final {
    std::uint32_t 合同版本;
    L2结构请求头 请求头; // G0
    L2存在身份 自我;
};
```

读取状态统一为：

```text
已读取
入口拒绝
许可拒绝
当前性漂移
结构未登记
集合不闭合
引用冲突
资源失败
内部错误
```

成功必须返回规范有序完整事实组、完整集合见证和精确 `G0`。全部非成功返回空载荷、截止 0。读取前后必须重新核对当前事实代次仍为 G0；不得把跨代次拼接结果作为成功。

公开入口：

```cpp

读取当前有效未满足服务合同完整集合_v1(
    const 服务合同完整集合读取请求_v1&) const noexcept;

读取到期未满足事件完整集合_v1(
    const 服务到期事件完整集合读取请求_v1&) const noexcept;
```

本切片不公开合同建立、状态迁移、到期事件发布或消费入口。后继 `SERVICE-C1` 必须在本模块内部形成合同 owner 参与写集，并与服务值当前值、状态和动态一起通过 L1 有限 N 事务最后发布；不得先单独发布合同再补预支。

## 5. 持久结构

登记写集建立：

```text
结构登记锚点
当前有效合同索引根
到期事件索引根
当前有效合同成员关系类型
合同当前状态关系类型
合同各外部引用关系类型
合同载荷属性类型
合同状态载荷属性类型
到期事件成员 / 合同 / 目标未满足引用关系类型
到期事件载荷属性类型
```

合同、合同状态和到期事件均是永久历史事实。当前有效合同只由索引根到合同的当前成员关系表达；合同进入终态时退出该关系，不删除合同或旧状态。合同当前状态只由合同到状态事实的唯一当前选择关系表达；迁移退出旧选择并建立新选择。

到期事件是不可变历史事实。本切片只读全部正式事件；后继维护按维护游标和事件边界消费，不能通过删除事件或把空查询当已消费。

## 6. 装配与调用边界

普通应用构造时从同一 L1 运行包取得专属 owner 交付，构造唯一 `服务合同事实权威服务` 并由上下文持有。构造只完成 owner 与登记，不形成合同或事件。

阶段三后继基础材料组合器的合法调用顺序为：

```text
冻结 G0
-> 读取本能被动维护基础快照
-> 读取当前有效未满足服务合同完整集合
-> 读取到期未满足事件完整集合
-> 读取活动 / 主动安全 / 低位回升门禁提供者
-> 读后守卫仍为 G0
-> 才形成单秒规则输入
```

当前 `运行期只读查询` 占位模块不在本切片修改面；后继消费计划必须停止生产使用其四次同义状态读取，但不得在本 owner 计划中顺带重写整个治理 WIP。

## 7. 验证矩阵

至少覆盖：

1. owner 与结构首次登记、同进程重构恢复、重启持久恢复；
2. 当前合同 0 / 1 / N 和到期事件 0 / 1 / N 的合法完整集合；
3. 身份规范排序、重复、乱序、额外成员、漏成员；
4. 合同预算、30% 预支、余款、时间和版本边界的完整性拒绝；
5. 当前有效索引只含 `有效未满足`，终态合同不能进入成功载荷；
6. owner / 登记缺失、关系复义、载荷版本未知、外部引用缺失或已退出；
7. G0 读前 / 读后漂移、资源失败和内部错误；
8. 非成功空载荷 / 截止 0；合法空集合仍有非零截止和完整见证；
9. Debug / Release 根工程、仓库外 ABI consumer、普通应用唯一构造；
10. 生产源码没有自动合同、自动到期事件、测试 fixture 或独立合同写入调用。

专项允许在验证宏下直接形成结构 fixture，以覆盖非空和损坏分支；fixture 不进入普通应用生产调用图，不证明人类请求、合同准入、预支或 SERVICE-C1 业务闭环完成。

## 8. 完成声明边界

本设计完成的代码结果最多证明：服务合同与到期事件已经具备唯一结构 owner 和同截止完整集合读回，生产无合同状态可以被证明为合法空集合。

不得据此声明：合同可以由人类请求建立、30% / 70% 已结算、到期事件可以生产、有效活动已裁决、服务值维护或安全根回归已接线、阶段三或 `INSTINCT-ROUTE` 已完成。
