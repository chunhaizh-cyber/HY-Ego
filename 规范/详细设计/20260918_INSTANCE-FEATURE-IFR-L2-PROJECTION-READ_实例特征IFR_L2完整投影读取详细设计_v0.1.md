# 实例特征 IFR L2 完整投影读取详细设计 v0.2

读取只调用既有 `L1事实基座服务` 的当前事实代次、历史节点、历史关系组和历史属性值组接口；每次读取后重新核验读回代次仍等于请求 Gread。它不使用写端口。

空 IF/R 是合法 `未找到`，由 L3 解释为首个 R；任何已出现的半结构、重复关系、错误 owner/type/direction、属性槽缺失或多值均为 `引用冲突` 或 `内部不一致`，不由 L2 解释业务意义。预算计数包含已读取的所有相关关系；不足即返回并清空投影。R项的材料属性读取以 v2 `R项材料属性类型` 为唯一允许类型，U64组以 `{格式版本,类别,规范化载荷...}` 反序列化。

对 H 时刻活动关系，`角色或顺序` 与目标稳定编码共同构成形状合同，L2 不得按 L1 返回顺序推断或重写角色：

| 关系组 | 读取与回显顺序 | 必须的角色值 | 偏离结果 |
| --- | --- | --- | --- |
| `E→IF` | 唯一关系 | `1` | `引用冲突` |
| `IF→R集合` | 唯一关系 | `1` | `引用冲突` |
| `R集合→版本` | 唯一关系 | `1` | `引用冲突` |
| `IF→F` | 目标 F 稳定编码严格升序 | 第 i 条为 `i`，`i=1..N` | `引用冲突` |
| `版本→R项` | 目标 R项稳定编码严格升序 | 第 i 条为 `i`，`i=1..N` | `引用冲突` |
| `R项→F` | 每个 R项内目标 F 稳定编码严格升序 | 第 i 条为 `i`，`i=1..N` | `引用冲突` |

投影承载所有节点和关系的编码、创建H、可选退出H及关系的 `角色或顺序`；当前成功投影仅含 H 时刻活动事实。R项、IF 成员和每项形成成员均按上表顺序保存，使后续预期快照逐字段比较不依赖底层返回顺序。形成成员的集合并集必须恰等 IF 成员集合；不等即清空投影并返回 `引用冲突`。

每个 R项在 H 必须有且仅有一个材料属性值。该值的属性类型为 v2 `R项材料属性类型`、载体为 U64组、来源节点为该 R项自身；来源节点不等于该 R项、属性类型/载体不符或存在多值均返回 `引用冲突`。仅当这些结构条件满足后才按 `{格式版本,类别,规范化载荷...}` 反序列化为 `特征R区间材料`；载荷不能规范化反序列化时返回 `内部不一致`。读取不创建属性槽或值，也不尝试迁移历史记录。

## v0.2 修订

本版依据用户确认冻结单值关系 role `1`、成员关系按目标稳定编码升序的 `1..N` role 编码，及 R项材料 U64组值的来源节点必须为 R项自身。它补齐 v0.1 未明确的排序、角色、值来源与失败分类，不改变 L2 零写、同截止或后续 L3 的职责边界。
