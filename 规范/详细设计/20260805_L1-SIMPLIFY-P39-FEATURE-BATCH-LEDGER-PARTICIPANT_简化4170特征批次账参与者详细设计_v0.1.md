## 1. 目标与完成边界

本叶原位扩展 P38 唯一 `L1实例特征批次数据操作`，实现节点直接新域 4170 已发布记录账的具体附属事务参与者，并新增一个只供后继实例特征领域发布者使用的内部提交根：

```text
调用方给出的 L1 v2 完整写集 + 特征批次发布记录草案
-> 参与者在 P37 第一写前取得本账独占许可并最终复核批次未发布
-> 用 P37 候选见证的规范化写集和本地键映射解析完整稳定编码记录
-> 逐项证明4170记录与本次L1写集、退出和属性槽变更一一对应
-> 在同账内形成不可见候选、确认、逆序撤销
-> 与L1候选共同关闭撤销、共同发布同一事实代次
-> P15同锁通用读回成功后释放账许可；矛盾则隔离全账后释放
```

成功或精确重复只返回调用方拥有的不可变记录副本和 L1 首次映射。该结果仍是领域数据操作的内部提交结果，不解释 P36 规格、不证明公开初始特征批次请求同义、不替代后继业务服务的 provider 前幂等探测和完整批次准入。

本叶不聚合 P36 规格，不生成公开批次身份、幂等键、请求意图摘要或执行证据摘要，不构造 L1 写集/读回计划，不分配稳定编码，不提供 P32 第二写门面，不形成生产装配、持久证据、恢复、全量冻结或运行期接线。

## 3. 所有权、物理位置与依赖方向

原位修改 P38 三个目标文件，不新增模块、自检根或启动顺序：

```text
海中鱼巣/领域/L1特征批次账.数据.h
海中鱼巣/领域/数据操作.L1实例特征批次.ixx
海中鱼巣/领域/自检.L1特征批次账.ixx
```

`L1实例特征批次数据操作` 继续唯一拥有本域4170账、共享/独占许可、候选、发布和隔离状态；P37核心桥只编排业务中性生命周期，不解释记录。后继实例特征业务服务只构造完整请求、草案和摘要，不接触参与者对象、锁或候选。

依赖方向固定：

```text
未来实例特征完整批次发布者
-> L1实例特征批次数据操作::提交带特征批次记录
   -> 私有 L1特征批次发布记录参与者
      -> P37 L1事实基座服务::提交写集_内部附属参与
         -> P15/P37 唯一 L1 提交算法

读取消费者
-> L1实例特征批次数据操作::读取发布记录（P38，签名不变）
```

数据操作从本叶起以构造注入保存非拥有 `L1事实基座服务&`。P38 的公开默认构造替换为：

```cpp
explicit L1实例特征批次数据操作(L1事实基座服务& L1) noexcept;
```

P38 尚未形成生产装配且无正式生产构造调用点；P39 激活时必须从 P38 真实结果重新枚举调用点并只迁移其自检夹具。禁止保留无 L1 provider 的可提交对象、nullable 指针、setter 或双构造语义。`读取发布记录` 不调用该引用，读合同和非阻塞行为不变。

## 4. 记录草案与内部提交结果

在 `L1特征批次账.数据.h` 追加领域内部纯值 DTO。草案引用直接复用 L1 `事实引用=variant<稳定编码, 写集本地键>`，只描述本次写集中的稳定事实或新事实本地键；它不是公开世界树 DTO。

```cpp
inline constexpr std::uint32_t L1特征批次参与合同版本 = 1;

struct L1特征批次节点草案见证 final {
    事实引用 编码;
    节点种类 种类 = 节点种类::普通;
};

struct L1特征批次关系草案见证 final {
    事实引用 编码;
    事实引用 关系类型;
    事实引用 源节点;
    事实引用 目标节点;
    std::int64_t 顺序 = 0;
};

struct L1特征批次值草案见证 final {
    写集本地键 编码;
    事实引用 所属节点;
    事实引用 属性类型节点;
    事实引用 来源节点;
};

struct L1特征批次发布项目草案 final {
    std::uint32_t 顺序号 = 0;
    L1特征批次项目种类 种类 = L1特征批次项目种类::初始;
    L1特征批次节点草案见证 特征定义;
    L1特征批次节点草案见证 实例槽;
    L1特征批次关系草案见证 宿主关系;
    L1特征批次关系草案见证 定义关系;
    L1特征批次值草案见证 新当前值;
    L1特征批次节点草案见证 来源;
    std::optional<L1特征批次值见证> 写前当前值;
};

struct L1特征批次发布记录草案 final {
    std::uint32_t 参与合同版本 = L1特征批次参与合同版本;
    std::uint32_t 记录格式版本 = L1特征批次记录格式版本;
    std::uint64_t 业务规则版本 = L1特征批次业务规则版本;
    L1特征批次身份 批次;
    L1特征批次节点草案见证 宿主;
    std::vector<L1特征批次发布项目草案> 项目组;
};

enum class L1特征批次附属提交状态 : std::uint8_t {
    已提交 = 1,
    精确重复 = 2,
    入口拒绝 = 3,
    未找到 = 4,
    已退出 = 5,
    事实代次漂移 = 6,
    幂等冲突 = 7,
    许可拒绝 = 8,
    未知格式 = 9,
    资源失败 = 10,
    内部不一致 = 11
};

struct L1特征批次附属提交结果 final {
    L1特征批次附属提交状态 状态 = L1特征批次附属提交状态::入口拒绝;
    L1特征批次身份 批次;
    写集幂等键 幂等键;
    std::uint64_t 事实代次 = 0;
    bool L1发布已存在 = false;
    std::vector<std::pair<写集本地键, 稳定编码>> 新编码映射;
    std::optional<L1特征批次发布记录> 记录;
};
```

全部结果回显输入批次和 L1 写集幂等键。仅 `已提交`、`精确重复` 携带完整映射和记录；`L1发布已存在` 对二者为真，其中精确重复只表示首次发布已存在、不表示本次推进代次。发布后 P15 读回矛盾或参与者隔离结果必须回显已发布事实代次并令 `L1发布已存在=true`，但映射/记录为空，不得伪装成部分成功。发布前非成功回显 P37/L1 安全取得的当前代次，`L1发布已存在=false`。本内部结果不承担持久证据状态，固定为不适用；后继公开业务结果另行冻结持久状态字段。

草案不携带发布事实代次；该字段只能由 P37 `待发布事实代次` 和最终 `完成发布并保持许可(已发布事实代次)` 建立。草案不携带原始材料、摘要副本、许可、锁或参与者地址。

## 5. 草案形状与 L1 写集一一对应

草案在参与者 `第一写前复核` 前不作会访问 provider 的解释；真正完整校验只发生在 P37 首次路径的参与者回调内。同义 P15 短路时参与者全部方法必须为0次。

共同要求：

1. 三版本精确为1，批次、宿主和项目组非零/非空，顺序恰为 `0..N-1`；宿主、定义、来源必须是非零稳定编码普通节点，定义和实例槽分别唯一，来源可重复；
2. 草案全部本地键必须非零且在 P37 映射中恰一命中；全部稳定编码必须非零；解析后必须通过 P38 `L1特征批次发布记录完整`；
3. 规范化 L1 写集不得含本批次之外的节点、关系、值、退出或属性槽变更。草案对五类写项形成精确全覆盖，任何遗漏、重复或夹带为内部不一致；
4. P15 通用读回计划必须精确覆盖每个新节点/关系/值、每个换代旧值退出、每个属性槽新当前值，以及草案引用的必要既有宿主、定义、来源、实例槽和结构关系；空、重复、错当前性、错代次或额外业务对象拒绝；
5. P37 写前见证中的期望当前事实代次、幂等键、请求意图摘要和执行证据摘要必须与传入 `L1写集请求` 完全相等；参与者不重算或解释摘要。

初始项固定：

```text
实例槽编码 = 本次节点新建本地键，节点种类普通
宿主关系/定义关系编码 = 本次关系新建本地键
新当前值编码 = 本次值新建本地键
写前当前值 = 空
L1写项 = 1节点 + 2关系 + 1值 + 1属性槽变更
退出事实 = 0
```

两关系端点、类型、顺序和值所属槽/属性类型/来源必须逐字段等于草案；属性槽变更必须把同一实例槽+属性类型指向同一新值本地键。

换代项固定：

```text
实例槽、宿主关系、定义关系 = 已发布稳定编码见证
新当前值编码 = 本次值新建本地键
写前当前值 = 非空已发布稳定编码见证
L1写项 = 1值 + 1属性槽变更 + 退出写前当前值
新节点/新关系 = 0
```

写前值与新值所属槽、属性类型相同且编码不同；退出组必须恰含全部换代写前值且无其它编码。草案本叶支持初始、换代和混合形状，但不提供形成这些草案的公开业务入口。

## 6. 数据操作根函数

新增唯一内部根：

```cpp
L1特征批次附属提交结果 提交带特征批次记录(
    const L1写集请求& 请求,
    const L1特征批次发布记录草案& 草案);
```

函数固定流程：

1. 初始化结果并回显草案批次及请求幂等键。只校验参与合同/记录格式/业务规则、非零批次和请求最小 L1 v2 形状；不在调用 P37 前读取本账或解释草案项目。
2. 在同步栈构造私有 `L1特征批次发布记录参与者`，只保存请求 const 引用、草案 const 引用和本数据操作引用；不复制 provider 材料，不把引用保存到调用外。
3. 调用 `L1_.提交写集_内部附属参与(请求, 单参与者span)` 恰一次。不得先调用公开 `提交写集`，不得二次提交。
4. 若 P37 返回参与者失败见证，按 `许可拒绝/幂等冲突/资源失败/内部不一致` 无损映射；发布前载荷为空。撤销失败或发布后读回失败按 P37 已发布事实代次和隔离状态返回内部不一致。
5. 若 L1 首次提交成功，参与者必须已完成发布并释放许可，返回参与者持有的完整记录副本、首次映射、已提交和新代次；任一坏成功为内部不一致。
6. 若 L1 返回精确重复，参与者方法必须0次。函数忽略本次草案项目和执行证据；对同一账尝试取得一次共享许可，按输入批次二分定位已发布记录，同时互证内部提交绑定的首次 L1 幂等键与本次键相同、首次请求意图摘要与本次意图摘要相同、记录发布代次等于 L1 首次代次。全部成立才返回精确重复。未找到、许可拒绝、未知格式、资源失败、绑定矛盾和记录损坏保持各自分类，不得补造记录或把缺账当成功。
7. 其它 L1 结果逐类映射；所有非成功清空记录和映射。函数不 sleep、不重试、不访问 SQL/材料/旧账。

精确重复分支不得重新解析草案、比较本次执行证据或比较后来 provider 结果，保持 P15“同意图重试不重算执行证据”的边界。内部提交绑定只保存首次键、首次意图摘要和首次执行证据摘要；本分支仅比较前两者。最终业务发布者仍须在调用 P36 等 provider 前先执行 P15 幂等探测与 P38 批次预读；本根的精确重复分支只收敛预读后并发首次提交。

## 7. 私有参与者状态机

私有参与者实现 P37 `L1事实附属事务参与者`，阶段固定为：

```text
已构造 -> 已复核持锁 -> 候选已准备 -> 已确认 -> 已关闭撤销
-> 已发布持锁 -> 已释放
或任一发布前阶段 -> 已撤销
或撤销不完整/发布后读回矛盾 -> 已隔离释放
```

各回调：

- `第一写前复核`：校验 P37 写前见证与请求绑定；try-lock 本账独占许可，失败立即许可拒绝；检查全账未隔离、批次精确未命中、无重复/候选泄露。命中一律返回幂等冲突，因为同意图同键应已由 P15 短路，业务同义预读由上层承担。
- `准备候选`：在持锁状态解析全部本地键，逐项核对规范化写集/读回计划，构造发布事实代次为 P37 待发布代次的完整记录；以批次升序插入唯一不可见候选。分配失败返回资源失败，其它矛盾返回内部不一致。
- `确认待发布`：只验证候选位置、记录完整、阶段和许可并转为已确认；`noexcept`。
- `完成撤销`：发布前按确定位置删除候选，清空自有材料并释放许可；重复撤销幂等返回已撤销；`noexcept`。
- `关闭撤销能力`：只切换阶段，不分配、不解锁；`noexcept`。
- `完成发布并保持许可`：传入代次必须等于候选记录发布代次，把候选状态改为已发布但继续持有独占许可；`noexcept`。
- `释放已发布许可`：只在已发布持锁阶段释放，记录从此可由 P38 读取；`noexcept`。
- `完成隔离并释放`：把本账和相关记录单调标记隔离，保留已发布记录/候选证据，不删除已发布事实，然后释放许可；`noexcept`。

P38 内部升序容器在本叶精确固定为 `std::vector<std::unique_ptr<内部记录>>`：vector 按 `记录.批次` 严格升序，unique_ptr 保持记录对象地址稳定且移动无抛出。候选插入的记录分配和 vector 扩容全部发生在准备阶段；撤销只移动无抛出 unique_ptr 槽并 erase，最后发布区只改枚举/布尔和解锁。P38 实际结果若使用其它表示，P39 施工必须在同一数据操作文件内迁移为该形状并保持 P38 公开读取不变；若无法在白名单内完成则退回计划支撑。

每个内部记录槽除 P38 已发布记录和内部阶段外，还保存不可公开的 `L1特征批次提交绑定`：首次 L1 幂等键、首次请求意图摘要和首次执行证据摘要。绑定由 P37 写前见证建立，与候选共同确认、撤销、发布或隔离；它不进入 P38 公共记录 DTO，不由普通读取返回，也不成为 L1 幂等账的第二权威。它只用于证明本账记录确实从同一 L1 首次事务产生，以及收敛 P15 精确重复。未来恢复设计必须把该绑定与 L1 幂等账共同互证，本叶不设计持久格式。

析构只作防御：关闭撤销前仍持锁则显式撤销；关闭撤销后或已发布但未释放则标记全账隔离后释放。析构成功不能替代 P37 显式生命周期。

## 8. 并发、幂等、异常与生命周期

P37 L1 独占事务域先于本账独占许可；P38 普通读取只取得本账共享 try-lock。固定锁序：

```text
L1事务域独占许可 -> 特征批次账独占许可
```

参与者持有本账许可覆盖第一写前最终复核、候选、确认、L1 swap、P15同锁读回和释放/隔离。因此普通读取看不到候选，也不会在 L1 通用读回完成前看到已发布标记。参与者不得在持本账许可时反向调用 L1、P8、P36、SQL、材料或旧账。

两个相同批次并发首次请求由 L1 独占域串行：同 L1 幂等键/意图由 P15 返回精确重复且参与者0调用；异义由 P15冲突；若错误地以不同 L1 键复用批次，后到参与者在第一写前得到4170幂等冲突。P39不替最终发布者派生或解释这两个身份。

允许抛出/分配的只有根函数构造、第一写前复核和准备候选；异常分别映射资源失败或内部不一致并进入 P37 撤销。确认、撤销、关闭撤销、发布、释放、隔离和析构均 `noexcept`。引用和 span 只在同步提交调用内有效，参与者、数据操作和桥均不得保存调用方引用到返回后。

## 9. 与 P36/P37/P38/P15 的分账

- P15：唯一拥有 L1 双摘要幂等、首次映射、通用读回、失败见证和 L1 隔离；P39只绑定现成请求，不重算摘要。
- P37：唯一编排参与者顺序和 L1 原子发布；P39不复制提交算法、不公开参与者。
- P38：唯一拥有4170记录形状、账和读取；P39只原位增加候选/发布生命周期，读取签名和状态不变。
- P36：事实所有者形成单项初始规格；P39不读取规格，不解释值域或世界归属。
- 后继最终发布者：唯一聚合 P36 规格、固定业务幂等和摘要、本地键、L1写集/读回计划并把本根结果映射为公开批次结果。
