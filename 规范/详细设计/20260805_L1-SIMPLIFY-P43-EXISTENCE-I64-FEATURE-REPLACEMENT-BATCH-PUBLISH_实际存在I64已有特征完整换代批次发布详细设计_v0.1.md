## 2. 业务闭环与完成条件

新增实例特征领域业务类及唯一公开根：

```text
公开完整换代批次请求
-> 纯值准入并形成唯一0x0F L1键和请求意图摘要
-> P15 provider前探测 + P38 provider前预读
-> 双账已存在时只用首次结果和4170记录完整互证并幂等读回
-> 双账均未找到时逐项调用P42
-> 一次校验完整规格集合
-> 形成N个新值、N个属性槽切换、N个旧值退出的确定性L1 v2写集
-> 形成通用读回计划、执行证据摘要和全换代P39草案
-> P39/P37/P15恰一次单事务提交
-> 返回本批次0..N-1完整有序换代结果
```

完成必须证明：写前所有项目仍在同一非零截止；一批只推进一次事实代次；旧值全部在该代次退出、新值全部在该代次创建并成为唯一当前值；实例槽和两结构关系保持原编码当前；4170记录与结构同事务发布；同批同义读回原结果，同批异义零写冲突；任何失败不返回部分项目。

## 5. 批次身份、L1键与双摘要

初始和换代共同使用 4170 域内唯一批次身份和同一 L1 幂等域：

```text
L1幂等域 = 0x0F
1 <= 批次.值 <= 0x00FFFFFFFFFFFFFF
L1幂等键.值 = (uint64(0x0F) << 56) | 批次.值
```

同一批次不能先作为初始再作为换代，也不能映射第二 L1 键；P15/P38 任一已存在语义不同即冲突或内部不一致。

P43 领域操作标签固定为 `U32 0x00010F02`。请求意图摘要按 P15 标准编码：魔数、格式版本、操作标签、顶层合同/规则、批次、期望代次、项目数及每项 P42 请求全部字段声明顺序。它不含 P42 返回、新稳定编码、本地键、锁或执行分支。

执行证据摘要只在双账未找到并形成完整规格后编码：请求意图摘要、P42/P38/P39/P15合同版本、共同截止、全部 P42 规格、规范化 L1 写集、规范化通用读回计划。使用 P15 标准 SHA-256，全零为内部不一致。

## 6. provider 前双账收口

固定顺序：

1. 纯值校验顶层和项目集合；失败入口拒绝，provider调用0。
2. 形成 0x0F L1键和请求意图摘要。
3. 调用 `L1_.探测幂等` 恰一次；异义、隔离、坏记录或许可非成功立即返回。
4. 调用 `批次数据操作_.读取发布记录(请求.批次)` 恰一次；保持许可/未知格式/资源/损坏分类。
5. 双账组合只允许：

| P15 | P38 | 收口 |
| --- | --- | --- |
| 未找到 | 未找到 | 进入 P42 首次规格路径 |
| 精确同义首次结果 | 已读取同批次完整全换代记录 | 互证首次键、摘要、发布代次和全部读回后返回幂等读回 |
| 仅一侧存在 | 任意 | `内部不一致`，不得补写 |
| 任一异义/隔离/损坏/许可失败 | 任意 | 原分类或内部不一致，P42调用0 |

幂等互证逐项要求：记录种类全为换代；批次/规则/宿主/数量/顺序、定义、槽、两关系、写前值及旧来源、新值及新来源与公开请求一致；P15 首次完整读回证明旧值在记录发布代次退出且历史材料/来源等于请求，新值在该代次创建、材料/来源等于请求，属性槽指向新值，槽与两关系仍当前。任何缺失、额外、重复或错代次整体内部不一致。

## 7. 首次 P42 规格集合准入

双账均未找到时，按容器顺序逐项调用：

```cpp
实例特征_.形成实际存在I64已有特征换代写入规格(项目请求)
```

每项恰一次；任一非 `已读取` 立即映射返回，已形成规格销毁，P39调用0。全组一次验证：

- 合同/规则完整，顺序恰为 `0..N-1`，全部截止等于顶层期望代次；
- 宿主事实、宿主读取见证和世界根全组相等；
- 定义、实例槽、写前当前值各自唯一；宿主关系和定义关系各自唯一且不跨项复用；
- 四登记见证全组相等且完整互异；
- 每项写前读取见证、写前事实、两关系、写前来源资格逐字段一致；
- 新值在定义闭区间；新值等于旧值合法；新来源与宿主同世界；
- 不允许空规格、坏成功、排序后解释、去重后丢项或跨宿主拼批。

规格只在同步栈内存续，不形成缓存或第二账。期间事实推进由 P15 期望代次零写拒绝。

## 8. 确定性写集、读回计划和 P39 草案

第 `i` 项唯一新值本地键固定为 `i + 1`，数量门禁保证 uint32 不溢出。规范化写集：

```text
节点 = 0
关系 = 0
值 = N：所属=既有实例槽；属性类型=P42当前I64值属性类型；材料=新值；来源=P42新来源
属性槽变更 = N：既有实例槽 + 当前I64值属性类型 -> 同项新值本地键
退出事实 = N：同项写前当前值稳定编码
```

退出组按项目顺序形成且编码唯一。不得建立新槽/关系、退出结构关系、夹带其它当前值或调用 P10。

通用读回计划精确覆盖：

```text
全部新值和N个当前属性槽（期望本次发布代次）
+ 全部写前当前值历史/已退出见证（退出代次=本次发布代次）
+ 去重后的共同宿主、全部定义、实例槽、两结构关系
+ 全部写前/新来源节点及P42提供的实际存在资格见证
+ 四个登记节点见证
```

既有结构见证以共同固定截止校验；新值和旧值退出以本次发布代次校验。计划不得为空、重复、遗漏或加入本批次之外业务对象。

P39 草案共同宿主；每项种类固定换代；定义、实例槽、宿主关系、定义关系用 P42 已发布稳定编码；新当前值使用本地键 `i+1`，所属槽/属性类型/来源来自 P42；`写前当前值` 用 P42 旧值编码、槽、属性类型和旧来源形成完整见证。草案、写集和读回计划一一覆盖后才形成执行证据摘要。

## 9. 单事务提交、结果形成与失败

首次路径只调用：

```cpp
批次数据操作_.提交带特征批次记录(写集, 草案)
```

恰一次。不得先调用公开 L1 提交、逐项 P10、失败重试或事务后补账。

- `已提交`：映射数量必须为N且恰覆盖本地键1..N；记录为完整全换代，发布代次非零；形成已提交完整结果。
- `精确重复`：只可能是探测后并发首次提交；P39 已互证首次键/意图/记录，形成幂等读回。
- 入口拒绝、未找到、已退出、漂移、冲突、许可、未知格式、资源失败逐类映射到同名公开状态，不合并或降级。
- 发布后读回矛盾或隔离：返回内部不一致、非零发布代次和 `L1发布已存在=true`，项目/记录空；不删除、不补写。
- 映射数量不等N、键缺失/重复、记录项目缺项、非全换代或结果顺序不连续均为内部不一致。

成功项目只含本批次项目并保持0..N-1顺序：结构编码沿用 P42；写前值/材料/来源沿用规格；新值编码来自 P39 映射，新材料/来源沿用规格。不得扫描或返回宿主其它槽。

服务无自有互斥量。P15与4170许可裁决并发；同批同义只一笔首次发布，其余幂等读回；同批异义冲突；不同批次最终由 L1 唯一事务串行。分配失败在发布前映射资源失败，未知异常映射内部不一致。进入 P39 后以其发布存在标志和代次区分前后失败。
