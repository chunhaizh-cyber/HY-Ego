## 1. 目标与完成边界

本叶为唯一简化 `L1事实基座` 增加一个只供固定内部数据操作使用的附属事务参与者桥接，使一个 L1 三类事实写集和零至多个具名领域侧账参与者能够在同一独占事务域中：

```text
第一写前复核
-> 确定性候选与本地键映射
-> 参与者顺序准备
-> L1候选与参与者顺序确认
-> 失败时逆序撤销
-> 无失败区关闭撤销能力
-> L1状态单次swap推进事实代次
-> 参与者完成发布，并按P15读回结果释放或隔离内部许可
```

公开 `L1事实基座服务::提交写集(const L1写集请求&)` 的纯值合同和行为不变，固定调用空参与者组。新增能力只有一个私有内部入口，L2、组合服务和普通领域服务不能取得、构造或传入参与者、回调、仓库、许可、事务视图或锁。

本叶只提供业务中性的桥和生命周期状态机，不建立 4170 特征批次账、不定义简化批次记录 DTO、不解释 P36 规格、不形成批次身份、不发布初始特征、不修改 P32 门面。旧 `参与者.特征批次发布记录.ixx` 仍属旧节点直接事务栈，不接入本桥。

## 3. 物理位置、所有权与依赖方向

新增一个核心内部模块，原位扩展仓库、服务和既有专项：

```text
海中鱼巣/核心/内部.L1事实附属事务参与者.ixx
海中鱼巣/核心/仓库.L1事实基座.ixx
海中鱼巣/核心/服务.L1事实基座.ixx
海中鱼巣/核心/自检.L1事实基座.ixx
海中鱼巣/海中鱼巣.vcxproj
海中鱼巣/海中鱼巣.vcxproj.filters
```

核心桥唯一拥有参与顺序、L1 独占域内调用时机、撤销和最后发布编排；具体领域参与者唯一拥有自有侧账候选、内部锁和领域记录完整性。核心桥不解释领域字段，领域参与者不读取或修改 L1 仓库。

依赖方向固定：

```text
未来具名领域数据操作
-> L1事实基座服务 私有内部提交入口
   -> L1事实基座仓库::提交带附属参与者
      -> L1事实附属事务参与者（业务中性内部接口）

普通领域服务 / L2 / 组合器
-> L1事实基座服务::提交写集（空参与者组）
```

`L1事实基座服务` 只为未来具名 `L1实例特征批次数据操作` 声明 friend；本叶不实现该数据操作。不得提供公开 getter、注册表、setter、全局回调或运行期字符串路由。

## 4. 内部接口与只读见证

新模块不由 `服务.L1事实基座` 公开 re-export，只供核心仓库、核心自检和未来获授权数据操作显式 import。

```cpp
inline constexpr std::uint32_t L1附属事务参与合同版本 = 1;

enum class L1附属事务参与状态 : std::uint8_t {
    第一写前已复核 = 1,
    候选已准备 = 2,
    已确认待发布 = 3,
    候选已撤销 = 4,
    许可拒绝 = 5,
    幂等冲突 = 6,
    资源失败 = 7,
    内部不一致 = 8
};

struct L1附属事务写前只读见证 final {
    std::uint32_t 合同版本 = L1附属事务参与合同版本;
    std::uint64_t 当前事实代次 = 0;
    写集幂等键 幂等键;
    L1确定性摘要 请求意图摘要;
    L1确定性摘要 执行证据摘要;
};

struct L1附属事务候选只读见证 final {
    std::uint32_t 合同版本 = L1附属事务参与合同版本;
    std::uint64_t 基线事实代次 = 0;
    std::uint64_t 待发布事实代次 = 0;
    const L1写集请求& 规范化写集;
    std::span<const std::pair<写集本地键, 稳定编码>> 新编码映射;
};

class L1事实附属事务参与者 {
public:
    virtual ~L1事实附属事务参与者() = default;
    virtual L1附属事务参与状态 第一写前复核(
        const L1附属事务写前只读见证&) = 0;
    virtual L1附属事务参与状态 准备候选(
        const L1附属事务候选只读见证&) = 0;
    virtual L1附属事务参与状态 确认待发布() noexcept = 0;
    virtual L1附属事务参与状态 完成撤销() noexcept = 0;
    virtual void 关闭撤销能力() noexcept = 0;
    virtual void 完成发布并保持许可(std::uint64_t 已发布事实代次) noexcept = 0;
    virtual void 释放已发布许可() noexcept = 0;
    virtual void 完成隔离并释放() noexcept = 0;
};

struct L1附属事务失败见证 final {
    std::uint32_t 参与者顺序 = 0;
    L1附属事务参与状态 状态 = L1附属事务参与状态::内部不一致;
};

struct L1内部附属提交结果 final {
    L1写入结果 写入结果;
    std::optional<L1附属事务失败见证> 参与失败;
};
```

实际名称以本设计为准。接口只传强类型纯值见证、规范化写集 const 引用和本次映射只读 span；引用/span 只在同步调用内有效，参与者不得保存。没有候选容器、状态对象、事务会话、锁或可变仓引用。

`关闭撤销能力`、`完成发布并保持许可`、`释放已发布许可`、`完成隔离并释放` 是无分配、无失败、`noexcept` 末区动作。任何实现若不能证明这四步无失败，不得登记为参与者。`参与失败` 只在内部数据操作边界保存精确参与者顺序和状态；公开空组提交永远为空，L2 不可见。

## 5. 仓库根函数与访问边界

仓库新增唯一根：

```cpp
L1内部附属提交结果 L1事实基座仓库::提交带附属参与者(
    const L1写集请求& 请求,
    std::span<L1事实附属事务参与者* const> 参与者组);
```

现有 `提交(请求)` 只调用该根并传空 span，验证 `参与失败` 为空后返回 `写入结果`，不复制第二套提交算法。

服务新增私有入口：

```cpp
L1内部附属提交结果 提交写集_内部附属参与(
    const L1写集请求& 请求,
    std::span<L1事实附属事务参与者* const> 参与者组);
```

该函数不 export 为公开能力，只允许 friend `L1实例特征批次数据操作` 调用；普通 `提交写集` 仍只传空组。参与者类型即使被内部模块 import，也不能绕过私有入口取得 L1 事务权。

参与者组按调用方给出的稳定顺序执行；空组合法且必须与 P15 普通提交逐字段等价。非空组中空指针、重复地址、数量溢出或合同坏值在取得 L1 独占许可前 `入口拒绝`，参与者调用0。

## 6. 固定事务算法

P15 v0.5 实现后的唯一算法原位扩展为：

1. 校验/规范化请求、两摘要和非空读回计划；校验参与者组地址唯一。
2. 取得 L1 独占许可，先执行 P15 隔离、状态完整、幂等键和期望代次裁决。已有同义、异义、隔离或坏记录均在参与者调用前收口；同义首次结果机械返回，参与者调用0。
3. 对首次未命中路径按顺序调用每个参与者 `第一写前复核`；见证精确携带当前代次、幂等键和两摘要。调用成功者计入已进入组。
4. 形成唯一 L1 候选副本、确定性本地键映射和待发布代次；应用三类写项、退出和属性设置，并完成候选完整性校验。
5. 以规范化写集和完整映射按顺序调用 `准备候选`；参与者只能形成自有未发布候选并持有自有内部许可，普通读取仍不可见。
6. 按顺序调用 `确认待发布`；随后完成 P15 幂等账、审计、结果摘要、通用读回预期、失败见证和隔离容量预构造。所有可能分配在最后发布区前完成。
7. 任一步失败时，对全部已进入参与者按逆序调用 `完成撤销`。全部返回 `候选已撤销` 才允许按原失败分类返回；任一撤销失败/未知则在 L1 候选中安装失败见证并隔离，随后调用全部未释放参与者 `完成隔离并释放`。
8. 全部确认后进入无失败最后发布区：按顺序调用 `关闭撤销能力`，单次 `swap` 发布 L1 候选并推进一个事实代次，再按顺序调用 `完成发布并保持许可(新代次)`；参与者已标记发布但仍持有自有内部许可，普通读取不可见。
9. 仍持有 L1 独占许可和全部参与者内部许可时执行 P15 通用发布后读回。成功则按顺序调用 `释放已发布许可`；矛盾时 L1 保留已发布代次、写失败见证并隔离，再按顺序调用 `完成隔离并释放`。参与者已发布记录不得撤销、删除或补写。
10. 释放 L1 许可并返回内部双层结果；未来数据操作用 `参与失败` 无损映射许可拒绝/冲突/资源/内部状态，公开空组提交只返回 `写入结果`。

参与者读取方必须先取得 L1/事务域冻结或按其专属 try-lock 合同读取；参与者在最后发布完成前持有内部独占许可，因此即使内部 `已发布` 标记先于 L1 swap 设置，普通读取也不可见。

## 7. 状态映射、异常与生命周期

| 参与状态 | L1 收口 |
| --- | --- |
| 各阶段期望成功状态 | 继续 |
| `许可拒绝` | 内部 `写入结果.状态=内部不一致` 作为不可公开的失败载体，`参与失败` 精确保存参与者顺序与 `许可拒绝`；未来数据操作只按后者无损映射 |
| `幂等冲突` | `写入结果.状态=幂等冲突`，`参与失败` 保存同名状态，零 L1 发布 |
| `资源失败` | `写入结果.状态=资源失败`，`参与失败` 保存同名状态，完整撤销 |
| `内部不一致`、错阶段、异常、未知值 | `写入结果.状态=内部不一致`，`参与失败` 保存顺序与内部不一致；完整撤销，否则隔离 |

参与者失败时 `写入结果.事实代次` 固定为当前已发布 L1 代次，编码映射为空；不得回显未发布候选映射。公开空组路径永远不产生 `参与失败`，因此不会把内部许可拒绝载体泄露给普通 L1 调用方。

虚函数允许分配的只有第一写前复核和准备候选；所有异常由桥捕获并记录精确失败参与者。确认、撤销和末区函数均 `noexcept`。析构未释放参与者属于实现缺陷，具体参与者必须自防御撤销/隔离，但不能以析构成功替代桥的显式收口。

桥不保存参与者指针、只读见证或 span；调用结束后零悬空引用。未来数据操作拥有参与者对象并保证其寿命覆盖同步提交。

## 8. 与 4015/4170/P15 的分账

- 4015：L1 状态仍只保存节点、关系、值、属性槽、幂等/审计/恢复发布元数据；不保存领域批次记录。
- 4170：未来特征数据操作通过本桥把专用侧账参与者加入同一事务；记录仍由特征领域唯一解释。
- P15：两摘要探测、首次结果、通用读回、失败见证与隔离仍由 L1 唯一拥有；本桥只扩展其内部参与顺序，不建立第二幂等账。
- P36：单项规格仍是未来发布者的值式输入；本桥不读取 P36、不聚合项目。

4170 旧“关系22角色3句柄”与 4015/P8 当前属性槽投影的最终简化记录形状不在本叶裁决。后继简化 4170 参与者计划必须按正式规范与已接受 P8/P10 路线单独冻结；不得让核心桥以通用字段替代该机器语义裁决。

## 9. 验证矩阵

既有 L1 专项原位追加业务中性假参与者，至少覆盖：

1. 空参与者组与 P15 普通提交在成功、同义、异义、漂移、资源失败和发布后隔离上逐字段等价；
2. 空指针、重复地址和坏组在锁前拒绝，参与者调用0；
3. 已有同义/异义、隔离、坏幂等记录时参与者全方法0次；
4. 首次成功的调用顺序严格为全部复核、全部准备、全部确认、全部关闭撤销、单次L1 swap、全部发布释放；
5. 两参与者以上按登记顺序准备/确认/发布，失败按已进入组逆序撤销；
6. 每个复核/准备/确认失败点均零普通可读 L1/参与者事实；
7. 撤销失败或异常形成失败见证并隔离 L1 与相关参与者，不允许后继普通提交；
8. 关闭撤销后注入点为0；末区无分配、无异常、无失败分支；参与者发布后继续持有许可直至P15读回成功释放或失败隔离释放；
9. 候选见证中规范化写集、本地键映射、基线和新代次完整一致，参与者不能保存引用；
10. 发布完成前并发参与者读取被内部许可拒绝/阻塞于其正式非阻塞合同，不能看到候选；发布后只能看到与 L1 同一代次记录；
11. P15 通用读回矛盾发生在发布后时，L1 和参与者均不撤销，L1 写见证并隔离，参与者在仍持有许可时同步标记隔离后释放；
12. 私有服务入口只有未来 friend 数据操作可调用；公开 `提交写集` 的函数地址/签名/调用点不新增参与参数；
13. 静态扫描 L2/组合服务没有参与者、内部见证、仓库、锁、span 或私有入口引用；
14. Debug/Release Rebuild、两配置完整自检、strict、MSVC 模块扫描、工程/filters一致性和白名单 diff check 通过。
