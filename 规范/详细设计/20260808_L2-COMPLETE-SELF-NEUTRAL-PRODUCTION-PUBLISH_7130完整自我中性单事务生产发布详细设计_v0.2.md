## 2. 正式冲突与当前接口裁决

4015 第 5 节和 4030 第 3、8 节明确规定：普通 CRUD 只能按请求中的稳定编码和必要索引访问受影响事实；旧全量读取、审计和恢复是分离的诊断或管理入口，不能成为生产写路径固定前置。

现有 `L1事实基座服务::尝试读取中性一致当前投影` 已公开六类精确选择：

```text
节点稳定编码
+ 关系稳定编码
+ 值稳定编码
+ 节点与属性类型
+ 源节点与关系类型
+ 目标节点与关系类型
```

该入口在一个非阻塞共享许可内按必要索引回读受影响事实，不遍历全仓。它足以复核本次已经具名的世界、登记、成员、资格值和已知端点竞争，因此本叶不需要新增 L1 查询接口。

该入口不能按“关系类型 + 角色”全局枚举，也不能证明全仓不存在未知的关系 21 角色 1、角色 2 或孤立半结构。本修订不得把精确投影冒充全局缺失证明。

## 3. 当前首跑适用门禁

本叶保持可执行，只因为当前正式生产形态同时满足以下四项。四项都是本设计适用条件，不是由一次精确读取反推的机器事实：

1. `运行期上下文` 唯一拥有的 `L1事实基座服务` 随上下文默认空构造；世界登记首个中性写集从事实代次零开始，后续结果沿同一 L1 事实代次链传递；
2. 当前生产路径不执行 L1 恢复、导入、持久材料重放或其它预装事实入口；
3. 自我结构关系类型登记成功后到完整自我发布之间，没有其它合法的关系 21 角色 1 或角色 2 写入方；
4. `L1完整自我发布数据操作` 是当前运行期唯一完整自我生产发布者，组合服务、两个准入服务和其它领域服务均不能直接提交本结构。

因此，本叶只证明“当前空构造、无恢复导入、唯一写者的首次生产链”中的完整自我发布。未知全局候选在该运行形态下由构造链和唯一写入所有权排除，不由精确投影扫描证明。

任一门禁改变时，本合同立即停止适用并必须重新 S0。届时若仍要求从任意已有 L1 状态证明关系 21 全局唯一，须先建立独立的业务中性“关系类型 + 角色”条件读取能力；不得退回旧全量诊断读取，也不得由本计划临场扩大 L1 白名单。

| 字段 | 唯一来源 | 所有者与用途 |

`完整自我存在准入规格完整` 必须逐项证明：

- 世界根、实际存在服务、自我结构登记服务为互异普通节点；

`完整自我存在准入结果完整` 与 `成功()` 的唯一成功形状是 `已批准 + 完整规格`。三个非成功状态必须规格为空。函数为 `const noexcept`，不分配容器；坏上游成功形状、身份碰撞、错误类型、错误固定键或不可分类状态返回 `内部不一致`。

### 6.2 字段来源与所有权

`世界登记`、`实际存在规格`、`自我结构登记`和共同截止与存在请求来自同一组 provider 副本，组合服务必须逐字段全等传入两个准入函数。出生期成员资格组来自按顶层成员稳定编码顺序逐项调用 `读取当前实际存在资格` 的正式结果；不得静默排序、去重或只保存裸编码。

场景规格唯一批准：

- 三个新场景节点及其三个标记值和属性槽；
- 世界根到世界根内部世界场景、世界根内部世界场景到自我所在场景、世界根内部世界场景到自我内部世界场景三条父关系；
- 自我所在场景到自我存在的一条直接成员关系；
- 从本地键 14 起按成员稳定编码升序形成的关系 21 角色 2 关系。

它不批准自我存在资格值、本地键 8 或关系 21 角色 1 本地键 13。

`完整自我场景准入请求有效` 检查版本、非零截止、三个上游 DTO 完整，以及成员组非空、按 `存在.编码` 严格升序、无重复、每项为完整普通实际存在资格且值为 1。生产固定 N=1；通用合同仍允许 N 大于 1。

`完整自我场景准入规格完整` 还必须证明：

- 世界登记服务、标记类型、父/成员关系类型与登记逐字段相同；
- 自我结构登记服务、关系类型与登记逐字段相同；
- 四角色精确为 1—4，节点键精确为 1—4，标记值键精确为 5—7，固定关系键精确为 9—12；
- 首个成员关系键精确为 14，后继第 `i` 项机械使用 `{14 + i}`，不得在规格内复制一份裸键数组；
- 固定父子和直接成员顺序为 0，出生期成员关系角色为 2；
- 成员资格组与请求同序全等，每项截止等于共同截止、资格属性类型和来源服务等于实际存在规格；
- 任一成员不得等于世界根或任何服务/类型节点；新自我稳定编码尚未分配，因此自我非成员由角色职责和后继映射保证，不能用猜测编码比较。

`完整自我场景准入结果完整` 与 `成功()` 的唯一成功形状是 `已批准 + 完整规格`。其它状态规格必须为空。成员错值、错类型、乱序、重复或与实际存在规格不一致返回 `出生期成员不合格`；截止不一致返回 `事实代次漂移`；复制成员组分配失败返回 `资源失败`；坏 provider 成功形状、身份复用或固定键矛盾返回 `内部不一致`。

## 7. 两域互证

组合服务只接受两个结果均成功，并逐字段确认：

1. 合同、规则和共同事实截止全等；
2. 世界登记、实际存在规格和自我结构登记的来源副本全等；
3. 世界根、自我结构登记服务和关系类型全等；
4. 场景规格的自我存在角色/键 3 与存在规格全等；
5. 场景规格的自我内部世界场景角色/键 4 与存在规格全等；
6. 场景规格不含资格键 8 和角色 1 关系键 13，存在规格不含标记值、父/成员关系或角色 2；
7. 成员资格组与顶层请求编码组逐项对应。

组合服务不得修正、重排或补写任一规格字段。任何坏成功形状返回 `完整自我状态::内部不一致`，零 L1 调用。

## 8. 首次写前精确一致投影

数据操作在形成规范化写集后、调用 L1 提交前，构造一次 `L1中性一致当前读取请求`。六组精确内容如下；所有稳定编码列表先升序去重，任何本应互异的业务身份发生碰撞都在 L1 前返回内部不一致。

| 选择组 | 精确内容 | 成功判定 |
| --- | --- | --- |
| `节点` | 世界根；世界登记、实际存在、自我结构三个服务身份；场景标记和实际存在资格两个属性类型；直接父、直接成员、自我结构三个关系类型；全部出生期成员节点 | 全部成功；世界根、服务和成员为普通节点，两个属性类型为对应 I64 属性类型，三个关系类型为普通节点 |
| `关系` | 空 | 首次写前没有待分配新关系编码，也没有其它必须按已知关系编码复核的关系；禁止伪造编码 |
| `值` | 每个成员资格事实中已经正式读回的资格值编码 | 全部成功并与资格事实逐字段全等 |
| `属性值` | `(世界根, 场景标记属性类型)`；每个 `(成员, 实际存在资格属性类型)` | 世界根当前标记值为 I64 1、来源为世界登记服务；成员当前资格值与请求资格事实全等、为 I64 1、来源为实际存在服务 |
| `源关系组` | `(世界根, 自我结构关系类型)`；每个 `(成员, 自我结构关系类型)` | 每组为空；当前首跑中已知世界根和成员都不能是关系 21 的源端 |
| `目标关系组` | `(世界根, 自我结构关系类型)`；每个 `(成员, 自我结构关系类型)` | 每组为空；当前首跑中已知世界根和成员都不能是关系 21 的目标端 |

源/目标组只判定这些已知端点的竞争关系，不判定未知端点，也不声称全仓不存在完整或半完整自我。新四节点、四值和 `5 + N` 关系的稳定编码尚未分配，不能进入写前具名编码组；它们由 L1 在同一事务候选中按规范化写集完成结构校验、完整候选读回和唯一约束最终复核。

写前精确投影只调用一次。非成功映射固定为：

| L1 状态 | 完整自我状态 |
| --- | --- |
| 入口拒绝 | 内部不一致 |
| 事实代次漂移 | 事实代次漂移 |
| 许可拒绝 | 许可拒绝 |
| 资源失败 | 资源失败 |
| 内部不一致 | 内部不一致 |

成功顶层形状、六组数量、请求顺序、项目状态、事实字段或空竞争组任一不符都返回内部不一致。该失败发生在提交前，机器事实零变化。

## 9. 一次提交与发布后正式读回

写前精确复核通过后只调用一次 `提交中性写集`。成功或精确重复继续服从 v0.1 的 13+N 映射、幂等键和发布后隔离合同。

发布后的一致当前投影仍覆盖五身份节点、全部成员节点、五加 N 条新关系、四个新值、四个新属性槽、成员资格属性投影及全部登记服务/类型节点。此时新稳定编码来自 L1 写入结果的本地键映射，能够按编码精确读回；不得把写前空关系组当作发布后读回。

首轮事实代次漂移只允许销毁本轮全部投影并以回显代次完整重构一次发布后请求；第二轮漂移或其它失败保留 `L1发布已存在=true` 并进入隔离，不撤销、不补写、不换键。

## 11. 修订验证矩阵

除 v0.1 未替代的验证外，本修订必须覆盖：

1. 两个准入请求的所有版本、上游 DTO、截止、身份碰撞和成员排序门禁；
