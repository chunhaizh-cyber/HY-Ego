## 1. 对象、原因、目标与不做范围

本叶有两个不同修改对象：

1. 现实世界中自我普通存在的服务值Fself，依据已完成来源任务的Vt服务值Q增加，属于普通方法。原因是新贡献K已被正确计算和直属接收，但所有实际入口仍被固定`A0+1`旧合同隔离；目的是真正按来源Q消费一次。
2. 来源任务Vt的状态Fts由9变12，属于内部治理。原因是最终来源不能只凭R收尾；目的仅在U及本次现实结果完整读回后记明该来源已经结算。治理动作/S/D归C(T)，普通增值动作/S/D归现实场景。

唯一生产路径为：已有完成贡献反馈→self组织最终消费工作→manager既有10线程工作池→运行服务建立正式参数场景→同一个`执行服务值结算()`→唯一U与Fself组合发布→结果读回→最终9→12→消息回执。

本叶不为self直接调用伪造L的X/A，不新增D/T，不重算K/R，不消费L累计值。只迁出最终U重活；self现有`处理贡献定位()`中的K/R贡献推进仍同步执行，完整贡献编排迁到工作线程是具名后继。

明确排除：L需求驱动多来源/多轮重新筹办、旧固定目标D改为长期方向目标、全本能通用模拟、方法C(M)、跨场景因果窗口、方法统计泛化、跨进程持久保存/重启防重复承诺。旧需求驱动路径的新K保护继续保留，不借本叶放行旧`+1`。新头只有声明且无经验配对，不能称任务已经可据此预测采用。

直接规范依据：[0050](../0050_项目通用机器逻辑与禁止性规则总纲_20260721.md)、[3300](../3300_根规范_方法.md)第7节、[5350](../5350_子规范_方法治理详细合同.md)第6/11节、[5360](../5360_子规范_方法函数登记执行与任务反馈.md)、[5260](../5260_子规范_任务治理详细合同.md)、[6190](../6190_子规范_服务值治理结算与时间衰减.md)及上位已裁决替代范围。服务值没有业务上限分支，I64算术越界是工程故障，不钳制、不按零结算。

## 3. 正式信息与唯一owner

沿用T、Vt、Fts、Ftq、K、R、L、M、C(T)。新增P为“最终消费准备阶段”，U为“最终消费核心事实”。P不是消费成功，U核心存在也不自动说明下游EC/S/D已经完整。P/U都由task owner管理，不能存在另一可写余额。

## 4. 方法头与存量方法的限定新代际

新头仍使用原C++登记名、同一个本能函数入口，作用域`普通世界`，涉及FT仅自我服务值；来源任务Q不是该方法声称改变的外部FT。结果声明是自我服务值合法域及增加能力，不冻结某一个A0或A0+1。Q0是零额治理消费，不伪称增加能力已经发生。

参数两个角色保持明确区分，即使self与Vt的服务值FT相同，也不能合并：

| 角色键 | 规格 |
| --- | --- |
| self服务值FT | 普通世界、要求C/E、selfF合法非负I64域、自我服务任务集合非空域 |
| task状态FT | 任务虚拟存在、stateFT={9}、task服务值FT=非负I64域；同一个T必须属于前一角色集合 |

采用既有FT/正式域；非负域建正式子概念，不能用字符串或硬编码编码。声明不预造C/R。self概念只引用当前正式初始化E的专属概念，不另造按名称的“自我”；独立全局self概念导出仍留后继，不据此阻断本次已有正式引用。

方法owner在`新_方法类.h/.cpp`新增：

只允许服务值结算登记名、精确旧两角色/三项声明条件固定+1合同→本节新规格。这里核的是旧Vm正式参数规格，不要求旧M已经有学习产生的条件结果对；只有头和完整规格、配对数为0的合法旧M同样可替代。不是任意方法版本发布器。`新方法信息`新增可选`父代方法节点`，持久用独立父代字段；**不得复用`来源方法节点`**，后者仍与实例根成对且只表达旧复制实例。

无旧头：新建完整M/Vm/规格、空C/R。旧头已经是同义Q头：严格读回重用。存在完整旧固定+1头：保留旧M/Vm/C-R、登记名和全部历史身份；在同一次method owner原子发布中新M挂方法根、写新M父代=旧M、旧M启用改停用。新头完整离根构造，失败仅清理未公开私有材料；旧头及根在最终原子发表之前不改。没有根公开的半新头不得成为查找候选。

严核旧M为唯一合法固定+1抽象本能、没有未解释组合结构；只停用旧头，不复制旧配对到新头，不补Q=1，不重置旧Vm统计，不改历史X/采用/副本。旧头停用不是运行异常降可靠度，是已授权语义替代；二者不可混写。

`查询本能登记结构`对其它登记名保持原唯一规则。对本登记名允许两类完整结构：替代前唯一旧固定+1头供初始化迁移读取；替代后恰一启用Q头和零或一个精确父代。全新安装可无父代且不得残留同名旧头；替代场景必须恰一相连的停用固定+1父代。完整核全部结构和父代无环，不能简单跳过所有停用头。两个启用、两个父代、不相连同名头、坏旧头或部分替代全部工程停止。`修改启用状态`不得重新启用已作为父代的旧头，不允许停新启旧绕过迁移。

`调用本能函数`在实际调用前同时核抽象身份、启用和父代关系；旧冻结X不能因为仍持旧场景绕过停用重新执行+1。历史`获取方法(M旧)`不受影响。初始化只在工作线程启动前完成替代；运行中发现异义头不在线自动迁移。

### 4.2 旧D/L、配置和旧动作投影

本叶不改旧结算D的固定目标或伪造新D。登记材料拆分`当前Q头规格`与`既有首子需求初始化材料`：旧A0/目标仅用于读回/复用旧D和旧历史X，不再进入Q调用条件、加法或U证明。新安装仍只建原唯一结算子D；本叶不声称它已经支持任意Q后的多轮重筹办。当前配置M指向Q头，L/D身份保持，且新K的需求驱动保护保持。

旧9→12治理动作定义需要冻结“历史固定+1方法引用”。在task owner旧动作定义上增加正式单值M字段；只在能由旧M、旧X或完整旧普通动作包唯一证明时补入。新的动作投影按该字段读旧M，不再`查询本能登记`取当前头。没有旧发生且无旧M时可没有该关联；一旦读已有旧发生而关联不能唯一还原必须停止。新J5按P/U冻结新M，不把旧历史投影接到新Q头。

task owner在`新_任务类.h/.cpp`提供公开只读签名`std::optional<稳定编码> 读取任务已结算动作方法() const noexcept;`，供动作方法投影读取旧定义上已冻结的旧M，不扩大中立接口。合法没有旧发生且没有旧M时返回空，坏引用或已有发生却缺合法映射工程终止。配置新Q时，由task owner凭唯一旧定义及受限方法父代只追加这一个单值M关联；重复时核同义，不能改写既有旧M。投影不得直接读取task私有字段，也不得改为按当前登记名取得新M。

## 5. 来源资格、参数场景与执行前复核

新增task最终来源只读入口，以`T/K/R`而非裸Q定位。核验顺序固定：

1. 先用无递归原始reader核T/K/R身份及P/U/J5/旧包。完整U/J5/12直接读其冻结资格、边界、S/D及9→12证明，不因今天运行配置或确认有效性变化降为未消费。完整U结果+state9、尚无J5同样使用冻结证明，只允许补J5。历史依赖不可读仍是工程故障；不能用fresh未确认掩盖历史损坏。只有P、只有U核心或半J5停止，不进入重试。此分支不强制今天Fself仍等历史B。
2. 只有完全没有P/U/J5的新消费才fresh复核完整T/D/Vt/Fts/Ftq、K、R及反向引用；K.T/D/X/A与T当前完成来源一致，Q=Ftq=K.Q=R.Q。运行配置确定L/结算D/服务根/M，R父恰为L、T不是L；D→父D→唯一T证明直属。配置确实未装配返回等待配置，非零坏引用终止。
3. 以K的`服务贡献.直接子接收节点组`递归只读展开**本来源T的封闭贡献证明树**。每条R核父T、子T、子K、Q和D-T直接关系，汇总Q只核验等于直接R之和，不再修改或重算贡献权威。循环、重复子K、越界到L其它兄弟或不相符的边停止。每个K的实际结果S闭包完整，X/A同源，A允许完成且归因/安全等现行门满足；任务9/12本身不替代这些证据。
4. 每个正贡献服务叶必须能在其到本来源T的已证明路径中定位一个明确确认的人类服务需求（可为自身，也可为该路径中祖先），核完整目标、合法承接/外部要求、人类来源和`复核需求服务要求语义`当前有效。服务准备叶可由其上级服务需求覆盖；内部治理汇总T不强求自己的D有确认，但必须逐个覆盖全部正贡献叶，不能仅找到一个后代确认就覆盖其余分支，也不能借L或L的其它子链。各叶的实际完成/归因证据按第3项核；确认待重新取得为业务条件不具备，坏材料为工程故障。
5. Q0不需要虚构正贡献叶，但仍须在本T贡献证明树及其T以内路径存在完整、明确确认的人类服务目标及对应实际结果证明，且所有零额R/K合法封闭。没有该资格的纯治理0保持未消费；不能为了清理任务而发布U。正贡献叶既有K/R已被本树之外最终U覆盖为冲突，禁止换包装重复入账。
6. sourceT属于self服务任务集合，self C/E/F归属正确，Q非负。动作前捕获全部资格和贡献树依赖，作为P冻结来源及U组合预期；无P/U时的合法来源变化可零动作返回，发布P后遵循部分现场停止边界。

现有旧`核验直接服务结算来源()`继续返回新K保护结果；内部可提取资格共同helper，但新consumer直接调用本节入口，不能先删除保护让其它旧消费者落到固定+1。

`方法参数场景::读取绑定任务虚拟存在`、`新_方法类::建立参数场景`由只许stateF改为：stateF必须存在，所有额外F必须由同一个中立`读取任务虚拟存在特征组`证明属于该Vt，本叶只许正式QF。新Q规格严格绑定两F；旧规格仍只绑定stateF。不得只看FT相等放行外部F。模拟读取器缺该能力不回落真实task。

在`新_方法参数场景.h/.cpp`新增公开只读签名：

### 7.2 Q>0顺序与保护

1. runtime持独立最终结算串行门至整个U结果/J5完成。task token不持task mutex；world短锁核C/E/F和fresh A，受检计算B=A+Q后释放。sourceP/定义M通过动作投影在world锁外核验，后续回锁fresh复核定位与值仍一致。普通方法无“达上限”业务分支。
2. 选择真实当前A的最近合法前S；无前S时，world在锁外调用存在owner的`建立当前I64特征状态`建立当前A状态，再核验并挂场景，不直接调用state私有入口，不补造过去时间；已有前S与当前A不符且不能合法解释则停止。每次从正式时钟读取实际UTC，并检查前S时间≤动作时间<后S时间；后S时钟尚未越过动作时只能重取实际时间，不能用action+1造时间。动态/动作读取在world锁外。
3. 在world锁外调用动态owner建立普通动作，来源P；回world短锁重新核定位并挂现实C，禁止该挂接内部再次调用动作投影。动作一旦已发表，即使随后挂接/提交失败也保留，不沿旧“挂接失败删除动作”回滚该发生；新入口不改变其它调用者既有合同。
4. 全部前S/P/动作对F的消费者引用建立后重新捕获保护快照，返回world准备对象并释放world锁。runtime再在短期task锁内封存U片段；task保护快照必须取上述引用已建立之后。无owner在另一owner持锁期间被反向回调。
5. 第二world入口核同一次准备、全部正式见证仍一致，之后才准备feature顶层I64更新，核其实际旧值仍A。U片段已预封存，直接值传`提交顶层I64更新`恰一次，F核心与U片段共同成功或共同零发表。动作后发生合法并发变化而预期不符时也保留动作并工程停止，不覆盖新值，不新建动作重试。
6. `完成顶层I64更新`完成聚合后继续保留token逻辑占用；token生命周期不持F mutex。存在owner只补EC/后S，随后world锁外挂S/D所需动态创建/读回与原动作关联，短world锁仅挂接已建正式节点；最后才`结束顶层I64更新`。新入口不能走旧`完成动态发布`在挂D失败时删除D的回滚分支：D已建即保留，挂接失败工程停止。feature end只核F信息投影与逻辑占用，不核旧入边快照；S/EC/D新增引用不改变F投影。占用阻止其它写/删F在核心与后S之间插入，保证状态读取的是本次B。不是第二次更新F，不新增跨收尾长E锁。
7. 返回附加回执与完整变化；runtime交task读回U、追加结果引用、J5收尾。后续另一个来源可能已改变Fself，历史读回只比较U冻结S，不要求累计F永远等B。

### 10.3 容量、停止及锁

- 邮箱满、同T已有工作、10槽满、尚未启动：manager保留同一工作编号/定位，self保留原消息，按既有资源重试时点或完成唤醒重投；不额外建立线程或新编号绕过去重。
- 重复提交必须得到同一future；相同编号不同定位是工程身份冲突。结果未消费前不销毁future槽。
- 停止请求之后不开始新动作；pool尚未领取的工作以既有`停止取消`收束且保持U未写；已经领取且进入本能的工作不在中途撤销，完成本次可确认发布后返回。runtime/provider仍须存活至join和以下专属收束结束。
- self、manager、pool各自只在本锁内操作队列和定位；任何互调、task/world读取、等待future和完成通知均在锁外。发布中不得反向调用self/manager。
- 业务条件不具备清本次在途但保留正式未消费；只按下文冻结的现有事件重试，不无意义忙转。工程故障不折算成该状态。
- 同一Fself不同来源由最终运行服务串行协调及world唯一更新边界累加，不能各拿旧A覆盖；同一K两个入口竞争由task唯一P/U事实收敛。

停止闭合必须同时修改两端：

1. self现有`终结剩余消息`对具有最终工作future的槽，以`已交接未收回`兑现原承诺；`新自我消息处理结果`在self头追加`std::optional<新任务工作请求> 未收回最终消费工作; std::shared_future<新任务工作处理结果> 未收回最终消费结果;`。保留实际request/future，不写到类型不同的`未收回任务结果`。尚未被pool接收的纯pending消息为`停止取消`，manager保留正式未消费待办，不假称已提交。
2. manager停止先停接收、join池，再对最终工作专属收束；self解绑后但manager尚运行时也用同一专属收束函数取就绪项。不进入普通`处理工作结果`，不创建普通筹办。短锁领取`停止收束中`；正在self确认中的项等其确认完成，不并发二次ack。
