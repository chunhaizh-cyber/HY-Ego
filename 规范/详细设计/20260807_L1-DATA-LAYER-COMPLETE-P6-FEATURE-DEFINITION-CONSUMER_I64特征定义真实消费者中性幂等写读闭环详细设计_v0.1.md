## 1. 目标与完成边界

本叶把现有 `L1特征定义服务` 的登记建立、I64 特征定义建立和正式读取原位迁移到 L1 业务中性 CRUD。合法第二层特征定义消费者从正式生产运行期取得上下文租约后，只调用具名特征定义服务；服务以两个中性写集依次建立一项登记和一个 I64 区间定义，并以中性精确读取重新形成结构化领域结果。

本叶保留现有模块、类、公开函数、DTO、合同版本和规则版本，不建立第二特征定义服务或专用 L1 验收入口。它删除本三条路径中的领域意图、预探测、业务操作标签、执行证据、完整快照和 legacy 读写；服务只保留非权威稳定编码定位，每次公开读取都重新读取 L1 权威事实。

真实消费者合同同时自然覆盖：首次登记与定义成功、同一完整定义请求精确重复、同一幂等键但不同合法值域发生幂等冲突、非法值域写前拒绝，以及冲突/拒绝前后定义权威读回零变化。测试不得为 L1 建立专用函数、直接访问 L1、解析日志或修改生产变量。

本叶不建立实例特征槽、当前值、关系 22、当前值换代、退出事实、历史读取、批次、状态、动态或恢复；不考虑崩溃、重启、断电和跨进程恢复。

## 4. 登记中性写集与读回

登记技术幂等键保持现有隔离映射：

```text
登记键 = (0x03ULL << 56) | 请求.幂等身份.值
```

`建立登记` 固定过程：

1. 验证合同、规则、幂等身份和非零期望事实代次。
2. 构造一个 `L1中性写集请求`：四个新节点、零关系、零值、零属性槽变更、零退出。
3. 四个节点依次为：普通服务身份节点、I64 定义标记属性类型、I64 下界属性类型、I64 上界属性类型；本地键固定 1—4。
4. 恰一次调用 `提交中性写集`，不预探测、不附带业务标签或证据。L1 必须先按幂等键和完整规范化请求裁决精确重复/冲突，再对首次新键裁决期望事实代次；领域服务不得以提交前当前代次检查阻断合法精确重复。
5. 成功或精确重复必须回显同一中性键、非零事实代次和四项完整唯一映射；成功形成一次发布，精确重复不形成新发布。
6. 从映射形成四编码定位，经中性精确读取重新形成登记；四节点创建事实代次必须等于写入结果的首次发布代次，本次共同读取截止不得早于该代次；只在完整读回后保存定位。

读取登记固定执行：起始事实代次→四个当前节点→结束事实代次。首末代次必须相同且非零；服务节点必须为普通节点，三个属性类型节点必须为属性类型且表示种类均为 I64；全部节点未退出。返回的 `事实截止代次` 使用本次共同读取代次，不回显缓存代次。

服务只保存 `std::optional<std::array<稳定编码, 4>>` 定位，不保存 `特征定义登记` 权威副本。定位命中后仍须完整权威读回；任一缺失、退出、类型矛盾或混代返回具名非成功。

## 5. I64 定义中性写集与读回

定义技术幂等键保持现有隔离映射：

```text
定义键 = (0x04ULL << 56) | 请求.幂等身份.值
```

`建立I64特征定义` 固定过程：

1. 验证合同、规则、幂等身份、非零期望事实代次和 `下界 <= 上界`。
2. 调用 `读取当前登记`；只接受已读取且完整。登记的四个稳定编码用于形成同一中性写集，但不得以前后其它事实推进造成的登记当前截止变化阻断精确重复；首次新键的期望代次仍由 L1 原子提交裁决。
3. 构造一个中性写集：一个普通定义节点、三个 I64 值、三个属性槽变更、零关系、零退出；本地键固定 1—4。
4. 三个值均属于本地定义节点，属性类型分别取登记的定义标记、下界和上界，来源均为登记服务身份，材料依次为 `1`、请求下界、请求上界。
5. 恰一次调用 `提交中性写集`。成功类结果必须具有四项完整唯一映射，并符合发布标志和重试边界。
6. 从映射形成公开读取请求，调用与公开读取相同的中性读回；定义节点和三个值的创建事实代次必须等于写入结果的首次发布代次，本次共同读取截止不得早于该代次。后续无关事实推进不能使合法精确重复失效。

`读取I64特征定义` 固定执行：当前登记→起始事实代次→定义节点→三个当前属性槽→三个当前值→结束事实代次。全部读取代次必须一致；定义节点必须为普通节点且恰有登记定义的三个当前属性；三个值必须属于定义节点、类型匹配、来源为登记服务、未退出且材料分别为 1、合法下界和合法上界。任何混代、缺失、重复、类型或来源矛盾返回内部不一致或相应中性失败，不返回部分事实。

## 6. 状态映射与幂等合同

中性写入状态映射固定为：

| 中性状态 | 特征定义状态 |
| --- | --- |
| 成功 | 已提交 |
| 精确重复 | 幂等读回 |
| 入口拒绝 | 入口拒绝 |
| 未找到、已退出 | 未找到 |
| 事实代次漂移 | 事实代次漂移 |
| 幂等冲突 | 幂等冲突 |
| 资源失败 | 资源失败 |
| 内部不一致 | 内部不一致 |

中性读取状态映射固定为：成功→继续，入口拒绝→入口拒绝，未找到/已退出/属性未设置→未找到，资源失败→资源失败，内部不一致→内部不一致；首末代次不一致单独映射事实代次漂移。

同幂等键且完整规范化中性写集逐字段相同由 L1 返回精确重复，即使当前事实代次已因首次发布或其它事实继续推进也不得在领域层提前拒绝。服务不得依赖进程内首次请求副本裁决同义。相同定义键但下界或上界不同形成不同中性写集，由 L1 返回幂等冲突；冲突前后正式定义读取必须逐字段一致，且冲突/拒绝本身不得推进事实代次。`下界 > 上界` 在服务写前拒绝，L1 调用次数为零；拒绝前后正式读回同样不变。
