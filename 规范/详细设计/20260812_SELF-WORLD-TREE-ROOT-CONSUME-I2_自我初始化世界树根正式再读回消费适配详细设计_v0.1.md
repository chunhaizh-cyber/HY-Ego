# SELF-WORLD-TREE-ROOT-CONSUME-I2 自我初始化世界树根正式再读回消费适配详细设计 v0.1

日期：2026-08-12

## 1. 目标、完成条件与声明边界

本设计建立 I1 之后的 L5 外自我根消费适配：`运行普通程序` 只从 I1 成功结果形成版本化值式请求，交给普通应用唯一持有的 `自我世界树根消费适配器`；适配器通过构造期绑定的 A1 同实例 R1 场景服务，每次重新正式读取当前树结构登记和目标整树，逐字段证明仍是同一合法现实世界树根后，才发布调用方拥有的值式消费材料。

完成必须同时满足：

1. 输入只锚定 I1 已验证根的不可变选择、首次建立请求、树、根场景和首次根标记，不携带 owner、写端口、缓存、自我或恢复材料；
2. 每次成功都发生本轮 R1 `读取当前场景树结构登记` 与 `读取场景树`，同参数重复也不走缓存成功；
3. I2、A1 对 R1 和全部业务事实零写；参数、结果、上下文和适配器缓存都不是根事实；
4. 值式发布、同参数重复、异参数冲突、并发串行、异常和旧值保留闭合；
5. 正式启动在 I1 成功后调用 I2，I2 失败映射阶段 16；I2 接通后删除阶段 15，但因当前不存在真实自我形成 provider，I2 成功固定映射阶段 17，仍不进入方法根、自我线程、概念、投影或宿主；
6. 旧基础信息世界根、旧完整自我 DTO / 入口、旧自我线程世界树快照和兼容恢复路径保持不存在；
7. 生产外双配置专项、主工程双配置重建和静态门禁通过，临时验证三文件在结果接受和索引退出后独立清理。

I2 成功最多证明“供自我初始化后继消费的根材料已经本轮由 R1 正式再读回验证并值式发布”。它不证明自我存在、自我所在场景、内部世界、成员、实例槽、状态、动态、需求、方法或概念已经建立，也不证明完整系统初始化或宿主运行成功。

## 3. 能力裁决、所有权与依赖方向

### 3.1 复用与新建

复用且只复用：

- I1 的 `系统世界树根初始化结果 / 系统世界树根读回` 作为正式生产调用方的输入来源；
- A1 透明返回的同一个 `L2场景结构服务`；
- R1 的 `读取当前场景树结构登记` 和 `读取场景树`；
- 普通应用的唯一 provider、成员生命周期和 `运行普通程序` 正式路由。

新建一个 L5 外值式 DTO 头和一个适配器命名模块。适配器只编排读取、验证和值式发布，不复制 R1 DTO、树结构解释或 CRUD，不建立第二服务、第二 owner 或第二根。

### 3.2 物理位置与依赖

```text
海中鱼巣/业务/自我世界树根消费.数据.h
海中鱼巣/业务/适配.自我世界树根.ixx
```

模块名固定为 `海中鱼巣.业务.适配.自我世界树根`。数据头承载请求、状态、来源、发布材料和结果；适配模块唯一拥有 `自我世界树根消费适配器`。模块只 import R1 场景服务并包含数据头，不 import 普通应用、启动、自我线程、方法、概念、L1、仓库、SQL 或旧世界模块。

依赖方向固定为：

```text

-> I1 成功结果
-> 普通应用持有的自我世界树根消费适配器
```

R1、A1、I1 不反向 import I2。普通应用负责构造和持有适配器，不解释根；启动模块是唯一生产消费方。

### 3.3 生命周期

普通应用先在局部形成最终六服务和 `std::unique_ptr<L2结构聚合服务> 聚合服务`，再在它们尚未 move 时以 `聚合服务->取得L2场景结构服务()` 构造局部 `std::unique_ptr<自我世界树根消费适配器> 根消费适配器`。两者都成功后，普通应用上下文私有构造函数在最终六服务和聚合参数之后追加适配器参数，把运行包、六服务、聚合和适配器一次移动进上下文；不得先构造上下文后注入。

上下文成员声明顺序固定为运行包、最终六服务、A1 聚合、I1 发布锁 / 待收敛请求 / 根读回、I2 适配器。适配器因声明最晚而最先析构；其非 owning 场景服务引用在整个生命周期有效。上下文析构只销毁值式材料，不退出根事实。

## 4. 公开 DTO

数据头包含 I1 `系统世界树根初始化.数据.h` 和最终 R1 `L2场景结构.数据.h`，不复制其类型。

```cpp
inline constexpr std::uint32_t 自我世界树根消费合同版本 = 1;

struct 自我世界树根消费请求 final {
    std::uint32_t 合同版本 = 自我世界树根消费合同版本;
    系统世界树根初始化请求 项目树选择;
    L2场景树根建立请求 首次根建立请求;
    L2场景树身份 树;
    L2场景身份 根场景;
    L2场景树归属事实 首次根标记;
};

enum class 自我世界树根消费状态 : std::uint8_t {
    已发布 = 1,
    精确重复 = 2,
    请求无效 = 3,
    已发布选择冲突 = 4,
    树结构登记读取失败 = 5,
    根正式读回失败 = 6,
    根读回不一致 = 7,
    资源失败 = 8,
    内部不一致 = 9
};

enum class 自我世界树根消费来源 : std::uint8_t {
    首次消费 = 1,
    已发布重复消费 = 2
};

struct 自我世界树根消费材料 final {
    自我世界树根消费请求 请求;
    L2场景树结构登记 当前结构登记;
    L2场景树事实 正式树读回;
    std::uint64_t 本次事实截止代次 = 0;
};

struct 自我世界树根消费结果 final {
    自我世界树根消费状态 状态 = 自我世界树根消费状态::请求无效;
    std::optional<自我世界树根消费来源> 来源;
    std::optional<L2场景树结构登记结果> 结构登记读取;
    std::optional<L2场景树读取结果> 根读取;
    std::optional<自我世界树根消费材料> 已发布材料;
    bool 成功() const noexcept;
};
```

请求由 `运行普通程序` 在 I1 成功且 `已发布根` 存在时逐字段形成：前四个锚点来自 I1 根读回同名字段，`首次根标记` 来自 `已发布根.正式树读回.根标记`。请求不携带 I1 的整树快照或截止，避免把旧快照当成本次根事实；本轮整树和截止只来自 I2 的 R1 读取。

请求有效性完整且只要求：

1. `合同版本 == 自我世界树根消费合同版本`；
2. `项目树选择` 通过 I1 请求有效性校验；
3. `首次根建立请求` 通过 R1 请求有效性校验，其合同版本、期望事实代次和幂等身份均有效；
4. `首次根建立请求.幂等身份 == 项目树选择.根建立幂等身份`；
5. 树身份和根场景有效，且 `树.值 == 根场景.值`；
6. `首次根标记` 通过 R1 树归属事实完整性校验，类别为根；
7. `首次根标记.树 == 树`、`场景 == 根场景`、`根场景 == 根场景`，其关系稳定编码、物理目标、创建事实代次均非零，退出事实代次为空。

除此之外不扫描或补字段。请求不要求 I1 整树快照或旧截止存在，也不按名称、无父、第一棵树或缓存判断。

结果形状固定为：

| 状态 / 来源 | 结构登记读取 | 根读取 | 已发布材料 |
| --- | --- | --- | --- |
| `已发布 / 首次消费` | 成功且有登记 | 成功且有树 | 存在 |
| `精确重复 / 已发布重复消费` | 成功且有登记 | 成功且有树 | 存在 |
| `请求无效` | 空 | 空 | 空；旧值保持 |
| `已发布选择冲突` | 空 | 空 | 空；旧值保持 |
| `树结构登记读取失败` | 存在且 `成功()==false` | 空 | 空；旧值保持 |
| `根正式读回失败` | 成功且有登记 | 存在且 `成功()==false` | 空；旧值保持 |
| `根读回不一致` | 成功且有登记 | 存在；可能为坏成功形状或成功载荷与请求不一致 | 空；旧值保持 |
| `资源失败` | 空 | 空 | 空；旧值保持 |
| `内部不一致` | 空 | 空 | 空；旧值保持 |

`资源失败 / 内部不一致` 即使发生在某次 R1 调用或结果复制之后，也统一清空两个阶段 optional，避免异常处理再次复制不完整材料；既有发布值不变。`成功()` 必须逐字段核对上述形状、请求、登记、树身份、根标记和截止。结果中的 R1 DTO只供诊断与验证，不取得根权威。

## 6. 消费算法、并发与异常

`消费` 完整持有 `发布锁_`，唯一锁序为 `I2 发布锁 -> R1 场景服务内部锁`；R1 不回调 I2，I2 不同时持有 I1 私有锁、普通应用锁或其它服务锁，不做 I/O、日志、等待或用户回调。

固定算法：

1. 纯值验证请求；无效返回 `请求无效`，零 R1 调用；
2. 若 `已发布材料_` 存在且其内嵌请求与本次请求不同，返回 `已发布选择冲突`，零 R1 调用；
3. 调用 `场景服务_.读取当前场景树结构登记()`；失败映射 `树结构登记读取失败`，保留实际结果；
4. 用本轮登记结果的非零截止、当前读取类别和请求树形成 `L2场景树读取请求`，调用 `场景服务_.读取场景树()`；失败映射 `根正式读回失败`；
5. 验证返回树的 `树 / 根场景` 与请求相等，根位于场景组；当前根标记与请求首次根标记的树、场景、根场景、类别、关系稳定编码、物理目标和首次创建生命周期相同；根无父；结构登记与读取内嵌登记一致；全部投影完整且共同截止等于本轮登记截止；
6. 任一坏成功形状或不一致返回 `根读回不一致`，不发布；
7. 在局部完整构造材料、来源和结果；`自我世界树根消费材料` 及嵌套值式 DTO 必须通过不抛出移动 / 交换编译期断言；
8. 用局部 `optional` 与唯一成员 `已发布材料_` 执行无抛出 `swap`；材料内嵌请求是唯一发布选择副本，首次返回 `已发布 / 首次消费`，已有同请求返回 `精确重复 / 已发布重复消费`。

即使已有同请求发布值，第 3—5 步也必须再次执行。树在此期间可以合法增加非根成员并推进截止；只要根身份、首次标记和 R1 整树不变量仍成立，I2 刷新为新整树材料。根退出、根标记改变、树身份复义、根有父或任何整树不一致固定失败并保留旧值。

外层捕获 `std::bad_alloc` 返回 `资源失败`；其它异常返回 `内部不一致`。锁取得异常、R1 未捕获异常、局部复制或结果构造异常均不得越过 `noexcept`。构造 / 交换前失败不清空旧值；I2 从不撤销 R1 事实。

`读取已发布材料()` 在同一锁下按值复制；未发布返回 `nullopt`，锁或复制异常向调用方抛出，不伪装为空或成功。

## 7. 普通应用装配与正式启动

普通应用装配在局部 A1 聚合成功后、发布上下文前构造一个 `std::unique_ptr<自我世界树根消费适配器>`，构造参数精确为 `聚合服务->取得L2场景结构服务()`。上下文私有构造函数在聚合参数后追加 `std::unique_ptr<自我世界树根消费适配器>&& 根消费适配器`；构造初始化列表和成员声明都在 I1 三槽之后追加 `根消费适配器_`，最终成功路径一次移动全部局部所有者。适配器构造或分配失败返回专属装配状态，不发布上下文。新增 const / 非 const getter：

```cpp
自我世界树根消费适配器& 取得自我世界树根消费适配器() noexcept;
const 自我世界树根消费适配器& 取得自我世界树根消费适配器() const noexcept;
```

适配器 `make_unique` 失败使用从 I1 激活基线最终最大 `普通应用装配状态` 后连续追加的专属状态；具体整数在执行 S0 绑定，不复用旧值。上下文成功发布前适配器必须非空；不允许延迟构造或可空成功上下文。

`运行普通程序` 顺序固定：

```text
普通应用装配
-> I1 初始化并发布系统世界树根
-> 从 I1 成功结果形成 I2 请求
-> 上下文唯一 I2 适配器.消费
-> I2 失败：初始化失败 / 自我世界树根消费 = 16
-> I2 成功：初始化失败 / 自我初始化能力未实现 = 17
```

I2 实施同步删除 I1 引入的 `自我初始化待适配 = 15` 枚举项和成功后的阶段 15 无条件返回，但保留其它既有枚举数值且永久不复用 15。阶段 16、17 连续追加且不重排旧值。I1 失败继续映射阶段 14且不调用 I2。

所有三条路径都不进入方法登记根、自我线程、概念、控制面板、停止信号或宿主。后继真实自我形成 provider 实现、正式读回、生产接通和验证后，才能另立计划删除阶段 17；不得由 I2 预建空 provider 或固定成功结果。
