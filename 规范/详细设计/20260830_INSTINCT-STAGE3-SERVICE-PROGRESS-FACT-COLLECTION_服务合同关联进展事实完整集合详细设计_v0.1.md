# INSTINCT-STAGE3-SERVICE-PROGRESS-FACT-COLLECTION 服务合同关联进展事实完整集合详细设计 v0.1

日期：2026-08-30

设计身份：`INSTINCT-STAGE3-SERVICE-PROGRESS-FACT-COLLECTION`

## 1. 目标与完成边界

本设计扩展现有唯一 `服务合同事实权威服务`，使它能够在指定非零事实截止 `G0` 下返回同一自我的完整当前服务合同关联进展事实组，并以结构登记、规范成员身份组和读前 / 读后守卫证明合法空集合与“未取得材料”不同。

本叶只形成进展事实的中性权威承载和完整集合读取，不裁决 `6170` 的“当前存在有效服务活动”。进展事实携带服务合同、任务、方法、执行冻结、方法真实执行、安全门禁、进展状态 / 动态和运行状态的强类型引用；后继活动裁决必须逐项独立读回这些引用后再执行五项合取。任何引用缺失、复义或漂移都不得被解释为“不存在活动”或“安全门禁允许”。

本叶不建立第二 owner，不新增服务准备语义，不建立低位安全回升门禁 owner，不调用单完整秒规则内核，不推进维护游标，不写 A / V、状态或动态，也不接生产进展发布者。没有生产发布者时，完整空进展集合只是当前事实，不能证明阶段三维护闭环完成。

## 2. 正式依据与当前事实

正式依据：0050 v2.1、6100 v0.5、6120 v0.10、6160 v0.4、6170 v0.6，以及 `计划/数据服务最终需求清单.md` 对 DATA-EXT-16 当前服务进展组的既有能力边界。

当前代码基线：`main == origin/main == de9fd384bc4b3841bfd25c43d216171c4d25ac4a`，index 空。当前已有：

1. `服务合同事实权威服务` 的唯一 owner、基础结构登记、有效未满足合同完整集合和到期未满足事件完整集合；
2. `0x0307'3001..3013` 已使用，原计划为同 owner 后继保留 `0x0307'3014..301F`；
3. `服务活动裁决_v1` 仅是单完整秒纯值内核输入，生产代码没有服务进展完整集合读取入口；
4. 现有任务、方法、状态、动态和安全相关代码没有一个公开入口能单独证明 `6170` 第 5 节五项有效活动条件；
5. 工作区存在与本设计无关的 SELF-GOVERNANCE WIP，本设计和后继施工不得覆盖或带入。

因此裁决为：扩展同一服务合同 owner 形成“进展事实承载 + 完整集合”，而不是扩展任务 owner、从线程 / 队列 / 日志推断活动，或新建第二服务活动 owner。

## 4. 数据合同

### 4.1 身份与运行状态

```cpp
inline constexpr std::uint32_t 服务进展事实扩展合同版本_v1 = 1;

struct 服务进展事实身份_v1 { 稳定编码 值; };
```

### 4.3 请求、见证和结果

```cpp
struct 服务进展完整集合读取请求_v1 {
    std::uint32_t 合同版本;
    L2结构请求头 请求头;
    L2存在身份 自我;
};

struct 服务进展完整集合见证_v1 {
    std::uint32_t 结构登记版本;
    std::uint64_t 声明成员数;
    std::vector<服务进展事实身份_v1> 规范成员身份组;
    std::uint64_t G0;
};

struct 服务进展完整集合读取结果_v1 {
    std::uint32_t 合同版本;
    服务合同事实权威读取状态_v1 状态;
    std::vector<服务合同关联进展事实_v1> 完整进展事实组;
    std::optional<服务进展完整集合见证_v1> 完整集合见证;
    std::uint64_t 本次正式读回截止;

```

成功只允许 `状态=已读取`、截止等于 `G0`、见证完整、事实组与规范身份组逐项相同、按进展身份严格升序且每项完整。0 项是合法成功；全部非成功必须空组、空见证、截止 0。

保留现有 owner 身份、交付类型和 `0x0307'3001..3013` 基础登记不变。新增独立幂等扩展登记，不改写或重放基础登记写集：

```text

3015 当前服务进展索引根
3016 当前服务进展成员关系
3017 进展服务合同关系

3019 进展需求关系
```

## 6. 读取算法

公开入口：

```cpp
服务进展完整集合读取结果_v1
服务合同事实权威服务::读取当前服务合同关联进展完整集合_v1(
    const 服务进展完整集合读取请求_v1&) const noexcept;
```

固定流程：

```text
合同版本 / 自我 / G0 校验
-> G0 读前守卫
-> 同 owner 一致关系类型闭包读取进展成员及合同、自我、需求、任务、方法、状态、动态关系
-> 基础登记与扩展登记逐项互证
-> 按成员重建进展载荷
-> 互证合同载荷中的自我、需求和请求自我
-> 互证全部关系端点、生命周期和载荷引用
-> 按进展身份规范排序
-> 形成完整集合见证
-> G0 读后守卫
-> 成功或结构化非成功
```

成员关系、载荷、合同引用或任一外部引用缺项 / 多义时整体 `集合不闭合`或`引用冲突`，禁止跳过坏成员返回部分成功。底层资源失败、入口拒绝、许可拒绝和当前性漂移沿用现有状态矩阵。

## 7. 验证矩阵

专项至少覆盖：

1. 既有基础登记恢复后首次追加扩展登记，以及扩展登记精确恢复；
2. 0 / 1 / N 当前进展完整集合、规范排序和同一 `G0`；
3. 进行中与七种非进行状态全部保留，不由 provider 裁决有效活动；
4. 状态 only、动态 only、状态 + 动态，以及两者都空拒绝；
5. 合同 / 自我 / 需求错绑，任务 / 方法 / 三类见证无效，时间窗逆序和版本为零；
6. 漏成员、额外成员、重复成员、坏载荷、错关系端点和混合 `G0`；
7. 读前漂移、读中漂移、资源失败、异常映射和非成功零载荷；
8. 同进程重构、持久恢复后逐字段一致；
9. 仓库外 ABI consumer 调用公开读取，生产构建不存在 fixture 或公开进展写入口；
10. v143 x64 Debug / Release 根工程 Rebuild。

## 8. 完成声明边界

本设计完成只证明同一服务合同 owner 可以权威承载并完整读取服务合同关联进展事实。它不证明真实任务执行已经发布进展，不证明安全门禁或方法执行见证成立，不证明当前存在有效服务活动，不证明服务准备活动、低位安全回升门禁、被动维护事务、阶段三或 `INSTINCT-ROUTE` 完成。
