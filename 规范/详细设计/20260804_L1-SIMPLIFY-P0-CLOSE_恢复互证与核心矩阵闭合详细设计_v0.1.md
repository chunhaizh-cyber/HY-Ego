# L1-SIMPLIFY-P0-CLOSE 恢复互证与核心矩阵闭合详细设计 v0.1

设计基线：`fcbb7a908e90f0bc56100a5977601cacf77c0d01`

## 1. 目标与边界

本叶只闭合 4015 已经冻结、但 P0-FIX v0.2 结果尚未完整兑现的两类核心合同：

1. 恢复材料中的当前、历史、永久占用、幂等账和审计记录必须形成可机械验证的完整互证；恢复发布后必须从仓库权威状态重新构造快照并校准结果。
2. 顺序 270 专项必须覆盖多属性、多关系、属性替换、关系替换、幂等、冲突、生命周期、恢复拒绝和隔离。

不改变 `L1事实基座.数据.h`、11 个服务函数签名、状态枚举稳定值或 L2 领域合同；不接入 SQL、索引、材料文件、运行期、P4、旧仓或生产恢复。

当前正式事实：

- `仓库.L1事实基座.ixx` blob=`a340c39701aecc87ec1594cb6844f8aea203e506`；
- `自检.L1事实基座.ixx` blob=`3243ebc7cbb93b78fd4d4ee03cfae12b3c4bb885`；
- `状态完整` 只验证部分当前引用、历史已退出和幂等账基本形状；
- `恢复材料转状态` 只搬运材料，没有验证历史生命周期、永久占用闭合、规范化写集、审计序号及幂等账互证；
- 恢复确认在交换后没有以重新构造的权威快照逐项校准；
- 当前专项只有单属性成功、悬空关系拒绝、单值退出和基础恢复，没有覆盖 4015 §6 的多属性、多关系及替换矩阵。

## 3. 仓库不变量

### 3.1 当前、历史与永久占用

建立恢复候选前先校验当前仓库自身；随后仅在隔离副本中校验外部材料。两者使用同一组不变量，但错误归属不同。

1. 当前节点、关系和值编码非零、跨三表唯一，记录编码与表键一致，创建代次在 `1..当前事实代次`，退出代次为空。
2. 历史事实编码非零、跨当前/历史唯一，记录编码与表键一致，创建代次非零，退出代次存在，并满足 `创建代次 <= 退出代次 <= 材料事实代次`。
3. 永久占用编码非零、唯一，且与当前事实编码和历史事实编码的并集精确相等；不得缺失，也不得以没有事实记录的额外编码掩盖历史缺口。
4. 当前关系的源、目标和关系类型节点必须是当前节点；历史关系的三端必须能在当前或历史节点全集中找到。
5. 当前值的所属、来源和属性类型必须是当前节点；历史值的三项引用必须能在当前或历史节点全集中找到。属性类型必须为属性类型节点，材料分支与其表示一致；独立材料引用指向相应生命周期内存在的节点。
6. 当前属性槽按属性类型编码严格升序且唯一，槽值必须是当前值，并精确回指同一所属节点和属性类型。历史事实不携带第二份当前槽表。

当前仓库违反上述不变量时返回 `内部不一致` 并进入隔离；外部材料违反时返回 `材料不完整 + 当前事实代次`，候选不存在且权威状态零变化。

### 3.2 幂等账与审计互证

每条恢复幂等账必须满足：

1. 表键、`账.幂等键`、`规范化写集.幂等键` 三者相同且非零；
2. 对 `规范化写集` 再次规范化后逐项相等，写集本地键唯一，首次结果状态为成功；
3. 首次结果代次非零且不超过材料事实代次；新编码映射的本地键与写集中新建节点、关系和值本地键一一对应，映射编码属于当前或历史事实，且该事实创建代次等于首次结果代次；纯退出写集允许空映射；
4. 每个幂等键存在且只存在一条 `提交成功` 审计事件，其状态、事实代次和新编码映射与首次结果相同；
5. 同键审计记录从事件序号 1 开始连续严格递增，记录键全部等于分组键；审计组不得没有幂等账，幂等账也不得没有成功审计；后续精确重复、冲突或恢复事件不得改写首次结果。

互证失败一律属于外部 `材料不完整`；不得在恢复时推断、补写或修复输入账目。

## 4. 恢复状态机

### 4.1 建立候选

固定顺序：

```text
取得独占锁并冻结当前代次
-> 隔离检查
-> 未决候选检查
-> 当前仓库不变量检查
-> 期望代次与材料声明代次检查
-> 外部材料确定性校验和互证
-> 构造隔离候选并再次校验同一不变量
-> 保存候选与当前基线
```

- 已有未决候选时返回 `入口拒绝 + 当前事实代次`，不冒充代次漂移。
- 期望代次、材料声明代次或当前代次不相等时返回 `事实代次漂移 + 实际当前代次`。
- 外部材料缺陷返回 `材料不完整`；当前状态或通过材料校验后的候选构造矛盾返回 `内部不一致` 并隔离。

### 4.2 确认与发布后读回

确认时再次校验隔离、候选存在、当前仓库不变量和候选基线。基线漂移丢弃候选并返回实际当前代次。

通过后：

1. 候选目标事实代次设置为确认前当前代次加一；保留材料中各事实的原创建/退出代次。
2. 一次交换整个状态；不得逐表回填。
3. 在同一独占事务内，从已经交换的权威状态重新构造排序后的 `L1完整快照`，并与发布候选的当前三表、永久占用和新事实代次逐项比较；同时重跑仓库不变量。
4. 全部一致才返回 `恢复已发布 + 新当前代次`。
5. 不一致时保留已经发布的新当前代次，设置隔离，返回 `内部不一致 + 新当前代次`；不得回滚为旧状态或用候选预计结果替代读回。

### 4.3 撤销和隔离

撤销只丢弃候选，不推进代次。隔离后当前读取、完整快照、普通提交、建立候选和确认候选均返回内部不一致；不得返回业务事实。隔离不是由调用方材料缺陷触发。

## 5. Debug 专属故障注入

为机械覆盖不能由合法公开输入制造的内部矛盾，允许在 `仓库.L1事实基座.ixx` 中增加仅 `_DEBUG` 编译存在的三项窄测试入口和一次性私有标志：

```text
自检_破坏下一次建立前当前状态不变量()
自检_破坏下一次候选构造结果()
自检_使下一次发布后权威读回不一致()
```

约束：

- 入口只属于仓库模块，不进入 L1 合同/服务模块；Release 不声明、不定义、不导出；
- 只有 `自检.L1事实基座.ixx` 可以调用，全仓其它调用点必须为零；
- 每次设置只消费一次，不能制造成功、不能绕过校验、不能用于生产路径；
- 前两项必须零发布并隔离；第三项必须保留已发布新代次后隔离。

## 6. 顺序 270 专项矩阵

在现有专项内追加，不新增顶层自检项：

1. 一个普通节点同时拥有两个不同属性类型的当前值和两个不同关系子节点；节点只保存两条属性槽，关系只在关系表出现。
2. 一个原子写集完成新属性值发布、旧值退出和槽切换；另一个原子写集完成新关系发布和旧关系退出。分别独立读取新当前、旧历史和完整快照。
3. 上述两类替换的精确重复返回首次映射/代次，同键异义返回冲突且快照零变化；旧编码持续在永久占用中，新分配不得复用。
4. 当前、历史、审计和完整快照 DTO 分账；已退出值/关系的当前读取不返回事实，只能从历史取得；审计序号连续且与幂等账首次成功互证。
5. 恢复材料分别破坏：历史生命周期、永久占用、当前槽、关系端点、材料表示、规范化写集、首次映射、审计键、审计序号、成功事件互证；每项均为材料不完整、零候选、零状态变化。
6. 候选建立、重复建立入口拒绝、撤销、无候选、建立漂移、确认漂移和确认成功逐项断言实际当前代次。
7. Debug 下分别触发建立前状态、候选构造和发布后读回内部矛盾，断言错误分账和隔离；Release 只静态证明测试入口不存在。
8. 并发写入期间重复读取完整快照，任何成功快照都必须通过同一代次不变量；不得返回混代材料。

## 7. 完成边界

完成只证明独立 L1 仓库实例的恢复互证、发布后权威读回和 4015 核心最小矩阵通过。本叶不证明索引重建、属性类型兼容关系、生产恢复来源、运行期恢复接线、旧基座退出、所有领域消费者迁移或集成验收；因此本叶完成后仍不能宣称整个 L1 迁移闭合。
