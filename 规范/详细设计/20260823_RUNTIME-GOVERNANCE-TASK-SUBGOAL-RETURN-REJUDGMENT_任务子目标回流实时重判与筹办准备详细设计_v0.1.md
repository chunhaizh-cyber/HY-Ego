# RUNTIME-GOVERNANCE-TASK-SUBGOAL-RETURN-REJUDGMENT 任务子目标回流实时重判与筹办准备详细设计 v0.1

日期：2026-08-23
版本：v0.1

## 1. 裁决结论

本叶消费一份具名、已发布且处于`子需求已回流待父需求重判`的任务子目标承接记录，实时重判记录中的显式父需求，并只形成以下一个闭合结果：

```text
父需求当前已满足
-> 不筹办，零任务写

父需求当前未满足 + 父需求列表项无当前任务
-> 调用既有需求初次筹办 provider，形成统一轮次 1

父需求当前未满足 + 当前任务就是记录来源任务 + 统一轮次权威
-> task owner 原子形成子目标回流触发的 N+1 后继准备并换代当前关系

父需求当前未满足 + 当前任务就是记录来源任务 + legacy
-> 轮次权威待迁移，零变化
```

原路线少了一个会改变机器结果的幂等条件：首次调用若在“无当前任务”分支建立了新任务，重试时列表项已经出现当前任务；若机械改走统一后继分支，会把同一回流记录错误推进为轮次 2。本设计因此把“已发布筹办结果的同记录分支稳定性”列为核心合同：处理幂等身份不允许调用方选择，而唯一派生为`L2结构幂等身份{回流记录.值.值}`；每次调用先按该稳定键恢复既有初次记录或后继记录，没有既有写结果时才按当前 G 事实裁决。新出现但不等于记录来源任务的当前任务不能消费该记录。

`目标已满足不筹办`、`轮次权威待迁移`和`当前任务冲突`均为绑定本次 G0 与输入的零写裁决，不建立第二决策账；后续以新 G 调用时必须允许重新实时重判。一旦初次或统一后继正式写结果存在，同记录稳定键只能恢复原结果，永不改走另一任务或另一筹办分支。

## 2. 目标、范围与完成条件

目标业务闭环：

```text
读取具名 L2任务子目标承接记录
-> 取记录.父需求，不扫描任选记录
-> 同 G0 读取父需求完整事实、当前成员关系、完整列表项和列表项当前任务
-> 实时裁决父需求当前满足
-> 按已满足 / 无当前任务 / 统一当前任务 / legacy 当前任务分流
-> 对需要筹办的分支形成可恢复的强类型筹办工作包
```

完成必须同时成立：

1. 只消费调用方具名记录，不扫描任务、轮次或记录组选择候选；
2. 父需求只取自记录显式字段，父成员、列表项和当前任务全部按同一 G0 权威读回；
3. 当前满足由已发布`裁决需求当前满足`执行，不从回流状态、子任务完成、任务结果或日志推断；
4. 已满足分支零任务写，且不退出需求、记录或历史任务；
5. 无当前任务分支直接复用已发布初次筹办 provider，新建任务原子取得版本 1 统一权威和轮次 1 当前关系；
6. 只有当前任务等于记录来源任务并且分区为统一权威时，才能发布子目标回流触发的 N+1 后继准备；
7. task owner 在一个事务中创建后继记录、退出旧当前筹办关系并建立新当前关系，不改写旧记录；
8. legacy 当前任务具名返回`轮次权威待迁移`，不 fallback、不暗迁移、不使用实例轮次；
9. 处理幂等身份由具名回流记录稳定身份唯一派生；初次或后继结果一旦存在，同记录只能恢复原结果，不能换键、换任务或换分支；零写结果只绑定本次 G0，后续新 G 允许重新裁决；
10. 实现者不需要再决定 DTO、函数、物理位置、事务顺序、错误映射或验证标准。

## 3. 明确排除项

- 不扫描任选任务子目标记录、需求树或任务组；
- 不让子需求回流、子任务完成或实际状态直接证明父需求满足；
- 不复活旧路径、旧实例、旧冻结、旧结果、旧裁决或旧验证；
- 不取得筹办执行权，不召回方法，不创建路径、实例、冻结或实际结果；
- 不迁移 legacy，不接入初次筹办生产线程，不退役 legacy；
- 不修改任务子目标承接记录状态，不新增“已消费”第二状态账；
- 不进入成员逐项结算、结果共用 / 争用、优先级分配、价值、预算或归因；
- 不把专项测试、工作包、日志、消息或返回摘要当作机器事实；
- 不新增 HTML 流程图。

## 6. 核心机器不变量

### 6.1 具名记录与显式父域

入口只接受一份`L2任务子目标承接记录身份`。当前记录必须：

```text
状态 = 子需求已回流待父需求重判
子需求存在
回流存在且完整
记录.父需求非零
记录.任务非零
```

父需求身份只能取`记录.父需求`。记录组扫描、子需求反查父需求、稳定编码顺序和当前任务反推均不得替代该字段。

### 6.2 同 G0 预读

没有既有幂等结果时，以下读取必须共享请求 G0：

```text
当前记录
父需求完整事实
父需求当前成员关系
完整需求列表项
列表项当前任务
父需求当前满足裁决
```

裁决快照中的需求、当前成员、列表项和事实截止必须与前置读取逐项相等。任一漂移、截止分叉、身份复义或坏成功形状均停止分支选择。

### 6.3 记录身份唯一派生键与双分支恢复

公开请求不接受调用方提供`处理幂等身份`。提供者在校验非零具名记录后唯一派生：

```text
处理幂等身份 := L2结构幂等身份{回流记录.值.值}
```

该稳定键固定映射为：

```text
初次分支：初次筹办准备幂等身份 = 任务建立幂等身份 = 处理幂等身份
后继分支：准备幂等身份 = 触发业务幂等身份 = 处理幂等身份
```

每次调用在实时分支选择前，必须按派生稳定键固定顺序读取：

```text
按处理幂等身份读取后继筹办准备记录
-> 后继存在：立即恢复后继，不再调用初次 reader
-> 后继为空：再按处理幂等身份读取首次初次筹办准备记录
```

该顺序由当前 ABI 冻结：后继 reader 遇到初次写会返回成功空；初次 reader 遇到后继写会把非初次 / 非普通任务事务形状视为内部不一致，因此禁止无条件并列调用或先初次后后继。同一个 task owner 首次写入幂等键只能绑定一份首次规范化写集，合法终态只有无写、初次写或后继写，不存在同键两份首次写。

- 后继存在：证明后继触发类型为子目标回流、触发事实等于记录身份、任务等于记录来源任务、请求 / 运行代次与本次相等，准备幂等身份 / 触发业务幂等身份均等于派生稳定键；按后继保存的来源 G 和发布 G 读回原工作包。不得按当前 N 或最新 G 再推进。
- 后继为空、初次存在：读取具名回流记录，证明首次记录完整请求的需求等于`记录.父需求`，请求身份 / 运行代次等于本次请求，任务建立幂等身份等于派生稳定键；然后用首次记录保存的原完整请求调用既有初次 provider 恢复原工作包。不得按当前任务或最新 G 重新选分支。
- 两次读取都空：只有此时才按 G0 当前事实选择新分支。

公开入口不存在“同一记录换键”自由度。DATA 请求若伪造不等于`L2结构幂等身份{回流记录.值.值}`的键，必须在入口拒绝且零写；同键异义、同一记录已有结果后换任务或换分支均返回具名冲突，不能降级为新请求。

零写裁决不写入持久分支选择：同一记录在后续新 G 上可以重新实时裁决。该边界不能被表述为四类分支全部永久固定；耐久稳定性只由已经发布的初次 / 后继事实证明。

### 6.4 分支稳定

新分支只允许：

| 当前事实 | 唯一动作 |
| --- | --- |
| 父需求已满足 | `目标已满足不筹办`，零写 |
| 未满足、列表项无当前任务 | 调用初次 provider |
| 未满足、当前任务等于`记录.任务`、统一分区 | 提交子目标回流后继准备 |
| 未满足、当前任务等于`记录.任务`、legacy | `轮次权威待迁移`，零写 |
| 当前任务存在但不等于`记录.任务` | `当前任务冲突`，零写；它可能是初次分支结果，只有原键恢复能把它认作本调用结果 |

这保证一次“无当前任务 → 初次筹办”成功后，即使新任务后来退出，同记录重试仍先以派生稳定键恢复原初次结果，不会改走统一后继或再次建立初次任务。

## 7. DATA-L2 task owner 扩展

### 7.1 DTO 物理位置

在现有：

```text
海中鱼巣/领域/L2任务子目标承接记录.数据.h
```

新增：

```cpp
struct L2提交任务子目标回流后继筹办准备请求 final {
    L2结构请求头 请求头;
    L2结构幂等身份 幂等身份;
    L2任务身份 任务;
    L2任务子目标承接记录身份 回流记录;
    L2提交统一轮次推进材料 统一轮次推进;
    friend bool operator==(const L2提交任务子目标回流后继筹办准备请求&,
        const L2提交任务子目标回流后继筹办准备请求&) = default;
};

struct L2提交任务子目标回流后继筹办准备结果 final {
    L2结构结果头 结果头;
    std::optional<L2任务后继筹办准备记录事实> 后继准备记录;
    bool 成功() const noexcept;
    friend bool operator==(const L2提交任务子目标回流后继筹办准备结果&,
        const L2提交任务子目标回流后继筹办准备结果&) = default;
};
```

请求有效性固定要求：合同 / G / 任务 / 回流记录 / 两个幂等身份非零；`幂等身份.值 == 回流记录.值.值`；`幂等身份 == 统一轮次推进.准备幂等身份 == 统一轮次推进.触发业务幂等身份`；推进来源 G 等于请求 G；前驱与 N 形状继续复用`L2提交统一轮次推进材料完整`。因此 DATA 层也不能接受同记录换键。

结果`成功()`只接受`已提交/精确重复`、非零截止和完整后继记录。`引用冲突`允许只携带已消费的既有后继记录供 DATA 外映射，但`成功()`必须为假；其它非成功不得携带成功载荷。

DTO 放在任务子目标记录数据头而不是`L2任务结构.数据.h`，因为它同时引用已定义的记录身份和统一轮次类型，避免建立反向 include 或第二记录身份。

### 7.2 服务函数

在现有`L2任务结构服务`新增：

```cpp
L2提交任务子目标回流后继筹办准备结果
提交任务子目标回流后继筹办准备(
    L2提交任务子目标回流后继筹办准备请求 请求) noexcept;
```

它在现有`L2任务结构服务::互斥体_`下执行：

1. 先按准备幂等身份恢复首次写入；同键同完整请求返回原后继，异义返回幂等冲突；
2. 没有首次结果时要求当前 G 等于请求 G；
3. 同 G 读取具名回流记录，要求状态、回流、父需求和`记录.任务 == 请求.任务`完整；
4. 以`后继触发事实`关系类型按记录身份反查 0..1 个后继；已有同记录同任务同完整键返回原结果，已有不同任务 / 键 / 请求返回`引用冲突 + 既有后继`，多项内部不一致；
5. 同锁读取统一分区，legacy、未知版本、链断和坏当前关系均零写拒绝；
6. 逐项核对权威、首次锚、期望前一后继、期望 N 和当前关系；N 为`UINT64_MAX`内部不一致；
7. 形成并提交本节事务；
8. 按发布 G 读回后继记录和新当前关系，坏读回内部不一致且不撤销已发布事实。

### 7.3 原子写集

复用已发布`任务筹办轮次定位_`、后继节点 / 关系 / 属性类型和写入键，不新增物理登记。一次提交固定：

```text
创建 1 个 L2任务后继筹办准备记录节点
+ 建立后继族 / 任务 / 虚拟存在 / 列表项 / 权威 / 首次锚关系
+ N > 1 时按既有规则建立直接前一后继关系
+ 建立触发事实关系，目标 = 具名回流记录
+ 写入触发类型 = 子目标回流
+ 写入请求身份 / 运行代次 / 业务幂等 / N / N+1 / 来源G / 发布G / 准备幂等
+ 退出旧任务当前筹办准备关系
+ 建立任务到新后继记录的唯一当前关系
```

旧路径、旧实例、实际结果、目标裁决证据和正式待重筹办状态关系必须全空。后继记录和所有旧轮次永久保留，只换代当前关系。

## 9. 固定算法

1. 校验合同、请求身份、运行代次、G 和具名记录；失败零下游调用。校验通过后唯一派生`处理幂等身份 := L2结构幂等身份{回流记录.值.值}`，禁止接收或生成其它键。
2. 用派生稳定键先读后继记录；存在即按 §6.3 恢复并停止，空时才读首次记录；两次都空才进入新裁决。恢复使用已发布记录保存的原 G，不把最新 G 拼入首次结果；不得无条件并列调用两个 reader。
3. 没有既有结果时，以 G0 读取具名回流记录；只接受完整待重判状态。
4. 以`记录.父需求`读取父需求完整、当前成员和完整列表项；三者所属存在、目标、成员端点和列表项必须自洽。
5. 按列表项读取当前任务；可空，非空必须引用同一列表项。
6. 调用`裁决需求当前满足({合同版本, 请求身份, 记录.父需求, G0})`并与前置父需求 / 成员 / 列表项逐项互证。
7. 已满足：返回`目标已满足不筹办 + 裁决`，零写。
8. 未满足且无当前任务：构造既有初次请求，请求身份 / 运行代次 / 父需求来源固定为本请求和记录字段，初次筹办准备幂等身份与任务建立幂等身份固定为派生稳定键；调用初次 provider。`已形成/精确重复`映射为对应状态，其它状态逐项映射。
9. 未满足且当前任务不等于记录来源任务：返回`当前任务冲突`，零写。
10. 未满足且当前任务等于记录来源任务：读取轮次分区。legacy 返回`轮次权威待迁移`；内部不一致停止；统一分区构造推进材料并调用新 task-owner 提交。
11. 统一提交成功后，以后继记录保存的 G0 / G1 历史读回任务、记录、权威、首次锚、前驱和新当前关系，形成后继工作包。引用冲突携带其它既有后继时映射`回流触发冲突`。
12. 发布未知只按原处理键读取后继记录收敛；不得换键、刷新 N 后重放或切换到初次分支。
