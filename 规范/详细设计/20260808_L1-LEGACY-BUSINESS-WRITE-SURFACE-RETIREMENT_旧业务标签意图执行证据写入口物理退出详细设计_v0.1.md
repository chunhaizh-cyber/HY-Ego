## 1. 目标与完成条件

在 `L2-STATE-DYNAMIC-ATOMIC-PUBLISH-NEUTRAL-CRUD-MIGRATION` 结果进入正式 main 后，物理删除核心 L1 已无消费者的 legacy 业务写入和幂等预探测公开面。删除只覆盖旧业务标签、意图、执行证据驱动的写通道；中性 CRUD、管理/恢复/读取、历史 legacy 材料兼容校验和 P13/P14 纯写入规格全部保留。

完成条件：

1. `L1事实基座服务` 不再公开任何 `提交写集` 重载或 `探测幂等`。
2. `L1事实基座仓库` 不再实现旧 `提交`、旧 `探测幂等` 及仅由旧提交调用的私有执行 helper。
3. 核心合同模块不再导出旧幂等探测请求/结果及映射函数。
4. 全仓生产代码对上述入口和类型的引用为 0；正式写入口只剩 `提交中性写集`。
5. 历史幂等账、审计、完整快照、失败见证和恢复材料仍可编译并继续由现有管理面读取/校验；P13/P14 的 `L1写集请求` 纯规格不变。

本叶是接口和死路径删除，不改变中性 CRUD 事务、事实代次、稳定编码、恢复语义或领域业务语义，因此不需要流程图；删除清单和保留矩阵已经足以机械施工。

## 3. 精确删除合同

### 3.1 服务公开面

从 `海中鱼巣/核心/服务.L1事实基座.ixx` 删除：

```cpp
L1写入结果 提交写集(const L1写集请求& 请求);
L1写入结果 提交写集(L1写集请求& 请求, std::uint32_t 操作标签);
L1写入结果 提交写集(const L1写集请求& 请求, std::uint32_t 操作标签);
L1写入结果 提交写集(L1写集请求&& 请求, std::uint32_t 操作标签);
L1幂等探测结果 探测幂等(const L1幂等探测请求& 请求) const;
```

删除上述实现内的标签白名单、意图摘要、执行证据组装和探测转发。`提交中性写集`、全部中性精确读取、legacy 当前/历史/审计/完整快照读取、恢复材料导出及恢复候选建立/确认/撤销逐字语义保留。

### 3.2 仓库入口与仅属旧提交的 helper

从 `海中鱼巣/核心/仓库.L1事实基座.ixx` 删除：

- `L1幂等探测结果 探测幂等(const L1幂等探测请求&) const`；
- `L1写入结果 提交(const L1写集请求&)`；
- 仅由旧提交调用的 `解析读回引用`、`代次匹配`、`执行读回计划`、`形成结果摘要`、`记录审计`。

不得删除或改写：

- `提交中性写集` 及其中对 legacy 幂等键占用的冲突保护；
- legacy `幂等账`、`审计`、`领域结果见证状态组`、`失败见证` 状态字段；
- `规范化写集`、`请求结构有效`、`幂等记录完整` 及恢复材料完整性校验；
- 当前/历史/审计/完整快照/恢复读取、导出和候选操作；
- 中性写集规范化、结构检查、发布和精确读回 helper。

删除后不再产生新的 legacy 幂等账或审计事件，但恢复载入的历史记录仍可被验证和读取。这个边界不授权把历史材料转换成中性账，也不授权清空旧状态。

### 3.3 旧探测合同

从 `海中鱼巣/核心/合同.L1事实基座.ixx` 删除只服务旧探测的：

```text

L1幂等探测请求
L1幂等首次结果副本
L1幂等探测结果
```

该模块中的当前/历史/审计/完整快照/恢复请求合同全部保留。`节点直接类型化结构提交` 的同名幂等探测属于另一套类型和入口，不在本叶范围。

## 4. 必须保留的数据合同

`海中鱼巣/核心/L1事实基座.数据.h` 本叶零修改。至少以下结构不能因“名称含 legacy 字段”而删除：

1. `写集本地键`、`事实引用`、节点/关系/值/属性槽新建项和 `L1写集请求`：P13/P14 仍以它们形成不可变纯规格，尚未迁移提供者合同。
2. `L1写入结果`、`L1幂等账记录`、`L1审计记录`、`L1完整快照`、`L1恢复材料`、发布后失败见证：历史账和管理/恢复材料仍依赖。
3. 意图、确定性摘要、执行证据、领域结果见证及其校验函数：仍是历史幂等账与恢复材料完整性的一部分。本叶只取消普通生产写入入口，不改写历史格式。
4. `读取提供者身份` 与 `L1提供者身份凭证` 保守保留；其清理需要单独证明没有历史或管理合同依赖，不与本入口删除混做。

P13/P14 不取得 L1 写权；保留 `L1写集请求` 只表示它们现行规格 DTO 尚未拆分，不允许新的业务调用方用该类型调用核心 L1。
