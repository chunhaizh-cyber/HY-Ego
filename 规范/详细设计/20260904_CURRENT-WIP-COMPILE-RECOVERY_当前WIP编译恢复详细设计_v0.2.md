# 当前 WIP 编译恢复详细设计

身份：`CURRENT-WIP-COMPILE-RECOVERY`
版本：v0.2
日期：2026-09-04
状态：可施工设计；替代 v0.1，仅与同身份 v0.2 实施计划共同授权代码施工。

## 1. 修订原因、目标与不变边界

执行 `CURRENT-WIP-COMPILE-RECOVERY` v0.1 后，隔离构建的首个新增错误位于
`海中鱼巣/业务/提供者.真实自我形成.ixx`：该 WIP 删除了
`import 海中鱼巣.装配.普通应用;`，而其导出的 `真实自我形成请求` 仍按既有 ABI
以 `自我世界树根消费材料 根消费材料` 为字段。该类型只由
`海中鱼巣.装配.普通应用` 导出，故所有“根消费材料不是成员”、`截止` 未声明和随后
`optional::emplace` 失败均是同一模块不可见的级联。

本修订仍只恢复保留旧服务和 E2E canonical 源删除后的 `Debug|x64`、`Release|x64`
编译。它不恢复 `服务.需求初次筹办准备.ixx`、其 DTO 或任何端到端测试源码，不继续
C031 或已退出退役计划，也不声称运行、业务闭环或端到端验收。

不改变 `真实自我形成请求`、`自我世界树根消费材料` 或任何其它公开 DTO 的字段、版本、
状态值、所有权、生命周期和业务语义；不在普通应用模块中引入 SELF-FORM import；不改
`启动.应用程序.ixx`、`真实自我形成.数据.h`、普通应用模块正文或工程登记。

## 2. 已核对事实与裁决

1. `真实自我形成.数据.h` 的第 25 行声明 `自我世界树根消费材料 根消费材料`；该头在
   `提供者.真实自我形成.ixx` 的 `export {}` 中被公开，因此其类型在本模块编译时必须
   已可见。
2. `海中鱼巣/装配.普通应用.ixx` 以 `export module 海中鱼巣.装配.普通应用` 导出该
   类型与 I2 相关自由函数；8120 §5 指定该普通应用上下文拥有 I1/I2 值式材料。
3. 当前普通应用模块不 import `海中鱼巣.业务.提供者.真实自我形成`；启动模块才同时
   import 两者。因此恢复既有 provider -> ordinary-application 依赖不形成模块环。
4. `HEAD` 中该 provider 的相同位置原已有该 import；现场差异只有该行被删。恢复它是
   编译可见性修复，不是 DTO 迁移、接口扩展或机器语义选择。

裁决：在 v0.1 的既有恢复步骤之后，只恢复该条既有 import。不得为绕过模块可见性而把
`自我世界树根消费材料` 复制到 DTO 头、改为前置声明、移动类型、改聚合初始化或更改
`真实自我形成请求`。

## 3. 精确施工合同

唯一新增允许写入文件为 `海中鱼巣/业务/提供者.真实自我形成.ixx`。在其既有三个 L2
service import 之后、`export { #include "真实自我形成.数据.h" }` 之前，恢复且只恢复：

```cpp
import 海中鱼巣.装配.普通应用;
```

不得改变相邻 module 声明、其它 import、`export {}`、provider 实现、类成员、请求字段或
任何调用点。若该行恢复后仍报告普通应用 module 不存在、出现模块环，或首错要求修改
`真实自我形成.数据.h` / `装配.普通应用.ixx` / `启动.应用程序.ixx`，停止受影响施工并
具名退回计划支撑；这些情形不由本修订静默扩展。

v0.1 已授权的普通应用工程输入恢复、旧筹办 consumer 删除和 L2 回流尾段补全仍保留，
但其余允许/禁止集、施工步骤、隔离构建和旧服务归零要求均以 v0.1 为准；本文件只在
上述冲突处优先。
