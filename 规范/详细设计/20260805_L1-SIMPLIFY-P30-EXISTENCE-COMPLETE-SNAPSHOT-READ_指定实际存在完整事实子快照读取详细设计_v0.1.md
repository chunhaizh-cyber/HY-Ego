## 1. 目标与完成边界

本叶原位扩展 P29 冻结的唯一 `世界树快照读取服务`，新增 `读取存在完整事实`。函数先校验指定世界根和目标实际存在见证，随后恰调用一次 P29 `读取完整世界事实快照`；整树成功后只在该不可变纯值快照上投影目标存在、当前场景、全部当前实例特征、相关状态和迁移动能，形成 4200 §4 要求的指定存在完整事实子快照。

必须同时成立：

- 目标必须在 P29 完整世界快照的当前存在组恰一命中；移出树但仍存在、历史存在、场景或任意其它节点不得混入；
- 当前场景、当前归属关系、宿主特征组与目标一一闭合；全部实例槽、定义、当前值、材料和来源只复用 P28 已验证事实；
- 状态只纳入 `主体 == 目标存在`；动态只纳入主体/来源存在为目标，或被改变目标属于该存在实例槽的当前状态迁移动能；
- 结果沿用整树根、非零事实截止、合同/组合/完整性/排序版本，筛选后仍保持稳定顺序；
- 合法零特征、零状态、零动态成功空组；目标不在当前树返回未找到；任一矛盾返回零部分子快照；
- 函数对 P19/P21/P17/P22/P24—P28 等直接 provider 调用均为0，只调用 P29 整树入口恰一次且不建立第二重试。

本叶不设计场景子快照、统一 `世界树业务服务`、写入口、比较、动作动态、因果、结算、恢复装配、生产线程接线、旧消费者迁移或 STEP-5。

在 `L1完整世界快照.数据.h` 追加：

```cpp
inline constexpr std::uint32_t 完整世界对象快照投影规则版本 = 1;

struct 完整世界存在事实快照 final {

    std::uint32_t 世界规则版本 = 世界登记规则版本;
    std::uint32_t 组合规则版本 = 完整世界快照组合规则版本;
```

## 5. 请求准入与整树结果映射

调用 P29 前固定验证：

1. `请求.世界` 满足 P28/P29 合同、世界规则、组合规则和非零普通节点根；
2. `投影规则版本 == 完整世界对象快照投影规则版本`；该版本由存在/场景对象子快照共用，后继场景叶不得另建第二对象请求版本；
3. `目标.稳定编码` 非零且节点类型为普通节点；实际存在资格只由整树 `存在组` 命中证明，不能由名称、场景成员裸关系或 P7 登记猜测。

任一失败返回入口拒绝、空快照、空缺项，P29调用0。准入成功后以 `请求.世界` 恰调用一次 `读取完整世界事实快照`：

| P29状态 | P30结果 | 规则 |
| --- | --- | --- |
| 已读取且快照完整 | 进入纯值投影 | P29调用恰1 |
| 未找到/入口拒绝/版本漂移/许可拒绝/资源失败/未实现 | 同名返回 | 快照空、缺项空 |
| 内部不一致 | 内部不一致 | 快照空；P29稳定缺项原样复制 |
| 写入口状态、坏成功、未知枚举 | 内部不一致 | 快照空、缺项空 |

P29 成功必须同时具备 optional、`完整=true`、非零截止、根/版本等于请求且缺项空，否则为坏成功，立即内部不一致。P30 不在 P29 版本漂移后再次调用 P29；P29 自己冻结的最多两轮已经是唯一重试边界。

## 6. 目标、当前场景与宿主特征闭合

helper 固定按以下顺序处理：

1. 在 `世界.存在组` 按 `存在.存在.存在` 的完整节点见证查找请求目标；零命中返回未找到，多命中或同稳定编码异内容返回内部不一致；
2. 目标 `当前场景` 必须在 `世界.场景组` 恰一命中；对应 `完整世界场景事实.场景.场景` 逐字段等于目标当前场景；
3. 目标 `当前归属关系` 必须在当前场景的 `直接存在成员关系` 恰一命中，方向为当前场景到目标，且逐字段等于 P19/P21 已映射归属；
4. `世界.宿主特征组` 必须按 `宿主.存在` 对目标恰一命中，即使实例特征为空也不得缺失；夹带第二宿主组、同宿主异内容或组内宿主错位返回内部不一致；
5. 宿主组中的每个实例特征必须属于目标，定义、槽、当前值、材料、来源及排序已经由 P28 完整性保证；P30 只复核宿主和稳定顺序，不重新解释 P17。

合法目标零实例特征由一个宿主等于目标且 `实例特征` 为空的宿主特征事实表达，不能用宿主组缺失表示。输出中的当前场景身份与当前归属关系只由 `完整世界存在事实` 携带；P30 不复制整个 `完整世界场景事实`，因此不会把当前场景的其它子场景或成员关系夹带进存在子快照。

内部不一致缺项使用 P28 既有种类：实际存在范围矛盾、存在当前归属矛盾、实例槽/定义/当前值范围矛盾或稳定排序错误；诊断按 P28 `(种类, 主身份, 关系身份, 相关身份)` 排序去重。不得新增文本诊断或第二缺项枚举。

## 7. 状态与动态相关性投影

状态组只保留 `当前世界状态事实.主体 == 请求.目标` 的项目。每项场景必须等于目标当前场景或属于 P27 已冻结的本树合法场景范围，特征端点必须在目标宿主特征组恰一命中；来源存在和全部类型化见证仍由原项目携带。任一目标状态引用其它宿主实例槽、缺少特征或同身份异内容返回内部不一致，不静默丢弃损坏项目。

先从目标宿主特征组建立纯值实例槽身份集合。动态组保留满足任一条件的项目：

```text
动态.主体 == 请求.目标
或 动态.来源存在 == 请求.目标
或 动态.被改变目标 == 请求.目标
或 动态.被改变目标 属于目标实例槽身份集合
```

保留动态的前/后状态必须在整树状态组恰一命中；若它因相关性被选中但前/后状态、场景、主体、来源存在或被改变目标与整树闭合关系矛盾，返回内部不一致。P30 不补造动作来源，不解释关系20角色，不改变 P27 已冻结的角色1—5/9与6—8为空规则。

状态组和动态组分别是 P28 稳定排序组的保持顺序子序列；禁止按地址、容器顺序、显示名、时间戳或重新排序算法形成输出。相同整树快照和请求必须逐字段确定相等。

## 8. 输出、异常、并发与生命周期

全部检查完成后才形成成功值：

- 六个版本来自正式常量/请求并与整树相等；
- 世界根、截止来自整树；
- 存在事实（内含当前场景和当前归属关系）、宿主特征逐字段复制已验证项；
- 状态/动态为保持稳定顺序的相关子序列；
- `完整=true`，缺项空。

未找到、入口拒绝、版本漂移、许可拒绝、资源失败和未实现均为空快照、空缺项。内部不一致为空快照，可携带稳定缺项。任一失败先销毁临时 vector，不返回部分子快照。

函数不 `noexcept`；`std::bad_alloc` 映射资源失败，其它未预期异常映射内部不一致，异常不触发第二次整树读取。函数只借用请求和 P29 返回值，返回后不保存引用、目标索引、子快照、截止或缓存。多个线程并发调用只共享 P29 服务对象的只读入口，P30 无新锁和共享状态。
