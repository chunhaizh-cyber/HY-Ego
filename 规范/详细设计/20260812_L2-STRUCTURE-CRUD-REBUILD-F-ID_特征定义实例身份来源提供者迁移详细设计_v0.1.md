## 1. 目标与完成边界

本叶把现有单一中性写面的 `L2特征结构服务` 原位迁入 G2 的两个独占 owner：特征定义与特征实例。完成条件固定为：

1. 两套不可默认构造、不可复制、可移动且编译期不可交换的 owner 交付替代 raw 端口；
2. 定义 / 实例分别建立不可变族锚点和归属关系类型；
3. 新定义与定义归属关系同写，新实例与实例归属、宿主、定义三关系同写；
4. 宿主只经 E-ID 公开来源证明，定义引用只经本服务定义来源证明；
5. 定义 / 实例当前、历史、完整读取和按存在枚举按同一请求代次闭合来源；
6. 属性、值、退出全部复用正式来源，wrong-family、legacy、裸节点、内部节点和 malformed 精确失败；
7. 普通应用在唯一 L1 运行包内依次发布存在服务、两个特征 owner 和唯一特征服务；
8. 根工程与生产外双配置矩阵通过，临时验证三文件随后独立删除。

本叶不修改 L1、4230/G2/E-ID 合同、状态 / 动态 / 因果 / 场景服务、T1、DYN2、S-ID 或 A1，不沿用历史状态 / 动态登记代码，不 adoption v1 特征事实，不建立第二仓、成员表、身份缓存权威或恢复入口。计划通过只证明设计可机械施工，不证明 E-ID 或 F-ID 已实现。

## 4. 数据合同

在 `L2特征结构.数据.h` 新增两套请求 / 结果，字段顺序固定为：

```cpp
struct L2特征定义身份来源读取请求 final {
    L2结构请求头 请求头;
    L2读取类别 读取类别 = L2读取类别::当前;
    L2特征定义身份 特征定义;
    std::uint64_t 历史截止事实代次 = 0;
};
struct L2特征定义身份来源读取结果 final {
    L2结构结果头 结果头;
    L2读取类别 读取类别 = L2读取类别::当前;
    std::uint64_t 历史截止事实代次 = 0;
    std::optional<L2节点族身份来源事实> 身份来源;
};
```

实例套用同形字段，类型名为 `L2特征实例身份来源读取请求 / 结果`，身份字段为 `L2特征实例身份 特征实例`。四个结构均提供默认等号；请求有效性与 E-ID 同规则：合同 / 类别 / 身份 / 截止非法即入口拒绝。

`L2特征定义退出请求` 在 `特征定义` 后、`当前固定属性值` 前新增 `稳定编码 族归属关系稳定编码`；`L2特征实例退出请求` 在 `特征实例` 后、`自有关系` 前新增同名字段。定义 / 实例事实与完整读取结果保持现有公开形状，不重复嵌入来源 DTO；其成功路径内部必须闭合来源。

L1 owner ABI 要求值、所属节点和属性类型节点同 owner。raw 定义端口封装后，外部 L1 创建的属性类型不能再供定义属性写入，因此本叶必须同时提供定义 owner 内属性类型登记，不能把现有固定属性成功分支永久变成许可拒绝。新增四个精确身份 `L2特征定义I64属性类型身份`、`L2特征定义I64组属性类型身份`、`L2特征定义U64组属性类型身份`、`L2特征定义独立材料属性类型身份`；新增 `L2特征定义属性类型登记请求 / 登记 / 结果` 和独立 `L2特征定义属性类型登记状态`。字段及成功 / 失败形状与现有 `L2特征值类型登记*` 同构，但两套身份类型不可互换。服务公开：

```cpp
L2特征定义属性类型登记结果 建立特征定义属性类型登记(
    const L2特征定义属性类型登记请求&);
L2特征定义属性类型登记结果 读取当前特征定义属性类型登记() const;
```

登记规则版本固定为 1，固定请求幂等身份为 1。登记字段固定为合同版本、规则版本、首次幂等身份、首次期望代次、建立代次、截止代次和上述四身份；结果字段固定为状态、截止和可选登记。状态数值与现有值类型登记严格同构：`已提交=1、精确重复=2、已读取=3、登记未加载=4、入口拒绝=5、许可拒绝=6、事实代次漂移=7、幂等冲突=8、资源失败=9、内部不一致=10`。定义属性写请求的 `新属性.属性类型身份` 必须等于登记中与材料表示精确匹配的类型，否则入口拒绝。不得复用实例值类型编码或仅靠材料变体猜类型。

## 5. 强类型 owner 与构造

服务模块 export：

```cpp
inline constexpr L1所有者范围建立幂等身份 特征定义所有者建立身份{
    0x4C31'4F57'4E45'5232ULL};
inline constexpr L1所有者范围建立幂等身份 特征实例所有者建立身份{
    0x4C31'4F57'4E45'5233ULL};

class L2特征定义所有者交付;
class L2特征实例所有者交付;
std::optional<L2特征定义所有者交付> 尝试形成L2特征定义所有者交付(
    const L1事实基座服务&, L1所有者范围交付&&) noexcept;
std::optional<L2特征实例所有者交付> 尝试形成L2特征实例所有者交付(
    const L1事实基座服务&, L1所有者范围交付&&) noexcept;
```

两包装均不可默认构造 / 复制，不提供 raw 解包、owner 选择、模板共型或跨包装转换；只允许对应形成函数构造、`L2特征结构服务` 消费。两形成函数逐项镜像 E-ID：建立结果合同版本必须为 `L1所有者范围CRUD合同版本`，回显幂等身份必须为本族常量；首次成功必须发布且重试边界为不适用，精确重复必须不发布且重试边界为原幂等身份读回收敛。owner 事实必须存在、独占、创建代次非零且未退出；结果代次、owner 事实、端口 owner 和包装 owner 一致；端口有效并绑定传入同一 L1 实例。其余状态或形状不形成。定义交付不能放入实例参数，反之亦然；错合同版本、发布位、重试边界、代次、owner 和跨实例都进入错交付矩阵。

构造固定为：

```cpp
explicit L2特征结构服务(
    const L1事实基座服务& 第一层读取服务,
    const L2存在结构服务& 存在服务,
    L2特征定义所有者交付&& 特征定义所有者交付,
    L2特征实例所有者交付&& 特征实例所有者交付);
```

成员为两个精确端口、const L1 读取和 const 存在服务。失效 / 已移动包装抛 `std::invalid_argument`；任一初始化结构化失败抛 `std::runtime_error`。构造固定依次完成定义来源、定义属性类型登记、实例来源、实例宿主 / 定义关系类型登记、实例四值类型登记；全部定位重载完成后才发布服务，失败不发布半构造服务。

## 6. 两套来源初始化

固定常量与本地键：

| 族 | 来源登记幂等身份 | 锚点键 | 类型键 | 每节点归属关系键 |
| --- | --- | --- | --- | --- |
| 特征定义 | `0x4C32'4944'5352'4302ULL` | `0x0203'2001U` | `0x0203'2002U` | `0x0203'2003U` |
| 特征实例 | `0x4C32'4944'5352'4303ULL` | `0x0203'2101U` | `0x0203'2102U` | `0x0203'2103U` |

`初始化特征定义身份来源()` 与 `初始化特征实例身份来源()` 分别通过对应端口同写锚点 / 关系类型两个普通节点，从首次代次 owner-aware 历史读回。首次 / 精确重复必须取得同两个不同编码并形成不可变非权威定位 `{owner, 锚点, 类型, 建立代次}`。不得扫描、补登记、恢复或复用另一族定位；全部定义 / 实例公开写分别拒绝使用本族来源登记幂等身份。

现有宿主 / 定义关系类型和四个值类型登记全部迁入实例端口；它们不是族来源锚点。关系类型登记 owner-scoped 固定幂等身份为 `0x4C32'4649'5245'4C01ULL`，值类型登记固定为 `0x4C32'4649'5641'4C01ULL`，沿用现有本地键和公开请求 / 结果合同。定义固定属性值只走定义端口。实例节点、宿主 / 定义关系、当前值和其类型登记只走实例端口。

定义属性类型登记使用定义端口，以私有固定 owner-scoped 写幂等身份 `0x4C32'4644'4154'5201ULL` 同写四个 `节点种类::属性类型`，本地键固定 `0x0203'2201U`、`0x0203'2202U`、`0x0203'2203U`、`0x0203'2204U`，表示依次为 I64、I64组、U64组、独立材料引用。首次 / 精确重复从首次代次读回四个不同编码并形成只读定位；同键异义冲突。全部普通定义写拒绝该内部幂等身份。它不是第三节点族，不建立族归属关系，不接受公开定义身份读取。

构造期用上述三个固定登记幂等身份执行首次建立或精确重复重载，故服务对外可见时内部保留集合必定完整：定义集合为定义锚点、定义归属类型和四个定义属性类型；实例集合为实例锚点、实例归属类型、宿主 / 定义关系类型和四个实例值类型。来源读取在检查归属前先按本族保留集合拒绝目标编码；即使 raw 路径曾给内部普通关系类型恶意挂上归属，也固定 `入口拒绝`。任何定位缺失、重复、与首次读回不符或构造后丢失均 `内部不一致` 并停止全部写入；禁止在定位未加载时退化为 owner + 普通形状。

## 7. 创建与引用证明

新增定义写集固定为：定义普通节点 + `定义节点 -> 定义族锚点`，类型为定义归属类型、角色 1。成功 / 精确重复回两个映射，按首次代次读回 owner、节点、锚点、类型、关系；节点和归属关系同 owner、同创建代次。

新增实例先在请求期望代次完成：

1. `存在服务_.读取存在身份来源(当前)` 证明宿主；
2. 本服务 `读取特征定义身份来源(当前)` 证明定义；
3. 读取实例 owner 下当前关系类型登记；
4. 仍以原期望代次提交实例写集。

实例写集固定为一个实例普通节点和三条关系：实例归属关系、实例到宿主关系、实例到定义关系。三关系均由实例 owner 写；归属指向实例锚点，宿主 / 定义可跨 owner 引用；四事实同创建代次。任一来源失败原样映射且零写；期间发布由 L1 返回事实代次漂移。禁止直达 L1 重演存在来源。

## 8. 当前、历史、完整与枚举

公开 const 函数：

```cpp
L2特征定义身份来源读取结果 读取特征定义身份来源(
    const L2特征定义身份来源读取请求&) const;
L2特征实例身份来源读取结果 读取特征实例身份来源(
    const L2特征实例身份来源读取请求&) const;
```

当前来源使用对应 owner-aware 一致投影核对 owner、目标、锚点、类型和“目标为源 + 精确归属类型”的关系组。目标当前已退出优先 `已退出`；目标 owner 错、非普通节点、内部元数据、legacy、裸 / 未标记节点为 `入口拒绝`；定位后重复、错 owner / 锚点 / 类型 / 角色、混代或生命周期不闭合为 `内部不一致`。

历史来源使用 E-ID 已冻结算法：前后当前代次夹取；节点未在请求截止退出时以请求截止判关系，已退出时以 `节点退出代次 - 1` 判关系；空组再回到节点创建代次区分从未登记与来源提前退出；随后按关系编码读完整生命周期并投影到请求截止。全部历史读回的当前事实代次等于请求期望代次。

定义完整读取把定义来源、节点和全部属性并入同一当前一致投影 / 历史夹取。实例完整读取把实例来源、节点、宿主 / 定义关系、可选当前值纳入实例闭环：当前类别对 E-ID 宿主来源和定义来源均发出当前请求、历史截止固定 0；历史类别对二者均发出历史请求，`历史截止事实代次` 精确等于实例完整读取请求的历史截止，禁止改用实例 / 关系 / 端点创建代次。三个来源和实例字段共享请求头的同一期望当前代次，外层前后代次确保组合历史不混代。端点在该截止已退出时，其历史来源仍以完整退出生命周期证明所属族，不把当前 `已退出` 错用于历史。当前值新增 / 换代 / 历史值读取前必须先证明实例正式来源。

来源结果截止规则与 E-ID 相同：当前成功回显请求期望代次；历史成功回显历史截止；漂移回显实际当前代次；快照前入口 / 许可 / 资源失败回显 0；来源读取永无变更代次。具名 `读取特征值历史` 先在外层当前代次夹取中读取值完整生命周期，再以该值创建代次作为历史截止证明实例来源，并要求值生命周期被实例生命周期覆盖；因此实例退出后仍能读具名历史值，不能错误地用当前来源 `已退出` 阻断历史。

`读取按存在当前特征` 固定流程：先以 E-ID 证明请求存在；按精确宿主关系类型读取目标关系组；对升序唯一实例组以同一期望代次批量闭合实例来源、宿主 / 定义关系和值，并对去重后的定义身份调用定义来源；最后复核当前代次。合法存在无匹配返回 `已读取 + 空组`；wrong-family 存在、实例或定义不得折叠为空组。

## 9. 退出

定义退出写集为定义节点 + 显式定义归属关系 + 全部当前固定属性值。实例退出写集为实例节点 + 显式实例归属关系 + 宿主 / 定义两关系 + 可选当前值。请求关系必须等于同一期望代次完整读取结果；零关系入口拒绝，错关系 / 漏自有事实引用冲突。节点与归属关系同代退出；锚点、归属类型、宿主 / 定义关系类型和值类型登记保持当前。外部引用未闭合继续由 L1 引用闭包拒绝。

## 11. 验证矩阵与完成边界
