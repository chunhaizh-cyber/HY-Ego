## 1. 目标与完成边界

本叶原位扩展唯一新 `L1事实基座` 提交合同，使每笔可能成功的新 L1 写集都在提交前冻结一份业务中性的通用发布后读回计划，并固定执行：

```text
候选完整校验
-> 在候选内形成幂等账、提交审计和预期纯值读回
-> swap发布权威状态并推进一次事实代次
-> 仍持仓库独占锁，按本地键映射从刚发布权威状态重新读回
-> 逐项比较对象种类、中性字段、当前/退出生命周期、属性槽和发布代次
-> 全部一致才返回成功并释放锁
```

发布后出现映射、对象、字段、槽、生命周期、代次或内部异常矛盾时，事实代次和已发布幂等账保持不变；仓库在同一独占锁内安装失败见证并单调进入隔离，然后才返回结构化内部不一致。不得回滚 `swap`、删除事实、补写业务事实、改写首次幂等结果或开放领域稍后通知入口。

本叶最多证明新 L1 具备提交内通用读回、失败见证、隔离、审计和恢复材料互证。它不证明 P6、P13、P14 已实现，不发布后状态或动态，不建立 SQL 运行期权威、生产恢复装配、旧 WORLD-TREE 迁移或 STEP-3 完成。

## 2. 正式依据与当前差异

- 0050 §5：内存代次切换是唯一线性化点，发布后不得伪回滚；读回不一致进入审计/恢复。
- 4015 §4、§6：所有新 L1 写集继续服从 4040 的发布后读回，恢复材料必须互证幂等账和审计。
- 4040 §5：发布后必须按原稳定身份、幂等身份和代次从权威内存读回。
- 4070：恢复材料、发布证据和审计必须全量互证后才能重新发布。
- 4200 §7.6—§7.7：幂等账保存通用值式读回；L1 在独占许可释放前完成读回，矛盾时隔离并写失败见证。

正式基线 `97fea11aece4c4315192de908b6b754b790270ef` 中，`L1事实基座仓库::提交` 在候选中形成幂等账和提交审计，`std::swap(状态_, 候选)` 后立即返回；普通提交没有通用读回计划、权威二次读取、失败见证或隔离分支。恢复确认已有交换后快照读回与隔离，只能作为事务顺序的正面证据，不能替代普通提交逐项读回。

当前幂等账已经保存规范化写集和首次映射；精确重复会返回首次映射。恢复材料已经保存幂等账与审计。因此本叶原位扩展这些结构，不建第二提交入口、旁路索引或扫描式身份恢复。

## 5. 通用发布后读回 DTO

在 `L1事实基座.数据.h` 定义：

```cpp
inline constexpr std::uint32_t L1通用发布后读回计划版本 = 1;

enum class L1通用读回对象种类 : std::uint8_t {
    节点 = 1, 关系 = 2, 值 = 3, 属性槽 = 4
};

enum class L1通用读回当前性 : std::uint8_t {
    当前 = 1, 本次发布退出 = 2
};

enum class L1通用读回代次种类 : std::uint8_t {
    固定 = 1, 本次发布 = 2
};

struct L1通用读回代次期望 final {
    L1通用读回代次种类 种类 = L1通用读回代次种类::固定;
    std::uint64_t 固定代次 = 0;
};

struct L1节点读回期望 final {
    事实引用 身份;
    节点种类 种类 = 节点种类::普通;
    std::optional<值表示种类> 属性类型表示;
    L1通用读回代次期望 创建代次;
    L1通用读回当前性 当前性 = L1通用读回当前性::当前;
};

struct L1关系读回期望 final {
    事实引用 身份;
    事实引用 源节点;
    事实引用 目标节点;
    事实引用 关系类型节点;
    std::int64_t 角色或顺序 = 0;
    L1通用读回代次期望 创建代次;
    L1通用读回当前性 当前性 = L1通用读回当前性::当前;
};

struct L1值读回期望 final {
    事实引用 身份;
    事实引用 所属节点;
    事实引用 属性类型节点;
    原始值材料 材料;
    事实引用 来源节点;
    L1通用读回代次期望 创建代次;
    L1通用读回当前性 当前性 = L1通用读回当前性::当前;
};

struct L1属性槽读回期望 final {
    事实引用 所属节点;
    事实引用 属性类型节点;
    事实引用 当前值;
};

using L1通用发布后读回期望 = std::variant<
    L1节点读回期望, L1关系读回期望,
    L1值读回期望, L1属性槽读回期望>;

struct L1通用发布后读回计划 final {
    std::uint32_t 计划版本 = L1通用发布后读回计划版本;
    std::vector<L1通用发布后读回期望> 项目组;
};
```

`固定`创建代次必须非零；`本次发布`的固定值必须为0。`本次发布退出`只允许稳定编码身份，退出代次必须等于本次新代次。属性槽只描述发布后的当前槽，不允许“空槽”或已退出槽。

节点、关系和值的实际返回使用现行 `节点事实/关系事实/值事实`；槽使用 `L1属性读取副本`。结果定义为：

```cpp
enum class L1通用发布后读回状态 : std::uint8_t {
    成功 = 1, 未执行 = 2, 内部不一致 = 3
};

using L1通用发布后读回副本 = std::variant<
    节点事实, 关系事实, 值事实, L1属性读取副本>;

struct L1通用发布后读回项目 final {
    L1通用读回对象种类 种类 = L1通用读回对象种类::节点;
    L1通用发布后读回副本 副本;
};

struct L1通用发布后读回结果 final {
    L1通用发布后读回状态 状态 = L1通用发布后读回状态::未执行;
    std::uint64_t 发布事实代次 = 0;
    std::vector<L1通用发布后读回项目> 项目组;
};
```

`L1写入结果` 增加 `发布后读回` 和可选 `失败见证身份`。写前非成功为 `未执行/0/空组`；成功与精确重复必须返回首次完整读回；发布后失败返回 `内部不一致`、已发布非零代次、原映射和失败见证身份，不返回部分读回成功。

## 6. 计划完整性和规范化

计划进入 `L1写集请求`，因此属于幂等完整语义并随写集规范化。规范化固定按：对象种类、身份引用种类（稳定编码先于本地键）、身份值、槽所属/类型排序；重复目标或同目标异义期望在写前拒绝。

计划必须精确覆盖本次变更：

1. 每个新节点、关系和值本地键各有且只有一个同种类当前期望；
2. 每个退出稳定编码各有且只有一个同种类 `本次发布退出` 期望；
3. 每个属性槽变更各有且只有一个槽期望，当前值必须等于该变更的新值本地键；
4. 允许增加必要的既有稳定编码中性互证项，但不得遗漏、重复或把一种事实按另一种类读取；
5. 全部本地引用必须能由本写集唯一解析，稳定引用必须在发布后当前或历史权威状态中唯一解析。

L1只比较中性字段。节点比较编码、种类、表示和生命周期；关系比较编码、三端点、角色和生命周期；值比较编码、所属、类型、材料、来源和生命周期；槽比较所属、类型和当前值。关系19/20、资格、单位、用途和领域值域不进入L1解释。

## 7. 首次提交算法

`L1事实基座仓库::提交` 固定为：

1. 规范化写集和读回计划，校验版本、非空、覆盖、幂等键和请求结构；
2. 取得唯一 `std::unique_lock<std::shared_mutex>`；隔离或已有状态不完整立即拒绝；
3. 已有幂等键：规范化请求全等才返回首次映射与首次通用读回，状态改为 `精确重复`；异义返回冲突；两者均不重放写集；
4. 校准期望事实代次，形成候选、分配映射、建立/退出三类事实和槽；
5. 在候选中形成新代次、首次成功结果、完整预期读回、幂等账和 `提交成功` 审计；
6. 在候选中为同幂等审计组预留一个失败事件容量，并在栈上预构造固定大小失败见证骨架；预留或预构造资源失败发生在 `swap` 前，返回资源失败且零发布；
7. `std::swap(状态_, 候选)`，至此事实和代次已经发布且禁止撤销；
8. 仍持同一独占锁，按权威 `状态_` 和映射重新形成实际读回；不调用公开读取函数、不递归加锁、不扫描猜测编码；
9. 实际读回与候选预期结果逐字段全等才返回成功；
10. 任一矛盾或交换后异常进入 §8，不能走普通异常返回遗漏隔离。

计划项目解析本地键只查本次 `新编码映射`；稳定编码直接定位当前三表或历史表。当前项必须没有退出代次且创建代次符合期望；退出项必须只在历史表中、退出代次等于本次发布代次。所有返回项目的发布事实代次统一等于本次新代次。

## 8. 失败见证、审计和隔离

定义：

```cpp
struct L1失败见证身份 final {
    写集幂等键 幂等键;
    std::uint64_t 审计事件序号 = 0;
};

enum class L1发布后读回失败原因 : std::uint8_t {
    映射缺失 = 1, 映射重复 = 2, 对象缺失 = 3,
    对象种类不符 = 4, 中性字段不符 = 5,
    生命周期不符 = 6, 发布代次不符 = 7,
    计划覆盖不符 = 8, 内部异常 = 9
};

struct L1发布后读回失败见证 final {
    L1失败见证身份 身份;
    std::uint64_t 发布事实代次 = 0;
    std::uint32_t 失败项目索引 = 0;
    L1通用读回对象种类 对象种类 = L1通用读回对象种类::节点;
    L1发布后读回失败原因 原因 = L1发布后读回失败原因::内部异常;
    std::uint64_t 计划证据摘要 = 0;
    std::uint64_t 实际证据摘要 = 0;
};
```

摘要只用于诊断和恢复互证，不能代替逐字段比较或幂等同义判断；编码采用冻结字段顺序、明确variant标签和U64模运算，不使用 `std::hash`、地址、容器顺序或平台字节布局。

`L1审计事件` 新增 `发布后读回失败隔离=9`；`L1审计记录` 增加可选完整失败见证。仓库状态增加失败见证有序组和可选当前隔离见证身份。失败路径必须按以下无失败窗口顺序执行：

```text
状态_.隔离 = true
-> 安装预构造的固定失败见证
-> 向已预留容量的审计组移动追加失败事件
-> 返回内部不一致、已发布代次、映射和见证身份
-> 释放独占锁
```

隔离标记先成立；见证和审计安装不得再分配内存或抛异常。若实现不能证明这三步在 `swap` 后无分配、无异常，施工必须停工，不能退化为“尽力记录”。

隔离后，普通提交和当前/历史/完整快照读取按结构化内部不一致拒绝。没有合法隔离修复候选时，恢复确认同样拒绝；只有按 §9 建立并互证完成的隔离修复候选可以进入既有恢复确认。审计读取是恢复证据入口，允许在隔离状态按幂等键返回完整有序审计与失败见证；不得返回普通事实副本。

## 9. 幂等、审计和恢复材料互证

`L1幂等账记录.首次结果` 保存首次预期成功结果、映射和完整通用读回。发布后失败不改写它；失败审计和当前隔离见证说明该结果尚未安全交付。隔离解除前同键同义、异义和其它普通写均不执行写集。

`L1恢复材料` 增加有序 `发布后读回失败见证组` 和可选 `当前隔离见证身份`。恢复校验必须证明：

- 每个失败见证身份非零、发布代次非零且不超过快照代次；
- 身份所指审计组存在恰一 `发布后读回失败隔离` 事件，完整见证逐字段相同；
- 该幂等账存在，首次结果的发布代次、映射和计划与见证一致；
- 所有失败审计均有恰一见证，所有见证均有恰一失败审计；
- 首次成功读回可由当前或历史事实按其原发布代次互证，后续退出不使首次结果失效。

未解除的恢复材料必须携带与失败见证组、审计完全一致的 `当前隔离见证身份`，进程重建时不得把它静默当成已开放材料。当前隔离实例允许调用既有 `建立恢复候选`，但普通写关闭；候选必须包含当前失败见证、完整幂等/审计证据和经过修复的全量三类事实。用于解除隔离的候选把该身份从“当前”移入永久失败见证历史，不能删除见证或审计；遗漏或篡改返回材料不完整。

`确认恢复候选` 是唯一解除隔离路径：只有上述候选存在时才可在隔离状态进入确认；它重新校准基线、原子替换并按现行恢复读回验证，成功后清除当前隔离身份但永久保留失败见证和审计历史。失败继续隔离。不得新增 `解除隔离`、`确认损坏` 或领域通知入口。带未解除身份的启动恢复材料只能重建隔离状态，不能开放普通入口。

本叶不接 SQL、不声称恢复材料已经生产持久化。它冻结进程重建所需的值式证据形状和互证规则；生产持久恢复装配仍属后继。

## 10. 现有调用点迁移规则

每个现有调用点从其已经形成的中性写集机械形成计划：

- 新节点/关系/值直接复制本地键和中性字段，创建代次取 `本次发布`；
- 退出事实使用写前已读取的真实对象种类和固定创建代次，当前性取 `本次发布退出`；
- 槽变更复制所属、属性类型和新当前值本地键；
- 必要既有端点、类型和来源可按固定创建代次加入，但不得把领域语义塞入计划；
- 发布成功后领域只把 L1 已返回的纯值项目机械映射为自己的 DTO，不再用普通快照证明原提交。

世界登记、场景、特征定义、实例特征、可重建索引夹具、运行期上下文夹具和P6比较登记的原业务幂等、写集和返回分类不变。P6文件只补计划字段，不修改其待实现比较合同。

## 11. 多线程与异常

整个首次提交、swap、权威读回、失败见证和隔离使用同一独占锁。并发提交不能插入 `swap` 与隔离之间；隔离单调保持到具名恢复确认成功。

精确重复不推进代次、不重建映射、不重新执行写集；返回首次通用读回。异义冲突不读取旧成功为本次成功。读回计划排序和比较不依赖容器迭代顺序。

所有可能分配的候选、预期结果、实际结果容量、审计容量和失败见证承载在swap前准备。swap后只允许无分配权威查找、逐字段比较、固定见证安装和预留审计移动。Debug故障注入只改变仓库私有测试分支，不产生生产损坏入口。

## 12. 错误矩阵

| 情形 | 结果与事实 |
| --- | --- |
| 合同版本1、版本2空计划、计划不覆盖或引用非法 | `入口拒绝`，零发布 |
| 期望代次漂移 | `事实代次漂移`，零发布 |
| 同键同义 | `精确重复`，原代次、原映射、原完整读回 |
| 同键异义（包括计划异义） | `幂等冲突`，零新发布 |
| swap前分配/候选/预期读回失败 | `资源失败`或结构化拒绝，零发布 |
| swap后任一读回矛盾 | `内部不一致`，保留新代次和映射，返回见证身份，立即隔离 |
| 隔离后的普通读写 | `内部不一致`，零后继写 |
| 隔离后的审计读取 | 允许返回该幂等键有序审计与失败见证 |
| 隔离恢复材料缺见证/审计/账互证 | `材料不完整`，保持隔离 |
| 具名恢复确认读回成功 | 新恢复代次发布，解除当前隔离，历史见证永久保留 |

## 13. 验证矩阵

扩展现有 `L1-SIMPLIFY-P0-S01`，至少覆盖：

1. 节点、关系、值、属性槽的当前读回，以及关系/值退出后的历史读回；
2. 同一计划混合本地键和既有稳定编码，完整结果顺序确定；
3. 计划版本、空计划、遗漏新项、遗漏退出/槽、重复、错种类、坏字段和坏代次均在swap前拒绝；
4. 精确重复返回首次代次、映射和完整读回；同键计划异义冲突；
5. Debug在swap后分别注入映射缺失/重复、对象缺失、错种类、错字段、错生命周期、错代次和内部异常；
6. 每种故障均证明已发布代次保留、永久编码不回收、当前隔离立即成立、失败见证和审计完整、后续普通写零执行；
7. 静态和运行时证明无第二业务写、无回滚、无删除、无补偿、无领域回调、无锁释放窗口；
8. 审计在隔离中仍可读；普通当前/历史/快照读和写均拒绝；
9. 恢复材料中首次映射、计划、首次读回、失败见证和审计逐项互证；缺/改任一项拒绝；
10. 只有既有恢复确认成功能解除隔离，失败或漂移继续隔离；
11. 全部现有新L1调用点均形成非空覆盖计划，源码中版本1成功写和空计划成功路径为零；
12. Debug/Release x64 Rebuild、两配置退出式完整自检、strict110/110、MSVC模块扫描、目标与cached diff check通过。
