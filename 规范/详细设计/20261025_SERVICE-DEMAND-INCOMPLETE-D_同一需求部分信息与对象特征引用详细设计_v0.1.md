## 3. 同一D的唯一结构

全部DTO追加到`领域/新_需求类.h`，实现归同cpp：

```cpp
enum class 新需求信息完善阶段 : std::int64_t { 待完善=1, 已完善=2 };
struct 新待完善被认知需求建立请求 {
    稳定编码 需求主体存在节点;
    新部分服务要求目标 已知目标; // 复用值式形状，不创建R
};
struct 新被认知需求信息更新请求 {
    稳定编码 需求节点;
    新需求治理信息 预期信息;
    新部分服务要求目标 已知目标; // 完整替换快照，不是缺省清空含义不明的patch
    std::optional<新需求认知来源> 认知来源;
};
struct 新被认知需求信息更新结果 {
    新需求操作状态 状态;
    std::optional<新需求治理信息> 信息;
};
```

`新需求治理信息`尾部追加`optional<新需求信息完善阶段> 信息完善阶段`及`optional<新部分服务要求目标> 已知目标`。这两项仅对被认知D有值，自我执行D保持原结构；不把活动状态的已满足当信息已完善。新被认知D持久保存阶段I64字段，目标各既有字段按已知情况保存实际typed引用/枚举，未知不存假0/空编码。

逻辑目标槽始终存在：`已知目标`这个固定值式结构中的每个optional代表该正式槽当前是否有准确内容，不代表槽是否定义。物理字段可缺省表示未知，不能用物理字段缺省推断概念内容项不存在；第7节明确本叶正式身份引用与旧完整概念符合性的边界，不提供新概念匹配能力。

`完整目标`继续是**从同D已知槽确定产生的完整投影**，不得另保存第二份目标：已知目标足以构成合法值/方向目标时才有值；缺项时无值。写口置为已完善时，必须核验完整目标、必要来源及确认当前有效共同成立，否则保持待完善；该阶段不承诺来源以后永久有效，后续消费者仍须按现正式入口fresh复核。结构getter不因此新增fresh C依赖。

部分写入必须逐项合法：已有目标E可独立存在，已有FT必须是正式FT；已有FC/RC须各自合法，在FT/相关目标都已知时必须相容；目标形式为值则方向不得有值，方向形式不得同时带FC/RC。形式未知可先有一个合法分支的已知字段，但两分支互斥载荷同时出现拒绝。未知不补默认形式，已知部分不因尚未齐备被清空。

## 4. 创建、更新与确认

新增public精确API：

```cpp
新需求建立结果 新_需求类::建立待完善被认知需求(
    const 新待完善被认知需求建立请求&) noexcept;
新被认知需求信息更新结果 新_需求类::更新被认知需求信息(
    const 新被认知需求信息更新请求&) noexcept;
```

创建明确是新身份，不按主体+空白内容、目标相同或当前F猜测去重。调用方拿到D后必须持原D复用，重复交接不能再调用创建。L1本接口无发布未知返回，不新增公共幂等账。若调用中断没有取得身份，先从本次已确认调用结果收敛，不扫描所有空白D挑一份“相同需求”。

创建条件：主体为真实合法存在，部分目标逐项合法，需求owner已初始化。一个L1组合追加发布D字段与既有被认知登记引用；阶段=待完善、域=被认知、主体固定、权重=0、活动=活动，无自我父链/列表项/任务来源，不制造U/C。成功返回同D并独立读回治理信息及完整已知槽。创建只证明D存在，不证明已进入对象F；第5节另返回F发布事实，不能合并谎称两步原子。

更新在需求业务锁内读取当前D，核域/主体及`预期信息`完整相等；主体不能变，D身份不能换。将请求作为已知目标的新完整快照核验，构造同D目标字段替换/追加/删除与阶段/当前认知来源的一个L1组合变化；以D及必要正式定义/来源的完整联合预期提交。竞争预期不符零变更，返回现`前提已变化`，不覆盖新信息；结构/资源错误走工程链，不当缺项。

新目标或任一关键字段变化后，不沿用旧U/C为新内容背书：若请求不附认知来源，清除D当前认知来源引用，阶段=待完善。原U/C/R节点保留，不删除、不改内容；它们的既有registry/其他引用不动。请求显式附来源时，目标必须已完整且其主体、独立目标、目标形式与全部载荷逐项同义，经现确认语义owner fresh核验后，才将当前认知来源写入同D并置已完善。显式来源与部分/新目标不符则认知来源不合法零写，显式来源失效则需重新确认零写；不能吞掉请求来源伪称已确认。调用方仍可明确以无来源请求保存新的部分目标，不要求确认reader装配才能保存无来源材料。

空/部分/完整但未确认都正式读回已知内容，不能只支持空→全。修改已完善D可合法回到待完善；旧执行消费者下一次fresh取得完整getter为空/来源需重核后必须等待，不拿旧内容继续执行。完整同义更新返回无变化，不新增D或F历史编码，不重复计数。

现`获取需求(D)`保持**结构完整投影**：新待完善阶段返回合法无完整信息，已完善阶段且结构完整才投影`新需求信息`；不在getter新增fresh C调用。确认是否当前有效继续由既有显式复核入口及使用该D的消费者负责，避免初始化/迁移时C reader未装配造成新耦合。写口只有对应来源当前有效才置已完善，改内容时原子清旧来源并回待完善，足以阻止旧内容继续投影；单纯查询不改阶段。不可把合法待完善当结构坏，也不可将工程读取失败吞成空。`读取需求治理信息(D)`返回所有合法阶段及部分字段；身份reader只判断正式D结构/主体/域/槽，不能以当前是否完整拒绝被F引用。

## 6. 查询与旧消费者安全

`新需求记录全集结果`保留原`vector<新需求信息> 需求组`，尾部追加`vector<新需求治理信息> 待完善需求组`；两组只是一份正式D全集的两种值式投影，不是第二账。结构完整且阶段已完善入完整组，待完善阶段被认知D入治理组，不重复、不遗漏；查询不增加fresh C依赖。现已完善D的确认失效由原显式复核路径处理，不因只读查询改组/改持久阶段。

同步：

- `查询全部需求()`自我树遍历保持；其全类型覆盖核验必须把合法待完善被认知登记也算入两域并集。认知来源唯一键只对真实有来源的D核对，不以零U合并空白D。
- `查询全部需求记录()`一次归并完整组与待完善组，不对每个被认知D强求完整getter成功。结构重复登记/坏字段仍工程故障。
- `查询主体需求(H,域)`同时过滤两组；`查询被认知需求来源(U)`在两组中只匹配实际当前认知来源，不把未知U当任意或让旧已解除来源继续命中。
- 全仓消费这些结果的代码必须显式仅取完整组做旧执行/服务采用；需要显示/筹办部分信息的消费者读取待完善组。相关材料来源、对象发布读取、全记录审计不得把“原完整组为空”解释为“该主体没有需求”，应检查两组。
- `复核当前满足/按完整目标查询/任务建立/服务要求采用`对未完善D明确返回现需求待完善/执行域不适用或合法未命中，不报工程损坏，不创建T。

新请求不触碰自我D/T；旧self同对象采用合同及其来源=目标守卫不改。manager通知/self新承接是后续路线。

## 7. 身份引用与完整概念符合分开，概念消费不在本叶

实码证明本叶F引用不调用旧D结构概念匹配：`新_特征类::准备顶层需求引用更新`进入准确值准备，`准确值与概念相容`对需求引用只委托`读取需求节点引用身份(D)`；`概念_特征类`同规则也核D身份和保护。它不以`概念_存在类`旧完整需求结构作为引用准入。因此本叶只扩展需求owner正式身份/槽形状及F引用，不需要改任何先天概念，也不新增槽概念API。

**旧先天完整需求根、值/方向及被认知子类定义、编码、字段、语义全部不改。** 空白/部分D不声称符合它，不用旧完整概念取得本能参数匹配资格；这不是绕过符合性，而是本叶尚不提供/调用这一能力。本叶的合法D身份由owner新阶段、部分槽typed形状、主体/域/根登记及全部引用闭合共同判定。

固定槽存在与值是否已知在治理DTO中分别表达：`已知目标`总存在于新被认知D治理投影，内部各optional未知不代表字段种类被删除，不使用假0/假目标。后继设计新E+D参数范围时，需独立正式待完善概念或明确共同范围，复用这些固定槽及允许未知的正式约束；旧完整概念只用于完整形状。不把此未实现的后继当作本叶的当前概念符合能力，也不提前登记后继计划。
