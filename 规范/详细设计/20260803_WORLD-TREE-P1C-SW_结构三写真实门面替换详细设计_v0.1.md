## 1. 选择与范围

三读真实委托依赖 P1C-QF、P1A3真实结构读取、FEATURE-Q 和 P1B-Q，当前链均未闭合；结构三写只依赖 P1C-F 最终门面和当前已可执行的 P1A3 v0.3 真实结构提供者，因此选择 P1C-SW 作为最早真实替换叶。

本叶不新建类、DTO、公开函数、模块、自检顶层身份或工程项。它只原位替换 P1C-F 的创建、移动、移除三个骨架函数体，并扩充同一 `WORLD-TREE-P1C-F-S01` 内部矩阵。其它六根保持骨架未实现。

正式依据：0050、4030、4200 v0.9、4201 v0.5；P1A3F v0.3 最终 ABI；P1A3 v0.3 真实提供者设计/计划；P1C-F v0.1 最终门面 ABI。旧 P1C 大设计、计划及旧六写图不作为直接依据。

未知枚举值一律 `内部不一致`。场景结果无论成功与否，门面都保留其 `发布代次` 与 `持久状态`；provider 状态为 `内部不一致` 时原样保留 `缺项组`，其它非成功清空缺项组，且所有非成功均清空目标、关系和操作读回。门面自己发现的矛盾没有合法缺项来源，缺项组固定为空。这样既不丢失 provider 的结构化诊断，也不会把发布后内部不一致伪装成事实未发生。

## 3. 创建存在并接纳

1. 构造 `形成节点直接实际存在规格请求{请求.幂等身份, 1}`，调用存在服务一次。
2. 非 `已形成` 按 §2 返回；场景调用数0。`已形成` 但 `规格` 为空返回内部不一致、代次0、持久不适用、空载荷。
3. 构造 `节点直接场景创建并接纳请求{请求.头, 请求.场景, *规格}`，调用场景服务一次。
4. 场景非成功按 §2 映射。
5. 成功/幂等必须同时满足：发布代次非零；provider 缺项组为空；读回存在且 variant 为 `世界树创建存在读回`；`读回.存在.当前场景归属` 有值且等于 `读回.场景归属`；归属源端等于请求场景、目标端等于新存在、类型为归属、`角色或顺序=0`。
6. 满足时返回原状态/代次/持久状态，`目标=读回.存在.存在`、旧关系空、新关系=场景归属、操作读回包装创建读回、缺项空。
7. 任一成功读回不变量失败返回内部不一致，保留原代次/持久状态，其它载荷全空。

门面不预判世界根、场景当前性或幂等语义；这些由两个具名 provider 负责，避免复制 P1A3。

## 4. 移动世界树成员

调用 `场景_.移动世界树成员(请求)` 恰一次。非成功按 §2 映射。成功/幂等必须满足：非零代次；provider 缺项组为空；读回 variant 为 `世界树移动读回`；读回成员等于请求成员；读回旧关系等于请求预期旧关系；新关系源端等于请求新父场景、目标端等于请求成员、`角色或顺序=0`；存在成员的新关系类型为归属，子场景为普通父子。

成功统一结果固定为目标=成员、旧/新关系取读回、操作读回包装移动读回、缺项空。失败后的内部不一致处理同 §3.7。门面不做无环、单父或世界归属判定。

## 5. 移除世界树存在

调用 `场景_.移除世界树存在(请求)` 恰一次。非成功按 §2 映射。成功/幂等必须满足：非零代次；provider 缺项组为空；读回 variant 为 `世界树移除读回`；读回存在等于请求存在；已失效归属等于请求预期归属关系；该关系源端等于请求预期场景、目标端等于请求存在、类型为归属、`角色或顺序=0`。

成功统一结果固定为目标=存在、旧关系=已失效归属、新关系空、操作读回包装移除读回、缺项空。门面不删除存在，不重读其它事实。

## 6. 诊断责任、异常与所有权

三个 provider 根均为 `noexcept`。门面不捕获后伪装成功。provider 已分类的入口拒绝、冲突、漂移、许可、资源、内部不一致或未实现只映射，不重复记录。

门面自己发现的三类防御性矛盾以分支标识追踪：`P1C-SW-E01=已形成无规格`、`P1C-SW-E02=成功状态但零代次/错variant/非空缺项组`、`P1C-SW-E03=成功专属读回字段矛盾`。这些标识只服务于设计、源码闭包和自检命名，不是日志码、机器状态或对外字段。门面统一结构化返回 `内部不一致`，不写日志；同一因果链的最终逻辑错误日志责任保留给 P1D 正式运行期请求入口。

`服务.世界树.ixx` 不得新增日志 include、日志模块依赖、包装器、宏或调用边。三个根分别内联状态映射和读回校验，不新增 module-private 或类私有辅助函数。一个坏形状同时满足 E02 与 E03 时先按 E02 收口；只有 E02 全部通过后才检查 E03。

请求和 provider 结果仅在同步调用栈存续；返回值由调用方拥有。门面不保存请求、规格或结果，不取得仓库、许可、事务、锁、SQL、缓存或快照。

## 7. 全根、字段、提供者与事务矩阵

| 根 | provider调用 | 事实写入 | 逻辑内返回 | 完成 |
| --- | --- | --- | --- | --- |
| 创建 | 存在1；仅已形成时场景1 | 门面0 | 规格非成功/场景非成功/读回矛盾 | 匹配创建读回 |
| 移动 | 场景1 | 门面0 | 场景非成功/读回矛盾 | 匹配移动读回 |
| 移除 | 场景1 | 门面0 | 场景非成功/读回矛盾 | 匹配移除读回 |

| 统一字段 | 来源 |
| --- | --- |
| 状态/代次/持久状态 | provider 原结果；门面新矛盾只改状态为内部不一致 |
| 目标/旧关系/新关系 | 入口匹配的 provider 专属读回 |
| 操作读回 | 专属读回原值包装为 `世界树写后事实` |
| 缺项组 | provider `内部不一致` 原样保留；其它 provider 非成功和门面自发现矛盾为空；不得编造缺项 |

事务成功、失败撤销、发布未知和原许可读回完全属于 P1A3。门面调用前后不另开事务；provider 返回后不再写机器事实。日志是人读诊断，不是机器事实。


规格/场景全部枚举映射以及 E01—E03 属于防御性闭包，其中 `未实现`、未知枚举和“成功但错variant/零代次/非空缺项/字段矛盾”等形状不能由合规 P1A3 真实入口主动形成。它们不伪造运行时覆盖，改由等价源码闭包逐分支证明：五个规格状态、九个场景状态和未知值均有唯一返回；成功分支按 E02 后 E03 顺序检查；坏形状返回内部不一致、保留 provider 代次/持久状态、清空全部业务载荷和缺项组；日志调用0。完成报告必须区分“真实入口运行覆盖”与“不可达防御分支源码闭包”，不得宣称全分支运行覆盖。
