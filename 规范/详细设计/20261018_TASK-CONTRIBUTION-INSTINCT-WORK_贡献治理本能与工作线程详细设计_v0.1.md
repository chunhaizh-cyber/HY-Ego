## 1. 对象、原因、目的与范围

本次改变来源任务及直接父任务Vt的服务值、来源任务状态，属于内部治理。目的是把既有Q计算、K冻结、R直属接收、普通子任务J4收尾纳入同一结算本能，并移出self消息循环。现实自我服务值的增加仍由已经发布的最终U消费链负责；两种动作、状态、动态和世界归属不混写。

复用唯一入口：

```cpp

新_本能函数集::执行服务值结算(const 方法参数场景&) noexcept;
```

不增加内部治理方法头、治理需求、任务、假L-X或第二贡献算法。普通方法头仍只表达现实自我服务值增加。纯治理调用不产生普通增值方法条件结果知识，不增加其真实运行/成功次数。

1. `来源`必须有同T的D/Vt/stateF/QF/C(T)，X/A等于`完成来源`。X/A为完成来源身份，不是为治理工作新增的执行实例。

## 4. 任务owner入口与同锁来源防护

新增`新_任务类`公开接口（头/源原文件）：

```cpp
新任务贡献治理参数读取结果 读取任务贡献治理参数(
    const 新任务贡献反馈定位&) const noexcept;
新任务贡献治理执行材料 执行任务贡献治理(
    const 新任务贡献治理参数&) noexcept;
void 核验任务贡献治理返回材料(
    const 新任务贡献治理返回材料&) const noexcept;
```

现有`推进任务完成贡献(稳定编码)`移为private helper，不保留self等外部调用。它仍唯一承载原计值/交接算法，不复制到runtime或本能函数。

`读取任务贡献治理参数`在既有任务互斥下取一致结构引用；核对原T当前X/A、状态9或12、A允许完成，允许已有K/R。既有正式T不存在/结构破损是工程错误；X/A被合法替换或状态不再完成/已结算是来源变化。结果为来源变化时参数为空，不创建动作。

`执行任务贡献治理`必须在**同一次任务owner锁区间**内执行以下步骤：

1. 重读原T/X/A及上述关系，和场景引用逐项核对。外层读取或方法构造的核验不能替代此处。合法引用集合变化则返回原定位+`预期已变化`，零新动作；不得从当前T取一个新的X继续执行。
2. 读取来源、已有直接父、已有直接子的当前特征组；保存源/父既有J阶段集合。允许当前数值不同于场景建立时，因为场景不冻结数值。
3. 调用私有既有推进算法；原子保护写集、Q/K/R/J4和预期不符分支不变。递归锁可复用，不新增跨owner长持锁。
4. 收集本次新增源/父阶段，核对种类、原T/X/A及目标归属，经既有治理世界reader取得完整动作/S/D；保留调用实际完成的部分。等待直接父等分支可能已经建立K/J1，不能把等待一概当零动作。
5. 只返回本次材料。精确重复返回正式K/R等进度，不复制旧动作；若旧R本次才合法补J4，则只报告新J4。

`核验任务贡献治理返回材料`只核验正式不可变身份与动作发生：原T/X/A、K/R若有则同源，J种类/目标/来源/S/D和场景一致，动作组唯一；不要求历史前值等于今天值，不把后来的合法推进误判为损坏。当前进度独立判断仍由manager现有交接reader负责。接口不补事实、不写世界树，损坏走现有日志/弹窗/终止链。

本能端口新增：

```cpp
virtual 新本能函数本次条件结果对 执行贡献治理场景(
    const 方法参数场景&) noexcept = 0;
```

统一本能执行顺序：取得用途对应端口→读取登记材料→函数内部确保自身正式Q头→核对场景M→用途4走治理分支，否则保留登记/普通/模拟原分支。治理不要求现实目标和服务任务集合实参；不能为通过校验伪造它们。确保头不等于创建内部方法头；运行时不启用第二代替代迁移。

治理返回`状态=已按合同返回`；有本次真实治理动作则`动作阶段=已按函数合同返回`，无动作则`未进入动作`；`结果取得状态=已取得`表示推进函数已返回正式进度，不表示完成任务或普通服务入账。等待/预期变化均由原推进状态表达；工程故障不成为业务样本。

## 7. runtime与模拟端口

`服务值结算本能运行服务`公开override上述工作入口和`执行贡献治理场景`。调用链固定：

```text
worker(T/X/A)
  → runtime读取task正式参数
  → method建立专用参数场景并调用已登记结算函数
  → 同一执行服务值结算确保正式头并选择治理分支
  → runtime复核同task reader、专用用途及M
  → task同锁复核原T/X/A并执行唯一贡献算法
  → 专用条件结果材料原样返回worker
```

外层读取已来源变化时，不伪造场景或实际执行：返回原T/X/A、推进`预期已变化`，条件参数为空、前值/动作空。内部owner复核才发现变化时亦零新动作；不得用新T/X/A替换工作原请求。

runtime不在跨方法调用期间持自己的消费串行锁，防同一本能回调端口自锁。K/R继续由task锁和已有原子保护负责；U仍用已发布最终消费逻辑。不新增全局/TLS业务参数，不直接绕过本能调用task推进。

## 8. 工作池、manager与self

### 8.1 公共工作合同

既有工作枚举追加`执行任务贡献治理 = 8`，处理状态末尾追加`任务贡献治理已返回`。请求增加`std::optional<新任务贡献反馈定位> 贡献来源`，结果增加`std::optional<新本能函数本次条件结果对> 贡献治理`。治理工作只带原T/X/A，T与请求任务一致，其它专属负载均空；不得携带假W3请求。

复用`绑定最终服务消费端口`已装配的同一确认接口，不新增工作线程或装配参数。worker只调用端口`执行贡献治理工作`，完成通知只唤醒manager；仍受总10槽、邮箱及同T排他约束。

### 8.2 必须持久到ACK结束的进程内相位

```text
已保留编号/待提交 → 已接收 → future已完成
  → 正式材料核验 → pool已ACK且精确活动项已移除
  → 贡献确认已完成 → 当前T/X/A映射释放
```

这只是工程记录，不是新的业务节点/持久化承诺。每阶段幂等；邮箱满/同T占用保留同编号，不能一轮一个编号。并发相同请求取得同原请求/future；同编号在self多个消息槽传播future，不能先完成的槽清理后另一槽误领新编号。

确认规则：

1. 必须先核原ID/请求/owner及ready future、专用返回身份和空普通字段，再调用task材料核验及已有交接正式读取。不信任worker返回的标量或状态替代事实。
2. 调用pool`确认结果已接收(ID,T)`成功后，移除manager**准确ID**的活动项并记录pool已ACK。其它同T活动项不得忽略。这个相位以前不得清理任务贡献缓存。
3. 复用贡献确认主体，提取private `确认任务贡献复核内部(const 新任务贡献反馈定位&, const 新任务贡献推进结果&, bool 停止收束) noexcept`。公开旧入口以false委托；治理ACK以对应停止状态委托。保留既有来源、K/R/J4读回及同轮缓存条件。
4. 读回漂移导致现有`资源失败`时，保留原future、原结果、当前映射和pool已ACK相位，只重做读取/确认；不得重跑本能、重领编号或再次占工作槽。相位未完成期间本T不得被新的治理/最终工作接管；普通调度也须把未完治理ACK视为同T技术占用，避免缓存清理和新筹办竞态。
5. 确认完成或定位已变化后释放当前T/X/A映射（成功也释放），保留ID记录供重复ACK。后续真实子贡献变化才可生成新的治理工作。等待条件沿既有待贡献复核/正式变化触发重投，不用自旋反复提交相同等待。
6. self确认已完成后重新读取K/R和直属分类，只有“最终消费保留/最终已收尾”等既有合法分支才进入已发布的`推进最终消费消息`；其它分支按原贡献处理结果结束/等待。不在本叶合并U工作。

### 8.3 self迁移点及消息保留

`处理贡献定位`统一替换同步推进，完成结果、贡献批次、已有K恢复三入口都走同一专属工作。self不做Q求和/交接，也不阻塞future.get；先`wait_for(0)`，ready才读。

消息项增加贡献工作缓存（原请求/future/专用返回/ACK相位）；沿用最终消费缓存防竞争原则。进入异步贡献阶段后，同源再次触发不能简单合并为旧消息“精确重复”而丢弃后继事件，按既有再次唤醒/待重投保留。锁内仅操作本对象技术状态，跨owner调用在锁外。

self停止返回结构追加`未收回贡献治理工作`、`未收回贡献治理结果`（类型分别为optional工作请求、shared_future工作结果），与现有最终消费句柄分开；不改写为已成功、已取消或空业务材料。

### 8.4 完成分派、解绑和停止

必须覆盖manager现有四处专属路径：`处理已完成工作`在“来源已替代”普通收回前分派；普通ready筛选排除；自我通知/解绑后的收束；`停止工作线程并收束`的join后专属drain。遗漏任何一处都可能把治理future误送普通W3。

停止前已开始的工作允许把已有原子动作收束并交真实future；尚未开始的工作由pool停止取消，不进行业务写入。manager保留端口至pool join和专属drain结束；self解绑不销毁已接纳请求或future。

`停止收束=true`只允许正式读回、pool ACK、精确活动移除和同轮技术缓存收口；不得因manager已停止直接返回“已停止接收”留下永久未ACK，也不得新派工作、触发普通条件筹办或创建最终U工作。已产生K/R保留；下一次正常启动按已有正式贡献批次读取继续。读回合法漂移保留中间相位并在drain安全重读，不重执行；不可恢复结构损坏按工程终止。重复ACK只读取保留记录，不再重复唤醒。
