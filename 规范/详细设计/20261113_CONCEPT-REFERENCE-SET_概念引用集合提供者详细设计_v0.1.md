## 2. 校验、业务计算与并发边界

- L1负责结构读写校验、引用有效性、原子发布、索引和删除安全；上层不重复审计L1已经承诺的结构正确性。
- 上层使用当前数据进行集合判等、包含、规范化、条件判断及目标判断。不得比较跨调用的整组旧快照来要求概念内容不变。
- 成员来自正式概念生产者。概念集合提供者不再逐个调用概念身份reader，不扫描概念树，不做反向身份证明；调用方传入错误语义对象属于程序逻辑问题，不能要求中性的L1理解概念意义。
- 材料类型分派及解码是计算所需操作；已有错误状态如实传播。不得把读取失败变为空集合、不匹配或普通业务否定。
- 真实节点引用保留；引用保持不等于概念定义冻结。引用集合身份不因成员概念内容更新而改变；消费者需要内容时从其owner读取当前内容。
- owner的既有互斥及L1原子事务保留，用于串行化同一对象的修改。不得以“实时变化”为由允许重复建立保护记录、丢失更新或半发布。

当前L1对既有字段替换/删除要求写宿主及相关旧、新引用目标的联合预期。适配现有API时，只在准备该次写入时读取API必需的当前材料，交L1执行检查，不在上层增加比较、跨次保存或写后互证。L1返回预期变化时，本次未提交，沿既有前提变化通道重新读取，不认定概念损坏；不可沿用原预期忙等重试。本叶不修改L1、不声称已取消其现有写入合同；纯新建保护记录无须提交成员联合预期。

## 3. 类型与集合语义

在概念_特征类.h追加：

```cpp
struct 特征概念概念集合值域 final {
    std::vector<稳定编码> 必含概念节点组;
    bool 至少一个概念 = false;
    friend bool operator==(const 特征概念概念集合值域&,
        const 特征概念概念集合值域&) = default;
};
```

追加到特征概念值域末尾（variant下标9）；比较规则追加概念集合身份判等=10，旧值和次序不变。物理载荷为新_特征值类的U64数组，无单位，聚合采用完整材料精确集合。按FT的明确规则分派，不能把任意U64数组猜成概念集合。

三类值域：

1. 全材料域：全部概念身份集合。
2. 有限域vector<稳定编码>：一组完整集合材料V形成的域，不是概念成员列表。
3. 新struct：必含成员及非空约束。必含为空且不要求非空时规范化为全域；必含非空时非空标志规范化为true。

成员是正式存在概念、特征概念（包括二次特征）或动态概念的稳定编码，正式根也可被引用。名称owner另行决定名称挂接目标。无成员reader装配前提，动态owner和普通应用装配无需改动。

排序去重只产生逻辑签名，不修改不可变材料V，也不要求const值服务生成标准化V。有限域按完整集合签名去重，同签名选最小V作为存储代表。F写入若命中历史同签名，复用该历史V并累加命中；首次保留输入V。单成员集合仍是集合。

准确空集合、没有当前值、非空约束三者不同。概念层级相似不等于成员身份相同；读取不得暗中改接成员。

## 5. 真实引用与发布

### 5.1 材料保护记录

沿用现有集合组织方式，增加私有“概念集合保护记录类型、材料来源字段、成员保护字段”。一条记录引用材料V及其去重成员，所有内容均为稳定编码引用字段，不把编码只存在数值数组里。

确保入口在既有特征概念树互斥（与存在特征共享）下完成查找及创建，全部创建者经过此入口，同一V至多一条记录。查询材料来源字段用于决定复用或建立；已有记录直接复用，不逐字段审计形状、不与V重新比较、不进行发布后读回互证。

新建保护记录直接调用L1原子追加节点组，请求只包含新保护节点及初始字段，不提交材料、成员、组织类型的旧快照。L1在写锁内检查字段键、V及成员引用是否存在，同时发布全部引用及索引。目标已删除则本次无发布、如实返回技术状态；引用先发布则后续删除由L1拒绝。其它既有封存链需要登记引用目标时，直接从待写引用填写只读预期.节点组中的基础节点编码清单，由L1检查当前存活；无需查询旧结构，不得用完整成员快照替代该清单。

保护记录及其引用随不可变材料使用期保留，不因F换当前值而释放历史、标准值、状态或有限域仍需要的引用。失败前已成功建立的保护记录仍是合法事实，可复用；不得谎称零写入，不删除输入材料。清理沿现有owner入口和L1入向引用规则，不绕过外部引用强删概念，不新增后台回收器。

### 5.2 条件域与定义更新

正向条件域的必含概念直接保存为定义的具名引用字段，随定义同次建立或更新，不另外保存概念身份快照。有限域每个完整V均经上述入口建立真实引用。移除条件引用使用既有L1字段修改合同，操作依据为本次当前读数，不保留上次业务判断时的概念快照。

### 5.3 F更新与实时变化

准备阶段按明确FT规则取得材料签名并确保真实引用；F仍使用既有占用和封存机制，实际写入与调用者附加片段共同发布。完成阶段按既有规则更新历史命中、标准值、聚合与概念同步，再结束占用。发布前失败沿技术状态返回；已发布后不得取消成未执行或伪造回滚。

同值真实再次写入按1130累加命中；同一个业务请求的重复处理由其业务流程决定是否需要写入。本叶不增加重复消费校验器。状态、动态及自我调整由后继持有者/治理处理，不在此伪造词条状态。

## 6. 比较算法

- 准确集合按规范化成员编码逐项判等；旧相似度返回相等10000、不等0，不对节点编码求方向差值。
- 准确集合满足条件域：必含组是当前集合子集，且非空条件满足。
- 强条件A蕴含弱条件B：B必含组包含于A必含组；B非空时A必含组非空或A明确非空。双向蕴含相等，单向包含，其余正向条件相交。
- 有限域之间按完整集合签名计算相等、包含、相交或分离。
- 有限域对条件域逐项求满足：全命中为条件域包含有限域、部分为相交、零为分离。不按当前已知概念数量推断条件域已被有限域穷尽。
- 全域与无约束条件同义；有限域不能没有候选，但其候选可为准确空集合。

比较不调用成员概念归属推理或身份reader，不产生“成员归属未知”。有限域比较需要FT上下文；仅物理材料类型无法确定该语义，不能让普通U64分支代替。
