## 1. 目标与边界

用户目标为继续完善控制面板。当前叶接入实际服务值、学习线程完整活动工作列表，以及当前任务调度材料引用的正式执行证据时间线。界面只读取和投影，不修改需求、任务、方法、学习、结算或世界事实，不启动任何本能方法。它不是本能函数，不涉及改变任何虚拟存在或现实存在特征值。

“任务执行证据时间线”只覆盖本轮正式任务调度材料中的执行实例所引用动作、实际状态，以及这些动作显式关联的结果动态与其状态。不称三世界完整业务历史，不扫描全场景或全部状态/动态，不从快照差异、日志或时间接近推造事件、完成和因果。

完整三世界历史浏览、全量方法目录、统一全系统最近业务推进时间留作未接入缺口；不得用局部记录最大时刻冒充全系统最近推进时间。

## 4. 学习只读合同（待实现）

在 `海中鱼巣/线程/新_学习线程类.h` 新增下列值式类型；定义仍在同名cpp，不新增文件：

```cpp
enum class 新学习工作快照读取状态 : std::uint8_t {
    已取得, 尚未建立, 资源失败, 内部错误
};
enum class 新学习工作种类 : std::uint8_t { 方法模拟, 问题材料 };
enum class 新学习工作阶段 : std::uint8_t { 排队中, 执行中, 完成待确认 };
struct 新学习工作快照项 final {
    新学习工作种类 种类;
    新学习工作阶段 阶段;
    稳定编码 方法节点;
    std::optional<稳定编码> 问题归档节点, 任务节点, 执行实例节点;
    std::optional<std::uint64_t> 排队序号;
};
struct 新学习工作快照 final {
    新学习工作快照读取状态 状态=新学习工作快照读取状态::内部错误;
    std::optional<新学习线程快照> 线程快照;
    std::vector<新学习工作快照项> 项组;
};
```

新增两个公开const入口：

```cpp
新学习工作快照 新_学习线程类::读取工作快照() const noexcept;
新学习工作快照 新_自我线程类::读取学习工作快照() const noexcept;
```

学习owner在一次现有互斥锁内复制线程状态与全部活动工作。排队项按FIFO实际位置从1开始赋排队序号；非排队项为null，不以方法编码顺序冒充排队顺序。输出确定顺序为FIFO项、执行中项、完成待确认项；后两组可按工作种类和正式身份排序，只作显示排序。

方法工作来自工作组；问题工作来自问题工作组且 `!已确认`，以归档节点去重。阶段以原位为准：未开始未完成为排队；已开始未完成为执行；已完成未确认为完成待确认。已确认问题缓存不输出且来源标签明确排除。当前 `待处理数量` 的旧含义不改变；另按新列表统计三阶段数量，不把旧计数改称排队数。

读取不调用服务、promise/future的get/wait/ready检查、通知或ACK；不得读取异常结果并把“完成待确认”说成学习成功。问题任务/执行/归档引用只从原问题消息复制，普通方法项这些字段为null。线程尚未启动但对象存在时，成功快照显示原未启动状态和实际空列表；self尚无学习线程返回尚未建立。实现缺失返回内部错误，bad_alloc返回资源失败，其它异常为内部错误；非已取得时 `线程快照=nullopt` 且项组清空，UI为暂不可用/读取失败，不作成功空队列。

### 4.1 锁与寿命

self转发持 `状态互斥` 保护学习unique_ptr并调用学习只读入口，锁序固定self状态互斥→学习互斥。学习只读入口不回调、不取self锁、不等待线程。启动创建已在self状态锁内，保持原行为。self析构在原工作回收及解除通知之后，以状态互斥把学习unique_ptr移入局部，释放锁再销毁局部、停止并join，禁止持self锁join造成完成通知反锁。不得改shared_ptr、借出裸指针或detach。公开对象本身不能与其析构并发调用，依然服从C++对象寿命；此处保护的是存活self内的线程成员。

## 5. 服务值与时间线投影（待实现）

### 5.1 服务值

在原 `普通控制投影::采集()` 中使用装配完成后不再更改的 `当前_.装配结果->自我->本能双根结果->服务实际特征节点`，固定经正式 `世界树.查询特征(F)` 读取当前准确值，不另增加候选读口。缺任一级则状态暂不可用并说明尚无正式身份；F不可读、无当前值、非I64分别明确说明，不填0。I64准确值完整保留负值，JSON十进制字符串。内容为 `status,feature,value,source`，feature使用实际引用；来源为自我实际服务特征。显示值只表示采集时的实际值，不证明结算正确。

### 5.2 执行证据闭包

只在任务调度材料成功时采集。对各 `T.执行`，提取X身份、任务身份、普通动作引用及实际状态引用；多个任务/执行引用同一证据按节点类型+身份去重，合并来源引用数组，不复制事实。

动作通过共享世界事实的动态服务按ID读取。原样展示动作时间、主体、定义、来源、目标以及显式动作结果关系。对动作显式结果组的每个结果动态按ID读取，其状态组通过状态服务读取；复合动态已返回汇总状态组，只保存成员引用，不递归查无关动态。实际状态也按原ID读取。每轮局部map缓存已读D/S，避免重复读取；缓存只活于本轮投影，不成为持久事实仓。

状态项显示S、被描述存在、来源实例F、FT、准确值和强时间；结果动态项显示种类、主题、状态组和成员引用，不从关系或状态值自行形成新动态。引用准确值只显示引用身份，非I64内容不另展开巨型材料。动作记录≠实际效果；关系为导致变化/观察取得，保持原类型，不改称“因果成立”。

时间排序只用正式实例绝对UTC纳秒。状态用其强时间，动作用动作时间，变化/复合动态保留端点最早/最晚时点并以最晚端点作显示排序键；明确它是区间而非单次完成事件。同一时点按种类/节点身份稳定排列，不暗示先后因果。缺时间或抽象时间不伪造UTC，项保留在“无可比较实际时刻”区域，且不能贡献最近证据时间。

任务材料成功、没有任何执行证据引用时，成功空数组合法。正式引用已给出但读不到内容时，本轮timeline区块为暂不可用、items:null、reason指出具体引用不可读；不能丢弃该项后声称完整。任务材料非成功，时间线跟随暂不可用。资源异常遵守首版采集失败/旧显示缓存合同，无业务写入。
