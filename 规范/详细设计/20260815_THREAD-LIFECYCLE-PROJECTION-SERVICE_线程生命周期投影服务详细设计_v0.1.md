# THREAD-LIFECYCLE-PROJECTION-SERVICE 线程生命周期投影服务详细设计 v0.1

日期：2026-08-15

状态：provider-only 已实现并完成施工验证；尚未装配或运行真实线程

## 1. 目标与边界

为 8110 的所有项目线程提供一个 BIZ 运行基础设施服务：接收纯线程生命周期消息，保存请求正文不可变的消息账，并按“运行代次 + 线程逻辑身份”形成当前只读投影。消息的 `当前/历史` 是服务端可更新投影元数据，不改变原发布请求。该服务不是 DATA-L1—L3，不写世界、概念、需求、任务、方法、动作、因果或价值事实。

本切片完成最多证明通用发布/读取 ABI、消息账和当前投影实现存在且通过本计划验证；不证明 SELF-THREAD、事件日志线程、缓存统计线程、持久证据线程、控制面板或程序启动链已经接线。

## 2. 正式依据与复用裁决

正式依据：0050、8100、8110 v0.2、CODE-FILE-01 v2.6。`SELF-THREAD-PRODUCTION-CREATE-AND-PARK v0.1` 只作为待接入消费者证据，不是本 provider 的实现前置。

当前 `运行消息协议` 属于普通运行消息传递，`有界运行消息队列` 没有 8110 的稳定消息身份、迟到语义和只读投影，不能复用为生命周期事实所有者。已删除的事件日志/缓存线程壳也不能承担通用服务。故新增唯一模块 `海中鱼巣.线程.投影.线程生命周期`；所有具体线程只作为发布者，不再各自声明生命周期 DTO 或端口。

## 3. 公开合同

### 3.1 身份与消息

- 投影主键：非零 `运行代次 + 线程逻辑身份`；系统线程 ID 只作可选诊断绑定，不参与主键。
- 消息稳定身份：投影主键 + 非零事件序号；同身份同完整请求为精确重复，同身份异请求为身份冲突。
- 线程类别和所属模块使用本模块唯一登记的强枚举；覆盖现行运行宿主、任务管理/工作、缓存、事件日志、外设、自我、持久证据和控制面板。同一投影主键首次接受后不可改变；普通运行消息角色若需对应必须显式映射，不得裸强转或另建生命周期类别表。
- 诊断引用类别只允许任务/工作项强枚举，引用身份非零；不得以任意整数充当类型。
- 发布请求携带：架构合同版本、事件模式版本、消息身份、类别、模块、可选系统线程 ID、当前/前一投影、非零诊断墙钟毫秒、原因键和可选诊断引用。当前顺序只由事件序号裁决，墙钟不参与排序。
- 架构合同版本与事件模式版本是两个独立版本域；当前都为 1，但分别由 `线程生命周期投影合同版本` 和 `线程生命周期事件模式版本` 表达与校验，不得因数值相同而共用常量。
- 服务端形成 `当前/历史` 当前性，发布者不得自报当前性。最近被接受的高序号消息为当前；较低序号只进入历史账。

系统线程 ID 首次出现后成为该投影的稳定诊断绑定。后续消息可以省略，当前投影仍保留；非空不同值拒绝为 `系统线程身份冲突`。这不把系统 ID 升级为线程主键。

### 3.2 发布结果

状态固定覆盖：已发布、精确重复、已接收迟到消息、请求拒绝、消息身份冲突、前一投影不一致、终态回退、系统线程身份冲突、非法状态转换、历史链冲突、运行代次不匹配、投影暂不可用、容量已满、资源失败和内部不一致。

结果不提供含混的 `成功()`。`已接受()` 只说明本消息已进入账或精确重复；`已成为当前()` 还要求本次消息当前性为当前且等于返回投影的当前消息。迟到消息和历史消息的精确重复只能“已接受”，不得被调用方解释为自身状态已经成为当前。

事件序号 1 只能是无前态的创建；其余事件必须携带合法前态且不能再次创建。固定转换矩阵覆盖创建、启动、运行、等待、暂停/恢复、停止、收尾、退出和故障收口。首个或后续被观察事件都可以因非阻塞发布失败而出现向前缺口：若新序号恰为 `当前序号 + 1`，其前态必须等于当前投影；若跨过缺口，则只先验证本消息自身的前态转换并把当前投影标为 `前置不完整`，不得用旧当前状态冒充缺失前态。迟到消息写入前同时核对已存在的相邻前驱/后继；矛盾链返回 `历史链冲突` 且零写。只有从 1 到当前序号连续且相邻前态全部互证时才清除不完整标志。

`已退出/异常退出` 为终态；更高序号运行消息也不得使其回退。若终态作为迟到消息到达而账内已经存在任何更高序号事件，则说明更高链跨越终态，必须返回 `历史链冲突` 且零写，不能因直接相邻消息尚缺失而暂时接受。`故障` 是不可丢失的历史事件，但可继续收尾并进入退出终态，不在本切片擅自升级为物理线程已退出。

### 3.3 读取结果

读取端口提供：

1. 按运行代次和逻辑身份读取单一当前投影；
2. 按运行代次枚举完整当前投影组。

空组是成功的已读取空值，不等于资源失败。读取只返回值式副本，不暴露锁内引用、可写容器或消息账修改入口。当前投影携带当前消息、稳定系统线程绑定、是否已见创建、前置是否不完整和是否已进入终态。

## 5. 事务与并发

一个服务实例只拥有一个非零运行代次，配置同时给出最大线程数和最大消息数，且不得超过项目固定上限；随普通应用运行上下文析构整体释放，不提供普通业务清理写入口。服务内只有一把 mutex，保护有界消息账和当前投影账。发布/读取均使用 `try_lock`；竞争时立即返回 `投影暂不可用`，生命周期上报不得等待锁。取得锁后的遍历和复制均受配置上限约束。

发布固定顺序：

```text
锁外校验配置、请求、运行代次和局部状态转换
-> 单锁内查消息身份与当前投影
-> 精确重复/冲突零写返回
-> 容量已满零写返回
-> 迟到消息先互证相邻历史，再以历史当前性写消息账
-> 高序号消息先验证类别、模块、系统ID、终态和前一投影
-> 预构造完整新消息
-> 写入消息账
-> 原当前消息改为历史
-> 无抛出替换当前投影
-> 返回值式结果
```

首次投影先写消息账，再建立当前投影；第二步分配失败必须删除第一步，恢复零变化。既有投影更新在任何可能分配之前不修改旧值；新消息插入成功后只执行无分配的当前性和固定值对象替换。所有返回副本均不包含动态字符串。锁内禁止日志、回调、文件、数据库、DATA 或其它服务调用。

发布接口 `noexcept`：分配失败映射资源失败，其它异常映射内部不一致。读取分配失败同样结构化返回；任何失败都不泄漏可写内部引用。

## 6. 消费者边界与 SELF-THREAD 阻断

具体线程只能 import 本模块并消费通用 DTO、发布端口和读取端口，不得声明第二套逻辑身份、生命周期枚举、请求、结果或端口。具体线程自行形成严格递增事件序号、系统时钟毫秒、类别、模块和真实物理前态；端口竞争失败只留下可解释序号缺口，不得让 provider 返回值反向改写线程物理前态。真实系统线程 ID 由具体线程后继接线验证，本服务不从 `std::thread::id` 哈希伪造操作系统线程 ID。

SELF-THREAD 当前已有未登记候选改用本通用 ABI，但其失败候选安全回收后的同运行代次重试语义尚未冻结：事件序号不得清零、创建只能是序号 1、终态不可回退，与候选源码允许再次创建互相冲突。该问题固定为 `DRIFT-SELF-THREAD-FAILED-CANDIDATE-RETRY-LIFECYCLE-SEMANTICS-UNDEFINED`。在 SELF 详细设计形成新版本裁决前，本 provider-only 切片不得修改、登记、编译、提交或宣称完成 SELF-THREAD；provider 发布也不解除 SELF-FORM、装配、阶段 20 或真实线程接线门禁。

## 7. 函数与诊断责任

| 函数 | 可见性 | 责任 | 诊断责任 |
| --- | --- | --- | --- |
| `线程生命周期投影服务::发布` | 导出公开成员 / 发布端口 | 原子接收消息并更新账 | 向上送出结构化状态 |
| `读取当前线程投影` | 导出公开 const 成员 / 读取端口 | 返回单一值式投影 | 向上送出结构化状态 |
| `读取当前线程投影组` | 导出公开 const 成员 / 读取端口 | 返回运行代次完整投影组 | 向上送出结构化状态 |
| 请求、键、终态与投影形成辅助 | 模块内部纯函数 | 校验和机械转换 | 无适用错误分支 |

本服务不写日志。未来装配/入口才是生命周期基础设施不可构造或业务阶段失败的最终诊断责任边界；合法拒绝和投影缺失不逐层重复记录。

## 8. 验证矩阵与完成边界

- 零版本/身份/序号/时间/类别/模块、坏系统 ID、坏诊断引用拒绝且零写；
- 首次创建、无创建先到、迟到创建、正常高序号更新；
- 精确重复、同消息身份异内容、类别/模块冲突、系统 ID 首次绑定/省略保留/冲突拒绝；
- 序号1非创建、二次创建、非法转换、前一投影缺失或不一致、终态回退拒绝；
- 当前消息历史化、迟到消息相邻链互证、缺口保持不完整、完整补齐、迟到消息不覆盖当前；
- `已接受/已成为当前` 分账，历史精确重复不得冒充当前；
- 单运行代次、错代、有界线程/消息容量、服务析构释放；
- 发布/读取锁竞争立即暂不可用，并发同身份只产生一个当前值，锁内零外部调用；
- 首次双账第二步失败回滚与既有更新异常安全；
- 根工程 x64 Debug/Release、专项双配置、UTF-8/XML、strict、工程唯一登记和生产零验证痕迹。

provider 公开边界的生产外专项 Debug / Release 均为 `19/19 PASS`，覆盖版本分域、前向缺口与迟到补齐、迟到终态、终态回退、幂等、系统线程绑定、容量、读取和并发同身份收敛；清理后根工程 Debug / Release x64 Rebuild、strict `113/113`、UTF-8 / XML 和精确 diff 检查通过。临时专项已移出仓库，生产工程零验证代码。

无法从公开边界确定性触发的分配失败和持续锁竞争保持 `NOT_RUN`，未为验证增加生产 seam。真实具体线程发布、普通应用装配、控制面板消费和完整运行联调同样保持 `NOT_RUN`，不得据此宣称 8110 全链完成。
