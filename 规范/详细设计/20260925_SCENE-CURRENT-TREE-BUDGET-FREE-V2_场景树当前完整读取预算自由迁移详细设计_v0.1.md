# SCENE-CURRENT-TREE-BUDGET-FREE-V2 场景树当前完整读取预算自由迁移详细设计

版本：v0.1

日期：2026-09-25

状态：创建侧设计冻结候选

对应目标：`GOAL-SELF-GOVERNANCE-CLOSURE`

事实基线：`b474e24df44ddecad2c2c68c5edc6b6c06bd627b`

## 1. 目标与边界

本设计闭合 fresh self 正式上下文前置链的紧邻下一叶：给定事实代次和具名世界树根场景，完整读取该根沿联合直接归属结构可达的全部当前场景角色，不使用节点、关系、场景、深度或步骤数量预算，不返回被截断的成功结果。

本叶只负责场景 owner 的当前树读取合同及其为完成整树读取必需的预算自由场景角色位置、完整角色和父语境读取。它不迁移场景写入口、世界树根读取、真实自我读取、自我线程正式上下文、task owner 恢复、自我线程消费、manager 交接或治理门开放。

本叶不修改正式规范或 L1，不改变旧版本1 ABI；版本1入口只保留迁移识别，版本2实现禁止转调版本1入口，也禁止用极大数量模拟无预算。

## 2. 正式依据与当前事实

### 2.1 正式依据

1. 0050 第3.2节：上层定义完整语义范围；下层资源计数不得成为成功上限或截断依据；无法完整完成时返回资源失败；旧预算字段和分支降为迁移识别。
2. 1150、4202：世界树从场景根沿联合直接归属结构递归；同一对象的存在/场景视角共享稳定节点；没有场景角色的结构中间节点不能截断后代遍历。
3. 4204：世界根无父语境；非根当前场景角色恰有一条父场景语境投影；同一截止先读唯一结构父，再读父语境，两者不匹配为内部不一致。
4. 已发布 `DIRECT-OWNERSHIP-UNION-BUDGET-FREE-V2` 详细设计及提交 `b474e24d`：联合父、联合子组、场景包含父组/子组和存在组成父/子组的六个预算自由版本2入口已经形成。

### 2.2 当前代码事实

1. `场景类数据服务::读取当前场景树`仍是版本1；请求带`最大场景数量/最大关系数量`，实现及成功谓词以1..4096和关系计数裁剪成功。
2. 旧树读取仍调用版本1`读取当前场景角色位置`、`读角色`、`读取当前父场景语境`、`读取当前场景包含子组`和联合父/子组。
3. `读角色`含多处4096硬限制；直接删除判断仍会保留旧查询链，不能取得预算自由生产资格。
4. 已有`读取节点全部当前引用_v2`和`尝试读取所有者范围一致当前投影`可在已知节点、已知owner和已知关系类型下形成预算自由当前投影；`读取存在身份来源历史见证(G0,G0,E)`没有执行数量预算。
5. 旧`场景树节点当前事实/场景树当前事实`不含预算字段，已经承载完整角色、树证明、直接父、两类直接包含、上游路径和父语境投影，可以复用；旧请求、结果头和成功谓词不能复用。

## 3. 完整业务范围

请求的完整范围固定为：从`根场景`开始，沿同一`G0`下联合直接子组递归可达的全部结构节点；其中每一个具有当前活动场景角色且属于该根场景树的节点形成一个`场景树节点当前事实`。没有活动场景角色的结构节点不进入`场景组`，但必须继续沿其联合直接子组下钻。

成功结果必须同时满足：

- 根场景是当前活动场景树根且联合直接父为空；
- 每个可达结构节点只由一条路径到达，结构无环、无多父、无重复关系；
- 每个返回场景角色完整、四根齐全、树证明有效；
- 非根场景角色的父语境投影与本次联合直接父逐字段一致；
- 每个返回场景的直接存在成员组和直接子场景组完整；
- 从最近上游场景到本场景的联合路径连续、完整；
- 场景组按场景稳定编码严格升序，且恰含一个请求根。

任何失败均不返回部分树。

版本2成功谓词复用旧事实DTO的结构含义，但必须独立实现。它保留严格排序、唯一根、树证明、路径连续、父语境、直接成员/子场景和权威关系唯一核验，删除全部预算条件。

关系重复规则按事实角色冻结：

1. 只有父侧`读取当前联合子组_v2`枚举出的结构边首次登记进唯一`权威结构边表`，同一编码只能对应一个逐字段完整事实。子侧`读取当前联合父_v2`是该边的必需复核投影：编码相同且逐字段相等时成功，不二次登记。只有另一个父侧子组、另一个待查父或其它遍历位置把同一编码当作另一条权威遍历边，或者同一编码携带不同事实，才返回`引用冲突`。
2. `直接父`、`从上游场景到本场景路径`、直接存在成员/直接子场景组中的关系，以及父语境内嵌`结构父`是权威结构边的合法投影。同一编码可在这些DTO位置重复出现，但必须与权威结构边逐字段一致，且其出现位置必须符合父、成员和路径语义。
3. 树证明边在全部返回场景节点中编码唯一；父语境投影边在全部非根场景节点中编码唯一。二者彼此不得复用编码，也不得与权威结构边复用编码。
4. 任一相同编码携带不同事实、任一树证明/投影边重复或任一非允许位置复用，成功谓词失败；不得把合法DTO投影重复误判为第二条关系事实。

### 5.1 当前完整角色形成

1. 调用`读取存在身份来源历史见证(G0,G0,C)`形成对象存在来源；不存在、已退出、漂移、资源失败按第7节映射。
2. 调用`读取节点全部当前引用_v2(C,G0)`取得C的全部当前引用；只选择场景族登记边和根绑定边。合法反向边及C仅作为关系类型节点的引用忽略；被选方向事实才核验owner、角色、生命周期和端点。
3. 登记边与根绑定边同时为空返回`场景角色未启用`。登记边恰一且四条当前根绑定按角色1..4各恰一时进入活动角色形成；缺失、重复、错向、错owner、错类型、错生命周期均为`内部不一致`。
4. 登记边仍当前有效但当前根绑定为空时，使用预算自由`读取所有者范围历史完整关系组`，以`期望读取事实代次=G0、历史截止事实代次=登记创建代次`读取当时四条根绑定；再逐项以已知编码单事实历史读取取得四根和四边的实际生命周期。只有历史组严格为角色1..4各一、四根/四边与登记共同出生、且八项在同一非零代次退出并不晚于G0，才返回`目标已退出`。历史完整组或任一已知事实返回`历史材料已清理`时原样上送；登记边存在而仅部分根绑定当前有效、历史组不是严格四项、部分退出或退出代次不一致均为`内部不一致`，不得伪装合法退出。
5. 收集登记边、四条根绑定边、四个根节点和三个布局元节点的已知编码，调用一次`尝试读取所有者范围一致当前投影`在`G0`核验全部场景owner事实。不得逐项回退历史版本1组读取形成当前活动成功。
6. 核验登记边创建代次与四根/四绑定共同出生，根节点身份互异且不等于C或三个元节点；每个根绑定目标的根节点全部当前引用中，该根绑定是该关系类型的唯一合法入边。
7. 形成`场景角色历史事实{G0,G0,...}`并调用既有`场景角色历史结果::成功({2,G0,G0,C})`作最后后置校验。

### 5.2 场景角色位置

1. 先以预算自由`确认当前存在结构身份(G0,E)`确认对象存在。
2. 以`读当前完整角色_v2`判断场景角色；先保留“当前活动角色”“从未启用”“内部八项已完整证明合法退出”三种分支，不在此处提前返回。历史材料已清理、结构残缺或部分退出必须上送对应非成功，不能伪装未启用。
3. 无论上一步是哪一种分支，都调用一次`读取节点全部当前引用_v2(E,G0)`，选择根标记、树归属证明和父场景语境三类当前出边；任一错owner/角色/端点/生命周期均为`内部不一致`。
4. 从未启用或内部八项已合法退出时，三类当前边必须全部为空，才转换为`已读取 + 角色=nullopt`；任一根标记、树归属或父场景语境仍当前有效，都是部分退出或残缺结构，返回`内部不一致`。
5. 当前活动角色时，根标记和树归属两类不能同时存在且各自至多一条。无证明边形成`未纳入场景树`；根标记形成`场景树根`且树根=E；树归属形成`场景树非根`且树根=证明边目标。父语境边在位置v2中只核验当前边形状和基数：根不得有父语境；未纳入不得有父语境；非根必须恰一，精确目标与联合结构父一致性继续由树入口第5.3节核验。
6. 返回前调用v2成功谓词；非成功清空角色。

状态映射固定为：存在身份`未找到/目标已退出/事实代次漂移/资源失败`分别映射位置v2同名状态；完整角色`场景角色未启用/目标已退出`映射`已读取 + nullopt`；`历史材料已清理/事实代次漂移/资源失败`分别映射位置v2同名状态；其余非成功统一`内部不一致`。任何L1当前引用的`未找到/已退出`若发生在存在身份已经成功之后，统一为`内部不一致`。

### 5.3 父语境

1. 该helper只接受树遍历已经由联合父v2成功读回的非根`已核验结构父`，不在内部重新创建组合器或调用联合v1。
2. 调用`读取节点全部当前引用_v2(C,G0)`，只选择`C -> 父场景语境`的场景owner出边；必须恰一。
3. 投影边目标必须等于`已核验结构父.父`；形成的`结构父`必须与传入事实逐字段相等：`Gread/H/来源/关系/父/成员/创建事实代次/退出事实代次`全部一致。
4. 根场景不调用此helper，并必须不存在当前父语境投影；发现根投影为`内部不一致`。

父语境私有结果只使用`场景角色数据状态`中的`已读取/入口拒绝/未找到/事实代次漂移/资源失败/内部不一致`：参数无效=`入口拒绝`；L1当前引用漂移/资源失败分别同名映射；已由活动场景角色和联合父证明的C在L1读取中未找到或已退出=`内部不一致`；合法读取但投影边为空=`未找到`；多边或任一形状/逐字段不匹配=`内部不一致`。树入口对非根的`未找到`再收口为树`内部不一致`，不会把缺父语境当成正常空投影。

### 5.4 树证明

1. helper只接受角色位置v2已经成功返回的非空角色，并用其`树证明关系`作为唯一已知编码调用`读取所有者范围历史事实`；该单事实读取不带执行数量预算。
2. 读取事实代次必须等于G0，事实必须当前有效且为关系。未找到、已退出、类型错误、错owner/角色/源/目标/关系类型均为`内部不一致`；事实代次漂移、历史材料已清理和资源失败分别原样映射。
3. 根角色要求证明为`场景树证明种类::根标记`、源为场景、目标为树登记锚点、树根为场景；非根要求证明为`树归属`、源为场景、目标为请求树根。
4. 形成`场景树证明事实{G0,G0,...}`并由私有成功谓词完整后置校验；非成功清空证明。

## 6. 整树算法

1. 校验版本2、G0、根编码和联合provider绑定；失败返回`入口拒绝`。
2. 以场景角色位置v2读取根：存在未找到=`根未找到`，存在已退出=`根已退出`，当前存在但无活动根角色、角色不是根或树根不等于请求根=`根角色未启用`；布局已出现但残缺=`内部不一致`。
3. 用`读取当前联合父_v2`核验根无直接父；再以根的`读取节点全部当前引用_v2`明确筛查父场景语境关系。根父非空或根存在任一当前父语境投影=`内部不一致`。
4. 广度遍历联合结构。待查项固定含`节点E + optional<直接父> + 从最近上游场景到E的结构边路径 + 从请求根到E的完整祖先节点链`。完整祖先链不因遇到场景角色而重置；最近上游场景路径按场景DTO语义重置。每个非根节点先用联合父v2重新读回并要求与待查直接父逐字段相等；不相等=`引用冲突`。
5. 维护全局已完成/已入队节点集合及权威结构边表。加入子节点前，若子节点已在本待查项完整祖先链中（含回到请求根）则`形成场景环`；否则若已入队或已完成则`引用冲突`。联合子读取的每条关系先加入权威结构边表；同编码再次作为另一条遍历边出现、相同端点出现不同关系或同一成员出现不同父均为`引用冲突`。
6. 对每个结构节点调用场景角色位置v2。由同G0联合边召回后又返回未找到/已退出=`内部不一致`；历史材料已清理、漂移和资源失败分别映射树同名状态。无场景角色时不产出场景节点，但继续读取联合子组。
7. 有场景角色时要求树根等于请求根且位置不是未纳入；否则`引用冲突`。调用私有完整角色helper和`读当前场景树证明_v2`形成完整角色及`场景树证明事实`。
8. 非根调用父语境helper；根明确核验无父语境。调用`读取当前场景包含子组_v2`，按种类分入直接存在成员组/直接子场景组。
9. 以`读取当前联合子组_v2`取得全部直接子。若当前节点有场景角色，则每个子路径从该场景重新开始；否则延续上一个场景到当前结构节点的路径。
10. 全部完成后按场景编码严格升序，调用v2成功谓词。成功返回完整树；任何失败清空树。
