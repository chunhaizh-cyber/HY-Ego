# L1-SIMPLIFY-P12-PRESTATE I64 相邻前状态选择详细设计 v0.1

日期：2026-08-05

状态：设计就绪；代码未实现；计划必须待激活

## 1. 目标与完成边界

本设计只完成 SELF-GOV-CLOSURE STEP-3F-PRESTATE：在发布实际存在某个 I64 实例特征的后继状态之前，由状态领域根据主体、实例槽和拟发布后状态业务发生时间，选择严格更早且时间最大的唯一相邻前状态，并经 P9 v0.3 同一公开读取入口返回完整不可变前状态快照。

真实成功行为只有两种：

1. `无前状态`：候选集合为空；这是合法读取结果，不是未实现、未找到或错误；
2. `已选择`：返回一个完整 P9 v0.3 状态快照及可复核选择证据。

本叶只读，不登记比较、不发布状态、关系20、动态、动作、因果或结算。它不修改 P9 v0.3 的不可变状态读取语义，也不决定后继应走首态还是第二状态写入；3F 后继写入口若意图发布第二状态，收到 `无前状态` 必须结构化拒绝，不得回落到首态入口。

## 2. 正式依据与能力裁决

- 4190 §6 要求当前状态由主体、特征、时间、事实截止和版本明确选择，不得依赖缓存顺序。
- 4200 §5.2 冻结状态排序为场景、主体、特征、发生时间、状态稳定编码；§7.8 禁止业务调用方提供前状态；§7.9 固定无前状态、前后等价和存在差异三分支。
- 4210 §2 要求新状态入账后按同一主体、同一实例特征查找相邻前状态；不同主体或特征不能直接组成迁移动能。
- 4015 的 `L1完整快照` 在一个非零事实代次返回全部当前节点、关系和值；关系端点后来退出不自动使关系退出。它足以作为本叶单轮候选枚举的权威观察。
- P9 v0.3 已冻结关系19角色1主体、角色2采样场景、角色3 P8实例槽及按状态自身身份读取完整当前/历史快照的公开合同，但明确不选择当前或相邻状态。
- 当前能力目录只登记旧 `状态服务.h` 句柄/对象版本能力；旧 `服务.状态.ixx`、旧状态动态组合和 WORLD-TREE 计划均不使用新 L1 稳定编码关系19，不能复用、包装或迁移。

裁决：原位扩展待实现的 `海中鱼巣.领域.服务.L1状态`。候选枚举使用一次 L1 完整快照；只解析选择所需的关系19角色、状态资格和发生时间编码，不复制 P9 对历史端点、被采样值、属性类型、来源和生命周期的完整解释。选定身份后调用 P9 v0.3 `读取实际存在I64基准状态`，并以相同读取截止互证；漂移时整轮重试一次。

本入口不增加世界根字段。P9 状态事实没有可由状态领域独立互证的世界根见证，且稳定编码全局唯一；添加世界根只会形成请求回显。世界范围、后状态当前场景和跨场景迁移合法性仍由后继世界/状态发布入口结合 P7/P10/P11 校准。本入口不得调用 P7 当前场景隐藏候选。

## 5. 候选集合与确定排序

单轮算法固定如下：

1. 校验合同、规则、选择规则、业务查询身份、主体、实例槽和拟发布时间均非零；非法返回 `入口拒绝`。
2. 调用 `读取完整快照` 取得 `G0`。快照失败按 §8 映射；主体或实例槽不在当前节点组返回 `未找到`。本入口服务于拟发布后状态，因此输入主体和实例槽必须当前可解析。
3. 按登记中的关系19类型分组当前关系。每个源状态必须满足角色1—5恰一、源一致、角色编号有效；角色1目标等于请求主体且角色3目标等于请求实例槽的组进入本查询范围。
4. 对查询范围内每个状态，从状态节点当前属性槽取得登记中的状态资格值和发生时间值；两槽必须唯一。资格必须为 I64 `1`；发生时间必须为单项非零 U64 组。这里只读取候选身份、角色与排序时间，不解释采样值、P2定义、来源或历史端点。
5. 只保留 `候选发生时间 < 拟发布后状态发生时间`。等于或晚于拟发布时间的状态不是前状态候选。
6. 若同一主体、实例槽和同一发生时间对应两个不同状态，返回 `冲突`；关系19残缺、重复角色、错误类型/端点、重复状态资格或发生时间槽、状态身份与关系源矛盾返回 `内部不一致`，不得忽略坏项或选择容器首项。
7. 候选为空返回 `无前状态`；否则选取发生时间最大的唯一状态。稳定编码只用于验证结果与稳定枚举，不用于打破同时间冲突。
8. 从快照中的状态、见证节点、五关系及五状态域值编码构造 P9 v0.3 `实际存在I64基准状态读取请求`，调用同一公开读取入口。不得让调用方提供这些编码。
9. P9 必须返回成功且完整快照的主体、角色3实例槽、状态身份、发生时间分别等于选择结果，`读取事实截止代次 == G0.事实代次`。否则按 P9 状态映射为非成功；成功载荷矛盾返回 `内部不一致`。
10. 再次读取 L1 完整快照取得 `G1`。只有 `G0.事实代次 == P9.读取事实截止代次 == G1.事实代次` 才可发布结果。代次变化时丢弃整轮材料并完整重试一次；仍变化返回 `版本漂移`。

候选组排序键固定为：

```text
(发生时间升序, 状态稳定编码升序)
```

该排序只保证确定遍历和验证；相邻前状态由严格最大发生时间决定，同时间不同状态永远是冲突。

## 6. 当前、历史、场景与生命周期

- 选择依据是关系19冻结的主体、实例槽和发生时间，不读取 P7 当前场景。
- P7 后来移动场景时，前状态仍保留采样时角色2；选择器照常返回。P11 或后继发布入口再判断前状态采样场景与后状态当前场景是否允许直接迁移。
- 主体、场景、实例槽或被采样值后来退出，不自动删除关系19或历史状态，也不使候选消失；P9 v0.3 负责从当前/历史入口互证完整状态。
- 本阶段已发布状态节点、关系19及状态域选择键必须继续作为当前可枚举事实存在。若未来清理规则真实退出这些选择键，却仍要求无身份枚举历史状态，必须先建立可由权威状态事实确定重建的状态目录；不得扫描审计、SQL、日志或缓存补造。
- `读取事实截止代次` 只是本次稳定选择的技术边界，不是业务发生时间。调用方不得传入或锁定它。

## 7. 并发与线程安全

函数为 `const`，不修改服务登记、幂等账、缓存或 L1。并发调用只持有实现所需的状态服务只读同步边界；不得跨 P9 调用持有 L1 许可或仓库锁。

每轮以 `G0 -> 候选解析 -> P9读取 -> G1` 构成稳定观察。并发发布新状态、状态清理或其它 L1 写入使代次变化时，整轮丢弃并至多重试一次；不得返回旧候选与新 P9 快照拼接的混代结果。资源分配失败返回 `资源失败`，不改变任何事实。

## 8. 状态映射

| 情形 | 结果 |
| --- | --- |
| 合同/规则/查询身份/主体/实例槽/拟发布时间非法 | `入口拒绝` |
| 主体或实例槽在起始当前快照不可解析 | `未找到` |
| 合法范围内没有严格更早状态 | `无前状态` + 空前状态 + 完整零前态证据 |
| 唯一最大时间状态且 P9 完整读回 | `已选择` + 完整前状态 + 选择证据 |
| 同一主体+实例槽+同一时间多个状态 | `冲突` |
| L1/P9 许可竞争 | `许可拒绝` |
| 首末/P9 截止不一致且重试后仍漂移 | `版本漂移` |
| L1/P9 资源失败或分配失败 | `资源失败` |
| 关系19、属性槽、时间、身份或成功载荷矛盾 | `内部不一致` |

`未找到` 不得降级成 `无前状态`；`无前状态` 只在主体和实例槽合法且候选集合确实为空时成立。未知状态一律映射 `内部不一致`，不形成第三种空成功。

## 9. 验证矩阵

专项顺序在 P9 顺序360后原位新增顺序370，至少覆盖：

1. 合法零状态返回 `无前状态`、非零截止和零前态证据；
2. 一项严格更早状态被选择并通过 P9 返回完整不可变快照；
3. 多项乱序插入时选择最大合法发生时间，不依赖容器顺序或稳定编码大小；
4. 等于和晚于拟发布时间的状态不进入候选；
5. 同时间两个不同状态返回 `冲突`，不得任取其一；
6. 不同主体、不同实例槽的状态不进入候选；
7. 关系19缺角色、重复角色、错源/端点、重复资格/时间槽和坏成功载荷返回 `内部不一致`；
8. P10式旧值退出、P7式场景移动、端点后来退出后仍选择并由 P9 历史互证；跨场景候选不被隐藏；
9. 并发发布造成首末代次变化时完整重试或 `版本漂移`，不返回混代候选；
10. 入口、未找到、许可、资源和 P9 非成功逐项分账且载荷为空；
11. 请求结构中前状态身份、事实截止、算法、注册、动态、许可和事务字段均为零处；
12. 函数中 P7/P8/P10/P11、SQL、材料、缓存、旧句柄仓和写入调用均为零；
13. Debug/Release Rebuild、两配置完整自检、strict、MSVC模块扫描和 diff check 通过。
