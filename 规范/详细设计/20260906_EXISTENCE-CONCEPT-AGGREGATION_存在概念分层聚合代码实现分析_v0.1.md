# 存在概念分层聚合代码实现分析

日期：20260906

版本：v0.1

性质：当前代码事实与实现路线分析；不是正式逻辑规范、冻结接口设计或可执行代码计划。

本轮目标：修订存在概念形成规范，分析如何实现；本轮不修改生产代码，不恢复旧施工计划。

正式依据：2220 v1.9、7100 v1.3、7110 v1.3、7140 v1.4、4240 v0.20。二次至 n 次单项 I64 及一次二维轮廓、三维体素的边界继续服从 1180、2100。

## 1. 结论

应扩展现有新概念树数据服务和存在概念应用，复用世界存在已有的子存在组成关系。关键变化是从“特征概念身份集合”改为“自身特征约束 + 子存在概念及数量 + 组成关系约束”，再实现分层聚合、层内组合遍历和使用退出。仅在原循环中增加子集枚举不能实现这个目标。

分割聚合与分类聚合具有不同结果：前者的具体组成由世界服务保存，后者的抽象类别由概念服务保存。子存在可以在父存在描述中作为一个聚合单元，但它仍保持存在身份，不需要改造成特征值。

## 3. 实际缺口

1. 存在定义缺少子存在角色、数量、关系及其引用保护；现有精确相等是FC身份集合相等，不能处理同义模板或对称角色重编号。
2. 实例形成依赖调用者显式给出模板见证，没有自动收集当前层描述、递归处理子存在和分类归组。
3. 上位只删除模板，不会借用FC上位值域或子存在上位概念；数据层图无环也不能证明业务定义包含。
4. 没有按类型组合跨分支召回、完整层内穷举、分页续行或直接边精简的自动主流程。
5. 没有独立业务命中 / 使用依据及相应治理入口；不能把支持关系数量直接当使用次数。
6. 特征概念前置尚未闭合：当前源码及2220第6.1节、4240第5.5/11/13节仍保留宿主范围和成熟结构。它们与此前确认的“FT + 值域、无成熟字段、单值逐层聚合”目标存在待修订差距。本轮修订的是存在形成口径，没有声称已完成特征概念全链迁移；后继必须同步修订这些特征专门合同及消费者，不能在EC内部偷改FC身份。

## 4. 建议的数据结构变化

以下名称为建议，未冻结C++公开签名。

| 目标位置 | 建议结构 / 能力 | 用途 |
| --- | --- | --- |
| `数据服务.概念树类.ixx` | 扩展`概念树存在定义`，包含自身约束、组成约束、关系约束三组 | 保留原特征模板能力，表达完整结构 |
| 同上 | 组成角色、目标存在概念引用、数量约束、次序语义；关系类型、参与角色、相应值域引用 | 区分多个同类部件、有序排列及关系，不把句柄打包进数值 |
| 同上 | 规范化完整定义读取 / 精确查找、按类型及结构签名有界召回 | 跨父分支找相关定义，完整比较后复用 |
| 同上 | 组成定义关系与来源依据关系分账、递归引用校验及退出闭包 | 来源退出不改义，仍被使用的子定义不被删除 |
| 同上 | 独立业务命中 / 使用记录及同请求去重读写 | 为窗口统计和生命周期提供可回查依据 |
| `应用服务.存在概念树类.ixx` | 层内描述、逐约束世界见证、形成阶段结果、枚举继续材料 | 同H、原key恢复，不把第一批成功解释为全部完成 |

规范化须处理关系角色的同构：两个同类部件交换临时编号但关系含义不变，不能因此生成两个概念。不能仅按传入角色号排序，也不能用哈希相等代替完整结构相等。建议先区分正式有序角色与无序同类角色，对后者形成确定规范表示；公开格式、算法版本和预算失败必须在代码计划中冻结。

实例见证与定义分开。定义引用“轮子概念”；见证引用某个具体轮子、父子组成关系、其概念支持依据及截止。要求四个轮子时，见证集合必须有四个互异实例；同一轮子的四次读取不满足数量约束。

## 5. 应用流程建议

建议在`应用服务.存在概念树类.ixx`内组合现有入口，职责相符的内部函数可分别承担：

```text
读取层内存在描述
-> 收集自身特征及直接子存在，核验共同截止
-> 按组成递归形成 / 复用子概念，检测循环
-> 按类别归组，保留数量、顺序和关系
-> 规范化存在定义并精确查找
-> 复用或创建存在概念，建立真实支持
-> 召回同类型及结构可对齐概念，计算分类上位
-> 遍历本层合法组合，逐个复用 / 发布
-> 校验语义包含并整理多父直接边
-> 返回已完成阶段、概念结果和未完遍历的继续材料
```

建议内部函数边界为`读取层内存在描述`、`规范化存在约束`、`计算分类聚合`、`枚举下一批组合`、`验证存在定义包含`、`整理直接上位关系`。公开入口优先演进既有`形成或复用存在概念`和继续函数，不新增绕开原发布/恢复路径的第二套入口。最终签名须随提供者、消费者和验证一并冻结。

分类上位计算有两种不同操作：保持角色而放宽值域 / 子类别，或删除部分条件。都必须证明原定义蕴含新定义。不能把同FT当成域相同，不能把已有图边当成唯一证明；放宽多个域形成的交叉组合不建立新的实例支持。

兄弟比较可以作为加速路径，完整相关集合仍按类型和结构从当前根内召回。例：A和B先形成P，C后来到根下；只比较根下P和C可能漏掉B和C的共同分类。验收应比较换序输入后的规范化定义集合和分类可达性，而非分配出来的节点编码。

层内穷举以有限输入快照驱动，使用确定组合顺序和依赖闭包过滤。完成每个定义后用精确规范化键去重；父概念在下一轮作为更高层输入，不能在当前遍历中无限追加原子。工程预算允许暂停，不允许把未遍历部分直接丢弃。层内m个独立单元仍可能产生2^m−1个非空组合，分层只能降低m，不能证明任意输入都无组合增长。

## 6. 世界服务与场景入口

`数据服务.存在类.ixx`已有子存在关系，优先复用；它只保存调用者提交的世界结构。将深度材料分割为部件、判断哪些对象聚为整体属于观察 / 分割业务，不能塞入概念provider或仅靠场景父子关系推断。

`应用服务.场景成员概念类.ixx`可以将同截止场景直接成员送入新的存在形成入口，并保留每个成员的真实阶段结果。场景仍只界定范围，不建立场景概念根。按完整批次扫描和增量变更触发均可由应用宿主编排，不由DATA自建线程。

数量、距离及角度等二次结果分别使用具名I64特征类型；子存在引用是结构引用，不属于“多分量二次特征值”。一次二维轮廓和三维体素仍作为观察与分割材料保留，不为满足I64把完整材料打包成一个整数。

## 7. 使用与退出

实际业务查找命中和实际采用分开解释，但都只使用独立、可回查的业务请求依据。统计投影可以从记录重建，避免把“计数缓存”和“记录”变成两份不同步权威。生成、聚合查重、读回和重放不累计使用。

治理入口依具名规则的观察窗口推进活跃、冷却、退役，复用现有生命周期事务。长期不使用的父概念仍引用子概念时，先退役父概念；在其满足不可逆退出条件后，由退出父概念的同笔事务解除定义引用，再清理不再被引用的子概念。不能因退役而先拆定义，也不能为清理子概念原地删掉仍有效父定义的条件。生成时建立的当前支持不是用途，必要时先按具名支持退出请求关闭并保存历史，再核验概念退出。中间层退出使用现有替代边闭包，四个根不参与退出。

没有固定成熟度字段或候选晋级阶段。实际采用、长期未使用、资料读取失败、引用保护拒绝要返回不同含义；治理无动作是合法结果，不能猜成功删除。

## 8. 事务、格式与恢复

单个存在定义连同角色、组成及关系约束应在同一概念owner事务中发布，不能暴露一半定义。实例、多个子概念、父概念、支持和上位边可能已经分别发布，整体结果须保留分阶段事实。发布未知时先按原key回查，不换key重新生成。

旧EC定义及FC宿主签名迁移涉及公开DTO、定义等价、历史读取、引用保护和消费者，不能当普通局部代码修补。新格式应可识别旧格式并保留原解释；当前同义迁移须有明确映射和引用迁移顺序，不能改旧身份含义或将旧记录伪装为新记录。

原实例观察H与本次概念结构读取G需要分开保存。处理批次期间新概念会发布新的G，不能把由本次发布引起的G变化当成原观察H失效；新增世界观察也不能混入原H。继续材料应绑定输入、规则、已完成定义及实际发布状态，其完整性由正式读回核验，不建立应用私有事实账。

## 9. 建议实施顺序与尚需冻结项

先闭合特征概念提供者的FT + 值域规范化、类型化聚合和旧宿主 / 成熟合同迁移，再将存在新定义、提供者公开接口、存在应用及首个合法消费者作为同一闭环代码计划推进。场景批次接入与使用治理在同链内按真实提供者能力安排，不把只有DTO的提交宣称为完成。

实施前仍需冻结：

- 特征值域聚合的具名算法、支持类型、精度 / 距离规则及版本；I64、一次向量和轮廓 / 体素不能无依据共用一个比较公式。
- 组成角色、数量和关系约束的最终C++类型、规范化算法、字段对应关系及持久格式迁移。
- 新旧FC/EC定义同义映射、已有实例名称和动态模板消费者的迁移边界。
- 独立使用请求去重命名空间、窗口参数、记录保留和计数溢出处理。
- 原H与阶段G、遍历恢复、并发同义创建冲突及发布未知的完整结果合同。

这些是进入可执行计划所需的合同，不是本轮规范修订尚未执行，也不以“等待概念成熟”规避实现。本材料没有新增执行队列项，旧FEATURE-EXISTENCE-SCENE-CONCEPT-APPLICATION方案不能按已失效的严格子集口径直接续工。
