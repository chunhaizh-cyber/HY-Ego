# 方法虚拟存在到任务虚拟存在实例化详细设计

日期：2026-09-05

版本：v0.4

身份：`ARCH-L4-METHOD-VM-TO-TASK-VT-INSTANTIATION`

状态：执行侧具名 DRIFT 已按用户最新语义裁决，等待代码实施重新 S0

## 1. 最新输入与唯一解释

用户补充：“方法函数中需要调用方法类中函数添加方法自身特有的特征信息到方法虚拟存在
中，主要是方法函数所需要的参数（场景、存在、特征等信息）。”

这里的“参数”只能解释为方法定义期参数规格，不能解释为某次运行的实际参数：

```text
方法函数的定义/登记过程
-> 调用方法类公开入口
-> 在方法唯一Vm登记0..N项参数规格
-> 每项保存参数类别、全局顺序和参数特征类型FT

任务实例化
-> 读取Vm完整参数规格组
-> 在任务Vt下的实例头I复制同长度、同顺序、同类别的规格引用
-> 逐槽绑定本任务已有的具体特征节点
-> fresh读回全部特征节点并形成按全局顺序排列的可执行参数组
```

参数类别稳定值域：`场景=1、存在=2、特征=3`。数量运行时确定，可为零且没有固定上限；
每次读取必须提供正数预算。方法函数是参数规格登记和最终参数消费的合法未来调用方；本叶
只提供规格登记、实例复制、实际数据绑定和完整参数读回，不修改具体方法函数，也不执行
方法、选择场景或取得执行授权。

## 2. 规范裁决与结构选择

5350 已规定输入规格是方法头或条件的强类型值式关系，必须保存作用角色和顺序；3300 规定
输入规格只能作为关系、引用、治理事实或值式材料，不能扩张为第四类长期方法知识节点。
因此本叶不建立参数规格节点 P，而用三种具名关系类型编码类别、关系角色编码全局顺序：

```text
method owner:
M --方法Vm--> Vm --场景参数特征类型[顺序]--> FT
                  --存在参数特征类型[顺序]--> FT
                  --特征参数特征类型[顺序]--> FT

task owner:
T --任务Vt--> Vt --实例宿主--> I
                  I --来源方法--> M
                  I --来源Vm----> Vm
                  I --场景参数规格[顺序]--> FT
                  I --存在参数规格[顺序]--> FT
                  I --特征参数规格[顺序]--> FT
                  I --场景参数数据[顺序]--> F
                  I --存在参数数据[顺序]--> F
                  I --特征参数数据[顺序]--> F
```

裸的一种 `Vm -> FT` 关系无法无歧义保存类别，v0.3 方案失效。三种方法关系均由 method
owner 持有，三种任务关系均由 task owner 持有；它们共同使用一个从 1 开始、无缺口、无
重复的全参数顺序空间。同一 FT 可在任意不同顺序槽重复出现；同一顺序至多一项。

FT 必须由 L1 当前读回证明为 `节点种类::属性类型` 且有值表示。当前允许依赖中没有场景类，
存在类和特征类也没有公开“参数类型本体资格”查询，因此记录面不得声称已证明 FT 的场景/
存在/特征业务值域；类别由三种强类型关系权威保存，FT 的业务准入由方法应用面在提交前
裁决。本叶不调用场景类，不用名称、文本或编码区间猜测类别。

规范无需修改：这是输入规格关系的薄记录实现。它不补齐 5350 要求的条件关联、作用对象
角色、规格材料来源、内容版本和生命周期，也不声称完整方法已发布。

## 3. 身份、复制和业务边界

1. Vm 是方法头抽象信息宿主；I 及其参数规格关系是 Vt 内任务实例信息。
2. Vm、Vt、I、M、FT 身份分离，不移动节点、不合并 owner、不回写 Vm。
3. “复制”是建立新的 task-owner `I -> FT` 规格引用，保留源类别和顺序；不复制源关系身份。
4. 实际参数绑定是 task owner 新建 `I -> F` 关系；F 是已有的具体特征节点，且其特征类型
   必须等于槽 FT。绑定冻结 F 身份；该身份唯一确定不可变创建代次，不重复持久化第二份创建
   代次。执行前须 fresh 查询同一 F，并返回其创建事实代次与值。
5. 特征换代不会改写被绑定节点；F 已退出时参数组不可执行。本叶不提供重绑，须由后继实例
   或正式冻结合同处理，不得静默跟随新特征。
6. 场景/存在参数的业务对象只能由 F 的正式特征值材料引用承载。本叶只验证外层 F/FT 当前
   性和类型相等，不调用场景类，也不伪称验证引用目标的业务本体资格。
7. 不创建、修改或换代特征节点，不把具体场景、存在实例、特征值或运行参数写进 Vm。
8. 条件/结果节点、二次特征方向、状态、授权、运行结果不进入本实例写集。
9. 业务应用面必须先裁决采用，才能请求实例化；方法已登记只证明引用闭合，不表示采用。
10. 本叶不建立路径、轮次、冻结或 5260 正式实例方法；新旧并行，旧 `服务.L2*` 零调用。

内容版本/代际的未来合同，本薄记录不提供原地修改、删除或替换。

键固定为 `1`。形成前必须证明目标 I、对应规格槽及 FT；任务类在请求规格前以特征类证明
F 当前且其类型等于 FT。同槽无绑定才返回写集；同 F 同义已绑定返回`已实例化`，同槽不同 F
或额外绑定返回`结构冲突`。组读回允许未绑定槽，但每槽至多一个类别匹配的数据关系；任何
错类别、错顺序、无规格的数据关系或复义绑定均整体失败。

绑定流水：G0/首次材料 → T/Vt/I及槽 → `特征服务_.查询特征` fresh读 F → 要求 F 当前且

可执行参数读取在同一 G0 读 I 全部槽。零参数实例成功返回空组；非零时每槽必须恰一绑定，
