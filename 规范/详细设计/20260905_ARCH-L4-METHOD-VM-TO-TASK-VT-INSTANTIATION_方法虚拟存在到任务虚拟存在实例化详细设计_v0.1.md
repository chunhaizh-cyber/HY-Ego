# 方法虚拟存在到任务虚拟存在实例化详细设计

日期：2026-09-05

版本：v0.3

身份：`ARCH-L4-METHOD-VM-TO-TASK-VT-INSTANTIATION`

状态：执行侧具名 DRIFT 已按用户最新语义裁决，等待代码实施重新 S0

## 1. 来源问题与唯一裁决

用户明确修订：“实例化就是复制一份特征类型添加到任务虚拟存在中，这里待复制的特征类型
数量是不固定的。”因此 v0.2 的 `M/Vm/C/R` 来源投影语义失效；条件和结果节点不是本次
实例化应复制的对象，简单 `Vt -> Vm` 也不能表达逐项实例信息。

v0.3 将实例化冻结为：method owner 在方法唯一 `Vm` 上保存有序、可变长度的
`方法抽象特征类型组`；task owner 在任务唯一 `Vt` 下建立任务局部实例头 `I`，为源组中
每一项建立一条新的 task-owner `I -> 特征类型` 关系。

```text
method owner: M --方法Vm--> Vm --抽象特征类型[1..n]--> FT[1..n]
task owner:   T --任务Vt--> Vt --实例宿主--> I
                                  I --来源方法--> M
                                  I --来源Vm----> Vm
                                  I --实例特征类型[1..n]--> FT[1..n]
```

源、目标两侧引用同一个当前属性类型节点，但拥有不同 owner 的关系事实，这就是“复制一份
特征类型”的精确数据含义。`n` 运行时确定，可为零且没有固定上限；每次调用仍须给正数扫描
预算，写集按实际 `n` 形成一个 I 和 `3+n` 条关系，并先检查数量与本地键溢出。

## 2. 语义边界与规范裁决

1. `Vm` 是方法头抽象信息宿主；`I` 及其 `I -> FT` 是 `Vt` 内任务实例信息。
2. Vm、Vt、I、M、FT 身份分离；不移动节点、不合并 owner、不回写 Vm。
3. FT 必须由 L1 当前读回证明为 `节点种类::属性类型` 且具有值表示。这里只复制类型引用，
   不调用特征类新增，不创建特征结点，不复制或生成特征值。
4. 条件/结果节点、一次特征实例、二次特征值/方向、参数、状态、授权和运行结果不进入写集。
5. Vm 抽象类型组是方法声明给任务实例使用的模板关系，不是从条件/结果计算并持久化的能力
   投影；它没有形成第四类方法知识节点，符合 3300 对“关系、引用”的边界。
6. 本叶是 ARCH-L4 薄记录面。业务应用面必须先裁决方法采用，才能提交实例化请求；本叶不
   建立采用、选择、路径、轮次、冻结或 5260 正式实例方法，也不把“方法已登记”解释为采用。
7. 新旧并行；旧 `服务.L2*` import、调用、DTO 复用和强转均为零。

因此无需修订正式规范：3300/5350 允许 Vm 挂载正式结构引用；5260 对“当前采用方法正式
声明的任务业务特征”的前置由业务应用面负责。没有合法调用方时，本入口存在不证明采用。

## 3. 当前事实与 WIP 裁决

正式基线 `66fc28a9d412f1dc5288cfd247157ed846a65157` 与 `origin/main` 一致：方法类 v2
有 M/Vm/C/R 数据操作但无 Vm 抽象类型组；存在类有 Vt/Vm 独立专用规格；任务类 v2 有
T/Vt/方法薄引用和 task-owner 写端口；特征类以 L1 属性类型节点作为“特征类型”；L1 支持
一个 owner 写集中建立指向跨 owner 稳定端点的关系、期望代次、首次材料和提交后读回。

存在类、任务类未提交 v0.2 WIP 不是接口事实，其 `I -> C/R` DTO、状态和辅助函数全部失效；
执行者须在原所有权内用 v0.3 替换，不得作为兼容 ABI 保留。方法类从正式 v2 增量实施。

顺序返回。预算不足、断序、重复、错 owner/端点/类型或非当前属性类型均零载荷失败。

抽象类型组/来源规范化/规格/提交/Gend 读回，非成功零投影或零组。
