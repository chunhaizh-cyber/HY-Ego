## 4. 外部事务包内部合同

`安全维护外部事实参与包` 由数据操作模块唯一声明，真实实现属于 #359 适配，自检实现属于 #377。包至少提供以下私有虚函数，由 `分层安全数据操作` 友元调用：

```cpp
virtual std::span<节点直接身份结构写入事务参与者* const>
    读取参与者视图() noexcept = 0;
virtual void 写入核心候选(
    节点直接身份结构写入会话& 会话) = 0;
virtual 安全维护外部事实发布读回结果
    读取发布后事实() const = 0;
```

提供者形成包时只冻结规格和内部对象；普通读取仍看不到候选。`写入核心候选` 在执行器回调中形成三类节点候选、完整关系和索引，并把候选句柄写入包内共享材料；随后状态/动态等参与者在准备阶段只读这些材料。任何写前业务拒绝必须在形成包时返回，不得拖到核心回调中猜测；核心回调只允许产生核心结构状态、版本、资源或内部结果。

## 5. 功能确认

1. 后特征值、后状态和动态的稳定主键来自请求；对应句柄只由外部事务包在统一核心会话形成。
2. `来源已发布事实批次` 在纯被动分支为空；主动分支只引用既有结算批次，不由本轮生成。
3. 外部包、参与者 span 和包内候选身份材料的生命周期覆盖核心回调、参与者准备/确认/发布和发布后读回。
4. 发布后读回必须同时证明稳定主键、已发布句柄、前后值、前后状态、动态、来源存在/动作、可选来源批次、候选代次和来源版本一致。
5. 未决项为空。

## 6. CORE-C1/v1 计划内提供者门禁

当前核心普通入口在 `节点直接身份结构写入会话::请求提交()` 发现核心写集为空且没有核心幂等读回时固定记录 `内部不一致`，因此不能提交只有安全维护记录参与者的无变化候选。F-S108 不得用普通入口、伪造核心候选或绕开参与者生命周期。

预冻结待实现合同 `CORE-C1/v1`：

```cpp
节点直接身份结构写入结果
节点直接身份结构写入执行器::执行仅参与者事务(
    std::span<节点直接身份结构写入事务参与者* const> 参与者组) const;
```

该合同由 #381 提供；#377 v0.6 在 #381 真实结果进入 `main` 前保持 `待激活`。完整算法、所有权、失败与验证见 #381 设计包。
