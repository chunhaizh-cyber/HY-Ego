# INSTINCT-STAGE3-SERVICE-EXPIRY-CONTRACT-READBACK 服务到期事件合同终态完整读回详细设计 v0.1

日期：2026-08-30

设计身份：`INSTINCT-STAGE3-SERVICE-EXPIRY-CONTRACT-READBACK`

## 1. 目标与完成边界

扩展现有唯一 `服务合同事实权威服务`，在指定自我和非零事实截止 `G0` 下，完整读取每一项到期未满足事件及其原服务合同、合同当前终态，使后继服务维护组合器能够从原合同正式取得时间纪元，并证明事件确实对应一个已经到期的合同。

本叶只形成中性只读投影，不计算“本秒到期”、最长等待、有效服务活动、服务值衰减或生存安全回归，不写任何事实。当前生产阈值定义保持不变：值域 `0..I64_MAX`，`L=2,767,011,611,056,432,742`，`H=7,378,697,629,483,820,645`；未来只能通过新定义版本调整。

## 2. 正式依据与当前事实

正式依据：0050 v2.1、6100 v0.5、6120 v0.10、6160 v0.4、6170 v0.6。

当前正式代码基线：`main == origin/main == aae866f184ec8e0183bbf11c405e97b4776a5b02`，index 空。当前唯一服务合同 owner 已能完整读取到期未满足事件，但结果只返回事件本身；事件事实不重复保存时间纪元，时间纪元只存在于其原合同。现有读取实现已在内部读取事件引用的合同来校验关系，却丢弃了合同投影，也没有把合同当前状态纳入结果。

因此后继不能安全执行：

```text
事件.到期完整秒边界 == 当前完整秒边界
```

因为不同时间纪元中的相同数值不可比较。正确修复不是给事件复制第二份时间纪元，而是从同一 owner、同一 `G0` 正式读回事件、原合同和当前终态。

依赖方向：

```text

```

## 4. 数据合同

### 4.1 投影

新增：

```cpp
struct 服务到期事件合同终态投影_v1 final {
    服务到期未满足事件事实_v1 事件;
    服务合同事实_v1 原合同;
    服务合同状态事实_v1 当前终态;
};
```

完整性必须同时证明：

1. 三项事实各自在 `G0` 完整；
2. `事件.合同 == 原合同.身份 == 当前终态.合同`；
3. 事件的需求、提出者和冻结有效总秒分别等于原合同字段；
4. 当前终态为 `已到期`；
5. 当前终态的已消费有效秒等于事件的实际已消费有效秒，并等于合同冻结有效总秒；
6. 当前终态版本等于事件合同终态版本；
7. 事件到期边界不早于合同有效开始边界；
8. 原合同的自我等于请求自我。

禁止只凭事件枚举、日志或边界数值推断合同已到期。

### 4.2 请求、见证和结果

请求直接复用 `服务到期事件完整集合读取请求_v1`，避免第二个同义读取键。

新增见证和结果：

```cpp
struct 服务到期事件合同终态完整集合见证_v1 final {
    std::uint32_t 结构登记版本;
    std::uint64_t 声明成员数;
    std::vector<服务到期未满足事件身份_v1> 规范成员身份组;
    std::uint64_t G0;
};

struct 服务到期事件合同终态完整集合读取结果_v1 final {
    std::uint32_t 合同版本;
    服务合同事实权威读取状态_v1 状态;
    std::vector<服务到期事件合同终态投影_v1> 完整投影组;
    std::optional<服务到期事件合同终态完整集合见证_v1> 完整集合见证;
    std::uint64_t 本次正式读回截止;
    bool 成功() const noexcept;
};
```

成功只允许 `状态=已读取`、截止等于 `G0`、见证完整、投影组与规范事件身份组逐项相同、事件身份严格升序且每项完整。0 项是合法成功。全部非成功必须空投影、空见证、截止 0。

## 5. 公开入口与固定算法

新增公开入口：

```cpp
服务到期事件合同终态完整集合读取结果_v1
服务合同事实权威服务::读取到期未满足事件合同终态完整集合_v1(
    const 服务到期事件完整集合读取请求_v1&) const noexcept;
```

固定流程：

```text
合同版本 / 自我 / G0 校验
-> G0 读前守卫
-> 读取全部到期事件成员关系
-> 读取事件到原合同关系和两端载荷
-> 读取全部合同当前状态关系和状态载荷
-> 按事件身份逐项连接唯一原合同与唯一当前状态
-> 校验自我、需求、提出者、有效秒、终态和版本
-> 按事件身份规范排序并形成完整集合见证
-> G0 读后守卫
-> 成功或结构化非成功
```

漏事件、额外事件、重复事件、事件无唯一合同、合同无唯一当前状态、终态不是已到期、版本或秒数不一致均整体返回 `集合不闭合`或`引用冲突`，不得跳过坏项返回部分成功。

## 6. 验证矩阵

至少覆盖：

1. 0 / 1 / N 投影完整集合、事件身份规范排序和共同 `G0`；
2. 原合同时间纪元按原值返回，不向事件复制第二份时间纪元；
3. 事件、合同、状态三者身份、需求、提出者、自我、有效秒和终态版本逐项互证；
4. 非已到期状态、消费秒不足、合同终态版本错配、错误合同关系、缺状态和重复状态整体失败；
5. 漏 / 多 / 重成员、坏载荷、混合 `G0`、读中漂移和资源失败；
6. 非成功零载荷，合法空集合与未取得材料分离；
7. 仓库外 Debug / Release ABI consumer；
8. v143 x64 Debug / Release 根工程 Rebuild、持久恢复、strict 和两类 diff-check；
9. 静态确认无新 owner、写入口、键段和 L/H 修改。

## 7. 完成声明边界

本设计完成只证明到期未满足事件、原合同及当前到期终态可以在同一 `G0` 完整读回，并为后继提供正式时间纪元来源。它不证明任一事件属于当前秒，不裁决最长等待或有效活动，不写服务值 / 安全值，不完成阶段三或 `INSTINCT-ROUTE`。
