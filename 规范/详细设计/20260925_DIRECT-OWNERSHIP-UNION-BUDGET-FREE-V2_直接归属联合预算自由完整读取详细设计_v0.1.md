# DIRECT-OWNERSHIP-UNION-BUDGET-FREE-V2 直接归属联合预算自由完整读取详细设计

版本：v0.1

## 1. 目标与边界

本设计建立一个最早可独立施工的预算自由读取叶：在已知事实代次和已知端点节点下，完整读取存在组成关系、场景直接包含关系，并把两族结果合并为联合唯一直接父或完整直接子组。

本叶只解决 `SELF-ROOT-GOVERNANCE-INTENT-SINK` 的 fresh 上下文前置链中最靠下的一项真实阻断。它不实现预算自由场景树、世界树根读取、真实自我读取、自我线程正式上下文、task owner 按意图恢复、自我线程消费、manager 交接或治理门开放。

旧版本1请求、状态和入口保留为旧 ABI 迁移识别；新生产不得调用旧入口，不得传极大值模拟无预算。本叶不修改 L1，不建立索引、缓存、第二账、进度账或持久消息记录。

## 2. 正式依据与当前事实

1. `规范/0050_项目通用机器逻辑与禁止性规则总纲_20260721.md` 第3.2节规定：上层定义完整语义范围，节点、关系、材料、深度等资源计数不得成为成功上限；资源不能完成完整范围时返回`资源失败`并清空业务载荷；旧预算 ABI 只作迁移识别。
2. `规范/1140_根规范_存在节点_20260720.md` 与 `规范/4202_子规范_场景字段与实例树组织.md` 规定：存在组成、场景成员和直接子场景合计至多一个直接父；直接子组为完整结构集合。
3. 当前 `直接归属联合只读组合器` 依次调用版本1的存在组成和场景包含父/子组入口；三类请求都含`最大关系数量`，成功谓词也以数量预算为门禁。
4. L1 已发布 `读取节点全部当前引用_v2`。它以已知节点和期望事实代次定义完整范围，返回该节点涉及的全部当前关系和值；无最大数量字段，资源不足返回`资源失败`。
5. 当前 `存在类数据服务::确认当前存在结构身份` 已使用预算自由的一致当前投影，可继续作为存在组成 v2 的端点身份门禁。

由此，场景树 v2 不能先于联合归属 v2：否则仍必须调用旧预算入口或伪造无限预算。

## 3. 语义范围

### 3.1 查询范围

- 父读取：给定 `G0 + 成员节点`，完整读取三族当前直接父关系；成功结果为零个或一个父。
- 子组读取：给定 `G0 + 父节点`，完整读取三族当前直接子关系；成功结果包含全部成员，不允许分页、截断或部分成功。
- 三族固定为：存在组成、场景成员、直接子场景。不得将父场景语境投影、树归属证明、四根组织边或其它关系解释为直接归属。
- `G0` 同时是期望事实代次、读取截止和结果 `Gread/H`。本合同不提供历史查询。

### 3.2 结构不变量

1. 单族父读取最多一条；联合父读取三族合计最多一条。超过一条返回`内部不一致`，不得任取一条。
2. 子组允许零到多条；同一成员在三族中重复出现属于`内部不一致`。
3. 每条关系必须为当前有效、角色1、类型匹配、方向匹配且由对应结构 owner 写入。
4. 输出按`成员编码 -> 来源枚举 -> 关系编码`严格升序；父读取只有 optional 父，子组读取只有 vector 子组。
5. 非成功必须清空父和子组。

## 5. 实现算法

### 5.1 存在组成提供者

物理位置：`海中鱼巣/领域/数据服务.存在类.h`。

1. 校验版本2、非零G0和有效端点。
2. 调用既有预算自由 `确认当前存在结构身份(G0, 端点)`；按同名状态映射。`未找到/目标已退出`保留，不伪装为空组。
3. 调用 `L1事实基座服务::读取节点全部当前引用_v2({2, 端点, G0})`。
4. 只接受 variant 中的关系事实；关系类型不是`子存在关系类型_`时忽略。类型命中后必须核验`写入所有者==所有者_`、`角色或顺序==1`、当前有效且方向匹配；任何不符均为`内部不一致`，不得把错owner的正式类型边忽略。
5. 父读取要求目标为端点且命中数不超过1；子组读取要求源为端点并返回全部命中。
6. 按关系编码严格升序形成 `存在组成关系事实`；三层新增v2入口统一捕获 `bad_alloc/length_error/system_error` 为`资源失败`，其它异常为`内部不一致`，非成功时清空业务载荷。

### 5.2 场景直接包含提供者

物理位置：声明位于 `海中鱼巣/领域/数据服务.场景类.h`，定义位于 `海中鱼巣/领域/数据服务.场景类.cpp`。

1. 校验版本2、非零G0和有效端点。
2. 调用 `读取节点全部当前引用_v2`。L1 的`未找到/已退出/事实代次漂移/资源失败`精确映射；其它异常或头部矛盾为`内部不一致`。
3. 只筛选 scene owner 写入、角色1、关系类型为`直接存在成员关系类型`或`直接子场景关系类型`且方向匹配的当前关系。
4. 把两类关系分别映射为 `场景直接包含种类::存在成员/子场景`；按关系编码严格升序返回完整组。
5. 任一引用关系的类型命中本服务正式直接包含关系类型后，必须继续核验正式 owner、角色、方向和当前生命周期；任一不符均为`内部不一致`，不得作为“其它类型”忽略。只有关系类型不属于本服务正式类型集合的引用才忽略。
6. 命中关系形状错误、同一成员同时命中两种直接包含关系或重复关系编码均为`内部不一致`。

### 5.3 联合组合器

物理位置：`海中鱼巣/领域/合同.场景角色组织.cpp`。

父读取顺序固定为存在组成 v2，再场景包含 v2；子组读取顺序相同。顺序只用于确定失败优先级，不是事实优先级。

- 任一提供者非成功时停止，映射同名状态并清空载荷。场景子组提供者对当前有效的普通父存在可以成功返回空组，因此联合组合不需要错类分支。
- 父读取合并后数量为0或1才成功；超过1为`内部不一致`。
- 子组读取合并全部结果，按`成员编码 -> 来源 -> 关系编码`排序；同一成员出现多次或相同关系编码重复为`内部不一致`。
- 不对结果数量设上限，不记录读取用量，不持久化组合结果。

## 6. 状态映射

| L1 v2 | 组成/场景 v2 | 联合 v2 |
| --- | --- | --- |
| 成功 | 继续筛选 | 继续合并 |
| 入口拒绝 | 内部不一致（有效上层请求下不应发生） | 内部不一致 |
| 未找到 | 未找到 | 未找到 |
| 已退出 | 目标已退出 | 目标已退出 |
| 事实代次漂移 | 事实代次漂移 | 事实代次漂移 |
| 资源失败 | 资源失败 | 资源失败 |
| 内部不一致 | 内部不一致 | 内部不一致 |

只有请求头本身不合法返回`入口拒绝`。任何非成功结果必须回显合同版本和实际 `Gread`（若下层已给出），并清空业务载荷。

### 6.1 成功谓词

三类结果不增加独立`H`字段；这是只读当前合同，结果头的`Gread`是唯一截止，每条事实的`Gread`和`H`都必须等于结果头`Gread`。即使父为空或子组为空，仍由请求`G0`、结果`Gread`和成功状态核验当前截止。

- 所有成功谓词先核验请求版本、非零G0、有效端点、结果版本、状态`已读取`及`Gread==请求.G0`。
- 父读取成功要求`子组.empty()`；optional父为空合法。非空父必须当前有效，`Gread==H==结果.Gread`、成员等于请求端点、父和关系编码有效、创建代次非零且不晚于H、无退出代次。
- 子组读取成功要求`!父`；每项必须当前有效，`Gread==H==结果.Gread`、父等于请求端点、成员和关系编码有效、创建代次非零且不晚于H、无退出代次。
- 组成子组按关系编码严格升序；场景包含组按关系编码严格升序；联合子组按`成员编码 -> 来源枚举 -> 关系编码`严格升序，并要求成员编码不重复。
- 场景父组成功允许0或1项，不允许超过1项；联合父成功允许optional 0或1项。场景结果使用`包含组`表达父组，因此父组谓词额外要求大小不超过1且每项成员等于请求成员。
- 任一非成功状态要求父为空、子组/包含组为空；谓词不得把非成功空载荷当作成功。

## 7. 物理所有权与依赖

- 组成关系解释权：`存在类数据服务`。
- 场景直接包含解释权：`场景类数据服务`。
- 三族联合唯一与确定排序：`直接归属联合只读组合器`。
- L1 只提供中性完整引用，不解释关系类型；本设计不修改 L1。
- 依赖方向保持：组合器 -> 两个只读提供者 -> L1；不存在反向依赖。

## 8. 验证合同

新增独立专项 `验证工具/直接归属联合预算自由完整读取专项验证.cpp` 与 `.vcxproj`。成功、未找到、已退出、代次漂移和结构冲突路径必须使用真实L1运行包和真实两族服务，不用伪provider冒充生产成功；资源失败映射按下列第8项的可达性边界验证。至少覆盖：

1. 请求头非法、零G、零端点；
2. 端点未找到、已退出、G漂移；
3. 三族各自零父、单父、完整多子组；
4. 联合父三族合计0、1和多于1；
5. 子组跨三族合并、稳定排序、重复成员冲突；
6. 错owner、错类型、错方向、错角色、退出关系、重复关系编码；
7. 大于4096条关系仍完整成功，不出现`数量预算不足`；
8. L1资源失败映射分支、catch分支和非成功零载荷用静态代码核查与直接构造结果谓词核查覆盖；当前真实L1没有确定性资源失败注入钩子，不要求用实际内存耗尽制造运行失败；
9. v1入口仍可编译但专项 v2 路径零调用 v1；
10. Debug/Release专项构建运行与根工程Debug/Release隔离Rebuild。

静态核查必须证明新增 v2 请求无`最大*`、`预算`字段，v2实现不调用版本1组成/包含/联合入口，不使用`UINT64_MAX`模拟无预算。
