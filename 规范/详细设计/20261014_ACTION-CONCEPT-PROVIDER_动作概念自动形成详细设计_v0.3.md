# ACTION-CONCEPT-PROVIDER 动作概念自动形成详细设计

日期：2026-10-14；版本：v0.3；代码基线：`904f9dba0cecc6d010520fbf9f83608170416dc7`。执行修订闭合只读实例F依赖、新旧动作读回区分、概念强类型核验与动作删除的工程失败边界，不改变DTO或用户动作能力语义。

本文件是施工设计，不修改正式规范。直接依据用户本窗口对动作概念的具名裁决：归动态概念树；定义类别变化/动作与实例/聚合轴独立；首次真实动作自动形成；保存能力、概念角色及参数规格，显式关联抽象方法；不保存具体执行来源、对象、时间；不在登记阶段造动作。1170中“动作没有动态概念”的旧限制在本叶被替代，其余状态、变化概念、明确来源和改变/观察关系合同不变。

## 1. 当前事实及完成边界

`概念_动态类`只有实例/聚合轴，变化概念至少一个状态槽位。`新_动态类::建立动作动态()`与`建立内部治理动作动态()`真实生产动作，但无概念字段。动作定义字段当前用于方法身份或任务owner的已结算动作能力定义，不能改填概念导致既有校验失效。方法实例保留`来源方法节点`，规格在Vm，完整复制不复制概念。普通动作主体/目标可查询专属存在概念；Vt无存在概念接口，任务参数规格明确禁止存在概念约束。

本叶实现首次实际动作前生成、持久保存、读回及复用动作概念，覆盖普通目标和任务虚拟目标。只改变动态/概念事实的组织，不改变现实对象或Vt值；原因是供后续因果读取真实动作的可复用语义，目的不是替代执行授权、推断效果或建立因果。动作能力概念在真实动作入口形成，而登记头、函数注册、方法复制和模拟登记零动作、零动作概念。

## 2. 唯一物理合同

新增中立头`海中鱼巣/领域/动作概念.只读投影合同.h`。不包含方法类、方法公共类型、任务类或装配。

```cpp
enum class 动作参数对象类别 : std::int64_t {
    普通世界=1, 任务虚拟存在=2, 服务要求来源人类=3,
    服务要求目标存在=4, 服务要求目标特征类型=5,
    服务要求目标定义=6, 服务要求确认=7
};
struct 动作参数特征规格 {
    稳定编码 特征类型概念节点;
    std::optional<稳定编码> 值域概念节点;
    std::vector<稳定编码> 二次特征概念组;
};
struct 动作参数规格 {
    稳定编码 参数角色节点;
    std::optional<稳定编码> 存在概念节点;
    bool 要求场景=false;
    std::vector<动作参数特征规格> 特征规格组;
    动作参数对象类别 对象类别=动作参数对象类别::普通世界;
};
struct 动作概念角色 {
    std::optional<稳定编码> 存在概念节点;
    std::optional<稳定编码> 参数角色节点;
    动作参数对象类别 对象类别=动作参数对象类别::普通世界;
};
struct 动作概念定义 {
    稳定编码 能力定义节点;
    稳定编码 抽象方法节点;
    动作概念角色 执行主体;
    动作概念角色 作用目标;
    std::optional<稳定编码> 目标特征类型概念节点;
    std::vector<动作参数规格> 参数规格组;
};
struct 动作方法投影请求 {
    稳定编码 动作定义节点;
    std::optional<稳定编码> 执行主体概念节点;
    std::optional<稳定编码> 普通目标概念节点;
    std::optional<稳定编码> 目标特征类型概念节点;
    bool 任务虚拟目标=false;
};
class 动作方法定义只读提供者 {
public:
    virtual ~动作方法定义只读提供者()=default;
    virtual 动作概念定义 读取动作方法投影(
        const 动作方法投影请求&) const=0;
};
```

上述值式结构逐字段默认相等，名称及字段即为冻结源级合同。技术参数角色身份来自Vm，不冒称具体存在或存在概念。执行主体必须有合法存在C，普通目标必须有合法存在C；请求中的可选形状不授予缺失主体的执行资格。内部目标允许存在概念为空，明确表示源规格无该约束；不能用Vt编码或参数角色编码填入存在概念字段。

`海中鱼巣/业务/动作概念.方法投影服务.h/.cpp`定义`动作方法投影服务 final : public 动作方法定义只读提供者`，构造签名为`动作方法投影服务(新_方法类&, const 新_任务类&, const 概念_存在类&, const 概念_特征类&) noexcept`。借用各服务，不写它们；普通应用装配中持有并注入世界树/动态。构造只保存引用，不读取方法、不建立概念。提供者投影调用发生在动态锁外，避免dynamic→method/task反向锁序。

动态服务新增配置`void 设置动作方法定义提供者(const 动作方法定义只读提供者&, const 新_特征类&) noexcept`，同时借用方法投影provider及只读实例F服务，只能在无活动调用的初始化阶段一次设置。新增private成员`const 新_特征类* 动作特征读取_ = nullptr`；两个指针共同配置，重复同两个地址无变化，任一个异义地址均工程终止，不用全局可变provider。配置权仅组合根，关闭后不允许动作调用。短构造器不获得动作生成能力，合法生产动作缺任一依赖时工程停止。

## 3. 字段来源与方法实例解析

普通动作主体、普通目标经存在服务查询正式专属C（场景目标经场景服务专属C）。首代合法专属C可用，不猜上位。目标FT通过`动作特征读取_->获取特征(目标特征节点)`完整读取实例F的正式特征概念引用，再由已有特征概念服务解析根类型；不存在目标F则不限制FT。有目标F但读回异常、引用不完整或不属于核验目标为工程故障，不能默认省略FT。实例F读取及方法投影均在动态锁外完成并冻结为局部值式材料，随后持动态锁复核发布。

方法定义若是正式M：读取本次M并沿`来源方法节点`到源抽象M，检测环、缺失、跨实例根异常，拒绝把混合方法容器当可调用M。实例副本与源抽象M共用来源身份；新独立抽象M即使登记名相同也不误并。能力定义设为源抽象M，抽象方法关联设为该M。规格投影读取源抽象M的Vm完整声明，不从任务收窄的条件/结果或实参推导；复制实例已有模型不回写抽象M。

参数七类逐项显式switch投影，不通过整数强转接受未知枚举。完整保留角色、对象类别、可选存在概念、场景要求、全部特征FT/可选值域C/二次C。规格顺序源Vm有序，不任意排序改变角色约定。特征和二次列表按其集合合同规范化去重；所有引用须当前合法读回。服务要求特殊五类保持无存在/场景/特征约束的现行形状。

任务虚拟目标使用源Vm中唯一任务虚拟角色及其对象类别、特征规格；角色C约束可为空，不新增Vt概念，不改`参数规格有效()`。无任务虚拟角色或多项无法唯一确定目标是声明/调用工程错误，不生成概念。

现有任务已结算动作定义是task owner的正式能力，不是M。业务投影服务先调用任务owner既有`获取任务已结算动作定义()`，严格核对请求定义身份；再经服务值结算本能登记读取唯一抽象M，采用其任务虚拟角色规格。能力定义仍引用已结算定义，抽象方法引用结算M；目标FT为任务状态FT，不能误用普通服务值FT。普通服务值增加动作则能力定义为结算M，目标为自我C/服务值FT。二者完整定义不同，永不合并，不给技术节点赋M类型，不新增函数或预造条件结果。

提供者仅接收概念/声明身份与目标种类，绝不接收X、动作来源、具体E/Vt、准确实参或时间。

## 4. 概念定义类别与持久承载

`概念_动态类.h`新增`动态概念定义类别 {变化=1,动作=2}`，信息增加类别和可选动作定义。既有`动态概念种类 {实例,聚合}`保持不变。变化类别保持原状态槽及动态特征合同；动作类别必须动作定义恰一、变化槽/变化特征为空，不允许把空变化概念解释为动作。

概念owner原构造签名追加第四默认参数`const 概念_存在类* 动作存在概念读取 = nullptr`；其头只前置声明`概念_存在类`，实现包含该基础概念类，不包含方法类。世界树现有概念服务构造传`&存在概念服务_`。旧三参变化服务兼容；其动作概念入口缺该依赖时工程停止，不影响变化入口。发布和读回均核验主体存在C、普通目标C及参数存在C确为正式存在概念；内部目标C可空，不能仅凭节点存在通过。主体C强制非空，普通目标C强制非空。所有FT引用必须为正式根链特征类型；可选值域C的类型根必须等于所属FT，二次C按既有二次概念owner核验。动作能力身份与抽象方法身份分别保存，不擅自把它们当存在概念。

新增：

```cpp
动态概念建立结果 建立或取得动作概念(const 动作概念定义&) noexcept;
bool 是动作概念节点(稳定编码) const noexcept;
```

动作概念是可复用完整定义，种类存聚合、无对应动态节点；这里聚合轴表达共享性质，不冒称经过两次变化归纳。首次真实动作即可建立。变化类别原实例/聚合规则不变。类别字段新编码独立，旧无类别但完整变化结构读作变化，不将旧动作事实追补为发生记录。读回新动作结构类别/字段有缺损属于工程结构错误。

动作定义完整相等包含能力定义、源抽象方法、主体/目标角色、目标FT和完整规格；不按名称/头结果相同复用。新概念挂动态概念根，规范化查重在概念锁内，所有动作C引用合法存在/特征/二次C与抽象M。字段直接值存I64/布尔，节点字段存强引用；规格只使用下面冻结的单节点技术形状数组和有序节点引用字段，不建立额外规格、方法或实参节点。

新动作概念只用基础数据集既有`原子建立节点()`一次建立：请求上级为动态概念根，初始字段组包含类型、动作类别、聚合种类及完整动作定义。禁止建立嵌套规格节点后分次挂根，禁止新建底座组合接口。原子发布完成再独立完整读回；不能产生根下半概念。既有变化发布不强行重写为本叶无关迁移。概念已成功发布而动作后续失败时保留可复用能力概念，不能伪造动作；业务操作尚未发生。

该原子入口建立的上级父子关系角色固定为0；动作C必须在动态概念根下恰有一条角色0的成员关系。查询全部概念接受角色0且定义类别为动作的节点，既有变化C保留角色1成员关系。不得先原子建立再改关系角色，不得把角色0普通节点直接判为动作C；成员关系与完整动作类别定义必须共同校验。

动作定义单节点承载：能力定义、抽象方法、主体存在C、可选主体参数角色、可选目标存在C、可选目标参数角色、可选目标FT为独立节点引用字段；所有规格涉及的稳定身份按规范顺序写重复的`动作规格引用`节点字段，不塞入I64或裸字节。技术`动作规格形状`字段保存I64数组，其前七项严格为`主体对象类别,目标对象类别,有主体参数角色,有目标存在C,有目标参数角色,有目标FT,规格数`；随后每规格四项`对象类别,有存在C,要求场景,特征数`，并紧随该规格每特征的两项`有值域C,二次C数`。无其它隐式字段、裸身份或时间。标志只能0/1，数量非负且按容器容量检查。

规格引用序列严格按Vm规格顺序展开：角色→可选存在C→每特征FT→可选值域C→其二次C组。读回先读取形状，检查非负计数、合法枚举、布尔及总量溢出，再按字段身份升序取得重复引用组并逐槽解码；恰好消费全部shape和引用，剩余/不足均结构故障。能力和所有C/角色/M均为节点字段引用，数组只有形状。相等比较解码后的完整值式定义，不以shape或hash碰撞判同义。

动作实例同样使用既有`原子建立节点()`的完整初始字段组，包含原动作定义/来源/主体/目标/时间/零引用、新动作C字段以及`动作已概念化=1`、`动作冻结能力节点`、`动作冻结抽象方法节点`三个技术字段。标志仅区分新结构是否已完整概念化，不是业务状态、声明版本或事实代次；能力及抽象方法均用节点引用字段。不指定概念根上级，随后由场景owner正常挂接。创建后未进入场景的节点可按既有失败清理撤销；已经进入场景的真实动作及可能已发生的业务事实不能删除补造成功。不把动作C与场景挂接的分阶段冒称跨owner原子事务。

## 5. 实例建立、读回、删除和查询

先核验动作请求/主体目标/时间/来源唯一性；同源精确重放读回既有动作C，零新概念、零新动作。异义来源按既有合同拒绝。然后在锁外读取已核验概念角色及方法投影，形成/复用动作C；最后在动态锁内复核来源、目标和声明身份，并建立动作及概念引用。动作必须挂场景后才能执行实际业务操作。

动作`动作定义节点`继续保存原M或内部能力定义；`动态概念节点`新增引用正式动作C。执行实例、X、来源、对象和时间只留动作实例，不进C。getter以三个技术字段分账：有标志的新动作必须标志恰一且值1、C恰一、冻结能力及抽象方法各恰一，三者与动作C定义引用一致，能力/角色/FT与已记录动作一致；不能只验证C节点存在，不能读回时从当前可变M重新推导冻结身份。缺标志且无C、无两个冻结字段的旧动作只按旧完整动作事实读回，不补造C，不进入新动作概念语义消费。无标志却有部分新字段、标志非法或新标志缺C/冻结项均结构故障，不当旧格式吞掉。动作C与M身份分账，不直接比较二者编码。

删除动作沿用既有删除helper和结果引用释放顺序，开始前核验引用次数为0及incoming完整；底座`删除节点()`不自动清字段或关系，本叶不新增底座ABI、不虚报原子级联能力。在动作字段清理中增加解除动态概念字段、冻结能力节点、冻结抽象方法节点，技术`动作已概念化`标志最后删除，随后按既有流程删除已无引用节点。共享动作C留存，不调用变化专属实例C删除，不新建动作C淘汰规则。拆除开始前仍被引用可按既有业务拒绝；一旦开始删除字段/关系/释放结果引用，任何内部失败必须工程异常终止，保留实际阶段并调试修复，不能返回正常业务结果让程序继续读取半动作。普通原子/复合动态删除流程不改。查询全部动态概念包含动作C；变化识别/抽象、共同动态聚合、动态特征保存、采用变化聚合C必须过滤类别并拒绝变化/动作混合。`按概念查询动态()`支持动作C。

既有启动登记保持零动作C。装配：世界树初始化→方法/任务初始化与本能头登记→创建业务只读投影服务→`世界事实.动态服务.设置动作方法定义提供者(provider, 世界事实.特征服务)`→启动线程。只使用既有`新世界事实服务引用`公开引用，不新增世界树公开setter或治理服务。provider及特征服务寿命均长于动态调用；关闭先停线程、等待在途调用，再析构provider/方法服务。世界树不开放任务写入口。

## 6. 工程失败、验证与排除

正式输入不合法沿既有入口拒绝；已接纳生产方法缺失、规格错误、读取异常、投影未知类别、恢复结构矛盾、原子建立失败均按既有`工程异常终止()`日志、弹窗、终止，不能变成业务不符合/无动作概念/空规格让执行继续。动作前故障零业务执行；动作后故障保留实际事实，不重跑真实动作。

默认实际项目Debug/x64统一Build、链接通过，未运行测试。获明确测试后覆盖：登记零概念；普通首次动作有C；第二执行复用C但实例来源不同；副本M解析源M；独立抽象M不误并；内部已结算与普通结算不误并；七类参数完整；Vt无伪C；类别混合拒绝；动作删除保留共享C；同源重放；工程读取终止；停止等待无悬空provider。不能为本叶新建临时工程。

本叶不实现因果形成、被动窗口、角色映射归纳、动作命名理解、自动复杂方法、现实效果验证算法或全仓异常改写。
