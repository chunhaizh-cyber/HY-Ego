## 1. 目的、对象和边界

本叶不新增本能函数，不改变自我承接需求的逻辑。它把两段已经存在的内部治理代码逻辑预置为可正式读取的客观被动因果定义：自我服务任务特征的正式任务投影，以及任务虚拟存在的完成状态发布。原因是这些变化由治理代码自动产生，筹办需要认识其前提和直接结果；目标是补齐定义提供者，不是假装已经发生。

正常操作是初始化四条定义；没有现实世界动作，没有创建具体 T/X/A，没有消息、观察、状态或动态事实，也不增加任何统计。后续筹办可以调用只读查询获取定义；本叶不实现角色实例绑定、条件求值或递归筹办消费。

正式依据：AGENTS 第1.1节、0050 关于取消服务合同版本的规定、1190 第9.5节先天被动因果许可。旧结算有符号加法族的 DTO、ABI、存储布局、初始化、查询及消费者完全保留。Q 不能限制非负，Q>0 只表明增加，不能写成固定加一。

## 2. 当前事实和复用裁决

- `新_任务类::查询服务任务`读取需求任务对应，按需求父链归根选取服务任务并排除配置需求；不按完成、结算状态过滤。
- `装配.普通应用.cpp::同步服务任务集合特征`当前值相等时直接返回；无当前值或合法数组不同时实际写入并读回。数组总量不代表这次新增量。
- `新_任务类::发布自我任务后继决议`先复核同一任务、最近执行、评估关联、需求准备和评估允许，之后同状态可精确重复；首次发布另要求等待自我决议和执行已评估。不能混入管理线程的缓存重复语义。
- 旧先天因果形状固定为两角色和加法结果，不能把非加法治理写成该族。
- 动作概念正式入口已经支持普通治理 self→self/零参数，以及任务虚拟目标/一个带状态特征的参数。两种本叶动作正好匹配，不修改动态概念规范化。

裁决：扩展因果所有者的并行类型族；新增业务初始化协调服务和不可变动作定义只读口；组合根初始化。不是复制业务方法，不增加私有动作概念入口。

## 4. 条件的闭合签名与含义

角色编号在每个规则内从0连续；条件序号从0连续；参数为概念引用，不能塞具体对象来代替角色。关系概念必须由元数据发放且与种类和签名相符，禁止以名称猜关系。

| 条件 | 角色签名 | 概念参数及精确定义 |
| --- | --- | --- |
| 角色有效 | 一个对应类别角色 | 该角色范围概念；正式节点可读且类别正确 |
| 自我服务投影绑定 | E,P,B | 服务任务FT；自我E、配置服务根P、排除需求B与正式同步绑定一致；还须满足下述完整特征身份与类型合同 |
| 需求父链归根 | P | 需求根概念；P是本次服务根，不是安全根 |
| 排除需求有父 | B,P | 无；B属于P根的父链且有父，不能无排除材料就发表投影 |
| 投影源对应完整 | E,P,B | 服务任务FT；下文完整投影定义成立 |
| 当前引用集合合法 | E | 服务任务FT；F存在、当前值为稳定引用、该引用材料可读且物理类型及内容为U64数组；不额外核验旧成员身份或状态以改变既有分支 |
| 当前集合等于投影 | E,P,B | 服务任务FT；当前合法数组与完整排序投影相等 |
| 投影待写入 | E,P,B | 服务任务FT；F存在且【无当前值 OR 当前为合法U64数组并与投影不同】，非法数组不算此分支 |
| 需求准备非待完善 | T,D | 需求概念；任务正式关联D，正式准备复核结果不是待完善，不扩大为额外业务内容检查 |
| 任务关联需求 | T,D | 需求概念；T正式需求字段为D |
| 任务最近执行 | T,X | X范围；T最近执行为X |
| 执行关联任务 | X,T | 任务概念；X任务字段为T |
| 执行关联评估 | X,A | A范围；X评估字段非空且等于A |
| 评估关联任务 | A,T | 任务概念；A任务字段为T |
| 评估关联执行 | A,X | X范围；A执行字段为X |
| 评估允许完成 | A | 下面七项语义子约束的正式概念，固定次序保存，不是一句无结构标签 |
| 自我接受完成决议 | E,T,X,A | 完成决议范围；同一真实完成决议已由自我接受并进入task发布入口，不创建持久消息对象 |
| 任务状态属于 | T | 任务状态FT、指定域；从T对应Vt正式读取 |
| 执行状态属于 | X | 执行已评估信息域；读X状态，不能伪造为新FT |

`自我服务投影绑定`关系定义必须存储以下有序语义子约束：E的正式特征组恰好持有配置F一次；F的正式特征类型根恰为配置FT；FT的材料物理类型为U64数组、值域为全域、无单位、比较规则为集合判等、不自动聚合；E/P/B与正式同步绑定一致。F身份经既有正式绑定取得，不增加业务对象角色或把F编码写成存在概念。上述子约束为完整合取，不能只存一个“绑定正常”标签。

`投影源对应完整`关系定义必须存储以下有序语义子约束：需求身份唯一；每个需求父链完整；父链无环；根节点没有父需求；根角色为服务时身份必须精确等于配置P；非服务根必须具有正式安全根角色且身份精确等于配置安全根，不能遇到其它根就无声跳过；排除B确属服务根且有父；从完整正式需求任务对应取得全部有T的成员、排除D=B；最终任务成员排序、无重复，不能只读截断片段。安全根身份由现有正式根角色配置读取，不另造安全根。等价集合为 `{ T | 正式需求任务对应(D,T), root(D)=P, D!=B }`，但来源完整性同时约束被排除的安全分支。没有任务状态筛选，没有将一次投影理解为固定新增一项。

`评估允许完成`关系定义必须存储七项有序子约束：目标需求结果已满足；预计但未发生项为空；计划外状态组为空；多渠道验证已通过或不适用；禁止结果验证已通过或不适用；副作用验证已通过；归因验证已通过。子约束用因果元数据子节点保存其闭合类别和必要枚举域，不是新的业务特征，不只保存一句“允许完成”。它们为合取；两处“或不适用”保留明确析取。

这些是定义语义，本叶不运行求值器。工程错误不成为条件失败的正常业务结论。

## 5. 四条规则完整矩阵

投影两规则角色一致：0=E普通存在/自我概念，1=P需求信息/需求概念，2=B需求信息/需求概念。共同条件依次为三次角色有效、自我服务投影绑定(E,P,B)、需求父链归根(P)、排除需求有父(B,P)、投影源对应完整(E,P,B)。

| 规则概念固定槽 | 追加条件 | 唯一结果 |
| --- | --- | --- |
| 0：正式任务投影改变 | 投影待写入(E,P,B) | 结果种类正式服务任务投影；改变；结果E/服务任务FT/正式FT根范围；来源P,B；投影结果关系 |
| 1：正式任务投影保持 | 当前引用集合合法(E)、当前集合等于投影(E,P,B) | 同一投影结果；保持；不新增成员、不算一次状态变化 |

保持分支不依赖UTC或当前场景写入条件；它在代码相等早退处成立。改变分支的当前值可以不存在，不能误加“已有合法当前集合”使首次写入无规则。写入后的实际动态仍由原世界树流程形成，不由初始化制造。

完成两规则角色一致：0=E自我，1=T任务，2=D需求，3=X执行实例，4=A影响评估。共同条件依次为五次角色有效、任务关联需求(T,D)、需求准备非待完善(T,D)、任务最近执行(T,X)、执行关联任务(X,T)、执行关联评估(X,A)、评估关联任务(A,T)、评估关联执行(A,X)、评估允许完成(A)、自我接受完成决议(E,T,X,A)。

| 规则概念固定槽 | 追加条件 | 唯一结果 |
| --- | --- | --- |
| 2：正式完成首次改变 | 任务状态属于(T,等待自我决议域)、执行状态属于(X,已评估域) | 特征值域；改变；结果T所对应Vt/任务状态FT/已完成域；来源T,X,A；状态结果关系 |
| 3：正式完成精确保持 | 任务状态属于(T,已完成域) | 同一任务状态结果；保持；不是新完成、不增加次数 |

完成保持仍要求共同条件全部成立，不能只看状态已完成。但不要求等待自我决议或X已评估，符合task函数先同状态早退再检查首次变更门的顺序。不覆盖manager缓存重复、不覆盖未执行但目标已满足、不覆盖失败或取消决议。

每条定义分别有唯一规则概念；两操作分别有治理定义。触发方式全部被动，四结果均不能用旧加法结果解释。

## 6. 物理持久结构、事务和生命周期

在现有因果根下新建独立关系元数据列表及关系规则列表，字段/节点类型全部由因果owner注册。不得复用旧先天列表、旧种类1解码或旧16条件形状。

元数据头字段：类型、格式1、完整请求九引用（含投影及任务治理两个范围）、两治理源引用、四规则概念引用、19关系概念引用、5角色范围引用、执行状态/决议域及两个结果关系。治理源子节点：类型、操作枚举、所属实际作用范围、完整请求引用。关系概念节点：条件类别、角色类别签名、有序概念参数类别；自我服务投影绑定、投影源对应完整、评估允许完成三个复合关系还保存上述有序子约束节点组。规则概念节点：所属元数据引用及0..3独立规则槽。

规则头字段：类型、格式1、规则概念、治理定义、场景范围、动作概念、被动触发枚举、角色形状数组(序号/类别)、对应范围引用组、条件子节点组、唯一结果子节点、四计数、发生身份引用组。条件子节点字段：类型、格式1、序号、种类、关系概念、角色序号数组、概念参数引用组。结果子节点：类型、格式1、种类、变化、结果角色序号、结果FT、结果范围、来源角色序号数组、结果关系。

格式1只用于解码，不是合同版本。解码检查字段类型、单值唯一、无未知字段、子节点单一归属、向量长度、连续序号、角色引用存在及类别、关系签名、FT/范围归属、独立规则与治理源一致，禁止读取时修补结构。

元数据组及单条规则各用现有L1组发布能力原子挂接；未成功时不出现半条可查询规则。四条分别幂等，启动中途失败会阻止应用进入已装配；已完成元数据/规则保留，重试精确复用。允许已发表且合法的元数据先于动作和规则存在，不删除别的owner或真实数据。发生记录为空、四统计为0只适用于新建；复用已有定义不清空后续真实统计。解除或物理删除不在本叶，所有节点保留原有因果所有权，不把业务对象搬入因果树。

## 7. 正式动作提供者、只读和锁序

`海中鱼巣/领域/动作概念.只读投影合同.h`新增窄接口，不改已有接口含义：

```cpp

public:
    virtual ~关系治理动作只读提供者()=default;
    virtual std::optional<动作概念定义> 读取关系治理动作定义(
        稳定编码 治理定义) const=0;
};
```

`动作方法投影服务`原构造函数尾追加 `const 关系治理动作只读提供者* = nullptr` 并保存借用指针；旧调用兼容。`读取动作方法投影`先读新不可变目录；命中严格核验请求自我概念、FT、目标形状及虚拟标志，再返回正式定义，不命中才走原任务/方法路径。命中却损坏抛错，不能fallback。`核验普通治理动作定义`命中目录时全定义比较，不命中保留旧结算核验；不得回调新因果或全量动态核验。

新增 `业务/内部治理.先天因果初始化服务.h/.cpp`，类实现上述窄接口，持有 `新_因果类&`、`新_动态类&`、`概念_存在类&`、`概念_特征类&` 借用，公有签名：

私有不外溢：`构造动作目录(const 新关系先天元数据&)->std::vector<动作概念定义>`、`构造规则(const 新关系先天元数据&,const std::vector<稳定编码>&)->std::vector<新关系先天因果定义>`、`核验初始化读回(const 内部治理先天初始化回执&)->void`。初始化限组合根单线程调用。目录使用 `std::atomic<std::shared_ptr<const std::vector<动作概念定义>>>`，读口只load和按正式源身份查找，绝不取得因果/动态/任务/概念锁，也不ensure。目录发表后不可修改已有源定义；同义重初始化复用。

投影动作：能力类别内部治理、治理源1、无抽象方法、自我概念执行主体、自我概念目标、服务任务FT、零参数。完成动作：治理源2、自我概念主体、任务虚拟目标、任务状态FT、唯一参数角色为元数据的任务范围角色节点，参数FT为任务状态。不生成方法头。正式动作C一律通过 `新_动态类::确保动作定义概念`，不能直接在因果私有树造C。

## 8. 组合根装配顺序

新服务作为普通应用实现成员，声明在动作投影服务之前，借用依赖先构造、服务后析构，保证动态回调使用期间存在。将只读提供者传入动作投影构造。

初始化调用放在自我/概念/根、任务治理场景、服务任务FT和同步绑定及取得合同、需求运行提供者均装配之后，应用标记已装配和线程启动之前。材料使用现有正式自我概念、先天需求任务概念、服务任务FT、任务状态FT、等待及完成子域。场景范围必须分别正式读取：投影用self真实所属场景的专属场景概念，完成用内部治理根正式场景概念；不得任取一个scope，也不得造泛全域。相同范围复用类型根，严格子域才新建。不得传本次具体任务编码冒充范围。

任务治理范围的精确语义为“由正式内部治理根概念所锚定的治理场景树范围”，包含各任务独立治理场景；实际组织归属沿既有场景父链判断。不能假定根专属场景概念自然是所有子场景概念的上位概念，也不能把定义scope当成某次变化已发生在哪个场景的证据。

过程为：元数据确保→不可变动作目录发表→两个动作C正式确保→四规则确保→四规则/两动作完整读回→返回回执。异常走现有工程诊断并阻止装配成功，不能返回“已初始化”或将失败装成无可用业务结果。工程写后失败锁存、UTC读取失败、材料保存失败及所属场景读取/写后核验失败属于工程边界，不包装成可筹办业务条件或规则正常否定结果。只读正式查询可按结果FT和可选结果种类筛选，返回完整定义；没有运行实例时照样能读取，但不能声称条件已满足。
