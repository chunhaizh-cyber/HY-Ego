## 3. 唯一事实权威及特征定义

新增正式特征类型名称“外设对话框输出队列”。由原外设初始化通过既有特征概念及名称owner建立/精确复用，合法定义为：材料`U64数组`、全材料域、比较`完整材料精确`、聚合`完整材料精确集合`、无单位。顺序即数组顺序；重复消息引用、零引用、其它窗口消息及非输出消息均非法。**禁止用`消息集合身份判等`，禁止排序或去重后当作队列。** 同样内容的两次提交可有两个不同输出消息身份。

每个正式窗口有且只有一个输出队列F，初值为空有序数组，并按既有窗口初始化形成初始状态。现`新外设对话框定位`追加`输出队列特征`；`读取窗口定位`、首次建立和已有窗口补齐均核对唯一归属。新增空F不伪造实际入列。

沿原`消息根`建立不可变输出消息，复用现十字段及UTF8正文材料，`新外设消息方向`增加`输出=3`，旧1/2值不变。消息来源键为`公开宿主会话＋对话框标识＋方向＋提交序号`，同键异内容是工程错误。输出与实际发送是两个事实节点，使用同会话/对话框/提交序号且方向分别3/2建立明确来源对应，不按时间猜测。实际发送记录不得倒推修改原输出记录。

root现无公开消息物理删除入口；输出记录与正文沿同root生命周期持有，F当前项移除不删除消息。队列材料引用通过原消息保护字段保护成员；既有F历史/S引用保留旧准确材料。禁止新建独立队列历史账。跨进程恢复仍未由现宿主/外设生命周期支持，本叶不承诺重启重发。

## 4. 外设owner公开合同

所有定义放`业务/新_外设世界树类.h/.cpp`。不得把宿主状态码塞入领域F。

```cpp

    新外设输出队列状态 状态;

新外设输出队列结果 输出入列(const 新外设输出入列请求&) noexcept;
```

成功入列/复用/领取/移除必须返回完整消息；清空仅返回状态，不伪造单个消息。`不在队列`允许原输出记录仍存在；此时不再入列、不创建新身份。`来源不存在`是原来源键未建立。读取完整消息组按F序保留；合法空队列返回`已读取+空组`，取空队首返回`队列为空`。结构损坏、分配/时钟/提交失败沿现工程异常终止，不转换为空队列、对方拒绝或需求失败。F/S/D由原owner保存，本叶回执不虚构尚无公开返回的变化对象。所有成功返回载荷涉及的字符串/数组分配在实际F改变之前准备，改变后仅无抛出移动或填写稳定编码；读回失败为工程故障，不把已发生改变报成普通未入列。

### 4.1 入列身份与重试

在`外设互斥`内验证定位、序号、UTF8及原消息root。已有同键消息必须逐项匹配目标、正文；仍在F则`已复用`，已被领取/取消则`不在队列`且返回既有消息定位供宿主收束，绝不自动再次发送。宿主不对同一正式调用分配第二提交序号重试。

首次先保存/复用UTF8材料，以既有基础原子追加发布完整十字段输出记录及消息root持有引用，再构造队列新准确材料（旧顺序末尾追加），调用原普通特征更新并形成S/D。**这是两阶段，不是消息与F联合原子发布。** 第一阶段完整记录可读但尚未待发，不暴露半字段记录；第二阶段成功并读回后才能返回已入列。第二阶段失败保留已建立消息身份并工程终止，不报成功、不删除事实、不重发。若同来源记录已存在但未入F，在当前生产会话中宿主已有取消/领取状态则不得重入；只有尚未完成本次首次发布的同调用内部重试可以完成第二阶段，不能以任意外部重复调用猜测补发。

### 4.2 有序材料更新：复用普通特征链，不扩特征ABI

现`准备顶层引用集合更新`只支持需求/存在/消息集合专用比较规则，不支持完整材料精确数组；不得把队列传入该入口。采用原`更新窗口特征并形成动态`普通值更新路径，将新队列F加入其允许特征名单。由外设互斥保证所有队列写入单owner串行，不对外开放通用数组修改作为队列操作。

新私有helper`读取输出队列成员(定位)`直接完整读取F的U64数组，保持顺序，逐项通过`读取正式消息`核验方向3、窗口/场景/公开会话/对话框、非零且无重复。不能调用会排序的`读取消息成员`。消息root永久持有及正文引用复用原生命周期；队列材料增加原消息保护字段引用，先核验完整成员再发布引用保护，不新建成员owner。

出列、取消和清空只产生保序新材料，原普通特征更新形成当前值/历史/S/D；其返回成功后fresh读回F及正式消息才返回队列操作成功。准确值相同不生成新状态/动态。时间沿既有`当前强时间`与窗口更新规则；时钟或结构不满足工程保障时终止，不转换为队列业务失败，不伪造时间。

## 5. 宿主端口与真实生产装配

放`界面/宿主.网页对话.h`，使用值式DTO，不泄漏world对象：

```cpp
enum class 网页输出队列状态 : std::uint8_t {
```

四函数缺任一则宿主启动前返回现`网页对话宿主状态::内部错误`，不回退私有vector。扩展当前四参数`运行本地网页对话宿主`为五参数，最后参数为`const 网页输出队列回调组&`；旧重载保留同样拒绝且零启动，不生成默认队列。所有实际生产调用同步迁移。回调异常只能进入宿主工程终止边界。

装配新增`取得普通应用网页输出队列回调() -> 网页输出队列回调组`，在上下文锁内只取得一次world引用并生成闭包。闭包直接调用同world的定位和第4节接口，**不得再次取得上下文锁**。`启动.应用程序.cpp`在进入宿主前取得回调组并传入。上下文为现unique_ptr，不改shared_ptr；运行宿主期间上下文不销毁，宿主返回且所有调用/写出收口后才按原应用停止顺序析构。没有回调跨此寿命缓存。

网页确认页面、输入和实际发送事实保持其既有回调职责。新增队列回调不能再次调用宿主或连接runtime；新增输出消息不经过旧`更新发送`。实际完整发送仍经现发送完成回调形成方向2消息，正文/目标/序号必须与已领取输出消息一致。

## 6. 单权威调度与锁顺序

宿主新增`队列操作互斥`，只串行入列、领取、取消、停止接纳/清空及出站占用的条件转移。统一顺序为：队列操作锁→短暂共享状态锁→释放共享锁→world回调（外设锁）→短暂共享锁收口。任何world回调期间不持宿主共享锁；world不调用宿主；socket写出不持队列操作锁。应用上下文可能在外层，但回调不取它，不能形成上下文→宿主→上下文回路。

宿主技术索引每条仅保留提交目标/序号、正式消息编码、`网页定向发送结果`；正文由正式消息读取/领取返回，不保留可变私有第二正文权威。历史已发送页面显示副本仍是既有投影。索引不是待发列表；GET不能依据索引枚举队首。`正在写出`只表示传输现场，不另建立世界业务状态特征。

### 6.1 提交

1. 队列操作锁内核验会话、页面、停止、占用和正文。宿主当前单条协议字节上限不在本叶改变，不把它上升为语言能力。
2. 共享锁内先预分配技术索引项与可返回载荷，包括容器reserve/节点和字符串所需容量，冻结序号；索引尚未对外可用。释放共享锁调用正式入列。world成功后的索引收口只允许noexcept移动、稳定编码和标量改写，不再插入可分配容器或复制正文。
3. 验证回执目标、序号、正文、正式消息编码完全一致；共享锁内将索引置`已排队`并推进序号，返回已排队。提交成功的入列点是world F实际更新，不是消息记录先建立或索引更新。
4. world已发布后工程故障终止，保留正式消息和F，不重新提交。校验失败在world写前才返回现输入/会话/页面/占用拒绝状态。

### 6.2 GET/outbound领取及发送

队列操作锁内先核验页面；若该页技术索引已有正在写出项，返回204，不领取第二项，保持同窗口发送顺序。调用world领取队首；领取在world锁内从F移除并返回不可变消息，代表进入传输现场而非发送成功。再按其序号找到唯一已排队索引并置正在写出。索引缺失或内容不同为工程故障，不把正式队首丢弃后继续。

释放全部队列锁后沿原HTTP写出。完整写出先调用既有发送完成事实回调，再置已完整写出并追加显示投影；写出未完成置技术失败，不生成发送事实，也不自动重新入列，避免部分发送导致重复。无论写出结果如何，先前入列事实仍成立。后续新调用可重新提出内容，但不是本叶自动重放。

### 6.3 取消、停止与隔离

取消只对`已排队`索引调用world按来源移除；成功后置已取消。索引已排队而world称不在队列是工程不一致，不伪装取消成功。已领取/正在写出的项不强制取消socket，也不重入F；返回当前技术状态。已取消重复取消只读返回，不再修改F。查询提交、占用检查及释放与领取使用同队列操作锁，不能读到入列回调尚未完成的技术索引占位或在回调期间切换占用。

停止先在队列操作锁内关接纳，取得全部本会话已登记页面值式清单，逐页world清空F，再将对应已排队索引置已取消。清空不删除正式消息历史。不以新会话重用旧队列；公开会话＋页面ID完全匹配，页面reload新ID创建新窗口/F，不搬迁旧项。正在写出项照原路径收口，宿主析构前不得残留未收口写出；停止不清除真实发送事实。停止函数拆为锁内状态计算与锁外回调，严禁现`停止接纳提交`在共享锁内触发world。

### 6.4 同步请求停机与分配异常的精确边界

现宿主是单线程accept→处理请求同步循环，客户端收/发超时均为2秒，没有HTTP工作线程。本叶不增加线程/join框架：正常停止只在当前请求（含发送事实回调和技术状态收口）结束后停止接纳、清空待发F、退出循环。客户端socket由当前请求租约先释放，监听socket随后随函数租约关闭；不从另一线程强行关闭正在写出socket。若提交线程先观察停止标志，可先关闭接纳和清空未领取项，但不得删除正在写出索引；同步请求继续收口。

`网页对话会话租约`析构及浏览器启动失败、服务会话失败、select/accept失败等所有已开始会话的提前return统一执行同一停止清空函数。租约存活期间借用完整四回调，回调寿命覆盖析构；停止幂等。析构不持共享锁进入world回调，私有“已持队列锁”清空helper避免递归锁。宿主返回前清空回调借用；之后启动层才调用治理线程停止/回收，不能持队列锁、宿主共享锁或上下文锁等待线程结束。

分配边界逐项固定：提交的索引/正文请求及返回载荷在world入列前分配；world领取在F改变前构造完整返回消息，host只无抛出移动领取载荷及改既有索引状态；world取消先准备完整消息回执再删F引用，host只改状态；停止在任何world清空前预分配完整目标清单，逐页清空后只改现索引枚举。JSON编码与页面显示投影的分配仍分别发生在领取后及真实发送后，如失败进入工程终止、保留已出列/已发送事实，不返回普通空队列或重发；这不是承诺所有I/O后分配都能移到事前。旧显示消息不是发送权威，追加失败不能撤销真实发送记录。

## 7. 引用与迁移

新增方向3解码必须同步所有原方向switch：现接收/发送查询仍只允许1/2；新队列查询只接受3，不能把未知方向落入发送else。旧消息十字段保持原编码布局及1/2含义；旧root记录原位可读。定位新增队列F由原窗口补齐，不改旧发送/接收F。

源码更新需要重启应用，无热替换运行期宿主vector迁移。旧运行期私有待发项不存在持久恢复合同，不猜测恢复、不重放。修改后新会话开始时要求对应新窗口队列空；发现已有来源不一致先工程报告，不清理未知历史。

输出提供者首叶不造A，本能后继必须在正常任务调用中记录真实A并以本次正式入列回执关联实际变化；不能把本叶已经发生的任意入列事后归给某个本能。
