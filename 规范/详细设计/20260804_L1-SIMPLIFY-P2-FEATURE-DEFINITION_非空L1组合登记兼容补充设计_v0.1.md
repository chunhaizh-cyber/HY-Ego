# L1-SIMPLIFY-P2 非空 L1 组合登记兼容补充设计 v0.1

更新时间：2026-08-04

## 1. 适用范围

本补充只修订 `L1-SIMPLIFY-P2-FEATURE-DEFINITION v0.1` 的 `L1特征定义服务::建立登记` 前置条件，供 P3 初始场景实例叶在同一运行期 L1 上按顺序消费。P2 的公开 DTO、四个公开函数签名、私有幂等域、四节点写集形状和读回字段均不变。

## 2. 组合登记合同

世界登记服务先在空 L1 上成功发布世界根和初始场景；随后 P2 登记允许在同一 L1 的非空当前状态上追加自身四节点。P2 登记首次调用必须满足：

1. P2 服务实例尚未保存登记；
2. `读取完整快照()` 成功，当前事实代次为非零；
3. 请求 `期望事实代次` 精确等于该快照代次；
4. 当前快照可被完整校验，不能因世界事实存在而拒绝；
5. 只提交 P2 固定四节点，不能修改、退出或复用世界登记/场景事实。

期望代次不匹配返回 `事实代次漂移`，快照内部矛盾返回 `内部不一致`，其它入口合同错误返回 `入口拒绝`；均零写入。P2 服务已有登记时保持原同义幂等读回、异义幂等冲突，不重新扫描或追加节点。

## 3. 顺序与验证

运行期初始化顺序固定为：

```text
世界登记::建立空世界
-> 初始场景::创建初始场景
-> P2::建立登记 / 建立I64特征定义
-> P3::建立登记 / 建立初始场景I64实例特征
```

P2 专项自检增加一个已发布世界/初始场景非空快照上的首次登记成功、精确代次追加、独立四节点读回和重复/冲突矩阵；不得把空基座作为唯一成功夹具。P2 数据头及公开结果字段不变。

## 4. 边界

本补充不开放其它宿主、值换代、批次、比较、状态动态、恢复、旧特征体系或生产初始化，也不改变 P2 之外的 L1 写入者合同。
