# RUNTIME-GOVERNANCE-TASK-PLANNING-ROUND-AUTHORITY 任务统一筹办轮次账与当前关系详细设计 v0.1

日期：2026-08-23
版本：v0.1

## 1. 裁决结论

本设计撤回把“任务子目标回流后继筹办准备”直接作为下一代码叶的原判断。真正更早的结构叶是 task owner 的统一筹办轮次权威；但当前仓库同时存在必须保留的 legacy 生产路径：

1. `17edb9d9` 已发布 `L2任务初次筹办准备记录事实`，它是统一 population 的唯一轮次 1 锚点；
2. 该初次筹办 provider 当前只有治理专项测试调用，尚未进入生产装配；
3. 既有 `任务目标未达成重筹办触发提供者` 已由`任务管理线程`和`任务结果生产运行包`接线，并按 `实例.筹办轮次 + 1` 形成 legacy 下一轮工作包；
4. 因而不能假定全部生产任务已经有首次记录，也不能让缺统一权威的任务直接停止现有重筹办；
5. 同时也不能把缺权威当轮次 1、顺手迁移或让同一任务在 legacy 与统一轮次之间来回 fallback。

本叶固定建立两个严格互斥的 population：

```text
统一 population
= 存在版本化任务筹办轮次权威登记记录
+ 存在唯一当前筹办准备端点关系
+ 轮次 1 直接引用既有首次记录
+ 轮次 2..N 使用不可变后继准备记录
+ 所有后继只走统一 CAS，永不回退 legacy

legacy population
= 不存在任务筹办轮次权威登记记录
+ 不存在统一后继记录和统一当前关系
+ 仅既有实际结果未达成入口保留原实例轮次路径
+ 禁止创建统一记录或当前关系
```

这不是失败 fallback，而是 task owner 在同 G 下按显式权威登记记录存在性和版本作出的强类型分区。任务子目标回流未来只接受统一 population；legacy 固定返回具名`轮次权威待迁移`并零变化。

显式迁移 provider、初次筹办生产接线和 legacy 退役是后继独立目标，本叶不实现。

## 2. 目标与完成条件

目标：由 `L2任务结构服务` 建立显式、版本化、可历史读回的统一筹办轮次权威，并让既有实际结果未达成入口在同一公开入口内按强类型分区执行：统一任务原子推进 N → N+1，legacy 任务保持当前已发布事务和工作包语义。

完成必须同时成立：

1. 不复制、包装或重建第二份轮次 1；统一链直接以现有首次记录为锚点；
2. 新的初次筹办融合事务同 G1 创建权威登记、轮次 1 当前关系、任务和首次记录；
3. 统一当前读取只信任版本化权威登记和显式当前关系，不以关系缺失推断轮次；
4. 轮次 2 及以后由不可变后继记录承载，引用权威登记、首次锚点和直接前驱；
5. 实际结果未达成统一分支在原第二段 task-owner 原子事务内创建 N+1、换代当前关系并发布正式治理状态；
6. 实际结果未达成 legacy 分支维持原事务和 `实例.筹办轮次 + 1` 工作包，只能在明确无权威登记时进入，且零统一写；
7. 统一任务请求 legacy 形状、legacy 任务请求统一形状均拒绝，不跨分区重试；
8. 同一正式触发最多产生一份统一后继记录；同键同义恢复首次结果，同键异义冲突；
9. 并发下同一任务不能一边建立统一权威一边完成 legacy 推进；
10. 任务子目标回流、显式迁移和初次筹办生产接线均保持未实现，不在完成声明中冒充接线。

## 3. 明确排除项

- 不实现任务子目标回流 consumer、回流记录扫描或完整父需求回流编排；
- 不新增 legacy → 统一的迁移 provider，不回填任何旧轮次；
- 不把初次筹办 provider 接入线程或运行包；
- 不清退 legacy 分支，不改变 legacy 实际结果工作包字段和成功语义；
- 不执行筹办，不取得筹办执行权，不召回方法，不创建路径、实例、冻结或实际结果；
- 不进入结算、结果共享 / 竞争、分配优先级、价值、预算或归因；
- 不以日志、消息、工作包、调用来源、任务编码或记录创建时间划分 population；
- 不把源码存在、自检通过或关系建立升级为生产业务已闭环。

## 5. 强类型 population 分区

### 5.1 权威登记记录

新增：

```cpp
struct L2任务筹办轮次权威记录身份 final {
    稳定编码 值;
    explicit L2任务筹办轮次权威记录身份(稳定编码 编码 = {}) noexcept;
};

inline constexpr std::uint32_t L2任务筹办轮次权威规则版本 = 1;

struct L2任务筹办轮次权威记录事实 final {
    L2任务筹办轮次权威记录身份 身份;
    L2任务身份 任务;
    L2任务虚拟存在身份 任务虚拟存在;
    L2需求列表项身份 需求列表项;
    L2任务初次筹办准备记录身份 首次准备记录;
    std::uint32_t 权威规则版本 = 0;
    std::uint64_t 建立事实代次 = 0;
    L2生命周期 生命周期;
};
```

每个统一任务恰有一份不可变权威登记。它不是轮次 1 的第二记录，只声明该任务采用哪个轮次规则版本，并引用既有首次记录为唯一锚点。

### 5.2 分区判定

task owner 在同一 G 读取任务、按任务反查权威登记、统一当前关系和统一后继记录：

| 形状 | 分区结果 |
| --- | --- |
| 恰一完整权威登记，版本 = 1，恰一合法当前关系 | `统一轮次权威` |
| 0 权威登记、0 统一当前关系、0 统一后继记录 | `遗留实例轮次` |
| 其它任意组合 | `内部不一致` |

禁止依据首次记录是否存在、记录 G、稳定编码区间、调用方类型或入口来源猜分区。legacy 任务可以有或没有旧首次记录；只要没有显式权威登记，它就不是统一任务。

### 5.3 永不回退

任务一旦有权威登记：

- 所有新筹办轮次只能使用版本 1 当前关系和 CAS；
- 任何 legacy 形状请求固定`引用冲突`，零 legacy 写；
- 当前关系缺失、版本未知、链断或后继记录复义固定`内部不一致`，不得回退实例轮次；
- 权威登记和后继记录永不退出；只有当前关系换代。

## 6. 唯一轮次链

### 6.1 轮次 1

统一链的第一个轮次节点就是现有 `L2任务初次筹办准备记录事实`。禁止新增“统一轮次记录 1”、桥接轮次 1 或复制首次记录字段。

显式当前关系：

```text
任务 --任务当前筹办准备端点--> 首次准备记录或后继准备记录
```

关系角色固定为 1，轮次从目标记录读取，不把 `uint64_t` 写入有符号角色字段。

### 6.2 后继记录

```cpp
struct L2任务后继筹办准备记录身份 final;

enum class L2任务后继筹办触发类型 : std::uint8_t {
    实际结果未达成 = 1,
    子目标回流 = 2 // 仅冻结未来兼容值，本叶无该生产者
};

struct L2任务后继筹办准备记录事实 final {
    L2任务后继筹办准备记录身份 身份;
    L2任务筹办轮次权威记录身份 轮次权威;
    L2任务身份 任务;
    L2任务虚拟存在身份 任务虚拟存在;
    L2需求列表项身份 需求列表项;
    L2任务初次筹办准备记录身份 首次准备记录;
    std::optional<L2任务后继筹办准备记录身份> 前一后继准备记录;
    L2任务后继筹办触发类型 触发类型;
    稳定编码 触发事实;
    std::uint64_t 触发请求身份 = 0;
    std::uint64_t 运行代次 = 0;
    L2结构幂等身份 触发业务幂等身份;
    std::uint64_t 前一筹办轮次 = 0;
    std::uint64_t 新筹办轮次 = 0;
    std::uint64_t 来源共同事实截止 = 0;
    std::uint64_t 准备发布事实代次 = 0;
    L2结构幂等身份 准备幂等身份;
    L2生命周期 生命周期;
};
```

完整性：

```text
权威登记版本 = 1
新筹办轮次 = 前一筹办轮次 + 1 >= 2
发布 G > 来源 G
轮次 2：前一后继为空，当前前驱为首次记录
轮次 >2：前一后继必有且恰为 N 记录
记录、权威、任务、虚拟存在、列表项、首次锚点全同源
```

后继记录永久保留。同一正式`触发事实`在该任务全部后继历史中最多一份；换准备幂等身份不得形成 N+2，固定返回`触发已消费`和既有记录身份。

### 6.3 实际结果专用引用

统一实际结果未达成记录的`触发事实`固定为旧任务实际结果身份；同一实际结果不得因换首态键、迁移键或请求身份重复推进。记录另以关系引用正式待重筹办状态、旧路径、旧实例和目标裁决证据。`触发业务幂等身份`保存原 `任务重筹办意图::意图幂等键`，`准备幂等身份`保存 DATA 原子迁移幂等键；二者分账。首次结果工作包的旧实际结果从强类型触发事实恢复，不再另设重复的“后继旧实际结果”关系。

未来子目标回流记录只能引用正式子目标承接记录，旧路径 / 实例 / 结果 / 目标裁决关系必须全空。

## 7. 新初次筹办建立统一权威

扩展 `L2任务结构服务::新增任务与首次初次筹办准备记录` 的同一 G1 写集：

```text
任务 + 虚拟存在 + 既有首次准备记录
+ 版本 1 权威登记记录
+ 权威登记到任务 / 虚拟存在 / 列表项 / 首次记录关系
+ 任务到首次记录的唯一当前关系
```

发布后读回必须证明首次记录仍是唯一轮次 1，权威登记版本 1，当前端点指向该首次记录。

旧幂等结果兼容：若原准备幂等身份命中没有权威登记的旧首次结果，DATA 融合结果按原合同返回旧首次记录 / 任务并标记`遗留实例轮次`，零补写、零冲突；既有 BIZ 初次筹办公开结果不增加分区字段。不得依据记录创建时间区分新旧，也不得把原键重放变成迁移入口。

`L2新增任务与首次初次筹办准备记录结果`增加`轮次分区`及可选`轮次权威`：新首次提交 / 新精确重复必须是统一分区且携带权威；旧首次重放必须是 legacy 分区且权威为空。现有 BIZ 仍只消费原首次记录 / 任务 / 身份来源，其公开 DTO 不变。

本叶不把该 provider 接入生产线程。它只保证以后合法调用该既有入口所新建的任务原子进入统一 population。

## 9. 实际结果未达成双分区适配

### 9.1 单一公开入口、强类型请求形状

保留现有公开 BIZ 入口，不新增第二个实际结果 provider。扩展 `L2提交目标未达成待重筹办迁移请求`：

```cpp
L2任务筹办轮次分区 轮次分区;
std::optional<L2提交统一轮次推进材料> 统一轮次推进;
```

合法联合：

| 分区 | 统一轮次推进材料 |
| --- | --- |
| `统一轮次权威` | 必有，含权威记录、首次记录、期望前一后继、期望 N、准备幂等、触发请求、运行代次、来源 G |
| `遗留实例轮次` | 必须为空 |
| 其它 | 非法 |

DATA 在持有现有 `L2任务结构服务` 互斥体后重新读取同 G 分区。请求形状与权威事实不一致固定`引用冲突`，不得切换分支重试。

### 9.2 统一分支

BIZ 在第一段“执行结果待验证首态”写入前读取统一分区和当前 N，并要求 `实例.筹办轮次 == N`。第二段原 task-owner 原子事务同代：

```text
退出旧当前治理 / 路径 / 实例关系
+ 发布正式待重筹办状态
+ 创建实际结果触发的 N+1 后继准备记录
+ 退出旧当前筹办准备关系
+ 建立指向 N+1 记录的新当前关系
```

全部共享原 owner 锁、同一 G CAS、同一写入幂等身份和同一提交结果。工作包旧 / 新轮次只从后继记录读回；统一分支禁止出现 `实例.筹办轮次 + 1` 的权威计算。

### 9.3 legacy 分支

只有 task owner 在同 G 证明：0 权威登记、0 统一后继、0 统一当前关系，才执行原 `提交目标未达成待重筹办迁移` 写集。该分支：

- 保持原正式状态、路径 / 实例退出、错误和幂等语义；
- 保持原工作包字段及 `旧筹办轮次 = 实例.筹办轮次`、`新筹办轮次 = 实例.筹办轮次 + 1`；
- 不创建权威登记、后继记录或当前关系；
- 只允许现有实际结果未达成入口使用；未来子目标回流不得复用。

这是明确 legacy 合同，不是统一分支失败后的 fallback。

### 9.4 首次结果与未知提交

统一分支同键同完整请求返回同一治理状态、后继记录和工作包。正式触发相同但换幂等身份返回`触发已消费`，不得推进 N+2；该结果只携带既有后继准备记录身份，不携带工作包，也不算成功 / 精确重复。提交结果未知时按准备幂等身份读回本次后继记录，再以记录 G 历史读回专用引用重构工作包；不得取当前最新轮次代替首次结果。

`任务重筹办触发状态`增加`触发已消费`；`任务重筹办触发结果`增加可选`已消费后继准备记录`。合法形状固定：`已形成 / 精确重复`携带工作包且已消费记录为空；`触发已消费`不携带工作包且携带既有记录身份；其它失败两者均空。legacy 分支永不返回已消费记录。

legacy 分支维持现有幂等和读回行为，不新增统一读回副作用。

## 10. 并发、锁序与未来迁移边界

固定锁序：

```text
BIZ 无锁读取 G0 分区与业务材料
-> 第一段 task-owner 调用按现有锁 / G CAS 提交首态
-> 第二段 task-owner 调用取得唯一 L2任务结构服务互斥体
-> 同锁内重读分区、当前端点、治理 / 路径 / 实例关系
-> 单一 owner 写集提交
```

未来迁移 provider 必须复用同一 task-owner 锁和 G CAS，并在提交权威登记前证明没有 legacy 后继推进事实。竞争收口固定：

- 未来迁移先成功：legacy 请求的旧 G 或无权威前提失效，零 legacy 推进；刷新后只能走统一；
- legacy 首态 / 迁移先成功：未来迁移 G 漂移并重新审查，不能越过新治理事实补权威；
- 已有权威登记：任何 legacy 形状永远拒绝；
- 已有 legacy 后继推进：本叶不迁移、不补账，交给未来具名迁移设计。

本叶虽然不实现迁移，也必须以 V 组证明请求分区形状互换时零写拒绝，避免未来出现同任务双写。

## 11. 退役条件

legacy 只能由后继独立目标退役，必须同时具备：

1. 初次筹办 provider 已通过合法 consumer 接入生产新任务创建；
2. 已有任务经具名迁移形成版本化权威，或其 legacy 生命周期已正式闭合；
3. 迁移能从机器事实裁决当前轮次，无法裁决的任务不被回填；
4. 集成验收证明生产入口不再产生无权威新任务；
5. 独立计划删除 legacy 分支并完成回归。

本计划不宣称上述条件已满足。

## 14. 错误边界

| 条件 | 结果 | 统一写 / legacy 写 |
| --- | --- | --- |
| DTO / 分区联合非法 | 入口拒绝 | 0 / 0 |
| 权威版本未知、关系复义或链断 | 内部错误 | 0 / 0 |
| 统一任务携带 legacy 形状 | 引用冲突 | 0 / 0 |
| legacy 任务携带统一形状 | 引用冲突 | 0 / 0 |
| 统一 N、实例轮次或 G 漂移 | 当前性漂移 / 引用冲突 | 0 / 0 |
| 统一 N 为 `UINT64_MAX` | 内部错误 | 0 / 0 |
| 统一同键同义 | 精确重复 | 返回首次结果 |
| 统一同键异义 | 幂等冲突 | 保留首次结果 |
| 同触发换键 | 触发已消费 | 只返回既有记录身份，不返回工作包 |
| legacy 合法请求 | 保持原结果 | 0 / 原写集 |
| 统一提交后读回失败 | 内部错误 | 保留已提交统一事实 |

发布后没有隐式撤销或删除。取消必须由未来显式任务域迁移处理。

## 16. 完成声明边界

未来代码和验证完成后，只能证明：

- 通过既有初次筹办入口新建的任务可原子取得版本 1 统一轮次权威；
