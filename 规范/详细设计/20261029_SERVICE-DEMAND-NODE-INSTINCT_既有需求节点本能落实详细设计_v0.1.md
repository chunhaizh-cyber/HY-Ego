## 1. 当前裁决与本叶边界

修改对象是现实认知场景中服务对象 H 的需求特征 F，而非任务/方法虚拟存在的治理特征。原因是上级方法必须能读取对方的一项明确需求；直接目的为使正式被认知需求 D 内容符合完整需求概念，且 H.F 实际引用同一 D。D 仍属 H，不形成自我需求，不取得自我承接或任务资格。状态、变化动态及概念维护由实际事实的原 owner 完成，不是本函数直接修改目标。

本轮用户已裁决：函数唯一 C++ 参数为方法参数场景；其中明确 H、F、预先建立的 D 及已经取得的材料。D 由筹办预先建立，本函数不得另建 D、派生子需求、生成自我需求或执行语言交互。正常次序为读取/复核、必要材料不足零动作待齐、记录动作、按同一 D 落实、正式读回。完成性是结果核验，不增加旧条件 5。

本叶只实现已取得材料已经由前置子任务直接补齐到同一 D 的合法分支。本函数不重复更新 D。另一组补充材料的输入引用、字段路径、冲突裁决及其与 D 的绑定尚未规定；本叶不添加第 4 参数、不猜取全局当前材料、不调用整份替换接口冒充合并。本文不声称“补充合并分支”或筹办首次建 D 已实现。该界限是当前可交付叶的精确范围，不改变用户给出的最终方向。

## 4. 三个有序引用及结果合同

唯一入口保持 `新_本能函数集::获取服务对象新需求(const 方法参数场景&) noexcept`，不新增业务参数。

| 序号 | 信息类型 | 范围概念 | 绑定与所有权 |
| --- | --- | --- | --- |
| 1 | `新方法参数信息类型::存在` | 配置的人类概念 | H，原存在 owner |
| 2 | `新方法参数信息类型::特征` | 配置的对象需求类型 | H 实际持有且唯一的 F，原特征 owner |
| 3 | `新方法参数信息类型::存在` | `先天信息概念组.需求` | 正式 D，需求 owner；不是普通 E |

E/F 类型枚举及其已有数值不改。第 3 位的范围只用于“需求身份”准入，合法待完善 D 和未知内容可以建立参数场景。`完整被认知需求`只保留为方法头结果概念，不作为第 3 位参数范围或初始必要条件。初始必要条件仍为 H 属人类，初始关系仍为 F 属 H；不得借这个身份条件宣称 D 已完整。

运行材料 `新本能需求材料`改为：`稳定编码 服务对象,需求特征,需求节点`、`新需求治理信息 动作前需求`、`新特征信息 动作前需求特征`、`std::vector<正式直接内容项> 需求内容`、`std::vector<基础联合节点快照> 完整保护`。删除该 DTO 的 `新被认知需求建立请求 请求`与`内容存在`，不把真实 D 另存为永久副本。

发布结果必须带同一 D，且本次结果的 D 等于第 3 参数。现有 `新本能已发布需求结果`保持：D/H/F/结果场景、本次 A、首次发布 A。首次发布 A 取原正式关联，不能用本次 A 覆盖旧关联。D 已含于 F 时不产生第二成员、第二变化或新首次关联。对合法结果的首次关联不可读属于工程不一致，不从成员身份倒造过去动作。

## 5. 通用正式信息参数读取合同（待本叶实现）

声明唯一放在已有 `海中鱼巣/领域/信息内容.数据.h`。它是值类型/纯接口，无需新增 `.cpp`或工程项；增加 `<vector>`，不包含需求私有结构头。

```cpp
enum class 正式信息参数读取状态 : std::uint8_t {
    已读取=1, 信息不存在, 范围未支持, 依赖未就绪, 前提已变化, 资源失败
};
struct 正式信息参数投影 final {
    稳定编码 信息节点, 类别概念;
    std::vector<正式直接内容项> 直接内容组;
};
struct 正式信息参数读取结果 final {
    正式信息参数读取状态 状态=正式信息参数读取状态::范围未支持;
    std::optional<正式信息参数投影> 信息;
    std::vector<基础联合节点快照> 完整保护组;
};
class 正式信息参数读取接口 {
public:
    virtual ~正式信息参数读取接口()=default;
    virtual 正式信息参数读取结果 读取正式信息参数保护(
        稳定编码 信息节点, 稳定编码 范围概念) const noexcept=0;
};
```

首轮唯一现实实现为 `新_需求类`，在其现有头/源中 public override，不新建 registry、映射仓或 provider 服务。仅范围恰等于正式 `先天信息概念组.需求`时支持，必须由概念 owner 的现行正式读取证明该范围身份。其它正式结构概念明确返回 `范围未支持`，不得一概按 D 解析。节点不存在返回 `信息不存在`；节点存在但不是需求时同样不得给成功载荷。合法需求身份由需求 owner 读取和解码，其私有 schema 不交给方法类。

需求 owner 为读取正式根，现构造函数末尾增加显式依赖 `概念_存在类& 存在概念服务`，保存非拥有引用：`新_需求类(新_特征值类&,新_存在类&,新_特征类&,概念_特征类&,概念_二次特征类&,概念_存在类&) noexcept`。唯一实际装配构造点在 `装配.普通应用.cpp` 的 `普通应用上下文`，传入现有 `世界事实.存在概念服务`；不得从全局可变对象补依赖或解析概念私有 schema。其寿命仍由普通应用上下文覆盖需求服务。

reader 对两种执行域都可确认需求根身份；共同字段的值式内容包括主体/执行域/权重/活动及当前已知目标各项，未知保留 `正式内容值状态::当前未知`，值/方向互斥的另一分支为 `不适用`。被认知 D 的内容投影复用本类现有字段投影和直接读取；自我执行 D 只返回其合法共同内容，不伪造对方确认来源。本叶本能另行要求 D 主体等于 H 且执行域为被认知，不能将这种业务资格塞进通用 reader。

范围核验成功只证明正式需求身份及完整读回的当前保护，不证明目标完整、内容确认当前有效或 F 已引用 D。`已读取`必须同时有 N、需求类别概念和非空联合保护；其它状态不携带成功投影。读取失败不得伪装为未知内容；资源失败清空依赖完整性的载荷。领域不一致进入原工程终止链，不新增业务失败。

方法类新增 `bool 装配正式信息参数读取接口(const 正式信息参数读取接口*) noexcept`。非拥有指针，普通装配在需求/概念提供者就绪后、首次登记与参数场景之前注入 `&需求服务`；关闭时停止接纳、等待在途场景释放后清空。重复同指针无变化成功，已装配其它非空指针拒绝；不在方法锁内回调 reader。作用域及寿命与现有装配引用一致，不建立新线程。

`方法参数场景`新增 `正式信息参数读取结果 读取正式信息参数保护(std::uint32_t 参数序号) const noexcept`：按声明/绑定获取 N/C，仅存在信息类型且范围正式时调用；现实使用同一注入 reader，模拟只使用同次模拟 owner 提供的能力。非正式范围返回 `范围未支持`，失效绑定按原参数错误处理，不扫描或猜取另一个 D。场景只保存非拥有只读端口，不能用它更新需求。

方法 owner 所有存在范围的生产读写/恢复校验都必须承认“普通存在范围或正式信息范围”两类；普通 E 仍走原存在 owner，正式范围走本 reader。必须包括参数规格合法性、初始声明定义读取、登记、方法读回、实例化、真实参数场景及模拟参数场景。不得只修改某个 `if` 后在后续 `else` 把 D 当 F；其它正式范围没有实现时明确拒绝/未支持，不因 N 有稳定编码就放行。初始声明仅对普通 H 条件作人类核验，遍历规格时允许正式需求范围，但不增加 D 完整性条件。

重点消费者包括 `新_方法类.cpp` 的 free function `核验通用概念必要声明`：其对全部存在规格的循环必须按范围类别读取正式定义及保护，不能仍调用普通存在定义 reader 拒掉 D；以及 `读取方法执行结构闭包`：其完整闭包的存在范围采集必须保存正式信息结构定义保护。`确保本能方法登记`和方法/参数规格恢复中的 `获取存在概念`假设同步处理。范围声明读取是概念 owner 职责，实例身份读取是本 reader 职责，不把声明 D 实例当作登记前置。

模拟接口最小新增同名只读虚方法，默认返回 `范围未支持`；不转真实 reader。当前模拟没有新需求运行 writer，本叶登记/构造遇到正式信息参数时结构化返回未支持，学习保留此具名能力缺口；不得抛成正常否定样本、写 C/R 或扩大实现整个模拟学习。真实核心不根据模拟用途切换机器语义。

## 6. 正常过程与非成功边界

1. 参数形状必须恰为 H/F/D；通用准入只核类型/范围身份。真实运行 provider 从这三个引用读取，核 F 唯一属于 H、FT 为需求类型，D 主体为 H、执行域为被认知，保留共同保护；不读 TLS 当前任务、固定自我或最新网页内容补业务材料。
2. 读取 D 已知目标、真实理解与内容确认来源。所需字段未齐、仍待完善或确认待取得时返回 `材料待齐`，不建 A、不写 D/F、不形成已完成结果。实际材料读取的工程故障按工程路径中止，不映射为待齐。确认失效走 `需重新确认`，不吞成空结果。
3. 动作前再次读取相同 H/F/D、内容、确认和完整保护。任何会改变实现的变化返回前提变化，零动作。本检查是执行条件复核，不登记额外旧条件 5、不预造长期 C/R。
4. 复核通过后使用外层工厂固定的动作场景/主体/来源，经原世界 owner 建 A；direct K 或任务执行来源的已有绑定规则保持，不把 H 或 D 冒充 self。A 只记录一次；已进入动作的 provider 不重入零动作核心。
5. 本叶不调用 `建立待完善被认知需求`、`建立或取得被认知需求`或`更新被认知需求信息`。读取原 D，若已完整则保留全部字段及认知来源。D 的内容符合性使用指定 D 纯内容判定；不要求其事先挂接 F。
6. F 尚无 D：经既有发布服务、需求/特征/世界 owner，将同一 D 与 A 交给原发布入口，按当前 F 预期保留全部已有成员，不覆盖并发追加。F 已有 D：读回原正式发布关联，直接保留引用，不修改来源、增加命中或伪造变化。
7. 从原 owner 读回 D 内容符合 `完整被认知需求`，H.F 包含同一 D，以及正式发布关联；再核本次 A 与结果身份，才返回 `已按合同返回/已取得`。已发布但当前变化不能仅据过去发布回执判当前完成，保留已发生 A 和可确认 D/F，返回部分/待取得。

D 已齐但 F 未落实不是结果完成；F 已含 D 但内容/确认未完成也不是结果完成。缺字段时不从其它需求拼齐，不修改其它 D，不发子需求。返回 D 是实际材料，不说明现实目标已满足、自我已承接或任务已完成。

## 7. 旧登记与持久材料迁移

固定规格不可原地改写。新稳定登记名为 `builtin.service_object.demand.acquire_node.v1`；在 `新_本能函数管理类.h`增加 `新本能函数登记名_获取服务对象需求节点`。旧 `builtin.service_object.demand.acquire_new.v1`常量保留作迁移识别，停止为旧名注册可执行函数；新名绑定现 C++ 函数。不得将旧 H/F/E 作为 H/F/D 静默执行。

新方法建立结果 新_方法类::退役旧服务对象需求登记(

这是具名生命周期迁移入口，位于现有 `新_方法类.h/.cpp`，不授予参数准入按本能名放行权。它核验旧登记名、普通作用域、本能改变行为、H/F/通用存在 E 三规格、原头/初始必要条件/关系，再完整枚举旧根及同来源派生方法族。仅识别的旧族允许通过原方法启用特征治理入口停用；保留 M、Vm、所有 C/R、执行记录、D/F 和引用。读不到完整族或出现异义声明时工程终止，不猜测、不物理删除、不复制旧配对到新头。旧名未登记是零变化完成；已停用精确重复可复用。中途失败保留已停用部分，恢复后继续同一身份，不重新建旧方法。

运行服务初始化先通过原 `确保本能方法登记`精确建立/复用新 H/F/D 头，随后执行旧族退役；全部读回完成前不发布本服务就绪，也不接纳新动作。新头创建成功而退役失败时保留新头、初始化失败/工程中止；下次精确复用新头并完成剩余退役，不以再次创建补偿。其它名字、其它本能、任务执行冻结及历史函数材料不迁移。已冻结旧规格的任务不得重新解释参数；原支持工厂对旧登记链拒绝，等待原上层重新筹办，本叶不重写旧执行材料。

## 8. 事务、锁与生命周期
