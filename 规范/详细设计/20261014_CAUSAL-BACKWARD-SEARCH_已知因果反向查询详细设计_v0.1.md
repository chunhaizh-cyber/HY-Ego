# CAUSAL-BACKWARD-SEARCH 已知因果反向查询详细设计

日期：2026-10-14；版本：v0.1；基线：`a9503c148b0e706d8a4f53e14c8529cbd848750d`。

用户本轮目标：输入目标结果及可选起点条件，只读追溯自我已知最前端原因；不是客观必然，不执行动作，不自动创建方法/任务/规律。本叶落实4320反向查找的只读部分，按现行current-only及用户裁决取消旧历史截止/业务预算截断，只遍历当前有限已知图并识别环。

## 1. 最小模块与依赖

新增`海中鱼巣/业务/因果.反向查询服务.h/.cpp`，namespace `海中鱼巣`。唯一业务查询类`因果反向查询服务`构造借用只读服务：

```cpp
因果反向查询服务(const 新_因果类&, const 新_特征类&,
    const 概念_特征类&, const 概念_存在类&, const 概念_动态类&,
    const 新_动态类&, const 新_存在类&, const 新_场景类&) noexcept;
反向因果查询结果 查询(const 反向因果查询请求&) const noexcept;
```

构造只保存引用，不初始化、不写事实；依赖比调用长寿。真实起点动作D由借用`新_动态类`读取，不能用`概念_动态类`把实例D当C。当前world事实服务缺少动态概念owner引用，同叶在`新世界事实服务引用`最窄新增`const 概念_动态类& 动态概念服务`，既有getter返回内部正式owner的只读引用；无setter、无新治理入口。调用方可经该事实服务及因果owner创建本业务服务，不新增普通应用长期可写入口。本叶不建立独立根/索引/持久链，唯一工程登记为新h/cpp。

现因果owner缺具体全集，唯一允许下层新增：`std::vector<稳定编码> 查询具体因果() const noexcept`，在owner锁内复用现有匿名`查询全部因果节点()`，仅返回完整具体Q、准确成员角色，编码升序去重。不得由业务扫基础表或把概念Q当具体Q；全集中的结构错误工程终止，不静默跳过。

## 2. 源级请求合同

头中以下结构提供逐字段默认相等，值式材料不入基础数据集：

```cpp

using 反向因果状态约束=std::variant<反向因果准确约束,
    反向因果概念域约束,反向因果直接I64区间约束>;
struct 反向因果状态条件 {

struct 反向因果查询请求 {

```

参与者标识正数且唯一，至少实际E或正式EC之一；同时给出时核验实际E专属C的完整定义符合EC，不仅上位图归属。状态FT解析正式根，准确值保留实际材料，可超概念域准入；概念域必须同FT。直接I64闭区间可表示任意查询目标/起点域，必须下界不大于上界，通过现有直接I64值域比较材料处理，不为了查询建立或修改FC。所有使用的参与者标识须已声明。起点null表示未指定；空集合表示明确没有已给条件。角色绑定只用于概念Q（分支1起，局部role1起），同槽不得有冲突绑定，不修改来源规律。

起点是调用方明确提供的材料；服务不擅自从世界当前值添加起点。动作起点必须引用真实动作D，不把动作C或方法登记当动作已发生。合法输入缺起点不是工程错误；非法字段/失效身份/内部读取异常进入工程诊断，不作为“无路径”。

## 3. 返回图合同

输出有限AND/OR图而非无限路径列表。源规则候选为OR，同一来源分支的全部状态/动态/动作/场景依赖为AND，禁止把不同分支条件交叉组合。

```cpp
enum class 反向因果覆盖 : std::uint8_t { 未指定起点=1, 完整, 部分, 无已知路径 };
enum class 反向因果端类型 : std::uint8_t { 状态=1, 动态, 动作, 场景, 参与者绑定 };
enum class 反向因果未解释原因 : std::uint8_t {
    无更前规则=1, 未绑定递归角色边界, 比较材料尚不支持, 动作参数未确认,
    具体实体待绑定
};
enum class 反向因果参与者键类 : std::uint8_t { 输入符号=1, 实际存在, 规则局部符号 };
struct 反向因果参与者键 {
    反向因果参与者键类 类别;
    std::int64_t 输入标识=0;
    稳定编码 实际存在节点, 规则因果节点;
    std::int64_t 规则分支=0, 局部角色=0;
};
struct 反向因果图角色绑定 {
    std::int64_t 局部角色=0;
    反向因果参与者键 参与者;
};
struct 反向因果图节点 {
    std::size_t 编号=0;
    反向因果端类型 类型=反向因果端类型::状态;

    std::optional<反向因果状态条件> 状态;
    std::optional<稳定编码> 动态概念节点, 动作概念节点, 场景节点;
    std::optional<稳定编码> 待绑定实际存在节点;
    bool 起点已覆盖=false, 完整覆盖=false, 角色尚未实际绑定=false;
    std::optional<反向因果未解释原因> 未解释原因;
};
struct 反向因果图分支 {
    std::size_t 编号=0, 结果节点=0;
    稳定编码 因果节点;
    std::int64_t 来源分支=0;
    bool 概念因果=false;
    std::vector<反向因果图角色绑定> 角色映射;
    std::vector<std::size_t> 全部前提节点;
    bool 完整覆盖=false;
};
struct 反向因果环边 { std::size_t 前提节点=0, 返回节点=0; };
struct 反向因果未绑定角色边界 {
    std::size_t 前提节点=0;
    稳定编码 因果节点;
    std::int64_t 来源分支=0, 局部角色=0;
    std::vector<反向因果图角色绑定> 已有角色映射;
};
struct 反向因果查询结果 {
    反向因果覆盖 覆盖=反向因果覆盖::无已知路径;
    std::size_t 目标节点=0;
    std::vector<反向因果图节点> 节点组;
    std::vector<反向因果图分支> 分支组;

```

节点/分支编号仅调用期技术索引、从1连续，非稳定事实身份。图状态条件中参与者标识只保留输入已声明标识；规则局部符号用节点外层参与者键定位，状态的参与者标识为0，不能把该0当输入身份。动作节点绑定其来源规则完整角色映射，不能仅以相同动作C合并。場景未知节点场景值为空并保留缺口，不假默认。

覆盖完整只表示给定起点材料在已知参考规律图上的条件覆盖，不等于现实结果已发生、动作已授权或路径可执行。未绑定符号方案必须显式标记，不能包装为具体可执行方案。

## 4. 只读快照与候选

查询入口先枚举具体Q/概念Q并完整读回为调用期值式快照。概念已不相容属于当前源材料不能采用，记录对应Q供调用者复核；全集ID读回缺失、结构损坏或比较资源失败是工程故障，不静默drop。概念分支已保存完整源Q/FT/DC/C/R，读取它而不是重新抽象或修改它。具体规则准确结果与条件保持准确，类型根经特征owner解析。

具体及其抽象来源可能同时召回，保留来源种类和Q，不累加统计或当两次证据；完全相同图分支规范化复用，同源编码避免重复展开。不是按名称或概率选择唯一原因，来源四统计/覆盖发生次数不参与搜索资格或排序可信度。没有预算字段、截止/版本/代次，不以固定层数截断有限知识。

查询结束前重新读取本次使用的Q、EC、FC、DC、场景定义及实际读取过的D/E/F内容和用于选择的字段，与初读完整值式内容比较；不读取未使用的当前值填输入，也不因某值没用过而赋其影响。合法内容/关系变更置材料已变化并清空覆盖/图结论，由调用方重发；工程读取失败、损坏、应存在身份消失不包装合法变化或无链。没有全局原子快照，不声称跨owner读回原子；不自动无限重试，不创建历史快照。

## 5. 接边与共享角色绑定

值域比较必须为“后继条件/当前目标域完整包含前驱结果域”。调用`新_特征类::比较特征值域()`（准确或概念域材料）取得1相等或左包含右才完整接边。仅交叠不建立完整支持边，不任取交叠点替代完整结果；记录未覆盖目标即可。相同FT、单位及角色范围须相容，不能跨FT用I64数值相等接边。非I64材料现有比较规则明确不支持时保留未解释条件边界，不据此把已存在参考规则伪称无路径；资源/内部错误与合法不支持分开处理。

具体E键以真实身份规范化，输入两个标识绑定同一E是同一个实体。概念规则的局部角色仅在该规则/分支有效；结果role先绑定当前目标的参与者键，显式角色绑定优先；余下角色生成有限符号键`(Q,分支,局部role)`，不同local role保持不同参与者。每条边保存完整映射且检查全部角色EC的完整FT域包含及不同角色不能映到同一个真实E。不能把局部role1与另一规则role1直接等同，不能按EC相同自动合槽。

memo键包含条件类型/FT/约束、共同场景语境、规范化参与者键，以及规则分支的完整本次角色映射，不能只按Q或Q+分支缓存。固定节点键空间来自请求角色、已有实际E和有限规则局部符号；不为每次递归再造无限新符号。

固定局部符号仅是有限查询抽象，不保证可无限递归实例化同一规则。展开同Q时，若新生成的`(Q,分支,局部role)`会与本次另一个必须不同角色的既有参与者键相同，则停止该候选的该前提展开：记录`未绑定递归角色边界组`及来源Q/分支/角色/已有映射，前提未解释原因设未绑定递归角色边界。不合槽、不记录为真实环、不将该前提覆盖；仍展开其它可唯一对齐候选。显式绑定满足不同角色约束、或同一角色的真实返回循环按正常AND/OR与环处理。输出不得称未绑定递归分支已全展开，不增加无限fresh符号。

动作依赖节点的独立memo键也必须包含动作C、来源Q/分支以及**完整角色映射**（主体、目标、部位及全部参数角色上下文），不能只按动作C或执行主体键合并。输出动作上下文通过引用它的来源图分支`角色映射`完整读回；同动作C在两套参与者映射下保留不同节点。

起点匹配需要同一规范化参与者键，并且起点实际域完全被所需条件域包含。未绑定规则局部符号不能仅凭同EC被任意具体起点覆盖；只有请求显式绑定后才能使用该具体E材料。一个角色的多个AND条件始终共用同一映射，禁止杯子A温度与杯子B颜色拼成同杯子条件。不自动逐条件选择具体E；自动枚举实参替换不在本叶。

具体规则E与目标实际E必须相同；目标仅有符号EC时，具体规则可以形成带明确待绑定实体的参考候选，但不得据此自动将该符号覆盖为具体起点。存在类别匹配读正式C的完整FT域，不调用仅图归属bool替代。

执行期具体实体绑定收口：具体Q匹配仅EC的目标符号时，该分支的完整角色映射始终保存源规律真实E键（包括结果角色），不能把源结果E改成目标符号。另添加独立AND前提节点：类型为参与者绑定，参与者为目标符号键，待绑定实际存在节点为源具体结果E，未解释原因为具体实体待绑定。其memo键包含目标符号与待绑定E，不与状态/动作合并。该节点不被任何起点状态/动态/动作条件覆盖、不展开上游规则、不在固定点传播完整，列入未覆盖和已知最前端。源Q仍作为带真实角色映射的参考分支保留；即使符号起点温度/颜色满足其它条件，实体绑定前提仍阻断完整。调用者明确目标实际E后重新查询，同一真实E走正常路径，不同E不能命中该具体Q。请求的概念规则显式角色绑定不是改写具体Q身份的授权。本修订复用既有AND机制，不增加隐式分支禁用开关。

## 6. 动态、动作与场景前提

条件DC作为AND前提保留；起点DC完整满足时按`判断动态概念包含(所需DC,起点DC)`和同参与者键覆盖。不从DC名称或其中状态自动制造新的因果边。当前规律结果为状态，不能反向产生结果DC的规则时DC停止在已知前端。

已知动作规则必须增加独立动作依赖，保留动作C、执行者/部位/对象映射及参数规格。起点实际动作D只有正式动作C相同且真实主体/对象与本次全部已绑定角色相符才能覆盖；未绑定角色或参数规格无法从动作事实完整证明时保留动作缺口，不把“发生过同名动作”当本分支动作已成立。当前动作D未保存完整实际参数：动作C的Vm参数规格非空时，一律保留`动作参数未确认`依赖，不用规格本身、当前F值、起点条件或方法名称代替当时完整实参；本叶不新增完整实参证据provider。参数规格为空且其它角色条件完整时才可由真实动作D覆盖该依赖。规则节点不自动执行动作、不检查授权后替调用者执行；能力可调用与已发生不是同一材料。

已知场景来源保留为场景语境；请求共同场景给出时，规则场景必须为该场景或其真实子场景，概念场景C须与该场景专属C完整相容。跨子场景只能在请求已给真实共同上层内衔接，不创建上层场景。没有给共同场景时，每条替代分支以首个已知来源场景为符号语境，不跨不兼容场景拼接；即使同场景C也不推定同实际场景，保留场景尚待明确绑定前提，不能称实际起点完整。旧具体来源缺场景同样保留未知前提，不补猜。后续不读E当前迁移位置冒充来源场景历史。

## 7. AND/OR固定点、环与最前端

建立按目标反向可达的有限图，使用工作队列+memo，不以递归栈耗尽当环。一个结果所有候选分支是OR；一个分支全部前提是AND。起点命中节点先置完整，反复传播：全部前提完整则分支完整，任一分支完整则结果完整，直到没有新节点完整。循环不能凭互相依赖自证成立；起点明确给出循环中某条件时，可以正常传播。

用图强连通分量或等价DFS颜色法记录环边，不把环视为客观无原因；环出口可继续追，缺出口或未起点支持的环保留未覆盖。最前端为反向已知图中起点终止、没有更前规则的状态/动态、动作尚未发生/无法确认、场景未知以及闭环未解决边界。结果给出所有替代成因，不强行唯一根因。

目标已被起点直接覆盖为合法零规则完整结果。给起点时，目标固定点完整→完整；否则有候选规则→部分；没有规则且目标未被起点覆盖→无已知路径。未给起点时，有规则返回未指定起点及已知最前端，没有规则返回无已知路径且前端含目标。部分可以起点命中数为0，含义是已知链尚不闭合，不冒充已经匹配部分实参。

## 8. 工程、验证与排除
