# ARCH-L2-FEATURE-STATE-MODULE-ENTITY-OWNER-ABI-CORRECTION L2 特征/状态模块实体所有权 ABI 纠正详细设计 v0.1

日期：2026-08-31

状态：正式详细设计候选；完成创建侧验证、提交和推送后取得正式版本。本文件不授权代码施工。

## 1. 目标、范围与完成条件

本包只纠正当前正式基线中 `L2状态结构服务` 被 `海中鱼巣.领域.服务.L2特征结构` 错误前置声明后产生的命名模块实体第二所有权和 ABI 身份错配，使状态模块继续经特征 owner 的公开窄合同形成首值参与者，并保持依赖方向：

```text
海中鱼巣.领域.服务.L2状态结构
    -> import 海中鱼巣.领域.服务.L2特征结构
海中鱼巣.领域.服务.L2特征结构
    -/-> 海中鱼巣.领域.服务.L2状态结构
```

完成必须同时满足：

1. `L2状态结构服务` 只有模块 `海中鱼巣.领域.服务.L2状态结构` 一个实体所有者；
2. 特征模块内 `class L2状态结构服务;` 与 `friend class L2状态结构服务;` 均归零；
3. 状态模块不再直接访问特征服务私有字段或依赖错误 friend，且不新增反向 import；
4. 既有首值原子业务语义、幂等键、参与者序号、owner、写集、失败映射和发布后读回逐项不变；
5. v145 与 v143 的 Debug/Release x64 仓库外 fresh `Rebuild` 均证明对象与最终链接使用同一模块附着身份；
6. 修复后的后继未解析符号单独记账，不把“第一个 LNK 消失”冒充全仓链接通过。

本包不改变 Gseed、状态、动态、特征或 L1 的机器语义，不实现任何新业务能力。

## 3. 能力复用和物理位置裁决

### 3.1 复用裁决

不新建文件、模块、类、写端口或业务入口。直接扩展既有特征 owner 的最小公开面，并让状态 owner 复用已公开端口 getter：

| 能力 | 裁决 | 原因 |
| --- | --- | --- |
| 形成特征首值参与者写集 | 改变既有成员及其结果类型的可见性 | 算法、owner、幂等、失败和写集已完整存在；只缺合法跨模块消费面 |
| 校验特征首值编码映射 | 改变既有静态成员可见性 | 本地键和映射语义属于特征 owner；搬到状态模块会复制内部规则 |
| 取得特征实例 owner 写端口 | 直接复用 `取得组合发布写入端口()` | 已公开、同一实例、同一端口，不应继续读取私有字段 |
| `L2状态结构服务` 身份 | 删除特征模块错误声明/friend | 唯一所有者已是状态模块 |

知识库的 L2 特征内部函数索引绑定 `614e4a3` / blob `f0b8407...`，早于当前 source blob，且没有本次首值函数的当前用途卡；因此只作为滞后导航，裁决以正式规范、当前源码与真实调用点为准。施工记录必须形成知识变更清单，但执行者不直接修改共享知识库。

## 4. 目标代码变更

### 4.1 特征模块

1. 删除 namespace 顶层错误 `class L2状态结构服务;`；
2. 删除 `friend class L2状态结构服务;`；
3. 将第 6019—6119 行附近的 `首值原子参与者形成结果`、`形成首值原子参与者写集_v1`、`首值编码映射完整_v1` 移入同一类的公开窄区；
4. 函数体、常量、本地键、异常映射、owner、参与者序号和写集顺序零语义修改；
5. 不 import 状态模块，不新建平行声明。

### 4.2 状态模块

在 `形成特征首值与初始状态原子事务_v1` 中只作一次合法入口改接：

```cpp
特征服务_.特征实例写入端口_
```

```cpp
特征服务_.取得组合发布写入端口()
```

其它两个调用保留原名和参数，改由公开窄合同获得访问权。状态模块的 export module、import、构造函数、公开 DTO、事务顺序和读回均不变。

## 5. 非成功、事务、并发与恢复

- 本包不新增事务。首值原子事务仍由状态 owner 组装状态参与者与特征参与者，并经原 L1 跨 owner 端口一次提交。
- 所有入口拒绝、未找到、引用冲突、事实代次漂移、资源失败、内部不一致和已可能发布映射保持当前实现。
- 不新增锁、不改变锁序、不等待、不做 I/O。
- 不改变持久格式、幂等身份、首次写集、恢复或发布后读回；旧数据库/新数据库应只受原业务合同影响。
- 任一函数体或 DTO 为了“顺便整理”发生变化，都超出本包。

## 6. 第二同形前置声明的边界

特征模块还存在 `class L2状态动态原子发布服务;` 与同名 friend。当前源码证明该服务消费多个特征私有 helper，但本轮对象/链接证据尚未证明它是阻断 Gseed 的当前首因；合法收口将涉及多项结果类型和 helper 的独立公开面裁决，不能仅凭同形文本顺手扩大。

因此本包固定为：

- 不删除或改造动态发布服务前置声明/friend；
- 验证时记录其是否在当前首因消失后成为下一具名链接阻断；
- 若成为后继首因，另建最小提供者设计，禁止把本包扩展为“清理全部 friend”。
