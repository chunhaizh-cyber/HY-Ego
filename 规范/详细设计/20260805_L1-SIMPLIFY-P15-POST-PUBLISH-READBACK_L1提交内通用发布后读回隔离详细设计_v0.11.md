## 1. 最小裁决

v0.11 完整替代并禁止施工 v0.10。保留 G0 真实字段、16 文件 / 50 点业务操作身份标签矩阵、首次/同义/异义共享标签、provider 前 `探测幂等`、同锁一次提交、发布后权威读回、失败见证/隔离、结构化执行证据材料和领域 DTO 映射；本版本只补齐“空仓纯 G0 首次写”的合法执行证据模式及各组可为空边界。32 字节执行证据摘要仍是快速索引，但模式标签和计数使合法空组与缺失材料确定性可区分。

`L1写集请求` 是 L1 中性写集 DTO，不等同于 L2 世界业务公共请求。G0 不新增字段、不把 L2 的“世界规则版本”伪装成 L1 字段。G0 只有当前 DTO 已存在且由调用方公开提供的 `合同版本`、`摘要合同版本`、`期望事实代次`、`幂等键`、节点/关系/值/属性槽/退出事实写集。L2 G1—G8 的规则版本留在各自领域请求；provider 的规则/合同版本只进入执行证据摘要和恢复互证，不进入 G0 请求意图摘要。

同一业务操作的首次、同义重复、异义材料和隔离重试继续使用 v0.8 已冻结的唯一共享标签；异义只由实际公开字段差异形成不同请求意图摘要。provider 版本、共同事实截止和写前事实见证只在首次执行证据材料中记录，不进入 G0 请求意图摘要。C01/C02 和其它空仓纯 G0 首次夹具使用显式 `空仓纯G0` 模式；领域 G1—G8 不得使用该模式。

### 1.1 恢复互证的唯一证明对象

恢复不是“两个 32 字节摘要相等”就成功，而是证明同一个不可变首次执行事实同时被幂等账、提交成功审计记录、当前/历史事实和发布后读回描述。恢复候选必须以相同幂等键找到且只找到一个成功发布账；账与审计必须携带逐字段相等的 `首次执行证据材料`，其重新编码摘要等于两条记录的 `首次执行证据摘要`，并且该材料的写前见证、提供者版本组、共同事实截止和规范化写集能与完整快照/历史事实/发布后读回互证。任一只相等的摘要而缺少材料、账审计不一致或事实无法互证，均为 `材料不完整`，不得建立候选。

### 1.2 原始执行材料持久化裁决

原始执行材料必须持久化为强类型值，不保存为不可解释的单一字节串，也不得在恢复时从摘要反推。新增 DTO 位于 `海中鱼巣/核心/L1事实基座.数据.h`。执行证据模式固定为 `空仓纯G0=1`、`事实互证=2`：

```text
L1提供者版本见证 { 稳定编码 提供者身份; U32 合同版本; U32 规则版本; }
L1写前事实见证 { U8 对象种类; 稳定编码 身份; U64 观察事实代次; L1确定性摘要 事实摘要; }
L1执行证据材料 {
  U32 材料版本=1; U32 合同版本=2; U32 摘要合同版本=1;
  U8 执行证据模式; // 1=空仓纯G0, 2=事实互证
  U32 业务操作标签; 写集幂等键 幂等键; U64 共同事实截止代次;
  vector<L1提供者版本见证> 提供者版本组;
  vector<L1写前事实见证> 写前事实见证组;
  L1确定性摘要 规范化写集摘要; L1确定性摘要 材料摘要;
}
```

提供者版本组按提供者稳定身份升序唯一；写前事实见证组按对象种类、稳定身份升序唯一。`空仓纯G0` 模式只允许两组均为空、期望事实代次为0、写集为成功纯 G0、执行前完整快照为空且本点未读取 provider/当前事实；共同截止固定编码为0。`事实互证` 模式要求写前事实见证组非空；provider 版本组可在没有 provider 调用的纯 G0 现有事实替换中为空，但此时写前见证组必须非空；G1—G8 领域操作必须两组均非空。两组的 U64 数量会被编码，空组不是缺失值。

材料规范化编码固定为：材料版本→L1合同版本→摘要合同版本→执行证据模式→业务操作标签→幂等键→共同事实截止→提供者版本组数量及项目（身份、合同版本、规则版本）→写前事实见证组数量及项目（种类、身份、观察代次、事实摘要）→规范化写集摘要；对该编码取现有 `L1确定性摘要` 得到 `材料摘要`，不把摘要本身嵌回材料，避免递归。`首次执行证据摘要` 的完整编码固定为：`HZY-L1ID`→格式1→业务标签→实际执行证据模式→请求意图摘要→G0 写集载荷→发布后读回计划→材料摘要；模式1同样编码模式值1和显式两组数量0，不得按模式2或省略组字段重算。共同截止必须等于每个写前见证观察代次及候选 provider 结果的截止；规范化写集摘要必须等于首次规范化写集按 G0 合同的摘要。

`L1幂等账记录` 和对应 `L1审计记录` 各持一份不可变 `首次执行证据材料` 副本；恢复材料不再另建第三份可变副本，而是通过这两类记录携带完整材料。提交成功首次结果必须两处都有材料；精确重复只返回首次副本且不形成新材料；入口拒绝、异义冲突、provider 未找到前失败和明确未发布尝试不得伪造材料。材料在首次提交成功并完成发布后读回时持久化，生命周期覆盖审计、幂等重复和一次恢复确认；恢复发布后只作为非权威历史证据保留，不改变运行期代次。

## 3. G0—G8 公开字段、版本归属与编码

### 3.1 G0 实际 DTO 与精确编码

当前 `海中鱼巣/核心/L1事实基座.数据.h` 的 `L1写集请求` 精确字段为：

| 顺序 | 字段 | 来源/归属 | 是否进入 G0 请求意图摘要 |
| --- | --- | --- | --- |
| 1 | `合同版本` (U32) | L1 写集公开合同，当前值 2 | 是 |
| 2 | `摘要合同版本` (U32) | L1 幂等摘要合同，当前常量 `L1幂等摘要合同版本=1` | 是 |
| 3 | `期望事实代次` (U64) | 调用方公开写请求 | 是 |
| 4 | `幂等键` (U64) | 调用方公开幂等身份映射 | 是 |
| 5 | 节点/关系/值/属性槽/退出事实 | 调用方形成的强类型中性写集 | 是 |
| — | `请求意图摘要`、`执行证据摘要`、`发布后读回计划` | L1 派生/执行证据材料 | 否，分别按下述规则处理 |

G0 的请求意图摘要编码固定为：

```text
"HZY-L1ID"
+ U32 编码格式版本=1
+ U32 业务操作标签
+ U8 模式=1（请求意图）
+ U32 合同版本
+ U32 摘要合同版本
+ U64 幂等键
+ U64 期望事实代次
+ U64 节点数量 + 节点项目
+ U64 关系数量 + 关系项目
+ U64 值数量 + 值项目
+ U64 属性槽变更数量 + 属性槽项目
+ U64 退出事实数量 + 退出编码
```

节点、关系、值、属性槽项目的内部顺序和引用编码沿用现行 `写写集`；版本字段必须位于幂等键之前，不能从幂等键、期望代次或调用点推导。执行证据摘要复用同一 G0 载荷顺序，但在 `模式=2` 后先追加原始请求意图摘要，再追加上述 G0 载荷，最后追加发布后读回计划；结果摘要和幂等账已经单独保存/编码合同版本与摘要合同版本，必须与 G0 两字段互证。

G0 没有 `规则版本` 字段。不得新增同名字段、把 `规则版本` 解释为 `摘要合同版本`，或用默认值/调用点补造。规则版本只在拥有它的 G1—G8 L2 请求及 provider 执行证据中编码；L1 幂等账保存的摘要合同版本是摘要格式互证字段，不是业务规则版本。当前只支持合同版本 2 与摘要合同版本 1；任一版本不支持都在摘要/探测前入口拒绝并保持零 provider、零提交、零变化，不得静默重算。

### 3.3 执行证据材料与恢复拒绝矩阵

G1—G8 每个首次成功点在 provider 读取完成后，必须把该点拥有的合同/规则版本、同一次读取得到的共同事实截止、写前稳定事实见证和已形成的规范化写集摘要装入 `L1执行证据材料`，并固定为 `事实互证` 模式。提供者版本缺失、版本为零、同一提供者重复、写前见证缺失或排序不稳定均在 L1 提交前返回 `入口拒绝`；材料不能由领域调用序号、默认版本或摘要反推。纯 G0 现有事实替换即使 provider 组为空，也必须使用 `事实互证` 模式并携带非空写前见证，不能改用空仓模式。

恢复入口按幂等键配对一条 `L1幂等账记录` 与其 `提交成功` 审计记录，并按以下顺序拒绝：

| 检查 | 精确条件 | 结果 |
| --- | --- | --- |
| 材料存在 | 两条记录均有材料且字段完整 | 缺失为 `材料不完整` |
| 模式 | 模式1仅限表中五个空仓纯G0首次夹具且代次0/快照空；模式2用于其余成功路径 | 模式错配为 `材料不完整` |
| 版本 | 材料版本、L1合同版本、摘要合同版本均为当前支持值；每个 provider 合同/规则版本非零 | 错版本为 `材料不完整` |
| 空组判定 | 模式1两组必须空；模式2的 G0 现有事实替换允许 provider 组空但见证组非空；G1—G8 两组均非空 | 非法空组或模式1非空组为 `材料不完整` |
| 共同截止 | 材料共同截止等于全部写前见证观察代次、候选事实截止和首次发布前读取截止 | 不一致为 `事实代次漂移` |
| 写前见证 | 种类/身份唯一、稳定排序，事实摘要可由对应快照或历史事实重算 | 缺失或重算不等为 `材料不完整` |
| 规范化写集 | 材料的规范化写集摘要等于幂等账首次规范化写集按 G0 规则重算值；材料摘要等于材料规范化编码重算值 | 不等为 `内部不一致` |
| 双记录 | 幂等账与提交成功审计的材料逐字段相等，首次执行证据摘要按实际执行证据模式完整编码重算相等 | 不一致为 `内部不一致` |
| 事实/读回 | 首次发布代次、编码映射、完整读回和当前/历史事实均互证，发布后失败见证与隔离状态不矛盾 | 不一致为 `内部不一致` |

拒绝结果不创建候选、不推进代次、不清除已有隔离；若已进入候选阶段则撤销候选并保持普通入口关闭。只有上述检查全部成功才允许建立恢复候选；确认恢复后发布新代次并读回，恢复结果携带新事实代次。恢复材料中的错误 provider 证据即使碰巧产生相同 32 字节摘要，也因缺失/不匹配的结构化材料或事实互证而拒绝。

## 5. 探测、首次结果、执行证据与非成功映射

每点先以“幂等域+公开幂等身份、字段组、共享操作标签”形成请求意图摘要，再调用 `L1事实基座服务::探测幂等`。同义返回保存的首次执行证据、首次发布代次、结果摘要和完整读回，provider/提交次数均为 0；异义返回幂等冲突和零业务载荷；已隔离返回隔离拒绝和失败见证；仅未找到允许读取 provider/当前事实。

仅未找到路径读取 provider/当前事实后，先形成完整 `L1执行证据材料`，按 §1.2 固定顺序重算执行证据摘要；材料不完整时不调用 L1 提交。材料、规范化写集和发布后读回计划在同一独占许可内绑定，L1 v2 提交恰一次，并在同锁内做完整发布后读回；提交成功时把材料的不可变副本同时写入幂等账与提交成功审计。成功或精确重复映射保持 v0.8：世界登记→世界登记 DTO，场景→初始场景 DTO，定义→定义 DTO，实例→实例特征 DTO，存在/X01/X02→实际存在 DTO，状态→状态 DTO，比较→比较 DTO，核心/自检→L1结果断言材料。入口拒绝、版本漂移、资源失败、内部不一致和读取未找到按现有 DTO 稳定映射，零部分业务载荷；读回缺字段、重复键、错代次、双摘要不一致、结构化材料缺失或首次结果不一致进入内部不一致和隔离。

恢复只消费幂等账与审计中配对的首次材料，不消费调用方再次提供的 provider 版本，不从摘要逆推原始材料。候选建立前必须完成 §3.3 全部矩阵，并按操作身份重算模式：模式1带任何 provider/见证项目即拒绝，模式2空两组即拒绝，领域 G1—G8 使用模式1即拒绝。候选确认后读回新代次，若发布后读回失败则保留已发布代次和失败见证并隔离，不回写或删除原始执行材料。
