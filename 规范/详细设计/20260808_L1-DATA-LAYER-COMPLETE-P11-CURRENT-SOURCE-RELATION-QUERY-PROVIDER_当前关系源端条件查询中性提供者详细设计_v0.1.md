## 1. 目标与需求来源

本叶只补齐一个由真实第二层生产合同暴露出的第一层中性查询缺口：按“源节点稳定编码 + 关系类型节点稳定编码”读取全部当前关系，并按关系稳定编码严格升序返回完整关系事实。

4200 要求第二层“查询场景完整事实”返回直接子场景和直接存在成员。场景结构关系方向分别固定为 `父场景 -> 子场景` 和 `场景 -> 存在`，因此第二层必须能从已知场景枚举指定关系类型的当前出边。当前第一层只有按稳定编码读取单个关系，以及 P10 已发布的“目标节点 + 关系类型”查询；前者要求调用方预先知道关系编码，后者只能从已知目标反查入边，都不能形成场景出边全集。

旧 P19、P29—P31 以第一层完整快照和全仓扫描形成普通生产读取，已与 4015 v0.5 的职责收缩冲突。完整快照是分离的诊断 / 管理入口，不得成为普通 CRUD 固定成本。本叶不得复用或激活该旧方向。

本叶不是第一层自证，也不实现第二层场景完整事实服务。代码发布只形成待真实消费的中性提供者候选；紧接的后继计划必须建立或修订真正的第二层场景完整事实生产服务并消费本入口，只有该第二层服务经实际运行形成结构化结果和权威读回后，才累计证明本查询被真实覆盖。

## 3. 第一层职责与禁止解释

第一层只负责：

- 校验查询合同版本、源节点编码和关系类型节点编码；
- 在一次仓库共享锁内访问一个源 + 类型索引桶；
- 按桶内稳定编码回读 `当前关系` 权威事实；
- 验证每项仍满足源端和关系类型条件并且仍为当前事实；
- 返回同一读取事实代次和稳定有序的完整中性关系组。

第一层不解释源节点是不是场景、目标节点是不是子场景或实际存在、关系类型是不是直接父或直接成员、角色是否具有业务意义，也不判定单父、无环、成员资格、世界归属或场景完整性。

本叶不新增业务标签、意图、领域结果、执行证据、生产日志判定、独立验收模式或第一层完成结论。

## 4. 公开中性合同

### 4.1 DTO

在 `海中鱼巣/核心/L1中性CRUD.数据.h` 新增：

```cpp
struct L1中性源关系读取请求 final {
    std::uint32_t 合同版本 = L1中性CRUD合同版本;
    稳定编码 源节点;
    稳定编码 关系类型节点;
    friend bool operator==(const L1中性源关系读取请求&,
        const L1中性源关系读取请求&) = default;
};

struct L1中性源关系读取结果 final {
    L1中性读取状态 状态 = L1中性读取状态::入口拒绝;
    std::uint32_t 合同版本 = L1中性CRUD合同版本;
    稳定编码 源节点;
    稳定编码 关系类型节点;
    std::uint64_t 读取事实代次 = 0;
    std::vector<L1中性关系事实> 关系组;
    friend bool operator==(const L1中性源关系读取结果&,
        const L1中性源关系读取结果&) = default;
};
```

既有中性合同模块自动公开该数据头，不修改合同模块，不提升 `L1中性CRUD合同版本`，不改现有目标关系 DTO。

### 4.2 唯一公开入口

在既有 `L1事实基座服务` 新增：

```cpp
L1中性源关系读取结果 读取中性当前源关系组(
    const L1中性源关系读取请求& 请求) const;
```

入口固定为 const 值式查询；不公开仓库、索引、锁、内部句柄或容器引用。

### 4.3 状态合同

1. 合同版本不匹配，或源 / 类型编码为零，返回 `入口拒绝`、代次零、空组；
2. 合法请求零命中返回 `成功`、权威当前事实代次、空组；空仓时代次允许为零；
3. 一项或多项命中都返回 `成功`，每项为完整当前中性关系事实；
4. 关系组按关系稳定编码严格升序且无重复；
5. 结果始终回显调用方源节点和关系类型；任何非成功结果代次为零且关系组为空；
6. 分配异常映射 `资源失败`；索引、权威事实或生命周期矛盾映射 `内部不一致`；
7. 查询不读取完整快照、历史、审计、恢复材料、SQL、旧管理索引或日志。

## 5. 源端派生索引

### 5.1 形状与权威边界

仓库 `状态` 新增：

```text
(源节点稳定编码, 关系类型节点稳定编码)
    -> 按关系稳定编码严格升序、无重复的当前关系稳定编码组
```

实现可使用两级无序映射和有序编码组。索引只存编码，不保存端点、角色、创建代次、退出代次或第二份关系事实；空桶必须删除。源索引、P10 目标索引都不是权威，权威仍只有 `状态.当前关系`。

### 5.2 候选内维护

中性与 legacy 两条提交路径都固定执行：

1. 新关系成功加入 `候选.当前关系` 后，先后把同一关系编码插入源 + 类型桶和目标 + 类型桶；
2. 退出当前关系时，在删除权威关系前，按退出前关系字段分别从源索引和目标索引删除；
3. 任一插入、删除或候选完整性检查失败，都不交换 `状态_`；即使某一索引已在候选内局部变化，也不可被普通读取观察；
4. 节点、值和属性槽变化不直接修改关系索引；
5. 成功仍只通过既有一次状态交换同时发布权威关系和两个派生索引。

插入顺序固定为源索引后目标索引；删除顺序固定为源索引后目标索引。该顺序只约束候选构造，不赋予任一索引权威优先级。

### 5.3 helper 与完整性

在仓库私有区新增与 P10 对称的三个 helper：

```cpp
static bool 插入当前源关系索引(状态& 值, const 关系事实& 事实);
static bool 删除当前源关系索引(状态& 值, const 关系事实& 事实) noexcept;
static bool 派生当前源关系索引(状态& 值);
```

`状态完整` 分别验证源索引和目标索引：

- 每个当前关系在对应索引中恰出现一次；
- 每个索引编码都能在当前关系中找到，索引键和关系字段全等；
- 每桶无零编码、严格升序、无重复；
- 无空桶、悬空编码或额外编码；
- 两个索引各自覆盖全部当前关系，不能用一个索引的通过替代另一个。

既有状态材料转当前状态时，在 `当前关系` 已形成后分别调用两个纯派生 helper。此处只适配新增的进程内派生字段；不得修改恢复材料、恢复入口、状态枚举、持久格式、SQL或恢复测试，也不得把崩溃、重启或跨进程恢复加入本叶完成门禁。

普通源查询不得调用 `状态完整`、任一全量派生 helper 或目标查询；只访问请求对应源桶并回读该桶关系。

## 6. 仓库查询固定流程

仓库内部 `读取中性当前源关系组` 固定按以下顺序：

1. 纯值请求无效时返回入口拒绝；
2. 取得一次既有仓库共享锁；隔离状态返回内部不一致；
3. 查找源节点桶，再查找关系类型桶；任一不存在都返回成功、当前事实代次、空组；
4. 类型桶存在但为空，或当前关系非空而事实代次为零，返回内部不一致；
5. 按桶内编码顺序逐项查 `当前关系`；编码为零、非严格升序、重复、权威关系缺失、编码不等、源端不等、关系类型不等或携带退出代次时，清空临时组并返回内部不一致；
6. 逐项转换为完整 `L1中性关系事实`；
7. 仍在同一共享锁内返回成功、当前事实代次和完整组。

查询不另读首末代次。一次仓库共享锁已经保证索引桶、权威关系和事实代次属于同一状态。后继第二层跨多个第一层调用组合时，仍由第二层负责共同截止和业务完整性。

## 7. 异常、并发与生命周期

1. 公开服务只捕获异常并映射为结构化中性状态，不重试、不回源其它入口；
2. 仓库查询只使用既有共享锁，零新锁、零可变状态、零缓存；
3. 提交候选仍使用既有独占锁和一次交换，读者不会观察到只更新一个索引的候选；
4. 结果完全由调用方拥有，服务不保存请求、关系组或容器引用；
5. 空组是第一层合法成功，不等于场景无成员；业务解释留给后继第二层服务。
