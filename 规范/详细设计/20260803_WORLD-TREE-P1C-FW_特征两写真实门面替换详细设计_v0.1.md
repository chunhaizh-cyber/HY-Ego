# WORLD-TREE-P1C-FW 特征两写真实门面替换详细设计 v0.1

日期：2026-08-03

创建侧当前代码基线：`0371103724e2d6cb7eda79a6060be15d7d22ef54`。

## 1. 选择、范围与正式依赖

本叶不新建类、DTO、公开函数、模块、自检顶层身份或工程项。它只原位替换 P1C-F 的 `发布存在初始特征`、`更新存在已有特征` 两个骨架函数体，并扩充同一 `WORLD-TREE-P1C-F-S01 / 顺序260` 内部矩阵。其它七根保持届时正式行为。

直接依据：0050、4030、4170、4200 v0.9、4201 v0.5；P1C-F v0.1 最终门面 ABI；FEATURE-W-F v0.1 最终 provider ABI；FEATURE-W-DP v0.1 最终底层合同。FEATURE-W-F 固定未实现骨架、FEATURE-W-DP 数据操作/参与者结果或预冻结设计都不能解除真实写门禁。本叶必须等待独立 `WORLD-TREE-FEATURE-W` 真实行为设计、计划和代码结果原位替换 provider 骨架并通过真实初始/换代矩阵。

旧 P1C 大设计、计划和旧六写图不作为直接依据。本叶不直接依赖或调用 FEATURE-W-DP；该底层只由真实 FEATURE-W provider 消费，避免门面越过事实所有者。

## 2. 最小门禁与状态映射

两个根都先对 `请求.项目组` 做无分配顺序扫描：初始根发现任一 `种类 != 初始`，更新根发现任一 `种类 != 换代`，立即返回 `入口拒绝、代次0、持久不适用、目标/关系/读回空、缺项空`，provider调用0。未知枚举值按不匹配处理。空项目组没有不匹配项，交 provider 依据4170裁决，不在门面复制非空门禁。

门禁通过后调用 `特征_.提交世界树特征批次(请求)` 恰一次。状态映射固定为：

| provider `节点直接特征批次提交状态` | 门面 `世界树业务状态` |
| --- | --- |
| 已提交 | 已提交 |
| 幂等读回 | 幂等读回 |
| 入口拒绝 | 入口拒绝 |
| 幂等冲突 | 幂等冲突 |
| 版本漂移 | 版本漂移 |
| 许可拒绝 | 许可拒绝 |
| 资源失败 | 资源失败 |
| 内部不一致 | 内部不一致 |
| 未实现 | 未实现 |
| 未知数值 | 内部不一致 |

provider 结果无论成功与否均保留原 `发布代次` 和 `持久状态`。非成功时目标、旧/新关系和操作读回均为空；仅 provider `内部不一致` 原样保留其 `缺项组`，其它非成功缺项为空。未知数值按门面自发现矛盾收口，保留代次/持久状态，其它载荷和缺项为空。

## 3. 成功读回绑定

`已提交/幂等读回` 必须先通过防御形状组 D01：发布代次非零、provider缺项组为空、读回存在、读回宿主等于请求宿主、读回项目数等于请求项目数。失败返回门面 `内部不一致`，保留provider代次/持久状态，其它载荷和缺项为空。

随后按请求顺序逐项通过共同字段组 D02：

```text
读回.项目组[i].宿主 == 请求.宿主
读回.项目组[i].特征定义 == 请求.项目组[i].特征定义
读回.项目组[i].来源存在 == 请求.项目组[i].来源存在
读回.项目组[i].原始值类型合同身份 == 请求.项目组[i].原始值类型合同身份
读回.项目组[i].原始值类型合同版本 == 请求.项目组[i].原始值类型合同版本
读回.项目组[i].原始值 == 请求.项目组[i].新原始值
读回实例槽、当前值、宿主关系、定义关系、当前值关系均为完整见证
读回原始值记录身份完整，原始值版本、首次发布代次、当前状态发布代次均非零
```

初始根不要求请求携带实例槽；provider 成功读回提供新实例槽。更新根另要求请求四个写前 optional 全部存在、读回实例槽等于请求实例槽、读回前一原始值版本等于请求写前原始值版本、读回当前值不同于写前当前值、读回当前值关系不同于写前当前关系。任一不满足按 D02 返回门面内部不一致，不再调用 provider、查询或快照。

成功统一结果固定为：原provider状态/代次/持久状态；`目标=读回.宿主`；旧关系和新关系均空；`操作读回=世界树写后事实{原世界树特征批次读回}`；缺项空。批次包含多个关系变化，禁止把其中一条塞入统一单值旧/新关系字段。

## 4. 诊断、异常、所有权与调用边

provider 根为 `noexcept`，门面两根保持 `const noexcept`。D01/D02 和未知状态只是设计、自检与源码闭包分支标识，不是日志码、机器字段或对外诊断。门面日志调用边固定0，不 include/import 日志，不捕获后伪装成功；同一因果链最终日志责任保留给 P1D 正式运行期请求入口。

两个函数分别内联种类扫描、状态映射和成功校验，不新增 module-private / 类私有 helper、重载、包装器、坏结果工厂或测试 seam。请求和 provider 结果只在同步栈存续；返回值归调用方。门面不保存请求或结果，不取得仓库、DP、L1提交、许可、事务、锁、SQL、缓存、材料或快照。

## 5. 字段、提供者与事务矩阵

| 根 | provider调用 | 门面事实写 | 逻辑内返回 | 完成 |
| --- | --- | --- | --- | --- |
| 发布初始 | 种类匹配后特征1，否则0 | 0 | 种类拒绝/provider非成功/D01/D02 | 匹配初始批次读回 |
| 更新已有 | 种类匹配后特征1，否则0 | 0 | 种类拒绝/provider非成功/D01/D02 | 匹配换代批次读回 |

| 统一字段 | 唯一来源 |
| --- | --- |
| 状态/代次/持久状态 | provider 原结果；门面门禁使用固定入口拒绝；D01/D02只改状态为内部不一致 |
| 目标 | 匹配的 `读回.宿主` |
| 旧关系/新关系 | 固定空；批次关系留在操作读回各特征事实内 |
| 操作读回 | 原 `世界树特征批次读回` 包装为 `世界树写后事实` |
| 缺项组 | provider内部不一致原样保留；其它非成功和门面自发现矛盾为空 |

事务、幂等、失败撤销、发布未知、身份分配和原许可读回完全属于真实 FEATURE-W。门面调用前后不另开事务；provider 返回后不再写机器事实。

## 6. 真实可达运行验证与防御闭包分账

原 `WORLD-TREE-P1C-F-S01` 只用隔离仓和真实 FEATURE-W provider 运行覆盖：全初始首次成功/幂等、全换代首次成功/幂等、门面混合种类拒绝且provider调用0、provider可真实形成的入口拒绝/幂等冲突/版本漂移/许可拒绝/资源失败/内部不一致、失败零额外发布、SQL不可用不改变内存结果，以及其它七根保持正式行为。不得用 FEATURE-W-F 骨架结果代替真实成功覆盖。

未知枚举、provider未实现、成功零代次/非空缺项/空读回/错宿主/错数量/错顺序/错字段等不能由合规 final provider 主动形成的分支，不伪造运行时覆盖，改用 AST/等价源码闭包证明：九状态及未知值唯一映射；D01先于D02；任一坏形状返回内部不一致、保留provider代次/持久状态、清空全部业务载荷和缺项；日志调用0。完成报告必须分别列出真实入口运行覆盖与不可达防御源码闭包。
