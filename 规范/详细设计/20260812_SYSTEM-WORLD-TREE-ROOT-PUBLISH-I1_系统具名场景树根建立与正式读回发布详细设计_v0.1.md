# SYSTEM-WORLD-TREE-ROOT-PUBLISH-I1 系统具名场景树根建立与正式读回发布详细设计 v0.1

日期：2026-08-12

## 1. 目标与边界

本设计建立世界树路线中最早的 L5 外生产适配叶：普通应用完成 A1 装配后，系统初始化调用方明确选择“为本运行期建立项目现实世界具名场景树”，通过 A1 取得同一个 R1 场景服务，建立或按原请求幂等收敛根，随后经 R1 `读取场景树` 独立读回；只有完整读回成功，才把调用方拥有的值式根材料发布到 `普通应用上下文`，供后继自我初始化消费。

本叶不实现自我初始化，不修改 7130，不建立存在、自我、语素、需求、概念或状态事实，不恢复旧世界登记服务。根权威只存在于 R1 场景 owner 的根标记、树归属和场景事实中。初始化请求、幂等身份、上下文保存值、函数返回和缓存都只是选择、收敛或消费材料，不是第二根事实。

## 4. 公开 DTO 与固定选择

数据头包含 R1 最终 `L2场景结构.数据.h`，不复制其类型。公开合同冻结为：

```cpp
inline constexpr std::uint32_t 系统世界树根初始化合同版本 = 1;
inline constexpr L2结构幂等身份 海中鱼巣现实世界树根建立幂等身份{
    0x5359'5357'5452'0001ULL};

struct 系统世界树根初始化请求 final {
    std::uint32_t 合同版本 = 系统世界树根初始化合同版本;
    L2结构幂等身份 根建立幂等身份 =
        海中鱼巣现实世界树根建立幂等身份;
};

enum class 系统世界树根初始化状态 : std::uint8_t {
    已发布 = 1,
    精确重复 = 2,
    请求无效 = 3,
    已发布选择冲突 = 4,
    树结构登记读取失败 = 5,
    根建立失败 = 6,
    根正式读回失败 = 7,
    根读回不一致 = 8,
    资源失败 = 9,
    内部不一致 = 10
};

enum class 系统世界树根发布来源 : std::uint8_t {
    首次建立 = 1,
    待收敛精确重复 = 2,
    已发布重复消费 = 3
};

struct 系统世界树根读回 final {
    系统世界树根初始化请求 选择;
    L2场景树根建立请求 首次建立请求;
    L2场景树身份 树;
    L2场景身份 根场景;
    L2场景树事实 正式树读回;
    std::uint64_t 事实截止代次 = 0;
};

struct 系统世界树根初始化结果 final {
    系统世界树根初始化状态 状态 =
        系统世界树根初始化状态::请求无效;
    std::optional<系统世界树根发布来源> 来源;
    std::optional<L2场景树结构登记结果> 根建立前登记读取;
    std::optional<L2场景树节点写入结果> 根建立;
    std::optional<L2场景树结构登记结果> 根读回前登记读取;
    std::optional<L2场景树读取结果> 根读取;
    std::optional<系统世界树根读回> 已发布根;
    bool 成功() const noexcept;
};
```

请求接受合同版本 1 和任一非零不透明幂等身份；它允许嵌入方明确给出本上下文唯一的项目树建立意图，并让异参数冲突可被结构化验证。正式 `运行普通程序` 不开放命令行、配置文件或名称选择，只传入 `海中鱼巣现实世界树根建立幂等身份` 这一项目固定默认值。该值只在本进程同一 L1 场景 owner 幂等域内表示同一建立意图，不是跨进程项目 ID，不编码树稳定编码，也不证明旧根已恢复。

结果形状逐来源冻结：

| 状态 / 来源 | 建立前登记 | 根建立 | 读回前登记 | 根读取 | 已发布根 |
| --- | --- | --- | --- | --- | --- |
| `已发布 / 首次建立` | 成功且存在 | `已提交` 且存在 | 成功且存在 | 成功且存在 | 存在 |
| `精确重复 / 待收敛精确重复` | 成功且存在，或沿用保存的原建立前登记结果 | `精确重复` 且存在 | 成功且存在 | 成功且存在 | 存在 |
| `精确重复 / 已发布重复消费` | 空 | 空 | 成功且存在 | 成功且存在 | 存在 |
| 任一非成功 | `来源` 与阶段材料只允许包含失败前实际发生的调用；`已发布根` 空，但既有上下文发布值不受影响 |

`成功()` 只接受表中三种成功形状，并逐字段核对来源、R1 状态、树身份和截止；其它组合一律失败。结构化 R1 结果供诊断和验证；它们不取得业务事实权威。

## 5. 普通应用上下文发布槽

A1 最终实现后，`普通应用上下文` 在聚合成员之后追加：

```cpp
mutable std::mutex 系统世界树根发布锁_;
std::optional<L2场景树根建立请求> 待收敛系统世界树根请求_;
std::optional<系统世界树根读回> 系统世界树根读回_;
```

上下文新增一个只读值式入口：

```cpp
std::optional<系统世界树根读回> 读取系统世界树根读回() const;
```

它在同一锁下复制返回已发布材料；未发布返回 `nullopt`。该 getter 不标记 `noexcept`；锁取得或值式复制异常向调用方抛出，不伪装为空或成功。不得返回内部引用、指针、R1 服务所有权、owner、端口、仓库或锁。上下文把根读回放在 A1 和六服务之后只是保证消费值与服务生命周期同在；上下文析构不退出根事实。

唯一初始化函数作为上下文 friend 访问两个私有槽，避免公开第二写入口：

```cpp
系统世界树根初始化结果 初始化并发布系统世界树根(
    普通应用上下文& 上下文,
    const 系统世界树根初始化请求& 请求) noexcept;
```

函数持有发布锁完成一次完整建立 / 收敛 / 读回 / 发布，禁止并发双初始化。整个函数体置于最外层 `try/catch`；锁取得、局部值式构造或 R1 调用抛出的 `std::bad_alloc` 映射 `资源失败`，其它异常映射 `内部不一致`，两者都不得修改既有发布值。锁只保护上下文过程状态，不参与 R1 事实裁决。

实现必须以局部对象完整形成新的 `系统世界树根读回` 和结果载荷，验证通过后才提交。`系统世界树根读回` 及其嵌套 R1 值式 DTO 必须满足不抛出移动构造和交换的编译期断言；发布使用局部 `std::optional<系统世界树根读回>` 与成员 `swap` 的无抛出提交。首次提交前成员为空；重复刷新提交失败或此前任何异常均保留旧 `系统世界树根读回_` 不变。待收敛槽只在保存完整原请求后出现，只在明确零变更漂移或发布交换成功后清空。

## 6. 生产闭环

### 6.1 首次调用

1. 校验请求；无效返回 `请求无效`，零 R1 调用。
2. 若已有发布值：同选择进入第 6.2 节，异选择返回 `已发布选择冲突`，零 R1 调用。
3. 若无待收敛请求，调用 `读取当前场景树结构登记()`；成功结果的非零截止作为 `L2场景树根建立请求.请求头.期望事实代次`，调用方选择作为幂等身份，并先把完整建立请求保存到待收敛槽。
4. 若已有待收敛请求，同选择必须逐字段复用原请求；异选择返回冲突。不得因当前代次变化重写已可能提交的原请求。
5. 经 `上下文.取得L2结构聚合服务().取得L2场景结构服务()` 调用 `建立场景树根`。只接受 `已提交 / 精确重复` 且完整载荷；其它状态结构化映射为 `根建立失败`。明确 `事实代次漂移` 且零变更时可清空待收敛请求，让下一次重新取得当前代次；资源失败、提交后读回失败或结果未知必须保留原请求供同请求收敛。
6. 再次调用 `读取当前场景树结构登记()` 取得建立后的当前事实截止，禁止从缓存、首次登记截止或根返回值猜测当前代次。
7. 以根建立返回的 `L2场景树身份`、当前读取类别和新截止调用 `读取场景树`。
8. 验证树身份等于根场景编码，根位于场景组，根标记类别 / 端点 / 生命周期与 R1 结果一致，根无父，事实截止非零且所有嵌套投影完整。任一不一致返回 `根读回不一致`，不发布上下文值，保留原待收敛请求。
9. 在局部完整形成候选值和结果载荷，以无抛出交换形成 `系统世界树根读回_`，随后清空待收敛槽；根建立为 `已提交` 时返回 `已发布 / 首次建立`，为 `精确重复` 时返回 `精确重复 / 待收敛精确重复`。交换前异常保留旧发布值和原待收敛请求；R1 已发布事实不撤销，后继用原请求继续收敛。

### 6.2 同运行期重复调用

已有发布值且请求相同时，函数只再次正式读取，不重复提交写请求：

1. 重新读取当前树结构登记取得当前截止；
2. 再调用正式 `读取场景树`，逐字段验证同一树仍为合法当前树；
3. 验证本轮树投影的根标记、根场景和首次建立生命周期仍与保存材料一致；
4. 在局部完整形成新值式读回，以无抛出交换替换上下文副本，返回 `精确重复 / 已发布重复消费`；该成功结果的建立前登记和根建立 optional 固定为空。

`精确重复` 是 I1 对同一已发布选择的重复消费状态，不冒充本轮重新提交 R1 写请求。重复调用不是缓存命中成功；每次成功都必须有本轮 R1 正式读回。不同幂等身份或合同版本不得建立第二棵现实世界树，也不得覆盖已发布值。

## 7. 正式启动消费与失败短路

`运行普通程序` 在 `构造普通应用上下文` 成功后、控制面板 / 无窗口模式分支之前构造默认 `系统世界树根初始化请求` 并调用初始化函数。I1 失败统一返回：

```cpp
{模式, 程序运行状态::初始化失败,
    程序失败阶段::现实世界树根初始化}
```

`程序失败阶段` 在当前最大值 13 后追加 `现实世界树根初始化 = 14`，不复用旧 `方法登记根` 或 `自我线程初始化`。失败后不得启动自我初始化、投影、控制面板、停止信号或宿主。

本叶尚不修改 7130 或实现自我适配，因此 I1 成功发布根后必须立即返回：

```cpp
{模式, 程序运行状态::初始化失败,
    程序失败阶段::自我初始化待适配}
```

`程序失败阶段` 再连续追加 `自我初始化待适配 = 15`。该状态明确表示根已由 I1 正式发布，但当前进程不能沿旧自我输入继续；它不是 I1 失败，不撤销根，也不调用方法根、自我、概念、控制面板、停止信号或宿主。后继自我适配叶接通并验证后，才允许删除这个临时生产短路并继续 8120 第 3—6 步；不得在 I1 施工时预先移除。

本叶的正式生产消费者证明两种普通启动模式都真实调用 I1，并在成功发布根后以 `自我初始化待适配` 结束。控制面板既有宿主失败分支与无窗口信号宿主在本叶基线继续保留，但均不可达；I1 不删除或改义它们，后继适配完成后恢复其正常路由。

## 8. 非成功、恢复和旧入口

- R1 的入口拒绝、许可拒绝、漂移、幂等冲突、引用冲突、资源失败和内部不一致保留在阶段结果中，不翻译成成功。
- 根已经由 R1 发布但 I1 正式读回或值式复制失败时，禁止撤销、另键重建或建立第二根；只能保留原建立请求后继收敛。
- 当前 L1 是新进程内存运行包，没有跨进程恢复。再次启动会形成新的运行期事实和新根编码；不得声称恢复旧根。
- 非空旧域、旧裸场景、旧世界登记、旧 `基础信息身份` 世界根、旧自我快照和 `.codex-build` 历史产物全部不可采用、扫描或迁移。
- 未来跨进程恢复必须先由 4070 路线发布合法 R1 owner / 根事实，再由独立恢复适配读取；未来多项目选择必须有持久项目身份与项目到树的正式业务映射。二者都不是 I1。

## 10. 验证矩阵

生产外专项至少覆盖：

1. 无效合同版本或零身份入口拒绝，R1 事实代次不变；
2. 全新上下文首次调用返回 `已发布`，根建立为首次提交，正式树读回逐字段完整；
