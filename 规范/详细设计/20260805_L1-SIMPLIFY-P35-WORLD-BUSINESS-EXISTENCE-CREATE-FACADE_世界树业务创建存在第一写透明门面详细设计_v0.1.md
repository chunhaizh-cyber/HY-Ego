## 1. 目标与完成边界

本叶原位扩展 P32 冻结的唯一 L2 `世界树业务服务`，增加 4200 §4 六写中的第一项正式门面：

```text
世界树业务服务::创建存在并接纳到场景
-> L1当前场景实际存在发布服务::在当前场景创建实际存在（P34）
```

门面只把同一个 `当前场景实际存在创建请求` 以 const 引用传给 P34 恰1次，并逐字段原样返回同一个 `实际存在结果`。它不校验、映射、重组、缓存、重试、捕获改判或访问 L1；P34 唯一拥有双摘要、provider、写集、原子发布、同锁读回和隔离语义。

P32 的三个读取函数名称、签名、const、异常、依赖和一对一委托语义全部保持不变。本叶只把 P32 的单依赖构造扩展为“快照读取 + 当前场景实际存在发布”两个必需引用，不提供单参数兼容构造、空 provider、setter 或服务定位器。

本叶不设计第二写“发布存在初始特征”。当前新 L1 仍缺该能力的完整批次 provider；在已有 P34 provider 尚未进入正式门面时先越过第一写去设计第二写，会让 4200 的正式服务能力顺序留下真实断口。因此本叶是 P34 后最早可独立施工叶。

本叶不设计其它五写、治理白名单路由、状态动态、动作动态、因果、任务/结算、恢复装配、运行期接线、旧入口删除、集成验收或 STEP-5。

## 4. 最终类、构造迁移与函数签名

在 P32 的 `海中鱼巣.领域.服务.世界树` 原位形成：

```cpp
export inline constexpr std::uint32_t 世界树业务服务合同版本 = 1;

export class 世界树业务服务 final {
public:
    世界树业务服务(
        const 世界树快照读取服务& 快照读取,
        L1当前场景实际存在发布服务& 当前场景实际存在发布) noexcept
        : 快照读取_(快照读取),
          当前场景实际存在发布_(当前场景实际存在发布) {}

    世界树业务服务() = delete;
    世界树业务服务(const 世界树业务服务&) = delete;
    世界树业务服务& operator=(const 世界树业务服务&) = delete;
    世界树业务服务(世界树业务服务&&) = delete;
    世界树业务服务& operator=(世界树业务服务&&) = delete;

    完整世界存在快照读取结果 查询存在完整事实(
        const 完整世界对象读取请求& 请求) const;
    完整世界场景快照读取结果 查询场景完整事实(
        const 完整世界对象读取请求& 请求) const;
    完整世界快照组合结果 读取完整世界事实快照(
        const 完整世界快照组合请求& 请求) const;

    实际存在结果 创建存在并接纳到场景(
        const 当前场景实际存在创建请求& 请求) const;

private:
    const 世界树快照读取服务& 快照读取_;
    L1当前场景实际存在发布服务& 当前场景实际存在发布_;
};
```

`世界树业务服务合同版本` 固定为1，并静态断言等于 P32 的 `完整世界快照合同版本` 和 P34 的 `当前场景实际存在创建合同版本`。三个版本字段只在各自 DTO 中由事实所有者解释，门面不重复验证。

P32 的单参数构造被双引用构造完整替代，不保留 overload。原因是写门面存在时 P34 是必需生产依赖；保留单参数构造只能通过空指针、未实现写根或运行期 setter 形成半装配服务，违反 P32 已冻结边界。P35 激活 S0 必须枚举全部真实构造调用点；除 P32 专项外若出现新的生产或测试调用点，必须先修订白名单，不得漏改或增加兼容构造。

新写函数为 `const`、非 `noexcept`。门面自身无可变状态；C++ 的 const 成员仍可经其保存的非 const P34 引用调用 P34 非 const 写函数，不需要把门面公开函数降为非 const。请求由调用方拥有，函数同步 const 借用且不保存；结果按值返回并由调用方拥有。两个依赖引用均由装配宿主拥有，其寿命覆盖门面和全部同步调用。

## 5. 唯一函数算法

函数体固定为一条直接委托：

```cpp
实际存在结果 世界树业务服务::创建存在并接纳到场景(
    const 当前场景实际存在创建请求& 请求) const {
    return 当前场景实际存在发布_.在当前场景创建实际存在(请求);
}
```

调用前后不得增加：

- 合同、世界根、场景、幂等身份、事实代次或操作标签校验；
- 请求复制、字段变换、默认值、provider 规格或写集形成；
- 状态映射、optional 补造、成功形状再解释或失败降级；
- try/catch、日志、计时、retry、sleep、fallback 或旧栈回退；
- 第二 provider 调用、完整快照读取、结果缓存或跨调用状态。

P34 返回什么，门面逐字段返回什么，包括 `已提交/幂等读回/未找到/入口拒绝/幂等冲突/版本漂移/许可拒绝/资源失败/内部不一致`、optional 事实是否存在及其全部见证。异常若从 P34 越过其自身合同传播，门面不捕获改判；正式 P34 设计要求 provider 自身收口，但门面签名仍不额外承诺 `noexcept`。

## 6. 三读保持、并发与生命周期

P32 三个函数体保持原样，继续分别调用 P30/P31/P29 恰1次并全等返回。新增非 const P34 引用不能被三读访问；三读静态扫描对 `当前场景实际存在发布_` 调用为0，第一写对 `快照读取_` 调用为0。

门面不加锁。并发、幂等、许可拒绝、L1原子发布和隔离全部由 P34/P15 拥有；快照读取并发由 P29—P31 拥有。不同门面调用之间不保存状态，不建立跨请求顺序。构造只绑定引用，不读取、不注册、不恢复、不发布事实。

本叶不设计生产装配。未来装配必须先构造快照读取和 P34 发布者，再构造世界树门面；本设计只冻结依赖顺序，不授权修改运行期文件。
