# 局部二值格 U64 组解析提供者详细设计

身份：`LOCAL-BINARY-GRID-U64-PARSER`

版本：v0.3

日期：2026-09-17

状态：可执行

## 1. 目标与边界

本设计实现2100 v0.18、4120 v0.14唯一的进程内纯解析提供者。它只验证调用方借入的完整 `U64组`，并返回局部二值轮廓或局部二值体素的已核验格式；不创建、保存、改写或规范化任何值事实。

普通完整形式必须核验原始最高层、颜色（仅体素）、全部逐层OR压缩层和全零非规范化拒绝。全零描述形式严格为：

```text
轮廓：[0, 1, N]
体素：[0, 2, N]
```

它们表示已知的全零逻辑格，不是空材料、未知、未观察或摘要。解析器不得分配全零层数组、将其回写为普通完整形式，或把其作为第二值事实保存。具名格式生产方负责在调用通用U64保存服务前形成该描述；通用保存服务保持业务中性，不参与本设计。

服务不持有L1、写端口、概念树、特征值服务或可变全局状态。旧 `v1` 只核验旧的最高层布局，不能解释4120 v0.14，必须物理退出；不保留兼容入口或旧格式成功路径。

## 3. 冻结 v2 DTO 与入口

```cpp
enum class 局部二值格解析状态_v2 : std::uint8_t {
    已解析 = 1, 入口拒绝 = 8, 格式不合法 = 9,
    数量超限 = 10, 内部不一致 = 27
};
enum class 局部二值格编码形态_v2 : std::uint8_t {
    普通完整 = 1, 全零描述 = 2
};
struct 局部二值格解析请求_v2 {
    std::uint32_t 版本 = 2;
    const std::vector<std::uint64_t>* U64组 = nullptr;
};
struct 局部二值轮廓格式_v2 {
    std::uint64_t N = 0;
    std::uint64_t 最高层位图块数 = 0;
    std::uint64_t 压缩层数 = 0;
    局部二值格编码形态_v2 编码形态{};
};
struct 局部二值体素格式_v2 {
    std::uint64_t N = 0;
    std::uint64_t 最高层位图块数 = 0;
    std::uint64_t 压缩层数 = 0;
    std::uint64_t 颜色项数 = 0;
    局部二值格编码形态_v2 编码形态{};
};
```

两个结果各含 `{版本=2, 状态, optional<对应格式>}`；成功谓词同时要求请求/结果版本均为2、输入非空、状态为`已解析`、格式存在、`N`和最高层块数非零，且编码形态为两枚已定义值之一。非成功一律清空格式。

类保留两个具名入口：`解析局部二值轮廓(const 局部二值格解析请求_v2&)` 与 `解析局部二值体素(const 局部二值格解析请求_v2&)`。版本错误或空指针为`入口拒绝`；结构、类型、分辨率、长度、OR、颜色或非规范化全零冲突为`格式不合法`；任何受检计数、索引或 `size_t` 转换不可表示为`数量超限`；捕获到不应发生的异常为`内部不一致`。后两类及所有其它非成功均零格式载荷。

## 4. 解析算法

两个入口首先仅在长度恰为3且首项为0时识别描述。描述第二项必须与当前入口匹配，第三项必须满足本入口的 `N=8×2^k` 或 `N=4×2^k`；否则`格式不合法`。成功时返回相应 `N`、由安全迭代得出的最高层块数和压缩层数、`全零描述`；体素颜色项数固定为0。

非描述输入按普通完整形式解析：

1. 轮廓以受检循环枚举 `N=8,16,32,…` 及各层块数总和，只有总和恰等于组长度才接受。逐层按4120的低位编号验证每个下层位等于上一层对应四位的OR；所有层均零时拒绝。
2. 体素从第0项取得 `N`，以受检循环验证其为 `4×2^k`，计算最高层块数和全部压缩层块数。用总长度扣除各层及分辨率项得到颜色段长度，要求它恰等于最高层`popcount`、每项高40位为零，再逐层验证每个下层位等于八个上层位的OR；所有层全零且颜色段为空时拒绝。
3. 普通完整成功返回`普通完整`。解析回执只给出结构参数，不持有输入地址、迭代器或材料副本，也不生成坐标表。
