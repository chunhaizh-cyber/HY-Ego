# 局部二值格 U64 组解析提供者详细设计

身份：`LOCAL-BINARY-GRID-U64-PARSER`

版本：v0.2

日期：2026-09-17

状态：可执行

## 1. 目标与收束边界

本设计把 4120 §3.1.1、§3.2 已冻结的两种局部二值格格式落实为唯一的、进程内纯解析提供者：

- 局部二值轮廓 `U64组` 的长度、正方形分辨率和位图段核验；
- 局部二值体素 `U64组` 的 `N`、占用位图段、占用数与 RGB 尾段核验。

成功只证明传入的完整 `U64组` 符合对应局部格式，并返回调用方按正式位序展开所必需的尺寸与段边界。它不创建或登记 FT、F、FC、值事实、材料、比较注册或概念；也不把同一向量自动识别为轮廓还是体素。调用方必须按其已确定的正式 FT 调用对应入口。

因此本叶不实现海明差异、RGB 差异、边界/几何比较、值域、概念形成、特征持久化、初始化或装配。4181 的算法与 4182 的 FT 用途绑定仍是后继能力，不能因本解析器成功而被视为已启用。

## 2. 依据与当前代码裁决

- 2100 v0.15：局部二值轮廓和局部二值体素以完整 `U64组` 承载，且不保存现实坐标、材料头或版本字段。
- 4120 v0.12 §3.1.1、§3.2：分别固定体素和轮廓的完整布局、`N`、位序、颜色项、二态含义及合法形状。
- 4181 v0.2 §7：局部二值格是从完整组长度或首项得出 `N` 的唯一例外；格式成立不自动启用比较。
- 4180 v0.14 §5.2：非 I64 只能通过真实专用适配器取得成功，不得以长度、摘要或默认关系伪造成功。

当前 `海中鱼巣/领域/数据服务.特征值类.h` 已可在 `获取完整值` 中完整读取 `U64组`，但没有独立写入入口；`海中鱼巣/领域/数据服务.特征类.h/.cpp` 的准确特征生产和读取仍是 I64 路径。当前特征值域比较服务仅把 U64 组显式返回“待实现”。故新解析器只能依赖标准库、接受调用者已经读出的完整向量；不能修改这些服务或把本叶包装成非 I64 特征类型/值持久化。

## 3. 物理位置与唯一职责

新增：

```text
海中鱼巣/领域/数据服务.局部二值格解析类.h
```

类 `局部二值格解析数据服务` 不持有 L1、写端口、概念树、特征值服务或可变全局状态；它只读取请求在调用期间借出的 `std::vector<std::uint64_t>`。实现源文件由主工程登记，以便正常工程最终可链接；专项验证可用该两文件和独立驱动进行隔离编译。

解析结果不得保存传入指针、引用、迭代器或整份材料副本。调用方保留自身读取结果；成功回执只含已经核验的结构参数。这样结果不把临时读回材料伪装成第二事实仓，也不存在跨调用悬垂引用。

## 4. 冻结公开 DTO 与函数

全部 DTO 版本固定为 `1`。

```cpp
enum class 局部二值格解析状态_v1 : std::uint8_t {
    已解析 = 1,
    入口拒绝 = 8,
    格式不合法 = 9,
    数量超限 = 10,
    内部不一致 = 27
};

struct 局部二值格解析请求_v1 {
    std::uint32_t 版本 = 1;
    const std::vector<std::uint64_t>* U64组 = nullptr;
};
struct 局部二值轮廓格式_v1 {
    std::uint64_t N = 0;
    std::uint64_t 位图块数 = 0;
};
struct 局部二值体素格式_v1 {
    std::uint64_t N = 0;
    std::uint64_t 占用位图块数 = 0;
    std::uint64_t 颜色项数 = 0;
};
```

轮廓/体素结果各有 `{版本、状态、optional<对应格式>}`，并各自提供 `成功(const 局部二值格解析请求_v1&) const noexcept`。成功必须同时要求：版本均为 1、请求指针非空、状态为 `已解析`、对应可选格式存在；轮廓要求 `N` 与位图块数非零，体素要求 `N` 与占用位图块数非零。体素颜色项数可以为零：全零占用位图是合法的已知空局部体素，颜色尾段必须为空。非成功必须清空格式。

```cpp
class 局部二值格解析数据服务 final {
public:
    局部二值轮廓解析结果_v1 解析局部二值轮廓(
        const 局部二值格解析请求_v1&) const noexcept;
    局部二值体素解析结果_v1 解析局部二值体素(
        const 局部二值格解析请求_v1&) const noexcept;
};
```

请求指针只在函数调用期间借用，不进入返回值。请求版本错误或空指针返回 `入口拒绝`；格式矛盾返回 `格式不合法`；任何对 `uint64_t` 或 `size_t` 不可表示的中间计数返回 `数量超限`；捕获到不应发生的异常返回 `内部不一致`，并清空格式。纯读取实现不预期分配，故不新增资源状态。

## 5. 精确解析过程

### 5.1 局部二值轮廓

设 `L = U64组.size()`，先安全转换为 `uint64_t`。

1. `L == 0` 返回 `格式不合法`。
2. 求整数平方根 `q`，不得以浮点近似作为事实；只有 `q*q == L` 才继续，并在乘法前检查溢出。
3. 检查 `q > 0`、`8*q` 可表示，令 `N=8*q`；这等价于 `N×N` 单元数为 64 的倍数。
4. 返回 `{N, L}`。不扫描或改写任何位；第 `i` 位到 `(x,y)` 的映射仍严格为 `i=y*N+x`、块 `i/64`、低位起算 `i%64`，由后继实际使用者按 4120 展开。

### 5.2 局部二值体素

1. 空组返回 `格式不合法`；读取第 0 项为 `N`。
2. 检查 `N>0`、`N%4==0`，并以受检乘法计算 `N³`；任何不可表示结果返回 `数量超限`。
3. 得到 `B=N³/64`，检查 `1+B` 可表示且不超过组长度；否则返回 `格式不合法`。
4. 对 `[1,1+B)` 的每个占用块做 `popcount`，受检累计得到 `C`。检查完整长度严格等于 `1+B+C`；短、长、或计数不可表示均不可成功。
5. 对颜色尾段逐项检查高 40 位为零；低 24 位只按 `R=bits0..7、G=bits8..15、B=bits16..23` 保留，不作颜色比较或特征拆分。
6. 返回 `{N,B,C}`。占用位的展开规则仍为 `i=((z*N)+y)*N+x`、组 `1+i/64`、低位 `i%64`；本服务不生成坐标表。

## 6. 失败、可靠性与后继

本服务零写入、零 L1 调用、零事务、零幂等键、零发布未知和零恢复状态。它不对载荷作规范化、重排、补零或改写；同一完整请求在相同进程与实现版本下只按相同格式规则形成同一纯值结果，但这不是事实写入重放，故不得添加幂等身份或幂等冲突分支。任何非成功都不是“空轮廓”“空体素”“不包含”或“未观察”；调用方不得用其替代比较/值域结论。成功的零占用体素只说明该局部格全部已知未占用，不是解析失败或未知。输入中每一位的 0/1 已是已知的二态，解析器也不增加未知态。

后继 FT 初始化/绑定应在正式合同中将某 FT 唯一绑定到本服务的某一个入口，再把 `特征值类` 的完整 `U64组` 读回结果借给本服务。此设计不预先修改其接口或建立待实现空函数。海明差异等比较需在相同 FT、相同解释与已启用用途下另行设计和实施。
