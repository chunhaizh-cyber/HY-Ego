# INSTINCT-STAGE3-ACTIVE-SAFETY-SOURCE-CATALOG 主动安全结算来源方法完整集合详细设计 v0.1

日期：2026-08-30

状态：设计完成；只闭合主动安全结算来源规则的发布与同截止读回

## 1. 目标与完成边界

在现有唯一 `安全根定义与当前值服务` owner 内建立版本化主动安全结算来源方法完整集合，并由现有生产初始化提供者发布、恢复和独立读回当前规则版本 1 的显式空集合。

完成结果固定为：

```text
安全根定义版本 1 已发布 / 已恢复
-> 发布或恢复主动安全结算来源规则版本 1
-> 完整方法组显式为 0 项
-> 以新的事实截止同时读回安全根定义和来源规则
-> 规则版本、自我和安全根实例逐字段一致
-> 生产初始化才返回成功
```

本叶不改变 `0..I64_MAX`、`L=2,767,011,611,056,432,742`、`H=7,378,697,629,483,820,645` 或安全根定义版本 1；不实现主动安全结算方法，不解释永久变化账，不选择 UTC / 单调秒窗口，不计算低位回升门禁，也不发布 A/V、状态、动态或维护游标。

## 2. 正式依据与当前事实

- 6100 v0.6：主动安全结算只能由版本化来源方法完整集合解释；规则版本 1 显式为空。
- 6120 v0.10：安全根定义版本 1 绑定主动安全结算规则版本 1；绑定不证明生产 provider 已存在。
- 6170 v0.7：低位回升前必须逐项裁定永久变化账来源，未知来源 fail-closed。
- 4230 v0.19：永久变化账只保存可选来源方法，不解释业务语义。
- 当前 `安全根定义与当前值服务` 已有唯一 owner、定义登记、当前槽、版本连续、幂等重放和正式读回；不得建立第二安全规则 owner。
- 当前代码没有生产主动安全结算方法或正式方法身份清单；测试临时方法不得进入生产规则。

## 3. 唯一 owner 与持久结构

沿用：

```text
owner：安全根定义与当前值服务
L1 owner 建立幂等身份：0x494E'5354'5341'4645
现有定义登记键：0x0307'1201..0x0307'1204
```

在同一 owner 内新增独立来源规则登记，不改变现有定义登记首次写集：

```text
来源规则登记写入幂等身份：0x494E'5354'5341'4602
0x0307'1205：来源规则登记锚点
0x0307'1206：当前来源规则节点
0x0307'1207：当前来源规则属性类型（U64组）
0x0307'1208：来源规则值
```

定义当前槽与来源规则当前槽分离，但共享同一 owner。首次发布允许定义先形成、来源规则后形成；任一中间态对消费者都 fail-closed。生产初始化只在最终同截止读回两者完整且版本一致时成功。未来同时切换定义与规则版本需要新的组合原子合同，不得复用本 v1 入口制造混版成功。

## 4. 公开 DTO 与成功公式

合同版本为 1。

```cpp
struct 主动安全结算来源规则事实身份_v1 final {
    稳定编码 值;
};

struct 主动安全结算来源规则事实_v1 final {
    主动安全结算来源规则事实身份_v1 身份;
    L2存在身份 自我;
    L2特征实例身份 安全根特征实例;
    std::uint32_t 规则版本;
    std::vector<L2方法身份> 完整来源方法组;
    稳定编码 来源稳定编码;
    std::uint64_t 形成事实代次;
};
```

完整性：身份、自我、实例、来源和形成代次有效；规则版本非零；方法组按 `方法.值.值` 严格升序且无重复。`0` 项合法且必须被明确编码为声明数量 0。

发布请求字段顺序：合同版本、共同 `L2结构请求头(G0)`、幂等身份、本能根锚点、新规则版本、完整来源方法组、来源稳定编码。

发布状态：`已发布、精确重复、入口拒绝、许可拒绝、当前性漂移、版本漂移、幂等冲突、引用冲突、资源失败、内部错误、已可能发布`。只有前两项携带完整事实、首次提交 G1 和正式读回截止并成功；其它载荷空，`已可能发布`只保留幂等身份和可能提交 G1。

读取请求字段顺序：合同版本、共同 `L2结构请求头(G0)`、本能根锚点。读取状态：`已读取、未发布、入口拒绝、许可拒绝、当前性漂移、引用冲突、资源失败、内部错误`。只有 `已读取 + 完整事实 + G0` 成功。

公开入口：

```cpp

安全根定义与当前值服务::发布主动安全结算来源规则_v1(
    const 发布主动安全结算来源规则请求_v1&) noexcept;

主动安全结算来源规则读取结果_v1
安全根定义与当前值服务::读取当前主动安全结算来源规则_v1(
    const 主动安全结算来源规则读取请求_v1&) const noexcept;
```

## 5. 编码、版本与幂等

U64 组布局固定为：

```text
[0] 自我稳定编码
[1] 安全根特征实例稳定编码
[2] 规则版本
[3] 声明方法数 N
[4] 来源稳定编码
[5..5+N) 规范有序方法稳定编码
```

值所属节点、属性类型、来源锚点、写入 owner、形成 G1 与当前槽必须逐项互证。长度必须恰为 `5+N`；声明数、零值、乱序、重复、尾随材料和溢出均拒绝。

本 v1 发布入口只接受规则版本 1 且 `N==0`：当前未发布时形成首版；当前已经是同义版本 1 时读取当前并返回精确重复；任何其它版本、非空组或当前异义都返回版本漂移 / 入口拒绝，不允许借本入口提前发布版本 2。精确重复以首次规范化写集和首次结果收敛；同幂等身份异义返回幂等冲突。未来非空来源集合、方法 owner 同截止验证、版本 2 以及定义 / 规则联合切换必须由新的公开合同闭合，禁止测试方法进入生产空集。

## 6. 生产初始化接线

现有 `安全根生产定义初始化提供者::初始化并读取安全根生产定义_v1(...)` 保持请求 ABI 不变，在安全根定义发布 / 恢复成功后：

1. 以当前 G0 发布来源规则版本 1、空方法组、固定幂等身份和固定来源编码；
2. 当前性漂移按现有最多两次收敛边界重试，已可能发布只用原幂等身份重放；
3. 取得新 Gread 后，分别读取安全根定义和来源规则；
4. 互证自我、根实例、`定义.主动安全结算规则版本 == 来源规则.规则版本 == 1`、方法组为空；
5. 结果新增完整来源规则载荷，只有两份事实都完整才成功。

现有启动只调用 `成功()`，不改调用顺序或失败阶段。不存在来源规则时，恢复路径必须补发并读回，不能把定义中的裸版本号当成完整集合。

## 7. 非成功与并发边界

- 登记未形成、当前槽 0/N 复义、当前值坏载荷或定义 / 规则不一致：引用冲突或内部错误，空成功载荷。
- G0 读前或读后变化：当前性漂移；不得返回跨截止组合。
- 提交后首次读回失败：已可能发布；原请求重放后按首次 G1 收敛。
- 资源失败与未知异常分账，不吞并为未发布或合法空集。
- 方法组为空是正式完整事实；规则未发布不是空集。
- 本 v1 不验证非空方法生命周期，因为非空输入一律拒绝；未来非空版本必须新增同 G0 方法 owner 独立读回合同。
