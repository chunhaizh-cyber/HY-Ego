## 1. 目标、理由和完成边界

本设计只补齐 DATA-L1 当前缺失的“2..255 个互异内部结构分区共同发布一个事实代次”能力。阶段三正式服务生存维护至少同时涉及特征、状态、动态和维护 / 合同结构 owner；当前 v2 固定三分区无法承载。拆成多次提交、把维护游标塞进服务值或让错误 owner 承载都会制造公开可见半结构。

完成最多证明：v3 中性公开合同可由同一 L1 实例的一组合法写端口调用，取得共同 G1、逐参与者编码映射、独立幂等重放和格式 1/2/3 持久恢复。它不实现安全 / 服务规则、维护游标、合同结算、当前值变化批次、治理线程或业务授权。

v1 双参与者和 v2 三参与者 ABI、行为、幂等账及恢复语义保持不变。v3 不替代阶段二既有 v2 consumer。

## 2. 当前事实与复用裁决

当前 `L1三分区原子事务合同版本_v2=2` 已经具备：owner-scoped 五类写项、连续局部身份、向后跨分区引用、规范化完整请求、候选仓库顺序应用、共同代次归一、全局引用闭包、独立组合幂等账和内部格式 1/2 恢复。

不可直接复用的硬编码包括：

```text
请求参与者组 size == 3
服务入口接收者 + 第二 / 第三端口
仓库 array<...,3>、循环上界3和身份上界3
临时代次只调整第二 / 第三代次
结果 / 持久状态只保存三分区 v2 组合账
```

v3 复用 v2 的中性写项布局和参与者身份值类型，新增独立请求、状态、结果、服务入口、仓库入口和组合幂等账。不得以把 v2 的 `size==3` 改成可变长度的方式静默改变旧 ABI。

全部新 DTO 逐字段值式相等。公共写端口入口固定为：

```cpp

    const L1有限N分区原子事务请求_v3& 请求,
    const std::vector<const L1所有者范围写端口*>& 其余参与者) noexcept;
```

接收者绑定参与者 1，`其余参与者[i]` 绑定参与者 `i+2`。指针只作调用期间不可拥有引用；空指针、重复地址、失效端口、跨实例或 owner 不匹配均在仓库调用前拒绝。入口不保存端口指针，不公开端口枚举和 owner 选择服务。

仓库私有入口：

```cpp

    const L1有限N分区原子事务请求_v3& 请求) noexcept;
```

## 4. 有效性、规范化与引用

1. 专属合同版本为 3，共同 G0 和组合幂等身份非零。
2. N 在 2..255；规范排序后参与者身份恰为连续 1..N。
3. N 个 owner 有效且互异，N 个内部写入幂等身份有效且互异；端口逐项同实例、活动且绑定对应 owner。
4. 每份写集使用现行 owner-scoped CRUD 合同、共同 G0，五类写项合计非空。
5. 每个参与者内节点 / 关系 / 值的本地键共享一个非零唯一命名空间；退出事实和属性槽不重复。
6. 跨参与者引用只能从参与者 i 指向 `1..i-1` 已声明节点键；本地引用只指向本参与者节点键。
7. 属性槽新当前值只允许本参与者新值键。字段目标类型不合法映射引用冲突。

规范化顺序与 v2 相同，但所有循环使用 N。精确重复比较规范化完整 v3 请求；调用方容器排列不参加判同。

## 5. 事务与代次归一

```text
入口和端口组校验
-> 规范化完整请求
-> 取得仓库唯一写锁
-> 隔离 / 完整性守卫
-> v3 组合幂等账同义重放或异义冲突
-> 共同 G0 守卫
-> 复制私有候选仓库
-> 对 i=1..N：解析只向后引用、应用 owner 写集、保存映射和临时代次
-> 共同 G1 = 第一参与者临时代次 = G0+1
-> 把所有后序临时代次对应的创建 / 退出代次归一为 G1
-> 把 N 份首次写入账的首次请求 G0 和首次结果 G1 归一
-> 重建反向索引并执行全局引用 / owner 闭包
-> 写入独立 v3 组合幂等账
-> 准备格式3持久快照
-> 一次交换正式状态
-> 返回已提交
```

候选内部每应用一份普通 owner 写集会临时推进一次代次；这些代次从不公开。归一必须覆盖当前 / 历史 owner、节点、关系、值、历史副本、逐 owner 首次账和全部结果映射，不得只改事实表。

## 6. 结果矩阵

| 状态 | 共同代次 | 参与者结果 | 发布确认 | 重试边界 |
| --- | ---: | --- | ---: | --- |
| 已提交 | 首次 G1 | N 份完整有序映射 | 是 | 不适用 |
| 精确重复 | 首次 G1 | 首次 N 份映射 | 否 | 原幂等身份读回收敛 |
| 入口拒绝 | 0 | 空 | 否 | 修正请求后可重试 |
| 事实代次漂移 | 当前代次 | 空 | 否 | 修正请求后可重试 |
| 幂等冲突 | 当前代次 | 空 | 否 | 不适用 |
| 引用冲突 | 当前代次 | 空 | 否 | 修正请求后可重试 |
| 资源失败 | 可安全取得则当前代次，否则0 | 空 | 否 | 原请求可重试 |
| 内部不一致 | 可安全取得则当前代次，否则0 | 空 | 否 | 不适用 |

交换前持久准备失败是资源失败或内部不一致且零发布。不得为测试增加生产故障入口。

## 7. 持久格式与恢复

仓库状态新增 `有限N分区原子事务幂等账_v3`，保存规范化请求和首次结果。内部权威快照格式从 2 升 3：保持格式2全部字段原顺序，在 v2 三分区账之后追加 v3 账，再写原后续字段。

- 格式1：v2、v3 账初始化为空。
- 格式2：读取 v2 账，v3 账为空。
- 格式3：读取 v2 账后读取 v3 账。
- 编码只产生格式3。

v3 账按组合幂等身份升序；参与者必须规范有序、N 合法、请求结果互证、映射逐项匹配。未知版本、尾随字节、重复键、非规范请求或坏首次结果拒绝恢复。现有公开持久恢复 ABI 不变。

v3 顶层请求、结果和账必须使用具名的 v3 专属编解码路径。该路径可以逐字段复用 v2 中性写项的编码布局，但不得调用现有把参与者身份限制为 `1..3` 的 v2 参与者 / 请求解码函数，也不得通过修改该函数上界改变格式2语义；v3 解码按当前账声明的 N 独立校验 `1..N` 与最大值255。

## 9. 验证矩阵

1. 2、3、4、8、255 参与者正常提交，共同只推进一个 G1，逐 owner 正式读回一致。
2. v3 精确重复返回首次 G1 / 映射且零新代次；同键异义冲突。
3. N=0/1/256、身份缺 / 多 / 重 / 不连续、owner 重复、幂等重复、空端口 / 重复端口 / 跨实例 / owner 错配写前拒绝。

5. 第 1 / 中间 / 最后参与者普通写失败均整笔零变化；N 份首次账不泄漏。
6. 格式3 round-trip 后 v3 重放一致；格式1、格式2 合法样本恢复后能继续 v3 提交。缺合法旧样本时分别记录 NOT_RUN。

8. Debug / Release、ABI consumer、strict 和 cached diff-check 全部取得具名结果。
