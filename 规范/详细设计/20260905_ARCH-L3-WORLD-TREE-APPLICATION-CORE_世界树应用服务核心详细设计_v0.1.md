# 世界树应用服务核心详细设计

日期：2026-09-05

版本：v0.3

身份：`ARCH-L3-WORLD-TREE-APPLICATION-CORE`

状态：首个实质语义叶合同已冻结；可进入代码实施

代码事实基线：`2535d602549fa0107b80346a699418baa2d93e35`

## 1. 本次裁决

用户明确：场景关系操作属于场景类，存在的特征和子存在关系属于存在类，其余关系以此类推。因此世界树类不公开、不拥有也不换名转发任何单类关系 CRUD。v0.1 的 11 个查询 / 单关系增删签名继续永久撤销；v0.2 的语义总路线保留，但不能等全部远端能力齐备才建立空壳。

当前已发布的 `场景类::查询场景树` 能在一个调用截止验证候选根、根无父、子场景闭包和同代次完整结构；`场景类::迁移成员关系` 能由 scene owner 用一个写集原子替换子场景或存在的唯一归属关系。两者足以形成一个最小且实质的 ARCH-L3 闭环：

1. 由业务装配显式绑定现实世界根候选；
2. 每次操作 fresh 验证整棵现实世界场景结构；
3. 在该根闭包内唯一定位现实世界成员；
4. 以“移动现实世界存在”或“移动现实世界场景”的高层语义调用场景 owner 原子迁移；
5. 发布后重新读取现实根闭包并确认最终位置，不能确认时显式返回已发布待复核或结果未知。

这不是场景成员关系 CRUD 的包装：调用方不能选择新增或删除单边，也不能移动现实根、把世界外端点带入、绕过全树唯一位置检查，或把一次关系写成功直接提升为世界语义完成。

## 2. 层级、所有权与禁止边界

- 模块层级：`ARCH-L3` 应用语义；不新增 DATA owner，不直达 L1。
- 唯一依赖：新 `海中鱼巣.领域.数据服务.场景类` 公开面。不得 import 或调用任何旧 `服务.L2*`。
- 现实根绑定：是上层装配传入的值式配置，不写入 DATA，不伪称全进程 / 跨进程唯一现实根；每次函数仍必须通过 `查询场景树` 验证。
- 所有写入：只由注入的场景类数据服务执行；世界树类无写端口、owner、关系类型或直接事实写入能力。
- 子存在：本叶不建立内部世界。未来子存在只能成为内部世界场景的存在成员，严禁普通存在到子存在的结构边。
- 需求、任务、方法、Vt、Vm：不进入世界树结点、成员、请求或结果。所属存在业务视图仍归 ARCH-L4。
- 本叶不实现：创建场景并接纳、创建存在并进入场景、初始特征、特征更新、状态 / 动态发布、内部世界、存在移除、完整存在 / 特征 / 状态 / 动态事实聚合、现实根持久登记、生产装配或旧逻辑迁移。

正式依据为 0050 的事实 / 关系 / 代次与确定失败边界、1140/1150 的内部世界和子存在表达、4200 的纯世界树与 DATA 外现实根选择、4230 的新三层数据职责，以及`世界树业务服务与同代次完整事实快照详细设计`已冻结的现实世界语义参考。后者只作语义目标参照；其旧实现、旧 L2 名称和旧事务不构成本叶可复用能力。

## 3. 当前能力复用裁决

| 所需能力 | 当前公开面 | 本设计裁决 |
| --- | --- | --- |
| 根与全树结构验证 | `场景类数据服务::查询场景树` | 直接复用；根不是结构根、预算不足、端点失败和代次漂移均为整体非成功。 |
| 存在在世界中的位置 | `场景类树结果::场景组[*].存在组` | 由 ARCH-L3 在已验证树内值式聚合；零位置为世界外，多位置为结构复义，不访问 L1。 |
| 场景在世界中的位置 | `场景类结点::父场景` | 由 ARCH-L3 在已验证树内读取；现实根无位置且禁止移动，普通场景必须恰有父关系。 |
| 移动存在 / 场景 | `场景类数据服务::迁移成员关系` | 直接复用其 scene owner 单写集；分别由两个语义函数固定成员种类，不给调用方关系 CRUD 入口。 |
| 发布后确认 | `查询场景树` | 在迁移返回的发布代次重读全树并确认成员位于目标；失败不伪称语义完成。 |

场景类已在树读取时验证存在、状态、动态等关系端点，但返回载荷只是一组 `场景类结点`，不能称“完整世界事实快照”。本叶结果名称一律使用“现实世界场景结构”或“成员位置”。

### 5.3 结果

```cpp
struct 世界树现实根结果 final {
    世界树应用状态 状态 = 世界树应用状态::入口拒绝;
    std::uint32_t 合同版本 = 世界树应用合同版本;
    std::uint64_t 事实代次 = 0;
    std::optional<世界树现实结构> 现实结构;
    bool 成功() const noexcept;
};

struct 世界树成员位置结果 final {
    世界树应用状态 状态 = 世界树应用状态::入口拒绝;
    std::uint32_t 合同版本 = 世界树应用合同版本;
    std::uint64_t 事实代次 = 0;
    std::optional<世界树成员位置> 位置;
    bool 成功() const noexcept;
};

struct 世界树移动结果 final {
    世界树应用状态 状态 = 世界树应用状态::入口拒绝;
    std::uint32_t 合同版本 = 世界树应用合同版本;
    世界树应用阶段 阶段 = 世界树应用阶段::无;
    std::uint64_t 观察事实代次 = 0;
    std::optional<std::uint64_t> 已发布事实代次;
    std::optional<世界树成员移动投影> 投影;
    bool 成功() const noexcept;
};
```

- `世界树现实根结果::成功()`仅接受`已验证现实根`，并要求版本、非零代次、有效根编码、非空场景组，且组内恰有一个结点编码等于结果根编码。绑定根一致性由生成该结果的服务函数负责，值式谓词不能访问服务实例。
- `世界树成员位置结果::成功()`仅接受`已读取成员位置`，并要求版本、非零代次和四个有效位置字段。
- `世界树移动结果::成功()`仅接受`已移动`或`精确重复`，阶段必须为`现实树最终确认`，已发布代次与完整投影必须存在，投影两代次非零、`首次发布事实代次 == *已发布事实代次`、端点 / 关系有效、原目标不同、旧新关系不同。请求逐字段一致性由生成该结果的服务函数负责。
- 任何非成功结果的成功投影必须为空；`已发布待复核`只允许携带`已发布事实代次`，`结果未知`不得推定已发布代次。

## 6. 读取算法

### 6.1 验证现实世界根

1. 校验合同版本、非零读取代次和非零预算。
2. 调用 `查询场景树({场景类数据合同版本, 读取事实代次, 绑定根, 最大场景数量})`。
3. 仅当返回`已读取`、同请求代次、根等于绑定根、场景组非空且每个场景编码唯一时，返回`已验证现实根`与完整场景结构。
4. 其它状态按第 8 节映射，零载荷返回。

### 6.2 读取现实世界存在位置

1. 校验请求并按 6.1 取得同截止现实树。
2. 扫描所有场景的`存在组`，按目标结点等于请求存在收集位置。
3. 恰一条返回`已读取成员位置`；零条返回`存在不在现实世界`；多条返回`成员多重位置`。不得返回“第一条”掩盖复义。

读取不会查询需求、任务或存在子关系，也不把存在自身全部特征载荷聚合进结果。

## 7. 移动算法、重放与发布收口

两个移动函数共用私有过程，但分别固定 provider 的成员种类：场景=`子场景`，存在=`存在`。不得新增公共通用关系移动函数。

### 7.1 预读守卫

1. 校验合同、两个非零代次、有效幂等身份 / 三个端点、原目标不同及非零预算。
2. 以`读取事实代次`验证绑定现实树；原场景与目标场景都必须位于该树。
3. 唯一定位成员当前所在场景。存在零 / 多位置分别失败；场景成员以其`父场景`定位，绑定现实根直接返回`现实根不可移动`。
4. 当前位置必须是原场景或目标场景。其它位置返回`原位置不匹配`；允许当前位置已经是目标，唯一用途是把原迁移意图交给 provider 判定是否精确重放。

### 7.2 owner 原子迁移

应用服务逐字段构造：

```cpp
场景类成员迁移请求{
    场景类成员迁移合同版本,
    请求.迁移期望事实代次,
    请求.迁移幂等身份,
    请求.原场景,
    请求.目标场景,
    固定成员种类,
    请求.成员,
    请求.最大场景数量
}
```

只调用一次 `场景服务_.迁移成员关系`。不先删除、不后新增、不补偿、不替换幂等键。

### 7.3 成功、精确重放与并发覆盖

- provider 返回`已迁移`：先核对合同版本和非零发布代次；缺失 / 错误时返回`内部不一致`。在已能确认 provider 报告发布的前提下，投影逐字段不一致、以发布代次重读失败 / 漂移或成员不能唯一确认在目标，都返回`已发布待复核`，阶段=`现实树最终确认`，只携带已发布代次，不带成功投影。只有投影和最终位置都闭合才返回世界树`已移动`。
- provider 返回`精确重复`：只有预读已证明成员当前唯一位于目标，且 provider 投影逐字段一致，才返回世界树`精确重复`。首次发布代次来自 provider，确认代次来自本次 fresh 预读。
- provider 返回`精确重复`但 fresh 预读显示成员又位于原场景，说明原迁移曾发布但已被后继事实覆盖，返回`既有迁移已被后继事实覆盖`，不声称当前位置满足意图。
- provider 返回`成员已在目标`：这不是当前幂等身份的成功重放，返回`成员已在目标但非精确重放`。
- provider 返回`已可能发布`：返回`结果未知`，阶段=`场景成员原子迁移`，不得携带成功投影或推断发布代次。

`已发布待复核`重试与`结果未知`重试都必须保留第 5.2 节不可变迁移意图，只更新 fresh 读取代次。应用服务不缓存状态；续跑材料完全由请求与结构化结果携带。

## 8. 下游状态映射

| 场景类状态 | 世界树状态 |
| --- | --- |
| 树读取`未找到` | `现实根未找到` |
| 树读取`目标已退出` | `现实根已退出` |
| `非根场景` | `现实根不是结构根` |
| `数量预算不足` | `世界结构预算不足` |
| `事实代次漂移` | `事实代次漂移` |
| `资源失败` | `资源失败` |
| 树读取其它非成功、坏版本 / 代次 / 载荷 | `世界结构不一致`或`内部不一致`，零载荷 |
| 迁移`原场景未找到` / `目标场景未找到` | `场景不在现实世界` |
| 迁移`成员未找到` | 按语义映射`场景不在现实世界`或`存在不在现实世界` |
| 迁移`成员多重归属` | `成员多重位置` |
| 迁移`形成场景环` | `形成场景环` |
| 迁移`事实代次漂移` / `幂等冲突` / `引用冲突` / `历史材料已清理` / `资源失败` | 同名世界树状态 |
| 迁移`子场景读取失败` / `存在读取失败` / `内部不一致` | `内部不一致` |
| 迁移`已迁移`且版本 / 发布代次有效但投影或最终读回不能闭合 | `已发布待复核` |
| 迁移`已可能发布` | `结果未知` |

入口请求不合法在调用 provider 前返回`入口拒绝`。任何漏列的新 provider 状态必须保守映射为`内部不一致`，不得落入成功。

## 9. 异常、诊断与生命周期

- 四个公开函数捕获 `std::bad_alloc`、`std::length_error`为`资源失败`，其余异常为`内部不一致`；均返回零成功载荷。
- 本模块不是进程最终诊断边界，不直接写日志；结构化非成功向上送出，由最终消费者负责唯一日志。`成功()`等纯谓词无适用错误分支。
- 服务对象不拥有注入服务或根事实生命周期；装配方必须保证场景服务长于世界树应用服务。
- 不建立后台线程、缓存、定时任务、全局变量或跨调用可变状态。

## 10. 后继路线与完成边界

本叶完成只证明“现实根场景结构验证 / 存在位置读取 / 世界内存在与场景移动”候选源码已形成。总路线后继按最早闭环另行治理：

1. 场景 owner 的“创建场景并接纳”单写合同；
2. 跨 existence / scene owner 的“创建存在并进入场景”显式分阶段合同；
3. 特征初始化、状态 / 动态发布和存在移除的分阶段意图与最终读回；
4. 内部世界建立与子存在接纳；
5. 带统一预算、同截止整体成功的完整世界事实聚合；
6. 生产装配、现实根持久选择和旧逻辑迁移。

跨 owner 后继必须返回明确阶段、已发布事实、下一步与结果未知；不得用补偿删除伪造回滚或整体原子。上述后继不属于 v0.3 代码许可。
