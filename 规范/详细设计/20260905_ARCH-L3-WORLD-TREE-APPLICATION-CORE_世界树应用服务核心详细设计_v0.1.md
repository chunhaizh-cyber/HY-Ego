# 世界树应用服务核心详细设计

日期：2026-09-05

版本：v0.1

身份：`ARCH-L3-WORLD-TREE-APPLICATION-CORE`

状态：已冻结，等待代码实施

## 1. 目标与首叶边界

新建真实模块 `海中鱼巣/业务/应用服务.世界树类.ixx`，在不取得任何基础结构第二
owner 的前提下，把当前场景、存在、特征、状态和动态数据服务组合成现实世界树的应用级
作用域校验、成员关系操作与同截止读取。

首叶只操作**已经由其唯一数据服务建立的节点**。一次公开写入口恰好委托一个 DATA-L2
成员关系写；不把两个独立 owner 的“创建节点 + 接纳成员”伪装成原子操作，也不以补偿删除
伪装回滚。现实世界根由应用装配显式选择并不可变绑定；本服务不另存根事实、不扫描无父
场景猜根，也不建立第二根登记。

本叶实现：

1. 现实世界、单场景和世界内存在的同 `G0` 聚合读取；
2. 已有子场景在现实世界场景下的添加 / 移除；
3. 已有存在在现实世界场景普通成员中的添加 / 移除；
4. 已有状态、动态在场景事实目录中的登记 / 移除；
5. 已有特征在现实世界存在普通特征结构中的添加 / 移除。

这里的“添加 / 移除”只改变关系，不创建、修改、退出目标节点。状态和动态明确是场景事实
目录项，不是场景树成员。状态、动态本体不可修改；需要不同内容时由相应数据服务形成新
节点后再由本服务登记。

## 2. 正式依据与当前事实

- 0050、4030：`ARCH-L3/DATA-L3` 只组合 `ARCH-L2/DATA-L2` 公开服务，不直达 L1、
  不复制 CRUD、不取得第二 owner；`ARCH-L4` 需求、任务、方法不得反向进入世界树。
- 1140：子存在必须成为内部世界场景成员；状态、动态、需求、任务、方法不得进入存在普通
  特征结构；Vt/Vm 不是世界存在。
- 1150：场景普通成员只有子场景和存在；状态、动态及持久二次特征是事实目录项。
- 1160、1170：状态、动态是不可变事实；当前值变化不由世界树自动生成。
- 4200：树关系、当前 / 历史、同截止读取、关系替换和退出分账；现实世界资格由 DATA 之外
  的调用方选择。
- 4201：不得用未实现或空骨架冒充 CRUD。
- 4230：当前世界结构 owner、强类型服务与结构化失败边界。

当前 `cffb506992e90bc3f3b58b8e6160c39c7e03a94f` 已发布公开面中：

- 场景类：`新增场景/查询场景/查询场景树/新增成员关系/删除成员关系/删除场景`；成员种类
  只有子场景、存在、状态、动态；
- 存在类：`新增存在/查询存在/新增成员关系/删除成员关系/删除存在`，并含 ARCH-L4
  Vt/Vm 专用提供者；
- 特征类：`新增特征/修改特征/删除特征/查询特征`及派生特征入口；
- 状态类、动态类：不可变新增、退出、查询及组查询；
- 需求类、任务类、方法类属于 ARCH-L4，不能解释为世界成员。

当前场景类没有场景特征目录，存在类的`子存在/状态/动态`成员形状与 1140 的当前正式边界
不一致，且当前公开面没有“内部世界场景先归属世界根、再由宿主存在引用”的完整合同。
本叶不消费这些漂移入口。

共 11 个入口。类不可复制、不可移动；构造只拒绝无效根编码并保存服务引用和根编码，不
读取数据、不写事实。所有业务函数先校验版本、非零 `G0`、编码和正数预算，再以
`场景服务.查询场景树({v1,G0,现实世界根,预算})`证明本次操作的现实树作用域。不得把
缓存、无父关系、名称或调用者参数单独当作归属证明。

### 5.1 读取

`查询现实世界`按场景树返回顺序逐场景解析：普通存在成员经存在类查询；状态 / 动态目录
分别经对应服务查询。全部下游结果必须成功且事实代次恰等于 `G0`；任何一项失败返回零
场景载荷。每组按目标稳定编码升序且不得重复。

`查询场景`先证明场景属于绑定根，再形成同形单场景投影。`查询存在`证明场景属于根且目标
是该场景直接存在成员，再查询存在及其普通特征引用。存在当前读回若
含子存在、状态或动态成员，按正式边界返回`内部不一致`和零投影，不予解释；每个特征必须
经特征类在同一 G0 成功读回。

### 5.2 单 DATA-L2 写

每个写入口在同一 `G0` 完成根作用域与目标当前性读取后，只调用一次：

| 应用入口 | 唯一写调用 |
| --- | --- |
| 添加/移除子场景 | 场景类 `新增成员关系/删除成员关系`，种类=`子场景` |
| 添加/移除场景存在 | 场景类同入口，种类=`存在` |
| 登记/移除场景事实 | 场景类同入口，种类按请求映射为`状态/动态` |
| 添加/移除存在特征 | 存在类同入口，种类=`特征` |

添加子场景要求子场景当前、父为空且不在绑定树；移除要求其当前父关系精确指向请求父场景。
场景存在和场景事实写前分别由存在/状态/动态服务同 G0 读取。存在特征写前由特征服务同 G0
读取。提供者的`已添加成员/已移除成员`映射为对应应用成功，`精确重复`保持应用
`精确重复`；成员已存在/未找到、漂移、幂等冲突、引用冲突、资源失败、已可能发布和内部
不一致逐项映射，非成功不得带成员关系。写后结果只使用提供者返回的 Gend 和关系读回，
不再以旧 G0 拼载荷。

服务不自动重试事实代次漂移，不生成新幂等键。提交结果未知映射为`已可能发布`，调用方
必须用原请求重放；不得换键、补偿删除或声称零写。所有读取异常映射为`资源失败`或
`内部不一致`，不写日志、不吞异常为成功。

## 6. 明确后继缺口

以下用户目标不进入首叶，必须先形成相应数据提供者合同，不能由应用类临时拼装：

1. **现实根创建与持久唯一选择**：当前场景类没有 4200 的根标记/树归属公开投影；v1 只
   接受装配显式绑定的当前根候选，不宣称跨进程唯一现实选择。
2. **创建/删除场景、存在、特征、状态、动态并同时接纳**：跨 owner 时无共同原子事务；
   不能用两次写和补偿删除冒充原子成功。节点本体 CRUD 继续由各数据服务直接拥有。
3. **移动场景/存在、关系替换、特征修改后原子换接**：当前只有关系增删或特征换代，缺少
   对应 owner 的单事务替换公开合同；禁止先删后加冒充修改。
4. **场景特征/二次特征目录**：当前场景成员枚举没有特征，不能把特征伪装成状态、动态或
   存在成员。
5. **内部世界与子存在**：必须先建立独立内部世界场景归属，再由宿主存在持有正式引用；
   当前新数据服务缺此合同，存在类普通`子存在`入口不得被本服务消费。
6. **存在状态/动态**：1140 禁止成为存在普通结构成员；用场景事实目录和状态/动态自身
   结构表达，不暴露存在类现有同名成员入口。
7. **需求、任务和方法**：属于 ARCH-L4。Vt/Vm 绝不进入世界树；后继只能由 ARCH-L4
   应用服务按`所属存在`公开查询形成业务视图或业务引用，世界树不写、删、改这些事实。
8. **自动形成状态、动态、因果或业务真实性判断**：均不属于世界树结构组合职责。

或验证脚本，不建验证记录。不得声明编译运行、跨进程现实根唯一、完整 CRUD、内部世界、
需求/任务接线、旧逻辑替代、生产消费或业务验收完成。
