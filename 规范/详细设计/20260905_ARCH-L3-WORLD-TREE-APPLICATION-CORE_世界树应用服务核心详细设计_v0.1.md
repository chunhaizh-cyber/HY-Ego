# 世界树应用服务核心详细设计

日期：2026-09-05

版本：v0.2

身份：`ARCH-L3-WORLD-TREE-APPLICATION-CORE`

状态：语义总设计已修订；等待具名 DATA-L2 提供者

## 1. 修订裁决

用户明确要求世界树类实现现实世界语义，且单类关系操作必须留在对应数据类：场景父子、场景成员和场景事实目录由场景类拥有，存在特征和存在专用关系由存在类拥有，其余以此类推。因此 v0.1 冻结的 11 个“查询 + 单关系增删”入口全部撤销，不得实施、兼容或以私有转发重新导出。

世界树服务定位为 `ARCH-L3` 现实世界聚合语义编排与完整语义读取，只公开跨对象、现实世界级操作；它不取得 DATA-L2 owner，不复制对应类 CRUD，不直达 L1，不调用旧 L2。

## 2. 权威边界与层级

- 4200 只定义纯世界树结构；现实世界的选择由 DATA 之外的业务装配负责。
- 4230 把场景、存在、特征、状态、动态结构 owner 放在 `ARCH-L2/DATA-L2`，世界树聚合放在 `ARCH-L3/DATA-L3`，需求、任务、方法与 Vt/Vm 属于 `ARCH-L4`。
- 1140/1150 要求内部世界是场景子树：先归属世界根的内部世界场景，再由宿主存在持有专用引用；子存在是该内部世界场景的成员，不是存在普通子节点。
- 需求、任务只能经各自 ARCH-L4 所有者的`所属存在`关系形成业务视图；它们不是世界树节点、场景成员或存在成员。Vt/Vm 不得进入世界树。

因此不把完整目标提升为一个 `ARCH-L4` 服务。世界结构与事实聚合仍是 `ARCH-L3`；“某存在的需求/任务”是独立 `ARCH-L4` 业务视图，不进入本类 ABI。

## 3. 当前提供者复用与缺口

以 `8ce3298dedf4f7911b4023d8b8abf164facb240a` 为本次事实基线：

| 现实世界语义 | 当前可复用公开面 | 裁决 |
| --- | --- | --- |
| 根绑定/验证 | `场景类::查询场景树` | 装配显式绑定一个根；每次 fresh 读回根无父、树无环。当前不证明跨进程唯一现实根。 |
| 场景接纳/移出 | `场景类`新增场景与成员关系 CRUD | 单关系仍由场景类公开；世界树只提供“创建并接纳”语义。同 owner 创建+接纳尚缺原子入口。 |
| 存在进入/离开场景 | `存在类::新增存在`，`场景类`存在成员关系 | 异 owner；只能显式可续跑分阶段，不伪原子。 |
| 存在初始特征 | `特征类::新增特征`，`存在类`特征成员关系 | 异 owner，显式可续跑。不把裸特征关系增删重新导出。 |
| 更新存在特征 | `存在类::查询存在` + `特征类::修改特征` | 验证特征归属后由特征 owner 换代；可安全组合。 |
| 状态/动态发布与事实目录 | `状态类`、`动态类`新增/查询 + `场景类`目录关系 | 当前只能分阶段发布；现有状态/动态入口未闭合正式“前后状态+变化”原子语义，必须后续提供者。 |
| 场景/存在移动 | 当前只有两次独立关系增删 | 不可复用为移动；缺场景 owner 同事务关系替换。 |
| 内部世界 | 无 | 存在类尚无“宿主存在→内部世界场景”专用关系/读回；普通`子存在`不得替代。 |
| 完整世界事实读取 | 五类服务的带 G0 查询 | 可以“全部子读成功且代次全等”聚合；任一失败丢弃整体载荷。 |

最早独立可施工叶是 `DATA-L2-SCENE-MEMBER-ATOMIC-RELOCATION`，先在场景 owner 内闭合子场景/存在成员的原子迁移。本 `ARCH-L3` 只保留为总设计和后继路由，因仍有多个未闭合提供者，不登记为当前`待激活`库存；不在提供者前建立空世界树壳。

## 4. 目标语义公开面（消费者合同 v2）

目标模块仍为 `海中鱼巣.业务.应用服务.世界树类`，物理文件仍为 `海中鱼巣/业务/应用服务.世界树类.ixx`。它只 import 新 `数据服务.*`公开面。

撤销 v0.1 的 11 个签名后，v2 只冻结以下语义组，精确 DTO 在直接消费计划激活前按已发布提供者再对齐，不构成当前代码许可：

1. `验证现实世界根`：fresh 读回装配绑定根和完整场景树；
2. `推进创建场景并接纳`、`推进创建存在并进入场景`、`推进初始化存在特征`；
3. `更新存在特征`、`推进发布场景状态动态`；
4. `移动场景或存在`、`使存在离开场景`；
5. `读取完整现实世界事实`、`读取存在内部世界`。

“场景事实目录登记”、“存在特征关系增删”、“场景成员关系增删”不是世界树公开函数；它们只是上述语义操作内部的具名 DATA-L2 步骤。

## 5. 分阶段、事务与成功边界

同 owner 能以一个中性写集闭合的操作（关系替换、后续场景创建+接纳）必须由该 DATA-L2 类原子提交和读回，ARCH-L3 不拆成两次写。

异 owner 操作不宣称原子。语义入口使用不可变意图和每阶段独立幂等身份，返回：

- `已完成`：全部阶段发布，并以最终代次 fresh 读回完整语义；
- `待继续(下一阶段, 已形成稳定身份组, 下一期望代次)`：前阶段已发布，不回滚、不删除，使用原意图与原阶段幂等身份续跑；
- `结果未知(阶段)`：只能原阶段原幂等身份重放，不得跳阶段或换键；
- 其它非成功：带确定阶段与已发布事实，不夹带未证明的后继载荷。

续跑材料是值式诊断和幂等路由，不是交易、授权或第二事实权威。任一阶段的 G0 漂移必须返回结构化非成功，不自动重试、不补偿删除、不伪装整体零写或整体原子。

## 6. 完整读取与禁止投影

完整事实读取以一个非零 G0 调用场景树、存在、特征、状态和动态公开查询。全部结果成功、代次全等、关系端点/类型/当前性一致、预算未耗尽时才返回`已读取完整世界`。否则丢弃全部聚合载荷，保留失败类别与定位编码。不缓存跨请求投影。

需求、任务、方法、Vt、Vm 永不出现在世界节点组、场景成员组、存在普通成员组或完整世界快照中。后续 ARCH-L4 视图只能调用需求/任务类按`所属存在`的组读提供者，并保留其自身 owner 和失败。

## 7. 激活门禁与声明边界

本 ARCH-L3 计划当前不可执行。至少需先发布：

1. 场景类子场景/存在成员同 owner 原子迁移（当前叶）；
2. 场景类创建子场景并接纳的同 owner 原子提供者；
3. 存在类的内部世界场景专用引用/读回，以及不形成 import 环的场景当前性互证合同；
4. 状态/动态类符合 1160/1170 的发布提供者。

只有直接需要的提供者全部进入当前基线，才能把本计划重新修订为`可执行`并冻结 v2 精确 DTO。设计、计划或提供者发布均不证明世界树语义已实现、编译运行、现实根跨进程唯一、内部世界闭合、ARCH-L4 需求/任务视图或旧逻辑退役。
