## 1. 目标与最小闭环

本设计闭合 M1-A 的第一个真实根治理批次：普通应用在阶段20已经创建并停驻唯一self后，先启动唯一manager，生产一条可跨重启重放的首次双根触发，self工作线程在门仍关闭时消费该触发，完成budget-free fresh上下文读回、G4-A双根复核、既有初始化包恢复或正差距根的新包签发，把完整不可变包异步交给manager；manager独立复核、承接或恢复任务并再次读回任务核心和目标投影。只有本批self侧全部必要调用和异步投递成功，才真正开放治理运行门并进入后续根消息等待循环。

闭环固定为：

```text
阶段20唯一self已停门
-> 唯一manager线程就绪
-> 普通应用提交固定首次双根触发
-> self线程冻结首批消息，锁外budget-free fresh读回
-> G4-A同截止双根复核
-> 每根先按固定初始化意图恢复既有包
   ├─ 已恢复：无论当前是否满足，重投原包完成既有交接
   ├─ 未找到 + 当前满足：零新意图、零task owner写、零manager消息
   └─ 未找到 + 正差距：以当前复核截止签发一份新不可变包
-> self把每个既有/新包作为独立不可变消息异步交manager
-> self侧批次完整后开放门并进入治理循环
-> manager只用原包承接/恢复，随后按当前截止独立读回核心和目标投影
```

本叶只允许安全根和服务根。它不实现普通D、多D追加、任务筹办、worker、执行前选择、冻结、现实执行、结果、完成结算、安全值/服务值写入或后继子需求。

## 2. 正式依据与当前实现事实

正式依据为0050 v3.26、3100 v2.3、3200 v2.4、5090 v1.8、5170 v0.5、5260 v0.8、6120 v0.18、8000 v0.1、8100 v1.14、8120 v0.17、8200 v2.2、8300 v1.7和8310 v1.3。`SELF-ROOT-GOVERNANCE-INTENT-SINK` v0.3只保留后继边界；本文取代其未冻结的消费者部分，不恢复其中已经被0050 current-only裁决取消的历史读取要求。

当前代码事实：

1. `自我线程::运行()`只等待停止，邮箱只入不出；`复核前置并开放治理运行门()`固定返回`依赖未就绪`。
2. 普通应用唯一持有fresh provider、G4-A provider、task owner和self，但self只绑定fresh端口，零真实消费。
3. task owner已经提供签发/恢复、承接/恢复、核心读回和目标投影读回；旧任务v3已退出。
4. DATA-L1已经current-only，显式历史截止和退出后读回不再有生产资格。
5. fresh上下文公开请求仍含七项读取预算，内部仍调用旧预算世界树/真实自我接口。0050 v3.23/v3.26已经把这些预算合同降为旧ABI迁移识别，因此后继不能继续调用，也不能以极大值模拟无预算。
6. task owner现有`签发或恢复不可变初始化包(完整语义请求)`要求请求逐字段相同。重启后的fresh G已经变化，self仅凭固定初始化意图无法重建原`期望事实代次`，因而需要一个同owner的按意图只读恢复入口；否则“消息丢失/发布未知/重启恢复”无法成立。

## 3. 身份生产与不可混用边界

### 3.1 首次触发生产者

普通应用是首次触发的唯一生产者。固定值仅属于各自强类型命名空间，不是L1节点、事实代次、线程身份或任务事实：

```cpp
inline constexpr 自我线程消息身份 首次双根复核消息身份{0x5347524D00000001ULL};
inline constexpr 自我线程原请求身份 首次双根复核原请求身份{0x5347525100000001ULL};
inline constexpr 本能根任务初始化意图身份_v1 首次安全根任务意图{{0x5347495300000001ULL}};
inline constexpr 本能根任务初始化意图身份_v1 首次服务根任务意图{{0x5347495600000001ULL}};
```

这些常量放在`装配.普通应用.cpp`私有命名空间，不进入公共配置，不允许调用方改写。每次进程启动都生产相同完整首次消息；相同身份正文不同固定为逻辑冲突。安全、服务两个意图必须非零且互异。

### 3.2 一般根复核消息

旧`自我线程根需求复核消息_v1`物理替换为v2，不保留兼容入口：

```cpp
struct 自我线程根需求复核消息_v2 final {
  std::uint32_t 合同版本 = 2;
  自我线程消息身份 消息;
  自我线程原请求身份 原请求;
  自我线程复核触发根 触发根 = 自我线程复核触发根::双根;
  自我线程需求身份 正式需求定位;
  本能根任务初始化意图身份_v1 安全根任务意图;
  本能根任务初始化意图身份_v1 服务根任务意图;
};
```

完整性规则：双根触发要求需求定位为空、两个意图完整且互异；单安全根要求定位等于锁定安全D、安全意图完整、服务意图为空；单服务根对称。消息身份只用于self邮箱去重，原请求只用于本轮G4-A和消息链关联，任务意图只用于task owner包恢复/签发，三者不得数值互换。

self到manager的消息身份由self对象内单调非零输出序号产生，命名空间只属于该进程内通道；它不持久化、不充当任务意图。跨进程恢复只依赖消息携带的原不可变包和包内task owner技术幂等身份。

实现只读取task owner私有当前预留记录与技术幂等首次材料。零命中返回`未找到`；恰一且完整但尚未承接，或已经承接且对应T生命周期仍为`当前可治理`，返回`已读取`和原包；若初始化回执已经定位T而该T为`已完成/已失败/已取消/已退出当前资格`，返回`当前任务不可复用`并携带原包供具名诊断，self不得投递也不得签第二包；多命中、错owner、错材料、首次请求/结果不闭合或T生命周期载荷不合法返回`内部不一致`；G变化返回`事实代次漂移`；资源失败单列。除`已读取/当前任务不可复用`外其它状态清空包。它不签发号段、不建立T、不改变高水位。self读回包后必须核对包内角色、D、L、根形成F和意图与本次fresh复核根一致；旧包的`期望事实代次`只说明原签发并发前置，不要求等于新Gread。错业务来源为`消息冲突/引用冲突`，不得另签新包。

每根处理顺序固定为“先按意图恢复，再按业务结果决定是否新签”：因此当前满足严格表示零**新**意图；已经发布的同一意图仍必须恢复并完成原交接，避免重启后遗留半初始化。

### 6.3 manager消费与自主重试

消费固定为：

1. 校验消息、来源消息、原请求和包完整；消息正文不得改写包。
2. 调用`恢复任务初始化(原包)`；该入口与`承接或建立任务`同义收敛，manager不签发、不换键。
3. 总状态为`已完成/精确重复/已承接到当前任务`且有完整核心后，以返回G调用`按任务读取核心`和`按任务读取目标投影`；逐字段核对T、D、L、根角色、根形成F、P1和`Vt状态=待找方法`。
4. `事实代次漂移/已可能发布`允许在同一次消息消费内仅用原包再调用一次恢复；第二次仍非成功以及资源失败，均保留当前消息和原包，由manager自己以固定10毫秒可中断等待后重新执行同一消费，不依赖self回执或同消息重投，不换消息、不换包、不增加业务事实。停止请求立即打断等待。非恢复性冲突记录具名失败并清除当前项，不迁移任何额外业务状态。
5. 成功后清除当前项并增加“已独立读回承接数”。迟到同义消息可以再次调用owner并精确收敛，不建立已处理持久账。

停止采用有界排空：停止请求后拒绝新消息，打断自动重试等待；已经接收但尚未完成的每项从停止观察点起最多执行一轮上述正常消费及其一次原包恢复重试。仍为可恢复失败的项只记录“停机未完成”诊断后退出线程，不无限等待。内存消息无需持久化，下一进程由固定首次触发和按意图读回原包继续收敛，因此`等待停止`必须能够在具名等待时限内完成或明确返回等待超时。

manager不生成筹办工作包、不启动worker、不迁移`待找方法`之后状态，不向self发送“需求满足”或“任务成功”消息。

## 7. self工作线程算法与G2-B

### 7.1 依赖绑定

`自我线程::创建并停在治理运行门`原位扩展为接收四个非拥有端口引用：budget-free正式上下文端口v2、G4-A根复核端口、task owner端口、manager sink。第一次创建锁定请求和四个端口地址；同请求但任一端口地址不同返回选择冲突。创建阶段仍零调用全部端口、零消费邮箱、门关闭。

现有`自我线程操作状态`只追加稳定值`根初始化代际已结束=12`，既有数值不变。它只用于按固定首次意图读回到非`当前可治理`任务时的开门结果；此时生命周期保持`已停门`、`写业务事实=false`、不锁存内部错误，但本次开门终止且不得自动重试。后续只有新的正式意图合同才能重新推进。

### 7.2 首批与后续批次

`复核前置并开放治理运行门(等待毫秒)`不在调用线程调用provider。它只在锁内登记一次开门控制请求并等待工作线程形成结果。worker确认manager sink真实就绪后，将调用时已经在邮箱中的全部消息交换为本批；新到消息进入下一批。首批必须包含普通应用固定首次双根消息且正文精确一致，否则不开门。

self只在“邮箱中尚未冻结的消息 + 当前冻结批 + 当前处理消息”范围保留消息身份和完整正文，容量受邮箱容量及冻结批大小约束。在该活动范围内，同身份同正文是精确重复且只保留一份，同身份异正文是消息冲突。某消息批成功或具名非恢复失败收口后立即释放该指纹，不建立已处理消息账；此后迟到的同身份消息作为新消息重新执行完整校验和业务幂等收敛，不能声称检测历史异义。

worker逐消息锁外执行：

1. 以锁定启动材料调用fresh v2，完整成功后取得新Gread。
2. 以该投影和消息的触发、D、来源消息、原请求调用G4-A；必须双根技术状态都已复核、同Gread、零业务写。
3. 只处理触发覆盖的根，顺序固定安全后服务。每根先按消息携带意图调用按意图恢复；命中则校验并交manager；未命中且当前满足则零动作；未命中且正差距则构造`本能根任务初始化语义请求_v1{1,意图,Gread,{角色,D,L,根形成F},nullopt}`并签发包，再交manager。
4. 任一fresh/G4-A/task owner的`资源失败/事实代次漂移/已可能发布`，或sink的`队列已满/尚未就绪/资源失败`，都保留门关闭、当前消息和已取得原包；worker以固定10毫秒可中断等待后自动从fresh重新执行同一消息，重试时先按意图恢复，直到成功、停止或出现非恢复性失败。不得依赖调用线程再次开门、manager回执或外部重复投递，不得忙循环。入口拒绝、消息/引用冲突、结构内部不一致及其它非恢复状态锁存具名失败，门保持关闭并结束该次开门等待。
5. 全批成功后增加冻结批次数和成功治理批次数，先在锁内写`治理运行门开启=true`、生命周期`治理中`和`治理循环已进入=true`，再通知等待者。开门成功不要求manager已经完成异步任务建立，也不把投递成功写成任务事实。
6. 开门后循环持续按“等待消息/停止 -> 冻结当前完整批 -> 相同处理算法”运行；空队列只等待，不形成空成功批次，不按定时器创造根任务。

停止优先唤醒。已经取得不可变包但尚未投递时，停止不删除包；重启由固定首次意图读回。self停止后不再向manager投递，普通应用再令manager排空已经接收项并停止。

固定首次安全/服务初始化意图只覆盖各根第一项仍处于`当前可治理`生命周期的任务。按意图恢复到的包若对应任务已经`已退出当前资格`或owner返回当前任务不可复用，本叶必须锁存`根初始化代际已结束`具名失败、禁止签发第二包且门保持关闭；后续根任务的新意图来源属于任务结算后的后继设计，不在本叶用固定意图猜测。

### 7.3 G2-B真实成功条件

一次开门结果为成功必须同时满足：

- 同一self对象仍持有阶段20完整停门见证；
- 四个端口地址与创建锁定选择一致；
- 唯一manager线程已经真实进入接收态；
- 固定首次消息已经由self线程而非调用线程完成budget-free fresh、G4-A和每根恢复/零意图/签发分支；
- 所有需要交接的不可变包已由manager有界队列接受或精确重复；
- 门状态已经在对象锁内写为开放，worker已经发布治理循环进入见证；
- 无内部错误锁存、无停止请求，非成功零开放。

重复开门在相同对象已经开放且首次结果完整时返回精确重复；未确定是否开放的异常不得伪装成功。

## 8. 普通应用唯一装配与生产调用

普通应用上下文按依赖顺序持有task owner、唯一manager对象、fresh provider、G4-A provider和唯一self。阶段20仍先创建并停驻self；manager对象存在但线程未启动。

新增：

```cpp

自我线程操作结果_v1 停止并回收普通应用治理线程() noexcept;
```

启动函数在普通应用锁下：启动manager并等待真实就绪；提交固定首次消息；调用同一self的开门入口并等待治理循环进入；任一非成功按“停止self -> join self -> 请求manager排空停止 -> join manager”收口。普通控制面板模式仍不启动manager、不开放门，按现行阶段12真实失败返回并只回收self。

无窗口常驻模式在阶段20成功并安装停止信号后、进入`运行无窗口宿主`前调用启动函数。非成功安全回收后返回`程序运行状态::宿主失败 / 程序失败阶段::无窗口常驻(13)`；不复用已明确只属于阶段20停门失败的枚举，也不新增失败阶段。宿主结束后调用治理线程整体回收。`生产运行期`模式保持现行独立宿主，不在本叶伪装已装配普通应用治理。

## 9. 重复、乱序、队满、丢失与重启矩阵

| 情形 | 收敛规则 |
| --- | --- |
| self活动范围内同消息同正文 | 精确重复，只保留一份；活动范围释放后的迟到消息作为新消息重判 |
| self活动范围内同消息异正文 | 消息冲突，零新业务效果；已释放历史不建立消息账，也不声称可检测历史异义 |
| manager队满 | self本批非成功、门不开；保留同意图包，10毫秒可中断等待后自动从fresh重试并先恢复包 |
| 安全/服务消息乱序 | manager逐包独立处理，不以队列次序决定根角色或目标 |
| task owner签发成功、投递前中断 | 重启固定意图按意图读回原包，不使用新G另签 |
| manager接收后进程中断 | 重启固定触发恢复原包，manager调用恢复入口并独立读回 |
| 核心/P1/首迁移任一发布未知 | manager只用原包恢复；不得换三项键 |
| 当前满足且从未签包 | 零意图、零task owner写、零manager消息 |
| 当前满足但已有同意图包 | 只恢复并完成既有交接，不产生第二意图 |
| 同意图恢复包业务来源与fresh根不一致 | 引用/消息冲突，禁止另签或任选 |
| manager独立读回G漂移 | 原包一次恢复刷新G；仍漂移则manager保留原消息/原包并按固定间隔自主重试 |
| 固定意图对应T已退出当前资格 | 锁存根初始化代际已结束，禁止签第二包且门不开；新意图留给后继设计 |

不建立持久outbox、消息处理账、第二任务账或manager成功事实。消息丢失只通过固定首次触发、按意图包恢复和task owner原技术幂等材料收敛。

## 11. 失败、验证与完成边界
