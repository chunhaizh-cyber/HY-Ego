# SYSTEM-WORLD-TREE-ROOT-PUBLISH-I1 系统具名场景树根验证注入边界详细设计 v0.3

日期：2026-08-13

## 1. 来源问题与裁决

本修订只处理执行侧具名退回 `DRIFT-I1-VALIDATION-INJECTION-BOUNDARY-MISSING`。正式起点为 `428c667b7127aaa8f86a5c3d2678d5815ebc3b3d`；I1 v0.2 的公开 DTO、状态机、provider-only、A1 同实例、R1 正式读回、阶段 15 永久退出和启动 `NOT_RUN` 均不改变。

现有生产实现把完整状态机直接写在 `海中鱼巣/装配.普通应用.ixx` 的导出根函数中，且固定从普通应用取得 final R1。生产外专项只能驱动真实成功路径，不能确定地形成待收敛、四阶段失败、未知提交或坏成功投影；继续要求专项覆盖这些分支而不提供合法驱动边界，会导致不可执行验证合同。

裁决是在 I1 原目标内建立一个**生产内部单源编排 seam**：正式入口和生产外专项分别用真实访问器与脚本化访问器实例化同一份函数模板正文。该 seam 是生产实现结构，不是公开服务、测试钩子或第二套业务逻辑；生产路径不接收故障选择、脚本、计数器或测试配置。

## 2. 不变合同

- `系统世界树根初始化请求`、`系统世界树根初始化状态`、`系统世界树根发布来源`、`系统世界树根读回`、`系统世界树根初始化结果` 逐字段保持 v0.2；不得增加 `operator==`、测试字段或公开适配器。
- 唯一公开根函数仍为：

```cpp
系统世界树根初始化结果 初始化并发布系统世界树根(
    普通应用上下文& 上下文,
    const 系统世界树根初始化请求& 请求) noexcept;
```

- 普通应用上下文仍只有一个锁、一个待收敛请求槽和一个值式发布槽；getter 仍按值返回。
- 生产入口仍只经 `取得L2结构聚合服务().取得L2场景结构服务()` 取得 A1 同实例 R1；不得直连仓库、L1、raw、第二服务或扫描入口。
- v0.2 第 6—7 节的首次、重放、重复、失败、保留、发布、异常和并发语义全部原样成立。

## 3. 单源内部编排的物理合同

新增生产内部头：

```text
海中鱼巣/业务/初始化系统世界树根.内部编排.h
```

该头：

1. 不含 `export`、模块声明、公开 DTO 或标准库 `#include`；包含方必须先提供标准库、R1 DTO 和 I1 DTO。
2. 只定义 `namespace 海中鱼巣::系统世界树根初始化内部` 中的 `inline` 辅助函数和一个函数模板；它们不进入任何导出块。这里的“生产内部”只表示未导出实现边界，不声称函数模板具有 C++ internal linkage；模块接口实例与普通专项翻译单元实例来自同一源码正文。
3. 在 `装配.普通应用.ixx` 的 module purview 中，于 R1/A1 import、I1 DTO 导出之后普通包含；不得放入 `export {}`。
4. 生产外专项在 `import 海中鱼巣.装配.普通应用;` 之后普通包含同一头；专项因此编译同一算法源码，而不是调用模块内不可见名字。
5. 根工程和 filters 将该头作为普通 `ClInclude` 唯一登记；它不建立翻译单元、模块、分区或 IFC。

唯一编排函数形状冻结为：

```cpp
template<class 场景结构访问器>
系统世界树根初始化结果 编排系统世界树根初始化(
    std::mutex& 发布锁,
    std::optional<L2场景树根建立请求>& 待收敛请求,
    std::optional<系统世界树根读回>& 已发布读回,
    const 系统世界树根初始化请求& 请求,
    场景结构访问器& 场景访问) noexcept;
```

编排函数完整拥有 v0.2 根函数中的请求校验、锁、选择裁决、待收敛状态机、R1 三能力调用、逐字段互证、结果构造、无抛出交换及异常映射。所有逐字段比较 helper 同置于该内部头；不得向 DTO 增加运算符。

`场景结构访问器` 只按表达式合同提供：

```cpp
L2场景树结构登记结果 读取当前场景树结构登记();
L2场景树节点写入结果 建立场景树根(const L2场景树根建立请求&);
L2场景树读取结果 读取场景树(const L2场景树读取请求&);
```

函数模板不保存访问器、不取得其所有权，不要求虚基类，不把访问器类型写入公开 ABI。调用期间访问器由调用方拥有且必须保持有效。

## 4. 正式入口与专项调用关系

正式入口只做两件事：

1. 经 A1 聚合取得当前普通应用持有的同实例 `L2场景结构服务&`；
2. 把上下文三个私有状态引用、正式请求和该真实服务引用交给 `编排系统世界树根初始化`，原样返回结果。

`L2场景结构服务` 本身满足访问器表达式合同，无需生产适配类、虚调用或复制服务。精确 friend 仍只授权正式入口读取上下文私有成员；内部模板不成为 friend，也不接收上下文对象。

生产外专项定义自己的脚本化访问器。它只拥有预置返回队列、抛出动作、调用次序和计数；这些字段、枚举和分支不得进入内部头、普通应用、DTO、根工程或生产项目。专项以自己的 `std::mutex` 和两个 `optional` 状态槽调用同一模板，因此可以确定驱动失败矩阵而不破坏真实普通应用对象。

真实入口仍须以 final R1 覆盖首次、已发布重复、值式隔离、并发以及 A1/普通应用/I1 同址；脚本化专项只补足确定性状态机分支，不替代真实 R1 主路径证据。

## 5. 状态、异常与所有权

- 锁获取和全部状态判断都在模板内，锁的生命周期覆盖一次完整编排；同请求并发仍串行。
- 待收敛请求和值式发布槽由调用方拥有；模板只在 v0.2 指定的线性化点写入。访问器返回对象均按值由模板拥有。
- 脚本化访问器抛出 `std::bad_alloc` 只验证同一 catch 边界映射为 `资源失败`，不得宣称真实分配器耗尽已运行；其它异常验证 `内部不一致`。
- 真实资源耗尽、跨进程恢复、正式启动、阶段 14—18、I2、自我、概念和独立集成验收仍如实 `NOT_RUN`。
- 生产内部头不得出现 `测试`、`故障注入`、`脚本`、计数器、sleep、环境变量、预处理测试宏或运行期模式分支。生产正式入口不得接受替代 provider。

## 6. 验证闭合

专项至少形成以下具名证明：

1. 固定身份与 R1 四个保留身份不同；无效版本、非固定身份和已发布/待收敛异选择均在访问器调用前拒绝。
2. 首次严格为登记读、根建立、登记再读、整树读；已发布重复严格为登记再读、整树读且零根写。
3. 根建立失败后同请求逐字段重放原完整请求；事实代次即使外部变化也不得改写已保存请求。
4. 首次登记、根建立、读回登记、整树读取四阶段分别失败并短路，逐状态 optional 形状准确。
5. 明确零变化漂移清除待收敛；资源失败、提交未知及根提交后读回失败保留原请求。
6. 成功状态配坏 optional、树身份、根标记类别/端点、根父关系、首次生命周期、零/错截止均拒绝发布。
7. 既有发布值在上述失败和异常前后逐字段守恒；getter 值式隔离；同请求并发串行；异请求不建立第二根。
8. 真实普通应用路径证明 A1 getter、直接场景 getter和正式入口实际服务同址，且 final R1 主路径首次与重复通过。
9. 静态扫描证明正式入口只有 A1 取服务与单次委托；状态机正文只在内部头一份；生产无测试宏、脚本、计数器、故障选择和额外公开 ABI。
10. Debug/Release 根工程与完整专项均通过；strict、UTF-8/XML、工程唯一登记和白名单通过。

专项输出必须逐项列出上述矩阵，不得再用一个总 `NOT_RUN` 掩盖强制分支。脚本化 `bad_alloc` 只写为“异常映射 PASS”，真实分配失败仍单列 `NOT_RUN`。

## 7. 完成边界

本修订只使 I1 v0.2 已冻结状态机可由生产与专项合法共享并确定验证，不改变根事实、业务选择或公开 ABI。完成仍最多证明 I1 provider 经 A1 同实例 R1 建立/收敛并正式读回发布；不证明正式启动、I2、自我或概念初始化完成。
