## 1. 不变的认知边界

```text
特征当前值 = 业务比较权威
状态 = 某时刻事实记录
动态 = 已发生变化记录
因果 = 变化关系记录

状态 / 动态 / 因果 = 三类认知证据
任务 / 需求 / 方法 / 结算 = 独立治理事实
G0 / 幂等 / 事务 / 读回 / 恢复 = 工程正确性材料
```

旧任务治理状态、目标裁决证据和重筹办来源继续只读兼容；不得首次新建、复义或作为 current 任务状态权威。

## 2. v0.2 代码叶为何不可执行

正式 HEAD 不包含：

```text
发布任务筹办正式选择_v2
形成当前可执行冻结_v2
对应 v2 DTO 与完整有序动作组 v2 provider
```

这些符号只存在于未提交 SELF WIP。v0.2 的三个目标文件还依赖未跟踪 module、dirty 数据头和 dirty 工程登记；三文件整体提交会夹带其它 WIP，局部暂存 v2 hunk 又会形成不可编译提交。因此 v0.2 不再具有 `可执行` 资格。

## 3. 最早可独立发布叶

最早叶只修改正式 HEAD 已有的两个公开入口：

```text
L2任务结构服务::新增执行结果待验证状态(...)
L2任务结构服务::提交目标未达成待重筹办迁移(...)
```

共同顺序冻结为：

```text
请求静态有效性
-> 无条件读取本 owner 首次幂等账
-> 未找到：入口拒绝、截止0、空载荷、零写
-> 已有完整账：重建首次语义并精确重放
```

禁止先读取 current 业务事实、查“已消费”旁路或构造 proof 写集后才判断首次账。

## 4. 已有账精确重放

已有账必须同时满足：

1. 首次规范化写集与首次写入结果均存在；
2. 首次写集的期望事实代次等于本次请求 G0；
3. 首次写集的幂等身份等于本次请求幂等身份；
4. 首次结果能够定位该入口所需的旧治理状态、目标裁决证据和可选后继记录；
5. 历史投影与本次请求逐字段同义；
6. L1 重放只允许返回 `精确重复`，且 G1 和新编码映射等于首次结果。

必要本地键不存在表示同键不是本入口原写集，返回`幂等冲突`；键存在但历史投影或闭包损坏返回`内部不一致`。L1 意外返回首次`成功`、G1 不同或编码映射不同均返回`内部不一致`，不得形成空载荷成功。

## 5. 无账与现行调用影响

正式 HEAD 仍登记旧重筹办触发器，并直接调用两个 legacy 入口。最早叶发布后，这些调用会结构化 `入口拒绝`，不会再生产治理状态、目标裁决证据或后继准备记录。

这是认知证据边界的 fail-closed 止血结果，不宣称旧调用已经移除，也不宣称执行后结算链已经接通。调用移除、正式选择 v2、current provider v2 和执行后结算必须等待其真实 ABI / provider 正式发布后形成后继计划。
