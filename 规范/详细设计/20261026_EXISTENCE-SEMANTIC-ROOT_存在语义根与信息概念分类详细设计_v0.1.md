# 存在语义根与信息概念分类详细设计

标识：EXISTENCE-SEMANTIC-ROOT；版本：v0.1；日期：2026-10-26。

代码起点main `e3fadc7ab970ebd543b0c4c996c15dc19be49b7e`加root保留WIP。根语义依据用户本窗口裁决：存在是正式存在根概念；需求、任务、方法为其直接下位，保留原信息身份和内容。不是把组织根当概念，不把D/T/M改造成普通存在，也不建立影子对象。

## 1. 首叶目标和替代边界

建立语言无关、owner唯一登记、可零实例形成的“存在”语义根；普通存在范围和先天D/T/M结构共用它。新根仍用现有普通抽象存在概念物理身份承载，确保现有“存在＝通用存在”规格读取不中断。结构概念可引用它为直接上位，字段展开将其视为唯一受控的零字段、零约束基例。新共同分类只读入口读回两类分类边，并由普通应用启动直接消费。

本叶落实“存在”类别内的共同分类，不迁移参数信息类型枚举、不扩D/T/M实例到`新_存在类`普通存在读取器、不重造D/T/M、Vt或Vm，不强制所有基础范围/约束/成员组织概念成为D/T/M的同类。更远统一ABI及语言查询仅保留路线。

7165第5.1节“不恢复所有对象必经永久本体总根”与本用户具名裁决冲突的部分，不用来阻断此存在类别内首叶；仍不把全部信息种类、特征概念或动态概念移入本根。7165第2.1、2.3、3.2及5.2—5.3的信息身份、结构构成和多上位无环仍有效。所有写入由现存在概念owner经基础数据集原子能力完成，不改规范或建立第二仓。

## 3. 唯一根身份与新公共合同

唯一owner为`概念_存在类`，仅扩展其现有h/cpp，无新代码文件、工程项、全局第二树或新owner。新增概念schema键`存在语义根字段`，作为物理组织根上的可选单引用：

```text
物理组织根 --存在语义根字段--> R
R：普通抽象存在概念、无自身FT、无具体存在绑定、无分类父
```

字段负责定位唯一R，不承载第二份定义。schema键随本owner初始化及结构存在性检查纳入；无值表示尚未建立，多值/错引用属于结构损坏，不能另建根。R不登记到先天正式结构槽map，不伪造槽0，不让先天读取遍历R时误把它当正式结构定义。

冻结新增公共类型和签名如下，均位于`领域/概念_存在类.h`，定义在同名cpp：

```cpp
struct 存在根建立请求 final {
    std::optional<稳定编码> 既有根候选;
    std::vector<稳定编码> 必要直接下位普通概念组;
};
存在概念建立结果 建立或取得存在根概念(const 存在根建立请求&) noexcept;
普通存在概念定义保护结果 读取存在根概念保护() const noexcept;

enum class 存在分类概念形状 : std::uint8_t {
    普通专属=1, 普通抽象, 信息结构
};
struct 存在分类关系信息 final {
    稳定编码 概念节点;
    存在分类概念形状 形状;
    std::vector<稳定编码> 直接上位概念组, 直接下位概念组;

struct 存在分类关系保护结果 final {
    正式结构操作状态 状态=正式结构操作状态::输入拒绝;

```

根读取无登记返回`正式概念读取状态::非本提供者概念`且无载荷；未初始化用依赖未就绪，前提变化保留现状态。建立入口使用现`存在概念建立结果`状态：新建已建立，同根/同关系已复用，合法首次接管或追加分类已更新；错候选/异义已登记返回结构不一致或入口拒绝，前提变化用现结构不一致并由调用方重新读取，不新增业务失败值。已确认的正式材料损坏走现工程日志/弹窗终止，不返回假空让app再创建。

## 4. 首次创建、旧根接管和普通分类

### 4.1 名称只用于查候选

app私有定位器明确区分未找到、恰一合法普通概念、多义/损坏，不能继续复用`读取连接具名概念`的optional把多义当未找到。只检查正式词条/名称关系；多个关系指向同一节点可归一，两个不同目标拒绝。其他非普通类别同名目标也不得跳过后选择普通目标。没有旧候选才允许请求新根；名称不是根判据，最终以owner根登记为准。

定位器不取得跨owner原子命名保证。app按“候选查询→owner完整核验/原子根发布→名称建立/正式读回”分段；命名失败保留已发布根，不再建第二根。启动不得在根命名及最终分类读回完成前放行后继。

### 4.2 owner完整准入

根已登记时：完整核其普通抽象身份、恰一组织归属、零FT/零具体存在/零上位、允许字段及所有分类端点；候选为空则复用，候选等于R则复用，候选指另一节点则拒绝。不能按“名字相同/特征为空”替换已登记身份。

未登记且候选非空时：仅接管当前普通抽象、无FT、无具体存在绑定、无上位、组织归属完整的旧分类；既有子链及名称原样保留，完整核其普通role2分类端点/无环，不改旧身份或已有引用。非法字段、多重类型、未知组织归属或类别冲突拒绝，不能另建替代物掩盖。

未登记且无候选时：通过一次基础原子追加建立普通抽象R、类型字段、组织归属和组织根唯一登记；允许零子、零实例、零名称。不是调用“建立人工抽象存在概念({自我})”，不依赖某个自我/服务对象存在。根登记是零字段根有效性的必要证明，普通getter、普通定义保护、正式身份保护对零子R必须读入并复核登记快照，不放宽任意空抽象。

必要直接下位组仅允许已存在合法普通概念，去重后核不是R、不会成环；对缺失的R→子role2边与根登记同事务追加，对已有恰一边复用，重复边/错类型拒绝。多上位合法，不删除已有父链。app本叶只要求人类为直接下位；旧R→自我专属等边原样保留，不扩成自动重连全部普通概念。

所有相关schema、组织根、候选/子节点及分类端点以完整联合快照形成预期，一次CAS发布。CAS前提变化不得留下半根或部分分类；发布后完整读回R及请求下位。发布后故障保留事实，不拆除已被引用根，技术重试以原请求和同根读回复用。

## 5. 唯一父边与共同分类只读

普通专属/抽象的父边唯一来源为外部父子role2；正式信息结构的父边唯一来源为正式上位字段。**不把结构父字段再镜像成role2，不把普通父边再镜像成正式字段。**同一节点两套父承载同时出现视为结构错误，不能取并集掩盖。

共同读取只接普通专属/抽象及信息结构三种形状，不把基础范围、结构约束、成员组织或裸组织节点误认存在分类节点。输入不是这三种返回未找到/输入拒绝；正式类型已经确认但结构损坏必须工程报告。直接上位按自身形状读唯一承载；直接下位从普通role2出边与正式上位字段反查取得，核对反向一致及目标类型，去重仅用于确定排序，不隐藏重复事实。

新入口返回直接父子及其定义/分类保护，不读取D/T/M具体实例。对所遇父链用活动栈与完成集合分别检查环和DAG汇合，保护覆盖组织归属、节点类型、分类字段/边与根登记，统一重读后返回；前提变化零信息返回。无父/无子合法，空组不同读取失败。旧`查询上位/下位存在概念`和下位专属实例候选入口保持普通语义，不因为新共读接口而将D/T/M编码交普通存在服务。

具体而言，旧普通查询及`读取下位专属实例候选完整`仍只枚举role2普通分类边，不沿正式上位字段反向进入D/T/M结构分支；因此不调用普通`获取存在概念`解码D/T/M，也不把结构概念当专属实例候选。R的完整快照仍包含来自结构子类的上位字段入向引用并参与前提保护，但不据此扩展旧实例遍历域。旧API不得称为“全部信息存在实例枚举”；跨表示概念分类由新API承担。若role2边本身错误指向结构节点，须报告错误而非作为合法普通边跳过。

app使用新入口真实核：R无父；R直接子至少含人类、需求、任务、方法（旧其他子保留）；D/T/M各有且只有一个直接父R。该调用构成新查询提供者的实际生产消费，不新增无人使用接口。

## 6. 正式结构解码、展开和模板

在`定义模板`增加私有`std::vector<稳定编码> 普通上位引用组`，保留现槽号上位组；模板定义及编译模板均将两者写入**同一个**正式上位字段，交叉重复拒绝。三类定义模板接收真实R编码，仅槽1/2/3添加R；原子模板登记map仍只有真实先天槽，支持定义、子需求概念、约束及FT引用全部原样。

`解码正式定义`在读取结构上位R时捕获普通根及唯一登记证明，不尝试把它解码成`正式结构概念信息`，也不把R加入正式定义map；其他上位仍按原结构递归。`核正式结构图`展开父链遇R时，仅在快照中完整证明其为唯一登记零字段根后返回空内容/空约束基例；任何其他普通抽象父仍拒绝。父链环、重复父、非法收窄/继承冲突仍按原规则，不因空根放宽。

`读取正式结构工作保护`、正式定义批准备/发表/读回及有效内容展开均纳入相同根证明。不能只让读取getter跳过根而在发布前`核正式结构图`再次拒绝。以R为父不增加D/T/M内容字段，不重复继承“所有存在共同字段”；原完整结构判定及内容owner不变。

## 7. 存量D/T/M安全迁移

迁移为本owner具名私有函数，在现先天初始化完成FT准备后、`准备定义批(三类模板)`之前运行。输入为新R、现dep及已完成FT槽；复用三类模板构造**旧定义**（根父均空）与**新定义**（仅1/2/3父为R），不按字段数量猜旧版。

准入仅三态：

1. 槽1/2/3全部未存在：不迁移，按新模板正常同批建完整三类及支持定义。
2. 三根全部存在，所有本次三类模板当前定义与精确旧模板完全相同，三个根父均空：准备同批追加三条上位字段，保持三根、内容项、支持定义、引用、名称及所有子概念身份不变。
3. 三根全部与新模板完全相同：只读复用。

三根部分存在、部分旧/新父、额外未知父、不同R、其他字段/支持定义异义均返回定义冲突并停止受影响装配，不“能推断就补”、不删除或替换节点。独立已存在的自我需求等后续子类可保留，但其定义读取和继承必须在本次完整保护中合法；不要求把其复制到新树。

一次CAS保护包括根登记、全部相关定义快照、三根现有入出向引用和新字段键；只追加三个父字段，不替换已有内容。预期不符返回前提已变化，重试先重新读回；成功后按**新模板**完整读回及共同分类API确认三根父均为R。禁止发布一根后继续另一根，不以名称驱动逐根搬迁。

迁移不要求物理删除任何旧信息，不改D/T/M具体实例、Vm/Vt及方法规格。旧根接管已保留原身份，故现存通用存在范围引用无需替换。遇不能完整追溯的结构保留并报告，不建立替代根绕过。
