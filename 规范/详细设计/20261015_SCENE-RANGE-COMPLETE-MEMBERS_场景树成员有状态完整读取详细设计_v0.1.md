# SCENE-RANGE-COMPLETE-MEMBERS 场景树成员有状态完整读取详细设计

日期：2026-10-15
版本：v0.1
设计代码基线：`1ef6747579380b3ad0ddc41e99bca149f970d4f1`。

## 1. 目标、来源与完成边界

S01 已提供默认现实根下 `A是人` 一类技术占位符的只读归类提议，并在实际项目 `Debug|x64` 编译链接；未运行测试、未接生产调用。后继汉字对象指称若把词条的存在概念候选拿到现实场景寻找 E，必须先知道所查场景成员是否**完整**。现有 `新_场景类::查询场景范围存在` 及其直接成员/子场景子查询用裸 `vector`，真实空集、非法/失效节点、结构异常及资源失败可同为 `{}`；子查询失败还可能使父范围返回部分非空集合。`获取场景` 也消费这些裸列表。此时按结果数量选唯一 E 会把未查全冒充唯一。

本叶仅由场景结构 owner 增加一个**有状态、只读、无资源预算的本树范围成员读回**。完整语义范围固定为本服务当前根场景及其全部可达子场景的全部直接普通成员 E；它返回 E 及其直接所属场景，只有所有遍历和末端互证完成才给 `已完成`，真实空成员集也可明确返回 `已完成`。资源不足返回`资源失败`并清空候选，不能缩小必要闭包。其它状态同样不提供可被解释为完整候选域的部分结果。它不读词条、名称或概念，不选择 E，不建立或修改场景、成员及世界事实，也不决定哪个世界是现实世界。

该提供者只解除后继候选域读取缺口。`杯子`经词条和概念名称只能形成概念候选，不能直接成为世界 E；`杯子A`若是实例专名/别名，依 7200 §4 应由实例所属领域的别名合同处理，不能偷写到 2210 的专属概念名称关系中。后继语言业务须另外核对现实世界根、词条/概念候选、实例名或描述的有效依据、E 的唯一性及来源。本叶不证明真实汉字指称已实现。

## 2. 正式依据、复用和物理归属

依据：0050 的 current-only 与自顶向下完整读取边界、1140 的 E/专属概念区分、1150 的场景父子关系与成员字段分账、2200/2210/7200/7210/7240 的词条—概念—对象路由、CODE-FILE-01 的领域文件归属。现行 `新_场景类` 已是唯一场景组织 owner，其私有 `新场景互斥` 串行化合法场景结构操作；L1 `基础数据集::查询节点组完整结构` 能在单次 L1 共享锁下返回给定节点集合的字段、入/出外部关系和入向字段，并以 `基础结构操作状态` 区分资源/结构错误。`新_存在类::是存在节点`可核验成员的存在身份；本叶不宣称完整验证 E 的所有特征与概念内容。扩展 `海中鱼巣/领域/新_场景类.h/.cpp`，不新增文件、不改 L1 或已有裸列表 ABI、不改工程登记、装配及生产调用者。

`查询节点组完整结构` 只对**给定**节点组提供一次锁内快照，不能自己发现未知子场景。因此本叶先发现完整可达闭包，再用一次包含已发现全部场景和 E 的联合快照核对初读结构及闭包。成功只表示这次完成的当前结构读回；不产生公开事实代次，不声称跨服务原子快照或可检测 ABA，也不保证返回后结构不再变化。后继使用者须在作唯一裁决时重新核验有关当前端点，不能长期缓存本结果充当世界事实账。

## 3. 公开合同

在 `新_场景类.h` 的场景读取 DTO 区增加以下类型；在同类公开只读查询区声明入口，同名 `.cpp` 定义。只允许调用该类的场景业务及后继 DATA 外语言业务消费；不向 L1 反向引入语言语义。

```cpp
enum class 新场景范围成员读取状态 : std::uint8_t {
    已完成 = 1, 根不可读, 读取已变化, 结构不一致, 资源失败
};
struct 新场景范围成员项 final {
    稳定编码 场景节点;
    std::vector<稳定编码> 直接成员存在组;
};
struct 新场景范围成员读取结果 final {
    新场景范围成员读取状态 状态 = 新场景范围成员读取状态::根不可读;
    std::optional<稳定编码> 根场景节点;
    std::vector<新场景范围成员项> 场景成员组;
    std::vector<稳定编码> 范围成员存在组;
};
class 新_场景类 final {
public:
    新场景范围成员读取结果 读取本树范围成员完整() const noexcept;
};
```

上述 `class` 块仅定位新增成员，不重定义现有完整类。入口不接收调用方自称的根；成功结果的 `根场景节点` 必须是当前服务持有并正式核验的树根。调用方欲用于默认现实，仍须以 `新_世界树类::获取世界树根场景()` 与该根相等为独立前置。`场景成员组` 包括根场景和全部子场景，按场景稳定编码升序；每组直接 E 和全域 E 均升序且无重复。根为空树时仍有一项 `{根, {}}`，全域 E 为空。场景节点本身是存在，但**不**加入普通成员 E 集；边界引用也不当作成员归属。

结构/资源/读取失败时，`根场景节点`清空、两组清空；不返回可误用的部分候选。正常无成员只能是`已完成`且根与场景组有效。状态不带业务“没有这个对象”结论。读取过程不接收或暗设场景数、成员数、深度、步骤、时间等资源预算；内存无法完成完整语义范围时只返回`资源失败`。

## 4. 读取算法及失败分账

1. 在整个发现、核验及结果构造期间持有现行 `新场景互斥`，锁顺序遵循该类既有场景→L1及场景→存在读调用方向。根编码/场景结构字段身份未建立或根节点在 L1 不存在为`根不可读`；有效根的场景身份、用途、父关系不符合当前场景服务合同为`结构不一致`。根用途字段缺失按现行 `读取根用途` 解释为普通；存在时必须恰一且为合法值，并与服务`用途_`一致。不得调用`初始化`或`建立根场景`补根。
2. 以服务持有的根开始遍历至无未访问子场景。每个场景调用 L1 `查询节点组完整结构({场景})`，仅在`已完成`且快照存在时解析场景身份字段、根用途字段、直接成员字段，以及角色 `3` 的父子外部关系；每个场景还须由存在服务确认其存在身份。子场景不得持有根用途字段。不调用`查询直接成员存在`、`查询直接子场景`、`查询场景范围存在`或`获取场景`作为完整性依据。对根要求零个角色 3 入向父关系；对子场景要求恰好一个，且指向刚才发现它的直接父场景。其它角色外部关系不当场景层级。重复边、同一子场景再入、环、无效子节点或同一 E 重复挂接均为`结构不一致`。已访问集合只用于判环和多父，不限制规模。
3. 对每条直接成员字段要求字段关系身份、字段类型、所属场景、目标编码合法。首次发现每个 E 时先用 L1 有状态读取确认 E 节点实际存在，再由 `新_存在类::是存在节点(E)`确认存在身份；布尔 `false` 仅在 L1 已证明节点存在后解释为存在结构不合约，绝不单独作为“成员不存在”或“读取已完整”的证明。E 的 L1 快照不得含场景身份标记，场景节点不作为普通成员；不调用只判断本树归属的 `是场景节点(E)`，以免把别的树的场景误作普通成员。查询节点组返回`资源失败`映射同名状态；首次缺根映射`根不可读`，首次缺成员或有效节点无效结构及 L1 `内部不一致`映射`结构不一致`，已经读到的节点在末端缺失或内容变化映射`读取已变化`。`是存在节点` 内部的 C++ 读取异常由其现行工程诊断终止链处理，不把异常后的 `false` 当正常否定。L1 `入口拒绝`、`引用不存在`或其它非预期状态意味着本实现构造的请求失效，进入工程诊断终止链；预期的内存分配失败统一映射`资源失败`，不包装成空集。
4. 发现结束后一次调用 `查询节点组完整结构(全部已发现场景 + 全部 E)`。其 L1 单锁快照中的每个场景字段组、角色 3 入/出关系组须与初读逐项相同；出现新的/退出的子场景或成员字段即`读取已变化`，不能沿旧列表成功。每个 E 必须仍存在，且入向`成员存在字段`恰有一项，与某一场景的直接字段**同一关系身份**相互对应；多归属、缺归属、伪字段、错目标为`结构不一致`。E 的场景身份标记必须仍为零项，且存在身份由当前存在服务复核；本叶不读 E 的特征或概念内容。联合结果资源/内部状态按第3项映射；发现与复核不一致清空所有候选。全部一致后才排序填入成功 DTO。

此算法利用场景 owner 锁和 L1 对已知闭包的一次联合快照，消除旧入口把子查询失败静默吞成空/部分的路径。它不提供跨 L1、存在、语言等 owner 的全局事务，也不声称真实世界所有尚未登记对象都在树中。
