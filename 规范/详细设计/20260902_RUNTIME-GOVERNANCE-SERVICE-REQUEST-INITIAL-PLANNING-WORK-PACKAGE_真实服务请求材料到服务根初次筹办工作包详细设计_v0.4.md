# RUNTIME-GOVERNANCE-SERVICE-REQUEST-INITIAL-PLANNING-WORK-PACKAGE 真实服务请求材料到服务根初次筹办工作包详细设计 v0.4

状态：执行侧测试消费者范围漂移修订；配套 v0.4 计划登记后取代 v0.3 施工合同。

## 1. 修订裁决

v0.3 的机器语义、目标 ABI、生产白名单和业务流程保持不变。本修订只补齐正式 HEAD 中两个直接消费旧 DTO 的测试消费者，并把用户再次明确的结束口径写成无歧义表述：

1. 每次已经开始的筹办逻辑都必须形成一个且仅一个五类闭合结果；未取得唯一筹办权也形成`结构化非成功`，不能静默结束。
2. 任务工作线程把该结果封装为唯一强类型筹办结果消息并交给任务管理线程。
3. provider 形成结果表示“筹办逻辑已经闭合”；同一消息被任务管理线程接收或确认精确重复，才表示“本工作包处理正常结束”。
4. 消息交接暂时失败时，结果已经存在但处理尚未正常结束；只重投同一消息，不重调 provider、不补造第二结果。

这不是新账、新回执或新状态机，不改变 v0.3 五类结果、单 provider、单结果消息、单结果端口和管理端独立读回合同。

## 3. 精确测试迁移合同

### 3.1 本能路线阶段二

保留现有`下一筹办工作包`夹具、P00 正式任务/任务轮次/G、P01 线程提交和以下业务断言：一个已消费工作包、一次 provider 调用、一个已确认结果、容量等待只重投同一结果消息。

只做以下机械迁移：

1. 使用 v0.3 已冻结的 manager 后继来源纯值形成路径，把原工作包与同 G 的 task owner 正式任务/轮次读回组成`L2任务重筹办规范化来源材料`。
2. `任务筹办推进请求`写入`来源材料`，不再写`工作包`。
3. 消息任务、任务轮次、筹办轮次和 G 分别等于规范化来源公共 helper 的结果及请求头截止。

禁止手填裸任务轮次、从消息外层反推来源、删除 P01 专项、减少队列重投次数或改写原业务预期。

### 3.2 自我治理一致事实

保留方法查找公开入口、预算、结论、当前事实截止、零载荷和九结论业务矩阵。机械迁移固定为：

1. `任务特征方法查找请求.来源材料`保存同一规范化来源联合。
2. 成功结果必须存在`已互证来源材料`，与请求来源逐项相等；同时用公共 helper 复核任务、任务轮次、筹办轮次及 G 守恒。
3. 非成功零载荷必须没有`已互证来源材料`，相关任务/轮次/筹办身份和序号/G 保持空值或零值。
4. 九结论夹具只把旧工作包载荷换成同一规范化来源联合；不得改变九类结论、预算、预期状态和事实代次。

`评估下一筹办方法候选并形成条件提议`名称和业务入口不在本次删除范围。不得为测试保留旧`工作包`字段、旧`已互证工作包`兼容壳或第二入口。
