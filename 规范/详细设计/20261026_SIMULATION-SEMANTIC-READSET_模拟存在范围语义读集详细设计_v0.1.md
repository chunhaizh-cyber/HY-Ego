# 模拟存在范围语义读集详细设计

标识：SIMULATION-SEMANTIC-READSET；版本：v0.1；日期：2026-10-26。起点main `3826f008b3f877e908ff35f15ded9557ae9e4fb7`加root保留WIP。

## 1. 已证根因与首叶目标

`业务/模拟学习.服务.cpp`约1351在组合游标外保存存在范围概念C的完整联合快照，送入共享输入模板；一个样例发表C/R后，C新增入向引用，下一样例隔离发布仍核旧入向全集，出现与定义无关的CAS漂移并重跑整批。根因是把“定义被引用”混为“定义改变”，不是漏刷新日志或某个本能专用参数问题。

本叶只收敛**已标记存在范围C及本次实际用到的定义/分类依赖**：无关入向引用和名称不使其失效；身份、定义字段、实际上位关系和被采用的合法性依据改变仍失效。发布时L1继续原子核目标存续和合法材料，不靠忽略保护或刷新旧完整快照迁就当前。

源E/F/U/C/R、语言场景、方法/分支/消息闭包、FT/二次概念等原保护不整体改造。只有循环外共享正式定义模板内与本存在范围C重叠的节点需要同次分账；每组合fresh消息/方法闭包仍保留现必要full。该首叶不宣称所有模拟保护、全部owner或全仓CAS均已语义化。

依据0050及4015现行current-only合同、7165第8—10节与用户本窗口明确裁决。不是4080旧事实基座服务或7191等旧重建路线；不改规范、业务目标、方法规格、学习结果形成或实际动作。

## 2. 复用与扩展裁决

现`预期既有节点组`能核完整自有字段、不核入向/外边，但不能表达关系集合/负事实，封存入口又明确拒绝它；`预期联合节点组`核四面全集。现封存/组合只承认full，外边端点、删除/替换仍要求full。因此不能把所有full直接转fields-only，也不能只校已见几条分类边而漏新增冲突父。

在现`基础数据集.h/.cpp`扩展**只读**筛选集合预期，复用当前同锁查询与原子候选发布，不新建数据仓、owner、代次、SQL或泛查询优化器。存在概念owner提供最小语义读集，方法仅facade，模拟服务/world实际消费。只读guard不取得写资格，原写入、外边端点及删除/替换full准入不放宽。

## 3. L1中性公共合同

以下类型位于`核心/基础数据集.h`，无业务名/类别/权限：

```cpp
struct 基础只读字段集合预期 final {
    稳定编码 节点;
    std::optional<稳定编码> 字段节点; // 有值：恰此字段键；无值：全部自有字段
    std::vector<稳定编码> 排除字段键组; // 仅字段节点无值时允许；按键排除，不按值猜测
    std::vector<基础字段关系> 字段组;
};
struct 基础只读外部关系集合预期 final {
    稳定编码 节点;
    bool 出向=false;
    基础外部关系类型 类型=基础外部关系类型::父子;
    std::optional<std::int64_t> 角色或顺序;
    std::optional<稳定编码> 对端节点;
    std::vector<基础外部关系> 关系组;
};
struct 基础只读预期 final {
    std::vector<基础节点> 节点组;
    std::vector<基础只读字段集合预期> 字段集合组;
    std::vector<基础只读外部关系集合预期> 外部关系集合组;
};
```

`基础节点组追加请求`尾部新增`基础只读预期 只读预期;`，默认空保持现请求。新增只读方法`基础节点组追加状态 基础数据集::核验只读预期(const 基础只读预期&) const noexcept;`，内部共享锁；原子追加用同一私有已加锁校验逻辑，在唯一独占锁内、候选交换前再次核验。不能以封存前核一次代替提交时核。

节点组要求身份仍存在；每个selector宿主、显式字段键/排除键/对端必须在节点组中登记且合法。字段和关系期待组是该selector的**完整查询结果**，允许空以保护缺项/无父等负事实；筛选仅按明确键、方向、关系类型、角色和对端，不能按结果值或业务含义。全自有字段排除名字键，可保护未知非法字段新增而不把合法名称变化拉回。

校验字段/边编码唯一、端点方向/筛选一致、材料不失效、顺序规范化；不能只比较数量、仅逐条存在或丢掉未知项。相同selector同义合并，异义返回预期不符；不同重叠selector按AND保留，矛盾可由最终同锁校验拒绝，不实现求解优化。无效结构入口拒绝、宿主丢失节点不存在、键/对端丢失引用不存在、集合不等预期不符；当前索引/结构损坏工程报告。独立核验空读集入口拒绝，追加请求的默认空读集不改变旧行为。

## 4. 封存、组合和写资格

`规范化封存请求`同次规范化新读集并保留到封存内容；原`预期既有节点组`的封存拒绝不改。新读集节点可作为新字段内容的**只读引用目标**证明来源，不自动成为追加字段宿主、外边写端点或替换/删除宿主。现强写约束需要full的地方继续要求full；L1在交换前仍验证每个引用目标当前存在及材料合法。

`原子追加封存片段组`合并新读集，不把它转回full；相同selector异义可规范化拒绝，不同筛选保留共同约束。只读guard与原full并存时两者都要满足，不因有新guard删除其他片段的更强合法要求。原数据集身份、组内索引重定位、写者冲突、回执映射及原子交换均不改。整个组合只调用一次现原子追加；新guard不新增持久业务账。

## 5. 存在owner语义读取合同

新增公共类型/入口位于`领域/概念_存在类.h/.cpp`：

```cpp
struct 存在范围语义信息 final {
    稳定编码 节点;
    存在概念种类 种类;
    std::optional<稳定编码> 对应存在节点;
    std::vector<存在概念特征项> 特征组;
    std::vector<稳定编码> 上位概念组;
    friend bool operator==(const 存在范围语义信息&,
        const 存在范围语义信息&)=default;
};
struct 存在范围语义保护结果 final {
    正式概念读取状态 状态=正式概念读取状态::非本提供者概念;
    std::optional<存在范围语义信息> 信息;
    基础只读预期 只读预期;
};
存在范围语义保护结果 读取存在范围语义保护(稳定编码) const noexcept;
```

只接现普通专属/抽象存在概念，不把信息结构概念、组织根或FT改造成普通概念。owner直接用其私有布局解码当前语义及所用端点；**不得先调用旧完整定义保护reader再把成功快照裁小**，否则旧reader自身仍会因无关入向先拒绝。可复用无全联合准入的私有种类/特征项解码；语义DTO不包含名称/无关下位集合，核同不得比较旧完整`存在概念信息`。

精确字段和关系合同：

| 对象/依据 | 必须验证并保护 |
| --- | --- |
| C自身 | 类型恰一；专属对应存在恰一、抽象不得有对应存在；特征项集合无重。自有字段除名称键全部保护，允许键只有类型/对应存在/特征项/名称；额外非法字段工程错误。 |
| C的特征项节点 | 自有字段恰为项类型、FT、具体FC，各一且合法，未知字段错误；守完整自有字段。FT/FC正式定义继续由原FT消费者保护，本接口不代替它们。 |
| C组织归属 | 入向父子role1完整集合，恰一且来自存在组织根；组织根节点及所用schema身份存续。 |
| C上位分类 | 入向父子role2完整集合（含空），守每个实际父端点的类型字段；按原普通抽象父语义产出上位组，非法端点工程报告，不交service猜role/key。 |
| 零FT普通抽象合法性 | 若是owner唯一登记存在根，保护组织根对应登记字段恰一指C；否则须至少一条合法普通下位role2边作为存在见证，选择确定的一条，仅守该对端/role的完整集合及端点类型。新增其它下位不使本范围语义失效。 |
| 专属实际对象 | 对应存在节点存续及本接口实际使用的身份依据；复制其现实内容仍由原源E读取保护负责，不在此放弃或代替。 |

不保护C入向字段全集，不把谁又引用C视为定义改变；不保护名称变更，不枚举无关图根全部子链。所用字段键、root登记键及role值由owner封装，业务/模拟层不硬编码。捕获后经新L1只读核验和必要同语义重读，保证DTO与读集来自一致材料；采集变化返回前提已变化＋空信息/空读集，缺失/非本概念分别用现状态，正式损坏工程终止，不吞为业务缺条件。

## 6. facade与循环外模板分账

`领域/新_方法类.h/.cpp`新增只读转发：`存在范围语义保护结果 读取模拟存在范围语义保护(稳定编码) const noexcept;`，直接调存在owner，不增加方法写权或概念私有keys。原`读取模拟存在范围`及其它消费者保持ABI。

`模拟学习.服务.cpp`的存在归属采集缓存改为语义DTO＋只读预期，不再保存C四面full。范围包含仍遍历本次上位、检查环，并为实际父端点采集相同语义依据；不因名称/下位不相关变化判漂移。所选原型的归属仍核，原型候选集合的原有枚举/递归行为不改，不把本叶说成新增全原型事务。

关键是集中分账而非仅删除1355：`加保护`保留源事实全保护；`加正式保护`维护独立的循环外共享正式定义保护来源，不再把同份定义无区别塞进源事实map。最终共享模板中，已获存在owner语义授权的本C节点及其明确依赖，以相应语义guard替代该来源的full；剩余共享正式定义仍按原full。若相同节点另有源事实或实际成员集合的更强读取用途，不得按编码全局抹掉它，保持其独立full约束。

必须覆盖约801、保护内容定义、最终1351核同及1358模板重建等重复入口，不能后面又从旧map加回冻结C full。方法/分支/消息执行闭包每组合fresh读取可保留现full，不为形式追求“零full”扩接口；这条更强fresh并发保护及FT/二次全保护是未进一步收敛边界，不宣称所有无关变动在全系统均已消除。

共享C仅进行同语义比较及新L1只读核验，不刷新旧full来迁就新引用；真实定义/上位或选中来源值改变仍沿现采集漂移/重新筹办规则。组合游标和结果形成不改，不跳过失败样例冒称已测。
