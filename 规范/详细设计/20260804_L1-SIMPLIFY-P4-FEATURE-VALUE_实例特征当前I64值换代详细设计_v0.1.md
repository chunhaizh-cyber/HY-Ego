# L1-SIMPLIFY-P4-FEATURE-VALUE 实例特征当前 I64 值换代详细设计 v0.1

更新时间：2026-08-04
设计基线：`fa3cb1401e8c1cc2cf71ff704590404fbcc22889`

## 1. 目标与边界

P3 已在同一长寿命 L1 中建立一个初始场景 I64 实例槽及初始值。本设计只补齐 4015 要求的当前属性值换代：旧值退出、新值建立、当前属性槽切换和事实代次推进必须由一个 L1 写集原子发布，并在发布后从公开读取入口独立读回。

本叶不建立其它宿主或值形状，不修改特征定义，不新增关系，不实现关系 22、批次、比较、状态动态、恢复、生产初始化、旧特征体系迁移或删除，也不把换代等同于业务状态变化。

## 2. 当前事实与复用裁决

当前正式代码已经提供：

- `L1事实基座服务::提交写集`：支持新值、属性槽变更和退出事实同写集发布；
- `L1实例特征服务::读取I64实例特征`：按宿主、定义、槽、两关系、当前值和来源独立读取同代次完整事实；
- `L1实例特征服务::建立初始场景I64实例特征`：形成初始值，但没有当前值换代入口；
- P3 已冻结 `0x05` 登记幂等域和 `0x06` 初始实例幂等域。

因此直接扩展现有 `海中鱼巣.领域.服务.L1实例特征`，不新建第二个特征服务、仓库或事务模块。新写入使用私有 `0x07` 换代幂等域。

## 3. 公开合同

### 3.1 DTO

在 `海中鱼巣/领域/L1实例特征.数据.h` 新增：

```cpp
struct I64实例特征当前值换代请求 final {
    std::uint32_t 合同版本 = L1实例特征合同版本;
    std::uint32_t 规则版本 = L1实例特征规则版本;
    特征操作幂等身份 幂等身份;
    std::uint64_t 期望事实代次 = 0;
    I64实例特征读取请求 当前事实;
    std::int64_t 新值 = 0;
    稳定编码 新来源节点;
};
```

并新增 `I64实例特征当前值换代请求有效(const I64实例特征当前值换代请求&) noexcept`。有效性只检查合同/规则版本、非零幂等身份、非零期望代次、当前事实必要编码和非零新来源；值域、事实存在性及同代次性由服务在写前读取后裁决。

现有 DTO、枚举数值和函数签名保持不变；换代结果复用 `I64实例特征结果`。成功或精确重复时，`事实` 必须是新当前值的完整不可变事实，`宿主关系` 与 `定义关系` 保持原编码。

```cpp

    const I64实例特征当前值换代请求& 请求);
```

- 权威事实所有者：L1 三类事实基座；领域意图所有者：`L1实例特征服务`。
- 物理位置：`海中鱼巣/领域/服务.L1实例特征.ixx`，现有类的公开成员函数，模块导出可见。
- 直接调用：现有私有同代次读取辅助、`L1特征定义服务::读取I64特征定义`、`L1事实基座服务::读取当前节点`、`提交写集`、`读取当前值`、`读取历史事实`、`读取当前属性`。
- 诊断责任：向上送出。合法拒绝、未找到、代次漂移和幂等冲突不写错误日志；资源异常与内部不一致通过结构化状态返回，由最终调用责任边界决定是否记录一次。

## 4. 写前读取与错误映射

函数在服务锁内按以下固定顺序完成第一笔写入前检查：

1. 请求有效且 P3 登记已加载，否则返回 `入口拒绝` 或 `登记未加载`。
2. 通过现有内部读取路径读取 `请求.当前事实`；必须成功、材料为 I64、读取代次等于 `期望事实代次`。
3. 读取同一特征定义；定义读回代次必须等于期望代次，`新值` 必须位于闭区间 `[下界, 上界]`。
4. 读取 `新来源节点`；必须是同代次当前普通节点。
5. 再读完整快照并确认当前事实代次仍等于期望代次；不得使用动作预估代次代替回读。

映射固定为：请求或值域非法 -> `入口拒绝`；必要当前事实不存在 -> `未找到`；任一公开读回代次不同或提交返回代次漂移 -> `事实代次漂移`；同幂等键异义 -> `幂等冲突`；内存分配失败 -> `资源失败`；成功形状、类型、槽、历史或读回互证失败 -> `内部不一致`。非成功结果的 `事实` 为空，两关系编码为空。

## 5. 原子写集与发布后校准

写集固定为：

```text
期望事实代次 = 请求.期望事实代次
幂等键 = (0x07 << 56) | 请求.幂等身份.值
新值 = 1 项：所属节点=当前实例槽；属性类型=P3 当前I64值属性类型；材料=请求.新值；来源=请求.新来源节点
属性槽变更 = 1 项：当前实例槽 + P3 当前I64值属性类型 -> 新值本地键
退出事实 = 1 项：请求.当前事实.当前值
节点 = 0；关系 = 0
```

提交成功或精确重复后必须完成事实校准：

1. 从新编码映射取得唯一新值编码；
2. 构造只把当前值和来源替换为新编码/新来源的 `I64实例特征读取请求`，调用公开语义相同的独立读取路径；
3. 读回代次必须等于提交结果代次，宿主、定义、实例槽和两关系必须不变，新材料和来源必须匹配；
4. 旧值当前读取必须返回 `已退出` 且不带当前事实；历史读取必须返回旧值完整记录，其退出事实代次等于提交结果代次；
5. 当前属性读取必须指向新值且代次等于提交结果代次。

任一校准不成立返回 `内部不一致`，不得把提交返回中的预计形状冒充最终状态。已发布事实不在服务层回滚。

## 6. 幂等、并发与生命周期

- 同一 `0x07` 幂等键且规范化写集相同由 L1 返回精确重复；函数仍重新执行发布后独立读回，再返回 `幂等读回`。
- 同键但新值、来源、当前值或其它写集字段不同返回 `幂等冲突`。
- 两个调用从同一基线竞争时至多一个推进代次；后到者返回 `事实代次漂移`。
- 旧值永久保留历史身份和退出代次；其稳定编码不得复用。实例槽、宿主关系、定义关系和特征定义不换代。
- 服务不保存第二份当前值或换代侧账；当前性只由 L1 属性槽和事实生命周期决定。

## 7. 验证矩阵

扩展现有 `自检.L1实例特征`，不新增完整自检单元或顺序号。至少覆盖：

1. 在 P3 初始实例后换代成功，只新增一值，旧值退出，槽指向新值，事实代次只推进一次；
2. 新值、来源、宿主/定义/槽和两关系从独立读取同代次闭合；
3. 旧值当前读取为 `已退出` 且空载荷，历史读取保留旧材料并带本次退出代次；
4. 完全相同请求返回 `幂等读回` 且不再推进代次；同键异义返回 `幂等冲突`；
5. 旧基线竞争、错误当前值、错误来源、越界值和未登记服务均在写前失败且零新增事实；
6. 完整自检登记/执行数量保持 27，Debug/Release Rebuild、两配置退出式完整自检、strict、MSVC 模块依赖扫描和目标 diff check 通过。

## 8. 完成声明

本叶只证明一个已建立 I64 实例槽的当前值可以按 4015 原子换代、幂等和独立校准。它不证明通用多宿主/多值类型、业务状态动态、特征批次、比较、恢复、生产初始化、旧体系退出或端到端服务验收。
