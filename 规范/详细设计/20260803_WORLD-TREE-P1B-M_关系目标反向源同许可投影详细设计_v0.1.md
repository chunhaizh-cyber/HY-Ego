# WORLD-TREE-P1B-M 关系目标反向源同许可投影详细设计 v0.1

日期：2026-08-03

设计身份：WORLD-TREE-P1B-M

创建侧代码基线：`7ba6e151eec74cb87ed02c69720596e1838acad9`

## 1. 目标与能力裁决

本叶子为 L1 `节点直接结构查询服务` 增加一个业务中性组合读取：从已知关系目标和角色反向发现当前关系源，在同一共享许可内返回每个源的全部同类型当前关系及源节点全部当前类型化值。

P1B-Q需要按主体/场景发现关系19状态源和关系20动态源，再复核该源的全部角色与发生时间/动态种类值。当前按源、按目标和相关关系三个公开函数各自取得许可，不能事后拼成同代次。P1A2G 的方向是“已知源根向目标展开”，不能从目标反向发现未知源。因此裁决为扩展既有 L1 查询服务，不修改 P1A2G，不建立第二服务。

能力证据 `CAP-0011` 与 `CAP-0036` 均是旧当前代码候选，未证明新正式关系仓同许可组合读取，不能复用。4010 v1.2 §6.1 已授权业务中性同许可多结构投影，无需修改正式规范。

本设计不解释状态、动态或关系角色，不读取世界结构、特征比较、SQL、材料或旧栈，不写机器事实。

## 2. 关系领域边界

L1只允许关系类型19/20以缩小公开攻击面，但角色仍是业务中性 `std::int64_t`：零、负值或领域不适用值只产生零命中，不由 L1 拒绝。

P1B-Q 后继解释：

```text
关系19 状态 -> 1主体、2场景、3特征、4值、5来源存在；五项恰一
关系20 动态 -> 1主体、2场景、3被改变目标、4前状态、5后状态、6来源动作、7来源低层动态、8同源迁移动能、9来源存在
```

P1B-M 必须返回源节点该类型的全部当前关系，不能只返回命中过滤边。关系20的动态种类适用性、关系19/20基数、时间、端点业务一致性和领域稳定排序全部由 P1B-Q 负责。

## 3. DTO、稳定状态与所有权

唯一共享声明位置：`海中鱼巣/核心/节点直接结构合同.数据.h`。

```cpp
inline constexpr std::uint32_t 节点直接目标角色源投影合同版本 = 1;

struct 节点直接目标角色筛选 {
    节点稳定身份见证 目标;
    关系类型 关系种类 = 关系类型::普通父子;
    std::int64_t 目标角色 = 0;
};

struct 节点直接目标角色源投影请求 {
    std::uint32_t 合同版本 = 节点直接目标角色源投影合同版本;
    std::vector<节点稳定身份见证> 必须节点组;
    std::vector<节点直接目标角色筛选> 筛选组;
};

struct 节点直接当前关系源投影 {
    关系类型 关系种类 = 关系类型::普通父子;
    节点稳定身份见证 源;
    std::vector<关系稳定身份见证> 当前关系组;
    std::vector<类型化值读回> 当前类型化值组;
};

struct 节点直接目标角色源投影结果 {
    节点直接结构结果头 头;
    std::vector<节点稳定身份见证> 必须节点组;
    std::vector<节点直接当前关系源投影> 源组;
    std::optional<节点稳定身份见证> 未满足节点;
};
```

复用 `节点直接结构服务状态`：成功1、未找到2、入口拒绝3、版本漂移4、许可拒绝5、资源失败6、内部不一致7。请求由调用方拥有并 const 借用；服务不保存。结果由调用方拥有，可复制/移动，不含内部句柄、许可、锁、仓库、会话、SQL或引用。

## 5. 入口准入与稳定顺序

许可前准入：

1. 合同版本等于1，必须节点组和筛选组均非空。
2. 全部节点见证稳定主键有效、类型非未分类、身份版本非零。
3. 必须节点按稳定主键唯一；筛选目标必须逐字段等于必须节点组的一项。
4. 筛选关系类型只允许19或20。
5. 筛选三元组 `(关系类型, 目标稳定主键, 目标角色)` 唯一；角色允许任意 I64。

稳定排序：

```text
必须节点：(主键命名域,键值,节点类型数值,身份版本)
筛选：(关系类型数值,目标主键命名域,键值,目标角色,目标类型,目标版本)
源组：(关系类型数值,源主键命名域,键值,源类型,源版本)
关系：(关系主键命名域,键值,关系版本)
值：(所属身份.稳定主键.命名域,所属身份.稳定主键.键值,所属身份.类型数值,所属身份.身份版本,类型合同身份.命名域,类型合同身份.键值,类型合同版本,值记录身份.命名域,值记录身份.键值,值记录版本)
```

上述“类型数值”按 `static_cast<std::underlying_type_t<节点类型>>(所属身份.类型)` 比较；每一元组均自左向右逐字段升序比较，不得依赖复合结构的隐式次序或由执行者另选比较器。

关系稳定主键是关系去重身份；同主键异版本或任一字段不同为内部不一致。值记录稳定身份是值去重身份；同身份异内容，或同所属+同合同版本出现多个不同当前值记录均为内部不一致。

## 6. 唯一执行顺序

1. 在 `try` 中完成 §5 准入；失败返回入口拒绝、代次0、全空。
2. 测试宏合法注入后复制并稳定排序请求材料。
3. `事务域_.取得读取许可()` 恰一次；无效返回许可拒绝、代次0、全空。
4. 读取已发布代次恰一次；代次0返回未找到、代次0、全空。
5. 逐个重解析必须节点：未占用/历史占用返回未找到、当前非零代次和首个未满足见证；当前主键存在但类型/版本不同返回版本漂移、当前非零代次和该见证；其它矛盾内部不一致、代次0、全空。
6. 对每个筛选调用 `关系_.读取有效目标关系组(目标句柄, 类型)`；只保留目标端完整一致且角色相等的关系。仓返回非已读取或关系见证失败均内部不一致。
7. 以 `(关系类型,源见证)` 形成唯一源候选；同身份异内容内部不一致。零候选返回成功、当前非零代次、完整必须节点和空源组。
8. 对每个源调用 `关系_.读取有效源关系组(源句柄,同类型)`；第一跳当前关系必然在组中，因此非已读取或空组均内部不一致。
9. 全部源关系调用 `形成当前关系见证_`，按稳定身份校验、去重、排序；不丢弃任何角色。
10. 调用 `类型化值_.读取所属身份当前值组(源主键)`；空组合法保留。每项复用 `类型化值记录完整_`，并要求所属身份逐字段等于源、当前=true、首次/当前发布代次不晚于事实截止。
11. 值组按 §5 校验、去重、排序；组装并排序源组。
12. 返回成功、当前非零代次、重新解析的必须节点、完整源组和空未满足节点；许可随函数返回析构。

进入 `try` 前用 `static_assert(noexcept(...))` 冻结资源失败和内部不一致空结果构造。捕获 `std::bad_alloc`/`std::length_error` 返回资源失败；其它异常返回内部不一致；均代次0且全空。不重试、不 sleep、不读取时钟、不查询SQL。

## 7. 状态矩阵

| 状态 | 事实截止 | 必须节点组 | 源组 | 未满足节点 |
| --- | --- | --- | --- | --- |
| 成功 | 非零 | 完整，可非空 | 完整，可空；源值组可空 | 空 |
| 未找到 | 非零或空域0 | 空 | 空 | 非空域时首个未满足见证；空域为空 |
| 版本漂移 | 非零 | 空 | 空 | 首个漂移见证 |
| 入口拒绝/许可拒绝/资源失败/内部不一致 | 0 | 空 | 空 | 空 |

非成功不得返回部分关系或值。全部必须节点有效但筛选零命中是成功空源组，不是未找到。

## 8. 自检、调用和验证

本叶子原位扩充 `WORLD-TREE-P1A2-S01` 顺序170，不新增顶层自检项，不改变顶层完整自检总数。覆盖：

```text
关系19/20双类型；主体/场景多筛选；同源去重；全部角色保留
源当前类型化值与空值组；零命中成功
非法合同/见证/重复/类型；未找到；版本漂移；许可拒绝；资源失败
悬空端点、同身份异内容、同合同多当前、发布代次越界
全部稳定排序；调用前后六仓/代次/幂等/持久侧账相等
SQL关闭与材料不可用不改变结果
```

AST 必须证明根函数恰有一次事务域许可调用；关系仓只有目标组和源组读取；值仓只有源当前值读取；索引/类型合同/SQL/材料/旧栈调用边为0。

## 9. 依赖与完成边界

代码计划依赖 P1A2 v0.3 结果和 P1A2G v0.1 真实成功代码。依赖 P1A2G 是为了复用同三文件中的唯一关系见证与值完整性实现并避免并发写冲突，不表示两种投影语义相同。

本设计完成只证明 P1B-M 可机械施工。代码完成最多证明 L1 目标角色反向源同许可投影真实可用；不得声明关系19/20业务完整、状态动态查询、P1B发布、世界快照或服务验收完成。
