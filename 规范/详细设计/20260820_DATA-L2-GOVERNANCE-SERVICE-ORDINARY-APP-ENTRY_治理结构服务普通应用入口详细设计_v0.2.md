## 1. 路线位置与目标

当前顶层推进顺序固定为：

```text
基础信息迁移
-> 领域服务入口
-> 任务服务补全
-> 任务筹办编排
-> 自我治理循环骨架
-> 事实读取闭合
-> 真实治理
```

当前代码已经具有唯一 `L2需求结构服务` 和 `L2任务结构服务`，且根工程已经登记二者；但 `普通应用上下文` 不持有它们，启动形成的普通应用合法消费者无法取得同一 L1 运行包中的需求 / 任务结构服务。现有两个端到端入口仍各自手工签发 owner 和构造服务，不能证明生产装配入口成立。

本叶先闭合“领域服务入口”：把需求、任务服务纳入普通应用唯一运行包并提供同实例 getter，再把既有需求端到端消费者迁移为普通应用合法消费者。首次实际消费发现既有 `退出任务` 在提交退出后使用当前投影重新寻找已退出关系，确定性返回 `内部不一致`；v0.2 同时补齐该任务服务读回缺陷，但不进入任务方法路径或筹办语义。

## 2. 当前事实与复用裁决

基线 `f7274df197f690d03d49bafdc8c0f26e696ccdd6`：

## 3. 冻结装配合同

### 3.1 普通应用上下文

`海中鱼巣/装配.普通应用.ixx`新增导入：

```cpp
import 海中鱼巣.领域.服务.L2需求结构;
import 海中鱼巣.领域.服务.L2任务结构;
```

上下文新增唯一成员，并保持依赖者晚构造、早析构：

```cpp
std::unique_ptr<L2需求结构服务> 需求服务_;
std::unique_ptr<L2任务结构服务> 任务服务_;
```

公开四个零失败同实例 getter：

```cpp
L2需求结构服务& 取得L2需求结构服务() noexcept;
const L2需求结构服务& 取得L2需求结构服务() const noexcept;
L2任务结构服务& 取得L2任务结构服务() noexcept;
const L2任务结构服务& 取得L2任务结构服务() const noexcept;
```

### 3.2 owner 与构造顺序

普通应用使用现有同一 `L1事实基座运行包`的装配期签发器：

```text
世界结构服务完成
-> 建立需求 owner / 形成 L2需求所有者交付
-> 以同实例存在、特征、状态服务构造唯一需求服务
-> 建立任务 owner / 形成 L2任务所有者交付
-> 以同实例需求服务构造唯一任务服务
-> 继续构造概念、方法等无反向依赖服务
-> 一次移动进入普通应用上下文
```

新增六个连续装配失败状态：需求 owner 建立失败、需求交付形成失败、需求服务构造失败、任务 owner 建立失败、任务交付形成失败、任务服务构造失败。既有状态数值保持不变，新状态只追加在枚举尾部。

不得导出 L1 写端口、签发器或 owner 选择，不得让任务服务绕过需求服务读取列表项。

## 4. 合法消费者与读回

`端到端测试.需求服务.ixx`改为：

1. 调用 `形成普通应用生产配置`和`构造普通应用上下文`；
2. 只经普通应用 getter 取得存在、特征、状态、需求、任务五个同实例服务；
3. 沿用现有模拟参数建立目标状态合同和需求列表项；
4. 在需求退出前调用任务服务：
   - `新增任务`；
   - `读取任务`并逐字段确认列表项和任务身份；
   - `按需求列表项读取当前任务`确认返回同一任务；
   - `退出任务`并确认当前读取不再成功；
5. 再沿用既有需求退出读回。

测试不得手工建立 L1 运行包、owner 或服务，不得通过私有成员、仓库或 raw 端口构造成功。任务方法路径、当前路径、实例方法和筹办语义不在本叶动态覆盖。

## 5. 退出任务读回修复

`退出任务`在提交前已经从一致当前投影得到任务、虚拟存在和三条自有关系编码。内部 `读回退出任务`必须显式接收这些退出前稳定编码，提交后只按编码调用历史事实读取并验证同一退出代次；禁止再次调用当前投影发现已退出关系。公开 `退出任务(L2任务退出请求)`签名和 DTO 保持不变。
