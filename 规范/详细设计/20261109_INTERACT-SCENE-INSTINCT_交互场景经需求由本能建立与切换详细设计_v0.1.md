## 2. 目标与完成条件

1. 宿主允许多个会话（窗口）同时存在，一窗口一外设交互场景。
2. 现实交互场景、窗口副本、交互者副本及“参与交互者”由本能方法在需求驱动下建立；自我线程不再写这些事实，外设通知只作唤醒（新因素）。
3. 自我离开现实交互场景时，原场景“参与自我”同次清除。
4. 多个现实交互场景并存时，经任务调度选择、进入场景完成切换。
5. 被认知需求的说话者为该窗口的交互者副本（第7节第4项待裁决）。
6. 实际项目编译链接通过；完成声明只到“已编译、未运行测试”。

不在范围：建立连接确认基准的改动（另行裁决，见第7节第5项）；交互者从单值改为集合；连接断开与场景清理生命周期；身份核验本能（登录材料复制）。

## 4. 新增本能方法（AGENTS §1.1 分析）

### 4.0 输入、输出与被筹办发现的方式（v0.2）

筹办发现方法只有两条现成通路：
- **召回**：需求目标特征类型属于方法可改变的特征类型（R107：可能结果概念、结果项特征类型、“特征引用存在”左参数规格任一属目标FT）。
- **条件子需求**：父任务所选方法的条件项作用在**已绑定**参数上，产生子需求（目标存在＝该参数绑定的存在，目标FT＝条件项特征类型）。

所以每个新本能的输出特征类型就是它的召回键，而它的父需求，就是那个以该特征为条件项的方法所在的任务。

| 项 | 感知交互窗口 | 确定参与交互者 |
| --- | --- | --- |
| 参数1 | 自我原场景（存在；必需特征类型{现实交互场景集合}） | 现实交互场景（存在；必需特征类型{参与交互者}） |
| 参数2 | 现实交互场景集合特征（特征，属参数1） | 参与交互者特征（特征，属参数1） |
| 参数3 | — | 交互窗口副本（存在；必需特征类型{外设场景标识}） |
| 参数4 | — | 外设场景标识特征（特征，属参数3） |
| 函数内部读取（不作参数） | 外设交互场景列表 | 参数4所指外设交互场景中的交互者 |
| 必要条件（初始必要条件） | 无内部条件项；“有尚未对应的外设窗口”在函数内复核，不成立返回条件未具备 | 参数3是参数1的直接成员；参数2当前值未知（特征前态限定） |
| 行为 | 改变 | 改变 |
| 方法头：涉及特征类型 | {现实交互场景集合} | {参与交互者, 外设场景标识} |

父子链：

```text
交互者需求（自我.交互者 ∈ 人类）── 任务T1，方法：建立连接
  ├ 子需求A：原场景.现实交互场景集合 新增成员   → 召回：感知交互窗口
  ├ 子需求B：场景S.参与交互者 有确定值          → 召回：确定参与交互者
  └ 子需求C：自我.所在场景 = 场景S             → 召回：进入场景（可能结果＝所在场景）
```

**缺口（须裁决，见第11节）**：
1. 子需求B、C都作用在已绑定的场景S上，可以用现有条件子需求机制提出，前提是建立连接声明对应的初始必要条件项（现在v4没有初始必要条件，R94所说“按必需特征分解”在代码中的实际落点待S0核实）。
2. 子需求A不同：此时场景还不存在，建立连接的参数1没有任何候选可绑定，现有机制只会返回“材料未到”而等待，**不会提出子需求**。需要一条新的筹办规则。

### 4.1 感知交互窗口

| 项 | 内容 |
| --- | --- |
| 修改对象 | 现实世界的内部表示：在自我原场景下新增现实交互场景（子场景）及其窗口副本，附两个无值必需特征。属普通方法（改变现实世界在内部的存在与特征），不改任务或方法的虚拟存在。 |
| 原因 | 交互者需求的建立连接没有可绑定的现实交互场景。 |
| 目的 | 让每个当前存在的外设交互窗口在内部世界有对应的现实交互场景，供后续绑定。 |
| 正常操作与结果 | 函数内部列出外设交互场景，对**全部**尚无对应现实交互场景的外设场景各建立一个（不在函数内挑选，确定性地“全部新增”）。结果：自我原场景的可交互场景集合新增成员；返回新建场景列表。 |
| 目标特征 | “可交互场景”集合特征（挂在自我原场景或自我上，待裁决第7节第1项）新增成员；方法头涉及该特征类型，使R107召回成立。 |
| 必要条件 | 外设模块可用；至少存在一个尚无对应现实交互场景的外设交互场景（在函数内部读取，属方法内部复核，不作参数）。 |
| 条件不足 | 没有新外设场景时返回“条件未具备”，零动作；任务等待外设通知唤醒。 |
| 执行入口复核 | 锁内重读外设场景与已有对应关系；复核不通过不建立、不记动作。 |
| 动作 | 先记录本次动作，再建立场景与副本；同一外设场景只对应一个现实交互场景（沿用 `建立或取得现实交互场景` 的查重）。 |
| 工程故障 | 建立失败、对应关系重复等结构损坏走工程异常终止；已建立的保留，不补造结果。 |

### 4.2 确定参与交互者

| 项 | 内容 |
| --- | --- |
| 修改对象 | 指定现实交互场景的“参与交互者”特征值；必要时新建交互者副本（场景成员存在）。普通方法。 |
| 原因 | 候选场景的“参与交互者”无值，建立连接前提不成立。 |
| 目的 | 使该场景的参与交互者指向对应外设交互者的内部副本。 |
| 参数 | 现实交互场景、窗口副本（及其外设场景标识特征）。对象由参数指定，函数内不挑选。 |
| 正常操作与结果 | 函数内部按窗口副本的外设标识读取外设交互场景的交互者P；在该场景按P的标识建立或复用副本R；写“参与交互者”=R。 |
| 必要条件 | 外设场景仍存在且已有交互者（首条消息后才有）；参与交互者当前无值或不等于R。 |
| 条件不足 | 外设尚无交互者时返回“条件未具备”，零动作，等待首条消息通知。 |
| 执行入口复核 | 锁内重读外设交互者与场景特征；复核不通过不写。 |
| 动作 | 先记录动作，再建立/复用副本并写参与交互者（副本建立与参与交互者写入由世界树owner同一次调用完成，沿用R95“成员关系与参与特征同一入口”）。 |

### 4.3 进入场景（修改）

`迁移自我` 在迁入目标场景、写目标“参与自我”的同一次owner调用中，若原所在场景有“参与自我”特征且值为自我，清除其当前值（无值，不删特征），保留历史。补齐6120 §179“离开时一并改写”。

## 5. 多场景并存与切换

1. **候选差异（没有完全相同的存在）**：多个现实交互场景都可绑定时，筹办不得任选。比较依据（待裁决第7节第3项），建议起步：
   - 场景交互者副本是某个活动被认知需求的主体者优先；
   - 同等时按外设交互者首条消息先后（窗口副本或副本的建立强时间）。
2. **切换**：被选中任务的建立连接要求自我在场景B，而自我在场景A → 子需求C → 进入场景，离开A（清除A的参与自我）进入B。A中任务的前提随之不成立，转入等待；之后被调度到时再切回并重新建立连接。
3. **R94“只在候选唯一时提议”**：随第1项依据冻结而放开为“按依据排序后提议首位”。

## 6. 宿主与说话者

1. **宿主多会话**：`活跃网页会话标识` 改为按会话的集合；每个会话独立登记接收认知语境（`登记会话语境` 已按会话登记，需核实多会话并存）；会话结束时只移除该会话。
2. **说话者**：接收认知在复制消息时按“窗口→外设交互者→副本”定说话者为副本R；匿名会话不再中止。会话绑定人类不再作为说话者，改为后续“身份核验”本能复制登录材料到R（不在本切片）。依赖：R须先由4.2建立；未建立时消息保留待治理。

## 11. 新增待裁决（v0.2）

1. **参数无候选时如何提出子需求（子需求A）**：
   - 方案甲（推荐）：参数规格可声明“来源集合”（该参数的候选来自哪个存在的哪个集合特征）。筹办在该参数没有任何候选时，对来源集合提出“新增成员”子需求，父任务就是该方法所在任务。建立连接参数1声明来源集合＝自我原场景.现实交互场景集合。这是通用规则，以后别的方法同样适用；代价是`新方法有序参数规格`新增字段（公开DTO变更）和筹办新分支。

2. **建立连接补初始必要条件**：为提出子需求B、C，建立连接声明：参数1.参与交互者＝参数3（存在引用条件项）；自我.所在场景＝参数1。是否以此取代R94/R95中“按场景必需特征分解”的口径（待S0核实其现行实现后定）。

## 12. 监听口径（v0.3，用户裁决 2026-11-09）

用户裁决：对方打开窗口，就是已经进入交互状态；监听就是看有没有新开的对话窗口。

1. **监听子需求**：目标为自我原场景.现实交互场景集合 **新增成员**（相对需求建立时集合的基准，复用“新增成员”目标形式）。目标作用在始终存在的原场景上，不依赖尚不存在的场景；多窗口时每次以当时集合为基准，取代第11节第1项方案甲/乙。
2. **监听交互窗口**（取代4.1“感知交互窗口”）：等待型本能。已有尚未对应的外设窗口时立即为其建立现实交互场景与窗口副本；没有时以当前外设窗口集合为基准等待新开窗口。结果：集合新增成员。等待期间任务处于“动作已发出等待结果”；需求满足或失活时停止。外设通知只唤醒这个等待。
3. **打开窗口即有交互者**：外设在建立对话框场景（窗口打开）时同时派生交互者，不再等首条消息（修改 `业务/新_外设世界树类.cpp:781`）。因此“确定参与交互者”不需要等待：窗口一经监听建立，交互者即可确定。
4. **提出者**：建立连接增加参数“自我原场景”与条件“参数1属于原场景.现实交互场景集合”。参数1没有任何候选时，筹办按该成员条件对集合提出“新增成员”子需求（即监听子需求），父任务为交互者需求的任务T1。筹办新增此一分支，不改参数规格DTO。
5. **父子链**：

```text
交互者需求（自我.交互者 ∈ 人类）── 任务T1，方法：建立连接
  ├ 参数1无候选      → 监听子需求：原场景.现实交互场景集合 新增成员 → 监听交互窗口（等待新开窗口）
  ├ 场景S参与交互者无值 → 子需求B → 确定参与交互者（不等待）
  └ 自我不在S        → 子需求C：自我.所在场景 = S → 进入场景
```

6. **连接确认不变**：打开窗口表示进入交互状态，建立连接的“确认可达”仍按6120 §191以接收判定（确认基准另裁，见第7节第5项）。
