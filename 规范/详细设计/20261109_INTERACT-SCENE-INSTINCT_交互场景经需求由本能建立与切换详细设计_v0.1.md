# 交互场景经需求由本能建立与切换详细设计

标识：`INTERACT-SCENE-INSTINCT`；版本：v0.8（整合稿，取代v0.1—v0.7全部正文）；日期：2026-11-09；状态：草案（语义已由用户逐项裁决；待S0核实与施工所有权协调后定稿）。
起草：代码窗口（Claude）。施工所有者待定。

## 1. 用户裁决（2026-11-09，本窗口）

1. 内部治理负责需求、任务、方法、学习的闭环推进；本能方法直接改变特征或使特征改变，以真正满足自我的需求。所有动作都基于需求。任务筹办只做通用的目标分解与条件分解，不针对具体需求细分逻辑。
2. 外设应当一个交互窗口对应一个外设交互场景，允许多个窗口同时存在；现有“同时只能一个交互窗口”的限定不对。
3. 内部交互场景改由本能方法建立，不再由自我线程按外设通知自动写入。
4. 对方打开窗口就是进入交互状态；监听就是看有没有新开的对话窗口。
5. 服务对象首先是交互者，打开交互窗口的就是交互者；不是所有交互者都是服务对象，但首先要成为交互者才可能成为服务对象。建立连接是交互的前提，通过交互才能确认交互者是否为服务对象。
6. 用存在根概念生成一个存在作为实例即可，这个实例就是交互者，不用关心它有哪些特征；每个交互者都有自己独立且唯一的稳定编码。
7. 每个交互场景都是自我所在场景的子场景；自我在自我所在场景，必要时进入具体的交互场景。切换时，自我退回自我所在场景，再进入另一个交互场景；改的是自我与场景的关系信息。
8. 监听内置到获取服务对象本能内部；获取服务对象因此不再以交互者为条件。
9. 第7节第1—5项建议全部采纳（其中“可交互场景集合特征”已撤销）。

保留后续讨论（本切片不实施）：关系信息的变更也应生成状态与动态信息，现行只有特征值变化才生成。

## 3. 目标形态

```text
新增服务任务 → 条件一：有服务对象
  服务对象需求（自我.服务对象 ∈ 人类）
    方法：获取服务对象（内置监听）
      → 写 自我.服务对象 = 新来的交互者
    满足判定（“是”的算法 比较存在与概念信息）
      属于   → 满足
      未知   → R-1 认知子需求（例：服务对象.登录账号 有确定值）
                → 询问等交互本能（条件含“已连接”）
                    → 交互者需求（自我.交互者 = 该交互者）── 建立连接
                          └ 自我不在其交互场景 → 进入场景（先退回本场景，再进入）
      不属于 → 不满足，再次获取服务对象（等下一位）
```

人类概念当前为空，满足判定当即为“属于”；补充人类概念要求后自动走交互确认，流程不变。

## 4. 获取服务对象（内置监听）

| 项 | 内容 |
| --- | --- |
| 修改对象 | 现实世界在内部的表示：本场景下的交互子场景、窗口副本、交互者（新存在）；自我的“服务对象”特征值。普通方法。 |
| 原因 | 服务对象需求未满足（服务对象为空、或当前服务对象被判不属于要求概念）。 |
| 目的 | 取得一个新来的交互者作为服务对象，供后续确认与服务。 |
| 参数 | 1 自我（必需特征{服务对象}）；2 服务对象特征（属参数1）；3 本场景（自我所在场景）。 |
| 方法头 | 作用存在{自我概念}；涉及特征类型{服务对象}；可能结果{服务对象}。召回键：服务对象。 |
| 必要条件 | 无内部条件项。外设可用在函数内复核；不可用为条件未具备。 |
| 正常操作 | 1. 在函数内部读取外设交互窗口。2. 选取对象：优先“已有内部表示但从未成为过服务对象的交互者”；没有时取“尚无内部表示的外设窗口”中打开最早者（强时间）；两者都没有时以当前外设窗口集合为基准等待新开窗口（任务处于“动作已发出等待结果”，需求满足或失活时停止）。3. 先记录本次动作。4. 世界树owner同一次调用：为尚无内部表示的外设窗口各建立本场景下的子场景S（具备参与自我、参与交互者特征类型）及S中的窗口副本（外设场景编码特征），以存在根概念生成交互者（无特征，有唯一稳定编码）作为S成员，写S.参与交互者。5. 写自我.服务对象＝选中的交互者。 |
| 选取依据 | “从未成为过服务对象”与“打开先后”是真实差异，写入方法合同；不在多个无差异候选间任选。 |
| 结果 | 服务对象特征当前值变化为选中交互者（特征引用存在(2, 交互者)）；附带形成的子场景、窗口副本、交互者为感知结果，保留。 |
| 工程故障 | 结构损坏（同外设窗口多份内部表示、owner写入失败）工程异常终止；已发生的动作与事实保留，不补造结果。 |
| 模拟 | 外设只在真实执行中读取；模拟用途只记录条件实参，结果未取得（同v4的R96口径）。 |

撤销：v3参数1（现实交互场景）、参数3（交互者副本）、参数4（交互者特征）及其必要条件（参数3属于人类、连接关系）；参数3必需特征“外设存在标识”。v3改为新版本（v4编号由施工按方法版本规则确定）。

## 5. 场景、进入与切换

1. **结构**：每个外设窗口在本场景下对应一个交互子场景；自我平时在本场景。
2. **进入场景（修改）**：
   - 进入某交互场景的条件增加“自我当前在本场景”；自我在S1需要进入S2时，按通用条件分解提出“自我.所在场景＝本场景”，先退回再进入，不允许S1直接到S2。
   - `迁移自我` 在迁入目标、写目标“参与自我”的同一次owner调用中，清除原场景的“参与自我”当前值（保留历史）。
3. **建立连接**：参数保持v4形状；其交互者副本参数撤销必需特征“外设存在标识”，改为“参数3是参数1的参与交互者”（交互者无特征）。由交互本能的“已连接”条件经通用分解引出，不再挂在获取服务对象之下。连接确认基准不在本切片（第8节第3项）。

## 6. 宿主、外设与说话者

1. **宿主多会话**：`活跃网页会话标识` 改为按会话的集合；每个会话独立登记接收认知语境；会话结束只移除该会话。
2. **外设**：建立对话框场景（窗口打开）时同时派生外设交互者，不再等首条消息。
3. **说话者**：接收认知复制消息时按“窗口→外设交互者→内部交互者”定说话者为内部交互者；匿名会话不再中止。会话绑定人类不再作为说话者（身份材料复制留后续“身份核验”本能）。内部交互者尚未由获取服务对象建立时，消息保留待治理。
4. **自我线程**：撤除现实交互场景与交互者副本的全部补建（含启动时），外设通知只唤醒等待中的任务。
