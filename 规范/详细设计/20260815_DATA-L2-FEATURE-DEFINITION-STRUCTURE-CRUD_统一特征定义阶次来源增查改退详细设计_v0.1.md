## 1. 目标

在现有唯一 `L2特征结构服务`、特征定义 owner 和特征定义节点族内，把基础特征与实际二次至 n 次派生特征统一为一套可增、可读、可加改固定属性、可退出、可历史回查的强类型定义结构。

本设计只补齐当前代码缺少的四项权威结构：

```text
非零实际阶次
+ 有序直接来源特征定义关系
+ 每项非零输入角色
+ 派生规则身份与非零规则版本
```

基础特征固定为阶次 `1`、零直接来源、零派生规则；派生特征固定为阶次大于 `1`、非空直接来源和一份派生规则见证。新派生特征的阶次必须等于全部直接来源当前阶次最大值加一。

本设计不生成派生候选、不解释规则业务意义、不验证候选是否解决需求、不建立二次特征独立节点族、服务或 owner，也不修改状态、动态、因果、概念或 DATA-L3 聚合。

### 4.1 派生规则和直接来源

```cpp
struct L2特征派生规则身份 final {
    稳定编码 值;
    friend bool operator==(const L2特征派生规则身份&,
        const L2特征派生规则身份&) = default;
    friend auto operator<=>(const L2特征派生规则身份&,
        const L2特征派生规则身份&) = default;
};

struct L2特征派生规则提交项 final {
    L2特征派生规则身份 规则身份;
    std::uint32_t 规则版本 = 0;
    friend bool operator==(const L2特征派生规则提交项&,
        const L2特征派生规则提交项&) = default;
};

struct L2特征直接来源提交项 final {
    std::uint32_t 顺序 = 0;
    std::uint32_t 输入角色 = 0;
    L2特征定义身份 来源特征定义;
    friend bool operator==(const L2特征直接来源提交项&,
        const L2特征直接来源提交项&) = default;
};

struct L2特征直接来源事实 final {
    稳定编码 关系稳定编码;
    std::uint32_t 顺序 = 0;
    std::uint32_t 输入角色 = 0;
    L2特征定义身份 来源特征定义;
    L2生命周期 生命周期;
    friend bool operator==(const L2特征直接来源事实&,
        const L2特征直接来源事实&) = default;
};

struct L2特征派生规则事实 final {
    L2属性事实 规则见证属性;
    friend bool operator==(const L2特征派生规则事实&,
        const L2特征派生规则事实&) = default;
};
```

`规则身份` 是 DATA 外业务已经裁决并提交的非零稳定身份。它不是特征节点、规则节点族或本服务分配的事实身份。DATA-L2 只验证规则身份与规则版本非零、二者在规则见证属性中无损回显且值结构完整；不解释算法名称、用途、单位、当前可用性、正确性或是否解决当前需求。

### 4.2 统一特征定义事实

```cpp
struct L2统一特征定义事实 final {
    L2特征定义身份 身份;
    L2属性事实 实际阶次属性;
    std::vector<L2特征直接来源事实> 直接来源;
    std::optional<L2特征派生规则事实> 派生规则;
    L2生命周期 生命周期;
    std::vector<L2属性事实> 固定属性;
    friend bool operator==(const L2统一特征定义事实&,
        const L2统一特征定义事实&) = default;
};
```

`实际阶次属性` 的类型化材料必须为正 `I64`，且能无损转换为 `uint32_t`。其属性类型属于服务私有结构登记，不属于调用方可选择的四种固定属性类型。

基础定义完整形状：

```text
实际阶次 = 1
直接来源 = 空
派生规则 = 空
```

派生定义完整形状：

```text
实际阶次 > 1
直接来源非空，按顺序严格升序且顺序从 1 连续
每项输入角色非零
每项来源定义在同一截止完整且未退出
实际阶次 = max(直接来源实际阶次) + 1
派生规则存在，规则身份与版本非零且结构在同一截止有效
```

同一来源可以在不同输入角色下重复使用，同一输入角色也可以用于多个不同来源；`(来源特征定义, 输入角色)` 对不得重复。顺序只表达结构位置，输入角色表达该位置的具名角色，二者不得互相替代。

## 6. 物理事实与私有登记

全部事实仍写入特征定义 owner。服务构造期在现有定义族来源建立之后、任何公开定义创建之前，以一份固定幂等写集建立三个私有结构类型：

1. `实际阶次属性类型`：`I64`；
2. `派生规则见证属性类型`：`U64组`，材料固定为 `[规则身份, 规则版本]`；
3. `直接来源关系类型`：普通关系类型节点。

三者使用一组新的固定非零本地键和一份新的固定 owner 范围幂等身份；不得复用现有固定属性类型登记、特征实例关系类型登记、值类型登记或族来源登记身份。定位只在服务私有成员中保存，公开 DTO 只返回事实见证，不返回写端口、本地键或定位修改权。

精确私有常量冻结为：

```text
特征定义派生结构登记固定幂等身份 = 0x4C32'4644'5354'5201ULL
实际阶次属性类型本地键值         = 0x0203'2301U
派生规则见证属性类型本地键值     = 0x0203'2302U
直接来源关系类型本地键值         = 0x0203'2303U
实际阶次值本地键值               = 0x0203'0401U
派生规则见证值本地键值           = 0x0203'0402U
```

创建写集继续复用现有定义节点和定义族归属关系本地键。每项直接来源关系的本地键按来源顺序从 `1` 开始选择“尚未被本写集其它固定项使用的最小正 `uint32_t`”，遇到固定本地键就递增跳过；候选递增溢出为零时在调用 L1 前返回 `资源失败`。该分配只决定本次不可变写集的局部引用，必须确定性重放，不进入公开 DTO。

直接来源关系方向固定为：

```text
派生特征定义 -> 直接来源特征定义
```

L1 的 `角色或顺序:int64_t` 同时承载顺序与输入角色，唯一编码为：

```text
编码 = (uint64_t(顺序) << 32) | uint64_t(输入角色)
```

顺序只接受 `1..INT32_MAX`，输入角色只接受 `1..UINT32_MAX`，因此编码始终为正且不超过 `INT64_MAX`。解码必须逐值互逆；负值、零值、溢出或不能互逆均为坏结构。

派生规则见证作为派生定义节点的私有 `U64组` 属性保存，材料第一项是规则身份编码，第二项是规则版本；两项均非零且第二项不得大于 `UINT32_MAX`。该值与实际阶次值的来源节点都等于本特征定义身份。规则见证不建立规则节点、关系、owner 或当前可用性事实；规则是否当前可用由 DATA 外调用方在提交前裁决。

## 7. 创建事务

创建请求的期望事实代次必须非零。调用方首次没有任何定义身份时，先调用 `读取全部当前统一特征定义({{合同版本, 0}})`，以返回的非零事实截止作为创建守卫；不得读取私有类型登记、直达 L1 或缓存旧截止代替该公开入口。

### 7.1 基础定义

一份特征定义 owner-scoped 写集原子建立：

```text
定义节点
+ 定义族归属关系
+ 实际阶次值 1
+ 实际阶次属性槽
```

### 7.2 派生定义

写前以请求的非零期望代次完成一次同截止预读：

1. 每个来源经 `读取完整统一特征定义` 证明当前完整；
2. 规则身份和版本按纯值合同证明非零且可无损编码；
3. 计算来源最大阶次并严格核对 `请求.实际阶次 == 最大阶次 + 1`；
4. 核对顺序连续、角色非零、允许重复规则和 pair 唯一性；
5. 任一漂移、退出、坏来源或坏规则见证零写返回对应结构状态。

随后一份特征定义 owner-scoped 写集原子建立：

```text
定义节点
+ 定义族归属关系
+ 实际阶次值与属性槽
+ 每项直接来源关系
+ 派生规则见证值与属性槽
```

成功后以提交截止读回完整统一定义；结果缺项、混代、错误阶次、关系角色不可逆、规则见证错误或存在额外结构均返回 `内部不一致`，不得返回部分成功。

## 8. 读取

当前读取使用 L1 owner-aware 一致当前投影，在请求非零期望代次内闭合：

- 定义节点及定义族身份来源；
- 实际阶次属性；
- 直接来源关系组及来源定义的阶次属性；
- 可选派生规则见证属性；
- 调用方固定属性组。

`读取全部当前统一特征定义` 是无已知身份时取得当前截止和当前定义闭集的唯一公开入口。其 `期望事实代次=0` 精确表示在 L1 同一次关系类型闭包共享许可内选择调用时最新快照；非零值表示严格乐观守卫。成功允许定义组为空，但服务构造已经发布 owner、族来源和私有类型登记，因此事实截止必须非零。结果按定义身份严格升序，定义身份不得重复，任一当前族成员不完整、混代或不能由闭包全部解释时整次返回 `内部不一致`，不得过滤坏成员。

全组读取必须使用特征定义族归属关系类型作为闭包入口，在同一次 L1 闭包投影中取得全部当前族成员、两种私有属性、四种公开固定属性、直接来源关系及其端点阶次见证。不得用“先读当前代次，再逐定义非零读取”模拟零守卫原子最新；若真实 L1 闭包不能一次承载该投影，必须触发具名 DRIFT，而不是临场拼接两次读取。

历史读取以显式历史截止读取同一组历史节点、关系和值，在读取前后复核当前事实代次未漂移。晚于历史截止的退出必须隐藏；早于或等于截止的退出按历史投影保留生命周期。不得用当前关系或默认阶次补历史缺项。

按身份当前读取遇到已退出定义固定返回 `已退出` 且空载荷；历史截止早于创建返回 `未找到`。历史截止达到创建后固定返回 `已读取` 和完整截止投影，即使定义已经在该截止或更早退出，也必须在载荷生命周期、内部属性和直接来源关系中逐项回显退出，不能把历史已退出折叠为当前入口的空载荷 `已退出`。

固定属性结果必须排除两种私有结构属性；出现未知当前属性类型、重复内部属性、重复直接来源关系编码、未排序组、来源阶次不闭合或基础 / 派生形状互串均返回 `内部不一致`。

## 9. 固定属性与实例引用

固定属性新增 / 换代仍使用现有四种公开属性类型登记和现有 DTO。它们在写前必须证明目标是当前完整统一定义；调用方传入私有实际阶次或规则见证属性类型固定返回 `入口拒绝`。

`新增特征实例` 必须在请求期望代次调用 `读取完整统一特征定义`，不能只靠身份来源接受缺阶次旧定义。实例、当前值、按存在枚举和值历史读取的公开形状不变。

## 10. 退出

退出请求由调用方从最近一次同截止完整读取逐字段形成。服务写前重新读取并要求下列集合精确相等：

```text
定义族归属关系
实际阶次值
全部直接来源关系
零或一派生规则见证值
全部当前固定属性值
```

不完整、额外、缺失或错序返回 `引用冲突` 或 `内部不一致`，整笔零变化。一份定义 owner-scoped 写集同代退出定义节点、族归属、内部属性值、全部直接来源关系和固定属性值。

仍被当前特征实例、其它派生定义、概念支持或其它 L1 当前关系引用时，由 L1 当前引用保护返回 `引用冲突`。退出不递归退出来源、规则、实例或概念。成功后当前入口返回 `已退出`，历史入口在具名截止读回完整退出事实。

## 11. 状态、幂等与异常

沿用 4230 的 14 个 `L2结构状态`，不新增状态：

- 写成功只允许 `已提交`、`精确重复`，携带完整定义、非零截止和等于截止的变更代次；
- 读成功只允许 `已读取`，非零截止、无变更代次和完整定义；
- 全组读成功只允许 `已读取`，非零截止、无变更代次，允许零项，全部定义完整且按身份严格升序；
- 其它状态载荷为空；
- 同幂等身份同完整请求精确重复；同身份任一字段不同为 `幂等冲突`；
- 只有零变化且无首次结果的 `事实代次漂移` 允许调用方正式重读后保留同幂等身份重组；
- 资源失败、异常或发布结果未知必须原完整请求重放；
- `bad_alloc`、`length_error` 映射 `资源失败`，其它异常映射 `内部不一致`。

四类 `成功()` 的完整谓词固定为：

1. 创建成功：状态为 `已提交` 或 `精确重复`，截止非零，变更代次存在且等于截止，定义存在、完整且定义未退出；
2. 按身份读取成功：状态为 `已读取`，截止非零、变更代次为空、定义存在且在该截止完整；当前类别要求定义未退出且历史截止字段为零，历史类别要求历史截止等于结果截止；
3. 全组读取成功：状态为 `已读取`，截止非零、变更代次为空；组可以为空，非空时每项完整、未退出并按身份严格升序；
4. 退出成功：状态为 `已提交` 或 `精确重复`，截止非零，变更代次存在且等于截止，已退出定义存在且定义、实际阶次属性、可选规则见证属性、全部直接来源关系和固定属性的退出代次都等于截止。

任一非成功状态必须使用空 optional / 空 vector，且变更代次为空。坏成功形状必须由 `成功()` 返回 `false`，服务实现发现自身形成坏成功形状时改映射为 `内部不一致`，不得把坏载荷原样交给调用方。
