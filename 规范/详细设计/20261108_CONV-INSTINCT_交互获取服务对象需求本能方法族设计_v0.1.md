# 交互获取服务对象需求本能方法族设计

身份：`CONV-INSTINCT`；版本 v0.2（第6节已裁决）；日期 2026-11-08。

## 1. 目标与依据

沿已实现的“双根 → 完成服务需求 → 服务对象需求”链继续分解：通过交互场景取得服务对象的需求信息 → 自我承接为自我需求 → 任务 → 方法。本设计给出这一段需要的本能方法族，每个“出站”本能的直接产物是一个正式表达需求，由表达组织知识组织为一个最小含义网结构（7240 §2，7232 §2.2）。

依据：6120 §5、§11.1—11.3；5170 §2.1—2.3；7240 §2、§5.4；DEMAND-FIELD-QUESTION v0.4b；LANGUAGE-MODULE-CONVERSATION v0.5；CONV-MODEL v0.4；CONV-EXPR-STRUCT v0.3（已施工 `1503a9c66`）。分工：交互窗口（Claude）设计与施工，Codex 审计。

## 3. 需求分解树（目标形态）

```text
完成服务需求（自我.服务值）
└─ 获取服务需求：自我服务任务新增成员（6120 §11.3）
   ├─ 条件1 有服务对象 ── 获取服务对象 ← 建立连接 ← 进入场景            [已有]
   └─ 条件2 H.需求F 当前引用新的完整、经确认的被认知D
        └─ 获取服务对象新需求（落实D）                                  [改：声明条件]
             ├─ 前提 存在待完善或完整的D
             │    └─ 无D时（可选方法）：询问服务对象需求                [新，批2]
             ├─ 条件 D每个必需字段“有确定值”=已有确定值（5170 §2.2）
             │    └─ 补问子需求(D, 字段有确定值F) ── 询问指定需求字段     [改：方法头]
             │         ├─ 归类子需求(词条, 概念名称挂接) ── 询问词条概念     [新]
             │         ├─ 指代澄清子需求(指代实例, 指代消解结果) ── 询问指代所指 [新]
             │         └─ 分界子需求(语言材料范围, 有效分界结果) ── 询问分界   [新]
             └─ 条件 D.内容确认=已确认 ── 请求确认需求内容              [新，批2]
   承接前：D.求助=未知 ── 询问是否需要帮助                          [新，批2]
   服务后：告知行动结果、请求反馈（6190结算证据）……………………… 后续，不在本轮
```

5170 §2.2 已裁决：补问及三类同级子需求的目标F、值目标、维护owner均已定义；补问子需求的方法“可命中询问本能”；回答经治理写入后由F值变化闭合，询问方法不自证效果。本设计沿用，不新增机器语义。

## 4. 出站本能统一形态

每个出站本能遵循 AGENTS §1.1：

| 项 | 统一口径 |
| --- | --- |
| 修改对象 | 现实世界：向受话者发出一条话语（外设输出队列新增一条）；同时留档出站具体表达（语言场景）。不修改D或子需求目标F。 |
| 原因 | 子需求目标F未满足，且该F的值只能来自对方回答。 |
| 目的 | 让对方提供该F所需的信息；F由回答写回闭合，本能不自证。 |
| 方法头涉及特征类型 | 子需求目标F的特征类型（使筹办能按目标召回），外加输出队列类型。 |
| 必要条件 | 子需求目标F当前未满足；受话者在现实交互场景且已建立连接（交互者=H）；输出队列可用；组织所需材料可读。 |
| 执行 | 复核条件 → 建立正式表达需求 → 组织器（一条适用表达组织知识）→ 含义网 → 成文 → 建立动作 → 留档 → 入列（CONV-EXPR-STRUCT 已实现的核心时序复用）。 |
| 返回 | 已入列（附出站具体表达与表达需求）；字段已满足/不适用；前提已变化；缺语言知识/名称/指称/多义（入口拒绝，零动作）。 |
| 工程故障 | 按 CODE-FILE-01 §4.4 工程异常路径，不进入业务结果。 |

### 4.1 本轮出站本能清单与最小结构

| 本能 | 子需求目标F | 表达用途 | 含义网最小结构 | 例句（汉语） |
| --- | --- | --- | --- | --- |
| 询问指定需求字段（已有，改方法头） | D.字段“有确定值” | 疑问 | 静态单元：主体=D目标存在，谓项=特征值(字段FT, 值=疑问代词) | 水温要多少？ |
| 询问词条概念（新） | 词条.概念名称挂接 | 疑问 | 静态单元：主体=词条所指，谓项=概念归属(疑问代词) | “X”是什么？ |
| 询问指代所指（新） | 指代实例.指代消解结果 | 疑问 | 静态单元：主体=指代实例，谓项=同一指认(疑问代词) | “它”指的是哪个？ |
| 询问分界（新） | 语言材料范围.有效分界结果 | 疑问 | 静态单元：主体=语言材料范围，谓项=组成(疑问代词)；量化=列举候选（如有） | “ABC”是“AB/C”还是“A/BC”？ |

每个本能各配一条表达组织知识种子（`初始化材料/表达组织知识种子.txt`），取材算子沿 7240 §2.3 具名算子补充。

## 5. 相关非出站改动

1. **获取服务对象新需求声明字段条件**：D待完善时不再只返回“材料待齐”，而是按5170 §2.2 声明每个必需字段“有确定值=已有确定值”为必要条件，使通用筹办提出补问子需求；字段全部确定后才进入原落实动作。
2. **回答写回**：属输入侧治理（7240 §5.4“回应 → 被回应项的提出方”），依赖 CONV-INPUT（含义网输入、回应关联到出站具体表达），不是出站本能；排在本方法族之后。
3. **成文前置**：新结构要成文，必须先完成 CONV-EXPR-TEXT（含义网通用成文、拆除过渡转换）；过渡转换只接受首条知识形状。

## 6. 用户裁决（2026-11-08，已写入 5170 v3.4、6120 v1.9、0300 R106）

1. **想／做不拆分**：出站本能保持“组织 → 成文 → 留档 → 入列”在同一本能内。旧设计所说的“发送裁决”就是任务真正执行前既有的最后检查与权限核对（执行冻结、执行许可），已经实现，不另造发送本能。LANGUAGE-MODULE-CONVERSATION v0.5 中“想／做分为两个本能”的口径对本方法族不再适用。
2. **开放询问允许，只问不猜**：“询问服务对象需求”作为与获取服务对象新需求同一目标（H需求特征）的另一可选方法，必要条件为H在现实交互场景且已连接、当前没有待完善或未落实的被认知D。
3. **内容确认与求助本轮一起做**：被认知D新增需求owner维护的“内容确认”（未确认／已确认／被否认）与“求助”（未知／已求助／不需要）F；确认、求助子需求的值目标均为取得确定回应的等于集合；内容确认为已确认是D落实的必要条件；求助只影响自我承接。

## 7. 施工顺序（目标模式）

1. CONV-EXPR-TEXT：含义网 → 文字（计划2，前置）。
2. CONV-INSTINCT 批1：获取服务对象新需求声明字段条件；询问指定需求字段方法头；询问词条概念、询问指代所指、询问分界三个新本能及组织知识种子。
3. CONV-INPUT：回答关联与写回（计划3）。
4. 批2：询问服务对象需求、请求确认需求内容、询问是否需要帮助，及“内容确认”“求助”F的需求owner落地。
5. 批3：告知行动结果、请求反馈（与6190结算证据合并设计）。

每批：Claude 施工 → 实际项目编译链接 → Codex 审计 → 复核修正 → 提交推送。默认只编译，不运行测试。
