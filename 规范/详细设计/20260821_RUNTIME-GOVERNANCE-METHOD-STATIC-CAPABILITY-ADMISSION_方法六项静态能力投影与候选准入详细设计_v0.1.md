# 方法六项静态能力投影与候选准入详细设计

版本：v0.2
日期：20260822

## 1. 目标与完成边界

本设计闭合“下一筹办工作包”继续运行前的最早方法提供者缺口：

```text
正式方法结构
→ 同一事实截止形成零到多份六项静态能力值式投影
→ 按用途四元组有界粗召回
→ DATA 外逐投影执行六项精确匹配
→ 稳定返回匹配候选与结构不完整粗召回项
```

完成时只证明：方法结构能够正式承载并读回用途、方向、结果类型、条件结果关系、输入规格和限制条件；合法 DATA 外消费者能够在调用方冻结的共同截止取得六项静态候选准入结果。

本设计不实施：

```text
消费下一筹办工作包
目标状态解析
筹办占用或执行权
当前条件、动作入口、输入、参数、禁止项、授权、安全、验证和归因就绪复判
方法选择、路径、实例、执行冻结或真实动作执行
学习需求、方法补齐、任务完成、需求结算或价值回流
路径验证或跨进程恢复
```

## 4. DATA-L2 结构 ABI

### 4.1 合同与强类型

在 `海中鱼巣/领域/L2普通方法结构.数据.h` 中：

```cpp
inline constexpr std::uint32_t L2普通方法结构合同版本 = 2;

enum class L2方法变化方向 : std::uint8_t {
    负方向 = 1,
    无变化 = 2,
    正方向 = 3
};

enum class L2方法限制条件类别 : std::uint8_t {
    禁止项 = 1,
    适用范围 = 2,
    规格约束 = 3,
    安全限制 = 4
};
```

新增强类型稳定身份：

```cpp
L2方法用途身份
L2方法输入规格身份
L2方法限制条件身份
L2方法条件结果关系身份
```

每个新增身份只包装 `稳定编码` 并提供默认比较；零值非法。

目标对象类型直接复用概念 owner 的 `L2概念身份`，不建立方法专属包装。写前必须在相同期望事实代次确认它是存在本体根，或是当前归属于存在本体根的普通概念。

结果类型使用闭合强类型联合，不建立方法专属稳定身份：

```cpp
using L2方法结果类型引用 = std::variant<
    L2目标状态合同身份,
    L2概念身份>;
```

分支机器序号固定为 `1 = L2目标状态合同身份`、`2 = L2概念身份`。持久化、幂等材料、用途索引和排序统一使用两个 `U64`：`[分支机器序号, 身份稳定编码值]`；禁止使用 `std::variant::index()`、内存布局、类型名或哈希值。状态合同分支经 `L2状态结构服务::读取完整目标状态合同` 同截止互证；概念分支经 `L2概念结构服务` 同截止互证为动态本体根或归属于动态本体根的普通概念。联合分支不同即不相等，即使底层稳定编码数值相同也不得相等；裸稳定编码、目标值、名称、来源编码和材料身份均不得替代结果类型。

### 4.2 提交本地顺序

条件和结果提交项增加从 1 连续递增的请求本地顺序：

```cpp
std::uint64_t 条件本地顺序;
std::uint64_t 结果本地顺序;
```

用途、输入规格和限制条件提交项各自具有从 1 连续递增的本地顺序。条件结果关系通过条件/结果本地顺序引用同一请求内的提交项；零值、越界、重复或非连续顺序均为入口拒绝。

这些本地顺序只用于一笔提交内映射新身份，不成为长期方法语义或公开关系端点。

### 4.3 提交与事实类型

新增并按 4270 v0.2 精确实现：

```cpp
struct L2方法用途提交项;
struct L2方法用途事实;
struct L2方法输入规格提交项;
struct L2方法输入规格事实;
struct L2方法限制条件提交项;
struct L2方法限制条件事实;
struct L2方法条件结果关系提交项;
struct L2方法条件结果关系事实;
```

`L2方法条件提交项/事实` 增加 `L2概念身份 目标对象类型`；场景改为 `std::optional<L2场景身份>`。`L2方法结果提交项/事实` 删除场景和独立目标状态合同字段，增加 `L2概念身份 目标对象类型`、变化方向和 `L2方法结果类型引用 结果类型`。

`L2普通方法提交材料` 精确包含：

```cpp
L2方法内容版本 内容版本;
L2方法规格版本 规格版本;
L2方法生命周期版本 生命周期版本;
std::int64_t 生命周期发生时间;
稳定编码 生命周期来源稳定编码;
std::vector<L2方法用途提交项> 用途;
std::vector<L2方法条件提交项> 条件;
std::vector<L2方法结果提交项> 结果;
std::vector<L2方法条件结果关系提交项> 条件结果关系;
std::vector<L2方法输入规格提交项> 输入规格;
std::vector<L2方法限制条件提交项> 限制条件;
L2方法动作入口提交项 动作入口;
```

旧作用对象绑定、参数、禁止项和适用范围节点式/独立身份组从合同版本 2 的公开方法事实与提交材料退出。作用对象角色直接进入用途、条件、结果、输入规格和限制条件；方法所需参数的类型、角色和约束进入输入规格关系，某轮实际参数值只属于后继任务路径或实例绑定，两者都不得建立第四类长期方法知识结点。

`L2普通方法事实` 对应返回方法身份、身份来源、治理虚拟存在、三个版本、上述事实组、动作入口和生命周期事实。全部组按身份稳定升序；事实完整性必须互证方法、内容版本和截止。

### 4.4 条件结果映射

新增方法时：

1. 服务按本地顺序为条件和结果建立稳定身份；
2. 建立 `本地顺序 -> 正式身份` 的本次调用局部映射；
3. 条件结果关系、条件级输入规格和条件级限制条件通过该映射写入正式端点；
4. 任一引用失败时整笔写集零写；
5. 映射不保存到长期事实。

替换方法同样在一个 owner 写集中退出旧当前结构并发布完整新结构；不得分别修改单个条件或结果造成混代。

### 4.5 结构缺口

新增：

```cpp
enum class L2方法结构缺口类型 : std::uint8_t {
    缺方法用途 = 1,
    用途结果冲突 = 2,
    条件结果关系缺失 = 3,
    输入规格引用冲突 = 4,
    限制条件引用冲突 = 5,
    旧合同不能投影 = 6
};

struct L2方法结构缺口 final {
    L2方法结构缺口类型 类型;
    L2方法身份 方法;
    std::optional<L2方法条件身份> 条件;
    std::optional<L2方法结果身份> 结果;
};
```

缺口是只读值，不写入仓库，不解释为方法能力缺失、方法不可用或学习需求。

### 7.2 结果状态与结论

```cpp
inline constexpr std::uint32_t 方法静态能力准入合同版本 = 1;

enum class 方法静态能力准入状态 : std::uint8_t {
```

提供者不持有任务、需求、状态或写服务。

### 7.5 诊断责任

本切片新增或直接修改函数的诊断责任固定如下：

| 函数组 | 诊断责任 | 边界 |
| --- | --- | --- |
| 六项签名完整性、等值、规范化排序键、结果 `成功()` 等纯值函数 | 无适用错误分支 | 只做确定性值计算；非法值返回 `false`，不记录日志、不读取或写入事实 |
| `L2方法结构服务` 新增、替换、退出、当前/历史读取、用途粗召回、投影读取及其内部校验/映射/写集/读回辅助 | 向上送出 | 通过既有 `L2结构状态`、结果头或异常把入口拒绝、漂移、引用冲突、资源失败和内部不一致送到合法调用方；本层不重复记录 |
| `L2方法结构服务` 构造及普通应用装配调用点 | 向上送出 | 构造失败沿既有普通应用装配异常链送出，不新增第二日志责任边界 |
| `方法静态能力候选准入提供者` 构造函数 | 无适用错误分支 | 只保存已存在方法服务的非 owning `const` 引用 |
| `方法静态能力候选准入提供者::读取匹配候选` 及其模块内部状态映射/排序/去重辅助 | 向上送出 | `noexcept` 根函数把 DATA 非成功和内部异常收敛为冻结的业务结构化状态；不写日志、不吞成空候选 |
| 两个端到端专项入口中本切片直接修改的测试函数 | 向上送出 | 以既有专项布尔/结构化失败材料送到测试汇总入口，不成为生产机器事实或生产日志责任边界 |

不得为满足诊断责任新增生产日志字段、故障注入、计数器、测试模式或第二返回入口。

## 8. 根函数过程

`读取匹配候选` 固定过程：

1. 校验合同、请求头、读取类别、截止、六项签名和两个预算；非法返回入口拒绝。
2. 从需求签名抽取用途四元组，在相同读取类别和截止调用 `按用途读取方法粗召回组`。
3. DATA 状态映射：数量预算不足、事实代次漂移、引用冲突、入口拒绝、资源失败和内部不一致分别映射到同名业务状态；不得降级为空候选。
4. 逐个稳定升序的粗召回方法调用 `读取方法六项静态能力投影组`，每次使用原请求截止。
5. 读取结果有结构缺口时合并为一个方法级结构不完整项；同一缺口稳定去重。
6. 对每份完整投影调用 `L2方法六项静态能力签名相同`；相同者进入匹配候选，不同者只计入已扫描，不返回为候选。
7. 对相同方法、内容版本、规格版本、主轴结果和签名的重复候选稳定去重；其它复义返回内部错误。
8. 按组形状形成四态结论；返回原共同截止，不读取或升级到最新事实代次。

提供者不得读取名称、函数名、分类标签、日志或目标数值；不得执行当前条件和禁止项判断。

## 9. DATA 写入与读回事务

新增或替换方法必须在一个方法 owner 原子写集中形成：

```text
方法头和身份来源
治理虚拟存在
动作入口
用途组
条件组
结果组
条件结果关系组
输入规格组
限制条件组
生命周期事实
```

任一端点、版本或本地顺序错误都在写前拒绝。成功和精确重复后必须用写入代次独立历史读回完整方法，并重新形成投影，逐字段等于提交材料对应的规范化投影。

替换时旧完整结构同代退出，新完整结构同代创建；旧截止仍能读回旧投影，新截止只能读回新投影。退出后当前粗召回不返回方法，历史粗召回仍可按退出前截止重建。

## 10. 代码文件与依赖方向



## 11. 验证矩阵

### 11.1 DATA-L2 结构

1. 单用途、单结果、空条件与空限制形成一份完整投影。
2. 存在根/存在概念可作为目标对象类型；特征根、动态根或错根普通概念作为目标对象类型必须零写拒绝。
3. 目标状态合同与动态根概念两种结果类型分别可读；错根概念、已退出或混代结果类型必须零写拒绝。
4. 多用途、多结果按匹配四元组形成多份投影，不发生用途与无关结果笛卡尔组合。
5. 条件只进入正式关联结果；条件级和全方法输入/限制正确合并。
6. 本地顺序越界、重复、非连续、跨方法引用和版本冲突零写。
7. 新增、精确重复、同键异义、替换、退出、当前和历史读回完整。
8. 旧合同方法只形成结构缺口，不反推方向或结果类型。

### 11.2 候选准入

9. 六项完全相等形成候选；六项逐项各制造一次差异均不形成候选。
10. 结果类型联合分支不同即不匹配，即使底层稳定编码数值偶然相同也不得相等。
11. 空组只与空组相等；非空组与空组不匹配。
12. 同时存在匹配候选和结构不完整项时结论为“有匹配且有结构不完整”。
13. 全量扫描无匹配且无缺口时才是“匹配为空”。
14. 扫描或候选预算不足不返回截断组。
15. 当前性漂移、引用冲突、入口拒绝、资源失败和内部错误结构化分账。
16. 固定旧截止后发布新方法版本，重复读取仍返回旧候选，不升级截止。
17. 函数全链零写任务、需求、路径、实例、学习需求或能力缺口事实。

### 11.3 工程与生产外合法消费者

扩展 `端到端测试.需求服务.ixx` 覆盖 DATA-L2 方法结构往返；扩展 `端到端测试.自我治理一致事实.ixx` 作为 DATA 外合法消费者调用候选准入提供者。该专项现有手工装配必须在方法服务之前建立测试自有的不可变材料服务与概念服务，并把概念服务同实例只读借给方法服务；不得用伪概念编码绕过正式根/普通概念读回。专项必须通过公开入口和独立读回，不访问服务私有容器。
