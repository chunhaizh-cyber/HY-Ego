# 旧节点直接恢复门面与未实现世界引导删除详细设计 v0.1

日期：2026-08-09

状态：创建侧验证后登记

## 1. 目标与完成条件

删除旧节点直接结构恢复公开服务和只返回“未实现”的节点直接世界引导服务。两者不属于当前第一至第五层中性数据结构 CRUD，且没有生产构造者或调用者；不得为保留未来恢复可能性继续让它们进入生产工程。

完成必须同时满足：

1. `服务.节点直接世界引导.ixx` 与 `服务.节点直接结构恢复.ixx` 从源码和工程登记中消失。
2. 生产源码不再定义或引用 `节点直接世界引导服务`、`节点直接结构恢复服务`、`确保现实世界已引导` 和 `恢复安装实例`。
3. 现行节点直接结构提交、查询和第一层中性 CRUD 保持可构建；正式生产入口不因本次删除新增失败。
4. 下层持久证据端口、恢复 DTO、数据操作恢复入口、执行器恢复事务和仓库恢复候选保持原样，留给后续独立事实扫描和清理计划，不在本叶无审计连带删除。

## 2. 当前事实与裁决

正式起点为 `022203aee9ee091e8cedb2717a489dec4c936b07`。创建侧从已发布代码确认：

- `节点直接世界引导服务::确保现实世界已引导` 忽略请求并固定返回 `未实现`；全仓没有该服务的构造者、成员、参数传递或函数调用者。
- `节点直接结构恢复服务` 在生产源码中的唯一外部引用，是被上述未实现世界引导服务 import、构造注入并保存；没有其它服务构造或调用 `恢复安装实例`。
- `启动.生产运行期.ixx` 的文件规则明确当前生产启动不得进入恢复路径。
- 两个目标源码均为 clean；工程和 filters 另有异主双轴根登记 WIP，本计划只删除两个目标文件的登记行，不夹带双轴根新增行。
- 下层恢复实现仍存在相互引用，不能从顶层无调用事实直接推出其所有类型和函数均可在本叶删除。

裁决：先删除两个顶层零消费者死门面，释放公开模块和工程负担；不把“未实现”改写为中性 CRUD，不为恢复建立兼容壳。后续再从发布后的真实调用图审查下层恢复实现。
