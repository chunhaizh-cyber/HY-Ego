## 1. 目标、替代关系与不变边界

v0.16 替代并禁止施工 v0.15 中尚未冻结的 G1—G8 领域意图摘要编码部分。v0.15 已成立的 P-L1/P-I/P-S 身份、合同版本 2、规则版本 0/1、I02=`2/2`、F02=`3/3`、X02=`2/2`、模式 1/2/3、共享操作标签、provider 前探测、一次 L1 v2 提交、发布后读回、恢复拒绝、32 个生产/业务场景、18 个自检调用、16 文件/50 物理调用点和 24 文件白名单全部保留。

本版本只冻结：

1. G1—G8 公开请求字段的唯一顺序和确定性字节编码；
2. 唯一公共编码原语、摘要函数签名和物理位置；
3. 领域摘要与中性 G0 规范化写集摘要、操作标签的互证关系；
4. 同义/异义、恢复重算、缺字段和错误模式的拒绝矩阵。

这是一份待施工合同，不证明当前代码已有 G1—G8 领域摘要、provider 前探测或完整运行闭环。核心不得把 G0 写集摘要写回或覆盖调用方已经形成的领域意图摘要。

## 2. 当前事实与缺口

正式基线的 `核心/L1事实基座.数据.h` 已有 `写U8`、`写U32`、`写U64`（网络大端）、`写引用`、`写材料`、`写写集`、`写执行证据材料正文` 和同文件 SHA-256 `哈希`。现有 `准备L1写集v2` 仍按操作标签从 G0 写集形成 `请求意图摘要`；该行为必须由本版本施工步骤替换为“保留调用方摘要、只计算并校验独立 G0 摘要”。

正式 DTO 来源为：G1 `世界登记建立请求`，G2 `初始场景创建请求`，G3 `特征定义登记请求`/`I64特征定义建立请求`，G4 `初始场景I64实例特征建立请求`，G5 `L1写集请求`，G6 `实际存在创建请求`/`实际存在读取请求`，G7 `实际存在I64首个基准状态发布请求`，G8 `特征比较请求`/`I64状态迁移比较请求`及其嵌套见证。结果 DTO、provider 身份、写前事实见证和执行证据不得进入公开请求意图摘要。

## 3. 唯一公共编码合同

### 3.1 物理位置和签名

公共原语只允许位于 `海中鱼巣/核心/L1事实基座.数据.h` 的 `L1确定性编码内部`，不得在各领域重复实现：

```text
写U8(std::vector<std::uint8_t>&, std::uint8_t) noexcept
写U16(std::vector<std::uint8_t>&, std::uint16_t) noexcept      // 大端
写U32(std::vector<std::uint8_t>&, std::uint32_t) noexcept       // 大端
写U64(std::vector<std::uint8_t>&, std::uint64_t) noexcept       // 大端
写I64(std::vector<std::uint8_t>&, std::int64_t) noexcept        // 按 U64 二补码
写稳定编码(std::vector<std::uint8_t>&, 稳定编码) noexcept
写引用(std::vector<std::uint8_t>&, const 事实引用&) noexcept
写可选<T>(std::vector<std::uint8_t>&, const std::optional<T>&)
写变体<T...>(std::vector<std::uint8_t>&, const std::variant<T...>&)
写向量<T>(std::vector<std::uint8_t>&, const std::vector<T>&)
写数组<T,N>(std::vector<std::uint8_t>&, const std::array<T,N>&)
写字段头(std::vector<std::uint8_t>&, std::uint16_t 编号,
          std::uint8_t 类型, std::uint32_t 字节数) noexcept
哈希(std::vector<std::uint8_t>) -> L1确定性摘要
```

`写字段头` 的类型标签固定为：`1=U32`、`2=U64/I64`、`3=U8/枚举`、`4=稳定编码`、`5=嵌套`、`6=可选`、`7=变体`、`8=向量`、`9=定长数组`、`10=布尔`。所有长度为 U32；溢出、未知标签、字段号重复或字段未按冻结顺序写入均拒绝。

### 3.2 领域摘要帧

每个领域摘要先写固定 8 字节 ASCII 域前缀 `HZY-L1G1` … `HZY-L1G8`，再写 `格式版本(U32)=1`、`组号(U8)`、固定操作标签(U32)，随后按 §4 的字段号写字段头和 payload，最后调用唯一 `哈希`。字段不写名称、不写内存布局、不写 padding；整数和长度均大端。嵌套值递归使用同一字段头，optional 先写存在标记 `0/1`，variant 先写 alternative 标签，vector/array 先写元素数量（array 数量必须等于 N）再按元素顺序写入。

稳定编码只写 U64 值；节点/关系/值见证按 DTO 声明顺序写其稳定编码、种类/角色和代次。`std::int64_t` 按二补码 bit pattern 写 U64。该规则同时适用于嵌套请求和事实见证字段，禁止使用实现地址、unordered 顺序、locale 或 JSON/text 序列化。

## 5. 调用顺序、G0 互证与核心禁止覆盖

每个 G1—G8 首次路径严格执行：

```text
公开请求 DTO -> 领域摘要函数 -> 预探测幂等(领域摘要) -> 仅未找到时读取 provider/写前事实
-> 形成独立 G0 规范化写集摘要 -> 互证标签、组号、格式版本、幂等键和摘要关系
-> 准备/提交 L1 v2 -> 发布后读回
```

`L1领域意图凭证` 固定为 `{请求意图组(U8), 请求意图格式版本(U32), 请求意图操作标签(U32), 请求意图摘要(32 bytes)}`；`L1写集请求` 保留同名值式字段或等价嵌套 DTO。调用方在进入核心前一次性填写四者；核心仅接受非零摘要、已知组/版本、标签与入口白名单一致，并独立形成 G0 摘要。G0 摘要用于规范化写集和执行证据，不能作为领域意图摘要的替代物，且 `写写集` 明确排除这四个互证字段，避免把调用方摘要重新混入 G0。

`准备L1写集v2(L1写集请求&, L1领域意图凭证)` 不再从写集推导或覆盖 `请求意图摘要`；若调用方凭证、领域摘要、操作标签或 G0 互证不一致，返回入口拒绝且零 L1 写。执行证据摘要同时保留领域摘要和 G0 摘要的独立字段/互证值；摘要字节本身仍为不透明 32 字节，不尝试反推原文。

## 6. 恢复、同义/异义和失败矩阵

恢复候选必须从调用方登记的 G 组、格式版本、固定标签和公开请求 DTO 重新形成领域摘要，并从首次规范化写集重新形成 G0 摘要；两者分别与幂等账、首次审计、执行材料和发布后读回互证。缺少公开字段、字段顺序改变、未知类型标签、长度溢出、错误端序、错误组/版本/标签、领域摘要被 G0 替换、G0 与首次写集不等，均拒绝候选。

| 分支 | 领域摘要 | G0 摘要 | provider/提交 | 结果 |
|---|---|---|---|---|
| 首次合法模式1/3 | 形成并保留 | 独立形成 | 按 v0.15 模式，空仓模式允许合法空组 | 成功或既有模式结果 |
| 首次合法模式2 | 形成并保留 | 独立形成 | provider 前探测后读取 | 成功，DTO 与首次证据闭合 |
| 同义重复 | 与首次完全相等 | 只读首次 G0 | 0/0 | 账/读回结果，不重新读取 provider |
| 异义请求 | 与首次不同 | 不进入提交 | 0/0 | 幂等冲突，无业务载荷 |
| 缺字段/错版本/错标签/错摘要 | 无法重算或不等 | 任意 | 0/0 | 入口拒绝 |
| 双账、审计、恢复或发布后读回矛盾 | 可重算但互证失败 | 可重算但互证失败 | 不补写 | 内部不一致并隔离 |

G1—G8 的公开字段差异必须改变领域摘要；同义重复必须保持领域摘要、标签和幂等身份一致。核心不得用统一 provider 后 helper 代替 provider 前摘要，也不得以调用序号改变标签。

## 7. 测试向量与机械门禁

参考编码器必须提供以下固定向量，字节串以十六进制表示，哈希为 SHA-256：

1. `G1-min`：`485A592D4C31473100000001011500070100010100000004000000020002010000000400000001000302000000080000000000000001000402000000080000000000000000`，期望 `e8a069b8d3bb3da75aed2d92b16b22932c2682c7686312b4c882deec6f7c7b0b`。
2. `G1-rule-diff`：仅把字段 2 的值从 `00000001` 改为 `00000002`，期望摘要必须不同且不得等于 `G1-min`；该向量验证公开版本差异进入意图摘要。
3. `G2-nested-root`：最小合法世界根见证与 `G2` 固定标签，验证嵌套字段长度、节点种类标签和字段顺序；同一值式请求重复编码字节必须完全相等。
4. `G4-optional/vector`：定义读取请求的 optional 缺省/存在两版和空/非空 vector 两版，验证 `0/1` 存在标记、元素数量和元素顺序；四个摘要必须成对相等/成对不等。
5. `G8-variant`：目标判断请求 `预期算法族/版本` 缺省与存在两版，验证 optional 标签和枚举 U8；状态迁移请求验证两个嵌套读取请求按字段号固定排列。
6. `G0-mismatch`：同一写集分别以 G0 和任一 G1—G8 摘要提交，必须在核心互证入口拒绝；核心不得把 G0 字节复制到请求意图字段。

创建侧必须机械确认 8 组函数、所有固定标签、所有字段号/类型/物理位置、公共原语唯一、向量覆盖 nested/optional/variant/vector/array/大端/稳定编码/事实见证、同义/异义关系和 G0 不覆盖规则。
