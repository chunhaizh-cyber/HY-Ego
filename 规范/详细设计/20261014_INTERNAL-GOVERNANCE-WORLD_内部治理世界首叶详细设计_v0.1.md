## 1. 用户裁决、目标与排除项

用户最新明确授权新增类 `新_内部治理世界类`：治理实例独立世界根，与现实、自然语言、模拟世界并列；概念共享；任务／方法 owner 不变；内部治理世界组织治理场景、虚拟存在引用，协调真实状态、动态、动作，交付因果并提供限定查询。

本叶的唯一生产变化是 `新_任务类::标记任务已结算()` 已有的 Vt 任务状态 `已完成 → 已结算`。修改的是虚拟存在特征值，原因是普通服务值结果独立确认后的内部收尾，目的是记录已完成结算；不是再次改变服务值，不建立第二次现实动作。普通服务值动作及其 S/D 仍在现实场景，内部已结算动作及其 S/D 改入治理场景。

本轮具名替代旧口径：0050 中“Vt 不入世界树”在本叶解释为不入现实／语言／模拟世界，允许以引用进入独立内部治理世界；“任务阶段状态不属于世界 S/D”不再禁止本叶真实治理状态进入治理 S/D。Vt 实例身份和状态写权仍属于任务 owner，现实 self 不复制、不迁移、不取得第二身份。旧冲突条款仅是后继规范清理线索，不阻断本叶。

排除：材料内容域、服务对象／服务需求包持久化、Vt 材料子需求、自然语言理解、全部任务状态迁移自动化、方法 Vm 治理变化、跨 Vt 发生归纳、跨世界因果应用、自动生成组合方法。首叶不能宣称本能方法已全串联。

## 2. 当前事实与直接复用

1. `新_场景类` 构造已显式接受世界根引用；`是场景节点()` 沿父链核验归属根，可复用为严格根隔离。
2. `新_状态类::建立状态()` 已允许 task friend 以 Vt/F 当前值建 S；不必把 Vt 建成普通 E。
3. `新_动态类::建立原子动态()` 接受同主题 Vt 的两 S；当前 `关联动作结果()` 却只接受普通目标，必须增加 Vt 分派。
4. `建立内部治理动作动态()` 已核验 `{T,Vt,状态F}` 并生成动作概念；直接复用，不新建第二动作定义或因果来源账。
5. `标记任务已结算()` 当前将内部动作挂现实场景，只写 F，不生成 S/D。服务值结算确认的重复分支也在现实场景查内部动作，两处须同步迁移。
6. 因果根和待形成发生组是全局结构，单独构造第二因果对象不能自动隔离。完整因果构造没有动作证据 provider，必须显式装配；不能用简构造跳过场景门禁。
7. 具体 Q 分组保留实际参与者编码。一个任务已结算只能发生一次，不同 Vt 的两次结算不会变成同一具体 Q。本叶允许实际交付后仅保留首例；不修改这个统计语义。

## 3. 物理位置、唯一 owner 与组合根

新增 `海中鱼巣/业务/内部治理.世界.h/.cpp`，类名 `新_内部治理世界类`，符合功能.分类命名。该类只组合下层公开入口，不直接调用基础数据集 CRUD。

内部世界持有一个独立根编码和一个独立 `新_场景类` 视图，复用现有特征值、特征、状态、动态、存在以及全部概念 owner。根本身就是场景，首叶全部结算发生在此根场景；不为每次任务另造场景。下层场景 owner 保存治理引用结构；task 保存 Vt 和专属概念引用；S/D/Q 仍分别由原 owner 保存。

普通应用组合根构造本对象并注入 task 只读 provider，随后把内部世界引用装配到 task 和服务值结算运行服务；最后才启动线程。根工程登记新增 h/cpp。不得通过全局 task 查找器、隐式注册或临时项目绕过组合根。

## 5. 中立场景 owner 的引用结构和入口

`新_场景类.h/.cpp` 增加以下公开入口，均先完整核验参数再发布，回调发生在场景锁外：

```cpp
新场景操作状态 添加治理任务引用(稳定编码 C,
    const 新任务虚拟存在引用&, const 新内部治理对象读取接口&) noexcept;
新场景操作状态 添加治理执行主体引用(稳定编码 C, 稳定编码 E,
    稳定编码 现实C, const 新_场景类& 现实场景) noexcept;
std::optional<新治理场景参与者> 读取治理参与者(稳定编码 C, 稳定编码 节点,
    const 新内部治理对象读取接口&) const noexcept;
新场景操作状态 添加治理状态(稳定编码 C, 稳定编码 S,
    const 新内部治理对象读取接口&) noexcept;
新场景操作状态 添加治理动态(稳定编码 C, 稳定编码 D,
    const 新内部治理对象读取接口&) noexcept;
```

场景构造增加末尾参数 `新场景树用途 用途 = 新场景树用途::普通`，枚举只含普通、内部治理；根建立时在场景 owner 的根字段保存用途并核验构造配置一致。只有内部治理用途允许以上入口。用途不是世界根身份替代品，仍须沿父链核验当前根。

用途字段使用 I64：普通=1、内部治理=2。旧根缺此字段只解释为普通，不回填全仓；新治理根必须恰一用途字段且值为2。未知值、重复字段或普通构造绑定显式治理根均为工程结构错误。子场景不复制用途，沿唯一父链从根读取。

场景 owner 新增具名字段／类型：根用途；治理引用类型；所属治理C；引用种类；引用参与节点；引用任务、Vt、状态F；引用现实来源C。治理引用是所属 C 的独立内部结构节点，每 `(C,参与节点,种类)` 唯一，以正式引用保护全部端点。

唯一组织方向固定为“新引用记录节点 → 所属治理C字段 → 既有C”。记录自己的类型、C、种类、参与节点及分支所需T/Vt/F或现实来源C全部由 `原子建立节点组` 一次发布；按底座 `查询字段引用节点结构(C,所属治理C字段)` 反向枚举。不要另加 C→记录字段或外部关系，更不能把给既有 C 的二次挂接宣称为一次原子发布。场景写锁内先查完整同键记录：完全一致复用，异义工程停止；未命中才发布新记录。

Vt 引用持有 T/Vt/F，不复制状态值；self 引用持有真实 E、真实来源 C，不写成员存在字段。当前 EC 来自 task／existence owner，不能在场景中缓存第二份可变权威。读回必须检查种类1恰有完整T/Vt/F且无现实来源C，种类2恰有现实来源C且无T/Vt/F；缺字段、重复字段和异种字段均工程停止。

治理状态必须指向已登记 Vt 和该引用的 F；实际值、FT、时间从正式 S 读取。治理原子动态的两端 S 必须都已挂本 C。治理动作必须是 Vt 目标，该 T/Vt/F 与引用完全相同，执行 self 必须是本 C 的现实执行主体引用。普通 `添加状态/添加动态` 不接受治理 Vt；`添加动态` 的该拒绝必须位于已有挂接早退之前，不能让旧现实场景中的 Vt 动作因重放绕门。

引用增加、S/D 引用计数与现有 scene 规则相同。删除空场景须把治理引用视为非空；本叶不提供删除治理引用或迁移旧动作的公开操作，不能使仍被 S/D/Q 引用的 T/Vt/F 被删除。task 退出若遇到这些正式引用，应明确拒绝退出，不清理世界证据；不得把底层删除失败吞成成功。已绑定 Vt 专属概念禁止调用 `撤销未绑定专属存在概念()`；该旧入口内部先清理后删除，不能用最终强引用删除失败保护其内容。

`删除空场景()` 的治理引用非空判定必须加入当前 664—674 的写前空检查，在 `清理存在节点内容()` 之前返回非空拒绝，不能等基础节点强引用删除失败才发现。治理引用和用途核验严格绑定某个实际根；“已经装配任意治理读取器”不构成放开其它场景的理由。

### 5.1 世界入口的已知编码隔离

`新_场景类::是场景节点()` 已严格限制构造根，不改成全局任意场景判断。但 `业务/新_世界树类.cpp` 的查询存在／特征／状态／动态当前直接读全局 owner，必须同步防止用治理编码穿透现实世界入口。

场景 owner 新增公开只读 `bool 属于内部治理组织(稳定编码 节点) const noexcept`，只返回组织类别，不返回另一世界内容。它从正式根用途和组织引用确定：治理根及子场景、治理引用的 Vt／状态 F、场景状态列表中的 S、动态列表中的 D 均为治理组织材料；根自身实例 F 也按正式 holder 归属核验。概念节点永远不因此被屏蔽。节点不在治理组织正常返回 false；结构字段损坏或读取异常工程终止。

现实世界四个查询入口先调用该分类入口，命中则返回未提供该对象，不再解码返回治理内容；未命中保持既有非治理读取语义，不顺带收紧自然语言等旧接口。本叶已注册的 Vt 状态 F 及所有新生成 S/D 都必须命中。不能仅按动态主题 self 判归属，否则治理动作会因执行主体仍是现实 self 而漏出。

## 6. 内部世界公开 API 与一次结算顺序

构造依赖明确为共享值、FC、F、EC、DC、S、E、D owner 及现实场景只读视图；`DC` 只读依赖改为 const，因果构造中对应参数同步 const 化。本对象实现 `新治理参与者读取接口`、`新因果动作证据提供者` 和下述窄协作接口。task 不 include `业务/内部治理.世界.h`，不依赖该具体实现。

下列请求、结果和协作接口定义在 `领域/新_内部治理对象引用.h`；该头可包含 `新_状态类.h` 取得强时间类型，不包含动态或因果公共类型，避免循环依赖。因果交付在 world 内部消费，不放入 task 的公开变化结果。

具体 world 类以上述三个同签名 override 实现；另外公开 `反向因果查询结果 查询因果链(const 反向因果查询请求&) const noexcept`，此查询合同仅在业务世界头中包含因果反查头。task 新增 `bool 装配内部治理世界(新任务治理世界协作接口&) noexcept`，同指针重复为true、不同指针在工作前也拒绝；私有字段只持该中立接口指针。结算运行服务也只需该协作接口，不取得 task 状态写权。

三个世界组织函数的调用方只有 task 和结算运行服务。非法公开请求零写入；已通过正式调用链后发现结构破损终止。`完成任务状态变化` 非可选返回意味着已进入动作后必须完整完成或工程终止，不能把半结果交业务判断。

`标记任务已结算()` 增加一次装配的中立治理世界接口引用；原请求中的 `发生场景节点` 改名 `现实来源场景节点` 并迁移唯一生产调用者，不改变它原来的现实含义。原动态参数保留用于核验普通来源动作；新治理 C 由内部世界根取得，不能把现实 C 复义成治理 C。

执行顺序固定如下：

1. 外层结算服务先按现行逻辑验证普通服务值动作及真实服务值 S/D，仍在现实 C。
2. task 在唯一任务锁中核验来源任务已完成、普通来源动作、self 和现实 C；确保 Vt 专属概念。
3. 用请求的真实动作时间建立前 S，记录当前已完成值；它表示动作边界处读取的当前状态，不倒推更早时间。调用内部世界登记 Vt/self 引用，挂前 S，再建立唯一内部动作并挂治理 C。
4. 只有动作完整登记后，由原 task owner 写 F 为已结算；精确读回。调用现有 UTC 获取函数取得后状态时间，必须严格大于动作时间；时钟不成立属于工程停止，不用 `+1` 造时间。
5. task 建立后 S、更新 Vt 专属概念；内部世界挂后 S，调用原子 D 建立，以 `导致变化` 显式关联内部动作，然后挂 D。
6. 内部世界完成正式读回，按第 8 节实际交付一次因果发生。task 返回原状态及新增 `optional<新治理任务变化结果> 治理变化`；状态已经写入而后续故障不能回滚为未结算。

原子 D 与动作结果关系不是单个跨 owner 事务。每个正式节点完整发布，依次引用；不得声称整链原子。工程终止保留已发生动作和可确认事实。

## 7. 幂等、锁、失败和两处重复读回

原动作来源仍为已确认普通动作，沿用动态 owner 的唯一来源约束。首次前 S 以 task 锁中真实当前值建立；重复调用先查动作来源和 F，绝不先建新 S。

- 已结算且有完整内部动作/S/D：`读取任务状态变化()` 核验治理根归属、T/Vt/F、self、定义、原动作来源、前值已完成／后值已结算、时间、唯一关联后原样返回，结果为已是已结算。
- 已有动作但尚未结算，或已结算但缺 S/D／关联：进入已有部分完成工程诊断，保留现场并终止；不自动重做动作，不为旧数据补造前值和时间。
- 没有动作且当前不再已完成：保持原合法业务状态拒绝，零动作。

`服务值结算.本能运行服务.cpp` 的已结算重放分支不再要求内部动作位于现实 `c->动态节点组`，改用内部世界完整读回；普通动作及服务值 S/D 仍核验现实 c。`新_任务类::标记任务已结算()` 重放分支同样使用治理读回。两者必须同批迁移，不能只改新建路径。

新入口中的工程错误统一进入现有日志／弹窗／终止链，不生成业务 false、未知因果或资源不足伪空集。合法无规则、首例和无共同条件仍是因果业务结果。

## 8. 实际因果交付、范围隔离与查询

内部世界持有一个使用治理场景视图构造的完整因果服务视图，仍共享全局因果结构，不拥有第二 Q 仓。扩展完整构造的末尾可选参数 `const 新因果动作证据提供者*`、`const 新治理参与者读取接口*`；现实既有调用缺省为空，不退回简构造。内部世界显式传 `this`。

动作 provider 只接受治理 C 已组织的内部动作，返回现有动作定义加新字段 `optional<新任务虚拟存在引用> 作用对象任务虚拟存在`；与普通 `作用对象存在节点` 严格互斥。真实 self 仍是执行主体 E。状态／动态模式的现有主体编码可承载 Vt，但读取必须经治理参与者强类型投影确认；不得先尝试普通 E 读取、失败后猜测 Vt。

`新因果概念角色` 新增 `optional<新治理参与者种类> 治理类别`，普通角色为空；写读、角色对齐、概念共同抽象和反查均保留该类别。概念共享不等于普通 E 与 Vt 可互换。`参与C()` 在治理视图中从场景引用及 task 投影读取 Vt EC；现实 self 从明确执行主体引用取得 EC。

每个完成内部动作仅调用 `处理动作事实()` 一次：发生身份取内部动作节点；场景取治理根；结果为后 S；结果 D 为本次原子 D；动作证据为同一内部动作。状态／动态路径不得再以新身份重复提交。前置状态／动态范围是同一治理 C 内、上次同类结果 B 的时间（首次为 C 已有最早材料之前）至本次动作之前的全部合法材料，并加入本次前 S；结果后 S、结果 D 和本动作不得作为自身前提。相同结果 B 依现有精确参与者＋FT＋结果值分组，不新增跨 Vt 归纳。

窗口上界为动作时间，端点含本次前 S；下界为同类 B 前次结果时间，排除该前次结果之后尚未发生的未来材料。窗口计算读取正式场景 S/D，时间取 S 及动作／动态正式端点；不靠列表顺序、不跨根扫描。前次结果从本 C 已有已完成动作及其显式结果端点中查找，不建立第二持久观察账。同一动作重放只复用原完整发生，不增加次数。

因果全局发生缓存必须在读取／分组第一步按输入的实际 C 及所属根限定，不能仅靠“另一个因果对象”隔离。当前形成分组本来包含 C，保留并补核验根；首例待形成组的治理参与者不被普通视图解释。

新增 `新_因果类::查询当前场景树因果() const noexcept -> 新因果世界范围`，结果含完整具体编码组和概念编码组。先读原始具体 Q 的发生场景，只有本 scene 视图 `是场景节点(C)` 为真才展开参与者；无发生场景的旧 Q 不进入限定查询。概念 Q 只有全部正式来源具体 Q 均在该范围才进入结果。禁止先用普通 E／错误场景视图完整解码外根 Q 再过滤。

`新因果世界范围` 定义在 `新_因果公共类型.h`，字段为 `稳定编码 世界根节点; vector<稳定编码> 具体因果节点组, 概念因果节点组;`，完整比较采用默认 `operator==`。无规则是两空组的成功；缺少完整场景依赖或读回错误是工程停止。根来自该因果实例持有的 scene 视图，不接受调用者任意替换。

`因果反向查询服务::读取规则()` 及结束全集漂移检查改用上述范围枚举；原全局 owner 枚举保留供明确全局管理用途，不能用于世界查询。查询请求新增 `反向因果参与者::任务虚拟存在引用`，与普通实际存在／概念符号互斥；键枚举增加任务虚拟存在，键保存完整 T/Vt/F，节点键、环和 memo 不丢类别。

具体 ABI 固定如下，全部为末尾追加以便迁移既有聚合初始化；不重新解释旧字段：

输入参与者恰好一种：普通实际 E、概念符号、具名 T/Vt/F。虚拟键 `类别=任务虚拟存在`，只填完整虚拟引用，旧 `实际存在节点` 保持空；查询对象键、排序与等值比较显式包含三编码。具体规则中 Vt 角色由治理投影读出完整引用；概念规则只保留治理类别，未绑定时保持符号，不能猜任务。`键概念()` 的虚拟分支经 provider 读 EC，不调用普通 `读取E()`；结束漂移检查重读该强引用投影。

因果持久新增字段：动作目标任务、动作目标Vt、动作目标状态F（三者同时有或同时无，与普通作用对象字段互斥）；概念角色治理种类（缺省普通，存在时只允许1或2）。写读函数同步校验，来源动作的目标T/Vt/F必须完全一致。具体状态／动态的主题编码仍保持唯一正式主体身份，通过本场景治理引用确定类别；禁止将Vt编码填入动作的普通作用对象字段。`对齐来源()`、`同布局()` 及所有概念角色匹配纳入治理类别，不改变本叶不跨Vt统计的口径。

`因果反向查询服务` 构造增加末尾缺省 `const 新治理参与者读取接口* = nullptr`。内部世界显式传自身；现实视图缺省空。`参与概念()` 在治理规则中先使用场景限定的正式参与者投影，根场景本身仍走 scene 概念；只允许明确现实执行主体引用走 E 读取，不能把无投影当任意普通 E 回退。

内部世界的 `查询因果链()` 缺省共同场景为治理根；显式场景必须属于治理根，输入 Vt 及动作起点必须已在治理范围。现实查询同样只读现实 scene 视图中的规则，绝不自动混入治理规则。查询返回参考和未覆盖前提，不授权执行。首叶跨 Vt 不形成 Q 是已知语义边界，不能为了测试“有 Q”伪造第二发生。
