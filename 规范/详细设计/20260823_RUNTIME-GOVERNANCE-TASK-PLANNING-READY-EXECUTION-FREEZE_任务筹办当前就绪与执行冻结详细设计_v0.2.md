# 任务筹办当前就绪与执行冻结详细设计 v0.2

日期：2026-08-23

身份：`RUNTIME-GOVERNANCE-TASK-PLANNING-READY-EXECUTION-FREEZE`

状态：现行详细设计；解释 3100、3200、4010、4260 v0.4、5230 v0.9、5240、5250 v0.7、5300 v0.7、5310、6140、6150；不单独建立机器事实

## 1. 目标与完成边界

本设计接通 Stage C 结构化收束链：普通启动在授权安全材料缺失时形成合法等待；同时冻结可注入真实强类型授权安全来源后的成功选择、执行冻结和入队合同路径：

```text
下一筹办工作包
-> 方法查找结果
-> 方法当前就绪复判
-> 当前活动路径
-> 正式选择
-> 实例方法
-> 执行冻结
-> 任务管理线程两阶段队列
```

九种方法查找结论必须全部收束为`执行冻结候选`、`子目标承接`、`学习需求承接`、`方法补齐承接`或带等待对象、合法生产者和重新触发条件的`合法等待`，不得只保存裸枚举。本设计不执行方法，不把冻结入队说成动作发生，不进入任务结果共用 / 争用分配、任务完成、需求结算或价值回流。

## 2. 当前事实与能力裁决

创建基线：`main@c3eaebe7710d7b0e0aed299e2d92475d9d4199cc`。

执行期 DRIFT 复核基线：`main@1b15dab9489afd829a24d2f6990c972f4212a22e`，原计划 blob `016f33c9bcf08f7a8fe0c094772aa198f5f2ca42`。执行侧在同事务形成新冻结材料、新路径和新选择时发现：`L1所有者范围事实引用`允许关系端点引用`L1所有者范围写集本地键`，但`L1所有者范围原始值材料`只允许 I64、I64 组、U64 组或已发布稳定编码的独立材料引用；因此不能把冻结材料本地键或选择记录本地键构造成`稳定编码`后写入路径值。该问题属于 v0.1 物理事务表达漂移，不改变 5230 已冻结的选择语义。

## 3. 所有权与依赖方向

```text
BIZ-L3 内部治理编排
    -> DATA-L2 任务 / 需求 / 方法 / 状态 / 特征 / 场景公开服务
    -> 需求任务子目标承接公开服务
    -> 任务管理线程执行冻结两阶段队列

任务方法路径 facade
    -> L2任务结构服务公开读取 / 候选路径入口
    X 不拥有正式选择、当前投影或实例换代第二事务
```

`L2任务结构服务`是任务方法选择记录、执行绑定冻结材料、路径、当前选择投影和任务侧实例关联的唯一底层 owner。`L2任务结构.数据.h`及其服务只依赖 DATA-L2 公开数据事实，零引用`领域/内部治理`模块或无`L2`前缀的 BIZ DTO。内部治理 Stage C provider 单向依赖 task owner 并负责机械规范化；`L2任务方法路径结构服务`可以保留候选路径 facade，但删除`发布当前选中路径`的独立生产能力；不得建立第二存储。

### 4.3 唯一拓扑

```text
任务 -> 当前正式选择记录
选择记录 -> 方法
选择记录 -> 具体任务方法路径
选择记录 -> 来源需求组
选择记录 -> 稳定选择证据组
选择记录 -> 执行绑定冻结材料（恰一）
```

`任务 -> 当前选中路径`由同事务从`任务 -> 当前正式选择记录 -> 路径`派生。它没有独立公开写入口，不能单独证明选择；历史选择路径只从选择记录到路径关系恢复。

### 5.4 旧七编码投影的唯一映射与同写集表达

`L2完整路径材料`暂不作为权威冻结 DTO。Stage C 新路径的七项公开投影分成“写前已发布引用”和“发布后拓扑派生”两类；同写集内不得提前构造尚未发布的稳定编码：

| 旧字段 | 唯一来源 |
| --- | --- |
| `条件绑定` | 发布后从唯一`选择记录 -> 执行绑定冻结材料`关系目标取得冻结材料稳定身份；再从该材料的条件证据组解释 |
| `输入绑定` | 发布后从同一冻结材料关系目标取得；再从输入冻结组解释 |
| `参数绑定` | 发布后从同一冻结材料关系目标取得；再从参数冻结组解释 |
| `动作入口` | `L2方法动作入口事实.身份.值` |
| `预期结果` | `L2方法结果事实.身份.值` |
| `验证合同` | `L2目标状态合同身份.值` |
| `归因合同` | 发布后由唯一`选择记录 -> 具体任务方法路径`关系的源选择记录身份取得 |

禁止调用方自行构造上述七编码。组合写集只把动作入口、预期结果和验证合同三个写前已经发布的稳定身份保存到路径既有引用值；条件、输入、参数和归因四个兼容字段不建立值事实或属性槽，而由同事务已经必需的`选择记录 -> 路径`和`选择记录 -> 冻结材料`两条关系在正式读回时派生。关系端点可以合法使用同写集本地键，L1 发布后再取得稳定编码；任何本地键都不得进入`L1所有者范围原始值材料`、`稳定编码`包装、U64 数组或独立材料引用。

Stage C 正式读回以选择记录为根，在同一事实截止验证两条关系均恰一、端点均属于同一 task owner、路径与冻结材料均为本次写集新事实，然后机械形成四个兼容字段。按路径读取时必须反向读取`选择记录 -> 路径`：恰一选择记录时按相同规则派生；多条、缺少冻结关系、错端点、混 owner 或路径同时保存这四个 Stage C 值槽均为内部不一致。无选择记录的既有候选 / 迁移路径继续按旧七值只读兼容，不得补写选择、冻结材料或当前投影。

该表达不新增关系类型：复用 5230 已冻结的`选择记录 -> 具体任务方法路径`和`选择记录 -> 执行绑定冻结材料`。不得为绕过 L1 原始材料类型限制新增路径到冻结材料、路径到选择的重复关系，也不得拆成“先写身份、取稳定编码、再补路径”的第二事务。

组合发布入口内部形成路径，旧`新增任务方法路径`若保留，只用于未选候选或专项迁移，不得发布当前选择。

## 6. 原子事务、幂等、读回与恢复

### 6.1 一次 task owner 原子写

唯一幂等身份是`L2任务筹办规范化来源材料.原重筹办意图幂等键`。task owner 在第一笔写入前验证完整规范化来源材料、任务身份来源、方法生命周期、来源需求、冻结材料、旧当前选择 / 路径 / 实例和 G；一次 owner 事务同代完成：

```text
退出旧任务->当前选择、旧任务->当前路径、旧任务->当前实例
+ 退出旧路径 / 实例当前生命周期
+ 创建执行绑定冻结材料
+ 创建新路径
+ 创建正式选择记录与完整选择拓扑
+ 创建派生任务->当前路径
+ 创建新实例及任务侧当前实例关联
```

其中关系端点使用本事务本地键；路径只写筹办轮次、来源方法、方法内容版本、动作入口、预期结果、验证合同以及其对应当前槽。条件、输入、参数、归因四项不写值和槽，发布后按 §5.4 从同事务选择拓扑派生。提交结果的`新编码映射`只用于返回和正式读回，禁止据此开启第二笔补写事务。

新执行轮次固定为`旧执行轮次 + 1`；新筹办轮次必须等于工作包的新筹办轮次。历史记录、路径、实例和关系保留。

### 6.2 未知发布

`已提交`、`精确重复`均必须返回完整正式读回。资源失败或调用方未收到结果时，不换键、不重算请求；只以原幂等身份和原完整请求调用`按筹办工作包幂等身份读取正式选择`。首次账不存在才允许原请求重试；首次账存在但完整请求不同为幂等冲突。

### 6.3 正式读回后形成执行冻结

Stage C provider 必须在发布后的同一新事实截止调用 task owner 公开读取，联合验证选择记录、六类拓扑、冻结材料、路径、实例、派生当前路径、任务身份来源、方法生命周期和来源需求集合。只有全部一致才构造线程协议；发布返回值不能替代读回。

### 6.4 进程重启

重启后旧运行代次的执行冻结和队列预留不恢复为执行权。旧选择、路径、实例和冻结材料保持历史；恢复链失效旧当前执行权并形成新运行代次、新筹办触发和新筹办轮次。若旧外部动作是否停止无法证明，形成带动作核验生产者的合法等待，不重新入队。

## 7. 九结论分流

| 方法查找结论 | 唯一收束 |
| --- | --- |
| `方法能力缺失` | 正式学习门禁全部成立时形成`学习需求承接`值式草案；否则形成等待对象为学习门禁材料、生产者为具名学习门禁生产者的合法等待。不得直接写需求树或创建方法首。 |
| `当前无适用方法` | 合法等待；等待对象是适用方法变化，生产者是方法登记 / 当前事实变化入口，重新触发后从新工作包重查。 |
| `对象概念待形成` | 合法等待；生产者是概念支持关系正式入口。 |
| `所需方向不唯一` | 合法等待；生产者是目标比较 / 目标合同修订入口。 |
| `方法结构待补齐` | `方法补齐承接`；保存具体结构缺口、方法 / 内容 / 规格版本和合法补齐处理方。 |

## 8. 新执行冻结协议与线程接线

`海中鱼巣/线程/协议.任务执行请求.ixx`把协议版本升至 2，删除 legacy `节点句柄`任务 / 方法 / 动作材料，冻结请求改为：

```cpp
    std::uint64_t 任务序号 = 0;
    std::uint64_t 形成事实截止 = 0;
```

协议 v2 的字段映射唯一固定为：

```text

幂等键 = 来源工作包.原重筹办意图幂等键

```

v2 明确允许`请求编号`与`幂等键`相同，并删除 v1 对二者互异的检查；不得哈希、位运算、换键，也不得使用地址、线程号或墙钟。完整性要求任务、轮次、运行代次、选择、路径、方法、方法内容 / 生命周期、冻结材料、实例、来源需求和事实截止全部一致。

`任务管理线程`扩展`任务重筹办处理槽阶段`：

```text
待形成工作包 -> 待StageC处理 -> 非成功已收束
                         -> 待执行冻结队列准备
                         -> 队列容量等待
                         -> 执行冻结已确认
```

工作包形成后离锁调用 Stage C provider。provider 返回冻结请求时，槽先持有完整请求，再调用既有`准备强类型任务执行请求`；取得 move-only 候选后立即确认，确认失败则撤销。队列已满 / 容量暂不可用只进入`队列容量等待`，后续只以槽内完全相同冻结请求重试准备，不再调用方法查找、当前就绪或 task owner 发布。执行冻结已确认才是本 Stage C 成功终态；它仍不证明已取出或已执行。

provider 不拥有依赖、不可复制移动。`任务筹办授权安全材料来源`是只读抽象来源；普通应用配置必须显式提供生产实现或显式空来源。空来源只能返回材料缺失并形成合法等待，不能产生`不适用已证明`。provider 只读构造时注入的`任务筹办等待合同登记`，不得自行生成等待身份。

`普通应用配置`精确新增：

```cpp
任务筹办等待合同登记 等待合同登记;
任务筹办授权安全材料来源* 授权安全材料来源 = nullptr;
```

普通应用上下文值式只读拥有`等待合同登记`副本，并新增唯一 provider 和 const getter；授权安全来源非空时只保存非拥有引用，空时保存上下文自有的具名材料缺失来源。`任务结果生产运行包`构造改为接收该 getter 返回的 provider，并交给`任务管理线程`。`启动.应用程序.ixx`从同一普通应用上下文取得 provider；不得在运行包、线程或测试旁路再构造第二实例。

## 11. 验证矩阵

### 11.1 九结论与当前就绪

- 九种查找结论逐项命中唯一收束；每项必需 / 禁止载荷、等待对象、生产者和重新触发条件完整。
- 缺失条件逐项经需求统一承接；不直接调用需求结构写入口。
- 方法能力缺失只有全部学习门禁成立才形成学习草案；当前无适用方法不得进入学习。
- 当前方法内容 / 生命周期 / 来源成员 / 目标 / 治理状态同 G 互证；任一变化为漂移。
- 条件零 / 一 / 多项，已满足 / 未满足 / 场景不满足；证据保存完整当前状态和比较。
- 输入完整绑定、异角色待绑定；参数由输入规格机械形成。
- 限制为空可就绪；非空无解释器、证据不足、命中禁止项均不得就绪。
- 授权、安全已授权 / 权限为零 / 不适用有证据 / 材料缺失；无材料不得默认不适用。

### 11.2 选择事务与读回

- 同键同完整请求首次提交与精确重复；同键异义冲突；未知发布按首次账收敛。
- 旧当前选择 / 路径 / 实例退出与新结构建立同代原子；故障注入不得出现半结构。
- 六类选择拓扑的关系基数、端点、owner、任务 / 方法 / 轮次 / 内容版本守恒；冻结材料只走独立一对一拓扑，不重复进入稳定证据组。
- 来源需求组与列表项成员一致；稳定证据类别白名单、排序和去重。
- L2 任务数据 / 服务零引用内部治理模块和无`L2`前缀 BIZ DTO；规范化来源十三项与工作包逐项相等，task owner 按 G 独立互证。
- 限制解释器保留具名强类型；限制当前事实证据和授权安全来源证据保留`std::variant`强类型联合分支；持久 DTO 无裸`稳定编码`证据槽或类别 / 身份错配空间。
- 派生 task→path 与选择记录→path 相同；删除旧独立写入口，不能制造第二当前路径。
- 历史选择、路径、实例完整可读；同方法重复选择仍新建轮次 / 记录。
- 七编码投影逐项等于 §5.4 唯一来源；Stage C 写集的条件 / 输入 / 参数 / 归因四个值项与属性槽为零，写集中没有以本地键构造的`稳定编码`、U64 材料或独立材料引用；普通调用方没有构造入口。

### 11.3 线程、容量与恢复

- 工作包形成后 Stage C 实际被调用；非成功完整保槽。
- 等待登记项两 optional 键恰一非空；双空、双非空、未知键、重复键和缺项均装配拒绝。
- 冻结请求准备 / 确认 / 候选析构撤销 / 取出；同请求、同幂等键和同任务序号冲突。
- 队列满进入容量等待，重试期间 task owner 事实代次不变、首次账不增加、新选择不产生。
- 停止、排空和资源失败不丢槽、不产生半确认。
- 重启不恢复旧运行代次执行权；旧选择 / 实例历史保留，新轮次重新筹办。
- 任务工作线程仍不执行方法；冻结确认只证明队列可消费。

## 12. 完成声明边界

本设计施工完成只证明：合法`下一筹办工作包`在普通应用唯一生产路径中得到九结论收束；当前普通启动使用空授权安全来源时形成结构化合法等待；注入真实强类型授权安全来源且全部当前就绪、绑定、授权和安全前置满足时，合同路径可由 task owner 原子发布并正式读回唯一选择、路径、实例和冻结材料，随后将 L2 强类型执行冻结确认进任务管理线程两阶段队列；容量等待不会重复改写 task owner 事实。
