# 特征类型完整 R 集合版本到 FCr 归并提供者详细设计 v0.1

基线：`6c05c0c40694aaeb61971a4a16110478cbc9efe5`。状态：可执行。本设计是 `INSTANCE-FEATURE-IF-R-CONCEPT-FOUNDATION` 的唯一直接上游；只修正特征类型定义 owner 的 R→FCr 只读 ABI 与 I64 规则，不实现 IF/R、概念写入或普通应用装配。

## 裁决与所有权

4115 §4 要求规则一次接收该版本完整的 R项、成员 F 及其 FCv，并返回零个或多个规范化 FCr 定义及各自直接下位 `FCv*`。当前 `特征类数据服务::归并特征R概念` 只接收一个 `特征R规则项投影`；它不能核验或解释完整版本，故不得由 IF/R 消费计划调用。

特征类数据服务是 FT 规则唯一 owner。它只消费概念 owner 已按 `Gread/H` 同截止核验的 `F→FCv` 投影，核验 FT、R集合版本形状、材料、规则、预算和截止；不读取概念关系，不写 F、IF、R、FCv、FCr、上下位、汇聚回执或恢复游标。概念 owner 后续只消费成功输出建立/复用 FCr 及 `FCr→FCv*`。

## 冻结 DTO 与签名

声明在 `海中鱼巣/领域/数据服务.特征类.h`，定义在 `.cpp`；不得 include 存在类、概念树或普通应用头。

```cpp
struct 特征R集合版本规则投影 final {
    稳定编码 R集合;
    稳定编码 版本;
    std::vector<特征R规则项投影> R项;
};
struct 特征R概念归并请求 final {

    std::uint64_t Gread = 0, H = 0;
    特征类型身份 FT;
    特征R集合版本规则投影 R集合版本;
    特征R规则读取预算 预算;
};
struct 特征RI64概念归并项 final {
    特征规范I64域 域;
    std::vector<稳定编码> FCv下位;
};
struct 特征R概念归并结果 final {
    std::uint32_t 合同版本 = 2;
    特征R规则状态 状态 = 特征R规则状态::入口拒绝;
    std::uint64_t Gread = 0, H = 0;
    稳定编码 R集合{}, 版本{};
    std::vector<特征RI64概念归并项> 项;
};
特征R概念归并结果 归并特征R概念(const 特征R概念归并请求&) const noexcept;
```

成功结果回显 `Gread/H/R集合/版本`；非成功零 `项` 且不回显版本身份。`已归并零输出` 与 `已归并输出` 均成功，后者有非空项。`项` 是一个完整版本的全部 FCr 定义，按 `(域下界,域上界,FCv下位)` 严格升序且无重复；每个 `FCv下位` 非空、严格升序、无重复。它不携带 FCr 身份、写入结果、逐 R项部分结果、R到FCr关系或回执。

请求要求：版本 2、非零 `Gread/H`、`H<=Gread`、有效 FT/R集合/版本、非空 R项；R项按 R 编码严格升序且无重复；成员按 F 编码严格升序，且跨 R项全局无重复。每个成员必须是 H 时该 FT 未退出准确 F，FCv 为概念 owner 已核验的唯一直接投影。预算对完整版本总 R项、成员、材料元素和实际规则读取量核验；候选值预算必须为零。DTO/预算非法为入口拒绝；特征类可核验的内容冲突为内部不一致。

## I64 语义、错误与调用方

入口在 mutex 内核验截止和全版本形状。对启用域形成的 I64 FT，逐 R项核验单点材料、逐成员核验准确 I64 与材料相等、按每项最小 F 调用既有 `形成I64特征域`；最终对全版本候选定义按域及完整 FCv 集合规范化、排序、去重。任一项失败、跨项重复 F、材料/成员/域冲突或截止漂移均使整个调用零输出；不允许部分结果。I64 不放宽为误差、相邻或重叠归并。

无 I64 能力、无域形成或无归并规则时，仍先核验完整版本 DTO，再以未读取预算全零返回 `已归并零输出`。本计划是只读：漂移、资源失败、内部不一致分别结构化返回，零输出；不得自动重试。唯一预期消费者是后继 IF/R 计划，且仅在存在 owner 成功发布实际变化的完整 R集合版本后，以该版本完整读回投影至多同步调用一次。
