# DEMAND-SINGLE-TARGET-STRUCTURE-PUBLISH-CONSUME 单目标需求结构公开发布消费详细设计 v0.1

日期：2026-08-16
版本：v0.1

## 1. 目标、范围与完成边界

以 BIZ-L4-004-02-01-05 v0.2 替代旧 v0.1 `需求数据操作::发布单目标需求事务`，并同步把父 BIZ-L3-004-02-01 更新为 v0.3。新05只负责：

```text
接收上游已完成业务裁决的完整建立/补充候选
-> 转换为 DATA-EXT-12 中性强类型结构请求
-> 恰一次调用唯一 L2需求结构服务公开写入口
-> 互证已发布 / 精确重复的需求身份、首次请求见证和写后G1
-> 把结果交给06正式读回
```

本叶不复制 DATA CRUD，不建立 BIZ 数据操作层、事务参与者、L1写端口、owner、候选确认、撤销、幂等账或发布见证。5150拒绝回执仍由父 `提交或复用单目标需求`入口形成；05零治理回执写入。

本设计发布只冻结消费合同和所需基础数据公开接口语义。DATA-EXT-12最终服务、DTO和ABI尚未发布，01—04、06也未全部实现，因此计划登记 `待激活`。本设计不证明需求写入、读回、任务化或系统闭环。

## 2. 正式依据与当前事实

- 0050：DATA-L2只校验强类型结构、引用、生命周期、期望代次、幂等和事务；业务解释位于DATA之外。一次写集由DATA内部原子发布，发布未知只能用原请求重放。
- 3100、5100：一个需求只有一个目标宿主、目标特征和目标状态合同；来源和路径不改变目标语义；正式需求只能经需求领域统一提交入口。
- 5110：同父同目标复用或合并；来源差异不造第二需求；新增父路径必须防环且角色合法。
- 5150：业务入树拒绝由需求提交入口形成正式治理回执；日志和下层DATA状态不能代替。
- BIZ-L4-004-02-01-01 v0.3、02 v0.3、03 v0.2 已冻结来源准入、同父同目标当前读取和来源/路径补充候选；04仍待重基线。
- `计划/数据服务最终需求清单.md` 的 DATA-EXT-12 只在总表层面要求“新增或复用单目标需求”与完整读回，尚未冻结本叶所需建立/补充统一请求、首次请求见证和发布未知形状。
- 当前正式源码不存在 `海中鱼巣/领域/服务.需求.ixx`、L2需求结构服务或本叶DTO；旧 v0.1 的 `数据操作.需求.ixx`方向未实现且已经冻结。

具名漂移：`DRIFT-BIZ-L4-004-02-01-05-PRIVATE-DATA-OPERATION-OWNERSHIP`。旧图让BIZ取得许可、准备参与者、撤销和最后发布，违反现行 DATA-L1—L3所有权。

## 3. 上游候选与模式不变量

公开BIZ请求只允许两种模式：

| 模式 | 既有需求 | 来源变化 | 路径变化 | 04见证 |
| --- | --- | --- | --- | --- |
| 建立新需求 | 空 | 完整首次来源组 | 必须恰一非根路径 | 必须完整 |
| 补充既有需求 | 非零 | 至少一项来源追加/授权换代或路径追加 | 可空 | 只有新增路径时必须完整 |

普通运行期根请求已在01固定拒绝，因此本叶不接受无父新建。03返回`无需补充`时父函数直接返回已复用，不调用05。补充模式若来源与路径变化都空属于父状态机损坏；新建模式缺路径或04见证、补充新增路径缺04见证、仅来源补充却携带异义04见证均为内部不一致，零DATA调用。

候选必须携带并互证：

- 需求主体、提出主体、目标宿主、可空目标场景、目标特征定义、目标状态合同及目标语义键；
- 来源种类/对象、来源事实、授权事实或内在规则、发生时间、规则版本和生命周期；
- 可空既有需求身份；有路径时的父需求、路径组、路径角色、顺序、当前性/活动版本和04复核见证；
- 同一非零G0、事实/需求/路径规则版本、单一后继发布幂等身份和数量预算。

父需求、来源适用父需求、路径父端点及04见证必须相等。目标权威引用与目标语义键分账；路径和来源不进入目标键。

## 4. BIZ 值式合同与物理位置

新增值式合同头：

```text
海中鱼巣/领域/需求结构发布消费.数据.h
```

扩展唯一需求业务服务：

```text
海中鱼巣/领域/服务.需求.ixx
```

预冻结BIZ合同：

```cpp
inline constexpr std::uint32_t 单目标需求结构发布合同版本 = 1;
inline constexpr std::uint32_t 单目标需求结构发布规则版本 = 1;

enum class 单目标需求结构发布模式 : std::uint8_t {
    建立新需求 = 1,
    补充既有需求 = 2
};

struct 单目标需求结构发布请求 final {
    std::uint32_t 合同版本 = 单目标需求结构发布合同版本;
    std::uint32_t 规则版本 = 单目标需求结构发布规则版本;
    单目标需求结构发布模式 模式;
    单目标需求结构发布候选 候选;
    std::optional<需求父路径复核见证> 路径复核见证; // 待04最终ABI机械匹配
    std::uint64_t 事实截止代次 = 0;
    L2结构幂等身份 发布幂等身份;
    std::size_t 来源结构数量预算 = 0;
    std::size_t 路径结构数量预算 = 0;
};

enum class 单目标需求结构发布状态 : std::uint8_t {
    已发布 = 1,
    精确重复 = 2,
    请求拒绝 = 3,
    当前性漂移 = 4,
    幂等冲突 = 5,
    提供者拒绝 = 6,
    数量预算不足 = 7,
    资源失败 = 8,
    发布结果未知 = 9,
    未实现 = 10,
    内部不一致 = 11
};

struct 单目标需求结构发布材料 final {
    L2需求身份 需求;
    L2结构幂等身份 首次幂等身份;
    std::uint64_t 首次期望事实代次 = 0;
    std::uint64_t 写后事实代次 = 0;
    单目标需求结构发布模式 首次模式;
    单目标需求结构发布请求语义回显 首次请求见证;
};

struct 单目标需求结构发布结果 final {
    单目标需求结构发布状态 状态 =
        单目标需求结构发布状态::请求拒绝;
    std::uint32_t 合同版本 = 单目标需求结构发布合同版本;
    单目标需求结构发布请求 请求回显;
    std::optional<单目标需求结构发布材料> 发布材料;
};

单目标需求结构发布结果 需求业务服务::发布单目标需求结构(
    const 单目标需求结构发布请求& 请求) const noexcept;
```

上游 `单目标需求结构发布候选`、04见证和 DATA DTO 的精确字段顺序待对应正式代码结果机械匹配；不得复制同义类型。BIZ结果自身保留完整原请求，发布未知时由父级持有并决定何时用原请求重放。

只有`已发布`和`精确重复`携带发布材料；两者需求身份、首次幂等身份、首次G0和首次请求语义必须相同，写后G1非零。其它状态optional为空。精确重复返回原G1，不推进事实代次。

## 5. 基础数据公开接口最终需求

本节只冻结BIZ消费所需的DATA公开语义，不冻结DATA内部写集、事务参与者、物理文件或精确C++字段顺序。

### 5.1 取得路径

普通应用必须从同一L1运行包装配唯一 `L2需求结构服务`，并让同一 `需求业务服务`持有其 `const`服务引用。不得直达L1、owner、仓库或建立第二需求服务；DATA-L3不需要为无结构依赖的调用增加转发壳。

### 5.2 唯一写操作

DATA-EXT-12必须提供一个具名公开操作，语义名为：

```text
发布单目标需求结构(完整强类型请求) -> 结构化结果
```

请求至少承载：

| 分组 | 必需语义 |
| --- | --- |
| 请求头 | 建立/补充模式、非零G0、单一幂等身份、结构/规则版本、来源与路径数量预算 |
| 需求目标 | 可空既有需求、需求主体、提出主体、目标宿主、可空场景、目标特征定义、独立目标状态合同、生命周期 |
| 来源结构 | 稳定来源种类/对象、事实引用、授权引用或具名内在规则、适用父需求、发生时间、版本、生命周期 |
| 路径结构 | 可空父需求路径；父子端点、路径组、角色、顺序、当前性/活动版本和生命周期 |
| 约束 | 新建必须完整目标/来源/路径；补充只新增来源当前版本和/或路径；同父同目标唯一；全部引用在G0下互证 |

请求不得携带“来源已准入”“路径允许”“目标合理”等BIZ布尔或BIZ见证对象。BIZ只把裁决结果转换成DATA拥有的强类型节点、关系、值、生命周期和版本材料。

### 5.3 结果与首次见证

DATA结果至少分账：已发布、精确重复、请求拒绝、当前性漂移、幂等冲突、许可拒绝、数量预算不足、资源失败、发布结果未知、未实现、内部不一致。

已发布与精确重复必须提供：

```text
非零L2需求身份
+ 原首次幂等身份
+ 原首次期望事实代次G0
+ 原首次完整规范化请求见证
+ 原写后事实代次G1
```

同幂等身份同完整语义返回原结果，零写、零代次推进；同身份异义返回幂等冲突。DATA不得只返回摘要或进程内缓存定位代替完整首次请求见证。发布结果未知不得返回可消费成功材料，后继只允许原完整请求重放。

### 5.4 原子与并发

DATA内部必须在一个事实事务中原子发布需求身份/目标/来源/授权/父路径/生命周期及首次请求见证。新建与补充都不得出现半结构。G0漂移或并发唯一性竞争不得静默改用最新事实、换幂等身份或由DATA裁决业务合并；返回漂移后由父BIZ重新读取和重组。

### 5.5 后继读回

05成功材料只供06以需求身份和G1正式读取完整需求。DATA写结果不能代替06读回；06所需完整读操作另由后继设计冻结。

## 6. 固定执行顺序与状态映射

```text
校验BIZ合同、模式、候选、G0、版本、预算和幂等身份
-> 校验新建/补充与来源/路径变化、04见证的组合
-> 形成完整DATA强类型请求候选
-> 候选完整后一次无抛出交换
-> 恰一次调用唯一DATA发布操作
-> 精确映射漂移、冲突、许可、预算、资源、未知和未实现
-> 已发布/精确重复逐字段互证首次请求、需求身份和G1
-> 返回05值式结果
```

本函数零重试、零截止重选、零幂等探测预读、零历史拼装、零缓存、零日志裁决。`bad_alloc`/`length_error`映射资源失败，其它异常映射内部不一致。

对于一个已由上游BIZ证明完整且在G0当前的请求，DATA返回请求拒绝、引用缺失、父环、目标复义或坏路径形状表示上游/Data合同矛盾，05映射内部不一致；不能包装成普通来源/路径拒绝。当前事实已变化只能返回当前性漂移。

## 7. 5150、发布未知与读回边界

01、04和05都不写拒绝回执。父 `提交或复用单目标需求`按业务拒绝类别构造一次5150回执；内部不一致进入开发诊断，不生成普通拒绝回执。

发布未知时05返回原完整请求回显和`发布结果未知`，但零发布材料。父入口不得调用06、不得换G0/幂等身份、不得构造第二需求；后继显式重放仍必须使用同一完整请求。DATA最终收敛为已发布/精确重复后才取得原G1并进入06。

## 8. 验证矩阵

1. 零G0/幂等身份、坏版本、零预算、空目标/来源、非法模式均零DATA调用请求拒绝；
2. 新建缺既有身份且完整，补充必须有既有身份；新建缺路径/04见证、补充零变化、新增路径缺04见证均内部不一致且零调用；
3. BIZ见证正确转换为中性需求/来源/路径结构，DATA请求中零业务布尔、零BIZ见证、零内部写集；
4. DATA公开入口每次恰一调用，完整G0和幂等身份原样传递；
5. 已发布/精确重复完整回显需求身份、首次请求、首次G0、首次幂等身份和G1；重复返回原G1；坏成功形状内部不一致；
6. 漂移、冲突、许可、预算、资源、未知、未实现逐项唯一映射，非成功optional空；
7. 发布未知零自动重试、零换身份/截止，原完整请求保持可重放；
8. 05零5150写入，父图业务拒绝只形成一次回执；成功/重复都固定进入06；
9. 源码零L1/owner/仓库/事务/候选/撤销/内部幂等账/SQL/缓存；
10. 根工程Debug/Release、生产外专项双配置、strict、diff、UTF-8、工程唯一登记和临时专项清理后复验。

专项只能替代 DATA provider 验证BIZ纯逻辑和状态映射；真实DATA成功、并发和发布未知收敛必须等最终公开接口后由合法消费者验证，未运行前保持 `NOT_RUN`。
