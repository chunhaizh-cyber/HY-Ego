# GOVERNANCE-SECONDARY-CONCEPTS 治理二次特征应用详细设计

版本：v0.1；日期：2026-10-09。代码核对基线：`main@7d64c861e6ee0a74b2130cfb1cfdcd48ee520a46`。

## 1. 本叶目标及裁决来源

用户要求核对“交互智能体”今天的冲突检测共识并补齐已达成一致的代码。本窗口已明确：二次特征具有具名比较规则、准确结果和值域子概念；父、子概念的名称词条同时初始化；比较不按词面判断；工程错误、治理裁决与语义比较分离。

本叶只完成**时间窗口余量**的全链：真实纯计算输出 → 具名准确材料及来源 → 初始化类型和负/零/正结果子概念与名称 → 只读语义适配 → 普通应用装配及可调用入口。不是把一组枚举改成概念，也不宣称任务管理线程已采用这些裁决。

依据：0050 v3.33、4151 v0.7、7170 v1.2、7180 v1.2及用户本窗口结果值域子节点/初始化裁决。无历史代次、预算、持久二次实例或第二概念所有者。旧规范与新版模型冲突处按0050及规范目录替代，不恢复旧RC本体根或公共历史合同。

不纳入：新需求时间事实字段及其owner提供者、manager生产采用、损失度量、成本折算、任意值域交集、方法保护组合自动发现、自由文本理解。上述逻辑没有本叶可直接读取的正式来源，禁止伪造默认时间、默认权重或虚拟特征实例填充。

## 2. 已核对事实及复用裁决

- `任务时序可达性.领域服务.h/.cpp`是零写纯计算。当前仅保留成功路线余量、保证成功即早返、最短耗时只校验未求值；预计失败被称为不可同时满足；`bad_alloc`误映为材料不足。
- `概念_二次特征类`可建立根、结果子域、读回完整算法输入定义、只读按准确值找最具体子概念。扩展具名算法及输入种类，不调用会隐式建概念的`新_二次特征类::计算()`。
- `概念_名称关系类`与`新_词类`提供概念—词条关系及反查，直接组合复用；词条不构成概念身份。
- `装配.普通应用.cpp`持有世界事实引用及中文语言节点。初始化业务放在普通应用，禁止放入`新_世界树类`，不让底层场景/概念类反向依赖治理。
- 知识库当前未覆盖本基线；以上结论来自现行头源和调用点，没有把用途卡或旧代码能力当事实。

## 3. 纯计算扩展合同

保持原请求结构不变，所有非负时刻在同一调用方明确提供的纳秒时间基准下；投影身份仅标注来源，不证明数据已从需求/方法owner核验。函数不能凭稳定编码存在就宣称投影为当前事实。

在`任务时序可达性.领域服务.h`增加：

```cpp
enum class 时序耗时依据 : std::uint8_t { 最短 = 1, 预计, 保证最大 };
struct 时序时间比较材料 final {
    时序耗时依据 依据 = 时序耗时依据::保证最大;
    std::vector<时序转换选择> 路线;
    bool 可表示 = false;
    std::optional<std::int64_t> 第一需求满足时刻;
    std::optional<std::int64_t> 第二需求满足时刻;
    std::optional<std::int64_t> 第一需求窗口余量纳秒;
    std::optional<std::int64_t> 第二需求窗口余量纳秒;
    std::optional<std::int64_t> 最小窗口余量纳秒;
};
```

`时序路线评估`新增`最短比较`、`预计比较`、`保证比较`三个上述字段。旧保证/预计路线和采用后汇总字段保留以免破坏旧调用；无采用路线时旧汇总保持空，不从最短材料猜采用。

每条腿独立选择最短、预计、保证候选，前置门不变。排序键分别是 `(最短,预计,保证,方法编码)`、现有预计键、现有保证键；同地零耗时且无方法引用。现有保证/预计排序行为不变。

三个依据分别完整计算：

```text
到达先 = 当前时刻 + 第一腿耗时
满足先 = max(到达先,先需求最早时刻)
离开先 = 满足先 + 先需求最小保持时间
到达后 = 离开先 + 第二腿耗时
满足后 = max(到达后,后需求最早时刻)
余量D = D最晚允许时刻 − D满足时刻
最小余量 = min(余量第一,余量第二)
```

合法非负I64时刻相减落在`[-INT64_MAX,INT64_MAX]`，负余量照实保留，不饱和。所有加法溢出明确`计算不可表示`；不存在用INT64_MAX冒充可表示时刻的回退。各组有完整数值才设`可表示=true`；单组失败清空该组全部可消费数值。

路线判定顺序：保证满足→可保证；否则预计满足→仅预计；否则最短不满足→不可同时满足；否则新增`未能保证同时满足`。新增顶层`可达性未确定`，当尚有最短可达但预计不满足的路线时不按假定冲突选择优先需求、不输出等待重新确认节点。既有硬门、材料和计算失败优先级不降低；已存在保证可行路线时允许按现有规则选择它，但语义适配要求所有需输出材料完整才成功。

原路线状态`不可同时满足`现在仅在已检查最短路线仍失败时成立，不将“无保证”误称“不可能”。纯计算只能说明请求中给出的有限方法候选，不证明世界中不存在其它方法。

两级枚举各追加`资源失败`和`结构不一致`；`bad_alloc`及分配失败返回资源失败，未知异常返回结构不一致，不生成业务概念。保持旧枚举数值，不重新编号。

## 4. 唯一具名概念定义

扩展`二次特征算法::治理时间窗口余量 = 7`，以及`二次特征输入来源种类::治理时间合同投影 = 7`。这不是强时间事实、状态时间或准确特征实例；只准入本设计业务适配入口。概念类的规范化、合法算法集合、完整读回和默认定义推导均须同步支持。

`新_二次特征类::计算()`及其已有请求入口不支持该专属输入，遇到算法7明确返回算法不适用且零写入；不得因现有fallback先建立概念或伪造强时间。允许在该`.cpp`增加精确拒绝，不改变其它算法。

定义冻结：顺序0=左输入=本次路线计算得到的需求满足时刻；顺序1=右输入=同一需求时间约束的最晚允许时刻；两项来源均为治理时间合同投影；无具体需求编码、方法编码、场景编码和实例特征编码进入概念定义。算法为`右−左`，输出I64标量，纳秒单位，I64数值比较，不自动聚合，总域`[INT64_MIN,INT64_MAX]`，参照概念为空。

`INT64_MIN`属于定义的数学域边界，不是当前时间输入允许产生的数值；不可表示、缺源、结构错误不通过它表示。

初始化唯一根及三个直接结果子节点：

| 节点名称/唯一初始词条 | 值域 | 关系域 |
| --- | --- | --- |
| 时间窗口余量 | 全I64 | 任意 |
| 时间不足 | `[INT64_MIN,-1]` | 小于 |
| 恰好足够 | `[0,0]` | 等于 |
| 时间有余量 | `[1,INT64_MAX]` | 大于 |

不额外造“最短时间不足”“保证时间不足”三个同数学定义的类型；依据保留在本次材料中。词条不能自动扩写同义词，既有同词面节点复用。准确子域可进一步细分，但本叶返回的命中必须保留所属根并能向上核验其落在三基础域之一。

查重必须核对完整算法、输入来源、角色、输出域、单位，不得与输出域相同的强时间间隔根复用；测试两类根同场存在。当前特征概念服务无上位参数时建立独立类型根，语义等价先由二次概念服务判断，禁止因输出定义相同而覆盖原根派生字段。

## 5. 治理应用服务与公开接口

新建`海中鱼巣/业务/治理二次特征.应用服务.h/.cpp`。一般业务服务配对文件；上层依赖领域纯计算和概念/语言公开服务，后者不反向包含本文件。所有公开实体仅在该头文件声明。

```cpp
struct 治理时间概念集合 final {
    稳定编码 时间窗口余量;
    稳定编码 时间不足;
    稳定编码 恰好足够;
    稳定编码 时间有余量;
};
enum class 治理二次特征状态 : std::uint8_t {
    已完成 = 1, 尚未初始化, 输入不合法, 材料不足,
    计算不可表示, 结构不一致, 资源失败
};
struct 治理时间概念初始化结果 final {
    治理二次特征状态 状态 = 治理二次特征状态::尚未初始化;
    std::optional<治理时间概念集合> 概念;
};
struct 治理时间余量解释 final {
    需求时序顺序 顺序;
    时序耗时依据 依据;
    稳定编码 需求节点;
    稳定编码 二次特征类型根;
    稳定编码 结果值域概念;
    std::int64_t 满足时刻纳秒;
    std::int64_t 最晚允许时刻纳秒;
    std::int64_t 准确余量纳秒;
};
struct 治理时序解释结果 final {
    治理二次特征状态 状态 = 治理二次特征状态::尚未初始化;
    std::optional<需求时序可达性裁决请求> 来源请求;
    std::optional<需求时序可达性裁决结果> 裁决;
    std::vector<治理时间余量解释> 时间比较组;
};
class 治理二次特征应用服务 final {
public:
    治理二次特征应用服务(概念_二次特征类&, 新_词类&,
        概念_名称关系类&) noexcept;
    治理时间概念初始化结果 初始化(稳定编码 中文语言节点) noexcept;
    治理时序解释结果 裁决时序(
        const 需求时序可达性裁决请求&) const noexcept;
};
```

服务保存非拥有引用；依赖活得更久；概念集合是已完成初始化的运行期定位材料，不是第二事实owner。服务私有互斥保证初始化/读取集合不竞争，不在锁内回调上层。不新增全局概念树、不修改世界树。

`初始化`依次建立或复用根→子域→四词条→四名称关系→全部读回。每个既有服务调用独立发布其完整节点/关系；本函数不宣称跨调用原子事务。只有全部成功且定义/域/名称关系两端互证完整才交付集合并允许语义入口；失败无完整集合，已成功的合法概念/词条保留供精确重试，不反向删除共享身份。重试必须重新读回，不能只相信缓存。发现异义不修复覆盖，返回结构不一致。

`裁决时序`不得调用任何建立/确保/名称绑定接口。先核验当前根、子域算法/单位/来源定义，再调用纯计算；有合法腿的两种顺序，分别为三个依据的两个需求输出解释。缺失腿/前置否决允许在裁决中作为无时间材料的路线结果保留；计算不可表示、结构/资源错误导致整次无成功解释载荷。准确来源请求完整复制到返回中，里面保留需求约束、所有方法候选、时间基准和位置；路线保留实际采用方法。局部值本次即弃，不具有稳定身份。

匹配调用`查找结果对应最具体概念`，随后读回命中概念验证同一根、算法及准确值落域。可接受合法更细子域，但不得拿另一个根的同符号概念替代。无匹配/错误根/异常域不是“时间不足”，是结构不一致。名称不参加判断，需显示时按结果概念查名称关系再查词条。

本叶不按概念读回失败伪造最终可执行状态。调用结果仅表示**调用方提供的时间合同投影**的语义计算，不自动产生现实判断、任务状态改变、授权、结算或动作。

## 6. 普通应用生产装配

`装配.普通应用.h/.cpp`加入该服务依赖，`普通应用上下文`在世界事实引用之后、线程之前持有唯一服务，构造传入现有二次概念、词、名称关系服务。`完成装配()`在确认概念初始化成功之后、自我治理基础初始化之前调用；中文语言节点来自第一权限人初始化。线程启动前必须成功。装配结果追加可选`治理时间概念集合`，装配状态追加`治理二次特征初始化失败`，`普通应用装配结果::成功()`须同时核验集合四身份有效且互异，不能只看旧已装配状态。

普通应用新增非拥有服务的受控转发入口：

```cpp
治理时序解释结果 计算普通应用时序语义(
    const 需求时序可达性裁决请求& 请求) noexcept;
```

该函数在现有上下文生命周期锁内确认上下文与装配完成后调用服务；无上下文返回尚未初始化。禁止暴露可写服务指针、伪造默认请求、自动发送任务消息。本入口是实际装配到概念服务的生产可调用提供者；没有manager调用者，必须如实报告。

## 7. 验证矩阵与完成边界

1. 原裁决回归；保证/预计/最短分别成功、失败，保证成功仍有完整其它依据材料。
2. 负/零/正余量，两需求两个顺序来源准确；等待最早时刻、先需求保持时间正确。
3. 保证失败预计成功→风险；预计失败最短成功→未确定；最短也失败→该有限候选不可能；未确定不得输出假优先需求。
4. 非法请求、缺合同、前置材料不足、安全否决、保护约束拒绝、溢出明确区分；分配异常不等于材料不足。
5. 概念根+三个子域+四词条+四关系读回；重复初始化身份不变；与强时间差同输出定义仍不同根；运行前后基础节点数量不增加。
6. 子域被破坏、根算法/单位错配时只读失败且不自动修复；计算成功而名字多义不改变裁决。
7. 普通应用装配返回集合，真实公开转发调用成功，不启动manager来证明不存在的时间来源。
8. 根工程Debug/Release x64隔离Rebuild；专项黑盒运行；XML/四配置UTF-8静态检查；`git diff --check`。

验证目录唯一使用`D:/TEMP/海中鱼巣/GOVERNANCE-SECONDARY-CONCEPTS/<本轮唯一标识>`，不共享其它构建产物。生产无自检正文/故障开关。验证记录必须区分文档、构建、专项运行、普通装配、manager未接入、持久恢复未验证。

本设计不修改正式规范，也不补写其它窗口尚未确认的业务语义；创建侧只证明这一个叶的合同完整。
