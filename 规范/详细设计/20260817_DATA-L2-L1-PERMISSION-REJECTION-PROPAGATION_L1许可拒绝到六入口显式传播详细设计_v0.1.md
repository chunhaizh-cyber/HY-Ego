## 1. 目标与完成边界

本叶修复一条已由当前代码确认的 DATA 状态传播链：

```text
L1仓库 try_to_lock 锁竞争
-> L1读取状态::许可拒绝 + 事实截止代次0
-> L1中性读取状态::许可拒绝 + 事实代次0
-> L2六个公开当前读取入口返回 L2结构状态::许可拒绝
-> 事实截止代次0 + 变更事实代次空 + 全部业务载荷空
```

本叶不等待、不重试、不把锁竞争猜成事实代次漂移，不建立无锁代次镜像或预留代次，不改变锁、owner、事务、写入、历史读取、BIZ 分类或成功载荷语义。

完成最多证明：这一具名 L1 非阻塞读取拒绝可以通过公开强类型 DTO 守恒到六个 DATA-L2 当前读取结果，不再被误报为资源失败或内部不一致。不证明 WORLD-SELF 已恢复、BIZ 快照已成立、普通应用已消费、DATA-EXT-01—14 已全部完成或跨进程恢复成立。

## 3. S0 兼容性裁决

不能只修改最初的四个核心文件。`L1中性读取状态` 是公共枚举；追加新值后，不只场景和存在服务可以从 `读取中性当前事实代次` 观察到它。不受理的旧 switch 或直接判定会把新值落入内部不一致，从而把一个修复变成其它 DATA 服务的新回归。

因此本叶采用两层白名单：

1. 主目标四文件：追加 L1 中性许可拒绝，修正 L1 映射，并让场景 / 存在六入口显式传播。
2. 公共枚举兼容八文件：只在现有事实代次探测状态映射或直接失败收口中增加许可拒绝分支；不改这些服务的业务结构、公开函数、成功形状、owner 或验证结论。

这一兼容闭包属于同一个公共状态的必要机械传播，不是扩展到其它 DATA 业务语义。六入口并发矩阵仍是本叶唯一动态功能验收面；其它八文件只做编译、枚举穷尽和静态不退化复核。

## 4. 冻结的 L1 DTO 与函数合同

### 4.1 公共枚举

`L1中性读取状态` 只允许尾追加：

```cpp
enum class L1中性读取状态 : std::uint8_t {
    成功 = 1, 入口拒绝 = 2, 未找到 = 3, 已退出 = 4,
    属性未设置 = 5, 资源失败 = 6, 内部不一致 = 7,
    许可拒绝 = 8
};
```

1—7 的名称、数值和原语义不变；`L1中性CRUD合同版本` 不递增，请求 / 结果布局不变。本叶不给其它中性读取强行制造许可拒绝；只保留底层已经明确产生的状态。

### 4.2 现有公开函数

签名保持：

```cpp
L1中性事实代次读取结果
L1事实基座服务::读取中性当前事实代次(
    const L1中性事实代次读取请求& 请求) const;
```

函数顺序保持：先验证合同版本，再恰一次调用仓库 `尝试读取当前事实代次`，最后纯值映射结果。底层许可拒绝必须生成：

```text
状态 = L1中性读取状态::许可拒绝
合同版本 = L1中性CRUD合同版本
事实代次 = 0
```

不可读取、猜测或返回 writer 尚未提交的预留代次。只有真正取得锁并读到已发布事实代次时，才可以返回非零截止或事实代次漂移。

## 5. 冻结的 L2 映射与六入口合同

两个现有私有纯值函数只追加一个分支：

```cpp
case L1中性读取状态::许可拒绝:
    return L2结构状态::许可拒绝;
```

| owner / 文件 | 函数 | 责任 |
| --- | --- | --- |
| L2 场景 owner / `服务.L2场景结构.ixx` | `L2结构状态 映射事实代次探测失败(L1中性读取状态 状态) noexcept` | 场景当前代次预检和前后代次失败的统一映射 |
| L2 存在 owner / `服务.L2存在结构.ixx` | `L2结构状态 映射存在事实代次探测失败(L1中性读取状态 状态) noexcept` | 存在当前代次预检和前后代次失败的统一映射 |

六个既有公开签名保持不变：

| # | 公开函数 | 许可拒绝结果必须满足 |
| ---: | --- | --- |
| 1 | `L2场景树读取结果 L2场景结构服务::读取场景树(const L2场景树读取请求& 请求) const` | `树 == std::nullopt` |
| 2 | `L2存在单例角色读取结果 L2存在结构服务::读取存在单例角色(const L2存在单例角色读取请求& 请求) const` | `角色关系 == std::nullopt && 存在身份来源 == std::nullopt` |

```text

状态 == L2结构状态::许可拒绝
事实截止代次 == 0
变更事实代次 == std::nullopt
```

状态优先于 optional、空组、项目数、owner、端点和生命周期解释。一旦代次探测返回许可拒绝，入口必须经现有空载荷失败形成函数直接收口，不得继续解释部分材料。

## 6. 许可拒绝、漂移和资源失败分账

| 底层事实 | L1 中性结果 | L2 结果 | 截止 | 载荷 |
| --- | --- | --- | ---: | --- |
| `try_to_lock` 未取得共享锁 | 许可拒绝 | 许可拒绝 | 0 | 空 |
| 取得锁后正式读到 `Gobs != G0` | 成功 + `Gobs` 或具名守卫漂移 | 事实代次漂移 | `Gobs != 0` | 空 |
| 内存分配 / 长度资源耗尽 | 资源失败 | 资源失败 | 只使用安全已读取截止，否则0 | 空 |
| 合同版本、回声、owner、端点或成功形状矛盾 | 内部不一致 | 内部不一致 | 依安全读取证据 | 空 |

`Gobs == G0` 且未取得锁不能证明漂移；零截止的许可拒绝也不能被上层重分类。日志、调用次数、当前写线程意图和未提交候选都不是已发布事实代次。

六入口 × Debug / Release 均要覆盖：

| 场景 | 安排 | 必须结果 |
| --- | --- | --- |
| P0 稳定成功 | 在非零 `G0` 建立最小合法事实，无 writer 竞争 | 保持现行完整成功形状 |
