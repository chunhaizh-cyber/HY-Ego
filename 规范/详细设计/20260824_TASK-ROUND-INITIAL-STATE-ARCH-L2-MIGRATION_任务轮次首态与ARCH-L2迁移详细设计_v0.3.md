## 1. 完整替代范围

本文件是同计划身份 v0.3 的完整施工依据。正式发布和索引登记后整体替代 v0.2；执行者不得从 v0.1 / v0.2、聊天或旧 DTO WIP 拼接合同。

唯一目标仍是把`需求初次筹办准备提供者::形成唯一任务与初次筹办工作包`改造成最早合法 ARCH-L4 业务消费者：从当前具体需求 D 分阶段形成任务专属正式存在 E、任务 T、首个任务轮次 R1、首个筹办轮次 P1、E 上“筹办 / 待初次筹办”无动态首态，以及迁移到“筹办 / 筹办中”的第一动态，并从各 owner 独立读回完整工作包。

v0.3 同时闭合两项既有计划内漂移：

1. 保留 v0.2 对治理函数定义 U64 材料独立写入键 `0x0301'218F`的全部纠偏；
2. 冻结外层 v2 六阶段幂等键的唯一来源、持久恢复合同和两个真实生产调用者，扩展生产白名单，禁止执行者临场派生键。

本修订不改变“内部治理无需现实执行授权”、任务轮次收束后等待自我后继决议、需求树目标权威、状态 / 动态唯一 owner 或 ARCH-L1/L2/L3 ABI。

## 2. 当前事实与漂移裁决

当前代码事实：

1. `需求初次筹办准备合同版本`仍为 1，外层请求只有一枚`任务建立幂等身份`；首次记录完整请求持久值只有 8 个 U64 槽。
2. v0.2 已要求存在建立、任务核心建立、阶段特征实例建立、首态建立、P1 建立、首迁移六枚独立键，却没有冻结生产调用者如何取得这些键。
3. `形成唯一任务与初次筹办工作包`的生产直接调用只有两处，均在`海中鱼巣/领域/内部治理/服务.任务子目标回流重判.ixx`：一处用历史首次记录重构请求，一处在无当前任务时新建请求。
4. `重判父需求并准备筹办`当前没有生产上游调用者；其余直接调用均为`海中鱼巣/端到端测试.自我治理一致事实.ixx`中的专项。
5. 时间、运行代次、请求身份、回流记录身份或哈希都没有正式无碰撞命名域。尤其任务核心和 P1 同属 task owner，机械变换可能与其它请求身份碰撞。

唯一裁决是：六键属于原业务请求信封，由上游一次性分配并持久传递，不是 provider 的临时计算结果。当前没有生产上游的回流入口只扩展公开请求合同，不新增临时分配器；未来真实上游必须先取得六键再调用。

## 3. 六阶段幂等身份 DTO

在`海中鱼巣/领域/L2任务结构.数据.h`中、`L2任务初次筹办准备完整请求材料`之前定义：

```cpp
struct L2任务初次筹办阶段幂等身份组 final {
    L2结构幂等身份 存在建立;
    L2结构幂等身份 任务核心建立;
    L2结构幂等身份 阶段特征实例建立;
    L2结构幂等身份 首态建立;
    L2结构幂等身份 P1建立;
    L2结构幂等身份 首迁移;
    friend bool operator==(const L2任务初次筹办阶段幂等身份组&,
        const L2任务初次筹办阶段幂等身份组&) = default;
};

bool L2任务初次筹办阶段幂等身份组有效(
    const L2任务初次筹办阶段幂等身份组&) noexcept;
```

有效合同固定为：六键全部通过`L2结构幂等身份有效`，且六个值两两不同。全局任务阶段特征定义继续使用固定幂等身份 `0x5441'534B'5354'4147`（ASCII `TASKSTAG`），不进入六键组。

`海中鱼巣/领域/内部治理/任务初次筹办.数据.h`固定变为：

```cpp
inline constexpr std::uint32_t 需求初次筹办准备合同版本 = 2;

struct 需求初次筹办准备请求 final {
    std::uint32_t 合同版本 = 需求初次筹办准备合同版本;
    初次筹办准备幂等身份 准备幂等身份;
    std::uint64_t 请求身份 = 0;
    std::uint64_t 运行代次 = 0;
    L2结构请求头 请求头;
    L2需求身份 需求;
    L2任务初次筹办阶段幂等身份组 阶段幂等身份;
    std::uint32_t 治理函数合同版本 = L2任务治理函数合同版本;
    std::uint32_t 初次筹办推进规则版本 = L2初次筹办推进规则版本;
};
```

删除外层请求中重复表达任务阶段键的旧`任务建立幂等身份`字段；其语义由`阶段幂等身份.任务核心建立`唯一承载。入口有效性增加：

```text
准备幂等身份.值 == 阶段幂等身份.P1建立.值
六阶段组有效
治理函数合同版本 == 1
初次筹办推进规则版本 == 1
```

准备键只负责外层首次记录定位，不是第七枚阶段键。任务核心键与 P1 键必须不同。

## 4. 完整请求持久材料与版本读回

`L2任务初次筹办准备完整请求材料`同步替换旧单任务键为六键组，并增加治理函数合同版本和规则版本：

```cpp
struct L2任务初次筹办准备完整请求材料 final {
    std::uint32_t 外层合同版本 = 0;
    std::uint64_t 准备幂等身份 = 0;
    std::uint64_t 请求身份 = 0;
    std::uint64_t 运行代次 = 0;
    L2结构请求头 请求头;
    L2需求身份 需求;
    L2任务初次筹办阶段幂等身份组 阶段幂等身份;
    std::uint32_t 治理函数合同版本 = 0;
    std::uint32_t 初次筹办推进规则版本 = 0;
};
```

版本 2 的 U64 编码恰为 15 槽，顺序固定为：

```text
0  外层合同版本
1  准备幂等身份
2  请求身份
3  运行代次
4  请求头合同版本
5  请求头期望事实代次
6  需求稳定编码
7  存在建立键
8  任务核心建立键
9  阶段特征实例建立键
10 首态建立键
11 P1 建立键
12 首迁移键
13 治理函数合同版本
14 初次筹办推进规则版本
```

编码器只接受完整版本 2 材料。解码器必须区分三种结果：

```cpp
enum class L2任务初次筹办请求材料状态 : std::uint8_t {
    无记录 = 1,
    当前版本 = 2,
    初次请求版本待迁移 = 3
};
```

恰为 15 槽且全部合同完整才是`当前版本`；恰为旧 8 槽、外层版本 1 且旧字段形状有效，只能是`初次请求版本待迁移`；其它形状是结构内部不一致。不得把损坏材料归为旧版本，也不得把旧版本 8 槽补成当前 15 槽。

`L2按初次筹办准备幂等身份读取首次记录结果`和`L2任务初次筹办准备记录读取结果`增加上述材料状态。`当前版本`必须携带完整记录 / 任务 / 身份来源；`无记录`和`初次请求版本待迁移`不得携带可冒充当前版本的记录载荷。提供显式`初次请求版本待迁移()`检查，既有`成功()`不得把待迁移当成当前记录成功。所有三处原始完整请求解码调用点统一消费该强类型状态。

`L2任务筹办轮次分区`增加语义独立的`初次请求版本待迁移`，不得复用`遗留实例轮次`或外层`轮次权威待迁移`。这只描述首次请求信封版本缺失，不判断任务轮次权威是否迁移。

## 5. 两个生产调用者的精确合同

`任务子目标回流重判合同版本`升为 2，请求增加：

```cpp
L2任务初次筹办阶段幂等身份组 初次筹办阶段幂等身份;
```

入口要求六键有效，并固定：

```text
初次筹办阶段幂等身份.P1建立.值 == 回流记录.值.值
```

该相等关系维持当前以回流记录稳定编码作为处理键、准备键和首次记录读取键的顺序。其余五键必须由调用方原请求信封提供，不允许从回流记录派生。当前无生产上游，因此本叶只冻结 DTO、校验和专项；不得建立时间 / 哈希分配器或在 provider 内生成缺失键。

### 5.1 历史首次记录恢复分支

`服务.任务子目标回流重判.ixx`中现有历史恢复调用固定为：

```text
按 P1 / 准备键读取首次记录
-> 材料状态为初次请求版本待迁移：返回同名业务状态，零写
-> 材料状态为当前版本：读取回流记录并确认父需求
-> 当前请求六键与历史六键逐字段相同
-> 当前请求身份 / 运行代次与历史原请求相同
-> 仅以历史完整请求重构需求初次筹办准备请求
-> 调用初次筹办 provider 收敛
```

当前请求任一六键、请求身份、运行代次或需求与历史不符，返回`幂等冲突`。不得以当前请求覆盖历史请求，也不得用当前请求头刷新历史原请求头。

### 5.2 无当前任务的新初次分支

现有新建调用固定构造：

```text
准备键 = 请求.初次筹办阶段幂等身份.P1建立
需求 = 回流记录.父需求
六阶段组 = 请求.初次筹办阶段幂等身份
治理函数合同版本 = 1
规则版本 = 1
其它字段沿用经当前性复核的回流请求
```

只有该完整请求通过 v2 校验才调用初次筹办 provider。已有当前任务的后继筹办分支不消费六键，也不得因此自动建立新任务轮次。

外层状态枚举保留既有数值并追加：

```text
需求初次筹办准备状态::发布未知 = 14
需求初次筹办准备状态::初次请求版本待迁移 = 15
任务子目标回流重判状态::初次请求版本待迁移 = 19
任务子目标回流重判状态::发布未知 = 20
```

`成功()` / `已处理()`不得接受这两个非成功状态或携带工作包。

## 6. 治理函数定义键与读回合同

v0.2 的键裁决完整保留：

| 本地键 | 唯一角色 |
| --- | --- |
| `0x0301'2180..0x0301'218E` | R1、治理函数定义和 A1 的 15 项 task owner 服务登记键 |
| `0x0301'2185` | 初次筹办推进治理函数定义节点 |
| `0x0301'2186` | 治理函数定义材料 U64 组属性类型 |
| `0x0301'218F` | 治理函数定义材料值，只属于定义登记写集，不进入 15 项计数 |
| `0x0301'2660..0x0301'2664` | R1 运行时五项 |
| `0x0301'2680..0x0301'2687` | A1 运行时八项 |

定义写集的新编码映射必须精确包含互异的 2185 / 2186 / 218F。值的所属和来源均为定义节点，当前槽引用 218F，材料严格为`{初次筹办推进=1, 合同版本=1, 规则版本=1}`。公开定义 DTO 只能从当前属性槽、原始值事实、所属、类型、来源、材料和生命周期共同读回，不得从常量补齐。

编译期至少固定：登记计数 15、`218F == 218E + 1`、三键互异和`218F < 2201`。

## 7. 任务核心、P1 与 A1 合同

新任务 task-owner G_T 必须同次建立 T、任务族归属、`T→L/T→D/T→E`、R1、R1 族归属、`R1→T`和`T→当前 R1`。E 先由`L2存在结构服务`建立；task owner 只保存 E 引用。R1 序号和首条来源顺序均为 1。

公开强类型继续固定为：

```text
L2任务轮次身份 / 事实
L2任务来源需求关系事实
L2任务正式存在关系事实
L2任务治理函数身份 / 定义事实
L2任务治理动作调用身份 / 调用事实
```

核心 API：

```cpp
L2新增任务轮次与正式存在引用结果 新增任务轮次与正式存在引用(
    const L2新增任务轮次与正式存在引用请求&) noexcept;

L2按建立幂等身份读取任务轮次核心结果 按建立幂等身份读取任务轮次核心(
    const L2按建立幂等身份读取任务轮次核心请求&) const noexcept;
```

首态正式读回后，task owner 以`阶段幂等身份.P1建立`在单 G_P1 同次建立首次记录、P1 和 A1。首次记录保存第 4 节完整请求。A1 绑定治理函数、T、R1、P1、触发前态、G_P1 写前共同截止、P1 建立键、合同版本 1、规则版本 1 和生命周期。第一动态来源必须是 A1；P1、R1、函数名、普通方法、日志、缓存或魔数均不得替代。

## 8. 状态值和分阶段算法

阶段基础定义是实际阶次 1、无直接来源、无派生规则。每个 E 唯一一个阶段实例。I64 状态材料固定：

```text
首态 {1,1} = 筹办 / 待初次筹办
后态 {1,2} = 筹办 / 筹办中
```

时间材料是`{运行代次, 阶段序号}`，首态序号 1、后态序号 2。首态来源为 R1，第一迁移来源为 A1。

完整顺序：

1. 以准备键读取历史首次记录；当前版本完整时用历史原请求恢复，待迁移时零写返回。
2. G0 裁决 D 当前未满足并冻结 D/L 证据。
3. 用`存在建立`键建立 / 恢复 E，形成 G_E。
4. 取得不早于 G_E 的写前截止并复核 D/L/E；用`任务核心建立`键建立 / 恢复 T/R1/三关系，形成 G_T。
5. 用固定 `TASKSTAG` 建立 / 恢复全局阶段定义 G_FD；用`阶段特征实例建立`键建立 / 恢复 E 的实例 G_FI。
6. 用`首态建立`键建立 / 恢复`{1,1}`无动态首态 G_S0。
7. 用`P1建立`键同次建立 / 恢复首次记录、P1、A1，形成 G_P1。
8. 独立读回 A1 和治理函数定义；用`首迁移`键把首态迁移为`{1,2}`并形成第一动态 G_M1。
9. 经存在、任务、特征、状态、动态公开面独立读回并互证完整工作包。

工作包必须包含 E、T、R1、`T→D/T→E`、阶段定义 / 实例、首态、首次记录、P1、函数定义、A1、后态、第一动态和七段结果头 `G_E/G_T/G_FD/G_FI/G_S0/G_P1/G_M1`。

## 9. 发布未知与精确重复

任一阶段非成功但带非零截止，只允许使用该阶段的原键、历史版本 2 原完整请求和该 owner 公开读回收敛。确认同义才进入下一阶段；未确认或异义立即停止。已发布前段事实保留供恢复，不跨 owner 回滚、不换键、不刷新请求、不越段。

同准备键存在最终完整记录时，必须按各 owner 历史截止重建工作包。当前请求必须与历史完整请求逐字段相同，包括六键和两个治理版本；相同返回精确重复，任何差异返回幂等冲突。成功状态但载荷或独立读回不完整固定为内部错误。

历史版本 1 的首次记录不是发布未知，也不是轮次权威待迁移；它只返回初次请求版本待迁移，且零后继写。

## 10. 错误矩阵

| 条件 | 外层状态 | 后继 |
| --- | --- | --- |
| 版本、零键、六键重复、准备键不等于 P1 键、版本字段非法 | `入口拒绝` | 零写 |
| 历史首次记录恰为合法 v1 八槽材料 | `初次请求版本待迁移` | 零写，不补造 |
| D 已满足 | `目标已满足` | 零写 |
| L 已有异义当前任务 | `已有当前任务`或`引用冲突` | 不建第二 T |
| 同键同完整 v2 请求 | `精确重复` | 原键读回既有工作包 |
| 同键异义或当前 / 历史六键不等 | `幂等冲突` | 停在当前阶段 |
| 事实截止漂移 | `当前性漂移` | 新业务请求，不刷新原信封 |
| owner / 宿主 / 定义 / 前态 / A1 坏引用 | `引用冲突` | 零后继写 |
| 许可拒绝 | `许可拒绝` | 原样上送 |
| 分配或存储失败 | `资源失败` | 可按原键恢复 |
| 截止非零但提交结果未确认 | `发布未知` | 只读收敛，禁止越段 |
| 损坏材料、成功形状或历史互证矛盾 | `内部错误` | 零成功载荷 |

## 11. 普通应用、生产调用闭包与文件范围

修改白名单：

