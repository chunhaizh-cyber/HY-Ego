## 1. 当前结论

`e04887112`已经发布 self 可消费的 fresh 正式上下文 provider，`90d9b747b`已经发布 G4-A 双根只读复核 provider，普通应用也分别持有两者的唯一生产实例。当前 self 尚未实际调用两项 provider，但这部分控制流已经能够从现行合同唯一设计。

真正的最早阻断是正差距结果的正式承接方。现行代码没有任务管理线程、任务治理输入边界或符合 3200 / 5260 的任务核心 provider；`海中鱼巣/领域/数据服务.任务类.h`合同版本3仍是旧的“所属存在 + 单一来源需求”记录入口，不能承接无所属存在的安全根、服务根 D，也没有 5260 要求的查询锚点、`T→D`组、`Vt + R1 + 首态`核心、P1、首迁移和恢复合同。

此外，两项现行上游DTO仍没有合法生产输入：`自我线程正式上下文请求_v1`要求七项非零物理读取预算，但创建请求、开门入口和普通应用配置都不提供这些值；0050现行合同又禁止以资源预算裁剪完整业务范围，不能把普通应用私有阶段21常量或极大数塞入请求。G4-A请求还强制`来源消息`和`原请求`非零，而首次普通治理并没有外部根复核消息或正式身份生产者，不能用线程事件序号、时间或本地计数临时造号。

此外，现行双根规范把“负差”和“方向相反”并列为技术非成功，术语边界不够精确。目标状态合同本来可以要求增加或减少某个特征值；当目标要求减少时，带负号的`目标值-current`或“相对特征值正方向相反”都可以表示合法的减向差距，不能因方向为反向就判异常。必须把“目标要求沿特征值反方向变化”与“实际变化背离目标方向”分开，后者才是未朝目标推进。安全根、服务根当前专属目标固定为`I64_MAX`，所以在其合法值域内仍只会出现增向差距或当前满足；这是双根专属目标造成的结果，不能推广为普通需求通用规则。

因此，本轮不能形成“self消费 + 根治理意图 sink”的单一可执行计划。用旧`新增任务记录`、空回调、只入队不落正式owner、日志或消息成功代替任务承接，都会把未实现的 task owner 事实伪装成闭环；给旧预算或首次触发身份硬编码值也不能形成合法生产消费。

当前计划索引应继续为空。依赖顺序必须先闭合预算自由 fresh 请求与首次治理触发身份，再闭合“根需求任务核心正式承接 provider”。下述机器语义尚未由现行规范唯一裁决，且普通需求方向术语仍需正式校正；计划智能体不能临场补造。

## 2. 已确认可直接复用的上游能力

### 2.1 fresh正式上下文

`自我线程正式上下文端口::读取正式上下文(...)`及普通应用唯一提供者已经形成。它可以在 self 本轮处理时重新读回唯一 self、所在场景和双根锚点，并以同一非零截止返回值式投影。self 不需要也不得直接读取 DATA-L1 / DATA-L2。

现行 self 创建只预绑定该非拥有端口；线程停在关闭的治理运行门期间保持零调用。这是当前实现事实。provider本体已经存在，但其v1请求仍要求七项非零预算；0050已使这类物理资源预算退出生产资格，故self真实消费前必须形成预算自由的新请求合同并同步迁移provider，不得从私有常量补值。

### 2.2 G4-A双根复核

`自我线程根需求复核端口::复核双根当前需求(...)`及`自我根需求复核提供者`已经形成。它消费 fresh 上下文，以同一截止完整复核两根，并分别返回`当前满足`或`正差距`；技术失败按逐根状态和总状态分账，零业务写入。

该 provider 还没有注入 self。它只能形成本轮只读决策材料，不能建立任务或替代 sink。其v2请求当前要求`来源消息`和`原请求`非零，普通消息触发可以直接透传，首次普通治理则没有正式来源；首次触发身份及恢复重投合同必须先冻结，不能复用线程事件序号、G、D、时间或三项任务初始化键。

### 2.3 self线程骨架

`线程_自我.h/.cpp`已经具备单对象线程、关闭门停驻、有界邮箱、根复核触发消息、停止唤醒和`join`。当前`运行()`在停门后只等待停止，`复核前置并开放治理运行门(...)`仍固定返回依赖未就绪；这些是后继消费者接线位置，不是正式 task owner。

## 4. 不能由现行材料唯一裁决的机器语义

### 4.0 目标方向、带符号差距与“方向相反”必须分账

目标方向由目标状态合同规定，可以是增向、减向、进入区间、保持或其它具名关系。对有序I64目标，若业务选择以`目标值-current`表达带符号差距，则：

```text
差距 > 0：需要沿值域正方向增加
差距 < 0：需要沿值域负方向减少
差距 = 0：在精确等值目标下当前满足
```

正负号描述“为到达目标应往哪边变化”，两种非零方向都可以是合法业务差距。若既有“方向相反”专指相对特征值已登记正方向的反向，则它就是合法的减向差距结果；它们都不直接证明已经发生变化，也不直接证明某个方法适用。

为避免同词复义，正式合同应明确区分：

```text
相对特征值正方向相反：目标要求减少，属于合法减向差距
相对目标方向相反：实际变化、候选方法预期变化或冻结结果背离目标
```

后一个判断必须同时取得目标方向和被判断变化的有序方向后才能成立，不能仅凭`目标值-current < 0`得出。正式结果宜直接命名为`需增加`、`需减少`和`背离目标方向`，不再让裸“方向相反”同时承担两种含义。

安全根、服务根当前固定`目标=M=I64_MAX`且合法当前值在`0..M`，所以其专属求值只有`差距>0`的增向差距或`差距=0`的当前满足；`目标值-current < 0`在这两个固定合同下仍表示目标、当前值、公式或来源不一致。这里应描述为“双根固定公式下的非法负差”，不能据此否定普通需求合法的反向 / 减向目标。5170、6120、6130、8200及规范目录的现行文字仍有混称，须经用户确认后统一修订；本阻断稿不直接取得正式规范修订权。

### 4.1 双根D如何成为任务的确定目标

3100 / 5170规定普通D的核心契约为：

```text
所属存在 + 目标宿主 + 目标特征 + 目标状态合同
```

但安全根、服务根D是唯一初始化例外，只保有独立D、对应根特征、根目标合同、父空和顺序0；明确没有所属存在和目标宿主。3200 / 5260又要求任务从每条当前`T→D`逐项读回完整目标三元组并互证一致，没有当前有效D时不得形成任务目标。

因此，现行规范没有回答：根治理任务怎样从一个依法没有目标宿主的根D读出3200要求的目标三元组。不能由代码擅自把 fresh 上下文中的 self 填成D的目标宿主，也不能把阶段21锚点解释成D内不存在的字段。

需要正式裁决根任务的目标投影。推荐方向是：根D物理结构保持不变，由任务业务应用在同一 fresh 截止形成下列值式投影：

```text
目标宿主 = fresh正式self E
目标特征 = 对应正式根FT
目标状态合同 = 对应根目标合同
```

来源见证至少包含`根角色 + D + L + 根形成F + 目标值事实 + 共同截止`。根形成F只证明正式根FT及形成时self适用，不能充当目标特征、当前F或第二目标权威。投影只用于任务业务即时读取，不向根D补写所属存在或目标宿主，不持久写入T成为第二目标权威。

task owner至少需要两类读取：按当前共同截止形成本轮目标投影，以及按显式历史截止重建已经冻结的任务目标、结果和结算来源。现行根材料接口首版只支持`H=Gread`，不能证明历史冻结和跨重启恢复，因此后继精确合同必须补齐历史来源读取或等价的不可歧义恢复边界。该推荐会新增根任务专属业务语义，必须先修订正式规范，详细设计不能代替裁决。

### 4.2 三项任务初始化幂等身份由谁签发

5260要求首次承接请求一次携带三个互不相同且非零的稳定幂等身份：

```text
任务核心建立
P1建立
Vt首迁移
```

同时禁止按时间、会话代次、线程材料、哈希、需求 / 任务身份或中间结果临时派生，并要求发布未知和跨重启恢复继续使用原身份与原完整请求。8100还要求 self 发布的不可变任务发起意图含幂等身份并经异步边界交 manager。

现行规范和代码没有定义这三个身份的唯一签发者、签发入口、持久恢复来源、与消息 / 原请求身份的关系，以及“任务尚未存在时如何取得稳定且可跨重启恢复的原任务初始化请求”。计划若自行选择进程计数器、随机数、普通应用配置、需求 / 任务身份、哈希或裸稳定编码，都会改变所有权和恢复语义；用fresh业务查询判断“尚未发布”也不能替代L1对原幂等键的发布未知收敛。

推荐由新的task owner独占一份私有“持久高水位 + 预留号段”技术元数据。它不是逐请求治理账、任务业务账或第二事实权威：

1. 初始化只使用固定bootstrap/control键域收敛高水位；
2. 每次按块持久预留号段，进程内从已预留号段取得三个连续且互异的身份，依次用于任务核心建立、P1建立和Vt首迁移；
3. 任务核心首次写把三项身份，或可无歧义恢复三项身份的base，与完整原请求共同保存为T私有恢复材料；
4. 发布未知始终使用原控制键或原阶段键收敛，不通过fresh业务查询另造键；
5. 重启后未使用的预留号段永久作废并重新预留，已发布T从自身恢复材料继续后续阶段；
6. 不修改L1公开ABI，并使用新的task owner身份，避免与旧任务版本3任意键历史发生域冲突。

该方案比顺序探测业务稳定编码更符合5260的原键重放和恢复约束，但仍涉及唯一owner、持久技术元数据和公开恢复合同，必须由正式规范确认，不能由执行者直接采用。

### 4.3 task owner核心、当前资格和恢复的精确公开合同

5260冻结了逻辑组合和最低能力，但没有与当前`.h/.cpp`对应的现行精确DTO、关系类型、状态枚举、事务分段和迁移合同。至少仍缺：

- 根 / 普通D共同使用还是分开的承接请求和目标投影；
- L锚点、T、`T→D`、Vt、R1、首态的物理字段及关系身份；
- “0..1当前T”的当前资格、完成 / 失败 / 取消退出查询资格规则；
- 核心写集、P1建立和首迁移三段各自请求、结果、首次材料及失败优先级；
- 已有T时增加`T→D`与首次新建T的分支和幂等语义；
- 发布未知、部分阶段成功、消息丢失及重启后由哪个公开入口收敛；
- 旧任务版本3的拒绝、迁移或物理删除范围。

推荐建立新的task owner与新的任务核心公开ABI，使其一次承接根任务目标投影、L锚点、多条`T→D`、核心写集、P1、首迁移及恢复；旧任务版本3物理退出，不保留兼容旁路或双权威。若持久仓存在旧任务事实，迁移合同必须明确其只读识别、历史保留或物理退出方式，不能由“当前无生产调用”推导为可无条件擦除。

这些内容涉及公开ABI、唯一owner、事务、生命周期、恢复和迁移，必须由正式规范或经用户确认的规范修订先行冻结。仅凭“任务类已有新增函数”不能把它们降格为普通工程选择。

### 4.4 异步意图交接不等于正式任务承接

8100 / 8200已经固定 self→manager 必须经过不可变异步消息边界，manager独立取出、复核并读回正式owner结果。仍需在上项provider合同形成后精确冻结：

- self发出的根治理意图DTO、消息身份、原请求身份和完整初始化请求包；
- 进程内队列只证明接收，不证明任务建立；
- manager消费后返回 / 通知的只能是已发布T及其核心读回定位；
- 精确重复、异义冲突、队满、消息丢失、owner发布未知和重启恢复的分账；
- 当前满足时零意图，正差距时每根至多一份承接意图；双根均正差距时两份意图互不替代；任一技术非成功不提交部分成功意图。

这部分可以在task owner精确合同发布后由后继详细设计唯一闭合；当前不能用未实现sink反向冻结为成功。

## 5. 正确的依赖拆分

当前依赖链固定为：

```text
正式裁决目标增/减方向语义、根任务目标投影与初始化幂等身份签发边界
-> 冻结task owner任务核心精确物理合同、迁移和恢复
-> 建立最早provider详细设计与单一代码计划
-> provider发布并验证真实成功、重复、冲突、部分阶段与恢复
```

最早provider计划只负责正式任务核心承接，不把self线程、manager线程、工作线程、方法筹办或治理门混入同一代码叶。self消费者保留为直接后继路线输入；它不得在provider不存在时以占位成功解除停门。

## 6. 最小裁决问题

只有以下问题需要用户 / 规范治理裁决：

1. 是否按第4.0节统一方向语义：增向和减向均可成为合法目标差距；相对特征值正方向相反属于合法减向目标，实际 / 候选变化与目标方向相反则另称“背离目标方向”；双根固定最大值合同仍只产生增向差距或满足？
2. 是否采用第4.1节推荐的根任务目标投影：保持根D无所属存在 / 目标宿主，以`fresh self E + 正式根FT + 根目标合同`形成零持久化任务目标投影，并补当前 / 显式历史截止的来源见证？
3. 是否采用第4.2节的新task owner私有持久高水位 / 号段方案签发并恢复三项技术幂等身份，同时不修改L1公开ABI？
4. 是否以5260逻辑合同为基础建立新的任务核心公开ABI并物理退出旧任务版本3不相容入口，不保留兼容旁路；若发现旧任务持久事实，再由迁移合同明确其历史保留或退出方式？

上述任一问题未裁决前，不得创建可执行代码计划。
