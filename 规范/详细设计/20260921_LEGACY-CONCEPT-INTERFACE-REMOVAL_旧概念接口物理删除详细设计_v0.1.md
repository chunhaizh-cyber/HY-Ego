# 旧概念接口物理删除详细设计

身份：`LEGACY-CONCEPT-INTERFACE-REMOVAL`

版本：v0.1

日期：2026-09-21

状态：施工详细设计

## 1. 目标与完成边界

本设计物理删除概念owner中已经退出生产拓扑的旧接口：`概念树结构交付 + 概念树共享结构交付 + 特征概念结构交付 + 概念树存在扩展交付 + 四本体根/base布局`。不保留构造转发、双读双写、只返回`旧格式不支持`的公开壳或兼容验证。

删除完成后，生产概念服务唯一构造基础保持：

```text
纯概念结构交付_v2
+ 特征概念出生使用结构交付
+ 存在概念两组结构交付_v1
```

本切片不实现RC/DC，不改变pure v2、FC出生使用或存在两组定义的机器含义，不删除旧持久数据，不建立离线迁移器。历史数据需要转换时另立迁移合同。

## 2. 正式依据与当前事实

正式依据：4240 v0.42、4241 v0.3、4242 v0.2、7170 v1.2、7180 v1.2、7191 v0.5。

当前普通应用已经按pure v2、出生使用、两组定义顺序登记并构造唯一概念服务；不存在生产代码调用旧构造。旧接口只剩：

- `数据服务.概念树类.h/.cpp`中的5个旧构造、4组旧布局DTO/字段、旧CRUD和旧根访问；
- `相关概念窄参与专项验证.cpp`中的old-only与migration兼容测试；
- `绑定存在创建专项验证.cpp`中的旧概念夹具；
- 无受跟踪实例化者的`存在概念树应用服务`及工程登记。

`EXISTENCE-CONCEPT-DEFINITION-PROVIDER-REBUILD`的中间代码已经形成现行pure v2生产构造，但原计划未闭合旧消费者退出。本设计替代其剩余删除职责，不恢复其D/O/R旧目标。

## 3. 删除集合

### 3.1 数据服务公开面

删除以下类型及其仅为旧布局服务的请求、结果、辅助类型：

```text
概念树根引用组
概念树结构类型
概念树结构交付
概念树共享结构交付
特征概念结构交付
概念树存在扩展交付
```

删除所有接收`概念树结构交付`的5个构造重载，以及旧公开入口：旧根引用、共享应用启用、旧概念读取/查重/建立、旧直接上位操作、旧共享FC/EC应用和仅由这些入口使用的状态/DTO。不得保留deprecated声明、内联转发或运行时拒绝壳。

删除私有`layout_`、`shared_`、`feature_layout_`、`existence_layout_`、`旧布局()`及只从旧公开入口可达的私有实现、pending状态和辅助函数。

### 3.2 必须保留的当前公开面

必须保留并保持原义：

```text
pure_layout_
feature_birth_layout_
two_group_definition_layout_
related_layout_
纯概念v2、FC出生使用、存在两组定义和相关概念的现行构造/CRUD
```

公共概念身份、生命周期、预算、直接上位事实等仍被当前接口使用的值类型不得因物理位置接近旧DTO而误删。

### 3.3 旧应用与工程登记

`业务/应用服务.存在概念树类.h/.cpp`无生产消费者并依赖旧存在根、旧`读取概念`和旧共享应用入口，整文件删除。同步删除根工程、filters及三个专项工程中的对应`ClInclude`/`ClCompile`登记；不建立空替代类。

### 3.4 验证消费者

- `相关概念窄参与专项验证.cpp`保留现行相关概念构造及其断言，删除旧布局生成器、old-only和新旧迁移兼容用例。
- `绑定存在创建专项验证.cpp`保留存在绑定业务验证，把概念夹具迁移到pure v2、出生使用、两组定义的真实登记与当前构造；不得整份删除或以假对象绕过。
- `世界树根启动专项验证.cpp`源码已经使用现行构造，不修改其语义；仅删除旧存在应用文件的工程登记。

## 4. 实施方法

先从头文件删除旧公开面和私有字段，再从源文件删除对应定义。对源文件内被新接口复用的L1读取、关系/属性读取、生命周期投影等中性辅助函数，只有在当前调用图证明仍被pure v2/两组/相关概念使用时保留；旧实现块与当前实现共享辅助时，将辅助留在现有类中，不复制第二份。

删除后执行全仓旧符号检索。历史规范、施工记录和Git历史中的文字命中不作为生产残留；生产源码、验证源码和工程文件必须零命中。编译错误只能用于发现漏迁消费者，不能扩张机器语义或恢复旧接口。

## 5. 失败与恢复

若删除发现当前生产调用仍依赖旧接口，停止受影响范围并报告精确调用点；不得添加兼容层。若仅专项验证依赖，按第3.4节迁移或删除兼容断言。若共享辅助删除导致当前接口编译失败，恢复该中性辅助而不是恢复旧DTO/构造。

本切片不接触旧持久数据，因此不存在数据回滚或迁移写入。Git提交失败保留源码现场；禁止reset、clean、stash或带入未跟踪构建产物。

最低验证：

1. `rg`确认旧6组交付/根DTO、旧构造签名、`共享应用已启用`、`旧布局()`及旧存在应用生产符号在受跟踪代码和工程文件零命中；历史文档命中单独列账。
2. 根工程x64 Debug和Release编译链接通过。
3. `相关概念窄参与专项验证`、`绑定存在创建专项验证`、`世界树根启动专项验证`至少Debug构建；前两项运行并保持现行结构化断言通过，若运行依赖外部资源则记录具名未运行边界。
4. `git diff --check`、`git diff --cached --check`。

构建与专项只证明旧生产接口已物理退出且当前消费者编译/局部运行闭合，不证明RC/DC实现、历史数据迁移、跨进程恢复或业务闭环。
