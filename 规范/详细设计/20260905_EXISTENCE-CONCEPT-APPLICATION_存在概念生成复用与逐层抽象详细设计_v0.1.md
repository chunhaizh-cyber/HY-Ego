## 1. 目标与裁决

在唯一概念 owner 上实现“同截止世界存在见证 → 显式选定特征概念合取 → 精确复用或创建存在概念 → 世界存在支持 → 严格减少约束生成上位 → 既有存在根”的可调用业务闭环。具体世界存在只经支持关系进入底部，不复制实例、值或身份。多父 DAG 为权威，业务树结果是可清空重建的值式投影。

本轮固定显式模板身份组合：不同宿主形成的两个特征概念，即使 FT 和数值域相同，也不自动合并。相同所选模板组可用于多个目标存在，但每个目标均须重新取得真实特征见证。特征概念最初形成宿主不等于本次目标存在；模板应用只借用 FT 与值域谓词，不建立目标特征名称字段引用。

本轮抽象只实现严格子集，不实现特征概念语义上位替换、自动聚类、全部子集枚举、区间学习、存在概念成熟自动裁决、自然语言名称、世界实例创建、状态创建、主程序或设备接线。既有生命周期和支持退出仍由公开 owner 管理；不新增另一份成熟账、owner、缓存权威或语言根。

## 4. 业务 DTO 冻结

所有新 DTO `合同版本` 固定 `uint32_t=1`，请求头使用 `L2结构请求头`。计数/预算为 `uint64_t`，均显式非零，无默认业务阈值；稳定编码及身份沿已存在强类型。集合在入场复制规范化后确定排序去重；重复模板请求属于入口拒绝，不静默改变调用者合取。

| DTO | 全部业务字段与含义 |
| --- | --- |
| `存在概念预算` | `最大概念数`、`最大关系数`、`最大支持数`、`最大存在成员数`、`最大特征属性数`，全非零；关系预算计入每条直接边一次，支持按关系身份一次 |
| `存在特征见证` | `L2概念身份 模板`、`L2新特征值引用 精确值`、`稳定编码 宿主成员关系`；精确值包含实例与值事实，不接收调用者声称的 FT/原值作为事实 |
| `存在实例见证` | `L2新存在引用 实例`、`vector<存在特征见证> 特征见证`；全部同本次请求头 G，恰为所选模板逐项提供一个见证 |
| `存在下位抽象见证` | `L2概念身份 下位`；从其正式定义选严格子集，无世界实例见证也可形成更抽象概念 |

| `存在概念支持请求` | 合同版本、请求头、幂等身份、`L2概念身份 概念`、`存在实例见证 见证`、`不可变材料身份 建立依据材料`、`vector<不可变材料身份> 发布证据材料`、预算 |
| `存在概念上位请求` | 合同版本、请求头、幂等身份、`L2概念身份 上位`、`L2概念身份 下位`、预算；替换原根边由同 G 正式读出，不接受调用者猜测边身份 |

| `存在概念操作请求` | `variant<存在概念生成请求,存在概念支持请求,存在概念上位请求>` |
| `存在概念结构请求` | `variant<L2普通概念建立请求,L2概念世界事实支持新增请求,L2概念直接上位新增请求,L2概念直接上位替换请求>` |

新 `存在概念状态` 按顺序固定为：`已准备=1,已读取,已复用,已提交,精确重复,入口拒绝,引用冲突,未找到,已退出,事实代次漂移,幂等冲突,数量预算不足,资源失败,历史材料不可用,内部不一致,结构未配置`。新 `存在概念发布状态` 为 `未派发=1,已确认发布,可能已发布`；后者不是业务成功。

`存在概念准备结果` 字段：合同版本、状态、`原事实截止`、`optional<存在概念操作请求> 原请求`、`optional<存在概念结构请求> 结构请求`、`optional<L2概念身份> 复用目标`、`optional<L2普通概念事实> 复用普通概念`、`bool 复用存在根`。只读复用必须无结构请求；普通概念载荷完整且身份等于目标；根复用只带正式根身份。可发布准备必须有原请求、精确原 G 和结构请求，无复用载荷。非成功准备零成功载荷，可保留收到的原请求。

`存在概念写入结果` 字段：合同版本、状态、`事实截止`、发布状态、`optional<uint64_t> 发布截止`、`optional<存在概念准备结果> 原准备`、`optional<存在概念结构结果> 结构结果`、`optional<L2概念身份> 目标概念`、`bool 目标为存在根`。成功谓词仅接受只读复用（未派发+无发布截止+正式复用材料）、或 owner 完整已提交/精确重复结果（已确认发布+明确发布截止+原结构请求及结果类型匹配）；不能由枚举和非空目标 alone 判成功。可能发布可保留完整 owner 响应作诊断，但不返回成功谓词。

`存在概念树结果` 字段：合同版本、状态、`事实截止`、`L2概念身份 存在根`、`vector<L2概念身份> 概念组`（含根）、`vector<L2概念直接上位事实> 直接边`、`vector<L2概念世界事实支持关系事实> 叶级支持`。仅身份/关系引用，不复制世界实例或特征值，不持久化层高和路径。失败全部投影清空，事实截止只作失败位置，不是成功见证。

## 5. 定义、实例见证与精确复用

### 5.1 存在定义编码

应用专用签名标识角色 `0x4543'0001ULL`，值为 `int64_t{1}`，顺序为1；模板定义角色 `0x4543'0002ULL`。普通存在概念始终具有恰一个标识值式项、恰一个模板角色合同（min=max=N,N>0）、N 个概念目标定义，按模板身份稳定编码排序，顺序1..N。规则使用调用者真实不可变材料身份；规则材料标识与版本语义由不可变材料承载，本模块编码版本固定1。不得把模板身份塞到 U64 值或复制模板 FT/值域到存在签名。

初建普通存在概念直接上位恰为既有存在根，来源证据为调用方排序去重非空材料组。实例见证不进普通概念签名/定义；原业务请求及后续支持依据保留它。形成见证为下位时，必须读回本应用格式的活跃下位且签名规则材料相同，所选模板是其严格子集。空子集直接复用根，来源/幂等等输入形状仍校验，但零写，不绑定新键。

不同规则材料、不同模板身份组为不同完整签名。遍历同根全部当前概念并比较完整签名；根、其它格式普通概念均保留投影但不假装本应用候选。同签名发现1项：活跃则只读复用；冷却或退役则返回已退出/拒绝新准入并保留身份诊断，不创建重复身份，也不自动激活。多项同签名内部不一致，绝不取第一项。不可逆退出不在当前图内，是否重新形成仍由 owner 的当前唯一性合同裁决。

### 5.2 逐项实例准入

所有新实例准入必须先读取完整目标存在（关系预算），再对每个显式见证完成：

1. 同 G 读取存活的正式特征概念和 FT/值域；概念可未成熟，但须活跃，本业务不由成熟枚举推语义。
2. `读取特征历史事实` 使用 Gread=H=G、精确实例与值事实、明确属性预算；成功结果实例、值事实和 FT 均逐项核验。
3. `读取特征成员历史事实` 使用同 G、目标存在、提交的成员边和特征实例；只接受该存在自有且该 G 可见的真实成员。
4. 实例直接值沿 I64/I64组/U64组分支解析；值结点引用经值服务按结点历史事实取得原值，检查值 owner 自有类型、来源和形状。独立材料引用没有本轮可解码的数值合同，返回规则不支持所对应的入口拒绝，不猜测数值。
5. FT 身份必须等于模板 FT；实际值按精确全值相等或 I64闭区间包含检查，不扩张区间、不覆盖原值。
6. 每个选定模板恰一见证，不能漏项、多项或用另一模板见证替代。同 FT 多约束可各用不同真实成员，也可复用同一实际成员；所有见证仍是同 G 的合取。

最后同 G 读取根组作守卫。任何失败均在首次 owner 派发前结束。目标存在、成员或实际值不满足并不是概念身份失效。

### 5.3 支持与双向读回

支持目标可为本应用活跃普通存在概念或既有存在根。普通目标逐项验证其完整模板组；根目标要求空特征见证但仍读取目标具体存在。先按世界事实读取全部支持关系，完全相同目标已存在时只读复用；不根据其它概念支持推断新支持。新关系直接转成 generic 支持新增请求，保留原 G/key/依据材料/证据组。

owner 成功后，在 owner 明确发布 H 以历史读取按实例和按概念两个方向完整回读，确认同一关系身份、目标、世界身份、建立依据和证据，返回实际发布 H。期间当前 G 前进不允许把当前无关集合当发布时证据；历史读使用新 Gread 与原 H，所有读头一致。任何发布后失败保留原准备并标可能发布；不退出已合法概念或世界实例。

## 6. 严格子集上位、根边与多步骤

`连接抽象上位` 从正式定义证明：两端都是当前活跃存在根内身份，普通上位的模板组为下位严格子集且签名规则相同；存在根作为空约束终点。下位不得为根，自环、相同定义、非子集和跨根均拒绝。该 API 不接收任意拓扑边声明，也不从名字推顺序。

若请求上位为存在根，只要下位当前图已到该根，即返回零写复用；无需补冗余根直连。普通上位已为下位直接父时同样零写。新增普通中间上位时，读取下位全部直接父：有一条直接存在根边则使用 owner `替换概念直接上位关系`，准确替换这一条为新上位；没有根直连则使用新增。其它全部合法父边保留，不执行传递规约或单父化。替换与新增均为 owner 单笔原子操作，root 可达/无环最后由 owner 守卫。

生成上位和连接下位是两个显式 API 调用：先 `取得或生成存在概念(形成见证=下位,模板=严格子集)`，再按读回 G `连接抽象上位`。生成概念与实例支持也分两步。不得把它们宣称全原子；后一步失败时前一步概念仍合法存在。调用方持有每步原准备与结果，恢复只重放未确定的那一步，不能换键重做整个过程；零写复用不消费幂等键。测试必须证明概念已建/支持失败、上位已建/接边失败均可独立恢复且无重复节点。

## 7. 准备、发布、原键恢复与失败

所有准备均为纯读与值式构造，不拥有写端口、不占持久键。三个便捷方法仅执行“准备 → 发布或只读复用”。准备得到可派发结构请求之前必须完成输入、根、定义、实例见证/严格子集与完整候选校验。

准备载荷可由调用方保存并可能被篡改，因此发布入口先校验原请求和结构请求的值式一致性：合同、原 G、原 key、原请求类型、规则、规范化模板组/标识角色/定义基数、来源/支持依据/证据、目标、下位及上位必须相等；原请求不能缺失。root身份和被替换边是派生事实，必须在首次当前准入重建中验证，不能单凭客户端字段信任。结构 variant 类型不得跨业务操作替换。

读取当前 Gread 后分支：

- Gread < 原 G：入口拒绝，零派发。
- Gread == 原 G：重新准备原业务请求，只有重新得到的完整结构请求与收到的结构请求完全相同才派发；重新准备是复用或失败时不得将伪造可写准备当成功。收到的是只读复用准备时，必须重新取得同一复用目标后才返回复用，不绑定 key。
- Gread > 原 G：只允许完整可写准备；先按下一段验证原H历史见证，再按原结构请求、原 G 和原 key 交给 owner 的首次材料重放；不得按新 G 重新选择候选、换见证、换 key 或改根边。owner 未找到原 key 时原 G 守卫拒绝写入。只读复用准备过期应返回事实代次漂移，由调用者 fresh 读取。

`验证原请求历史见证` 固定 H=原请求G、Gread=当前G。生成的实例见证仍逐项验证当时目标存在、成员、精确值、模板FT和值域；形成见证为下位时，验证该H正式下位定义与所选严格子集。支持验证该H目标存在概念定义、原实例见证与材料；上下位验证该H两端定义、严格子集、原根边（替换时）及原结构请求的端点。只使用既有公开历史API，不按当前状态重做候选选择；源宿主/目标实例后来退出不使当时合法见证失效。历史材料不可用则在本次未派发状态保留原准备并返回历史材料不可用，不能伪称已确认成功。`未派发`只描述本次尝试没有调用owner，不能推导过去请求从未发布。

generic幂等身份持久绑定的是完整结构请求，而非客户端业务见证字节。历史复核证明收到的形成见证在原H合法，不能声称owner保存了首次客户端逐项见证或以原键证明其字节完全相同；签名排除实例见证的原则不改变。支持依据/来源证据仍是实际材料关系，可审计原请求包由调用方负责保留。本轮不为此另建第二幂等仓或临时持久字段。

每次实际 owner 派发后：成功且完整明确 H 才标已确认发布；非成功及异常统一保守标可能已发布，原准备原样保留。generic owner 的失败头没有足够信息区分首次材料读失败、发布后读失败与明确零写，不能从空 `变更事实代次` 断言零发布。派发前本应用拒绝才标未派发。失败结果不制造成功载荷、不自动补偿删除。资源异常映射资源失败，其余异常内部不一致；构造失败仅抛配置异常。

结构完整结果之后仍需业务读回：创建核验普通定义与根路径；支持核验双向集合；上位核验目标直接边、旧根边已退出或新增及全部其它父边保留。重复响应返回其首次发布 H，后续生命周期变化不改写该 H 的成功事实。

## 8. 特征概念形成来源的最小提供者修正

## 9. 业务树投影与预算

从正式根组定位唯一存在根，私有 BFS/队列沿公开 `读取概念直接下位关系组` 展开，每个节点只展开一次、每条直接边按关系身份计一次；收集完整多父边，普通概念逐个正式读回并核对唯一根。循环检测使用颜色/拓扑计数，不能因为 visited 就吞掉环。根、概念、边和支持必须共用请求 G；最后读取根组确认 G 未漂移。
