## 1. 目标、事实与裁决

本叶只在 P1C-F 最终门面中原位替换 `发布状态并整理动态` 一个骨架根，消费 P1B 最终动态业务服务并映射为 `世界树写入结果`。不新建 DTO、服务、公开函数、模块、工程项或顶层自检身份。

当前正式代码尚无 P1C-F、P1B-F、P1B-Q、P1B-W0 的目标生产模块；四项均为正式待激活计划。因此本设计可发布，施工计划必须保持待激活。P1B-W0 是首个真实写分支：无前状态可提交基准状态，已有前状态固定未实现14；本叶不得把“整理动态”函数名解释为迁移动能已真实形成。

直接依据为 0050、4030、4200、4201、P1C-F v0.1、P1B-F v0.2、P1B-Q v0.1、P1B-W0 v0.1 及现行函数功能确认。旧 P1C 大设计/计划和旧六写图只作差异证据，不取得施工身份。

## 2. 唯一函数、物理位置与保持范围

```cpp
世界树写入结果 世界树业务服务::发布状态并整理动态(
    const 世界树状态动态请求& 请求) const noexcept;
```

唯一生产文件：`海中鱼巣/领域/服务.世界树.ixx`。本叶只替换该函数体。模块 import、门面 DTO、类、五引用构造、成员顺序、九根声明、静态签名断言及其余八根均按 S0 基线原样保持。

“其余八根原样保持”是顺序无关合同：若 P1C-SW 或其它独立真实替换叶已先进入 main，则保留其真实函数体和专项矩阵；若未进入则保留骨架。不得用“应仍为未实现”覆盖已发布后继结果。

## 3. 唯一 provider 调用与顺序

门面无前置 provider 调用，固定执行：

```cpp
const auto 状态动态结果 = 状态动态_.发布状态并整理动态(请求);
```

恰调用一次，不重试、不回查、不先读快照。`存在_`、`场景_`、`特征_`、`快照_` 均调用0；P1B 的 `查询_ -> 特征_ -> 比较_ -> 状态_ -> 数据操作_ -> 提交_` 顺序只属于 `节点直接动态业务服务`，门面不得复制或穿透。

请求由调用方拥有，门面和 provider 仅在同步调用期 const 借用且不保存。provider结果和门面结果按值拥有。

## 4. 状态映射

| provider 状态 | 世界树业务状态 | 说明 |
| --- | --- | --- |
| 已提交 | 已提交 | 进入成功读回校验 |
| 幂等读回 | 幂等读回 | 进入同一成功读回校验 |
| 入口拒绝 | 入口拒绝 | 逻辑内拒绝 |
| 幂等冲突 | 幂等冲突 | 同键异义 |
| 前状态不唯一 | 内部不一致 | 不能任选前状态 |
| 比较未注册 | 资源失败 | 正式比较能力不可用，不伪装请求非法 |
| 不可比 | 入口拒绝 | 第一写前结构化拒绝 |
| 差异不可表示 | 入口拒绝 | 第一写前结构化拒绝 |
| 版本漂移 | 版本漂移 | 不重试 |
| 许可拒绝 | 许可拒绝 | 不等待 |
| 资源失败 | 资源失败 | 不回退旧栈 |
| 内部不一致 | 内部不一致 | 保留 provider 缺项组 |
| 历史插入拒绝 | 入口拒绝 | 不重算历史 |
| 未实现 | 未实现 | W0已有前状态等未闭合分支安全停止 |
| 未知枚举值 | 内部不一致 | 防御性源码闭包 |

所有分支保留 provider 的 `发布代次` 和 `持久状态`。除 provider `内部不一致` 原样保留其 `缺项组` 外，其它非成功均清空目标、旧关系、新关系、操作读回和缺项组。门面自发现的未知状态或读回矛盾没有合法 provider 缺项来源，缺项组为空。

## 5. 成功读回与统一字段

只有 `已提交/幂等读回` 可以发布统一业务载荷，必须同时满足：

1. `发布代次 != 0`、provider `缺项组.empty()`、`读回.has_value()`；
2. `读回.后状态` 的场景、主体、特征、特征值、来源存在逐字段等于 `请求.后状态`；状态节点见证完整且节点类型为状态；
3. 五条关系均为关系19、角色1—5恰一，源端均为后状态节点，目标端依次匹配请求的主体、场景、特征、特征值、来源存在；
4. 发生时间类型合同/版本、值记录身份/版本、来源和发布代次完整，材料U64等于 `请求.后状态.发生时间戳`，来源等于请求来源存在；
5. 可选迁移动能为空时合法；非空时只能为 `状态迁移`，场景/主体/后状态与后状态事实一致，前状态完整且不同于后状态，来源动作、来源低层动态和同源迁移动能及对应关系均为空，动态时间等于后状态时间，聚合规则版本为0。

满足时统一结果为：状态沿用 provider；发布代次/持久状态原样；`目标=读回.后状态.状态`；旧关系/新关系空；`操作读回=世界树状态动态读回` variant；缺项空。

任一成功不变量失败返回 `内部不一致`，保留 provider 的代次和持久状态，目标、关系、操作读回和缺项全部清空；不二次查询、不补写、不更改已发布 provider 结果。

## 6. 原子性、幂等和失败边界

门面不是第二事务控制器。幂等先探测、请求/执行双摘要、候选登记、原许可读回、确认、逆序撤销、最后发布、代次推进、持久见证和隔离全部由 P1B-W0/L1 负责。

同键同义门面只映射 provider 原 `幂等读回`、原代次、原持久状态和原读回；同键异义映射幂等冲突。门面不因 provider 变化重算，不把未实现改成基准成功，不在失败后补写，也不用普通快照证明原提交。

## 7. 诊断与异常

provider 根为 `noexcept`，门面不得增加 try/catch 来掩盖合同漂移。provider 已分类的非成功只映射，不重复记录。

防御标识只用于自检和源码闭包：

```text
P1C-SDW-E01 = provider未知状态
P1C-SDW-E02 = 成功状态但零代次、非空缺项或空读回
P1C-SDW-E03 = 成功读回后状态/关系/时间与请求矛盾
P1C-SDW-E04 = 可选迁移动能形状或端点矛盾
```

门面自发现 E01—E04 固定结构化返回内部不一致，日志调用边0。`服务.世界树.ixx` 不得新增日志 include、模块、宏、包装器或辅助日志函数；最终运行期逻辑错误日志责任留给 P1D 正式消费者入口。E02 在 E03/E04 前判断，E03 在 E04 前判断。
