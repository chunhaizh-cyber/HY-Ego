## 3. 精确公开合同

全部新增声明位于`领域/概念_存在类.h`，定义位于同基本名cpp；不新增文件、不改工程或装配。新类型位于现`正式结构概念保护结果`附近：

struct 正式结构有效内容项 final {

struct 正式结构有效约束 final {
    稳定编码 约束概念节点;
    结构约束定义 定义;

    friend bool operator==(const 正式结构有效约束&,

## 4. 有效内容的精确语义

1. 只展开请求C的**结构上位继承闭包**，合并直接内容项；内容项的范围C1和读取路径作为定义引用返回，不递归把C1的内容摊平，不枚举下位，不选择分支，不读取实例。
2. 必须复用当前`核正式结构图`的合并/收窄判定：同FT合并、路径冲突拒绝、范围比较取可证明更窄者、不可比较冲突拒绝、子类收窄只允许收窄已有项。不得新增区间交集规则、改变原有可判定范围或允许已有核验拒绝的定义。
3. 返回每FT恰一条有效内容项。其范围是最终生效范围，读取路径保留选中有效项的正式路径，不补路径，不将空路径解释为任意底层字段访问。
4. 原`结构概念内容项.序号`是声明内局部序号，多父同号合法。新DTO故意没有序号：内容项按FT稳定身份升序组织，**仅为确定的传输组织，不表达业务先后、优先级或AND顺序**。不能以FT编码大小推断任何语义。
5. 约束收集请求C及其全部结构上位在`约束概念组`中显式声明的约束，按约束节点身份去重。每条返回当前`结构约束定义`全文，`声明结构概念组`记录实际声明它的所有结构概念身份，去重后升序。菱形继承不重复约束，也不丢实际多声明来源。约束组按约束身份升序，仅确定传输组织。
6. 上位约束不能因子类未重复声明而丢弃。保留不同约束身份，即使定义相同也不擅自合并；不化简、不推导、不执行、不选择满足结果。禁止项目等约束继续沿旧定义合法性语义，不因被禁止FT不在内容项内而删掉约束。
7. 下位概念、范围概念或内容引用图上其它结构的约束，不属于C的继承约束，不能混入C输出。结构分类环仍工程故障；内容引用递归按现捕获规则处理，不无限展开，不把visited当实例符合。
8. 同分支必要项将来如何AND、目标形式未知时如何取得分支、关联约束如何用于实例判断，都是后继消费者职责。此入口只返回定义，不把所有已知子类或互斥分支拼为AND。

## 5. 唯一内部实现链与保护

在现cpp匿名命名空间提取内部结果，不公开私有helper：

```text
请求C
→ schema/身份检查
→ 调用期上下文捕获并解码正式定义及必要引用
→ 核正式结构图生成同一份内部有效项与继承约束结果
→ 补齐现有FT正式身份保护
→ 以完整保护组执行现末尾联合重核
→ 成功后按值交付C的有效内容与同批保护
```

内部`核正式结构图`改为返回私有核验/展开结果，至少包含按结构概念索引的原有效项目图，以及有效约束和实际声明来源；原定义批准备调用可丢弃返回值，但核验覆盖范围及拒绝条件不变。有效约束在同一结构继承遍历中累积，按身份合并来源，不另建第二套继承遍历算法。

将现`读取正式结构概念保护`的捕获、解码、完整图核验、跨FT保护及末尾联合重核提取为cpp私有共享工作读取函数，返回原正式信息、同批保护和内部展开结果。旧公开读口只投影原结果；新读口只投影新结果。共享函数不吞异常、不写结构；不先调旧公开读口后独立重读一套定义再拼结果，不用第二套解码/范围包含算法。

共享工作函数所需的特征概念owner从成员显式传入；不新增长期全局指针、缓存、跨服务注册或装配入口。辅助结果只在一次调用内存续。新公开入口必须在同一工作读取中区分已找到的基础/约束/成员组织定义（非信息结构），不能将其当空信息结构。

保护沿原正式读取完整语义范围：C、必要结构祖先、全部生效及校验所需内容范围、约束及路径引用、其正式定义/组织材料、现跨FT身份保护均纳入同批保护；不能只保护最终FT而漏祖先收窄或约束记录。保持现读口的完整闭包范围，不为性能裁剪必要范围，也不因新增接口扩张为扫描整个概念图。

无新增持久写入或发布事务，无幂等账，无引用占有或删除许可。末尾保护联合读回是本次一致性确认点；成功返回只是当时成立的定义值副本，不保证未来永久不变。后续长操作须重读或把同组保护并入其正式事务预期。本叶不承诺跨请求快照，也不自动重试掩盖竞争。

## 6. 非成功与工程边界

| 条件 | 结果 |
| --- | --- |
| 编码无效 | 输入不合法，零载荷 |
| 正式schema未就绪 | 依赖未就绪，不隐式初始化 |
| 节点已不存在，或不是本owner正式定义 | 未找到；普通存在概念不由本入口展开 |
| 合法正式定义是基础/约束/成员组织而非信息结构 | 非信息结构，不改成空结构 |
| 捕获重复节点快照不一致或末尾联合保护变化 | 前提已变化，零载荷；不把新旧两套拼起来 |
| 本边界可捕获的内存分配失败 | 资源失败，零载荷，明确是工程控制状态，不是业务否定或子需求 |
| 已声明正式依赖损坏、分类环、路径/范围冲突、非法收窄、约束形状坏、L1结构读取错误 | 沿现`正式定义故障`→具名日志/弹窗/终止；不返回空、未找到、false或学习材料 |

新公开noexcept入口按上述顺序分别处理正常状态、可捕获`std::bad_alloc`及其它工程异常；内部helper向上送出。旧公开入口保持原异常映射；下级既有正式边界主动工程终止不改写为本入口正常返回。不得为加新接口顺便将工程链批量改成状态或吞掉旧错误。

只读时不持概念owner互斥回调FT owner；沿当前读取器及L1组合查询保护方式，不新增锁序、长期租约或资源预算。合法缺定义与损坏的正式依赖区分；工程故障不伪装成未来需要补齐的业务条件。
