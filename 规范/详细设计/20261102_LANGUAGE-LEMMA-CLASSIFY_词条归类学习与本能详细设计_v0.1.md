# 词条归类学习与本能详细设计

身份：`LANGUAGE-LEMMA-CLASSIFY`。版本：v0.10。日期：2026-11-10（Asia/Shanghai）。

性质：经用户（经 claude管理员）确认的自然语言学习设计施工包。**只修订规范与详细设计，本文件不授权改生产代码**。代码起点仍为既有 main；归类询问／写回施工仍须另起具名叶。**未登记片段建词条**已另起具名叶 LANGUAGE-LEMMA-CREATE-FROM-FRAGMENT，不得并回本文件只读归类合同，也不得在 `读取缺口` 内写词条。

## 1. 总原则（已确认）

### 0. 未登记片段与纯读取缺口（20261103）

归类目标槽仍为**正式词条身份**，纯读取缺口不写词条。在缺口之外按[7250第3.3.1节](../7250_子规范_最小汉语知识与语言学习.md#331-未知词面显式准入与归类衔接)及[LANGUAGE-LEMMA-CREATE-FROM-FRAGMENT v0.3](20261103_LANGUAGE-LEMMA-CREATE-FROM-FRAGMENT_未登记片段建立词条详细设计_v0.1.md)先确认候选的词边界与规范化材料，再经词条owner建立或取得、正式读回并重新解释／读取缺口。无法确认边界时先询问分界，以固定原文及范围为问题对象，不伪造词条；这不是本文件的词条概念归类。功能词与代词可登记词条但不送归类；本次用法未决不能默认为普通内容词。登记不自动创建概念或名称关系；不新增“待归类”词条状态。

1. **不设独立自然语言学习模块或线程**。学习在理解服务对象原话的过程中自然完成。
2. 学到的信息写入**语言知识模块**，不直接写入自我内部世界。
3. 「获取服务对象需求信息」必要条件「必需字段有确定值」中，对**普通词条**，**确定值**＝字段中的词条已有对应的**概念信息节点**。不新增前提条件；新词条对不上概念节点，即该条件不满足。**代词例外见 §1.1**：有名称关系不等于确定值。
4. 走条件分解：通用筹办在「获取服务对象需求信息」下提出**归类子需求**（每个待归类普通内容词条一条；功能词、代词除外），与**补问子需求**同级，均为完整需求；经自我确认后进入任务链。
5. 服务对象不回答或离线时：等待，或用其它方法满足该需求——与其它需求相同处理。


## 1.1 代词例外（20261102）

**代词词条不建归类子需求。** 「我／你／他／她／它／这／那／谁／什么」等代词用法即使已有概念名称关系，也不使「必需字段有确定值」成立；须走指代消解，落到自然语言场景中的目标信息节点。未决时由通用筹办提**指代澄清补问子需求**，与归类／字段补问同级。详见 [LANGUAGE-PRONOUN-RESOLUTION](20261102_LANGUAGE-PRONOUN-RESOLUTION_代词指代消解与澄清详细设计_v0.1.md) 与 5170 代词口径。功能词仍不进概念树（既有条款不变）。
## 2. 归类子需求正式目标形状

归类子需求是**完整需求**，但属于**词条归类专属种类**，不走普通「目标存在 + 目标特征类型 + 特征值当前值」合同（见 3100／5170 专属例外）。目标形状固定如下：

| 槽 | 固定含义 |
| --- | --- |
| 需求种类 | **词条归类**（与普通值目标／方向目标需求分种；不得冒充普通存在目标） |
| 目标词条 | 待归类**正式词条身份**（`L2词条身份`；重复出现整理为同一词条；见 §7）。**不是**世界存在节点，身份不转换 |
| 满足条件 | 该词条已通过**概念名称关系**挂到至少一个位于存在／特征／动态根树下的正式概念节点（四本体根另含因果链根，归类不挂入） |
| 目标形式 | 本种类不适用普通值域／方向载荷；满足与否只由名称关系求值合同裁决 |
| 完整键 | `种类(=词条归类) + 目标词条`（查重／列表；与普通键空间分离） |

### 2.1 词条专属目标与关系求值合同

> 20261110（20261110用户裁决R109：以最新代码为准，代码未实现者以规范为准）：代码无需求种类字段，本节“专属目标／种类＋词条键”口径已由R15统一需求形状替代：目标信息节点＝词条，目标特征＝“概念名称挂接”F（《需求治理详细合同》第2.2节）。fresh读取名称关系的满足判定仍有效。

1. **目标就是词条。** 建立／复用归类需求时，目标槽保存正式词条身份；不得把词条伪装成普通存在，不得为此新建虚拟存在或布尔镜像特征。
2. **满足条件。** 「已满足」当且仅当：对目标词条，经概念名称关系公开服务 **fresh 当前读回**，至少存在一条当前名称关系，其概念端点是已发布概念，且该概念位于存在／特征／动态三类根树之一（可追溯至所属全局根）。零条、仅历史退出、概念端点缺失／退役、或只挂到因果链根，均不得判已满足。
3. **每次判定重新读取。** 准入后的满足复核、任务筹办／承接前后的复核，都必须重新调用名称关系读回；不得用需求建立时的快照、缓存候选、写回回执或上次布尔结果代替当前关系事实。
4. **求值边界。** 本求值只读词条身份、名称关系与概念公开读回；不定位世界实例特征，不读取特征值当前值，不走 3100 §6／5170 §4 的普通共同定位。比较关系／值域字段对本种类不适用；实现不得把「有无名称关系」编码成伪 I64 或伪特征当前值再套普通值目标。
5. **完整键与查重。** 列表／精确查重完整键为`种类(=词条归类) + 目标词条`；与普通`种类+目标存在+FT+形式+载荷`分键。同词条同种类同父同来源复用，不得因编码巧合并入普通存在键。
6. **种类标记。** 需求信息与列表项携带种类=`词条归类`；公开查询可按目标词条检索。旧「查询目标存在需求」等普通接口保持原语义，不返回本种类节点冒充存在目标。
7. **归属与生命周期。** 需求节点仍由需求 owner 建立／复用／权重／失活；词条仍归词条 owner；名称关系仍归名称关系 owner；概念仍归概念 owner。需求失活／退出**不**删除词条、不退出名称关系、不退役概念。词条或名称关系侧的真实退出／变更，只通过下一次 fresh 复核反映为未满足或结构非成功。
8. **与「确定值」的衔接。** 满足后，父方法「获取服务对象需求信息」按 §5.3 fresh 重读名称关系／字段时，该词条不再使「确定值」条件失败。未满足时继续归类子需求／询问路径。

**向上抽象与终止**：学习时沿概念上位**逐级向上抽象**；**到达存在／特征／动态所属全局根为止**（根不为词条，到达全局根即停；不以因果链根为终点）。不得环问。

每个新词条一条归类子需求；不得把多个无关新词条捆成一条目标，也不得把归类子需求写成方法学习需求或自我内部世界写入。功能词不进概念树，不为其建立归类子需求挂根。

## 3. 归类方式

1. **按词条在已知句式中的位置归类**。已知构式中该位置的成分类型约束，用于提出候选概念类型与候选句式。
2. **整句都未知**时：用句中**已知词条**生成**候选句式**；候选句式的成分类型亦为未知，不得臆造已确认类型。
3. 归类询问与写回采用种子构式第一对（见 §6）；「X有什么？/X有Z」「X能做什么？/X能W」本设计不用于归类主路径。

## 4. 新本能：询问词条归类

写法对齐 [DEMAND-FIELD-QUESTION](20261030_DEMAND-FIELD-QUESTION_通用字段询问与本能详细设计_v0.1.md)「询问指定需求字段」：想/做分离；产出正式表达需求与候选话语；发送判断后再入列；自我不直接执行本能。

### 4.1 方法头与规格（概念层）

| 项 | 内容 |
| --- | --- |
| 名称 | 询问词条归类 |
| 语义输入 | 一个或多个待归类词条信息节点；交互上下文（说话者/受询者/外设窗口/输出队列）同字段询问五参分账口径 |
| 直接产物 | 正式**表达需求**对象（语言模块生成候选话语）；**不是**已入列消息 |
| 问句形状 | 「X是什么？」；多个词条可合成一句，如「帮、倒、水分别是什么？」 |
| 不做 | 不等待回复、不写语言知识、不写需求字段、不入列 |

### 4.2 结果

| 状态 | 含义 |
| --- | --- |
| 已生成且唯一回读 | 候选话语经独立回读一致 |
| 缺知识 / 缺名称 / 缺指称 / 多义 / 范围未支持 / 前提已变化 | 与字段询问同族分账；零入列 |

## 5. 新本能：词条归类写回

| 项 | 内容 |
| --- | --- |
| 名称 | 词条归类写回 |
| 条件 | 已收到服务对象回答；按「X是一种Y」可理解；Y 可定位为已有概念（或可继续追问的词条）；对应归类子需求仍有效 |
| 理解合同 | 固定把回答按「X是一种Y」解析；Y 为概念类型 |
| 写入（概念侧） | 在 **Y 下新建概念身份**；类别取 Y 所在的类（存在／特征／动态之一）；用**概念名称关系**连接词条 X 与该新概念 |
| 写入（语言侧） | **语言知识模块**：固定词条类型；采用（或确认）候选句式；重复词条/句子整理为同一信息节点 |
| 定义状态 | 「有什么」「能做什么」等定义**待补**；该新概念以「**类型已知、定义未知**」为**专属合同**（见 7250 §2.5），不得假称定义已齐 |
| 不做 | 不直接写自我内部世界；不废弃原句；不自证父字段已齐全；不把功能词挂入概念树 |

### 5.1 写回后原句处理

写回后**原句不作废**。自我用已理解信息**重新组织原句**，并**咨询服务对象确认**。确认本身不替代 §5.3 的写后读回与父方法 fresh 重读；惟有名称关系当前挂接使「确定值」成立后，父方法才继续。

### 5.2 回答中的新词与循环／终止

若回答再出现新词条：继续提出归类子需求 / 询问，直至自己理解，或**抽象到达存在／特征／动态所属全局根**（根不为词条，到达全局根即停；不以因果链根为终点），或检测到未前进的循环。不得越过根继续追问。

### 5.3 写回成功后的重读顺序与失败处理（对齐普通写回惯例）

顺序固定如下，不得跳步或用回执冒充读回：

1. **正式写入**：概念 owner 在 Y 下发布新概念；名称关系 owner 发布词条 X→该概念的当前名称关系；语言知识侧固定词条类型／句式。各 owner 边界内组合变化；任一步写入非成功则整次写回非成功，不宣称概念或名称关系已建立。
2. **写后 fresh 读回互证**：对刚发布的概念身份与名称关系做公开服务当前读回；读回与写入声明不一致、端点缺失或资源失败 → 结构化非成功。**已发布事实保留**，不得伪报回滚；按原来源复用重试，不另造平行概念／关系。
3. **父方法重读确定值**：写回本能成功**只**证明本步语言／名称关系写入及读回互证通过，**不**宣称父字段已齐全、也不直接改父需求满足态。父方法「获取服务对象需求信息」须从参数场景／正式字段**重新读取**，并按 §2.1 fresh 判定名称关系是否使「确定值」成立；不得用写回回执、缓存布尔或上次满足结果代替。
4. **原句重述确认**：按 §5.1 重组织原句并咨询服务对象；确认失败或离线按普通需求等待／其它方法，不撤销已成功的名称关系事实。
5. **失败分账**：写入前拒绝 → 零新概念／零新名称关系；写入成功但读回失败 → 保留事实＋结构化非成功＋来源复用重试；读回成功但确定值仍不成立（例如挂到错误根、关系已退出） → 归类子需求未满足，继续询问／写回路径；技术非成功不得改写为需求失活或任务失败。

## 6. 种子构式三对（归类只用第一对）

| 对 | 询问 | 陈述写回 |
| --- | --- | --- |
| 1（归类主路径） | X是什么？ | X是一种Y |
| 2 | X有什么？ | X有Z |
| 3 | X能做什么？ | X能W |

## 7. 信息节点去重

可复用词条按语言＋规范化合同＋规范化词面复用**同一词条身份**；不因不同消息来源再建词条，也不覆盖原创建来源。归类子需求、询问与写回继续以正式词条为目标。每次词出现仍保留原文范围、顺序及来源；句子及解析按其固定材料／来源合同处理，不能仅因文字相同就合并不同出现或改写历史解析。词条复用不自动裁决本次唯一概念含义。

## 8. 字段补问写回本能（补缺）

字段询问侧此前只闭合「询问」；现补**写回本能**。**正式名称：需求字段回答写回**（已确认，不得另起别名冒充正式名）。

| 项 | 内容 |
| --- | --- |
| 名称 | **需求字段回答写回** |
| 方法头 | 对齐「询问指定需求字段」五参分账：定位 Q（D＋正式路径）、执行主体、受询者、外设窗口、输出队列相关只读核验；另接收已解析的回答载荷 |
| 条件 | 对应补问子需求有效；回答已按该字段正式路径解析为合法值式材料；D 仍为当前待写目标 |
| 结果 | 经需求/特征正式 writer 写回指定字段；成功只证明该字段本次写入；不宣称整份 D 已完整、不等待下一轮 |

详细参数表与 DEMAND-FIELD-QUESTION 同包维护。

## 9. 与条件子需求消息闭环的关系

[TASK-SUBDEMAND-MESSAGE-LOOP](20261010_TASK-SUBDEMAND-MESSAGE-LOOP_条件子需求消息闭环详细设计_v0.1.md) 原范围仅普通 I64 特征明确值域。本设计要求扩展支持范围：

- 保留原 I64 值域条件项与其结构，**不动**；
- **另立**与 I64 平行的消息种类「词条归类」：目标形状见 §2；提议→self 确认→需求 owner 建立/复用→任务承接的闭环同构，但载荷种类分离，不得塞进 I64 区间字段；
- 非 I64 且非本归类种类的条件仍返回「暂不支持」，零新 D。

归类子需求由「获取服务对象需求信息」路径的通用筹办提出，与补问子需求同级；不得把归类写成待完善被认知需求本身入链。

## 10. 验证边界（规范层）

至少区分：新词条无概念节点→归类子需求；已知位置归类 vs 整句未知候选句式；多词条合成询问；写回后原句重述确认；回答含新词继续追问；循环检测；离线/不答等待或其它方法；语言知识写入 vs 内部世界不写入；与补问子需求并行不互相吞并。

本文件不证明代码、初始化种子或运行闭环已实现。
