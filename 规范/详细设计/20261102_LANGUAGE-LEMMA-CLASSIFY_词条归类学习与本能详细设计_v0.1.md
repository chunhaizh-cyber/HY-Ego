# 词条归类学习与本能详细设计

身份：`LANGUAGE-LEMMA-CLASSIFY`。版本：v0.1。日期：2026-11-02（Asia/Shanghai）。

性质：经用户（经 claude管理员）确认的自然语言学习设计施工包。**只修订规范与详细设计，本文件不授权改生产代码**。代码起点仍为既有 main；施工须另起具名叶计划。

权威依据：[2340](../2340_根规范_自然语言知识.md)、[5170](../5170_子规范_需求治理详细合同.md)、[5260](../5260_子规范_任务治理详细合同.md)、[7220](../7220_子规范_概念多语种表达与自然语言接入.md)、[7240](../7240_子规范_自然语言双向转换与组织规则.md)、[7250](../7250_子规范_最小汉语知识与语言学习.md)、[DEMAND-FIELD-QUESTION](20261030_DEMAND-FIELD-QUESTION_通用字段询问与本能详细设计_v0.1.md)、[TASK-SUBDEMAND-MESSAGE-LOOP](20261010_TASK-SUBDEMAND-MESSAGE-LOOP_条件子需求消息闭环详细设计_v0.1.md)。

## 1. 总原则（已确认）

1. **不设独立自然语言学习模块或线程**。学习在理解服务对象原话的过程中自然完成。
2. 学到的信息写入**语言知识模块**，不直接写入自我内部世界。
3. 「获取服务对象需求信息」必要条件「必需字段有确定值」中，**确定值**＝字段中的词条已有对应的**概念信息节点**。不新增前提条件；新词条对不上概念节点，即该条件不满足。
4. 走条件分解：通用筹办在「获取服务对象需求信息」下提出**归类子需求**（每个新词条一条），与**补问子需求**同级，均为完整需求；经自我确认后进入任务链。
5. 服务对象不回答或离线时：等待，或用其它方法满足该需求——与其它需求相同处理。

## 2. 归类子需求正式目标形状

归类子需求是完整需求，目标形状固定如下（与 5170 值目标合同一致，不另造需求字段类）：

| 槽 | 固定含义 |
| --- | --- |
| 目标存在 | 待归类**词条信息节点**（重复出现的同一词条整理为同一信息节点；见 §7） |
| 目标特征类型 | 语言知识侧「词条—概念对应」所依的正式特征类型（词条类型/概念归属；由语言结构 owner 读回，不新增 ARCH 需求字段类） |
| 目标形式 | 值目标 |
| 目标值域 | 「已对应到至少一个正式**概念信息节点**」的合法值域（概念节点非空） |
| 比较关系 | 按既有值目标合同表达「落入该值域 / 已建立对应」 |

满足判定：对该词条信息节点，语言知识可读到与之绑定的概念信息节点。满足后，父方法「获取服务对象需求信息」重读字段时，该词条不再使「确定值」条件失败。

每个新词条一条归类子需求；不得把多个无关新词条捆成一条目标，也不得把归类子需求写成方法学习需求或自我内部世界写入。

## 3. 归类方式

1. **按词条在已知句式中的位置归类**。已知构式中该位置的成分类型约束，用于提出候选概念类型与候选句式。
2. **整句都未知**时：用句中**已知词条**生成**候选句式**；候选句式的成分类型亦为未知，不得臆造已确认类型。
3. 归类询问与写回采用种子构式第一对（见 §6）；「X有什么？/X有Z」「X能做什么？/X能W」本设计不用于归类主路径。

## 4. 新本能：询问词条归类

写法对齐 [DEMAND-FIELD-QUESTION](20261030_DEMAND-FIELD-QUESTION_通用字段询问与本能详细设计_v0.1.md)「询问指定需求字段」：想/做分离；产出正式表达需求与候选话语；发送判断后再入列；自我不直接执行本能。

### 4.1 方法头与规格（概念层）

| 项 | 内容 |
| --- | --- |
| 名称 | 询问词条归类 |
| 语义输入 | 一个或多个待归类词条信息节点；交互上下文（说话者/受询者/外设窗口/输出队列）同字段询问五参分账口径 |
| 直接产物 | 正式**表达需求**对象（语言模块生成候选话语）；**不是**已入列消息 |
| 问句形状 | 「X是什么？」；多个词条可合成一句，如「帮、倒、水分别是什么？」 |
| 不做 | 不等待回复、不写语言知识、不写需求字段、不入列 |

### 4.2 结果

| 状态 | 含义 |
| --- | --- |
| 已生成且唯一回读 | 候选话语经独立回读一致 |
| 缺知识 / 缺名称 / 缺指称 / 多义 / 范围未支持 / 前提已变化 | 与字段询问同族分账；零入列 |

## 5. 新本能：词条归类写回

| 项 | 内容 |
| --- | --- |
| 名称 | 词条归类写回 |
| 条件 | 已收到服务对象回答；按「X是一种Y」可理解；Y 可定位为概念类型（或可继续追问的词条）；对应归类子需求仍有效 |
| 理解合同 | 固定把回答按「X是一种Y」解析；Y 为概念类型 |
| 写入 | **语言知识模块**：固定词条类型；采用（或确认）候选句式；重复词条/句子整理为同一信息节点 |
| 不做 | 不直接写自我内部世界；不废弃原句；不自证父字段已齐全 |

### 5.1 写回后原句处理

写回后**原句不作废**。自我用已理解信息**重新组织原句**，并**咨询服务对象确认**。确认后，字段词条具备概念节点对应，「确定值」条件满足，父方法继续。

### 5.2 回答中的新词与循环

若回答再出现新词条：继续提出归类子需求 / 询问，直至自己理解或**检测到循环**。理论上最终归到概念根类型。循环检测：同一词条归类链上重复出现未前进的类型请求时停止该链并保留缺口，不得死循环提问。

## 6. 种子构式三对（归类只用第一对）

| 对 | 询问 | 陈述写回 |
| --- | --- | --- |
| 1（归类主路径） | X是什么？ | X是一种Y |
| 2 | X有什么？ | X有Z |
| 3 | X能做什么？ | X能W |

初始化与 7250 / INIT-LANGUAGE-KNOWLEDGE-SEEDS 同步登记这三对；本设计归类路径只消费第一对。

## 7. 信息节点去重

重复出现的词条或句子整理为**同一信息节点**。归类子需求、询问与写回均以该节点为身份，不得因同词再出现另建平行概念绑定。

## 8. 字段补问写回本能（补缺）

字段询问侧此前只闭合「询问」；现补**写回本能**：

| 项 | 内容 |
| --- | --- |
| 名称 | 需求字段回答写回 |
| 方法头 | 对齐「询问指定需求字段」五参分账：定位 Q（D＋正式路径）、执行主体、受询者、外设窗口、输出队列相关只读核验；另接收已解析的回答载荷 |
| 条件 | 对应补问子需求有效；回答已按该字段正式路径解析为合法值式材料；D 仍为当前待写目标 |
| 结果 | 经需求/特征正式 writer 写回指定字段；成功只证明该字段本次写入；不宣称整份 D 已完整、不等待下一轮 |

详细参数表与 DEMAND-FIELD-QUESTION 同包维护。

## 9. 与条件子需求消息闭环的关系

[TASK-SUBDEMAND-MESSAGE-LOOP](20261010_TASK-SUBDEMAND-MESSAGE-LOOP_条件子需求消息闭环详细设计_v0.1.md) 原范围仅普通 I64 特征明确值域。本设计要求扩展支持范围：

- 保留原 I64 值域条件项；
- 新增**词条归类项**：目标形状见 §2；提议→self 确认→需求 owner 建立/复用→任务承接的消息闭环与 I64 项同构；
- 非 I64 且非本归类形状的条件仍返回「暂不支持」，零新 D。

归类子需求由「获取服务对象需求信息」路径的通用筹办提出，与补问子需求同级；不得把归类写成待完善被认知需求本身入链。

## 10. 验证边界（规范层）

至少区分：新词条无概念节点→归类子需求；已知位置归类 vs 整句未知候选句式；多词条合成询问；写回后原句重述确认；回答含新词继续追问；循环检测；离线/不答等待或其它方法；语言知识写入 vs 内部世界不写入；与补问子需求并行不互相吞并。

本文件不证明代码、初始化种子或运行闭环已实现。
