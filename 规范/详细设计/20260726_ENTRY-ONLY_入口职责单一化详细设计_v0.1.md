## 3. 模式解析与退出码

### 3.1 解析算法

1. `参数数量 < 1`：`参数数量无效`。
2. `参数组 == nullptr`：`参数数组为空`。
3. 从索引 1 顺序扫描。
4. `参数组[i] == nullptr`：`参数指针为空`，记录 `i`。
5. 精确匹配六个 flag；未知即拒绝。
6. 已见任一模式 flag：
   - 与当前字符串相同：`重复模式参数`；
   - 不同：`模式组合冲突`。
7. 未见 flag：普通控制面板。
8. 性能/D455 宏未启用：`构建能力未启用`。
9. 返回 `已接受` 和唯一模式。

解析不分配领域对象、不写日志、不输出文本。

### 3.2 完整矩阵

| 输入 | 模式 | 状态 | 退出码 |
| --- | --- | --- | --- |
| 无额外参数 | 普通控制面板 | 已接受 | 由运行结果 |
| 单一已知 flag | 对应模式 | 已接受或构建能力未启用 | 0/1 或 2 |
| 同 flag 两次 | 无 | 重复模式参数 | 2 |
| 两个不同 flag | 无 | 模式组合冲突 | 2 |
| 未知 flag | 无 | 未知参数 | 2 |
| null 参数指针 | 无 | 参数指针为空 | 2 |

`映射进程退出码`：

```text
解析失败 -> 2
解析成功且运行指针为空 -> 1
运行.成功() -> 0
其余 -> 1
```

## 4. `main` 的最终正文

目标正文只有下列语义：

```cpp
const auto 解析 = 海中鱼巣::解析并验证启动选项(参数数量, 参数组);
if (!解析.成功()) {
    return 海中鱼巣::映射进程退出码(解析, nullptr);
}
const auto 运行 = 海中鱼巣::运行海中鱼巣(解析.选项);
return 海中鱼巣::映射进程退出码(解析, &运行);
```

入口不使用匿名命名空间，不含辅助函数、lambda、计时器、宏分支、日志或领域头文件。

## 7. 系统初始化

`系统初始化请求` 保存上述方法根键和根需求参数；`有效()` 复用 `自我根需求初始化参数::有效()` 并拒绝零方法根键。

固定节点：

| 节点 | 类型 | 调用 | 结果绑定 |
| --- | --- | --- | --- |
| I01 | 被调函数 | `方法.初始化方法登记根(键, 状态)` | `结果.方法登记根` |
| I02 | 指令 | 若无值，返回方法登记根失败 | 无结构回退猜测 |
| I03 | 被调函数 | `自我线程实例.启动(根需求参数)` | 启动结果 |
| I04 | 指令 | 必须成功且非复用 | 否则自我线程启动失败 |
| I05 | 被调函数 | `等待初始化完成(10s)` | bool |
| I06 | 被调函数 | `读取初始化快照()` | `结果.自我初始化` |
| I07 | 指令 | 等待/快照失败返回初始化失败 | 上下文析构负责线程收口 |
| I08 | 被调函数 | `概念图初始化.初始化四个根()` | `结果.概念图` |
| I09 | 指令 | 四根不完整返回失败 | 追根因 |
| I10 | 被调函数 | `概念图.确保存在实例根支持(自我存在节点)` | `结果.自我存在根支持` |
| I11 | 指令 | 必须等于存在根 | 否则追根因 |
| I12 | 指令 | 填写 `已初始化` 并返回 | 无额外测试动作 |

重复启动、重复四根、别名、第二实例、删除和错误类型不在该函数。

## 8. 普通程序

`运行普通程序` 只接受普通控制面板或无窗口模式，否则内部不一致。

顺序：

1. F07 构造上下文；
2. F08 初始化系统；
3. F10 以 `最佳努力` 执行一次启动结构审计；
4. F12 安装停止信号；
5. 控制面板模式：F09 生成投影，再 F13 运行窗口；
6. 无窗口模式：不生成控制面板投影，直接 F14；
7. 返回宿主结构化结果。

F10 最佳努力失败不得改写最终成功状态；但审计结果仍传给控制面板用于人读显示。F12/F09/F13/F14 失败会使普通程序失败。

## 9. 控制面板只读投影

迁移现有 8 个投影函数并保留其算法：

```text
读取世界树节点名称角色
读取世界树节点显示语义
生成世界树节点显示名称
生成控制面板世界树节点材料
生成控制面板世界树结构材料
生成控制面板语素树结构材料
生成语素树显示节点材料
生成概念名称语素树显示节点材料
```

F09 是唯一公开顶层函数；F19-F26 全部是该模块私有具名函数并各有单函数图。它只读取上下文和初始化结果，返回现有 DTO；任何读回结构不一致返回 `投影失败`，不写业务结构。

## 10. 数据库审计

`数据库审计要求`：

```cpp
enum class 数据库审计要求 : std::uint8_t { 最佳努力, 必须往返一致 };
```

F10：

1. 定义结构统计缓存命名空间；
2. 读取权威结构统计快照；
3. 调用 SQL 写入；
4. 写入成功后读取最近 1 条；
5. 核对审计编号、节点数、关系数、索引数；
6. 返回完整 DTO。

最佳努力模式下 DTO 失败不影响普通程序；必须往返一致模式下 F11 将失败映射为 `审计失败`。日志不参与一致性 bool。

## 11. 运行宿主

### 11.1 停止信号租约

F12 安装 SIGINT、SIGTERM，Windows 下追加 SIGBREAK。处理器只把租约内 `volatile sig_atomic_t` 置 1。安装失败返回结构化状态。租约析构恢复原处理器；不在入口保存全局状态。

### 11.2 控制面板宿主

F13 在局部作用域依序构造：

1. `控制面板服务`，引用上下文并消费 F09 树材料、根需求句柄；
2. `控制面板窗口`，引用控制面板、数据库和 F10 快照；
3. 调用 `窗口.运行(&信号.停止请求)`；
4. 把窗口结果映射为程序运行结果。

窗口关闭前上下文、投影、审计、信号均存活。

### 11.3 无窗口宿主

F14 不构造投影、控制面板服务或窗口。循环仅等待停止信号，每 100ms `sleep_for`；收到信号后返回成功。人读提示仅可经普通运行日志，不使用 stdout。

## 12. 专项模式

### 12.1 生产运行期

F05 局部构造 `生产运行期会话` 和版本 1 请求，调用 C01。失败映射为生产运行期首发失败；成功返回完成。会话在结果映射完成前保持存活。该模式不构造普通应用上下文。

### 12.2 数据库专项

F11 依次调用 F07、F08、F10(`必须往返一致`)；不调用 F09、F12、F13、F14 或完整自检。严格往返一致才成功。

### 12.3 性能和 D455

F16/F17 只调用各自现有专项函数并映射其结构化 `总通过`。宏未启用已在 F02 拒绝。二者不调用普通初始化或 F15。

## 13. 14 个隔离自检

### 13.1 环境

F18 每次新建 `普通应用上下文`，但不执行 SQL、投影或宿主。调用方独占 `unique_ptr`，函数返回后完整析构。禁止 static 仓库、共享全局夹具或复用普通程序上下文。


固定编号为 `ENTRY-ONLY-S01` 至 `ENTRY-ONLY-S14`。不得把多个项重新压成一个 bool。

### 13.3 完整自检运行器

F15 用顺序 10、20、…、140 登记 S01-S14；任一登记失败返回自检失败。全部登记后调用 `自检运行器::运行全部()`，再由批次结果形成程序结果。普通失败不短路其它自检；异常由现有运行器捕获并计失败。
