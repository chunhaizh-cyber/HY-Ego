# 按来源读取当前因果组详细设计 v0.1

日期：2026-08-15

设计身份：`DATA-L2-CAUSAL-CURRENT-GROUP-READ-BY-SOURCE`

状态：设计就绪；不等于代码已实现

## 1. 目标与当前缺口

为唯一 `L2因果结构服务` 增加按来源稳定编码读取全部当前直接因果事实的强类型有界查询。调用方给出非零当前事实代次守卫、来源节点和因果数量预算；服务返回按因果身份稳定编码严格升序的完整当前因果组，全部因果及其条件状态组、可选动作、结果状态组、来源和生命周期共享同一事实截止。

当前因果服务已经实现新增、完整当前 / 历史读取、身份来源、按条件状态 / 动作 / 结果状态读取、引用替换、来源换代和退出。L1 已由结果提交 `8e0928671d3584d399ce4d796b890401073e5676` 发布 owner + 来源节点有界当前值组原子读取。缺口只是把该中性 L1 provider 收敛为因果强类型结果，不重新实现 CRUD，也不扫描全部因果。

## 2. 边界与所有权

本设计只补当前来源查询，不新增事实截止之外的第二时间语义，不建立间接因果、因果链、因果真实性、必然性、有用性、证据统计或业务筛选。本叶不改变因果新增、替换、换代、退出、历史读取或既有三条端点查询，不建立缓存、第二索引、分页游标、零守卫最新读取或业务专用来源类型。

来源保持不透明 `稳定编码`。服务只证明来源是当前 L1 节点且当前因果的唯一来源属性值引用该来源；不判断来源是否可信或属于哪种业务对象。

唯一结构所有者仍为 `L2因果结构服务`。来源发现只使用：

```text
L2因果结构服务私有因果 owner
+ L1事实基座服务::按来源读取所有者范围全部当前值
+ L2因果结构服务::读取完整因果
```

禁止直达 L1 仓库、扫描全部值 / 因果、跨 owner 列举、调用缓存或从名称和本地键猜因果。

## 3. 精确公共 ABI

### 3.1 请求 DTO

物理所有者：`海中鱼巣/领域/L2因果结构.数据.h`。

```cpp
struct L2按来源当前因果读取请求 final {
    L2结构请求头 请求头;
    稳定编码 来源稳定编码;
    std::uint64_t 最大数量 = 0;
    friend bool operator==(const L2按来源当前因果读取请求&,
        const L2按来源当前因果读取请求&) = default;
};

inline bool L2按来源当前因果读取请求有效(
    const L2按来源当前因果读取请求& 请求) noexcept;
```

有效条件逐字冻结为：请求头合同有效、`期望事实代次 != 0`、来源稳定编码非零、最大数量非零。`最大数量` 以最终因果对象数计数，不以 L1 值事实数计数。

结果复用既有 `L2当前因果组读取结果`。成功形状保持：`已读取`、非零事实截止、零变更代次、因果组按身份严格升序、全部因果当前且完整。空组成功。预算拒绝复用已经发布的 `L2结构状态::数量预算不足 = 15`，不再扩枚举。

物理所有者：`海中鱼巣/领域/服务.L2因果结构.ixx`。

```cpp
L2当前因果组读取结果 按来源读取全部当前因果(

```

该函数是因果服务唯一公开来源查询入口，不增加自由函数、聚合快捷入口或普通应用直达 L1 入口。

## 4. 原子读取过程

1. 请求无效时返回 `入口拒绝`、截止 0、空组。
2. 读取当前因果结构类型登记；登记非成功按现行映射返回，空组。
3. 形成 `L1所有者范围来源当前值组读取请求`：owner 固定为因果服务私有 owner，来源与守卫逐字段取自请求。一个完整当前因果恰有一个来源属性值，L1 预算做饱和 `最大数量 + 1` 换算，多取至多一个因果只为区分公共预算超限。
4. 调用 `L1事实基座服务::按来源读取所有者范围全部当前值`，逐字段互证合同版本、owner、来源、期望 / 读取事实代次和非成功零载荷。
5. L1 成功后，每项值必须属于因果 owner、来源等于请求来源、当前生命周期完整、所属因果节点非零、属性类型恰等于登记的 `来源属性类型`，且独立材料引用编码等于来源。其它同 owner 值、同一因果多个当前来源值或坏材料均为 `内部不一致`。
6. 按所属因果节点排序，拒绝重复并保持严格升序。候选数不得超过 `最大数量 + 1`；L1 因更大原始集合返回预算不足时直接形成零载荷预算拒绝。
7. 对至多 `最大数量 + 1` 个候选以原非零守卫调用 `读取完整因果`。每项必须 `已读取`、截止等于 L1 截止、因果身份等于候选、来源等于请求、当前未退出，并通过 `L2因果事实完整`。明确漂移 / 资源失败沿用；其它失败和坏成功形状映射内部不一致。全部候选完整后，候选数超过公共预算才返回 `数量预算不足`。
8. 数量不超预算时返回 `已读取`、截止等于请求守卫、零变更代次和严格升序完整组。读取不推进事实代次。

全部 L1 调用和完整因果读回都使用同一非零守卫。并发发布使任一步不再处于该截止时返回事实代次漂移；禁止重试、拼接不同截止或返回部分组。

## 5. 状态映射

| 条件 | L2 结果状态 | 截止 | 因果组 |
| --- | --- | --- | --- |
| 坏合同、零守卫、零来源、零预算 | 入口拒绝 | 0 | 空 |
| 来源未找到 | 未找到 | L1 安全截止 | 空 |
| 来源已退出 | 已退出 | L1 安全截止 | 空 |
| 守卫漂移 | 事实代次漂移 | L1 当前截止 | 空 |
| L1 值预算或 L2 因果预算不足 | 数量预算不足 | L1 安全截止 | 空 |
| 分配 / 长度耗尽 | 资源失败 | 安全取得则保留，否则 0 | 空 |
| owner、来源属性、完整读回或同截止互证失败 | 内部不一致 | 安全取得则保留，否则 0 | 空 |
| 当前来源无因果 | 已读取 | 等于守卫 | 空 |
| 当前来源有 1—预算项因果 | 已读取 | 等于守卫 | 严格升序完整组 |

所有非成功结果的变更事实代次为空，因果组为空。读取接口没有幂等写语义。
