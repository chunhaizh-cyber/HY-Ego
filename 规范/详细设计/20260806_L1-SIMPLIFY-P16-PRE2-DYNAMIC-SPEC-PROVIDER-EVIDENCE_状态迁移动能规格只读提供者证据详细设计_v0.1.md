## 1. 裁决、目标与最大边界

P16 后继修订需要在非等价分支把 P14 状态迁移动能规格作为强类型执行证据材料交给 P15；P15 统一规范化证据、形成摘要和通用读回计划。当前 P14 公开结果只有 `状态 + 原因 + 规格`，没有稳定服务身份、直接调用计数、共同截止和完整写前事实凭证。P16 无权用默认 L1 身份、业务事实编码、快照首项、日志或私有登记地址补造这些材料。

本叶只扩展 P14 唯一动态事实/规格所有者，成功时原子回显：固定且版本化的 P14 提供者身份；直接调用次数1和去重提供者数量1；最终成功轮共同截止；P14 动态登记当前事实与 PRE1/P13 传递事实的强类型来源；排序去重后的写前事实身份、同索引完整 `L1事实副本` 及精确数量。

P13/PRE1 与 P14 是不同所有者。PRE1 只签发 P13 状态规格证据，P14 只消费其不可变成功结果，不让 P13/PRE1 拥有动态身份，也不修改 PRE1、P12、P15、P16。P14 已持有 `L1事实基座服务&`、动态登记副本和规格形成入口，因此无需改变其它独立所有者的公开结果即可闭合本叶。

本叶零 L1 写、零事实发布、零 P15/P16 调用；不涉及因果、生产装配、崩溃、重启、断电或跨进程恢复。

## 4. 固定提供者身份与生命周期

在 `L1动态.数据.h` 定义，在 `服务.L1动态.ixx` 提供无状态只读入口：

```cpp
inline constexpr std::uint32_t 状态迁移动能规格提供者证据合同版本 = 1;
inline constexpr std::uint32_t 状态迁移动能规格提供者证据规则版本 = 1;

struct 状态迁移动能规格提供者身份凭证 final {
    稳定编码 稳定身份{0x4C31445000000001ULL}; // ASCII L1DP + 序号1
    std::uint32_t 合同版本 = 状态迁移动能规格提供者证据合同版本;
    std::uint32_t 规则版本 = 状态迁移动能规格提供者证据规则版本;
};

状态迁移动能规格提供者身份凭证
读取状态迁移动能规格提供者身份() noexcept;
```

该值是公开软件服务合同身份，不是 L1 业务节点、动态登记服务节点、局部键或运行期分配结果。入口无参、只读、`noexcept`，不取锁、不读事实、不分配、不写日志；生命周期从合同版本进入同一生产程序开始，到该版本退出为止。进程内对象地址、线程和业务请求不改变身份。正式树中该值创建时占用0；执行前再次扫描，发生占用即停工，不临场换号。

enum class 状态迁移动能规格写前事实副本来源 : std::uint8_t {

struct 状态迁移动能规格提供者证据凭证 final {

    std::vector<状态迁移动能规格写前事实身份> 写前事实身份组;

## 6. 直接提供者与传递见证

P16 非等价分支对 P14 的一次公开调用只产生一个直接提供者见证：

```text
(0x4C31445000000001, 合同1, 规则1, 调用次数1)
```

故 P14 成功凭证固定 `直接调用次数=1`、`去重后提供者见证数量=1`。P13 结果由 P16 传入 P14，是本次 P14 调用的强类型前置材料，不是 P14 对 P13 的第二次调用；P14 不把 P13 身份登记为自身直接 provider。后继 P16 在非等价成功分支机械得到 P13、P14 两个不同直接 provider，各调用一次、去重数量各一；等价/无前状态分支不得调用 P14，也不得伪造 P14 凭证。

## 7. 共同截止、当前/历史边界与事实闭包

最终共同截止必须是同一非零值：

```text
P13状态规格截止
== PRE1凭证共同截止
== P14规格截止
== P14初次完整快照G0事实代次
== P14末次完整快照G1事实代次
```

成功流程只接受以下来源：

1. 复制 P14 私有 `登记_`，验证合同/规则和十项稳定身份完整；从 G0 当前节点组按身份逐项恰一读取服务身份、关系20类型及八个属性类型的完整 `节点事实`，来源为 `动态登记当前事实`。任一零命中、多命中或历史回退均为内部不一致。
2. PRE1 成功凭证必须身份、合同/规则、调用/数量、截止、身份组、完整副本组及数量一一互证。P14 不重读或重解释 P13 的事实：PRE1 的当前来源映射为 `P13传递当前事实`，P12 合法历史来源映射为 `P13传递历史事实`，完整副本逐字段原样传递。
3. 上述并集必须覆盖最终 `0x44` 写集中每个非本地端点、类型、来源以及决定写入内容的注册身份、单位、维度、分量角色、前后值事实。`0x44000001..0x4400000F` 与后状态本地键 `0x53000001` 都是本次写集局部键，不进入写前身份组。

身份按 `(种类稳定值, 稳定身份)` 严格升序。零身份、零截止、不同种类同身份、未去重重复、缺副本或写集引用缺见证均为内部不一致。同种类同身份若同时来自动态登记和 P13，必须完整副本逐字段相等后保留 `动态登记当前事实`；P13当前优先于P13历史，当前/历史副本不等即拒绝。不得用容器顺序决定结果。

末次读取 G1 后要求 `G1==G0==共同截止`。`身份组.size()==副本组.size()==去重后写前事实见证数量` 且成功时数量大于0。具体数量由真实身份相等关系机械决定；专项夹具断言其固定事实图的精确值，不在合同中硬编码总数。

## 8. 根函数机械流程

唯一根保持：

```cpp
状态迁移动能规格结果 L1动态服务::形成状态迁移动能规格(
    const 实际存在I64后继状态规格结果& 后继状态) const;
```

机械顺序：

1. 沿既有规则映射无前状态和上游非成功；只在 P13 `已形成` 时继续。
2. 要求状态规格、迁移证据和 PRE1 提供者证据三项同时存在并逐字段互证。
3. 复制 P14 登记，读取 G0，校验共同截止和十项登记当前完整事实。
4. 保留既有比较、角色、时间、差异和动态准入检查，形成原 `0x44` 规格。
5. 合并动态登记当前副本与 PRE1 传递副本，覆盖写集引用，排序去重并绑定同索引完整副本。
6. 读取 G1，互证全部截止、组长和数量；一次返回规格与 P14 提供者证据。

任一证据失败都返回 `内部不一致` 和全空载荷，不能保留“规格成功、证据缺失”的半成功。`std::bad_alloc` 仍映射资源失败。

## 9. 非成功、漂移与并发

- `无需形成/禁止形成/登记未加载/入口拒绝/未找到/幂等冲突/许可拒绝/资源失败`：沿既有状态和原因返回，规格与证据均空。
- 上游或凭证半结构、身份/版本错误、截止不等、来源越权、当前/历史冲突、覆盖/排序/数量错误：内部不一致，全空。
- `G1!=G0`：版本漂移，全空；本叶不新增 sleep、等待、阻塞重试或跨 provider 锁。
- 函数仍零写；动态登记复制只持有现有 P14 短锁，L1 快照读取不在该锁内执行。

## 10. P16 机械消费边界

后继 P16 只在幂等探测未找到、P13 非等价成功后恰调用 P14 一次。P14 `已形成` 时机械检查固定身份、合同/规则、直接调用次数1、provider数量1、共同截止、登记、身份/副本一一对应、数量及规格截止，再把整个强类型凭证交给 P15 后继统一接口。

P16 不得自行哈希完整副本、补服务身份、重读 L1、重建来源、选择读回项目或把 P13 传递事实重复登记为直接 provider。P14 非成功不得伪装为“无需动态”；P13/P14 共同截止不等不得提交。
