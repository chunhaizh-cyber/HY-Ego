# ARCH-L4-TASK-VIRTUAL-EXISTENCE-LIFECYCLE-FOUNDATION 任务通用虚拟存在与生命周期状态基础闭环详细设计

版本：v0.2
状态：设计就绪候选；未取得代码实施许可
基线：`main@a1c76c515e558a0ae9c0a016847be755afd327c0`
计划身份：`ARCH-L4-TASK-VIRTUAL-EXISTENCE-LIFECYCLE-FOUNDATION`

## 1. 目标、前置和禁止扩展

本叶把真实任务轮次结算接入已发布的 ARCH-L2 通用虚拟存在及状态/动态原子发布 provider。任务优先于方法，因为任务实际结果、目标裁决和轮次结算已经有正式身份链；方法治理虚拟存在没有等价的状态迁移输入。

本叶只闭合：任务业务身份到通用 `L2存在身份` 的一对一承载、任务生命周期最小强类型特征、轮次结算后的第一次状态/动态原子发布，以及同一任务事实的正式读回。它不实现路径验证、目标裁决算法、任务完成、目标未达成待重筹办、下一轮筹办、需求满足/结算、价值回流、学习、现实执行授权或安全值/服务值计算。

`目标裁决`是本叶的已冻结上游值式输入；本叶不读取日志、方法返回值、退出码、适用范围编码或目标比较结果来重新解释业务。目标已达成只形成“待验证后完成”，目标未达成只进入“本轮已收束/等待自我后继决议”；不恢复旧的 `目标未达成待重筹办` 私有状态。

## 2. 权威链与职责分账

现行 ARCH 映射为 `ARCH-L4 任务 -> ARCH-L2 结构 -> ARCH-L1 事实`。ARCH-L2 仍只保存、校验和原子发布结构；它不判断目标达成、不判断任务完成，也不发放授权。L4 任务消费者解释已形成的轮次结算并申请结构迁移；自我线程只调用该 L4 入口，不裸写 L2。

| 事实 | 唯一 owner | 本叶处理 |
| --- | --- | --- |
| 任务、实例方法、执行轮次、正式实际结果、目标裁决、轮次结算记录 | L4 任务服务 | 读取现有公开事实；新增值式轮次结算消费者结果，不复制 L2 状态/动态 |
| 任务通用虚拟存在 | L2 通用虚拟存在结构服务 | 通过公开 `新增/读取完整/退出` 取得 `L2存在身份` |
| 任务当前状态、状态值、状态关系、动态及其历史 | L2 状态/动态服务与原子 provider | 通过 `发布状态动态原子迁移` 唯一发布；不由任务服务写第二状态 |
| 任务名称、需求满足、结算价值、学习 | 各自后继 owner | 不在本叶 |

## 3. 当前事实与复用裁决

当前 `L2任务结构` 已有任务实际结果事实：任务、实例方法、执行轮次、方法、动作入口、场景、主体 `L2存在身份`、实际状态、动态证据、来源材料版本和运行代次，适合作为轮次结算输入。`L2任务治理状态事实` 目前是任务服务独立持有的第二状态权威，并带有 `目标未达成待重筹办`；它只能作为迁移兼容历史，不能继续作为 ARCH-L2 当前状态。

当前 `L2通用虚拟存在结构服务` 已返回强类型 `L2存在身份`，但任务服务仍自建 `L2任务虚拟存在身份`。本叶新增通用身份引用并停止新写私有身份；既有私有身份保留历史读投影，直到另一个具名迁移计划完成删除/归档。

当前 `L2特征结构服务` 已提供：统一特征定义新增/完整读取、实例新增/完整读取、按存在读取当前实例、当前值新增/换代/读取和历史读取。值采用稳定值事实身份、类型化不可变材料与唯一当前槽；本叶复用这些入口，不引入裸枚举值或第二值仓。

当前 `L2状态动态原子发布服务::发布状态动态原子迁移` 已冻结单一 `G0 -> G1`、幂等、失败零发布和五组正式读回，但全仓无生产调用者。本叶是首个真实消费者；组件 v0.3 的执行计划在登记本叶时退出，不重复施工。

## 4. 任务业务身份到通用虚拟存在

### 4.1 稳定关系

每个活动 `L2任务身份` 恰有一个当前 `L2存在身份` 映射。映射由 L4 任务消费者持有业务引用，通用存在 owner 只保存 `ARCHL4宿主引用 = 任务身份稳定编码`。不扩大 L1 owner DTO，不把任务私有虚拟存在编码转换成通用存在编码。

首次建立顺序固定为：读取任务完整事实与当前共同截止 `G0` → 以任务身份作为幂等材料调用通用存在 `新增` → 以结果中的 `L2存在身份` 写入任务的通用身份引用 → 立即按同一请求截止读取通用存在完整事实 → 逐字段核对宿主引用、生命周期和身份。重复调用以同一幂等身份返回精确重复；不同任务或不同宿主引用返回幂等冲突并零写。

任务事实更新与通用存在新增不是同一 L1 原子写集；因此先成功建立存在、随后任务引用写入失败时，L4 必须用同一幂等身份读回收敛，不能再建第二存在。任务引用尚未写回时不得调用状态/动态 provider。该可恢复窗口是本叶显式未闭合的跨 owner 恢复边界，不能声称跨进程恢复已完成。

### 4.2 生命周期

通用存在在任务尚未完成本迁移时保持当前；本叶不退出任务存在。任务业务退出与通用存在退出由后继关闭计划处理。私有 `L2任务虚拟存在事实` 的历史读取继续按旧合同返回，但任何新状态/动态发布必须使用通用 `L2存在身份`。

## 5. 生命周期特征与值材料

本叶只建立一项最小公共特征：`任务生命周期阶段`，实际阶次为 1，宿主为任务通用 `L2存在身份`，一个唯一当前实例槽和不可变值历史。固定值语义来自 5200/5210，不新增状态机：

| 值稳定键（由本计划固定） | 语义 | 允许进入本叶的迁移 |
| --- | --- | --- |
| `ARCHL4-TASK-LIFECYCLE/ROUND-SETTLED-WAITING-SELF-SUCCESSOR` | 本轮已收束，等待自我后继决议 | 首次真实消费者后态 |
| `ARCHL4-TASK-LIFECYCLE/EXECUTION-RESULT-PENDING-VALIDATION` | 目标已达成后的待验证后完成状态，也可作为合法前态 | 目标已达成后的唯一后态；路径验证仍由后继独立提供者完成 |

实现将这些稳定键映射为特征定义/属性类型/值事实的固定非零稳定编码，并在创建侧验证无全仓冲突；执行者不得临场使用任务枚举、日志文本或私有治理状态代替。定义、实例和值均必须通过 L2 特征结构公开入口创建或精确重复读回：

1. `L2统一特征定义新增`（实际阶次 1，固定定义幂等身份）；
2. `L2特征实例新增`（宿主为任务通用存在，定义为上述定义）；
3. `L2特征当前值新增/换代`（类型化不可变材料为值稳定键的强类型材料，来源为本叶固定 owner 稳定编码）；
4. `读取完整特征实例` 与 `读取特征当前值` 取得唯一当前值及历史。

执行计划必须将定义/实例/值的请求 DTO、固定幂等身份、值材料、来源稳定编码、唯一当前槽和历史读回列入白名单；不得创建第二个“任务状态节点”或把枚举写入任务服务私有字段当作当前权威。

## 6. 首个真实消费者与调用合同

### 6.1 消费者 owner 和入口

新增唯一 L4 业务 owner：`L4任务轮次结算状态消费者`（物理模块 `领域/服务.L4任务轮次结算状态消费者.ixx`，DTO `领域/L4任务轮次结算状态消费者.数据.h`）。普通应用只装配一个实例并公开只读 getter；自我线程后继通过该 getter 调用，不直接取得 L2 写端口。

入口固定为：

```cpp
L4任务轮次结算状态结果 提交轮次结算并发布当前状态(
    const L4任务轮次结算状态请求& 请求) noexcept;
```

请求至少包含：请求/幂等身份、任务身份、任务实例方法身份、执行轮次、正式任务实际结果身份、已形成目标裁决证据身份、轮次结算记录身份、任务当前通用 `L2存在身份`、当前状态身份、共同事实截止 `G0`、目标裁决后继准备，以及安全硬否决事实（若有）。L4 业务层负责证明这些引用属于同一任务/轮次并且当前；L2 provider 只校验结构引用和截止。

### 6.2 固定调用顺序

```text
读取任务/实例方法/实际结果/目标裁决/轮次结算（同一 G0）
 -> 读取任务通用虚拟存在（当前）
 -> 读取任务生命周期特征实例和值（当前）
 -> 读取当前状态来源，确认前态唯一当前
 -> 形成后态值材料与动态时间材料
 -> 调用 L2 状态动态原子发布 provider 一次
 -> 按同一 G1 读回五组材料
 -> 形成 L4 值式结果并记录正式回执
```

目标已达成只允许得到 `待验证后完成`；目标未达成只允许得到 `本轮已收束/等待自我后继决议`。不得调用旧 `L2提交目标未达成待重筹办迁移`，不得自动新增任务、列表项或下一筹办轮次，也不写任务完成。

### 6.3 L2 原子请求映射

L4 只把已证明的结构材料映射到既有 `L2状态动态原子发布请求`：主体=任务通用 `L2存在身份`；旧当前状态=前态 `L2状态身份`；新状态特征实例=任务生命周期实例；精确/时间/动态起止材料=本轮结算批准的强类型材料；来源方法稳定编码=实例方法稳定编码。L2 不读取目标裁决、授权、安全或轮次语义。

## 7. 幂等、当前性、失败和历史

- 幂等键由任务身份、实例方法、执行轮次、正式实际结果、目标裁决、轮次结算和 `G0` 的固定摘要派生。相同摘要必须返回首次完整结果；任一字段异义返回 `幂等冲突`，零写。
- 所有前置读取必须带同一非零 `G0`；任一读取返回代次漂移、许可拒绝、未找到、已退出、引用冲突、资源失败或内部不一致，L4 返回具名非成功且零写，不重试猜测。
- L2 provider 成功只允许 `已提交/精确重复`，返回同一 `G1` 的新状态、新关系、新动态、新关系和旧状态退出投影；五组任一断言失败不得再次发布。
- 同义重试必须保留旧路径、旧实例、旧实际结果、旧目标裁决、旧轮次结算和旧状态历史；不得覆盖或删除历史。
- 失败零发布：L4 自己的结算回执可在其 owner 内按既有合同记录失败，但不得伪造 L2 状态成功。

## 8. 现有第二权威的迁移边界

本叶只停止 `L2任务治理状态事实` 作为**新轮次结算当前状态写入**，并停止新调用 `L2提交目标未达成待重筹办迁移`。旧状态事实、旧关系、旧 `L2任务虚拟存在身份` 和历史读取接口保留；现有筹办/目标裁决兼容路径仍可能读取它们，因此本叶不能宣称“第二权威已全部消除”。

本叶成功后的唯一当前状态见证是 L2 状态服务按任务通用存在和生命周期特征返回的状态；任务服务只能保存 L4 结算记录及迁移证据引用。把旧治理状态转换成新 L2 状态的完整历史投影、旧关系退出和删除，另立迁移计划。

## 9. 验证矩阵与完成边界

必须在 `D:\TEMP` 临时根完成 Debug/Release 专项并在根工程 fresh Rebuild：

1. 通用存在首次新增、精确重复、异义幂等、完整当前/历史读取和失败零写；
2. 任务特征定义/实例/值的固定身份、唯一当前槽、历史完整和主体关系互证；
3. 首次任务轮次结算消费者调用，L2 状态/动态 provider 恰一次，G1 五组生产读回全部通过；
4. 目标已达成只得到“待验证后完成”，目标未达成只得到“本轮已收束/等待自我后继决议”；两支均无旧待重筹办写入、无下一筹办轮次、无任务失败；
5. 同义重试返回原结果、异义冲突零写、G0 漂移零发布、任一 provider 非成功零载荷；
6. 旧私有治理状态和私有虚拟存在历史读回不被破坏，且新消费者不再写它们；
7. 想/看无需授权，本叶无现实执行授权请求，安全只硬否决；专项不出现在生产目标；strict、diff-check、UTF-8/no-BOM、引用和工程登记全部通过。

构建、专项和五组读回只证明本叶消费者闭环，不证明任务完成、路径验证、重新筹办、需求结算、价值回流、学习、授权、安全值/服务值或跨进程恢复。代码发布后必须另由集成验收智能体按具名消费者、正式读回和结果证据验收。
