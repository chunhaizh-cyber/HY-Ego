# 场景成员原子迁移提供者详细设计

日期：2026-09-05

版本：v0.1

身份：`DATA-L2-SCENE-MEMBER-ATOMIC-RELOCATION`

状态：已冻结，可进入代码实施

## 1. 目标和范围

在现有 `海中鱼巣.领域.数据服务.场景类` 内增加一个强类型场景成员原子迁移入口。它在场景唯一 owner 下，以一个 L1 中性写集同时退出旧归属关系、建立新归属关系，并读回旧边已退出且新边唯一当前。

入口只支持 `子场景`和`存在`两种位置成员。`状态`、`动态`是事实目录，不属于移动。本目标不新建/删除场景或存在，不改动现有单关系 CRUD，不建立世界树服务，不实现内部世界、状态动态发布或 ARCH-L4 关联。

## 2. 当前事实与所有权

基线 `8ce3298dedf4f7911b4023d8b8abf164facb240a` 上：

- 场景类已拥有子场景、存在、状态、动态四种关系类型和唯一写端口；
- `新增成员关系`、`删除成员关系`各自是独立事务，连续调用会暴露零归属或多归属中间状态，不能代表移动；
- L1 公开查询能按目标+关系类型读当前反向关系，场景 owner 的中性写集能同时包含一条关系退出和一条关系新建；
- 场景类已具备场景、存在当前性验证，场景树成环检查，幂等首次写材料和历史读回。

迁移关系的唯一事实所有者仍是场景类 owner。存在类只验证目标存在当前，不提交关系；ARCH-L3 后续只调用本入口，不再拆成两次 CRUD。

## 3. 冻结公开合同

所有类型仍在 `export namespace 海中鱼巣`中：

```cpp

enum class 场景类成员迁移状态 : std::uint8_t {
    已迁移 = 1,
    精确重复 = 2,
    入口拒绝 = 3,

    目标场景未找到 = 5,

    成员多重归属 = 8,

    存在读取失败 = 10,

    数量预算不足 = 12,

    场景类成员迁移状态 状态 =
        场景类成员迁移状态::入口拒绝;
```

`场景类数据服务` 增加一个公开成员：

```cpp
场景类成员迁移结果 迁移成员关系(
    const 场景类成员迁移请求& 请求);
```

`成功()` 仅接受`已迁移`或`精确重复`，要求合同版本精确、事实代次非零、投影全部编码有效、原/目标场景不同、旧/新关系不同，且成员种类只是子场景或存在。所有非成功结果的`投影` 必须为空。

## 4. 准入、写集和读回

### 4.1 首次请求

1. 验证版本、非零 G0、幂等身份、五个编码/预算字段，拒绝原场景=目标场景、成员为状态/动态、子场景自指。
2. 以 G0 读原场景、目标场景和目标成员的当前性。
3. 按“成员结点 + 对应关系类型”读场景 owner 全部当前反向关系：必须恰一条且源为原场景。零条返回`成员未找到`，目标场景已有该成员返回`成员已在目标`，多条或唯一源不是原场景返回`成员多重归属`。
4. 子场景迁移必须以`最大场景数量`为硬预算遍历成员子树，验证目标场景不是成员本身或其后代；预算耗尽不写。
5. 形成唯一中性写集：G0、原幂等身份、一条新关系 `目标场景 -> 成员结点`（原关系类型、角色/`顺序=1`），且`退出事实`恰含旧关系编码。不含节点、值、属性槽或其它退出。
6. 只调用一次`写入端口_.提交所有者范围中性写集`。任一准入失败不得写入。

### 4.2 发布后读回

成功发布 G1 后必须证明：新编码映射恰一条新关系；旧关系历史事实的退出代次=G1；新关系当前、端点/类型/角色精确；原场景在 G1 不含成员，目标场景在 G1 恰含新关系；按目标反查恰一条当前关系且源为目标场景。任一无法证明都返回`已可能发布`和空投影，不再改写。

## 5. 幂等、失败和生命周期

入口先经场景写端口读首次幂等材料。已有记录时不再用当前图重建旧边，而是：

1. 验证首次规范化写集只含一条关系新建+一条关系退出，头部与请求 G0/幂等身份相等；
2. 按历史事实验证旧边的原场景、成员、类型和退出代次，验证新边的目标场景、成员、类型和创建代次；
3. 与本次请求意义不等或原结果非成功返回`幂等冲突`；精确相等时以首次规范化写集重放，必须取得 L1 `精确重复`；
4. 以首次发布代次的历史快照形成`精确重复`投影，不被更晚的再次移动改写原回执。

L1 状态逐项映射为代次漂移、幂等冲突、引用冲突、历史材料已清理、资源失败、内部不一致或已可能发布。只要提交可能已发布但完整读回不成立，就必须使用`已可能发布`；调用方只能重放原请求。不补偿、不生成新键、不把未知当零写或成功。

## 6. 依赖、验证和声明边界

不新增 import；只使用场景类已有 L1 公开函数、写端口和存在类公开查询。禁止旧 `服务.L2*`、SQL、仓库私有面、回调、跨 owner 写或世界树反向依赖。

用户已明确当前代码不需要验证；执行阶段不运行构建、链接、程序、测试、专项、静态扫描、diff/strict、故障注入或独立验收。计划治理仍执行文档 `git diff --check` 和 `check_specs.py --strict`。
