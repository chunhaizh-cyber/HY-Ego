# 状态记录变为未知详细设计

标识：`STATE-UNKNOWN-VALUE`；版本：v0.1；日期：2026-11-06；状态：第8节用户裁决全选A、第7节规范修订经用户同意已落入 `7c35bab8c`（R98），定稿。

方向依据：用户2026-11-06裁决——扩展状态模型，允许状态的变化后准确值为空，表示“变为未知”；`建立状态` 前提由“F有当前值”改为“F当前值实际改变”；原保护随之调整；单独成计划。规范基线：1160 v2.4、4212 v1.2、1170 v3.4、4211 v2.2、0300 R98。代码基线：main `7c35bab8c`（工作区另有其它窗口WIP：`线程/新_任务管理线程类.cpp`、`领域/新_任务类.cpp`）。

## 1. 目标与完成条件

修改对象：状态（虚拟存在侧事实记录）的值域。原因：F当前值由有值变为无值是真实变化（被认知需求已知目标被纠正为未知；1150 §5 坐标置空记入原场景），现状态模型无法记录，只能失败或伪造值。目的：让“变为未知”成为可记录、可读回、不冒充任何值的状态事实，供 `DEMAND-GOV-SCENE` 及后续坐标置空使用。

完成条件：
1. 状态可以是“变为未知”：被描述存在、来源F、特征类型、强时间、引用计数照常；准确值为“无”，不写任何代替值。
2. 只有在F当前值确实为空、且调用方声明这是一次实际变化时才能建立未知状态；有值状态的建立合同不变。
3. 全部读取固定准确值的生产代码都显式处理“未知”，不存在把未知当0、当空节点、当旧值使用的路径。
4. 实际项目编译链接通过。

不在范围：需求入场景（`DEMAND-GOV-SCENE`）；坐标置空的业务实现（当前无绝对坐标F）；以未知状态形成动态、因果或概念的新语义（见Q4）。

## 2. 当前事实（路径相对 `海中鱼巣/海中鱼巣/`）

- `新状态信息::固定准确值` 为非optional `新特征准确值`（`领域/新_状态类.h:43`）。
- `建立状态` 遇F无当前值返回 `特征当前值不存在`（`领域/新_状态类.cpp:249—251`），随后写 `*特征->当前值`（:273）并读回比较（:286）。全仓没有调用方专门处理该枚举值，都只判 `已完成`：存在类回滚/返回资源失败或“特征已更新但状态未完成”，任务/方法路径按工程故障终止。它是防调用方逻辑错误的入口保护。
- 特征层已支持清空：`新_特征类.cpp:6229—6230` 把“原有值→空”标为 `已完成`、`当前值已改变=true`。
- 固定准确值共约120处使用，分布21个文件（状态类18、任务类18、内部治理世界17、世界树15、模拟世界9、其余各1—6）。按用法分三类：
  1. 与具体值比较（`!= 新特征准确值{x}`、`== *F->当前值`、两状态互比）：约占一半，改为optional后语义仍正确（未知与任何值都不相等），多数源码不必改，只需逐处确认。
  2. 取值（`std::get/get_if/holds_alternative/visit`、`members(...)`、`集合成员(...)`）：约40处，必须改。
  3. 整体传递给其它DTO（`二次特征准确特征输入`、`新因果状态模式`、动态特征抽取、方法问题归档）：约10处，必须按Q4决定。

## 3. 复用裁决

- 复用 `std::optional<新特征准确值>`，与 `新特征信息::当前值` 同一表示，不新增“未知”哨兵值，不改 `新特征准确值` 变体。
- 物理存储沿用状态节点字段组，未知状态不写准确值字段（Q2）。
- 有值状态的全部既有入口签名、语义与保护不变。

## 4. 接口

```cpp
// 领域/新_状态类.h
struct 新状态信息 final {
    ...
    std::optional<新特征准确值> 固定准确值;   // 无值 = 变为未知
    ...
};
// 新增，私有，friend 同 建立状态
新状态建立结果 建立变为未知状态(稳定编码 被描述存在节点, 稳定编码 特征节点,
    const 新状态强时间&) noexcept;
新状态建立结果 建立变为未知状态(稳定编码, 稳定编码, const 新状态强时间&, 新事实追加保护增量&) noexcept;
```

- `建立状态`：保留现有前提（F必须有当前值），保护不变——仍防“本该有值却无值”的逻辑错误。
- `建立变为未知状态`：前提为F存在且当前值为空；F有值时返回入口拒绝（逻辑错误保护）。是否“实际变化”由调用方依据特征层 `当前值已改变` 结果声明，状态类不追溯历史。
- `获取状态`/读回：准确值字段缺失解析为未知；字段多于一个或类别非法仍为结构不一致。

## 5. 读取点改造规则

1. 第1类比较：逐处确认optional比较语义成立；`*F->当前值` 改为直接比较 `F->当前值`（两边同为optional）。
2. 第2类取值：
   - 只处理不可能出现未知的领域（任务Vt、方法Vm、世界树现实存在、外设、模拟世界、连接与消息规则）：遇未知为逻辑错误，沿用该处既有工程故障或入口拒绝路径，不新增业务分支。
   - 通用消费者（动态概念、动态特征抽取、方法问题学习、执行场景采集、因果状态模式、装配显示、方法问题归档）：按Q4。
3. 第3类传递：按Q4，未知状态不进入这些DTO（跳过），调用处说明跳过依据。
4. `新_动态类` 建原子动态入口：任一态为未知时返回入口拒绝（4211 v2.2）。
5. S0须列出全部约120处的分类表并写入施工记录；不允许用 `.value()` 一律解包了事。

## 6. 非成功、事务、验证

- 未知状态建立失败（资源、结构）与有值状态同样映射；不改变任何调用方的事务顺序。
- 本计划不新增任何调用 `建立变为未知状态` 的业务入口；首个使用者是 `DEMAND-GOV-SCENE`。
- 验证：静态矩阵（有值入口不变、未知入口前提双向、读回解析、120处分类全覆盖）＋实际项目编译链接；不运行测试。

## 8. 裁决项（用户2026-11-06全选A）

生效结论：Q1 `std::optional<新特征准确值>`；Q2 未知状态不写准确值字段；Q3 新增 `建立变为未知状态`，原 `建立状态` 保护不变；Q4 通用消费者遇未知按材料不具备跳过，不形成原子动态、因果模式或二次比较，不当false、不报错。以下保留选项原文。

- **Q1 表示**
  - A（推荐）：`固定准确值` 改为 `std::optional<新特征准确值>`。编译器强制每个取值点处理未知，不会遗漏。
  - B：保留原类型，另加 `bool 变为未知`。改动少，但旧读取点会静默读到无意义的值。
- **Q2 物理存储**
  - A（推荐）：未知状态不写准确值字段，缺失即未知。
  - B：写一个显式“未知”标记字段。
- **Q3 入口**
  - A（推荐）：新增 `建立变为未知状态`，原 `建立状态` 保护不变。两种情况各有明确前提，原保护继续防逻辑错误。
  - B：放宽 `建立状态` 本身，F无值时直接建未知状态。改动少，但原保护失效，调用方漏写值时会悄悄记成“未知”。
- **Q4 通用消费者遇未知**
  - A（推荐）：本版视为“材料不具备/不可比较”，跳过该状态，不形成原子动态、因果模式或二次比较；不当作false，也不报错。未知参与动态与概念的语义以后单独裁决。
  - B：本版就定义“值→未知”为一种原子动态，并规定其比较方向。需同步修订1170、4211及动态概念系列。
