# 实例因果类数据操作详细设计

身份：`DATA-L2-CAUSAL-CLASS-INSTANCE-CRUD`

版本：v0.1

日期：2026-09-04

代码基线：`aaa6d40df3b02357ac172c39f8dd79fd21e54b04`

## 1. 目标、依据与完成边界

本设计为现有 `数据服务.特征类`、`数据服务.状态类`、`数据服务.动态类`、
`数据服务.存在类`、`数据服务.场景类` 候选链补一份实例因果数据操作模块：
`海中鱼巣/领域/数据服务.因果类.ixx`。它保存调用方已经裁决的实例因果信息，提供新增、
当前查询、条件查询和生命周期退出；不判断因果真伪，不生成状态或动态，不计算概率，不形成
因果链层级，不装配普通应用，也不替换现有 `L2因果结构服务`。

依据和裁决：

1. 1190 v0.8 要求实例因果可回查条件、可选动作、结果、动态来源、适用范围、规则版本和计数；
   一次完整证据即可形成实例，数据层不得把统计或日志冒充因果成立。
2. 4230 v0.26 的共同 owner、幂等、同截止读取、单 owner 原子写、引用保护和失败边界继续适用；
   其既有 `L2因果事实` ABI 和服务不在本切片修改。
3. 用户本轮明确要求建立新 `数据服务.因果类.ixx`，并允许它调用 L1 公开面以及特征、存在、
   场景、状态、动态类公开函数。为避免同层身份重演，本设计实际只直接调用状态、动态、场景
   三类公开查询；动作是可空的不透明稳定编码，只由 L1 公开当前节点读取验证形状。
4. 当前候选链没有公开 `绑定于(L1)`，所以构造器不能伪造跨服务同底座证明；运行期每次跨类
   查询仍要求其结果截止精确等于请求 `期望事实代次`，再以该代次提交因果 owner 写集。

本切片完成只证明新模块进入工程并通过计划规定的编译与专项验证。没有生产消费者、应用装配、
既有 L2 迁移和独立集成验收时，不得声称因果能力已完成或正式替换已经发生。

## 2. 模块与依赖

新模块固定：

```cpp
export module 海中鱼巣.领域.数据服务.因果类;
export import 海中鱼巣.领域.数据服务.场景类;
```

`场景类` 的现有公开 import 链已经传递存在、动态、状态、特征和 L1 公共类型。新文件不得 import、
调用或引用任何 `服务.L2*`、仓库、内部命名空间、私有函数、业务服务或装配模块。

服务唯一拥有一份因果 `L1所有者范围写端口`。构造器只保存以下只读依赖引用：

```cpp
因果类数据服务(
    const L1事实基座服务& 第一层服务,
    const 状态类数据服务& 状态服务,
    const 动态类数据服务& 动态服务,
    const 场景类数据服务& 场景服务,
    L1所有者范围写端口&& 写入端口,
    稳定编码 来源属性类型,
    稳定编码 规则版本属性类型,
    稳定编码 样本数量属性类型,
    稳定编码 失败数量属性类型,
    稳定编码 条件关系类型,
    稳定编码 动作关系类型,
    稳定编码 结果关系类型,
    稳定编码 动态证据关系类型,
    稳定编码 适用场景关系类型);
```

九个类型编码必须有效且两两不同；四个属性类型由因果 owner 当前持有，表示分别为
`独立材料引用、I64、I64、I64`；五个关系类型均为因果 owner 当前普通节点。写端口必须有效、
绑定 `第一层服务`、owner 有效且其当前范围是 `独占结构范围`。任一配置不成立抛
`std::invalid_argument`；构造过程零事实写入。

## 4. 字段来源与结构编码

| 公开字段 | 来源 / L1 承载 |
| --- | --- |
| `结点` | 因果 owner 写集中创建的普通节点 |
| 条件、结果 | `源=因果结点` 的相应关系；角色为从 1 连续增长的顺序；目标经 `状态服务.查询状态` 同截止确认 |
| `动作` | 可空动作关系，角色固定 1；目标只经 L1 公开当前节点读取确认是未退出普通节点 |
| 动态证据 | 动态证据关系；角色为从 1 连续增长的顺序；目标经 `动态服务.查询动态` 同截止确认 |
| 适用场景 | 适用场景关系，角色固定 1；目标经 `场景服务.查询场景` 同截止确认；结果按目标编码升序 |
| 来源 | 来源属性槽的 `独立材料引用`，目标经 L1 公开当前节点读取确认；值事实编码公开为 `来源值事实` |
| 规则版本 | I64 值，必须大于 0 |
| 样本数量 | I64 值，必须等于动态证据项数且大于 0 |
| 失败数量 | I64 值，必须在 `[0, 样本数量]` |
| 生命周期 | 结点、四个值和全部自有关系的创建 / 退出代次共同推导 |

动作、来源的 L1 读取只验证稳定编码当前对应一个普通节点，不解释其业务身份。状态、动态、场景
不得用 L1 直接读取重演其类型证明。特征类和存在类不被直接调用；它们只通过被调用公开服务的
既有闭包间接参与，不新增反向依赖。

## 5. 新增事务

1. 先校验版本、非零 `期望事实代次`、有效幂等身份、四个非空组、组大小、组内不重复、动作和
   来源编码、正规则版本、计数关系。适用场景请求先按编码升序规范化；其它三组保留调用方顺序。
2. 在任何当前性读取前，按完整规范化请求尝试 L1 幂等重放。同键同义由首次事实代次历史读回
   恢复完整结果，返回 `精确重复`；同键异义返回 `幂等冲突`。
3. 逐项调用状态、动态、场景公开查询，所有成功结果必须为 `已读取`、载荷身份吻合且事实代次
   精确等于请求代次；未找到 / 已退出分别映射专用状态，其它非成功映射对应 `读取失败`。
4. 用 L1 公开当前节点读取动作和来源；请求代次漂移、节点不存在 / 已退出、类型错误分别结构化
   失败。不得访问仓库、私有 owner 或其它类内部函数。
5. 一份因果 owner-scoped 写集同时创建：1 个因果结点、4 个属性值、全部条件 / 动作 / 结果 /
   动态证据 / 适用场景关系。每项使用互异固定本地键；关系角色和材料按 §4 冻结。
6. 恰一次调用写端口提交。交换前入口错误、读取失败、漂移、幂等冲突、资源失败或内部异常均
   零写；写状态按现有候选链同名状态映射。
7. 首次提交或精确重复后以写入事实代次完整读回，逐字段核对节点、四值、各关系、owner、角色、
   顺序、生命周期和计数。完整时返回对应成功状态；提交已确认后的读回失败返回 `已可能发布`
   并保留非零事实代次、空载荷，调用方用原完整请求和幂等身份重放收束。

本地键固定为：结点 `1`；四值 `2..5`；条件关系从 `0x00010000`、动作关系 `0x00020000`、
结果关系从 `0x00030000`、动态证据关系从 `0x00040000`、适用场景关系从 `0x00050000` 开始。
组上限保证不越过各区间。

## 6. 读取、查询与退出

完整读取以因果结点为根，在同一请求代次读取结点、四值和五类关系。条件、结果、动态证据按
角色严格升序且必须从 1 连续；动作 0/1 条且角色 1；适用场景按目标编码升序。缺项、复义、
错 owner、错类型、错角色、混代、计数不闭合均返回 `内部不一致`，不得返回部分载荷。

四个条件查询都先用 L1 公共关系 / 属性条件读取取得候选根，再复用完整读取逐项闭合：

- 状态查询按条件、结果或任意位置筛选；同一因果只返回一次；
- 动态查询只匹配动态证据，不把动作关系当动态证据；
- 场景查询匹配适用场景；
- 来源查询精确匹配来源独立材料引用。

候选读取达到调用方数量预算前必须能够证明没有遗漏；预算不足返回 `数量预算不足` 和空组。
成功组按因果结点编码升序，全部载荷共享请求事实代次。

删除先尝试幂等重放，再完整读取当前因果，随后在一个因果 owner 写集中退出结点、四个值和全部
自有关系。L1 当前引用保护若发现未闭合外部引用，返回 `引用冲突` 且零变化。提交后从退出代次
历史读回原完整快照，确认全部自有事实同代退出后返回 `已退出` / `精确重复`；提交后不能闭合
读回时返回 `已可能发布`。删除不物理清理历史，不退出任何状态、动态、场景、动作或来源目标。

## 7. 异常、诊断与验证

公开数据函数捕获 `std::bad_alloc`、`std::length_error` 为 `资源失败`；其它未预期异常为
`内部不一致`。构造器配置错误仍抛 `std::invalid_argument`。模块不得写日志、弹窗或吞掉诊断
后伪造成功。

专项驱动必须位于 `D:\TEMP\DATA-L2-CAUSAL-CLASS-INSTANCE-CRUD\`，不进入工程或提交；
使用隔离构建目录和自己的 L1 运行包，不能消费生产数据库、端口或固定日志。至少证明：

1. 被动因果（空动作）和主动因果（非空动作）分别新增并完整读回；
2. 状态、动态证据、场景和来源四类查询命中，结果排序、顺序、计数和同截止闭合；
3. 零身份、空组、重复成员、坏计数、坏类型、坏引用和旧代次结构化失败且代次不变；
4. 同键同义精确重复、同键异义幂等冲突；
5. 删除前的外部当前引用保护，闭合引用后退出成功、当前不可见且历史自有事实仍存在；
6. 提交后读回失败注入返回 `已可能发布`，原请求重放收束；
7. canonical 工程 Debug / Release x64 编译成功，且项目和 filters 各有且仅有一个新模块条目；
