## 1. 目标、交付范围与依据

本设计汇总本窗口已确认的三个相连目标：

1. 一个任务结算本能入口同时承接需求驱动和任务完成消息驱动；内部统一贡献计算、直属交接及最终服务值增加。
2. 任务虚拟存在、方法虚拟存在的特征实际变化，经统一治理事实链被动形成状态、动态和满足成立条件的因果材料，归入内部治理世界。
3. 每个任务有一个稳定的任务治理场景，组织该任务的虚拟存在引用及治理事实；跨任务交接在共同上级场景组织，不复制事实。

## 4. 信息组织与所有权

### 4.1 核心对象

| 符号 | 含义及唯一责任 |
| --- | --- |
| T、Vt、Ftq、Fts | 来源任务、其虚拟存在、服务值F、任务状态F；任务类负责治理写入，特征类负责特征结构 |
| P、Vp、Fpq | 直接父任务、父Vt及父服务值F；P必须由D→父D→唯一T确定 |
| L | 长期“结算服务需求”任务；不是每个来源额外生成的新任务 |
| Eself、Fself | 现实世界自我存在及其服务值F；通过世界/特征正式入口更新 |
| M、Vm | 结算方法及唯一方法虚拟存在；方法类唯一维护 |
| C(T)、Cg | 任务治理场景、内部治理世界根场景；世界类组织，场景类保存结构 |
| K、R、U | 来源任务唯一完成结算、直接父接收事实、最终服务值消费事实；既有正式记录优先复用 |

K中的冻结Q是该次交接的来源证据，不是第二个可独立更新的当前余额；Vt服务值F是任务当前Q的权威。父级累计字段不能继续与Fpq各写一份。

### 4.2 每任务一个稳定治理场景

```text
内部治理世界根 Cg
├─ 任务 A 的治理场景 C(A)
│  ├─ A 的 Vt 引用与特征引用
│  ├─ 本任务内部治理动作及来源
│  ├─ 状态引用、变化动态引用
│  └─ 因果发生材料及共享概念引用
└─ 任务 B 的治理场景 C(B)
   └─ 同类组织
```

1. 每个正式T恰有一个C(T)。新任务创建流程须确保场景绑定完整后才向治理消费者交付；同一T重复建立、重新筹办、挂起唤醒均复用场景，不按方法调用新建场景。
2. C(T)保存T的强类型归属引用；查询按T唯一定位。反查索引可重建，不成为第二权威绑定。T、Vt及世界根编码相互不可混用。
3. 首版采用根下的任务场景组织；需要共同场景时使用Cg或已正式建立的共同上级，不凭业务父子关系暗中移动场景。若后续将任务场景嵌套，其包含关系仍只作组织，业务父子判定始终读需求树。
4. “写在任务场景”指把正式信息按引用组织到该场景，并非把状态、动态、特征内容塞成场景自定义大字段。底层类仍各自负责身份、读写、引用计数及删除。
5. 任务普通现实动作及外部结果仍归现实场景，任务场景仅保存必要来源关联，不能复制为内部治理世界中的现实事实。
6. 任务终结不自动删除C(T)或仍被引用的事实。物理删除须先解除正式引用，不能以场景销毁级联删除共享概念、Vm或其它任务材料。

### 4.3 共享方法及跨任务信息

- 同一M只有一个Vm。任务场景可以引用本次参与的方法、相关正式变化及运行来源，不各存一份方法运行次数、成功次数或可靠度。
- 方法自身治理特征变化也必须进入内部治理世界。任务相关发生可以关联C(T)；共享Vm的正式归属及无任务初始化/学习发生的场景，仍需第13节裁决，不假定属于某个任意任务。
- 子任务向父任务交接时，Ftq、Fpq的本地变化分别组织在对应任务场景；交接发生关系在包含双方的共同治理场景组织。引用同一状态/动态，不再复制一套。
- 共同场景查询必须覆盖其合法子场景范围、按稳定身份去重，并验证参与者引用。当前因果递归收集能力不等于治理参与者递归读取已完成；两者必须一起接通。
- 跨现实世界与内部治理世界只保存明确来源关联，不能为了串联而把两棵世界树混成一个发生场景或伪造跨世界单条因果事实。

### 4.4 状态、动态、因果的形成边界

统一链路为：治理操作经任务/方法owner → 正式特征变更 → 形成合法状态 → 场景组织引用 → 有真实前后变化时形成动态 → 明确动作关联 → 交付因果能力。

无实际值变化不补造变化动态；缺合法前状态时保留可确认的新状态，不伪造过去；同一动作按显式身份关联，不靠时间邻近、列表最后一条或线程名称猜来源。前状态时间不晚于动作进入时间，结果状态时间晚于实际动作进入时间，不重写既有状态时间。

没有显式动作材料的合法特征变化仍保留S/D，不补造主动方法调用。已知被动代码触发与未知动作必须分开；只有已知正式来源及适用条件完整时才能表达被动触发。重复交付复用同一变化身份，不重复累计发生次数。

因果概念共享，发生材料保留在对应治理场景。经验归纳仍满足1190的独立发生要求；代码预置因果只能体现已实现代码及完整必要条件，初始统计为0。不能在每次特征写入后强制新造一个因果概念。一个果的不同成因分别组织；无足够原因材料则保留事实而不伪造因果。

## 5. 本能方法头、输入和输出

### 5.1 统一入口及正式方法信息

保留现行入口形状：

```cpp
新本能函数本次条件结果对
新_本能函数集::执行服务值结算(const 方法参数场景& 场景) noexcept;
```

函数内部先查询并确保自身正式方法登记。注册表仍只保存登记名→C++入口；方法头表达“作用于自我、改变服务值”的普通方法能力，参数规格由唯一Vm承载。内部贡献治理仍用本能实现，但暂不单独建立方法头和治理需求。

方法头对外语义：作用对象为既有自我概念，可改变FT为自我服务值，结果方向为增加，具体增加量来自本次来源任务Q。自我概念必须引用正式初始化结果，不临时按字符串造概念；当前独立全局引用及其交付仍是待补项。

首次登记只形成正式头、函数绑定、Vm及必要规格；没有真实运行或合规学习材料时不预造长期条件—结果对、动作、运行次数或因果发生。初始结算需求沿现有初始化责任建立/复用，内部治理子步骤不另建需求。治理专用调用不能混入普通增值方法的成功样本或真实运行计数。

### 5.2 参数场景角色

| 角色 | 必须提供的正式引用 | 读取/使用 |
| --- | --- | --- |
| 来源任务 | T、Vt、Fts、Ftq、来源需求 | fresh核对状态、Q及需求归属 |
| 来源证明 | 真实执行/评估、完成结算或其成立材料 | 校验完成、服务资格、未消费及归集完整；不信任消息快照 |
| 直接接收方 | P、Vp、Fpq、需求直接父子关联 | 普通子结算及最终边界交接 |
| 现实目标 | 自我E、所属现实场景、Fself | 仅最终普通增值分支读取并修改 |
| 治理场景 | C(T)、C(P)及本次共同场景 | 登记治理动作、路由S/D及交接材料 |
| 阶段来源 | 本次正式K及相应阶段记录/已有回执 | 去重、动作关联、恢复，不能用调用线程推断 |

上述是角色化合同，不是增加通用“上下文”参数。必要业务引用均进入场景；外层保留纯调度、执行冻结和工作项关联。角色之间必须核对归属，不接受裸Q、字符串状态或随意任务编码替代正式引用。

不同分支只要求自己真正需要的角色；纯父级交接不为凑参数伪造现实增值动作或Fself绑定。方法规格→任务Vt要求→筹办定位正式节点→参数场景的链路继续使用通用机制。场景容器临时、绑定只读，所指特征按合法owner合同读写；不持久复制实参成为第二余额。

### 5.3 本次返回

返回本次实际读取和使用的条件材料，以及实际形成的动作、状态、动态、结果取得进度和正式结果引用；返回材料不是长期方法知识，不直接裁决需求满足或父任务完成。

来源任务被结算与“执行结算方法的任务达到其需求目标”是两个不同结论。前者按本设计治理收尾，后者仍由任务独立读回并判断。self直接调用不伪造一个任务执行X来满足旧外层接口，应使用正式结算来源/工作项定位结果。

## 6. 计值、直属交接和最终消费

### 6.1 计值

```text
Q(T) = 1                         已完成服务叶子
Q(T) = 0                         合法纯治理叶子
Q(T) = Σ 已正式接收的 Q(C)        非叶子，C为直接子任务
```

所有新Vt初始Q=0；零不是“尚未计算”的标志。计值准备是否完成由正式完成、子需求枚举、唯一任务关联、合法子回执及冻结记录共同证明，不新增Q>0的准备门槛。

来源任务自身必须完成；非叶子发布K前重新核对全部直接子需求和子结算。缺任务、待完成、已完成但未交接、发布未知不能按0封口；失败/取消子任务按既有规则处理，不能替代父自身完成资格判断。非叶子不额外+1，不同时加子任务汇总和孙叶子值。

本设计不再为内部治理操作创造新D/T；对已存在治理任务的0值及传递规则只说明其结算处理，不据此授权批量迁移或删除。

### 6.2 普通子任务只结算一级

1. 从D→父D→唯一T定位P，禁止从场景树或方法调用栈推断P。
2. 通过统一流程把源Q写入/读回Ftq，形成唯一K。
3. 以K查唯一直属接收R；不存在时将R和父Fpq增加Q作为一致业务发布处理。
4. 正式读回R、父值及相关变化。建议在普通直属交接完成后将来源Fts从已完成改为已结算；这一普通子任务状态机扩展须按第6.3、13节确认，不能仅凭R已存在擅自改状态。
5. 通知父任务重新读取条件；不递归替父任务结算，不直接增加自我服务值，也不自动宣告父任务完成。

没有父需求的根任务不虚构P。长期结算任务L不把自身再算作服务贡献。

### 6.3 最终服务来源消费

本次来源必须是L的直接子任务完成结算，并满足6190保留的人类服务资格、明确需求确认、实际结果验证、当前认知归因及未消费门禁。任务完成本身不自动证明这些门禁全部成立。

读取来源Ftq的Q并与K一致核验，按本次K消费一次：`Fself新值 = Fself当前值 + Q`。Q=0不产生正向增值动态，不伪造+1；符合资格的零额来源仍须有明确零额处理事实，避免重复扫描当新来源。不消费L的累计总额，不把已消费下层贡献再作为祖先贡献入账。

不同直接来源各自独立：任一来源具备条件就可处理，不等待L的所有其它直接子任务完成。这是最终来源选择的“或”，不是普通父任务归集的“或”。

最终来源可以先完成直属接收，但“已接收”不等于“已计入自我”。只有最终消费及正式结果读回完成后，才把该最终来源标为已结算；中断时保留已接收未消费事实继续同次收尾，不撤销R、不重加Fpq。

状态语义的方案建议是：“已结算”表示该任务应履行的这一级结算已完成，普通子任务以R完整为门，最终来源以U及实际增值读回完整为门。用户已经明确结算涉及任务状态已完成→已结算；但把这一标记推广到所有普通子任务，并分别采用R/U作为门，尚无单独明确裁决。本文将其作为待确认建议，不授权实施者据此扩展状态机；R与U始终分账，不能用一个无区分状态代替二者。

## 7. 两个触发入口与四阶段执行

```text
结算任务筹办/执行 ─┐
                 ├─ 同一结算来源协调 → 参数场景 → 统一本能入口
manager完成消息 ──┘                               │
                                                 ├─ 贡献治理/直属交接
                                                 └─ 符合最终资格时自我增值
                                                      → 正式读回 → 状态收尾
```

### 7.1 需求驱动

结算需求仍是服务根的子需求。任务根据目标FT查方法，读取方法条件并定位已完成服务来源；缺少真实服务来源时继续通用筹办。只是内部汇总/收尾未完成时，走治理工作及事件复核，不派生“执行内部代码”的需求。

没有长期条件—结果知识的方法头不自动证明可预测满足目标；登记、直接本能治理可调用、学习完善、任务查找可采用必须分别报告，不能以直接调用旁路补造配对。

### 7.2 完成消息驱动

manager只发送正式T/X/A等定位，self fresh读取后提出结算工作。较重读取、归集和事务交给既有工作线程，保持self消息循环不长时间阻塞，服从已有激活工作并发上限。无需为这项工作新增需求或任务。

工作结果唤醒self；self及manager按正式R/U/任务状态读回更新本次处理中标记和后继唤醒。消息不是结算事实，重复、丢失后重查、顺序变化不能改变入账次数。旧`处理贡献定位()`不再独立调用一遍旧算法后又调用新本能。

### 7.3 函数四阶段

1. **确保方法信息**：核对正式头/Vm，登记用途止于登记；不覆盖学习结果。
2. **读取并复核**：从场景按角色读取状态、Q、父子、资格及既有阶段事实。条件变化时零动作退出，交原流程复核；工程坏引用不是业务条件不足。
3. **实际动作与写入**：内部计值/交接/状态收尾分别记录治理动作；最终增值记录现实普通动作。每项动作必须早于其实际修改，经owner写入。
4. **正式结果读回与交付**：沿同次来源读取真实结果和已形成S/D，关联显式动作，返回本次条件—结果材料；学习独立消费，不在方法内修改长期知识。

内部治理代码按必要条件成立后确定操作设计；现实普通结果仍必须正式读回，不因函数返回成功就宣称已改变。模拟调用只允许重映射到模拟世界参数实例，不得修改真实任务、真实服务值或真实治理场景。

## 8. 动作身份、并发、事务和恢复

### 8.1 一次来源、多阶段动作

现有动态来源查重全局唯一，不能把同一K直接用作多个动作的唯一来源。目标合同是：同一次任务完成结算关联若干具名阶段记录，每个实际阶段有自己稳定的动作来源身份；一个阶段最多一个真实动作。阶段至少区分来源Q确定、父贡献接收、最终普通增值和来源状态收尾，实际未发生的阶段不得预造动作。

阶段记录用于真实结算来源及恢复，不是新的需求、任务、业务轮次或通用事件账。既有R/U/收尾来源能够承载时优先复用；完整物理字段和注册须在施工接口冻结时确定。阶段记录的存在不等于动作已经执行。来源Q确定发生在正式K成立前时，必须由已核验的任务完成来源提供阶段身份，K成立后再显式关联；不得预先伪造合法K来解决循环依赖，此项物理映射属于第13节冻结项。

纯治理动作不能继续强制要求`来源普通动作节点`。父级交接必须使用真实治理来源，不能为满足旧ABI伪造一次现实动作。最终收尾可以引用普通动作作为来源，但与治理来源显式分型。

### 8.2 一致发布要求

| 边界 | 必须共同成立的事实 |
| --- | --- |
| 新任务治理组织 | T、唯一Vt、初始F与唯一C(T)绑定完整可读；不对外交付半结构 |
| 来源Q确定 | 完成及子归集核验、Ftq值、唯一K及其来源一致 |
| 父级接收 | 唯一R及父Fpq本次增加一致，不允许只加值无回执 |
| 最终增值 | 唯一U及Fself本次增加一致，不允许已加值仍可重复消费 |
| 收尾 | Fts已结算必须有对应完成接收/最终消费事实；不能只收到消息就置状态 |

这是上层各owner组合的业务一致性要求，不授权本能函数或世界类越过owner直接CRUD。现有锁内组合能力不等于跨任务/特征/世界的完整事务已接通，具体写集提供者、锁顺序和读回合同属于第13节待冻结项。

同来源双入口竞争按已成立的来源及阶段身份收敛；不同来源向同一父F或Fself累加时，在唯一更新边界读取当前值并受检相加，不能各自拿旧值覆盖。仅进程内“正在处理集合”不能替代正式去重事实。

本节一致性和恢复描述是目标合同，不是现有跨进程保证。同进程重入可按已发布内存事实读回；进程终止后的恢复还依赖实际接通的持久快照、阶段材料保存和恢复提供者。本文未核定该生产链已完整成立，不能声称R/U/阶段身份已经具备可靠落盘。第13节须冻结持久化边界、最后完整发布恢复、未保存动作事实的处置及启动门禁后，才能承诺重启防重复入账。

### 8.3 中断处理

- 动作前条件失效：不产生动作或变化；业务条件等待原流程，参数结构损坏进入工程链。
- 已有阶段动作、尚未确认写入：先读取原阶段发布结果，不把“没有返回”解释成未执行。
- 值已修改、S/D或关联缺失：保留实际值和原动作；在相同来源下补齐合法组织，不再次改值制造第二次变化，不伪造缺失前状态。
- R已完成、U未完成：只恢复最终消费及收尾，不重做父累加。
- U已完成、Fts未收尾：只补同次治理收尾，不再次增加自我服务值。
- 已结算且事实完整：复用原结果；不计第二次方法运行、动态或服务贡献。
- 读取失败、结构冲突、求和溢出：日志、弹窗、终止进程；不返回0、false或空材料让业务误判，不形成业务失败知识。修复重启后只有经正式恢复入口确认来源和值一致，才可恢复该来源处理；恢复链未接通或事实无法确定时不得自动重算、重加。
