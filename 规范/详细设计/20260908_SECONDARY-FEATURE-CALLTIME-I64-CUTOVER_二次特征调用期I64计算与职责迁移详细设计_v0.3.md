## 1. 本版唯一修订

4182 冻结的唯一路由键是`输入 FT + 用途`。v0.2 第 5 节把同一输入 FT 的全部入向绑定节点统称为“候选”，又要求候选数恰为 1，会在同一 FT 为不同用途各有一个合法绑定时误报注册不唯一。

本版只把“扫描候选”和“用途匹配”分账。除本文件明确替换的 v0.2 第 5 节字段及谓词外，v0.1 与 v0.2 的全部设计继续有效；冲突处以本版为准。不得借此修改初始化、准确 F、provider、K、上下文、方向应用、迁移删除集、RC、持久实例或工程范围。

## 2. 当前绑定读取请求与用量 DTO

v0.1 的 `特征I64当前比较绑定读取请求`中字段`最大候选数量`替换为更精确的`最大扫描候选数量`，字段位置和类型不变：

```cpp
struct 特征I64当前比较绑定读取请求 final {
    std::uint32_t 版本 = 1;
    std::uint64_t Gread = 0;
    特征类型身份 输入FT;
    特征I64比较用途 用途 = 特征I64比较用途::识别区分;
    std::uint64_t 最大扫描候选数量 = 0;
    std::uint64_t 最大读取材料数 = 0;
};
```

v0.2 的用量 DTO 完整替换为：

```cpp
struct 特征I64当前比较绑定读取用量 final {
    std::uint64_t 扫描候选数 = 0;
    std::uint64_t 匹配数量 = 0;
    std::uint64_t 关系数 = 0;
    std::uint64_t 材料总数 = 0;
};
```

`扫描候选数`与`匹配数量`是独立字段：

- 扫描候选数：从请求输入 FT 的全部活动入向`I64比较绑定输入FT关系`中得到的不同绑定节点数量，不先按用途过滤；
- 匹配数量：上述扫描候选完成结构解析后，定义的输入 FT 与请求输入 FT 相同且用途等于请求用途的数量；
- 关系数与材料总数：沿用 v0.2 的真实、按稳定编码去重计量，所有匹配和非匹配扫描中实际读取、检查的关系、节点和值事实都计费。

不增加“最大匹配数量”。匹配集合是扫描集合的子集，已受`最大扫描候选数量`和材料上限约束；匹配数量承担 0/1/多的唯一路由语义。如果另设上限并在第二个匹配处先报预算不足，会把已知注册不唯一错误误报为资源预算不足。

## 3. 扫描、过滤、计费和返回顺序

当前读取固定执行：

1. 校验请求版本、Gread、输入 FT、用途以及两个非零上限，按 Gread 固定 H；
2. 读取输入 FT 的全部活动入向输入关系；每个实际关系先计`关系数/材料总数`，重复关系编码为内部不一致；
3. 依关系源节点形成去重扫描集合；每个新绑定节点进入集合前检查扫描候选余额并递增`扫描候选数`；同一节点出现第二条输入关系仍须计关系材料，随后因绑定结构不唯一失败，不能用节点去重掩盖坏边；
4. 对每个扫描候选完整解析绑定节点、归属、两个合同值、唯一输入关系、全部输出关系、输出 FT 及其结构核验材料。每项事实进入解析上下文前扣材料；即使最终用途不同，已经读取、检查的材料也保留在用量中，不返还、不按匹配集合重算；
5. 只有完整绑定的输入 FT 和用途均与请求相等才递增`匹配数量`并暂存该匹配事实。用途不同是合法非匹配，不进入返回事实；无法完整解析用途或结构不是合法非匹配，按原格式/内部错误失败；
6. 必须扫描完预算允许的全部候选后再按匹配数量裁决：0=`未找到`，1=`已读取`并仅返回该唯一匹配事实，大于1=`注册不唯一`且不返回任一事实。

预算不足在新增扫描候选或读取任一材料前返回`数量预算不足`，不返回候选或匹配身份；用量保留到失败点的真实数字。同次缓存命中不重复读取或计费，但不能用缓存把非匹配候选的首次真实读取费用抹掉。不得在找到第一个匹配后提前结束，否则无法证明同键唯一；不得把同 FT 的其它用途计入匹配数量。

二次计算调用当前绑定读取时，继续把`最大扫描候选数量`和`最大读取材料数`都设为当时剩余读取材料数。返回后只按`材料总数`扣减二次计算材料预算；`扫描候选数`和`匹配数量`用于回执与路由互证，不重复扣材料。

## 4. 结果形状与成功谓词

`特征I64比较绑定结果`继续回显完整`当前读取原请求`和上述新用量。只有`操作=当前读取`允许这些字段非空/非零；其它操作仍要求无当前请求且四项用量全零。

当前读取成功谓词完整替换 v0.2 对“候选数恰 1”的要求：

1. 原请求版本正确，Gread 与输入 FT 有效，用途合法，`最大扫描候选数量`和`最大读取材料数`非零；
2. 状态为`已读取`，结果`Gread=H=原请求.Gread`，无首次发布 H、无正式回执；
3. `扫描候选数 >= 匹配数量 == 1`，扫描候选数不超过扫描上限，材料总数不超过材料上限，关系数非零且不超过材料总数；
4. 返回事实存在、在 H 完整活动，其输入 FT/用途分别等于原请求，并且就是唯一匹配项；
5. 扫描中的其它合法绑定可以具有相同输入 FT，但必须具有不同用途；它们不影响成功，只贡献扫描和材料用量。

`未找到`要求匹配数量为 0；`注册不唯一`要求匹配数量大于 1；两者都不得携带事实。`数量预算不足`、格式失败、历史失败或内部错误可保留真实扫描/匹配/关系/材料用量，但不得携带事实。非当前读取操作出现任一当前用量或原请求均使结果非成功。

## 5. 实施与验证替换

1. v0.2 A1.4 中“候选数”全部改为“扫描候选数与匹配数量”，字段名按本版落位。
2. v0.2 A3.2 当前 K 扣费继续只消费材料总数；不得把匹配数量当材料数。
3. v0.2 V16 增加同 FT 三种用途各一绑定的静态路径：扫描候选数 3，指定用途匹配数量 1，成功返回指定事实，三项绑定的实际扫描材料全部计费。
4. 增加同 FT 同用途两个绑定路径：扫描全部后匹配数量 2，返回注册不唯一且无事实；不同用途不得触发该分支。
5. 增加 0 匹配、扫描预算不足、非匹配候选格式坏、重复输入关系和找到首匹配后仍继续扫描的代码审阅证据。
