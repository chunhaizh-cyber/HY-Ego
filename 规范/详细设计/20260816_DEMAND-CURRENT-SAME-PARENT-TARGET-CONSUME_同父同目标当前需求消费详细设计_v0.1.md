# DEMAND-CURRENT-SAME-PARENT-TARGET-CONSUME 同父同目标当前需求消费详细设计 v0.1

日期：2026-08-16
版本：v0.1

## 1. 目标、范围与完成边界

本叶实现 BIZ-L4-004-02-01-02 v0.2：在同一 `需求业务服务` 中，按需求主体、可空父需求和精确单目标语义键，在调用方给定的非零共享事实截止 `G0` 恰一次调用 DATA-EXT-12 完整当前需求组读，再裁决不存在、唯一当前需求或多个当前同目标。

完成只证明这一枚 BIZ 只读定位叶。它不复核正差距、来源资格、父路径角色或防环，不新增 / 合并需求，不更新目标场景，不创建任务，也不证明 BIZ-L3-004-02-01、DATA-EXT-12 或系统治理闭环完成。

## 2. 正式依据与当前事实

- 0050、4030：BIZ 只能经公开强类型 DATA 服务读取结构；BIZ 不取得 L1、owner、仓库或事务参与者。
- 3100：需求是“主体要求目标宿主的确定特征达到目标状态”的长期合同，完整事实还必须保留目标场景、来源、授权、路径和生命周期。
- 5100：一个需求只绑定一个目标宿主、一个目标特征和一个目标状态合同；来源途径不改变目标语义。
- 5110：同一父需求下，目标宿主、目标特征、目标状态和满足关系相同的当前需求必须复用或合并；来源、归因、观测和文本差异不得制造第二身份。
- `L2目标状态合同身份`及完整目标合同 CRUD 已实现并退出；目标合同保存比较注册引用、目标 I64、允许关系位和规则版本，比较注册正式读回提供完整 `L2特征比较I64合同材料`。本叶把同一 G0 的两份权威材料组成目标状态语义键，不另造第二满足关系身份或用裸值替代合同。
- DATA-EXT-12 已冻结“新增或复用单目标需求、读取单需求和完整当前结构组”的服务族边界，但当前最终需求清单尚未登记“按主体、可空父和目标结构材料有界读取当前需求组”、跨合同 / 注册身份的同语义键组读及语义键回显。本设计只预冻结这一新 BIZ 消费需求，不宣称现有 DATA 能力或 ABI。
- 当前生产代码只有 `L2需求身份`和节点族，没有需求 owner、需求结构服务或 `服务.需求.ixx`；既有三个 DEMAND 当前读取计划均待 DATA-EXT-12 后激活。
- BIZ-L4-004-02-01-01 v0.1 仍缺来源权威 DTO / provider，且重复读取正差距前驱；该叶冻结不影响本只读定位叶继续设计。

## 3. 精确身份键与 DATA 消费合同

### 3.1 BIZ 精确复用键

```text
需求主体
+ 可空父需求
+ 目标宿主
+ 目标特征定义
+ 目标状态语义键{
    完整L2特征比较I64合同材料,
    目标I64,
    允许关系位,
    目标状态合同规则版本
  }
```

`L2目标状态合同身份`和 `L2特征比较注册身份`都是本次权威材料的引用与读回见证，不是内容规范化唯一键。现行 DATA-EXT-04 允许不同幂等身份建立内容相同的目标合同，比较注册也可替换为新身份；因此 5110 的“目标状态和满足关系相同”必须按目标状态语义键逐字段相等裁决。键中的完整 `L2特征比较I64合同材料`覆盖用途、算法族 / 版本、原始类型、左右角色、差异方向、单位、维度、分量角色、允许结果、边界、量化和误差 / 容差合同；不同合同或注册身份只要这份完整比较合同材料、目标 I64、允许关系位和目标状态合同规则版本相同，就属于同一精确目标候选组。

目标状态语义键是从同一 G0 权威目标合同与比较注册读出的不可变查询快照，不是可独立修改、持久发布或替代目标合同身份的第二权威。本叶只闭合逐字段精确相同目标的查询；5110 的明确值优先于区间、区间优先于宽泛方向等细化 / 合并规则仍由父级后继裁决。不同语义键之间不得在本叶推导广义包含、近似裸值或显示文本等价。

目标场景、提出者、来源证据、授权、发生时间、显示文本和到达顺序不进入复用键。

目标场景仍是需求完整事实必含字段。它描述目标上下文，不把宿主移动到另一场景变成第二长期目标；本叶只读回既有场景，不更新或裁决场景变化。

### 3.2 预冻结 DATA-EXT-12 组读

语义能力名：

```text
需求结构服务::按主体父需求与目标结构材料有界读取当前需求组（待最终需求清单登记）
```

精确 C++ 名称、DTO、状态枚举和字段顺序待 DATA-EXT-12 正式发布后机械匹配；不得由执行者从旧设计发明 ABI。请求至少携带：

```text
L2结构请求头{当前合同版本, 非零G0}
需求主体
可空父需求
目标宿主
目标特征定义
权威L2目标状态合同身份
目标状态语义键{完整L2特征比较I64合同材料, 目标I64, 允许关系位, 目标状态合同规则版本}
事实范围版本、需求范围版本、需求树规则版本、父关系规则版本
目标结构规则版本、路径规则版本、来源授权规则版本、生命周期规则版本、读取规则版本
非零当前候选数量预算
```

成功必须是 `已读取 + optional 有值`，值中含零或多项完整当前单目标需求事实、全部请求字段回显、预算回显和事实截止 `G0`。待登记的 DATA-EXT-12 操作先在同一 G0 互证请求中的权威目标合同及其比较注册确实承载所给语义键，再按强类型结构逐字段匹配语义键并返回所有命中项；任一权威引用与语义键不符属于引用冲突。这只是数据结构等值查询，不解释需求是否合理、是否应复用或合并。每项至少包含：

```text
需求身份及身份来源
需求主体
目标场景、目标宿主、目标特征定义、L2目标状态合同身份、L2特征比较注册身份及完整目标状态语义键
可空唯一当前父需求及关系见证
当前路径身份、角色与当前性见证
全部来源证据与当前授权
生命周期
目标、父关系、来源/授权、生命周期及读取结构版本
单项事实截止G0
```

DATA 不执行零 / 一 / 多业务裁决，不按来源、时间或场景过滤，不截断后伪装完整。无匹配项是成功空组；预算不足、漂移、许可拒绝、资源失败、运行态未实现 / 未装配和内部不一致分别返回且零组。BIZ 正式接线后不暴露“未实现”业务状态，DATA 的运行态未实现 / 未装配统一收敛为内部不一致。

## 4. BIZ DTO 与物理位置

新增：

```text
海中鱼巣/领域/需求同父目标读取.数据.h
海中鱼巣/领域/服务.需求.ixx（与既有 DEMAND 计划串行扩展同一服务）
```

预冻结 BIZ 合同：

```cpp
inline constexpr std::uint32_t 同父同目标需求读取合同版本 = 1;
inline constexpr std::uint32_t 同父同目标需求读取规则版本 = 1;

    std::uint64_t 目标结构规则版本;
    std::uint64_t 路径规则版本;
    std::uint64_t 来源授权规则版本;
    std::uint64_t 生命周期规则版本;
};

struct 目标状态语义键 final {
    L2特征比较I64合同材料 目标判断比较合同;
    std::int64_t 目标I64;
    std::uint8_t 允许关系位;
    std::uint32_t 目标状态合同规则版本;
};

struct 同父同目标需求读取请求 final {
    std::uint32_t 合同版本 = 同父同目标需求读取合同版本;
    std::uint32_t 规则版本 = 同父同目标需求读取规则版本;
    std::uint64_t 运行代次;
    std::uint64_t 事实范围版本;
    std::uint64_t 需求范围版本;
    std::uint64_t 需求树规则版本;
    std::uint64_t 父关系规则版本;
    std::uint64_t 目标结构规则版本;
    std::uint64_t 路径规则版本;
    std::uint64_t 来源授权规则版本;
    std::uint64_t 生命周期规则版本;
    std::uint64_t 读取规则版本;
    L2存在身份 需求主体;
    std::optional<L2需求身份> 父需求;
    L2存在身份 目标宿主;
    L2特征定义身份 目标特征定义;
    L2目标状态合同身份 目标状态合同;
    目标状态语义键 目标语义;
    std::uint64_t 事实截止代次;
    std::uint64_t 当前候选数量预算;
};

enum class 同父同目标需求读取状态 : std::uint8_t {
    不存在 = 1,
    唯一当前需求 = 2,
    多个当前同目标 = 3,
    请求拒绝 = 4,
    当前性漂移 = 5,
    数量预算不足 = 6,
    提供者拒绝 = 7,
    资源失败 = 8,
    内部不一致 = 9
};

struct 同父同目标需求读取结果 final {
    同父同目标需求读取状态 状态 = 同父同目标需求读取状态::请求拒绝;
    std::uint32_t 合同版本 = 同父同目标需求读取合同版本;
    std::uint32_t 规则版本 = 同父同目标需求读取规则版本;

class 需求业务服务 final {
public:

        const 需求当前根组固定配置& 根组固定配置,
        const 需求同父目标读取固定配置& 同父目标固定配置) noexcept;

    同父同目标需求读取结果 读取同父同目标当前需求(
```

`当前单目标需求值式事实`的精确子类型机械匹配 DATA-EXT-12 最终强类型 DTO，但必须覆盖第 3.2 节全部字段，不得用裸编码、布尔授权或省略目标状态语义键、目标场景 / 当前路径。只有 `唯一当前需求`携带 optional 值；不存在、多个和全部失败均为空。`多个当前同目标`只保留为便于父级精确映射的具名内部矛盾状态，不是成功形状。只有 DATA `已读取`且完整形状互证通过后形成的 `不存在`、`唯一当前需求`和 `多个当前同目标`回显事实截止 G0；请求拒绝、漂移、预算、提供者拒绝、资源失败和内部不一致均把 `事实截止代次`置0，不用请求守卫或失败回显冒充已读事实截止。

服务复用首个根组叶已经保存的稳定 `const 需求结构服务&`和 `需求当前根组固定配置`，只增加一份不重复共同字段的 `需求同父目标读取固定配置`。构造函数按上列签名扩展：共同的运行代次、事实范围版本、需求范围版本和读取规则版本仍只有根组配置一份权威；新增配置只保存六个本叶结构规则版本。构造不读事实、不缓存结果，不取得 L1、owner或第二 DATA 服务。普通应用后继负责从同一 L1 运行包装配唯一 DATA 服务与 BIZ 服务。

## 5. 固定流程与结果映射

```text
校验根组固定配置与同父目标固定配置完整
-> 校验请求自身
-> 校验请求共同字段逐字段等于根组固定配置，六个结构规则版本逐字段等于同父目标固定配置
-> 构造一次 DATA-EXT-12 精确键组读请求
-> 恰一次调用需求结构服务
-> 互证请求回显、G0、版本、预算和 optional 形状
-> 逐项互证当前生命周期、身份来源、主体、父和精确目标语义键
-> 零项返回不存在
-> 多项返回多个当前同目标
-> 一项继续互证权威目标合同引用、目标状态语义键、目标场景、来源、授权、生命周期和全部结构版本
-> 一次构造完整值式需求结果
```

DATA 事实代次漂移或回显 G0 不等映射当前性漂移；数量预算不足、许可拒绝和资源失败分别同名映射。因为这是本函数唯一一笔 DATA 调用，BIZ 前检不能证明强类型包装内稳定编码属于正确节点族；DATA 请求拒绝或引用冲突映射请求拒绝。DATA 运行态未实现 / 未装配、内部错误、未知状态、坏 optional、错键项、错语义键、重复需求身份、半结构、已退出项混入、错生命周期或混代均映射内部不一致。上述全部未读取或失败状态的 BIZ `事实截止代次`均为0；只有完整已读取分支保留 G0。

成功组中不同顺序不得影响零 / 一 / 多裁决。唯一项结果按值复制；`std::bad_alloc`、`std::length_error`映射资源失败，其它异常映射内部不一致。函数零锁、零等待、零重试、零截止重选和零缓存。

## 6. 验证矩阵

1. 根组 / 同父目标固定配置坏、请求版本坏、零主体 / 目标 / G0 / 预算及版本不匹配均在 DATA 调用前零载荷返回；共同字段只由根组配置拥有；

4. 唯一项完整携带目标合同引用、目标状态语义键、目标场景、身份来源、来源 / 授权、可空父、生命周期、全部结构版本和同一 G0；
5. DATA 漂移、预算、许可、资源精确映射；首笔请求拒绝 / 引用冲突映射请求拒绝；运行态未实现 / 未装配和内部错误映射内部不一致；全部失败状态事实截止为0；已读取空组 / 多项可回显 G0 但仍零业务载荷；
6. 错请求回显、错父、错目标语义键、重复身份、已退出项、半结构和混代收敛内部不一致；
7. 源码静态证明恰一次 DATA 组读、零 L1 / owner / 仓库 / 写入 / 历史 / 缓存 / sleep / retry；
8. 根工程 Debug / Release、生产外专项、diff、strict、UTF-8、工程唯一登记和清理后复验通过；公开 ABI 不可稳定构造的坏形状保持 `NOT_RUN`并以静态防御证据分账。
