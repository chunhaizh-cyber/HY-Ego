## 1. 目标、用户裁决与本叶边界

用户已确认：每个正式方法拥有唯一独立内部治理场景 C(M)，方法唯一虚拟存在 Vm 的特征变化记录在该场景；任务引用同一个方法及其事实，不复制方法运行统计。概念共享，实例分世界保存。旧资料能完整证明来源才迁接，无法还原保留现场并报告。

本次改变对象为 Vm 的启用状态特征。原因是当前启用状态仍为方法节点 M 的直接字段，不能通过正式特征组织状态、变化和治理场景；目标是完成 M—Vm—启用 F—C(M) 的唯一权威、全部现有写入和生产装配。现实世界实例和自我服务值不在本叶改动范围。

本叶交付：

1. 每个正式根成员 M，包括保留的旧副本 ABI 新建的 M，各有独立 Vm、启用 F、专属存在概念及 C(M)。副本不得与源 M 共享可写 F 或 C(M)。
2. 新方法完整发布、旧方法可证明迁接、重复复用、普通启用修改、结算新 Q 方法替代旧固定加一方法均使用同一权威。
3. 所有启用状态实际变化形成真实前后状态及唯一原子动态，归本方法场景；同值不造变化。
4. 方法参与者、治理场景范围和现实世界隔离由中立合同贯通。

下列仍属用户活动总体目标，但不是本叶完成声明：

- 运行次数、成功次数、可靠度的正式统计消费。5350 §6.1 已确定算法，但基线没有完整的真实动作进入去重与方法结果独立核验合同；只给旧方法填 0 会制造假历史，给新方法填 0 而不接维护会制造假当前值。因此本叶不预置无人维护的三个统计特征。
- 方法启用变更的正式治理动作来源及完整因果发生窗口。现有 `修改启用状态(M, 状态)` 没有正式执行主体、动作来源阶段或真实运行身份；本叶只组织实际 S/D，不伪造本能调用、未知动作、治理动作或因果。
- 学习异常条件多结果发布、真实可靠度算法消费、模拟学习泛化、任务策略改变。

上述边界不是把整个用户方案宣布完成，也不是自动停止后续目标。首叶交付后依据新代码继续冻结最早统计提供者；不登记多层待激活库存。

新增字段键由现有schema扩展方式单独建立，不改变旧键序号和旧根身份：`治理所属方法字段`、`治理所属方法虚拟存在字段`、`治理所属方法启用特征字段`；显式引用采用独立`治理方法字段`、`治理方法虚拟存在字段`、`治理方法启用特征字段`。不得把“所属任务”字段改义为任意治理对象。

C(M)必须是内部治理根的直接子场景，三个归属字段恰一且完整；C(T)三字段与C(M)三字段不能共存。反查 M 所属场景必须恰一。其 Vm 是隐式拥有参与者；其它任务/方法场景可用显式引用引用同一 Vm，但不能复制它的 F 或 S/D。

`新方法治理场景信息::启用特征归属字段关系`仅投影已经存在的C(M)所属启用F字段关系身份，不增加存储字段。场景owner读回时按自己的正式字段键核验恰一、所属节点为本C、内容为本F，再提供精确关系编码；world原样传递，方法owner不得用“来自本C的任意一条入边”代替此投影。

底层完整覆盖：`读取治理引用组`、`解析治理引用`、`发布治理引用`、`查询治理参与节点`、`读取治理参与者`、`属于内部治理组织`、`添加已核验状态/动态`、删除空场景的字段清理。私有挂接可增 optional 方法引用，与 optional 任务引用互斥；不引入方法/任务实现头。`回收未消费方法治理场景`在调用读取器完成核验后取得scene递归锁，再次核对完整快照、无外来引用及空事实列表；在该锁内先以完整预期CAS删除三个归属字段，再调用现有`删除空场景`清除本场景及父边。归属字段仍在时隐式Vm参与者使`删除空场景`返回场景非空，不能直接调用并把失败吞掉。归属已清理后任何失败保留现场并工程终止。

方法治理 S/D只允许目标 Vm、来源启用 F、启用类型根、0/1准确值；首次初始化无状态动态，同值不建立变化；本叶不接受方法动作动态或方法场景混入现实主体状态。中立共享概念不属于内部治理实例。普通场景挂接 Vm、F、C(M)、其S/D必须拒绝；其它世界不能通过裸节点引用绕过。

方法版`添加治理状态/添加治理动态`的末尾只读概念服务由world传入既有`特征概念服务_`，不保存额外服务指针、不改变场景构造器或状态ABI。按1160，S的`特征类型概念节点`实际保存建立时的具体FC，允许是启用FT根下的历史子概念；不能要求该字段等于FT根或方法当前FC。逐个状态调用`比较单特征概念(S.FC, S.FC)`，仅在结果为`已完成`、关系为`同一`且返回`特征类型根 == 方法.启用特征类型概念节点`时通过类型核验。概念读取/比较未完成属于工程异常，不能当正常类型不相容；完整比较确认其它FT时按既有挂接不一致合同拒绝。其它强归属、准确值、时间和锁要求不变。这是对已有下层特征概念公开能力的显式只读依赖，不允许场景反向包含方法类或world实现。

### 5.2 内部治理世界owner

world继承新方法世界协作接口，新增 `bool 装配方法读取(const 新方法治理对象读取接口&) noexcept`；只在根初始化前装配，同一指针重入无变化。保存`方法读取_`和构造已取得的`特征服务_`引用。方法与任务reader分别保留，不强迫所有旧task/mock实现方法纯虚函数。

`发布新方法治理场景组`准备全部C后，一次组合方法片段及所有C片段；有联动F准备时，通过特征owner的`提交顶层I64更新`完成同一核心，不先发表C或M。world不能自行决定停用哪个方法、不能直接改F；调用者持有准备对象并负责完成/结束。world只做组合发表和新M/C结构读回，批次输出按传入引用组顺序。联动旧F核心已经变化但派生概念/旧Vm专属概念尚未收尾，此时不得读取旧M完整语义来误报不一致；必须返回方法owner完成/结束特征更新、刷新旧EC后，再读旧M与组织旧S/D。

已有 `读取范围治理参与者` 按记录种类选择正确reader；共同根查询完整覆盖C(T)、C(M)。已有任务迁接的根子场景扫描必须识别并略过已完整证明的C(M)，方法迁接同样略过合法C(T)，不把未知子场景当合法空场景。任务迁接还须覆盖其根/C(T)参与者枚举：kind3的方法引用由method-reader和C(M)强归属独立核验后保留，仅作为引用，不纳入任务状态或任务S/D迁移；不能只允许任务/现实两类而在重启时拒绝自己已建立的合法方法引用。方法迁接中对任务显式引用采取对应的只读验证，不跨owner移动事实。

`完成方法特征变化`先读回 M/Vm/F/EC/C(M)和两S的完整归属，前后准确值不同、时间严格增加后建立/复用唯一原子D，挂入同一C(M)，再次完整读回；调用方法版场景S/D挂接时显式传入既有`特征概念服务_`，使场景独立核验历史FC所属FT。重复只复用同一S对，不按最近时间猜变化，不复制现有D。`读取方法特征变化`完整检查场景S/D和相关入边，发现孤立/异场景/重复D进入工程链；合法首次无变化返回空。

本叶不调用经验因果生成，不把事实变化推断成已知或未知动作；因果层仍可读取合法共同范围内的已有材料，但不新增因果事实。

方法类继承新方法读取接口，构造在现有参数尾部加入`新_状态类& 状态服务`并保存引用，状态类只追加`friend class 新_方法类`。新增：

新建步骤：

1. 私有准备M、头、Vm、参数、配对；通过特征owner建立F并写启用1；建立只归Vm的专属存在概念。初始F没有执行状态/动态。

3. world准备C(M)，组合一次发表M根成员、Vm强归属、C(M)归属和父场景关系；发表前不交付M，发表后全部读回。
4. 只有明确零发表才能撤销本次私有材料。发表不明或读回不一致保留M/F/C现场并工程终止，不删除已公开材料。

普通重复登记只复用已完整M/Vm/F/C，不重置启用，不增加统计或状态，不覆盖学习结果。方法知识C/R仍在方法树，参数规格仍在Vm，模拟材料不移入C(M)。

## 7. 两个启用写入入口

### 7.1 `修改启用状态`

取得方法锁，校验M、Vm、F、C与当前值；非法枚举返回原入口拒绝，合法同值返回无变化。保留当前服务结算父代/子代/按Q声明不能经普通`修改启用状态`改写的准入检查，不因特征化扩大方法停启权限。值改变时：

1. 用状态owner从真实F建立前状态，强时间为当前UTC，不能给前状态填未来预测值。本叶要求每一对前后状态时间严格增加；不凭未提供的全历史读取接口推导全局顺序。
2. 用特征owner准备并提交顶层I64更新；完成特征概念同步后更新Vm专属概念的正式组成，保持F为唯一当前权威。
3. 从真实F建立后状态，时间严格大于前状态；world组织S/D并完整读回。
4. 当前F已改变而后续失败时保留实际值和两S，不重做启用修改；本叶不声称跨进程恢复已完成。下次初始化见不完整场景即停止报告，不能当作无变化掩盖。

已有特征准备对象锁必须完整结束。时间溢出、特征/概念读回错误、重复归属都是工程错误；不返回停用、无变化等业务结果继续运行。

### 7.2 新Q方法替代旧固定加一方法

保留当前“只允许一个启用Q登记头”合同。先读取旧启用F并建立真实前状态，准备旧F=0，同时准备新M/Vm/F=1/EC/结构及C。

调用`发布新方法治理场景组({新引用}, 方法片段, &旧F更新准备)`：新头根公开、父代关系、旧F核心停用、C(M)强归属一次CAS。旧`方法启用状态字段`不得再参加业务发表。

发表后完成旧F派生特征概念与EC、建立后状态并组织到**旧方法C(M)**；新方法没有初始化变化动态。重复调用返回已存在Q方法，不再次停用旧方法或建立S/D。任何核心发表不明保留两代及准备来源，不再尝试新建Q头。

## 8. 副本与未采用生命周期

保留现有副本ABI，不扩展任务采用策略。`方法复制字段规格`必须退出旧M启用值复制；Vm的F与专属EC不当作通用方法结构字段深拷贝。每个源M单独读取当前启用，再通过特征/概念owner建立新F与专属EC；头、C/R、参数、内部方法调用仍按当前映射复制。新M有独立C，新混合实例根本身不是方法，不建Vm/C。

整个复制闭包或增补批次的根成员/实例成员/候选入口及新增M的全部C一次组合发表。不能每个M逐个公开造成半闭包。已有M/F/C保持不变，源M后续启用变化不追改副本快照。复制不生成运行次数、动作或变化动态。

采用回调仅在完整读回后调用，仍处方法锁保护中；返回不明、抛异常或出现任何外部消费证明时保留现场并工程终止，不走一般失败回滚。

明确未采用且全闭包未被外部引用时允许原合同回收：

1. method持有唯一方法锁，先检查本批图、创建账和所有F/专属EC；整批预检结束前不得删除任一C、字段或私有子项。本批方法图也通过§8.1核验字段键消费，不能只检查快照中的内容入边。
2. 对每个F和专属EC，method只核验自己拥有的Vm归属以及通过scene正式投影取得的C→F关系，形成精确允许外部字段关系编码；调用§8.2的两个owner预检。F/EC内部历史记录、聚合域和特征项完全由其owner枚举；方法owner不探测私有字段键，不把根快照当完整删除闭包。
3. world完整核对本批C均无S/D、无显式外来参与者、无子场景；场景owner按已发布空场景删除合同删除C及父场景关系和自身存在内容。不得调用“撤销未发布方法场景”。
4. method再撤销本批根公开及内部私有图；解除Vm引用后，使用空允许外部字段组再次通过F/EC预检，随后仍分别调用其现有owner清理入口。顺序不可倒置为删M后留悬空C。
5. 若整批预检不能证明未消费，所有材料原样保留并工程终止；若已经开始合法回收而后续遇到工程故障，保留剩余材料并终止，不能谎称零删除。此接口仅用于当前调用创建、明确未被采用的图，不是公开删除任意方法能力。

这不是跨owner单次删除事务。合法并发读取须按第10节锁与读回规则观察完整前后，不能在持scene锁时反向等待method；不能声称跨进程原子回收。当前基础追加合同不支持删除外部边，禁止偷偷扩展L1以伪装组合删除。

### 8.1 最小基础只读引用闭包提供者

在`核心/基础数据集.h/.cpp`新增公开、业务中立入口；不新增DTO、索引、事实节点或删除能力：

```cpp
基础结构操作状态 检查节点结构引用闭包(
    const std::vector<稳定编码>& 节点组,
    const std::vector<稳定编码>& 自有字段关系组,
    const std::vector<稳定编码>& 结构外部关系组,
    const std::vector<稳定编码>& 允许外部入向字段关系组) const noexcept;
```

一次共享锁内完整核验；调用者给出的每组编码均非零且无重复，节点组非空。自有字段必须属于节点组；结构外部关系至少有一端在节点组；允许外部字段必须属于组外节点、字段内容是节点引用且指向组内节点，且不得与自有字段重叠。允许组只是本次检查的精确结构材料，不是写入许可、owner名单或未来豁免。

内部抽出并复用`原子删除节点结构`现有的无写入校验，覆盖全部节点、全部自有字段、全部内外关系，以及字段内容和字段键引用。原删除入口仍用空允许外部字段组执行原独占锁内校验后删除；原返回和写入语义不变。实现可用私有`检查节点结构引用闭包已加锁`帮助函数；不得在共享锁内重入公开加锁入口。下段“任何字段键引用均拒绝”是新只读入口针对本轮非字段定义闭包的附加检查，不得反向加到原删除入口，改变其原本允许完整集合内自有字段一起删除的语义。

完整性规则：遗漏自有字段或组内关系为`内部不一致`；组外仍有未列字段内容入边或接触该组的关系为`引用仍存在`。**任何以组内节点作为字段键的字段关系都必须拒绝**，即使其编码出现在允许外部组也不能豁免；本轮所有目标闭包均不是字段定义节点。组内自有字段如果以组内节点作字段键，同样不能通过本只读入口。底座不猜方法、特征、概念的业务类型。

零/重复/不合形状输入返回`入口拒绝`；具名节点消失返回`节点不存在`；具名字段或关系不存在返回`引用不存在`；资源分配失败返回`资源失败`；索引或容器不变量错误进入工程终止链。`已完成`只证明本次锁内给定结构范围的引用闭合，不证明调用者有删除权限，不提供跨调用快照或回收保留锁。整个入口零事实写入。

两个函数均为公开只读、`const noexcept`，仅供本叶方法owner的同次私有创建/明确未采用回收调用，不暴露私有节点编码，不增加通用物理删除入口：

```cpp
// 新_特征类.h/.cpp

    稳定编码 特征节点, 稳定编码 预期特征概念节点,

    const std::vector<稳定编码>& 允许外部入向字段关系组) const noexcept;

// 概念_存在类.h/.cpp

    稳定编码 专属概念节点, 稳定编码 对应存在节点,
    const 存在概念特征项& 预期特征项,
    const std::vector<稳定编码>& 允许外部入向字段关系组) const noexcept;
```

F入口持现有特征递归锁，确认无联合更新占用、顶层无父/子特征、无单位、无实例输入区间、无归组标记。F当前概念必须为给定FC，FC正式材料类型为I64；当前值和标准值等于初始值，完整历史恰有该值且命中次数恰为1，历史聚合域恰为`[初始值,初始值]`。本叶调用值只允许0/1，但通用特征owner不硬编码方法启用语义。

F owner按自己的字段结构完整枚举F、唯一历史命中记录、唯一历史聚合I64域及其全部字段；核验命中记录的类型/所属F/准确值/次数、聚合域的I64表示，不允许其它私有子结构、额外字段或未知关系。共享FT/FC、类型/字段定义节点不是删除集；只检查引用它们的自有字段，不递归回收共享概念。枚举后的完整节点、自有字段、结构关系及调用者精确允许组交§8.1核验；不得仅从公开DTO猜私有节点或从F根快照断言无消费。

EC入口持现有存在概念递归锁，确认专属种类、对应存在相同、完整特征投影恰为给定一项、无名称、无上位/下位概念、恰一存在概念图根组织边。由EC owner枚举EC和唯一私有特征项节点，核验其类型、FT/FC引用与全部字段；共享FT/FC及图根不进入删除集。EC根组织边作为精确结构外部关系交§8.1；其余组外入边只允许调用者明确给出的Vm→EC字段关系。私有特征项任何单独外部消费均拒绝。

两入口成功仅正常返回；结构不符、材料曾被使用/改变、外部消费、缺失、任何底座非`已完成`或异常均记录日志、弹窗并工程终止，不返回`false`冒充“可回收/未采用”，也不拆任何字段。方法调用方仍先核验F无状态，并完成M/Vm/场景完整未消费判定；owner预检不替代上层生命周期权限。

F的允许组只含method自己正式Vm→F关系及scene读回的`启用特征归属字段关系`；EC只含method正式Vm→EC关系。未发表时这两组为空；解除全部Vm/C引用后的再次检查也为空。不能按来源节点整体放行、不能豁免一个字段键、不能把任意关系编码混进允许组。

回收由方法唯一锁贯穿，同次尚未交付或明确未采用的批次不得再开放新的合法采用/消费；scene读取遵循§10的先解scene锁再读method、最终重取scene锁核对当前归属协议。预检不保证绕过owner直接写基座的非法并发；一旦发现这种变化必须停止，不能据旧预检继续拆除。没有新增保留令牌、后台清理器或跨owner事务。

初建尚未形成完整F/EC准备时的错误清理仍按本次实际创建账处理，只有确证从未交付、没有外部调用者取得这些身份的私有半成品才可走原清理分支；不能把已完整交付准备或已发布后回收降格为“创建失败”来绕过上述全批预检。根级创建快照可作辅助读回，但不得继续命名或宣称为完整未消费证明。

## 10. 锁、装配、失败及恢复

### 10.1 锁与完整读取

- 方法类递归互斥是M/Vm/F归属、复制与启用写入唯一串行门。现有任务→方法调用方向保持；方法不得反向取得任务锁。
- 新建准备和更新保持方法→特征→基座顺序；world不得持scene锁调用method reader，scene中立方法reader调用亦在scene锁外。
