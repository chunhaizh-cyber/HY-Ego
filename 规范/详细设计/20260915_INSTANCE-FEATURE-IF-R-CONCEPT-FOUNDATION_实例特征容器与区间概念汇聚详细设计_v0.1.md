# 实例特征容器与区间概念汇聚详细设计 v1.0

重新 S0 基线：b3fef3ef。状态：可执行；I64 R 已发布为成功零 FCr 输出。

## 已确定闭环与上游停点

```text
输入(E,C,P,FT,候选值,G0)
-> L3 同截止读取 IF/R
-> 首次 / 后续 / 结构异常分类
   -> 结构异常：固定结果、零业务写、释放锁后尽力诊断
   -> 对全部 R区间材料调用 FT 归组规则
      -> 唯一命中：零F写入，更新R项区间材料快照
      -> 未命中：调用已发布的四 owner 原子特征出生提供者
         -> FCv 已发布 + F内容/位置/已知引用/F→FCv同次发布并读回
         -> 以新F建立兄弟R项
      -> L2存在 owner 中性IF/R一次写集与同截止读回
      -> 实际R变化后，按已发布归并规则进行一次R→FCr汇聚
```

`ea195241` 的四 owner 提供者已满足 F→FCv 同次发布和读回，不得退回旧三 owner 定位事务，也不得顺序创建无 FC F 后补写。4115 v0.5 已明确当前采用不参与R归组；漂移内候选不形成F，而按FT规则更新R区间材料快照。两类规则都逻辑并物理归正式特征类型定义 owner，并由直接上游 `FEATURE-TYPE-R-INTERVAL-RULE-PROVIDER` 冻结持久表示、公开读取 ABI及归并输出到既有 I64 FCr 概念定义的映射。该上游只启用已有 I64 FT；非I64无规则时返回未启用且零 IF/R 写。概念 owner 只消费归并输出创建/复用概念和直接上位边；需要新增非I64概念定义或规则时必须另立计划冻结。本详细设计不改变1130、4110、4115、7150或7160。

## L3 分类、L2中性操作与诊断

新显式入口位于 `海中鱼巣/业务/应用服务.特征概念类.h/.cpp`，不得改变旧 `处理类型观察` 或 `收敛类型观察` 的语义。入口先取得同一 `Gread/H`，然后只读取完整 IF/R；当前采用既不读取也不参与R归组：

| 读回结果 | L3结论 | 写入 |
| --- | --- | --- |
| IF/R 均未找到 | 首个R | 建立 F，再建立以该F为形成成员的首个 R项。 |
| IF/R完整 | 归组 | 调用FT规则；唯一命中则只更新R区间材料快照，形成新R才建立F。 |
| 读取成功但出现半结构、空R项、缺区间材料或多命中 | 结构异常 | 零 FCv、F、IF/R、采用及汇聚写。 |
| 读取失败、漂移、预算不足或退出 | 原具名非成功 | 零业务写；不伪装成结构异常。 |

`海中鱼巣/领域/数据服务.存在类.h` 的 IF/R 接口只接收已经形成的中性目标结构及预期快照，负责读回、一次写集、六关系、区间材料、引用与形状核验。它不得根据当前采用、候选值或缺失 IF/R 解释首个R、归组、形成新R或结构异常；预期快照不再成立时返回漂移或引用冲突，零本次写。当前采用仍由既有存在 owner 入口独立变更，IF/R不得隐式改写它。

普通应用在 `海中鱼巣/装配.普通应用.cpp` 私有构造一个 `noexcept` 诊断适配并注入特征概念应用服务。适配只记录模块、入口、结构异常分类、E/FT及已持有的截止摘要；不为日志新增读取或写入。L3先固定返回结果、退出自身 mutex；普通应用调用入口也必须退出 `上下文锁`，之后才调用适配。适配依次尽力调用 `记录逻辑错误日志` 与同因 `MessageBoxW(nullptr,...)`，捕获全部 C++ 异常并忽略日志返回值和弹窗失败。它不是UI线程调度器、机器结果或恢复材料；无窗口/非交互环境可能看不到弹窗。

## 后续代码位置与禁止项

既有四 owner 出生提供者不属于本计划，故其 L1、定位特征或概念 owner 文件没有本计划写权。`FEATURE-TYPE-R-INTERVAL-RULE-PROVIDER` 发布后，本计划才可扩展存在、特征、特征概念应用和普通应用装配的既有文件：装配在存在类构造前登记/读回六关系类型并末参数注入 `实例特征结构交付`，随后构造定位服务和特征概念应用服务；装配不调用新入口、预建IF/R、启动线程或进入阶段21。

R的 I64 分组仍只按完整准确值相等；非I64只调用FT的“候选值对R区间材料组”归组、区间更新和代表值规则，未启用时零 IF/R 写。R真实变化才进行一次上位 FCr 汇聚；汇聚失败保留R，不回滚、不回执、不自动重试。按存在持有特征变更只在 F/IF/R 成功后独立调用既有当前采用操作；其失败不声称获得阶段21可用实际F。

## v0.8 施工合同与阻断

L2 的请求、结果和投影采用计划 v0.8“L2 IF/R合同”的精确 C++ 名称、字段和成功谓词。`实例特征结构交付_v2` 新增唯一 `R项材料属性类型`，以 L1 `U64组` 属性存放 `{材料格式版本,材料类别,规范化载荷...}`；六条稳定关系类型不变。目标不同使用单存在 owner 写集，局部键先全部新节点、再全部新关系、再值和属性槽，退出集合仅包括当前 `R集合→旧版本` 关系并按稳定编码升序。当前完整投影和退出读回是提交成功的必要条件；发布未知只以原幂等键读回收束。

L3 请求、结果、既有I64出生调用和单次汇聚映射采用计划 v0.8“L3入口与未裁决上游漂移”。`归并特征R概念` 的非零 I64 输出目前与成员FCv同 FT、同域；7160 因而要求概念服务复用FCv，不能建立所要求的 FCr→FCv 上位边。这个冲突不是 L2 编码、装配或执行错误，必须先由正式规则裁决 I64 R 的 FCr 语义，并由新的特征R规则提供者结果发布；在此之前不得写生产代码或将计划登记为可执行。


## v0.9 I64 零 FCr 裁决

I64 单点 R 的同步归并在 R 真实变化后仍调用特征类规则提供者，但成功结果固定为已归并零输出与空项。L3 将其计为汇聚完成零写，不调用概念 owner、不给 FCv 填写上位、也不建立任何 FCr 关系。旧 FCr 请求键序列在 I64 零输出分支不消耗；非 I64 规则和其它归并失败映射不变。实现前仍须取得该规则修正发布结果并重新 S0。
