## 2. 目标与边界

新增一个实例特征领域业务发布类及唯一公开根：

```text
公开完整批次请求
-> 从公开请求形成请求意图摘要和唯一 L1 幂等键
-> P15 provider 前探测
-> P38 provider 前预读同批次4170记录
-> 仅两账均未找到时逐项调用 P36 形成完整规格
-> 一次校验全组并形成确定性 L1 v2 写集、通用读回计划、执行证据摘要和 P39 草案
-> P39/P37/P15 恰一次单事务提交
-> 用 P38 记录、P15 首次读回或本次已验证材料形成完整有序业务结果
```

本叶只支持实际存在 I64 **初始**项目；不接受换代或混合批次，不调用 P8 旧单项建立入口，不形成多个事实代次。它不实现 P32 门面、状态/动作动态、因果、任务、结算、恢复装配、运行期接线、旧入口删除、集成验收或 STEP-5。

## 5. 批次身份、L1 幂等键与双摘要

本叶不接受第二个公开幂等身份。4170 批次身份唯一确定 L1 写集幂等键：

```text
初始特征批次 L1 幂等域 = 0x0F
要求 1 <= 批次.值 <= 0x00FFFFFFFFFFFFFF
L1幂等键.值 = (uint64(0x0F) << 56) | 批次.值
```

因此同一批次不可能合法映射到多个 L1 键；同键同请求由 P15 返回首次结果，同键异请求冲突，P38/P39 再证明4170记录来自同一次 L1 首次事务。该映射与既有0x01—0x0E及已冻结0x10域不重叠。

领域操作标签固定为 `U32 0x00010F01`。请求意图摘要按 P15 通用编码写入：魔数、格式版本、操作标签、顶层合同/规则、批次、期望代次、项目数及每项 P36 请求全部字段声明顺序。它不得包含 P36 返回、稳定编码分配、本地键、锁或算法分支。

执行证据摘要只在 P15/P38 均未找到后形成，固定编码请求意图摘要、P36/P38/P39/P15合同版本、共同事实截止、按项目顺序的全部 P36 规格、规范化 L1 写集和规范化通用读回计划。摘要使用 P15 的标准 SHA-256；全零为内部不一致。

## 6. provider 前双账收口

公开函数：

```cpp
实际存在I64初始特征批次发布结果 发布实际存在I64初始特征批次(
    const 实际存在I64初始特征批次发布请求& 请求);
```

在访问 P36 前固定执行：

1. 纯值校验请求、批次映射范围、非空项目、连续顺序、共同宿主请求、共同代次、定义请求唯一和数量上界；失败立即入口拒绝。
2. 形成请求意图摘要和 L1 幂等键；异常按资源失败/内部不一致返回。
3. 调用 `L1_.探测幂等` 恰一次。异义、隔离、坏记录和入口异常立即映射，不访问 P36。
4. 调用 `批次数据操作_.读取发布记录(请求.批次)` 恰一次。许可拒绝、未知格式、资源失败和损坏保持原分类。
5. 两账组合只允许：

| P15 | P38 | 收口 |
| --- | --- | --- |
| 未找到 | 未找到 | 进入首次 provider 路径 |
| 同义已发布 | 已读取 | 互证 P15 首次完整读回、P38记录、确定性键和公开请求；完整才返回幂等读回 |
| 异义冲突 | 任意 | 幂等冲突，零 provider |
| 未找到 | 已读取 | 内部不一致；禁止猜测旧键或补账 |
| 同义已发布 | 未找到 | 内部不一致；禁止只靠 L1 伪装4170成功 |

幂等互证要求 P38 记录为非空完整初始批次，批次/规则/宿主/项目数/顺序/定义/来源与公开请求一致；P15 首次映射和首次完整读回精确证明每项槽、两关系、值和属性槽在记录发布代次共同建立，I64值等于请求，且无夹带。任一缺失、额外、重复、错代次或错角色均整体内部不一致，不返回部分项目。

## 7. 首次规格集合准入

仅双账未找到时，按容器顺序逐项调用：

```cpp
实例特征_.形成实际存在I64初始特征写入规格(项目请求)
```

每项恰一次，任一非 `已读取` 立即按原分类返回；已取得的纯值规格直接销毁，不提交半批次。全部规格形成后一次校验：

- 合同/规则完整，项目顺序恰为 `0..N-1`；
- 全部 `事实截止代次 == 请求.期望事实代次`；
- 宿主事实和宿主读取见证相同，世界根相同；
- 定义编码两两唯一，且定义读取见证与公开请求逐项相等；
- 四个实例特征登记见证全组相同且各自完整互异；
- 每项来源与宿主同世界，初始值在定义范围，`当前匹配槽数量 == 0`；
- 不允许空规格、坏成功、排序后再解释、去重后悄悄丢项或跨宿主拼批。

规格组只是同步栈内不可变值，不形成缓存或第二账。P36 调用期间任何事实推进最终由 L1 v2 期望代次零写拒绝。

## 8. 确定性写集、读回计划与 P39 草案

第 `i` 项（从0开始）的四个本地键固定为：

```text
实例槽 = 4*i + 1
宿主关系 = 4*i + 2
定义关系 = 4*i + 3
当前值 = 4*i + 4
```

数量门禁保证 uint32 不溢出。写集按项目顺序形成：每项恰 `1普通节点 + 2关系 + 1 I64值 + 1属性槽变更`，退出组为空。宿主关系为 `宿主 -> 实例槽`、角色1；定义关系为 `实例槽 -> 定义`、角色2；值属于实例槽，属性类型为 P36 当前I64值属性类型，来源为 P36 来源；属性槽指向同项当前值本地键。不得夹带登记、宿主、定义、来源或其它槽位写入。

通用发布后读回计划规范排序并精确覆盖：

```text
全部新实例槽、宿主关系、定义关系、I64值和属性槽
+ 去重后的共同宿主、全部定义、全部来源
+ 四个登记节点见证
```

新事实期望本次发布代次；既有见证期望共同固定代次。计划不得为空、重复、遗漏或加入其它业务对象。

P39 草案按同一顺序形成：共同宿主；每项种类固定初始；实例槽/两关系/当前值使用上述本地键；定义、来源和四种类型使用 P36 稳定编码；`写前当前值` 为空。草案、写集和读回计划必须一一覆盖后才形成执行证据摘要。

## 9. 单事务提交和结果映射

首次路径只调用：

```cpp
批次数据操作_.提交带特征批次记录(写集, 草案)
```

恰一次。不得先调用公开 `提交写集`、逐项提交、失败重试或事务后补4170记录。

- P39 `已提交`：记录、映射、发布代次和每项四编码必须完整且与规格/本地键一致；形成 `已提交` 完整有序结果。
- P39 `精确重复`：只可能是探测后并发首次提交；P39 已互证首次键/意图和记录，按同一公开请求形成 `幂等读回`。
- 入口拒绝、未找到、已退出、代次漂移、幂等冲突、许可拒绝、未知格式、资源失败逐类映射；不得降级。
- P39 返回发布后读回矛盾或隔离时，返回 `内部不一致`、非零已发布代次、`L1发布已存在=true`，项目和记录为空；不得删除或补写已经发布的 L1/4170事实。
- 任何坏成功、映射数量不是 `4*N`、本地键缺失/重复、记录项目不完整或结果顺序不连续均为内部不一致且零业务载荷。

成功项目只包含本批次项目并保持0..N-1顺序，不扫描或返回宿主其它槽位。

## 10. 并发、异常与生命周期

发布类不持有自有互斥量。P15 shared/unique 许可和 P38/P39账许可分别裁决并发；探测未找到后的竞争由 P37/P39 单事务最终收口。同批同义并发只一笔首次发布，其余幂等读回；同批异义由同一确定性 L1 键冲突；不同批次可并行读取 provider，最终按 L1 唯一事务串行提交。

函数不得同时持有 P36 服务锁、P38共享许可或 L1探测许可跨下一 provider 调用。所有依赖返回值先复制为调用方自有值，锁序仍由 P37/P39 固定为 `L1事务域独占 -> 4170账独占`。

摘要、vector 和 DTO 分配失败在发布前返回资源失败。未知异常在发布前为内部不一致。进入 P39 后以其 `L1发布已存在` 和代次区分发布前/后失败；发布后不得抛出服务边界、重试、回滚或返回部分载荷。
