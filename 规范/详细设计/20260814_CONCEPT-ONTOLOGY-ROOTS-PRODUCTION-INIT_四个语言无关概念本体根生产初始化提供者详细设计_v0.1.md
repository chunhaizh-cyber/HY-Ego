# 四个语言无关概念本体根生产初始化提供者详细设计 v0.1

日期：2026-08-14

计划身份：`CONCEPT-ONTOLOGY-ROOTS-PRODUCTION-INIT`

当前设计状态：BIZ 合同已冻结，基于预冻结 DATA ABI 的 BIZ 并行实现候选已开始；DATA 实现、工程登记、装配、启动接线和动态验证均未完成。

## 1. 目标与完成边界

本叶在 SELF-FORM 成功打开阶段 18 控制门后，经普通应用唯一 `L2概念结构聚合服务` 取得同一 `L2概念结构服务`，建立或幂等收敛以下四个语言无关空本体根：

```text
存在
特征
动态
因果链
```

每个角色都必须正式按角色读回，最后再次读取全部当前根，证明当前恰四根、角色齐全、根身份互异、根角色关系永久当前、直接上位为空、首次幂等请求见证一致且零第五根，才把调用方拥有的完整值式材料无抛出发布。

本叶不建立场景概念根，不读取或建立语言、词条、词性、名称，不建立普通概念、二次特征、直接因果或普通因果链概念，不扫描动态列表，不进入方法根、自我线程、投影、信号、宿主或跨进程恢复。

## 2. 权威依据与当前事实

机器语义依据：0050、2220 v1.3、4240 v0.4、7140 v1.2、8120 v0.8。

业务依据：`BIZ-L2-001-03`、`BIZ-L3-001-03-09`、SELF-FORM 成功后的阶段 18 控制门。

当前正式 `main` 中尚不存在 `L2概念结构.数据.h`、`服务.L2概念结构.ixx` 或 `服务.L2概念结构聚合.ixx`。旧 C1 / A1 v0.1 的按词性维度根合同已经与四根规范冲突，不是本叶 ABI。用户明确授权 BIZ 侧决定所需基础数据公开服务并交由“继续执行当前计划”实现；本设计已把下述 root-only C1 / A1 合同发给 DATA 任务。

因此本叶允许在不登记工程、不修改装配 / 启动、不占用 Git 发布租约的前提下形成 BIZ 源码候选，但在 DATA 正式结果发布前不得宣称代码可编译、可接线或计划可激活。

## 3. 最小 DATA 公开合同

### 3.1 公共身份

`L2结构公共.数据.h` 增加 `L2概念身份`，并在保留节点族数值 8—10 的前提下登记 `L2节点族::概念 = 11`。本叶不定义 8—10 的语言、词条、词性 DTO。

不新增 deadline、墙钟、sleep、取消或忙重试合同；代次只使用现有 `L2结构请求头::期望事实代次` 和 `L2结构结果头`。

### 3.2 根 DTO

```cpp
enum class L2概念本体根角色 : std::uint8_t {
    存在 = 1,
    特征 = 2,
    动态 = 3,
    因果链 = 4
};

struct L2概念本体根角色事实 final {
    L2概念本体根角色 角色;
    L2概念身份 根概念;
    稳定编码 关系稳定编码;
    L2生命周期 生命周期;
};

struct L2概念本体根事实 final {
    L2概念身份 根概念;
    L2节点族身份来源事实 身份来源;
    L2概念本体根角色事实 根角色;
    L2结构幂等身份 首次幂等身份;
    std::uint64_t 首次期望事实代次;
    std::vector<L2概念身份> 直接上位概念;
};
```

完整根必须满足：根身份非零；身份来源节点族为概念且节点编码等于根身份；owner、节点、族锚点、关系类型和族归属生命周期在结果截止当前；根角色闭合、角色关系非零、关系根身份与外层一致且未退出；首次幂等身份和首次期望事实代次非零；直接上位概念为空。节点、族归属和根角色只是每根写集的必含结构，不是“精确仅三事实”；C1 还必须在同 owner、同一根建立事务内持久化首次请求见证，并以 C1/C2/C3 共享的正式直接上位关系类型在同截止枚举空组。内部属性类型和值槽由 DATA 设计冻结，不进入 BIZ 公开 ABI。

直接上位空组是 8120 的正式读回材料，不授权阶段 18 调用 C2。后继 C2 仍须在写前拒绝把任一本体根作为下位，C1 读取不得过滤底层错误父边后伪造空组。

### 3.3 三项 C1 能力

```cpp
L2概念本体根写入结果 L2概念结构服务::建立概念本体根(
    const L2概念本体根建立请求& 请求);

L2当前概念本体根读取结果 L2概念结构服务::按角色读取当前概念本体根(
    const L2当前概念本体根读取请求& 请求) const;

L2当前概念本体根组读取结果 L2概念结构服务::读取全部当前概念本体根(
    const L2当前概念本体根组读取请求& 请求) const;
```

`读取全部当前概念本体根` 是 C1 取得当前根事实截止的唯一入口：该请求的 `期望事实代次 = 0` 明确表示“选择调用时最新当前快照”，成功必须返回一个非零事实截止；零请求返回事实代次漂移或未找到是内部不一致。漂移后的零代次正式重读还必须返回不早于调用前已知截止的快照，BIZ 才能接受并更新本地守卫。非零值表示“只接受当前事实代次仍等于该值”，不相等返回零变化、无首次结果的 `事实代次漂移`；成功结果的事实截止必须精确等于请求期望代次。按角色读取和建立请求必须使用非零期望事实代次，单根读成功的事实截止同样必须精确等于请求期望代次。不得要求 BIZ 直达 L1 取得首次截止，也不得把 `0` 解释为历史代次、无效请求或任意忽略并读取。公开纯值请求 helper 必须按此分别校验三类请求。

建根请求固定为共同请求头、非零幂等身份和闭合根角色。每根由概念 owner 在一份写集中原子建立概念节点、概念族归属、根角色关系、首次幂等身份与首次期望事实代次持久见证，并预登记 / 复用直接上位关系类型以支持同截止空组枚举；这些是必含事实，DATA 可以增加事务完整性所需的内部结构事实。服务不公开根退出、替换、普通概念、签名、DAG、支持或名称入口。

`L2概念本体根写入结果` 与 `L2当前概念本体根读取结果` 各用 `optional<L2概念本体根事实> 本体根` 承载单根，`L2当前概念本体根组读取结果` 用 `vector<L2概念本体根事实> 本体根` 承载根组。写成功只允许 `已提交 / 精确重复`，必须含完整根、严格晚于实际建立请求期望代次的单一事实截止，以及等于该截止的变更代次；单根读成功只允许 `已读取` 且 optional 有值；全组读成功允许 0—4 根，零根仍是成功。任一非成功必须同时满足 optional 为空或 vector 为空、变更事实代次为空；否则不按其枚举字面降级，直接映射内部不一致。通用 C1 在角色尚未建立时可返回空载荷 `未找到`，但 BIZ 在“预读已有或建根成功”之后的同代正式读回若未找到，必须映射内部不一致。全组结果按角色严格升序、角色不重复、根身份互异且在同一截止完整。第五根、非法角色、错误父边、退出根、混代、写成功截止未推进、读入口返回写状态、写入口返回读状态、未知状态或其它坏形状属于内部不一致。

资源失败和底层发布结果未知统一映射现行 `L2结构状态::资源失败`，调用方必须保留原完整请求重放；不新增公共状态数值 15。

### 3.4 单服务 A1

唯一聚合为 `L2概念结构聚合服务`，只持一份 non-owning `L2概念结构服务&`，提供 const / non-const `取得L2概念结构服务()`。聚合没有 owner、写、锁、缓存或 DTO 映射。

普通应用持有唯一概念服务和唯一概念聚合。BIZ 只能按以下路径消费：

```text
四本体根生产初始化提供者
-> L2概念结构聚合服务::取得L2概念结构服务()
-> 同一 L2概念结构服务
```

旧 `L2语言概念结构聚合服务` 不与本聚合并存。后继语言表达结构如需聚合，必须具名设计并不得形成第二 C1 getter。

## 4. BIZ DTO 与物理归属

| 文件 | 归属 | 内容 |
| --- | --- | --- |
| `海中鱼巣/业务/四本体根生产初始化.数据.h` | 阶段18 BIZ | 固定四幂等身份、请求、状态、逐调用证据和值式发布材料 |
| `海中鱼巣/业务/初始化.四本体根.inl` | 阶段18 provider 模块所属单源正文 | 请求锁定、四根收敛、正式读回、互证和值式发布 |
| `海中鱼巣/业务/提供者.四本体根生产初始化.ixx` | 阶段18 BIZ provider | 唯一聚合引用、调用锁、选择槽、四请求槽和发布槽 |

生产 provider 不可复制、不可移动。普通应用装配恰好拥有一个生产 provider；成员生命周期必须短于概念聚合，析构顺序反向安全。模块的公开构造能力只供普通应用装配和生产外验证复用同一正文，不授权第二生产入口或全局单例。

请求的四个角色由四个具名字段闭合，不接受可扩展角色 vector。默认常量分别用于存在、特征、动态和因果链；四者非零互异。首次合法请求在任何 C1 getter、读或写之前锁定到 provider，读取失败、写入失败或部分成功均不清除，直至 provider 析构。异义请求零 DATA 调用返回选择冲突。

结果保存初始与最终全组读取的完整“实际请求 + 调用结果”、每个角色零至两次完整“实际建立请求 + 调用结果”和一次完整“实际单根读取请求 + 调用结果”，并把每次零变化漂移后的正式全组重读与触发角色、调用前已知截止、实际请求及调用结果绑定；不得用后一次调用覆盖前一次证据。provider 另为每个保存请求持有“发布结果仍未知、进入下次调用必须原样重放”标记；结果把本角色进入时的待重放完整请求作为 optional 证据回显。成功形状必须证明：若该 optional 有值，本角色第一次建立调用必与其逐字段相等，即使初始预读已经出现该根也不得跳过；没有待重放请求时，初始预读或更早角色触发的漂移重读在本角色处理前已取得该根才允许零次建根且必须逐字段等于发布根，全部这些处理前快照均缺失时才允许建根；零代次漂移重读截止不早于调用前截止，全部非零单根和最终全组结果截止精确等于各自请求守卫；全部漂移重读、四次单根读回、适用的写结果和最终全组均完整；成功写根的首次幂等身份 / 首次期望事实代次与实际发送请求一致；漂移重读已出现的根、成功写结果、随后单根正式读回与最终根均逐字段相等。所有成功负载先完整构造并自证，再以编译期证明无抛出的 `optional::swap` 最后交换发布；结果构造或复制失败时正式发布槽仍保持旧值。

## 5. 编排顺序

```text
校验请求
-> 锁定或复核同上下文选择
-> 经概念聚合取得同一 C1
-> 读取全部当前根
-> 按存在、特征、动态、因果链循环
   -> 本角色有发布结果未知的待重放请求：不受预读已有根影响，先原样重放一次
   -> 无待重放请求且已有角色：正式按角色读回
   -> 无待重放请求、缺失角色且有保存请求：原样重放
   -> 缺失角色且无保存请求：按当前截止形成并先保存请求
   -> 建根已提交/精确重复：正式按角色读回
   -> 明确零变化且无首次结果的漂移：正式重读全组
      -> 角色已出现：正式按角色读回
      -> 仍缺失且本角色本次未重组：同角色同幂等身份按新截止重组一次
      -> 再次漂移：返回事实代次竞争
   -> 资源失败、异常、坏非成功形状或发布未知：保留原完整请求并把待重放标记保持为真后返回
-> 最终读取全部当前根
-> 四次单根读回与最终根组逐字段互证
-> 构造完整候选
-> 无抛出交换发布
```

建立结果为新提交时，其事实截止晚于调用前截止并推进本地读守卫；精确重复返回首次结果时，其截止可能早于本次全组预读截止，只能在更晚时推进本地读守卫，不能把已知较新截止回退到首次提交截止。随后单根正式读取和最终全组读取始终使用本轮已知最新的非零截止。

跨四根不是一个 DATA 事务。前项已发布后后项失败不回滚；后次同请求继续原请求收敛。重复调用预期零根写，但必须再次执行全组预读、四次按角色正式读取和最终全组读取，不得使用 BIZ 发布槽或缓存替代。

## 6. BIZ 结果状态

成功只有 `已发布` 和 `精确重复`，且必须携带完整 `四本体根发布材料`。其它状态均为空成功负载并保持旧发布值：

```text
请求无效
已发布选择冲突
当前根组预读失败
存在根形成失败
特征根形成失败
动态根形成失败
因果链根形成失败
单根正式读回失败
最终根组读回失败
事实代次竞争
根读回不一致
资源失败
内部不一致
```

`L2概念结构聚合服务::取得L2概念结构服务()` 是 `noexcept` 同实例引用 getter。概念服务不存在时普通应用不能完成装配，或消费端尚不能通过编译门禁；它不是阶段 18 已进入后的运行态结果，因而不设 `DATA能力未就绪` 状态，也不允许在 provider 中用空指针、可选 getter 或第二服务入口模拟这一分支。

任何未知 DATA 枚举、写入口返回读取状态、读入口返回写状态、成功空负载、非成功携带 optional / vector 根载荷、非成功携带变更事实代次或坏根形状都映射内部不一致，不得猜成功或按枚举字面降级。零代次全组预读 / 漂移重读返回漂移或未找到映射内部不一致；非零最终全组读和非零单根读只有空载荷、零变更的事实代次漂移映射竞争，同代未找到映射内部不一致。普通系统初始化把所有阶段18非成功映射到失败阶段 18；阶段 15 永久缺号且数值不复用。

## 7. 并发、异常与发布守恒

同一 provider 用一把调用 / 发布锁串行化完整调用。锁只保护 BIZ 选择、保存请求和发布材料，不取得 DATA 根事实权。最终工程登记必须把 provider 状态归入普通应用上下文的私有唯一成员或提供等强的单实例构造限制；当前隔离 `provider.ixx` 只有未登记候选身份，公开构造器不构成最终唯一性证明，在完成该机械归属前不得登记工程或宣称唯一 provider 已实现。不同普通应用实例不伪造跨实例单事务或跨进程恢复。

`std::bad_alloc` 映射资源失败；其它未预期异常映射内部不一致。任一异常或非成功都不能部分替换已发布 BIZ 材料。只有完整候选构造完成后执行一次 optional 值式交换。

## 9. 激活与完成声明边界

激活至少等待：M1 当前结果接受、退出和专项清理；root-only C1 v0.2 与单服务 A1 的正式设计 / 实现结果发布并清理；SELF-FORM 实现、接线、退出和清理；普通应用、启动、工程、构建和验证资源释放。届时从最新 `main` 机械匹配 DTO、签名、装配状态和固定身份占用。

本设计和当前源码候选只证明 BIZ 需求与编排已经形成，不证明 DATA 服务、provider、普通应用装配、阶段18接线、阶段17解除、任何构建或运行验证已经完成。
