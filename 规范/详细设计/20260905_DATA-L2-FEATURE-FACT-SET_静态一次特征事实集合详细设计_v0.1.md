# 静态一次特征事实集合详细设计

日期：2026-09-05

身份：`DATA-L2-FEATURE-FACT-SET`

版本：v0.1

状态：设计已冻结 / 等待代码实施

## 1. 目标与完成条件

在现有 `海中鱼巣.领域.数据服务.特征类` 中增加通用静态一次特征事实集合的数据操作。首叶完成条件是：集合稳定身份、不可变版本、全量成员换代、退出、当前 / 指定截止历史、按成员反向当前和按版本追溯均由同一特征 owner 的强类型合同闭合；不实现任何分类算法、概念关系或二次特征计算。

## 2. 当前事实与复用裁决

基线：`8edd1e02f8cbe73400710d06606a18d9dae8f41a`。

当前 `数据服务.特征类.ixx` 已具备：

- 一个私有 `L1所有者范围写端口`、owner 校验、当前 / 历史节点关系值读取；
- 普通特征新增、换代、退出、按身份 / 类型和值查询；
- 派生定义新增、读取、退出与二元 I64 比较；
- 同 owner 写集、首次幂等、提交未知、正式读回和异常分类的可复用机械模式。

现有派生合同固定恰两个来源、实际阶次大于 1 且带比较注册，不能承载本目标。`二次特征类` 只包装行动方向型派生，保持零修改。旧 `服务.L2*` 禁止 import、调用、强转或复制。

## 3. 事实模型

```text
集合身份 S --当前版本(唯一当前)--> 版本 Vn
版本 Vn --成员(顺序,角色)--> 普通一次特征 F1..FN
版本 Vn --前版本(至多一个)--> Vn-1
S / V --集合族归属(角色 1 / 2)--> provider 集合锚点
```

`S` 长期稳定；`V` 和成员关系不可变。换代一次提交新 `V`、新全量成员、前版本关系和新当前版本关系，同时退出旧当前版本关系及旧成员关系。旧 `V` 与历史关系保留。退出一次退出 `S`、当前版本关系及当前成员关系，版本历史保留。

成员关系的 64 位 `角色或顺序` 固定编码为 `(uint64_t(顺序) << 32) | 成员角色`。顺序连续 `1..N`，角色非零，成员身份不重复。集合本身无原始值属性槽，不走普通 `特征类结点` 查询。

## 4. 公开 ABI

新增合同版本：

```cpp
inline constexpr std::uint32_t 特征类事实集合数据合同版本 = 1;
```

新增状态（数值顺序即冻结 ABI）：

```cpp
enum class 特征类事实集合状态 : std::uint8_t {
    已创建=1, 精确重复=2, 已换代=3, 已退出=4, 已读取=5,
    入口拒绝=6, 未找到=7, 目标已退出=8, 成员未找到=9,
    成员已退出=10, 当前版本漂移=11, 事实代次漂移=12,
    幂等冲突=13, 引用冲突=14, 数量超限=15, 结构未配置=16,
    资源失败=17, 内部不一致=18, 已可能发布=19
};
```

新增值式类型：

- `特征类事实集合身份 { 稳定编码 值; }`
- `特征类事实集合版本身份 { 稳定编码 值; }`
- `特征类事实集合结构类型 { 集合锚点, 集合族归属关系类型, 当前版本关系类型, 成员关系类型, 前版本关系类型, std::size_t 最大成员数; }`
- `特征类事实集合成员提交项 { uint32_t 顺序; uint32_t 成员角色; 稳定编码 特征; }`
- `特征类事实集合成员事实 { 稳定编码 关系; uint32_t 顺序; uint32_t 成员角色; 特征类结点 特征; uint64_t 创建事实代次; optional<uint64_t> 退出事实代次; }`
- `特征类事实集合版本事实 { 版本身份; 集合身份; optional<前版本身份>; optional<前版本关系>; vector<成员事实>; uint64_t 创建事实代次; optional<uint64_t> 退出事实代次; }`
- `特征类事实集合事实 { 集合身份; 版本事实; 稳定编码 当前版本关系; uint64_t 创建事实代次; optional<uint64_t> 退出事实代次; }`

请求 / 结果固定为：

```cpp
struct 特征类事实集合新增请求 { 合同版本; 期望事实代次; 幂等身份; vector<成员提交项> 成员; };
struct 特征类事实集合换代请求 { 合同版本; 期望事实代次; 幂等身份; 集合身份; 预期当前版本; vector<成员提交项> 新成员; };
struct 特征类事实集合退出请求 { 合同版本; 期望事实代次; 幂等身份; 集合身份; 预期当前版本; };
struct 特征类事实集合查询请求 { 合同版本; 期望事实代次; 集合身份; };
struct 特征类事实集合历史查询请求 { 合同版本; 读取事实代次; 历史截止事实代次; 集合身份; };
struct 特征类事实集合版本查询请求 { 合同版本; 读取事实代次; 历史截止事实代次; 版本身份; };
struct 特征类事实集合成员反查请求 { 合同版本; 期望事实代次; 稳定编码 成员特征; size_t 数量预算; };
struct 特征类事实集合结果 { 状态; uint64_t 事实截止代次; optional<uint64_t> 首次提交事实代次; optional<事实集合事实> 集合; };
struct 特征类事实集合版本结果 { 状态; uint64_t 事实截止代次; optional<版本事实> 版本; };
struct 特征类事实集合组结果 { 状态; uint64_t 事实截止代次; vector<事实集合事实> 集合组; };
```

字段在代码中按上列次序声明，所有结构提供默认相等性。`历史截止事实代次` 必须非零且不大于读取事实代次；成功结果截止精确等于 H。

```cpp

特征类事实集合结果 查询历史特征事实集合(const 特征类事实集合历史查询请求&) const noexcept;
```

## 5. 构造与兼容

保留现有构造函数原样；新增 overload，在原四个参数后增加 `特征类事实集合结构类型`。旧构造实例调用七入口统一返回 `结构未配置`、零载荷、零截止、零写。新构造必须验证锚点当前有效、四个关系类型当前有效且互异、最大成员数非零；配置坏形状同样只使集合入口不可用，不影响现有普通 / 派生入口。

这使首叶只修改现有模块而不强迫当前装配迁移。生产装配创建集合锚点 / 关系类型并改用新 overload 属具名后继，首叶不得宣称已接线。

## 6. 写入状态机

### 6.1 新增

验证请求、配置和 `G0`；逐成员调用本类普通特征查询并要求同 G0 完整；形成 `S + V1 + 两条族归属 + 当前版本 + N 成员` 的一个 owner 写集；提交；以首次 G1 走专用当前入口读回。任何成员为派生定义、集合结构或裸节点均拒绝。

### 6.2 换代

在 G0 完整读取 S，要求当前版本等于预期；验证全量新成员；一个写集新增 Vn、族归属、前版本、新当前版本与全量成员，同时退出旧当前版本关系及旧版本当前成员关系。不得拆成“删后加”，不得补偿删除。结果 `已换代` 或 `精确重复` 必须返回新完整集合。

### 6.3 退出

在 G0 完整读取 S 并核对预期当前版本；一个写集退出 S、S 的族归属、当前版本关系和当前成员关系。版本节点、版本族归属、前版本关系均不退出。成功 / 重复以首次 G1 历史读回证明退出闭包。

提交前任何失败零写。L1 返回成功 / 精确重复以后若正式读回失败，返回 `已可能发布`，仅保留首次提交代次；禁止返回半结构或补偿。

## 7. 读取算法

当前查询以 G0 双守卫读取 S、族归属、唯一当前版本、版本族归属和全部成员；逐成员调用 `查询特征` 并要求同截止。历史查询以 L1 历史节点 / 关系组在 H 重建同一闭包；晚于 H 的退出对 H 不可见。版本查询允许读已非当前的 V，并回显其前版本与 H 成员闭包。

反向查询先确认成员普通特征当前，再按“成员关系类型 + 目标端点”读取当前关系组，逐个回到版本及集合当前关系，去重并稳定排序；任一坏关系使整个集合查询 `内部不一致`，不得跳过坏项。超过预算返回 `数量超限` 且空组。

## 8. 失败优先级

固定顺序：请求形状 → 配置 → G0 / Gread 守卫 → 集合 / 成员存在性与退出 → 本族归属 → 当前版本预期 → 成员与关系闭包 → 数量预算 → 写入 / 读回。资源异常映射 `资源失败`；非预期异常或 L1 合同形状矛盾映射 `内部不一致`。非成功除 `已可能发布` 的首次代次外均空载荷、截止 0。

## 9. 依赖与禁止范围

模块依赖保持 `export import 海中鱼巣.领域.数据服务.特征值类`；只调用当前 L1 公开函数、本类已有公开 / 私有能力和特征值类公开能力。禁止新增对 `数据服务.二次特征类`、概念空间、4180 算法、旧 `服务.L2*` 或仓库层的依赖。

## 10. 未覆盖边界

首叶不创建业务名称，不判断“正面 / 侧面”，不解析轮廓，不形成样本归属，不计算方向，不修改二次特征，不迁移现有数据，不改生产装配，不提供无限历史时间线，不允许成员增量原地修改。
