## 1. 裁决与原目标边界

P14 v0.3 的代码提交 `bfae0a2a2a1e72a68fe0e611e88ada7f9446b73b` 已证明八文件可构建、
顺序390自检可达；独立验收提交 `a300acd47465e62b1df0366d600ec6eda878d0fe` 证明：
四个公开入口当前只有 `海中鱼巣/领域/自检.L1动态.ixx` 调用，生产运行期和合法生产消费者
调用数为0，P14专项正式日志命中为0，32个可执行函数未登记诊断责任。

这些事实分成两个边界：

1. **无生产消费者是 P14 原目标内的预期边界。** P14 是关系20状态迁移动能的提供者叶，
   只提供登记、纯值规格和十五项读取候选；P16 或其它后继组合器才可能成为正式消费者。
   P14 不得修改 P16、增加 P16 调用边或把生产原子发布塞入本叶。当前生产调用为0因此是
   `正式接线/正式读回` 的合同级 `NOT_APPLICABLE`，不是 P14 自身的代码失败。
2. **诊断与观察合同属于 P14 原目标内的最小修复。** 自检必须把结构化结果送到同一生产
   程序的正式启动观察边界，并在现有运行日志中留下可检索的人读记录；日志不是机器事实，
   也不把自检结果升级为生产服务验收。

P14 v0.3 已成立的 G7、入口变体3、`0x15000F01U`、幂等域 `0x0F`、L1 v2 意图编码、
十节点写集、事实互证、P13/P12、`0x44`、十五键读取、顺序390、八路径、单生产目标和
排除崩溃/重启/跨进程恢复全部保持不变。本版本不创建第二 exe、第二工程目标、第二装配、
第二自检解释者、恢复材料或新的领域机器语义。

## 2. `--self-test-exit` 与单目标验收适用性

用户冻结的是单一生产程序目标；现行 `AGENTS.md` 与历史正式验证均允许同一
`海中鱼巣.exe` 通过受控参数进入统一自检后退出，没有要求为自检建立第二 exe 或第二工程
目标。因此 Release 接受 `--self-test-exit` 本身不构成 ACCEPTANCE-01 的失败条件，不能
通过删除或门控该入口修复本漂移。

固定适用性如下：

| 验收项 | P14 v0.4 固定解释 |
| --- | --- |
| Release/Debug 正式构建 | 目标各自只生成一个 `海中鱼巣.exe`；通过即为正式构建隔离 PASS |
| `--self-test-exit` | 同一目标的受控自检模式；可运行并退出，不是第二目标，不改变生产运行期调用图 |
| P14 自检观察 | 由 `日志/运行.log` 的 P14 专项记录确认；stdout 和退出码仅作辅助证据 |
| 正式接线 | 当前无合法生产消费者；`NOT_APPLICABLE` 仅标记未覆盖，不计入服务集成 PASS，仍为 `未正式接线` |
| 正式读回 | 当前无生产发布入口；`NOT_APPLICABLE` 仅标记未覆盖，不计入服务集成 PASS；自检读回不等价于正式独立读回 |
| 验收结论 | 最多 `自检通过` 或 `局部可继续`；不得写 `服务验收通过`、生产接线完成或 P16 完成 |

后续集成验收必须按此适用性重建清单：组件构建与自检可观察性可在日志合同成立后判定为组件级通过，
正式接线/正式读回按上述合同级理由标为 NOT_APPLICABLE，但不构成服务集成 PASS。不得追溯改写 v0.3 验收记录，
不得把 v0.3 的失败证据改写为成功。

## 3. 正式日志观察合同

P14 自检当前唯一最终观察边界是现有
`海中鱼巣/启动.应用程序.ixx::运行L1动态专项自检()`；它调用
`运行L1动态自检()`，得到非权威 `L1动态自检报告` 后只做一次人读摘要记录，再返回
`自检单元结果` 给统一运行器。不得在持有 L1 或领域锁时写日志，不得在四个公开领域入口
内重复写日志。

复用现有 `海中鱼巣/核心/日志系统.h` 的 `记录运行日志` 与 `记录逻辑错误日志`，该头文件
不在 P14 白名单内且不得修改。运行日志记录固定为：

```cpp
bool 记录运行日志(std::wstring_view 模块, std::wstring_view 入口, std::wstring_view 内容);
bool 记录逻辑错误日志(std::wstring_view 模块, std::wstring_view 入口, std::wstring_view 内容);
```

两者均只返回日志写入是否成功；返回值不得进入 P14 机器结果或改变任何事实。

```text
日志类别：运行
模块：L1-SIMPLIFY-P14-DYNAMIC-SPEC
入口：运行L1动态专项自检
观察标识：L1-SIMPLIFY-P14-DYNAMIC-SPEC-S01
内容：结果=通过|失败；验收项数=28；失败项数=N；未分类异常=0|1；正式接线=不适用；正式读回=不适用
```

每次 `运行L1动态专项自检()` 恰写一条运行摘要；成功、合法入口拒绝、幂等冲突、版本漂移、
资源失败等结构化合同结果只进入摘要中的观察计数，不作为逻辑错误逐项记录。只有
`运行L1动态自检()` 捕获到未分类异常时，最终边界再写一条 `逻辑错误` 日志，内容带固定
入口、异常标记和失败数量；内部函数不得重复写该错误。日志写入失败不改变结构化自检结果、
事实代次、幂等账或任何 L1 机器事实。

`日志/运行.log` 是人读观察材料，不是 P14 成功事实、L1 权威状态、生产接线证明或正式读回。
验收必须检索该文件中的 `L1-SIMPLIFY-P14-DYNAMIC-SPEC-S01`，不能以 stdout、退出码、
日志不存在或日志文本单独宣称机器能力完成。
