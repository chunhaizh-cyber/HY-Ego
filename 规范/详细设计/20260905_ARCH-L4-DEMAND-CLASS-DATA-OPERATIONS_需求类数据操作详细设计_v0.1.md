# 需求类数据操作详细设计

日期：2026-09-05

版本：v0.1

身份：`ARCH-L4-DEMAND-CLASS-DATA-OPERATIONS`

状态：设计已冻结，等待代码实施

## 1. 目标与完成边界

新建 `海中鱼巣/领域/数据服务.需求类.ixx`，只形成一组薄数据操作：

```text
新增一条不可变需求数据记录
+ 按记录身份读取
+ 按“所属存在 + 目标宿主 + 静态目标特征 + 方向二次特征定义”精确读取
+ 用记录中的静态目标特征和调用方指定的当前事实特征计算临时方向
```

本模块的架构职责是 `ARCH-L4` 新记录面，不属于 `DATA-L2`，不得写成 `DATA-L4`。物理文件名沿用用户指定的“数据服务”，不据此改变层级。

本叶不是3100/5170定义的完整正式需求治理：不建立需求树、需求列表、self 产生确认、任务子目标来源、活动资格、预算、任务承接、结算或调度；新身份不得强转、别名化或回显为旧 `L2需求身份`，也不得由旧消费者当作正式需求。它只提供后继新逻辑可以消费的独立、不可变数据记录和临时计算。完整治理及最终替代旧逻辑属于后继目标。

用户明确允许新旧两套在迁移期并行。本叶不调用、修改、适配、迁移或退出旧 `服务.L2*`；新 owner、新稳定编码、DTO 和模块均与旧需求结构隔离。并行存在不证明迁移完成或旧逻辑已被替代。

## 2. 正式依据与当前事实

- 0050：ARCH-L4 记录面只能机械保存、读取和校验调用方已经裁决的记录；不得裁决需求成立、当前满足或结算。
- 3100：完整正式需求仍以“所属存在 + 目标宿主 + 目标特征 + 目标状态合同”为稳定契约，身份不可原地改义，当前满足不得持久化。本叶不宣称完成该治理合同。
- 5170：当前满足必须读取同一 G0 当前值并按目标合同比较；状态、动态只能作可选证据。本叶只返回二次特征比较结果，不将方向或满足结论落盘。
- 4030：需求属于 ARCH-L4；跨 owner 引用必须经公开结构服务互证；独占 owner 只写自身结构。
- 当前基线 `4ac54c3890789bf78c43594333a1af3d1e301211` 的新链已经公开：
  - `存在类数据服务::查询存在(const 存在类查询请求&) const`；
  - `特征类数据服务::查询特征(const 特征类查询请求&) const`；
  - `二次特征类数据服务::查询二次特征节点(const 特征类派生定义查询请求&) const`；
  - `二次特征类数据服务::计算二次特征(const 二次特征计算请求&) const`；
  - L1 当前代次、owner 当前事实、关系组、一致读取、首次写入和 owner 中性写集公开能力。
- `数据服务.二次特征类.ixx` 当前要求两个直接来源互异、顺序为1/2；比较请求左来源对应顺序1，右来源对应顺序2。故本设计不假定当前事实特征与静态目标特征使用同一类型身份，而是由方向二次特征定义显式绑定两个角色类型。
- 新需求文件当前不存在；当前计划索引为空。旧 `服务.L2需求结构.ixx`仍在工程中，但只作隔离的迁移期兼容实现事实，不提供本叶接口或代码复用依据。

## 3. 模块、依赖与 owner

文件与模块固定为：

```text
文件：海中鱼巣/领域/数据服务.需求类.ixx
模块：海中鱼巣.领域.数据服务.需求类
工程：海中鱼巣.vcxproj，以 ClCompile 登记
filters：海中鱼巣.vcxproj.filters，置于现有领域模块分组
```

模块只 `export import 海中鱼巣.领域.数据服务.二次特征类;`，允许使用该公开链导出的 L1、特征类和存在类类型；禁止 import 任何旧 `服务.L2*`、`L2*.数据.h`、状态类、动态类、因果类、场景类、任务、方法、组合或业务 provider。

唯一服务类持有一个专属、move-only `L1所有者范围写端口`，只写本叶新记录节点和四条关系。构造器固定为：

```cpp
struct 需求类结构类型 final {
    稳定编码 所属存在关系类型{};
    稳定编码 目标宿主关系类型{};
    稳定编码 静态目标特征关系类型{};
    稳定编码 方向二次特征关系类型{};
};

需求类数据服务(const L1事实基座服务& 第一层服务,
    const 特征类数据服务& 特征服务,
    const 存在类数据服务& 存在服务,
    const 二次特征类数据服务& 二次特征服务,
    L1所有者范围写端口&& 写入端口,
    需求类结构类型 结构类型);
```

四个关系类型必须非零、互异、当前、未退出、为普通节点并由该写端口 owner 持有；owner 必须是当前独占结构范围。构造失败抛 `std::invalid_argument`，不隐式创建类型、不领取第二端口。

依赖函数白名单精确冻结为：

```text
L1事实基座服务：
  读取中性当前事实代次
  读取当前结构所有者
  读取所有者范围当前节点
  读取所有者范围当前关系
  读取所有者范围当前源关系组
  读取所有者范围当前目标关系组
  尝试读取所有者范围一致当前投影
L1所有者范围写端口：
  读取首次写入材料
  提交所有者范围中性写集
存在类数据服务：查询存在
特征类数据服务：查询特征
二次特征类数据服务：查询二次特征节点、计算二次特征
```

不得使用 L1 中性 v1 写入口、私有仓库、SQL、锁、缓存、raw owner 选择、旧 L2 DTO/函数或白名单外函数。

## 5. 公开函数合同

```cpp
class 需求类数据服务 final {
public:
    需求类记录结果 新增需求记录(const 需求类新增请求& 请求);
    需求类记录结果 查询需求记录(const 需求类身份查询请求& 请求) const;
    需求类记录结果 按所属存在和目标精确查询(
        const 需求类精确查询请求& 请求) const;
    需求类方向计算结果 计算临时需求方向(
        const 需求类方向计算请求& 请求) const;
};
```

四个入口诊断责任均为“向上送出”：只返回结构化结果，不写日志，不吞掉资源失败或内部不一致。构造器配置错误通过 `std::invalid_argument`向装配责任边界送出。

### 5.1 新增需求记录

入口要求合同版本、G0、幂等身份和四个端点均有效。固定流程：

1. 读取 L1 当前代次，必须等于请求 G0。
2. 先用写端口首次写入材料处理幂等：同键同规范化请求读回原记录并返回精确重复；同键异义返回幂等冲突。
3. 在 G0 分别用存在类查询所属存在、目标宿主；只接受`已读取 + 成功 + 身份回显一致 + 事实代次=G0`。
4. 用特征类查询静态目标特征；只接受当前、事实代次=G0、值为直接 `std::int64_t`，且目标宿主的当前特征成员中恰有该特征。
5. 用二次特征类查询方向定义；只接受当前、实际阶次恰为2、两个直接来源顺序1/2、比较用途为`目标判断`、左角色为`当前事实`、右角色为`目标状态`、算法/规则版本一致，且顺序2来源等于静态目标特征的`特征类型`。定义宿主如存在，只能等于目标宿主。
6. 按四端点执行精确查询；已有唯一记录返回`精确目标已存在`并携带既有记录，多个记录为内部不一致。
7. 一份本 owner 写集原子创建一个普通记录节点及四条角色为0的关系。固定本地键：记录节点`1`、所属存在关系`2`、目标宿主关系`3`、静态目标特征关系`4`、方向二次特征关系`5`。不建立属性、树、列表、来源、状态或方向值。
8. 恰一次提交。成功或精确重复后按新编码映射和 Gend 完整读回，所有五项事实必须由本 owner 同代创建并逐字段吻合；已确认发布但无法闭合时返回`已可能发布`和发布代次，调用方只能以原幂等身份和原请求重放。

任何写前失败零变化。跨 owner 端点只引用，不修改、不退出。

### 5.2 按身份查询

在请求 G0 用 L1 owner 一致当前读取记录节点和四类源关系；前后当前代次均必须等于 G0。记录节点必须是本 owner 当前普通节点、无属性、恰有四条当前关系，关系类型、源端、目标端、owner 和生命周期完整且互异。

随后在同 G0 用允许的三个公开服务重新互证所属存在、目标宿主、静态目标特征、宿主成员关系和方向定义。任一混代返回事实代次漂移；完整自有形状矛盾返回内部不一致；身份不属于本结构返回未找到。

### 5.3 精确查询

请求最大候选数量必须非零。先冻结 G0 并互证四端点，再分别调用 L1 owner 当前目标关系组读取四个端点与对应关系类型。四组结果的读取代次必须全部等于 G0、关系 owner/类型/目标/生命周期必须完整；任一组数量大于预算返回数量预算不足。

对四组源记录身份取交集：零项返回未找到；一项再调用按身份查询并逐字段精确相等后返回；多项返回内部不一致。不得按编码顺序选一个，不缓存索引，不返回部分候选。

### 5.4 临时方向计算

本函数零 L1 写、零需求记录修改、零方向持久化：

1. 校验版本、G0、非零请求身份、需求身份、当前事实特征和结果位1..7。
2. 在 G0 按身份读取需求记录，再查询目标宿主、当前事实特征、静态目标特征和方向二次特征定义。
3. 当前和目标特征都必须是目标宿主当前特征成员、直接 I64、当前且同 G0；当前特征类型必须等于方向定义顺序1来源，目标特征类型必须等于顺序2来源。两类型按现有二次特征合同必须互异。
4. 从方向定义的比较注册合同唯一取得用途、算法版本、单位、维度、分量角色和左右角色；不得由请求覆盖。
5. 构造一次 `二次特征计算请求`：左为当前特征的值事实和值，角色`当前事实`；右为静态目标特征的值事实和值，角色`目标状态`；两侧来源稳定编码分别为各自特征类型，输入版本为 G0，创建代次取特征事实，退出代次为空；特征定义为记录中的方向定义，预期算法版本为注册算法版本，结果位取调用请求。
6. 调用一次`二次特征类数据服务::计算二次特征`。成功只原样包装其比较结果；比较非成功映射为方向定义不匹配、事实代次漂移、资源失败或内部不一致，不自行重算或降级为裸 I64 减法。
7. 读后 L1 当前代次仍须等于 G0，否则清空比较并返回事实代次漂移。

比较的`具名关系`和可选`差异材料`只是调用方拥有的临时值式结果；本模块不把它解释成需求成立、当前满足、优先级、动作或结算。

## 6. 失败映射与不变量

- 存在类未找到/已退出分别映射所属存在或目标宿主具名状态；其它非成功只映射事实代次漂移、资源失败或内部不一致。
- 特征类未找到/已退出按目标/当前角色分别映射；非 I64 或引用型/向量型值使用具名“一阶 I64”拒绝。
- 二次特征未找到/已退出具名映射；阶次、来源、角色、用途、版本、目标类型或宿主不匹配统一为方向定义不匹配。
- L1 写入精确重复只有首次规范化写集同义且完整读回时成功；许可拒绝不得产生，出现时按内部不一致；引用冲突、幂等冲突、代次漂移、资源失败原类映射。
- 核心四元组和记录身份永不修改、不退出。本叶不提供修改、删除、退出、恢复或历史查询入口。
- 同一精确四元组最多一个当前新记录；同一记录恰有四条自有关系；计算永远零写。
