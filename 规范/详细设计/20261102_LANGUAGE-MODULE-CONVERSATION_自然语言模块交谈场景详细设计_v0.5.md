## 1. 目标、非目标与范围

### 1.1 目标

1. 交谈场景中，本能经任务链提出正式、固定、语种无关的表达需求；语言模块经基础表达结构完成基础信息 ↔ 自然语言双向转换。
2. 语种差异仅=用词与词序（语言知识）；学习为阶段 2。
3. 权威组织按规范：表达目的与对象种类正交。
4. 检查仅在失败有明确动作时保留：追问、重读、切换候选、观察补信息。
5. 优先闭合：经「获取服务对象需求信息」筹办出的完整补问子需求任务链（生成与发送分账）+ 行动请求输出对称；写回由本能/输入侧闭合（非表达需求）。
6. 解析与写回时，临时对象按「当前场景 / 其它场景」分流处理（见 5.3、6.6）。
7. 出站「想/做」分账：语言生成只产候选话语；是否发送另做判断后再入列（见第 8 节）。

### 1.2 非目标

- 语言成功 ≠ 世界事实 / 需求确认 / 任务完成 / 发送成功。
- 不写需求/任务/方法 owner；不把写回做成表达需求。
- 自我不直接调用本能、不亲自满足自身需求；追问不得绕过任务方法链。
- 写作、绘画暂不考虑；问候等推断流程意图不在本步本流立项。
- 不一次性覆盖规范操作闭集；不改 DATA owner 拓扑。

### 1.3 范围

| 在范围内 | 在范围外（本版） |
| --- | --- |
| 正式表达需求对象、交谈双向管线、种子（含三对）、往返验收、缺字段追问出站、临时对象分流写回、**理解中词条归类学习（归类子需求／询问／写回／原句重述）** | 写作/绘画；问候等礼貌与全流程推断意图立项；独立学习模块/线程（已禁止） |

## 3. 架构与位置

字段不足或代词未消解时「获取服务对象需求信息」经通用筹办提出完整补问子需求／指代澄清补问子需求（代词不归类；见 LANGUAGE-PRONOUN-RESOLUTION（含帮我新根壳与指代澄清种类）） → 自我承接/确认该完整需求并裁决筹办 → 任务「查找方法→采用→执行」驱动本能 → 出站本能提交正式表达需求并由语言模块生成候选话语（想）→ 发送裁决通过后入列（做）；待完善被认知需求本身不进此链；接收认知与写回本能走输入侧。

| 组件 | 职责 | 不做 |
| --- | --- | --- |
| 自我 | 承接与确认需求；裁决筹办；判断对方是谁、场景归属；做出发送相关裁决所需的判断材料 | 直接拼句；直接调用本能；自己满足自己的需求 |
| 任务治理 / 工作 | 查找方法、采用、执行已采用本能；装入参数场景 | 生成自然语言；绕过方法链放行追问 |
| 自然语言模块 | 消费表达需求；双向转换；回读；只交付候选话语 | 发送/入列、写回字段、召回方法、建任务 |
| 本能（想/生成侧） | 经任务执行：据需求缺项形成并提交正式表达需求，取得候选话语 | 硬编码句子；擅自入列；自证任务效果 |

## 4. 数据结构

### 4.1 正式表达需求对象（已冻结）

运行期冻结正式对象：由真实需求缺口经任务链上的出站本能形成并提交，语言模块消费。自我不直接提出/调用。字段询问等不得长期停留在「仅调用内派生」。

必含：表达目的（陈述/提问/提出需求）、含义操作（可空）、对象/信息种类与槽绑定、说话者/受话者、交互窗口与作用域、语种、触发真实需求与方法引用。详略由提出方按估计认知差距填写槽完备度，不另建固定分套枚举。

落点：业务层正式数据合同；接纳与消费路径需登记；禁止旁路拼字符串。

### 4.2–4.4

基础表达结构映射、语言知识条目、解析结果同 v0.1 方向；解析后写回由输入侧消费者决定。解析结果应能携带：指称候选、是否已绑定现实存在、是否判定属当前场景（可由自我/本能在消费时补全）。

## 5. 生成与解析管线

### 5.1 生成（想）

1. 任务链执行出站本能：据需求缺项等形成并提交正式表达需求。
2. 校验槽（详略已体现在完备度；内部可补则不对外表达）。
3. owner 只读投影。
4. 映射为基础表达请求/含义图。
5. 按目的、含义操作、角色、语种召回知识。
6. 生成可回读单句 → **候选话语**；失败则无候选，更不得入列。
7. 交付候选话语即止。**不**在此步入列；入列见发送裁决与「做」。

### 5.1b 发送（做）

1. 取得已回读成功的候选话语。
2. **先做是否发送的判断**（发送裁决）；未通过则保留候选、不入列，并须有明确下一动作。
3. 裁决通过后，由经任务采用的发送/入列本能（或通道动作）写入外设输出队列。
4. 生成成功 ⇏ 发送裁决通过 ⇏ 入列成功 ⇏ 对端已读。

### 5.2 解析

固定原文 → 只读解释 → 候选收窄 → 交付值式含义给接收认知或**写回本能**等输入侧消费者。写回不进入表达需求生成管线。

### 5.3 指称消解与临时对象（解析→写回）

对话里提到某个东西、但内部还没有对应现实「存在」时，**不得一律立刻进现实树**，也**不得一律禁止记含义**。按是否属于当前场景分流：

1. **属于当前场景**：自我须先获得其它证据（例如观察、向对方追问核对），并**必须先绑定到现实存在**，才允许写回正式内容。禁止以「未绑定的主张」落库当前场景对象。
2. **属于其它场景**：允许先记下主张（挂起含义），待日后证据与绑定时再落到现实存在。
3. 场景归属由自我判断；语言模块只交付解析候选与指称线索，不代替自我做场景终裁。
4. 当前场景缺证据或缺绑定时：失败动作明确——继续观察、追问，或暂缓写回；禁止静默伪造绑定。

## 6. 交谈场景

### 6.1 确认对方是谁（自我驱动）

由自我判断。必要时要求对方提供必要信息，或通过观察等自我方法获取。不限于网页登录绑定。失败须有明确下一动作。

### 6.2 交谈阶段

仍作分析附录，非已实现状态机；礼貌与全流程推断意图本版延后。

### 6.3 本版表达需求（最小相关）

| 白话 | 说明 | 现状 |
| --- | --- | --- |
| 就需求缺字段向对方追问 | 正式表达需求；由「获取服务对象需求信息」筹办完整补问子需求后经任务查找方法→采用→执行 | 现网生成+入列绑在同一次本能；正式对象与补问子需求调度未按 v0.5b 闭合 |
| 用语言投影重述并请确认 | 正式表达需求 | 规范有；工程旁路应废止 |
| 经发送裁决后投递候选话语 | 「做」；通道/入列本能 | 网页对话通道已登记；发送裁决未单列 |
| 行动请求出站 | 提出需求目的 | 生成入口仍为桩 |

### 6.4 延后项（不在本步本流）

开场问候、自我介绍、请对方表明身份（固定剧本）、指称消歧追问、给出选项、进度/阻塞陈述、结果交付、请换说法、纠正误解、话题切换、道别、是否继续、请对方配合行动——均延后，移出最小闭环。

说明：上列「指称消歧追问」指礼貌/流程类固定剧本；**当前场景临时对象取证所需的观察与追问**仍属写回前置，见 5.3 / 6.6，不因延后清单而取消。

### 6.5 写回（非表达需求）

把对方答复写回需求字段属于输入侧/本能写回能力，不属于表达需求，不进入生成管线。最小闭环仍需要它，但由本能页施工。

### 6.6 临时对象与写回分流（已裁决）

| 情况 | 允许做法 | 不允许 |
| --- | --- | --- |
| 提到的对象属于**当前场景** | 先取其它证据，绑定现实存在后再写正式内容 | 未绑定就记主张；静默进现实树 |
| 提到的对象属于**其它场景** | 先记下主张，待后续绑定 | 假装已经是当前场景的现实存在 |

## 7. 权威表达需求目录（按规范采纳）

### 7.1 检索与引文

规范已描述组织方式：**不以交谈场景一张表为权威编号空间**，而以表达目的与对象种类正交，并用含义操作组织可执行结构。

《2340 根规范 自然语言知识》（`规范/2340_根规范_自然语言知识.md`）：

> 完整表达目的分为陈述、提问、提出需求。陈述包括事实、观点、特征、变化和过程报告；提问用于获取或确认信息；提出需求用于表达希望对方提供的信息或改变。目的与对象种类正交：需求、任务、方法自身都可以被陈述、询问或作为请求内容，不建立需求概念、任务概念、方法概念本体根。

同文件：

> 描述结构分基础表达结构和内容组织结构，字段、角色、取材、组成与条件按7230/7240展开……

《7240 子规范 自然语言双向转换与组织规则》（`规范/7240_子规范_自然语言双向转换与组织规则.md`）§3.2：

> 按表达目的、含义操作、角色类型和语言从知识索引召回；精确读回全部候选定义及采用范围，匹配目标含义并求值条件。

§2.2 给出首版语义操作闭集（概念归类、特征描述、组成、场景包含、状态/变化、信息请求、需求描述、行动请求等）。

设计稿 `20261029_LANGUAGE-INTERNAL-WORLD-BIDIRECTIONAL_*_v0.3.md` §14 有「节点类型 × 陈述/疑问/指令」分析矩阵，文内标明「待用户确认」「不是已冻结实现合同」。与 2340 思路一致，但本身未冻；本模块权威回落 2340/7240。

### 7.2 本模块采纳

1. 权威目录维度：表达目的（陈述/提问/提出需求）× 对象/信息种类；由含义操作与槽位签名具体化。
2. 知识召回键：表达目的 + 含义操作 + 角色类型 + 语种。
3. 交谈阶段表仅作分析附录，不充当权威编号空间。
4. 写作/绘画暂不扩展目录。

### 7.3 祈使详略规则

「请对方做某事」不固定拆套。详细程度由实际需要决定，随双方估计认知差距伸缩。语言模块按已提交表达需求的槽完备度生成，不自行加戏。

## 8. 与本能方法函数的接口

### 8.1 界面是否清晰（结论）

**合同层已清晰，实现未闭合。** v0.5b 硬边界：待完善被认知需求不入集/不建任务；补问由「获取服务对象需求信息」经通用筹办提完整补问子需求后走任务链；自我不直接调本能；生成（想）与发送（做）分账且发送前须裁决。现网字段询问仍把派生问句与入列绑在同一次本能，正式表达需求对象亦未落地——施工须按本节收口。

### 8.2 关系：谁调用谁（v0.5）

| 角色 | 调用 / 被调用 | 不做 |
| --- | --- | --- |
| 自我 | 承接与确认需求；裁决筹办与发送相关判断；判断对方是谁、场景归属 | **直接调用本能**；**自己满足自己的需求**；直接拼句 |
| 任务治理 / 工作 | **唯一**合法路径（仅完整补问子需求等完整需求）：查找方法 → 采用 → 执行；装入参数场景 | 把待完善本身送进查找方法；生成自然语言；让自我旁路执行本能 |
| 本能（想） | 经任务执行：据需求发现的缺项形成并提交正式表达需求；取得语言模块回读成功的候选话语 | 硬编码句子；无发送裁决即入列 |
| 本能（做） | 经任务执行：发送裁决通过后入列/发送 | 无候选或未裁决仍发送 |
| 本能（写回） | 经任务执行（输入侧）：采纳答句写字段 | 登记为表达需求 |
| 自然语言模块 | 被出站「想」消费：表达需求→候选话语；入站：正文→值式含义 | 召回方法、建任务、发送、写字段 |

一句话：语言模块只负责想清楚怎么说；是否说出去、如何说出去，归任务链上的「做」；自我从不亲手调本能。

### 8.3 跨界对象

| 方向 | 跨界对象 | 接收方 |
| --- | --- | --- |
| 出站·想 | 正式表达需求 | 语言模块 → 候选话语 |
| 出站·做 | 候选话语 + 发送裁决通过证据 + 动作身份 | 外设/对话通道入列 |
| 入站 | 自然语言正文 + 会话上下文 | 语言模块 → 值式含义 |
| 入站消费 | 值式含义 | 接收认知或写回本能 |

禁止：成品问句冒充表达需求；未生成或未裁决冒充已入列；语言模块直接改需求字段；自我或非任务路径直接调本能。

### 8.4 完整补问子需求如何到达语言相关本能（唯一合法路径）

1. 服务对象侧出现**待完善被认知材料**（如缺目标形式）；该材料本身**不**进需求集合、**不**建任务、**不**进查找方法。
2. 「**获取服务对象需求信息**」经通用筹办提出**完整补问子需求**交自我确认；父方法不执行。
3. **自我只承接与确认**该完整补问子需求（及筹办裁决），**不**亲自去问、**不**直接调本能满足它。
4. **任务**承接该完整需求；任务工作 **查找方法**（按作用对象、涉及特征、可能结果等召回，可命中已登记本能）。
5. **采用**方法并冻结条件后 **执行**本能：装入参数场景。
6. **想**：出站本能据补问意图提交正式表达需求 → 语言模块生成并回读 → 得到**候选话语**。
7. **发送裁决**：判断是否发送；未通过则不入列，须有明确下一动作。
8. **做**：裁决通过后，经任务采用的发送/入列动作写入对话框输出队列。
9. 答句经接收路径解析；**写回**走输入侧本能（须同样由完整需求经任务链驱动，尚未实现），不走表达生成管线。

现状偏差（施工收口）：

- 字段询问仍在同一次本能内派生问句并直接入列（想/做未分账，亦无独立发送裁决）。
- 正式表达需求对象未落地。
- 内容叶方法召回对改需求字段仍常「定位未支持」；与输出队列入列本能的召回键尚未按「完整补问子需求→询问」闭合。
- 自我侧尚无「只确认、不自满足」与「获取服务对象需求信息」筹办补问链的完整接线说明实现。

### 8.5 代码与规范锚点（只读核对）

| 环节 | 落点 |
| --- | --- |
| 方法登记/执行 | 规范 5360、5350 |
| 字段询问与语言 | DEMAND-FIELD-QUESTION；字段询问.本能运行服务 / 语言服务 |
| 表达需求承载缺口 | FIELD-METHOD-DISCOVERY |
| 本能入口 | 新_本能函数集：询问指定需求字段；本能函数管理类登记 |
| 语言统一双向 | 从基础信息生成可回读单句；只读解释单句基础语言 |
| 任务方法召回 | 任务工作线程查找方法；查询任务方法候选并发布；查询候选方法 |
| 入站 | 接收需求认知服务；内容待完善时中断入集/建任务 |
| 补问触发 | 「获取服务对象需求信息」；5170第2.1节通用筹办补问子需求 |

### 8.6 边界合同（v0.5b 冻结）

1. 待完善被认知需求本身不进任务链；字段不足时由「获取服务对象需求信息」经通用筹办提完整补问子需求，再经任务「查找方法 → 采用 → 执行」。
2. 自我**只**承接与确认完整需求，**不得**自己满足自己的需求，**不得**直接调用本能。
3. 正式表达需求是「想」侧与语言模块的唯一出站句义合同；语言模块只返回候选话语。
4. 生成与发送拆分：生成成功 ≠ 发送；发送前必须先有发送裁决；入列为「做」。
5. 写回属输入侧本能（由完整需求经任务链驱动），永不登记为表达需求；遵守临时对象分流。
6. 语言模块不参与「该不该问 / 该不该发」，只回答「给定表达需求能否唯一生成/回读」。

### 8.7 语言补全读取缺口与缺口外建词条／分词本能（20261103）

接口约定（规范权威；实现头注释须对齐）：

1. **纯读取缺口不建 D／T、不写词条**；目标只来自原来源中的正式词条或指代实例。本条**不变**。
2. 缺口外显式准入按[7250第3.3.1节](../7250_子规范_最小汉语知识与语言学习.md#331-未知词面显式准入与归类衔接)及[LANGUAGE-LEMMA-CREATE-FROM-FRAGMENT v0.3](20261103_LANGUAGE-LEMMA-CREATE-FROM-FRAGMENT_未登记片段建立词条详细设计_v0.1.md)：先形成候选并确认词边界、规范化材料，再经词条owner建立或取得并正式读回，重新解释和读取缺口后按本次用法分流。候选不因过滤或唯一而自动取得正式资格；功能词／代词可有词条但不归类。
3. 不得在 `读取缺口` 内旁路写词条或分词持久化；不得把整段未知原文直接建成一个词条；不得无词条身份伪造归类目标。归类询问／写回仍归 LANGUAGE-LEMMA-CLASSIFY；代词澄清仍归 LANGUAGE-PRONOUN-RESOLUTION。
4. 分界未定允许先询问如何划分，问题对象为固定原文及范围，不是词条或指代实例；回答提供分界依据，不自动成为概念含义。此处不宣称原正式表达需求／任务接口已经支持分界澄清；其承载、生成、发送及回答接续仍须后续设计。分词本能的材料与消费者、参数及结果合同也未冻结，不能据本接口注记直接登记或实施。

## 10. 失败处理

| 失败 | 允许动作 | 不允许 |
| --- | --- | --- |
| 缺知识/多义 | 切换候选或追问 | 静默首条 |

| 回读不等价 / 无候选 | 不进入发送 | 带缺口发送 |
| 发送裁决未通过 | 保留候选；明确下一动作 | 强行入列 |

## 11. 种子与往返验收

- 保留六构式；首批对齐缺字段追问、重述确认、行动请求出站。
- 不写入延后礼貌意图种子冒充已立项。
- 最小环：「获取服务对象需求信息」发现字段不足 → 通用筹办完整补问子需求 → 任务查找方法→采用→执行（想：表达需求→候选话语）→ 发送裁决 → 做（入列）→ 答句写回 → 资格重读通过。
- 临时对象：当前场景路径验收「无绑定则不落库」；其它场景路径验收「可记主张且不冒充已绑定」。
- 分账：生成成功⇏发送裁决通过⇏入列成功；解析成功⇏写回成功；自我不得出现直接调本能的验收路径。

## 12. 分阶段实施计划

第一最小环：正式表达需求对象 + **经「获取服务对象需求信息」筹办的完整补问子需求任务链**（想/做分账 + 发送裁决）+ 行动请求输出对称；写回经任务/输入侧闭合（含临时对象分流）；待完善本身不进链；自我不直接调本能；问候等延后。

1. 设计入库（本文 v0.5）
2. 正式表达需求对象与接纳（语言只产候选话语）
3. 拆分字段询问：想（提交表达需求→生成回读）与 做（发送裁决→入列）；废除同一次本能绑死生成+入列
4. 闭合任务召回：完整补问子需求 → 查找方法→采用→执行询问本能（禁止自我直调；禁止待完善本身进链）
5. 发送裁决显式化（未通过不得入列）
6. 写回本能（经任务；当前场景绑定 / 其它场景主张）
7. 行动请求出站去桩（同样遵守想/做分账）
8. 重述确认 + 废止工程重述旁路
