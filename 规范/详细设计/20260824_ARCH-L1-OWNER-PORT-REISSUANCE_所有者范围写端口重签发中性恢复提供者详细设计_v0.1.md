## 1. 最小 S0 裁决

4015 §5.1 已冻结公开合同 `L1所有者范围签发器::重新签发所有者范围写端口(const L1所有者范围重入请求&)`，数据头已有 `L1所有者范围重入请求` 与 `L1所有者范围重入结果`，但当前 `服务.L1事实基座.ixx`、`仓库.L1事实基座.ixx` 均没有该入口实现。当前代码只有建立、退出和 owner-scoped 写端口运行期租约。

候选对账：

| 候选 | 当前事实 | 依赖/边界 | 裁决 |
| --- | --- | --- | --- |
| 4015 L1 端口重签发 | DTO 已有，签发器函数缺失；owner 当前事实、建立幂等账和活动端口集合已有 | 只需 L1 签发管理面；不解释 L2/L4，不要求业务消费者 | **最早可独立交付** |
| L2 状态/动态原子 G1 技术矩阵 | provider 已有单 G1、参与者写集和五组读回代码；无独立生产消费者，G1 运行矩阵未闭合 | 代码缺口不是 ABI 缺口；应由后续中性专项或集成验收验证，不抢占 L1 提供者 | 不新建本轮计划 |
| 特征值表示/独立材料/向量形状 | 独立材料值类型、四类值表示和基本材料/属性类型准入已有；公开比较入口当前实际只执行 I64，向量逐分量/形状算法与值域详细设计仍未冻结 | 需要新的算法/值域机器语义和直接依赖裁决，不能由执行者补齐 | 保留缺口，不激活 |

因此本叶只实现同一 L1 运行包内、owner 当前且无活动端口时的能力重签发。它不是崩溃恢复、快照恢复、跨进程恢复或业务重连；4015/4070 的持久恢复材料与确认候选仍是后续独立目标。

## 2. 权威与职责边界

L1 只验证中性 owner 事实、建立幂等账、当前代次、同实例运行包和活动端口互斥，并重新交付不可复制、可移动的 `L1所有者范围写端口`。不得改变 owner 事实、稳定编码、历史、幂等账、普通写入 ABI 或事实代次；不得接受 L2 节点族、服务枚举、名称、进程/线程、token、缓存、快照或恢复材料。

重签发成功不是事实发布，不产生 G1，不修改 `状态_.事实代次`，结果的 `事实代次` 只回显安全取得的当前代次。旧端口永久失效；新端口是同一 owner 的唯一活动能力。重复签发在已有活动端口时返回 `许可拒绝`，不能返回第二端口。

## 3. 冻结公开 DTO 和状态映射

复用现有数据头，不新增业务字段：

```cpp
struct L1所有者范围重入请求 final {
    std::uint32_t 合同版本 = L1所有者范围CRUD合同版本;
    L1结构所有者身份 所有者;
    L1所有者范围建立幂等身份 建立幂等身份;
};

struct L1所有者范围重入结果 final {
    L1所有者范围管理状态 状态;
    std::uint32_t 合同版本;
    L1所有者范围建立幂等身份 建立幂等身份;
    std::optional<L1结构所有者事实> 所有者事实;
    std::uint64_t 事实代次;
    bool 是否形成内存权威发布;
    L1所有者范围重试边界 重试边界;
};
```

固定映射：

| 前置事实 | 结果 |
| --- | --- |
| 合同版本、owner、建立幂等身份为零/错版本 | `入口拒绝`，代次 0，无 owner 事实 |
| L1 运行包已销毁/签发器状态失效 | `许可拒绝`，代次 0 |
| owner 建立幂等账不存在 | `未找到`，代次为安全读取的当前代次 |
| owner 事实存在但已退出 | `已退出`，不交付端口 |
| owner 事实不是独占范围、建立请求不是独占范围或账与 owner 不互证 | `引用冲突`；若仓库状态本身损坏则 `内部不一致` |
| 同一实例该 owner 已有活动端口 | `许可拒绝`，不改变端口集合 |
| 当前 owner 与建立账逐字段一致且无活动端口 | `成功`，交付一份新 move-only 端口，不推进事实代次 |
| 非材料原因的仓库/锁/分配异常 | `资源失败` 或 `内部不一致`，不交付端口 |

`精确重复`不用于表示第二次能力签发；请求相同但已有活动端口仍是许可拒绝。所有拒绝返回空 `所有者事实` 或仅返回已安全读取的事实投影，绝不返回半交付能力。

## 4. 原子顺序与并发

签发器先取得 `状态->端口锁`，然后在同一运行包实例的仓库管理读取中验证 owner 当前事实、建立幂等账和独占范围，最后在仍持有端口锁时原子检查/插入 `活动端口所有者` 并构造端口。退出路径已采用“端口锁后仓库退出”顺序；重签发必须保持相同顺序，避免 owner 退出与新端口交错。

仓库内部验证不得写事实，不改变代次；验证成功后由签发器在端口锁内插入活动 owner 并交付端口。任一验证或构造失败均不写 owner、账或代次。端口移动、析构和运行包销毁继续由现有 RAII 释放活动集合；新端口跨实例、跨 owner、移动源和析构后提交均沿现有 `许可拒绝`。

## 5. 内部函数和复用边界

不新增对外仓库管理 ABI。`仓库.L1事实基座.ixx`增加模块内部只读验证辅助，固定返回“当前 owner 事实 + 建立账首次请求/结果互证 + 当前事实代次 + 管理状态”；它不得返回仓库引用、锁、候选或可写 token。`服务.L1事实基座.ixx`只新增签发器公开重签发函数，调用该辅助并负责端口锁和 move-only 交付。

复用现有：`L1所有者范围建立请求/结果`、owner 当前读取、`活动端口所有者` 互斥集合、`L1所有者范围写端口` RAII、`L1所有者范围重试边界`。不得复制建立账、owner 事实或写端口类型。

## 6. 验证矩阵与完成边界

生产外 `D:\TEMP` 专项必须覆盖：单运行包/异运行包、当前/退出/未找到 owner、建立账缺失/异义、非独占范围、同 owner 活动端口、两个不同 owner 并发重签发、端口移动/析构/运行包销毁后失效、重签发成功后首次写入/首次账读回、异常和分配失败零事实变化。Debug/Release 根工程、strict、diff-check、UTF-8/no-BOM、生产零专项痕迹均通过。

本叶不证明：崩溃/重启/跨进程恢复材料、快照候选确认/撤销、跨进程旧 token 收敛、L2 状态动态 G1、任务/方法/需求消费者、任何 L4 业务语义。L2 provider 的 G1 五组读回仍由其专门验证/集成验收负责。
