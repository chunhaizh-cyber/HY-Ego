# 任务方法路径权威引用入口详细设计

日期：2026-08-20

身份：`DATA-L2-TASK-METHOD-PATH-VALIDATED-ENTRY`

版本：v0.2

替代：v0.1。v0.1 以跨 named-module 的同名 friend 类作为私有承载授权，在 MSVC C++20 模块所有权下形成两个不同实体并稳定链接失败；本版改为任务模块自有的 move-only capability 端口。

## 1. 目标与边界

本设计只闭合“任务方法路径写入前，来源方法及内容版本由权威方法事实证明，并由普通应用提供唯一合法入口”。它属于“任务服务补全”的第一段，不证明路径组读、路径退出、当前选择、实例方法或任务筹办已经完成。

正式依据为 4260 第 21 节与第 37.2 节：路径写前必须验证方法身份和内容版本；该依赖不得反塞进基础 `L2任务结构服务`。

## 2. 漂移事实与裁决

v0.1 把 `L2任务方法路径结构服务`在任务模块中前置声明并设为 friend，又在路径模块中定义同名类。C++20 named-module 实体附着于声明所在模块；两处同名不形成同一实体。结果是普通应用 getter 与测试消费者看到不同修饰身份，私有路径方法调用也无法闭合，Debug Rebuild 稳定 `LNK2019`。

以下方案均禁止：

```text
把写入已验证任务方法路径改成 public
把 L2方法结构服务注入基础 L2任务结构服务
让任务模块 import 路径模块或让两个模块循环 import
在两个 named module 中靠同名声明冒充同一 friend 实体
复制第二套路径写集或路径事实
```

本版裁决：

```text
任务模块
    拥有私有原子承载函数
    拥有不可复制的写入能力交付凭据
    拥有不可复制的写入能力端口
    只由同模块能力端口 friend 调用私有承载

普通应用装配
    从唯一任务所有者交付中一次性提取能力交付凭据
    构造唯一任务服务
    将凭据与该任务服务精确绑定为能力端口
    把端口移动给路径服务，之后不保留副本

路径模块
    读取当前普通方法并校验内容版本
    验证成功后经能力端口调用私有原子承载
```

能力端口是装配期 capability，不是普通业务写入口。没有由同一任务所有者交付产生且尚未消费的凭据，不能形成端口；普通应用上下文不提供凭据或端口 getter。

## 3. 模块、类型与函数合同

### 3.1 任务模块自有能力类型

文件：`海中鱼巣/领域/服务.L2任务结构.ixx`

在 `海中鱼巣.领域.服务.L2任务结构`模块内定义并导出：

```cpp
class L2任务方法路径写入能力交付 final {
public:
    L2任务方法路径写入能力交付() = delete;
    L2任务方法路径写入能力交付(
        const L2任务方法路径写入能力交付&) = delete;
    L2任务方法路径写入能力交付& operator=(
        const L2任务方法路径写入能力交付&) = delete;
    L2任务方法路径写入能力交付(
        L2任务方法路径写入能力交付&&) noexcept;
};

class L2任务方法路径写入端口 final {
public:
    L2任务方法路径写入端口() = delete;
    L2任务方法路径写入端口(
        const L2任务方法路径写入端口&) = delete;
    L2任务方法路径写入端口& operator=(
        const L2任务方法路径写入端口&) = delete;
    L2任务方法路径写入端口(
        L2任务方法路径写入端口&&) noexcept;

    bool 有效() const noexcept;

    L2新增任务方法路径结果 写入已验证任务方法路径(
        L2新增任务方法路径请求 请求) noexcept;
};
```

两类均不得公开默认构造、复制、从裸指针构造或从稳定编码构造。移动后来源固定失效。端口仅保存对已绑定 `L2任务结构服务`的非拥有引用；端口先于任务服务析构。

### 3.2 一次性交付与绑定

`L2任务所有者交付`新增一次性提取函数：

```cpp
std::optional<L2任务方法路径写入能力交付>
提取任务方法路径写入能力交付() noexcept;
```

合同固定为：

```text
任务所有者交付有效且尚未提取
    -> 返回一份绑定同一 L1 owner 身份的 move-only 凭据
    -> 将本交付的“路径能力已提取”永久置位

交付无效、移动后或重复提取
    -> nullopt
    -> 不改变 L1 事实和任务服务
```

任务模块再提供装配期形成函数：

```cpp
std::optional<L2任务方法路径写入端口>
尝试形成L2任务方法路径写入端口(
    L2任务结构服务& 任务服务,
    L2任务方法路径写入能力交付&& 交付) noexcept;
```

形成函数只在以下条件全部成立时返回端口：凭据有效且未消费、凭据 owner 与任务服务持有的 L1 写端口 owner 精确一致、任务服务写端口仍有效。成功或失败均消费本次右值凭据；错 owner、失效或重复固定返回 `nullopt`且零事实写入。

`L2任务结构服务::写入已验证任务方法路径`继续为 private；其唯一 friend 改为同一任务模块拥有的 `L2任务方法路径写入端口`。任务模块删除 `L2任务方法路径结构服务`的前置声明和 friend，不 import 方法模块或路径模块。

### 3.3 路径服务

文件：`海中鱼巣/领域/服务.L2任务方法路径结构.ixx`

```cpp
class L2任务方法路径结构服务 final {
public:
    L2任务方法路径结构服务(
        const L2方法结构服务& 方法服务,
        L2任务方法路径写入端口&& 写入端口);

    L2新增任务方法路径结果 新增任务方法路径(
        L2新增任务方法路径请求 请求) noexcept;
};
```

服务拥有唯一写入端口并借用方法服务；不再直接借用任务服务，也不由任务模块声明或 friend。构造时端口无效应抛出，由普通应用映射为具名装配失败。新增入口先完成请求形状和权威方法版本验证，只有成功分支才调用端口。

### 3.4 普通应用

普通应用装配顺序固定为：

```text
形成 L2任务所有者交付
-> 一次性提取 L2任务方法路径写入能力交付
-> 构造 L2任务结构服务
-> 构造 L2方法结构服务
-> 以任务服务 + 能力交付形成写入端口
-> 以方法服务 + 写入端口构造 L2任务方法路径结构服务
-> 将路径服务作为上下文最后依赖成员之一持有
```

装配状态至少分开：

```text
任务方法路径能力交付提取失败
任务方法路径写入端口形成失败
任务方法路径服务构造失败
```

现有状态值只能尾部追加或对尚未发布的新值重新尾部编号，不得改变已经发布状态数值。上下文只提供路径服务 const / non-const getter，不提供能力交付或写入端口 getter。

### 3.5 消费者

`任务筹办编排服务`继续只借用任务核心服务和任务方法路径服务；路径新增只走后者。`--test-需求`必须显式 import 路径模块后消费普通应用 getter，不能从任务模块取得同名替代实体。

## 4. 状态、代次与错误映射

1. 请求形状不合法：`入口拒绝`。
2. 方法读取在同一 `期望事实代次`失败：原样传播该结构状态和事实截止。
3. 方法存在但身份或内容版本不等于请求：`引用冲突`，零写入。
4. 方法读取成功且版本一致：把完整原请求移动给写入能力端口。
5. 端口在合法构造后意外失效：`内部不一致`，零写入；不得改成公开任务服务写入兜底。
6. 原子写入首次成功或精确重复：沿用基础任务服务现有权威读回和结果形状。

服务不得自动重试事实代次漂移，不得把历史方法冒充当前方法，不得根据名称或裸编码补齐方法。

## 5. 模块依赖闭包

```text
L2任务结构模块
    -> L2需求结构公开读取
    -> L1事实基座

L2任务方法路径结构模块
    -> L2方法结构公开读取
    -> L2任务结构模块导出的 capability 端口

普通应用模块
    -> 两个结构模块
```

不存在任务模块到方法模块或路径模块的反向依赖，不存在循环模块，不存在跨模块 friend 类身份。

## 6. 普通应用读回场景

在既有 `--test-需求`合法消费者中复用同一普通应用上下文：

1. 核对 const / non-const getter 返回同一个路径服务实体；
2. 初始化并读回系统场景树根；
3. 复用测试已建立的存在、特征定义和目标状态合同，新增一份真实普通方法并读回；
4. 建立需求列表项和任务；
5. 经路径服务以错误版本提交，必须 `引用冲突`且事实代次不变；
6. 经路径服务以权威版本提交，必须成功；
7. 经任务结构公开读取核对任务、方法、版本和七项材料一致。

测试不得直接形成第二写入端口验证绕过；装配失败分支通过静态构造合同和普通应用具名状态覆盖。本段不要求扩大到其它任务入口。

## 7. 完成边界

完成只证明普通应用可取得路径专属入口，且来源方法当前事实与内容版本在写前得到权威校验。capability 端口只证明装配期权限隔离，不证明恶意进程内代码不可调用基础设施接口。

以下仍为 `NOT_RUN`：路径组读、路径退出、当前选择、实例方法、筹办占用、任务筹办生产装配、任务线程、自我治理与真实治理。
