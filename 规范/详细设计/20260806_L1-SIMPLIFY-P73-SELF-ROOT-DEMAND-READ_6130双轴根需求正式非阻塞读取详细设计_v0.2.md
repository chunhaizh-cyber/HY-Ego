## 1. 修订裁决与继承边界

P73 v0.1 已冻结唯一 `L1自我根需求读取服务::读取当前自我双轴根需求`：它按
P56→P69→P17 各恰一次，从同一非阻塞 P17 当前快照解释安全/服务两个活动无父根需求、
八字段、角色1—7、目标五字段和当前实例值。P73 是当前需求及目标字段的唯一解释者，满足、
6170或装配不得直接解析P17/P72形成第二解释者。

P74 已冻结 `I64显式目标输入见证`，其右目标必须同时携带目标状态、目标值稳定编码、来源
服务、目标值创建事实代次和预计值。v0.1 `自我根目标状态当前事实`虽返回目标值稳定编码与
I64材料，却遗漏同一P17值事实中的创建代次，后继无法无损形成P74请求。当前截止、P72发布
代次、需求来源截止和目标状态创建代次都不能替代该字段。

唯一最小修复是：P73在已经读取并验证的目标值事实上回显其真实`创建事实代次`。本版本继承
v0.1未被本文件替换的目标、服务所有权、三个provider、结构筛选、非成功映射、并发、八文件
白名单、顺序573、验证和完成边界；不新增provider、P17调用、快照、写入、满足解释或装配。

## 2. 版本与DTO精确修订

公开聚合字段发生ABI变化，故禁止沿用v0.1版本号。共享头精确调整：

```cpp
inline constexpr std::uint32_t 自我双轴根需求读取合同版本 = 2;
inline constexpr std::uint32_t 自我双轴根需求读取规则版本 = 2;
```

请求、事实和结果中引用上述常量的默认值随之为2；P56/P69嵌套请求版本不变。v0.1请求固定
入口拒绝，不能以缺省补零或聚合尾部兼容继续接受。

`自我根目标状态当前事实`只增加一个字段，位置固定在`目标值`之后、两个版本字段之前：

```cpp
struct 自我根目标状态当前事实 final {
    稳定编码 目标状态;
    根目标比较种类 比较种类;
    std::int64_t 目标值 = 0;
    std::uint64_t 目标值创建事实代次 = 0;
    std::uint32_t 目标状态合同版本 = 0;
    std::uint32_t 比较合同版本 = 0;
    std::array<自我根需求字段值稳定身份, 5> 字段值;
};
```

其它公开结构字段、枚举数值、默认状态、阶段和函数签名不变。不得把新字段加入顶层事实、
单根需求事实、字段值稳定身份或P72发布DTO，也不得直接复用P74类型造成特征比较域反向拥有
需求读取结构。

## 3. 唯一字段来源

P73原有N10目标读取已经在P17同一快照中，对每个当前目标状态的五个字段执行：

1. 目标状态节点当前且创建代次不晚于共同截止G；
2. 五个字段属性类型分别匹配P72稳定定位，当前属性槽各恰一；
3. 槽指向的值事实当前、唯一，所属节点等于目标状态；
4. 值事实属性类型等于本字段属性类型，来源节点等于`事实.需求服务`；
5. 值事实创建代次非零且不晚于G，退出代次为空，材料为I64；
6. `字段值`中本字段稳定编码等于该值事实编码。

当字段为`自我根需求字段::目标值`时，结果来源固定为：

```text
目标状态.目标值 = 该值事实.I64材料
目标状态.目标值创建事实代次 = 该值事实.创建事实代次
目标状态.字段值[目标值].值 = 该值事实.编码
```

安全和服务分别从各自目标状态的目标值事实形成，禁止共用一个创建代次、取目标状态节点创建
代次、P72发布代次、当前截止G、来源事实截止或另一次读取结果。即使两个值事实恰在同代次
创建，也必须逐项独立复制并验证。

## 4. 成功、拒绝和一致性

只有`已读取`且携带完整`自我双轴根需求当前事实`时，新字段必须非零并满足：

```text
目标值创建事实代次 <= 事实.事实截止代次
目标值创建事实代次 == 本轮P17目标值事实.创建事实代次
目标值稳定编码 == 字段值中唯一“目标值”项.值
目标值I64材料 == 本轮P17目标值事实.I64材料
目标值事实.来源节点 == 事实.需求服务
```

安全仍固定`比较种类=大于、目标值=1`；服务仍固定`比较种类=等于、目标值=I64_MAX`。
创建代次只证明该目标值事实的输入版本，不裁决模板命中或当前满足。

以下任一情况沿用v0.1结构损坏分账：返回`内部不一致`、阶段`根需求结构`、事实为空：

- 目标值事实创建代次为0、晚于G或与值事实不等；
- 目标值字段缺失、重复、错属性、错所属、错来源、错材料或错稳定编码；
- 调用方、P72定位或其它字段尝试提供/覆盖目标值创建代次；
- 安全与服务创建代次被容器顺序、最小值、最大值或共同截止统一改写。

P17许可拒绝、资源失败和上游版本漂移仍按v0.1映射；它们不携带目标值创建代次。双根均无
时的`尚无当前双轴根需求`只可回显共同截止，不构造目标事实。不得把缺字段降级成0或
`尚无当前双轴根需求`。

## 5. P74消费接口

P75或其它合法后继只能消费P73 v0.2成功事实形成P74右输入：

```text
I64显式目标输入见证.目标状态
    = P73单根事实.目标状态.目标状态
I64显式目标输入见证.目标值
    = P73单根事实.目标状态.字段值中字段为“目标值”的唯一值编码
I64显式目标输入见证.来源服务
    = P73双轴事实.需求服务
I64显式目标输入见证.创建事实代次
    = P73单根事实.目标状态.目标值创建事实代次
I64显式目标输入见证.预计值
    = P73单根事实.目标状态.目标值
```

后继不得直接调用P17、读取P72发布结果、从P74合同猜测目标值版本或把P73截止填入创建代次。
P74继续拥有注册与比较；P73不import P74、不调用P74、不返回比较请求或比较结果。

## 7. 验证增量

v0.1全部验证继续有效，并新增：

1. 安全/服务目标值事实创建代次不同，结果分别精确回显；
2. 创建代次同值、非零且不晚于G成功；
3. 创建代次0、晚于G、错取目标状态创建代次、错取P72发布代次、错取G逐项拒绝；
4. 目标值字段编码、材料、所属、属性、来源和创建代次六者任一不一致均空事实内部不一致；
5. 双空、P17许可拒绝、版本漂移和资源失败不携带伪目标事实；
6. 源码确认P17调用仍为1，P72发布入口/P74/P15/P37/P54调用均为0；
7. P74映射夹具逐字段证明右输入五项可完全由P73 v0.2成功事实形成；
8. v0.1请求版本拒绝，v0.2请求成功路径和完整成员指针签名成立；
9. Debug/Release Rebuild、自检、strict110/110和模块扫描通过。

启动自检身份和顺序仍为`L1-SIMPLIFY-P73-SELF-ROOT-DEMAND-READ-S01`、573；不得新增第二专项
根或改变574及其它顺序。
