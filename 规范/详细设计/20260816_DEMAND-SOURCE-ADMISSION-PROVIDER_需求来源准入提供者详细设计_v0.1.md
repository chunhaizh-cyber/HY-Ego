# DEMAND-SOURCE-ADMISSION-PROVIDER 需求来源准入提供者详细设计 v0.1

日期：2026-08-16
版本：v0.1

## 1. 目标、范围与完成边界

实现 BIZ-L5-004-02-01-01-01 v0.1 的统一 BIZ `需求来源准入服务`合同：以版本化强类型来源种类和与其绑定的来源对象身份，从不可变 provider 注册中选择恰一个来源专用 provider，消费来源专用材料 / 拒绝 / 非成功，完成跨来源公共互证并形成统一 `已准入需求来源授权见证`。

本叶只建立公共 DTO、来源专用 provider 抽象协议、结构化装配 factory 和统一分派服务。当前必需来源专用 provider 的真实实现、普通应用装配、01候选准入、04防环、05发布、06读回和需求整体建立均为 `NOT_RUN`。抽象协议、未实现 provider 或专项替身不能冒充真实来源准入能力。

## 2. 正式依据与五项冻结裁决

- 3100、5100、5110、5130：来源只形成候选或草案，正式需求只经统一需求提交入口；来源差异不改变目标语义。
- 5150：业务拒绝必须保留结构化原因、失败阶段、冲突证据和重提条件；本叶只返回材料，正式回执由父提交入口写。
- 普通 `提交或复用单目标需求`不得建立新根；冷启动根由独立具名入口建立。父01必须在任何来源调用前完成根拒绝。
- 需求来源统一经一个 BIZ `需求来源准入服务`，内部按来源种类调用各自 provider；不新增第二 DATA 来源授权服务。
- 路径组 OR / 组内成员 AND、精确目标语义键重叠和04防环属于后继，不进入本叶。
- 01/04均只读；拒绝回执由父提交入口写。

## 3. 开放来源种类协议

公共 ABI 不冻结固定数量的封闭枚举。来源种类使用版本化强类型稳定身份；新来源只有在正式规范或用户裁决已经给出其业务边界、形成具名来源专用 provider 合同并登记到普通应用所需来源组后才能使用，无默认或未知来源 provider。

现行规范已识别的 provider 设计队列为：复合特征分解；正式因果或条件链；临时因果视图；已确认任务筹办缺口；方法结构化 / 学习 / 方法自检缺口；根特征自检；普通自检；身体反馈；观察候选；外部输入；正式结算后的后续目标。此清单是当前设计路由，不是稳定数值全集。

临时因果视图必须独立于正式因果或条件链；前者只能承载候选 / 草案，不能冒充正式主动致变因果。5100 中“执行结果”不形成额外通用来源：它只能作为已确认任务缺口的材料，或经正式结算形成后续目标；“方法能力”归方法结构化 / 学习来源；“因果反推”按正式性进入正式因果或临时因果 provider。

## 4. 公共强类型与目标语义键

物理位置：

```text

```

文件与模块合同：

| 文件 | 分类 / 唯一所有者 | 工程登记 | 依赖与调用 |
| --- | --- | --- | --- |
| `服务.需求来源准入.ixx` | 真实模块 / 需求来源准入公开值类型、来源专用协议、装配和分派服务 | `ClCompile`恰一次 | `export module 海中鱼巣.领域.服务.需求来源准入;`；全局模块片段只包含所需标准库，随后以普通 `import` 私有依赖 `海中鱼巣.领域.合同.L2结构公共`、`海中鱼巣.领域.服务.L2特征结构`和`海中鱼巣.领域.服务.L2状态结构`；只导出本模块自己的 DTO / helper / 协议 / 服务，不传递导出整项 DATA 服务；只允许 BIZ 消费者 import，禁止 DATA 反向依赖 |

不建立 `需求来源准入.数据.h/.cpp`。本叶没有需要传统头文件完整类型的既有 `.h/.cpp`调用者；当前和后继合法消费者均为真实模块并统一 import 本模块。仅因 DTO 较多建立传统头会违反 CODE-FILE-01 3.1 的准入条件。若未来出现真实传统调用边界，必须另建迁移 / 适配计划，不能在本叶预建兼容头。

公开函数归属固定：

| 函数 | 能力 / 所有者 | 文件 / 可见性 | 允许 / 禁止调用方 |
| --- | --- | --- | --- |

| `需求来源准入服务::复核需求来源与主体授权` | 恰一分派与公共互证 / 统一来源准入服务 | 服务模块导出公开 `const noexcept`成员 | 01及后继合法 BIZ 消费者可调用；禁止 DATA/L1、来源专用 provider反向调用 |

该物理归属不建立第二事实所有者：模块导出的 DTO 只是调用方拥有的值，服务对象不保存需求、来源或授权机器事实，只借用生命周期覆盖自身的 provider 并执行只读分派。

目标语义键必须复用 `DEMAND-CURRENT-SAME-PARENT-TARGET-CONSUME v0.2` 已冻结的内容键，不得用目标合同或比较注册身份代替：

来源种类身份的稳定编码标识具名来源协议，语义版本标识该协议字段与解释版本；二者整体才是注册键。来源规则版本描述同一来源协议下的具体业务裁决规则，不能代替种类语义版本。发生时间见证是来源正式时间事实的不透明身份与规则版本；统一服务只校验与请求完全相等，不跨时间域排序、不换算单位、不读取系统时钟。

`需求来源待补事实种类`是不引用尚不存在事实的 BIZ 缺口定位键：稳定编码区分同一角色下不同的待补材料，语义版本冻结该缺口的字段与解释。两者都必须非零；它不是事实身份、DATA 类型身份或生命周期。其 `operator<`先比较稳定编码，再比较语义版本；专用 provider 必须在自己的合同中登记所能返回的具名缺口种类，统一服务只作结构互证，不从名称或角色猜测缺口种类。

`需求来源对象身份`整体才是公开强类型定位键；不存在只接收 `对象`字段的公共入口。各专用 provider 必须把完整绑定机械转换为自身更具体的任务、方法、因果或其它强类型身份并互证，禁止跨来源种类解释相同裸编码。

`需求来源种类身份::operator<`先比较稳定编码，再比较语义版本；factory、注册查重和二分定位统一使用这一顺序，不得按 provider 地址、传入顺序、名称或裸对象编码排序。

服务模块公开下列纯值 helper，签名与责任固定：

```cpp
bool 需求目标语义键有效(const 需求目标语义键& 目标) noexcept;
bool 需求来源准入请求有效(const 需求来源准入请求& 请求) noexcept;
bool 需求来源专用准入结果形状有效(
    const 需求来源专用准入结果& 结果,
    const 需求来源准入请求& 请求) noexcept;
bool 需求来源准入结果形状有效(
    const 需求来源准入结果& 结果) noexcept;
```

前两个 helper 要求：完整来源种类身份与对象编码非零且两处种类相等；主体、目标 / 引用、G0和时间身份非零；目标比较合同通过 `L2特征比较I64合同材料有效`，并固定用途为目标判断、左角色为当前事实、右角色为目标状态、方向为右减左；允许关系位通过 `L2目标状态允许关系位有效`，目标状态规则版本等于正式常量；来源、授权、时间规则版本及两个预算全部非零。后两个 helper 只判断本节和第6节冻结的状态、截止与 optional 形状，不调用 provider、不读取事实、不替代服务的逐字段业务互证。四个定义在模块中置于所引用 DTO 全部定义之后，禁止依赖未完成类型。

来源对象见证的身份、提出主体、目标 / 引用、时间、来源规则版本和 G0必须与请求相等；身份来源角色必须为`身份来源`且事实身份等于来源对象编码，来源对象生命周期及全部采用事实都要求创建代次不晚于 G0且无退出代次。`采用事实`不得重复单独的身份来源，按角色、事实身份稳定排序且不超过来源读取预算；`采用授权见证`按“依据分支、正式授权事实身份或内在规则身份、适用来源、被授权主体、覆盖目标”稳定排序、零重复、非空且不超过授权组预算。每项适用来源必须等于请求来源身份，禁止把同主体 / 同目标但来自其它对象的授权移接到本来源。DATA 返回合法空授权事实组不是内部错误；来源专用 provider 只有在正式来源规则允许且能形成至少一项可审计 BIZ 授权见证时才能形成成功材料。

两种授权依据不得互相冒充：

- `需求来源正式授权事实依据`要求授权事实角色恰为`授权依据`、授权方非零，授权事实生命周期在 G0 当前；
- `需求来源内在规则依据`要求来源种类等于请求来源种类、规则身份非零、规则版本等于请求授权规则版本；它没有也不得补造 `L2存在身份`授权方或 DATA 生命周期；
- 两个分支都必须把适用来源、被授权主体、完整覆盖目标、授权规则版本和 G0 与请求逐字段绑定。内在授权不能只返回布尔成功，也不能把 BIZ 规则伪装成 DATA 授权事实。

    来源拒绝 = 4,
    观察或材料待定 = 5,
    来源未找到 = 6,
    来源已退出 = 7,
    当前性漂移 = 8,
    版本漂移 = 9,
    提供者拒绝 = 10,
    许可拒绝 = 11,
    数量预算不足 = 12,
    资源失败 = 13,
    未实现 = 14,
    内部不一致 = 15
};

struct 需求来源准入结果 final {
    需求来源准入状态 状态 = 需求来源准入状态::请求拒绝;
    std::uint32_t 合同版本 = 需求来源准入合同版本;
    std::uint32_t 规则版本 = 需求来源准入规则版本;
    std::uint64_t 事实截止代次 = 0;
    std::optional<已准入需求来源授权见证> 见证;
    std::optional<需求来源拒绝证据> 拒绝证据;

专用 `已形成材料`只允许 `材料`存在、拒绝证据为空；专用 `来源拒绝` / `观察或材料待定`只允许拒绝证据存在、材料为空；其它专用状态两个 optional 都为空。公共 `已准入`只允许见证存在；公共 `来源拒绝` / `观察或材料待定`只允许拒绝证据存在；其它公共状态两个 optional 都为空。

事实截止形状固定如下：

- 专用 `已形成材料`、`来源拒绝`、`观察或材料待定`、`来源未找到`、`来源已退出`必须回显请求 G0；其中前三类的材料或拒绝证据也必须回显同一 G0；
- 专用 `当前性漂移`必须携带非零且不等于请求 G0 的实际截止；
- 专用其它状态截止为0。公共结果除本服务入口拒绝、来源类型不匹配、未登记未实现固定截止为0外，逐项保留合法专用截止；任何错截止均映射公共 `内部不一致`且截止为0。

拒绝证据的来源身份必须等于请求来源身份。`冲突事实`只引用已经存在的事实，按“角色、事实身份”稳定排序、零重复，生命周期必须完整；它可以显式携带已退出事实，但不得把未产生事实伪装成零身份引用。`待补事实`不携带事实身份、事实版本或生命周期，只用角色、强类型缺口种类、来源、被授权主体、目标、可空预期授权方和所需规则版本描述缺口；其中缺口种类、来源、主体、目标和规则版本必须有效且与请求 / 专用 provider 合同一致。由于每项来源、主体和目标都必须与同一请求相等，稳定排序键固定为“角色、缺口种类、预期授权方有值标记、预期授权方、所需规则版本”，并按完整定位零重复；相同角色下的不同缺口种类不得合并。两组计数总和不得超过来源读取预算与授权组预算之和，且至少一组非空。

类别、阶段、证据角色、生命周期和两组形状只能采用下表；“必含角色”要求该组至少一项，“允许角色”约束该组每一项，表外组合全部是坏结果：

| 拒绝类别 | 固定失败阶段 | 冲突事实组 | 待补事实组 | 允许 / 必含角色 | 生命周期与版本 |
| --- | --- | --- | --- | --- | --- |
| 来源不成立 | 来源规则 | 非空 | 空 | 只允许且必含`来源内容` | 每项创建代次不晚于 G0、无退出代次 |
| 提出主体不匹配 | 来源规则 | 非空 | 空 | 只允许且必含`来源内容` | 每项创建代次不晚于 G0、无退出代次 |
| 目标绑定不匹配 | 来源规则 | 非空 | 空 | 只允许且必含`目标绑定` | 每项创建代次不晚于 G0、无退出代次 |
| 授权缺失 | 授权读取 | 空 | 非空 | 只允许且必含`授权依据` | 缺口种类 / 语义版本有效，所需规则版本等于请求授权规则版本；预期授权方可空，有值时必须非零 |
| 授权范围不覆盖 | 授权规则 | 非空 | 空 | 只允许且必含`授权依据` | 每项创建代次不晚于 G0、无退出代次 |
| 授权已退出 | 授权读取 | 非空 | 空 | 只允许且必含`授权依据` | 每项创建代次不晚于 G0，退出代次存在且不晚于 G0 |
| 来源规则拒绝 | 来源规则 | 非空 | 空 | 只允许且必含`来源内容` | 每项创建代次不晚于 G0、无退出代次 |
| 观察或材料待定（来源材料） | 来源读取 | 空 | 非空 | 只允许`来源内容`或`当前性`，且至少一项 | 缺口种类 / 语义版本有效，所需规则版本等于请求来源规则版本；预期授权方必须为空 |
| 观察或材料待定（授权材料） | 授权读取 | 空 | 非空 | 只允许且必含`授权依据` | 缺口种类 / 语义版本有效，所需规则版本等于请求授权规则版本；预期授权方可空，有值时必须非零 |

`来源拒绝`不得使用`观察或材料待定`类别，`观察或材料待定`必须使用同名类别并匹配上述两个阶段之一。冲突事实除`授权已退出`一行外都必须在 G0 当前；待补定位永远没有生命周期。`允许重提=false`时重提所需规则版本必须为0，`允许重提=true`时必须非零。错来源、错阶段、错类别 / 角色、错 G0、无效缺口种类、坏生命周期、重复 / 乱序 / 超预算或重提形状错误都属于 provider 坏结果，统一映射 `内部不一致`，不得作为普通业务拒绝返回。

provider 已返回 `已形成材料`后，来源、主体、目标、时间、G0、版本、采用授权见证或范围任一错配都是坏成功形状，统一映射 `内部不一致`，不得降级为业务来源拒绝。业务拒绝只能来自 provider 的明确 `来源拒绝`。

服务构造函数私有，只能由 factory 建立。输入顺序不具语义；来源种类身份有效固定为“稳定编码非零且语义版本非零”。factory 在任何复制、排序或 provider 调用前要求注册版本非零、必需来源组非空且其中每个身份有效；任一不满足都返回`请求拒绝`、零服务和零冲突来源。通过输入门禁后复制两组，恰一次读取每个 provider 的承载种类；任一 provider 回显无效身份固定返回`内部不一致`、零服务和零冲突来源。只有全部 provider 身份有效后才按完整来源种类身份稳定排序，并执行下列固定优先级：

```text
必需来源组重复 -> 来源种类重复，冲突来源为排序后首个重复项
provider承载种类重复 -> 来源种类重复，冲突来源为排序后首个重复项
provider存在不属于必需组的种类 -> 提供者种类不匹配，冲突来源为排序后首个额外项
必需组存在无provider的种类 -> 必需来源缺失，冲突来源为排序后首个缺失项
两组一一对应 -> 已装配
```

因此两组数量不等不单独发明状态：多出的 provider 按错种类处理，缺少 provider 按缺失处理。复合错误总优先级固定为“输入门禁请求拒绝 -> provider无效身份内部不一致 -> 必需来源重复 -> provider来源重复 -> provider额外错种类 -> 必需来源缺失 -> 成功”；进入四项集合比较后按上表只返回首个状态。成功后服务内部保存排序后的不可变引用组和注册版本。任何失败只返回装配失败，不交付半配置服务。provider 生命周期必须覆盖服务。

装配结果 optional 形状固定：仅 `已装配`允许 `服务`存在、冲突来源为空且注册版本回显非零；`必需来源缺失`、`来源种类重复`、`提供者种类不匹配`只允许冲突来源存在、服务为空且注册版本回显原值；`请求拒绝`、`资源失败`、`内部不一致`两个 optional 都为空，其中请求拒绝的注册版本为输入值，其余为0。`成功()`只接受 `已装配 + 非零注册版本 + 服务有值 + 冲突来源为空`。失败对象不可调用运行入口，且不存在默认构造、半配置或“调用时再报装配失败”的服务实例。

运行请求的来源种类未登记唯一返回 `未实现`；已登记 provider 返回 `请求拒绝`唯一映射公共 `提供者拒绝`，`许可拒绝`单独映射，不与提供者拒绝合并。注册内部出现理论上不可能的重复或错位映射内部不一致。

## 8. 固定控制、失败与并发

```text
校验合同、来源种类/对象绑定、主体、完整目标语义键与引用、G0、时间见证、版本和预算
-> 在不可变注册中定位恰一provider
-> 未登记返回未实现
-> 原请求恰一次调用provider
-> 专用请求拒绝映射提供者拒绝；其它非成功逐项同义映射
-> 专用业务拒绝/待定只转交完整拒绝证据
-> 专用材料逐字段互证来源、主体、目标、时间、G0、版本和非空授权见证
-> 一次形成统一值式见证并无抛出返回
```

函数零写、零锁、零等待、零重试、零缓存、零截止重选。不同请求可并发只读；异常中 `bad_alloc` / `length_error`映射资源失败，其它映射内部不一致，均零成功见证。

## 9. 当前能力与待实现接口

- 可复用：L2 特征定义 / 状态 / 动态 / 因果完整读取及公共 G0 / 状态；任务线程请求 / 回执、自我治理消息、D455上行材料只可作为非权威定位材料。
- 待实现：当前已识别来源协议中的权威来源专用 provider；正式因果主动致变资格也是 BIZ provider 的职责，不能由 L2 因果存在直接推出。
- 每个来源专用 provider 后继设计在自己的详细设计中冻结“根据哪些参数读取哪些中性数据”及最终 DATA ABI。统一服务不修改 `计划/数据服务最终需求清单.md`，不发明通用 DATA 来源授权服务。

## 10. 验证与激活门禁

验证覆盖：factory 的成功、缺失、重复、错种类、无效必需身份、provider无效回显、资源失败、复合错误优先级和零半配置服务；所有已登记来源分别恰一次路由；未登记、错来源对象绑定在 provider 前拒绝；专用结果与公共结果 optional 矩阵；拒绝类别 × 阶段 × 证据组 × 角色 × 生命周期 / 缺口版本矩阵；提供者拒绝与许可拒绝分账；成功见证的来源、主体、完整目标语义键 / 引用、时间、G0、版本和授权范围逐字段相等且采用授权见证非空；坏成功形状内部不一致；DATA合法空授权事实组不被统一服务擅自授权；零 DATA / L1 直达、零写、零锁 / 等待 / 重试 / 缓存。

实现验证要求根工程 Debug / Release、生产外专项双配置、diff、strict、UTF-8、工程唯一登记和临时专项清理后复验。

计划保持待激活，直到当前普通应用必需来源组的每个专用 provider 目标合同、真实依赖和最终 ABI 均冻结，且不会改变公共结果、装配、目标语义键或授权见证边界。任何要求把来源种类改回封闭枚举、把所有对象压成无种类裸编码、让 DATA 返回业务布尔、让统一服务广播猜测或把非权威消息冒充来源事实的变化，固定退回 `DRIFT-DEMAND-SOURCE-ADMISSION-PROVIDER-BOUNDARY`。
