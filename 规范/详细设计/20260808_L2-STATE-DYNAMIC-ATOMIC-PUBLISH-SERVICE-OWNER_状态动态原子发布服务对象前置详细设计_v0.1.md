日期：2026-08-08

状态：设计就绪；只冻结最早可独立施工的服务对象前置合同，不证明状态动态联合发布已经迁移到中性 CRUD、已经进入运行期装配、已经被世界树门面消费或已经实际运行。

## 1. 目标、问题与完成条件

当前 `海中鱼巣.领域.服务.状态动态原子发布` 只导出无对象状态自由函数：

```cpp
状态动态原子发布结果 发布实际存在I64后继状态与迁移动能(
    L1事实基座服务&,
    L1实例特征服务&,
    L1状态服务&,
    特征比较服务&,
    L1动态服务&,
    const 状态动态原子发布请求&);
```

后继业务中性 CRUD 迁移不能机械保留该形状。4015、4040 要求同一中性幂等键只有在规范化完整中性写集逐字段相同时才返回精确重复；当前入口的首次写集却由 P13 当前前状态选择和可选 P14 动态规格形成。首次发布后当前状态已经变化，重复请求若重新运行 P13/P14，不能保证重建首次写集，也不能用普通 CRUD 的审计、完整快照或恢复入口补取首次写集。

因此最早独立叶先只完成所有权前置：把既有自由函数原位收束为非复制的具名 `状态动态原子发布服务` 对象方法，使未来专属锁、完整业务请求和首次规范化中性写集缓存具有唯一对象生命周期所有者。现有 legacy 探测、G7、执行证据、`提交写集` 和领域读回本叶保持逐字语义不变；中性 CRUD 迁移由下一消费叶完成。

完成条件：

1. 模块只导出一个 `状态动态原子发布服务` 类型和其同名发布方法；旧六参数自由函数定义与声明归零。
2. 服务构造一次绑定 L1、实例特征、状态、比较和动态五个非拥有引用；对象不可复制。
3. 既有发布函数体机械迁入对象方法，只把五个显式服务形参替换为对应成员引用；请求、分支、调用次数、legacy 写集、错误映射和读回语义均不改变。
4. 本叶不新增锁、缓存、中性写集、运行期对象、世界树门面调用或测试入口。
5. 后继中性迁移叶可以在该对象内唯一增加专属串行锁和按幂等身份保存的完整首次材料，而不再决定服务形态、依赖所有权或未来调用方向。

## 4. 方法正文机械迁移

本叶不重写算法，只做以下参数到成员的一一替换：

| 当前实参/形参 | 目标成员 | 用途 |
| --- | --- | --- |
| `L1` | `L1_` | legacy 幂等探测、执行证据形成、legacy 提交 |
| `实例特征` | `实例特征_` | P13 后继状态规格输入 |
| `状态` | `状态_` | P13 和发布后状态领域读回 |
| `比较` | `比较_` | P13 状态迁移比较 |
| `动态` | `动态_` | P14 规格和发布后动态领域读回 |

必须保持：

1. `请求有效` 在任何 provider / L1 调用前拒绝。
2. `形成请求意图摘要`、`形成最终键`、G7 意图和第一次 `探测幂等` 的顺序不变。
3. 同义已发布仍不调用 P13/P14/提交，只从旧首次结果完成领域读回。
4. 未找到才调用 P13；等价分支不调用 P14，非等价分支恰一次调用 P14。
5. `合并写集`、`形成执行证据材料`、`提交写集(..., 0x15000603U)` 以及精确重复后的第二次胜者探测不变。
6. `完成领域读回` 的参数、首次/重复状态、P13/P14 摘要和失败见证处理不变。
7. `std::bad_alloc` 仍映射资源失败，其它异常仍映射内部不一致。

内部 helper、数据头、常量、枚举、DTO、模块 import 和工程登记全部保持不变。若机械迁移发现 helper 必须改签名、公开 DTO 必须改变或需要新依赖，停止并退回计划支撑，不得顺带进入中性 CRUD 迁移。

## 5. 并发、缓存与后继消费门禁

### 5.1 本叶明确不实现

本叶不新增互斥量，也不声称当前 legacy 入口具有对象级串行合同。当前事务和 legacy 幂等并发仍由原 L1 路径承担；本叶只建立未来可承载专属锁的对象边界。

本叶不新增任何请求或写集缓存。尤其禁止：

- 单项“最后请求”缓存；P16 可连续发布多个不同状态，不能只记最后一次；
- 模块全局或函数静态缓存；其生命周期和运行期上下文不一致；
- 用日志、当前状态、L1 完整快照、审计或恢复材料重建首次业务写集；
- 在数据头加入 L1 业务字段或恢复 legacy 探测作为中性迁移方案。

### 5.2 下一消费叶的硬门禁

下一份“状态与动态原子联合发布入口业务中性 CRUD 迁移”计划必须等待本叶真实代码结果进入 main 并经交互接受，再从新 HEAD 重做 S0。它必须在本服务对象内冻结并实现：

```text
P16 专属整段串行锁
+ 按最终中性幂等键索引的多项缓存
+ 每项完整公开请求
+ 首次规范化 L1中性写集请求
+ 首次新编码映射 / 领域读回定位与必要结果见证
```

同义重复必须从缓存重建并恰一次重新提交首次完整中性写集，再按当前权威入口读回；缓存不能直接返回成功。异义同键在 L2 返回冲突或由相同最终写集交 L1 裁决，具体映射必须由下一详细设计冻结。首次失败、L1 非成功或发布后读回失败如何写入/不写入缓存也必须逐分支冻结，不能交给执行者决定。

P45 后继必须改为消费 `状态动态原子发布服务&`，不得继续保存五个 P16 底层引用并调用旧自由函数。运行期装配必须保证只建立一个 P16 服务实例；这两个后继都不属于本叶代码白名单。
