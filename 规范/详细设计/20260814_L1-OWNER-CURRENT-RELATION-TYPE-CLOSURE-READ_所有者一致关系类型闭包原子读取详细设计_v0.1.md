# 所有者一致关系类型闭包原子读取详细设计 v0.1

日期：2026-08-14

设计身份：`L1-OWNER-CURRENT-RELATION-TYPE-CLOSURE-READ`

状态：设计就绪；不等于代码已实现

## 1. 目标与具名缺口

建立与既有 `L1事实基座服务::尝试读取所有者范围一致当前投影` v2 并列的新具名关系类型闭包投影：调用方给出一个已知入口关系类型，以及两端需要投影的属性类型和一跳源 / 目标关系类型；L1 在同一次仓库共享锁内枚举入口类型的全部当前关系，并为每个成员返回完整关系、源 / 目标节点、被选择的两端当前属性值和端点一跳关系组。既有 v2 ABI 和行为保持不变。

当前 C1 草稿必须先通过固定角色关系取得动态根编码，再以这些编码读取根节点、首次请求见证和直接上位关系组。现行 L1 只能按已知端点读取关系组，两次公开读取之间允许任意 owner 推进全局事实代次，不能证明 C1 的零守卫全组读来自一个原子最新快照。该缺口命名为：

`DRIFT-C1-L1-DYNAMIC-ROOT-CLOSURE-ATOMICITY`

本叶只补 DATA-L1 通用读取闭包，不创建概念、方法、根、owner、缓存、自动重试、整库快照或全 owner 扫描入口。

## 2. 当前事实与复用裁决

正式基线 `1af85dd9e9d71ea6e5cce90df896702c4a935e02` 已具备：

- owner-aware v2 节点、关系、值、属性槽、源 / 目标关系组和一致当前投影；
- `期望事实代次=0` 在一次共享锁内原子选择当前截止；
- 当前源关系索引和当前目标关系索引，关系编码组严格升序；
- 节点投影携带当前属性槽，属性值投影携带槽与完整当前值事实；
- 关系类型与关系写入 owner 同一、关系端点可以跨 owner 的状态完整性约束。

不能复用的现行能力：

- 源关系组要求请求前已知源节点；
- 目标关系组要求请求前已知目标节点；
- 具名关系读取要求请求前已知关系编码；
- 任一两次调用组合都不能宣称同一个共享锁快照。

采用“入口关系类型 + 端点一跳闭包”而不采用“owner 全量快照”或“第二关系类型全仓扫描”：未来概念 owner 会承载普通概念、DAG、支持和生命周期事实；每次只读四根不应固定扫描该 owner 的全部节点、值、全部直接上位边或其它无关关系。闭包只枚举调用方明确选择的入口关系类型，再利用既有端点索引为已发现端点读取明确选择的一跳关系组和属性。

## 4. 请求有效性与结果形状

### 4.1 入口校验

新具名入口固定：

1. 合同版本必须为 1；八组选择全部为空才是空请求；仅关系类型闭包非空是合法请求。
2. 每个 `入口关系类型节点` 必须非零，同一请求的闭包选择中不得重复。
3. 每项两端的属性类型、源关系类型和目标关系类型六个选择组必须分别严格升序、非零且不重复；空组合法。
4. 关系类型同时出现在普通 `节点` 选择中合法，两者证明目的不同，不使用跨选择组的全局去重拒绝。
5. 任一非法项使整次请求 `入口拒绝`；新结果的八组载荷为空，`读取事实代次=0`。既有 v2 入口继续按原七组合同校验。

### 4.2 闭包项目状态

仓库在取得共享锁并完成零 / 非零守卫裁决后，先读取入口关系类型节点：

- 当前存在且节点种类为关系类型：项目 `成功`，回显完整 `关系类型事实`；没有当前关系时成员为空仍是成功。
- 当前不存在但历史存在：项目 `已退出`，事实和成员为空。
- 从未存在：项目 `未找到`，事实和成员为空。
- 当前节点存在但不是关系类型：项目 `种类不匹配`，事实和成员为空。

项目状态不是领域资格。调用方自行使用 owner-aware 节点事实核对其预期 owner。

### 4.3 成员形状

成功项目的成员覆盖该关系类型在所选截止的全部当前关系，按关系稳定编码严格升序。每个成员必须满足：

- `关系.关系类型节点` 等于 `入口关系类型节点`；关系当前、完整、未退出；
- `源节点.编码` 和 `目标节点.编码` 分别等于关系端点，两节点当前、完整、未退出；
- 关系、关系类型、两端节点、端点属性和端点一跳关系组都来自同一仓库状态和同一 `读取事实代次`；
- 源 / 目标属性值结果分别与请求属性类型一一对应并保持请求顺序；节点字段固定为对应端点；
- 槽存在时状态为成功并携带属性槽和完整当前值事实；槽不存在时为属性未设置且投影为空；
- 两端源 / 目标关系组分别与请求的一跳关系类型一一对应并保持请求顺序；每组端点固定为当前成员的对应端点；关系类型当前且种类正确时项目成功并回显完整类型事实，成员按关系稳定编码严格升序并携带完整关系与对端节点，合法空组仍成功；关系类型未找到、已退出或种类不匹配时使用同名项目状态且类型事实 / 成员为空；
- 当前索引、关系、端点、槽、属性类型和值不能逐字段互证时，整次闭包投影返回 `内部不一致`，八组载荷全部为空。

闭包只从入口关系成员的两端展开一跳，不递归沿对端继续展开，不按被选择的一跳关系类型全仓枚举，不隐式读取端点全部当前值，不过滤跨 owner 端点，也不解释关系类型的领域含义。

### 4.4 总结果状态

- 零守卫：锁内选择当前截止，成功回显 `期望事实代次=0` 和实际 `读取事实代次`；不返回事实代次漂移。
- 非零守卫：精确匹配才读取；不匹配返回事实代次漂移，八组载荷为空，读取代次回显当前代次。
- 共享锁竞争：许可拒绝，零载荷。
- 分配或长度资源失败：资源失败，零载荷。
- 私有状态、索引或投影互证失败：内部不一致，零载荷。

所有失败必须清空新旧全部项目组，不能保留半闭包。

## 5. 仓库内部结构与算法

### 5.1 当前关系类型索引

`仓库.L1事实基座.ixx` 的私有状态增加：

```cpp
std::unordered_map<std::uint64_t, std::vector<std::uint64_t>> 当前关系类型索引;
```

键是关系类型节点编码，值是全部当前关系编码严格升序组。它只作可重建运行期索引，不取得第二事实权威。

所有当前关系建立 / 退出候选必须与既有源 / 目标索引同时插入 / 删除关系类型索引。任一索引操作失败使候选写集失败且不发布；候选副本不会污染已发布状态。

`状态完整` 必须证明：

- 索引键和值非零，编码组非空且严格升序；
- 每个索引键对应一个当前、未退出、节点种类为关系类型的节点；
- 每个索引关系在当前关系表中恰好存在一次且类型匹配、未退出；
- 每个当前关系在关系类型索引中恰好出现一次；
- 索引关系总数等于当前关系总数。

### 5.2 同锁读取顺序

新旧两个公开仓库函数共享一个私有规范化投影核心 `尝试读取所有者范围一致投影内部`。旧 v2 包装传入原七组选择和空闭包；新 v1 包装传入八组选择。核心只取得一次共享锁，不允许一个公开函数调用另一个公开函数或发生第二次读取。步骤固定为：

```text
对应具名合同入口校验
-> try_lock 取得一次共享锁
-> 校验状态完整
-> 零守卫选择锁内当前 / 非零守卫严格比较
-> 投影既有七组选择
-> 新 v1 请求再逐个投影关系类型闭包：
     入口关系类型节点状态
     -> 当前关系类型索引成员
     -> 完整关系和两端节点
     -> 明确选择的两端属性槽与当前值
     -> 以已发现端点读取明确选择的一跳源 / 目标关系组
-> 成功一次性返回
```

闭包内部辅助必须是仓库私有 `已加锁` 风格辅助：不重新取得锁，不调用公开入口，不执行日志、I/O、回调、等待或上层服务调用，不返回内部引用。

入口关系成员只从 `当前关系类型索引[入口关系类型节点]` 取得；端点一跳源 / 目标关系组必须复用已发现端点对应的 `当前源关系索引` / `当前目标关系索引` 路径，不得再查 `当前关系类型索引[一跳关系类型]` 后全仓过滤端点。

## 7. 兼容、失败与禁止项

现行调用者继续使用相同 v2 DTO、函数和常量，字段布局、行为、顺序、状态、零 / 非零守卫和锁竞争语义不变。新 v1 合同独立失败、独立返回，不从 v2 版本或结果猜测兼容；两个入口只共享仓库私有实现，不互相调用。

禁止：

- 新建同义读取函数、整库 / owner 全量快照、第二关系类型全仓扫描或概念专用入口；
- 先枚举后再次读取、两次零读、忙重试、sleep、yield 或缓存动态编码；
- 在 L1 DTO 中加入根角色、概念、方法或业务标签；
- 过滤坏关系、坏端点或坏属性后返回成功；
- 增加生产验证分支、测试友元、seam、公开运算符以外的验证专用 ABI；
- 修改写事务、幂等、事实代次、源 / 目标索引或 owner 许可语义。
