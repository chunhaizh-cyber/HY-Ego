# INSTINCT-STAGE3-SERVICE-ACTIVITY-V2-PUBLISHER 服务活动 v2 生产事实发布详细设计 v0.1

日期：2026-08-30

## 1. 目标与边界

在现有唯一 `服务合同事实权威服务` 内，为已经发布的 `服务合同关联进展事实_v2` 和 `服务准备当前事实_v2` 增加正式生产发布入口。入口负责在同一 owner 写集中建立新事实、替代同一活动流的旧当前事实、保留历史、处理幂等重放，并以现有 v2 完整集合读取结果完成提交后正式读回。

本叶只补事实来源能力。它不执行方法，不从任务结果猜进展，不自动发布样本，不裁决有效服务活动，不形成安全门禁，不调用单完整秒维护规则，不推进游标，不写 A/V、状态或动态。

当前生产安全根定义保持版本 1：值域 `0..I64_MAX`，`L=2,767,011,611,056,432,742`，`H=7,378,697,629,483,820,645`。本叶不得修改阈值或增加运行期自动调节。

## 2. 当前事实与复用裁决

当前 `main@b988ca12066995c0921884af42041ea92c51861c` 已发布：

1. 服务进展/准备 v2 强类型事实、独立登记、当前索引、载荷、关系和 0/N 完整读取；
2. task owner 的生产首个显式 `T→D`、任务退出收口和按任务/G0 完整当前组读取；
3. v2 事实中的正式选择、执行冻结材料、实例方法、筹办轮次和执行轮次强类型布局；
4. L1 owner 范围写集、首次写入材料读取、当前/历史读取和引用当前性验证。

当前缺口：v2 事实只能由专项宏私有 fixture 写入，正式类没有生产发布函数。完整空集合因此只能说明“当前没有 v2 成员”，不能说明全部合法生产者已经把活动事实交付给该 owner。

复用结论：

- 复用现有服务 owner、写端口、`0x0307'3030..304F` 登记和读取入口；
- 不新增 owner、模块、工程文件、键段或第二当前索引；
- 新事实节点、载荷值、当前成员关系和全部强类型引用关系在一个 owner 写集中形成；
- 外部 task/demand/method/state/dynamic 身份只作为当前稳定节点引用，后继活动裁决仍须在 G0 独立读回其业务含义。

### 3.4 状态与结果

```cpp
enum class 服务活动事实发布状态_v2 : std::uint8_t {
    已发布 = 1,
    精确重复 = 2,
    入口拒绝 = 3,
    许可拒绝 = 4,
    当前性漂移 = 5,
    幂等冲突 = 6,
    当前事实冲突 = 7,
    引用冲突 = 8,
    结构未登记 = 9,
    集合不闭合 = 10,
    资源失败 = 11,
    内部错误 = 12,
    已可能发布 = 13
};

template<class 事实类型>
struct 服务活动事实发布结果_v2 final {
    std::uint32_t 合同版本 = 服务活动事实发布合同版本_v2;
    服务活动事实发布状态_v2 状态 = 服务活动事实发布状态_v2::入口拒绝;
    L2结构幂等身份 幂等身份;
    std::optional<事实类型> 事实;
    std::uint64_t 首次提交事实代次 = 0;
    std::uint64_t 本次正式读回截止 = 0;
    bool 成功() const noexcept;
};

using 服务进展事实发布结果_v2 =
    服务活动事实发布结果_v2<服务合同关联进展事实_v2>;
using 服务准备事实发布结果_v2 =
    服务活动事实发布结果_v2<服务准备当前事实_v2>;
```

只有 `已发布/精确重复 + 事实在首次G1完整 + 生命周期创建代次等于首次G1 + 非零首次G1 + 非零Gread + G1<=Gread` 成功。精确重复时首次事实可能已经被同流后继事实退出，因此成功谓词按首次 `G1` 验证事实完整性，不要求该事实在 `Gread` 仍为当前；返回生命周期必须来自本次正式历史读回，不能从首次请求补造。`已可能发布` 只携带幂等身份和首次提交见证，不携带未经正式读回的事实，成功为假。其它非成功事实空、截止 0；是否保留首次提交见证只允许 `已可能发布`。

模板可以物理实现为两个具体结果类型，禁止让执行者改变字段顺序或成功公式。

## 4. 活动流身份与替代规则

同一进展流由以下字段逐项共同定义：

```text
self + 服务合同 + 需求 + 任务 + 方法 + T→D
+ 正式选择 + 执行冻结材料 + 实例方法 + 筹办轮次 + 执行轮次
```

同一准备流由以下字段逐项共同定义：

```text
self + 来源variant标签/身份 + 准备目标 + 适用服务范围
+ 任务 + 方法 + optional T→D
+ 正式选择 + 执行冻结材料 + 实例方法 + 筹办轮次 + 执行轮次
```

发布前以 G0 的现有 v2 完整集合读取重建同流当前组：

- 0 项且请求无预期当前事实：首次发布；
- 恰 1 项且请求预期身份等于该项：更新；
- 其它组合：`当前事实冲突`，零写；
- 同流多项：`集合不闭合`，零写。

更新在一个写集中退出旧事实节点、由当前索引指向旧事实的成员关系、旧载荷当前值及该事实发出的全部本 owner 引用关系，同时建立新事实。退出集合只能包含服务 owner 自有事实；引用目标所属的 task/demand/method/state/dynamic 节点绝不退出。历史读取仍可取得旧事实及其退出代次；v2 当前完整集合只返回新事实。

不同流可以并存。运行状态不是流身份的一部分，因此进行中、等待、暂停、阻塞、失败、取消、到期、终止或准备完成都通过替代形成同一流的新当前事实，不建立并行当前副本。

## 5. 写入与正式读回算法

两个入口固定为：

```cpp
服务进展事实发布结果_v2 发布服务进展事实_v2(
    const 发布服务进展事实请求_v2&) noexcept;

服务准备事实发布结果_v2 发布服务准备事实_v2(
    const 发布服务准备事实请求_v2&) noexcept;
```

算法顺序：

1. 锁定服务 owner；检查合同、共同头、G0、幂等身份、材料和可选预期身份。
2. 先读同幂等身份的首次规范化写集及首次写入结果；存在时必须同时取得首次 `G1` 和首次本地键到稳定编码映射，解析原材料、预期旧身份和写入类型。逐字段同义才进入精确重复历史读回，异义、映射缺失或跨入口复用同键返回幂等冲突/内部错误。
3. 读前守卫要求当前代次等于 G0；验证对应 v2 登记完整。
4. 读取该 self 的当前 v2 完整集合，按第 4 节定位唯一同流旧事实。
5. 对进展材料，要求服务合同在 G0 属于同 self/需求；其余外部引用至少必须是 G0 当前节点。对准备材料，全部强类型引用至少必须是 G0 当前节点。服务 owner 不替代 task/method/state/dynamic owner 裁决业务含义。
6. 形成一个 owner 写集：必要的旧事实闭包退出 + 新事实节点 + 载荷值 + 当前成员关系 + 全部具名引用关系。退出闭包必须逐项来自 G0 正式读回，禁止根据固定数量猜关系；新事实本地键和关系本地键按入口固定，不从容器位置或时间生成。
7. 提交；严格映射 L1 状态。只有成功或精确重复且发布形状正确进入正式读回。
8. 首次发布成功后，在仍持有服务 owner 互斥锁时重新冻结当前 `Gread`，通过类内“已锁定 v2 完整读取”路径按首次写入映射取得新事实身份，逐字段确认新事实存在、旧事实不再当前、形成代次和生命周期正确。不得在持锁状态递归调用会再次加锁的公开读取函数。
9. 精确重复不要求首次事实仍在当前集合。它按首次结果映射取得首次事实身份，以首次 `G1` 为历史截止，通过 L1 历史事实、历史属性值和历史关系组重建首次事实闭包；读前/读后均绑定本次 `Gread`，并确认返回生命周期、首次载荷和全部引用关系与首次规范化写集一致。禁止直接从首次请求构造成功载荷。
10. 首次提交后任何正式读回失败返回 `已可能发布(G1)`；相同请求重试必须从首次写入材料收束为精确重复并读回首次事实。提交前失败不得返回首次提交见证。

为复用现有读取而不形成自锁，服务类将现有两个 v2 公开读取函数的锁内主体抽取为 module-private `...已锁定` 辅助函数：公开读取仍负责加锁并调用该主体，发布入口在已经持锁时直接调用主体。该机械抽取不得改变既有 v2 读取状态、排序、见证或成功公式。

公开入口不读取动态后状态，不把状态/动态当当前值，不调用安全算法，不自动生成进展或准备材料。

## 6. 失败映射

| 下层/业务事实 | 公开状态 |
| --- | --- |
| 坏合同、零G0、零幂等、坏材料 | 入口拒绝 |
| L1许可拒绝 | 许可拒绝 |
| 读前、写前或读后代次变化 | 当前性漂移；提交后读回失败例外为已可能发布 |
| 同键异入口或异材料 | 幂等冲突 |
| 预期旧事实与同流当前不符 | 当前事实冲突 |
| 外部节点不存在/已退出、合同self/需求不符 | 引用冲突 |
| v2登记缺失/版本错误 | 结构未登记 |
| 同流多当前、成员或关系闭包异常 | 集合不闭合 |
| bad_alloc、length_error、L1资源失败 | 资源失败 |
| 未分类异常或不可能形状 | 内部错误；若已提交则已可能发布 |

## 8. 验证矩阵

至少覆盖：

1. 真实 L2 task/demand/method/状态或动态节点作为跨 owner 端点的首次进展发布和正式读回；
2. 同流更新原子退出旧当前并保留历史；历史闭包包含退出节点、载荷、成员关系和全部自有引用关系，且不退出任何外部端点；
3. 精确重复零第二事实、同键异义/跨入口冲突；首次事实尚为当前和已经被后继替代两种重放都能正式收束；
4. 省略预期、错预期、同流多当前均零写；
5. 八种进展运行状态均按原值保存；状态 only、动态 only、二者同时；
6. 准备需求来源携带 T→D、能力缺口来源不携带 T→D、九种状态及完整完成形状；
7. 坏时间窗、坏版本、坏绑定、缺/多 T→D、缺完成结果/验证；
8. 外部引用已退出、服务合同 self/需求冲突；
9. 旧 G0、资源失败、提交后读回失败和重试精确收束；公开读取与发布后锁内读取均无递归加锁；
10. 首次装配、释放后同一 L1 持久根恢复、再次精确重复；
11. v1 读写形状和 v2 读取回归、Debug/Release、ABI consumer、strict、两类 diff-check；
12. 生产 L/H 与安全根定义 blob 零改，生产调用方仍为 0 的事实如实标记。

## 9. 完成声明边界

本设计完成后最多允许声明：服务 owner 具备 v2 进展/准备当前事实的正式生产写入、替代、幂等和读回能力。

它仍不证明真实任务执行已经调用发布入口，不证明合法活动来源全集已经接齐，不允许仅因 v2 空集合就裁决“不存在有效服务活动”。后继必须先接入真实方法执行/准备生产者，并补齐同 G0 安全门禁提供者，才能施工有效活动五项合取。
