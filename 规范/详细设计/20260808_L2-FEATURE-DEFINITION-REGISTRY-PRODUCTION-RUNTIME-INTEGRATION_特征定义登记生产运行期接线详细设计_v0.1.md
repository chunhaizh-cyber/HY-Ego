# 特征定义登记生产运行期接线详细设计 v0.1

日期：2026-08-08

状态：设计就绪；只冻结后续实施合同，不证明代码、生产运行或第一层完善。

## 1. 目标与最早缺口

当前 `L1特征定义服务` 已由唯一生产运行期上下文构造并拥有，具备四节点结构登记、I64 特征定义发布和公开当前读回，但生产启动从未建立其结构登记。没有登记时，后继不能合法创建特征定义、实例特征或首个基准状态。

本叶只闭合最早独立缺口：

```text
复用运行期上下文现有 L1特征定义服务
-> 在动态结构登记成功后建立特征定义结构登记
-> 经同一第二层公开服务权威读回登记
-> 把登记完整性纳入候选上下文发布条件
-> 发布后的运行期租约继续暴露同一服务
```

本叶不创建任何具体特征定义，不选择名称、值域、宿主或初始值；因此不会为了证明第一层制造业务数据。

## 2. 正式依据与当前事实

- 1120：特征定义是抽象特征的权威身份；具体定义和实例槽必须由正式结构区分。
- 4015：第一层只承担业务中性 CRUD、原子提交和最小幂等；能力只由下游真实使用自然累计。
- 4020：类型化值和组合投影必须保持明确类型、来源和不可变读回。
- 4030：领域服务负责业务准入、结构和结果解释，不得为补齐第一层矩阵制造请求。
- 4050：失败必须保留结构化状态，不能用日志或退出码代替。
- 8120、ACCEPTANCE-01：生产入口不承载自检或验收运行器；日志只供人观察。

当前代码事实：

1. `运行期上下文` 已唯一拥有 `L1特征定义服务_`，构造依赖只有同一 `L1事实基座服务_`，并已有 const / 非 const 服务访问器。
2. `L1特征定义服务::建立登记` 已固定形成一个普通服务节点和三个 I64 属性类型节点，以一次中性写集原子提交，并经公开读取根精确读回。
3. `读取当前登记` 已返回值式 `特征定义登记结果`，并在当前事实代次逐字段核对四节点。
4. 生产启动已完成世界、场景、实际存在、状态和动态登记，但没有特征定义登记请求、结果回显或候选完整性读回。
5. 实例特征登记虽已实现，但其具体业务能力依赖特征定义；首个基准状态还要求合法实例特征读取请求，均应后置。
6. 当前计划索引没有可执行项；三个生产文件已释放，异主修复、路线、旧世界树与 `.codex-build` 不重叠。

## 4. 运行期上下文合同

### 4.1 新增窄入口

在现有实际存在读回与状态登记入口之间或与既有构造顺序一致的位置新增：

```cpp
特征定义登记结果 初始化特征定义登记(const 特征定义登记请求& 请求);
特征定义登记结果 读取特征定义登记() const;
bool 特征定义登记完整() const;
```

规则：

- 初始化入口只核对结构核心和 `特征定义登记请求有效`，要求非零期望事实代次，然后恰一次委托现有 `建立登记`；
- 读取入口恰一次委托现有 `读取当前登记`；
- 完整判断只接受 `已读取 + 非空完整登记`；
- 不新增服务成员、代理、缓存、第二登记定位或第二业务解释者。

### 4.2 候选完整性

`运行期上下文::完整()` 增加一次特征定义登记当前读回。发布候选必须同时满足：

- 特征定义登记结果为 `已读取`；
- 登记非空且通过 `特征定义登记完整`；
- 特征定义登记事实截止与世界、场景、实际存在、状态和动态登记的当前共同截止完全相同。

该检查只核对生产候选中的当前权威数据同代次，不证明已有具体特征定义。

## 5. 固定生产配置

`生产运行期配置` 新增：

```cpp
特征操作幂等身份 特征定义登记幂等身份;
```

固定值为 `{1}`，只属于特征定义登记私有幂等域。配置形成、全等和有效性同步核对该字段。

配置头在未由模块导入特征定义数据时包含 `领域/L1特征定义.数据.h`；生产运行期模块使用显式宏边界避免重复声明。

不增加命令行覆盖、环境变量、配置文件、随机身份或运行时补造。

## 6. 生产启动流程

在动态结构登记成功后、系统角色初始化前形成：

```cpp
const 特征定义登记请求 特征定义登记请求值{
    L1特征定义合同版本,
    L1特征定义规则版本,
    配置.特征定义登记幂等身份,
    动态登记结果值.登记->事实截止代次};
```

然后恰一次调用：

```cpp
候选->初始化特征定义登记(特征定义登记请求值)
```

成功只接受 `已提交` 或 `幂等读回`，且结果必须携带完整登记。其它结果立即返回新增的 `特征定义登记初始化错误`，不继续系统角色、概念活动或候选发布。

`生产运行期启动结果` 增加特征定义登记业务状态。已有当前上下文回显 `已读取`；早期失败保持入口拒绝；执行后的分支回显真实领域状态。

## 7. 事务、幂等和失败边界

- 四节点仍由现有特征定义服务的一次中性写集原子提交；本叶不修改事务。
- 同一固定请求按现有完整写集幂等合同收敛；不增加第二账、摘要、业务标签或重试循环。
- 特征定义登记失败时候选不发布；此前局部候选随生命周期销毁，不增加撤销或恢复协议。
- 启动层只映射具名初始化错误并保留特征定义结构化状态。
- 当前阶段不处理崩溃、重启、断电或跨进程恢复。

## 9. 验证与完成边界

实施至少验证：

1. 三个生产文件和两份专属记录以外零本轮差异；
2. 现有特征定义服务成员和访问器数量不变；新增初始化与读取委托各一；
3. 生产启动恰一次特征定义登记，位于动态登记成功后、系统角色前；
4. 固定身份参与配置形成、全等和有效性；
5. 候选完整性公开读回特征定义登记并互证共同截止；
6. 生产代码不新增自检、验收、驱动、第二目标或日志 PASS；
7. Debug / Release 完整重建、双配置模块扫描、strict 和两配置正式生产运行期模式通过。

本叶完成只证明第二层特征定义结构登记成为真实生产初始化能力，并累计四节点中性新增、原子可读和当前查询的实际使用。它不证明具体特征定义、实例特征、状态事实、其它下游服务或第一层整体完善。
