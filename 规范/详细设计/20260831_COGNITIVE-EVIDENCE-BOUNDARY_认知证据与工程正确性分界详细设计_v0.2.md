## 1. 目标与完成边界

本设计只把已冻结机器语义映射为兼容迁移边界：

```text
特征当前值 = 业务目标比较唯一权威
状态 = 某时刻特征事实记录
动态 = 已发生变化及来源记录
因果 = 变化之间的直接关系

状态、动态、因果 = 三类认知证据
任务轮次、选择、结果、结算、后继决议 = 独立治理事实
G0 / 幂等 / 事务 / 读回 / 恢复 / 水位 / 线程同步 = 工程正确性材料
```

完成目标固定为：

1. 停止目标裁决证据节点、稳定证明节点、权威用途观察账及同义证明链的新生产；
2. 停止旧 `L2任务治理状态事实`、`执行结果待验证`和`目标未达成待重筹办`成为 current 任务状态或新生产来源；
3. 保留旧目标裁决证据、旧任务治理状态、旧重筹办来源、旧稳定证据编码和公开符号的历史读取及已有幂等账精确重放；
4. 当前任务阶段只由 ARCH-L2 通用特征、状态和动态以及任务轮次正式事实表达；执行形成结果后进入结算，目标未达成只形成轮次结论，禁止自动重筹办；
5. 当前首次方法选择只接受任务轮次初次筹办来源及其原正式准备记录；
6. 不新增 DTO、公开枚举、普通 bool 一阶特征、无类型证据数组、第二 owner 或第二当前状态权威；
7. 工程正确性机制继续存在，但不进入目标比较、认知样本或方法效果统计。

本设计不恢复 current 自动重筹办，不设计执行后目标未达成迁移，也不宣称未来同任务轮次执行前重新筹办来源 ABI 已闭合。

## 2. 权威冲突裁决

### 2.1 当前状态权威

3200 与 5210 已冻结：任务主阶段和业务状态段由任务专属正式存在上的 ARCH-L2 特征实例、当前特征值、状态和动态承载。旧 `L2任务治理状态事实` 只作历史兼容事实，新的消费者不得把它当作 current 状态。

因此，禁止以下迁移方案：

```text
旧任务治理状态格式 1
-> 新任务治理状态格式 2
-> 继续以 task owner 私有状态表达 current 阶段
```

即使格式 2 不再绑定目标裁决证据，它仍会形成第二任务状态权威，不能施工。旧治理状态材料向量第 0 槽不得增加 current 格式；未知格式继续拒绝。

### 2.2 执行后后继

执行开始或正式实际结果形成后固定进入结算：

```text
正式实际结果
-> 当前值 / 验证 / 归因 / 停止材料独立读回
-> 任务轮次结论与结算
-> 轮次收束
-> 等待自我继续 / 结束 / 等待 / 取消决议
```

`目标未达成`是任务轮次结论，不是主阶段，不是 `目标未达成待重筹办` current 状态，也不能直接形成下一筹办工作包。旧 `提交目标未达成待重筹办迁移(...)` 不再具有首次生产资格。

### 2.3 选择来源

选择来源引用只能指向已经存在的状态、动态、因果或具有独立业务作用的治理事实。不得为了证明选择建立新证据节点。

当前已闭合的首次选择来源只有：

```text
任务轮次初次筹办来源
-> L2任务初次筹办准备记录身份
-> 当前首次正式方法选择
```

旧 `L2任务重筹办规范化来源材料` 绑定执行后实际结果、目标裁决证据和待重筹办治理状态，与现行轮次语义冲突，只保留历史解码和已有账重放资格。

下列公开类型、字段顺序、枚举数值、函数符号和旧持久编码全部保留，不删除、不重排、不复义：

```text
L2任务目标裁决证据身份
L2任务目标裁决结构材料
L2任务目标裁决证据事实
L2任务治理状态事实::目标裁决证据
L2任务选择稳定证据类别::目标裁决证据
L2任务选择稳定证据类别::任务治理状态
L2任务重筹办规范化来源材料
L2任务筹办归因证据引用中的目标裁决证据分支
L2新增执行结果待验证状态请求 / 结果
```

兼容保留只允许：

- 解码已存在的格式 1 节点、关系、属性值和完整请求；
- 按历史截止严格读回旧目标裁决证据和旧治理状态；
- 对已经存在的首次幂等账执行原请求、原规范化写集和原结果的精确重复收敛；
- 返回旧请求原有的强类型事实，不补造 current 投影。

兼容保留不允许：

- 首次建立目标裁决证据节点或旧治理状态节点；
- 以零证据身份解释成新治理状态格式；
- 用 `任务治理状态` 类别承载 current 选择来源；
- 把旧重筹办来源改称同轮重新筹办来源；
- 用旧目标裁决证据身份包装状态、动态、因果或其它治理身份。

## 4. 旧治理写入口冻结合同

### 4.1 共同分支顺序

`新增执行结果待验证状态(...)`和`提交目标未达成待重筹办迁移(...)`保留函数符号，但实现必须按以下顺序执行：

```text
请求公开形状与共同头最低检查
-> 以原强类型幂等身份读取本 owner 首次幂等账
-> 已有账：进入 legacy 精确重放
-> 无账：结构化入口拒绝，零写
```

不得先以“current 不再允许”为由拒绝请求，再遗漏已有账收敛；也不得在无账分支构造任何写集后才拒绝。

无账首次请求的结果固定为：

```text
结果头.状态 = L2结构状态::入口拒绝
结果头.变更事实代次 = 空
全部业务载荷 = 空
零节点、零关系、零值、零属性槽变更、零退出事实
```

入口拒绝是旧生产资格退出的结构化结果，不表示资源失败、当前性漂移或内部不一致。

### 4.2 `新增执行结果待验证状态(...)`已有账重放

已有账必须具备首次规范化写集、首次写入结果，以及能够从首次映射和历史投影完整重建原业务语义的闭包；L1 幂等账不另存本入口的完整业务请求 DTO。处理固定为：

1. 从首次映射和首次事实截止的历史投影重建原治理状态、目标裁决材料及全部来源字段，并与本次请求逐字段相等；不同返回`幂等冲突`，不得重放；
2. 首次写集必须是原格式 1，且包含一个旧治理状态节点、一个目标裁决证据节点、原状态到证据关系、原证据来源关系、原材料值和原治理迁移证据角色；
3. 以原规范化写集调用 L1 精确重放；只接受`精确重复`、首次事实代次和首次编码映射完全相等；
4. 按首次事实代次历史读回旧治理状态和旧目标裁决证据；二者必须逐字段闭合并等于首次请求；
5. 返回原`精确重复`结果。任一旧节点、关系、值、端点或生命周期损坏均为历史结构不闭合，不得降级为空证据 current 状态。

该分支只重放已发布历史事实，不形成新事实代次，不把旧状态恢复为 current 状态权威。

### 4.3 `提交目标未达成待重筹办迁移(...)`已有账重放

已有账处理同样只允许原请求精确重复：

1. 从首次映射和首次事实截止的历史投影重建原迁移语义；本次请求必须与其逐字段相等，包括前驱治理状态、目标裁决证据、旧路径、旧实例、轮次分区和统一轮次推进材料；
2. 原写集及原结果必须完整，L1 重放必须返回首次事实代次的`精确重复`；
3. 只按历史截止读回原目标状态、前驱状态、旧目标裁决证据、旧路径、旧实例和可选旧后继准备记录；
4. 不新建迁移状态，不退出 current ARCH-L2 状态、路径、实例或选择，不形成新后继准备记录。

无首次账一律`入口拒绝`。禁止以旧迁移入口承接执行后的目标未达成结论。

### 4.4 历史读取与恢复

`读取任务治理状态(...)`、`读取任务当前治理状态(...)`和恢复解释器只读取格式 1：

- 目标裁决证据身份必须非零；
- 状态到目标裁决证据关系恰一；
- 目标裁决证据节点、族关系、11 项来源关系和材料值完整；
- 治理状态迁移证据角色 `40..44` 恰五条；
- 公开结果中的目标裁决证据必须存在并与状态字段相等；
- 0 条按原读取合同返回未找到，多条或缺项按原合同返回内部不一致 / 引用冲突；
- 未知材料格式拒绝，不补造、不升级、不改写历史。

`读取任务当前治理状态(...)`中的“当前”仅表示旧 task owner 当前关系在给定历史解释下的投影，不取得现行任务阶段权威。current 业务消费者禁止调用该结果裁决任务阶段。

## 5. 当前首次正式方法选择

### 5.1 首次新发布门禁

`发布任务筹办正式选择_v2(...)`必须先定位原筹办来源首次账，再分流：

```text
已有账
-> 原完整请求相等：精确重放并按原格式读回
-> 原完整请求不等：幂等冲突

无账
-> 来源是 L2任务初次筹办规范化来源材料：继续 current 首次发布
-> 来源是 L2任务重筹办规范化来源材料：入口拒绝，零写
```

已有账判断必须早于 current 来源资格判断，从而保留旧分支已发布事实的恢复能力；无账旧分支不得进入路径、选择、冻结或实例写集构造。

当前首次发布还必须证明：

1. 来源材料的首次准备记录、任务、来源需求、需求列表项、G0、任务建立 G1、筹办轮次 1 和运行代次完整；
2. `稳定证据组`恰一项，类别为`初次筹办准备记录`，身份等于来源材料中的首次准备记录；
3. `冻结材料.归因证据`分支为`L2任务初次筹办准备记录身份`，且身份相同；
4. 当前任务轮次仍处于筹办阶段，尚无本轮当前选择、路径和实例；
5. 来源需求、方法生命周期、完整动作组、冻结材料和共同截止满足现行 v2 合同。

任一目标裁决证据或旧任务治理状态进入 current 首次稳定证据组、归因证据或来源材料，均返回`入口拒绝`或`引用冲突`并零写；具体映射沿现有 v2 状态矩阵，不新增状态枚举。

### 5.2 旧正式选择读取

正式选择持久序列继续解码旧重筹办来源和旧稳定证据类别，以支持：

- 历史选择读回；
- 已有来源幂等账精确重复；
- 持久恢复和损坏检测。

解码成功不等于来源取得 current 生产资格。读取方不得把旧`目标裁决证据`或`任务治理状态`类别复制进新请求。

### 5.3 当前就绪与冻结消费者

`任务筹办当前就绪与执行冻结提供者::形成当前可执行冻结_v2(...)`只接受初次筹办来源：

```text
请求.正式选择基础材料.来源材料
    必须持有 L2任务初次筹办规范化来源材料
```

请求入口在读取方法、条件、输入、限制或动作组之前拒绝旧重筹办来源。`取得归因证据(...)`的 current 可达分支只返回首次准备记录；旧目标裁决证据分支只为历史源码兼容保留，不能由 current provider 调用。

## 6. 稳定选择引用边界

现有 `L2任务选择稳定证据引用` 是“类别 + 稳定编码”旧 ABI，当前不能强类型表达普通状态、动态、因果或新的同轮重新筹办来源。不得采取以下替代：

```text
把状态 / 动态 / 因果编码塞进 目标裁决证据 类别
把 ARCH-L2 当前状态塞进 任务治理状态 类别
把日志 / 哈希 / 请求键作为稳定证据身份
新增证明节点再引用
```

本叶只冻结 current 初次选择的一项来源关系。旧`目标裁决证据`和`任务治理状态`类别仅可随历史选择读取，不得出现在新的选择事务中。

“稳定证据节点停止生产”不等于删除选择记录到既有来源事实的关系；current 关系的目标必须是已经具有独立业务作用的正式来源，本叶唯一已闭合目标是初次筹办准备记录。

## 7. 执行后结算与未来重新筹办

### 7.1 执行后固定进入结算

任何正式实际结果，包括目标已达成、目标未达成、不可比较或材料不足，都不得调用本设计冻结的旧治理写入口。生产链固定为：

```text
正式实际结果读回
-> 同截止读取当前特征值和目标合同
-> 形成任务轮次结论 / 结构化非成功
-> 验证、归因、停止和结算
-> 轮次收束
-> 自我后继决议
```

自我决定`继续`时建立新任务轮次并走普通初次筹办来源，不恢复旧自动重筹办分支。

### 7.2 独立 DRIFT

具名未决点：

```text
DRIFT-CURRENT-SAME-ROUND-PRE-EXECUTION-REPLANNING-SOURCE-ABI-UNFROZEN
```

适用范围仅为：任务仍在筹办阶段、实例执行尚未开始，因等待回流、来源 / 目标 / 方法 / 条件 / 输入或冻结当前性变化而结束旧筹办轮次并建立同一任务轮次的新筹办轮次。

现有 ABI 的旧重筹办分支绑定执行后实际结果、目标裁决证据和待重筹办状态，不能表达上述来源；现有归因联合也不能强类型引用新的合法治理来源。后继设计必须冻结：

- 强类型来源分支及字段顺序；
- 任务轮次、旧 / 新筹办轮次、旧选择 / 路径 / 实例与“尚未执行”的同截止证明；
- 等待回流或冻结失效事实的正式 owner 和读取入口；
- 幂等、当前性、退出旧当前关系、发布未知和恢复矩阵；
- 选择来源引用与冻结归因的强类型表达。

该 DRIFT 不阻塞本叶停止旧证明生产和闭合当前首次选择；在专属合同冻结前，同轮重新筹办返回材料不足 / 合法等待，不得回落旧分支。

## 8. 用途观察与工程见证

用途观察节点类型、关系类型和稳定命名域保持原数值，只允许历史解码。当前代码没有正式 provider 时继续保持没有，不建立“退役服务”，也不创建空节点证明其已退役。

G0 / G1、幂等账、规范化写集、提交见证、发布读回、恢复、水位、线程槽和日志只证明工程过程。它们不得进入目标比较，不得成为认知证据，不得生成独立生命周期的证明事实。

值式授权票据只在目标事务准入时消费。目标写集只发布对象及其成立所需的业务事实；授权若有独立后继业务作用，归其正式治理 owner，否则零授权持久事实。

| 无首次账调用旧目标未达成迁移 | `入口拒绝`，全载荷空，事实代次不变 |
| 已有账、原请求精确重复 | L1 精确重复，返回首次代次和原历史投影，零新应用 |
| 已有账、同键异义 | `幂等冲突`，零重放、零写 |
| legacy 节点 / 关系 / 值缺失 | 结构化拒绝，不降级为空证据 current 状态 |
| 未知治理材料格式 | 拒绝，不猜测、不升级 |

### 10.3 当前首次选择

| 场景 | 预期结果 |
| --- | --- |
| 初次来源 + 唯一初次准备稳定引用 + 同身份归因 | 按现行 v2 合同发布并正式读回 |
| 无账旧重筹办来源 | `入口拒绝`，零选择 / 路径 / 冻结 / 实例写入 |
| 初次来源携带目标裁决证据或任务治理状态稳定引用 | 结构化拒绝，零写 |
| 已有旧来源账 + 原完整请求 | 只精确重放 / 历史读回，不取得新生产资格 |
| 已有旧来源账 + 异义请求 | `幂等冲突` |
| 当前就绪 provider 收到旧重筹办来源 | 读取业务材料前拒绝，不调用目标裁决证据分支 |

### 10.4 恢复与生产扫描

- 恢复前后旧目标裁决证据、旧治理状态和旧选择逐字段一致；
- 首次新写扫描证明目标裁决证据节点、状态证据关系、11 项证据来源关系、证据材料值和角色 `40..44` 均为零；
- 生产调用扫描证明两个旧治理写入口无首次生产调用；
- 当前正式选择新写扫描证明旧重筹办来源、目标裁决证据类别和任务治理状态类别为零；
- 端到端覆盖执行后直接进入结算，目标未达成不形成旧状态、旧意图、下一工作包或自动队列推进。

### 10.5 声明边界

```text
规范 / 设计完成 != 代码完成
旧入口首次新写拒绝 != 历史事实删除
当前首次选择闭合 != 同轮重新筹办 ABI 闭合
编译通过 != 任务结算或自我治理闭环完成
旧编码可读 != 旧证明生产继续有效
工程读回成功 != 认知证据成立
```

## 11. 旧设计覆盖关系

本设计在目标裁决证明节点、旧任务治理状态、旧自动重筹办来源和稳定选择证明范围内覆盖：

```text
20260821_RUNTIME-GOVERNANCE-TASK-LIFECYCLE-TARGET-UNMET-RECHOOSE v0.1
20260821_RUNTIME-GOVERNANCE-TASK-TARGET-UNMET-REPLAN-PRODUCTION-TRIGGER v0.2
20260823_RUNTIME-GOVERNANCE-TASK-PLANNING-READY-EXECUTION-FREEZE v0.1..v0.3
方法学习候选晋级新代际与后继回合详细设计 v0.1
权威用途观察结构承载与事务发布恢复详细设计（已归档）
```

禁止从旧设计恢复用途观察账、目标裁决证据节点、task owner 私有 current 状态、执行后目标未达成自动重筹办、稳定证明节点或结果容量 / 分配语义。旧文件继续只作历史形成材料，其它不冲突语义须由现行规范和后继设计重新裁决。
