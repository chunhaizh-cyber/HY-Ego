## 1. 目标与完成边界

本设计只补齐 DATA-L1 当前缺失的“恰好三个内部结构分区共同发布一个事实代次”能力。它为后继 DATA-L2 统一特征当前值变化入口提供中性原子底座，但本设计不实现或宣称以下业务能力：

```text
特征当前值变化 provider
状态或动态业务结构组合
被动安全 / 服务维护
需求自检或目标比较
任何业务许可、动作成功、状态真实性或因果真实性
任意 N 参与者分布式事务
```

完成最多证明：新 v2 公开合同可由同一 L1 实例的三个合法内部写端口调用，结构化结果、共同事实代次、三份映射、当前 / 历史公开读回和适用持久恢复行为符合本设计。它不证明路线阶段二整体完成。

## 2. 当前事实与复用裁决

当前 `L1跨所有者原子事务合同版本=1` 物理固定为“状态、动态”两参与者：

```text
L1所有者范围CRUD.数据.h
  L1跨所有者原子事务参与者序号::{状态, 动态}
  L1跨所有者原子事务请求::{状态写集, 动态写集}

服务.L1事实基座.ixx
  接收者端口 + 另一参与者端口

仓库.L1事实基座.ixx
  状态候选 -> 动态候选 -> 共同 G1 -> 一次交换
```

阶段一的 `新增特征首值与初始状态_v1` 借用旧第二参与者槽承载特征 owner，是已发布兼容实现，不是三分区扩展点。阶段二需要特征实例、状态、动态三个互异结构分区，因而不能删除一个调用点、复义“动态”槽或把其中两个分区合并为第二权威。

现有可复用能力：

- owner-scoped 五类中性写项、稳定本地键和确定编码映射；
- 同仓独占锁、候选副本、普通 owner 写入算法；
- 当前节点引用闭包、全状态完整性和持久准备；
- owner 当前 / 历史正式读取和首次写入材料读取；
- 旧跨 owner v1 的共同代次归一化、精确重复和持久序列化框架。

不复用或不复制：

- v1 的状态 / 动态枚举及两个固定结果映射字段；
- L2 特征、状态、动态 DTO、类型枚举和业务含义；
- 上层凭证、装配或 consumer；
- 任意 N 参与者容器、回调参与者或第二事务仓库。

当前源码新于相关函数用途知识卡。执行 S0 必须重新读取当前声明、服务、仓库、持久编码和调用点；施工后只形成知识变更清单，不在本计划内直接修改共享知识库。

## 3. 公共 ABI

全部新值类型物理定义在 `海中鱼巣/核心/L1所有者范围CRUD.数据.h`，由既有 `海中鱼巣.核心.合同.L1所有者范围CRUD` 导出。不得新建第二数据头或在 L2 复制。

### 3.1 身份、引用和写项

```cpp
inline constexpr std::uint32_t L1三分区原子事务合同版本_v2 = 2;

struct L1三分区原子参与者身份_v2 final {
    std::uint8_t 值 = 0;
    friend bool operator==(const L1三分区原子参与者身份_v2&,
        const L1三分区原子参与者身份_v2&) = default;
};

struct L1三分区原子事实引用_v2 final {
    L1三分区原子参与者身份_v2 参与者;
    L1所有者范围写集本地键 本地键;
    friend bool operator==(const L1三分区原子事实引用_v2&,
        const L1三分区原子事实引用_v2&) = default;
};

using L1三分区原子事实引用值_v2 = std::variant<
    稳定编码,
    L1所有者范围写集本地键,
    L1三分区原子事实引用_v2>;
```

节点、关系、值、属性槽变更四类新建 / 变更项逐字段复用现有跨 owner v1 同义字段，只把引用类型替换为 v2 引用。`L1三分区原子写集请求_v2` 字段顺序固定为：

```text

节点
关系
值
属性槽变更
退出事实
```

### 3.2 参与者、请求和结果

```cpp

    已提交 = 1,

    入口拒绝 = 3,
    事实代次漂移 = 4,

struct L1三分区原子事务结果_v2 final {
    L1三分区原子事务状态_v2 状态 =

    L1所有者范围写入幂等身份 组合写入幂等身份;
    std::uint64_t 共同事实代次 = 0;

```

所有新 DTO 提供逐字段值式相等；不得用 `variant::index()`、类型名、结构布局、地址或摘要派生持久标签。v2 引用规范标签固定为：稳定编码 `1`、本参与者本地键 `2`、跨参与者引用 `3`。

### 3.3 公开函数

```cpp
L1三分区原子事务结果_v2

    const L1三分区原子事务请求_v2& 请求,
```

接收者、第二参数、第三参数分别绑定参与者 `1、2、3`。该函数只存在于 move-only 内部写端口，不加入普通读取服务，不公开签发器、owner 选择或通用端口组。

仓库私有函数签名固定为：

```cpp
L1三分区原子事务结果_v2 提交三分区原子事务_v2(
    const L1三分区原子事务请求_v2& 请求) noexcept;
```

## 4. 请求有效性与规范化

入口依次验证：

1. 专属合同版本为 2，共同 G0 和组合幂等身份非零。
2. 参与者组数量恰为 3；按参与者身份规范化后身份恰为 `1、2、3`。
3. 三个 owner 有效且互异；端口同实例、有效、与三个 owner 逐项绑定。
4. 三份写集使用现行 owner-scoped CRUD 合同、共同 G0、有效且互异的内部写入幂等身份。
5. 每份写集五类写项合计至少一项；节点、关系和值的本地键在本参与者全类型命名空间内唯一。
6. 跨参与者引用只允许 `2 -> 1` 和 `3 -> 1/2`；引用目标本地键必须存在且类型可用于目标字段。
7. 属性槽变更的新当前值必须是本参与者值新建项本地键；跨参与者值不能成为该 owner 的新槽值。

规范化先复制请求，再将参与者按身份升序、节点 / 关系 / 值按本地键升序、退出事实按稳定编码升序、属性槽按规范引用元组排序。精确重复比较规范化完整请求，不比较调用方原容器排列。任何重复、异义、排序键复义或无法解析引用都在候选前返回入口拒绝或引用冲突。

## 5. 事务算法

```text
纯值入口校验
-> 三端口同实例和 owner 绑定校验
-> 规范化完整请求
-> 取得仓库唯一写锁
-> 仓库完整性 / 隔离守卫
-> 查 v2 组合幂等账
   -> 同义：直接返回首次 G1 / 三映射
   -> 异义：幂等冲突
-> 比较共同 G0
-> 复制候选仓库
-> 参与者 1 应用，取得映射 1
-> 解析 2 对 1 的引用并应用，取得映射 2
-> 解析 3 对 1/2 的引用并应用，取得映射 3
-> 把候选临时 G1/G2/G3 及三份首次写入账归一到 G0+1
-> 重建 / 核对全部当前反向索引
-> 全局引用与 owner 分区闭包
-> 形成首次结果并写 v2 组合幂等账
-> 准备持久权威快照
-> 一次交换候选状态
-> 返回已提交
```

三个普通写算法只在私有候选副本中复用。其局部 `成功 / 精确重复` 不能直接成为外部成功；外部成功必须由三份映射、共同 G1、最终全局闭包、v2 组合账和持久准备共同成立。

## 6. 幂等、代次和结果矩阵

| 分支 | 共同代次 | 参与者结果 | 发布确认 | 重试边界 |
| --- | ---: | --- | ---: | --- |
| 已提交 | 首次 G1 | 三份完整有序映射 | 是 | 不适用 |
| 精确重复 | 首次 G1 | 首次三份完整有序映射 | 否 | 原幂等身份读回收敛 |
| 入口拒绝 | 0 | 空 | 否 | 修正请求后可重试 |
| 事实代次漂移 | 锁内当前代次 | 空 | 否 | 修正请求后可重试 |
| 幂等冲突 | 锁内当前代次 | 空 | 否 | 不可用原异义请求重试 |
| 引用冲突 | 锁内当前代次 | 空 | 否 | 修正请求后可重试 |
| 资源失败 | 安全取得则回显，否则 0 | 空 | 否 | 原请求可重试 |
| 内部不一致 | 安全取得则回显，否则 0 | 空 | 否 | 停止依赖路径 |
| 已可能发布 | 已知则回显候选 G1，否则 0 | 空 | 否 | 仅原幂等身份读回收敛 |

`已可能发布` 只覆盖正式状态交换或交换后结果形成是否完成不可判定的边界；交换前持久准备失败仍是资源失败或内部不一致并保证零发布。实现不得为了制造测试分支增加生产故障注入入口。

## 7. 持久格式与恢复

仓库状态新增独立 `三分区原子事务幂等账_v2`，记录规范化请求和首次结果。旧 `跨所有者原子事务幂等账` 不改名、不改类型、不迁移。

内部权威快照载荷从格式版本 1 升为 2：

```text
既有 v1 全部字段原顺序
-> 旧双参与者组合账
-> 新三分区 v2 组合账
-> 旧共享 owner 定位
```

解码版本 1 时，按旧原顺序完成并把新 v2 账初始化为空；解码版本 2 时再读取新账。两种版本都必须执行状态完整性和索引重建。编码只产生版本 2。清单外层版本、公开持久恢复合同 v1 和现有持久运行包 ABI 不因内部载荷升级而改变。

v2 账序列化按组合幂等身份升序；参与者、写项、引用、结果和映射使用固定数值标签与规范顺序。未知版本、尾随字节、重复键、非规范参与者、坏映射、请求结果不能互证或跨版本同账碰撞均拒绝恢复并进入现行结构化恢复失败边界。

## 9. 验证矩阵

创建侧只要求设计文档检查。代码执行侧必须至少完成：

1. Debug / Release `海中鱼巣.vcxproj` 编译和链接。
2. ABI consumer：只 import 公共合同，静态构造全部 v2 DTO 并调用三端口正式入口。
3. 三 owner 首次提交：三份写项和跨分区后向引用成功，共同只推进一个 G1；正式当前读取逐项一致。
4. 精确重复：原 G0 在后继代次重放返回首次 G1 和相同三映射，零新应用。
5. 同键异义、参与者缺 / 多 / 重、owner 重复、内部键重复、前向引用、缺失引用、G0 漂移：结构化非成功，前后正式读回零变化。
6. 三分区闭包：关系端点、值来源、属性槽和退出引用任一悬空时整笔零写。
7. 持久 round-trip：v2 提交后退出进程，以同一隔离根恢复，三 owner 事实、共同 G1、三份首次写入账和 v2 精确重复一致。
8. 旧格式兼容：若能够从精确发布基线取得版本 1 隔离快照，使用新代码恢复并继续一次 v2 提交；若没有合法旧产物则明确 `NOT_RUN`，不得伪造通过。
9. 旧 v1 回归：至少一个既有双参与者生产外结构场景保持原 ABI、原状态值和原映射形状。

临时检查只消费公开工厂、签发器、三端口入口和正式读取，不得 friend 私有仓库、解析日志、检查内存地址或新增故障注入。运行结果只证明实际发生分支，不把 provider 自测升级为 L2 当前值变化闭环。

## 10. 直接后继
