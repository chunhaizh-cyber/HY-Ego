## 1. 正式依据与当前事实

直接依据为8121 v0.6、8120 v0.16、6130 v0.17、4115 v0.9、7130 v0.19、8100 v1.12、8200 v1.9及 CODE-FILE-01 v4.0。

当前代码已经具备本叶所需的两个真实上游：

- `特征概念应用服务::形成或读取本能根I64实际F(const 本能根I64实际F请求&) noexcept`：消费系统初始化已经形成并正式读回的安全值/服务值先天 FT 与完整域概念；形成或恢复 IF/R、准确 F、FCv 和当前采用，并返回实际 F。
- `需求类数据服务::建立或读取本能根材料(const 本能根材料请求&)`：形成或恢复根目标合同 T、独立根需求 D、根列表项 L、`D→F`、`D→T`、`L→D`及 `I64_MAX` 目标值，并读回独立根闭包。
- `需求类数据服务::核验当前事实代次(std::uint64_t) const noexcept`：提供阶段21每一步之间和最终 `Gfinal` 的当前性守卫。
- `方法登记根生产初始化结果::最终Gread`：阶段19成功后提供阶段21首次尝试所需的非零正式截止；阶段21不自行猜测或读取“当前代次”。
- `真实自我形成服务::读取当前自我(const 真实自我读取请求&) const noexcept`：调用方以本次正式截止重读完整真实自我；只有`真实自我形成结果::成功(读取请求)`成立的结果才能用于构造本 provider。
- `线程_自我.h` 已冻结 `自我线程本能根启动材料_v1` 的消费字段：自我、安全根/服务根各自的需求、列表项、实际特征、目标合同和共同 `Gread`。

当前普通应用已持有上述真实服务，但尚无阶段21 provider、阶段21入口或锚点缓存；`启动.应用程序.cpp`在方法登记根成功后仍固定返回失败阶段21。这两个消费缺口不进入本叶。

现行提交`c84334b`保留了本设计直接复用的公开 provider 和 DTO 合同；`.ixx→.h/.cpp`没有改变这些业务语义。RC-P1任务已经暂停并释放 Git index，但其未提交普通应用、根工程及领域 WIP仍由原切片所有；本设计因此把最早可独立施工叶限定为四个全新生产文件和专属隔离专项，不触碰任何重叠文件、语义或验证资源。

## 2. 业务闭环与完成边界

本 provider 是“一次阶段21尝试对象”。它接受一份由调用方在本次尝试前以最新正式截止经现行自我形成服务完整读回并验证的`真实自我投影`，以及只含合同版本和唯一自我的公开初始化请求。它不重新查询“哪个是自我”，不在对象内刷新截止，也不从编码、名称或创建顺序猜测根。

首次尝试的正式截止只取阶段19成功结果的`最终Gread`。调用方据此构造`真实自我读取请求`并调用`真实自我形成服务::读取当前自我`；只有`真实自我形成结果::成功(读取请求)`成立后才能构造本 provider。阶段21若成功，后续精确重复可用已返回锚点的`事实截止代次`重新正式读回自我；若阶段21非成功、`已可能发布`或进程重启，则调用方先按阶段19原合同重新形成/读回方法登记根，取得新的非零`最终Gread`，再重读自我并重建 provider。自我读回若因并发变化失败，返回当前性失败并从阶段19正式读回重新开始；不得把失败回执中的实际代次当成成功起点。

闭环如下：

```text
验证请求、自我投影和服务同上下文
→ 从自我投影确定定位：场景 = E，组织父 = 自我场景四根中唯一特征根
→ 形成/读取安全根实际F
→ 形成/读取安全根材料
→ 形成/读取服务根实际F
→ 形成/读取服务根材料
→ 冻结非零Gfinal
→ 在同一Gfinal按原键重新读回安全F、服务F、安全根材料、服务根材料
→ 核验双根互异、根闭包完整、实际F一致且无交叉
→ 返回不可变值式本能根运行锚点
```

只要本调用首次形成过任一上游材料，最终成功状态为`已形成`；本调用零新发布且最终完整读回成功为`已恢复`。非成功不得携带锚点。该结果只证明阶段21 provider 在隔离真实服务栈中形成/恢复并同截止读回双根锚点，不证明普通应用接线、启动短路映射、自我线程创建、治理开门、跨进程故障恢复或自我内部治理闭环。

构造函数只保存服务引用、经公开成功谓词取得的本次新鲜自我投影值和一个初始为假的“已经调用”进程内标志。配置不成立时抛 `std::invalid_argument`，不写事实：

1. `特征概念.使用存在服务(存在)`为真；
2. `需求.与存在服务同底座(存在)`为真；
3. 必须直接调用`自我读取结果.成功(自我读取请求)`，并要求`自我读取结果.投影`存在；阶段21不得复制、缩减或重新解释`应用服务.自我形成.cpp`内部的投影完整算法；
4. 从该成功投影的`场景.场景角色.四根`按枚举值寻找`场景根角色::特征`，必须唯一命中且根身份有效。其它角色、绑定和生命周期完整性已经由第3项公开成功谓词证明，不在本叶建立第二套判断。

公开`初始化`请求仍只有版本和唯一自我。请求自我必须等于构造时锁定的投影 E；阶段21不得由请求注入位置、FT、完整域概念、键、预算、根角色或截止。每个 provider 对象只允许调用一次`初始化`：入口在任何请求处理和上游调用前检查并把“已经调用”置真；同一对象的第二次及后续调用返回`入口拒绝`且零事实写入。该标志不持久化、不参与幂等、不携带当前截止；任何重试都必须以本次新鲜自我读回重建对象。

### 4.3 内部组合端口

`应用服务.本能根运行初始化.内部.h`在`海中鱼巣::本能根运行初始化内部`中声明一个非持久、无业务身份的抽象调用端口，精确入口只有：调用实际F provider、调用根材料 provider、核验当前事实代次。它还声明一个接收该端口、已由公开成功谓词验证的`真实自我投影`和公开初始化请求的`执行组合`函数。真实适配类只在`.cpp`中定义并原样转发给现行两个 provider和事实代次守卫；公开`初始化`只构造该适配并调用同一个`执行组合`。

精确声明固定为：


该内部端口不是新的数据服务、owner、业务 ABI、运行配置或测试开关，不保存事实，也不允许普通应用、启动、线程或其它生产模块直接消费。专项以脚本端口调用同一个`执行组合`内核，只用于确定性返回现行公开结果类型并选择第N次守卫失败；生产对象中不存在回调、故障注入字段或运行期开关。

## 5. 固定定位、键与预算

固定定位由锁定自我投影导出：

```cpp
存在信息身份 E{投影.E};
定位特征位置 位置{投影.E, 唯一特征根.根.编码};
```

这里自我 E 本身是同节点场景；`场景=E`不表示把特征嵌入自我字段。F仍由既有特征/存在/场景/概念 owner 按公开 provider 形成，根 D 仍是需求 owner 的独立根。

两根固定键只在 `.cpp` 的匿名命名空间定义，不上升为公开字段或节点编码：

| 用途 | 安全根 | 服务根 |
| --- | --- | --- |
| IFR | `0x4952415341460001ULL` | `0x4952415352560001ULL` |
| FCv概念 | `0x4952415341460002ULL` | `0x4952415352560002ULL` |
| 当前采用 | `0x4952415341460003ULL` | `0x4952415352560003ULL` |
| F出生：组合 | `0x4952415341460011ULL` | `0x4952415352560011ULL` |
| F出生：内容 | `0x4952415341460012ULL` | `0x4952415352560012ULL` |
| F出生：已知 | `0x4952415341460013ULL` | `0x4952415352560013ULL` |
| F出生：组织 | `0x4952415341460014ULL` | `0x4952415352560014ULL` |
| F出生：概念使用 | `0x4952415341460015ULL` | `0x4952415352560015ULL` |

根 T/D/L 的固定键继续由`需求类数据服务::建立或读取本能根材料`内部唯一管理；阶段21不复制也不传入这些键。

固定读取预算如下，均为有界工程参数，不是持久业务字段：

```cpp
实例特征IFR读取预算       {8, 8, 32, 8, 64};
特征R规则读取预算          {16, 64, 16, 8, 8, 64, 64};
原子I64特征候选读取预算    {8};
原子I64特征组织读取预算    {8};
原子I64特征概念读取预算    {16, 64, 16};
概念树预算                 {64, 256, 64, 64, 64, 64, 64, 64};
当前采用关系预算           = 16;
```

预算不足归`材料未闭合`，不得自动放大、扫描全库或转为成功。

## 6. 精确算法

### 6.1 进入和逐步形成

1. 在任何请求处理和上游调用前检查“已经调用”；若为真返回`入口拒绝`，否则置真并消费本对象唯一一次调用资格。随后值式检查合同版本、自我身份、投影和唯一特征根；失败返回`入口拒绝`。
2. 以本次新鲜投影 `Gread` 调`需求.核验当前事实代次`。非成功按第7节归一；只有完全相等继续。该守卫不负责刷新截止；失败后只能由调用方重新取得正式截止、重读自我并重建 provider。
3. 以当前 G、固定安全键/预算、角色`安全值`和固定位置调用`形成或读取本能根I64实际F`。成功必须携带实际F且其所有成功读回截止一致；记录本调用是否出现`已形成`，并把其最终读回截止作为新 G。
4. 守卫新 G；以安全实际F调用`建立或读取本能根材料({1,G,安全,F})`。成功必须携带完整材料、角色/实际F匹配；记录是否`已形成`，以结果事实代次更新 G。
5. 守卫新 G；按同样规则形成/读取服务实际F及服务根材料。两套固定键、FT、完整域概念、实际F必须互异；任一交叉为`引用冲突`。
6. 守卫服务根材料返回的 G，并将其冻结为 `Gfinal`。`Gfinal`必须非零。

任何上游成功回执若携带的`Gread/事实代次`不是该次调用完成后的当前事实代次，或成功载荷缺失，返回`内部不一致`；不使用局部成功材料组装锚点。

`本能根I64实际F结果`没有顶层 `Gread`。实现必须使用唯一帮助函数`提取根F成功截止`机械提取调用后当前G，不得由执行者另选字段：只有在`结果.成功()`为真且`初始化交付、IFR读回、当前采用、准确F、原子读回、单值概念读回、实际F`全部存在时，取`当前采用->Gread`为候选G；随后要求候选G非零，并与`IFR读回->Gread`、`准确F->Gread`、`原子读回->Gread`、`单值概念读回->Gread`逐项相等。同时要求`当前采用->采用`存在，且`实际F == 当前采用->采用->F == 准确F->信息.身份`，`原子读回->事实->F == 实际F.编码`。`初始化交付->Gread`是实际F provider进入时对双FT/完整域概念的读取截止；首次形成可能在它之后继续发布IF/R/F/当前采用，所以只要求其非零且不大于候选G，绝不能要求它等于调用后当前G。全部成立才返回候选G；任一不成立均返回空并由调用者归`内部不一致`。提取后立即用`需求.核验当前事实代次(候选G)`守卫；不得用`初始化交付.Gread`、出生H、首次H或任一历史H替代当前G。

### 6.2 同 `Gfinal` 正式重读

冻结后执行以下固定顺序，四次调用之间及最后一次之后都调用`需求.核验当前事实代次(Gfinal)`：

1. 原完整请求、原安全键，以 `G0=Gfinal` 再调安全实际F provider；必须返回`已读取`，实际F与首次阶段一致，所有携带读回截止均为`Gfinal`。
2. 原完整请求、原服务键，以 `G0=Gfinal` 再调服务实际F provider；要求同上。
3. `{1,Gfinal,安全,安全F}`再调根材料 provider；只接受`已恢复`或`已读取`，材料角色、F和`读取事实代次`等于`Gfinal`。
4. `{1,Gfinal,服务,服务F}`再调根材料 provider；要求同上。

最终互证：

- 安全F与服务F不同；两根 D、L、T、F全部互异；
- 每根材料自身`完整()`，目标为`I64_MAX`，`D→F`、`D→T`、`L→D`闭包已由需求 provider正式读回；
- 根材料没有自我字段、所属存在、目标宿主或自我 owner；阶段21不另建自我关系；
- 重读没有新发布。若任一重读返回`已形成`，即使载荷看似完整也按`内部不一致`失败；
- 最后守卫仍精确等于`Gfinal`。

只有全部成立才组装锚点。`自我线程本能根启动材料_v1`的后继映射固定为：

| 锚点字段 | self消费字段 |
| --- | --- |
| `自我.编码` | `自我线程存在身份{值}` |
| `安全根.{需求,列表项,实际特征.编码,目标合同}` | `安全根`四个身份值 |
| `服务根.{需求,列表项,实际特征.编码,目标合同}` | `服务根`四个身份值 |
| `事实截止代次` | `Gread` |

本叶只冻结并验证此纯值映射，不修改线程文件，也不创建线程。

## 7. 状态归一与失败收口

### 7.1 根材料状态

| 上游状态 | 阶段21状态 |
| --- | --- |
| `入口拒绝` | `入口拒绝` |
| `事实代次漂移` | `当前性漂移` |
| `幂等冲突` | `幂等冲突` |
| `引用冲突`、实际F未找到/已退出/类型不匹配 | `引用冲突` |
| `根材料未闭合` | `材料未闭合` |
| `根材料已退出` | `根材料已退出` |
| `已可能发布` | `已可能发布` |
| `资源失败` | `资源失败` |
| 其它非成功或成功谓词不成立 | `内部不一致` |

### 7.2 实际F状态

`入口拒绝→入口拒绝`，`初始化交付不完整→材料未闭合`，`事实代次漂移→当前性漂移`，`引用冲突→引用冲突`，`资源失败→资源失败`，`内部不一致→内部不一致`。

现行实际F provider在非成功收口时会清空`IFR读回、准确F、原子读回、单值概念读回、实际F`，但保留已经写入结果的`IFR`和`当前采用`；它在两条`当前采用读取失败`路径中不保存局部读取回执。阶段21只能消费真实保留载荷，禁止假设被清空或从未回显的来源仍可读取。包装状态先按下表机械处理：

| 实际F包装状态 | 唯一处理 |
| --- | --- |
| `当前采用读取失败` | 固定归`内部不一致`；现行回执没有保留该读取来源，禁止猜测为资源、漂移或缺项 |
| `IFR失败` | 仅当`IFR`存在时递归读取该观察结果；否则归`内部不一致` |
| `F出生失败` | 仅当`IFR`及其`F出生`都存在时递归读取出生结果；否则归`内部不一致` |
| `当前采用写入失败` | 仅当`当前采用`存在时递归读取其`存在类数据状态`；否则归`内部不一致` |

对允许递归的真实载荷，若同一失败链携带多个非成功回执，归一优先级固定为：`已可能发布`、`幂等冲突`、`当前性漂移`、`资源失败`、`引用冲突`、`材料未闭合`、`入口拒绝`、`内部不一致`。精确映射如下，未列出的成功枚举不参与失败归一：

| 来源枚举 | 精确映射 |
| --- | --- |
| `存在类数据状态` | `入口拒绝→入口拒绝`；`事实代次漂移→当前性漂移`；`幂等冲突→幂等冲突`；`引用冲突/目标已退出/结构类型已退出→引用冲突`；`未找到/结构类型未找到/历史材料已清理/格式不支持/数量预算不足→材料未闭合`；`已可能发布→已可能发布`；`资源失败→资源失败`；其它非成功→内部不一致 |
| `实例特征IFR状态` | `入口拒绝→入口拒绝`；`未找到/数量预算不足→材料未闭合`；`已退出/引用冲突→引用冲突`；`事实代次漂移→当前性漂移`；`幂等冲突→幂等冲突`；`已可能发布→已可能发布`；`资源失败→资源失败`；`内部不一致→内部不一致` |
| `I64单值出生概念确保状态` | `入口拒绝→入口拒绝`；`规则缺失/历史材料不可用→材料未闭合`；`类型不相容→引用冲突`；`事实代次漂移→当前性漂移`；`幂等冲突→幂等冲突`；`已可能发布→已可能发布`；`资源失败→资源失败`；`内部不一致→内部不一致` |
| `原子I64特征候选查询状态`、`原子I64特征窄读取状态` | `入口拒绝→入口拒绝`；`目标已退出/位置冲突→引用冲突`；`未找到/预算不足/历史材料不可用→材料未闭合`；`事实代次漂移→当前性漂移`；`资源失败→资源失败`；`内部不一致→内部不一致` |
| `原子I64特征出生状态` | `入口拒绝→入口拒绝`；`目标已退出/位置冲突/概念不适配→引用冲突`；`未找到/存量未定位/预算不足/历史材料不可用→材料未闭合`；`事实代次漂移→当前性漂移`；`幂等冲突→幂等冲突`；`已可能发布→已可能发布`；`资源失败→资源失败`；`内部不一致→内部不一致` |

## 8. 复用与禁止

`.ixx→.h/.cpp`只为规避C1001；业务逻辑基本未变的部分必须优先复用现行 `.h/.cpp` provider及仍符合现行规范的旧编排，不把文件形态迁移当成业务重写理由。不得复制 IF/R、FCv、F出生、当前采用或根 T/D/L 写集。允许借鉴旧实现的只有仍符合现行8121的组合顺序、纯值帮助函数风格和异常封闭方式；已废止 ABI、旧世界树/需求服务耦合、旧消息账、旧宿主线程和与现行独立根 D / IF-R / 当前采用语义冲突的初始化逻辑一律不恢复。

禁止：

- 修改现有特征概念、存在、需求、自我形成、线程、L1或场景实现；
- 直接读写 L1、签发 owner端口、硬编码节点编码或按创建顺序猜根；
- 为根 D 写入自我、所属存在、目标宿主、owner或新增角色节点/关系；
- 创建任务、方法、子需求、状态、动态、因果、服务账或线程；
- 恢复旧 `.ixx`、旧 L2 ABI、旧启动 DTO或旧本能根计划；
- 修改普通应用、启动、根工程、filters、计划索引或目标账。

## 9. 隔离验证合同

专属验证使用新的生产外工程和源码，不登记根工程，不调用普通应用或启动入口。它分成两个边界：真实服务栈在临时受控持久根上装配现行 L1、owner、场景/存在/特征/概念/需求服务；每次尝试都以该次正式截止构造`真实自我读取请求`，只用满足`真实自我形成结果::成功(读取请求)`的新鲜结果构造新的公开 provider。确定性失败分支只用本叶内部脚本端口驱动同一个`执行组合`内核。脚本端口不得复制组合算法，也不得被生产入口持有；`执行组合`可以多次调用，但每次必须传入与该次起始截止一致的新鲜投影，不得用同一旧投影模拟重复或恢复。

必须覆盖：

1. 首次调用：双根形成，返回`已形成`，锚点完整且 self 映射完整；
2. 同进程精确重复：以首次锚点截止重新正式读回自我并新建 provider；零新事实，返回`已恢复`，锚点相同；同一 provider 第二次调用固定`入口拒绝`且零写入；
3. 完整重启恢复：同一持久根重建服务，先按阶段19原合同取得新`最终Gread`，再完整读回自我并新建 provider；原键恢复，零新事实；
4. 部分前缀：分别在安全F、安全根、服务F后中断；每次恢复都先按阶段19原合同取得新截止、完整重读自我、重建 provider，再以原请求收敛；
5. 请求拒绝：坏版本、零self、与锁定self不等；
6. 固定键异义：预占任一键为不同规范化请求，返回`幂等冲突`；
7. 引用/退出：实际F交叉、根材料退出或错误绑定分别落`引用冲突/根材料已退出`；
8. 发布未知：脚本端口在实际F保留载荷或根材料回执返回现行`已可能发布`，同一内核必须返回空锚点；脚本随后以新正式截止对应的新鲜投影和原请求返回完整成功序列并收敛；不得复用旧投影或公开 provider。该用例只证明组合内核映射/重试，不冒充真实L1故障注入；
9. 最终截止漂移：脚本端口分别让安全F、服务F、安全根、服务根重读前后对应的第N次`核验当前事实代次(Gfinal)`返回正式漂移回执，逐点要求`当前性漂移`且无部分锚点；真实适配静态证明每次守卫原样调用需求 provider；
10. 自我读取拒绝：伪造投影即使局部字段看似成立，只要`真实自我读取结果::成功(请求)`为假，公开构造就必须拒绝；
11. 静态负面：provider源码不调用L1、不出现`.ixx`、不修改现有provider、不创建线程，根D无自我物理绑定；内部端口头只允许provider `.cpp`和本专项包含，生产公开头不得暴露它。

Debug/Release x64均须隔离 Rebuild 和运行专项，全部断言通过；`git diff --check`通过。若隔离工程无法在不修改根工程/普通应用或异主 WIP的情况下完成，执行侧只能退回本计划，不得扩大范围。
