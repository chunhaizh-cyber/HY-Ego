# L1-SIMPLIFY-P8-EXISTENCE-FEATURE 存在宿主 I64 实例特征详细设计 v0.1

日期：2026-08-04

状态：设计就绪；代码未实现；计划必须待激活

## 1. 目标与边界

本设计只完成 SELF-GOV-CLOSURE v0.2 STEP-3B：在 P7 已发布的实际存在事实之上，复用现有 `海中鱼巣.领域.服务.L1实例特征`，为一个已验证实际存在建立它自己的 I64 实例槽、宿主关系、定义关系、初始当前值和当前属性槽，并从权威 L1 同代次独立读回。

本叶必须形成真实成功、幂等和冲突行为。它不创建关系19状态、状态迁移动能、动作动态、因果、自我资格、治理虚拟存在或结算；不实现存在宿主当前值换代、运行期装配、持久恢复、旧消费者迁移或集成验收。

## 2. 正式依据与当前事实裁决

- 1130 允许特征实例宿主为存在或场景，并要求同一宿主与同一特征定义只有一个当前实例槽。
- 4110 冻结角色1为宿主到实例槽、角色2为实例槽到定义模板、角色3为实例槽的当前值；不得为存在复制平行实例体系。
- 1140 与 4200 要求实际存在资格和初始场景归属由存在领域提供；存在初始特征复用特征领域服务并以一个 L1 写集发布。
- P2 提供 I64 特征定义登记与独立读回；P3 已提供初始场景专用实例入口以及 `1节点 + 2关系 + 1值 + 1属性槽` 写集；P4 只提供现行场景请求形状的当前值换代。
- 当前 `初始场景I64实例特征建立请求`、`I64实例特征读取请求` 和 P4 换代请求均绑定 `初始场景读取请求`。现有场景入口语义不得静默改成存在入口。
- 当前服务只缓存一份场景建立/读取请求，不能作为多个实际存在的并发与幂等账。
- P7 v0.1 冻结 `L1实际存在场景组合服务::读取实际存在` 及 `实际存在读取请求/事实/结果`，但尚未成为正式代码能力；本设计只把它作为待实现提供者合同。
- P6 特征比较与本叶没有机器语义依赖。共享 Git 或工程文件所有权只构成施工门禁，不得写成业务前置。
- 旧节点直接合同、句柄、仓库、WORLD-TREE 计划和旧草稿只作负面差异证据，不复用、不迁移、不修改。

## 3. 所有权与依赖方向

唯一领域所有者仍是 `L1实例特征服务`。最终物理位置：

```text
DTO/常量/校验：海中鱼巣/领域/L1实例特征.数据.h
生产实现：      海中鱼巣/领域/服务.L1实例特征.ixx
专项验证：      海中鱼巣/领域/自检.L1实例特征.ixx
```

模块依赖固定为：

```text
L1实例特征服务
  -> L1事实基座服务
  -> L1场景结构服务（保留现行场景入口）
  -> L1特征定义服务
  -> L1实际存在场景组合服务（只供新增存在入口核验宿主资格）
```

不得建立第二个实例特征服务、第二套登记、第二套关系类型或存在领域对特征事实的写入口。P7 服务只证明宿主资格和当前场景归属，不解释或写入特征实例。

## 4. 最终 DTO 与公开函数

在 `L1实例特征.数据.h` 追加：

```cpp
struct 实际存在I64实例特征建立请求 final {

    std::uint32_t 规则版本 = L1实例特征规则版本;
    特征操作幂等身份 幂等身份;

struct 实际存在I64实例特征读取请求 final {
    std::uint32_t 合同版本 = L1实例特征合同版本;

    稳定编码 宿主关系;
    稳定编码 定义关系;
    稳定编码 当前值;
    稳定编码 来源节点;
    friend bool operator==(const 实际存在I64实例特征读取请求&,

```

追加完整性函数：

```cpp
bool 实际存在I64实例特征建立请求有效(
    const 实际存在I64实例特征建立请求& 请求) noexcept;
bool 实际存在I64实例特征读取请求有效(
    const 实际存在I64实例特征读取请求& 请求) noexcept;
```

服务保留现行三参构造与三个场景专用公开函数，新增四参构造和两个入口：

```cpp
L1实例特征服务(
    L1事实基座服务& L1,
    L1场景结构服务& 场景结构,
    L1特征定义服务& 特征定义,
    L1实际存在场景组合服务& 实际存在) noexcept;

I64实例特征结果 建立实际存在I64实例特征(
    const 实际存在I64实例特征建立请求& 请求);

I64实例特征结果 读取实际存在I64实例特征(
    const 实际存在I64实例特征读取请求& 请求) const;
```

三参构造把非拥有 `L1实际存在场景组合服务*` 保存为 `nullptr`，继续完整支持现行场景入口；四参构造保存调用方长寿命服务地址。未绑定 P7 provider 时，两个新增入口返回 `入口拒绝` 与空载荷。不得通过 setter 在并发运行中更换 provider。

两个入口继续返回现有 `I64实例特征结果`：成功事实的 `宿主` 是实际存在稳定编码，`特征定义/实例槽/当前值/I64值/来源节点` 均完整，结果的 `宿主关系/定义关系` 非零。非成功状态的 `事实` 为空且两个关系编码为零。

## 5. 宿主与定义资格

建立入口在服务互斥量内按以下固定顺序取得材料：

1. 校验自身版本、规则、幂等身份、非零期望代次、来源编码和两份嵌套请求形状；
2. 通过 P7 `读取实际存在(请求.宿主)` 取得 `实际存在事实`；只接受 `已读取` 且载荷完整；
3. 通过 P2 `读取I64特征定义(请求.定义)` 取得定义事实；
4. 两份事实截止代次必须等于请求期望代次；
5. 读取一次 L1 完整快照，快照代次也必须等于请求期望代次；
6. 来源节点必须在该快照内为当前普通节点。

P7 状态映射固定为：`未找到 -> 未找到`，`版本漂移 -> 事实代次漂移`，`资源失败 -> 资源失败`，`入口拒绝/幂等冲突/许可拒绝 -> 入口拒绝`，`内部不一致` 或坏成功载荷 `-> 内部不一致`。P2 继续采用现有定义状态映射。

实际存在的初始场景归属关系只用于证明存在资格；它不是实例槽宿主关系，不得复用为本叶角色1关系。

## 6. 唯一性与单写集

建立前必须在同一完整快照中联结现有当前关系和节点，按登记中的关系类型验证：

- 指定实际存在作为源、`宿主槽关系类型`、目标为实例槽；
- 该实例槽作为源、`定义模板关系类型`、目标为指定特征定义；
- 指定 `宿主 + 定义` 已有完整唯一实例时，只允许相同幂等请求走 L1 精确重复和独立读回；不得发布第二槽；
- 同一宿主的其它定义、同一定义的其它宿主均合法；
- 一个槽多宿主、多定义、多当前值，或同一宿主与定义有多个当前槽，返回 `内部不一致`；
- 已有同一宿主与定义但请求见证不能形成精确幂等重复，返回 `幂等冲突`。

首次建立的唯一 L1 写集沿用现有实例幂等域 `0x06`，不新建存在专用域：

| 本地键/项 | 事实 |
| --- | --- |
| 节点1 | 普通节点：新的实际存在实例槽 |
| 关系2 | 源=实际存在；目标=节点1；类型=登记.宿主槽关系类型；顺序=0 |
| 关系3 | 源=节点1；目标=P2特征定义；类型=登记.定义模板关系类型；顺序=0 |
| 值4 | 所属=节点1；属性类型=登记.当前I64值属性类型；材料=请求.初始值；来源=请求.来源节点 |
| 属性槽变更 | 节点1 的当前I64值属性槽指向值4 |

期望代次只取请求值，幂等键为 `0x06 << 56 | 请求.幂等身份.值`。同键同义返回同一事实，同键异义返回 `幂等冲突`。成功或精确重复都要求编码见证完整、非零且互异：L1 返回本地键1—4的精确映射时直接校验并使用；精确重复没有映射时只允许从本进程按幂等身份保存的已发布读取见证取得编码，再走公开读回。两者都没有时返回 `内部不一致`，不得扫描或猜测编码。

发布前任一失败由 L1 保证零普通可读事实变化。服务不接触 L1 候选、事务、撤销或补偿；发布后读回失败不得补写、删除或回滚。

## 7. 共享私有核心与幂等缓存

现行场景入口语义保持不变，但场景入口与新增存在入口必须复用一个私有写集构造/提交核心和一个私有事实读回核心。共享核心只接收已经由领域 provider 验证的值式材料：宿主稳定编码、定义稳定编码、截止代次、初始值、来源以及各见证编码；它不知道宿主是场景还是存在。

新增存在入口不得复用现有单值 `首次实例请求_` 与 `实例读取请求_`。服务增加以 `特征操作幂等身份.值` 为键的有序值式账，值至少包含完整建立请求、完整读取请求、写入代次和最终结果：

- 同键同义返回相同已发布事实并重新走独立读回；
- 同键异义返回 `幂等冲突`；
- 不同键可并发请求不同存在或不同定义，互斥量只串行服务内检查和提交；
- L1 幂等账是跨调用的权威，本进程账只保存精确重复所需见证，不扫描 L1 推测服务曾经建立的实例；
- 资源分配失败返回 `资源失败`，不得留下半项缓存。

场景入口现有可观察状态、请求相等规则和现有单值幂等行为保持不变。共享核心的抽取不得改变其 DTO、公开签名、写集形状、幂等域或返回映射。

## 8. 独立读取与同代次校准

`读取实际存在I64实例特征` 不读取服务缓存来证明事实，固定执行：

1. P7 读取实际存在，P2 读取 I64 定义；
2. 从 L1 公开当前节点/关系/值/当前属性槽入口读取实例槽、两关系、当前值；
3. 所有结果必须具有同一非零事实代次，并与 P7/P2 截止代次一致；
4. 核验实例槽为当前普通节点；角色1方向为 `实际存在 -> 实例槽`；角色2方向为 `实例槽 -> 定义`；两个关系类型和顺序精确；
5. 当前值所属实例槽、属性类型、I64材料、来源精确；当前属性槽唯一指向该值；
6. 在同代次完整快照中确认指定宿主与定义组合只有该槽，槽无第二宿主、第二定义或第二当前值。

任一必需编码不存在或已退出返回 `未找到`；请求见证、代次或当前值漂移返回 `事实代次漂移`；关系方向/类型/基数、节点种类、值所属/类型/材料表示或属性槽损坏返回 `内部不一致`。

建立成功或精确重复后必须构造 `实际存在I64实例特征读取请求` 并调用同一公开读取入口。读回代次必须等于写入结果代次，否则返回 `事实代次漂移`。

## 9. 当前、历史、生命周期与线程

- 本叶只建立首个当前值。建立完成时没有前一值，实例槽历史值组为空。
- 初始值不得原地覆盖。现有 P4 换代请求绑定场景专用读取 DTO，不能静默用于实际存在；存在宿主换代留给后继叶。
- 3C 只消费本叶独立读回的初始当前值，不要求本叶先实现换代。
- 事实随 L1 生命周期长期保存；服务缓存随服务实例销毁，不拥有 P7/P2/L1 provider。
- 所有服务内可变状态受现有互斥量保护。公开读取也按现有方式串行；不得跨调用持有 L1 许可、快照引用、事务对象或锁。
- `std::bad_alloc` 映射 `资源失败`，其它异常映射 `内部不一致`。服务不写事件或调试日志。

## 10. 验证矩阵

现有 `海中鱼巣.领域.自检.L1实例特征` 顺序320专项原位扩展，不新增模块、不改工程或启动聚合，完整自检登记数不变。至少覆盖：

1. P7 真实实际存在、P2 定义与普通来源节点上建立实例，写集精确为一节点、两关系、一值、一属性槽；
2. 宿主关系、定义关系、值所属/类型/材料/来源和当前属性槽逐项独立同代次读回；
3. 不复用初始场景实例槽、当前值或 P7 当前场景归属关系；
4. 同一存在+定义唯一；同宿主其它定义和同定义其它宿主成功；重复槽、多宿主、多定义、多当前值为内部不一致；
5. 同键同义只发布一次并重复读回，同键异义冲突，不同键多线程形成不同事实；
6. 错版本/规则、零幂等身份、零代次、零来源、未绑定 P7 provider 和坏嵌套请求入口拒绝；
7. P7 未找到、资格/归属损坏，P2 未加载/未找到，来源未找到，事实代次漂移逐项分账；
8. L1 资源失败、写入映射损坏、发布后读回漂移和未知异常不产生假成功；
9. 现有场景建立、读取和 P4 换代矩阵保持通过，三个旧公开函数 blob/签名不变；
10. 建立前后不生成关系19状态、动态、因果、自我资格、治理虚拟存在或结算事实；
11. 生产模块对旧句柄/仓、旧 WORLD-TREE 服务、SQL、材料、P5、P6 和日志调用为零；
12. Debug/Release x64 Rebuild、两配置完整自检、strict、MSVC 模块扫描与 diff check 通过。
