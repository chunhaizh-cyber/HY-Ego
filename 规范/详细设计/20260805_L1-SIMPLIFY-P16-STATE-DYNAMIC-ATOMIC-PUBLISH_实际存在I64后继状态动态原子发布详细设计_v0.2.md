## 1. 目标、裁决和完成边界

本叶建立唯一、无领域解释权的组合发布服务。它消费 P13 冻结的后继关系19状态纯值规格，并只在 P13 判定非等价且允许动态时消费 P14 冻结的关系20状态迁移动能纯值规格；随后把规格机械拼接成一个 L1 合同 v2 写集，以一个期望事实代次、一个最终幂等键、一次提交和一个发布事实代次，原子发布后状态及可选迁移动能。

本叶不解释关系19、关系20、比较算法、状态相邻性或字段来源。状态事实由 `L1状态服务` 解释，动态事实由 `L1动态服务` 解释，L1 只解释节点、关系、值、属性槽及生命周期。

完成行为严格分为：

- P13 无前状态：返回具名 `无前状态`，零 P14 调用、零 L1 写入；
- P13 等价且禁止动态：只发布 P13 `0x53` 规格；
- P13 非等价且允许动态：形成 P14 `0x44` 规格，并与 P13 在一个写集中发布；
- P13/P14 非成功或坏成功：零 L1 写入；
- L1 成功或精确重复：使用首次映射和首次完整通用读回，分别交由状态、动态领域形成读取请求并独立读回；
- 任一完整性矛盾不得包装为部分成功，不得二次写、补偿、回滚或删除。

本叶最多证明未来源码形成上述真实原子发布候选；不证明 P6—P15 代码已经实现，不证明动作动态、因果、任务、结算、生产线程装配、SQL 持久恢复、旧消费者迁移、STEP-4 或治理闭环完成。

## 6. 请求意图、执行证据与正式幂等探测

请求意图摘要严格复用 P15 v0.29 的 G7 字节编码：

```text
ASCII "HZY-L1G7"（固定原始字节，不写长度/NUL）
→ U32 请求意图格式版本 = 1（大端）
→ U32 业务操作标签 = 0x15000603U（大端）
→ U8 入口变体 = 4
→ 按声明顺序编码 P16 公开请求 DTO 的全部字段
→ SHA-256 = L1领域意图凭证.请求意图摘要
```

P16 是状态/状态变化领域的独立 G7 入口，固定使用变体4、生产操作标签 `0x15000603U` 和独立幂等域 `0x10`；不复用 G7 T01/T02、P14 变体3/`0x15000F01U`，不复用 G9 或任何 L1 自检标签。DTO 字段从外到内严格按当前声明顺序编码：P16 合同版本、P16 规则版本、整理幂等身份、`实际存在I64后继状态规格请求` 的全部公开字段，以及其嵌套 `实际存在I64实例特征读取请求` 的全部公开字段；嵌套字段继续使用现有字段头、网络大端、optional/variant/vector/array 规则。领域凭证固定为 `{请求意图组=7, 请求意图格式版本=1, 请求意图操作标签=0x15000603, 请求意图摘要=上述摘要, 领域结果计划摘要=全零}`。provider 结果、共同截止、P13/P14 结果、写集、映射、稳定编码和读回不进入请求意图摘要。

执行证据摘要只在探测 `未找到` 且 P13/P14 分支完整后形成，使用同一确定编码和标准 SHA-256。载荷严格为：请求意图摘要32字节；P13规格版本、分支状态、动态准入、P13既有U64确定性摘要、完整状态规格与P10/P12/P11见证；可选P14规格版本、形成状态、P14既有U64确定性摘要和完整动态规格；分支形状；共同事实截止；provider合同/规则/算法版本；按L1规则规范化的最终写集全部字段；完整非空通用读回计划。它只供首次执行、审计和恢复互证，不能裁决同义/异义。

公开函数在调用 P13/P14、实例特征、状态、比较、动态或任何可变 provider 前，固定调用：

```cpp
L1.探测幂等({
    L1事实基座合同版本,
    L1幂等摘要合同版本,
    写集幂等键{最终幂等键},
    请求意图摘要
});
```

探测分支固定：

1. `同义已发布`：P13/P14及全部可变provider调用为零；直接消费首次执行证据摘要、首次发布代次、首次映射、首次完整通用读回和L1确定性结果摘要；
2. `异义冲突`：返回 `冲突`，provider零调用、零写；
3. `已隔离`：返回 `许可拒绝` 或携带见证的 `内部不一致`，不得包装成功；
4. `内部不一致`：返回同名非成功，零provider、零写；
5. `未找到`：才调用 P13 并进入首次形成；
6. `入口拒绝`：映射入口拒绝。

同义已发布以首次映射调用两个领域映射函数，再独立读回领域结果；成功状态为 `幂等读回`，`来自精确重复=true`。首次副本缺任一摘要、映射、完整读回、发布代次或形状矛盾返回 `内部不一致/幂等首次证据不完整`，不得扫描编码、读取SQL或重放写集。

运行期不查询 SQL，不建立旁路索引或第二幂等账。

## 7. 首次形成与分支

固定顺序：

1. 校验公开请求、最终幂等键并形成32字节请求意图摘要；
2. 调用 P15 v0.29 `探测幂等`；只有 `未找到` 才继续；
3. 调用 P13 `形成实际存在I64后继状态规格`；
4. `无前状态` 直接返回 `无前状态`，不调用 P14、不提交；该结果不建立成功幂等记录，后续同请求只有在 L1 仍探测未找到时才可重新评估；禁止用空写集推进代次记忆拒绝；
5. P13 非成功逐项映射为 `入口拒绝/未找到/冲突/不可比较/版本漂移/许可拒绝/资源失败/内部不一致`；
6. P13 已形成必须有完整状态规格、零部分幂等键、非零共同截止及确定性摘要；
7. 等价分支必须是 `禁止生成迁移动能` 且迁移证据等价、差异0；只采用 P13；
8. 非等价分支必须是 `允许形成迁移动能规格` 且迁移证据非等价、checked 差异非零；调用 P14；P14 必须返回一份完整规格；
9. 其它组合为坏成功，零提交；
10. 校验规格身份、版本、共同截止和命名空间，形成最终写集和非空读回计划；
11. 按第6节形成32字节执行证据摘要；
12. `L1写集请求` 同时填入请求意图摘要、执行证据摘要、一个最终幂等键、一个共同期望代次和非空完整计划，并只调用一次 P15 v0.29 L1提交，操作标签固定为 `0x15000603U`。

无前状态不得调用 P9 首态入口。值编码或事实代次改变但材料相同必须沿 P11 等价结果走仅状态分支，不能形成动态。

## 8. 规格拼接和唯一写集

等价分支只接收 P13 的 `0x53000001..0x5300000C`：二节点、五值、五关系19、五属性槽，零退出。不得出现 `0x44`、动态节点、关系20或 P14 属性值。

非等价分支直接按规范化顺序拼接：

- P13 `0x53`：二节点、五值、五关系、五槽；
- P14 `0x44`：一节点、八值、六关系、八槽；
- 零退出事实；
- P14 关系20角色5目标保持本地引用 `0x53000001`；
- 关系20角色仅1、2、3、4、5、9，角色6—8无节点、值、关系或槽。

发布者只能验证局部键集合全局唯一、引用可解析、部分写集合同和共同截止一致、部分幂等键均为0；不得重编号、重映射、重排角色、修改材料或补字段。最终请求只有一个 `期望事实代次=共同截止`、一个最终幂等键和一个 L1 v2 读回计划。

## 9. L1 v2 非空通用发布后读回计划

计划必须覆盖本次全部新事实，且只使用 P15 中性 DTO。

等价分支精确覆盖 P13：

- 两个新节点及其种类、表示、生命周期和本次发布创建代次；
- 五个新值的所属、属性类型、材料、来源、生命周期和本次发布创建代次；
- 五条新关系的源、目标、类型、角色、生命周期和本次发布创建代次；
- 五个发布后当前属性槽；
- P13 写集实际引用的必要既有稳定编码端点、类型和来源中性互证项。

非等价分支在上述项目外精确覆盖 P14 的一节点、八值、六关系和八槽，以及动态写集引用的必要既有稳定编码端点、类型和来源。角色5目标按本地键 `0x53000001` 互证；角色6—8没有计划项，因为没有对应事实。

每个新节点/关系/值必须且只能有一个 `本次发布/当前` 期望，每个槽只能有一个当前值期望；本叶零退出，所以不得制造 `本次发布退出`。重复、缺项、错种类、错引用或计划为空均在提交前拒绝。L1 不解释关系19/20、角色业务名、状态或动态语义。

## 10. L1 提交与领域读回

L1 v2 返回成功或精确重复时必须携带：首次执行证据摘要、首次完整新编码映射、首次 `L1通用发布后读回结果::成功`、L1确定性结果摘要和唯一非零发布事实代次。探测未找到后若并发同意图请求先发布，最终提交必须按 P15 v0.29 只比较意图摘要并返回竞争胜者的首次结果；本轮后来形成的执行证据或写集不同不得改判冲突，也不得覆盖首次证据。P15 v0.29 已在独占锁内捕获映射/对象/字段/生命周期/代次等中性矛盾；若该阶段失败，结果携带失败见证且 L1 已单调隔离，本服务只映射为 `内部不一致`，不再读取领域成功。

许可释放后固定执行：

1. 把完整映射交给 `L1状态服务::从后继状态新编码映射形成读取请求`；
2. 调用 P9 v0.3 同一公开读取入口取得不可变后状态；
3. 等价分支要求动态读取请求与动态事实均为空；
4. 非等价分支把完整映射交给 P14 动态映射函数，再调用 P14 既有公开读取入口；
5. 两个事实必须各自报告本次同一发布代次；
6. 非等价结果还机械互证：动态角色4为既有前状态，角色5为本次后状态，角色1/2/3/9与 P13/P14 输入见证一致，角色6—8为空。

发布者只比较领域结果中已冻结的身份、发布代次和输入见证，不自行解析关系向量。任何映射或领域读回矛盾返回 `内部不一致`，不得返回“状态成功、动态失败”的成功载荷。

## 11. 锁内隔离与锁外错误边界

边界固定：

- L1 读回计划覆盖的中性事实矛盾发生在 P15 同一独占锁内，由 L1 保留已发布代次、形成失败见证并隔离；
- 许可释放后才发现的领域映射函数缺口、领域 DTO 解释矛盾或 P16 计划遗漏，属于调用方内部错误；保留发布事实和首次 L1 证据，不进行第二写、补偿、回滚或删除，也不得伪称完整事务交付；
- 锁外错误结果必须保留最终幂等键、发布代次、L1 审计、首次映射/完整读回、P13/P14 摘要及已经形成的领域读取请求，供审计和既有恢复流程定位；
- 本叶不新增领域隔离入口、第二事务框架、人工解除或 SQL 裁决。若中性事实本身完好，是否需要沿既有恢复合同处理只能由后继治理裁决，发布者无权自行隔离或改写。

## 13. 线程、幂等、撤销和恢复

发布服务不持有跨 provider 锁。探测未找到后 P13/P14 才形成值式规格；L1 只在一次 `提交写集` 内取得自身独占许可。不同工作线程使用同一整理幂等身份收敛到同一最终键；已发布同义重试在provider前返回首次证据，异义在provider前冲突。两个同义请求均探测未找到时，最终独占提交只发布一笔，输家忽略本轮后来执行证据/写集并返回胜者首次结果。

不同请求竞争同一前态/实例槽时，各自规格携带共同截止。至多一个基于该截止提交成功；后到者因 L1 期望代次漂移或幂等冲突失败。不得依赖容器顺序或跨 provider 持锁。

提交前失败只丢弃值式规格。swap 后禁止撤销、补偿或回滚。P15 v0.29 的隔离只能由既有恢复候选确认合同解除；本叶不增加恢复或解除入口。当前用户范围排除崩溃、重启、断电和跨进程恢复，本叶不把恢复材料列为执行前置；正常进程内精确重复仍从 L1 双摘要幂等账经正式探测取得首次摘要、映射、完整读回和结果摘要，不扫描稳定编码。

## 14. 工程、自检和验证矩阵

工程登记新增数据头、服务模块和自检模块；启动文件登记自检顺序 `400`，位于 P14 顺序390之后。专项必须覆盖：

- 等价仅 P13 精确形状，动态为空；

- 探测未找到后的同义首发竞态只一笔发布，输家返回胜者首次结果；provider后来变化不改变同义结果；
- 首次执行证据摘要和L1确定性结果摘要逐字段与P15 v0.29首次副本互证；隔离探测不得返回成功；
