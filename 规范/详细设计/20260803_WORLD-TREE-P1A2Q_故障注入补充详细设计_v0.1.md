## 1. 目的与适用范围

本补充只冻结 P1A2Q 详细设计 v0.2 §5 已要求的“分配失败、其它异常”确定性验收入口，不改变两个生产根函数、公开 DTO、状态、正常控制流或事实语义。它与 v0.2 共同构成 P1A2Q v0.4 的直接施工依据。

唯一受影响生产文件：

```text
海中鱼巣/核心/仓库.可重建索引.ixx
海中鱼巣/核心/服务.节点直接结构.ixx
```

唯一测试消费者为 `海中鱼巣/核心/自检.节点直接结构查询.ixx`。生产代码、其它模块、旧 optional 包装和 L2 服务不得调用测试入口。

## 2. 编译边界与物理合同

全部测试类型、字段、函数声明、函数定义和注入分支必须位于既有专项编译宏：

```cpp
#if defined(HY_EGO_ENABLE_STRUCTURE_COMMIT_FAULT_SELF_TEST)
// 本补充冻结的内容
#endif
```

宏关闭时两个目标类的生产布局、公开符号、调用边和函数体分支均不得包含本补充内容。不得新增第二宏、全局变量、静态共享故障状态、环境变量、命令行开关或运行期配置。

两个目标模块的全局模块片段都必须补充 `#include <atomic>` 与 `#include <new>`，分别提供实例原子状态和 `std::bad_alloc`；不得依赖传递包含。头文件引入本身不产生项目符号或运行期分支。

### 2.1 索引仓实例私有注入

在 `可重建索引仓库` 类中仅于宏内增加：

```cpp
public:
    void 测试_令下次结构化精确读取抛出资源异常() noexcept;
    void 测试_令下次结构化精确读取抛出其它异常() noexcept;

private:
    mutable std::atomic<std::uint8_t> 测试_下次结构化精确读取故障_{0};
```

稳定内部值只允许：`0=无、1=资源异常、2=其它异常`。两个设置函数分别以 `store(1/2, std::memory_order_release)` 覆盖本实例尚未消费的模式；不累计、不跨实例共享、不抛异常、不读取事实。

`读取索引物理键结构化(const 索引物理键& 键) const` 在完成非法键拒绝后、取得索引仓锁前，于原有统一 `try` 内恰一次执行 `exchange(0, std::memory_order_acq_rel)`：

- 取到1：显式 `throw std::bad_alloc{}`，由本函数现有异常边映射 `资源失败`、空记录；
- 取到2：抛出本模块宏内私有空类型 `可重建索引精确读取测试异常{}`，由 catch-all 映射 `内部不一致`、空记录；
- 取到0：继续 v0.2 正常流程。

非法键不得消费故障；合法调用无论注入分支或正常分支均最多消费一次。注入调用不得取得仓锁、读取正反绑定、调用节点/关系仓或写机器事实。

### 2.2 查询服务实例私有注入

在 `节点直接结构查询服务` 类中仅于宏内增加：

```cpp
public:
    void 测试_令下次当前索引读取抛出资源异常() noexcept;
    void 测试_令下次当前索引读取抛出其它异常() noexcept;

private:
    mutable std::atomic<std::uint8_t> 测试_下次当前索引读取故障_{0};
```

设置、覆盖、内存序和稳定内部值与 §2.1 相同。`读取当前索引(const 索引物理键& 键) const` 在完成非法键拒绝后、取得事务域读取许可前，于原有统一 `try` 内恰一次 exchange：

- 1 抛 `std::bad_alloc{}`，本函数返回 `资源失败、代次0、空索引组`；
- 2 抛宏内私有空类型 `节点直接当前索引查询测试异常{}`，本函数返回 `内部不一致、代次0、空索引组`；
- 0 继续 v0.2 正常流程。

非法键不消费故障。注入分支中事务域、索引仓、节点仓和关系仓调用计数均为0，许可不取得，事实不变化。

## 3. 自检矩阵

专项自检必须在各自新建实例上完成，禁止让一个注入影响其它断言：

| 根函数 | 设置 | 第一次合法调用 | 第二次相同合法调用 | 事实与调用证明 |
| --- | --- | --- | --- | --- |
| 仓结构化读取 | 资源异常 | 资源失败、空记录 | 恢复正常未注入结果 | 第一次零锁后跨仓调用；权威导出不变 |
| 仓结构化读取 | 其它异常 | 内部不一致、空记录 | 恢复正常未注入结果 | 同上 |
| 查询服务读取 | 资源异常 | 资源失败、0、空组 | 恢复正常未注入结果 | 第一次事务域/六仓调用均0；代次与导出不变 |
| 查询服务读取 | 其它异常 | 内部不一致、0、空组 | 恢复正常未注入结果 | 同上 |

另须证明非法键调用后下一次合法调用仍触发预设故障，从而确认许可前准入不消费注入。测试入口 AST 调用方只能是专项自检；宏关闭的正式配置中四个测试函数名、两个字段名和两个私有异常类型均零命中。

## 4. 所有权、并发与完成边界

故障状态由目标对象实例拥有，生命周期与该实例一致；原子交换只治理测试指令消费，不形成项目机器事实、事务版本或业务并发协议。它不允许生产调用方依赖，也不改变仓库锁、事务许可或发布代次顺序。

本补充只使强制异常矩阵可确定性施工和验收，不证明 P1A2Q 真实查询已经实现、构建或运行通过。
