# 来源前驱绑定当前必要性与替换详细设计

标识：`SOURCE-BIND-NECESSITY`；版本：v0.1；日期：2026-11-09；状态：草案（待用户裁决第6节）。
起草：代码窗口（Claude）。施工所有者待定（采用路径当前由交互窗口负责）。

依据：
- 用户裁决（2026-11-09）：来源前驱目标实例采用，D出生后到绑定只核写入身份；绑定之后的语义变化交由子需求当前必要性复核与父任务重新筹办处理。
- 用户裁决（2026-11-08）：内部世界允许随时变化，发现变化时按变化种类应对。
- `验证记录/20261109_ADOPT-BIND_采用绑定只核写入身份与调度暂态修正记录.md` 第4节（交互窗口核实：绑定后无必要性复核，也无解绑/替换）。
- 规范：3100 §48、§161、§163、§171；3200 §57、§105；5170 §137、§147。

## 1. 修改对象、原因与目的（AGENTS §1 第5项）

| 项 | 内容 |
| --- | --- |
| 修改对象 | 虚拟存在的特征值，属内部治理：父任务的“来源前驱目标实例”绑定字段、服务取得槽实例登记、来源前驱内容子需求的活动状态。不改变现实世界。 |
| 原因 | 绑定只在出生时依据当时的交互者H成立。绑定之后交互者可能变化（H→H′），而绑定没有任何复核与替换：父任务再也取不到H′的需求，旧H的内容子需求继续被治理。 |
| 目的 | 发现绑定已不再必要时，让父任务能为当前服务对象重新取得需求内容，同时停止治理已不再需要的旧内容子需求。 |

## 2. 当前事实（路径相对 `海中鱼巣/海中鱼巣/`，基线 `9c7280f6b` 加交互窗口未提交改动）

1. **绑定字段**：父任务至多一个“来源前驱目标实例”字段，指向出生记录R。采用时已绑定则 `贡献要求` 断言指向本次出生记录（`领域/新_任务类.cpp` `建立或取得来源前驱目标实例` 绑定段）。
2. **槽实例登记**：需求owner `读取服务取得目标槽实例(父T,槽,根路径)` 经需求树根的“服务取得实例登记字段”查找，登记按（父任务、槽、根路径）定位，不含H。实例信息的键 `新服务取得目标实例键` 记录了服务对象H（`领域/新_需求类.h:262`）。
3. **键不符**：`读取来源前驱目标实例(键)` 在本槽实例的键与请求键不同时返回“前提已变化”（`领域/新_任务类.cpp:14129`）。
4. **由此造成的阻断**：交互者从H变为H′后，父任务重新筹办得到H′的前端；采用读到本槽实例的键仍是H，每次都返回“前提已变化”，父任务永远取不到H′的需求内容。旧H的内容子需求 `{D_H, 路径}` 保持活动。
5. **现有必要性复核**：
   - `复核复合子目标当前必要性`：只对复合来源子需求。
   - `复核方法内容子需求必要性`（`领域/新_任务类.cpp:18675`）：入口条件是“有引用内容定位、非复合、来源类型为任务子目标”，来源前驱内容子需求也满足；但它按父任务的方法条件子需求提议的“已知条件项组”找对应项。来源前驱内容子需求来自因果前端，不在方法条件提议中，**很可能被判为“已不再必要”或“等待读取”，使其任务一直业务等待**。内容子需求至今没有在运行中出生过，此点待核实（见第5节）。
6. **“不再必要”的后果**：现有复核结果只让任务进入业务等待（`需求材料未到`）。代码中没有任何把需求置为“失活”的写入口；3100、3200、5170 定义了失活状态及其权重与收束效果，但没有规定何时进入失活。

## 3. 设计

### 3.1 绑定当前必要性（任务owner，只读）

新增 `复核来源前驱绑定当前必要性(父T)`。父任务没有绑定时不适用。三项全部成立为“仍必要”：

| 项 | 判据 | 不成立时 |
| --- | --- | --- |
| a | 父任务未终结；父需求活动，且 `复核当前满足` 不是“已满足” | 已不再必要 |
| b | 自我的交互者特征当前值等于实例键中的服务对象H | 已不再必要 |
| c | `比较存在与概念信息(H, 人类概念)` 结论为“属于” | 不属于：已不再必要；未知：暂不能判定 |

- 结果：仍必要 / 已不再必要 / 暂不能判定 / 资源失败。未知不当作否定（暂不能判定时任务等待，不做替换）。
- 返回保护：父任务、绑定字段、交互者特征、H归属依据的快照，供调度场景批按“依据未变就沿用”复用。
- 不重做因果逆推（理由与待裁决见第6节第1项）。

### 3.2 来源前驱内容子需求的必要性

识别：子需求的引用内容定位所指需求，等于其父任务绑定实例的需求节点。对这类子需求，不走方法条件提议的查找，必要性规定为：

- 父任务绑定字段仍指向该子需求所在实例，**并且** 3.1 为仍必要 → 仍必要；
- 绑定已指向其它实例或已无绑定 → 已不再必要；
- 3.1 为暂不能判定 → 等待读取。

这同时修正第2节第5项的误判风险。

### 3.3 绑定替换（推荐方案R1，待裁决见第6节第3项）

1. **登记按H区分**：需求owner的槽实例查找增加服务对象参数，登记唯一性改为（父任务、槽、根路径、H）。H′出生新实例，不与旧H实例冲突；旧实例及其D作为事实保留。
2. **采用时替换绑定**：`建立或取得来源前驱目标实例` 绑定段：
   - 字段为空 → 照旧追加；
   - 字段已指向本次出生记录 → 照旧复用；
   - 字段指向旧实例R_old，且 3.1 对R_old判为已不再必要 → 原子替换为本次出生记录，对父任务与R_old出生记录做严格预期；
   - 其余情况 → 绑定冲突，不写。

   替换之前的判定沿用用户 11-09 裁决的口径：这里核的是写入目标（父任务字段当前指向谁），属于写入身份，不是语义依据重算。
3. 旧绑定不删除出生记录与D。D不再被任何绑定引用后，按3100 §171 生命周期规则清理。

备选方案R2：解除绑定（删除字段）＋需求owner给旧出生记录加“已退出”标记，查找时跳过已退出实例。R2写入点更多，并且需要跨owner的两步写顺序，所以不推荐。

### 3.4 旧内容子需求失活（待裁决见第6节第2项）

- 需求owner新增写入口 `置子需求失活(D, 原因)`：只接受非根、非双根的自我执行子需求；CAS写活动状态为失活，并按5170 §137 递归重算受影响子树权重。
- 3.2 判为“已不再必要”的来源前驱内容子需求，由任务管理线程提交失活。
- 其任务按3200 §57 收束：全部服务需求失活或满足时收束。已发出的询问不撤回；对方之后的回答仍按回答写回写入D_H（只是事实，不再被治理）。

### 3.5 触发位置

不新增轮询：

- **父任务**：在调度场景批中计算 3.1（有绑定时）。判为已不再必要时，调度项等待原因记为“条件发生变化需重新筹办”，父任务重新筹办，采用按3.3替换。交互者特征变化会改变其快照，使场景批重新计算。
- **内容子需求任务**：在调度场景批中计算 3.2。判为已不再必要时，提交 3.4 失活。

## 6. 待用户裁决

1. **必要性判据只用三项事实（父需求未满足、交互者仍是H、H属于人类），不重做因果逆推。** 理由：逆推是筹办的职责，并发下“材料已变化”频繁（11-09运行中30次），用它判必要性会反复误判；执行许可已按同样思路改为只看目标是否达成（CAUSAL-PERMIT-GOAL-CHECK）。代价：因果规则本身变化而交互者未变时，旧绑定不会被替换，只能等父任务的重新筹办发现。
2. **引入需求失活写入口**：来源绑定被替换后，旧内容子需求置为失活，权重重算，任务收束。不引入时，这些子需求只能永久业务等待。此项需要随后修订5170（何时进入失活），须用户确认。
3. **替换方式**：R1（登记按H区分、采用时原子替换绑定，推荐）还是 R2（解绑并标记旧实例已退出）。
4. **交互者回到旧H时**：R1下直接复用旧H实例并重新绑定；已失活的旧内容子需求不恢复，需要时按正常筹办新建（符合3100 §171“以后再需要时作为新需求重新建立”）。需要核对新建子需求与已失活同目标子需求的重复判定。
