## 1. 最小裁决

v0.9 完整替代并禁止施工 v0.8。保留 v0.8 已冻结的 16 文件 / 50 点业务操作身份标签矩阵、首次/同义/异义共享标签、provider 前 `探测幂等`、同锁一次提交、发布后权威读回、失败见证/隔离、审计/恢复互证和领域 DTO 映射；本版本只修订 G0 的真实字段来源、版本归属和确定性编码顺序。

同一业务操作的首次、同义重复、异义材料和隔离重试继续使用 v0.8 已冻结的唯一共享标签；异义只由实际公开字段差异形成不同请求意图摘要。

## 3. G0—G8 公开字段、版本归属与编码

### 3.1 G0 实际 DTO 与精确编码

当前 `海中鱼巣/核心/L1事实基座.数据.h` 的 `L1写集请求` 精确字段为：

| 顺序 | 字段 | 来源/归属 | 是否进入 G0 请求意图摘要 |
| --- | --- | --- | --- |
| 1 | `合同版本` (U32) | L1 写集公开合同，当前值 2 | 是 |
| 2 | `摘要合同版本` (U32) | L1 幂等摘要合同，当前常量 `L1幂等摘要合同版本=1` | 是 |
| 3 | `期望事实代次` (U64) | 调用方公开写请求 | 是 |
| 4 | `幂等键` (U64) | 调用方公开幂等身份映射 | 是 |
| 5 | 节点/关系/值/属性槽/退出事实 | 调用方形成的强类型中性写集 | 是 |
| — | `请求意图摘要`、`执行证据摘要`、`发布后读回计划` | L1 派生/执行证据材料 | 否，分别按下述规则处理 |

G0 的请求意图摘要编码固定为：

```text
"HZY-L1ID"
+ U32 编码格式版本=1
+ U32 业务操作标签
+ U8 模式=1（请求意图）
+ U32 合同版本
+ U32 摘要合同版本
+ U64 幂等键
+ U64 期望事实代次
+ U64 节点数量 + 节点项目
+ U64 关系数量 + 关系项目
+ U64 值数量 + 值项目
+ U64 属性槽变更数量 + 属性槽项目
+ U64 退出事实数量 + 退出编码
```

节点、关系、值、属性槽项目的内部顺序和引用编码沿用现行 `写写集`；版本字段必须位于幂等键之前，不能从幂等键、期望代次或调用点推导。执行证据摘要复用同一 G0 载荷顺序，但在 `模式=2` 后先追加原始请求意图摘要，再追加上述 G0 载荷，最后追加发布后读回计划；结果摘要和幂等账已经单独保存/编码合同版本与摘要合同版本，必须与 G0 两字段互证。

G0 没有 `规则版本` 字段。不得新增同名字段、把 `规则版本` 解释为 `摘要合同版本`，或用默认值/调用点补造。规则版本只在拥有它的 G1—G8 L2 请求及 provider 执行证据中编码；L1 幂等账保存的摘要合同版本是摘要格式互证字段，不是业务规则版本。当前只支持合同版本 2 与摘要合同版本 1；任一版本不支持都在摘要/探测前入口拒绝并保持零 provider、零提交、零变化，不得静默重算。

### 3.2 G1—G8 字段存在性复核

以下表按当前正式 DTO 逐组冻结；表中没有出现的设计字段不得由执行者临场添加：

## 5. 探测、首次结果和非成功映射

每点先以“幂等域+公开幂等身份、字段组、共享操作标签”形成请求意图摘要，再调用 `L1事实基座服务::探测幂等`。同义返回保存的首次执行证据、首次发布代次、结果摘要和完整读回，provider/提交次数均为 0；异义返回幂等冲突和零业务载荷；已隔离返回隔离拒绝和失败见证；仅未找到允许读取 provider/当前事实。

候选成功后形成执行证据摘要，L1 v2 提交恰一次，并在同锁内做完整发布后读回。成功或精确重复映射保持 v0.8：世界登记→世界登记 DTO，场景→初始场景 DTO，定义→定义 DTO，实例→实例特征 DTO，存在/X01/X02→实际存在 DTO，状态→状态 DTO，比较→比较 DTO，核心/自检→L1结果断言材料。入口拒绝、版本漂移、资源失败、内部不一致和读取未找到按现有 DTO 稳定映射，零部分业务载荷；读回缺字段、重复键、错代次、双摘要不一致或首次结果不一致进入内部不一致和隔离。
