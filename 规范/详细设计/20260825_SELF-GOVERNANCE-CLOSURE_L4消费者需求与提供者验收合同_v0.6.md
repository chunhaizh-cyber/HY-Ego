# SELF-GOVERNANCE-CLOSURE L4 消费者需求与提供者验收合同 v0.6

设计身份：`SELF-GOVERNANCE-CLOSURE-L4-CONSUMER-CONTRACT`

版本：v0.6

日期：2026-08-25

状态说明：本文件是 v0.5 的计划支撑修订候选；运行状态只由计划索引裁决。发布并登记后，本文件取代 v0.5 第 4.3、4.4、8、10 节中的冲突口径；其余目标 ARCH-L2 ABI、提供者验收边界和八文件 WIP 裁决继续沿用 v0.5。

## 1. 修订原因

执行 S0 发现两项 L4 自身合同未闭合：

1. v0.5 只要求争用结果先分配，但没有正式成员分配优先级的业务来源，也没有冻结关系、优先级、逐项扣减和最终剩余的不可分割发布边界；
2. v0.5 把自我授权写在控制态、调度资格和安全硬否决之前，与 8200 的派发前置顺序冲突。

本修订不改变交互2负责的 ARCH-L1/L2 状态、当前选择和动态公开 ABI。

## 2. 现实执行授权与安全硬否决唯一顺序

内部治理相当于“想”，纯现实观察只读世界，二者都不建立现实执行授权。现实改变相当于“做”，只有它在执行冻结形成后、任何真实动作开始前取得一份自我授权。

固定门控顺序为：

```text
独立读回当前阶段、Rn/Pn/En、冻结、实例和有序动作范围
-> 读取 6170 当前生存控制态
-> 读取安全 / 服务调度资格及适用 6150 倍率
-> 读取稳定动作端口的当前技术许可
-> 调用同一只读现实执行硬否决 provider 做第一次预检
-> 控制、资格、技术许可或硬否决不通过：不请求授权，零真实动作
-> 冻结含现实改变：自我 owner 发布并独立读回唯一现实执行授权
-> 内部治理 / 纯观察：显式记录“无需授权”，不建立零授权占位
-> 真实动作开始前再次独立读回冻结、控制态、资格、技术许可、适用授权
-> 调用同一只读硬否决 provider 做最终复核
-> 全部成立后才迁移执行进入动作并确认工作队列
```

第一次预检和最终复核不是两份安全事实，也不建立第二安全 owner；二者消费同一安全事实入口和规则版本。请求必须显式绑定`授权前预检 / 动作前最终复核`阶段、完整有序冻结动作范围、`零现实改变 / 含现实改变`分类、来源共同事实截止和硬否决规则版本。结果状态完整固定为`不适用、未命中、已命中、材料不足、当前性漂移、资源失败、内部错误`，并把作用范围证据、安全事实正式读回见证、命中证据和本次裁决截止分账返回。`不适用`只允许`零现实改变 + 完整作用范围证据 + 零安全读回见证 + 零命中证据`；`未命中`只允许`含现实改变 + 完整作用范围证据 + 完整安全读回见证 + 零命中证据`；二者都是门控允许继续的合法结果，但都不是正向授权。`不适用 + 含现实改变`、`未命中 + 零现实改变`、阶段回显错误或证据形状错误都属于门控内部不一致并阻断。授权不能覆盖硬否决，硬否决可以阻止已经取得授权但尚未开始的现实动作。混合方法含任一现实改变时，整个有序冻结在第一步动作前取得一份授权，不得先运行观察前缀。

## 3. 正式成员分配优先级的唯一来源

争用结果的成员顺序属于自我对需求之间现实资源争用的治理裁决，不属于任务调度、需求权重、预算、创建时间、队列位置或稳定编码。

唯一来源定义为：

```text
自我线程冻结本次争用治理批次
-> 独立读取正式结果、冻结合格 T→D 成员、需求当前事实、消费资格、容量合同和共同截止
-> 调用“裁决并发布自我结果争用成员优先级”
-> 自我领域 provider 验证完整成员一一对应、证据当前、规则版本和显式全序
-> L2自我治理结构 owner 在一次 owner 写入中发布优先级批次及全成员事实
-> 独立读回完整批次
```

自我治理请求必须显式给出每个成员的`消费资格、优先级序号、同级顺序序号、理由证据组`，并绑定`自我、T、Rn、正式结果、完整争用容量合同、冻结成员集合版本、共同事实截止、来源规则身份、关系规则版本、优先级规则版本、同级规则版本、幂等身份`。provider 只验证并发布自我裁决，不读取或折算现有排序字段，不补默认值，不按稳定编码破同级。消费关系与完整分配记录随后由 result owner 在同一事务中形成；优先级批次不引用尚未形成的消费裁决身份。

同一优先级内必须有非零且唯一的同级顺序序号；全成员必须一一覆盖，漏项、多项、重复顺序、证据过期或成员集合变化都零写拒绝。精确重复读回首次事实，同键异义零新增。

## 4. 跨 self / result 的唯一共享合同 module

跨 self owner 与 result owner 的消费身份、消费形态、扣减维度、容量合同和成员资格材料只有一份物理定义：

```text
文件：海中鱼巣/领域/合同.任务结果消费共同.ixx
module：海中鱼巣.领域.合同.任务结果消费共同
```

该 module 只导出跨 owner 的强类型值合同，不是业务 owner，不提供 service、provider 或写入口。`服务.L2自我治理结构.ixx`与`服务.L2任务结果消费结构.ixx`各自只`export import`它；禁止再建立`任务结果消费共同.数据.h`，也禁止在两个结构 module 的文本数据头内复制、转声明或分别拥有这些共享实体。

## 5. 争用分配不可分割事务

结果 owner 的唯一公开发布入口必须一次消费：

```text
正式结果
+ T / Rn
+ 冻结成员集合与版本
+ 消费容量合同
+ 完整自我优先级批次及全成员证据
+ 关系 / 优先级 / 同级规则版本
+ 显式幂等身份
+ 来源共同事实截止
```

它在一个 owner 事务内发布一份完整`任务结果消费分配记录`，记录同时包含：

```text
消费关系
+ 规范化冻结成员
+ 完整优先级证据组
+ 初始容量 / 剩余
+ 按(优先级序号, 同级顺序序号)形成的逐项分配链
+ 每项分配前剩余、实际分配、分配后剩余
+ 最终剩余
+ 请求幂等账和生命周期
```

可共用路径不形成优先级批次或分配记录中的优先级账；争用路径禁止逐成员公开部分提交。三类结果的逐成员算法固定为：

1. `可重复引用`：成员按成员身份规范化形成稳定输出顺序；该顺序不取得业务优先级语义。每成员状态为`共同引用`，正式优先级为空，最低合法单位、期望单位、分配前剩余、实际分配和分配后剩余全部为 0；初始与最终剩余均为 0。
2. `可分割单位`：容量合同只允许一个扣减维度；按正式`(优先级序号, 同级顺序序号)`全序处理。若当前剩余为 0，成员状态为`结果已耗尽`、实际分配 0；若当前剩余小于该成员最低合法单位，状态为`未获分配`、实际分配 0 且剩余不变，后继成员仍继续裁决；否则状态为`已分配`，实际分配固定为`min(期望分配单位, 当前剩余)`。每一步的分配后剩余是下一步分配前剩余。
3. `不可分割资格`：初始单位固定为 1，每成员最低和期望单位均固定为 1；按正式全序的首个合法成员状态为`已分配`并分配 1，其余成员状态为`结果已耗尽`且分配 0，最终剩余为 0。

成员状态枚举只允许`共同引用、已分配、未获分配、结果已耗尽`。可重复引用的处理顺序按规范化成员身份连续形成`1..N`，只表示稳定输出位置；两类争用的处理顺序按正式全序连续形成`1..N`。完整链必须满足`sum(实际分配单位)+最终剩余=初始剩余`、无下溢且逐步前后连续；现有单标量容量合同遇多个扣减维度时必须交换前`关系不可裁决`，不得临场解释成多维账。任何成员资格、优先级、容量、扣减、溢出、当前性或闭包失败都在交换前零写返回。提交后独立读回失败保留已确认事实和幂等账，以原键重放收束。

只有完整记录独立读回后，各需求 owner 才逐 `T→D` 核算；任务轮次收束只引用该记录和各需求核算事实，不复制第二分配账。

## 6. 完成与验收边界

最终统一验收新增以下必测：

1. 不合格控制态、零资格、技术许可拒绝或第一次硬否决时不产生授权请求；
2. 现实改变取得唯一授权后，最终硬否决仍能阻止动作；内部治理和纯观察全程零授权；
3. 可共用结果零优先级账；
4. 争用结果的优先级批次覆盖全部成员且不使用禁止字段；
5. 可重复引用的零数值/零优先级账、可分割的耗尽/低于最低单位后继续/合法部分或完整分配、不可分割的唯一首个获配均以单记录原子发布，逐项剩余连续、总量守恒且最终剩余正确；多扣减维度确定性零写拒绝；
6. 缺优先级、同级顺序、成员证据或容量时零分配、零需求核算、零轮次收束；
7. 同键重复、异义冲突、提交后读回失败和原键重放均按结构化结果收敛；
8. 预检和最终复核分别覆盖`不适用 / 未命中 / 已命中 / 材料不足 / 当前性漂移 / 资源失败 / 内部错误`，且`不适用`不能用于任何含现实改变的冻结。

本文件发布只证明 L4 需求合同完成修订，不证明代码、ARCH-L2 提供者接线或自我内部治理闭环已经完成。
