# INSTINCT-STAGE3-MAINTENANCE-CURSOR-FACT-GENERATION-WATERMARK 维护游标事实代次水位基础详细设计 v0.1

日期：2026-08-30

设计身份：`INSTINCT-STAGE3-MAINTENANCE-CURSOR-FACT-GENERATION-WATERMARK`

## 1. 目标与完成边界

把 6170 v0.8 冻结的“已消费主动安全变化事实代次”加入现有本能被动维护游标，并在生产启动中先确保永久变化账登记，再建立、迁移或恢复双水位游标。

本叶完成后，唯一当前游标同时保存：

```text
时间水位：上一已维护完整秒边界
事实水位：已消费主动安全变化事实代次
```

首次事实水位固定等于永久变化账首次登记事实代次；新运行代次 / 新时间纪元继承既有 v2 事实水位，不重置、不补算停机秒。现有 v1 游标只允许在正式登记见证下迁移为 v2，首次事实水位同样取登记代次。

本叶不导出同一纪元推进入口，不调用单秒规则，不写 A/V、状态或动态，不把事实代次解释为完整秒。后继完整维护事务必须在 `(旧事实水位,G0]` 完整裁决成功后，才把两个水位与 A/V 变化共同原子提交。

固定生产材料保持不变：

```text
值域 = 0..INT64_MAX
L = 2767011611056432742
H = 7378697629483820645
安全根定义版本 = 1
主动安全来源规则版本 = 1
```

## 2. 正式依据与当前事实

- 6170 v0.8：首次事实水位等于账登记代次；事实水位跨运行代次连续；两个水位只能在完整维护提交中共同推进。
- 4230 v0.20：永久变化账登记、按事实代次 `(排除起点,G0]` 完整读回及覆盖边界已经冻结并实现。
- `662cf491`：`读取事实代次覆盖主动安全变化裁决_v1` 已实现规则版本 1 的完整空覆盖裁决，非空变化组 fail-closed。
- 当前 `本能被动维护游标事实_v1` 只保存完整秒边界，持久材料为 6 项 U64 组；`建立或恢复..._v1` 明确拒绝同纪元推进，生产启动使用 v1。
- 当前游标 owner、当前属性槽、历史值和普通应用唯一服务实例已经发布；无需新 owner、第二当前槽或工程文件。

复用结论：扩展同一游标数据头和服务，保留 v1 源码兼容；复用状态动态原子发布服务的正式账登记结果作为不可变登记见证；生产启动切换到 v2。不得让游标 owner 复制永久账索引或直接读取其 private 登记 helper。

## 3. v2 数据合同

专属合同版本固定为 2。v1 类型、枚举值和函数继续保留。

```cpp
struct 本能被动维护游标事实_v2 final {
    L2存在身份 自我;
    std::uint64_t 运行代次;
    std::uint64_t 时间纪元身份;
    std::int64_t 上一已维护完整秒边界;
    std::uint64_t 已消费主动安全变化事实代次;
    std::uint32_t 时间源版本;
    std::uint32_t 服务时间维护规则版本;
    std::uint64_t 形成事实代次;
};
```

全部身份和版本有效；两个事实代次非零；完整秒边界非负。持久 U64 组顺序固定为：自我、运行代次、时间纪元、完整秒边界、主动安全事实水位、时间源版本、维护规则版本。

```cpp
struct 建立或恢复本能被动维护游标请求_v2 final {
    std::uint32_t 合同版本;
    L2结构请求头 请求头;
    L2结构幂等身份 幂等身份;
    本能根运行锚点_v1 本能根锚点;
    std::uint64_t 运行代次;
    std::uint64_t 时间纪元身份;
    std::int64_t 当前完整秒边界;
    std::uint64_t 目标已消费主动安全变化事实代次;
    L2特征当前值变化账登记结果_v2 变化账登记见证;
    std::uint32_t 时间源版本;
    std::uint32_t 服务时间维护规则版本;
};
```

登记见证必须 `成功()`，锚点有效，首次登记代次非零，且：

```text
首次登记事实代次
<= 登记见证.本次正式读回截止
<= 请求头.期望事实代次
```

请求不得用裸 G0、日志或缓存替代登记见证。

建立状态固定为：`已建立、已恢复、已迁移、已建立新纪元、精确重复、入口拒绝、当前性漂移、幂等冲突、引用冲突、资源失败、内部错误、已可能发布`。前五种只有在完整提交游标、首次提交代次和正式读回截止齐全时成功；已可能发布只保留幂等身份和首次提交见证。

读取合同：

```cpp
本能被动维护游标读取结果_v2 读取当前本能被动维护游标_v2(
    const 本能被动维护游标读取请求_v2&) const noexcept;
```

读取状态固定为：`已读取、未建立、待迁移、入口拒绝、当前性漂移、引用冲突、资源失败、内部错误`。`待迁移` 表示当前槽存在完整 6 字段 v1 材料；它返回空 v2 载荷和零截止，不允许调用方把缺水位的 v1 投影当成 v2 成功。

## 4. 兼容、建立、迁移与新纪元

1. 物理解码先区分 6 项 v1 与 7 项 v2。v1 读取入口可以从 7 项 v2 材料投影原六字段，保持旧源码消费者可读，但投影不包含事实水位，不能用于后继维护提交。
2. 当前游标不存在：目标事实水位必须等于登记首次代次；建立 v2，状态为已建立。
3. 当前是 v1：目标事实水位必须等于登记首次代次；运行代次 / 纪元与请求同值，或二者共同变化。建立 v2 并切换当前槽，状态为已迁移或已建立新纪元。旧 v1 值永久保留。
4. 当前是 v2 且运行代次 / 纪元相同：边界、水位、时间源和规则版本必须逐字段相同，返回已恢复、零写；任一不同都返回引用冲突。本入口不推进同纪元任一水位。
5. 当前是 v2 且运行代次 / 纪元共同变化：目标事实水位必须等于当前 v2 水位；建立新纪元 v2，完整秒边界取当前运行观察，事实水位跨代次继承。只变化运行代次或只变化纪元拒绝。
6. 时间源版本或维护规则版本漂移拒绝，不静默换代。
7. 精确重放先于当前性裁决。重放逐字段核对首次规范化写集，返回首次提交游标和首次 G1；不得因当前槽已经被后继维护推进而把原提交改判失败。
8. 首次提交后以 G1 正式读取提交值和当前槽；读回不闭合返回已可能发布。原键重放负责收束，不做补写。

## 5. 生产启动顺序

`启动应用程序` 在安全根生产定义完成后按以下顺序处理：

```text
读取 Gledger
-> 调用确保特征当前值变化永久账登记_v2
-> 登记非成功则初始化失败
-> 读取当前 v2 游标
-> 已读取：目标事实水位取当前 v2 水位
-> 未建立 / 待迁移：目标事实水位取登记首次代次
-> 其它非成功：初始化失败
-> 读取本运行代次完整秒边界
-> 建立 / 恢复 v2 游标
-> 以新 Gread 独立读取当前 v2 游标并逐字段互证
-> 成功后才创建自我线程
```

生产不再调用 v1 建立入口。登记与游标仍是两个顺序提交：登记是不可变覆盖边界，游标建立只记录该边界；这不构成维护推进。若登记成功而游标失败，下次以同一固定登记身份读取原登记，再重试游标，不丢失变化。

## 7. 验证矩阵

- v2 首次建立：登记代次等于首次水位，边界 0 / 正值均成功。
- v1 兼容：v1 当前可由 v1 入口读取；v2 读取返回待迁移；v2 建立迁移后旧 v1 历史保留。
- 同纪元：完全相同恢复零写；边界变化、水位变化、时间源 / 规则漂移全部拒绝。
- 新纪元：运行代次与纪元共同变化，完整秒取新观察，事实水位继承；只变化一项拒绝。
- 登记：未登记、坏见证、已可能登记、见证晚于 G0、目标水位早 / 晚于应有水位均拒绝。
- 幂等：精确重复、同键异义、提交后读回失败原键收束；当前槽后续变化不改变首次重放结果。
- 启动：正式登记、v2 建立 / 迁移、独立读回全部成功才到达自我线程创建；任一非成功 fail-closed。
- 回归：旧 v1 专项语义、基础快照 v1、主动安全事实代次空覆盖裁决保持。
- Debug / Release 根工程 Rebuild；专项 Debug / Release 实际运行；`/GL + /LTCG` ABI consumer；strict 与精确差异门禁。
- 固定值域、L/H、定义版本、来源规则版本、单秒规则、A/V、状态 / 动态和游标推进入口零变化。
