# L1-SIMPLIFY-P18-WORLD-REGISTRY-READ 世界登记非阻塞定位读取详细设计 v0.1

## 1. 身份、目标与完成边界

计划身份：`L1-SIMPLIFY-P18-WORLD-REGISTRY-READ`

版本：`v0.1`

创建侧正式代码基线：`3927a931dfc8947ba58b88573993a0ffe6bdb889`

本叶是 SELF-GOV-CLOSURE STEP-4 在 P17 之后发现的更早定位提供者，只原位扩展唯一 `世界登记服务`，形成版本化、纯值式、一次 try-lock 的 `尝试读取当前登记`。它向后继场景结构事实所有者提供世界根、场景标记属性类型、直接父场景关系类型、直接成员关系类型和登记服务身份的不可变定位材料。

完成必须同时成立：

- 输入合同/规则版本明确，输出复用唯一 `世界登记结果` 和 `世界结构登记`；
- 许可竞争立即返回 `许可拒绝`，不等待、不 sleep、不重试；
- 登记未加载、坏登记、资源失败和内部异常结构化分账；
- 成功只返回已经建立并完整验证的登记副本，不扫描 L1、不查询 SQL、不猜测稳定编码；
- 新旧登记读取共用唯一私有已持锁复制/校验实现，不建立第二登记缓存或第二解释逻辑；
- 明确 `已验证事实代次` 只是登记首次建立时的验证见证，不能冒充当前事实截止代次。

本叶不调用 P17、不读取当前世界结构、不解释场景关系或成员资格，也不形成指定根世界结构、完整世界快照或统一世界门面。

## 2. 正式依据与只读能力矩阵

正式依据：

- 4015：新 L1 只提供业务中性事实；L2 不得取得仓库、锁、许可、事务或句柄；
- 4200 §3：世界结构登记是 L2 对已发布事实的值式定位材料，不是第二数据仓或运行期权威；新服务实例未恢复登记时必须 `登记未加载`，不得扫描或猜测；
- 4200 §5.1：读取许可竞争立即拒绝，不能等待、sleep 或隐式循环；当前事实代次必须来自权威内存读取；

## 4. DTO、公开函数与唯一私有实现

在 `世界登记.数据.h` 新增：

```cpp
struct 世界登记读取请求 final {
    std::uint32_t 合同版本 = 世界登记合同版本;
    std::uint32_t 世界规则版本 = 世界登记规则版本;
    friend bool operator==(const 世界登记读取请求&,
        const 世界登记读取请求&) = default;
};

inline bool 世界登记读取请求有效(const 世界登记读取请求& 请求) noexcept {
    return 请求.合同版本 == 世界登记合同版本
        && 请求.世界规则版本 == 世界登记规则版本;
}
```

复用现有：

```cpp
enum class 世界登记状态 : std::uint8_t {
    已提交 = 1, 幂等读回 = 2, 已读取 = 3, 登记未加载 = 4,
    入口拒绝 = 5, 幂等冲突 = 6, 事实代次漂移 = 7,
    许可拒绝 = 8, 资源失败 = 9, 内部不一致 = 10
};

struct 世界登记结果 final {
    世界登记状态 状态;
    std::optional<世界结构登记> 登记;
};
```

新增公开函数：

```cpp
世界登记结果 世界登记服务::尝试读取当前登记(
    const 世界登记读取请求& 请求) const;
```

在服务内抽取唯一私有：

```cpp
世界登记结果 复制已持锁当前登记() const;
```

私有函数只在调用方已经持有 `锁_` 时使用：未加载返回 `登记未加载`；`世界结构登记完整` 失败返回 `内部不一致`；否则复制并返回 `已读取`。既有阻塞兼容入口 `读取当前登记()` 和新非阻塞入口共同调用它，禁止复制两套判断。

既有入口不改签名、不改阻塞兼容语义；本叶不迁移现有调用点。STEP-4 后继场景结构叶必须使用新入口，不能回退旧入口。

## 5. 固定读取算法

`尝试读取当前登记` 固定执行：

1. 在锁外校验请求合同版本和世界规则版本；错误返回 `入口拒绝`、空登记，锁尝试为0；
2. 用 `std::unique_lock<std::mutex>{锁_, std::try_to_lock}` 尝试一次服务内部许可；
3. 未取得许可立即返回 `许可拒绝`、空登记；不等待、不 sleep、不循环；
4. 取得许可后调用唯一 `复制已持锁当前登记`；
5. 未加载返回 `登记未加载`；坏登记返回 `内部不一致`；完整登记返回 `已读取` 和逐字段副本；
6. 返回前释放锁，不外泄锁、引用、指针、许可或可写缓存。

成功副本必须保持：合同/规则版本、首次幂等身份、已验证事实代次、服务身份、场景标记属性类型、直接父场景关系类型、直接成员关系类型和世界根场景逐字段不变。五个稳定编码非零且互异，已验证事实代次非零。

本入口不读取 L1，因此不返回当前事实截止，不校准登记缓存与当前事实，也不产生 `事实代次漂移`。后继必须在 P17 快照中逐项互证登记身份及其当前类型/生命周期，并把 P17 快照代次作为领域结果截止。

## 6. 状态、异常与生命周期矩阵

| 条件 | 状态 | 登记载荷 | 副作用 |
| --- | --- | --- | --- |
| 合同或规则版本错 | `入口拒绝` | 空 | 锁尝试0 |
| 锁竞争 | `许可拒绝` | 空 | 零等待、零重试 |
| 登记未加载 | `登记未加载` | 空 | 不扫描、不补造 |
| 登记缓存不完整 | `内部不一致` | 空 | 不返回部分登记 |
| 完整登记 | `已读取` | 完整副本 | 零写入 |
| 复制分配失败 | `资源失败` | 空 | 零写入 |
| 其它异常 | `内部不一致` | 空 | 零写入 |

`幂等冲突`、`事实代次漂移` 不是本读取入口的输出分支。`已验证事实代次` 在登记建立后不可变，只证明这些定位身份曾在该代次完成建立后读回；后续世界事实推进不更新它。调用方不得把它用于 G0/G1、排序、当前性或漂移裁决。

新服务实例若没有经正式恢复装载登记，固定返回 `登记未加载`。本叶不新增恢复装载、扫描恢复、SQL 回源或默认登记。

## 7. 并发、自检与确定性

- `建立空世界` 和既有阻塞读取持锁时，新入口立即许可拒绝；
- 多个新读取同时竞争普通 `std::mutex` 时至多一个取得许可，其余允许许可拒绝；调用方不得要求所有并发读都成功；
- 新入口无内部重试；后继 4200 的一次整轮漂移重试不适用于登记许可拒绝；
- Debug 自检通过仅测试用同步屏障稳定持有 `锁_`，不得导出生产锁、令牌或可写登记；
- 相同登记重复成功读取逐字段相等，不依赖容器顺序、显示名、时间戳或地址。
