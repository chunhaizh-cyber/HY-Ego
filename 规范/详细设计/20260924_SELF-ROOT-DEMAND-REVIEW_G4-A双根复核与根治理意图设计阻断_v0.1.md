## 1. 当前结论

G4-A 的 RC 定义、系统初始化、稳定定位、双 K、预算自由版本 2 完整读取链和 4242 二次关系求值器已经形成并发布；旧的“缺 RC / K / 求值器 / 无预算读取能力”阻断全部关闭。

当前最早阻断已经收敛为一个不能由现行规范和代码自行裁决的机器语义问题：

```text
双根目标 M = I64_MAX
目前只作为需求根目标合同中的正式目标值存在

4242 求值器
目前只接受准确 F 或状态使用绑定 B 作为两侧来源

因此：M 不是现行 4242 可以消费的合法操作数
```

在该问题经用户裁决并正式进入规范前，不能建立 G4-A 双根业务复核 provider 的可执行代码计划，更不能把根治理意图 sink / manager 与其合并成一个伪闭环计划。`计划/计划索引.md`继续保持当前为空。

本文件只记录设计阻断和最小裁决问题，不修改正式规范、计划索引、代码、目标账或流程图。

## 3. 当前首阻断：根目标 M 没有 4242 合法来源

### 3.1 正式目标和当前值属于两种不同材料

6120 固定：

```text
M = I64_MAX
安全根目标：A == M
服务根目标：V == M
Δsafe = M - A
Δservice = M - V
```

阶段 21 和需求 owner 目前分别保存：

- 当前值：唯一 self 对应根 FT 的当前采用准确 F；
- 目标：独立根需求 D 所引用的目标合同节点、目标值事实和 `目标I64值=I64_MAX`。

现行`本能根材料`也明确把`实际特征`与`根目标合同 / 目标值 / 目标I64值`分开。目标值事实不是准确 F，不是状态 S，更不是状态使用绑定 B。

### 3.2 4242 输入联合不接受目标合同值

4242 v0.6 第 7 节当前只定义：

```cpp
二次关系准确F来源
二次关系状态端点来源
using 二次关系特征来源 = variant<F来源, B来源>;
```

两侧参与者材料只能由上述 F / B 来源组成。求值器固定物理左为 B、右为 A，计算`difference(B,A)=A-B`，并要求两侧均完成 FT、FC、EC、K、参与存在、来源和截止互证。

要表达根正差距，当前 F 可以作为物理左侧，但目标 `M`必须成为物理右侧。现行公开 DTO、读取服务和来源互证算法没有任何分支可以把需求目标合同值合法放入右侧。

4151 同时明确：目标常量也必须具有正式目标 / 类型来源，不能用裸 I64、便利参数或上轮缓存绕过事实读取。故不能仅把`I64_MAX`写入局部变量后交给比较器。

### 3.3 下列“实现捷径”全部非法

1. 把根当前 F 同时作为 A、B：实际计算的是`current-current=0`，不是`M-current`。
2. 把目标值事实强转、别名或包装成准确 F：目标值没有 1130 / 4110 的 F 身份、宿主当前采用和完整准确 F 闭包。
3. 为目标临时制造状态或 B：这会伪造一次不存在的世界观察，并改变状态 / 场景事实语义。
4. 在 root provider 内直接写`M-current`：这复制 4242 / 4182 的比较算法，绕过已登记 RC、固定 K、FC / EC 和来源后置校验。
5. 直接调用底层 I64 比较器：self 或根复核 provider不能以基础计算成功代替 8100 / 6120 要求的已登记 RC 求值。
6. 让消息、启动缓存或 RC 初始化交付携带裸 M：它们不是目标事实 owner，也不能取得正式来源资格。

因此，这不是普通 DTO 适配或代码错误，而是现行 4242 来源联合无法表达已由 6120 固定的合法业务操作数。

## 4. 必须由用户裁决的两种方案

### 4.1 方案 A：新增强类型目标合同值来源（推荐）

在 4151 / 4242 中增加一个与 F、B并列但不混义的强类型来源分支，使求值器能够通过正式 provider 核验：

```text
根需求 D
+ 目标合同身份
+ 目标值事实身份
+ 正式 FT / 值解释
+ Gread / H
+ 需求 owner 的完整读回见证
= 可供本次 RC 求值使用的目标合同值来源
```

推荐理由：

- 保持目标仍是需求目标，不把它伪装成已经发生的世界事实；
- 不新建 F、状态或 B，不改变 self 当前采用；
- 可以继续由同一个 4242 求值器完成固定 K、FC / EC、D 域及实际差异计算；
- 目标值来源的合法性由需求 owner 正式读回证明，而不是信任调用方裸 I64；
- 本次结果仍为调用期临时材料，零持久二次实例写入。

若用户选择本方案，正式规范至少必须进一步冻结：目标来源 DTO 的精确字段；唯一读取 provider；目标 FT 的证明方式；`Gread/H`映射；与 RC 两侧角色的绑定；成功载荷见证；未找到、退出、漂移、目标合同不完整、FT 不相容、资源失败和内部不一致的映射；以及 4242 构造依赖和现有四个消费者的同次迁移范围。

这些内容会改变 4242 的公开来源联合和求值 ABI，必须先经用户确认和正式规范修订，不能由代码计划临场决定。

### 4.2 方案 B：把目标物理化为准确 F 或状态 B（不推荐）

另一路线是为每个根目标建立可由 4242 直接消费的准确 F，或建立状态 / B来源。

该方案会实质改变当前机器语义：

- 需求目标将部分进入世界事实体系；
- 必须定义目标 F 的宿主、当前采用、生命周期、是否可变化及与根目标合同的唯一性；
- 若使用 B，还必须定义不存在现实观察时为何可形成状态、场景、主体和强时间；
- 5170、6120、8121及特征 / 状态边界均需重新裁决；
- 容易把“想要达到的目标”混成“已经观察到的事实”。

除非用户明确希望改变需求目标与世界事实的边界，否则不得采用本方案。

## 5. 后继 DTO 仍需在目标来源裁决后冻结

现行`线程_自我.h`中的预冻结根复核合同仍不满足正式语义：

- `自我线程根当前满足状态`只有`满足 / 未满足`，不能区分`正差距 / 方向相反`；
- `自我线程根复核读取预算_v1`仍保存已退出的物理数量预算；
- 单根投影没有 RC、K、当前值、目标值、准确差异和求值见证；
- 外部调用状态没有把 4242 的证据不足、规则不支持、历史材料不可用、运算溢出、退役不可用、类型 / 单位 / 参照不相容逐项映射；
- 结果成功谓词尚不能核验两根互不交叉、同一共同截止和业务分支与 RC 判断一致。

这些缺口可以在方案 A 或 B 正式冻结后唯一推导；在目标来源未知时先改 DTO，会迫使执行者猜测来源、失败状态和成功载荷，因此仍不得建立 G4-A provider 代码计划。

后继每根成功业务分支仍必须至少区分：

```text
当前满足
正差距
方向相反
```

不可比较、材料不足、当前性漂移和内部不一致继续属于具名技术或来源非成功，不得混入上述三种业务分支。每次合法触发仍完整复核双根；安全根 / 服务根触发只作唤醒定位，不裁剪结果范围。

## 6. sink / manager 仍是独立后继阻断

即使目标来源得到裁决并完成 G4-A provider，当前代码仍没有满足 5260 / 8100 的正式根治理意图消费方：

- 没有任务管理线程生产类；
- 没有按根列表项读取`0..1`当前同目标任务的上层应用入口；
- 没有原子建立`T + T→L + T→D + Vt + R1 + 首态`并分段形成 P1 / 首迁移的完整 task owner 接口；
- 没有建立、唤醒、复用与完成 / 失败 / 取消任务隔离的 manager 结果合同；
- 没有不可变根治理意图 DTO、异步交接、独立读回和恢复合同。

现行`数据服务.任务类.h`中的基础任务记录、任务虚拟存在和方法关系能力不能冒充上述应用面 / manager 闭环。self也不得直接下钻该数据服务建立任务。

因此，sink / manager 必须以后继真实消费者需求另行形成设计和代码计划。不能用只返回成功的进程内回调、空队列或日志代替，也不能在 G4-A provider 计划中伪造任务创建成功。

## 7. 阻断解除顺序

1. 用户裁决第 4 节目标合同值进入求值器的正式来源方案。
2. 规范治理角色按裁决修订 4151 / 4242及受影响直接转引，冻结公开 ABI、owner、依赖方向、失败映射和迁移边界。
3. 计划智能体基于届时正式 HEAD 形成最早可施工的“目标合同值来源与 4242 求值适配”代码叶；若规范裁决使现有求值器无需独立提供者变更，则直接形成 G4-A 双根复核 provider 代码叶。
4. provider 完成后，依据真实`正差距`载荷形成根治理意图 DTO 和 task owner / manager 最小提供者计划。
5. 上述完成仍不开放治理运行门。G2-B必须另行证明任务管理线程、工作线程池及其它 8120 要求的生产者 / 消费者均已真实就绪，再由独立步骤开门。

同一依赖链在当前没有可执行计划，也不登记多层`待激活`库存。
