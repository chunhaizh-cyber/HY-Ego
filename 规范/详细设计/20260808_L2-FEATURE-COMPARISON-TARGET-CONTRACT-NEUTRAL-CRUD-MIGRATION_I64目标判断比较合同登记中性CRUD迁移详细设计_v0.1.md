## 3. 公开合同、缓存和共享边界

### 3.1 公开合同保持不变

```cpp

    const I64目标判断比较合同登记请求& 请求);
I64目标判断比较合同结果 读取I64目标判断比较合同(
    const I64目标判断比较合同读取请求& 请求) const;
```

两类请求、`I64目标判断比较合同`、结果 DTO、`特征比较状态`、`比较拒绝原因`、构造和可见性全部不变。幂等域数值继续为 `0x09`；M03 的 `0x0E` 不变。

### 3.2 缓存语义

- `合同请求_`：保存首次成功的完整公开登记请求，只在同一服务对象生命周期内裁决同键完整业务请求同义 / 异义；不是 L1 事实，也不能跳过成功类权威读回。
- `合同_`：保存首次合同的稳定编码、上游值见证和边界值，用于重建相同中性写集、合法当前读取和既有运行比较定位；`事实截止代次` 每次成功读取后取本次 G0，缓存旧截止不权威。
- `登记_`：继续由 M01 管理；M02 新请求路径必须调用公开 `读取当前登记()`，不能直接把缓存当权威。精确重复路径可以用已核对一致的 `登记_ + 合同请求_ + 合同_` 重建首次中性写集，但返回前仍须调用当前精确读回。

缓存必须成组：`合同请求_` 与 `合同_` 只允许同时为空或同时完整。仅一项存在、已有完整请求相同但合同 / M01 定位不完整、首次提交却已有缓存、精确重复却无同义完整缓存均为 `内部不一致`。这保留当前服务对象生命周期边界，并防止 L1 的物理写集相等被误升格为未经领域证明的完整业务请求同义。

新增一个私有 `mutable std::mutex 目标判断合同锁_`，只串行保护 M02 登记与公开当前读取的整段业务操作。两条 M02 公开根先取得该锁，再按需短暂取得现有 `锁_` 复制或更新共享缓存；M01、M03 和运行比较不取得新锁。固定锁序只有“目标判断合同锁_ -> 现有锁_”，不存在反向取得。这样同义并发的第二请求只能在首次请求完成缓存发布后进入精确重复路径，不会把合法同义竞争误报为缓存缺失的内部不一致；同时 M02 可在不持有现有锁的阶段安全调用会自行取得现有锁的 `读取当前登记()`。

## 5. 登记输入的当前读取

首次路径在提交前形成一次完整 L2 输入束；允许因首末代次竞争完整重试一次，仍不一致才返回 `版本漂移/输入版本失效`：

1. 调用 M01 `读取当前登记()`，要求 `已比较`、登记完整。
2. 读取中性当前事实代次 G0。
3. 精确读取当前代码实际要求的定义节点、标记值、下界值、上界值和八关系目标节点。所有读取必须合同正确、回显一致、事实存在、未退出且读取代次等于 G0。
4. 标记 / 下界 / 上界值必须属于请求特征定义；属性类型分别等于请求定义登记的标记 / 下界 / 上界类型；来源等于定义登记服务；标记 I64=1，下界和上界为 I64 且下界不大于上界。
5. 再读 G1；要求 M01 登记事实截止、G0、全部读取代次、G1 相同。若仅因并发不一致，重做第 1—5 步一次；第二次仍漂移返回版本漂移，不返回混代输入。
6. G0 只作为首次成功一致性诊断和合同见证，**不得因 `G0 != 请求.期望事实代次` 在提交前提前返回**。新键旧期望、提交前竞争和精确重复最终由 L1 顺序裁决。

请求的定义登记和实例登记仍按既有 `请求基础有效` 校验完整；本叶不扩张为验证两个上游登记 DTO 的所有字段当前性，也不新增跨领域 provider。

## 6. `登记I64目标判断比较合同` 唯一控制流

1. 进入现有异常边界并取得 `目标判断合同锁_`，校验 `请求基础有效`；失败保持当前默认 `入口拒绝/无`、零 L1 调用。
2. 在短锁内读取缓存组：
   - 缓存半结构：`内部不一致`；
   - 已有完整请求与本次不同：`入口拒绝/注册不唯一`，零 L1 调用；
   - 已有完整请求与本次相同：复制 `合同请求_`、`合同_` 和 `登记_`，按 §4 重建首次完整中性写集，不读 provider，不用当前代次提前阻断；标记为预期精确重复路径；
   - 缓存全空：执行 §5，形成首次合同见证和固定中性写集；标记为预期首次路径。
3. 每个合法且可形成完整写集的请求恰一次调用 `提交中性写集`；不调用 `探测幂等`，不形成 G8 凭证，不传业务标签。
4. 非成功优先按 §8 映射；不得以缓存或预读覆盖 L1 最终状态。
5. 成功类核对合同版本、回显幂等键、非零首次发布代次和十项映射完整唯一：
   - `成功` 只允许首次路径，要求登记输入 G0 等于请求期望、发布标志 true、重试边界 `不适用`；
   - `精确重复` 只允许已有同义完整缓存路径，要求发布标志 false、重试边界 `原幂等键读回收敛`；
   - 路径与结果种类矛盾均为 `内部不一致`。
6. 从本地键 1、2 取得注册与配置编码；其余八映射只用于完整唯一和共同创建代次核对。形成 `I64目标判断比较合同` 见证：稳定字段按 §4 与当前公开 DTO 组装，定义标记 / 下界 / 上界值身份取原请求，下界 / 上界材料取首次输入或同义缓存。
7. 调用 §7 中性精确当前读回；只有完整成功才进入短锁更新缓存。已有缓存必须与本次完整请求及稳定合同定位一致，否则 `内部不一致`。
8. 成功与精确重复统一返回 `已比较/无` 和本次当前读回合同。
9. `std::bad_alloc` 返回 `资源失败/无`；其它异常返回 `内部不一致/无`。

这种顺序保证同一服务对象的原请求精确重复无需再次读取上游 provider 就能到达 L1；同时禁止把 L1 物理写集相等单独解释为完整业务请求同义。当前阶段不为第二服务对象、重启或跨进程恢复补造业务幂等证据。

## 7. 目标判断合同中性精确当前读回

建立登记与公开读取共享一个私有 helper。它接收 M01 登记定位、完整目标判断合同见证和可选首次创建代次，允许因并发首末漂移完整重试一次：

1. 读取 G0。
2. 精确读取注册节点和配置值；读取注册节点的合同配置当前属性；按注册节点 + 合同字段关系类型调用 `读取中性当前源关系组`。
3. 精确读取八个关系目标节点和定义标记 / 下界 / 上界值；重复目标编码可去重读取，但逻辑角色仍恰八项。
4. 所有结果要求合同正确、查询字段回显一致、读取代次等于 G0、事实存在且未退出。注册节点为普通；配置值所属注册、类型 / 来源符合 M01 登记、材料精确等于 §4.2；当前属性唯一指向配置值。
5. 源关系组必须恰八项，关系均当前有效、源为注册、类型正确、角色 1—8 各一且目标逐项等于 §4.3；不得接受额外同源同类型关系。
6. 注册节点、配置值和八关系的创建代次非零且相同；建立登记传入首次发布代次时还必须等于写入结果代次。
