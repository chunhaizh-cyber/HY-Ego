# SELF-CONTEXT-PRE-GATE-BINDING 停门状态正式上下文端口预绑定详细设计

版本：v0.1

对应目标：`GOAL-SELF-GOVERNANCE-CLOSURE`

## 1. 目标和完成边界

本设计闭合 G2-A 已发布正式上下文 provider 到唯一 self 线程对象之间最小、纯工程性的预绑定缺口。普通应用在创建 self 物理线程时，把其唯一持有的 `自我线程正式上下文提供者` 作为现行抽象端口 `自我线程正式上下文端口&` 交给 self；self 在首次合法创建选择中原子锁定该端口地址，但本叶绝不调用端口。

本叶完成后只可证明：

1. self 的一次性物理创建选择同时锁定值式创建请求和一项非拥有正式上下文端口依赖；
2. 普通应用传入自己唯一持有、且寿命长于 self 的 G2-A provider；
3. 相同请求加同一端口重复调用精确复用原停门见证；不同请求或不同端口地址形成选择冲突；
4. 治理运行门保持关闭，邮箱只入队不出队，冻结批次数和成功治理批次数保持零；
5. 创建、重复、冲突、开门占位、消息排队、停止和析构路径对正式上下文端口的调用次数均为零。

本叶不证明 self 已经消费 fresh 正式上下文，不证明 G3 消息循环、G4-A 双根复核、RC 求值、根治理意图 sink、任务管理/工作线程或治理门开放。预绑定成功不能解除任何后继门禁。

## 3. 分层、所有权和依赖方向

依赖方向固定为：

```text
普通应用上下文
  ├─ 唯一持有 自我线程正式上下文提供者
  └─ 唯一持有 自我线程
          └─ 非拥有保存 自我线程正式上下文端口*
```

`自我线程正式上下文端口` 仍由 `线程_自我.h` 声明；provider 实现仍位于业务应用层。self 不 include provider 具体类型，不 include DATA-L1/DATA-L2，不取得 provider 所依赖服务的所有权。

普通应用上下文中的成员声明顺序保持：provider 在 self 之前。C++ 反向析构保证 self 先停止并析构，provider 后销毁；provider 的世界、自我、需求和方法服务继续晚于 provider 销毁。端口地址只能在 self 存活期间指向该同一对象，普通应用不得重置或替换已经绑定的 provider。

端口是进程内非拥有工程依赖：

- 不进入 `自我线程创建请求_v1`；
- 不参与 self 的业务身份、业务幂等、消息正文或持久恢复；
- 不编码、记录、输出或持久化地址；
- 仅以进程内对象地址区分同一 self 物理对象的创建选择；
- 重启后由新普通应用上下文重新构造 provider，并建立新的 self 物理租约。

## 4. 公开函数合同

现有创建函数原位改为唯一签名，不保留旧两参数重载或兼容转发：

```cpp
[[nodiscard]] 自我线程创建结果_v1 创建并停在治理运行门(
    const 自我线程创建请求_v1& 请求,
    自我线程正式上下文端口& 正式上下文端口,
    std::uint64_t 等待毫秒) noexcept;
```

参数职责：

| 参数 | 来源 | 作用 | 不属于 |
| --- | --- | --- | --- |
| `请求` | 普通应用本轮正式读回材料与具名邮箱配置 | self 的既有值式创建选择 | provider 身份、读取预算、持久恢复 |
| `正式上下文端口` | 普通应用唯一 G2-A provider 的抽象端口视图 | 本物理 self 的非拥有依赖绑定 | 业务事实、业务幂等、fresh 读回成功 |
| `等待毫秒` | 普通应用具名运行配置 | 等待线程进入停门的调用方工程时限 | 创建选择、业务事实 |

引用形态使空端口在类型上不可表达，不新增“空端口”状态。调用方若没有 provider，不得调用本函数；普通应用现有包装入口应在调用前检查 provider 存在，缺失继续返回现有入口拒绝形状并保持 self `未创建`。

除上述签名外，不修改任何公开 DTO、枚举、成功谓词或诊断字段。尤其不向 `自我线程诊断快照_v1` 增加“已绑定”字段，不改变合同版本和已退役枚举数值。

## 5. 私有承载和创建选择

`自我线程::实现`只新增一个私有非拥有指针：

```cpp
自我线程正式上下文端口* 正式上下文端口 = nullptr;
```

不得使用 `shared_ptr`、`unique_ptr`、全局变量、线程局部变量、端口注册表或 provider 具体类型替代。不得把地址加入 `创建选择相同` 的值式请求比较；端口地址在创建函数内独立比较。

首次合法创建在 `状态互斥` 保护下原子完成：

```text
校验请求完整
-> 加锁
-> 确认对象尚未尝试创建
-> 同一临界区锁定请求和 &正式上下文端口
-> 标记创建已尝试、生命周期=创建中
-> 建立唯一工作线程
-> 工作线程形成既有停门见证
```

“原子锁定”只指其它并发创建调用不能看到“请求已锁定但端口尚未锁定”或相反的半选择。它不是 L1 事务，也不发布业务事实。

重复与冲突的优先级固定为：

1. 请求不完整：`入口拒绝`，对象保持未创建，端口不锁定。
2. PImpl 分配失败：`资源失败/启动失败`。
3. 已锁存停止或工作线程已完成：保持既有一次性对象规则，返回`入口拒绝`，不因参数相同而重启。
4. 已尝试创建但锁定请求或锁定端口缺失：锁存`内部错误`，不得补写或改绑。
5. 请求不同或 `&正式上下文端口` 不同：`选择冲突`，不改变首次选择。
6. 请求相同、端口地址相同且已有完整停门见证：`精确重复`并返回原见证。
7. 请求相同、端口地址相同但首个线程仍在进入：复用既有等待逻辑；超时返回`等待超时`，不建立第二线程。

首次线程建立失败沿现有一次性对象合同返回`资源失败/启动失败`，保留已尝试创建和首次端口选择，不允许改端口或换请求重启。外层 `bad_alloc/length_error` 映射资源失败，其它异常映射内部错误，均不得调用端口。

## 6. 工作线程、运行门和邮箱不变量

本叶不修改 `自我线程::实现::运行()` 的行为。工作线程仍只完成：进入见证、停门见证、等待独立停止信号、停止完成见证。

以下均保持为零：

- `自我线程正式上下文端口::读取正式上下文` 调用次数；
- `自我线程根需求复核端口::复核双根当前需求` 调用次数；
- 邮箱出队数量；
- 已冻结批次数量；
- 成功治理批次数量；
- 业务事实写入。

`复核前置并开放治理运行门`保持现有签名、注释和实现，继续返回`依赖未就绪`；不得因端口已绑定而读取正式上下文或改变门、生命周期、邮箱和计数。

`提交根需求复核消息`保持现有校验、去重、冲突和队满语义。关闭门期间消息只排队。端口预绑定不允许消费、冻结、拒绝或重排既有合法消息。

`请求停止`、`等待停止`和析构不得解引用、调用、释放或重置外部 provider；它们只执行既有停止锁存、唤醒、完成和 join。self 析构结束后私有指针随 PImpl 一并消失，不执行外部操作。

## 7. 普通应用接线

`创建并停门普通应用自我线程()` 的前置检查新增“`自我线程正式上下文`非空”。其它世界、自我、锚点和配置前置保持不变。缺 provider 时返回现有默认入口拒绝结果，不创建线程，也不尝试临时构造 provider。

唯一生产调用改为：

```cpp
auto created = 上下文->自我线程对象.创建并停在治理运行门(
    request,
    *上下文->自我线程正式上下文,
    已选配置->自我线程进入停门等待毫秒);
```

不得新增普通应用 getter、第二 self、第二 provider、setter、热替换、运行期重绑或新的启动阶段。普通应用现有失败收口继续安全停止并回收已经开始创建的 self；收口不得调用 provider。

## 8. 专项验证和完成条件

`验证工具/自我线程上层骨架专项验证.cpp`定义最小假端口，只实现现行抽象函数并用原子计数记录调用次数。返回值内容不得被本叶消费。专项至少验证：

1. 无效请求带任意合法端口仍入口拒绝、零线程、零端口调用；
2. 完整请求加端口 A 成功进入停门；同请求加同一 A 精确重复且见证不变；
3. 同请求加端口 B 为选择冲突；不同请求加端口 A 为选择冲突；
4. 多线程用同请求和同一 A 并发，恰一成功，其余精确重复，见证一致；
5. 多线程用同请求和不同端口竞争，只有首次选择可以成功/精确重复，异端口均为选择冲突，不形成第二线程；
6. 调用开放门占位两次仍为依赖未就绪，门关闭；
7. 消息入队、精确重复、异义冲突、队满、停止、等待和析构保持原行为；
8. 上述全部阶段，所有假端口调用计数均为零；
9. 停止后同请求/同端口、异请求或异端口调用都按既有一次性对象规则入口拒绝；
10. 无新诊断字段、无 provider 实现修改、无 `读取正式上下文` 或`复核双根当前需求`生产调用进入 `线程_自我.cpp`。

专项 Debug/Release 均须构建并运行通过；根工程 Debug/Release x64 隔离 Rebuild 均须零错误。验证只证明端口预绑定、选择规则、寿命顺序和零调用停门边界，不证明 fresh 上下文已被 self 消费、消息循环或治理门可用。
