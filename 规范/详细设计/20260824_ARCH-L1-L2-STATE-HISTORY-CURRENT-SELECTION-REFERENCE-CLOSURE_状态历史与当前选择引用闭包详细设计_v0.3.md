## 1. 目标、边界与本版裁决

本版在同一 ARCH-L1/L2 状态—动态原子发布目标内，把永久状态事实、当前选择关系、两参与者引用闭包和 L4 消费所需的公开证据冻结为可施工合同。通用 L2 状态仍是唯一状态权威，现实与虚拟存在均由 L2 动态承载；L3/L4 不取得第二写入权。

本叶不处理任务、方法、需求、授权、安全、配额、轮次、工作包持久化、普通应用装配、崩溃/重启/跨进程恢复或生产消费者接线。当前业务工作包不含选择关系证据；是否纳入工作包完整性由底座发布后的独立 L4 计划支撑事项处理，本叶不得宣称已闭合。

唯一裁决如下：

1. 既有状态类型登记 v1 的十项身份和本地键原样保留，不把它沿旧登记 DTO 扩成第十一项。
2. 当前选择关系使用独立 v2 登记 DTO/幂等域；关系方向固定为 `L2特征实例 -> L2状态`，由状态 owner 持有。
3. 状态新增与状态动态迁移共享一个专用 `L2状态当前选择操作状态` 枚举；它不是 L4 业务枚举，公共 `L2结构结果头` 仍负责通用结构结果。
4. 公开生产顺序仍为状态 owner 后动态 owner；逆序只经仓库外专项接缝验证，不能由静态阅读代替。
5. 迁移成功后的唯一当前性权威是具名当前选择读取；按特征实例读取全部当前状态仅保留为兼容包装/辅助视图。

## 3. 当前选择类型 v2 登记与持久身份

### 3.1 v1 不变

v1 登记规则版本 `1`、幂等域 `0x20`、十项既有身份和其本地键全部原样保留：主体关系 `0x02040101`、特征实例关系 `0x02040102`、精确值 `0x02040201..04`、时间值 `0x02040301..04`。v1 仓库/账不可重写为十一项；旧 v1 读回仍按原十项验证。

### 3.2 独立 v2 登记

现有登记域 `0x20`（状态）、`0x21`（动态）和 `0x22`（因果）均已占用；新增具名 `L2状态当前选择关系类型登记`，规则版本 `2`，幂等域固定为当前唯一未占用的 `0x23`，登记请求的公开字段顺序固定为：

```text
L2结构请求头 请求头
uint32_t 规则版本                 // 只能为 2
L2结构幂等身份 幂等身份           // 只能属于域 0x23
稳定编码 关系类型稳定编码         // 首次为空，结果填充
L1所有者范围写集本地键 局部写入键  // 固定 0x02040103，非零
uint8_t 源端点角色                 // 固定“特征实例”角色值
uint8_t 目标端点角色               // 固定“状态”角色值
```

首次登记时“关系类型稳定编码”必须且只能为零，由结果填充并持久化；重复/读取请求必须带已发布的非零编码且逐字相等。除这一明确的首次零值例外，缺字段、其它默认零值、规则版本非 2、幂等域错误、端点角色错误或局部键不为 `0x02040103` 均为入口拒绝，零载荷、零写、零代次。首次登记只发布一次稳定关系类型身份；精确重复须返回同一稳定身份和同一登记截止；同一幂等身份材料不同为幂等冲突；G0、许可、资源和恢复读回失败保持专用分账，不自动改写 v1。

持久身份映射固定为：

```text
关系类型登记身份 = {域 0x23, 本地键 0x02040103}
关系类型稳定编码 = (uint64_t(0x23) << 56) | uint64_t(0x02040103)
当前选择关系写集局部键 = 0x02041103
```

稳定关系方向和材料固定为 `特征实例身份 -> 状态身份`、状态端点角色、状态 owner、首次登记事实代次和合同版本 `2`。不存在独立适用范围身份；适用范围仍等同特征实例。节点是中性身份锚点，不等同 owner；不能用局部键、关系引用或关系属性把节点冒充 owner。

## 4. 请求、结果与操作状态 ABI

### 4.1 首态新增请求

现有 `服务.L2状态结构::新增状态` 是唯一首态入口。其请求字段顺序冻结为现有七字段后追加两个字段：

```text
L2结构请求头 请求头
L2结构幂等身份 幂等身份
L2存在身份 主体存在
L2特征实例身份 特征实例
L2原始值材料 精确值材料
L2原始值材料 时间值材料
稳定编码 来源稳定编码
L1所有者范围写集本地键 当前选择关系局部写入键
L2状态当前选择幂等材料 当前选择关系幂等材料
```

`L2状态当前选择幂等材料` 的字段顺序为 `规则版本、关系类型稳定编码、特征实例身份、源端点角色、目标端点角色`；其关系类型必须是 v2 登记结果，特征实例必须等于请求第三字段，角色必须是固定值。缺省、零值、重复不一致、非 v2 身份或无法在同一 G0 与状态材料互证均入口拒绝，严禁由服务默认生成选择关系材料。

该材料的公开强类型定义冻结为：

```text
uint32_t 规则版本
稳定编码 关系类型稳定编码
L2特征实例身份 特征实例
uint8_t 源端点角色
uint8_t 目标端点角色
```

### 4.2 状态写入结果

`L2状态写入结果` 字段顺序冻结为：

```text
L2结构结果头 结果头
L2状态当前选择操作状态 当前选择操作状态
optional<L2状态事实> 状态
optional<L2状态自有关系引用> 自有关系
optional<L2状态当前选择关系引用> 当前选择关系
```

首次和精确重复必须同时返回完整状态事实、自有关系和完整当前选择关系引用；操作状态分别为 `已提交`、`精确重复`。成功谓词为：公共头状态是 `已提交` 或 `精确重复`、操作状态相同、三份载荷非空、变更/事实截止一致，并且独立读取状态、当前选择和宿主—主体互证全部通过。任何只返回状态或只返回选择关系都不是成功。

### 4.3 状态动态迁移结果

`L2状态动态原子发布结果` 保持现有字段顺序，在通用结果头后追加选择证据：

```text
L2结构结果头 结果头
optional<L2状态事实> 新状态
optional<L2状态自有关系引用> 新状态自有关系
optional<L2动态事实> 新动态
optional<L2动态自有关系引用> 新动态自有关系
optional<L2状态自有关系退出投影> 已退出旧状态关系
L2状态当前选择操作状态 当前选择操作状态
optional<L2状态当前选择关系引用> 新当前选择关系
optional<L2状态当前选择关系退出投影> 已退出旧当前选择关系
```

生产迁移一次提交：退出旧选择、建立新永久状态/新选择、动态前态指向旧状态、动态后态指向新状态；所有结果在共同截止返回。成功谓词要求公共头 `已提交`/`精确重复` 与操作状态一致，且新选择、旧选择退出、状态、动态载荷完整且同截止互证。

### 4.4 共享专用操作状态及公共头优先级

`L2状态当前选择操作状态 : uint8_t` 固定数值如下，状态新增、状态动态迁移和当前选择读取共用，不占用任何 L4 业务枚举：

```text
已提交=1, 精确重复=2, 已读取=3, 待迁移=4, 已有异义当前=5,
已可能发布=6, 发布未知=7, 入口拒绝=8, 许可拒绝=9,
事实代次漂移=10, 幂等冲突=11, 引用冲突=12,
资源失败=13, 内部不一致=14
```

组合优先级固定为“交换后事实不确定 > 交换前候选失败 > 成功/重复”：

| 操作状态 | 公共 `L2结构结果头.状态` | 载荷 | 说明 |
| --- | --- | --- | --- |
| 已提交/精确重复 | 同名已提交/精确重复 | 完整成功载荷 | 仅此组合可进入成功谓词 |
| 已读取 | 已读取 | 当前选择载荷 | 仅独立读取使用 |
| 待迁移 | 入口拒绝 | 零载荷 | 选择关系缺失；不等于 task owner v1 请求迁移 |
| 已有异义当前 | 引用冲突 | 零载荷 | 特征实例已有不同当前状态 |
| 已可能发布/发布未知 | 内部不一致 | 已有载荷可保留，禁止声称零写 | 交换后读回失败，不回滚 |
| 入口/许可/代次/幂等/引用/资源/内部 | 同名公共状态 | 零载荷 | 不得同时给出矛盾状态 |

公共头与操作状态必须按表成对生成；禁止例如“公共成功+操作待迁移”或“公共资源失败+操作已提交”。

## 5. 独立当前选择读取与 L4 消费

公开请求字段顺序固定为：`L2结构请求头 请求头、L2读取类别 读取类别、L2特征实例身份 特征实例、uint64_t 历史截止事实代次`。公开结果字段顺序固定为：`L2结构结果头 结果头、L2状态当前选择操作状态 当前选择操作状态、L2读取类别 读取类别、uint64_t 历史截止事实代次、optional<L2状态当前选择关系引用> 当前选择`。当前读取最多一条选择关系；重复、端点失效或状态身份不一致返回公共 `内部不一致` + 操作 `内部不一致`。历史读取按指定截止读取，不推断当前性。

迁移成功后，L4 唯一权威互证入口是该具名当前选择读取；按特征实例读取全部当前状态只作为迁移兼容包装/辅助视图，不能裁决当前性。P1/A1 只需持久化首态状态身份；恢复时用特征实例当前选择读取取得选择关系，再与保存的状态身份互证，不持久化第二选择身份。

L4 四类操作状态语义映射固定为：

- `待迁移`：底座旧状态事实缺当前选择，停止当前工作包并提交底座迁移事项；严禁映射为需求层现有“初次请求版本待迁移=15”，后者专指 task owner 历史 v1 八槽请求。
- `已有异义当前`：当前性冲突，保留零写，转人工/计划冲突处理；不得重试或把它当新状态。
- `已可能发布`：交换已发生但独立读回失败，使用同一幂等键重放并正式读回；在收束前不得进入业务成功。
- `发布未知`：发布事实未知，执行同样的同键重放和独立读回；不得新建工作包、猜测漂移或映射为业务成功。

本叶不新增、复用或改写 L4 业务枚举；四类结果的 L4 工作包完整性登记由底座发布后的独立计划支撑事项完成。

`TASK-ROUND-INITIAL-STATE-ARCH-L2-MIGRATION v0.3` 继续待激活，不因本叶发布自动转为可执行。其既有“不得改变 ARCH-L1/L2/L3 ABI、工作包不含当前选择证据”口径与本版公开 ABI 不兼容；底座返还后由 L4 所有者在同一计划身份形成 v0.4，冻结字段顺序、专用结果映射、首态/迁移选择证据和工作包完整性，取得新 plan blob 后才可登记。

## 6. 原子顺序、闭包、幂等与失败

生产顺序固定为状态 owner → 动态 owner。交换前按 G0 校验、复制候选、应用两侧写集、解析稳定局部引用、统一事实代次、检查全局引用闭包、写幂等账、交换正式仓库；候选失败均零载荷、零写、零代次、不写幂等账。精确重复只返回首次闭合结果。

逆序验证不改生产 ABI：在 `海中鱼巣/核心/仓库.L1事实基座.ixx` 仅增加内部顺序无关 helper，由 `D:\TEMP\ARCH-L1-L2-STATE-HISTORY-CURRENT-SELECTION-REFERENCE-CLOSURE\` 专项 harness 以显式参与者序号调用；该接缝不进生产工程、DTO、运行包或普通应用。动态→状态矩阵必须实际调用该 helper，不能用静态阅读替代。

交换后独立读回故障不进入生产合同。专项 harness 在交换完成与公开读回之间替换公开读回提供者；若替身无法机械形成，则只做静态+同键重放证据并收窄完成声明，执行者不得自行添加生产测试钩子。读回失败映射为 `已可能发布` 或 `发布未知`，不回滚、不宣称零写，保留幂等账和事实代次。
