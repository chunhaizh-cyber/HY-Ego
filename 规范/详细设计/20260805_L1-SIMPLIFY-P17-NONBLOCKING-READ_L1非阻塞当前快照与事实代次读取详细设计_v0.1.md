# L1-SIMPLIFY-P17-NONBLOCKING-READ L1 非阻塞当前快照与事实代次读取详细设计 v0.1

## 1. 身份、目标与完成边界

计划身份：`L1-SIMPLIFY-P17-NONBLOCKING-READ`

版本：`v0.1`

创建侧正式代码基线：`fe0a894a2cf927c9354624ccd241dca4018b9cd1`

本叶是 SELF-GOV-CLOSURE STEP-4 的最早前置叶，只补齐新 L1 在一次非阻塞共享许可内形成当前完整快照副本和当前事实代次见证的通用中性读取能力。它不读取或解释世界、场景、存在、特征、关系19或关系20语义。

完成必须同时成立：

- 公开、版本化、纯值式 `尝试读取完整快照` 和 `尝试读取当前事实代次` 已形成真实成功行为；
- 两个入口均只尝试取得一次 L1 共享许可，竞争时立即返回 `许可拒绝`，不等待、不 sleep、不重试；
- 快照和代次均来自取得许可后同一权威内存状态，代次读取非零才成功；
- 完整快照投影复用唯一私有投影实现，不建立第二事实仓、旁路索引或第二套快照解释逻辑；
- 资源失败、隔离、状态损坏和异常均结构化分账；
- 当前阻塞式 `读取完整快照` 的既有调用语义不在本叶迁移，STEP-4 后继只能消费本叶非阻塞入口。

本叶不形成指定根世界结构、不形成完整世界快照或统一世界门面，也不证明 P7—P16 已实现。

## 5. 唯一读取算法

### 5.1 公共前置校验

服务先校验请求合同版本等于 P15 v0.2 实际 `L1事实基座合同版本`。错误返回 `入口拒绝`、代次0、空载荷，仓库调用为0。

### 5.2 `尝试读取完整快照`

仓库固定执行：

1. 用 `std::shared_lock<std::shared_mutex>{锁_, std::try_to_lock}` 只尝试一次共享许可；
2. 未取得许可立即返回 `许可拒绝`、空快照；不等待、不 sleep、不循环；
3. 已隔离返回 `内部不一致`、空快照；只读入口不得解除隔离或写失败见证；
4. 校验当前权威状态满足 P15 v0.2 的状态完整性；损坏返回 `内部不一致`，不得投影部分材料；
5. 在仍持许可时调用唯一私有 `形成完整快照副本`，复制当前节点、关系、值、永久占用编码和当前事实代次；
6. 按稳定编码升序排序四组；不依赖 unordered 容器迭代序；
7. 完整副本形成后返回 `成功`，函数退出释放许可。空 L1 的代次0快照允许作为通用中性成功，领域服务不得把它发布为 4200 世界快照成功。

现有阻塞式 `读取完整快照` 与新函数必须复用同一 `形成完整快照副本` 私有实现；本叶不删除或改写其阻塞兼容语义，也不要求旧调用点迁移。

### 5.3 `尝试读取当前事实代次`

仓库以同样的一次 try-lock 取得共享许可，校验隔离和状态完整性，只复制 `状态_.事实代次`：

- 非零：`成功` + 非零 `事实截止代次`；
- 零：`未找到` + 0，表示尚无任何已发布事实，不能作为 4200 世界快照截止；
- 竞争：`许可拒绝` + 0；
- 隔离或损坏：`内部不一致` + 0。

它不先形成完整快照，不返回缓存登记代次、运行期纪元、许可序号、时间戳或仓库高水位。

## 6. 状态、异常和生命周期矩阵

| 条件 | 快照结果 | 代次结果 | 写入/重试 |
| --- | --- | --- | --- |
| 合同版本错 | `入口拒绝`、空 | `入口拒绝`、0 | 无 |
| 共享许可竞争 | `许可拒绝`、空 | `许可拒绝`、0 | 无等待、无内部重试 |
| 隔离已成立 | `内部不一致`、空 | `内部不一致`、0 | 不恢复、不解除隔离 |
| 状态损坏 | `内部不一致`、空 | `内部不一致`、0 | 不返回部分材料 |
| 空初始 L1 | `成功`、代次0完整空副本 | `未找到`、0 | 无 |
| 正常已发布状态 | `成功`、完整副本 | `成功`、非零代次 | 无 |
| 分配失败 | `资源失败`、空 | 不适用 | 无 |
| 其它异常 | `内部不一致`、空 | `内部不一致`、0 | 无 |

`事实代次漂移` 不由单次持锁读取产生；后继 L2 组合器比较多个具名结果时才使用该状态。`已退出`、`属性未设置` 不适用于完整快照或代次入口。任何坏成功（状态成功但载荷缺失、快照代次与权威代次不等、排序不稳定）均由自检视为内部错误，不能由调用方修补。

结果是调用时不可变副本；许可在函数返回前释放。返回后事实可继续推进，因此后继必须使用返回的事实截止代次执行 4200 首末代次校准，不能把副本持有时间误作锁生命周期。

## 7. 线程、隔离与恢复边界

- 多个非阻塞读者可同时成功；与独占写竞争时读者立即 `许可拒绝`；
- 不把许可跨服务传递，不在 provider 之间持锁，不依赖线程编号或容器顺序；
- 本叶不建立 retry；4200 的一次整轮漂移重试属于后继 L2 组合器；许可拒绝不消耗该重试；
- 隔离单调性、失败见证、审计、恢复和双摘要幂等仍由 P15 v0.2 所有；本叶只读，不新增恢复管理入口；
- 精确重复提交、恢复发布或隔离状态改变后，两个入口始终读取当时唯一当前权威状态，不查询 SQL 或旁路账。

## 8. 机械验证矩阵

执行至少验证：

1. 合同版本正确/错误两入口分账；
2. 空初始 L1：快照成功代次0、代次入口未找到0；
3. 建立世界登记后：两入口返回同一非零代次，快照四组稳定排序；
4. 再提交节点、关系、值、属性槽和退出事实后，快照只含当前事实且代次推进；历史不混入；
5. 同一权威状态重复读取逐字段相等，不受插入或 unordered 容器迭代序影响；
6. 两个并发共享读者均可成功；
7. Debug 专项在另一线程持有独占许可，两个入口均立即 `许可拒绝`，耗时门禁证明没有等待或 sleep；释放后恢复成功；
8. Debug 故障注入令状态损坏/隔离，返回内部不一致且零部分载荷；恢复只能走 P15 既有合同；
9. 分配失败映射资源失败，其它异常映射内部不一致；
10. P15 v0.2 双摘要、通用发布后读回、失败隔离与恢复专项不退化；
11. Debug/Release x64 串行 Rebuild、两配置退出式完整自检、strict、MSVC 模块扫描和目标 diff check 全部通过。

测试故障注入只可位于 `#ifdef _DEBUG` 仓库自检辅助中，以同步屏障稳定占用既有锁；不得导出生产锁、令牌或可写状态。
