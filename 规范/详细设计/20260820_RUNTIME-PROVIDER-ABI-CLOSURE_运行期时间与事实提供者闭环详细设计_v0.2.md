# 运行期时间与事实提供者闭环详细设计 v0.2

日期：2026-08-20

计划身份：`RUNTIME-PROVIDER-ABI-CLOSURE`

状态：合并后最终设计；替代同身份 v0.1，并吸收 `RUNTIME-MONOTONIC-TIME-EVIDENCE-PROVIDER v0.1`。

## 1. 来源与目标

当前代码已经在 `服务.完整秒时钟.ixx` 内直接读取 `steady_clock`，并把旧 DTO 集中在 `运行期Provider.数据.h`；路由、自我线程和启动入口已经消费这套临时 ABI。若仍先单独新增单调适配器，会形成一份无人消费的重复时间实现。

本设计改为一个可编译、可运行、可读回的代码闭环：

```text
单调时钟适配器
-> 完整秒服务只消费该适配器
-> 事实版本服务只消费同实例 L2结构聚合
-> 批次路由保存两个提供者的完整值式材料
-> 自我线程临时装配最终提供者
-> 启动入口传入同一结构聚合
-> 合法消费者读回并验证
```

同一提交删除旧共享 DTO 头并迁移全部当前生产调用点，禁止兼容别名、双构造、fallback、第二时间源或半 ABI 提交。

## 2. 当前事实与边界

代码基线 `094ed4ee3b8137428b7ee16d5a7fddb5c14b8938`：

- `完整秒时钟服务`直接读取平台 epoch，尚无独立纪元起点；
- 完整秒区间仍表达为旧形状，当前路由只保存裸观察和裸截止；
- `运行期事实版本服务`只持有存在服务并返回裸截止；
- 自我线程已经临时拥有三个运行期 provider，启动入口传入存在服务；
- 当前代码已经实际调用批次路由，因此提供者迁移必须同步修复消费者。

本叶只闭合运行期时间证据、完整秒、共享事实截止及现有消费者 ABI。批次路由自身的最终重试状态机、普通应用最终 ownership、T02 停止边界、治理业务语义、G0/G1 和跨进程恢复保持 `NOT_RUN`。

## 3. 最终模块与公开合同

### 3.1 单调时钟适配器

新建 `海中鱼巣/适配/适配器.单调时钟.ixx`，模块为 `海中鱼巣.适配.适配器.单调时钟`。唯一导出：

```cpp
inline constexpr std::uint32_t 单调时间证据合同版本 = 1;
inline constexpr std::uint32_t 稳态时钟时间源版本 = 1;

struct 单调时钟适配器配置 final {
    std::uint64_t 运行代次 = 0;
    std::uint64_t 时间纪元身份 = 0;
};

struct 单调时间证据读取请求 final {
    std::uint32_t 合同版本 = 单调时间证据合同版本;
    std::uint64_t 运行代次 = 0;
    std::uint64_t 时间纪元身份 = 0;
    std::uint32_t 期望时间源版本 = 稳态时钟时间源版本;
};

enum class 单调时间证据读取状态 : std::uint8_t {
    已读取 = 1, 请求拒绝 = 2, 纪元错配 = 3,
    时间源版本漂移 = 4, 计数不可表示 = 5, 内部不一致 = 6
};

struct 可信单调时间证据 final {
    std::uint32_t 合同版本 = 单调时间证据合同版本;
    std::uint64_t 运行代次 = 0;
    std::uint64_t 时间纪元身份 = 0;
    std::int64_t 从纪元起点经过纳秒 = 0;
    std::uint32_t 时间源版本 = 稳态时钟时间源版本;
};

struct 单调时间证据读取结果 final {
    单调时间证据读取状态 状态 = 单调时间证据读取状态::请求拒绝;
    std::optional<可信单调时间证据> 证据;
};
```

`单调时钟适配器`构造时唯一取得 `steady_clock` 起点；保存不可变配置和起点，不可复制、不可移动。`读取可信单调时间证据(const 单调时间证据读取请求&) const noexcept`在全部准入通过后恰一次读取当前时点，返回非负且可表示的 I64 纳秒。全部非成功证据为空。

### 3.2 完整秒服务

`海中鱼巣.领域.服务.完整秒时钟`直接导出自己的 DTO，不再 include 共享头。最终合同沿用 `当前完整秒边界提供者详细设计 v0.1`第 3—5 节：

- 构造：`完整秒时钟服务(const 单调时钟适配器&, 完整秒时钟服务配置) noexcept`；
- 入口：`读取当前完整秒边界(const 完整秒边界读取请求&) const noexcept`；
- 当前边界为经过纳秒除以十亿；
- `当前 > 上一 >= 0`时区间严格为 `[上一+1, 当前]`，数量为 `当前-上一`；
- `已读取`携带观察和区间，`无新完整秒`只携带观察，其余双空；
- 零直接 `steady_clock`、零游标写、零缓存。

### 3.3 运行期事实版本服务

`海中鱼巣.领域.组合.运行期事实版本`直接导出自己的 DTO。最终合同沿用 `共享当前事实截止消费详细设计 v0.1`第 4—6 节：

- 构造：`运行期事实版本服务(const L2结构聚合服务&, 运行期事实版本服务配置) noexcept`；
- 入口：`读取当前已发布共享事实截止(const 共享事实截止读取请求&) const noexcept`；
- 准入后经同实例聚合 getter 取得存在服务并恰一次读取当前事实代次；
- 只有完整成功返回 `optional<已发布共享事实截止>`；资源失败独立映射，其它坏状态和坏形状为内部不一致；
- 零 L1 直达、零写入、零缓存。

### 3.4 DTO 所有权

删除 `海中鱼巣/领域/运行期Provider.数据.h`及工程登记：完整秒 DTO、事实截止 DTO、批次路由 DTO 分别由三个真实模块唯一导出。禁止兼容转发头和重复实体定义。

## 4. 当前消费者迁移

1. `路由.自我治理批次.ixx` import 两个最终服务模块；完整复核状态、optional 和配置回显，私有槽与交付批次保存完整观察、可选区间和完整共享截止材料。现有下游暂需标量时，只从已经复核的完整材料显式取值，不恢复裸 DTO。
2. `创建.自我线程.ixx`构造参数由 `const L2存在结构服务*`改为 `const L2结构聚合服务*`；临时成员依次为单调适配器、完整秒服务、事实版本服务和路由，声明顺序保证逆序析构安全。
3. `启动.应用程序.ixx`只把阶段 20 参数改成同一普通应用上下文的 `取得L2结构聚合服务()`，不改变本叶之外的启动控制流。
4. 现有合法自我治理端到端入口改为消费最终 DTO，至少读回单调证据、完整秒观察和共享事实截止的完整成功形状；不建立第二实现或 fake provider。

## 5. 文件、依赖和失败收口

生产与工程文件：


依赖方向固定为：适配器 -> 完整秒；DATA-L2 -> 结构聚合 -> 事实版本；两个子提供者 -> 路由 -> 自我线程 -> 启动。任何半迁移都不得提交。编译错误和机械字段适配在本范围内修复；若当前 L2 getter、读取状态或自我线程生命周期发生改变机器合同的漂移，停止并修订本设计。

## 6. 验证和完成声明

验证围绕公开 CRUD 式读取边界：坏请求零下游调用；成功返回完整值式材料；连续/并发单调证据不倒退；完整秒区间满足 `[上一+1, 当前]`；事实截止成功非零且配置回显一致；路由和现有合法消费者不再引用旧 DTO。根工程 Debug/Release fresh Rebuild、现有端到端测试入口、strict、diff、模块依赖、工程唯一登记和生产零测试 seam 必须通过。

真实平台倒退、I64 极限、DATA 资源竞争、内存耗尽、跨进程恢复和完整治理闭环保持 `NOT_RUN`。本设计完成只证明本运行进程内的两个提供者及现有消费者形成单一 ABI 并经合法入口读回。
