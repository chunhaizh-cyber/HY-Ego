# SYSTEM-WORLD-TREE-ROOT-PUBLISH-I1 系统具名场景树根补验单源模板详细设计 v0.4

日期：2026-08-13

## 1. 来源问题与最终裁决

本修订只处理 `DRIFT-I1-INTERNAL-ORCHESTRATION-FILE-KIND-CONFLICT`。正式起点为 `3fe1e9ba28e7c758de92e3ede7e584eb6c83912f`，该基线已正式发布 CODE-FILE-01 v2.6 与规范目录 v4.9。

v0.3 使用传统 `.h` 承载完整初始化状态机，违反当时现行文件分类规则，物理合同永久失效。v0.4 采用 CODE-FILE-01 第 3.3 节窄准入：新增 `海中鱼巣/业务/初始化.系统世界树根.inl`，它是既有 `海中鱼巣.装配.普通应用` 模块所属模板实现片段，不形成模块、分区、翻译单元、第二实体所有者或公开能力。

生产主接口和生产外专项在各自依赖完整后直接包含同一 `.inl` 源码正文，并以真实 R1 与脚本化访问器分别实例化。两者是不同翻译单元中的不同模板实体，绝不宣称同一二进制实例。专项动态结果必须与真实 R1、静态源码、根工程物理证据分账。

本修订不改变 I1 v0.2 的公开 DTO、状态机机器语义、provider-only、A1 同实例、阶段 15 永久退出或启动 `NOT_RUN`；I2 继续冻结。

## 2. 文件、所有者与包含合同

| 文件 | 分类 | 唯一所有者 | 工程登记 | 调用方式 | 生命周期 |
| --- | --- | --- | --- | --- | --- |
| `海中鱼巣/业务/初始化.系统世界树根.inl` | CODE-FILE-01 3.3 模板实现片段 | 既有模块 `海中鱼巣.装配.普通应用` | 根工程 / filters 各唯一 `ClInclude` | 生产 module purview 与获授权专项 TU 普通 `#include` | 永久生产实现，不随专项清理 |

`.inl` 不含 `module`、`export` 或任何 `#include`；不建立 include guard，因为每个获授权翻译单元只允许包含一次。它只在 `namespace 海中鱼巣::系统世界树根初始化内部` 内定义函数模板及其直接私有逐字段辅助。跨 TU 出现的非模板辅助必须声明为 `inline`，不得产生多重定义；模板与辅助均不得取得外部公开能力身份。不得出现测试宏、脚本状态、故障选择、计数器、sleep、让行、输出、替代生产 provider 或验证专用分支。

生产包含位置固定在 `海中鱼巣/装配.普通应用.ixx` 的 module purview：完成标准库全局模块片段、R1/A1 imports 和 I1 DTO 导出之后，现有匿名辅助区之前包含一次。正式 wrapper 定义仍位于 `普通应用上下文` 完整定义之后。

专项 TU 固定先提供 `<cstdint> <memory> <mutex> <optional> <type_traits> <utility> <variant> <vector>` 以及专项自身所需标准库依赖，再依次直接 `import 海中鱼巣.领域.合同.L2结构公共;`、`import 海中鱼巣.领域.服务.L2场景结构;`、`import 海中鱼巣.装配.普通应用;`，之后包含 `.inl` 一次。三者均是专项工程已编译的既有公开模块；直接 import 不新增生产依赖、公开 ABI 或模块所有者。若真实 MSVC 编译证明任一 `.inl` 依赖仍不可见，执行必须具名退回，不得复制 DTO、手填模块依赖或扩大 export。

## 3. 逐函数合同

唯一编排模板：

```cpp
template<class 场景结构访问器>
系统世界树根初始化结果 编排系统世界树根初始化(
    std::mutex& 发布锁,
    std::optional<L2场景树根建立请求>& 待收敛请求,
    std::optional<系统世界树根读回>& 已发布读回,
    const 系统世界树根初始化请求& 请求,
    场景结构访问器& 场景访问) noexcept;
```

- 功能分类：I1 初始化状态机单源编排。
- 权威事实所有者：根事实仍由 R1 场景 owner 拥有；两个 optional 仅为调用方拥有的过程 / 值式发布状态。
- 形态 / 可见性：函数模板，未导出，属于上述既有模块内部命名空间。
- 诊断责任：向上送出；把合法失败映射为结构化 I1 结果，`bad_alloc` 映射资源失败，其它异常映射内部不一致，不自行记录日志。
- 所有权：不保存访问器或参数引用；锁与两状态槽由调用方拥有，访问器调用结果按值由本轮拥有。

访问器表达式合同固定为：

```cpp
L2场景树结构登记结果 读取当前场景树结构登记();
L2场景树节点写入结果 建立场景树根(
    const L2场景树根建立请求& 请求);
L2场景树读取结果 读取场景树(
    const L2场景树读取请求& 请求);
```

生产 specialization 的访问器类型就是 `L2场景结构服务`。专项 specialization 的脚本化访问器只存在于专项 `.cpp`，按值返回预置结果并记录调用序列；模板不知道脚本、计数或故障模式。

正式 wrapper 保持既有公开签名：

```cpp
系统世界树根初始化结果 初始化并发布系统世界树根(
    普通应用上下文& 上下文,
    const 系统世界树根初始化请求& 请求) noexcept;
```

wrapper 仅经 `上下文.取得L2结构聚合服务().取得L2场景结构服务()` 取得真实服务引用，随后把上下文既有锁、待收敛槽、发布槽、请求和服务引用交给模板并原样返回。精确 friend 不变；不新增公开/私有状态出口、setter、测试入口或 provider 参数。

所有逐字段比较与反例 helper 迁入 `.inl` 并保持未导出；DTO 不新增 `operator==`。`系统世界树根初始化结果::成功()` 可留在主接口，但调用 `.inl` 的具名内部逐字段 helper；状态机正文只能存在于 `.inl` 一份。

## 4. 不变状态机与精确边界

v0.2 首次、待收敛、重复、读回、交换和异常语义原样迁移。特别冻结：

```text
可重组 = 根建立状态 == 事实代次漂移
        && !结果头.变更事实代次
        && !树
        && !场景节点
        && !直接父关系
```

只有该完整谓词为真才清除待收敛请求。其它事实代次漂移，以及资源失败、内部不一致、入口拒绝、许可拒绝、幂等冲突等均保留原请求；“提交未知”不新增不存在的 L2 枚举，而以任一上述谓词反面形状验证保留。

公开 I1 请求只接受唯一固定身份，不存在第二个合法异选择。专项不得把另一有效身份说成业务冲突；只允许预置损坏的已发布槽选择或待收敛槽幂等身份，验证防御性 `已发布选择冲突` 且访问器零调用。

坏形状分层：

- L2 成功谓词先拒绝：成功枚举配缺失必要 optional、非成功枚举却 `成功()`、首次 / 收敛成功枚举与路径不匹配。
- I1 跨结果互证：树身份、根标记类别或端点、根父关系、首次生命周期、登记 / 读取截止不一致逐个拒绝。
- 零截止属于 L2 成功谓词 / DTO 完整性拒绝；错截止属于 I1 登记、整树、发布材料跨结果互证拒绝。不得混成一个“坏成功”用例。

旧值守恒分账：

1. 首次或待收敛失败前发布槽为空；失败后仍为空，并按路径检查待收敛槽保留或清除。
2. 已发布重复路径先存在完整旧发布值；后二次登记失败、整树失败、`bad_alloc` 和其它异常后，旧发布值逐字段不变，待收敛槽仍为空。

## 5. 四层证据分账

| 层 | 能证明 | 不能证明 |
| --- | --- | --- |
| seam specialization 动态矩阵 | 同一 `.inl` 源码的专项 specialization 在脚本结果下执行全部状态分支、调用顺序与两状态槽变化 | 生产二进制实例、真实 R1 对象或真实资源耗尽 |
| 真实 R1 / 普通应用 | final R1 首次、已发布重复、并发、值式 getter；直接 getter 与 A1 getter 同址 | 脚本化失败分支；I1 实际服务地址不可单靠黑盒返回宣称 |
| 静态源码合同 | wrapper 只从 A1 getter 取引用并直接交模板，因此结合上一层证明 I1 实际取同一 R1；A1 接口零写；I1 固定身份与 R1 四个源码保留值不同；状态机正文唯一、公开 ABI 零变化 | 运行结果或构建通过 |
| 构建 / 工程 | 根工程真实完整依赖图和专项完整依赖图 Debug / Release 均编译链接运行；`.inl` 仅 ClInclude、无第二 TU / module / partition | 业务闭环、启动接线或独立集成验收 |

不得把不同 TU specialization 称为同一二进制实例，不得用专项 seam 替代真实生产主路径，不得用静态扫描替代动态强制分支。

## 6. 动态专项七组矩阵

每个用例必须独立输出：用例名、输入脚本、实际调用序列、结果状态与六个 optional 格、待收敛槽前后、发布槽前后；坏形状必须逐个命名，不得聚合输出。

1. **准入与损坏槽防御**：无效版本、非固定身份；损坏已发布槽选择、损坏待收敛身份均冲突且访问器零调用。固定身份与四保留值差异只作源码静态证据。
2. **顺序、重放与重复**：首次 `登记读 -> 根建立 -> 登记再读 -> 整树读`；失败后同请求逐字段原样重放；已发布重复 `登记再读 -> 整树读` 且根写零次。
3. **四阶段失败与 optional 格**：首次登记、根建立、后二次登记、整树读取分别失败并立即短路；结果 optional 与实际已发生阶段完全一致。
4. **重组 / 保留**：精确可重组谓词清除；其它漂移、资源、内部、入口、许可、幂等失败及提交未知反面逐项保留原请求。
5. **坏形状分层**：L2 成功谓词各反例、树身份、根标记类别、三个端点、根父关系、首次场景生命周期、树归属生命周期、零截止、各错截止分别命名并拒绝发布。
6. **状态守恒**：首次 / 待收敛空发布槽守恒；已有发布重复的后二登失败、整树失败、`bad_alloc`、其它异常旧值逐字段守恒；getter 值式隔离另由真实路径证明。
7. **并发与来源**：专项同请求并发只证明模板锁串行和调用计数；真实普通应用同请求并发、首次来源、已发布重复来源及值式隔离必须在真实 R1 层另行通过。

第 1—7 组动态强制项不得记为 `NOT_RUN`。真实资源耗尽只可记 `NOT_RUN`；脚本化 `bad_alloc` 仅为异常映射 PASS。

## 7. 静态、工程与范围矩阵

- 静态解析 I1 固定身份与 `场景身份来源登记幂等身份`、`场景关系类型登记幂等身份`、`场景属性类型登记幂等身份`、`L2场景树结构登记固定幂等身份` 四个源码值均不同。
- 真实运行核对普通应用直接场景 getter 与 A1 getter 同址；静态核对 wrapper 只取得该 A1 引用并传给模板；静态核对 A1 无写函数。这三项分账后才允许声明 I1 实际使用同一 R1 且 A1 零写。
- `git diff 34b9cbcc --` 对 I1 DTO、`启动.应用程序.ixx`、`程序运行结果.数据.h` 三条精确路径零变化。
- `.inl` 无 module/export/include/验证词与测试分支，主接口和专项各唯一 include；工程 / filters 仅 ClInclude 唯一登记，零 ClCompile / 模块扫描 / 分区 / 手工模块依赖。
- 根工程与专项 Debug / Release 必须从 fresh 隔离输出重建；专项项目必须继续编译完整真实模块依赖图，不允许最小探针外推。
- strict、UTF-8/XML、staged 白名单和独立 I1 `.cpp/.ixx` 实现文件零命中通过。

## 8. NOT_RUN 与完成边界

允许 `NOT_RUN`：真实分配器耗尽、正式启动及阶段 14—18、恢复 / 跨进程、长时生产、I2、真实自我、概念维度根、独立集成验收。不得用其覆盖第 6 节动态强制项或第 7 节静态 / 工程项。

I1 完成最多证明 provider 经 A1 同实例 R1 建立或收敛根，并在正式登记与整树读回互证后发布值式材料；不证明启动、I2、自我、概念或完整系统闭环。
