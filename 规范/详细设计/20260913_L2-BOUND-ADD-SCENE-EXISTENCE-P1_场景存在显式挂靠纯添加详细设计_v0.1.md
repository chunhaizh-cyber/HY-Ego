## 1. 目标和完成条件

P1为场景类与存在类建立显式挂靠的纯添加入口。一次成功必须在同一`L1有限N分区原子事务_v3`中形成新E、本次直接挂靠、存在概念生成或精确复用所需写入及`概念 -> 新E`世界挂接，并在实际`Gread/H`独立读回全部事实。新场景使用同一E的存在概念，不建立场景概念类别或第二E。

本叶不修改世界树应用、普通应用装配、特征/状态/动态/因果入口、概念旧布局迁移或已有E启用场景视角。世界树在P6才改为调用两个L2公开入口；本叶只保证接口与结果可供该迁移消费。

## 2. 当前事实与复用裁决

1. `数据服务.绑定存在.ixx::绑定存在数据服务::创建绑定存在`是现有唯一绑定协调器。父存在组成使用存在owner，场景成员与直接子场景使用存在/场景两个owner；新E固定为存在参与者本地键1，已经具备首次材料恢复、L1 v3提交及两个owner读回。
2. `存在类数据服务`公开继承`绑定存在内容参与者`，`场景类数据服务`公开继承`绑定存在场景参与者`。两者已提供协调器所需私有片段和读回，不新增第二套出生写集。
3. `相关概念添加参与者`已发布，但只接受稳定世界挂靠。新E提交前没有稳定编码，因此P1必须给该合同增加唯一的待发布E前向引用；不得预分配编码或分阶段补挂接。
4. `世界树应用服务`仍保存`绑定存在数据服务 binding_`并直接调用`创建绑定存在`。P1保留该旧入口和ABI以维持现有消费者编译；新概念协调入口只供两个L2包装函数调用。P6切换调用点后再计划收窄或退出旧公开入口。
5. 已有`场景类数据服务::启用并接纳直接子场景`处理既有E启用视角。它不创建信息节点，不纳入本次纯添加入口；P1不得借此新增结构父或概念类别。

## 4. 精确DTO与函数

### 4.1 待发布存在挂靠

在`合同.相关概念添加参与.ixx`追加：

```cpp
struct 相关概念待发布存在挂靠 final {
  L1有限N分区原子参与者身份_v3 参与者{};
  L1所有者范围写集本地键 本地键{};
  friend bool operator==(const 相关概念待发布存在挂靠 &,
                         const 相关概念待发布存在挂靠 &) = default;
};
```

在`相关概念参与请求`末尾追加`std::optional<相关概念待发布存在挂靠> 待发布存在挂靠;`，保留现有字段顺序。给`相关概念世界挂靠`、`相关概念精确复用方案`、`相关概念创建方案`和`相关概念参与请求`补默认`operator==`；其全部成员已经是可比较纯值，比较必须覆盖新增optional，供外层原请求逐字段恢复，不另造哈希等价。稳定挂靠与待发布挂靠恰一有效。P1只接受`{参与者{1}, 本地键{1}}`；概念参与者身份分别为2（父存在组成）或3（场景成员、直接子场景）。概念类别固定为存在，定义分支固定为`概念树存在定义`。

`相关概念参与读回`只追加无状态成员谓词`bool 成功(const 相关概念参与请求 &稳定化请求) const noexcept;`，不向`概念树形成引用事实`、`相关概念完整事实`或其它P0事实DTO增加证据截止、原请求或旁路证明字段。谓词要求稳定化请求版本1、无待发布挂靠、稳定世界引用及证据截止有效，读回状态为`已读取`、`0 < H <= Gread`、概念载荷存在；载荷类别和规范化定义与方案一致，精确复用时概念身份等于请求身份，挂接关系/记录/所属概念有效且所属概念等于载荷概念，挂接世界引用逐字段等于稳定化请求世界引用，概念与挂接生命周期在H有效。创建方案还要求载荷直接上位身份组与请求规范化父组一致。该谓词依赖`读取相关概念结果`的生产者不变量：只有内部已按同一稳定化请求核验挂接证据截止恰等于`稳定化请求.挂靠.证据截止`后才能返回`已读取`；谓词不得从关系创建H、记录编码或其它公开字段反推、伪造证据截止。

### 4.2 L2共同请求和结果

在`数据服务.绑定存在.ixx`追加：

```cpp
struct 绑定存在概念添加请求 final {
  std::uint32_t 版本 = 1;
  绑定存在创建请求 绑定请求;
  L1所有者范围写入幂等身份 组合幂等身份{};
  相关概念参与请求 概念请求;
  friend bool operator==(const 绑定存在概念添加请求 &,
                         const 绑定存在概念添加请求 &) = default;
};

enum class 绑定存在概念添加状态 : std::uint8_t {
  已添加 = 1, 精确重复 = 2, 入口拒绝 = 3,
  绑定未完成 = 4, 概念未完成 = 5, 事实代次漂移 = 6,
  幂等冲突 = 7, 数量预算不足 = 8, 历史材料不可用 = 9,
  资源失败 = 10, 内部不一致 = 11, 已可能发布 = 12
};

struct 绑定存在概念添加结果 final {
  std::uint32_t 版本 = 1;
  绑定存在概念添加状态 状态 = 绑定存在概念添加状态::入口拒绝;
  std::uint64_t Gread = 0;
  std::optional<std::uint64_t> 首次发布H;
  std::optional<绑定存在概念添加请求> 原请求;
  std::optional<绑定存在创建状态> 绑定原因;
  std::optional<相关概念参与状态> 概念原因;
  std::optional<绑定存在事实> 绑定事实;
  std::optional<场景绑定出生见证> 场景事实;
  std::optional<相关概念参与读回> 概念读回;
  bool 成功(const 绑定存在概念添加请求 &) const noexcept;
};
```

成功谓词先从原概念请求构造唯一稳定化请求：清空`待发布存在挂靠`，把`挂靠.世界事实`改为`概念树存在引用{绑定事实.新存在}`，保留方案、幂等身份、预算、`G0`和`挂靠.证据截止`。随后要求状态为`已添加/精确重复`、原请求逐字段相等、`绑定请求.G0 < H <= Gread`、绑定事实的新E有效、`概念读回`存在且`概念读回->成功(稳定化请求)`；并显式要求概念读回的`Gread==外层Gread`、`H==首次发布H`、概念类别为存在、挂接所属概念等于概念身份、挂接世界引用逐字段等于稳定化请求世界引用且其中E等于绑定事实的新E。精确复用方案再要求返回概念身份等于请求概念身份。场景分支要求存在同`Gread/H/E`的场景事实，父存在分支要求无场景事实。成功结果不得携带非成功原因。证据截止只由概念读回成功谓词的生产者不变量证明，外层不得访问不存在的事实字段，也不得以`H`、关系创建代次或记录编码替代。

`绑定存在数据服务`增加下列受限公开协调函数和不泄露端口的参与者身份核验：

```cpp
bool 绑定内容参与者(const 绑定存在内容参与者 &) const noexcept;
bool 绑定场景参与者(const 绑定存在场景参与者 &) const noexcept;
绑定存在概念添加结果 创建绑定存在并关联概念(
    const 绑定存在概念添加请求 &,
    相关概念添加参与者 &) noexcept;
```

两个公开L2入口固定为：

```cpp
// 存在类数据服务
绑定存在概念添加结果 添加存在节点(
    const 绑定存在概念添加请求 &,
    绑定存在数据服务 &,
    相关概念添加参与者 &) noexcept;

// 场景类数据服务
绑定存在概念添加结果 添加场景节点(
    const 绑定存在概念添加请求 &,
    绑定存在数据服务 &,
    相关概念添加参与者 &) noexcept;
```

存在入口只允许`父存在组成/场景成员`，并通过值式身份核验确认协调器的内容参与者就是`this`；场景入口只允许`直接子场景`，并确认协调器的场景参与者就是`this`。包装入口不准备写集、不直接访问端口。新增函数是现有协调器的概念闭合版本，不建立第二个协调类或应用服务；其合法调用方只限这两个L2入口，世界树及普通业务不得绕过L2直接调用。旧`创建绑定存在`仅为P6前兼容消费者保留。

## 5. 写入映射与原子顺序

| 分支 | 参与者1 | 参与者2 | 参与者3 |
| --- | --- | --- | --- |
| 父存在组成 | 存在出生：E=`{1}`、族归属=`{2}`、组成边=`{3}` | 概念owner：生成/引用及形成端点`{1,{1}}` | 无 |
| 场景成员 | 存在出生：E=`{1}`、族归属=`{2}` | 场景成员边=`{1}` | 概念owner：生成/引用及形成端点`{1,{1}}` |
| 直接子场景 | 存在出生：E=`{1}`、族归属=`{2}` | 场景角色/四锚/直接子场景边/父语境，保持既有12项映射 | 概念owner：生成/引用及形成端点`{1,{1}}` |

创建概念可形成概念节点、定义、零或多条上位及世界挂接；精确复用仍必须为本次新E形成新的挂接记录，不能返回概念空写集。场景分支复用存在类别和同一E端点，不生成“场景概念”。概念owner不写E、场景边或父语境；绑定协调器不写任何owner事实。

## 6. 控制流、首次账和读回

1. L2包装函数先校验允许的绑定种类、协调器参与者身份及概念参与者同L1，失败零写。
2. 协调器固定`Gread=当前G`，要求请求`G0==Gread`、三个owner键与组合键非零且互异，并完成现实树、绑定端、类别/定义、预算和待发布引用形状预检。
3. 按绑定分支读取存在、可选场景、概念三个owner的首次材料。全部成功时从存在首次结果解析E和共同H，完成三个owner独立读回；精确一致返回`精确重复`。全部未找到时继续。部分存在、H不一致、owner/键/请求不一致返回`内部不一致`；资源、清理和漂移保持精确映射。
4. 使用既有存在/场景参与接口准备前序片段；以参与者2或3调用`准备相关概念片段`。所有片段必须同G、owner不同、键匹配且概念片段只含允许的前向E引用。
5. 通过`提交相关概念组合事务`唯一进入L1 v3。父存在分支传一个前序端口，场景分支传两个；组合键只使用外层`组合幂等身份`。
6. L1返回提交或重复后，从参与者1本地键1的映射取得E，核对全部参与者映射和共同H。构造稳定概念读回请求：清空待发布字段，设置`挂靠.世界事实=概念树存在引用{E}`，保留其余字段和证据截止。
7. 按实际`Gread/H`读取存在出生、可选场景绑定和完整`相关概念参与读回`。必须先以稳定化请求调用概念读回成功谓词，再按4.2节交叉核对外层`Gread/H`、概念身份、所属概念和世界引用；三者闭合后保存该完整读回并返回成功。任何提交后异常、映射缺失或读回不完整返回`已可能发布`，保留原请求和可能H，不回滚。

若概念组合函数在并发窗口看到待发布请求的概念首次材料，返回`已可能发布/已进入L1=false`。协调器立即以全部owner原键执行第3步；只有全体首次材料与读回闭合才收敛。禁止只凭概念首次账或当前挂接猜测外部事务已完成。

## 7. 非成功映射

- L2入口形状、版本、空挂靠、错误分支或协调器不匹配：`入口拒绝`。
- 绑定预读/片段非成功：外层`绑定未完成`并保留精确`绑定原因`。
- 概念准备/读回非成功：外层`概念未完成`并保留精确`概念原因`。
- L1漂移、幂等、预算、资源、历史清理分别映射同名外层状态；不压成未找到。
- 提交前所有失败：`首次发布H`及三份事实为空，L1零写。
- L1已进入或不能证明未进入后的失败：`已可能发布`；只允许原四个幂等键和逐字段相同请求恢复。
- 捕获异常必须保留`noexcept`，调试诊断只解释结构化状态，不代替状态。

## 8. 并发与生命周期

复用`绑定存在数据服务`现有实例互斥，不在两个L2类另设协调锁。不同协调器实例仍以L1 v3共同代次和owner首次账为最终裁决。同键同请求收敛，同键异请求冲突；同G不同键可以竞争，一个提交后另一个按漂移处理。所有span和端口引用只在调用期借用；请求、结果及持久事实不得保存端口、服务地址或容器地址。

稳定E、概念及挂接的生命周期仍由各owner合同负责。本叶不增加删除、撤销或补偿写；发布后读回失败只能恢复，不能物理删除已提交事实。

## 9. 消费者迁移边界

P1不得修改`业务/应用服务.世界树类.ixx`。P6给世界树增加概念参与者依赖和概念方案字段后，`创建存在`改调`存在类数据服务::添加存在节点`，`创建场景`改调`场景类数据服务::添加场景节点`。世界树继续负责读取当前位置和传入明确父节点，不直调私有概念协调函数、不准备写集、不接触owner端口。

P6完成且`rg`证明世界树及其它业务消费者对`创建绑定存在`调用归零后，另行收窄旧公开入口及`binding_`暴露。P1不得提前删除它，也不得新增平行应用服务。

## 10. 验证矩阵

专项矩阵至少覆盖：三种绑定分支；概念创建与精确复用；顶层零上位与多上位；同一新E挂接；同键重放；同键异请求；错误类别/定义；空、反向、越序、错键待发布引用；绑定不在现实树、已退出、类型错、多父和成环；预算边界；全首次账、全未找到、部分首次账；提交前漂移；提交后映射/读回失败与再次恢复；两个协调器并发；场景结果无场景概念且只有一个E。另须直接覆盖概念读回成功谓词：错`Gread/H`、错复用身份、错所属概念、错世界引用、错父组或非活动生命周期均为false；正确稳定化请求为true。不得通过给P0事实DTO增加证据截止使测试通过。

## 11. 完成声明

P1完成只证明场景类和存在类可以通过现有唯一绑定协调器，在明确挂靠下原子添加新E、直接绑定和存在概念世界挂接，并完整读回。它不证明世界树或普通应用已经消费这些入口，也不证明其它四类、已有E场景视角修复、迁移删除或自我治理闭环完成。
