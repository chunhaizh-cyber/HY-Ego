## 1. 目标与设计裁决

本设计是`GOAL-SELF-THREAD-M1A-TOP-DOWN-DESIGN`的第一个代码叶。它先把`线程_自我.h/.cpp`实现为唯一物理自我线程、关闭治理门、独立停止控制和线程安全有界邮箱。正式上下文读回、双根需求复核和根治理意图sink只在本设计中冻结后继调用点，不进入首叶实现；下层能力不预先建设数据服务库存。

首叶可独立施工和动态验证，但不进入普通应用生产启动链，也没有任何成功开放治理门的分支。原因是当前正式代码尚无8121要求的`本能根运行锚点_v1`及阶段21提供者，fresh上下文、双根裁决和根治理意图sink也不存在，同时`海中鱼巣.vcxproj(.filters)`和`装配.普通应用.cpp`正由`SECONDARY-RELATION-CONCEPT-STRUCTURE-P1`活动切片修改。首叶不得覆盖该现场，也不得用默认锚点、布尔成功、稳定编码猜测或测试夹具开放生产治理。

固定后继顺序：

```text
上层线程对象、关闭门与强类型邮箱实现
-> 隔离证明创建/停门/排队/停止/join且零开门
-> 在真实调用点确认阶段21提供者缺口
-> 建立并完成最小阶段21提供者目标
-> 建立fresh上下文、双根裁决和根治理意图sink
-> 工程与普通应用所有权释放
-> 把真实值式锚点适配到本设计启动上下文
-> 登记主工程并完成生产创建、停门
-> 所有必要端就绪后另行实现并验证治理开门
```

这不是“永远不可接线的线程空壳”：上层类、生命周期、关闭门和邮箱是最终对象的一部分；首叶以`待实现/依赖未就绪`明确封闭开门入口，把真实provider、治理sink和生产装配留在后继，不把占位返回当成成功。

## 3. 分层与事实边界

`线程_自我`属于DATA之外的ARCH-L4治理编排载体。它只能：

- 保存物理线程生命周期、运行门、工程邮箱和只读诊断快照；
- 消费普通应用传入的值式启动上下文；
- 在后继具备窄端口后请求“正式上下文读回”和“双根需求复核”；
- 接收只承担唤醒/定位的强类型根需求复核消息，并在关闭门期间有界排队；
- 停止、唤醒和join。

它不得：

- include或调用`核心/`、`领域/数据服务.*`、世界树、L1仓库、写端口或事务端口；
- 持有仓库、服务getter、可变节点、需求/任务/方法第二账；
- 直接发布需求、任务状态、安全值、服务值或现实执行授权；
- 把消息、线程字段、测试provider、循环次数、超时或队列顺序解释为业务事实；
- 因下层返回`待实现/依赖未就绪`而开放治理运行门。

- 上下文预算：最大自我候选、每根最大候选、最大关系材料；

```cpp
  自我线程运行代次 运行代次;
  自我线程消息身份 消息;
  自我线程原请求身份 原请求;
  自我线程复核触发根 触发根 = 自我线程复核触发根::双根;
  自我线程需求身份 正式需求定位; // 双根时为空，其余必须对应锁定根
};
```

它只允许重新读取，不携带当前值、满足结论或业务写入。停止不进入邮箱，使用独立进程内控制信号和同一条件变量唤醒，永不受邮箱容量限制。

邮箱由`线程_自我`私有`mutex + condition_variable + deque`实现。队列容量固定；提交在锁内按`运行代次+消息身份`扫描当前队列和当前处理项：同义返回精确重复，异义返回消息冲突。处理完成后不持久记录消息账；迟到重复允许再次触发fresh读取，业务效果仍由owner和原请求收敛。

## 8. 生命周期与上层控制流

公开类固定为不可复制、不可移动。首叶构造函数不接收业务端口；后继开门计划才按第6节增加依赖并同步生产装配：

```cpp
class 自我线程 final {
public:
  自我线程() noexcept;
  ~自我线程();
  自我线程创建结果_v1 创建并停在治理运行门(
      const 自我线程创建请求_v1&, std::uint64_t 等待毫秒) noexcept;
  自我线程操作结果_v1 复核前置并开放治理运行门(
      std::uint64_t 等待毫秒) noexcept;
  自我线程操作结果_v1 提交根需求复核消息(
      const 自我线程根需求复核消息_v1&) noexcept;
  自我线程操作结果_v1 请求停止() noexcept;
  自我线程操作结果_v1 等待停止(std::uint64_t 等待毫秒) noexcept;
  自我线程诊断快照_v1 读取诊断快照() const noexcept;
};
```

控制流：

```text
创建：校验并锁定请求 -> 建立唯一std::thread -> 入口见证 -> 停门见证 -> 调用方读回
首叶开放：固定返回依赖未就绪 -> 门保持关闭 -> 零端口调用、零消息消费
后继开放：向同一线程登记开放复核 -> fresh上下文 -> 双根复核 -> 根治理意图sink就绪
          -> 全部成功才原子标记治理门开放
首叶消息：关闭门期间有界入队；不冻结、不出队、不形成业务结果
后继消息：等待停止/业务消息 -> 停止优先 -> 出队 -> fresh上下文 -> 双根复核 -> 形成根治理意图
停止：独立锁存 -> notify_all -> 线程退出见证 -> 完成后join -> 已停止
```

`创建并停门`同选择精确重复返回原见证，不新建线程；异选择冲突。等待预算只控制调用方等待，不进入选择。启动中任一失败按8120顺序锁存停止、唤醒、等待完成、完成后join；超时保留joinable租约，禁止detach或覆盖。

首叶`复核前置并开放治理运行门`不登记内部控制请求，不调用provider，固定结构化返回依赖未就绪。后继不得在调用线程执行provider；它提交内部控制请求并等待工作线程结果。`待实现/依赖未就绪/漂移/引用冲突/不可比较/资源失败/入口拒绝`均不开门。内部错误锁存并终止线程。

对象是一次性物理租约：从首次合法创建进入`创建中`后，无论后来成功、启动失败、内部错误或已停止，都禁止再次创建。`已停门/正在停止/已停止`的同选择调用只在原见证仍完整且线程未进入停止时返回精确重复；停止已经锁存或线程已经完成后统一返回入口拒绝，不新建第二线程。所谓“唯一”在首叶只证明**每个对象生命周期至多创建一个物理线程**；进程/普通应用唯一self必须由后继普通应用上下文唯一租约和生产接线另行证明。

析构总是锁存停止并最终join，不调用外部端口。持有内部锁时禁止调用端口、日志、文件、数据库或用户回调；调用端口前复制最小值式请求并释放锁，返回后重新加锁核对运行代次、停止和当前处理身份。

## 9. 非成功、异常与恢复边界

- 所有公开函数`noexcept`；`bad_alloc/length_error`映射资源失败，其它异常映射内部错误。
- 首叶零外部端口调用；后继端口声明`noexcept`，线程入口最外层仍须捕获错误实现异常并锁存内部错误、完成见证和唤醒。
- 当前性漂移只丢弃本次投影；不会更改锁定启动材料或建立事实。
- 队满是工程拒绝，不是业务等待；调用方可在新事实通知或容量释放后重投同一消息。
- 通知丢失不改变正式事实；后继生产恢复必须补扫owner，而不是依赖邮箱账。
- 首叶不实现跨进程恢复。重启后必须重新从普通应用取得8121正式锚点并建立新运行代次；禁止恢复裸线程、内存消息或门状态。

## 10. 首叶验证与完成边界

独立专项必须覆盖：

1. 无效请求零线程，完整请求使一个对象至多创建一个线程并形成关闭门/零批次见证；
2. 停止前同选择精确重复、异选择冲突；停止锁存后同/异请求均不能重启对象；
3. 首叶开放入口带`待实现`注释且每次返回依赖未就绪；门始终关闭、端口调用数为0；
4. 消息运行代次、身份、根定位校验，同义在队重复、异义冲突、队满；
5. 关闭门期间消息只入队不冻结、不出队；停止不受队满影响；
6. 停止可在队满、停门、开放复核等待和普通消息等待中立即唤醒；完成后join；无detach；
7. 端口阻塞/内部错误测试不产生业务写，失败租约不遗失；
8. 源码静态检查无`核心/`、`领域/数据服务`、`L1`服务/仓库调用、getter下钻、`detach`、旧`.ixx`或通用运行队列复用；
9. 专项Debug/Release x64构建与运行；`git diff --check`。

首叶完成只证明单个self对象的隔离生命周期至多创建一个物理线程、关闭门、线程安全邮箱和停止回收。它不证明进程/普通应用唯一self、窄端口已经调用、治理门可开放、阶段21、生产工程登记、普通应用接线、真实上下文读回、真实双根比较、根治理意图、任务管理、恢复、连续治理或集成验收。生产接线必须等真实provider、根意图sink和共享文件所有权释放后另行激活。
