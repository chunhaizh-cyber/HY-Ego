## 3. 当前事实与删除闭包

创建侧对生产代码扫描确认：`旧格式不支持=14` 只在 B 合同枚举声明中出现；不存在 `状态使用绑定数据状态::旧格式不支持` 消费者、别名、专属 `case` 或按数值 14 分支。

动态类和因果类对 B 状态的映射均已有 `default -> 内部不一致`，删除该成员不要求修改其源码。其它模块中同名的 `旧格式不支持` 属于各自独立枚举，不在本目标内。

当前场景类不存在旧格式证据 DTO、provider、扫描器、解析器、import 或双读迁移器；不得虚构删除对象。世界树、存在概念树和概念树中的旧场景 API 悬空调用属于另一迁移闭包，也不属于本枚举删除。

唯一生产改动为：

```cpp

    已创建=1, 精确重复=2, 已读取=3, 已退出=4,

    存在未找到=10, 存在已退出=11,

    事实代次漂移=15,
    幂等冲突=16, 引用冲突=17, 数量预算不足=18,
    历史材料已清理=19, 资源失败=20,
    内部不一致=21, 已可能发布=22, 未实现=23

```

以下全部保持不变：

1. 底层类型 `std::uint8_t`；
2. 1..13、15..23 的名称和显式数值，合法成员总数为 22；
3. `场景状态使用绑定合同版本 == 1`；
4. 全部请求、结果、事实 DTO 的字段、类型、顺序和默认值；
5. `状态使用绑定结构交付` 的三个字段；
6. `状态使用绑定只读提供者` 的签名；
7. 场景类现有七个 B 公开入口的签名；
8. 各结果 `成功()` 谓词及其行为；
9. 原工程登记和模块名。

这是源码枚举名退出。虽然 DTO 对象布局和其余数值保持不变，也不能宣称对未重新编译的未知二进制消费者兼容；合法消费者须按本阶段验证闭包重新编译。

## 6. 非成功、迁移与恢复

本阶段不新增运行入口和失败分支。删除后，新 B 读取的未知结构按4203进入 `入口拒绝`，已命中新 B 成员类型但结构残缺进入 `内部不一致`；本阶段不通过代码实现这些尚属场景 P1 的行为。

没有数据迁移、物理清理或恢复写入。L1存量事实保持原样；未来场景P1只读取新结构，不能据本删除操作擦除旧事实。

## 7. 验证矩阵

1. 静态删除：生产代码内 `状态使用绑定数据状态::旧格式不支持`、`旧格式不支持=14` 和等价空格写法零命中；该枚举中无其它 `=14` 成员。
2. 数值探针：底层类型为 `std::uint8_t`；22个合法成员分别等于 1..13、15..23。
3. 形状探针：合同版本、DTO 字段类型/顺序、三字段结构交付、provider、七个 B 入口和成功谓词保持。
4. 编译闭包：按当前真实 import 递归取得 B 合同、场景骨架、动态、因果及其依赖，在 `D:/TEMP` 本计划独占目录建立外置工程；Debug/Release x64 分别 Rebuild、链接并运行外置 ABI/数值探针。场景骨架返回 `未实现` 不判失败。
5. 差异：生产代码差异严格只有删除该一枚举成员；工程文件零差异。
6. 运行 `git diff --check`、`git diff --cached --check`；运行 `python tools/check_specs.py --strict`，若仅命中已知范围外 `tools/l1_frozen_surface_manifest.json` 缺失既有 `acceptance_record`，须如实分账且不得补造或恢复异主记录。
