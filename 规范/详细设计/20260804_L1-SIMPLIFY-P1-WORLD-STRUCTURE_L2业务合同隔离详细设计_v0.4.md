## 1. 目标与完成条件

本版接管并修订已暂停的 v0.3 七文件 WIP，在不改变“唯一初始子场景、单写集原子发布、逐项同代次读回、幂等与冲突”业务语义的前提下，先固化 L2 世界结构的业务请求边界：

1. L2 公开请求、登记和结果不再出现 `写集幂等键`、`写集本地键`、`L1写集请求`或其它 L1 写机制类型；
2. L2 公开使用自己的 `世界操作幂等身份`；
3. 世界登记与初始场景服务在各自模块内部把业务身份确定性映射为互不碰撞的 L1 写集幂等键；
4. `稳定编码`、`节点种类`和事实截止代次继续作为 L1 公共事实合同被 L2 值式见证使用；
5. 动作返回只有经过独立 L1 读取校准后才可携带成功事实。

完成只证明隔离世界登记与唯一初始子场景的 L2 业务合同和真实写读闭环；不证明 L1 仓库已经隐藏、L1 全部入口已经显式版本化、运行期接线、持久恢复、存在、状态动态或端到端世界树能力。

## 3. L2 公共业务幂等合同

新建 `海中鱼巣/领域/世界操作.数据.h`，唯一拥有：

```cpp
struct 世界操作幂等身份 final {
    std::uint64_t 值 = 0;
    friend bool operator==(const 世界操作幂等身份&, const 世界操作幂等身份&) = default;
};

inline bool 世界操作幂等身份有效(世界操作幂等身份 身份) noexcept;
```

有效值域固定为 `1..0x00FF'FFFF'FFFF'FFFF`。最高 8 位保留给领域服务内部的幂等命名空间，不属于调用方可写字段。该头不包含或声明任何 L1 写请求、写集键、本地键、仓库、锁、事务、候选或恢复类型。

`世界登记.数据.h` 与 `L1场景结构.数据.h` 都包含本头；公开字段作如下替换：

```text
世界结构登记.首次幂等键        -> 世界结构登记.首次幂等身份
世界登记建立请求.幂等键        -> 世界登记建立请求.幂等身份
初始场景创建请求.幂等键        -> 初始场景创建请求.幂等身份
```

字段类型均为 `世界操作幂等身份`。公开状态编号、其余字段、事实见证和读请求不变。

## 4. 确定性 L1 键映射

映射只存在于对应服务模块内部，不导出辅助函数或映射结果：

```text
L1键 = (服务域 << 56) | 世界操作幂等身份.值
世界登记服务域 = 0x01
初始场景服务域 = 0x02
```

调用方身份先通过第 3 节值域校验；映射结果必定非零。同一服务域、同一业务身份恒等于同一 L1 键；不同服务域即使业务身份数值相同也不会碰撞。不得使用哈希、地址、时间、随机数、当前代次、固定编码位置或请求内容临时派生键。

映射只解决 L1 全局幂等账的技术命名空间，不改变 L2 同义/异义裁决：

- 世界登记同一业务身份与完全相同请求为幂等读回；同身份异义为幂等冲突；
- 初始场景同一业务身份形成相同确定性写集时由 L1 返回精确重复；同身份异义为幂等冲突；
- 不同 L2 服务使用同数值身份时各自独立。

## 5. 世界登记 v2 迁移

`世界登记合同版本` 从 `1` 升为 `2`。v1 请求必须返回 `入口拒绝`，不得兼容转发或按旧字段解释。

`世界登记服务::建立空世界` 的公开签名不变，内部步骤改为：

1. 校验合同版本 2、规则版本 1和业务幂等身份；
2. 本地已保存请求仍以完整 L2 请求全等裁决；
3. 通过空 L1 快照门禁后，按世界登记服务域映射出私有 L1 键；
4. 只把映射键写入 `L1写集请求`；
5. 独立完整快照读回成功后，登记只保存原 `世界操作幂等身份`，不回显 L1 键。

服务的 L1 写集形状、五节点一值一槽、登记五编码、状态映射和读回规则保持 P1B v0.1 正式语义。

## 6. 初始场景 v2 迁移

`L1场景结构合同版本` 从 `1` 升为 `2`。v1 请求固定入口拒绝。

`L1场景结构服务::创建初始场景` 保持 v0.3 的准入、P1B 登记、固定本地键 1—3、单次提交和独立读取过程，只把写集键来源改为：

```text
初始场景创建请求.幂等身份
-> 校验 L2 身份值域
-> 以服务域 0x02 映射私有 L1 键
-> 写入 L1写集请求.幂等键
```

创建结果与公开独立读取结果不得携带映射键。写入返回的新编码映射仍只能作为形成独立读取请求的临时材料，最终成功事实仍来自 `读取初始场景` 的逐项同代次读回。

## 8. 验证矩阵

在原 10 项世界登记专项和 12 项初始场景专项基础上增加并冻结：

1. 世界操作身份零值和超过 56 位拒绝且 L1 零变化；
2. 两个服务使用相同业务身份值均能成功，L1 审计中分别出现 `0x01`、`0x02` 域键；
3. L2 结果和登记只回显业务身份，不回显 L1 键；
4. 世界登记 v1 与初始场景 v1 请求均入口拒绝；
5. 两个 L2 数据头对 `写集幂等键|写集本地键|L1写集请求|L1事实基座仓库` 静态零命中；
6. 动作返回事实与再次公开读取全等，任何预计编码或预计代次不能直接成为成功事实。

专项仍由现有两个自检模块承载；完整自检登记总数保持 25，WORLD-STRUCTURE 顺序保持 300。Debug/Release Rebuild、两配置完整自检、strict、MSVC 模块闭包和精确 diff check 必须全部通过。
