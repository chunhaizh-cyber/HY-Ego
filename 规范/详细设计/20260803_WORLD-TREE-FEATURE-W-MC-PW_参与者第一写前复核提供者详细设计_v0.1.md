## 1. 目标、范围与完成条件

目标是在已发布的类型化结构事务参与者桥接中增加一个真实的“第一写前复核”阶段，使未来 4170 参与者可以在事务域独占许可已取得、任一核心候选形成前，读取自己的已发布事实并建立可撤销的私有预复核状态。

完成必须同时满足：新 DTO 和纯虚调用合同进入执行器模块；六个非空参与者业务分支都在最后静态准入之后、首笔核心候选之前调用；失败参与者自身也逆序撤销；预复核后任意核心失败仍撤销所有已预复核参与者；撤销失败尽力继续并隔离；113项顶层自检身份和数量不变，专项扩展原位进入顺序170。

本设计不新增领域参与者、不实现4170仓、不改数据操作公开入口、不新增顶层自检、不改变现有状态1—9的数值和外层八状态。

## 4. 参与者权限和生命周期

参与者在 `第一写前复核` 中可以取得并释放自身仓锁、读取自身已发布事实、建立仅参与者私有且能由 `完成撤销()` 清理的预复核状态。它不得接触核心仓锁或许可对象，不得形成核心候选，不得读取候选读回或计划身份见证。

只要执行器已经调用某参与者，该参与者就进入本事务的撤销义务域，包括它返回非成功或抛异常的本次调用。参与者必须让 `完成撤销()` 对“只经历预复核”“预复核成功但未准备”“准备中失败”“已准备”都安全、幂等地清理自己的未发布状态。

## 5. 私有辅助函数

新增：

```cpp
static 节点直接类型化结构事务参与者结果
安全第一写前复核类型化结构参与者_(
    节点直接类型化结构事务参与者& 参与者,
    const 节点直接类型化结构第一写前复核只读视图& 视图) noexcept;

static 节点直接类型化结构事务参与者状态
第一写前复核类型化结构参与者组_(
    const 节点直接类型化结构数据操作请求& 请求,
    std::uint64_t 事务序号,
    std::uint64_t 当前事实截止代次,
    std::span<节点直接类型化结构事务参与者* const> 参与者组,
    std::size_t& 已进入事务参与者数量) noexcept;
```

安全包装把任意异常映射为参与者 `内部不一致`。组函数先把计数清零；空组返回 `第一写前已复核`。非空组按登记顺序调用，每次调用前把计数推进到当前项，因此第一个参与者失败时计数也是1。非10状态原样返回。

六个分支现有的 `已触及参与者数量` 统一改名/扩义为 `已进入事务参与者数量`。预复核全部成功后它固定为参与者总数；现有准备函数不得把它清零或缩小。现有逆序撤销函数继续消费该计数，从而覆盖“只预复核、未准备”的参与者。

## 6. 六分支机械重排

共同顺序固定为：

```text
分支形状已识别
-> 完成分支现有静态/当前事实预扫描
-> 第一写前复核类型化结构参与者组_
-> 形成业务候选
-> 形成幂等候选
-> 准备类型化结构参与者组_
-> 现有确认/发布
```

### 6.1 仅含类型合同

保留计划合同构造和排序。排序后先按项执行完整只读预扫描：

1. 调用 `读取精确合同(合同身份, 合同版本)`；有命中时必须用现有 `类型合同写项静态内容等于读回_` 区分同义与异义并保留诊断证据，但两者均保持当前候选外层映射为 `入口拒绝`，不得调用参与者。
2. 对每个首次出现的合同身份命名域调用一次 `读取命名域高水位`，建立本请求私有的每域模拟高水位；计划合同按既有排序逐项验证 `键值 == 模拟高水位 + 1`，高水位饱和或不连续映射 `版本漂移`，通过一项后只推进模拟值，不形成仓候选。
3. 本请求内同身份同版本重复、同键跨版本或排序后不能满足上述连续性时，按现有静态/高水位分类在预复核前拒绝。

复核切点在全部精确占用和模拟高水位检查完成后、首次 `结构化发布合同未发布候选` 前。通过后按现有顺序建立合同候选和幂等候选；预复核后候选仍返回非 `已形成候选` 表示同许可内不变量漂移，按候选原状态进入现有失败收口，不得重跑参与者。

### 6.2 仅含关系失效

把当前逐项“读取当前关系 -> 立即建候选”拆为两遍。第一遍对全部项完成排序、重复拒绝、当前有效和版本上限检查，保存正式关系句柄和失效后见证；随后预复核；第二遍只按已冻结句柄形成候选。任一第一遍失败时不调用参与者且零候选。

### 6.3 仅含类型化值退役

把当前逐项“读取当前值 -> 立即建候选”拆为两遍。第一遍完成全部所属身份当前值匹配并保存 `退役前值组`；随后预复核；第二遍从该值式副本按顺序形成退役候选。不得在预复核后重新选择另一个当前值替代预扫描结果。

### 6.4 仅含类型化值发布

第一遍完成全部映射、所属节点当前性、合同可写性、材料、来源、同所属+合同唯一性和预期当前版本检查，形成完整 `值结果组/计划值组`，但不调用 `结构化发布值未发布候选`。随后预复核，再遍历计划值形成候选。计划值的来源、版本和目标代次不能在预复核后重算为另一语义。

### 6.5 仅含索引和节点删除

第一遍完成全部索引创建目标当前性、索引移除前态（复用统一动态准入的同许可结果或等价显式复核）、删除节点当前见证和版本检查，形成索引操作计划与删除句柄计划。每个索引创建项还必须在同一事务许可下调用 `读取索引物理键(键, 事务序号)`：未命中才允许进入计划；命中时比较目标种类和稳定目标，记录同义或异义分类，但两者都保持当前候选外层映射为 `入口拒绝`。本请求内重复创建键或创建/移除同键由现有静态完整性在预复核前拒绝。随后预复核，再依现有“索引组、删除组”顺序形成候选。索引创建和移除都不得在预复核前形成候选；预复核后候选发现键占用只可能是同许可不变量漂移，进入现有失败收口。

### 6.6 仅含节点关系和索引创建

第一遍验证全部计划映射、命名域、稳定键、局部端点引用闭包、外部端点当前见证和索引目标引用，形成不依赖候选句柄的节点/关系/索引计划。对每个索引创建项，以计划中的稳定目标调用 `读取索引物理键(键, 事务序号)` 完成键占用预扫描；未命中才继续，命中同义/异义均映射 `入口拒绝`，不得等待局部节点候选建立后才判断键冲突。局部新节点的稳定见证可由冻结映射、类型和初始版本1形成，但物理句柄必须等节点候选建立后绑定。随后预复核，再按现有节点 -> 关系 -> 索引顺序形成候选。不得为了预复核暴露或虚构候选句柄。

### 6.7 不接入分支

空域治理、固定混合原子写形状和旧入口空参与者路径保持现状。它们没有非空类型化参与者，不得为形式统一新增无意义调用或改变其候选顺序。

## 7. 失败、撤销和隔离

1. 参与者预复核返回 `入口拒绝/版本漂移/许可拒绝/资源失败`：先逆序撤销已进入组；撤销及现有持久未发布收口全部成功后，复用 `映射类型化结构参与者失败_` 返回对应外层状态。
2. 返回其它非10状态或抛异常：首次失败按 `内部不一致`；仍执行同一撤销闭环。
3. 任一参与者撤销失败/异常：继续逆序尝试剩余已进入项；不得提前停止。最终不得把首次普通分类返回给调用方，必须标记许可隔离并返回外层 `内部不一致`。
4. 预复核全部成功后，业务候选、幂等候选、结果编码、准备或确认任一步失败：现有统一失败路径以 `已进入事务参与者数量 == 参与者组.size()` 撤销全部参与者，再撤销幂等和业务候选。
5. 只有参与者、幂等和业务候选全部撤销，且持久端确认未发布见证并清除临时侧账，才返回首次失败。否则隔离并返回 `内部不一致`。
6. 所有预复核非成功路径保持零业务载荷、零已发布事实变化和零代次推进。

## 8. 自检设计

只扩展现有 `类型化事务自检参与者` 和 `WORLD-FEATURE-W-MC-A01—A12` 内部证据，不新增顶层报告项，不改变113个名称和顺序。测试参与者增加真实 `第一写前复核` override、预复核故障点、视图捕获和阶段记录。

专项覆盖：

1. 状态10且旧1—9数值不变。
2. 视图四字段准确；静态证明无候选读回、计划见证、仓、许可和锁。
3. 六个非空分支都在独占许可后、首个核心候选前真实调用。
4. 多参与者按登记顺序；第一、中间、最后失败分别覆盖。
5. 当前失败参与者自身也撤销；未调用后继不撤销；撤销顺序严格逆序。
6. 撤销失败后仍继续清理更早参与者，并隔离、返回内部不一致。
7. 预复核成功后注入首个业务候选/幂等候选/准备失败，证明全部已预复核参与者撤销。
8. 异常映射和四类现有参与者失败映射不漂移。
9. 预复核失败时零核心候选、零仓权威变化、零代次推进、零业务载荷。
10. 原准备、确认、完成发布顺序和六分支旧成功/失败结果不漂移。
11. 无默认成功 virtual、无旁路调用、无第三正式派生类遗漏。
12. 顶层113项总数、顺序170身份和旧专项名称不变。
13. 类型合同已存在同义/异义、每域高水位连续/断序/饱和，以及两类索引创建分支的未占用/已占用同义/异义，均在参与者调用前完成分类；这些预扫描拒绝时参与者零调用、零撤销。
