# L1-SIMPLIFY-P1B 世界登记与初始场景详细设计 v0.1

创建侧代码基线：`31593f880ca01f249256bd3edf64cb75a26e2b23`。

## 1. 目标、范围与完成条件

本叶在新 L1 三类事实基座上建立第一个真实 L2 提供者：`世界登记服务`。它只在确认 L1 当前完整快照为空时，向 `L1事实基座服务` 提交一个固定写集，原子建立世界结构的最小语义，并只在读回验证成功后保存值式 `世界结构登记`。

完成条件是：隔离 `L1事实基座服务` 中可以建立并读回一份完整登记，重复同请求不推进事实代次，同键异义、非空 L1、错误合同和服务重建均不能产生扫描、猜测或补造。它不接入运行期上下文或生产启动，也不创建子场景、存在、特征、状态、动态、SQL / 材料恢复或旧世界树兼容入口。

## 2. 事实写集与登记 DTO

一次首次成功的 `L1写集请求` 固定如下；所有本地键、种类、表示、归属和来源都是本叶公开合同，执行者不得临时选择替代形状。

| 本地键 | 写集项目 | 固定内容 |
| --- | --- | --- |
| 1 | 节点 | 服务身份普通节点 |
| 2 | 节点 | 场景标记属性类型节点，表示为 `I64` |
| 3 | 节点 | 直接父场景关系类型普通节点 |
| 4 | 节点 | 直接成员关系类型普通节点 |
| 5 | 节点 | 根场景普通节点 |
| 6 | 值 | 所属根场景(5)、属性类型(2)、材料 `I64{1}`、来源服务身份(1) |
| — | 属性槽变更 | 所属根场景(5)、属性类型(2)、新当前值(6) |

写集不含关系、退出事实或其它节点、值、槽。`期望事实代次` 必须等于提交前完整快照代次，首次建立时该快照同时必须满足：事实代次为 0、当前节点/关系/值和永久占用编码均为空。任何非空或不能成功读取的 L1 快照均不允许建立。

新增头文件 `领域/世界登记.数据.h` 固定声明下列纯值类型；它只包含 `../核心/L1事实基座.数据.h` 和所需标准头，不包含旧节点直接合同、SQL、材料、运行期上下文或任何仓库头。

```cpp
inline constexpr std::uint32_t 世界登记合同版本 = 1;
inline constexpr std::uint32_t 世界登记规则版本 = 1;

struct 世界结构登记 final {
    std::uint32_t 合同版本 = 世界登记合同版本;
    std::uint32_t 世界规则版本 = 世界登记规则版本;
    写集幂等键 首次幂等键;
    std::uint64_t 已验证事实代次 = 0;
    稳定编码 服务身份;
    稳定编码 场景标记属性类型;
    稳定编码 直接父场景关系类型;
    稳定编码 直接成员关系类型;
    稳定编码 世界根场景;
};

struct 世界登记建立请求 final {
    std::uint32_t 合同版本 = 世界登记合同版本;
    std::uint32_t 世界规则版本 = 世界登记规则版本;
    写集幂等键 幂等键;
    std::uint64_t 期望事实代次 = 0;
};

enum class 世界登记状态 : std::uint8_t {
    已提交 = 1, 幂等读回 = 2, 已读取 = 3, 登记未加载 = 4,
    入口拒绝 = 5, 幂等冲突 = 6, 事实代次漂移 = 7,
    许可拒绝 = 8, 资源失败 = 9, 内部不一致 = 10
};

struct 世界登记结果 final {
    世界登记状态 状态 = 世界登记状态::入口拒绝;
    std::optional<世界结构登记> 登记;
};
```

四种全等只使用默认 `operator==`：`世界结构登记`、`世界登记建立请求`、`世界登记结果` 和其成员值类型。登记完整当且仅当：合同/规则均为 1、幂等键非零、已验证事实代次非零、五个稳定编码均非零且两两不同。非成功结果 `登记` 必须为空。

`世界登记状态` 与 4200 的稳定结果编号对齐。P1B 不使用 `许可拒绝`，但不得改写或压缩其稳定值；`登记未加载` 是本服务的“未找到已保存登记”语义，不表示 L1 扫描未找到世界根。

```cpp
class 世界登记服务 final {
public:
    explicit 世界登记服务(L1事实基座服务& L1) noexcept;
    世界登记服务(const 世界登记服务&) = delete;
    世界登记服务& operator=(const 世界登记服务&) = delete;

    世界登记结果 建立空世界(const 世界登记建立请求& 请求);
    世界登记结果 读取当前登记() const;
private:
    L1事实基座服务& L1_;
    mutable std::mutex 锁_;
    std::optional<世界登记建立请求> 首次请求_;
    std::optional<世界结构登记> 登记_;
};
```

服务只有上述两项导出成员。`读取当前登记` 只在本服务锁内复制 `登记_`：有登记返回 `已读取 + 登记`，没有登记返回 `登记未加载 + 空`；不得读取 L1、扫描、按名称匹配、回源恢复或构造默认根。

## 4. `建立空世界` 的机械分支

调用全程持有本服务的 `锁_`，但该锁不跨越其它 L1 调用者；L1 的原子边界只由一次 `提交写集` 形成。

1. 若请求合同/规则不是 1、幂等键为零，返回 `入口拒绝 + 空`，零 L1 调用。
2. 若 `首次请求_` 已保存：完全相等时返回 `幂等读回 + 已保存登记`；不同请求（包括同键异义、不同期望代次或合同）返回 `幂等冲突 + 空`。不读取或写入 L1。
3. 调用 `L1_.读取完整快照()`。L1 非成功映射为：`资源失败 -> 资源失败`，`内部不一致 -> 内部不一致`，其余 -> `入口拒绝`；快照缺失同样为 `内部不一致`。快照不为空、请求期望代次不等于快照代次、或首次代次不为 0，均返回 `入口拒绝 + 空`，零写入。
4. 按第 2 节固定本地键形成唯一写集并调用一次 `L1_.提交写集`。L1 `成功` 或 `精确重复` 才进入下一步；`幂等冲突 -> 幂等冲突`、`事实代次漂移 -> 事实代次漂移`、`资源失败 -> 资源失败`、`内部不一致 -> 内部不一致`，其余非成功 -> `入口拒绝`。不得为了成功而换键、重新取快照或第二次写入。
5. 对 L1 返回的 `新编码映射` 按本地键查找 1—6，逐项确认每键仅出现一次、没有零编码、共六项且六编码两两不同。键 1—5 形成登记五编码，键 6 只用于读回；任何映射缺失、重复或多余均返回 `内部不一致 + 空`。
6. 立即再次调用 `L1_.读取完整快照()`，并要求成功、有快照、代次严格等于本次 `L1写入结果.事实代次`，以及快照精确为五当前节点、零当前关系、一个当前值、六个永久占用编码。逐字段验证第 2 节固定形状、创建代次均为本次代次、无退出事实、根的唯一属性槽和值/来源/表示完全匹配。失败且读回代次不同返回 `事实代次漂移`；其它读回错误或形状矛盾返回 `内部不一致`。此分支不保存登记。
7. 仅第 6 步成功后，以本次请求和登记在锁内一次保存 `首次请求_`、`登记_`，返回 `已提交 + 登记`。保存中资源异常返回 `资源失败 + 空`，未知异常返回 `内部不一致 + 空`；调用方必须以同一请求重试，L1 的精确重复映射可重新验证并保存登记。

第 6 步的严格同代次读回是有意门禁，不假设 `世界登记服务` 的本地锁能阻止其它 L1 写入者。若另一个合法写入在本次提交后先完成，P1B 不谎称“完整读回”，而是报告 `事实代次漂移`；已由 L1 原子发布的写集不回滚、不扫描、不换键。同一请求重试只有在读回稳定时才可形成登记。后继运行期装配必须在本服务成为唯一初始化写方前，另行冻结 L1 写入所有权；这不属于 P1B。

## 5. 自检、工程与验证

`自检.世界登记.ixx` 导出 `世界登记自检报告{验收, 失败数量, 总通过}` 和 `运行世界登记自检()`。它创建隔离 `L1事实基座服务` 与 `世界登记服务`，不使用运行期上下文或旧仓。固定 10 项验收：

1. 空服务读取返回 `登记未加载` 且无 L1 事实；
2. 合同/规则/零幂等键拒绝且 L1 仍为空；
3. 空域首次建立返回 `已提交`、事实代次 1 的登记和五个互异编码；
4. L1 完整快照精确为五节点、零关系、一值、一根槽和六永久编码；
5. 根槽和值的所属、类型、`I64=1`、来源、创建代次和当前性完整；
6. `读取当前登记` 逐字段等于首次登记；
7. 同一请求返回 `幂等读回`，L1 事实代次和快照不推进；
8. 同键异义（只变期望代次）返回 `幂等冲突`，零变化；
9. 对预先用中性写集写成非空的 L1，建立返回 `入口拒绝`，不附加世界事实；
10. 新 `世界登记服务` 指向已建立 L1 仍只返回 `登记未加载`，零 L1 扫描或写入。

工程登记精确增加三个 `ClCompile`：`领域/服务.世界登记.ixx`、`领域/自检.世界登记.ixx`（位于现有 L1 三模块之后、旧领域模块之前），并增加一个 `ClInclude`：`领域/世界登记.数据.h`（位于 `核心/L1事实基座.数据.h` 之后）。`启动.应用程序.ixx` 新增自检模块导入、包装函数和唯一顺序 290 的 `L1-SIMPLIFY-P1B-S01`；完整自检总数与成功条件从 23 精确变为 24。

执行验证固定为 `git diff --check`、`python .\\tools\\check_specs.py --strict`、Debug / Release x64 Rebuild、两配置 `--self-test-exit` 和 `扫描.MSVC模块依赖.ps1 -配置 Debug -平台 x64`。静态核对新模块三处一致、顺序 290 唯一、完整自检 24/24、十项专项矩阵、以及零旧世界/节点直接/SQL/材料/运行期上下文导入。

## 6. 完成声明边界

本叶只证明隔离 L2 世界登记服务可以在新 L1 中建立并验证最小世界根语义。它不证明持久恢复登记、运行期装配、生产启动、场景成员、存在、特征、状态、动态、同代次世界快照、旧基座删除或集成验收。
