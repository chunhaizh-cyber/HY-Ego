# SYSTEM-WORLD-TREE-ROOT-PUBLISH-I1 系统具名场景树根补验可构造反例详细设计 v0.5

日期：2026-08-13

## 1. 来源问题与裁决

本修订只处理 `DRIFT-I1-V04-NON_SUCCESS-SUCCESS-PREDICATE-UNCONSTRUCTIBLE`。执行者在正式 `877cb54727d2c675390d0a89031335abd687af3a` 的 v0.4 组 5A 机械确认：

- `L2场景树结构登记结果::成功()` 只可能接受 `已提交 / 精确重复 / 已读取` 中与载荷形状匹配的成功枚举；
- `L2场景树节点写入结果::成功()` 只可能接受 `已提交 / 精确重复`；
- `L2场景树读取结果::成功()` 只可能接受 `已读取`；
- 因此“非成功枚举却令上述 `成功()==true`”不是可构造 C++ DTO 状态。

v0.4 详细设计第 4 节中该措辞失效。v0.5 将其替换为可构造且保持同一防御目标的反例：**非成功枚举即使人为携带一份完整成功载荷，对应 L2 `成功()` 仍必须为 false，I1 必须在该阶段拒绝且不得越过、不得发布。** 禁止继续要求构造逻辑上不可能的 `非成功枚举 && 成功()==true`。

这是验证输入形状修正，不改变 I1 生产状态机、公开 ABI、机器语义、`.inl` 物理合同、九条白名单、四层证据、其它七组矩阵或 `NOT_RUN` 边界。I2 继续冻结。

## 3. 组 5A 可构造反例冻结

v0.4 第 4 节“L2 成功谓词先拒绝”中的 `非成功枚举却 成功()` 精确替换为：

```text
对登记结果、根写结果、整树读取结果分别：
1. 从一份本来能通过该 DTO 成功谓词的完整载荷形状出发；
2. 只把结果头状态替换为该阶段具名非成功枚举；
3. 保持成功载荷 optional 和逐字段材料仍存在；
4. 先独立断言对应 L2结果.成功() == false；
5. 再把该结果作为脚本 provider 的本阶段返回；
6. 断言 I1 返回该阶段具名失败、调用序列立即截止、后继调用为零；
7. 断言 I1 结果 optional 格只反映实际发生阶段，发布槽不形成新值；
8. 按首次 / 待收敛 / 已发布重复路径检查待收敛槽与旧发布值守恒。
```

至少覆盖：

| 阶段 | 非成功枚举示例 | 完整载荷 | L2先验 | I1预期 |
| --- | --- | --- | --- | --- |
| 首次登记 | `内部不一致` | 保留完整登记 | `成功()==false` | `树结构登记读取失败`，根写及后继零调用，发布槽仍空 |
| 根建立 | `资源失败` | 保留树、场景节点与合法根形状 | `成功()==false` | `根建立失败`，后二登 / 整树零调用，原待收敛请求保留 |
| 后二次登记 | `事实代次漂移` | 保留完整登记 | `成功()==false` | `树结构登记读取失败`，整树零调用；首次空发布槽或重复旧值守恒 |
| 整树读取 | `内部不一致` | 保留完整整树 | `成功()==false` | `根正式读回失败`，不发布新值；首次空槽或重复旧值守恒 |

具体非成功枚举可以按阶段合法返回集合增加，但不得选择该 DTO `成功()` 接受的成功枚举，也不得伪造 `成功()` 实现或绕过公开 DTO 方法。

## 4. 不变矩阵

以下要求不因本修订降低：

- 成功枚举配缺失必要 optional / 错截止 / 不完整载荷仍逐项由 L2 成功谓词先拒绝；
- 首次路径和待收敛路径所接受的成功枚举 / 来源不匹配仍由 I1 路径谓词拒绝；
- 树身份、根标记类别与三个端点、根父关系、首次场景 / 树归属生命周期、各跨结果错截止仍逐个由 I1 互证拒绝；
- 精确可重组谓词、其它漂移和非成功保留、损坏私有槽防御、首次空槽与重复旧值守恒、调用序列、optional 格、四层证据和逐用例独立输出全部不变；
- 第 1—7 组动态强制项仍不得 `NOT_RUN`。

## 5. 证据与完成边界

组 5A 每个用例仍独立输出输入脚本、调用序列、L2 `成功()` 先验、I1 状态与六 optional 格、两状态槽前后。记录必须明确写“可构造的非成功枚举 + 完整成功载荷被 L2 成功谓词拒绝”，不得写成已验证不可构造状态。

本修订只证明验证合同可构造，不证明生产实现、完整矩阵、构建、运行或 I1 已接受退出。允许 `NOT_RUN` 仍严格沿用 v0.4，不得覆盖本文件要求。
