## 1. 目标、边界与依据

扩展既有`新_需求类::读取正式信息参数保护(D,C)`：在一次owner保护读取内交付需求现有15项直接内容；直接目标交付既有正式owner能够合法出具的FT/FC/RC完整值式定义；引用内容目标只保留原定位、原15槽、目标FT定义及已有引用/承载保护，不展开其目标域。业务层无需再次分时读取FC/RC或查询底座拼义，即可决定能否形成H，不能把未展开定位冒充完整语义。

不新增`读取需求目标内容保护()`、平行完整目标DTO、H专用需求、公开写服务、持久字段、迁移、事实代次、合同版本或引用保活承诺。需求主体与目标存在保持分离；值/域及关系与增加/减少方向严格互斥。H首期只消费I64准确值、单闭区间、增加/减少及需求陈述/确认，本提供者不把其它合法目标删掉或改义。

依据：用户当前具名裁决；[0050](../0050_项目通用机器逻辑与禁止性规则总纲_20260721.md)第1.1、1.2、3.1、3.2、9节；[3100](../3100_根规范_需求.md)第1、2、9节；[5170](../5170_子规范_需求治理详细合同.md)第2、4、7节；[7160](../7160_子规范_特征概念形成组织与名称关联.md)；既有FC/RC正式读取合同。跨owner读取后的最终联合核验留在D owner内部，不让业务解析私有schema。

这不是本能方法：零世界或治理事实写入、零动作动态形成；不改变需求满足状态、任务或方法。读取到需求不等于确认其成立、允许执行或目标已经达到。

## 4. 唯一公开合同变更

物理位置：`海中鱼巣/领域/信息内容.数据.h`。只新增以下值式类型，并在现有投影末尾追加字段；既有前三字段位置及reader签名、状态枚举保持不变：

```cpp
// 附加语义是否足够解释本次已读信息；不表示H可表达、需求已满足或已获确认。
enum class 正式引用概念语义状态 : std::uint8_t {
    完整 = 1,
    部分 = 2,
    引用内容未展开 = 3
};
struct 正式内容引用定位 final {
    稳定编码 信息节点;
    std::vector<稳定编码> 正式内容路径;
};
struct 正式引用概念语义 final {
    正式引用概念语义状态 状态 = 正式引用概念语义状态::部分;
    std::vector<特征概念定义保护信息> 特征概念定义组;
    std::vector<二次特征概念信息> 二次特征定义组;
    std::optional<正式内容引用定位> 引用内容定位;
};
struct 正式信息参数投影 final {
    稳定编码 信息节点, 类别概念;
    std::vector<正式直接内容项> 直接内容组;
    std::optional<正式引用概念语义> 引用概念语义;
};
```

附加语义是直接目标现有引用所指定义的值式闭包，或显式未展开的引用目标材料；不重新声明目标存在/形式/值域/方向字段，这些仍唯一取15槽。同节点只出现一次，特征定义组按`定义.节点`、二次定义组按`节点`稳定编码升序。FC项保留原`定义`和`类型根`，RC项保留原`节点/二次特征类型根节点/输出特征概念/算法/输入定义组/参照/结果域种类组`，不裁掉单位、值域variant或输入顺序。引用分支的域C只保留原身份，不作为FC定义入组，二次定义组为空；其特征定义组只包含已合法取得的目标FT及类型根定义。

顶层`读取状态::已读取`仍仅表示正式身份及约定直接内容已读，不能由此推定附加语义存在、完整或支持H；所有非`已读取`结果必须`信息==nullopt && 完整保护组.empty()`，不夹带成功材料。成功但语义部分/引用未展开有真实15槽及原材料，不是伪造“完整H”。

### 4.1 三种状态及未提供

| 材料 | 唯一解释及允许载荷 |
| --- | --- |
| `引用概念语义==nullopt` | 当前reader未提供引用语义；旧模拟reader默认属于此类，禁止H补查现实数据冒充已完整 |
| `完整` | 原完整目标无引用定位；所需定义及本次目标不变量均核验，D owner最终联合核验通过；不等于H语言模式支持 |
| `部分` | 无引用定位的正式被认知D仍有未知必需目标字段；直接目标已知FT/FC/RC引用的定义经现有owner合法取得并保护；不补造缺字段，不生成完整H |
| `引用内容未展开` | 原完整目标带引用内容定位；保留信息身份、15槽、原路径、目标FT定义和已有引用/承载保护。域C可能是CE结构概念，不经FC或CE展开，不强求RC；不宣称该域完整语义已交付，业务返回目标形态未支持 |

自我执行D不存在合法“部分成功”分支，核心字段缺失或物理形状损坏走工程中断。方向目标值域及比较是不适用，不作为未知；它的完整语义仍必须交付目标FT定义及单位依据。合法非I64、多段域或集合等，只有既有正式owner实际合法出具了全部必要定义时才可交付`完整`；H适配器按自己首期闭集返回未支持，不能反过来称D损坏。RC算法11/12的既有工程读取缺口不是业务“部分/未支持”，见第6.3节。

### 4.2 引用定位适配

只在D.cpp内部：`原目标.引用内容定位->引用需求节点`原样进入`正式内容引用定位::信息节点`；`正式内容路径`逐项、原顺序、原重复值复制，绝不排序、去重、截断或只取末项。原D `新需求引用内容定位`与其writer/解码合同保持不变。这个通用结构既不是第二个目标DTO，也不建立任何生产节点。

路径不展开，不能递归调用该reader、引用内容求值器、CE结构定义展开或业务确认服务来获得伪完整H；必须先保存该定位并在目标域采集前分支，再进入`引用内容未展开`状态。域C原身份和已有快照保护保留，不把C经FC reader强读，也不凭无RC判坏。若领域解码确认定位自身损坏，属于工程结构错误而非未支持。

## 6. D读取顺序和算法

1. 保留先天需求根C身份读取及范围判定。仍只支持该根，不顺便开放子概念符合性。D不存在/异类的现有状态不变。
2. 需求锁内按当前路径取得D、身份、五目标F承载与原始保护，解码原`新需求治理信息`。保留现有自我分支自身引用快照/父引用；保留被认知分支直接内容reader、主体/确认来源核验。**在进入任何本次新增FC/RC/E服务调用前释放需求锁。**
3. 按现有15槽读正式FT身份及保护，投影直接内容；不改变已有槽顺序或已知/不适用处理。被认知路径复用现有结果和保护。
4. 调私有采集器：自我必须有原完整目标；被认知完整目标优先，不存在完整目标时用原已知目标提取已知字段。若原完整目标包含引用定位，在任何部分视图构造及目标域FC/RC采集前先完成4.2节适配并选择**引用未展开分支**，不能抹去定位后按普通目标处理。
5. 主体E身份维持既有核验；目标E已知时由`加需求存在保护`核验并合并。两分支均读目标FT完整定义并要求其类型根就是目标FT；目标FT未知只允许被认知部分状态，不补默认FT。引用未展开分支到此停止新增语义采集：保留原路径、15槽、该FT定义及原引用/承载保护，语义状态固定`引用内容未展开`，直接跳第10步，**不得进入第6—9步**。该域C可能是CE结构概念，不经FC/RC读取、不强求RC、不调用求值器或CE展开。
6. **仅直接目标分支**：值域FC已知时通过FC正式口读定义和类型根；存在目标FT时要求同根。方向目标禁止FC/RC且方向仅增加/减少；直接值目标禁止方向，完整目标须FC/RC均存在。被认知部分字段形状沿原合法未知组合，不用方向的“不适用”充缺项。
7. **仅直接目标分支**：RC已知时通过RC正式口读其全部定义。读取并留存：RC本节点及其二次特征类型根的RC定义；二者的输出特征概念FC定义；所有非空参照FC定义；所有输入定义中非空特征概念的FC定义；以及上述每项的类型根FC定义。对FC读到类型根不同于自身时再读根一次，根必须自指类型根，不递归扫描概念树。所有读取均按节点去重、核对返回身份并合并保护；RC根不能被当作另一个目标比较关系。既有RC owner算法11/12局限按第6.3节处理，不自行改reader或白名单。
8. **仅直接目标分支**以本次缓存的根、完整RC和目标域执行现有`比较关系适用纯判据`同等判断：参照必须是目标FC；准确值来源输入须给出FT且归目标根，至少一个准确值输入。部分目标只能判断已知约束；无值域时不强加参照等值结论。输出FC及RC根定义都须已由正式owner合法读取并交付。不按“相等/在…之间”等词条判断，也不把已有RC合法性改成H首期算法白名单。
9. **仅直接目标分支**：原完整时按既有目标定义核验的全部字段约束得出`完整`；合法被认知缺项为`部分`。部分状态只对可判断的已知约束核验，不因缺FC/RC判坏。引用分支已在第5步跳过，绝不因它合法无RC而判为部分或坏目标。
10. 将缓存按稳定键转成值式定义组，赋给本次局部输出。确保采集的每项定义来源都有正式owner保护，原D、主体、目标E、先天槽、范围C、原F承载、原字段引用与新增定义保护全部合并；同节点快照不同立即返回前提已变化，绝不用后值覆盖前值。
11. **唯一最终提交点**：调用既有`需求内容保护未变(保护)`，由它一次共享锁批读整个联合集合，完整比较节点、字段及入/出关系。成功后才把局部输出移入结果。此前任何非成功均清空信息及保护；不循环重试、不设轮数兜底、不保持D锁跨owner调用。

原被认知reader为其原消费者仍可能提前做局部最终核验；它不能代替本reader的最后联合核验。本叶允许该既有重复读取，不为了省读而改其公开合同。完整输出的最后一次核验包含新收集全部定义，不能只复核D或裸FC引用节点。

### 6.1 并发与生命周期

本叶无写事务、无创建/撤销/删除/发布未知。结果是当前调用时的值式语义，不把返回保护当跨调用存活租约；之后若消费者需要持久确认或执行授权，依自己的正式合同重新核验。不同读取阶段同节点改变而合并冲突返回前提已变化；最终共享锁核验后马上发生的变化不伪造历史读取保证。现行保护没有事实代次和全程阻写语义，不新增ABA或历史见证承诺。
