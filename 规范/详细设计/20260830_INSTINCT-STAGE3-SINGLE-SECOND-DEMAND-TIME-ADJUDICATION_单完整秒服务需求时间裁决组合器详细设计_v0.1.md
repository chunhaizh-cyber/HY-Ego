# INSTINCT-STAGE3-SINGLE-SECOND-DEMAND-TIME-ADJUDICATION 单完整秒服务需求时间裁决组合器详细设计 v0.1

日期：2026-08-30

设计身份：`INSTINCT-STAGE3-SINGLE-SECOND-DEMAND-TIME-ADJUDICATION`

## 1. 目标与完成边界

组合现有 `本能被动维护基础快照组合器` 与唯一 `服务合同事实权威服务`，在同一非零事实截止 `G0` 下形成当前维护完整秒所需的服务需求时间裁决：当前有效未满足需求数量、最长等待完整秒、全部并列最长来源、本秒到期未满足事件数量和 `服务维护需求裁决_v1`。

本叶只读并形成值式结果，不调用单秒规则内核，不改变服务值 `V`、安全根值 `A`、维护游标、状态或动态，不裁决有效服务活动、主动安全结算或低位回升门禁，也不解决多秒批量分段。当前生产安全根定义版本 1 保持不变：值域 `0..I64_MAX`，`L=2,767,011,611,056,432,742`，`H=7,378,697,629,483,820,645`；“浮动”只表示未来可以发布新定义版本，运行期不得自行变化。

## 2. 正式依据与当前事实

正式依据：0050 v2.1、6130 v0.10、6160 v0.4、6170 v0.6。

创建基线：`main == origin/main == 8fda31978fcd8ccfd50845b74119562087de1900`，index 空。

当前已有：

```text

到期事件合同终态完整集合

单完整秒规则内核
= 消费需求裁决、有效数量、最长等待、本秒事件数量及其它独立门禁
```

当前缺少的是上述三个正式读取结果到单秒规则内核需求字段的唯一上层组合。该组合不得从合同数量之外的任务、线程、日志或缓存补造需求，也不得把所有历史到期事件计入本秒。

## 4. 数据合同

### 4.1 请求

```cpp
inline constexpr std::uint32_t
    本能单完整秒服务需求时间裁决合同版本_v1 = 1;

struct 本能单完整秒服务需求时间裁决读取请求_v1 final {
    std::uint32_t 合同版本;
    本能被动维护基础快照读取请求_v1 基础快照请求;
};
```

请求不重复携带自我、`G0`、运行代次或时间纪元；这些字段只从嵌套基础快照请求和其正式读回取得。

### 4.2 并列最长来源

```cpp
struct 服务需求最长等待来源_v1 final {
    服务合同身份_v1 合同;
    L2存在身份 提出者;
    L2需求身份 需求;
    std::int64_t 提出完整秒边界;
    std::int64_t 等待完整秒;
};
```

等待公式严格使用 6170 的正式提出边界：

```text
t = 当前维护完整秒边界 - 合同.提出完整秒边界
```

禁止改用有效开始边界、已消费秒、最后结算边界、任务等待时间或循环次数。有效开始边界仍作为“合同此刻已经生效”的闭包约束；若其晚于当前维护秒，整体返回 `时间材料不闭合`。

并列最长来源按以下键严格升序：

```text
提出完整秒边界
-> 提出者稳定身份
-> 需求稳定身份
-> 合同稳定身份（只作全序收口，不改变并列语义）
```

同一有效集合中的需求身份和合同身份必须分别唯一；违反时不得按数量重复计算。

### 4.3 裁决快照与结果

```cpp

    本能被动维护基础快照_v1 基础快照;

    std::int64_t 当前维护完整秒边界;
    服务维护需求裁决_v1 需求裁决;
    std::uint64_t 有效未满足需求数量;
    std::optional<std::int64_t> 最长等待完整秒;
```

完整性必须可从嵌套的两个完整集合及基础快照重新计算全部派生字段，不接受调用方提供的摘要或裸计数。

```text
当前性漂移
```

## 5. 当前秒裁决规则

1. 当前维护完整秒边界取基础快照的 `时间观察.当前完整秒边界`。
2. 每个有效未满足合同必须属于请求自我，合同时间纪元必须等于当前游标时间纪元；提出边界、有效开始边界和状态最后结算边界不得晚于当前维护秒。
3. 有效未满足需求数量按唯一需求身份计数；由于一个当前有效合同只能绑定一个需求，数量必须同时等于完整合同数。
4. 逐合同计算 `t`，取最大值并保留全部并列来源；0 合同时最长等待与并列来源均为空。
5. 到期事件完整集合是历史全集。只有 `原合同.时间纪元身份 == 当前游标.时间纪元身份` 且 `事件.到期完整秒边界 == 当前维护完整秒边界` 的事件进入本秒组；其它时间纪元的历史事件不比较边界，当前纪元的过去事件忽略，当前纪元的未来事件返回 `时间材料不闭合`。
6. 本秒事件的合同身份必须唯一，且不得仍出现在当前有效合同集合中。
7. 当前支持合同 / 到期事件规则版本 1；其它版本返回 `版本漂移`，不得套用版本 1 公式。
8. 最终裁决：

```text
本秒到期事件数量 > 0 或 最长等待 >= 2,592,000
-> 三十天门禁已成立

否则有效未满足需求数量 > 0
-> 存在未满观察窗需求

否则
-> 无有效未满足且无到期事件
```

## 6. 公开入口与固定流程

```cpp
class 本能单完整秒服务需求时间裁决组合器 final {
public:
    本能单完整秒服务需求时间裁决组合器(
        const 本能被动维护基础快照组合器&,
        const 服务合同事实权威服务&) noexcept;

    本能单完整秒服务需求时间裁决读取结果_v1
    读取当前维护秒服务需求时间裁决_v1(
        const 本能单完整秒服务需求时间裁决读取请求_v1&) const noexcept;
};
```

固定顺序：

```text
校验专属合同和嵌套请求
-> 第一次读取基础快照
-> 同 G0 读取当前有效未满足合同完整集合
-> 同 G0 读取到期事件合同终态完整集合
-> 第二次读取基础快照并与第一次逐字段相等
-> 校验时间纪元、当前秒、规则版本、唯一需求 / 合同
-> 计算数量、最长等待、并列来源和本秒事件
-> 形成需求裁决和完整快照
-> 返回已读取或无新完整秒
```

第二次基础快照用于捕获读取期间单调秒边界推进以及 A/V/L/H/游标漂移；任何差异统一返回 `当前性漂移`。不得只比较 `G0`，因为单调时钟推进不必产生 L1 事实代次。

## 7. 验证矩阵

至少覆盖：

1. 无新完整秒的完整成功但 `可维护=false`；
2. 0 合同 / 0 本秒事件的合法空裁决；
3. 单合同 `t=0`、`T-1`、`T` 和未来提出 / 未来有效开始；
4. N 合同不同等待、全部并列最长、稳定排序、需求或合同重复；
5. 当前纪元过去 / 当前 / 未来事件，以及其它纪元同数值边界不误计；
6. 本秒事件合同仍在有效集合、规则版本漂移、时间纪元漂移；
7. 两个 provider 的入口、结构、集合、引用、资源和内部错误映射；
8. 读取期间 `G0` 漂移和单调秒推进；
9. DTO 完整性拒绝伪造计数、最长值、来源组或事件组；
10. v143 x64 Debug / Release 根工程 Rebuild、专项、仓库外 Debug 和 Release `/GL + /LTCG` ABI consumer、strict 与两类 diff-check；
11. 静态确认没有生产 L/H 改动、新 owner、写入口、游标推进或规则内核调用。

## 8. 未解决边界

本结果只裁决基础快照所观察到的当前完整秒边界。若待维护区间包含多个完整秒，它不重建每个历史秒的合同活动集合，也不能单独证明批量结算与逐秒等价。有效服务活动、同秒主动安全裁决、低位回升安全门禁、服务准备补回、跨多秒事实分段和最终原子维护事务仍是后继叶。
