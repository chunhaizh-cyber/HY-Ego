## 2. 目标来源唯一裁决

4180/4130 要求目标判断明确绑定实际值和目标值，但没有要求每个比较叶都建立新的目标值注册服务。当前正式 P2/P3/P4 链只冻结：P2 I64 定义的当前下界/上界值，P3/P4 实例当前值始终位于闭区间 `[下界, 上界]`。当前 P6 DTO 和合同已经把 `I64目标输入见证` 的目标稳定编码固定为 P2 当前上界值；P6 原目标没有独立目标值登记入口、所有权或提供者计划。

因此本叶继续采用 **P2 当前上界作为目标状态**，并把该策略写成注册合同：

```text
左值 = P3/P4 实例槽当前 I64 值
右值 = P2 当前上界值
目标身份 = 合同.上界值
目标来源 = P2 定义登记.服务身份
目标创建代次 / 预计值 = 同一 L1 快照中的上界事实
```

执行者不得临场引入独立目标节点/值、放宽 P2/P3/P4 值域、改用下界或交换左右角色。若未来需要“独立目标值”语义，必须建立新的目标值来源与所有权计划，不属于本叶修订。

## 3. 可达分支与错误映射

第一笔比较前必须在同一完整快照中确认：左当前值和右上界值均为当前 I64 值，定义、属性类型、来源、代次、请求预计值和合同身份逐项匹配，并且两值均位于 P2 闭区间。成功矩阵固定为：

| 条件 | 结果 |
| --- | --- |
| 左值 < 上界值 | `已比较`，排序 `-1`，关系 `当前低于目标` |
| 左值 == 上界值 | `已比较`，排序 `0`，关系 `当前达到目标` |
| 左值 > 上界值 | `入口拒绝/值域不允许`，全部比较载荷为空 |

第三行是防御性合同分支，不是成功三态分支。按 P2/P3/P4 正式合同，合法当前值永不大于上界；因此专项不得通过越界写入或伪造快照宣称 `当前高于目标` 成功。若输入目标身份不是注册上界，返回 `入口拒绝/输入版本失效`；若右值材料、来源、属性类型或代次不符，同样返回结构化非成功。

差异仍只在请求包含差异位且顺序前置成立时计算 `右值 - 左值`；溢出返回 `入口拒绝/差异不可表示`，不影响仅请求排序或关系的合法成功。

## 4. DTO、写集与物理位置

P6 v0.2 的公共 DTO 和 L1 写集不变：服务登记为五普通节点加一个 I64 组属性类型节点；合同登记为一个注册节点、一个配置 I64 值、一个属性槽和八条节点目标关系；P2 标记/下界/上界值事实通过稳定编码及配置材料互证。`I64目标输入见证` 继续承载目标编码、来源、创建代次和预计值，但其合法值只能是合同 `上界值` 的同一当前事实。

代码位置、函数签名、依赖方向和禁止范围全部沿用 v0.2。没有新的 DTO 字段、模块、工程文件或提供者计划。

## 5. 验证矩阵修订

专项必须覆盖：

1. 左值严格小于上界的成功排序/关系/差异；
2. 左值等于上界的成功排序/关系/差异；
3. 越界左值、目标身份错配、目标来源错配、目标代次错配均结构化拒绝且零比较载荷；
4. 源码保留 `左 > 右` 防御判断，但不得把它标记为可由正式 P2/P3/P4 生命周期形成的成功用例；
5. P4 合法换代后仍以新当前值与同一 P2 上界比较，若低于或等于上界分别按前两项返回；
6. 其余 v0.2 的登记、读回、幂等、结构损坏、结果位、极值差异、并发和静态禁用项矩阵继续有效。
