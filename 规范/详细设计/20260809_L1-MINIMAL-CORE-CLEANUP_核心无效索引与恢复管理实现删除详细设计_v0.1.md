# L1 核心无效索引与恢复管理实现删除详细设计 v0.1

日期：2026-08-09

状态：正式设计候选

## 1. 目标和完成条件

本叶物理删除当前没有生产消费者的 L1 可重建索引，以及当前阶段明确不实施的恢复、审计和候选管理实现。删除后生产 L1 只继续承载现行中性 CRUD、仍有真实调用者的旧读取过渡面和同一内存事实状态；不建立兼容壳、固定未实现返回或替代自检。

完成必须同时满足：

1. 可重建索引的三个源码文件和工程登记全部消失，生产代码对其模块、类型和类零引用。
2. L1 服务公开面不再提供提供者身份、审计读取、恢复材料导出、恢复候选建立、确认和撤销。
3. 仓库不再保存旧恢复候选、旧审计账、旧领域结果见证状态和旧发布后失败见证；中性幂等账、当前 / 历史事实、永久编码占用和关系条件索引保留。
4. 当前仍有真实消费者的旧精确读取和完整快照过渡面暂时保留，并登记为下一清理叶，不在本叶制造编译断链。
5. Debug、Release、模块依赖扫描、生产启动和严格规范检查通过；不宣称崩溃或恢复能力。

## 2. 当前事实

正式基线为设计发布前实时 `main == origin/main`。创建侧扫描确认：

- `L1事实可重建索引` 只在自身模块中定义，没有生产构造者或调用者；其合同和数据头也只被该模块互相引用。
- 两个旧 L1 专项自检源码已经不存在，工程中没有残留引用。
- 审计读取、恢复材料导出、恢复候选建立、确认和撤销在服务外调用数均为零。
- `读取完整快照` 仍被状态、动态、特征比较、后继状态规格和方法登记根旧读取代码调用，不能在本叶连同旧读取类型直接删除。
- `海中鱼巣.vcxproj` 与 filters 存在另一所有者的双轴草案登记 WIP；本叶只能删除 L1 索引对应的独立行，并在暂存时排除该 WIP。

## 3. 保留、删除与迁移矩阵

| 对象 | 裁决 | 原因 / 后续 |
| --- | --- | --- |
| `L1公共事实.数据.h` 与合同模块 | 保留 | 稳定编码和节点种类是中性结构基础 |
| `L1中性CRUD.数据.h` 与合同模块 | 保留 | 现行唯一普通 CRUD 公开 DTO |
| `L1事实基座仓库::提交中性写集` | 保留 | 唯一普通写入口 |
| 中性当前、历史、关系条件、一致当前投影读取 | 保留 | 现行增删改查正式读取能力 |
| 中性幂等账、永久占用、当前 / 历史事实、源 / 目标关系条件索引 | 保留 | 中性 CRUD 正确性所需内部状态 |
| `L1可重建索引.数据.h`、合同模块、索引模块 | 删除 | 零消费者且保存第二份可重建视图，没有当前必要性 |
| `读取提供者身份` | 删除 | 零消费者，普通 CRUD 不需要服务身份见证 |
| 审计公开请求、结果和仓库读取 | 删除 | 当前不实施管理面，普通 CRUD 不消费 |
| 恢复材料、恢复结果、候选状态及四个恢复入口 | 删除 | 当前不考虑崩溃和跨进程恢复，未来重新设计 |
| 旧幂等账、审计账、领域结果见证状态、失败见证和隔离候选字段 | 删除 | 旧写入口已退出且这些状态无合法生产写入者 |
| 旧精确读取、完整快照和内部旧事实存储类型 | 暂留 | 仍有真实调用者；下一叶迁移到精确中性读取后删除 |
