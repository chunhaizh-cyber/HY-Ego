## 1. 本轮裁决与交付边界

本轮用户已授权直接实现以下闭合切片：服务值结算进入统一本能函数入口；初始化运行其登记部分，形成可查找方法头与服务根第一子需求；实际调用必须显式提供来源任务；方法普通动作确认服务值变化后，由任务 owner 以另一个内部治理动作将来源任务从已完成改为已结算。

两种修改分别说明如下：

| 动作 | 修改对象 | 原因与目的 | 唯一事实 owner |
| --- | --- | --- | --- |
| 服务值结算 | 现实世界自我存在的服务值特征 | 按本轮定义每次结算增加 1 | 世界树通过特征/状态/动态服务发布 |
| 标记任务已结算 | 来源任务 Vt 的任务状态特征 | 普通结算结果确认后结束这份任务的结算资格 | 任务类 |

二者必须是两个动作动态，不把任务状态修改藏进普通动作，也不把 Vt 冒充世界存在。结算前置业务条件只有来源任务当前状态为已完成；不增加旧 6190 的人类确认、归因、资格凭据等门槛。工程结构合法、真实来源、结果可读、阶段/所有权检查不是额外业务需求。

本轮不重定义首子需求目标。现有目标 `自我.服务值 = INT64_MAX` 仅迁移创建责任；不得声称一次 +1 已满足此需求。根需求目标、根链判断不变。初始化无来源任务，只登记和建立该首子需求，不加值、不造动作、不挑任意任务、不生成目标不明确的下级需求。来源任务自动发现、完整筹办自动产生下级需求不在本轮接线中。

`INT64_MAX` 饱和沿用旧函数：当前已达最大值则保持最大值，普通动作的独立读回确认该饱和结果后仍可收尾；不得发生有符号溢出。此分支不宣称实际增加了 1。

## 2. 当前事实与复用裁决

- `新_本能函数集::执行服务值结算(const 新服务值结算请求&)` 仍是专用入口，未注册统一函数表；其私有完成结算编码 map 是旧防重账，本轮删除。

- 任务管理线程保存旧专用函数指针，却没有实际调用该指针的生产语句；删除指针不是删除已接通业务链。

## 6. 本轮运行服务精确边界

业务运行服务负责装配、执行阶段与调用治理；本能函数负责自身声明、按参数场景读必要事实和交付本次条件结果对。服务不得拥有 world/task/method 的第二份事实。

公开 DTO 和入口放新增业务服务头中：

```cpp
struct 服务值结算初始化请求 final {
    稳定编码 自我所在场景, 自我存在, 服务值特征, 服务根需求;
    新需求目标定义 既有首子需求目标;
};
struct 服务值结算初始化结果 final {
    新方法操作状态 状态;
    std::optional<稳定编码> 方法节点, 结算服务需求;
};
struct 服务值结算调用请求 final {
    稳定编码 结算任务节点, 执行实例节点, 来源任务节点;
    新状态强时间 普通动作时间, 普通结果时间, 内部动作时间;
};
enum class 服务值结算推进状态 : std::uint8_t {
    已完成 = 1, 来源任务不具备, 来源任务已结算,
    入口拒绝, 已停止推进, 工程异常
};
struct 服务值结算调用结果 final {
    服务值结算推进状态 状态;
    std::optional<新本能函数本次条件结果对> 普通动作结果;

    std::optional<新任务虚拟存在读回> 来源任务读回;

class 服务值结算本能运行服务 final {
public:
    服务值结算初始化结果 初始化(
        const 服务值结算初始化请求&) noexcept;
    服务值结算调用结果 执行(
        const 服务值结算调用请求&) noexcept;

```

构造依赖为 world、method、task、demand、scene、dynamic、feature、feature-concept、secondary-concept 服务和工程错误报告端口；均为非拥有引用。普通应用构造唯一实例并装配到本能函数管理类；装配端口同实例精确重复、不同实例所有者冲突。运行服务不会自动扫描任务，不自行建立调用 X，不伪造方法采用授权。

函数内部不能只转发一个“执行结算全部逻辑”端口。管理类暴露的运行端口只负责提供只读登记材料及转发 owner 的细粒度操作：确保方法登记、确保首子需求、发布普通动作、更新服务值、读取服务值。方法声明的组装、登记/执行分支、动作前条件材料、仅新建动作才允许改变以及本次条件结果对的组装，必须在 `新_本能函数集.cpp` 的函数正文完成。外层独立读回和内部标记则在业务运行服务完成，不能放入普通本能函数正文。

调用请求中的结算任务是执行此本能方法的任务，来源任务是被结算任务，二者必须不同。X 必须经任务 owner 读回确认属于结算任务、方法为已登记结算方法并处于合法执行阶段；参数和结果读取方案已经由外层合法冻结。来源任务只通过明确参数选定，不以任务全集首项、最近完成或登记名推测。

本轮公开入口支持具名调用和专项验证；没有完成任务自动派送的生产触发器，不能报告自动结算闭环。

### 6.1 通用阶段控制的最小实现

不新增进度表、防重表、持久结算账或自动恢复框架。复用 4220 的动作来源唯一性和动作建立回执的新建/复用区别，控制真实动作只能从“新建动作”分支进入。

普通动作来源固定为明确传入的来源任务节点：其身份是本轮用户规定的单次完成任务治理来源，不另造结算凭据。内部标记动作来源固定为本次普通动作动态节点，表示“这个普通结算动作已经被独立确认”触发内部收尾。两个来源为不同正式身份；不能以时间、随机数、函数名或临时指针制造来源。

控制阶段为：准备→参数已核验→普通动作新建→普通结果已独立确认→内部动作新建→任务已结算→终结。登记模式不进入动作链。所有异常先设置本次返回的停止状态，再报告，不自动重新进入任何改变阶段。

动作建立返回复用时必须先读取来源任务：已结算只读返回；尚未结算时读取已有普通动作及其正式结果关系，仍不得再加值。本轮不做自动恢复收尾：明确报告“既有动作尚未完成收尾”工程异常并停止，由后续调试修复。相同来源的其它内容/时间冲突同样工程停止，不能换新来源绕过。

外层对同一服务实例的真实调用串行；task owner 的已结算写入再次 fresh 核验已完成。若外部治理在动作期间改变来源任务状态，收尾拒绝并工程停止，已经发生的普通结果保留；不宣称跨owner原子性。两个并发调用即使同时通过早期状态检查，动态owner的一来源一动作发布保证只有新建者允许加值，复用者不得执行改变。初始化与真实调用不得竞争。

外层 X 仅用于验证合法调用治理，不传给本能函数。本能函数从参数场景直接取得来源任务引用，因此不需要场景地址映射或隐式通用上下文。动作来源由该正式实参确定。

### 6.2 普通动作与内部收尾顺序

1. 校验请求身份及三时间严格递增、完整装配、合法 X 与已冻结结果读取方案。
2. fresh 读取来源 Vt。非完成/非已结算返回来源任务不具备；已结算零动作返回来源任务已结算。结构无值或类型错配是工程异常，不是业务不具备。
3. 通过只读参数场景记录源任务状态 F 和自我服务值 F 的实际前值。普通动作定义为方法节点，不再把需求节点当作方法动作定义。
4. world 建立普通动作并挂入自我场景；失败零服务值写入。随后调用现有更新特征并形成动态，显式传普通动作 ID。
5. 从 world owner 再读服务值 F，确认实际后值、正式状态/动态与来源；正常非饱和结果是前值+1。关联缺失、读回缺失或未知均停止，不改来源任务为已结算，也不重加。
6. 普通动作结果返回外层后，外层重新从正式 world owner 确认，不以函数局部成功状态代替验证。
7. 以普通动作动态为来源建立内部动作并挂入同一场景，目标为来源任务 Vt 状态 F。完成该发布后，task owner 唯一将已完成改为已结算并 fresh 读回。
8. 任务状态写入后聚合失败时复用现有 fresh 读回收敛，已读到已结算则不能再解释成未写。保留诊断缺口，不追加服务值。全部必要事实确认后返回已完成。

服务值更新成功但内部动作/状态写入失败时，真实世界服务值保留；不回滚真实变化、不标业务失败、不再次结算。两次写入不是原子事务，结果明确报告工程停止。

## 7. 任务 owner 的最小提供者
