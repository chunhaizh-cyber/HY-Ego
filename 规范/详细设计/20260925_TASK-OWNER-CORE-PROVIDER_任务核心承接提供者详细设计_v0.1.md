# TASK-OWNER-CORE-PROVIDER 本能根任务核心承接提供者详细设计

版本：v0.1

日期：2026-09-25

状态：正式详细设计；对应单一代码计划

对应目标：`GOAL-SELF-GOVERNANCE-CLOSURE`

代码事实基线：`42556450a1554f84ead96bcdc03c512ddc338c1a`

## 1. 目标与分期裁决

当前self主链的第一个真实任务消费者只承接安全根或服务根。3100 v2.3、3200 v2.4和5260 v0.8冻结最终统一任务核心必须支持普通D与双根D，但没有要求第一个代码叶同时开放两条入口。因此本叶只实现：

```text
安全根/服务根初始化语义请求
-> task owner签发或恢复不可变初始化包
-> 按根L查询当前T
-> 新建T或精确复用同根当前T
-> 发布T + L引用 + T→D + Vt + R1 + Vt首态
-> 建立P1
-> Vt首迁移到待找方法
-> 当前/历史根目标投影与核心读回
```

全部公开名称使用“本能根任务核心”具名。首版只接受安全根、服务根；普通D、普通需求列表读取、多条等价`T→D`和普通任务入口明确后置。它们不得冒充本计划完成范围。

本叶不接线self、manager、worker，不开放治理门，不执行筹办、方法、结果或结算。普通应用只建立并持有唯一provider，启动期零任务业务调用。

## 2. 当前事实与复用裁决

1. 旧`数据服务.任务类.h`是合同版本3纯头实现，只表示“所属存在 + 单一来源需求”，无法承接无所属存在的双根D；全仓没有生产构造或调用。
2. 旧`应用服务.任务目标方向.h`是唯一消费者，同样没有生产构造或调用。
3. `需求类数据服务`已经持有双根D、根L、根形成F、根目标合同、目标值和成员关系；只缺按`Gread/H`读回不可变根材料的历史入口。
4. `存在类数据服务::读取单例角色`能在`Gread/H`读回唯一self E；`读取当前采用完整_v2`能证明根形成截止时E采用根形成F。
5. `特征类数据服务::读取准确特征事实`能从根形成F读回正式FT。task owner不得信任调用方自报FT。
6. L1现有独占owner、原子写集、当前/历史读取、首次材料、属性槽换代和持久恢复足够，不修改L1 ABI。
7. task owner固定键、控制键和阶段键均不得进入不持久化的`0x4E43................`进程维护键域。

裁决：不建立普通需求列表provider计划；组合现有需求、存在、特征和L1能力实现根专用最小叶。

- `海中鱼巣/领域/任务治理.本能根任务核心.cpp`：结构、签发/恢复、三阶段事务和读回；
- `验证工具/本能根任务核心承接提供者专项验证.cpp/.vcxproj`；
- `实施记录/20260925_TASK-OWNER-CORE-PROVIDER_本能根任务核心承接提供者实施记录_v0.1.md`。

普通应用以固定owner建立键`0x1008`建立唯一独占结构owner。它写入任务结构元数据、私有高水位、预留记录、回执、T、Vt、R1、P1、任务内部关系、生命周期和Vt状态。D、L、self E、根形成F、FT和根目标合同继续由原owner提供。

高水位、预留和回执是工程恢复材料，不是第二任务账。每个阶段的幂等结果唯一以L1按原阶段键保存的`首次规范化写集 + 首次写入结果`为权威；task owner回执节点只保存提交前已知的请求索引并与首次材料交叉核验，不保存或替代L1提交后结果。T只保存根来源定位、预留记录和base，不保存E、FT、目标合同、目标值或目标投影。

## 4. 结构与固定编码

结构登记幂等键固定为`0x544F000000000001`，高水位首次建立键固定为`0x544F000000000002`。

| 本地键 | 结构事实 |
| ---: | --- |
| 1..3 | 任务族根、预留记录族根、初始化回执族根 |
| 10..18 | 任务族成员、任务查询锚点、L当前任务、任务来源D、任务Vt、任务R1、R1的P1、预留记录成员、初始化回执成员关系类型 |
| 20..25 | 私有高水位I64、任务生命周期I64、Vt状态I64、预留材料U64组、根来源定位U64组、回执材料U64组属性类型 |

`本能根任务核心结构交付_v1`按表中顺序包含合同版本、task owner身份、三个族根、九个关系类型和六个属性类型。全部必须从首次材料和正式事实读回；缺失、重复、错类型或退出使装配失败。

完整C++字段冻结为：

```cpp
struct 本能根任务核心结构交付_v1 final {
  std::uint32_t 合同版本 = 1;
  L1结构所有者身份 task_owner{};
  稳定编码 任务族根{}, 预留记录族根{}, 初始化回执族根{};
  稳定编码 任务族成员关系类型{}, 任务查询锚点关系类型{},
      L当前任务关系类型{}, 任务来源D关系类型{}, 任务Vt关系类型{},
      任务R1关系类型{}, R1的P1关系类型{}, 预留记录成员关系类型{},
      初始化回执成员关系类型{};
  稳定编码 私有高水位属性类型{}, 任务生命周期属性类型{},
      Vt状态属性类型{}, 预留材料属性类型{}, 根来源定位属性类型{},
      初始化回执材料属性类型{};
  friend bool operator==(const 本能根任务核心结构交付_v1&,
                         const 本能根任务核心结构交付_v1&) = default;
};
```

高水位初值0。每次换代在同一写集中退出旧值、建立新值并交换当前槽。

全部新关系的`角色或顺序`固定为0。各写集本地键完整冻结为：

- 高水位首次写集：值`高水位值=1`，无节点、无关系；把任务族根的高水位槽指向该值；
- 预留/高水位换代写集：节点`预留记录=1`，值`预留材料=2,新高水位值=3`，关系`预留记录成员=20`；退出旧高水位值并交换任务族根高水位槽；
- 新建核心写集：节点`T=1,Vt=2,R1=3,回执节点=4`，值`来源定位值=10,生命周期值=11,Vt状态值=12,回执材料值=13`，关系`任务族成员=20,T→L=21,L→当前T=22,T→D=23,T→Vt=24,T→R1=25,回执成员=26`；来源定位材料中的预留记录和base在提交前已经稳定，回执材料不得引用本写集新建T或关系；
- 既有T回执-only写集：节点`回执节点=1`，值`回执材料值=10`，关系`回执成员=20`；不得建立T、Vt、R1、P1或第二条`T→D`；
- P1写集：节点`P1=1,回执节点=2`，值`回执材料值=10`，关系`R1→P1=20,回执成员=21`；
- 首迁移写集：节点`回执节点=1`，值`新状态值=10,回执材料值=11`，关系`回执成员=20`；退出旧状态值并交换Vt状态槽；
- 当前资格退出写集：节点`回执节点=1`，值`新生命周期值=10,回执材料值=11`，关系`回执成员=20`；退出既有`L→当前T`关系和旧生命周期值，并交换T生命周期槽；回执材料只保存提交前已知的旧关系和旧生命周期值，不保存本写集新生命周期值。

同一写集内节点、值和关系本地键各自在自己的键空间解释；实现不得把上述键改为按容器追加顺序临时分配。

U64组编码固定：

- 预留材料14项：`[1,意图,G,根角色,D,L,H,根形成F,前序T或0,n,control,base,base+1,base+2]`；
- T根来源定位8项：`[1,根角色,D,L,H,根形成F,预留记录,base]`；
- 核心阶段回执6项：`[1,1,预留记录,意图,分支,既有T或0]`；新建分支末项必须为0，既有T分支必须是提交前已经读回的T；
- P1阶段回执5项：`[1,2,预留记录,T,R1]`；T和R1均来自已完成核心阶段读回；
- 首迁移阶段回执6项：`[1,3,预留记录,T,Vt,旧Vt状态值]`；各身份均来自已完成前段读回；
- 退出回执8项：`[2,T,L,期望前生命周期,目标生命周期,退出幂等身份,L→当前T关系,旧生命周期值]`。

首项是格式判别码：`1`表示初始化三阶段回执，第二项阶段码固定为`核心=1、P1=2、首迁移=3`；`2`表示退出回执。读取必须先按判别码、阶段码和精确长度选择格式，再逐字段核对。退出回执节点仍挂在初始化回执族根下，但使用独立强类型，不得冒充初始化回执。分支固定为`新建T=1、承接既有当前T=2、同D精确重复=3`。不做尾字段兼容。

上述回执U64组严禁保存本写集本地键、尚未生成的稳定编码、提交后事实代次或从`新编码映射`倒填的字段。L1不提供预分配；实现不得拆成“先提交取编码、再补回执”的第二事务。提交后产生的T、`T→D`、P1、新状态值、新生命周期值、回执身份及本阶段G，只能从同一原键的`L1所有者范围首次写入读取结果.首次写入结果`之`新编码映射`和`事实代次`读回。

## 6. 根目标当前/历史重建

当前读取要求`H==Gread`；历史读取要求`0<H<=Gread`。统一算法：

1. 从T读回首次根来源定位；
2. 调用`读取本能根历史材料({1,Gread,H,角色,F})`并核对D/L/F；
3. 调用`存在类数据服务::读取单例角色({1,Gread,H,self角色,1})`读回H时唯一self E；
4. 调用`特征类数据服务::读取准确特征事实({1,Gread,根材料.创建事实代次,F})`取得正式FT；
5. 调用`存在类数据服务::读取当前采用完整_v2({2,Gread,根材料.创建事实代次,E,FT})`，并核对返回的F等于根形成F，证明根材料创建截止时同一E对该FT采用F；
6. 值式形成`E + FT + 根目标合同`，目标I64只取根材料。

不得从T、F准确值、角色常量或调用方回显补造目标。依赖成功头、身份、G/H或载荷不符为内部不一致。

依赖状态映射逐项冻结：

- `读取本能根历史材料`内部的每项L1历史读取：`成功→继续并核验事实`；`入口拒绝→入口拒绝`；`未找到→未找到`；`已退出→已退出`；`历史材料已清理→历史材料不可用`；`事实代次漂移→事实代次漂移`；`资源失败→资源失败`；`属性未设置/许可拒绝/内部不一致/其它→内部不一致`。公开根历史结果再映射为：`已读取→继续`；`入口拒绝→入口拒绝`；`未找到→未找到`；`已退出/历史材料不可用→历史材料不可用`；`事实代次漂移→事实代次漂移`；`幂等冲突→幂等冲突`；`引用冲突→引用冲突`；`资源失败→资源失败`；其余→内部不一致。

- `读取准确特征事实`的`std::variant<准确特征读取事实,特征数据错误>`：命中事实且`Gread/H/身份/创建退出/类型关系`完整才继续；错误`未找到/未设置→未找到`，`已退出/历史材料不可用/旧格式不支持→历史材料不可用`，`并发变化→事实代次漂移`，`引用冲突/类型不相容→引用冲突`，`资源失败→资源失败`，`幂等冲突→幂等冲突`，其它错误→内部不一致。

## 7. 高水位、号段与三阶段

```text
control(n)=0x544F100000000000+n
base(n)=0x544F200000000000+4*n
core=base; P1=base+1; migration=base+2
```

`n`上限为`0x2AEC37FFFFFFFFFF`（`3092908616747843583`）；`base+3`永久不用。计算前逐步检查溢出和键域。

签发时按意图完整扫描预留记录：同意图同完整请求返回首次包；同意图异请求为幂等冲突；多重为内部不一致。未命中时以control原子建立预留材料并换代高水位。首次形成必须满足`来源H==请求G`；恢复必须返回首次保存的完整原请求和首次H。发布未知不得换号；重启只按原control、原阶段键和原请求恢复。预留一经发布不回收，未用阶段键永久作废。

每个阶段入口都必须先以该阶段原键调用L1`读取首次写入材料`：

1. 命中时要求owner、原键、首次规范化写集、首次写入结果和发布边界完整；按冻结本地键从`新编码映射`取得本阶段全部新稳定编码，事实代次只取首次写入结果；
2. 用首次规范化写集内的预提交回执材料与预留记录完整原请求交叉核验，再按首次映射读回同一写集建立/退出的任务事实；全部成立才重放首次结果；
3. 同键的规范化写集或回执绑定不同原请求时返回幂等冲突；映射缺项/重复、结果与写集不闭合或回执矛盾时返回内部不一致；
4. 只有L1明确返回原键未找到，才执行本阶段当前准入并构造一次原子写集。

不得先按当前状态拒绝一个本可由原L1首次材料精确重放的请求。task owner回执只作同写集请求索引；L1首次材料是唯一重放结果，不形成平行权威。

核心阶段完成上述重放检查后，才重建根目标并按L读取0..1当前T：

- 无T：core单写集发布完整核心；
- 有同根当前T：只建立本意图回执，首次返回`已承接到当前任务`，已有同请求回执返回`精确重复`，不得增加第二`T→D`；
- 多T、异根占用、终态仍当前、目标不一致或闭包错误：零写并返回具名非成功。

仅新建T分支以P1键建立强类型P1和`R1→P1`；随后以migration键把Vt从`已建立待首轮准备`换代为`待找方法`。P1和首迁移同样先按原键/回执重放，再检查R1、P1和Vt当前状态。既有T分支的P1/首迁移阶段为`不适用`，两键永久不用。

三阶段分别原子。前段已发布不回滚；恢复按三个原阶段键依次读L1首次材料，从首个未确认阶段继续。新建三阶段完整成功为总状态`已完成`，全部由L1原键首次材料重放为`精确重复`。不得依赖自定义U64回执中的提交后编码或G，因为这些字段不再存在。

## 8. 失败、退出与历史

失败优先级：入口字段→owner/结构→G漂移→来源未找到/历史不可用→当前资格/目标→结构闭包→幂等冲突→提交后发布未知→资源→内部不一致。提交后无法证明成功或重复时，`已可能发布`优先；提交前资源异常为资源失败。

退出只准从`当前可治理`迁移到已完成、已失败、已取消或已退出当前资格。退出入口先按原幂等键读取L1首次写入材料，并按判别码2及上述8项预提交回执格式核对T、L、期望前生命周期、目标生命周期、原键、旧当前关系和旧生命周期值；新生命周期值、退出回执身份和最终G只从首次写入结果的冻结本地键映射及事实代次取得。随后按首次写集的退出集合与槽交换读回闭包并返回。同键异请求返回幂等冲突，格式、映射或结果闭包不符返回内部不一致。只有L1明确原键未找到后才核验当前生命周期和当前关系。同写集退出`L→当前T`和旧生命周期值，建立新值、交换槽并写入预提交回执；不删除任务历史。

历史读取允许当前关系已退出，但H时来源必须完整；物理历史清理返回历史材料不可用。
