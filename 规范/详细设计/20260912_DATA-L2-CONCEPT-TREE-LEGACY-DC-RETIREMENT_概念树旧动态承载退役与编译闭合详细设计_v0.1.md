# 概念树旧动态承载退役与编译闭合详细设计

日期：2026-09-12

版本：v0.2

身份：`DATA-L2-CONCEPT-TREE-LEGACY-DC-RETIREMENT`

状态：设计完成；执行状态以计划索引为准

代码事实基线：`679ed322884e06964ecdcef47fe4d6222e42101f`

## 1. 目标与裁决

本设计处理当前最早且可独立闭合的代码叶：从 `海中鱼巣/领域/数据服务.概念树类.ixx` 物理退役已经失去提供者的旧动态概念承载、旧场景/动态具体服务构造和旧历史读取逻辑；同时物理退役仍完整消费这些旧入口的旧`应用服务.动态概念树类`及其工程登记。结果使概念数据模块仅保留当前仍有提供者的基础概念、特征概念、存在概念和共享治理能力，并让干净正式HEAD不遗留旧消费者编译断裂。

本片不是7191新动态概念提供者实现。正式HEAD尚无 `合同.概念基础.ixx`、`合同.二次关系概念.ixx`、`合同.动态概念.ixx` 及对应4242 RC提供者；7191新DC又直接依赖4242的RC定义、求值和引用闭包。把它们临时塞回概念树单文件会违反4240/4242/7191的物理位置与依赖方向，并把一个编译恢复叶扩张成RC/DC全链实现。因此本片先关闭旧入口，不新增空成功、旧名转发、DTO别名或未实现骨架；后继须按`概念公共合同/4242 RC提供者 -> 7191 DC合同与数据提供者 -> 动态概念应用`另行形成计划。

本片不修改正式规范。7191第12节已经要求旧动态时间槽、旧动态定义、旧动态扩展、旧请求、具体服务构造、旧模板API和旧历史读取全部替换或删除；4240要求缺提供者时结构化拒绝，禁止借旧L2接口伪装新能力。当前新DC尚未启用，故最小合法动作是彻底删除旧DC分支，而不是把旧模型适配到4213/4204窄provider。

## 2. 正式依据与当前事实

### 2.1 正式依据

- 0050及4030：DATA-L2只维护冻结的强类型结构，不得用应用语义或第二数据模型补缺口。
- 4240第10—12节：四个本体根继续存在；新RC/DC各走专属合同和唯一概念owner；旧动态DTO不能冒充新DC；缺少提供者时明确能力不足。
- 4213：现行动态只读面是`动态结构只读提供者`及`动态信息身份/动态内容事实`，旧`动态类数据状态`和`读取动态历史事实`已经退出。
- 4204：现行场景动态组织只读面是`场景动态组织只读提供者::读取动态场景组织历史`，旧`场景类数据状态`和`读取场景历史事实`已经退出。
- 7191第2、6、7、8、12节：新DC须使用专属合同、31类型交付、封闭写联合和4213/4204窄provider；旧动态定义、扩展、构造、模板和历史读取闭包不得并存。
- CODE-FILE-01与单工作区规则：只修改获准代码文件和专属记录，保护其它WIP；编译只证明静态闭合。

### 2.2 当前代码事实

1. 目标文件直接 `export import 数据服务.场景类`，其中`概念树场景引用`和`使用同一场景基座`仍被存在/场景成员概念应用消费，必须保留；但旧动态专属构造借此依赖的`动态类数据服务`及两个旧历史入口已经不存在。`读取场景角色历史`是非static const成员；退役scenes_及其唯一注入构造后，没有合法借入实例。现非DC构造原来也被dynamic_门禁阻断该分支，因此本片保留场景引用类型，明确暂停概念provider内该范围的核验/读取，返回现有不支持，不虚构能力。
2. 目标文件仍定义`概念树场景引用/概念树动态引用/概念树动态时间槽/概念树动态定义/概念树动态扩展交付`和整套旧动态请求、结果、模板、依据与证据类型，并把旧动态定义塞在通用`概念树定义`variant内。
3. 目标文件仍保存`scenes_/dynamics_/dynamic_`，存在六组接收旧扩展的构造组合，以及`使用同一场景基座/使用动态世界服务/创建动态概念/释放动态形成依据/读取动态形成依据/核验动态支持依据/读取动态特征模板`等旧公开面。
4. 私有逻辑仍调用`读取动态历史事实`和`读取场景历史事实`，并映射已删除的`动态类数据状态/场景类数据状态`；当前根工程Debug/Release日志各有138条错误行且均来自该模块。
5. 正式HEAD中的`应用服务.动态概念树类.ixx`仍大量消费旧动态定义、旧构造和旧动态公开入口，且主工程仍登记该模块；它是必须同次退出的主要旧消费者。`应用服务.存在概念树类.ixx`还以`概念树动态模板事实`作为判定应用特征模板结果中的拒绝分支，需同次机械删除这一个分支。工作树中动态概念应用当前只有3字节，属于来源不明WIP，不能被计划智能体采用或覆盖；执行者必须等待该WIP明确释放或交接后，才可按本设计物理删除。`应用服务.场景成员概念类.ixx`的零字节异主WIP只消费须保留的场景引用/绑定谓词，继续禁止修改。
6. 两个主工程文件当前工作树blob与HEAD blob完全一致，属于状态缓存/行尾假脏；为使已删除模块不再参与干净HEAD构建，本片必须精确删除动态概念应用的一个`ClCompile`和一个filters登记。概念树模块登记保留；新合同模块本片不创建。

## 3. 保留面与删除面

### 3.1 必须保留

- `概念树根角色`的四个角色及四个正式根，尤其动态根身份本身；删除旧DC承载不等于删除动态本体根。
- 基础`概念树结构交付`、基础构造、当前事实代次读取、基础概念/图/支持/形成引用、生命周期和退出能力。
- 当前已发布的特征概念、存在概念、共享定义/名称/用途/治理入口及其构造组合。
- 现有L1 owner、写端口、幂等、事实代次、历史读回和错误边界；不得改变其字段、枚举数值或事务语义。
- `动态根引用()`可作为四根中动态根的只读身份getter保留；它不表示7191 DC结构服务已经启用。

### 3.2 必须物理删除

按实体及所有引用闭包删除，不保留`#if 0`、注释代码、别名或转发壳：

1. 旧动态世界引用：`概念树动态引用`及其在`概念树世界引用/概念树形成世界引用`中的分支；保留存在、特征、特征类型和场景范围引用的现行分支并同步修正所有variant分派，不依赖旧固定index。
2. 旧定义：`概念树动态时间槽`、`概念树动态定义`及通用`概念树定义`中的旧动态分支；概念种类3只作为可识别旧持久格式，不再解码为成功DTO。
3. 旧交付与事实：`概念树动态结构类型`、`概念树动态扩展交付`、旧动态依据/模板/审计/支持事实及其成功谓词。`概念树应用模板事实`收口为只含`特征概念事实`的值式variant；存在概念应用中对旧动态模板分支的拒绝检查同次机械删除，特征概念应用现有`get_if<特征概念事实>`调用保持可编译。
4. 旧请求和公开入口：旧动态建立、依据释放、依据审计、支持核验、模板读取请求/结果；所有旧动态请求从通用写/读variant移除。
5. 旧构造和成员：全部接收`场景类数据服务/动态类数据服务/概念树动态扩展交付`的动态专属构造组合，`scenes_/dynamics_/dynamic_`，以及`使用动态世界服务`；保留独立非DC场景绑定谓词。
6. 旧实现：动态扩展校验、动态定义/依据完整性、模板解码、动态审计、两种旧状态映射、场景/动态历史读、旧动态写集、重放、图、支持和应用关联分支。
7. 因旧动态分支而存在的预算计量字段/缓存只在不被FC/EC/共享逻辑复用时删除；保留项必须由实际剩余调用点证明。

### 3.3 旧持久事实与失败分账

- 读取到基础`概念种类=3`的旧动态概念时返回`旧格式不支持`并清空业务载荷；不得按新DC、普通存在概念或特征概念解释，也不得物理删除旧事实。
- 本片不识别或发布`概念种类=5/6`的新RC/DC专属完整事实；这些种类只由未来4242/7191专属服务承接。本片不冻结它们在未来通用身份/图头中的投影方式，不得为消除旧代码而提前添加拒绝或成功分支。
- 动态世界事实的新支持、形成依据和名称关系不在本片实现。删除旧分支后，含旧动态引用的旧请求在源级不再可构造；没有兼容转换。
- 删除动态分支后任何旧variant序号不得作为持久类别；持久类别只由显式概念种类和具名关系类型裁决。

## 4. 依赖和构造收口

1. 保留目标文件对`数据服务.场景类`的import、`概念树场景引用`及`使用同一场景基座(const 场景类数据服务&) const noexcept`原签名；该谓词仅核验给定实例同底座，不存储或注入实例，不代表支持场景范围。场景角色历史读取需要真实服务对象，本片没有该依赖，不作静态调用、临时构造、全局查找或L1跨owner重解。概念provider中场景范围分支按第4.1节返回现有不支持。
2. 所有不启用DC的既有构造必须保留原签名和委托链：基础；基础+共享；基础+特征；基础+特征+存在；以及当前真实存在的合法组合。构造校验不得再引用旧动态交付或旧具体服务。
3. 特征/存在扩展的互异编码校验只比较当前真实启用的基础、特征、存在、共享布局；删除对`dynamic_`的条件分支，不放宽现有有效交付的互异、owner和同L1要求。
4. 删除旧动态专属`scenes_`成员，但不删除独立的场景绑定谓词。本片不新增任何场景身份只读provider成员、4213/4204 provider或构造参数。新DC构造必须等`合同.概念基础/二次关系概念/动态概念`与4242提供者落盘后，按7191完整签名一次实现；当前叶不以闲置引用制造“已迁移”假象。

### 4.1 场景范围暂不支持的封闭边界

具名漂移 SCENE-RANGE-READ-PROVIDER-SOURCE 在基线 `5d420883fecaed2608248b6775a4761a5ac98e4b` 确认：所有剩余非DC构造只借入L1、特征、存在和值服务；没有可复用的场景角色抽象provider。增加成员/构造会改变本退役计划冻结的保留ABI，因此本片裁决为暂不支持，不删除场景引用DTO，不实现空壳provider。

- `验证世界` 遇 `概念树场景引用` 时，经原请求形状及G/H守卫后抛出/传播现有 `概念树数据状态::不支持`（30），不调用任何场景身份历史函数，也不将场景编码当普通存在读取。其它存在/F/FT分派和实际provider不变。
- `形成引用组` 对场景引用必须显式类型分派返回不支持，不能因删除动态关系类型后类型集合为空而返回成功空组；移除原 `world.index() >= 3` 与旧动态索引数组，按保留的强类型分支消费原关系类型。
- 公开 `读取形成来源当前引用(概念树形成引用读取请求)`、通用/共享读取variant中的对应分支，以及通用/应用写入口中的 `概念树形成引用释放请求` 均承接同一拒绝。合法头/预算/编码但世界引用为场景时，返回不支持、业务载荷为空、成功谓词为false。本次零新节点/关系/值/首次账/事实代次变化；不得降为未找到、无须变更或把空预期释放当成功。
- 释放的场景类型门禁须在首次重放/写集准备/提交之前统一完成；旧场景释放首次账已经存在也不能绕该分支报告完整能力，仍返回不支持，本次不改旧账。原请求及已经由原结果合同携带的首次H可继续保留作审计，但不宣称先前从未发布。其余非场景请求的原键重放不变。
- 已持久化且必须核验场景身份的范围/形成材料只能返回不支持并清空整项或完整组载荷，不能跳过该项后返回完整成功，也不物理删除原事实。若目标本身已由旧概念种类3门禁识别，优先按既有旧格式不支持处理；二者分别表示旧模型与缺合法provider。

4240要求世界结构由对应公开provider验证；缺provider时不支持是能力边界，不是放宽结构条件。4205/1130准确F的C/P定位继续由独立定位服务和三个owner负责，7160按FT及规范域形成概念；本片不把概念provider的场景范围不支持转成“F无需位置”，也不在概念形成时补猜父。场景/存在概念应用已经自行借入的场景实例与其定位核验保持各自职责，不能借这个谓词把它偷偷转交概念provider。本片不修改这些应用的场景消费逻辑；其中旧读取接口的编译/运行缺口继续按外部文件分账，不声明完整应用链已恢复。

将来恢复此概念场景范围能力，必须另外冻结合法窄provider、实际借入/装配及同实例校验、G/H/状态映射和消费者迁移；本片不登记新后继、不新增公开DTO/构造、不扩大七文件白名单。

## 5. 读取、写入和重放收口

执行者按编译器诊断和调用闭包机械删除旧分支，但须满足：

1. 规范化、完整定义查找、概念图、应用图和成功谓词只接受剩余正式定义类型；凡请求目标或所请求动态根完整图实际需要解码旧种类3定义时，返回`旧格式不支持`，不能跳过旧节点后让完整图假成功。其它根的独立读取不因未请求的动态根旧节点自动失败。
2. 基础图的四根仍全部校验；读取特征根/存在根不因动态根下存在旧节点而伪造其它根失败。请求读取动态根下完整旧图时明确旧格式不支持。
3. 基础写、共享写、特征写和存在写的原key重放继续按原G与L1首次规范化写集恢复；删除旧动态请求不得改变其它请求variant的语义。代码不得用variant index持久化或比较请求种类；内部若存在此类依赖，改为显式类型分派。
4. 任何删除后的非成功分支清空旧动态载荷，不生成默认概念、空成功图或`无须变更`假成功。
5. 若目标文件剩余FC/EC能力仍引用旧动态专属helper，仅可拆出其真正通用部分并保留原非动态语义；不能因函数名复用而保留旧动态DTO。
