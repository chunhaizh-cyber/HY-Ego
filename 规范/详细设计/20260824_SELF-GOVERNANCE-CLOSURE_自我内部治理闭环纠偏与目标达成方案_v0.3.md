## 1. 顶层目标与完成声明

本方案把当前已经正式收敛的“想 / 看 / 做、任务轮次、逐需求核算和自我后继决议”口径落实为生产闭环。最终只有同时满足以下条件，才允许声明“自我内部治理闭环达成”：

```text
具体需求 D 经其所属需求列表项 L 查询 / 防重后建立或复用任务 T
-> 新任务建立独立任务轮次 R1
-> R1 按筹办、执行、结算推进并进入轮次已收束
-> 每次既有状态的真实变化均形成同一 G1 的内部治理动态
-> 内部治理与纯现实观察不请求现实执行授权
-> 含现实改变步骤时只在冻结后、进入执行前取得一份自我现实执行授权
-> 安全服务只提供调度材料和硬否决
-> 正式结果先裁决可共用 / 争用，再逐个 T→D 独立核算
-> 任务轮次结算完成后停止自行推进
-> 只有自我“继续”决议建立 R2，并重新筹办、冻结和按范围重新判断授权
-> 旧任务私有当前状态和目标未达成自动重筹办链退出生产
```

编译、DTO 存在、线程返回、日志、自检或单次状态写入都不能代替上述完成声明。

## 2. 本轮 S0 纠偏结论

### 2.1 已成立的正式机器语义

- `0050 v1.5`：ARCH-L2 通用存在、状态和动态只能有一份结构权威；首个状态不产生动态。
- `3200 v0.9`、`5210 v1.0`：任务轮次、筹办轮次和执行轮次分账；主阶段固定为筹办、执行、结算、轮次已收束。
- `5230 v1.2`：筹办和冻结属于内部治理；现实改变只在冻结后、执行前取得一份自我授权。
- `5160 v0.4`：结果可共用 / 争用先裁决，每个 `T→D` 单独核算；目标未达成不自动迁移任务或建立下一筹办工作包。
- `8100 v0.7`、`8200 v0.7`、`8300 v0.6`：轮次收束后只有自我形成继续、结束、等待或取消决议。

### 2.2 当前实现偏差

1. `L2通用虚拟存在结构服务`以私有 `unordered_map`、自增身份和私有事实代次保存存在，重复了现有 `L2存在结构服务`，不属于 ARCH-L1 统一事实代次。
2. 该服务的请求携带 `ARCHL4宿主引用`，把业务宿主语义带入 ARCH-L2 通用结构合同。
3. `L2状态动态原子发布服务`只保存该服务的引用，从未调用；状态和动态参与者实际已经通过各自服务验证正式 `L2存在身份`。
4. 当前任务结构只有筹办轮次权威和执行轮次材料，没有独立任务轮次身份；现有融合入口在任务建立时直接形成筹办轮次 1。
5. 旧任务私有治理状态、目标未达成待重筹办迁移、重筹办意图和线程处理槽仍在生产链。
6. Stage C 仍把旧授权安全材料当作筹办冻结前置，与现行授权口径冲突。

### 2.3 对输入路线的必要修正

“任务建立首个筹办状态并同时形成首条动态”不成立。现行 0050 要求首个状态不产生动态；正确顺序是：

```text
任务建立和任务轮次 R1
-> 首态：筹办阶段 / 待初次筹办（无动态）
-> 建立筹办轮次 P1
-> 状态迁移：待初次筹办 -> 筹办中
-> 形成第一条真实内部治理动态
```

ARCH-L4 任务对 ARCH-L2 存在的业务引用由任务 owner 保存；ARCH-L2 只认识正式 `L2存在身份`，不保存 `ARCHL4宿主引用`。

### 2.4 2026-08-25 当前执行检查点

本检查点只更新路线的实现事实，不改变第 1 节目标、正式机器语义或最终验收合同：

1. `ARCH-L2-GENERIC-VIRTUAL-EXISTENCE-AUTHORITY-CORRECTION` 已发布代码结果：冗余 `L2通用虚拟存在结构服务` 私有存在权威及其装配依赖已经退出，状态动态组合只消费正式 `L2存在身份`。该结果不证明任务轮次或自我治理消费者已经接通。
2. `ARCH-L1-OWNER-PORT-REISSUANCE` 已发布代码结果，提供同运行包 owner 无活动端口时的重签发边界；它不证明崩溃恢复、跨进程恢复或 L4 消费者闭环。
3. `TASK-ROUND-INITIAL-STATE-ARCH-L2-MIGRATION v0.3` 的八个 L4 生产文件 WIP 已在执行 S0 后停驻。停驻原因不是任务业务语义变化，而是当时的中性 L2 provider 会退出旧状态事实，同时又保留动态到旧状态的引用，违反 L1 引用闭包。
4. 直接前置已经收敛为 `ARCH-L1-L2-STATE-HISTORY-CURRENT-SELECTION-REFERENCE-CLOSURE`：状态事实永久保留，当前性由状态 owner 的当前选择关系表达；首态无动态，迁移只退出旧当前选择并形成新状态、新当前选择和动态。该前置当前仍在 v0.4 设计修订期，尚无可执行计划或生产能力结果。
5. 因直接前置 ABI 尚未正式发布，`TASK-ROUND-INITIAL-STATE-ARCH-L2-MIGRATION v0.3` 继续保持`待激活`，不得原样恢复。前置发布并返还真实 ABI 后，必须从新 HEAD 重新 S0，以同一计划身份形成修订版本；不得把保留 WIP、历史专项二进制或旧验证结果当作可继续施工证据。

因此当前最早代码缺口不是继续扩展任务业务阶段，而是先完成中性状态历史与当前选择闭包，再恢复任务轮次首叶。叶 2—6 仍只属于路线输入，不具备计划或施工身份。

## 4. 关键事实所有权

| 事实 | 唯一 owner | 禁止的第二权威 |
| --- | --- | --- |
| 任务、`T→L`、`T→D`、任务轮次、筹办轮次、执行轮次、冻结、实际结果、轮次结算引用 | ARCH-L4 任务 owner | 线程槽、列表项授权包、日志 |
| 通用存在身份和生命周期 | 现有 ARCH-L2 `L2存在结构服务` | `L2通用虚拟存在结构服务`私有 map |
| 特征定义 / 实例 / 当前值 | ARCH-L2 特征 owner | 任务枚举或私有字段 |
| 状态 / 动态 | ARCH-L2 状态 owner / 动态 owner，经单 G1 provider | `L2任务治理状态事实`新当前写入 |
| 需求正式满足 | 需求 owner | 任务轮次结论或列表汇总 |
| 结果共用 / 争用与分配 | 对应结果关系 / 分配 owner | 线程消费顺序 |
| 自我现实执行授权 | 自我业务 owner | 安全服务、任务、方法的第二正向授权 |
| 自我后继决议 | 自我业务 owner | 目标未达成自动继续 |

## 5. 端到端验收合同

最终生产级 headless 场景至少证明：

1. 新任务只由具体需求 D 触发，经 L 防重；复用任务只新增当前 `T→D`，不重建 R1。
2. R1 首态无动态；每次后续状态变化恰有一条同主体、同特征、相邻前后状态的动态。
3. P1、E1、冻结、实际结果、逐需求核算、轮次结算均可按正式身份独立读回。
4. 目标未达成后没有 R2、下一筹办工作包或自动继续决议。
5. 自我“继续”后才建立 R2；R2 不复用 R1 的路径、实例、冻结、实际结果或现实执行授权。
6. 内部治理与纯观察零现实执行授权；含现实改变时一冻结一授权，硬否决优先且不能被授权绕过。
7. 首次、精确重复、同键异义、G0 漂移、许可拒绝、坏引用、资源失败和发布未知均按合同收敛；非成功零越权事实。
8. 结果可共用时每个成员独立核算；争用时按正式优先级分配后核算；任何一个成员结果不能代替其它成员。
9. 旧任务私有状态、重筹办意图和处理槽不再决定生产主阶段。

达到 8300 等级 6 才能声明内部循环建立；连续两轮及无任务风暴、空转和自动重筹办达到等级 7 后，才完成本目标。
