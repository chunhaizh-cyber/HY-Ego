# TARGET-POSITIVE-GAP-CONFIRM-COMPOSE 当前正差距确认组合详细设计 v0.1

日期：2026-08-16
版本：v0.1

## 1. 目标与完成边界

本叶实现 BIZ-L2-004-01 v0.2：以一个非零 `G0`、五个目标身份和比较请求身份，先经 `需求目标事实提供者`读取完整目标合同 / 当前事实，再经 `特征判断收束服务`执行一次注册比较裁决，最后形成完整 `需求正差距结果`。

完成最多证明目标候选正差距组合服务。需求建立、来源授权、父路径、任务树、普通应用持有 / getter / 装配、T02 正式接线和系统闭环保持 `NOT_RUN`。

## 2. 所有权与物理归属

旧 `需求业务服务`归属退出：本函数没有需求身份、允许需求尚未建立且不消费需求结构；把它放入 `服务.需求.ixx`会占用 DATA-EXT-12 需求 owner 消费面并制造构造 ABI 冲突。

新建：

```text
海中鱼巣/领域/需求正差距.数据.h
海中鱼巣/领域/服务.需求目标裁决.ixx
```

传统头冻结父 DTO；模块 `海中鱼巣.领域.服务.需求目标裁决` export import `海中鱼巣.领域.提供者.需求目标事实`、`海中鱼巣.领域.服务.特征判断收束`和 `海中鱼巣.领域.服务.L2结构聚合`，按项目 `NO_INCLUDES` 模式 export 包装自己的数据头。

```cpp
class 需求目标裁决服务 final {
public:
    explicit 需求目标裁决服务(const L2结构聚合服务& 结构服务) noexcept;
    需求正差距结果 确认当前正差距(
        const 需求正差距请求& 请求) const noexcept;
private:
    需求目标事实提供者 目标事实提供者_;
    特征判断收束服务 判断收束服务_;
};
```

构造顺序固定：`目标事实提供者_(结构服务)`，随后 `判断收束服务_(结构服务.取得L2特征结构服务())`。两个子对象按值唯一持有，均只借用同一 L2 运行包；不持有 `需求业务服务`、普通应用、L1、owner或第二聚合。

## 3. DTO 与稳定状态

```cpp
inline constexpr std::uint32_t 需求正差距合同版本 = 1;
inline constexpr std::uint32_t 需求正差距规则版本 = 1;

enum class 需求正差距状态 : std::uint8_t {
    已满足 = 1,
    存在可处理正差距 = 2,
    方向相反 = 3,
    约束冲突 = 4,
    目标材料未找到 = 5,
    目标材料已退出 = 6,
    目标上下文引用冲突 = 7,
    目标场景未找到 = 8,
    目标场景已退出 = 9,
    目标范围不成立 = 10,
    目标特征实例未找到 = 11,
    目标特征当前值未设置 = 12,
    当前值类型不兼容 = 13,
    不可比较 = 14,
    算法未登记 = 15,
    当前性漂移 = 16,
    版本漂移 = 17,
    入口拒绝 = 18,
    许可拒绝 = 19,
    资源失败 = 20,
    未实现 = 21,
    内部不一致 = 22
};

struct 需求正差距请求 final {
    std::uint32_t 合同版本 = 需求正差距合同版本;
    std::uint32_t 规则版本 = 需求正差距规则版本;
    std::uint64_t 事实截止代次 = 0;
    L2场景树身份 目标场景树;
    L2场景身份 目标场景;
    L2存在身份 目标宿主;
    L2目标状态合同身份 目标状态合同;
    L2特征定义身份 目标特征定义;
    std::uint64_t 比较请求身份 = 0;
};

struct 需求正差距结果 final {
    需求正差距状态 状态 = 需求正差距状态::入口拒绝;
    std::uint32_t 合同版本 = 需求正差距合同版本;
    std::uint32_t 规则版本 = 需求正差距规则版本;
    std::uint64_t 事实截止代次 = 0;
    std::optional<需求目标当前事实结果> 当前事实证据;

};
```

请求 helper 要求当前版本、非零 G0、五个身份和比较请求身份。业务裁决只接受前四状态、同一版本 / G0、两个 optional存在且各自成功 / 已形成业务裁决，当前事实与比较证据的请求身份、G0、合同、定义、注册和当前值逐字段闭合。

## 4. 固定控制顺序

```text
纯值校验父版本、G0、五身份和比较请求身份
-> 构造当前 BIZ-L3-004-01-01 请求并恰一次调用同对象 provider
-> 非成功精确映射，两个证据 optional 为空
-> 以完整当前事实结果和原比较请求身份构造 BIZ-L3-004-01-02 请求
-> 恰一次调用判断收束服务
-> 比较非成功精确映射，保留完整当前事实与比较结果
-> 四类业务状态逐字段互证
-> 一次形成完整候选并无抛出返回
```

不得用第一结果回显截止重选 G0，不得在第二叶失败后重做第一叶，不得缓存或拆出裸目标 / 当前值形成第二权威。

## 5. 状态映射与失败守恒

第一叶 `需求目标当前事实状态`除 `已形成`外全部同名映射；`入口拒绝`同名，未知值和坏成功形状为内部不一致。第一叶失败时两个证据均为空。

第二叶映射：已满足、存在可处理正差距、方向相反、约束冲突、不可比较、算法未登记、版本漂移、许可拒绝、资源失败、未实现、内部不一致均同名。父请求已验证且比较请求由本函数从完整事实机械构造，因此第二叶仍返回 `入口拒绝`表示本函数或前驱合同矛盾，必须映射内部不一致。第二叶其它协议内非成功保留完整当前事实结果与完整目标差距比较结果；若比较结果本身形状错误，则返回内部不一致且两个证据清空，禁止发布半可信材料。

进入第一调用后的普通失败回显父 G0；当前性漂移使用事实 provider 的非零实际截止；比较版本漂移仍保留父 G0和两个完整证据。异常：`bad_alloc` / `length_error`为资源失败，其它为内部不一致；没有完整子结果时零证据。

## 6. 并发、验证与激活

函数只使用局部值式请求和候选，零锁、零等待、零重试、零缓存、零写。并发事实推进只允许完整同 G0 结果、当前性漂移或结构化比较版本漂移，不能拼装混代。

生产文件与工程：两个新生产文件加 `.vcxproj` / `.filters`唯一登记。验证覆盖父入口拒绝、第一叶全部状态、第二叶全部状态、四类业务结果、G0 / 身份 / 证据互证、异常守恒、恰两次 BIZ 调用、零 DATA函数名 / L1 / 需求 owner / 写入 / 缓存 / 重试；根工程 Debug / Release、生产外专项、diff、strict、UTF-8和清理后复验。

计划保持待激活，直到 `TARGET-CURRENT-FACTS-COMPOSE v0.1`与 `TARGET-GAP-REGISTERED-COMPARE-CONSUME v0.1`真实结果、退出、临时专项清理及生产文件释放，且唯一代码段、工程和构建资源可用。最终 ABI、状态、模块 import、构造顺序或文件所有权漂移固定退回 `DRIFT-TARGET-POSITIVE-GAP-CONFIRM-ABI-OR-OWNERSHIP`。
