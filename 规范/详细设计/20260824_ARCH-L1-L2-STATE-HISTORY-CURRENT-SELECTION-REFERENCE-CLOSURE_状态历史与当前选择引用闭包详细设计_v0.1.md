# ARCH-L1-L2-STATE-HISTORY-CURRENT-SELECTION-REFERENCE-CLOSURE

## 状态历史、当前选择与跨 owner 引用闭包详细设计 v0.1

状态：设计就绪候选；未实施代码、未登记计划索引

设计基线：`main@c6e2431e612a13a4e8aa277cd94b31e06a12431c`

## 1. 目标与边界

本设计闭合 ARCH-L1 / ARCH-L2 状态—动态原子发布中的两个中性缺口：

1. 跨 owner 全部参与者候选写集应用后的最终全局当前引用闭包；
2. 状态事实永久保留与由状态 owner 持有的特征实例→状态当前选择关系。

本叶只处理 L1/L2 中性结构、状态与动态的结构化读回和两 owner 原子发布。它不处理任务、方法、需求、结算、学习、A1 业务关系写入、普通应用装配、任务轮次或任何现实授权。

## 2. 当前事实与复用裁决

### 2.1 L1

`核心/仓库.L1事实基座.ixx::提交跨所有者原子事务`当前固定状态 owner 先、动态 owner 后的两参与者事务，并在候选形成后调用通用 `状态完整`。单 owner 退出路径已有 `检查当前节点引用闭包`，但它只看参与者写入前的退出集合，不能单独证明后续参与者新建关系不会引用刚退出的节点。

L1 公共事务 DTO 已包含参与者、跨 owner 局部引用、统一幂等身份、共同期望事实代次和聚合结果；本叶不新增 L1 DTO、不扩展参与者枚举、不增加第三 owner。

### 2.2 状态与动态

`领域/服务.L2状态结构.ixx::形成状态原子参与者写集`当前退出旧状态节点及其主体 / 特征关系和值；`领域/服务.L2动态结构.ixx`形成动态前状态关系（旧状态稳定身份）和后状态关系（状态参与者局部引用）。这使旧状态节点可能在动态关系建立前已退出，形成引用闭包冲突风险。

当前状态读组通过状态→主体、状态→特征实例关系枚举，尚无独立当前选择关系。`L2特征实例事实`已有宿主存在和特征定义，但没有额外独立适用范围身份；因此本叶将当前适用范围等同于特征实例身份，不新增 L3 范围对象。

## 3. L1 最终全局引用闭包

### 3.1 函数位置与调用顺序

在 `海中鱼巣/核心/仓库.L1事实基座.ixx` 新增内部函数：

```cpp
当前节点引用闭包检查结果 检查跨所有者原子候选全局引用闭包(
    const 状态& 候选仓库) noexcept;
```

调用顺序固定为：

```text
获取仓库独占锁
→ 校验 G0 / 幂等账 / 参与者身份
→ 复制候选仓库
→ 应用状态参与者写集
→ 应用动态参与者写集并解析跨 owner 局部引用
→ 统一候选事实代次
→ 检查跨所有者原子候选全局引用闭包
→ 形成结果
→ 写入跨 owner 幂等账
→ 交换正式仓库
```

最终闭包失败时，结果形成和幂等账写入步骤均不得执行。

### 3.2 检查内容

函数必须检查候选中：

- 每个当前关系的源节点、目标节点和关系类型节点均为当前有效节点；
- 每个当前值的所属节点、属性类型节点、来源节点以及独立材料引用均为当前有效节点；
- 当前属性槽只指向同一候选中的当前值，且所属节点 / 类型匹配；
- 当前源 / 目标 / 类型 / 节点引用索引与权威当前事实逐项一致；
- 历史事实已退出且不再出现在当前索引；
- 全部跨 owner 局部引用已经解析为稳定编码；
- 参与者顺序反转不能留下任一悬空关系或值。

### 3.3 结果映射与代次

内部检查结果复用现有 `当前节点引用闭包检查结果`：

```text
已闭合     → 继续提交
引用冲突   → L1跨所有者原子事务状态::引用冲突
内部不一致 → L1跨所有者原子事务状态::内部不一致
```

请求造成的未闭合引用返回 `引用冲突`；候选仓库原有索引或不变量损坏返回 `内部不一致`。两类结果均满足：

- `是否形成内存权威发布=false`；
- 正式仓库不交换；
- 事实代次不推进；
- 跨 owner 幂等账不写入。

G0 漂移、许可拒绝、资源失败和幂等冲突保持现有分账，不得重分类为引用冲突。精确重复只从已成功写入的幂等账返回，不增加代次。

## 4. L2 状态永久事实与当前选择

### 4.1 当前选择关系

新增状态 owner 专属关系类型：

```text
L2状态当前选择关系类型身份
```

新增关系方向：

```text
源：L2特征实例身份
目标：L2状态身份
角色：状态端点角色值
owner：L2状态结构 owner
```

唯一键为：

```text
(特征实例身份, 当前选择关系类型)
```

特征实例事实的 `宿主存在` 必须与被选状态的主体在同一共同截止互证。当前适用范围等同于特征实例身份；若未来出现独立适用范围，必须建立新合同，不得在本叶暗加字段。

### 4.2 永久事实规则

以下事实发布后不得因失去当前性而退出或覆盖：

- 状态节点；
- 状态主体关系；
- 状态特征实例关系；
- 精确值；
- 时间值；
- 来源与版本材料。

当前性只由当前选择关系决定。状态身份事实读取和当前选择读取是两个不同判断：前者返回事实 / 历史材料，后者返回当前选择关系及目标状态。

### 4.3 首态与迁移

首态由状态 owner 一笔写集建立：

```text
永久状态节点
+ 族归属、主体、特征关系
+ 精确值、时间值、来源 / 版本材料
+ 当前选择关系
```

首态不建立动态。

迁移由状态 owner + 动态 owner 的现有两参与者事务完成：

```text
旧当前选择关系退出
+ 新永久状态事实建立
+ 新当前选择关系建立
+ 动态主体关系建立
+ 动态前状态关系 → 旧状态节点
+ 动态后状态关系 → 新状态节点
```

旧状态节点、旧状态自有关系和值继续有效。A1 与动态前状态关系都可以普通 L1 关系长期引用旧状态节点，不得材料化状态身份、建立第二见证节点或增加第三 owner。

### 4.4 旧数据

旧状态存在但没有当前选择关系时：

- 当前选择读取返回具名 `待迁移`；
- 结果无状态 / 关系载荷；
- 不从主体关系、特征关系、时间、来源或版本自动推断；
- 原子写入口零写拒绝；
- 需要单独迁移合同时才可建立选择关系。


```text

```

`L2状态动态原子发布结果`增加新选择关系与旧选择关系退出证据。状态登记规则版本和状态—动态原子发布专属合同版本递增；`L2结构合同版本`、L1 合同版本和参与者枚举不变。

## 6. 所有权、幂等与失败

- 当前选择关系只能由状态 owner 写入；动态 owner 只写动态事实；A1 不属于本叶写集。
- 同一特征实例的首态建立是同义幂等；同一特征实例已有不同当前状态或旧选择编码不符返回引用冲突。
- 同义迁移重试返回首次结果；异义请求返回幂等冲突；G0 变化返回事实代次漂移。
- 所有非成功结果零载荷，不写幂等账，不改变当前选择。
- 发布后必须在同一共同事实截止读回新状态、新选择关系、动态前后关系和旧选择历史。
