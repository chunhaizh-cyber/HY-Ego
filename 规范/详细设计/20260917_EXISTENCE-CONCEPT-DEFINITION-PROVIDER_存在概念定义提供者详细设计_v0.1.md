# 存在概念两组定义提供者详细设计

身份：`EXISTENCE-CONCEPT-DEFINITION-PROVIDER-REBUILD`

版本：v0.2

日期：2026-09-17

状态：待激活；两组定义的结构合同已收紧，但非 I64 特征值域核验/比较提供者尚未冻结

## 1. 目标、范围与完成条件

本设计在唯一概念 owner 内建立普通存在概念的两组定义提供者。它只接受并持久化已经由调用方裁决的：

```text
自身特征值域组：每项 {正式 FT，已发布 FC 值域概念}
+ 已知子存在概念组：每项 {已发布存在 EC}
```

它提供规范化、候选有界枚举、同义精确查询、创建或复用、完整读回，以及定义引用保护所需的物理读回。存在首次形成的递归、特征实际值到 FC 值域的包含判断、全部候选中的唯一最具体裁决、主动归纳目标选择、世界 E 建立及 E→EC 使用引用均不在本提供者内；它们分别由 7100、7110 和后继世界树编排实现。

完成时，概念 owner 能在同一结构事务内发布“类别、生命周期、两组定义及调用方显式直接上位”；候选读取可从概念族锚点的成员关系在请求预算内返回完整两组定义；旧 D/O/R 格式、DTO、函数和消费者引用均物理退出。完成不证明世界树流程、递归形成、最具体裁决、主动归纳、恢复或运行验收。

本层只能保存已裁决的 `FT→FC` 项，却仍必须在入口核验该项的 `FC` 类别、完整读回和该 FT 的值域/比较规则是否兼容。当前接口仅有 I64 类型规格、I64 域与 I64 域包含入口；非 I64 的 `FC` 可以依据 4240 §12 使用真实值或不可变材料，但没有同截止的“FC 完整值域读回 + FT 比较合同读取 + 实例值/候选域包含或域间包含”提供者。因此，本计划不得实施为只支持 I64 的新 ABI，也不得将非 I64 映射为规则缺失后仍发布两组定义。该提供者合同冻结前，本设计和计划保持待激活。

## 2. 正式依据与当前事实

- 2220 v1.22 §1—§4：存在概念只以自身特征值域和已知子存在概念定义；根链是投影，不有持久总根。
- 7100 v2.0 §2—§4：两组完整、规范化、完整匹配、唯一最具体和先概念后实例。
- 7110 v2.0 §2—§6：主动归纳与首次路径分离；概念 owner 只保存已裁决定义和直接边。
- 4240 v0.42 §13—§14：同一概念 owner 的两组定义、同事务发布、有界结构检索、独立生命周期与旧 D/O/R 物理退出。

当前 `海中鱼巣/领域/合同.相关概念添加参与.h` 中的 `完整存在概念定义` 仍含自身特征、组成和关系三组；`完整存在概念结构交付_v1` 仍声明组成角色、关系类型等八种类型。`数据服务.概念树类.h/.cpp` 仍公开/实现相同旧 ABI，并在 `纯概念定义` 中保留旧 variant。它们与上述正式依据冲突，只能删除重建，不能改名或升版复用。

`仓库.L1事实基座.h` 已提供 owner 范围的当前源/目标关系组、历史关系组、历史事实和历史属性值组读取。每个结果携带实际读取代次；概念 owner 可据其概念族锚点→概念族成员关系有界枚举候选，再逐项完整读回。L1 不提供全仓扫描，方案也不请求或模拟全仓扫描。

## 3. 新公开 DTO 和函数

所有新类型放入 `海中鱼巣/领域/合同.相关概念添加参与.h`，实现服务成员声明放入 `海中鱼巣/领域/数据服务.概念树类.h`。版本均为 `1`。

```text
存在概念特征值域项_v3 { 特征类型身份 FT; 概念树概念身份 FC; }
存在概念两组定义_v3 { bool 自身特征组已完整声明; vector<存在概念特征值域项_v3> 自身特征值域组;
                         bool 子存在概念组已完整声明; vector<概念树概念身份> 已知子存在概念组; }
存在概念两组预算_v3 { 概念树预算 基础; 最大自身特征项; 最大子概念项;
                       最大候选数; 最大定义成员数; 最大首次材料项数; }
```

`FT` 不为零，`FC` 和子 `EC` 不为零。两个“已完整声明”标志必须都为 true；它们使空 vector 成为调用方明确声明的空组，而不是信息漏填。规范化按 FT、FC、EC 的稳定编码升序排序：同一 FT 重复、FC 重复、EC 重复、FC/EC 类别不符、退役、缺完整读回、值域/比较规则版本不相容和超预算均是非成功，绝不降为缺项或空组。

公开请求/结果固定为：

| 函数 | 请求 | 成功载荷 |
| --- | --- | --- |
| `规范化存在概念两组定义` | `{版本,Gread,H,定义,预算}` | 同截止规范化定义 |
| `枚举存在概念候选` | `{版本,Gread,H,预算}` | 至多预算内的完整 `存在概念两组事实_v3` 组 |
| `精确查询存在概念` | `{版本,Gread,H,定义,预算}` | 唯一同义完整事实或确认未找到 |
| `创建或复用存在概念` | `{版本,G0,幂等身份,定义,直接上位,预算}` | 原请求、发布状态、Gread/H/首次发布H、完整事实和直接边 |
| `读取存在概念两组定义` | `{版本,Gread,H,EC,预算}` | 一项完整两组事实 |

完整事实只包含 EC、存在类别、定义记录及其生命周期、概念生命周期/治理状态、`存在概念两组定义_v3`、自身特征项物理事实组、子概念关系事实组和直接上位组。它不返回 D/O/R、角色、数量、端点、世界支持、名称、当前采用或来源账。

状态枚举 `存在概念两组状态_v3` 固定区分：入口拒绝、已规范化、已枚举、已读取、未找到、已创建、精确重复、目标已退出、概念已退役、类别冲突、定义不相容、规则缺失、事实代次漂移、幂等冲突、数量预算不足、历史材料不可用、资源失败、内部不一致、已可能发布、旧格式不支持。失败清空所有定义、候选、事实及边载荷；可能发布只保留原创建请求和实际读到的截止。

## 4. 物理布局和 owner 事务

新增同 owner 的独立结构登记 `登记存在概念两组结构_v1`，不重登或改写既有 `纯概念结构_v2`。登记请求为 `{版本=1,G0,幂等身份,纯概念结构v2,最大首次材料项数}`；登记结果保存原请求、发布状态、Gread、首次发布 H、交付和首次材料。交付固定为格式锚点加以下五个类型节点；五者都是本布局中关系的类型见证，不另设没有写入位置的“项属性”：

```text
两组定义成员
自身特征值域项
自身项特征类型
自身项值域概念
已知子存在概念
```

首次写集精确为 6 个节点（格式锚点和五个属性类型节点）、5 条“格式锚点→属性类型”的类型登记关系、1 条格式版本值，合计 12 个首次材料映射项。缺任一既有 pure v2 交付、同 owner 不一致、原键异写集、G0 漂移或发布未知均按独立原请求收敛；禁止换键重建。

每个新定义在同一概念 owner 事务写入；以下五条关系逐一使用上述五个新类型节点：

```text
C --两组定义成员(顺序=1)--> D
D --自身特征值域项(顺序=1..M)--> IFItem
IFItem --自身项特征类型--> FT
IFItem --自身项值域概念--> FC
D --已知子存在概念(顺序=1..N)--> 子EC
```

`D` 与 `IFItem` 均为普通节点；`D` 是该 `C` 的唯一两组定义记录，`IFItem` 是一个 `FT→FC` 的唯一项，禁止裸 FT、裸 FC 或同 FT 的两个 IFItem。顺序只确定稳定读回顺序，不是概念语义。FC 与子 EC 是已发布概念节点引用，FT 是正式特征类型节点引用。D/O/R 节点、组成角色/关系类型属性和值事实、关系参与角色关系均不得创建。定义引用不得经形成来源释放接口退出；概念退出必须先核验没有仍有效的两组定义引用。

## 5. 读取、规范化、查询与发布

所有读入口先守卫 `Gread`，要求非零 `H<=Gread`，每次 L1 读取结果的实际代次都必须等于 `Gread`。`枚举存在概念候选` 只通过概念 owner 的概念族锚点→成员关系读出存在类别候选；达到 `最大候选数` 前逐项完整读回。成员关系重复、类别不符、成员/定义缺失、退出、历史清理、超过任一预算或中途漂移均失败且返回零候选，不能伪造空候选集。

`精确查询` 必先规范化输入，再用候选枚举逐一比较两组的精确相等。零匹配才是确认未找到；多个同义匹配是内部不一致，不任选其一。`创建或复用` 同样先规范化并完整查询；命中唯一同义概念时只在原幂等请求语义相同的条件下精确重复。零匹配时才组成上述写集，写后按实际 H 完整读回。直接上位由调用方明确提供并按既有同类别、无环、直接边规则校验；空直接上位合法，禁止旧“存在概念必须先有上位”的诊断或拒绝。

在进入上述流程之前，每一个 `FT→FC` 项必须完成以下强制核验：FT 已发布且其比较合同在 H 可读；FC 为已发布特征概念且其完整值域在 H 可读；该值域与 FT 的正式比较合同相容。I64 可由当前 I64 域读取/包含接口承担；非 I64 不得由特征值原始材料、节点编码、摘要或 `特征类型准确值核验` 替代，因为它们未给出域的同截止比较语义。未有统一提供者前，返回“规则缺失/能力未提供”，零候选、零写入，而不是选择 I64 子集施工。

此层不计算“实例值是否被 FC 域包含”或“候选是否最具体”：这些需要特征类型比较合同和 7100 调用方上下文。它只给调用方返回所有可读候选的完整两组定义；调用方选出唯一最具体后，应以精确查询/创建接口读回或建立该定义。

## 6. 旧格式退出和消费者迁移

以下符号及其实现必须从生产 `.h/.cpp` 物理删除：`存在概念完整性声明`、`完整存在概念自身特征约束`、`完整存在概念组成约束`、`完整存在概念关系参与角色约束`、`完整存在概念关系约束`、`完整存在概念定义`、`完整存在概念*` 全部请求/结果/事实/结构登记类型和函数、`完整定义布局_`、旧 pure variant 分支，以及旧 D/O/R 读取、规范化、写集、注册和读回辅助函数。

同步清理 `海中鱼巣/装配.普通应用.cpp`、`海中鱼巣/业务/计算.二次特征.h`、`海中鱼巣/领域/数据服务.特征类.h/.cpp` 中对这些旧符号的使用。若某处真实需要存在概念定义，只能改用本设计的两组只读/写入 ABI；若该处无法按正式依据构造完整两组定义，则删除该旧路径并返回既有“能力缺失/旧格式不支持”结构化结果，不能保留 D/O/R 兼容层。

## 7. 文件、依赖方向与验证

允许生产文件：`合同.相关概念添加参与.h`、`数据服务.概念树类.h/.cpp`、所有旧符号实际命中的消费者文件；允许工程登记仅在当前工程确实未自动包含新增 `.cpp` 时修改。禁止修改 L1、正式规范、世界树/存在类业务编排、特征比较算法、装配启动顺序及任何 `.ixx`。

只有非 I64 提供者完成设计并发布后，验证至少包括：

1. 两组排序、去重、类别和引用闭包；每个非成功分支零定义载荷。
2. 锚点成员有界枚举、跨直接父分支候选可读、预算/漂移/退役/不完整不伪装为空。
3. 同义唯一复用、零同义创建、多个同义内部不一致、原键重放/冲突/可能发布。
4. 六节点/五登记关系/一格式值布局和同事务完整读回；D/O/R 及角色/端点属性零残留。
5. 顶层 EC 可空直接上位；直接边仍同类别无环。
6. I64 与每一种正式支持的非 I64 值域：同截止类别/完整读回/规则兼容核验；规则缺失、材料不可读或比较不相容均零写入。
7. 全仓生产源码旧符号零命中，主工程 Debug/Release 编译；用户未另行授权前不做运行、恢复或集成验收。

## 8. 完成声明边界

该提供者完成只证明 DATA-L2 概念 owner 可安全保存、读取和精确复用已裁决的两组存在概念定义，并已物理退出本切片旧 D/O/R 格式。它不证明 7100 世界创建闭环、7110 主动归纳、特征域形成、IF/R、场景/存在数据、概念树算法正确性、持久恢复、运行期或业务闭环。

## 9. 待提供合同与重新激活门禁

重新激活前必须有一份正式冻结并已发布的通用特征值域核验/比较提供者合同，至少明确：

1. 非 I64 `FC` 的类别和完整规范化值域如何在指定 `Gread/H` 读回；真实值和不可变材料的各自读取、退出、历史清理、预算与漂移状态。
2. 如何按同一 `FT` 取得适用比较合同，并对“实例实际值在 FC 域内”“FC 域与 FC 域等价”“FC 域被另一 FC 域包含”分别返回确定结果或具名非成功。
3. 不同非 I64 表示、材料格式、规则版本不相容时的零写入错误映射；不得由数据服务猜测跨类型相等或包含。
4. 该提供者的唯一物理 owner、公开 DTO/函数、幂等与同截止 readback 边界，以及本计划可调用的已发布接口。

这些是现行 7100 对完整匹配和 4240 对真实值/材料的共同必需实现合同，不是本计划可以新增、缩窄或临场决定的字段。用户或正式规范必须先裁决其机器语义；在此之前，本计划只保留本节的结构裁决，不能开工。
