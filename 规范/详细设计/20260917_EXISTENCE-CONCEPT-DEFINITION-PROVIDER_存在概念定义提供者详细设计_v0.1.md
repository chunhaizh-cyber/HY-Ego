# 存在概念两组定义提供者详细设计

身份：`EXISTENCE-CONCEPT-DEFINITION-PROVIDER-REBUILD`

版本：v0.6

日期：2026-09-17

状态：施工设计；直接上游 `FEATURE-DOMAIN-COMPARISON-BINDING-ABI` 已由 `0e8e2db9` 发布比较服务同 L1 绑定核验，非 I64 的真实成功比较仍由具名待实现适配器后续提供

## 1. 目标、范围与完成条件

本设计在唯一概念 owner 内建立普通存在概念的两组定义提供者。它只接受并持久化已经由调用方裁决的：

```text
自身特征值域组：每项 {正式 FT，已发布 FC 值域概念}
+ 已知子存在概念组：每项 {已发布存在 EC}
```

它提供规范化、候选有界枚举、同义精确查询、创建或复用、完整读回，以及定义引用保护所需的物理读回。存在首次形成的递归、特征实际值到 FC 值域的包含判断、全部候选中的唯一最具体裁决、主动归纳目标选择、世界 E 建立及 E→EC 使用引用均不在本提供者内；它们分别由 7100、7110 和后继世界树编排实现。

完成时，概念 owner 能在同一结构事务内发布“类别、生命周期、两组定义及调用方显式直接上位”；候选读取可从概念族锚点的成员关系在请求预算内返回完整两组定义；旧 D/O/R 格式、DTO、函数和消费者引用均物理退出。完成不证明世界树流程、递归形成、最具体裁决、主动归纳、恢复或运行验收。

本层只能保存已裁决的 `FT→FC` 项，却仍必须在入口核验该项的 `FC` 类别、完整读回和该 FT 的值域/比较规则是否兼容。`8a7ba623` 已发布 4180 §5.2 的唯一只读组合 owner：I64 取得真实同截止读回与关系核验；I64组、U64组和独立材料引用经同一公开 ABI 明确返回 `待实现`/`规则缺失`，零写入、零成功载荷。故本计划可统一调用该 ABI，不能收窄为 I64-only，也不能把非 I64 的结构化失败降为可发布定义；非 I64 的真实成功比较仍等待各 FT 专用适配器。

比较服务已经在构造时只读依赖概念树服务，故概念树服务不得反向保存、构造或注入比较服务。两组定义入口必须以**调用期**接收 `const 特征值域比较数据服务&`：概念树 `.h` 只前置声明该类，`.cpp` 才包含比较服务头；每个入口先调用其公开 `绑定于(const L1事实基座服务&)` 核验同一 L1，再对每一 `FT→FC` 调用 4180 §5.2 的 `读取特征值域`。这只是短时只读参数，不是概念 owner 的字段、第二 owner 或持久事实。普通应用须先构造概念树、再构造比较服务，随后才调用两组定义入口，因而没有 C++ 头文件环、构造环或运行时服务环。

比较服务私有引用不可访问，且读取结果的 `Gread/H` 是某一 L1 的代次数字，不能证明它与概念 owner 是同一 L1。因此不能以“读取结果恰好同截止”替代绑定核验。`FEATURE-DOMAIN-COMPARISON-BINDING-ABI` 已由 `0e8e2db9` 在比较服务中发布只读 `bool 绑定于(const L1事实基座服务&) const noexcept`：仅当概念树、特征类和特征值类三条已保存引用全部绑定该参数时返回 true，否则 false；专项矩阵已覆盖同 L1 true、任一混用 false 与零写入。该 ABI 不读写机器事实、构造第二服务或改变 4180 的域比较结果。本计划具备该上游前提，但执行者仍必须重新 S0。

## 2. 正式依据与当前事实

- 2220 v1.22 §1—§4：存在概念只以自身特征值域和已知子存在概念定义；根链是投影，不有持久总根。
- 7100 v2.0 §2—§4：两组完整、规范化、完整匹配、唯一最具体和先概念后实例。
- 7110 v2.0 §2—§6：主动归纳与首次路径分离；概念 owner 只保存已裁决定义和直接边。
- 4240 v0.42 §13—§14：同一概念 owner 的两组定义、同事务发布、有界结构检索、独立生命周期与旧 D/O/R 物理退出。

当前 `海中鱼巣/领域/合同.相关概念添加参与.h` 中的 `完整存在概念定义` 仍含自身特征、组成和关系三组；`完整存在概念结构交付_v1` 仍声明组成角色、关系类型等八种类型。`数据服务.概念树类.h/.cpp` 仍公开/实现相同旧 ABI，并在 `纯概念定义` 中保留旧 variant。它们与上述正式依据冲突，只能删除重建，不能改名或升版复用。

`仓库.L1事实基座.h` 已提供 owner 范围的当前源/目标关系组、历史关系组、历史事实和历史属性值组读取。每个结果携带实际读取代次；概念 owner 可据其概念族锚点→概念族成员关系有界枚举候选，再逐项完整读回。L1 不提供全仓扫描，方案也不请求或模拟全仓扫描。

## 3. 新公开 DTO 和函数

所有新类型放入 `海中鱼巣/领域/合同.相关概念添加参与.h`，实现服务成员声明放入 `海中鱼巣/领域/数据服务.概念树类.h`。版本均为 `1`。

```text
存在概念特征值域项_v3 { 特征类型身份 FT; 概念树概念身份 FC; }
存在概念两组定义_v3 { bool 自身特征组已完整声明; vector<存在概念特征值域项_v3> 自身特征值域组;
                         bool 子存在概念组已完整声明; vector<概念树概念身份> 已知子存在概念组; }
存在概念两组预算_v3 { 概念树预算 基础; 最大自身特征项; 最大子概念项;
                       最大候选数; 最大定义成员数; 最大首次材料项数; }
```

`FT` 不为零，`FC` 和子 `EC` 不为零。两个“已完整声明”标志必须都为 true；它们使空 vector 成为调用方明确声明的空组，而不是信息漏填。规范化按 FT、FC、EC 的稳定编码升序排序：同一 FT 重复、同一 FC 重复、EC 重复、FC/EC 类别不符、退役、缺完整读回、值域/比较规则版本不相容和超预算均是非成功，绝不降为缺项或空组。FT 去重与 FC 去重必须用各自集合独立核验，不能因排序键先是 FT 而漏过“不同 FT 指向同一 FC”。

公开请求/结果固定为：

| 函数 | 请求 | 成功载荷 |
| --- | --- | --- |
| `规范化存在概念两组定义` | `{版本,Gread,H,定义,预算}` + 调用期 `const 特征值域比较数据服务&` | 同截止规范化定义 |
| `枚举存在概念候选` | `{版本,Gread,H,预算}` + 调用期比较服务 | 至多预算内的完整 `存在概念两组事实_v3` 组 |
| `精确查询存在概念` | `{版本,Gread,H,定义,预算}` + 调用期比较服务 | 唯一同义完整事实或确认未找到 |
| `创建或复用存在概念` | `{版本,G0,幂等身份,定义,直接上位,预算}` + 调用期比较服务 | 原请求、发布状态、Gread/H/首次发布H、完整事实和直接边 |
| `读取存在概念两组定义` | `{版本,Gread,H,EC,预算}` + 调用期比较服务 | 一项完整两组事实 |

完整事实只包含 EC、存在类别、定义记录及其生命周期、概念生命周期/治理状态、`存在概念两组定义_v3`、自身特征项物理事实组、子概念关系事实组和直接上位组。它不返回 D/O/R、角色、数量、端点、世界支持、名称、当前采用或来源账。

状态枚举 `存在概念两组状态_v3` 固定区分：入口拒绝、已规范化、已枚举、已读取、未找到、已创建、精确重复、目标已退出、概念已退役、类别冲突、定义不相容、规则缺失、事实代次漂移、幂等冲突、数量预算不足、历史材料不可用、资源失败、内部不一致、已可能发布、旧格式不支持。失败清空所有定义、候选、事实及边载荷；可能发布只保留原创建请求和实际读到的截止。

## 4. 物理布局和 owner 事务

新增同 owner 的独立结构登记 `登记存在概念两组结构_v1`，不重登或改写既有 `纯概念结构_v2`。登记请求为 `{版本=1,G0,幂等身份,纯概念结构v2,最大首次材料项数}`；登记结果保存原请求、发布状态、Gread、首次发布 H、交付和首次材料。交付固定为格式锚点加以下五个类型节点；五者都是本布局中关系的类型见证，不另设没有写入位置的“项属性”：

```text
两组定义成员
自身特征值域项
自身项特征类型
自身项值域概念
已知子存在概念
```

首次写集精确为 6 个节点（格式锚点和五个属性类型节点）、5 条“格式锚点→属性类型”的类型登记关系、1 条格式版本值，合计 12 个首次材料映射项。缺任一既有 pure v2 交付、同 owner 不一致、原键异写集、G0 漂移或发布未知均按独立原请求收敛；禁止换键重建。

每个新定义在同一概念 owner 事务写入；以下五条关系逐一使用上述五个新类型节点：

```text
C --两组定义成员(顺序=1)--> D
D --自身特征值域项(顺序=1..M)--> IFItem
IFItem --自身项特征类型--> FT
IFItem --自身项值域概念--> FC
D --已知子存在概念(顺序=1..N)--> 子EC
```

`D` 与 `IFItem` 均为普通节点；`D` 是该 `C` 的唯一两组定义记录，`IFItem` 是一个 `FT→FC` 的唯一项，禁止裸 FT、裸 FC 或同 FT 的两个 IFItem。顺序只确定稳定读回顺序，不是概念语义。FC 与子 EC 是已发布概念节点引用，FT 是正式特征类型节点引用。D/O/R 节点、组成角色/关系类型属性和值事实、关系参与角色关系均不得创建。定义引用不得经形成来源释放接口退出；概念退出必须先核验没有仍有效的两组定义引用。

### 4.1 独立结构登记的首次键、重放与 owner 非空规则

两组结构是与 `纯概念结构_v2`、特征概念出生使用结构并列的独立 owner 扩展，不是 pure v2 的重登记、替换或附加写集。因而“首次”只指本请求的 `写入幂等身份` 尚无首次材料；**不指概念 owner 空域**。在同一 owner 已成功登记 pure v2、特征概念出生使用或其它独立布局时，使用新的两组结构键登记仍是正常首次登记，必须能发布六节点、五条类型登记关系和一个格式值。

结构登记按以下有限分支执行：

1. 先按 `{owner, 写入幂等身份}` 读取首次写入材料，并核验合同版本、owner 与原键回显。若命中成功，只有首次规范化写集与本次写集逐项完全相同、首次写入结果确认发布且其事实代次为原 `G0 + 1` 时，才提交同一写集取得精确重复；交付和首次材料必须由该原写集的映射完整读回。
2. 若同一键的首次材料存在但本次规范化 12 项写集不同，返回 `幂等冲突`，零交付、零首次材料；不能换键重建，也不能把它降为 owner 非空或旧格式。pure v2 交付仍须先独立核验为同一 owner 的真实 pure v2 布局；预算只约束本次入口是否足够，不被虚构为首次写集字段或新的持久材料。
3. 若该键未找到，只有其读取事实代次严格等于请求 `G0`、且没有异常携带的首次写集或结果时，才可提交本两组的独立 12 项写集。此分支**不得调用 `读取所有者范围空域`，也不得检查或要求整个 owner 没有既有事实**；owner 内其他已发布结构既不构成冲突，也不进入本请求的成功谓词。
4. 键未找到但读取截止不等于 `G0` 返回 `事实代次漂移`；首次读取/提交资源故障返回 `资源失败`；提交返回幂等冲突返回 `幂等冲突`；首材料或提交结果无法确认是否已发布，保留原请求并返回 `已可能发布`。首次材料结构自身不符合可识别 v1 形状时才返回 `旧格式不支持`，不能把“owner 不空”映射为该状态。
5. 这项登记不新增、修改或退出 pure v2、特征概念出生使用或其它结构交付；每项结构各用自己的原键和首次材料恢复。所有结构共同使用 owner 端口仅表示同一物理分区，不表示必须合并为一个首次空 owner 写集。

因此本计划的专项验证必须按同一 owner 顺序登记 pure v2、特征概念出生使用和两组结构，并验证第三项首次成功、同键精确重放、异请求幂等冲突以及未调用 owner 空域前置。该规则是 4240 §11.1、§14 已有“同一概念 owner 的独立结构承接”及本设计既定“独立结构登记”的施工落实；不改变存在概念的机器语义、字段或 owner。

### 4.2 pure v2 交付的同 owner 真实读回核验

`登记存在概念两组结构_v1` 不能把调用方传入的 `纯概念结构交付_v2` 当作已证明事实。进入首次材料读取或提交前，必须以当前请求 `G0`、同一个 `L1事实基座服务` 和同一个 `L1所有者范围写端口` 执行只读 `核验纯概念结构_v2`。该辅助函数复用或抽取 `登记纯概念结构_v2` 成功后已经执行的逐项 L1 读回逻辑，而不是复制一份弱化的编码检查：

1. 核验交付版本为 v2，15 个交付节点非零且两两不同；逐项读回均属于端口 owner、未退出、种类正确。
2. 核验格式锚点、概念族锚点、13 个类型节点、13 条格式类型登记关系和格式版本值构成已发布 pure v2 的完整物理形状；关系端点、关系类型、顺序、材料值及创建截止均与读回相符。
3. 将从事实读回重建的交付逐字段等于请求交付，并要求所有读取实际截止均等于 `G0`。缺项、跨 owner、退役、形状不符、读取失败或截止漂移分别映射既有结构化失败，绝不以“编码非零”或“owner 里存在其它结构”代替成功。

该核验不读 owner 空域、不写入事实、也不需要纯 v2 原幂等键；它证明“本次交付确为该 owner 已发布的 pure v2 布局”。特征概念出生使用登记和两组结构登记都必须采用它。两组登记的同键精确重复成功谓词还必须逐字段比较 `原请求->纯概念结构 == 本次请求.纯概念结构`，再比较既有版本、G0、幂等键、最大首次材料项数、12 项规范化写集、确认发布及完整首次材料；不能仅凭相同 12 项写集接受伪造或跨 owner 的 pure 交付。

## 5. 读取、规范化、查询与发布

所有读入口先守卫 `Gread`，要求非零 `H<=Gread`，每次 L1 读取结果的实际代次都必须等于 `Gread`。`枚举存在概念候选` 只通过概念 owner 的概念族锚点→成员关系读出存在类别候选；达到 `最大候选数` 前逐项完整读回。成员关系重复、类别不符、成员/定义缺失、退出、历史清理、超过任一预算或中途漂移均失败且返回零候选，不能伪造空候选集。

`精确查询` 必先规范化输入，再用候选枚举逐一比较两组的精确相等。零匹配才是确认未找到；多个同义匹配是内部不一致，不任选其一。`创建或复用` 同样先规范化并完整查询；命中唯一同义概念时只在原幂等请求语义相同的条件下精确重复。零匹配时才组成上述写集，写后按实际 H 完整读回。直接上位由调用方明确提供并按既有同类别、无环、直接边规则校验；空直接上位合法，禁止旧“存在概念必须先有上位”的诊断或拒绝。

在进入上述流程之前，每一个 `FT→FC` 项必须通过调用期比较服务完成以下强制核验：先调用公开 `绑定于(l1_)`；返回 false 时五个两组入口固定返回 `入口拒绝`、零定义/候选/事实/边载荷且不调用任何域读取。返回 true 后才核验 FT 已发布且其比较合同在 H 可读、FC 为已发布特征概念且其完整值域在 H 可读、该值域与 FT 的正式比较合同相容。概念树不得直接用 `读取特征概念值域基础` 取代本核验；该基础读取仅可供 4180 比较服务内部组合。I64 可由统一 ABI 的当前 I64 域读取/包含路径承担；非 I64 不得由特征值原始材料、节点编码、摘要或 `特征类型准确值核验` 替代，因为它们未给出域的同截止比较语义。统一服务返回 `未实现` 或 `规则缺失` 时映射两组 `规则缺失`、零候选、零写入，而不是选择 I64 子集施工。

所有五个两组公开入口及其私有展开链在读取 `pure_layout_` 或 `two_group_definition_layout_` 前都必须同时确认二者存在。旧构造只有 pure v2 或缺两组交付时，公开入口固定返回 `旧格式不支持`、零定义/候选/事实/边载荷；不得解引用 optional，也不得把旧布局缺失伪装为“未找到”。

此层不计算“实例值是否被 FC 域包含”或“候选是否最具体”：这些需要特征类型比较合同和 7100 调用方上下文。它只给调用方返回所有可读候选的完整两组定义；调用方选出唯一最具体后，应以精确查询/创建接口读回或建立该定义。

### 9.1 普通应用装配顺序

普通应用以同一个概念 owner 的单一仍可移动写端口按如下顺序装配；每一步成功后使用其真实 `Gread/首次发布H` 作为下一步 `G0`，不得复用过期代次：

```text
签发概念 owner 端口
-> 登记 pure v2
-> 按 §4.2 真实读回 pure v2
-> 登记特征概念出生使用结构
-> 真实读回出生使用结构
-> 登记存在概念两组结构（再次核验同 owner 的 pure v2）
-> 真实读回两组结构
-> 移动端口构造概念树类数据服务
-> 以该概念树、特征类和特征值类构造特征值域比较数据服务
-> 仅在调用两组定义 API 时传入比较服务只读引用
```

结构登记阶段不得先移动端口，也不得构造一个引用尚未完全交付结构的概念树服务。比较服务构造后不回写概念树；概念树也不缓存其地址。专项驱动必须按此顺序覆盖首次、重放、异请求冲突、G0 漂移、提交未知和 pure 伪造/跨 owner 拒绝，主工程构建只证明该装配能编译链接，不替代这些断言。

直接上游门槛已满足：`0e8e2db9` 发布比较服务的公开绑定谓词；独立专项证明其对同一 L1 的三项引用返回 true、任一混用 L1 返回 false 且零写入；上游计划及其索引项已收束。本计划执行者仍须以含该提交的当前正式 HEAD 重新 S0，核对新增 ABI 的实际头/源/工程登记、比较服务与概念树的无环装配、目标文件 WIP 和验证资源，才可开始本计划代码步骤。
