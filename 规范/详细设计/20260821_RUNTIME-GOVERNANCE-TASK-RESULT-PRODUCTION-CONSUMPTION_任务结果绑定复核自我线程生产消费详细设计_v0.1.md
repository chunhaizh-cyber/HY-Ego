# 任务结果绑定复核自我线程生产消费详细设计 v0.1

日期：2026-08-21

计划身份：`RUNTIME-GOVERNANCE-TASK-RESULT-PRODUCTION-CONSUMPTION`

代码基线：`3236c229697856f74a6302a5a9a15c66463319d4`

## 1. 目标与完成边界

本设计承接已经正式退出的 `RUNTIME-GOVERNANCE-TASK-RESULT-IDENTITY-BINDING v0.1`，把任务结果治理输入的 002-04 复核真正接入 `自我线程::运行治理循环()`。

完成链固定为：

```text
真实任务结果治理消息
-> 自我线程私有唯一治理邮箱
-> 冻结不可变治理批次和共享事实截止 G0
-> 002-03 分类并形成任务结果路由项
-> 自我线程当前批次处理槽
-> 002-04 从同 G0 当前实例方法取得执行轮次并绑定正式任务实际结果
-> 当前处理槽冻结任务结果治理后继输入
```

本叶只证明真实自我线程能够消费一条任务结果治理输入并把它绑定到正式任务实际结果事实。后继输入只是批次内值式材料，不写 DATA，不调用 002-05，不裁决任务完成、需求满足、服务成功、安全值、服务值或学习。

## 2. 当前事实与缺口

- 002-04 已经正式实现，公开入口为 `复核任务结果治理输入绑定事实`；状态为`已绑定、合法等待、当前性漂移、引用冲突、数量预算不足、入口拒绝、资源失败、内部错误`。本计划不得把它改写为并不存在的`可消费、精确重复、版本漂移`。
- `自我线程::运行治理循环()`已经能够通过唯一批次路由冻结邮箱消息和共享 G0，也已经调用 002-03 形成有序路由组，但 N09—N13 仍统一合法等待，未调用 002-04。
- 冻结成功后的`不可变治理批次`当前只存在于 `运行治理循环()`栈内；函数返回后销毁。源码注释所称“处理槽”没有持久承载结构，无法证明保槽重试。
- `自我线程`私有持有唯一邮箱，但没有公开的生产消息提交入口；现有测试只能直接构造邮箱或直接调用 002-04，不能证明真实自我线程消费。
- 普通应用当前没有调用 `装配运行期只读查询组合器`；即使未来消息进入自我线程，002-04 仍只会返回合法等待。
- 当前 N04—N07 的其它治理骨架会在 002-03/002-04 之前结构化终止。任务结果定位是 8100 §3、§8 授权的独立正式结果读回，不依赖 002-05、任务完成或需求满足，因此本叶把纯分类和任务结果绑定窄路径放在其它尚未完成治理骨架之前；非任务结果输入仍沿既有路径，不宣称闭合。

## 3. 自我线程值式合同

在 `海中鱼巣/线程/自我线程生产创建.数据.h` 增加以下生产合同。

### 3.1 创建配置

`自我线程生产创建请求`新增：

```cpp
std::uint64_t 最大任务结果来源需求成员数 = 64;
```

该值是 002-04 独立读回的调用方资源预算，不是业务事实。创建请求必须非零，重复创建语义比较必须包含该字段；自我线程创建成功后锁定该值。普通应用显式使用 64，与当前治理读取默认预算一致，禁止从邮箱容量、消息数量或任务结果反推。

### 3.2 处理槽状态

```cpp
enum class 任务结果治理处理槽状态 : std::uint8_t {
    待复核 = 1,
    后继已形成 = 2,
    合法等待 = 3,
    当前性终止 = 4,
    输入拒绝 = 5,
    数量预算不足 = 6,
    资源等待 = 7,
    内部终止 = 8
};
```

处理槽状态是自我线程的非权威运行材料，不替代 002-04 状态，不写入 DATA，也不成为任务或需求状态。

### 3.3 后继输入与公开快照

```cpp
struct 任务结果治理后继输入 final {
    std::uint64_t 治理批次身份;
    std::uint64_t 治理消息编号;
    std::uint64_t 治理输入幂等键;
    L2任务身份 任务;
    L2实例方法身份 实例方法;
    std::uint64_t 执行轮次;
    L2任务实际结果身份 任务实际结果;
    std::uint64_t 共享事实截止G0;
    治理输入事实复核状态 复核状态;
};

struct 任务结果治理处理槽快照 final {
    任务结果治理处理槽状态 状态;
    std::uint64_t 治理批次身份;
    std::uint64_t 治理消息编号;
    std::uint64_t 治理输入幂等键;
    L2任务身份 任务;
    std::uint64_t 共享事实截止G0;
    std::uint64_t 复核次数;
    治理输入事实复核状态 复核状态;
    std::optional<任务结果治理后继输入> 后继输入;
};
```

治理输入的线程内身份固定为`治理消息编号 + 幂等键`；二者都来自原始冻结消息，不新增业务稳定编码。只有`后继已形成`携带后继输入；其它状态后继为空。

`任务结果治理后继输入`是未来直接后继的输入材料，不是 002-05 请求，不声明任务完成或需求满足。

### 3.4 治理循环退出结果

`自我治理循环退出结果`新增`任务结果后继已形成`。它只表示当前线程处理槽已冻结一份完整任务结果后继输入，线程入口不得把它升级为任务、需求或服务成功。

## 4. 自我线程公开生产入口

在现有 `自我线程` 类中新增：

```cpp
自我治理提交结果 提交治理消息(
    const 自我治理消息& 消息,
    std::uint64_t 当前时间戳) noexcept;

std::optional<任务结果治理处理槽快照>
等待任务结果治理处理槽(
    std::uint64_t 最小复核次数,
    std::uint64_t 最大等待毫秒) const noexcept;

bool 请求重试任务结果治理处理槽() noexcept;
```

- `提交治理消息`只在创建完成且唯一邮箱仍存活时委托 `有界自我治理邮箱::提交`；协议、幂等、顺序、容量和停止仍由邮箱唯一裁决。它不复制队列、不绕过准入、不直接调用领域函数。
- `等待任务结果治理处理槽`只复制受锁保护的值式快照；最小复核次数和等待时间必须非零。超时或尚无对应快照返回空。
- `请求重试任务结果治理处理槽`只在当前槽为合法等待或资源等待且物理线程仍在运行时递增重试信号并唤醒同一线程；其它状态返回 false。它不提交消息、不改 G0、不改路由项。

## 5. 唯一处理槽与执行顺序

`自我线程`新增唯一私有当前批次处理槽，持有：

```text
不可变治理批次
+ 002-03 有序路由结果
+ 当前输入索引
+ 当前任务结果路由项
+ 已发布任务结果治理处理槽快照
```

执行顺序固定为：

1. 若无当前处理槽，调用唯一批次路由冻结下一批；成功后把完整批次移动到自我线程私有槽，禁止保留栈内第二份。
2. 对槽内批次恰一次调用 002-03。停止优先仍立即停止；入口拒绝或内部错误结构化终止。
3. 按冻结顺序取得第一条任务结果复核路由项。没有任务结果输入时，复用同一分类结果继续既有 N04 以后路径；不得再次分类。
4. 以槽内批次身份、路由项消息中的 G0 和创建时锁定预算调用 `复核任务结果治理输入绑定事实`。
5. 每次调用前递增槽内复核次数并发布待复核快照；调用后按第 6 节映射状态。
6. 成功时逐字段互证消息任务、批次、G0 与 002-04 绑定，冻结唯一后继输入并返回`任务结果后继已形成`。本叶不清槽、不推进最后成功批次游标，等待未来直接后继消费。

同一槽已有后继输入时不得再次读取邮箱或再次猜测执行轮次。若内部恢复路径再次得到`已绑定`，只有与已冻结后继逐字段全等才是槽级精确重复；任何差异为内部终止。槽级精确重复不新增 002-04 状态，也不生成第二后继输入。

## 6. 状态分账与重试

| 002-04 状态 | 处理槽状态 | 行为 |
| --- | --- | --- |
| 已绑定 | 后继已形成 | 冻结唯一后继输入；允许未来直接后继消费；本叶停止 |
| 合法等待 | 合法等待 | 保留同一批次、同一路由项、同一 G0 和原始输入，等待显式重试信号 |
| 当前性漂移 | 当前性终止 | 采用用户允许的结构化终止；不自动换新 G0，不重新读取邮箱 |
| 引用冲突、入口拒绝 | 输入拒绝 | 当前输入拒绝，零后继，不进入后继 |
| 数量预算不足 | 数量预算不足 | 结构化终止，零后继；不得返回截断材料 |
| 资源失败 | 资源等待 | 保留同一槽，等待显式重试信号 |
| 内部错误 | 内部终止 | 结构化终止，零后继 |

合法等待或资源等待被唤醒后，只重新调用 002-04；不得调用邮箱冻结、不得重新分类、不得改变消息、批次身份、G0 或预算。停止锁存优先于重试并正常退出。

## 8. 生产级验证

治理专项必须在现有公开 DATA-L2 服务形成正式任务实际结果后，经过以下真实链路：

```text
自我线程创建并停门
-> 自我线程::提交治理消息
-> 私有真实治理邮箱
-> 开放治理运行门和真实物理自我线程
-> 唯一批次路由冻结
-> 002-03 分类
-> 自我线程持久处理槽
-> 002-04
-> 任务结果治理后继输入快照
```

至少验证：

1. 成功链的批次身份、消息编号、幂等键、任务、实例方法、执行轮次、实际结果身份、G0 和复核状态逐字段一致；
2. 重复提交同一消息由真实邮箱返回重复材料，不形成第二批或第二后继；
3. 未知任务经真实线程形成合法等待槽；显式重试后复核次数增加，但批次身份、消息编号、幂等键、任务和 G0 不变，证明零邮箱重读；
4. 旧 G0 经真实线程形成当前性终止和零后继；
5. 处理槽读取超时、非法重试状态和停止唤醒不会伪造后继；
6. Debug/Release x64 全量 Rebuild、两配置 `--test-治理`、strict 和 diff 检查通过。

禁止只直接调用 002-04 证明本叶完成，禁止手工构造任务实际结果，禁止以日志文本代替结构化槽快照和逐字段断言。
