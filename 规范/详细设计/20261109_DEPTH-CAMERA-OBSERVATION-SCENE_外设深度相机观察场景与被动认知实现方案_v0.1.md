## 1. 目标与首版范围

建立一条独立工作的深度观察链：相机持续取得深度材料，将点簇及其可测特征保存到外设世界的观察场景；已建立的自我读取任务被动读取变化，完成对象对应后，更新内部世界树当前场景。

相机已安装在可主动控制的云台上，不能继续采用“相机对场景固定”的前提。云台与相机分别作为独立外设，以安装关系连接。首版建议限定云台底座固定，相机随云台转动；底座是否固定尚需现场确认。先实现几何观察，不要求能把每个点簇命名为杯子、桌子或人。不以自然语言转换、上层筹办找到方法、跨帧稳定识别或体素重建作为相机采集的启动前提。

首版必须覆盖：独占采集、深度点材料、点簇、前景优先调度、背景分帧缓存、观察场景发布、持续读取任务、云台按需控制与反馈、采样时相机位姿关联、内部当前场景更新以及停止回收。底座自由移动时的定位、完整物体重建和通用类别识别作为后继能力；若底座实际在移动，首版不承诺全局坐标融合。

## 2. 语义边界

1. **相机独立工作。** 外设模块更新外设观察场景，不直接修改自我内部世界；自我通过读取任务消费场景。
2. **观察内容先于身份判断。** 观察场景中的点簇存在表示“这次观察到的候选”，不自动证明其现实身份、完整形状或类别。
3. **通常一簇对应一个存在，但不强制一一对应。** 遮挡可能把一个物体分成多簇，接触表面可能把多个物体连成一簇。相机会话内簇号不能直接作为内部存在编码。
4. **事实优先有适用范围。** 同一对象、同一特征、兼容坐标与时间条件下，新有效实测优先于旧认识和预测。噪声、无效深度、插值及历史补全不因来自相机就成为更高优先级的新实测。
5. **前景是处理优先级，不是存在类别。** 距离、视野位置、遮挡程度和关注对象分别表达。近处、中央或关注区域、遮挡较少的材料优先处理；“完整可见”只指当前视角可见部分，不包含物体背面。
6. **忽略背景是跳过本帧重处理。** 不能据此删除背景存在、判定消失、刷新最后观测时间，或将历史背景与本帧前景称作同一时刻的完整场景。
7. **特征是正式承载。** 通过场景、存在、特征等领域公开函数写入；相机业务不直接写基础数据集。状态和动态由事实发布链按变化形成，不由采集器或本能函数补造。
8. **队列只通知，场景供读取。** 原始大缓冲由受控材料缓存持有，观察场景通过正式引用访问；通知消息不是另一份点簇事实。
9. **云台请求不是云台事实。** 目标角度、命令已发送和设备已接收均不能充当实际角度或到位证据。驱动持续读取反馈并经领域服务更新外设场景，自我再读取实际状态。

## 4. 总体流程

```text
普通应用启动外设模块（不等待任务筹办）
  → 独占打开相机 → 取得带标定与时间的深度帧
  → 全幅轻量变化/有效性检查
  → 优先区选择 → 前景点簇处理 → 剩余预算处理背景区域
  → 形成带来源的点簇特征及覆盖信息
  → 经领域服务发布到外设观察场景
  → 发布变化通知
                              ↓
自我已确认的持续读取任务：等待 → 读取观察场景当前材料
  → 检查来源、时间与坐标适用性 → 建立/更新候选与内部对象对应
  → 经领域服务更新内部当前场景 → 提交本任务读取进度 → 再等待
```

每帧不新建需求和任务。通知可合并；读取任务不能依赖每条通知都到达才能恢复当前场景。

主动改变视向另走一条控制链，不由采集线程自行决定转动：

```text
观察任务发现目标不在视野、需要细看或需要补全指定区域
  → 自我确认相应需求 → 任务筹办确定目标视向及必要条件
  → 本能方法提交云台控制请求 → 云台驱动执行
  → 云台实际反馈更新外设场景 → 读取任务判定视向/运动状态
  → 位姿及时序可用时采用对应深度帧 → 继续观察或完成需求
```

已有任务可在其确认范围内执行观察路径；不要求每次微调重建需求树。后台区域处理只分配计算预算，不因此取得无限扫描或转动外设的权限。

## 5. 观察场景的信息组织

以下是拟新增语义结构，不是已存在的字段编码或 C++ DTO。实施计划需将其逐项映射到正式概念、特征和值域，不创建平行的相机私有事实模型。

| 所属对象 | 特征/材料 | 规则 |
| --- | --- | --- |
| 相机存在 | 设备标识、运行状态、采集配置、标定引用、相机坐标系、当前观察批次 | 设备标识不是被观察对象身份；重连建立新会话 |
| 云台存在 | 设备标识、可控轴及量程、实际角度/运动状态（若可读）、反馈来源时间、可用性 | 轴数、零位、方向、单位按设备合同；不可读的实际值保留未知 |
| 云台控制场景 | 云台引用、待执行请求、请求处理状态、实际反馈引用 | 控制记录与测量事实分开；请求号只追踪一次操作，不充当实际状态 |
| 安装关系 | 相机到云台末端的刚性变换、各轴几何、底座到当前场景的变换及其适用期 | 相机光心通常不在转轴中心，必须包含转动引起的平移 |
| 观察场景 | 相机引用、当前批次、区域覆盖、候选引用、最近实际采样时间 | 批次用于该设备局部材料关联，不引入全局事实代次 |
| 点簇候选存在 | 点材料引用、成员索引、位置/包围范围、实测点数量、可见范围、观察来源 | 点材料不可变；位置是可见点几何量，不冒充完整物体质心 |
| 区域覆盖 | 本批已处理、历史保留、尚未处理、无有效深度或已失效，以及各自源时间 | “无有效深度”与“本帧没处理”不可混同；不能用缺测直接证明空闲空间 |
| 点材料 | 米制 XYZ、源深度像素索引、有效性、源帧、标定版本 | 原始、滤波、补全分账；插值点不计为当前实测点 |

不为每个深度点建立通用节点。大规模点集保存在有界不可变材料缓存中，通过领域认可的类型化材料引用访问，禁止把内存地址或临时文件路径伪装成特征值。

时间保留设备源时间及其时间域、宿主接收单调时间、处理和发布时间。接收时间不冒充曝光时间；没有时间标定时，不捏造跨设备统一绝对时间。

相机帧另关联其采样期间适用的云台位姿依据。云台反馈保留其时间域、来源、测量精度和有效期，可按有界时间窗口保留，供读取任务关联，不要求相机独立采集先等待它。不能用处理时最新角度替代曝光期间角度。

当前批次给出一份一致的引用清单，但清单中的历史背景仍保留自己的源时间。批次一致不等于所有区域同时采样。

## 6. 深度点簇处理

1. 从原深度像面读取有效深度和内参；识别无效编码及配置量程，不把无效值转换成距离零。
2. 按实际标定和畸变模型反投影，生成深度相机坐标系中的 XYZ（米）。深度 Z 是光轴距离，不等于点到相机的欧氏距离。
3. RGB 仅按需关联颜色；不能先裁到彩图视野而丢失深度视野边缘的有效点。
4. 用有组织深度网格邻接形成候选，以三维相邻距离、深度跳变和有效性约束断开边界。距离阈值随深度/噪声配置，不能跨无效区域无条件连通。
5. 对区域边界保留重叠带和跨块归并信息，避免同一表面被处理瓦片永久切断。不同源时间区域只能建立候选关联，不能直接宣布为同帧完整簇。
6. 提取可见点簇位置、范围、点数与质量；小簇是否过滤应可配置，并保留处理覆盖语义，不能把过滤等同于现实不存在。
7. 跨帧关联只维护相机会话内候选连续性。分裂、合并或歧义时保留关联依据，不强行沿用内部存在身份。

首版先用深度主导的有组织邻接算法，避免依赖旧 RGB 轮廓前置。接触物体、镜面和透明物体是能力边界，不能用算法输出保证“一簇就是一个完整实体”。

## 7. 前景优先与背景逐步补全

每帧处理分为低成本全幅检查与有预算的详细处理。轻量检查用于发现近处新物体和明显变化，不等同于完成全幅点簇重建。

优先顺序建议为：显著新变化及正在关注的区域 → 近处/中央且可见性较好的区域 → 其他待更新背景。距离、中心范围、可见性、变化阈值和帧预算均为配置，不写死为概念分类。

背景按最久未处理区域轮转，记录积压量和最老观测年龄；年龄须注明是同一设备时间域内的源相对年龄，还是宿主单调时钟下接收后的驻留时间，禁止跨时钟直接相减。留出可配置背景预算，避免前景永久占满。若前景负载仍超出总预算，应降采样/降低刷新频率或报告处理积压，不能承诺背景必然按时补齐。

允许当前帧不处理未补完背景，前提是：

- 保留其已知材料及原源时间；消费者能辨别历史、未知和失效。
- 已发现变化或遮挡的区域标记需要重新观察，不能继续作为当前实测。
- 相机坐标或标定变化后，使受影响缓存失效或重新配准；禁止沿旧像素位置直接拼接。
- 相机随云台转动而没有可靠位姿时暂停向内部世界写入全局位置，仍可保留相机局部观察。新视向必须重新建立图像域覆盖；旧背景可作为带原位姿和源时间的历史材料保留，但不能继续当新视向下的当前像素缓存。不得把视野整体移动直接判成各个物体同时移动。

### 7.1 云台位姿与观察时序

对深度相机坐标中的点，按以下安装链转换到当前场景：

```text
场景中的点 = 底座到场景变换
           × 云台各轴在采样时刻的运动学变换
           × 深度相机到云台末端安装变换
           × 深度相机坐标中的点
```

各变换须约定方向、单位、轴顺序和标定版本；不能只把深度点绕相机原点旋转。底座移动时，第一项也随时间变化，不能靠云台角度单独恢复相机在场景中的位置。

相机内部的深度到彩色外参不能代替云台安装标定。重新找零、安装调整、设备重连或反馈来源改变后，须重新确认受影响的坐标/位姿适用性，不自动沿用旧姿态。

首版推荐“转动→确认实际停稳→采用停稳期间新采集帧”的分步观察，而非边转边精确融合。采集本身可持续，转动中的原始材料可缓存；没有曝光期位姿或质量不合格的帧不参与全局几何更新。

转动时一帧可能跨越一段姿态变化，RGB 与深度也可能不是同一采样时刻。没有经过验证的运动补偿，不以帧首尾角度插值就宣布整帧位姿准确；静态输入的时间配对门槛不证明动态融合可靠。运动停止与观察质量恢复分别判断，余振、模糊和深度不稳定不能仅因收到停止反馈而忽略。

停稳须由可用反馈和配置的角度/速度容差、稳定时间窗共同判断，具体参数随硬件冻结。只有运动标志而无实际角度，只能确认反馈所支持的停止状态；只有命令角度或等待时长，不能确认实际到位。还应考虑相机内部排队延迟：停稳后收到的旧帧不一定是在停稳后采集；须按源帧时间关联，或使用经过核实的同步/排队上界选取安全的新帧，不能随意睡眠固定时长代替依据。

若设备没有足够反馈，先完成请求发送与相机局部观察；角度仅可作为带来源的估计，不能按最高优先级实测覆盖内部位置。要完成全局融合，需增加编码器、有效视觉定位或其他可验证位姿来源，不暗中假定云台具备这些能力。

## 8. 发布、状态与动态

处理器在锁外准备不可变材料、点簇描述和特征更新清单。领域发布入口完成本批引用/特征的组合提交，成功后再发通知；读取者不得看到新批次指向尚未完成的材料。

发布失败时释放未发布候选，不推进当前批次或读取进度；已发布事实不得因通知失败回滚。通知丢失通过后续通知或周期性读取当前批次恢复。

按当前特征/状态合同执行：首次观察形成基准状态；有可比较的前后状态才形成变化动态。相同几何值的新有效观测可以更新其观察时间/来源特征，但不能伪造几何值变化。接收心跳不能刷新物体的实测时间。

相机观察到变化不等于变化由某个自我动作导致。只有明确来源关联时才建立动作与变化的对应，禁止按时间相邻自动宣告因果。

缓存引用在发布前取得租约；当前场景和活动读者持有的材料不可被淘汰。预算不足时跳过或替换尚未发布候选并记录缺口，不阻塞采集无限增长。历史大材料允许按保留合同到期释放，但历史状态必须保留来源元数据及“材料已不可回读”的明确语义，不能留下伪装有效的悬空引用。具体存储/释放 ABI 在首份代码计划中冻结。

## 9. 自我的被动读取与内部场景更新

持续读取任务仍来自自我确认的需求；相机启动不依赖它已经建立。任务建立后先读当前观察场景，再等待变化，等待不占用一个永久阻塞的工作线程；复用现有任务等待/唤醒机制，不在本方案偷偷改为整池停止或新线程模型。

读取步骤：

1. 按场景和读取任务定位自己的进度，获取当前批次及可用变化范围；不同任务独立进度，不“消费掉”共享观察事实。
2. 若历史范围已丢失，明确记录缺口并回读当前全量。全量可恢复当前值，不能补造遗漏期间的变化动态。
3. 核对本次实际使用材料的类型、来源、时间、坐标及必要租约，不反复比较整棵世界树旧快照。
4. 根据已有对应、几何一致性和必要上下文建立观察候选到内部存在的关联。对应不明确时保留候选，不拿最近对象或数组位置猜身份。
5. 对首次可用的孤立点簇，可在内部场景建立匿名观察候选，记录来源；它不是已确认的命名现实物体。后续确认/合并通过领域接口完成，不每帧重建同一个候选。
6. 在对象和坐标对应有效时更新内部存在的实际可测特征。新的有效实测可替换旧估计；旧帧、历史补全、未处理背景不得覆盖较新的实测值。
7. 只有有效覆盖和足够的缺席证据才讨论对象不再可见；不把遮挡、无效深度或跳过区域变成删除存在。
8. 成功写入后推进该任务进度。部分目标写入失败时保留已发生事实，按来源批次与目标对应恢复；重读相同来源不得重复创建候选或重复记录同一次变化。

自我所在场景与相机观察场景不是同一个场景；相机安装位置、视线和坐标变换必须显式表达，不能假定自我位于相机原点。

### 10.1 按需控制云台的本能方法边界

修改对象是**现实外设云台的姿态/运动特征**；原因是当前视野不能满足已确认的观察需求；目的是使相机获得所需观察方向。它属于普通方法，不是任务虚拟存在的内部治理方法。

拟设“请求云台转向”和“请求云台停止”两类操作，名称及方法头在后续合同中冻结。转向函数仍只接收一个参数场景节点，其中定位云台、目标视向及必要参考坐标；有多个观察任务时，由统一控制服务仲裁，同一云台同一时刻仅一个有效运动指令流。

必要条件按实际分支声明：指定云台及可用控制通道、受支持的目标形式、所需坐标/安装材料，以及目标位于设备可达范围。绝对角度指令和相对转动指令分别声明条件，不要求两套材料同时具备；设备不可读当前位置时，不能据此保证相对转动最终达到某个绝对视向。

函数复核必要条件后，记录真实动作并提交控制请求；直接操作结果是请求已入列/已发送的实际材料，不是“相机已经看见目标”或“云台已经到位”。方法头与因果链须区分直接请求变化和设备反馈所证明的姿态变化；发送成功不能结算观察需求。后续任务通过外设场景实际状态判定目标，再采用相机材料。条件不足返回筹办/等待，不在函数内部派生子需求。

驱动对每条请求维护唯一标识，区分未发送、已发送、设备接受、实际执行反馈及失败/未知。超时不是未执行证明，尤其相对指令不能盲目重发。新请求的替换、排队与取消策略需在设备接入合同中冻结；本草案不擅自允许某个背景扫描任务抢占其他控制任务。
