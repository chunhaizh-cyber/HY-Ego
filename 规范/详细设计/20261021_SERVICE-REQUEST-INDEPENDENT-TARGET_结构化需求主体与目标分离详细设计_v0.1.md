## 1. 目标及边界

“周春海希望这杯水达到40℃”中，需求主体是周春海，目标存在是这杯水。来源会话证明谁表达、确认内容，不能把目标存在强制改成来源人类。本切片让结构化入口完整保留该区别，形成可读回的要求材料 R、理解 U 和内容确认 C。

本切片不实现本能方法，不改变现实存在或任务虚拟存在特征，不建立服务对象需求 D，不把 D 加入服务对象需求特征，不建立自我需求或任务。后续“获取服务对象需求信息”方法消费经确认材料、建立或复用 D、落实需求特征集合，仍是独立后继。自然语言理解、补问策略、服务对象发现与连接均不属于本提供者。

正式依据：[0050](../0050_项目通用机器逻辑与禁止性规则总纲_20260721.md)、[5170](../5170_子规范_需求治理详细合同.md)第2.1节、[6120](../6120_子规范_自我存在服务与生存基本因果闭环_20260720.md)，以及[获取服务需求方案](../../目标/20261020_获取服务需求本能方法实现方案_v0.1.md)。确认具体内容不等于提出求助，也不等于自我承接。

## 3. 输入、DTO与唯一所有者

保留 `结构化服务要求服务` 为R/U/C唯一业务owner；网页宿主只解析/显示；装配负责活跃会话核验及来源绑定。调用方不得从浏览器输入指定来源人类。

以下增量冻结为未来实现合同：

1. `服务要求理解请求` 增加 `稳定编码 目标存在节点`，放在来源人类后。它是必填显式参数，零值拒绝。新U直接保存该字段，不再从来源推导。
2. `网页服务目标提交` 增加 `std::uint64_t 目标存在编码 = 0`；`网页部分服务要求提交` 增加 `std::optional<std::uint64_t> 目标存在编码`。完整请求必须有值；部分请求没有该字段就是未知，不能自动填人类。
3. `网页服务要求显示信息` 中 `服务对象编码` 固定表示来源/主体；目标E从嵌套目标字段读取。部分结果的 `已知目标` 也回传目标E，已有服务对象字段保持来源含义。
4. 在 `宿主.网页对话.h` 新增 `enum class 网页服务材料投递状态 : std::uint8_t { 未尝试 = 0, 等待后继消费 = 1, 消息已接纳 = 2, 暂未接纳 = 3 };`；`网页服务要求结果` 与 `网页部分服务要求结果` 各增加同类型字段 `材料投递状态`，默认 `未尝试`。这不是确认结果或自我承接状态。
5. 既有部分结果 `消息已接纳` 保留为兼容投影，仅当本次确有消息接纳回执时为true。它不是“存在确认C”“自我已承接”或“任务已建立”的别名。
6. `网页服务输入状态` 尾部追加 `目标范围已变化`，不重排原枚举。它仅表示场景完整查询未取得稳定读回，本次不接受写入，不作为确认否定或工程故障。

完整请求和部分请求的目标都是已知存在的稳定引用。不通过名称、数组第一项或会话来源猜测；不在此入口创建缺失存在。非法/不存在编码按输入拒绝；不能定位时由上游继续取得目标信息。本轮不增加跨世界搜索或目标发现，也不新增“必须和来源同场景”的限制；现实目标由调用者提供对应现实存在引用，不能伪装成任务虚拟存在。通用存在合法性复用存在owner，不通过底表字段拼装身份。

现实归属是装配入口的显式前置合同，不由浏览器编码自证。新增装配内部函数 `网页服务输入状态 核验服务要求现实目标(普通应用上下文&, 稳定编码)`，声明/定义均限 `装配.普通应用.cpp` 的内部命名空间，调用 `当前.世界事实.场景服务.读取本树范围成员完整()`。只有 `已完成` 且E出现在根场景、场景成员组的场景编码、或范围成员存在组中才返回 `已完成`；完整范围内不存在返回 `输入不合法`。`读取已变化` 返回新增 `目标范围已变化`，不使用部分候选；根不可读、结构不一致、资源失败以及该无起点接口不应出现的起点不可读/不属本树均走工程路径。禁止用吞异常为false的 `存在属于场景范围()` 替代。

完整预览在owner建立U前核验目标；部分写入口对新传入目标及既有R中已知目标去重后逐一核验，再调用owner；确认入口先按会话/主体授权读取U，再核验U的目标，最后调用owner确认。不跨这道门写新R/U/C。纯读取保留历史材料，不要求旧材料仍在本次现实范围，不能因现实位置变化抹掉已发生内容。该快照是入口范围资格核验，不是长期世界归属锁；后续消费者必须依据自己的当前场景及身份保护合同重新核验，不能把该核验当执行许可。

结构化owner保持通用目标存在核验；它的可信调用方必须先落实所属世界范围前提。网页生产调用只有上述装配路径，不新增绕过入口。除DTO字段、第6节装配内部返回类型及以上私有核验函数外，现有服务公共函数签名、材料读取接口和构造注入不变；不新建源文件或工程登记。

## 4. 完整与部分材料处理

### 4.1 完整理解

装配先核验会话，绑定来源人类，再把显式目标E和目标定义传入owner。owner分别验证来源人类归属、目标E存在及既有目标形状/语义合法性。目标E可以不是人类，不必与来源相同；不要求当前值已经满足目标，也不把目标当前值变化当确认失效。

带来源R时必须核对会话、主体、R完整目标E和目标定义。R已有U时，E、目标定义、固定语义均一致才复用，否则保持旧材料并报告不匹配/需重新确认；不得用新的E覆盖旧U。

无R时精确复用键至少包括来源人类、会话、目标E、目标定义、固定语义、可选R。不同E即便温度和目标域完全相同，也不能复用同一个理解。

### 4.2 部分补齐

沿用来源人类＋会话＋来源要求标识及可选R的身份合同。目标E和其他字段一样：未知可补；相同为重复；已有不同值为已知值冲突，不覆盖旧事实。同一R不能借补充改成另一对象的要求。

目标E未知时保留缺项，不形成完整U。补齐所有目标字段后复用现有 `形成部分理解`；其目标E必须来自R，不能回退为来源人类。需要改目标时提交新的来源要求标识/材料，再由对方确认新的U。

### 4.3 重述与确认

重述明确分开“需求主体#E1、目标存在#E2、目标特征、值目标或方向目标”；值目标采用确认时的固定语义，不能引用后来改变的概念含义冒充原要求。网页显示稳定编码为字符串，不能经JS Number损失精度。

确认仍由同一有效绑定会话和来源人类针对精确U执行。确认保护继续核对来源人类身份/人类概念；同时使用 `新_存在类::读取存在身份保护(目标E)` 保护目标身份，两者相同则合并去重保护条目。保留现有特征类型、值域、比较概念语义保护及最终读回。

不得把目标要求为人类，不能保护全部实时特征值作为目标语义。目标温度变动不改变“这杯水到40℃”的内容；目标身份丢失、确认引用结构损坏或定义变化则不能按有效确认消费。身份不存在与工程读取失败严格分开，后者进入现有工程路径，不解释为正常否定或未知。

## 5. 事务、持久化及并发

沿用R/U/C既有原子节点组发布、R补充分项CAS、U引用和C追加事务；不增加装配直接写底表。完整请求补入目标字段后仍在节点发布前完成输入校验，发布后执行现有固定语义读回。

R冲突、语义变化和确认失效保留既有材料；不得原地改写U/C。并发同来源重投依既有锁/CAS实现唯一复用，不以新目标绕开R身份冲突。确认完成后投递失败不能回滚C，更不能返回“确认失败”；重复确认读回已有C，并可按原有投递入口重试。

本切片不增加存在删除/迁移服务、不声明新的强引用生命周期合同。使用既有身份保护和材料引用能力；若实际调用发现其保护范围不足以满足既有确认事务，作为本提供者具名漂移返回，不临场扩展全仓删除机制。

## 6. 内容确认与后续消息分账

`投递完整服务需求材料` 保留装配内部函数形态及参数，返回类型由bool改为 `网页服务材料投递状态`，唯一允许调用方为本文件的 `提交普通应用部分服务要求`、`确认普通应用服务要求` 两个写入口。控制顺序冻结如下：

| 本次调用情况 | 内容结果 | 材料投递状态 | 兼容bool |
| --- | --- | --- | --- |
| 预览、只读查询、材料未完整或未确认；完整确认没有来源R而不存在既有交接包 | 沿用相应材料结果，C可独立成功 | 未尝试 | false |
| 已确认且目标E不同于来源人类 | C成功建立/复用且可读回 | 等待后继消费；不调用旧自我入口 | false |
| 已确认、同对象，旧自我入口返回已接收/精确重复 | C成功不变 | 消息已接纳 | true |
| 已确认、同对象，旧入口队列满或已停止等正常暂拒 | C成功不变 | 暂未接纳 | false |

对已有结构损坏、读取异常不使用上述正常暂拒兜底，保持工程日志/报告/中断链。旧入口的 `资源失败` 目前与邮箱满合并返回false，本次拆出为工程错误，不归入正常暂拒枚举；保留同对象投递通路不意味着继续混淆这两类错误。

`确认普通应用服务要求` 必须消费投递枚举写入独立结果字段，不能再忽略返回值；没有来源R时保持未尝试，不为交接而补造R。原确认状态与确认编码不受投递状态覆盖。网页分别展示“内容已确认”“尚待后继消费，未交自我承接”或“消息已接纳，不代表任务已建立”。不从消息回执填需求编码、任务编码，也不增加推测的已承接字段。

`形成部分要求网页结果` 固定为纯结果映射函数，删除其中实际投递调用，不增加隐含读写bool。它仅形成显示/缺项/冲突及已知目标，投递枚举始终默认未尝试、兼容bool为false。

`提交普通应用部分服务要求` 在owner返回成功并完成结果映射后，显式调用投递函数并填写枚举/兼容bool；材料未完整或未确认仍返回未尝试。`确认普通应用服务要求` 在确认成功且有来源R时显式投递。`读取普通应用部分服务要求`、预览读取、目标选项查询等纯读入口只映射结果，零投递；不可仅改回显而保留helper的副作用。不增加历史投递账。

新异目标材料只停留在提供者。未来D发布/自我承接消费者完成其独立合同后才解除阻隔；不能仅删装配判断而复用旧自我硬等式路径。

## 7. 网页兼容及旧数据

表单、JSON解析白名单、完整形状判断、序列化与内置JS同步增加显式目标E。可将绑定人类作为界面上可见、可修改的初始输入值，但提交必须携带该值；后端不能替旧缺字段请求默认为来源。

完整旧客户端缺目标E返回现有输入不完整结果；部分旧客户端缺目标E保持缺项。这是明确的输入收紧，不伪装无损兼容。内置页面与后端同批发布。原“当前特征提示组”仍只是来源人类提示，必须标注对象，不宣称是任意新目标的特征；本轮不增加全世界目标枚举。

存量U已有目标E字段，无需数据回填或重编号；原同对象U/C继续有效且沿旧投递路径。解码去除来源等于目标限制，但保留各自存在、来源、人类和目标定义核验。缺字段或不完整存量不能推断修补，保留并报告。异目标材料即便旧持久层可以存储，也不能自动送入旧自我消费者。
