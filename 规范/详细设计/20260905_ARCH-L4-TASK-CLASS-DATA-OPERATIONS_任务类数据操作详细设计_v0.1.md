# 任务类数据操作详细设计

日期：2026-09-05

版本：v0.1

身份：`ARCH-L4-TASK-CLASS-DATA-OPERATIONS`

状态：设计已冻结，等待代码实施

## 1. 目标与完成边界

新建 `海中鱼巣/领域/数据服务.任务类.ixx`，只形成一组薄数据操作：

```text
新增一条不可变任务类记录
+ 按记录身份读取
+ 按“所属存在 + 来源需求”精确读取
+ 经来源需求公开入口读取本次任务目标方向
```

本模块属于 `ARCH-L4` 新结构记录面，不属于 `DATA-L2`，也不得写成未定义的
`DATA-L4`。物理文件名沿用用户指定的“数据服务”，不据此改变架构层级。

本叶不是3200/5260定义的完整正式任务治理。它不建立同类任务查询锚点、正式
`T→D`关系组、任务虚拟存在Vt、任务状态、任务轮次、筹办轮次、执行轮次、路径、
实例方法、执行冻结、结果、验证、结算、调度或生命周期退出；新记录身份不得强转、
别名化或回显为旧`L2任务身份`，也不得由旧消费者当作完整正式任务T。本叶只为后继
新逻辑提供独立、不可变的“所属存在 + 来源需求”引用记录和零写目标方向读取。

用户允许新旧两套在迁移期并行。本叶不调用、修改、适配、迁移或退出旧
`服务.L2*`；新 owner、新稳定编码、DTO 和模块均与旧任务结构隔离。最终替代旧逻辑
不属于本计划完成条件。

## 2. 正式依据与当前事实

- 0050、4030：需求、任务和方法位于ARCH-L4；记录面只能机械保存、读取和校验
  调用方已裁决的结构，不得判断任务成立、目标达成、状态、执行或结算。
- 3200：完整正式任务的目标必须从当前显式来源需求读回，任务不得复制需求所属存在、
  目标宿主、目标特征、目标状态合同或当前世界事实。本叶因此只保存来源需求引用。
- 3200、5260同时要求完整正式任务具有查询锚点、Vt、首轮次与首态等闭包；这些均被
  用户本次薄数据函数范围明确排除，故新记录不得宣称正式任务治理闭环。
- 当前基线 `f783e22d5faa9c811201d5f2238c2091c91b2356` 已发布
  `数据服务.需求类.ixx`，其记录公开返回所属存在、目标宿主、静态目标特征和方向定义，
  且 `计算临时需求方向` 可在同一G0按需求身份、当前事实特征、请求身份和结果位形成
  零写比较结果。
- 当前新任务文件不存在，计划索引为空。旧`服务.L2任务结构.ixx`及相关旧任务模块
  仍在工程中，但只作迁移期隔离事实，不提供本叶授权、DTO或实现来源。

## 3. 模块、依赖与 owner

文件和模块固定为：

```text
文件：海中鱼巣/领域/数据服务.任务类.ixx
模块：海中鱼巣.领域.数据服务.任务类
工程：海中鱼巣.vcxproj，以 ClCompile 登记
filters：海中鱼巣.vcxproj.filters，置于现有领域模块分组
```

模块只允许：

```cpp
export import 海中鱼巣.领域.数据服务.需求类;
```

它不直接保存特征类、存在类或二次特征类服务引用。用户允许的这三个服务已经由需求类
负责其自身记录互证与方向计算；任务类不得绕过需求类复制相同目标解释或形成第二计算链。

唯一服务类持有一个专属、move-only `L1所有者范围写端口`，只写本叶新记录节点和两条
关系。构造合同固定为：

```cpp
struct 任务类结构类型 final {
    稳定编码 所属存在关系类型{};
    稳定编码 来源需求关系类型{};
};

任务类数据服务(const L1事实基座服务& 第一层服务,
    const 需求类数据服务& 需求服务,
    L1所有者范围写端口&& 写入端口,
    任务类结构类型 结构类型);
```

两个关系类型必须非零、互异、当前、未退出、为普通节点并由该写端口 owner 持有；
owner 必须是当前独占结构范围。构造失败抛 `std::invalid_argument`，不隐式创建类型、
不领取第二端口。

依赖函数白名单精确冻结为：

```text
L1事实基座服务：
  读取中性当前事实代次
  读取当前结构所有者
  读取所有者范围当前节点
  读取所有者范围当前目标关系组
  尝试读取所有者范围一致当前投影
L1所有者范围写端口：
  读取首次写入材料
  提交所有者范围中性写集
需求类数据服务：
  查询需求记录
  计算临时需求方向
```

禁止直接调用特征类、存在类和二次特征类；禁止使用L1中性v1写入口、私有仓库、SQL、
锁、缓存、raw owner选择、旧L2 DTO/函数或白名单外函数。

### 3.1 文件、函数归属与复用裁决

| 文件 | 分类 | 唯一所有者 | 工程登记 | 调用方式 | 写入方 / 读取方 |
| --- | --- | --- | --- | --- | --- |

| 函数 | 能力 / 事实所有者 | 形态 / 可见性 | 声明、定义与插入锚点 | 允许 / 禁止调用方 | 新建理由 |
| --- | --- | --- | --- | --- | --- |
| `新增任务记录` | 不可变二元记录原子发布 / 本任务类owner | `任务类数据服务`公开非const成员，类内定义 | 构造器之后、查询入口之前 | 允许后继新ARCH-L4消费者；禁止旧L2、DATA-L1/L2反向调用 | 当前没有符合新白名单和新owner隔离的入口 |
| `查询任务记录` | 本任务类记录完整当前读回 / 本任务类owner | 公开const成员，类内定义 | 新增之后、精确查询之前 | 同上 | 旧任务服务身份与结构被禁止复用 |

| `读取任务目标方向` | 组合本记录来源需求与需求类临时方向 / 本任务类owner | 公开const成员，类内定义 | 三个记录入口之后、private之前 | 允许后继新ARCH-L4消费者；禁止用作目标达成/状态/执行/结算裁决 | 当前需求类已有唯一目标方向计算，任务类只需窄组合而非复制实现 |

四个公开函数的诊断责任均为`向上送出`。类私有辅助保持最小可见性，只服务同文件的
请求校验、状态映射、写集形成、首次材料重放、L1核心读回和发布后收口，不构成第二公开
能力。任务类不持有自身锁，不接收或返回可变引用；每次外部服务调用结束后才进入下一步，
不跨调用持有L1内部锁，也不建立跨owner事务。

复用裁决为：组合当前L1 owner-scoped公开CRUD与需求类两个公开入口；不重复实现需求目标
读取和二次特征计算。旧任务模块虽然存在，但其`L2*`身份、DTO、owner和完整治理职责与
用户白名单冲突，只作迁移事实，不能直接复用、适配或包装。当前不存在其它新任务类模块，
因此建立一个新的唯一记录owner和真实模块。

## 4. 公开 DTO 与稳定状态

```cpp

enum class 任务类数据状态 : std::uint8_t {
    已创建=1,
    精确重复=2,
    已读取=3,
    已读取目标方向=4,
    入口拒绝=5,
    未找到=6,
    所属存在未找到=7,
    所属存在已退出=8,
    来源需求未找到=9,
    来源需求不属于存在=10,
    来源需求不可用=11,
    精确记录已存在=12,
    数量预算不足=13,
    事实代次漂移=14,
    幂等冲突=15,
    引用冲突=16,

struct 任务类记录身份 final {
    稳定编码 值{};
};

    稳定编码 所属存在关系{};
    稳定编码 来源需求关系{};

    std::uint32_t 合同版本 = 任务类数据合同版本;

```

全部DTO提供默认相等比较。`任务类记录结果::成功()`只接受已创建、精确重复、已读取，
并要求版本、非零代次、来源需求状态为`已读取`及完整记录；
`任务类目标方向读取结果::成功()`只接受`已读取目标方向`，并要求版本、非零代次、
来源需求状态为`已计算`、全部回显身份有效、比较成功且比较代次等于结果代次。

`来源需求状态`是下游公开结果的结构化诊断回显，不是任务业务状态、任务完成性或第二
需求状态权威。非成功结果不携带任务记录或比较业务载荷；`精确记录已存在`也只返回
状态和事实代次，不借非成功分支暴露既有记录。

## 5. 公开函数合同

```cpp
class 任务类数据服务 final {
public:
    任务类记录结果 新增任务记录(const 任务类新增请求& 请求);
    任务类记录结果 查询任务记录(const 任务类身份查询请求& 请求) const;
    任务类记录结果 按所属存在和来源需求精确查询(
        const 任务类精确查询请求& 请求) const;
    任务类目标方向读取结果 读取任务目标方向(
        const 任务类目标方向读取请求& 请求) const;
};
```

四个入口只返回结构化结果，不写日志。构造器配置错误向装配边界抛
`std::invalid_argument`。

### 5.1 来源需求互证与统一映射

所有新增、身份查询和精确查询的返回链都必须在请求G0恰一次调用
`需求类数据服务::查询需求记录`；新增通过其调用的精确查询完成这次互证。只接受成功、`已读取`、合同版本正确、事实代次等于
G0、完整需求记录，且需求记录的`所属存在`等于任务请求或任务记录的所属存在。

需求查询状态映射固定为：

| 需求类状态 | 任务类状态 |
| --- | --- |
| `未找到` | `来源需求未找到` |
| `所属存在未找到` | `所属存在未找到` |
| `所属存在已退出` | `所属存在已退出` |
| `事实代次漂移` | `事实代次漂移` |
| `资源失败` | `资源失败` |
| 其它非成功 | `来源需求不可用` |

查询成功但所属存在不等返回`来源需求不属于存在`。全部分支原样回显
`来源需求状态`；任务类不得把需求的目标端点非成功解释成任务业务失败或等待。

### 5.2 新增任务记录

入口要求合同版本、G0、幂等身份、所属存在和来源需求均有效。固定流程：

1. 读取L1当前代次，必须等于请求G0。
2. 先以写端口首次写入材料处理幂等：同键同规范化请求读回原记录并返回精确重复；
   同键异义返回幂等冲突。
3. 调用按所属存在和来源需求精确查询；该入口按5.1节互证来源需求和所属存在。已有
   唯一记录时，本入口返回`精确记录已存在`和既有事实代次但清空记录；多个记录返回
   内部不一致，未找到才继续创建。
4. 一份本owner写集原子创建一个普通记录节点和两条角色为0的关系。固定本地键：
   记录节点`1`、所属存在关系`2`、来源需求关系`3`。不建立属性、目标副本、Vt、状态、
   轮次、树、列表或索引节点。
5. 恰一次提交。成功或精确重复后按新编码映射和Gend调用身份查询完整读回；三项事实
   必须由本owner同代创建并逐字段吻合。已确认发布但无法闭合返回`已可能发布`和发布
   代次，只允许原幂等身份与原请求重放。

任何写前失败零变化；跨owner端点只引用，不修改、不退出。

### 5.3 按身份查询

私有`读取任务记录核心`只在请求G0用L1 owner一致当前读取记录节点和两类源关系，不调用
任何领域服务；前后当前代次均必须等于G0。
记录节点必须是本owner当前普通节点、无属性、恰有两条当前关系；关系类型、源端、
目标端、owner和生命周期必须完整且互异。

公开身份查询先调用该核心读取，再按5.1节恰一次通过需求类公开查询互证来源需求及所属
存在。混代返回事实代次漂移；完整
自有形状矛盾返回内部不一致；身份不属于本结构返回未找到。不得经存在类再次解释所属
存在，也不得读取或复制需求目标字段到任务记录。

### 5.4 精确查询

请求最大候选数量必须非零。先冻结G0并按5.1节互证来源需求与所属存在，再分别调用L1
owner当前目标关系组读取两个端点与对应关系类型。两组读取代次必须都等于G0，关系
owner、类型、目标和生命周期完整；任一组数量超过预算返回数量预算不足。

对两组源记录身份取交集：零项返回未找到；一项调用私有`读取任务记录核心`并逐字段
精确相等后返回，不再重复查询已经在本入口互证的同一来源需求；多项返回内部不一致。
不得按编码顺序选择，不缓存索引，不返回部分候选。

### 5.5 读取任务目标方向

本入口零L1写、零任务记录修改、零目标或方向持久化：

1. 校验版本、G0、非零请求身份、任务身份、当前事实特征和结果位1..7。
2. 按身份读取任务记录，取得且只取得其所属存在和来源需求。
3. 构造一次`需求类方向计算请求`：需求取任务记录的来源需求，其余G0、请求身份、当前
   事实特征和结果位原样来自调用请求。
4. 恰一次调用`需求类数据服务::计算临时需求方向`。成功必须为`已计算`、合同版本正确、
   事实代次等于G0、需求身份和当前特征回显吻合、目标宿主/静态目标特征/方向定义有效、
   比较成功且比较代次等于G0；任务类只将这些字段复制到调用期结果DTO，不保存为任务
   事实。
5. 方向调用的`事实代次漂移`和`资源失败`原类映射，`未找到`映射来源需求未找到，
   其它非成功映射来源需求不可用并原样回显来源需求状态。任一非成功清空目标与比较
   载荷。
6. 读后L1当前代次仍须等于G0，否则清空目标与比较并返回事实代次漂移。

结果只表示“此任务类记录引用的需求在本次G0返回了一个临时方向比较”。它不判断任务
成立、目标达成、状态、适用方法、下一动作、完成、失败或结算。

## 6. 不变量、失败与生命周期

- 同一精确“所属存在 + 来源需求”最多一个当前新记录。
- 一条记录恰为一个普通节点加两条自有关系；无属性、无可变字段。
- 记录身份、所属存在和来源需求引用不可原地修改。本叶不提供修改、删除、退出、恢复
  或历史查询入口。
- 写前失败零变化；发布未知不撤销，只允许原幂等身份和原请求收敛。
- L1许可拒绝不得由现行路径产生，若出现按内部不一致处理；引用冲突、幂等冲突、代次
