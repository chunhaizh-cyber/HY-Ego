# 任务类数据操作详细设计

日期：2026-09-05

版本：v0.2

身份：`ARCH-L4-TASK-CLASS-DATA-OPERATIONS`

状态：设计已冻结，待任务虚拟存在专用提供者完成后激活

## 1. 目标与边界

新建`海中鱼巣/领域/数据服务.任务类.ixx`，形成ARCH-L4新owner的七个薄数据操作：新增
不可变“所属存在 + 来源需求”记录、按身份查询、按二元组精确查询、经需求类读取目标方向、
初始化唯一任务虚拟存在Vt、添加方法节点引用、读取方法节点组。

本叶不是3200/5260的完整正式任务治理。它不建立查询锚点、正式T→D关系组、Vt首态、R1、
任务/筹办/执行轮次、路径、方法业务版本、采用、冻结、执行、验证、结算或调度。Vt初始化
只指task owner内一个普通Vt节点与一条T→Vt关系原子发布；方法引用只证明输入编码在G0
是当前普通节点，不证明方法资格。新旧两套迁移期并行，本模块零调用、零适配、零迁移、零
退出旧`服务.L2*`；最终替代旧逻辑不属于本计划完成条件。

## 2. 架构、模块与端口裁决

Vt属于ARCH-L4，不是世界存在。任务类不得调用普通`新增存在/查询存在`，不得使用存在类
世界owner，也不得把Vt加入存在族、子存在组或世界树。

`L1所有者范围写端口`不可复制且不得跨服务借用，故不把task端口交给存在类。上游
`EXISTENCE-CLASS-TASK-VIRTUAL-EXISTENCE-PROVIDER`只形成固定、无权限的task owner写集
规格并提供专用读回；任务类持有唯一task owner端口并恰一次提交。

```text
文件：海中鱼巣/领域/数据服务.任务类.ixx
模块：海中鱼巣.领域.数据服务.任务类
工程：海中鱼巣.vcxproj，以ClCompile登记
filters：海中鱼巣.vcxproj.filters，置于现有领域模块分组
```

模块只需`export import 海中鱼巣.领域.数据服务.需求类;`；需求类已公开传递存在类模块，
因此可使用存在类专用Vt DTO与服务，不建立旧L2依赖。

## 3. owner、结构类型与白名单

```cpp
struct 任务类结构类型 final {
    稳定编码 所属存在关系类型{};
    稳定编码 来源需求关系类型{};
    稳定编码 任务虚拟存在关系类型{};
    稳定编码 任务方法关系类型{};
    bool operator==(const 任务类结构类型&) const = default;
};

任务类数据服务(const L1事实基座服务& 第一层服务,
    const 需求类数据服务& 需求服务,
    const 存在类数据服务& 存在服务,
    L1所有者范围写端口&& 写入端口,
    任务类结构类型 结构类型);
```

四类型必须非零、两两互异、当前、未退出、为task owner持有的无属性普通节点；owner必须
是当前独占结构范围。构造失败抛`std::invalid_argument`，不创建类型、不领取第二端口。

直接调用白名单：L1的`读取中性当前事实代次`、`读取当前结构所有者`、
`读取所有者范围当前节点`、`读取所有者范围当前目标关系组`、
`读取所有者范围当前源关系组`、`尝试读取所有者范围一致当前投影`；写端口的
`读取首次写入材料`、`提交所有者范围中性写集`；需求类的`查询需求记录`、
`计算临时需求方向`；存在类的`形成任务虚拟存在写集规格`、`查询任务虚拟存在`。

特征类和二次特征类只由需求类合法转调。禁止L1中性v1写入口、私有仓库、SQL、raw owner
选择、缓存、跨调用持锁、普通存在入口、白名单外函数和全部旧`服务.L2*`。

`已读取目标方向`；Vt结果成功接受`已初始化虚拟存在/精确重复/虚拟存在已初始化`；方法

成功必须版本、代次和载荷完整；非成功不携带部分业务载荷。

## 5. 七个公开入口

```cpp
任务类记录结果 新增任务记录(const 任务类新增请求&);
任务类记录结果 查询任务记录(const 任务类身份查询请求&) const;
任务类记录结果 按所属存在和来源需求精确查询(const 任务类精确查询请求&) const;
任务类目标方向读取结果 读取任务目标方向(const 任务类目标方向读取请求&) const;
任务类虚拟存在结果 初始化任务虚拟存在(const 任务类虚拟存在初始化请求&);
```

七入口均返回结构化结果、不写日志，诊断向上送出。私有辅助只服务请求校验、首次材料
重放、状态映射、同G0读回与发布收口，不形成第二公开能力。

## 6. 基础记录、查询与方向

基础新增固定本地键任务`1`、所属存在关系`2`、来源需求关系`3`，由task owner同一写集
原子创建一个无属性普通节点和两条角色0关系。来源需求通过`查询需求记录`在G0互证所属
存在；同一“所属存在 + 来源需求”最多一个当前记录。首次材料同键同请求精确重放、同键
异义幂等冲突；发布已确认但读回未闭合返回`已可能发布`，只允许原键原请求重放。

按身份读取证明基础节点和两关系完整，再读取零或一T→Vt关系及零到多T→方法关系。Vt
多于一条为内部不一致；方法关系超过预算返回`方法节点数量预算不足`，目标逐一是G0当前
普通节点，去重并按稳定编码升序返回；重复目标关系或形状矛盾为内部不一致。后续关系可
有不同创建代次，不要求与基础记录同代。精确查询对所属存在和来源需求两组目标关系取源
任务交集，零/一/多分别返回未找到/完整记录/内部不一致。

方向读取先读任务，再把来源需求、G0、请求身份、当前事实特征和结果位原样交给需求类
`计算临时需求方向`。成功只值式回显目标与比较，零持久化、零任务业务判断。

## 7. 初始化任务虚拟存在

基础任务新增与Vt初始化是两个独立生命周期阶段，使用不同幂等键且不共用写集。流程：

1. 校验请求并在G0读回基础任务；读取task端口首次材料。同键异义返回幂等冲突，同键
   同请求用原材料收敛。
2. 调用提供者专用查询。已有唯一合法Vt时，首次材料重放返回精确重复，否则返回
   `虚拟存在已初始化`；结构错误映射内部不一致。
3. 未初始化时调用规格形成；必须返回版本1、`已形成写集`、G0、相同owner/幂等身份及
   固定一节点一关系写集，否则映射`提供者不兼容/虚拟存在规格失败`。
4. 任务类以自己私有端口恰一次提交原规格；成功或精确重复后，以Gend调用专用查询完整
   读回。已确认发布但无法闭合返回`已可能发布`，不撤销、不换键，只允许原请求重放。

Vt节点和关系必须由task owner同写集创建、同创建代次、无属性、当前、角色0。Vt不进入
世界存在族/世界树；本入口不建立Vt首态，不得声称5260正式任务核心完成。

## 8. 方法节点操作

添加入口先读任务，再用L1证明方法编码非零、在G0当前、未退出且为普通节点；方法可属于
另一owner。不得根据节点名、属性、类型或来源证明方法业务资格、版本、条件或效果。

已有相同目标时，首次材料同键同请求返回精确重复，不同键返回`方法节点已存在`。否则
task owner以只含一条角色0关系的写集发布T→方法：本地键`1`，源任务和目标方法均为稳定
编码引用，类型为任务方法关系类型。提交后按Gend精确读回；发布未知只用原键原请求收敛。

读取方法组要求非零预算，读取当前源关系组并逐一证明目标是G0当前普通节点；超预算返回
`方法节点数量预算不足`，重复目标或形状错误返回内部不一致。成功返回稳定编码升序、无
重复值式数组，空数组合法，不解释方法业务语义。

## 9. 失败、不变量和实施边界

- 需求类未找到、所属存在未找到/已退出、代次漂移、资源失败分别映射对应任务状态；其余
  非成功映射来源需求不可用，所属存在不等映射来源需求不属于存在。
- 提供者不兼容、结构矛盾和普通失败分别结构化映射，并原样回显提供者状态。
- 方法节点未找到、已退出、非普通分别映射`方法节点未找到/已退出/不是普通节点`。
- 写前失败零变化；写入口恰一次提交，不跨owner写、不补偿、不覆盖、不退出。
- 基础任务身份、所属存在和来源需求不可原地修改；一任务至多一个当前Vt，方法组为零到
  多个唯一稳定引用；Vt与方法均不复制需求目标。
