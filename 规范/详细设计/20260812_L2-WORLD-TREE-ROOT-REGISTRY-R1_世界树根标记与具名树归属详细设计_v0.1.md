# L2-WORLD-TREE-ROOT-REGISTRY-R1 世界树根标记与具名树归属详细设计 v0.1

日期：2026-08-12

状态：设计完成，等待前置结果后实施

## 1. 目标与裁决摘要

本设计在唯一 `L2场景结构服务` 和场景独占 owner 内补齐具名树身份、根标记、非根显式树归属和同树父子约束。它解决“场景 CRUD 已存在，但树根只可能停留在参数、缓存或上层解释中”的结构缺口，不恢复旧世界登记服务，也不裁决哪棵树是现实世界。

最终结构为：

```text
场景 owner
├─ 场景族锚点 / 场景族归属关系类型（S-ID）
├─ 场景树登记锚点（R1 私有元数据）
├─ 根标记关系类型（R1 私有元数据）
├─ 树归属关系类型（R1 私有元数据）
├─ 根场景 --根标记--> 场景树登记锚点
└─ 非根场景 --树归属--> 根场景
               同时由同树父场景 --父子--> 非根场景
```

`L2场景树身份` 的值等于根场景稳定编码。它不是独立节点族、第二节点、别名仓或新 owner。一个物理场景底座允许多棵具名树；每棵树恰一当前根，每个当前树内场景恰属一树。根没有父，非根恰有一个同树当前父，整树连通且无环。

## 3. 所有权、依赖与生命周期

### 3.1 唯一 owner

R1 不建立树 owner。树登记锚点、两种关系类型、根场景、非根场景、场景族归属、根标记、树归属和父子关系全部由 S-ID 最终同一个场景 owner 与同一 `L1所有者范围写端口` 写入。关系端点及关系类型都必须通过 owner-aware 同截止读取互证为该 owner。

树登记锚点和两种关系类型是场景服务私有不可变元数据，不取得 `L2场景身份` 或 `L2场景树身份`。它们在服务构造阶段继 S-ID 三组登记之后初始化，生命周期覆盖全部具名树、普通场景、幂等结果及历史 / 恢复引用；R1 不提供其退出入口。

### 3.2 直接依赖

R1 的直接机器依赖只有：

```text
S-ID 最终 L2场景结构服务
+ L1 owner-scoped CRUD / owner-aware 当前历史读取
+ E-ID 最终存在来源（只由既有场景成员读取继续消费）
```

DYN2、因果 C1 / C2 只构成用户路线、唯一代码段和普通应用 provider 前缀门禁，不是 R1 的 import、函数或业务数据依赖。A1 是后继透明聚合，不是 provider。自我初始化是后继消费者，不允许被 R1 反向 import。

### 3.3 生命周期选择

R1 不实现整树退出。因此根标记和根场景在普通入口永久不可退出，`退出场景` 对根固定返回 `引用冲突`。非根场景只有在其当前直接子关系为空时才能显式退出；同事务关闭树归属、当前直接父关系、场景族归属、节点、成员、属性和值。树登记锚点和两种关系类型不随任何单树或节点退出。

未来若需要整树退出，必须另立具名计划，冻结全树快照、外部引用闭包、原子性或可恢复分批协议。R1 不以递归级联、部分退出或后台清理预实现该语义。

树结构登记在一笔 owner-scoped 写集中建立一个不可变树登记锚点和两个 L1 正式关系类型身份节点，三者编码互异、同场景 owner、无场景族归属。当前 L1 `节点种类` 只有 `普通 / 属性类型`，所以锚点与关系类型身份节点的物理种类均固定为 `节点种类::普通` 且无属性类型表示；“物理普通”不允许把两个类型身份解释为公开普通场景。首次成功和精确重复均 owner-aware 读回其正式登记角色与完整生命周期；定位丢失不扫描、不猜测、不按普通节点形状补登记。

## 6. 原子写集与幂等

### 6.1 建立根

`建立场景树根` 的一笔写集精确为：

```text
节点：根场景节点
关系：根场景 -> 场景族锚点，场景族归属类型，角色 1
关系：根场景 -> 场景树登记锚点，根标记类型，角色 1
值 / 属性槽 / 退出：空
```

树身份由写后根场景编码形成。写前不得要求调用方提供或猜测该编码。写后必须从同一变更截止独立读回根场景来源、根标记、无树归属、无父关系和唯一树身份；缺项、重复、错 owner、错类型或出现父关系均为内部不一致。

### 6.2 新增非根

`新增树内场景` 先在请求期望代次读取目标树和直接父的树归属，要求树当前有效、父属于同一树且不是内部元数据。其一笔写集精确为：

```text
节点：新场景节点
关系：新场景 -> 场景族锚点，场景族归属类型，角色 1
关系：新场景 -> 根场景，树归属类型，角色 1
关系：直接父场景 -> 新场景，父子类型，请求顺序
值 / 属性槽 / 退出：空
```

提交仍使用原期望代次，因此前置读取后任何并发发布由 L1 裁决漂移。写后独立读回四项同 owner、节点 / 场景族归属同创建代次、树归属与父子同创建代次、父子两端同树且新节点恰一父。

两个业务创建入口直接以 `L2结构幂等身份.值` 形成场景 owner 范围写入幂等身份，共享 S-ID 场景 CRUD 的同一个 owner 全局幂等身份域，不添加操作类型高位、哈希前缀或第二幂等账。固定登记身份是该全局域中的保留值；任一业务创建请求命中它固定入口拒绝。同一个非保留值无论被根建立、树内场景新增还是其它场景完整请求复用，只要完整请求逐字段不同就返回幂等冲突；同值同完整请求才返回首次完整结果。发布结果未知只允许原身份原请求收敛。

## 7. 读取、同树约束与退出

### 7.1 树归属读取

当前读取在一份 owner-aware 一致当前投影内读取：请求场景、场景来源、树登记、以场景为源的根标记 / 树归属关系及其目标。成功只允许以下二选一：

- 唯一根标记、零树归属、关系目标等于登记锚点、树身份等于场景编码；
- 零根标记、唯一树归属、目标是当前正式场景根，且目标拥有唯一根标记。

两类都要求精确 owner、类型、角色 1、端点和生命周期。零关系对 S-ID 之后的新场景属于内部不一致；对激活基线以前的旧裸场景返回入口拒绝，普通读取和退出都不接管。重复、双类并存、链式归属、目标非根、错 owner / 类型 / 角色或混代均为内部不一致。

历史读取以显式截止重建相同证据，隐藏晚于截止的未来退出，不能从当前定位补历史项。创建前未找到；截止早于退出可返回当时有效投影并隐藏未来退出，截止达到或晚于退出返回已退出空载荷；当前入口也固定已退出空载荷。

### 7.2 整树读取

`读取场景树` 先以 `树.值` 作为根场景编码证明根标记，再按树归属类型和根目标读取全部非根成员。对根和每个成员读取场景身份来源、完整场景及父子关系，要求：

1. 根零父关系；
2. 每个非根恰一当前父，父也在同一成员集合；
3. 父子关系的全部当前端点均属于本树；
4. 从根沿父子边可达全部成员，且无环、无重复节点；
5. 场景成员关系与存在身份不增删或改变树成员集合；
6. 所有投影共享一个非零截止并按冻结顺序返回。

当前和历史均使用正式关系索引条件，不进行恢复扫描或无父猜根。任一缺项或额外跨树父子返回内部不一致，不返回部分树。

### 7.3 既有 CRUD 和退出

现有固定属性、成员关系、完整读取和父子替换在写前调用 `读取场景树归属`。父子替换要求旧父、新父、子三者同树且子不是根。成员关系和存在来源仍只表达成员结构，既不能替代树归属，也不要求存在与树绑定。

`退出场景` 分两路：

- 已登记根：固定引用冲突，R1 无整树退出；
- 已登记非根：权威快照必须无当前直接子关系，且请求完整列出树归属、直接父、场景族归属、成员、属性和值；同事务全部退出；
- 激活前旧裸场景：全部公开场景入口固定拒绝，不自动补登记、不沿用普通退出；读取或清退只能由独立 legacy 退役合同承接；
- S-ID / R1 激活后形成的无树归属新场景：内部不一致，不得降级为 legacy。

退出后当前读取已退出，历史截止仍可读取节点、场景族来源、树归属和直接父的完整生命周期。外部引用未闭合由 L1 返回引用冲突，不级联修改存在或其它族事实。

## 8. 恢复、迁移与失败分账

全新空域由场景服务先建立私有登记，首个合法根请求再创建第一棵树；不需要预设唯一根。已有同一 owner、同一固定幂等身份和同一完整登记写集时精确重复读回。非空但缺少合法固定登记、根标记或树归属时，普通 CRUD 不扫描、猜测、adopt 或补写。

R1 不提供持久恢复入口、跨进程重建、旧场景读取 / 清退或保码迁移。旧裸场景全部公开入口拒绝；若未来必须保码认领、读取或清退，需另立具名 legacy 合同，提供可审计原 owner、创建基线、目标树和并发隔离，不得原位扩张 R1。

失败状态沿共同合同：纯值非法、根作子端、跨树父子、旧裸场景写入为入口拒绝；未找到、已退出、事实代次漂移、幂等冲突、引用冲突、许可拒绝、资源失败按同名返回；登记 / owner / 类型 / 端点 / 数量 / 生命周期矛盾为内部不一致。提交前失败零变化。提交后读回失败不得宣称零变化，只能返回安全取得的首次代次并使用原幂等请求收敛。

## 9. A1、自我初始化和实施顺序

A1 仍只持有六服务非 owning 引用并透明返回同一个场景服务实例。R1 不修改 A1 的六服务数量、provider 顺序、owner 或写入边界；A1 后继 S0 只需按 R1 最终场景服务 ABI 重验 getter 调用。

当前 7130 把世界根写成旧基础信息身份，与 0050 / 4200 / 4230 冲突。自我初始化适配必须在 R1 实现结果后另立规范 / 设计计划：调用方明确提交 `L2场景树身份`，初始化只经正式 `读取场景树` 消费根场景，不创建、扫描、缓存猜测或用 A1 建根。

用户路线顺序冻结为：

```text
DYN2 -> 因果 C1 -> 因果 C2 -> S-ID -> R1 -> A1
     -> 各叶临时验证源码清理 -> A1 独立集成验收
```

R1 设计可以先发布，但状态保持 `待激活`。只有前序真实结果、接受、索引退出和共享资源释放后，执行者才能从新 HEAD 重新 S0。

## 10. 生产外验证与完成边界

专项验证至少覆盖：两个以上树身份互异且各恰一根；根三项和非根四项原子写；当前 / 历史归属与整树读回；同树新增 / 移动；跨树父子、根作子端、无父猜根、重复归属和旧裸场景全部公开入口拒绝；成员关系不改变树归属；幂等、旧代次、并发和发布后读回；非根叶退出、非叶退出拒绝、根退出拒绝及历史生命周期。

R1 删除裸创建与父关系单独新增 / 退出 ABI 时，同步删除三套只验证旧 ABI 的已跟踪专项资产：`L2场景节点参数验证`、`L2场景关系类型登记参数验证`、`L2场景关系CRUD与完整读取参数验证` 各自的 `.cpp / .vcxproj / 运行脚本`。这九个文件是旧叶完成后遗漏的临时验证源码，当前无 dirty、无根工程登记且无具名活动所有者；其消费 ABI 被物理删除后必须在同一实施提交退役，不能留下失效额外源码。永久历史施工 / 验证记录保留，删除专项源码不删除历史证据，也不证明 R1 能力；R1 新专项必须覆盖新 ABI。

验证驱动只能通过正式 L2 入口输入参数，不取得私有 owner 端口、仓库或测试友元。私有损坏注入、真实分配失败、恢复、跨进程、长期公平、生产业务和独立集成验收未运行时必须记为 `NOT_RUN`。

R1 完成最多证明场景 owner 内的多树、单根、显式归属和同树父子结构实现并通过规定生产外矩阵。不证明现实世界资格、自我初始化、A1、启动消费者、生产业务、持久恢复、整树退出或独立集成验收。
