当前状态：BIZ 详细设计候选；未登记计划索引，未实施本次收紧，未构建，未接入治理批次。

## 1. 目标与边界

收紧 `BIZ-L3-002-01-01` 的现有 `有界自我治理邮箱::等待并冻结下一批`：保留锁内条件等待、停止唤醒、整批冻结和提交时已经形成的稳定顺序，补齐负等待拒绝、非零严格后继批次序号、资源失败 / 其它异常分账，以及失败时队列和计数零变化。

本叶只处理运行期非权威消息承载，不读取或写入 DATA、需求、任务、方法、状态、动态、因果、安全值或服务值。消息准入、消息提交、L2 治理批次组合、普通应用装配和自我线程循环均为 `NOT_RUN`。

## 2. 当前事实与漂移

正式基线 `c58d108cac3c779f081410bb353bba7a3c0ff023` 中，唯一模块 `海中鱼巣.线程.有界自我治理队列` 已提供条件变量等待、停止或非空谓词、稳定顺序整批取出和批次计数；没有生产调用点。

现有实现不能直接复用为目标合同：

1. 负 `milliseconds` 未校验，结果取决于队列是否已有消息，且冻结状态没有请求拒绝；
2. `++已冻结批次数量_` 在 `UINT64_MAX` 后回绕为 0；
3. 计数先递增，再 `reserve`并逐项移动；分配失败会消耗序号，移动异常可能留下半移动队列；
4. 函数不是 `noexcept`，没有结构化资源失败。

父级事后检查不能修复已经移动的消息或已经推进的计数，因此必须先修本叶。

## 3. ABI 修订

保持既有枚举值和字段顺序，只在尾部追加状态与拒绝原因：

```cpp
enum class 自我治理冻结状态 : std::uint32_t {
    已冻结 = 1,
    等待超时 = 2,
    已停止 = 3,
    内部不一致 = 4,
    请求拒绝 = 5,
    资源失败 = 6
};

enum class 自我治理队列拒绝原因 : std::uint32_t {
    无 = 0,
    容量为零 = 1,
    协议拒绝 = 2,
    协议内部不一致 = 3,
    重复材料 = 4,
    队列已满 = 5,
    队列已停止 = 6,
    等待超时 = 7,
    空批次 = 8,
    等待参数无效 = 9,
    资源失败 = 10,
    批次序号耗尽 = 11,
    内部异常 = 12
};

自我治理冻结结果 等待并冻结下一批(
    std::chrono::milliseconds 最大等待时间) noexcept;
```

`自我治理冻结结果`和`自我治理冻结批次`字段不变。只有 `已冻结`允许 `批次序号()>0`且`数量()>0`；其它状态必须返回默认零序号、空消息组。0 毫秒是合法非阻塞观察，负值固定请求拒绝。

## 4. 固定控制流与强守恒

1. 锁外先检查负等待，返回请求拒绝、等待参数无效和空批次；
2. 在最外层 `try` 内取得唯一队列锁并用现有谓词等待；
3. 超时、停止空队列和伪唤醒保持现有具名结果；
4. 非空时先证明 `已冻结批次数量_ < UINT64_MAX`，否则返回内部不一致、批次序号耗尽，队列和计数不变；
5. 在锁内把当前 `deque` 按现有顺序**复制**到局部 `vector`候选；不得移动原消息、重新排序或逐项清除；
6. 候选完整后，以默认 allocator 的 `vector::swap`把局部候选无抛出交给结果批次，再以无抛出操作清空原队列并把计数赋为已检查的后继值；
7. 解锁后返回调用方拥有的完整结果。

`std::bad_alloc`映射资源失败 / 资源失败原因和空批次；`std::system_error`及其它异常映射内部不一致 / 内部异常原因和空批次。伪唤醒继续使用内部不一致 / 空批次，序号耗尽使用内部不一致 / 批次序号耗尽。所有 catch 发生时，候选尚未提交，原队列、停止态、已见幂等索引、同任务顺序索引和已冻结批次数量必须不变。新增 `<limits>`和`<new>`只服务受检上界与异常分类；实现须静态确认消息可复制、消息析构不抛出且默认 allocator 的 vector swap 不抛出，否则退回计划支撑，不得把可能抛出的操作放入提交段。

## 5. 并发、停止与生命周期

- 等待、候选复制和最后提交始终持有同一队列锁；生产者不能把迟到消息混入当前候选。
- 提交入口已经按正式优先级稳定插入；冻结不得二次排序。
- 停止且仍有待处理消息时先冻结完整剩余批次；下一次空队列读取返回已停止。
- 超时、请求拒绝、资源失败和内部不一致均不推进计数、不移除消息。
- 返回批次为独立值；不暴露队列引用、锁或条件变量。
