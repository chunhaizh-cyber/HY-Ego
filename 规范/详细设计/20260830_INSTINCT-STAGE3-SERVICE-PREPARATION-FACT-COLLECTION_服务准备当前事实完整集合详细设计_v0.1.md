# INSTINCT-STAGE3-SERVICE-PREPARATION-FACT-COLLECTION 服务准备当前事实完整集合详细设计 v0.1

日期：2026-08-30

设计身份：`INSTINCT-STAGE3-SERVICE-PREPARATION-FACT-COLLECTION`

## 1. 目标与完成边界

本设计扩展现有唯一 `服务合同事实权威服务`，在指定非零事实截止 `G0` 下返回同一自我的完整当前服务准备事实组，并以独立结构登记、规范成员身份组和读前 / 读后守卫证明合法空集合。

本叶只形成服务准备的中性权威承载和完整集合读取。它不裁决准备是否合法、是否形成有效服务活动、是否完成、是否可补回衰减，也不建立生产准备发布入口。后继业务组合器必须逐项独立读回任务、方法、执行冻结、安全门禁、状态、动态、结果和验证引用，再依据 6160 / 6170 裁决。

当前生产阈值定义版本保持不变：值域 `0..I64_MAX`，`L=2,767,011,611,056,432,742`，`H=7,378,697,629,483,820,645`。阈值可随未来正式定义版本调整，但本计划不得修改当前版本。

## 2. 正式依据与当前事实

正式依据：0050 v2.1、6100 v0.5、6120 v0.10、6160 v0.4、6170 v0.6，以及 `计划/数据服务最终需求清单.md` 的 DATA-EXT-16 边界。

当前正式代码基线为 `main == origin/main == 7a187802c89edb1ec2d22c73900b5d9a527ac0aa`。已经具备：

1. 唯一服务合同 owner；
2. 当前有效未满足合同、到期未满足事件和合同关联进展的同 `G0` 完整集合读取；
3. 合同基础登记 `0x0307'3001..3013` 和进展扩展登记 `0x0307'3014..301F`；
4. L1 owner 范围一致关系类型闭包、幂等登记和持久恢复。

当前缺少服务准备强类型身份、生命周期、完整当前成员索引和完整集合见证。现行任务 / 方法 / 安全代码也没有已发布的统一有效活动见证；未提交 SELF-GOVERNANCE WIP 不作为本设计依据。

因此下一最早提供者不是有效活动组合器，而是同一 owner 内的服务准备完整集合。

## 4. 数据合同

### 4.1 身份、来源和状态

```cpp
inline constexpr std::uint32_t 服务准备事实扩展合同版本_v1 = 1;
inline constexpr std::uint32_t 服务准备事实结构登记版本_v1 = 1;

struct 服务准备事实身份_v1 { 稳定编码 值; };
struct 服务能力缺口身份_v1 { 稳定编码 值; };
struct 服务准备目标身份_v1 { 稳定编码 值; };
struct 服务准备结果身份_v1 { 稳定编码 值; };
struct 服务准备验证事实身份_v1 { 稳定编码 值; };

using 服务准备来源身份_v1 =
    std::variant<L2需求身份, 服务能力缺口身份_v1>;

enum class 服务准备运行状态_v1 : std::uint8_t {
    进行中 = 1,
```

来源只能是一个具体服务需求或一个服务能力缺口，不能两者同时存在，也不能使用名称、日志、队列位置或任务类别代替。

完整性要求：

1. 全部必填身份、版本和运行代次非零；
2. 服务需求来源必须携带非零 `T→D` 关系编码，能力缺口来源不得伪造 `T→D`；
3. `0 <= 有效开始 <= 进展发生 <= 计量窗口结束 <= 有效结束`，且 `计量窗口开始 <= 进展发生`；
4. `进行中` 至少携带状态或动态一项；
5. `已完整完成` 必须同时携带准备结果和完成验证；其他状态不得据此自动成立完成；
6. 形成事实代次和生命周期在 `G0` 生效；
7. provider 保留全部九种状态，不在 DATA 层过滤有效活动。

### 4.3 请求、见证和结果

```cpp
struct 服务准备完整集合读取请求_v1 {
    std::uint32_t 合同版本;
    L2结构请求头 请求头;
    L2存在身份 自我;
};

struct 服务准备完整集合见证_v1 {
    std::uint32_t 结构登记版本;
    std::uint64_t 声明成员数;
    std::vector<服务准备事实身份_v1> 规范成员身份组;
    std::uint64_t G0;
};

struct 服务准备完整集合读取结果_v1 {
    std::uint32_t 合同版本;
    服务合同事实权威读取状态_v1 状态;
    std::vector<服务准备当前事实_v1> 完整准备事实组;
    std::optional<服务准备完整集合见证_v1> 完整集合见证;
    std::uint64_t 本次正式读回截止;

```

成功只允许 `状态=已读取`、截止等于 `G0`、见证完整、事实组与规范身份组逐项相同并按身份严格升序。0 项是合法成功。全部非成功必须为空组、空见证、截止 0。

## 6. 读取算法

公开入口：

```cpp
服务准备完整集合读取结果_v1
服务合同事实权威服务::读取当前服务准备完整集合_v1(
    const 服务准备完整集合读取请求_v1&) const noexcept;
```

固定流程：

```text
合同版本 / 自我 / G0 校验
-> G0 读前守卫
-> 同 owner 一致关系类型闭包读取全部当前准备成员及引用关系
-> 基础 / 进展 / 准备登记逐项互证
-> 按成员重建载荷
-> 互证来源二选一、任务、方法、状态、动态、结果和验证端点
-> 按准备身份规范排序
-> 形成完整集合见证
-> G0 读后守卫
-> 成功或结构化非成功
```

漏成员、额外成员、重复成员、混合 owner、来源双写 / 缺失、错端点或坏载荷整体返回 `集合不闭合`或`引用冲突`，不得跳过成员形成部分成功。

## 7. 验证矩阵

至少覆盖：

1. 既有基础 / 进展登记恢复后首次追加准备登记，以及三层登记恢复；
2. 0 / 1 / N 当前准备完整集合、规范排序和共同 `G0`；
3. 需求来源与能力缺口来源二选一，以及双写、全空和 `T→D` 形状错误；
4. 九种运行状态全部保留；进行中状态 only、动态 only、状态 + 动态；
5. 已完整完成必须绑定结果和验证，未完成状态不被 provider 解释为完成；
6. 自我 / 任务 / 方法 / 外部引用错绑、时间窗逆序、版本为零；
7. 漏 / 多 / 重成员、坏载荷、错关系端点、混合 `G0`；
8. 精确恢复、读中漂移、资源失败和全部非成功零载荷；
9. 仓库外 Debug / Release ABI consumer；生产构建无 fixture 和公开准备写入口；
10. v143 x64 Debug / Release 根工程 Rebuild、持久恢复、strict 和两类 diff-check。

## 8. 完成声明边界

本设计完成只证明服务准备当前事实完整集合 provider。它不证明生产准备发布已接线、任一准备合法或完成、准备补回成立、三类外部见证可独立读回、有效服务活动已裁决、阶段三或 `INSTINCT-ROUTE` 完成。
