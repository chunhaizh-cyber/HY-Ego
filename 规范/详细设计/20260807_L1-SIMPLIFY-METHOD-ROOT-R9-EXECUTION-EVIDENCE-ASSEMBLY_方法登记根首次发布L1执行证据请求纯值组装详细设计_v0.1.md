## 4. DTO、状态与根签名

```cpp
inline constexpr std::uint32_t 方法登记根首次发布执行请求合同版本 = 1;
inline constexpr std::uint32_t 方法登记根首次发布执行请求规则版本 = 1;

enum class 方法登记根首次发布执行请求状态 : std::uint8_t {
    已形成 = 1,
    预探测不允许 = 2,
    入口拒绝 = 3,
    事实截止漂移 = 4,
    版本漂移 = 5,
    资源失败 = 6,
    内部不一致 = 7
};

struct 方法登记根首次发布执行请求组装请求 final {
    std::uint32_t 合同版本 = 方法登记根首次发布执行请求合同版本;
    std::uint32_t 规则版本 = 方法登记根首次发布执行请求规则版本;
    方法登记根首次发布意图请求 公开请求;
    方法登记根首次发布意图结果 请求意图;
    方法登记根首次发布幂等键结果 幂等键;
    方法登记根首次L1草案结果 写集草案;
    L1幂等探测请求 预探测请求;
    L1幂等探测结果 预探测结果;
    方法登记根首次发布准入提供者证据结果 准入证据;
};

struct 方法登记根首次发布执行请求结果 final {
    方法登记根首次发布执行请求状态 状态 =
        方法登记根首次发布执行请求状态::入口拒绝;
    std::optional<L1写集请求> 写集请求;
};

class L1方法登记根首次发布执行请求数据操作 final {
public:
    方法登记根首次发布执行请求结果 形成方法登记根首次发布L1执行请求(

```

只有 `已形成` 携带完整写集请求；任一非成功的 `写集请求` 为空。输入均为调用方拥有的不可变值，
输出按值转移给后继，不保存引用。

## 5. 入口、预探测请求与结果互证

任何组装前逐项验证：

1. R9/R4/R5/R2/R8 合同和规则版本均为冻结值，全部成功结果携带必需载荷；
2. R4、R5 和公开请求中的幂等身份逐字段相等，R5 键高8位为 `0x19`，低56位回到公开身份；
3. R4 凭证为 G10、格式1、入口变体1、操作标签 `0x15001101U`，领域结果计划摘要全零；
4. 预探测请求为 L1合同2、摘要合同当前版本，最终键等于 R5，意图摘要和完整凭证等于 R4；
5. 预探测结果必须是 `未找到`，回显键等于请求键且首次结果为空；
6. `同义已发布/异义冲突/已隔离` 返回 `预探测不允许`；入口拒绝、内部不一致或坏状态返回
   `内部不一致`，不得形成半请求。

本函数只互证已取得的预探测材料，不执行或重放探测，也不能仅凭 `未找到` 结果证明调用时序。
后继发布者必须先调用 P15 探测，只有未找到才调用 R8 和 R9；同义、异义及隔离分支不得调用
provider 或 R9。

## 6. 截止、草案与准入证据互证

共同事实截止必须非零，并同时等于：

```text
公开请求.写集请求.预期事实代次
= R2结果.事实截止代次
= R2草案.事实截止代次
= R8结果.事实截止代次
= R8凭证.共同事实截止代次
= R8凭证.当前准入.事实截止代次
= R8凭证.最终完整快照.事实代次
```

任一不等返回 `事实截止漂移`。R2 草案必须精确满足3节点、0关系、1值、1槽、0退出、连续本地键
1—4和5项读回；R8 必须为 `已形成`，内部 R7 结果必须为 `可首次发布`、候选数0、候选为空。

R8 直接 provider 固定为 `0x4C314D5200000001`、合同/规则1/1、调用次数1、去重 provider 数1。
写前身份组、副本组和去重数量必须相等且大于0，按 `(对象种类,稳定身份)` 严格升序；每个副本
种类、编码和完整内容精确匹配同索引身份。任何缺项、重复、错种类、坏副本或空组返回
`内部不一致`，不得从快照占用编码、历史、默认 L1 身份或日志补造。

## 7. 最终 L1 请求与执行证据材料

先从 R2 草案按值复制节点、关系、值、属性槽、退出和读回，设置：

```text
合同版本 = L1事实基座合同版本（2）
摘要合同版本 = L1幂等摘要合同版本
期望事实代次 = 共同截止
幂等键 = R5最终键
领域意图凭证 = R4 G10凭证
领域结果见证计划 = 空
```

调用既有纯值 `准备L1写集v2(写集, 0x15001101U)`，随后必须逐字段确认生成的5项通用读回与
R2 草案完全相等，请求意图摘要等于 R4 凭证摘要，领域结果计划摘要仍为零。失败返回
`内部不一致`；不得修改 P15 helper 或在 R9 复制第二套摘要字节编码。

执行证据材料固定为：

```text
材料版本 = L1执行证据材料版本
合同版本 = 2
摘要合同版本 = L1幂等摘要合同版本
执行证据模式 = 事实互证
业务操作标签 = 0x15001101U
幂等键 = R5最终键
共同事实截止代次 = R8共同截止
提供者版本组 = [{R8身份, 1, 1, 调用次数1}]
写前事实见证组 = R8每项身份 + 截止 + 形成L1写前事实摘要(同索引副本)
```

提供者组必须按身份唯一升序；这里只有 R8 一项。写前组保持 R8 顺序，不截断、不重新读取事实。
随后调用既有纯值 `完成L1执行证据(写集, 材料)`，由 P15 唯一原语形成规范化写集摘要、材料
摘要和执行证据摘要。成功后再次调用 `L1执行证据材料基本完整`，并验证两类摘要非零、请求中
材料与上述字段逐项一致；否则返回 `内部不一致`。

## 8. 确定性、非成功与并发

- 相同输入在重复、交错和并发调用中结果逐字段全等；不读取时间、随机数、线程号或全局状态；
- 任一输入非成功、载荷缺失或版本错误均不保留其它输入中的成功材料；
- `std::bad_alloc` 返回 `资源失败`，其它未分类异常返回 `内部不一致`；
- 函数无锁、无 sleep、无跨 provider 生命周期，不产生事实代次变化；
- P15 探测、R8 调用和 R9 调用的运行期先后由后继发布者冻结，本叶只验证传入值的相互一致；
- 稳定编码仍由 L1 提交时按本地键分配，本叶不得预分配、预测或缓存任何最终编码。
