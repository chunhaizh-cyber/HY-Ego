## 1. 目标与边界

本设计只恢复保留当前删除 WIP 后的 `Debug|x64` 与 `Release|x64` 工程可编译性：恢复缺失的普通应用模块产物、切断已物理删除的旧“需求初次筹办准备”服务消费、去除仅因源文件已删除而失效的端到端测试工程登记，并补全当前 `L2任务结构服务::提交任务子目标回流后继筹办准备` 的已有实现缺口。

它不是已退出 `SELF-GOVERNANCE-LEGACY-PLANNING-E2E-RETIREMENT` 或 C031 的恢复，也不恢复 `海中鱼巣/领域/内部治理/服务.需求初次筹办准备.ixx`、其 DTO，或任何已删除端到端测试源码。它不宣称生产运行、任务闭环、端到端验收或 DATA-L2 收口。

不改变：既有 L2 / ARCH-L4 公开 DTO 的字段、版本、状态值或所有权；8120 的 I1/I2 根材料和 SELF-FORM 机器语义；根目录未跟踪副本；其它当前 WIP；规范、规则、历史计划与流程图。

## 3. 固定实现合同

### 3.1 普通应用模块

唯一工程模块路径必须恢复为 `海中鱼巣/装配.普通应用.ixx`，模块名仍为 `海中鱼巣.装配.普通应用`。从根目录副本提取时，执行者逐段核对：

1. 恢复模块正文及现有 I1/I2 声明、`普通应用上下文` 的 `自我世界树根消费材料_`、`消费并发布自我世界树根`、`读取自我世界树根消费材料`；不得改名、删字段或改变锁/返回值合同。
2. 成品不得 import、持有、构造或 getter 暴露 `需求初次筹办准备提供者`，也不得重新登记已删除的旧服务模块；当前来源副本已经不含该 provider 链。
3. 仅在 `.vcxproj` 和 `.filters` 分别登记 canonical `海中鱼巣\装配.普通应用.ixx`，不得登记 `装配.普通应用.ixx` 或创建第二个相同 export module。

### 3.2 删除旧服务消费者

在 `任务管理线程.ixx` 删除旧服务 import 和四参 `提交任务主阶段治理请求(const 需求初次筹办准备结果&, ...)`；在 `运行包.任务结果生产.ixx` 删除同一 import 和仅转发该旧重载。保留并不改动单参 `提交任务主阶段治理请求(const 任务主阶段治理请求&)`、现有线程构造/停止/结果上行链以及所有无旧服务消费者。该物理删除是使删除的 module 无零调用者的最小迁移，不建立替代入口。

### 3.3 子目标回流函数补全

函数只在无首次幂等账且 `当前代次 == 请求.请求头.期望事实代次` 后继续：

1. 以 `Gs` 读取回流记录，要求其状态为“子需求已回流待父需求重判”、任务一致、父/子需求和回流材料完整；以回流记录为目标读取关系类型 `[12]`，已有同义记录返回精确重复，异义记录返回 `引用冲突` 并回显既有后继。
2. 调用既有 `读取筹办轮次分区投影`，只接受统一轮次权威与完整当前准备；逐字段核验任务、轮次权威、首次记录、前一后继与前一筹办轮次等于请求 `统一轮次推进`。读取任务的当前筹办关系类型 `[17]` 并验证其唯一目标。
3. 用既有 `形成子目标回流后继筹办准备写集` 提交唯一 L1 写集；只接受 `已提交` 或 `精确重复`，再以现有编码映射和历史投影读取后继，逐字段用 `子目标回流后继与请求一致` 核验。
4. 同一新截止再次调用 `读取筹办轮次分区投影`，必须读到该后继为当前后继，才返回现有结果 DTO。资源、长度和未知异常保持已有的 `资源失败` / `内部不一致` 映射。

这仅接上当前已经存在的写集与读回闭环，不新增任务、需求、路径、冻结、状态、选择或自动重筹办语义。
