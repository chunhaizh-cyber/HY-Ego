## 3. 精确字节合同

### 3.1 RP 计划摘要本体

E01 计划继续为 `0x15000301U / 领域合同 1 / 规则 1 / 入口变体 1`，两个字段严格为：

| 顺序 | 标签 | 写集本地键 | 对象种类 | optional 值表示 |
| ---: | ---: | ---: | --- | --- |
| 1 | `0x00000001` | `1` | `节点种类::普通` | `std::nullopt` |
| 2 | `0x00000002` | `2` | `节点种类::属性类型` | `std::optional{值表示种类::I64}` |

RP 由唯一公共函数 `形成L1领域结果计划摘要(const L1领域结果见证计划&)` 形成。所有整数使用现有 `L1确定性编码内部::写U8/写U32/写U64` 的大端序；ASCII 前缀是原始固定字节，不写长度和 NUL；数组先写大端 U64 数量，再按字段标签升序逐项写入；节点枚举写现有 underlying U8；optional 先写 U8 `0` 或 `1`，只有 `1` 才紧跟一个 U8 `值表示种类` underlying；不得有填充、指针、地址、JSON、SQL 或容器迭代顺序。

RP 本体的完整输入序列固定为：

```text
ASCII "HZY-L1-RP"
→ U32 格式版本=1
→ U32 业务操作标签=0x15000301
→ U32 领域合同版本=1
→ U32 领域规则版本=1
→ U8 入口变体=1
→ U64 字段数量=2
→ 字段1：U32 标签1 → U32 本地键1 → U8 普通 → U8 optional=0
→ 字段2：U32 标签2 → U32 本地键2 → U8 属性类型 → U8 optional=1 → U8 I64
→ SHA-256，输出 32 字节 L1确定性摘要
```

### 3.2 G6 中 RP 的唯一位置

G6 请求意图编码只允许一次 RP 摘要，位置冻结在入口变体之后、登记请求四字段之前：

```text
ASCII "HZY-L1G6"
→ U32 请求意图格式版本=1
→ U32 操作标签=0x15000301
→ U8 入口变体=1
→ 原始 32 字节 RP 摘要（无长度、无 NUL、不可再次 SHA-256）
→ U32 登记请求合同版本
→ U32 登记请求规则版本
→ U64 登记请求幂等身份值
→ U64 登记请求期望事实代次
→ SHA-256，输出 L1领域意图凭证.请求意图摘要
```

RP 不得出现在四字段之前、四字段之后、G0 写集载荷中、执行证据材料中或结果摘要中第二次出现。`L1领域意图凭证.领域结果计划摘要` 必须等于 RP 本体摘要；非 E01 结果计划摘要保持全零。RP 不含尚未产生的稳定编码、发布代次、RW 或领域缓存。

### 3.3 RW 结果见证摘要

RW 由唯一公共函数 `形成L1领域结果见证摘要(const L1领域结果见证段&)` 形成，版本固定为 `1`，输入仅来自候选新编码映射和同一候选发布事实。完整字节序列为：

```text
ASCII "HZY-L1-RW"
→ U32 结果见证摘要版本=1
→ U32 业务操作标签=0x15000301
→ U32 领域合同版本=1
→ U32 领域规则版本=1
→ U8 入口变体=1
→ U64 发布事实代次
→ U64 写集幂等键
→ U64 字段数量=2
→ 每字段（按标签升序）：U32 标签 → U32 本地键
  → U8 对象种类 → U8 optional 标记
  → 标记1时 U8 值表示种类 underlying
  → U64 本次新稳定编码
→ SHA-256，输出 32 字节 RW 摘要
```

字段的对象种类和 optional 值必须与 RP 逐项相等；稳定编码只能取本次候选 `新编码映射`。RW 不从领域返回 DTO、普通快照、缓存或显示身份推导。

### 3.4 E01 结果摘要版本 2

E01 在 `L1写入结果`、`L1幂等首次结果副本`、`L1幂等账记录`、`L1审计记录` 和恢复结果段中增加值式 `确定性结果摘要版本`：非 E01 为 1，E01 为 2。E01 记录同时保存 `领域结果见证摘要`（RW v1）。

结果摘要 v2 的输入序列严格复用当前结果摘要 v1 的全部字节，顺序和字段不变：

```text
ASCII "HZY-L1RS"
→ U32 结果摘要版本=2
→ 现有 v1 载荷：合同版本、摘要合同版本、幂等键、请求意图摘要、执行证据摘要、发布代次、映射数量/键值、通用读回数量/逐项读回
→ 原始 32 字节 RW v1 摘要（无长度、无 NUL）
→ SHA-256，输出确定性结果摘要
```

这里的“现有 v1 载荷”必须逐字节复用当前 `形成L1确定性结果摘要` 的实现顺序；v1 非 E01 不追加 RW，也不改变其摘要。结果摘要 v2 不把 RP 再次追加，RP 只通过请求意图摘要间接被保留。

## 4. 同义、持久化、恢复与失败

首次 E01 成功候选中，RP 已在 G6 意图摘要中互证；候选形成 RW v1，随后形成结果摘要 v2。幂等账、成功审计、结果见证状态组和 `L1写入结果` 保存同一 RW、结果摘要版本 2 和确定性结果摘要。三副本仍在一次候选交换中原子可见。

同键同意图重试只比较公开请求意图摘要；命中 E01 首次账后原样返回首次保存的 RP 绑定结果、RW v1、结果摘要版本 2、结果摘要和通用读回，provider/提交为 0/0，绝不按当前映射、当前代次或新 RP 重算。异义仍为幂等冲突。

恢复导出分别复制幂等账、成功审计和结果见证状态组，并保存每条记录的结果摘要版本。恢复校验按版本分派：E01 必须按 §3.3 重算 RW v1，再按 §3.4 重算结果摘要 v2；非 E01 继续重算结果摘要 v1。RW、版本、结果摘要、映射、通用读回任一不等返回 `材料不完整`；通过材料校验后的候选构造或交换后读回矛盾返回 `内部不一致` 并隔离。禁止补记、二次提交或从 SQL/缓存补造。

锁前 RP 缺失、位置错误、重复或 G6 摘要绑定错误固定 `入口拒绝`，provider/提交为 0/0；锁内 RW 字段、版本或映射不一致固定 `入口拒绝`，候选不交换；交换后 RW/结果摘要/权威读回不一致固定 `内部不一致`，保留已发布代次与已有成功记录并追加失败见证/隔离审计。
