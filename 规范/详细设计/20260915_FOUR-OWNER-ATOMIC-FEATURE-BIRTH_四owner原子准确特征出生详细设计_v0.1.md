# FOUR-OWNER-ATOMIC-FEATURE-BIRTH 四 owner 原子准确特征出生详细设计 v0.1

状态：待施工设计。设计基线：`a41b1f914743c8f9c1b9a2b674981ad3dc47b47d`。

## 1. 目标与依据

本设计实现 1130 §1、§3.1、§4，4110 §5.1、§8，以及 4115 §2—§3 已冻结的唯一前置能力：世界新准确特征 `F` 只能在同一次原子发布中同时拥有完整内容、真实 holder 已知引用、`P→F` 组织边和到已发布单值概念 `FCv` 的使用引用。

它交付“原子特征出生”提供者，不实现 IF/R、当前采用变更、R 汇聚、名称、观察计数、线程或启动。`FCv` 是独立前置发布的概念事实；若其成功而 F 出生随后拒绝或失败，已发布的 `FCv` 保留，不能倒写为无概念 F 或回滚。

当前事实：`L1有限N分区原子事务_v3` 已在 `L1所有者范围CRUD.数据.h`、`服务.L1事实基座.h` 和 `仓库.L1事实基座.h` 实现，允许 2—255 个不同 owner 以同一事实代次提交、以原组合幂等身份精确重放，并允许参与者仅引用编号更小的参与者本地节点。因此本设计**不改 L1 ABI、仓库或服务**。

## 2. 原子边界、owner 与固定顺序

一次新 F 出生的唯一原子边界为：

```text
1 特征 owner：F 普通节点、F→FT 类型边、准确值材料/值事实
2 存在 owner：真实 holder→F 已知边
3 场景 owner：P→F 组织边
4 概念 owner：F→已发布 FCv 使用边
```

`L1有限N分区原子事务_v3` 的参与者序号严格固定为上表顺序。存在与场景片段只向后引用特征 owner 的 F 本地键；概念片段只向后引用特征 owner 的 F 本地键、向稳定编码引用已发布 `FCv`。不允许任何反向跨参与者引用。

四个 owner 只产生自己的片段：

| owner | 只负责 | 明确不负责 |
| --- | --- | --- |
| 特征 | F 内容、FT、完整准确值与内容候选读回 | C/P 位置、holder、FC 使用边、概念生成 |
| 存在 | 已由场景位置核验取得的真实 holder 已知 F 边 | F 内容、位置判断、当前采用、FC 写入 |
| 场景 | C/P 类别、路径、真实 holder 见证及组织边 | F 内容、已知边、FC 写入 |
| 概念 | 已发布 FCv 同 FT/生命周期核验和 F→FCv 使用边 | F 内容、位置、holder、概念定义出生 |

所有“首次/复用/多候选/位置不一致/存量未定位”的业务分类在 `特征概念应用服务` 完成；下层参与者只核验本次请求的形状、同截止见证与自身写集。该安排符合“尽量在上层判断，不把业务异常混入底层”的口径。

## 3. 新公开合同和物理位置

### 3.1 原子出生组合服务

保留物理文件 `海中鱼巣/领域/数据服务.定位特征.h`，但删除其中旧三 owner `定位特征数据服务::创建或复用` 及其三 owner 创建 DTO；文件内新建下列具名合同和服务，避免旧入口仍可发布无 FC 的 F：

```cpp
struct 原子特征出生键 final {
  L1所有者范围写入幂等身份 组合, 内容, 已知, 组织, 概念使用;
};

struct 原子特征出生请求 final {
  std::uint32_t 版本 = 1;
  std::uint64_t G0 = 0;
  定位特征位置 位置;                 // C、P
  稳定编码 正式特征类型;
  std::variant<std::int64_t, 特征值身份> 准确值;
  概念树概念身份 FCv;                 // 已发布单值概念
  std::optional<稳定编码> 指定复用F;
  原子特征出生键 键;
  定位特征预算 预算;
};

enum class 原子特征出生状态 : std::uint8_t {
  已创建, 已复用, 精确重复, 入口拒绝, 未找到, 目标已退出,
  位置冲突, 需选择F, 存量未定位, 概念不适配, 事实代次漂移,
  幂等冲突, 预算不足, 历史材料不可用, 资源失败, 内部不一致, 已可能发布
};

struct 原子特征出生事实 final {
  稳定编码 F, 正式特征类型, FCv;
  特征准确值 完整准确值;
  定位特征位置 位置;
  稳定编码 holder, 已知关系, 组织关系, 概念使用关系;
  std::uint64_t 出生H;
};

struct 原子特征出生结果 final {
  std::uint32_t 版本 = 1;
  原子特征出生状态 状态;
  std::uint64_t Gread = 0;
  std::optional<std::uint64_t> 首次发布H;
  std::optional<原子特征出生事实> 事实;
  std::vector<稳定编码> 候选F;
  原子特征出生请求 原请求;
};

class 原子特征出生数据服务 final {
public:
  原子特征出生数据服务(原子特征内容参与者&, 原子特征holder参与者&,
                         原子特征组织参与者&, 原子特征概念参与者&);
  原子特征出生结果 创建或复用(const 原子特征出生请求&);
  原子特征出生读取结果 读取(const 原子特征出生读取请求&) const;
};
```

结果成功必须回显四条关系、`FCv`、`F` 的完整准确值和同一 `H`。`已复用`没有新 `H`；`已创建`与`精确重复`的 `H == G0 + 1`。不得把“概念无词条名称”映射为失败。

`原子特征出生读取请求` 固定为 `{版本=1, Gread, H, F, 预算}`，其结果固定回显上述 `原子特征出生事实`。读取时 `F` 内容、P 路径、holder 已知边与概念使用边都必须在同一 H 当前有效；任何一项缺失、重复、错 owner、错 FT 或与 C/P 不一致，均不返回半成功。

### 3.2 窄 owner 参与接口

在同一头文件建立四个仅友元可调用的参与接口：`原子特征内容参与者`、`原子特征holder参与者`、`原子特征组织参与者`、`原子特征概念参与者`。每个接口统一提供：同一 L1 绑定核验、owner 端口借用、结构就绪、幂等键可用、同截止只读见证、`准备原子出生片段(...) -> 原子特征参与者结果<L1有限N分区原子参与者写集_v3>` 与首次材料读回。

实现位置固定如下：

| 文件 | 实现责任 |
| --- | --- |
| `领域/数据服务.特征类.h/.cpp` | 内容参与者；形成 owner #1 片段和准确内容读回 |
| `领域/数据服务.存在类.h` | holder 参与者；只形成 owner #2 已知边 |
| `领域/数据服务.场景类.h` | 组织参与者；核验 C/P 并产生 owner #3 片段及 holder 见证 |
| `领域/数据服务.概念树类.h/.cpp` | 概念参与者；核验已发布单值 FCv 并形成 owner #4 使用边 |
| `领域/数据服务.定位特征.h` | 组合、v3 调用、精确重放、四片段读回核验 |

概念 owner 的片段只接受稳定、同 FT、当前有效且已发布的 `FCv`。不得在该片段内创建概念、补词条名称或替换 F 名称。

场景参与者的同截止位置见证必须明确返回 `{C, P, 真实holder, P种类, 路径}`。`P种类`只可为场景特征根、存在或父 F；场景根的 holder 为 C，存在 P 的 holder 为该 E，父 F 的 holder 继承已读父 F 的 holder。存在参与者只接受该见证给出的 holder，核验其当前有效后形成 `holder→F`，不得从 P、C、缓存或名称自行猜 holder。

### 3.3 上层概念前置与消费者迁移

`业务/应用服务.特征概念类.h/.cpp` 新增私有的“按完整准确输入确保单值 FCv”路径：它以 `FT + 准确输入 + 已冻结域规则` 查询或独立建立单值 `FCv` 并同截止读回；不先建立临时 F，也不调用旧定位创建。取得 `FCv` 后才形成 `原子特征出生请求` 并调用组合服务。

该私有路径的值式合同固定为：

```cpp
struct 单值出生概念确保请求 final {
  std::uint32_t 版本 = 1;
  std::uint64_t G0 = 0;
  特征类型身份 FT;
  特征准确值 准确值;
  L1所有者范围写入幂等身份 概念键;
  特征概念预算 预算;
};
enum class 单值出生概念确保状态 : std::uint8_t {
  已建立, 已复用, 精确重复, 规则缺失, 类型不相容, 入口拒绝,
  事实代次漂移, 幂等冲突, 历史材料不可用, 资源失败, 内部不一致, 已可能发布
};
struct 单值出生概念确保结果 final {
  单值出生概念确保状态 状态;
  std::uint64_t Gread = 0;
  std::optional<std::uint64_t> 首次H;
  std::optional<特征概念事实> FCv;
  单值出生概念确保请求 原请求;
};
```

它只建立定义为该完整准确输入的单值域 `FCv`，而非 R、上位概念或名称；成功结果必须读回 `FCv.定义.类型 == FT`、单值域与完整输入一致且当前有效。`已可能发布`同样只能以原 `概念键` 收敛。应用取得 FCv 成功后重新读取 G0，再进入四 owner 出生；概念确保与出生绝不共享或重用同一个幂等键。

`特征概念应用服务` 构造器改接收 `原子特征出生数据服务&`，并验证四个参与者与概念服务属于同一 L1。`业务/应用服务.场景成员概念类.h/.cpp` 同步替换旧三参与者断言。`装配.普通应用.h/.cpp` 建立并保存新组合服务，再注入特征概念应用服务；装配不主动调用出生入口。

旧 `定位特征数据服务` 的创建 DTO、`创建或复用`、三 owner 写集、三 owner 精确重放和全部生产调用必须物理删除；不提供别名、兼容壳或“无 FC”回退。只读历史检查若遇到旧无 FC F，返回 `存量未定位` 或`历史材料不可用`，不能作为新成功结果。

## 4. 控制流、幂等与读回

```text
L3 校验 C/P、FT、完整值、预算与五个不同键
→ 在同一 Gread 选择/独立建立并读回 FCv
→ 重新取得 G0；查询同位置的准确 F 候选
→ 0 个候选：四 owner 准备片段，v3 同次提交
→ 1 个候选：完整读回 C/P、holder、FT、值、唯一 FCv 使用
→ 多候选：需选择F，零写
→ 提交/重放后，以原键和同一 H 读回四 owner 全部事实
```

首次建立仅当五个首次材料均未找到、`G0 == 当前G` 且四片段完整时允许提交。任一首次材料已存在时，五者必须同时存在、来自同一 `H`、与请求规范化后的五片段和组合键逐项相同；否则 `幂等冲突`，绝不混合旧片段与新片段。

提交前拒绝、候选歧义、概念不适配、位置/holder/路径异常、漂移、预算和片段核验失败均零本次 F/关系/组合账写入。提交结果为`已可能发布`或写后读回中断时，只保留原请求和原五键，调用者只能重试原请求收敛；不得换键重建、不得声称零写或回滚。精确重放和首次成功均必须按四 owner 的首次材料及历史事实独立读回。

复用只允许“完整准确内容、请求 C/P、真实 holder 和唯一 FCv 使用均一致”的单个当前 F。其它位置的同内容 F 不自动复制、移动或重挂；不同 FCv、多个同位置候选、旧无父/无 FC 结构均分账为 `位置冲突`、`需选择F` 或`存量未定位`。

## 5. 非成功、删除和兼容边界

组合服务把四个参与者的已知失败转换为本服务同名结构化状态；不把底层错误改为“结构异常”。L3 负责 IF/R 的首次/后续/结构异常分类和 UI 诊断，不由本提供者执行。

本计划不实现 F 删除，但任何现有删除路径在迁移后必须把概念 owner 的 F→FCv 使用边列入保护/退出闭包；若尚未具备完整四 owner退出合同，则明确拒绝，不能沿用旧三 owner删除。

禁止改动：L1 v3、IF/R 六关系及其初始化、当前采用语义、F 原地值、I64 域/误差归并、概念汇聚记录/重试、线程、启动和阶段 21。
