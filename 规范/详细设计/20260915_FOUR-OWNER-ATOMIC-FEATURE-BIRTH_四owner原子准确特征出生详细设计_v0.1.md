## 1. 目标、依据与收紧边界

本设计仅实现正式 1130 §1、§3.1、§4，4110 §5.1、§8 和 7160 §5.1 所要求能力中的 **I64 阶段**：一个世界新 I64 准确特征 `F` 在同一次 `G0→H` 原子发布中，同时具备完整 I64 内容、真实 holder 的已知引用、`P→F` 组织边，以及到已发布 I64 单值域概念 `FCv` 的使用引用。

`L1有限N分区原子事务_v3` 已支持 2—255 个不同 owner 的同次提交、原组合键重放及向前跨参与者引用。因此本设计不改 L1 ABI、仓库或服务。

这不是对正式规范的收窄：4110 §8 和 7160 §10 仍要求 I64组、U64组及独立材料引用的完整能力。本计划完成后，三者的完整值读回、单值域 FC 编码与规范化、匹配、概念 owner 核验、定位读回、四 owner 出生和专项验证仍未实现，必须保留为后续缺口；不得宣称通用准确 F 已完成。

## 2. 原子边界和职责

一次新 I64 F 出生的唯一原子边界固定为：

```text
1 特征 owner：F 普通节点、F→FT 类型边、完整 I64 值事实
2 存在 owner：真实 holder→F 已知边
3 场景 owner：P→F 组织边
4 概念 owner：F→已发布 I64 单值域 FCv 使用边
```

参与者序号严格为 `1/2/3/4`。存在和场景片段只向前引用 owner #1 的 F 本地键；概念片段向前引用同一 F，并按稳定编码引用已发布 FCv；不允许反向引用。

| owner | 本次只负责 | 明确不负责 |
| --- | --- | --- |
| 特征 | F、FT 和完整 I64 内容的写集及读回 | C/P、holder、FCv 生成或使用边 |
| 存在 | 经场景见证取得的 holder→F | F 内容、位置判断、当前采用、FCv |
| 场景 | C/P、路径、真实 holder 见证及 P→F | F 内容、已知边、FCv |
| 概念 | 已发布 I64 单值域 FCv 的同 FT/生命周期核验及 F→FCv | F 内容、位置、holder、概念出生 |

首次/复用/多候选/位置不一致/存量未定位等业务分类，以及诊断 UI / 日志，均在 `特征概念应用服务` 完成。L2 参与者只核验请求形状、同截止见证与自身写集，不解释为 IF/R 结构异常，也不弹窗或记 UI 日志。

不得在这些 DTO 或参与接口中保留 `std::variant<std::int64_t, 特征值身份>` 来伪称已支持其它表示。候选查询只返回在请求 `Gread` 下、满足同一 `C/P/FT/I64` 精确召回条件的全部 `{F,出生H}`，不排序、不删重为单项、不把读取失败解释为零候选；`出生H` 是后续完整读取的历史截止，绝不是当前 `Gread` 的替代。候选、组织路径和概念读取预算相互独立，三者的必需字段均不得为零；候选查询用自己的组织读取预算核验 C→…→P，不能默认路径上限或从其它预算推导。L3 只可把“已读取且候选空”判为创建前提；每个非空项必须先以其 `{Gread,出生H,F,C,P}` 和独立组织/概念预算调用下文完整读取，读取失败、交叉不一致或旧格式均不是“没有候选”。

`创建`不查询、不枚举、不分类候选，也不接受指定复用 F；它只处理 L3 已在同一 `G0` 取得的零候选决定和新建的四 owner 事务。创建请求中的组织读取预算必须非零，并由组合器不改写地传给 owner #3 的片段准备；owner #3 以它核验 C→…→P 路径和组织父 P，预算不足、路径不通或位置不符在提交前返回具名失败和零片段。若并发发布使 G0 失效，L1 的截止核验返回具名漂移，L3 从新快照重新查询和判断。成功结果必须回显四条关系、FCv、完整 I64 和同一 H；`已创建/精确重复`的 `H == G0 + 1`。读取在同一 H 核验 F 内容、P 路径、holder 已知边和概念使用边；不得返回半成功。

四个仅友元可调用的参与接口均命名为 `原子I64特征内容/holder/组织/概念参与者`；共同提供同一 L1 绑定核验、owner 端口借用、结构就绪、幂等键可用、同截止只读见证、`准备原子I64出生片段(const 原子I64特征出生请求&, std::uint64_t)` 与首次材料读回。概念参与者在准备片段前必须读回 `FCv` 的 I64 单值域、FT 和当前生命周期；不得创建或改写概念。候选查询由组合器只组合既有的精确召回和历史截止事实；不得调用准备片段、分配身份、写入、调用旧定位 DTO 或根据返回数量切换到创建/读取。

内容、holder、组织参与者各增加一个仅友元可调用的窄读取接口，声明在`数据服务.定位特征.h`，分别由`数据服务.特征类.h/.cpp`、`数据服务.存在类.h`、`数据服务.场景类.h`实现：

```cpp
virtual 原子I64特征窄读取结果<原子I64特征内容事实>
读取原子I64内容(const 原子I64特征内容读取请求&) const = 0;

virtual 原子I64特征窄读取结果<原子I64特征holder事实>
读取原子I64holder(const 原子I64特征holder读取请求&) const = 0;

virtual 原子I64特征窄读取结果<原子I64特征组织事实>
读取原子I64组织(const 原子I64特征组织读取请求&) const = 0;
```

三者均以 L1 的现有历史节点、关系和值读取组成自己的结果，不调用或返回旧 `准确特征读取事实`、`定位特征事实`、`存在已知准确特征读取结果`、`场景特征组织历史结果`等旧业务 DTO。每次先后读取中性当前事实代次；两次均须等于请求 Gread，且请求 H 有效并不大于 Gread，才可返回`已读取`。组织读取预算的最大路径长度为零一律入口拒绝；路径超过该请求独立上限映射`预算不足`，不得以候选或概念预算补值。历史墓碑映射`历史材料不可用`；L1 资源失败映射`资源失败`；缺失映射`未找到`；目标在 H 已退出映射`目标已退出`；其它形状、owner、类型、角色、端点、生命周期或唯一性不符映射`内部不一致`。任一失败均清空事实。

内容读取必须在 H 返回一个仍有效 F、唯一 `F→FT` 类型关系、FT、唯一完整 I64 值事实及其值、关系和事实创建 H；类型关系和值事实均属于 owner #1，且 F/关系/值都在 H 有效。holder 读取必须按请求的 holder 与 F 返回唯一 `holder→F` 已知关系、关系类型及创建 H；该关系属于 owner #2、角色为`1`、在 H 有效。组织读取必须按请求 C/P/F 返回：C 到 P 的无环连续路径（每边角色`1`、在 H 有效、路径长度不超过独立预算）和唯一 `P→F` 组织关系（owner #3、角色`1`、在 H 有效）；C/P 不符、路径断裂或 P 不是路径终点映射`位置冲突`，而不是改为候选搜索。

组合器的`读取`不再只读 owner #4。它固定按 `内容 → holder → 组织 → 概念使用` 顺序，以同一 `{Gread,H,F}`调用四个窄读取；holder 输入必须是读取请求的 `位置.场景`，组织输入必须是 `位置.场景/位置.组织父/F` 和读取请求的独立组织读取预算，概念输入使用同一概念读取预算。四个结果均`已读取`后才合并：内容 F/FT/I64、holder F、组织 F、概念使用 F 必须相同；holder 必须等于 C，组织 C/P 必须等于原请求位置；四个关系和概念 FCv 均唯一且在 H 有效。任一参与者失败映射到`原子I64特征出生状态`的同名状态（概念不适配除外保持`概念不适配`），任一交叉不符映射`内部不一致`，并使组合结果零事实。只有四项都通过才返回完整`原子I64特征出生事实`与`状态=已读取`。

`原子I64特征概念读取预算`三个字段都必须非零。概念参与者在每次读取时仅构造 `概念树预算{最大概念数, 最大关系数, 0, 0, 0, 最大特征属性数, 0, 0}` 传给既有`读取纯概念`；不得从候选读取预算或组织读取预算补值、截断或推导，也不得把后五个概念预算字段暴露到原子出生 ABI。调用方（L3 的概念前置/候选查询/组合调用链）负责同时提供三份独立预算；候选查询、创建和读取均各自验证自己收到的候选/组织/概念预算，不得省略组织预算。L2 只验证自己消费的字段并原样传递。概念读取预算不足映射为`预算不足`，纯概念读取的代次、历史、目标退出、资源和内部错误保持其对应具名映射；任一失败在四 owner 提交前返回，零 owner #4 写集。

### 3.1 owner #4 的独立出生使用物理合同

这不是名称关系、共享用途记录或对现有 `特征概念结构交付::类型[11]` 的重解释。当前名称关系可为空、替换或解除，`概念树共享使用`还带业务标识、观察、时间和用途角色；二者均不能证明出生时已经成立的使用事实。普通应用当前实际构造的是 `纯概念结构交付_v2`，其中已显式交付格式锚点、概念族锚点及 13 个基础类型（包括 `格式版本`、`I64域` 和 `类型登记`）。因此出生使用结构只依赖这份已装配交付；不扩容或改义旧 24 项格式，也不依赖、扫描或核验未装配的旧 `特征概念结构交付`、`概念树存在扩展交付`：

```cpp
struct 特征概念出生使用结构交付 final {
  稳定编码 锚点;
  std::uint32_t 格式 = 1;
  稳定编码 F到FCv出生使用关系类型;
};

struct 特征概念出生使用事实 final {
  稳定编码 关系;
  特征信息身份 F;

struct 特征概念出生使用结构登记请求 final {
  std::uint32_t 版本 = 1;
  std::uint64_t G0 = 0;
  L1所有者范围写入幂等身份 幂等键;
  纯概念结构交付_v2 纯概念结构;
  std::uint64_t 最大首次材料项数 = 0;

// 全部都是已提交后的指定 H 历史读回；不得用提交返回映射替代。
struct 特征概念出生使用结构首次材料读回 final {
  L1所有者范围节点事实 锚点;

  纯概念状态 状态 = 纯概念状态::入口拒绝;
  纯概念发布状态 发布 = 纯概念发布状态::未进入;

  std::optional<std::uint64_t> 首次发布H;

  std::optional<特征概念出生使用结构交付> 交付;
  std::optional<特征概念出生使用结构首次材料读回> 首次材料;

```

概念 owner 的登记请求必须接收已由 `登记纯概念结构_v2` 成功读回的 `纯概念结构交付_v2`。登记函数只按该输入中的 15 个具名身份读取和核验：版本 `2`、格式锚点、概念族锚点、13 个基础类型的互异性，以及纯格式锚点上恰有 13 条既有类型登记。它不枚举 owner 空域、不搜索其它锚点，也不接受“缺省旧扩展”。

登记函数在同一概念 owner 端口以独立原键新建四项首次材料：出生使用锚点普通节点、无值普通关系类型节点、锚点到关系类型的登记边、锚点的格式 `1` 值。格式值的属性类型必须是 `纯概念结构.类型.格式版本`；登记边的关系类型必须是 `纯概念结构.类型.类型登记`、角色固定为 `1`。新锚点与新关系类型必须互异，且都必须同那 15 个已输入纯结构身份互异；禁止修改纯格式锚点原有 13 条登记边。

登记结果是公开 ABI，不能只以 `optional<交付>` 表示。其 `成功(r)` 必须同时断言：版本均为 `1`；`状态` 为`已创建`或`精确重复`；`发布`为`确认发布`；`原请求`与 `r` 的版本、G0、原键、纯概念交付和预算完全相同；`首次发布H == r.G0 + 1 <= Gread`；`交付`和`首次材料`均存在。`首次材料`四项均为同一概念 owner 在同一首次发布 H 建立、未退出的历史事实：两个节点的身份分别等于交付锚点和交付关系类型，登记关系的源/目标/类型/角色分别等于锚点/关系类型/纯交付类型登记/`1`，格式值的所属/来源/属性类型/材料分别等于锚点/锚点/纯交付格式版本/`int64_t{1}`。任一断言不成立就不是成功。

登记开始时必须按请求原键读取 L1 首次材料。`未找到`只在读回 Gread 恰为 G0 且没有残留写集/写入结果时可形成首次写集；`成功`只在首次规范化写集与本登记预期写集精确相同、首次写入结果为成功且 `H == G0 + 1`、已形成内存权威发布时可进入原键精确重放。其它既有材料必须映射为具名旧格式、幂等冲突、事实代次漂移、资源失败或内部不一致，绝不以新键补写。首次提交只接受`成功`，原键重放只接受`精确重复`；二者都必须逐项按同一 H 历史读回四项材料，再构造交付和成功结果。

一旦已进入提交而提交返回、当前代次读回、首次材料或四项历史读回不能证明上述成功条件，结果必须为`已可能发布/可能发布`，保留原请求、Gread（取得时）与首次 H（已知时），但清空`交付`和`首次材料`；调用方只可按**同一原键**重试或读取收敛，不能声明零写或改键新建。任何确认未发布的失败同样保留原请求和具名状态，但`交付`、`首次材料`、首次 H 均为空；失败绝不返回空壳交付。

普通应用的唯一顺序固定为：`登记纯概念结构_v2 → 取得并保留纯概念交付 → 用同一概念 owner 端口登记出生使用结构 → 两份登记结果均以各自成功谓词确认原键、H、交付及首次材料读回 → 构造概念树类并同时注入两份交付`。纯结构或出生使用结构任一失败、可能发布或读回不完整都停止装配；不得构造仅含纯结构的概念树服务来充当本计划 owner #4 提供者，也不得以名称类型或共享用途类型代替。

`原子I64特征概念参与者`除既有出生片段准备外，固定只增加下列两个友元私有接口；它们声明在`数据服务.定位特征.h`，由`数据服务.概念树类.h/.cpp`实现，普通应用和 L3 不能直接调用：

```cpp
virtual 原子I64特征出生使用读取结果 读取原子I64出生使用(
    const 原子I64特征出生使用读取请求&) const = 0;

virtual 原子I64特征参与结果<L1有限N分区原子参与者写集_v3>
准备原子I64出生使用退出片段(
    const 原子I64特征出生使用退出片段请求&, std::uint64_t Gread) const = 0;
```

读取成功仅当请求版本为`1`、`Gread/H/F`有效且 `H <= Gread`、三项概念读取预算均非零，并返回`状态=已读取`、相同`Gread/H`和完整`特征概念出生使用事实`。该事实必须是 H 时 F 唯一当前的出生使用关系，关系类型为注入交付类型、角色为`1`、源为 F、目标为当前活跃 FCv；同时 FCv 经既有`读取纯概念`读回为当前 FT 的 I64 单点域。结果不得使用任何创建、复用或候选分类状态冒充读取成功，失败清空事实。

退出片段请求只用于已经由四 owner 叶退出组合器确定的 F；`Gread`必须等于请求 G0。它先以`{版本=1,Gread=G0,H=G0,F,概念读取预算}`调用上述读取接口，成功后返回 owner=`4`、预期代次=`G0`、幂等身份=`概念使用退出键`且只退出该出生使用关系的 N 分区参与者写集。不得创建节点/值，不得退出 FCv、名称关系或共享用途；读取失败、键/结构无效或关系不唯一时零片段。该接口不增加 F 叶退出的公开服务、组合键或其它三 owner 退出 ABI；完整退出入口仍须由持有其完整既有合同的组合器提供。

准备出生片段时概念 owner 接收原子请求中的 `FT`、`准确I64`、`FCv`、概念使用幂等键和 owner #1 的前向 F 本地引用；它以请求的`概念读取预算`通过已注入的纯概念结构读取 FCv，只核验其为当前已发布的特征类别 `纯I64特征概念定义`、定义类型等于 FT、规范化 I64 域恰为单点 `[准确I64,准确I64]`，以及结构/端口/键/预算合法。它不查询候选、不形成概念、不判断首次或后续、不写弹窗或 UI 日志。

准备成功的片段只写一条概念 owner 关系：源为 owner #1 的 F 前向引用、目标为稳定已发布 FCv、类型为 `F到FCv出生使用关系类型`、角色为 `1`，不新建节点或值。与同一 I64 出生对应的 F 在同一 H 必须恰有一条当前该类型关系；零条、重复、端点/类型/角色/生命周期不符均为具名拒绝或内部不一致，绝不回落到名称。首次材料与精确重放必须使用第五把“概念使用”原键；首次发布后该关系的创建 H 必须等于 F、holder 已知和 P→F 的 H。

读取必须在同一 `{Gread,H}` 核验 F 外部节点、唯一当前出生使用边、FCv 当前性及完整 I64 单值定义，并返回该 `关系/F/FCv/生命周期`。组合服务再把此见证同另三 owner 见证合并；概念 owner 不自行读取尚未发布的 F 内容。F 的叶退出由上述 owner #4 片段把这条关系加入既有组合退出事务，FCv 在任一当前入边存在时不得退出。名称建立、替换、解除以及共享用途的写入和退出对该关系零影响；它们也不得被当作退出它的授权。

### 4.1 最小 FCv 父组读取提供者

当前 `概念树类数据服务::精确查询纯概念(const 纯概念查询请求&)` 只能按完整定义返回零或一个 `纯概念事实`；它不能证明不存在更近中间域。旧`查找特征概念`虽能按类型返回旧`特征概念事实`，但它属于本计划待物理删除的观察 / 旧定位链，DTO、预算、生命周期和读取合同均不等价，禁止借用。既有 `特征类数据服务::读取I64类型完整域(const 特征类型截止请求&)` 则已精确提供 FT 完整允许域，继续直接复用，不新增特征类 ABI。

在`领域/合同.相关概念添加参与.h`紧邻纯概念读取合同新增下列公开 DTO；在`领域/数据服务.概念树类.h/.cpp`由概念 tree owner 新增唯一只读提供者：

```cpp
    const I64特征概念组织读取请求&) const;
```

请求版本须为`2`，`Gread/H/FT`有效且 `H <= Gread`；预算的最大概念数、最大关系数和最大特征属性数均非零。成功只在同一 `{Gread,H}` 返回**全部** H 时当前、类别为特征、定义为 `纯I64特征概念定义` 且定义 FT 等于请求 FT 的完整 `纯概念事实`。每项必须包含完整规范域、生命周期和直接上位组；按概念稳定编码严格升序、无重复。零项是`状态=已读取`的合法完整结果，不返回`未找到`。超过最大概念数或完成事实所需关系/特征属性超过相应预算返回`数量预算不足`且清空组，绝不截断或返回前缀。任一代次漂移、历史材料不可用、目标退出、资源失败或内部不一致按既有`纯概念状态`具名返回并清空组；结果不得查询、形成、恢复、治理、写入或改变缓存。

L3 只在精确查询单点域已`确认未找到`后，以同一新取得的 `{Gread,H}` 同时调用此提供者和既有 `读取I64类型完整域`。二者必须同截止成功，才能计算父组；任一失败不进入纯概念创建，不把空组或部分组当作顶层。该提供者只满足 FCv 形成的父组读取，不能作为通用概念全表、名称、用途或旧观察枚举接口。

### 4.2 L3 v1.0 公开合同、FCv 形成与注入

旧`特征概念观察请求`不是本计划的输入：它把观察记录、`定位特征创建请求`、`std::variant`值、`指定F`和旧`创建或复用`的业务决定混为一个 L3 入口，既不能表达四 owner 的五把出生键，也不能提供本节所需的 FCv 原键、组织路径预算和纯概念组织信息。其替代公开合同固定为：

```cpp
struct I64原子准确特征出生应用请求 final {
  std::uint32_t 版本 = 1;
  std::uint64_t G0 = 0;
  定位特征位置 位置;                 // 显式 C、P
  特征类型身份 FT;
  std::int64_t 准确I64 = 0;
  L1所有者范围写入幂等身份 FCv概念键; // 只用于纯概念创建/原键收敛
  原子I64特征出生键 F出生键;          // 组合、内容、已知、组织、概念使用五把键
  原子I64特征候选读取预算 候选读取预算;
  原子I64特征组织读取预算 组织读取预算;
  原子I64特征概念读取预算 出生概念读取预算;
  概念树预算 FCv概念预算;             // 纯概念查询、创建及首次读回
};
enum class I64原子准确特征出生应用状态 : std::uint8_t {
  已创建, 已复用, 精确重复, 需选择F,
  FCv确保失败, 候选查询失败, 候选读取失败, 出生失败, 入口拒绝
};
struct I64原子准确特征出生应用结果 final {
  std::uint32_t 版本 = 1;
  I64原子准确特征出生应用状态 状态;
  std::uint64_t Gread = 0;
  std::optional<I64单值出生概念确保结果> FCv确保;
  std::optional<原子I64特征候选查询结果> 候选查询;
  std::vector<原子I64特征出生读取结果> 候选读取组;
  std::optional<原子I64特征出生结果> 出生;
  std::optional<原子I64特征出生事实> 事实;
  I64原子准确特征出生应用请求 原请求;
};
```

入口要求 `版本=1`、非零 G0/C/P/FT、有效且互异的 `FCv概念键` 与五把 `F出生键`，以及候选数、路径长度、出生概念读取三项和 `FCv概念预算`中的最大概念数/最大关系数/最大特征属性数均非零。`FCv概念键`不得替代任一 F 出生键，反之亦然；任一键或预算无效只返回`入口拒绝`，不查询、不创建、不写入。结果保留各阶段的结构化结果以给出失败原因；仅其所列成功分支可设置完整`事实`，不得以空 FCv 或部分候选读回冒充复用。

FCv 确保顺序固定如下，所有读取使用同一成功读回的概念截止；任何预算、读取、比较或组织失败都不是“未找到”，不得新建：

1. 用 `FCv概念预算`按完整 `FT + [I64,I64]` 定义查询纯概念；同义当前概念直接读回复用，退役、冲突或非成功按具名失败收束。
2. 只有`确认未找到`时，L3 以同一新取得的 `{Gread,H}` 调用既有`特征类数据服务::读取I64类型完整域(const 特征类型截止请求&)`和新的`概念树类数据服务::读取当前I64特征概念(const I64特征概念组织读取请求&)`，取得 FT 完整允许域和全部当前纯 I64 概念，计算新单点域的直接上位。若单点域等于完整允许域，冻结 `组织=显式顶层` 与空上位组；否则冻结 `组织=具名上位`，上位组是全部仍当前、严格包含新域且不存在“仍当前并严格夹在两者之间”的概念。该集合按稳定编码去重排序后写入请求；空集合、无法证明包含、相等但非同义、退役或不完整材料均具名失败，绝不把特征根、任意首项或空组默认成父。
3. L3 以同一 `G0`、`FCv概念键`、完整 I64 单点定义、上述组织和直接上位组以及原样 `FCv概念预算`调用`创建或复用纯概念`；成功或精确重复后必须按原请求读回完整定义、组织和直接上位。进入提交后的不确定状态只可按`FCv概念键`收敛，不能用新键或直接新建 F。
4. 只有 FCv 确保结果完整成功后，L3 重新取得 G0 并进入候选/四 owner 流程；FCv 已发布而后续候选或 F 出生失败时保留 FCv，结果不得伪称完整成功。

`特征概念应用服务`的唯一构造注入固定为`(特征类数据服务&, 概念树类数据服务&, 原子I64特征出生数据服务&)`；构造时核验概念树已注入纯概念结构交付与出生使用结构交付，且原子服务绑定同一四 owner 提供者。L3 不再持有、构造或调用`定位特征数据服务`。`场景成员概念类`只接受和转发上述应用请求 / 结果，不能重新引入定位 DTO、指定 F 或独立候选分类；普通应用必须在四 owner 原子服务及双概念交付均成功装配后才构造这两个 L3 消费者。

控制流固定为：

```text
L3 核验 C/P、I64 FT、I64 完整值、三份独立预算与五个不同键
→ 确保并读回 I64 单值域 FCv
→ 重新取得 G0；以非零候选和组织路径预算调用 L2 精确候选查询，取得全部 `{F,出生H}`
→ L3 逐项以 `{Gread,出生H,F,C,P}` 调用 L2 四 owner 完整读取
→ L3 分类：空候选才以同一 G0、非零组织路径预算和非零概念预算调用 L2 `创建`；恰一项完整候选直接复用其读回事实；多项完整候选返回`需选择F`且零写
→ 任一候选读取失败、交叉不一致或候选查询失败：具名失败，绝不降格为零候选
→ 创建提交/重放：按原键、同一 H 读回四 owner 事实
```

首次材料必须五者全无；已存在时五者须同 H 且与原请求逐项相同，否则 `幂等冲突`。提交后或读回中断只允许用原五键收敛，绝不换键重建。

## 5. 非成功、迁移与明确排除

- FCv 缺失、错 FT、已退出或读回失败：不进入提交，零 F/关系写。
- 纯概念交付缺失/旧格式/13 条登记不完整、出生使用结构未登记、交付格式/身份冲突、关系重复、名称或共享用途被误传为出生使用：拒绝或报告内部不一致，零本次 F 出生写；不得以补名称继续。未装配旧特征概念结构或概念树存在扩展不是本入口的失败依据。
- 输入、C/P、holder、路径、任一独立预算（含出生请求和候选查询/读取请求的组织路径预算为零）、候选查询/候选历史读取、候选歧义、旧无 FC、片段或端口异常：保留具名状态，零本次写。组织路径超出请求上限为`预算不足`；不得借候选/概念预算或默认值继续 owner #3 片段准备。候选数的解释和“复用还是创建”只在 L3；L2 不产生`已复用`或`需选择F`。
- `事实代次漂移`：调用方从新快照重走全流程；`已可能发布`：仅按原五键读回/重试。
- 旧三 owner 创建 DTO、写集、公开成员、构造路径和生产调用须物理删除；旧无 FC 存量只返回`存量未定位/历史材料不可用`，不自动补边。
- FCv 概念确保的纯概念查询、创建、精确重复和读回只使用`FCv概念键`；该键与五把 F 出生键任一相等、预算不足、组织未指定、直接上位组为空但非显式顶层、父不当前、父不严格包含、存在更近中间域或无法证明包含时，停止在 FCv 阶段并零 F 写。不得把特征根、空组或任意一项候选默认成父。
- FCv 父组读取要求新`读取当前I64特征概念`与既有`读取I64类型完整域`以同一 Gread/H 完整成功；前者空组是成功，超预算必须零组失败而非部分结果。任一失败、截止不一致、旧`查找特征概念`/旧`特征概念事实`误用或缓存代替均停止 FCv 创建并零 F 写。
- 新 L3 请求/结果、FCv 确保、原子服务注入与场景成员消费者全部迁移后，物理删除旧`特征概念观察请求`、`特征概念处理状态`、`特征概念处理结果`、旧`指定F`/variant/定位字段、旧`处理类型观察`和两种`收敛类型观察`、旧定位回执/待确认分支、`定位特征数据服务::创建或复用`生产调用及旧 DTO 构造路径。删除前必须确认这些符号的生产和验证声明、定义、调用均为零；任一残留消费者均阻止删除，不保留别名、空函数、双写或旧到新适配壳。v1.2 明确旧验证消费者也属于此门禁：`验证工具/定位特征创建专项验证.cpp`、`验证工具/定位特征创建专项验证.vcxproj`及其运行脚本必须在同一发布中物理删除，并从任何解决方案、工程、筛选器和脚本引用中退出；现工作区中已有的删除 WIP 不是已发布证据，执行者必须以 `ea195241` 的 HEAD 文件为删除起点。
