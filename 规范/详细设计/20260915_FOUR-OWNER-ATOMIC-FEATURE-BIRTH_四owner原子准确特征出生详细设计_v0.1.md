# FOUR-OWNER-ATOMIC-FEATURE-BIRTH 四 owner I64 准确特征出生详细设计 v0.2

状态：待施工设计。修订基线：`9a8e6f444de0f8c1eb479546e560dd670bd7dc03`。

## 1. 目标、依据与收紧边界

本设计仅实现正式 1130 §1、§3.1、§4，4110 §5.1、§8 和 7160 §5.1 所要求能力中的 **I64 阶段**：一个世界新 I64 准确特征 `F` 在同一次 `G0→H` 原子发布中，同时具备完整 I64 内容、真实 holder 的已知引用、`P→F` 组织边，以及到已发布 I64 单值域概念 `FCv` 的使用引用。

`L1有限N分区原子事务_v3` 已支持 2—255 个不同 owner 的同次提交、原组合键重放及向前跨参与者引用。因此本设计不改 L1 ABI、仓库或服务。

这不是对正式规范的收窄：4110 §8 和 7160 §10 仍要求 I64组、U64组及独立材料引用的完整能力。本计划完成后，三者的完整值读回、单值域 FC 编码与规范化、匹配、概念 owner 核验、定位读回、四 owner 出生和专项验证仍未实现，必须保留为后续缺口；不得宣称通用准确 F 已完成。

## 2. 原子边界和职责

一次新 I64 F 出生的唯一原子边界固定为：

```text
1 特征 owner：F 普通节点、F→FT 类型边、完整 I64 值事实
2 存在 owner：真实 holder→F 已知边
3 场景 owner：P→F 组织边
4 概念 owner：F→已发布 I64 单值域 FCv 使用边
```

参与者序号严格为 `1/2/3/4`。存在和场景片段只向前引用 owner #1 的 F 本地键；概念片段向前引用同一 F，并按稳定编码引用已发布 FCv；不允许反向引用。

| owner | 本次只负责 | 明确不负责 |
| --- | --- | --- |
| 特征 | F、FT 和完整 I64 内容的写集及读回 | C/P、holder、FCv 生成或使用边 |
| 存在 | 经场景见证取得的 holder→F | F 内容、位置判断、当前采用、FCv |
| 场景 | C/P、路径、真实 holder 见证及 P→F | F 内容、已知边、FCv |
| 概念 | 已发布 I64 单值域 FCv 的同 FT/生命周期核验及 F→FCv | F 内容、位置、holder、概念出生 |

首次/复用/多候选/位置不一致/存量未定位等业务分类，以及诊断 UI / 日志，均在 `特征概念应用服务` 完成。L2 参与者只核验请求形状、同截止见证与自身写集，不解释为 IF/R 结构异常，也不弹窗或记 UI 日志。

## 3. I64 公开合同

`领域/数据服务.定位特征.h` 删除旧三 owner 的 `定位特征数据服务::创建或复用`、对应 DTO 和一切可创建无 FC F 的符号，改为下列 I64 专用组合服务：

```cpp
struct 原子I64特征出生键 final {
  L1所有者范围写入幂等身份 组合, 内容, 已知, 组织, 概念使用;
};

struct 原子I64特征出生请求 final {
  std::uint32_t 版本 = 1;
  std::uint64_t G0 = 0;
  定位特征位置 位置;                  // C、P
  稳定编码 正式特征类型;
  std::int64_t 准确I64 = 0;
  概念树概念身份 FCv;                  // 已发布 I64 单值域概念
  std::optional<稳定编码> 指定复用F;
  原子I64特征出生键 键;
  定位特征预算 预算;
};

struct 原子I64特征出生事实 final {
  稳定编码 F, 正式特征类型, FCv;
  std::int64_t 准确I64 = 0;
  定位特征位置 位置;
  稳定编码 holder, 已知关系, 组织关系, 概念使用关系;
  std::uint64_t 出生H;
};

enum class 原子I64特征出生状态 : std::uint8_t {
  已创建, 已复用, 精确重复, 入口拒绝, 未找到, 目标已退出,
  位置冲突, 需选择F, 存量未定位, 概念不适配, 事实代次漂移,
  幂等冲突, 预算不足, 历史材料不可用, 资源失败, 内部不一致, 已可能发布
};

struct 原子I64特征出生结果 final {
  std::uint32_t 版本 = 1;
  原子I64特征出生状态 状态;
  std::uint64_t Gread = 0;
  std::optional<std::uint64_t> 首次发布H;
  std::optional<原子I64特征出生事实> 事实;
  std::vector<稳定编码> 候选F;
  原子I64特征出生请求 原请求;
};

struct 原子I64特征出生读取请求 final {
  std::uint32_t 版本 = 1;
  std::uint64_t Gread = 0, H = 0;
  稳定编码 F;
  定位特征预算 预算;
};

struct 原子I64特征出生读取结果 final {
  std::uint32_t 版本 = 1;
  原子I64特征出生状态 状态;
  std::uint64_t Gread = 0, H = 0;
  std::optional<原子I64特征出生事实> 事实;
};

class 原子I64特征出生数据服务 final {
public:
  原子I64特征出生数据服务(原子I64特征内容参与者&, 原子I64特征holder参与者&,
                            原子I64特征组织参与者&, 原子I64特征概念参与者&);
  原子I64特征出生结果 创建或复用(const 原子I64特征出生请求&);
  原子I64特征出生读取结果 读取(const 原子I64特征出生读取请求&) const;
};
```

不得在这些 DTO 或参与接口中保留 `std::variant<std::int64_t, 特征值身份>` 来伪称已支持其它表示。成功结果必须回显四条关系、FCv、完整 I64 和同一 H；`已复用`没有新 H，`已创建/精确重复`的 `H == G0 + 1`。读取在同一 H 核验 F 内容、P 路径、holder 已知边和概念使用边；不得返回半成功。

四个仅友元可调用的参与接口均命名为 `原子I64特征内容/holder/组织/概念参与者`；共同提供同一 L1 绑定核验、owner 端口借用、结构就绪、幂等键可用、同截止只读见证、`准备原子I64出生片段(const 原子I64特征出生请求&, std::uint64_t)` 与首次材料读回。概念参与者在准备片段前必须读回 `FCv` 的 I64 单值域、FT 和当前生命周期；不得创建或改写概念。

## 4. 物理位置、上层前置和控制流

| 文件 | 施工责任 |
| --- | --- |
| `领域/数据服务.特征类.h/.cpp` | owner #1 I64 内容片段、I64 内容候选与读回 |
| `领域/数据服务.存在类.h` | owner #2 holder 已知片段 |
| `领域/数据服务.场景类.h` | owner #3 C/P/holder 见证及组织片段 |
| `领域/数据服务.概念树类.h/.cpp` | owner #4 已发布 I64 单值域 FCv 核验及使用片段 |
| `领域/数据服务.定位特征.h` | 四片段组合、v3 调用、原键重放和完整读回 |
| `业务/应用服务.特征概念类.h/.cpp` | 按 `FT + I64` 确保/读回 I64 单值域 FCv，再调用组合器 |
| `业务/应用服务.场景成员概念类.h/.cpp`、`装配.普通应用.h/.cpp` | 消费者与构造注入迁移 |

L3 的概念前置只复用现有 I64 类型域、I64 域形成和规范化能力；先独立发布并读回 I64 单值域 FCv，再重新取得 G0 并进入四 owner 出生。FCv 已成功而 F 后续失败时，FCv 保留，不回滚也不创建无 FC F。

该私有前置路径固定为：

```cpp
struct I64单值出生概念确保请求 final {
  std::uint32_t 版本 = 1;
  std::uint64_t G0 = 0;
  特征类型身份 FT;
  std::int64_t 准确I64 = 0;
  L1所有者范围写入幂等身份 概念键;
  特征概念预算 预算;
};
enum class I64单值出生概念确保状态 : std::uint8_t {
  已建立, 已复用, 精确重复, 规则缺失, 类型不相容, 入口拒绝,
  事实代次漂移, 幂等冲突, 历史材料不可用, 资源失败, 内部不一致, 已可能发布
};
struct I64单值出生概念确保结果 final {
  I64单值出生概念确保状态 状态;
  std::uint64_t Gread = 0;
  std::optional<std::uint64_t> 首次H;
  std::optional<特征概念事实> FCv;
  I64单值出生概念确保请求 原请求;
};
```

成功必须读回 `FCv.定义.类型 == FT`、其 I64 单点域恰为 `准确I64`且当前有效。概念确保和 F 出生使用不同幂等键；`已可能发布`只按原概念键收敛。

控制流固定为：

```text
L3 核验 C/P、I64 FT、I64 完整值、预算与五个不同键
→ 确保并读回 I64 单值域 FCv
→ 重新取得 G0；查询同位置同 FT 同 I64 的 F 候选
→ 0 个候选：准备四 owner 片段并同次提交
→ 1 个候选：完整读回 C/P、holder、FT、I64 和唯一 FCv 使用
→ 多候选：需选择F，零写
→ 提交/重放：按原键、同一 H 读回四 owner 事实
```

首次材料必须五者全无；已存在时五者须同 H 且与原请求逐项相同，否则 `幂等冲突`。提交后或读回中断只允许用原五键收敛，绝不换键重建。

## 5. 非成功、迁移与明确排除

- FCv 缺失、错 FT、已退出或读回失败：不进入提交，零 F/关系写。
- 输入、C/P、holder、路径、预算、候选歧义、旧无 FC、片段或端口异常：保留具名状态，零本次写。
- `事实代次漂移`：调用方从新快照重走全流程；`已可能发布`：仅按原五键读回/重试。
- 旧三 owner 创建 DTO、写集、公开成员、构造路径和生产调用须物理删除；旧无 FC 存量只返回`存量未定位/历史材料不可用`，不自动补边。
- 不实现 I64组、U64组或独立材料的 F / FCv 出生；不新增“通用 variant”兼容壳、默认拒绝映射或虚假成功读回。
- 不改 L1、IF/R 六关系、当前采用、F 原地值、概念汇聚、线程、启动或阶段21。
