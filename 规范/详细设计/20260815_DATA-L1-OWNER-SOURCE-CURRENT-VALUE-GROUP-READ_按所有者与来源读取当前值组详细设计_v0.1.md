# 按所有者与来源读取当前值组详细设计 v0.1

日期：2026-08-15

设计身份：`DATA-L1-OWNER-SOURCE-CURRENT-VALUE-GROUP-READ`

状态：设计就绪；不等于代码已实现

## 1. 目标与缺口

为 `DATA-L1` 增加一个业务中性的原子读取能力：调用方给出一个已知结构 owner、一个来源节点、非零事实代次守卫和非零数量预算，读取该 owner 下全部以该节点为 `来源节点` 的当前值事实。

现行仓库已经维护 `当前节点引用索引`，值事实的所属节点、属性类型、来源节点和独立材料引用都会进入该索引；该索引目前只服务退出引用保护，没有公开的来源角色反向读取入口。L2 若自行扫描全部状态、动态或因果节点，既无法保证同截止，也违反 4015 普通 CRUD 不执行全仓扫描的合同。具名缺口为：

`DRIFT-DATA-L1-SOURCE-CURRENT-VALUE-REVERSE-READ-MISSING`

## 2. 边界

本设计只冻结 L1 中性值发现，不建立状态、动态、因果或其它领域查询，不增加第二仓库、第二 owner、缓存、通用节点引用枚举、分页游标或零守卫最新读取。

当前值组必须来自一次共享锁和一个事实截止。空组是成功；超出预算必须拒绝整组，不能返回前 N 项。L2 消费者仍须按自己的属性类型、关系、基数、生命周期和完整读取合同验证所属节点，不能把值命中直接解释为领域对象。

## 4. 状态与载荷

| 条件 | 状态 | 读取代次 | 当前值组 |
| --- | --- | --- | --- |
| 错合同、零 owner、零来源、零守卫或零预算 | 入口拒绝 | 0 | 空 |
| owner 或来源从未存在 | 未找到 | 锁内当前代次 | 空 |
| owner 或来源已经退出 | 已退出 | 锁内当前代次 | 空 |
| 守卫不等于锁内当前代次 | 事实代次漂移 | 锁内当前代次 | 空 |
| 匹配数超过预算 | 数量预算不足 | 锁内当前代次 | 空 |
| owner 与来源当前且匹配数为 0—预算 | 成功 | 等于守卫 | 严格升序完整组 |
| 分配或长度耗尽 | 资源失败 | 安全取得则保留，否则 0 | 空 |
| 隔离、索引或事实互证失败 | 内部不一致 | 安全取得则保留，否则 0 | 空 |

owner 与来源存在性在守卫比较之后解释，保证陈旧调用统一得到事实代次漂移，不泄漏另一截止的对象状态。成功组中每项必须当前、owner 相同、来源相同、编码非零且严格升序；任何非成功结果不得夹带部分组。

## 5. 仓库过程

1. 纯值校验失败直接入口拒绝，不加锁。
2. 取得一次 shared lock，记录锁内事实代次；隔离或全局状态不完整返回内部不一致。
3. 比较非零守卫；不等返回漂移。
4. 验证请求 owner 与来源节点当前；历史存在分别映射已退出，否则未找到。
5. 从 `当前节点引用索引[来源节点]` 读取已排序候选编码；逐项只接受当前值表中 `写入所有者==owner && 来源节点==请求来源` 的值事实。关系、所属节点角色、属性类型角色和独立材料引用角色仅作为索引中的其它合法候选跳过。
6. 匹配数超过预算立即清空并返回数量预算不足；否则转换为 owner-scoped 公共值事实并返回成功。
7. 现有 `状态完整` 必须继续证明索引由全部当前关系和值确定派生；本入口不维护第二索引。

## 6. 验证与完成边界

生产外临时检查至少覆盖：坏请求、空组、单 owner 多来源、同来源跨 owner 隔离、有序多值、精确预算、超预算零载荷、陈旧守卫、owner / 来源未找到与已退出、读前后事实代次不推进，以及既有当前 / 历史 / 一致读取不回归。资源耗尽、私有索引损坏和跨进程恢复没有稳定公开注入时记 `NOT_RUN`，不得增加生产 seam。

结果只证明该 L1 原子来源读取 provider。它不证明 `DATA-EXT-04—06` 的来源查询已实现；后继状态、动态、因果必须各自建立强类型查询叶并通过完整读回。
