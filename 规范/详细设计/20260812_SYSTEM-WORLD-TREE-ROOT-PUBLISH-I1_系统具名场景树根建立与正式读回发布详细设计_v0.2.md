纵向追溯固定为：


## 5. 普通应用状态与同实例

普通应用模块的全局模块片段只包含 `<cstdint>`、`<memory>`、`<mutex>`、`<optional>` 等标准库头，不包含 I1 或 R1 项目头。进入 `export module 海中鱼巣.装配.普通应用;` 的 module purview 并完成 R1 / A1 import 后，再以 module-attached 文本包含导出 I1 DTO：

```cpp
export {
#include "业务/系统世界树根初始化.数据.h"
}
```

I1 数据头只定义 DTO，不自行包含标准库或 R1 数据头，也不声明根函数；包含方必须先提供标准库与已 import 的 R1 类型。普通应用主接口随后在 `普通应用上下文` 定义之前前置声明该类并导出根函数声明；新普通 `.cpp` 以 `module 海中鱼巣.装配.普通应用;` 进入同 named module，直接定义该已导出函数并取得精确 friend 权限。不得建立独立 I1 模块、import 普通应用模块或使用分区，因此不存在主接口反向依赖、跨模块 friend 或模块环。

不得临时改成 public setter、暴露锁 / optional 引用或另建第二状态对象。getter 不标记 `noexcept`，不返回内部引用、服务、owner、端口或锁。I1 必须经 `上下文.取得L2结构聚合服务().取得L2场景结构服务()` 取得与普通应用直接场景 getter 同址的 R1；A1 和上下文不复制服务，也不解释根结果。上下文析构只销毁过程槽和值式副本，不退出 R1 根事实。

## 6. 首次、收敛与重复流程

1. 合同版本不等于 I1 当前版本，或根建立幂等身份不等于 I1 唯一固定身份时，写前返回 `请求无效`；不得复制 R1 私有保留身份做上层校验。
2. 已发布值存在时，同选择进入重复消费，异选择在 R1 调用前返回冲突。
3. 尚未发布且无待收敛请求时，先调用最终 R1 当前树结构登记读取能力，以真实成功截止形成完整根建立请求；完整请求先保存到待收敛槽，再调用根建立。
4. 已有待收敛请求时，同选择逐字段原样重放；异选择冲突。不得因当前代次变化重写一个可能已经提交的请求。
5. 根建立只接受最终 R1 定义的首次提交或同完整请求精确重复成功形状。明确证明零变化且无首次结果的事实代次漂移可以清除待收敛槽并在下次以同键重组；资源失败、未知发布和提交后读回失败必须保留原请求。
6. 根建立成功后再次读取当前树结构登记，以其正式截止形成整树当前读取请求；不得从首次登记、缓存或根返回猜测当前截止。
7. 正式整树结果必须互证树身份等于根编码、根在场景组、根标记端点 / 类别 / 首次生命周期一致、根无父、截止非零、嵌套投影完整且稳定排序。
8. 局部完整形成结果后以不抛出交换发布，并清空待收敛槽。交换前异常保留既有发布值和原待收敛请求。
9. 已发布同请求重复时根写调用为零，但必须再次读取当前登记和整树；成功返回 `精确重复 / 已发布重复消费` 并刷新值式副本。

## 7. 失败、幂等、并发与后继启动消费

I1 的锁只保护同一上下文的请求选择、收敛请求和值式副本，不参与 R1 事实裁决。同请求并发串行；异请求不建立第二根。`std::bad_alloc` 映射资源失败，其它异常映射内部不一致。任何失败都不清空或半更新既有发布值；R1 已发布根不得由 I1 撤销、换键或重建。

本叶不修改 `运行普通程序` 或 `程序运行结果.数据.h`。I1 提供者结果接受并退出后，计划智能体必须从最新正式基线重做 I2 设计与计划绑定并发布替代版本；只有该替代计划才能统一完成下列连续启动接线：

- I1 失败返回 `初始化失败 / 现实世界树根初始化 = 14`；
- I1 成功把同一次 `已发布根` 结果交给 I2；
- 本叶不新增、恢复或返回阶段 15；
- 阶段 16 / 17 / 18 由各自后继实现和验证。
