# ARCH-FIVE-LAYER-FOUNDATION 全局五层架构映射与 L2 虚拟存在、状态、动态唯一权威详细设计

版本：v0.3
状态：替代设计候选，未取得代码实施许可
基线：`main@21281ea14132d52163f52681ffc4fbb98cb42ff2`
计划身份：`ARCH-FIVE-LAYER-FOUNDATION`

## 1. 目标与边界

本版本只修订执行退回的“参与者写集 ABI”缺口。ARCH-L2 仍只有一份通用状态权威和一份通用动态权威；状态 owner 与动态 owner 保持不同，二者通过一个 L1 中性双参与者事务完成一次事实发布。通用虚拟存在返回 `L2存在身份`，动态主体固定消费该身份；动态前/后端点固定为 `L2状态身份` 或事务内明确的状态参与者局部引用。owner 是写权限范围，节点只是中性身份/存在锚点；节点可以作为结构代表，但节点编码、局部键和代表节点都不等于 owner。

`想`/`看`、安全硬否决、活动资格、调度配额、自我现实执行授权、任务轮次结算及轮次后继决议仍是 ARCH-L4 上游边界。本 provider 只消费已裁决的结构请求，不签发或推导授权，不自动续作，不建立第二状态/动态权威，不让 L3/L4/L5 直写 L1。

## 2. 21281ea1 后的当前 WIP 事实与 v0.2 缺口

执行侧 WIP 已加入：

- `L1所有者范围CRUD.数据.h` 的 `L1跨所有者原子事务*` 类型、状态/动态参与者序号和幂等账；
- `仓库.L1事实基座.ixx` / `服务.L1事实基座.ixx` 的组合提交骨架；
- 状态/动态服务的 `取得组合发布写入端口()`；
- 通用虚拟存在 DTO/服务、组合 provider DTO/服务、装配和工程登记。

但当前 WIP 仍不能作为 v0.2 合同：

1. 状态/动态服务没有“形成参与者写集”的可消费函数，组合 provider 只能返回 `内部不一致`；
2. `L1跨所有者原子参与者写集` 仍把 `跨参与者引用` 放在无位置的独立列表，仓库对非空列表直接返回 `引用冲突`，无法表达动态后状态关系指向本次新状态；
3. 没有冻结参与者输入、局部键表、owner 绑定、幂等派生、失败返回和编码映射；
4. 没有冻结发布后的五组正式读回及旧状态退出/新状态当前/动态前后关系断言。

因此 v0.2 退出，v0.3 只补齐上述合同，不改变 ARCH-L2 机器目标。

### 2.1 基础数据层口径（参与者 ABI 的共同前提）

- owner 可先由 4015 签发器建立并取得端口，代表节点随后由结构写入创建；二者不要求原子建立。最小空结构允许只有代表节点，代表节点语义由对应 L2 结构设计解释，不扩张 L1 owner DTO。
- 节点引用节点统一编码为关系；标量、文本和材料统一编码为属性槽和值。参与者局部键只定位本次候选中的事实，绝不提升为 owner 或稳定身份。
- `内部`、`向外`、`外来` 不进入节点、关系或值的新增字段。对 owner O 的观察按源节点 owner 与目标节点 owner 推导；同一跨 owner 关系从两端 owner 观察可不同，禁止固化为关系属性。
- 父/子只由关系方向决定，兄弟由共享父推导，L1 不裁决单父/多父。成环只按稳定节点编码判断，不按节点类型重复判环；没有真实证据时不增加祖先回连或错误删除机制。
- 不新增全 owner 扫描、递归图读取或内外分类入口；组合 provider 只复用现有 owner-aware 节点读取及源/目标关系组读取，由上层组合。已满足 L2 的 L1 对外服务保持稳定，纯内部能力不得无故公开。

上述约束同时禁止通过局部键或跨参与者引用把 owner 等同节点、固化内外分类或偷偷引入通用图扫描。

## 3. 状态参与者形成 ABI

DTO 物理位置：`海中鱼巣/领域/L2状态结构.数据.h`；声明/定义：`海中鱼巣/领域/服务.L2状态结构.ixx`。新增唯一 owner-only（组合 provider 可调用、普通调用方不可调用）函数：

```cpp
L2状态原子参与者形成结果 L2状态结构服务::形成状态原子参与者写集(
    const L2状态原子参与者请求& 请求) const noexcept;
```

`L2状态原子参与者请求` 字段顺序固定为：

```cpp
std::uint32_t 合同版本 = 1;
std::uint64_t 共同期望事实代次;                 // 非零 G0
L1所有者范围写入幂等身份 组合写入幂等身份;      // 由组合入口固定域产生
L2存在身份 主体存在;
L2状态身份 旧当前状态;
L2特征实例身份 新状态特征实例;
L2原始值材料 新状态精确值材料;
L2原始值材料 新状态时间值材料;
稳定编码 来源方法稳定编码;
```

形成函数只读当前状态和结构登记，验证 `G0`、主体来源、旧状态当前性、旧状态完整自有闭包、特征实例来源、值材料类型、来源稳定编码和旧状态未被退出；它不提交、不推进代次、不改变幂等账。新状态写集必须包含：新状态节点、族归属、主体关系、特征实例关系、精确值、时间值，以及旧状态节点/族归属/主体关系/特征关系/两值的同 owner 退出闭包。

返回 `L2状态原子参与者形成结果`：

```cpp
L2结构状态 状态;                 // 已读取=材料已形成；其余为结构化失败
std::uint64_t 共同期望事实代次;    // 成功时等于 G0，失败为观察截止或 0
std::optional<L1跨所有者原子参与者写集> 参与者;
L2状态原子参与者局部键 局部键;
std::optional<L2状态自有关系退出投影> 旧状态退出闭包;
```

局部键命名空间固定为 `状态` 参与者：节点 `0x02041001`、族归属 `0x02042003`、主体关系 `0x02041101`、特征关系 `0x02041102`、精确值 `0x02041201`、时间值 `0x02041202`。返回的参与者必须绑定状态服务私有 owner，参与者序号固定为 `状态=1`；这些局部键只定位写集事实，不是 owner、代表节点或稳定编码。组合写入幂等身份由本请求派生，不接受调用方另传 owner 或另一写入幂等键。

## 4. 动态参与者形成 ABI

DTO 物理位置：`海中鱼巣/领域/L2动态结构.数据.h`；声明/定义：`海中鱼巣/领域/服务.L2动态结构.ixx`。新增唯一函数：

```cpp
L2动态原子参与者形成结果 L2动态结构服务::形成动态原子参与者写集(
    const L2动态原子参与者请求& 请求) const noexcept;
```

字段顺序固定为：

```cpp
std::uint32_t 合同版本 = 1;
std::uint64_t 共同期望事实代次;                 // 与状态参与者同一 G0
L1所有者范围写入幂等身份 组合写入幂等身份;
L2存在身份 主体存在;
L2特征实例身份 变化特征实例;                   // 仅作与状态参与者互证
L2状态身份 前状态;
L2状态身份 后状态;                              // 已发布旧身份或事务内跨 owner 引用
L1跨所有者原子事实引用 后状态局部引用;         // 二者恰一，禁止猜测
稳定编码 来源方法稳定编码;
L2原始值材料 起始时间材料;
L2原始值材料 结束时间材料;
```

`后状态` 与 `后状态局部引用` 恰一：本次迁移使用局部引用，普通动态新增使用已发布 `L2状态身份`；不得两者同时有效或都为空。形成函数验证主体来源、前状态来源、共同 G0、时间值材料、来源稳定编码、局部引用参与者必须为 `状态=1` 且局部键必须等于状态参与者的新状态节点键。它不读取尚未发布的新状态，不提交，不推进代次。

返回 `L2动态原子参与者形成结果`：状态/截止、绑定动态 owner 的参与者、局部键表和必要的前置来源读回。动态参与者序号固定为 `动态=2`。局部键固定为：动态节点 `0x02051001`、族归属 `0x02052002`、主体关系 `0x02051101`、前状态关系 `0x02051102`、后状态关系 `0x02051103`、起始值 `0x02051201`、结束值 `0x02051202`。动态节点局部键不是动态 owner，也不是通用虚拟存在的替代身份。

## 5. L1 参与者写集和跨 owner 引用合同

`L1跨所有者原子参与者写集` 的 owner、参与者序号、合同版本、写集幂等身份必须由形成函数填充并由事务凭证再次核对。v0.3 删除当前 WIP 中无位置的 `vector<跨参与者引用>` 语义，改为在参与者关系/值/属性槽事实引用字段内使用：

```cpp
using L1跨所有者原子事实引用值 = std::variant<
    稳定编码,
    L1所有者范围写集本地键,
    L1跨所有者原子事实引用>;
```

该类型只存在于 `L1跨所有者原子写集` 的事务 DTO；普通 `L1所有者范围写集请求` 永远拒绝跨 owner 引用。动态后状态关系的目标字段必须携带 `{参与者=状态, 本地键=0x02041001}`，其它动态关系和值只能使用自身节点局部键或已发布稳定编码。引用只能出现在关系端点、值材料或属性槽事实引用字段中，不能新增关系属性来表示 owner 视角。任何未声明位置、未知参与者、重复局部键、跨第三参与者、把未发布局部键用于退出项或把局部键泄漏为稳定身份，均为 `引用冲突`，零写。

L1 事务凭证只接受状态/动态两个绑定 owner，固定锁内顺序为：验证凭证与 owner → 验证共同 G0/组合幂等 → 校验两参与者写集和跨引用 → 在候选副本中同时应用两个写集 → 将所有新建/退出事实归一到唯一 `G1` → 单次交换发布。禁止向真实状态先提交、再向动态提交，禁止通过事后修正两个可见代次模拟原子。

## 6. 组合 provider 合并、幂等和结果

`L2状态动态原子发布服务::发布状态动态原子迁移` 的固定顺序为：

1. 验证请求合同、组合幂等域 `0xA2C0'0201`、所有公开字段和非零共同 G0；
2. 以同一 G0 构造状态参与者请求；失败立即返回，不能构造动态或提交；
3. 以状态局部键构造动态参与者请求；失败立即返回；
4. 调用 L1 双参与者凭证恰一次提交；任何非成功返回五组空载荷；
5. 从 `状态编码映射[状态节点局部键]` 和 `动态编码映射[动态节点局部键]` 取得正式身份；映射缺失、重复或 owner 错误为内部不一致；
6. 以唯一 G1 做正式读回并形成结果。

同一组合幂等身份与全部公开请求字段相同返回首次结果且不推进代次；任一字段不同为幂等冲突。许可拒绝、入口拒绝、事实代次漂移、引用冲突、资源失败、未找到、已退出和内部不一致均五组 `nullopt`、零载荷、零变化。发布未知只用同一组合幂等身份读首次材料收敛，不重建身份、不拆分提交、不重试猜测。

## 7. G1 五组正式读回与断言

发布成功得到 `G1` 后，provider 必须只经公开服务完成以下读回：

1. `状态服务.读取完整状态(新状态身份, 当前, G1)`：成功、截止 `G1`、主体等于请求主体、特征等于请求特征、值/来源与请求相同、生命周期当前；
2. `状态服务.读取状态自有关系(新状态身份, 当前, G1)`：族归属、主体和特征关系各一且同截止；
3. `动态服务.读取完整动态(动态身份, 当前, G1)`：成功、截止 `G1`、主体等于请求主体、前状态等于旧状态、后状态等于新状态、来源和时间材料相同；
4. `动态服务.读取动态自有关系(动态身份, 当前, G1)`：族归属、主体、前状态、后状态关系各一且同截止；
5. `状态服务.读取完整状态(旧状态, 历史, G1)` 与当前入口：历史保留完整，当前入口明确 `已退出`；旧状态退出关系闭包逐项存在，不能被新状态关系替代。

五组结果头的事实截止必须全部等于 G1；任一混代、身份复义、旧状态仍当前、新状态非唯一当前、动态前后关系不一致、主体来源变化或载荷缺项，统一 `内部不一致`，停止依赖路径，不修改已发布事实。日志只供人观察，不参与上述断言。
