# 当前 WIP 编译恢复详细设计

身份：`CURRENT-WIP-COMPILE-RECOVERY`
版本：v0.4
日期：2026-09-04
状态：compile-only 可施工设计；替代并永久停止 v0.1—v0.3 的施工许可。

## 1. 用户裁决与完成边界

本修订唯一目标是令当前 canonical 工程的 `Debug|x64`、`Release|x64` 均完成编译。
用户明确授权：物理删除 `海中鱼巣/装配.普通应用.ixx`，删除其所有调用；不能删除而
又为编译所必需的入口可改成最小零副作用空壳。

本计划不保证启动、装配、线程、事实写入、真实自我形成、筹办或任何业务逻辑可运行。空壳
不得返回成功或写入机器事实。此前的 ABI 等价、生命周期与业务闭环要求不再是本次编译
施工门禁，但正式规范不因此改变。

`服务.需求初次筹办准备.ixx`、`任务初次筹办.数据.h` 及九个 E2E canonical 源保持物理
删除，禁止恢复；根目录未跟踪副本不是来源、不得加入工程。

## 2. 已核对事实与裁决

1. `海中鱼巣.装配.普通应用` 的仅有 direct importers 为
   `启动.应用程序.ixx`、`业务/提供者.真实自我形成.ixx` 与
   `线程/创建.自我线程.ixx`。启动模块还直接调用普通应用上下文、系统根初始化和根消费。
2. `自我世界树根消费材料` 的实体定义在
   `海中鱼巣/业务/自我世界树根消费.数据.h`，但当前只由普通应用 module export；
   它又是 `真实自我形成请求` 和 `自我线程生产创建请求` 的值成员。这正是“根消费材料未知
   重写说明符”、`截止` 未声明和 `optional::emplace` 级联的唯一可见性根因。
3. 当前 `真实自我形成提供者` 只有一个外部构造器
   `真实自我形成提供者(L2结构聚合服务&) noexcept` 和一个公开动作
   `真实自我形成结果 形成(const 真实自我形成请求&) noexcept`；它没有其它合法消费者。
4. `启动.应用程序.ixx` 是 `创建.自我线程`、真实自我提供者、四本体根、方法根、本能根、
   安全根和任务运行包的唯一 direct consumer。删除普通模式的整段调用链不会令这些模块失去
   自身工程编译资格。
5. `L2任务结构服务::提交任务子目标回流后继筹办准备` 的 current WIP 正文在 try、三个
   catch 分支中均 return；若 MSVC 在该函数仍报 C4715，只能在 catch 链之后追加同签名的
   `return 失败(L2结构状态::内部不一致);`，不得改 DTO、写集、调用者或成功结果。

## 3. 最终物理边界与接口合同

### 3.1 删除的普通应用 module

物理删除 `海中鱼巣/装配.普通应用.ixx`，并从 `海中鱼巣.vcxproj` 与
`海中鱼巣.vcxproj.filters` 各删除其唯一 `ClCompile` 条目。工程及 filters 中不得剩下
`海中鱼巣.装配.普通应用`、`装配.普通应用.ixx` 或根目录同名副本登记。

### 3.2 根消费材料的独立归属

新建 `海中鱼巣/业务/合同.自我世界树根消费.ixx`，唯一导出 module
`海中鱼巣.业务.合同.自我世界树根消费`，并只在 export 区包含既有
`自我世界树根消费.数据.h`。它不定义函数、不保存状态、不进行写入。

工程与 filters 各新增该文件的一条 `ClCompile`。下列两处在其 `export { #include ... }`
之前 import 该合同模块：

- `海中鱼巣/业务/提供者.真实自我形成.ixx`；
- `海中鱼巣/线程/创建.自我线程.ixx`。

这两个 DTO 的字段、默认值、版本及类型保持原样；只是从独立业务合同而非已删除的装配模块
获得可见性。

### 3.3 真实自我 provider 的 compile-only 空壳

`海中鱼巣/业务/提供者.真实自我形成.ixx` 保留以下 ABI，且只保留这些公开成员：

```cpp
真实自我形成提供者(L2结构聚合服务&) noexcept;
真实自我形成结果 形成(const 真实自我形成请求&) noexcept;
```

`形成` 的函数体忽略请求和保存的聚合服务引用，返回
`{真实自我形成状态::请求无效}`；不设置 `已形成自我`，不写 L2/L1，不调用其它 provider。
`真实自我形成结果::成功()` 的现有定义保留。因此该空壳永不报告成功。

### 3.4 启动与自我线程链

`海中鱼巣/启动.应用程序.ixx` 删除普通应用 import、`形成中性实例材料维护回调` 及
`运行普通程序` 中从生产配置直至运行包收口的全部装配/初始化/自我线程调用。保留
`程序运行结果 运行普通程序(启动模式)` 签名，函数体唯一返回：

```cpp
{模式, 程序运行状态::初始化失败, 程序失败阶段::普通应用装配}
```

这是显式不可用结果，不是成功或空运行。同步删除因此只被该函数使用的 imports；保留
`启动.程序运行宿主` 及生产运行期函数需要的 imports。

`海中鱼巣/线程/创建.自我线程.ixx` 不改请求 DTO、创建函数、队列或线程逻辑，仅以
§3.2 contract import 替换普通应用 import。`
海中鱼巣/线程/自我线程生产创建.数据.h` 不改；它经创建 module 的 export 获得字段类型。

### 3.5 已删旧筹办与其他编译错误

继续保持并核对：任务管理线程和运行包对
`海中鱼巣.领域.内部治理.服务.需求初次筹办准备`、`需求初次筹办准备提供者` 与
`需求初次筹办准备结果` 为零引用。不得为这些名称建立兼容空壳。

`L2任务结构服务::提交任务子目标回流后继筹办准备` 只允许 §2(5) 的不可达兜底 return；若
当前编译诊断不再指出 C4715，该文件为零变更。其它首次编译错误仅可在其现有函数中删掉已
删除模块的 import/直接调用，或以现存返回 DTO 返回非成功、零副作用值；需要新业务字段、
成功态、事实写入、工程外源或变更公开签名时停止并重新退回计划支撑。
