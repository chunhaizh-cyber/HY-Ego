# INSTINCT-STAGE3-HARD-DENIAL-RULE-UNIVERSE 任务现实执行硬否决规则宇宙详细设计 v0.2

日期：2026-08-31

本版完整继承 v0.1 的规则宇宙、版本发布、Gnow 全集读取、覆盖见证、hard-veto v2 和完成声明；只修订“正式 HEAD 已具备任务冻结动作 ABI”的错误当前事实，并冻结最小前置 ABI 的物理落点。与本节冲突时以本版为准。

## 1. 执行退回事实与裁决

正式 `main@dd815b62de25842e1d7ccb788a2cd0ee1aa2dfd6` 中尚无：

```text
L2方法动作作用范围
L2任务轮次身份
L2任务执行轮次身份
L2任务执行冻结身份
任务动作作用范围
任务冻结动作项
```

这些名字只存在于未发布 SELF-GOVERNANCE WIP。若仅提交 v0.1 的安全文件，正式提交树会在安全数据头和专项处因类型未声明而失败。因此 v0.1 第 2 节“L2任务冻结公开 ABI 已足够”和第 8 节“禁止修改任务 owner”不成立。

本切片实际只需要冻结材料的跨 owner 值类型，不需要先实现方法动作 v2 发布服务、任务筹办冻结写入、当前选择或 FRESH。裁决为：

```text
方法 owner 数据头发布动作作用范围枚举
-> 任务 owner 数据头发布轮次 / 执行 / 冻结强类型身份
-> 任务 owner 数据头发布冻结动作值类型并直接复用方法枚举
-> 安全 owner 只读消费该值类型
```

禁止在安全治理目录建立局部枚举、兼容 typedef、测试专属身份或第二份冻结动作 DTO。

## 2. 最小 ABI

### 2.1 方法 owner

物理位置：

```text
海中鱼巣/领域/L2普通方法结构.数据.h
```

在既有 `L2方法动作入口事实` 后增加：

```cpp
enum class L2方法动作作用范围 : std::uint8_t {
    内部治理 = 1,
    纯现实观察 = 2,
    现实改变 = 3
};
```

该枚举是方法动作作用范围的唯一强类型。数值是稳定 ABI；后继方法动作 v2 必须直接复用，不能重新定义同义枚举。

本切片不增加 `L2方法动作入口事实_v2`、写入 / 读取请求、服务入口、持久键或方法事实。旧方法事实也不被推断为具备该作用范围。

### 2.2 任务 owner

物理位置：

```text
海中鱼巣/领域/L2任务结构.数据.h
```

在既有任务强类型身份组内增加：

```cpp
L2任务轮次身份
L2任务执行轮次身份
L2任务执行冻结身份
```

三者继续使用既有任务身份宏的 `{稳定编码 值}` 布局、显式构造和默认相等性；普通整数和其它身份不得互换。

在任务来源需求关系事实前增加：

```cpp
using 任务动作作用范围 = L2方法动作作用范围;

struct 任务冻结动作项 final {
    std::uint64_t 顺序 = 0;
    L2方法动作入口身份 动作入口;
    L2方法稳定动作键 稳定动作键;
    任务动作作用范围 作用范围 = 任务动作作用范围::内部治理;
    L2存在身份 作用主体;
    std::optional<L2场景身份> 作用场景;
    稳定编码 动作范围材料;
    稳定编码 预期结果材料;
    稳定编码 结果验证合同;
    稳定编码 动作归因合同;
    friend bool operator==(const 任务冻结动作项&,
        const 任务冻结动作项&) = default;
};
```

字段顺序是 ABI。任务别名必须与方法枚举同型，不得复制枚举值。`作用场景`是 5230 v1.6 的共同场景约束；它不是对象角色、场景列表或 self 当前位置。

该 DTO 只定义冻结材料的值式形状。任务筹办 / 冻结服务仍是唯一生产方；本切片不建立冻结事实、不从旧方法入口补造字段、不声称生产冻结链已完成。专项可以显式构造 fixture，但 fixture 不取得生产权威。

## 3. 安全 owner 消费边界

安全规则 owner 与 hard-veto v2 可以：

1. 检查 `完整有序冻结动作范围` 的顺序、身份、作用范围、主体、共同场景和非零材料；
2. 只提取 `现实改变` 子集做场景 / 成员 / 规则范围互证；
3. 对零现实改变返回 hard-veto 不适用；
4. 在专项中构造完整 fixture 验证规则宇宙机制。

安全模块不得：

- 发布或修改任务冻结；
- 把旧方法输入 / 输出场景推断为共同作用场景；
- 从方法 v1 补造作用主体、动作范围或三项结果合同；
- 把 ABI 存在声明为方法 v2 或任务冻结生产能力已经完成。

## 4. 修订后的实施白名单

在 v0.1 白名单基础上仅增加：

```text
海中鱼巣/领域/L2普通方法结构.数据.h
海中鱼巣/领域/L2任务结构.数据.h
```

两个混合 WIP 文件只允许发布第 2 节精确 ABI hunk。禁止带入其余 SELF-GOVERNANCE 增量；仍禁止修改方法 / 任务服务、筹办冻结服务、普通应用、线程、FRESH、L1、状态动态、场景 owner 和 L/H。

## 5. 验证增量

除 v0.1 矩阵外必须增加：

1. 从正式 HEAD 物化的隔离树只叠加两个 ABI hunk、四个安全文件、专项和工程登记，Debug / Release 编译阶段不得再依赖其它 SELF WIP；
2. 外部 ABI consumer 静态断言三类任务身份互异，`任务动作作用范围`与`L2方法动作作用范围`同型，三个枚举值分别为 `1/2/3`；
3. `任务冻结动作项`逐字段相等性覆盖可选场景有 / 无及任一字段差异；
4. 全仓扫描禁止安全目录定义第二份动作作用范围或冻结动作项；
5. 当前值域、L、H、安全根定义版本 1、主动安全结算规则版本 1 保持不变。

隔离 Debug 已验证两个最小 ABI hunk能够消除 v0.1 的类型未声明错误并完成全部 C++ 编译；随后出现的正式 HEAD 既有装配链接符号缺失不属于本次 ABI，也不能被误报为本计划代码错误。正式完成仍须按计划对本切片执行独立模块 / 专项和两配置验证。

## 6. 完成边界

本版仍只允许声明规则 owner 与 hard-veto v2 的独立服务闭环。新增 ABI 只证明后续任务冻结材料有唯一共享类型，不证明方法动作 v2 服务、任务冻结 producer、FRESH、普通应用或生产安全闭环完成。
