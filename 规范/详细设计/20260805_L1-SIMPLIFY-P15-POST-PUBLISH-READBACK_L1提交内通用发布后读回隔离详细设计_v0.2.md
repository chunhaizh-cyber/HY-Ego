## 1. 目标和唯一裁决

本叶原位扩展唯一新 `L1事实基座`。每笔普通写在访问可变 provider 后材料并进入首次提交前，必须携带两份固定32字节摘要：

- `请求意图摘要`：只编码公开业务请求，唯一裁决同键同义/异义；
- `执行证据摘要`：只编码首次 provider 解析、共同截止、确定性写集和读回计划，供首次执行、审计和恢复互证。

L1 把两摘要视为版本化、不透明、非全零的确定值，不解释领域字段。同键同意图必须在 provider 解析前通过纯值探测返回首次完整结果；不得比较后来执行证据或写集，不得重算、推进代次或访问 SQL。同键异意图固定冲突。

首次提交仍固定：候选完整校验 -> 双摘要/幂等/审计和读回预期进入候选 -> `swap` 一次推进业务代次 -> 同一独占锁内按通用计划从权威状态读回 -> 成功后返回；矛盾则保留发布代次和首次幂等记录、形成失败见证并单调隔离。

本叶不建立旁路幂等账、第二提交入口、领域回调、关系19/20解释、SQL运行期裁决或 P16 事实。

## 2. 正式依据和当前差异

- 4200 §7.6：请求意图/执行证据分账；同意图重试不得因 provider 变化重算；内存幂等记录保存两摘要、首次代次、通用读回和确定性结果摘要。
- 4200 §7.7、4015、4040、4070：发布后同锁权威读回、失败见证、隔离、审计和恢复互证。
- 当前正式 L1：`L1写集请求` 只有合同版本、期望代次、幂等键和写集；`L1幂等账记录` 只有幂等键、规范化写集和首次结果；同义按规范化写集全等裁决；公开服务只有审计读取。
- P15 v0.1：已冻结 L1 合同 v2 非空读回计划及隔离，但未冻结双摘要和 provider 前探测。

因此不存在可以复用的正式方案 B；v0.2 必须原位补齐同一 L1 合同和同一幂等账。

## 4. 双摘要 DTO 和完整性

在 `L1事实基座.数据.h` 定义：

```cpp
inline constexpr std::uint32_t L1幂等摘要合同版本 = 1;
inline constexpr std::uint32_t L1确定性结果摘要版本 = 1;

struct L1确定性摘要 final {
    std::array<std::uint8_t, 32> 字节{};
    friend bool operator==(const L1确定性摘要&, const L1确定性摘要&) = default;
};

inline bool 完整(const L1确定性摘要& 摘要) noexcept {
    return std::any_of(摘要.字节.begin(), 摘要.字节.end(),
        [](std::uint8_t 字节) noexcept { return 字节 != 0; });
}
```

两摘要都是标准 SHA-256 的32字节原始输出，不是十六进制字符串。全零拒绝；SHA-256 的合法输出理论上可能全零，但本合同用全零保留为“未提供”，故领域编码必须在极端全零结果时返回内部不一致，不得改写摘要值。

`L1写集请求` 在合同版本2中完整定义为：

```cpp
struct L1写集请求 final {
    std::uint32_t 合同版本 = L1事实基座合同版本;
    std::uint32_t 摘要合同版本 = L1幂等摘要合同版本;
    std::uint64_t 期望事实代次 = 0;
    写集幂等键 幂等键;
    L1确定性摘要 请求意图摘要;
    L1确定性摘要 执行证据摘要;
    L1通用发布后读回计划 发布后读回计划;
    std::vector<L1新节点请求> 新节点;
    std::vector<L1新关系请求> 新关系;
    std::vector<L1新值请求> 新值;
    std::vector<稳定编码> 退出事实;
    std::vector<L1属性设置请求> 属性设置;
};
```

字段顺序以实际现行五类写集 DTO 名为准，但合同/摘要版本、期望代次、幂等键、两摘要、读回计划必须位于写集容器之前并按上述顺序参与规范化。普通写合同版本1、摘要版本错误、任一摘要全零或读回计划为空均在取得首笔候选前 `入口拒绝`。

## 5. 领域摘要编码合同

每个 L1 写调用点必须在领域所有者内形成两个摘要，不把 DTO 或编码器下沉给 L1。

通用确定性二进制编码：

1. 固定写入 ASCII 魔数 `HZY-L1ID` 八字节；
2. 写 `编码格式版本 U32=1`、操作标签 U32、字段；
3. 所有 U16/U32/U64 和有符号整数按网络字节序；bool 为 U8 0/1；
4. 枚举先写冻结底层宽度再写数值；optional 写 U8 0/1 后写载荷；variant 写正式稳定标签后写载荷；
5. string/字节组/vector 先写 U64 项数或字节数；空集合精确编码 U64 零；
6. 无序事实先按正式稳定字段排序，再写 U64 数量和逐项载荷；有序业务组保持合同顺序；
7. 禁止写地址、padding、C++对象内存、RTTI、`variant.index()`、`std::hash`、显示名称、日志、容器迭代偶然顺序或本机字节序；
8. 对完整编码字节直接计算标准 SHA-256；使用空串和 `abc` 标准向量验证算法实现。

请求意图编码固定：`魔数 + 格式版本 + 领域操作标签 + 公开业务请求全部字段声明顺序`。不得包含 provider 返回、事实截止、稳定编码分配、本地键、执行算法选择、锁或事务。

执行证据编码固定：`魔数 + 格式版本 + 领域操作标签 + 请求意图摘要32字节 + provider合同/规则版本 + 首次共同事实截止 + 稳定排序的写前事实见证 + 规范化写集全部字段（不重复两摘要） + 规范化通用读回计划`。它只在首次未命中路径形成。

领域操作标签必须由各现有服务固定非零稳定值，写入其本地私有常量；同一服务不同公开写操作不得复用。执行侧不得临场由文件名或函数地址派生标签。

## 6. 通用发布后读回合同

完整保留 v0.1：

```cpp
inline constexpr std::uint32_t L1通用发布后读回计划版本 = 1;

enum class L1通用读回对象种类 : std::uint8_t {
    节点 = 1, 关系 = 2, 值 = 3, 属性槽 = 4
};
enum class L1通用读回当前性 : std::uint8_t {
    当前 = 1, 本次发布退出 = 2
};
enum class L1通用读回代次种类 : std::uint8_t {
    固定 = 1, 本次发布 = 2
};
struct L1通用读回代次期望 final {
    L1通用读回代次种类 种类 = L1通用读回代次种类::固定;
    std::uint64_t 固定代次 = 0;
};
```

节点、关系、值和属性槽期望 DTO、variant 计划、结果副本沿 v0.1 完整实现。计划必须精确覆盖每个新节点/关系/值、每个退出事实和每个槽变更；允许必要既有稳定编码互证。空、缺、重、错种类、错生命周期或不可解析引用均在 `swap` 前拒绝。

`L1通用发布后读回结果` 保存状态、发布事实代次和规范排序的全部项目。成功和精确重复返回首次完整读回；发布后失败返回内部不一致、非零发布代次、首次映射和失败见证身份，不返回部分成功。

## 7. 幂等账、首次结果和确定性结果摘要

`L1幂等账记录` 完整定义为：

```cpp
struct L1幂等账记录 final {
    写集幂等键 幂等键;
    std::uint32_t 摘要合同版本 = L1幂等摘要合同版本;
    L1确定性摘要 请求意图摘要;
    L1确定性摘要 首次执行证据摘要;
    std::uint64_t 首次发布事实代次 = 0;
    L1写集请求 首次规范化写集;
    std::vector<std::pair<写集本地键, 稳定编码>> 首次新编码映射;
    L1通用发布后读回结果 首次完整读回;
    L1确定性摘要 确定性结果摘要;
    std::optional<L1失败见证身份> 发布后失败见证;
};
```

`首次规范化写集` 保留两摘要及完整计划。重复请求不能覆盖任何首次字段。首次结果摘要由 L1 在候选中形成，算法为标准 SHA-256；确定性编码固定：

```text
ASCII "HZY-L1RS" 8字节
+ U32 结果摘要版本1
+ U32 L1合同版本2
+ U32 摘要合同版本1
+ 幂等键U64
+ 请求意图摘要32字节
+ 首次执行证据摘要32字节
+ 首次发布事实代次U64
+ 首次新编码映射（按本地键升序，U64数量，逐项本地键U64+稳定编码U64）
+ 首次完整通用读回（按计划规范顺序，U64项目数，逐项种类稳定标签+完整中性副本）
```

空映射或空读回按 U64 零编码，但普通成功因非空计划不得产生空读回；恢复/完整性校验遇到该形状必须拒绝。节点/关系/值/槽副本逐字段按 DTO 声明顺序和第5节数值规则编码。结果摘要不得包含失败见证、重复审计事件或当前隔离状态，避免后续诊断改写首次结果；这些字段必须另行与首次结果关联互证。

## 8. 公开幂等探测合同

在合同模块定义：

```cpp
struct L1幂等探测请求 final {
    std::uint32_t 合同版本 = L1事实基座合同版本;
    std::uint32_t 摘要合同版本 = L1幂等摘要合同版本;
    写集幂等键 幂等键;
    L1确定性摘要 请求意图摘要;
};

enum class L1幂等探测状态 : std::uint8_t {
    未找到 = 1,
    同义已发布 = 2,
    异义冲突 = 3,
    入口拒绝 = 4,
    已隔离 = 5,
    内部不一致 = 6
};

struct L1幂等首次结果副本 final {
    L1确定性摘要 首次执行证据摘要;
    std::uint64_t 首次发布事实代次 = 0;
    std::vector<std::pair<写集本地键, 稳定编码>> 首次新编码映射;
    L1通用发布后读回结果 首次完整读回;
    L1确定性摘要 确定性结果摘要;
    std::optional<L1失败见证身份> 发布后失败见证;
    bool 当前隔离 = false;
};

struct L1幂等探测结果 final {
    L1幂等探测状态 状态 = L1幂等探测状态::入口拒绝;
    写集幂等键 幂等键;
    std::optional<L1幂等首次结果副本> 首次结果;
};
```

公开函数：

```cpp
L1幂等探测结果 L1事实基座服务::探测幂等(
    const L1幂等探测请求& 请求) const;
```

仓库在一次 `std::shared_lock<std::shared_mutex>` 内只读内存幂等账：

- 无键：`未找到`；
- 有键且意图摘要相同：校验记录完整后返回 `同义已发布` 和首次副本；
- 有键且意图摘要不同：`异义冲突`，载荷为空；
- 隔离状态：若目标键有完整记录，返回 `已隔离` 并携带允许公开的首次副本与见证；目标键不存在返回 `已隔离` 空载荷；
- 账、审计、结果摘要或失败见证关联矛盾：`内部不一致`。

探测不访问 SQL、provider、普通事实读取、完整快照或可重建索引，不推进代次，不写审计，不外泄锁、容器引用、事务视图或可写记录。领域所有者必须在访问可变 provider 前先探测；探测 `同义已发布` 直接机械映射首次结果，`异义冲突/已隔离/内部不一致` 不进入首次形成。

## 9. 最终提交裁决

`L1事实基座仓库::提交` 在唯一独占锁内再次裁决，避免探测到提交之间竞态：

1. 校验合同、摘要版本、幂等键、请求意图摘要；
2. 已有键且意图相同：直接返回首次完整结果，状态 `精确重复`；不比较本次执行证据、规范化写集、期望代次或读回计划，不新增审计，不推进代次；
3. 已有键且意图不同：`幂等冲突`；
4. 仅未找到时，才校验执行证据非全零、期望代次、规范化写集、完整非空读回计划；
5. 建立候选、首次两摘要、首次映射/读回预期、结果摘要、幂等账和一条 `提交成功` 审计；
6. 预留发布后失败见证和审计容量；资源失败必须发生在 `swap` 前；
7. `swap` 推进一次业务代次；
8. 同一独占锁内从刚发布权威状态逐项读回；成功才返回；矛盾则安装失败见证、失败审计并隔离后返回。

审计固定：同义探测和同义提交重试都不追加 `精确重复` 审计事件。首次只有一条 `提交成功`；异义提交可追加 `幂等冲突`，但不得改变首次结果摘要。这样重试次数不是业务事实，也不让审计增长影响确定性恢复。

## 10. 失败见证、隔离和读回

完整保留 v0.1 的无分配失败收口：所有可能分配的失败见证正文、审计项目和容器容量在 `swap` 前准备。发布后中性读回发生异常或出现映射、对象、字段、槽、生命周期、代次矛盾时：

1. 已发布业务代次和幂等账保持；
2. 先将事务/写域设为隔离；
3. 在同一独占锁内安装预构造失败见证和失败审计；
4. 返回内部不一致、发布代次、首次映射、失败见证身份；
5. 禁止回滚、删除、补写、第二业务提交或改写首次双摘要/结果摘要。

隔离后普通提交、当前/历史/完整快照读取拒绝；审计和幂等探测按本设计允许恢复定位。只有既有恢复候选确认成功可解除当前隔离；本叶不新增解除入口。

## 11. 审计和恢复材料

`L1审计记录` 的首次提交和发布后失败事件增加摘要合同版本、两摘要、首次发布代次和确定性结果摘要；失败事件另带失败见证身份。审计读取仍按幂等键返回有序记录组。

`L1恢复材料` 中每个 `L1幂等账记录` 必须原样包含两摘要、首次发布代次、首次规范化写集、首次映射、首次完整读回、确定性结果摘要和可选失败见证。恢复验证逐项要求：

- 请求意图摘要和首次执行证据摘要均非全零且与首次规范化写集一致；
- 首次发布代次、映射、读回和结果摘要重新编码后完全一致；
- 首次审计与幂等账两摘要、代次、结果摘要一致；
- 失败见证/隔离审计指向同一幂等键、两摘要、发布代次和结果摘要；
- 当前或历史事实可以按首次读回的原发布代次互证；后续退出不使首次结果失效。

缺失、默认补零、从规范化写集反推意图摘要、从当前 provider 重算、结果摘要错误或多个首次记录均判材料不完整/内部不一致，拒绝建立或确认恢复候选。

## 12. 调用点迁移

世界登记、场景结构、特征定义、实例特征和正式HEAD中存在的特征比较写入口必须：

1. 从公开请求形成请求意图摘要；
2. 调用 `探测幂等`；同义直接返回首次结果，provider调用次数为零；
3. 仅未找到时读取 provider/当前事实，形成确定性写集和非空读回计划；
4. 形成执行证据摘要并提交；
5. 把 L1 精确重复机械映射为领域幂等读回。

专项夹具同样使用两摘要，禁止固定全零或把执行证据复制为意图摘要。P6若尚未被目标接受，其调用点迁移只证明 L1 v2 适配和编译，不证明比较能力。

## 13. 线程和异常

探测使用单次共享锁并复制值式结果后释放。提交使用单次独占锁；探测未找到后并发首次提交由独占锁再次按意图摘要裁决。同意图线程只一笔首次发布，其余精确重复；异意图线程冲突。

摘要编码和 SHA-256 在领域进入 L1 前完成；编码分配失败映射资源失败，SHA实现/不可能全零/字段不完整映射内部不一致。L1 候选、结果摘要编码和容器异常在 `swap` 前为资源失败；`swap` 后任何异常走预构造见证和隔离，不越过服务边界。

## 14. 验证矩阵

- provider变化前后，同键同意图探测均返回首次完整结果，provider零调用、代次不变；
- 同键异意图探测和提交均冲突；
- 同意图但后来执行证据、期望代次、写集或计划不同，探测/提交仍返回首次结果；
- 首次请求合同/摘要版本错误、任一摘要全零、空读回计划写前拒绝；
- SHA-256空串/`abc`标准向量；网络序、optional、variant、空集合和无序组编码稳定；
- 结果摘要字段逐一扰动均改变摘要；容器插入顺序变化不改变摘要；
- 精确重复不追加审计、不改首次记录、不推进代次；
- 正常节点/关系/值/槽、当前/退出、本地键/稳定编码混合读回；
- swap后每类矛盾保留代次、形成见证并在释放锁前隔离；
- 隔离中探测已有同义键返回首次定位和隔离见证，普通写/普通事实读取拒绝；审计可读；
- 恢复材料缺任一摘要、首次代次、映射、完整读回、结果摘要或失败关联均拒绝；
- v0.1通用读回、失败见证、隔离和恢复矩阵不退化；
- Debug/Release x64串行Rebuild、两配置完整自检、strict、模块扫描和diff check通过。
