# WORLD-TREE-P1A2Q 恢复式双目标索引夹具补充详细设计 v0.4

日期：2026-08-03

设计身份：WORLD-TREE-P1A2Q

来源问题：`DRIFT-P1A2Q-LOWLEVEL-FIXTURE-PUBLISHED-GENERATION-UNFORMABLE`

## 1. 裁决与替代范围

P1A2Q v0.6 要求专项自检通过
`节点直接身份结构写入执行器::执行(callback)` 形成两节点、一关系和两类索引，
随后读取非零已发布代次。该合同不可施工：现行低层 callback 入口只完成仓候选发布，
不调用 `节点直接身份结构事务域::推进普通已发布代次`。候选完成发布不等于运行期事实发布，
不得把状态 `已提交`、代次0或后续无关事务解释为本次写集的非零发布代次。

现行执行器已经提供唯一可复用的隔离恢复入口：

```cpp
节点直接恢复数据操作结果
节点直接身份结构写入执行器::执行节点直接恢复事务(
    const 节点直接恢复数据操作规格& 规格) const;
```

该入口在空的等待恢复事务域上依次形成并确认节点、类型合同、类型化值、关系、索引和幂等六仓恢复候选；
全部仓完成发布后，唯一调用
`事务域_->从零设置恢复事实截止代次并开放(许可, 恢复事实截止代次)`。
因此本版唯一裁决是：P1A2Q 的双目标索引基线改由现有恢复执行器一次形成，
恢复事实截止代次固定为1。不得继续调用低层 callback 入口形成本夹具，
不得用无关普通事务补推代次，也不得直接调用任一仓库恢复候选接口。

本文件完整替代关系索引夹具补充详细设计 v0.3。主详细设计 v0.2、
故障注入补充详细设计 v0.2 的生产读取与故障谓词合同继续有效；其中夹具来源统一以本文件为准。

## 2. 当前接口与可构造性证据

正式代码已经具备以下真实接口和行为：

1. `节点直接恢复结构事务请求` 可同时承载节点历史、关系历史、节点目标索引和关系目标索引；
2. 恢复执行器按稳定见证解析节点和关系内部句柄，索引恢复材料同时支持
   `节点目标` 与 `关系目标`；
3. 恢复执行器在六仓全部完成发布后才开放非零代次，失败时保持未开放或隔离；
4. `自检.节点直接身份结构写入.ixx` 的 WORLD-P1A2-A33 已以相同入口证明
   两节点、一关系、索引和代次1可以在隔离对象内恢复；
5. 空类型合同、空类型化值和空幂等恢复材料是现行恢复仓合同允许的完整空集合，
   不要求伪造业务记录。

因此本修订不需要修改执行器、事务域、共享 DTO、SQL、恢复服务或数据操作。

## 3. 物理位置、私有实体与对象生命周期

唯一物理位置仍为：

```text
模块：海中鱼巣.核心.自检.节点直接结构查询
文件：海中鱼巣/核心/自检.节点直接结构查询.ixx
层级：专项自检模块私有命名空间
```

冻结函数签名不变：

```cpp
struct 精确索引查询已发布夹具 {
    索引物理键 节点索引键;
    索引物理键 关系索引键;
    节点句柄 节点目标;
    关系句柄 关系目标;
    std::uint64_t 已发布代次 = 0;
};

std::optional<精确索引查询已发布夹具>
形成已发布双目标索引夹具(
    精确索引查询隔离夹具& 夹具);
```

`精确索引查询隔离夹具` 唯一拥有：节点仓、正式关系仓、可重建索引仓、类型合同仓、
类型化值仓、事务幂等仓、以 `等待恢复` 模式构造的事务域、一个模块私有空操作持久证据端口、
八参数执行器和查询服务。成员按被引用对象在前、端口/执行器/服务在后的顺序声明。

模块私有空操作持久证据端口只满足八参数执行器的完整构造依赖；
`执行节点直接恢复事务` 不调用它。若该端口收到准备、发布见证或撤销见证调用，
统一返回资源失败并令专项失败，不得记录或发布机器事实。

函数参数是同步非空可变借用，函数不保存引用。成功返回值式键、内部句柄和代次；
失败返回 `std::nullopt`。内部句柄只能来自恢复完成后的索引结构化读回，禁止根据排序或仓编号猜测。

## 4. 恢复请求逐字段形成合同

专项在调用前构造下列完整值式身份：场景节点见证、文章节点见证、普通父子关系见证、
节点索引键、关系索引键和安装实例身份。所有稳定主键完整、互异且版本固定1。

`节点直接恢复结构事务请求` 字段唯一来源如下：

| 字段 | 冻结来源与值 |
| --- | --- |
| `合同版本` / `材料格式版本` | 1 / 2 |
| `安装实例身份` | 专项固定非零命名域和键值 |
| `恢复事实截止代次` | 固定1 |
| `高水位组` | 场景命名域=1、文章命名域=1、正式关系命名域=1 |
| `历史占用组` | 两节点稳定主键及节点类型；关系稳定主键，节点类型见证为 `未分类` |
| `节点历史组` | 场景、文章身份见证，均 `当前有效=true` |
| `关系历史组` | 普通父子关系见证，源=场景、目标=文章、顺序号固定1、`当前有效=true` |
| `索引历史组` | `{节点键,true,文章见证,nullopt}` 与 `{关系键,true,nullopt,关系见证}` |
| 类型合同 / 类型化值历史 | 空集合 |
| 幂等历史 / 持久侧账 | 同为完整空集合 |

关系准入表继续由专项私有构造函数覆盖全部正式关系 ABI 槽；普通父子恢复记录必须通过现行关系仓校验。

## 5. 根函数控制流与结果形成

1. 构造上述稳定见证、两索引键和恢复请求。
2. 仅调用一次 `夹具.执行器.执行节点直接恢复事务({请求})`。
3. 只接受 `状态 == 已恢复` 且 `事实截止代次 == 1`；其它状态返回空。
4. 取得一次读取许可，只接受许可有效且 `读取已发布代次() == 1`。
5. 分别调用索引仓结构化读取两键；两次都必须为 `已读取` 且记录完整。
6. 节点索引记录必须为节点目标，关系索引记录必须为关系目标；
   从这两条正式读回提取节点句柄和关系句柄，禁止自行形成句柄。
7. 以句柄读取节点和关系权威记录，并复核其稳定见证等于请求中的文章和普通父子见证。
8. 分别调用查询服务读取两键；两次必须成功、代次均为1、目标稳定见证与请求逐字段相等。
9. 全部成立才返回夹具；任一不成立返回空，不补写、不重建、不再次恢复。

恢复是该隔离对象的唯一基线写入。后续故障注入调用仍必须证明代次与六仓导出逐值不变。

## 6. 提供者—消费者与事务矩阵

| 提供者 | 输出 | 消费者 | 边界 |
| --- | --- | --- | --- |
| 专项固定值 | 稳定见证、索引键、安装身份 | 恢复请求 | 不形成内部句柄 |
| 恢复执行器 | 六仓恢复结果、非零代次 | 夹具根函数 | 六仓发布与代次开放为同一最后发布边界 |
| 索引仓结构化读取 | 两条内部索引记录 | 夹具根函数 | 唯一内部句柄来源 |
| 节点/关系仓 | 当前权威记录 | 夹具根函数 | 只读核对稳定见证 |
| 查询服务 | 稳定节点/关系目标与代次 | 夹具根函数 | 证明生产读路径可消费恢复事实 |

| 分支 | 六仓候选 | 代次 | 结果 |
| --- | --- | --- | --- |
| 请求不完整/身份冲突/关系矛盾 | 不发布或恢复入口收口 | 保持0 | 空夹具 |
| 六仓确认或发布失败 | 撤销或隔离 | 不得开放为1 | 空夹具 |
| 六仓发布完整但代次开放失败 | 隔离 | 不得宣称成功 | 空夹具 |
| 恢复成功但任一基线读回不匹配 | 已发布隔离基线存在 | 1 | 专项失败，禁止补写 |
| 全部成功 | 六仓恢复事实完整 | 1 | 返回夹具 |

## 7. 禁止边与验证

```text
专项自检 -X-> 节点直接身份结构写入执行器::执行(callback)
专项自检 -X-> 用后续普通事务补推前序夹具代次
专项自检 -X-> 直接调用任一仓恢复候选/确认/完成发布
专项自检 -X-> 伪造或推导内部句柄
专项自检 -X-> 扩展共享 DTO、生产提交服务或恢复服务
专项自检 -X-> 把代次0解释为成功
```

机械验证必须证明：恢复入口唯一调用一次；请求同时含节点和关系目标索引；
事务域以等待恢复模式启动；八参数执行器依赖完整；恢复结果、读取许可、仓读回和服务读回代次均为1；
低层 callback 入口在本专项模块零调用；执行器、事务域、共享合同和其它仓零差异。

## 8. 完成边界

本设计只闭合 P1A2Q 隔离双目标索引基线与非零代次的可构造性。
它不把恢复入口升级为生产索引提交服务，不证明 P1A2Q 已实现、编译、运行或进入后继世界树服务。
