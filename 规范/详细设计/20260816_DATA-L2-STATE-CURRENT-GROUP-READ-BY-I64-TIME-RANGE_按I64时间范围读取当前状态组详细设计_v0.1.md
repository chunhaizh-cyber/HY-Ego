# 按 I64 时间范围读取当前状态组详细设计 v0.1

日期：2026-08-16

设计身份：`DATA-L2-STATE-CURRENT-GROUP-READ-BY-I64-TIME-RANGE`

状态：设计就绪；不等于代码已实现

## 1. 目标与缺口

为唯一 `L2状态结构服务` 增加一个当前组读取入口：调用方提交同一 L1 的非零事实代次守卫、I64 时间值闭区间、候选数量预算和返回数量预算，服务返回时间值使用正式 `L2状态时间I64值类型身份`且落入区间的全部当前完整状态。

现行状态服务已经登记四种互异时间材料类型，并能按身份、主体、特征实例和来源读取当前状态；L1 结果提交 `b9e03f984516cd4577e18d868533ad1ea4f5f11a` 已发布按 owner + 属性类型有界读取全部当前值的中性入口。缺口不再是 L1 候选发现，而是 L2 尚未用本族正式 I64 时间类型完成范围筛选、完整状态读回和双预算收口。

本叶关闭 `DATA-EXT-04` 的一个最小分支，不关闭状态服务整族。具名缺口为：

`DRIFT-DATA-L2-STATE-I64-TIME-RANGE-CURRENT-GROUP-READ-MISSING`

## 2. 语义边界

1. 本入口只查询当前状态，读取类别固定为当前，不增加历史范围查询。
2. “I64 时间范围”只表示状态时间属性的当前材料是 `std::int64_t`，且属性类型精确等于状态登记中的 `L2状态时间I64值类型身份`。I64 数值的单位、纪元、业务真实性和时间有效性不由 DATA 解释。
3. 区间固定为闭区间 `[最小时间I64, 最大时间I64]`；只要求最小值不大于最大值。零值、负值和整数边界不由本查询附加业务禁令。
4. 时间 I64 组、时间 U64 组和时间独立材料引用是三种独立结构材料，不参与本入口，也不因形状可转换而报错或命中。
5. 输出按 `L2状态身份.值`严格升序，不按时间排序；相同时间值允许对应多个互异状态。
6. 空组表示在该截止没有匹配的当前 I64 时间状态，是成功结果。
7. 本入口不比较精确值，不判断状态真实，不形成动态、因果、需求或任务。

## 3. 精确公开 ABI

DTO 物理所有者：`海中鱼巣/领域/L2状态结构.数据.h`。

```cpp
struct L2按I64时间范围当前状态读取请求 final {
    L2结构请求头 请求头;
    std::int64_t 最小时间I64 = 0;
    std::int64_t 最大时间I64 = 0;
    std::uint64_t 最大候选数量 = 0;
    std::uint64_t 最大返回数量 = 0;
    friend bool operator==(
        const L2按I64时间范围当前状态读取请求&,
        const L2按I64时间范围当前状态读取请求&) = default;
};
```

新增同一 DTO 所有者的纯值 helper：

```cpp
bool L2按I64时间范围当前状态读取请求有效(
    const L2按I64时间范围当前状态读取请求& 请求) noexcept;
```

有效条件固定为：`L2结构请求头合同有效`、非零期望事实代次、`最小时间I64 <= 最大时间I64`、两个预算均非零。两个预算互相独立，不要求大小关系。

结果复用现有 `L2当前状态组读取结果`，不复制结果 DTO、不增加分页、游标或第二查询状态。服务公开入口位于 `海中鱼巣/领域/服务.L2状态结构.ixx`：

```cpp
L2当前状态组读取结果 按I64时间范围读取全部当前状态(
    const L2按I64时间范围当前状态读取请求& 请求) const;
```

不修改 `L2结构聚合服务`、普通应用或工程登记；现有状态服务 getter 已经是唯一入口。

## 4. 候选发现与双预算

服务先读取并验证当前状态结构类型登记，取得正式 `登记.时间I64值类型.值`。随后只调用：

```cpp
L1事实基座服务::按属性类型读取所有者范围全部当前值({
    L1所有者范围属性类型当前值组读取合同版本,
    状态身份来源定位_.所有者,
    登记.时间I64值类型.值,
    请求.请求头.期望事实代次,
    请求.最大候选数量});
```

`最大候选数量`约束该 owner 下全部当前 I64 时间值候选，而不是只约束区间内命中。超过预算时 L1 整组拒绝，L2 映射 `数量预算不足`、空状态组，不得截断候选后猜测区间结果完整。

L1 成功后，L2 必须逐项互证：值编码和所属节点非零、owner 等于状态 owner、属性类型等于登记的时间 I64 类型、材料替代项精确为 `std::int64_t`、生命周期覆盖请求截止且当前、值组按值编码严格升序。任何坏形状都是 `内部不一致`。

服务对落入闭区间的候选保存三项值式材料：状态编码、时间值编码、I64 材料。区间命中数超过 `最大返回数量`时返回 `数量预算不足`和空状态组；否则按状态编码排序，重复状态编码是内部不一致。

两个预算的拒绝都不返回部分候选、部分状态或下一页令牌。调用方只能以新的完整请求和明确预算重试。

## 5. 同截止完整读回

候选排序和预算检查完成后，服务对每个状态编码调用现有：

```cpp
读取完整状态({请求.请求头, L2读取类别::当前,
    L2状态身份{状态编码}, 0});
```

每项必须满足：

1. 结果为 `已读取`、事实截止等于请求守卫、无变更代次；
2. 状态身份等于候选状态编码，生命周期当前；
3. `L2状态事实完整(...)`在同一截止成立；
4. 时间属性类型等于登记的时间 I64 类型；
5. 时间值编码和 I64 材料与 L1 候选完全相同；
6. I64 材料仍落在闭区间内。

任一单项发生事实代次漂移或资源失败时向上保留该状态并返回空组；其它未找到、已退出、入口拒绝、错载荷、混代或互证失败统一为内部不一致。全部单项完成后才形成最终 `已读取`结果，因此不存在公开部分组。

## 6. 状态映射

| 条件 | L2 状态 | 截止 | 状态组 |
| --- | --- | --- | --- |
| 请求 helper 失败 | 入口拒绝 | 0 | 空 |
| L1 事实代次漂移 | 事实代次漂移 | L1 锁内当前代次 | 空 |
| L1 候选预算不足 | 数量预算不足 | 请求守卫 | 空 |
| 区间命中数超过返回预算 | 数量预算不足 | 请求守卫 | 空 |
| L1 资源失败或完整读回资源失败 | 资源失败 | 安全取得则保留 | 空 |
| 登记损坏，或内部 owner / 类型未找到、已退出、入口拒绝 | 内部不一致 | 安全取得则保留 | 空 |
| 候选、材料、排序、生命周期或完整状态不能互证 | 内部不一致 | 请求守卫 | 空 |
| 0—预算项全部同截止闭合 | 已读取 | 等于请求守卫 | 身份严格升序完整组 |

登记中的 owner 与时间 I64 类型是服务私有永久结构前置，不是调用方查询对象。因此 L1 对它们返回未找到、已退出或入口拒绝时不能映射为普通查询空组或调用方未找到。

## 8. 验证与完成边界

生产外临时检查至少覆盖：坏合同、零守卫、逆序范围、两个零预算；空组；闭区间两端和单点区间；相同时间多状态；输出按身份排序而非时间排序；其它三类时间材料不命中；候选预算精确与少一；区间外候选仍计候选预算；返回预算精确与少一；陈旧守卫；时间值换代后只命中新当前值；状态退出后不返回；读取前后事实代次不推进；既有按主体、特征实例、来源和完整状态读取不回归。

真实资源耗尽、私有登记 / 索引 / 状态损坏、共享锁长期公平、跨进程恢复和正式 BIZ 消费没有稳定合法注入时记 `NOT_RUN`，不得增加生产故障 seam。

本设计完成只冻结当前状态的显式 I64 时间值范围读取。它不证明 I64 组、U64 组、独立材料引用具有统一排序，不证明动态时间范围、`DATA-EXT-04`整项、`DATA-EXT-05—14`或数据服务最终需求清单整体完成。
