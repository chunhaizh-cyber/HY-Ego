# 网页自我指代归类表达详细设计

日期：2026-10-15。版本：v0.1。目标代码基线：main `cb60b784`；本叶允许代码文件自 `e50f355f` 至此未变化。这是 `LANGUAGE-EXPRESSION-S01-SELF-PRONOUN` 的施工设计，不新增正式机器规范。

## 1. 目标与当前事实

本叶只使普通应用在**当前活跃网页会话中，拟由自我发出**一条 S01 概念归类陈述时，把已读回的自我存在 A 表达为“我”，形成完整的“我是C”调用期文本、知识/名称/指代出现对齐。C 必须是可读的正式存在概念及有且仅有一个可选用名称；输出只表述请求中的归类主张，不裁决 A 实际属于 C，不自动提交消息。用户或后续业务显式调用现行网页设置/提交入口时，送达和显示由该入口另行报告。

现行 `新_语言类` 的 S01 知识对象槽固定 `明确对象描述`，`表达.基础语言.cpp`遇该槽返回`缺指称`；S09/S02 只生成概念到概念的问句/陈述。`概念_存在类::获取指代概念`和`概念_名称关系类::查询指代概念名称`可读已初始化的“我”定义及名称。普通应用已保存活跃网页会话、自我存在和语言服务，网页宿主以单运行会话保存消息，并把提交的自我文本标为`网页对话消息角色::自我`。这些现有入口未向语言生成器提供本次出站说话者或已消解指代出现。

网页宿主的单运行会话不证明唯一观看者：同一 URL/令牌可在多个浏览器打开；`网页会话绑定人类`只证明服务要求入口按配置匹配的授权对象，不证明每个页面观看者身份。因此本叶不生成“你”。已显示消息的页面序号在提交后才出现，也不能作为提交前生成“你”的依据。“我”只需接收者恢复该条消息的**说话者**；拟发布通道的角色固定为自我，接收者数量不改变这个单目标。

依据为[1110](../1110_根规范_指代_20260720.md)§2、§4—6，[7230](../7230_子规范_语言材料知识与交互字段.md)§3.2、§4.2—4.4，[7240](../7240_子规范_自然语言双向转换与组织规则.md)§3.1—3.2，[7250](../7250_子规范_最小汉语知识与语言学习.md)§2，以及[代码归属规范](../代码文件建立归属与模块命名规范.md)。本叶为 DATA 外表达治理，不是修改现实或虚拟存在特征值的本能函数。

## 2. 范围和唯一所有者

同一代码切片拥有语言知识 DTO/持久读取、初始化元格式和种子、表达消费者、普通应用出站来源及网页宿主只读会话核验。不得拆开公开字段、种子、初始化顺序与生成消费。写入只涉及新语言知识定义及其来源的初始化；一次表达调用不写领域或语言事实。暂不建立持久语言场景/交互记录/指代实例：本叶以调用期材料表达本次作用域和出现，后继保存须经语言与场景 owner 另设合同。

允许改：`海中鱼巣/界面/宿主.网页对话.h/.cpp`、`海中鱼巣/装配.普通应用.h/.cpp`、`海中鱼巣/领域/新_语言类.h/.cpp`、`海中鱼巣/业务/初始化.语言知识.h/.cpp`、`海中鱼巣/业务/表达.基础语言.h/.cpp`、`初始化材料/最小语言知识种子.txt`，以及本计划专属施工与编译记录。不新建 C++ 文件；不改概念/指代名称/词/存在 owner、vcxproj/filters、服务要求、普通应用消息接收、本能函数、共享知识索引或正式规范。宿主仅新增核验，不改变消息接收、提交和页面序号合同。

## 3. 类型化合同与知识

### 3.1 本次角色来源与表达请求

在`表达.基础语言.h`定义值式`基础表达指代选择`：`规则角色`、`指代概念节点`、`目标类型=存在`、`目标存在节点`。本次来源独立放在`基础表达请求.网页自我来源`；其类型采用**私有构造器**，只有普通应用的具名生产包装函数能在核验活跃会话、宿主会话、自我及交互窗口后构造。通用生成器不能凭调用方自报的普通公开结构将“我”判为已消解。来源固定含`种类=网页自我待发`、公开会话标识、本次说话者存在节点、交互窗口节点及读取时页面末序号；不含私有 URL 令牌、接收者推测、焦点或可变指向槽。`基础表达请求`追加可选选择与可选来源，二者必须同时存在或同时缺失；缺省保持现有 S02/S09 和 S01 `缺指称` 行为。仅允许一个选择，且仅能用于陈述/概念归类/普通陈述的 S01 主体角色。选择存在即**要求**采用对应已消解指代知识，不能静默回退到名称或明确描述，也不能仅因目标等于 self 就启用。

在`表达.基础语言.h`定义调用期`基础表达指代出现`：局部出现编号、语言场景待保存来源（会话标识及本次表达，不伪称已有场景节点）、作用域来源、采用定义节点、指代名称关系节点、目标强类型`存在`与稳定编码、文本零基 Unicode 标量半开范围、所用知识及结构项路径。`基础表达结果`追加出现组；成功时本叶恰一项，失败时与文本/知识/绑定/对齐一并为空。`基础表达对齐项`追加独立的指代名称关系引用，普通概念名称关系字段保持原义。旧出现以值式结果固定，不会被后续焦点或会话变化改写；本叶不分配持久实例身份。

`表达.基础语言.h`在声明私有构造器的 friend 函数前，仅前置声明上述普通应用请求/结果；`装配.普通应用.h`包含`业务/表达.基础语言.h`并给出其完整定义。普通应用入口在同一函数内先构造私有来源、调用通用生成器、再核验宿主与活跃会话；来源类型不暴露公开构造函数、公开静态工厂、反序列化入口或可写字段。调用方不能仅填`基础表达指代选择`伪造本次角色：缺私有来源时`输入拒绝`。旧请求两个新增 optional 均为空，原有规则的匹配含义不变；现行候选枚举先按该语言全部知识数核对`最大知识条目数`，新增独立知识会提高该计数，因此旧额度恰好卡住旧知识总数的请求可能转为`额度不足`，调用方须给出覆盖新总数的额度。本叶不暗改候选枚举的预算语义。

普通应用在`装配.普通应用.h`增加`普通应用网页自我归类表达请求`（公开会话标识、归类概念节点、可选概念名称关系、三项现行额度）和`普通应用网页自我归类表达结果`（状态、可选完整`基础表达结果`、已核验会话/说话者）；公开函数`生成普通应用网页自我归类表达(const 普通应用网页自我归类表达请求&) noexcept`。此函数是唯一可把网页来源称为已核验的生产入口。调用期DTO不能独立当作语言服务的永久可信来源；直接调用通用生成器的结果只对调用方提供的来源条件成立，不证明网页会话真实存在。

在`宿主.网页对话.h/.cpp`增加只读`核验网页对话当前会话(std::string_view 公开会话标识) noexcept`，结果为`已匹配`并附当前页面末序号，或`宿主未运行/会话不匹配/输入拒绝/资源失败/内部错误`；与消息组同锁读取，不返回私有令牌或页面正文，不改变会话。`bad_alloc`及`length_error`返回`资源失败`，其它异常返回`内部错误`，非成功序号为空。它只证明当前宿主运行的公开会话，绝不证明观看者身份。普通应用保持已有`上下文锁 → 宿主互斥`方向，不在宿主锁内回调普通应用。

公开签名和可见性固定如下；新增的业务函数都不是本能函数，定义位于同名现有 `.cpp`，不引入转发模块。


`网页对话会话核验结果`非成功时序号为空；`已匹配`时序号可为零（无任何消息）。`普通应用网页自我归类表达请求`的会话标识必须精确等于当前活跃值；归类概念节点和三个额度不可缺省为无界。`生成基础语言表达`保留现行六个服务参数顺序；`新_存在类`继续为尾参，既有生产调用只需按新增来源选择的缺省行为工作。

状态映射固定如下。外层非成功时`表达`与`已核验来源`为空；如已调用生成器，`表达状态`保留其非成功枚举，否则为空。外层成功时`表达状态=已生成`、`表达`和`已核验来源`均有值，且后者等于表达中出现的来源快照。

| 来源/生成结果 | 包装状态 |
| --- | --- |
| 普通应用无成功装配或上下文 | `上下文不存在` |
| 会话标识无效、额度为零、C 编码无效 | `输入拒绝` |
| 活跃会话不存在/不匹配、宿主会话不匹配或末次会话身份变化 | `会话失效` |
| 宿主未运行 | `来源不可用` |
| 宿主内部错误、已发布结构损坏、生成器`内部不一致` | `内部不一致` |
| 宿主`资源失败`、包装入口的`bad_alloc`/`length_error`、生成器`工程未完成` | `工程未完成` |
| 生成器`输入拒绝` | `输入拒绝` |
| 生成器`缺规则/缺名称/名称待选/缺指称/多规则待选/能力未支持/引用不可读/读取漂移/额度不足` | `表达未完成`，内层保留精确状态 |
| 生成器`已生成`且末次来源仍匹配 | `已生成` |

### 3.2 知识及初始化

`新语言知识表达方式`增加`已消解指代`。`新语言知识角色表达项`追加可选`指代概念节点`：只有该方式必须有值，旧三方式必须为空。语言 owner 的定义规范化、身份查重、schema 字段、持久读回、候选枚举及有效性核验全部包含该字段；不把词面或初始化标签当作持久语义。该方式首叶只允许角色为`领域对象引用/存在/单项`，定义经`概念_存在类::获取指代概念`读取为`单个已登记强类型信息节点`且规则为`作用域说话者`，参数/特征约束与已发布定义完整相符。跨 owner 读在进入语言锁前完成，发布后和返回前重读；语言锁内不回调概念或名称 owner。引用退出后使用知识时返回`引用不可读`，不能把其名称继续当有效指代。

本叶允许的“我”定义形状与现行`初始化材料/指代定义种子.txt`首行一致：`目标范围=单个已登记强类型信息节点`，`规则=作用域说话者`，参数组恰为`(目标, 强类型信息节点)`和`(作用域, 交互作用域)`，特征约束组为空。核验按字段和集合内容完成，不依赖首行位置；别的说话者定义即使词面也叫“我”仍不能进入本叶。定义节点以正式读口取得，不把种子文本或词面当运行时身份。

语言知识公开发布/查询/枚举函数在既有`新_词类`只读参数之后增加`const 概念_存在类&`；同模块全部生产调用同步迁移，不保留不核验指代引用的兼容入口。旧定义无指代字段，解码按空值，身份与含义不变。`初始化.语言知识`的元格式只新增`项 <序号> 角色 <角色号> 已消解指代 我`，其它行不变；`我`只用于初始化时从已发布的词条—指代名称关联找到**唯一**满足本作用域说话者完整定义的正式指代概念，知识正式字段保存概念节点。零个或多个合格关系均拒绝，不按第一项选取。

`初始化语言知识请求`不新增身份型字段；其它来源建立/读取入口不增参数。上述两个概念读口的现行精确签名为`指代概念查询结果 概念_存在类::获取指代概念(稳定编码) const`与`指代名称列表读取结果 概念_名称关系类::查询指代概念名称(稳定编码) const`；按查询状态和完整 DTO 读回，不凭布尔值/数组位置判定。知识四入口的已知生产调用仅位于`初始化.语言知识.cpp`和`表达.基础语言.cpp`，本切片白名单覆盖；其它调用若 S0 新增则暂停签名迁移受影响范围。

物理记录只在语言知识 `知识标识` 的现有尾部追加一个`项指代定义`字段锚；指代角色项保存一条该字段到正式指代概念的强类型稳定引用，不另建知识节点族或第二索引。旧角色项缺此字段即 `std::nullopt`；新角色项恰一条。字段数量超过一、非引用载荷、旧方式却带字段、新方式却缺字段或目标不再可读均拒绝。`初始化语言知识结构`沿已有整体 schema 处理新尾锚，不能以旧数组长度读取新 schema；当前已发布知识的旧项在新解码合同下仍须完整可读，不复制或替换其身份。初始化发布未知沿现行同请求读回；本叶不设计物理迁移/删除或历史查询。

标准种子增加独立`S01网页自我`定义，与原 S01 共享`概念归类/普通陈述`目标和两角色，但主体结构项为`已消解指代 我`，其余仍为“是”及归类概念名称。它不覆盖原 S01，也不让标签参与运行选择。首次普通应用装配在指代种子前先显式调用一次`当前.世界事实.语言服务.初始化语言知识结构()`，要求返回`新语言知识状态::已完成`；此阶段只使语言知识 schema 就绪，不发布任何语言知识或功能词。指代种子先要通过`查询知识先天来源`读该 schema，因此不能只把现有两个初始化调用交换顺序。schema 阶段失败按现有普通应用初始化工程诊断调用`工程异常终止`并中止后续阶段，保留已发生的 schema 身份，不伪造指代或知识完成结果。schema 成功后，原始词条/指代名称种子先发布并完整读回，随后发布语言知识；后者内部重复初始化 schema 应取得`已完成`。重复装配只读路径不再次调用写式 schema 初始化，先完整只读核验指代种子，再只读核验语言知识；已有成功装配保证 schema 曾就绪，读回失败按现有对应初始化诊断收口。各 owner 部分发布保留真实阶段，不假回滚；重复初始化须按完整知识定义复用同一身份，新知识来源范围与实际文本对应。

## 4. 消费与来源核验顺序

1. 普通应用入口核对装配成功、公开会话标识非空且 UTF-8 合法、与活跃网页会话完全一致；用宿主新只读入口核对同一公开会话正运行。读取`装配结果.自我->自我存在`并经`新_存在类::获取存在`核验实际存在，交互窗口节点同样可读。读取`zh-CN`正式语言身份；输入 C 仅作为请求中的归类概念，不从自我特征推断。
2. 由已初始化指代种子结果及正式概念/名称联合读口确定唯一“我”定义与首选名称；不依赖数组位置。形成固定`网页自我待发`来源及`基础表达请求`：`语言节点=按登记键查询("zh-CN")`所得身份，`目的=陈述`、`操作=概念归类`、`作用域=普通陈述`；参数恰为`{主体, 存在, 领域对象, 自我存在节点, 无名称关系}`与`{归类概念, 存在概念, 概念, C, 请求.选用归类名称关系}`；`受询者/被询操作/确认范围`为空；三个额度逐项取请求正值。`指代选择={规则角色=0, 指代概念节点=已读回“我”定义, 目标类型=存在, 目标存在节点=自我存在节点}`；`网页自我来源`由本包装入口的私有构造器形成。不声称接收方身份，不借网页交互者或第一权限人作为“你”。
3. 通用生成器按目标、类别、作用域和选择过滤**全部**知识候选：选择存在时只接纳主体角色`已消解指代`且定义节点相同的规则，原明确描述规则不构成多规则；选择缺失时该指代变体不可入选。现行语言 owner 在过滤前按该语言全部知识数核对调用额度；新增变体计入总数，旧额度不足时仍返回`额度不足`，不声称旧请求在相同额度下结果恒定。额度足够后，零/多仍分别为`缺规则`/`多规则待选`。验证 A 与来源说话者是同一可读存在，C 是正式存在概念。获取所选指代定义、唯一可选“我”名称关系及词条、C 的名称；不把类别词直接用作实例名。
4. 依正式结构逐项展开，返回“我”的完整标量范围、定义/名称关系/目标/来源和固定出现。再次读回已用规则、指代定义/名称/词条、C/名称、存在 A 及候选完整性；变化或会话**身份**最终复核不一致时清空全部输出并返回`读取漂移`或`会话失效`。网页宿主最终复核与普通应用上下文在同一入口锁作用域内完成；该锁只保障本次来源快照，结果生成后会话关闭不改写结果。期间页面末序号增长不改变“我”的所指，保留初次读取的序号作为来源快照，不因其增长拒绝。生成不调用设置输入框或提交消息。

语言 owner 的读写部分发布一个完整知识定义为原子边界；概念/名称/词/语言之间无跨 owner 原子事务。初始化依赖先后及完整读回处理跨 owner 部分失败。表达调用零事实写入，无撤销；已返回的调用期出现只记录当次解释，后继保存须重新核验来源和目标。任何已发生的网页消息事实不因生成失败删除。

## 5. 状态、工程失败与完成边界

非法枚举/缺字段/目标不等于来源说话者为`输入拒绝`；普通应用无活跃匹配会话为`会话失效`，宿主未运行为`来源不可用`；正式 A/C/定义/名称/词条不可读为`引用不可读`；候选零/多及名称零/多分别沿既有`缺规则/多规则待选/缺名称/名称待选`；额度不足沿既有`额度不足`。正式来源或引用两次读回不一致为`读取漂移`。损坏的已发布结构为`内部不一致`并进入既有工程诊断边界；宿主资源失败及包装入口的`bad_alloc`/`length_error`为独立`工程未完成`，不能包装成“不是自我”或`缺指称`。包装入口捕获生成器未处理的其它`std::exception`及未知异常，按现有`工程异常终止`弹窗/日志与中止路径处置，不让异常越过`noexcept`触发无诊断终止，也不伪造业务未完成。初始化后发布未知保留真实阶段和身份并按原请求读回，不换键重建。

首叶成功只证明：在当前网页自我待发作用域中，可以由正式 S01 指代知识、概念名称与类型化绑定生成一条完整的“我是C”调用期陈述及一个固定出现。它不证明归类主张为真、文本已提交/送达/被理解、入站“我/你”、出站“你”、第三方/近远/焦点指代、任意场景对象描述、持久指代实例、反向解释或完整双向语言转换。

默认工程验证为实际项目 Debug|x64 编译链接、`git diff --check`、种子源与部署副本逐字节核对、现行 S02/S09 所有签名调用可编译。没有当前用户明确测试指令时记录“已编译，未运行测试”。若获具名测试指令，优先在实际项目验证首次/重复知识初始化、自我 S01 正例、旧 S02/S09、无会话/换会话、非自我 A、指代名称零/多、C 名称零/多、候选超额、来源漂移和结果零载荷；不得自建外部临时工程替代。
