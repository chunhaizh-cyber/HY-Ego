# L1-SIMPLIFY-P10-EXISTENCE-FEATURE-VALUE 存在宿主 I64 当前值换代详细设计 v0.1

更新时间：2026-08-05

创建侧正式代码基线：`4cf49c19ae403e47f4a74d808f247dc4603a9114`

## 1. 目标与完成边界

本设计实现 SELF-GOV-CLOSURE STEP-3D 的最早真实提供者：在 P7 已验证实际存在拥有 P8 I64 实例槽和当前值后，通过现有 `海中鱼巣.领域.服务.L1实例特征` 将该实例槽的当前 I64 值原子换代，并从权威 L1 重新读取新当前、旧历史和当前属性槽校准结果。

完成必须同时成立：

- 实际存在自己的实例槽、宿主关系和定义关系保持不变；
- 新值建立、当前属性槽切换和旧值退出只由一个 L1 写集发布一个新代次；
- 新当前只能由 P8 存在读取入口和 L1 当前属性入口证明，旧值只能由 L1 历史入口取得；
- 同键同义、同键异义、旧基线竞争、多轮换代和多线程调用均有确定结果；
- 场景专用 DTO、入口和可观察语义保持不变，两个入口复用同一私有换代核心，不形成第二套值服务。

本叶不创建或修改关系19状态、关系20迁移动能、动作动态、来源动作、因果、需求、任务、结算或 P9 状态见证；不接入运行期、SQL、材料、恢复或生产装配。

## 2. 正式依据与当前事实裁决

正式依据为 0050、1130、2100、4015、4020、4040、4110、4190、4200、4210，SELF-GOV-CLOSURE v0.2，P4 v0.1 正式设计与结果，以及 P7/P8 v0.1 冻结合同。

当前正式事实：

- P4 已在 `L1实例特征服务` 实现场景专用 `换代I64实例特征当前值`，固定使用私有 `0x07` 幂等域和“一新值、一属性槽变更、一旧值退出”写集；
- P4 的 `I64实例特征当前值换代请求` 绑定 `I64实例特征读取请求`，后者绑定 `初始场景读取请求`，不得静默解释为实际存在；
- P4 服务内当前四个单值换代见证只能保存最后一次请求，不能承载多实际存在、多轮换代的长期同键收敛；
- P8 v0.1 冻结了同一服务中的 `实际存在I64实例特征读取请求` 和 `读取实际存在I64实例特征`，但尚不是当前代码能力；
- P7 当前场景归属只用于 P8 证明实际存在宿主资格，不是实例槽当前值换代的写入对象；
- 新 L1 `值事实` 没有“前一值”字段。4015 以同一写集中的旧值退出、新值发布、当前槽切换、幂等审计和历史事实形成换代链，不得为本叶另建第二权威前驱字段或侧账。

复用裁决：原位扩展 P4/P8 所在服务；不新建服务、模块、关系或 L1 合同。P7 是 P8 的宿主资格前置，3D 只调用 P8 公开读取一次，不再额外调用 P7 拼接另一代材料。P9 和 P6 均不是本叶机器语义前置。

## 3. 相同材料的唯一裁决

P4 正式合同只要求新 I64 位于定义闭区间，没有“无变化”结果；其固定写集无条件建立新值并退出旧值。3D 保持这一已经冻结并实现的语义：

1. 完整请求和幂等身份都相同：返回 `幂等读回`，事实代次不再推进；
2. 使用新幂等身份、最新当前见证和最新期望代次：即使 `新值 == 旧值.I64值` 且来源相同，仍建立新值编码、退出旧值、切换当前槽并推进一次事实代次；
3. 同一幂等身份而任何请求字段不同：返回 `幂等冲突`，零事实变化；
4. 后继状态/动态不得以“值编码变化”代替“原始材料变化”。4190/4210 要求无材料变化不生成动态；该判断属于后继 3E，不属于本叶。

本裁决不新增“无变化”状态，也不把换代动作自动解释为状态变化。

## 6. 共享私有换代核心与统一幂等账

服务内部新增不导出的已验证材料：

```cpp
struct I64当前值换代已验证材料 final {
    特征操作幂等身份 幂等身份;
    std::uint64_t 期望事实代次 = 0;
    稳定编码 宿主;
    稳定编码 特征定义;
    稳定编码 实例槽;
    稳定编码 宿主关系;
    稳定编码 定义关系;
    稳定编码 旧当前值;
    std::int64_t 旧I64值 = 0;
    稳定编码 旧来源节点;
    std::int64_t 新I64值 = 0;
    稳定编码 新来源节点;
};
```

私有函数固定为：

```cpp
L1写入结果 提交I64当前值换代写集(
    const I64当前值换代已验证材料& 材料);
```

它只负责构造和提交 `0x07` 写集，不读取场景或存在 provider，不保存业务结果。场景入口和新增存在入口都必须在各自 provider 读取成功后构造该材料并调用此函数；不得复制第二段写集代码。

现有四个单值字段 `换代请求_ / 换代写集_ / 换代后读取请求_ / 换代旧事实_` 替换为按 `幂等身份.值` 排序的统一值式账。账项保存：

```text
场景或实际存在请求的具名 variant
+ 规范化 L1 写集
+ 对应宿主形状的换代后读取请求 variant
+ 换代前完整 I64实例特征事实
+ 首次发布事实代次
```

- 同一数字幂等身份跨场景/实际存在入口共享 `0x07` 域；同 variant 且请求逐字段相同才是精确重复，跨 variant 或任何字段不同均为 `幂等冲突`；
- 不同键允许多存在、多实例槽和同一实例槽多轮顺序换代；互斥量只串行本服务实例的检查、提交和账更新；
- L1 幂等账是权威，本进程账只保留精确重复所需编码见证。进程重建后遇到 L1 精确重复但没有本地编码映射和见证时返回 `内部不一致`，本叶不扫描 L1 猜测编码，也不承担恢复装配；
- 账项只在发布成功且完整见证可保存后写入。分配失败返回 `资源失败`，不得留下半项。

统一账不得成为当前值、前一值链或业务资格的第二权威；最终返回始终以公开事实再次读取为准。

## 7. 写前读取与字段来源

新增入口在服务互斥量内按固定顺序执行：

1. 校验请求、登记已加载且 P8 的实际存在 provider 已绑定；否则返回 `入口拒绝` 或 `登记未加载`；
2. 查统一幂等账：同键异义立即 `幂等冲突`；同键同义取得既有写集、旧事实和新读取见证，进入重复提交/校准；
3. 首次请求只调用 `读取实际存在I64实例特征(请求.当前事实)`；必须为 `已读取` 且载荷完整；该入口内部负责 P7 实际存在资格、当前场景归属、P2 定义、实例槽、两关系、当前值和属性槽的独立同代次互证；
4. P8 事实截止代次必须等于请求期望代次；事实中的宿主、定义、实例槽、当前值、来源及两关系必须等于请求见证；
5. 调用 P2 `读取I64特征定义(请求.当前事实.定义)`，定义同代次且 `新值` 位于闭区间；
6. 从 L1 当前节点入口读取 `新来源节点`，必须是同代次当前普通节点；
7. 再读取一次完整快照，代次仍等于请求期望代次，并确认 P8 当前属性槽唯一指向旧当前值，实例槽、宿主关系和定义关系仍为当前且形状未漂移；
8. 把 P8 读回形成 `I64当前值换代已验证材料`，随后才允许提交第一笔写入。

不得直接消费初始场景的实例槽/值，不得把 P7 当前场景归属关系当宿主关系，不得读取或修改 P9 状态见证节点。

## 8. 原子写集、换代链与撤销边界

共享核心固定提交：

```text
期望事实代次 = 已验证材料.期望事实代次
幂等键 = (0x07 << 56) | 已验证材料.幂等身份.值
节点 = 0
关系 = 0
值 = 1：所属=实例槽；属性类型=登记.当前I64值属性类型；
         材料=新I64值；来源=新来源节点
属性槽变更 = 1：实例槽 + 当前I64值属性类型 -> 新值本地键1
退出事实 = 1：旧当前值
```

L1 同一写集同时建立新值、退出旧值并切换槽；提交前失败零普通可读事实变化。领域服务不接触候选、确认、撤销或补偿；提交失败直接按状态返回。发布后读回失败不得补写、删除、撤销或发布第二写集。

“前一值链”唯一冻结为以下权威组合，不新增字段：

```text
同一写集审计：退出旧当前值 + 建立新值本地键1 + 槽切换到键1
+ 旧值历史记录.退出事实代次 == 新值.创建事实代次 == 本次发布代次
+ 发布后当前属性槽唯一指向新值
```

服务本地统一账只帮助幂等回放，不能替代该组合。旧值稳定编码和历史材料永久保留，实例槽、宿主关系、定义关系和特征定义不换代。

## 9. 发布后独立读回

成功或精确重复后必须：

1. 从本地键映射或精确重复账项取得唯一新值编码；
2. 只替换 P8 读取请求的 `当前值` 和 `来源节点`，构造新的 `实际存在I64实例特征读取请求`；
3. 调用公开 `读取实际存在I64实例特征`，读回代次等于写入结果代次，宿主、定义、实例槽和两关系不变，新 I64 材料与来源匹配；
4. 调用 L1 `读取当前值(旧值)`，必须返回 `已退出` 且空当前载荷；
5. 调用 L1 `读取历史事实(旧值)`，必须返回完整旧值，所属/类型/材料/来源不变，退出事实代次等于本次发布代次；
6. 调用 L1 `读取当前属性(实例槽, 当前I64值属性类型)`，必须唯一指向新值且读取代次等于发布代次；
7. 再次确认实例槽、宿主关系和定义关系仍为当前且创建身份未变。

任一矛盾返回 `内部不一致`；P8 再读发生合法代次漂移时返回 `事实代次漂移`。动作返回的预计形状和服务缓存均不得冒充最终事实。

## 10. 状态映射、并发与生命周期

状态映射固定：

- 请求版本/形状非法、新值越界、来源非普通节点、未绑定 P7 provider -> `入口拒绝`；
- 登记未建立或 P8 `登记未加载` -> `登记未加载`；
- P8 必需事实不存在/退出 -> `未找到`；
- P8/P2/L1 任一截止代次不同、提交基线漂移、发布后合法竞争漂移 -> `事实代次漂移`；
- 同键异义、跨场景/存在同数字键异义 -> `幂等冲突`；
- `std::bad_alloc` 或 L1 资源失败 -> `资源失败`；
- 坏成功载荷、关系/槽/类型/材料/映射/历史互证损坏及未知异常 -> `内部不一致`。

所有非成功结果业务载荷为空。生产函数不写事件日志、调试日志、运行日志或排错日志，诊断由最终调用责任边界处理。

多工作线程可以同时调用两个换代入口；服务互斥量串行本地账，L1 期望代次与幂等账裁决跨调用原子性。同一旧当前事实的不同键竞争至多一个提交；后到者为代次漂移或未找到，不能覆盖新当前。不同存在也必须基于各自相同全局事实代次依次提交，调用方在每轮重新读取最新 P8 当前事实和代次。

## 11. 验证矩阵

原位扩展 `海中鱼巣.领域.自检.L1实例特征` 的顺序320专项，不新增模块、工程项或顶层自检单元。完整自检数和模块数在执行 S0 从 P7/P8 正式结果读取，不预写猜测值。至少覆盖：

1. P7 实际存在的 P8 初始当前值成功换代，写集精确零节点、零关系、一值、一槽变更、一退出，事实代次推进一次；
2. 新当前经 P8 入口独立读回；旧当前为已退出且空载荷，旧历史完整，当前槽唯一指新值；宿主/定义/实例槽/两关系编码不变；
3. 新材料等于旧材料且使用新幂等身份、最新见证时仍换代并推进一次；相同完整请求只幂等读回且不推进；
4. 同键异义以及同一数字键跨场景/存在入口冲突；统一账不得混淆两个宿主形状；
5. 同一存在连续至少两轮换代，每轮都以最新当前见证为输入；较早两值只从历史入口读取，当前槽只指最后值；
6. 两个不同存在或不同实例槽的不同键多线程调用，结果只能是串行成功/合法漂移集合，不产生混宿主、混槽或假成功；
7. 旧基线竞争、错误当前值、错误宿主/定义/槽/两关系、初始场景槽、P7归属关系、P9见证节点、错误来源、越界值逐项零写入；
8. P7/P8 未实现或未绑定、P8 未找到/登记未加载/坏成功、P2 未找到、L1 资源失败、映射损坏、发布后读回漂移和未知异常逐项结构化分账；
9. 现行场景建立、读取和换代矩阵保持通过；场景 DTO/入口签名不变，P8 两个存在入口签名不变；
10. 生产代码对旧句柄/仓、WORLD-TREE、P6、P9、SQL、材料、日志和状态/动态服务调用为零；
11. Debug/Release x64 Rebuild、两配置完整自检、`check_specs.py --strict`、MSVC 模块扫描、目标和 cached diff check 通过。
