## 1. 目标与完成边界

本设计把已经进入 4151 v0.5、4242 v0.7、5170 v0.4、6120 v0.17、8200 v2.1 的机器合同落实为一个单一代码叶：

1. 为现行 `二次关系求值应用服务`实现第三种强类型来源“本能根目标合同值”，且只准入已成立 RC 的`求值二次关系`入口；
2. 建立只读的 G4-A 双根复核 provider，在同一 `G0`分别形成安全根、服务根的`M-current`；
3. 将合法双根结果收束为`正差距`或`当前满足`，把全部来源、比较和当前性失败保留为结构化技术非成功；
4. 物理退出从未被生产消费的旧根复核预算、二态投影和 v1 端口骨架；
5. 在普通应用内形成唯一 provider 所有权和只读取得入口，但不注入自我线程、不开放治理运行门。

本包不实现根治理意图 sink、任务 manager/worker、治理邮箱消费、消息循环、任务建立、需求发布、执行前判断、治理门开放或自我治理完整闭环。普通需求仍按自身目标合同允许增加、减少、方向相反及其它正式结果；本设计的两态业务成功限制只属于安全根、服务根。

## 2. 当前事实与单包裁决

### 2.1 已有能力

- `需求类数据服务::读取本能根材料`已经能在指定 `G0`按根角色和根形成实际 F 完整读回 D、列表项、目标合同、目标值事实、`I64_MAX`及创建截止；不得新增第二需求读取入口。
- `存在类数据服务::读取当前采用完整_v2`能够按 `E + FT + G0/H`读取当前采用 F。
- `二次关系求值应用服务`已经完成 F/B、FC、EC、固定 K、当前 K、RC 和公开比较提供者的读取与后置校验，但当前来源联合只有 F/B。
- 普通应用唯一持有需求服务、存在服务、双根 RC 初始化交付和二次关系求值器；求值器全仓只有这一处生产构造。
- 旧`自我线程根复核读取预算_v1`、旧满足/未满足投影、请求、结果和端口没有实现者、成员、注入或调用者，可以同包物理退出；`自我线程根需求复核消息_v1`及邮箱提交是另一条仍在使用的合同，必须保留。

### 2.2 为什么必须单包

目标来源扩展改变求值器公开来源联合、见证联合及构造依赖；G4-A provider是该第三来源的第一个正式生产消费者，并与它共享普通应用装配和双根专项夹具。拆开会产生“公开 ABI 已扩展但没有合法业务消费者”或“provider 存在但无法构造 M”的中间态，因此合并为一个代码包。sink、治理门和 manager 不共享本包的冻结合同，继续作为后继目标。

## 3. 4242 目标合同值来源适配

### 3.1 公开 DTO

在`海中鱼巣/业务/计算.二次关系求值.h`严格实现 4242 第 7 节的类型，不增减字段：

```cpp

  本能根角色 角色 = 本能根角色::安全;
  稳定编码 根需求{}, 根目标合同{}, 目标值事实{};
  特征信息身份 对应实际特征;
};

using 二次关系特征来源 = std::variant<
    二次关系准确F来源,
    二次关系状态端点来源,
    二次关系本能根目标合同值来源>;

struct 二次关系本能根目标合同值见证 final {
  本能根材料 根材料;
  存在当前采用事实 根形成采用;
};
```

`二次关系准确来源见证::内容`扩为：

```cpp

             状态内容事实,
             二次关系本能根目标合同值见证> 内容;
```

不得恢复已删除的`二次关系判断结果::成功()`，不得给请求添加裸目标值、调用方自报 FT 或读取预算。

### 3.2 求值器构造依赖

构造函数在现有八项依赖中，于特征值服务之后、比较提供者之前增加：

```cpp
const 需求类数据服务&
```

类内保存`const 需求类数据服务& 需求_`。构造时额外要求`需求_.绑定于(l1_)`；无效装配抛`std::invalid_argument`。需求服务仅用于现有`读取本能根材料`和同底座核验，不新增 owner、写端口、持久结构或 DATA provider。

### 3.3 三分支解析

现有“若为 F，否则当作 B”的二分支写法必须全部改为显式 F、B、目标三分支，至少覆盖：来源身份提取、参与者形状检查、来源解析、见证形状校验、来源段后置校验和异常分支。

目标来源解析顺序固定为：

1. 要求`H == Gread`，角色只能为安全或服务，D、目标合同、目标值事实、对应实际 F 和参与 E 均非零；
2. 以`{本能根材料合同版本,Gread,角色,对应实际特征}`调用`需求类数据服务::读取本能根材料`；
3. 要求结果成功、读取截止等于 `Gread`，并逐项精确匹配请求回显的 D、目标合同、目标值事实和对应实际 F；目标 I64 只能取材料中的正式值；
4. 在请求 `Gread`完整读取对应实际 F，取得正式 FT；不把该 F 的准确值当作目标值；
5. 以根材料的`创建事实代次`为 H、请求 `Gread`为 G，调用`存在类数据服务::读取当前采用完整_v2`，要求参与 E 当时对该 FT 的采用 F 正是根材料的对应实际 F；
6. 在请求截止 `Gread/Gread`独立读取参与 E 的身份来源见证；
7. 形成准确来源见证：`值=根材料.目标I64值`，`内容=目标合同值见证`，公共`绑定`和公共`采用`均为空。

根形成 F 只证明 FT 与形成时适用。即使 `Gread` 时该 E 已经采用同 FT 的新 F，目标来源仍必须成功。

同一参与者来源组仍必须单一分支，F/B/目标三类不得混用；解析完成后同方同 FT 只能有一项。目标来源只允许`求值二次关系`，`求值候选定义`、`求值特征概念`、`求值存在概念`在任何读取前发现目标来源即返回`入口拒绝`，且三组成功载荷为空。

### 3.4 通用求值器不取得双根方向语义

求值器继续按 RC/K 的有序角色计算，物理左为 B、右为 A，`difference(B,A)=A-B`。它不得硬编码“A 永远是目标”或“负差永远非法”；普通需求、其它 RC 和 F/B 求值语义不变。只有后述 G4-A provider 固定：

```text
A = 本能根目标合同值来源
B = 当前准确 F 来源
A.E == B.E == self
difference(B,A) = M - current
```

## 5. Provider 物理合同与算法

### 5.1 类和构造

```cpp
class 自我根需求复核提供者 final
    : public 自我线程根需求复核端口 {
public:
  自我根需求复核提供者(
      const L1事实基座服务&,
      const 需求类数据服务&,
      const 存在类数据服务&,
      const 二次关系求值应用服务&,
      const 本能双根二次关系概念初始化结果&);

  自我线程根需求复核结果_v2 复核双根当前需求(
      const 自我线程根需求复核请求_v2&) const noexcept override;

  bool 绑定于(const L1事实基座服务&) const noexcept;
  bool 使用需求服务(const 需求类数据服务&) const noexcept;
  bool 使用存在服务(const 存在类数据服务&) const noexcept;
  bool 使用求值服务(const 二次关系求值应用服务&) const noexcept;
};
```

禁止默认构造、复制和移动。构造只借用同一 L1 的需求、存在和求值服务；要求 RC 初始化结果成功，复制安全/服务各自 FT、K、RC 稳定身份作为进程内不可变角色锚点。安全/服务 FT、K、RC必须分别不交叉，共享通用 EC 不构成冲突。构造不读取或写入事实；绑定错误抛`invalid_argument`。

### 5.2 每次调用顺序

1. 校验 v2 请求、fresh 正式上下文、触发定位、来源消息和原请求；固定`G0=请求.上下文.Gread`。
2. 分别以上下文中安全/服务的根形成实际 F 调用`读取本能根材料`，要求角色、D、列表项、根形成 F、目标合同和 G0 与上下文精确一致；要求目标值为`I64_MAX`。
3. 对每根使用构造期锁定 FT，以`E=self,FT,Gread=H=G0`调用`读取当前采用完整_v2`，取得本轮当前 F。不得用根形成 F 或消息值替代；当前 F 可以不同于根形成 F。
4. 为每根构造 RC 请求：A 只有一项根目标来源，回显角色、D、目标合同、目标值事实和根形成 F；B 只有一项当前准确 F 来源；两边 E 都是 self；RC 使用构造期锁定身份；`Gread=H=G0`，请求身份使用外层原请求身份。
5. 先安全、后服务调用现有`求值二次关系`。任一技术非成功立即映射，清空双根投影；不把失败改成未满足。
6. 对成功求值结果执行 G4-A 专属后置解释：A/B反置或任一身份/角色/来源交叉为`入口拒绝`；见证内部矛盾为`内部不一致`；正差命中形成`正差距`；零差且仅正域不命中形成`当前满足`；负差、FC/EC失败却返回不命中、错误域或第三种业务方向全部为技术非成功。
7. 两根完成后调用`需求类数据服务::核验当前事实代次(G0)`作尾守卫；漂移则清空双投影并返回当前性漂移。
8. 返回同 G0 的双根完整投影，零事实写入。

### 5.3 失败映射

| 下层/条件 | G4-A 状态 |
| --- | --- |
| 坏版本、零身份、触发定位错误、A/B反置、请求角色或来源混用 | `入口拒绝` |
| 根材料、当前采用、当前 F 或必要形成见证未找到/不完整 | `材料不足` |
| 求值`规则不支持`，或非 I64/旧格式 | `规则不支持` |
| 根材料、采用、求值或尾守卫漂移 | `当前性漂移` |
| 历史采用/特征材料已清理 | `历史材料不可用` |
| RC/根材料/概念正式退役 | `退役不可用` |
| FT冲突 | `类型不相容` |
| 单位或量化不相容 | `单位量化不相容` |
| 参照要求不相容 | `参照不相容` |
| 比较差异不可表示 | `运算溢出` |
| 分配、长度或下层资源失败 | `资源失败` |
| 旧预算不足、成功材料冲突、目标不是`I64_MAX`、合法根负差、双根交叉、成功见证不完整 | `内部不一致` |

`二次关系判断状态::不命中`不是技术失败，但只有“差异为0、FC/EC命中、正域未命中”才能解释为当前满足；其它不命中形状均转技术非成功。
