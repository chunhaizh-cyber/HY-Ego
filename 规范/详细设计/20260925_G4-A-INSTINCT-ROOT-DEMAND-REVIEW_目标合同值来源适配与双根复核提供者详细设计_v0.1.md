## 1. 目标与完成边界

本设计把已经进入 4151 v0.5、4242 v0.7、5170 v0.4、6120 v0.17、8200 v2.1 的机器合同落实为一个单一代码叶：

1. 为现行 `二次关系求值应用服务`实现第三种强类型来源“本能根目标合同值”，且只准入已成立 RC 的`求值二次关系`入口；
2. 建立只读的 G4-A 双根复核 provider，在同一 `G0`分别形成安全根、服务根的`M-current`；
3. 将合法双根结果收束为`正差距`或`当前满足`，把全部来源、比较和当前性失败保留为结构化技术非成功；
4. 物理退出从未被生产消费的旧根复核预算、二态投影和 v1 端口骨架；
5. 在普通应用内形成唯一 provider 所有权和只读取得入口，但不注入自我线程、不开放治理运行门。

本包不实现根治理意图 sink、任务 manager/worker、治理邮箱消费、消息循环、任务建立、需求发布、执行前判断、治理门开放或自我治理完整闭环。普通需求仍按自身目标合同允许增加、减少、方向相反及其它正式结果；本设计的两态业务成功限制只属于安全根、服务根。

## 2. 当前事实与单包裁决

### 2.1 已有能力

- `需求类数据服务::读取本能根材料`已经能在指定 `G0`按根角色和根形成实际 F 完整读回 D、列表项、目标合同、目标值事实、`I64_MAX`及创建截止；不得新增第二需求读取入口。
- `存在类数据服务::读取当前采用完整_v2`能够按 `E + FT + G0/H`读取当前采用 F。
- `二次关系求值应用服务`已经完成 F/B、FC、EC、固定 K、当前 K、RC 和公开比较提供者的读取与后置校验，但当前来源联合只有 F/B。
- 普通应用唯一持有需求服务、存在服务、双根 RC 初始化交付和二次关系求值器；求值器全仓只有这一处生产构造。
- 旧`自我线程根复核读取预算_v1`、旧满足/未满足投影、请求、结果和端口没有实现者、成员、注入或调用者，可以同包物理退出；`自我线程根需求复核消息_v1`及邮箱提交是另一条仍在使用的合同，必须保留。

### 2.2 为什么必须单包

目标来源扩展改变求值器公开来源联合、见证联合及构造依赖；G4-A provider是该第三来源的第一个正式生产消费者，并与它共享普通应用装配和双根专项夹具。拆开会产生“公开 ABI 已扩展但没有合法业务消费者”或“provider 存在但无法构造 M”的中间态，因此合并为一个代码包。sink、治理门和 manager 不共享本包的冻结合同，继续作为后继目标。

### 3.2 求值器构造依赖

构造函数在现有八项依赖中，于特征值服务之后、比较提供者之前增加：


类内保存`const 需求类数据服务& 需求_`。构造时额外要求`需求_.绑定于(l1_)`；无效装配抛`std::invalid_argument`。需求服务仅用于现有`读取本能根材料`和同底座核验，不新增 owner、写端口、持久结构或 DATA provider。

### 3.3 三分支解析

现有“若为 F，否则当作 B”的二分支写法必须全部改为显式 F、B、目标三分支，至少覆盖：来源身份提取、参与者形状检查、来源解析、见证形状校验、来源段后置校验和异常分支。

目标来源解析顺序固定为：

1. 要求`H == Gread`，角色只能为安全或服务，D、目标合同、目标值事实、对应实际 F 和参与 E 均非零；
2. 以`{本能根材料合同版本,Gread,角色,对应实际特征}`调用`需求类数据服务::读取本能根材料`；
3. 要求结果成功、读取截止等于 `Gread`，并逐项精确匹配请求回显的 D、目标合同、目标值事实和对应实际 F；目标 I64 只能取材料中的正式值；
4. 在请求 `Gread`完整读取对应实际 F，取得正式 FT；不把该 F 的准确值当作目标值；
5. 以根材料的`创建事实代次`为 H、请求 `Gread`为 G，调用`存在类数据服务::读取当前采用完整_v2`，要求参与 E 当时对该 FT 的采用 F 正是根材料的对应实际 F；
6. 在请求截止 `Gread/Gread`独立读取参与 E 的身份来源见证；
7. 形成准确来源见证：`值=根材料.目标I64值`，`内容=目标合同值见证`，公共`绑定`和公共`采用`均为空。

根形成 F 只证明 FT 与形成时适用。即使 `Gread` 时该 E 已经采用同 FT 的新 F，目标来源仍必须成功。

同一参与者来源组仍必须单一分支，F/B/目标三类不得混用；解析完成后同方同 FT 只能有一项。目标来源只允许`求值二次关系`，`求值候选定义`、`求值特征概念`、`求值存在概念`在任何读取前发现目标来源即返回`入口拒绝`，且三组成功载荷为空。

### 3.4 通用求值器不取得双根方向语义

求值器继续按 RC/K 的有序角色计算，物理左为 B、右为 A，`difference(B,A)=A-B`。它不得硬编码“A 永远是目标”或“负差永远非法”；目标合同值来源在通用 4242 `求值二次关系`中可按具体 RC/K 作为 A 或 B，通用求值器不得因它位于 B 而拒绝。普通需求、其它 RC 和 F/B 求值语义不变。只有后述 G4-A provider 的请求构造与 G4-A 专属后置校验固定：

```text
A = 本能根目标合同值来源
B = 当前准确 F 来源
A.E == B.E == self
difference(B,A) = M - current
```

因此“A/B 反置”不是 4242 通用入口的非法形状，也不进入通用求值器失败映射。G4-A provider 不接收调用方给出的 A/B；它必须自行构造上述唯一顺序，并在消费返回见证时拒绝任何与该顺序不一致的结果。该拒绝属于 G4-A 后置合同，不修改 4242 的通用角色语义。

## 5. Provider 物理合同与算法

### 5.1 类和构造

```cpp

    : public 自我线程根需求复核端口 {
public:
  自我根需求复核提供者(
      const L1事实基座服务&,
      const 需求类数据服务&,
      const 存在类数据服务&,
      const 二次关系求值应用服务&,
      const 本能双根二次关系概念初始化结果&);

  自我线程根需求复核结果_v2 复核双根当前需求(
      const 自我线程根需求复核请求_v2&) const noexcept override;

  bool 绑定于(const L1事实基座服务&) const noexcept;
  bool 使用需求服务(const 需求类数据服务&) const noexcept;
  bool 使用存在服务(const 存在类数据服务&) const noexcept;
  bool 使用求值服务(const 二次关系求值应用服务&) const noexcept;

```

禁止默认构造、复制和移动。构造只借用同一 L1 的需求、存在和求值服务；要求 RC 初始化结果成功，复制安全/服务各自 FT、K、RC 稳定身份作为进程内不可变角色锚点。安全/服务 FT、K、RC必须分别不交叉，共享通用 EC 不构成冲突。构造不读取或写入事实；绑定错误抛`invalid_argument`。

### 5.2 每次调用顺序

1. 校验 v2 请求、fresh 正式上下文、触发定位、来源消息和原请求；固定`G0=请求.上下文.Gread`。请求版本、上下文、触发定位或全局身份不合法属于全局入口拒绝，可以在进入任一根前返回；两项单根技术状态保持`未复核`。
2. 建立两个互不共享成功载荷的局部单根结果槽，按安全、服务顺序执行同一个单根复核过程。该固定顺序只用于确定执行与诊断顺序，不授予安全根短路服务根的资格。
3. 每根以上下文中的根形成实际 F 调用`读取本能根材料`，要求角色、D、列表项、根形成 F、目标合同和 G0 与上下文精确一致；要求目标值为`I64_MAX`。随后用构造期锁定 FT，以`E=self,FT,Gread=H=G0`调用`读取当前采用完整_v2`取得本轮当前 F。不得用根形成 F 或消息值替代；当前 F 可以不同于根形成 F。
4. 为该根构造唯一 RC 请求：A 只有一项根目标来源，回显角色、D、目标合同、目标值事实和根形成 F；B 只有一项当前准确 F 来源；两边 E 都是 self；RC 使用构造期锁定身份；`Gread=H=G0`，请求身份使用外层原请求身份。G4-A 不接收调用方提供的 A/B，因而反置只能由构造错误或返回见证错位暴露，并由本 provider 后置拒绝；通用 4242 求值器不得增加这一拒绝。
5. 调用现有`求值二次关系`并把真实技术结果写入该根技术状态。普通单根技术非成功只终止该根的局部过程，不终止另一根：材料不足、规则不支持、历史材料不可用、运算溢出、退役、类型/单位/参照不相容及单根内部不一致均继续复核另一根。只有三类全局条件允许提前停止：请求整体非法；任一读取得到可确认的同一`G0`事实代次漂移；`std::bad_alloc`、`std::length_error`或下层资源失败已经使本次调用无法继续持有/完成另一根必要材料。提前停止时尚未进入的根保持`未复核`，已进入根保留真实状态。
6. 对成功求值结果执行 G4-A 专属后置解释：必须逐项验证来源组恰2项且顺序为 A目标/B当前F、条件组恰1项且条件 A/B 对应来源；反置或身份/角色/来源交叉为该根`入口拒绝`，见证内部矛盾为该根`内部不一致`；正差命中形成局部`正差距`，零差且仅正域不命中形成局部`当前满足`；负差、FC/EC失败却返回不命中、错误域或第三种业务方向全部为该根技术非成功。
7. 若未因全局漂移或不可继续资源失败提前停止，则无论首根是否普通技术失败都必须完成第二根复核。两根过程结束后调用`需求类数据服务::核验当前事实代次(G0)`作尾守卫；漂移时总状态为当前性漂移并清空双投影，但保留两项已经取得的单根技术状态用于诊断。
8. 仅当两项单根技术状态均为`已复核`且两个局部业务投影都通过完整性与交叉核验时，才同时发布到结果的安全根/服务根字段并返回`已复核`。否则两项业务投影同时为空；总状态按安全根、服务根固定顺序选择首个非`已复核`且非`未复核`状态，若只有`未复核`则使用对应全局提前停止状态。全调用零事实写入。

### 5.3 失败映射

| 下层/条件 | G4-A 状态 |
| --- | --- |
| 坏版本、零身份、触发定位错误、G4-A 自构造顺序错误或返回见证 A/B 与其自构造来源反置、请求角色或来源混用 | `入口拒绝` |
| 根材料、当前采用、当前 F 或必要形成见证未找到/不完整 | `材料不足` |
| 求值`规则不支持`，或非 I64/旧格式 | `规则不支持` |
| 根材料、采用、求值或尾守卫漂移 | `当前性漂移` |
| 历史采用/特征材料已清理 | `历史材料不可用` |
| RC/根材料/概念正式退役 | `退役不可用` |
| FT冲突 | `类型不相容` |
| 单位或量化不相容 | `单位量化不相容` |
| 参照要求不相容 | `参照不相容` |
| 比较差异不可表示 | `运算溢出` |
| 分配、长度或下层资源失败 | `资源失败` |
| 旧预算不足、成功材料冲突、目标不是`I64_MAX`、合法根负差、双根交叉、成功见证不完整 | `内部不一致` |

`二次关系判断状态::不命中`不是技术失败，但只有“差异为0、FC/EC命中、正域未命中”才能解释为当前满足；其它不命中形状均转技术非成功。

上述映射逐根执行并写入对应单根技术状态。除全局请求非法、同一G0漂移和不可继续资源失败外，安全根映射失败不得阻止服务根复核，服务根映射失败也不得删除已经形成的安全根技术状态；但任何一根失败都会使最终两个业务投影同时为空。

```cpp
自我根需求复核提供者*
```

getter只返回普通应用唯一实例，不创建第二 provider。不得把该 provider传给`自我线程::创建并停在治理运行门`，不得调用`复核前置并开放治理运行门`，不得消费邮箱或增加成功治理批次。

1. `验证工具/自我线程正式上下文提供者专项验证.vcxproj`保留既有项目身份、入口和断言，只在原`ClCompile`组补登记：

   - `..\海中鱼巣\业务\计算.二次关系求值.cpp`；
   - `..\海中鱼巣\业务\应用服务.自我根需求复核.cpp`。
2. `验证工具/本能根运行锚点组合提供者专项验证.vcxproj`保留既有项目身份、入口和断言，只在原`ClCompile`组补登记：
   - `..\海中鱼巣\领域\合同.二次关系概念.cpp`。

上述四项只修复两个既有隔离专项的链接依赖闭包，不新增验证工程、不改变生产源、公开头、机器语义、生产 ABI、专项项目 GUID/名称/配置、验证入口、断言或完成条件。不得借工程登记扩大到其它源文件；若补齐后仍出现新的未解析生产依赖，必须以精确符号和提供源再次退回计划支撑，不得临场扩充白名单。

不新增验证工程；复用`本能双根二次关系概念初始化专项验证.cpp`的真实普通应用夹具覆盖目标来源和 G4-A provider。现有 F/F、候选、FC、EC 回归必须保留。

验证严格分成三层，三层结论不得互相升级：

### 7.1 合法夹具运行验证

只使用公开入口可合法建立的普通应用事实和现有专项夹具，覆盖：安全、服务各自目标来源成功；根形成 F 后当前 F 换代，目标来源仍成功且 B 使用新当前 F；正差距`M-floor(M/2)`精确值；`current=M`当前满足；双根同 G0、身份不交叉；调用前后事实代次不变和零持久写；普通应用 getter 唯一；重复装配与现有 ordinary-seed/ordinary-recover 恢复路径；治理门仍关闭、邮箱零消费、sink/manager零调用。合法公开请求可以构造的错 E、错角色/D/合同/值事实/形成F、`H<Gread`、来源混用、重复同FT、目标来源进入候选/FC/EC也在本层断言其结构化拒绝。

本层还必须有“首根普通技术失败仍复核次根”的可观察断言：使用合法坏请求使安全根产生可达的普通技术非成功，确认服务根技术状态不是`未复核`；交换根失败位置再次验证。两种情况下安全根/服务根业务投影均同时为空，且两个单根技术状态准确定位失败。不得为了得到某状态写入违反公开不变量的损坏事实。

### 7.2 静态分支核验

对无法由合法公开夹具构造但必须存在的防御分支，逐项核对源码控制流与返回收口：G4-A 自构造 A/B 反置或求值见证错序、来源组不等于2、条件组不等于1、条件 A/B 与来源组错位、成功材料冲突、负差、错误域、FC/EC 失败却返回不命中、运算溢出、历史清理、退役、类型/单位/参照不相容、不可继续资源异常及尾守卫漂移。静态核验必须确认普通单根失败继续另一根、只有全局非法/G漂移/不可继续资源失败可提前、任一失败最终清空两项业务投影、通用4242没有目标来源位于B即拒绝的分支。

同时静态确认：旧根复核预算、旧二态 DTO/端口零引用；`二次关系判断结果::成功()`继续零命中；provider唯一构造且未注入self；三份外部流程图不在 staged diff。静态核验只证明分支形状和引用关系，不证明该分支已运行。

### 7.3 明确未覆盖

本计划不宣称通过合法运行触达损坏事实、成功见证自相矛盾、强制内存分配失败、发布中途硬故障、任意跨进程故障注入或生产长期运行；也不覆盖 self 消费、sink、manager/worker、治理门开放、消息循环、根治理任务或端到端自我治理。无法合法触达的分支不得用测试钩子、mock ABI、直接写L1损坏事实或新增公开入口伪造为运行覆盖。

执行时以 `D:\TEMP\海中鱼巣\G4-A-INSTINCT-ROOT-DEMAND-REVIEW\<本轮唯一标识>`隔离 Debug/Release x64 输出。至少 Rebuild 并运行双根专项，回归运行本能根运行生产消费、世界树根启动、二次关系结构、自我线程上层骨架、自我线程正式上下文和本能根运行锚点组合专项；根工程 Debug/Release x64 隔离 Rebuild。全部实际运行的具名断言须 PASS、FAIL 为0，构建错误为0；报告必须把运行覆盖、静态核验和未覆盖三类分别列出。
