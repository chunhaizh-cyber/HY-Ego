# LANGUAGE-SCENE-S01-BIDIRECTIONAL 空白语言场景 S01 归类双向详细设计

日期：2026-10-16。版本：v0.1。代码起点：`a085fdc0df4ae0f321be26dcd1b55d8d71daa3d8`。本文件冻结首个可交付叶，不把一个叶的完成称为全部基础句型完成。

## 1. 目标、裁决与边界

本叶处理单个汉语 S01 `E1 是 C1` 构式，例如原文 `杯子是容器`（带空格的 `杯子 是 容器` 只是结构展示）。左侧完整词条唯一指向一个**抽象存在概念**后，才在本次新建的空白自然语言场景内经现有 `新_自然语言世界树类::实例化概念` 建立一个名称为空的匿名 E；右侧完整词条唯一指向一个抽象存在概念。结果中的调用期含义项为“该 E 被陈述归类为右侧 C”，附原文、词出现、知识、名称关系、角色、作用域和对齐。此项是有来源的语言陈述，不证明归类真实，也不写现实树、概念支持边、正式特征、任务或方法。没有交互上下文、跨句回指、现实采信、形容词修饰或代词。

用户本轮具名裁决允许在**空白语言场景**按唯一类名形成匿名 E。7250 S01 的“不自动创建实例/支持关系”继续约束一般只读解释和现实事实；本叶以显式语言场景保存步骤形成 E，不把该例外外推到现实场景。7240 §1、§4 将调用期解释、按请求保存语言场景和现实裁决分开；7230 §3.3 允许本次含义与对齐默认保持值式。本叶只持久建立场景与 E，**不持久保存 S01 主张或语言记录**；丢失调用期含义项后，仅凭场景 E 不能重建右侧 C 或原文，后继若需要历史复述须另建语言 owner 的采用解析/主张保存合同。

总目标仍是空白自然语言场景内各基础单短语/句型的双向信息转换。本叶只闭合 S01 的无修饰、无指代、各角色恰为一个完整已登记词条的形态；S03、S05、单纯短语、同句多出现的关系、其它世界和生产交互接线均在本叶之外。未来 `杯子挨着杯子` 的两个词出现必须分别实例化，即使来源概念相同也不能按概念节点合并 E；本叶的出现编号、角色与范围按**出现**而非概念键定位，为后续多出现扩展留下边界。

正式依据：[0050](../0050_项目通用机器逻辑与禁止性规则总纲_20260721.md) §3.2、[1100](../1100_根规范_语言记录_20260720.md)、[2210](../2210_根规范_概念名称关系.md) §3—4、[2340](../2340_根规范_自然语言知识.md)、[7200](../7200_子规范_词条概念候选与上下文消歧.md)、[7210](../7210_子规范_语言候选与对象领域路由.md)、[7230](../7230_子规范_语言材料知识与交互字段.md) §3.3、[7240](../7240_子规范_自然语言双向转换与组织规则.md) §1/§4、[7250](../7250_子规范_最小汉语知识与语言学习.md) S01。旧知识枚举预算 ABI 尚未迁移；本叶只对该 ABI **确实完整枚举**的请求交付成功，额度不足返回非成功，绝不截断后宣布唯一。

## 2. 当前代码与复用

`新_语言类::按已登记词条最长匹配` 返回 UTF-8 原文字节与 Unicode 标量范围；`新_词类::获取词条`、`概念_名称关系类::查询词条候选概念/获取名称关系/查询概念名称`、`概念_存在类::获取存在概念` 与指代名称读回提供正式词条、名称、概念。`新_语言类::枚举语言知识候选/获取语言知识` 提供已发布 S01 结构；不以固定字符串建立第二套知识。`新_自然语言世界树类::建立空场景/实例化概念/获取场景/获取概念实例` 已有独立语言场景和可重复概念实例；后者每调用一次建新 E，实例没有语言专名。`解释单句基础归类`及`语言候选路由业务::形成候选`目前固定现实世界根与现实 E 检索，不能把语言场景根伪装成现实根调用，也不能以它们的 `主体待绑定` 当本叶写入许可。本叶在 DATA 外新建一对 S01 业务入口，共用现行结构服务，不复制词条、名称、概念或场景 owner。

新头源位置为 `海中鱼巣/业务/转换.语言场景归类.h/.cpp`；头文件声明两公开函数及值式 DTO，源文件内私有 `只读解释语言场景S01(...)` 供输入前置与输出回读共用。工程在根 `海中鱼巣.vcxproj` 及 `.filters` 登记。没有独立持久路由表、第二语言知识仓或普通应用生产调用。

`解释原文范围`复用现有零基、半开 Unicode 标量 DTO；输入两个出现的局部编号固定为 1、2，分别绑定 E1 和 C1，固定词“是”另在只读解释快照中记录其词条与范围。含义作用域只能为`普通陈述`。`未核验来源语言记录节点`仅原样回显，不参与成功证明；正式来源是本次固定原文与范围，尚未形成可恢复语言记录。候选必须保留两侧全部相容概念/名称关系/知识和各自范围，确定排序；多义时没有场景、实例和含义。输出成功才填文本与对齐，非成功文本为空。

## 4. 正向和反向流程

1. **只读解释**：核验正式语言、严格 UTF-8 和非空原文，完整匹配已登记词条。首版只接受 S01 知识的三项有序结构：左侧名称表达、固定“是”、右侧名称表达；原文全部被三个已登记词条覆盖，或仅在三个词条之间有 ASCII 空格分隔片段；不接受首尾空格、其它未知片段、修饰、代词、子规则及标点。空间写法与无空格写法保留各自真实原文范围。枚举知识若额度不足即非成功。对两侧词条分别回读**全部**普通/指代名称候选及其目标强类型，只有抽象存在概念进入相应 E/C 角色；不丢未读完项，不能按词面或词性猜类型。完整候选按 `(所用知识, 主体概念, 归类概念, 两名称关系)` 排序；不同语义对大于一为概念多义，不同适用知识大于一为多规则，二者均零写。唯一语义且唯一规则才可进入下一步；不检查“杯子是否真是容器”。
2. **语言场景写入**：只读结果唯一后才调用既有 `建立空场景()`；已取得场景节点立即保留在结果。对左侧抽象存在概念调用既有 `实例化概念(场景,主体概念)`一次，不为右侧 C 建 E；该实例是本句这次主体出现的匿名 E。写后通过 `获取场景`、`获取概念实例`、正式主体/右侧概念及所用知识、名称关系再次读回并核对场景归属、来源概念、种类和对齐。全部一致才返回含义；右侧 C 保持**主张目标引用**，不写概念图或 E 特征值。
3. **反向生成**：仅消费上列值式含义或同合同明确绑定的调用期材料，先读回场景、E 的来源概念、右侧抽象概念、知识和两侧当前名称。逐项核验语种、词条和名称关系；按所用知识的有序结构组合候选文字，不印稳定编码，不凭概念签名造词。每个生成候选用同一私有只读解释函数完整重解析；只接纳唯一 `(主体来源概念,C1,所用知识)` 且回读的**本次选用**名称关系、角色顺序和新文字范围均一致的候选。原输入名称可以已经退出，输出不强求与旧词面相同。多个等价可回读文字按 `(UTF-8文本,主体名称关系,归类名称关系)` 稳定排序取首项；无可用项返回缺名称/名称待选/回读多义等具名状态，文本为空。回读只比较角色**来源概念**和主张目标，不要求新旧匿名 E 句柄相等，也不调用场景创建。

输入输出都不依赖对方是否理解，也不把陈述自动采纳为现实事实。左侧同一概念在两个未来出现中不能复用本次 E；本 DTO 的局部出现编号不是概念身份。反向的输入若仅给 E 而没有 C 和知识/作用域材料，返回输入拒绝，不猜历史主张。

## 5. 写后失败、验证和完成声明

词条/知识/名称/概念读取技术失败、读取漂移或候选不完整均在建场景之前退出。`建立空场景`若失败，透传状态且不报告实例；若已建场景而实例建立/核验失败，返回`已取得场景节点`和实际可确认的`已取得实例节点`，不伪称零副作用或已形成含义，不在业务层擅自删除已有节点。`实例化概念`自身的补偿由其 owner 负责，业务层不能假定失败必然回滚干净；不明确的残留进入工程诊断。输出全程只读。失败不能被翻译为“没有归类关系”或“词不表示概念”。

实施只新增上述业务头源、登记正式工程并写专属施工/编译记录；不改 `新_自然语言世界树类`、现实 S01 入口、名称/概念/词条/知识 owner、正式规范或普通应用装配。实际工程 `Debug|x64` 编译链接是本轮代码默认门槛。当前无测试指令，不运行测试、自检或启动程序；若以后获明确测试指令，优先覆盖无空格/带空格唯一输入、同词多概念/多规则零写、两个同概念出现不按 C 合并、名称退出、知识读取未完成、场景/实例写后失败、生成文字的实际回读与只读性。编译不证明运行、恢复、历史主张保存、生产交互或所有句型互逆。
