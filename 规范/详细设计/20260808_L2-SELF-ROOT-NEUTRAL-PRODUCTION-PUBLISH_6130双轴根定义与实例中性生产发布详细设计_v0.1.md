## 1. 目标与完成边界

在完整自我已经由正式生产入口发布并读回后，建立唯一第二层双轴根服务，使生存安全轴和服务轴成为现行第一层业务中性特征定义、实例槽和当前 I64 值的真实生产消费者。

本叶完成时必须同时成立：

1. 生存安全轴和服务轴各有一个 `0..I64_MAX` 的 I64 特征定义；
2. 当前完整自我分别拥有上述两个定义的唯一实例槽；
3. 生存安全初值固定为 `A=1`，服务初值固定为 `V=0`；
4. 两个当前值的来源节点均为当前完整自我；
5. 只经现有 `L1特征定义服务` 和 `L1实例特征服务` 完成发布与正式读回，新增代码对 `L1事实基座服务` 和仓库直接调用为零；
6. 生产候选只有在双定义、双实例和一次公开读回逐字段互证成功后才可继续旧兼容初始化并最终发布运行期上下文；
7. 旧系统角色双轴根组只保留为尚未迁移消费者的 `legacy` 兼容材料，任何本叶新增代码不得读取、解释或写入它。

本叶不形成 6130 完整治理定义，不承载低位阈值、高位阈值、主动安全结算规则、被动服务维护规则、根需求、目标状态、状态、动态、因果或结算；这些字段继续由对应第二至第五层合同拥有。

## 2. 正式依据与当前事实

- `4015`、`4030`：第一层只提供业务中性 CRUD；第二至第五层拥有业务准入和结果解释。第一层不自证，实际调用只是消费者运行的自然证据。
- `6120`：生存安全根值使用 I64 `0..I64_MAX`，`0` 为终止态，`1` 为休眠态，`A>1` 才允许普通主动运行；服务值使用 I64 `0..I64_MAX`。
- `6130`：安全和服务必须具有抽象根特征定义、自我实例槽和当前值，不能只由清单或显示字段代替。
- `7130`：自我实例槽统一使用特征领域关系 22 结构，完整自我聚合入口不得直接写实例槽。
- 当前 `L1特征定义服务` 已提供 const `建立I64特征定义`、`读取I64特征定义`；当前 `L1实例特征服务` 已提供 const `建立实际存在I64实例特征`、`读取实际存在I64实例特征`。
- 当前 `完整自我当前事实` 已包含形成 `实际存在读取请求` 所需的世界根、自我所在场景、场景标记、直接父关系、自我存在、资格值和当前场景归属关系，无需扩展第一层或实际存在服务。
- 当前旧 `系统角色初始化器::创建根需求组` 仍被旧程序宿主、自我治理和需求链消费，不能在本叶直接物理删除；但它不再取得新链机器语义权威，也不得成为新双轴根的读取来源。

## 5. 发布顺序、幂等与失败收敛

`发布自我双轴根` 在私有锁内执行：

1. 校验请求和完整自我，形成自我实际存在读取请求；
2. 若已有完整结果：同请求且同自我返回 `幂等读回`，不同请求或不同自我返回 `幂等冲突`；
3. 以调用时完整自我截止为期望代次，调用安全定义建立；成功后保存定义定位和结果；
4. 以上一步结果截止为期望代次，调用服务定义建立并保存；
5. 以上一步结果截止建立安全实例，初值 1，来源为自我；
6. 以上一步结果截止建立服务实例，初值 0，来源为自我；
7. 用四个底层结果形成定位，调用同类私有读回路径；
8. 只有读回四项共同截止、逐字段完整且与发布结果一致时保存完整结果并返回 `已提交` 或 `幂等读回`。

服务在每个成功底层步骤后保留定位和请求。发生资源失败、代次漂移或其它结构化非成功时不伪造完整结果；同请求重入跳过已经成功且已缓存的步骤，从最早未完成步骤继续。当前阶段不考虑进程崩溃，缓存不承担跨进程恢复。

底层状态按以下原则映射：

- 登记未加载、未找到：`前置不满足`；
- 入口拒绝：`入口拒绝`；
- 幂等冲突：`幂等冲突`；
- 事实代次漂移：`事实代次漂移`；
- 资源失败：`资源失败`；
- 坏成功形状或其它无法解释状态：`内部不一致`。

## 6. 正式当前读回

`读取当前自我双轴根` 必须：

1. 验证当前完整自我仍与首次自我稳定编码一致；
2. 若尚无完整定位返回 `前置不满足`；
3. 分别经现有特征定义服务读取两个定义；
4. 分别经现有实例特征服务读取两个实例；
5. 要求四项读取截止相同、宿主相同、定义和值域/初值/来源与双轴合同一致；
6. 成功返回 `已读取`，任何坏成功或交叉轴混淆返回 `内部不一致`。

该读回不直接调用第一层，不读取完整快照，不扫描全仓，不访问旧根组，不解析日志。

### 7.2 启动顺序

生产顺序固定为：

```text

-> 双轴根发布
-> 双轴根公开读回并与发布结果逐字段相等
```
