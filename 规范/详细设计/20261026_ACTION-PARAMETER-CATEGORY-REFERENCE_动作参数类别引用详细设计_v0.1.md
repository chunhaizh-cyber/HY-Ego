## 1. 目标与范围

本叶只将动作概念定义中有序参数的类别，从旧I64派发hint改为正式存在/特征类别根引用。修改的是概念owner的声明结构，不改变现实或任务/方法虚拟存在特征值，不生成动作事实、C/R或效果。

公共`动作概念定义`、`新方法有序参数规格`、`动态概念信息`和投影服务接口均不改。旧角色格式、旧有序v2合法读取及同义复用保留，不迁移已有动作C或历史动作。D/T/M通用参数、其它类别、模拟业务、实例动作、任务筹办、名称与特征根定义不施工。

## 2. 当前事实与实际消费者

`编码动作定义`约899起将有序参数写为`[-1,2]`前缀、每项数字序号+枚举类型、引用仅范围。`解码动作定义`约947只接受v2，完整消费数字/引用流。`建立或取得动作概念`约1027以完整DTO查重，当前`原子建立节点`无联合预期入口。`读取动作概念定义保护`约1816只保护C/动态组织根/schema，缺类别根证明。

真实调用链为`业务/动作概念.方法投影服务.cpp::读取动作方法投影`→`新_动态类::确保动作定义概念/建立动作`→现动作概念owner；连接初始化及动作执行已消费该链。投影从方法有序规格DTO转抄，可原样复用。不得为了本叶另设业务方法、验证入口、动作参数影子节点或新底座ABI。

## 3. 唯一新布局与兼容读取

不增schema字段，复用原`动作规格形状字段`和重复`动作规格引用字段`。旧无前缀角色布局保持不变；有序布局以负标记`-1`和版本明确分派：

| 布局 | 数字流 | 规格引用流 |
| --- | --- | --- |
| 无前缀旧角色 | 原七项头＋原各角色/特征形状 | 原角色、存在、FT、域、二次C顺序 |
| v2 `[-1,2]` | 原七项头＋每参数`序号,旧类别1/2` | 每参数`范围概念` |
| v3 `[-1,3]` | 原七项头＋每参数`序号` | 每参数`类别根概念,范围概念` |

七项头仍为主体对象类别、目标对象类别、四个有值标志及规格数，含义和顺序不改。新建非空有序参数动作只写v3；零参数仍原无前缀格式，不制造空有序定义。v3不保留旧枚举数值，不把类别编码塞入I64形状。参数位置1..N连续，引用组仍按字段关系编码升序读取，恰好消费全部数字和引用。

仅明确版本2/3可读；未知版本、负标记错误、断流/溢出/尾随材料、伪布尔、错误类别引用、混入v2整数或v3额外引用均工程结构错误，不猜格式、不转默认类别。旧v2不要求新增类别根已建立，继续依原枚举1/2及原范围合法性核验；旧角色完整准入不变。

## 4. owner根证明与私有读取核心

类别映射只允许现存在owner唯一语义根、现特征owner唯一类别根。复用`读取存在根概念保护`、`读取特征类别根概念保护`；新引用必须与正式读回根身份相等，不接受任意同名概念、裸组织根、普通FT根或其他正式概念。FT类别根不能拿来作为参数范围或值域。公有枚举只作解码后的技术分派，范围和顺序仍按原`规范化动作定义`完整核验。

新增能力均在动态概念cpp匿名命名空间，无公开ABI：

```cpp
struct 动作类别前提变化 final {};
struct 动作参数类别保护 final {
    新方法参数信息类型 分派类型;
    稳定编码 类别概念;
    std::vector<基础联合节点快照> 完整保护组;
};
动作参数类别保护 读取动作参数类别保护(
    新方法参数信息类型, const 概念_存在类&, const 概念_特征类&);
动作参数类别保护 解析动作参数类别保护(
    稳定编码, const 概念_存在类&, const 概念_特征类&);
struct 动作概念读取材料 final {
    动态概念信息 信息;
    std::vector<基础联合节点快照> 类别保护组;
};

    稳定编码, const 概念_特征类&, const 概念_二次特征类&,
    const 概念_存在类*);
```

共享核心承接原getter动作分支完整形状检查、解码和规范化；v3收集实际所用根证明，v2/旧角色不额外引入类别根依赖。`解码动作定义`和编码helper相应增加owner/proof参数属于私有适配，不改领域接口。多参数重复根只合并同身份且同快照的证明；快照不同抛`动作类别前提变化`，不选较新一份掩盖采集漂移。

`获取动态概念`动作分支调用共享核心；其optional/noexcept没有“前提变化”表达，遇专门变化异常按既有工程诊断停止，**不能返回空伪装概念不存在**。`读取动作概念定义保护`直接调用可传播变化的共享核心，不先经会终止的公有getter；将类别保护与C/组织根/schema原保护合并、完整联合重读，变化映射既有`动作概念定义保护状态::前提已变化`，信息及保护均空。真正不存在仍原概念不存在；已确认正式根却损坏、未就绪、错引用走工程链，不包装前提变化。

根证明不枚举全部FT语义定义；其组织根完整快照可能随出边增长，成本未测量，不宣称恒定。

## 5. 查重、CAS发布与回执

`建立或取得动作概念`先按原规则规范化输入，按原完整DTO查重。旧角色/v2/v3同义定义复用既有C，不换C身份、不重写旧字段；复用返回空追加增量，不因当前新写v3制造第二份同义概念。查重遇v3时使用可传播前提变化的私有核心，不经公有getter吞掉专门变化。

确无同义C后：为输入实际有序类别取得完整根证明→编码v3字段→用现`基础节点组追加请求`一次追加一个C及动态组织根到C的父子role0边，预期联合组含类别根证明、动态组织根及所有所用schema/直接引用端点快照。字段初始顺序与原编码vector一致；不新增底座接口，不分次写类别字段。

原`原子建立节点`没有CAS能力，本叶**仅动作概念新建路径**改为既有`原子追加节点组`，变化概念及实例动作入口不改。语义相等仍依解码DTO，不依物理版本/形状hash。当前动态概念锁继续串行查重/新建，不引入反向方法/task回调；类别proof只调用概念owner，保持现锁顺序。

追加预期不符、类别根owner明确前提已变化或证明合并漂移，均映射既有`动态概念操作状态::状态不一致`（值8）＋空概念编码＋空追加增量。这是本次结构前提失效的非发布结果，不是方法业务失败、效果或学习知识；上层现动作调用链不得进入真实动作。原调用方遇非完成会工程报告，不在本叶增加重试、任务或学习需求。其他追加错误、正式结构损坏与读回不符仍工程终止。

具体现有消费边界：`新_动态类.cpp`约681的确保入口对非成功工程终止，约858的动作建立入口对缺概念编码工程终止。因此本叶前提变化虽然在概念owner按原状态和零载荷分账，现消费者仍会停止当前运行；本叶没有“自动重试、挂起或返回筹办”的能力，不得作此完成声明。该边界保持原消费者和零动作安全，不扩白名单修改线程/动态实例；今后如需可恢复治理，必须另行冻结消费者合同。

发布成功后不能复用发表前root快照：新类别引用已改变根的入向字段。重新读取类别根证明及C的完整定义保护，核新C身份、v3解码DTO、原字段顺序及根边role0。后置保护发生前提变化时保留已发表C、返回上述无载荷状态且输出增量保持空；下次按原输入完整查重，不盲目补造第二C。后置结构错误工程停止，不能回滚已共享定义。

仅全部完成后交付原`新事实追加保护增量`：一新C节点、完整新增字段关系组、恰一role0根边，顺序及字段内容按原编码vector/正式关系编码核对，不返回虚构字段码。类别引用本身进入该新增字段组，调用方原追加保护推进能据其准确更新目标根入向；不扩增量DTO或塞入第二权威。复用无变化增量为空，失败不返回部分回执。

## 6. 生命周期、复制与完成边界

共享动作C不是某次动作的专属变化概念。现动作删除仅解除动作→C引用并保留共享C；原变化实例概念删除保持只接变化实例，不能把v3根引用引向类别根删除。新类别根由原owner登记存续，不增加FT实例引用计数，不新建清理器、强引用账或删除入口。

当前动态概念owner没有公开动作C克隆入口；动作事实复用同C，模拟隔离路径已有自己的定义材料消费，不在本叶改造。基础完整快照/历史保真复制若保存动作C，保留原v2/v3数字及有序引用流，类别根为外部引用不复制成私有概念。不新增迁移器，不删除或重排旧C字段，不把“格式可读”写成跨进程恢复已验证。
