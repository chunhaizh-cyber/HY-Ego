# 需求结构与任务后继一致快照详细设计

日期：2026-08-20

设计身份：`RUNTIME-GOVERNANCE-DEMAND-STRUCTURE-TASK-SNAPSHOT v0.1`

## 1. 目标与完成边界

本设计把 `运行期只读查询组合器`中固定返回`材料缺失`的需求子快照改为真实公开读取闭环：

```text
指定自我 + 单一G0
-> 当前根需求组
-> 根下全部当前可达需求结构
-> 每个需求的唯一列表归属
-> 每个唯一列表项的0或1个当前任务
-> 不可变需求结构与任务后继快照
```

本设计不产生活动结论。活动路径、当前授权、权重、主需求、目标差距、任务化资格和满足仍由后继治理判断负责。

完成只证明：现有隔离端到端合法消费者可以经 L1 运行包公开签发能力建立各 L2 owner 交付，使用公开 L2 服务写入建立数据，再装配并调用公开组合器取得同一 G0 的空快照、单根无任务快照和单根有任务快照。父函数只机械消费新类型和预算；本叶不证明 BIZ-L2-002-02 最终三子完整、完整错误传播或读取后 G1，不证明生产普通应用装配、BIZ-L2-002-06、治理判断、任务筹办或任务执行完成。

## 2. 正式依据与冲突裁决

- 0050：DATA-L2 只承载结构类型语义；业务有效、完成和成功位于 DATA 外；组合投影必须声明截止、完整性和结构化非成功。
- 3100：需求树与需求列表分账；父子拓扑不证明活动、授权、权重或优先；任务以需求列表项为查询键。
- 4250：指定存在允许 0..N 个当前根需求；根组空是`已读取+空组`；排序不代表优先；当前需求必须恰一列表归属。
- 4260：同一需求列表项至多一个当前任务；`按需求列表项读取当前任务`的 0 项是合法空。
- 5090、8100、8200：自我治理先读取事实再裁决；任务、需求和方法分账。

4250/4260 当前登记仍带“待确认修订”标记，不能单独建立新业务语义。本设计采用的根定义、空组、列表查询键和 0/1 当前任务同时受 0050、3100、3200、5090 约束，并已在当前公开 DTO / 服务中形成同向代码事实；不使用其中尚未确认的活动、权重或授权算法。

旧 BIZ-L3-002-02-03 v0.1 要求先取得“活动路径”，而 BIZ-L2-002-06 才负责重判活动集，形成循环依赖；且当前 `L2需求结构`没有活动性权威承载。裁决如下：

```text
旧“需求活动与任务后继快照”退出
-> 新“需求结构与任务后继快照”只提供治理判断输入
-> 活动性由后继治理判断形成，不从父子拓扑推断
```

## 3. 当前代码事实

### 3.1 已有能力

`L2需求结构服务`已有：

- `读取需求完整`；
- `读取需求直接子`；
- `读取需求成员列表`；
- `读取需求列表项完整`；
- 当前/历史读取的共同结果头和结构状态。

`L2任务结构服务`已有：

```cpp
L2按需求列表项读取当前任务结果 按需求列表项读取当前任务(
    L2按需求列表项读取当前任务请求 请求) const noexcept;
```

它已严格分账 0 项合法空、1 项完整任务、>1 项内部不一致。

### 3.2 最早缺口

`L2需求结构.数据.h`已有`L2按所属存在读取当前根需求组请求/结果`草案，但：

- 请求缺数量预算；
- 结果含无正式语义的`根父子占位组`；
- `L2需求结构服务`没有公开实现。

同一数据头已有`L2按子需求读取当前父需求请求/结果`及“根可空、非根单父”的成功谓词，但服务也没有公开实现。现有`读取需求完整`不返回父关系，不能替代该接口；只靠从根向下遍历和重复身份检测，无法证明子需求没有来自闭包外的第二当前父。

`运行期只读查询.数据.h`仍以活动命名，含未被调用方填写的`需求范围版本`和`任务树合同版本`，以及会诱导拓扑推活动的路径 DTO。组合器固定返回`材料缺失`。父调用方也未填写上述两个字段。

### 3.3 必须保留的现有接口事实

- `读取需求成员列表`可能以成功空 optional 表示没有当前归属；本组合器对“已经从当前根闭包读到的当前需求”必须把该形状升级为内部不一致，不能把它当合法空。
- `读取需求成员列表`返回的`所属列表项`目前不保证完整字段；组合器只用成员关系取得列表项身份，并另行调用`读取需求列表项完整`取得权威完整事实。
- 各 L2 公开读取当前实现可能观察到调用后的最新截止；组合器必须检查每个结果截止是否恰等于请求 G0，不允许用最大截止或重试拼包。

## 4. 最终接口与物理位置

### 4.1 L2根需求组提供者

物理位置：

```text
DTO：海中鱼巣/领域/L2需求结构.数据.h
实现：海中鱼巣/领域/服务.L2需求结构.ixx
所有者：唯一L2需求结构服务
可见性：public const noexcept
```

最终请求：

```cpp
struct L2按所属存在读取当前根需求组请求 final {
    L2结构请求头 请求头;
    L2存在身份 所属存在;
    std::uint64_t 数量预算 = 0;
};
```

最终结果：

```cpp
struct L2按所属存在读取当前根需求组结果 final {
    L2结构结果头 结果头;
    std::vector<L2需求事实> 根需求组;
    bool 成功() const noexcept;
};
```

删除`根父子占位组`。`成功()`要求：状态已读取、非零截止、无变更代次、全部需求完整且当前、所属存在一致、身份严格升序。空组仍成功。

最终签名：

```cpp
L2按所属存在读取当前根需求组结果 按所属存在读取当前根需求组(
    L2按所属存在读取当前根需求组请求 请求) const noexcept;
```

实现固定顺序：

1. public 入口只取得一次 `L2需求结构服务::互斥体_`，在该锁内验证合同、非零期望事实代次、所属存在和数量预算。
2. 读取当前事实代次；与期望 G0 不等立即返回`事实代次漂移`和空组。
3. 经需求 owner 的“需求所属存在关系类型”反向读取该存在的当前需求候选。
4. 对每个候选在同一 G0 调用已有 module-private `读取需求完整当前投影`读取完整需求事实，并调用第 4.2 节新增的 module-private 当前父投影 helper；不得在锁内回调 public `读取需求完整`或 public `按子需求读取当前父需求`。主体不符、身份复义或结构矛盾为内部不一致。
5. 仅保留无当前父关系者；筛出的根数量超过请求的根数量预算时，返回`数量预算不足`和空组。
6. 按需求稳定身份升序返回根组；不得用根数量预算限制包含全部子孙的候选扫描数量。总需求节点预算由组合器遍历闭包时独立裁决；如未来确需限制候选扫描，必须另设具名预算字段，不能复用根预算。
7. 返回`已读取`；0 项合法。

不得增加第二 owner、第二服务、业务筛选、活动字段或测试专用入口。

### 4.2 L2当前父需求提供者

物理位置与所有者同第 4.1 节，复用现有 DTO，不新建模块：

```cpp
L2按子需求读取当前父需求结果 按子需求读取当前父需求(
    L2按子需求读取当前父需求请求 请求) const noexcept;
```

在 `服务.L2需求结构.ixx` 的 `L2需求结构内部` 命名空间新增唯一 module-private helper：

```cpp
L2按子需求读取当前父需求结果 按子需求读取当前父需求当前投影(
    const L1事实基座服务& 第一层服务,
    const 需求身份来源定位& 来源定位,
    const 需求结构类型定位& 类型定位,
    const L2按子需求读取当前父需求请求& 请求,
    std::uint64_t 期望代次);
```

public `按子需求读取当前父需求`只取得一次`互斥体_`，完成请求守卫和当前截止取得后调用该 helper。根需求组 public provider 在自己的单次锁内直接复用同一 helper。helper 不加锁、不回调任何 public 服务函数；读取唯一父需求完整事实时直接调用已有 module-private `读取需求完整当前投影`。这样两个 public 入口共享一套父关系形状裁决，同时不发生非递归 mutex 二次加锁。

实现必须在服务互斥边界内固定 G0，经需求父子关系类型对目标为子需求的当前关系组做反向读取：

- 0 条：`已读取`，父关系和父需求 optional 均空；
- 1 条：读取完整父需求，返回关系和父需求；
- >1 条、关系端点不符、父需求不完整或截止不一致：`内部不一致`；
- 请求 G0 与当前代次不同：`事实代次漂移`；
- 任一非成功两个 optional 均空。

本接口只返回结构父关系，不判断父需求是否活动、有效、授权或优先。

## 5. 组合算法

1. 入口验证合同版本、运行代次、事实范围版本、唯一自我、G0 和三个非零预算。
2. 调用根需求组提供者；传入 G0 和`最大根需求数`。根预算只限制根结果，组合器总节点预算独立限制后继遍历。
3. 根组为空立即形成 G0 下三向量全空的成功快照。
4. 根组非空时以根身份升序建立待展开队列，根深度为 1。
5. 每个需求只处理一次：
   - `读取需求完整(G0)`；
   - 复核所属存在和生命周期；
   - `按子需求读取当前父需求(G0)`：根必须两个 optional 均空；非根必须恰一父，且父身份、关系身份、端点和队列携带父关系逐字段相等；
   - `读取需求成员列表(G0)`，要求恰一当前成员关系；
   - `读取需求直接子(G0)`，按父子顺序和子身份入队。
6. 任一重复需求、根有父、非根无父/多父、队列父关系不等、父端点不匹配、环或跨主体关系为内部不一致。
7. 已处理需求数超过总量预算或下一层深度超过深度预算，返回数量预算不足且丢弃全部局部向量。
8. 对去重后的每个列表项身份按升序：
   - `读取需求列表项完整(G0)`；
   - 与全部成员需求的所属存在和三个目标引用逐字段互证；
   - `按需求列表项读取当前任务(G0)`；空任务成功，单任务要求任务引用回显同一列表项。
9. 根需求组、需求结构组和列表任务组分别稳定排序；全部截止必须等于 G0。
10. 一次移动形成快照。任何中途失败不返回部分前缀。

## 6. 状态与合法空

| 情况 | 结果 |
| --- | --- |
| 自我当前无根需求 | 已形成；三个组为空；截止=G0 |
| 列表项当前无任务 | 已形成；对应任务 optional 为空 |
| 当前需求缺列表归属 | 内部不一致 |
| 根有父、非根无父、多父、环、重复端点 | 内部不一致 |
| 入口自我或必需结构身份未找到/已退出 | 材料缺失 |
| 根成功后某个已枚举后继消失；根有父；非根无父、多父或父关系不等 | 内部不一致 |
| 任一结果观察截止不等G0 | 当前性漂移 |
| 根、节点或深度预算超限 | 数量预算不足 |
| 分配失败 | 资源失败 |

## 7. 允许依赖与禁止项

允许：

```text
组合器 -> L2需求结构服务公开读取（含根组和按子需求当前父）
组合器 -> L2任务结构服务公开读取
L2需求结构服务 -> 自身唯一L1 owner范围读取
```

禁止：

- 组合器直达 L1、SQL、材料、缓存或 owner 写端口；
- 新增需求业务转发服务；
- 从树形、排序、列表或有任务推断活动；
- 为测试新增第二根来源、私有构造器、friend 或故障 seam；
- 在失败后用新 G0 重试拼包；
- 修改 BIZ-L2-002-06 及其后继治理语义。

## 8. 首次合法消费者验证

沿现有 `--test-治理` 入口，复用 `端到端测试.自我治理一致事实.ixx` 已有的隔离端到端合法消费者：从同一 L1 运行包的公开签发器建立各 L2 owner 交付，经公开构造函数取得需求、任务、状态、特征、存在、场景服务并装配公开 `运行期只读查询组合器`。所有事实只能经现有 L2 公开写入形成，组合只经公开组合器入口读取；不得增加测试私有构造、`friend`、故障 seam 或绕过公开 owner 交付的入口。

本验证不宣称调用生产 `构造普通应用上下文` 或普通应用 getters；该生产装配不在本计划白名单内，保持 `NOT_RUN`。隔离消费者必须使用与生产代码相同的公开签发、公开 L2 构造和公开读写合同，不能把“测试文件能够直接构造公开对象”升级为生产装配已接通。

最小矩阵：

1. 空需求结构：建立自我后，在 G0 读取，返回已形成、三组空、截止 G0。
2. 单根无任务：经`新增需求并建立列表项`形成一个根和列表项，新 G0 读取，根/结构/列表后继均一项，任务 optional 空。
3. 单根有任务：经`新增任务`绑定上述列表项，新 G0 读取，任务身份和列表引用逐字段一致。
4. 旧 G0：写入后用旧 G0 读取，返回当前性漂移且零快照。
5. 零预算或坏合同：请求拒绝且零快照。
6. 父`读取自我治理一致事实`在其余材料具备时收到相同需求结构任务快照，不再接受“DATA-EXT-12 未就绪”作为通过理由。

测试只证明公开服务读回，不伪造内部矛盾；不可达结构损坏不通过测试 seam 构造。

## 9. 漂移停工条件

仅在以下事实出现时退回计划支撑：

- 根需求或当前父关系只能通过新增第二 owner、第二服务或组合器直达 L1 才能读取；
- 当前正式规范要求本叶产生活动事实；
- 现有隔离端到端消费者无法从同一 L1 运行包的公开签发器建立需求和任务 owner 交付，或无法经公开 L2 构造取得服务；
- 现有公开写入无法形成合法根需求与任务，且修复超出本计划七个生产/测试文件。

普通编译错误、结果字段机械调整和测试代码复用不构成设计漂移。
