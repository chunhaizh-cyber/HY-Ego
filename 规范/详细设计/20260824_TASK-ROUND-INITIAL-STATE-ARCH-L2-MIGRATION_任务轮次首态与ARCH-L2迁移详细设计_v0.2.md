## 1. 完整替代范围

本文件是同身份 v0.2 的完整、独立施工依据，正式发布和索引登记后整体替代 v0.1；执行者无需依赖聊天、未提交 WIP 或从旧版补齐合同。

唯一目标是把 `需求初次筹办准备提供者::形成唯一任务与初次筹办工作包`改造成最早合法 ARCH-L4 业务消费者：由当前具体需求 D 形成任务专属正式存在 E、任务 T、首个任务轮次 R1、首个筹办轮次 P1、E 上“筹办 / 待初次筹办”无动态首态，以及迁移到“筹办 / 筹办中”的第一动态，并从各 owner 独立读回完整工作包。

本版本同时闭合执行期发现的物理合同缺口：治理函数定义的 U64 组材料值使用独立本地写入键。该纠偏不新增业务事实、不改变治理函数或 A1 语义，也不修改 ARCH-L1/L2/L3 ABI。

## 2. 当前事实与唯一裁决

1. `L1所有者范围写集请求`的节点、关系和值共用一个本地键集合；同一写集跨三组复用本地键会被结构校验拒绝。
2. 旧版把 `0x0301'2185`分配给治理函数定义节点，把 `0x0301'2186`分配给定义材料属性类型，却没有给值事实分配键，因此执行者无法机械形成合法写集。
3. 全仓当前生产字面复核中 `0x0301'218F`零占用；同一 task owner 已冻结的 `0x0301'2180..0x0301'218E`为 15 项登记键，下一既有生产键为 `0x0301'2201`。
4. 因此唯一新值写入键冻结为 `0x0301'218F`。它紧邻登记范围末端，但不属于 15 项登记键，也不得被解释为第 16 项登记角色。

## 3. 精确键表与计数

| 本地键 | 唯一角色 | 所属写集 |
| --- | --- | --- |
| `0x0301'2180` | R1 族锚点 | task owner 服务登记 |
| `0x0301'2181` | R1 族归属关系类型 | task owner 服务登记 |
| `0x0301'2182` | R1→T 关系类型 | task owner 服务登记 |
| `0x0301'2183` | T→当前 R1 关系类型 | task owner 服务登记 |
| `0x0301'2184` | R1 轮次序号属性类型 | task owner 服务登记 |
| `0x0301'2185` | 初次筹办推进治理函数定义节点 | task owner 服务登记 |
| `0x0301'2186` | 治理函数定义材料 U64 组属性类型 | task owner 服务登记 |
| `0x0301'2187` | A1 族锚点 | task owner 服务登记 |
| `0x0301'2188..0x0301'218D` | A1 族归属、被调用函数、T、R1、P1、触发前态六个关系类型 | task owner 服务登记 |
| `0x0301'218E` | A1 调用材料 U64 组属性类型 | task owner 服务登记 |
| `0x0301'218F` | 治理函数定义材料值 | 治理函数定义登记写集 |

固定计数必须分账：

```text
登记键 = 5 + 2 + 8 = 15（0x2180..0x218E）
定义材料值写入键 = 1（0x218F，不进入登记计数）
治理函数定义登记写集的新事实键 = 3（0x2185、0x2186、0x218F）
属性槽变更 = 1（引用 0x218F，不建立第四个事实键）
```

R1 运行时写入仍为 `0x0301'2660..0x0301'2664`共 5 项；A1 运行时写入仍为 `0x0301'2680..0x0301'2687`共 8 项。二者均不消费 `0x0301'218F`。

## 4. 治理函数定义写集

服务登记时的定义写集必须精确形成：

```cpp
节点 = {
    {键(0x0301'2185), 节点种类::普通, std::nullopt},
    {键(0x0301'2186), 节点种类::属性类型,
        L1所有者范围值表示种类::U64组}
};
关系 = {};
值 = {{
    键(0x0301'218F),
    键(0x0301'2185),
    键(0x0301'2186),
    std::vector<std::uint64_t>{1, 1, 1},
    键(0x0301'2185)
}};
属性槽变更 = {{
    键(0x0301'2185),
    键(0x0301'2186),
    键(0x0301'218F)
}};
退出事实 = {};
```

有序材料三个位置固定为：

| 位置 | 含义 | 当前值 |
| --- | --- | --- |
| 0 | `L2任务治理函数种类` | `初次筹办推进 = 1` |
| 1 | `L2任务治理函数合同版本` | `1` |
| 2 | `L2初次筹办推进规则版本` | `1` |

写入结果的新编码映射必须精确包含上述三个互异键；缺 `0x218F`、多映射、错映射或把任一键复用到另一事实都返回内部不一致，不能把登记成功伪装成定义事实成功。

## 5. DTO 与独立读回

公开 DTO 固定为：

```cpp
struct L2任务治理函数定义事实 final {
    L2任务治理函数身份 身份;
    L2任务治理函数种类 种类;
    std::uint32_t 合同版本;
    std::uint32_t 规则版本;
    L2生命周期 生命周期;
};
```

不得增加本地键、原始值身份或 L1 写集字段。task owner 的定义读取实现必须从定义节点的当前属性槽读取 `0x2186` 属性，取得其当前值事实，并逐项确认：

- 值事实属于定义节点；
- 属性类型是正式读回的 `0x2186` 属性类型；
- 来源节点等于定义节点；
- 材料形状是恰好三个元素的 U64 组；
- 三个值分别可无损转换为函数种类、合同版本和规则版本，且当前只接受 `{1,1,1}`；
- 定义节点、属性类型、值事实和当前槽在读取截止共同成立，定义节点当前未退出。

只有全部成立才重建 `L2任务治理函数定义事实`。不得从编译期常量补齐缺失 / 损坏值，不得因为节点存在就返回定义成功。A1 提交前和第一动态读回后继续通过该公开强类型定义读回来互证版本。

## 9. 当前能力、对象与所有权

当前唯一正式存在入口为 `L2存在结构服务`；旧私有通用存在已经退出。特征基础定义 / 实例、状态首态和状态动态原子迁移均有现行公开服务。状态动态 provider 只能迁移已有旧态，因此首态必须先由状态 owner 单独建立且不形成动态。当前任务融合入口没有正式 E、独立 R1、正式 `T→D/T→E`或 ARCH-L2 首态 / 第一动态，生产调用必须迁移。

| 对象 / 事实 | 唯一 owner | 本叶写入 |
| --- | --- | --- |
| E 与存在身份来源 | `L2存在结构服务` | `新增存在节点` |
| T、R1、`T→L/T→D/T→E` | `L2任务结构服务` | task-owner G_T |
| 全局任务阶段特征定义 | 特征定义 owner | 固定 `TASKSTAG` 幂等身份建立 / 恢复 |
| E 的阶段特征实例 | 特征实例 owner | `新增特征实例` |
| 无动态首态 | 状态 owner | `新增状态` |
| 首次准备记录、P1、A1 | task owner | task-owner G_P1 |
| 筹办中后态与第一动态 | 状态 / 动态 owner | 既有跨 owner 原子 provider |
| 业务编排与恢复 | `需求初次筹办准备提供者` | 不持有事实，只消费公开面 |

依赖固定为：

```text
需求初次筹办准备提供者
  -> 运行期需求查询组合器
  -> L2存在结构服务
  -> L2任务结构服务
  -> L2特征结构服务
  -> L2状态结构服务
  -> L2状态动态原子发布服务
```

不得直达 L1、借用 owner 私有端口、在 task owner 复制 ARCH-L2 状态 / 动态，或把多个 owner 的结果冒充成一个共同 G1。

## 11. 外层请求、工作包和状态值

`需求初次筹办准备合同版本 = 2`。请求保留外层准备幂等身份，并携带六个非零且逐字段参与精确重复的结构幂等身份：存在建立、任务核心建立、阶段特征实例建立、首态建立、P1 建立、首迁移。请求同时携带并回显治理函数合同版本 1 和规则版本 1。全局基础特征定义使用固定幂等身份 `0x5441'534B'5354'4147`（ASCII `TASKSTAG`）。

工作包至少包含 E、T、R1、`T→D/T→E`、阶段定义 / 实例、首态、首次记录、P1、函数定义、A1、后态、第一动态，以及七段完整结果头和最终独立读回截止 `G_E/G_T/G_FD/G_FI/G_S0/G_P1/G_M1`。成功守卫必须逐项互证 owner、身份、生命周期、端点、值、A1 及所有版本；只比较载荷字段不构成成功。

阶段特征定义固定为基础特征“实际阶次 1、无直接来源、无派生规则”。每个 E 唯一建立一个实例。精确值材料为 I64 组：首态 `{1,1}`表示“筹办 / 待初次筹办”，后态 `{1,2}`表示“筹办 / 筹办中”。时间材料为 U64 组 `{运行代次, 阶段序号}`，首态序号 1、后态序号 2。首态来源编码为 R1，第一迁移来源编码为 A1。

## 12. 分阶段算法与发布未知

1. 按准备键读取；已有完整最终记录则按各 owner 历史截止重建并返回精确重复。
2. G0 裁决 D 当前未满足并冻结 D/L 证据。
3. 原存在键建立 / 恢复 E，形成 G_E。
4. 取得不早于 G_E 的 G_T0 并复核 D/L/E；原任务核心键建立 / 恢复 T/R1/三关系，形成 G_T。
5. 各自在新截止用全局固定键建立 / 恢复阶段定义 G_FD，再用实例键建立 / 恢复 E 的实例 G_FI。
6. 在实例可见截止用首态键建立 / 恢复 `{1,1}`无动态首态 G_S0。
7. 在首态可见截止用 P1 键同次建立 / 恢复首次记录、P1、A1，形成 G_P1。
8. 在 P1/A1 可见截止独立读回 A1 与定义；用首迁移键和 A1 来源把首态迁移为 `{1,2}`并形成第一动态 G_M1。
9. 分别经存在、任务、特征、状态、动态公开面独立读回并互证完整工作包。

任一写端非成功但带非零截止，只允许原键、原请求和该 owner 公开读回收敛；未确认不得越段。已经发布的前段事实保留供同键恢复，不做跨 owner 回滚，不换键重做。成功状态但载荷不完整固定内部不一致。

## 13. 错误矩阵

| 条件 | 外层状态 | 后继 |
| --- | --- | --- |
| 版本、零键、键字段或阶段材料非法 | `入口拒绝` | 零写 |
| D 已满足 | `目标已满足` | 零写 |
| L 已有异义当前任务 | `已有当前任务`或`引用冲突` | 不建第二 T |
| 同键同请求 | `精确重复` | 各 owner 读回既有工作包 |
| 同键异义、E/T/R1/状态端点异义 | `幂等冲突` | 停在当前阶段 |
| G0 或后继期望代次漂移 | `当前性漂移` | 新业务请求，不在原请求刷新 |
| owner / 族 / 宿主 / 定义 / 前态 / A1 坏引用 | `引用冲突` | 零后继写 |
| 许可拒绝 | `许可拒绝` | 原样上送 |
| 分配或存储失败 | `资源失败` | 原样上送，可原键恢复 |
| 截止非零但提交结果未确认 | `发布未知` | 只读收敛，禁止越段 |
| 成功形状、键映射或历史互证矛盾 | `内部错误` | 零成功载荷 |

非成功不得携带可冒充完整工作包的部分载荷。`成功()`只接受全部七段权威读回完整的“已形成 / 精确重复”。
