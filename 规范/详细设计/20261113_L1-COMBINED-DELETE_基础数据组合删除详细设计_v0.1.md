## 2. 公开合同

基础节点组追加请求末尾追加默认空成员：

```cpp
std::vector<稳定编码> 删除节点组;
std::vector<稳定编码> 删除外部关系组;
```

基础节点组追加状态末尾追加引用仍存在，值为8，旧枚举值不变。不改变结果数组和片段回执形状；删除成功由整个事务的已完成状态表达。纯删除片段的新增数组均空，但组合成功时仍得到对应片段的回执。

新组沿原子删除节点结构的精确编码删除语义：非零、组内唯一、提交时相应类别的对象存在。不存在的节点返回节点不存在，不存在的外部关系返回引用不存在；零编码、重复删除为入口拒绝。不同对象类别共用编码空间，传入错误类别按相应不存在处理。删除边不删除端点；删除节点不隐式级联删除字段或边，需在完整事务中明确解除。

这两个新组不要求调用方另读整组旧快照。L1在提交独占锁内以当前数据及完整候选变化判断引用闭合。4015 §10.1、§12的上层引用闭包证明文字，在本切片按用户“只有L1层读写需要数据校验”的最新裁决处理，不恢复为新增上层预检义务。显式携带的既有联合/只读预期仍按其合同核验；字段替换、字段删除、既有宿主追加和外部边追加的现行预期要求保持不变。本叶不把新增能力扩大为全仓旧预期机制清理。

删除集合为空时保持旧入口行为，包括拒绝完全无变化的原子追加请求。封存入口仍允许已有的纯读取保护片段；新增纯删除片段合法。不承诺二进制跨版本ABI和持久化格式，实际项目统一重编译。

## 3. 精确函数与流程

### 3.1 规范化封存请求

物理位置为基础数据集.cpp匿名命名空间，签名保持：基础节点组追加状态 规范化封存请求(基础节点组追加请求&)。

在既有值式形状处理外，把两组删除计入是否有操作；分别检查非零和重复编码。保留请求顺序，不补造引用保护快照，不访问当前数据集，不在封存时判断最终引用是否已解除。字段/边可能由别的片段解除，完整候选才有权作闭包判断。

### 3.2 原子追加节点组

签名保持：基础节点组追加结果 基础数据集::原子追加节点组(const 基础节点组追加请求&) noexcept。

顺序固定为：

1. 取得唯一L1独占锁。检查有变化、既有预期及原写入要求；在锁内检查两组删除编码非零、唯一、对象存在。不增加上层调用或回调。
2. 拷贝现有节点、字段及四份字段索引作为候选。外部关系有追加或删除时，拷贝关系表、源索引和目标索引；没有边变化时继续用当前关系索引读取。
3. 为新节点分配编码并建立候选；删除显式字段并更新四索引，替换字段并更新四索引；删除显式外部关系并更新两索引；追加所有新字段和外部关系。候选中此时还保留待删节点。
4. 对每个待删节点，在最终候选索引上查是否仍作为字段所属、字段键、字段内容引用目标、外部边源、外部边目标。任一残留返回引用仍存在，整个候选丢弃。使用lower_bound按节点前缀查询，不新增整表扫描。直接值中的数字不解释为节点引用。
5. 全部待删节点通过后从候选节点表物理删除。包括互相引用、自环、多节点环在内的关系，必须显式删除或改向后才能通过；不能因为两端都在删除集就默许悬挂关系。
6. 所有分配和可失败操作完成后，在锁内交换候选节点、字段、索引和有变化的边表/索引。交换区间无分配、无上层调用；读者不能看见半状态。返回既有新增结果数组。

新写入指向待删节点（包括新字段的键、新字段内容、追加宿主、外部边端点）不单独设第二套语义检查，由步骤4的候选引用统一拒绝。修改待删节点上仍保留的字段同样不能成功。允许其他片段解除引用后同次删除。

分配编码后失败可能消耗编码，保留现有单调分配、不复用规则；零公开变化指正式节点、字段、边和索引不变，不承诺分配器回滚。

### 3.3 原子追加封存片段组

签名保持：基础片段组合结果 基础数据集::原子追加封存片段组(const std::vector<基础封存追加片段>&) noexcept。

保留数据集身份和同批片段重复检查、既有字段/字段键/追加边写冲突、局部新节点引用重定位。合并两组删除时检查容量和跨片段重复：同一节点或同一外部关系由两个片段请求删除，整批入口拒绝，不静默去重；不同对象删除组没有局部索引重定位。

一个片段请求删除节点、另一个片段删除它的字段或边，是合法合作。只读预期或联合预期检查的是提交前提，不等同于保活承诺，允许本事务随后删除该节点。不同片段新增的引用若在最终候选仍指向待删节点，由唯一原子提交点返回引用仍存在；不得按片段顺序先发后删。

删除一条边并新建同端点/类型/角色的另一条边可按现有多边合同成立，两条有不同稳定编码；不会按端点相等暗中合并。原有跨片段追加相同边键的冲突检查不变。

全部回执及数组在提交前分配。合并后仅调用一次原子追加节点组。非成功原样传出，不交付回执。成功后只填已有新增数组；纯删除片段仍与原片段身份绑定。片段可复制、非一次性、不会保活、没有跨调用幂等账；成功后重放删除不能伪成功，按届时前提或对象不存在失败。

## 4. 错误、并发和生命周期

工程资源失败保持资源失败，不转成业务无匹配。现有内部异常仍经原函数工程异常终止边界；本叶不增加日志调用或诊断切片。结构及引用校验全部在L1进行，封存阶段的形状检查也属于L1。

直接提交只持L1一把锁；组合在调用提交前不持L1外层锁。没有新锁序、owner注册表、上层回调和线程等待。封存与提交之间对象允许变化，依据实际提交时的当前数据作判断；既有明确预期失败仍原样报告。

字段/外部关系索引按原加删助手同步维护。候选资源异常只销毁局部副本；交换后没有新失败点。现有封存组合的发布后尺寸不一致仍作为内部逻辑错误处理，不能宣称未写入再重试。

合法调用方仍是结构owner及获准具名编排，本叶不开放业务直写资格。后继词条名称提供者需另行闭合owner准备、场景/状态形成、名称唯一性与删除集来源；不能仅凭通用L1接口宣称这些已完成。
