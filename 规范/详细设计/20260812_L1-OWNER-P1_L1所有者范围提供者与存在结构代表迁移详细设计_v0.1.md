# L1所有者范围提供者与存在结构代表迁移详细设计 v0.1

日期：2026-08-12

设计身份：`L1-OWNER-P1`

设计状态：创建侧候选

## 1. 目标、边界与完成定义

本设计把 4010、4015、4030、4040、4050、4070 已冻结的 L1 技术所有者合同落成一个可独立施工的代码叶，并选择现有唯一 `L2存在结构服务` 作为真实代表消费者。

本叶必须同时闭合：

1. 同仓 `L1结构所有者事实`、三类普通事实不可变 `写入所有者`、owner-scoped v2 写入 / 当前 / 历史 / 一致投影；
2. 一个 L1 运行包只有一个实例、一个签发器，raw 写端口不可复制、只能移动、绑定精确实例和 owner；
3. v1 legacy 与 v2 owner 域共仓、共代次而隔离，v1 不能写入、修改或退出独占 owner 事实；
4. `L2存在结构服务` 的全部三个 L1 写调用迁到同一实例绑定端口，全部存在读回改用 owner-aware 公开读取；
5. 普通应用装配建立唯一存在 owner 和唯一存在服务，普通调用者可重复取得同一服务引用，但不能取得 raw 端口、签发器、owner 选择或第二服务；
6. 场景服务不再临时构造存在服务，而是只读注入同一存在服务；特征服务既有只读注入形状保持；
7. 生产外公开接口矩阵验证 L1 owner 合同，以及普通调用者经公开装配工厂取得真实存在服务后完成存在节点新增、当前读取、退出和历史读取。

本叶不实施恢复、重启或跨进程重入，不实现七族身份来源治理 G2，不实现 A1 聚合面，不给存在固定属性发明测试专用属性类型，不迁移场景 / 特征写 owner，不修改 T1、DYN2、4230、路线输入、流程图或 `.codex-build/`。

“计划可执行”只表示本设计与施工合同已冻结；“本叶实施完成”最多证明 owner provider 与存在节点代表消费链成立，不证明七族结构、固定属性类型来源、场景成员写、A1、恢复或整个 L2 重建完成。

## 4. owner v2 公共数据合同

### 4.1 常量、身份与 owner 事实

`L1所有者范围CRUD.数据.h` 固定：

```cpp
inline constexpr std::uint32_t L1所有者范围CRUD合同版本 = 2;
inline constexpr std::uint32_t L1所有者范围一致当前读取合同版本 = 2;

struct L1结构所有者身份 final { 稳定编码 编码; };
enum class L1所有者范围种类 : std::uint8_t {
    旧共享范围 = 1,
    独占结构范围 = 2
};
struct L1结构所有者事实 final {
    L1结构所有者身份 所有者;
    L1所有者范围种类 范围种类;
    std::uint64_t 创建事实代次;
    std::optional<std::uint64_t> 退出事实代次;
};
struct L1所有者范围建立幂等身份 final { std::uint64_t 值; };
struct L1所有者范围写入幂等身份 final { std::uint64_t 值; };
```

全部包装类型提供默认值式比较和 `有效(...)`。owner 编码继续来自全局稳定编码空间；请求不携带服务名、枚举、模块名或业务资格。

### 4.2 owner 管理 DTO

| 类型 | 精确字段 |
| --- | --- |
| `L1所有者范围建立请求` | `合同版本`、`建立幂等身份`、`范围种类` |
| `L1所有者范围重入请求` | `合同版本`、`所有者`、`建立幂等身份` |
| `L1所有者范围退出请求` | `合同版本`、`所有者`、`建立幂等身份`、`期望事实代次` |
| `L1结构所有者读取请求` | `合同版本`、`所有者` |

管理状态固定为：`成功`、`精确重复`、`入口拒绝`、`许可拒绝`、`未找到`、`已退出`、`事实代次漂移`、`幂等冲突`、`引用冲突`、`资源失败`、`内部不一致`。

建立 / 重入 / 退出结果均回显合同版本、请求幂等身份、结构化状态、owner 事实、结果事实代次、是否发布和重试边界。纯 DTO 不保存端口、租约、nonce、地址或 token。`L1所有者范围交付` 在服务模块定义为“值式建立结果 + 可选 move-only 端口”，不放进数据头。

当前阶段只实现建立和退出。重入请求 / 结果类型按正式静态合同存在，但 `重新签发所有者范围写端口` 不在本叶导出，也不得建立固定未实现函数；恢复重新进入时另立计划实现并验证。

### 4.3 写集 DTO

owner v2 使用独立类型，不复用或 typedef v1：

- `L1所有者范围写集本地键`
- `L1所有者范围事实引用 = variant<稳定编码, L1所有者范围写集本地键>`
- `L1所有者范围独立材料引用`
- `L1所有者范围原始值材料`
- `L1所有者范围值表示种类`
- `L1所有者范围节点新建项`
- `L1所有者范围关系新建项`
- `L1所有者范围值新建项`
- `L1所有者范围属性槽变更项`
- `L1所有者范围写集请求`

新建项字段与 v1 同构，但请求字段固定为：

```text
合同版本
期望事实代次
L1所有者范围写入幂等身份
节点
关系
值
属性槽变更
退出事实
```

请求没有 owner 字段。写入状态固定为：`成功`、`精确重复`、`入口拒绝`、`许可拒绝`、`未找到`、`已退出`、`事实代次漂移`、`幂等冲突`、`引用冲突`、`资源失败`、`内部不一致`。写入结果固定回显：状态、合同版本、端口隐式绑定 owner、幂等身份、事实代次、是否发布、重试边界和有序新编码映射。

### 4.4 owner-aware 事实与读取 DTO

owner-aware 节点 / 关系 / 值分别包含现行 v1 对应事实的全部字段，再增加非零 `写入所有者`；属性槽不增加 owner 字段。必须具名定义：

- 当前 / 历史单事实请求与结果；
- 源关系组、目标关系组、历史关系组请求与结果；
- 历史属性值组请求与结果；
- owner 当前 / 历史读取结果；
- 一致当前读取请求、顶层状态、项目状态、owner / 节点 / 关系 / 值 / 属性值 / 源关系组 / 目标关系组结果项。

单事实读取请求只携带合同版本与稳定编码，不携带期望 owner。读取结果如实返回实际 owner；provider 在自身服务边界核对 owner。owner 一致当前请求除 v1 六组选择外增加有序 `所有者` 选择组；成功结果中所有者事实、三类事实、属性值和关系组共享同一非零截止。

当前 / 历史状态至少区分 `成功`、`入口拒绝`、`许可拒绝`、`未找到`、`已退出`、`属性未设置`、`事实代次漂移`、`资源失败`、`内部不一致`。非成功不得携带可用事实。

读取 DTO 的精确字段固定为：

| DTO | 精确字段 |
| --- | --- |
| `L1所有者范围事实读取请求` | `合同版本`、`编码` |
| `L1所有者范围当前读取结果` | `状态`、`合同版本`、`查询编码`、`读取事实代次`、`optional<owner-aware 节点/关系/值 variant> 事实` |
| `L1所有者范围历史读取结果` | `状态`、`合同版本`、`查询编码`、`读取事实代次`、`optional<owner-aware 节点/关系/值 variant> 事实` |
| `L1所有者范围源关系组读取请求` | `合同版本`、`源节点`、`关系类型节点` |
| `L1所有者范围目标关系组读取请求` | `合同版本`、`目标节点`、`关系类型节点` |
| `L1所有者范围源关系组读取结果` | `状态`、`合同版本`、`源节点`、`关系类型节点`、`读取事实代次`、`有序关系组` |
| `L1所有者范围目标关系组读取结果` | `状态`、`合同版本`、`目标节点`、`关系类型节点`、`读取事实代次`、`有序关系组` |
| `L1所有者范围历史关系组读取请求` | `合同版本`、`方向`、`端点节点`、`关系类型节点`、`历史截止事实代次` |
| `L1所有者范围历史关系组读取结果` | 请求回显字段、`状态`、`读取事实代次`、`有序 owner-aware 关系组` |
| `L1所有者范围历史属性值组读取请求` | `合同版本`、`所属节点`、`历史截止事实代次` |
| `L1所有者范围历史属性值组读取结果` | 请求回显字段、`状态`、`读取事实代次`、`有序 owner-aware 值组` |
| `L1结构所有者当前读取结果` | `状态`、`合同版本`、`查询所有者`、`读取事实代次`、`optional<所有者事实>` |
| `L1结构所有者历史读取结果` | `状态`、`合同版本`、`查询所有者`、`读取事实代次`、`optional<所有者事实>` |
| `L1所有者范围一致当前读取请求` | `合同版本`、`期望事实代次`、`所有者`、`节点`、`关系`、`值`、`属性值`、`源关系组`、`目标关系组` 九组有序选择 |
| `L1所有者范围一致当前读取结果` | `状态`、`合同版本`、`期望事实代次`、`读取事实代次`、与请求九组一一对应的项目结果 |

owner-aware 三类事实字段固定为：节点=`编码、种类、属性类型表示、写入所有者、创建事实代次、退出事实代次、当前属性`；关系=`编码、源节点、目标节点、关系类型节点、角色或顺序、写入所有者、创建事实代次、退出事实代次`；值=`编码、所属节点、属性类型节点、材料、来源节点、写入所有者、创建事实代次、退出事实代次`。不得改变字段来源、删减生命周期或在属性槽复制 owner。

## 5. 单仓内部模型与不变量

### 5.1 内部事实

`L1事实基座.数据.h`：

- 新增内部 `L1结构所有者事实` 对应值式记录；
- `节点事实`、`关系事实`、`值事实` 各增加 `L1结构所有者身份 写入所有者`；
- 内部 owner 与普通事实共用稳定编码、创建 / 退出事实代次；
- `L1事实副本` 仍只表示三类普通事实；owner 历史使用独立内部结果，不能塞入普通事实 variant。

### 5.2 仓库状态

现有 `状态` 原位增加：

```text
当前所有者：owner 编码 -> owner 事实
历史所有者：owner 编码 -> owner 历史事实
owner 建立幂等账：建立键 -> 首次规范化请求 / owner / 首次结果
owner-scoped 写入幂等账：(owner 编码, 写入键) -> 首次规范化写集 / 映射 / 首次结果
legacy owner 定位：可选 owner 编码
```

现有 v1 幂等账不改键、不改结果、不与 v2 互返重复。全局永久占用必须等于当前 owner、历史 owner、当前三类事实和历史三类事实的编码并集。

`状态完整` 增加双向互证：

1. 每项当前 / 历史普通事实 owner 在该事实创建截止存在且范围合法；
2. 当前普通事实 owner 当前有效，历史普通事实 owner 的生命周期覆盖事实创建；
3. 当前 / 历史 owner 编码不与普通事实复用；
4. 关系类型节点 owner 等于关系 owner；值所属节点、属性类型、值 owner 相同；属性槽所属节点、类型、当前值 owner 相同；
5. legacy 定位若存在只指向唯一 `旧共享范围` owner；独占 owner 不复用；
6. 两套幂等账分别完整，v2 键域是本实例内 `(owner, 写入幂等身份)`；
7. owner 缺失、复义、生命周期不覆盖或读回变化直接隔离为内部不一致。

### 5.3 v1 legacy

首笔合法 v1 新写在同一候选 / 代次内建立唯一 `旧共享范围` owner，并给全部 v1 新事实绑定该 owner；后续 v1 复用定位。v1 请求 / 结果、函数名和幂等行为不变，v1 读取投影剥离 owner 字段。

v1 写前必须拒绝：

- 关系端点 / 类型中任何独占 owner 事实；
- 值的所属、类型、来源或材料引用中任何独占 owner 事实；
- 属性槽所属、类型、新值中任何独占 owner 事实；
- 退出任何独占 owner 事实；
- 试图创建 / 修改 owner 事实。

这些分支固定 `入口拒绝`、零候选、零代次推进。不存在按名称、形状、本地键或类型编码 adoption。

## 6. owner 管理与 v2 提交算法

### 6.1 建立 owner

仓库私有建立入口在独占事务内执行：

```text
请求形状 / 版本 / 非零建立键 / 独占范围校验
-> 现行状态完整性
-> 建立幂等账：同键同义返回首次 owner 事实；同键异义冲突
-> 分配全局稳定编码
-> 建立独占 owner 候选
-> 记录建立幂等账
-> 状态完整
-> 原子交换与 owner 精确读回
```

签发器在仓库成功 / 精确重复后检查本实例活动端口表。同 owner 已有活动端口时结果固定 `许可拒绝` 且不交付第二端口；没有活动端口才建立运行期租约并与结果成对交付端口。owner 事实发布与端口交付分账；端口分配失败不能撤销已经发布的 owner 事实，结果必须允许同建立键收敛后重新尝试唯一交付。

### 6.2 v2 写入顺序

端口先在运行态检查：实例仍存活、端口未移动 / 析构 / 失效、租约仍是 owner 唯一活动端口。失败为 `许可拒绝`、零仓库候选。

仓库独占锁内顺序固定：

```text
请求合同 / 形状校验
-> 当前状态完整
-> owner 当前且范围为独占
-> owner 域幂等同键同写集 / 异写集裁决
-> 期望事实代次
-> 五类写项 owner 校验
-> 现行类型、引用、退出闭包和结构前置
-> 复制单一候选
-> 分配编码并写入 owner-scoped 三类事实
-> 退出 / 槽换代 / 索引同步
-> 记录 owner 域首次结果
-> 候选完整性
-> 原子交换
-> owner-aware 精确读回
```

五类 owner 校验完全按 4015 第 3.4 节：关系类型同 owner，关系端点可跨 owner；值所属 / 属性类型 / 新值同 owner，来源可跨 owner；属性槽同 owner；退出只能本 owner。owner 不符先于引用闭包返回 `许可拒绝`。同 owner 但外部当前引用未闭合才返回 `引用冲突`。

不同 owner 使用相同数值写入键互不复用；同 owner 同键同完整规范化写集返回首次结果；同 owner 同键异写集幂等冲突。实例维度由独立仓库状态天然隔离，不进入持久 DTO。

### 6.3 owner 退出

签发器只在端口租约已失效后进入仓库退出事务。仓库同一代次检查该 owner 当前节点 / 关系 / 值为零、owner-scoped 当前幂等提交已收敛、无未闭合引用；当前阶段恢复 / 审计引用为不适用。通过后 owner 移入历史、编码永久占用；退出后不得复活或重新签给其它服务。

本叶不实现重入，也不以“owner 退出后重建同编码”模拟恢复。

## 7. 运行包、签发器与 raw 端口

`服务.L1事实基座.ixx` 在同一模块内定义非导出的实例状态，包含单一仓库、实例内部身份、活动端口互斥与 owner 到弱租约的表。导出：

- owner 编码、实例内部身份、地址、nonce、服务枚举或模块名都不能重建端口。

`绑定于` 只返回布尔实例匹配，不回显实例身份或租约；它用于 L2 服务构造时拒绝把 A 实例端口与 B 实例读取服务拼接。

`L1事实基座服务` 的精确签名固定为：

## 9. L2存在结构代表迁移

### 9.1 构造与成员

旧构造 `explicit L2存在结构服务(L1事实基座服务&)` 删除。新唯一构造固定为：

```cpp
explicit L2存在结构服务(
    const L1事实基座服务& 第一层读取服务,
    L1所有者范围写端口&& 第一层写入端口);
```

构造时要求端口有效且 `绑定于(第一层读取服务)`；否则抛出 `std::invalid_argument`，端口不被保存。服务不可复制，保存一份 const 读取引用和一份 move-only 端口，不返回、借用、复制或转签端口。

增加：

```cpp
L2结构结果头 读取当前事实代次() const;
```

该函数只把 L1 全局当前事实代次映射为结构化 L2 读取结果，使普通调用者能形成后继请求头；不回显 owner、端口或实例身份，不作为 owner 证明。

存在服务公开函数全集固定为现行六根加本次事实代次读取：`新增存在节点`、`新增存在固定属性`、`换代存在固定属性`、`读取完整存在`、`退出存在`、`读取存在节点`、`读取当前事实代次`。现行六根的请求 / 返回类型不变；不得建立第二同义读取或写门面。

### 9.2 三处写调用

以下三个现行写根全部构造 `L1所有者范围写集请求` 并调用端口：

1. `新增存在节点`；
2. `提交并读回存在固定属性写集`（被新增 / 换代固定属性共用）；
3. `提交并读回存在退出写集`。

L2 `L2结构幂等身份` 仍一对一映射为 owner v2 写入幂等身份，不改变 L2 DTO。所有写入结果必须核对合同版本、回显 owner 等于端口 owner、幂等身份、发布 / 重复形状、事实代次和编码映射。

全部存在节点、值、属性和历史读回改用 owner-aware 入口；形成 L2 值式投影前必须核对：

- 存在节点、固定属性值、属性类型属于服务端口 owner；
- 来源节点允许跨 owner；
- owner 事实当前有效且范围为独占；
- 当前 / 历史 / 一致投影代次和 owner 一致。

任何 v1 legacy 投影或其它 owner 事实都不能被存在 provider 接受；不按形状、关系数、本地键或类型编码猜 owner。

固定属性方法的代码必须完成 v2 迁移和静态闭包，但本叶不发明“存在专用测试属性类型”。其成功运行需要后继正式身份来源提供同 owner 属性类型；因此本叶完成声明不得声称固定属性类型来源或 G2 已完成。

### 9.3 公开装配 provider

`装配.普通应用.ixx` 成为 owner 与存在服务绑定的唯一上层 provider：

- `普通应用上下文` 不再 public 默认构造，不再公开 `L1` 成员；
- 上下文 private 持有一个 move-only `L1事实基座运行包` 和一个 `unique_ptr<L2存在结构服务>`；
- `构造普通应用上下文` 建立运行包，以本实例固定建立幂等身份建立一个 `独占结构范围` owner，移动端口构造唯一存在服务；任一步失败映射为具名装配非成功；
- 上下文公开 `L2存在结构服务& 取得L2存在结构服务() noexcept` 与 const 重载；重复调用返回同一地址；
- 不公开运行包、L1 服务、签发器、owner 编码选择、raw 端口或按 owner 重建服务入口。

`普通应用装配状态` 在现有值后追加 `所有者范围建立失败` 和 `存在服务构造失败`，不重排现有数值。启动层继续只消费装配成功 / 非成功，不取得 L1 权限。

公开装配签名固定为：

```cpp
L2存在结构服务& 普通应用上下文::取得L2存在结构服务() noexcept;
const L2存在结构服务& 普通应用上下文::取得L2存在结构服务() const noexcept;
普通应用装配结果 构造普通应用上下文(const 普通应用配置& 配置);
```

### 9.4 场景 / 特征构造闭包

`L2场景结构服务` 构造改为：

```cpp
explicit L2场景结构服务(
    L1事实基座服务& 第一层服务,
    const L2存在结构服务& 存在服务) noexcept;
```

私有保存 `const L2存在结构服务&`。内部 `检查成员存在端点` 改接该引用；`读取存在当前场景成员引用` 同样使用成员引用。两处临时 `{L1}` 构造归零。

场景服务本叶仍走 v1 legacy 写。它若尝试用 v1 关系引用独占存在节点，将按 L1 v1 隔离合同返回结构化入口拒绝；本叶不建立兼容旁路，不宣称场景成员写已迁移。`L2特征结构服务` 已注入 const 存在服务，保持源码不变。

## 10. 生产外验证矩阵

### 10.1 L1 owner 黑盒矩阵

验证项目只能 import 公开合同 / 服务模块，禁止 import 仓库、访问锁、状态、租约或解析日志。必过：

1. 每个运行包只有一实例一签发器；两个独占 owner 编码不同；另一运行包同数值建立键属于另一实例；

3. 移动源、析构后保存的无能力观察、owner 退出后提交均许可拒绝且零代次推进；A 端口与 B 服务 `绑定于` 为 false；
4. 请求类型无 owner 字段；新节点自动 owner；关系类型 / 关系 owner 相同，端点可跨 owner；值所属 / 类型 / 新值同 owner，来源可跨 owner；
5. 属性槽和退出混 owner 在候选前许可拒绝；同 owner 但引用未闭合才引用冲突；
6. owner 域同键同写集精确重复、同键异写集冲突、不同 owner 同数值键互不复用；
7. owner 当前 / 历史、三类事实当前 / 历史、关系组、属性值组和一致投影回显正确 owner 与同截止；
8. v1 代表节点 / 关系 / 值 / 属性 / 退出原 DTO 行为保持且全部落 legacy owner；v1 触碰独占 owner 任一角色入口拒绝；
9. legacy 事实不能经 v2 端口原地改 owner；无 adoption 合同时保码迁移拒绝；
10. owner 当前事实归零、端口析构、幂等和引用闭合后退出成功，历史可读且重新建立不会复活原 owner；
11. 静态扫描证明 L1 核心零 L2 import / friend / 枚举分支，raw 端口 private 构造且无复制；
12. 当前阶段不执行未知发布后的恢复重入，该缺口必须标为未覆盖，不能返回伪 PASS。

## 12. 失败收口与执行门禁

以下任一发生即停止受影响切片并具名返回计划支撑：

- owner DTO / 状态 / 事务顺序无法按本设计唯一实现；
- 需要让 L1 反向识别 L2，或需要公开 signer / raw 端口才能装配；
- 场景构造闭包出现本设计未列出的正式生产调用点；
- 固定属性成功验证需要发明未经 G2 / 正式结构合同裁决的属性类型来源；
- 主工程或专项双配置持续失败且无法在白名单内归因；
- 目标文件 / 语义或发布租约与其它所有者重叠。

执行不得用兼容旧构造、测试专用服务、假 owner、默认 owner、名称推断、raw 端口公开构造或空成功绕过失败。
