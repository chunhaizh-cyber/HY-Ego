状态说明：计划支撑修订候选；运行状态只由`计划/计划索引.md`裁决。本文件完整继承 v0.4、v0.3 和 v0.1，只修订本文件具名的 method v2、派发门控与 worker 公开合同；冲突时以本文件为准。

## 1. 来源问题、裁决与边界

来源执行退回：

```text
DRIFT-METHOD-V2-PUBLIC-ABI-AND-SUBJECT-CONSTRAINT-UNFROZEN
```

当前`L2普通方法结构.数据.h`只有旧`L2方法动作入口事实`；`服务.L2方法结构.ixx`虽已有内部`动作入口V2`类别，却仍按旧五字段负载解析。当前没有`L2方法动作入口*_v2`公开 DTO/入口，也没有`实例方法技术许可*`、`实例方法动作调用/返回`、`任务执行派发门控*`和`任务强类型执行请求`目标合同。执行者因此无法机械完成“method v2 -> 门控 -> worker”单一叶。

需求权威已经裁决：

```text
动作作用主体约束必须使用 L2存在身份。
L2概念身份只可作为方法或动作约束材料，不是运行时作用主体。
```

本版本只冻结下列三段 ABI：

1. 方法动作入口 v2 的结构写读合同；
2. 技术许可、控制态、调度资格、安全硬否决与授权汇合后的派发门控合同；
3. 任务管理线程到 worker、worker 到稳定动作端口、worker 到待验证材料的合同。

本版本不改变 self 授权、安全硬否决、任务阶段、结果发布、核算、轮次收束或后继决议的机器语义；不修改流程图、正式规范或其它叶设计。v0.3 业务流程图继续有效。

依赖方向唯一为：`实例方法执行.数据.h -> 任务执行派发门控.数据.h -> 服务.实例方法执行.ixx`。门控数据头还可以依赖已发布的阶段消费 DTO、6170 快照值合同、自我授权事实和硬否决 DTO；实例执行基础数据头只依赖 method v2 与 task 值合同，绝不反向包含门控数据头。这样`任务执行派发冻结`不会与技术许可形成循环包含。任何数据头都不得持有 service、写端口、事务凭证或事实仓库。

## 3. 方法动作入口 v2

### 3.1 作用范围、事实与请求

下列声明按所示物理顺序落入`L2普通方法结构.数据.h`；所有 struct 均逐字段`operator== = default`：

```cpp
inline constexpr std::uint32_t L2方法动作入口合同版本_v2 = 2;

enum class L2方法动作作用范围 : std::uint8_t {
    内部治理 = 1,
    纯现实观察 = 2,
    现实改变 = 3
};

struct L2方法动作入口事实_v2 final {
    L2方法动作入口身份 身份;

    std::uint32_t 技术许可合同版本 = 0;
    L2生命周期 生命周期;
};

struct L2方法动作入口写入请求_v2 final {
    std::uint32_t 合同版本 = L2方法动作入口合同版本_v2;

    L2结构幂等身份 幂等身份;
    L2方法身份 方法;
    L2方法内容版本 方法内容版本;
    std::uint64_t 顺序 = 0;
    L2方法稳定动作键 稳定动作键;
    L2方法动作作用范围 作用范围 = L2方法动作作用范围::内部治理;
    L2存在身份 作用主体约束;
    std::optional<L2场景身份> 场景约束;

};

struct L2方法动作入口读取请求_v2 final {
    std::uint32_t 合同版本 = L2方法动作入口合同版本_v2;
    L2结构请求头 请求头;
    L2方法身份 方法;
    L2方法内容版本 方法内容版本;
    std::uint64_t 顺序 = 0;
    L2方法稳定动作键 稳定动作键;

```

`L2方法动作作用范围`是该三值集合的唯一物理定义。既有`L2任务结构.数据.h`删除自己的重复枚举声明，并只保留`using 任务动作作用范围 = L2方法动作作用范围;`；既有`任务冻结动作项`的源码拼写和枚举成员用法因此保持兼容，但不再形成第二作用范围类型。

有效性固定为：合同版本精确为 2；请求头有效且期望事实代次非零；方法、内容版本、顺序、稳定动作键、作用主体、动作范围材料和技术许可合同版本均有效/非零；作用范围只能是三枚举之一；可选场景存在时必须有效。`作用主体约束`只能是`L2存在身份`。`L2概念身份`、零存在、字符串、稳定编码别名或 optional 主体均不得进入该字段。

同一`方法 + 方法内容版本`内，动作顺序从 1 连续；首次写只能追加当前最大顺序的下一项，不允许空洞。顺序和稳定动作键分别唯一。精确重复必须全部字段相同；同键异义、同顺序异义或同动作键异义分别结构化拒绝，禁止覆盖。


| 入口 | 状态 | 完整 v2 事实 | 提交见证 | 正式读回截止 | `成功()` |
| --- | --- | --- | --- | --- | --- |
| 写 | `已形成`、`精确重复` | 必有 | 空 | 非零 | 是 |
| 写 | `已可能发布` | 空 | 必有且四字段有效 | 0 | 否 |
| 写 | 其它 | 空 | 空 | 0 | 否 |
| 读 | `已读取` | 必有 | 不适用 | 非零 | 是 |
| 读 | 其它 | 空 | 不适用 | 0 | 否 |

交换前失败零写。L1 已确认提交后独立读回失败只返回`已可能发布 + 提交见证`；原请求和原幂等身份重放后，精确重复零应用、零新代次，并在正式读回成功后返回首次事实。

### 3.3 v1 边界

既有`L2方法动作入口事实`、`L2方法动作入口提交项`和既有普通方法写读 ABI 保持源码兼容，只代表旧 v1 形状。它们不升级、不补 optional 尾字段、不别名为 v2、不猜测作用范围，不得作为 v2 两入口的成功载荷。现有内部`动作入口V2`类别必须改为上述真实 v2 物理负载；旧五字段解析不得保留为 v2 兼容路径。

### 6.3 旧任务请求协议退出边界

现行源码中的`任务执行冻结请求`、`下一筹办工作包`、外部`提交已形成任务工作结果`及“调用方预形成结果 -> 工作线程只跑尾部”属于旧请求形状，全部退出生产。现行旧协议常量即使仍名为`任务执行请求协议版本 = 2`，也不得被误称或别名为本节合同版本 1；目标合同版本 1 是新的`任务强类型执行请求`独立形状。

旧类型可在删除消费者前短暂保持可编译，但必须确定性拒绝进入新队列和新 worker，零动作、零待验证材料、零正式结果；最终白名单施工删除其生产 import、队列槽、转发入口和普通应用装配。禁止用 optional 尾字段、字段缺省或摘要桥接两代协议。

## 7. 实施顺序与验证矩阵

机械实施顺序固定为：

```text
method v2 DTO与写读入口
-> 稳定动作端口与技术许可
-> 当前阶段/控制态/调度资格证据
-> 派发门控与派发冻结
-> 强类型任务请求队列
-> worker真实动作调用与待验证材料
-> 旧外部预形成结果入口退出
```

最终统一验证至少覆盖：

1. method v2 首次、精确重复、幂等异义、顺序冲突、动作键冲突、引用冲突、提交后读回失败与同键收束；
2. `L2存在身份`主体成功，零主体和`L2概念身份`材料化主体均交换前拒绝；v1 不升级、不进入 v2 成功载荷；
3. 空/零/重复动作端口使 provider 不可用；许可八状态逐项覆盖；
4. 终止、休眠、主动运行，安全/服务来源，零资格及 6150 适用倍率分账；配额或倍率不能替代授权；
5. 门控十一状态逐项覆盖，只有可派发有冻结；不合格控制、零资格、技术拒绝、预检硬否决均零授权请求；
6. 内部治理/纯观察零授权，现实改变必须有唯一当前授权；最终硬否决可阻断已授权但未开始的动作；
7. 强类型请求两阶段准备/确认、精确重复、异义、容量等待、停止排空；未确认请求不被 worker 消费；
8. 动作返回逐项顺序、键、时间和状态闭合；只有前两种成功状态有待验证材料；
9. worker 是执行入口唯一生产调用者，旧外部提交已形成结果入口和旧请求生产符号归零；
10. 待验证材料经现实独立读回后才形成正式结果，动作返回不能直接完成任务、满足需求或推进后继。
