## 1. 目标与最早缺口裁决

本叶只补齐一个已由真实第二层消费者暴露的第一层中性查询缺口：按“目标节点稳定编码 + 关系类型节点稳定编码”读取全部当前关系，并让既有场景事实所有者判定一个实际存在是否只有一条当前直接场景归属。

当前 `L1场景结构服务::读取初始场景接纳` 只按调用方给出的 `归属关系` 稳定编码读取一条当前关系。该读取能证明“这一条关系字段正确”，但不能证明同一成员没有第二条同类型当前关系。4200 要求一个存在在同一世界中恰有一个当前直接场景；唯一性属于第二层场景业务，第一层只需提供不解释场景、存在或唯一性的条件关系组查询。

不选择其它候选的理由：

1. 关系替换需要第二个真实已发布场景；当前新链只有初始场景，不能为覆盖矩阵虚构移动入口。
2. “删除实际存在”被 4200 明确排除；当前只允许退出场景成员关系，不删除、退役或回收存在本体。
3. 旧实例特征入口中的完整快照调用没有正式仓库外生产消费者，不能作为本轮真实消费者依据。
4. 既有可重建管理索引依赖完整快照并服务于旧管理路径；普通查询不得复用其全仓扫描、完整快照或末尾再次读取快照的成本。

本叶不是第一层自证。代码候选发布后，只允许由合法第二层消费者经既有场景服务实际使用新查询，并以结构化结果和最终权威读回累计证明本消费者覆盖的查询行为。单个消费者不能宣称整个第一层已经完善。

## 3. 分层与所有权

### 3.1 第一层责任

第一层只负责：

- 校验中性查询合同版本、目标节点编码和关系类型节点编码；
- 在一次仓库共享锁内读取指定索引桶；
- 按桶内稳定编码回读当前关系权威事实；
- 验证每项仍满足目标和类型条件；
- 按关系稳定编码严格升序返回当前关系组和同一读取事实代次。

第一层不解释目标节点是不是实际存在、源节点是不是场景、关系类型是不是直接成员、角色是否等于零、结果是否业务唯一，也不决定请求中的精确归属关系是否成立。

### 3.2 第二层责任

`L1场景结构服务` 继续是直接存在成员关系的唯一场景事实所有者。它负责：

- 读取并验证当前成员节点和直接成员关系类型节点；
- 调用第一层中性条件查询；
- 零项映射为场景接纳未找到；
- 一项时验证精确关系编码、源端、目标端、类型和角色；
- 多项映射为内部不一致；
- 只在场景、成员、类型、关系组和首末代次一致时返回场景接纳事实。

场景服务不保存关系组缓存，不建立第二索引，不直达仓库，也不把日志作为成功依据。

## 4. 第一层公开中性合同

### 4.1 DTO

以下类型进入 `海中鱼巣/核心/L1中性CRUD.数据.h`，由既有 `海中鱼巣.核心.合同.L1中性CRUD` 自动公开，无需修改合同模块：

```cpp
struct L1中性目标关系读取请求 final {
    std::uint32_t 合同版本 = L1中性CRUD合同版本;
    稳定编码 目标节点;
    稳定编码 关系类型节点;
    friend bool operator==(const L1中性目标关系读取请求&,
        const L1中性目标关系读取请求&) = default;
};

struct L1中性目标关系读取结果 final {
    L1中性读取状态 状态 = L1中性读取状态::入口拒绝;
    std::uint32_t 合同版本 = L1中性CRUD合同版本;
    稳定编码 目标节点;
    稳定编码 关系类型节点;
    std::uint64_t 读取事实代次 = 0;
    std::vector<L1中性关系事实> 关系组;
    friend bool operator==(const L1中性目标关系读取结果&,
        const L1中性目标关系读取结果&) = default;
};
```

### 4.2 唯一公开入口

```cpp
L1中性目标关系读取结果 读取中性当前目标关系组(
    const L1中性目标关系读取请求& 请求) const;
```

物理所有者：`海中鱼巣/核心/服务.L1事实基座.ixx` 中既有 `L1事实基座服务`。

合同固定为：

1. 合同版本不匹配，或目标 / 类型编码为零，返回 `入口拒绝`、代次零、空组；
2. 合法请求零命中返回 `成功`、权威当前事实代次、空组；整个仓库仍为空时该代次可以为零，已有任何事实时必须非零；零项不是 `未找到`；
3. 一项或多项命中均返回 `成功`，每项是完整当前中性关系事实；
4. 关系组按关系稳定编码严格升序且无重复；
5. 所有结果回显调用方的目标和关系类型；任何非成功结果都返回代次零和空组；资源异常返回 `资源失败`，索引与权威事实矛盾返回 `内部不一致`；
6. 入口不读取完整快照、历史、审计、恢复材料、SQL、旧管理索引或日志。

## 5. 仓库派生索引

### 5.1 形状

仓库 `状态` 新增业务中性的当前目标关系派生索引，逻辑形状固定为：

```text
(目标节点稳定编码, 关系类型节点稳定编码)
    -> 按关系稳定编码严格升序、无重复的当前关系稳定编码组
```

实现可使用两级无序映射加有序编码组，但不得保存关系端点、角色、创建代次、退出代次或第二份关系事实。空桶必须删除。

索引不是权威。权威仍是 `状态.当前关系`；索引只提供受影响关系的候选编码。

### 5.2 候选内维护

中性提交与 legacy 提交都已先复制 `状态` 为候选并在最后一次交换发布。本叶要求：

1. 每次候选新建关系成功后，以新关系的目标、类型和编码插入对应桶并保持严格升序；
2. 每次候选退出关系前保留原关系目标和类型，从对应桶删除该编码；桶空时删除桶；
3. 节点或值新建、退出和属性槽变更不修改关系索引；
4. 索引插入、删除、候选完整性校验和关系事实变更属于同一候选；任一失败都不得交换权威状态；
5. 状态交换一次发布关系事实和派生索引，不存在可观察的半更新窗口。

### 5.3 完整性与进程内派生

`状态完整` 必须验证：

- 每个当前关系恰在其目标 + 类型桶出现一次；
- 每个索引编码都能在当前关系中找到且目标、类型全等；
- 每桶严格升序、无零编码、无重复；
- 索引没有空桶和额外编码。

允许的“重建”只表示：在当前进程内，从已经形成的第一层权威 `当前关系` 纯函数派生该索引，防止索引成为第二权威。既有状态材料转成当前关系状态后可调用同一纯派生函数维持现有兼容路径，但本叶不得新增或修改恢复材料格式、恢复公开入口、恢复状态、持久文件或 SQL，也不得增加崩溃、重启、断电、跨进程恢复测试或完成门禁。

普通条件查询不得调用 `状态完整` 或进程内全量派生函数。全量派生只用于状态构造 / 候选不变量维护；普通查询只访问请求对应桶并回读该桶涉及的权威关系。

## 6. 仓库查询流程

仓库内部条件查询按固定顺序：

1. 请求纯值无效时返回入口拒绝；
2. 取得一次仓库共享锁；隔离状态返回内部不一致；
3. 保存当前事实代次；代次为零时仍允许合法空仓查询返回成功和零代次，非空关系状态必须有非零代次；
4. 查找目标 + 类型桶；不存在时返回成功、当前代次、空组；
5. 按桶中编码顺序逐项查 `当前关系`；缺失、重复、非升序、目标或类型不符、携带退出代次时返回内部不一致和空组；
6. 逐项复制完整关系字段为 `L1中性关系事实`；
7. 在同一共享锁释放前返回成功、保存的事实代次和关系组。

查询不另读首末代次，因为桶和权威当前关系已经在同一仓库共享锁内读取。第二层跨多个第一层调用组合时仍须用自己的首末代次门禁防止混代。

## 7. 第二层真实消费者修订

### 7.1 目标函数

只原位修改：

```cpp
L1场景结构服务::读取初始场景接纳(
    const 初始场景接纳读取请求& 请求) const
```

公开签名、请求和结果 DTO、服务构造、锁和调用者全部不变。

### 7.2 内部读取

模块内部 `读取接纳实现` 保留现有场景读取、起始代次、成员节点、关系类型节点和结束代次，将精确关系读取替换为：

```cpp
L1.读取中性当前目标关系组({
    L1中性CRUD合同版本,
    请求.成员,
    登记结果.登记->直接成员关系类型});
```

结果分账固定为：

| 条件查询结果 | 第二层结果 |
| --- | --- |
| 第一层非成功 | 按现有中性读取状态映射，空事实 |
| 成功且关系组为空 | `未找到`，空事实 |
| 成功且关系组多于一项 | `内部不一致`，空事实 |
| 成功且恰一项，但编码、源端、目标端、类型或角色不等于请求的初始场景接纳 | `未找到`，空事实 |
| 成功且恰一项并逐字段匹配 | 继续形成既有 `初始场景接纳事实` |

第一层结果回显的目标、类型和读取代次必须分别等于请求成员、登记直接成员类型和本次共同截止。关系事实必须未退出，创建代次非零且不晚于共同截止。第一层组内字段若违反查询条件属于内部不一致，不得降级为未找到。

P9 退出后的读取不再读取精确已退出关系：条件组自然为空，第二层返回未找到。历史事实继续只能由 P9 场景退出入口的历史读回拥有，本查询不返回历史。

## 8. 并发、状态与非成功

1. 仓库条件查询只使用既有共享锁；不新增锁、许可令牌或可变仓访问。
2. 关系索引更新只在提交候选内发生，与关系创建 / 退出同一原子交换；失败候选不影响权威状态。
3. 场景服务继续使用既有场景锁串行其业务组合读取；不跨层传递第一层锁。
4. 第二层首末代次不同返回版本漂移；不重试拼接，不用部分结果补成功。
5. 第一层空组是合法查询结果；是否代表业务未找到由第二层决定。
6. 日志只供人观察，不参与零 / 一 / 多判定，不替代结构化状态或权威读回。
