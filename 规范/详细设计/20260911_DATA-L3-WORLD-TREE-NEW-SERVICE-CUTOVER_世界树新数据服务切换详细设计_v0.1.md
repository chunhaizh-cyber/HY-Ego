日期：2026-09-11

版本：v0.1

身份：`DATA-L3-WORLD-TREE-NEW-SERVICE-CUTOVER`

状态：创建侧设计已闭合；执行状态以计划索引为准

代码事实基线：`cc58a59c173526d7c35465d112cfd9595d8b1fc7`

## 1. 目标与本次裁决

本设计把已经失去提供者的旧世界树实现清空重构为现行 `DATA-L3` 世界树消费者，并在同一闭环计划内补齐其最早且不可分割的 `DATA-L2` 场景直接包含与树读取提供者。用户已裁决：L2 缺少的函数可以在不违反正式规范的前提下补充；世界树只保留仍有意义的六个公开函数名称和目的，旧函数体、旧 DTO、旧 helper 与旧场景接口依赖全部物理删除。

保留的六个目的为：

1. `验证现实世界根`：验证装配方显式给出的根场景，并读取其当前场景树闭包；
2. `读取现实世界存在位置`：在已验证树中唯一定位直接存在成员；
3. `移动现实世界存在`：由场景 owner 原子替换直接存在成员父关系；
4. `移动现实世界场景`：由场景 owner 原子替换直接子场景父关系；
5. `创建场景并纳入现实世界`：先由存在 owner 创建对象，再由场景 owner 在一笔写集中启用同节点场景角色并接纳为直接子场景；
6. `创建存在并纳入现实世界`：先由存在 owner 创建对象，再由场景 owner建立直接存在成员关系。

本片不修改正式规范，不恢复旧 R1 独立场景节点族、旧场景类 DTO 或旧业务资格账。4230 仍要求场景 owner 内的树登记锚点、根标记和非根树归属；本片须按同节点 C 角色重新实现这些私有结构元数据，而不是恢复旧独立场景节点。`现实世界根`由 DATA 外装配显式提交，但世界树只有在新场景树读取合同确认该 C 具有当前根标记、完整同树闭包时才接受，不能从无父节点、名称、缓存或显示顺序猜根。

## 3. 字段、owner 与物理关系

### 3.1 场景字段与树元数据确认

本片只补4202已经确认的两项关系字段，不增加场景第八字段。4230要求的树登记锚点、根标记和树归属是场景owner私有结构元数据，不是场景本体字段：

| 字段 | owner | 关系方向 | 端点 | 基数 |
| --- | --- | --- | --- | --- |
| 直接存在成员 | 场景 owner | `父场景 C -> 成员存在 E` | C须启用场景角色；E须为当前存在 | 一个E在“存在组成父、直接存在成员父、直接子场景父”三类当前关系合计至多一个；一个C可有0..N直接存在成员 |
| 直接子场景 | 场景 owner | `父场景 C -> 子场景 C` | 两端都须启用场景角色并且也是当前存在 | 一个子C在三类当前父关系合计至多一个；一个父C可有0..N直接子场景 |

两字段使用两个互异的场景 owner 专属关系类型，角色/顺序固定为1。树元数据再使用一个不可变树登记锚点、一个根标记关系类型和一个树归属关系类型；五个编码与根绑定、状态组织、动态组织、特征组织、C/E/S绑定和存在组成关系类型全部互异。根标记固定为`根C -> 树登记锚点`，树归属固定为`非根C -> 根C`，角色均为1；`L2场景树身份`等于根C编码。

`场景树当前事实`是按显式根和 `G0` 形成的调用方值式投影，不持久化为节点、关系或第二列表。递归父链来自三类既有权威关系：直接子场景、目标已启用C角色的直接场景成员、目标已启用C角色的存在组成；后两类只是角色投影，不补直接子场景边。直接存在成员组仍只列第一类场景成员事实，不能把组成或子场景复制进去。

### 3.2 联合单父与无环

联合直接归属提供者对同一成员在同一`G0`读取三类当前目标关系并形成0或1条联合父事实；多于1条固定`内部不一致`。建立或迁移任一组成/直接包含关系前，对应数据服务在同一`G0`：

1. 用各自现行身份提供者确认关系端点；
2. 调用同一个联合提供者读取成员的当前联合父；
3. 新增要求联合父为空；迁移要求唯一联合父逐字段等于请求原关系；
4. 从候选父开始反复读取其联合父，若命中成员则`形成场景环`，任一步多父或坏见证为`内部不一致`，代次变化为`事实代次漂移`，超过调用方祖先预算为`数量预算不足`；
5. 前置全部使用请求G0，所属owner写集仍以同一G0提交。并发另一归属发布后，全局代次改变，后提交写固定漂移而不能形成双父。

同类别关系替换由所属 owner 一个写集同时退出旧边并建立新边。跨“存在组成父 ↔ 场景包含父”的类别迁移不在本片；发现另一类别父时返回引用冲突，不能分两次移动。L1有限N事务v3只在两边均有真实写集时可用，不能用空写参与者模拟联合读取守卫。

共同抽象接口只定义跨模块调用形状，沿用仓库既有`provider + 绑定于(L1)`信任边界，不新增针对恶意非生产C++实现的安全模型。唯一生产组合实现`直接归属联合只读组合器`完整定义于`合同.场景角色组织.ixx`，不在其它named module重复声明或补成员定义；它只保存两侧普通窄provider的non-owning引用，构造不接收或查找L1。`绑定于(candidate L1)`每次同时调用两侧provider的`绑定于`，只有双方都绑定该candidate才返回true；存在或场景服务在各自入口用自己已经持有的L1调用该谓词，因此不需要L1 getter。组合器按同一G0分别调用两侧公开窄读，合并三类事实；父多于一条固定`内部不一致`，任一漂移/预算/资源/坏形状结构化映射且零联合载荷。它不直达L1、不缓存、不写入；两个`使用...提供者`以`std::addressof`比较构造时保存的接口实例地址。

父读取成功允许`父==nullopt`且`子组`为空；子组读取成功要求`父`为空，子组按`(成员,来源,关系)`稳定升序。存在的子存在新增/删除函数与场景的全部包含写/树读都显式接收`const 直接归属联合只读提供者&`。存在侧通过共同接口的`使用存在组成提供者(*this)`核对本侧实例；场景侧因已完整可见final组合器，先`dynamic_cast<const 直接归属联合只读组合器*>`，失败即入口拒绝，再调用`使用场景包含提供者(*this)`核对本侧实例。两侧同时核对`绑定于(本L1)`，但不得先按旧G0读取联合事实。组合器在两个数据服务完成构造后建立，因此没有构造循环；服务不保存它，不泄露raw端口。

全部存在/场景归属新增、退出、迁移和角色启用统一使用以下时序：

1. 完成请求形状与联合provider绑定/本侧实例校验；短暂取得本owner写互斥，只查本owner现有幂等记录。同键同完整请求且已经确认发布时，直接按首次H读回并返回精确重复；同键异义返回幂等冲突；随后释放锁。
2. 无既有结果时，在不持有任何owner写锁的情况下，以请求G0执行两侧窄读、联合父/子闭包、角色和预算校验；两侧窄读自身不得取得owner写锁。任一失败零写。
3. 重新取得本owner写互斥，再次检查同一幂等键；并发期间若已有同请求发布则精确重复，异义则冲突。仍未发布时只使用第2步完整结果形成本owner写集，并以原请求G0提交；期间不回调联合provider或另一服务。
4. L1提交负责最终事实代次守卫；漂移返回漂移且零写，已可能发布冻结原请求，确认发布后按首次H和明确后继截止读回。任何路径都不同时持有两个owner写锁，也不在持锁时重入本服务窄读。

存在类具体改动固定为：`存在类数据服务`同时继承`存在组成结构只读提供者`；新增`新增子存在关系(const 存在类成员新增请求&, const 直接归属联合只读提供者&)`与`删除子存在关系(const 存在类成员删除请求&, const 直接归属联合只读提供者&)`。既有`新增成员关系/删除成员关系`只继续接受`成员种类::特征`，对子存在请求返回`入口拒绝`且零写，防止绕过联合守卫；当前生产源码没有子存在调用者。两个具名入口除联合父与祖先检查外，必须在请求关系预算内扫描目标子E的完整组成子闭包并逐项读取C角色：只要目标自身或任一组成后代已启用C角色，新增与删除都返回`引用冲突`且零写，避免把已有场景投影接入另一树或留下仍指旧根的无路径C。该闭包合法为空，任何漂移、多父、环或预算不足均结构化失败。本片不提供跨类别替换函数；当前入口遇到另一类别父时返回已有`引用冲突`，不以两次调用模拟。

诊断责任：结果谓词和实例同一性为`无适用错误分支`；两侧读取、联合读取和服务入口为`向上送出`。

普通`新增直接存在成员`只接纳未归属E，并在关系预算内扫描目标E的完整组成子闭包；目标自身或任一后代已有C角色时固定`引用冲突`，不得把既有场景投影接入另一树。`退出直接存在成员`执行相同扫描，发现任一C固定拒绝；只有不承载C投影的普通E才可直接退出且不删除E。`迁移直接存在成员`也扫描同一闭包：没有C时按普通同类迁移；存在C时只有目标场景、原场景及闭包内全部C的树证明均指向同一根才允许同owner原子换父，任一跨树、缺证明、复义或超预算均拒绝且零写，树证明不改。直接子场景字段的“增”由`启用并接纳直接子场景`原子承接，不接受既有另一树根；“改”由`迁移直接子场景`承接且只允许同一树内换父。本片不提供独立子树退出/拆树业务；既有场景角色退出入口继续增加树证明、联合父、直接成员、直接子场景及F/S/D组织引用保护，命中任一项即`引用冲突`且零写。

`退出场景角色`增加引用保护：根场景固定拒绝；非根仍有树归属、联合直接父、直接成员、直接子场景或任何F/S/D组织时返回引用冲突。本片不提供普通场景角色退出成功路径，不隐式退出或搬迁树证明及关系。

所有新增/修改服务入口诊断责任为`向上送出`；纯成功谓词、稳定比较和`使用存在提供者`为`无适用错误分支`。

## 7. 六个函数算法与同截止

### 7.1 根验证与位置读取

`验证现实世界根`调用一次`读取当前场景树({1,G0,绑定根,预算},联合组合器)`。只有绑定根存在唯一当前根标记、无树归属/直接父、Gread/树形/稳定顺序和全闭包逐项一致才成功；无父但无根标记、错根、漂移、预算不足或结构复义全部非成功。

`读取现实世界存在位置`先取得同一G0的根结果，再扫描所有场景的直接存在成员组。零条=`存在不在现实树`，一条成功，多条=`成员多重位置`。不得把子场景角色投影、存在组成子节点或后代间接包含伪装成直接存在成员。

### 7.2 移动

两个移动入口先在G0读取现实树，证明原父、目标父和成员都在绑定根闭包；现实根不得作为子场景移动。随后分别以联合组合器调用场景服务的`迁移直接存在成员`或`迁移直接子场景`。provider在一笔scene-owner写集中退出旧边并建立新边。这里只覆盖scene owner内同类别替换；成员已有存在组成父或请求要求在组成/场景类别间迁移时返回`引用冲突`并保留后继能力缺口，不调用两次CRUD。

provider确认发布后，以其`Gread`重新读取现实树并唯一确认成员在目标。最终读回失败或形状矛盾返回`已发布待复核`；provider`已可能发布`映射`结果未知`。精确重复但fresh读回显示后继移动已经覆盖时返回`既有操作已被后继事实覆盖`。

### 7.3 创建场景

1. 在`观察G0`验证现实树及父场景；
2. 调用存在服务`新增存在({存在创建期望G0,存在幂等身份})`；
3. 若确认存在已发布，形成E、存在首次H和完整`场景直接子场景启用请求`。调用方已带固定请求时必须逐字段等于由E和顶层字段导出的请求，否则入口拒绝；
4. 以联合组合器调用场景服务`启用并接纳直接子场景(第二阶段请求,组合器)`；第二阶段交换前漂移时，用下游Gread重新验证父仍属于绑定现实树，再返回只更新G0的续跑请求；发布未知后原第二阶段请求冻结，不得更新；
5. 以provider返回Gread重新读树，确认E已启用C角色、直接父为请求父、只出现一次，才返回成功。

存在已创建而第二阶段尚未发布时返回`部分已发布`并携带原请求、进度及仅在安全时存在的续跑请求；不得删除E。第二阶段发布未知或最终读回失败分别返回`结果未知`或`已发布待复核`。

### 7.4 创建存在

与7.3相同，但第二阶段完整请求为`场景直接包含写请求`并调用`新增直接存在成员(...,联合组合器)`，最终确认E唯一位于目标场景。存在已创建不等于整体成功；不建立第三意图账，续跑只使用返回的完整顶层续跑请求。

### 7.5 状态映射

| 下游 | 世界树映射 |
| --- | --- |
| 预读或存在创建交换前的入口拒绝、事实代次漂移、幂等冲突、数量预算不足、历史材料已清理、资源失败 | 同名，且无已发布进度 |
| 场景未找到/已退出 | `场景不在现实树` |
| 存在未找到/已退出 | `存在不在现实树` |
| 预读已成功后provider成员未归属/多重归属 | 移动为`事实代次漂移`或`内部不一致`，按Gread是否改变分账；读取位置的零/多项才分别为不存在/多重位置 |
| 成员已归属 | 同一请求目标为`目标位置相同`，其它为`引用冲突`；不能算精确重复 |
| 原父不匹配/目标父相同/形成场景环/引用冲突 | `原位置不匹配`/`目标位置相同`/`形成场景环`/`引用冲突` |
| 存在创建确认后，第二阶段交换前任一非成功 | 顶层`部分已发布`，阶段=`场景包含发布`，保留对应场景原因；仅漂移且fresh父验证仍成立时给续跑请求 |
| 任一实际提交阶段provider已可能发布 | `结果未知`，阶段指明存在创建或场景包含发布；已知进度按阶段携带 |
| 确认发布后最终读回不闭合 | `已发布待复核` |
| 精确重复的首次历史结果完整且fresh当前形状已被合法后继改变 | `既有操作已被后继事实覆盖`；无法确认当前为`已发布待复核`，结构自相矛盾为`内部不一致` |
| 坏版本、坏回显、混代、遗漏枚举及其它不可能形状 | `内部不一致` |

`std::bad_alloc/std::length_error`映射资源失败，其它异常映射内部不一致。任何非成功均不得返回成功投影。

3. 世界树服务不拥有L2服务或事实，不缓存树，不持有跨调用锁，不建立线程。
