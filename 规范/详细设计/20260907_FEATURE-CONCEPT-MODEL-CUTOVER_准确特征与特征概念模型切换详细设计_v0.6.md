# FEATURE-CONCEPT-MODEL-CUTOVER 准确特征与特征概念模型切换详细设计

日期：2026-09-08
版本：v0.6
身份：`FEATURE-CONCEPT-MODEL-CUTOVER`
正式修订基线：`ea2c3f950d8e349d1738d73dc1a63eed491e6603`

## 1. 修订范围

本版本继承 v0.5 未被本文件改写的全部合同，只闭合场景三阶段恢复实现暴露出的一个只读 ABI 缺口。

v0.5 正确禁止场景在“存在采用”和“最终读回”阶段重跑 `收敛类型观察`，但现有只读入口仍不能证明继续材料中的完整 `特征概念观察请求::准确值` 与持久观察锁定的 F 内容等值：

- 持久 `类型观察事实` 只保存观察键、F 和时间，不保存原 `特征准确值`；
- `特征概念应用服务::读取命名特征` 返回 F 的当前表示和名称，但外部 `特征值身份` 输入建立 F 时会复制完整 I64，F 自有值事实身份可以与原输入身份不同；
- raw variant 相等会误拒绝内容等值但身份不同的值，不比较又允许同观察键的继续材料改写原准确值；
- 解引用内容等值的现有权威能力是 `特征类数据服务::查询准确特征(FT, 准确值)`，场景不应新增对特征数据服务的直接依赖。

正式 1130、4110、4180、4230、4240、7160 及当前特征/概念接口足以在原目标内裁决：由已经持有特征数据服务的 `特征概念应用服务` 新增一个零写公开读取入口。场景只消费该入口，不增加 provider、持久字段、恢复账、跨 owner 事务或第二写入口。

## 2. Fapp 零写读取入口

### 2.1 签名、位置与可见性

在 `海中鱼巣/业务/应用服务.特征概念类.ixx` 的 `特征概念应用服务` 公共区新增：

```cpp
特征概念处理结果 读取已发布类型观察(
    const 特征概念观察请求& 请求,
    std::uint64_t Gread) const;
```

不新增 DTO。入参使用完整原观察请求和调用方已固定的非零当前事实代次；结果复用现有 `特征概念处理结果`。函数只读取 `特征类数据服务` 和 `概念树类数据服务`，不得读取或修改本实例的 `pending_input_`、`pending_`、`pending_feature_`、`confirmed_`，不得调用 `推进`、`写头`、`写`、`消费待确认写入`、`处理类型观察` 或 `收敛类型观察`。

该入口是 Fapp 对外只读应用函数，不是 DATA owner，不暴露内部 provider 引用，不允许场景自行调用 `查询准确特征`。函数为 `const`，不需要用应用 pending 互斥保护，因为它不接触实例恢复状态；开始和返回前必须用概念 provider 守卫同一 `Gread`，provider 并发变化按事实代次漂移分账。

### 2.2 成功流程

顺序固定：

1. 验证 `Gread != 0`、观察键 FT/来源/序号、准确值浅层结构、可选指定 F、最大保留观察数和预算形状；守卫概念 provider 当前事实代次等于 `Gread`。
2. 调用既有 `特征类数据服务::查询准确特征(请求.观察.类型, 请求.准确值)`。该函数负责把内联 I64 或外部特征值身份解引用为完整内容后查询；不得改用 `特征准确值::operator==`。
3. 在同一 `Gread/Gread` 调用 `概念树类数据服务::读取类型观察`，按完整观察键读取；必须恰有一条，且其键、时间分别等于请求，F 有效，可选指定 F 若存在则等于该 F。
4. 在第 2 步的准确查询结果中，观察锁定的 F 身份必须恰好命中一次；允许同时存在其它内容等值 F，因为持久观察已经唯一锁定本次 F。零次返回幂等冲突，重复同身份属于内部不一致。
5. 按该 F 调用 `concepts_.读取特征当前名称({2,{1,Gread,Gread},F,请求.预算.基础})`；名称必须存在、F 端等于观察 F。再按名称 C 调用 `concepts_.读取应用特征模板({2,{1,Gread,Gread},C,请求.预算})`；返回模板必须是非退役 `特征概念事实`，C、FT 与名称逐项一致。
6. 调用 `concepts_.判定应用特征模板({2,{1,Gread,Gread},C,{1,Gread,Gread,F},请求.预算})` 核验该 F 在 `Gread/Gread` 适用该 C；返回的模板必须仍是第 5 步同一完整 `特征概念事实`，判定中的完整准确 F、C 域、`Gread/模板H/实际H` 和命中结果必须逐项一致且 `适用=true`。守卫事实代次仍为 `Gread`。
7. 返回局部构造的 `特征概念处理结果`：`状态=完成`，`准确匹配` 只含观察锁定 F，`观察`、`概念`、`名称` 分别为上述已发布事实，`待确认请求` 和 `原因` 均为空。

该函数不登记新观察、不登记命中、不建立/组织概念、不变更名称、不生成写入头或幂等键。相同输入重复读取不增加任何业务计量事实。

### 2.3 非成功分账

结果继续使用现有状态与 `原因`：

| 事实 | 结果 |
| --- | --- |
| 请求字段或 Gread 非法 | `入口拒绝`；原因使用对应入口拒绝 |
| 指定 F、观察 F 与解引用准确查询不一致 | `入口拒绝`，`原因=特征数据错误::幂等冲突` |
| 同键观察不存在 | `材料缺失`，原因保留 provider 未找到 |
| 同键观察多于一条、同身份准确结果重复或不可能载荷 | `内部不一致` |
| 观察与准确值成立但名称不存在 | `准确F已成立名称未完成`；保留观察和单一 F |
| 名称 C、FT、生命周期或域适用不一致 | 对应引用冲突、类型不相容、规则缺失或内部不一致 |
| provider 旧格式、预算、历史、资源或事实代次失败 | 沿现有 `原因` 和状态映射返回，不改写为未找到 |

所有非成功结果的 `待确认请求` 必须为空；该只读入口永不返回“待原请求确认”，也不承诺通过再次调用自己完成缺失写入。

## 3. 场景三阶段调用

`海中鱼巣/业务/应用服务.场景成员概念类.ixx` 的调用固定为：

| 场景阶段 | 唯一 Fapp 入口 | 副作用边界 |
| --- | --- | --- |
| 初次处理 | `处理类型观察(原请求.观察)` | 允许 Fapp 按其合同推进内部观察、概念、命中和名称流程 |
| `特征应用` 续行 | `收敛类型观察(原请求.观察)` | 只由 Fapp 收敛自己的 pending |
| `存在采用` 续行 | `读取已发布类型观察(原请求.观察, 当前G)` | 纯读；再用读回 F 逐字段互证已保存采用原请求 |
| `最终读回` 续行 | `读取已发布类型观察(原请求.观察, 当前G)` | 纯读；若要求采用，只读取当前采用事实，不重造写请求 |

场景删除自己拼装的“类型观察→名称→C”替代实现；它把新入口返回值交给既有 `消费特征结果` / `补全特征`，继续复核单一 F、完整 F/C/名称、域适用和同 G 事实。新入口非成功时保留原场景继续材料和已确认结果，不进入存在采用或最终完成。

场景仍不得直接调用特征数据服务、`收敛特征概念写入` 或五分支概念写入口。`存在采用` 阶段只有只读特征结果成功且 F 等于保存请求中的 F 时才原样调用 `收敛当前采用`；`最终读回` 不生成新采用幂等键。

## 5. 验证

静态验证至少证明：

1. `读取已发布类型观察` 只有一个公开定义，签名、`const`、参数和结果与本设计一致；
2. 函数体调用 `查询准确特征(FT, 准确值)`、同键 `读取类型观察`、名称/C 读取和域判定，并在前后守卫同一 G；
3. 函数体对全部写入口、写入头、pending 和 confirmed 成员零引用，非成功不返回 provider 原请求；
4. 场景初次、特征应用、存在采用、最终读回四种路径分别只调用表中入口；E/最终阶段不调用 `收敛类型观察`，不直接拼装类型观察/名称/C 恢复链；
5. 外部特征值身份与 F 自有复制值事实身份不同但 I64 内容相同的请求，经解引用查询能命中观察 F；内容不同返回幂等冲突；
6. v0.5 全部旧 ABI 零命中、DC/EC、场景、消费者和两配置构建门禁继续通过。

计划验证仍只运行静态检查和隔离 Debug/Release x64 Rebuild，不运行程序、数据库、恢复或业务验收。设计可执行不证明代码或业务闭环完成。
