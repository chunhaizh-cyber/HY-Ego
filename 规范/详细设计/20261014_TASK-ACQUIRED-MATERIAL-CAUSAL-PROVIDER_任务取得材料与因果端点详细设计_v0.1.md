## 1. 目标与已裁决边界

用户目标是补完本能方法，使实际运行形成的因果可以组织这些方法。本叶处理最早的材料承接提供者，不以声明方法头、伪造条件结果对或预置因果代替真实执行。

本轮用户已明确：观察、获取、组包实际取得的材料，保存为对应任务虚拟存在的材料特征，成为后继条件。以下两类为本叶有限范围：服务对象观察材料、完整已确认服务需求信息包。

按本能方法分析顺序明确：

1. 修改对象是执行任务的虚拟存在 `Vt` 的已取得材料特征；现实存在只是读取来源，不因观察而被改变。
2. 修改原因是当前值式返回无法被后继方法及因果端点正式引用。
3. 目的是真实取得的材料拥有正式身份、明确内容和后继可读条件。这个内部治理动作不建立正式需求，不提供服务权限，不确认任务完成。

获取服务对象和主动／被动获取服务需求采用一个动作：在读取／组包前登记指向本次 `Vt/F` 的内部治理动作；任务 owner 采用返回材料形成该内部结果。不得另造一个“采用动作”，也不得把原动作写成改变了现实人类存在。设置网页输入和提交网页消息仍是普通方法，不在本叶修改。

## 3. 材料身份及保存内容

### 3.1 共同边界

任务 owner 负责正式材料节点及 Vt 的材料 F；F 的准确值仍按现有非 I64 机制引用 `新_特征值类` 的 U64 材料节点。物理材料内容为空组或恰一个正式材料节点编码；不是任意任务集合，不复用服务任务集合 FT。

材料节点与其引用的 E、FT、FC、特征值材料、理解、确认均建立正式字段引用。U64 数字只承载 F 的物理值，不能代替这些引用保护。任务、执行实例和状态／动态保留材料引用时，材料不得释放；不能在执行返回时销毁后继仍需的材料。

这里保存的是真实取得材料，不是参数场景本体。`方法参数场景`、角色查询缓存、执行租约、线程身份及临时比较结果均不得整体复制进 Vt；执行身份只承担外层来源关系。

“未取得”用空材料值表达；“已取得”必须可以读回完整的具名材料。不能只存 `已取得=true`，不能用 0／假编码表示未知服务对象。

内容同一性与来源分账：动作 X、执行实例、观察时间、会话标识、消息序号不进入内容同一键。来源是定位与复核材料，不能使同一服务对象同一事实的重读变为新业务内容。精确内容去重必须逐字段比较正式内容，不以哈希碰撞或包 ID 判定同义。

### 3.2 服务对象观察材料

保存实际 E、人类概念、当时专属存在概念、全特征匹配的正式结果以及本次确实使用的特征材料。每项至少包含 F、FT、所采用 FC、当前准确值／无准确值状态、参与比较的实例区间及对应概念定义读取材料。不能默认复制 `新特征信息` 中全部历史命中和聚合统计。

应保留“不符合”和“材料不足”的真实观察结果，但这两者不能满足“已取得符合人类概念的服务对象”条件。人类概念空定义按现行全特征匹配合同是无约束，不能自行增加姓名、性别或物种的必需性。

会话／消息位置放在本次执行的来源关系中；该材料不等于已授权服务关系。保存事实不新增人类归属标签，不伪造服务对象确认。

### 3.3 服务需求信息包

保存现有 `新服务需求信息包` 的正式内容：来源人类 E、目标 E、完整 `新需求目标定义`、四项理解分项引用、确认引用。正式确认的固定语义仍由原 owner 持有，任务材料不能建立第二份可变确认权威。

语义去重须复用 `比较服务要求确认固定语义()`，并检查来源人类和目标 E 等字段；不同会话、理解或确认身份但同固定目标含义，可以复用同一内容材料，另保留本次来源引用。确认变动需要重新确认时，不删除既有已取得事实，但不得当作当前有效的完整确认条件。

## 5. 一次真实执行及结果采用

```text
筹办选择方法，核验声明材料和结果读取渠道
→ 为执行任务定位／准备材料 F，冻结 X、Vt/F 和发生场景
→ 参数场景最终复核；条件不具备则零动作，返回筹办
→ 方法记录唯一内部治理动作
→ 真实读取／组包，返回本次值式材料
→ task owner 核验 X、动作、目标和来源后采用正式材料
→ F 真变化时建立 S，并有合法前状态时建立原子 D
→ 组织到同一发生场景，D 显式关联该动作“导致变化”
→ 以正式材料／S/D 读回形成结果；任务独立复核
→ 交付因果形成器；后继按当前材料 F 与语义域检查条件
```

这里“导致变化”只指本动作导致 Vt 取得的材料发生变化，不指观察导致现实 E 改变。读取现实状态的既有 `观察取得` 关联仍保持独立。

同一内容重读不改 F、不造变化 D；本次动作和来源仍可存在。初始化 F 的空值是尚无取得材料的真实内部状态，不是虚构现实事实。初始 S 只能在正式空值成立后建立，不能补造比动作更早的时间。

首次声明只登记方法头、Vm 参数规格及结果目标，不登记长期 C/R。真实结果、学习及方法 owner 的现有发布边界继续有效。

## 6. 并发、可见性、寿命与故障

同一任务只能有一个有效执行；材料采用以 `(任务, X, 输出材料F)` 去重。同 X 同内容重入只读回；同 X 异内容属于工程错误。不同任务允许并行，不共享可变参数场景。

底层未提供跨 task／feature／state／dynamic／scene 全链原子接口，不能声称上述流程整链原子。每个正式对象必须完整发布；F、S、D、场景组织及动作关联是有顺序的不同事实。任务最终“结果已取得”不能在必需材料尚未完整可读时发布。

外部 owner 回调在本 owner 锁外；进入写锁后重读必要本地身份。禁止 task 持锁调用 dynamic，而 dynamic 再持锁回调 task；因果 owner 也不能持自己的锁通过场景回调 task。参数视图的读取 owner 由既有运行服务寿命保障，停止时先禁止新执行、等待调用结束、解除回调，再销毁 owner。

工程读取失败、引用异义、后置发布失败进入日志／弹窗／终止链，不返回“不属于人类”“没有服务要求”或伪空包。动作后失败保留已发生动作及可确认正式事实，不自动重复动作。恢复时只允许依据该 X 现有完整事实补派生组织；不得重读现实并冒充原次结果。

材料不可变内容由正式引用保护。删除 task／X 前先依现有引用减法处理材料、状态、动态和场景持有；尚有方法、因果、学习材料引用时保留。不得无引用校验递归删除材料树。本叶不实施全仓旧材料迁移或物理清理。

## 7. 因果交付与可声明边界

本叶需要“完成发生交付”而非 `添加状态()` 即通知：必须在结果 S、可选 D、显式动作关联和场景组织具备后交付。来源方提供同一真实发生身份；状态、动态、动作路径不能为同一次发生各造一次统计。

因果形成器仍复用同一场景、同类 B、两次之间完整前置材料集合求交集、至少两次独立发生、一个条件组对应一个结果以及已知／未知动作分账。第一例只是材料，不强行生成 Q；同一个果的不同成因可形成不同 Q。存在多场景材料时只接受已正式组织的共同上层场景，不隐式创建虚拟世界。

后继使用原始正式材料中的实际 E、FT、目标、确认含义等，不把“前方法执行成功”当后方法所有条件成立。反向链返回所有必要前提和未覆盖端点；不会自动跳过结果获取、安全或权限判断。

完成本提供者只能声明“有正式材料端点及被动交付能力”。尚无至少两次独立合格发生时，不保证已有具体 Q；没有多条适合抽象的具体 Q 时，不保证已有概念 Q；未经运行证据不能宣称本能方法自动编排闭环。

## 8. 必须闭合的精确设计与共享资源

### D1：未知具体材料身份的后继条件表示

现有精确材料域只能表示已知材料编码。它不能表达“任意符合人类概念的服务对象观察材料”或“任意完整当前有效的已确认服务需求包”。`全材料域`包含空材料，不能冒充已经取得；虚构材料 ID 也不可用。

有限两类业务语义已明确，下一步冻结一个封闭的任务材料域家族，严格限制两种业务形态：

- 服务对象观察域：要求内容种类匹配、存在与全特征匹配材料完整，实际 E 满足给定存在概念；可以附加具体 E 约束。
- 已确认需求包域：要求内容完整、来源与目标正式、确认固定语义当前有效；可以附加已有确认的固定语义约束。

它不是任意谓词 DSL，不增加“名字等于字符串”类临时条件。具体值仍是正式完整材料。现有 `特征概念值域` 没有该语义域；拟增加具名分支及只读 owner 比较入口。尚需完成 FC 持久字段、域包含／交集、反向查询比较和子需求目标生产的精确 API 与物理合同。存储表示属于本范围的设计工作，不再作为用户未决业务问题。

独立代码复核补充：上述有限两类内容匹配可依据现有语义设计，不必因“尚无具体材料 ID”再次请求用户决定；未闭合的是精确的公开 ABI、全量消费者与生命周期，而非业务含义。必须区分外层“可接受哪些材料包”的集合域和包内“服务要求想要达到的特征值域”。包内目标值域包含不自动推出两个服务要求同义；固定语义等价继续使用原服务要求 owner。

语义条件至少应有以下机械规则：

1. 空材料不满足任何“已取得”内容域；已取得但缺字段的材料不满足完整包域。
2. 服务对象条件逐项核对实际 E、必需 FT 和概念值域，复用全特征匹配，不以历史归属链或 `属于人类` 单个 bool 取代完整核对。
3. 服务需求包条件核对四项同源、各项值与确认固定内容一致、确认有效。只有来源、目标以及需求目标含义一致才满足指定需求语义；并不要求来源会话或包编码相同。
4. 域对域比较计算外层约束的包含。来源／目标不受限与指定身份、任意有效确认与指定固定语义必须区分；仅已知身份集合相同不是内容域比较。
5. 包中工程读取失败不是“不满足”；材料尚未取得、字段不足、当前确认需重做才是可筹办的业务条件缺口。

方法参数能读取并不等于需求可以表达该目标。现行需求 owner 以普通存在核验目标宿主；本叶若声称“材料不足可生成子需求并筹办”，必须同步冻结具名 Vt 目标引用、引用保护以及需求复核／查重／任务承接的全部消费点。该门不闭合时，只能声明材料持有和读回，不能声明子需求闭合。

### D2：历史材料与当前概念语义的精确快照合同

服务需求包已有固定确认语义提供者，可以复用。服务对象 DTO 当前只保存特征快照和匹配枚举，没有完整的概念定义快照。历史材料保留当时参与比较的正式定义内容，当前条件 fresh 复核，二者分账。这一语义可依据现行边界确定，不要求用户再裁决；剩余是逐字段投影、不可变内容的引用／直接值存储和当前匹配函数的完整 API。不能仅保存 bool，也不能让后续概念修订静默重解释旧 Q。
