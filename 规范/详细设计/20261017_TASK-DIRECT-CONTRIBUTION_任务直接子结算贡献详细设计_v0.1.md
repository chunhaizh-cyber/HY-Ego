# TASK-DIRECT-CONTRIBUTION 任务直接子结算贡献详细设计

日期：2026-10-17；版本：v0.1；代码起点：`962243f4d6d56c804ae1944a6c50902fb6a8f5be`。

本文件解释6190§3.2—3.3的首个生产代码切片，不修改正式规范。最终服务值更新、预置被动因果、因果辅助任务筹办不在本切片；不能把本切片完成写成最终服务值闭环完成。

## 1. 对象、原因与结果

修改对象为任务内部治理结算材料，不修改现实存在，不增加服务值。目的为使每个已完成任务能够按正式需求父子关系，只向直接父任务交付一次合法贡献，防止父任务过早封口、漏计和重复计值。

正式依据：0050§1.3、3100§3.1、3200、5260§12及6190§3。现有完成结算保存T/D/X/A及结果状态引用；`结算已完成任务`未枚举直子需求，`查询服务任务`仅按根筛选，不能判断服务叶子。self现于发布完成决议后建立完成结算，再确认manager释放工作定位。最终服务值路径仍冻结加1，不能消费新Q记录。

## 2. 范围与唯一事实

沿用一个D最多一个T、一个T最多一个完成结算节点。不建立任务轮次、第二完成账或新的父子任务树。

直接父任务唯一由D的父D和D-T映射获取。接收事实属于父T；完成结算属于子T；二者不是服务值消费事实。最终服务值消费属于后续独立owner合同。

### 2.2 父任务接收

`新任务直接子结算接收信息`字段为`节点、父任务节点、子任务节点、来源完成结算节点、贡献值`。父T持有重复字段`直接子结算接收`及一个非负I64`已接收服务贡献`。它是已接收直子贡献的内部小计，不是自我服务值。初始化无接收时字段缺省解释为小计0；首次接收同次建立字段，之后替换该字段。

接收主键为来源完成结算节点，且同一子T不得对应两个接收。接收节点、父T接收引用、父T新小计、来源完成结算的唯一接收引用在一个`基础数据集::原子追加节点组`中发布。采用完整联合快照保护父T、子T、来源结算、双方D及需求父链关系端点；重复只读回原记录，不重加。小计必须等于当前接收记录Q受检求和，任何不一致为工程错误。子结算不因接收改变任务状态9为12，后者仍属于最终消费收尾。

本条为执行期具名并发缺口修订，不新增接口或任务生命周期规则。状态核验必须位于任何状态引用预留、完成结算创建和父接收写入之前；返回预期变化时保持已有正式结算、X/A和接收事实不变。self/manager沿既有预期变化分支fresh重读或等待下一正式进度，不继续使用旧完成定位、不忙重试、不把合法重启升级为工程终止。

`建立任务完成结算(T,X,A)`保留签名，在既有完成资格检查后调用共享私有贡献准备逻辑；已有`新任务操作状态`追加`等待直接子结算、等待目标分类、历史结算缺贡献`，不得挤入资源失败。旧调用者在本切片全部迁移；新的推进入口不绕过原X/A核验。

`读取任务完成结算`/`获取完成结算`严格解码可选贡献组；有组时必须完整、非负、分类与值一致，直子接收引用完整。空组仅表示旧记录；半组是工程损坏。新增接收节点读取保持task owner私有，外部只消费返回定位。

### 3.1 只读交接投影（执行侧具名退回修订）

manager确认入口需要独立核验接收，但不能调用会写的`推进任务完成贡献`代替只读，也不能解析task私有接收字段。因此在`新_任务类.h/.cpp`增加唯一公开只读入口：

```cpp
enum class 新任务贡献交接读取状态 : std::uint8_t {
    已读取 = 1, 任务不存在, 预期已变化, 工程故障
};
struct 新任务贡献交接投影 final {
    稳定编码 任务节点, 需求节点;
    std::optional<稳定编码> 完成结算节点;
    std::optional<std::int64_t> 服务贡献值;
    std::optional<稳定编码> 直接父需求节点, 直接父任务节点;
    std::optional<稳定编码> 直接父完成结算节点;
    std::optional<稳定编码> 接收节点;
};
struct 新任务贡献交接读取结果 final {
    新任务贡献交接读取状态 状态 = 新任务贡献交接读取状态::工程故障;
    std::optional<新任务贡献交接投影> 交接;
};
新任务贡献交接读取结果 读取任务完成贡献交接(
    稳定编码 任务节点) const noexcept;
```

`已读取`只表示完整读回，不表示任务完成或可以计值。根无父D时两个父定位及父结算/接收均空；有父D尚无父T时仅父D非空；本T尚未完成结算时完成身份/Q/接收均空；旧结算有身份但Q空，不能解读为0；父T已封口可有父完成身份而无本来源接收。

接收非空仅在task私有解码已独立核验接收的父T、子T、来源完成身份、Q及双方反向引用全部相符后返回，故外部不需要接收字段访问权。任何半结构或多义映射为工程故障，不返回部分投影。使用本类锁及正式完整D-T读取，获取本T/D、父D/T、完成/接收的联合节点快照并再次经owner读回身份；前后语义或快照不一致返回`预期已变化`且无载荷，由caller重新读取。无任务须由正式节点不存在结果确认，不能把读取异常变成`任务不存在`。不写Q、不创建接收、不改缓存事实，不发送消息。

manager允许调用本入口核对来源及父接收；self可用作只读恢复定位。内部单个接收记录解码仍私有。`确认任务贡献复核`必须比较此投影与请求结果中的T、完成身份、父T和接收身份；若预期已变化保留复核待办且不释放工作缓存，不以调用写入口消除差异。

## 4. 完成结算准备算法

1. 通过`读取需求列表任务对应()`读取完整有状态D-T对应集合，依D父指针提取本T全部直接子D；不以吞错的`查询直接子需求().empty()`判叶。
2. 无直接子D才判断叶子。非服务根链叶子Q=0；服务根链内按第5节判治理叶子0或外部服务叶子1。安全链不得借外部目标得到服务贡献。
3. 有直接子D：缺T、未完成非失败/取消、已完成但无完成结算、缺贡献、尚未被本T正式接收，均为待归集，不能按0封口。失败/取消子T不贡献；本T自身仍须满足完成资格。对于已结算12子T，要求存在同一完整完成结算和接收，不再累计。
4. 新入口可为一个已完成子T建立其合法完成结算并接收至父T；父T复核仅使用已经正式存在的子完成结算，不在一次调用内递归完成整棵树。
5. 归集完整时Q为本T直接接收Q之和，冻结接收节点引用组；新完成结算、完整Q及T→完成结算引用同次原子追加。保护本T、D、全部直接子D/T/接收及结果闭包端点完整快照；子链在检查后变化则零发布，返回预期已变化并重新完整读取。

   语义枚举必须与提交快照互证，采用不读取需求私有字段的固定顺序：首次通过需求/task正式入口取得语义全集并计算候选；状态引用预留后捕获完整联合节点快照（包含父D全部入出边）；再次通过相同正式入口完整读取语义集合，逐项要求直接子D全集、D-T映射、子T状态、X/A身份、完成结算和接收来源与候选完全相等，然后提交CAS。快照之前发生的新增由第二次语义读取发现；快照之后发生的新增由CAS挡住。不能先按旧全集算Q，再拿最新快照直接CAS。二次读取不符时撤销本次引用预留并重新完整准备，不发布旧Q。接收交易同样在快照后重读父子身份、旧小计及全部既有接收集合，与实际求和材料逐项相等再提交。业务侧不得绕过需求owner解析私有父子角色字段。
6. 新完成结算无父D时返回无直接父任务；有父D无父T则保持该已发布完成结算，返回等待直接父任务；父T存在则执行§2.2原子接收。
7. 已有完成结算只做身份/冻结引用核验及尚未完成的父接收，不能按现在新出现的子任务重新修改既有Q。本叶不扩展需求owner的完成后新增子需求准入规则；发布前守住完整直子快照，发布后不重算、不撤销、不重开旧完成结算。0050允许同T重新启用，6190禁止的是取得第二次完成结算资格，不是禁止重新启用；本叶不得新增“已有结算一律禁止重启”规则。父Q冻结时失败/取消子贡献未计入，之后该子重新启用不反写父Q，不仅因该合法进度变化报告工程损坏；既有父完成结算仍以原冻结身份复用，未来如需新服务计值资格须由新的正式目标合同另行处理，不能在本叶伪造第二结算。

8. 接收前先检查父T是否已有完成结算。已有同源接收仍精确重复；父已封口但没有此源接收，返回`父完成结算已封口`，零父接收/小计写入，保留子T新完成结算。此为治理非接收，不自动终止工程。manager可释放子T原运行缓存，以来源结算身份保留待裁决材料；当前版本没有重开父Q的授权，也不自动反复发送。恢复枚举同样保留该正式来源，只有后续具名裁决能力或新的明确进度事件才重新复核。不得越级交付祖父或直接增加服务值。

状态引用沿用状态owner正式增引用与失败撤销能力，但完成节点字段和T引用由组合发布取代手工逐字段发布；不在本切片重构所有状态引用计数。已知零发布失败可撤销预留引用；原子发布成功后禁止撤销引用。异常后必须先读回T的正式结算，再决定恢复，不根据返回值猜测未写入。该沿用部分不证明跨进程状态引用修复能力。

## 6. 生产self/manager闭合

修改`新_自我线程类.h/.cpp`、`新_任务管理线程类.h/.cpp`现有结果回流：

- self完成决议发布后调用贡献推进。已完成/精确重复/无父根且完整结算可读时，再用原`确认任务完成结算`释放manager运行定位。
- 本T等待直接子结算或分类时，不撤销已完成状态，不将其重新执行，不丢X/A，不报告工程失败。manager运行期去重保存待归集T定位；它不是第二完成事实账。
- 本T结算已经存在但父T尚缺时，可以确认本T结果并释放worker；待交接索引以完成结算身份重建，不需要一直保留worker。
- manager的现有状态扫描新增一次有界执行批次：完整枚举已完成/已结算T，发现无完成结算或有贡献但无父接收者的候选，发self定位消息。消息仍用既有T/X/A定位；不得把Q写入消息作为权威。
- 任务关联建立、子结算接收、子失败/取消以及初始化恢复，标记归集复核待触发；现有循环每次只提交一个去重归集工作，不持manager锁调用task，不占用10个方法执行worker等待。已有扫描可合并，禁止新常驻轮询线程。
- 等待集合只在新进度/初始化恢复或正式分类可用时复核，同一未改变事实不忙轮询；收到既有重复消息允许fresh复核。同一T处理中和在途各至多一份。无消息的恢复通过正式T/结算枚举重建，不依赖进程内集合持久化。

### 6.1 消息与函数冻结

它不携带工作包身份、Q或完成许可，允许恢复后从正式T最近X及X的A重新构造。manager向self公开具名协作类型`贡献反馈接收函数=std::function<新任务结果反馈接收状态(const 新任务贡献反馈定位&)>`，追加到现有`绑定自我筹办反馈`参数，self在现有`绑定任务管理`唯一调用点安装；解除绑定同其它回调一起清理，self先停止/解除再析构。回调存储、扫描、消息排队及确认处理helper仍为manager私有。

self `新自我消息类型`追加`任务完成贡献复核=9`，`新自我治理消息`追加`optional<新任务贡献反馈定位> 完成贡献复核`；消息校验要求只带这一载荷，不伪填`原工作`。接收/去重沿已有邮箱规则，处理私有函数`处理任务完成贡献复核(消息项&)`按T/X/A fresh读取，调用task `推进任务完成贡献`，再调用manager向self公开的具名协作入口`新任务完成结算确认状态 确认任务贡献复核(const 新任务贡献反馈定位&, const 新任务贡献推进结果&) noexcept`；只有manager持有其事实核验与缓存清理权，公开入口不开放可变容器。

manager确认入口独立读task正式结算/接收并比较定位，不信任结果DTO作为事实。完成且父接收已成或根无父，释放原最近执行结果/决议及待归集索引；完成但父T缺失，可释放原工作缓存，保留可由正式完成结算重建的交接待办；父完成结算已封口按§4.8保留来源、零父修改且不忙重试；等待直子/分类保留原X/A定位并移入独立`待完成贡献复核`集合，不能放回`待结果反馈任务`抢占begin。失败/取消子T进度通知不造其完成结算。

原`处理任务结果反馈`首次完成路径遇到归集等待时，调用上述确认入口将定位转移到独立集合，返回新增self处理状态`任务完成贡献待归集`；原结果消息正常出队。manager `提交自我任务后继决议`已将完成项从待结果反馈删除，禁止重新加回该集合等待贡献。

manager新增私有`标记贡献复核待触发()`和`尝试反馈任务完成贡献()`：初始化/绑定反馈成功、承接建立D-T完成、self后继决议已发布(完成/失败/取消)、贡献接收确认成功时调用标记；循环在既有W0扫描阶段处理标记。一次触发以当前完整T集合生成待复核定位有序队列，每个定位本批最多发送一次；邮箱满保留队首并按现有资源重试间隔重试；已接收移至在途、确认后释放；等待项不自行重新置触发。同一批次按游标前进，不能每次选最小编号。新进度合并为下一批，避免父等待阻断子结果回流。恢复时无运行缓存仍从T/X/A构造；缺X/A而状态已完成是工程不一致，不伪填定位。

## 7. 最终+1旧路径隔离

新Q完成结算不能进入旧固定+1路径，包括Q=0和Q=1；Q=1也缺原子来源消费，不证明旧算法安全。

task的`核验直接服务结算来源`、`接纳服务结算来源`、`准备服务结算筹办`及执行前本能输入复核须识别新Q记录并返回专门的`最终贡献消费尚未装配`治理等待，不转换成工程故障、不制造子需求；manager入队、已有来源绑定恢复与自动扫描均保留来源完成结算定位而不安排旧结算执行。self`接纳明确完成来源`仅将其标为待最终消费，不能因此阻止正常子完成结算确认。

具体枚举：`新直接服务结算来源状态`及`新任务操作状态`各追加`最终贡献消费尚未装配`；`新任务本能输入复核状态`追加同名项，W3执行入口按已有条件已变化的零动作回筹办/等待路径处理，但不可将其变为条件子需求。`服务值结算.本能合同.h`中的`新服务值结算协作状态`追加同名项；manager来源接收/排空及self`接纳明确完成来源`把它视为已知治理等待，保留候选，既不报工程失败也不安排worker。相关switch必须显式消费，不落default失败。历史无Q记录保留既有读取/行为，不升级为新Q合法贡献，不声称修复旧最终消费。

服务值本能运行服务的`建立普通动作`入口增加最后硬门：读取来源T正式完成结算，新Q来源若穿透到旧`加一`调用链，在创建动作之前报告工程错误并终止受影响操作，零动作、零服务值写入；不能等到`更新普通结果`才拦截。最终人类资格、Q上界、原子消费、状态/动态收尾在后续特征owner提供者完成前不开放。

## 8. 非成功、并发、恢复与生命周期

业务等待不含工程异常。缺合法进度为等待；完整查询失败、基数冲突、来源异义、负Q/溢出、旧记录半字段、错误父子关系为工程故障，按现行日志/弹窗/终止链，不当作无子/零贡献。预期不符只重读同一事实范围，不换新来源重加。

完成结算、接收和来源引用生命周期与所属T一致；本切片不删除历史T、不增加撤销完成结算功能、不物理迁移旧记录。已发布接收不允许被单独删除使小计不一致。已封口父结算禁止补计迟到新来源；合法失败/取消子后续重新启用产生的新完成按§4.8治理非接收，不冒充工程损坏。若证据证明冻结时本应计入且漏掉，则仍属归集算法工程错误，不能用治理等待掩盖。
