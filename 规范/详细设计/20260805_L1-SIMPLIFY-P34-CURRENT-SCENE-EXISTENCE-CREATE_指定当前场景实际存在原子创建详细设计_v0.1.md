## 1. 目标与完成边界

本叶建立一个具名的场景侧原子发布者，在指定正式世界根内的任意当前可达场景，以一个 L1 v2 写集共同发布：

```text
新实际存在普通节点
+ 资格 I64 值1（所属新存在、类型=P7资格类型、来源=P7服务身份）
+ 新存在资格属性槽
+ 目标当前场景 -> 新存在 的直接成员关系（P33关系类型、顺序0）
```

真实首次顺序固定为：

```text
公开请求意图摘要
-> P15 provider 前幂等探测
-> 仅未找到时依次取得 P7 存在写入规格、P33 当前场景接纳规格
-> 共同截止与两域见证互证
-> 执行证据摘要 + 唯一非空通用读回计划
-> 单次 L1 v2 提交
-> L1 独占许可内四项权威读回
-> 发布者映射实际存在结果
```

同义已发布必须在 provider 调用前机械返回首次完整结果；异义冲突、隔离或内部不一致不调用 provider、不提交。首次成功只推进一个事实代次。发布后读回矛盾保留已发布代次和幂等账，由 L1 写失败见证并隔离；本服务不得补写、回滚、重取普通快照或第二次提交。

本叶不扩写现有 P7 `L1实际存在场景组合服务`。4015 §5、4030 §3 禁止组合服务直连 L1，4200 §3.7 又规定直接成员边的唯一写入方为场景业务侧。因此新类身份固定为领域原子发布者，不是第二组合器；未来 `世界树业务服务` 写门面只能透明委托本发布者。

本叶不发布初始特征，不写状态、动态、因果、任务或结算，不设计移动/移除、恢复装配、生产线程接线、P32 写门面、旧 P7 入口删除、集成验收或 STEP-5。

```text
海中鱼巣/领域/自检.L1当前场景实际存在发布.ixx
```

类身份固定为：

```cpp
class L1当前场景实际存在发布服务 final;
```

它属于场景直接成员关系的领域发布边界，只保存 `L1事实基座服务&`、`L1实际存在服务&`、`L1场景结构服务&` 三个非拥有引用。它消费 P7/P33 不可变规格并形成一个中性 L1 写集，不保存幂等缓存、仓库、锁、事务、许可或首次结果副本。

依赖方向固定为：

```text
后继世界树业务服务写门面
-> L1当前场景实际存在发布服务::在当前场景创建实际存在

   -> L1实际存在服务::形成实际存在写入规格（P7）

```

P7/P33/L1 不反向依赖本发布者。现有 P7 初始场景组合器不调用本发布者，本叶也不迁移或删除它。

## 4. 公开 DTO、函数与稳定身份

在 `L1实际存在.数据.h` 追加：

```cpp
inline constexpr std::uint32_t 当前场景实际存在创建合同版本 = 1;
inline constexpr std::uint32_t 当前场景实际存在创建规则版本 = 1;

struct 当前场景实际存在创建请求 final {
    std::uint32_t 合同版本 = 当前场景实际存在创建合同版本;
    std::uint32_t 世界规则版本 = 世界登记规则版本;
    std::uint32_t 创建规则版本 = 当前场景实际存在创建规则版本;
    世界结构节点身份见证 指定世界根;
    世界结构节点身份见证 目标当前场景;
    实际存在操作幂等身份 幂等身份;
    std::uint64_t 期望事实代次 = 0;
    friend bool operator==(const 当前场景实际存在创建请求&,
        const 当前场景实际存在创建请求&) = default;
};
```

返回复用 P7 的 `实际存在结果/实际存在事实/实际存在状态`，不建立第二结果枚举或临时结果 DTO。成功事实仍携带世界根、存在、当前场景、资格、当前场景归属关系和同一非零事实截止代次。

公开函数固定为：

```cpp
实际存在结果 L1当前场景实际存在发布服务::在当前场景创建实际存在(
    const 当前场景实际存在创建请求& 请求);
```

构造函数固定三引用且 `noexcept`；服务不可复制、不可移动、不可默认构造。公开函数不标 `noexcept`，捕获 `std::bad_alloc` 为 `资源失败`，其它未分类异常为 `内部不一致`。所有非成功结果业务载荷为空。

L1 私有幂等键继续使用 P7 创建域：

```text
高8位 = 0x0B
低56位 = 实际存在操作幂等身份.值
```

不得新增第二创建域，否则同一公开身份可从旧 P7 与 P34 各发布一个存在。P34 摘要操作标签固定为 `U32 0x5033'3401`；激活 S0 必须确认 P15 真实迁移后的全部领域操作标签中无重复。旧 P7 与 P34 使用同一幂等键但公开意图不同，跨入口同键应为异义冲突，绝不能在两个域分别成功。

## 5. 请求意图摘要与 provider 前探测

### 5.1 入口校验

任何 provider/L1 调用前校验：三个版本精确匹配；根和目标均为非零普通节点见证；幂等身份在 `1..0x00FF'FFFF'FFFF'FFFF`；期望事实代次非零。失败返回 `入口拒绝`，探测/P7/P33/提交调用均为0。

### 5.2 请求意图编码

严格按 P15 编码规则形成标准 SHA-256 原始32字节：

```text
ASCII HZY-L1ID
+ U32编码格式版本1
+ U32操作标签0x50333401
+ U32合同版本
+ U32世界规则版本
+ U32创建规则版本
+ 指定世界根（稳定编码U64 + 节点种类稳定宽度和值）
+ 目标当前场景（同形）
+ 幂等身份U64
+ 期望事实代次U64
```

全部整数网络字节序，不编码地址、padding、显示名、容器顺序、provider 结果或本地键。摘要全零为内部不一致且不探测。

### 5.3 探测分支

用 `0x0B` 幂等键和请求意图摘要调用 `L1事实基座服务::探测幂等` 恰1次：

| 探测状态 | P34结果 | 后继调用 |
| --- | --- | --- |
| `未找到` | 继续首次形成 | P7/P33各最多1次，提交最多1次 |
| `同义已发布` 且首次副本完整 | 机械映射 `幂等读回` | provider 0、提交0 |
| `异义冲突` | `幂等冲突` | provider 0、提交0 |
| `入口拒绝` | `入口拒绝` | provider 0、提交0 |
| `已隔离` | `许可拒绝` | provider 0、提交0；不把携带的首次副本升级成功 |
| `内部不一致`、坏成功或未知值 | `内部不一致` | provider 0、提交0 |

同义机械映射必须验证首次发布代次、三个本地键映射、四项读回、确定性结果摘要和失败见证/当前隔离形状满足 P15；任何矛盾为 `内部不一致`，不得重调 provider 修补。

## 6. 两份规格、共同截止与执行证据

只在探测 `未找到` 后按固定顺序调用：

1. `L1实际存在服务::形成实际存在写入规格({L1实际存在合同版本, L1实际存在规则版本, 请求.期望事实代次})`；
2. `L1场景结构服务::形成当前场景接纳规格({L1场景结构合同版本, 请求.世界规则版本, 当前场景接纳规格规则版本, 请求.指定世界根, 请求.目标当前场景, 请求.期望事实代次})`。

两者非成功按同名业务状态映射；P33 `许可拒绝` 立即返回。P7/P33 坏成功、空规格、版本/类型/字段矛盾为 `内部不一致`。任一规格截止与请求代次不等，或两截止不等，返回 `版本漂移`。不得重取规格或快照。

执行证据摘要固定编码：请求意图摘要、P7合同/规则版本、P33场景合同/世界/规格规则版本、共同截止、P7服务身份/资格类型/资格值、P33根/目标/成员关系类型、规范化写集全部字段及规范化通用读回计划。固定顺序本身即规范顺序，不用显示名、句柄、时间戳或容器迭代顺序。摘要全零为内部不一致，零提交。

## 7. 唯一写集与通用发布后读回计划

L1 v2 写集固定为：

| 本地键/项 | 精确内容 |
| --- | --- |
| 节点1 | 新普通节点，实际存在身份 |
| 值2 | 所属=本地1；属性类型=P7资格属性类型；材料=I64 `1`；来源=P7服务身份 |
| 关系3 | 源=P33目标当前场景；目标=本地1；类型=P33直接成员关系类型；顺序=0 |
| 属性设置 | 本地1 + P7资格属性类型 -> 本地2 |

无退出事实、无其它节点/关系/值/槽、无调用方指定稳定编码。写集期望代次等于共同截止，幂等键为 `0x0B` 域，两摘要和计划非空。只调用 L1 v2 `提交写集` 一次。

通用发布后读回计划精确四项且按 `节点、关系、值、属性槽` 的 P15 规范顺序：

1. 本地1节点，当前，本次发布代次；
2. 本地3关系，当前，本次发布代次；
3. 本地2值，当前，本次发布代次；
4. 本地1节点 + P7资格类型的属性槽，当前，期望目标本地2，本次发布代次。

计划不得为空、缺项、重复或夹带既有世界根/场景/类型/来源读取。首次执行时两份 provider 规格已经在共同截止互证既有见证；同义重试只复用首次结果。

## 8. L1结果与领域结果映射

`成功` 映射 `已提交`；竞态 `精确重复` 映射 `幂等读回` 并使用 L1 返回的首次完整结果；`幂等冲突/事实代次漂移/资源失败/内部不一致` 分别同名映射。入口拒绝或未知状态不得降级成功。发布后内部不一致即使携带非零已发布代次、映射和失败见证，P34 仍返回 `内部不一致` 空业务载荷，不二次读取或补写。

成功/幂等读回必须机械验证：

- 首次映射恰含本地键1、2、3，三个稳定编码非零互异；
- 四项通用读回恰好完整且均为同一非零发布代次；
- 节点1是当前普通节点；
- 值2所属节点1、属性类型=P7资格类型、I64材料=1、来源=P7服务身份；
- 关系3方向为 `P33目标场景 -> 节点1`、类型=P33成员关系类型、顺序0；
- 属性槽精确为 `节点1 + P7资格类型 -> 值2`；
- 生命周期创建代次、当前发布代次与 L1 首次发布代次符合 P15/4015；
- 世界根/目标场景精确来自公开请求，不能从回显或显示名推断。

据此形成 `实际存在事实`：世界根=请求根，当前场景=请求目标，存在=节点1，资格=值2，当前场景归属关系=关系3，事实截止代次=L1首次发布代次。`实际存在事实完整` 必须成立。

## 9. 并发、异常与生命周期

服务不自建互斥量或 `已提交_` 账。并发由 P15 探测加 L1 独占提交最终裁决：同键同义至多一次发布，竞争者得到同一首次结果；同键异义至多一个发布，其余冲突；不同键共享同一事实代次基线时至多一个先提交，后继按代次漂移返回，不隐式改写请求代次或重试。

provider 调用发生在 L1 独占许可之前，服务不持锁跨调用。请求、规格、摘要、写集、计划和读回均为调用栈/调用方拥有的值；服务只保存三个依赖引用。依赖宿主寿命必须覆盖服务及同步调用。本叶不设计生产装配。
