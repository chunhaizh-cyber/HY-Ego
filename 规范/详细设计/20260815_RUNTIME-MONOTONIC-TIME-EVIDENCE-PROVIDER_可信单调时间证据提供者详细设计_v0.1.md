# 可信单调时间证据提供者详细设计 v0.1

日期：2026-08-15

计划身份：`RUNTIME-MONOTONIC-TIME-EVIDENCE-PROVIDER`

当前状态：BIZ 详细设计候选；未登记计划索引，未实施代码，未构建，未接入普通应用或治理批次。

## 1. 目标与完成边界

实现 `BIZ-L4-002-01-02-01`：新建一个普通应用运行纪元内唯一持有 `std::chrono::steady_clock` 起点的适配器，按请求绑定的运行代次、时间纪元身份和固定时间源版本，返回从该起点经过的非负 `I64` 纳秒证据。

本叶只建立平台时间读取提供者，不计算完整秒、不推进时间游标、不创建运行代次或纪元身份、不读取墙钟、DATA、缓存或日志。完成只证明 L4 提供者；L3 完整秒边界、L2 治理批次、普通应用持有、自我线程和服务值 / 安全值维护保持 `NOT_RUN`。

## 2. 当前事实与裁决

正式基线 `4b6902ea085f1d455a47bb904d974deb5b1a7318` 中：

- 6170 规定完整秒只能来自同一运行代次和时间纪元内的单调物理时间，循环、等待、消息和墙钟不得参与。
- `BIZ-L3-002-01-02`需要一个可信单调时间证据提供者；当前生产代码没有该公开能力。
- `采集器.D455相机.ixx`中的局部 `steady_clock::now()`只服务 D455 采样，不绑定治理运行纪元，不能提升为共享时间权威。
- 旧 L4 图的物理路径与映射冲突，且请求中的读取序号没有签发者也不参与父级语义。

裁决固定为：

1. 唯一文件 `海中鱼巣/适配/适配器.单调时钟.ixx`，模块 `海中鱼巣.适配.适配器.单调时钟`。
2. 后继普通应用装配提供非零运行代次和时间纪元身份；适配器不签发、不递增、不持久化这两个身份。
3. 适配器构造时读取一次 `steady_clock::now()`并唯一持有本实例纪元起点；模块固定时间源版本 1。
4. 删除读取序号。调用返回本身已经绑定请求；调用方序号不是时间证据，适配器内部原子序号也不应改变 const 并发语义。

## 3. DTO 与公开函数

```cpp
inline constexpr std::uint32_t 单调时间证据合同版本 = 1;
inline constexpr std::uint32_t 稳态时钟时间源版本 = 1;

struct 单调时钟适配器配置 final {
    std::uint64_t 运行代次 = 0;
    std::uint64_t 时间纪元身份 = 0;
};

struct 单调时间证据读取请求 final {
    std::uint32_t 合同版本 = 单调时间证据合同版本;
    std::uint64_t 运行代次 = 0;
    std::uint64_t 时间纪元身份 = 0;
    std::uint32_t 期望时间源版本 = 稳态时钟时间源版本;
};

enum class 单调时间证据读取状态 : std::uint8_t {
    已读取 = 1,
    请求拒绝 = 2,
    纪元错配 = 3,
    时间源版本漂移 = 4,
    计数不可表示 = 5,
    内部不一致 = 6
};

struct 可信单调时间证据 final {
    std::uint32_t 合同版本 = 单调时间证据合同版本;
    std::uint64_t 运行代次 = 0;
    std::uint64_t 时间纪元身份 = 0;
    std::int64_t 从纪元起点经过纳秒 = 0;
    std::uint32_t 时间源版本 = 稳态时钟时间源版本;
};

struct 单调时间证据读取结果 final {
    单调时间证据读取状态 状态 = 单调时间证据读取状态::请求拒绝;
    std::optional<可信单调时间证据> 证据;
};

class 单调时钟适配器 final {
public:
    explicit 单调时钟适配器(单调时钟适配器配置 配置) noexcept;

    单调时钟适配器(const 单调时钟适配器&) = delete;
    单调时钟适配器& operator=(const 单调时钟适配器&) = delete;
    单调时钟适配器(单调时钟适配器&&) = delete;
    单调时钟适配器& operator=(单调时钟适配器&&) = delete;

    单调时间证据读取结果 读取可信单调时间证据(
        const 单调时间证据读取请求& 请求) const noexcept;
};
```

成功证据中的经过纳秒允许为 0；其它身份和版本必须非零。只有 `已读取`携带 `证据`，其它状态均为空。

## 4. 所有权与生命周期

- 适配器保存值式配置和一个 `steady_clock::time_point`纪元起点；无堆分配、锁、缓存或静态当前值。
- 同一实例的运行代次、时间纪元和起点构成不可换代绑定。需要新代次或新纪元时构造新实例，不修改旧实例。
- 后继普通应用上下文必须唯一拥有一个实例并覆盖全部治理调用；本叶不修改装配代码，也不冻结运行代次 / 纪元身份的上游签发算法。
- 适配器销毁后结果仍为调用方拥有的值式材料；结果不泄漏平台时点、引用或内部配置地址。

## 5. 固定控制流与状态映射

```text
复核适配器配置非零
-> 复核请求合同和非零字段
-> 复核运行代次与时间纪元
-> 复核期望时间源版本
-> 读取一次 steady_clock::now()
-> 受检计算 now - 纪元起点并换算纳秒
-> 构造完整值式证据
```

| 条件 | 状态 | 守恒 |
| --- | --- | --- |
| 请求合同错误或任一请求字段为零 | 请求拒绝 | 不读取平台时钟；证据为空 |
| 适配器配置为零 | 内部不一致 | 本次读取不再调用当前 `now()`；证据为空 |
| 请求运行代次或纪元与适配器不等 | 纪元错配 | 证据为空；不自动换代 |
| 期望时间源版本不是固定版本 1 | 时间源版本漂移 | 证据为空；不降级为其它时钟 |
| 当前时点早于起点 | 内部不一致 | 证据为空；不得钳制为 0 |
| 纳秒差超过 `I64_MAX`或转换无法精确受检完成 | 计数不可表示 | 证据为空；不得回绕 |
| 差值非负且可表示 | 已读取 | 一次构造完整证据 |

全部公开边界 `noexcept`。意外异常统一收口为内部不一致；当前固定类型和值式构造不应分配。

## 6. 并发与时间语义

- `steady_clock`是唯一平台来源；禁止 `system_clock`、文件时间、日志时间、线程 Tick 或调用方当前时间。
- 多线程可以并发 const 读取。适配器没有内部序号和可变状态，因此结果只由各次平台时点决定。
- 连续调用只要求经过纳秒不倒退；允许相等，不把相等解释为错误或“没有一秒”。
- 经过纳秒不是 DATA 事实代次，也不是业务完成或完整秒游标。L3 才负责结合上一完整秒边界计算完整秒区间。
- 跨进程和跨运行代次不得比较原始经过纳秒；恢复连续性证明与新纪元签发不在本叶。

## 8. 验证与完成声明

生产外专项动态覆盖：零运行代次配置、零时间纪元配置均返回内部不一致且证据为空；坏合同 / 零字段请求拒绝；运行代次 / 纪元错配；时间源版本漂移；真实读取成功；连续读取非递减；同配置合法并发请求全部返回已读取、完整值式证据和一致配置回显。源码静态复核：配置错误、请求拒绝和漂移分支先于本次读取的当前 `now()`，每次成功恰一次当前 `now()`，零墙钟 / 睡眠 / 循环序号 / DATA / 日志，以及受检负差和溢出映射。

当前没有生产 fake clock seam；真实时钟倒退、`I64_MAX`溢出和平台 `now()`异常保持 `NOT_RUN`，不得通过导出测试 seam 或伪造 provider 宣称动态覆盖。根工程 Debug / Release、专项双配置、UTF-8 / XML、模块唯一登记和生产零专项痕迹按计划验证。

L3 完整秒、L2 治理批次、普通应用持有、自我线程、恢复连续性和独立集成验收均为 `NOT_RUN`。本设计不证明系统计时或治理闭环完成。
