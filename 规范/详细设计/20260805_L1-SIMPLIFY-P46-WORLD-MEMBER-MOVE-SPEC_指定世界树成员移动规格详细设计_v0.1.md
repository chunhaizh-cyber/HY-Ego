## 2. 目标与完成条件

新增唯一无状态组合函数：

```cpp
世界树成员移动规格结果 形成世界树成员移动规格(
    const L1场景结构服务& 场景结构,
    const L1实际存在服务& 实际存在,
    const 世界树成员移动规格请求& 请求);
```

函数对调用方指定的一份世界根、成员种类、成员、预期旧父、预期旧关系、新父和事实截止执行一次当前事实校准：

```text
P19读取指定根完整当前结构
-> 精确匹配成员、旧父、旧关系和新父
-> 实际存在分支用P21同范围互证资格
-> 子场景分支形成新父到根的唯一父链并拒绝自身/后代
-> 返回调用方拥有的不可变移动规格
```

完成必须同时满足：

- 实际存在移动与非根子场景移动使用一个强类型函数和显式成员种类，不靠节点名称或关系类型猜种类；
- P19恰调用1次；P21只在实际存在分支恰调用1次，子场景分支调用0；
- 所有成功材料来自同一个非零P19事实截止，P21截止必须完全相等；
- 预期旧关系必须是P19当前集合中恰一条完整精确关系，且源端、目标端、关系类型和顺序全部匹配；
- 新父是同根当前场景且不同于旧父；子场景不能是根、不能移入自身或后代；
- 规格携带关系类型、旧关系、同代次实际存在资格（适用时）及新父到根父链，使后继发布者无需重解释场景图；
- 任一非成功返回空规格，不返回部分成功，不重取快照、不取锁、不写事实。

请求不携带移动幂等身份、摘要、L1局部键、稳定编码、写集、读回计划、许可、事务或参与者。`预期旧关系`是调用方对当前边的完整乐观见证，不允许只传关系编码后扫描补全。

完整规格固定要求：版本精确；五个节点见证均有效且类型正确；旧关系完整、源端等于旧父、目标端等于成员、顺序0；新关系类型等于旧关系类型；旧父与新父不同；截止非零。`新父到根父链`按新父向上直到根的语义顺序保存，根作为新父时为空；每条关系必须源端为下一层父、目标端为当前层子，链首目标为新父、链末源端为根。实际存在分支必须有完整资格且其存在、输入成员关系和截止分别等于成员、旧关系和规格截止；子场景分支资格必须为空。

## 5. 固定形成算法

### 5.1 provider前校验

在任何provider调用前校验：

- 三个版本精确，成员种类是两个已知值，期望事实代次非零；
- 根、成员、旧父、新父均是非零普通节点；
- 旧关系见证完整，顺序为0，源端等于旧父、目标端等于成员；
- 旧父与新父不同，成员与新父不同。

任一失败返回`入口拒绝`、空规格和双空诊断，P19/P21调用均为0。这里只校验请求自身闭合，不用关系类型猜成员种类。

### 5.2 P19当前结构

构造`当前世界结构读取请求`并调用`场景结构.读取当前世界结构`恰1次。固定映射：

| P19结果 | P46结果 |
| --- | --- |
| `已读取`且完整 | 继续 |
| `未找到` | `未找到` |
| `许可拒绝` | `许可拒绝`，立即返回 |
| `资源失败` | `资源失败` |
| `内部不一致` | `内部不一致`，原样保留结构缺项 |
| 入口拒绝、写状态、空/坏成功或其它值 | `内部不一致`，诊断空 |

成功事实的版本、根、完整标志、稳定排序、空缺项和非零截止必须符合P19；截止不等于请求期望事实代次返回`版本漂移`，不重试。

随后精确查找：

1. 旧父和新父在当前场景组各恰一项，节点见证完全相等；缺失返回`未找到`，重复或同编码异见证为`内部不一致`。
2. 实际存在分支：成员不得出现在当前场景组；预期旧关系必须在当前直接成员关系组恰一项且逐字段全等。
3. 子场景分支：成员必须在当前场景组恰一项且不得等于指定根；预期旧关系必须在当前直接父子关系组恰一项且逐字段全等。
4. 成员或旧关系已不在当前范围返回`未找到`；成员仍在但当前旧边与请求见证不同返回`版本漂移`；集合重复或矛盾返回`内部不一致`。

P46不从原始L1重新解释关系类型。P19成功合同已经证明当前关系使用正式登记类型、方向、基数和顺序；P46只取精确旧关系的`关系类型`作为新关系类型。

### 5.3 新父到根父链与防环

用P19当前直接父子关系为每个非根场景建立唯一父映射，只允许消费P19已经证明完整的结果。以新父为起点逐级向上直到指定根：

- 根作为新父时父链为空；
- 任一步无父、重复父、不能到根或循环，视为P19坏成功并返回`内部不一致`；
- 输出关系按“新父的直接父关系、其父的直接父关系……直到根”顺序排列，不按稳定编码重排；
- 子场景分支若成员等于新父或出现在该祖先链任一节点，返回`入口拒绝`，证明禁止移入自身或后代；
- 实际存在分支只保留父链作为新父同根见证，不用它解释存在资格。

### 5.4 P21资格与规格形成

实际存在分支用完整P19事实构造P21请求并调用`实际存在.读取当前实际存在资格集合`恰1次。P21的入口拒绝/坏成功映射`内部不一致`；未找到、版本漂移、许可拒绝、资源失败、内部不一致分别同名映射，内部不一致原样保留存在缺项。

P21成功必须完整、空诊断、同根同截止且按冻结规则稳定排序。成员对应资格项必须恰一项，且其存在等于请求成员、输入成员关系见证等于精确旧关系；缺失、重复或矛盾为`内部不一致`。子场景分支P21调用严格为0，资格为空。

全部成立后逐字段形成规格：根、成员、旧父、旧关系和新父来自P19精确见证；新关系类型来自旧关系；资格来自P21（适用时）；父链来自本轮P19；截止来自P19。返回`已形成`、完整规格、双空诊断。

## 6. 状态、异常、并发与生命周期

| 条件 | 状态 | 规格/诊断 | 副作用 |
| --- | --- | --- | --- |
| 请求版本、种类、身份、关系自洽或零截止错误 | `入口拒绝` | 空/双空 | provider调用0 |
| 根、成员、父场景或当前旧边确定缺失 | `未找到` | 空/双空 | 零写入 |
| 请求旧边或截止已变化 | `版本漂移` | 空/双空 | 零重试 |
| 子场景是根或将移入自身/后代 | `入口拒绝` | 空/双空 | 零写入 |
| P19/P21许可竞争 | `许可拒绝` | 空/双空 | 立即返回 |
| P19结构损坏 | `内部不一致` | 空/结构缺项 | 不返回部分规格 |
| P21资格损坏 | `内部不一致` | 空/存在缺项 | 不返回部分规格 |
| 分配失败 | `资源失败` | 空/双空 | 零写入 |
| 其它异常或provider坏成功 | `内部不一致` | 空/双空 | 零写入 |
| 完整移动材料 | `已形成` | 完整规格/双空 | 零写入 |

函数不`noexcept`；捕获`std::bad_alloc`为资源失败，其它异常为内部不一致。P46不取得任何服务锁，不持锁跨provider，不等待、不sleep、不重试。P19/P21分别自行完成非阻塞读取；P21只接受本轮P19纯值事实并校准同截止。

规格由调用方拥有，只对该事实截止有效。后继发布者必须把截止作为唯一L1期望代次；任何随后变化由L1拒绝，禁止用旧规格静默重读或改写请求。P46无缓存、无登记、无幂等账和跨调用状态。

11. 相同请求和相同provider结果重复形成逐字段全等；
12. 全部分支前后L1节点、关系、值、槽、退出、事实代次和幂等账零变化；
13. 静态扫描P15、L1提交、写集、稳定编码分配、SQL、仓库、缓存、锁、日志、时间、旧节点直接场景和世界树门面调用为0；
