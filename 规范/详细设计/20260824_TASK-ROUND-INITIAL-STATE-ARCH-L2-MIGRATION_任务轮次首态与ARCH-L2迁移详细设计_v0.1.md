版本：v0.1
日期：2026-08-24

## 1. 唯一目标与完成边界

把 `需求初次筹办准备提供者::形成唯一任务与初次筹办工作包` 改造成最早合法 ARCH-L4 业务消费者：由一个当前具体需求 D 触发，形成任务 T、任务专属正式存在 E、首个任务轮次 R1、首个筹办轮次 P1，以及 E 上“筹办 / 待初次筹办”无动态首态和迁移到“筹办 / 筹办中”的第一动态，并从各 owner 独立读回完整工作包。

本叶完成时只证明：

```text
D -> E -> T/R1/T→L/T→D/T→E
  -> 全局任务阶段特征定义 / E 的唯一特征实例
  -> 无动态首态（筹办 / 待初次筹办）
  -> P1
  -> 筹办中后态 + 第一动态
  -> 按原准备键恢复并独立读回
```

本叶不形成方法候选、路径、实例方法、执行冻结、现实执行授权、任务实际结果、需求结算、任务轮次收束或后继任务轮次；也不证明崩溃后跨进程恢复。

## 2. 当前事实与复用裁决

1. 唯一正式存在入口是 `L2存在结构服务`；旧私有 `L2通用虚拟存在结构服务` 已退出。
2. 普通应用已经持有存在、特征、状态、动态及 `L2状态动态原子发布服务` 的同实例公开入口。
3. `L2状态结构服务::新增状态` 可以建立无动态首态；`L2状态动态原子发布服务::发布状态动态原子迁移` 要求已有旧态，因此首态必须先由状态 owner 单独建立。
4. 当前融合入口只在 task owner 内建立 T、私有任务虚拟存在、首次准备记录和 P1；它没有独立 R1、正式 `T→D`、正式 `T→E`、ARCH-L2 首态或第一动态。
5. 当前没有全局“任务主阶段 / 业务状态段”特征定义，但 `新增统一特征定义` 已允许“实际阶次 1、无直接来源、无派生规则”，`新增特征实例` 已允许把该定义唯一挂到 E；不需要新增或修改 ARCH-L2 特征 ABI。
6. `L2任务虚拟存在身份` 只能保留为 ARCH-L4 迁移期兼容引用类型。新任务的该字段投影必须与 E 的稳定编码相同，但该相同只由正式 `T→E` 关系和存在公开读回证明；类型之间没有隐式转换，也不允许新建第二存在节点。
7. 当前 `L2治理函数骨架.数据.h` 只有合同版本、治理批次裸整数和待激活请求 DTO，没有可回读的治理函数 / 治理动作强类型身份、唯一 owner、动作定义事实或初次筹办规则版本；`L2方法动作入口身份`只适用于已经登记的方法动作入口，而 P1 前尚无方法。两者都不能作为本次第一状态变化的来源动作。

## 3. 对象、所有权和依赖方向

| 对象 / 事实 | 唯一 owner | 本叶写入 |
| --- | --- | --- |
| E 与存在身份来源 | `L2存在结构服务` | `新增存在节点` |
| T、R1、`T→L`、`T→D`、`T→E`、首次准备记录、P1 | `L2任务结构服务` | 两笔 task-owner 原子提交 |
| 全局任务阶段特征定义 | 特征定义 owner | `新增统一特征定义`，全局固定幂等键 |
| E 的任务阶段特征实例 | 特征实例 owner | `新增特征实例` |
| 无动态首态 | 状态 owner | `新增状态` |
| 初次筹办推进动作定义与本次动作事实 A1 | task owner | 定义在服务登记时幂等建立；A1 与 P1 同次建立 |
| 筹办中后态与第一动态 | 状态 / 动态两个 owner | 既有跨 owner 原子 provider |
| 业务编排与恢复 | `需求初次筹办准备提供者` | 不持有事实，只调用公开面 |

依赖固定为：

```text
需求初次筹办准备提供者
  -> 运行期需求查询组合器
  -> L2存在结构服务
  -> L2任务结构服务
  -> L2特征结构服务
  -> L2状态结构服务
  -> L2状态动态原子发布服务
```

不得直达 L1、借用 owner 私有端口、在 task owner 复制 ARCH-L2 状态 / 动态，或把多个 owner 的结果冒充成一个共同 G1。

将首次准备记录 / P1 从核心建立中拆出，新增：


该 API 在 task owner 一个独立 G_P1 中建立首次准备记录、P1 和初次筹办推进调用事实 A1，并保存对 T、R1、E、阶段特征实例和无动态首态的强类型引用。它不写状态 owner，也不把 G_P1 与 G_T 或 G_S0 写成同代。

旧 `新增任务与首次初次筹办准备记录` 保留为迁移期兼容 ABI 和旧专项编译入口，但生产 provider 不再调用。执行者只能做使旧专项继续编译的机械适配，不能让旧入口重新建立私有存在或成为第二生产路径。

### 4.4 初次筹办推进治理函数与调用事实

本叶可以在原白名单内闭合最小业务侧来源动作：治理函数定义、调用事实、P1 都归 task owner，且只修改现有任务 DTO / 服务和既有 provider。它们共享 owner 不等于同一事实；定义在服务登记时建立，A1 与 P1 是同一 G_P1 内的两个独立节点 / 事实。无需先建立单独提供者计划，也不新增 ARCH-L2 动态 ABI。

```cpp
inline constexpr std::uint32_t L2任务治理函数合同版本 = 1;
inline constexpr std::uint32_t L2初次筹办推进规则版本 = 1;

struct L2任务治理函数身份 final { 稳定编码 值; };
struct L2任务治理动作调用身份 final { 稳定编码 值; };

enum class L2任务治理函数种类 : std::uint8_t {
    初次筹办推进 = 1
};

struct L2任务治理函数定义事实 final {
    L2任务治理函数身份 身份;
    L2任务治理函数种类 种类;
    std::uint32_t 合同版本;
    std::uint32_t 规则版本;
    L2生命周期 生命周期;
};

struct L2任务治理动作调用事实 final {
    L2任务治理动作调用身份 身份;
    L2任务治理函数身份 被调用治理函数;
    L2任务身份 任务;
    L2任务轮次身份 任务轮次;
    L2任务筹办轮次权威记录身份 筹办轮次;
    L2状态身份 触发前态;
    std::uint64_t 来源共同事实截止;
    L2结构幂等身份 调用幂等来源;
    std::uint32_t 函数合同版本;
    std::uint32_t 规则版本;
    L2生命周期 生命周期;
};
```

`初次筹办推进`函数定义由 `L2任务结构服务`在 task owner 服务登记中以固定登记幂等身份建立并正式读回。定义身份来自 owner 发布的稳定编码，不是常量编码、函数名或文本；定义事实的种类 / 合同 / 规则固定为 `初次筹办推进 / 1 / 1`。

A1 与 P1 在同一 task-owner G_P1 中建立，A1 必须引用当前 T、R1、P1、正式读回的待初次筹办首态和函数定义，并保存 G_P1 写前共同截止、P1 建立幂等身份、合同版本 1 和规则版本 1。P1 只是 A1 的筹办轮次端点，不是动作调用身份。`L2新增首次准备记录与P1结果`增加 `std::optional<L2任务治理动作调用事实> 初次筹办推进调用`；按首次准备键和按 A1 身份读取都必须回显并互证上述全部字段。

第一状态变化请求的遗留字段名虽然是 `来源方法稳定编码`，但 4230 正式纯结构合同只把它解释为不透明 `来源稳定编码`；本业务消费者填写 A1 的稳定编码，并在提交前、读回后分别通过 task owner 独立读取 A1，证明它调用实际 `初次筹办推进`定义。不得填写 P1、R1、provider 函数名、日志标签或固定常量。

### 4.5 固定本地键

当前 task owner 已占用的键保持不变；本叶固定使用以下已复核未占用键，不得由执行者临场重编号：

```text
任务来源需求关系类型登记键              0x0301'2114
任务正式存在关系类型登记键              0x0301'2115
R1 / 治理函数定义 / A1 登记键范围        0x0301'2180..0x0301'218E
新任务首条 T→D 写入键                   0x0301'2613
新任务 T→E 写入键                       0x0301'2614
R1 节点 / 族归属 / R1→T / T→R1 / 序号  0x0301'2660..0x0301'2664
A1 节点、6 条关系与调用材料值            0x0301'2680..0x0301'2687
复用任务新增 T→D 写入键                 0x0301'2650
```

`0x0301'2180..218E` 的 15 个登记键固定展开为下列可计数项：R1 族锚点 1 个、R1 族归属关系类型 1 个、R1→T 关系类型 1 个、T→当前 R1 关系类型 1 个、R1 轮次序号属性类型 1 个；初次筹办推进函数定义节点 1 个、函数定义材料属性类型 1 个；A1 族锚点 1 个、A1 关系类型 6 个、A1 调用材料属性类型 1 个，即 `5 + 2 + 8 = 15`。这 15 项分别服务于 G_T 的 R1 写集、服务登记时的函数定义写集和 G_P1 的 A1 写集，不包含运行时事实节点本身。A1 六条关系依次是族归属、被调用函数、T、R1、P1、触发前态；函数定义材料是有序 U64 组 `{函数种类, 函数合同版本, 规则版本}`，调用材料是有序 U64 组 `{来源共同事实截止, 调用幂等来源, 函数合同版本, 规则版本}`。实现必须用 `static_assert` 检查范围、数量和相邻边界。

初次记录、P1 与轮次权威继续复用现有 `0x0301'2602`、`0x0301'2620..2632`、`0x0301'2640..2646`及筹办轮次登记范围；核心建立不再使用私有虚拟存在节点键 `0x0301'2601`。

## 5. 外层请求、工作包与稳定幂等

`需求初次筹办准备合同版本` 升为 2。请求保留外层 `准备幂等身份`，并新增六个非零、逐字段参与精确重复判断的结构幂等身份：

```text
存在建立幂等身份
任务核心建立幂等身份
阶段特征实例建立幂等身份
首态建立幂等身份
P1建立幂等身份
首迁移幂等身份
```

调用方必须持久重放原请求；provider 不在重试时换键、刷新运行代次或替换 D。请求还必须携带并回显 `L2任务治理函数合同版本`和`L2初次筹办推进规则版本`，当前只接受 1 / 1。全局基础特征定义使用固定幂等身份 `0x5441'534B'5354'4147`（ASCII `TASKSTAG`），不从单个任务键派生，也不得每任务重复定义。

`任务初次筹办工作包` 至少增加：E、R1、`T→D`、`T→E`、阶段特征定义、阶段特征实例、无动态首态、P1、A1、筹办中后态、第一动态，以及各段完整 `L2结构结果头`和最终独立读回截止 `G_E/G_T/G_FD/G_FI/G_S0/G_P1/G_M1`。这些 G 表示该段最终确认载荷所用的非零截止，不要求彼此等同，也不要求全局定义精确重复时重新发布；是否发生新写只由结果头的可选变更事实代次表达。完整性守卫必须逐项核对 owner 读回、稳定身份、生命周期、端点、A1 的函数定义、T/R1/P1、触发前态、来源共同事实截止、调用幂等来源、合同 / 规则版本和阶段值；只比较载荷字段不构成成功。

## 6. 任务阶段特征和值合同

全局特征定义固定为基础特征：

```cpp
L2统一特征定义新增请求{
    请求头, 固定幂等身份, 1, {}, std::nullopt
};
```

每个 E 只建立一个该定义的特征实例；宿主必须为 E。首态和后态都绑定这个实例。

精确值材料固定为 `std::vector<std::int64_t>`，位置和值固定为：

| 位置 | 含义 | 值 |
| --- | --- | --- |
| 0 | 任务主阶段 | `筹办 = 1` |
| 1 | 业务状态段 | `待初次筹办 = 1`、`筹办中 = 2` |

因此首态为 `{1, 1}`，后态为 `{1, 2}`。时间材料固定为 `std::vector<std::uint64_t>{运行代次, 阶段序号}`：首态阶段序号 1，后态阶段序号 2；第一动态的起始 / 结束时间分别复用这两份值式材料。首态 `来源稳定编码` 固定为 R1 的稳定编码；第一状态变化请求的遗留字段 `来源方法稳定编码` 固定填写 A1 身份稳定编码。4230 对该字段只作不透明来源编码，ARCH-L2 不解释其业务种类；ARCH-L4 必须通过 task owner 调用事实读回 A1 的函数定义、T/R1/P1、触发前态、来源共同事实截止、调用幂等来源、合同 / 规则版本和生命周期。

首态由 `新增状态` 建立，必须无动态；随后建立 P1；最后 `发布状态动态原子迁移` 以首态为旧当前状态，在状态 / 动态两个 owner 的共同 G_M1 中建立后态、第一动态并退出旧状态当前关系。不得在 P1 前先发布“筹办中”。

## 7. 分阶段算法和恢复

业务四检查点与 owner 提交分账如下：

1. 读原准备键；若已有完整最终记录，按历史各 owner 截止重建并返回精确重复。
2. 在 G0 裁决 D 当前未满足并冻结 D/L 证据。
3. 读取该阶段当前截止，以原存在键调用 `新增存在节点`，取得 / 恢复 E（G_E）。
4. 重新取得不早于 G_E 的 G_T0 并复核 D/L/E；以原任务核心键调用 task owner，建立 / 恢复 T、R1、`T→L/T→D/T→E`（G_T）。
5. 每次写前重新取得当前截止；以全局固定键建立 / 恢复任务阶段特征定义（G_FD），再以任务实例键建立 / 恢复 E 的实例（G_FI）。
6. 在实例已可见的新截止，以首态键建立 / 恢复 `{1,1}` 无动态首态（G_S0）。
7. 在首态已可见的新截止，以 P1 键同次建立 / 恢复首次记录、P1 和 A1（G_P1）。
8. 在 P1 / A1 已可见的新截止，先独立读回 A1，再以首迁移键和 A1 来源编码把首态迁移为 `{1,2}` 并形成第一动态（G_M1）。
9. 分别按存在、task、特征、状态、动态公开读取互证，形成最终工作包。

任一步骤返回成功状态但载荷不完整，或精确重复读回与原请求异义，均按内部不一致 / 幂等冲突收口。写端返回非成功但带非零截止时，只允许用原键、原请求和该 owner 的公开读回收敛发布未知；不得进入下一阶段。已完成的前段事实保留并供同键恢复，不做跨 owner 回滚，也不换键重做。

## 8. 错误与零载荷矩阵

| 条件 | 外层状态 | 后继 |
| --- | --- | --- |
| 版本、零键、键字段缺失或阶段材料非法 | `入口拒绝` | 零写 |
| D 已满足 | `目标已满足` | 零写 |
| L 上已有异义当前任务 | `已有当前任务` 或 `引用冲突` | 不建立第二 T |
| 同键同请求 | `精确重复` | 从各 owner 读回既有工作包 |
| 同键异义请求、E/T/R1/状态端点不一致 | `幂等冲突` | 停在当前阶段 |
| G0 或后继期望代次漂移 | `当前性漂移` | 调用方重新发起新的业务请求；不得在原请求内刷新 |
| owner / 族 / 宿主 / 特征定义 / 前态 / A1 函数定义、触发前态或版本坏引用 | `引用冲突` | 零后继写 |
| 许可拒绝 | `许可拒绝` | 原样上送 |
| 分配或存储失败 | `资源失败` | 原样上送，可按原键恢复 |
| 返回截止非零但无法确认提交结果 | `发布未知` | 只读收敛，禁止越段 |
| 成功形状、跨 owner 引用或历史互证矛盾 | `内部错误` | 零成功载荷 |

非成功结果不得携带可冒充完整工作包的部分载荷。诊断可以保留已确认阶段，但 `成功()` 只接受最终全部七段读回完整的 `已形成 / 精确重复`。

## 9. 普通应用接线

普通应用在现有服务全部成功构造后持有一份 `需求初次筹办准备提供者`，构造时借用同一上下文中的需求查询组合器、任务、存在、特征、状态和状态动态 provider；增加 const / non-const getter。返回引用不转移所有权，不得构造第二组 owner。

真实启动线程是否自动调用该 getter 不在本叶内；本叶必须至少通过普通应用上下文作为合法消费者取得 provider，并在生产外治理专项走完整公开调用与读回矩阵。不得把治理专项命中写成普通启动线程已自动筹办。
