# 目标状态合同定义消费详细设计

日期：2026-08-16
版本：v0.1
身份：`TARGET-STATE-CONTRACT-DEFINITION-CONSUME`

## 1. 目标与完成边界

实现 BIZ-L4-004-01-01-01 v0.2：建立一个只读 `需求目标事实提供者`，从普通应用同一 `L2结构聚合服务` 取得同实例状态、特征服务，在一个调用方冻结的非零事实截止 `G0` 下依次读取并互证：

1. 完整当前 `L2目标状态合同事实`；
2. 完整当前 `L2统一特征定义事实`；
3. 当前唯一目标判断 `L2特征比较注册事实`。

成功只发布不可变值式材料；本叶不读取宿主当前值、不比较差距、不创建需求或任务、不判断多个目标等价、不修改 DATA。

完成最多证明这一枚 BIZ 组合读取 provider 可由普通应用合法消费者经现有聚合 getter 构造并真实调用。普通应用持有 provider、专用 getter和启动接线保持后继 `NOT_RUN`。当前只闭合 I64 目标状态与“标量有序比较和安全差异”注册，不证明向量、角度、空间、集合或时间序列值域，也不证明 BIZ-L3-004-01-01、当前正差距、需求建立、任务树或系统治理闭环。

## 3. 所有权、位置与依赖

新增文件：

```text
海中鱼巣/领域/需求目标事实.数据.h
海中鱼巣/领域/提供者.需求目标事实.ixx
```

`需求目标事实提供者` 是 DATA 之外的 BIZ 只读组合提供者。构造函数只接收 `const L2结构聚合服务&` 并保存该聚合引用；每次调用再由聚合取得同实例 `const L2状态结构服务&` 和 `const L2特征结构服务&`。禁止保存 L1、owner、仓库、写端口、缓存或第二份目标材料。

合法消费者从现有普通应用 const getter 取得聚合并在自己的调用作用域构造 provider：

```cpp
需求目标事实提供者 提供者{上下文.取得L2结构聚合服务()};
```

provider 的引用有效期不得超过普通应用上下文。当前叶不修改 `海中鱼巣/装配.普通应用.ixx`、`L2结构聚合服务` ABI 或任何普通应用装配状态，也不增加 DATA 业务快捷入口。普通应用未来是否持有 provider、公开专用 getter以及怎样分配装配失败状态属于独立后继，不得在本计划临场扩入。

## 4. BIZ DTO 与公开 ABI

全部类型置于 `海中鱼巣/领域/需求目标事实.数据.h`，函数名、类型名和字段名使用中文。

```cpp
inline constexpr std::uint32_t 目标状态合同定义消费合同版本 = 1;
inline constexpr std::uint32_t 目标状态合同定义消费规则版本 = 1;

enum class 目标状态合同定义读取状态 : std::uint8_t {
    已读取 = 1,
    入口拒绝 = 2,
    目标材料未找到 = 3,
    目标材料已退出 = 4,
    当前性漂移 = 5,
    许可拒绝 = 6,
    资源失败 = 7,
    目标上下文引用冲突 = 8,
    内部不一致 = 9
};

struct 目标状态合同定义读取请求 final {
    std::uint32_t 合同版本 = 目标状态合同定义消费合同版本;
    std::uint32_t 规则版本 = 目标状态合同定义消费规则版本;
    std::uint64_t 事实截止代次 = 0;
    L2目标状态合同身份 目标状态合同;
    L2特征定义身份 目标特征定义;
};

struct 目标状态合同定义材料 final {
    L2目标状态合同事实 目标状态合同;
    L2统一特征定义事实 目标特征定义;
    L2特征比较注册事实 目标判断比较注册;
    std::uint64_t 事实截止代次 = 0;
};

struct 目标状态合同定义读取结果 final {
    目标状态合同定义读取状态 状态 = 目标状态合同定义读取状态::入口拒绝;
    std::uint32_t 合同版本 = 目标状态合同定义消费合同版本;
    std::uint32_t 规则版本 = 目标状态合同定义消费规则版本;
    std::uint64_t 事实截止代次 = 0;
    std::optional<目标状态合同定义材料> 材料;
    bool 成功() const noexcept;
};

class 需求目标事实提供者 final {
public:
    explicit 需求目标事实提供者(const L2结构聚合服务& 结构服务) noexcept;
    目标状态合同定义读取结果 读取目标状态合同与值域定义(
        const 目标状态合同定义读取请求& 请求) const noexcept;
};
```

请求有效要求合同版本、规则版本分别为当前值，`G0` 非零且两个强类型身份非零。结果始终回显本次请求的合同版本、规则版本和最终截止；成功谓词要求状态为已读取、两个回显版本为当前值、结果和材料截止均等于非零 `G0`、optional 有值且三份 DATA 事实完整互证。所有非成功结果的 optional 必须为空；当前性漂移可回显 DATA 返回的非零截止，其它已进入 DATA 的非成功回显请求 `G0`，入口拒绝可回显原请求中的零 `G0`，都不得携带部分成功材料。

## 5. 读取顺序与逐字段互证

固定控制顺序：

```text
纯值校验合同版本、规则版本、G0和两个身份
-> 状态服务按当前/G0/目标合同身份完整读取
-> 互证结果状态为已读取、成功谓词、当前读取、历史截止为0、空变更代次、合同身份、目标判断用途、规则版本、有效允许关系位、当前生命周期和G0
-> 合同引用特征与请求目标特征不同则返回目标上下文引用冲突
-> 特征服务按当前/G0/特征定义身份完整读取
-> 互证结果状态为已读取、成功谓词、当前读取、历史截止为0、空变更代次、定义身份、当前生命周期和G0
-> 特征服务按G0/特征定义/目标判断读取当前唯一比较注册
-> 互证结果状态为已读取、成功谓词、当前读取、历史截止为0、空变更代次
-> 互证注册身份等于目标合同引用、注册特征等于目标特征、用途为目标判断、原始类型I64、算法族为标量有序比较与安全差异、左当前事实、右目标状态、方向右减左、单位/维度/分量角色非零、注册允许结果位包含具名关系、算法版本/边界/量化/误差合同完整、当前生命周期且G0一致；目标合同允许关系位自身必须在1—7冻结组合内，不把两类位掩码混作同一字段
-> 一次性构造完整候选材料
-> 无抛出值式返回
```

三次 BIZ 显式 DATA 请求头都固定为 `{L2结构合同版本, G0}`。不得使用零代次重选当前、不得把第一次返回截止带入后续形成新快照、不得用缓存跳过任何一次正式读回。`L2状态结构服务`为履行自己的公开目标合同读取语义可以内部再次读取特征定义和比较注册，因此这里只约束 BIZ 显式调用恰三次，不声称底层恰三次读取。

目标合同的 `目标I64` 和 `允许关系位` 是目标状态语义；比较注册的合同是值域、单位、维度、分量角色、算法、左右角色、方向、边界、量化和误差语义。内部稳定编码、首次幂等见证、来源和生命周期是结构审计材料，不复制为 BIZ 第二权威。

## 6. 状态映射、异常与并发

| 下层状态 | BIZ 状态 |
| --- | --- |
| 第一笔合同读取 `已读取` 且载荷完整 | 继续 |
| 第一笔合同读取 `未找到` | 目标材料未找到 |
| 第一笔合同读取 `已退出` | 目标材料已退出 |
| `事实代次漂移` | 当前性漂移 |
| `许可拒绝` | 许可拒绝 |
| `资源失败` | 资源失败 |
| 第一笔成功载荷中的特征定义与请求目标特征不同 | 目标上下文引用冲突 |
| 第一笔成功后，第二或第三笔返回 `未找到`、`已退出`、`属性未设置`或引用缺失 | 内部不一致 |
| 三笔成功且全部互证通过 | 已读取 |
| 合法 BIZ 请求触发 `入口拒绝`、`未实现`、任何写状态、幂等/预算状态、成功形状错误、非空变更代次、非当前读取、历史截止非零或混代 | 内部不一致 |

每次调用只使用局部值式材料，不加业务锁、不 sleep、不重试。并发写导致 `G0` 失效时直接返回当前性漂移，由父级重新选择完整截止并重做整个业务读取；本函数不得在内部半重试。捕获 `std::bad_alloc`、`std::length_error` 为资源失败，其它异常为内部不一致，`noexcept` 不允许终止进程。

## 8. 验证矩阵

1. 根工程 x64 Debug / Release Rebuild；
2. 通过普通应用现有 const 聚合 getter 取得 `L2结构聚合服务`并在合法消费者作用域构造 provider，确认其消费同一聚合实例；普通应用持有 / 专用 getter / 装配失败状态保持 `NOT_RUN`；
3. 生产外合法消费者用公开 DATA 入口建立 I64 特征定义、目标判断比较注册和目标状态合同，再按共同非零 `G0` 读取，逐字段等于三份权威读回；
4. 零 G0、零身份、错规则版本零 DATA 调用并返回入口拒绝；
5. 第一笔缺失 / 已退出合同分别返回目标材料未找到 / 已退出且空载荷；由于状态服务在第一笔成功前已于同一G0内部互证定义与注册，公开 ABI 无法动态构造“第一笔成功、第二 / 三笔缺失或退出”，该防御映射只做静态检查并记 `NOT_RUN`，不得增加生产 seam；
6. 请求特征定义与合同引用不一致返回目标上下文引用冲突；
7. 选择 `G0` 后推进事实代次，整次读取返回当前性漂移且不拼装；
8. 调用前后事实代次不变，源码零 DATA 写入口、零 L1 / owner / 仓库 / 缓存 / 日志裁决；
9. 每个成功 DATA 结果均检查 `已读取`、`成功()`、截止为G0、空变更代次、当前读取、历史截止为0、身份链和当前生命周期；
10. 完整特征定义值式复制可触发的 `std::bad_alloc`、`std::length_error` 映射资源失败，其它异常映射内部不一致；`noexcept` 不终止进程；
11. 不可由公开 ABI 构造的后继缺失、半结构、混代和私有坏形状只做静态防御检查并保持 `NOT_RUN`；
12. `git diff --check`、strict `113/113`、UTF-8 无 BOM、工程登记唯一、生产零验证 seam。

真实资源耗尽、许可拒绝、私有数据损坏和并发极限未发生时必须记录 `NOT_RUN`，不得用构建通过升级为完整业务闭环。
