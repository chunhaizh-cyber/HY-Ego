## 1. 修订边界

## 2. 唯一运行期顺序

同一长寿命 L1 实例的初始化顺序固定为：

```text
世界登记服务::建立空世界
-> L1场景结构服务::创建初始场景
-> L1特征定义服务::建立登记
-> L1特征定义服务::建立I64特征定义
-> L1实例特征服务::建立登记
-> L1实例特征服务::建立初始场景I64实例特征
```

世界登记仍是唯一允许在事实代次 0 且三表/永久占用全空时占用基座的入口。初始场景成功后，P2 `建立登记` 不再要求空基座；它必须读取同一 L1 的完整当前快照，接受非零当前代次且精确匹配请求期望代次，并确认本 P2 服务实例尚未登记，然后只追加自身固定四节点。P2 的公开 DTO、函数签名和四节点写集不变。

P3 自身登记继续要求期望事实代次与同一 L1 当前代次精确相等，不要求回到零代次；登记成功后实例建立仍在同一服务与同一 L1 上以一个写集发布一节点、两关系、一值和一属性槽。

## 3. 失败与事务边界

P2 或 P3 的快照失败、代次不匹配、已登记、关系/类型矛盾均在各自第一笔写入前返回具名非成功；不得清空世界或场景事实，不得重建 L1，不得用预计代次替代读回代次。跨服务初始化只按上述顺序串行执行，任一步失败停止后继步骤；已发布事实不回滚。

## 4. 验证增量

P3 专项必须在同一隔离 L1 中依次形成世界、初始场景、P2 登记/定义和 P3 登记/实例，断言每次成功只推进一个代次、前置事实完整保留、P2 四节点在非空基座追加且同代次读回、P3 实例写集与独立读回闭合。P2 服务与专项自检作为 P3 白名单兼容修改，只允许增加上述非空组合夹具；不得新增 DTO 字段或公开函数。

## 5. 完成边界

仍只证明一个已验证初始场景上的 I64 实例槽和初始值原子发布、幂等及独立读回；不扩展其它宿主、换代、批次、比较、状态动态、恢复、旧体系或生产接线。
