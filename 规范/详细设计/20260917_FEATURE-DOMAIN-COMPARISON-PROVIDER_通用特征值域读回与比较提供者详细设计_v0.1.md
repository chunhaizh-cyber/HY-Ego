# 通用特征值域读回与比较提供者详细设计

身份：`FEATURE-DOMAIN-COMPARISON-PROVIDER`

版本：v0.1

日期：2026-09-17

状态：可执行

## 1. 目标与边界

本设计形成 4180 §5.2 的只读提供者，使调用方能够以同一 `Gread/H` 对已发布特征概念 `FC` 取得其 `FT`、值表示、规范化值域和规则见证，并判定：域间相等、左包含右、右包含左、不包含，以及实例准确 `F` 是否被 `FC` 值域包含。

它只提供读取和判断，不创建或变更任何 F、FC、FT、值、材料、概念、关系、注册、命中、名称、使用或来源事实。I64 必须复用当前 `特征规范I64域`、`读取I64类型完整域`、`规范化I64特征域` 和 `判定I64域包含` 的实际语义；不得复制区间算法。

四种 2100 值表示都取得统一的公开入口。当前实际成功范围仅为已能完整读回的 I64 FC。I64组、U64组、独立材料引用**不缩窄为不支持的类型**：它们必须经同一入口被明确识别并返回“未实现”或“规则缺失”；所有此类暂未实现函数的声明及紧邻定义均须写出 `待实现`，且必须零事实写入、零关系写入、零成功关系载荷。未来的 FT 专用适配器只能填充该分支，不改变入口、状态含义或调用方合同。

完成不证明非 I64 规则/材料解析已经实现，不证明存在概念首次形成、最具体选择、主动归纳、世界实例创建、恢复、运行或业务验收。

## 2. 正式依据、真实代码与裁决

- 2100 v0.14：值对象只有表示与完整内容；值域、材料解释和比较均由 FT/比较规则负责。
- 4120 v0.11 §3、§8：四表示，I64组/U64组/材料的完整点域与实际材料解释边界；不得按编码或长度猜语义。
- 4130 v0.4 §5.1：值域关系不属于三态方向；非 I64 未实现只能结构化失败。
- 4180 v0.13 §5.2：统一值域读取、域间关系和实例命中合同、唯一 owner、同截止与零写入边界。
- 4182 v0.1：FT 唯一路由、专用规则与未启用能力分账。
- 7100 v2.0、7110 v2.0、4240 v0.42：存在概念完整匹配/归纳必须使用 FT 的真实值域关系，不能用节点号、摘要或 I64 降级。

当前 `数据服务.特征类.h/.cpp` 仅公开 I64 类型规格、`特征规范I64域` 和 I64 域读取/包含；`数据服务.特征值类.h` 已能在同截止完整读出四种值表示，但独立材料依赖正式材料服务；`数据服务.概念树类.h/.cpp` 仅能从现有纯 I64 特征概念结构读出 I64 域。因此没有非 I64 成功路径，不能由本计划假造。

## 3. 物理位置、唯一 owner 与依赖方向

新建唯一组合服务：

```text
海中鱼巣/领域/数据服务.特征值域比较类.h
海中鱼巣/领域/数据服务.特征值域比较类.cpp
```

类 `特征值域比较数据服务` 是 4180 §5.2 的唯一公开 owner。它以构造注入方式持有 `特征类数据服务`、`特征值类数据服务` 与 `概念树类数据服务` 的只读引用；不能持有 L1 写端口，不能暴露写方法。

`数据服务.概念树类.h/.cpp` 只新增概念 owner 的窄读取入口，用于按已知 `FC` 同截止读出其 `FT`、表示和 I64 域，或返回结构化非成功。概念树不调用新服务，不比较域，不创建适配器。`数据服务.特征类.h/.cpp` 只在实际需要时补充“当前 I64 规则/类型读回”的无写薄入口；不得为非 I64 建第二注册表。`数据服务.特征值类.h` 已有完整值读取，除编译需要外不修改。

依赖固定为：`特征值域比较 → 概念树窄读 + 特征类I64读 + 特征值完整读`。概念树、特征类、特征值类之间不得反向引用新服务；新服务不进入世界树、存在类、IF/R、动态、因果、线程或装配业务逻辑。

## 4. DTO、状态与函数合同

所有版本均为 `1`，所有预算使用现有 `世界结构预算_B1` 与 `概念树预算` 的组合上限；请求必须指定非零 `Gread`、非零 `H` 且 `H<=Gread`。新值域比较预算：

```text
特征值域比较预算_v1 {
  世界结构预算_B1 值与材料预算;
  概念树预算 概念预算;
  uint64 最大域项数;
}
```

`最大域项数` 约束 I64 区间数及未来完整点/材料域项数；为零是入口拒绝。

概念 owner 新增：

```text
特征概念值域基础读取请求_v1 { 版本,Gread,H,FC,概念树预算 }
特征概念值域基础事实_v1 {
  FC, FT, 特征值表示类型 表示,
  optional<特征规范I64域> I64域,
  概念创建/退出及读取截止见证
}
```

`I64域` 只在 `表示==I64` 且完整读回时存在。现阶段非 I64 的成功事实不产生空域或伪域；窄读取直接返回 `未实现`。状态至少为：`已读取、未找到、目标已退出、类别冲突、规则缺失、未实现、事实代次漂移、数量预算不足、历史材料不可用、资源失败、内部不一致、入口拒绝`。

组合 owner 固定公开：

```cpp
特征值域读取结果_v1 读取特征值域(const 特征值域读取请求_v1&) const;
特征值域关系结果_v1 核验特征值域关系(const 特征值域关系核验请求_v1&) const;
实例值域命中结果_v1 核验实例值域命中(const 实例值域命中核验请求_v1&) const;
```

读取请求为 `{版本,Gread,H,FC,预算}`；域间请求为 `{版本,Gread,H,左FC,右FC,预算}`；实例请求为 `{版本,Gread,H,F,FC,预算}`。域成功事实包含 `FC、FT、表示、规则身份/版本、特征规范I64域、基础读回见证、实际用量`。非 I64 成功域类型预留为不透明强类型联合，不以空 vector、材料 ID 或裸数编码暂代；在首版没有非 I64 成功事实。

关系枚举固定：`相等、左包含右、右包含左、不包含`。实例命中成功只允许 `相等、左包含右（FC包含实例点）、不包含`。所有结果另有稳定状态：`已读取、已核验、未找到、目标已退出、类别冲突、类型不相容、规则缺失、未实现、事实代次漂移、数量预算不足、历史材料不可用、资源失败、内部不一致、入口拒绝`。任何非成功清空域、关系、规则与成功见证；结果的 `成功()` 必须同时核验版本、截止、用量、FT、表示、规则、关系允许集合和所有嵌套读回。

## 5. 算法、截止与空实现

1. 先验证请求形状、预算、`Gread/H`。失败为入口拒绝，零载荷。
2. 对每个 FC 调用概念 owner 的窄读取。每一次 L1/概念/值/材料读出的实际代次必须等于 `Gread`；尾部截止复核仍为 `Gread`。不一致为事实代次漂移，清空成功载荷。
3. I64 分支验证两个 FC 同 FT、同表示、当前规则可读，取得规范化 I64 域；域间关系委托既有 I64 包含：双向包含为相等，仅左/仅右包含分别为左右包含，否则不包含。实例路径按准确 F 同截止读回、FT相等、准确 I64 转单点域，再委托既有 I64 包含。
4. I64组、U64组、独立材料引用分支在声明和紧邻定义中分别标注 `待实现`。如果 FC/FT 基础读回已证明此分支而缺专用适配器，返回 `未实现`；FT/格式/解析/比较规则未登记，返回 `规则缺失`。两者均不调用 I64 区间函数，不读取或写入任何新事实，也不返回关系枚举或成功值域。
5. FT 不同或表示不相容是 `类型不相容`；FC不是当前特征概念是`类别冲突`。未找到、退出、预算、历史清理、资源和内部异常按来源精确映射，均不转换为不包含或未找到。

本服务没有写入事务、幂等键、首次 H 或可能发布成功状态。若底层错误中包含幂等/发布未知诊断，只能映射为内部不一致或来源状态，绝不由此创建/复用任何对象。

## 6. 施工步骤与物理退出

1. 在概念树公共头/实现增加窄读取 DTO、状态、结果与按 FC 的 I64 基础读回；复用现有纯 I64 读取/规范化私有逻辑，禁止全域枚举。非 I64 与未知结构均在紧邻 `待实现` 定义中返回指定失败。
2. 建立新特征值域比较头/实现，构造注入三项只读服务，冻结 DTO/成功谓词/预算合并与状态映射。
3. 实现 I64 三入口：同截止读取、域间关系及实例单点命中；仅调用现有 I64 读回/规范化/包含，不复制区间运算。
4. 实现三种非 I64 相邻空函数。每个声明及定义均含 `待实现` 文本；确认没有任何写端口、L1 写集、关系写集、bool 默认成功或成功载荷。
5. 在 `.vcxproj`、`.filters` 登记新 `.cpp/.h`，仅调整因新源文件必须修改的工程项。清理本计划实际替代的临时非 I64 假比较/编码比较代码；若不存在则明确零删除，不顺带改旧特征概念模型或概念提供者计划。

## 7. 验证矩阵

1. `git diff --check` 与 `python .\tools\check_specs.py --strict` 通过。
2. Debug/Release x64 编译主工程；新 `.cpp` 在工程中恰好一次。
3. I64：同域、单向包含、双向相等、不交；实例单点命中/不命中；FT/表示不符；每个结果的 Gread/H/规则/预算读回正确。
4. 截止、预算、退役、历史清理、材料服务缺失、资源失败、内部异常均零域/零关系成功载荷，且不被误判为不包含或未找到。
5. 三类非 I64：入口可调用；规则缺失与未实现分账；声明和紧邻定义均检出 `待实现`；静态检查零写入口、运行前后权威事实代次不变、结果不成功且无关系。
6. 搜索确认本切片没有把节点编码、材料身份、摘要、长度、向量长度、默认排序或 I64 区间用于非 I64 成功关系；没有 L1 写端口成员或写集调用。
7. 运行/恢复/外设材料解析不在本计划验证范围；非 I64 专用成功行为必须另起适配器计划和真实消费者验证。

## 8. 对后继的交付

代码发布后，`EXISTENCE-CONCEPT-DEFINITION-PROVIDER-REBUILD` 可从“缺通用非 I64 比较合同”重新 S0 并激活：它可对 I64 真实核验，对已声明非 I64 取得结构化未实现/规则缺失而零写入。它不得把该发布解释为非 I64 存在概念已经能够成功形成；该能力要等各 FT 专用适配器完成。
