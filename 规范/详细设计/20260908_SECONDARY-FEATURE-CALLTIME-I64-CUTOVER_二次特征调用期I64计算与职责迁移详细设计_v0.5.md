## 1. 本版修订

4151 要求一次请求的公共上游可在本次图内共享，本次内部缓存用完释放；v0.1 第 6 节进一步冻结“共享子图同次只读取、计算和回执一次，真实读取不重复计费”。当前候选的 `读取标量派生定义` 只接受一个根，每次调用新建独立递归读取上下文。若两个保存定义根 A、B 共同依赖保存定义 C，计算应用分别读取 A、B 时会物理重复读取 C，并把 C 的材料重复计入预算；应用在两次返回后合并结构不能撤销已发生读取和计费。

本版主要新增保存派生定义的批量共享闭包读取合同，并冻结二次计算应用的一次预取顺序；同时收口执行侧同轮报告的方向结果文字缺口，不新增方向业务步骤。v0.1—v0.4 的其它设计继续有效；冲突处以本版为准。不得借此修改单根读取既有 ABI、持久结构、准确 F 合同、当前 K 读取、算法、上下文、RC、持久二次实例、owner 或工程文件范围。

## 2. 复用与新建裁决

应用侧在多个单根 DATA 调用之后合并结果只能对返回对象去重，不能证明 L1 材料没有被重复读取，也不能把已发生的真实用量倒扣，因此不满足已冻结合同。跨调用暴露可变读取会话会扩大生命周期、锁和并发所有权，复杂度更高。

采用一个批量只读入口：调用者一次提交本轮直接引用的去重保存根；特征 owner 在一个锁作用域、一个 G/H 和一个共享递归上下文内展开全部根。现有递归上下文已经按稳定编码维护定义、关系、叶、值集合，可直接形成联合去重，不建立持久缓存、第二 owner 或跨调用会话。

## 3. 批量读取 DTO 与入口

在 `海中鱼巣/领域/数据服务.特征类.ixx` 增加：

```cpp
inline constexpr std::uint32_t 特征类标量派生批量读取合同版本 = 1;

struct 特征类标量派生批量读取请求 final {
    std::uint32_t 版本 = 特征类标量派生批量读取合同版本;
    std::uint64_t Gread = 0, H = 0;
    std::vector<特征类定义身份> 根定义组;
    特征类派生读取预算 预算;
};

struct 特征类标量派生根读取回执 final {
    特征类定义身份 定义身份;
    std::vector<稳定编码> 左叶组, 右叶组;
};

struct 特征类标量派生批量读取结果 final {
    std::uint32_t 版本 = 特征类标量派生批量读取合同版本;
    特征类标量状态 状态 = 特征类标量状态::入口拒绝;
    std::uint64_t Gread = 0, H = 0;
    特征类标量派生批量读取请求 原请求;
    std::vector<特征类标量派生根读取回执> 根回执组;
    std::vector<特征类标量派生事实> 完整定义组;
    std::vector<特征类标量叶回执> 基础叶组;
    特征类派生读取用量 用量;
    bool 成功() const noexcept;
};

特征类标量派生批量读取结果 批量读取标量派生定义(
    const 特征类标量派生批量读取请求&) const;
```

不修改`特征类标量派生读取请求/结果`和`读取标量派生定义`；既有单根消费者继续使用原入口。新批量入口只供同一次调用期图联合读取多个保存定义根，不用于写入、概念形成或跨调用缓存。

## 4. 请求与返回不变量

请求必须满足：版本正确，`0 < H <= Gread`，预算六项全非零；`根定义组`非空、按定义节点稳定编码严格升序、无重复且每项有效。调用应用负责从请求图提取直接出现的保存定义身份并排序去重；递归上游不重复加入请求根，由 DATA 展开。入口一开始完整回显`原请求`；成功谓词只依赖结果自身字段，不依赖已离开作用域的函数参数。

批量入口在同一个 mutex 作用域内创建唯一`标量读取上下文{Gread,H,预算}`，按请求根顺序调用既有递归展开。上下文内定义、关系、基础叶和值事实均按稳定编码首次出现时读取和计数；共享定义 C 及其共享下游只展开、读回和计量一次。根本身也属于`完整定义组/定义数`，不另增材料费。每个根仍独立计算左右来源叶闭包；同一叶可出现在多个根回执的角色集合中，但在`基础叶组/叶数/材料总数`只出现一次。

成功结果固定：

1. `原请求`版本、Gread/H、根组和预算有效，结果`Gread/H`逐项等于原请求，状态为`已读取`；
2. `根回执组`与请求根一一对应、顺序相同、身份相等，各根在`完整定义组`恰出现一次；
3. 每个根的左右叶组均非空、分别严格升序无重复，所有身份都能在联合`基础叶组`定位；联合基础叶组中的每项至少被一个根的左/右闭包引用；
4. `完整定义组`和`基础叶组`分别按稳定身份严格升序无重复；每个定义完整，全部派生来源定位到同组更低阶定义及具名输出，全部准确来源定位到联合基础叶；
5. `用量={联合唯一定义数, 联合唯一关系数, 联合唯一叶数, 联合唯一属性值数, 所有根路径中的最大深度, 四类联合材料总数}`，四类加法可表示且逐项不超过请求预算；
6. 返回前 G 守卫仍等于请求 Gread。

任一根入口非法、未找到、已退出、格式坏、来源不匹配、历史不可用、成环、预算不足、G 漂移、资源或内部失败时，整批非成功：清空根回执、完整定义和基础叶成功载荷，只保留原请求、Gread/H、状态以及失败点以前真实联合用量。不得返回部分成功根供计算消费。

## 5. 二次计算应用的固定预取顺序

`海中鱼巣/业务/计算.二次特征.ixx` 在任何准确 F 或保存定义读取前执行：

1. 从全部本次局部图项的两个直接输入及全部根输出中，收集直接出现的`二次已保存定义输出来源`之定义身份；按身份排序去重形成批量请求根。递归保存来源由 DATA 展开，不由应用预猜。
2. 集合非空时恰调用一次`批量读取标量派生定义`。批量预算机械换算为：`最大定义数=min(剩余图项数,剩余读取材料数)`、`最大关系数=剩余读取材料数`、`最大叶数=min(剩余基础叶数,剩余读取材料数)`、`最大属性值数=剩余读取材料数`、`最大深度=剩余展开深度`、`最大材料总数=剩余读取材料数`；任一为零即预算不足。
3. 批量成功后、改变任何缓存前，令 `N=完整定义组.size()`：检查 N 不超过剩余图项数，检查 `N <= UINT64_MAX/2`且`2*N`不超过剩余来源边数，联合基础叶数不超过剩余基础叶数，材料总数不超过剩余读取材料数；任一不成立返回预算不足。
4. 随后按联合`用量.材料总数`扣一次读取材料预算，按联合唯一基础叶数扣一次基础叶预算，按 N 扣一次图项预算，按`2*N`扣一次来源边预算；把联合定义组按身份放入本次 `saved` 缓存，把联合基础叶转换并放入本次 `leaves` 缓存。四项扣减必须在逻辑上作为一个准入步骤，不能部分扣减后继续。
5. 后续图展开遇到任一已保存定义时必须命中 `saved`，不得再调用单根读取入口，也不得再次扣该定义的图项、两条直接来源边、闭包叶或读取材料；未命中表示批量闭包不完整，返回`内部不一致`。同一保存定义计算节点仍只形成一个回执，并由所有使用边引用。本次局部计算项继续在首次展开时各扣一个图项和两条直接来源边。
6. 后续直接准确 F 来源先查 `leaves`；若它已由批量保存闭包读回，不再调用有界准确 F 入口、不再扣材料或叶预算。只有不在联合闭包中的新 F 才调用原有界准确读取并按真实用量计费。
7. 应用按每条使用路径继续核验整个本次 DAG 深度；批量 DATA 的最大深度只证明各保存根内部闭包，不替代局部图前缀深度核验。

请求不含保存定义来源时不调用批量入口，准确 F 与本次局部图按原合同执行。禁止为了使用批量入口把本次局部输出伪装成保存根，也禁止把批量结果留到下一次调用。

## 6. 计费示例与失败边界

若根 A、B 都直接或递归依赖 C，联合定义集合为 `{A,B,C,...}`：C 的节点、关系、值和其独有叶材料只读取、计量一次；A/B 两条到 C 的使用路径仍分别存在，来源边和路径深度按计算图各自核验，不能因材料去重合并角色边。若一个显式准确 F 同时也是 C 的基础叶，批量先放入 `leaves` 后，显式来源命中缓存，不发生第二次准确读取。

预算在任何新材料进入共享上下文前检查。批量读取中途超限时返回到失败点的真实联合用量，但计算应用只用于诊断并整次返回预算不足；不得用失败载荷继续计算。资源异常、未知状态或返回结果不满足`成功()`均 fail-closed，不回退为逐根读取。

## 7. 方向结果成功谓词与任务尾 G

v0.1 第 7.1 节“计算基础叶、当前采用和结果回显互证”以及 v0.2 第 7 节“自包含判断成功”容易被理解为`需求目标方向结果::成功()`必须在 DTO 内重新保存并证明全部宿主成员和当前采用 L1 事实，但冻结 DTO 并无这些字段。正式规范只要求应用在本次一致截止核验合法来源，不要求方向结果复制宿主快照或采用关系作为业务输出。

本版作最小替换：目标宿主存在、全部基础叶属于该宿主、当前 F 是该 FT 的唯一当前采用，都是`需求目标方向应用服务::读取并计算`在请求 G 下必须完成的权威入口核验；计算完成后必须做尾 G 守卫。它们是产生成功结果的控制前置，不新增结果字段。`需求目标方向结果::成功()`只自包含互证结果包已有字段：原请求、G、需求、目标宿主身份、当前/目标 F、方向定义、计算子结果、根角色和计算来源闭包。它不得声称仅凭 DTO 可离线重证当时完整宿主成员表或当前采用关系；也不得因成员函数不重复访问 L1 而省略入口权威核验。

任务应用调用需求方向后若自己的尾 G 守卫失败，顶层固定返回`事实代次漂移`且`成功()`为假，同时完整保留已经返回的`方向`子结果及其原请求、状态和成功载荷作诊断。该子结果只证明它自身在请求 G 内完成，不能在顶层 G 已漂移后继续作为可消费的任务方向结果。调用需求方向前失败时`方向`为空；需求方向本身失败时沿 v0.2 映射并完整保留失败子结果。此裁决与既有“调用后失败保留完整方向、顶层仍非成功”一致，不清空或改写子结果状态来伪造同层失败。
