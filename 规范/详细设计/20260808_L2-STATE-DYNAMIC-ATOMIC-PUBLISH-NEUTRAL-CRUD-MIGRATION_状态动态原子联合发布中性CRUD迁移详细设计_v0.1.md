# L2-STATE-DYNAMIC-ATOMIC-PUBLISH-NEUTRAL-CRUD-MIGRATION 状态动态原子联合发布中性 CRUD 迁移详细设计 v0.1

日期：2026-08-08  
状态：设计已闭合；代码待实施

## 1. 目标与结论

唯一目标是把现有 `状态动态原子发布服务::发布实际存在I64后继状态与迁移动能` 从旧 L1 业务意图、执行证据和业务标签写入口迁移到正式业务中性 CRUD 入口，同时保持 P13 状态规格、可选 P14 迁移动能规格、一次原子发布以及状态 / 动态领域权威读回的业务边界。

本叶完成后，领域生产代码中的旧 L1 写调用应归零：

- 不再调用旧幂等探测；
- 不再形成请求意图摘要、领域意图凭证或执行证据材料；
- 不再把业务操作标签交给 L1；
- 不再调用旧 `提交写集`；
- 不再从旧完整读回、审计、恢复、SQL、日志或完整快照补取首次写集。

本叶不是 L1 自证或专项验收。它只让该第二层服务能够按自身合同经正式中性入口提交并从状态 / 动态所有者读回；当前尚无合法生产消费者，业务场景保持未运行。

## 3. 公开合同 v2

### 3.1 请求

`状态动态原子发布合同版本` 与 `状态动态原子发布规则版本` 均升为 2。请求字段形状保持：

```cpp
struct 状态动态原子发布请求 final {
    std::uint32_t 合同版本;
    std::uint32_t 规则版本;
    std::uint64_t 整理幂等身份;
    实际存在I64后继状态规格请求 后状态;

```

旧公开幂等域、意图组、入口变体和业务操作标签从数据头删除。最终中性幂等键的域值保持当前数值不变，但成为服务实现私有常量。

### 3.2 结果

删除旧 `状态动态原子发布首次证据`，改为：

```cpp
struct 状态动态原子发布首次见证 final {
    std::uint64_t 整理幂等身份 = 0;
    std::uint64_t 发布事实代次 = 0;
    状态动态原子发布形状 形状 = 状态动态原子发布形状::无;
    稳定编码 后状态稳定身份;
    std::optional<稳定编码> 迁移动能稳定身份;
};
```

`状态动态原子发布结果` 保留：领域状态、内部原因、是否精确重复、可选首次见证、后状态事实、可选迁移动能事实。删除 `L1失败见证`。

首次见证只报告该领域发布已经通过权威读回确认的事实身份和代次；缓存中的中性写集、L1 本地键映射、锁和内部阶段均不得公开。

内部原因改为 v2 的领域可解释集合：无、上游状态规格矛盾、上游动态规格矛盾、共同截止不一致、局部键或引用矛盾、中性写集转换失败、中性写入结果矛盾、中性映射不完整、状态读回请求形成失败、动态读回请求形成失败、状态权威读回矛盾、动态权威读回矛盾、缓存记录矛盾、发布后隔离。旧幂等首次证据和执行证据材料原因删除。

## 4. 服务所有权与串行边界

`状态动态原子发布服务` 新增普通 `std::mutex`，公开发布入口在读取或修改任何内部账之前取得整段独占锁，直到结构化结果形成后释放。

当前函数不调用自身公开方法，P13、P14、L1、状态读回和动态读回均属于其它服务，因此不存在合法自重入链。不得使用递归锁，不得允许回调重新进入本对象。

锁顺序固定为：

```text
状态动态原子发布服务锁
-> P13 / 可选 P14 的内部读取
-> L1 中性提交
-> 状态所有者读回
-> 可选动态所有者读回
```

后续装配和消费者不得建立持有任一下游服务锁再回调本服务的反向路径。

## 5. 多项发布账

服务拥有 `std::map<std::uint64_t, 发布记录>`，键为最终中性幂等键的数值。不得只保存最后一次请求。

每项记录保存：

- 完整公开请求；
- 首次实际提交的完整 `L1中性写集请求`；
- L1 返回的完整中性本地键到稳定编码映射；
- 状态领域读回请求；
- 可选动态领域读回请求；
- 可选首次见证；
- 内部阶段：`提交中`、`已发布待读回`、`已发布`。

缓存不是成功来源。任何同义重复都必须把缓存的完整中性写集原样再次提交 L1；只有 L1 精确重复且本次状态 / 动态权威读回一致，才能返回幂等读回。

## 6. 首次路径

### 6.1 上游规格

缓存未命中时才运行 P13；只有非等价迁移才运行 P14。继续核对：

- P13 成功必须携带状态写入规格、迁移判定和共同事实截止；
- P14 成功必须携带完整动态写入规格；
- P13 与 P14 的共同截止必须相等；
- 等价分支只发布后状态，非等价分支同时发布后状态与迁移动能。

旧提供者证据凭证不再成为本入口成功必要条件，也不再转换成 L1 执行证据。

### 6.2 中性写集一一转换

P13 / P14 当前仍返回旧写项值结构。本叶只读取其中节点、关系、值、属性槽、退出项、期望截止和本地引用，机械转换到中性类型：

- 本地键数值不变；
- 稳定编码引用不变；
- 本地引用按相同数值转换；
- 节点种类和属性类型值表示逐项转换；
- I64、I64 组、U64 组和独立材料引用逐项转换；
- 关系角色 / 顺序不变；
- 状态写项保持 P13 原顺序并置于前部，动态写项保持 P14 原顺序并置于后部；
- 属性槽变更和退出项采用同样顺序规则。

转换后的完整写集固定为中性合同版本 1，期望事实代次为共同截止，幂等键由整理幂等身份映射到服务私有域。不得读取或声称缓存 L1 内部规范化结果。

### 6.3 发布前预占

在调用 L1 前完成全部可能分配的公开请求副本、中性写集、记录对象和映射容量准备，再以 `提交中` 阶段预占 map 节点。预占失败返回资源失败，L1 调用次数为零。

同键已有记录时：完整公开请求不同立即返回冲突；完整请求相同进入重复路径，不运行 P13 / P14。

### 6.4 L1 返回后的不可丢失边界

首次路径恰一次调用 `L1事实基座服务::提交中性写集`。

- `是否形成内存权威发布 == false` 且状态非成功：确定零发布，删除预占记录并按中性状态映射返回。
- `是否形成内存权威发布 == true`：无论最终状态是否成功，记录必须保留并进入 `已发布待读回`。当前实现中该非成功形状只可能是交换后读回矛盾并进入 L1 隔离；不得把它解释为零发布。
- 成功或精确重复：先核对合同版本、幂等键、事实代次、发布标志 / 重试边界和完整唯一映射；将 L1 返回映射移动到记录后，才允许继续形成领域读回请求。

映射转换、读回请求形成或领域读回失败时记录仍保留，返回内部不一致。后续同义请求仍原样重提首次写集；已发布记录解除隔离后只允许得到 L1 精确重复，不能再次形成首次成功。

## 7. 重复路径

重复路径固定为：

```text
按最终键命中发布记录
-> 逐字段比较完整公开请求
-> 原样复制记录中的首次完整中性写集
-> 恰一次提交 L1
-> 只接受精确重复
-> 核对合同、幂等键、首次发布代次和完整映射均与记录一致
-> 使用记录中的状态 / 动态读回请求重新调用领域所有者
-> 逐字段核对权威事实
-> 返回幂等读回
```

同键异请求不调用 P13、P14 或 L1。缓存命中不得直接返回以前的结果。

## 8. 领域权威读回

中性映射先按本地键完整唯一核对，再机械形成现有状态和动态所有者所需的读回请求。允许为了复用现有只读请求形成函数在服务内部把中性映射转换为等值临时映射，但该临时映射不得进入公开 DTO 或缓存权威。

状态读回必须证明后状态事实存在、身份等于映射、创建事实代次等于首次发布代次。非等价分支还必须证明迁移动能存在、身份等于映射、创建事实代次相同且其后状态关系指向本次后状态。等价分支不得出现动态事实或动态身份。

全部核对通过后形成并保存首次见证，记录进入 `已发布`。后续事实代次可以继续前进，因此重复读回只要求返回的具名事实仍为当前且创建代次 / 身份与首次见证一致，不要求本次读取截止等于首次发布代次。

## 9. 失败和异常

| 阶段 | 结果 | 记录处理 |
| --- | --- | --- |
| 请求版本 / 身份无效 | 入口拒绝 | 不建立记录 |
| P13 / P14 非成功 | 映射领域状态 | 不建立记录 |
| 规格或转换矛盾 | 内部不一致 | 不建立记录 |
| 预占分配失败 | 资源失败 | 不调用 L1 |
| L1 明确零发布非成功 | 映射中性状态 | 删除提交中记录 |
| L1 已发布但返回内部不一致 | 内部不一致 / 发布后隔离 | 保留已发布待读回记录 |
| L1 成功结果字段矛盾 | 内部不一致 | 若发布标志为真则保留记录 |
| 映射或领域读回矛盾 | 内部不一致 | 保留记录，后续同义请求继续收敛 |
| 同键异请求 | 冲突 | 原记录不变 |
| 资源异常发生在发布前 | 资源失败 | 删除未发布预占记录 |
| 资源异常发生在发布后 | 资源失败或内部不一致 | 保留已发布记录 |

不得以日志、摘要、审计、恢复或快照把失败改成成功。
