## 1. 设计结论

新建 `世界树业务服务`，但不把它做成拥有全部底层写权的万能服务。它是 L2 统一门面，复用存在、场景、特征、状态、动态的唯一业务所有者，并增加两个当前缺失的提供面：

1. 关系稳定身份、类型化结构提交、现实世界引导、场景结构枚举、移动和移除关系；
2. 由全部具名服务结果的同一发布代次见证组成的完整世界事实快照。

旧 `世界服务.h` 不扩展、不保留兼容壳。当前 12 个直接消费者和 2 个间接受影响消费者必须先由各自事实所有者的独立稳定身份迁移包完成迁移；`世界服务.h` 自身是待删除提供者，不计入消费者数量。P1D 只在这些前置结果已进入当前代码基线后执行生产装配切换和头文件、include、成员、构造及工程登记删除，不在切换计划中临场重设计上层协议。现有两个运行期组合器改为消费世界树门面的正式消费者，不成为第二权威。SQL 不参与普通世界树裁决。

### 4.2 完整性状态

`完整世界事实快照` 只有在状态为 `已读取` 时允许 `完整=true`。其它状态必须清空事实集合并保留请求头、根和必要诊断分类；不得返回“部分成功”。诊断只记录具名缺项类别和相关稳定身份，不包含日志文本、SQL 行或内部地址。

## 5. 读取算法

`世界树快照读取服务::读取完整世界事实快照` 固定执行最多两轮。每轮顺序：

1. 验证请求头，调用 `节点直接世界结构读取服务::读取世界结构`。该 L2 服务先调用 L1 `读取当前事实代次` 取得首个非零代次，再通过 L1 纯值查询函数按稳定身份遍历根、场景和直接关系，最后再次读取代次；每个 L1 函数各自取得一次 try-lock 共享许可，许可竞争立即返回。
2. 只有该服务内部全部成功结果和首末代次相等时，才按稳定主键队列检查根类型、根无父、场景单父、无环、存在单位置、关系端点和世界归属并返回；内部代次漂移丢弃全部材料并完整重试一次。L2 世界结构服务不取得许可，内部句柄不会越过任何 L1 函数边界。
3. 快照服务把结构结果中的宿主组传给 `节点直接特征查询服务::读取宿主组完整当前特征`；把场景/主体组传给 `节点直接状态动态查询服务::读取世界状态动态`。两个服务各自取得 try-lock 共享许可并返回非零代次和值式材料。
4. 调用 `节点直接世界结构读取服务::读取当前事实代次` 取得末次代次。任何许可竞争、资源失败、未找到或内部不一致立即按原分类返回，不伪装成代次漂移。
5. 只有首次结构、特征、状态动态和末次结果的非零代次完全相等时，才按 4200 稳定规则排序、检查重复与缺项并发布完整快照。
6. 若所有服务都成功但代次不等，丢弃整轮全部材料。第一轮漂移时从步骤 1 完整重试一次；第二轮仍漂移返回 `版本漂移`。不得只重读漂移的子集。

L2 快照服务不取得共享许可，不调用 `_已许可` 私有函数，也不把一个服务的许可传给另一个服务。一次服务内部的许可只证明该服务结果对应其返回代次；跨服务一致性只由首末代次完全相等证明。

## 6. 写入算法

### 6.1 启动恢复与首次世界引导

普通业务入口开放前，运行期装配调用 `节点直接世界引导服务::确保现实世界已引导`：

1. 以安装实例身份调用 4070 恢复服务；完整恢复候选通过全部领域重新准入后，经恢复服务→数据操作→执行器一次发布并读回世界根场景、初始场景和直接关系。
2. 只有恢复服务依据持久安装证据返回 `确认无已发布历史` 时，才进入空域初始化；SQL/材料不可达、证据缺失或损坏均不能等价为“空库”。恢复服务唯一调用数据操作的恢复专用入口，要求当前代次 0、全部业务仓为空和实例证据明确，先发布仅含治理幂等记录的代次 1。该治理事务的节点/关系/类型化值/索引读回、业务操作读回和计划身份映射全部为空，结果摘要仍显式覆盖这些空集合。
3. 世界引导再以普通提交和 `预期事实截止代次=1` 创建世界事实；L1 分配两个节点稳定主键和一条关系稳定主键，同事务发布现实世界根场景、初始子场景、场景资格类型化记录、直接父子关系和索引，成功代次为 2。根与初始场景资格值的所属分别为各自局部节点，来源统一固定为世界结构服务稳定身份；不得以自引用新节点、父场景或 SQL 行补造来源。
4. 同安装实例身份同义重试返回原代次和原读回；异义或已存在第二根返回冲突/内部不一致。
5. 引导成功后关闭首次创建分支；普通世界服务没有重新引导、清空或从 SQL 覆盖当前内存的入口。

### 6.2 创建存在并接纳

```text
世界树服务核验请求头和目标场景属于世界
-> 节点直接存在服务形成实际存在写入规格和稳定幂等语义
-> 节点直接场景服务核验场景稳定身份、现有归属和幂等账
-> 场景服务形成纯值式类型化结构写集并调用 L1 提交服务
-> L1 内部固定参与者完成候选、确认、逆序撤销和最后发布
-> 代次推进后且独占许可释放前，L1 按节点/关系通用读回项返回材料，场景服务映射为创建存在读回
```

同一世界树幂等身份已经发布且完整语义相同时返回原稳定身份和归属见证；异义返回幂等冲突。存在于别的场景不自动移动，调用方必须显式调用移动函数。调用方不得指定内部节点稳定主键；真实新建分支由存在领域在对应命名域内取得下一合法稳定主键。实际存在资格值所属为新存在局部节点，来源固定为存在服务稳定身份；接纳场景只通过归属关系承担位置事实，不接受空来源、安装实例、新存在自引用或接纳场景冒充资格来源。

### 6.3 初始特征与换代

- 初始入口遍历 `项目组`，每项必须是 `特征批次初始项请求`。
- 更新入口每项必须是 `特征批次换代项请求`。
- 宿主必须是快照中该世界的存在；场景特征需后继专门入口，不在这两个“存在特征”函数中静默接受。
- 判断通过后调用 `节点直接特征写入服务::提交世界树特征批次`；不拆批、不改顺序号、不生成第二批次身份。服务内只在真实新建分支为初始槽和新值分配稳定主键；旧结构栈的 `提交特征批次请求` 不参与本链。
- 发布成功后在原独占许可内按批次项目稳定身份读回本次项目；逐项核对槽、定义、新值、原始值版本和来源。事务释放后的“宿主全部当前特征”只由独立查询入口读取，不用于证明本次提交。

### 6.4 状态与动态

调用方只提供待发布后状态的场景、主体、特征、特征值、来源存在、发生时间和唯一整理幂等身份，不提供第二状态事务身份、前状态、来源动作或动态稳定身份。当前旧状态接口不满足 1160/4210，不能直接复用；实现必须先补齐关系 19/20 的具名完整入口。调用顺序：

```text
节点直接动态业务服务读取主体、场景、特征相等的全部状态；非空时最大时间戳必须恰一项且新时间必须严格更晚，否则拒绝历史插入/多解且不得按身份择一
-> 无前状态：发布基准状态并读回关系 19 角色 1—5；不创建动态
-> 有唯一前状态：调用 4180 当前唯一注册路由比较前后特征值
-> 等价：调用状态业务服务只发布后状态，不创建/占用动态身份
-> 有合法差异：由动态业务服务在一个事务发布后状态和关系 20 状态迁移动能
-> 未注册、不可比、差异不可表示、前状态不唯一、同采样点异义或版本漂移：第一笔写入前结构化拒绝
-> 发布后在原独占许可内读回后状态；仅合法差异分支要求迁移动能存在
```

无前状态分支不创建动态；等价分支不得占用动态身份；合法差异分支才由动态领域分配稳定身份。旧 `状态动态组合器` 不取得新世界树合同身份，也不能为新门面提供回退。

状态节点/时间值/关系 19 与差异分支的动态节点/三项类型化值/关系 20 使用函数确认 2.6 冻结的局部身份和写项顺序。角色 3 固定为特征定义，动态时间等于后状态时间，全部类型化值来源固定为来源存在。入口先仅按完整公开请求形成请求意图摘要并调用 L1 幂等探测；同义已发布在任何状态读取和 4180 比较前返回原结果。只有未找到才解析唯一前状态并调用比较，执行证据摘要另含前状态、比较提供者稳定身份、合同版本、算法版本、比较分类、代次和写集材料。新事务把请求意图摘要、执行证据摘要和查询结果代次写入提交请求，L1 在独占许可内最终复核幂等和代次；L1 不重算领域执行证据摘要，漂移则零写入返回版本漂移。

### 6.5 移动和移除

节点直接场景服务拥有归属关系语义。移动在一个独占会话中：

1. 以稳定身份见证重读根、成员、旧父、旧关系和新父，并在许可内形成内部句柄投影；
2. 构造去除旧边后的场景图；子场景移动验证新父不是成员或后代；
3. 确认成员没有第二当前父；
4. 失效旧关系候选，再创建新归属关系候选；
5. 读回候选图仍单根、单父、无环；
6. 请求提交、确认、逆序撤销边界、最后发布；
7. 以关系稳定主键读回旧关系已失效且新关系唯一当前，再形成公开稳定身份见证。

移除存在执行同样流程但不创建新关系。子场景不允许移除，以免形成无根子树。

## 7. 代次发布

`节点直接身份结构事务域` 独占拥有初值为 `0` 的内存已发布代次。共享/独占许可只持同一代次见证；现有通用 `执行` 入口不承担本目标。`节点直接类型化结构提交服务` 由 `核心/服务.节点直接类型化结构提交.ixx` 唯一拥有，并调用 `核心/数据操作.节点直接类型化结构.ixx` 唯一拥有的数据操作；数据操作逐字段形成中性规格后调用执行器窄入口。执行器模块只拥有固定事务执行能力，不声明服务类、不 import 服务模块、不建立跨模块 friend。只有该窄入口能在类型合同、节点、类型化值、关系、索引、删除和幂等记录全部参与者完成最后发布后推进代次：

- 空域治理初始化：仅确认从未发布实例允许 `0 -> 1`，业务写集和通用读回为空；
- 普通成功提交：仅接受非零预期代次，`N -> N+1` 且 `N >= 1`；
- 入口拒绝、幂等纯读回、版本漂移、候选失败、撤销成功：不推进；
- 最后发布部分失败或代次溢出：隔离事务域并返回内部不一致；
- 恢复一次发布：只在空且隔离的内存域原子设置为持久证据最大连续发布代次，不按恢复记录数量逐次推进，也不重置为 1。

固定入口先在独占许可下只读计算计划稳定身份、预计后继代次和确定性写集材料，不推进高水位也不建立候选；写前持久准备成功后才按计划身份建立候选。这样持久准备失败时没有候选、高水位或普通事实变化，且独占许可防止计划身份在准备期间被占用。幂等候选保存计划通用读回和确定性结果摘要并与全部参与者一起最后发布。代次推进后、独占许可释放前按请求的通用对象种类、身份、预期版本和当前/失效/移除状态复核稳定身份值式结果，再由 L2 事实所有者映射操作读回。读回不一致不撤销或二次改写已发布事实，而是隔离事务域、保留代次并返回内部不一致。代次是事实截止见证，不是节点、关系、特征批次或世界规则版本。

## 8. 装配和运行期消费

`运行期业务装配` 的新域唯一共享实例按以下顺序构造：事务域和节点/关系/索引/类型合同/类型化值/幂等仓库及持久端口 → 使用八项指针完整构造的节点直接身份结构写入执行器 → 节点直接类型化结构数据操作 → L1 查询服务 → 只保存安装实例身份/数据操作引用的提交服务 → 只保存恢复材料端口/数据操作引用的 4070 恢复服务 → 世界引导、存在、场景、特征、状态动态服务 → 世界结构读取与快照读取服务 → `世界树业务服务` → 运行期只读/写组合器。提交服务、恢复服务和数据操作分别由 `服务.节点直接类型化结构提交`、`服务.节点直接结构恢复`、`数据操作.节点直接类型化结构` 唯一拥有；执行器模块只提供固定事务执行能力。析构逆序自然成立。既有四参数执行器只支持旧通用入口，不能注入新提交或恢复服务。所有服务引用覆盖全部同步请求，不缓存仓库锁或调用期句柄。

`运行期业务操作组合器` 增加世界树写入口并只委托世界树服务；`运行期只读查询组合器` 增加三个世界树读入口。`运行期业务请求路由` 只增加写请求 variant 和结构化结果，不取得世界服务引用以外的依赖。

P1D 生产切换开工前必须只读证明 12 个直接消费者和 2 个间接受影响消费者的独立稳定身份迁移已经进入当前代码基线。当前旧结果的三个关系句柄只在初始化内部消费，无需兼容复制；阻断点是世界根、场景、自我存在裸句柄和旧坐标槽。旧基础信息世界根到新场景世界根是语义切换，不允许按字段改名。前置满足后，P1D 只执行：

1. 接入世界引导、九类统一门面、组合器和运行期路由，普通入口仅在引导成功后开放。
2. 复核所有上层消费者已不再要求旧世界初始化结果或句柄；任一残留即返回具名依赖漂移，不在本计划补迁移。
3. 删除 `领域/世界服务.h`，移除残余 include、装配成员、构造参数和工程登记；全仓零命中是删除完成门禁。

这项删除只针对旧统一 `世界服务` 门面。旧存在/场景等单领域服务仍有本目标外真实调用者，本计划不在未经迁移设计的情况下顺带删除它们；但新门面禁止调用它们。

## 9. 错误、撤销和恢复

诊断责任以函数功能确认 §4 为唯一明细：正式服务公开入口或启动/路由最终边界是本地记录点；执行器、仓库、数据操作、查询提供者和内部组合委托只返回结构化结果向上送出；仅无分配、无外部访问、无可失败分支的纯值谓词、比较器和稳定映射为无适用错误分支。同一异常链只记录一次，合法业务拒绝不写错误日志。

- 入口拒绝：坏合同、坏身份、类型错误、根移动、跨世界、混合批次。
- 逻辑内结果：未找到、幂等读回、幂等冲突、版本漂移、许可拒绝、资源失败。
- 内部不一致：多父、环、槽/值重复或缺失、端点悬空、第二世界根、发布后读回不符、撤销失败。
- 发布前失败按参与者确认逆序撤销；无法证明前态时隔离。
- 发布后异常不撤销已经发布事实，固定代次和请求身份进入审计/恢复。
- 恢复只消费已验证持久证据，在隔离候选中重建世界结构和全部类型化记录后一次发布；世界引导服务只调用 4070 恢复服务，不直接查询 SQL。

持久证据采用 4040 的“写前准备 + 发布后见证”策略：

1. 第一笔内存候选前，L1 持久端口用幂等身份、请求意图摘要、执行证据摘要和写集写入并读回 `已准备` 证据；SQL/材料不可用时返回资源失败、零内存写入。
2. 内存最后发布、代次推进和操作读回完成后，追写发布代次、结果摘要和一致见证。追写未知不撤销已发布事实，结果仍为已提交并携带 `持久化结果未知`。
3. 启动恢复只接受完整且互证的发布见证。只有准备证据而没有可验证发布见证时返回 `发布未知` 并阻止普通入口，不能猜测事务是否发生。
4. 普通读取永不查询 SQL；持久状态只说明恢复证据，不参与当前事实裁决。发布见证结果只单调更新内存非权威侧账，幂等业务记录保持不可变。

持久材料格式 1 使用函数确认冻结的 variant 标签和网络字节序；单事务材料最多 `67,108,864` 字节，任一 vector 最多 `1,048,576` 项。解码必须在分配前完成 SQL `DATALENGTH`、U64 到 `size_t`、最小剩余字节和乘加溢出检查；任何超限或尾随材料均判持久证据损坏并保持隔离。新请求编码超限则入口拒绝且零写入。`SQL节点直接持久证据适配` 同一实例实现写入和恢复端口，只借用 `SQL数据库适配` 配置且不保存长期连接；普通业务查询无此依赖。
