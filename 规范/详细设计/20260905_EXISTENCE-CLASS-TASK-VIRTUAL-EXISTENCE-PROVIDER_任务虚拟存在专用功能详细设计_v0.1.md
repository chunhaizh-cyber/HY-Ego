# 任务虚拟存在专用功能详细设计

日期：2026-09-05

版本：v0.1

身份：`EXISTENCE-CLASS-TASK-VIRTUAL-EXISTENCE-PROVIDER`

状态：设计已冻结，等待代码实施

## 1. 目标与边界

在既有`海中鱼巣/领域/数据服务.存在类.ixx`中新增任务虚拟存在Vt的专用结构规格形成
与读回能力，供直接后继任务类使用。Vt仍属于ARCH-L4 task owner：

```text
任务T（task owner当前普通节点）
-> 一条task owner的T→Vt专用关系
-> Vt（task owner新普通节点）
```

本提供者不得调用`存在类数据服务::新增存在`，不得使用或提交存在类世界owner写端口，
不得返回`存在类结点`，不得把Vt加入世界存在族、子存在组、世界树或世界状态/动态。
它只提供任务owner写集的确定规格与专用值式读回，不建立Vt首态、任务轮次或完整任务治理。

## 2. 安全端口裁决

L1 owner写端口是不可复制能力，4030禁止结构服务借用、转签或交换其它owner端口。因此
不存在类函数接收`L1所有者范围写端口&`，也不由存在类替task owner提交。

采用以下机械替代：存在类公开函数只接收task owner身份、任务节点、Vt关系类型、G0和
写入幂等身份，读取L1公开事实后返回一份调用方拥有、无写权限的
`L1所有者范围写集请求`规格；任务类用自己私有持有的task owner端口恰一次提交，并再
调用本提供者专用读回。写集本身不是能力、候选事实或发布结果，不能脱离匹配task owner
端口生效。

## 3. 物理位置、依赖与白名单

只修改现有真实模块：

```text
文件：海中鱼巣/领域/数据服务.存在类.ixx
模块：海中鱼巣.领域.数据服务.存在类
工程：既有ClCompile登记不变
```

新增DTO位于既有存在类DTO之后、`存在类数据服务`之前；两个成员函数位于构造器之后、
普通`新增存在`之前。它们只使用当前模块已公开导入的L1类型。

L1白名单固定为：`读取中性当前事实代次`、`读取当前结构所有者`、
`读取所有者范围当前节点`、`读取所有者范围当前源关系组`、
`尝试读取所有者范围一致当前投影`。零L1写调用、零普通存在函数调用、零旧`服务.L2*`。

## 4. 公开 DTO

```cpp
inline constexpr std::uint32_t 任务虚拟存在专用合同版本 = 1;

enum class 任务虚拟存在专用状态 : std::uint8_t {
    已形成写集=1,
    已读取=2,
    未初始化=3,
    已初始化=4,
    入口拒绝=5,
    任务所有者未找到=6,
    任务所有者已退出=7,
    任务节点未找到=8,
    任务节点已退出=9,
    关系类型未找到=10,
    关系类型已退出=11,
    所有者不匹配=12,
    结构冲突=13,
    事实代次漂移=14,
    资源失败=15,
    内部不一致=16
};

struct 任务虚拟存在写集规格请求 final {
    std::uint32_t 合同版本 = 任务虚拟存在专用合同版本;
    std::uint64_t 期望事实代次 = 0;
    L1结构所有者身份 任务所有者;
    L1所有者范围写入幂等身份 写入幂等身份;
    稳定编码 任务节点{};
    稳定编码 任务虚拟存在关系类型{};
};

struct 任务虚拟存在查询请求 final {
    std::uint32_t 合同版本 = 任务虚拟存在专用合同版本;
    std::uint64_t 期望事实代次 = 0;
    L1结构所有者身份 任务所有者;
    稳定编码 任务节点{};
    稳定编码 任务虚拟存在关系类型{};
};

struct 任务虚拟存在投影 final {
    稳定编码 任务节点{};
    稳定编码 虚拟存在节点{};
    稳定编码 任务虚拟存在关系{};
    std::uint64_t 创建事实代次 = 0;
};

struct 任务虚拟存在写集规格结果 final {
    任务虚拟存在专用状态 状态 = 任务虚拟存在专用状态::入口拒绝;
    std::uint32_t 合同版本 = 任务虚拟存在专用合同版本;
    std::uint64_t 事实代次 = 0;
    L1结构所有者身份 任务所有者;
    L1所有者范围写入幂等身份 写入幂等身份;
    std::optional<L1所有者范围写集请求> 写集;
    bool 成功() const noexcept;
};

struct 任务虚拟存在查询结果 final {
    任务虚拟存在专用状态 状态 = 任务虚拟存在专用状态::入口拒绝;
    std::uint32_t 合同版本 = 任务虚拟存在专用合同版本;
    std::uint64_t 事实代次 = 0;
    L1结构所有者身份 任务所有者;
    std::optional<任务虚拟存在投影> 投影;
    bool 成功() const noexcept;
};
```

全部DTO默认相等。规格结果成功只接受`已形成写集`，要求G0、owner、幂等身份及唯一完整
写集；查询结果成功只接受`已读取`，要求G0、owner和完整投影。其它状态零写集/零投影。

固定本地键：Vt节点`1`、T→Vt关系`2`。写集必须严格为一个普通无属性节点和一条角色0
关系：源为既有任务节点稳定编码，目标为本地键1，类型为请求关系类型稳定编码；值、
属性槽变更和退出事实均为空。

## 5. 公开函数

```cpp
任务虚拟存在写集规格结果 形成任务虚拟存在写集规格(
    const 任务虚拟存在写集规格请求& 请求) const;

任务虚拟存在查询结果 查询任务虚拟存在(
    const 任务虚拟存在查询请求& 请求) const;
```

二者均为`存在类数据服务`公开const成员、类内定义，诊断责任为向上送出。允许新任务类
调用；禁止旧L2、普通存在消费者、DATA-L1/L2反向调用。新增理由是当前不存在不借用
task owner端口、又能冻结Vt专用结构形状的公开提供者。

## 6. 形成规格

请求版本、G0、owner、幂等身份、任务节点和关系类型必须有效。函数在G0完成：

1. 当前代次等于G0；task owner当前存在、未退出且为独占结构范围。
2. 任务节点和关系类型均为该owner当前普通节点；关系类型无属性类型和当前属性。
3. 调用`查询任务虚拟存在`。已读取映射`已初始化`，未初始化才继续；其它状态原样传播。
4. 形成固定一节点一关系写集，合同版本为L1 owner-scoped版本、期望代次为G0、写入幂等
   身份原样取请求。
5. 再读当前代次仍为G0后返回。全程零写，任何异常映射资源失败或内部不一致。

## 7. 专用读回

查询先校验owner、任务节点和关系类型，再在G0读取T的该类型当前源关系组：

- 零条返回`未初始化`；
- 多于一条返回`结构冲突`；
- 一条时取得关系和Vt目标编码，再用owner一致当前投影读取owner、T、Vt和关系。

T、Vt、关系类型必须同属请求task owner且当前；T和Vt都是普通节点、无属性类型和当前
属性；关系必须由task owner创建、源T、目标Vt、类型吻合、角色0、无退出，Vt和关系创建
代次相同且非零。前后当前代次都必须为G0。成功返回专用投影；不得调用普通`查询存在`。

## 8. 失败、所有权与声明

- 未找到/已退出按owner、任务节点、关系类型分别映射；错owner为`所有者不匹配`。
- 零关系不是失败，返回`未初始化`；多关系或形状矛盾为`结构冲突`。
- 本提供者不读取首次写入材料、不提交、不解释幂等结果。精确重复、幂等冲突、发布未知
  和提交后读回全部由持有task owner端口的任务类负责。
- 本提供者没有锁，不跨L1调用持锁，不返回端口、仓库对象、可变引用或普通存在结点。
- 本代码结果只证明Vt规格与专用读回源码形成，不证明正式任务核心、Vt首态、轮次、
  世界存在、生产消费者、编译运行、恢复或验收。
