日期：2026-10-23；版本：v0.1；代码核对基线：`dd641ea1e5d0ab05bf12b063e307b4d3ec7be873`。

性质：创建侧合同已冻结、待根窗口审查登记，未批准施工、未证明实现。本文不替代正式规范。

## 1. 目标与用户最新裁决

需求特征当前值直接引用一个具体需求节点D；历史不同值是需求节点引用的历史集合。不是当前值引用U64数组材料，也不是把多个D打包成一个当前集合值。需求、任务、方法身份保持独立，本次不外推任务和方法特征。

所有添加值、设置当前及维护历史必须由`新_特征类`完成。调用方不得修改其底层字段。现有`添加特征值`首次出现新值即纳入历史不同值，当前值须能在历史中找到，因此历史不同值不是严格排除当前值的时间队列；保留该既有通用行为，不新造第二套观察历史。

业务修改对象是现实认知场景内服务对象的需求特征，目的为使已理解的具体需求可被正式读取；不是修改任务Vm/Vt。底层提供者本身只实现信息结构，不建立业务动作或虚构状态、动态、因果。后继业务发布须由世界组合服务依据实际变化形成记录。

## 3. 最早提供者叶合同

本节是创建侧已冻结的施工合同；根窗口复核和计划登记完成前不是施工入口，也不是当前能力。

### 3.1 类型与范围

`概念_特征类.h`在已有枚举末尾追加`特征概念材料物理类型::需求节点引用`和`特征概念比较规则::需求身份精确`，旧值不重排。准确值仍使用`variant<int64_t, 稳定编码>`，该分支必须为稳定编码。编码定位D，不交给2100完整材料读取。

该物理类型合法域只允许既有`特征概念全材料值域`和`vector<稳定编码>`：前者表示全部合法D，后者表示有限合法D身份集合，不能把向量解释为完整材料身份或数值区间。空有限域不等于全部合法D。成员必须由需求owner校验；任务、方法、Vm、Vt、条件节点、普通存在、集合材料全部拒绝。根定义、同域复用、严格子域和比较须使用这一类型分支；同域复用根，严格缩小才建子概念。

新类型定义的聚合规则为`不自动聚合`，不执行数值连续归组、不分裂子特征；历史不同值和命中按特征owner保留。概念选择允许在同类型全域和有限域内匹配，不以节点编码数值排序赋予距离或区间含义。

此叶不自动建立先天“需求”类型根、不改旧“服务对象需求集合”根；因此不触发生产装配和存量迁移。后继根定义按本合同建立，不改旧根原义。

### 3.2 owner读取接口

保留既有`特征需求成员读取接口::读取需求集合成员身份`和旧集合消费者。新增：

```cpp
struct 特征需求引用读取结果 final {
    特征概念规则状态 状态 = 特征概念规则状态::入口拒绝;
    std::optional<特征需求成员身份> 身份;
    std::vector<基础联合节点快照> 身份保护;
};
// 声明在概念_特征类.h，默认返回读取接口未装配，零身份/零保护。
virtual 特征需求引用读取结果 读取需求节点引用身份(稳定编码) const noexcept;
```

`新_需求类.h/.cpp`覆盖该函数；实现按已有`校验集合成员需求身份`的冻结schema读取同一次L1结构快照并返回强类型D、主体及执行域投影，附D身份和参与身份判断的节点快照。读取不写需求、不制造确认、不取得需求治理锁后反入特征锁。正常无D、类型错误、未装配、前提变化、资源失败分别沿现有规则状态返回。内部结构损坏走工程错误链，不能伪装D不存在。

`新_特征类`新增`void 装配需求引用读取接口(const 特征需求成员读取接口*) noexcept;`，仅线程启动前装配，join后解绑。概念owner沿既有`装配需求成员读取接口`读取新能力，不新建需求仓。装配顺序与寿命由后继生产装配负责；本叶默认未装配时拒绝新类型操作，不影响旧路径。

### 3.3 特征写入与联合发布

在`新_特征类.h/.cpp`新增move-only `新特征需求引用更新准备`，与存在引用准备一样通过私有实现和RAII持有同线程保护；准备未提交退出即取消，已提交退出不能撤销已发布事实。公开入口：

```cpp
struct 新特征需求引用准备结果 final {
    新特征I64准备状态 状态 = 新特征I64准备状态::入口拒绝;
    std::optional<新特征需求引用更新准备> 准备;
};
新特征需求引用准备结果 准备顶层需求引用更新(稳定编码 F, 稳定编码 D) noexcept;
新特征I64提交结果 提交顶层需求引用更新(
    新特征需求引用更新准备&, const std::vector<基础封存追加片段>&) noexcept;
新特征值添加结果 完成顶层需求引用更新(新特征需求引用更新准备&) noexcept;
void 结束顶层需求引用更新(新特征需求引用更新准备&) noexcept;
void 取消顶层需求引用更新(新特征需求引用更新准备&) noexcept;
```

准备完整捕获F版本、当前/标准/历史及新旧D身份快照；所有新出现D建立F到D的正式强引用保护字段。通用类型同时允许被认知和自我执行两种正式需求域，不把已确认、可承接、主体属于服务对象等业务条件塞进类型根。提交把当前值、历史命中/标准值、保护和调用方追加片段在同一个L1事务发布；调用方不能先改F再补需求来源。完成只做现有owner算法的归组及完整读回；不能二次写业务当前值。取消不产生观察次数。重复添加仍遵循既有添加值次数语义；业务幂等由后继发布服务在调用前判定。

`添加特征值(F, 新特征准确值{D})`对新类型委派同一准备/提交/完成链；建立特征、获取特征、比较特征、按概念比较特征值、值域包含/相等及历史归组都识别新分支。不得保留一条无保护的直接添加旁路。

`建立特征强类型`现行实现只建立类型、概念、可选单位及概念实例引用，传入实际值用于概念选择，不写当前值/历史值。本叶保持该职责：可先建立尚未采用的空F；D写入仅经`添加特征值`或需求引用更新准备链。空F没有D值，因而不需要伪造D保护或新增“创建F同时写初始D”事务。不得把空F返回当作已经发表了需求事实。存在采用、初次状态/动作/来源共同发表的顺序由后继业务发布合同明确，本叶不扩张F建立职责。

### 3.4 比较与生命周期

比较只在相同FT语义内，合法同D为相等、异D为不等；不对编码求差，不用内容相等代替身份相等。需求目标或状态读取由需求服务完成，引用不变不表示内容不变。全域、有限集的包含交并规则按集合身份计算，先校验节点类别，不能从整数范围判断。

保护至少覆盖F当前、标准及历史不同值中所有D；三者去重后建立一份F来源保护。F退出须在同一退出准备中解除自身保护，不能解除其他F、状态、动态或业务来源的保护。D不能因当前值切换就被回收。旧需求集合材料的保护不得被本叶删除。任何清理入口必须遵守L1入向引用检查；无公共D删除入口不是忽略保护的理由。定义域显式D引用同样以正式字段保护D，不能仅在序列化数组里藏编码。

保护schema冻结如下，不复用存在集合保护键，也不增加通用引用管理器：

| 键与唯一owner | 物理字段形状 | 写入、读回和退出 |
| --- | --- | --- |
| `需求引用保护键`；概念_特征类初始化、公开`稳定编码 需求引用保护字段() const noexcept;` | 已成立需求单引用F到D，内容为稳定编码；每F每D至多一条 | 特征owner在写值同一追加事务中建立；获取特征校验当前/标准/历史D均被保护，且无不相关D字段；F清理准备只允许移除此F持有的该键字段，与F退出同一L1事务 |
| `需求域引用保护键`；同一初始化owner、公开`稳定编码 需求域引用保护字段() const noexcept;` | 新类型的有限域概念FC到D，内容为稳定编码；每FC每D至多一条 | 概念owner在概念成立/域更新同一L1事务中建立或精确替换；读取概念核对有限域D集合与字段目标集合相等；概念退出在既有引用门禁通过后，仅移除此FC自有域保护 |

两个键在`概念_特征类.cpp`的schema全局声明、`结构已初始化`、`结构仍存在`及`初始化`的既有建立链同步登记。getter仅返回初始化所得稳定身份，不另设可写公开setter。字段身份存在于概念owner已有schema结构中；F及FC保护字段的实际入向端点为D，故底层删除D自然受L1入向字段关系检查阻止。概念域更新必须先取得全部新D身份快照，再通过既有基础原子封存接口将域内容和保护字段差异一次发布；不使用先写域再加保护的顺序调用。全材料域没有具体D端点，因此没有域成员保护字段。历史聚合若形成有限D域概念，同样走此唯一概念owner路径。

锁与准备次序固定为既有特征更新链：特征owner保护F，需求reader只读取L1冻结schema快照、不取需求业务锁；概念比较只读。L1提交共同核验F和D快照，变化时返回前提变化并零写。不得在持有需求业务锁时回调特征添加。结果读取缺D或身份变化不是编码相等，必须停止比较/更新并按已有状态返回。

## 4. 后继整体迁移路线（本叶不施工）

1. 核对先天FT命名和旧类型引用，建立新“需求”单引用类型，不原地改旧根材料解释。
2. 世界组合服务增加需求单引用的准备/提交/完成与动态发布；需求来源封存片段和F更新同事务，动作在条件复核后记录，关联实际变化。
3. 需求发布服务新增当前/历史读取投影，保留D主体、认知来源及幂等。再发布已历史发布D是否应切回当前须在业务合同明确，不能凭幂等旧接口猜。
4. 第五参数改为“特征＝需求”，执行读取当前D；查询历史显式遍历历史不同值，通过需求owner读取内容。不能把历史全部当未满足服务需求。
5. 模拟输入增加隔离D定义及存在/目标/值引用位置，单向复制并重映射闭包。无来源时按正式需求构成生成，不能调用现实被认知D建立函数伪造确认来源；具体隔离owner合同待后继冻结。
6. C/R结果只由原方法实际写回生成，不把模拟输入直接冒充输出。清理先解除模拟引用，再释放本地D和F，现实材料零改写。
7. 旧集合有唯一实际发布序列、动作/状态来源可追溯时恢复最新当前及去重历史。空集合保持未知/无需求，不能用编码0伪D；多项无可靠先后证据保留旧材料并报告，不挑首项。

## 5. 设计冻结与后继边界

准备结果复用现有`新特征I64准备状态`、提交回执复用`新特征I64提交结果`；保护schema、owner、建立/更新/退出时序已由第3节冻结。空F建立不承担初值写入，因此没有额外首次F事务待选择。提供者无剩余需要执行者裁决的机器语义；仍待根窗口审查本合同和正式计划登记，不因文档完成自动取得代码施工权。

更后业务门禁包括旧集合当前值恢复依据、历史D再发布的当前切换语义、模拟D合法认知来源与本地owner读取合同、生产FT根初始化/方法固定规格迁移；它们不是可让执行者现场补设计的小参数。无需为底层提供者先解决所有后继问题，但不得把提供者编译成功写成学习已修复。
