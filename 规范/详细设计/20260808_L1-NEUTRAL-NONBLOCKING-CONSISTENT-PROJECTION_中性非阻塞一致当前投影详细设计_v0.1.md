# 中性非阻塞一致当前投影详细设计 v0.1

日期：2026-08-08

状态：创建侧设计；待登记；代码未实施

创建侧正式基线：`main == origin/main == 5df9ff8aeb2fa0fe4b074111074abef3a99c272c`

## 1. 最早缺口裁决

当前中性节点、关系、值、属性及源/目标关系条件组入口均分别取得阻塞式共享锁。首末调用`读取中性当前事实代次`只能发现事实代次漂移，不能证明中间读取不等待；该代次入口又把底层许可拒绝映射为资源失败，并在 try-lock 成功后调用`状态完整(状态_)`执行全仓扫描。

现行普通领域路径已经真实出现两类问题：

1. `L1方法登记根当前读取服务`依赖 P17 非阻塞完整快照，因此能区分许可拒绝；直接换成阻塞单项读取会无版本改变地破坏现行服务语义。
2. 状态、动态、特征比较和后继状态组合仍以完整快照或多次阻塞单项读取取得已知节点、关系、值、属性及源/目标关系条件组；继续用 P17 会保留全仓复制，逐项替换又不能形成一次许可内的共同截止。

因此本叶建立一个业务中性、指定代次、一次共享 try-lock 的一致当前选择批次。选择器统一覆盖本轮现行消费者已经使用的当前节点、关系、值、属性所指当前值，以及源/目标关系条件组与对端节点；不加入业务字段、全仓选择、永久占用、审计或恢复。

历史事实依 4015 必须与当前读取显式分离。本叶可用项目`已退出`证明指定编码在当前批次时已经退出，但不返回历史事实正文；状态、动态和后继状态仍需另立非阻塞历史批次或具名迁移裁决。该缺口明确保留，不用当前 provider 混合历史语义。

## 2. 正式依据与消费者扫描矩阵

- 4015 §4：当前、历史、审计和恢复入口显式分离；组合当前读取必须共享事实代次。
- 4015 §5：普通 CRUD 只访问请求编码及必要索引，不固定执行完整快照、全仓扫描、审计或恢复材料组装。
- 4015 §6：第一层不设独立自证门；能力只由第二至第五层为完成自身服务而真实调用后累计证明。
- 4030/4050：L1 只返回中性不可变事实和结构化状态；领域资格与结果解释留给消费者。

| 现行普通路径 | 已确认当前读取需求 | 本合同选择器 | 未纳入本叶 |
| --- | --- | --- | --- |
| 方法登记根当前读取 | 三个已知节点；根的具名属性槽及其当前值 | 节点、属性值 | 无 |
| 状态服务 | 已知节点/关系/值；源/目标关系条件组；由关系发现的对端节点 | 节点、关系、值、源关系组、目标关系组及对端节点 | 已退出事实正文 |
| 动态服务 | 已知节点/关系/值；部分当前或历史回读；完整快照中的具名当前事实 | 节点、关系、值 | 已退出事实正文 |
| 特征比较服务 | 已知节点/值；具名属性；源关系条件组及目标节点 | 节点、值、属性值、源关系组及对端节点 | 无 |
| 后继状态规格组合 | 已知节点/关系/值当前副本；不存在时历史副本 | 节点、关系、值 | 已退出事实正文 |

核心索引的完整快照重建、审计、恢复导出与恢复候选属于管理面，不迁移到本入口。

## 6. 仓库内部传输与唯一转换

仓库模块内新增嵌套值式`一致当前读取内部结果`及内部项目，只使用现有`节点事实/关系事实/值事实/L1事实副本`深复制和公共项目状态，不含引用、指针、迭代器或锁。它只供`L1事实基座服务`导入消费，不从服务模块 re-export。

仓库完成 try-lock、局部查找和 legacy 副本形成后先释放锁。服务在锁外：

1. 顶层非成功只形成同名公开空结果；
2. 顶层成功逐项验证内部事实 variant 与请求种类一致；
3. 复用现有唯一`转换中性节点/关系/值/事实`生成全部公开项目；
4. 分配失败返回公开资源失败，其它转换矛盾返回内部不一致，六组全空、代次 0。

不得在仓库新增另一套中性转换器，也不得把 legacy DTO 暴露给 L2—L5。

## 7. 入口、许可与事实代次

锁外验证版本、非零期望、非空选择、有效编码和组内唯一。失败入口拒绝，锁获取 0。

合法请求只执行一次：

```cpp
std::shared_lock<std::shared_mutex> 锁(锁_, std::try_to_lock);
```

- 未取得：立即许可拒绝；不 sleep、轮询、重试或回退阻塞锁。
- 取得后只直接读取`状态_.隔离`和`状态_.事实代次`；禁止调用`尝试读取当前事实代次`、`状态完整`或`构造快照`。
- 隔离或零代次：内部不一致。
- 当前代次不等于请求期望：事实代次漂移并回显实际非零代次，六组空。
- 相等后才按请求范围形成内部结果。

非阻塞只冻结许可取得不等待；锁内复制仍消耗与请求项、命中关系成员及被复制节点属性槽数量相称的 CPU/内存，但不得扫描全仓。

## 8. 请求范围读取算法

### 8.1 具名节点、关系和值

按请求顺序从对应当前表精确查找。命中时校验表键、编码、创建/退出代次和事实种类局部结构：

- 当前节点的种类与`属性类型表示`形状一致；每个返回槽的属性类型严格唯一，槽和值编码有效；槽指向的属性类型节点当前存在且种类为属性类型，槽指向值当前存在并绑定本节点和该属性类型，材料 variant 与属性类型表示一致。
- 当前关系的源节点、目标节点和关系类型节点都当前存在；关系类型节点为普通节点、无属性类型表示；关系端点、角色/顺序和生命周期有效。
- 当前值的所属节点、来源节点和属性类型节点都当前存在；属性类型节点种类为属性类型；其`属性类型表示`与材料 variant 精确对应：I64、I64组、U64组或独立材料引用。

上述验证只跟随被返回事实直接引用的节点、槽和值，不继续递归解释这些节点的业务拓扑。命中后复制 legacy 事实，项目成功。

对应当前表未命中时：同编码若在其它当前事实表，或历史事实种类与请求种类不同，项目种类不匹配；历史中存在同种事实则已退出；否则未找到。非成功事实空。

节点副本的当前属性槽会按上一段校验其直接属性类型和值绑定，但不把全部槽值正文自动加入公开结果；只有`属性值`选择器返回一个具名槽的完整当前值事实。

### 8.2 属性值

节点不存在、已退出或种类不匹配按项目状态分账；节点存在而没有该属性槽返回属性未设置。唯一槽存在时，槽必须有效，当前值必须在当前值表；所属节点和来源节点必须当前存在；属性类型节点必须当前存在、种类为属性类型，且其表示与值材料 variant 一致；值编码、所属、属性类型、来源和生命周期均须完整。随后同时复制槽和值事实。重复槽、悬空值或任一绑定矛盾使顶层内部不一致。

### 8.3 源/目标关系条件组

复用现有`当前源关系索引/当前目标关系索引`作为候选，不遍历全关系表。索引无键返回合法空组。命中时候选编码必须非空、严格升序；逐项回读当前关系表并校验查询方向、生命周期、源/目标节点当前存在，以及关系类型节点当前存在、为普通节点且无属性类型表示；再复制关系与相应对端节点。返回的对端节点继续按第 8.1 节节点局部结构校验。

空关系组只表示该锚点+关系类型在当前候选索引下没有成员，不证明锚点或关系类型节点存在。调用方若需区分“合法空组”和锚点/类型缺失，必须把相应锚点和关系类型节点同时列入本请求的`节点`选择，并解释同批次节点项目；L1 不在空组路径补造业务资格。

候选重复、悬空、方向/类型错、关系或对端节点局部不完整使顶层内部不一致。索引只提供候选，结果事实均从当前权威表复制；不得把索引项直接作为事实返回。

## 9. 零写、禁止入口与历史后继

全路径零写：不推进代次、不改变隔离、不分配稳定编码、不提交写集、不改幂等账、不建缓存/索引、不写日志机器事实。

新仓库根禁止：

```text
尝试读取当前事实代次 / 状态完整 / 构造快照
遍历全部当前节点、关系、值、永久占用或历史事实
读取历史事实正文、审计、恢复、SQL、材料或日志
任何提交、候选、事务、编码分配或写入口
```

历史后继缺口：为状态、动态和后继状态提供按已知编码、指定截止、业务中性的历史事实批次；它必须保持当前/历史入口分离，并按历史生命周期与请求截止裁决。该后继不是本计划的隐含代码范围，也不妨碍本 provider 承接现行全部“当前”选择需求。
