# 存在与存在概念绑定创建详细设计

身份：EXISTENCE-BOUND-CREATION；版本：v0.3；日期：2026-09-12。

## 1. 目标、基线与完成边界

用户裁决：普通存在或普通存在概念只有在创建请求已经明确合法绑定节点时才能增加新节点；任何绑定失败都保持零新身份、零写入并触发统一调试诊断。缺少绑定属于入口拒绝类别，普通存在服务用专用机器状态`绑定未明确`表达；无效、已退出、错类、错树、漂移和技术失败保留各自精确结构化状态。诊断开关只控制人读输出，不能改变机器拒绝。

原设计基线为 `1ef90704545d72feb77dbb789950f2b737b5e489`；执行S0已在前序结果 `95ee472364ecaead26628f4fa48c2e4b03313073` 重扫。正式依据为 1140 v1.4、7100 v1.5、7110 v1.6、7140 v1.9、7150 v0.8、0300 C044、0050、4015、4202、4203、4204、4230及日志系统规范。

本设计交付普通存在的绑定原子创建、世界树两个创建消费者迁移，以及存在概念新旧创建入口的绑定诊断。固定系统结构初始化继续走既有具名登记入口，不进入普通创建合同。概念归类、特征创建、已有节点移动、批量迁移、跨进程恢复和正式集成验收不在范围。

`FEATURE-PARENT-BOUND-CREATION` 已由 `d47f70b95dbab60194dbab76b03ba8c5eec6344b` 发布并在 `95ee472364ecaead26628f4fa48c2e4b03313073` 关闭。本计划以该正式结果为直接起点；定位特征private参与者保持独立，不能被本计划复用或改变。

## 3. 绑定语义

### 3.1 普通存在

`存在初始绑定`固定包含`种类`和非零`绑定节点`。种类只有：

1. `父存在组成`：绑定节点为当前普通存在，建立`父存在 -> 新E`组成关系；
2. `场景成员`：绑定节点为当前场景，建立`场景 -> 新E`直接成员关系；
3. `直接子场景`：绑定节点为当前父场景，新E同时取得完整场景角色和四根，并建立`父场景 -> 新E`直接子场景关系。

三类都须在请求G0下核验绑定节点、存在族/场景角色、现实树位置、联合唯一和无环。绑定节点不能等于待分配的新E，不能使用存在族锚点、关系类型节点或本体根冒充业务位置。未明确绑定指种类不在枚举内、绑定编码无效或请求缺少该值；这三种都先触发同一诊断，再返回`绑定未明确`。

### 3.2 普通存在概念

普通存在概念的绑定就是请求中至少一个`直接上位`。每个上位必须为当前有效存在概念，全部位于存在本体根、无重复且不会成环。空组为`绑定未明确`；无效、已退出、错根或无法完成同截止核验分别映射为现有结构化失败状态，同时触发同一类绑定诊断。数据服务不得为空组自动补`存在概念根`。

存在概念根及其它本体根由固定系统初始化入口建立；存在族锚点与结构类型由存在结构登记入口建立。这些封闭引导不接受普通创建DTO，也不提供可选择的“无绑定”枚举。

全部键复用现行`L1所有者范围写入幂等身份`。父存在组成只接受单所有者键；场景成员和直接子场景只接受三键，且组合、存在、场景键均非零并互异。`期望现实树根`对三类普通创建都必须非零：父存在组成核验绑定父经联合归属递归可达该根；场景成员核验目标场景属于该根；直接子场景核验父场景属于该根。绑定种类与键变体不匹配时入口拒绝，不能忽略多余键或把同一请求改走另一事务。

`存在绑定出生见证`对三类均要求存在身份、存在族归属关系完整且创建H不晚于见证H；仅父存在组成要求`组成绑定关系`存在并与请求父、新E、角色1互证，其余两类要求为空。`场景绑定出生见证`只用于场景两类：场景成员要求`子场景结构`为空；直接子场景要求其存在，且其中场景角色、新E、四根、根边、现实树根与父场景路径完整互证。全部节点/关系的owner、创建H及可选退出H由上述具体事实类型承载。参与者结果成功只允许`状态=精确重复`作为内部“已读取”映射、`Gread/H`精确相等且见证完整；预算不足不截断。

具体类只公开继承接口，不公开写端口getter。`绑定存在结构已就绪`只核对本owner本计划所需的现行登记交付与首次材料；`绑定存在幂等键可用`拒绝零、owner初始化键、已登记固定维护键及进程维护前缀，组合服务须逐键向对应owner询问，不能自行猜保留集合。两个provider借用只服务构造`直接归属联合只读组合器`，不暴露给普通调用方；场景参与者的`核验绑定现实树`用该组合器完成三类绑定路径至期望根的有界核验，成功返回`绑定现实树见证`，错树映射`绑定不在现实树`。

`绑定现实树见证`成功谓词固定为：Gread等于请求G0，两个编码分别等于请求绑定节点和期望根；`根角色`证明期望根的场景角色位置为`场景树根`且树根就是自身；上行路径按成员到父方向连续、无重复、每条在Gread当前有效。绑定节点等于期望根时路径必须为空；不等时路径必须非空，首项成员为绑定节点，末项父为期望根。根场景没有父边，不得伪造自归属或虚构直接关系。

构造核验两个参与者底座对象地址相同、端口有效、存在owner与场景owner均有效且互异、两个结构就绪谓词为真、两个窄provider均绑定同一底座；组合服务内部构造并持有`直接归属联合只读组合器`。失败抛`invalid_argument`且零写。组合服务仅持两个借用引用、联合只读组合器和一个串行互斥锁，不缓存事实，不持某参与者内部锁进入另一参与者；片段准备只读并返回值，所有跨owner锁定和发布由L1 v3承担。`FEATURE-PARENT-BOUND-CREATION`的定位特征private参与者仅服务特征事务，本模块不得继承、转换或复用它。

## 5. 事务与函数流程

### 5.1 `创建绑定存在`

1. 只检查不依赖事实读取的请求形状：版本、G0、预算、枚举、非零绑定编码、非零期望现实树根、键变体、键非零/互异、各owner`绑定存在幂等键可用`及`variant`未失效。缺绑定返回`绑定未明确`；缺期望根、保留键或其它形状错误返回`入口拒绝`。两者调用`追根因检查(false, L"普通存在创建前必须明确合法绑定节点及现实树根")`一次。
2. 在读取当前绑定前先读owner首次材料。父存在组成只读存在键；场景两类分别读存在键和场景键。读取结果必须回显合同版本、owner、原键和非零读取代次。
3. 首次材料全无才进入首次路径；此时各读取代次都必须等于请求G0。组合服务调用场景参与者`核验绑定现实树`，传入内部联合只读组合器，按G0核验绑定节点、生命周期、类型、绑定路径实际可达`期望现实树根`、联合唯一、预算和无环，再形成并提交写集。目标虽处于另一棵合法树仍返回`绑定不在现实树`并保持零写。任一核验失败在最终责任边界诊断一次，并保持对应精确结构化状态和零写。
4. 父存在组成的存在owner写集固定本地键：节点1为新普通E，关系2为`新E -> 存在族锚点`、既有存在族归属类型、角色1，关系3为`父E -> 新E`、既有子存在关系类型、角色1。它以请求`存在幂等身份`和`G0`调用单owner中性写集一次。
5. 场景两类的参与者1固定为存在owner：节点1为新普通E，关系2为存在族归属。场景成员的参与者2只有关系1：`绑定场景 -> {参与者1,本地节点1}`、既有直接存在成员关系类型、角色1。直接子场景的参与者2固定为四个根节点本地键1..4；关系5为`{参与者1,节点1} -> 场景族锚点`、角色1；关系6..9为新E到四根、既有根绑定关系类型、角色1..4；关系10为`新E -> 既有现实树根`、既有树归属关系类型、角色1；关系11为`父场景 -> 新E`、既有直接子场景关系类型、角色1。现实树根由父场景G0见证取得，不由请求猜测。参与者2只能后向引用参与者1的新E。
6. 两owner路径构造精确`L1有限N分区原子事务请求_v3{合同版本_v3,G0,组合幂等身份,{参与者1,参与者2}}`，由存在端口调用`提交有限N分区原子事务_v3(request,{&场景端口})`一次。参与者1/2的写集分别使用存在键/场景键，owner互异，均有实际变化。
7. 如果父存在组成首次材料存在，必须同时含首次规范化写集和成功首次写入结果；比较原请求G0、`存在组成绑定创建键::幂等身份`、上述固定写集和完整映射后，直接重送该首次规范化单owner写集。不得按当前父位置重新核验，也不得生成新G或新键。
8. 如果场景两类的两个首次材料都存在，首次H必须相同，分别完整比较参与者原始规范化片段、映射及原请求G0，然后重建同一个v3组合请求并重送。仅一个存在、H不同、材料缺项或映射不完整均为`内部不一致`，禁止补齐；片段不同为`幂等冲突`。重放不以当前场景路径重新裁决原始出生。
9. `已可能发布`只允许以完全相同的原请求、G0和键重试。提交结果确认后以首次H读原始出生见证，再以当前Gread读取当前位置。原始见证完整且当前绑定仍相同返回`已创建`或`精确重复`；原始见证完整但已被后续合法移动/退出覆盖返回`既有操作已被后继事实覆盖`；历史不可读、读取失败或事实矛盾保留精确非成功，不宣称回滚。

### 5.2 旧入口与世界树

`存在类新增请求`和公开`新增存在`物理删除；不存在无绑定兼容重载、默认父或自动根回退。存在类内部出生片段成为参与者private实现；其幂等重放比较纳入绑定组合请求的规范化写集。

世界树构造时以已有存在类和场景类构造`绑定存在数据服务`。两条创建公开DTO升级到v3并固定为：

```cpp
struct 世界树场景创建请求 final {
  std::uint32_t 版本 = 3;
  std::uint64_t G0 = 0;
  L1所有者范围写入幂等身份 组合幂等身份{}, 存在幂等身份{}, 场景幂等身份{};
  稳定编码 父场景{};
  世界树绑定创建预算 预算{};
};
struct 世界树存在创建请求 final {
  std::uint32_t 版本 = 3;
  std::uint64_t G0 = 0;
  L1所有者范围写入幂等身份 组合幂等身份{}, 存在幂等身份{}, 场景幂等身份{};
  稳定编码 目标场景{};
  世界树绑定创建预算 预算{};
};
```

`世界树绑定创建预算`是v3创建专用类型，精确包含`最大场景数量`、`最大关系数量`、`最大祖先数量`三个`uint64_t`字段，并逐字段机械映射为绑定预算；现有v2读取预算不变。`创建场景`传`直接子场景 + 父场景`，`创建存在`传`场景成员 + 目标场景`。旧`观察G0`、`存在创建期望G0`、`已固定第二阶段请求`、`续跑请求`以及两个创建进度结构物理退出。结果继续使用`世界树结果头`、原请求和最终投影，但创建请求/结果的合同版本为3；结果头增加`optional<绑定存在创建状态> 绑定原因`。

状态映射固定如下：`已创建`映射请求对应的世界树创建成功状态，`精确重复`映射同名状态，`入口拒绝/绑定未明确/绑定未找到/绑定已退出/绑定类型不符`映射`入口拒绝`，`绑定不在现实树`映射`场景不在现实树`，`包含冲突`映射`成员多重位置`，`成环`映射`形成场景环`，`事实代次漂移/幂等冲突/数量预算不足/历史材料已清理/资源失败/内部不一致/既有操作已被后继事实覆盖`映射世界树同名状态，`已可能发布`映射`已发布待复核`。每次均在`绑定原因`保留原绑定状态，不能仅凭世界树粗状态反推根因。原`部分已发布`不再由两个创建路径产生。

两个创建结果的成功谓词要求：请求/结果版本3、结果状态为对应创建成功或`精确重复`、阶段为`现实树最终确认`、`Gread != 0`、首次H存在且`G0 < H <= Gread`、原请求逐字段相等、无进度/续跑、绑定原因是`已创建`或`精确重复`、最终投影完整且与父/目标场景一致。其它世界树读取、移动DTO继续保持v2，不做全模块无关迁移。

世界树不能自行判断首次或重放，因此两条创建函数统一把自身`root_`写入`期望现实树根`后调用一次`创建绑定存在`。绑定服务按第5.1节先读首次账：有完整首次材料时直接执行原请求重放；全无首次材料时才在请求G0内确认绑定路径属于该根并创建。绑定服务成功后，世界树再按返回Gread做同一根最终确认；绑定服务返回非成功时直接映射，不另行发起创建。这样旧G重放可以进入账本收敛，首次创建也不会先在另一现实树发布。首次调用在`事实代次漂移`且确认没有首次材料时，可以用新G0和全新三键重建业务意图；已经进入提交、返回`已可能发布`或任一首次材料存在后，只能重送原请求，禁止换G0或换键。

### 5.3 存在概念诊断

概念树v2 `创建存在概念`和旧`创建概念`在普通存在概念分支进入现有验证前，分别对直接上位组执行`追根因检查(!组.empty(), L"普通存在概念创建前必须明确直接上位绑定节点")`。无效父、错根、退出父和核验失败的已有分支也在最终责任边界触发一次诊断并保持原结构化状态。应用服务继续显式传`{root_}`，不新增兜底。
