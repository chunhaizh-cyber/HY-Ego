# 十类信息的最小表达结构与用途清单

2026-11-22。适用范围为自然语言与场景、存在、特征、状态、动态、因果、二次特征、需求、任务和方法之间的双向转换。十类信息和表达用途来自用户本轮裁决。本文列出设计和施工输入，代码覆盖情况单列于末节。

## 1. 怎样确定一条最小表达

一条基础表达回答一个可以独立判断的问题。它指定所指的信息对象、要表达的谓项或关系，以及必要角色。去掉一个角色会改变所问对象、事实地位或成立条件时，必须保留该角色。角色可由当前语境唯一绑定，也可引用子表达。句中没说出的值按实际情况保留为未给出、待求或明确未知。

每条结构有两种表示。含义模板规定角色和约束。汉语模式规定固定词项、角色表达和子规则的顺序。多个模式可以映射到同一个含义模板。名称、数值和单位从相应角色取得。表中并列的谓项各自展开为独立结构。

## 2. 按信息类型取材的基础结构

| 信息类型 | 可以单独表达的内容 | 最小句例与必须保留的区别 |
| --- | --- | --- |
| 场景 | 场景与直接成员；子场景与直接父场景；状态或动态的发生场景 | “甲室里有设备乙。”“乙区是甲区的子场景。”“这次变化发生在甲室。”同一世界内分别读取成员、层级和发生场景。递归范围须明确。 |
| 存在 | 存在的概念归属；两个指称指向同一存在；部分与整体 | “乙是一个传感器。”“它就是乙。”“探头丙是乙的一部分。”“乙是传感器”中的类别不能与“它就是乙”中的对象身份互换。概念上下位可作为独立子表达。 |
| 特征 | 信息节点持有某类型的实例特征；该特征当前取值；该值满足某个类型化条件 | “设备乙有温度特征。”“设备乙的温度是20摄氏度。”“温度在指定范围内。”持有者、特征类型、实例特征分别绑定。存在特征而当前值未知也是可表达的信息。 |
| 状态 | 某个实例特征在某个确定时刻变化后的固定值或明确未知 | “10时的那次变化后，设备乙的温度为20摄氏度。”指定历史状态时由它取得特征、时刻和值。只问“现在多少”由特征读取当前值。 |
| 动态 | 同一特征从前状态到后状态；一次已发生动作及其目标；同一主题下多个原子变化组成的复合动态；有显式来源的动作与结果关联 | “设备乙的温度从20升到30摄氏度。”“甲执行了测温动作。”“这一过程包含升温和压力变化。”原子变化两端同属一个实例特征；各通道按实际时间组织。只陈述发生动作时可以没有已知结果。 |
| 因果 | 具体话语提出的原因与结果；正式因果规律中的条件和结果，以及已知时的动作角色 | “甲说这次断电导致了停机。”“依这条规律，在条件甲下执行动作乙，预期结果为丙。”前句保留说话者及其主张，后句读正式规律的角色、值域与来源。未知动作允许保留；现实中先后发生两件事不足以补出因果关系。 |
| 二次特征 | 对有序来源应用具名规则取得一个具名结果；在给定范围内判断该结果是否满足条件 | “这两次测温的温差为10摄氏度。”保留输入顺序、结果类型及角色、规则、单位与范围、真实阶次。每个正式结果是一个具名整数标量。可复算的临时结果与由状态或动态实际持有的结果分别取材。 |
| 需求 | 需求主体希望哪个目标信息节点的哪项特征达到什么值域或按哪个方向改变；已有需求中某个目标字段是否待补 | “甲需要水乙的温度达到40摄氏度。”“这项需求还缺目标值。”说话者、需求主体、目标节点分别绑定。目标40℃与实际温度20℃可以同时成立。 |
| 任务 | 任务对应的需求；它实际服务的需求；它的当前状态及已有正式材料的进度、结果 | “这项任务服务于需求甲。”“这项任务正在等待执行条件。”将两句合成时显式共指同一任务。任务对应需求、服务需求和当前状态分别读回。 |
| 方法 | 方法的动作和有序参数；适用分支所需条件；该条件下的预期结果；具名条件与结果的配对 | “方法甲需要条件乙。”“在条件乙下，用方法甲预期得到丙。”参数规格来自方法虚拟存在，条件和结果来自同一配对。预期、尝试和已取得的结果分别表达。 |

场景作为存在可复用存在结构；状态或动态持有二次特征时可复用特征持有结构。对同一对象的多个主张由既有含义网组合。取材依据见[场景](../1150_根规范_场景节点.md)、[存在](../1140_根规范_存在节点.md)、[特征](../1130_根规范_特征节点.md)、[状态](../1160_根规范_状态节点.md)、[动态](../1170_根规范_动态节点.md)、[因果](../1190_根规范_因果.md)、[二次特征](../1180_根规范_二次特征.md)、[需求](../3100_根规范_需求.md)、[任务](../3200_根规范_任务.md)和[方法](../3300_根规范_方法.md)。

## 3. 同一内容按用途生成表达

下表展示十类各一条主张及其两种问法。括号标明取材的限制。填项问把一个允许查询的强类型角色置为待求；确认问保留完整主张，询问其是否成立。回答可以有明确未知，必须保留原问题的角色、来源与作用域。表中的甲、乙、温度等都是可替换材料。

| 类型 | 陈述 | 填项问 | 确认问 |
| --- | --- | --- | --- |
| 场景 | 设备乙在甲室。 | 设备乙在哪个房间？ | 设备乙在甲室吗？ |
| 存在 | 乙是传感器。 | 乙属于哪一类设备？ | 乙是传感器吗？ |
| 特征 | 设备乙具有温度特征。 | 设备乙具有哪些特征？（枚举已知范围） | 设备乙具有温度特征吗？ |
| 状态 | 10时那次变化后温度为20摄氏度。 | 那次变化后温度是多少？ | 那次变化后的温度为20摄氏度吗？ |
| 动态 | 那次设备乙的温度从20升到30摄氏度。 | 那次设备乙的温度从20摄氏度升到了多少？ | 那次设备乙的温度是从20升到30摄氏度的吗？ |
| 因果 | 依规律甲，条件乙下动作丙的预期结果是丁。 | 依规律甲，在这些条件下执行丙，预期结果是什么？ | 依规律甲，在这些条件下执行丙，预期结果是丁吗？ |
| 二次特征 | 后一次与前一次测温的差值为10摄氏度。 | 后一次比前一次高多少摄氏度？（已知方向时） | 后一次与前一次的温差按此顺序为10摄氏度吗？ |
| 需求 | 甲希望水乙达到40摄氏度。 | 甲希望水乙达到多少摄氏度？ | 甲希望水乙达到40摄氏度吗？ |
| 任务 | 任务甲在等待执行条件。 | 任务甲当前处于什么状态？ | 任务甲在等待执行条件吗？ |
| 方法 | 在条件甲下，方法乙的预期结果为丙。 | 在条件甲下，方法乙的预期结果是什么？ | 在条件甲下，方法乙的预期结果是丙吗？ |

**提出需求**有不同内容，必须限定受请求者及所求目标。

- 请求告知可以嵌入各类查询，如“请告诉我任务甲当前的状态”。它要求取材和告知。
- 请求执行引用已知动作及必要参数，如“请用方法乙测量设备甲的温度”。理解该句可形成请求材料。实际承接、执行和结果由任务与方法的所属服务记录。
- 请求达成引用目标，如“请把水乙的温度提高到40摄氏度”。对于历史状态、动态和因果，可以请求查询、解释或取得证据。任何实际变更仍须有可执行动作及合适的目标。
- 招呼按语言场景的交往用途独立处理。否定、条件、引述、量化以及并列、时间顺序、因果、目的等组合按既有作用域作用于内容。回应关联其被回应项。例如“甲说设备在室内吗”需区分是在确认甲是否说过，还是甲在引语中询问位置。

## 4. 双向实现与验收边界

1. 按含义操作、角色种类及来源把每个谓项映射到既有语言知识。陈述、查询变量、确认范围和请求角色分别编码。词面、标题及现实对象编号不参与业务分派。遇到含义重复的汉语模式，复用含义角色并保留各模式自己的语序、显式子规则映射。
2. 输入经正式解释器保存语言材料。输出从相应对象的正式读口取材，通过同一角色合同生成文本。独立回读检查对象、关系方向、单位、时刻、变量作用域、表达用途和事实地位。表达效果相同允许使用不同字词。
3. 每条可用结构分别记录正式源数据、输入解释、由正式信息成文和独立回读。换对象、换同类特征、换同义说法后继续核查。不足材料另记具体缺项，例如历史状态没有可定位时刻、调换二次特征的有序来源、任务指称有两个候选、请求执行缺少必要的参数。正式读口的工程故障单独报告。
4. 本清单核对基线为 `690c7abcb`。公开基线的[语言模型](../../海中鱼巣/领域/新_语言类.h)、[输入解释](../../海中鱼巣/业务/解释.基础语言.cpp)、[输出生成](../../海中鱼巣/业务/表达.基础语言.cpp)与[语言场景转换](../../海中鱼巣/业务/转换.语言场景基础.cpp)已有可复用入口。普通应用显式装载[语言知识种子](../../初始化材料/最小语言知识种子.txt)和[表达组织知识种子](../../初始化材料/表达组织知识种子.txt)。另放一个文件无法取得普通启动覆盖。
5. 词典学习工作树基于 `4715864b1` 的联合在制版本已记录七组原文中的第1、2、4、5、6组通过，覆盖具体例句。该树还有第3组的容量语言读回和第7组的任务材料及在制种子。其正式种子、初始化、含义模型、解释、表达和工程文件已有写入所有者。生产接线需由该所有者继续或在明确交接后按交付基线复核，通用能力按上一项逐条取证。本清单只交付表达结构设计，尚未登记可执行计划。
