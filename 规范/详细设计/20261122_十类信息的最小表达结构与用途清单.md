# 十类信息的最小表达结构与用途清单

2026-11-22。本次设计有两个入口。输入从一条自然语言消息出发，产出该消息所属语言场景的信息节点和带来源的含义。输出从自我按需求形成的正式表达需求信息出发，产出可回读的自然语言文本。场景、存在、特征、状态、动态、因果、二次特征、需求、任务和方法界定可谈论的内容。自我如何按需吸收语言场景信息留待后续设计。

## 1. 怎样确定一条最小表达

一条基础表达回答一个可以独立判断的问题。它指定所指的信息对象、要表达的谓项或关系，以及必要角色。去掉一个角色会改变所问对象、事实地位或成立条件时，必须保留该角色。角色可由当前语境唯一绑定，也可引用子表达。句中没说出的值按实际情况保留为未给出、待求或明确未知。

每条结构有两种表示。含义模板规定角色和约束。汉语模式规定固定词项、角色表达和子规则的顺序。多个模式可以映射到同一个含义模板。名称、数值和单位从相应角色取得。表中并列的谓项各自展开为独立结构。

### 1.1 自然语言转为语言场景中的信息节点

1. 从接收消息取得原文、语言、来源和可用的交互上下文。按来源消息建立或取得语言场景，记录每次语言出现的局部编号与原文范围。同一段文字出现两次时分别对齐；重读同一来源时复用已有记录。
2. 按语言知识识别用途、结构和各角色，把文字中给出的主体、属性、所述值、时间参照和关系组织为含义网。语境可用于解释“它”“现在”和省略项。所指仍有多个候选时保留候选与范围。问句保留待求角色或确认范围，即使系统已知答案也照原问保存。
3. 在来源语言场景保存已确定的内容及其与原文的对齐，使信息节点能按来源读回。完整唯一、多义、部分解释和缺规则分别记录。外层否定、条件或引述未定时，已识别的子句仍属于原来的范围。输入完成条件是可读回“谁说了什么、以何种用途、指称确定到哪一步”。陈述所指对象当前的实际取值可以与所述值不同。

依据见[语言场景与采用记录](../7231_子规范_句子解析与词出现字段.md)和[语言双向转换](../7240_子规范_自然语言双向转换与组织规则.md)。场景中的需求信息是“某人提出或描述了一项需求”的语言信息；即使没有对应的内部需求或任务，这项语言转换也有自己的完成条件。

### 1.2 正式表达需求信息转为自然语言

1. 入口接收已经形成的表达需求。它给出表达用途、要谈论的对象或内容、说话者与受话者，以及可用的来源关联、语言和上下文。触发自我表达的业务需求与这次要表达的内容分别绑定。例如自我为答复询问而报告任务状态，话语内容是任务状态。
2. 表达组织知识依用途选取必要材料，形成一份具体的、与语种无关的含义网。报告现状时，组织阶段从指定对象的正式读口取得相应字段；转述时使用指定来源的主张；提问时保留待求项。组织完成后，成文使用已组织的内容。缺少必需材料时返回缺项和未覆盖范围。
3. 按语种选择基础表达知识，把角色映射到词项、名称、指代、值或子表达，生成候选文本。用输入规则只读回读实际生成的文字，与表达需求要求的内容及组织结果核对。可接受的同义说法应保留对象、用途、来源立场、作用域、值、单位和时间。结果交付文本、所用知识及回读结果。送达由外设流程另行记录。

### 1.3 同一句状态描述在两个方向的绑定

“任务甲正在等待执行条件”使用**状态描述**结构，主体类型为任务，字段为任务的当前状态，所述值为“等待条件”，“正在”给出话语参照下的当前时间。这里的“状态描述”是语句结构；若表达需求指定的是一条历史状态记录，才按该记录取得实例特征、时刻和当时取值。

| 情形 | 主体和状态值从哪里来 | 转换完成时交付什么 |
| --- | --- | --- |
| 收到这句话 | “任务甲”和“等待执行条件”来自原文；语境只在指称可唯一恢复时绑定具体任务 | 语言场景里的一条状态陈述，带说话者、来源、任务指称、所述值和时间参照。即使正式任务值为“已完成”，仍保存原话所述的“等待条件”。 |
| 自我需要报告任务甲的当前状态 | 表达需求指定任务；组织阶段由任务所有者读回当前状态 | 读到“等待条件”时可以生成原例；读到“已完成”时生成相应的完成状态描述。两种值共用状态描述结构。 |
| 自我需要询问任务甲的当前状态 | 表达需求指定任务和字段，值位置是待求变量 | 可以生成“任务甲当前处于什么状态？”，并从回读中恢复同一任务、字段和待求项。 |

设计中的字段写法 `任务.当前状态` 表示带类型的字段含义。现有模式槽位保存局部标识，映射到含义角色。输入让“状态值”角色接收原文给出的值；输出在组织阶段按表达需求绑定所述值或待求项。字段编码的物理登记和存储方式仍以正式接口合同为准。

## 2. 按信息类型取材的基础结构

| 信息类型 | 可以单独表达的内容 | 最小句例与必须保留的区别 |
| --- | --- | --- |
| 场景 | 场景与直接成员；子场景与直接父场景；状态或动态的发生场景 | “甲室里有设备乙。”“乙区是甲区的子场景。”“这次变化发生在甲室。”同一世界内分别读取成员、层级和发生场景。递归范围须明确。 |
| 存在 | 存在的概念归属；两个指称指向同一存在；部分与整体 | “乙是一个传感器。”“它就是乙。”“探头丙是乙的一部分。”“乙是传感器”中的类别不能与“它就是乙”中的对象身份互换。概念上下位可作为独立子表达。 |
| 特征 | 信息节点持有某类型的实例特征；该特征当前取值；该值满足某个类型化条件 | “设备乙有温度特征。”“设备乙的温度是20摄氏度。”“温度在指定范围内。”持有者、特征类型、实例特征分别绑定。存在特征而当前值未知也是可表达的信息。 |
| 状态 | 某个实例特征在某个确定时刻变化后的固定值或明确未知 | “10时的那次变化后，设备乙的温度为20摄氏度。”指定历史状态时由它取得特征、时刻和值。只问“现在多少”由特征读取当前值。 |
| 动态 | 同一特征从前状态到后状态；一次已发生动作及其目标；同一主题下多个原子变化组成的复合动态；有显式来源的动作与结果关联 | “设备乙的温度从20升到30摄氏度。”“甲执行了测温动作。”“这一过程包含升温和压力变化。”原子变化两端同属一个实例特征；各通道按实际时间组织。只陈述发生动作时可以没有已知结果。 |
| 因果 | 具体话语提出的原因与结果；正式因果规律中的条件和结果，以及已知时的动作角色 | “甲说这次断电导致了停机。”“依这条规律，在条件甲下执行动作乙，预期结果为丙。”前句保留说话者及其主张，后句读正式规律的角色、值域与来源。未知动作允许保留；现实中先后发生两件事不足以补出因果关系。 |
| 二次特征 | 对有序来源应用具名规则取得一个具名结果；在给定范围内判断该结果是否满足条件 | “这两次测温的温差为10摄氏度。”保留输入顺序、结果类型及角色、规则、单位与范围、真实阶次。每个正式结果是一个具名整数标量。可复算的临时结果与由状态或动态实际持有的结果分别取材。 |
| 需求 | 需求主体希望哪个目标信息节点的哪项特征达到什么值域或按哪个方向改变；已有需求中某个目标字段是否待补 | “甲需要水乙的温度达到40摄氏度。”“这项需求还缺目标值。”说话者、需求主体、目标节点分别绑定。目标40℃与实际温度20℃可以同时成立。 |
| 任务 | 任务对应的需求；它实际服务的需求；它的当前状态及已有正式材料的进度、结果 | “这项任务服务于需求甲。”“这项任务正在等待执行条件。”将两句合成时显式共指同一任务。任务对应需求、服务需求和当前状态分别读回。 |
| 方法 | 方法的动作和有序参数；适用分支所需条件；该条件下的预期结果；具名条件与结果的配对 | “方法甲需要条件乙。”“在条件乙下，用方法甲预期得到丙。”参数规格来自方法虚拟存在，条件和结果来自同一配对。预期、尝试和已取得的结果分别表达。 |

本表按内容所指的信息类型索引。入站按文字中实际表达的内容形成语言节点；表中关于领域取材、计算和实际记录的约束用于出站确需报告这些事实的情形。例如“温差为10摄氏度”入站时可以保存说话者所述的量值及其比较对象；出站要求报告测得的温差时，须取得符合规则的两项测温材料或有来源的既有结果。场景作为存在可复用存在结构，状态或动态持有二次特征时可复用特征持有结构。取材依据见[场景](../1150_根规范_场景节点.md)、[存在](../1140_根规范_存在节点.md)、[特征](../1130_根规范_特征节点.md)、[状态](../1160_根规范_状态节点.md)、[动态](../1170_根规范_动态节点.md)、[因果](../1190_根规范_因果.md)、[二次特征](../1180_根规范_二次特征.md)、[需求](../3100_根规范_需求.md)、[任务](../3200_根规范_任务.md)和[方法](../3300_根规范_方法.md)。

## 3. 同一内容按用途生成表达

下表展示十类各一条主张及其两种问法。括号标明取材的限制。填项问把一个允许查询的强类型角色置为待求；确认问保留完整主张，询问其是否成立。回答可以有明确未知，必须保留原问题的角色、来源与作用域。表中的甲、乙、温度等都是可替换材料。

| 类型 | 陈述 | 填项问 | 确认问 |
| --- | --- | --- | --- |
| 场景 | 设备乙在甲室。 | 设备乙在哪个房间？ | 设备乙在甲室吗？ |
| 存在 | 乙是传感器。 | 乙属于哪一类设备？ | 乙是传感器吗？ |
| 特征 | 设备乙具有温度特征。 | 设备乙具有哪些特征？（枚举已知范围） | 设备乙具有温度特征吗？ |
| 状态 | 10时那次变化后温度为20摄氏度。 | 那次变化后温度是多少？ | 那次变化后的温度为20摄氏度吗？ |
| 动态 | 那次设备乙的温度从20升到30摄氏度。 | 那次设备乙的温度从20摄氏度升到了多少？ | 那次设备乙的温度是从20升到30摄氏度的吗？ |
| 因果 | 依规律甲，条件乙下动作丙的预期结果是丁。 | 依规律甲，在这些条件下执行丙，预期结果是什么？ | 依规律甲，在这些条件下执行丙，预期结果是丁吗？ |
| 二次特征 | 后一次与前一次测温的差值为10摄氏度。 | 后一次比前一次高多少摄氏度？（已知方向时） | 后一次与前一次的温差按此顺序为10摄氏度吗？ |
| 需求 | 甲希望水乙达到40摄氏度。 | 甲希望水乙达到多少摄氏度？ | 甲希望水乙达到40摄氏度吗？ |
| 任务 | 任务甲在等待执行条件。 | 任务甲当前处于什么状态？ | 任务甲在等待执行条件吗？ |
| 方法 | 在条件甲下，方法乙的预期结果为丙。 | 在条件甲下，方法乙的预期结果是什么？ | 在条件甲下，方法乙的预期结果是丙吗？ |

**提出需求**有不同内容，必须限定受请求者及所求目标。

- 请求告知可以嵌入各类查询，如“请告诉我任务甲当前的状态”。表达保留提出者、受询者及所求的信息。
- 请求执行引用动作及必要参数，如“请用方法乙测量设备甲的温度”。表达保留受请求者、方法及测量对象。
- 请求达成引用目标，如“请把水乙的温度提高到40摄氏度”。表达保留目标对象、特征、所求值及单位。对历史状态、动态和因果的询问可以嵌入请求告知。
- 招呼按语言场景的交往用途独立处理。否定、条件、引述、量化以及并列、时间顺序、因果、目的等组合按既有作用域作用于内容。回应关联其被回应项。例如“甲说设备在室内吗”需区分是在确认甲是否说过，还是甲在引语中询问位置。

依据见[结构项与角色映射](../7232_子规范_自然语言知识与表达材料字段.md)、[双向转换与作用域](../7240_子规范_自然语言双向转换与组织规则.md)、[汉语种子与缺口](../7250_子规范_最小汉语知识与语言学习.md)和[结构概念与表达模式](../7270_子规范_自然语言结构概念与跨语言表达.md)。

## 4. 双向实现与验收边界

1. 按含义操作、角色种类及来源把每个谓项映射到既有语言知识。陈述、查询变量、确认范围和请求角色分别编码。词面、标题及现实对象编号不参与业务分派。遇到含义重复的汉语模式，复用含义角色并保留各模式自己的语序、显式子规则映射。
2. 输入验收从原消息按来源读回语言场景信息，逐项对照句子预期的用途、角色、所述值、时间、作用域和未决项。单独覆盖所述值与内部当前值相异、内部对象未绑定、两条相同文字有不同来源三种情况。
3. 输出验收从正式表达需求出发，核对具体含义网、候选文本和唯一回读。报告当前状态、转述他人主张和询问状态应各自保留来源与用途。交换对象、字段值或同义说法后按相同合同检查。回读一致还须和样例独立预期核对。必需材料不足、语义歧义和读取期间的工程故障分别报告。
4. 本清单核对基线为 `690c7abcb`。公开基线的[语言模型](../../海中鱼巣/领域/新_语言类.h)、[输入解释](../../海中鱼巣/业务/解释.基础语言.cpp)、[输出生成](../../海中鱼巣/业务/表达.基础语言.cpp)与[语言场景转换](../../海中鱼巣/业务/转换.语言场景基础.cpp)已有可复用入口。普通应用显式装载[语言知识种子](../../初始化材料/最小语言知识种子.txt)和[表达组织知识种子](../../初始化材料/表达组织知识种子.txt)。另放一个文件无法取得普通启动覆盖。
5. 对照本轮设计起点 `deaed871b`，输入已有[接收场景信息](../../海中鱼巣/领域/新_语言类.h)和[同源保存调用](../../海中鱼巣/业务/接收需求认知.服务.cpp)。输出已有[正式表达需求](../../海中鱼巣/业务/正式表达需求.h)、[具体表达结构组织器](../../海中鱼巣/业务/表达.组织.cpp)及[字段询问成文路径](../../海中鱼巣/业务/字段询问.语言服务.cpp)。该基线表达对象的代码分支为需求字段、招呼和需求目标栏；本节任务状态报告是目标设计。十类覆盖须分别从上述两个正式入口举证。本次交付设计文档。
