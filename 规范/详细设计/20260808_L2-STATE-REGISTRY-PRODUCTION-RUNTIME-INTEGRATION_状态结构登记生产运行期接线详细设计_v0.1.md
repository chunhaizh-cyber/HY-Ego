# 状态结构登记生产运行期接线详细设计 v0.1

日期：2026-08-08

状态：设计就绪；只冻结后续实施合同，不证明代码、生产运行或第一层完善。

## 1. 目标与最早缺口

当前 `L1状态服务` 已经具有中性的状态结构登记、当前登记读回和首个基准状态发布能力，但唯一新数据运行期上下文没有拥有该服务，生产运行期启动也没有调用它。因此现行代码只能证明状态服务候选可构建，不能让真实生产程序使用这项第二层数据服务。

本叶只闭合最早独立缺口：

```text
生产运行期构造唯一 L1状态服务
-> 以当前事实代次建立状态结构登记
-> 经同一第二层公开服务权威读回登记
-> 把登记完整性纳入候选上下文发布条件
-> 发布后的运行期租约只读暴露同一服务
```

这是第二层状态服务自身的生产初始化，不是第一层自证、专项消费者、覆盖补格或验收模式。第一层只接受现有中性写集并返回业务中性结构化结果。

## 2. 正式依据与当前事实

- 4015：第一层只承担业务中性 CRUD、通用原子提交和最小幂等；其适用能力由第二至第五层真实服务使用自然证明。
- 4030：领域资格、固定结构和结果解释由具名领域服务负责，第一层不得理解状态语义。
- 4050：入口拒绝、未找到、许可拒绝、资源失败和内部不一致必须保留结构化分账。
- 4190、4210：状态属于状态与状态变化领域；状态结构登记由该领域唯一解释。
- 8120、ACCEPTANCE-01：生产入口不承载自检或验收运行器；日志只供人观察。

当前代码事实：

1. `L1状态服务` 构造需要唯一 `L1事实基座服务`、`L1实际存在场景组合服务` 和 `L1实例特征服务`，三者已由 `运行期上下文` 按同一生命周期拥有。
2. `建立登记` 已使用现有 `L1中性写集请求`，固定新增七个互异节点，按写入结果形成登记定位并经公开读取根精确读回。
3. `运行期上下文` 当前只拥有到实例特征服务，没有状态服务成员、访问器或初始化入口。
4. `生产运行期会话::启动` 当前完成世界登记、初始场景、实际存在登记、初始场景实际存在、系统角色和概念活动；状态登记不在候选完整性内。
5. 当前计划索引没有可执行计划；目标文件与既有异主修复、路线和旧世界树 WIP 不重叠。

## 3. 唯一所有权与物理位置

不新建状态 DTO 或状态服务。唯一服务对象仍为：

```cpp
海中鱼巣::L1状态服务
```

生产生命周期唯一所有者为：

```cpp
海中鱼巣::运行期上下文
```

精确生产文件：

```text
海中鱼巣/启动.运行期上下文.ixx
海中鱼巣/启动.生产运行期.ixx
海中鱼巣/生产运行期配置.数据.h
```

`L1状态.数据.h`、`服务.L1状态.ixx`、核心第一层和其它领域文件保持不变。

## 4. 运行期上下文合同

### 4.1 构造与成员顺序

`启动.运行期上下文.ixx` 增加：

```cpp
export import 海中鱼巣.领域.服务.L1状态;
```

成员按依赖顺序固定为：

```text
L1事实基座服务
-> 世界登记 / 场景 / 实际存在
-> 特征定义 / 实例特征
-> L1状态服务
```

构造参数必须原样引用本上下文现有三个依赖：

```cpp
L1状态服务_(L1事实基座服务_,
    L1实际存在场景组合服务_, L1实例特征服务_)
```

不得建立第二个第一层服务、第二个实际存在组合器、动态分配包装器或空壳服务。

### 4.2 公开上下文入口

新增三个窄入口：

```cpp
L1状态登记结果 初始化状态登记(const L1状态登记请求& 请求);
L1状态登记结果 读取状态登记() const;
bool 状态登记完整() const;
```

规则：

- 初始化入口只校验结构核心和正式请求，然后恰一次委托 `L1状态服务::建立登记`，逐字段原样返回；
- 读取入口恰一次委托 `L1状态服务::读取当前登记`；
- 完整判断只接受 `已读取 + 非空完整登记`，不得把已提交、幂等读回、日志或成员存在视为当前读回成功；
- 新增 const / 非 const `读取L1状态服务()`，只返回同一成员引用，不创建代理语义。

### 4.3 候选完整性

`运行期上下文::完整()` 增加一次状态登记当前读回。发布候选必须同时满足：

- 状态登记结果为已读取；
- 登记非空且通过 `L1状态结构登记完整`；
- 状态登记事实截止与本轮世界登记、初始场景、实际存在登记和初始场景实际存在的共同截止完全相同。

这只证明候选发布时所有当前事实来自同一权威代次，不要求第一层自判业务通过。

## 5. 固定生产配置

`生产运行期配置` 新增：

```cpp
状态操作幂等身份 状态登记幂等身份;
```

固定配置取 `{1}`。该值只在状态登记私有幂等域中有效，不与世界、场景、实际存在或其它领域身份合并。

配置等值和有效性必须同步核对该字段。`生产运行期配置.数据.h` 在没有由模块导入状态数据时才包含 `领域/L1状态.数据.h`；`启动.生产运行期.ixx` 通过与现有世界、实际存在相同的显式宏边界避免重复声明。

不增加命令行覆盖、环境变量、配置文件、随机身份或运行时默认补造。

## 6. 生产启动流程

在初始场景实际存在成功之后、旧业务装配的系统角色初始化之前，形成：

```cpp
const L1状态登记请求 状态登记请求值{
    L1状态合同版本,
    L1状态规则版本,
    配置.状态登记幂等身份,
    初始场景实际存在结果值.事实->事实截止代次};
```

然后恰一次调用：

```cpp
候选->初始化状态登记(状态登记请求值)
```

成功类只允许已提交或幂等读回，并且结果必须带完整登记。非成功立即返回新增的 `状态登记初始化错误`，不继续系统角色、概念活动或候选发布。

`生产运行期启动结果` 增加状态登记业务状态。首次成功、已有当前上下文和各失败分支必须按真实已执行阶段回显；未执行阶段保持入口拒绝。不得把程序退出码、日志文本或默认枚举冒充状态登记结果。

## 7. 事务、幂等和失败边界

- 本叶不修改状态服务事务；七节点仍由一次现有中性写集原子提交。
- 同一固定请求在同一服务对象内按现有幂等合同收敛；不同请求语义仍冲突。
- 状态登记失败时，候选上下文不发布；此前已形成的候选只随局部 `shared_ptr` 生命周期销毁，不增加撤销协议或跨进程恢复。
- 资源失败、许可拒绝、版本漂移和内部不一致由状态服务结构化返回，启动层只映射为状态登记初始化错误并保留领域状态。
- 当前阶段不处理崩溃、重启、断电或跨进程恢复。

## 8. 明确排除

- 第一层新接口、DTO、索引、锁、缓存、审计或恢复逻辑；
- 第一层自检、专项消费者、独立 L1 验收、第二目标或覆盖补格；
- 创建 I64 特征定义、实例特征或首个基准状态；
- 动态登记、状态迁移动能、特征比较、因果或世界树门面；
- 改动普通应用旧栈、系统角色业务语义、概念活动语义；
- 通过日志或进程退出单独宣称第二层业务合同或第一层完善。

## 9. 验证与完成边界

实施至少验证：

1. 三个生产文件和两份专属记录以外零差异；
2. 运行期上下文恰一状态服务成员、恰一构造和一对访问器；
3. 生产启动恰一次状态登记初始化，且位于实际存在成功后、系统角色前；
4. 配置身份固定、参与等值和有效性；
5. 候选完整性真实读取状态登记并互证共同截止；
6. 生产代码中不新增自检、验收、驱动、第二可执行目标或日志 PASS；
7. Debug / Release 完整重建、双配置模块扫描、strict 和两配置正式生产运行期模式通过。

本叶完成只证明第二层状态结构登记成为生产运行期真实初始化能力，并在候选发布前经自身公开读回闭合。它不证明首个基准状态、后继状态、动态、因果、全部下游服务或第一层完善。第一层是否完善继续由当前全部第二至第五层服务的真实业务运行累计判定。
