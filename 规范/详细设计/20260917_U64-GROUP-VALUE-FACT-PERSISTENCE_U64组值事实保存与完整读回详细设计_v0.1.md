# U64组值事实保存与完整读回详细设计

身份：`U64-GROUP-VALUE-FACT-PERSISTENCE`
版本：v0.2
状态：可执行

## 1. 目标和边界

落实2100 v0.17：完整相同的 `std::vector<uint64_t>` 全局复用同一永久值身份，并能按身份同截止完整读回。仅实现 `U64组`；不实施 I64组、独立材料、FT/F、格式解析、比较、概念或业务采用。

4120 v0.13 已改变局部二值格格式；已发布 `LOCAL-BINARY-GRID-U64-PARSER` 仍按旧格式，故本计划不调用、不改动它。其修订是独立后继，非本叶依赖。后继格式入口必须把“不是8×2^k/4×2^k，或不能逐层二分抵达8×8/4×4×4”精确返回为`格式不合法`，结果不携带尺寸、层或颜色载荷；不得退化为“任意8/4倍数可接受”。本叶不拥有格式解释，保存普通U64组不能作该拒绝。

## 2. 当前事实与所有者

现有 `数据服务.特征值类.h` 只有按身份读取和 B1 完整读回；普通应用以无 owner 构造它。L1 已有 owner 写端口、按 owner+属性类型读取全部当前值、首次写入材料、新编码映射和原子单 owner 写集。

特征值类成为唯一 owner：装配建立 `特征值所有者`，其初始化写集建立三个普通/属性类型事实。来源节点和承载节点可为同一已发布普通节点；属性类型节点必须声明 `U64组`。交付不进入任何值对象。服务持有该 owner 写端口；构造时核验同 L1、同 owner、三编码有效且结构仍当前。普通应用负责签发 owner、登记结构、移交端口；不建立 FT/F 或其它业务结构。

## 3. 公开合同

新增于 `数据服务.特征值类.h/.cpp`：

```cpp
struct 特征值U64组保存请求_B2 final {
  uint32_t 版本{1}; uint64_t G0{};
  L1所有者范围写入幂等身份 幂等;
  vector<uint64_t> 内容; 世界结构预算_B1 预算{};
};
enum class 特征值U64组保存状态_B2 : uint8_t {
  已复用=1, 已保存=2, 入口拒绝=8, 结构未就绪=9, 许可拒绝=10,
  未找到=11, 已退出=12, 事实代次漂移=13, 数量预算不足=14,
  幂等冲突=15, 引用冲突=16, 资源失败=17, 内部不一致=18,
  已可能发布=19

  uint32_t 版本{1}; 特征值U64组保存状态_B2 状态{入口拒绝};

  L1所有者范围写入幂等身份 幂等;
};

  L1结构所有者身份 所有者{};
  稳定编码 承载节点{}; 稳定编码 U64组属性类型节点{}; 稳定编码 来源节点{};

  已登记=1, 入口拒绝=8, 许可拒绝=9, 未找到=10, 已退出=11,
  事实代次漂移=12, 幂等冲突=13, 引用冲突=14, 资源失败=15,
  内部不一致=16, 已可能发布=17
};
struct 特征值U64组结构登记结果_B2 final {
  uint32_t 版本{1}; 特征值U64组结构登记状态_B2 状态{入口拒绝};

// B2 不另造值读取载荷：成功载荷与 B1 完全相同；失败时值、材料和用量归零。

  const 特征值完整读取请求_B1&) const noexcept;
static 特征值U64组结构登记结果_B2 登记U64组结构_B2(
  const L1事实基座服务&, L1所有者范围写端口&,
  const 特征值U64组结构登记请求_B2&) noexcept;

特征值类数据服务(const L1事实基座服务&, L1所有者范围写端口&&,
  const 特征值U64组结构交付_B2&) noexcept;
```

`保存U64组` 仅在成功时返回一个值身份。`读取完整U64组_B2` 固定返回既有 `特征值完整读取结果_B1`：先调用 `获取完整值`，其成功载荷的表示不是 `U64组` 时改为 `类型不相容`，并清空值、材料和用量；其他B1失败原样返回。`退出U64组` 不存在：永久值没有删除/退出 ABI。

`登记U64组结构_B2` 只接收绑定同一 L1 的活动 owner 写端口和登记请求。首次提交固定建立一个承载普通节点及一个 `U64组` 属性类型节点；来源节点固定复用承载节点，故实际写集恰有两个节点。无论首次或重放，交付均由首次规范化写集的两个局部键及首次成功结果的新编码映射唯一还原，并令`来源节点==承载节点`。随后以本次 `Gread` 逐项读回：承载/来源必须为同一所有者的当前未退出普通节点，属性类型必须为同一所有者的当前未退出属性类型节点且表示 `U64组`；否则失败且无交付。构造函数重复该核验，并持有移入的端口。无 owner 的既有构造保留为 B1 通用只读构造；它不能调用 `保存U64组`，后者固定返回 `结构未就绪`。这是为计划白名单外的两个既有验证工具保留的读取兼容，不是B2生产保存路径。

## 4. 保存和读回算法

1. 核验版本、G0、幂等身份、预算和已读回结构；读取 `owner+U64属性类型` 的全部当前值，必须同截止 G0 且不超预算。
2. 每项必须归属该 owner、承载节点、属性类型与来源节点，并为 U64 材料；否则 `内部不一致`。
3. 以长度及同下标元素精确比对完整向量：一项命中直接 `已复用`；两项以上命中 `内部不一致`、零写；未命中继续。
4. 未命中时只构造一项 L1 值新建项（承载、属性类型、完整内容、来源），不建节点/关系/属性槽、不改现有值；以请求幂等和 G0 提交。`成功`或`精确重复`都必须从该次结果或端口的首次写入材料唯一取得本地键映射，再以提交代次作为 `Gread=H` 完整读回核验内容后报告 `已保存`。提交已被 L1 接受但唯一映射或该次读回无法取得时，唯一报告`已可能发布`、不携带值且不得自动重试。
5. 读取和尾部代次均必须保持同一截止；任何漂移/预算/资源/映射不唯一均不产生成功载荷。

### 4.1 L1 状态映射

所有入口字段、端口绑定及登记/构造结构不成立，分别在调用L1前返回`入口拒绝`或`结构未就绪`。读取候选组的 L1 `成功`进入逐项核验；`入口拒绝/未找到/已退出/事实代次漂移/数量预算不足/资源失败/内部不一致`逐一映射同名B2状态。写入结果的 `入口拒绝/许可拒绝/未找到/已退出/事实代次漂移/幂等冲突/引用冲突/资源失败/内部不一致`逐一映射同名B2状态；`成功/精确重复`只在唯一映射和同截止读回成功后成为`已保存`，否则为`已可能发布`。登记结果使用相同映射，且`成功/精确重复`只在首次材料、映射和三项读回均成功后成为`已登记`，否则为`已可能发布`。任何`已可能发布`均为零交付/零值，重试边界由L1原结果记录，不由B2虚构另一写入身份。

全局性由唯一 owner 的完整当前值组和永久保存保证；N、长度摘要、颜色计数或任何局部二值格解释不参加服务去重。

## 5. 失败、迁移与验证

普通应用同步建立特征值 owner、登记结构并以移入端口构造B2保存服务。现有两个白名单外验证工具仍使用的无owner构造不删除：它仅保留B1通用读取，B2保存固定拒绝为`结构未就绪`。B1读取仍可作为通用读取实现，但 B2成功必须核验 U64表示和完整内容。

验证至少覆盖：首次保存、相同内容复用、顺序/重复差异不复用、空组合法复用、伪造结构拒绝、同 owner 非U64/错承载项内部不一致、候选预算不足、G0漂移、幂等冲突、映射异常、保存后完整读回；并验证没有退出入口。另以真实局部轮廓和体素完整多层组仅作为普通不同U64载荷，证明不会按N合并。主工程 Debug/Release 构建和隔离专项驱动按 CODE-FILE-01 执行。
