# U64组值事实保存与完整读回详细设计

身份：`U64-GROUP-VALUE-FACT-PERSISTENCE`  
版本：v0.1  
状态：可执行

## 1. 目标和边界

落实2100 v0.17：完整相同的 `std::vector<uint64_t>` 全局复用同一永久值身份，并能按身份同截止完整读回。仅实现 `U64组`；不实施 I64组、独立材料、FT/F、格式解析、比较、概念或业务采用。

4120 v0.13 已改变局部二值格格式；已发布 `LOCAL-BINARY-GRID-U64-PARSER` 仍按旧格式，故本计划不调用、不改动它。其修订是独立后继，非本叶依赖。

## 2. 当前事实与所有者

现有 `数据服务.特征值类.h` 只有按身份读取和 B1 完整读回；普通应用以无 owner 构造它。L1 已有 owner 写端口、按 owner+属性类型读取全部当前值、首次写入材料、新编码映射和原子单 owner 写集。

特征值类成为唯一 owner：装配建立 `特征值所有者`，其初始化写集建立三个普通/属性类型事实并返回 `特征值U64组结构交付_B2{承载节点,U64组属性类型,来源节点}`。来源节点和承载节点可为同一已发布普通节点；属性类型节点必须声明 `U64组`。交付不进入任何值对象。服务持有该 owner 写端口；构造时核验同 L1、同 owner、三编码有效且结构仍当前。普通应用负责签发 owner、登记结构、移交端口；不建立 FT/F 或其它业务结构。

## 3. 公开合同

新增于 `数据服务.特征值类.h/.cpp`：

```cpp
struct 特征值U64组保存请求_B2 { uint32_t 版本{1}; uint64_t G0{};
  L1所有者范围写入幂等身份 幂等; vector<uint64_t> 内容;
  世界结构预算_B1 预算{}; };
enum class 特征值U64组保存状态_B2 { 已复用=1, 已保存=2, 入口拒绝=8,
  结构未就绪=9, 事实代次漂移=10, 数量预算不足=11, 幂等冲突=12,
  引用冲突=13, 资源失败=14, 内部不一致=15, 已可能发布=16 };
struct 特征值U64组保存结果_B2 { uint32_t 版本{1}; 状态; uint64_t Gread{};
  optional<特征值身份> 值; 世界结构用量_B1 用量{}; bool 成功(const 请求&) const; };
struct 特征值U64组结构登记请求_B2 { uint32_t 版本{1}; uint64_t G0{};
  L1所有者范围写入幂等身份 幂等; };
```

`保存U64组` 仅在成功时返回一个值身份；`读取完整U64组_B2(特征值完整读取请求_B1)` 调用既有完整读回并要求表示为 U64组，否则结构化拒绝。`退出U64组` 不存在：永久值没有删除/退出 ABI。`登记U64组结构_B2` 是静态初始化函数，只接收同 L1 的 owner 写端口和登记请求，建立三项内部结构后从新编码映射交付。

## 4. 保存和读回算法

1. 核验版本、G0、幂等身份、预算和已读回结构；读取 `owner+U64属性类型` 的全部当前值，必须同截止 G0 且不超预算。
2. 每项必须归属该 owner、承载节点、属性类型与来源节点，并为 U64 材料；否则 `内部不一致`。
3. 以长度及同下标元素精确比对完整向量：一项命中直接 `已复用`；两项以上命中 `内部不一致`、零写；未命中继续。
4. 未命中时只构造一项 L1 值新建项（承载、属性类型、完整内容、来源），不建节点/关系/属性槽、不改现有值；以请求幂等和 G0 提交。成功或精确重复必须从本地键映射唯一取得编码，再以同次截止完整读回核验完整内容后报告 `已保存`。提交未知映射为`已可能发布`且不携带值。
5. 读取和尾部代次均必须保持同一截止；任何漂移/预算/资源/映射不唯一均不产生成功载荷。

全局性由唯一 owner 的完整当前值组和永久保存保证；N、长度摘要、颜色计数或任何局部二值格解释不参加服务去重。

## 5. 失败、迁移与验证

旧无-owner构造和旧读取 ABI 不保留为生产兼容路径；普通应用同步改为先登记结构再构造。B1 读取仍可作为通用读取实现，但 B2 成功必须核验 U64 表示和完整内容。

验证至少覆盖：首次保存、相同内容复用、顺序/重复差异不复用、空组合法复用、伪造结构拒绝、同 owner 非U64/错承载项内部不一致、候选预算不足、G0漂移、幂等冲突、映射异常、保存后完整读回；并验证没有退出入口。另以真实局部轮廓和体素完整多层组仅作为普通不同U64载荷，证明不会按N合并。主工程 Debug/Release 构建和隔离专项驱动按 CODE-FILE-01 执行。
