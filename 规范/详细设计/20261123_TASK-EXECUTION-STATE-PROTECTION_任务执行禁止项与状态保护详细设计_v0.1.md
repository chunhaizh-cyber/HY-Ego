# 任务执行禁止项与状态保护详细设计

编号 `TASK-EXECUTION-STATE-PROTECTION`，版本 v0.2，日期 2026-11-23。用户已确定由自我维护正式禁止项，接入明确指令和安全事实两个来源。第 7 节冻结第一施工片，其余接口随相邻施工片冻结。生产源码起点 `28208abaac6cd67072bfcb6356ec358ce53a760d`。

依据 [0050 §8](../0050_项目通用机器逻辑与禁止性规则总纲.md)、[3200 §5–6](../3200_根规范_任务.md)、[5260 §5.1、§7](../5260_子规范_任务治理详细合同.md)、[5350 §2–4](../5350_子规范_方法治理详细合同.md)、[6150 §9–10](../6150_子规范_因果安全层级与任务执行优先级权限.md)。

## 1. 执行决定

保留现行安全硬限制。自我对选定方法及实参的执行请求先适用正式禁止项，再比较状态保护，随后使用现行调度规则。禁止命中时拒绝该动作。状态保护冲突时，自我决定允许哪一个动作先使用或改变该条件，另一项等待。自我把决定交给管理线程执行。两者都通过时才进入原执行路径。

同一执行请求第一次判断和最终发出动作之间，禁止项可能增加，保护也可能释放或生效。首次判断用于确定调度，临近动作使用当前事实和裁决复核。若在动作开始前结论发生变化，停在零动作边界，转为等待或筹办。实际状态从事实所有者读取。禁止和保护记录只保存治理依据及引用，观察和事实写入照常发生。

## 2. 自我维护的正式禁止项

每项有稳定身份，关联唯一自我，保存来源类型和来源引用、适用动作、作用范围及生效条件。动作使用正式方法或动作概念，作用范围使用实际对象、场景或特征定位。若规则禁止某个结果，还保存正式结果谓词，包括适用的特征取值位置、值域或关系。有效规则和撤销都由自我发布。治理项引用既有特征和定义；准确值仍由其事实所有者维护。

物理记录以正式自我存在节点为宿主。自我治理初始化登记禁止项节点类型及宿主关联字段，启动时读取该自我的规则。一个节点保存规则定义、来源证明及生效状态，来源中有独立操作身份，撤销保留原节点和已发生事实。新增规则和宿主关联使用同一次 `基础数据集::原子追加节点组`，撤销按正式规则身份更新。等待索引和保护材料随本次治理建立，调度直接消费自我发布的当前读回，不另外保存一致性副本。[原子发布入口](../../海中鱼巣/核心/基础数据集.h)

- **明确指令。** 已核验的第一权限人拥有专门的网页禁止项控制权限。入口使用同一正式对话会话，同时核对本机页面的来源、会话和当前绑定的第一权限人；每次新增或解除均适用，匿名或错绑会话拒绝操作。控制请求采用结构化字段并携带操作标识。自我读取已核验的发令身份、来源、动作、作用对象和规则身份后裁决发布。普通自然语言先作为材料；歧义表达保持待澄清。重复指令返回同一次发布结果。解除只作用于指令明确指定的人工来源规则。[普通装配的会话和身份入口](../../海中鱼巣/装配.普通应用.cpp)
- **安全事实。** `核验任务执行方向内部` 已绑定动作及预计变化，并区别 `安全方向不一致`、`等待材料`、`结果定义暂不支持` 和结构异常。自动来源首片采用其中有明确作用对象与安全需求依据的确定冲突。任务端交付具体安全需求、当前事实定位、触发冲突的预计影响及适用谓词，自我按该范围建立或更新规则。该状态码单独不足以形成规则。将来由同一安全依据的正式读回确认规则已失效，再解除对应规则。明确解除指令与安全事实各保留自身来源；安全依据依然成立时继续适用。[任务所有者](../../海中鱼巣/领域/新_任务类.cpp) · [安全硬限制](../6150_子规范_因果安全层级与任务执行优先级权限.md)

自我为每条自动规则登记安全需求、当前事实和约束来源的依赖。安全需求或事实有正式就绪变化时，由自我独立重读并重算原谓词。禁止中的任务停在等待中，解除不依赖该任务先取得执行许可。读取材料未齐时既有安全规则继续适用，等来源就绪后再读。重算解除后定向唤醒本来受该规则约束的任务。

比较使用同次执行绑定的动作、对象及预计影响。明确命中按禁止处理。可以证明对象、时间或预计结果域分离时，规则对这次动作不适用。直接相关的规则尚缺决定材料时，保留具名等待，由正式材料就绪再读。规则定义使用正式的既有值域关系和条件比较。方法配对已有的禁止结果项继续由结果方案在执行后结合实际事实评估。[方法结果及确认要求](../5350_子规范_方法治理详细合同.md#4-结果节点与结果项)

## 3. 状态保护列表

任务所有者从本轮已选择的分支和当前采用的必要条件形成清单。每项记录父任务及本轮定位、来源条件、绑定的实际对象和特征 F 或正式关系、须维持成立的条件，以及最后使用该条件的动作或阶段。替代分支、已消费条件和只读取历史事实的条件按其正式取值语义处理。初版可用已有调用起止作为缺少更细阶段信息时的保护边界。

自我在条件已满足且即将使用时签发保护；可按已有筹办材料保留尚未生效的条目。收到子任务完成通知后从实际状态读回满足。管理线程以同次预计影响中的作用对象、实际 F 或关系定位筛出可能冲突的动作，证明仍可维持所需条件时允许并行。两方要求互相排斥时，使用现行安全限制和优先级裁决同一次先后次序，完整决定生效后才能进入派发，避免两个动作互相等待。对已经派发或开始的动作，只有已声明安全停止能力且尚未跨过停止边界时，才允许经现有方法入口停下；其余动作按已知时序等待完成并重读。

最后一次使用条件、换方案、收束、取消或禁止导致该筹办退出时，按所属任务和原工作定位解除保护并唤醒受影响的等待。事实先失效时，父任务按当前必要条件回筹办；同义子目标沿需求所有者取得原 D，终结 T 走正式重新启用路径。历史完成记录保留。[子需求与动作前复核](../5260_子规范_任务治理详细合同.md) · [任务重新启用](../3200_根规范_任务.md)

## 4. 生产接入点和状态所有权

- `新_自我线程类` 是禁止项与保护裁决的唯一发布者。对外只提供正式来源接收、当前规则读取和具名裁决；禁止项采用自我内部治理的正式记录，保护项采用本次筹办执行材料。规则写入和来源变更沿正式治理发布入口执行。
- `新_任务类::核验任务执行方向`、`新任务本能采用材料` 和 `新任务治理本能执行请求` 已承载实际参数、选定条件及预计变化。任务所有者负责从这次正式采用提取保护材料，匹配复用 `新_特征类` 规则和既有值域运算。
- 自我在 `处理筹办反馈` 的现行方向判断后应用新裁决，确保旧临时放行只作用于它原来覆盖的方向判断，新禁止和保护暂缓不会被它改写。管理线程在 `尝试派发执行工作` 消费决定，保留正式等待原因和受影响的依赖，以保护释放、规则或相关材料变化唤醒。
- 管理线程在派发时保留已作出的执行排序。worker 在 `复核执行本能输入` 返回仍具备后、进入 `调用本能函数` 前，消费当次动作开始许可。这一消费点与自我发布禁令、签发或解除保护串行，同一采用和执行实例只能消费一次。禁止先发布就走零动作分流，使用具名的调度等待原因。许可先消费就按在途工作处理随后出现的禁令。串行段只处理调度决定；在段外读取世界事实，并在离开后调用本能。许可占用随原工作成功、零动作返回或正式停止收束，迟到回执按原工作归属处理。[自我执行前判断](../../海中鱼巣/线程/新_自我线程类.cpp) · [管理派发](../../海中鱼巣/线程/新_任务管理线程类.cpp)

网页控制在现有会话路径下新增 `GET /api/control/prohibitions` 读取和 `POST /api/control/prohibitions` 操作。复用现有控制请求的本机来源约束及 `核验服务会话` 的第一权限人绑定。新路由对读取和修改均要求此身份，修改还要求同源 POST。请求使用稳定编码选择正式动作或方法、实际作用对象或场景，以及可选的正式结果谓词；解除使用禁止项身份。网页接收回执区分「已提交给自我」和「已发布／已解除」，结果读取限于该授权会话。现有控制输出供稿渠道保持独立。[会话核验](../../海中鱼巣/装配.普通应用.cpp) · [控制请求的来源约束](../../海中鱼巣/界面/宿主.网页对话.cpp)

默认第一权限人为周春海，与现行普通应用启动配置一致。授权判断使用初始化得到的正式存在节点。源码中的 `可信服务对象可绑定` 只核对已配置的登录名和内部实体。`开始普通应用网页会话` 依据该配置绑定浏览器会话。专门控制需要一个能确认实际操作者的独立凭据，并且只授予本次已绑定第一权限人的会话。凭据来源待定。会话关闭时清除本次控制授权，已发布的规则继续由自我按各自来源治理。[默认第一权限人](../../海中鱼巣/装配.普通应用.h)

## 5. 验证范围

实际工程 Release/x64 编译链接。获得运行测试指令后用正式入口分别证明两种来源各自建立、重复和解除规则；同一动作同时遇到禁止和保护时按禁止处理；仅有保护冲突时由自我延后并在解除后恢复；对象不同或预计结果仍符合条件时可推进；事实在派发前失效时零动作回筹办；已开始的动作按其安全停止能力处理。保存规则、实际对象、条件、决定、工作和动作的正式读回及正常退出。静态与编译证据分别保留。

## 6. 待冻结接口

当前代码能提供网页会话的身份与场景、所选方法和条件，以及安全方向不一致的结论。创建正式网页指令、将安全方向结果落实到具体事实依据、对两个可能并发的动作形成唯一临近许可，是新增的三个生产接口。施工前要明确各接口的 DTO、绑定证据和锁外调用顺序。`继续任务本能执行` 中的词条归类和词典查询都可能在原执行实例尚无动作时发起动作，此时须消费同一执行许可；已经正式发布动作的续接按原动作身份和后继合同处理。项目现有通用停止入口按整个线程或工作池处理，任务级安全暂停须有具体方法合同。首版延后未开始的冲突动作，已开始的动作按可用停止能力或正常收束推进。[本能续接入口](../../海中鱼巣/领域/新_任务类.cpp)

## 7. 第一施工片的正式记录

第一片交付自我控制的正式禁止项记录库及初始化、发布、读回和解除接口。运行中的自我线程为业务发布者，库的接口供自我使用。领域存取保持同一所有者，写操作依靠既有 L1 原子发布，无持久化工程迁移。本片以正式方法和实际作用存在为第一可表达规则，后续对动作概念、场景和结果谓词的接入继续用同一个规则库。

每条规则存放方法节点、作用存在节点、来源类型、正式来源引用及有效性。发布输入的完整键是上述字段中除有效性外的四项；同键重复返回原规则及当前是否有效。来自同一正式来源的重投不会重新开启已解除的规则。新的业务指令或新的安全发生使用新的正式来源身份。解除接收原规则身份、原来源类型和正式解除来源引用，只解除匹配来源的规则；同一解除来源重投返回原回执。首片方法和对象端点由后续自我业务入口按正式服务解析，本片对实际字段和引用的正确性使用 L1。正式来源引用必填，当前列表读取从 L1 直接取得，各记录的稳定编码用于引用。

自我完成正式初始化后，以其存在节点初始化库，生命周期随该自我运行。`新_自我执行禁止项库` 使用独立互斥串行本库的创建、发布、解除与读回；持该锁时只调用 L1。自我通过只读入口 `读取当前执行禁止项` 返回当前有效规则；首片业务写入仅通过内部 owner，留给后续已有来源入口。入口失败区分未初始化、来源不符、规则不存在、资源失败和正式结构不一致。源码接入点与工程文件见现行实施计划。
