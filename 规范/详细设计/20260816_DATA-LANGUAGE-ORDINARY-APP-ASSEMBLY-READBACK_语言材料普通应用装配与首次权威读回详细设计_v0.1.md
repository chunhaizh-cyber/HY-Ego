日期：2026-08-16

版本：v0.1

状态：设计就绪；以计划索引为准

## 1. 目标与完成边界

本设计一次闭合当前最早的真实结果缺口：让普通应用从正式生产配置取得唯一不可变材料受控根，在同一 `L1事实基座运行包` 中装配唯一不可变材料 owner / 服务、语言 owner、词条 owner 和唯一 `L2语言结构服务`，再由合法消费者只经 `普通应用上下文` getter 完成材料写入、语言建立、词条建立以及当前 / 历史权威读回。

本叶不再把配置、owner、服务、getter 或首次读回拆成后继小计划。完成必须同时满足：

```text
正式生产配置可形成
+ 普通应用配置可纯值拒绝坏根
+ 材料、语言、词条三个固定 owner 同属一个 L1
+ 唯一材料服务与唯一语言服务由普通应用持有
+ 现有普通概念服务取得完整材料和六类世界依赖
+ const / non-const getter 返回同实例
+ 合法消费者经 getter 写材料、建语言、建词条并当前 / 历史读回
+ 根工程和生产外专项通过
```

本结果不证明语言记录、概念名称、默认语言、分词、规范化算法、BIZ 消费、跨进程恢复或完整 `DATA-EXT-08` / `DATA-EXT-10` 已完成。

## 3. 生产受控根裁决

### 3.1 唯一来源

普通应用生产受控根固定取 Windows `FOLDERID_LocalAppData` 已知目录下：

```text
<LocalAppData>/海中鱼巣/数据/不可变材料
```

该路径是每用户安装实例的物理存储配置，不是语言身份、材料身份、业务事实、owner 身份或动作来源。禁止：

- 从仓库根、当前工作目录、可执行文件相邻目录或临时目录推导；
- 使用 `D:` 等硬编码盘符；
- 新增 `--material-root` 或其它必填启动参数；
- 把环境变量字符串直接当作已验证绝对路径；
- 在失败时静默回退到另一目录。

### 3.2 目录建立与校验分账

应用配置形成函数使用 Windows 已知目录 API 取得 `LocalAppData`，以 `std::filesystem::create_directories` 建立固定子路径；I/O 只发生在配置形成阶段。`普通应用配置::有效()` 仅检查合同版本和路径字面量，不访问文件系统。材料服务构造继续负责目录存在、普通目录、非重解析点、句柄规范路径及同卷受控子目录检查。

## 4. 目标类型、函数、参数与返回

### 4.1 普通应用生产配置

在现有模块 `海中鱼巣.装配.普通应用`、文件 `海中鱼巣/装配.普通应用.ixx` 的导出命名空间内扩展：

```cpp
struct 普通应用配置 {
    不可变材料存储配置 不可变材料存储;
    bool 有效() const noexcept;
};

enum class 普通应用生产配置状态 : std::uint8_t {
    已形成 = 1,
    已知目录不可用 = 2,
    目录建立失败 = 3,
    配置无效 = 4,
    资源失败 = 5,
    内部不一致 = 6
};

struct 普通应用生产配置结果 final {
    普通应用生产配置状态 状态 =
        普通应用生产配置状态::内部不一致;
    std::optional<普通应用配置> 配置;
    bool 成功() const noexcept;
};

普通应用生产配置结果 形成普通应用生产配置() noexcept;
```

合同：

| 函数 | 参数 | 成功返回 | 非成功 | 副作用 / 诊断责任 |
| --- | --- | --- | --- | --- |
| `普通应用配置::有效` | 隐式 `this` | 材料合同版本正确、路径非空且绝对、无 `.` / `..` 时 `true` | 其它为 `false` | 纯值；无适用错误分支；零 I/O |
| `普通应用生产配置结果::成功` | 隐式 `this` | 状态已形成、配置有值且 `配置->有效()` 时 `true` | 其它为 `false` | 纯值；无适用错误分支 |
| `形成普通应用生产配置` | 无参数 | `已形成 + optional<普通应用配置>` | 按已知目录、目录建立、配置、资源或内部失败分账，配置为空 | 本地记录；只建立固定物理目录，不写 L1 或领域事实 |

`形成普通应用生产配置` 使用 `SHGetKnownFolderPath(FOLDERID_LocalAppData, KF_FLAG_CREATE, ...)`，释放系统缓冲后拼接固定相对路径。工程链接只使用 Windows `Shell32.lib`；不得新建配置模块、工具模块或第二路径入口。

### 4.2 材料 owner 建立身份

把现有值不变的材料 owner 建立身份从内部命名空间提升为材料服务模块唯一公开常量：

```cpp
inline constexpr L1所有者范围建立幂等身份
    不可变材料所有者建立身份{0x4C32'4D41'5445'5201ULL};
```

物理位置：`海中鱼巣/领域/服务.不可变材料.ixx` 的既有 `export namespace 海中鱼巣`。内部验证改用同一公开常量；禁止保留同值内部副本、增加 owner 选择参数或建立第二 owner。

### 4.3 普通应用服务 getter

在现有 `普通应用上下文` 增加：

```cpp
不可变材料服务& 取得不可变材料服务() noexcept;
const 不可变材料服务& 取得不可变材料服务() const noexcept;
L2语言结构服务& 取得L2语言结构服务() noexcept;
const L2语言结构服务& 取得L2语言结构服务() const noexcept;
```

四个函数无参数、无失败分支、零创建、零写入、零锁，只返回上下文持有的同一实例引用。引用不得跨越上下文生命周期；const 重载不能调用写入口。

### 4.4 既有装配与启动函数

保留公开签名：

```cpp
普通应用装配结果 构造普通应用上下文(
    const 普通应用配置& 配置);
```

输入增加材料存储配置语义；成功仍为 `已装配 + non-null 上下文`。现有枚举值不得重排，在 31 后追加：

```text
32 不可变材料所有者范围建立失败
33 不可变材料服务构造失败
34 语言所有者范围建立失败
35 语言所有者交付形成失败
36 词条所有者范围建立失败
37 词条所有者交付形成失败
38 语言服务构造失败
```

`运行普通程序(启动模式)` 签名和模式合同不变。它先调用 `形成普通应用生产配置()`；配置非成功或普通应用装配非成功统一映射现有 `程序运行状态::装配失败 / 程序失败阶段::普通应用装配`。它不增加启动参数、运行模式、验证分支或错误文本。

## 5. 装配事务与生命周期

`构造普通应用上下文` 的新顺序固定为：

```text
校验普通应用配置
-> 建立唯一 L1 运行包
-> 以公开固定身份签发材料 owner
-> 构造唯一不可变材料服务
-> 分别以公开固定身份签发语言 owner、词条 owner
-> 形成两份强类型 owner 交付
-> 构造唯一 L2语言结构服务（同一 L1 + 同一材料服务 + 两owner）
-> 按既有顺序装配六类世界服务与世界聚合
-> 签发唯一概念 owner
-> 使用现有完整 L2概念结构服务构造（同一 L1 + 材料 + 六世界 + 概念owner）
-> 构造现有概念聚合、方法服务和方法聚合
-> 一次移动进普通应用上下文
```

材料、语言和词条 owner 的建立分别是 L1 正式步骤，不伪装为跨 owner 原子事务；任一步失败不发布普通应用上下文，已形成的局部对象按 RAII 析构。发布结果未知只允许底层既有固定幂等身份读回收敛，不由装配函数生成新身份重试。

成员声明必须保证依赖者先析构：`L1运行包` 最先声明，材料服务随后，语言服务在材料之后，六世界服务随后，概念服务和各聚合最后；私有构造参数、初始化列表和成员声明保持同一依赖顺序。不得保存裸 owner 端口、建立第二服务实例或让聚合拥有服务。

## 6. 合法消费者首次权威读回

生产外专项是合法消费者，不进入生产工程。它只能：

1. 在仓库外建立普通非重解析点材料根；
2. 用显式 `普通应用配置` 调用 `构造普通应用上下文`；
3. 反复取得材料 / 语言 getter，证明地址稳定且 const / non-const 指向同一实例；
4. 在材料根的 `候选` 子目录形成严格 UTF-8 规范化合同、规范化词面、来源和语言登记键材料；
5. 经材料服务写入四份材料并当前 / 历史读回；
6. 经语言服务新增语言并按身份、登记键当前 / 历史读回；
7. 经同一语言服务新增词条并按身份、规范化键当前 / 历史读回；
8. 逐项互证事实截止、材料身份、语言身份、规范化键、来源和生命周期；
9. 销毁上下文后删除仓库外专项实际文件。

专项不得直达 L1、raw owner 端口、材料内部路径 helper 或语言内部 helper。可以在生产配置形成、装配函数、两个 getter 和公开材料 / 语言 / 词条入口设置调试器断点检查真实参数与返回；不得在 `入口.cpp`、启动模块、普通应用或领域模块增加验证调用、模式、条件分支、友元或状态出口。验证完成后专项源码、工程、对象、二进制和日志实际文件计数必须为零。

## 8. 验证矩阵与失败收口

执行必须覆盖：

- 生产配置：已知目录成功、固定相对位置、目录已存在重入、坏合同 / 相对路径 / 点路径纯值拒绝；
- 装配：材料 owner、语言 owner、词条 owner 同一 L1 且两两不同；配置无效和各新增装配状态空上下文；
- getter：const / non-const 同实例、重复取得地址稳定、引用生命周期受上下文约束；
- 材料：四材料写入、精确重复、当前 / 历史读回和非成功空载荷；
- 语言：新增、按身份 / 键当前历史读取和材料绑定；
- 词条：新增、按身份 / 键当前历史读取和语言 / 三材料绑定；
- 概念服务：普通应用实际使用完整构造，根三入口和现有概念聚合 ABI 不回归；
- 工程：x64 Debug / Release fresh Rebuild、模块扫描、strict `113/113`、XML、UTF-8、四配置 `/utf-8`、diff、白名单、唯一工程登记和生产零测试痕迹；
- 清理：仓库外专项所有实际文件计数为零。

真实资源耗尽、Shell API 故障注入、目录权限长期变化、发布结果未知、长时间并发、跨进程恢复、真实语言记录 / 名称 / BIZ 消费和完整最终需求清单保持 `NOT_RUN`。

若执行时发现必须增加启动参数、第二材料根、第二 owner / 服务、通用服务定位器、L1 新接口、生产验证分支、知识库写入或正式机器语义，固定 `DRIFT-DATA-LANGUAGE-ORDINARY-APP-ASSEMBLY-CONTRACT-OR-SCOPE` 并停止扩大。计划范围内的编译、Windows API 适配、装配状态映射和专项错误由执行者自行修复。
