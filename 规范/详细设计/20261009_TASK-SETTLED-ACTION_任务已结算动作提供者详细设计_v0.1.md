# TASK-SETTLED-ACTION 任务已结算动作提供者详细设计

日期：2026-10-09

版本：v0.1

基线：`fb086b69e53c154c07d8241574fcede0c489715f`

## 1. 本叶目标和明确排除

实现 task owner 的已完成→已结算，以及发生前的内部治理动作；内部目标是任务 Vt，不伪装成世界存在。普通服务值改变及其效果确认由后继本能消费者完成，本叶不加服务值、不登记结算本能、不建立或改写需求、不改根目标、不自动选择来源任务。

本叶只修改任务虚拟存在的状态特征，原因是在调用方已独立确认普通服务值结算结果后结束来源任务结算资格，目的为避免已结算任务再次作为完成任务参与结算。内部动作与普通结算动作为两个不同动作事实。本叶不把动作存在等同于效果确认。

依据为本轮用户明确裁决、4220一来源一动作与跨owner部分结果边界。工程错误由返回载荷明确报告，调用边界后续负责日志/弹窗/停止；本叶领域提供者不能自行弹窗，也不把工程错误转成任务已失败。

## 2. 可复用事实与代码范围

复用任务类已有唯一Vt、状态F、任务锁、`写入已核验任务状态值`及其写后fresh读回；复用动态类的动作来源唯一性、动作完整读取/删除、场景添加动态与引用计数。新增Vt强类型引用合同；扩展动作目标类别，不放宽普通动作目标。

不修改世界树、本能函数、方法、需求、自我或任务管理线程、普通应用装配及共享规范。新增头是共同依赖，无cpp、全局实例或第二事实仓。

## 3. Vt只读核验合同

新增头完整声明：

```cpp
struct 新任务虚拟存在引用 final {
    稳定编码 任务节点;
    稳定编码 虚拟存在节点;
    稳定编码 状态特征节点;
    friend bool operator==(const 新任务虚拟存在引用&,
        const 新任务虚拟存在引用&) = default;
};
struct 新任务虚拟存在读回 final {
    新任务虚拟存在引用 引用;
    稳定编码 状态特征类型概念节点;
    std::int64_t 当前状态;
};
class 新内部治理对象读取接口 {
public:
    virtual ~新内部治理对象读取接口() = default;
    virtual std::optional<新任务虚拟存在读回> 读取任务虚拟存在引用(
        const 新任务虚拟存在引用&) const noexcept = 0;

```

`新_任务类 final : public 新内部治理对象读取接口` 实现该接口，并新增 `std::optional<稳定编码> 获取任务状态特征类型() const noexcept`。读取必须经现有task结构验证任务、其唯一Vt和状态F全部相等，再从F取得当前状态和所属FT；不能仅检验三编码存在。无值表示未取得合法读回，不提供业务状态默认值。动态建立把无值映射为目标不合法/结构失败，调用层不得当作普通效果失败。

## 4. 动作目标与动态提供者

`新_动态类.h`新增：

```cpp
enum class 新动作目标种类 : std::int64_t {
    普通存在 = 1, 任务虚拟存在 = 2
};
struct 新内部治理动作动态建立请求 final {
    稳定编码 执行主体节点;
    稳定编码 动作定义节点;
    稳定编码 动作来源节点;
    新任务虚拟存在引用 目标;
    新状态强时间 动作时间;
};
新动态建立结果 新_动态类::建立内部治理动作动态(
    const 新内部治理动作动态建立请求& 请求,
    const 新内部治理对象读取接口& 目标读取服务) noexcept;
```

`新动态信息`增加动作目标类别（普通存在默认）及可选`动作目标任务虚拟存在`。普通动作完整读回必须有旧`动作目标存在节点`并无内部目标；内部动作必须有新强类型目标并无普通目标，`动作目标特征节点`等于Vt状态F。二者不能同时有值。

持久结构新增目标种类、内部目标任务、内部目标Vt三个字段；状态F继续用动作目标特征字段。新建动作总是写显式种类。旧无种类字段且只有旧普通目标的动作按旧普通存在合同读回；其它缺/多/混合字段拒绝。所有字段编码仍由全局基础数据集分配，不能硬编码节点身份。

内部动作请求的主体必须是正式真实存在；定义/来源必须是正式存在的稳定节点；强时间合法。先在动态锁外调用目标读取接口，校验完整目标相等及状态F/FT有效，再进入动态锁写入。这样不能在持有动态锁时反调task锁。读取接口只作输入核验，不执行任务状态修改。

动作来源仍共享唯一索引：同来源同完整主体、定义、目标种类、强类型目标、时间精确复用；任一不同冲突；普通/内部动作不能使用同一个来源编码。新建/复用通过现有`已完成/无变化`返回，非成功不得携带伪完整动态。

普通 `建立动作动态` 保持原真实存在要求。`获取动态`、删除字段清理、按主题查询及精确重放都需覆盖新目标类别；不得只改建立路径。读取内部动作检查结构、引用存在和互斥字段，不反调task owner；历史动作描述当时的目标，不要求任务当前仍完成。内部动作不制造实例概念、普通世界状态或结果动态。本叶不扩展 `关联动作结果` 支持Vt结果；该入口遇内部目标明确拒绝，不崩溃、不套用普通存在字段。

## 5. 场景中立挂接

修改`新_场景类::添加动态`动作分支：真实执行主体必须属于该场景范围；普通目标仍同时要求其属于场景范围；内部目标按动态完整读回的强类型字段核验其结构，不要求Vt有场景归属。不把Vt加入场景存在列表，不反向包含任务类。现有同动态同场景幂等、跨场景拒绝和引用计数合同保留。

## 6. 任务收尾入口与状态迁移

`新任务状态::已结算 = 12`，旧值不变。合法状态读区间与任务状态FT总域扩到12。初始化读到原`[1,11]`状态类型时由task owner使用已有概念值域修改能力扩大到`[1,12]`，保护原身份；只接受该明确旧域或新域，其它域不猜修。任务完成子域等不修改。

终结列表排除已结算任务；通用状态迁移禁止任意调用者写入已结算。`重新启用任务`仍只接收旧已完成/已失败/已取消，明确拒绝已结算，不能因复用终结谓词自动扩大重启权限。其余数值范围与终结使用点须全检索适配。

任务头新增精确DTO：

```cpp
struct 新任务已结算请求 final {
    稳定编码 来源任务节点;
    稳定编码 执行主体节点;
    稳定编码 发生场景节点;
    稳定编码 内部动作定义节点;
    稳定编码 已确认普通动作节点;
    新状态强时间 内部动作时间;
};
enum class 新任务已结算状态 : std::uint8_t {
    已标记 = 1, 已是已结算, 来源任务不具备,
    入口拒绝, 结构不一致, 动作建立失败, 动作挂接失败,
    既有动作未收尾, 状态写入失败, 已写入但读回失败, 资源失败
};
struct 新任务已结算结果 final {
    新任务已结算状态 状态 = 新任务已结算状态::入口拒绝;
    std::optional<稳定编码> 内部动作节点;
    std::optional<新任务虚拟存在读回> 任务读回;
};
新任务已结算结果 新_任务类::标记任务已结算(
    const 新任务已结算请求& 请求,
    新_动态类& 动态服务) noexcept;
```

该入口是调用方已经确认普通效果之后的内部治理命令。字段名“已确认”是调用前置合同，不是task owner凭动作存在推导的验证结论。任务类只核验传入动作是完整普通动作、其来源等于来源任务、主体为传入真实主体、动作时间严格早于内部动作时间；不得报告自己已核验加值。本叶不接受简单布尔值来替代动作身份，也不判断服务值、对服务结算量作计算或核验MAX饱和。普通效果完整确认责任明确留在后继外层消费者；本叶报告不能称普通效果闭环。

内部动作来源=`已确认普通动作节点`，定义=`内部动作定义节点`，目标由task owner自己从来源任务获得Vt/F；调用方不能指定另一Vt。动作定义由上层正式内部治理定义节点提供，本叶只验证身份存在，不用任务节点/字符串假装定义。来源普通动作的来源固定为该来源任务，是本轮单次完成任务治理身份；不得临时换来源绕过已有动作。

事务顺序：

1. 输入、动作/主体/场景身份和时间校验不通过零写入。
2. 持task递归互斥完整取得当前任务及Vt；非完成且非已结算返回来源任务不具备。已结算通过同普通动作/内部来源只读定位后返回已是已结算，不新建动作或改状态；找不到其内部动作为结构不一致，不能伪称本次精确重放。
3. 保持task锁防止同任务并发重启/状态修改。调用动态内部动作入口时目标读取回调先于动态锁且只递归进入本线程task锁。任何新动态读取不得在动态锁内反调task，场景读取亦不得反调task，固定锁序为task→dynamic/scene。
4. 新动作先建立，再以已有`场景服务_`挂接。任一失败保留已发布动作并返回相应失败，不写已结算、不自动删动作或重做。没有普通效果回滚。
5. 只有动作新建且挂接成功，才调用现有已核验状态写入helper改为12。若动作是复用且任务仍完成，返回既有动作未收尾并停止；不自动恢复写状态。
6. fresh读回Vt状态。已读到12按已标记返回；若底层报告后段聚合失败而fresh仍12，保留已发生状态并使用现有helper收敛，不再写第二次。无法判断当前值则已写入但读回失败；仍旧9则状态写入失败。返回保留内部动作ID。

执行期间不得在锁内记录弹窗或调用用户报告端口。调用者依据这些结构化状态决定日志/弹窗/停止；已标记/已是已结算之外的工程状态不能当作业务任务失败或自动重复普通加值。

## 7. 验证与证据边界

必须运行：合法完整普通动作经外层测试明确表示已确认，来源任务完成→内部动作新建且入场景→状态12；调用前后服务值完全不变；Vt未进入普通存在或场景成员；普通动作/内部动作身份和来源不同；普通目标路径回归；伪Vt/错任务F/错动作来源/主体不在场景/时间错配零状态写入；重复调用不新增动作；已有内部动作但状态仍9明确停止；已结算不能重新启用；任务列表/状态读取识别12；动作删除/引用保护/场景跨挂接回归。

失败矩阵至少覆盖动作建立、场景挂接、状态写入、写后读回四位置。测试无法真实注入的分支写NOT_RUN，不能把静态检查冒充运行。提供者无UI测试需求；日志和弹窗属于后继调用边界。
