## 1. 目标与完成边界

本叶建立一个真正由第二层业务拥有的生产读取能力：`L1实际存在场景组合服务::读取初始场景完整事实`。它从正式初始场景请求出发，返回该场景的直接子场景、直接存在成员以及每个成员的完整实际存在事实。

本叶是 P11 第一层“源节点 + 关系类型”当前关系组查询的首个具名生产消费者。第二层负责解释场景资格、关系方向、角色、单父、局部无环、世界归属、共同截止和业务排序；第一层仍只返回中性当前关系事实。

本叶不让第一层自证。代码、构建和静态检查只能证明生产候选成立；只有生产代码外的合法第二层消费者经正式运行期会话和有效租约调用本入口，取得结构化结果并通过同一入口的最终权威读回，才累计证明本叶实际使用的第一层能力得到覆盖。单次覆盖不推出第一层整体完善。

## 3. 职责分解与依赖方向

固定依赖如下：

```text
L1实际存在场景组合服务
  -> L1场景结构服务
       -> L1事实基座服务::读取中性当前源关系组
       -> L1事实基座服务::读取中性当前目标关系组
       -> 其它既有中性精确读取
  -> L1实际存在服务::读取当前实际存在资格
  -> 初始场景实际存在原子发布服务::读取初始场景实际存在
```

场景服务拥有场景标记、直接父和直接成员关系的业务解释；实际存在服务拥有资格属性和值的解释；原子发布服务拥有初始场景实际存在的跨事实完整读回；组合服务只编排三者并互证，不取得第一层或两个领域的写入权。

不得建立 `L1场景结构服务 -> L1实际存在服务` 反向依赖，不得让组合服务访问第一层、仓库、索引、完整快照、SQL、材料、缓存、锁、事务或日志。

### 4.3 固定读取流程

1. 无效 `初始场景读取请求` 返回 `入口拒绝`、空事实。
2. 读取当前世界登记；非成功按既有 `登记状态` 映射，登记必须为 `已读取`，世界根、合同和规则与请求一致。
3. 读取一次第一层起始事实代次，必须成功且非零。
4. 调用既有 `读取实现` 取得请求中的初始场景事实；必须为 `已读取` 且截止等于起始代次。
5. 以 `源=初始场景、类型=登记.直接父场景关系类型` 调用 P11 源关系查询一次，枚举直接子场景边。
6. 以 `源=初始场景、类型=登记.直接成员关系类型` 调用 P11 源关系查询一次，枚举直接成员边。
7. 对每条子场景边，精确读取目标节点、场景标记属性槽、标记值、标记属性类型和来源服务节点；再以 `目标=子场景、类型=直接父场景关系类型` 调用 P10 目标关系查询，结果必须恰一项且与源查询中的关系逐字段全等。
8. 对每条成员边，精确读取目标节点；再以 `目标=成员、类型=直接成员关系类型` 调用 P10 目标关系查询，结果必须恰一项且与源查询中的关系逐字段全等。
9. 读取一次第一层结束事实代次。起始、结束、初始场景、两个源关系组和全部逐项读取的事实代次必须等于同一非零截止；任一不等返回 `版本漂移`、空事实，不重试。
10. 形成完整结构事实并稳定排序。合法零子场景或零成员返回 `已读取` 和空组。

### 4.4 场景业务不变量

直接子场景必须同时满足：

- 关系类型等于登记的直接父场景关系类型；源端等于请求初始场景；目标端等于子场景；角色为零；关系当前有效；
- 子场景是当前普通节点，不是请求初始场景或世界根；
- 子场景恰有一个当前直接父关系，且该关系就是本次枚举关系；
- 子场景恰有一个登记场景标记属性槽；值为 I64 `1`，所属节点为子场景，属性类型和来源分别等于世界登记中的场景标记属性类型和服务身份；
- 初始场景已有唯一父关系 `世界根 -> 初始场景`，子场景又以初始场景为唯一父，因此本次返回的“世界根、初始场景、直接子场景”可达范围内无环。

直接成员必须同时满足：

- 关系类型等于登记的直接成员关系类型；源端等于请求初始场景；目标端等于成员；角色为零；关系当前有效；
- 成员是当前普通节点，且不等于世界根、初始场景或任一直接子场景；
- 成员恰有一个当前直接成员关系，且该关系就是本次枚举关系；
- 同一编码不能在直接子场景组和直接成员组同时出现。

任何重复关系、重复目标、错方向、错类型、非零角色、多父、多归属、悬空节点、错标记、跨组重复或坏成功都返回 `内部不一致`、空事实。第一层非成功按既有读取状态映射；合法零命中不降级为未找到。

本入口只证明请求初始场景及其直接边的业务完整性，不扫描全仓，也不证明不存在从世界根不可达的孤儿节点或其它分支中的坏事实。

### 4.5 排序

- 直接子场景组按 `子场景.编码` 升序，编码相同再按 `直接父关系.编码` 升序；任何相同子场景或相同关系均拒绝；
- 直接成员组按 `成员.编码` 升序，编码相同再按 `归属关系.编码` 升序；任何相同成员或相同关系均拒绝；
- 不使用容器迭代顺序、内部句柄、显示名称、创建顺序或日志顺序。

### 5.2 唯一实现与锁边界

在实际存在服务私有实现区抽取“已持有服务锁时按存在和可选资格值读取资格”的唯一 helper。两个公开入口各自只取得一次既有服务锁：

- 旧入口把调用方显式资格值传给 helper；
- 新入口先从当前登记得到资格属性类型，再以当前属性读取取得资格值编码，并把它传给同一 helper；
- 不允许新入口在持锁时递归调用旧公开入口，也不改为递归锁；
- 属性不存在或存在未找到返回 `未找到`；属性成功却无值、值/槽/登记矛盾返回 `内部不一致`；
- 起始、登记、节点、类型、来源、属性、值和结束必须同一非零截止，漂移返回 `版本漂移`；
- 返回仍为既有 `实际存在资格事实`，不暴露属性槽内部容器、登记定位或第一层对象。

### 6.2 唯一生产入口

在既有 `L1实际存在场景组合服务` 新增：

```cpp
初始场景完整事实结果 读取初始场景完整事实(
    const 初始场景读取请求& 请求) const;
```

固定流程：

1. 调用 `场景服务_.读取初始场景完整结构(请求)` 恰一次；非成功原状态返回，坏成功映射 `内部不一致`。
2. 直接成员组为空时，实际存在资格入口和原子发布读取入口调用数均为零，直接形成成功空组。
3. 对每个直接成员，调用 `实际存在服务_.读取当前实际存在资格` 恰一次；必须得到该成员的当前资格且截止等于场景结构截止。
4. 由请求、成员结构项和资格事实机械形成 `实际存在读取请求`：合同/规则来自正式常量，请求场景原样使用，存在编码来自成员，资格值编码来自资格事实，当前场景归属关系来自成员结构项。
5. 调用 `发布服务_.读取初始场景实际存在` 恰一次；必须返回 `已读取` 和完整事实。
6. 逐字段互证世界根、当前场景、存在、资格、归属关系和共同截止；关系必须与场景结构项全等，资格必须与资格定位读取全等。
7. 任一成员非成功、坏成功、字段矛盾或截止漂移都销毁整组并返回一个非成功结果，不保留部分成员。
8. 成员完整事实组按 `存在.编码` 严格升序；数量必须与场景结构直接成员组相等且一一对应。

组合服务不重试、不缓存、不写入，不调用第一层、P11、完整快照、SQL、材料或日志。

### 6.3 状态映射

场景结构状态原样保留。实际存在读的 `入口拒绝`、`版本漂移`、`许可拒绝`、`资源失败` 分别映射同名世界结构状态；枚举出的当前成员若资格或组合事实 `未找到`，说明场景结构与成员事实矛盾，映射 `内部不一致`；写状态、幂等冲突、未知状态或成功无事实都映射 `内部不一致`。

## 7. 并发、异常与生命周期

1. 三个入口都返回调用方拥有的值式副本，不返回内部容器或引用。
2. 场景服务和实际存在服务各自只使用既有互斥锁；组合服务不加跨服务锁。
3. 共同截止通过各具名服务结果和第一层首末代次互证，不把锁或许可跨服务传递。
4. `bad_alloc` 映射 `资源失败`；其它异常映射 `内部不一致`；非成功不带部分事实。
5. 任一调用期间有发布导致代次变化，本轮返回 `版本漂移`；本叶不隐式重试、等待或 sleep。
6. 当前阶段不验证崩溃、重启、断电、持久恢复或跨进程材料。

这次真实运行最多累计证明：初始场景完整事实生产入口成立；P11 源 + 类型查询在直接成员一项到零项场景中被第二层真实消费；P10 目标 + 类型查询与精确节点 / 属性 / 值读取共同支撑局部业务完整性。
