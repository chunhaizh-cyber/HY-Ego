# INSTINCT-STAGE3-TD-CURRENT-GROUP-READBACK 任务来源需求关系组正式读回详细设计 v0.1

日期：2026-08-30

## 1. 目标与边界

在现有唯一 `L2任务结构服务` 内补齐显式 `T→D` 关系的生产写入和按任务、按共同事实截止 `G0` 的完整组读取，使后继服务活动裁决能够逐项互证 `服务事实.需求 + 服务事实.T到D关系稳定编码`，禁止从需求身份组、列表项、查询锚点或容器位置补造关系事实。

本叶只形成 task owner 的中性关系事实和只读 provider：

- 生产 `新增任务与首次初次筹办准备记录` 同事务追加首个 `T→D`；
- 兼容 `新增任务` 保持零 `T→D`，用于证明 `0` 项成功，不取得新生产资格；
- 读取返回 `G0` 当前活动的 `0/N` 完整关系组；
- 任务退出时同步退出该任务全部当前 `T→D`；
- 不实现有效服务活动、安全门禁、服务进展 / 准备发布者、FRESH、任务结果结算或任务正式存在切换。

当前生产安全根定义版本 1、值域 `0..I64_MAX`、`L=2,767,011,611,056,432,742`、`H=7,378,697,629,483,820,645` 保持不变；“浮动”仍只表示后继定义版本可调整，本叶不得增加运行期自动变化。

2. 已发布 task owner 没有 `按任务读取来源需求关系组` DTO 或函数，也没有专属 `T→D` 关系类型登记；

4. 旧 `新增任务` 只被兼容 / 测试路径消费，继续允许形成没有显式来源需求关系的任务；
5. 工作区 task 两文件存在更大范围未提交 WIP；本叶从 `HEAD` 合成精确最小候选，发布时只把本设计冻结的差异写入 index，其余 WIP 原地保留。

## 4. 结构登记与兼容

在现有 task owner 下使用已冻结但未被已发布代码消费的键：

```text
任务来源需求关系类型键 = 0x0301'2114
任务正式存在关系类型键 = 0x0301'2115
后继核心类型登记幂等身份 = 0x4C32'5452'434F'5245
首次融合 T→D 写入本地键 = 0x0301'2613
```

现有 `任务结构类型登记幂等身份` 的十项请求绝对不改，否则恢复旧持久库会发生同键异义。新增 module-private 登记函数以独立幂等身份一次登记上述两个类型节点，并把编码填入现有类型定位。`任务正式存在关系类型` 本叶只为保持已冻结同幂等登记形状而登记，不建立任何 `T→E` 事实，也不宣称正式存在切换完成。

首次、精确重复和跨进程恢复都必须逐项核对两项映射；缺项、额外项、错本地键、无效编码或不同首次请求均在服务构造阶段 fail-closed。

## 5. 生产写入与退出

### 5.1 首次融合写入

`形成初次筹办融合写集` 在既有任务—列表项关系后追加：

```text
源 = 本次新任务节点
目标 = 请求.首次需求裁决.需求事实.身份
类型 = 任务来源需求关系类型
角色 / 来源顺序 = 1
本地键 = 0x0301'2613
```

它与任务、首次准备记录和统一筹办轮次继续处于同一个 task owner 写集。写入编码映射、首次结果读回和精确重复读回必须增加该关系并逐字段验证；任何缺项、错端点、错类型、错顺序、混代或退出均使整个首次融合结果失败，不允许任务成功但 `T→D` 缺失。

不把关系复制进 `L2任务事实` 或首次结果 DTO；消费者只经公开完整组读取取得关系。

### 5.2 任务退出

`退出任务` 的同代退出集合追加当前全部 `任务来源需求关系类型` 源关系。它允许 `0/N`，但每项必须属于本 task owner、源为请求任务、类型正确、顺序为 1、目标需求节点有效且关系当前活动。任何坏成员使退出写前失败；不得只退出任务节点留下当前 `T→D`。

历史关系仍可由 L1 历史事实审计；公开本叶入口只返回当前活动组。

## 6. 读取算法

```text
校验专属版本、共同头、G0 和任务
-> 读前中性当前事实代次必须等于 G0
-> owner-aware 一致当前投影读取：task owner、任务节点、任务源 T→D 关系组
-> 任务不存在 / 已退出分账
-> 逐成员验证 task owner 关系、端点、类型、顺序、生命周期和目标需求节点当前有效
-> 重建强类型关系事实
-> 按需求身份、关系身份规范排序
-> 关系身份重复或排序闭包异常 => 引用冲突
-> 读后中性当前事实代次必须等于 G0
-> 绑定结果任务和正式读回截止
-> 结果自身成功谓词与请求后置条件复核
```

禁止从 `L2任务事实.需求列表项`、需求列表成员组、当前选择的来源需求组、服务事实或缓存补造 `T→D`。

## 7. 状态矩阵

| 条件 | 公共状态 | 载荷 |
| --- | --- | --- |
| `0/N` 完整当前关系 | `已读取` | 任务、规范组、截止 `G0` |
| 坏专属版本 / 共同头 / 零 G0 / 坏任务 | `入口拒绝` | 空 |
| L1 许可拒绝 | `许可拒绝` | 空 |
| 任务从未存在 | `未找到` | 空 |
| 任务在 G0 已退出 | `已退出` | 空 |
| 读前 / 读后代次不同 | `事实代次漂移` | 空 |
| 错 owner / 端点 / 类型 / 顺序 / 生命周期 / 重复关系 | `引用冲突` | 空 |
| `bad_alloc` / `length_error` | `资源失败` | 空 |
| 其它异常或下层矛盾 | `内部不一致` | 空 |

全部非成功只保留固定合同版本和对应公共结果头；结果任务无效、组空、截止 0。重复只读仍为 `已读取`，不返回 `精确重复`。

## 8. 验证与完成边界

验证至少覆盖：结构登记首次 / 精确重复 / 恢复；生产首次融合形成单项 `T→D`；兼容任务 0 项；验证缝形成逆序 N 项并证明规范排序；结果值式谓词拒绝乱序 / 重复；关系退出后组缩减；任务退出后入口返回已退出；坏请求、未找到、旧 G、坏端点、读中漂移、资源失败；Debug / Release 根工程、公开 ABI consumer 和 strict / diff-check。

本叶完成只证明 task owner 能在生产首次任务融合中形成首个显式 `T→D`，并能按任务和 `G0` 完整读取当前 `0/N` 关系组。它不证明服务进展 / 准备生产发布、任务选择仍当前、安全门禁允许、有效服务活动成立、阶段三或 `INSTINCT-ROUTE` 完成。
