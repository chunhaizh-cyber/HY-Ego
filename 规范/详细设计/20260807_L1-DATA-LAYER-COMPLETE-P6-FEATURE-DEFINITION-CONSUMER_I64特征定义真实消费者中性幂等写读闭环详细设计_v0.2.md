## 1. 来源问题与唯一裁决

候选提交 `3faf31fcecdd38e86816d1318f7ae4bb5c10e0da` 已按 v0.1 完成唯一
`L1特征定义服务` 的中性 CRUD 迁移，Debug/Release 构建和正式 `--runtime-context`
均已通过；这些结果只证明代码候选可编译、可链接和生产启动成功。

独立验收从正式生产边界发现：

```text
生产运行期会话::启动
-> 生产运行期启动结果::租约
-> 运行期上下文租约::读取() const
-> const 运行期上下文*
-> 运行期上下文::读取L1特征定义服务() const
-> const L1特征定义服务&
```

而 v0.1 保留的两条写函数只有非 `const` 成员形态，合法调用方无法调用：

```cpp
特征定义登记结果 建立登记(const 特征定义登记请求& 请求);
I64特征定义结果 建立I64特征定义(const I64特征定义建立请求& 请求);
```

不得用 `const_cast`、验收专用入口、直调 L1、返回可变运行期上下文或公开 L1 服务来绕过。
唯一最小裁决是：在同一具名领域服务上增加同请求、同结果、同机器语义的 `const` 写重载，
保留既有非 `const` 重载作兼容入口；两种调用形态进入同一实现和同一服务锁。租约、上下文、
L1、DTO、合同版本、规则版本及 v0.1 的中性写集、幂等和权威读回语义均不改变。

## 3. 最小合法写消费边界

### 3.1 公开函数

唯一服务、模块和文件保持：

```text
模块：海中鱼巣.领域.服务.L1特征定义
文件：海中鱼巣/领域/服务.L1特征定义.ixx
类：L1特征定义服务
```

既有四条公开函数保留；两条写函数增加 `const` 重载：

```cpp
特征定义登记结果 建立登记(const 特征定义登记请求& 请求);
特征定义登记结果 建立登记(const 特征定义登记请求& 请求) const;

特征定义登记结果 读取当前登记() const;

I64特征定义结果 建立I64特征定义(const I64特征定义建立请求& 请求);
I64特征定义结果 建立I64特征定义(const I64特征定义建立请求& 请求) const;

I64特征定义结果 读取I64特征定义(
    const I64特征定义读取请求& 请求) const;
```

非 `const` 重载只把调用转给同对象的 `const` 重载，不复制算法、不另取锁、不改变结果。
`const` 重载拥有 v0.1 已冻结的完整写入算法。这里的 `const` 只表示调用方不能改变服务对象
身份、装配和其它上下文成员；写入副作用仍严格属于具名领域服务公开合同，并由强类型请求、
业务准入、服务锁和 L1 中性事务约束。

### 3.2 内部可变性

服务成员保持：

```cpp
L1事实基座服务& L1_;
mutable std::mutex 锁_;
mutable std::optional<std::array<稳定编码, 4>> 登记定位_;
```

`L1_` 仍是服务私有依赖；消费者不可见、不可取得。`登记定位_` 只在登记首次/精确重复经
中性提交和权威读回完整后写入，仍是非权威定位。const/non-const 两种入口均在同一 `锁_`
临界区内完成请求校验、提交、读回和定位确认；不存在两套缓存、两把锁或跨入口竞态。

### 3.3 生命周期与调用规则

正式调用方必须在整个调用和读回期间持有有效 `运行期上下文租约`：

```cpp
生产运行期会话 会话;
const auto 启动结果 = 会话.启动({生产运行期启动请求当前版本});
const auto* 上下文 = 启动结果.租约.读取();
const auto& 服务 = 上下文->读取L1特征定义服务();
const auto 登记结果 = 服务.建立登记(登记请求);
const auto 定义结果 = 服务.建立I64特征定义(定义请求);
```

调用前必须验证 `启动结果.成功()`、租约有效且上下文非空。服务引用不得保存到租约生命期
之外，不得跨上下文比较地址或把地址解释为稳定身份。会话、宿主和租约仍只负责上下文首发、
存活与只读定位，不代理请求、不解释结果、不授予 L1 权限。

## 4. 继承的机器合同

下列内容完整继承 v0.1，不因本次接口可达性修订改变：

1. 登记固定 4 节点、定义固定 1 节点 + 3 值 + 3 槽，两次分别恰一次 `提交中性写集`；
2. 登记键域 `0x03`、定义键域 `0x04`，完整中性请求由 L1 裁决精确重复和冲突；
3. `下界 > 上界` 写前拒绝且 L1 调用 0；
4. 服务只保存登记四编码定位，每次公开读取都回到 L1 权威当前事实；
5. 登记和定义读回均执行首末事实代次校准与逐字段完整性检查；
6. 中性写入/读取状态到特征定义状态的映射、坏成功处理和零部分事实边界不变；
7. 合同版本 1、规则版本 1、DTO 字段、枚举稳定值和幂等身份语义不变；
8. 不恢复预探测、业务标签、执行证据、完整快照或 legacy 写入。

新增 const 重载是对同一领域服务的兼容可调用形态，不建立新业务合同版本或第二服务身份。

## 6. 验收路径与矩阵

代码发布后，独立验收绑定新候选提交，从生产目标之外编译普通调用器；调用器只 import
`海中鱼巣.启动.生产运行期`，不得 import L1 模块。固定路径为：

```text
生产运行期会话::启动
-> 成功结果与有效租约
-> const 运行期上下文*
-> const L1特征定义服务&
-> const 建立登记
-> const 建立I64特征定义
-> const 读取I64特征定义
```

至少覆盖：登记首次、定义首次、定义精确重复、同键不同合法值域冲突、非法值域拒绝，以及
冲突/拒绝前后正式定义读取逐字段零变化。编译探针必须显式使用 `const auto& 服务`，并静态
确认两条 const 重载可调用；不得用非 const 上下文、`const_cast`、日志解析或 L1 直调补格。

Debug/Release Rebuild、两配置 `--runtime-context`、模块扫描、strict 和白名单检查仍是施工
门禁，但不能代替上述公开入口与权威终态验收。
