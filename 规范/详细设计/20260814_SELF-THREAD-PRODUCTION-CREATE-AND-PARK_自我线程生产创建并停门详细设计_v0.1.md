# SELF-THREAD-PRODUCTION-CREATE-AND-PARK 自我线程生产创建并停门详细设计 v0.1

日期：2026-08-14

状态：待激活设计；源码仅为未登记预 ABI 候选

## 1. 目标和结论

方法登记根生产初始化真实成功并正式读回后，普通应用上下文持有唯一 `自我线程` 对象，以本轮 I2 根消费材料和 SELF-FORM 正式读回材料创建一个物理线程候选。成功必须同时成立：

```text
候选创建成功
+ 线程入口真实进入
+ 治理运行门仍关闭
+ 内部停门见证已经发布
+ 治理邮箱已冻结批次数量为0
+ 唯一线程租约仍由普通应用上下文持有
```

阶段 20 冻结为 `自我线程创建并停门 = 20`。创建失败、入口未进入、停门失败和启动候选不能在诊断时限内安全回收都映射阶段 20；既有程序结果中的旧 `自我线程启动 = 4`、`自我线程初始化 = 5` 不得复用为本叶。

本叶没有新的 DATA-L1—L3 服务需求。阶段 18 四本体根和阶段 19 方法登记根结果只作调用顺序门，不进入请求；线程不得反向建立或选择世界根、自我、概念本体根或方法登记根。

## 2. 正式依据和当前事实

正式依据：0050、8100、8110、8120 v0.10、BIZ-L1-T01、BIZ-L2-001-03、BIZ-L3-001-03-11、BIZ-L4-001-03-11-01。

当前代码事实：

- `有界自我治理邮箱` 已提供提交、等待冻结、停止唤醒和快照；本叶只构造与读取快照，不调用冻结入口；
- `任务管理线程`、`运行宿主线程` 可参考 `std::thread` 和 join 管理，但不具有自我线程关闭门、运行代次或内部见证合同；
- 当前没有受跟踪的 `自我线程` 模块；旧 `BIZ-L3-001-03-02—04` 永久历史冻结；
- 当前运行消息协议不能冒充 8110 生命周期服务；`THREAD-LIFECYCLE-PROJECTION-SERVICE v0.1` 已形成通用发布/读取预 ABI 和未提交源码候选，本包只机械消费，保持真实装配与运行接线 `NOT_RUN`；
- SELF-FORM 真实源码仍未发布，故两份候选源码不登记工程、不编译，最终输入 DTO 只按 v0.2 设计机械匹配。

## 3. 输入、输出与事实边界

### 3.1 唯一业务材料

请求中只有两份值式业务材料：

1. `自我世界树根消费材料`：必须来自本轮 I2 正式再读回；
2. `真实自我事实`：必须来自 SELF-FORM 共同截止正式读回。

两份材料必须指向同一现实世界树和同一根场景，事实截止均非零。它们是线程启动上下文，不是长期权威事实；后继治理需要当前事实时仍须经正式服务重读。

非业务运行配置只含：合同版本、非零创建幂等身份、线程逻辑身份、运行代次、治理邮箱容量、入口停门等待毫秒、失败回收诊断毫秒。普通应用运行身份分配器必须为该上下文形成非零逻辑身份和单调运行代次；它们不从名称、地址、系统线程 ID、日志或业务节点派生，也不取得业务事实权。等待时限只控制本次调用，不属于创建幂等语义；同一创建意图重试可以使用新的非零等待预算。

### 3.2 结果和成功形状

成功状态只有 `已创建并停门 / 精确重复`，且必须携带完整 `自我线程停门见证`：非零逻辑身份与运行代次、非零且严格递增的入口/停门见证序号、关闭门投影、治理邮箱运行中且已冻结批次数为 0。

非成功分账：请求无效、已发布选择冲突、线程候选创建失败、线程入口未进入、治理运行门停驻失败、启动候选回收超时、资源失败、内部不一致。非成功不得携带停门见证；生命周期投影结果可以作为诊断材料保留，但不能改变 `成功()`。

## 4. 物理归属与公开 ABI

| 文件 | 分类 | 唯一所有者 | 工程合同 |
| --- | --- | --- | --- |
| `海中鱼巣/线程/自我线程生产创建.数据.h` | 单头数据结构 | `海中鱼巣.线程.创建.自我线程` | 激活时 `ClInclude`；只由唯一模块包含，无 `.cpp`，因为只有稳定 DTO 和自身不变式 |
| `海中鱼巣/线程/创建.自我线程.ixx` | 真实模块 | 自我线程运行租约、关闭门和见证 | 激活时 `ClCompile`；唯一 `export module 海中鱼巣.线程.创建.自我线程`；调用方只 `import` |

公开类：

```cpp
class 自我线程 final {
public:
  explicit 自我线程(线程生命周期发布端口* 生命周期发布端口) noexcept;
  自我线程生产创建结果 创建并使自我线程停在治理运行门(
      const 自我线程生产创建请求& 请求) noexcept;
  自我线程启动候选回收结果 收口启动失败候选(
      std::uint64_t 完成等待毫秒) noexcept;
  std::optional<自我线程停门见证> 读取停门见证() const;
};
```

对象不可复制、不可移动。普通应用上下文必须先构造并持有唯一对象，再调用创建函数；对象析构顺序早于其生命周期端口和业务材料所有者。线程候选、邮箱、锁、条件变量、锁定请求、运行代次和见证均为该对象私有运行态，不是机器业务事实。

`线程生命周期发布端口` 由 `海中鱼巣.线程.投影.线程生命周期` 唯一拥有，是 BIZ 运行基础设施依赖，不属于 DATA-L1—L3。自我线程不得再声明私有逻辑身份、生命周期枚举、请求/结果或发布端口。通用请求承接 8110 的稳定消息身份、逻辑线程身份、可选系统线程 ID、线程类别、所属模块、生命周期、前一投影、原因键、时间和版本；在 provider 正式发布前仍只能视为预冻结合同。

## 5. 创建与停门状态机

固定顺序：

```text
校验完整请求
-> 首个线程创建前锁定同上下文选择
-> 已发布同请求直接返回原停门见证；异请求零线程创建
-> 采用请求中的逻辑身份、运行代次，构造邮箱和关闭门
-> 普通应用已持有对象租约后创建唯一 std::thread
-> 线程入口发布内部进入见证
-> 确认门关闭且停止未锁存
-> 发布更晚的停门见证并通知创建方
-> 线程在条件变量上释放锁等待门开放或停止
-> 创建方以 steady_clock 单调时限等待停门或完成
-> 读取邮箱快照并证明零冻结批次
-> 完整候选无抛出发布
```

生命周期发布在状态锁外最佳努力调用。创建、启动中、等待、停止请求中、退出前、已退出均只作 8110 投影；自我线程使用通用事件序号、固定类别/模块身份和服务端当前性，不因失败重试清零事件序号。停止回收必须先锁存停止、锁外发布停止请求，再唤醒门等待；工作线程的退出前事件以前述停止请求为物理前态。端口竞争失败只造成具名序号缺口，不能改写线程真实前态。线程入口异常还须最佳努力发布故障/异常退出诊断，同时保留内部原子完成见证作为回收依据。端口缺失或发布失败不能伪造内部见证，也不能把未停门候选升级为成功。正式激活前必须机械匹配正式 provider ABI 并完成装配。

## 6. 并发、门和邮箱

独立创建调用序列锁覆盖完整创建调用和外部启动失败回收调用，保证首个调用在停门等待释放状态锁时，同请求并发也不能进入第二候选判断。对象状态锁只保护请求选择、门、停止锁存、线程状态和见证；条件变量等待必须释放状态锁，但不释放创建调用序列锁。不得在持有状态锁期间调用生命周期端口、日志、DATA、用户回调、文件或数据库。

同请求并发由创建调用序列锁完整串行：首次发布前只有一个候选；成功后每次精确重复只返回值式见证，不新建线程。幂等语义比较覆盖合同版本、创建身份、逻辑身份、运行代次、两份业务材料和邮箱容量，但不覆盖本次调用等待预算。异请求在任何线程创建前冲突。运行门初始且成功时固定关闭；本叶没有开放入口。BIZ-L2-001-08 后继只能在同一对象上读取/确认门并等待治理进入见证，不得建立第二门或第二线程。

线程入口在门开放前禁止调用 `有界自我治理邮箱::等待并冻结下一批`。因此创建成功时 `已冻结批次数量 == 0` 是内部后置条件；待处理消息数不是本叶业务成功来源，但正常启动顺序下生产者仍未开放。

## 7. 失败回收与截止

失败候选固定按：

```text
锁存停止
-> 唤醒关闭门等待
-> 等待内部完成见证
-> 完成后移动并 join
-> 清除邮箱和候选见证
```

入口等待与失败回收均使用 `std::chrono::steady_clock`。回收诊断时限到仍未完成时返回 `启动候选回收超时`，但禁止 detach、覆盖、销毁 joinable thread 或遗失租约；普通应用上下文继续持有自我线程对象，顶层不得在候选未安全回收时销毁上下文并假装已返回。对象析构最终锁存停止并 join，可能继续等待真实线程完成；这是安全守恒，不是成功。

线程入口的 `noexcept` 外壳必须捕获正文中的所有异常；异常路径不得再次依赖可能已经失败的状态锁，而是以原子异常锁存和原子完成见证唤醒创建方，使其返回内部不一致并进入阶段20回收。所有外部生命周期端口调用必须在线程完成见证之前结束，保证创建方观察到完成后，工作线程不再调用外部端口。回收时线程租约在 `join()` 真正成功前始终保留在成员 `std::thread` 中，禁止先移动到局部 joinable 对象；若 `join()` 抛出，成员租约仍由普通应用上下文持有，返回内部不一致而不触发局部线程析构终止。

成功后的正常停止属于 BIZ-L2-001-11—15，不得调用本叶的启动失败候选回收入口。

## 9. 普通应用与阶段接线

激活时普通应用上下文新增唯一 `std::unique_ptr<自我线程>`，声明在其依赖之后并保证析构早于生命周期端口。构造状态追加具名失败，不复用已有 0—23 数值；精确数值在从最终装配枚举 S0 后机械追加。

`初始化普通系统` 固定：

```text
方法登记根生产初始化非成功 -> 阶段19
方法登记根生产初始化成功 -> 以本次 I2 + SELF-FORM 材料调用本函数
本函数非成功 -> 程序失败阶段::自我线程创建并停门 = 20
本函数成功 -> 只证明线程停在关闭门；返回后继续支持/工作/任务管理/外设线程准备
```

阶段20属于 `程序失败阶段`，与 `普通应用装配状态::场景所有者范围建立失败 = 20` 是不同强类型枚举，不构成数值冲突。旧阶段 4/5 不复用。

## 10. 验证矩阵与完成边界

- 请求版本、零幂等、零容量/时限、两材料错树和异请求零线程创建；
- 首次真实入口、门关闭、停门见证、零冻结批次和唯一租约；
- 同请求精确重复不新建，异请求冲突；
- 创建异常、入口延迟、提前完成、停门坏形状和虚假唤醒；
- 线程入口正文异常由 noexcept 外壳收口并发布原子完成见证，零 `std::terminate`；
- 每个失败点按固定顺序回收，完成后 join；诊断超时零 detach、租约守恒；
- join 异常前成员租约不移动，异常后对象仍持有 joinable 候选；
- 生命周期端口成功/失败/缺失均不能替代内部见证；
- 方法登记根失败零自我线程调用，成功后本函数非成功映射20；
- 运行门未开放、治理邮箱零消费、概念/方法/世界 DATA 零写；
- 根工程 Debug/Release、生产外专项、UTF-8、XML、strict、工程唯一登记和生产零验证痕迹。

当前只运行文档与源码静态门禁。通用 provider 可独立登记和构建，但 SELF-THREAD 本体的工程登记、SELF-FORM/生命周期端口联调、真实线程动态专项、普通应用装配和阶段20接线仍为 `NOT_RUN`。即使后续本叶通过，也不证明运行门开放、自我治理循环、需求/任务/方法闭环、语言形成、线程组或完整程序宿主完成。
