# 治理输入强类型协议与唯一路由详细设计

日期：2026-08-20

身份：`RUNTIME-GOVERNANCE-INPUT-V3-ROUTING v0.1`

对应目标图：`BIZ-L2-002-03 v0.3`、`BIZ-L2-002-04 v0.2`

## 1. 目标和完成条件

本叶把已经闭合的 002-03 分类从 legacy 句柄消息升级为 v3 强类型消息，并在分类后形成唯一、可机械测试的九类路由。完成条件是：

```text
v3每个分支直接携带领域公开强类型稳定身份
+ 九类分类与路由一一对应
+ 停止优先截断
+ 未实现后继形成可保留合法等待/NOT_RUN
+ 同批其它类别继续路由
+ 自我线程不再把所有分类结果无差别送入002-04
```

本叶不建立任务实际结果结构，不实现 6340 承接事实，不实现 002-04/05/06 的真实业务读写，不接入任务筹办或任务执行。

## 2. 当前事实和裁决

当前 `自我治理消息协议` v2 使用一个包含十四个 `节点句柄`的万能句柄组；`任务结果回执协议`也复用该句柄类型。当前 DATA-L2 公开身份已经使用 `L2需求身份`、`L2任务身份`、`L2状态身份`等稳定编码强类型，仓库不存在 legacy 句柄到这些身份的正式映射服务。

裁决固定：协议升 v3，不建适配器、不双路兼容、不从仓库号/节点号/版本号推断稳定身份。旧消息对象只因协议版本不匹配被拒绝。来源材料版本、运行代次和 G0 是独立字段。

002-03 的九类表是唯一表。旧 002-04 的父链变化、事实更新退出。任务结果复核和已由 6340 正式承接的观察材料才进入 002-04；其它路由按目标图执行。

## 3. v3 消息载荷

`自我治理消息`保留信封字段，但删除 `自我治理只读材料句柄组`，新增 `自我治理消息载荷`有限 `std::variant`。每个分支恰好匹配一个载荷类型：

```cpp
struct 任务结果复核载荷 { L2任务身份 任务; L2状态身份 实际结果状态;
  L2动态身份 动态证据; L2方法身份 方法; L2方法动作入口身份 动作入口;
  L2场景身份 场景; L2存在身份 主体; };
struct 派生需求载荷 { L2存在身份 目标宿主; L2特征定义身份 特征定义;
  L2特征实例身份 特征实例; L2状态身份 当前状态; L2状态身份 目标状态; };
struct 观察材料准入载荷 { L2存在身份 主体; L2场景身份 场景;
  不可变材料身份 材料; std::optional<L2任务身份> 绑定任务;
  std::optional<稳定编码> 绑定工作项; std::optional<稳定编码> 正式承接身份; };
struct 执行前许可预判载荷 { L2任务身份 任务; L2方法身份 方法;
  L2方法动作入口身份 动作入口; };
struct 自检缺口载荷 { L2存在身份 主体; L2场景身份 场景; 不可变材料身份 材料; };
struct 缓存刷新载荷 { std::variant<L2需求身份,L2任务身份,不可变材料身份> 目标; };
struct 事件日志载荷 { std::variant<L2需求身份,L2任务身份,L2动态身份,不可变材料身份> 目标; };
struct 停止载荷 {};
struct 概念待命名载荷 { L2概念身份 概念; };
```

`绑定工作项`与`正式承接身份`在当前没有公开领域强类型时不得用裸值发布为可消费事实。执行侧应优先新增治理消息协议私有的具名强类型 wrapper（内部持有稳定编码），不得使用 `std::optional<稳定编码>` 作为最终 ABI。上面伪码仅表达来源值；最终类型名冻结为 `自我治理工作项身份`、`自我治理承接身份`，二者只作消息定位身份，不宣称对应事实 provider 已存在。

`来源材料版本`保留为信封独立字段；`运行代次`和`读取截止代次`新增为信封独立非零字段。停止消息的运行代次非零，但读取截止可为零；普通消息读取截止必须非零。每个分支的 `消息类型`、材料类型、材料性质、来源角色、来源服务、目标服务和载荷 alternative 必须完全一致。

## 4. 任务结果回执协议

`任务结果回执协议`升 v2，删除从自我治理万能句柄组推导的别名，直接使用与任务结果载荷一致的强类型身份。旧 `任务执行冻结请求`仍是 legacy 协议，不能被用于推断 v2 身份；因此 v2 回执不再嵌套该旧请求。其来源执行绑定只保存 v2 已知的请求编号、任务序号、批次编号、幂等键和强类型任务/方法/动作身份。没有合法 v2 生产者时保持 NOT_RUN，不建立转换函数。

## 5. 分类后路由 DTO

在 `路由.自我治理批次.ixx`新增：

```cpp
enum class 治理输入后继 : std::uint8_t {
  治理输入事实复核 = 1, 生存控制裁决 = 2, 派生需求准入 = 3,
  自检缺口准入 = 4, 概念命名准入 = 5,
  缓存支持旁路 = 6, 日志支持旁路 = 7, 停止 = 8
};
enum class 治理输入路由状态 : std::uint8_t {
  已路由 = 1, 合法等待 = 2, 入口拒绝 = 3, 内部错误 = 4
};
struct 治理输入路由项 { 治理输入项 输入; 治理输入后继 后继;
  治理输入路由状态 状态; };
struct 治理输入路由结果 { 治理批次分类状态 分类状态;
  std::uint64_t 批次序号; std::vector<治理输入路由项> 有序路由组;
  std::vector<治理输入诊断> 逐项诊断; };
```

新增公开函数：

```cpp
治理输入路由结果 自我治理批次路由::复核分类并路由治理批次(
    const 治理批次分类请求& 请求) const noexcept;
```

它复用既有分类函数，不复制邮箱准入；停止返回停止优先。当前只有路由裁决本身实现，后继 provider 是否实现由固定能力表表达：本叶全部普通后继均为 `合法等待`，但保留唯一后继和原值式消息。合法等待不终止同批后续项。后继真实实现时只改变对应能力表和调用接线，不改变九类映射。

## 6. 自我线程接线

自我线程调用新函数并逐项处理：

- 停止优先：返回邮箱停止；
- `合法等待`：保留处理槽和路由项，继续检查同批其它项，不调用骨架函数；
- `已路由`：只调用该项具名后继；禁止无差别调用 002-04；
- 同批没有任何已消费输入时，以现有 `领域治理终止`安全收口，不能推进成功批次游标；
- 只有任务结果 002-04 返回可消费时才设置“需要需求活动重判”，并允许调用 002-06；其它类别不得触发 002-06。

当前能力表全部普通分支未实现，因此本叶运行结果是可观察的合法等待，不会越过到 002-06。生产主循环更早的未实现阶段仍可能先终止；专项应直接调用路由公开入口验证本叶。

## 8. 直接后继缺口

不登记第二份计划。待本叶代码结果进入 main 后，最早后继按 owner 分开选择：

1. 任务 owner 建立本轮实际结果和独立状态/动态/来源需求同 G0 读回 provider；
2. 或 6340 owner 建立报告稳定身份到唯一当前承接事实读回 provider。

只能先选择其中一个最早可交付 provider，再激活相应 002-04 分支；不得把两套事实模型、002-06、任务筹办和任务执行一次并入。
