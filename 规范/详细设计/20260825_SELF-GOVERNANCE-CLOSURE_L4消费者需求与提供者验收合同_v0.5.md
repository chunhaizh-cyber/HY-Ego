## 1. 目的与职责方向

本文件冻结自我内部治理闭环作为 ARCH-L4 合法消费者，对 ARCH-L2 中性公开能力的目标函数、结果空间和最终交付验收边界。依赖关系不是“提供者先完成、消费者才设计”，而是两条并行收敛链：

```text
ARCH-L4 自我 / 任务治理确定业务需求
-> 冻结具名公开目标函数、DTO、结构化结果和合同版本
-> 把同一目标 ABI 提交 ARCH-L1/L2 所有者
-> ARCH-L4 立即依据目标 ABI 继续完整下游设计和实施

同时：
ARCH-L1/L2 所有者依据目标 ABI 设计、实现并验证提供者
-> 若目标不可达则具名返回；否则完成正式实现

最后：
提供者正式实现接入完整 L4 流程
-> 联合编译
-> 完整流程统一测试
-> 连续两轮生产级端到端验收
```

ARCH-L4 不终审 ARCH-L1/L2 的 private helper、候选状态、事务内部类型、专项编译命令或对象链接组织；ARCH-L1/L2 也不得替 ARCH-L4 决定任务阶段、现实执行授权、任务轮次结论或自我后继决议。

本文件所称“目标 ABI”是 L4 需求权威确认并已经提交提供者的待实现公开合同。它足以供下游设计和实施使用，但不等于当前仓库已经存在该能力，不证明联合编译、运行、发布或验收成功。提供者尚未返回本身不构成 L4 设计实施阻断；只有提供者具名报告目标不可达，或实际接入与目标 ABI 存在会改变 L4 机器语义的冲突，才形成受影响切片 DRIFT。

## 2. 顶层业务完成合同

最终生产闭环必须同时成立：

1. 具体需求 `D` 经所属列表项 `L` 查询和防重后建立或复用任务 `T`；复用只新增合法 `T→D`，不重建首轮。
2. 新任务建立独立任务轮次 `R1` 和任务专属正式存在 `E`，并由任务 owner 保存正式 `T→E`。
3. `E` 的首态为“筹办 / 待初次筹办”，首态无动态；建立 `P1` 和版本化治理动作调用事实 `A1` 后，才迁移为“筹办 / 筹办中”并形成第一动态。
4. 任务管理按 `E` 的当前状态依次选择筹办、执行、结算或轮次收束治理，不以线程槽、日志或任务私有枚举决定主阶段。
5. 内部治理与纯现实观察不请求现实执行授权；只有执行冻结包含现实改变步骤时，才在冻结完成后、进入执行阶段前由自我业务 owner 发布一份授权。
6. 安全服务只提供调度材料和安全硬否决；硬否决优先，任何授权不得绕过。
7. 正式结果先裁决可共用或争用，争用时先正式分配，再对每个合格 `T→D` 独立核算；任务轮次结算只引用各 owner 的正式结果。
8. 任务轮次结算完成后进入“轮次已收束”并停止自行推进；目标未达成只是本轮结论。
9. 只有自我形成“继续”决议，任务管理才建立 `R2` 并重新筹办；结束、等待、取消分别进入自己的合法收口。
10. 旧任务私有当前状态、目标未达成自动重筹办、下一筹办工作包自动生成及其线程处理槽全部退出生产决策链。

## 3. ARCH-L2 中性提供者需求

本节各项是 L4 已确认并提交给 ARCH-L1/L2 所有者的公开目标函数能力合同。连续 L4 计划必须把它们标记为“待实现目标 ABI”并按其请求、结果和错误空间施工；不得把未接入的目标函数写成当前已发布能力，也不得建立生产 stub、默认成功或第二结构权威。

### 3.1 存在

ARCH-L2 必须通过唯一 `L2存在结构服务`提供：

- 建立一个调用方指定、结构合法、独占稳定身份的存在；
- 当前和历史身份来源、生命周期及同截止正式读回；
- 首次、精确重复、同键异义、G0 漂移、许可拒绝、资源失败和内部不一致的结构化分账；
- 交换前失败零写；已确认提交后的读回失败保留事实、账和代次并可按原键收敛。

ARCH-L2 不保存任务身份、任务阶段、`T→E`、任务轮次或其它业务宿主解释。`T→E`及“该存在属于哪个任务”只由 ARCH-L4 task owner 保存和解释。

### 3.2 特征

ARCH-L2 必须通过唯一特征公开面提供：

- 幂等建立或正式读取全局任务阶段基础特征定义；
- 为一个正式存在建立唯一、可独立读回的特征实例；
- 以强类型材料承载调用方提交的阶段 / 状态段值，不解释“筹办、执行、结算、轮次已收束”的业务意义；
- 定义、实例、值、宿主关系和共同截止的当前 / 历史读回。

全局定义和每个存在的实例由各自 owner 按正式合同建立。ARCH-L4 负责把业务阶段映射为材料；ARCH-L2 不维护业务枚举或任务状态机。

### 3.3 无动态首态

ARCH-L2 状态公开面必须支持：

- 对一个合法特征实例建立永久状态事实；
- 在同一状态 owner 的单个 `G1` 内建立该状态事实和唯一当前选择关系；
- 返回状态事实、状态自有关系、当前选择关系及共同 `G1`；
- 分别通过正式状态读取和当前选择读取在同一截止互证；
- 首态入口不建立动态，不退出任何旧状态事实。

首态成功只证明中性状态和当前选择结构成立。首态值的业务含义、任务是否处于初次筹办、`R1/P1/A1`是否成立仍由 ARCH-L4 裁决。

### 3.4 状态—动态迁移

ARCH-L2 状态 / 动态组合公开面必须支持：

- 状态 owner 精确退出旧当前选择关系，建立新永久状态事实和新当前选择关系；
- 动态 owner 建立主体、前状态、后状态、时间和来源引用完整的动态事实；
- 两个参与者在同一最终 `G1` 发布，应用顺序不改变正式映射或最终事实；
- 旧状态事实、旧状态自有关系和动态到前状态的引用保持历史及引用闭包可读；
- 正式返回新状态、新状态自有关系、新动态、新动态自有关系、新当前选择和旧选择退出证据；
- 状态、当前选择和动态三类独立读回共享同一截止并逐字段互证。

ARCH-L2 不判断一次迁移是不是“进入筹办、执行或结算”，也不判断来源是不是合法自我授权。ARCH-L4 只在完成业务裁决后提交完整强类型请求。

### 3.5 当前、历史和失败收敛目标结果空间

目标 ABI 必须表达、提供者最终接入时必须实际实现并验证：

```text
首次成功
精确重复
同键异义
入口拒绝
许可拒绝
G0 漂移
坏引用 / 旧选择定位冲突
资源失败
交换前内部不一致
已确认提交后的独立读回失败
按原幂等身份重放并正式读回收敛
```

当前选择读取必须区分未登记、已登记零条、一条闭合、多条或坏闭包；历史读取必须提供具名截止的零或一条快照。任何非成功都不得用默认身份、日志、缓存或调用返回补成成功。

## 4. ARCH-L4 消费者责任

ARCH-L4 task owner 独占保存和解释：

```text
T、T→L、T→D、T→E
任务轮次 Rn
筹办轮次 Pn
执行轮次 En
当前路径、实例方法和执行冻结
版本化内部治理动作调用事实 An
现实执行授权引用及消费收口
正式实际结果、任务轮次结算引用
自我后继决议引用
```

ARCH-L4 必须先正式读回所需存在、特征、状态和动态，再形成业务结论。它不得取得 L1 私有仓、写端口、候选、锁或事务权限，不得以任务私有状态继续形成第二当前权威。

阶段值的初始最小映射为：

```text
{筹办=1, 待初次筹办=1}
{筹办=1, 筹办中=2}
```

后继筹办、执行、结算和轮次收束状态值由当前正式 3200、5200、5210、5230 及后继 L4 设计冻结；不能要求 ARCH-L2 理解这些数值的业务含义。

### 4.1 L4线程、编排者与业务 owner 边界

自我线程只形成自我意图和治理材料；任务管理线程只独立读回当前正式状态、验证材料并调用相应 L4 领域入口；工作线程只执行已冻结实例并返回正式结果定位。三者均不得裸写存在、特征、状态或动态，不得用线程槽、队列位置、日志或返回值替代任务阶段、授权、结算或后继决议事实。

所有异步交接必须使用不可变身份和版本化材料；接收方必须重新独立读回，不能沿用发送方内存判断作为业务事实。

### 4.2 同一任务轮次内重新筹办

必须区分：

```text
同一未收束 Rn 内建立新 Pn
!=
轮次收束后建立 R(n+1)
```

实例尚未开始执行且尚未形成正式实际结果时，等待回流、路径 / 实例 / 冻结失效、输入 / 条件 / 目标 / 成员当前性变化可以保留旧历史并在同一 `Rn` 建立新的筹办轮次。实例已经开始执行或正式实际结果已经形成后不得沿该分支换路，必须进入结算并收束本轮。轮次收束后仍只有正式自我“继续”决议可以建立 `R(n+1)`。

### 4.3 现实执行授权与正式派发门控

含现实改变步骤的执行冻结必须在任何步骤开始前取得一份自我现实执行授权；混合方法不得先执行观察前缀再补授权。授权至少绑定：

```text
自我
T / Rn / Pn / En
冻结身份与版本
实例方法与内容版本
有序现实动作范围
共同事实截止
授权规则版本
发生时间与有效期
```

同冻结同义请求只读回原事实；任一绑定、冻结或动作范围变化使旧授权失效。拒绝、等待或撤回不写任务失败。内部治理和纯观察不建立该授权。

授权成立仍不等于可以派发。冻结后、真实派发前必须读取 6170 生存控制态：`A=0/1`不派发普通任务；`A>1`再读取安全 / 服务调度配额及适用的 6150 倍率。零调度资格只排除本次排序，不等于未授权。真实动作开始前再次复核控制态、调度资格、授权当前性和安全硬否决；硬否决具有最终优先级。

### 4.4 任务轮次收束成功谓词

只有以下材料全部正式发布并独立读回，任务轮次才能进入“轮次已收束”：

```text
正式实际结果，或合法无执行短路结果
+ 目标已达成 / 未达成等具名轮次结论
+ 验证与归因收口
+ 结果可共用 / 争用裁决
+ 争用时的正式分配
+ 每个合格 T→D 的独立核算结果或具名结构化非成功
+ 适用的价值结算或学习后继引用
+ 任务轮次结算结果
+ 任务运行已停止
+ 执行冻结与授权消费已经收口
```

任一项缺失都不得写“轮次已收束”。结算编排只引用各 owner 的正式结果，不复制成第二权威。

### 4.5 初始化幂等重放与既有任务复用

新任务请求必须一次携带并保存完整版本化六阶段幂等材料；六键非零、两两不同，准备键与 `P1`键按正式合同绑定，重试和回流不得现场派生补键。精确重复只能读回原事实；同键异义必须零新增拒绝。

已有同目标当前任务时只新增合法 `T→D`，不得建立第二 `E/R1/P1/A1/首态/第一动态`。异目标任务、列表项后来新增成员或未经逐项承接的其它需求不得自动挂入现有任务。

## 5. 目标 ABI 确认、提供者交付与最终消费验收

### 5.1 目标 ABI 确认

L4 需求权威确认具名公开目标函数、DTO、结构化结果、合同版本和第 3.5 节错误空间，并把同一合同提交给交互2后，目标 ABI 即取得下游设计和实施约束力。此后 L4 不等待提供者返回；交互2负责满足该合同，除非具名报告目标不可达。

目标 ABI 确认只证明需求和消费形状已经冻结。它不证明当前源码存在对应符号、提供者实现正确、普通应用已经接线或联合编译能够通过。

### 5.2 提供者最终交付

ARCH-L1/L2 所有者交付时必须给出：

1. 已提交并推送的精确代码提交、`main/origin` 和干净 index；
2. 公开模块、DTO、函数签名、合同版本、字段物理顺序和构造 / 装配边界；
3. 实际证明的首次、重复、冲突、漂移、许可、资源、读回故障和重放矩阵；
4. 无动态首态、迁移单 `G1`、旧状态永久保留、当前 / 历史独立读回的证据；
5. 明确未证明的崩溃、重启、跨进程恢复、业务消费者或集成范围；
6. 代码、构建、Git、索引和验证资源已经释放的状态。

### 5.3 最终接入消费验收

ARCH-L4 在完整流程代码形成且提供者实际接入后，只检查：

- 正式 ABI 是否足以表达第 3 节请求；
- 结构化结果是否足以按第 4 节形成业务裁决；
- 当前 / 历史 / 故障后读回是否足以证明事实；
- 是否仍要求 ARCH-L4 取得私有权限、补造字段或临场决定提供者语义；
- 是否引入第二存在、状态、动态或当前选择权威。

验收不重复审批提供者 private helper、测试 seam、编译命令或对象链接方案。实际公开实现偏离目标 ABI 时返回具名 ABI / 语义缺口；提供者具名报告不可实现时返回目标不可达。没有这两类事实时，不得把“尚未返回”重新解释成 L4 设计实施等待门禁。

## 8. 最终验收

第 1—13 项只在叶1—叶6完整实现且提供者实际接入后统一执行。任何中间叶的局部检查、模拟返回、未接入调用或专项结果都不能形成阶段验收。最终合法消费者必须至少证明：

1. `R1`首态无动态，后续每次真实阶段变化恰有一条同主体、同特征、相邻前后状态的动态；
2. 新任务完整保存六阶段幂等材料；精确重放只读回原事实；既有同目标任务只新增 `T→D`且不重建 `E/R1/P1/A1/首态/第一动态`；
3. `P1/E1`、冻结、授权消费、实际结果、逐需求核算和轮次结算均可按正式身份独立读回；
4. 未执行前的等待回流或冻结失效可以在同一 `Rn`建立新 `Pn`；执行开始或形成正式结果后禁止该分支；
5. 内部治理和纯观察零现实执行授权；现实改变一冻结一授权；授权完整绑定且任一绑定变化失效；混合方法不提前执行观察前缀；
6. `A=0/1`、无调度资格、授权缺失 / 失效或安全硬否决均按各自语义阻断派发；调度资格不冒充授权，授权不越过硬否决；
7. 自我线程、任务管理线程和工作线程只通过不可变材料、正式入口及独立读回协作，零线程状态替代业务事实；
8. 可共用结果逐成员独立核算，争用结果先分配再核算；第4.4节收束谓词缺任一项都不得进入轮次已收束；
9. 目标未达成后任务停驻且没有 `R2`、重筹办意图、自动工作包或自动继续；
10. 自我“继续”后才建立 `R2`，且不复用旧路径、实例、冻结、结果或授权；等待、结束和取消进入各自合法收口；
11. 首次、重复、冲突、漂移、许可、资源和发布后读回故障均按合同收敛；
12. 旧任务私有状态、Stage C、重筹办意图端口 / 处理槽和自动工作包入口不再决定生产行为；
13. 连续两轮无任务风暴、空转、重复动态或无授权现实执行，且上一轮正式结果会影响下一轮重新筹办选择。

只有完整流程统一编译、统一测试和连续两轮验收可以更新完成证据；日志、单次成功、局部机械检查、计划退出或 DTO 存在都不能替代上述验收。
