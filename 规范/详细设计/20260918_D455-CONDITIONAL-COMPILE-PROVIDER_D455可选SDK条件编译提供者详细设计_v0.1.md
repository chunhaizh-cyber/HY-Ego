# D455 可选 SDK 条件编译提供者详细设计

设计身份：`D455-CONDITIONAL-COMPILE-PROVIDER`

日期：2026-09-18
版本：v0.1
状态：施工设计

## 1. 问题与唯一职责

`采集器.D455相机.cpp` 是 D455 的唯一 SDK 边界，公开头只含 SDK 无关的协议类型。当前工程已经把 RealSense 的 include、link 与 DLL 复制置于 `EnableD455RealSense=true` 条件下，但专项工程仍编译该源；源文件本身无条件 include SDK，故“默认关闭”没有真正关闭翻译单元依赖。

本设计只让该 SDK 边界在未启用宏时成为确定的不可用提供者。它不改变协议、外设控制域、采样语义或消费者。

## 2. 编译和运行合同

```text
EnableD455RealSense=true 且 x64
  -> 工程定义 HY_EGO_ENABLE_D455_REALSENSE
  -> 采集器源可见 SDK 头、rs2 实现和真实工厂

否则
  -> 编译同一采集器源但不包含任何 SDK 头
  -> 工厂按配置无效/当前无可用提供者返回空指针
```

关闭分支不是模拟设备，也不能创建 `D455帧来源`。调用方只可由 `D455操作结果.成功=false` 和空指针识别不可用；有效配置的原因固定 `无设备`、`追根因=false`，无效配置优先 `配置无效`。这些都是既有协议值，不能新增“SDK 未启用”公开状态。

## 3. 精确代码组织

`海中鱼巣/适配/采集器.D455相机.cpp` 保持其头包含和公开工厂签名。其后：

```cpp
#if defined(HY_EGO_ENABLE_D455_REALSENSE)
// 现有 SDK 包含、匿名命名空间、D455相机采集器和真实工厂
#else
std::unique_ptr<D455帧来源> 创建并打开D455相机采集器(
    D455采集配置 配置, D455操作结果& 打开结果) {
  打开结果 = D455采集配置有效(配置)
      ? D455操作结果{false, false, D455采集拒绝原因::无设备}
      : D455操作结果{false, false, D455采集拒绝原因::配置无效};
  return {};
}
#endif
```

实际位置可把 `namespace 海中鱼巣` 包在条件外，但 SDK 头和所有 `rs2_*` 声明不可越过开启分支。真实分支沿用原工厂，不能出现第二个定义。

## 4. 非成功、验证和交付

关闭分支无内存事实、缓存、线程、设备、SDK 动态加载或日志副作用；返回前不读取硬件。开启分支的 SDK 缺失仍由工程的 `验证D455RealSense构建输入` 早期拒绝。

验证使用全新临时对象目录编译默认宏关闭的源文件；再以预处理/文本扫描核验 SDK 包含只在开启区域、工厂仅一处定义。真实 SDK 开启验证不是本设计完成门槛。通过后该提交交给世界树专项 v4 消费者迁移重新 S0。
