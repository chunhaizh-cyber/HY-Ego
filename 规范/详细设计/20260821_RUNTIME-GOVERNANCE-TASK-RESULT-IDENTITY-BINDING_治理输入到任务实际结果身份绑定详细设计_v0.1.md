# 治理输入到任务实际结果身份绑定详细设计 v0.1

日期：2026-08-21

计划身份：`RUNTIME-GOVERNANCE-TASK-RESULT-IDENTITY-BINDING`

代码基线：`2f67dea50d503ebfebef47acdfaa3fb431ca2136`

## 1. 目标与完成边界

本设计实现 BIZ-L2-002-04 当前最早直接后继：把已经分类并路由到“治理输入事实复核”的任务结果治理输入，绑定到同一事实截止下唯一正式任务实际结果身份。

完成条件固定为：

```text
已路由任务结果治理输入
+ 同一 G0 当前实例方法
+ 从实例方法取得正式执行轮次
+ 按任务与执行轮次读取任务实际结果
+ 消息七项强类型身份、来源材料版本、运行代次全部互证
+ 返回任务实际结果身份、实例方法身份、执行轮次和事实截止
```

本叶不调用需求父链重判，不形成任务完成、需求满足、结算、学习或价值回流；不让自我线程把绑定成功当作整个输入已经消费。观察材料准入仍为合法等待，002-05 及以后不推进。

## 2. 当前事实与复用裁决

- `RUNTIME-GOVERNANCE-INPUT-V3-ROUTING v0.1`已经提供九类强类型消息、分类结果和唯一后继；任务结果复核载荷含任务、实际状态、动态证据、方法、动作入口、场景和主体，消息封套含来源材料版本、运行代次和读取截止。
- 治理消息的`来源任务序号`只是同任务消息顺序，不是执行轮次。现行任务结果回执来源绑定同样没有正式执行轮次，禁止从两者反推。
- `RUNTIME-GOVERNANCE-TASK-ACTUAL-RESULT-PROVIDER v0.1`已经正式退出，并提供 `L2任务结构服务::按任务读取当前实例方法`。实例方法当前投影权威携带执行轮次，因此它是本叶唯一合法执行轮次来源。
- 同一提供者还提供 `运行期只读查询组合器::读取任务本轮实际结果与独立读回`，能够按任务和执行轮次读取结果，并在同一 G0 下独立互证实例方法、路径、状态、动态、场景、主体和来源需求成员。本叶必须复用，禁止重新实现第二套结果解释器。
- 现有 `治理输入事实复核请求/结果`及`复核治理输入绑定事实`只是待激活占位，没有真实输入字段或结果身份。本叶精确替换该占位合同。

## 3. 合同

### 3.1 DATA 之外的值式请求

在 `L2治理函数骨架.数据.h`冻结：

```cpp
struct 任务结果治理输入事实 final {
    L2任务身份 任务;
    L2状态身份 实际状态;
    L2动态身份 动态证据;
    L2方法身份 方法;
    L2方法动作入口身份 动作入口;
    L2场景身份 场景;
    L2存在身份 主体;
    std::uint64_t 来源材料版本;
    std::uint64_t 运行代次;
};

struct 治理输入事实复核请求 final {
    std::uint32_t 合同版本;
    std::uint64_t 治理批次身份;
    std::uint64_t 共享事实截止G0;
    std::uint64_t 最大需求成员数;
    任务结果治理输入事实 输入;
};
```

该 DTO 是线程消息到治理业务组合器的值式边界，不含线程枚举、消息编号、来源任务序号、非权威摘要或执行轮次。执行轮次禁止由调用方填写。

### 3.2 强类型绑定结果

```cpp
enum class 治理输入事实复核状态 : std::uint8_t {
    已绑定, 合法等待, 当前性漂移, 引用冲突,
    数量预算不足, 入口拒绝, 资源失败, 内部错误
};

struct 治理任务实际结果绑定 final {
    L2任务身份 任务;
    L2实例方法身份 实例方法;
    std::uint64_t 执行轮次;
    L2任务实际结果身份 实际结果;
    std::uint64_t 事实截止代次;
};

struct 治理输入事实复核结果 final {
    治理输入事实复核状态 状态;
    std::optional<治理任务实际结果绑定> 绑定;
};
```

只有`已绑定`携带绑定；所有非成功状态必须零绑定。

### 3.3 唯一治理输入入口

在 `线程/路由.自我治理批次.ixx`新增：

```cpp
治理输入事实复核结果 复核任务结果治理输入绑定事实(
    const 治理输入路由项& 路由项,
    std::uint64_t 治理批次身份,
    std::uint64_t 最大需求成员数) noexcept;
```

该入口只接受：类别为任务结果复核、后继为治理输入事实复核、当前状态为合法等待、消息类型为任务结果复核请求且载荷 alternative 正确的路由项。它逐字段复制七项强类型身份、来源材料版本、运行代次和读取截止到业务请求，然后恰一次调用 `复核治理输入绑定事实`。其它类别、错后继或坏路由形状返回入口拒绝。

## 4. 唯一执行轮次来源与读取顺序

`复核治理输入绑定事实`固定执行：

1. 守卫合同版本、批次身份、G0、预算及全部输入字段；
2. 确认运行期只读服务已经装配；未装配返回合法等待；
3. 以 `{任务, G0, 当前}`调用 `按任务读取当前实例方法`；
4. 结果头事实截止不等 G0 返回当前性漂移；资源失败单独返回资源失败；当前实例方法为空返回合法等待；坏成功形状返回内部错误；
5. 从实例方法事实取得非零执行轮次，并互证任务和方法；这里不得读取或使用来源任务序号；
6. 以该执行轮次和输入全部字段构造 `任务实际结果独立读回请求`，恰一次调用现有公开组合器；
7. 映射组合器状态；成功时再次互证结果、实例方法、任务、轮次和 G0，形成强类型绑定。

状态映射：

| 组合器状态 | 绑定状态 |
| --- | --- |
| 已形成 | 已绑定 |
| 尚未形成 | 合法等待 |
| 当前性漂移 | 当前性漂移 |
| 数量预算不足 | 数量预算不足 |
| 请求拒绝 | 入口拒绝 |
| 轮次不匹配、引用冲突 | 引用冲突 |
| 资源失败 | 资源失败 |
| 内部不一致或坏成功形状 | 内部错误 |

## 5. 所有权、生命周期和并发

- 绑定结果只在一次调用内形成并按值返回，不缓存、不入账、不写事实，不拥有任务结果生命周期。
- 当前实例方法和任务实际结果仍由唯一 `L2任务结构服务`拥有；本叶只读。
- G0只来自已经冻结的治理消息读取截止，组合器不得自动重取新截止。任何子读取观察到不同当前代次都返回当前性漂移。
- 本叶不修改邮箱、分类、消息协议、任务回执协议或任务结构服务，不增加第二执行轮次来源。

## 7. 验证矩阵

验证只走公开治理输入入口、公开任务服务和公开组合器：

1. 真实任务结果治理输入在同一 G0 绑定到刚发布的实际结果身份；返回的任务、实例方法、执行轮次和截止逐项一致；
2. 修改来源任务序号但保持同一合法输入，绑定仍从当前实例方法取得相同执行轮次，证明两者不等价；
3. 当前实例方法尚未形成或本轮结果尚未形成返回合法等待；
4. 旧 G0 返回当前性漂移；
5. 方法、动作入口、状态、动态、场景、主体或来源材料版本不配返回引用冲突且零绑定；
6. 预算不足返回数量预算不足且零绑定；
7. 非任务结果类别、错后继、错路由状态、零批次或零预算返回入口拒绝；
8. Debug/Release x64 全量 Rebuild、两配置 `--test-治理`、strict 和 diff 检查通过。

禁止用日志、直接 L1、私有 helper、测试 seam或手工构造任务实际结果证明绑定成功。
