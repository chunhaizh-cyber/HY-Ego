# 任务方法路径权威引用入口详细设计

日期：2026-08-20

身份：`DATA-L2-TASK-METHOD-PATH-VALIDATED-ENTRY`

版本：v0.1

## 1. 目标与边界

本设计只闭合“任务方法路径写入前，来源方法及内容版本由权威方法事实证明，并由普通应用提供唯一合法入口”。它属于“任务服务补全”的第一段，不证明路径组读、路径退出、当前选择、实例方法或任务筹办已经完成。

正式依据为 4260 第 21 节与第 37.2 节：路径写前必须验证方法身份和内容版本；该依赖不得反塞进基础 `L2任务结构服务`。

## 2. 当前事实与裁决

当前 `L2任务结构服务::新增任务方法路径`能够原子写入并读回路径，但只验证任务，不读取 `L2方法结构服务`；任何非零方法编码和版本都可进入路径。唯一源码调用者 `任务筹办编排服务`会先读取方法，但基础写入口仍公开，不能把调用者自律当成结构合同。

裁决：

```text
普通应用 / 任务筹办
-> L2任务方法路径结构服务::新增任务方法路径
-> 同代次读取 L2方法结构服务::读取普通方法
-> 精确比较方法身份与内容版本
-> L2任务结构服务私有原子承载入口
-> 权威路径读回
```

不把方法服务注入基础任务核心；不复制路径写集；不建立第二套路径事实。

## 3. 函数与物理位置

### 3.1 新服务

文件：`海中鱼巣/领域/服务.L2任务方法路径结构.ixx`

```cpp
class L2任务方法路径结构服务 final {
public:
    L2任务方法路径结构服务(
        const L2方法结构服务& 方法服务,
        L2任务结构服务& 任务服务) noexcept;

    L2新增任务方法路径结果 新增任务方法路径(
        L2新增任务方法路径请求 请求) noexcept;
};
```

服务只借用普通应用拥有的唯一方法服务和任务服务，不拥有 L1、不持有写端口、不另建锁或缓存。

### 3.2 基础承载入口

`L2任务结构服务`把现有写入正文改名为私有 `写入已验证任务方法路径`，只授权 `L2任务方法路径结构服务`调用。现有 DTO、写集、幂等映射和权威读回不变。

### 3.3 普通应用

`普通应用上下文`在方法服务与任务服务均已构造后建立唯一 `L2任务方法路径结构服务`，提供 const / non-const getter。成员声明保证路径服务先于其借用对象析构。

### 3.4 消费者

`任务筹办编排服务`分别借用任务核心服务和任务方法路径服务；路径新增只走后者。不得借本段实现其余固定拒绝入口或把筹办宣称为已接线。

## 4. 状态与代次

1. 请求形状不合法：`入口拒绝`。
2. 方法读取在同一 `期望事实代次`失败：原样传播该结构状态和事实截止。
3. 方法存在但内容版本不等于请求版本：`引用冲突`，零写入。
4. 方法读取成功且版本一致：把完整原请求移动给基础承载入口。
5. 原子写入首次成功或精确重复：沿用现有权威读回和结果形状。

服务不得自动重试事实代次漂移，不得把历史方法冒充当前方法，不得根据名称或裸编码补齐方法。

## 5. 普通应用读回场景

在既有 `--test-需求`合法消费者中复用同一普通应用上下文：

1. 初始化并读回系统场景树根；
2. 复用测试已建立的存在、特征定义和目标状态合同，新增一份真实普通方法并读回；
3. 建立需求列表项和任务；
4. 经新路径服务以错误版本提交，必须 `引用冲突`且事实代次不变；
5. 经新路径服务以权威版本提交，必须成功；
6. 经任务结构公开读取核对任务、方法、版本和七项材料一致。

测试数据只存在于测试进程的普通应用运行包，不建立生产默认事实。

## 6. 完成边界

完成只证明普通应用可取得路径专属入口，且来源方法当前事实与内容版本在写前得到权威校验。以下仍为 `NOT_RUN`：路径组读、路径退出、当前选择、实例方法、筹办占用、任务筹办生产装配、任务线程、自我治理与真实治理。
