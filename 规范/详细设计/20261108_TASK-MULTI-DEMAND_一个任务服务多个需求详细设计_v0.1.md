# TASK-MULTI-DEMAND 一个任务服务多个需求 详细设计

身份：TASK-MULTI-DEMAND；版本：v0.2（用户2026-11-08：按需求列表项对应，不增字段；列表项任务已终结则重新开始）；日期：2026-11-08；依据：用户裁决 R108（3200 v4.4 第4、6节，5260 v3.6）。

## 1. 起因

服务根需求 12781 与其结算子需求 12851 的任务各自运行同一结算派生（正式服务任务投影），推导出两个目标完全相同的“新增服务任务”需求（18212、18297），各建任务，两任务指向同一服务取得槽，自我采用“待实例化需求内容”前端时互相使对方来源过期，补问链路无法进入。

## 2. 裁决要点（R108）

1. 一个需求最多对应一个任务；任务按需求列表项对应，同一列表项（完整目标相同）至多一个任务，同项其它需求由它服务；已终结而同项有需求需要治理时重新启用。
2. 任务对所服务需求不分主次；仍有一个需求活动且未满足即继续。
3. 完成一次、结算一次；各需求按各自当前满足状态闭合；服务值贡献只按任务计一次。
4. 子需求挂在当前满足需求下：建立需求仍活动时为建立需求，否则为建立顺序最早的活动需求。

## 3. 数据

- 不增持久字段。需求列表项（3100，键为完整目标）已把完整目标相同的需求列为一项；任务按列表项对应。
- 任务 `需求字段` 仍为建立需求（Vt、候选材料、执行冻结沿用）。
- 需求D的任务 = 以D为建立需求的任务，否则D所在列表项其它成员建立的任务（`需求服务任务`）；一个需求、一个列表项多于一个任务为结构损坏。
- 需求owner新增只读 `读取需求所在列表项(D)`。

## 4. 行为

| 处 | 规则 |
| --- | --- |
| `建立或取得任务(D)` | 先按D反查既有任务→复用；否则D所在列表项已有任务→复用（终结的由自我按重新启用规则唤回）；否则新建 |
| `查询需求任务(D)` | `需求服务任务` |
| `读取需求列表任务对应` | 无直接任务的需求取其列表项的任务；一个列表项两个任务为结构不一致 |
| 贡献投影 | 允许多个需求对应同一任务，任务成员只计一次 |
| 任务调度活动判定 | 所服务需求任一活动即视为活动 |
| 子需求提议（条件、因果） | 父需求取当前满足需求；对应核验改为“该需求由此任务服务” |
| 其余直接读 `任务需求字段` 的核验点 | 改为 `需求服务任务(D)==T`；`读回需求任务` 去掉“任务需求节点==D” |

## 6. 不变

任务状态机、执行实例、影响评估、完成结算记录形状；需求树恰一父；一个需求最多一个任务。

## 7. 验证

默认编译；按用户测试指令运行端到端，观察两个“新增服务任务”需求由同一任务服务、“待实例化需求内容”前端采用不再来源过期。

## 8. 直接切片试实施结论（2026-11-08，Codex 审计不通过，代码已撤回）

按第4节实施后（补丁留存于交互窗口暂存区），Codex 审计指出 R108 牵涉面远超直接切片，须形成完整计划后实施。必须闭合的范围：

1. **结算与投影消费者**：`业务/因果.任务筹办服务.cpp`（正式服务任务投影要求每个T只出现一次、按D收集成员）、`领域/任务结算.规则.cpp`（要求 `T.需求节点==当前D` 且T在对应表唯一；按子需求累加接收事实，共享T有重复计值风险）。
2. **共享任务的子结算归集与唯一交接路线**：直接子需求只按建立需求枚举、只沿建立需求父链交接一次；跨父链共享T时其它父任务可能永久等待。
3. **“建立需求==请求需求”假设**：管理线程因果/复合子需求承接回执、自我线程外部服务/行动请求承接回执、因果承接激活与既有采用读回、行动请求来源匹配、前置语言父请求、`概念_特征类` 集合条件（必含需求任务、服务要求对应需求、约束蕴含）、`查询唯一任务`。
4. **当前满足需求作为子需求父需求**：需求owner新增成员见证出生准入（`读取任务所属需求`）、因果子需求父T核验、条件子需求身份/就绪/承接、内容条件必要性、复合目标分解父需求。已建立的子需求保留原父，复核不随当前满足需求重挂。
5. **活动性与重新启用**：内容目标调度、学习唤醒、因果提议入口、结果分支选择、筹办资格、自我线程活动门；行动请求/外部服务/因果/条件承接遇既有终结T的提前返回；5090 禁止已结算T重启与 R108 重新开始的统一（重启后不得重复原结算）。
6. **读取失败与唯一性**：列表项读取失败不得当作无任务而新建；单需求查询与完整对应表的同项唯一性检查一致；区分无任务／资源失败／结构损坏。
7. **规范残留**：3200 第35行、3100 第31行“一任务恰一需求”，5090 “D与T一对一”检查项，单一父任务交接与全部直接子需求归集的解释。

建议保留两种语义：任务建立身份（候选材料、X/A/K 绑定建立需求）与任务服务需求（业务关联、活动性、父子服务关系）。

## 9. 与补问链路阻断的关系

单一“新增服务任务”任务的运行中，自我采用“待实例化需求内容”前端仍“来源过期”：`建立或取得来源前驱目标实例` 内 `构造来源前端自身发布后请求` 的逆推返回“材料已变化”，后续尝试捕获“因果读取来源变化信号”（保护快照在并发写入下变化）。补问链路的直接阻断是该保护在并发下持续失效，不由 R108 解决。
