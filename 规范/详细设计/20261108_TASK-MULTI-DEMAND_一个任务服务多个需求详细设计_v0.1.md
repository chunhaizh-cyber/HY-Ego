# TASK-MULTI-DEMAND 一个任务服务多个需求 详细设计

身份：TASK-MULTI-DEMAND；版本：v0.1；日期：2026-11-08；依据：用户裁决 R108（3200 v4.4 第4、6节，5260 v3.6）。

## 1. 起因

服务根需求 12781 与其结算子需求 12851 的任务各自运行同一结算派生（正式服务任务投影），推导出两个目标完全相同的“新增服务任务”需求（18212、18297），各建任务，两任务指向同一服务取得槽，自我采用“待实例化需求内容”前端时互相使对方来源过期，补问链路无法进入。

## 2. 裁决要点（R108）

1. 一个需求最多被一个任务引用；新自我执行需求的完整目标（目标信息节点＋目标定义）与某个未终结任务的建立需求完全相同时，挂靠到该任务，不另建任务。
2. 任务对所服务需求不分主次；仍有一个需求活动且未满足即继续。
3. 完成一次、结算一次；各需求按各自当前满足状态闭合；服务值贡献只按任务计一次。
4. 子需求挂在当前满足需求下：建立需求仍活动时为建立需求，否则为挂靠顺序最早的活动需求。

## 3. 数据

- 任务节点保留 `任务需求字段`（建立需求，唯一）；新增多值 `任务挂靠需求字段`（按字段关系编码升序即挂靠顺序）。
- `新任务信息` 增加 `挂靠需求节点组`；`需求节点` 仍为建立需求（Vt、候选材料、执行冻结沿用）。
- 需求反查任务：`任务需求字段` 与 `任务挂靠需求字段` 两者目标字段合并；同一需求反查多于一个任务仍为结构不一致。
- 候选方法材料的 `需求节点` 仍等于建立需求（目标相同，召回结果相同）。

## 4. 行为

| 处 | 规则 |
| --- | --- |
| `建立或取得任务(D)` | 先按两字段反查既有任务→复用；否则遍历任务集合成员，找未终结、建立需求为自我执行且完整目标与D完全相同的任务→原子追加挂靠字段并读回，返回“已复用”；否则新建 |
| `查询需求任务(D)` | 两字段合并反查 |
| `读取需求列表任务对应` | 任务的建立需求与挂靠需求都映射到该任务；正反向核验按两字段；一个需求只映射一个任务 |
| 贡献投影 | 允许多个需求对应同一任务，任务成员只计一次 |
| 任务调度活动判定 | 所服务需求任一活动即视为活动 |
| 子需求提议（条件、因果） | 父需求取当前满足需求；对应核验改为“该需求由此任务服务” |
| 其余直接读 `任务需求字段` 的核验点（约20处，见第5节） | 改为“需求由该任务服务”的统一判定 `任务服务需求(T,D)` |

## 6. 不变

任务状态机、执行实例、影响评估、完成结算记录形状；需求树恰一父；一个需求最多一个任务。
