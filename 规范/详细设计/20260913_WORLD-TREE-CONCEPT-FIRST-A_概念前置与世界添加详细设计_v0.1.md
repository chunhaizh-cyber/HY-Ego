# 概念前置与世界添加详细设计

日期：2026-09-13

版本：v0.1

身份：`WORLD-TREE-CONCEPT-FIRST-A`；对应总体方案批次 A。代码事实基线：`b0a27c4858c739a0c21273245aab5b00faac3033`。

本设计冻结第一项实际可用结果：普通启动经真实自我形成服务调用世界树，先取得具名通用存在概念，再原子建立同节点自我存在/场景、唯一结构父、单例角色及对已发布概念的引用，最终按同一截止独立读回。并交付相同提供者上的普通场景/两类存在创建与纯 I64 FC/EC 定义查询创建能力。它不把其它类型 CRUD、完整自我线程或全部世界树方案标为完成。

用户本轮已明确：“先使用具名规则定义的通用存在概念，不预设特征，随后按真实信息细化”。此裁决只开放具名通用 EC 的零约束分支；普通合取 EC 仍不得以漏填模板成为通用概念。

## 3. 纯概念定义与公开合同

### 3.1 类型和唯一性

新增类型使用独立名称，不静默重释旧 `概念树特征定义::形成宿主`：

```cpp
enum class 通用存在定义规则 : std::uint8_t { 未指定 = 0, 不预设特征 = 1 };
struct 通用存在概念定义 final {
  std::uint32_t 规则版本 = 0;
  通用存在定义规则 规则 = 通用存在定义规则::未指定;
  friend bool operator==(const 通用存在概念定义&, const 通用存在概念定义&) = default;
};
struct 纯I64特征概念定义 final {
  概念树特征类型引用 特征类型;
  std::vector<概念树I64区间> 规范域;
  friend bool operator==(const 纯I64特征概念定义&, const 纯I64特征概念定义&) = default;
};
struct 纯合取存在概念定义 final {
  std::vector<概念树概念身份> 特征模板组;
  friend bool operator==(const 纯合取存在概念定义&, const 纯合取存在概念定义&) = default;
};
using 纯概念定义 = std::variant<纯I64特征概念定义,
                                纯合取存在概念定义, 通用存在概念定义>;
enum class 概念初始组织指定 : std::uint8_t { 未指定 = 0, 显式顶层 = 1, 具名上位 = 2 };
struct 纯概念读取请求 final {
  std::uint32_t 版本 = 2;
  std::uint64_t Gread = 0, H = 0;
  概念树概念身份 概念;
  概念树预算 预算;
};
struct 纯概念查询请求 final {
  std::uint32_t 版本 = 2;
  std::uint64_t Gread = 0, H = 0;
  纯概念定义 定义;
  概念树预算 预算;
};
struct 纯概念创建请求 final {
  std::uint32_t 版本 = 2;
  std::uint64_t G0 = 0;
  L1所有者范围写入幂等身份 幂等身份;
  纯概念定义 定义;
  概念初始组织指定 组织 = 概念初始组织指定::未指定;
  std::vector<概念树概念身份> 直接上位;
  概念树预算 预算;
};
```

所有请求比较为逐字段值相等；预算、G0 和幂等身份也属于原请求。读取必须 `0 < H <= Gread`；当前读使用 H=Gread，调用方先经服务取得当前代次，零不是隐含最新。新接口版本只接受 2。

FC 使用正式类型的规范化接口合并重叠/相邻 I64 闭区间，保留不连续空隙，拒绝空域和超出 FT 允许域；输出转换逐端点保真。模板 EC 排序去重、非空，各目标必须是当前有效纯 FC；不接受未来 FC、普通存在或旧格式概念。通用 EC 只接受规则 1 / 版本 1，定义内容无 FT、F、观察、宿主或自我身份。

上述“当前有效”约束用于新创建和当前查询。历史读取/历史定义查询使用固定H核验FT、模板、直接上位、使用和生命周期；目标或依赖后来在Gread之前退役/退出，不取消其H时合法性。历史返回当时完整定义及其真实后继生命周期，不用当前活动枚举漏掉已退出身份，也不为了读历史重新建节点。

同义键为不可变类别加完整规范化定义。当前冷却概念也参加精确查询并允许复用；退役概念返回 `概念已退役`，不得新建同义项。本批不提供退役恢复算法。不可逆退出概念只供历史，同义重建产生新身份。多个当前同义项返回内部不一致；不按编码或首项取一个。

显式顶层必须空上位；具名上位必须非空且全部同类别、当前可用、不重复、无环。FC 上下位以正式域包含且不相等证明；合取 EC 的上位约束是下位约束的严格子集；通用 EC 可以作为任何非通用 EC 的上位，通用 EC 自身只允许显式顶层。同义身份与组织意图不一致返回 `组织冲突`，不得在创建重试中顺带改图。

### 3.2 事实与结果

`纯概念事实`字段固定为：概念身份、`相关概念类别`、规范化 `纯概念定义`、定义记录、定义关系全组、直接上位全组、治理生命周期值及值事实、概念生命周期。图读取若未请求世界使用，不强行展开世界；没有使用是合法完整概念。

`纯概念状态`固定数值：已读取1、已创建2、精确重复3、已退出4、未找到5、入口拒绝6、类别冲突7、定义不支持8、定义不相容9、组织冲突10、上位成环11、概念已退役12、目标已退出13、引用冲突14、事实代次漂移15、幂等冲突16、数量预算不足17、历史材料不可用18、资源失败19、内部不一致20、已可能发布21、旧格式不支持22、已迁移生命周期23。

`纯概念读取结果`含版本2、状态、Gread/H、optional 完整事实；`纯概念查询结果`同形状，零命中为未找到且无事实。`纯概念写入结果`另有 optional 首次发布 H、optional 原请求和发布状态（未进入/确认未发布/确认发布/可能发布）；写后失败保留已知阶段但不提供伪完整事实。成功谓词必须逐字段互证请求、返回实际 G/H、定义/类别/完整关系和生命周期，不能只检查状态枚举。

新增公开函数均在 `概念树类数据服务`：

```cpp
纯概念查询结果 精确查询纯概念(const 纯概念查询请求&) const noexcept;
纯概念写入结果 创建或复用纯概念(const 纯概念创建请求&) noexcept;
纯概念创建恢复结果 读取纯概念创建首次结果(const 纯概念创建恢复请求&) const noexcept;
纯概念读取结果 读取纯概念(const 纯概念读取请求&) const noexcept;
纯概念生命周期结果 迁移纯概念生命周期(const 纯概念生命周期请求&) noexcept;
纯概念退出结果 退出无引用叶概念(const 纯概念退出请求&) noexcept;
存在概念使用读取结果 读取存在概念使用(const 存在概念使用读取请求&) const noexcept;
```

生命周期请求字段：版本2、G0、幂等身份、概念、预期生命周期值事实、预期治理状态、目标治理状态、预算。开放活跃→冷却、冷却→活跃、冷却→退役；进入退役必须没有世界使用、定义引用、支持、来源、名称及其它活动保护引用，且没有直接下位。除此之外返回入口拒绝；不以L1节点引用检查代替退役检查。结果含原请求、首次H和同截止完整概念事实。退出请求字段：版本2、G0、幂等身份、概念、预期生命周期值事实、预算；只允许当前退役叶。存在使用、EC模板、任何新旧格式来源/名称/支持及其它 owner 真实入向引用均保护。目标有子边拒绝，本批不实现中间节点重连。退出节点、类别/定义本 owner 关系和值及生命周期在一个 owner 事务完成；历史仍按首次生命周期读回。不能在退出集合中顺手清除其它合法使用。

存在使用读取请求：版本2、Gread/H、E、预算；结果含同截止 E 身份确认和零或一条 `存在概念使用事实{关系,E,EC,生命周期}`。零条明确未找到；多条内部不一致；关系目标还须按相同截止读取完整 EC。历史读不以 E 当前位置替代当时事实。

### 3.3 v2 物理布局与新旧隔离

新 `纯概念结构交付_v2`含版本2、格式锚点、概念族锚点和具名类型组，不含 owner、本体根、根归属或世界挂接前置。概念族锚点只服务元结构枚举，不是概念身份，不能进入定义、上位、使用或世界树。

固定类型登记顺序为：1类型登记（关系）、2概念族成员（关系）、3格式版本（I64）、4概念类别（I64）、5定义成员（关系）、6定义种类（I64）、7定义特征类型（关系）、8定义模板（关系）、9I64域（U64组）、10通用规则（I64）、11直接上位（关系）、12生命周期（I64）、13存在概念使用（关系）。类型和两锚互异，登记为格式锚点→类型、对应顺序1—13；格式锚点的格式版本固定2。未知额外本类结构、缺项或错表示拒绝构造。

定义本体固定：族锚点→C（概念族成员/角色1）；C→定义记录（定义成员/1）；C 的类别1=EC或2=FC；C 的生命周期1=活跃、2=冷却、3=退役。定义记录的种类1=I64 FC、2=合取EC、3=通用EC。FC保存恰一 FT 关系和非空 U64 端点组（每区间两项，signed bit_cast）；合取EC保存排序后的模板关系，角色从1连续；通用EC只保存通用规则I64=1，规则版本由本格式2冻结为1。三分支互斥，不保存空宿主边或假世界证据。上下位为上位→下位，角色1。

新增静态装配函数 `登记纯概念结构_v2(const L1事实基座服务&, L1所有者范围写端口&, const 纯概念结构登记请求_v2&) noexcept`；请求为版本2、G0和幂等身份；结果为状态、Gread、首次H和optional交付。仅零数据的新概念 owner 可首次登记；同键按首次完整材料恢复并逐节点/边/属性核验。若 owner 已有旧根、related v1 或未知普通概念材料且非本请求精确重放，返回旧格式不支持并零写。普通装配使用唯一新 owner，不创建双布局实例。

新增构造重载沿现有类参数保留 l1/features/existences/values/scenes、唯一port，加 `纯概念结构交付_v2`。旧构造和旧格式历史解码保持原义；所有旧写入口在新格式实例上先返回旧格式不支持，不读旧根，也不接受旧静态根应用类构造。旧域只读取和拒绝新写，本批无旧数据转换/删除，不宣称旧库迁移完成。

## 4. 现存概念引用与单例角色

### 4.1 关系映射

| 关系 | 源→目标 | owner及约束 |
| --- | --- | --- |
| 世界存在采用的概念引用 | E→已发布EC | 概念 owner；类型为 v2 存在概念使用、角色1，E当前至多一项；不等于名称、支持或观察 |
| 单例角色登记 | 存在族锚点→角色锚点 | 存在 owner；新具名角色登记类型，角色1；角色锚点普通、无本体属性 |
| 单例角色目标 | 角色锚点→E | 存在 owner；新单例角色目标类型，角色1；每个角色当前至多一项 |

前一关系表达世界信息创建请求所指定的分类引用，不自动证明 EC 的全部具体特征已被观察。通用EC只表示不附加特征约束。后两关系是中性结构：L2不认识“自我”；由自我形成服务解释装配交付的那个角色。角色不是概念节点，不用通用EC唯一性代替自我唯一性。

新增 `存在单例角色身份{稳定编码 值}`；`存在单例角色结构交付`包含两个关系类型和项目当前角色锚点。登记由存在类静态 `登记单例角色结构`提供，形状和所有者核验沿场景元登记；输入版本1、G0、幂等身份，首次在无此结构的 owner 建三个普通节点（两类型+角色锚点）、一条角色登记。重复必须恢复并完整读回同一次首次材料，不造第二角色；本批只开放这一个具名装配登记槽，不实现任意角色业务枚举。

`读取单例角色(const 存在单例角色读取请求&) const noexcept`输入版本1、Gread/H、角色、预算，返回未绑定或唯一完整角色→E及同截止 E 身份；多重目标、跨owner伪角色、已退出角色和不完整关系分别拒绝。角色保留期间普通 E 删除受该关系保护。本批不开放单例解绑或自我退役。

### 4.2 绑定添加合同

新增 `已发布概念绑定创建请求`的完整声明见附录A；直接承载三种绑定、根、具名键variant、已发布EC及预期定义，不嵌套旧请求或复制两套键。单例角色可选只影响中性出生关系，不自动启用场景；自我由明确直接子场景分支同时获得场景视角。

结果 `已发布概念绑定创建结果`包含版本2、绑定状态、概念状态、Gread、首次H、原完整请求、完整绑定事实、完整使用事实、optional 单例角色目标事实。成功要求 EC 的创建H早于世界出生H；使用边、E出生、初始父边及可选角色边同世界H；子场景还要求角色/四根/树归属/父语境同H且E=C。父存在分支也必须具有唯一世界根上行路径，不能跳过现实树核验。

三个调用点固定：

```cpp
// 存在类，允许父存在组成或场景成员。
已发布概念绑定创建结果 添加存在节点(
  const 已发布概念绑定创建请求&, 绑定存在数据服务&,
  已发布概念引用参与者&) noexcept;
// 场景类，只允许直接子场景。

  const 已发布概念绑定创建请求&, 绑定存在数据服务&,
  已发布概念引用参与者&) noexcept;
// 绑定协调器内部完成所有者组合。
已发布概念绑定创建结果 创建绑定存在并引用概念(
  const 已发布概念绑定创建请求&, 已发布概念引用参与者&) noexcept;
```

`已发布概念引用参与者`只在现有合同模块声明，由概念类实现。对普通调用者只可传引用；端口、L1写集、participant-local引用、准备和首次材料读取为 private，friend 仅绑定协调器。内部能力固定为：同底座绑定核验、取得仅本 owner 端口、按G0核验已发布EC与预期定义/生命周期、形成出生使用边片段、读取首次片段和按稳定E/EC读回。禁止在此能力创建概念、写定义/上位/支持、处理未发布概念或接收概念创建方案。

出生事务顺序：存在参与者1；场景分支场景参与者2；概念引用参与者最后。组成分支只有存在+概念两个参与者。现有组成单owner键升级为带组合键与概念键的具名新分支，旧原请求仍只供旧历史。E本地键固定沿原存在片段的1；概念使用边的源为参与者1/本地键1，目标为已发布EC稳定编码。角色→E在存在片段内使用本地键1，不制造前向引用。

写前共同G0核验父、联合路径、可选角色未绑定、EC可用和所有者唯一。L1只承担共同发布及引用完整性；单例当前至多一项与E当前至多一EC由各 owner 在相同G0上完整枚举保证，并发最终由L1代次守卫裁决。概念先退役/退出则出生漂移或精确拒绝；出生先赢则活动使用保护概念治理/退出。不能仅依赖L1节点退出守卫保护生命周期值变更。

## 5. 世界树编排与恢复

创建公开 ABI 升级为版本4，位置/移动现有版本3合同不因本次强制升级。两个创建请求与键variant完整声明见附录A；组成分支没有场景键，场景分支才有场景键，未使用键不参与请求。没有合法EC定义/父参数时零概念写并诊断。

原具名入口 `创建场景并纳入现实世界`、`创建存在并纳入现实世界`接受上述新请求；旧创建请求不保留新写重载，已发布旧请求只供读取/历史。新构造 `建立世界树应用服务(场景类数据服务&, 存在类数据服务&, 概念树类数据服务&, const 世界树根验证请求&)`，世界树持有同一concept引用并把窄引用参与者传给L2；根服务不依赖概念。

原 `绑定存在数据服务::创建绑定存在(const 绑定存在创建请求&)`不得继续保留为公开普通写入口；其准备/历史核验算法改为私有复用，新普通写唯一经带已发布EC的新合同。原世界v3创建及旧P1共同出生重载退出公开新写路径。系统唯一根仍走具名根引导私有参与合同，不能从普通绑定入口选择无概念创建。

固定流程：

1. 校验完整字段、绑定种类、键互异及预算；经全局根与联合位置读回确认父在根内，缺父/错树/退出/预算不足立即返回，无概念写。
2. 当前截止精确查询规范化定义。完整命中复用；仅完整未找到调用 `创建或复用纯概念`。查询漂移、预算、退役、读取失败不进入创建。
3. 取得完整EC及创建H后刷新当前G，重新核验父、角色和EC。不得用概念创建前G0作世界发布守卫。
4. 用世界子请求、EC稳定身份和当前G调用场景/存在类公开添加；必要的参与者写集只在DATA-L2内形成。
5. 以世界提交后的统一Gread/H，经世界层级位置、场景角色、存在身份、单例角色和概念使用公开读取互证。本轮各项必须同截止，读取漂移返回已发布待复核。
6. 完整返回本次定义和使用事实；本批零观察、零事实支持、零名称写，不以初始化生成材料证明经验用途。

新增结果 `世界树概念创建结果_v4`：版本4、世界状态、阶段（输入定位1/概念查询2/概念发布3/世界发布4/最终读回5）、概念子结果、世界子结果、完整原请求、optional最终投影。投影含E、根、直接父、EC完整事实、使用边、可选场景角色及单例角色。只有阶段5的完整互证可成功；不得用“E已创建”代替整体。

恢复识别经绑定协调器的具名公开只读函数，不允许世界层读取L1首次账：

```cpp
已发布概念绑定恢复结果 读取已发布概念绑定创建(
  const 已发布概念绑定恢复请求&, const 已发布概念引用参与者&) const noexcept;
```

恢复请求字段：版本2、当前Gread、绑定种类/父节点、期望世界根、规范化纯EC定义、全部世界组合/存在/场景/概念引用键、optional单例角色、世界/概念预算；没有owner、写集、未发布编码或调用方猜的EC。结果状态为未派发/已读回/已被后继覆盖/幂等冲突/事实代次漂移/预算不足/历史材料不可用/已可能发布/资源失败/内部不一致；数据只含原实际绑定子请求、首次H、当前Gread及完整公开绑定/使用/角色投影。协调器经各private参与能力读取各owner首次材料，在历史H从使用边反取已发布EC，再由概念窄读取核验定义；公开返回不携带首次写集和映射。全账完整且同一个组合结果才能已读回；全无账才未派发；任一部分账不转换为未派发。

世界创建每次先做不触及当前端点的输入形状核验，再经此只读恢复入口识别原世界键。已读回走最终读取；后继覆盖如实返回；已可能发布/读取错误保留原键，只有未派发才进入第1步当前父校验和概念查询。因此曾成功后父退出/改挂不能被前置校验误报零写。首次无账的恢复预算/读取失败也不得进入新写。

当世界键确认未派发时，再经概念公开`读取纯概念创建首次结果`查询该定义键。该入口只读所属owner首次材料，核验规范化定义、组织、上位、键及首次实际G0，返回概念已发布/未派发/可能发布等精确分账。概念已发布时采用其完整身份、首次G0和H，再取得当前G重新核验父及EC，不能继续要求等于最初外层G0；未知或读错停止本次，不进入新概念创建。两种首次键均无账时才使用外层G0做首次位置守卫。

此前别键同义概念零写复用时，本定义键确实没有首次账。重试仍返回未派发，不冒称本键已发布；随后在当前合法位置守卫通过后重新完整查询同义概念。此时若外层G0已漂移，返回漂移，调用者可用新的位置守卫重试，因为该概念键及世界键均未绑定写入G0。SELF-FORM每轮从正式当前根生成位置守卫；不能更改任何已有首次账的G0/键。

恢复不建立进度节点或私有权威字典。各 owner 原键的首次材料及原完整请求是依据；世界结构结果只持值式恢复输入。定义键、世界组合键及各参与者键须由调用方固定且互异，不从节点/线程/时间临时重算。首次材料中的G0属于那次真实子提交，原世界请求G0属于最初输入；两者分别保留，不能为重试篡改首次材料。

同原世界请求重试先查各世界参与者首次账：全无账才按当前父/EC重新准备；有首次账则复用其规范化写集、映射、原子成员键和首次H，转换跨参与者局部引用后完整比对身份、绑定、EC和角色。不得先按旧原G0拒绝精确重放。全参与者账必须同次原子结果；部分账、内容不符或无法确认时保持已可能发布/内部不一致，不补写另一套。概念阶段单独成功而世界失败时保留EC。世界H后父/角色/引用被后继合法操作改变时返回既有操作已被后继事实覆盖，不重建E。

外层世界请求G0是本次最初位置守卫，不是概念提交后的世界子请求G0；成功前刷新产生的子请求完整保存于所属owner首次材料。恢复只能读出并使用首次已经绑定的子G0/键，不以外层新G0覆盖它。外层请求回显是调用方值式材料，首次事实同义由规范化定义、位置、角色和各键互证；不得把回显或缓存声称为一份额外持久业务请求账。只有尚未进入相应owner首次写入的阶段可以取得新当前G0。

## 6. 真实自我形成与普通入口

### 6.1 唯一业务合同

新增 `真实自我形成服务`仅持世界树、存在只读服务和装配交付的单例角色。构造校验同实例，不存自我权威缓存。`形成(const 真实自我形成请求&) noexcept`和`读取当前自我(const 真实自我读取请求&) const noexcept`为仅有业务入口。

形成请求字段及完整声明见附录A：期望世界根、角色和五个固定子键（定义、组合、存在、场景、概念引用）是可恢复的事实选择，没有额外业务请求身份或权威缓存，不接受任意自我编码。异义同键由各owner首次材料裁决请求冲突；不同键企图占用已绑定角色同样冲突，同参必须重新权威读取。预算是读取限额，不是自我身份。

形成顺序：从世界树正式读回唯一根→读角色→无目标时以通用EC规则1/版本1和显式顶层，通过世界树直接子场景创建，将唯一根作为明确父、把同一角色交给出生→有目标时验证原请求首次材料并正式读回→在同一当前截止核验角色唯一指E、E≠根、E的唯一父为根、E=C、场景四根及父语境完整、E→通用EC引用完整→返回真实形成。

自我内部世界就是E的场景视角。不会另建“自我所在场景”“内部场景宿主”对象；本批其外部发生场景为唯一世界根。通用EC不表达自我是单例、不预设特征或能力，不产生安全/服务值；随后具体化必须来自真实信息，不能改写通用EC定义。

结果状态固定：已形成1、精确重复2、已读取3、入口拒绝4、请求冲突5、根无效6、角色冲突7、概念阶段失败8、世界阶段失败9、读取未完成10、已可能发布11、资源失败12、内部不一致13。结果带原请求、实际阶段、世界子结果及optional值式自我投影；投影包含E、根、单例关系、世界位置、场景角色/四根和EC使用的完整公开读回，全部同非零Gread/H。成功谓词不得只检查非零E。

### 6.2 装配、生命周期和启动阶段

普通上下文新增概念 owner（owner签发键0x1006）、纯概念结构（登记键0x1401）、单例角色结构（存在owner登记键0x1202）、概念服务、自我形成服务。已有0x1001—0x1005、0x1101、0x1201、0x1301、0x2001—0x2003保持原义。概念纯定义键0x3001、世界组合0x3002、存在0x3003、场景0x3004、概念引用0x3005只用于该进程上下文，不是世界身份；0x3006不使用、不建立业务请求账。

成员构造顺序：既有底座及四类基础服务→场景→概念结构/服务→根初始化→世界树→自我形成服务；单例角色登记在存在服务构造前完成并追加具名构造重载参数，不能构造后换owner。声明顺序保证析构反序。相关引用均非拥有，普通上下文完整持有到进程退出；析构不得退出世界事实或概念。

世界工厂必须先分配候选世界服务并完成全部可抛验证/值式结果构造，最后在全局根锁内以无抛交换发布根引用与绑定底座；禁止先写全局L1裸指针再执行`new 世界树应用服务`。普通装配在工厂成功后只进行无抛`unique_ptr`移动，立即把含同一L1/世界树的candidate移入全局上下文；此后才分配自我形成服务或执行任何self写。自我服务构造、概念发布、世界出生或读回失败均保留该上下文，下一次从已有服务/正式首次材料继续，不重建底座。工厂发布前的私有candidate失败可以销毁，但不得留下全局根绑定；工厂发布后的异常路径不得销毁其底座。已有上下文而self尚未成功不是完整初始化成功，须继续实际形成/读取。锁保护实例生命周期，成功依据仍来自公开事实。

装配本身不创建普通概念或自我；新增 `初始化普通应用自我() noexcept -> 真实自我形成结果`：在同一上下文锁保护生命周期下调用真实形成。新增 `读取普通应用自我() noexcept -> 真实自我形成结果`只调用完整读取，零写。它们是实际业务调用与独立观察口，不返回owner、端口、L1、锁或悬空world引用。普通上下文不需要为了本批增加裸getter。

`运行普通程序`顺序为装配/唯一根/无根概念结构就绪→`初始化普通应用自我`。真实失败返回阶段17；纯概念结构就绪失败保留阶段18的具体原因（由装配结果分支传递），不进入self。成功后进入下一尚未实现的**方法登记根生产初始化阶段19**并如实返回初始化失败，不创建方法根或线程。阶段18的结构就绪实际前移，稳定数值不是时序。新形成结果不是阶段19成功依据；不得通过固定成功、宿主启动或测试入口解除后续门禁。

### B.1 成功谓词及载荷

共同要求请求/结果版本2，身份有效，原请求全等（含该owner实际G0、键与预算），`0<H<=Gread`；完整事实类别由定义分支确定，C与定义记录互异、同创建H、在读取H有效；定义组恰一C→记录、FC再恰一记录→FT、合取EC按规范模板顺序1..n、通用EC无其它定义边；所有边身份有效、不重复、生命周期在H有效且定义相关边同概念出生H。上位边下位=C且无自环/重复；完整FT/模板类型及图无环由提供者真实读取核验，谓词不以编码非零替代。

登记：已创建/精确重复、确认发布、首次发布H=请求G0+1<=Gread、原请求相等、15个类型/锚身份两两不同；真实表示/关系/owner由服务形成交付前逐项读回。类型登记本地节点键1格式锚点、2族锚点、3—15按13类型顺序，登记边键0x10001—0x1000D，格式值键0x20001及其属性槽变更固定指向格式锚点/格式版本类型；不与节点/关系键碰撞。

读取：已读取，头等于请求，目标概念相同且完整；身份读取允许H时退役但尚未退出。查询额外比对规范化定义；确认未找到仅状态未找到且完整扫描完成、载荷为空，预算/漂移/退役不视为未找到。当前查询退役命中返回概念已退役，历史查询按H返回当时状态。

创建首次写/原键重放：已创建/精确重复、确认发布、首次发布H=G0+1、H=首次发布H、完整定义和父组等于规范化请求。**别键同义复用**：精确重复、确认未发布、首次发布H为空、H=Gread，返回当前活跃/冷却概念；不为复用新写记录或把该概念的历史创建H当成本请求提交H。重试别键同义复用只再查询，不产生owner首次账。

生命周期：已迁移生命周期/精确重复、确认发布、首次发布H=G0+1=H，目标治理值与请求一致，新生命周期值事实不同于预期旧值、其创建H等于本次H；不改变定义或概念出生。退役约束由共同G0真实引用读取证明。

退出：已退出/精确重复、确认发布、首次发布H=G0+1，返回历史读取H=首次发布H-1；历史事实处于退役、旧生命周期值等于预期，概念/定义节点及必需定义边的实际退出H均为首次发布H。服务另在Gread证明当前已退出，不能在退出H要求读取仍活动的完整概念。历史保留已知退出字段；清理或读取不完整时非成功。

使用读取：已读取、头同请求、使用E相同、目标EC与完整概念一致、关系H时有效。无使用为未找到并同时无使用/概念载荷；存在E确认失败不是未找到。所有写非成功清空完整事实/投影，可保留原请求、Gread、已知首次H和真实发布状态；可能发布不降格确认未发布。

创建恢复请求的Gread/预算为本次只读限额，不能当作原写入G0或原预算事实。成功仅已读回，Gread同请求、首次实际G0+1=首次发布H<=Gread，事实在首次H完整且与规范化定义/组织/父组互证；当前退出则目标已退出，不重建。未派发必须完整确认本键没有首次材料，两个首次代次和事实均空；不能由超预算或读取失败推未派发。该函数与创建入口共享同一个private首次材料解码/规范化写集互证helper，不建立第二创建实现或持久请求账。

## 附录D：private概念引用参与和逐键映射

本声明仍位于纯概念合同模块，仅前置声明friend类，不import绑定实现。绑定原因使用`纯概念状态`表达公开概念核验原因，`概念引用原因`使用下列专用枚举表达参与/首次材料状态；两个枚举不得强转。

```cpp
enum class 已发布概念引用参与状态 : std::uint8_t {
  已准备=1, 精确重复=2, 入口拒绝=3, 概念未找到=4, 概念已退役=5,
  目标已退出=6, 类别冲突=7, 定义不相容=8, 引用冲突=9,
  事实代次漂移=10, 幂等冲突=11, 数量预算不足=12,
  历史材料不可用=13, 资源失败=14, 内部不一致=15,
  已可能发布=16, 旧格式不支持=17, 已读取=18, 未派发=19
};
struct 已发布存在概念引用准备请求 final {
  std::uint32_t 版本=2; std::uint64_t G0=0;
  L1所有者范围写入幂等身份 幂等身份;
  L1有限N分区原子参与者身份_v3 参与者;
  L1有限N分区原子事实引用_v3 新存在;
  概念树概念身份 EC; 纯概念定义 预期定义; 概念树预算 预算;
};
struct 已发布概念引用片段结果 final {
  已发布概念引用参与状态 状态=已发布概念引用参与状态::入口拒绝;
  std::uint64_t Gread=0;
  std::optional<L1有限N分区原子参与者写集_v3> 写集;
};
struct 已发布概念引用首次材料结果 final {
  已发布概念引用参与状态 状态=已发布概念引用参与状态::入口拒绝;
  std::uint64_t Gread=0;
  std::optional<L1所有者范围首次写入读取结果> 首次材料;
};
class 绑定存在数据服务;
class 已发布概念引用参与者 {
  friend class 绑定存在数据服务;

  virtual L1所有者范围写端口& 借用存在概念引用写端口() noexcept=0;

    const 已发布存在概念引用准备请求&, std::uint64_t Gread) const noexcept=0;
  virtual 已发布概念引用首次材料结果 读取存在概念引用首次材料(
    L1所有者范围写入幂等身份) const noexcept=0;
  virtual 存在概念使用读取结果 读取存在概念使用(
    const 存在概念使用读取请求&) const noexcept=0;
public:
  virtual ~已发布概念引用参与者()=default;
};
```

派生概念类公开`读取存在概念使用`可以覆盖同名private虚函数；普通场景/存在包装类不能调用private绑定/准备方法，统一由绑定协调器核验它们。端口只在同步L1-v3调用期间借用，存入调用期局部span；不返回、跨调用缓存或异步保存。非成功清空写集/原始材料；准备成功仅已准备，首次材料成功仅已读取，首次账确认不存在仅未派发。读回与首次材料不返回公开上层。

准备请求要求版本2、G0=Gread>0、参与者>1，新存在必须为`参与者1/本地节点键1`的跨参与者引用；EC为稳定当前身份、类别EC、完整定义相同且活跃/冷却。写集零节点/零值、仅关系键1，源前序E、目标稳定EC、类型为存在概念使用、角色1，owner/幂等身份只能来自本概念实例及请求。预算/引用核验失败精确返回；禁止概念定义/支持/观察片段。

状态映射：私有已准备只允许准备有唯一合法写集；已读取只允许完整首次材料；未派发只允许确认无账。其它状态按入口拒绝→绑定入口拒绝，概念未找到/退役/退出/类别/定义/引用/旧格式→绑定概念失败，其余代次/幂等/预算/历史/资源/内部/可能发布对应同名绑定状态；精确重复只用于真实同键首次材料收敛，不能作为空写集成功。未知值内部不一致，原专用原因保留。
