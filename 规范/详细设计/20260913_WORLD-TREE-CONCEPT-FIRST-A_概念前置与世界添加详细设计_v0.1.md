## 3. 纯概念定义与公开合同

### 3.1 类型和唯一性

新增类型使用独立名称，不静默重释旧 `概念树特征定义::形成宿主`：

```cpp
enum class 通用存在定义规则 : std::uint8_t { 未指定 = 0, 不预设特征 = 1 };
struct 通用存在概念定义 final {
  std::uint32_t 规则版本 = 0;
  通用存在定义规则 规则 = 通用存在定义规则::未指定;
  friend bool operator==(const 通用存在概念定义&, const 通用存在概念定义&) = default;
};
struct 纯I64特征概念定义 final {
  概念树特征类型引用 特征类型;
  std::vector<概念树I64区间> 规范域;
  friend bool operator==(const 纯I64特征概念定义&, const 纯I64特征概念定义&) = default;
};
struct 纯合取存在概念定义 final {
  std::vector<概念树概念身份> 特征模板组;
  friend bool operator==(const 纯合取存在概念定义&, const 纯合取存在概念定义&) = default;
};
using 纯概念定义 = std::variant<纯I64特征概念定义,
                                纯合取存在概念定义, 通用存在概念定义>;
enum class 概念初始组织指定 : std::uint8_t { 未指定 = 0, 显式顶层 = 1, 具名上位 = 2 };
struct 纯概念读取请求 final {
  std::uint32_t 版本 = 2;
  std::uint64_t Gread = 0, H = 0;
  概念树概念身份 概念;
  概念树预算 预算;
};
struct 纯概念查询请求 final {
  std::uint32_t 版本 = 2;
  std::uint64_t Gread = 0, H = 0;
  纯概念定义 定义;
  概念树预算 预算;
};
struct 纯概念创建请求 final {
  std::uint32_t 版本 = 2;
  std::uint64_t G0 = 0;
  L1所有者范围写入幂等身份 幂等身份;
  纯概念定义 定义;
  概念初始组织指定 组织 = 概念初始组织指定::未指定;
  std::vector<概念树概念身份> 直接上位;
  概念树预算 预算;
};
```

所有请求比较为逐字段值相等，用于核验本次调用回显；预算、G0和幂等身份均保留在回显中。首次持久身份只按真实规范化写集及组合账核验；预算未持久化，不能用本次回显证明原预算相等，恢复按第5.2节分账。读取必须 `0 < H <= Gread`；当前读使用 H=Gread，调用方先经服务取得当前代次，零不是隐含最新。新接口版本只接受 2。

FC 使用正式类型的规范化接口合并重叠/相邻 I64 闭区间，保留不连续空隙，拒绝空域和超出 FT 允许域；输出转换逐端点保真。模板 EC 排序去重、非空，各目标必须是当前有效纯 FC；不接受未来 FC、普通存在或旧格式概念。通用 EC 只接受规则 1 / 版本 1，定义内容无 FT、F、观察、宿主或自我身份。

上述“当前有效”约束用于新创建和当前查询。历史读取/历史定义查询使用固定H核验FT、模板、直接上位、使用和生命周期；目标或依赖后来在Gread之前退役/退出，不取消其H时合法性。历史返回当时完整定义及其真实后继生命周期，不用当前活动枚举漏掉已退出身份，也不为了读历史重新建节点。

同义键为不可变类别加完整规范化定义。当前冷却概念也参加精确查询并允许复用；退役概念返回 `概念已退役`，不得新建同义项。本批不提供退役恢复算法。不可逆退出概念只供历史，同义重建产生新身份。多个当前同义项返回内部不一致；不按编码或首项取一个。

显式顶层必须空上位；具名上位必须非空且全部同类别、当前可用、不重复、无环。FC 上下位以正式域包含且不相等证明；合取 EC 的上位约束是下位约束的严格子集；通用 EC 可以作为任何非通用 EC 的上位，通用 EC 自身只允许显式顶层。同义身份与组织意图不一致返回 `组织冲突`，不得在创建重试中顺带改图。

### 3.2 事实与结果

`纯概念事实`字段固定为：概念身份、`相关概念类别`、规范化 `纯概念定义`、定义记录、定义关系全组、直接上位全组、治理生命周期值及值事实、概念生命周期。图读取若未请求世界使用，不强行展开世界；没有使用是合法完整概念。

`纯概念状态`固定数值：已读取1、已创建2、精确重复3、已退出4、未找到5、入口拒绝6、类别冲突7、定义不支持8、定义不相容9、组织冲突10、上位成环11、概念已退役12、目标已退出13、引用冲突14、事实代次漂移15、幂等冲突16、数量预算不足17、历史材料不可用18、资源失败19、内部不一致20、已可能发布21、旧格式不支持22、已迁移生命周期23。

`纯概念读取结果`含版本2、状态、Gread/H、optional 完整事实；`纯概念查询结果`同形状，零命中为未找到且无事实。`纯概念写入结果`另有 optional 首次发布 H、optional 原请求和发布状态（未进入/确认未发布/确认发布/可能发布）；写后失败保留已知阶段但不提供伪完整事实。成功谓词必须逐字段互证请求、返回实际 G/H、定义/类别/完整关系和生命周期，不能只检查状态枚举。

生命周期请求字段：版本2、G0、幂等身份、概念、预期生命周期值事实、预期治理状态、目标治理状态、预算。开放活跃→冷却、冷却→活跃、冷却→退役；进入退役必须没有世界使用、定义引用、支持、来源、名称及其它活动保护引用，且没有直接下位。除此之外返回入口拒绝；不以L1节点引用检查代替退役检查。结果含原请求、首次H和同截止完整概念事实。退出请求字段：版本2、G0、幂等身份、概念、预期生命周期值事实、预算；只允许当前退役叶。存在使用、EC模板、任何新旧格式来源/名称/支持及其它 owner 真实入向引用均保护。目标有子边拒绝，本批不实现中间节点重连。退出节点、类别/定义本 owner 关系和值及生命周期在一个 owner 事务完成；历史仍按首次生命周期读回。不能在退出集合中顺手清除其它合法使用。

### 3.3 v2 物理布局与新旧隔离

新 `纯概念结构交付_v2`含版本2、格式锚点、概念族锚点和具名类型组，不含 owner、本体根、根归属或世界挂接前置。概念族锚点只服务元结构枚举，不是概念身份，不能进入定义、上位、使用或世界树。

新增静态装配函数 `登记纯概念结构_v2(const L1事实基座服务&, L1所有者范围写端口&, const 纯概念结构登记请求_v2&) noexcept`；请求为版本2、G0、幂等身份和本次最大空域核验事实数；结果为状态、Gread、首次H和optional交付。完整调用顺序和预算分账见附录E.1。仅零数据的新概念 owner 可首次登记；同键按首次完整材料恢复并逐节点/边/属性核验。若 owner 已有旧根、related v1 或未知普通概念材料且非本请求精确重放，返回旧格式不支持并零写。普通装配使用唯一新 owner，不创建双布局实例。

## 5. 世界树编排与恢复

创建公开 ABI 升级为版本4，位置/移动现有版本3合同不因本次强制升级。两个创建请求与键variant完整声明见附录A；组成分支没有场景键，场景分支才有场景键，未使用键不参与请求。没有合法EC定义/父参数时零概念写并诊断。

原具名入口 `创建场景并纳入现实世界`、`创建存在并纳入现实世界`接受上述新请求；旧创建请求不保留新写重载，已发布旧请求只供读取/历史。新构造 `建立世界树应用服务(场景类数据服务&, 存在类数据服务&, 概念树类数据服务&, const 世界树根验证请求&)`，世界树持有同一concept引用并把窄引用参与者传给L2；根服务不依赖概念。

原 `绑定存在数据服务::创建绑定存在(const 绑定存在创建请求&)`不得继续保留为公开普通写入口；其准备/历史核验算法改为私有复用，新普通写唯一经带已发布EC的新合同。原世界v3创建及旧P1共同出生重载退出公开新写路径。系统唯一根仍走具名根引导私有参与合同，不能从普通绑定入口选择无概念创建。

固定流程：

1. 校验完整字段、绑定种类、键互异及预算；经全局根与联合位置读回确认父在根内，缺父/错树/退出/预算不足立即返回，无概念写。
2. 当前截止精确查询规范化定义。完整命中复用；仅完整未找到调用 `创建或复用纯概念`。查询漂移、预算、退役、读取失败不进入创建。
3. 取得完整EC及创建H后刷新当前G，重新核验父、角色和EC。不得用概念创建前G0作世界发布守卫。
4. 用世界子请求、EC稳定身份和当前G调用场景/存在类公开添加；必要的参与者写集只在DATA-L2内形成。
5. 以世界提交后的统一Gread/H，经世界层级位置、场景角色、存在身份、单例角色和概念使用公开读取互证。本轮各项必须同截止，读取漂移返回已发布待复核。
6. 完整返回本次定义和使用事实；本批零观察、零事实支持、零名称写，不以初始化生成材料证明经验用途。

新增结果 `世界树概念创建结果_v4`：版本4、世界状态、阶段（输入定位1/概念查询2/概念发布3/世界发布4/最终读回5）、概念子结果、世界子结果、完整原请求、optional最终投影。投影含E、根、直接父、EC完整事实、使用边、可选场景角色及单例角色。只有阶段5的完整互证可成功；不得用“E已创建”代替整体。

恢复识别经绑定协调器的具名公开零新增事实函数；其内部允许第5.2节限定的旧G重放，不允许世界层读取L1首次账或借用端口：

```cpp
已发布概念绑定恢复结果 读取已发布概念绑定创建(
  const 已发布概念绑定恢复请求&, 已发布概念引用参与者&) const noexcept;
```

恢复请求字段：版本2、当前Gread、绑定种类/父节点、期望世界根、规范化纯EC定义、全部世界组合/存在/场景/概念引用键、optional单例角色、世界/概念预算；没有owner、写集、未发布编码或调用方猜的EC。结果状态为未派发/已读回/已被后继覆盖/幂等冲突/事实代次漂移/预算不足/历史材料不可用/已可能发布/资源失败/内部不一致；数据只含原实际绑定子请求、首次H、当前Gread及完整公开绑定/使用/角色投影。协调器经各private参与能力读取各owner首次材料，在历史H从使用边反取已发布EC，再由概念窄读取核验定义；公开返回不携带首次写集和映射。全账完整且同一个组合结果才能已读回；全无账才未派发；任一部分账不转换为未派发。

世界创建每次先做不触及当前端点的输入形状核验，再经此只读恢复入口识别原世界键。已读回走最终读取；后继覆盖如实返回；已可能发布/读取错误保留原键，只有未派发才进入第1步当前父校验和概念查询。因此曾成功后父退出/改挂不能被前置校验误报零写。首次无账的恢复预算/读取失败也不得进入新写。

当世界键确认未派发时，再经概念公开`读取纯概念创建首次结果`查询该定义键。该入口只读所属owner首次材料，核验规范化定义、组织、上位、键及首次实际G0，返回概念已发布/未派发/可能发布等精确分账。概念已发布时采用其完整身份、首次G0和H，再取得当前G重新核验父及EC，不能继续要求等于最初外层G0；未知或读错停止本次，不进入新概念创建。两种首次键均无账时才使用外层G0做首次位置守卫。

此前别键同义概念零写复用时，本定义键确实没有首次账。重试仍返回未派发，不冒称本键已发布；随后在当前合法位置守卫通过后重新完整查询同义概念。此时若外层G0已漂移，返回漂移，调用者可用新的位置守卫重试，因为该概念键及世界键均未绑定写入G0。SELF-FORM每轮从正式当前根生成位置守卫；不能更改任何已有首次账的G0/键。

恢复不建立进度节点或私有权威字典。各owner原键首次材料与原组合账是持久依据，调用方请求提供待核验的身份及本次预算；世界结构结果只持值式恢复输入，不假称恢复完整历史业务请求。定义键、世界组合键及各参与者键须由调用方固定且互异，不从节点/线程/时间临时重算。首次材料中的G0属于那次真实子提交，原世界请求G0属于最初输入；两者分别保留，不能为重试篡改首次材料。

同原世界请求重试先查各世界参与者首次账：全无账才按当前父/EC重新准备；有首次账则复用其规范化写集、映射、原子成员键和首次H，转换跨参与者局部引用后完整比对身份、绑定、EC和角色。不得先按旧原G0拒绝精确重放。全参与者账必须同次原子结果；部分账、内容不符或无法确认时保持已可能发布/内部不一致，不补写另一套。概念阶段单独成功而世界失败时保留EC。世界H后父/角色/引用被后继合法操作改变时返回既有操作已被后继事实覆盖，不重建E。

外层世界请求G0是本次最初位置守卫，不是概念提交后的世界子请求G0；成功前刷新产生的子请求完整保存于所属owner首次材料。恢复只能读出并使用首次已经绑定的子G0/键，不以外层新G0覆盖它。外层请求回显是调用方值式材料，首次事实同义由规范化定义、位置、角色和各键互证；不得把回显或缓存声称为一份额外持久业务请求账。只有尚未进入相应owner首次写入的阶段可以取得新当前G0。

### 5.1 当前根读取与同实例核验（v0.2支撑）

直接复用`概念树类数据服务::读取当前事实代次() const -> 概念树截止结果`。该既有public入口只读取真实当前事实代次，不读旧概念根，在纯v2概念实例上同样可用；不新增L2接口、owner、元结构或文件。世界树工厂已保证其concept、scene、existence同底座，业务调用者不取得L1或概念端口。

仅在`海中鱼巣/业务/应用服务.世界树类.ixx`的既有类追加以下public成员；声明和定义仍在该模块内：

```cpp
// 世界树应用服务
世界树根验证结果 读取当前现实世界根(const 世界树读取预算&) const noexcept;
bool 使用存在提供者(const 存在类数据服务&) const noexcept;

// 世界树根验证结果：保留原成功(世界树根验证请求)并追加此重载
bool 成功(const 世界树读取预算& b) const noexcept {
  return b.最大场景数量 >= 1 && b.最大场景数量 <= 4096 &&
         b.最大关系数量 >= 1 && b.最大关系数量 <= 4096 &&
         !结果头.绑定原因 &&
         成功(世界树根验证请求{2, 结果头.Gread, b});
}
```

`使用存在提供者`精确返回`&provider == &existence_`（成员名称可随既有实现保持一致），只证明为world装配时同一个存在服务实例；不查询事实、不写入、不返回内部引用，不把同底座不同实例视为相同。真实自我形成服务构造时调用此谓词，false抛`std::invalid_argument`，由既有装配边界映射自我服务构造失败；不得在构造中创建事实或用自我形成结果代替实例核验。

`读取当前现实世界根`复用`世界树读取预算`和根验证v2结果，不新增请求/结果类型、枚举或协议版本。它是读取当前值的入口，输入不带调用方猜测的G0；`世界树应用合同版本`及原位置/移动、创建v4版本均不因此变化。唯一算法：

1. 初始结果头为版本2、入口拒绝、现实树预读、Gread=0，所有optional为空。预算两项均在1..4096，非法直接返回且不读底座。
2. 调用同一concept的`读取当前事实代次()`取得g1。必须`成功()`，即合同1、已读取、Gread>0；据此形成唯一局部`世界树根验证请求{2,g1.Gread,b}`。
3. 调用既有`验证现实世界根`，完整验证同截止场景树和世界根无联合父；成功还须根身份等于本world工厂绑定根。非成功保留原世界状态、场景原因和已读Gread，清空树；不能将global根缓存中的`最近验证G`作为本次截止或完整根证明。
4. 完整根验证成功后，再次通过同一concept读取g2。必须成功且`g2.Gread==g1.Gread`；不同则返回事实代次漂移，Gread=g2.Gread，清空树。未通过不循环重试，不把一次请求偷偷切换为新截止。
5. 最终结果须通过新增预算谓词后才交付。全部读取零写；不更新全局根缓存或任何权威/非权威索引，不持久记录截止，不把成功谓词当作实际图验证。该成功只证明上述守卫内一致，不能保证返回后并发写入不再发生。

两次concept截止读取的精确映射相同：有效成功继续；合同版本错误、已读取却Gread为0、未知枚举或其它非成功均映射世界`内部不一致`；`概念树数据状态::资源失败`映射世界`资源失败`，`事实代次漂移`映射世界`事实代次漂移`。concept失败前没有实际G则世界Gread=0；g1已取得而g2失败则保留g1.Gread。根验证已返回的精确世界原因沿原映射保留；任何异常中bad_alloc/length_error为资源失败，其它异常内部不一致。所有非成功均清空树、首次发布H、存在原因和绑定原因；仅根验证实际产生的场景原因可保留。只读失败不得返回部分已发布、已可能发布或写入结果未知。

自我接线固定使用`世界树读取预算{r.预算.最大场景数量,r.预算.最大关系数量}`。`形成`每次先读完整当前根，以返回Gread读取单例角色和构造尚未绑定首次账的世界请求；期望根与读回根不等返回根无效。原键恢复依第5节进行，不能将新G覆盖已绑定子G0。`读取当前自我`也先调用该当前根入口，必须读回Gread等于其显式请求Gread，再用同一G读取角色、世界完整信息及概念使用；不等返回读取未完成且无投影。`读取普通应用自我`先调用该入口得到真实G和根，再形成自我读取请求；第二次守卫若遇并发漂移同样如实失败，不借缓存绕过。

自我对当前根失败的映射：入口拒绝→入口拒绝；资源失败→资源失败；内部不一致及不属于根读取的成功/移动/创建/幂等/发布状态→内部不一致；事实代次漂移、数量预算不足、历史材料已清理→读取未完成；场景不在现实树、引用冲突、形成场景环及根身份不符→根无效。其它状态内部不一致。每次失败无完整自我投影。若本次世界出生已经发生，原世界结果和首次发布事实仍保留，不把随后根读取失败改记为零写；无新事实时只读失败不产生发布未知。

### 5.2 组合键恢复与预算分账（v0.3支撑）

已核L1物理事实：`核心/L1所有者范围CRUD.数据.h`的owner首次材料只有owner键、规范化单owner写集和首次结果，没有组合键或预算。`核心/仓库.L1事实基座.ixx`的v3实现在独占锁内先查询组合键并比较完整规范请求；命中返回精确重复，未命中先检查共同G0，之后才构造候选仓库和新组合账。因此本恢复函数可在以下前置条件成立后调用已有提交入口，仍保证零新增事实、零新幂等账；这里的“只读”指机器效果，不声称内部只调用读取API。

1. 先按请求Gread/预算完整读取所有规定参与者的首次材料。全无材料仍返回未派发；它只证明该组子键未发布，不证明组合键未被其它请求使用，禁止在该分支试探提交。部分材料、不完整材料或代次不一致如实非成功，禁止重放。
2. 全部材料必须证明同一次真实首次成功：owner、子键、分支映射符合附录D，所有首次H相同，首次G0均为H-1，且`0<G0<H<=请求.Gread`。请求身份、EC、角色和全部结构材料按同截止及历史H互证；预算或历史读取失败禁止重放。此时才允许恢复原实际G0，不能使用调用者外层新G0。
3. 从首次单owner规范化写集及附录D映射重建原v3表示：参与者序号/owner/子键/局部键保持，原跨参与者新E端点还原为前序`{P1,K1}`，稳定EC及既有父/角色/类型仍是稳定编码。本地节点引用保持本地键，不把所有稳定编码泛化为局部引用。重建候选再次降为单owner规范化表示，须逐字段等于全部首次材料；不重新调用按当前状态准备出生的入口。
4. 候选的组合键取本次请求待核验值，共同G0固定为上述原G0；所有片段G0相同。由绑定协调器借用存在、场景（有则）及概念参与者的既有私有端口，以第1参与者端口调用`提交有限N分区原子事务_v3(候选,其余参与者)`；其余参数为该API的调用期`std::vector<const L1所有者范围写端口*>`。不缓存端口，不用const_cast。第二个公开参数因此改为nonconst参与者引用；协调器成员函数仍为const，借用的是其引用成员指向的既有服务。
5. 唯一通过条件：L1返回合同3、请求组合键、状态精确重复、共同H等于已知首次H、`是否已确认形成内存权威发布==false`、重试边界为原幂等身份读回收敛，参与者序号/owner/映射逐项与首次材料相同。通过后再完成同一请求Gread的独立读回；如并发使该读取截止漂移，则返回事实代次漂移，不返回完整恢复投影。

零新增事实证明：已验证的真实首次H使`G0=H-1<请求.Gread`，同一底座事实代次只会保持或增长；L1在组合键未命中时必先因旧G拒绝，不能进入候选状态、新身份、新关系、新值、新owner账、新组合账或持久发布。组合键命中也只返回既有结果。禁止为收到漂移刷新G、改变子键/局部表示或再次尝试新写；不得把此合同扩展为任意旧G探测接口。

| 受控重放L1结果 | 恢复结果 |
| --- | --- |
| 精确重复且完整字段/映射均相等 | 继续真实读回，完整后才为已读取 |
| 事实代次漂移或幂等冲突 | 幂等冲突；完整子账分支下表明请求组合键不匹配，不能返回未派发 |
| 资源失败 | 资源失败；已知首次H可保留 |
| 入口拒绝、引用冲突、内部不一致、未知枚举、精确重复材料失配 | 内部不一致，不伪装合法请求输入错误 |
| 已可能发布，或异常返回已提交/本次权威发布为true | 已可能发布，停止依赖分支并保留诊断材料；不得按零新增事实成功解释这一违反前提的结果 |

正常受控分支的bad_alloc/length_error为资源失败，其它异常内部不一致；仅报告发布迹象的异常合同结果走上表已可能发布。组合尚未核验成功时清空`原实际子请求`和完整投影，可保留已知首次H、实际读取G及精确原因；核验通过而最终读取失败时可以保留已核验子请求，仍无完整投影。L1漂移返回的共同事实代次只表示它实际观察的当前G，不能覆盖原首次H或原G0。

预算证据固定分账：恢复结果继续使用现有`原实际子请求`字段，其绑定身份、根、EC、角色、键与G0由首次材料及组合账核验；其中两组预算填本次恢复请求的限额，不能声称是首次写入预算。`成功(恢复请求)`要求这些预算等于本次限额、其它身份字段与请求及正式事实相符，且`原G0+1=首次H`；不能以请求回显代替组合账证明。适当增加预算不构成幂等冲突；减少到无法完整核验时返回数量预算不足并停止，不能放宽完整性。其它纯概念恢复同样不恢复原预算；写入结果的逐字段原请求相等只检查当前调用回显，不新增预算持久事实、请求账或跨重建缓存。

## 6. 真实自我形成与普通入口

### 6.1 唯一业务合同

新增 `真实自我形成服务`仅持世界树、存在只读服务和装配交付的单例角色。构造校验同实例，不存自我权威缓存。`形成(const 真实自我形成请求&) noexcept`和`读取当前自我(const 真实自我读取请求&) const noexcept`为仅有业务入口。

形成请求字段及完整声明见附录A：期望世界根、角色和五个固定子键（定义、组合、存在、场景、概念引用）是可恢复的事实选择，没有额外业务请求身份或权威缓存，不接受任意自我编码。异义同键由各owner首次材料裁决请求冲突；不同键企图占用已绑定角色同样冲突，同参必须重新权威读取。预算是读取限额，不是自我身份。

形成顺序：按第5.1节从世界树正式读回当前唯一根→读角色→无目标时以通用EC规则1/版本1和显式顶层，通过世界树直接子场景创建，将唯一根作为明确父、把同一角色交给出生→有目标时验证原请求首次材料并正式读回→在同一当前截止核验角色唯一指E、E≠根、E的唯一父为根、E=C、场景四根及父语境完整、E→通用EC引用完整→返回真实形成。

自我内部世界就是E的场景视角。不会另建“自我所在场景”“内部场景宿主”对象；本批其外部发生场景为唯一世界根。通用EC不表达自我是单例、不预设特征或能力，不产生安全/服务值；随后具体化必须来自真实信息，不能改写通用EC定义。

结果状态固定：已形成1、精确重复2、已读取3、入口拒绝4、请求冲突5、根无效6、角色冲突7、概念阶段失败8、世界阶段失败9、读取未完成10、已可能发布11、资源失败12、内部不一致13。结果带原请求、实际阶段、世界子结果及optional值式自我投影；投影包含E、根、单例关系、世界位置、场景角色/四根和EC使用的完整公开读回，全部同非零Gread/H。成功谓词不得只检查非零E。

### 6.2 装配、生命周期和启动阶段

普通上下文新增概念 owner（owner签发键0x1006）、纯概念结构（登记键0x1401）、单例角色结构（存在owner登记键0x1202）、概念服务、自我形成服务。已有0x1001—0x1005、0x1101、0x1201、0x1301、0x2001—0x2003保持原义。概念纯定义键0x3001、世界组合0x3002、存在0x3003、场景0x3004、概念引用0x3005是同一受控存储中普通应用的固定请求键，按4070保留首次账并跨进程恢复，不是世界身份；0x3006不使用、不建立业务请求账。

成员构造顺序：附录H持久配置/运行包→六owner原键端口→既有四类基础服务→场景→概念结构/服务→根初始化或原键恢复→世界树→自我形成服务；单例角色登记在存在服务构造前完成并追加具名构造重载参数，不能构造后换owner。声明顺序保证析构反序。相关引用均非拥有，普通上下文完整持有到进程退出；析构不得退出世界事实或概念。

世界工厂必须先分配候选世界服务并完成全部可抛验证/值式结果构造，最后在全局根锁内以无抛交换发布根引用与绑定底座；禁止先写全局L1裸指针再执行`new 世界树应用服务`。普通装配在工厂成功后只进行无抛`unique_ptr`移动，立即把含同一L1/世界树的candidate移入全局上下文；此后才分配自我形成服务或执行任何self写。自我服务构造、概念发布、世界出生或读回失败均保留该上下文，下一次从已有服务/正式首次材料继续，不重建底座。工厂发布前的私有candidate失败可以销毁，但不得留下全局根绑定；工厂发布后的异常路径不得销毁其底座。已有上下文而self尚未成功不是完整初始化成功，须继续实际形成/读取。锁保护实例生命周期，成功依据仍来自公开事实。

装配本身不创建普通概念或自我；新增 `初始化普通应用自我() noexcept -> 真实自我形成结果`：在同一上下文锁保护生命周期下调用真实形成。新增 `读取普通应用自我() noexcept -> 真实自我形成结果`只调用完整读取，零写。它们是实际业务调用与独立观察口，不返回owner、端口、L1、锁或悬空world引用。普通上下文不需要为了本批增加裸getter。

`运行普通程序`顺序为装配/唯一根/无根概念结构就绪→`初始化普通应用自我`。真实失败返回阶段17；纯概念结构就绪失败保留阶段18的具体原因（由装配结果分支传递），不进入self。成功后进入下一尚未实现的**方法登记根生产初始化阶段19**并如实返回初始化失败，不创建方法根或线程。阶段18的结构就绪实际前移，稳定数值不是时序。新形成结果不是阶段19成功依据；不得通过固定成功、宿主启动或测试入口解除后续门禁。

### B.1 成功谓词及载荷

共同要求请求/结果版本2，身份有效，原请求与本次调用全等（含该owner实际G0、键与本次预算；该比较不证明原预算持久化），`0<H<=Gread`；完整事实类别由定义分支确定，C与定义记录互异、同创建H、在读取H有效；定义组恰一C→记录、FC再恰一记录→FT、合取EC按规范模板顺序1..n、通用EC无其它定义边；所有边身份有效、不重复、生命周期在H有效且定义相关边同概念出生H。上位边下位=C且无自环/重复；完整FT/模板类型及图无环由提供者真实读取核验，谓词不以编码非零替代。

登记：已创建/精确重复、确认发布、首次发布H=请求G0+1<=Gread、原请求相等、15个类型/锚身份两两不同；真实表示/关系/owner由服务形成交付前逐项读回。类型登记本地节点键1格式锚点、2族锚点、3—15按13类型顺序，登记边键0x10001—0x1000D，格式值键0x20001及其属性槽变更固定指向格式锚点/格式版本类型；不与节点/关系键碰撞。

读取：已读取，头等于请求，目标概念相同且完整；身份读取允许H时退役但尚未退出。查询额外比对规范化定义；确认未找到仅状态未找到且完整扫描完成、载荷为空，预算/漂移/退役不视为未找到。当前查询退役命中返回概念已退役，历史查询按H返回当时状态。

创建首次写/原键重放：已创建/精确重复、确认发布、首次发布H=G0+1、H=首次发布H、完整定义和父组等于规范化请求。**别键同义复用**：精确重复、确认未发布、首次发布H为空、H=Gread，返回当前活跃/冷却概念；不为复用新写记录或把该概念的历史创建H当成本请求提交H。重试别键同义复用只再查询，不产生owner首次账。

### E.1 概念登记的合法消费

在本设计的`纯概念结构登记请求_v2`末尾增加`std::uint64_t 最大空域核验事实数=0;`，作为本次限额，零值入口拒绝；版本轴仍为尚未完成实施的纯布局v2。普通装配显式填入`1048576`。该数只限制本次核验成本，不是布局身份、不写入任何节点或幂等材料，也不以其推断世界规模。原请求回显中的限额来自本次请求；同键重放不能声称从首次账恢复了该预算。

登记顺序固定：

1. 校验本次请求和port同底座；先按本次登记键读取owner首次材料。
2. 原键有完整首次材料：按 A v0.3 已定物理布局、原G0、映射和正式读回恢复；不要求owner现在为空。更换原G0/写集是幂等冲突；增加本次核验限额不改变首次布局身份。
3. 原键确认未找到：以`G0`调用4015第9.1节读口。false或范围不支持映射为纯概念旧格式不支持；true才允许形成原有登记写集。空域读与正式提交之间若有其它写入，全局G0守卫使本请求漂移，不能刷新G后沿用旧空域结果。
4. 空域读取的入口拒绝、漂移、预算、资源和内部不一致按同名纯概念状态返回；owner未找到/已退出映射内部不一致，因为装配port应绑定一个活动独占owner。此阶段确认未发布，清空交付。
5. 之后仍用既有owner提交和首次材料正式读回，不改布局写集。发布未知时保留原键/G0，不重新新建owner或换登记键。

异键已存在v2布局仍返回旧格式不支持，不把“形状相同”当另一键的精确重放；后续真需要跨键发现布局，应另有明确合同。本批只承诺防止在既有域重复登记。

### E.2 概念退役与退出消费规则

L1只返回事实。准许哪些引用由概念owner根据 A 纯v2完整布局和已有生命周期规则解释。不能在L1增加“支持、来源、名称、退役”分支。
