## 1. 目标与完成边界

本叶新建 4200 唯一正式服务身份 `世界树业务服务` 的三读真实门面。服务只保存 P29—P31 唯一 `世界树快照读取服务` 的只读引用，并提供：

```text
查询存在完整事实 -> P30 读取存在完整事实
查询场景完整事实 -> P31 读取场景完整事实
读取完整世界事实快照 -> P29 同名入口
```

每个门面函数只把调用方的强类型请求 const 借用原样传给唯一 provider 恰一次，并把 provider 的完整值式结果逐字段原样返回。门面不重新校验请求、不重解释状态、不重组快照、不改写诊断、不捕获后改判异常、不建立重试或第二读取链。

必须同时成立：

- 新模块和类身份唯一，当前代码不存在第二 `世界树业务服务`；
- 只复用 P28—P31 请求、结果、状态、快照和诊断 DTO，不声明门面专属读 DTO；
- 三个函数分别恰调用对应 provider 一次，其它两个 provider 根调用0；
- `已读取`、全部结构化非成功、`未实现` 与载荷逐字段保持，不把空组、未找到、漂移或许可拒绝改判；
- 函数不读取仓库、SQL、缓存、材料、历史、审计、锁、许可、事务、时钟或运行期路由；
- 门面无写入口、无写 provider、无机器事实所有权和无生产装配。

本叶不设计 4200 六个写能力、状态身份轻量定位、治理白名单 variant 路由、动作动态、因果、任务/结算、恢复装配、运行期接线、旧入口删除、集成验收或 STEP-5。

```cpp
export inline constexpr std::uint32_t 世界树业务服务合同版本 = 1;

export class 世界树业务服务 final {
public:
    explicit 世界树业务服务(
        const 世界树快照读取服务& 快照读取) noexcept
        : 快照读取_(快照读取) {}

    世界树业务服务() = delete;
    世界树业务服务(const 世界树业务服务&) = delete;
    世界树业务服务& operator=(const 世界树业务服务&) = delete;
    世界树业务服务(世界树业务服务&&) = delete;
    世界树业务服务& operator=(世界树业务服务&&) = delete;

    完整世界存在快照读取结果 查询存在完整事实(
```

`世界树业务服务合同版本` 固定为1，并静态断言等于本阶段 `完整世界快照合同版本`。三读请求继续由 P28/P30 唯一 DTO 中的 `合同版本` 字段携带，不追加门面版本字段、不双重校验；后继写面必须继续遵守 4200 的服务合同版本1。

构造只绑定非空左值引用，不读取 provider、不恢复、不注册入口。调用方拥有 provider 并保证其寿命覆盖门面及全部同步调用。禁止默认构造、指针/optional 依赖、setter、运行期替换、服务定位器、全局单例或兼容构造。

本叶只冻结三读阶段的最小构造。后继六写门面必须在独立设计中冻结其真实 provider、构造扩展和源兼容策略，不得由 P32 执行者预留空指针、未实现写根或万能依赖容器。新增写面不得改变本叶三个函数的名称、参数、返回、可见性或一对一委托语义。

## 6. 状态、异常、并发与生命周期

三根返回值必须与 provider 返回值默认全等，具体包括：

```text
状态枚举
optional 是否有值及完整快照全部字段
合同/规则/根/目标/事实截止/完整性/排序
合法空组
缺项组内容和顺序
未实现及零载荷
```

provider 返回 `已读取`、未找到、入口拒绝、版本漂移、许可拒绝、资源失败、内部不一致或未实现时，门面均原样返回。写入口状态或坏成功若由 provider 违反合同返回，门面也不得擅自修复；该错误应由 provider 专项和后继集成验收发现。

门面不 `noexcept`，与 P29—P31 实际签名一致；provider 若按合同内部映射异常，门面收到结构化结果。任何违反 provider 合同而外泄的异常原样传播，本叶不通过二次调用或改判掩盖根因。

门面只有一个 const 引用成员，无锁、缓存或可变状态。并发调用的许可、代次和重试语义完全属于 provider；门面不声明返回后事实仍当前。析构不拥有或释放 provider。

专项至少覆盖：

1. 类不可默认构造、复制或移动，只能由 `const 世界树快照读取服务&` 左值构造；
