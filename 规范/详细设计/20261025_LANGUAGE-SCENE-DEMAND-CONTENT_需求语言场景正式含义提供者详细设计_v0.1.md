## 3. 有限范围与事实地位

本叶仅承载7240已经规定的两个含义操作：需求描述（期望内容）与语言回应（指向具体内容的赞同主张/确认所指/纠正/拒绝请求）。材料来源则有两个独立分支：实际外设接入材料、本次自我生成表达。后者按7230§2.1建立本次生成来源，不以未来发送成功或对端回复为前置。需求提议可不完整，缺项是已保存内容的缺口，不创建不完整正式D。回应的具体方式是语言操作载荷，不是“确认=true”的世界特征。

需求的表达者、需求主体、目标存在是不同角色；表达者未明可以保存，不能从窗口、用户昵称或接收时间猜人类。需求内容为期望，不表示目标当前已实现。回应指向固定内容身份，不因文字“收到/明白”自动判赞同；发布接口保存调用方已经完成解释并选择的含义，不解释自由字符串，也不授予任何需求/任务操作资格。

不实现全量否定、量词、条件、引述或嵌套语言引擎。出现这些未覆盖用途必须显式未支持，不能剥去作用域后按肯定需求保存。内容来源和未覆盖范围可保留，但不能报告完整含义。

| 本次生成来源 | 类型、所属内容组织根、生成者存在、依据内容*（显式顺序）、所生成文本；只记录本次生成，不含发送成功/对端响应 |
| 交互记录 | 类型、所属内容组织根、自然语言场景、语言、固定文本、来源分支；外设分支为外设消息/场景/窗口/正文材料/来源键各项及正式记录时间语义/纳秒，生成分支为生成来源引用；回应交互? |
| 作用域 | 类型、所属内容、种类；本叶单层无父域；不支持嵌套时零内容发布 |
| 内容 | 类型、所属内容组织根、场景、交互、作用域、操作、来源起/止、表达者?、表达者来源起/止?、需求内容概念?、角色项*、被回应内容?、回应方式?、相关内容? |
| 角色项 | 类型、所属内容、字段FT、值种类、节点引用或目标形式I64或方向I64（严格一项）、来源起/止 |

所有“类型/所属/登记”等均为语言owner私有结构键，与业务FT分开；角色项的 `字段FT`必须是正式概念身份，不能写1001等数字充当FT。内容操作、回应方式和作用域只保存有限语言操作枚举，不拿它们充任世界特征或底层外部关系类型。新语言含义不是正式D，不保存权重、活动状态、父需求或执行域。

没有额外场景成员列表权威：语言owner通过内容的“场景”字段目标索引完整反查，交互和文本均通过真实引用可回查。主内容只在语言组织根登记，作用域/角色由内容唯一持有，不用普通场景父子边组织这些非E信息。发布时成组闭合全部字段/引用，读回核双方归属与根登记；不把未登记私有节点交付为正式内容。

## 7. 来源、内容准入与复用键

### 7.1 真实外设来源

`登记外设语言交互`先在语言锁外调用源reader及自然语言场景保护。外设使用现 `读取正式消息(节点,&保护)`，完整保护包含消息、消息根、正文材料、外设场景和窗口；成功还须消息方向为既有接收/发送/输出之一，正文/原始来源键/正式记录时间全部可读，不填写机器当前时间或将输出当发送成功。返回前按当前完整保护再核消息及正文未变化，分类前提变化而不是以旧消息拼新保护。消息根其它追加造成快照变化可返回前提变化，不能虚报正文被篡改。

语言owner在同一原子组建立固定文本及交互，引用正式外设消息和正文材料，并复制已核原文到唯一语言文本材料；外设消息编码本身不是语言记录。原材料保留供追溯，语言文本是固定语言材料而非另一份业务事实。`来源`的外设分支中`UTF8正文`及来源键从固定记录/被保护原消息读回核同，不能从调用者任意字符串构造。

幂等键为 `(自然语言场景,语言,外设消息)`：同键全部固定材料及回应交互相同才复用，不重复建文本；同键异义输入拒绝。不同场景可对同一原始消息建立不同语言出现，不合并出现。回应交互必须是语言owner真实交互，可跨语言场景引用；只记录回应来源，不自动赞同或合并两场景。

没有表达者字段从宿主推导。语言记录的表达/接收时刻不混写，本叶只保存已有外设正式记录时间；表达时刻未知，既不复制为已知表达时间，也不由时间推出人类身份。

### 7.2 本次自我生成来源

`登记本次生成表达`接收语言功能已经实际生成的固定UTF8原文，而不是替调用方补造自然语言。调用方提供正式生成者存在、语言场景/语言、已经保存的依据内容有序组以及可选回应交互；先在语言锁外保护生成者存在与语言场景，再在语言锁内核依据内容、回应交互和语言身份。依据内容组允许明确为空，表示本次未绑定语言内容依据，不得将它解释为已完成语义往返或源内容一致性证明。本叶不新增D/T任意引用或自由字符串解析以填补空依据。

首次请求不带`已发表交互节点`，每次建立独立出现：一个原子组生成固定文本、本次生成来源及交互记录，并登记三者。生成来源对生成者和已有依据内容使用正式字段引用，保留有序依据；原文按严格UTF8校验并保留原始标量序列。它没有外设消息/时间/会话/窗口字段，也不伪造接收事实。这里的“交互”是本次语言出现，尚未入队、发送或被对端看到；输出方法后续可读取它入队，实际发送后另有外设事实，不能回写本次生成来源冒充过去已经发送。

写后完整读回失败时，返回已经发表的交互身份；调用方以同一请求及`已发表交互节点`重入恢复。该身份属于本owner的生成分支且全部固定字段一致才返回已复用；异义输入拒绝，合法他类/不存在身份返回未找到，不自动新建替代。未给恢复身份的相同文本仍是新的生成出现，不能以文本、场景或依据相同抹去重复表达。没有未来发送事实时此入口照常可用，故“先生成询问→输出队列→真实发送→对端接收/回复”没有循环依赖；询问的`信息请求`含义操作及新的生成算法仍不在本叶。

### 7.3 需求内容

需求描述只能搭配请求范围，回应只能搭配普通陈述；不支持的操作/作用域值返回未支持。调用方必须明确声明本次内容范围覆盖为完整且未覆盖范围组为空；部分/未解析或尚有未覆盖范围返回未支持、零内容发表，原交互材料保留。未覆盖范围须位于原内容范围内，越界属于输入拒绝。已有字段未表达与语言未解析不同：语句没有给目标时可保存缺目标的完整需求提议，不能把尚未解析的句段冒充“对方未提出”。

结构化发布请求来自已完成解释的调用方，本叶校验保存这份解释，不根据自由文本重新猜句意，也不能自动发现调用方未声明的否定/条件/引述/量词。调用方必须将这些未覆盖用途声明为部分/未解析或选择未支持操作，不得剥去后谎报完整；本叶只提供合同及结构门，不宣称已经实现识别。合法保存不证明该解释正确、内容为真或原文已被自动理解。新中文需求语法、往返表达及生产解析调用仍未实现，不能借此标成功。

需求内容概念必须等于 `读取先天需求任务方法概念()`读回的正式需求类别C。角色表由以下既有槽根解析，不能创建同名替代FT：

| 正式槽 | 必须的值种类/用途 |
| --- | --- |
| 1001需求主体、1003目标存在 | 存在引用，经存在owner核合法身份；两者不合并 |
| 1004目标FT | 正式特征类型根引用 |
| 1005目标形式 | 值/变化方向枚举 |
| 1008目标域 | 特征概念引用，类型根与1004相同 |
| 1009比较关系 | 正式二次概念引用，按现目标比较适用合同核同FT及域 |
| 1010目标方向 | 增加/减少枚举 |

角色FT不重复，顺序按上述槽语义序规范化。允许缺项，缺项返回投影的正式FT清单；值/方向载荷已经冲突、角色类别不符或已知FT/域互不相容是输入拒绝，不能当缺项。完整值目标要求1001/1003/1004/1005/1008/1009，无1010；完整方向目标要求1001/1003/1004/1005/1010，无1008/1009。部分载荷未给形式时，可以保存已知单分支材料，混两分支拒绝；投影缺形式仍不完整。正式原语/规则及单位由概念owner读取，不在语言类重写范围包含算法。

内容范围必须非空、在交互固定文本的Unicode标量范围内；字段来源范围及表达者来源范围非空、在内容范围内，不要求各角色来源范围互不重叠。原文可以是确实收到/生成的空文本，但没有非空内容范围时只能保存交互材料，不能发表假句子。Unicode标量数量超过I64可表达范围返回资源失败，禁止截断或用字节位置替代。表达者与来源范围同有或同无，存在身份经owner核验。它保存本次解释采用的角色，不声称认证身份；需求主体即使同表达者也要显式两个角色。原文指代尚未唯一时不发布假绑定，可缺角色保留为不完整内容；本叶不实现多候选或作用域变量引擎。

### 7.4 回应、固定内容与重投

语言回应必须引用已完整读回的本owner内容节点；赞同主张、确认所指、拒绝请求只有被回应内容，纠正还必须引用另一已保存需求内容，不能原地覆盖被回应内容。它们都是表达者的语言内容，不是世界中“已经确认/已经拒绝”的权威状态；内容确认是否足够加入D、求助与self承接由后继治理判断。本叶不新增确认类别或C节点。

内容幂等键为 `(交互,操作,来源起,来源止)`：完整规范化请求相同复用，异义返回输入拒绝且原记录不变；不同出现保留不同身份。内容一经发布不修改，纠正新建内容并用语言回应关联。请求不能直接或间接循环引用：新回应只能引用已发布的需求内容，不能引用回应内容，本叶因此无回应链递归求值。相同目标不同主体/出现不得合并。

## 8. 锁、事务、前提与读回

外设消息只读保护在外设原互斥内复用私有reader，不取得语言/world锁。world场景保护在既有自然语言world互斥下，经既有场景/存在公开读口核root为自然语言根、目标场景在该根下、唯一场景父链无环；在一次L1批读取得根、所经场景/场景存在、归属字段与关系端点完整保护，重核读回身份。普通世界场景或失效根返回未找到/前提变化；不新建场景、E、特征、状态或动态。

语言发布的全部外部依赖读取在 `新语言互斥`之外：场景、真实消息（仅外设分支）、生成者/表达者/主体/目标E、需求类别C、正式槽FT、目标域、比较关系分别使用所属公开完整保护入口；概念身份成功后才读定义，非本提供者不能当空定义。所有返回的保护按稳定编码规范化，同ID完整快照不等返回前提变化，不能后者覆盖前者。生成分支禁止为来源读取未来外设消息。

随后取得语言锁，完整查询幂等键与原记录，精确重复优先返回旧身份；未命中才构造整个发布组并以已捕获外部保护和语言组织根完整预期提交唯一 `原子追加节点组`。锁内不回调外设/world/存在/概念，也不调用用户回调；各依赖不得指回语言owner形成锁环。原请求预期不符返回前提已变化，由调用方重新读取后重试，不在本函数无限循环；资源失败零发表，不用默认空集合继续。

### 8.2 私有实现位置与最小可见性

新增辅助函数仅在`海中鱼巣/领域/新_语言类.cpp`匿名命名空间：`核场景内容结构已加锁()`、`读取场景交互已加锁(稳定编码)`、`读取场景内容已加锁(稳定编码)`、`规范化需求角色组(…)`、`采集需求角色保护(…)`、`合并语言内容保护(…)`。已加锁reader返回第5节对应结果DTO，禁止再次取得`新语言互斥`或回调owner；保护采集仅在锁外执行。角色规范化按第7.3节表顺序、重复检测与分支互斥实现；保护合并对同ID不同完整快照返回前提变化。辅助参数只传本节DTO、现有领域只读服务引用及本次局部向量，不新增公开DTO或新服务owner。局部封装名称/排版可以施工调整，机器分支及公开签名不可调整。

新增schema使用固定`场景内容标识`和对应句柄数组，只在语言锁内初始化；首次使用`原子追加节点组`一次发表所有字段键/类型句柄、内容组织根及其属于`自然语言组织根节点`的唯一父子边。原子请求的组内引用无需提前公开空节点。句柄数组正式值只在完整读回成功后赋值；L1发表成功但读回失败时把返回身份组保留到待核数组，下次按该组重读，不再次发表。未初始化或资源不足时不建立原文/用户材料。schema私有字段/类型符号可按第6节逻辑表一一命名，不允许漏字段后在业务写路径临时补结构。

外设交互发布原子组＝固定文本＋交互＋语言根登记；本次生成发布原子组＝固定文本＋生成来源＋交互＋语言根登记；内容发布原子组＝作用域＋全部角色＋内容＋根登记。三者分别原子，内容失败不删除已有原始语言材料；不称跨外设/语言/world事务。外部保护与结构字段键端点全部纳入同次追加预期，组内循环引用只限内容和其唯一作用域/角色归属，发布前完整闭合。

发布成功后的完整读回必须在语言锁下从L1重建，核类型、根登记、所属、字段基数、操作/作用域配对、角色值类型、固定文本范围与所有直接引用；与规范化请求一致才返回信息。写后读回失败保留 `已发生身份`，无完整信息、不报告成功；不得删除已发表事实或自动再建。明确结构损坏走CODE-FILE-01工程诊断；资源读取失败结构化返回资源失败并保留实际阶段。下一次同键重投核原身份，不能把先前成功发表当不存在。

只读 `读取语言场景内容/交互`对合法他类节点返回未找到，已有本类型结构损坏返回内部不一致；不是空内容。按场景查询先取得反向引用来源节点完整集合，逐条核场景一致、根登记唯一、内容结构，再按稳定编码升序返回；任何失败返回空结果组和具名非成功，不截断为成功。该接口不额外扫描全语言树。

## 9. 生命周期、失效与旧数据
