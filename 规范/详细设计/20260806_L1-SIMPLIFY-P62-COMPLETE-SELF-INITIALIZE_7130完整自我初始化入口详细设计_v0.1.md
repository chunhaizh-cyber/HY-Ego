7130要求全新运行期系统角色初始化入口一次提交完整自我，且普通调用方不得逐项提交裸键值。P61已经拥有全部机器语义；若P62再次形成幂等键、规格、写集或状态映射，就会产生第二发布解释者。故本叶只建立参数为空的具名初始化入口：装配时值式冻结一份完整P61请求，调用时向唯一P61服务原样委托一次，并把结果逐字段原样返回。

## 4. 请求所有权与“无裸键”边界

P62不新增初始化请求DTO，唯一配置类型就是P61的版本化`完整自我发布请求`。这份请求已经包含强类型幂等身份、登记身份、指定世界根、事实截止和有序出生期成员见证；它不允许调用方指定新节点、关系或值稳定编码，真实编码仍只由L1在P61首次事务内分配。

请求只能在构造初始化服务时提供一次。`初始化完整自我()`参数为空，因而每次调用都使用逐字段相同的冻结请求；调用前修改原始变量不能影响服务内副本。P62不得拆出、重排、补全、裁剪或重编码任何字段，不读取配置文件、环境变量、SQL、系统角色清单、旧句柄或显示名来替换请求。

“无裸键”不表示P62重新校验P61字段。请求版本、幂等范围、登记、根、截止、成员顺序和全部业务准入仍由P61唯一解释；P62不建立第二套合法性规则。

## 5. 单函数执行合同

函数固定只有一次调用和一次返回：

```cpp
完整自我发布结果 L1完整自我初始化服务::初始化完整自我() const {
    return 发布服务_.发布完整自我(发布请求_);
}
```

具体要求：

1. 每次入口调用P61恰一次，实参为保存请求的const引用；
2. P61返回的状态、幂等身份、L1幂等键、事实代次、`L1发布已存在`和可选事实逐字段原样返回；
3. 不把`入口拒绝`、`版本漂移`、`幂等冲突`、`资源失败`或`内部不一致`改名、折叠、重试或升级为初始化成功；
4. 不在P61前后调用P15、P53—P60、L1、SQL、材料、恢复、日志或旧WORLD-TREE；
5. 不捕获后伪造结构化成功。函数保持非`noexcept`，分配或复制异常按P61/语言边界传播，不补写事实；
6. 不保存首次结果。相同服务对象再次调用仍调用P61一次，由P61同义幂等读回裁决；P62不以进程内布尔值短路。

P62没有新幂等域、新操作标签、新摘要、新账、新事务、新稳定编码、新发布后读回和新状态枚举。P61的`0x14`、`0x50336101`、一次L1 v2提交及P56正式读回保持唯一。

## 6. 生命周期、并发与失败

初始化服务自身无可变状态，多个线程误并发调用时只表现为对同一P61请求的并发调用；最终首次/同义/冲突/漂移由P61和L1裁决。P62不加锁、不sleep、不retry、不串行化，也不以返回先后重写事实。

构造后的发布服务引用失效属于宿主生命周期错误，必须由后继装配静态和专项验证防止；本叶不增加空指针或可空端口。P61任何非成功逐字段返回，调用方不得用初始化入口名称、旧初始化结果、缓存或系统角色清单证明完整自我已经发布。
