# SELF-CONTEXT-FRESH-READ-PROVIDER G2-A自我正式上下文fresh读回详细设计

版本：v0.2

日期：2026-09-23

状态：正式详细设计；v0.2修正当前self读回复用首次出生形状的执行漂移

对应目标：`GOAL-SELF-CONTEXT-FRESH-READ-PROVIDER-IMPLEMENTATION`

## 1. 目标与边界

本设计冻结阶段20之后最早缺口 G2-A：形成一个实现现行`自我线程正式上下文端口`的只读上层提供者，并在普通应用上下文中按依赖顺序持有它。提供者在新的共同事实截止重新读回世界根、唯一self、self当前所在场景、安全根、服务根及唯一方法登记根，返回现行值式正式上下文投影。

本叶不把provider注入`自我线程`，不调用`复核前置并开放治理运行门`，不开放运行门，不消费邮箱，不实现G3消息循环、G4-A当前特征值/目标比较或根治理意图sink。方法登记根只作本次同截止初始化门，当前特征值留给G4-A；二者均不扩入正式上下文投影。

完成只证明G2-A提供者及生产所有权就绪，不证明G2完成、治理门可开、M1-A或内部治理闭环完成。

## 2. 正式依据与当前事实

- 8100 v1.13 §3要求首次普通治理前fresh读回唯一self、两个根角色和锚点闭包；self只消费上层公开服务。
- 8120 v0.17 §5固定阶段20停在关闭门，后继消费端就绪后才独立开门；方法登记根是阶段21以前的正式顺序门。
- 8121 v0.6固定双根锚点字段与同截止完整读回；根D不得带自我物理字段。
- 8200 v2.0 §§2、4要求当前读取使用同一非零G0、预算按对象类别分账，缺provider不得用默认值或万能DTO补齐。
- 当前`线程_自我.h`已经声明正式上下文端口、请求、结果和投影，但没有provider；`复核前置并开放治理运行门`仍固定返回依赖未就绪。
- 当前需求服务只有写能力入口`建立或读取本能根材料`。它在首次材料缺失时会提交写集，不能用于运行期只读上下文复核。
- 当前方法结构服务已有按指定Gread读取全部当前方法登记根的只读入口；世界树与真实自我服务已有fresh固定截止读取。
- 当前世界树的`世界树存在信息结果_v4::成功`和完整位置投影允许合法多层上行路径；但`应用服务.自我形成.cpp`的私有`投影完整/场景完整`仍把当前self强制为直接根父、单边路径，并把当前父边创建代次当作self出生代次。该实现与7130 v0.19第8节和本设计的移动场景要求冲突，必须在本叶内原位修正，不能由provider绕过`读取当前自我`另读位置。

## 3. 物理位置与依赖方向

### 3.1 纯读根材料入口

在`海中鱼巣/领域/数据服务.需求类.h`新增：

```cpp
本能根材料结果 读取本能根材料(
    const 本能根材料请求&) const;
```

复用既有`本能根材料请求/结果/状态`，成功状态固定为`已读取`。本函数只读取本owner首次材料和请求Gread下的当前闭包，绝不调用`建立或读取本能根材料`，绝不提交写集、补根、退出或修复事实。首次材料未找到返回`根材料未闭合`；退出、漂移、幂等/引用冲突、资源失败和内部不一致沿既有状态准确返回。

实现复用现有私有完整读回校验，逐项核验T/D/L、D→F、D→目标合同、L→D、目标值及T/D/L引用闭包。读取前后当前截止必须等于请求截止，成功结果的`事实代次`和材料`读取事实代次`必须都等于请求截止。错误请求或失败结果零业务写。

### 3.2 上层provider

新建：

- `海中鱼巣/业务/应用服务.自我线程正式上下文.h`
- `海中鱼巣/业务/应用服务.自我线程正式上下文.cpp`

公开类型：

```cpp
class 自我线程正式上下文提供者 final
    : public 自我线程正式上下文端口 {
public:
  自我线程正式上下文提供者(
      世界树应用服务&,
      const 真实自我形成服务&,
      const 需求类数据服务&,
      const L2方法结构服务&,
      存在单例角色身份) noexcept;

  自我线程正式上下文结果_v1 读取正式上下文(
      const 自我线程正式上下文请求_v1&) noexcept override;
};
```

provider只持有长于自身的服务引用和角色值，不持有L1、写端口、SQL、可变节点或普通应用全局上下文。`线程_自我.h/.cpp`不包含或调用DATA-L1/DATA-L2；下钻只发生在该上层provider内部。

### 3.3 普通应用所有权

`普通应用上下文`在世界树、自我、需求和方法结构服务之后、`自我线程`之前持有唯一`自我线程正式上下文提供者`。析构时self先退出，provider后销毁，再销毁其依赖。初次装配和既有上下文补齐自我服务后都必须补齐同一个provider；构造资源失败沿普通应用现有资源失败处理。

本叶不新增普通应用getter、裸指针或并列读取入口，不把provider传给self，不改变启动阶段编号或模式宿主控制流。

### 3.4 当前self读回成功谓词修正

在`海中鱼巣/业务/应用服务.自我形成.cpp`内只修正私有完整性辅助和两个既有结果成功谓词的分工，不修改`应用服务.自我形成.h`、任何公开DTO、枚举、函数签名、世界树/场景服务或出生事务。

首次出生与当前读取固定分账：

- `真实自我形成结果::成功(const 真实自我形成请求&)`继续以既有世界创建原请求、`世界结果->成功`、首次发布H、角色目标、同节点E/C、通用EC和使用关系证明首次出生；其直接父必须是请求中的世界根、出生路径必须恰一，现有严格出生语义不得放宽。
- `真实自我形成结果::成功(const 真实自我读取请求&)`改用当前完整性谓词。当前谓词只要求同一Gread下的唯一角色/E、世界根、完整当前场景位置、当前EC使用和仍有效的出生身份闭包；不得要求当前直接父等于世界根、上行路径恰一或当前父边创建代次等于self出生代次。

私有实现机械合同固定为：

1. 把当前场景辅助收紧为`当前场景完整(const 场景树节点当前事实&, const 世界树层级位置&, std::uint64_t, const 世界树绑定创建预算&) noexcept`或等价同文件私有函数。它必须逐字段互证场景事实与位置投影的当前直接父、父场景语境和完整上行路径；路径非空，首边等于直接父，逐边同截止、当前有效、成员到父连续且无环，末端恰为锁定世界根，长度同时不超过关系预算和祖先预算。
2. self为场景视角，当前直接父来源仍必须为`直接子场景`；直接父可以是世界树内任一合法当前场景。场景树证明的树根和见证目标必须等于锁定世界根，不得改写成当前直接父。
3. self出生H从角色中的存在身份节点生命周期取得，并继续互证角色目标、同节点场景角色登记、四根、概念使用和概念先于self；当前父边、完整上行路径和父场景语境只证明当前位置，不参与出生H相等判断，也不得覆盖出生材料。
4. `读取当前自我实现`仍只消费`世界树应用服务::读取世界存在信息`的成功投影，不新增旁路读取、不重建self、不提交写集。世界结果成功但当前投影交叉互证失败，仍返回`内部不一致`并清空投影。
5. 当前修正不得改变立即出生后的成功：首次形成和精确重复仍经严格出生结果成功谓词，再经当前读取返回同一E；合法移动只改变当前直接父、路径及相关当前位置材料，不改变世界根、角色、E、场景角色、四根、EC或使用身份。

## 4. 上下文预算DTO收紧

现行三字段不能合法映射真实自我读取所需的世界位置和概念预算。原位收紧`自我线程上下文读取预算_v1`为：

```cpp
struct 自我线程上下文读取预算_v1 final {
  std::uint64_t 最大世界场景数量 = 0;
  std::uint64_t 最大世界关系数量 = 0;
  std::uint64_t 最大自我位置祖先数量 = 0;
  std::uint64_t 最大自我概念数量 = 0;
  std::uint64_t 最大自我概念关系数量 = 0;
  std::uint64_t 最大自我概念世界成员数量 = 0;
  std::uint64_t 最大自我概念特征属性数量 = 0;
};
```

全部字段非零才完整。映射固定为：

| provider调用 | 预算来源 |
| --- | --- |
| 世界根读取/末次验证 | 最大世界场景数量、最大世界关系数量 |
| 真实self位置读取 | 同一世界场景/关系数量，加最大自我位置祖先数量 |
| self概念/角色闭包读取 | 四个自我概念分项 |
| 双根材料读取 | 根结构为固定有限闭包，不使用变量扫描预算 |
| 方法登记根读取 | 唯一owner全组只读，结果必须恰一，不把数量塞入本DTO |

旧`最大自我候选数量/每根最大候选数量/最大关系材料数量`删除，不保留兼容别名。`自我线程合同版本_v1`和现有枚举数值不变；本次是未被真实provider消费的预冻结ABI原位闭合。当前代码消费者仅`线程_自我.cpp`完整性函数；全仓没有旧字段构造调用。执行仍须全仓复核并同步任何新出现消费者，禁止静默保留两套预算。

四个自我概念分项都进入现行`真实自我形成服务::读取当前自我`请求。其中`最大自我概念世界成员数量`对应`概念树预算::最大世界成员数`，现行`自我形成内部::预算有效`在读取前明确要求其非零；即使后继概念读取当前没有扫描世界成员组，它仍是该公开读取入口真实消费的入场预算，不能由provider补固定值或省略。`最大来源数/最大支持数/最大动态槽数/最大动态模板数`在本读取链不被要求，固定为零且不进入本DTO。

## 5. provider算法

1. 请求不完整或provider角色无效，返回`入口拒绝`、空投影、`写业务事实=false`。
2. 用世界预算调用`读取当前现实世界根`取得fresh `Gread`和唯一根；根必须与锁定世界身份/根场景一致，否则`引用冲突`。
3. 在同一`Gread`调用`真实自我形成服务::读取当前自我`。要求角色唯一、E等于锁定self、世界根一致、当前世界位置闭合；允许self合法移动到世界树内新的当前场景，返回该当前直接父场景，不把锁定启动场景冒充当前场景。
4. 在同一`Gread`调用`L2方法结构服务::读取全部当前方法登记根`，要求成功且恰一完整当前根。该根只证明调用顺序门，不进入返回投影。
5. 分别以锁定安全/服务实际F和角色调用新增纯读根材料入口；逐字段要求D、L、实际F、目标合同等于锁定锚点，两个根互不交叉。缺失、退出或异义均不修复。
6. 调用现有公开`需求类数据服务::核验当前事实代次(Gread)`，再以同一`Gread`验证世界根；结合两次纯读根材料入口各自的前后截止守卫及结果代次回显，任何前后变化返回`当前性漂移`。本叶不新增当前事实代次getter。
7. 形成`自我线程正式上下文投影_v1{Gread, 世界根, 当前所在场景, E, 安全根, 服务根}`。只返回值式身份；状态为`成功`，零业务写。

下层状态到`自我线程外部调用状态`的映射固定如下；任何成功枚举但成功谓词、合同版本、截止、载荷或身份互证失败，都不继续并映射`内部错误`：

| 来源 | 下层状态 | 外部状态 |
| --- | --- | --- |
| provider前检 | 请求不完整、角色无效 | `入口拒绝` |
| 世界根读取（首次与末次） | `入口拒绝` | `入口拒绝` |
| 世界根读取（首次与末次） | `事实代次漂移`、`历史材料已清理` | `当前性漂移` |
| 世界根读取（首次与末次） | `场景不在现实树`、`引用冲突`、`形成场景环`，或成功根与锁定世界不一致 | `引用冲突` |
| 世界根读取（首次与末次） | `数量预算不足`、`资源失败` | `资源失败` |
| 世界根读取（首次与末次） | 其它非成功或不属于根读取的成功/写入状态 | `内部错误` |
| 真实self读取 | `入口拒绝` | `入口拒绝` |
| 真实self读取 | `读取未完成` | `当前性漂移`；该下层状态已合并截止变化、下层预算不足和历史不可用，本层不得猜测更细原因 |
| 真实self读取 | `请求冲突`、`根无效`、`角色冲突`、`概念阶段失败`、`世界阶段失败`，或成功投影与锁定世界/E/角色不一致 | `引用冲突` |
| 真实self读取 | `资源失败` | `资源失败` |
| 真实self读取 | `已可能发布`、`已形成`、`精确重复`、`内部不一致`或其它非读取成功状态 | `内部错误` |
| 方法登记根全组读取 | `入口拒绝` | `入口拒绝` |
| 方法登记根全组读取 | `尚未建立`、`当前根缺失` | `依赖未就绪` |
| 方法登记根全组读取 | `当前根已退出`、`所有者非空冲突` | `引用冲突` |
| 方法登记根全组读取 | `事实代次漂移` | `当前性漂移` |
| 方法登记根全组读取 | `数量预算不足`、`资源失败` | `资源失败` |
| 方法登记根全组读取 | `首次材料冲突`、`首次材料不完整`、`当前根形状错误`、`已可能发布`、`内部不一致`及其它非读取成功状态 | `内部错误` |
| 双根纯读 | `入口拒绝` | `入口拒绝` |
| 双根纯读 | `事实代次漂移` | `当前性漂移` |
| 双根纯读 | `实际特征未找到`、`实际特征已退出`、`实际特征类型不匹配`、`幂等冲突`、`引用冲突`、`根材料未闭合`、`根材料已退出`，或成功材料与锁定锚点不一致/双根交叉 | `引用冲突` |
| 双根纯读 | `资源失败` | `资源失败` |
| 双根纯读 | `已形成`、`已恢复`、`已可能发布`、`内部不一致`及其它非纯读成功状态 | `内部错误` |
| 末次需求事实代次核验 | `入口拒绝` | `入口拒绝` |
| 末次需求事实代次核验 | `事实代次漂移` | `当前性漂移` |
| 末次需求事实代次核验 | `资源失败` | `资源失败` |
| 末次需求事实代次核验 | 其它非`已读取`状态 | `内部错误` |
| provider异常 | `std::bad_alloc`、`std::length_error` | `资源失败` |
| provider异常 | 其它异常 | `内部错误` |

非成功结果一律为空投影、`写业务事实=false`，不得保留下层部分载荷。方法根读取成功还必须满足`Gread`等于共同截止、根组恰一且根事实完整；否则`内部错误`。上述映射不改变任何下层枚举，也不新增`数量预算不足`外部枚举。

## 6. 非职责与门禁

- 不读取根当前特征值、准确内容或目标I64比较；它们属于G4-A。
- 不向投影新增方法根、角色事实、根目标值、服务指针或底层见证。
- 不修改`复核前置并开放治理运行门`；provider成功也不能改变门、邮箱、生命周期或成功批次。
- 不注入self，不冻结消息批次，不建立根治理任务或意图sink。
- 不修改规范、流程图、共享知识或三份现有目标业务流程图WIP。

G2-B只有在G4-A双根复核provider和根治理意图sink合同均冻结后，才能设计provider注入、工作线程锁外调用、回返核对和原子开门；不得从本叶成功推导开门资格。

## 7. 验证合同

新建生产外专项，至少覆盖：

1. 纯读根入口首次材料缺失时返回`根材料未闭合`且事实代次、首次材料和当前事实数零变化；静态确认零调用写入口。
2. 已有双根在同一Gread读取成功；身份、目标、列表或实际F异义返回冲突且零写；退出和漂移准确分账。
3. 上下文预算七字段逐一零值拒绝，旧三字段全仓零引用；枚举数值和合同版本不变。
4. 首次形成及同持久根新进程恢复后，provider均返回完整投影；方法根恰一只作内部门。
5. 先把self场景合法移动到世界根下另一个场景，再在新的共同截止直接调用`真实自我形成服务::读取当前自我`：读取成功，E/世界根/角色/场景角色/四根/EC与使用身份不变，当前直接父为新场景，上行路径允许大于1，当前父边创建代次不得被要求等于self出生H；随后provider投影返回同一fresh所在场景且锁定双根不变。
6. 世界、自我、方法根或双根缺失/多重/退出/漂移/引用错、资源失败可触发项均不开门、零写；不可合法注入项明确NOT_RUN。
7. 普通应用上下文实际构造provider；self诊断仍为已停门、门关闭、零成功批次，普通启动控制流不新增阶段。
8. 专项Debug/Release x64构建运行、根工程Debug/Release x64隔离Rebuild、`git diff --check`和允许范围审计通过。
