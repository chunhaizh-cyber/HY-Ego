# 生存安全与服务维护共享截止快照消费详细设计 v0.1

日期：2026-08-15

计划身份：`SURVIVAL-SERVICE-CURRENT-SNAPSHOT-CONSUME`

## 1. 目标与完成边界

实现下列同一业务叶链：

```text
BIZ-L3-002-02-02 v0.2 运行期只读查询组合器::读取生存安全与服务维护当前快照
-> BIZ-L4-002-02-02-01 v0.2 服务生存治理服务::读取当前服务生存维护快照
-> BIZ-L4-002-05-01-01 v0.2 服务生存治理服务::读取生存安全根当前值
-> DATA-EXT-15 / DATA-EXT-16 公开强类型事实读取
```

父级给出唯一自我、运行代次、事实范围版本、完整秒边界和一个非零共享事实截止 `G0`。安全与服务全部 DATA 读取必须使用同一个 `G0`；DATA 只返回权威事实，BIZ 依据 6120、6160、6170 派生控制态、裁决有效服务活动、最长未满足来源和稳定摘要。只有全部结果截止等于 `G0`且引用和值域闭合时才形成不可变快照。

本叶全程只读，不执行安全维护、服务合同结算、服务值衰减、生存安全根回归、完整秒推进或任务权限计算。完成只证明具名共享截止读取 provider 与 L3 值式组合已经真实接线；父级 `G0/G1`、需求/任务快照、自我治理一致事实、T02 循环和系统闭环仍为后继。

## 3. 基础数据公开消费需求

本叶只复用 DATA-EXT-15、DATA-EXT-16；不直达 L1，不新增通用查询、owner、缓存或 SQL 入口。

### 3.3 精确 ABI 状态

上述操作、参数语义、成功/空/失败和同截止守恒已经冻结。精确 DATA 模块名、C++ 强类型身份名、请求字段顺序、状态枚举数值和 getter 由 DATA 最终发布 ABI 决定，本计划只允许机械匹配，不允许执行者改变操作集合、合法空、预算或职责边界。

## 5. DTO 语义合同

DATA 强类型尚未发布，因此本节冻结字段语义和不变量，不伪造当前存在的 C++ 类型。

### 5.1 请求共同字段

| 字段 | 约束 | 来源 |
| --- | --- | --- |
| 合同版本 | 精确匹配本 BIZ 合同版本 | 编译期常量 |
| 运行代次 | 非零 | 普通应用运行上下文 |
| 事实范围版本 | 精确等于具名自我治理事实范围版本 | 普通应用运行上下文 |
| 唯一自我 | DATA 最终强类型存在身份，非零 | SELF-FORM 值式结果 |
| 共享事实截止 G0 | 非零 | 本批 `运行期事实版本服务`结果 |
| 完整秒边界 | 同运行代次、同时间纪元、非负完整秒 | 本批 `完整秒时钟服务`结果 |
| 安全根选择 | 安全根强类型身份及定义/维护/回归规则版本 | 普通应用正式配置/自我材料 |
| 服务值选择 | 服务值强类型身份及合同/维护/时间规则版本 | 普通应用正式配置/自我材料 |
| 四类数量预算 | 各自非零；分别约束合同、准备、进展、到期事件对象数 | 普通应用有界配置 |

请求不携带 owner、L1、发布见证、日志时间、调用序号、缓存版本或“读取最新”开关。

### 5.2 生存安全根载荷

成功载荷包含：合同版本、运行代次、事实范围版本、自我、安全根身份、A、L/H、定义/维护/回归规则版本、维护来源事实的完整值式副本、派生控制态和 `G0`。

控制态只允许：

```text
A = 0 -> 终止
A = 1 -> 休眠
A > 1 -> 主动运行
```

控制态是可重算投影，不是 DATA 字段或第二当前事实。

### 5.3 服务生存维护载荷

在安全根载荷上增加：服务值、服务值身份、时间纪元、上一已结算完整秒、维护来源事实、当前合同/准备/进展/到期事件完整有序组、有效活动摘要、最长未满足来源 optional、规则版本和 `G0`。

合法空组保持空组成功。只有服务值、安全根定义/当前值、时间纪元或维护游标缺失时整份材料缺失；空合同、准备、进展或到期组不能自动升级为缺失。

### 5.4 结果状态

三层结果分别使用自己的强类型状态，但语义顺序统一冻结：

```text
已形成/已读取
请求拒绝
尚无权威
材料缺失
当前性漂移
提供者拒绝
数量预算不足
资源失败
内部不一致
```

只有成功状态携带 optional 载荷；其它状态载荷为空。任何 DATA 坏成功形状、同截止矛盾、重复唯一键、悬空引用或值域错误都映射内部不一致，不降级为合法空。

## 6. 固定读取与裁决顺序

```text
校验 BIZ 请求和四类预算
-> DATA-EXT-15 按 G0 读取完整安全根当前事实
-> 验证 A/L/H、来源和规则版本并派生控制态
-> DATA-EXT-16 按 G0 读取服务值与维护游标
-> DATA-EXT-16 按 G0 有界读取当前合同组
-> 有界读取当前准备组
-> 有界读取当前进展组
-> 有界读取当前到期未满足事件组
-> 验证全部结果截止都等于 G0
-> 按强类型稳定身份连接合同、准备、进展和事件引用
-> 依据 6160/6170 裁决有效服务活动和最长未满足来源
-> 规范化稳定排序
-> 一次形成 L4 完整候选
-> L3 复核请求回显并一次形成共享截止快照
```

有效服务活动只在正式事实同时证明合同或准备归属、门禁满足、方法真实执行、当前计量窗有新进展且未处于停止/阻塞/失败/等待/终止时成立。DATA 不预先给出这个结论；BIZ 不从线程状态、队列长度或标签补齐。

最长未满足来源按正式未满足起点/到期事实和稳定身份确定，只取最长等待来源及全部同值并列身份，不按合同数量叠加时间，不提前计算下一秒衰减。

## 7. 一致性、并发与失败守恒

- 所有 DATA 请求都使用同一非零 `G0`。任一结果截止不等于 `G0`，整体返回当前性漂移；不只重读失败项，不与旧材料拼装。
- 父级随后读取 `G1`；只有 `G1 == G0 == 本叶结果截止`时更高层一致快照成立。
- 服务和组合器无锁、无缓存、无已发布成员；全部中间值仅活在一次调用局部。
- `std::bad_alloc`和`std::length_error`映射资源失败；其它未知异常映射内部不一致；全部非成功零载荷。
- 读取不取得幂等身份、不推进事实代次、不写 DATA，也不持有仓库、端口、锁或事务。

## 8. 依赖方向、所有权和生命周期

```text
DATA-EXT-15 / DATA-EXT-16 正式模块
-> 服务.服务生存治理（只读 BIZ 裁决）
-> 组合.运行期只读查询（跨 BIZ 只读组合）
-> 自我治理一致事实父级
```

禁止 DATA 反向 import BIZ，禁止服务生存模块 import 普通应用、自我线程、L1、日志、缓存、控制面板或旧 SERVICE-P1 自检模块。普通应用后继唯一拥有两个 DATA 服务、服务生存治理服务和运行期只读查询组合器；所有借用覆盖自我线程完整生命周期。
