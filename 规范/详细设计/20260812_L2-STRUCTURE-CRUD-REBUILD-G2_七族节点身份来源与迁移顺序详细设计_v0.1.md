## 1. 目标与完成边界

G2 解决一个确定的系统性缺口：`L2场景身份`、`L2存在身份`、`L2特征定义身份`、`L2特征实例身份`、`L2状态身份`、`L2动态身份` 和 `L2因果身份` 当前只是稳定编码的强类型包装；普通 L1 节点形状、名称、本地键或一条节点到自身的关系都不能证明编码由本族唯一服务发布。

本设计冻结七族各一独占 owner、同 owner 非自环族归属事实、七套公开身份来源读取、创建 / 当前 / 历史 / 退出 / legacy 边界、跨族同截止验证、物理文件与迁移顺序。它不建立中央身份服务、第二仓、缓存权威或业务资格层。

本叶只修订 4015、4030、4230、规范目录、本文和治理计划；不写 C++，不修改 T1、DYN2、路线输入、流程图、构建目录或任何执行 WIP。

## 3. 核心裁决

### 3.1 七 owner 与六服务持有方式

七个独占 owner 两两不同：场景、存在、特征定义、特征实例、状态、动态和因果各一。

| 服务 | 持有端口 | 可写范围 |
| --- | --- | --- |
| `L2场景结构服务` | 场景端口一份 | 场景节点、场景自有关系 / 值、场景身份来源 |
| `L2存在结构服务` | 存在端口一份 | 存在节点、存在固定属性、存在身份来源 |
| `L2特征结构服务` | 定义端口、实例端口各一份 | 定义端口只写定义；实例端口只写实例、宿主 / 定义关系、实例值 |
| `L2状态结构服务` | 状态端口一份 | 状态节点及其自有关系 / 值、状态身份来源 |
| `L2动态结构服务` | 动态端口一份 | 动态节点及其自有关系 / 值、动态身份来源 |
| `L2因果结构服务` | 因果端口一份 | 因果节点及其自有关系 / 值、因果身份来源 |

一个端口不得写另一族。特征服务不能以同一服务类名共享 owner，也不能接收 owner 参数动态选端口。跨 owner 结构只能通过引用连接，不能进入一笔 owner-scoped 写集。

### 3.2 为什么 owner 仍需正式判别事实

owner-aware 节点事实证明合法技术写入方，但一个 owner 内还会有关系类型节点、属性类型节点和来源登记节点。只检查 `写入所有者 + 节点种类::普通` 仍可能把内部关系类型节点冒充公开身份。

因此每族在同一 L1 权威仓建立：

```text
一个不可变族锚点节点
+ 一个不可变族归属关系类型节点
+ 每个公开节点到该锚点的一条唯一族归属关系
```

归属关系固定 `源=公开节点`、`目标=本族锚点`、`类型=本族归属关系类型`、`角色=1`，并与公开节点由同一端口、同一写集、同一幂等请求和同一事实代次发布。它不是自环，也不是业务拓扑；锚点不反向列举成员，不保存第二成员表。

身份只由本族公开服务联合核对 owner、节点、锚点、关系类型和归属关系后成立。非权威定位只保存锚点 / 类型编码以构造 L1 读取请求；它不能接受、拒绝或补造身份。

### 3.3 初始化幂等与生命周期

每族 owner 建立幂等身份和来源登记写集幂等身份固定非零且七族互不复用。来源登记在首个公开节点创建前完成：

1. provider 建立本族独占 owner 并取得唯一端口；
2. 服务私有初始化路径以该端口同写锚点和归属关系类型节点；
3. 从首次事实代次 owner-aware 历史入口读回 owner、锚点与类型；
4. 精确重复必须回显首次两个编码；同键异义返回幂等冲突；
5. 出现第二锚点、第二类型或同 owner 第二登记定位属于内部不一致。

锚点和关系类型创建代次不晚于首个公开节点，生命周期覆盖该族全部公开节点和归属关系。单个节点退出不退出锚点 / 类型。族退役先使用仍有效的本族端口退出全部公开节点、归属关系、锚点和类型并使当前事实归零，再释放端口；幂等、历史、恢复与审计引用闭合后，签发器才退出 owner。owner、锚点和类型历史永久保留且不得复活或转族。

### 4.3 六服务构造签名

构造参数顺序固定为“L1 const 读取、按依赖顺序的 const L2 服务、最后为本服务族专属 owner 交付”；特征的定义交付严格先于实例交付。禁止六服务直接接收同型 `L1所有者范围写端口`，七套不可复制、可移动的族专属强类型固定为：

```cpp
L2存在所有者交付
L2特征定义所有者交付
L2特征实例所有者交付
L2状态所有者交付
L2动态所有者交付
L2因果所有者交付
L2场景所有者交付
```

每套类型只由对应 `服务.L2*结构.ixx` 提供的具名形成函数构造；特征模块分别提供定义、实例两套。精确形态为 `std::optional<L2{族}所有者交付> 尝试形成L2{族}所有者交付(const L1事实基座服务&, L1所有者范围交付&&)`。形成函数必须同时核对：建立结果回显本族具名建立幂等常量；所有者范围为 `独占结构范围`；建立结果 owner、端口 owner 与交付包装 owner 相同；端口绑定传入的同一 L1 服务实例；建立状态只允许成功或精确重复且 owner 未退出。任一不符都不形成包装，已移动入的端口随失败路径释放。包装不 export raw 端口、owner 选择或通用解包入口，只允许同模块对应服务构造函数消费。由此特征定义 / 实例交付即使参数位置相邻也不能在编译期互换。

```cpp

    L2存在所有者交付&& 存在所有者交付);
explicit L2特征结构服务(
    const L1事实基座服务& 第一层读取服务,
```

形成函数先证明各交付属于同一 L1 实例和精确本族 owner；构造函数只接收已经通过该证明的族专属交付。任何来源登记初始化失败都使构造失败，provider 不发布半构造服务。私有初始化函数固定为 `初始化场景身份来源`、`初始化存在身份来源`、`初始化特征定义身份来源`、`初始化特征实例身份来源`、`初始化状态身份来源`、`初始化动态身份来源`、`初始化因果身份来源`，不 export。当前不提供初始化恢复入口；定位丢失固定使该服务返回内部不一致并停止写入，未来恢复只能另立管理面计划，不能扫描 L1 补登记。

### 4.4 provider 物理位置

`海中鱼巣/装配.普通应用.ixx` 继续是唯一 provider，不新建通用身份工厂。它只持有一个 `L1事实基座运行包`，最终按以下固定顺序签发并构造：

```text
存在 owner / 服务
-> 特征定义 owner + 特征实例 owner / 同一个特征服务
-> 状态 owner / 服务
-> 动态 owner / 服务
-> 因果 owner / 服务
-> 场景 owner / 服务
```

每个 `取得L2*结构服务()` 只返回上下文持有的同一实例 / 引用。普通调用者不能取得 owner、端口、锚点初始化入口或按 owner 重建服务。后继按依赖逐叶扩展这一前缀，不要求 G2 一次实现全部服务。

## 5. 创建、读取、错误与退出

### 5.1 创建

新公开节点写集固定包含节点与一条非自环族归属关系。写入成功 / 精确重复必须同时取得两个新编码并从首次代次读回；只出现节点、只出现关系、owner 不一致或创建代次不一致均为内部不一致。

特征定义创建只走定义端口。特征实例创建只走实例端口，并在同一期望代次先通过存在、特征定义公开身份来源验证宿主和定义；其后实例提交仍使用原期望代次，期间发生发布则由 L1 返回事实代次漂移。

### 5.2 当前读取

当前来源读取先按 L1 当前读取裁决生命周期：编码已退出固定返回 `已退出` 且空载荷，不补读历史判族，因此退出优先遮蔽 wrong-family。仍可读时再用一次 owner-aware 一致投影核对：精确 owner 事实、请求节点、锚点、关系类型、以请求节点为源且类型精确匹配的关系组。成功要求唯一关系指向锚点、角色为 `1`、全部项目当前且共同截止等于请求期望代次。

完整读取把上述项目和本结构其它节点 / 关系 / 值并入同一投影。条件查询先验证端点来源；合法本族端点无匹配才允许 `已读取 + 空组`。

### 5.3 历史读取

历史读取先确认当前事实代次等于请求期望代次，再按历史截止读取 owner、节点、锚点、关系类型和归属关系，最后复核当前代次未漂移。owner 在节点创建截止必须有效且唯一；owner 提前退出、复义或生命周期不能覆盖节点属于内部不一致。晚于截止的未来退出从值式生命周期隐藏：

- 截止早于节点创建：`未找到`；
- 截止达到创建且早于退出：`已读取`，返回当时当前的来源投影；
- 截止达到退出：仍为历史 `已读取`，返回完整退出生命周期；
- 当前入口读取已退出节点：`已退出`，空载荷。

不得用当前关系、缓存或晚于截止的事实补历史缺项。

### 5.4 精确错误

| 情况 | 状态 |
| --- | --- |
| 合同、读取类别、截止或零身份非法 | `入口拒绝` |
| 稳定编码未占用 / 截止前未创建 | `未找到` |
| 当前入口目标已退出，不论其历史所属族 | `已退出`，优先遮蔽族判定 |
| 当前仍可读或历史截止可判定的 wrong-family owner、v1 legacy、裸 L1 节点、同 owner 元数据节点、旧未标记节点 | `入口拒绝` |
| 来源关系重复、错 owner、错锚点、错类型、错角色、生命周期不闭合 | `内部不一致` |
| 读取或写入期望代次不符 | `事实代次漂移` |
| L1 许可 / 资源失败 | 同名状态 |

所有非成功空来源载荷、零普通事实变化。除当前 `已退出` 的明确遮蔽外，wrong-family 不得折叠成未找到或合法空组。同一编码不能被两族来源同时接受由 provider / 集成矩阵跨服务证明，单族服务不得扫描其它族。

### 5.5 退出与迁移

节点退出写集必须显式包含本节点、族归属关系及本结构其它自有关系 / 值。节点与归属关系同代退出；漏归属关系由 L1 引用闭包拒绝。锚点 / 类型不随单节点退出，外部引用未闭合仍返回引用冲突。

旧事实默认不 adoption：

- 已有存在 owner 下但没有归属关系的节点拒绝；
- v1 legacy 特征定义 / 实例拒绝；
- 不按形状、名称、本地键、旧模块、缓存或历史调用方补族；
- 不在读取中静默补写；
- 需要保码时必须另立具名迁移合同并提供可审计原 owner 证据；否则由新 owner 重建新编码，再独立退出 legacy。

## 6. 依赖与无环证明

身份来源不增加跨服务调用：每个族只向自己的 L1 锚点建立单向关系，锚点不反向引用成员。服务依赖保持：

```text
存在 -> L1
场景 -> 存在 + L1
特征 -> 存在 + L1
状态 -> 存在 + 特征 + L1
动态 -> 存在 + 状态 + L1
因果 -> 状态 + L1
聚合只读面 -> 六服务
```

消费者只能调用目标族公开身份来源，不得直达 L1 重演目标族证明。存在不依赖场景；特征定义 / 实例共处一个服务但 owner 和端口分离，不形成服务自调用环。provider 只构造依赖，不取得结构写入解释权。

## 7. 后继迁移顺序

```text
G2 规范治理（本叶）
-> E-ID：存在身份来源迁移
-> F-ID：特征定义 / 实例双 owner 与身份来源迁移
-> T1 按真实 E-ID / F-ID ABI 重做 S0
-> 后续状态、动态、因果首次实现直接采用本合同
-> S-ID 场景身份来源迁移
-> A1 最终聚合公开面
```

E-ID 先行，因为当前存在已经具备真实 owner-scoped ABI，只需在现有 owner 内增加来源登记、同写归属和来源读回；旧未标记存在不 adoption。

F-ID 后行，因为它消费存在身份来源，并需要把现有 v1 特征整体迁入定义 / 实例两个新 owner：

1. provider 在存在服务之后依次建立定义 owner、实例 owner；
2. 特征服务构造函数取得 const L1 读取、const 存在服务和两份 move-only 端口；
3. 定义的节点 / 固定属性 / 来源登记只走定义端口；
4. 实例、宿主 / 定义关系、实例值及相应类型登记只走实例端口；
5. 原 v1 特征事实不改 owner、不保码；新 owner 重建后由独立退出叶处理 legacy。

场景不前置 T1，因为 T1 直接消费存在与特征；但场景必须在 A1 前完成。状态、动态、因果尚无本路线已发布新版事实，应在首次实现时直接同写本族归属，禁止先建立弱身份再迁移。

## 8. 生产外验证矩阵

每个身份来源叶至少验证：

1. owner 与来源登记首次建立、精确重复、同键异义和 owner-aware 读回；
2. 锚点 / 类型创建不晚于首节点，生命周期覆盖全部成员；
3. 节点与非自环归属关系同写、同 owner、同创建代次；
4. 当前 / 历史来源和完整读取同截止，不用当前补历史；
5. wrong-family、v1 legacy、裸节点、锚点 / 类型节点和旧未标记节点拒绝且零变化；
6. 单族读取对本族错 owner、错锚点、错类型、错角色、重复关系和混代来源精确失败，不扫描其它族；
7. 同键同请求返回首次节点 / 关系，同键异请求幂等冲突；
8. 漏归属关系退出冲突，完整闭合后节点 / 关系同代退出，退出前后历史可读；
9. 外部引用未闭合继续引用冲突，不能借族归属自动退出消费者事实；
10. provider / 跨服务生产外集成矩阵证明七 owner 两两不同、同一编码不能被两族同时接受；特征两套强类型 owner 交付不可交换、不可混写，一个端口不能制造另一族接受的事实；
11. provider 重复取得只返回同一服务，普通调用者零 raw 端口 / owner 选择；
12. L1 核心零 L2 import / friend / 枚举分支，生产零测试友元、第二仓、身份缓存权威或业务语义。

验证者位于生产代码外，只经公开 DTO / 服务和 L1 权威读回，不解析日志、不访问私有仓、不把构建或未观察到错误当作通过。

## 9. 完成声明边界

G2 发布只证明正式规范、物理合同和迁移顺序已冻结，不证明任何 DTO、owner、锚点、关系类型、来源函数、provider 迁移、构建、运行或集成验收已经完成。

G2 治理计划登记 `已退出`，不产生代码执行许可。后继 E-ID、F-ID 及其它实现叶必须各自按当时正式代码形成设计就绪计划并通过生产外矩阵。
