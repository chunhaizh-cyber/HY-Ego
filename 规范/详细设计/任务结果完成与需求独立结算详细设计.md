# 任务结果、目标达成、任务完成与需求结算分层详细设计

日期：2026-08-23
版本：v0.3
状态：设计重基线；不授予代码实施许可

## 1. 定位与重基线结论

本文重基线旧“任务结果完成与需求独立结算”设计，吸收当前已发布的任务实际结果、实例方法、执行轮次、正式结果身份和任务结果治理后继输入。旧 `BIZ-L2-004-06 结算需求并形成服务结算输入` 仍是待激活的合并骨架，不得按旧签名直接激活，也不得把以下层次压入一个函数：

```text
正式任务实际结果
-> 任务目标达成裁决
-> 任务生命周期完成
-> 任务结果消费关系裁决与争用分配
-> 当前承接需求成员的目标满足裁决
-> 需求唯一正式结算
-> 普通任务现实影响 / 服务合同或准备绑定
-> 价值结算
-> 安全值 / 服务值变化
```

这不是把一个旧组合器拆成多个同义包装器，而是按机器事实所有权、写入事务和生命周期分账拆开。每层必须有自己的强类型输入、结构化结果、权威读回和非成功边界。

## 2. 当前事实与旧设计冲突

### 2.1 已发布的任务结果事实

当前 `L2任务实际结果事实` 已明确绑定：

```text
任务身份
实例方法身份
执行轮次
正式任务实际结果身份
实际状态 / 动态等结果材料
形成时事实截止
```

任务结果治理后继输入进一步绑定：

```text
任务身份
实例方法身份
执行轮次
正式任务实际结果身份
共同事实截止
```

因此，来源任务序号、回执编号、路径名称或旧“已发布任务结果 + 独立实际结果”二元组不得再作为结算主键。

### 2.2 当前目标达成裁决边界

现行任务目标达成设计只回答：

> 本轮正式任务实际结果是否达到任务唯一目标？

它通过任务结果治理后继输入回读任务、需求列表项、实例方法、当前路径、目标状态合同、实际状态和动态，再形成值式目标达成裁决。它不直接写任务生命周期，不形成需求结算，也不形成服务值变化。

### 2.3 旧 `004-06` 合并骨架

当前 `服务.L2治理函数骨架.ixx` 中的 `BIZ-L2-004-06` 仍是待激活 TODO，旧合同把以下动作放在一个入口内：

```text
收束任务实际结果
提交需求正式结算
读取服务合同 / 服务准备
形成服务生存聚合输入
```

该骨架不是当前机器事实，也不是合法的实施入口。任何执行计划在新分层设计发布前不得把它实现为万能服务、第二任务结果写入口或跨域事务入口。

### 2.4 旧“完成任务并独立结算”组合器

旧组合器只可作为历史兼容材料。它不能继续同时拥有任务完成和需求结算写权，也不能把一次函数成功返回解释为任务完成、需求满足或价值结算完成。后继实现必须按本文分层重新形成公开入口和调用链。

### 2.5 当前结果消费与成员优先级缺口

现行代码和正式接口尚未提供“任务结果面向当前需求成员集合的消费关系裁决”，也没有正式成员分配优先级 provider。已有任务执行优先级只用于任务调度，不具备结果分配语义；需求权重、预算、队列位置、创建时间和稳定编码同样不能补默认顺序。

因此本文只冻结结果消费关系和分配层必须满足的业务合同，不冻结其最终函数、DTO、物理 owner 或事务 ABI，不据此授权施工。后继计划必须先闭合该 provider；争用路径在 provider 发布前保持零写停止。

## 3. 七层职责矩阵

| 层 | 权威问题 | 合法输入 | 权威输出 | 允许写入 | 明确禁止 |
| --- | --- | --- | --- | --- | --- |
| 1. 任务实际结果 | 本轮实际观察到什么 | 任务、实例方法、执行轮次、实际材料、幂等身份 | 正式任务实际结果身份及不可变事实 | 任务实际结果事实 | 任务完成、需求满足、结算、服务值 |
| 2. 任务目标达成裁决 | 结果是否达到任务唯一目标 | 任务结果治理后继输入及同截止权威读回 | `已达成`、`未达成`、具名不可裁决状态 | 值式裁决材料或后继准备 | 裸 I64 比较、需求结算、生命周期写入 |
| 3. 任务生命周期完成 | 任务是否满足完成前置并进入完成 | 目标达成裁决、验证结果、结果当前性、完成来源和版本 | `任务完成` 或 `目标未达成待重筹办` 等生命周期后继 | 任务领域生命周期和任务完成事实 | 需求满足、需求正式结算、服务值 |
| 4. 结果消费关系与分配 | 同一结果能否被成员共同消费；若争用，谁先取得多少 | 已完成任务、正式结果、冻结合格成员集合、消费合同、规则版本、共同截止；争用时还需正式优先级证据 | `可共用`、`争用`、具名不可裁决；争用时逐成员分配与剩余 | 由后继独立 provider 按正式事务合同写关系 / 分配事实 | 把关系固化为结果永久布尔、先排序后猜关系、复用任务优先级 |
| 5. 需求目标满足 | 每个取得合法结果引用或分配的需求目标是否满足 | 已完成任务、正式结果、关系裁决、可选分配、目标合同、实际状态、必要动态 / 因果材料 | 每个需求身份的目标满足裁决 | 需求满足裁决所需值式材料 | 把列表项聚合键当结算身份、修改任务完成、把未获分配写成未满足 |
| 6. 需求正式结算 | 需求是否发布唯一正式结论 | 单一需求满足裁决、来源任务结果身份、关系 / 分配证据、目标合同和规则版本 | 该需求唯一正式结算记录 | 5160 需求结算记录 | 任务完成回滚、服务值、泛化满足 |
| 7. 现实影响与价值变化 | 现实影响是否具备服务 / 安全价值后继资格 | 已结算需求、直接服务合同或准备绑定、完整秒和规则版本 | 值式服务聚合输入；后继价值 / 安全 / 服务变化 | 仅由服务生存聚合事务写价值和安全 / 服务事实 | 004-06 直接支付、补回或写安全值 |

同一层可以有多个只读步骤，但不得因为步骤数量增加而重新合并跨层写权。层间传递必须使用值式强类型结果和正式身份，不传递布尔“全部成功”。

## 4. 第一层：正式任务实际结果

任务结果提供者只追加不可变实际结果事实。结果业务键至少包含：

```text
任务身份 + 实例方法身份 + 执行轮次
```

正式结果身份由首次发布分配，并在独立读回中回传。相同完整请求精确幂等；同轮异义请求引用冲突、零载荷。结果未知、资源失败、当前性漂移或读回矛盾不得被任务完成层补成成功。

这一层的独立读回必须能够重新取得任务、实例方法、路径、实际状态、动态、需求列表项和共同事实截止。日志、回执文本和方法函数返回不具有结果权威性。

## 5. 第二层：任务目标达成裁决

目标达成裁决只消费冻结的任务结果治理后继输入：

```text
任务
实例方法
执行轮次
正式任务实际结果身份
共同事实截止
```

裁决过程：

```text
按正式结果身份读回实际结果
-> 读回任务、实例方法、路径和需求列表项目标
-> 读回目标状态合同、实际状态和必要动态
-> 使用正式比较服务形成目标达成裁决
-> 返回已达成 / 未达成 / 具名非成功
```

该层不得写任务生命周期。目标已达成只形成“待验证后完成”后继准备；目标未达成只形成“目标未达成待重筹办”后继准备；不可比较、当前性漂移、引用冲突或材料不足保持具名状态和零写入。

## 6. 第三层：任务生命周期完成

任务完成必须单独复核：

```text
目标达成 = 已达成
验证合同 = 通过
正式结果 = 当前
完成来源和完成版本 = 完整
旧执行冻结 = 正确失效 / 被完成迁移取代
```

只有任务领域服务可以发布任务生命周期完成。它可以复用同一任务实际结果身份和原子任务写集，但不得在该写集中发布需求结算或服务变化。

目标未达成时，任务领域服务只能把任务迁移到 `目标未达成待重筹办`；不得写任务失败，不得撤销真实实际结果和动态，不得调用需求正式结算。

任务完成后的正式读回至少证明：

```text
任务当前生命周期 = 任务完成
任务实际结果身份仍一致
实例方法和执行轮次仍一致
共同事实截止满足调用合同
```

## 7. 第四层：任务结果消费关系裁决与争用分配

### 7.1 裁决对象

`可共用`或`争用`不是任务结果脱离上下文后的永久类型。裁决对象必须完整绑定：

```text
正式任务实际结果身份
+ 本次冻结的合格需求成员集合及版本
+ 每个成员的目标和消费资格
+ 结果数量、范围、所有权和有效性合同
+ 消费关系规则版本
+ 共同事实截止
```

同一正式结果在不同成员集合、数量合同、所有权合同或规则版本下必须重新形成关系裁决，不能复用裸布尔或显示标签。在关系未唯一裁决前，不进入成员优先级排序，也不调用逐需求满足或 5160 正式结算。

### 7.2 可共用路径

若一个成员引用或消费结果不会减少其它合格成员可取得的数量、范围、所有权或有效性，关系为`可共用`：

```text
冻结关系裁决和同一正式结果引用
-> 对每个合格需求分别读取目标、当前事实、授权、路径和结算资格
-> 分别形成目标满足裁决
-> 每个已满足需求分别提交唯一正式结算
```

可共用路径不建立成员优先级队列。某个成员已满足、未满足、材料不足或结算非成功只影响本成员，不能代替、阻断或批量决定其它成员。共同结果证据可以复用，需求身份、满足裁决和结算记录不能合并；价值、预算、归因份额和其它争用权益不得重复领取。

### 7.3 争用路径

若一个成员消费结果会减少其它成员可取得的数量、份额、独占所有权或有效机会，关系为`争用`。开始分配前必须在同一共同事实截止上冻结：

```text
待分配正式结果及初始可用量 / 份额 / 独占资格
+ 当前合格需求候选
+ 每个候选的正式成员分配优先级证据
+ 优先级规则版本和同级确定性顺序
+ 初始已分配账与剩余结果
```

随后只按正式成员分配优先级依次处理：每次先复核当前成员资格和剩余，再形成合法分配并立即扣减剩余，最后才处理下一成员。不可分割结果首次合法分配后剩余归零；可分割结果按每次实际分配后的剩余继续。成员尚未轮到时是`等待分配`，结果耗尽或资格不足时形成`未获分配`、`结果已耗尽`或具名资格结果；这些都不是任务执行失败，也不是需求目标未满足或正式结算成功。

### 7.4 零写停止与未闭合合同

关系裁决材料、合格成员集合、共同截止、结果消费规则、正式成员分配优先级 provider、同级顺序或版本任一缺失时，返回具名材料缺口、当前性漂移或合同未形成，结果关系 / 分配和后继需求结算均零变化。不得默认结果可共用，也不得用任务执行优先级、队列顺序、需求权重、预算、创建时间或稳定编码填充分配顺序。

本文尚未冻结该层最终 provider 的 owner、函数、DTO、事务、幂等键、发布未知恢复和独立读回合同，所以该层仍是后继设计缺口，不是可执行代码叶。

## 8. 第五层：各承接需求的目标满足裁决

任务完成不自动等于所有需求满足。对当前任务承接的需求成员，需求领域必须逐项读取并裁决：

```text
需求身份
需求目标合同
任务完成及正式实际结果身份
实际状态 / 动态 / 可选因果材料
共同事实截止
```

需求列表项只提供聚合入口和成员视图，不替代单个需求结算身份。可共用时每个合格成员分别进入；争用时只有已经取得足够正式分配的成员进入。任一成员目标未满足、材料不足、当前性漂移或动态合同缺失，只影响该成员的满足裁决，不得把其它成员强行标为满足。未获分配或结果耗尽在第四层收口，不进入本层伪装成目标未满足。

这一层只形成值式目标满足材料或具名拒绝 / 待复核结果；不得直接创建 5160 正式结算记录。

## 9. 第六层：需求唯一正式结算

5160 需求正式结算按单一需求身份发布唯一正式结论。提交前必须复核：

```text
需求目标满足裁决 = 已满足
来源任务已完成
来源正式任务实际结果身份、实例方法身份和执行轮次一致
结果消费关系裁决当前且绑定本次成员集合
争用时本需求的正式分配身份、取得量 / 资格和分配版本一致
目标状态、实际状态和必要动态同源且当前
不存在同需求异义结算记录
```

结算失败或暂不可执行时：

- 需求结算结构零变化；
- 不回滚任务完成；
- 返回值式待复核材料；
- 不把“未结算”写成需求未满足终态。

同一需求同义提交精确幂等；异义提交冲突，不能用较新的时间或日志覆盖既有结算。

## 10. 第七层：普通任务现实影响与价值变化

需求正式结算完成后，若该普通任务具有现实影响或服务合同关系，才允许进入后继绑定：

```text
读取当前直接服务合同或服务准备
-> 形成值式服务生存聚合输入
-> 服务生存聚合事务裁决价值结算
-> 服务生存事务按自己的合同发布安全值 / 服务值变化
```

`BIZ-L2-004-06` 不拥有以上任何最终价值写入权。它最多在重构后成为窄的业务编排门面，分别调用已经明确 owner 的结果消费关系 / 分配、目标满足、需求结算和服务聚合入口；若无法保持逐层返回和独立读回，则不得保留该门面。

服务合同终态、余款 / 准备补回、衰减段归属、安全值和服务值变化必须由 6100、6160、6170 及其后继服务生存事务裁决。需求“已满足”不等于服务价值已入账。

## 11. 新旧入口迁移矩阵

| 旧入口 / 材料 | 现行归属 | 处理 |
| --- | --- | --- |
| `任务结果结算组合器::处理任务执行结果` | 任务结果治理与目标达成适配 | 只消费正式结果治理后继，不直接承担需求结算 |
| `任务业务服务::提交实际结果并完成` | 任务生命周期完成 | 保留任务领域 owner，不由 004-06 代写 |
| 当前无正式入口 | 结果消费关系裁决与争用分配 | 必须另行冻结具名 provider、优先级来源、事务、幂等和读回；当前不得临时内嵌到 004-06 或 5160 |
| `需求业务服务::提交独立结算` | 单需求正式结算 | 仅在逐需求满足裁决通过后调用 |
| `BIZ-L2-004-06` 合并骨架 | 旧跨层门面 | 待重构；未重构前禁止激活，禁止实现万能服务 |
| `读取当前服务合同或服务准备` | 服务绑定只读层 | 只形成后继聚合输入，不写服务值 |
| `形成服务生存聚合输入` | 服务生存治理输入层 | 只形成值式输入，由后继事务发布价值变化 |

## 12. 调用顺序与非成功边界

### 12.1 达成路径

```text
任务结果治理后继输入
-> 正式任务实际结果独立读回
-> 任务目标达成裁决 = 已达成
-> 任务生命周期完成并正式读回
-> 冻结合格需求成员集合并裁决结果消费关系
-> 可共用：不排优先级，逐需求独立形成结果引用
-> 争用：按正式成员分配优先级逐项分配并每次扣减剩余
-> 对每个取得合法结果引用 / 分配的需求独立形成目标满足裁决
-> 每个已满足需求分别发布唯一正式结算
-> 读取服务合同 / 准备并形成服务聚合输入
-> 后继服务生存事务裁决价值及安全 / 服务值变化
```

### 12.2 未达成路径

```text
正式任务实际结果
-> 目标达成裁决 = 未达成
-> 任务迁移目标未达成待重筹办
-> 需求满足和需求结算零变化
```

### 12.3 任何层的非成功

入口拒绝、许可拒绝、当前性漂移、资源失败、材料不足和版本冲突必须在所属层返回。关系不可裁决、争用优先级合同缺失、等待分配、未获分配和结果耗尽必须在第四层分账，不能折成需求未满足。后层不得吞掉前层非成功、猜测成功、用日志 PASS 或创建第二事实补齐。

## 13. 完成声明边界

本文完成只表示分层设计已冻结，不表示以下任何能力已经实现：

```text
004-06 新门面已重构
任务目标达成裁决已发布生产 ABI
任务生命周期完成写入已接通
结果消费关系裁决、争用分配和正式成员分配优先级 provider 已接通
逐项需求满足与 5160 结算已接通
服务合同 / 准备绑定已接通
价值结算、安全值或服务值变化已接通
```
