# SELF-THREAD-GOVERNANCE-ORCHESTRATION 自我线程治理编排详细设计

日期：2026-09-03
版本：v0.1
状态：需求冻结草案；消息协议与 manager 生产端上游尚未实现，不得登记施工

## 1. 目标与边界

本设计只补齐 `自我线程` 内部的初始化、治理消息循环、分类处理、需求治理编排、任务治理意图编排和安全治理编排。它借鉴旧实现中有价值的“有界邮箱、停止优先、定时唤醒、消息分类、显式重试”形状，但不迁移内存需求表、任务表、安全浮点值、时间衰减、全局启发式优先级或吞异常。

“需求管理、任务管理、安全管理”在本设计中的含义均为 self 的读取、判断和调用编排，不改变事实 owner：

- self 产生并确认需求目标；task owner 只记录；需求 owner 只发布或复用需求；
- self 只发送不可变任务承接意图和任务后继决议；manager 独立读回并调用 task owner；
- self 只请求安全治理与现实执行授权；安全值、硬否决和授权事实仍由各正式 owner 发布；
- 消息、线程缓存、循环次数、日志和端口返回均不成为第二事实源。

本轮不实现任何外部 provider，不修改任务管理线程、任务工作线程、数据服务、装配、工程文件、消息协议或端到端测试，不进行联合运行测试。

### 3.1 后续任务管理线程必须实现的完整消息能力

本计划只冻结消费合同。开始 self 代码施工前，后续任务管理线程实现必须通过独立上游计划同时完成：

1. 修改 `海中鱼巣/线程/自我治理消息协议.ixx`，把 `派生需求载荷` 扩展为完整强类型定位，提升协议版本，并同步更新消息相等、任务定位、路由和必填材料复核；
2. 修改 `海中鱼巣/线程/任务管理线程.ixx`，使 manager 成为该消息唯一合法生产者；manager 必须先独立读回，再逐字段填充并发送同一不可变消息。

冻结后的 `派生需求载荷` 至少包含：

```cpp
L2任务身份 父任务;
L2任务轮次身份 父任务轮次;
L2任务筹办轮次权威记录身份 父任务筹办轮次;
L2需求身份 父需求;
L2方法身份 候选方法;
L2方法内容版本 方法内容版本;
L2方法规格版本 方法规格版本;
L2方法结果身份 主轴结果;
std::vector<L2方法条件身份> 完整条件组;
std::uint64_t 作用对象角色;
稳定编码 条件来源稳定编码;
L2存在身份 目标宿主;
L2特征定义身份 目标特征;
L2目标状态合同身份 目标状态合同;
std::optional<L2场景身份> 条件场景;
std::uint64_t 来源共同事实截止G0;
```

上游协议准入必须要求：全部强类型身份有效；条件组无坏身份且无重复；作用对象角色和条件来源非零；G0 非零且等于消息头 `读取截止代次`；来源精确为任务管理线程正式上行边界。现有 `来源任务序号` 只作同任务邮箱排序，不能转换、哈希或包装成任务、轮次、筹办记录、需求、方法或条件身份。

消息始终只作定位。self 收到后必须以这些强类型身份和 G0 分别向 task owner、需求 owner、方法 owner fresh 读取父任务、任务轮次、筹办轮次、父需求、方法内容、主轴结果、完整条件组和目标合同，并与消息逐字段互证；消息值、manager 缓存和 self 处理槽都不能替代正式读回。上游端口未装配时创建非成功且不开治理门；消息必填定位缺失时协议拒绝；只有正式 fresh 读回明确返回具名业务条件待满足时才进入 `合法等待`，资源失败另入资源等待。三者均不得从旧五字段、裸序号或本地状态补造，也不得把 ABI/引用/结构缺口包装成业务等待。

### 3.2 task owner 承接记录合同的相邻门禁

5170 还要求正式任务子目标承接记录绑定任务轮次和 self 确认来源。当前 `L2任务子目标承接记录事实` / `L2新增任务子目标承接记录请求` 只有任务、裸筹办轮次、父需求、来源、子目标、G0 和幂等身份，缺任务轮次及 self 确认来源，且筹办轮次尚非 5260 要求的强类型身份。因此第三异步端口的 manager 实现还必须等待 task owner 记录 DTO/服务由独立上游计划完成这三项强类型迁移和正式读回；本设计不修改其数据头或服务，也不把现有入口伪装成已满足 5170。

## 4. 消费侧统一结果合同

在 `自我线程生产创建.数据.h` 增加 `自我线程外部调用状态`：

```cpp
enum class 自我线程外部调用状态 : std::uint8_t {
  已形成 = 1, 精确重复 = 2, 合法等待 = 3,
  当前性漂移 = 4, 引用冲突 = 5, 不可比较 = 6,
  资源失败 = 7, 入口拒绝 = 8, 内部错误 = 9
};
```

所有端口结果必须携带 `状态`、`本次正式读回截止` 和与请求绑定的强类型身份/快照；只有 `已形成`、`精确重复` 为成功。失败结果不得携带伪造事实。`合法等待` 与 `资源失败` 不得自旋；`当前性漂移` 不得复用旧投影；`引用冲突/不可比较/入口拒绝` 终止当前消息；`内部错误` 锁存受影响处理槽并使治理循环以结构化内部错误退出。

## 5. 外部支撑端口冻结规格

以下是 self 消费侧所需的最小公开合同。类型与抽象端口声明均放在自我线程数据头内以保证本切片可编译；本计划不提供实现。

### 5.1 需求治理端口

```cpp
class 自我线程需求治理端口 {
public:
  virtual ~自我线程需求治理端口() = default;
  virtual 需求治理当前快照结果 读取需求治理当前快照(
      const 需求治理当前快照请求&) noexcept = 0;
  virtual 自我需求目标确认结果 确认后继目标(
      const 自我需求目标确认请求&) noexcept = 0;
  virtual 已承接需求发布结果 发布或复用已承接需求(
      const 已承接需求发布请求&) noexcept = 0;
};
```

`读取需求治理当前快照请求` 固定包含：合同版本、运行代次、唯一 self 存在身份、双根锚点、可选父需求/任务/任务轮次/正式子目标记录定位、一个非零 G0 和成员预算。结果按同一 G0 返回目标合同、父链、当前活动资格、当前满足裁决和具体需求 D；不得从消息补字段。

`确认后继目标请求` 固定包含：运行代次、治理批次、消息编号、消息幂等键、self、父需求和父任务定位、目标宿主、特征定义、目标状态合同、独立必要性与祖先范围复核材料、G0。成功返回唯一确认身份及原请求逐字段回显，不发布需求。

`发布或复用已承接需求请求` 固定包含：上述确认身份、task owner 已正式发布的子目标承接记录身份、父需求、目标合同、运行代次、G0 和派生幂等身份。需求 owner 必须独立读回确认和承接记录；成功返回具体 D 及其列表项和父关系读回。self 不直接写需求结构。

### 5.2 任务管理异步提交端口

```cpp
class 自我线程任务管理提交端口 {
public:
  virtual ~自我线程任务管理提交端口() = default;
  virtual 自我子目标记录提交结果 提交已确认子目标承接记录意图(
      const 自我已确认子目标承接记录意图&) noexcept = 0;
  virtual 自我任务消息提交结果 提交任务承接意图(
      const 自我任务承接意图&) noexcept = 0;
  virtual 自我任务消息提交结果 提交自我任务后继决议(
      const 自我任务后继决议意图&) noexcept = 0;
};
```

`自我已确认子目标承接记录意图` 固定包含：合同版本、运行代次、治理批次、来源消息编号与幂等键、self、目标确认身份、父任务、父任务当前筹办轮次、父需求、方法/方法内容版本/方法规格版本/主轴结果/条件/作用对象角色/条件来源稳定编码组成的来源材料、目标宿主/目标特征/目标状态合同/可选条件场景组成的子目标材料、来源共同事实截止 G0，以及由上述完整内容确定的 task-owner 写入幂等身份。不得携带“已形成需求”或由 manager 产生的目标判断。

第三个函数是异步队列入口兼同键完成定位读回，返回 `自我子目标记录提交结果`：

- 首次合法入队返回 `已接收`，不携带记录；同义重投且 manager 尚未完成返回 `精确重复待处理`；
- manager 取出后必须按意图中的父任务和筹办轮次 fresh 独立读回任务、任务虚拟存在、父需求承接关系、来源方法/条件和目标合同；逐字段一致后才调用 task owner 的 `新增任务子目标承接记录`；
- task owner 返回提交或精确重复后，manager 必须按返回的 `L2任务子目标承接记录身份` 独立读回，确认任务、筹办轮次、父需求、来源、子目标、G0 和幂等身份逐字段一致；
- self 在下一完整秒边界或收到相关事实唤醒后，以完全相同的意图重放第三个函数；端口对已完成同键返回 `记录已形成`，并只携带 `L2任务子目标承接记录身份`、记录内容版本和 manager 正式读回截止。该返回只是定位回送，不是记录事实；
- self 收到 `记录已形成` 后把强类型记录身份交给需求治理端口的 `发布或复用已承接需求`。需求 owner 必须再次独立读回记录并校验目标确认绑定，不能消费 manager 缓存；
- 同键异义返回 `引用冲突`；队满、停止、资源和内部错误按统一非成功矩阵处理。

第三异步端口本身不新增消息类型、不要求第二回送通道；第 3.1 节完整派生需求消息仍由独立 manager 上游实现。完整秒只提供有界重查时机，不改变业务状态；同一处理槽每个新完整秒最多重放一次，禁止紧循环轮询。

`自我任务承接意图` 固定包含：合同版本、运行代次、治理批次、来源消息编号和幂等键、self、一个具体需求 D、D 的目标合同身份/目标宿主/特征定义/目标状态、D 当前活动与未满足见证、G0。不得只传列表项、需求组或通用授权包。

`自我任务后继决议意图` 固定包含：同一定位字段、任务、任务轮次、轮次结算、一个具体 D、本次 fresh 需求满足裁决身份、指令 `继续/结束/等待/取消`、理由枚举和 G0。目标未达成不自动等于继续；等待条件未变化不得自行重投。

任务承接和后继决议提交结果只证明异步邮箱 `已接收/精确重复/队满等待/已停止/入口拒绝/内部错误`，不得携带“任务已创建、已推进或已结束”结论。子目标记录入口仅在上述 manager 已独立正式读回记录后允许回送强类型记录定位；三者均不回送业务结论。

### 5.3 安全治理端口

```cpp
class 自我线程安全治理端口 {
public:
  virtual ~自我线程安全治理端口() = default;
  virtual 安全治理当前快照结果 读取安全治理当前快照(
      const 安全治理当前快照请求&) noexcept = 0;
  virtual 安全治理执行结果 请求执行安全治理(
      const 安全治理执行请求&) noexcept = 0;
  virtual 现实执行授权结果 请求现实执行授权(
      const 现实执行授权请求&) noexcept = 0;
};
```

安全快照请求绑定 self、双根、运行代次和 G0；结果分账返回 6100 主动结算定位、6140 分层安全快照、6150 调度倍率/硬否决材料及各自规则版本，不能合成第二安全值。

安全治理执行请求另绑定本批已复核的安全事件/任务轮次结算定位和消息幂等键。provider 按 6100→6140→6150 顺序处理并正式读回；无适用事件返回 `已形成+无变化`，循环次数和普通任务成功/失败不得改变安全值。

现实执行授权请求只适用于已冻结现实改变步骤，必须绑定任务、任务轮次、筹办轮次、执行轮次、冻结、实例方法、完整现实动作范围、当前硬否决读回和 G0；内部治理或无现实副作用的纯观察不请求。成功只返回自我业务 owner 的唯一授权定位，安全服务不得发布正向授权。

## 6. 初始化

`创建并使自我线程停在治理运行门` 在创建物理线程前完成：

1. 校验创建合同、运行代次、双根锚点、邮箱容量和三个端口均非空；
2. 锁存同一请求，异义重入返回选择冲突；
3. 复用现有有界邮箱、完整秒、事实版本和批次路由；不在 self 内建立 self、根需求、任务、安全值或 provider；
4. 以创建请求的唯一 self/双根材料调用需求和安全读取端口做 fresh 初始复核；等待、漂移、引用冲突、资源和内部错误按第 4 节返回创建非成功，不开放治理门；
5. 初始复核成功后才创建物理线程并停在关闭门，发布停门见证。开放门只改变线程门状态，不构成业务事实。

## 7. 消息循环与分类处理

主循环固定顺序：

```text
停止锁存优先
-> 有待重试槽时等待显式重试、相关新事实唤醒或下一完整秒边界
-> 冻结完整消息批次、完整秒和同一非零 G0
-> 复核分类，停止消息优先
-> 按冻结顺序逐条处理
-> 本批安全治理一次
-> fresh 读取需求治理快照
-> 形成零或多条任务承接/后继决议意图
-> 异步提交并逐条记录提交状态
-> 全部成功后推进只读游标并释放批次
```

分类处理：

- `任务结果复核请求`：保留现有 task owner 独立读回；再 fresh 读取具体 D 的当前满足裁决，形成四分支后继决议；
- `派生需求请求`：只消费第 3.1 节上游发布的完整强类型消息；先按同一 G0 fresh 读回父任务/轮次/筹办、父需求、方法/结果/条件组和目标合同，互证后才确认目标并调用第三个任务管理异步入口；收到 `已接收/精确重复待处理` 时保槽，下一完整秒最多同键重放一次；收到 `记录已形成` 后把强类型记录定位交需求 owner 独立读回并发布/复用；
- `自检缺口`、不可舍弃结构化缺口：只触发根需求治理任务或等待后续 manager 完整派生需求消息，不得由 self 从缺口载荷补造父任务、轮次、方法或条件；
- `观察材料准入`、`缓存刷新`、`事件日志`：不直接写需求/任务/安全，只触发相关目标与当前事实重读；
- `执行前许可预判`：先读安全硬否决；内部治理/纯观察返回无需授权定位，现实改变调用授权端口；
- `停止`：优先锁存，停止邮箱，保留已冻结事实定位，退出并 join。

一个消息只能在一个处理槽中推进。消息幂等键、运行代次、批次、消息编号和业务身份组成重放绑定；同键异义为引用冲突。禁止把队满、等待时间、循环次数或重试次数转成业务需求或后继理由。

## 8. 处理槽与失败收口

数据头增加只读诊断快照，内部实现保留唯一当前批次和当前消息下标；每条消息记录阶段、调用状态、G0、业务定位及是否等待显式重试。不得缓存完整权威事实作为下轮当前值。

- 合法等待：保留槽和定位，睡眠等待新消息、显式重试或下一完整秒；同一完整秒不得重复调用；
- 资源失败：保留槽，只有显式重试信号才重试同一幂等输入；
- 当前性漂移：废弃旧投影，保留原消息定位，重新冻结新 G0 后从首个 fresh 读取阶段开始；
- 引用冲突、不可比较、入口拒绝：结构化拒绝当前消息，继续同批下一条；
- 内部错误：锁存诊断，停止受影响治理循环，不伪装成功；
- 停止：高于上述所有普通分支。
