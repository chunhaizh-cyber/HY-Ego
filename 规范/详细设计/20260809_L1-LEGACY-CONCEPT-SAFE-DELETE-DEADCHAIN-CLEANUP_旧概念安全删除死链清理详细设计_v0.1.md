# 旧概念安全删除死链清理详细设计 v0.1

日期：2026-08-09

设计身份：`L1-LEGACY-CONCEPT-SAFE-DELETE-DEADCHAIN-CLEANUP`

## 1. 目标与完成边界

本设计只删除当前代码中零生产调用者、零编排器定义的旧“概念安全删除”准备与提交死链，收缩旧四仓及概念图相关头文件，不迁移消费者、不接入新 L1、不改变任何仍可达 CRUD 行为。

完成只证明本设计具名死链及工程登记退出。不得声明旧四仓退出、目标中性 L1 已装配、L1 CRUD 已验证或 L1—L5 已完成迁移。

## 2. 当前事实与复用裁决

创建侧基线为 `e1afec4f913582a07ae09ff2f0fc706bba7ae327`，`main == origin/main`。

当前事实：

1. 正式入口经 `启动.应用程序.ixx` 构造 `普通应用上下文`，旧四仓仍是生产活动对象；四仓类型及其普通 CRUD 必须保留。
2. `L1事实基座服务` 及中性 CRUD 合同属于目标保留实现，即使当前未进入普通应用装配也不得删除。
3. `概念安全删除编排器` 只有前置声明和 friend，没有类定义、实例、构造或调用点。
4. 四仓的概念删除准备 / 提交函数没有外部调用；它们只消费自身准备包和不可构造的提交会话。
5. 概念图服务、统计服务和四个领域服务中的相关函数只为该死链形成候选、缓存包或所有者授权，没有外部调用者。
6. `概念安全删除提交能力.数据.h` 的阶段、会话、请求和授权只被上述死链消费。

裁决：不建立替代接口或兼容壳，直接物理删除整条自循环死链；保留概念图其它读取、登记、投影和普通结构维护能力。

### 3.3 概念删除候选链

在 `概念图服务.h` 中删除只服务于该链的：

- 删除候选完备阶段、影响候选、待重算材料、结构写集补全候选和读取结果；
- 概念图清理准备包；
- `读取概念删除影响候选`、`准备概念登记与活动快照清理包`、`补全概念删除结构写集`；
- 相应私有准备、登记提交和活动快照提交辅助函数；
- `概念安全删除编排器` friend 和只由清理包提供的别名。

不得删除概念根登记、活动图、抽象树读取、普通关系维护或其它仍有调用者的概念图能力。

### 3.4 统计与领域授权死入口

- `统计服务.h`：删除概念缓存清理准备包、公开/私有准备函数、提交函数和专属 friend。
- `存在服务.h`、`动态服务.h`、`二次特征服务.h`、`因果服务.h`：分别删除零调用的 `形成概念节点清理授权`。

## 6. 清理安全检查

本计划不建立 L1 功能测试、CRUD 测试、生产运行测试或独立验收。只执行：

1. 删除符号、删除文件、include 和工程登记零命中；
2. 目标中性 L1 文件及公开中性 CRUD 入口仍存在；
3. `git diff --check`、`git diff --cached --check`；
4. Debug x64 与 Release x64 完整编译、链接；
5. `python .\tools\check_specs.py --strict`。

编译链接只证明清理后静态闭合，不证明数据逻辑正确。L1 能力只在后续 L2—L5 实际使用中按其自身合同累计确认。

## 7. 创建侧结论

本设计不新增函数、DTO、事实写入、事务或公开能力。所有删除对象均为无外部调用的自循环死链，执行者不需要决定机器语义或替代实现；满足建立独立清理叶的条件。
