## 1. 目标与完成条件

把 R102 的成员约束组落到代码：集合类特征值域除完整快照有限域外，可同时表达四种约束项——实例成员（现有“必含…组”）、概念成员（至少一个成员属于概念）、概念子集（全部成员属于概念）、至少一个成员（现有标志）。

完成条件：
1. 存在集合、需求集合、任务集合三种值域都能保存、读回、规范化、校验、比较满足、判断包含（蕴含）概念成员与概念子集；
2. 成员是否属于概念由成员原领域 owner 判定：存在按存在概念，需求、任务按各自类别概念（先天槽 1、2 及其下位子概念）；
3. 归属未知与“不属于”分账，不折算为不满足；
4. 模拟学习对无结果样例的存在集合条件改用概念成员；
5. 全部既有消费者编译通过且语义不变（原有字段原样保留）。

不在本设计范围（见第 9 节裁决）：消息集合、方法集合。完成声明只能写“R102 在存在、需求、任务三种集合落地”，不得写“R102 全部落地”。服务对象需求特征保持第 5.1 节单 D 引用，不恢复集合语义（v0.2，审计）。

## 3. 表示（公开 DTO 变更）

三个结构各追加两个字段，原字段不动：

```cpp
std::vector<稳定编码> 含概念成员组;    // 概念成员：至少一个成员属于该概念
std::vector<稳定编码> 全部属于概念组;  // 概念子集：全部成员属于该概念
```

- 默认空，既有构造与比较语义不变；`operator==` 仍为默认全字段。
- 规范化：两组各自排序去重；`含概念成员组` 非空时“至少一个…”强制 false（被蕴含）。
- 结构合法：概念节点有效且为本类型允许的概念（3.1）；同一概念可同时出现在两组。

### 3.1 允许的概念

| 集合 | 允许概念 | 判定 |
| --- | --- | --- |
| 存在集合 | 普通存在概念（专属或抽象，非信息结构形状） | `概念_存在类::是存在概念节点` 且非先天信息结构 |
| 需求集合 | 槽 1 需求或其下位信息结构概念 | 上位链到达槽 1 |
| 任务集合 | 槽 2 任务或其下位信息结构概念 | 上位链到达槽 2 |

不合法返回 `入口拒绝`，不建立概念。

### 3.2 持久

- 新增两个共用字段全局：`集合含概念成员字段`、`集合全部属于概念字段`（多节点引用），三种集合共用；在 `结构已初始化`、`结构仍存在`、`初始化` 字段登记、schema 不重叠列表、零引用清理字段列表（`概念字段类型` 1510-1531）中登记。
- 建立/更新：存在集合在原原子请求中追加两组字段；需求/任务集合在逐字段写入中追加，回滚列表同步。
- 读取（3086-3120、4971-4985、725）：读两组字段；字段存在而集合标记缺失视为损坏（同现有孤字段规则）。
- 读回比较：`值域 == 规范新定义->值域` 自然覆盖新字段。

### 3.3 保护

- 概念节点进入 `读取特征概念定义保护` 闭包：每个概念加 `概念_存在类::读取存在概念上位保护`（存在概念）或 `读取正式概念身份保护`（类别概念）的完整保护组。
- 概念退出：被引用概念的零引用删除本就检查入向字段；新字段进入 `概念字段类型` 后自动阻止删除。
- 存在集合保护节点 G 不扩展（只保护实例成员）。

## 4. 归属判定接口（owner 提供，均不取业务锁）

统一结果：

```cpp
enum class 特征成员概念归属 : std::uint8_t { 属于 = 1, 不属于, 未知 };
struct 特征成员概念归属结果 final {
    特征概念规则状态 状态 = 特征概念规则状态::入口拒绝;   // 已完成/读取接口未装配/资源失败/前提已变化/内部不一致
    特征成员概念归属 归属 = 特征成员概念归属::未知;
    std::vector<基础联合节点快照> 身份保护;
};
```

三个既有读取接口各追加一个虚函数（默认实现返回“读取接口未装配”，不破坏其它实现者）：

- `特征存在成员读取接口::判定存在集合成员概念(E, C)` —— 新_存在类实现：
  1. 读 E 专属概念（`读取专属存在概念身份保护`，无锁）；`存在概念包含(C, 专属)` 为真 → 属于；
  2. 否则 `匹配存在概念(E, C)`：匹配 → 属于；不符合 → 不属于；材料不足 → 未知；
  3. 采集期间材料变化 → 状态 前提已变化。
  依据：与 `证明真实存在引用范围` 同口径；`匹配存在概念` 只取共享递归锁，可在特征概念比较内调用；遇集合类 FC 返回规则不支持时为材料不足 → 未知，不递归求集合。
- `特征需求成员读取接口::判定需求集合成员概念(D, C)` —— 新_需求类实现：
  1. C 为槽 1 → 属于（D 身份由既有 `读取需求集合成员身份` 核验）；
  2. 否则新增无锁直接内容读取器 `读取需求直接内容无锁(D)`：只读冻结 schema 与 L1 字段（同 `读取需求节点引用身份` 方式），覆盖全部需求（不限被认知）；
  3. 调 `概念_存在类::判定正式结构内容(C, 内容, 读取器, 身份核验器, 关联核验器)`：符合 → 属于；不符合 → 不属于；当前未知/不适用/未支持 → 未知；前提已变化 → 前提已变化。关联核验沿用 801/802/812 现有规则。
- `特征任务成员读取接口::判定任务集合成员概念(T, C)` —— 新_任务类实现：
  1. C 为槽 2 → 属于；
  2. 否则新增无锁读取器 `读取任务直接内容无锁(T)`：读 T 的 L1 字段（对应需求、方法实例/采用方法、执行组织、最近执行实例、影响评估组、完成结算）及经任务虚拟存在路径的状态与服务值（同 `读取任务所属需求` 的无锁方式）；
  3. 读取路径项按 4.1 的已解析路径值合同交给判定器；
  4. 内容值种类追加 `任务引用`、`方法引用`（`信息内容.数据.h` 末尾追加，旧值不动）；引用项遇结构型范围概念时按 4.2 交对应领域继续判定。
  5. 结果映射同需求。
- `判定方法集合成员概念(M, C)`（新_方法类，无锁）：本轮不作为集合比较入口，只供 4.2 嵌套判定使用（如 211 “采用方法 → 方法概念”）；C 为槽 3 → 属于，否则以无锁直接内容读取器 + `判定正式结构内容` 判定。

### 4.1 已解析路径值合同（v0.2，审计第3条）

```cpp
enum class 正式路径值状态 : std::uint8_t { 已读取 = 1, 无值, 未知, 不适用, 未支持 };
struct 正式已解析路径值 final {
    稳定编码 实例;                       // 被判定对象（如任务T）
    std::vector<稳定编码> 完整路径;      // 结构项读取路径的完整FT序列，与概念项 读取路径 逐项相等
    正式路径值状态 状态 = 正式路径值状态::未支持;
    std::optional<正式内容值> 值;        // 仅 已读取 时有值，类型与路径末项FT的正式内容种类一致
    std::vector<基础联合节点快照> 保护;  // 读取该值时实际经过的节点联合快照
};
```

- `判定正式结构内容` 增加入参 `std::span<const 正式已解析路径值>`，默认空，旧调用不变。
- 定位只按（实例, 完整路径）精确匹配：实例必须等于本次被判定对象，完整路径必须与概念项的 `读取路径` 完全相等；不按末项FT查找，不同路径不得混用。同一（实例, 路径）出现两次为内部不一致。
- 状态语义：已读取 → 按普通项判定值域；无值 → 该项按“当前未知”（与直接项缺值同口径）；未知 → 当前未知；不适用 → 该项不适用；未支持或未提供 → 维持现有“未支持”。
- 保护：判定器把各路径值的保护并入本次判定的完整保护组；调用方（owner）在判定返回后按联合快照复核一次，任一快照变化返回前提已变化，保证路径值确为该实例本次实际读到的值。

### 4.2 结构型范围的嵌套判定（v0.2，审计第2条）

`比较正式内容范围` 遇到引用型内容值且范围概念为结构型（信息结构概念）时，不再直接返回未支持，而是调用调用方提供的 `结构范围判定器(内容值, 范围概念) → 特征成员概念归属结果`：

| 内容值种类 | 交给 |
| --- | --- |
| 存在引用 | `判定存在集合成员概念` |
| 需求引用 | `判定需求集合成员概念` |
| 任务引用 | `判定任务集合成员概念` |
| 方法引用 | `判定方法集合成员概念` |
| 其它 | 未支持 |

- 结果映射：属于 → 该项符合；不属于 → 不符合；未知 → 当前未知；非已完成状态原样上抛。
- 递归防护：判定器携带已访问（对象, 概念）集合与深度上限 8；重复或超限返回未知，不报结构错误（概念图无环，超限只作保护）。
- 未提供判定器时维持现有“未支持”，不影响其它调用方。
- 例：任务根概念 2 的“对应需求 → 202 自我执行域需求”交需求 owner 判定；215 已结算任务的状态经 4.1 路径值判定、结算依据经任务引用判定。

## 5. 比较语义

### 5.1 满足（准确集合 S 对值域 V）

各项同时成立：
- 实例成员：沿用现行；
- 至少一个：沿用现行；
- 概念成员 C：S 中存在成员归属 = 属于；若无属于而有未知 → 未知；
- 概念子集 D：S 中全部成员归属 = 属于；任一不属于 → 不满足；无不属于而有未知 → 未知；空集满足。

总判定：任一项不满足 → 满足=0；否则任一项未知 → 状态 `成员归属未知`（`特征概念规则状态` 末尾追加 11）；否则满足=1。
比较结果结构各追加 `缺少概念成员组`、`不属于概念组`、`未知概念组`（向量，默认空）。
`新_特征类::比较特征值域` 把 `成员归属未知` 映射为新追加的 `新特征比较状态::材料不足`（末尾追加 13）；任务条件核验侧（`当前值命中概念` 等）把它映射为材料未到，不判不具备。

### 5.2 包含（强 V1 蕴含弱 V2）——三态（v0.2，审计第1条）

蕴含判断结果为 成立 / 不成立 / 未能判定，不以“未证明”代替“不成立”。

现有实例/标志规则不变；两侧都没有概念项时按现行规则得到成立或不成立。有概念项时：

- 弱的每项按下列证据逐项判：
  - 实例成员 m：强含 m → 成立；
  - 至少一个：强有非空要求（标志、实例成员或概念成员）→ 成立；
  - 概念成员 C：强有实例成员 m 且 m 归属 C = 属于；或强有概念成员 C′ ⊑ C；或强有概念子集 D′ ⊑ C 且强有非空要求 → 成立；
  - 概念子集 D：强有概念子集 D′ ⊑ D → 成立。
- 弱的全部项成立 → 蕴含成立。
- 能构造反例 → 不成立：弱的某项在强下可被违反且存在满足强的集合违反它（判据见 5.4：强可满足，且“强 ∧ 非该项”可满足被证明）。本轮可证明的反例只有：弱要求实例成员 m 而强既无 m、强的概念子集也不排除含 m 以外的成员时，取强的见证集合即为反例；其余情形 → 未能判定。
- 归属未知、⊑ 无法判定 → 该项未能判定；接口未装配或读取故障 → 返回依赖状态（读取接口未装配/资源失败/前提已变化），不转成正常关系。
- ⊑：存在概念用 `存在概念包含`；类别概念沿信息结构 `上位结构概念组` 上位链；只读、在共享递归锁内。

### 5.3 值域关系（相等/包含/相交/分离/未能判定）

`比较值域`、`存在规则域关系`、`需求规则域关系` 及任务分支的结果增加“未能判定”：结果状态 `成员归属未知`，关系字段空。

- 约束对约束：左含右、右含左按 5.2 三态；相交与分离按 5.4 联合可满足性：联合可满足被证明 → 相交（或包含/相等）；联合不可满足被证明 → 分离；否则未能判定。两侧均无概念项时沿用现行结果。
- 有限快照对约束：逐快照按 5.1 得 命中/未命中/未知。全部命中 → 约束包含快照域；有命中 → 相交成立；全部未命中 → 分离；有未知时：包含与分离都未能证明，若另有命中仍为相交，否则未能判定。
- 快照对快照：沿用现行（不涉及归属）。
- `是严格子值域`、`结构定义相同` 只在得到确定关系时使用；未能判定按“不是严格子值域/不相同”处理并不建立层级，但返回状态让调用方区分（建立时返回 `成员归属未知`，不建立概念）。

### 5.4 约束可满足性（v0.2，审计第4条）

单个约束 V 与联合约束（两约束要求并集）的可满足性三态：

- 证明不可满足（空值域）：
  - 某实例成员 m 对某概念子集 D 归属 = 不属于；
  - 某概念成员 C 与某概念子集 D 证明不相交（存在概念用 `存在概念相交` 为否；类别概念：C 与 D 在信息结构上位链上互不包含且收窄同一项为不同值）；
  - 有非空要求而概念子集组的交被证明为空（同上判据）。
- 证明可满足：无概念子集时恒可满足（只含“必须包含”类要求）；有概念子集时须：每个实例成员对每个 D 归属 = 属于，且每个概念成员 C ⊑ 每个 D，且（有非空要求时）至少存在一个实例成员或概念成员。
- 其余 → 未能判定。
- 建立或更新值域时，证明不可满足的约束返回入口拒绝；未能判定允许建立。

## 8. 失败与边界

- 归属判定接口未装配：满足比较状态 `读取接口未装配`；不当作不属于。
- 判定器读取故障：资源失败/内部不一致按现有工程路径；不伪装为不属于。
- 前提已变化：沿现有重读路径。
- 存在概念为先天信息结构形状、或类别集合给了普通存在概念：入口拒绝。
- 不新增物理删除；概念引用保护按 3.3。
- 内存数据集无持久化，不需迁移、不升版本号。
