# 旧四仓退役后孤立合同清理详细设计 v0.1

日期：2026-08-10

设计身份：`L1-LEGACY-POST-FOUR-STORE-ORPHAN-CONTRACT-CLEANUP`

## 1. 目标与完成条件

在旧四仓及其主要反向闭包已经退出后，继续物理删除已经失去全部生产消费者、且只承载旧普通应用装配、旧业务角色、旧概念链、传统仓库事务或旧控制面板投影合同的八个孤立头文件。

完成必须同时满足：

1. 第 3 节八个文件及其现有工程登记归零；
2. 八个文件名及其具名根类型在现行生产源码、`海中鱼巣.vcxproj` 和 `海中鱼巣.vcxproj.filters` 中归零；
3. 新 L1、现存 L2 数据服务、线程基础模块、D455 适配、通用日志与容错文件保持不变；
4. Debug / Release x64 完整编译链接通过。

完成只证明八个孤立旧合同退出，不证明其历史业务已经迁移、现存不可达模块都应删除、L1—L5 完成或程序恢复原业务能力。

## 2. 当前事实与裁决

施工起点为 `e1e6b253f8224a10bb94ab0332b5f65c481a379e`。

- 八个目标文件均没有集合外生产包含者；其中旧生产运行期配置只向内包含旧概念/角色链及若干数据 DTO，没有任何现行调用方。
- 七个目标文件仍作为 `ClInclude` 登记在工程和 filters；`显示服务.h` 已不在工程中，也没有任何生产包含者。
- `结构事务接线.数据.h` 明确承载“传统仓库”许可；`索引所有权.数据.h` 仍含未知兼容、业务域所有者和兼容释放；`结果.结构写入.h` 使用对象版本式旧写入结果，均不属于 4015 当前中性 CRUD 公开合同。
- 系统角色、概念活动和概念图算法承载业务角色与概念解释，且当前无消费者；0050 已把业务解释固定在 L5 之外。
- `显示服务.h` 只服务已退出的旧控制面板链，当前无工程登记和调用方。
- `句柄.h` 仍被现存线程、动态/因果及安全模块引用，不属于本批；通用日志和容错虽当前没有生产调用者，但不是旧四仓专属合同，也不纳入本批。

因此本批只做物理删除，不迁移、不改名、不建立兼容壳，也不以“当前入口不可达”为理由删除新 L1、L2 服务、线程、D455 或安全算法模块。
