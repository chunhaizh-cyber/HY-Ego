# 旧四仓反向依赖闭包退役详细设计 v0.1

日期：2026-08-10

设计身份：`L1-LEGACY-FOUR-STORE-REVERSE-CLOSURE-REMOVAL`

## 1. 目标与完成条件

根据用户确认的整体退场裁决，物理删除主信息、节点、关系、索引旧四仓，以及只因该旧基座存在而继续编译的反向依赖闭包；不把旧业务迁移到新接口，不建立兼容壳。

完成必须同时满足：

1. 旧四仓八个源码文件及工程登记归零；
2. 旧四仓类名、头文件引用和旧闭包模块在生产工程归零；
3. 程序入口、未依赖旧基座的线程基础模块及全部新 L1 模块保留；
4. 普通应用上下文只拥有一个新 `L1事实基座服务`；
5. 普通控制面板模式对已退出窗口业务返回结构化非成功，不产生空成功；
6. 无窗口模式保留停止信号租约和驻留等待，不建立业务事实；
7. Debug / Release x64 可以完整编译链接。

完成不证明新 L1 数据逻辑正确、旧功能等价迁移、控制面板可用、领域服务完成或 L2—L5 已接线。

## 2. 当前事实

- 当前普通应用直接构造旧四仓，并把它们注入世界、存在、场景、状态、动态、概念、语素、需求、任务、方法和控制面板等旧服务。
- 范围受限的 include / import 反向闭包扫描得到 44 个源码文件，其中 31 个文件直接出现旧四仓类型。
- 新 `海中鱼巣.核心.服务.L1事实基座` 及其中性 CRUD 模块已经独立存在，但当前普通应用没有持有该服务。
- 用户已经明确接受：旧业务能力整体退场；删除后只保留程序入口、线程框架、新 L1 和最小空装配。

## 3. 目标入口合同

### 3.1 普通应用装配

文件：`海中鱼巣/装配.普通应用.ixx`

目标结构：

```cpp
struct 普通应用配置 {
    bool 有效() const noexcept;
};

class 普通应用上下文 {
public:
    L1事实基座服务 L1;
};
```

`构造普通应用上下文`只校验空配置并构造上下文；构造失败返回既有 `构造失败`，不创建世界、场景、自我或其它默认事实。

### 3.2 程序宿主

文件：`海中鱼巣/启动.程序运行宿主.ixx`

保留停止信号安装、租约恢复和无窗口等待。`运行无窗口宿主`只接收停止信号租约，不读取普通应用上下文。删除控制面板宿主及其旧服务、旧投影、旧窗口参数。

### 3.3 顶层程序

文件：`海中鱼巣/启动.应用程序.ixx`

固定顺序：

```text
验证模式
-> 构造新 L1 最小空上下文
-> 普通控制面板：返回 宿主失败 + 控制面板窗口
-> 无窗口常驻：安装停止信号并进入无窗口宿主
```

不得运行旧系统初始化、旧统计、旧投影或旧自我线程，不得把控制面板退出返回为成功。

`海中鱼巣/入口.cpp`保持不变，继续负责参数解析、调用唯一顶层程序和映射退出码。

## 5. 编译错误裁决

删除后以 MSVC 编译错误继续发现遗漏依赖：

- 错误位于仍引用已删除旧类型的函数或旧模块时，删除该旧函数、旧 import、旧 include 或整个仅旧用途文件；
- 错误位于第 3 节保留入口时，按最小空装配合同收束；
- 错误位于新 L1 或不依赖旧基座的线程基础模块时，不删除该模块，只清除来自旧闭包的调用边；
- 不允许新增兼容类型、转发门面、默认有效事实、空成功或旧名字的新实现；
- 若出现计划清单外的新旧混合文件，必须先证明其旧函数可独立删除且不改变新 L1 / 线程基础合同，再纳入本计划记录。
