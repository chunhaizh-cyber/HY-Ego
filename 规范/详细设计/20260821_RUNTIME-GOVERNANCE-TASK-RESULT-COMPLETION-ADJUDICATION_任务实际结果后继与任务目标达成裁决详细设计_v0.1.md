## 1. 目标与完成边界

本设计承接已经正式发布的任务结果上行生产链和自我线程任务结果治理处理槽，在同一治理事实截止下完成以下窄链：

```text
任务结果治理后继输入
-> 按正式任务实际结果身份独立读回本轮结果
-> 读回任务、实例方法、当前选中路径、完整方法、任务唯一目标和目标状态合同
-> 读回实际状态、动态证据和实际状态的特征实例
-> 调用正式特征比较服务
-> 按目标状态合同允许关系形成任务目标达成裁决
-> 在当前治理处理槽冻结生命周期后继准备
```

本叶只回答：

> 本轮正式任务实际结果是否达到该任务的唯一目标？

本叶不把“目标已达成”升级为“任务已完成”。正式规范要求任务完成还必须具备验证通过、结果当前、完成来源和完成版本；当前代码没有任务生命周期业务状态写入口，也没有执行路径验证合同的正式服务。因此：

- 目标已达成时只冻结“待验证后完成”准备；
- 目标未达成时只冻结“目标未达成待重筹办”准备；
- 不写任务生命周期，不退出任务节点，不写需求满足或结算。

该边界符合用户允许的“调用或准备现行任务生命周期合法迁移”，并避免由自我线程越权写任务状态。

`治理输入幂等键`只用于互证本次治理输入没有异义复用，不是新的业务稳定编码，也不参与 DATA 写入。

### 3.2 状态和生命周期准备

## 4. 唯一裁决函数

### 4.1 物理位置和签名

在现有模块 `海中鱼巣.领域.组合.运行期只读查询` 的 `运行期只读查询组合器`增加：

```cpp
任务目标达成裁决结果 裁决任务目标达成(
    const 任务目标达成裁决请求& 请求) const noexcept;
```

组合器增加不破坏现有调用方的八服务构造重载：

```cpp
运行期只读查询组合器(
    const L2需求结构服务&,
    const L2任务结构服务&,
    const L2方法结构服务&,
    const L2状态结构服务&,
    const L2特征结构服务&,
    const L2存在结构服务&,
    const L2场景结构服务&,
    const L2动态结构服务&) noexcept;
```

现有七服务构造保持不变，继续服务已经发布的实际结果上行桥；通过七服务构造的实例调用新裁决函数固定返回入口拒绝，不允许隐式取得第二方法服务。

### 4.2 固定执行顺序

1. 校验请求合同、五个非零身份/编号和 G0。
2. 按任务实际结果身份，以当前类别和请求 G0调用`读取任务实际结果`；任何读回截止不等 G0 为当前性漂移。
3. 互证结果的任务、实例方法和执行轮次与请求完全一致。
4. 用正式结果字段构造现有`任务实际结果独立读回请求`并调用`读取任务本轮实际结果与独立读回`，禁止用步骤2返回对象替代完整独立读回。
5. 以 G0读取完整方法、完整特征实例、完整目标状态合同和当前目标判断比较注册。
6. 按§2.3逐项互证任务目标、路径预期结果、实际状态和动态证据。
7. 从实际状态精确值和目标状态合同目标值形成比较输入；字段来源按下表固定。单位、维度、分量角色只来自正式比较注册合同，左右角色固定为当前事实和目标状态。
8. 调用`L2特征结构服务::比较特征`，只请求具名关系；不得在组合器内比较两个 I64。
9. 将具名关系映射为目标合同位：当前低于目标=`0x01`、当前达到目标=`0x02`、当前高于目标=`0x04`。只有对应位包含于`允许关系位`才是目标已达成。
10. 已达成返回`待验证后完成`；未达成返回`目标未达成待重筹办`。两者都不写事实。

步骤9只解释目标状态合同已经持久化的三位集合，不改变特征比较结果。位映射必须集中在一个纯值辅助函数中并由三关系全覆盖测试锁定，治理线程不得复制该映射。

比较请求字段映射固定为：

| 比较请求字段 | 当前事实左输入 | 目标状态右输入 |
| --- | --- | --- |
| 请求身份 | `治理输入幂等键` | 同一请求身份，不另生成 |
| 特征定义 | 需求列表项`目标特征定义` | 同一目标特征定义 |
| 用途 | `目标判断` | `目标判断` |
| 事实身份 | 实际状态`精确值.值稳定编码` | 目标合同`目标值稳定编码` |
| 类型化不可变材料 | 实际状态`精确值.类型化不可变材料` | 目标合同`目标I64` |
| 来源稳定编码 | 实际状态`精确值.来源稳定编码` | 目标合同`来源稳定编码` |
| 输入版本 | 实际状态`精确值.创建事实代次` | 目标合同`生命周期.创建事实代次` |
| 生命周期 | 由实际状态精确值的创建/退出代次形成 | 目标合同生命周期 |
| 原始类型 | `I64`，实际材料不是 I64 则不可比较 | `I64` |
| 单位/维度/分量角色 | 正式比较注册合同 | 同一正式比较注册合同 |
| 角色 | `当前事实` | `目标状态` |
| 预期算法族/版本 | 正式比较注册合同 | 同一注册合同 |
| 要求结果位 | 仅`具名关系`，值为`0x02` | 同一请求 |

比较返回还必须互证请求身份、事实截止、注册身份、算法版本、左右输入回执、单位、维度、分量角色和左右角色；只检查`状态 == 已比较`不足以形成裁决。

### 4.3 错误映射

| 来源 | 裁决状态 |
| --- | --- |
| 正式结果尚未形成、方法或目标合同在 G0 尚无 | 合法等待 |
| 任一读回截止不等 G0、比较注册或输入版本失效 | 当前性漂移 |
| 任务/实例/轮次/路径/方法/目标/状态/动态引用不一致 | 引用冲突 |
| 未注册、类型/单位/维度/角色不匹配、比较结果不完整 | 不可比较 |
| 请求形状或合同错误 | 入口拒绝 |
| DATA 或比较服务资源失败、`bad_alloc`、`length_error` | 资源失败 |
| 重复关系、零/多预期结果命中、成功载荷不完整或未知异常 | 内部错误 |

禁止把不可比较、材料不足或当前性漂移当作目标未达成。

## 5. 治理入口与装配

`海中鱼巣.领域.服务.L2治理函数骨架`的装配入口增加`L2方法结构服务`借用，并增加值式转发入口：

```cpp
任务目标达成裁决结果 裁决任务结果治理后继目标(
    const 任务目标达成裁决请求& 请求) noexcept;
```

该入口只在八个服务均已装配时构造八服务组合器并转发；未装配返回入口拒绝。它不缓存裁决、不持有任务写能力。

普通应用和治理专项必须把同一应用上下文的`L2方法结构服务`加入现有装配调用。任务实际结果上行桥继续使用七服务构造，不修改其职责或上行协议。

## 6. 自我线程处理槽消费

现有任务结果处理槽增加：

```text
目标裁决次数
optional 任务目标达成裁决快照
```

内部槽增加一个冻结后继值。固定顺序为：

1. 002-04首次成功后，先把现有`任务结果治理后继输入`冻结到内部槽；
2. 从该冻结值构造`任务目标达成裁决请求`，恰一次调用新入口；
3. 已达成或未达成时，把裁决快照冻结到公开处理槽并返回“任务目标裁决已形成”；
4. 合法等待或资源失败保留同一批次、原消息、原后继、原业务键和原 G0，等待显式重试；
5. 同槽重试只重试目标裁决，不重新读取邮箱、不重新分类、不重新调用 002-04、不猜执行轮次；
6. 当前性漂移、引用冲突、不可比较、入口拒绝和内部错误结构化终止，零生命周期写入；
7. 已冻结裁决若被内部路径再次遇到，只允许逐字段全等读回；任何异义为内部终止。

生产上游已经按正式任务实际结果身份去重，现有自我线程又只有一个当前任务结果处理槽，因此相同业务键在本链只形成一份裁决。精确重复工作结果必须读回同一上行槽、同一治理批次、同一后继和同一裁决，不能形成第二次比较或第二个生命周期准备。

## 7. 生产级验证

主成功路径必须经过：

```text
任务结果生产运行包
-> 任务工作线程
-> 任务管理线程
-> 任务实际结果上行桥
-> 正式结果发布与独立读回
-> 自我治理邮箱
-> 批次路由
-> 002-04
-> 任务结果后继
-> 任务目标达成裁决
-> 自我线程处理槽
```

至少覆盖：

1. 目标等于实际值且合同允许“当前达到目标”，形成`目标已达成 + 待验证后完成`；不写任务状态。
2. 实际值与允许关系不匹配，形成`目标未达成 + 目标未达成待重筹办`；不把任务记失败。
3. 精确重复工作结果不形成第二正式结果、第二治理批次、第二后继或第二目标裁决。
4. 同一业务键异义输入在上游正式结果或处理槽互证处冲突，零新裁决。
5. 来源任务序号变化不改变正式执行轮次，也不改变裁决业务键。
6. 目标列表项、方法预期结果、特征实例、实际状态或动态后状态任一错绑时为引用冲突。
7. 未注册、单位/维度/分量角色不一致为不可比较，不得按未达成继续。
8. 旧 G0 只返回当前性漂移，禁止换用最新事实截止。
9. 合法等待或资源失败重试保持同一批次、消息、业务键、后继和 G0，且不再次调用 002-04。
10. 三个具名比较关系到`0x01/0x02/0x04`逐一覆盖；组合位按包含关系判断。
11. 处理槽始终零/一后继、零/一裁决；任务、需求、服务值、安全值和学习事实均零新增。

Debug/Release x64均执行全量 Rebuild 和治理专项。日志只辅助定位，所有通过结论来自结构化返回、正式读回、处理槽快照和逐字段断言。
