## 1. 本次计划支撑裁决

执行侧从正式计划提交 `745b95a31641ab8a6b0fbd9ab4694e42bcecff44`、plan blob `605b6f9ebd4f33c3f7213bc7ef37f99b97e84e55` 退回两个具名漂移：

1. v0.1把构造冻结为 `const L1事实基座服务&`，但同步物理清理必须调用现行唯一且非 const 的 `L1事实基座服务::执行L1物理清理`；写端口没有该能力，禁止 `const_cast`。
2. 因果规范与因果类已进入独立重建切片，状态计划不能继续拥有因果消费者迁移。

裁决如下：

- 状态服务构造和成员改为保存同一实例的 `L1事实基座服务&`。该非 const 引用只为调用既有物理清理写入口；创建、退出及其它普通状态写入仍只通过状态 owner 写端口，不能改走 L1 中性写入口。
- 不修改 L1 公开合同、实现或 owner 写端口；不新增第二个清理入口。
- 因果类从允许文件、完成条件、施工步骤、知识清单和验证目标中移除。因果规范发布后由后继重新扫描状态读取 ABI，本计划不预判其目标合同。
- 4230 v0.43 已由因果规范切片先行发布；本支撑不修改4230。执行重新 S0 时只消费该正式版本的状态相关条款，不消费后续未提交因果 WIP。

## 2. 目标、完成条件与排除项

目标是把当前 `数据服务.状态类.ixx` 的旧“时间 + 多特征快照”模型一次性替换为状态身份、正式 FT、固定准确值、强时间四字段模型，并使存在类、场景类两个仅做状态身份核验的消费者改用窄身份入口。

完成条件：合同版本2 DTO和十一项公开函数全部实现；两种值表示、两种时间语义和0成立；创建、当前/历史读取、三类字段查询、退出、同步实例清理、共同身份读回和旧格式拒绝闭合；旧 v1 声明/定义及存在/场景调用零命中；状态服务合法调用 L1 物理清理且零 `const_cast`；工程可编译。

明确排除：因果消费者迁移、4202 C/E/P/S 状态使用绑定、动态数据、场景动态组织、动作来源、动态概念、因果业务、当前选择关系、普通应用周期装配、存量转换程序、测试专用生产入口。它们不得进入状态 DTO 或状态写集。

- v0.1计划正式发布提交为 `745b95a31641ab8a6b0fbd9ab4694e42bcecff44`，plan blob 为 `605b6f9ebd4f33c3f7213bc7ef37f99b97e84e55`；计划支撑接管时 `main == origin/main` 且 index 空。

- 执行侧已经在特征、状态、存在、场景文件形成允许范围内 WIP；本设计不覆盖或回退这些代码，发布后由原执行所有者按 v0.2 重新 S0、复核并续作。

- 正式基线直接调用旧 `查询状态` 的存在、场景、因果三处都只核对节点身份；本计划只迁移存在和场景。因果文件由独立重建切片拥有并已从执行现场释放。
- 旧 L2 状态结构文件已由 `6a2cfbca` 删除，不能复用或恢复。

知识库的旧 L2 状态用途卡绑定退役模块，低于当前源码；本设计只用其确认“旧材料不可作为新 ABI”，不复用旧实现。

## 4. 字段与 L1 映射

| 类别 | 字段 | 物理表达 | 基数/可变性 |
| --- | --- | --- | --- |
| 身份 | 状态身份 | 状态 owner 普通节点 + 指向状态族锚点的归属关系 | 恰一；不复用 |
| 关系 | 正式 FT | 状态节点 → FT 节点具名关系 | 恰一；不可修改 |
| 值 | 固定准确值 | I64属性，或长度1 U64组保存特征值身份编码 | 两分支恰一；不可修改 |
| 值 | 强时间 | 实例绝对UTC或抽象相对属性类型之一，材料I64 | 两分支恰一；非负；不可修改 |
| 技术材料 | 首次形成UTC | I64属性 | 恰一；不可修改；非本体字段 |

结构交付八项身份、默认TTL和数量上限及构造签名逐字采用4212 v0.2第3、11节。创建写集固定为一个节点、两条关系、三个值和三个槽；所有自有事实同次创建。

### 4.1 字段操作裁决

CODE-FILE-01要求逐字段操作映射；1160又禁止类型、值、时间独立改写。两者按权威顺序收口如下，不建立拒绝壳或同义setter：

| 对象/字段 | 新增 | 查询 | 修改 | 删除/退出 | L1映射 |
| --- | --- | --- | --- | --- | --- |
| 完整状态 | `创建状态` | 当前/历史读取 | 不允许；新内容另建状态 | `退出状态` | owner原子写集/历史读回 |
| 状态身份 | 随完整创建 | `确认当前状态结构身份`、历史见证 | 不允许 | 随完整状态退出 | 节点+族归属 |
| 正式FT | 随完整创建 | 完整读取、`按正式特征类型查询当前状态组` | 不允许 | 随完整状态退出 | FT关系/目标关系组 |
| 固定准确值 | 随完整创建 | 完整读取、`按固定准确值查询当前状态组` | 不允许 | 随完整状态退出 | 互斥属性/属性类型值组 |
| 强时间 | 随完整创建 | 完整读取、`按强时间范围查询当前状态组` | 不允许 | 随完整状态退出 | 互斥属性/属性类型值组 |

“不允许”来自上级机器语义，不生成永远失败的公开函数；所有可成立操作均有独立强类型入口。技术首次形成UTC只供同步清理内部读取，不上升为对象字段公开CRUD。

## 5. DTO、构造、函数和物理位置

4212 v0.2第2、5、6、11节的声明逐字进入现有模块 `海中鱼巣.领域.数据服务.状态类`、文件 `海中鱼巣/领域/数据服务.状态类.ixx`；公开类型置于 `export namespace 海中鱼巣`，实现 helper 留在模块内部命名空间或类 private。不得新建第二状态文件或 DTO owner。

特征窄核验 DTO 与 `特征类数据服务::核验正式特征类型准确值` 置于现有 `海中鱼巣.领域.数据服务.特征类`，声明紧邻现有准确特征读 DTO/公开读函数，定义复用 `读类型`、`解析输入`、值域检查和G/H守卫。诊断责任为“向上送出”，零日志、零写。

状态构造精确为：

```cpp
状态类数据服务(L1事实基座服务& 第一层服务,
    const 特征类数据服务& 特征服务,
    L1所有者范围写端口&& 写入端口,
    const 状态类结构交付& 结构交付,
    状态类保留策略 保留策略 = {});
```

成员保存 `L1事实基座服务& 第一层服务_`、`const 特征类数据服务& 特征服务_`、`L1所有者范围写端口 写入端口_` 及结构/策略值。构造核对特征服务、写端口均绑定于同一 `第一层服务`。`绑定于(const L1事实基座服务&) const noexcept` 的公开签名保持不变。

非 const L1 引用的唯一获准写用途是：`同步清理实例状态材料` 在 owner 逻辑退出成功后调用 `第一层服务_.执行L1物理清理(...)`。状态创建与退出继续调用 `写入端口_.提交所有者范围中性写集(...)`；不得调用 `第一层服务_.提交中性写集(...)`，不得新增清理代理、修改写端口或使用 `const_cast`。读取函数只调用 L1 const 读取入口。

状态十一项函数均为状态结构 owner 的对外服务函数；构造/绑定属于装配与特殊成员。读取、查询、身份确认和历史见证为 const；创建、退出、同步清理为写函数。公开函数诊断责任均为“向上送出”，以结构化结果承载；私有转换/校验 helper同样向上送出到公开边界，不本地重复记录。

## 6. 核心流程

### 6.1 创建

校验请求形状与G0 → 先查首次幂等材料 → 未绑定时调用特征窄核验 → 取得服务内部当前UTC → 形成固定写集 → 状态owner一次提交 → 从映射取得节点/关系/值身份 → 按发布截止完整历史读回 → 返回已创建。已绑定同请求不重新按当前来源否定首次事实，按首次材料和首次截止读回；异请求冲突。

### 6.2 读取与查询

完整读取使用同一Gread/H依次读取节点、族归属、FT关系和三值，逐项核对owner、角色、创建/退出与互斥分支；首尾重读当前G防拼接。字段查询先用L1具名组入口召回候选，再调用同G完整当前读取，排序去重。空组成功，预算不足零载荷。

身份确认只读取节点和族归属；历史见证只返回身份来源。二者不读取四字段，也不能供4202冒充状态内容。

### 6.3 退出与清理

退出先完整当前读回，再以一个状态owner写集退出节点、两关系、三值，最后在新截止历史读回。任何外部引用由L1引用保护拒绝，状态类不级联。

同步清理按首次形成UTC属性有界取得全量当前候选，完整读回后只保留实例分支，按首次形成UTC/身份排序，计算TTL与数量并集。无候选零写成功；有候选先通过 owner 写端口批量逻辑退出，再以退出提交产生的新截止构造精确六事实清理请求，调用同一实例的非 const L1 服务物理清理入口。任一引用冲突整次不形成部分成功。普通应用先清动态/绑定/组织/当前选择的跨owner编排不在本计划。

## 7. 旧格式和消费者迁移

删除状态 v1 DTO、函数及内部快照编码/解析/查询。版本2只识别新族归属、FT关系、互斥准确值、互斥时间和首次UTC；旧“一个时间+一个快照”形状返回 `旧格式不支持`。存量材料不删除、不回写、不双读、不转换。当前不存在可无歧义选择多快照中唯一FT的规则，因此任何转换都属于未来独立合同。

存在、场景两处旧 `查询状态` 改为 `确认当前状态结构身份`；只检查头的已读取、合同版本、截止和零变更。它们不得读取完整状态或新增反向依赖。

因果消费者不修改、不扫描为本计划完成项。因果正式规范和代码结构稳定后，后继任务必须重新读取当时状态 ABI，并自行裁决是否需要身份确认、完整状态读取或不再依赖状态类；本计划不冻结答案。
