## 1. 目标与非目标

本叶交付中性状态、动态、引用、实例材料清理、普通应用宿主自动维护和任务阶段消费者迁移。状态和动态不携带主体、场景、业务 owner 或许可；DATA 不裁决调用者权限。

本叶不形成主体语义、场景语义、因果、抽象算法、任务状态、业务当前性、授权、安全值、服务值或结算。上层引用方自行解释引用；抽象服务只向本叶提交已经形成的抽象结果见证，不由本叶判断抽象是否正确。

旧 `新增状态_v2` 与 `发布状态动态原子迁移_v2` 只保留零写兼容拒绝。旧账只读，不参与新合同。

四个策略上限必须非零。`L2状态结构服务` 与 `L2动态结构服务` 各自保存一份同值的 `L2中性实例材料保留策略_v1 保留策略_`。两类服务现有构造函数的最后一个参数固定追加为：

```cpp
L2中性实例材料保留策略_v1 保留策略 =
    L2中性实例材料默认保留策略_v1
```

因此既有装配调用无需修改；显式传参只用于部署覆盖和专项测试。默认实例状态/动态 TTL 都是 7 天，默认状态总量上限为 1,000,000，默认动态总量上限为 250,000。覆盖策略四项必须全部非零，否则构造函数抛出 `std::invalid_argument`，不得退回默认值或形成半初始化服务。策略不写入事实、不产生业务 owner 或许可语义；同一生产装配显式覆盖时必须向两类服务传入逐字段相同值。专项测试显式传入小 TTL 和小总量上限。

生产当前 UTC 纳秒统一由 `std::chrono::system_clock::now()` 转换；测试只允许在 `ARCH_L2_NEUTRAL_STATE_DYNAMIC_LIFECYCLE_VALIDATION` 宏下使用一次性时钟覆盖，宏关闭时无覆盖符号。

## 6. 清理算法

1. 取得一次生产当前 UTC 纳秒和请求 G0。
2. 枚举全部活动实例动态、活动实例状态及活动动态成员关系；抽象材料排除。
3. 按动态 `首次形成UTC纳秒`选出动态 TTL 到期项和满足动态数量上限所需的最旧动态。
4. 按状态 `首次形成UTC纳秒`选出状态 TTL 到期项和满足状态数量上限所需的最旧状态；不得使用 `状态.时间.纳秒`。
5. `抽象完成`请求把具名实例动态加入动态清理集合，并记录抽象结果见证。
6. 清理集合按首次形成 UTC 纳秒、稳定身份升序规范化。
7. 动态阶段先逻辑退出清理集合中的动态及动态成员关系，并用 `执行L1物理清理` 清理动态完整材料；该阶段形成自己的正式变更代次和清理进度。
8. 动态 provider 根据进度形成唯一 `L2中性实例状态清理阶段请求_v1`，调用状态服务 private 入口；状态阶段退出目标当前选择并清理没有活动动态成员引用的状态完整材料，形成自己的正式变更代次。
9. 两阶段分别从中性或 owner 正式读回取得完整墓碑投影；L2 形成逻辑墓碑并汇总最终结果。任一提交后读回失败不回滚，按原清理幂等身份和进度重放收束。
10. 当前读普通引用遇目标墓碑返回已清理、引用载荷与目标事实为空、墓碑存在、成功否。历史读遇目标材料已清理返回历史材料已清理，禁止从普通引用重建状态。

## 7. 状态矩阵

| 操作观察 | 状态 | 载荷 | 写入 |
| --- | --- | --- | --- |
| 状态/动态/引用首次成功 | 已提交 | 完整正式读回 | 一个新代次 |
| 同键同请求 | 精确重复 | 首次映射与首次事实 | 零新写 |
| 同键异请求 | 幂等冲突 | 空 | 零写 |
| 坏版本、零键、坏时间、坏数量 | 入口拒绝 | 空 | 零写 |
| 新请求 G0 不等当前代次 | 事实代次漂移 | 空 | 零写 |
| 动态少于2项、重复、时间语义混合或时间递减 | 动态不闭合 | 空 | 零写 |
| 动态成员/引用目标未找到、已退出或已清理 | 引用冲突 | 空或目标墓碑 | 零写 |
| 当前选择预期旧关系不匹配或出现多条 | 引用冲突 | 空 | 零写 |
| 当前完整读 | 已读取 | 唯一完整事实 | 零写 |
| 当前不存在 | 未找到 | 空 | 零写 |
| 当前目标已物理清理 | 已清理 | 仅墓碑 | 零写 |
| 历史截止内材料仍保留 | 已读取 | 截止时完整事实 | 零写 |
| 历史事实已物理清理 | 历史材料已清理 | 仅墓碑 | 零写 |
| 退出首次/重复 | 已退出/精确重复 | 已退出事实 | 一个新代次/零新写 |
| 清理无候选且未超量 | 无须清理 | 四个计数，清理组空 | 零写 |
| 清理首次/重复 | 已提交/精确重复 | 墓碑、退出选择和计数 | 一个新代次/零新写 |
| 分配失败 | 资源失败 | 空 | 零写 |
| 内部写会话、闭包或提交后读回异常 | 内部错误 | 空或首次墓碑见证 | 交换前零写，交换后保留 |

策略矩阵固定为状态 / 动态各 7 天、状态 1,000,000、动态 250,000 的四项独立边界；普通应用宿主负责立即和 60 秒周期维护，DATA 服务零自建线程。

所有新状态枚举均没有许可拒绝。内部写会话失败不得映射为入口拒绝或许可拒绝。

## 8. 旧 ABI 与旧账

`新增状态_v2` 和 `发布状态动态原子迁移_v2` 的函数签名、旧 DTO 布局和符号保留，但函数体固定返回入口拒绝、零载荷、零事实截止、零变更代次、零写。旧 v1 继续相同拒绝。新函数不得调用旧状态原子参与者、动态原子参与者或跨 owner 事务。

旧 owner 幂等账和跨 owner 账不得删除，也不得追加；它们只供现有历史诊断读取。新状态、动态、引用和清理分别使用独立幂等域，域常量在代码中具名且互不相等。
