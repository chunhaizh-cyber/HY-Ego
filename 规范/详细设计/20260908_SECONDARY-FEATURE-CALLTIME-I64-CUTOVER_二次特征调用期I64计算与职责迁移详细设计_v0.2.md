## 1. 本版适用方式

本版只修订执行智能体在 v0.1 S0 退回的六项合同缺口。除本文件明确替换的内容外，v0.1 第 1—10 节的目标、模块、公开类型、迁移删除集、工程、验证和完成声明继续有效；发生文字冲突时以本版为准。执行必须同时读取 v0.1 和本版，不能只实现本版增量，也不能借修订扩大到 RC、AND、持久二次实例、其它算法或生产装配。

正式依据仍为 1180 v0.9、4150 v0.12、4151 v0.1、4180 v0.11、4181 v0.1、4182 v0.1。当前源码额外确认：definition 初始化幂等键固定为 `{1}`，其规范化写集恰含 16 个既有结构节点；初始化恢复会逐字节重建并比较该旧写集。因此 v0.1 所述“扩展 definition owner 初始化角色”不可实施，它会把所有已存在实例判为旧格式。

## 2. 旧初始化不变与独立增量初始化

### 2.1 身份、幂等键和精确写集

既有 definition 初始化必须保持：幂等身份 `{1}`、本地键 `1..16`、16 个既有结构节点的种类/值表示和映射顺序全部不变。`定义角色`、`d_`、`初始化写集(分区::定义, ...)`、旧首次写入材料及恢复比较不得加入四个新身份。

四个 I64 比较绑定结构身份使用同一 definition owner 下的独立扩展初始化：

```cpp
inline constexpr L1所有者范围写入幂等身份 I64比较绑定结构扩展初始化幂等身份{
    0x4645'4154'4936'3442ULL // ASCII FEATI64B；不是 0x4E43 维护域
};

enum I64比较绑定结构角色 : std::size_t {
    I64比较绑定输入FT关系,
    I64比较绑定输出FT关系,
    I64比较绑定U64属性,
    I64比较绑定I64属性,
    I64比较绑定结构角色数
};
```

扩展规范化写集固定为：合同版本 `L1所有者范围CRUD合同版本`、调用时取得的非零 `期望事实代次`、上述固定幂等身份；只含四个节点，无关系、值、属性槽变更或退出事实：

| 本地键 | 结构身份 | 节点种类 | 属性类型表示 |
| --- | --- | --- | --- |
| 1 | 输入 FT 关系类型 | 普通 | 空 |
| 2 | 输出 FT 关系类型 | 普通 | 空 |
| 3 | U64 合同属性类型 | 属性类型 | `U64组` |
| 4 | I64 合同属性类型 | 属性类型 | `I64组` |

四项写入所有者必须等于 definition owner，首次结果映射必须恰含本地键 1—4 且四个稳定编码非零、互异。扩展身份只保存在独立 `std::array<稳定编码, 4>` 中，不追加进 `d_`，不改变旧派生 definition 的任何角色下标。

### 2.2 fresh、旧实例、发布未知与恢复

`初始化特征定义结构()`在同一服务 mutex 内顺序执行“旧 `{1}` 初始化/恢复 → 扩展初始化/恢复”。fresh 实例先形成旧 16 项写集，再以最新 G 形成四项扩展写集，允许产生两个连续事实代次；只有两者都已权威读回才返回成功。已有旧实例的 `{1}` 首次写集必须原样通过，扩展键未找到时只补四项；扩展键已存在时不得再写。

扩展初始化先按固定键读取首次写入材料：

1. `成功`：使用首次规范化写集记录的 `期望事实代次`重建上述四项写集并要求精确相等；确认首次结果的 owner、键、事实代次、发布标志和四项映射后接受身份。
2. `未找到`：以本次当前 G 构造精确扩展写集，保存完整原请求后调用同一 owner 的中性写集提交。
3. 其它确定读取状态：沿现有读取状态映射失败，不建立替代身份。

派发前的确定失败清除本次扩展 pending；派发后未能证明未发布、首次材料读取不完整或返回无法确认时保留完整扩展写集和“扩展初始化”种类，返回现有`发布结果未确认/前次写入待收敛`边界。`收敛待确认写入()`只能按所存原键、原 G 和原完整写集读取首次材料并原样重放，禁止换 G、重新生成键或并入旧 `{1}` 写集。确认后填充四项身份并清除 pending。

进程重启没有内存 pending 时，下一次初始化仍通过固定扩展键的首次持久材料恢复；同键异写集、缺/多映射、旧 owner、非法节点种类或表示均为`旧格式不支持/幂等冲突`，不得覆盖。信息分区初始化不依赖扩展身份；新比较绑定四入口在扩展未就绪时 fail-closed，不使用零身份。

## 3. 有序 I64 provider 的状态 5

v0.1 第 5 节的稳定状态数值保持不变：

```cpp
enum class 特征比较状态 : std::uint8_t {
    已比较=1, 未注册=2, 入口拒绝=3, 版本漂移=4,
    许可拒绝=5, // 仅为 4180 稳定数值历史保留洞
    资源失败=6, 内部不一致=7, 未实现=8
};
```

新 `有序I64特征比较提供者`没有许可输入、许可依赖或 L1 访问，因此任何代码分支都不得产出状态 5。`许可拒绝=5`只保持正式数值兼容，`特征比较执行结果::成功()`拒绝它；provider 可产状态仅为 1、3、4、6、7、8。当前绑定缺失由计算应用在调用 provider 前返回`未注册`，所以 provider 本体也不需要产出状态 2。禁止为“用上状态 5”增加许可服务或默认授权逻辑。

## 4. 有界准确 F 读取合同

### 4.1 DTO 与公开入口

在特征 owner 新增以下只读入口；既有 `读取准确特征事实(const 准确特征读取请求&)`保持 ABI 不变，其它既有调用方不迁移：

```cpp
inline constexpr std::uint32_t 有界准确特征读取合同版本 = 1;

struct 有界准确特征读取预算 final {
    std::uint64_t 最大节点数=0, 最大关系数=0,
        最大属性值数=0, 最大材料总数=0;
    bool 有效() const noexcept;
};
struct 有界准确特征读取用量 final {
    std::uint64_t 节点数=0, 关系数=0,
        属性值数=0, 材料总数=0;
};
struct 有界准确特征读取请求 final {
    std::uint32_t 版本 = 有界准确特征读取合同版本;
    std::uint64_t Gread=0, H=0;
    特征信息身份 身份;
    有界准确特征读取预算 预算;
};
struct 有界准确特征读取结果 final {
    std::uint32_t 版本 = 有界准确特征读取合同版本;
    特征类标量状态 状态 = 特征类标量状态::入口拒绝;
    有界准确特征读取请求 原请求;
    std::optional<准确特征读取事实> 事实;
    有界准确特征读取用量 用量;
    bool 成功() const noexcept;
};

有界准确特征读取结果 读取有界准确特征事实(
    const 有界准确特征读取请求&) const noexcept;
```

预算有效要求四项全非零。实际用量按本次入口真实读取并检查的唯一 L1 事实编码计数：节点、关系、属性值各自去重；`材料总数=节点数+关系数+属性值数`且加法可表示。F、FT、外设/单位、可选域规则/参数节点，族归属、F→FT、FT→外设/单位及可选规则关系，F值、FT规格及可选规则属性都依其真实分支计数。这里的列举不是白名单；本入口为完成准确 F 完整读回而实际读取、检查的所有 L1 事实均须按真实种类计量。引用值再次经特征值服务核验同一值事实时，同一稳定编码不重复计数；缓存命中也不重复读取、不重复计数。

每个事实进入本次读取上下文前同时检查分类余额和总余额；关系组或属性组返回后先逐项计量，预算不足不得把组内容并入成功事实。任何加法溢出或上限不足返回`预算不足`。失败清空`事实`，保留`原请求`和到失败点的真实`用量`用于诊断；不得把用量当作部分 F 消费。

`成功()`要求：版本和原请求版本正确，`0<H<=Gread`、身份有效、预算有效；状态为`已读取`且事实存在并满足原准确事实完整性；事实 Gread/H/身份逐项等于原请求；三类用量均非零、不超过对应上限，材料总数可表示且精确等于三类之和。其它状态一律非成功且无事实。二次计算只能使用本入口读取准确 F，并按`用量.材料总数`扣减`二次计算预算.最大读取材料数`。

## 5. 当前 I64 绑定读取回执与真实用量

v0.1 第 4.2 节的当前读取请求不变，新增：

```cpp
struct 特征I64当前比较绑定读取用量 final {
    std::uint64_t 候选数=0, 关系数=0, 材料总数=0;
};
```

并在 `特征I64比较绑定结果` 增加：

```cpp
std::optional<特征I64当前比较绑定读取请求> 当前读取原请求;
特征I64当前比较绑定读取用量 当前读取用量;
```

只有`操作=当前读取`允许`当前读取原请求`存在；建立、身份读取、退出必须为空且用量全零。当前读取总是完整回显原请求，包括候选/材料上限。

候选数是从输入 FT 入向绑定关系取得的不同绑定节点数；关系数是本次实际检查的不同关系事实数；材料总数是本次实际检查的不同节点、关系和值事实总数。三项均按稳定编码去重，同次缓存命中不重复计量。入向输入关系本身同时计关系和材料；候选绑定节点先计材料，再计候选；绑定归属、输入和输出关系逐项计关系/材料；两个合同值、绑定节点、输出 FT 及其结构核验材料逐项计材料。任何候选进入候选集合前检查`最大候选数量`，任何事实进入解析上下文前检查`最大读取材料数`；不足返回`数量预算不足`，不返回候选身份或`事实`，但保留数值用量诊断。

当前读取成功谓词替换为：原请求版本正确、`Gread`非零、输入 FT 有效、用途合法、两上限非零；状态`已读取`，`Gread=H=原请求.Gread`，事实在 H 完整活动且其输入 FT/用途等于原请求；候选数恰为 1，关系数非零且不大于材料总数，候选数/材料数不超过原上限；无首次发布 H 和正式回执。零候选为`未找到`，多候选为`注册不唯一`；两者与预算、格式或历史失败都不得携带事实。

二次计算每次调用当前读取时，把两上限都设置为当时剩余读取材料数；返回后只能按`当前读取用量.材料总数`扣减材料预算，不能用候选数、关系数或固定常数替代。状态为预算不足时映射二次计算`预算不足`；其它失败按 v0.1 映射。

## 6. K 上下文要求与计算结果回显

v0.1 第 5 节的 `有序I64比较合同快照`在左右角色后增加：

```cpp
std::uint8_t 上下文要求位 = 0;
```

独立绑定快照逐字段复制绑定定义的要求位。旧 v2 保存定义没有该持久字段，规范化为固定 K 时只能置 0，不得按用途推导新历史含义；它与 G 下当前绑定比较时，要求位也必须等于 0，否则返回`固定规则不兼容`。

v0.1 第 6 节的 `二次准确计算结果`在`请求身份`后增加：

```cpp
二次计算上下文 上下文;
```

结果始终回显请求上下文；非成功只清空四个成功载荷组，不清空该诊断回显。上下文存在位由五个 optional 依 `参与者A=1、参与者B=2、左时间=4、右时间=8、参照=16`组成；稳定编码字段存在时必须有效。完成全部 K 读取后，计算本次所有实际计算项 `K.上下文要求位`的按位并集，必须精确等于请求上下文存在位：缺任一要求或携带无人使用的额外字段均为`入口拒绝`。不同计算项可以消费并集中的不同字段，不能覆盖 K 自己的要求。

`二次准确计算结果::成功()`新增要求：上下文结构有效；每项回执 K 的要求位只含 0—31 已知位；所有 K 要求位并集精确等于结果上下文存在位；计算项快照要求位逐字段来自对应独立绑定或固定 K 规范化；其余 v0.1 的 G/H、根、图、输出和来源闭包互证不变。provider 不自行解释上下文，但执行请求中的 K 必须原样保留要求位，执行结果成功不得改变 K 身份或算法版本。

## 7. 需求/任务请求依据回显与成功谓词

v0.1 第 7 节两个结果分别增加完整原请求：

```cpp
struct 需求目标方向结果 final {
    // 其余 v0.1 字段保持顺序与含义
    需求目标方向请求 原请求;
    ...
};
struct 任务目标方向结果 final {
    // 其余 v0.1 字段保持顺序与含义
    任务目标方向请求 原请求;
    ...
};
```

机械字段顺序固定为：`版本、状态、原请求、G、既有身份/子结果字段`。入口收到请求后、任何来源读取前即逐字段复制到结果，成功和失败均不改写；请求含版本、G、请求身份、目标记录身份、当前 F、要求结果位和完整预算，因此不再依赖离开作用域的参数判断成功。

需求方向应用必须把`要求结果位`逐个已置位角色展开成根输出组：按角色数值 1、2、3 升序遍历，位 `1<<(角色-1)` 已置位时追加且只追加一项`二次根输出{二次已保存定义输出来源{方向定义, 该角色}}`。因此请求位 1—7 可产生 1—3 个根，不新增根位集字段，也不把多输出压成一根；同一方向定义和同一角色不得重复。

需求结果成功谓词在 v0.1 基础上新增：原请求版本 1、G/请求身份非零、需求与当前 F 有效、要求结果位 1—7、预算有效；结果 G/需求/当前 F 分别等于原请求；计算结果请求身份等于原请求请求身份、上下文等于该方向应用按实际材料构造的空上下文。计算请求及结果的根输出组都必须等于上一段确定展开，数量等于`popcount(要求结果位)`，方向定义全部相同、角色严格升序无重复，角色位并集精确等于原请求要求结果位；每根在计算结果组定位到一项同 K 输出。目标 F、宿主、方向定义、计算 G=H=结果 G 和全部叶闭包继续按 v0.1 互证。这里替换 v0.1 的“唯一根”措辞。

任务应用委托需求应用时，派生请求固定为：版本 1，G、请求身份、当前 F、要求结果位和预算逐字段复制任务原请求，只把目标记录身份替换为已读来源需求。任务结果成功谓词在 v0.1 基础上新增：任务原请求自身有效；结果 G/任务等于原请求；方向原请求精确等于上述派生请求；方向的请求身份、当前 F、要求结果位和预算因此均与任务请求一致。调用前失败时方向为空；调用后失败保留完整方向及其原请求，但顶层仍非成功。

两个应用的非成功状态映射沿用 v0.1。原请求回显只是只读相关性证据，不是持久幂等身份、发布回执或重试授权。

## 8. 对 v0.1 实施与验证的替换项

1. A1 不得扩展旧 definition 初始化写集，必须实现第 2 节独立扩展初始化及恢复。
2. A2 保留状态 5 数值但静态扫描必须证明 provider 无任何赋值/返回分支产出 5。
3. A3 的准确 F 只用第 4 节有界入口；当前绑定只按第 5 节真实回执扣费；计算结果按第 6 节回显上下文。
4. A4 两个方向结果必须回显完整原请求，并按第 7 节自包含判断成功。
5. V04 增加：旧 `{1}` 写集未变、固定扩展键/四项写集、有界准确读取 DTO/用量、当前绑定三项用量、K 要求位、计算上下文、两个原请求回显。
6. V05 增加：旧实例只补扩展写集、fresh 两阶段初始化、未知发布只用原请求收敛、状态 5 永不可产、所有用量来自真实公开读取。
