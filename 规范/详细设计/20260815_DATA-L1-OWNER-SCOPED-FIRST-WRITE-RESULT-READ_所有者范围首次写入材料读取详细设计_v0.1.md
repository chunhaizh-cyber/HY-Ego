# 所有者范围首次写入材料读取详细设计 v0.1

日期：2026-08-15

设计身份：`DATA-L1-OWNER-SCOPED-FIRST-WRITE-RESULT-READ`

状态：设计就绪；不等于代码已实现

## 1. 目标

为 `DATA-L1` owner-scoped v2 增加一个 capability-protected 的只读能力：仍持有有效活动 `L1所有者范围写端口` 的唯一结构所有者，可以按一个非零 `L1所有者范围写入幂等身份` 读取本 owner 私有幂等账中保存的：

```text
首次规范化完整写集
+ 原始首次成功写入结果
```

该能力用于结构服务在构造期固定登记、内存发布结果未知和晚到精确重复时，机械证明同一幂等身份首次绑定的完整请求语义及确定编码映射。它不增加第二写入口，不读取当前业务结构，不列举幂等账，也不向普通 `L1事实基座服务` 暴露跨 owner 查询。

## 2. 当前事实与具名缺口

创建侧最终复核基线为 `main == origin/main == 83cfc8e5df6d53cca8ea6e509997cb5ed38f2c95`，index 为空。当前相关代码 blob：

- `L1所有者范围CRUD.数据.h`：`f77b4dc9e63abb3092280465354f8a1467b6ffdb`；
- `服务.L1事实基座.ixx`：`78348e162e2584ed18c3cf75fc95a61ebfab2b66`；
- `仓库.L1事实基座.ixx`：`9873676e1705fab0fa0a9cf159a5c9b835aa5739`。

现行仓库已经以 `(L1实例, owner, 写入幂等身份)` 保存 `所有者范围幂等记录`，记录具有首次规范化 `L1中性写集请求`、首次发布代次、首次编码映射和原始首次成功结果。重复提交可以在内部使用该账，但公开 owner 端口没有只读入口。

因此结构服务若遇到“登记已经发布，但首次调用未得到可用结果”或新实例构造时，只能盲重放本地假定请求；它不能在提交前证明固定幂等身份是否已被异义完整写集占用，也不能在不推进代次的情况下恢复首次期望代次和确定编码映射。该缺口命名为：

`DRIFT-DATA-L1-OWNER-FIRST-WRITE-MATERIAL-UNREADABLE`

这不是 C1 专用字段缺口。固定结构登记、后继方法结构和其它合法 owner-scoped provider 都可能复用该纯事实能力；L1 仍不知道调用方结构族。

## 4. 精确公开 ABI

### 4.1 合同版本与 DTO

在 `L1所有者范围CRUD.数据.h` 增加：

```cpp
inline constexpr std::uint32_t L1所有者范围首次写入读取合同版本 = 1;

struct L1所有者范围首次写入读取请求 final {
    std::uint32_t 合同版本 = L1所有者范围首次写入读取合同版本;
    L1所有者范围写入幂等身份 写入幂等身份;
    friend bool operator==(const L1所有者范围首次写入读取请求&,
        const L1所有者范围首次写入读取请求&) = default;
};

struct L1所有者范围首次写入读取结果 final {
    L1所有者范围读取状态 状态 = L1所有者范围读取状态::入口拒绝;
    std::uint32_t 合同版本 = L1所有者范围首次写入读取合同版本;
    L1结构所有者身份 所有者;
    L1所有者范围写入幂等身份 写入幂等身份;
    std::uint64_t 读取事实代次 = 0;
    std::optional<L1所有者范围写集请求> 首次规范化写集;
    std::optional<L1所有者范围写入结果> 首次写入结果;
    friend bool operator==(const L1所有者范围首次写入读取结果&,
        const L1所有者范围首次写入读取结果&) = default;
};
```

两个 DTO 在现有 `L1所有者范围读取状态` 定义之后、普通 owner-aware 事实读取 DTO 之前声明，避免复制或前置声明第二状态类型。现有公开类型与枚举数值全部不动。

不新增第二状态枚举，复用现行 `L1所有者范围读取状态`。本入口只允许该枚举的 `成功`、`入口拒绝`、`许可拒绝`、`未找到`、`资源失败`、`内部不一致` 六种值；`已退出`、`属性未设置` 和 `事实代次漂移` 不是本操作合法结果。

不增加公开 `有效(请求)` helper。合法性只有合同版本正确且幂等身份非零，入口直接机械判断，避免为两个字段扩张公共辅助 ABI。

### 4.2 唯一函数

在 `L1所有者范围写端口` 增加：

```cpp
L1所有者范围首次写入读取结果 读取首次写入材料(
    const L1所有者范围首次写入读取请求& 请求) const;
```

函数是 `const` 只读成员。它不接收 `L1事实基座服务`、owner、期望代次或任何结构族字段。`L1事实基座服务` 不增加同义公开函数，签发器也不增加按 owner 代查入口。

## 5. 请求与结果不变量

### 5.1 请求

合法请求必须同时满足：

```text
合同版本 == L1所有者范围首次写入读取合同版本
写入幂等身份.值 != 0
调用对象是仍持有本实例 owner 租约的有效活动端口
```

请求不携带 owner。外部知道 owner 编码和幂等身份仍不能读取；必须持有精确实例、精确 owner 的活动 raw 端口。

### 5.2 成功

成功结果必须逐项满足：

```text
状态 == 成功
合同版本 == L1所有者范围首次写入读取合同版本
所有者 == 端口.所有者身份()
写入幂等身份 == 请求.写入幂等身份
读取事实代次 != 0
首次规范化写集.has_value()
首次写入结果.has_value()
```

首次规范化写集必须为 owner-scoped v2 公共 DTO，且：

- `合同版本 == L1所有者范围CRUD合同版本`；
- `写入幂等身份 == 请求.写入幂等身份`；
- `期望事实代次` 是首次请求原值；
- 节点、关系、值、属性槽变更和退出事实均按现行规范化确定顺序返回；
- 五类写项的字段、variant 分支、材料和本地键不删减、不补默认。

原始首次写入结果必须为首次发布时保存的成功结果，而不是把状态改为精确重复：

```text
状态 == 成功
合同版本 == L1所有者范围CRUD合同版本
所有者 == 端口 owner
写入幂等身份 == 请求身份
事实代次 != 0
是否形成内存权威发布 == true
重试边界 == 不适用
新编码映射与私有记录逐项相同且按本地键严格升序
事实代次 <= 本次读取事实代次
```

本入口证明首次账目材料，不证明首次写集建立的普通事实在当前截止仍活动。当前结构必须另经正式当前读取入口确认。

### 5.3 非成功

所有非成功结果的两份 optional 都为空：

全部状态都回显首次写入读取合同版本和请求幂等身份；`所有者` 回显端口调用开始时绑定的身份，移动源可以为零。入口先校验请求合同与幂等身份，再校验端口 capability，所以坏请求与失效端口同时出现时固定 `入口拒绝`。

| 条件 | 状态 | 读取事实代次 |
| --- | --- | --- |
| 错合同版本、零幂等身份 | `入口拒绝` | 0 |
| 移动源、失效端口、实例销毁、租约不再持有 | `许可拒绝` | 0 |
| 有效 owner 下该身份没有首次记录 | `未找到` | 锁内当前代次 |
| 返回值转换发生 `bad_alloc` / `length_error` | `资源失败` | 已安全取得则保留，否则 0 |
| owner 当前事实、账记录、首次写集、结果、代次或映射不能互证 | `内部不一致` | 已安全取得则保留，否则 0 |

`未找到` 不是“绝对未发布”证明。调用方只能依据自身协议决定是否首次提交；不得仅凭未找到换新幂等身份、跨 owner 搜索或推断其它进程 / 恢复材料。

## 6. 仓库算法

在 `L1事实基座仓库` 增加一个非导出成员：

```cpp
L1所有者范围首次写入读取结果 读取所有者范围首次写入材料(
    L1结构所有者身份 所有者,
    const L1所有者范围首次写入读取请求& 请求) const;
```

固定过程：

```text
入口校验合同版本、owner 和幂等身份
-> 取得仓库 shared_lock
-> 若仓库已隔离，返回内部不一致
-> 读取并回显当前事实代次
-> 核对 owner 是当前未退出独占 owner
-> 在 所有者范围幂等账[owner][幂等身份] 精确查找
-> 未命中返回未找到
-> 局部核对所选记录的规范化写集、首次代次、映射和首次成功结果
-> 将私有 L1中性写集请求机械转换为公开 L1所有者范围写集请求
-> 将私有 L1中性写入结果机械转换为公开 L1所有者范围写入结果
-> 双 optional 同时装入后返回成功
```

只检查所选 owner、所选键及其直接互证材料；不得为该读取新增全仓扫描、整库快照、索引重建或审计材料组装。现有私有规范化函数仍是唯一规范化算法；返回前必须证明记录的首次写集再次规范化后逐字段不变。

私有转换只做同构类型映射：

- `L1中性写集本地键` -> `L1所有者范围写集本地键`；
- `L1中性事实引用` 的稳定编码 / 本地键分支逐分支转换；
- `L1中性值表示种类` 和 `L1中性原始值材料` 逐枚举 / variant 分支转换；
- 私有首次结果的状态、首次代次、发布 bool、重试边界和编码映射逐字段转换，owner 由本次端口隐式输入填入。

禁止从当前事实重新推导首次请求，禁止从编码映射猜写集，禁止把私有 `L1中性写集请求` 或内部记录类型直接导出。

## 7. 端口控制流与锁边界

`L1所有者范围写端口::读取首次写入材料` 固定为：

```text
锁定 weak_ptr 实例状态
-> 核对端口持有租约且 owner 有效
-> 在端口租约锁内确认 owner 仍在活动集合
-> 释放端口租约锁
-> 调用仓库只读函数并隐式传入 owner
```

仓库读取只持 `shared_lock`，不取得写锁、不修改 `状态_`、不推进事实代次。端口租约锁不得与仓库 shared lock 交叠持有，保持现行“先确认 capability、再进入仓库”的锁方向。owner 正常退出要求活动端口归零，因此有效活动端口进入仓库后发现 owner 缺失或已退出不是普通 `已退出`，而是内部不一致。

并发提交可以在本读取取得共享锁前或后推进代次；结果只要求所选不可变首次记录与本次锁内读取代次互证。幂等记录一经成功发布不可修改，读取不需要期望代次、自动重试、sleep、yield 或忙轮询。

## 8. 安全与所有权边界

明确禁止：

- 在 `L1事实基座服务` 增加按 owner / 幂等身份查询函数；
- 允许请求携带 owner 或返回其它 owner 的记录；
- 列举幂等身份、读取 v1 legacy 账或 owner 建立账；
- 返回私有仓库记录引用、地址、摘要、锁、事务、候选、撤销或恢复材料；
- 由 `DATA-L1` 判断调用方是概念、方法、场景或其它结构服务；
- 以未找到、日志、异常文本或空 optional 推断业务成功 / 失败；
- 修改首次结果为精确重复、用当前代次覆盖首次代次或以当前事实重建首次请求；
- 新增生产测试 seam、故障注入、检查入口或第二可执行目标。

这一公开 ABI 仍是 raw capability 的成员能力。普通调用者无法从只读 `L1事实基座服务`、owner 编码或模块名获得它；上层结构服务也不得把端口或首次材料入口继续转交给 BIZ / DATA-L3 消费者。

## 10. 诊断责任与异常

| 函数 | 诊断责任 | 合同 |
| --- | --- | --- |
| 公共 DTO 默认比较 | 无适用错误分支 | 纯值逐字段比较，不记录日志 |
| 端口 `读取首次写入材料` | 向上送出 | 失效 capability 映射许可拒绝，其它结构化状态透明返回 |
| 仓库 `读取所有者范围首次写入材料` | 向上送出 | `bad_alloc` / `length_error` 映射资源失败，其它异常映射内部不一致 |
| 私有请求 / 结果转换与局部互证 | 向上送出或无适用错误分支 | 只向仓库入口返回值 / 状态，不记录重复日志 |

每个新增项目函数在定义前增加一行中文“诊断责任”注释。生产结果不依赖日志、诊断宏、弹窗或异常文本。

## 11. 风险相称施工检查与清理

实现阶段可以在生产工程外临时建立 `验证工具/L1所有者范围首次写入材料读取参数检查.{cpp,vcxproj,vcxproj.filters}`，只使用正式运行包、签发器、活动端口和本入口，检查：

1. 新 owner 尚无写入时指定非零身份返回未找到、双 optional 为空且回显锁内代次；
2. 首次提交后读取成功，规范化五类写项、首次期望代次、首次成功状态、owner、身份、发布代次和映射逐字段一致；
3. 原完整请求精确重复和其它 owner 后续提交后再读，仍返回同一原始首次成功结果，不改成精确重复；
4. 同 owner 另一非零身份未找到；不同 owner 使用相同数值身份只能分别读到各自材料；
5. 错合同、零身份入口拒绝；移动源 / 释放租约后的端口许可拒绝；
6. 读取前后当前事实代次不因本入口推进；普通 `L1事实基座服务` 没有同义查询函数；
7. 根工程 Debug / Release 编译链接和现行代表性 owner 写入 / 读取不回归。

这些是施工检查，不是独立验收阶段。正式分配耗尽、私有账损坏、实例销毁并发数据竞争和跨进程恢复没有合法稳定公开注入时保持 `NOT_RUN` 或静态检查，不增加生产 seam。

临时三件套不得登记生产工程、不得进入最终结果提交；完成后立即删除，并复核生产工程零引用、正式代码零检查 / 测试 / 注入专用逻辑。永久记录只说明实际施工与实际检查，不声称服务永久合格。

## 12. 完成与后继边界

本叶完成只证明：活动 owner 写端口已经具备按一个非零幂等身份读取本 owner 首次规范化完整写集和原始首次成功结果的 capability-protected DATA-L1 能力，并通过实际执行的施工门禁。

它不证明 C1 四本体根、方法登记根、任何 DATA-L2 服务、DATA-L3 聚合、普通应用、阶段 18 / 19、启动、恢复或业务闭环已经实现。合法结构消费者仍须在实际使用时核对返回状态、首次材料与当前权威读回；后继发现实现缺陷按本合同修复，发现机器语义漂移再回设计治理。

C1 两份现有未发布候选必须等待本叶正式结果与临时检查清理后，从最新 HEAD 重新 S0，并把构造登记恢复机械改为消费本入口；不得继续把历史事实拼接当作私有幂等账读取，也不得沿当前候选直接登记为可执行。
