# TASK-CURRENT-SOURCE-DEMAND-TARGET-MATERIAL-GROUP-CONSUME 候选任务全部来源需求目标材料组消费详细设计 v0.1

日期：2026-08-16
版本：v0.1

## 1. 目标与完成边界

本设计实现 `BIZ-L4-004-02-02-06 v0.1`：

```text
02完整成功结果
-> 提取全部任务—来源需求关系中的唯一来源需求身份组
-> 只经同一需求业务服务，逐唯一来源需求在同一非零G0恰一次正式读取
-> 互证完整当前需求并投影目标宿主、目标特征和目标状态合同引用
-> 返回稳定、不可变、零部分前缀的来源需求目标材料组
```

本叶不定义目标等价算法。它不读取目标状态合同 / 特征定义 / 比较注册正文，不执行 I64 比较，不判断任务目标与来源目标是否等价，不选择当前任务树根，不读取拓扑、治理存在或当前世界特征值。

## 2. 正式依据与 S0 裁决

设计 S0 基线为 `main@b9b953f98c697ab5d9272faf625654d98b3958a6`：

1. 3100、5100 规定一个需求只有一个目标宿主、目标特征和目标状态合同；需求目标是目标状态，需求领域不直接比较原始值。
2. 3200、5100 规定一个任务只有一个确定目标，但可保留多个当前有效、目标语义等价且分别授权的来源需求；5100 v0.2 明确本规范不定义目标等价算法。
3. 5200 规定任务目标宿主、特征和状态通过全部来源需求与任务目标关系联合回读；不得在任务结构中复制第二套目标宿主或目标特征权威。
4. `BIZ-L4-004-02-02-02 v0.2` 已冻结每个任务的全部当前来源关系和唯一任务目标状态合同引用，但明确不返回来源需求目标正文。
5. `BIZ-L4-002-04-02-01 v0.2` 已冻结 `需求业务服务::读取需求当前父关系与生命周期`：按需求身份、同一非零 `G0`一次读取完整当前需求，结果包含目标宿主、目标特征、`L2目标状态合同身份`、生命周期和结构版本。
6. DATA-EXT-12 最终公开清单已经要求读取单需求并返回完整需求事实；当前生产 `需求结构服务`、`需求业务服务`及最终 DTO / ABI 尚未实现，上述 BIZ 计划仍待激活。
7. DATA-EXT-04 / 03 的目标状态合同、统一特征定义和 I64 目标判断注册读回已实现；对应 `需求目标事实提供者`的 BIZ 设计已发布但代码待激活，属于后继 07 的正文读取能力，不属于本叶。

裁决：不新增 DATA 批量接口。先按 02 全部来源关系稳定去重得到 `D` 个需求身份，再对每个唯一身份恰一次复用既有单需求 BIZ 读取；全部请求共享同一 `G0`，已经足以保证快照一致。任一失败整叶零结果，不需要 DATA 批量原子读。

## 3. 上下游合同

### 3.1 输入 02 完整成功结果

请求必须携带一份 `任务完整承接生命周期读取结果`。它必须满足：

- 状态为 `已读取`，optional 任务材料组有值且非空；
- 结果截止与请求中的共享事实截止均为同一非零 `G0`；
- 02 请求回显、运行代次、事实 / 需求 / 任务范围和目标 / 来源 / 场景 / 生命周期 / 读取规则版本完整；
- 每个任务至少一条当前来源关系，任务与需求端点、身份来源、生命周期、版本和单项 `G0`完整；
- 任务、来源需求和关系排序 / 唯一性已经由 02 证明，本叶仍作防御互证，不接受调用方另传裸需求组。

### 3.2 唯一复用的 BIZ 操作

本叶只复用：

```text
需求业务服务::读取需求当前父关系与生命周期(
    需求身份, 运行代次, G0, 范围/规则版本)
```

对规范化后的每个唯一来源需求恰一次调用。该操作内部才恰一次消费 DATA-EXT-12；本叶不持有 `需求结构服务`、L1、owner、仓库或写端口，不建立第二需求业务服务。

成功结果至少提供：

```text
需求身份及完整身份来源
主体
目标宿主强类型身份
目标特征定义强类型身份
L2目标状态合同身份
需求生命周期
目标结构版本、生命周期版本和单项事实截止G0
```

当前父关系、父端点、来源证据和当前授权仍由下层完整结果拥有；本叶只验证下层成功谓词和共享字段，不复制这些非目标材料到本叶结果。最终精确类型名、字段顺序、状态数值和函数签名待两份上游代码结果发布后机械匹配。

### 3.3 调用次数与预算

从 02 的全部来源关系提取需求身份，按正式稳定身份排序并去重。设唯一需求数为 `D`：

```text
0 < D <= 最大来源需求数量
需求业务服务调用次数 = D
DATA-EXT-13调用次数 = 0
目标合同 / 特征 / 比较注册读取次数 = 0
```

同一来源需求出现在多个任务时只读一次；这是单次函数内的值式去重，不是跨调用缓存。任一读取失败时丢弃局部候选并返回零业务载荷、零事实截止，不发布成功前缀。

## 4. BIZ DTO、物理位置与所有权

新增合同头：

```text
海中鱼巣/领域/任务来源目标事实.数据.h
```

预冻结语义形状：

```cpp
inline constexpr std::uint32_t 候选任务来源需求目标合同版本 = 1;

struct 候选任务来源需求目标固定配置 final {
    std::uint64_t 运行代次;

struct 来源需求目标引用值式事实 final {
    L2需求身份 需求;
    L2节点族身份来源事实 需求身份来源;
    L2存在身份 主体;
    目标宿主强类型身份 目标宿主;
    目标特征强类型身份 目标特征;

enum class 候选任务来源需求目标读取状态 : std::uint8_t {
    已读取 = 1,
    请求拒绝 = 2,
```

精确代码中不得用模板占位强类型；上游最终 ABI 发布后机械匹配。`目标结构版本`和`生命周期版本`只来自每个上游成功结果，逐项互证后投影，不是本叶固定配置或下层请求的预期版本。`主体`仅作为来源需求结构见证保留，不参与后继目标等价键。只有 `已读取`携带有值且非空的 `目标材料组`及非零 `G0`，全部非成功载荷为空、事实截止为零。

## 5. 固定控制顺序与失败映射

```text
校验固定配置和需求业务服务借用
-> 校验合同、02完整结果、G0、运行代次和非零来源需求预算
-> 互证02状态、请求回显、结果截止、optional任务材料、版本和同一G0
-> 遍历逐任务来源关系，互证端点 / 来源 / 当前性 / 版本 / G0并提取需求身份
-> 按需求稳定身份排序去重；空组或坏端点请求拒绝；D超预算返回数量预算不足
-> 对D个需求逐项构造同一G0的需求当前父关系生命周期读取请求
-> 每个唯一需求恰一次调用同一需求业务服务
-> 精确映射非成功；任一失败清除局部候选
-> 逐项互证请求回显、需求身份、成功谓词、G0、身份来源、生命周期和目标三引用
-> 投影并按需求稳定身份保留D项目标引用材料
-> 无抛出交换完整候选并返回已读取
```

| 下层 / 本叶情形 | 本叶状态 | 载荷 |
| --- | --- | --- |
| 固定配置无效 | 内部不一致 | 空；零调用 |
| 坏合同、坏02结果、零G0/预算、空/坏来源关系 | 请求拒绝 | 空；零需求读取 |
| D超出最大来源需求数量 | 数量预算不足 | 空；零需求读取 |
| 请求与固定配置的运行代次或版本不等 | 当前性漂移 | 空；零需求读取 |
| 任一来源需求在同G0未找到或已退出 | 内部不一致 | 空；与02当前任务—来源关系矛盾 |
| 任一读取当前性漂移 | 当前性漂移 | 空 |
| 任一读取提供者拒绝 / 资源失败 | 对应本叶状态 | 空 |
| 合法构造触发下层入口拒绝、未知状态、错身份、错G0或坏成功形状 | 内部不一致 | 空 |
| D项完整成功 | 已读取 | G0和D项稳定目标引用材料组 |

全部分配、复制、累计和排序位于异常收口内。`std::bad_alloc`、`std::length_error`映射资源失败，其它异常映射内部不一致；函数 `noexcept`，禁止终止进程。

## 6. 后继目标等价边界

本叶结果只证明每项来源需求在 `G0` 下的权威目标引用。后继 07 才能：

1. 以每个来源的目标特征和目标合同调用 `需求目标事实提供者::读取目标状态合同与值域定义`；
2. 以入口来源仅作为候选宿主 / 特征初始化见证，并逐任务、逐来源全量互证；
3. 按已冻结的 I64 目标语义材料比较目标宿主、目标特征、完整比较合同、目标 I64、允许关系位和目标状态合同规则版本；
4. 把任务目标合同身份和全部来源合同身份仅作权威引用，不以身份相等替代语义相等。

本叶不得提前实施上述步骤，也不得把第一项来源升级为额外权威。
