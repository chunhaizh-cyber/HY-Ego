## 1. 目标、范围与完成条件

在 `构造普通应用上下文`中建立一条无模块环且生命周期完整的 T02 运行基础设施所有权链：普通应用唯一拥有线程生命周期投影服务、单调时钟适配器、完整秒时钟服务、运行期事实版本服务和唯一自我线程；自我线程后继创建邮箱时立即构造唯一批次路由，并只保存对两个 BIZ provider 的稳定借用。

本计划完成必须同时证明：

```text
I1/I2 DTO完整传递闭包只有一个命名模块所有者
+ 创建.自我线程不再import装配.普通应用
+ 运行代次/时间纪元/线程逻辑身份有唯一进程内签发源
+ 事实范围版本有具名BIZ合同来源
+ 普通应用成员按依赖顺序声明并反向析构
+ 自我线程构造邮箱后先构造路由、再创建物理线程
+ 任一装配失败零半上下文外泄
```

本叶不启动自我线程，不开放治理门，不执行 T02，不冻结邮箱，不读取时间或 DATA，不闭合失败批次停机见证，不实现跨进程恢复。

## 2. 正式依据与当前事实

正式依据为 0050、8100、8110、8120 v0.10，BIZ-L2-001-01 v0.2、BIZ-L3-001-01-01 v0.1、BIZ-L1-T02 v0.2，以及当前时间、事实截止、批次路由和 SELF-THREAD 的正式设计。

当前正式代码事实：

- `普通应用上下文`拥有同一 L1 运行包及六个 DATA-L2 结构服务和一个结构聚合服务，但尚未拥有生命周期、时间、事实版本或自我线程对象；
- `创建.自我线程.ixx`为取得 `自我世界树根消费材料`直接 import `海中鱼巣.装配.普通应用`；普通应用若反向 import 自我线程会形成模块环；
- `自我世界树根消费.数据.h`文本包含 `系统世界树根初始化.数据.h`。只迁移 I2 头会使 I1 类型分别附着于普通应用和新合同模块；
- 线程生命周期投影服务已实现 provider-only；单调时间、完整秒、事实版本和批次路由已有最终设计合同，但最终代码结果并未全部进入正式主线；
- SELF-THREAD 当前有活动代码现场，最终 ABI 尚未发布，故本计划只冻结调用方向并保持待激活。

## 3. 模块环消除与DTO单一所有权

新建：

```text
文件：海中鱼巣/业务/合同.自我世界树根消费.ixx
模块：海中鱼巣.业务.合同.自我世界树根消费
```

该模块唯一 `export {}` 包含：

```text
业务/系统世界树根初始化.数据.h
业务/自我世界树根消费.数据.h
```

之所以同时拥有两组类型，是 I2 头传递包含 I1 头。普通应用删除对两头的 `export include`并 import 共享合同；自我线程删除 import 普通应用并 import 共享合同。不得在第二模块重新 export include 任一头，也不得复制 DTO、改成前置声明不完整类型或让数据头拥有业务函数实现。

共享合同模块只拥有稳定值类型。为使两个现有头中的 `L2结构幂等身份`、场景树请求 / 结果和读回类型具有唯一可见来源，它只允许 import 正式 `海中鱼巣.领域.服务.L2场景结构`作为类型依赖；不得取得或调用服务对象，也不得 import 普通应用、线程、业务编排、日志、SQL 或 L1。I1/I2 函数实现继续归普通应用模块；迁移不改变 I1/I2 请求、结果、状态数值或事实语义。

## 4. 运行身份来源裁决

### 4.1 三个不透明身份

普通应用模块私有命名空间各持有一个独立 `std::atomic<std::uint64_t>`序列：

```text
下一个普通应用运行代次
下一个时间纪元身份
下一个自我线程逻辑身份
```

私有 `分配下一个非零身份(std::atomic<std::uint64_t>&)`使用 CAS 循环：首个返回值为1；每次成功返回当前非零值并把序列推进一；观察到 `UINT64_MAX`返回耗尽且零回绕。并发调用恰一取得每个值，失败构造允许产生跳号但不得回收或复用。三序列是互异身份域；数值偶然相等不表示身份相同。

这些身份只在当前进程内有效。进程重启可以重新从1开始；系统线程 ID、对象地址、墙钟、日志、DATA事实、项目树身份和调用次数均不得替代。跨进程连续身份须由独立恢复合同后继实现。

### 4.2 事实范围版本

新增长期具名常量：

```cpp
inline constexpr std::uint32_t 自我治理事实范围版本 = 1;
```

它标识 T02 当前一致事实请求所覆盖的世界、自我、需求、任务、安全与服务事实字段集合，是 BIZ 合同版本，不是动态身份、事实截止或 DATA 版本。范围字段改变时必须升版；运行时不分配、不递增，也不从任一 provider 结果推导。

`稳态时钟时间源版本`继续由单调时间模块唯一拥有；装配只读取具名常量，不复制数值1为第二权威。

### 4.3 值式材料

模块私有：

```cpp
struct 普通应用运行身份材料 final {
    std::uint64_t 运行代次 = 0;
    std::uint64_t 时间纪元身份 = 0;
    线程逻辑身份 自我线程身份;
    std::uint32_t 事实范围版本 = 自我治理事实范围版本;
};
```

只有四字段完整才可继续装配。材料随普通应用上下文持有并供后继形成请求回显；它不是 DATA 事实，不公开可写 getter。

## 5. 配置、结果与根函数

### 5.1 普通应用配置扩展

`普通应用配置`追加运行基础设施容量字段，默认值必须使用具名常量且位于正式 provider 上限内：

```cpp
std::uint32_t 合同版本 = 普通应用配置合同版本;
std::uint64_t 线程生命周期最大线程数量 = 256;
std::uint64_t 线程生命周期最大消息数量 = 65536;
```

治理邮箱容量、入口停门等待和失败回收诊断仍属于 `自我线程生产创建请求`，不提前混入上下文配置。配置不携带运行身份、时间值、事实截止、owner、DATA服务或 provider 指针。

### 5.2 L3装配结果

模块私有 DTO：

```cpp

struct 自我治理运行上下文候选 final {
    普通应用运行身份材料 运行身份;
    std::unique_ptr<线程生命周期投影服务> 生命周期服务;
    std::unique_ptr<单调时钟适配器> 时间适配器;
```

成功恰一候选且全部指针非空；非成功候选必空。候选本身只用于本模块无抛出移交，不导出。

### 5.3 根函数

```cpp
自我治理运行上下文装配结果 装配自我治理运行上下文(
    const L2结构聚合服务& 结构聚合服务,
    const 普通应用配置& 配置) noexcept;
```

固定顺序：配置准入 -> 分配三身份 -> 构造生命周期服务 -> 单调适配器 -> 完整秒服务 -> 事实版本服务 -> 自我线程 -> 完整候选提交。构造不调用任何 provider 读取函数。`bad_alloc` / `length_error`映射资源失败，其它异常映射内部不一致；具名构造失败优先保留具体状态。

## 6. 最终所有权、借用与构造合同

普通应用成员声明顺序冻结为：

```text
L1运行包
-> 各DATA-L2结构服务
-> L2结构聚合服务
-> 线程生命周期投影服务
-> 单调时钟适配器
-> 完整秒时钟服务（只借用适配器）
-> 运行期事实版本服务（只借用结构聚合）
-> 自我线程（借用生命周期发布端口、完整秒服务、事实版本服务）
```

反向析构时，自我线程必须先锁存停止、唤醒当前关闭治理门并 join 物理线程，销毁尚未被调用的路由和邮箱，随后才允许两个 provider、适配器、生命周期服务和结构聚合析构。所有借用只用引用或不可空指针保存，不采用 `shared_ptr`、全局 singleton 或可换代 service locator。本叶禁止线程入口调用 `自我治理批次路由::冻结当前治理批次`，所以本叶析构不可能阻塞在邮箱冻结等待；该结论不得外推到真实 T02 接线。

`自我线程`目标构造合同：

```cpp
struct 自我线程运行配置 final {
    std::uint64_t 运行代次 = 0;
    std::uint64_t 时间纪元身份 = 0;
    std::uint32_t 时间源版本 = 稳态时钟时间源版本;
    std::uint32_t 事实范围版本 = 自我治理事实范围版本;
    线程逻辑身份 线程身份;
};

自我线程(
    线程生命周期发布端口& 生命周期发布端口,
    const 完整秒时钟服务& 完整秒服务,
    const 运行期事实版本服务& 事实版本服务,
    自我线程运行配置 配置) noexcept;
```

构造只保存稳定借用和值式配置，不创建邮箱或线程。SELF-THREAD 最终 ABI 若把配置并入已有请求或采用等价不可空引用形态，执行前允许机械匹配；不得改变唯一所有权、身份来源或借用方向。

## 7. 邮箱、路由与父处理槽

后继 `创建并使自我线程停在治理运行门`在创建调用序列锁内固定：

```text
校验请求身份等于对象运行配置
-> 构造唯一有界自我治理邮箱
-> 立即以同邮箱、完整秒服务、事实版本服务和同一配置构造唯一自我治理批次路由
-> 确认邮箱冻结计数仍为0
-> 创建物理线程
```

自我线程成员必须先声明邮箱、后声明路由，使路由先析构、邮箱后析构。路由是邮箱唯一冻结消费者；T02 只能调用该路由，不得公开邮箱 getter、provider getter或建立第二路由。父级 `当前治理批次处理槽`由 `RUNTIME-GOVERNANCE-T02-PARENT-REBASELINE`后继代码拥有；父槽非空时零路由调用。

本叶只冻结装配与构造顺序，不实现 T02 处理槽，也不允许线程入口调用路由。后继第一次把 `冻结当前治理批次`接入线程入口前，必须先冻结并实现：停止新输入 -> 正式停止邮箱并唤醒阻塞等待 -> 路由返回 / 排空 -> 双空正常，或形成路由待完成 / 父槽未完成二者互斥的值式退出见证 -> join。该缺口命名为 `DRIFT-T02-PENDING-WITNESS-SHUTDOWN-BOUNDARY-MISSING`，不阻断本叶装配，但硬阻断首个路由调用、治理门开放后的 T02 接线和完整生命周期声明。

## 8. 基础数据服务消费边界

本叶新增 DATA 服务需求为零。唯一 DATA 相关借用是已经构造完成的 `const L2结构聚合服务&`，仅传给 `运行期事实版本服务`构造；本函数不调用 getter 或读取。后继事实版本服务每次经公开聚合与存在服务读取共享截止，合同仍以 `计划/数据服务最终需求清单.md v0.4` 的 DATA-EXT-02 / 07 为准。

不得等待 DATA 实现才形成本计划，也不得在本计划新增 owner、L1入口、缓存、第二截止、恢复账或 DATA验收。

## 10. 验证矩阵与完成边界

- 三序列并发签发唯一、单调、非零；耗尽零回绕；失败允许跳号不复用；
- 配置零值、超上限、坏合同零成员交付；
- 每个成员构造失败独立状态，已构造成员逆序释放，结果候选为空；
- provider 构造期零读取，普通应用成功后引用地址稳定；
- 自我线程先析构并 join，之后 provider / adapter / lifecycle / aggregate 才析构；
- 共享合同模块唯一导出 I1/I2 两头，普通应用与自我线程零重复 export include，最终模块依赖图无环；
- 邮箱构造后路由立即构造且冻结计数为0，物理线程创建之前恰一邮箱 / 路由；本叶生产源码零 `冻结当前治理批次` 调用；
- 根工程 Debug / Release、专项双配置、模块扫描、UTF-8 / XML、strict、生产零专项痕迹。

无法从公开边界确定性触发的原子序列耗尽和真实分配失败保持动态 `NOT_RUN`，用源码静态复核，不新增生产故障 seam。T02 治理循环、实际时间 / 截止读取、运行门开放、失败批次停机见证、系统宿主、业务闭环和跨进程恢复均 `NOT_RUN`。
