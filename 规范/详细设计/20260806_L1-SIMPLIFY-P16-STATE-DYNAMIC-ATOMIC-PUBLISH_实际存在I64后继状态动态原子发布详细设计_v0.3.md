## 1. 目标与唯一修订

P16 仍是 G7 状态/状态变化领域的独立发布入口，只把 P13 后继状态规格和非等价时的 P14 状态迁移动能规格合并为一次 L1 v2 纯值写集。等价分支只发布后状态；非等价分支同一写集发布后状态与迁移动能。固定入口变体4、生产标签 `0x15000603U`、幂等域 `0x10`，不进入因果、生产装配、恢复或第二生产程序。

本版本唯一修订是：P16 在首次成功分支形成公开请求意图，并把 PRE1/PRE2 成功结果中的强类型 provider 证据合并为 `L1执行证据材料`；P16 不计算材料摘要、执行证据摘要或通用读回计划。P15/底层提交服务负责规范化固定字段、材料摘要、最终执行证据摘要、标准通用发布后读回计划、首次账、审计和隔离；提交成功后由状态与状态变化事实所有者分别独立读回。

PRE1（计划 blob `3c14385983bbbadcdbe322c7483625c91e3a378c`）和 PRE2（计划 blob `497375f4131bad0d8cef08775a6c1ab604dac932`）当前只有正式设计合同，不能视为代码能力。P16 v0.3 必须保持待激活，直到两者真实结果分别进入 `main`、经交互接受、接口匹配且代码/验证资源释放。

## 2. 正式依据与上游合同

依据为 4015、4190、4200、4210 及正式 P12 v0.4、P13 v0.2、P14 v0.4、P15 v0.29。4200 §7.6 的请求意图摘要、执行证据摘要、写前事实、通用读回和结果摘要分账由 P15 完成；P16 只提供强类型事实材料，不能把自己的首次结果 DTO当作 L1 材料。

PRE1 `实际存在I64后继状态规格结果` 成功时必须同时有状态规格、迁移证据和 `后继状态规格提供者证据凭证`：固定身份 `0x4C31535000000001`、合同/规则1、直接调用1、provider数量1、最终共同截止、排序唯一写前身份组和一一对应的 `L1事实副本` 组。PRE2 非等价成功时必须同时有 `状态迁移动能规格` 和 `状态迁移动能规格提供者证据凭证`：固定身份 `0x4C31445000000001`、合同/规则1、直接调用1、provider数量1、共同截止、动态登记与 PRE1 传递事实的排序唯一身份/副本组；等价、无前态和所有非成功均无 PRE2 证据。

这些是设计合同，不是当前实现证明。实际 DTO、字段名、排序、来源和截止若与合同不符，执行侧必须返回具名漂移，不得临场适配。

## 3. 身份、请求和同义规则

```text
G7 状态/状态变化
入口变体：4
生产标签：0x15000603U
独立幂等域：0x10
L1 合同：2；请求意图格式：1
```

唯一公开函数保持：

```cpp
状态动态原子发布结果 发布实际存在I64后继状态与迁移动能(
    L1事实基座服务& L1,
    L1实例特征服务& 实例特征,
    L1状态服务& 状态,
    特征比较服务& 比较,
    L1动态服务& 动态,
    const 状态动态原子发布请求& 请求);
```

请求只含合同/规则版本、整理幂等身份和完整后状态规格，不含前状态、动态身份、比较注册/算法、事实截止、L1 局部键、稳定编码、许可、事务或参与者。最终键固定为 `(0x10ULL << 56) | 整理幂等身份`。

请求意图编码复用公共能力且只出现一次标签/变体：

```text
ASCII HZY-L1G7（无长度/NUL）
→ U32(1，大端)
→ U32(0x15000603U，大端)
→ U8(4)
→ P16 公开请求 DTO 全字段（声明顺序、现有字段头、网络大端规则）
→ SHA-256
```

只有全部公开请求字段字节完全相同才是同义。provider 结果、共同截止、PRE1/PRE2 材料、写集、映射、稳定编码、读回和 P15 摘要不参与同义判定。

## 4. 强类型执行证据材料合并

P16 在 P13/P14 成功材料形成后创建一个 `L1执行证据材料`，只填写正式强类型字段，不调用摘要器：

1. `材料版本`、L1 合同版本、摘要合同版本、业务操作标签、最终幂等键和执行模式按当前 P15 DTO 设置；
2. `共同事实截止代次` 必须同时等于 PRE1 共同截止、非等价时 PRE2 共同截止、P13/P14 规格截止以及最终写集所需共同截止；等价分支没有 PRE2 项；
3. `提供者版本组` 合并 P13/PRE1、非等价时 P14/PRE2 的 `直接提供者`、合同版本、规则版本、直接调用次数。另加入本次直接使用的 L1 提供者身份一次，以满足 P15 材料的完整直接调用链。按提供者稳定身份严格升序；同身份合同/规则/次数不一致或重复未合并为内部不一致；
4. `写前事实见证组` 由 PRE1/PRE2 各自成功凭证的身份组与同索引 `L1事实副本` 一一转换而来，按 `(对象种类, 稳定身份)` 升序去重。副本不相等、种类不符、零身份、零截止、数量不等、写集引用缺项均为内部不一致；
5. 每个见证的摘要调用现有公共 `形成L1写前事实摘要`，P16 不复制 SHA-256 或重建事实。P16 不把 PRE1/PRE2 的领域结果 DTO、U64 确定性摘要或局部键直接放入 L1 材料；它们保存在 P16 自有首次证据中，仅供领域读回互证；
6. `规范化写集摘要`、`材料摘要`、`执行证据摘要` 保持零值/未形成，交由 P15 `准备L1写集v2`、`完成L1执行证据` 规范化和计算；`发布后读回计划`保持空值，由 P15 按本次新事实重建；`领域结果见证计划`不提供。

P15 带生产标签入口必须是唯一提交路径。若材料任一必需组为空，P16 不能依赖 P15 默认 L1 身份或首个快照事实补齐，必须在提交前返回内部不一致。

## 5. 首次流程、探测和一次提交

1. 校验公开请求并形成请求意图摘要/最终键。
2. 在任何 P13/P14/provider 前调用 P15 `探测幂等`：同义直接消费首次 P15 结果；异义冲突；隔离/内部不一致非成功；仅未找到继续。
3. 未找到时调用 P13 一次。无前态或 P13 非成功零 P14、零 L1 写；等价分支不调用 P14。
4. 非等价且 P13 成功时调用 P14 一次；必须同时取得 PRE1/PRE2 完整证据、规格截止一致且身份/副本组完整。
5. 机械合并 `0x53` 与合法 `0x44` 写项：等价精确 2 节点/5 值/5 关系/5 槽；非等价精确 3 节点/13 值/11 关系/13 槽；角色 6—8、退出事实为零，角色5引用 `0x53000001`；不重编号、不补字段。
6. 填写领域意图凭证、请求意图摘要、最终键、共同期望代次、纯值写项和第4节强类型执行证据材料；不填写最终执行摘要和通用计划。
7. 恰调用一次 `L1事实基座服务::提交写集(可变请求, 0x15000603U)`。提交成功/精确重复只消费 P15 的首次摘要、首次映射、标准通用读回、结果摘要和代次。

## 6. 成功后独立领域读回

提交成功后，状态所有者按 PRE1/P13 映射形成后状态读取请求并独立读回；非等价时状态变化所有者按 PRE2/P14 映射形成迁移动能读取请求并独立读回。两者必须验证同一非零发布代次、完整字段、角色和输入见证；任一矛盾返回内部不一致，保留 P15 已发布事实与首次证据，不二次提交、补偿或 SQL 裁决。

同义路径不得调用 P13/P14 或提交；只读取 P15 首次结果并重复领域读回。P15 首次账、审计、恢复材料和结果摘要是 L1 权威，P16 首次证据不是第二账。

## 7. 失败、日志和恢复边界

写前 DTO/版本/身份/截止/材料错误为入口拒绝或版本漂移，零写；provider 前幂等冲突/隔离按 P15 状态映射，provider/提交 0/0；PRE1/PRE2 证据半结构、截止不等、身份/副本冲突为内部不一致，零提交；P15 锁内失败保留其失败见证/隔离；发布后领域读回失败保留已发布事实，不二次写。

只使用一个生产程序和正式日志供人读观察；日志不是机器事实、摘要、幂等账或验收升级。当前排除崩溃、重启、断电、跨进程恢复、因果、P82 和生产装配。
