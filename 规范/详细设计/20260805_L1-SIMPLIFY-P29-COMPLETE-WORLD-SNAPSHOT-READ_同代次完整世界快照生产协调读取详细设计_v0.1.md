## 1. 目标与边界

本叶建立 4200 §5 的唯一 `世界树快照读取服务` 生产协调入口。入口不解释 L1 节点、关系和值，不拥有世界、场景、存在、特征、状态或动态事实；它只按固定顺序调用 P19/P21/P17/P24/P22/P25/P26/P27，取得 G1 后调用 P28 纯值组合器，并在第一轮仅因 P28 报告共同截止不等时完整重读一次。

必须同时成立：

- 每轮固定为 `G0 -> 领域读取 -> G1 -> P28组合`，不是先组合再取 G1；
- 任一 provider 非成功立即同类短路，不等待、不 sleep、不继续调用、不消耗漂移重试；
- 只有全部 provider 成功且第一轮 P28 返回 `版本漂移` 时，丢弃整轮全部材料并完整执行第二轮；
- 第二轮成功即返回完整快照，第二轮仍由 P28 返回版本漂移才对外返回版本漂移；
- 每轮 P24—P27 只消费该轮同一份 P17 快照，新旧轮材料绝不混用；
- 正式根单场景、零成员、零槽、零状态、零动态是合法成功，其中零槽时 P22 调用数为0；
- 入口只返回 P28 已冻结的 `完整世界快照组合结果`，不建立第二快照、第二结果状态或第二缺项 DTO。

本叶不设计存在/场景子快照、统一 `世界树业务服务` 门面、比较、动作动态、因果、任务、结算、恢复装配、生产线程接线、SQL、旧 WORLD-TREE 迁移或 STEP-5。

## 6. 单轮固定算法与请求形成

每轮必须严格按以下顺序执行，前一步成功载荷是后一步请求的唯一来源：

1. 以 P19 编译期合同/读取规则常量及公开请求的世界规则和根机械形成 `当前世界结构读取请求`；公开请求的 P28 合同/组合规则不得冒充 P19 版本，随后调用 `L1场景结构服务::读取当前世界结构`，成功事实截止记作 G0；
2. 以 P19 完整事实形成 P21 `当前实际存在集合读取请求`，调用 `L1实际存在服务::读取当前实际存在资格集合`；
3. 以正式 L1 合同版本形成 P17 `L1完整快照读取请求`，调用 `L1事实基座服务::尝试读取完整快照`；该快照只作为不透明值传给 P24—P27，P29 不读取节点、关系或值；
4. 以 P21 事实和构造保存的实例特征定位形成 P24 请求，调用 `L1实例特征服务::从快照读取当前实际存在实例特征槽集合`；
5. 若 P24 槽总数为0，不调用 P22，并以 `登记定位=nullopt` 形成 P25 合法空请求；若槽非空，调用 P22 `L1特征定义服务::尝试读取当前登记` 恰一次，成功完整副本进入 P25 请求；
6. 调用 P25 `从快照读取实例槽引用I64特征定义详情集合`；
7. 以 P24、P25 和同一实例特征定位形成 P26 请求，调用 `从快照读取当前实际存在I64实例特征值集合`；
8. 以 P19、P21、P24 和构造保存的 P9/P14 登记定位形成 P27 请求，调用 `从快照读取当前世界状态动态集合`；
9. 以公开请求根形成 P19 `当前世界事实代次读取请求`，调用 `L1场景结构服务::读取当前事实代次`，成功截止记作 G1；
10. 只有以上全部成功，才把同轮请求、P17 快照、P19/P21/P24/P25/P26/P27 事实和 G1 交给 P28 `组合同代次完整世界事实快照`。

P29 不预先比较各截止、不重新排序、不解析跨域端点；共同截止、范围、完整性、排序与诊断唯一由 P28 裁决。这样不会形成第二套组合逻辑。

## 7. 两轮、短路与材料隔离

固定控制分支不是无界循环：

```text
执行第一轮
-> 任一provider非成功：原类映射返回
-> P28非版本漂移：原样返回
-> P28版本漂移：销毁第一轮全部局部材料
   -> 执行第二轮（从P19 G0重新开始）
   -> 任一provider非成功：映射该非成功返回
   -> P28结果：原样返回；若仍漂移即最终版本漂移
```

禁止只重读 G1、只重读漂移领域、复用第一轮 P17 快照、复用 P22 登记结果、拼接两轮 vector 或在第二轮前 sleep/yield。第一轮 P28 返回内部不一致、许可拒绝、资源失败、未实现或其它非版本漂移状态都不得重试。

单次公开调用的最大调用数：P19结构2、P21 2、P17 2、P24 2、P22每轮按槽空0/非空1且总计至多2、P25 2、P26 2、P27 2、P19 G1 2、P28 2。任一早期失败后，后继调用数和第二轮调用数必须为0。

合法空世界仍要求 P19、P21、P17、P24、P25、P26、P27、G1 和 P28 全链成功；只允许 P22 因零槽跳过。不得把空根、空场景组、缺登记或未找到降级为空成功。

## 8. 异常、并发和读取生命周期

- provider 用结构化结果报告业务失败；若调用抛出 `std::bad_alloc`，P29 返回资源失败；其它未预期异常返回内部不一致；均不进入第二轮；
- P28 自身的结构化结果原样返回；调用 P28 抛出 `std::bad_alloc` 映射资源失败，其它异常映射内部不一致；
- 入口不 `noexcept`，但不传播异常文本、地址或平台错误码到机器结果；
- P29 不取得 L1/领域锁、许可、仓库、事务、会话或令牌；每个 provider 自己管理一次许可生命周期；
- 返回的成功快照永久只代表其非零 `事实截止代次`，函数返回后世界可以继续推进；P29 不提供“当前仍未变化”保证；
- 并发调用互不共享轮次材料；provider 竞争产生许可拒绝时立即返回，不由 P29 排队或重试。
