# 按 I64 时间范围读取当前动态组详细设计 v0.1

日期：2026-08-16

设计身份：`DATA-L2-DYNAMIC-CURRENT-GROUP-READ-BY-I64-TIME-RANGE`

状态：设计就绪；不等于代码已实现

## 1. 目标与当前缺口

在唯一 `L2动态结构服务` 增加一个当前组读取入口：调用方提交同一 L1 的非零事实代次守卫、I64 查询闭区间、每端候选数量预算和返回数量预算，服务返回起始、结束时间当前材料均为 `std::int64_t`且与查询区间相交的全部当前完整动态。

现行服务已经具备：

- 唯一动态 owner、唯一写端口和正式动态结构类型登记；
- 互异的起始 / 结束 I64、I64 组、U64 组和独立材料类型；
- 当前 / 历史完整动态读取、身份来源读取；
- 按主体、前状态、后状态和来源读取有界当前动态组；
- L1 owner + 属性类型节点 + 非零事实代次 + 数量预算的原子当前值组入口。

因此本叶不新增 L1 能力、第二索引或第二动态服务。具名缺口为：

`DRIFT-DATA-L2-DYNAMIC-I64-TIME-RANGE-CURRENT-GROUP-READ-MISSING`

## 2. 结构语义与中性边界

1. 本入口只读取当前动态，读取类别固定为当前，不增加历史范围查询。
2. 只有起始材料类型精确等于登记中的 `L2动态起始I64值类型身份`、结束材料类型精确等于 `L2动态结束I64值类型身份`，且两项材料均为 `std::int64_t`的动态参与。
3. 查询范围固定为闭区间 `[最小时间I64, 最大时间I64]`，请求只要求最小值不大于最大值；负值、零值和整数边界没有额外业务禁令。
4. 命中谓词固定为：

```text
动态起始I64 <= 最大时间I64
且
动态结束I64 >= 最小时间I64
```

这是两个公开结构字段与查询闭区间的机械相交谓词，不授权 DATA 判断发生时间是否真实、时间单位或纪元是否正确。
5. 4230 明确动态结构不要求起始时间早于结束时间。因此本入口不得把 `动态起始I64 > 动态结束I64`映射为入口拒绝或内部不一致，也不得偷偷交换两值；仍只按上述两个不等式机械判断。
6. 任一端使用 I64 组、U64 组或独立材料引用时，该动态不参与本入口，也不因此报错。两端材料类型的其它组合由后继具名查询承接，不能在本叶建立四类材料统一排序。
7. 输出按 `L2动态身份.值`严格升序，不按起始值、结束值或属性值编码排序；空组表示该截止没有匹配动态，是成功结果。
8. 本入口不比较前后状态、不判断是否发生变化、不解释来源或动作，也不形成因果、需求或任务。

## 3. 精确公开 ABI

DTO 物理所有者：`海中鱼巣/领域/L2动态结构.数据.h`。

```cpp
struct L2按I64时间范围当前动态读取请求 final {
    L2结构请求头 请求头;
    std::int64_t 最小时间I64 = 0;
    std::int64_t 最大时间I64 = 0;
    std::uint64_t 最大候选数量 = 0;
    std::uint64_t 最大返回数量 = 0;
    friend bool operator==(
        const L2按I64时间范围当前动态读取请求&,
        const L2按I64时间范围当前动态读取请求&) = default;
};
```

同一 DTO 所有者新增纯值 helper：

```cpp
bool L2按I64时间范围当前动态读取请求有效(
    const L2按I64时间范围当前动态读取请求& 请求) noexcept;
```

有效条件固定为：`L2结构请求头合同有效`、期望事实代次非零、`最小时间I64 <= 最大时间I64`、两个预算均非零。`最大候选数量`独立约束起始 I64 当前值组和结束 I64 当前值组中的每一组；两个预算不要求大小关系。

结果复用现有 `L2当前动态组读取结果`。服务公开入口位于 `海中鱼巣/领域/服务.L2动态结构.ixx`：

```cpp
L2当前动态组读取结果 按I64时间范围读取全部当前动态(
    const L2按I64时间范围当前动态读取请求& 请求) const;
```

不修改 `L2结构聚合服务`、普通应用、世界树聚合或生产工程；现有动态服务 getter 已是唯一公开实例入口。

## 4. 双端候选发现与预算

服务先读取并验证当前动态结构类型登记，取得正式起始 / 结束 I64 属性类型。随后用同一 owner、同一非零请求守卫和同一个 `最大候选数量`分别调用两次：

```cpp
L1事实基座服务::按属性类型读取所有者范围全部当前值({
    L1所有者范围属性类型当前值组读取合同版本,
    动态身份来源定位_.所有者,
    登记.起始I64值类型.值,
    请求.请求头.期望事实代次,
    请求.最大候选数量});

L1事实基座服务::按属性类型读取所有者范围全部当前值({
    L1所有者范围属性类型当前值组读取合同版本,
    动态身份来源定位_.所有者,
    登记.结束I64值类型.值,
    请求.请求头.期望事实代次,
    请求.最大候选数量});
```

任一端全部当前 I64 值超过预算时，L1 整组拒绝，L2 返回 `数量预算不足`和空动态组。即使另一端为空或最终相交结果为空，也不得截断某端候选后猜成功。

每份 L1 成功组必须逐项互证：值编码、所属动态和来源节点非零；owner、属性类型精确匹配；创建代次覆盖请求截止且当前；材料替代项精确为 `std::int64_t`；原组按值稳定编码严格升序。坏形状统一为 `内部不一致`。

服务把两端候选转换为值式 `{动态编码, 值编码, I64材料}`，分别按动态编码排序；同一端同一动态重复是内部不一致。只有两端都存在 I64 候选的动态才进入相交判断；只有一端为 I64 是合法不命中，不得作为坏结构。

命中数超过 `最大返回数量`时返回 `数量预算不足`和空组。两个候选组、筛选中间项和最终组都不得返回分页、截断标志或下一页令牌。

## 5. 同截止完整读回

候选预算与相交筛选完成后，服务按动态身份升序逐项调用现有：

```cpp
读取完整动态({请求.请求头, L2读取类别::当前,
    L2动态身份{动态编码}, 0});
```

每项必须满足：

1. 结果为 `已读取`、事实截止等于请求守卫、无变更代次；
2. 动态身份等于候选动态编码，生命周期当前；
3. `L2动态事实完整(...)`在同一截止成立；
4. 起始 / 结束属性类型分别等于登记中的两项 I64 类型；
5. 两个时间值编码和 I64 材料分别与 L1 候选完全相同；
6. 两个材料仍满足公开相交谓词。

单项发生事实代次漂移或资源失败时保留该状态并返回空组；其它未找到、已退出、入口拒绝、错载荷、混代或互证失败统一为内部不一致。全部单项完成后才形成最终 `已读取`结果，不公开部分组。

## 6. 状态映射

| 条件 | L2 状态 | 截止 | 动态组 |
| --- | --- | --- | --- |
| 请求 helper 失败 | 入口拒绝 | 0 | 空 |
| 任一 L1 候选读事实代次漂移 | 事实代次漂移 | L1 锁内当前代次 | 空 |
| 任一端候选预算不足 | 数量预算不足 | 请求守卫 | 空 |
| 区间命中数超过返回预算 | 数量预算不足 | 请求守卫 | 空 |
| L1 或完整读回资源失败 | 资源失败 | 安全取得则保留 | 空 |
| 动态登记读取返回登记未加载 / 入口拒绝 / 许可拒绝 / 漂移 / 资源失败 | 复用现有登记失败映射 | 安全取得则保留 | 空 |
| 登记已成功后，L1 私有 owner / 属性类型未找到、已退出、入口拒绝或坏形状 | 内部不一致 | 安全取得则保留 | 空 |
| 候选、材料、重复角色、生命周期、排序或完整动态不能互证 | 内部不一致 | 请求守卫 | 空 |
| 0—预算项全部同截止闭合 | 已读取 | 等于请求守卫 | 身份严格升序完整组 |

登记中的 owner 与两项 I64 类型是服务私有永久结构前置，不是调用方查询对象。因此 L1 对它们返回未找到、已退出或入口拒绝时不能映射为合法空组。

## 8. 验证与完成边界

生产外临时检查至少覆盖：坏合同、零守卫、逆序查询范围、两个零预算；空组；查询边界和点区间；左交、右交、动态包含查询、查询包含动态及两侧不相交；相同区间多动态；输出按身份排序；任一端非 I64 不参与；逆序动态不被 DATA 拒绝且只按谓词判断；任一端候选预算精确 / 少一；区间外候选仍计预算；返回预算精确 / 少一；陈旧守卫；起始 / 结束值换代；动态退出；逐字段互证；既有主体 / 前状态 / 后状态 / 来源 / 身份来源 / 完整动态读取保持；读取前后事实代次不推进。

真实资源耗尽、私有登记 / 索引 / 动态损坏、共享锁长期公平、极端并发调度、跨进程恢复和正式 BIZ 消费没有稳定合法注入时记 `NOT_RUN`，不得增加生产故障 seam。

本设计完成只冻结当前动态的双端 I64 时间值闭区间相交读取。它不证明其它起止材料类型组合具有统一排序，不证明历史时间范围、`DATA-EXT-05`整项、`DATA-EXT-06—14`或数据服务最终需求清单整体完成。
