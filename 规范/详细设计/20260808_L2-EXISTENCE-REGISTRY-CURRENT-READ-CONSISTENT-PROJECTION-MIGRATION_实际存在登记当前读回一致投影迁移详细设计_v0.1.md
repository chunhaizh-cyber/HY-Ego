## 4. 冻结目标函数、请求与数据所有权

唯一目标根保持现有私有签名和物理位置：

```cpp
// 海中鱼巣/领域/服务.L1实际存在.ixx
实际存在登记结果 L1实际存在服务::按登记读取权威事实(
    const 实际存在结构登记& 定位,
    std::optional<std::uint64_t> 期望创建代次 = std::nullopt) const;
```

定位由实际存在服务的登记写入结果和服务内定位缓存拥有。L1 唯一拥有事实代次、共享许可和中性当前事实；实际存在服务唯一解释服务身份、资格属性类型、首次幂等身份和创建代次。函数只返回调用方拥有的 `实际存在登记结果`，非成功不带部分登记。

在定位完整性校验通过后，每轮形成唯一请求：

```cpp
L1中性一致当前读取请求 一致请求;
一致请求.合同版本 = L1中性一致当前读取合同版本;
一致请求.期望事实代次 = 本轮期望代次;
一致请求.节点 = {定位.服务身份, 定位.实际存在资格属性类型};
一致请求.关系 = {};
一致请求.值 = {};
一致请求.属性值 = {};
一致请求.源关系组 = {};
一致请求.目标关系组 = {};
```

固定六组形状为 `2/0/0/0/0/0`。禁止为证明关系、值或属性读取而增加业务不需要的选择项。

可在 `海中鱼巣::L1实际存在内部` 新增目标专用的顶层失败状态映射、项目失败状态映射和失败形状校验 helper；全部中文命名、纯值、最小可见性。既有 `映射读取状态(L1中性读取状态)` 继续供资格读取使用，不得改义或删除。

## 5. 唯一控制流与完整重试边界

1. `实际存在结构登记完整(定位)` 不成立，立即返回 `内部不一致`，零一致投影调用。
2. 首轮期望代次唯一取 `定位.事实截止代次`。该值是登记首次创建时或调用方上一轮取得的权威截止定位，不是身份版本。
3. 每轮形成第 4 节 `2/0/0/0/0/0` 请求，物理调用 `尝试读取中性一致当前投影` 恰一个调用点。
4. 首轮返回合法事实代次漂移时，丢弃全部本轮材料，以回显非零实际代次作为第二轮期望代次，完整重做一次请求。
5. 第二轮仍漂移，返回 `实际存在状态::版本漂移`；最多两次完整尝试，不得第三次调用、无限循环、等待或 `sleep`。
6. 允许一次完整重试的原因：定位只保存登记身份和较早事实截止，不组合其它领域的旧截止材料；后继消费者写入推进事实代次后，登记仍可在新共同截止按相同两编码完整重读。该边界不同于初始场景把本轮世界登记截止作为跨服务输入时禁止局部重试的合同。
7. 许可拒绝立即返回 `许可拒绝`，不等待、不重试；资源失败保持资源失败；入口拒绝、内部不一致和坏顶层失败形状返回内部不一致。
8. 成功只接受合同正确、期望代次回显精确、读取代次等于本轮期望且非零、六组长度精确为 `2/0/0/0/0/0` 的完整结果。
9. 通过第 6 节业务形状验证后，复制定位并把 `事实截止代次` 更新为顶层读取代次，返回 `已读取`。

## 6. 成功结果的业务形状验证

### 6.1 两个节点项目

按请求顺序固定解释：

1. 服务身份节点；
2. 实际存在资格属性类型节点。

两项都必须满足查询编码与事实编码等于对应定位编码、项目状态成功且事实存在、未退出、创建事实代次非零且不晚于读取代次、当前属性为空。

服务身份节点额外要求：

- 节点种类为普通；
- 无属性类型表示。

资格属性类型节点额外要求：

- 节点种类为属性类型；
- 属性类型表示精确为 `L1中性值表示种类::I64`。

两个节点创建事实代次必须相等。若 `期望创建代次` 有值，共同创建代次必须精确等于该值；这保持 `建立登记` 写后读回合同，不把后继当前截止误作创建代次。

### 6.2 项目失败与坏成功

- 任一节点项目 `未找到` 且其余项目不存在内部错误，返回 `未找到`；
- `已退出`、`种类不匹配`、`属性未设置`、成功无事实、非成功带事实、顺序或字段矛盾，返回 `内部不一致`；
- 多项目同时非成功时，内部错误优先于未找到，禁止用一个未找到掩盖另一个坏项目；
- 顶层成功但合同、代次、长度、顺序、项目状态或业务字段任一矛盾属于坏成功，返回内部不一致。

不得挑选部分项目、重新排序、调用旧入口补齐或返回部分登记。
