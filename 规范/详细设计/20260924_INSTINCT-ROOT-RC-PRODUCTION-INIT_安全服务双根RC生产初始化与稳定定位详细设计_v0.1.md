版本：v0.7

## 1. 目标和完成边界

本设计闭合完整 G4-A 之前最早能够独立施工的生产提供者：在普通应用构造期、双根先天 FT 与完整域 FC 已经完成以后，建立或恢复一份通用存在概念 EC，并分别为安全根、服务根建立或恢复目标判断 K 与正差距 RC，最终在共同非零截止返回不可变值式交付。

本设计只证明以下事实：

1. 安全值、服务值各有自己的正式 FT、完整域 FC、目标判断 K 和 `D_POS` 原子 RC；
2. 两根共享同一份已正式发布、可完整读回的 `不预设特征` 通用 EC；
3. K 与 RC 都由现有唯一 owner 发布，不建立第二仓库、第二 owner 或固定节点编码；
4. 普通应用在世界树实例和 SELF-FORM 之前取得按根角色区分的完整读回交付；
5. SELF-FORM 后续仍按精确定义查询并复用同一通用 EC，不改变其真实自我形成语义。

本设计不实现：RC 调用期求值、目标常量进入 4242 求值来源、G4-A 双根复核 provider、根治理意图 sink、任务管理线程、治理门开放、消息循环或完整自我治理闭环。不得用本提供者的成功替代这些后继门禁。

## 2. 正式依据和已验证事实

### 2.1 正式语义

- 6130 v0.17 固定安全值和服务值均为先天 I64 FT，值域为 `[0,I64_MAX]`，目标均为 `I64_MAX`。
- 6130 第3节固定目标判断 K 的单位、维度、分量角色三个稳定身份均分别使用对应根 FT 身份；禁止另建辅助节点或填入猜测编码。
- 6130 固定 `Δ=M-当前值`；合法根值只产生正差距或零，不产生方向相反。负值、坏类型、坏目标或公式不一致是技术非成功。
- 7180 与 4242 固定 RC 是独立概念身份；原子 RC 至少具有 D、FC、EC、K 和差异输出。
- 4242 固定调用期物理左为 B、右为 A，差异为 `A-B`。因此本根定义中 A 表示目标值，B 表示当前事实。
- 4242 固定 `D_POS=4`，原子两侧均必须受正式 FC 与 EC 约束；本版输出只允许差异。
- 8121 只禁止阶段21创建二次概念。本提供者位于普通应用构造期，不进入阶段21。
- 8120 与当前 SELF-FORM 均要求先精确查询通用 EC、缺失时才创建；提前形成同一定义后，SELF-FORM 会复用，不改变唯一自我语义。

### 2.2 当前可复用能力

| 能力 | 现有入口 | 本设计用途 |
| --- | --- | --- |
| 双根 FT/完整域 FC 初始化 | `本能先天特征概念初始化提供者::初始化` | 提供两根正式 FT 与完整域 FC |
| 纯概念查找/恢复/创建/读取 | `概念树类数据服务` 的 pure v2 入口 | 建立或恢复通用 EC |
| K 建立与读取 | `特征类数据服务::建立I64比较绑定`、`读取I64比较绑定`、`读取当前I64比较绑定` | 建立两根唯一目标判断 K |
| RC 规范化、查找、建立、收敛、读取 | `概念树类数据服务` 的 RC-P1 入口 | 建立两根正差距 RC |
| RC 结构 owner | `初始化二次关系结构` 与唯一概念 owner | 保持单 owner |
| 普通应用装配 | `构造普通应用上下文` | 生产构造、缓存值式交付和失败分流 |

当前 `概念树类数据服务::精确查询纯概念` 仍把 pure v2 概念族锚点下的每个成员都直接交给 `读取纯概念内部`。4242 已明确 RC 复用同一概念族成员、不可变类别、`定义成员`、生命周期和直接上位关系，但 RC 定义记录使用自己的 `定义种类`，不是 pure v2 的 `定义种类`。因此首轮 RC 发布以后，再次查询通用 EC 会把 RC 当作 pure v2 定义解码并返回 `内部不一致`。这是同一概念 owner 内的候选格式过滤缺口，不是 RC 非法进入概念族，也不能由 provider 访问 L1、缓存 EC 身份、换键或跳过精确查重来规避。

执行侧完成上述 `精确查询纯概念` 修复后，五模式生产消费专项仍证明 `stage-first` 与 `stage-recover` 在阶段21返回完整锚点前失败。当前 `特征概念应用服务::确保FCv` 在单值 FC 尚未存在时会调用 `概念树类数据服务::读取当前I64特征概念`，而该读取入口仍把 pure v2 概念族全部成员无条件交给 `读取纯概念内部`；普通应用构造期已经发布的合法 RC 因而仍会被误作 pure v2 定义解码。这是 v0.3 同一 owner 候选过滤裁决遗漏的第二个消费入口，不改变 RC 或 pure v2 的机器语义。`ordinary` 与 `headless` 都依赖同一阶段21前置链，当前失败只证明前置阶段21尚未通过；8120 已规定阶段21失败不得被控制面板阶段12覆盖，也不得进入无窗口常驻成功，因此在 owner 缺口修复并复验前不扩大宿主代码范围。

现行 `概念树类数据服务::读取二次关系概念` 已完整读回事实中的真实治理状态，却无条件把结果状态设置为`已读取`。4242 与 `二次关系概念读取结果::成功()` 均要求读取状态和事实生命周期严格对应：活跃为`已读取`、冷却为`冷却命中`、退役为`退役命中`。因此 RC 冷却或退役后的身份读回虽然事实完整，结果成功谓词仍失败。provider 必须继续服从公开成功谓词，不能把事实字段自行改写为成功或绕过状态检查；该缺口只能由同一概念 owner 修正状态投影。

既有 `验证工具/世界树根启动专项验证.cpp` 的实例特征结构夹具仍提交版本 1 和旧键 `0x4946525354525543`；现行 `实例特征结构登记请求` 默认/唯一生产版本为 2，`登记实例特征结构` 明确只接受版本 2 和键 `0x4946525354525632`，同时保留旧键仅用于内部读取并迁移既有 v1 首次材料。该专项在 `existence-instance-feature-layout` 的失败发生于 RC provider 进入前，是测试夹具漂移，不是 RC-P1 生产逻辑失败。验证入口仍有价值，不得删除、跳过或用另一个工程替代；应只把夹具请求更新为现行 v2 版本/键。

当前不存在 `业务/计算.二次关系求值.h/.cpp` 和 `业务/应用服务.二次关系概念类.h/.cpp`。本初始化器不冒充这两项后继能力，也不通过临时数值计算证明 RC 成立。



## 4. 公开DTO和接口

### 4.1 请求、状态和交付

在新头文件声明：

```cpp
inline constexpr std::uint32_t 本能双根二次关系概念初始化合同版本 = 1;

enum class 本能双根二次关系概念初始化状态 : std::uint8_t {
    已形成=1, 已恢复=2, 入口拒绝=3, 初始化交付不完整=4,
    通用存在概念失败=5, 比较绑定失败=6, 二次关系概念失败=7,
    当前性漂移=8, 幂等冲突=9, 引用冲突=10,
    类型或概念已退出=11, 数量预算不足=12, 历史材料不可用=13,
    已可能发布=14, 资源失败=15, 内部不一致=16

    概念树预算 纯概念预算;

struct 本能根二次关系概念交付 final {
    本能值角色 角色=本能值角色::安全值;
    先天I64特征概念交付 先天;
    纯概念事实 通用存在概念;
    特征I64比较绑定事实 目标判断K;
    二次关系概念事实 正差距RC;

struct 本能双根二次关系概念初始化结果 final {
    std::uint32_t 版本=1;
    本能双根二次关系概念初始化状态 状态=
        本能双根二次关系概念初始化状态::入口拒绝;

class 本能双根二次关系概念初始化提供者 final {
```

允许实现以引用成员保存同一普通应用上下文中的两项服务；类不可默认构造、复制或移动。

构造函数保持 `noexcept`，不访问仓库。`初始化()` 的首项装配核验固定使用现有公开面：

```cpp
const auto& l1 = 概念服务_.原子I64底座();
特征服务_.绑定于(l1) && 概念服务_.绑定于(l1)
```

不得调用 `特征类数据服务` 的私有 `原子I64底座()`，也不得为本计划增加“使用特征服务”公开谓词。普通应用只有一份特征服务实例、概念服务构造时已经核验并借用该实例且两服务均绑定上述同一 L1；这三项共同构成本计划的同上下文证明。装配核验失败返回 `入口拒绝` 且零写。

### 4.2 成功谓词

成功只接受 `已形成` 或 `已恢复`，并同时满足：

- 原请求版本、G0、预算和先天交付完整；
- 安全根、服务根交付均存在且角色不交叉；
- 两交付 `Gread` 与结果 `Gread` 相同且非零；
- 两根 FT、FC、K、RC 两两分立；通用 EC 身份完全相同；
- 通用 EC 处于活跃或冷却且定义完整；退役不得成功；
- K 的 FT、用途、左右角色、算法、量化和唯一差异输出与第5节完全相同；
- RC 处于活跃或冷却、定义完整的 `D_POS` 原子概念，且引用对应根 K/FC 与共同 EC；退役不得成功；
- 非成功清空两根交付，不得保留可被消费为成功的半结果。

### 4.3 生产预算

新头文件声明、普通应用直接使用以下具名常量构造初始化请求。纯概念预算是每次 pure 公开调用的独立硬上限；K 读取预算与扫描上限只约束 `读取当前I64比较绑定` 和 `读取I64比较绑定`；RC 预算是每次 RC 公开调用的独立硬上限。这些预算都不是整个 provider 调用的累计共享余额，也不是无限预算，不得由执行者临场缩放：

```cpp
inline constexpr 概念树预算 本能双根RC纯概念预算{
    1024,8192,1024,1024,1024,1024,1024,1024};
inline constexpr 有界事实读取预算_B1 本能双根RCK读取预算{
    4096,4096,4096,8192};
inline constexpr std::uint64_t 本能双根RCK最大扫描候选数量 = 1024;
inline constexpr 二次关系预算 本能双根RC二次关系预算{
    16384,16384,16384,32768,1024,1024,64,1024,1024,1024,32768};
```

请求中的三组预算必须逐字段等于这些具名常量；0 不解释为无限。同一初始化调用内，`精确查询纯概念`、`读取纯概念创建首次结果`、`创建或复用纯概念` 和 `读取纯概念` 每次都接收完整纯概念预算；`查找二次关系完整定义`、`建立二次关系概念`、`收敛二次关系概念建立` 和 `读取二次关系概念` 每次都接收完整 RC 预算；`读取当前I64比较绑定` 每次接收完整 K 读取预算及扫描上限，`读取I64比较绑定` 每次接收完整 K 读取预算。

`建立I64比较绑定` 及以其完整 `建立原请求` 进行的重放是 4182 v0.3 与现行 K owner 冻结的无预算写入口：调用者不得向 `特征I64比较绑定建立请求` 增加读取预算字段，不得在外层包装第二套写预算，也不得把 K 读取预算解释为 K 写预算。该写入口每次返回结果的 `读取用量` 按现行合同保持四项全零；内部 owner 核验不由本 provider 重新计量。provider 不跨公开调用累计或抵扣任何预算，也不把一次调用的未用余额转给下一次。专项需要分别构造 pure、K 读取和 RC 的不足预算验证，并验证 K 建立与原请求重放保持无预算请求及零读取用量；生产装配不得动态降低预算或在失败后扩大重试。

## 5. 固定定义

### 5.1 通用EC

通用 EC 定义固定为：

```text
类别：存在
规则版本：1
规则：不预设特征
组织：显式顶层
直接上位：空
```

创建键复用 SELF-FORM 已冻结的 `0x3001`。初始化器先精确查询；查询命中时零写复用。仅确认未找到时读取该键首次材料并按 pure v2 恢复或创建。SELF-FORM 后续仍先查询，不会因同一 EC 已存在而新建第二身份。

### 5.2 每根K

安全根与服务根分别形成一份定义：

```text
输入FT：对应先天FT
用途：目标判断
算法族：标量有序比较与安全差异
算法版本：1
左角色：当前事实
右角色：目标值
上下文要求：无
误差合同版本：1
误差预算：空
相等容差：空
关系编码：空
输出：恰一项“差异”
输出FT：对应先天FT
```

输入和差异输出量化均固定为：

```text
单位=对应FT身份
维度=对应FT身份
分量角色=对应FT身份
缩放=1/1
下界=0
上界=I64_MAX
量纲=无量纲
舍入=不转换
溢出=拒绝
```

该输出范围对本根固定 `目标=I64_MAX` 与合法当前值 `[0,I64_MAX]` 完整，因为结果只能位于 `[0,I64_MAX]`。不得把此 K 泛化为任意目标常量的已证明路线。

K 固定业务幂等身份必须互不相同：

```text
安全K：0x4952'4B53'4146'0001
服务K：0x4952'4B53'5256'0001
```

这些数值只作为所有者范围写入幂等身份，不是 K 节点编码。

### 5.3 每根RC

每根 RC 固定为一个原子定义：

```text
D=4（D_POS）
输出=差异
K=对应根目标判断K
共同FC=对应根完整域FC
共同EC=通用EC
组织=显式顶层
父组=空
形成来源=空
```

物理求值约定为左 B、右 A，因此后继只能把 A 绑定为目标材料、B 绑定为当前事实，取得 `A-B=M-current`。本计划不实现这一后继来源适配。

RC 固定业务幂等身份必须互不相同：

```text
安全RC：0x4952'5243'5341'4601
服务RC：0x4952'5243'5352'5601
```

同样只作为写入幂等身份，不是概念编码。

## 6. 初始化、恢复和共同截止读回

### 6.1 入口核验

初始化器先核验：

1. 版本、G0 和全部预算有效；
2. 先天交付成功且 Gread=G0；
3. 安全、服务角色正确，FT 和 FC 均不同；
4. 两 FT 均为先天来源、单位绑定读回为各自 FT、缩放 1/1、允许集合恰为 `[0,I64_MAX]`；
5. 两 FC 均是对应 FT 的 pure v2 完整域、显式顶层、当前可用；
6. 按第4.1节公开核验式证明特征服务与概念服务绑定同一 L1；同一普通应用上下文由唯一装配实例保证，不增加新 ABI。

任一入口失败零写。

### 6.2 通用EC收敛

固定当前截止，先精确查询完整定义。只有命中活跃或冷却、显式顶层且父组为空的精确事实时才复用；退役映射 `类型或概念已退出`。确认未找到时：

1. 调用 `读取纯概念创建首次结果` 检查固定键；
2. 首次已发布时按首次实际 G0 取得完整事实；
3. 确认未派发时以当前真实 G 建立；
4. 发布未知只保留原完整请求；本次能收敛则按 pure v2 恢复，不能证明则返回 `已可能发布`；
5. 不另建恢复表或第二 key。

为使上述公开路径在 RC 已经存在后仍成立，本计划同时修正唯一概念 owner 的 `精确查询纯概念` 候选过滤，不新增 ABI：枚举到的每条概念族成员关系仍须角色为 1；每个成员先读取并核验恰一条 pure v2 `定义成员`关系，再检查该定义记录是否具有 pure v2 自己的`定义种类`属性。恰一项才作为 pure v2 候选调用 `读取纯概念内部`并参与定义比较；多项直接返回`内部不一致`。零项不能直接解释为独立扩展，只有 `secondary_relation_layout_` 已存在，并且该概念节点在同一 `Gread/H` 下恰有一条当前 `secondary_relation_layout_->类型.规范化规则归属` 关系、角色为 1、目标严格等于 `secondary_relation_layout_->规范化规则.值` 时，才证明它是当前已知合法 RC 候选并跳过；零条、多条、错角色、错目标、布局缺失或读取失败均返回`内部不一致`。坏成员关系或已经具有 pure v2 判别项但完整 pure 结构错误同样保持`内部不一致`，不得把损坏的 pure 概念静默当作扩展跳过。过滤读取继续服从本次截止和现有数量预算，不改变 RC 物理结构、概念族成员关系、定义、身份、owner、预算 DTO 或写入事务。

`读取当前I64特征概念` 必须在调用 `读取纯概念内部` 前复用完全相同的格式判别和 RC 合法跳过规则：成员角色、唯一 `定义成员`、定义记录种类、pure v2 `定义种类`计数、RC `规范化规则归属`见证及失败边界与上一段一致。恰一项 pure v2 `定义种类`才进入既有完整 pure 读取及 FT 过滤；零项且 RC 见证完整时跳过；其它情况均返回`内部不一致`。不得只因目标 FT 不匹配而跳过格式核验，也不得把 RC、未知扩展或损坏成员计入返回概念组。该修复只扩展同一 `概念树类数据服务` 私有读取过程，不新增 DTO、公开 ABI、预算字段、关系、owner 或写入。

provider 不得以固定首次键、进程缓存、普通应用上下文旧值或 RC 枚举代替精确查询：固定首次键不能证明其它调用方以不同键预建的同义通用 EC 不存在，RC 入口也不提供通用 EC 的定义查重。owner 修复完成后，首次、同进程重复和跨进程恢复均继续走同一 `精确查询纯概念` 公开入口。

### 6.3 K收敛

每根先按 `FT+目标判断` 读取唯一当前 K：

- 唯一命中且完整定义相同：零写复用；
- 唯一命中但定义不同：`引用冲突`；
- 注册不唯一：`内部不一致`；
- 确认未找到：使用本根固定键和当前真实 G 调用无预算写入口 `建立I64比较绑定`；不得向建立请求补读取预算字段；
- 建立返回已可能发布且携带 `建立原请求`：本调用必须先以该完整原请求再次调用无预算写入口 `建立I64比较绑定`，让现有 K owner 读取首次材料并收敛；两次 K 写结果的 `读取用量` 都必须为零。收敛仍为已可能发布时，再以最新真实截止和具名 K 读取预算、扫描上限重新读取当前路由。只有唯一路由已经完整读回同一定义时才能继续，否则保持 `已可能发布`；不得用新的 G 改造原请求；
- 建立返回已可能发布但没有完整 `建立原请求`：直接保持 `已可能发布`，不得猜测原 G、换键或构造第二恢复账；
- 跨进程恢复先读取当前路由。原子提交若已成立必能读到完整 K；若首次材料存在但当前 K 仍不可完整读回，不得换键或猜原 G，返回 `已可能发布/内部不一致`。

本节所有当前路由读取使用具名 K 读取预算与扫描上限；所有身份读取使用具名 K 读取预算。读取结果必须按现行用量合同核验；建立和原请求重放只核验无预算请求形状、零 `读取用量`、完整定义和正式回执。

### 6.4 RC收敛

每根先按完整定义调用 `查找二次关系完整定义`：

- 唯一命中同义 RC：零写复用；
- 确认同义缺失：以固定键和当前真实 G 建立；
- 建立返回发布未知且携带 `建立原请求`：本调用按原请求调用 `收敛二次关系概念建立`；
- 收敛确认无首次记录：在新的真实 G 重新完成查找后，才允许用尚未绑定的同一固定键建立；
- 跨进程先按完整定义查找；已发布 RC 直接复用，不能为恢复读取 owner 私口、建立恢复账或换键。

RC 定义可不带形成来源；本提供者只发布系统概念定义，不宣称任何具体 A/B 实例关系已经发生。

### 6.5 最终读回

两根前缀完成后冻结 `Gfinal`，在同一截止执行：

1. 以 `Gread=H=Gfinal` 读回通用 EC；
2. 以具名 K 读取预算分别按身份读回安全 K、服务 K，并以同一读取预算和具名扫描上限分别按 `FT+用途` 读回当前路由，必须命中同一 K；
3. 以具名 RC 预算分别按身份读回安全 RC、服务 RC；
4. 分别调用现行 `读取I64基础特征类型事实` 与携带具名纯概念预算的 `读取纯概念`，以 `Gread=H=Gfinal` 重新读回两根 FT 与 FC 的当前完整事实；
5. 核对完整定义、生命周期、角色、交叉隔离和共同截止；
6. 最后一项读回后再核对当前代次仍为 `Gfinal`。

只有本调用真实形成新的 EC、K 或 RC 权威发布时返回 `已形成`；精确重复、首次材料恢复、K/RC 原请求重放收敛和既有身份复用均不计为本调用新发布。全程零新发布且最终读回完整返回 `已恢复`。
