# INSTINCT-STAGE3-SERVICE-HISTORY-WATERMARK 服务维护历史事实代次水位详细设计 v0.1

日期：2026-08-31

## 1. 目标与完成边界

本叶为服务维护历史账建立可恢复的增量消费起点，并把该起点加入现有唯一维护游标。完成后，生产启动能够正式读回两个不同 owner 的登记事实代次，建立或迁移一份同时保存以下三项水位的游标：

```text
上一已维护完整秒边界
已消费主动安全变化事实代次
已消费服务维护历史事实代次
```

本叶不读取或解释历史业务事实，不形成有限单调秒事实段，不调用批量内核，不推进维护后的水位，不发布 A / V、状态或动态，也不改变当前值域、阈值或规则版本：

```text
值域 = 0..INT64_MAX
L = 2,767,011,611,056,432,742
H = 7,378,697,629,483,820,645
安全根定义版本 = 1
主动安全结算规则版本 = 1
```

“阈值未来可调整”只表示未来发布新定义版本；当前运行期保持上述整数值不变。

## 2. 当前事实与必要性裁决

当前已发布：

- `按特征实例与事实代次范围读取完整变化组_v2`，读取要求调用方给出主动安全旧水位；
- `按事实代次范围读取服务维护历史事实完整组_v1`，读取要求 `历史账登记事实代次 <= 排除起始事实代次 <= G0`；
- 维护游标 v2 保存完整秒水位和主动安全变化事实代次水位；
- 服务维护历史账见证返回登记事实代次，但只有范围读取成功后才可取得，不能用来发现一个合法的首次排除起点。

因此现有接口存在首次消费闭环缺口。以下替代均不成立：

```text
从 G0 开始读取空范围
-> 不能证明 (登记代次,G0] 没有已经退出的事实

扫描当前合同 / 进展 / 准备集合
-> 不能发现已经退出的历史版本

复用主动安全水位
-> 两个 owner 的登记时点和成员宇宙不同

每轮从历史账登记起点重读全部历史
-> 长期数量无界，不能形成可恢复的有限增量消费
```

裁决：服务合同事实权威 owner 公开读回自身历史账覆盖起点；唯一维护游标升为 v3 并保存独立服务历史事实代次。不得建立第二游标 owner。

```cpp

    L2结构请求头 请求头;
    L2存在身份 自我;

struct 服务维护历史覆盖起点快照_v1 final {
    std::uint32_t 结构登记版本;
    std::uint64_t 历史账登记事实代次;
    L2存在身份 自我;

};

enum class 服务维护历史覆盖起点读取状态_v1 : std::uint8_t {

struct 服务维护历史覆盖起点读取结果_v1 final {
    std::uint32_t 合同版本;

```

公开入口：


读取固定执行 `G0` 读前守卫、历史登记结构和首次规范写集互证、self 绑定、`G0` 读后守卫。成功必须返回非零登记事实代次且 `登记事实代次 <= G0`；全部非成功快照空、截止 0。


v3 物理载荷固定为八个 `uint64_t`：

```text

时间源版本, 服务维护规则版本
```

## 6. 建立、迁移和恢复规则

1. 请求头、锚点、运行代次、纪元、完整秒、两个目标水位和版本必须有效。
2. 主动安全登记见证与服务历史覆盖起点见证都必须成功，self 与锚点一致，正式读回截止不晚于请求 `G0`。
3. 无当前游标：两个目标水位必须分别等于各自登记代次，建立 v3。
4. 当前 v1：仅在两个登记见证完整时迁移；主动安全和服务历史目标分别等于登记代次。
5. 当前 v2：保留其主动安全水位；服务历史目标必须等于历史账登记代次，然后迁移 v3。
6. 当前 v3、同运行代次和同纪元：两个目标水位及完整秒必须与当前事实相同，只形成恢复或精确重复，不允许此入口推进水位。
7. 当前 v3、新运行代次 / 新纪元：继承两个事实代次水位，完整秒使用新纪元当前边界，形成新纪元事实。
8. 任一目标水位早于自身登记代次、晚于 `G0`、回退或由另一 owner 见证提供，返回引用冲突或入口拒绝，零写。
9. 精确重复返回首次提交事实，零第二写；同键异义为幂等冲突。
10. 提交后读回失败返回已可能发布和四字段提交见证，后继必须同键收束。

兼容读取：v1 解码允许 6/7/8 字段并投影共同字段；v2 解码允许 7/8 字段并投影主动安全水位；v3 只接受 8 字段。v3 读取遇到 v1/v2 返回`待迁移`，不得补造服务历史水位。

## 7. 生产启动顺序

```text
读取当前 G0
-> 确保主动安全变化账登记并读回登记代次
-> 读取服务维护历史账覆盖起点
-> 读取当前游标 v3
-> 已是 v3：继承两个水位
-> 未建立 / v1 / v2：按各自登记见证形成迁移目标
-> 建立或恢复 v3
-> 新 Gread 独立读取 v3
-> 逐字段互证 self、运行代次、纪元、完整秒、两个水位和规则版本
-> 成功后才允许创建自我线程
```

任一非成功继续映射既有`本能根运行初始化`失败阶段，不创建线程。启动不读取历史事实组，不把覆盖起点当成已经处理过业务事实；它只建立首次合法排除边界。

## 8. 验证矩阵

至少覆盖：

1. 覆盖起点首次读、恢复读、旧 G、错 self、坏登记、资源失败；
2. v3 首次建立，两个登记代次不同且分别保存；
3. v1→v3、v2→v3，服务历史水位固定取自身登记代次；
4. v3 同纪元恢复、新纪元继承、精确重复、同键异义；
5. 水位为 0、早于登记、晚于 G0、交换两个 owner 水位、见证 self / G0 漂移；
6. v1/v2 读取 v3 的兼容投影，v3 读取旧载荷返回待迁移；
7. 提交后读回失败与同键收束；
8. 持久恢复后 v3 逐字段一致；
9. 普通应用唯一服务实例和生产启动真实 v3 构造 / 独立读回；
10. Debug / Release 编译、专项运行、ABI consumer、`git diff --check`、`check_specs.py --strict`。
