# L2 旧链清理与六类结构 CRUD 分步重建详细设计 v0.1

日期：2026-08-10

设计身份：`L2-STRUCTURE-CRUD-REBUILD`

首个施工叶：`L2-STRUCTURE-CRUD-REBUILD-D1-LEGACY-SELF-CLOSURE-REMOVAL v0.1`

## 1. 目标与完成边界

在新版 `L1事实基座服务` 的业务中性节点、关系、值、属性槽、事实代次和中性写集接口之上，重建只承担数据结构职责的 L2。L2 最终分别拥有场景、存在、特征、状态、动态和因果六类结构的创建、读取、更新、退出与历史读取能力。

本目标固定采用“先删旧代码，再建新合同，再逐族实现”的顺序。旧 L2 代码不得改名保留、包兼容壳或边删边迁；只有新版 L1 与不属于旧 L2 的独立生产能力可以保留。

目标完成至少需要：

1. 当前旧世界、场景、存在、特征、状态、动态、因果服务及其反向依赖闭包按小计划物理退出；
2. L2 六类结构的唯一写入所有者、公开 DTO、结构状态、生命周期、幂等和一致性边界取得正式合同；
3. 六类结构均具备创建、当前 / 条件查询、替换更新、退出和历史读取；
4. 节点到节点的拓扑只由 L1 关系事实承载，节点固定属性由属性槽和值承载，不在节点内复制成员表；
5. L2 对外返回完整值式投影，使调用方不需要自己拼接 L1 关系和值；
6. 每个公开接口叶都由生产二进制外的自定义参数驱动调用，核对结构化结果及当前 / 历史权威读回；
7. 不恢复生产内自检、业务剧本、日志判定、深度专项验收、崩溃或跨进程恢复验证。

本设计不授予 L2 判断场景、存在、状态、动态或因果业务真实性的权力。L2 只保存和返回调用方明确提交的强类型结构；业务解释位于 L5 之外。

## 2. 正式依据

- 0050：L1—L5 均为无业务语义的数据结构服务；高层只能经低层公开合同组合结构。
- 4015：L1 唯一保存业务中性节点、关系、值、属性槽、稳定编码、事实代次和中性 CRUD。
- 4030：每类结构只有一个具名写入所有者；旧业务准入、资格和结果解释必须退出。
- 4190：场景、存在、特征、状态、动态和因果在数据层只作为结构记录，不自动推断或证明业务事实。
- 4200：树 / 图结构使用稳定节点、关系和值；支持创建、查询、关系 / 属性替换、退出和历史读取。
- 4201：骨架只可使用最终合同并返回零副作用 `未实现`；本路线不以骨架代替真实 CRUD。
- ACCEPTANCE-01：验证驱动位于生产代码之外，只经公开入口输入受控强类型结构并核对结构化结果和最终读回。

## 3. 当前代码事实与复用裁决

创建侧事实基线为 `f4dba8d14c5a93aec86da320cac4249bcdc1a005`，发布前必须从新 HEAD 复核。

### 3.1 新版 L1 保留

`海中鱼巣.核心.服务.L1事实基座` 已公开：

- `提交中性写集`；
- `尝试读取中性一致当前投影`；
- 当前节点、关系、值和属性读取；
- 当前源 / 目标关系组读取；
- 历史事实读取；
- 当前事实代次读取。

这些接口已经覆盖新 L2 所需的底层原子写、稳定编码映射、关系组枚举、同截止组合读取和历史事实读取。新 L2 禁止直达 L1 私有仓、锁、候选或事务令牌，也不得建立第二数据底座。

### 3.2 旧 L2 不原位扩展

当前工程仍编译旧 `世界登记`、`L1场景结构`、`L1实际存在`、`L1特征定义`、`L1实例特征`、`L1状态`、`L1动态`、`特征比较`及若干完整自我、动态模式、因果模式模块；生产 `普通应用上下文` 当前只持有新版 L1，未持有这些旧服务。

旧链存在以下结构问题：

1. 服务名和 DTO 仍把领域结构写成 `L1*`，所有权与新版分层冲突；
2. 多个入口包含旧资格、准入、领域结果见证、自动整理或业务解释；
3. 场景读取固定为初始场景，未形成任意场景结构查询；
4. 单个实例特征读取要求调用方提供宿主、定义、实例槽、多条关系、当前值和来源编码，未提供“按存在读取全部当前特征”的结构投影；
5. 旧动态和因果模式包含推断 / 算法职责，不是调用方提交记录的纯结构 CRUD；
6. 旧历史验收和已删除运行期装配不能证明当前生产入口可达。

裁决：旧 L2 代码只作为删除范围和新合同差距证据，不复制函数体，不建立兼容转发，不以历史验收解除新接口验证。

## 4. 新 L2 的统一结构原则

### 4.1 物理承载

每一条场景、存在、特征定义、特征实例、状态、动态和因果记录都有一个稳定 L1 节点。固定标量或类型化材料通过该节点的属性槽和值事实保存；节点之间的父子、成员、宿主、定义引用、前后状态和条件 / 动作 / 结果引用通过 L1 关系事实保存。

节点内不得复制当前成员列表。L2 查询服务在一个事实截止代次内读取节点、属性槽和值及所需关系组，形成调用方拥有的完整值式投影。这样关系仍是图权威，调用方仍能一次取得“场景完整结构”或“存在全部当前特征”。

### 4.2 CRUD 含义

- 增：调用方提交完整强类型结构，L2 形成一份不可变中性写集并恰一次调用 L1。
- 查：按稳定编码或正式关系条件读取当前 / 历史结构，组合结果携带统一非零事实截止代次并稳定排序。
- 改：不原地修改历史事实；建立新值或新关系，同时退出旧值或旧关系并切换当前槽 / 引用。
- 删：表现为结构事实退出；当前查询不可见，历史查询仍可读。引用未闭合时结构化拒绝且零变化。

### 4.3 六类唯一所有权

后续治理叶必须冻结下列唯一写入边界，代码叶不得提前自行改变：

| 结构族 | 唯一写入责任 | 允许组合读取 | 禁止责任 |
| --- | --- | --- | --- |
| 场景 | 场景节点、场景父子 / 成员关系、场景固定属性 | 场景直接成员与子场景组 | 判断现实世界、所在场景或成员资格 |
| 存在 | 存在节点及固定属性 | 存在当前结构、被哪些场景关系引用 | 判断存在真实性或业务资格 |
| 特征 | 特征定义、实例槽、宿主 / 定义引用、当前值与历史值 | 按存在返回全部当前特征 | 为每种轮廓 / 颜色 / 位置建立专用 CRUD |
| 状态 | 调用方提交的主体 / 特征 / 值 / 时间结构 | 当前与历史状态组 | 判断状态真实性或自动补状态 |
| 动态 | 调用方提交的前状态、后状态、时间和来源结构 | 当前与历史动态组 | 比较状态后自动生成动态 |
| 因果 | 调用方提交的条件、可选动作、结果、顺序和来源引用 | 当前与历史因果组 | 判断因果真实、必然或主动 / 被动 |

## 5. 分步计划路线

计划智能体一次只登记一份施工叶。以下顺序是目标路线，不代表后继接口已经实现或可执行。

### A. 旧代码反向依赖清理

1. `D1`：删除完整自我存在 / 场景准入、完整自我发布与组合闭包。
2. `D2`：删除旧因果模式服务、因果 / 动态算法及材料链。
3. `D3`：删除旧状态、动态和特征比较服务及专属 DTO。
4. `D4`：删除旧特征定义、实例特征服务及专属 DTO。
5. `D5`：删除旧世界登记、场景、存在、原子发布和组合服务及专属 DTO。

每个删除叶只允许删除其零外部消费者闭包、工程 / filters 登记并新增专属记录。发现集合外生产消费者时停止该叶，不扩大删除范围。

### B. 新 L2 合同治理

6. `G1`：正式冻结 L2 对六类结构的所有权、共同状态、稳定编码引用、当前 / 历史类别、幂等、同截止、公开 DTO 和自定义参数驱动边界。必要时修订 4190 / 4200 或建立唯一直接子规范并同步目录。

### C. 新 L2 小步实现

7. `S1`：场景节点新增与当前 / 历史查询。
8. `E1`：存在节点新增与当前 / 历史查询。
9. `S2`：场景父子 / 成员关系新增、替换、退出及任意场景完整结构查询。
10. `S3`：场景固定属性换代、场景退出和引用保护。
11. `E2`：存在固定属性换代、存在退出和被引用结构查询。
12. `F1`：特征定义增、查、改、退及历史读取。
13. `F2`：通用特征实例新增、单项查询和按存在枚举全部当前特征。
14. `F3`：特征当前值换代、实例退出和历史值读取；轮廓、颜色、位置等只使用类型化参数，不新增专用函数。
15. `T1`：状态新增、当前 / 条件查询和历史查询。
16. `T2`：状态引用替换、状态退出和结构引用保护。
17. `DYN1`：动态新增、当前 / 条件查询和历史查询。
18. `DYN2`：动态引用替换、动态退出和结构引用保护。
19. `C1`：因果新增、当前 / 条件查询和历史查询，动作引用允许为空。
20. `C2`：因果引用替换、因果退出和结构引用保护。
21. `A1`：装配唯一 L2 结构服务聚合公开面；只持有六类服务，不建立第二写入入口或业务解释层。

## 6. 轻量自定义参数验证

代码叶只采用服务族级轻量黑盒验证，不运行旧专项验收或深度集成：

1. 验证代码放在生产目标之外，不登记进 `海中鱼巣.vcxproj`；
2. 由命令行或固定输入文件接收人可修改的稳定编码、期望代次、类型、端点、顺序、值、时间和幂等参数；
3. 参数解析后构造该服务正式强类型 DTO，禁止把字符串 / JSON 当作权威事实；
4. 经公开服务入口执行本叶新增操作，再经同一结构所有者公开读取入口逐字段核对当前或历史结果；
5. 每个写叶至少运行一个合法自定义参数样例和一个非法参数零变化样例；
6. 只报告本叶实际覆盖的 CRUD，不由一次成功推出整个结构族或 L2 完成。

不做：生产启动链完整验收、逐函数覆盖、旧状态矩阵、性能、长时间并发、故障注入、崩溃、重启、断电、跨进程恢复、日志解析或业务真实性剧本。
