# 治理批次复核分类详细设计

日期：2026-08-20

身份：`RUNTIME-GOVERNANCE-BATCH-CLASSIFICATION v0.1`

对应目标图：`BIZ-L2-002-03 复核并分类治理批次 v0.1`

## 1. 目标与完成边界

闭合正式主链：

```text
BIZ-L2-002-01 不可变治理批次
-> BIZ-L2-002-02 一致事实读取
-> BIZ-L2-002-03 复核并分类治理批次
```

本设计只实现治理批次完整消息交付、逐项协议复核、稳定顺序分类、具名拒绝诊断和停止优先分流。它不读取消息引用的领域事实，不形成需求，不执行治理判断，不接入任务筹办。

## 2. 当前事实与缺口

当前邮箱冻结结果真实拥有 `std::vector<自我治理消息>`，但 `自我治理批次路由`只把 `治理消息编号`复制到待完成槽和 `不可变治理批次::消息身份组`。邮箱结果离开作用域后完整消息被销毁。因此：

- `BIZ-L2-002-03`无法复核协议、来源、时效、路由类别和材料形状；
- `L2治理函数骨架`中的同名全局函数只接收批次身份，固定返回空批次；
- 自我线程虽调用分类函数，实际永远跳过逐项治理输入。

现有 `复核自我治理消息`已经冻结逐消息协议合同，应复用，禁止在分类层复制消息形状规则。

## 3. 唯一所有权和依赖方向

```text
有界自我治理邮箱
  -> 值式交付现有完整冻结批次
自我治理批次路由
  -> 唯一拥有待完成完整消息组
  -> 形成不可变治理批次
  -> 复核并分类同一批次
自我线程
  -> 先读取一致事实
  -> 再调用同一路由实例分类
```

`L2治理函数骨架`退出 002-03 DTO 与全局函数。分类 DTO 和函数物理归属统一为 `海中鱼巣/线程/路由.自我治理批次.ixx`。不增加新模块，不让领域骨架反向持有线程消息。

## 4. 冻结批次合同

### 4.1 不可变治理批次

`不可变治理批次`固定包含：

```cpp
std::uint64_t 批次序号;
std::uint64_t 运行代次;
自我治理冻结批次 消息批次;
完整秒边界观察 完整秒;
std::optional<完整秒区间> 完整秒区间;
已发布共享事实截止 共享事实截止;
```

删除只保存编号的 `消息身份组`。待完成槽同样保存完整 `自我治理冻结批次`和运行代次；成功冻结后直接 move 接管邮箱结果中的批次，重试只复用槽内对象，零再次读取邮箱。分类只经现有 `读取消息组()`取得 const 消息组，不增加邮箱写入口或可变引用。

## 5. 分类 DTO

```cpp
enum class 治理批次分类状态 : std::uint8_t {
  已分类 = 1,
  空批次 = 2,
  停止优先 = 3,
  存在具名拒绝 = 4,
  内部错误 = 5,
  入口拒绝 = 6
};

enum class 治理输入类别 : std::uint8_t {
  任务结果复核 = 1,
  派生需求 = 2,
  观察材料准入 = 3,
  执行前许可预判 = 4,
  自检缺口 = 5,
  缓存刷新 = 6,
  事件日志 = 7,
  停止 = 8,
  概念待命名 = 9
};

struct 治理输入项 final {
  治理输入类别 类别;
  自我治理消息 消息;
};

struct 治理输入诊断 final {
  std::uint64_t 消息编号;
  自我治理准入结果 准入结果;
};

struct 治理批次分类请求 final {
  std::uint32_t 合同版本;
  const 不可变治理批次* 批次;
  std::uint64_t 当前单调时间;
  std::uint64_t 运行代次;
  std::uint32_t 协议版本;
};

struct 治理批次分类结果 final {
  治理批次分类状态 状态;
  std::uint64_t 批次序号;
  std::vector<治理输入项> 有序治理输入组;
  std::vector<治理输入诊断> 逐项诊断;
};
```

请求中的批次指针只在同步调用期间借用，不能为空；结果全部值式拥有，不泄漏批次内部引用。

## 6. 分类函数

物理位置和签名：

```cpp
治理批次分类结果 自我治理批次路由::复核并分类治理批次(
    const 治理批次分类请求& 请求) const noexcept;
```

固定流程：

1. 校验合同、非空批次、批次序号、当前单调时间、运行代次和协议版本；请求运行代次必须等于路由配置及批次运行代次。
2. 空消息组返回 `空批次`及批次序号。
3. 按冻结顺序逐项处理，不排序。
4. 从已处理消息构造同幂等键既有消息及同任务最新序号上下文，调用 `复核自我治理消息`。
5. `可准入`按消息强类型一一映射类别并追加值式消息；未知映射为内部错误。
6. `重复材料`和`已拒绝`只追加诊断；存在任一具名拒绝时最终状态为 `存在具名拒绝`。
7. `内部不一致`立即返回 `内部错误`，不把部分输入交给下游消费。
8. 可准入停止消息追加后立即返回 `停止优先`，不处理其后普通输入；停止之前已经形成的结果保留用于审计，但线程不得继续普通治理。
9. 无停止且无拒绝返回 `已分类`。
10. `bad_alloc`、`length_error`或其它异常返回 `内部错误`和空治理输入组；本函数零业务事实写入。

## 7. 自我线程接线

自我线程在 002-02 成功后构造请求，批次指向当前处理槽中的同一 `不可变治理批次`，协议版本使用 `自我治理协议版本`，并调用 `批次路由_->复核并分类治理批次`。

- `入口拒绝`或`内部错误`：保槽并领域治理终止；
- `存在具名拒绝`：保留诊断并领域治理终止，不伪造业务结果；
- `停止优先`：进入停止后继，不执行普通输入；
- `空批次`或`已分类`：进入后续治理输入事实复核。

本叶只证明分类结果进入线程控制流；002-04 绑定事实复核仍未实现，因此非空普通输入不得越过为机器事实。

## 8. 验证

使用现有 `--test-治理`合法消费者补充：

- 路由冻结后完整消息逐字段保留，批次运行代次一致；
- 正常多类型消息保持邮箱顺序并映射唯一类别；
- 到分类时已过期的消息形成具名拒绝；
- 同键同义为重复诊断、同键异义为具名拒绝；
- 停止输入返回停止优先并截断后继；
- 坏合同、坏运行代次、空指针和坏协议版本入口拒绝；
- 分类零领域写入，共享事实截止不变。

运行 Debug / Release x64 Rebuild 和两配置 `--test-治理`，并执行 strict 与 diff 检查。
