## 1. S0 与最早缺口裁决

P57、P58分别冻结存在域和场景域零写规格，P59逐字段互证为跨域总规格。P59明确把具体L1本地键、写集项、发布后读回计划、稳定编码、幂等身份、双摘要、操作标签、事务和发布者留给后继。

| 所需能力 | 唯一现有或冻结提供者 | P60裁决 |
| --- | --- | --- |
| 完整自我两域资格与共同截止 | P59跨域总规格 | 只消费，不重读P57/P58或原始provider |
| 四个新节点的业务角色 | P59固定角色组 | 机械映射为本叶私有L1本地键1—4 |
| 三场景标记与自我资格值/槽 | P57/P58经P59传递 | 机械形成值键5—8与四个槽变更 |
| 五条固定关系和出生期角色2关系 | P57/P58经P59传递 | 机械形成关系键9—13及14以后 |
| 发布后逐项读回 | P15冻结通用读回合同 | 本叶形成草案；激活时须匹配P15真实结果 |
| 幂等身份、意图/执行证据、操作标签和提交 | 无已接受的完整自我发布者 | 后继发布者拥有，本叶不预判P15漂移语义 |
| 第二领域投影或附属事务参与者 | 无需求 | P53登记已由P55独立发布；P56直接读L1，不新建参与者 |

7130要求具名存在场景组合器编排原子服务和专用数据操作。直接进入发布者会迫使同一叶同时裁决写集编排与正在修订的P15 provider身份/证据合同；先建立参与者又没有第二领域候选可提交。故本叶选择纯确定性的L1专用数据操作：冻结完整写集和读回草案，不取得许可、不打开事务、不提交。

## 5. 本地键、写集和固定语义

### 5.1 本地键分配

四角色固定映射，不接受调用方传键：

| 本地键 | 业务角色或事实 |
| ---: | --- |
| 1 | 世界根内部世界场景节点 |
| 2 | 自我所在场景节点 |
| 3 | 自我存在节点 |
| 4 | 自我内部世界场景节点 |
| 5—8 | 依次为键1、2、3、4的当前值 |
| 9 | 已发布世界根 → 键1，直接父/0 |
| 10 | 键1 → 键2，直接父/0 |
| 11 | 键2 → 键3，直接成员/0 |
| 12 | 键1 → 键4，直接父/0 |
| 13 | 键3 → 键4，自我结构关系21/角色1 |
| 14+i | 键4 → 第i个出生期成员，关系21/角色2 |

`i`从0开始，成员沿P59中P58资格组的严格升序。空成员组时最大键13。全部键在单次写集中非零唯一；关系键不因成员内容重排。

### 5.2 四类写项

节点组按键1—4，均为`节点种类::普通`且无属性类型表示。

值组按键5—8：键5、6、8使用P58的场景标记属性类型、I64值1和场景标记服务；键7使用P57实际存在资格的属性类型、I64值1和资格服务身份。所属节点分别为键1—4。不得把服务身份改作属性类型或材料。

关系组按键9—13、14以后：前三条父/成员关系和键12使用P58冻结的关系类型与顺序0；键13使用P57/P58共同自我结构关系类型和角色1；成员关系使用同一关系类型和角色2，目标为已发布成员稳定编码。禁止为成员新建节点、值或当前场景成员关系。

属性槽组按角色键1—4，分别把场景标记、场景标记、实际存在资格、场景标记绑定到值键5—8。退出事实固定为空；创建完整自我不得退出、删除、替换任何既有事实。

若出生期成员数为`N`，精确数量为：

```text
新节点4；新值4；新关系5+N；属性槽变更4；退出事实0；首次新编码13+N。
```

## 6. 发布后读回计划

草案使用P15冻结的通用读回DTO，并按其规范化键形成`17+N`项：节点4项、关系`5+N`项、值4项、属性槽4项。对象种类顺序固定为节点、关系、值、属性槽；同类按身份本地键或槽所属/类型排序。

节点、关系和值均要求`创建代次=本次发布`、`当前性=当前`；槽要求发布后的当前值分别为键5—8。每一项逐字段复制对应写项，不从数量、首项、哈希或容器地址反推。计划精确覆盖全部创建事实和槽变更，不多读、不漏读；退出读回为0。

P15 v0.13设计冻结上述通用形状，但当前代码结果仍受具名漂移修订。P60激活前必须从正式结果确认L1合同版本、读回DTO、规范化排序、provider身份/合同版本和执行证据接口机械匹配；若接口变化，只修订受影响适配，不把P15证据语义写入草案。

## 7. 入口、完整性与异常

入口先验证P59合同/规则版本、非零登记、普通指定根、非零截止、固定四角色顺序和两域原规格存在。然后逐字段复核P57/P58合同、登记、根、截止、关系类型、节点类型、服务/属性类型、I64值、固定关系角色/顺序及出生期成员资格。入口格式失败为`入口拒绝`，合法形状内的互证破坏为`内部不一致`。

构造完成后再验证：

1. 所有本地键非零唯一且恰为1至`13+N`；
2. 所有本地引用指向本草案已有键，所有稳定引用来自P59已发布见证；
3. 四类写项排序、数量、端点、材料、来源和槽一一匹配；
4. 读回计划版本、数量、种类、顺序和每项字段与写集全等；
5. 草案无幂等键、摘要、操作标签、许可、锁、事务、稳定编码映射或参与者。

函数不读取机器事实，不会发生版本推进重取。输入和结果均为调用栈值式副本；除`std::bad_alloc`外未知异常映射`内部不一致`，不返回部分草案。
