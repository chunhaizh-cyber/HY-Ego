## 5. 预检、锁及原子发布

1. 原登记名解析、原函数声明、头、作用域/实现、固定规格、启用状态、请求格式以及全部分量和行为先完整核验。任何差异在写入前返回原准确冲突/不合法结果。不能先补关系，再检查事件或分支。
2. 需要跨概念owner取得的正式定义与闭包保护在方法锁外取得值式副本；不在方法锁中租端口、读取宿主或回调上层。进入方法锁后经原L1完整快照核同方法、Vm、规格/头、分支、C/R及定义保护。发现合法前提变化不写入，返回既有前提变化对应状态（当前一般登记以`结构不一致`明确返回，不能当作“未找到”另建M）。
3. 空分量补齐候选只追加既有布局：关系和事件数组为Vm新字段；执行分支为新分支节点及其完整条件子树，所属引用准确指向原M及Vm，顺序从0连续；行为为原M上的既有行为字段。分支子树使用L1组内引用，不能提前逐节点公开建立再挂入。
4. 将全部待补分量、需要一起补的行为字段及全部联合预期放进一份`基础节点组追加请求`；通过原封存/原子追加路径一次发布。不调用原直接写关系、直接写事件或普通写分支helper来逐段发布。没有变化则只完整核同并复用，不进行空事务或改写已有字段。
5. 同义并发请求核同失败后，只允许按同M完整请求读回消歧：若全部待补项已同义成立且其余方法身份/头/规格/知识/治理均保持则复用；部分成立、冲突或读取故障不能以成功复用。禁止根据一个新字段存在就再次补剩余字段。
6. 发布后完整读取同M并核全部请求分量及既有内容保持不变。L1报告不确定时只读回同一次完整候选消歧，不重发；无法确认走工程链并保留事实。资源失败或预期不符且确认无发布时返回既有准确状态，候选值式材料释放即可，不撤回现实或旧方法材料。

原子追加具备失败前零可见变化，故不设计补偿删除已公开声明，也不在读回失败时覆盖/清理原M。新分支组内节点随同次操作成功可见，失败由L1原子路径不发布。没有第二清理账、版本或治理状态。
