日期：2026-08-04

版本：v0.1

状态：详细设计；供后续计划智能体拆分施工叶使用；不证明代码已实现，不构成计划开工许可

## 1. 目标与完成边界

本设计把已经确认的安全、服务、需求、任务、方法、状态、动态、因果和结算语义装配成一个最小可实施闭环：

```text
自我根定义和当前事实
-> 安全 / 服务根正差距
-> 条件性初始子需求
-> 已登记本能方法召回
-> 任务筹办和执行
-> 外部状态变化及权威回读
-> 状态迁移与动作致变实例因果
-> 任务结果、需求满足和价值结算分账
-> 安全值 / 服务值正式回写
-> 下一治理批次重新判断
```

“闭环完成”只表示上述链在隔离的确定性模拟材料中能够以正式入口走通，并能对完成、等待、能力缺口、失败、取消、到期和终止形成合法闭合结果。它不表示：

- 已接入真实外设、真实人类交互或长期实时运行；
- 已具备任意服务能力、复杂因果学习或通用自主方法生成；
- 服务值已经达到 `I64_MAX`；
- 所有旧数据基座、旧世界树或旧任务入口已经删除；
- 编译、自检或日志出现成功文字就等于业务闭环成立。

## 4. 根目标与初始需求

### 4.1 安全根目标

生存安全根值 `A` 使用 `0..I64_MAX`：

```text
A = 0  -> 终止控制态
A = 1  -> 休眠控制态
A > 1  -> 允许主动运行
```

本初始闭环的最低安全目标是 `A > 1`，不是把安全值无条件推到最大值。具体安全子需求必须由当前场景、自我状态、风险事实和有效因果路径动态形成；未知事实不得默认安全，也不得凭固定因素清单制造风险。

### 4.2 服务根目标

服务值目标固定为：

```text
目标 V = I64_MAX
当前 V = I64_MAX -> 服务根正差距为零
当前 V < I64_MAX -> 存在服务根正差距
```

`V < I64_MAX` 只说明服务方向仍有差距，不证明当前存在人类服务对象、真实需求、合同、可执行任务或应入账价值：

- 有真实有效人类需求时，才进入提出者、法规、目标、范围、合同和能力检查；
- 没有真实人类需求时，只能形成监听服务触发、检查服务机会、校准服务能力、服务根缺口检查和最小闭环能力维护候选；
- 已具备可验证能力时直接进入服务任务，不强制建立服务准备；
- 缺失、失效或不可验证的能力才形成具名服务准备需求；
- 禁止建立“掌握全部服务能力”或“自动寻找任意服务对象”的无限需求。

### 4.3 条件性初始子需求算法

初始子需求不是固定全部激活的清单。统一算法为：

```text
根需求有效且当前未满足
AND 候选事实或能力是判断、行动、验证、归因或回写的必要条件
AND 当前材料未知、过期、失效或证据不足
AND 存在合法提供者、观察来源、准备路径或明确等待条件
AND 取得该结果会改变后继裁决
-> 经需求统一入口形成或复用一个条件性子需求
```

观察不是第三根需求。只有满足上述条件时，安全或服务父需求才能派生观察子需求。

服务根需求的最小管理型能力集合为：

1. 接收真实人类需求；
2. 复核提出者、授权、法规、生存控制、范围和有效期；
3. 明确服务对象、目标、服务前状态和满足关系；
4. 查询并匹配现有方法、能力和材料；
5. 建立唯一合同并按 6160 结算 30% 预支；
6. 筹办或执行服务任务；
7. 观察服务后的外部实际状态；
8. 验证目标是否达成；
9. 判断改善是否可归因于自我动作并审查副作用；
10. 完成合同、结算 70% 余款或形成合法终态并进入下一轮。

只有上述某项能力缺失、失效或不可验证时才形成对应准备需求。

## 5. 本能方法和出生期材料

### 5.1 最小本能方法集合

出生期可以正式登记的最小本能方法只覆盖确定性、具名且可验证的动作：

| 方法族 | 用途 | 最低结果 |
| --- | --- | --- |
| 读取/观察方法 | 取得安全或服务判断所需的权威当前事实 | 带来源、截止、质量和有效期的观察结果 |
| 人类请求准入方法 | 复核提出者、授权、法规、范围和有效期 | 准入、拒绝或具名等待 |
| 服务能力匹配方法 | 按目标结果能力查询已登记方法和材料 | 可执行候选、能力缺口或等待 |
| 已登记语义动作方法 | 对明确主体和特征执行一个具名业务动作 | 动作运行身份和完成消息，不直接声明目标成功 |
| 结果验证方法 | 读取前后状态并按注册比较合同判断目标 | 达成、未达成、不可比较或待补证据 |
| 安全处置方法 | 沿已成立安全因果路径执行具名预防或处置 | 动作事实和可验证安全结果 |

“通用改变特征值”、数据库 CRUD、队列投递、线程启动、日志写入和任意名称匹配都只是底层能力，不得登记为可被需求直接召回的业务本能方法。

### 5.2 出生期不预造主动因果

本能方法登记可以包含条件、输入、预期结果、允许结果、禁止结果、动作入口和验证规则，但这些是方法规格，不是已发生动态或已验证因果。

4220 禁止登记出生期主动动作因果。因此初始闭环固定为：

```text
设计/出生期：登记本能方法规格和结果验证规格
运行期：方法真实执行
-> 动作完成消息
-> 权威状态迁移
-> 动作致变动态
-> 形成一个实例因果样本
```

单个实例只足以支持本轮归因审查和后续候选，不自动晋级为通用因果模板。复杂因果抽象、统计学习和方法自动生成不属于本设计首轮范围。

## 6. 内部世界与外部世界的证据桥

结算不是内外世界的连接桥。连接桥由四类材料组成：

1. 外设或合法提供者发布的观察材料；
2. 方法运行产生的动作运行身份和完成消息；
3. 权威状态所有者发布的动作前后状态与状态迁移动能；
4. 绑定同一主体、场景、特征、端点和动作来源的动作致变动态及实例因果。

顺序冻结为：

```text
冻结任务、方法、输入和动作入口
-> 调用具体语义动作
-> 发布或重试同一不可变动作完成消息
-> 独立读取动作运行登记并逐项验真
-> 从权威实在域读取动作后实际状态
-> 使用注册比较合同校准预计结果与实际结果
-> 原子发布后状态、状态迁移动能和可证明的动作致变动态
-> 独立读回并形成实例因果
-> 任务领域裁决结果
```

方法返回值、完成消息摘要、调度请求字段、日志、控制面板、线程退出或任务回执均不能代替权威动作后状态。

## 7. 任务、需求、因果和结算分账

内部治理的直接运行目标是让有效需求取得闭合结果，并在证据成立时完成任务和结算。它不是强迫所有任务都成功。

### 7.1 三个独立业务裁决

```text
任务领域：实际结果是否满足任务目标
需求领域：正式任务结果和当前目标事实是否使需求满足
结算领域：已发布事实是否满足安全或服务结算门禁
```

任务完成不得直接写需求满足；需求满足不得直接写安全值或服务值；实例因果也不得直接结算。

### 7.2 允许修改核心值的三类入口

| 类别 | 合法入口 | 证据 |
| --- | --- | --- |
| 合同结算 | 服务合同建立时 30% 预支 | 唯一有效合同、冻结预算和准入事实 |
| 主动结果结算 | 主动安全结算；直接服务完整完成 70% 余款；服务准备实际衰减补回 | 任务结果、需求满足、同源状态迁移、动作归因、副作用审查 |
| 时间/证据维护 | 服务完整秒衰减、生存安全根被动回归、分层安全值被动维护 | 单调完整秒、当前合同/活动、残余风险或有效未复发证据 |

任务、方法、线程、动态和因果不得直接写 `A` 或 `V`。更准确的口径是：核心值只能由正式价值结算或维护入口修改；任务结果是主动结算的重要证据，不是唯一写入口。

### 7.3 服务结算

- 同一来源需求有效期内只有一个合同；合同建立原子结算预算的 30%；
- 完整完成且归因、副作用和同源证据成立后结算 70% 余款；
- 无法完成、取消、到期或终止不支付余款，预支不追回；
- 服务准备完整完成只补回其唯一归属的实际衰减，不产生净增长；
- 所有增加使用饱和加法，`V` 不得超过 `I64_MAX`；
- 时间维护按完整物理秒，与自我线程循环频率无关。

### 8.1 最小 DTO

所有公开 DTO 使用中文类型名和字段名，收发稳定身份、强类型值和不透明材料引用，不暴露仓库、锁、线程编号或事务令牌。至少冻结：

| DTO | 必需字段组 |
| --- | --- |
| `治理批次输入` | 自我身份、运行代次、事实截止向量、单调完整秒边界、输入消息身份组 |
| `根差距结果` | 根需求身份、目标定义身份、当前值身份和值、目标值、比较合同、差距状态、来源截止 |
| `条件性子需求规格` | 父需求、必要条件、当前缺口、合法生产者、重新触发条件、目标宿主/特征/状态、来源证据 |
| `本能方法冻结` | 方法代际、条件结果对、动作入口键、输入冻结、允许/禁止结果、验证规则、授权 |
| `不可变任务工作包` | 包身份、种类、任务、工作项、筹办/执行轮次、方法冻结、事实截止、幂等键 |
| `动作完成消息` | 消息身份、工作包、任务、工作项、方法运行、动作入口、动作运行代次、完成序号、来源版本 |
| `权威动作结果` | 主体、场景、特征、前状态、后状态、读取截止、状态所有者、质量/误差、来源定位 |
| `实例因果发布规格` | 条件、来源动作、前后状态、状态迁移动能、动作致变动态、主体、场景、时间窗、同源证据组 |
| `任务实际结果定位` | 任务、工作项、结果版本、状态/动态/因果稳定身份组、完成分类、禁止结果命中 |
| `价值结算输入` | 结算种类、合同/安全需求身份、预算阶段、任务和需求结果、同源证据、副作用、幂等版本 |

## 9. 多线程责任和消息边界

| 线程 | 责任 | 禁止 |
| --- | --- | --- |
| 程序主线程 | 初始化、启动、分阶段停止和连接 | 执行业务任务或修改治理事实 |
| 自我线程 | 冻结治理批次、读取一致事实、维护安全/服务、重判需求、提交任务治理意图 | 同步执行任务或用线程轮次计时 |
| 任务管理线程 | 消费治理输入/外设承接/工作回执，重判任务状态，决定筹办、执行、等待或收口并派发工作包 | 执行筹办算法、方法动作或需求结算 |
| 任务工作线程池 | 并行消费不同任务的筹办/执行工作包，调用领域服务并上报定位回执 | 同一工作项重复动作；直接写需求满足或核心值 |
| 外设线程 | 采集、冻结并发布强类型材料 | 自建需求/任务或直接改世界事实 |
| 控制面板线程 | 按显示范围读取正式只读投影并显示 | 反写业务事实或成为事实来源 |

跨线程只传不可变消息和稳定定位。消息只负责唤醒和定位，消费者必须独立读回正式事实。任务管理线程按任务状态决定筹办或执行，再调用工作线程池；不同任务可以并行，同一任务以稳定身份、筹办轮次和工作项占用隔离。

## 10. 事务、幂等、失败、撤销和恢复

1. 每个领域保持唯一写权；跨领域发布使用现行 L1 事务参与者和最后发布合同，不建立第二事实仓。
2. 合同、当前值、状态动态、实例因果、任务结果、需求满足和结算均具有独立幂等键；同义重复读回既有结果，同键异义写前拒绝。
3. 动作完成消息暂不可发布时保留同一消息重试，不得重复外部动作。
4. 动作已完成但权威状态不可读时进入具名等待；不得按预计值补写后状态。
5. 状态迁移存在但动作归因不足时只保留状态变化线索，不发布动作致变因果，不结算。
6. 任一多参与者准备失败按逆序撤销全部已准备候选；最后发布失败不得留下半可见事实。
7. 恢复必须重建正式节点、关系、值、属性槽、代次/见证、合同阶段、任务/工作项状态、动作运行、动态、因果和结算幂等账。不能证明前轮动作已经收口时，只能形成合法等待，不得重新执行。
8. 内部错误不降级为业务拒绝；业务拒绝、等待、能力缺口和目标未达成也不抛成进程级异常。

## 11. 最小验收剧本

### 11.1 直接服务成功

```text
V < I64_MAX
-> 有效人类请求
-> 唯一合同和30%预支
-> 已有能力，直接服务
-> 语义动作执行
-> 动作完成消息独立验真
-> 权威后状态读取
-> 状态迁移和动作致变实例因果同源
-> 任务完成
-> 需求满足
-> 70%余款结算
-> 下一轮重新比较V与I64_MAX
```

验收必须证明 30% 和 70% 只各结算一次，结算使用饱和算术，任务回执未直接写服务值。

### 11.2 服务能力缺口

```text
有效服务请求
-> 无匹配已登记方法
-> 形成具名能力缺口或准备需求
-> 不自动创建方法首
-> 合同预支不追回，余款不支付
```

### 11.3 无真实服务请求

```text
V < I64_MAX
-> 无真实服务触发
-> 不建立服务对象、合同或直接服务任务
-> 只形成合法监听、机会检查或能力校准候选
```

### 11.4 安全闭环

```text
安全事实未知或有效风险路径成立
-> 条件性观察或处置需求
-> 已登记本能方法
-> 权威状态变化和实例因果
-> 任务/需求裁决
-> 主动安全结算
-> 下一轮A与控制态重判
```

### 11.5 非成功、维护和恢复

至少覆盖：

- 动作完成但目标未达成；
- 只有任务回执，没有权威后状态；
- 只有状态迁移，没有动作归因；
- 合同取消、到期、正式终止和无法完成；
- 服务完整秒衰减、有效活动最低 1 保护和 30 天门禁；
- 服务准备失败、重复、并行归属和完成补回；
- 同一工作包、动作消息、合同阶段和结算输入重放；
- 发布准备失败、确认失败、最后发布失败和逆序撤销；
- 恢复后前轮动作未收口时拒绝重复执行；
- `A=0`、`A=1`、`A>1` 三个控制态的线程和任务门禁。
