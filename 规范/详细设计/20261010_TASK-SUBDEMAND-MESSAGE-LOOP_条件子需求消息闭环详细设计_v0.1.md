# 条件子需求消息闭环详细设计

身份：TASK-SUBDEMAND-MESSAGE-LOOP；版本：v0.9；日期：2026-11-10。

代码基线：`68503939df34630e4559d7c3c4d27363d6bf9751`。用户最新裁决：任务筹办仅产生子需求提议，经worker、manager交回self，由self确认后向需求owner添加或复用正式子需求并返回回执；task不再直接写需求树。复合需求先拆分的目标另有提供者缺口，本计划不猜测其机器语义。

## 1. 独立最小范围

本设计原I64分支实现已唯一选定实例M/P/C/R、角色已绑定实际世界存在或场景、条件关系为单项或全部成立的缺口提议与消息闭环。另有已确认平行逻辑分支：（1）原有 **I64条件子需求**——结构与字段保持本文件原合同，**不得改动**；（2）**词条归类**——目标形状见LANGUAGE-LEMMA-CLASSIFY／5170；（3）**指代澄清**——目标＝指代实例、满足＝指代已消解，见LANGUAGE-PRONOUN-RESOLUTION；（4）**原文范围分界澄清**——目标和fresh满足见下方v0.8扩展。各分支共享提议→self确认→owner建立／复用→任务承接的治理顺序，但载荷类型分离，禁止塞进I64区间或互相冒充。逻辑分支获批不代表全部消息DTO与生产消费者已实现。

来源是方法条件不足，不是复合目标分解。现有需求只存单目标FT，建立入口只接受特征概念；存在概念特征组是类型/具体概念对，未包含子需求目标关系、宿主角色或变化方向，不能擅自当作复合需求。存在引用值域也不等于被引用对象的全部特征需求。

I64自动需求化不支持任一/有序/条件选择、二次特征条件、状态/动态条件、无角色实际绑定、缺当前值、任务虚拟存在和未形成实例特征；其它非I64不得套入该结构。已批准语言分支按各自专属合同，不因不符合I64而被拒绝，也不能冒称原DTO已支持。未支持、材料未到或结构错误须分别返回，零新D。词条归类项不得写成方法学习需求，也不得写入自我内部世界。条件中仅存在概念要求可作为合法性前置验证，但存在概念本身不转换为新D。

本次不实现组合方法解释执行、学习需求、复合需求提供者、子需求撤销/淘汰、任务树、持久提议账、跨进程消息重放或崩溃exactly-once。全部需求/任务关系仍由需求树父子与一D一T表达。

## 2. 当前复用与所有权

HEAD已有：实例结果选择、完整C/R查询、W2、worker工作编号和shared_future交接；manager最近筹办结果及完整原工作定位；self受限筹办反馈桥；自我筹办裁决回执；需求owner按父D、目标存在、完整目标、来源类型及来源任务精确去重；数量差触发全树扫描补T。

`新_任务类::建立子需求`当前公开直接写需求owner私有入口，HEAD无生产调用。本次删除声明/定义，需求类private friend由task改为self。task只给出值式建议并复核来源，不能调用需求建立函数；manager/worker同样不能写需求树。self确认是唯一治理写入裁决，实际节点由需求owner建立。

本次对任务治理状态和内部需求信息进行操作，目的为补足已选方法执行条件；不把此过程当作改变现实特征的普通动作，不直接修改条件所指世界特征。真实改变由新子需求对应任务的普通方法完成。

`条件项序号`为原C项的从0开始下标，结合完整配对及原工作才形成消息内项身份，不是业务节点身份。`全部条件项组`逐原C项保存完整目标域区间、单位、实际对象与特征定位；它包含已经满足的项，且不保存会随世界变化的当前数值。`子需求项组`只是当前未满足项的规范去重子集。区间/单位快照捕获外部条件概念原编码不变而内容变化，不持久化第二概念。来源一致要求T/D/父目标身份、实例/M/P/C/R、角色绑定与全部条件定义快照相同；允许原缺口自然变为已满足，因此比较来源时不比较状态及缺口组。父目标只要求完整目标身份未变且fresh统一选择仍选同一配对；不承诺父目标全部概念内容历史或跨调用共同快照。

提议算法：

1. 读取非终结父T、唯一D和当前混合实例，要求T待检查条件；调用统一选择。
2. 统一选择为已选定或等待条件时均继续完整读取来源；已选定且C全部具备返回无需子需求时仍填完整T/D/实例/M/P/C/R、绑定及全部条件项快照。没有完整配对及绑定返回材料未到；其它选择状态准确映射，不制造提议。
3. 读取选中完整配对。关系只允许单项/全部成立；预检所有条件种类均受支持后再生成项，避免一半支持冒充完整分解。
4. 每个条件须能定位唯一世界实际对象、实际FT及I64当前值；目标域同FT根、同单位，域规范且非空。逐项直接测试当前值落域。
5. 已落域不生成项；未落域输出该C项的目标存在、FT根、原目标域及区间。目标语义固定“当前值落入条件值域”，不转换为增加/减少方向，不猜某个具体端点。
6. 相同对象/FT/规范I64区间与单位的语义重复项去重，保留最小原C项序号；同对象FT不同域不合并，全部成立的交集为空返回暂不支持、零提议，不生成冲突子需求。
7. 从父D沿正式父链读取全部祖先（包含父D），拒绝父链环或坏结构。若任一拟生成目标与祖先具有相同目标存在、FT、规范I64域/单位和“包含于参照值域”比较语义，即使概念编码不同也返回形成循环依赖、零提议，不能以新编码规避语义循环。方向目标或其它比较关系不被错误判成等价；无法完整读取祖先时返回对应非成功。
8. 任何必需材料缺失或失败返回对应状态，缺口组为空；`已形成`保证非空且可机械建立单目标D。无需子需求保证来源完整、全部条件快照完整及缺口为空。

纯提议阶段不新建概念、需求、任务，不修改任务状态。

## 4. 线程消息复用及新增DTO

不新增发送方/接收方字段或第二回调通道。沿用：

```text
worker：W2 → task提议 → 工作结果
manager：独立纯读重算 → 保存最近筹办结果 → 现有筹办定位回调
self：按完整原工作读回 → fresh来源复核 → 确认采用 → 需求owner写D
self：冻结逐项回执 → 现有自我筹办裁决 → manager
```

`新任务工作处理结果`增加`optional<新任务条件子需求提议> 条件子需求提议`。只在检查条件W2中填写；其它工作种类非空拒绝。W2完成后纯读提议，已形成、无需、材料未到和暂不支持均是明确处理结果，不把不支持包装为成功拆分。

`新任务筹办处理结果`增加`optional<新任务条件子需求提议> 独立子需求提议`。manager调用同一纯函数，与worker完整值式提议精确比较；不相等返回来源已变化或独立读回失败，不转发旧内容为采用材料。使用既有`新任务筹办反馈定位{任务节点,原工作}`，不只拿工作编号匹配。

## 5. self唯一采用入口

self使用`世界树.获取事实服务()`现有需求与二次特征概念服务，不新增装配服务。在self现有`实现`内、`消息项`定义之后增加私有成员`新自我消息处理结果 处理条件子需求提议(消息项& 项, const 新任务筹办处理结果& 筹办) noexcept`承担核验和采用；资源重试沿现有消息处理状态表达，不公开给任意调用者。公开self提交消息继续拒绝外部伪造任务筹办反馈，只能经已绑定manager窄回调进入。

需求owner保留私有`建立或取得普通需求已核验`，friend仅self；self必须先用task公开只读查询确认T存在、D恰为T唯一需求、父任务未终结、原工作仍是manager当前定位、提议来源仍匹配当前M/P/C/R和区间单位。禁止用户/外设直接提交一份提议越过来源检查。

采用时self通过已有二次特征概念服务路径建立/取得：两份同FT准确值输入、有向特征差值算法、条件目标域为参照，随后取得“包含于参照值域”子概念。沿现有初始化实现读取并复核返回身份，不用词条或裸布尔作目标关系。

随后形成普通需求请求：父D=父任务唯一D；目标存在/FT/域取核验提议；目标形式=值；比较关系=上述包含关系；来源类型=任务子目标；来源承接节点=父T。由需求owner精确添加/复用并正式读回父子/目标/来源，self不手写底层字段。

采用前对每项fresh重核来源与当前值：来源变动停止剩余发布；若该条件已具备，标已无需要，零新D。来源比较使用第3节规则，不能因未满足项组缩减而拒绝合法的条件变化。新建概念后需求建立失败，概念保留为合法可复用概念，不删除共享概念。self不在本阶段更改目标世界特征。成功D须由需求owner正式读回，其父D、来源类型/父T、目标存在、FT、值域及包含比较定义全部一致；返回编码本身不构成成功。

## 6. 幂等、部分失败与消息关联

原工作含工作编号、任务、种类及完整强类型请求，构成进程内交接定位；提议项序号仅在该完整组内有效。同身份异内容返回身份冲突。工作编号不充当事实代次、任务轮次或跨进程去重键。

self消息项在首次领域写入前分配完整采用进度、每项子D承接消息与future槽，保存已经读回的正式D和冻结回执。进度字段固定为`optional<新子需求采用回执> 条件子需求回执`、`bool 条件子需求回执已接收=false`、`vector<新任务承接消息> 条件子需求承接消息组`、`vector<shared_future<新任务承接处理结果>> 条件子需求承接结果组`、`vector<bool> 条件子需求承接完成组`，三组均与原提议项组同长。无D项不发送承接。回执只在各项处理终结后冻结；资源暂失败不提前冻结为最终失败。重试发送必须发送同一回执，不把首次`已建立`重新计算为`已复用`造成异义。manager收存回执失败时self保留消息并按现有资源重试机制重发；不再次写已完成项。

多子D没有组合事务：逐项建立；后项失败保留已正式发布前项。资源暂失败可重试未完成项；结构失败、来源过期或停止时返回部分完成及剩余状态，不能删除已有D或宣称整组已完成。重试/重新筹办由需求owner正式语义键去重，而非持久消息账。

manager只在完整原工作仍相同、回执内容合法、成功项D正式读回与提议对应后接纳。精确重复复用已收回执，异义拒绝。收存完毕后才清除待反馈任务。父T保持待检查条件且manager阻塞，在回执未收束前禁止新工作覆盖最近筹办定位。

新D发布后self合并设置需求数量复核触发标志，沿现有全树扫描补齐子T；扫描在途/处理结果时不重复发起。扫描仅建立唯一关联并置等待条件，不能据此唤醒普通子T。manager处理采用回执本身不能顺便建T。只有回执被manager正式接收后，self才逐项fresh读取成功D，确认其仍需治理或已满足，并发送受限子D承接消息；已满足项也允许补齐唯一关联。self保留future进度，等待的是manager承接处理结果，不等待子任务完成。

### 6.1 受限子D承接合同

在manager头文件的private区、既有self friend及筹办裁决入口旁新增：

```cpp
新任务承接接收结果 提交已确认条件子需求(
    const 新任务筹办反馈定位& 父筹办定位,
    const 新任务承接消息& 消息) noexcept;
```

`新任务承接依据`尾部追加`自我条件子需求`；消息仍沿现有承接邮箱、编号及shared_future，不另加线程/通道。公开`提交消息`拒绝此依据。内部消息项保存`optional<新任务筹办反馈定位> 父筹办定位`；私有入口要求该依据、无来源状态节点、完整父原工作仍匹配且子D确实在已收固定回执成功项内。同消息号及定位异义拒绝。处理时再次核对，不能只在接收时验证。

manager收存回执时即按全部成功D预置待承接集合，不能仅统计已经到达的子D消息；每项承接处理终结后才退出该集合。尚有成功D未交接或处理中时，保持父原工作定位及重筹办阻塞；资源失败保留重试资格，停止/永久错误只停止受影响父路径，不把缺失交接当就绪。

manager调用task私有`承接已确认条件子需求(父T,子D)`：fresh核验非终结父T、直接父D关系、任务子目标来源=父T、规范I64值目标与包含关系，并确认子D没有失活。关联缺失时复用`建立需求任务关联`；已满足只补关联、保持等待或既有状态。需增加、需减少及未满足但无有向差值（多区间空洞）均表示需要治理，已建立/等待条件子T可进入待查找方法；既有非终结且已推进子T只复用，不倒退/重做；任何终结子T返回既有终结，不自动重启。资源失败、结构错误、材料不足原样收口，不能误当已承接。该入口不写D、不改变目标世界值。

## 7. 父任务等待与安全重筹办

等待采用不新建任务状态；父T保持待检查条件，manager保留其阻塞及最后确认回执。仅下列真实事件触发当前材料重核：

- self已接受事实变化消息，经既有`提交结果状态通知`进入manager。
- 子任务正式完成结算确认。
- manager首次收存采用回执后的一次fresh补查，避免事实变化早于回执而丢失唤醒。

重核通过第3节task纯读函数，输入父T及回执中成功D与原提议项组，输出全部D当前满足与统一方法选择结果。核验每个D确实为父D直接子需求、来源为父T、目标匹配原提议及当前域内容/单位，逐个`复核当前满足`；不是只看子任务状态或“已建立D”。同时重选当前方法及其C。空成功组时“全部需求已满足”为真，但仍须当前统一选择为已选定才就绪；任何非成功均不得返回已就绪。

只有明确满足重筹办条件才清除阻塞、旧筹办反馈/旧采用定位，重新派发W2；不直接进入待执行，更不直接调用函数。重复事件不得派发并行同T工作。条件仍缺/无准确值/结构错/资源失败不假称就绪，不忙轮询。

就绪条件严格为`全部需求已满足 && 当前选择.状态==已选定`。旧D未满足时，即使当前方法选择变化仍保持阻塞；本次不自动废弃旧D、解除依赖或更换目标。父T已终结、状态变化、当前材料缺失/错误和资源失败都不触发重W2。全部D已满足后的fresh选择可选当前合法配对，必须重新经W2及self执行前判断，不能复用旧执行许可。parent最近工作定位在回执/子D承接尚在途时不得覆盖：事件只合并待复核标志，待子D承接进度收口后进行一次fresh复核；无新事件不定时轮询。首次回执补查结果可先记录，但不得抢先清除承接仍依赖的定位。

## 8. 锁、生命周期和恢复边界

worker完成通知只唤醒manager；manager调用self桥不持manager互斥。self创建需求期间不持self邮箱锁；通过消息项进度保证同消息串行。manager域查询和task/需求owner调用不持manager邮箱锁，结果提交前重新核对原工作。

跨owner无事务：每项发布前fresh核验，同T筹办定位受manager阻塞保护；不能宣称核验后世界条件永不变化。后续变化由正式需求复核处理，不用伪版本或消息号假装全局快照。

停止仅停止后续采用/派发并完成已接收消息的结构化收尾，不撤销已正式D。进程内精确重复与语义去重可验证；重启须重读正式需求并重新筹办，不把旧工作编号当授权。本计划不补基础持久恢复，跨进程消息恢复和崩溃原子明确未证明。

## 9. 验证矩阵

- task纯提议前后需求节点数、概念节点数、任务状态不变；删除旧task写入口且无调用；需求私有friend不再给task写权。
- I64单项、AND多项、已满足项跳过、重复项去重、多区间、同单位核验；任一/有序/非I64/二次/状态动态/虚拟存在/无绑定/无当前值零新D。
- 真实worker→manager→self→需求owner→回执；父D和来源T正确，新D由扫描补T，不由manager直接建。
- 相同反馈/回执重发零重复D；异义、错父T、旧原工作、概念内容变更拒绝；半组资源失败保留前项且重试不重复。
- 已满足条件仍保留完整来源；全部条件快照不随缺口缩减而丢失；原缺口变满足允许采用收口，条件域同编码内容改变拒绝；祖先同语义域异编码仍阻止循环；AND交集空零D。
- 扫描补T停在等待条件；self受限承接在manager收到回执后才发送；需增/需减/多区间空洞可唤醒，已满足只补关联，终结不重启；外部伪造新依据拒绝；future未就绪不阻塞线程，定位保持至承接收口。
- 条件未满足时不唤醒，回执后fresh补查及事实/子完成事件触发，重复通知同T不并发；重筹办回W2而非直接执行。
- self/manager停止、邮箱满、回执接收失败、已发布但交接失败保留正式D；无持久exactly-once宣称。
- 隔离HEAD+本切片净增量Debug/Release Rebuild及专项；服务结算WIP不作为输入。

专项必须使用真实self/manager/worker实例及其生产邮箱/反馈路径；父T可由公开夹具入口预置待查找方法，不宣称全树扫描自动启动普通父T。当前世界事实变化到self尚无自动生产装配，专项用正式世界状态节点调用`self.提交消息(事实变化)`，仅证明正式通知入站后的链路，不宣称自动世界观察装配。普通方法执行和真实外设不是本次新增能力；条件变化通过正式领域写入口形成，不把测试注入当自动业务生产者。
