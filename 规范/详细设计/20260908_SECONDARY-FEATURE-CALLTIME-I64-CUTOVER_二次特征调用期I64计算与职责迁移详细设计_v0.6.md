## 1. 本版唯一修订

v0.1 第 6 节及 v0.5 把派生读取`材料总数`定义为`定义数+关系数+叶数+属性值数`。但`定义数`和`叶数`是逻辑对象数量；完成真实读取还会读取 definition 结构角色节点、FT 节点、单位/维度/分量角色节点、规则节点及其它结构节点。这些 L1 节点既不是派生定义，也不是基础叶、关系或属性值。若仍要求四项相加恰等于材料总数，真实读取要么无法计费，要么只能把额外节点误计成定义/叶，破坏对应逻辑数量的成功谓词。

本版只修订单根与批量派生读取的用量语义、计量上下文、成功谓词和计算应用扣费依据。字段名称、顺序和类型不变，不增加第七预算维度。v0.1—v0.5 其它设计继续有效；冲突处以本版为准。不得借此修改持久结构、读取结果业务载荷、算法、方向、RC、owner 或工程范围。

## 2. 六项用量的确定语义

`特征类派生读取用量`六字段固定解释为：

| 字段 | 计数对象 |
| --- | --- |
| `定义数` | 本次成功展开或失败前已经接纳的唯一逻辑派生定义身份数；成功时等于`完整定义组.size()` |
| `关系数` | 本次从 L1 实际读回并检查的唯一关系事实编码数 |
| `叶数` | 本次成功展开或失败前已经接纳的唯一基础准确 F 身份数；成功时等于`基础叶组.size()` |
| `属性值数` | 本次从 L1 实际读回并检查的唯一属性值/值事实编码数 |
| `最大深度` | 按每条根到基础叶使用路径核验的最大展开深度 |
| `材料总数` | 本次从 L1 实际读回并检查的全部唯一事实编码数，包括所有节点、关系和值事实 |

定义身份和叶身份各对应其自身节点事实；关系事实和值事实属于不同 L1 事实种类。因此成功时必须满足：

```text
材料总数 >= 定义数 + 关系数 + 叶数 + 属性值数
```

右侧四项加法必须逐步检查 U64 溢出。大于部分只允许来自真实读回的其它节点事实，例如结构角色、FT、单位、维度、分量角色、规则或材料节点；不能来自容器项、缓存命中、查询次数、失败尝试、局部编号或估算常数。不得为了恢复等式把其它节点归入定义数或叶数。

## 3. 共享计量上下文

单根`读取标量派生定义`和 v0.5 批量入口都使用同一类调用内读取上下文。上下文除既有逻辑定义、逻辑叶、关系和值去重集合外，必须有覆盖全部 L1 事实种类的`已读材料编码`集合及按编码缓存的事实副本。

每次准备读取一个尚未缓存的 L1 事实编码时，必须先检查`已读材料编码.size() < 预算.最大材料总数`，再调用 L1；成功读回并完成编码/类型基本互证后，把该编码恰一次加入已读材料及对应实际种类集合。关系组或属性值组返回时逐项执行同样准入，不能先把整组并入业务结构再检查。相同编码在同一上下文命中缓存时不再次调用 L1，也不增加任一用量。

定义和叶分类的接纳时点固定：派生定义自身节点成功读回，且已完成该定义节点的编码、owner、节点种类、生命周期及定义身份基本准入后，才把定义身份加入定义集合；基础准确 F 必须完成其完整准确事实读回准入后，才把 F 身份加入叶集合。读前预算不足、未找到或没有事实不增加定义/叶计数；定义或叶已经完成上述准入后，后继关系、值、来源或闭包检查失败，保留已经接纳的定义/叶及全部已读材料计数。禁止在读取自身节点前预占分类计数。

计数关系固定：

- `材料总数 = 已读材料编码.size()`；
- `关系数 = 已读关系编码.size()`；
- `属性值数 = 已读值编码.size()`；
- `定义数 = 已接纳定义身份.size()`；
- `叶数 = 已接纳基础F身份.size()`；
- 关系/值集合都是全部材料集合的子集；定义/叶身份对应的节点编码也必须存在于全部材料集合；四个分类集合互不冒充。

若 L1 调用返回未找到、已退出、历史不可用或其它无事实失败，不凭查询编码增加材料数；已经成功读回的前序事实保留真实用量。若读回事实后发现格式、owner、生命周期或结构不合法，该事实已经实际读取，必须进入材料及其种类计数，再返回对应失败。预算检查发生在新事实读取前；预算不足本身不增加材料数。

## 4. 单根读取成功谓词替换

`特征类标量派生读取结果::成功()`中以下旧条件废止：

```text
材料总数 == 定义数 + 关系数 + 叶数 + 属性值数
```

替换为：四项分类和可表示，`材料总数 >= 四项分类和`，材料总数、关系数、属性值数、定义数、叶数和最大深度均非零；定义数/叶数继续分别等于返回的完整定义组/基础叶组数量。其它仅依赖结果包字段的 G/H、根定义、来源闭包、排序唯一和完整性条件不变。

本段同时明确废止并替换 v0.1 第 6 节“所有用量不超过请求预算”属于单根结果成员`成功()`的要求。单根结果沿既有 DTO 不新增原请求字段；入口必须在共享读取上下文中依据请求六项预算逐次准入并在返回成功前完成尾 G 守卫。成员`成功()`只验证结果内部非零用量、分类和可表示、总数不小于分类和、定义/叶与载荷一致及其它包内闭包/G-H条件，不核对已经离开作用域且未回显的请求预算上限。调用者必须按返回`材料总数`扣费，不得按四项分类和扣费。

## 5. 批量读取成功谓词替换

v0.5 批量结果保留完整`原请求`。其`成功()`必须同时验证：

1. 四项分类和可表示，`材料总数 >= 四项分类和`；
2. 六项用量分别不超过原请求对应预算，其中`材料总数 <= 最大材料总数`；
3. 定义数/叶数分别等于联合完整定义组/基础叶组数量；
4. 关系数、属性值数和材料总数来自同一共享计量上下文的唯一集合，缓存命中不重复；
5. v0.5 已冻结的原请求、根回执、联合闭包、最大深度和尾 G 条件全部成立。

批量失败继续清空成功载荷，保留原请求、G/H、状态及失败点的真实六项用量。失败用量不要求四项分类和与材料总数相等；任何已读额外节点仍必须进入材料总数。

## 6. 计算应用扣费与缓存

二次计算应用收到单根或批量派生读取结果后，只以`用量.材料总数`扣`二次计算预算.最大读取材料数`。`定义数/叶数`继续分别用于图项和基础叶逻辑预算，批量的`2*N`来源边扣减继续按 v0.5；关系数和属性值数只用于回执互证，不重复扣读取材料预算。

批量共享 A/B→C 时，C 及其结构角色、FT、单位和规则等全部事实编码都在同一`已读材料编码`集合中只出现一次。批量结果填充 saved/leaves 后，应用后继命中缓存不再调用 L1，也不增加任何用量。不同编码即使内容相同仍是不同事实，必须分别计材料；同一编码被多个结构角色引用只计一次实际读取。

禁止按`定义+关系+叶+属性值`的分类和代替真实材料总数，禁止以预算上限冒充实际用量，也禁止因批量失败回退逐根读取来绕过真实计费。
