## 3. 目标业务事实

复用当前世界根，新增四个普通节点：

1. 世界根内部世界场景；
2. 自我所在场景；
3. 自我存在；
4. 自我内部世界场景。

新增四个 I64 值与四个当前属性槽：三个场景标记值的属性类型和来源取自当前世界登记；一个实际存在资格值的属性类型和来源取自当前实际存在登记；四个材料值均为各自现行登记合同中的 `1`。

五条固定关系为：

1. 世界根到世界根内部世界场景：直接父场景关系类型，顺序 0；
2. 世界根内部世界场景到自我所在场景：直接父场景关系类型，顺序 0；
3. 自我所在场景到自我存在：直接成员关系类型，顺序 0；
4. 世界根内部世界场景到自我内部世界场景：直接父场景关系类型，顺序 0；
5. 自我存在到自我内部世界场景：自我结构关系类型，角色 1。

出生期成员按请求给出的稳定编码严格升序、无重复。每一成员必须由当前实际存在服务在请求期望事实代次正式读回资格值 `1`。成员关系为“自我内部世界场景到成员”，关系类型为自我结构关系类型，角色 2。自我不得成为成员；成员既有现实世界位置不改变，角色 2 只增加自我内部世界成员事实。

## 6. 组合根的确定顺序

`发布完整自我` 在互斥锁内固定执行：

1. 校验版本、幂等身份值域 `1..0x00FF'FFFF'FFFF'FFFF`、非零期望事实代次、成员组严格升序无重复且不得为空；入口失败零 provider、零 L1。
2. 调用数据操作`尝试收敛已有完整自我(请求)`。无首次定位返回`尚无完整自我`并进入首次路径；首次原请求全等时，数据操作用已保存的原规范化写集重新到达同一 L1 键，取得精确重复并正式当前读回后返回`幂等读回`；首次原请求不同或已隔离则在新写前返回幂等冲突/内部不一致。组合服务直接返回所有非`尚无完整自我`结果。
3. 依次读取当前世界登记、自我结构登记和实际存在写入规格；三者必须完整且事实截止全部等于请求期望代次。
4. 按成员顺序逐项调用`L1实际存在服务::读取当前实际存在资格`；每项必须完整、编码全等、资格值为 1 且同截止。生产 N=1 时该成员必须与运行期上下文正式读回的当前初始场景实际存在编码相等。
5. 调用存在准入服务一次，再调用场景准入服务一次；任一拒绝都在 L1 前逐类收口。
6. 组合服务只比较两规格的合同/规则、世界根、关系 21 类型、共同截止、角色互补、成员规范化顺序；不改写任何规格字段。
7. 调用数据操作`提交完整自我`恰一次；数据操作之外 L1 调用为 0。
8. 仅数据操作返回`已提交/幂等读回`且携带完整正式当前事实时成功。

`读取当前完整自我`只在组合锁内转发数据操作公开读回并逐字段检查结果形状，不调用两个准入服务，不形成新写集。

## 7. 专用数据操作、一次提交与正式读回

数据操作先把两域规格机械映射为第 3 节唯一中性写集。四个新节点均为普通节点；三个场景标记和一个资格值均为 I64；属性槽指向本次值本地键。写集幂等键固定为：

```text
(0x1C << 56) | 请求.幂等身份.值
```

在首次提交前，以请求期望代次取得一次`尝试读取完整快照`，机械核对两规格引用的世界根、服务身份、属性类型、关系类型、全部出生期成员及资格值仍为当前，且当前快照中不存在任何会与本次五固定关系和角色 2 集合竞争的完整或半完整自我结构。任何相关角色 1、角色 2、自我候选或固定拓扑残片都写前返回`幂等冲突`或`内部不一致`，不得借创建路径修复。

只调用`L1事实基座服务::提交中性写集`一次。`成功/精确重复`必须逐项验证幂等键、发布事实代次、`是否形成内存权威发布`、13+N 项新编码映射和固定本地键；其它状态映射为入口拒绝、事实代次漂移、幂等冲突、资源失败或内部不一致。零第二账、零第二提交、零事务外补写、零退出事实。

成功或精确重复后，以已知映射和批准成员见证形成一次`尝试读取中性一致当前投影`请求，覆盖：

- 五身份节点和全部出生期成员节点；
- 五加 N 条关系；
- 四个新值；
- 四个新属性槽和每个成员的当前实际存在资格属性投影；
- 世界登记、自我结构登记和实际存在登记的服务身份、属性类型和关系类型节点。

读回必须逐字段互证节点类型、关系端点/类型/角色、值所属/类型/来源/I64、属性槽当前值、发布代次、成员资格和严格顺序，随后形成`完整自我当前事实`。第一次顶层事实代次漂移允许销毁本轮结果并按返回的新代次完整重读一次；第二次漂移返回`事实代次漂移`且事实为空。其它非成功不重试。

首次提交后保存原请求、两域规格、规范化写集和稳定编码定位。`尝试收敛已有完整自我`只在首次原请求全等时重用保存材料向 L1 提交原写集并取得精确重复；即使只改变期望事实代次也属于同键异义，返回幂等冲突。已有完整自我后不同请求必须在 L1 前拒绝，不能创建第二自我。

若 L1 已发布而映射或正式读回失败，数据操作进入进程内发布后隔离：保留`L1发布已存在=true`，禁止任何不同请求继续写；相同请求只允许再次走原 L1 键收敛和正式读回。发布后不得撤销、退出或补写。

## 8. 生产接线与运行期完整性

`生产运行期配置` 新增 `完整自我操作幂等身份 完整自我幂等身份`，固定值 `{1}`；它进入固定配置比较和有效性检查。

`运行期上下文` 唯一拥有两个准入服务、数据操作和组合服务。新增初始化转发和公开读回：

```cpp
完整自我结果 初始化完整自我(const 完整自我发布请求& 请求);
完整自我结果 读取当前完整自我() const;
```

生产链在自我结构登记成功后、旧系统角色初始化前：

1. 从当前初始场景实际存在正式事实取存在编码，形成唯一出生期成员组；
2. 以自我结构登记的事实截止代次作为期望事实代次；
3. 以配置固定幂等身份调用`初始化完整自我`一次；
4. 只接受`已提交/幂等读回`且事实完整；
5. 再调用`读取当前完整自我`，只接受`已读取`且与发布结果全等；
6. 之后才允许调用旧系统角色初始化。

`运行期上下文::完整()` 新增完整自我正式当前读回门禁：完整自我截止不得早于自我结构登记截止，且世界、初始场景、初始场景实际存在、各登记以及完整自我引用的共同身份必须全等。旧系统角色清单仍只按旧职责复核，不能替代完整自我事实。

生产启动状态新增具名`完整自我初始化错误`，启动结果新增`完整自我状态 完整自我业务状态`。所有提前返回聚合初始化列表同步增加该字段，禁止位置错配；最终成功结果必须携带实际业务状态。

## 9. 并发、错误与生命周期

- 组合服务互斥锁串行化读取、首次发布和同进程幂等收敛；它不是事实权威。
- 两个准入服务只处理调用栈值，零异常外部状态；场景成员 vector 分配失败映射资源失败。
- 数据操作在首次 L1 调用前完成所有可能分配和规范化，提交后只移动既有材料并执行正式读回。
- `bad_alloc` 映射资源失败；未分类异常映射内部不一致；发布后异常必须保留已发布边界并隔离。
- 零等待、零 sleep、零后台线程、零 SQL、零材料文件、零旧栈回源。
- 本叶只保证单进程内首次创建、同键幂等和当前读回，不处理崩溃、重启、断电、跨进程恢复或持久化重建。

## 10. 验证矩阵

实现验证至少覆盖：

1. 版本、零/越界身份、零代次、空/乱序/重复成员在 provider 前拒绝；
2. 存在准入只批准自我资格和角色 1，场景准入只批准三场景、固定拓扑和角色 2；两个服务直接 L1 调用均为 0；
3. 世界、实际存在、自我结构登记或成员资格未加载、坏字段、错截止逐类短路；
4. 成员资格必须来自正式当前实际存在读回；自我成员、错资格、重复成员写前拒绝；
5. 本地键 1—13 与 14+N 精确，写集只能为 `4/4/(5+N)/4/0`；生产 N=1 为 `4/4/6/4/0`；
6. 0x1C 唯一，低 56 位无损，首次和精确重复键全等；只改代次或成员即冲突；
7. 数据操作是唯一 L1 调用点，组合服务直接 L1 调用 0；一次快照复核、一次提交、一次正式读回；
8. 已存在完整/半完整自我、角色 1/2 竞争、坏固定拓扑全部第一写前拒绝；
9. 13+N 映射、五身份、五固定关系、四值/槽、N 成员关系和成员资格逐项读回；
10. 首轮漂移完整重读一次，第二轮漂移无部分事实；
11. 发布后读回失败保留`L1发布已存在=true`并隔离，不撤销、不补写；
12. 相同原请求并发只发布一次；不同请求并发只有一个可能提交；
13. 生产顺序固定自我结构登记→完整自我→旧系统角色，完整自我失败不进入旧系统角色；
14. `运行期上下文::完整()` 必须消费正式当前完整自我读回；日志、启动返回和旧清单不能替代；
15. Debug/Release Rebuild、两配置生产程序运行及退出码、正式日志人读观察、模块扫描、strict 和白名单 diff check 通过；
16. 不新增专项自检、验收驱动、生产内 PASS 或第二目标；黑盒能力验收仍由生产二进制外的正式入口执行。
