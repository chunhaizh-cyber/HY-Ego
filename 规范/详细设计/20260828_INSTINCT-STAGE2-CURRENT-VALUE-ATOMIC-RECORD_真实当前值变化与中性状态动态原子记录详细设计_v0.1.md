# INSTINCT-STAGE2-CURRENT-VALUE-ATOMIC-RECORD 详细设计

日期：2026-08-28
版本：v0.1
状态：创建侧候选；通过本文件门禁并发布登记后方可施工

## 1. 目标与完成边界

本设计闭合本能路线阶段二的最早代码缺口：让一个已经有正式当前值的特征实例，通过唯一公开组合入口完成真实值变化，并在同一 L1 三分区事务中形成新当前值、中性状态当前选择、状态迁移动能及完整上下文关系。

本叶完成只证明：

```text
普通应用取得唯一组合服务
-> 真实变化 / 无变化 / legacy 基线兼容
-> 特征、状态、动态三个 owner 同 G1 提交
-> 公开结果
-> 独立正式读回
-> 本能根重启优先消费中性记录选择
```

不实现安全值/服务值被动维护规则、周期游标、自检、需求、任务、方法执行和结算；这些只能在本叶结果发布后形成后继计划。

## 2. 正式依据与当前事实

正式依据：0050 v2.0、1130 v0.6、1160 v0.8、1170 v0.4、4210 v0.4、4220、4230 v0.18。

当前代码事实：

- `L1所有者范围写端口::提交三分区原子事务_v2` 已发布，恰好支持三个互异 owner、参与者 1/2/3、后向跨参与者节点引用、单一 G1、精确重复、幂等冲突、漂移和已可能发布。
- `L2状态动态原子发布服务` 是现有唯一组合服务，但两个旧迁移入口均固定零写拒绝。
- 特征、状态、动态服务已有正式当前/历史读取、中性状态/动态与中性当前选择；现有组合 helper 仍是旧双参与者语义，不能复活。
- 第一阶段双根通过 legacy `新增特征首值与初始状态_v1` 建立首值和旧首态选择。本叶必须允许第一次真实变化把旧首态转换为中性基线，同时不改写旧历史。
- 本能根初始化当前每次要求 legacy 当前状态值等于特征当前值；真实变化后该条件会过期，因此恢复逻辑必须优先读取中性当前选择。

## 3. 复用与新建裁决

| 能力 | 裁决 |
| --- | --- |
| L1 三分区原子事务 v2 | 直接复用，不修改 L1 |

| 中性状态、引用和读取 | 复用现有物理编码；增加只供组合服务的上下文关系登记、参与者 helper 和完整读回 helper |
| 中性动态和读取 | 复用现有有序状态本体；增加上下文关系登记、参与者 helper 和完整读回 helper |

| legacy 首态 | 只读兼容；第一次变化新建中性基线，不修改或退出 legacy 事实 |
| 普通应用 | 移动现有组合服务构造点到场景服务可用之后，仍只持有一份服务和一组 getter |

## 4. 公开数据合同

数据继续物理落在 `领域/L2状态动态原子发布.数据.h`；状态/动态上下文关系的强类型事实分别落在各自数据头。专属合同版本固定为 1。

```cpp
inline constexpr std::uint32_t L2特征当前值变化记录合同版本_v1 = 1;
inline constexpr 稳定编码 L2特征当前值记录状态角色_v1{
    0x4E53'4355'5252'454EULL};

struct L2特征当前值变化记录请求_v1 final {
    std::uint32_t 合同版本;
    L2结构请求头 请求头;
    L2结构幂等身份 组合幂等身份;
    L2结构幂等身份 特征参与者幂等身份;
    L2结构幂等身份 状态参与者幂等身份;
    L2结构幂等身份 动态参与者幂等身份;
    L2特征实例身份 特征实例;
    L2特征值事实 预期旧当前值;
    L2原始值材料 新值材料;
    std::int64_t 变化UTC纳秒;
    L2存在身份 主体存在;
    L2场景身份 共同场景;
    L2存在身份 来源存在;
    std::optional<L2方法身份> 来源方法;
};
```

四个幂等身份有效且两两不同；G0、全部身份和 UTC 纳秒非零；旧当前值必须是 G0 可见且未退出的完整值事实，属于请求特征实例；新值材料必须满足当前特征定义的值类型和值域。主体必须等于特征实例宿主。共同场景、主体、来源存在及可选来源方法必须在 G0 可由正式结构引用闭合。

状态上下文事实固定为：状态身份、主体、共同场景、特征实例、来源存在、四条关系稳定编码和共同生命周期。动态上下文事实固定为：动态身份、类别、主体、共同场景、被改变特征实例、前/后状态、可选来源方法、可选同源状态迁移动能、来源存在、对应关系编码组和共同生命周期。

动态类别固定：`状态迁移=1、动作致变=2`。状态迁移没有来源方法、来源低层动态和同源迁移动能；动作致变必须同时有来源方法和同源状态迁移动能。来源方法为空时不建立动作致变动态。

写结果物理顺序：合同版本、状态、四幂等身份提交见证、optional 当前值、optional 前状态、optional 后状态、optional 当前选择、optional 已退出旧选择、optional 状态迁移动能、optional 动作致变动态、状态上下文组、动态上下文组、legacy 基线兼容标志、正式截止。

写状态数值：

```text
1 已提交
2 精确重复
3 无变化
4 入口拒绝
5 当前性漂移
6 幂等冲突
7 材料不足
8 引用冲突
9 资源失败
10 内部错误
11 已可能发布
```

`成功()` 对已提交/精确重复要求完整变化载荷和 G1；对无变化只要求旧当前值和 G0，且其它变化载荷全空；其它状态必须空业务载荷。已可能发布只允许返回四幂等身份和 optional G1 见证。

独立读取请求字段顺序：合同版本、共同请求头(Gread)、特征实例、新当前值稳定编码、新当前选择身份、前状态、后状态、状态迁移动能、optional 动作致变动态、首次 G1。读取结果返回与写成功形状相同的业务载荷，但状态固定为 `已读取、入口拒绝、当前性漂移、材料不足、引用冲突、资源失败、内部错误`，非成功载荷空且截止 0。

## 5. 固定物理登记

新增登记不扩展旧不可变登记请求，避免既有数据同键异义：

```text
状态上下文关系类型登记幂等身份 = 0x4C32'5354'4354'5801
状态上下文关系类型本地键       = 0x0204'0501

动态上下文关系类型登记幂等身份 = 0x4C32'4459'4354'5801
动态上下文关系类型本地键       = 0x0205'0401
```

两项由各自服务构造期建立或精确恢复，进入服务构造完整性；不得复用或改写旧状态/动态结构登记。关系 19 和 20 的写入仍落在状态、动态 owner，不新增 owner。

## 6. 三分区写集

### 6.1 特征参与者 1

module-private helper 固定形成：

- 一条新值事实，材料为请求新值；
- 特征实例当前属性槽切换到新值；
- 退出请求完整指定的旧值事实；
- 值来源：有来源方法取方法节点，否则取来源存在节点。

helper 必须先正式读取值类型登记、特征实例、当前槽和值事实；请求旧值任一字段不等于正式读回即返回当前性漂移或引用冲突。

### 6.2 状态参与者 2

正常路径建立：新中性状态、关系 19 四角色、新中性当前选择，并退出旧中性当前选择。新状态的特征类型取特征实例定义，值取请求新值，时间为实例 UTC。

legacy 兼容路径在同一参与者内额外建立：旧值中性基线状态及其四条关系 19。基线时间同本次变化时间，明确表示“迁移时刻读回的旧值基线”，不伪装成第一阶段历史发生时间。新选择直接指向新状态；旧 legacy 状态与选择保持历史只读。

中性选择固定：引用方=`特征实例.值`，引用角色=`L2特征当前值记录状态角色_v1`。后继变化只允许恰一当前选择。

### 6.3 动态参与者 3

始终建立一条状态迁移动能：有序状态组 `[前状态, 后状态]`，关系 20 角色 1/2/3/4/5/9 完整。

请求有来源方法时再建立动作致变动态：同样引用 `[前状态, 后状态]`，关系 20 另含角色 6 来源方法和角色 8 同源状态迁移动能。参与者 3 可以后向引用参与者 2 的状态节点及本参与者先建迁移动能；写集本地键严格固定并由 L1 规范排序。

## 7. 服务算法与错误映射

```text
验证请求
-> 读取 L1 当前 G0
-> 正式读取特征实例、旧当前值、主体、共同场景、来源存在
-> 新旧材料相同：返回无变化，零写
-> 读取中性当前选择
   -> 1 条完整：正常路径
   -> 0 条：读取 legacy 首态；完整且匹配才走兼容路径
   -> 多义/坏闭包：内部错误
-> 三个服务分别形成参与者写集
-> L1 三分区事务一次提交
-> 已提交/精确重复取得首次映射与 G1
-> 以当前 Gread 做读前守卫，以 G1 逐项历史读回
-> 再读当前 Gread 守卫
-> 返回完整结果
```

L1 状态映射：入口拒绝→入口拒绝；事实代次漂移→当前性漂移；幂等冲突→幂等冲突；引用冲突→引用冲突；资源失败→资源失败；内部不一致→内部错误；已可能发布→已可能发布。提交映射或独立读回不完整时，如果 L1 已确认交换则已可能发布，否则内部错误。

精确重复优先于 G0；原请求重放以首次映射/G1读回。新键+旧 G0 为当前性漂移。禁止用新幂等身份重试已可能发布。

## 8. 本能根恢复适配

`提供者.本能根运行初始化` 的根值恢复顺序改为：

1. 读取特征当前值；
2. 按固定引用方/角色读取中性当前选择；
3. 若存在，读取目标中性状态及状态上下文，逐字段验证类型、值、主体和特征实例；
4. 若中性选择不存在且当前值仍等于第一阶段初值，才读取 legacy 首态兼容；
5. 当前值已变化却没有中性记录，或中性记录与值不一致，返回材料不足/内部不一致并停止启动。

本适配不创建状态或动态，不把 legacy 选择重新解释为当前值。

## 9. 装配与依赖

普通应用继续持有唯一 `L2状态动态原子发布服务` 和现有 getter。构造函数增加同实例的存在、场景和特征服务引用以及三分区凭证；构造点移到场景服务已建立之后。三分区凭证验证三个端口有效、绑定同一 L1、owner 两两不同，提交时再固定 participant owner。

不修改 L1，不新建工程生产模块。新增专项测试模块时才修改工程登记。
