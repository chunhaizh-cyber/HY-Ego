# L2-DYNAMIC-REGISTRY-NEUTRAL-WRITE-MIGRATION 动态结构登记中性写入迁移详细设计 v0.2

日期：2026-08-08

状态：设计就绪；替代 v0.1，只冻结后续代码实施合同，不证明代码已经修改、构建、运行或由真实消费者完成业务合同。

## 1. 修订原因与唯一裁决

执行侧在 v0.1 施工中具名退回 `DYNAMIC-REGISTRY-IDEMPOTENCY-ORDER`：v0.1 §6.3 要求提交前读取当前事实代次且必须等于请求期望代次，§6.7、§9、§10 又要求原请求精确重复到达 L1 并复用首次十编码。首次提交会推进事实代次，因此原请求携带的旧期望代次在领域层被提前映射为版本漂移，L1 精确重复分支不可达。

当前正式合同已经唯一裁决，不需要改变机器语义：

1. 4015 §4.2 与 4040 §6 要求同幂等键且规范化完整中性写集逐字段相同返回原结果；同键异写集返回冲突。
2. 当前 `L1事实基座仓库::提交中性写集` 在取得独占许可后，依次裁决：同键同规范化写集精确重复、同键异义冲突、legacy 键占用冲突、期望事实代次漂移，之后才形成候选。
3. `L1中性写集请求::operator==` 覆盖合同版本、期望事实代次、幂等键和完整写集。因此只有原请求精确重复才同义；同键但只更换期望代次仍是异义冲突。

由此冻结唯一控制流：领域层可以在提交前读取当前事实代次，用于确认 L1 入口健康并保存诊断快照，但不得用预读代次与请求期望代次的不等提前阻断提交。每个合法请求都恰一次到达 `提交中性写集`，由 L1 按上述顺序最终裁决。首次路径的新键旧代次由 L1 返回事实代次漂移；原请求精确重复即使当前代次已经推进，也由 L1 返回首次十编码；同键异义由 L1 返回幂等冲突。

## 2. 目标与完成边界

把 `L1动态服务::建立登记` 从 legacy 领域意图、幂等预探测、完整快照和带业务标签提交迁移为正式业务中性 CRUD：领域服务自行校验公开请求并解释结构化结果，只向 L1 提交恰十个节点的不可变中性写集、期望事实代次和不透明幂等键。登记发布成功或精确重复后，领域服务按 L1 返回的十个稳定编码从当前事实精确读回，再形成现有 `L1动态结构登记`。

本设计保持下列公开合同不变：

- `L1动态登记请求`、`L1动态登记结果`、`L1动态结构登记` 的字段、默认值和可见性；
- `L1动态服务::建立登记(const L1动态登记请求&)`；
- `L1动态服务::读取当前登记() const`；
- `L1动态服务(L1事实基座服务&)` 的构造和对象所有权；
- 登记幂等域 `0x0F` 及现有业务结果枚举。

完成条件是目标两份生产代码在本叶范围内满足：建立登记不再产生或提交业务标签、意图组、入口变体、领域意图凭证，不再调用旧幂等探测、完整快照或 legacy 写入口；恰一次提交固定十节点中性写集；提交前代次预读不提前裁决漂移；成功类结果的十项映射完整唯一；建立登记和读取当前登记均以中性当前代次首末一致、十节点精确当前读取闭合。

## 6. 建立登记唯一控制流

1. 取得现有递归互斥锁并进入现有异常边界。
2. 校验公开请求；失败返回 `入口拒绝`、无登记、零提交。
3. 调用一次 `读取中性当前事实代次`，得到预读代次 P。结果必须为成功、合同版本精确、P 非零；否则映射读取非成功。P 只证明入口可用并为首次成功一致性提供诊断，**不得在提交前比较 `P == 请求.期望事实代次` 后提前返回**。
4. 映射中性幂等键，形成 §5 固定写集，原样保留请求期望代次。
5. 物理调用 `提交中性写集` 恰一次；不得先探测幂等，不得因 P 与请求期望值不等跳过该调用。
6. 先按 L1 返回状态裁决：
   - `精确重复`：允许 P 不等于请求期望代次；核对重复结果合同并继续十编码读回。
   - `成功`：除成功结果合同外，P 必须等于请求期望代次；若不等却返回成功，说明当前 L1 顺序或结果与冻结合同矛盾，返回 `内部不一致`。P 与期望相等后发生并发发布时，L1 仍可合法返回漂移，不能用 P 覆盖 L1 结果。
   - `幂等冲突`、`事实代次漂移`、`入口拒绝`、`未找到`、`已退出`、`资源失败`、`内部不一致`：按 §7 映射并返回，不带登记。任何预读判断不得覆盖这些 L1 最终状态。
7. 成功类结果必须核对合同版本、回显幂等键、非零事实代次和十项新编码映射完整唯一。首次成功要求发布标志为 true、重试边界为 `不适用`；精确重复要求发布标志为 false、重试边界为 `原幂等键读回收敛`。矛盾返回 `内部不一致`。
8. 按本地键 1—10 取得十编码，执行 §8 当前事实读回。只在读回完整时更新 `登记_` 并统一返回 `已登记`。
9. `std::bad_alloc` 映射 `资源失败`，其它未知异常映射 `内部不一致`。

### 6.1 顺序矩阵

| 请求 / 当前状态 | L1 最终裁决 | 领域结果 |
| --- | --- | --- |
| 新键，P 等于期望，提交时仍同代 | 成功并发布新代次 | 精确读回后已登记 |
| 原请求精确重复，当前代次已高于原期望 | 精确重复，复用首次十编码，不发布 | 精确读回后已登记 |
| 同键、同十节点但更换期望代次 | 幂等冲突，因为完整规范化请求不同 | 幂等冲突 |
| 新键，P 已不等于期望 | 事实代次漂移，零发布 | 版本漂移 |
| 新键，P 等于期望但提交前发生竞争发布 | 事实代次漂移，零发布 | 版本漂移 |

## 7. 中性状态映射

| L1 中性写入状态 | L1动态状态 | 登记材料 |
| --- | --- | --- |
| 成功 | 已登记 | 成功合同、P 一致性和精确读回完成后携带 |
| 精确重复 | 已登记 | 重复合同和精确读回完成后携带；P 可高于原期望 |
| 幂等冲突 | 幂等冲突 | 无 |
| 事实代次漂移 | 版本漂移 | 无 |
| 资源失败 | 资源失败 | 无 |
| 内部不一致 | 内部不一致 | 无 |
| 入口拒绝 | 入口拒绝 | 无 |
| 未找到、已退出 | 未找到 | 无 |

任何成功状态而合同、映射或读回不完整都升级为 `内部不一致`，不得伪造登记。读取状态中的未找到 / 已退出 / 属性未设置映射为未找到，资源失败 / 入口拒绝 / 内部不一致保持对应业务分类。

## 8. 十稳定编码精确中性读回

共享私有 helper 由建立登记和读取当前登记复用：

1. 输入首次幂等身份和十个稳定编码，验证身份、编码有效且两两不同。
2. 读取当前事实代次 G0，要求成功、合同版本精确、G0 非零。
3. 按固定顺序对十编码各调用一次 `读取中性当前节点`。每项要求状态成功、合同版本精确、查询编码回显一致、读取事实代次等于 G0、事实存在、事实编码一致、未退出，并符合 §5 节点形状。
4. 再读取当前事实代次 G1，要求成功、合同版本精确、G1 非零且等于 G0。节点代次、G0、G1 任一不等返回 `版本漂移`，不返回混代登记。
5. 只在全部成立时组装现有 `L1动态结构登记`，`事实截止代次=G0`，完成完整性校验后返回。

L1 写入结果的 `事实代次` 表示首次发布代次；读回登记的 `事实截止代次` 表示本次当前读回的 G0。精确重复时二者可以不同，不得强制相等。`读取当前登记()` 只从 `登记_` 复制定位身份和十编码；无完整缓存返回 `登记未加载`，否则调用 helper，成功映射为 `已读取`。

## 9. 并发、失败与生命周期

- 服务互斥锁只串行保护领域定位缓存；L1 的幂等、代次和原子发布由 `提交中性写集` 自身最终裁决。
- 预读 P 不是幂等探测、事务许可或提交授权。L1 返回状态优先，P 只能在 L1 返回首次成功时用于检查不可能合同矛盾。
- 精确重复复用首次十编码并零新发布；同键异义包括只改变期望代次，由 L1 返回冲突。
- 发布后读回期间发生其它发布时返回版本漂移；不缓存混代材料、不重试、不补写、不生成第二幂等键。
- `登记_` 不是事实权威；L1 当前读取裁决节点是否存在、退出和形状是否一致。
- 发布成功后读回异常不能撤销已发布事实，只返回结构化非成功并保留 L1 实际状态。
