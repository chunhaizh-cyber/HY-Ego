## 1. 目标与边界

本设计补齐 P01 消息闭环所依赖的最早 task-owner 提供者：新任务形成时，在同一个 task-owner 原子写集中形成首个任务轮次 `R1` 和唯一当前关系 `T→当前R1`，并提供按任务、同一事实截止 `G0` 读取当前任务与当前轮次的公开入口。

固定因果链为：

```text
存在 owner 已建立任务专属 E
-> task owner 原子建立 T + T→L + 首条 T→D + T→E + R1 + T→当前R1
-> task owner 独立读回整个任务核心
-> 任务管理线程在派发筹办工作包前按 G0 读取 T 与当前 R
-> P01 把该 R 写入工作包
-> 每次筹办结束形成一个结果，并通过消息回送任务管理线程
```

最后两步属于 P01。本设计不建立消息、线程、筹办结果、回执、持久 outbox、主阶段治理、轮次结算或自我后继，不形成第二套账。

```cpp
        const L2按任务读取当前任务与轮次请求&) = default;
};

inline bool L2按任务读取当前任务与轮次请求有效(
    const L2按任务读取当前任务与轮次请求& 请求) noexcept {
    return 请求.合同版本 == L2按任务读取当前任务与轮次合同版本
        && 请求.请求头.合同版本 == L2结构合同版本
        && L2任务结构请求头合同有效(请求.请求头)
        && 请求.请求头.期望事实代次 != 0
        && 有效(请求.任务.值);
}

enum class L2按任务读取当前任务与轮次状态 : std::uint8_t {
    已读取 = 1,
    任务未找到 = 2,
    当前轮次未找到 = 3,
    任务已退出 = 4,
    入口拒绝 = 8,
    许可拒绝 = 9,
    事实代次漂移 = 10,
    关系多义 = 11,
    引用冲突 = 12,
    资源失败 = 13,
    内部不一致 = 14
};

struct L2按任务读取当前任务与轮次结果 final {
    std::uint32_t 合同版本 = L2按任务读取当前任务与轮次合同版本;
    L2结构结果头 结果头;
    L2按任务读取当前任务与轮次状态 状态 =
        L2按任务读取当前任务与轮次状态::内部不一致;
    std::optional<L2任务事实> 任务;
    std::optional<L2任务轮次事实> 当前任务轮次;
    std::uint64_t 本次正式读回截止 = 0;
    bool 成功() const noexcept {
        if (合同版本 != L2按任务读取当前任务与轮次合同版本
            || 结果头.合同版本 != L2结构合同版本
            || 结果头.状态 != L2结构状态::已读取
            || 状态 != L2按任务读取当前任务与轮次状态::已读取
            || 结果头.事实截止代次 == 0 || 结果头.变更事实代次
            || 本次正式读回截止 != 结果头.事实截止代次
            || !任务 || !当前任务轮次)
            return false;
        const auto G0 = 本次正式读回截止;
        return 有效(任务->身份.值) && 有效(任务->需求列表项.值)
            && 有效(任务->任务虚拟存在.值)
            && 任务->生命周期.创建事实代次 != 0
            && 任务->生命周期.创建事实代次 <= G0
            && !任务->生命周期.退出事实代次
            && L2任务轮次事实完整(*当前任务轮次)
            && 当前任务轮次->任务 == 任务->身份
            && 当前任务轮次->生命周期.创建事实代次 <= G0
            && !当前任务轮次->生命周期.退出事实代次;
    }
    friend bool operator==(const L2按任务读取当前任务与轮次结果&,
        const L2按任务读取当前任务与轮次结果&) = default;
};

L2按任务读取当前任务与轮次结果 按任务读取当前任务与轮次(
    L2按任务读取当前任务与轮次请求 请求) const noexcept;
```

`许可拒绝=9`保留，因为该入口复用 L1 owner-aware 当前节点、关系组和值读取，L1 读取状态可能明确返回许可拒绝；它只机械映射为公共`许可拒绝`和专用`许可拒绝`，不得由 task owner 自行推断权限。

一个当前任务缺少本应单例的 `T→当前R`关系时，专用状态使用`当前轮次未找到=3`保存精确诊断，但公共`结果头.状态`必须为`L2结构状态::内部不一致`；不得作为合法空或普通未找到。

完整映射矩阵冻结为：

| 条件 | 公共状态 | 专用状态 |
| --- | --- | --- |
| 坏专属版本、共同头、G0 或 T | `入口拒绝` | `入口拒绝=8` |
| T 从未形成 | `未找到` | `任务未找到=2` |
| T 在 G0 已退出 | `已退出` | `任务已退出=4` |
| L1 owner-aware 读取许可拒绝 | `许可拒绝` | `许可拒绝=9` |
| 当前 `T→R` 为 0 条 | `内部不一致` | `当前轮次未找到=3` |
| 当前 `T→R` 恰一条且 T/R 完整 | `已读取` | `已读取=1` |
| 当前 `T→R` 多于一条 | `内部不一致` | `关系多义=11` |
| owner、类型、端点、角色、T/R 或生命周期冲突 | `内部不一致` | `引用冲突=12` |
| 读前或读后当前代次不等于 G0 | `事实代次漂移` | `事实代次漂移=10` |
| `std::bad_alloc`或`std::length_error` | `资源失败` | `资源失败=13` |
| 底层状态/载荷矛盾或其它异常 | `内部不一致` | `内部不一致=14` |

实现固定为一次 task-owner 锁内结构化投影：

```text
读前当前代次 == G0
-> 读取 T 当前投影并区分从未存在 / 已退出
-> 读取 T→当前R 活动关系组
   0 条：内部不一致 / 当前轮次未找到
   1 条：继续
   >1 条：内部不一致 / 关系多义
-> 按关系目标重建 R 并互证 owner、族、R→T、序号和生命周期
-> 读后当前代次 == G0
-> 返回 T、R，结果头截止和本次正式读回截止均等于 G0
```

禁止先做多次探测再由 optional helper 重读；内部投影一次返回结构化状态，公开入口只映射一次。所有非成功结果只保留固定合同版本与对应状态，任务和轮次载荷为空、截止为零。

`成功()`不得捕获请求；它只检查结果自身闭包：专属合同版本和`结果头.合同版本 == L2结构合同版本`，公共状态为`已读取`、专用状态为`已读取=1`、结果头变更代次为空，两项载荷存在；T 和 R 均在结果截止活动，`R.任务 == T.身份`且 R 完整；`本次正式读回截止 == 结果头.事实截止代次 != 0`。公开函数的后置条件再独立断言任务等于请求任务且该截止等于请求 G0。

内部物理结构固定为：

```cpp
struct 当前任务轮次结构化投影 final;
当前任务轮次结构化投影 读取当前任务轮次结构化投影(
    L2任务身份 任务, std::uint64_t G0) const noexcept;
```

该 helper 在已持有 task-owner 锁时完成一次底层读取序列，直接返回公共状态、专用状态、T、R和截止；不得返回裸`optional`令公开入口再次探测。

## 6. 依赖、所有权和失败边界

- 唯一写入 owner 为既有 `L2任务结构服务`及其 L1 owner-aware 写端口；
- 复用既有任务身份来源、任务结构类型、当前任务投影、`读取中性当前事实代次`、互斥体和首次写入读回能力；
- 不新增仓储、线程、队列、缓存、定时器或持久记录；
- 资源失败和其它异常均返回结构化失败，非成功零载荷；
- 写入成功但读回不完整属于内部不一致，不得返回部分成功；
- 同幂等身份同完整请求精确重复；同键异义由 L1 幂等边界拒绝；
- 本设计不改变筹办 provider 的结果分支。每次筹办的唯一结果仍由 P01 包装成一条消息回送任务管理线程。

P00 的生产调用边界只到正式写/读服务和既有专项 harness。P00 不修改白名单外普通业务调用点，也不把旧融合入口迁为新入口。P01 只有在 P00 provider 专项成功证据存在且上述正式接口可用后才允许激活；普通任务创建的生产接线仍由本能路线后继计划拥有。一个结果联合体的五个互斥分支、工作线程处理和回送任务管理线程的消息均仍属 P01。
