# 动态结构登记生产运行期接线详细设计 v0.1

日期：2026-08-08

状态：设计就绪；只冻结后续实施合同，不证明代码、生产运行或第一层完善。

## 1. 目标与最早缺口

当前 `L1动态服务` 已具备十节点动态结构登记、当前登记读回和状态迁移动能规格能力，但生产运行期上下文没有拥有该服务，生产启动也没有调用动态登记。另一方面，首个基准状态要求已经存在合法的 I64 特征定义与实例特征；当前生产初始化没有这份业务输入，不能为证明第一层而补造。

本叶只闭合最早且真实需要的下游缺口：

```text
生产运行期构造唯一 L1动态服务
-> 在状态结构登记成功后建立动态结构登记
-> 经同一第二层公开服务权威读回登记
-> 把动态登记完整性纳入候选上下文发布条件
-> 发布后的运行期租约只读暴露同一服务
```

这是第二层动态服务自身的生产初始化。它不是第一层自证、专项消费者、覆盖补格，也不创建动态事实。

## 2. 正式依据与当前事实

- 4015：第一层只承担业务中性 CRUD、原子提交和最小幂等；能力证据只由第二至第五层真实业务使用自然累计。
- 4030：动态结构和结果解释由具名领域服务负责，第一层不得理解动态语义，也不得为覆盖矩阵制造请求。
- 4050：入口拒绝、未找到、许可拒绝、资源失败和内部不一致必须保留结构化分账。
- 4190、4210：动态属于状态与状态变化领域；动态登记是后继动态形成的必要领域基础。
- 8120、ACCEPTANCE-01：生产入口不承载自检或验收运行器；日志只供人观察。

当前代码事实：

1. `L1动态服务` 构造只需要 `L1事实基座服务&`，该对象已由 `运行期上下文` 唯一拥有。
2. `L1动态服务::建立登记` 已形成十节点中性写集、恰一次调用 `提交中性写集`，随后按十项新编码精确读回并保存登记定位。
3. `L1动态服务::读取当前登记` 已通过十节点权威当前读取返回值式完整登记。
4. 生产运行期当前已经真实初始化世界、场景、实际存在和状态登记；没有动态服务成员、配置身份、初始化入口或候选完整性读回。
5. 首个基准状态发布需要 `实际存在I64实例特征读取请求`，当前生产链没有创建可供使用的 I64 特征定义或实例特征，因此它不是本轮可合法施工的更早叶。
6. 当前计划索引没有可执行项；共享生产文件已由上一计划释放，异主修复、路线、旧世界树和 `.codex-build` 与本设计包不重叠。

## 3. 唯一所有权与物理位置

不新建动态 DTO 或动态服务。唯一服务对象仍为：

```cpp
海中鱼巣::L1动态服务
```

生产生命周期唯一所有者为：

```cpp
海中鱼巣::运行期上下文
```

精确生产文件：

```text
海中鱼巣/启动.运行期上下文.ixx
海中鱼巣/启动.生产运行期.ixx
海中鱼巣/生产运行期配置.数据.h
```

`L1动态.数据.h`、`服务.L1动态.ixx`、状态服务、核心第一层和其它领域文件保持不变。

## 4. 运行期上下文合同

### 4.1 构造与成员顺序

`启动.运行期上下文.ixx` 增加：

```cpp
export import 海中鱼巣.领域.服务.L1动态;
```

成员顺序固定为：

```text
L1事实基座服务
-> 世界 / 场景 / 实际存在 / 特征服务
-> L1状态服务
-> L1动态服务
```

构造固定为：

```cpp
L1动态服务_(L1事实基座服务_)
```

不得建立第二个第一层服务、动态分配包装器、代理服务或第二动态解释者。

### 4.2 公开上下文入口

新增三个窄入口：

```cpp
L1动态登记结果 初始化动态登记(const L1动态登记请求& 请求);
L1动态登记结果 读取动态登记() const;
bool 动态登记完整() const;
```

规则：

- 初始化入口只校验结构核心和正式请求，恰一次委托 `L1动态服务::建立登记` 并原样返回；
- 读取入口恰一次委托 `L1动态服务::读取当前登记`；
- 完整判断只接受 `已读取 + 非空完整登记`；
- 新增 const / 非 const `读取L1动态服务()`，只返回同一成员引用，不复制动态业务语义。

### 4.3 候选完整性

`运行期上下文::完整()` 增加一次动态登记当前读回。发布候选必须同时满足：

- 动态登记结果为 `已读取`；
- 登记非空且通过 `L1动态结构登记完整`；
- 动态登记事实截止与本轮世界登记、初始场景、实际存在登记、初始场景实际存在和状态登记的当前共同截止完全相同。

该检查只保证候选发布时各领域当前投影同代次，不让第一层判断动态业务正确。

## 5. 固定生产配置

`生产运行期配置` 新增：

```cpp
动态操作幂等身份 动态登记幂等身份;
```

固定配置取 `{1}`。该值只在动态登记私有幂等域有效，不与状态或其它领域身份合并。配置等值和有效性同步核对该字段。

`生产运行期配置.数据.h` 在没有由模块导入动态数据时才包含 `领域/L1动态.数据.h`；`启动.生产运行期.ixx` 使用显式动态数据宏边界，避免重复声明。

不增加命令行覆盖、环境变量、配置文件、随机身份或运行时默认补造。

## 6. 生产启动流程

在状态结构登记成功之后、系统角色初始化之前，形成：

```cpp
const L1动态登记请求 动态登记请求值{
    L1动态合同版本,
    L1动态规则版本,
    配置.动态登记幂等身份,
    状态登记结果值.登记->事实截止代次};
```

然后恰一次调用：

```cpp
候选->初始化动态登记(动态登记请求值)
```

成功只接受 `已登记 + 非空完整登记`。其它结果立即返回新增的 `动态登记初始化错误`，不继续系统角色、概念活动或候选发布。

`生产运行期启动结果` 增加动态登记业务状态。首次成功、已有当前上下文和各失败分支按真实已执行阶段回显；未执行阶段保持入口拒绝。已有当前上下文分支使用 `已读取`，不得用退出码、日志或默认值冒充领域结果。

## 7. 事务、幂等和失败边界

- 本叶不修改动态服务事务；十节点仍由一次现有中性写集原子提交。
- 同一固定请求依现有中性幂等合同收敛；本计划不增加第二幂等账、摘要或业务标签。
- 动态登记失败时候选不发布；不增加撤销协议、重试循环或跨进程恢复。
- 领域状态由动态服务结构化返回，启动层只映射为动态登记初始化错误并保留原状态。
- 当前阶段不处理崩溃、重启、断电或跨进程恢复。

## 8. 明确排除

- 第一层新接口、DTO、索引、锁、缓存、审计或恢复逻辑；
- 第一层自检、专项消费者、独立验收、第二目标或覆盖补格；
- I64 特征定义、实例特征、首个或后继状态；
- 动态事实、状态迁移动能、比较、因果或世界树门面；
- 普通应用旧栈、系统角色或概念活动业务语义；
- 通过日志、构建或单次运行宣称整个第二层或第一层完善。

## 9. 验证与完成边界

实施至少验证：

1. 三个生产文件和两份专属记录以外零本轮差异；
2. 运行期上下文恰一动态服务成员、恰一构造和一对访问器；
3. 生产启动恰一次动态登记初始化，位于状态登记成功后、系统角色前；
4. 配置身份固定并参与等值和有效性；
5. 候选完整性真实读取动态登记并与全部当前基础材料互证共同截止；
6. 生产代码不新增自检、验收、驱动、第二目标或日志 PASS；
7. Debug / Release 完整重建、双配置模块扫描、strict 和两配置正式生产运行期模式通过。

本叶完成只证明第二层动态结构登记成为生产运行期真实初始化能力，并在候选发布前经自身公开读回闭合。它累计十节点中性新增、原子可读和当前查询的实际使用；不证明精确重复、非法请求、修改、退出 / 历史、动态事实、因果、全部下游服务或第一层完善。
