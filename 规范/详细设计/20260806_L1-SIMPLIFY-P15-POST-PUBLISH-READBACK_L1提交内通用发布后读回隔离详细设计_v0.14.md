## 1. 裁决

v0.14 替代并禁止施工 v0.13。保留 v0.13 的 16 文件、32 个生产/业务场景行、18 个自检调用行和 50 个物理调用点的闭合映射、模式1/2/3、共享操作标签和发布后读回合同。本版本只绑定三个未闭合事实：L1 provider 的真实稳定身份与合同版本、provider 调用次数与去重见证数量的分账、恢复和静态门禁的对应校验。

正式 HEAD 的 4015/4020 只规定 L1 的事实边界与分层合同；执行 WIP 中已经采用 `L1事实基座合同版本=2`，但当前正式基线没有公开 provider 身份读取接口。v0.14 把该缺口冻结为待实现合同，不把 WIP 当作已发布能力。

## 2. 唯一 L1 provider 身份来源

P-L1-S（完整快照）、P-L1-F（节点/关系/值/属性读取）和原 P-C（自检夹具）不再是三个 provider。它们全部归属于同一个稳定 provider：`L1事实基座服务`。P-C 改名为 `P-L1-F(自检面)`，自检夹具只通过 L1 服务读取，不携带独立 provider 身份。

### 2.1 DTO、物理位置和生命周期

在现有白名单文件内增加以下只读合同，不新增模块或文件：

```text
物理 DTO：海中鱼巣/核心/L1事实基座.数据.h
公开声明：海中鱼巣/核心/合同.L1事实基座.ixx
唯一实现：海中鱼巣/核心/服务.L1事实基座.ixx

L1提供者身份凭证 {
    std::uint64_t 稳定身份 = 0x4C31464200000001;
    std::uint32_t 合同版本 = 2;
    std::uint32_t 规则版本 = 0;       // L1 中性 provider，无领域规则
}
L1事实基座服务::读取提供者身份() const noexcept -> L1提供者身份凭证
```

该值是 L1 provider 身份域唯一分配的不可变身份，不是节点/关系/值事实稳定编码，不由写集分配、不随实例、不随调用面变化。服务构造后身份只读并活到服务实例销毁；函数无锁、无事实读取、无代次变化，任何领域服务可读。调用顺序固定为“先编码公开请求意图并执行 `探测幂等`，仅 `未找到` 后读取身份，再读取实际事实 provider”；身份读取是合同见证读取，不计入事实 provider 调用次数。若身份为零、版本不是 `(2,0)`、同一运行期实例两次返回不同值，入口拒绝并零写入。`规则版本=0` 仅对这个精确 L1 身份合法；领域 provider 的规则版本仍必须非零。

### 2.2 版本组与调用统计 DTO

把现有 `L1提供者版本见证` 扩展为以下强类型、公开只读值式字段（字段顺序也是规范化编码顺序）：

```text
std::uint64_t 稳定身份;
std::uint32_t 合同版本;
std::uint32_t 规则版本;
std::uint32_t 调用次数;
```

所有整数按网络字节序编码；调用次数不得溢出 `std::uint32_t`，溢出即入口拒绝。版本组按稳定身份唯一升序；调用次数是该身份本次首次路径实际 provider 函数调用总数，不能用去重项数替代。L1 身份在 P-L1-S 与 P-L1-F 之间合并为一个见证项，调用次数相加。P-C 不再产生第二项。

## 4. 摘要、恢复和拒绝

执行证据材料编码新增 `L1提供者版本见证.调用次数`；版本组项目仍按身份升序，项目字段严格为 `稳定身份(U64)、合同版本(U32)、规则版本(U32)、调用次数(U32)`，调用次数字段紧随规则版本。材料摘要和首次执行证据摘要都包含该字段。请求意图摘要不包含 provider 身份、版本或调用次数。

恢复重算除 v0.13 原有模式、共同截止、写前事实、双账和读回检查外，增加：

1. 每个 L1 见证身份必须等于 `L1事实基座服务::读取提供者身份()` 的 `(0x4C31464200000001,2,0)`；P-L1-S/P-L1-F/P-C 分裂身份、旧合同1、领域规则版本0或未知身份均为 `材料不完整`。
2. 版本组每项调用次数必须等于对应 50 点矩阵的首次调用总数，且去重后的项目数等于矩阵去重数；同一身份重复项目、调用次数为零、账审计不等均为 `材料不完整`。
3. provider 实际调用次数只用于证据互证，不改变事实代次和幂等身份；同义重试严格 `0/0`，不得重新读取 provider。
4. L1 provider 身份读取失败、合同版本漂移、身份不一致在提交前入口拒绝；恢复阶段材料字段缺失或重算不等拒绝候选，双账/发布后读回矛盾为内部不一致并隔离。

## 5. 物理范围和静态门禁

不新增模块、工程、filters、启动文件或顺序；仍只允许 v0.13 的 20 文件白名单。新增/扩展的 DTO、身份读取接口和编码只落在 `核心/L1事实基座.数据.h`、`核心/合同.L1事实基座.ixx`、`核心/服务.L1事实基座.ixx` 及既有 16 个调用点文件。

创建侧门禁必须同时通过：strict、diff check、L1 合同版本为2、身份常量唯一且非零、P-L1-S/P-L1-F/P-C 合并为一个 provider 身份、32/32 生产/业务场景、18/18 自检调用行、32→50 映射唯一、展开后 50/50 物理调用点闭合、调用/去重列均存在且与上述数值一致、模式1/3为0/0、同义/异义/隔离为0/0、领域模式2首次项非零、恢复拒绝矩阵包含身份/版本/调用次数/去重数四项。执行侧再验证真实接口、构建、自检和运行恢复；本设计不宣称代码能力已完成。
