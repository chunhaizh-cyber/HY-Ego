## 1. 目标、范围和非目标

目标是把一条既有任务的内部治理改成下列职责顺序：

```text
筹办：找候选方法，找每个方法自己的条件组
-> manager：按消息独立读回并路由
-> self：确认是否真有需要，管理其后继
-> demand owner：建立或复用正式需求
-> 执行前：fresh 判断可用性，选择一个可执行选项并冻结
-> 既有授权 / 硬否决 / 调度 / 动作 / 结果链
```

范围只包括筹办发现、线程交接、需求确认、执行前选择与既有选择 / 冻结的时机调整。

### 1.1 先骨架、后血肉的实现顺序

本设计将用户要求的“自我管理需求、任务管理推进任务进程”固定为实现顺序，不把它解释成新的通用请求账、普通方法注册表或跨 owner 直接写入：

```text
外层需求治理骨架
self fresh 确认 / 编排
-> 需求领域服务建立或复用 D
-> self 发布绑定 D 的不可变任务发起意图
-> manager 独立读回意图与 D
-> 请求任务领域“按具体需求承接或复用任务”入口
   - 新任务：存在 owner 建 E；task owner 建 T、T→L、T→D、T→E 与 R1，完成首态、P1/A1、首迁移及各 owner 正式读回
   - 既有任务：复核 / 复用既有 T，幂等建立 T→D，并按既有分支正式读回

任务内层推进骨架
筹办发现
-> 执行前选择 / 冻结后执行
-> 正式结果独立读回、任务轮次结算 / 收束
-> self 决定继续、结束、等待或取消
```

这里的“自我管理需求”只指 fresh 确认、优先级和后继编排；需求领域服务仍是写入或复用 `D` 及其父子关系的唯一入口。“manager 生成任务”只指 manager 独立读回后请求 task owner 的正式承接 / 复用入口；manager 不裸写任务，也不据此确认需求成立。`T + R1`不是可省略首态合同的简称：新任务必须闭合 `E`、`T→L / T→D / T→E`、`R1`、首态、`P1/A1`、首迁移和逐 owner 正式读回；既有任务则按独立的承接 / 复用分支处理。

两条方向不得倒置：已有 `D` 启动任务时是上图的 `self -> manager -> 任务领域`；筹办发现缺口后则是 `manager -> self fresh 确认 -> task owner 发布 / 重放带自我确认来源的承接记录 -> 需求领域建立或复用子 D`。后者形成的子 `D` 若需任务，仍重新走前一条任务发起链；self 不直写 `D`，manager 不直建子任务。筹办、执行、结算是任务进程的三个主阶段，不是进入普通方法候选集的三个方法：筹办只发现，执行必须包含执行前选择 / 冻结子段，结算不等于需求满足。

本输入不：

- 新建服务合同、服务预算、服务余额、预期收益账、筹办历史账、持久 outbox、第二结果账、专用筹办线程或第二消息通道；
- 把服务根当前值、服务合同余额或服务进展作为自动方法代价；
- 改变 6100 / 6140 的实际安全值结算，或把执行前预测写成安全 / 服务实际值；
- 声称当前代码、P01 消息链、P02 子目标准入、运行测试或整条本能路线已完成。

## 2. 已确认的业务合同

### 2.1 筹办发现

筹办只回答“当前有哪些可能方法、它们各自需要哪些条件、哪些材料当前缺失”。它不回答“该任务应当采用哪一个方法”，也不把任一方法写成已采用。

每个发现候选必须保留：

```text
方法身份
+ 方法内容版本 / 规格版本 / 生命周期读回身份
+ 目标结果或用途的正式引用
+ 0..N 个该方法自己的条件组
```

每个条件组是一次执行可选项的值式部分：

```text
规范有序的条件 / 条件结果关系集合
+ 输入、参数和限制绑定材料
+ 各项在来源截止的可读状态（满足 / 缺失 / 结构缺失 / 漂移）
```

条件组内部按方法合同共同成立；组间可替代、可组合或其它关系只能由同一方法内容版本的正式组合条件关系显式声明。没有强类型组身份或组合语义时，返回`条件组结构缺口`，不猜测“多个组天然可替代”。条件组是由既有条件关系和绑定材料组成的值式投影，不建立新的持久条件组节点、历史账或任务级总条件清单。

因此发现结果可表达：

```text
M1@V1 -> C11 / C12
M2@V7 -> C21
```

`方法缺失`是完整粗召回后候选为空的发现；`条件缺失`精确属于某个“方法 + 版本 + 条件组 + 条件”组合。两者都不是需求，也不能自动演变为子任务。

### 2.2 每个工作包的一条消息

保留“一个已消费筹办工作包最终只投递一条不可变消息；队满只重投同一消息；manager 已接收或精确重复后工作包才结束”的协议。

未来消息承载的是一次`筹办发现`定位，而不是现行五类互斥业务结果。正常发现以候选、条件组、缺口和来源事实的强类型定位为载荷；当前性漂移、引用冲突、资源失败和内部错误仍走结构化非成功，不能静默结束。

消息不是正式候选、条件、需求、路径、选择或冻结事实。manager 必须使用任务、任务轮次、筹办轮次、工作包、来源截止和结果截止重新读取各 owner 的正式事实。

目标已满足、合法等待、正式子目标承接和执行冻结不再是筹办消息的业务结果：它们分别由目标比较、self 后继治理、确认后的正式需求承接和执行前选择 / 冻结链处理。

### 2.3 初次与后继来源

筹办传输请求必须以一个强类型判别联合同时承载：

```text
初次筹办来源：任务初次筹办工作包
后继筹办来源：下一筹办工作包
```

两个分支都绑定任务、任务身份来源、来源需求、任务轮次、筹办轮次、G0 和幂等身份；它们不能由裸序号、消息外层字段或空 optional 互相伪装。复用一条工作包运输协议和一条结果消息，不创建初次筹办的平行线程或平行队列。

## 3. manager、自我和需求领域的边界

### 3.1 manager 独立读回后只路由

manager 不重跑候选发现、不选择方法、不形成条件结论、不直接写需求或子任务。它收到筹办发现后：

```text
验证不可变消息与工作包身份
-> 按同一事实截止独立读回任务、轮次、候选方法、条件组和缺口
-> 可进入执行前判断的候选：编排执行前选择工作项
-> 需要需求治理的发现：向 self 发缺口定位
-> 当前性 / 引用 / 资源问题：转交既有结构化非成功或具名后继 owner；manager 不生成等待合同
```

正式 HEAD 没有方法 / 条件缺口的 manager -> self 消息。因此新增的是**既有自我治理消息协议中的一个强类型“筹办发现缺口定位”分支**，不是新的消息通道。最小载荷只含任务、父需求、任务 / 筹办轮次、工作包、来源 / 结果截止、发现类别、方法与版本、条件组 / 条件或粗召回证据、候选独立目标定位、合法生产者与重触发材料。消息不携带 manager 的需求结论。

### 3.2 self 确认，需求 owner 写入或复用

self 收到定位必须 fresh 读取父需求、目标合同、任务 / 轮次、候选材料和当前事实。它只能形成基于正式材料的后继治理意图：

| fresh 结论 | 后继 |
| --- | --- |
| 外部事实未产生、时间未到、材料可由已知 owner 产生 | 正式等待及重触发；不建需求 |
| 已有方法但输入、入口、验证或归因合同缺失 | 当前任务结构缺口或等待；不自动建需求 |
| 独立目标确实必要、父域合法、目标合同可最终判定 | 形成 self 确认的承接意图 |
| 粗召回完整为空且学习目标满足独立目标门禁 | 可形成同一类承接意图；不是自动学习需求 |
| 粗召回非空但候选当前均不可用 / 不适用 | 不得伪装为方法缺失或学习需求 |

self 确认后的意图通过既有 self 治理交接进入 task owner。task owner 以公开入口发布或精确重放既有`任务子目标承接记录`；需求领域服务独立读回该记录，建立或复用正式子需求并绑定回记录。manager 只是转运和编排者，不能代替 self 确认或需求 owner 写入。

现有子目标记录当前主要携带方法版本和条件来源。正式收口必须扩展 / 重构其来源联合，使它能区分“已确认条件目标”“合法学习目标”“不应承接的结构缺口”，但不得用布尔门禁、文本、裸编码或第二证明账填充缺失语义。

## 4. 执行前可用性、选择和冻结

### 4.1 执行选项与硬过滤

执行前的值式选项是：

```text
方法身份 + 方法内容版本 + 条件组 + 输入 / 参数绑定 + 动作范围
```

在一个 fresh 事实截止下，只有同时通过以下硬门的选项才可进入比较：

```text
目标 / 结果合同允许
方法生命周期、内容版本和动作入口当前
本选项自己的条件组、输入和参数闭合
作用范围、验证和归因合同完整
禁止项、结构拒绝和安全硬否决未命中
生存安全根控制态允许普通执行竞争
```

任何不通过的选项不进入比较。安全硬否决不能由时间、资源、服务目标或任何收益抵销；`A=0/1` 不能被普通服务任务绕过。6150 调度倍率仍只在冻结后、真实派发前用于安全任务调度排序，不是方法选择、成本或授权。

### 4.2 选择

硬过滤后才进行实际适用性判断和选项选择。结果一致、条件 / 输入闭合、禁止 / 风险、运行质量的现有分层原则必须在新的执行前入口中重新冻结，而不留给 worker 临场判断。

目前不引入把安全、服务和时间相加的“最小代价”公式：

- 安全实际值只通过 6100 / 6140 的事后正式链变化；跨安全层原始值不可相加。
- 服务根当前值、服务合同、余额、预支、进展、准备和衰减账已退出；它们不能成为选择维度。
- 只有来源、单位、范围和规则版本均已正式定义的运行质量材料（例如同一单位的预计单调执行时长、资源或既有成本）才能比较。

未知、不可比或并列最优时不得按遍历顺序、编码、哈希或线程顺序选择。只保留发现与原因并向 self 发具名待裁决定位；只有具名后继 owner 才能形成正式等待，self 也不能用主观偏好补造比较算法。

### 4.3 复用既有选择 / 冻结记录

一旦选择完成，复用当前 L2 选择、路径、实例方法和执行冻结结构；其 producer 从筹办阶段迁移到执行前入口。原子写入必须仍同时绑定选中方法版本、条件组、输入 / 参数、动作入口 / 范围、验证、归因、来源事实截止和规则版本。任一绑定事实变化使选择和冻结失效，下一次尝试重新 fresh 读回和判断。

不增加选择历史账或代价账；既有选择记录就是已选一个执行选项的唯一业务记录。

### 6.2.1 先骨架、后血肉的施工门禁

当前执行队列为空，且外层消息、任务管理、任务工作线程、任务 / 方法结构与筹办 provider 都存在异主 WIP；因此现在不能登记或施工任何 C031 代码计划。取得明确所有权并重新 S0 后，第一份计划优先形成上节的外层—内层骨架，而不是孤立增加一个条件组字段：

```text
已确认 D 的 self -> manager 不可变任务发起意图
-> manager 独立读回后请求待实现的“按具体需求承接或复用任务”入口
-> 新任务：E owner 建 E；task owner 建 T、T→L、T→D、T→E、R1，完成首态、P1/A1、首迁移和逐 owner 正式读回
   既有任务：复核 / 复用 T，幂等建立 T→D 并正式读回
-> 初次 / 后继统一筹办工作包 -> 一条筹办发现 / 结构化非成功消息
-> 完整发现才进入执行前选择 / 冻结与执行工作包
-> 正式结果读回后由 task owner 结算 / 收束轮次
-> self 消费定位并决定后继
```

在上述 self -> manager -> “按具体需求承接或复用任务”的完整新任务 / 既有任务分支 -> 初次工作包链闭合前，C031 的发现叶只适用于外部已存在且已合法进入筹办的任务，不能被称为从自我需求启动的完整实现路径；也不得把初次包伪装成旧后继包。

该骨架可以合法地把尚无条件组 ABI 的方法定位为`条件组结构缺口`并交 self，而不能伪造正常发现、执行选项、冻结或现实动作。这样先闭合真实的跨 owner 交接与三阶段边界，后续再填充方法发现、条件、动作、验证和归因的血肉；不得为了演示骨架建立空任务、假选择、假结果、第二消息通道或持久账。

骨架计划的完成声明必须限于：已确认需求的交接、任务 / 轮次正式入口、工作包 / 结果消息边界、manager 独立读回、结构缺口路由，以及任务 owner 对结构化非成功的结算 / 收束入口。它不能因此宣称已经具备正常条件组发现、执行前选择、真实动作、基于动作结果的正常结算或需求满足。

条件组公开 ABI 是筹办血肉的第一门禁：已发布方法结构没有条件组身份、成员关系或组间组合语义，`4260` 已规定该缺失必须 fail-closed。后续方法 owner 要么发布可独立读回的强类型“组身份 + 成员 / 条件结果关系 + 组合语义”，要么该方法永远只返回精确结构缺口；任务筹办不得以平铺条件、本地顺序、稳定编码、哈希或线程顺序补造一组。前者不要求新建持久条件组节点、候选账、历史账或第二消息通道；条件组可以是既有方法内容的值式投影，但其身份和组合语义必须由方法 owner 公开、强类型且可独立读回。

骨架发布并重新 S0 后，才把“初次 / 后继统一筹办来源 + 多方法—条件组发现 DTO / 消息 + manager 独立读回”扩展为可产生正常发现项的血肉。其后才依次形成 self 确认承接、执行前选择 / 冻结和合法消费者端到端验证；不得预先登记多层待激活计划。
