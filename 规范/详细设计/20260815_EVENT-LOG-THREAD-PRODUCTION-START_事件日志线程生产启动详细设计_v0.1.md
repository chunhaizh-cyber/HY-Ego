## 1. 目标、边界和完成条件

本设计建立一个真实事件日志支持线程。它接收有界、强类型、仅供人读的事件摘要，按 FIFO 顺序对每个已取出摘要最多调用一次现行 `记录事件日志(...) -> bool`，并经已经发布的 SUPPORT 候选生命周期取得唯一移动线程租约。

本叶完成必须同时满足：

1. `启动事件日志线程` 固定使用 SUPPORT 的“创建候选 -> 等待内部进入见证 -> 非成功移动候选租约回收 -> 成功返回唯一移动租约”合同；不读取 8110 投影判断物理进入，不返回第二份线程租约。
2. 事件摘要只承载受控人读观察材料，不承载、确认、恢复或修复机器事实；日志是否写入不得改变任何业务结果、线程继续条件或权威状态。
3. 摘要队列是事件日志专属有界 MPSC / 单消费者 FIFO；满时拒绝新项，不驱逐旧项，不使用停止哨兵，不复用旧 `有界运行消息队列`。
4. 成功租约唯一拥有队列状态、生产写入适配器、事件入口和 SUPPORT 候选租约；SUPPORT 租约必须先停止并连接，随后才允许销毁其借用的入口、适配器和队列状态。
5. 租约公开提交、停止接收并取得截止、等待 / 读取完成位置、冻结并读取未取出快照及显式停止连接能力，为后继 BIZ-L2-001-15 提供材料边界；本叶不实现支持线程组装配或阶段 15 总协调。
6. 入口观察到 stop 后不得再从队列取出新项；stop 到达时已移到线程局部的一个摘要最多完成一次写入尝试，未移出的摘要保留在有界队列并可形成值式快照。

本叶明确不实现：DATA-L1—DATA-L3、业务事实写入、8110 生命周期所有权、支持线程组、缓存统计、持久证据、普通应用装配、T01 正式接线、阶段 15 总收口、日志恢复、轮换、重放、跨进程恢复或机器可靠事件总线。

## 2. 正式依据和当前代码事实

正式依据：

- 0050：日志、线程和过程材料不能建立或替代机器事实；结构化非成功与内部不一致分账。

## 3. 稳定值类型合同

不含移动租约或 SUPPORT 见证的 EVENT 稳定值类型唯一声明于 `海中鱼巣/线程/事件日志线程.数据.h`。包含 `事件日志线程租约` 或 `支持线程候选见证` 的启动 / 停止连接组合结果由真实模块唯一声明。数据头只有声明和结构自身不变式，无独立 `.cpp`。

### 3.1 常量和事件摘要

```cpp
inline constexpr std::uint32_t 事件日志线程合同版本 = 1;
inline constexpr std::uint64_t 事件日志摘要队列最大容量 = 65'536;
inline constexpr std::size_t 事件日志模块最大字符数 = 128;
inline constexpr std::size_t 事件日志操作最大字符数 = 128;
inline constexpr std::size_t 事件日志来源摘要最大字符数 = 1'024;
inline constexpr std::size_t 事件日志人读摘要最大字符数 = 4'096;

enum class 事件日志诊断分类 : std::uint8_t {
  运行观察 = 1,
  结构观察 = 2,
  生命周期观察 = 3,
  支持降级观察 = 4,
  审计观察 = 5
};

struct 事件日志摘要 final {
  std::uint32_t 合同版本 = 事件日志线程合同版本;
  std::uint64_t 运行代次 = 0;
  std::uint64_t 摘要身份 = 0;
  std::uint64_t 事件发生时间毫秒 = 0;
  std::wstring 所属模块;
  std::wstring 入口或操作;
  事件日志诊断分类 诊断分类 = 事件日志诊断分类::运行观察;
  std::optional<std::uint64_t> 稳定编码;
  std::optional<std::wstring> 来源请求摘要;
  std::wstring 人读摘要;
};
```

摘要准入固定为：合同版本精确匹配；运行代次非零且等于本租约运行代次；摘要身份和发生时间非零；模块、入口 / 操作和人读摘要非空且分别不超过上限；来源摘要存在时非空且不超过上限；稳定编码存在时非零；诊断分类必须属于已知枚举。拒绝只返回结构化结果，零入队、零日志调用。

`摘要身份` 只在本次运行代次内定位旁路摘要，不承诺全生命周期幂等、恰好一次、可靠投递或跨进程恢复。队列不按摘要身份去重；相同身份的第二次提交仍是独立请求，调用方不得靠重复身份猜测第一次是否接受。

`事件日志摘要` 不提供“已确认机器事实”“业务成功”“可恢复”“可靠投递”等布尔字段。调用方只能在自身正式业务裁决完成后构造人读摘要；EVENT 不读取 DATA、缓存或 8110 来复核或补造该裁决。

## 5. 所有权和生命周期

`事件日志线程租约` 的模块私有成员按以下声明顺序固定：

```text
1. unique_ptr<事件日志线程状态> 队列状态（内含本租约非零运行代次）
2. unique_ptr<事件日志生产写入适配器> 写入适配器
3. unique_ptr<事件日志线程入口> 线程入口
4. 支持线程候选回收请求 析构回收请求
5. optional<支持线程候选租约> 支持候选租约
```

C++ 逆序析构使 SUPPORT 租约先请求停止并连接，随后才销毁入口、适配器和队列状态。正常收口必须调用 rvalue 限定的 `停止并连接`：先在事件状态锁内读取原队列前置；若尚未停收则同时锁存停收截止并记住前置未闭合，再把唯一 SUPPORT 租约移动给 `停止并连接支持线程启动候选`，取得最终见证和位置后清空本对象其余拥有体。析构仅在调用方遗漏显式收口时先锁存停止接收，再使用已存请求执行保守停止连接；它不产生可向上交付的成功结果，也不得称为阶段 15 正式收口。成员逆序析构再作最后安全网。两条路径都不得 detach，不得在 SUPPORT 尚可调用入口时提前释放任何借用对象。

显式停止连接的前置只有两种合法闭合形状：

```text
已经停止接收，且已完成位置 >= 同一接受截止
或
已经停止接收，且同一接受截止的未取出快照已经成功读取
```

未停收，或已完成位置尚未到截止且没有同截止成功快照，都属于 `前置未闭合`。资源安全优先于前置错误：函数仍必须 stop 并 join，但返回 `前置未闭合但已安全连接` 和最终位置，不能包装成普通已安全连接或请求拒绝。事件停止请求自身无效时同样必须使用租约内已存的合法 fallback 回收请求完成 stop / join，再返回 `请求拒绝但已安全连接`。

启动局部对象也按相同依赖顺序建立。只有 `等待支持线程进入见证` 返回 `已进入` 且候选见证完整时，才把全部拥有体组装为成功租约。创建后任一失败都必须把唯一 SUPPORT 候选租约移动给回收函数；回收返回前入口、适配器和状态持续存活。

移动构造把全部所有权一次转移，移动源变为空；移动赋值删除，避免覆盖仍持有 joinable 线程的租约。`停止并连接` 只能对 rvalue 调用，消费后对象与普通移动源相同；重复调用返回 `租约已消费`。其它公开成员在移动源上返回结构化拒绝 / 保守位置，零内部访问。

显式停止连接状态优先级固定为：未安全连接或最终见证 / 位置矛盾 -> `内部不一致`；请求无效 -> `请求拒绝但已安全连接`；阶段 15 前置未闭合 -> `前置未闭合但已安全连接`；入口故障 -> `入口故障已安全连接`；超过诊断预算 -> `超过诊断预算后已安全连接`；否则 -> `已安全连接`。`租约已消费` 只适用于调用前已无 SUPPORT 租约的对象。

## 6. 队列并发和位置合同

模块私有 `事件日志线程状态` 固定使用一把 `std::mutex` 和一个 `std::condition_variable` 保护：有界 `std::deque<事件日志排队项>`、下一接受位置、已完成位置、可选正在处理位置、停止接收截止、取出冻结、入口完成 / 故障、写入未成功计数及同截止快照成功读取见证。

锁序只有这一把事件状态锁；不与 SUPPORT 见证锁、8110 生命周期串行锁或日志内部锁嵌套。锁内只校验 / 移动 / 复制有界内存材料、更新位置和通知；禁止调用日志、DATA、8110、SUPPORT 公开函数、文件、回调或等待外部 I/O。

SUPPORT 的 `request_stop()` 不会自动唤醒本模块的 `condition_variable`。入口在进入任何等待前必须为本次 `std::stop_token` 注册一个 `std::stop_callback`，回调唯一动作是对同一事件状态条件变量执行 `notify_all()`；回调不取得事件状态锁，不调用日志、SUPPORT、8110、DATA 或其它回调。stop callback 的生命周期覆盖入口全部等待，销毁发生在线程不再进入等待之后。每次唤醒都在事件状态锁内重新检查 `stop_requested()`、取出冻结、队列非空和内部故障完整谓词，禁止把一次通知解释为条件成立。

### 6.1 提交

```text
锁外校验摘要形状
-> 取得事件状态锁
-> 复核仍接收、容量和位置未溢出
-> 为下一位置构造完整排队项
-> 成功后一次追加并推进接受位置
-> 释放锁并唤醒消费者
```

分配 / 构造失败返回 `资源失败`，队列、接受位置和现有项不变。队列满返回 `队列已满`，不得驱逐、覆盖、改优先级或等待空间。停止接收 / 取出冻结 / 入口完成后返回 `队列已停止`。多个生产者的唯一线性化点是锁内成功追加；接受位置从 1 单调递增并定义 FIFO 总序。

### 6.2 停止接收和读取位置

`停止接收并取得截止` 在线程状态锁内把接收状态从开切到关，并把当时最后接受位置锁存为永久截止；并发提交只有在该线性化点之前完整入队才属于截止。重复调用返回同一截止和 `精确重复`，零状态变化。

`读取处理位置` 只在短锁内复制值式字段。它不触发刷新、不补日志、不等待、不请求停止。

### 6.3 等待完成和冻结快照

`等待完成到截止` 只接受已经停止接收且请求截止精确等于锁存截止的请求；使用 `steady_clock` 和非零有界毫秒等待 `已完成位置 >= 接受截止`、入口故障或入口完成。虚假唤醒重新检查谓词。零截止且完成位置为零返回 `无需等待`。

刷新超时或入口故障后，阶段 15 可调用 `冻结并读取未取出快照`。该函数先在锁内永久锁存 `已冻结取出=true` 并唤醒入口；从该线性化点起入口不得再移出新项。冻结本身不冒充 stop，也不使入口提前返回：入口只等待后继正式 stop。随后以当前有界队列形成按接受位置升序的值式副本。副本分配失败返回 `资源失败`，但原队列及冻结状态不变；同截止可重试并取得同一未取出集合，异截止拒绝。

快照只包含尚在队列、从未被入口移出的项；已经移到入口局部的 `正在处理位置` 单独回显，不复制到未取出项。快照是后继接管材料，不是写入成功证明、恢复事实或业务事实。

## 7. 入口循环和写入适配器

入口循环固定为：

```text
注册覆盖全部等待的 stop callback
-> 等待 stop、取出冻结、队列非空或内部故障
-> stop / 取出冻结先于取出判断
-> 可取时只在锁内把队首一项移动到线程局部并登记正在处理位置
-> 释放锁
-> 格式化受控人读内容
-> 机械调用一次 记录事件日志(所属模块, 入口或操作, 内容)
-> 重新取得锁，清空正在处理位置并推进已完成位置
-> false 时饱和增加写入未成功次数
-> 释放锁并通知等待者
-> 下一轮
```

消费者严格按接受位置 FIFO 取出。入口对已移出摘要再做一次结构形状防御性复核；因全部公开提交已经先行校验，命中坏版本、坏枚举或越界字段属于内部不一致并使入口故障收束，不把坏摘要写入日志。已移出合法项无论写入返回 true / false 都只完成一次，不重试、不回队、不改变调用方业务结果。日志格式化或调用抛出由适配器捕获并映射 `未写入`；异常不得越过线程入口。

stop 到达时，入口在下一次取得状态锁后锁存停止接收并返回 `支持线程入口退出状态::已响应停止`。若 stop 在某项已经移出后到达，该项允许完成唯一一次写入尝试；随后零新取出。若内部位置倒退、重复位置、队首不连续或控制状态矛盾，入口锁存故障、停止接收、通知全部等待者并返回 `内部故障`；日志失败、队列满和合法停止都不是入口故障。

入口不发布进入 / 完成见证，不发布 8110 生命周期，不访问候选租约。SUPPORT 包装在调用入口前形成内部进入见证，并在入口返回和终态投影尝试后形成内部完成见证。

## 8. 启动状态机和 SUPPORT 映射

```text
完整校验启动请求
-> 由事件专属字段机械形成固定 SUPPORT 三请求
-> 分配带运行代次的队列状态、生产写入适配器和入口
-> 创建支持线程候选(事件日志固定类别/模块)
-> 创建非成功：机械映射并返回，零 EVENT 租约
-> 等待支持线程进入见证
-> 已进入且见证未显示入口已故障 / 提前完成：组装并返回唯一 EVENT 移动租约
-> 已进入但同次见证已经显示入口故障 / 提前完成：移动租约回收
-> 未进入 / 内部不一致：移动 SUPPORT 候选租约执行回收
-> 回收完成：按等待与回收结果形成 EVENT 非成功
```

映射规则：

| SUPPORT 结果 | EVENT 状态 | 所有权 |
| --- | --- | --- |
| 创建 `已创建` + 等待 `已进入`，且见证未显示入口已故障 / 提前完成 | `已进入` | 返回唯一 EVENT 移动租约；返回后异步故障由租约位置 / SUPPORT 见证后继处理 |
| 创建 `请求拒绝` | `请求拒绝` | 零租约 |
| 创建 `身份已使用` | `身份已使用` | 零租约；不得读取 8110 寻找旧租约 |
| 创建 `线程创建失败` | `线程创建失败` | 零租约 |
| 创建 `资源失败` | `资源失败` | 零租约 |
| 等待超时 + 回收 `已安全连接` | `进入超时已安全连接` | 零租约 |
| 回收 `入口故障已安全连接` | `入口故障已安全连接` | 零租约 |
| 回收 `超过诊断预算后已安全连接` | `超过诊断预算后已安全连接` | 零租约 |
| 任一见证 / 状态矛盾或回收内部不一致 | `内部不一致` | 零租约；回收函数自身仍已履行其安全连接合同 |

启动不支持“同义已进入复用”。SUPPORT 的逻辑身份是进程级墓碑，同一 `(运行代次, 线程逻辑身份)` 第二次创建返回 `身份已使用`；EVENT 不能复制、借出或从投影重建旧线程租约。

## 9. 阶段 15 接口边界

正式 BIZ-L2-001-15 的顺序在 EVENT 上具体解释为：

```text
停止接收并取得接受截止
-> 等待完成到该截止
-> 已到达：移动 EVENT 租约调用显式停止并连接
-> 超时 / 故障：冻结并读取未取出快照
-> 后继接管或形成具名支持降级
-> 再移动 EVENT 租约调用显式停止并连接
```

本叶实现租约上的队列控制和单线程显式停止连接能力，但不实现 `刷新并连接支持线程组`、未刷新旁路材料持久接管端口、三类支持租约 variant 或普通应用停止阶段。调用方不得绕过未取出材料分类 / 接管就直接把“日志不重要”解释为可以静默丢弃。

正常 EVENT 停止不要求“收到 stop 后继续排空全部队列”。排空裁决已经发生在 stop 之前的“停收 -> 等待截止”；超时 / 故障时先冻结未取出快照，再 stop。这样既保证 stop 后零新取出，也不让日志写入失败或阻塞造成无限重试。
