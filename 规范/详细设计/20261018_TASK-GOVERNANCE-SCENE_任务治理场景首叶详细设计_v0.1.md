## 1. 目标及不可扩展的边界

本叶只改变内部治理实例的场景组织，不改变任务完成、服务资格、贡献计算或自我服务值。目的是让每个任务有稳定C(T)，并让既有最终来源“任务状态9→12”生产链的动作、前后状态、变化动态和因果读取完整使用C(T)。

交付包括：

1. 新任务T/Vt/F与唯一C(T)一并交付；重复建立、重新筹办及挂起恢复不增加第二场景。
2. 已完整成立的旧T建立C(T)；旧治理根上的可完整追溯9→12事实保留身份、原子改变唯一列表归属。
3. 写入、结果读回、动作概念投影、因果发生窗口及根/任务场景查询同步切换，不能只改写入位置。
4. 原初始化及重复调用只读回完整事实；不把迁移当新动作，不重复因果统计。

明确不含：Q算法及权威余额迁接、旧Ftq补值、普通子任务新增9→12路径、Vm场景、通用全部Vt特征变化、self直接结算调用、零额消费、阶段身份重构、持久化/重启防重保证、旧D/T删除。所有新建任务仍保留已经实现的独立Ftq=0。

用户本轮已明确三个总设计裁决：普通子任务R完整后可标记已结算，最终来源须U及实际入账读回完整；每个方法有独立治理场景并持有唯一Vm；同时迁移可追溯旧数据，不能还原时停止并报告。本叶只实施第三项中任务场景/既有9→12组织部分，其余是后继范围，不据此扩大代码。

## 3. 身份、字段及权威归属

### 3.1 场景结构

```text
内部治理根 Cg
├─ C(T1) ——正式归属引用→ {T1,Vt1,Fstate1}
└─ C(T2) ——正式归属引用→ {T2,Vt2,Fstate2}
```

所有Ct均是Cg直接子场景。每Ct仍是合法场景/存在，拥有自身专属概念，初始特征为空。业务父子只来自D树；本叶不按父任务嵌套场景。

在`新_场景类.cpp`现有私有schema中新增三个字段节点：

| 私有字段 | 所属节点/内容 | 基数与规则 |
| --- | --- | --- |
| `治理所属任务字段` | Ct→T的稳定编码引用 | Ct恰一；同一T全治理树最多被一个Ct引用 |
| `治理所属虚拟存在字段` | Ct→Vt的稳定编码引用 | 与T的正式Vt完全一致 |
| `治理所属状态特征字段` | Ct→Fstate的稳定编码引用 | 与Vt唯一状态F一致，不借此限定未来全部F类型 |

三字段一起成立或全无。Cg不持有三字段；其它树用途不得持有。它们由场景owner唯一写入，task不增加T→C镜像字段。反查使用`查询目标字段(T,治理所属任务字段)`，只是同一正式字段索引，不建map权威或第二关联记录。

Ct的拥有者Vt同时是该场景参与者：`读取治理参与者(Ct,Vt)`从上述三字段取得强类型引用后调用task只读接口。不得再为同一拥有者写一份重复的`治理引用记录`。现有`添加治理任务引用(Ct,同一引用)`返回无变化；若Ct拥有者与所请求引用冲突，工程终止。旧Cg参与者记录及现实执行主体引用继续沿用旧schema。

`属于内部治理组织()`必须识别新三字段所引用的Vt/Fstate；不能把T或共享概念当普通成员，也不能遗漏新Ct中的事实。

## 4. 提供者接口及精确落点

### 4.1 场景owner的组合准备

在`新_场景类.h`场景类声明前定义不可伪造的技术准备材料：

```cpp
class 新任务治理场景发布准备 final {
public:
    新任务治理场景发布准备(const 新任务治理场景发布准备&) noexcept = default;
    新任务治理场景发布准备& operator=(const 新任务治理场景发布准备&) noexcept = default;
    稳定编码 候选场景节点() const noexcept;
    const 基础封存追加片段& 场景片段() const noexcept;
private:
    struct 内容;
    explicit 新任务治理场景发布准备(std::shared_ptr<const 内容>) noexcept;
    std::shared_ptr<const 内容> 内容_;

```

`内容`只在cpp定义，包含所属场景服务身份、候选C、已准备专属概念、目标引用和封存片段；不能序列化成业务节点。复制只共享技术准备内容。所有非inline方法定义在同名cpp，不新建工程文件。

在`新_场景类`治理接口段新增：

```cpp

    const 新任务治理场景发布准备&) noexcept;

    稳定编码 任务节点) const noexcept;

    稳定编码 场景节点) const noexcept;
新场景操作状态 原子迁移治理状态动态(
    稳定编码 原场景节点, 稳定编码 目标场景节点,
    const std::vector<稳定编码>& 状态节点组,
    const std::vector<稳定编码>& 动态节点组,

```

准备入口只供内部治理世界调用。它核验治理根和三引用编码存在、无既有Ct，分配尚未挂树的C，以`存在服务_.初始化存在节点(C,{},true,nullopt)`建立空存在及专属概念，再封存本owner的候选写集：C场景身份、三归属字段及Cg→C父子关系。此时没有C场景身份和父边，故没有可消费的半场景；不在准备期回调尚未发布的T。场景owner不检查或写task字段，正式T语义由组合发布后task读回确认。nullopt是独立工程零发表返回，只能在本次scene候选已经完整撤销后返回；不能被上层解释为“没有业务场景”。清理失败或无法确定发表状态立即工程终止并保留现场，不承诺继续执行task清理。

撤销只允许同owner准备材料且C没有场景身份、没有正式父边/归属/其它外部消费者；通过存在owner清理其专属内容后删除本次空节点。已发布C禁止撤销。重复撤销已不存在候选可收敛；冲突/清理失败工程终止。不得以“新建失败”删除既有Ct或任何事实。

读取在场景锁内核对全树唯一归属、三个字段完整、Cg直属父、合法场景/存在身份；不存在返回nullopt，声明字段不全、多重或坏类型工程终止。该结构读取不回调task，以免锁倒置；世界/调用者随后核验task身份。

`查询治理参与节点(C)`在场景锁内完整解析该C直接治理引用记录，并纳入Ct拥有者Vt；不递归、不回调task、不向上层暴露原始私有字段。返回按稳定编码排序的参与节点，合法零引用场景才返回空；坏场景、坏引用、重复/冲突参与者工程终止，不能去重掩盖重复。世界迁移预检以此枚举，再逐项调用已有正式`读取治理参与者`核验task或现实主体语义，不能只从已知T/S/D端点猜引用全集。Cg直接子场景全集与T→Ct集合双向相等，不明孤立Ct停止；不需要另建场景登记索引。

原子迁移接口只供已冻结旧数据移动使用。它不改S/D本体或引用次数，详见第7节。

### 4.2 世界与任务窄协作接口

在`新任务治理世界协作接口`增加三个纯虚方法，在`新_内部治理世界类.h/.cpp`实现：

```cpp
virtual 新任务治理场景发布结果 发布新任务治理场景(
    const 新任务虚拟存在引用&,
    const 基础封存追加片段& 任务发布片段) noexcept = 0;
virtual void 迁移已有任务治理场景(
    const std::vector<新任务虚拟存在引用>&) noexcept = 0;
virtual std::optional<新任务治理场景信息> 读取任务治理场景(
```

task是唯一生产调用方；任务发布片段是task封存的私有写集，世界只组合不可变片段，不读取/改写其字段内容。不新增对外裸基础变化集出口。scene准备返回nullopt、封存失败或底座明确组合零发表失败时，world先确认本次C已撤销，再返回`未发布已清理场景`，由仍持有候选的task撤销自己的T/Vt/F/专属概念并统一工程终止。组合已完成后的任何读回异常直接工程终止，不能返回未发布或撤销；不得在world提前终止的同时声称task清理必已完成。

世界读取组合场景结构读回与`任务读取_->读取任务虚拟存在语义()`；两者必须完整一致。缺Ct返回nullopt只用于初始化迁移判断；生产动作链缺Ct是工程缺口，不能回退Cg或现实根。

### 4.3 任务owner入口与启动装配

在`新_任务类.h`的`装配内部治理世界`附近声明，在cpp同区域定义：

```cpp
void 初始化任务治理场景组织() noexcept;
```

私有增加`bool 任务治理场景组织已就绪_ = false;`，仅为进程内装配门，不是持久业务状态。入口持`新任务互斥`：确认schema/世界已装配、完整枚举并交叉核验T/D/Vt/F/root登记，先核验既有专属概念，再仅补齐确实缺失的Vt专属概念，调用世界迁移，逐项读回唯一Ct，最后置位。存在专属概念字段时必须先调用正式语义读取核对身份和完整特征组成，不能先调用会更新概念的`确保任务虚拟存在语义()`把不一致覆盖掉；无字段且其余身份完整时才允许ensure。重复调用仍核对已登记任务和Ct，不凭布尔直接宣称全部完整。完整枚举复用`读取需求列表任务对应()`及其类型集合对登记集合检查；无法完整枚举不是空集。

`装配.普通应用.cpp::完成装配()`在`任务服务.初始化治理()`与本能动作/反馈装配成功的if块之后、self初始化之前，调用此入口。治理根此时已存在，manager/self尚未启动。禁止把迁移放到消息循环或持有场景锁时反调task；不增加命令行模式或运行测试入口。

## 5. 新任务组合发布与失败合同

`建立或取得任务()`仍是唯一创建入口。持task锁，完成既有需求合法性和唯一T检查后：

1. 要求场景组织已就绪、世界已装配；否则工程终止，不返回业务“无任务”。
2. 建立状态F=已建立及Ftq=0，分配尚未定型的T/Vt节点。
3. 通过存在概念owner，用Vt及实际两个F概念建立专属概念。此处不能调用要求正式T已成立的旧`确保任务虚拟存在语义()`；可提炼同cpp私有构造步骤，但不扩大公共API。
4. task封存自己的完整片段：T类型/D/Vt、Vt类型/T/Fstate/Fq/专属概念及任务根成员字段。上述正式类型、D反向可发现关系及根成员均不得在组合发布前逐项写出。联合预期包含D、任务根和所有已准备节点结构/入向关系，防止同D重复发布及材料变化。
5. 世界调用scene准备C；将task片段与scene片段一次提交`原子追加封存片段组()`。两片段只引用已分配的稳定编码，不需要跨片段组内索引。它们重叠的联合预期必须完全一致；无法合并视为工程设计/实现错误，不能退化为顺序两个发布。
6. 一次成功后，按回执核对两片段身份，task完整读回T/Vt/D/F/专属概念，world读回Ct及参与者，再执行现有服务任务集合被动同步并返回。只有此时对外返回`已建立`。同步失败沿现有工程/诊断合同，不撤销已发布T/C。

准备失败或明确原子发布失败：按第4节零发表工程状态逐层收口，scene先撤销C并返回，world返回`未发布已清理场景`，task撤销未绑定专属概念、空T/Vt及本次独占F，逐项检查清理结果后统一工程终止；不能清理成功以前继续业务。若底层清理失败或发表结果无法确定，立即保留现场并工程终止，后续清理不会执行，报告不得称“全部回滚”。成功后读回出错保留完整已发布事实并工程终止，不删除T/C、降为可重试资源失败或重复分配任务。

重复建立分支只核对原T/Vt/F/Ct，保持既有状态和Ftq。就绪后出现缺Ct不得当旧格式顺手补齐；旧格式只允许进入第7节启动迁移。新T类型/根成员/Ct绑定同次发布，因此完整旧T无Ct与本轮创建中断的半结构有明确区分：未发布候选无正式T类型/D/root成员；已有正式类型但登记不全一律工程停止，不能冒充旧任务。

仅保证当前进程内原子发表和同进程读回；原始空候选节点及已准备F/概念仍可能在工程终止时留在内存，不能宣称跨进程崩溃恢复或自动清理。持久化和重启门禁不在本叶。

## 6. 既有生产9→12链完整路由

`标记任务已结算()`保留现有条件、普通动作来源、状态值及时序，不扩展普通子任务新路径。它必须要求目标Ct正式可读；不为缺Ct临时创建第二组织。

| 原函数 | 必须同步改变 |
| --- | --- |
| `建立任务状态动作()` | 由目标T读Ct；目标Vt采用Ct归属参与者；现实执行主体以纯引用加入Ct；前状态和动作只挂Ct |
| `完成任务状态变化()` | 从动作目标T核对同一Ct，后状态、原子变化及动作结果按原算法形成，只挂Ct |
| `读取任务状态变化()` | 按目标T定位Ct，核对动作/S前/S后/D全部在该Ct；结果返回Ct；同源完整重复不写 |
| `读取自我动作事实()` | 先读动作本体目标T，再读Ct及挂接，不能先要求动作在Cg动态列表；校验主体、目标及原普通动作来源；保持被动触发分类 |
| `交付实际发生()` | 使用变化结果中的Ct构造窗口，只收集Ct实际S/D；不扫描兄弟任务、根最后一项或将时间接近当来源 |
| `查询因果链()` | 无共同场景仍查询Cg范围；入参参与者验证须覆盖所选场景全部合法下级；显式Ct不允许兄弟任务参与者；调用既有反查服务 |

在世界类cpp增加私有范围读取helper，按当前场景及子场景完整遍历、稳定编码去重；同一参与者多个纯引用必须身份/概念/来源一致，冲突工程终止。该helper只供查询入参核验，公共`读取治理参与者(C,E)`仍表示该C的直接引用，避免破坏因果服务的场景身份校验。

保留状态内容、动态时间和动作来源身份。重复结算时现有状态12分支读取同一Ct结果，不重新交付因果。9→12既有旧动作只有完整迁移后才能进入新读取路径。

## 7. 已有数据迁移（启动静止窗口）

### 7.1 全量预检与允许数据

任务owner先对全部正式T做双向核验，世界再扫描Cg及所有已有Ct，使用`查询治理参与节点()`完整枚举每级引用，并核对Cg直接子场景与全部已绑定Ct双向一致。先形成完整只读迁移清单，发现不可还原项即工程报告并停止，不边猜边迁。允许：

- 完整T/D/Vt/Fstate，尚无Ct、尚无治理动作：按实际身份建Ct。没有旧Ftq不是本叶拒绝理由，也不能补为0；专属概念按当前存在的合法F组成确保。
- 完整T及已有唯一Ct：精确复用，禁止再建。
- Cg上的完整9→12动作包：动作目标三引用、正式动作定义、普通来源动作及现实场景/主体、两个准确状态、唯一原子结果、时间、显式导致变化关系、概念投影均可交叉核对。当前任务仍须符合既有已结算读回合同。
- 可被同一已核验任务唯一归属的旧根状态/原子动态，且其正式引用闭包完整：按包移动，不靠名称或编码接近归属。首叶仅接受上述9→12包；未知其它种类不猜归属。

不可还原而停止的例子：正式T不在唯一任务根、D反向重复、Vt归属错/Fstate错误、专属概念存在但结构矛盾、同T多个Ct、Ct三字段不全、旧root动作无来源/结果、同一S/D挂多场景、状态端点混任务或混特征、无法找到唯一动作包、未知治理参与者、因果参与者或原发生范围无法读回。不能把这些解释成“不符合服务”、空材料或迁移成功跳过。

缺少专属概念而其它结构完整是可补齐项；已存在错误专属概念不是“缺少”而是工程故障。新任务未完成发布的候选不进入旧任务枚举，已有定型半结构不修复成旧完整任务。

### 7.2 发布及读回

完整预检通过后，逐T确保Ct。现有T无Ct时只发布scene片段，T/F数值零修改；新建C前后核对同一T快照。不得创建新的需求、任务或修改任务状态。

为每个可迁包在Ct添加其已核验现实执行主体纯引用，再调用场景owner的`原子迁移治理状态动态(Cg,Ct,S组,D组,task读取)`。场景owner先在场景锁外核验task/主体/S/D，在锁内重新核对源/目标列表及完整联合预期：

1. 每个S/D在Cg恰一挂接，或整包已在Ct且Cg零挂接；后者返回无变化。
2. 原子动态全部端点随同迁入同一Ct，动作目标归该Ct，结果引用不变；包既有Ct/根混挂或不完整时停止，不猜中间进度。
3. 以一次`原子追加节点组()`追加Ct列表字段并删除Cg的相应列表字段。请求没有新业务节点，联合预期覆盖Cg/Ct、全部被移S/D及其入向字段/相关边。
4. 迁移前后场景引用数量恒为1，故不调用S/D引用增加/减少，不触发减至零删除；变化的是组织引用，不是事实、强时间、动作或概念。
5. 发布失败无任何列表半移动；成功后读回两边、事实身份、引用次数及动作完整包。结果不明或读回矛盾停止，不再盲目重复。

同进程再次初始化重新读取正式清单：已建Ct复用，整包已迁复用，尚在Cg的完整包继续；不依赖内存“已迁”集合作为事实。整个世界迁移不是一个大事务；只保证每个任务动作包移动原子且启动未交付给运行线程。失败保留已经完整完成的前包，不回滚事实、不启动治理线程。

### 7.3 旧因果与根引用处理

旧因果发生场景Cg仍是Ct合法祖先，因此不改其发生身份、定义、统计、概念和原Cg范围引用；旧Cg参与者引用也保留，供旧因果直接场景投影读取。这是保留原先真实共同场景，而不是漏迁S/D：具体动作/S/D唯一列表必须迁入Ct，Cg只保留共同范围和引用。

迁移前后核验`因果服务_.查询当前场景树因果()`及已形成因果的身份/发生场景/计数/定义不变，所有旧Cg参与者可读，相关S/D仍在Cg递归范围内。不能为迁移重调`处理动作事实()`，否则可能增加发生统计或改写知识。既有待形成发生材料也不重新提交或改写；以后新发生采用Ct，是否归纳与旧范围知识由既有因果规则决定。

对已有Ct的新因果，场景为Ct且参与者通过Ct归属/主体引用读回。根查询递归可达全部；显式Ct查询不承诺把原Cg经验规则自动降成Ct规则，不把此范围区别误报“因果丢失”。

## 8. 锁、依赖、生命周期和工程失败

- 创建/迁移入口持task递归锁；场景callback在场景锁外调用task。锁次序是task→scene→基础，不能scene锁内反调task；因果既有冻结参与者投影在因果锁外继续保持。
- 世界层不增加包围task回调的互斥锁；新任务唯一性由task锁与Ct场景唯一字段核对共同保证。场景组合准备不能先持scene锁再回调task。
- scene准备/移动封存材料是一次调用技术对象，不进入业务树；片段和回执必须按身份对应，不能从回执数组位置猜节点。
- `新_场景类`不得include任务类、内部治理世界或线程实现；继续只依赖中立强类型引用/接口。世界层可组合task只读接口，但不写task字段。
- 所有新增结构损坏、读取失败、发布/清理失败走已有`工程异常终止`日志+弹窗+终止链，不生成业务失败、因果样本或待满足子需求。
- 场景终结/任务完成不删除Ct；本叶没有task删除入口。`删除空场景(Ct)`必须拒绝正式拥有者字段，不能留下T无Ct。未发布候选只由专属撤销入口清理。
- 单次组合发布成功只是当前内存原子性；不宣称磁盘持久、重启后自动恢复或全部治理操作已覆盖。
