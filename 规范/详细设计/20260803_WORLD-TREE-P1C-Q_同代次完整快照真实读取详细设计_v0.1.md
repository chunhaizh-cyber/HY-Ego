## 4. 请求准入、请求回执与通用结果规则

### 4.1 整树请求准入

`世界树读取请求` 只有同时满足下列条件才通过：

```text
请求.头.合同版本 == 世界树服务合同版本 == 1
请求.头.世界规则版本 == 世界树规则版本 == 1
请求.头.世界根为完整节点稳定身份见证
请求.头.世界根.类型 == 节点类型::场景
```

失败固定返回：`入口拒绝、默认世界树请求头、空快照、空缺项组`，provider 调用数0。

### 4.2 对象请求准入

对象入口先独立执行上述请求头准入，再要求：

```text
目标为完整节点稳定身份见证
存在入口目标类型 == 节点类型::存在
场景入口目标类型 == 节点类型::场景
```

失败固定返回：`入口拒绝、默认世界树对象读取请求、空快照、空缺项组`，整树根调用数0。

### 4.3 请求回执

- 入口准入完成前的任何拒绝或异常使用默认请求回执。
- 入口准入成功后，所有成功和非成功结果均回显已经验证的请求头/对象请求。
- 不得回显未经验证的输入，不得用 provider 请求替代 P1C 请求回执。

### 4.4 结果载荷

- 只有 `已读取` 可携带 `完整=true`、非零代次的对应快照。
- 只有 `内部不一致` 可携带非空稳定缺项组；该分支快照必须为空。
- `未找到、入口拒绝、版本漂移、许可拒绝、资源失败、未实现` 均为空快照、空缺项。
- provider 的内部不一致缺项可以在验证其稳定见证完整、排序和去重后原样转交；其它 provider 文本、日志和异常消息不进入缺项。

## 5. 整树根的两轮同代次算法

唯一施工图：`流程图/20260803_世界树快照读取服务读取完整世界事实快照_函数流程图_v0.3.md`。

入口通过后，`轮次` 从1开始，最多执行两轮。每轮直接调用顺序严格固定：

```text
1. 世界结构_.读取世界结构(
       节点直接世界结构读取请求{
           节点直接世界结构读取合同版本, 请求.头})
2. 特征_.读取宿主组完整当前特征(
       节点直接宿主组特征读取请求{
           节点直接特征查询合同版本, 请求.头, 全部存在身份})
3. 状态动态_.读取世界状态动态(
       节点直接世界状态动态读取请求{
           节点直接状态动态查询合同版本,
           请求.头, 全部场景身份, 全部存在身份})
4. 世界结构_.读取当前事实代次()
```

结构结果必须先满足：状态已读取、代次非零、世界根与请求根逐字段相等、场景/存在身份组按完整身份唯一。FEATURE-Q 的宿主组只取全部存在，不把场景静默加入特征宿主。P1B-Q 的场景组/主体组分别取全部场景和全部存在，即使一组为空也照常调用，以取得该 provider 自己的同次非零代次见证；P1C 不利用 P1B-Q 内部“空筛选提前成功”规则跳过 provider。

四个结果状态全部为已读取，且四个代次均非零时：

- 四代次完全相等：进入完整性检查。
- 四代次不完全相等且轮次1：丢弃本轮所有容器、缺项、排序状态和快照临时值，完整执行轮次2。
- 四代次不完全相等且轮次2：返回版本漂移、代次不对外暴露、空快照和空缺项。

任一 provider 返回非成功时立即按第8节映射，不重试。provider 返回已读取但代次0、成功结果携带缺项、结构根/身份组自相矛盾属于 provider 合同矛盾，立即返回内部不一致，也不进入代次漂移重试。

每次外层调用的直接 provider 最大调用数为：结构读取2、特征读取2、状态动态读取2、末次代次读取2。不得 sleep、等待、循环 try-lock、跨 provider 保存许可或用旧轮次材料补新轮次。

## 6. 跨 provider 完整性与稳定排序

四代次相等后，整树根依次检查：

1. 世界根等于请求根且在场景组恰一，根无直接父关系。
2. 每个非根场景恰一直接父关系，关系方向为父场景到子场景；全场景从根可达且无环。
3. 每个存在恰一当前场景归属，归属关系源端为本树场景、目标端为该存在。
4. 场景的直接子关系组、直接成员关系组与场景/存在记录双向一致；无悬空端点、重复关系或同稳定身份异内容。
5. 每个特征宿主属于存在组；实例槽、定义、当前值关系、当前值、原始值版本、来源和类型化证据完整；同宿主同槽唯一。
6. 每个状态的场景属于场景组，主体和来源存在属于存在组，特征/特征值来自该主体完整特征；全部角色关系和类型化发生时间完整。
7. 每个动态的场景属于场景组；主体、被改变目标或来源存在按其种类满足本树范围；前后状态、关系角色、动态种类、发生时间和聚合规则值与 P1B-Q 已验证材料一致。
8. provider 成功缺项组均为空；同身份事实逐字段相等，不能以去重掩盖矛盾。

任一失败返回内部不一致、共同非零代次仅用于诊断语境而不形成快照、稳定缺项组。缺项种类固定使用现有 `根、场景父关系、场景成员关系、存在归属、特征槽、特征定义、特征当前值、状态角色、动态角色、端点`；没有对应稳定对象的纯代次合同矛盾返回空缺项并由模块私有诊断承担，不新增枚举。

稳定排序规则版本固定为1：

```text
节点：稳定主键命名域、键值、身份版本
关系：稳定主键命名域、键值、关系版本
场景/存在：各自节点稳定身份
特征：宿主、特征定义、实例槽的节点稳定身份
状态：场景、主体、特征、发生时间值、状态身份
动态：场景、发生时间值、动态身份
缺项：种类、对象有无/对象身份、关系有无/关系身份
```

禁止使用内部句柄、容器迭代顺序、显示名称、SQL行序或调用时钟排序。成功快照固定写入合同版本1、世界规则版本1、请求世界根、共同非零代次、排序规则版本1、`完整=true` 和五类完整事实。

## 7. 两个对象根的纯值筛选

### 7.1 共同规则

对象入口准入成功后恰调用一次：

```cpp
读取完整世界事实快照(世界树读取请求{请求.头})
```

整树非成功立即映射到对象专属结果，回显已验证对象请求。整树内部不一致缺项可稳定转交，其它分支缺项为空。整树返回已读取但快照为空、`完整=false` 或代次0属于本层发现的内部不一致。

对象根之后不得直接调用世界结构、特征、状态动态或末次代次 provider，不重试整树根，不修改整树快照。

目标匹配规则：

- 目标完整身份精确命中一项才继续。
- 无相同稳定主键：未找到。
- 存在相同稳定主键但类型/身份版本不同：版本漂移。
- 多个精确命中或同完整身份异内容：内部不一致。

### 7.2 存在快照

唯一施工图：`流程图/20260803_世界树快照读取服务读取存在完整事实_函数流程图_v0.3.md`。

唯一存在必须携带当前场景归属。该关系目标端等于目标存在，源端在场景组中恰一精确命中；归属关系和场景事实双向一致。否则形成 `存在归属` 缺项并返回内部不一致。

纯值筛选：

```text
特征组：宿主 == 目标存在
状态组：主体 == 目标存在
动态组：主体、被改变目标、来源存在任一 == 目标存在
```

筛选后再次检查端点仍属于整树、同身份内容一致并按第6节规则排序。合法零特征、零状态、零动态为成功空组。成功结果沿用整树合同版本、规则版本、世界根、共同代次和排序规则版本，并写入 `完整=true`、唯一存在、当前场景及三组相关事实。

### 7.3 场景快照

唯一施工图：`流程图/20260803_世界树快照读取服务读取场景完整事实_函数流程图_v0.3.md`。

唯一目标场景的范围只含：目标场景事实、直接子场景、直接存在成员及这些直接成员的相关事实；不递归包含后代场景成员。

直接子场景从目标场景的直接子场景关系组解析，关系源端必须为目标，目标端在场景组恰一；直接成员从直接存在成员关系组解析，关系源端必须为目标，目标端在存在组恰一且该存在当前归属等于此关系。任一缺失、重复、反向或同身份矛盾形成 `场景父关系/场景成员关系/存在归属` 缺项并返回内部不一致。

纯值筛选：

```text
特征组：宿主属于直接成员存在组
状态组：场景 == 目标场景 且 主体属于直接成员存在组
动态组：场景 == 目标场景，且主体/被改变目标/来源存在至少一项属于直接成员存在组
```

合法零直接子场景、零直接成员及全部相关空组均为成功。成功沿用整树合同、规则、根、共同代次和排序规则版本，写入 `完整=true`、范围根场景、直接子场景组、直接成员存在组及三组相关事实。

## 8. provider 状态映射

世界结构、特征、状态动态和末次代次的非成功均立即同名映射：

| provider 状态 | 世界树业务状态 | 重试 | 快照 | 缺项 |
| --- | --- | --- | --- | --- |
| 已读取 | 继续；必须代次非零 | 仅四代次不等可整轮重试 | 待形成 | 必须空 |
| 未找到 | 未找到 | 否 | 空 | 空 |
| 入口拒绝 | 入口拒绝 | 否 | 空 | 空 |
| 版本漂移 | 版本漂移 | 否 | 空 | 空 |
| 许可拒绝 | 许可拒绝 | 否 | 空 | 空 |
| 资源失败 | 资源失败 | 否 | 空 | 空 |
| 内部不一致 | 内部不一致 | 否 | 空 | 验证后稳定转交 |
| 未实现 | 未实现 | 否 | 空 | 空 |

不得把 provider `未实现` 转为未找到、空成功、资源失败后重试、SQL回源、旧栈回退或默认世界。P1B-Q 对合法聚合形状返回未实现时，P1C 同样立即返回未实现且不得返回非聚合部分事实。

## 9. noexcept、异常和诊断责任

三个根固定 `noexcept`，各自完整实现置于 `try`。容器扩容、排序、去重、缺项形成和快照构造全部在 try 内。

异常映射：

```text
std::bad_alloc / std::length_error -> 资源失败、空快照、空缺项
其它异常 -> 内部不一致、空快照、空缺项
```

入口已验证时 catch 结果回显已验证请求；入口未验证时使用默认请求回执。catch 内只构造 P1C-QF 已静态证明无抛的空失败结果，不再次分配。

生产模块在全局模块片段精确包含 `../核心/容错检查.h`，非导出私有 helper 固定为：

```cpp
void 安全记录快照读取逻辑异常_(const wchar_t* 说明) noexcept {
    try { (void)追根因检查(false, 说明); } catch (...) {}
}
```

允许诊断：本层首次发现的跨 provider 材料内部不一致、对象筛选矛盾、成功结果合同矛盾、本层资源异常和其它异常。下层已返回的许可拒绝、未实现、资源失败、内部不一致及其诊断不得重复记录。合法未找到、入口拒绝和版本漂移不记录逻辑异常。诊断返回、日志文本和诊断设施异常不参与机器结果。

唯一诊断边：

```text
三个公开根
-> 安全记录快照读取逻辑异常_
-> 核心/容错检查.h::追根因检查(bool,const wchar_t*)
```

公开根不得直接调用 `追根因检查`，不得新建日志服务或让诊断决定返回状态。

## 10. 创建侧四矩阵

### 10.1 全根函数矩阵

## 11. 零代码机械推演

1. 默认整树请求世界根不完整，N01直接入口拒绝，四 provider 调用均0。
2. 合法请求第一轮结构/特征/状态动态/末次代次均为7，完整性通过，形成代次7完整快照。
3. 四状态均成功但代次为7/7/8/8，清空整轮；第二轮均为9时只返回代次9材料。
4. 第一轮和第二轮均代次不等，返回版本漂移，任何轮次材料均不外泄。
5. 特征返回未实现，立即返回世界树未实现；状态动态和末次调用均0，不查询 SQL。
6. 状态动态返回合法零状态/动态、代次7，继续形成成功空组，不映射未找到。
7. provider返回已读取但代次0，记录本层合同矛盾一次并返回内部不一致，不重试。
8. 存在入口准入后整树根恰调用一次；唯一存在归属到场景，纯值筛选相关事实并沿用整树代次。
9. 场景入口只解析直接子场景和直接成员，不递归后代；合法零成员成功。
10. 对象同稳定主键但版本不同返回版本漂移；多解形成稳定缺项并内部不一致。
11. 任一路径前后节点、关系、索引、类型合同、类型化值、幂等、持久侧账和事实代次导出逐值不变。

上述推演与三张单函数图、四矩阵和计划验证项双向对应，执行者无需再决定调用顺序、重试条件、状态映射、字段来源、异常、缺项、排序或对象范围。

## 12. 自检和验证合同

原位扩充唯一顶层身份：

```text
WORLD-TREE-P1C-QF-S01
顺序240
```

S0记录当前顶层自检登记/执行数量 `N`；本叶不新增、删除或重命名顶层项，完工仍为 `N`。专项至少覆盖：

- 三根默认、非法、完整、边界版本/主键请求；
- 四 provider 每种非成功同名映射和调用截断；

- 根、多父、环、多归属、跨树、重复身份、同身份异内容；
- 特征槽/定义/当前值、状态角色、动态角色和端点缺项；
