## 1. 目标、基线与不变边界

用户已裁决：没有上级节点信息不能创建准确特征信息。上级定位固定为场景C和组织父P，P是C特征根或同树已组织父F。缺失、无效、错场景或无法核验时，不分配身份、不写F、不登记观察、不生成概念。F内容、C已知F和P到F组织必须同次正式发布，不允许先造无父F后补挂。

代码基线为 `45ff0105a15b4f65e0160b71f6ac203f5f48e705`。1130/4110/4202/4205/7150/7160及0050、4030新口径是实施依据；0300 C043只记裁决路由。概念仍按FT加规范化域独立形成，位置不参与概念签名，名称/概念失败不撤销已定位F。C038具体二次派生实例不在范围。

本计划交付数据组合发布与现有应用消费者迁移，不要求主程序真实采集或跨进程恢复证明。两个20260906 FEATURE-EXISTENCE-SCENE未跟踪记录属于他人，禁止修改、移动、删除或提交。本任务不复活已退出的20260905/06旧概念计划。

## 3. 唯一物理位置及可见性

新增模块 `海中鱼巣/领域/数据服务.定位特征.ixx`，模块名 `海中鱼巣.领域.数据服务.定位特征`。本模块定义本节全部DTO、窄参与者接口及 `定位特征数据服务`，只import现L1公开合同/服务和特征值模块，不import特征/存在/场景具体类。新类型使用具名稳定编码字段，不迁移既有FT/F身份类型的模块归属。

三个既有类import新模块并各自公开继承 `定位特征内容参与者`、`定位特征已知参与者`、`定位特征组织参与者` 中对应的一个；三接口的虚方法全部private，只有在同一新模块定义的 `定位特征数据服务` 为friend，析构public virtual。既有类的override也为private。外部仅能传递借用引用以装配，不能调用准备、读取端口或提交自造写集。禁止将接口用于其它事务/owner选择或新增公开操作令牌。

每接口private固定四个基本方法：`const L1事实基座服务& 定位底座() const noexcept`、`L1所有者范围写端口& 定位端口() noexcept`、`bool 定位结构已就绪() const noexcept`、`bool 定位幂等键可用(L1所有者范围写入幂等身份) const noexcept`；仅用于一次组合的同实例核验和同步提交，组合服务不保存/复制/移动端口。其余private方法见第5节；方法体留各自原模块。组合服务持三接口引用及自己的串行互斥锁，不持第二owner、签发器或可变事实缓存。组合核心不得持有某参与者的本地锁再进入另一参与者；各owner既有内部只读依赖沿原锁顺序，L1 G守卫负责外部并发收敛。

构造 `定位特征数据服务(定位特征内容参与者&,定位特征已知参与者&,定位特征组织参与者&)` 的顺序固定为：先由外部合法装配完成三个现有owner的构造及显式结构初始化，再构造组合服务；组合构造只检查底座地址相同、各真实端口有效且绑定该底座、owner两两不同，取当前G后调用三个private就绪谓词，最后再读G相同。任一不满足抛 `std::invalid_argument`，组合构造自身零写、零分配事实身份，不调用初始化/登记/提交/接受材料，也不以端口有效代替就绪。外部先前初始化的独立写入不冒称组合构造写入。构造期间登记必须保持稳定；G变化可以重新装配，不猜已就绪。

`定位结构已就绪()` 不增加public ABI：三个override均private、const、noexcept，只在本owner锁内读已有布局/首次材料及L1事实，任何未就绪、资源失败、漂移、退出或异常返回false，不改成员状态、不补登记、不调用原带写入副作用的初始化。具体判定固定：

- 内容：`definition_ready_ && information_ready_` 为必要条件；同时在同G读取并核验d_/f_两组完整结构，复用 `结构就绪(定义,G,G)` 与 `结构就绪(信息,G,G)` 及原端口/来源读取。两bool为false直接false，不能临时置true。此检查不要求业务FT/F已存在。
- 已知：读取原 `存在族来源初始化幂等身份` 首次材料，按现 `形成存在族初始化写集` 和 `接受存在族首次材料` 中已有只读算法核验完整首写、映射、所有者、现有效普通空锚点/归属类型，并与已保存的存在族锚点/归属类型逐项相等；不调用会给字段赋值的接受函数。再复用现关系类型组有效及特征成员类型读取，检查全部已保存配置和真实同底座。不得调用 `初始化存在族来源`，也不依赖任意业务存在ID。
- 组织：复用现 `布局形状有效`、`包含布局形状有效`、`登记材料匹配()`、`扩展登记材料匹配()`、`包含扩展登记材料匹配()` 和端口/现有只读依赖绑定检查；特征组织扩展必须已交付且真实可读，不能因原六编码有效就推断特征扩展就绪。

各谓词首尾G须一致；组合构造还统一核验三次读取期间G未改变。公开写操作依然按请求G/H独立核验，不将一次构造就绪视为永久权威。接口不得从编号相同推断同底座。内容端口非const只为调用既有非const L1 v2成员；第二/第三端口作为const实参借入，同步结束即释放引用，不使用const_cast。

## 4. 新公开合同

全部结果值式，操作字段不进入F本体。当前准确特征实现仅支持I64及可解析为I64的特征值身份，本计划保持该表示面；其它表示明确不支持，不增加轮廓算法。

| 类型 | 精确字段 |
| --- | --- |
| 定位特征位置 | `稳定编码 场景,组织父`，两者有效且不等 |
| 定位特征预算 | `uint64_t 最大候选数,最大路径长度`，前者非零，后者1..4096；内容/已知组合窄读沿现有限预算 |
| 定位特征创建请求 | `uint32_t 版本=1; uint64_t G0=0; 定位特征位置 位置; 稳定编码 正式特征类型; variant<int64_t,特征值身份> 准确值; optional<稳定编码> 指定F; L1所有者范围写入幂等身份 组合键,内容键,已知键,组织键; 定位特征预算 预算` |
| 定位特征事实 | `稳定编码 F,正式特征类型; int64_t 准确I64; 定位特征位置 位置; 稳定编码 已知关系,组织关系; uint64_t 出生H`；出生H取F实际创建代次，迁移后位置关系可较晚，不伪造同生 |
| 定位特征结果 | `uint32_t 版本=1; 定位特征状态 状态; uint64_t Gread=0; optional<uint64_t> 首次发布H; optional<定位特征事实> 事实; vector<稳定编码> 候选F; 定位特征创建请求 原请求` |
| 定位特征读取请求 | `uint32_t 版本=1; uint64_t Gread,H; 稳定编码 F; 定位特征预算 预算` |
| 定位特征读取结果 | 版本1、专属状态、Gread/H、`optional<定位特征事实> 事实` |

`定位特征状态:uint8_t` 固定：已创建=1、已复用=2、精确重复=3、已读取=4、入口拒绝=5、未找到=6、目标已退出=7、位置冲突=8、需选择F=9、存量未定位=10、事实代次漂移=11、幂等冲突=12、预算不足=13、历史材料不可用=14、表示不支持=15、资源失败=16、内部不一致=17、已可能发布=18。映射现provider精确同义状态；无对应的引用冲突按其位置/内容来源映射位置冲突或入口拒绝，损坏来源/回显矛盾内部不一致，不吞掉资源/历史/漂移。

公开函数：`定位特征结果 创建或复用(const 定位特征创建请求&)`、`定位特征读取结果 读取定位特征(const 定位特征读取请求&) const`。同一创建入口承担原键重放，不再设通用提交函数。仅供装配的三个公开只读谓词为 `bool 使用内容参与者(const 定位特征内容参与者&) const noexcept`、`bool 使用已知参与者(const 定位特征已知参与者&) const noexcept`、`bool 使用组织参与者(const 定位特征组织参与者&) const noexcept`，分别只比较借入对象地址，不返回provider或端口。

`定位幂等键可用` 为三个参与者各自实现的private纯值谓词，只有同模块组合核心可调用。它不读L1、不查首次账、不分配身份、不加锁、不准备片段，不依赖业务F/FT或当前G，也不改变就绪标记。返回true仅表示该键形状有效且不属本owner保留键；不证明该键未使用或请求可提交。各owner复用自身唯一保留常量来源及原守卫，不在组合模块复制这些常量：内容owner拒绝原结构初始化键1及 `I64比较绑定结构扩展初始化幂等身份`；已知owner拒绝原初始化键1及 `存在族来源初始化幂等身份`；组织owner拒绝原结构登记键1、`场景特征组织扩展登记固定幂等身份`、`场景直接包含扩展登记固定幂等身份`。三者均拒绝零键及整个0x4E43前缀。原准备方法对四键的校验改为调用本owner同一谓词；若原键1尚以字面量散列，收敛为该owner内部唯一具名常量并由其初始化/守卫共用，不改变任何键值或公开字段。

创建或复用入口顺序固定：先检查请求版本、位置/字段形状和四键互异等纯值条件，再对四个键分别调用三个参与者谓词（全部十二项须为true），任一false返回入口拒绝=5；这一门禁必须早于本次请求的任何首次材料读取、准备、候选查询或写入。它同时覆盖首次创建、指定F复用、自动复用及原键重放，不能通过“先准备新F”间接检查，因为复用不应建立片段。初始化键已有首次材料也仍由此提前返回5，不再进入4/1/1材料形状核验而误报17。普通已用非保留键通过此门禁后，仍按原首次材料/完整语义规则判断精确重复或幂等冲突；不能把“可用”解释为首次不存在。

请求四键必须非零且两两不同，四者均必须满足 `(键.值 >> 48) != 0x4E43`，拒绝整个进程维护保留前缀而非某个单键；不得等于任一参与owner的保留登记键；保留键判断复用各owner的现有守卫。请求不能缺位置后在函数内部默认填根。候选/路径预算不参与内容同一性，调用方须保存原完整请求以便有界重试。L1精确幂等比较的是原G、四键、C/P/FT、准确表示种类和解析I64所形成的完整规范化三写集；不声称能从首次账恢复未写入的预算或同值输入引用身份字节。新建必须指定F为空；非空只能进入复用裁决。预算变更仍须重新满足完整核验，不造成新的语义身份；不同原始引用解析为相同I64且表示种类相同，按原复制值模型是同义写入，不另存外部身份整数副本。

创建成功谓词仅接受1/2/3、版本1、非零Gread、完整F/FT/位置/两关系及出生H不晚于读回截止，准确值和位置与原请求互证；1/3必须有非零首次发布H及共同三参与者读回，2零本次发布且无首次发布H。需选择F返回全部确定身份升序唯一候选且无事实；超预算不截断。其它失败事实及候选均空；已可能发布保留原请求及已知首次H，不把部分F作为成功载荷。读取成功要求4且Gread/H回显严格一致，H时三种事实均有效。

## 6. 原键重放、首次创建和复用

入口先形状检查及第4节四键乘三owner纯值门禁，缺C/P或任一保留键必须在首次材料读取及任何provider写之前结束。取实际Gread；G0>Gread漂移。所有首次已有端点以G0为H读取，读时Gread保持一致；不将G0覆盖为freshG。各owner准备必须支持历史G0，包括后来已退出的C/P/FT，不能在重放前强制它们仍当前。历史材料被清理明确失败，不猜恢复。

先查三个owner内部原键首次材料（由组合核心经private端口调用既有读取首次写入材料，不增公开首次查询）。每项先核验读取合同版本、owner、内部键及读取Gread精确回显；未找到必须首次写集/首次结果同时为空，成功必须两者同时完整。首次结果须为原CRUD合同、对应owner/键、成功、发布位true、重试边界不适用，H等于其首次规范化写集期望G加1；映射形状按§6.1且自身事实有效。首次写集内部合法但期望G或语义与本请求不同为幂等冲突；错误读取头/不完整材料/自身矛盾为内部不一致，资源或漂移保留原状态。不得把失败查询当未找到。完成每项核验后：全无时才是首次；一项/两项存在或三个首次发布H不同为内部不一致，禁止补齐。三个存在时非空指定F返回入口拒绝；先验证各首次材料头、结构和映射完整，损坏返回内部不一致；再将跨参与者引用通过原映射转换为原owner规范化请求，与本次三个原请求片段完整比较，语义不符返回幂等冲突。互证通过直接重送原组合请求，由L1组合账决定精确重复或幂等冲突；不要依据当前同值查询或当前父路径重决策。首次记录存在但组合键不同或其组合账不存在时不能单独重放owner片段。三份材料已证明首次H=G0+1；若重送v2返回事实代次漂移，意味着该组合键未证明绑定原请求，映射为幂等冲突，不用新G补建组合账。L1因其完整性检查返回内部不一致则原样映射；不新增组合账读取API，不从三个owner账自行拼出组合成功。

若全无且Gread不等于G0，返回漂移零写。Gread=G0时核验位置、正式FT/值和预算，再按准确内容查询全部候选。指定F只允许属于此完整候选组；按实际路径分类：同C/P且C已知F可以复用，异C/P位置冲突，无路径存量未定位，损坏路径内部不一致。未指定且多于一项精确候选返回需选择F，不自动按位置过滤到首项；一项按上述规则，零项才建立新F。准确相同但位置不同不隐式复制。复用不写出生事务、不新增组织或已知边；缺C已知F但F路径/内容完好时明确返回位置冲突=8，读取定位特征同样如此；零写且没有完整事实载荷，由外部原有存在操作修复后新请求重试。重复已知关系、损坏关系或错误owner仍为内部不一致，不混成正常缺失。

首次新建重新同G核验三片段并提交。前置拒绝、L1交换前失败均零F/零两边/零首次账。提交后确认三份映射和共同G1=G0+1，再以实际新Gread及H=G1分别读取内容、已知、组织历史及原C/P路径；一致才返回已创建。结果不确定返回已可能发布和原请求/已知G1；即使异常也不回滚、不换键、不独立补边。重放成功按首次G1读回而非把后来的治理变化映射进首次结果。

读取定位特征先读准确内容，再通过场景路径得到自身C/P及正式组织边，再核验C已知F。原生F出生必须三事实创建代次同G1；已明确迁移的存量允许旧出生H与后来组织H不同，并按实际事实报告，不重释出生代次。无路径返回存量未定位，不能包装成已定位。

## 7. 概念报告与消费者迁移

`特征概念观察请求` 必加 `定位特征创建请求 定位`，原观察中的FT/准确值/指定F须与定位请求逐字段一致。构造签名改为 `特征概念应用服务(特征类数据服务&,概念树类数据服务&,定位特征数据服务&)`，在原 `concepts.使用特征服务(features)` 核验之外必须用定位服务的 `使用内容参与者(features)` 比较实际同一实例；三参与者同底座由定位构造保障。不在应用新增L1。增加只读装配谓词 `bool 使用定位参与者(const 定位特征已知参与者&,const 定位特征组织参与者&) const noexcept`，仅转调定位服务的两项对象地址检查。处理首先调用定位创建/复用，在完整成功之前不调用类型观察登记或概念形成。原无父 `创建准确特征` 声明/定义从特征类物理删除，没有默认父重载或fallback。

`特征概念处理结果` 添加 `optional<定位特征结果> 定位结果`，沿原完整概念/名称字段报告最终概念身份及定义。新增状态 `定位拒绝=11`、`定位待原请求确认=12`、`准确F已定位概念未完成=13`（尾部追加，不复义原值）；原成功“完成”必须定位事实完整且概念、名称指向同一实际F/最终概念，概念C与场景C严格分字段。已有概念处理的技术原因枚举可用，定位原因为 `optional<定位特征状态>`，不压成未找到。

定位失败返回原定位请求及真实原因，概念/观察载荷空。定位已可能发布必须先原请求收敛，不能进入观察。定位成功但概念失败保留定位事实、准确F、已发布观察和原概念待确认请求，报告准确F已定位概念未完成；重建应用后以调用方保存的完整原观察+定位请求及既有观察键恢复。定位原键固定，概念后续使用自己的合法G，不用出生G强迫全部阶段原子。完成结果不能只有F或FT而遗漏概念事实。

场景成员应用输入中的实际场景必须与定位C一致，组织父显式传递，不从成员E/概念父推断P；其特征请求及结果组合沿现服务，场景成员应用构造签名保持现有五参数，并追加 `features.使用定位参与者(existences,scenes)` 检查，证明定位中的存在/场景正是当前消费者借入实例。存在概念应用只消费已定位准确F与概念，不新增另一创建链。扫描所有旧创建调用，当前唯一生产点和 `验证工具/场景特征实例组织专项验证.cpp` 同次迁移。已有场景组织专项的独立新叶用三分区定位创建得到，既有组织行为测试使用起点旧模型的确定存量fixture：测试装配期以唯一L1端口按起点创建路径的实际字段/关系形状写入无父F，再将同一端口move交真实特征provider，当前新模块不得提供该写入口；fixture无第二端口、无整数伪造身份，记录其仅代表旧存量。不能通过公开无父创建恢复旧生产入口。

场景组合的恢复与返回同步闭合：`场景成员概念继续材料_v2` 尾部增加 `optional<定位特征结果> 已确认定位`，特征阶段取得完整定位成功后保存；重建对象继续时将其传给下述双参特征收敛入口，未知发布材料不伪装成功回执。`场景组合投影_v2` 增加必需 `定位特征事实 定位`，完整谓词必须互证定位F与投影F、定位场景与S、根路径/已知关系及H读取。`场景特征概念结果_v2::成功` 还须其处理结果定位完整并与已确认F一致。场景状态尾部追加 `定位拒绝=22`、`定位待原请求确认=23`、`准确F已定位概念未完成=24`，映射子结果三状态且保留原完整子载荷；需选择F仍映射原需选择准确F并保留全部候选。不能把这些状态降成内部不一致或已完成。现版本2保持，旧调用缺新增必需定位输入时入口拒绝；无隐式默认语义。

`读取已发布类型观察` 等返回完成的只读路径同样以调用方Gread和该路径的正式H读取定位事实并互证观察F；预算沿请求定位预算。未归树只返回存量未定位的具名原因，不补组织、观察或概念。只读名称查询可继续作为准确内容审计，但不据其返回宣称完成定位创建。

存量无父F不批量推断位置、不删除；正常创建/复用返回存量未定位，调用方显式C/P并先按7150建立已知后走原4205组织入口，位置核验通过才可使用新应用。已有其它位置的F只能按原使用引用共享，调用创建接口要求错误自身位置时失败。当前不增加换父/解组织/级联删除。

零出生写的已复用结果不绑定四键，因此跨调用恢复不能把原G0请求当作已发布创建重放。追加公开重载 `特征概念处理结果 收敛类型观察(const 特征概念观察请求&,const 定位特征结果& 已确认定位)`：先逐字段核验保存结果原请求与本次定位输入相同，以实际Gread和保存成功结果的Gread为H调用定位历史读取，核验F/FT/准确值/C/P/两边/出生H全部一致，才恢复已定位阶段并按原观察键继续概念。该重载不产生出生写、不修改原键、不接受调用方未经provider验证的成功标记。保存的创建成功回执同样可走此路；只有已可能发布回执时必须原创建键收敛，不能跳过出生确认。无保存回执且零写复用无法在新G恢复时返回具名材料缺失，不猜新F。原单参收敛入口保留用于已绑定创建键和现有对象已确认状态，不谎称可恢复已丢弃回执。

### 7.1.2. 三项真实历史见证与固定截止

对给定合法的S、E、R和 `0 < H <= Gread`，按同一Gread执行以下固定只读链，每一步失败立即停止，不把失败当无成员：

1. 在实际场景实例调用 `读取场景角色历史(场景历史身份请求{2,Gread,H,S})`；要求 `成功(原请求)`，角色载荷的场景、Gread/H与请求一致，真实场景角色/四根及来源由该provider证明。
2. 在实际存在实例调用 `读取存在身份来源历史见证(Gread,H,E)`；要求 `成功(Gread,H,E)`（合同版本2、相同截止和完整族来源/生命周期）。不读取/解释E的全体成员、当前采用或其它特征。
3. 在同一场景实例调用 `读取直接存在成员历史(场景直接包含历史读取请求{1,Gread,H,R})`；只接受结果头状态已读取、版本1、精确Gread/H、首次发布H为空及 `成功()`。包含载荷必须完整，种类为存在成员、父场景=S、成员=E、关系编码=R、关系源=S、目标=E、有效关系类型、角色或顺序=1；包含和头的Gread/H一致，关系创建代次非零且不晚于H、投影退出代次为空。返回该完整载荷。

直接包含入口只证明该关系的历史形状及生命周期，不能单凭它证明场景角色和E身份，前两步不得省略。任何provider声称已读取而成功谓词/自身头或载荷不完整，返回内部不一致；一个本身合法的关系却与调用方指定S/E/R不相符，返回引用冲突。窄直接存在入口对其它种类关系返回内部不一致时忠实保留，不越provider重新解释为存在关系。所有读取完成后沿应用当前事实守卫确认Gread未改变，漂移保留原请求，零本次后续写。

场景成员处理在首次特征处理之前，以及每次继续进入尚未提交的特征/采用写阶段之前，均用同一实际Gread分别核验 `H=原请求.H` 和 `H=Gread`（二者相同只读一次）。位置C必须等于请求S；P始终是原定位请求给定的组织父，E及成员关系不替代P，也不使概念身份随S/E改变。进入写阶段仍遵循各原写请求的固定G/原键守卫；前置读取不把freshG覆写到原定位请求或概念待确认请求。

存在概念应用的 `场景检查` 沿既有调用点执行上述同一算法，截止分别为限制的原场景H与本次Gread；不改形成/复用、概念身份、世界材料算法、事务和原键收敛。继续入口先比较保存原限制与外部传入限制（含R），不能切换成员关系后续办旧业务。

最终投影在本次最终Gread核验原H及当前H的同一个R，再保留当前H的完整直接包含事实；定位、准确F、概念、名称及采用也按原最终同cut规则互证。投影完整谓词必须检查成员事实Gread/H与投影一致、存在成员种类、源S/目标E/R非零及生命周期有效、定位场景=S及F/概念/名称一致；外层完成判定另外将R与原请求逐项相等。不能因R已退出但新R2又连接相同S/E就重选R2宣称原请求完成。此前已发布的定位/观察/概念/采用事实不撤销；成员检查失败返回真实非成功及已有子结果/原继续材料，最终投影为空，不能伪造完成，也不声称此前阶段零写。

单关系历史接口不接受枚举预算；原 `场景关系预算` 保留且必须至少1，仅准许读取一个显式成员关系，不声称它是整个场景成员集合的数量上限。原存在概念预算的非零准入保持，本检查读取固定S/E/R见证，不枚举或截断成员组；其它算法原预算消耗不变。provider内部若报告数量预算不足仍完整向上传递，不能以只需一个关系为由吞掉预算失败。
