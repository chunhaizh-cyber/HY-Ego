# L1-SIMPLIFY-P76-DYNAMIC-CAUSAL-CANDIDATE 动态事件因果候选投影详细设计 v0.1

## 1. 目标与最高裁决

用户已正式裁决：因果信息来自动态信息；动作不是因果来源或形成前提；允许不知道造成变化的动作；动态材料不足时跳过；因果按事件时间生成且事件级图必须有向无环；类型或对象层面的后续往复允许；由动态形成的候选与经实际应用确认的因果必须分权。

本叶据此成为 STEP-6 依赖链中最早可独立施工 provider：新建唯一无对象状态纯值所有者 `海中鱼巣.领域.服务.L1动态因果候选投影`，实现 `投影当前世界动态事件因果候选`。它只消费调用方经 P29 正式入口取得的 P28 `完整世界事实快照`，把其中 P27 完整关系20状态迁移动能机械投影为 `待应用确认` 的事件级被动因果候选。

本叶形成独立、调用方拥有的不可变纯值投影，写入数为0。它不分配稳定因果身份、不发布因果事实、不持久化候选、不实现安全直接因果图、不确认“准备因必得果”。

当前阶段只覆盖同一生产进程正常存活期间的读取、纯值投影、调用方消费和后继确认接口边界。程序崩溃、异常终止、断电、重启后续作、跨进程恢复及跨进程幂等重放全部排除。

## 2. 规范冲突与最小可执行边界

1190允许一次角色闭合、来源完整且可回查的证据形成实例因果；4310同时规定单样本只是证据、不是已验证因果。按用户本轮更高权威，二者在本叶的最小统一解释固定为：

1. 一次完整动态足以形成一条事件级因果候选，不足以形成已确认可应用因果；
2. 候选只表达“这个动态中前状态可能是条件、后状态是结果”，不表达跨事件必然性；
3. 只有后继实际应用验证取得独立确认事实后，已发布因果才可进入 `已确认可应用`，并承担“准备好因，应用条件成立时应获得果”的保证；
4. P76 输出永远是 `待应用确认`，不得由调用方改写成已确认；
5. 4310 的反例、样本族、适用范围和应用确认属于后继叶，不在 P76 内猜测。

这已经闭合施工所需语义，无需新的用户裁决。

## 6. 输入、材料不足与状态分账

正式输入链固定为：调用方以同一根调用 P29 `读取完整世界事实快照`；只有 `世界树业务状态::已读取`、快照存在、`完整=true`、根及非零截止符合请求时才调用P76。P29非成功时P76调用0。

P76入口校验本叶三个版本、非零根/截止、P28全部版本、完整性、根和截止。版本或请求形状错误为入口拒绝；根不存在为未找到；请求截止与快照截止不同为版本漂移；完整成功载荷内部互相矛盾为内部不一致。所有非成功均零投影。

材料不足与损坏严格分开：

1. 合法动态材料尚不足以同时给出唯一条件、结果、时间方向、适用锚点或可回查来源链时，记录一项稳定跳过原因，不生成候选，整体仍可成功；
2. 后续同一动态在更晚正式快照中材料充分时，按新截止重新形成候选；P76不缓存“已跳过”；
3. 动态身份重复、同一字段出现矛盾值、快照声称完整却引用不存在对象、排序破坏或生命周期不可能属于内部不一致，不得伪装材料不足；
4. 当前P27 v0.1只公开完整关系20迁移动能，故正常输入中材料不足跳过数应为0；不完整原始动态不会被P27收入公开组。冻结跳过分账是为了禁止未来调用方把知识不足升级为错误或猜测，不授权P76旁路读取原始动态；
5. 合法零动态返回 `已投影`、同根同截止、完整空候选/空跳过组。

计数必须满足：`已检查动态数 == 候选组.size() + 材料不足跳过组.size()`。

## 7. 单动态确定映射

按P27动态组既有 `(场景编码, 后状态发生时间, 动态编码)` 顺序处理。每个可形成候选的动态映射固定为：

| 候选字段 | 唯一来源 |
| --- | --- |
| 证据动态/事件身份 | P27当前迁移动能的动态稳定编码 |
| 条件状态/条件事实/条件时间 | 关系20角色4前状态及P27完整状态事实 |
| 结果状态/结果事实/结果时间 | 关系20角色5后状态及P27完整状态事实 |
| 场景、主体、被改变目标 | 同一迁移动能角色2、1、3 |
| 来源链 | 关系20角色9来源存在及完整动态证据 |
| 真实性 | 固定待应用确认 |
| 动作身份、方法运行身份 | 固定空 |
| 共同截止 | P28快照事实截止代次 |

必须互证条件与结果身份不同、主体/场景/实例槽/来源存在相同、`0 < 条件时间 < 结果时间`、动态时间范围等于两端时间、差异非零、角色6—8为空、全部创建代次不晚于截止。

## 8. 时间顺序、同序与事件级DAG

输出按 `(结果发生时间, 条件发生时间, 证据动态编码)` 升序。时间是因果方向；稳定编码只用于同一时间材料的确定性平局，不赋予因果先后。

每条候选边从较早条件事件状态指向较晚结果事件状态。构图验证按事件身份和时间进行，不按状态类型或对象业务值进行：

- 自环、逆时间、同一事件回指自身或沿候选边回到不晚于起点的事件属于内部不一致；
- 两个不同事件可形成 `t1: A→B`、`t2: B→A`，只要事件/状态身份不同且 `t1 < t2`，这是允许的类型/对象层往复，不是事件级环；
- 完整排序键重复、同一动态重复或同一事件身份映射不同端点属于内部不一致；
- 同一时间的不同动态只确定输出次序，彼此不得因编码平局顺序建立因果边。

P76只输出直接事件候选，不计算间接边、路径、层级或安全深度。

## 9. 生命周期、并发与零写

函数只借用调用方快照，返回前不保存引用。投影生命周期由调用方拥有，只代表其非零截止；世界推进后旧投影仍是历史纯值，不冒充当前。

函数无对象状态且不 `noexcept`；`std::bad_alloc`映射资源失败，其它未预期异常映射内部不一致。生产函数对P15/P16/P17/P27/P29/P75/L1、安全直接因果图provider、锁、许可、事务、仓库、SQL、缓存、日志、时钟、sleep、retry和事实写入调用均为0，不形成第二快照。

本叶不拥有持久写入、确认状态推进或已确认事实生命周期。候选只有后继正式发布后才可能取得稳定因果身份；应用确认也必须另形成可回查事实，不能原地改写P76纯值。

本叶不设计恢复介质、恢复编码、启动扫描、崩溃窗口、提交后未返回恢复、跨进程成功账或失败恢复矩阵。该排除不取消后继正常运行发布叶所必需的业务权威事实、进程内幂等/冲突或原子提交；这些合同必须由对应写入叶按实际事务范围独立冻结，不能借P76零写边界预先删除。
