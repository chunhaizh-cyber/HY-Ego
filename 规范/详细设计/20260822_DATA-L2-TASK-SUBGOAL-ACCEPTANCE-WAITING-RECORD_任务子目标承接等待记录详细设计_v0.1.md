# DATA-L2-TASK-SUBGOAL-ACCEPTANCE-WAITING-RECORD 任务子目标承接等待记录详细设计 v0.1

日期：2026-08-22

状态：当前最早提供者叶的施工设计；代码尚未实现，计划尚未登记

## 1. 目标、范围与完成条件

本设计为任务 owner 增加一类挂在任务虚拟存在下的强类型`任务子目标承接记录`。它保存一次已经由 DATA 外任务业务裁决通过、需要跨调用保留的子目标承接与等待结构，不保存仍处于调用栈内的`任务缺失条件草案`，也不把该记录解释成需求候选或正式需求。

记录固定绑定：

```text
来源任务 + 唯一任务虚拟存在 + 筹办轮次
+ 显式父需求
+ 本轮采用方法、内容版本、规格版本、主轴结果和条件
+ 子目标三元组与可选条件场景
+ 来源共同事实截止 G
+ 建立幂等身份
+ 待绑定子需求 / 等待子需求 / 子需求已回流待父需求重判状态
```

本叶完成条件：

1. DATA-L2 能以一份完整原子写集建立记录，返回强类型记录身份和权威读回；
2. 同一记录只能从`待绑定子需求`迁移到`等待子需求`，再迁移到`子需求已回流待父需求重判`；
3. 绑定时必须证明已发布子需求的当前父需求就是记录中的显式父需求，且子需求目标与记录冻结的子目标精确相同；
4. 回流登记必须引用同一子需求、当前结果状态、可选动态、可选子需求承接任务、发生时间和版本；它只形成“待父需求重判”结构，不直接唤醒来源任务；
5. 记录可以按身份当前 / 历史读取，并可按任务与筹办轮次有界读取当前或历史记录组；
6. 显式退出使记录退出当前投影但保留历史，旧筹办轮次不得被覆盖；
7. 四个写入口均满足同键同完整请求精确重复、同键异请求幂等冲突、旧 G 发布未知收敛和非成功零变化；
8. 普通应用能够取得唯一`L2任务子目标承接记录结构服务`实例，专项只能经该实例验证公开合同。

## 2. 明确排除

本叶不负责：

- 判断条件草案是否应形成独立子目标；
- 选择多个需求列表成员中的父需求；
- 建立需求、需求列表项、父子关系或列表成员关系；
- 在需求 owner 中建立对本记录的来源引用；
- 把任务中间字段复制进需求核心；
- 裁决子需求已经满足、父需求已经满足或需求正式结算；
- 直接唤醒旧来源任务、复用旧路径 / 旧实例 / 旧冻结或自动建立新筹办轮次；
- 实现成员逐需求核算、结果可共用 / 争用关系裁决、争用结果的优先级分配、共享证据复用或价值 / 预算结算。

需求侧统一入树是本提供者的直接后继。父需求重判、按当时当前需求列表 / 任务关系决定是否重新筹办，是更后的业务叶。任务完成后的成员核算只保留为总路线完成边界，不进入本记录字段、状态或写集。

## 3. 正式依据和关键裁决

### 3.1 正式依据

- `规范/0050_项目通用机器逻辑与禁止性规则总纲_20260721.md`：DATA-L2 只保存强类型结构；每类结构只有一个写入 owner；业务裁决在 DATA 外；完整请求幂等和原子发布不可拆散。
- `规范/3100_根规范_需求.md`：只有独立子目标进入需求树；普通方法步骤和替代方法不得伪装成需求。
- `规范/3200_根规范_任务.md`：任务虚拟存在是任务治理状态唯一宿主；筹办闭合可以形成子目标承接或合法等待；等待必须包含等待对象、合法生产者、重新触发条件、版本和事实截止；重新筹办保留旧轮次和旧事实。
- `规范/5210_子规范_任务状态特征集合与阶段关联_20260720.md`：`等待子目标`必须具备子目标、合法生产者和回流触发关系，且旧筹办轮次状态保留为历史。
- `规范/5220_子规范_子任务完成触发父任务重筹办_20260720.md`：子项回流先触发父需求 / 父任务重新裁决；子任务结束或消息不直接证明父目标完成。
- `规范/5160_子规范_需求正式结算记录与唯一结论.md`：任务完成、需求满足和价值结算分账；当前目标事实与价值 / 预算分配不得互相替代。

`规范/4260_子规范_L2任务核心方法路径与对外接口统一合同.md`仍是待确认修订稿，只作为结构命名和缺口定位参考，不承担本设计的机器语义来源。本轮用户裁决只作为设计输入；本叶机器语义受上述现行正式规范约束，本设计负责在其范围内冻结可施工合同，不单独建立第二套机器事实。后继成员结果分配在取得对应正式规范治理前不得进入代码计划。

### 3.2 关键裁决

1. 显式父需求是子需求的正式来源 owner 与回流锚点；来源任务、方法、版本、主轴结果和条件只作本次发现 / 准入证据，不取代父需求。
2. 多成员需求列表项由 DATA 外调用方显式选择本次父需求；本结构服务只验证该父需求确属来源任务当前列表项，不任选、不全挂。
3. `任务缺失条件草案`和需求确认材料保持值式；只有需要跨调用等待的结果才进入本记录。
4. 需求结构后继只保存需求自身父子 / 列表结构，并在正式合同需要时引用本记录身份；不得复制本记录全部任务字段。
5. 子需求回流只把本记录推进到`子需求已回流待父需求重判`。后继必须先重判父需求，再读取当时当前列表成员和任务关系决定是否形成新筹办；本记录中不存在“永久来源任务回流关系”。
6. 任务完成后的需求成员按冻结成员快照逐项独立核算。逐成员核算前必须先裁决任务结果对当前成员集合属于哪一种消费关系：
   - `可共用结果`：一个成员消费或引用后，不减少其它成员可消费的结果数量、范围、所有权或有效性；全部具备当前资格的成员可以共同引用同一正式结果 / 共同事实，但仍须分别重读自己的目标、当前事实、路径、授权和结算资格，形成各自的满足 / 结算记录；
   - `争用结果`：一个成员消费后会减少其它成员可取得的数量、份额、独占所有权或有效机会；必须在共同事实截止上冻结可分配结果、当前候选成员、每个成员的优先级证据和规则版本，再按正式成员分配优先级依次核算、分配并扣减剩余结果；不可分割结果在首个合法分配后即无剩余，可分割结果则以每次分配后的剩余量继续核算下一成员；
   - 目标事实可以共同证明多个需求当前满足，但价值、预算、归因份额和其它争用结果不得因共同事实复用而重复领取。
7. `正式成员分配优先级`是后继需求成员核算叶必须单独冻结的业务合同。现有任务有效执行优先级只决定任务调度顺序，不得直接复用为结果分配优先级；需求权重、结算预算、队列位置、创建时间和稳定编码也不得在缺少正式映射时充当默认优先级或同级裁决。优先级提供者、输入、版本、同级确定性顺序和漂移处理尚未由现行材料闭合，必须在后继设计中具名解决；该缺口不进入也不阻断本 DATA-L2 记录叶。

### 5.1 新建文件

```text

海中鱼巣/领域/服务.L2任务子目标承接记录结构.ixx
```

模块固定为：

```cpp

```

新数据头的模块附着位置唯一冻结为`海中鱼巣.领域.服务.L2任务结构`的导出区：在`服务.L2任务结构.ixx`现有全局模块片段中定义`L2_TASK_SUBGOAL_ACCEPTANCE_RECORD_NO_INCLUDES`，并在现有`export { ... }`内、`L2任务结构.数据.h`之后恰好一次文本包含：

```cpp
#define L2_TASK_SUBGOAL_ACCEPTANCE_RECORD_NO_INCLUDES

export {
#include "L2任务结构.数据.h"
#include "L2任务子目标承接记录.数据.h"
}
```

`L2任务子目标承接记录.数据.h`使用`#pragma once`，仅在未定义上述宏的普通头文件消费路径中包含其最小依赖；不得成为独立 header unit、模块分区或第二个 DTO 导出面。新`服务.L2任务子目标承接记录结构.ixx`只从`海中鱼巣.领域.服务.L2任务结构`取得本记录 DTO 和受限端口，同时为调用公开读取合同直接导入需求、方法、状态、特征和动态五个服务模块：

```cpp
import 海中鱼巣.领域.服务.L2任务结构;
import 海中鱼巣.领域.服务.L2需求结构;
import 海中鱼巣.领域.服务.L2方法结构;
import 海中鱼巣.领域.服务.L2状态结构;
import 海中鱼巣.领域.服务.L2特征结构;
import 海中鱼巣.领域.服务.L2动态结构;
```

新服务禁止再次`#include`该数据头；任务模块也禁止反向导入新服务。这样 owner 内端口与外层结构服务消费同一组导出类型，不形成循环或第二 DTO 导出面。

`L2任务子目标承接记录结构服务`属于 DATA-L2 任务 owner。它依赖任务、需求、方法、状态、特征和动态服务的公开读取合同，再经任务 owner 的受限写入端口发布记录；不得取得 L1 raw 端口、仓库、锁或事务。

| 状态 | `子需求` | `回流` |


前三个入口成功时`记录`必有；退出首次成功或精确重复返回退出发生代次上的最后历史投影，且该投影生命周期带退出代次。`成功()`只接受`已提交`或`精确重复`、非零截止与变更代次以及完整记录。所有非成功结果`记录`为空。

### 6.4 物理结构角色与基数

记录节点属于任务 owner 的独立结构族，不复用任务、路径、实例、实际结果或治理状态节点类型。每个当前记录必须恰有：

| 记录关系角色 | 基数 | 目标 |
| --- | --- | --- |
| 所属任务 | 1 | `L2任务身份` |
| 所属任务虚拟存在 | 1 | `L2任务虚拟存在身份` |
| 显式父需求 | 1 | `L2需求身份` |
| 来源方法 | 1 | `L2方法身份` |
| 来源主轴结果 | 1 | `L2方法结果身份` |
| 来源条件 | 1 | `L2方法条件身份` |
| 子目标宿主 | 1 | `L2存在身份` |
| 子目标特征 | 1 | `L2特征定义身份` |
| 子目标状态合同 | 1 | `L2目标状态合同身份` |
| 条件场景 | 0..1 | `L2场景身份` |
| 已绑定子需求 | 按状态 0..1 | `L2需求身份` |
| 子需求承接任务 | 回流状态 0..1 | `L2任务身份` |
| 回流实际状态 | 回流状态恰 1 | `L2状态身份` |
| 回流动态证据 | 回流状态 0..1 | `L2动态身份` |

任务到记录另有一类有界组读取关系，允许一个任务在同一轮拥有 0..N 条不同条件记录。属性槽固定承载：筹办轮次、方法内容版本、方法规格版本、作用对象角色、条件来源稳定编码、来源共同事实截止、建立幂等身份、记录状态，以及回流发生时间 / 版本 / 共同截止。每个属性类型每记录当前恰一值，只有回流三项在前两状态为空。

记录建立时同代形成节点、任务组关系、全部必需引用和属性；绑定、回流只替换受影响状态属性并增加相应 0..1 引用；退出同代退出记录节点、任务组关系、全部当前引用和属性。不得用一个通用关系类型加自由顺序号、万能属性、JSON 或任意字节载荷代替上述角色。

## 8. 建立流程与父需求互证

配套单函数图：`流程图/20260822_新增任务子目标承接记录_函数流程图_v0.1.md`。

当前 G 首次建立固定顺序：

1. 纯值形状无效返回`入口拒绝`；`来源共同事实截止`必须等于请求头 G。
2. 以 G 读取任务作为首个当前引用；若该读取报告`事实代次漂移`或回显当前截止不等于 G，立即停止后续当前引用读取，把原完整请求交给受限写入端口做首次写入材料探测，不得把该漂移直接返回调用方。
3. 首读成功后继续在 G 读取任务虚拟存在，要求任务当前、二者互指且请求虚拟存在就是该任务唯一虚拟存在；后续任一当前读取若报告漂移，也执行与第 2 步相同的端口收敛路由。
4. 在 G 以显式父需求调用`读取需求成员列表`，只消费其当前成员关系和列表项身份；随后以该身份调用`读取需求列表项完整`，并以父需求调用`读取需求完整`，要求两份完整事实当前、父需求所属存在等于列表项所属存在、列表项身份等于任务的需求列表项。禁止从`读取需求成员列表`的默认空列表项事实读取所属存在。
5. 在 G 读取普通方法，要求方法、内容版本、规格版本、主轴结果和条件都存在于同一完整方法投影；条件结果关系必须把请求条件连到请求主轴结果；条件作用对象角色、场景、特征、目标状态合同和来源稳定编码与请求逐字段相同。
6. 目标宿主由 DATA 外调用方按已裁决的条件作用角色绑定；本服务只校验非零及其与条件材料的一致结构，不判断独立子目标准入。
7. 把完整请求交给受限端口。端口在任务 owner 同一互斥边界内再次确认 L1 当前代次仍为 G，再发布记录节点、任务 / 虚拟存在 / 父需求 / 方法 / 主轴 / 条件 / 目标引用、属性值和建立幂等身份的完整写集。
8. 在发布代次读回完整记录；任何缺项、复义或载荷矛盾返回`内部不一致`，不得补写。

## 9. 绑定、回流和退出

### 9.1 绑定子需求

当前 G 首次绑定：

1. 读取当前记录并要求状态为`待绑定子需求`；
2. 分别读取子需求、记录显式父需求的完整事实和子需求当前父关系，要求父关系唯一且父需求等于记录显式父需求；
3. 要求父子需求所属存在相同，并比较子需求的目标宿主、目标特征和目标状态合同与记录子目标完全相同；
4. 以子需求调用`读取需求成员列表`，只消费唯一当前成员关系中的`需求`和`列表项`身份；成功但无当前成员关系、复义、关系需求不是请求子需求或列表项身份无效，统一为`内部不一致`；
5. 以第 4 步关系给出的列表项身份调用`读取需求列表项完整`。当前关系指向的列表项未找到、已退出、读回身份不等或事实半结构，统一为`内部不一致`；完整列表项的所属存在和目标三元组必须分别等于子需求完整事实，对不上表示既有成员结构自相矛盾，返回`内部不一致`；子需求 / 列表项虽然彼此一致、但与记录父需求所属存在或冻结子目标不一致，属于本次正常异引用，返回`引用冲突`；
6. owner 内一次原子迁移状态、增加记录到子需求引用并保留旧状态历史。

### 9.2 登记回流

当前 G 首次登记：

1. 当前记录必须为`等待子需求`且请求子需求与记录相同；
2. 子需求及其显式父关系仍在 G 当前，父需求仍等于记录父需求；
3. 与绑定流程相同，以子需求调用`读取需求成员列表`取得唯一当前成员关系和列表项身份，再调用`读取需求列表项完整`；缺失、复义、悬空或子需求与列表项自身核心契约不一致统一为`内部不一致`，与记录父需求所属存在或冻结子目标不一致返回`引用冲突`；禁止读取`读取需求成员列表`回显的默认空列表项事实；
4. 实际状态必须可在 G 完整读取且主体等于记录子目标宿主；以该状态的特征实例在 G 调用`读取完整特征实例`，要求实例宿主等于子目标宿主、特征定义等于子目标特征；动态存在时必须可在 G 完整读取且其主体、后状态分别等于子目标宿主和请求实际状态；
5. 可选子需求承接任务存在时，必须在 G 当前，且任务的需求列表项身份等于第 3 步关系取得的当前列表项身份；没有子任务时不得填零身份占位；
6. 回流发生时间、版本和共同事实截止必须非零，且回流截止等于 G；
7. owner 内一次原子迁移到`子需求已回流待父需求重判`并保存完整回流材料。

该成功只说明结构化回流材料已登记。它不证明父需求已经重判，不发布旧来源任务的重筹办触发，不读取或修改旧路径、旧实例或旧冻结。

### 9.3 退出与历史

退出只接受当前存在记录，以一个 owner-aware 写集退出记录节点和全部当前关系 / 值。业务调用方决定何时退出；DATA-L2 不解释“父需求已重判”“轮次已结束”或“条件已取消”。历史读取必须能在具名截止重建退出前最后状态以及更早的待绑定 / 等待状态。

## 10. 幂等、旧 G 收敛与错误唯一化

四个写入口统一采用以下顺序：

```text
纯值形状守卫
-> 以 G 执行本入口首个当前引用读取
   -> 漂移：不向上返回，转任务 owner 首次写入材料探测
   -> 成功：继续完成本入口其余当前引用互证
   -> 其它非成功：按唯一状态映射
-> owner 写端口再次检查首次材料 / G / 当前前驱
-> 提交完整写集
-> 权威读回
```

规则固定：

1. 同幂等身份 + 同完整请求：返回`精确重复`和首次结果代次的完整历史读回；即使当前记录已迁移或退出，也不拿当前状态替换首次结果。
2. 同幂等身份 + 任一请求字段不同：返回`幂等冲突`，零变化。
3. 旧 G 且 owner 首次账未命中：返回`事实代次漂移`，零变化；未命中不证明可以换键重试。
4. 首次账命中后只允许提交其中的原规范化写集收敛，不重新构造另一分支、不生成新编码。
5. 建立请求的预期写集完全由请求字段和固定本地键形成；绑定、回流和退出在旧 G 收敛时必须从记录的 G 历史投影取得当时前驱关系 / 属性稳定编码，再重建预期完整写集。禁止用漂移后的当前记录重建、补齐或改写首次请求。
6. 首次账命中的规范化写集、首次结果和按第 5 项重建的预期写集必须逐字段一致；任一差异返回`幂等冲突`，首次材料自身缺项或与首次结果矛盾返回`内部不一致`。
7. 请求合同、空身份、零轮次 / 时间 / 版本 / 预算或状态组合非法：`入口拒绝`。
8. 合法强身份当前不存在：`未找到`；已经退出：`已退出`。
9. 父需求归属、任务 / 虚拟存在、方法字段、父子关系、目标、状态 / 动态或前驱状态不一致：`引用冲突`。
10. G 变化：`事实代次漂移`；写端口许可无效：`许可拒绝`；预算不足：`数量预算不足`；同键异请求：`幂等冲突`。
11. 资源异常：`资源失败`；前置通过后复义、半结构、读回矛盾或未知枚举：`内部不一致`。

不存在`入口拒绝`与`证据不足`二选一，也不新增 DATA 外业务状态枚举，从而消除旧设计 V01 的错误语义歧义。

## 12. 后继路线与完成声明边界

本叶代码完成后只允许声明：任务 owner 已能持久保存、迁移、退出和按当前 / 历史读取强类型子目标承接等待记录；记录完整绑定显式父需求、任务来源材料、子目标、G、幂等和回流状态。

直接后继必须另行设计：

```text
DATA 外独立子目标准入
-> 建立待绑定记录
-> 需求 owner 原子建立子需求并引用记录身份
-> 任务 owner 绑定已发布子需求
-> 任一步失败 / 漂移 / 发布未知的两 owner 收敛
```

后继必须补齐旧独立审查发现的父需求完整互证、需求侧完整请求幂等、需求入树旧 G 重试和独立子目标准入；不能把本记录存在升级为需求成立。更后的回流叶必须先触发父需求重判，再按当时当前需求列表和任务关系决定是否建立新筹办轮次。

本设计不证明子需求已建立、已满足、已回流，不证明父需求已重判，不证明旧任务已重筹办，也不证明成员满足核算或价值 / 预算分配已实现。
