## 2. 完成边界

本叶完成必须同时满足：

```text
阶段19成功结果.最终Gread
→ 同截止正式读回现实世界根与唯一self E
→ 构造一次阶段21 provider并真实调用
→ 成功缓存完整值式锚点；任一非成功映射阶段21
→ 以锚点截止fresh读回世界/self
→ 构造不含运行代次、独立逻辑身份和未来读取预算、但含具名配置邮箱容量的self创建请求
→ 使用普通应用工程配置中的创建等待调用唯一self对象
→ 入口进入、停门见证、关闭门、零冻结批次和唯一租约共同证明阶段20成功
→ 普通控制面板安全stop/join后返回宿主失败/阶段12
  或无窗口模式复用现有宿主，宿主结束后安全stop/join
```

阶段21或阶段20先失败时立即返回其原失败阶段，不进入模式宿主，不能被阶段12/13覆盖。阶段20已经成功后，普通控制面板返回阶段12只表示窗口宿主未接通；不否定阶段21/20已经完成。任何self停止或join失败仍优先返回阶段20，因为进程尚未安全释放唯一线程租约。

完成只证明本能根运行锚点的生产消费、自我线程创建并停门和既有宿主分流接线，不证明治理门开放、普通控制面板窗口可用、任务线程组建立、自我内部治理循环运行或跨进程业务恢复闭环。

## 3. self创建合同纠偏

### 3.1 唯一身份

self唯一业务身份是世界树正式存在节点`E`。`自我线程逻辑身份`和`自我线程运行代次`类型及其在self DTO、见证、消息和实现中的字段全部退出。不得以线程地址、系统线程ID、计数器、时间、随机值、Gread或另一个节点身份补回第二套self身份。

`自我线程创建请求_v1`精确业务形状改为：

```cpp
struct 自我线程创建请求_v1 final {
    std::uint32_t 合同版本 = 自我线程合同版本_v1;
    std::uint64_t 邮箱容量 = 0;
    自我线程世界启动材料_v1 世界;
    自我线程自我启动材料_v1 自我;
    自我线程本能根启动材料_v1 本能根;
};
```

完整性要求为：三组材料完整；世界身份和根场景分别与self材料一致；`自我.自我 == 本能根.自我`；本能根截止不早于世界/self截止。self E只来自fresh `真实自我投影.E`，不由锚点、角色、配置或节点创建顺序反推。

`自我线程停门见证_v1`删除旧运行代次/逻辑身份，只保留入口序号、停门序号、门关闭和零冻结批次。见证不复制E；调用方以锁定创建请求中的正式E和同一对象租约证明对象归属。

未来上下文读取和双根复核DTO继续按各自调用携带读取预算，但退出运行代次和独立逻辑身份。根需求复核消息退出运行代次，按不可变消息身份、原请求身份和分支业务定位判重；原枚举数值8的`运行代次不匹配`退役且不得改作业务成功。治理门仍固定关闭，这些未来provider不在本叶实现或调用。

### 3.2 工程配置与物理选择

创建请求不再含上下文预算或根复核预算；邮箱容量保留为工程配置字段，但其唯一来源是普通应用具名运行配置。创建入口保持：

```cpp
自我线程创建结果_v1 创建并停在治理运行门(
    const 自我线程创建请求_v1& 请求,
    std::uint64_t 等待毫秒) noexcept;
```

邮箱容量和等待时限都来自普通应用具名配置。首次合法调用锁定包含容量的完整创建请求；同一请求且仍处可重复状态时返回原见证，容量变化返回`选择冲突`。等待毫秒只控制本次调用方等待，不进入请求、物理选择、见证、消息或持久材料。

`自我线程上下文读取预算_v1`和`自我线程根复核读取预算_v1`保留为未来对应provider调用DTO，不再由创建请求提前锁定。

## 4. 普通应用配置、所有权与公开入口

### 4.1 配置

`普通应用配置`合同版本升为2，新增三个非业务字段：

```cpp
std::uint64_t 自我线程邮箱容量;
std::uint64_t 自我线程进入停门等待毫秒;
std::uint64_t 自我线程停止回收诊断等待毫秒;
```

三项必须非零；规范化配置、默认配置和配置相等比较都必须覆盖三项。默认配置必须引用装配模块中的三个具名工程常量，具体数值由代码计划施工时按现有线程资源边界选择并记录；这些默认值不是机器语义、性能上限或业务预算。三项只控制当前进程的工程资源和等待，不写入事实、不进入阶段21请求、self业务选择、消息、幂等或恢复。两组未来读取预算不进入普通应用线程运行配置，只在相应provider真实调用请求中由该调用设计给出。

### 4.2 上下文成员顺序

现有普通应用服务链之后依次增加：

```text
可选阶段21成功锚点
→ 可选阶段21对应fresh self投影/世界根身份
→ 唯一自我线程对象
```

自我线程对象最后声明，保证反向析构时先锁存停止并join，再销毁锚点和全部被借用服务。阶段21 provider在每次尝试中局部构造、每对象只调用一次且不保存为上下文成员；非成功后不得复用原对象，只有重新取得阶段19成功结果、同截止fresh读回self并构造新provider才能重试。成功锚点只作本进程值式缓存，不参与跨进程恢复。

### 4.3 普通应用公开入口

在`装配.普通应用.h/.cpp`增加：

```cpp
本能根运行初始化结果_v1 初始化普通应用本能根运行锚点(
    const 方法登记根生产初始化结果&) noexcept;

自我线程创建结果_v1 创建并停门普通应用自我线程() noexcept;

自我线程操作结果_v1 停止并回收普通应用自我线程() noexcept;
```

三个入口使用现有上下文锁串行，不公开provider、锚点引用、服务指针或self裸指针。停止回收入口固定执行`请求停止 -> 等待停止(配置回收等待)`；`等待停止`成功已经包含join。尚未创建时返回入口拒绝；已经安全停止并join的精确重复可以返回精确重复。

## 5. 阶段21生产消费算法

`初始化普通应用本能根运行锚点`固定执行：

1. 校验上下文、阶段19结果成功且`最终Gread`非零；否则返回阶段21`入口拒绝`。
2. 以现行世界树正式读回调用合同的具名调用预算执行`验证现实世界根({2,最终Gread,预算})`；预算只属于本次世界树调用，不进入线程运行配置或self创建请求。只有公开成功谓词成立才继续，漂移映射`当前性漂移`，其它非成功映射`内部不一致`。
3. 用同一根场景、角色及现有SELF-FORM预算构造`真实自我读取请求`，`Gread=最终Gread`；只有`真实自我形成结果::成功(请求)`成立且投影存在才继续。
4. 核对投影`E`有效、世界根等于正式根，直接结构父存在且来源为直接子场景，`直接结构父->父`等于根场景。
5. 以同一上下文中的特征概念、存在、需求服务和本次self请求/结果构造新的阶段21 provider；调用唯一一次`初始化({1,存在信息身份{E}})`。
6. 逐项保留provider原结果。只有`结果.成功()`成立时缓存锚点、根场景和本次self投影；任一非成功清除本次候选缓存，不拼接锚点、不创建self。

阶段21的11种状态不在启动层重新解释。启动层只按`成功()`分流：非成功统一返回`程序运行状态::初始化失败 / 程序失败阶段::本能根运行初始化(21)`，完整结果留在普通应用入口供专项和诊断读取。

## 6. 阶段20创建并停门算法

`创建并停门普通应用自我线程`只在阶段21锚点缓存完整时执行：

1. 以`锚点.事实截止代次`再次调用`验证现实世界根`并fresh读取唯一self；两者必须在同一截止成功。
2. 核对fresh self E等于锚点self，`位置.直接结构父->父`等于正式根场景，且来源仍为直接子场景。
3. 逐字段形成请求：

| self字段 | 唯一来源 |
| --- | --- |
| `世界.世界` | 同截止正式世界根场景 |
| `世界.根场景` | 同一正式世界根场景 |
| `世界.Gread` | 世界根成功结果`Gread` |
| `自我.自我` | fresh投影`E` |
| `自我.世界` | fresh投影`世界根` |
| `自我.所在场景` | fresh投影`位置.直接结构父->父` |
| `自我.Gread` | fresh投影`Gread` |
| `本能根.自我` | 锚点`自我.编码` |
| 两根四项 | 锚点安全根/服务根逐字段强类型转换 |
| `本能根.Gread` | 锚点`事实截止代次` |
| `邮箱容量` | 普通应用具名运行配置 |

4. 调用上下文唯一self对象的`创建并停在治理运行门(请求,配置进入停门等待)`。
5. 成功必须同时满足：结果成功；停门见证完整；诊断快照为`已停门`、门关闭、线程已进入、线程未完成、邮箱容量等于配置、邮箱为空、零冻结批次且无内部错误；锁定请求中的self仍为fresh E且上下文仍持有同一对象。
6. 任一非成功或成功后置条件不成立，立即执行配置停止回收/诊断等待下的停止与join。安全回收成功后返回原创建非成功；回收非成功或超时返回阶段20失败并保留上下文租约，禁止detach、重建对象或销毁上下文伪装安全返回。

阶段20不调用`复核前置并开放治理运行门`，不出队、不消费消息、不调用未来上下文/双根provider。

## 7. 模式宿主分流

`启动.应用程序.cpp`把现行`运行普通程序`拆成共同初始化前缀和阶段20后的模式分流，但不新增并列宿主：

### 7.1 共同前缀

```text
装配
→ 世界根/真实self
→ 阶段19
→ 阶段21
→ 阶段20
```

每一步首个非成功立即返回其既有失败阶段。阶段21/20分别固定为21/20，后续模式阶段不得覆盖。

### 7.2 普通控制面板

阶段20成功后立即调用`停止并回收普通应用自我线程`。安全停止并join成功后真实返回：

```cpp
{启动模式::普通控制面板,
 程序运行状态::宿主失败,
 程序失败阶段::控制面板窗口}
```

停止/join非成功返回阶段20。不得创建假窗口、睡眠循环或返回`已完成`。

### 7.3 无窗口常驻

阶段20成功后安装现有程序停止信号。安装失败先安全停止/join self；回收成功后返回阶段11，回收失败返回阶段20。安装成功后调用现有`运行无窗口宿主`且不传第二驻留循环。宿主返回后无条件安全停止/join self；回收失败返回阶段20，否则原样保留宿主结果并把模式保持为无窗口常驻。

生产运行期模式保持现状，不在本叶接入普通应用self链。

## 9. 失败、异常与恢复

- 所有普通应用公开入口`noexcept`；`bad_alloc/length_error`映射资源失败，其它异常映射内部不一致，并按是否已经创建线程决定是否先安全回收。
- 阶段21`已可能发布`保留原provider结果但不缓存锚点；后继调用必须从阶段19新成功结果重新开始，不复用provider。
- self创建等待超时不表示线程已经停止；必须进入回收，回收超时继续持有租约。
- 宿主失败不是阶段21/20失败；只有self无法安全回收时才以阶段20优先收口。
- 进程重启不恢复provider对象、锚点缓存、线程、邮箱、门或消息；按持久owner原合同重新经过阶段19、21和20。

## 10. 验证矩阵

验证由两个互补专项共同承担，二者均不登记根工程：

- 原位修订`验证工具/自我线程上层骨架专项验证.cpp/.vcxproj`，验证self对象级ABI、关闭门、邮箱、停止和join；
- 新建`验证工具/本能根运行生产消费专项验证.cpp/.vcxproj`，验证普通应用、阶段21/20和宿主分流。每个需要独立普通应用全局上下文的用例使用独立子进程和临时绝对受控根。

1. 配置版本、零邮箱/等待、配置相等和默认值；坏配置零线程。
2. 旧上层骨架专项在新ABI下通过：创建请求、见证、正式上下文和根消息零运行代次、零独立逻辑身份；创建请求零未来读取预算；同请求重复、异self选择冲突、根定位拒绝、消息重复/冲突、队满、停门零消费、停止/join和析构守恒均有运行断言。
3. 首次阶段21形成、同持久根新进程恢复；锚点完整且缓存只在本进程。
4. 阶段20真实线程进入并停门；锁定请求绑定E，见证完整、门关闭、邮箱空、零冻结批次；同请求精确重复，不同容量冲突。
5. 创建失败和创建等待超时后的停止、唤醒、完成见证与join；无法确定性注入的资源失败保持静态核对，不新增生产故障seam。
