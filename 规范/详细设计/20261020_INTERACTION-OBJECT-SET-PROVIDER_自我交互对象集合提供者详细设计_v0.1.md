## 1. 最早提供者与完成边界

本轮补齐现实世界自我存在的“交互对象集合”正式特征承载，不修改任务或方法虚拟存在。原因是已裁决的获取服务对象方法需要将已连接的人类纳入自我交互对象，而当前旧单值服务对象、需求集合和任务集合均不能代替存在引用集合。

交互对象可以是人类、设备或其它存在。集合仅保存正式存在引用；人类过滤、真实连接及业务纳入资格由后继方法核实。本文不实现新本能函数、不造条件结果对、不改变需求目标、不增加任务。生产完成边界是先天类型与读取提供者实际装配、自我唯一空集合首次初始化或已有集合完整复用、正式读回、通用受保护更新可用。非空生产纳入、主动获取服务对象、完整需求信息理解确认仍未完成。

网页消息数组追加不证明消息已发出；GET `/api/messages`才实际发送且现代码未记录成功回执；会话存在不证明当前连接。因此不能用消息顺序、角色标签、旧服务对象单值或“网页开启”填充集合。不得为通过读回而制造测试成员。

## 4. 无锁身份读取与工程边界

`领域/新_存在类.h/.cpp`使`新_存在类`同时实现`特征存在成员读取接口`，新增：

```cpp

bool 装配存在集合成员保护字段(稳定编码) noexcept;
```

读取实现先调用L1 `查询节点组完整结构`：按E的冻结schema验证恰一正式存在类型字段和恰一非零专属概念引用、未进入清理中。非零引用本身不证明专属EC合法，必须再调用第4.1节EC owner窄身份接口验证专属类型及反向所属E，返回该接口同次读得的E、EC完整联合快照。不得调用`是存在节点`、`读取存在身份保护`、`存在节点属于概念`、EC普通加锁读取、F或FC。schema已在线程前初始化，不取E/EC/F/FC业务互斥；L1自身锁保持由L1管理。

返回区分：无效入口/非存在为入口拒绝，节点不存在为值不存在；合法类型但身份字段重复/缺损、清理中或底座结构异常为内部不一致；L1资源故障为资源失败；未装配单列。比较只在已完成时输出满足/不满足，不能把其它状态当0/空集合。正常业务比较不写任何字段。正式生产调用沿现有工程日志、弹窗、终止链停止，不传播为需求缺失。

### 4.1 EC owner窄身份读取

`领域/概念_存在类.h/.cpp`新增独立强类型合同，不把EC私有schema或字段键公开给E：

```cpp
enum class 专属存在概念身份读取状态 : std::uint8_t {
    已完成 = 1, 输入拒绝, 提供者未就绪, 节点不存在,
    前提已变化, 结构不一致, 资源失败
};
struct 专属存在概念身份保护结果 final {
    专属存在概念身份读取状态 状态 =
        专属存在概念身份读取状态::输入拒绝;
    std::optional<稳定编码> 专属概念节点, 对应存在节点;
    std::vector<基础联合节点快照> 身份保护;
};
// 概念_存在类公开const成员；仅E窄身份读取调用。
专属存在概念身份保护结果 读取专属存在概念身份保护(
    稳定编码 专属概念节点, 稳定编码 预期存在节点,
    const 基础联合节点快照& 已读存在快照) const noexcept;
```

函数不取存在概念图互斥，不调用普通`获取存在概念`、`是专属存在概念节点`、E、F或FC。EC初始化在业务线程前完成；其类型字段、专属类型锚及对应存在字段保持初始化后的稳定标识，由本owner直接读取，不对外泄露。重复初始化只能沿既有只读复用路径，运行期间禁止重建/替换这些schema；服务对象寿命由普通应用既有EC owner持有。

输入必须均有效、E与EC编码不同且`已读存在快照.结构.节点`身份为预期E，否则输入拒绝。一次L1 `查询节点组完整结构({E,EC})`读取两者；该调用已有底座单次一致读取能力，不以两次分别查询拼接。完整比较此次E快照和传入E快照（字段内容、字段关系身份及所有入/出向关系均相同，不比较指针或容器地址），不同返回前提已变化、结果身份与保护组均空。如此保证E owner刚验证的类型、EC引用和清理门，与本次EC事实属于同一读取时点。

EC快照须恰一节点类型字段，其内容是本owner的专属存在概念类型；恰一对应存在字段，其内容为预期E。抽象概念、错误类型、重复/缺失字段、错误反向E均为结构不一致，不能作为合法非成员。两节点缺任一为节点不存在；L1内部不一致/资源失败分别映射结构不一致/资源失败。成功同时返回`专属概念节点=EC`、`对应存在节点=E`，保护组恰含此次读取的E与EC各一次；不需要加载EC全部特征概念，不进行人类归属判断。

E窄接口核对成功返回身份与预期编码一致，然后原样带回两个快照；状态映射为：输入拒绝→入口拒绝，提供者未就绪→读取接口未装配，节点不存在→值不存在，前提已变化→前提已变化，结构不一致→内部不一致，资源失败→资源失败。读取时的前提变化是并发技术拒绝，不是业务不满足，也不在函数内循环重试。

FC比较仅使用此次成功身份；需要正式建立G时，`追加存在集合保护写集`合并每个成员的E和EC完整联合快照，按节点编码去重。重复节点快照完全相同才可合并；同一节点快照不同返回前提已变化，不选择一份覆盖另一份。G提交时L1保护两种节点，E→EC或EC→E任一在读取后改变都拒绝发布。已有G复用同样重新核验成员身份，不能以旧G代替当前合法性。此合同不开放EC清理新入口，不扩展一般概念生命周期。

#### EC撤销的必要原子边界

EC删除collector的“全部字段”限于验证过的自有白名单：EC类型、对应E、特征项持有字段，私有特征项类型/特征类型/具体概念字段，以及唯一已核实root/role的组织父边。发现其它字段或边不得加入删除集绕过引用检查；名称和概念上下位关系沿原拒绝逻辑，未知结构进入工程诊断。

`概念_存在类::撤销未绑定专属存在概念`在现有EC锁内保持原概念关系、名称与身份检查，收集EC、全部私有特征项节点、各自全部字段及EC组织关系，使用现有L1`原子删除节点结构`一次校验、一次删除；空私有特征项组合法。不得先解除组织边或逐字段清理后再判断是否仍绑定。E→EC属于删除集外引用，因此仍绑定、其它外部合法引用或并发新引用均零写拒绝。共享特征概念、名称节点及实际E绝不加入删除集。合法E清理仍先通过G门、再解除自己的E→EC字段，最后请求EC撤销。无须新L1接口，无须EC回调E或取得E锁。该修复使已保护G的身份保持证明成立，而不让普通比较重新检查活E全结构。

保留该入口bool ABI时，`true`仅表示完整删除；`false`仅表示输入不属于本撤销入口、仍有概念关系/名称、仍绑定或原子删除返回`引用仍存在`，且全部零写。对已核验合法输入，节点/字段/关系缺失、内部不一致、资源失败及C++异常进入既有工程日志、弹窗与终止链，不再`catch (...) { return false; }`。L1`已完成`映true，`引用仍存在`映false；其余状态均作为已冻结删除请求与当前底座不一致的工程诊断，不产生业务否定。

### 5.1 物理引用

FC拥有三种新schema：`存在集合保护节点类型`、`存在集合保护来源字段`、`存在集合成员保护字段`。对于被用作存在集合准确值的材料V，建立一个FC保护节点G：G类型字段、G→V来源引用、G→每个E的成员保护引用。对概念域D中的必含成员，G来源为D；有限快照域逐材料保护。G在FC锁内按来源唯一查找/复用，重复或不一致是工程损坏，不任选。

保护按来源生命周期，不按当前值位置：V仍在原始材料库时保护不解除，所以F历史、标准、状态及概念域转用V不会丢保护。现有值服务没有正式材料删除API，本轮不增加回收器，不删除V/G，也不为当前移除而撤销G。概念D删除或修改域时，FC按现有定义更新/删除事务同步处理其G引用；未成功删除D不得提前解除G。概念退出所引用V的保护仍随V保留，宁可保留事实，不提前放行E。

保护发布前捕获每个E身份完整联合快照；以L1封存追加片段及联合预期原子建立G及所有正式引用。所有将新V解释为该类型的写路径（F初始、添加历史、当前/标准变化、FC有限域、正向域、聚合/归组）在业务引用正式发布前，必须先确保保护成功。比较只读，不因比较临时U64自动建立G。失败不能让F/FC持有未经保护的新材料；保护先行后业务发布失败可留下仍合法的G，不清除已建立事实。

跨owner统一调用`确保存在集合材料保护(类型根,V,值服务)`，仅F写入与世界准备路径调用；它在FC锁内核对规则6、完整读V并规范化成员，通过只读身份接口捕获E快照。已有唯一G必须精确覆盖V全部成员才返回已完成，缺项或多项为内部不一致，不默默补错；无G以联合预期原子新建，预期不符返回新枚举`特征概念规则状态::前提已变化=10`，无写且不得继续F提交。空V允许零成员G（仍保存类型与来源）。同材料在不同存在集合根使用复用一个G，不把其它U64材料自动变为引用材料。只读比较不要求临时材料已有G，但正式持久引用必须有G。

具名写路径：

- `建立或取得特征概念`在规则6新概念分支，使用一个L1原子追加请求发布D、D的完整定义字段/父关系及其正向域G；G来源使用D组内引用。有限域各V先经`确保存在集合材料保护`，D原子发布只引用V；父域复用不重复G。失败未产生D时已成功的V保护可保留，不能返回半定义D。
- `更新特征概念值域`在规则6分支不走现有逐字段删除/回滚循环：捕获D及原G完整联合快照，以同一次L1原子追加删除旧域字段、追加新域字段、调整原G成员引用，或者创建新G。正向域转全域/有限域时保留唯一空G（来源D仍在，成员引用变空）；新有限V先保护，提交失败D/旧G完全不变。提交后完整读回定义与G，错误工程终止，不以回滚补造一致。其它规则原合同不改。
- `尝试删除零引用叶概念`把该D自己的G、G全部字段纳入既有`原子删除节点结构`完整删除集，同时删除D与分量/父边；前置入向检查排除仅属于此删除集的G→D来源引用，不排除其它外部引用。原子拒绝则D/G/成员保护均保留；成功后才解除D的成员保护。不得先删G再试删D。V的G不属于此删除集。

### 5.2 删除前技术门

E owner新增私有`存在清理中字段`和`存在清理中标记节点`，不属于业务特征，不产生动作/动态。FC保护字段由装配在所有线程前传给E一次，不允许事后变更。E清理前必须已装配保护字段，否则工程停止，不静默略过检查。

`清理存在节点内容`在其既有E锁内，先完成现有结构、状态/子存在/专属概念及特征可退出检查；读取E完整联合快照，检查其所有`存在集合成员保护字段`入向引用。存在任一正式保护则返回新枚举`仍被存在集合引用=18`，零写。它表示生命周期退出被阻止，不是业务方法结果。

其中“特征可退出检查”必须取得第5.3节整组F清理准备令牌，不能用释放F锁后的只读预检替代。已有联合更新占用映射E新增`特征联合更新占用=20`，已有外部引用映射`特征仍被外部引用=21`，均在清理门之前零写返回。非法结构或资源异常走工程终止，不转换为这两种正常竞争/引用拒绝。

无保护时，使用`原子比较变更字段组`，保护同一E完整联合快照并追加唯一清理中标记；CAS前提变化返回新增`清理前提已变化=19`，零清理，不自动重试。新G发布也保护该E快照：G先提交则清理CAS失败；清理门先提交则G提交失败，重读身份为清理中，不可再加入。没有“检查完引用但删字段前又加入”的窗口。

门成功后执行现有分段清理，不通过FC/E互相取锁恢复判断。正常最后以一次L1字段组合事务清除门和E类型/剩余身份字段；此前已删除的字段不重复删除，成功必须读回无正式身份和无清理门。阶段异常进入工程终止，保留门和已发生删除，绝不恢复为正常存在或继续业务。若尚未拆除任何原字段而需退出，只能以当前完整联合快照CAS撤销自己所建门，CAS失败仍工程终止。重入发现门不是已完成，直接工程报告。下次初始化以`查询目标字段(标记节点,清理中字段)`检测残留门，停止并报告节点及完整快照；不自动补全、回滚或忽略。数据人工修复后再启动。这是本清理入口的失败封锁，不是新增通用回收/恢复框架。

`新_场景类.h/.cpp`的清理调用同步：场景删除及成员删除先完成外层预检，保留原有成员/边界/父子挂接，调用E清理后才删除外层关联和最终L1节点；不在E合法拒绝之前拆除这些外层关系。新增场景状态`存在仍被存在集合引用=26`、`存在清理前提已变化=27`分别映射E的18/19。E返回门前拒绝时外层零写；E已完成后任何外层字段/关系/节点删除失败必须工程终止并输出剩余快照，不返回普通可恢复失败，更不能把无身份或半清理E重新挂回。最终L1节点仍存在但无类型且无门是“内容清理已完成、外层物理退出失败”的诊断，不能被当成合法E重新初始化。初始化补偿中的各清理调用同样核对返回；新建未发布E若被引用则是补偿冲突，应工程终止，不忽略返回继续报告初始化成功。不得增加自动重放清理或扫描修复全库。

本轮没有旧存在集合数据自动迁移。现有普通E无门正常使用；只在实际退出时新增门。不得修改旧需求/任务集合的保护语义。

### 5.3 F清理整组准入及占用竞争

`领域/新_特征类.h/.cpp`新增如下接口；F唯一持有删除结构解释权，E只交出自己实际持有的根F和即将解除的字段关系编码，不让E解析F私有字段：

```cpp
enum class 新特征清理准备状态 : std::uint8_t {
    已准备 = 1, 联合更新占用, 仍被外部引用,
    入口拒绝, 结构不一致, 资源失败
};
class 新特征清理准备 final {
public:
    ~新特征清理准备();
    新特征清理准备(新特征清理准备&&) noexcept;
    新特征清理准备& operator=(新特征清理准备&&) noexcept;
    新特征清理准备(const 新特征清理准备&) = delete;
    新特征清理准备& operator=(const 新特征清理准备&) = delete;
private:
    struct 实现;
    explicit 新特征清理准备(std::unique_ptr<实现>);
    std::unique_ptr<实现> 实现_;
    friend class 新_特征类;
};
struct 新特征清理准备结果 final {
    新特征清理准备状态 状态 = 新特征清理准备状态::入口拒绝;
    std::optional<新特征清理准备> 准备;
};
// 新_特征类公开成员
新特征清理准备结果 准备特征组清理(
    const std::vector<稳定编码>& 根特征组,
    const std::vector<稳定编码>& 允许解除入向字段关系组) noexcept;
void 执行已准备特征组清理(新特征清理准备&) noexcept;
```

准备方法内部先取得既有`新特征互斥`的`std::unique_lock<std::recursive_mutex>`，锁移入Pimpl保持到整组消费或未消费析构；不暴露mutex、不新增全局业务锁、不把清理令牌插入`联合更新占用表`。Pimpl保存owner、创建线程、根F组、完整待删子树及其私有历史命中/值域节点、预期F结构、允许解除字段组和阶段`未开始/删除中/已完成`。根组与允许字段组去重，根子树不得互相重叠；每个允许字段必须确实引用所选根F，不能以无关字段扩大允许删除边界。空根组允许得到空准备，消费零写完成。

**准入一次检查全部根及后代。** 使用`枚举特征保护子树`和现有F私有读取能力，先检查全部节点是否已有`联合更新占用表`占用；任一被占用，整组不产生令牌、零写、返回联合更新占用。继而完整读取每个F及历史命中记录、实例区间/聚合域私有节点，确认正常删除路径将要使用的类型、唯一概念、单位/当前/历史/标准字段、父子关系和私有引用结构均完整；不能只检查根F存在。

对于待删结构的入向字段/外部关系，允许待删集合内部边及调用方列明的根F外部字段；其它真实外部引用返回`仍被外部引用`，不部分取得保护。共享特征值材料V和FC概念不是F删除节点，不作为F私有对象误删；其引用只解除F持有部分，FC引用计数及其零引用回收仍由FC处理。非法字段/循环/重复结构与L1失败分别返回结构不一致/资源失败，由E工程链终止。准入检查无任何机器事实写入；准备失败自动释放F锁。

生产根F的实际持有关系是E→F实例特征字段，不是E→F父子外边：`新_存在类::建立存在`与`添加特征`调用`建立特征`后建立持有字段，`新_特征类::建立特征`新建无父节点。根F出现未知外部父边仍拒绝，不新增“持有E父边”例外；待删F子树内部父子边由F删除。执行侧曾提出的根父边漂移经源码复核已撤回，不构成结构迁移。

准备成功后，持F锁直到所有F清理完成，不能逐根解锁。既有联合准确值/引用集合准备及普通F写入均先取得同一F互斥，因此其它线程不能在准入和清理之间新登记占用、改变后代或扩展归组；准备前已持有跨调用联合凭据者已经在占用表中，被准入拒绝，不等它释放或取消。既有`删除特征`不会把本令牌误认为联合占用，因为本令牌不写占用表。不得为绕过检查删除其它联合凭据。

E的固定调用顺序：

1. 持E锁完成E/EC预检，读取精确E→F字段并准备整组F令牌。
2. 持令牌期间只做E先前捕获数据的检查及L1读取/CAS，原子建立E清理门；CAS不符时销毁未开始令牌、释放F锁，返回清理前提已变化，E未拆任何原字段。
3. 门成功后由E通过L1删除所声明的E→F字段，然后立即调用`执行已准备特征组清理`。禁止在此期间调用其它E方法、EC方法、用户回调或等待消息；F内部只沿现有F→FC/L1方向调用，身份读取仍不能取E锁。
4. 消费方法复核owner、线程、阶段、全部允许外部字段已被解除及结构只有这些已知变化；开始第一项删除前置阶段为删除中。持同一个F递归锁执行既有递归删除逻辑，不经异步，不新增占用；任何结构漂移/删除失败立即工程终止，保留E清理门，不返回普通false。
5. 所有F确实删除且读回确认后置已完成并释放F锁，再返回E；E此后才解除/清理专属EC和剩余E字段。不得带F锁进入EC清理。

未消费令牌析构只释放内存锁，不改事实；移动/使用/析构必须同线程。删除中析构或再次消费是工程故障，不能静默释放后让E继续；已完成析构无动作。门成功后但F消费尚未开始发生异常，同样按第5.2节保留门工程终止，未开始令牌析构并不表示E可以恢复业务。

场景映射追加`存在特征联合更新占用=28`、`存在特征仍被外部引用=29`，分别对应E的20/21；正常删除入口在这些门前拒绝下保留场景原挂接。该合同只保证完整清理准入与占用排他，不宣称多owner物理删除整体事务回滚；L1之外的违规写入或门后工程失败仍按保留现场终止处理。
