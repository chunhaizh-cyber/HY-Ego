# INSTINCT-STAGE3-PRODUCTION-SAFETY-DEFINITION 安全根生产定义启动发布详细设计 v0.1

日期：2026-08-29

## 1. 目标与完成边界

本切片消费已发布的安全根定义 owner/provider，在生产普通启动中于本能根锚点之后、完整秒和维护游标之前，建立或恢复唯一安全根生产定义并独立读回。

```text
完成 = 生产启动首次发布版本1定义
    + 同进程重复不形成第二权威
    + 重启恢复互证既有定义
    + 已有异义定义 fail-closed
    + 启动只在独立读回完整后继续
```

不实现主动安全结算、服务被动维护、双根自检或后继线程治理；不新增定义 owner、安装配置 owner、CLI 参数或默认空定义。

## 2. 正式依据与当前事实

- 6120 v0.10、6170 v0.6 冻结生产定义 v1 的 I64 30% / 80% 阈值和三个版本 1。
- `2fdcc4bf` 已发布 `发布安全根定义_v1`、`读取当前安全根定义_v1` 及普通应用唯一服务装配。
- 当前 `运行普通程序` 在本能根锚点成功后直接建立完整秒、维护游标；生产定义没有调用者。
- `普通应用配置` 和正式启动参数没有安全阈值来源，当前设计不扩大它们。

## 3. 生产常量与安全算术

物理定义落入 `海中鱼巣/业务/安全根生产定义初始化.数据.h`：

```cpp
inline constexpr std::uint32_t 安全根生产定义初始化合同版本_v1 = 1;
inline constexpr std::int64_t 安全根生产低位阈值_v1 = 2767011611056432742LL;
inline constexpr std::int64_t 安全根生产高位阈值_v1 = 7378697629483820645LL;
inline constexpr std::uint32_t 安全根生产定义版本_v1 = 1;
inline constexpr std::uint32_t 主动安全结算规则版本_v1 = 1;
inline constexpr std::uint32_t 被动服务维护规则版本_v1 = 1;
inline constexpr L2结构幂等身份 安全根生产定义发布幂等身份_v1{0x494E'5354'5344'5031ULL};
```

两个 I64 常量是 `floor(I64_MAX*30/100)` 与 `floor(I64_MAX*80/100)` 的规范化结果。运行期不再以浮点或 `UINT64_MAX` 重算。测试必须静态证明常量满足范围、顺序和商余等价式。

## 4. DTO 与结果矩阵

```cpp
struct 安全根生产定义初始化请求_v1 final {
    std::uint32_t 合同版本 = 安全根生产定义初始化合同版本_v1;
    本能根运行锚点_v1 本能根锚点;
};

enum class 安全根生产定义初始化状态_v1 : std::uint8_t {
    已发布 = 1,
    已恢复 = 2,
    入口拒绝 = 3,
    当前性漂移 = 4,
    定义冲突 = 5,
    许可拒绝 = 6,
    资源失败 = 7,
    内部错误 = 8,
    已可能发布 = 9
};

struct 安全根生产定义初始化结果_v1 final {
    std::uint32_t 合同版本;
    安全根生产定义初始化状态_v1 状态;
    std::optional<安全根定义事实_v1> 定义;
    std::uint64_t 本次正式读回截止;
    bool 成功() const noexcept;
};
```

只有 `已发布`、`已恢复` 携带逐字段等于生产定义 v1 的完整事实和非零独立读回截止。全部其它状态定义为空、截止 0、`成功()==false`。

下层 `版本漂移`、现有正式定义异义或独立读回异义统一映射 `定义冲突`。`已可能发布` 只在同键一次收束仍无法取得完整读回时返回。

## 5. provider 与算法

```cpp
class 安全根生产定义初始化提供者 final {
public:
    安全根生产定义初始化提供者(
        const L2状态结构服务& 状态服务,
        安全根定义与当前值服务& 定义服务) noexcept;

    安全根生产定义初始化结果_v1
    初始化并读取安全根生产定义_v1(
        const 安全根生产定义初始化请求_v1& 请求) noexcept;
};
```

模块：`海中鱼巣.业务.提供者.安全根生产定义初始化`。

算法服从 `BIZ-L3-001-03-13 v0.1`：

1. 校验合同与锚点。
2. 读取 G0，再读取当前定义。
3. 已存在时只逐字段互证；异义立即 `定义冲突`，零写。
4. 未发布时以固定键、来源和生产常量调用现有发布入口。
5. 当前性漂移或已可能发布最多重试一次，保持同一幂等身份和同义定义，只更新请求头事实截止。
6. 取得当前 Gread 并独立读取当前定义；逐字段互证后返回。
7. 捕获 `bad_alloc` / `length_error` 为资源失败，其它异常为内部错误。

provider 不保存第二份定义、不缓存成功、不读 SQL、不修改锚点或当前 A。

## 6. 启动接线

`运行普通程序` 在 `本能根.锚点` 成功后构造局部 provider：

```text
L2状态结构服务
+ 安全根定义与当前值服务
-> 安全根生产定义初始化提供者
-> 初始化并读取安全根生产定义_v1
```

失败继续映射现有 `程序失败阶段::本能根运行初始化`，不为单一子步骤扩大公开程序失败 ABI。成功后才建立单调时钟、完整秒服务和本能被动维护游标。

## 8. 验证矩阵

| 编号 | 场景 | 必须证明 |
| --- | --- | --- |
| P00 | 常量与入口 | I64 30% / 80% 精确值、错合同和坏锚点拒绝 |
| P01 | 首次生产发布 | 状态已发布，完整定义和独立读回一致 |
| P02 | 同进程重复 | 状态已恢复，事实代次不前进，无第二定义 |
| P03 | 进程重启恢复 | 同一持久根恢复后互证同一定义，零新发布 |
| P04 | 已有异义 v1 | 返回定义冲突，既有定义不覆盖、不迁移 |
| P05 | 下层非成功 | 漂移 / 许可 / 资源 / 内部 / 已可能发布保持结构化空载荷 |
| P06 | 正式启动消费者 | 定义成功早于游标；定义失败时游标与线程均不进入 |
| P07 | ABI consumer | 数据头和 provider 可被独立消费者 Debug / Release 导入调用 |

执行验证至少包括提交树 Debug / Release、专项运行两配置、持久恢复、ABI consumer、`check_specs.py --strict`、diff-check 和生产启动静态接线检查。普通 provider 专项不单独证明启动顺序，必须由启动调用点与 P06 共同证明。
