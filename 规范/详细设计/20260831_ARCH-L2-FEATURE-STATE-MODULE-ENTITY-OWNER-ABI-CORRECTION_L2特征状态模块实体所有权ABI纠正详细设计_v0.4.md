## 1. 第四层根因与唯一裁决

dumpbin 已固定：普通应用 getter 定义返回 `L2状态动态原子发布服务[海中鱼巣.领域.服务.L2动态结构]`，消费者要求 `L2状态动态原子发布服务[海中鱼巣.领域.服务.L2状态动态原子发布]`。`海中鱼巣/领域/服务.L2动态结构.ixx` 当前 clean blob `563a37ef7ec9da856e21786111514303d4c2a138`，第 35 行仍有同名错误前置声明，第 2441 行仍有同名 friend。

全仓限定扫描证明 `class L2状态动态原子发布服务;` / `friend class L2状态动态原子发布服务;` 当前只剩动态结构模块这一对，无第四个模块。v0.4 必须删除这两个声明；完成后全仓错误 forward/friend 均归零，`L2状态动态原子发布服务` 只由 `海中鱼巣.领域.服务.L2状态动态原子发布` 首次声明和定义。装配不改，fresh Rebuild 使 getter 自然绑定真实类身份；禁止用 import 顺序、装配重写、alias、typedef、第二声明或链接选项规避。

该裁决不改变正式机器语义、业务能力、DTO、请求、结果、事务或持久格式，属于原 ABI 纠正目标内的第四层同形实体所有权漂移。

## 2. 动态 owner 实际私有消费与窄合同

动态发布模块对 `L2动态结构服务` 的私有消费只有：

| 当前私有访问 | 现有用途 | 裁决 |
| --- | --- | --- |
| `结构类型登记定位_`、`动态上下文关系类型定位_` | 发布前材料就绪检查及上下文关系类型注入 | 收束为一个 const 就绪 helper |
| `中性动态提供者_.形成当前值记录动态参与者_v1(...)` | 形成动态 owner 三分区参与者 | 收束为外层服务 const wrapper |
| `第一层写入端口_.所有者身份()` | 注入动态 owner 身份 | 由形成 wrapper 内部注入 |
| `第一层写入端口_` | 永久账完整读回中的首次写入材料核对 | 增加既有 getter 的 const 重载 |

公开的 `读取中性动态_v1(...)`、`读取中性动态上下文_v1(...)` 等读回入口原样复用，不属于 friend 私有面，不修改。

只公开既有结果类型并增加三个窄入口：

```cpp
struct L2动态结构服务::当前值记录动态参与者结果_v1 final {
    L2结构状态 状态 = L2结构状态::内部不一致;
    std::optional<L1三分区原子参与者写集_v2> 参与者{};
    L1所有者范围写集本地键 状态迁移动能本地键{};
    std::optional<L1所有者范围写集本地键> 动作致变动态本地键{};
};

bool 组合发布当前值动态材料就绪_v1() const noexcept;

当前值记录动态参与者结果_v1 形成组合发布当前值记录动态参与者_v1(
    const L2结构请求头&, L2结构幂等身份,
    L2存在身份, L2场景身份, L2特征实例身份, L2存在身份,
    const std::optional<L2方法身份>&,
    const L1三分区原子事实引用值_v2&,
    const L1三分区原子事实引用值_v2&,
    std::int64_t) const noexcept;

const L1所有者范围写端口& 取得组合发布写入端口() const noexcept;
```

形成 wrapper 的 10 个显式参数是冻结 ABI，数量、顺序、传值 / 引用形态和 const 约束均不可改变：`const L2结构请求头&`、`L2结构幂等身份`、四个依次表示主体存在 / 共同场景 / 特征实例 / 来源存在的身份参数、`const std::optional<L2方法身份>&`、两个 `const L1三分区原子事实引用值_v2&`、`std::int64_t`。尤其不得把可选方法身份或两个事实引用改为值传递，也不得把 owner 身份和上下文关系类型重新暴露为显式参数。

`海中鱼巣/领域/L2动态结构.数据.h:418` 的既有 `L2动态原子参与者形成结果` 不等价，禁止复用或适配它替代上述既有结果类型和形成 wrapper。该类型携带 `L1跨所有者原子参与者写集`，而当前值记录链要求 `L1三分区原子参与者写集_v2`；它也不提供当前链必须回传的 `状态迁移动能本地键` 与可选 `动作致变动态本地键`。二者的语义、参与者事务形状和后继键消费合同均不同。

就绪 helper 精确等价于现有动态侧前置条件：`结构类型登记定位_.has_value()` 且 `动态上下文关系类型定位_.关系类型` 有效。动态发布必须先调用它，`false` 仍返回 v1 `材料不足`。

形成 wrapper 原样委托现有 `中性动态提供者_.形成当前值记录动态参与者_v1(...)`，由动态 owner 内部注入 `动态上下文关系类型定位_.关系类型` 和 `第一层写入端口_.所有者身份()`；其余 10 个参数来自原调用点且顺序、值均不变。wrapper 自身也必须防御复核就绪 helper，缺定位时返回空载荷、`状态 = L2结构状态::未找到`，使现有 `映射结构失败` 继续归类为 `材料不足`；不得解引用缺失定位或返回会改变分类的 `入口拒绝`。

动态发布持有 `const L2动态结构服务&`，故 const 端口 getter 是必需 ABI；现有非 const getter保留。三个入口都不新增许可、写入、提交、锁或事实；不得公开字段、嵌套 provider 或整个 private 区。
