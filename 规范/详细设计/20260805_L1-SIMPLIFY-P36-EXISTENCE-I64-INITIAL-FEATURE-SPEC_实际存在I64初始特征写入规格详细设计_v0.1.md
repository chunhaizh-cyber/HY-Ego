## 1. 目标与完成边界

本叶原位扩展唯一 `L1实例特征服务`，新增一个零事实写入的单项规格 provider：

```cpp
实际存在I64初始特征写入规格结果
L1实例特征服务::形成实际存在I64初始特征写入规格(
    const 实际存在I64初始特征写入规格请求& 请求) const;
```

它在调用方给出的一个非零 `期望事实代次` 下完整互证：

```text
P7 宿主是当前正式实际存在
+ P2 定义是当前 I64 特征定义且初始值在闭区间内
+ 来源是同一世界内当前正式实际存在
+ P8 服务身份、角色1宿主槽关系类型、角色2定义模板关系类型、当前I64值属性类型当前有效
+ 宿主与定义在该截止下恰无当前实例槽
```

成功只返回调用方拥有的不可变纯值规格。函数不提交 L1、不形成批次幂等账、不计算请求意图/执行证据摘要、不分配节点/关系/值稳定编码、不保存缓存或首次结果。

后继“存在初始特征完整批次发布者”必须消费一组本规格，验证项目顺序完整连续、定义不重复和共同截止，以一次 L1 v2 写集共同发布全部槽、值、关系、属性槽和 4170 批次账。本叶不提前设计该发布者。

本叶不进入当前值换代、状态动态、动作动态、因果、任务/结算、恢复装配、运行期接线、旧入口删除、集成验收或 STEP-5。

直接设计最终批写发布者会迫使跨领域发布者重新解释 P7/P2/P8 当前事实，违反 4200 §7.3 的事实所有者规格边界。逐项调用 P8 又会产生多个事实代次并绕过 4170 完整批次账。因此先补本 provider 是最早且可独立施工的缺口。

旧 `数据操作.特征体系.ixx`、旧 `服务.特征.ixx` 和旧 `特征批次发布记录` 只属于隔离旧结构栈，不是本叶提供者，也不得被包装复用。

```text

```

不新增第二实例特征服务、模块、工程项、启动入口或共享验证资源。依赖方向固定为：

```text

-> L1实例特征服务::形成实际存在I64初始特征写入规格
   -> L1实际存在服务::读取实际存在（宿主）
   -> L1特征定义服务::读取I64特征定义
   -> L1实际存在服务::读取实际存在（来源）
   -> L1事实基座服务::读取当前节点 / 读取完整快照
```

P7、P2、L1 不反向依赖 P36。P36 不依赖 P32/P34/P35；它既可服务 P34 新建存在的后继批次，也可服务其它已经存在且仍在当前世界中的宿主。

## 4. DTO 与完整性合同

在 `L1实例特征.数据.h` 追加：

```cpp
inline constexpr std::uint32_t 实际存在I64初始特征写入规格合同版本 = 1;
inline constexpr std::uint32_t 实际存在I64初始特征写入规格规则版本 = 1;

struct 实际存在I64初始特征写入规格请求 final {
    std::uint32_t 合同版本 = 实际存在I64初始特征写入规格合同版本;
    std::uint32_t 规则版本 = 实际存在I64初始特征写入规格规则版本;
    std::uint64_t 期望事实代次 = 0;
    std::uint32_t 项目顺序 = 0;
    实际存在读取请求 宿主;
    I64特征定义读取请求 定义;
    std::int64_t 初始值 = 0;
    实际存在读取请求 来源;

struct 实际存在I64初始特征写入规格 final {

    std::uint32_t 规则版本 = 实际存在I64初始特征写入规格规则版本;
    std::uint64_t 事实截止代次 = 0;
    std::uint32_t 项目顺序 = 0;
    实际存在事实 宿主;
    I64特征定义事实 定义;
    I64特征定义读取请求 定义读取见证;

    实际存在事实 来源;

    世界结构节点身份见证 宿主槽关系类型;

    世界结构节点身份见证 当前I64值属性类型;

    实例特征状态 状态 = 实例特征状态::入口拒绝;
    std::optional<实际存在I64初始特征写入规格> 规格;
    friend bool operator==(const 实际存在I64初始特征写入规格结果&,

```

请求不携带 `特征操作幂等身份`、批次身份、本地键、摘要、稳定编码候选或事务材料。`项目顺序` 是调用方完整有序项目组中的原始位置；provider 只原样保留，既不排序也不判断连续性。完整集合的顺序连续、无重复定义和非空门禁只由后继批次发布者一次裁决。

规格完整性至少要求：两个版本精确；截止非零；宿主、定义、来源事实完整且截止完全相等；宿主与来源世界根相等；定义读取见证与定义事实的定义编码和三个值编码一致；初始值在定义闭区间；四个登记节点见证非零、类型分别为普通/关系类型/关系类型/属性类型且互异；`当前匹配槽数量 == 0`。

该“零数量”只证明指定截止下的负事实，不是跨代次保留权。后继提交仍必须使用同一共同截止作为 L1 v2 期望代次；期间任何写入都会由代次漂移阻止旧规格发布。

## 5. 固定执行流程

函数取得现有 P8 `recursive_mutex` 后固定执行：

1. 校验规格合同/规则版本、非零期望代次，以及宿主、定义、来源三个读取请求的现有完整性；失败返回 `入口拒绝`。
2. 登记未加载返回 `登记未加载`。
3. 调用 P7 `读取实际存在(宿主)` 恰一次；非 `已读取` 按现有映射返回，坏成功为 `内部不一致`。
4. 调用 P2 `读取I64特征定义(定义)` 恰一次；同样映射，且初始值越界返回 `入口拒绝`。
5. 调用 P7 `读取实际存在(来源)` 恰一次。来源必须是当前正式实际存在，且与宿主 `世界根` 相等；不同世界返回 `入口拒绝`。来源可与宿主相同。
6. 三个结果的事实截止必须都等于请求期望代次；任一不等返回 `事实代次漂移`。
7. 依次读取 P8 登记的服务身份、两种关系类型和 I64 属性类型节点；读回截止必须等于请求代次。退出、错类型、重复编码、形状矛盾为 `内部不一致`。
8. 调用 `L1_.读取完整快照({})` 恰一次。许可/资源/内部状态按 L1 结果映射；快照截止不等返回 `事实代次漂移`。
9. 调用既有 `检查宿主定义唯一性`。它必须遍历正式角色1/角色2/当前值/属性槽结构：损坏、重复组合或悬空端点返回 `内部不一致`；恰一匹配返回 `幂等冲突`，因为本请求是初始项而非换代；零匹配继续。
10. 构造完整不可变规格并返回 `已读取`。任何坏成功或空规格为 `内部不一致`。

函数不取得或向外传递 L1 许可；P7/P2 调用、节点读取和完整快照都是各自同步值式调用。没有 sleep、隐式重试、第二快照、SQL、材料文件或进程内实例账裁决。

## 6. 状态映射和失败边界

| 条件 | 结果 |
| --- | --- |
| 请求版本/形状错误、初始值越界、来源跨世界 | `入口拒绝` |
| P8 登记未加载 | `登记未加载` |
| 宿主、定义或来源确定未找到 | `未找到` |
| 任一读取截止不等、快照截止不等 | `事实代次漂移` |
| P7/P2/L1 许可拒绝 | 映射为 P8 已有可表达状态；P15/P7 实际接口若新增不可无损映射状态，激活前退回计划支撑 |
| 已有恰一宿主+定义实例槽 | `幂等冲突` |
| 结构损坏、重复槽、坏成功、错类型、悬空或未知状态 | `内部不一致` |
| 分配失败 | `资源失败` |
| 全部互证且零匹配 | `已读取` + 完整规格 |

所有非 `已读取` 结果的 `规格` 必须为空。许可拒绝必须立即返回，不等待、不循环。P36 没有可撤销写集、发布后读回或隔离动作，因为它从不写事实。

## 7. 并发、所有权与生命周期

现有 P8 服务锁只串行化本服务登记与读取过程，不成为 L1 事实权威，也不跨函数返回。结果中的全部字段均为自有值；请求和结果由调用方拥有，函数不保存引用。`L1实例特征服务` 继续只保存既有依赖引用、登记和旧入口状态，本叶不新增缓存、索引或幂等账。

同一个请求并发调用可以各自返回相同截止的等值规格；任一并发发布推进代次后，旧规格只能在后继 L1 v2 期望代次门禁处零写漂移。provider 不以锁持有时间、缓存命中或调用顺序建立跨调用当前性。

## 8. 后继批次发布者必须承担的职责

本规格不是可直接提交的万能写集。后继发布者必须另行冻结并实现：

```text
完整批次身份与非空完整项目组
+ 项目顺序恰为 0..N-1 且无重复
+ 同一宿主、同一世界根、同一事实截止
+ 定义唯一、来源和规格版本完整
+ provider 前 P15 幂等探测
+ 请求意图摘要 / 执行证据摘要
+ 每项确定性本地键布局
+ 一个 L1 v2 写集
+ 4170 批次账具名参与者
+ 全批次通用发布后读回、失败见证与隔离
```

不得逐项调用 P8 旧建立入口，不得把多个规格拆成多个事实代次，不得让世界树业务服务直接解析 L1 或自行重做 P7/P2/P8 事实验证。

## 9. 验证矩阵

1. 两版本、零代次及宿主/定义/来源坏请求在依赖调用前拒绝；
