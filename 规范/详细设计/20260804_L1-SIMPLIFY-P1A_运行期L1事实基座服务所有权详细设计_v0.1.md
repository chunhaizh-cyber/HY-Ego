# L1-SIMPLIFY-P1A 运行期 L1 事实基座服务所有权详细设计 v0.1

设计基线：`4c34d759d7c15e459c8fb68d42f28da21c977d8f`

## 1. 目标和边界

让每个 `运行期上下文` 在构造时唯一拥有一个长寿命的 `L1事实基座服务`，并只经值式公开访问器将它提供给后续 L2 服务。该服务与旧四仓聚合并存但不互调；本叶不创建世界根、场景、存在、特征、状态、SQL 或材料，也不删除任何旧仓。

这是 4015 新三类事实基座进入运行期装配的最小提供者：后继世界结构服务只能依赖该访问器，不得从 `读取L1事实基座()` 的旧仓库引用拼接新事实。

## 2. 当前事实与裁决

`核心/服务.L1事实基座.ixx` 已提供不可复制的 `L1事实基座服务`，默认构造后可通过 `提交写集` 及值式读取接口工作。`启动.运行期上下文.ixx` 当前只拥有旧四仓的嵌套 `L1事实基座`；`自检.运行期上下文.ixx` 已在工程但未登记到完整自检入口。

裁决：新服务作为 `运行期上下文` 的值成员构造，访问器只返回该成员引用；不把它放入全局、静态、旧仓包装器、裸指针或可选对象。`运行期上下文.完整()` 与旧初始化门禁保持原样，避免把“已持有新 L1”误称为旧领域已迁移或世界服务已经可用。

## 3. 函数、位置与合同

| 文件 | 函数或结构 | 合同 |
| --- | --- | --- |
| `启动.运行期上下文.ixx` | `运行期上下文::读取L1事实基座服务()`（const / 非 const） | 返回当前上下文唯一成员 `L1事实基座服务` 的引用；不分配、不恢复、不提交、不读取旧仓。模块以 `export import 海中鱼巣.核心.服务.L1事实基座` 公开返回类型。 |
| 同上 | `L1事实基座服务 L1事实基座服务_` | 值成员、不可复制，随上下文构造 / 销毁；无独立锁、无第二实例。 |
| `自检.运行期上下文.ixx` | `运行运行期上下文自检()` 新增一项 | 同一上下文两次访问器取得同一服务；用 `期望事实代次=0` 的一节点中性写集得到代次 1，再由第二次访问器读回映射节点。只验证所有权和服务连续性。 |
| `启动.应用程序.ixx` | `运行运行期上下文所有权自检()` 及顺序 280 登记 | 将已有上下文自检包装为 `L1-SIMPLIFY-P1A-S01`，完整自检登记 / 执行计数由 22 同步改为 23。 |

专项写集固定只含一个 `节点种类::普通` 节点、本地键 1 和非零幂等键；不得引入世界语义、属性类型、关系、值或属性槽。成功条件是 `L1写入状态::成功`、事实代次 1、唯一新编码映射，以及第二个访问器的 `读取当前节点` 返回成功、同一事实代次和同一节点编码。

## 4. 非成功与不变量

- 访问器不能取得新服务、两次地址不同、映射不唯一、写入非成功或读回不一致：专项失败；不得回退旧 `读取L1事实基座()`。
- 新服务写入不得改变旧四仓节点 / 关系 / 索引数量；本叶不为此建立双写或同步。
- 不得修改 4015 的 11 个公开服务函数、其状态枚举、旧仓接口、运行期发布状态枚举、生产启动流程或世界树合同。
- 运行期上下文、宿主和租约继续不可复制；新服务引用仅在上下文存续期内有效。

## 5. 验证和完成边界

执行侧运行 `git diff --check`、`python .\tools\check_specs.py --strict`、Debug / Release x64 Rebuild、两配置 `--self-test-exit` 与 MSVC 模块依赖扫描。静态核对仅一个 `L1事实基座服务` 值成员、两个访问器、无旧仓回退和完整自检顺序唯一 280。

完成只证明运行期上下文已拥有并能连续访问一个独立的新 L1 服务实例；不证明世界结构、启动恢复、SQL 持久证据、任何 L2 迁移、旧基座删除或集成验收。
