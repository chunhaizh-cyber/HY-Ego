# ARCH-FIVE-LAYER-FOUNDATION 全局五层架构映射与 L2 虚拟存在、状态、动态唯一权威详细设计

版本：v0.2
状态：替代设计候选，未取得代码实施许可
基线：`main@3fb19d8ca11486eff3de8b5dc983b6d321fda04f`
计划身份：`ARCH-FIVE-LAYER-FOUNDATION`

## 1. 目标与边界

本叶建立 `ARCH-L2` 的通用虚拟存在结构，并为状态迁移与动态形成冻结一个跨 owner 的专用原子发布入口。通用状态仍由 `L2状态结构服务` 唯一拥有，通用动态仍由 `L2动态结构服务` 唯一拥有；本叶不建立第二状态、第二动态或第二事实仓。任务、方法、世界树、概念空间、名称、真实消费者、崩溃/跨进程恢复不在本叶施工。现实改变请求的治理授权属于调用方前置，不由本叶签发或推导。

`ARCH-L5 -> ARCH-L4/ARCH-L3/ARCH-L2 -> ARCH-L1` 是唯一依赖方向。`ARCH-L4` 任务/方法的旧虚拟存在和治理状态只作迁移兼容身份，不能成为当前权威。

## 2. 正式依据与冲突裁决

- 0050、4030、4230 已冻结 DATA-L1 为中性事实内核，DATA-L2/ARCH-L2 为强类型结构服务；每一结构有唯一写入服务，L3/L4/L5 不直写 L1。
- 4230 §3、§4、§6 要求场景、存在、特征、状态、动态、因果的技术 owner 两两不同；普通 L2 CRUD 每次只形成一个 owner-scoped 写集，跨族原子业务操作不属于普通 CRUD。
- 当前代码中状态服务与动态服务各持一份不可复制 L1 owner 端口，且没有跨 owner 提交入口。把两次提交串接或把两个结构改成同一 owner 都违反上述合同。

因此本叶唯一采用“结构 owner 保持分离、ARCH-L2 组合迁移使用中性双参与者事务”的模型：新增的 L1 事务能力只接收已绑定的状态 owner 与动态 owner 参与者，不识别 ARCH 领域，不接受可写 owner 字段，不改变普通 CRUD、owner 建立、读取、幂等和退出 ABI。它是一个明确登记的跨族组合发布入口，不是第二结构服务。

### 2.1 治理授权前置（不进入本 provider）

`想`是内部治理，`看`是纯无副作用观察；两者均不请求业务授权，也不调用本写入口。包含任一现实改变步骤的请求，必须由 ARCH-L4 调用方在筹办与冻结完成后、进入执行阶段前取得一份自我现实执行授权；安全只提供硬否决，活动资格、调度配额和自我现实执行授权彼此分账。授权的签发、撤销、资格判断、配额判断和“是否现实改变”分类不进入 ARCH-L2 DTO、L1 事务或状态/动态 owner。

本 provider 只接受调用方已经裁决的强类型状态变化与被动动态请求，不读取治理记录、授权材料、日志或安全投影，也不自行继续决议。目标未达成只由 ARCH-L4 形成任务轮次结算结果；轮次收束后等待正式自我后继决议，不由本 provider 自动创建下一筹办轮次、工作包、授权或状态变化。调用方未满足上游前置时不得调用；即使被错误调用，provider 也只按结构合同校验请求，不把结构成功解释为授权或业务成功。

## 3. 当前代码事实与复用

`领域/L2状态结构.数据.h` / `服务.L2状态结构.ixx` 已提供状态身份、主体/特征实例引用、精确值/时间值、来源稳定编码、当前/历史读取、引用替换和退出；`领域/L2动态结构.数据.h` / `服务.L2动态结构.ixx` 已提供动态身份、主体/前状态/后状态、起止值、来源稳定编码、当前/历史读取和退出。两服务的 owner 端口分别由普通应用装配。

动态主体端点在本叶明确固定为现有 `L2存在身份` 分支。通用虚拟存在服务产生同一类型的 `L2存在身份`，所以现实存在和虚拟存在不需要第二种联合或桥接 ABI；动态前状态、后状态固定为 `L2状态身份`。来源方法只作为 `稳定编码 来源方法稳定编码` 的不透明结构引用，L2 不 import 或解释 ARCH-L4 方法。

## 4. 冻结 DTO 与稳定身份

新增 `领域/L2状态动态原子发布.数据.h` 与 `服务.L2状态动态原子发布.ixx`。公开请求唯一字段及顺序如下：

```cpp
struct L2状态动态原子发布请求 final {
    L2结构请求头 请求头;                 // 合同版本、非零共同期望代次
    L2结构幂等身份 幂等身份;             // 组合入口独立域
    L2存在身份 主体存在;                 // 现实或通用虚拟存在
    L2状态身份 旧当前状态;               // 必须在共同截止读回为当前
    L2特征实例身份 新状态特征实例;
    L2原始值材料 新状态精确值材料;
    L2原始值材料 新状态时间值材料;
    L2原始值材料 动态起始时间材料;
    L2原始值材料 动态结束时间材料;
    稳定编码 来源方法稳定编码;           // 不透明、可为零表示无来源方法
};
```

结果唯一公开为（不含授权、资格、配额或业务结论字段）：

```cpp
struct L2状态动态原子发布结果 final {
    L2结构结果头 结果头;                 // 状态、共同事实截止、变更代次
    std::optional<L2状态事实> 新状态;
    std::optional<L2状态自有关系引用> 新状态自有关系;
    std::optional<L2动态事实> 新动态;
    std::optional<L2动态自有关系引用> 新动态自有关系;
    std::optional<L2状态自有关系退出投影> 已退出旧状态关系;
};
```

成功（`已提交` 或同义 `精确重复`）必须同时具有完整五组载荷和唯一非零共同截止；任何非成功均五组 `nullopt`、零变更，不返回局部编码。组合幂等域为本服务固定域 `0xARCH'0201`，同键按请求字段逐字段比较；任一公开字段不同即 `幂等冲突`，不把相同结果或业务同义当作重复。

## 5. 唯一公开 ABI 与物理 owner

### 5.1 通用虚拟存在

新增 `领域/L2通用虚拟存在结构.数据.h` / `服务.L2通用虚拟存在结构.ixx`。服务唯一持有通用虚拟存在 owner，公开入口为：

```cpp
L2通用虚拟存在写入结果 新增(...);
L2通用虚拟存在完整读取结果 读取完整(...);
L2通用虚拟存在退出结果 退出(...);
```

主体事实只含强类型 owner 类别、ARCH-L4 宿主引用和生命周期；不含名称、不进入场景树、不产生状态或动态结论。其返回身份是 `L2存在身份`，由状态/动态服务按现有公开身份来源读取。

### 5.2 双参与者中性事务

在 `海中鱼巣/核心/L1所有者范围CRUD.数据.h` 增加仅供组合入口使用的中性类型：

- `L1跨所有者原子事务合同版本 = 1`；
- `L1跨所有者原子事务参与者序号` 固定 `状态=1`、`动态=2`；
- `L1跨所有者原子事实引用 {参与者序号, L1所有者范围写集本地键}`，只在事务请求内部使用；
- `L1跨所有者原子事务请求 {合同版本, 共同期望事实代次, 组合写入幂等身份, 状态写集, 动态写集}`；
- `L1跨所有者原子事务结果 {状态, 合同版本, 共同事实代次, 是否形成内存权威发布, 重试边界, 两参与者编码映射}`。

请求不暴露 owner 编码、端口、仓库、锁或事务令牌；参与者身份由事务凭证绑定。状态写集中的新状态本地键可被动态写集的事实引用使用，L1 在同一候选中解析为状态 owner 的新稳定编码。动态引用旧状态时使用已读回的稳定编码；引用解析失败为 `内部不一致`。

`L1跨所有者原子事务凭证` 为 move-only、不可复制、不可转签能力，由 `L1事实基座运行包` 在普通应用装配时以状态/动态两个有效端口的非拥有引用形成；端口失效、owner 退出、运行包销毁或参与者顺序不符立即返回 `许可拒绝`。唯一提交函数为：

```cpp
L1跨所有者原子事务结果 L1跨所有者原子事务凭证::提交(
    const L1跨所有者原子事务请求& 请求) noexcept;
```

仓库在一次独占事实锁内验证两个 owner、共同期望代次、跨参与者引用、全量幂等和所有结构不变量，形成一个候选并只发布一个新事实代次；任一失败零写。普通单 owner 入口继续恰一次提交，不能调用该凭证模拟跨 owner 事务。

### 5.3 组合 provider

新增 `服务.L2状态动态原子发布.ixx` 的 `L2状态动态原子发布服务`。普通应用在存在、特征、状态、动态 owner 按 4230 顺序建立后，给状态/动态服务各自注入原有端口，并以两端口的非拥有绑定形成事务凭证；组合 provider 只保存状态服务、动态服务、通用虚拟存在服务的 const 引用和事务凭证，不取得仓库或 raw 锁。

唯一结构入口为（调用方治理前置已经完成）：

```cpp
L2状态动态原子发布结果 发布状态动态原子迁移(
    const L2状态动态原子发布请求& 请求) noexcept;
```

状态服务和动态服务各新增一个仅供该 provider 使用的“形成参与者写集”函数：它们在同一请求截止读取各自身份来源、构造本 owner 写集和局部键，不提交、不推进代次。provider 先验证主体、旧状态、特征实例和来源稳定编码，再把两个参与者交给 L1 凭证一次提交；provider 不复制状态/动态 DTO 解释，也不直接改写 L1。

## 6. 事务、幂等、失败、撤销与读回

1. 写前一次 `L1事实基座` 当前代次读取得到 `G0`；状态与动态所有参与者均以 `G0` 形成。期间任一发布使 L1 返回 `事实代次漂移`，两参与者均不写。G0/G1 只表示事实边界，不表示授权、轮次或业务目标。
2. 首次成功一次发布 `G1`，同时完成旧状态关系退出、新状态节点/主体/特征关系、动态节点/主体/前后状态关系、状态/动态值和来源稳定编码。成功结果的五组 DTO 均标记 `G1`。
3. 同一幂等身份和完整请求精确重复只读首次材料并返回原结果，不推进代次；任一字段不同返回 `幂等冲突`。资源失败、许可拒绝、入口拒绝、未找到、已退出、事实代次漂移、引用冲突和内部不一致均零载荷、零变化。
4. 发布未知只能用同一组合幂等身份读取 L1 首次写入材料收敛；不得重建新身份、拆成两次提交或猜测是否发布。首次材料缺失或两参与者材料不互证返回 `内部不一致`。
5. 本入口不提供撤销或补偿写。撤销必须由未来具名状态/动态退出计划分别经各自 owner 的正式退出合同完成；本叶不得以回滚第二次提交冒充撤销。
6. 提交成功后，provider 只做一次共同 `G1` 的状态完整读回、动态完整读回和主体身份来源读回；任何缺项、混代、关系角色错误或来源不一致返回 `内部不一致`，不得把已发布事实伪装为失败并重写。

## 7. 装配、迁移与兼容

生产白名单新增 `海中鱼巣/核心/L1所有者范围CRUD.数据.h`、`海中鱼巣/领域/L2通用虚拟存在结构.数据.h`、`海中鱼巣/领域/服务.L2通用虚拟存在结构.ixx`、`海中鱼巣/领域/L2状态动态原子发布.数据.h`、`海中鱼巣/领域/服务.L2状态动态原子发布.ixx`，并允许现有 L1 服务/仓库、状态/动态 DTO/服务、普通应用及两个工程文件为接线改动。任务/方法、L3/L5、验证工具、知识库和 `.codex-build` 不在白名单。

普通状态/动态 CRUD ABI 与稳定编码不迁移；旧任务/方法私有事实不删除、不再被解释为 ARCH-L2 当前权威。迁移顺序固定为：建立通用虚拟存在 owner → 建立状态 owner → 建立动态 owner → 形成双参与者事务凭证 → 建立组合 provider → 后继业务逐项改为公开 L2 引用 → 经独立读回后再由具名计划退出旧兼容事实。任何一步缺失都保持旧兼容事实但不得标记 ARCH-L2 迁移完成。

## 8. 验证矩阵与未证明边界

必须覆盖：通用虚拟存在增/重复/异义/当前历史/退出保护；状态和动态既有 CRUD 回归；双参与者首次成功、同义重复、异义冲突、期望代次漂移、参与者许可拒绝、交叉本地键解析、任一失败零变化、发布未知收敛；成功后同 `G1` 五组读回；普通状态/动态端口不能制造跨参与者半提交；调用方治理前置只做静态/合同边界核对，不由 provider 生成授权或后继轮次；Debug/Release、strict 和生产目标无专项痕迹。

这些证据不证明任务/方法消费者、想/看治理授权、现实执行授权签发、安全硬否决、活动资格、调度配额、轮次结算、后继决议、世界树/概念空间、L3/L4/L5 装配、名称绑定、业务结果、崩溃恢复或跨进程恢复。

## 9. 设计结论

v0.1 的“联合或桥接”“执行期扩展事务或重组选定 owner”全部退出。v0.2 唯一方案是分离结构 owner + L1 中性双参与者事务凭证 + ARCH-L2 组合 provider。当前代码尚未提供该凭证、跨参与者引用或通用虚拟存在；本设计和计划发布不代表实现完成，v0.2 只能在代码结果和独立验收后激活。
