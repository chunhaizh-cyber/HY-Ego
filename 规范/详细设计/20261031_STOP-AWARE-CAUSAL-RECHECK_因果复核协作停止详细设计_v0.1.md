## 5. 私有实现、锁获取与循环检查

### 5.1 原锁的可停止获取

`新_需求类.cpp`新增私有`void 检查需求读取停止(std::stop_token)`、`std::unique_lock<std::recursive_mutex> 获取需求读取锁(std::stop_token)`；task cpp对应`检查因果读取停止`、`获取因果读取任务锁`。manager cpp只为本叶新增`检查因果提交停止(std::stop_token)`及`std::unique_lock<std::mutex> 获取因果提交锁(std::mutex&,std::stop_token)`，仅允许传自身`实现::互斥`。无导出、无全局状态、无回调/跨owner控制器。

有stop能力的路径：检查停止→构造defer_lock的unique_lock→`try_lock`，失败则用当前调用局部`std::mutex`和`std::condition_variable_any::wait_for(waitLock,token,10ms,[]{return false;})`停车→重新检查/尝试；获取成功后再检查。无stop能力传入时直接原阻塞`lock()`。标记在获取成功后到达也由已拥有的RAII守卫先释放再展开，不能漏锁。10ms是私有获取重试粒度，不是业务TTL、截止、完整范围或成功上限；没有循环次数上限，不忙旋，不把一次`try_lock`失败返回业务否定。C++20 token等待受stop唤醒，不必等10ms。

**root已明确的施工解释**：CODE-FILE-01第6.2节允许固定锁序的多参与者锁获取，该获取可能停车，不等于第6.5节禁止的持仓库锁等待线程/任务/业务条件完成。本方案局部等待mutex不共享、不进入业务锁序；等待谓词只用于停止唤醒，每次仍`try_lock`同一既有目标锁。仅实现原task→demand下序锁的可取消获取，不等待任务、消息、worker、future、外设或上层回调，不用于解除死锁、取得超时成功许可或替代完整性。锁失败永不当成功，停止到达立即控制取消。不能扩成共享等待仓、其它锁参与者或业务回调，不改规则/全仓mutex类型。

保持task→demand及既有领域内部锁方向；manager锁只复制组织/提交组织，释放后才调task，绝不持manager锁调task。self不持状态锁调用task/manager。原task锁内读demand范围不拆成跨时刻拼快照；取消只解除本次守卫，不解除别的调用者锁。重入同一recursive_mutex由`try_lock`正常递归取得，没有新增递归语义。

取消标记可在各cpp私有栈内作为精确控制异常使用，但不得越过对应可停止公开入口/`noexcept`。需求tag由task显式映射为task tag；不是`std::bad_alloc`或一般异常。`catch(精确取消标记)`必须先于原`catch(...)`，任务资格核心允许原样向上展开到提议/候选可停止边界，不能被工程异常终止捕获。其他异常、未知枚举、成功无载荷、variant无值仍依原合同/最终诊断链处理，不随停止转换正常结果。

## 6. self完整处理流程及manager采用

`处理因果子需求提议`入口捕获一次`停止源.get_token()`；整个本次处理传同一token。self实现内部新增两个私有成员：

```cpp
void 移交因果采用进度(消息项&,新自我消息处理结果&) noexcept;
void 标记因果停止并移交进度(消息项&,新自我消息处理结果&) noexcept;
```

前者只将原项的可选因果回执移动到结果尾部，再reset已移出的原可选项；不改结果状态/原消息、未收回future或接收回执，不重新核验/manager采用，不分配或复制大图。仅允许目标尾部为空或原项已空的幂等调用；现回执类型的无异常move以`static_assert(std::is_nothrow_move_constructible_v<新自我筹办裁决::因果采用回执> && std::is_nothrow_move_assignable_v<新自我筹办裁决::因果采用回执>)`约束，不能默默换为copy。后者只用于确实停止的因果处理分支，设原消息/`停止取消`后调用纯移交helper。两者诊断责任为受上述输入约束的“无适用错误分支”；前缀只是已有进度，不是新账。

`终结剩余消息(状态)`由正常停止和`内部错误`两条路径共同调用，必须先保持原状态/未收回future/异常映射，再仅调用**纯移交**helper；不得无条件调用会标停止取消的helper。正常停止原状态仍可依既有future分流为`已交接未收回`；内部错误终结也不因新增进度变成停止取消。普通结果及原promise兑现一次规则保持。

最终交付站点明确固定：①`终结剩余消息`末尾原`项->承诺.set_value(结果)`改为`项->承诺.set_value(std::move(结果))`，其后不再读取/复制被移动结果；②主运行循环正常终结单次消息的`项->承诺.set_value(std::move(结果))`已是move，保持该调用，交付后只按原逻辑移除活动项/更新生命周期，不再访问结果。不能helper先move而promise又选const引用copy。`set_value`自身的重复兑现/无共享状态等异常仍按原异常链及broken_promise处理，不承诺它无异常，也不因停止吞掉交付错误或重发已成立事实。

`fresh`局部lambda显式返回`新任务因果提议可停止结果`：先检查token→manager `读取因果等待边(token)`→检查→task `提议任务因果子需求(...,token)`→检查。取消直接返回控制分支，不返回一个可与原提议比较的假对象。所有`fresh()!=原`调用点先判分支，只有正常完整结果才能比较并标来源过期。

| 本函数现执行点 | 本叶精确行为 |
| --- | --- |
| 处理入口、已有因果回执重入 | 已停止立即移交已有前缀，不再正式一致读取、重建或提交。`处理筹办反馈`取得停止取消时返回该结果，不转`nullopt`重试；因果反馈路由前后检查，停止不送学习或改为无方法。 |

| 每个子项，含已发布D复用 | 每次循环先查stop；未停止才读取已发布一致性。不得在停止后为了复用再fresh。 |
| 首次采用fresh | 用上述lambda；取消移交进度即返回，不比较为来源过期，不继续创建概念。 |

这些检查用于“已观察到停止后不再开始下一操作”，不提供stop原子阻止所有owner提交的跨域发布门：信号在最后检查后/某owner已进入时到达，允许完成该一次现合同操作，必须保留事实，再停止后继。不要在一个原子操作中途加入cancel造成半结构。

manager私有完整签名固定为：`因果等待组织快照 读取因果等待组织已加锁(std::stop_token={}) const`、`std::vector<新因果任务等待边> 读取因果等待边内部(因果等待组织快照* =nullptr,std::stop_token={}) const`，以及第4.3节返回类型的`新自我因果筹办提交结果 提交因果筹办裁决内部(const 新自我筹办裁决&,std::stop_token)`、`新自我因果筹办提交结果 提交非执行筹办裁决内部(const 新自我筹办裁决&,const std::optional<新任务因果子需求提议>& 因果来源,std::stop_token)`。前者只遍历自己组织、不跨owner；锁外边读取调用新的`任务服务->查询需求任务(D,token)`，受限等待来源裁决锁外调用新的`获取任务(T,token)`，不能回旧无token task锁。保留原排序/判重，每组织/需求边单位、锁外D→T查询前后检查。新公开重载捕获控制取消，旧入口空token保留。

非执行共同尾部在任何正式修改前，取得manager锁并重核原停止/完成、学习失效、原工作、最近筹办及精确重复/冲突；`因果来源`非空时还须当前因果提议与复制快照精确相等（等待材料仍为待选择），否则`定位已变化`且零本次新增。读取等待T完成及进入最后锁后均检查停止；采用一旦开始，不在登记等待来源、最近裁决/后继/反馈及通知之间插停止。这是不在原修改段中途控制取消，不承诺原容器分配及异常路径获得新增事务保证，原错误处理仍保持。原通用空来源调用不增加因果限制。新受限形状不能携带执行材料，不可能创建执行工作或递增编号。

manager因果提交内部：在组织快照/新task提议/新对应全集/新身份核验前后检查，同token传递；预备容器完全本地，在最终manager锁内再检查token和原组织/定位。已有匹配采用若已正式读到，直接返回原精确重复/接收回执，不因稍后的stop伪装未采用；未取得锁即取消只说明**本调用零新采用，未重新判定历史采用**，不宣称历史为空，也不删除既有记录/前缀。一次node_handle正式采用一经开始，完整插入原裁决/阻塞/等待并notify后返回实际接收状态，不在三项中间取消；stop之后不回滚。取消发生在本次采用前则零本次manager采用，无部分结果；已有及当次实际回执/关联继续保留。

原通用提交除上述非执行尾部机械复用外，其非因果语义不变、仍传空token；manager后台首次提议/因果等待重筹办、worker、学习及贡献收束仍走原无token入口；本叶不是manager全部在途工作停止改造。self新入口仅由本函数的上述三处裁决使用，后续其它调用方不能自动沿用其取消权。

## 7. 非成功、生命周期与不可中断段

- 工程取消不参与请求/依据/目标相等，不进入因果图、学习、无路径、来源变化、条件不满足或业务状态枚举。取消返回不得携带部分业务结果；已发表事实只由停止进度/正式owner保留，不拿它冒充完整提议。
- 原有资源失败、合法未找到/等待及工程错误保持独立；发生实际工程错误时仍报告/中止，不用stop吞掉。所有新wrapper先验variant分支，不能无条件get、转换false或空vector。
- 不删必要fresh，不把第一次请求作为第二次fresh结果，不缓存旧D列表跨owner变化；不减少16条件、类型或双向完整性核验。
- 原目标范围概念创建不是只读：停止检查在owner调用前后，创建已发生则保留其正式节点。self概念、D、manager已接受组织、已存在T/X/动作等同理，停止不回滚、不重签来源、不重复执行或结算。
- 局部wait、unique_lock、token及候选随调用栈退出；无后台回调、线程、共享取消registry或析构后引用。原self/manager/work/learning、采集及全部owner仍由应用上下文持有至最终join。
- 不改停止广播、原5000ms、有界失败回执、最终join、宿主及退出码。provider在本叶仍可有6.6秒/17.8秒及其它同步滞留；单个D getter、概念调用、底座共享/独占锁等待也没有本叶可中断保证。新可停止task/demand取锁避免等待本锁持有者结束，不意味着中断该持有者。
- 具名残余：`读取任务贡献动作阶段(J)`内部为核验边界调用的`读取贡献对应(*this)`仍隐式使用空token，可能继续进入贡献/需求全集；该getter内部直接子接收等循环亦不在本叶token化。`核验需求列表物理`内部成员枚举及`读取需求完整物理`保持不可中断。外层在这些调用前后检查，只能证明外层已冻结枚举可取消；本次历史J为空负载不能证明历史J路径已覆盖，更不能证明上述内层停止时延。两段若成为新反例，按原目标另取证，不在本叶泛化getter/provider/L1。
