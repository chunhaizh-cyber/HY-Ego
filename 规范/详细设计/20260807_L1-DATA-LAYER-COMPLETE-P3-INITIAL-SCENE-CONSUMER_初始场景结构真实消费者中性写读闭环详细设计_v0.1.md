## 1. 目标与完成边界

本叶把现有语义归属 L2 场景领域的 `L1场景结构服务::创建初始场景` 从 legacy L1 合同迁移到业务中性的 `L1中性写集请求`，并在真实 `生产运行期会话::启动` 中，于世界登记成功之后、旧系统角色初始化之前恰一次调用。场景服务自行拥有初始场景准入、幂等域、写集业务形状、状态解释和场景事实投影；L1 只原子发布一个普通场景节点、一个 I64 场景标记值、一条直接父关系和一个属性槽，并提供精确当前读。

生产调用只有同时取得 `初始场景结果` 成功状态、完整事实和后续公开权威读回时才可继续。代码发布后的独立消费者验收只累计本消费者实际覆盖的关系创建、关系当前读以及该混合写集的新增、查询和原子性；不为补覆盖表注入重复、非法、并发、恢复或其它非业务调用。

本叶不创建存在、特征、状态、动态，不执行修改或退出，不建立 L1 自检、专用 L1 驱动、第二程序、日志 PASS 或独立 L1 结论；不考虑崩溃、重启、断电和跨进程恢复。

`世界登记服务::按登记读取权威事实` 保持原精确入口和字段验证，但目标代次改为本次 `读取中性当前事实代次` 的首末一致结果。五个登记节点和场景标记值必须：创建代次非零、彼此同一、不得晚于本次当前截止、均未退出；不得再要求创建代次等于当前截止。成功返回前复制登记并把 `已验证事实代次` 设为本次当前截止。

## 5. 初始场景中性写集

最终技术幂等键固定为：

```text
场景中性幂等域 = 0x02
最终键 = (0x02ULL << 56) | 请求.幂等身份.值
```

根函数先调用 `世界登记服务::读取当前登记()`；只接受成功、完整登记、请求世界根等于登记世界根且登记当前截止等于请求期望事实代次。随后形成：

| 本地键/项目 | 中性字段 |
| --- | --- |
| 1 节点 | `普通`；初始场景 |
| 2 值 | 所属=本地 1；属性类型=登记.场景标记属性类型；材料=`I64{1}`；来源=登记.服务身份 |
| 3 关系 | 源=登记.世界根；目标=本地 1；类型=登记.直接父场景关系类型；角色/顺序=0 |
| 属性槽变更 | 所属=本地 1；属性类型=登记.场景标记属性类型；当前值=本地 2 |

请求只含中性合同 1、调用方期望事实代次、最终幂等键和上述四组；退出组为空。不得调用 `探测幂等`、`读取完整快照`、legacy `提交写集`、审计、恢复、SQL 或旧仓；不得形成操作标签、G2 意图、摘要、执行证据、提供者/领域结果见证或发布后读回计划。`提交中性写集` 恰一次。

成功类结果必须满足合同 1、回显最终键、事实代次非零、3 项本地键/稳定编码映射各自唯一，且新编码与登记五编码均不重复。`成功` 必须形成内存权威发布且重试边界为不适用；`精确重复` 必须不形成新发布且重试边界为原幂等键读回收敛。坏成功一律映射内部不一致，不缓存定位。

写入状态映射：成功→已提交，精确重复→幂等读回，入口拒绝→入口拒绝，事实代次漂移→版本漂移，幂等冲突→幂等冲突，资源失败→资源失败；未找到、已退出和内部不一致在已经取得同截止完整登记的前提下均为内部不一致。

## 6. 权威读回与定位缓存

从成功映射形成 `初始场景读取请求`。私有读回固定：

```text
世界登记服务::读取当前登记
-> L1 读取中性当前事实代次（起始）
-> 精确读取初始场景节点
-> 精确读取初始场景当前场景标记属性
-> 精确读取场景标记值
-> 精确读取直接父关系
-> L1 读取中性当前事实代次（结束）
-> 首末、登记截止及四项读取代次相等
-> 逐字段验证场景、值、槽、来源、父关系方向/类型/顺序
-> 返回完整初始场景事实
```

场景节点、标记值和父关系的创建代次必须同一、非零且不大于本次截止；创建路径还要求该共同创建代次等于中性写入结果事实代次。读回允许后续无关写使当前截止大于初始场景创建代次。

服务用锁保护 `std::optional<初始场景读取请求> 当前初始场景定位_`。只有首次创建成功且权威读回完整时写入；重复创建必须与既有定位全等，否则内部不一致。新增：

```cpp
初始场景结果 读取当前初始场景() const;
```

它只以定位调用同一精确读回，不返回缓存事实。既有 `读取初始场景(请求)` 保留并走同一算法。读取未找到/已退出/属性未设置→未找到，资源失败→资源失败，字段矛盾→内部不一致，首末或逐项代次不等→版本漂移；所有非成功均无部分事实。

## 7. 生产接线

生产配置新增固定 `初始场景幂等身份{1}`，与世界登记身份同值但经不同领域前缀映射为不同技术键。世界登记成功后，生产会话用其结构化登记形成：

```cpp
初始场景创建请求{
    L1场景结构合同版本,
    世界登记规则版本,
    {世界登记.世界根场景, 节点种类::普通},
    配置.初始场景幂等身份,
    世界登记.已验证事实代次
}
```

并调用 `运行期上下文::初始化初始场景` 恰一次。上下文新增 `初始化初始场景(请求)`、无参数 `读取初始场景()` 和 `初始场景完整()`；只转发场景服务，不直调 L1、不保存第二份事实。

`运行期上下文::完整()` 同时要求世界登记和初始场景读回成功且二者当前事实截止相等，再检查旧系统角色和概念活动。固定顺序：世界登记→初始场景→旧系统角色→概念活动→候选完整性→首次发布。

`生产运行期启动状态` 末尾新增 `初始场景初始化错误=11`；`生产运行期启动结果` 在世界登记状态之后新增 `世界结构状态 初始场景业务状态`。所有聚合初始化按新字段顺序逐项具名冻结：请求/配置失败两业务状态默认；已有租约两者均为已读取；世界登记失败时场景默认；初始场景失败时保留世界登记成功状态和场景原样状态，后续三步均不调用；后续失败和最终成功均保留两项原样成功状态。
