## 1. 唯一目标与完成边界

本设计把六个历史路线叶合并为一个连续代码结果：

```text
具体需求 D 建立或复用任务 T
-> 建立 T→D / T→E / R1
-> E 上无动态首态 {筹办,待初次筹办}
-> 建立 P1 / A1
-> 迁移为 {筹办,筹办中}并形成第一动态
-> 任务管理只按 E 的当前状态选择筹办、执行、结算或轮次收束
-> 执行冻结完成
-> 内部治理 / 纯观察零授权；现实改变在执行开始前取得一份自我授权
-> 生存控制、调度资格和安全硬否决复核
-> 正式执行、实际结果和结算阶段
-> 结果可共用 / 争用裁决，争用时先分配
-> 对每个合格 T→D 独立核算
-> 任务轮次结算并迁移为轮次已收束
-> 停驻等待自我继续 / 结束 / 等待 / 取消决议
-> 只有继续建立 R(n+1)并重新筹办
```

完成必须同时证明：

1. 叶1—叶6全部进入同一代码候选，不能用任一局部叶替代完整结果；
2. ARCH-L2 提供者实际接入，L4 普通应用只消费公开服务；
3. 首态状态 owner 单 `G1`，每次状态—动态迁移最终单 `G1`；
4. 当前、历史和提交后故障均经正式独立读回收敛；
5. 连续两轮端到端场景成立，且旧私有状态、Stage C 和自动重筹办生产链为零调用。

本设计不把 ARCH-L1/L2 私有 helper、事务候选、写端口、测试 seam、编译对象组织或其专项验证纳入 L4 设计。基础提供者不是本计划的交付目标。

## 2. 权威、依赖和施工时序裁决

### 2.1 两条并行链

L4 需求权威已经确认并提交第 5 节目标 ABI，因此：

```text
L4 目标 ABI 确认
-> 本计划可以设计和连续实施全部 L4 消费代码

同时：
交互2实现 ARCH-L1/L2 提供者
-> 若不可达则具名返回

最终：
真实提供者接入
-> 联合编译、统一测试和连续两轮验收
```

“提供者尚未返回”不是 L4 设计或代码编写的等待条件。只有以下两项之一成立才停止受影响切片：

- 提供者具名报告目标 ABI 无法实现；
- 实际公开 ABI 与目标 ABI 的差异会改变 L4 机器语义，而不是可由无语义适配器机械映射。

### 2.2 目标 ABI 与当前能力分账

连续施工期间所有目标函数、DTO 和结果空间必须标注为`待实现目标 ABI`。禁止：

- 声称当前仓库已有对应公开符号；
- 建立返回默认成功的生产 stub；
- 让 L4 读取 L1 私有仓、候选、锁、内部写集或事务凭证；
- 以任务私有状态、缓存、线程槽或测试对象建立第二状态 / 当前选择权威；
- 在真实提供者接入前声称联合编译、运行或验收通过。

### 2.3 连续施工与统一验证

叶1—叶6只表示同一计划内部的修改顺序。叶间只运行：

- 精确白名单与所有权检查；
- `git diff --check`和新增模块 / 工程登记的文本闭包检查；
- 目标 ABI 名称、字段和合同版本一致性扫描；
- L1 私权、旧任务私有当前状态、Stage C 和自动重筹办入口不得新增调用的扫描。

叶间不构建、不运行专项、不运行端到端、不形成验收记录。只有完整 L4 候选和真实提供者接入后统一验证一次。

### 3.2 必须重写或退出

1. `需求初次筹办准备提供者`当前存在部分阶段已写、后继无法继续时缺少统一的原键收束；它还携带隐藏的第七个特征定义固定键、硬编码状态材料和跨阶段截止假设。新实现必须把固定全局定义键与六阶段请求键分账，每段保存原请求并可独立恢复。
2. `L2任务授权安全复判材料`、`任务筹办授权安全材料来源`、`授权安全等待`和冻结中的授权安全字段属于旧 Stage C，全部退出。
3. `L2任务治理状态事实`、`目标未达成待重筹办`、`下一筹办工作包`、重筹办意图协议 / 端口 / 处理槽及自动执行队列路由全部退出生产。
4. 旧融合兼容桥和`初次请求版本待迁移`占位不得继续作为新链分支。新计划只接受当前版本完整原请求；历史缺字段材料形成具名`历史合同不支持`且零新写。
5. `任务子目标回流重判.数据.h`和`服务.任务子目标回流重判.ixx`不得继续保留旧后继准备 / 下一筹办工作包类型；叶6必须取得其所有权并迁移为“同一未收束 Rn 内重新筹办”的定位入口。它们不得继续作为独立任务创建链。
6. 当前没有真实实例方法执行生产链：任务工作线程只接收调用方预先形成的`任务工作结果材料`，不读取冻结、不调用稳定动作键端口，也不形成真实动作结果。新链必须让工作线程成为强类型执行请求的唯一消费者并真实调用实例方法执行 provider；旧外部预形成结果生产入口退役。
7. 当前没有自我现实执行授权 owner、现实执行安全硬否决 provider或控制态 / 调度 / 技术许可 / 授权 / 硬否决的综合门控。现有安全任务权限算法只能复用为调度材料，不能冒充授权或硬否决。

## 4. 唯一事实所有权与依赖方向

| 事实 | 唯一结构 owner | 业务发布 / 解释者 | 禁止的第二权威 |
| --- | --- | --- | --- |
| T、T→D/T→E、Rn/Pn/En、路径、实例、冻结、实际结果、轮次结算及外部引用 | `L2任务结构服务` | L4任务治理提供者 | 线程槽、日志、任务私有状态 |
| E、特征定义 / 实例、状态、当前选择、动态 | 既有 ARCH-L2 公开服务 | L4只提交已裁决材料并独立读回 | L4私有 map、任务枚举、L1直达 |
| 自我现实执行授权、授权撤回 / 消费、自我后继决议 | 新`L2自我治理结构服务` | 自我业务 provider；自我线程只编排 | 安全服务、任务 / 方法 owner、消息布尔值 |
| 结果共用 / 争用关系和争用分配 | 新`L2任务结果消费结构服务` | 任务结果消费分配 provider | 线程顺序、任务级汇总值 |
| 每个 D 的正式核算 | 新`L2需求结算结构服务` | 需求核算 provider | 任务轮次结论、列表汇总 |
| 任务轮次结算 | `L2任务结构服务` | 任务轮次结算 provider | 需求、价值、安全、服务结果副本 |

三个新 L2 结构服务属于 ARCH-L4 业务族的强类型记录 owner，不是交互2负责的 ARCH-L1/L2 通用存在 / 状态 / 动态底座。它们只保存已由 L4 provider 裁决的强类型结构，不反向产生业务资格或结论。

## 5. 待实现 ARCH-L2 目标 ABI

### 5.4 当前和历史读取

当前读取以`任务正式存在 + 阶段特征实例 + 非零截止`为完整选择键，返回零或一条闭合当前选择；多条、坏端点、坏特征、目标状态缺失或关系生命周期矛盾均为内部不一致。历史读取以同一选择键和指定截止返回零或一条快照，不投影未来退出。

真实提供者接入前，本节类型只作为目标合同参与下游源码声明；不得在普通应用装配一个模拟实现。

固定读取顺序：

```text

-> 安全硬否决
-> 真实动作开始前再次复核全部当前性

-> 才允许进入工作队列
```

门控结果只携带正式引用和结构化阻断原因，不保存第二授权或调度事实。

`任务强类型执行请求`物理字段固定为`合同版本、执行幂等身份、T/R/P/E、冻结及版本、实例、方法及内容版本、有序冻结动作范围、执行进入治理动作、派发冻结、可选授权、授权收口幂等身份`；任务工作线程是唯一消费者。线程输出`任务动作待验证材料`，固定携带原请求定位、动作键逐项返回、开始 / 结束时间和执行 provider状态，不携带正式成功布尔值。任务工作线程从确认后的强类型请求队列取出唯一请求，重新读取冻结和门控见证，调用`执行已冻结实例方法`，将动作返回只作为待验证材料；随后按 8100 的实际世界独立回读、归因和正式结果发布链收束。删除“调用方提交已经形成的工作结果即进入上行”的生产入口。

四分支固定为：

- `继续`：task owner 同次建立新的 R(n+1)、新的 P、继续治理动作及对决议的引用；再从旧收束状态迁移到`{筹办,筹办中}`并形成一条动态。新轮次不复制旧路径、实例、冻结、结果或授权。
- `结束`：正式结束任务生命周期，不建立新轮次或状态迁移到筹办。
- `等待`：零任务事实写入，保持收束停驻；精确重复仍为零写。
- `取消`：形成取消收口，不建立新轮次；若已有动作必须先有停止证据。

目标未达成、需求仍存在或新方法可用都只是自我决议输入，不能由任务管理自动映射为`继续`。

## 7. 阶段迁移矩阵与任务管理选择

### 7.1 合法主链

| 当前阶段 | 必需业务事实 | 唯一后继治理 |
| --- | --- | --- |
| `{筹办,待初次筹办}` | T/E/R1、阶段实例、无动态首态 | 建立 P1/A1并迁移到`筹办中` |
| `{筹办,筹办中}` | 当前 R/P、筹办占用和最新事实截止 | 继续筹办，形成等待或冻结 |
| `{筹办,筹办等待}` | 等待对象、合法生产者、重触发条件 | 条件变化后在同一未收束 R 建新 P；不建新 R |
| `{筹办,可执行已冻结}` | 当前选择、实例、En、冻结和动作范围 | 纯内部治理 / 观察进入执行；现实改变先迁移到待授权 |

任何跳过中间状态、前驱事实缺失、存在第二当前选择、状态值组合非法、当前读回多义或共同截止无法互证都返回内部不一致，零后继业务写入。

### 7.2 任务管理线程唯一算法

任务管理线程每次只处理一个不可变治理输入：

```text
读取 T→E 和当前 R
-> 经任务阶段结构消费端口独立读取 E 当前阶段
-> 按第7.1节选择一个领域 provider
-> provider返回正式结果定位
-> 任务管理再次独立读回目标状态和任务 owner事实
-> 成功则提交下一合法队列项或上行定位
-> 非成功按原幂等身份保留 / 重试 / 等待
```

线程不保存主阶段副本。队列槽只承载定位和重试，不得以槽阶段决定业务迁移。

## 8. 初始化、重放和发布未知

### 8.1 R1 初始化

外层请求继续保存六个非零、两两不同的显式阶段幂等身份；固定全局阶段定义键`TASKSTAG`不是第七个请求键。顺序：

```text
D/L同截止裁决G0
-> E建立 / 原键读回
-> T/T→D/T→E/R1建立 / 原键读回
-> TASKSTAG定义读取或建立
-> E阶段实例建立 / 原键读回
-> 无动态首态建立 / 状态与当前选择独立读回
-> P1/A1建立 / task owner独立读回
-> 第一迁移 / 状态、当前选择、动态独立读回
-> 组合工作包
```

每段成功事实保留；后段失败不回滚前段。每次进入 provider 都先按完整原请求读取首次记录，再从第一个未收敛阶段继续。任何已确认提交后的读回失败只返回`已可能发布`和提交见证；原键重放正式读回成功后才允许越段。

### 8.2 后继阶段幂等

每个任务轮次必须由上游不可变治理信封显式携带：阶段迁移、执行轮次 / 冻结、授权、授权收口、结果消费、争用分配、逐需求核算、轮次结算、收束迁移、后继决议和继续轮次建立所需幂等身份。键不能由时间、代次、线程、哈希、任务身份或上一函数返回临时派生。

逐需求核算键按冻结的 T→D 关系稳定顺序逐项显式携带；成员集合变化使原结算请求异义，不得静默追加。

## 10. 构造、生命周期和线程接线

普通应用上下文最终持有同实例：任务、需求、方法、存在、特征、状态、动态、自我治理结构、结果消费结构、需求结算结构服务及全部 L4 provider。构造顺序按被依赖者先于消费者，析构反序。

任务管理线程构造改为只接收：

```text
任务主阶段治理提供者
+ 任务执行派发门控提供者
+ 实例方法执行提供者
+ 任务结果消费分配与轮次结算提供者
+ 自我任务后继决议消费提供者
+ 不可变邮箱 / 队列
```

删除重筹办提供者、重筹办意图端口和重筹办处理槽。结果上行循环只把正式实际结果定位转交结算入口；收束结果定位上交自我线程。自我线程调用自我业务 owner 发布授权或后继决议，再以不可变定位消息交任务管理独立读回。

## 11. 非成功、并发和恢复边界

所有新写入口统一：

- 交换前拒绝、G0漂移、许可、资源或内部不一致零普通事实写入；
- L1确认提交 / 精确重复后的独立读回失败保留事实、幂等账和代次，返回提交见证及`已可能发布`；
- 只允许原幂等身份、原完整请求重放；
- 同键异义零新增拒绝；
- 结果载荷与状态组合不合法视为内部错误；
- 精确重复返回首次事实和首次代次，零新动态、零新轮次、零新授权、零新结算；
- 多线程并发由 owner 幂等账和期望代次裁决，线程槽不得抢先决定成功。

本计划最终证明进程内运行期闭环，不证明崩溃 / 重启、跨进程恢复或 SQL 材料恢复。若现有服务具备正式恢复能力则保持，不在本目标扩张。

## 12. 最终统一验证合同

只有完整 L4 候选与真实提供者接入后执行：

1. strict、diff、精确白名单和工程登记；
2. 根工程 x64 Debug / Release 仓库外隔离 fresh Rebuild；
3. 完整治理专项一次，覆盖全部首次 / 重放 / 冲突 / 漂移 / 许可 / 资源 / 发布未知矩阵；
4. 普通应用合法消费者统一端到端场景；
5. 连续两轮：R1结算停驻，无R2；自我继续后才建立R2并重新筹办；
6. 当前 / 历史 / 故障后独立读回；
7. 旧私有状态、Stage C、重筹办意图 / 端口 / 槽 / 工作包的生产零调用和零装配扫描；
8. 真实现实改变用例证明一冻结一授权和硬否决优先，内部治理 / 纯观察证明零授权；
9. 可共用逐需求核算、争用先分配再核算及收束缺项拒绝矩阵；
10. 施工 / 验证记录和函数级知识变更清单。

完整成功前不得声明任一内部叶已经通过验收。最终声明边界只能是“L4自我内部治理闭环在当前发布基线完成联合编译、统一测试和连续两轮进程内验收”；跨进程恢复和真实外设世界改变继续具名`NOT_RUN`，除非本次确有对应正式证据。

## 13. 设计自审结论

本设计已经冻结：目标、完整主链、公开目标 ABI 消费边界、L4 DTO / 函数、结构 owner、幂等与重放、状态迁移、授权、门控、结算、后继、线程接线、旧链退役、生产文件和最终统一验证。执行者不得临场改变阶段值、owner、函数合同、错误映射或验证时序。

尚待真实外部事实只有：交互2提供者是否按目标 ABI 可达及其最终公开类型的机械名称映射。若仅名称不同而字段、所有权、结果和错误空间等价，由无状态适配器处理；若语义不等价，具名退回而不降低本设计。
