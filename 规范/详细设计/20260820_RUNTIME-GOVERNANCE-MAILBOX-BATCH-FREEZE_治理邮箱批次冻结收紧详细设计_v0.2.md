## 1. 目标与完成边界

原位收紧 `有界自我治理邮箱::等待并冻结下一批`：保留现有锁内条件等待、停止唤醒、提交时稳定顺序和整批冻结，补齐负等待拒绝、非零严格后继批次序号、资源失败 / 其它异常分账，以及全部非成功下队列、计数、停止态和索引零变化。

本叶只处理运行期非权威治理消息承载。消息协议和提交语义、完整秒、共享事实截止、L2 当前治理批次路由、自我线程 ownership、G0/G1 和领域事实均不在本叶修改范围。

## 2. 当前代码事实与复用裁决

当前正式基线 `f7274df197f690d03d49bafdc8c0f26e696ccdd6`：

- 唯一实现位于 `海中鱼巣/线程/有界自我治理队列.ixx`，根工程已登记，无需新增模块或工程项；
- `自我治理消息`是可复制值类型，消息析构不抛出，默认 allocator 的 `vector::swap`可无抛出交换；
- 提交入口已按优先级稳定插入，冻结入口不得再次排序；
- `等待并冻结下一批`当前先递增计数，再 `reserve`并逐项移动原队列。分配失败可能消耗批次序号并留下半移动队列；
- 当前未拒绝负等待，未守卫 `UINT64_MAX`，函数也没有结构化资源失败；
- 提交 `f7274df1`已经闭合最终时间 / 事实 provider ABI，但不能修复邮箱在下层冻结失败时已损坏原队列的问题。

因此只扩展现有邮箱入口；不新建第二邮箱、第二冻结函数、provider、缓存或 fallback。

## 3. 最终 ABI

保持全部既有枚举值和字段顺序，只在枚举尾部追加：

```cpp
enum class 自我治理冻结状态 : std::uint32_t {
    已冻结 = 1,
    等待超时 = 2,
    已停止 = 3,
    内部不一致 = 4,
    请求拒绝 = 5,
    资源失败 = 6
};

enum class 自我治理队列拒绝原因 : std::uint32_t {
    无 = 0,
    容量为零 = 1,
    协议拒绝 = 2,
    协议内部不一致 = 3,
    重复材料 = 4,
    队列已满 = 5,
    队列已停止 = 6,
    等待超时 = 7,
    空批次 = 8,
    等待参数无效 = 9,
    资源失败 = 10,
    批次序号耗尽 = 11,
    内部异常 = 12
};

自我治理冻结结果 等待并冻结下一批(
    std::chrono::milliseconds 最大等待时间) noexcept;
```

`自我治理冻结结果`、`自我治理冻结批次`和公开读取函数保持现有字段与签名。只有`已冻结`携带非零批次序号和非空消息组；其它状态返回默认零序号和空组。0 毫秒是合法非阻塞观察，负值为请求拒绝。

## 4. 固定控制流与提交点

```text
锁外检查最大等待时间非负
-> try 内取得唯一队列锁并按现有谓词等待
-> 超时 / 停止空队列 / 伪唤醒分账
-> 非空时检查批次计数未达 UINT64_MAX
-> 锁内按现有顺序完整复制 deque 到局部 vector 候选
-> 候选完整后形成已检查后继序号
-> 以无抛出 swap 把候选交给结果批次
-> 无抛出 clear 原队列并一次赋值发布计数
-> 解锁后返回完整值式结果
```

固定映射：

| 条件 | 状态 / 原因 | 守恒 |
| --- | --- | --- |
| 负等待 | 请求拒绝 / 等待参数无效 | 取锁前返回，空批次，邮箱零变化 |
| 合法等待超时 | 等待超时 / 等待超时 | 空批次，邮箱零变化 |
| 停止且队列为空 | 已停止 / 队列已停止 | 空批次，邮箱零变化 |
| 唤醒后为空且未停止 | 内部不一致 / 空批次 | 空批次，邮箱零变化 |
| 计数为 `UINT64_MAX` | 内部不一致 / 批次序号耗尽 | 空批次，队列和计数不变 |
| 候选复制 `bad_alloc` | 资源失败 / 资源失败 | 空批次，邮箱全部状态不变 |
| 锁、等待或其它异常 | 内部不一致 / 内部异常 | 空批次；已取得的锁由 RAII 释放 |
| 候选完整 | 已冻结 / 无 | 原稳定顺序、非零严格后继序号；仅此分支清队列并推进计数 |

catch 必须包住锁构造、等待和候选复制。候选完成前禁止递增计数、移动原消息或逐项删除。停止且仍有消息时先冻结完整剩余批次，下一次空队列读取才返回已停止。
