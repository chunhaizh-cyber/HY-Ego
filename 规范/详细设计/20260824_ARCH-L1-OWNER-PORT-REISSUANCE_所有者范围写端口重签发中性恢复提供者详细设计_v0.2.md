## 1. 漂移与唯一裁决

4015 §5.1 固定公开函数形态：

```cpp
L1所有者范围交付 L1所有者范围签发器::重新签发所有者范围写端口(
    const L1所有者范围重入请求& 请求);
```

当前 `服务.L1事实基座.ixx` 的 `L1所有者范围交付` 只有 `建立结果` 与 `写入端口`，而数据头已经有 `L1所有者范围重入结果`。四种候选中，新增返回类型会违反 4015 固定签名，variant/统一结果会改变既有建立消费者的字段访问，降装为建立结果会混淆建立与重入状态。因此 v0.2 唯一方案是扩展同一交付 DTO，保留既有字段顺序和语义，并追加具名重入结果：

```cpp
struct L1所有者范围交付 final {
    L1所有者范围建立结果 建立结果{};
    L1所有者范围重入结果 重入结果{};
    std::optional<L1所有者范围写端口> 写入端口;
};
```

追加字段不改变既有建立调用点读取 `建立结果` 和 `写入端口` 的源码合同；既有建立函数不填 `重入结果`，重签发函数不填 `建立结果`。两种结果均使用数据头既有 `L1所有者范围管理状态`、合同版本、建立幂等身份、owner 事实投影、事实代次、内存权威发布标志和重试边界，不新增业务字段、owner/token/进程字段或新状态枚举。本修订保证当前源码消费者零迁移，不宣称跨编译单元的二进制布局兼容；所有受影响生产文件必须按同一头文件重新构建。

## 2. 目标与边界

本叶只实现同一 L1 运行包内、owner 当前且无活动端口时的中性端口重签发。它不建立或退出 owner，不发布节点/关系/值，不推进事实代次，不产生 G1，不解释 L2/L4，不是崩溃、重启、快照或跨进程恢复。4015/4070 的持久恢复材料与确认候选仍是后续独立目标。

重签发请求仍为：

```cpp
struct L1所有者范围重入请求 final {
    std::uint32_t 合同版本 = L1所有者范围CRUD合同版本;
    L1结构所有者身份 所有者;
    L1所有者范围建立幂等身份 建立幂等身份;
};
```

请求没有独立重入幂等键；建立幂等身份只用于定位既有 owner 建立账。局部 owner、名称、服务枚举、端口、租约、nonce、线程/进程、恢复材料和业务标签均拒绝进入请求。

## 3. 两函数填充规则

### 3.1 建立函数

`建立所有者范围` 的返回类型仍为 `L1所有者范围交付`。它只填 `建立结果`；`重入结果` 保持其默认 `入口拒绝/合同版本/零代次/空事实/修正请求后可重试` 投影。既有成功/精确重复且 owner 当前、无活动端口时交付唯一 move-only 端口；任何其它路径端口为空。现有建立消费者无需修改。

### 3.2 重签发函数

`重新签发所有者范围写端口` 只填 `重入结果`；`建立结果` 保持默认投影。函数先验证请求，再取得 `状态->端口锁`，在同一运行包仓库管理读取中核对 owner 当前事实、独占范围、建立幂等账首次请求/首次结果与 owner 逐字段互证，最后在仍持有端口锁时登记活动 owner 并构造 move-only 端口。成功时 `重入结果.状态=成功`、`是否形成内存权威发布=false`、`事实代次`回显安全取得的当前非零代次，端口唯一且绑定该 L1 实例/owner；不推进代次。

重签发不返回 `精确重复`：同一 owner 已有活动端口即 `许可拒绝`，不交付第二端口；释放旧端口后，完全相同请求才可再次成功。所有非成功结果的 `写入端口` 必须为空。

## 4. 结果映射与不变量

| 条件 | 填充的结果 | 状态 | owner 事实 | 端口 | 事实变化 |
| --- | --- | --- | --- | --- | --- |
| 合同版本、owner 编码或建立幂等身份为零/错版本 | `重入结果` | `入口拒绝` | 空 | 空 | 零变化 |
| L1 运行包/签发器失效 | `重入结果` | `许可拒绝` | 空 | 空 | 零变化 |
| owner 建立账或 owner 事实不存在 | `重入结果` | `未找到` | 空 | 空 | 零变化 |
| owner 已退出 | `重入结果` | `已退出` | 可返回安全历史投影但不作为能力 | 空 | 零变化 |
| 非独占范围、建立账与 owner 逐字段不互证、夹带错误范围 | `重入结果` | `引用冲突` | 空或安全投影 | 空 | 零变化 |
| 建立账同键异义、owner 编码与账不匹配 | `重入结果` | `幂等冲突` | 空或安全投影 | 空 | 零变化 |
| 当前事实代次为零、隔离状态或仓库不变量损坏 | `重入结果` | `内部不一致` | 空 | 空 | 零变化 |
| 同 owner 已有活动端口 | `重入结果` | `许可拒绝` | 可返回安全当前投影 | 空 | 零变化 |
| 当前独占 owner、账互证、非零当前代次且无活动端口 | `重入结果` | `成功` | 完整安全当前投影 | 唯一 move-only 端口 | 不推进代次 |
| 非材料锁/分配异常 | `重入结果` | `资源失败` 或 `内部不一致` | 空 | 空 | 零变化 |

`事实代次漂移` 不由本入口主动制造：该管理操作不接受期望代次，当前代次只能安全回显；若管理读取期间无法取得一致当前事实，按 `内部不一致` 收口，不猜测代次。重试边界只允许修正请求后重试或在活动端口释放、owner 仍当前且建立账互证后重试；不得用新建立幂等身份掩盖异义。

## 5. 现有消费者兼容性与物理实现

现有建立消费者仅读取 `L1所有者范围交付.建立结果`、`写入端口`，包括不可变材料、场景、特征、状态、动态、需求、任务、概念、名称、方法等装配路径；它们零源码迁移。新增字段只由 L1 签发器内部重签发入口读取。

精确实现位置：

- `海中鱼巣/核心/L1所有者范围CRUD.数据.h`：复用既有重入请求/结果，不新增状态或字段。
- `海中鱼巣/核心/仓库.L1事实基座.ixx`：增加模块内只读 owner/建立账互证辅助，不返回仓库引用、锁或 token。
- `海中鱼巣/核心/服务.L1事实基座.ixx`：扩展 `L1所有者范围交付`，建立函数保持旧填充规则，新增签发器重签发入口并保持“端口锁→管理验证→活动 owner 登记→构造端口”顺序。

不得修改普通建立消费者、L2/L3/L4、业务 DTO、L1 普通写入 ABI 或异主 WIP。

## 6. 验证矩阵与完成边界

专项必须断言：重签发返回同一交付 DTO 的 `重入结果`；建立调用点的 `建立结果` 与 `写入端口` 行为不变；成功唯一端口绑定同一 L1 实例/owner 且不推进事实代次；所有非成功路径 `写入端口=nullopt`；合同/owner/账/范围/活动端口/隔离/代次/异常映射准确；建立、退出、普通写入和现有 L2 ABI 回归不变；不同 owner 可并行、同 owner 竞态不交付第二端口；移动源、析构、owner 退出、运行包销毁后端口失效。

必须运行 Debug/Release 根工程、`D:\TEMP` 专项、strict、diff-check、UTF-8/no-BOM 与生产零专项痕迹检查。不得宣称崩溃/跨进程恢复、快照候选、L2 G1、L4 消费者或业务闭环完成。
