## 1. 修改对象、原因、目的

- **修改对象**：语言 owner 新增的“表达组织知识”节点，以及出站语言场景中的具体表达结构记录。两者都属于内部治理侧的语言知识和语言场景内容，不改现实世界、需求、任务、方法。
- **原因**：输出时，现有代码在 `字段询问.语言服务.cpp` 里手工拼出含义图，`正式表达需求.h` 只支持“提问×需求字段”。每加一种表达，就要再写一段专用代码。
- **目的**：建立“正式表达需求 → 具体表达结构”的通用路径。由表达组织知识按类型复用，产出与语种无关、保留角色与关系的含义网，并留档。

## 2. 当前事实（路径相对 `海中鱼巣/海中鱼巣/`）

1. **正式表达需求** `正式表达需求`（`业务/正式表达需求.h:19-32`）的字段：
   - 目的（旧表达目的枚举）、对象种类（只有“需求字段”）、含义操作（旧枚举）、目标内容；
   - 需求范围概念、说话者、受话者、语言、交互窗口、交互作用域；
   - 第三方指代概念、选用指代名称关系；
   - 槽完备度、触发需求节点、触发方法节点。

   另有两个转换函数：`从字段询问目标形成表达需求`（`:35`）和 `投影为字段询问目标`（`:54`）。
2. **候选话语生成** `字段询问语言服务::生成候选话语`（`业务/字段询问.语言服务.cpp:20`）的过程：
   1. 核验需求与字段：路径长度为 1、字段当前未知；
   2. 读取字段询问范围（取得内容概念）；
   3. 读取第三方指代名称；
   4. 在 `:51-65` 手工拼出两节点含义图：根为信息请求（提问范围，确认范围＝填项内容），子节点为特征描述（主体＝需求，特征类型＝字段，特征值＝待求值〔内容范围概念〕），并写入专用槽位“被询正式内容”；
   5. 调用 `从基础信息生成可回读单句`。

   返回值 `新字段询问文字结果{状态, UTF8正文, 所用知识节点组}` 里没有含义。
3. **调用方** 是询问本能核心 `执行指定需求字段询问核心`（`业务/字段询问.本能运行服务.cpp:136`）：在 `:177` 生成文字，在 `:201-203` 建立输出动作（动作来源依次取执行实例 X、直接调用身份、自建直接调用身份），在 `:206` 入列。模拟世界实现了同型接口（`领域/新_模拟世界类.h:110`）。
4. **语言知识存储**：语言 owner `新_语言类` 有私有知识键组（`领域/新_语言类.cpp:917` 知识标识、`:965` 知识键），由 `初始化语言知识结构`（`.h:681`）发布。语言知识种子由 `业务/初始化.语言知识.cpp` 解析，装配时从 `初始化材料/最小语言知识种子.txt` 读入（`装配.普通应用.cpp:4355`）。
5. **出站语言场景**：自然语言世界的来源子场景由 `新_场景类::建立或取得来源子场景(根, 来源)`（`领域/新_场景类.cpp:1017`）建立。来源只要求是有效节点，接收侧以接收消息为来源；出站侧目前没有调用。
6. **含义网**：规范已定义（7240 §2、7232 §2.1），代码中没有对应类型。

## 3. 含义网数据类型

新增 `领域/语言含义网.数据.h`。按 7232 §2.1 定义完整的值类型，本计划只运行其中一部分，但类型一次定全，避免后续计划改合同。

```text
含义网
  局部项组：内容项（编号唯一）
  顶层：{ 语言出现编号（输出时可空）, 表达用途, 顶层内容引用 }

内容项 = 静态单元 | 事件单元 | 内容算子 | 篇章组合
静态单元   { 主体:指称, 谓项:(特征值{FT, 值:指称|类型化值|方向|概念条件} | 概念归属{概念} | 同一指认{另一指称}), 时间?, 范围? }
事件单元   { 动作发生?{主体?, 动作概念, 对象角色组, 方式}, 状态变化?{对象, FT, 前值?, 后值或方向?, 时间?}, 关联主张?:bool }
内容算子   { 种类:否定|条件|引述|态度|量化, 角色组, 内容引用组 }
           态度角色：持有者、提出者、受请求者、询问者、受询者、态度种类、确认范围
篇章组合   { 种类:文本顺序|时间顺序|并列|转折|因果|目的|说明, 有序子项引用组 }
跨场景引用 { 种类:回应|引用, 目标语言场景, 目标项编号 }
指称       = 已绑定引用{节点, 范围概念} | 指代实例{节点或网内编号} | 疑问代词实例{网内编号, 待求类型概念} | 名称或描述 | 匿名新对象 | 明确未知
```

不变量由 `核验含义网结构` 检查：
- 局部编号唯一；
- 内容引用都能解析，且无环；
- 每个算子的角色齐全；
- 顶层只有一个；
- 疑问代词实例只出现在询问内容中。

不满足时属于逻辑错误，走工程诊断路径，不作为业务结果。

## 4. 正式表达需求通用化

`正式表达需求` 改为：

| 字段 | 说明 |
| --- | --- |
| 表达用途 | 陈述、疑问、祈使（新枚举，取代旧表达目的） |
| 表达对象 | 变体。首批只有“需求字段{需求D, 字段特征类型, 需求范围概念}”，以后按种类扩展 |
| 说话者、受话者 | 强类型引用 |
| 来源关联 | 触发需求、触发方法，以及本次动作来源（X 或直接调用身份，可空） |
| 成文参数 | 语言、交互窗口与作用域、第三方指代概念、选用指代名称关系、槽完备度。属于第三层，组织器不读取，原样传给成文 |

删除字段“含义操作”。两个转换函数随新字段改写，语义不变。

## 5. 表达组织知识

1. **结构**按 7232 §2.2：适用表达需求类型（表达用途×表达对象种类）、适用条件组、取材步骤有序组、含义网模板、缺材处理。
2. **存储**：语言 owner 新增一组知识键（定义类型、取材步骤、模板项等）。组织知识与描述结构分开存放，查重依据是规范化的完整定义。新增公开接口：
   - `初始化表达组织知识结构()`；
   - `建立或取得表达组织知识(定义)`；
   - `查询适用表达组织知识(表达需求类型)`：返回完整候选，附保护快照；
   - `读取表达组织知识(节点)`。
3. **首批取材算子**（7240 §2.3）。只登记首条知识需要的三项，每项写明输入类型、输出类型、公开读取提供者和失败映射：

| 算子 | 输入 → 输出 | 提供者 | 失败映射 |
| --- | --- | --- | --- |
| 绑定角色 | 表达需求中的具名角色 → 强类型引用 | 表达需求本身 | 缺角色→缺材 |
| 读具名字段“需求字段内容状态” | 需求D、字段FT → 当前未知/已知/不适用 | `正式信息参数读取接口::读取正式信息参数保护` | 前提已变化、范围未支持原样传出 |
| 读具名字段“需求字段值域概念” | 需求D、字段FT → 内容范围概念 | 现有 `读取正式字段询问范围` | 同上 |

4. **种子**：新增 `初始化材料/表达组织知识种子.txt`，只含一条知识“询问需求字段”：

```text
组织 询问需求字段
适用 疑问 需求字段
条件 需求字段内容状态 等于 当前未知
取材 1 绑定角色 需求D
取材 2 绑定角色 字段特征类型
取材 3 读具名字段 需求字段值域概念 需求D 字段特征类型
模板 顶层 疑问 内容 1
模板 1 态度 询问 询问者=说话者 受询者=受话者 确认范围=填项内容 内容 2
模板 2 静态 主体=取材1 谓项=特征值 FT=取材2 值=疑问代词实例 类型=取材3
缺材 必需不足
结束
```

这条知识与现有手工拼图含义等价，是朴素明确的写法（主体就是需求本身）。更自然的组织方式，例如“你希望这杯水达到多少摄氏度”对应的“询问（期望（……））”，以后经学习增加，本计划不加。

5. **初始化**：新增 `业务/初始化.表达组织知识.h/.cpp`，负责解析、预检、建立或取得、逐条读回。在 `装配.普通应用.cpp` 中，紧接语言知识初始化之后读入种子；重载时只读核验。

## 6. 组织器

新增 `业务/表达.组织.h/.cpp`：

```text
新表达结构组织结果 组织具体表达结构(const 正式表达需求&, const 新_语言类&, const 正式信息参数读取接口&, 概念读取…)
  状态：已组织 | 缺组织知识 | 多规则待选 | 缺材 | 前提已变化 | 范围未支持 | 条件不成立
  含义网、所用组织知识节点、取材材料与完整保护快照
```

步骤：
1. 按表达需求类型查询适用的组织知识，完整读取候选，逐条求值适用条件（7240 §2.3：成立、不成立、未知、技术失败）。恰好一条成立才继续。
2. 按顺序执行取材步骤，记录保护快照。
3. 按模板绑定，生成含义网，调用 `核验含义网结构`。
4. 复读保护快照；有变化则返回前提已变化。

组织器只读，不写任何节点。

   含义网是这段话意义的唯一正式承载（7231 §3）。

4. 本计划不建疑问代词实例的独立节点，它记在含义网内；建节点属于计划 3（7233 §4.1）。
