# SECONDARY-FEATURE-CALLTIME-I64-CUTOVER 二次特征调用期 I64 计算与职责迁移详细设计

日期：2026-09-08
版本：v0.1
状态：设计就绪；仅对应规划闭环 A，不是代码完成声明
当前代码核对基线：`main / f5c3d1593e6c430909f1ed5cee6f20eb62be75c9`

## 1. 目标、完成条件与明确排除

本设计只闭合“调用期 I64 计算与职责迁移”：把准确 I64 的输入绑定、已保存定义展开、本次局部 DAG、高阶复算和算法执行从 DATA 移到只读应用与算法提供者；建立不绑定具体输入的 `FT + 用途` 唯一当前 I64 比较绑定；迁移需求/任务方向消费者；让方法结构服务直接读取合法派生定义；同次物理退出被替换的 DATA 计算入口和二次特征转发门面。

完成必须同时满足：

1. 调用者可以只提交准确 F、已保存定义输出、本次局部输出三类来源，不建立绑定具体输入的派生根，也能通过当前正式比较绑定计算有序 I64；
2. 已保存合法定义仍可按固定 K 展开和复算，旧 v1 历史治理读取/退出保持可用；
3. 任一根所需输出失败时整次无成功载荷，成功返回含 G/H、K、FT、角色、I64、量化、真实阶次和可重建的完整来源 DAG；
4. 计算前后零 L1 写入，临时编号和结果不取得稳定身份、持久幂等或跨调用资格；
5. 需求与任务 DATA 不再执行方向计算，方法 DATA 不再依赖“二次特征概念材料”假门面；
6. `数据服务.二次特征类.ixx` 及所有被替换声明、实现、import、成员和调用点物理退出；DATA 不反向 import 新业务模块；
7. 主工程 Debug/Release x64 Rebuild 均编译链接成功，静态扫描证明旧入口及反向依赖为零。

本设计不做：二次关系概念 RC 的结构、形成、查重、AND、求值、名称和治理（闭环 B）；持久二次准确实例（C038）；坐标、颜色、轮廓、体素、旋转、序列或后天槽位算法；全场搜索；生产装配或主程序调用；数据库迁移；恢复旧普通应用或端到端测试。

## 2. 正式依据与事实裁决

- 1180 v0.9：正式派生输出逐项为具名 I64，任务局部结果用完即弃。
- 4150 v0.12：计算应用位于 DATA 外，结构 owner 只保存/读取定义，比较提供者只执行合法算法。
- 4151 v0.1：三来源联合、G/H、有限 DAG、完整来源、请求原子性和零持久写入。
- 4180 v0.11、4181 v0.1、4182 v0.1：`FT + 用途` 唯一当前路由、有序 I64 公式、稳定比较状态/拒绝原因和逐类型启用。
- 4241 v0.1 只作为闭环 B 边界，本设计不得新增 RC 字段或入口。
- `计划/规划/20260908_二次特征与二次关系概念实现方案_v0.1.md` 第 5、7、8 节：先交付闭环 A，并同时迁移消费者和删除旧入口。

当前源码事实：特征 DATA 同时保存定义并执行 `标量复算/比较派生特征`；二次特征 DATA 只是五入口转发；需求 DATA 直接计算，任务 DATA 间接计算，方法 DATA 仅借“概念材料”核验派生定义；没有独立比较提供者、调用期图、业务计算应用或生产构造点。

关键裁决：无预建派生根仍必须取得正式 K。调用方携带合同或私有进程表不满足 4182，因此在既有特征 definition owner 中增加“不绑定具体 F 的 I64 比较绑定”结构。它是 FT 解释/规则结构，不是二次实例、第二 owner 或计算结果持久化。旧已保存定义内嵌 K 继续作为该定义的固定历史解释；新无根路径只使用独立当前绑定，二者不混成双当前路由。

### 4.1 导出类型和值编码

### 4.2 结构操作

```cpp
struct 特征I64比较绑定建立请求 final {
    std::uint32_t 版本 = 1;
    std::uint64_t G = 0;
    L1所有者范围写入幂等身份 幂等身份;
    特征I64比较绑定定义 定义;
};

    std::uint32_t 版本 = 1;
    std::uint64_t Gread = 0, H = 0;
    特征I64比较绑定身份 身份;
};

    std::uint32_t 版本 = 1;
    std::uint64_t Gread = 0;
    特征类型身份 输入FT;
    特征I64比较用途 用途 = 特征I64比较用途::识别区分;

    std::uint32_t 版本 = 1;
    std::uint64_t G = 0;
    L1所有者范围写入幂等身份 幂等身份;
    特征I64比较绑定身份 身份;
};

    std::uint32_t 版本 = 1;
    特征I64比较绑定操作 操作 = 特征I64比较绑定操作::身份读取;
    特征I64比较绑定状态 状态 = 特征I64比较绑定状态::入口拒绝;
    std::uint64_t Gread = 0, H = 0;
    std::optional<std::uint64_t> 首次发布H;
    特征类标量发布确定性 发布确定性 = 特征类标量发布确定性::未派发;
    std::optional<特征I64比较绑定事实> 事实;
    std::optional<L1所有者范围写入结果> 正式回执;
    bool 成功() const noexcept;

特征I64比较绑定结果 建立I64比较绑定(const 特征I64比较绑定建立请求&);
特征I64比较绑定结果 读取I64比较绑定(const 特征I64比较绑定读取请求&) const;
特征I64比较绑定结果 读取当前I64比较绑定(const 特征I64当前比较绑定读取请求&) const;

```

建立以 `输入FT + 用途` 为规范唯一键。输入 FT 及每项输出 FT 都必须在请求 G 前已经正式成立且能由特征 owner 读回为完整活动类型；建立只引用这些 FT，不创建、改写或退出任何 FT。同键同定义（包括逐项输出 FT 身份）收敛为精确重复，同键异定义为注册不唯一/幂等冲突。普通计算不得调用建立。退出前由 L1 引用闭包保护仍被派生定义引用的 K；输出 FT 作为外部正式类型不属于绑定退出集合。未知发布保留原幂等请求，沿原 owner 收敛。绑定读取按 H，当前路由读取固定 H=Gread；缓存不能成为权威。

`成功()`分支固定：`操作=身份读取/当前读取`要求`状态=已读取、0<H<=Gread、事实于H完整活动、无首次发布H/正式回执`；`操作=建立`且状态为`已创建/精确重复`要求`首次发布H>请求G、事实创建G=首次发布H、无退出G、确认已发布且正式回执匹配`；`操作=退出`且状态为`已退出/精确重复`要求`事实退出G=首次发布H`并回显完整退出前定义；操作与状态不配对或其它状态一律无事实成功载荷。结果显式保存操作种类，成员`成功()`不得依赖已离开作用域的原请求或仅凭生命周期猜测。

物理承载固定追加到特征 definition 分区，不改变 information 分区：初始化登记 `I64比较绑定输入FT关系`、`I64比较绑定输出FT关系`、`I64比较绑定U64属性`、`I64比较绑定I64属性` 四个新结构身份；只有绑定节点用既有 `定义归属` 指向 definition 锚点。绑定到输入 FT 的关系角色固定 1，绑定到输出 FT 的关系角色固定为结果角色 1/2/3；关系只是引用，不取得输出 FT 的所有权。按 `输入FT+用途` 查询时，从输入 FT 的入向 `I64比较绑定输入FT关系` 召回，在同 H 增量解析活动绑定并筛选用途；任何候选追加前检查`最大候选数量`，任何节点/关系/值追加前检查`最大读取材料数`，任一非零上限不足均返回`数量预算不足`且不暴露候选。零个为未找到，超过一个为注册不唯一，禁止按编码任选。

确定序列化如下，所有枚举先转无符号整数，未知值拒绝：

```text
U64 = [格式1, 用途, 算法族, 算法版本, 左角色, 右角色, 上下文要求位,
       输入单位, 输入维度, 输入分量角色, 输入缩放分子, 输入缩放分母,
       输入量纲类别, 输入舍入, 输入溢出, 误差合同版本,
       误差预算存在位, 相等容差存在位, 关系编码存在位, 输出数N,
       对每个升序输出重复:
       结果角色, 单位, 维度, 分量角色, 缩放分子, 缩放分母,
       量纲类别, 舍入, 溢出]

I64 = [输入下界, 输入上界, 误差预算值或0, 相等容差值或0,
       左小于码或0, 等价码或0, 左大于码或0,
       对每个升序输出重复: 输出下界, 输出上界]
```

U64长度必须为`20+9*N`，I64长度必须为`7+2*N`，N为1—3且输出角色位集非零。存在位为0时对应I64槽必须为0，存在位为1时才按真实0解释；关系存在位与关系输出位完全一致。写集本地键固定：绑定节点1、U64值2、I64值3、输入FT关系4、绑定归属5；每个结果角色r只使用输出关系`0x200+r`。绑定写集因此只创建一个绑定节点、两个属性值、一个输入关系、一个归属关系和 N 个输出关系；输入/输出 FT 均为写集外已成立事实。退出集合精确包含这些绑定自有事实，不含输入或输出 FT；任何额外/缺失/重复或生命周期不一致均为内部不一致，外部入边由L1原子引用保护裁决。

现有派生定义 v2 的建立/读取/退出以及旧 v1 治理读取/退出保持原物理格式和公开身份。新绑定不改写存量定义；定义内嵌注册只供该显式定义展开，不能被无根路径按 FT+用途召回。`特征类数据服务::比较派生特征`及只为该入口服务的计算 DTO/helper 删除；结构读取 helper 保留，建立准入不再复算实际值，只核验定义、K、来源、输出和阶次结构。

## 5. 比较提供者 ABI

预算计数：每个本次局部项和每个去重后的已保存定义都计一个图项；每个计算节点固定两个直接输入，因此计两条来源边；基础 F 身份全局去重后计叶；每次真实公开读取返回的定义节点、关系、值、叶和绑定逐项计读取材料，同次缓存命中不重复读也不重复计材料；从根到基础叶每条使用路径计深度；实际对外所需根输出计结果。所有计数在分配/读取前检查加法溢出并扣除，0 不表示无限；不能事后用去重抹掉已经发生的真实读取。

执行固定为：请求形状与上下文位校验 → 从根反向展开三类来源 → 增量预算及悬空/环检查 → 按 H 读取准确 F 和保存定义 → 按 G 读取当前 K 并核对保存定义固定 K → 拓扑执行 → 真实阶次=`max(直接特征输入阶次)+1` → 组装全部根输出与可重建 DAG → 返回前读取当前 G 并等值守卫。每个递归展开的已保存定义都以`二次已保存定义节点身份`形成一项独立`二次计算项回执`，每个本次项以`二次本次节点身份`形成一项；所有输入来源必须能定位到同包基础叶或另一计算项输出。共享子图同次只读取、计算和回执一次，但每条路径深度都检查。成功谓词要求所有根输出逐项可定位、根来源能沿计算项输入递归到完整基础叶、全部引用闭合、输出位和类型等于 K、基础叶完整且 G/H 一致；非成功清空 `根输出组/基础叶组/计算项组/结果组`，只保留请求身份、G/H和状态诊断。

已保存定义来源通过 `特征类数据服务::读取标量派生定义` 递归展开；同次定义缓存按“定义身份+H”去重，输出在缓存内按角色选择。该读取结果必须新增`完整定义组`和`用量`：`完整定义组`按定义身份升序回显根及全部递归定义事实；`用量={定义数,关系数,叶数,属性值数,最大深度,材料总数}`，其中材料总数精确等于前四项之和，且等于本次 DATA 读取实际扣除量。`特征类派生读取预算`相应新增非零`最大材料总数`，DATA 的读取上下文在每次追加节点、关系、叶或属性值前同时扣除分类额度和材料总额度，不能先分配后检查；`成功()`还要求完整定义组闭合、唯一、包含根定义且各计数与用量一致。v2 定义的内嵌合同规范化为只读 K 回执，绝不登记到新当前绑定索引，也不改写历史。静态一次特征集合、裸 I64、裸节点号、跨调用旧局部输出和调用方自报阶次均拒绝。

规范化快照规则固定：独立绑定逐字段复制并令`来源=当前独立绑定、Gread=H=G`；保存定义令`来源=已保存定义固定K、K=定义.注册身份、Gread=G、H=请求H`，用途只允许把旧`目标判断`映射为新`目标判断/当前事实-目标值`，把旧`状态迁移`映射为新`变化分析/旧状态-新状态`，其它值拒绝；输入FT从两侧完整来源读回且必须相同，输出逐项复制定义中的输出FT和量化。对每个保存定义还必须按该输入 FT 和映射用途在 G 读取唯一当前独立绑定：未找到映射`未注册`，多项或失效映射`事实冲突`；固定 K 与当前绑定逐字段比较算法族/版本、左右角色、上下文要求、输入量化、误差合同/预算/容差、关系编码以及按角色排序的输出 FT/量化。两者身份编码可以不同，除此之外任何字段不同（尤其输出 FT 不同）均为`固定规则不兼容`，不得替换固定 K 后复算。兼容时仍以保存定义固定 K 执行和回执；provider 不支持其算法族/版本映射`算法未实现`。

调用期预算到 DATA 读取预算的换算是机械的。每次尚未缓存的保存定义读取前，以当前剩余额度形成：`最大定义数=min(剩余图项数,剩余读取材料数)`、`最大关系数=剩余读取材料数`、`最大叶数=min(剩余基础叶数,剩余读取材料数)`、`最大属性值数=剩余读取材料数`、`最大深度=剩余展开深度`、`最大材料总数=剩余读取材料数`；任一为零立即预算不足。读取成功后按其`用量`逐维扣减，并把返回完整定义组中的每个定义计入图项、每个定义的两个直接来源计入来源边、基础 F 全局首次出现计叶；任何维度超额或算术溢出均为预算不足。每次当前绑定读取把`最大候选数量`和`最大读取材料数`都设为当时`剩余读取材料数`；返回`数量预算不足`映射二次计算`预算不足`，读取产生的候选关系和解析材料按真实数量扣减。准确 F 读取也必须以其公开 DTO 实际返回的节点、关系、属性值逐项在读取前受剩余材料上限约束、读取后按真实用量扣减；不得使用固定常数或隐藏读取绕过六维预算。

```cpp
    稳定编码 目标宿主{};
    特征信息身份 当前F, 目标F;
    特征类定义身份 方向定义;
    std::optional<二次准确计算结果> 计算;
    bool 成功() const noexcept;
};
```

应用保持当前结构语义：需求记录中的目标宿主、静态目标 F 和方向定义仍必填；读取宿主、当前采用和完整定义，证明当前 F 位于定义左来源闭包、目标 F 位于右来源闭包，全部基础叶属于目标宿主，再以“已保存定义输出来源”构造一个根计算。它不以局部图替代方向定义，不修改记录。旧 v1 治理定义只能被结构治理读取，不能形成可执行计算成功。

### 7.2 任务方向

```cpp
inline constexpr std::uint32_t 任务目标方向合同版本 = 1;
enum class 任务目标方向状态 : std::uint8_t {
    已计算=1, 入口拒绝=2, 任务未找到=3, 任务已退出=4,
    来源需求未找到=5, 来源需求已退出=6, 来源不匹配=7,
    需求方向失败=8, 事实代次漂移=9, 预算不足=10,
    资源失败=11, 内部不一致=12
};
struct 任务目标方向请求 final {
    std::uint32_t 版本 = 1;
    std::uint64_t G = 0, 请求身份 = 0;
    任务类记录身份 任务;
    特征信息身份 当前F;
    std::uint8_t 要求结果位 = 0;
    二次计算预算 预算;
};
struct 任务目标方向结果 final {
    std::uint32_t 版本 = 1;
    任务目标方向状态 状态 = 任务目标方向状态::入口拒绝;
    std::uint64_t G = 0;
    任务类记录身份 任务;
    稳定编码 所属存在{};
    需求类记录身份 来源需求;
    稳定编码 来源需求所属存在{};
    std::optional<需求目标方向结果> 方向;
    bool 成功() const noexcept;
};
```

任务应用完整读取任务记录和来源需求关系，再委托需求方向应用；回读任务与需求的身份、所属存在、G、当前 F、方向定义和根结果。它不复制来源展开或算法。需求失败映射为 `需求方向失败`并保留其结构化子结果；只有子结果成功且全部互证时成功。

任务应用的状态映射固定如下：任务记录读取`已读取`继续；`入口拒绝/未找到/所属存在未找到/所属存在已退出/来源需求未找到/来源需求不属于存在/来源需求不可用/数量预算不足/事实代次漂移/资源失败/内部不一致`依次映射`入口拒绝/任务未找到/来源不匹配/来源不匹配/来源需求未找到/来源不匹配/来源需求已退出/预算不足/事实代次漂移/资源失败/内部不一致`。来源需求单独读取的`未找到`映射`来源需求未找到`，已退出或历史不可用映射`来源需求已退出`，身份/所属存在不一致映射`来源不匹配`；其它未列或写入专用状态映射`内部不一致`。调用需求方向应用后，子结果`事实代次漂移/预算不足/资源失败`提升为任务同名状态，其它非成功统一为`需求方向失败`；所有这些分支都必须保留完整`方向`子结果，调用前失败则`方向`为空。

`任务目标方向结果::成功()`逐字段要求：状态为`已计算`、版本正确、G 非零，任务/所属存在/来源需求/来源需求所属存在均有效且两个存在身份相等，`方向`存在且成功，方向的 G、需求身份分别等于任务结果的 G、来源需求，并且子结果当前 F 等于请求当前 F；任一条件不满足均非成功。任一应用失败都不得留下可被消费的顶层成功载荷；结构化失败子结果只用于诊断，不能作为方向值继续使用。

## 9. 工程、异常和并发

主工程新增四个模块并删除二次特征 DATA 模块；顺序为：特征值 → 特征 → 有序 I64 比较 → 二次计算 → 方法/需求/任务 DATA → 需求方向应用 → 任务方向应用 → 其它业务模块。`.vcxproj` 与 `.filters` 必须一致。

绑定写入继续使用特征 definition owner 的 mutex、pending、幂等读回和 L1 原子写集；不得另设 mutex 保护一份第二表。只读计算每次调用使用局部容器，不共享跨请求缓存，不持锁跨模块调用。所有公开 `noexcept` 边界映射 `bad_alloc/length_error` 为资源失败，其它异常为内部不一致；成功载荷在任何失败路径统一清空。
