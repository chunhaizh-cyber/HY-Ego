## 1. 总原则（已确认方向）

1. **纯读取缺口不写词条**不变。`读取缺口`（及等价只读入口）禁止建立／取得词条、禁止建 D／T、禁止把未登记原文伪装成归类目标，也禁止在只读缺口内执行分词写入。
2. **由本具名叶承接**：在读取缺口**之外**处理未登记片段，不另建同目标重复叶。
3. **未登记与边界未定分开**。无词条身份只表示当前未登记，不证明该范围恰为一个词。全部未知的范围（含单字未知，用户11-03确认）须先经分词本能形成分词候选；任意候选都须经词边界与规范化准入，不能过滤空白／标点后就自动成为词条。
4. **分词立为本能方法函数「语言片段分词」**（用户11-03确认，命名按建议），规格见§4；不得为凑方法头虚构被改变的特征。候选可重算，不取得语素／词性持久身份。
5. 建／取得词条成功并正式读回后，**重新分词／解释并读取缺口**，不能沿用登记前的解释依据。只有本次用法确为待归类内容词且名称关系不足时，才形成正式词条归类目标；其后仍走 LANGUAGE-LEMMA-CLASSIFY。
6. **功能词与代词不送进归类**。代词走 LANGUAGE-PRONOUN-RESOLUTION。
7. 本叶不设独立自然语言学习模块或线程；不写自我内部世界。
8. **本文件不授权改生产代码**。

## 2. 步骤合同（缺口外）

固定顺序，不得跳步、不得并入只读缺口：

```text
A. 只读：保留固定原文、语言、来源与范围，取得已登记匹配和未覆盖范围
B. 分词候选：区分已知词面、未登记词面、边界未定；最长匹配不裁决唯一词序
C. 准入：按已知语言规则或本次明确的分界回答确认拟登记词的边界及规范化结果
   - 有多种切分或无充分边界依据 → 以原文及范围提出分界澄清；不登记，见 §6
   - 候选序列只有一套也不自动证明其边界已经确认
D. 缺口外写：对已通过C且确需复用／稳定身份的词面，通过词条owner建立或取得词条
   - 键：语言身份 + 规范化合同 + 规范化词面（2200／4240）
   - 同键取得当前词条；不同出现来源不另建身份、不覆盖原创建来源
   - 功能词／代词允许具有词条身份；不参与概念归类不等于不得登记
E. fresh 只读：正式读回词条，重新分词／解释并再次读取缺口
F. 按本次用法分流：正式构式中的功能词不归类；代词消解，未决走指代澄清
G. 普通内容词且当前名称关系不足 → 以正式词条身份提出归类目标
H. 用法或规则仍未决 → 保留来源与该类缺口，不把“尚未识别为功能词”当成内容词证明
```

禁止：

- 在 `读取缺口` 内分词写库或 `建立或取得词条`
- 仅因整段未命中、候选唯一或字级回退，就将整个范围或每个字认定为正式词条
- 无词条身份伪造归类目标
- 把分词候选写成语素／词性节点或词条字段（2200）
- 因本步为功能词／代词开归类或入概念树

### 6.1 目标定位、唯一键与来源

本种类的直接目标是取得**该次语言出现中、固定原文指定范围的有效分界结果**，不是改变现实对象、任务Vt或方法Vm的特征。读取候选／生成询问均不修改这些特征；发送产生正式对外消息；输入写回只由语言owner形成分界材料及采用关联。状态、动态和后续任务治理仍由各原owner按实际事实维护，不为可召回性虚构FT或条件—结果事实。

目标逻辑结构如下；这是待实现合同，字段中文名不是已存在的C++声明：

```text
原文范围分界目标
  种类 = 原文范围分界澄清
  来源出现定位 = 接收消息M + 原理解根范围 + 根出现路径
  固定文本材料引用
  待澄清范围 = [起始标量, 结束标量)

完整目标键 = 种类 + 来源出现定位 + 固定文本材料引用 + 待澄清范围
```

1. 本叶网页链优先复用现有 `新接收认知来源键` 的M、原文根范围和根出现路径定位原出现，不以正文相同、材料哈希相同或相同数组位置判同。固定材料必须与M的正式正文材料及接收／原理解来源互证，待澄清范围非空且包含于原理解根范围；单位沿7230为Unicode标量，半开区间。原始字节位置只作对齐，不能代替本范围。来源键本身不含U；使用它的具体查询是否仍依赖U，不能由结构声明推断。
2. 语言选择从该来源正式读回并保持一致；未知／混合语言按原合同保留，不造汉语身份。进入词条准入时必须已具备所需正式语言和规范化合同。自然语言场景、说话者／受话者、现实窗口及会话是相容性和执行来源，不用场景身份替代原文出现。
3. 同一固定文本材料被两个M复用，或同一M中不同根范围／出现路径复用，目标不同；同一出现中两个范围也不同。非网页出现须有语言owner的正式句／出现定位，不得降为仅按共享材料和范围复用；该入口不由本版新增。
4. 采用含义U、解析结果和候选序列不进入目标键：重解析不能因新U／新解析身份重建同一个分界目标。它们作为本次判断依据和接续材料显式关联；旧固定解析保留，不覆盖改义。原理解工作、信息父D／T和原待完善被认知D由来源关联持有，不能由目标键反猜。
5. 目标列表按完整目标键查重；同目标、同父、同来源重复提议复用既有子D／T。不同父或来源仍遵守3100需求节点规则，列表相同不代替各自需求身份。种类与普通值／方向、词条归类分键；不把文本材料编码填入目标存在或目标词条槽。

来源定位不要求先有完整含义U、正式词条或被认知D：未知可能发生在完整含义图形成之前。此时先经正式接收记录和语言固定材料取得该输入的出现／整体范围；根出现路径只复用已经正式确立的定位，不凭候选数组临造。若具体读口必须先取得U／D才能返回来源，须补齐**接收材料到前置语言出现定位**的提供者；在其形成前保留真实接收材料，不制造U、D或路径去满足下游签名。已有原工作／pendingD时必须保留其关联；尚未形成时不把这些下游对象列作来源存在的前置条件，后续治理按真实取得材料另行接续。

### 6.2 语言owner的分界结果与依据

沿1100／7230，分界结果及其解析／来源关联属于**既有语言owner**。不另建分词owner或学习线程；语言场景只提供关联和组织，句子已有范围关系只作来源，均不自动成为普通目标存在＋FT。

正式分界材料至少保存：自身语言材料身份、完整目标定位、固定原文引用、有序分界项及来源依据。分界项保存原文标量子范围和本次用途（拟登记词面／分隔材料）；范围在目标范围内、严格有序、不重叠，合起来完整覆盖本次目标范围，不能默删未覆盖字符。标点、空白是否为分隔须有规则或明确回答依据，不能只调用去末标点就宣布完成。只有部分范围有依据时保留部分材料，不报告整个目标有效。

**先于词条的分界项不是7230的「已确认词出现」。** 它尚无正式词条引用，只证明该范围边界有依据；不得填0词条、临时词条或把候选序列伪装成正式词序。词条准入并正式读回后，再形成引用真实词条的新解析／词出现，保留原分界材料与原解析。

有效依据分两路，逐路核验，不要求同时具备：

- 正式语言规则：引用实际采用的规则／知识定义与本次作用范围、必要语境，能确定该出现中的完整边界；已登记词面、词典前缀、唯一候选或最长匹配本身不是该证明。
- 本次明确分界回答：引用正式接收回答及其与本次询问的关联、回答解释和原文对齐，唯一确定目标范围的完整边界。回答只提供分界材料，不确立词义、概念名称、现实事实或原句已被理解。

语言owner保存分界材料及针对该目标的当前有效采用关联；重复提交同目标、同边界、同依据复用，异义不得覆盖已保存材料或静默替换。新的明确修正形成新的固定分界结果材料并显式更新采用，不改原文或目标键，旧结果材料保留其来源；不得自动选最新时间或最小编码。具体节点／关系布局和公开写口尚待第8节提供者合同冻结，不把本逻辑结构宣称为现有API。

### 6.3 fresh满足判定与有效／未知／歧义分流

每次筹办、执行前和父工作恢复时，经语言owner正式读口核对目标、来源出现、固定内容、范围和当前采用：

| 当前材料 | 语义裁决与动作 |
| --- | --- |
| 有且只有一个当前有效采用，完整覆盖目标范围，依据及必要语境仍适用 | 该分界目标已满足；取得正式结果，进入缺口外规范化／词条准入，不再为此范围发问 |
| 边界已由正式规则确定但尚未保存 | 缺口外经语言owner发布并正式读回；发布前不能把候选当已满足，无须先人工回答 |
| 无充分依据、未回答、回答仅部分覆盖 | 未知／不足，保留已有材料；经通用筹办提议或复用分界澄清子需求，父方法不执行 |
| 多套仍可能的边界或回答多解 | 歧义，保留各候选及来源，必要时继续同一问题的澄清，不取首、不默认逐字登记 |
| 依据的必要语境已不适用，且尚无新的有效结果 | 当前未满足；保留旧材料，重新筹办，不因旧结果曾有效而沿用 |
| 来源不对应、范围越界、结构损坏或读取／发布工程失败 | 拒绝或沿工程路径报告并中止受影响操作；不伪装未知、歧义、空候选、普通等待或需求失败 |

多个候选不等于多个当前采用。owner发现互斥的多个「当前有效采用」属于结构不一致，不能降为正常歧义让业务继续；正常歧义应在采用之前被明确保留。满足只裁决分界子目标，不证明词条已登记、归类已完成、父D完整或self已承接。

### 6.4 筹办、询问、发送和回答写回

1. 原理解工作先读取固定材料／范围与已有候选，区别未登记、边界有依据和边界未定。未登记不能直接触发人工分界；边界已有充分依据走6.2规则发布和第5节准入。需要澄清时，由「获取服务对象需求信息」的通用筹办形成完整的本专属目标提议，交self确认；待完善被认知D本身不进入需求集合或任务链。
2. self fresh复核并确认后，经需求owner建立／复用分界子D，manager建立／复用其T；正式子D仍必须具有合法的自我治理父D和来源任务，并保留原理解工作关联。该治理父D／T不等于待完善的被认知D；后者尚不存在时不构成准入缺项。原输入工作尚未取得合法治理承接时，保留实际来源和工作，先沿既有self确认与任务承接路径取得，不建无父子D、不伪造被认知D或含义U来补签名。子任务按查找方法、采用、参数场景、执行前复核进入相应本能，不由self直接生成句子或调用本能；具体前置承接接口仍属第8节设计范围。
3. 询问函数只从本次参数场景取得子D、固定原文／范围、必要来源及实际交互材料，形成正式表达需求；语言模块按正式知识生成并回读候选。询问只请求分界，不能把“X是什么”的概念归类问句或代词消解问句改标签充数；未具备表达知识就保留实际提供者缺口，不硬编码测试问句。
4. 候选生成不入列。独立发送步骤fresh核对需求有效性、目标、候选来源和窗口，经发送裁决后先登记动作，再提交正式外设输出队列并读回；动作开始后失败保留已发生事实，不补造发送成功。重复调度复用本次正式发送身份，不能把原文／范围相同当作所有消息的全局去重键。
5. 回答关联必须明确指向本次正式询问及完整目标，核对会话／窗口、原出现、交互主体与当前工作。仅凭发送后到达、最新消息、正文相同或数组次序不够。接入协议尚不能表达该关联时，这是第8节接口缺口，不能在运行时猜答复。未答不造答复；一个回答涉及多个范围时须分别取得各自明确关联与覆盖，不隐式广播。
6. 输入解释只形成关联明确的分界回答候选；相应写回函数从参数场景取实际材料，动作前复核全部必要条件，记录自身动作，再经语言owner发布分界结果／采用并正式读回。多解或不足先筹办，不执行父方法，也不把“写入失败”存成业务结果知识。不得暗读“当前全局消息”替代参数引用。
7. 发布后读回或后续接续失败，保留已经保存的结果／动作；按原来源复用后重读，不盲目重发、重新分配词条或重建D。工程状态与业务材料分账，现有正常否定返回不能吞掉工程故障。

### 6.5 规范化、词条准入与同一原工作接续

1. 分界子D满足通知只提示其合法治理父任务重读，不替代结果；原理解工作按实际关联恢复，若尚无被认知D亦可继续。恢复方须fresh取得语言owner当前有效结果，再按每个拟登记词面的原子范围形成规范化候选。规范化合同不改变固定原文或原范围：若产生另一词面值，须保留对齐与合同；不能在删空格、大小写／Unicode变换后的文本继续使用旧坐标。本叶现有可复用合同是严格UTF8字节精确，不暗增其它规范化算法。
2. 缺口外准入编排复用原 `新_词类::建立或取得词条`、`获取词条`、`按规范化词面查询`。同语言＋合同＋规范词面复用一身份，不覆盖原创建来源；本次每个出现的范围、顺序和分界依据另由语言owner关联，不塞入词条字段。功能词／代词也允许登记；尚未确定用法不能默认内容词。
3. 正式读回后，重新分词／解释并读取缺口，使用新解析材料关联**原M、原出现与原理解工作**；已有原待完善被认知D时保持同一D，尚无D时继续原输入工作，按正式内容形成合同在后续材料具备时建立D，不为接续伪造前置D。不把回答当新服务请求重开原需求，不用新U重建同一D，不把分界子D与原被认知D混同。新U／解析是新的理解材料，旧U不覆盖改义；采用与接续须有明确来源关联，不能借同一源键冲突就另造M或D规避。
4. 仅本次用法明确为内容词且fresh名称关系不足才提词条归类子需求；功能词走相应构式，代词走指代消解／澄清，规则或用法未定保留其缺口。分界满足不能直接把原D标为完整或确认，更不能自动令self承接建服务T。
5. 已有原D最终仍由原正式内容写回／确认合同完善；此前无D时按同一原输入的正式内容形成合同处理，不跳过确认。原工作继续重读并按既有资格交self治理。实际API若尚不能在保持已有原D的同时接续新解析，须补齐该提供者，不允许通过重建原D假闭环；已有原D已失活或原工作被撤销时停止推进并保留已保存语言事实，不重开任务。
6. 各步骤只按当前必要语义读回、结构owner单调用校验和具名发布前提处理；不恢复整组旧快照保护、事实代次或把旧快照全等当跨步骤正确性证明。读回与实际发布需共同成立的最小范围须在后续提供者API中明确，不由业务层拼接旧保护快照冒充原子事务。

### 6.6 本次用法分流与未知保留

功能词依据正式构式的固定词项及本次位置；代词依据正式指代定义、作用域和本次用法。功能词与代词均可具有词条身份，但不因此建立概念归类需求；代词未决走原指代澄清。量词、数词具有正式词条身份且当前名称关系不足时，与普通内容词同样进入归类（用户11-03确认）。尚未证明属于哪个分支时保留该类缺口，不把没有功能词／代词标记当作普通内容词的肯定依据；不新增持久词性字段或字符串黑名单。
