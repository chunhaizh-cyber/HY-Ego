# 未登记片段建立或取得词条详细设计

身份：`LANGUAGE-LEMMA-CREATE-FROM-FRAGMENT`（**建议名，待用户拍板**）。版本：v0.1。日期：2026-11-03（Asia/Shanghai）。

性质：经用户（经 claude管理员）同意「另起具名叶」方向的规范施工包。**只修订规范与详细设计，本文件不授权改生产代码**。与已合并的词条归类目标合同（LANGUAGE-LEMMA-CLASSIFY）及代词指代消解（LANGUAGE-PRONOUN-RESOLUTION）主题相邻但**步骤独立**：本叶只闭合「未登记最长匹配片段 → 正式词条身份」；归类询问／写回仍归 LEMMA-CLASSIFY；代词／功能词仍不进归类。

证据锚点（只读，不改代码）：PR #11 分支验证记录《20261103_ASK-BACK-SPEC10_实际入口验证与发布记录》§语言筹办等待材料根因；实跑 `run-20261103-062528` 站点原文「终态空目标且有未登记原文…片段数=3；rawUnknown=1」→ `读取缺口` 返回等待材料，反问发不出去。根因是归类目标槽必须是正式词条，而未登记片段尚无词条身份；接口约定「纯读取缺口不建D/T、不写词条」禁止在只读缺口内建词条。

权威依据：[2200](../2200_根规范_词_20260720.md)、[4240](../4240_子规范_语言词条与概念空间纯结构统一合同.md)、[5170](../5170_子规范_需求治理详细合同.md)、[7250](../7250_子规范_最小汉语知识与语言学习.md)、[LANGUAGE-LEMMA-CLASSIFY](20261102_LANGUAGE-LEMMA-CLASSIFY_词条归类学习与本能详细设计_v0.1.md)、[LANGUAGE-PRONOUN-RESOLUTION](20261102_LANGUAGE-PRONOUN-RESOLUTION_代词指代消解与澄清详细设计_v0.1.md)、[LANGUAGE-MODULE-CONVERSATION](20261102_LANGUAGE-MODULE-CONVERSATION_自然语言模块交谈场景详细设计_v0.5.md)、[DATA-L2-LANGUAGE-LEXEME-SERVICE-CLOSURE](20260816_DATA-L2-LANGUAGE-LEXEME-SERVICE-CLOSURE_词条公开服务闭合详细设计_v0.1.md)。

## 1. 总原则（已确认方向）

1. **纯读取缺口不写词条**不变。`读取缺口`（及等价只读入口）禁止建立／取得词条、禁止建 D／T、禁止把未登记原文伪装成归类目标。
2. **须另起本具名叶**：在读取缺口**之外**增加一步——对最长匹配得到的**未登记片段**，经词条公开服务 **建立或取得词条**（同键幂等读回），得到正式词条身份。
3. 建／取得成功后，**重新调用读取缺口**（或等价 fresh 只读路径），以正式词条形成 **词条归类** 目标；其后归类子需求／询问／写回仍走 LANGUAGE-LEMMA-CLASSIFY，本叶不改归类目标形状与求值合同。
4. **功能词与代词不送进归类**：即使为其建立了合法词条（功能词本就可有词条），也不得因本步而提出归类子需求，不得挂入概念树。代词仍走 LANGUAGE-PRONOUN-RESOLUTION。
5. 本叶不设独立自然语言学习模块或线程；不写自我内部世界；不授权在缺口只读路径内旁路写词条。
6. **本文件不授权改生产代码**；施工须按本叶另开代码分支。

## 2. 步骤合同（缺口外）

固定顺序，不得跳步、不得把 2～3 并入只读缺口：

```text
A. 只读：最长匹配 → 片段组（已有词条节点 / 未登记原文）
B. 过滤：剔除空片段、纯标点；标记功能词候选、代词用法（见 §5）
C. 缺口外写：对「未登记且非功能词、非代词」的片段，逐条调用词条公开服务「建立或取得词条」
   - 键：语言身份 + 规范化合同 + 规范化词面（2200／4240）
   - 同键同内容 → 幂等读回已有词条；同键异内容 → 幂等冲突／内部不一致，不得静默覆盖
D. fresh 只读：再次读取缺口（或等价只读重算）
E. 形成归类目标：仅对「已有正式词条 ∧ 非功能词 ∧ 非代词 ∧ 尚无使确定值成立的名称关系」提出词条归类目标／子需求（LEMMA-CLASSIFY）
F. 功能词／代词：不进入 E；代词未决走指代澄清；功能词只保留结构作用
```

禁止：

- 在 `读取缺口` 实现内直接 `建立或取得词条`
- 无词条身份时伪造归类目标或把原文字符串塞进目标槽
- 把多个无关未登记片段捆成一条词条或一条归类需求
- 因本步为功能词／代词建立归类子需求或写入概念树

## 3. 接口约定（语言补全／等价运行面）

下列约定为规范权威；实现头文件注释须与之对齐，冲突时改实现或另起规范修订，不得用代码现状覆盖。

| 入口 | 允许 | 禁止 |
| --- | --- | --- |
| **纯读取缺口**（如 `读取缺口`） | 只读来源中的正式词条与指代实例；报告等待材料／已有目标 | 建 D／T；写词条；把未登记原文写成归类目标 |
| **缺口外建词条步骤**（本叶） | 对过滤后的未登记片段调用词条 owner「建立或取得词条」；成功后触发 fresh 再读缺口 | 冒充仍是「纯读取」；跳过幂等键；为功能词／代词开归类 |
| **询问／发送／回答写回** | 仍只消费已形成的正式目标（词条归类或指代澄清） | 在询问路径内临时造词条冒充目标已齐 |

说明：当前 ask-back 实现头注释「纯读取缺口不建D/T、不写词条；目标只来自原来源中的正式词条或指代实例」**保留**；本叶只追加「缺口外建词条 → 再读缺口」步骤，不放宽只读入口。

## 4. 新建词条的初始状态（建议，待拍板）

建议默认（与 2200／4240／功能词种子口径一致）：

1. 成功建立或幂等取得后，词条为**当前合法词条身份**：具备语言、规范化合同、规范化词面；**不**自动建立概念、**不**自动建立概念名称关系、**不**写入自我内部世界。
2. 无名称关系时，父方法「确定值」仍不成立 → 由 LEMMA-CLASSIFY 提归类子需求（非功能词／非代词）。
3. 不引入「半词条／临时词条」第二身份；候选分词材料不得冒充词条（2200）。

待拍板：是否需要显式「待归类」标记字段，或仅以「无当前名称关系」隐含。

## 5. 功能词与代词如何识别（建议，待拍板）

硬边界已确认：**功能词不进概念树；代词不建归类子需求**。识别办法未冻结，下列为建议，冲突见 §8：

| 类别 | 建议识别 | 不得 |
| --- | --- | --- |
| 代词 | 与 1110／7250／LANGUAGE-PRONOUN-RESOLUTION 已登记代词概念／用法对齐（如我／你／他／她／它／这／那／谁／什么等）；以用法与指代合同为准，不单靠词面 | 因有名称关系就送归类 |
| 功能词 | 优先：已作为语言结构固定项／构式固定词登记的词条（种子与 7250 构式目录中的固定词）；次选：具名封闭表（须另裁） | 恢复持久词性节点族（2200 禁止）；臆造词性字段 |
| 普通内容词 | 未登记片段且非上两类 → 本叶建立或取得词条后可进归类 | 把量词／数词等争议类擅自永久划入功能词而不登记冲突 |

量词（如「杯」）、数词、专名等边界**不得自行拍板**，列入 §8 待裁决。

## 6. 去重与触发时机（建议，待拍板）

**去重**：同一语言＋规范化合同＋规范化词面只对应一个当前词条（2200）；本叶调用必须走「建立或取得」幂等读回；归类子需求仍按 LEMMA-CLASSIFY「种类+目标词条」键，同词条不平行建需求。

**触发时机（建议）**：

1. 在「获取服务对象需求信息」／语言筹办路径上，当只读最长匹配出现 **rawUnknown／未登记非空片段**，且即将或已经因空归类目标落入等待材料时，于**缺口外**执行本叶 §2 的 C，再 D→E。
2. 不得在每一次无关只读预览中批量建词条；须有明确理解／筹办来源。
3. 与「帮我…」壳解析的关系：壳匹配成功后的**剩余片段**同样适用；壳失败属另一路径（见只读 SPEAKER 核对，不在本叶范围）。

待拍板：C 步由哪一宿主执行（见 §8）——语言补全运行面缺口外写口／父方法条件分解／经任务链的新本能。
