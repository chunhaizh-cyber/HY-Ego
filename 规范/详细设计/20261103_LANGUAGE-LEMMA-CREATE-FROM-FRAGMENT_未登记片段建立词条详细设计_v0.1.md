# 未登记片段建立或取得词条详细设计

身份：`LANGUAGE-LEMMA-CREATE-FROM-FRAGMENT`（**建议名，待用户拍板**）。版本：v0.2。日期：2026-11-03（Asia/Shanghai）。

性质：经用户（经 claude管理员）同意「另起具名叶」方向的规范施工包。**只修订规范与详细设计，本文件不授权改生产代码**。与已合并的词条归类目标合同（LANGUAGE-LEMMA-CLASSIFY）及代词指代消解（LANGUAGE-PRONOUN-RESOLUTION）主题相邻但**步骤独立**：本叶闭合「未登记／全部未知片段 →（必要时分词）→ 正式词条身份」；归类询问／写回仍归 LEMMA-CLASSIFY；代词／功能词仍不进归类。

用户补充（20261103）：①「语言片段如果是全部未知，首先需要分词」——整段未知不得直接整段建一个词条；②「分词作为一个本能方法函数」。

证据锚点（只读，不改代码）：PR #11 验证记录《20261103_ASK-BACK-SPEC10_实际入口验证与发布记录》§语言筹办等待材料根因；实跑 `run-20261103-062528` 日志原文两次均为：

```text
站点=终态空目标且有未登记原文；M=18845；U=19838；目标数=0；片段数=3；rawUnknown=1
```

**日志未打印**三个片段各自的原文，也未标明哪一段触发 `rawUnknown`。只可认定：对消息正文做「按已登记词条最长匹配」得到 **3** 个片段，其中 **至少 1** 段无词条节点且去末标点后原文非空。不得臆造片段字面（例如不得把未打印内容写成「倒／杯／水」或整段「倒杯水」）。

权威依据：[2200](../2200_根规范_词_20260720.md)、[4240](../4240_子规范_语言词条与概念空间纯结构统一合同.md)、[5170](../5170_子规范_需求治理详细合同.md)、[5350](../5350_子规范_方法治理详细合同.md)、[5360](../5360_子规范_方法函数登记执行与任务反馈.md)、[7250](../7250_子规范_最小汉语知识与语言学习.md)、[8121](../8121_子规范_本能根运行初始化物理合同.md)、[LANGUAGE-LEMMA-CLASSIFY](20261102_LANGUAGE-LEMMA-CLASSIFY_词条归类学习与本能详细设计_v0.1.md)、[LANGUAGE-PRONOUN-RESOLUTION](20261102_LANGUAGE-PRONOUN-RESOLUTION_代词指代消解与澄清详细设计_v0.1.md)、[LANGUAGE-MODULE-CONVERSATION](20261102_LANGUAGE-MODULE-CONVERSATION_自然语言模块交谈场景详细设计_v0.5.md)、[DATA-L2-LANGUAGE-LEXEME-SERVICE-CLOSURE](20260816_DATA-L2-LANGUAGE-LEXEME-SERVICE-CLOSURE_词条公开服务闭合详细设计_v0.1.md)、[DEMAND-FIELD-QUESTION](20261030_DEMAND-FIELD-QUESTION_通用字段询问与本能详细设计_v0.1.md)。

## 1. 总原则（已确认方向）

1. **纯读取缺口不写词条**不变。`读取缺口`（及等价只读入口）禁止建立／取得词条、禁止建 D／T、禁止把未登记原文伪装成归类目标，也禁止在只读缺口内执行分词写入。
2. **须另起本具名叶**：在读取缺口**之外**处理未登记片段。
3. **全部未知的语言片段须先分词**，不得把整段未知原文直接建成一个词条；分词后再对分出的片段建立或取得词条，并进入归类路径（非功能词／非代词）。
4. **分词是本能方法函数**（正式名待拍板，见 §4）；经任务链「查找方法→采用→执行」召回，自我不直接调本能。分词产出为**解析候选片段**（2200），不取得词条／语素／词性持久身份。
5. 建／取得词条成功后，**重新调用读取缺口**，以正式词条形成 **词条归类** 目标；其后仍走 LANGUAGE-LEMMA-CLASSIFY。
6. **功能词与代词不送进归类**。代词走 LANGUAGE-PRONOUN-RESOLUTION。
7. 本叶不设独立自然语言学习模块或线程；不写自我内部世界。
8. **本文件不授权改生产代码**。

## 2. 步骤合同（缺口外）

固定顺序，不得跳步、不得并入只读缺口：

```text
A. 只读：按已登记词条最长匹配 → 片段组（已有词条节点 / 无词条节点的未登记原文）
B. 判定：对无词条节点且去末标点后非空的片段，判是否「全部未知」（边界待拍板，见 §8／报告）
C. 若全部未知：经任务链执行本能「分词」（§4）→ 得到有序候选子片段；不得跳过 C 直接整段建词条
D. 过滤：剔除空／纯标点；标记功能词候选、代词用法
E. 缺口外写：对「需建词条的内容片段」逐条「建立或取得词条」（是否另立本能见 §5／§8）
   - 键：语言身份 + 规范化合同 + 规范化词面（2200／4240）
   - 同键同内容 → 幂等读回；同键异内容 → 冲突，不得静默覆盖
F. fresh 只读：再次读取缺口
G. 形成归类目标：已有正式词条 ∧ 非功能词 ∧ 非代词 ∧ 尚无使确定值成立的名称关系 → LEMMA-CLASSIFY
H. 功能词／代词：不进入 G；代词未决走指代澄清
```

禁止：

- 在 `读取缺口` 内分词写库或 `建立或取得词条`
- 全部未知时整段冒充一词条
- 无词条身份伪造归类目标
- 把分词候选写成语素／词性节点或词条字段（2200）
- 因本步为功能词／代词开归类或入概念树

## 3. 接口约定（语言补全／等价运行面）

| 入口 | 允许 | 禁止 |
| --- | --- | --- |
| **纯读取缺口** | 只读正式词条与指代实例；报告等待材料／已有目标 | 建 D／T；写词条；分词持久化；未登记原文写成归类目标 |
| **缺口外：分词本能** | 对全部未知片段产出有序候选子片段 | 冒充纯读取；写词条／语素／词性；自我直调 |
| **缺口外：建／取得词条** | 对过滤后子片段幂等建／取得词条；再 fresh 读缺口 | 跳过必经分词；询问路径内临时造词条冒充目标已齐 |
| **询问／发送／写回** | 消费已形成正式目标 | 同上旁路 |

「纯读取缺口不建D/T、不写词条；目标只来自原来源中的正式词条或指代实例」**保留**。

## 4. 新本能：分词（方法函数）

用户已确认：**分词作为一个本能方法函数**。下列正式名／参数／返回为**建议，待拍板**。

### 4.1 方法头（建议）

| 项 | 建议内容 | 依据 |
| --- | --- | --- |
| 建议正式名 | **语言片段分词** | 对齐「询问词条归类」等具名本能；强调对象是片段而非整库分词器 |
| 语义 | 对一段**全部未知**的语言原文，在既定语言与规范化合同下，产出有序**候选子片段** | 2200：分词结果是解析候选，可丢弃重算 |
| 不做 | 不写词条；不建语素／词性节点；不建 D／T；不入列；不裁决归类；不猜唯一概念 | 2200 §词性／语素禁止；接口只读分账 |
| 调用路径 | 完整需求经任务「查找方法→采用→执行」；自我不直接调本能 | CONVERSATION／5350／5360 |

### 4.2 有序参数与返回（建议）

对齐 5350「有序信息类型=范围概念」、本能首次登记生成规格后不可改：

| 序 | 建议参数 | 含义 |
| --- | --- | --- |
| 1 | 语言身份 | 本次自然语言 |
| 2 | 规范化合同材料 | 与词条键一致的规范化合同 |
| 3 | 未知片段原文材料 | 全部未知片段的严格材料（非词条） |
| 4 | 调用期交互上下文（若需要） | 与字段询问分账口径一致的只读核验；若不需要则从规格删除（待裁） |

| 返回状态（建议） | 含义 |
| --- | --- |
| 已分词且唯一候选序列 | 有序子片段组可消费（仍为候选，非词条） |
| 多义／歧义 | 多套切分；**不得取首**；是否反问见 §6／§8 |
| 无法切分／输入拒绝 | 零词条写入；结构化非成功或保持等待材料 |
| 前提已变化／资源失败 | 与同族本能分账 |

直接产物：**候选子片段有序组**（词面区间／规范化候选），**不是**词条节点组，**不是**已入列消息。

### 4.3 触发条件（建议）

1. 只读最长匹配后出现「全部未知」片段（无词条节点且非空），且不得整段建词条。
2. 由「获取服务对象需求信息」／语言筹办路径在缺口外提出可执行步骤或子需求后，经任务链召回本本能。
3. 不得对已有词条节点的片段再分词冒充新切分；不得在无关只读预览中批量调用。

### 4.4 初始化注册位置（建议）

- 落在 [8121](../8121_子规范_本能根运行初始化物理合同.md) 第 3 节步骤 **8「初始化方法根和本能函数登记」**：与其它语言相关本能一并登记方法头／有序规格／函数绑定；**不**改双根物理形状，**不**把词条归类种类写入双根例外。
- 程序登记名、空登记发布头与规格的细则对齐 5360／DEMAND-FIELD-QUESTION 族；本叶不发明第二登记账。

### 4.5 分词方法与依据（须遵守现有规范）

1. **禁止**恢复持久词性、语素节点族、语素 CRUD、词条—语素组成（2200）。
2. 分词器标签／置信只作本次候选材料，绑定语言位置与解析版本；可丢弃重算。
3. DATA-L2 词条服务**不**执行分词算法（2200／词条公开服务闭合）；分词在本能／语言侧完成后再把需登记的规范化词面交给词条服务。
4. 具体切分算法（词典最长／字级回退／其它）**待拍板**；在选定前不得宣称唯一算法已冻。

## 5. 「建立或取得词条」与分词本能的关系

| 步骤 | 是否本能（建议） | 说明 |
| --- | --- | --- |
| 分词 | **是**（用户已确认） | §4 |
| 建立或取得词条 | **建议另立本能**「未登记片段建立或取得词条」，内部只调词条 owner 幂等入口；或薄封装同一任务链步骤 | 待拍板。若只直调 owner 而不立本能，须说明如何满足「自我不直调／经任务链」与缺口外分账 |
| 再读缺口／提归类 | 否（只读＋LEMMA-CLASSIFY） | 不改归类本能名 |

建议先后：**分词本能成功（或判定无需分词）→ 建／取得词条 → fresh 读缺口 → 归类**。禁止建词条先于必经分词。

## 6. 分不出来或有歧义（建议，待拍板）

1. **多义**：不得静默取首套切分；建议经通用筹办提**完整补问／澄清子需求**（问句形状待裁，例如请用户确认切分或改述），与字段补问／归类／指代澄清同级；或保持等待材料直至另有方法。
2. **无法切分**：零词条写入；返回结构化非成功或等待材料；不得整段强建一词条绕过。
3. 是否复用「询问词条归类」话术：**不建议**——分词未完成时还没有正式词条目标。
