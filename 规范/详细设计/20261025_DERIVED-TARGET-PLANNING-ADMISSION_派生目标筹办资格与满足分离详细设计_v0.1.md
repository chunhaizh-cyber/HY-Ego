## 1. 目标、依据与边界

用户确认：合法派生目标尚无本次准确计算结果时，允许先筹办；已有真实来源足够则及时计算，满足与否仍由真实事实及有效计算裁决，不伪造零、实际特征或成功。筹办资格不是方法条件齐备、执行许可、需求满足或任务完成。

本次修改的是需求/任务治理的只读判断和任务筹办状态推进，不修改现实目标值；原因是当前“先有达成后的派生结果才能筹办”形成循环；目的是让合法目标进入方法查找、空配对学习和真实条件分解。不是新增或修改本能函数，不能据此生成动作、世界状态/动态或方法条件结果对。

正式依据为 [1180](../1180_根规范_二次特征_20260720.md) 第2—6节、[3100](../3100_根规范_需求.md) 第5—6节、[0050](../0050_项目通用机器逻辑与禁止性规则总纲_20260721.md)。3100“所有值目标必须定位持久F后才能筹办”的外推由本窗口上述具名裁决替代；其普通值目标满足判断、方向目标执行前后比较、根需求及完成门不因此变化。不修改正式规范正文，不将局部裁决扩为所有缺F/缺值均可放行。

首个真实消费目标是“自我/服务任务数量变化量/新增服务任务域”，其算法为正式的“服务任务来源新增数”，不是服务任务集合总数差，也不是以本次缺结果推断新增为零。通用准入不按该词面、登记名或FT编码分支；只有任务已有的显式服务需求取得合同负责本轮已支持的执行来源解释，其他算法不增造输入绑定器。

## 4. 需求资格判定

1. 在既有需求owner锁纪律下完整读D及治理信息：不存在返回需求不存在，信息未完善返回需求待完善，非自我执行域返回目标定义不合法，非活动返回需求非活动；被认知需求不取得任务筹办资格。
2. 检查目标存在真实有效、唯一目标形式及完整载荷、目标FT根、目标域属于同一FT、单位/物理材料及比较关系适用。复用现owner目标合法性helper，不复制一份不同规则。
3. 用二次概念owner正式身份分类区分普通FT与派生FT，不能凭名称/数值范围猜测。非本提供者是普通路径；依赖未就绪映射结构不一致、前提变化映射材料已变化，不当成普通FT。正式派生类型取得完整派生定义保护，核同目标根、输出合同、非空连续有序输入定义、正式算法及引用的概念身份。未知/坏目标定义返回目标定义不合法；已识别合法结构损坏返回结构不一致；资源失败返回资源失败。原owner的工程异常终止链继续有效，不能把原始工程读取失败改成“材料待到”。
4. 读取原 `复核当前满足(D)`。已满足则目标已满足；普通值目标/方向目标仍按旧四种可继续状态准入，普通F或当前值缺失仍等待普通材料；其它错误原样分流。
5. 对非根、正式派生值目标，若完整定义及目标合同合法，当前状态仅为 `目标特征尚未形成` 或 `当前值不存在`，返回允许筹办，同时保留原状态、空准确差异和无实际派生F。此处只要求输入**定义**合法，不要求未来执行后的输入值或本次结果已经存在。真实执行输入是否具备仍由条件筹办/执行入口处理。
6. 不把所有“值缺失”状态统称派生待算；根需求不走此例外，普通缺特征仍等待；结构冲突/读取故障/不合法比较不允许。
7. 返回前fresh核同本次D、目标身份和定义保护。前提变化返回材料已变化，不自旋、不返回局部成功；原owner工程异常路径仍保留，不吞异常后正常允许。

不新增长锁或改变owner锁序。复用既有只读helper和完整保护，外部回调/线程调用不在需求锁内执行；不在底层DATA判断筹办资格。

## 5. 任务组合与真实结果

`复核任务筹办资格(T)`在task原锁序中核T存在、T-D唯一关联和活动目标，调用需求资格提供者。不存在T/坏关联不能借D合法而放行。现有错误分类映射为资格的结构不一致/资源失败/材料已变化。

任务当前满足的唯一改动是退出 `复核任务需求` 中未执行时的伪值：

- 无最近X，或已有X但正式来源读回为状态材料不足：返回需求owner原始当前满足结果；不填集合F为派生F、不填0、不填差异1，不宣称已满足或需增加。
- 已有X且原显式服务需求取得合同适用：立即复用 `读回服务需求取得结果(T,X)`；不得在无X时调用它再把缺材料折成0。
- `已找到`且有准确来源新增数时，0可以作为本次真实计算的0，映射未满足但无有向差值；本轮原支持结果1并且正式状态见证非空时才保留已满足。准确差异只来自真实目标边界与准确结果计算，不从“尚未发生”推定。
- 计算成功但尚缺原完成所需见证时不能已满足；保留未知/待材料，不把资格当完成。结构不一致、资源失败和来源身份冲突原样阻断，不降格为合法待算。
- 不在上述结果的 `实际特征节点`中保存服务任务集合F；它是执行计算来源，不是“数量变化量”的持久F。已有来源及状态见证仍由原结果DTO保存。

任务资格可携本次真实结果更新后的 `当前满足`，目标已满足优先，不重新筹办。此组合只支持现有显式取得来源合同；其他合法派生目标可进入筹办，但仍须找到可用方法/来源，不能伪造通用算法输入或承诺可执行。

已有X已经发出动作但本次结果仍未知时，保留原等待同次结果及不得盲目重做的保护；D定义合法只说明目标可被理解，不能让task组合或self决议允许重放该动作。初次无X与动作后未知结果不是同一种“缺本次结果”。

## 6. 等待及学习交接：三道门同步

| 位置 | 冻结行为 |
| --- | --- |
| self等待复核、学习完成复核 | 先核原定位、活动/终态及执行是否仍在进行，再读task资格。允许筹办才在决议携完整资格；当前满足状态保持真实缺结果状态。已满足/普通缺材料/错误仍各走旧路径。 |
| manager `提交等待复核决议`、`提交学习复核决议` | 不再仅接受四种当前状态作为允许依据。所有允许决议必须携资格，锁外fresh读取task资格；需求、完整目标、派生定义、当前结果与消息全值核同且fresh仍允许，才在原manager锁内核复核编号、定位和占用后保存。不得持manager锁调用领域owner。 |
| task `准备等待任务重新筹办`、`准备学习后重新筹办` | 原任务定位、活动性、无执行中X、学习方法关联和终态门保留；fresh核独立资格后只迁移到待查找方法。无结果不再是派生目标的阻断，但不设置待执行/已完成。 |

manager先按原记录核精确重复：已存完全相同决议返回精确重复，不因后来目标变化而重做旧提交。首次允许提交的领域fresh读取在锁外完成，再入锁重核同一记录未终结及定位未变化；读取期间记录变化返回原定位已变化。fresh目标/定义/结果与消息不同不能冒充定位变化，其重算交接严格按下节；资源失败仍按原交接重试同一决定，结构错误进入工程核查。task是最终fresh门，manager快照不取代它。

### 6.1 v0.2执行退回：材料变化与定位变化分别收口

来源：root在main `bf3c735c50dd316b6eccc306f96e5775c83ce936`执行本计划时正式退回。当前manager等待推进约1279处只选“未反馈或已有决议”的记录，学习约2948处已反馈则返回；self缓存 `项.等待决议`/`项.学习决议`，收到定位已变化会结束本条消息。因此v0.1所谓“返回定位已变化后由现有机制重新产生”并不存在，可能使manager已反馈但永远收不到决议。该问题是本计划交接设计缺口，不是新增业务语义。

两个manager提交口同步冻结以下优先级：

1. 保留入口合法性、原记录不存在/已终结/占用释放/复核编号或定位不符的真正定位变化及身份冲突判断。已保存完全相同决议返回精确重复，已存异义返回身份冲突，不因fresh读取改变旧提交结果。
2. 只有尚未保存决议的首次“允许重新筹办”提交需要锁外fresh资格核验。取得fresh材料后重新进入manager锁，再次核同原编号、完整定位、尚未终结及占用。读取期间记录真正失效，返回原定位已变化，不能返回新状态。
3. 同一有效记录仍在，fresh资格与消息携带资格不全等，或fresh返回可恢复的材料已变化时，返回该口的 `筹办材料已变化`。包括目标/定义/准确结果已合法改变，或者fresh已转成目标已满足/需求非活动/等待普通材料，均让self重新计算自己的决议，而不是manager代替self改许可。未提供资格、消息资格自身不合法仍入口拒绝；结构/资源错误保留原错误分流，不能以新状态隐瞒。
4. 返回新状态时不保存任何决议、不授筹办许可、不终结记录、不撤销占用、不修改已反馈位、不重发反馈、不分配新编号。没有新的发布或回滚操作。

self两个处理函数在收到对应 `筹办材料已变化` 时，分别执行 `项.等待决议.reset()` 或 `项.学习决议.reset()`，随后返回 `std::nullopt`；不得保留旧缓存、结束消息或把新状态记成一次已裁决。沿原消息循环约3777处以已有 `消息配置->资源重试间隔毫秒`推迟同一活动消息，下轮先核manager定位再fresh重算资格及决议。资源重试间隔在此仅复用现有调度退避，不表示材料变化是资源失败；不新增配置、忙等、立即递归或后台任务。

新状态不是资源失败：资源失败仍不清缓存，精确重试原决定；真正定位已变化仍结束旧消息；已接收/精确重复仍按原已裁决收束；停止及工程错误仍原分流。等待与学习两条链均须显式消费新枚举，并搜索全部对应枚举switch/比较，防默认分支误结束。持续合法材料变化可继续退避等待，不设任意重试次数后放行，也不伪造永久失败。

该修订不让manager周期重发已反馈记录，不改变任务执行/发布/消息存储生命周期；重算责任由仍存续的同一self活动消息承担。task最终fresh门继续负责提交后发生的变化，不能因为manager曾返回新状态而放宽。

学习完成复核只在原“确有相关可用方法及有效学习结果”的条件成立时用资格恢复筹办；不把本轮资格作为模拟学习成功证据，不恢复初始化主动学习入口。

## 7. 无前值静态分解与执行边界

`选择任务结果分支内部`增加独立的“合法派生值目标尚无本次前值”局部分支，来自fresh资格及派生定义，而非 `是服务需求取得目标`或方法词面。原普通缺F路径维持等待；普通有F无当前值的既有静态分解路径不改义。

v0.3澄清“无前值”在本静态分解分支指没有可读取的**持久派生实例特征当前值**，不能据此排除已有真实任务局部计算结果。第二次支撑来源为main `74d81f7a7f1809fb926e008da261da42b88907f8`：按第5节，原真实来源读口成功计算0时返回 `未满足但无有向差值`，却仍无持久派生F；只接受缺F/缺值状态会重新堵在约15435处。静态分解谓词因此同时接纳以下两类，且都必须有fresh独立资格允许、完整合法派生定义、值目标以及同D/目标的本次当前结果：

- 原 `目标特征尚未形成` 或 `当前值不存在`，保持尚无本次准确结果的含义；
- `实际特征节点`缺失，且本次任务owner通过原真实来源读口得到 `未满足但无有向差值`。本轮明确来源为 `已找到`且准确来源新增数为0；不是缺结果或工程失败推定的0，不从 `准确差异`反推出当前值。

无需新增DTO字段或来源标签；复用第5节唯一任务结果提供者及资格中同一次完整当前结果，不能把任意调用方构造的未满足枚举当真实来源。第二类只是允许静态域匹配与条件分解，并不改变准确0/1事实、不宣称仍无计算结果、不增加运行或学习规则。root及代码owner继续保留已发动作结果未知不得重放的原保护；真实0与未知结果严格区分。

该分支不要求实际派生F，`当前I64=nullptr`，单位从正式派生输出定义取得，删除 `取得初值=0`。结果作用对象仍需由参数正式绑定与目标E核同，结果FT需为同一根；只按正式结果值域与目标域的包含/相等，以及已有明确线性关系反求生成条件分解依据。条件不足继续生成真实子需求。不从无前值推导方向、幅度或端点优选；没有保证域/合法映射时保留结果定义暂不支持或幅度材料不足。
