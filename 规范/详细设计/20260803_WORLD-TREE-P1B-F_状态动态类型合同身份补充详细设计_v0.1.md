“生命周期长期”冻结为以下机器含义：

1. 四个稳定身份进入 ABI 后永久保留且不可复用；
2. 合同版本1首次发布时的正式生命周期枚举是 `类型合同生命周期状态::当前可写`；现行枚举不存在“长期”值，禁止新增同义枚举；
3. 后继正式生命周期入口可依法把合同推进为停止新写或退出普通使用，但不得恢复旧写资格、删除历史、复用身份或静默改变版本1内容。

## 4. 生产行为边界

P1B-F 仍只是最终合同骨架：

- `读取世界状态动态` 固定返回读取状态 `未实现(8)`、代次0、三组空；
- `形成完整世界实例状态写项` 固定返回发布状态 `未实现(14)` 和空内部规格；
- `发布状态并整理动态` 固定返回发布状态 `未实现(14)`、代次0、持久状态不适用、读回/缺项空；
- 三根不读取请求、不读取类型合同、不调用保存引用、不形成写集、不发布上述合同，不改变任何机器事实。

四个 `constexpr` 只提供稳定身份，不宣称运行期类型合同记录已发布。首次真实合同发布仍属于后继 P1B-W 的状态/动态事务设计和实现；P1B-Q 只读取并验证，不得创建合同。

### 5.2 隔离类型合同仓建立与读回

本自检使用函数内新建、只归本测试拥有的 `节点直接类型合同仓库`。测试仓不进入运行期装配，不与三个根函数的零副作用前后快照混用。

为满足仓库同命名域连续高水位规则，自检先以当前正式资格合同内容建立键1、2，再依次建立键3—6。键1、2只是隔离仓前置材料：

```text
世界场景资格类型合同：命名空间L2领域/1、版本1、I64标量值域1..3、所有者世界结构服务、当前可写、兼容空
世界存在资格类型合同：同命名空间/版本、I64标量值域1..2、所有者存在服务、当前可写、兼容空
```

对键1—6逐项执行现有仓库生命周期：

```text
结构化发布合同未发布候选
-> 候选读回逐字段等于计划合同且普通读取不可见
-> 确认候选
-> 完成发布
-> 读取精确合同(具名身份, 1)
-> 逐字段等于计划合同
```

每项使用具名测试事务序号且非零；不得把事务序号、数组位置或发布顺序当作类型合同身份。键3—6读回必须分别证明：表示和值域 variant 正确、所有者正确、生命周期为当前可写、直接兼容组为空、首次发布代次和当前状态发布代次为自检计划合同中冻结的非零值且后者不早于前者。

隔离仓测试失败只使专项自检失败，不映射为生产合同已发布、资源失败或任何骨架结果。自检结束后隔离仓随栈销毁，不产生运行期权威事实、SQL证据或恢复材料。
