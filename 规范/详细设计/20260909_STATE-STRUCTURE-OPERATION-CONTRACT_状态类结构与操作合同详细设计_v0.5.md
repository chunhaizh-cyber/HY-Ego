# STATE-STRUCTURE-OPERATION-CONTRACT 状态类结构与操作合同详细设计

日期：2026-09-09
版本：v0.5
状态：可施工详细设计
正式依据：1160 v0.18、4212 v0.5、4230 v0.44
相关正式边界：4202 v1.3、4211 v1.2、4080 v1.0
替代：同名详细设计 v0.4

## 1. 具名执行退回

执行侧已经用退出幂等身份成功逻辑退出一组状态事实，但首次物理清理在 L1 接受请求、形成清理幂等账前，因事实代次漂移或资源/内部失败返回。状态层没有也不允许增加持久 pair 材料，因此 v0.4 “改清理键即冲突”的绝对表述无法在 L1 未成账前成立。

## 2. 唯一裁决

1. 退出幂等身份和清理幂等身份分时绑定：前者由状态 owner 首次退出绑定原退出事实集合/Gexit；后者只由 L1 成功物理清理的幂等账绑定完整 L1 请求。
2. 每次清理都先从退出首次材料恢复同一 Gexit 和同一有序六事实组；已有退出材料后不得重扫、增删或替换候选。
3. 实际 L1 请求的 `期望事实代次` 使用本次 `G0`，并校验 `G0 >= Gexit`。未绑定键遭遇 L1 `事实代次漂移` 后，后续可以新 G0 重试原集合；可保留或更换非零清理键。
4. L1 一旦接受并成账，原键只能以首次完整 L1 请求精确重放；同键异请求冲突，异键对已清理墓碑也映射为状态 `幂等冲突`。
5. 状态层不新增 L1 接口、第二持久账、内存伪账或进程恢复缓存。L1 幂等账和墓碑是清理键已绑定的唯一权威证据。

## 3. 流程与分支

```text
读取退出首次材料
├─ 未命中 -> 扫描候选 -> 无候选读取成功，或首次逻辑退出
└─ 命中   -> 恢复固定集合/Gexit，禁止重扫
-> 校验 G0 >= Gexit
-> 调用 L1(期望=G0, 本次清理键, 原有序集合)
├─ 未接受非成功 -> 清理键未绑定；原集合/Gexit不变
├─ 已清理         -> L1成账，清理键绑定
├─ 精确重复       -> 核验首次墓碑后返回
└─ 异键命中墓碑   -> 幂等冲突
```

不得在 L1 调用前把清理键写入退出材料；不得用“同一退出键曾看到某个清理键”的进程内状态拒绝后续新键。

## 5. 验证和声明边界

执行侧须在原 v0.4 矩阵上新增四个静态分支：L1接受前同键换G0重试、L1接受前改键但原集合/Gexit不变、L1接受后原键原请求精确重放、L1接受后异键冲突。同时扫描状态模块不存在新持久 pair 材料或内存键账。

本设计只消除同步清理键绑定时点的执行歧义；不证明代码已实现、编译、运行、持久恢复、CES绑定或业务闭环。
