# 任务结果上行桥与自我治理邮箱生产接线详细设计 v0.1

日期：2026-08-21

计划身份：`RUNTIME-GOVERNANCE-TASK-RESULT-UPSTREAM-PRODUCER-WIRING`

代码基线：`e7d49114098363ad26901b9513d838607d6862f5`

## 1. 目标与完成边界

本设计承接已经正式退出的“任务实际结果事实与独立读回提供者”“治理输入到任务实际结果身份绑定”和“任务结果绑定复核自我线程生产消费”三项结果，补齐其上游真实生产接线：

```text
任务工作线程结果尾部取得已形成的强类型工作结果
-> 形成非权威任务结果回执
-> 任务管理线程接收并冻结结果上行槽
-> 任务实际结果上行桥读取同一 G0 的正式当前实例方法
-> 调用 L2 任务结构服务唯一入口发布或复用任务实际结果
-> 以发布结果截止 G1 独立读回正式结果及绑定事实
-> 只从正式读回形成任务结果复核治理消息
-> 任务管理线程向唯一自我治理邮箱提交同一消息
-> 自我线程冻结批次、分类、执行绑定复核并冻结唯一后继输入
```

本计划必须包含最小真实任务工作线程结果生产者。测试直接调用任务管理线程、上行桥或 `自我线程::提交治理消息`不能证明本计划完成。

任务工作线程结果生产者只消费已经形成的强类型工作结果材料并生成回执；它不执行方法、不形成实际状态或动态、不裁决任务成功。任务管理线程只负责接收、排队、调用唯一上行桥、提交邮箱、重试和停止。任务实际结果仍只由 `L2任务结构服务::记录任务实际结果`发布；自我治理邮箱仍是唯一接收边界。

本计划不进入下一治理步骤，不裁决任务完成、需求满足、服务成功、安全值或服务值变化，不实施任务筹办、任务执行方法逻辑、结算、学习或跨进程恢复。

## 2. 当前事实与复用裁决

### 2.1 已有能力

- `任务结果回执协议.ixx`已有非权威回执、来源执行绑定和准入复核，但协议版本 2 没有显式来源材料版本和任务实际结果写入幂等身份。
- `任务管理线程.ixx`已有物理线程壳和两阶段任务执行请求队列，但没有结果回执入口、上行槽、任务实际结果上行桥或自我治理消息提交。
- `L2任务结构服务::记录任务实际结果`已按任务与正式执行轮次保证唯一：首次发布、同义精确重复、同轮异义引用冲突均已正式实现。
- `L2任务结构服务::按任务读取当前实例方法`可在调用方指定的 G0 返回正式实例方法及执行轮次。
- `运行期只读查询组合器::读取任务本轮实际结果与独立读回`可在调用方指定的截止完整互证任务实际结果、实例方法、方法路径、状态、动态、场景、主体和来源需求。
- `自我线程::提交治理消息`是唯一治理邮箱公开提交入口；下游邮箱、批次、分类、绑定复核和后继冻结已经实现。
- `启动.应用程序.ixx`仍把任务工作线程池、任务管理线程和结果上行排空保留为空桩。

### 2.2 缺口与新建裁决

正式 Git 树当前没有任务工作线程实现。恢复已删除旧线程会把旧结构写入链和旧业务解释带回当前代码，因此禁止恢复旧文件。

本计划新建三个职责单一的生产模块：

1. `任务工作线程.ixx`：只运行结果尾部队列，形成回执并提交任务管理线程；
2. `上行桥.任务实际结果.ixx`：只编排正式执行轮次读取、唯一任务结果发布、独立读回和治理消息构造；
3. `运行包.任务结果生产.ixx`：只装配一个任务实际结果上行桥、一个任务管理线程和一个最小任务工作线程结果生产者，并冻结启动/停止顺序。

不得把以上职责并入 `自我线程`、`L2任务结构服务`或 `启动.应用程序`形成第二业务 owner 或线程上帝类。

## 3. 回执版本与工作结果输入合同

### 3.1 协议升级

`海中鱼巣/线程/任务结果回执协议.ixx`把 `任务结果回执协议版本`从 2 升为 3。版本 3 在现有回执上增加：

```cpp
std::uint64_t 来源材料版本 = 0;
L2结构幂等身份 任务实际结果写入幂等身份;
```

两项都必须非零，并进入完整相等比较。`来源材料版本`是形成本次工作结果材料的正式合同版本，不得用材料摘要、回执协议版本、来源任务序号或运行代次替代。`任务实际结果写入幂等身份`只供任务领域唯一写入口使用，不得复用治理消息幂等键、回执编号或来源任务序号临场生成。

### 3.2 已形成工作结果材料

同模块新增值式 `任务工作结果材料`，字段精确为：

```text
回执编号、发生时间戳、回执幂等键、来源任务序号、批次编号
非权威材料摘要、来源材料版本、任务实际结果写入幂等身份
运行代次、读取截止 G0、过期策略和截止时间戳
任务、实际状态、动态证据、方法、动作入口、场景、主体
来源执行请求编号、来源执行任务序号、来源执行批次编号、
来源执行幂等键、来源执行任务、来源执行方法、来源执行动作入口
```

它只描述动作和独立实际状态读取之后已经形成的工作结果，不携带“任务成功”“任务完成”“需求满足”或价值字段。

新增纯值入口：

```cpp
任务结果回执形成结果 形成任务结果回执(
    const 任务工作结果材料& 材料) noexcept;
```

该函数逐字段复核非零身份、版本、G0、来源绑定和时效形状，然后机械形成协议版本 3 的 `任务结果回执材料`。它不读取 DATA、不调用任务领域、不生成执行轮次。形成后的回执必须与输入逐字段互证；失败只返回结构化拒绝和空回执。

## 4. 最小任务工作线程结果生产者

新模块 `海中鱼巣.线程.任务工作线程` 导出唯一 `任务工作线程`。它持有有界的 `任务工作结果材料`队列、一个物理线程和借入的 `任务管理线程`引用。

公开入口固定为：

```cpp
任务工作线程(std::uint64_t 结果队列容量, 任务管理线程& 上行目标) noexcept;
任务工作线程操作结果 启动() noexcept;
任务工作线程提交结果 提交已形成任务工作结果(
    const 任务工作结果材料& 材料) noexcept;
任务工作线程操作结果 停止接收并排空() noexcept;
任务工作线程操作结果 收口等待() noexcept;
任务工作线程快照 读取快照() const noexcept;
```

线程入口只做：取出一项 -> 调用 `形成任务结果回执` -> 向任务管理线程提交回执。形成失败或任务管理拒绝必须冻结在快照中，不能改写材料重试。队列满返回资源等待；停止接收后拒绝新材料，但已经入队的材料必须排空后才允许线程退出。

这一模块不消费任务执行请求、不调用方法、不产生实际状态或动态。未来任务执行逻辑只能在形成强类型工作结果后调用本入口，不能绕过它直达任务管理线程。

## 5. 任务实际结果上行桥

新模块 `海中鱼巣.线程.上行桥.任务实际结果` 导出：

```cpp
class 任务实际结果上行桥 final {
public:
    任务实际结果上行桥(
        L2需求结构服务&, L2任务结构服务&, L2状态结构服务&,
        L2特征结构服务&, L2存在结构服务&, L2场景结构服务&,
        L2动态结构服务&) noexcept;

    任务结果上行形成结果 发布并形成治理消息(
        const 任务结果回执材料& 回执,
        std::uint64_t 最大来源需求成员数) noexcept;
};
```

桥持有上述服务的借用引用和一个内部 `运行期只读查询组合器`值对象；不持有 L1、仓库、自我线程或邮箱。

### 5.1 固定执行顺序

1. 复核协议版本 3、回执完整性和预算非零；`G0 = 回执.读取截止代次`。
2. 以 `{L2结构合同版本, G0}` 调用 `按任务读取当前实例方法`；只接受恰一当前实例方法，执行轮次来自其 `执行轮次`。来源任务序号不得进入执行轮次。
3. 互证实例方法的任务和来源方法与回执一致；动作入口继续由任务结果唯一发布入口按当前选中路径复核。
4. 构造 `L2记录任务实际结果请求`：期望代次为 G0；写入幂等身份、任务、方法、动作入口、场景、主体、实际状态、动态证据、来源材料版本和运行代次全部来自回执；实例方法和执行轮次来自第 2 步正式读取。
5. 恰一次调用 `记录任务实际结果`。只对 `已提交`或`精确重复`继续；同轮异义固定映射引用冲突并形成零治理消息。
6. `G1 = 记录结果.结果头.事实截止代次`。以 G1、正式执行轮次和同一回执字段调用 `读取任务本轮实际结果与独立读回`；不得沿用发布返回对象代替独立读回。
7. 只有独立读回状态为已形成且所有身份、版本、运行代次、执行轮次和 G1 全等，才形成治理消息。

### 5.2 治理消息确定性映射

治理消息字段固定为：

| 治理消息字段 | 唯一来源 |
| --- | --- |
| 协议版本 | 当前 `自我治理协议版本` |
| 治理消息编号 | 原回执编号 |
| 类型 | 任务结果复核请求 |
| 来源角色 / 来源服务 / 目标服务 | 任务管理上行桥 / 任务桥边界 / 任务 |
| 发生时间戳 | 原回执发生时间戳 |
| 优先级 | 普通 |
| 幂等键 | 原回执幂等键 |
| 来源任务序号 | 原样保留，只作消息顺序 |
| 来源材料版本 | 正式独立读回任务实际结果的来源材料版本 |
| 批次编号 | 原回执批次编号 |
| 材料类型 / 性质 | 任务结果材料 / 非权威回执 |
| 过期策略 / 截止时间戳 | 永不过期 / 0 |
| 运行代次 | 正式独立读回任务实际结果的运行代次 |
| 读取截止代次 | G1 |
| 任务结果载荷七身份 | 正式独立读回的任务、实际状态、动态、方法、动作入口、场景、主体 |

非权威材料摘要采用固定 FNV-1a 64 位混合，顺序为：任务实际结果身份、任务、实例方法、执行轮次、方法、动作入口、场景、主体、实际状态、动态证据、来源材料版本、运行代次、G1；每项按其公开 `uint64` 值混合，结果为零时写 1。摘要只用于非权威材料一致性，不替代任何身份或版本。

## 6. 任务管理线程结果上行槽

`任务管理线程`保留现有任务执行请求 API，并增加生产构造重载，借入一个 `任务实际结果上行桥`和一个 `自我线程`：

```cpp
任务管理线程(
    std::uint64_t 旧队列容量,
    std::uint64_t 强类型请求容量,
    std::uint64_t 结果上行容量,
    std::uint64_t 最大来源需求成员数,
    任务实际结果上行桥& 上行桥,
    自我线程& 自我治理目标) noexcept;

任务结果回执提交结果 提交任务结果回执(
    const 任务结果回执材料& 回执,
    std::uint64_t 当前时间戳) noexcept;

任务结果上行槽快照 读取任务结果上行槽(
    std::uint64_t 回执幂等键) const noexcept;

任务管理线程操作结果 请求停止新派发() noexcept;
任务管理线程操作结果 排空结果上行并停止() noexcept;
```

### 6.1 准入与唯一槽

- 提交入口用现有 `复核任务结果回执材料`完成版本、时效、同幂等键和同任务来源序号复核。
- 每个回执幂等键只建立一个进程内上行槽。精确重复返回既有槽，不再次入队；同键异义拒绝。
- 槽保存原回执、阶段、正式实例方法、正式执行轮次、任务实际结果身份、G1、不可变治理消息、结果发布尝试次数和邮箱提交尝试次数。
- 上行桥成功后按任务实际结果身份再去重；即使另一回执编号或来源任务序号指向同一正式结果，也复用首次消息槽，不形成第二治理消息、第二批次或第二后继。

### 6.2 阶段和失败分账

| 上行槽阶段 | 固定行为 |
| --- | --- |
| 待发布正式结果 | 允许以原回执调用上行桥；不得改 G0、版本或身份 |
| 治理消息待提交 | 只向 `自我线程::提交治理消息`重试已冻结消息；禁止再次调用上行桥或任务结果发布入口 |
| 已提交 / 精确重复 | 完成；后续重复回执只读回原槽 |
| 合法等待 | 正式当前实例方法或结果尚未形成；保留原回执等待同槽重试 |
| 当前性漂移 | 结构化终止；不自行换 G0 |
| 引用冲突 / 入口拒绝 | 拒绝本输入；零治理消息 |
| 资源等待 | 保槽重试当前阶段；已发布后不得回退到发布阶段 |
| 内部终止 | 结构化终止；零伪造成功 |

邮箱返回已提交时槽进入已提交；重复材料只有在消息与首次槽全等时进入精确重复。队列已满映射资源等待并保留同一消息。队列已停止、协议拒绝或内部不一致在正常停止顺序下均为结构化内部终止，不得丢弃后伪报排空成功。

管理线程的物理循环用条件变量等待任务执行请求、结果上行或停止，不再空转 `yield`。外部调用不得持有任务管理锁进入上行桥、任务领域、自我线程或邮箱。

## 7. 生产运行包与启动停止接线

新模块 `海中鱼巣.线程.运行包.任务结果生产` 导出 `任务结果生产运行包`。构造时借入普通应用同一组 L2 服务和当前 `自我线程`，内部按声明顺序持有上行桥、任务管理线程和任务工作线程。

公开入口：

```cpp
任务结果生产运行包操作结果 启动() noexcept;
任务工作线程提交结果 提交已形成任务工作结果(
    const 任务工作结果材料&) noexcept;
任务结果生产运行包操作结果 请求停止新派发() noexcept;
任务结果生产运行包操作结果 收口工作线程并排空结果上行() noexcept;
```

启动顺序固定为任务管理线程先进入、任务工作线程后进入。任一步失败立即逆序收口已经启动的对象。

停止顺序固定为：

```text
任务管理线程停止接收新任务派发
-> 任务工作线程停止接收新工作结果
-> 排空工作线程已经接收的结果并 join
-> 任务管理线程继续处理全部结果上行槽
-> 已发布但尚未入邮箱的消息保持原样重试
-> 全部槽达到已提交、精确重复或结构化终态
-> 任务管理线程 join
-> 才允许停止自我治理邮箱和自我线程
```

本计划不把进程内上行槽持久化。正常停止不得丢失已经发布但尚未成功提交邮箱的消息；程序崩溃、进程被终止和跨进程恢复明确为 `NOT_RUN`。

`启动.应用程序.ixx`删除任务工作线程池、任务管理线程和结果上行排空三个空桩在本链中的占位行为，改为构造并调用唯一 `任务结果生产运行包`。启动和收口失败必须进入现有结构化程序运行结果，不得只写日志判定成功。

## 8. 生产级验证合同

专项必须从 `任务结果生产运行包::提交已形成任务工作结果`进入，经过真实物理任务工作线程、任务管理线程、上行桥、正式任务结果发布与独立读回、唯一自我治理邮箱、真实自我线程、批次分类、绑定复核和处理槽后继。禁止直接调用任务管理结果入口、上行桥、任务结果发布入口、`自我线程::提交治理消息`或绑定复核函数证明本计划完成。

至少覆盖：

1. 首次合法工作结果形成一个正式任务实际结果、一个治理消息、一个治理批次和一个后继；全部字段与正式独立读回一致。
2. 精确重复工作结果或回执不再次发布结果，不形成第二消息、第二批次或第二后继。
3. 同一正式执行轮次的异义结果由任务事实层返回引用冲突，零治理消息。
4. 邮箱满时槽保持同一正式结果身份、G1 和治理消息；恢复容量后只重试邮箱提交，结果发布尝试次数不增加。
5. 请求停止新派发后，已经进入工作线程队列的结果仍能发布并提交；自我线程在上行排空前保持运行。
6. 来源任务序号变化不改变正式执行轮次；指向同一正式结果时仍只有首次消息和后继。
7. 当前性漂移、入口拒绝、引用冲突、资源失败和内部错误均按阶段分账，零伪造后继。
8. Debug/Release x64 全量 Rebuild、两配置治理专项、strict、diff 和精确白名单检查通过。

日志只能辅助定位，所有通过结论必须来自结构化结果、正式任务结果读回、上行槽快照、自我线程处理槽快照和逐字段断言。
