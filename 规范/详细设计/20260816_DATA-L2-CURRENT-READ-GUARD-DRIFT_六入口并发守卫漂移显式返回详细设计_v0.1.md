# DATA-L2 六入口并发守卫漂移显式返回详细设计

日期：2026-08-16

版本：v0.1

身份：`DATA-L2-CURRENT-READ-GUARD-DRIFT`

状态：设计就绪

## 1. 目标与完成边界

在现有 `L2场景结构服务` 与 `L2存在结构服务` 内修复六个公开当前读取入口的共同并发结果语义：

```text
调用方以非零事实截止 G0 发起当前读取
-> 任一影响最终载荷的 DATA-L1 当前子读取发现守卫已经失效
-> DATA-L2 返回 L2结构状态::事实代次漂移
-> 结果头.事实截止代次携带该次 DATA-L1 正式观察到的非零新截止 G1
-> 结果全部业务载荷为空，变更事实代次为空
```

本叶不改变六个公开函数的名称、参数、返回类型、DTO 字段、枚举数值、owner、历史读取语义或正常成功形状；不新增通用读取服务、BIZ 重分类、SELF 适配、普通应用接线、缓存、自动重试、生产验证 seam 或第二事实来源。

`事实代次漂移` 表示请求选择的 `G0` 已不再是当前事实截止，不表示私有事实损坏。`内部不一致` 只保留给合同版本、回声字段、owner、端点、生命周期、项目形状或成功载荷自身矛盾。BIZ 只能消费 DATA 的结构化状态，不得根据时间、退出码、日志或观察到的新截止把 `内部不一致` 猜成漂移。

2. 约第 3798 行读取目标父关系组；底层非成功被无条件折为 `内部不一致`，随后 `目标父读取代次 != G0` 也被折为 `内部不一致`。

另外五个入口已经使用 `尝试读取所有者范围一致当前投影` 及现有顶层解释器作为主要当前投影，但仍必须把其登记、来源、端点和后续同截止子读取共同纳入回归，证明漂移在任何层级都优先透传且不会被后续空值或形状检查覆盖。

## 4. 共同当前读取合同

### 4.1 单一守卫

每次公开当前读取只选择一个调用方提供的 `G0`。凡会影响最终成功载荷的登记、owner / 身份来源、节点、关系组、属性和值读取，都必须满足以下二者之一：

1. 子读取本身携带 `G0`，由 DATA-L1 原子一致当前投影直接裁决；或
2. 子读取不能携带守卫时，其正式结果必须在进入任何载荷形状解释前与 `G0` 互证，并把非零异截止作为 `事实代次漂移` 收口。

不得用函数进入时一次读取当前代次、锁外缓存、请求副本或调用方重试替代各子读取的守卫责任。实现可以复用或调整两个现有服务文件内的私有 helper，但本设计不冻结私有函数名、调用次数或具体投影拆分。

### 4.2 状态优先级

当前路径按下列优先级处理：

1. 公开请求纯值无效：保持现有 `入口拒绝`、截止 0、空载荷。
2. DATA-L1 守卫读取明确返回漂移且失败形状完整：返回 `事实代次漂移`、该读取观察到的非零 `G1`、空载荷。
3. 不能携带守卫的当前子读取成功返回非零 `G1 != G0`：把它解释为本次公开读取的守卫已经失效，返回同样的漂移结果。
4. DATA-L2 直接调用的具名子服务返回 `事实代次漂移`：原样传播状态与非零观察截止，先于 optional、空组或逐字段检查。
5. `许可拒绝`、`资源失败`、`入口拒绝`、`未找到`、`已退出`、`属性未设置`等已有合法状态继续按现行入口合同传播或分账，不因本修复互换语义。
6. 只有合同版本 / 请求回声矛盾、守卫式读取声称成功却返回错截止、失败带非空载荷、owner / 端点 / 生命周期 / 基数坏形状或成功载荷内部矛盾，才返回 `内部不一致`。

这里第 3 项专门处理正式缺口中的“无守卫当前子读取已经观察到新截止”。若一个守卫式 DATA-L1 接口收到 `G0` 却声称成功并返回 `G1 != G0`，则 DATA-L1 自身成功形状已坏，仍属于第 6 项 `内部不一致`；不得把坏成功形状伪装为普通并发。

### 4.3 零部分发布

六入口都先在局部候选中收集材料，只有全部子读取在同一 `G0` 成功且形状完整后才构造公开成功结果。任一漂移、逻辑非成功、资源失败或内部错误必须通过既有失败形成函数一次返回空载荷；不得保留此前已收集的场景、关系、存在、属性或身份来源。

本叶全部函数诊断责任为 `向上送出`：它们用结构化结果送出 DATA 状态，不新增错误日志，不吞异常，不以日志建立机器事实。

| 场景 | 并发安排 | 期望 |
| --- | --- | --- |
| S0 稳定控制 | 建立满足该入口的最小正式事实，冻结 `G0`，无 writer 调用当前入口 | `已读取`或该入口现行合法 `未找到`；不得出现漂移 / 内部不一致 |
