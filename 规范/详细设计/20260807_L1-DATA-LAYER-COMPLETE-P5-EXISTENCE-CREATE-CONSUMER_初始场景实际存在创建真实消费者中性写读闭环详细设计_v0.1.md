## 1. 目标与完成边界

本叶把“在初始场景中创建实际存在”这一跨存在与场景的真实 L2 消费者迁移到业务中性 CRUD。一次业务调用固定发布一个普通实际存在节点、一个 I64 资格值、一个资格属性槽和一条初始场景到该存在的直接成员关系；四项在一个 L1 中性写集中原子发布，并经存在资格和场景接纳两个事实所有者的正式精确读回组合为完整 `实际存在事实`。

本叶新增唯一 `初始场景实际存在原子发布服务`，归属 L2 场景领域。它只消费 `L1实际存在服务` 形成的资格写入规格和 `L1场景结构服务` 形成的接纳写入规格，唯一负责把两个不可变规格合并为一个中性写集并恰一次提交。直接成员关系的业务准入和写入责任仍唯一属于场景领域；存在服务仍唯一拥有实际存在资格语义。原子发布服务不反向取得两个事实的准入所有权。

现有 `L1实际存在场景组合服务` 删除 L1 引用和全部写集/幂等/事务实现；它的创建与读取公开根只把原请求原样委托给原子发布服务并原样返回，不形成第二发布者或第二结果解释者。

生产启动在 P4 实际存在登记成功后、旧系统角色初始化前创建一个固定配置的初始场景实际存在。该结果进入运行期候选完整性和公开当前读回；它不是验收夹具、自我身份或系统角色替身。本叶不进入特征、状态、动态、修改、移动、退出或历史读取，不建立 L1 自证、专用驱动、第二程序、重复/非法/并发补格或恢复材料；不考虑崩溃、重启、断电和跨进程恢复。

## 3. 唯一职责与调用方向

### 3.1 服务归属

```text
实际存在资格规格和资格事实：L1实际存在服务，L2 存在领域
初始场景接纳规格、直接成员关系及接纳事实：L1场景结构服务，L2 场景领域
跨规格单事务物化：初始场景实际存在原子发布服务，L2 场景领域
公开跨事实编排门：L1实际存在场景组合服务，只透明委托
中性稳定编码、原子事务、最小幂等和精确 CRUD：L1 事实基座
```

原子发布服务的正式身份由模块、类和函数三元组唯一确定：

```text
模块：海中鱼巣.领域.服务.初始场景实际存在原子发布
文件：海中鱼巣/领域/服务.初始场景实际存在原子发布.ixx
类：初始场景实际存在原子发布服务
发布函数：实际存在结果 发布初始场景实际存在(const 实际存在创建请求& 请求)
读取函数：实际存在结果 读取初始场景实际存在(const 实际存在读取请求& 请求) const
```

发布服务复用 `L1实际存在合同版本=2`、`L1实际存在规则版本=1`、`实际存在创建请求`、`实际存在读取请求` 和 `实际存在结果`，不新增第二套 DTO、机器稳定身份节点或业务版本字段。服务合同语义由上述具名身份与请求中的存在合同/规则共同确定。

### 3.2 固定调用方向

```text
生产运行期 / 合法调用方
-> L1实际存在场景组合服务
-> 初始场景实际存在原子发布服务
   -> L1实际存在服务::形成实际存在写入规格
   -> L1场景结构服务::形成初始场景接纳规格
   -> L1事实基座服务::提交中性写集（恰一次）
   -> L1实际存在服务::读取实际存在资格
   -> L1场景结构服务::读取初始场景接纳
```

组合服务的构造函数固定改为只接收 `初始场景实际存在原子发布服务&`。其 `在初始场景创建实际存在` 只调用发布函数恰一次；其 `读取实际存在` 只调用读取函数恰一次；零校验、零状态映射、零 DTO 重组、零锁、零缓存、零 L1、零事实所有者旁路。

原子发布服务构造固定接收同一运行期上下文中的 `L1事实基座服务&`、`L1实际存在服务&`、`L1场景结构服务&`。只有该服务可以在本业务根中调用 L1；它不得调用组合服务，避免环。

## 4. 请求、规格与业务准入

`L1实际存在合同版本` 保持 2，场景合同保持 3，不因内部迁移升版。`海中鱼巣/领域/L1实际存在.数据.h` 新增纯值判断：

```cpp
bool 实际存在创建请求有效(const 实际存在创建请求&) noexcept;
bool 实际存在资格读取请求有效(const 实际存在资格读取请求&) noexcept;
bool 实际存在读取请求有效(const 实际存在读取请求&) noexcept;
bool 实际存在结果::成功() const noexcept;
```

创建请求必须携带合同 2、规则 1、完整初始场景读取定位、有效 56 位业务幂等身份和非零期望事实代次。读取请求必须携带同版本、完整场景定位，以及存在、资格值和归属关系三个有效且互不相同的稳定编码。成功结果只接受已提交、幂等读回或已读取，并携带通过 `实际存在事实完整` 的完整事实。

发布根在第一笔写入前固定执行：

1. 验证完整创建请求。
2. 调用 `L1实际存在服务::形成实际存在写入规格` 恰一次，请求合同/规则/期望代次原样取自创建请求。
3. 只接受状态已读取、规格完整且截止等于请求期望代次。
4. 调用 `L1场景结构服务::形成初始场景接纳规格` 恰一次，请求场景定位和期望代次原样取自创建请求。
5. 只接受状态已读取、规格完整且截止等于请求期望代次。
6. 互证两个规格截止相等；资格来源服务节点、资格属性类型、初始场景和直接成员关系类型均有效且种类正确。

任何提供者非成功原样映射到 `实际存在状态`：未找到、入口拒绝、版本漂移、许可拒绝、资源失败和内部不一致分别保留；不得把缺失规格降级成空成功。场景状态按稳定同值枚举逐项显式映射，不使用裸 `static_cast`。

## 5. 中性写集与事务边界

最终技术幂等键保持既有领域隔离：

```text
初始场景实际存在中性幂等域 = 0x0B
最终键 = (0x0BULL << 56) | 请求.幂等身份.值
```

两个规格互证成功后形成唯一写集：

| 本地键/项目 | 中性字段 |
| --- | --- |
| 1 节点 | `普通`；新实际存在 |
| 2 值 | 所属=本地 1；属性类型=存在规格.资格属性类型；材料=`I64{1}`；来源=存在规格.服务身份 |
| 3 关系 | 源=场景规格.场景；目标=本地 1；类型=场景规格.直接成员关系类型；角色/顺序=0 |
| 属性槽变更 | 所属=本地 1；属性类型=存在规格.资格属性类型；当前值=本地 2 |
| 退出 | 空 |

请求只含中性合同 1、期望事实代次、0x0B 最终键和上述五组。不得调用 `探测幂等`、legacy `提交写集`、完整快照、审计、恢复、SQL 或旧仓；不得形成业务操作标签、G6 意图、摘要、执行证据、提供者见证、领域结果见证或发布后读回计划。`提交中性写集` 恰一次，L1 内一个事务分配三项稳定编码并最后推进一个事实代次；L2 不接触候选、确认、撤销、许可、锁或事务视图。

同键同一完整中性请求由 L1 返回精确重复；同键但任一中性字段、期望代次或业务解析结果不同返回幂等冲突。创建请求中世界根、场景标记值和直接父关系必须先被场景服务精确解析为同一场景事实，不能被省略字段绕过同义判定。

成功类结果必须满足合同 1、回显最终键、事实代次非零、三项本地键/稳定编码映射完整唯一且互不相同。`成功` 必须形成内存权威发布且重试边界为不适用；`精确重复` 必须不形成新发布且重试边界为原幂等键读回收敛。坏成功一律内部不一致。

写入状态映射：成功→已提交，精确重复→幂等读回，入口拒绝→入口拒绝，事实代次漂移→版本漂移，幂等冲突→幂等冲突，资源失败→资源失败；未找到、已退出和内部不一致在已取得两个完整同截止规格后均为内部不一致。

## 6. 精确读回与唯一关系证明

从三项映射形成 `实际存在读取请求`：场景定位原样取创建请求，存在=本地 1 映射，资格值=本地 2 映射，归属关系=本地 3 映射。发布根调用与公开读取根相同的私有组合读回：

```text
L1实际存在服务::读取实际存在资格
-> L1场景结构服务::读取初始场景接纳
-> 两结果均已读取、完整且事实截止相等
-> 资格所属节点等于接纳成员
-> 组装并验证完整实际存在事实
```

实际存在资格读回迁移为：当前登记权威读回→起始当前代次→存在节点→资格属性类型节点→资格来源节点→当前属性槽→资格值→结束当前代次。全部使用中性精确入口，首末、登记截止和五项读取代次必须相等；逐字段验证普通存在、I64 属性类型、来源服务、槽当前值、值材料 1、创建代次和未退出。

场景接纳读回迁移为：当前初始场景权威读回→起始当前代次→成员节点→直接成员关系类型节点→指定归属关系→结束当前代次。全部使用中性精确入口，首末、场景截止和三项读取代次必须相等；逐字段验证普通成员、普通关系类型、方向 `初始场景→成员`、角色 0 和未退出。

创建路径另要求实际存在节点、资格值和直接成员关系创建代次均等于本次写入事实代次。成员节点的稳定编码在本事务中首次分配，提交写集只创建一条以它为目标的直接成员关系；在场景服务唯一写入门成立的前提下，本次创建不可能已有第二当前父关系。因此本叶以新节点映射、单关系写集和指定关系精确读回证明本次单归属，不再扫描完整快照。后续移动或非法旁路不由本叶假设或补查。

原子发布服务不缓存事实。运行期上下文只为生产创建的一个初始实际存在缓存 `实际存在读取请求` 定位；初始化成功后新旧定位必须全等，每次公开当前读均经组合服务→原子发布服务→两个事实所有者重新读取权威事实。

## 7. 生产接线

生产配置新增固定 `实际存在操作幂等身份 初始实际存在创建幂等身份{1}`。它与 P4 登记身份同值，但 0x0B 与 0x0A 前缀使最终技术键不同。

运行期上下文新增并按声明顺序构造：

```text
L1实际存在服务
-> 初始场景实际存在原子发布服务
-> L1实际存在场景组合服务
```

新增公开入口：

```cpp
实际存在结果 初始化初始场景实际存在(const 实际存在创建请求& 请求);
实际存在结果 读取初始场景实际存在() const;
bool 初始场景实际存在完整() const;
```

初始化只调用组合服务创建根恰一次；成功后以原请求场景定位和结果中的存在、资格、归属编码形成并保存唯一定位。读取只以该定位调用组合服务读取根，不保存事实副本，不直调 L1。

P4 登记成功后，生产会话以初始场景结构化结果重建完整 `初始场景读取请求`，以 P4 登记结果的当前截止作为期望事实代次，并配入固定创建幂等身份形成 `实际存在创建请求`。随后恰一次调用上下文初始化；失败时旧系统角色、概念活动和候选发布均不得执行。

`运行期上下文::完整()` 要求世界登记、初始场景、实际存在登记和初始场景实际存在四项公开当前读均成功且事实截止相等，再检查旧系统角色和概念活动。固定顺序：世界登记→初始场景→实际存在登记→初始场景实际存在→旧系统角色→概念活动→候选完整性→首次发布。

`生产运行期启动状态` 末尾新增 `初始场景实际存在初始化错误=13`；`生产运行期启动结果` 在实际存在登记业务状态之后新增 `实际存在状态 初始场景实际存在业务状态`。所有聚合初始化按新字段顺序逐项冻结：请求/配置失败四项默认；已有租约四项均为已读取；任一前置失败时后续项默认；本叶失败时保留前三项成功状态和本叶原样状态；后续失败和最终成功均保留四项原样成功状态。
