# SUPPORT-THREAD-CANDIDATE-LIFECYCLE 支持线程候选生命周期基础详细设计 v0.1

日期：2026-08-15

状态：正式详细设计；代码未实现；执行资格只读 `计划/计划索引.md`

## 1. 目标与边界

为事件日志、缓存统计和持久证据等支持线程提供同一个纯运行期候选生命周期基础：创建一个可移动的线程候选租约，等待真实线程入口见证，并在启动失败或后继回收时请求停止、等待完成并 `join`。本基础只拥有物理线程候选、内部进入/完成见证和租约；8110 生命周期消息只作最佳努力投影，不参与物理成功裁决。

本设计不实现任何具体支持线程入口、事件摘要队列、日志写入、缓存重建、SQL/材料持久化、支持线程组装配或程序启动接线；不调用 DATA-L1—DATA-L3，不读写业务事实。

## 2. 正式依据与当前事实

- 0050、8100 v0.6、8110 v0.2、8120 v0.10、CODE-FILE-01 v2.6。
- `THREAD-LIFECYCLE-PROJECTION-SERVICE v0.1` 已在提交 `79802aa5038212a889d8b4b43c043ff423d44bb2` 发布唯一生命周期发布/读取 ABI；真实线程接线仍为 `NOT_RUN`。
- 旧 `海中鱼巣/线程/事件日志线程.ixx` 与 `缓存统计线程.ixx` 已在 `cb9de30c53b5093d0bcb0188053bfc2cda88d7de` 删除，不是可适配现状。
- 现行 `有界运行消息队列` 无并发锁，载荷只含通用数值摘要，既不拥有物理线程候选，也不能承载具体支持线程入口。

因此新增唯一共享模块；三个具体支持线程只实现各自入口端口，不重复声明候选租约、进入/完成见证或回收函数。

## 4. 创建、见证与回收

### 4.1 创建

固定顺序：

```text
锁外校验合同版本、运行代次、逻辑身份和三组允许类别—模块配对
-> 在进程级身份守卫中原子保留(运行代次, 线程逻辑身份)
-> 形成候选共享控制块
-> 最佳努力发布 seq1 创建
-> 构造唯一 std::jthread
-> 线程取得真实系统线程 ID
-> 最佳努力发布启动中和运行中
-> 原子发布内部已进入见证并唤醒等待方
-> 调用具体支持线程入口端口
```

进程级身份守卫是物理创建权威，不读取或依赖 8110 投影。一个 `(运行代次, 线程逻辑身份)` 最多被保留一次；并发重复或历史重用返回 `身份已使用` 且零线程、零租约、零新投影。身份一经保留即成为进程生命周期墓碑，线程创建失败、入口故障、正常回收或租约析构均不释放；有效请求在任何创建非成功后重试必须使用新的线程逻辑身份。若守卫自身分配失败且尚未保留身份，返回 `资源失败` 且零线程；这不改变调用方使用新尝试身份的重试规则。无效请求不进入守卫。

生命周期发布的 `投影暂不可用`、容量已满、资源失败或其它非接受状态只增加 `生命周期投影未接受次数`，不得把已形成的物理线程改判为创建失败。请求无效、控制块或线程资源分配失败在返回前零租约泄漏；物理线程创建失败时，无论 seq1 是否被接受，创建方都按本地物理状态继续消费后继序号，并经唯一串行器最佳努力发布“故障 -> 收尾中 -> 退出前 -> 异常退出”完整异常终态链；投影结果不替代结构化创建结果。

Windows 生产实现以 `GetCurrentThreadId()` 取得非零系统线程 ID，不得哈希 `std::thread::id`。生命周期诊断发生时间取 `system_clock` 的 Unix epoch 毫秒；若平台读数非正则使用 1，仅用于满足诊断字段，不参与排序或物理成功。控制块内另设一把生命周期发布串行锁和唯一物理投影状态；序号、前态和当前态只在该串行器中分配，8110 发布调用不得持有候选见证锁。正常路径固定为“创建 -> 启动中 -> 运行中 -> 停止请求中 -> 收尾中 -> 退出前 -> 已退出”；入口故障从当时物理态进入“故障 -> 收尾中 -> 退出前 -> 异常退出”。每次物理转换都消耗一个递增事件序号，即使对应发布未接受也不回退或复用序号。

成功构造物理线程后，线程包装唯一负责“启动中 / 运行中”和正常或故障终态链；回收方只在 `request_stop()` 后立即、至多一次发布“停止请求中”。包装必须在同一个生命周期串行区内连续处理启动中与运行中，回收方不能插入两者之间。若回收方先取得串行器并已把物理态推进到停止请求中，包装跳过启动中/运行中，但仍取得系统线程 ID、原子发布内部 `已进入`，再调用带已请求停止令牌的入口；因此早停不会产生非法投影转换，也不会形成合法的完成未进入结果。

若入口随后故障，包装从“停止请求中”继续发布“故障 -> 收尾中 -> 退出前 -> 异常退出”，不得再发布一条正常停止链；若入口正常响应停止，则继续发布“收尾中 -> 退出前 -> 已退出”。包装在同一个生命周期串行区内完成整条终态链，回收方不能插入故障、收尾、退出前和终态之间。终态发布尝试全部完成后，包装才原子发布内部 `已完成` 见证并唤醒等待方。只有 `std::jthread` 尚未形成的创建失败由创建方串行发布同一完整异常终态链；不存在两个发布者竞争同一序号或终态的路径。

### 4.2 进入见证

`等待支持线程进入见证` 只等待共享控制块中的内部 `已进入` 或 `已完成`，使用 `steady_clock` 形成单调等待预算，不读取 8110 当前投影、不依赖日志，也不轮询 `std::thread::id`。正式线程包装必定先发布 `已进入` 再调用入口，因此不存在合法的“已完成但未进入”结果；若内部见证出现该组合，返回 `内部不一致`。超时返回仍把候选租约留在调用方，调用方必须随后移动到回收函数；超时本身不授权 detach、销毁入口端口或丢弃租约。

### 4.3 回收

回收固定执行：

```text
锁存 stop request
-> std::jthread::request_stop()
-> 经唯一生命周期串行器检查物理投影是否仍可进入停止请求中
-> 可进入时立即且至多一次最佳努力发布停止请求中；已停止或已终态时零发布
-> 等待具体入口返回、完成终态发布尝试并发布内部完成见证
-> join
-> 标记已连接
-> 返回最终值式见证
```

`诊断等待毫秒` 只决定结果是否标记“超过诊断预算”，不是硬取消时限。预算到期后仍必须继续等待并 `join`；禁止 detach、把 joinable 线程遗留给上层、覆盖租约或让入口/生命周期端口先析构。入口返回 `内部故障` 时以异常退出投影收口，但不升级为任何业务失败。若包装已在回收取得生命周期串行器前完成 `已退出` 或 `异常退出`，回收仍调用 `request_stop()`，但停止投影守卫返回零操作：不消费事件序号、不调用 8110 端口、不增加 `生命周期投影未接受次数`；已经是停止请求中时同样零重复发布。

回收首先确认移动取得的是仍持有 joinable 物理线程的有效租约；空、已移动或已连接租约返回 `内部不一致` 和默认见证，不再调用端口。有效租约无论回收请求是否有效都必须完成安全连接。最终状态优先级固定为：安全连接事实或最终见证不一致 -> `内部不一致`；请求无效 -> `请求拒绝但已安全连接`；入口故障 -> `入口故障已安全连接`；超过诊断预算 -> `超过诊断预算后已安全连接`；否则 -> `已安全连接`。低优先级条件不得覆盖高优先级结果。

租约析构只作最后安全网：若仍持有 joinable 候选，执行同样的请求停止和连接；这不是正常支持线程组收口成功证据。正常调用方必须显式回收或把成功租约移交给后继支持线程所有者。

回收函数和租约析构不得由候选线程自身调用；具体入口不持有租约，正常依赖图因此无法形成自连接。具体线程所有者必须把入口端口依赖、入口使用的队列/状态、生命周期端口声明在租约之前，并在自身析构体中先显式停止连接，确保这些借用对象在租约销毁后才析构。

## 5. 并发、状态与诊断责任

- 控制块的候选见证使用一把 mutex 和一个 condition_variable；锁内只更新候选见证并通知，不调用入口、生命周期端口、日志、DATA 或用户回调。生命周期发布另用一把不可重入串行锁，只负责物理投影状态、序号和对已发布 8110 端口的一次短调用，不与候选见证锁嵌套。传入端口必须遵守 8110 的非长期阻塞边界，且不得回调本候选的创建、等待、回收或见证读取；生产只传入 `79802aa5` 的正式发布端口。
- 具体入口只接收 `std::stop_token`，不得取得租约、控制块、生命周期序号或 join 权。
- 生命周期序号由本模块按物理状态单调分配；一次发布未接受也不回退序号，允许 provider 形成可解释前向缺口。
- 创建结果不复制某一瞬间的“投影已降级”布尔值；创建后全部同步/异步非接受统一累计在租约见证的 `生命周期投影未接受次数`，调用方按需读取当前值式见证。
- `创建支持线程候选`、等待和回收均为最终运行基础设施边界，结构化返回向上送出；本模块不写日志。合法超时、投影降级和入口故障不得记录为业务逻辑错误。
- 具体支持线程不得再次拥有线程对象或声明另一份进入/完成见证；其唯一职责是实现 `运行线程入口` 并服从停止令牌。

## 7. 验证矩阵与完成边界

- 零版本/运行代次/逻辑身份、未知或非支持线程类别—模块配对拒绝且零线程；
