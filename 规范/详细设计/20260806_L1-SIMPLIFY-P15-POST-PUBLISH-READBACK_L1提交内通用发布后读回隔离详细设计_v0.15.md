## 1. 裁决与边界

v0.15 替代并禁止施工 v0.14。保留 v0.14 已冻结的 L1 provider 身份
`0x4C31464200000001`、合同版本 `2`、规则版本 `0`，以及模式、共享操作标签、provider 前探测、一次提交、发布后读回、32 个生产/业务场景行、18 个自检调用行、50 个物理调用点和 16 个调用文件映射。本版本只裁决 I02、F02、X02 中非 L1 provider 无稳定身份的问题，并把其物理来源、版本、调用次数、去重见证数量、恢复拒绝和白名单冻结为可施工合同。

当前正式代码没有可读取的 P-I/P-S 稳定身份 DTO 或接口：`L1可重建索引` 只有合同/规则版本，`L1场景结构` 只有结构事实与世界规则版本。索引键、事实节点、场景标记、世界登记身份和服务事实身份都不是 provider 身份。以下新增接口是待实现设计合同，不是当前能力或执行 WIP 的事实。

## 2. 两个非 L1 provider 的唯一身份来源

P-I 与 P-S 不并入 L1 provider，也不互相合并；每个 provider 只有一个身份读取入口。身份值由各 provider 身份域静态分配，不从实例、节点、索引键、场景事实或调用序号推导。

| provider | 稳定身份 | 合同/规则版本 | 唯一读取入口 | DTO/实现物理位置 |
| --- | --- | --- | --- | --- |
| P-I：L1 可重建索引 provider | `0x4C31495800000001` | `1/1` | `L1事实可重建索引::读取提供者身份() const noexcept` | DTO `核心/L1可重建索引.数据.h`；声明 `核心/合同.L1可重建索引.ixx`；实现 `核心/索引.L1事实基座.ixx` |
| P-S：L1 场景结构 provider | `0x4C31534300000001` | `2/1` | `L1场景结构服务::读取提供者身份() const noexcept` | DTO `领域/L1场景结构.数据.h`；声明/实现 `领域/服务.L1场景结构.ixx` |

两 DTO 均为 `{稳定身份(U64), 合同版本(U32), 规则版本(U32)}`。读取入口 public、只读、`const noexcept`，服务实例构造后恒定至销毁；不读 L1 事实、索引视图、场景事实或世界登记，不改变代次，不分配身份，不持锁。P-I 的 `(1,1)` 只表示索引合同/重建规则；P-S 的 `(2,1)` 只表示场景结构合同/世界结构规则。任何零值、未知值、合同/规则版本不匹配、同一实例两次返回不一致均在 provider 读取后、写入前入口拒绝。

P-L1-S/P-L1-F/P-C 仍合并为 v0.14 的唯一 L1 provider；P-I/P-S 不得借用 L1 身份。身份见证按稳定身份升序编码，provider 调用次数和去重后的身份见证数量分开记录。

## 4. 摘要、恢复和静态拒绝

首次执行证据的 provider 版本组项目固定为 `(稳定身份,合同版本,规则版本,调用次数)`，按稳定身份升序；P-I、P-S、P-L1-* 各自独立，L1 内部仍按 v0.14 合并。写前见证组按对象种类和稳定编码升序，保留共同事实截止。请求意图摘要不包含 provider 身份；provider 身份只进入首次执行证据摘要、幂等账、成功审计和恢复材料的规范化编码。

恢复候选必须从上述真实 provider 读取入口重算：

1. 缺身份、零值、未知身份、错误合同/规则版本、同一 provider 身份重复或身份与读取结果不等，返回 `材料不完整`；不得从索引键、事实节点、场景标记、世界登记身份或服务事实身份补造。
2. 调用次数必须等于逐点首次读取次数，去重数量必须等于唯一稳定身份数；两账、成功审计和摘要字段不一致，或排序/共同截止不一致，返回 `内部不一致` 并隔离。
3. 同义重试只读账与发布后读回，provider 调用/去重均为 `0/0`；异义、入口拒绝和隔离不带业务载荷，不推进代次。
4. P-I/P-S 接口不存在、返回缺字段或版本错时，恢复候选不可降级为 v0.14 的单 L1 身份模式；必须拒绝，直至真实接口和材料补齐。
