## 2. 正式代码事实与唯一入口矩阵

正式代码的三个物理 L1 标签必须按真实调用保留：`0x15000401` 是共享 `提交实例写集(L1事实基座服务&, const L1写集请求&)` 的标签，初始场景和实际存在两种建立请求共同经过它；`0x15000402` 只属于 `建立登记(const 实例特征登记请求&)`；`0x15000403` 是共享 `提交I64当前值换代写集(...)` 的标签，初始场景与实际存在两种换代请求共同经过它。共享底层标签不使不同公开 DTO 成为同一业务操作。

下表是 v0.20 唯一施工矩阵。F 编号只是审计点别名，不是新增机器标签；首次结果必须按公开函数真实返回类型映射。

| 点 | 真实公开函数 | provider 前公开请求 DTO | 物理 L1 标签/变体 | 首次结果 DTO | 同义/异义与恢复 |
|---|---|---|---|---|---|
| F01 | `建立登记(const 实例特征登记请求&)` | `实例特征登记请求` | `0x15000402` / 变体 `1` | `实例特征登记结果` | DTO 全字段相等同义；任一公开字段差异、错标签或改用初始建立 DTO 均异义拒绝 |
| F02 | `建立初始场景I64实例特征(const 初始场景I64实例特征建立请求&)` | `初始场景I64实例特征建立请求` | 共享 `0x15000401` / 变体 `1` | `I64实例特征结果` | 不得映射为 `实例特征登记结果`；同义读回使用首次 I64 结果，异义或错误 DTO 拒绝 |
| F03 | `建立实际存在I64实例特征(const 实际存在I64实例特征建立请求&)` | `实际存在I64实例特征建立请求` | 共享 `0x15000401` / 变体 `2` | `I64实例特征结果` | 与 F02 即使字段值相同也因 DTO 变体不同而异义；恢复不得互换首次 DTO |

## 3. G4 确定性摘要合同

公共原语仍唯一位于 `海中鱼巣/核心/L1事实基座.数据.h` 的 `L1确定性编码内部`；领域函数位于 `海中鱼巣/领域/服务.L1实例特征.ixx`，只读、无锁、无事实写入。公共域前缀为 `HZY-L1G4`，格式版本为 `1`，网络大端，所有嵌套 DTO 按声明顺序递归编码。

摘要根字段顺序固定为：`域前缀`、`格式版本(U32)`、`物理 L1 标签(U32)`、`公开 DTO 变体(U8)`，随后是对应请求 DTO 的全部公开字段。F02/F03 的 0x15000401 共享标签必须依靠变体 `1/2` 区分；F03-T1/F03-T2 的 0x15000403 同样依靠变体 `1/2` 区分。变体不是新的 L1 提交标签，也不改变底层写集。

DTO 字段顺序固定如下：

```text
F01 实例特征登记请求：合同版本、规则版本、幂等身份、期望事实代次。
F02 初始场景I64实例特征建立请求：合同版本、规则版本、幂等身份、期望事实代次、宿主(初始场景读取请求)、定义(I64特征定义读取请求)、初始值(I64)、来源节点。
F03 实际存在I64实例特征建立请求：合同版本、规则版本、幂等身份、期望事实代次、宿主(实际存在读取请求)、定义(I64特征定义读取请求)、初始值(I64)、来源节点。
F03-T1 I64实例特征当前值换代请求：合同版本、规则版本、幂等身份、期望事实代次、当前事实(I64实例特征读取请求)、新值(I64)、新来源节点。
F03-T2 实际存在I64实例特征当前值换代请求：合同版本、规则版本、幂等身份、期望事实代次、当前事实(实际存在I64实例特征读取请求)、新值(I64)、新来源节点。
```

`I64实例特征读取请求` 的嵌套顺序为合同版本、规则版本、宿主、定义、实例槽、宿主关系、定义关系、当前值、来源节点；`实际存在I64实例特征读取请求` 同序但宿主为实际存在读取请求。optional/variant/vector/array、稳定编码、整数端序和 SHA-256 继续沿用 G1—G8 公共原语，结果 DTO/provider/写前见证/执行证据不进入领域意图摘要。

## 4. 预探测、G0 互证、同义/异义与恢复

每个 F 点严格执行：先以真实公开请求 DTO 和固定变体形成 G4 摘要 → 立即调用 `探测幂等` → 只有 `未找到` 才读取场景、定义、实际存在、L1 或其它 provider → 形成独立 G0 规范化写集摘要 → 互证标签、变体、版本、领域摘要和 G0 摘要 → 一次 L1 v2 提交 → 首次结果 DTO/发布后读回。核心不得用 G0 写集覆盖调用方摘要。

同一点、同物理标签、同公开 DTO、同变体且全字段字节相等才是同义；provider/提交调用 `0/0` 并读回首次结果。F02 与 F03、F03-T1 与 F03-T2 即使底层标签相同，变体或 DTO 类型不同即异义。缺字段、字段顺序/类型错误、变体错误、标签错误、摘要与 G0 混淆、首次账/审计/读回不一致均入口拒绝或隔离，零业务载荷。

恢复必须从首次账保存的真实公开 DTO、物理标签、变体和首次结果 DTO 重算；不得用 `实例特征登记结果` 代替 F02 的 `I64实例特征结果`，不得用 F02/F03 或两种换代 DTO 互换。G1—G6 的身份/版本/调用去重、模式 1/3 空组和 32/18/50 矩阵不变。
