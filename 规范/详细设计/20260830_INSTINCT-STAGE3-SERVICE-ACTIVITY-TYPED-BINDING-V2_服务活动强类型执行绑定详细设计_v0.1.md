# INSTINCT-STAGE3-SERVICE-ACTIVITY-TYPED-BINDING-V2 服务活动强类型执行绑定详细设计 v0.1

日期：2026-08-30

设计身份：`INSTINCT-STAGE3-SERVICE-ACTIVITY-TYPED-BINDING-V2`

## 1. 目标与完成边界

在现有唯一 `服务合同事实权威服务` 内，为服务合同关联进展和服务准备事实建立 v2 强类型执行绑定，使后继有效活动裁决能够按同一事实截止 `G0` 回到 task owner 独立互证当前正式选择、执行绑定冻结材料、实例方法和执行轮次。

现有 v1 进展 / 准备事实中的 `服务进展执行冻结见证身份_v1`、`服务进展方法执行见证身份_v1`、`服务进展安全门禁见证身份_v1` 只是本 owner 内的稳定编码包装，当前没有任何任务、方法或安全公开入口能够按这些身份读回正式事实。v2 禁止把它们转换、别名或数值比较为外部 owner 身份。

本叶只建立中性强类型引用、独立 v2 当前索引和完整集合读回，不裁决有效服务活动，不证明方法正在执行，不计算安全权限，不新增安全门禁事实 owner，不接生产进展 / 准备发布者，不调用单完整秒规则内核，不写 A、V、状态、动态或维护游标。

当前生产安全根定义版本 1 保持不变：值域 `0..I64_MAX`，`L=2,767,011,611,056,432,742`，`H=7,378,697,629,483,820,645`。“浮动”只表示以后可以发布新的定义版本；本叶不得改变当前定义或增加运行期自动调节。

## 2. 正式依据与当前事实

正式依据：5230 的执行冻结当前性与冻结后门禁分账、6150 的真实派发前 fresh 调度投影、6170 第 5 节有效活动五项合取，以及现有服务进展 / 准备详细设计的“后继必须独立读回外部引用”边界。

创建基线：`main == origin/main == 783ffa0d4a935673f90ad87418423e44a4addc71`，index 空。

当前已发布能力：

```text
L2任务结构服务::按任务读取当前方法选择
-> 当前正式选择记录
-> 执行绑定冻结材料事实
-> 当前实例方法事实与执行轮次

L2方法结构服务::读取普通方法
-> 当前方法内容、规格和生命周期事实

L2状态结构服务::读取完整状态
L2动态结构服务::读取完整动态
-> 可按强类型身份和 G0 独立读回进展证据
```

当前缺口：v1 服务事实没有保存上述真实 owner 身份；安全权限只有纯值算法和输入协议，没有可按 v1 安全见证身份读取的正式事实。未提交 SELF-GOVERNANCE WIP 不作为本设计能力。

## 3. 复用、依赖与版本策略

继续复用同一 owner、同一数据头、同一服务模块和同一专项，不新建模块或工程登记：

```text
海中鱼巣/领域/服务合同事实权威.数据.h
海中鱼巣/领域/服务.服务合同事实权威.ixx
海中鱼巣/端到端测试.服务合同事实权威.ixx
```

服务模块新增对 `海中鱼巣.领域.服务.L2任务结构` 的公开模块依赖，只为导出 task owner 已有强类型身份；服务合同 owner 不持有、构造或解释 task owner 事实。

版本规则：

1. v1 类型、键段、登记、读取函数和结果谓词保持源码与持久兼容；
2. v2 使用独立结构登记、当前索引、载荷和关系类型；
3. v1 事实不自动投影到 v2，v2 读取不得回落 v1；
4. 进展 / 准备事实的业务稳定身份沿用现有身份类型，通过别名 `服务进展事实身份_v2`、`服务准备事实身份_v2` 表达，不建立第二业务身份；
5. 当前生产没有进展 / 准备发布者，因此生产 v2 合法空集合只是“尚无 v2 事实”，不得解释为不存在有效活动。

## 4. 强类型执行绑定

```cpp
inline constexpr std::uint32_t 服务活动强类型执行绑定合同版本_v2 = 2;

struct 服务活动任务执行绑定_v2 final {
    L2任务方法选择记录身份 正式选择;
    L2任务执行绑定冻结材料身份 执行冻结材料;
    L2实例方法身份 实例方法;
    std::uint64_t 筹办轮次;
    std::uint64_t 执行轮次;
};
```

完整性要求三个身份均有效且筹办轮次、执行轮次非零。该结构只引用 task owner 事实，不复制选择、冻结或实例内容。

后继裁决必须用进展 / 准备事实的 `任务` 和 `G0` 调用 `按任务读取当前方法选择`，并逐项证明：

```text
正式选择.记录.身份 == 绑定.正式选择
正式选择.任务 == 事实.任务
正式选择.方法 == 事实.方法
正式选择.记录.筹办轮次 == 绑定.筹办轮次
正式选择.冻结材料 == 绑定.执行冻结材料
冻结材料.身份 == 绑定.执行冻结材料
冻结材料.材料.筹办轮次 == 绑定.筹办轮次
实例方法.身份 == 绑定.实例方法
实例方法.任务 == 事实.任务
实例方法.来源方法 == 事实.方法
实例方法.筹办轮次 == 绑定.筹办轮次
实例方法.执行轮次 == 绑定.执行轮次
实例方法.来源方法内容版本 == 事实.方法内容版本
```

空当前选择、0/N 复义、任一错绑或漂移都不能降级为“活动不存在”。

## 8. 后继有效活动裁决边界

v2 强类型绑定只解除任务选择 / 冻结 / 实例引用不可读问题。后继活动裁决仍必须在同一 `G0`：

1. 读取服务合同或服务准备完整事实；
2. 读取 task owner 当前选择、冻结、实例和正式 T→D 关系组；
3. 读取 method owner 当前方法和三类版本 / 生命周期；
4. 按状态 / 动态身份读取完整事实，验证时间窗、主体、特征和来源；
5. 从正式安全事实来源 fresh 形成当前安全门禁结论；不得使用 v1 安全见证、历史门禁结果、日志或裸 bool；
6. 排除暂停、等待、阻塞、失败、取消、到期和终止；
7. G0 读后守卫后才能输出存在 / 不存在。

安全门禁不进入服务事实 v2 持久布局，因为它是 G0 当前投影，不是服务 owner 的第二权威。当前尚无完整生产安全门禁 provider，因此本叶完成后有效活动组合器仍不得施工。

## 9. 验证矩阵

至少覆盖：

1. v1 ABI、登记和读取回归不变；
2. v2 进展 / 准备 0 项合法完整成功；
3. N 项规范排序和完整成员见证；
4. 三个身份、筹办轮次或执行轮次无效，以及错关系、漏关系、多关系、错端点；
5. v1 成员不得出现在 v2 结果，v2 读取不得回落 v1；
6. 状态 only、动态 only、两者同时存在和两者都空拒绝；
7. 准备来源二选一、T→D 形状、完成结果 / 验证形状；
8. 时间窗、规则版本、形成代次和生命周期边界；
9. 读前 / 读后漂移、结构未登记、资源失败和内部错误空载荷；
10. Debug / Release 根工程、专项、Debug ABI consumer、Release `/GL + /LTCG` ABI consumer、strict 与两类 diff-check；
11. 静态确认生产 L/H 未改、没有新 owner / 模块 / 工程登记、没有安全门禁写入或有效活动裁决。

## 10. 完成声明边界

本设计完成只证明服务进展 / 准备 v2 能保存并完整读回 task owner 的真实强类型选择、冻结、实例和执行轮次引用。它不证明生产发布者已接线、方法正在执行、T→D provider 已发布、安全门禁允许、状态 / 动态属于本次执行、有效服务活动成立、阶段三或 `INSTINCT-ROUTE` 完成。
