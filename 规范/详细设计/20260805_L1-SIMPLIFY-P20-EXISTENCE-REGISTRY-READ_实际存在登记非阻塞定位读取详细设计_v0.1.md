# L1-SIMPLIFY-P20-EXISTENCE-REGISTRY-READ 实际存在登记非阻塞定位读取详细设计 v0.1

## 1. 身份、目标与完成边界

计划身份：`L1-SIMPLIFY-P20-EXISTENCE-REGISTRY-READ`

版本：`v0.1`

创建侧正式代码基线：`bc12bb3cbe4fc6aaa920135634266952479ff3c0`

本叶是 SELF-GOV-CLOSURE STEP-4 在 P19 之后发现的更早非阻塞定位缺口。它只原位扩展 P7 冻结的唯一 `L1实际存在服务`，为不可变 `实际存在结构登记` 增加版本化、纯值式、一次 try-lock 的 `尝试读取当前登记`。后继实际存在资格集合读取将用本入口取得存在服务身份和资格属性类型，再在 P17 的一个非阻塞 L1 快照中解释当前实际存在资格。

完成必须同时成立：

- 输入明确合同版本和实际存在规则版本；
- 许可竞争立即返回 `许可拒绝`，不等待、不 sleep、不重试；
- 登记未加载、登记损坏、资源失败和内部异常结构化分账；
- 成功只返回 P7 已建立并完整验证的登记副本，不扫描 L1、不查询 SQL、不猜测稳定编码；
- P7 既有阻塞兼容入口和本入口复用唯一私有已持锁复制/完整性判断；
- 明确登记中的 `事实截止代次` 只见证登记首次建立时的读回，不是当前世界快照截止代次。

本叶不调用 P17、不读取任何实际存在资格事实、不读取场景归属，不形成存在集合、存在详情、完整世界快照或统一世界门面。

## 2. 正式依据与只读能力矩阵

正式依据：

- 1140：实际存在身份和允许场景归属必须由具名事实读回验证，不能由普通节点或名称自动推出；
- 4190：实际存在资格与治理虚拟存在资格严格分账；跨事实所有者只通过具名、版本化、强类型公开函数交互；
- 4015、4030：L1 返回业务中性值式事实，领域服务不泄漏仓库、锁、许可、事务或句柄；
- 4200 §5.1、§6：每个领域读取必须提供非阻塞许可拒绝，普通世界快照不得由 L2 直接解析 L1；
- P7 v0.1：已冻结 `实际存在结构登记`、唯一 `L1实际存在服务` 和阻塞式 `读取当前登记()`，但尚未实现；
- P17 v0.1：已冻结非阻塞 L1 完整快照与当前事实代次读取；
- P19 v0.1：已冻结指定根当前成员结构读取，但成员目标只证明结构归属，不自动具备实际存在资格。

旧存在服务、旧节点直接仓、旧 WORLD-TREE 计划、旧句柄和对象版本只作负面证据，不迁移、不包装。

## 4. DTO、公开函数与唯一私有实现

在 P7 的 `L1实际存在.数据.h` 追加：

```cpp
struct 实际存在登记读取请求 final {
    std::uint32_t 合同版本 = L1实际存在合同版本;
    std::uint32_t 规则版本 = L1实际存在规则版本;
    friend bool operator==(const 实际存在登记读取请求&,
        const 实际存在登记读取请求&) = default;
};

inline bool 实际存在登记读取请求有效(
    const 实际存在登记读取请求& 请求) noexcept {
    return 请求.合同版本 == L1实际存在合同版本
        && 请求.规则版本 == L1实际存在规则版本;
}
```

复用 P7 冻结的稳定状态和结果，不建立第二结果类型：

```cpp
enum class 实际存在状态 : std::uint8_t {
    已提交 = 1, 幂等读回 = 2, 已读取 = 3, 未找到 = 4,
    入口拒绝 = 5, 幂等冲突 = 6, 版本漂移 = 7,
    许可拒绝 = 8, 资源失败 = 9, 内部不一致 = 10
};

struct 实际存在登记结果 final {
    实际存在状态 状态;
    std::optional<实际存在结构登记> 登记;
};
```

新增公开函数：

```cpp
实际存在登记结果 L1实际存在服务::尝试读取当前登记(
    const 实际存在登记读取请求& 请求) const;
```

在服务内形成唯一私有：

```cpp
实际存在登记结果 复制已持锁当前登记() const;
```

私有函数只允许在调用方已经持有 P7 服务内部 `锁_` 时调用。P7 既有阻塞 `读取当前登记()` 取得阻塞锁后调用它；新增入口取得 try-lock 后调用它。未加载返回 `未找到`；登记不完整返回 `内部不一致`；完整时逐字段复制并返回 `已读取`。

登记完整性固定要求：合同/规则版本匹配；首次幂等身份有效；`事实截止代次` 非零；服务身份和实际存在资格属性类型稳定编码均非零且互异。该校验只验证缓存形状，不重新读取 L1 当前生命周期。

## 5. 固定读取算法

`尝试读取当前登记` 固定执行：

1. 在锁外校验请求合同版本和规则版本；错误返回 `入口拒绝`、空登记，锁尝试0；
2. 用 `std::unique_lock<std::mutex>{锁_, std::try_to_lock}` 尝试一次 P7 服务内部许可；
3. 未取得许可立即返回 `许可拒绝`、空登记；不等待、不 sleep、不循环；
4. 取得许可后调用唯一 `复制已持锁当前登记`；
5. 未加载返回 `未找到`；坏登记返回 `内部不一致`；完整登记返回 `已读取` 和逐字段副本；
6. 返回前释放锁，不外泄锁、引用、指针、许可或可写登记。

成功副本逐字段保持 P7 首次发布后读回结果：合同/规则版本、首次幂等身份、登记验证事实代次、服务身份和实际存在资格属性类型。

本入口不调用 L1，因此不返回当前事实截止，不校准两个登记节点的当前生命周期，也不产生 `版本漂移`。后继必须在 P17 同一纯值快照中互证服务身份是当前普通节点、资格属性类型是当前 I64 属性类型节点，并把 P17 快照代次作为领域结果截止。

## 6. 状态、异常、并发与生命周期

| 条件 | 状态 | 登记载荷 | 副作用 |
| --- | --- | --- | --- |
| 合同或规则版本错 | `入口拒绝` | 空 | 锁尝试0 |
| 服务锁竞争 | `许可拒绝` | 空 | 零等待、零重试 |
| 登记未加载 | `未找到` | 空 | 不扫描、不补造 |
| 登记缓存不完整 | `内部不一致` | 空 | 不返回部分登记 |
| 完整登记 | `已读取` | 完整副本 | 零写入 |
| 复制分配失败 | `资源失败` | 空 | 零写入 |
| 其它异常 | `内部不一致` | 空 | 零写入 |

`幂等冲突`、`版本漂移` 不是本读取入口的正常输出分支。`事实截止代次` 在登记建立后不可变，只证明定位身份曾在该代次建立并读回；后续实际存在、场景、特征、状态或动态事实推进不更新它。调用方不得用它替代 P17 当前截止、G0/G1、排序或漂移裁决。

P7 `建立登记` 或既有阻塞读取持锁时，新入口立即许可拒绝。多个非阻塞读取同时竞争普通 `std::mutex` 时至多一个成功，其余允许许可拒绝；调用方不得要求所有并发读均成功。本叶不建立 retry、缓存、恢复装载、SQL 回源或默认登记。

## 7. 验证矩阵

执行至少验证：

1. 合同错、规则错在锁外入口拒绝，锁尝试0；
2. 新服务实例登记未加载，返回未找到且不扫描共享 L1；
3. P7 登记建立后新入口返回完整副本，逐字段等于建立结果和既有阻塞读取结果；
4. 相同登记重复读取逐字段确定相等，L1事实代次不推进；
5. Debug 同步夹具持有服务锁时立即许可拒绝，零等待、零 sleep、零重试；释放后再次成功；
6. Debug 坏登记夹具覆盖零/重复编码、错版本、零幂等身份和零验证代次，均返回内部不一致且无部分登记；
7. 资源失败与其它异常准确映射；
8. 既有 `读取当前登记()` 保持阻塞兼容语义，新旧入口复用唯一私有复制/完整性判断；
9. P7 登记、资格、创建和组合读回既有专项不退化；
10. Debug/Release x64 串行 Rebuild、两配置退出式完整自检、strict、MSVC 模块扫描和目标 diff check 全部通过。
