## 1. 本叶目标、正式依据及边界

依据5360 v0.13第2.1、3.1节、5370 v1.5第5.3节、5350第6节及本窗口用户裁决：方法自己声明正式输入限定；通用学习根据同一种结构构造隔离输入，不按方法名另写条件生成器。v25已经补齐三种旧声明分量的原子登记提供者。本叶扩展该提供者及其实际学习消费者，交付“消息信息的合法载荷、位置关系与时序声明→通用候选→模拟世界中的消息事实/待触发事件”。

本叶有两种写入，不能混写为同一动作：

1. M/Vm声明的内部结构治理：补充未有C/R方法的空消息输入方案分量，为通用学习提供可读构造依据；不修改固定七参数，不生成方法效果。
2. 隔离模拟实例的信息更新：按选中方案把消息加入本地窗口的消息F，事实owner据实际当前值变化形成本地S/D，供原函数后续读取；这是环境输入，不是原函数动作或方法结果。

不改变现实世界存在、窗口、外设、网络、任务或方法运行统计。概念定义可以共享，实例全部本地化。没有连接隔离后端之前，原函数模拟入口仍准确拒绝；输入生成完成不等于连接学习完成。输出队列入列/领取的中间动态R消费、隔离后端的实际发送、动作身份、连接许可及R14结果取得均不在本叶实现。

## 3. 统一声明合同

### 3.1 信息类型与事件不是本能方法类型

消息是一种信息构造形状，不是“建立连接事件”。本叶支持的构造是：生成一个正式消息信息节点，并把其身份加入指定消息集合F。时机只使用通用“调用前”或“某参数出现新增正式消息事实后”，不出现“连接第二阶段”“收到握手确认”等函数阶段名。后续相同形状的方法直接声明同一DTO即可；非消息信息构造将来可扩展，但本叶不虚称任意信息类型均已支持。

在`新_方法公共类型.h`声明以下值式类型，复用`消息交互.数据.h`现有的`新外设消息方向`身份。该头经`新_动态类.h→概念_动态类.h→动作概念.只读投影合同.h`确实回指方法公共类型，因此公共类型头不得include消息交互头，只作固定底层类型的枚举前置声明；需要枚举项的cpp在公共头之后include消息交互头。两个方向成员的零初始化明确是非法待填值，原函数声明时必须显式填写，不能默认为发送或接收。无需新建方向文件、复制方向枚举或扩大工程：

```cpp
enum class 新外设消息方向 : std::int64_t;
enum class 新方法模拟输入时机 : std::int64_t {
    调用前=1, 参数新增消息后=2
};
struct 新方法模拟消息触发 final {
    std::uint32_t 特征参数序号=0;
    新外设消息方向 方向{};
    friend bool operator==(const 新方法模拟消息触发&,
        const 新方法模拟消息触发&)=default;
};
struct 新方法模拟消息输入定义 final {
    std::uint32_t 顺序=0;
    std::uint32_t 目标特征参数序号=0, 窗口存在参数序号=0, 对端存在参数序号=0;
    新外设消息方向 方向{};
    稳定编码 正文范围概念;
    bool 正文非空=false;
    新方法模拟输入时机 时机=新方法模拟输入时机::调用前;
    std::optional<新方法模拟消息触发> 触发;
    friend bool operator==(const 新方法模拟消息输入定义&,
        const 新方法模拟消息输入定义&)=default;
};
struct 新方法模拟输入方案定义 final {
    std::uint32_t 顺序=0;
    std::vector<新方法模拟消息输入定义> 消息组;
    friend bool operator==(const 新方法模拟输入方案定义&,
        const 新方法模拟输入方案定义&)=default;
};
```

`新方法知识建立请求`及`新方法信息`各增加`std::vector<新方法模拟输入方案定义> 初始模拟输入方案组`。读取DTO不公开声明子树的可写节点引用；复制时按方法owned图复制附属结构。外层方案是OR候选，逐方案分别构造；单方案消息组是该环境样例的事件配置，不表示全部输入已发生，也不成为长期C的AND条件。方案为空保持旧无消息方法行为。每方案至少一项，方案和项的顺序均从0连续；不得将两个可选方案合成一份必要输入链。

参数位置只能引用固定规格中的正式位置，不能引用临时样例节点或私有配置槽：

- 目标是特征，概念须为U64数组且比较规则为消息集合身份判等；当前本叶只支持全材料消息集合域。其它消息集合域明确未支持，不能忽略限定。
- 窗口、对端是存在；目标F必须通过正式`特征所属存在`关系归于该窗口位置，不能因相邻、FT同名或读取顺序推断。
- 正文范围必须是可读正式UTF8特征概念，比较为完整材料精确；支持全材料域或有限完整材料枚举。非空是这一输入的明确构造限定，不变造新FT，不把字符串编码长度当方法结果。其它域返回参数规格不合法或学习规格未支持，不能选默认文本绕过。
- 调用前必须无触发；参数新增消息后必须有且仅有一个触发，触发位置必须也是消息集合F，且经相同正式所属关系归于同一窗口位置；触发方向及输入方向只允许接收/发送，输出队列的输出方向不由本叶模拟。
- “对端”确定本次模拟通信通道的另一端，不宣称它是人类、服务对象或已确认连接对象；记录来源不能替代身份判断。触发必须属于同一本地窗口、同一对端通道，不仅比较FT。
- 合法前提发生变化则返回明确前提变化，不被解释为“未登记”或偷偷重建。

本叶不增加执行分支限定字段；输入方案对本方法现有各执行分支均是可选环境候选，每次仍以实际执行分支条件过滤。将来某输入仅适用特定执行分支时需正式扩展，不以方案顺序冒充执行分支身份。

### 3.2 无C/R原子补齐

`初始模拟输入方案组`作为第四个受支持分量加入v25同一预检和原子发布。既有非空组必须完整相等，包括顺序、方向、位置、概念、非空及触发；请求为空不表示保留。已有C/R而该分量为空时拒绝补齐；不追改知识。行为、旧关系、整数事件、执行分支和新分量中任一冲突，全部零写。专用必要条件继续原样保留，通用请求`初始必要条件`仍不在本叶变通用。首次新建方法的整体发布同步接受、校验并写入新分量，不只做旧M补空。

## 4. 方法持久布局、保护、复制及退出

`新_方法类.cpp`中新增独立声明schema，不把新键加入旧架构的必需键集合、不重建旧根。键/类型在原方法初始化路径用现有独立扩展方式确保，原有方法无该可选字段读为空组。

```text
Vm --模拟输入方案字段--> P（模拟输入方案节点类型）
P：顺序字段、初始声明所属字段=Vm
P --模拟消息输入字段--> I（模拟消息输入节点类型）
I：顺序字段、初始声明所属字段=P
   模拟消息参数位置字段=I64数组[目标F位置,窗口E位置,对端E位置]
   模拟消息方向字段=I64
   模拟正文范围字段=正式UTF8概念引用
   模拟正文非空字段=I64 0/1
   模拟输入时机字段=I64
   [仅新增消息后] 模拟触发位置方向字段=I64数组[触发F位置,触发方向]
```

没有其它字段；严格检查类型、字段数量、归属、顺序、数组长度及位置边界，缺字段/重复字段不解释为空声明。P/I是Vm独占子结构，概念是共享外部引用，不把概念复制为子节点。新建、补空都用组内引用形成完整子树，再一次DATA-L1原子追加；不先公开P/I再挂Vm。

现`方法复制字段规格`、完整方法读取、DTO相等、执行结构闭包、普通/混合复制、退出现有owned图全部登记上述新类型、字段及独占子节点。概念及其定义保护是共享外部边，不随复制重写或退出删除。补空保护包括原M完整图、Vm、所有旧分量、每个新增字段键/类型/稳定引用端点及正文、目标/触发FT、窗口/对端概念的正式完整定义；概念owner读取在方法锁外完成值式捕获，保护捕获后重校验，提交以同一完整联合快照作CAS。

方法锁内只核同/提交；发布后锁外完整读回原M，新增声明与预期完全相等、原字段不变。复用或并发同义仅按全部声明完整读回消歧；部分存在不继续逐项补写。明确零发布按现状态返回；已发布或不确定且无法完整确认走工程异常链保留事实，不返回普通否定、不自动重试、不删除旧M。

新分量不进入运行C/R问题归档载荷，`方法问题归档.模拟世界`仍归档实际调用材料而非完整M；不无理由升级其格式或塞入环境输入计划。方法当前结构的基础持久恢复按新schema完整读取，无此可选字段的旧方法合法为空；其它owner持久格式不改。

## 5. 通用载荷取样与学习接入

### 5.1 通用UTF8取样

在既有`业务/模拟学习.算法.h/.cpp`新增纯函数，不持有world或方法owner：

```cpp
enum class 通用UTF8取样状态 : std::uint8_t { 已生成=1, 无合法候选, 域未支持 };
struct 通用UTF8取样结果 final {
    通用UTF8取样状态 状态;
    std::vector<std::string> 候选;
    bool 全有限域=false;
};
通用UTF8取样结果 生成通用模拟UTF8候选(
    const 新特征匹配定义快照& 范围, bool 非空,
    const std::vector<新特征值信息>& 有限材料, std::uint64_t 种子);
```

输入的有限材料必须与正式域中的材料身份逐项完整对应，由学习通过`读取模拟候选材料`取得；不是函数/调用方另传的任意样例。算法核物理类型、严格UTF8及精确材料身份，坏材料是工程结构错误，不当作被过滤的不合法业务候选。全材料域必须没有有限材料，统一复用现有UTF8代表政策，取合法非空ASCII句点；允许空串时取空串与句点两个去重代表。非空限定只过滤空串，不要求词义。有限域全部取合法成员、过滤不满足明确非空限定的项、去重并随机排列不放回。无合法候选明确返回，无截断/选首项；非全材料且非有限枚举域明确未支持。

句点只存在于这个通用材料取样函数，不在任何本能函数或world里写死；原函数只声明UTF8范围和非空，不能提交每方法的具体文本库存。全材料域的两代表不证明覆盖所有字符串、所有长度或语义；结果必须保持`全有限域=false`，不得据代表样例把正文全域宣称已经穷尽。现普通UTF8参数的句点构造同步调用此函数，避免新建第二UTF8政策；不改变固定参数或其它类型取样。

## 6. 模拟世界的消息owner与事件推进

### 6.1 来源、窗口、信息与事实边界

消息只属于本样例既有模拟场景，窗口使用规格位置映射的本地E；绝不新建替代窗口绕开第5位置，也不借外设真实窗口。窗口的所属场景从本地实例正式结构取得，不要求硬编码成第1位置；当前一般样例中窗口与其它参数同在本地场景是合法最简情况，不证明现实两个世界合并。消息F由原正式关系绑定到该窗口。

本叶消息集合初始候选为空数组；已有同world本地消息只由本地事实提供者加入。若来源复制上下文或候选材料携带非空现实消息引用，本叶没有真实消息内容/来源/状态的通用复制合同，学习必须在构造前报`规格未支持`，world也须在发布前拒绝，不能把U64数组原样搬进模拟集合。禁止将真实稳定编码当作本地消息身份或悄悄清空它以伪造复制成功；此拒绝只针对尚无重映射提供者的消息引用，已有存在引用/任务等原路径不改。

本地通道键由样例身份、本地窗口身份、对端参数映射身份及方向形成；公开宿主会话使用带模拟来源的确定字符串，框标识由本地窗口与对端身份的确定序列化取得，来源序号由本样例独立单调消息序号分配。编码只作身份序列化，不对节点编码求差值或把它当时间。它们不是现实宿主票据，不传到外设/网络，不能让语言据此确认人类身份。后续隔离后端必须复用这个world本地通道，不另造与输入不相符的来源。

在现world私有schema内使用`消息种类`，消息节点保存窗口、正文材料、方向、来源序号、抽象时间和通道字段；新增必要schema字段放原枚举末尾，不能改变既有序号。正文材料是本地UTF8节点；概念可共享引用，现实材料节点只能复制内容，不能成为可写指针。消息加入目标F的实际当前U64材料，原当前材料归历史，消息身份保留。owner依据实际前后材料形成本地状态和变化动态，方向/当前集合变化真实可读；不伪造原函数动作，不建立动作→变化关系，不写交互者F4、连接过程/许可或R14。

一个消息事件的正文、消息、集合材料、F当前/历史关系及S/D必须在一个DATA-L1组合变化中发布；完整保护已有F/材料/场景/窗口及所有键和引用端点，成功后完整读回才标此事件已交付。前态已存在以实际状态引用为准，无适用前态时在本次真实修改前形成准确前态再形成后态，不从未来预测反填；抽象步骤严格递增、防溢出，工程失败不伪装无变化或输入耗尽。动作不参与环境输入发布。

### 6.2 真实触发、等待和推进

选中方案每个事件存`未交付/已交付`及值式正文，正式结构仍来自方法声明。固定初始化顺序是：基础场景/绑定完整构造并核同→捕获全部待触发事件的基线→按声明顺序发布调用前消息→返回样例。调用前消息允许成为同方案待触发事件的真实触发来源；它不包含在已捕获基线中，但待触发事件仍须等后续`推进模拟输入()`实际检查，不在初始化时递归交付。未配置调用前事件的方案不产生调用前消息。

为每个待触发事件在样例建成时捕获触发F当前及历史中已经存在的本地消息身份作为基线。`推进模拟输入()`扩展读取触发F当前/历史的实际正式消息及状态，以消息身份/本地通道/方向/严格时间检查“基线之后确有新事实”。不比较集合数量，不因历史清理误认新增，不因计划存在或计时到期而制造消息。匹配多个新消息时按抽象事实时间和消息正式来源序号选择最早；同序不同事实是工程冲突，不用编码排序任选。

每次推进最多交付一个已经具备触发事实的消息事件，按声明事件顺序选择首个就绪者；未就绪项不阻止后面独立就绪项，已交付项不再触发。时序为输入消息时间严格晚于实际触发消息时间。一个触发消息允许激活多条分别声明的环境响应，各只一次；这不等于重复消费同一方法动作。没有任何就绪事件时不创建节点。

在既有`模拟学习.数据.h`的`新模拟操作状态`末尾追加`等待触发=5`，不更改原枚举值：

| 现象 | 返回 |
| --- | --- |
| 一项消息或旧整数输入已实际发布读回 | 已完成 |
| 有未交付消息但尚未出现真实触发 | 等待触发 |
| 所有声明输入均已交付，旧整数事件也耗尽 | 输入耗尽 |
| 样例/位置/调用范围不适用 | 输入不适用 |
| world已停止 | 停止取消 |

旧整数事件保持原独立位置/取样语义；先交付就绪消息，没有就绪消息时可推进一项既有整数事件，二者FT类型不同，不凭空设AND依赖。若两类都未推进且仍有待触发消息，返回等待触发。此函数无睡眠、无长期占线程，不轮询现实宿主。现生产无其它直接消费此枚举的函数，实施时仍搜索全调用点，不能把新等待值当成功或耗尽。

新增只读本地信息入口供通用触发及后续隔离后端使用，位于`新_模拟世界类.h/.cpp`，不放方法owner或真实外设类：

```cpp
std::optional<新外设消息信息> 读取模拟消息(稳定编码 消息节点) const;
std::vector<新外设消息信息> 读取模拟消息组(稳定编码 消息特征节点) const;
```

仅接受本样例拥有的消息/F身份，读取当前及历史去重身份。单消息目标不属于本样例或不是消息节点返回不适用的空optional；合法消息节点结构损坏抛工程异常。消息组读取仅合法本地消息F真无消息时返回空vector；外world身份、非特征或非消息FT抛`std::invalid_argument`，结构读取失败抛工程异常，不能以空集合吞错。通用触发先核合法绑定，不把该异常改成“尚无消息”。DTO从节点正式内容读回；缓存若使用只作可重建投影，不成为第二消息仓。v26不新增任意方法发送写接口，后端后继必须按动作来源另行冻结。

### 6.3 生命周期与停止

所有新本地节点、字段、外部边和事件进度归本world样例；记录加入既有`通用节点/字段/外部边`退出集合。候选写集失败未发布时零可见，值式候选释放；已发布读回失败保留事实并中止该样例，不自动重发。样例释放时先关闭调用/事件推进，清除待触发配置及本地读取缓存，再按现有模拟owner退出自己的材料；不能删除共享概念、现实消息或任何其它world节点。重建下一样例不沿用消息序号、触发基线、正文、动作或结果。
