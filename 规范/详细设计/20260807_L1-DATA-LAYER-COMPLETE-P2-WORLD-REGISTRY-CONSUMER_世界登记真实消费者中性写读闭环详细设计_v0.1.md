## 1. 目标与完成边界

本叶选择现有 L2 `世界登记服务` 作为第一位合法真实消费者，把 `世界登记服务::建立空世界` 的世界登记首次写入和 `读取当前登记` 的权威读回迁移到 P1 v0.2 冻结的业务中性 CRUD 公共合同，并在 `生产运行期会话::启动` 的全新候选路径中于旧系统角色初始化之前正式调用。

消费者仍自行拥有世界规则、请求同义、幂等域、世界结构登记和状态解释；L1 只接收 5 个节点、1 个值、1 个属性槽组成的中性写集，返回中性结构化结果并提供精确当前读。世界登记成功后，消费者按稳定编码经中性当前入口重新读取全部登记事实，形成调用方拥有的 `世界结构登记`；运行期候选只有同时取得成功结构化结果和后续权威读回时才可继续。

本叶完成后只证明世界登记这一消费者真实覆盖：首次中性创建、精确当前节点 / 值 / 属性读取、一次写集的原子发布和自身服务结果解释。它不证明更新、退出 / 历史读取、并发可见性、非法 L1 请求零变化、跨消费者幂等竞争、其它消费者、整个 L1 或完整世界树已经闭合。

本叶不建立专用 L1 驱动、L1 自检、独立 L1 验收提交、日志 PASS、第二程序或虚构消费者；不考虑崩溃、重启、断电或跨进程恢复。

### 4.1 请求

```cpp

    std::uint32_t 合同版本 = 世界登记合同版本;       // 固定 3
    std::uint32_t 世界规则版本 = 世界登记规则版本;   // 固定 1
    世界操作幂等身份 幂等身份;                       // 非零、最多 56 位
```

生产固定配置新增 `世界登记建立请求 世界登记`，唯一值固定为合同 3、规则 1、幂等身份 `1`、期望事实代次 `0`。该身份不是系统角色主键、动作键、域编号、日志编号或 L1 稳定编码。

## 5. 中性写集精确映射

`世界登记服务::建立空世界` 只 import P1 正式中性合同，并形成下列 `L1中性写集请求`：

| 本地键 | 中性事实 | 固定字段 |
| --- | --- | --- |
| 1 | 节点 | `普通`；世界结构服务身份 |
| 2 | 节点 | `属性类型`；值表示 `I64`；场景标记属性类型 |
| 3 | 节点 | `普通`；直接父场景关系类型 |
| 4 | 节点 | `普通`；直接成员关系类型 |
| 5 | 节点 | `普通`；世界根场景 |
| 6 | 值 | 所属本地 5、属性类型本地 2、材料 `I64{1}`、来源本地 1 |
| 槽 | 属性槽变更 | 所属本地 5、属性类型本地 2、当前值本地 6 |

请求其余字段固定为：P1 中性合同版本、调用方期望事实代次、映射后的非零中性幂等键；关系新建组和退出组为空。不得携带操作标签、意图组、领域凭证、摘要、执行证据、提供者 / 结果见证、读回计划、审计或恢复材料。

根函数不得先调用 `探测幂等`、`读取完整快照`、审计、恢复、SQL 或旧仓。它恰一次调用 `L1事实基座服务::提交中性写集`；精确重复由 L1 对完整规范化中性写集逐字段比较并返回首次映射。

成功类结果还必须逐字段满足：合同版本为 1、回显幂等键等于本请求最终键、事实代次非零、6 项本地键 / 稳定编码映射各自唯一。`成功` 必须 `是否形成内存权威发布=true` 且重试边界为 `不适用`；`精确重复` 必须 `是否形成内存权威发布=false` 且重试边界为 `原幂等键读回收敛`。任一矛盾都按坏成功返回 `内部不一致`，不得缓存登记。

## 7. 权威读回算法

`建立空世界` 从成功 / 精确重复结果取得 6 项唯一映射、首次事实代次和回显幂等键，形成候选登记后调用同一私有只读辅助。`读取当前登记` 在登记缓存存在时也调用该辅助，不直接返回缓存。

辅助顺序固定：

```text
读取中性当前事实代次 -> 起始代次
按登记稳定编码精确读取 5 个当前节点
读取中性当前属性(世界根场景, 场景标记属性类型) -> 当前值编码
按当前值编码精确读取中性当前值
读取中性当前事实代次 -> 结束代次
逐项校验类型、生命周期、槽、所属、来源、I64 值 1 和全部读取代次
起始代次 == 结束代次 == 登记.已验证事实代次 -> 返回已读取登记
```

任何精确读取的 `未找到 / 已退出 / 属性未设置` 或字段矛盾映射为 `内部不一致`；资源失败映射资源失败；首末或逐项代次不等映射事实代次漂移。不得返回部分登记。缓存只在建立成功且完整权威读回后一次赋值。
