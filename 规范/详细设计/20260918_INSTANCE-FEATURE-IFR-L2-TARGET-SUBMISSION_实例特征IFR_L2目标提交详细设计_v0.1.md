# 实例特征 IFR L2 目标提交详细设计 v0.4

本版完整定义 `实例特征IFR提交状态`、`实例特征IFR目标R项`、`实例特征IFR提交请求` 与 `实例特征IFR提交结果`，其字段、稳定值和成功谓词以配套 v0.3 计划为准；这些类型置于 `数据服务.存在类.h`，与既有 `实例特征IFR读取请求/结果` 同级，不改写其名称或字段。

## 前态、最终成员与状态映射

入口先按 G0 调用 `读取IFR结构`。读取成功时 `预期完整投影` 必须逐字段相等，否则`前态冲突`；读取未找到时仅空预期可继续，且同 G0 的 `确认当前存在结构身份(G0,E)` 与直接 E→IF 空组读回都必须成功。它们的未找到/退出/预算/漂移/资源/内部状态分别映射提交同名状态，其余半结构为`引用冲突`，均零写。

最终 IF成员集不是前态的替代列表，而是 `前态IF成员 ∪ 新增F`。前态每个成员必须仍出现，新增F不能与前态或另一新增F重复，并且逐个先由 `确认当前已知准确特征({1,G0,E,F})` 确认 E 已知准确，再由 `读取有界准确特征事实({1,G0,G0,F,新增F特征读取预算})` 成功确认类型为 FT。目标 R项的形成成员并集必须恰等最终集。输入/预算/幂等身份非法为`入口拒绝`；规范化、成员、材料、role、来源或唯一性冲突为`引用冲突`；同键异义为`幂等冲突`。

## 角色、提交与回显

三条单值关系 role=`1`，三组成员关系对目标稳定编码升序 role=`1..N`；R项材料是 v2 `R项材料属性类型` 的唯一 U64 值且 `来源节点==R项`。首建同次建立全结构；后续仅退出旧集合到版本关系，复用等价 R项，不退出其历史。若新增成员的位置要求改变已发布 IF→F role，则`引用冲突`零写。

`已提交`、`目标已满足`才成功并带完整当前投影；后者 H=G0、无首次H。所有失败清空投影和首次H且回显原请求。写后读回不一致为`内部不一致`；发布未知为`已可能发布`，只能以原幂等键读取收束。

本计划只授权存在类 L2 与专属记录，不承担出生、归组、L3、装配或诊断。

## v0.3 保守幂等协议

首次材料读取在所有 G0 依赖读取之前执行：最小包络无效仍为`入口拒绝`；包络有效时，键已有首次材料即无条件为`已可能发布`，不比较请求、预算、预期或目标，也不尝试以历史节点/关系重建旧 G0。键无首次材料才执行 v0.2 的首建、前态、最终成员与写集流程。

因此成功集只有`已提交`与`目标已满足`。后续使用同键的调用不能得到精确重复，即使其表面输入相同；调用者必须把`已可能发布`视作未确认、停止自动重试并保留原键、原请求和结构化结果。该协议不要求新增 L1 材料字段、回放摘要或历史读取合同。

## v0.4 同截止类型组合

`新增F特征读取预算`是提交请求的值式字段，调用前必须有效。该预算对每个新增F独立使用，不由存在已知读取替代。存在服务以自己的 `特征服务_` 组合有界读取，Gread 与 H 都等于提交 G0；有界读取的成功谓词要求请求/事实的 Gread/H、F 身份、有效特征信息/类型关系和所有用量上限一致。只有随后比较 `事实->信息.类型==FT` 才满足“E 已知、准确且同 FT”。

已知读取和有界读取失败依配套计划 v0.4 的逐类映射返回，绝不把类型空缺或名称相似当作同 FT；任一失败不建立写集。
