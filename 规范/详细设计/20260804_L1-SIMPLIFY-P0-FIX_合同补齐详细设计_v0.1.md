# L1-SIMPLIFY-P0-FIX 合同补齐详细设计 v0.1

设计基线：`ef78ea6cc2ffc275ffa75ccc1307b98420147e72`

## 1. 目标与完成边界

本叶修正 P0 v0.2 已进入正式代码、但没有兑现 4015 的部分。修正后，`L1事实基座服务` 的 11 个公开函数及其签名保持不变；节点、关系和值仍由一个仓库状态、一个全局事实代次和一把内部共享锁承载。

完成只证明 P0 的三类事实、类型形状、规范化幂等、原子提交、四类读取和两阶段恢复在隔离服务实例内符合本设计矩阵。它不接入生产上下文，不建立世界资格，不形成持久恢复材料，不迁移任何领域消费者，也不删除旧基座。

## 3. DTO 与不变量

### 3.1 唯一公开 DTO 变化

物理位置：`海中鱼巣/核心/L1事实基座.数据.h`

```cpp
struct 节点事实 final {
    稳定编码 编码;
    节点种类 种类 = 节点种类::普通;
    std::optional<值表示种类> 属性类型表示;
    std::uint64_t 创建事实代次 = 0;
    std::optional<std::uint64_t> 退出事实代次;
    std::vector<属性槽> 当前属性;
};
```

- 普通节点的 `属性类型表示` 必须为空。
- 属性类型节点的 `属性类型表示` 必须有值。
- 不增加对象版本、关系版本或值记录版本。
- `L1事实副本`、历史、快照和恢复材料通过 `节点事实` 同步携带该字段，不建立第二表示表。

其余公开结构、状态枚举和 11 个服务签名不变。

### 3.2 完整当前状态不变量

1. 当前三表和历史表中的稳定编码全局唯一；所有当前、历史编码均属于永久占用集。
2. 当前节点的创建代次非零且不大于当前事实代次，退出代次为空；历史事实退出代次有值且不小于创建代次。
3. 每条当前关系的源、目标和关系类型都解析到当前节点。
4. 每个当前值的所属、来源和属性类型都解析到当前节点；属性类型节点种类为 `属性类型`；材料分支与其 `属性类型表示` 精确相等。
5. `独立材料引用` 的编码必须解析到建立写集前已经发布的当前节点；同写集本地键不能伪装独立材料发布见证。
6. 当前属性槽按属性类型编码严格升序；槽类型是当前属性类型节点；槽值是当前值，且该值的所属节点和属性类型与槽一致。
7. 属性槽已有旧当前值时，写集必须同时退出旧值并发布一个新值；关系替换由调用方在同一写集中退出旧关系并建立新关系。
8. 应用退出事实后再次验证完整当前状态，禁止留下悬空关系、值或属性槽。

## 4. 规范化、提交与发布

物理位置：`海中鱼巣/核心/仓库.L1事实基座.ixx`

仓库内部建立唯一 `L1仓库状态`，拥有事实代次、下个编码、当前三表、历史表、永久占用、幂等账、审计账和隔离标记。共享锁不进入状态对象。

`规范化写集(const L1写集请求&)` 固定：

1. 节点、关系和值按本地键升序；
2. 属性槽变更按“所属引用、属性类型引用、新值本地键”升序；
3. 退出事实按稳定编码升序；
4. 重复本地键、重复槽目标或重复退出编码在写前拒绝；
5. 规范化不改写幂等键、期望事实代次、角色/顺序或材料数组内部顺序。

`提交` 固定顺序：

```text
取得独占锁
-> 规范化并检查同键同义/异义
-> 检查期望事实代次
-> 复制完整当前状态为候选
-> 只在候选内分配编码、应用写集、生成历史、幂等账和审计
-> 对候选运行完整不变量验证和发布后读回验证
-> 候选事实代次 = 旧代次 + 1
-> 一次 noexcept 状态交换
-> 返回候选中已经冻结的结果
```

任何异常、资源不足或验证失败都发生在交换前，返回结构化非成功且旧状态、旧代次、下个编码、幂等账和审计均不变。交换后不得再执行可能分配内存或改变返回结论的操作。精确重复在候选审计记录形成后一次交换，但不推进事实代次，并返回首次冻结映射。

## 5. 恢复候选

`建立恢复候选(材料, 期望事实代次)`：

1. 零或漂移基线按现有状态分类拒绝；
2. 在局部对象中从材料构造完整 `L1仓库状态`；
3. 验证当前/历史不重叠、全局编码占用、生命周期、类型表示、值材料、关系端点、属性槽、幂等账唯一性和审计序号；
4. 每个已发布幂等账必须能与同键提交成功审计的首次结果和映射互证；精确重复审计不得改写首次结果；冲突审计不能建立第二幂等账；
5. 校验全部通过后才保存隔离候选和建立时基线，当前状态零变化。

`确认恢复候选()`：

```text
无候选 -> 无候选
当前代次 != 候选基线 -> 丢候选并返回事实代次漂移
候选最终复核失败 -> 丢候选并返回材料不完整或内部不一致
通过 -> 候选发布代次设为当前代次+1 -> 一次 noexcept 状态交换
     -> 在同一锁内按新状态读回完整快照 -> 返回恢复已发布
```

交换后的读回若发现内部矛盾，仓库设置隔离标记并返回 `内部不一致`；隔离状态下普通提交和恢复确认拒绝继续发布，当前读取返回 `内部不一致`，不得逐项修补。

`撤销恢复候选()` 只丢弃候选，不改变当前状态、事实代次或审计。没有具名写集幂等键时不生成伪恢复审计记录。

## 6. 验证矩阵

专属自检仍使用 `L1-SIMPLIFY-P0-S01`、顺序 270；顶层完整自检登记数量仍为 22。内部验收至少增加：

- 属性类型表示发布、快照、历史和恢复保真；普通节点携带表示拒绝、属性类型缺表示拒绝；
- I64、I64组、U64组、独立材料引用四分支成功及四类错配拒绝；
- 关系类型不是当前节点、值类型不存在、来源不存在、材料引用未发布拒绝；
- 一个节点多个属性和多个关系子节点不重复记账；
- 属性替换旧值退出、新值/槽同代次；关系替换旧退新发同代次；
- 同键数组乱序同义返回原映射且代次不变，同键异义冲突；
- 提交候选失败前后完整快照、审计和下个编码不变；发布成功后账、审计和事实同在；
- 恢复缺项、重复编码、槽矛盾、关系断裂、材料错配、生命周期逆序、幂等/审计不互证均零发布；
- 恢复确认漂移丢候选，确认成功一次替换并独立完整快照读回，撤销零发布；
- 当前、历史、审计、完整快照 DTO 仍严格分账。
