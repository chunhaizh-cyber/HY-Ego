# DEMAND-SOURCE-PATH-MERGE-CANDIDATE-COMPOSE 需求来源路径合并候选组合详细设计 v0.1

日期：2026-08-16
版本：v0.1

## 1. 目标、范围与完成边界

实现 BIZ-L4-004-02-01-03 v0.2，并同步以 BIZ-L3-004-02-01 v0.2 修正父状态机。03 只消费 02 的唯一完整当前需求、01 的可准入来源授权见证和路径提交意图，纯值形成无需补充、仅来源补充或需要路径复核候选；零 DATA 调用、零写入、零缓存。

完成不证明01来源准入、04防环、05发布、06读回或需求整体建立；本计划必须保持待激活。

## 2. 正式依据与当前事实

- 0050、4030：BIZ 可以形成强类型请求和解释结果，但不得复制 DATA CRUD、内部写集、事务或撤销权。
- 3100、5100、5130：来源和获取途径不改变需求目标；更新保留来源历史，候选必须携带主体、目标、来源、授权、时间和版本。
- 5110：同父同目标复用 / 合并；来源差异不造第二需求；多个当前路径关系可以引用同一需求，实际活动 / 结算另行裁决。
- `DEMAND-CURRENT-SAME-PARENT-TARGET-CONSUME v0.2`已正式登记待激活，其唯一值式需求覆盖全部当前来源 / 授权、父关系、完整当前路径关系组、生命周期、版本和G0。
- 01 v0.1 仍缺正式来源授权 DTO / provider；本设计冻结03所需最小输入语义，但精确类型名和字段顺序必须等待01最终结果机械匹配。
- 旧03重复读取来源 / 路径并形成“冻结写集”，还把新路径异义直接当冲突；父图又让03后直达05。这与公开DATA边界、多路径复用和新增路径必经防环复核冲突。

具名漂移：`DRIFT-BIZ-L4-004-02-01-03-DUPLICATE-DATA-READ`、`DRIFT-BIZ-L3-004-02-01-02-03-ARGUMENT-BINDING-STALE`。

## 3. 上游输入和纯值候选

01 最终 `已准入需求来源授权见证`至少须携带：来源对象强类型身份与身份来源、来源种类、提出主体、被授权需求主体、目标宿主 / 特征 / 目标状态语义键绑定、授权事实身份 / 范围 / 当前性 / 生命周期、发生时间、来源与授权规则版本及同一G0。03不重新证明授权，只验证见证完整并与02主体 / 目标 / G0互证。

路径提交意图至少携带：可空父需求；有父时必须携带路径组强类型身份、路径角色强类型身份、路径顺序强类型值和规则版本；无父时上述路径字段必须全部为空。路径意图不携带已发布关系身份或“已经当前”断言。

路径意图语义键：

```text
父需求 + 当前需求 + 路径组 + 路径角色 + 路径顺序
```

03 只在02完整当前路径组中按该键比较。零命中形成待04复核新增路径意图；一命中表示无需路径补充；多命中为内部不一致。旧关系身份、到达时间和显示文本不进入意图键。

来源比较按来源稳定身份定位。零命中形成来源追加；一命中且完整来源 / 授权相同则无需追加；一命中但01携带同来源的已准入新授权时形成当前授权换代意图并保留旧历史。02来源组自身出现重复稳定身份、同身份异义或半结构时唯一映射内部不一致；01有效新见证与02既有不可变来源语义冲突时唯一映射来源冲突，两者都不覆盖既有事实。

输出候选只包含：02完整需求引用快照、01来源见证、可空来源追加 / 授权换代意图、可空新增路径意图、是否必须经过04、原后继发布幂等身份、G0、规则版本和值式语义摘要。它不是DATA内部写集，也不取得候选确认 / 撤销能力。

## 4. BIZ DTO 与物理位置

```text
海中鱼巣/领域/需求来源路径合并.数据.h
海中鱼巣/领域/服务.需求.ixx
```

预冻结合同：

```cpp
inline constexpr std::uint32_t 需求来源路径合并合同版本 = 1;
inline constexpr std::uint32_t 需求来源路径合并规则版本 = 1;

struct 需求来源路径合并请求 final {
    std::uint32_t 合同版本;
    std::uint32_t 规则版本;
    同父同目标需求读取结果 当前需求读取;
    已准入需求来源授权见证 来源授权见证; // 待01最终ABI机械匹配
    需求路径提交意图 路径意图;
    std::uint64_t 事实截止代次;
    std::uint64_t 来源规则版本;
    std::uint64_t 授权规则版本;
    std::uint64_t 路径规则版本;
    L2结构幂等身份 后继发布幂等身份;
};

enum class 需求来源路径合并状态 : std::uint8_t {
    无需补充 = 1,
    仅来源补充候选 = 2,
    需要路径复核候选 = 3,
    请求拒绝 = 4,
    当前性漂移 = 5,
    来源冲突 = 6,
    资源失败 = 7,
    内部不一致 = 8
};

struct 需求来源路径合并结果 final {
    需求来源路径合并状态 状态;
    std::uint32_t 合同版本;
    std::uint32_t 规则版本;
    需求来源路径合并请求 请求回显;
    std::uint64_t 事实截止代次;
    std::optional<需求来源路径补充候选> 候选;
};

需求来源路径合并结果 需求业务服务::合并来源与当前路径材料(
    const 需求来源路径合并请求& 请求) const noexcept;
```

只有两个候选状态携带 optional 值；无需补充和全部非成功均为空。无需补充回显G0；两个候选状态也回显G0。请求拒绝、漂移、来源冲突、资源失败和内部不一致截止为0、候选为空。上游精确类型与字段顺序待01 / 02最终代码结果机械匹配，不得重新定义同义DTO。

## 5. 固定流程与结果映射

校验请求与版本；要求02状态为唯一当前需求且optional完整，01状态为可准入且见证完整，G0 / 主体 / 目标语义键 / 规则版本一致，幂等身份非零。02或01的失败结果不得传入本函数冒充输入。

来源组与路径组都用 checked 数量和稳定身份比较；零 / 一 / 多严格分账。父为空时02路径组与提交意图路径字段必须都空，合法全空直接判定无需路径补充，不形成新增路径意图，也不进入04。父非空时02路径组至少一项且提交意图完整；此时新路径零命中不是冲突，而是形成必须经04的候选。任何候选构造完成后一次移动到结果；`bad_alloc` / `length_error`映射资源失败，其它异常映射内部不一致。

本函数不调用 DATA、不读取时间、不换G0、不重试、不加锁、不访问幂等账。同输入必须形成值相等结果，但这只是纯函数确定性，不是 DATA 精确重复。

## 6. 验证矩阵

1. 02非唯一 / optional坏、01非可准入 / 见证坏、G0 / 主体 / 目标 / 版本不等、零幂等身份均零候选拒绝；
2. 新来源不存在形成来源追加；同来源同授权无需追加；同来源已准入新授权形成授权换代意图；02组自身重复 / 同身份异义唯一为内部不一致，01新见证与既有不可变来源冲突唯一为来源冲突；
3. 父空时两侧路径均空并直接无需路径补充，最终只由来源补充决定无需补充或仅来源补充；父非空时路径意图完整，02路径组至少一项；违反为内部不一致；
4. 路径语义键一命中无需路径补充，零命中形成必须经04候选，多命中为内部不一致；互异现有路径全部保留；
5. 来源与路径均无需补充返回无需补充；仅来源变化返回仅来源候选；任何新增路径返回需要路径复核候选；
6. 后继幂等身份原样回显，03零幂等账访问、零DATA调用、零写入 / 缓存 / sleep / retry；
7. 只有无需补充和两个完整候选状态回显G0；全部非成功截止0、optional空；异常守恒；
8. 根工程双配置、生产外专项、diff、strict、UTF-8、工程唯一登记和清理后复验通过。

## 7. 激活与完成边界

必须等待01正式冻结并实现来源授权见证、02 v0.2真实代码结果 / 退出 / 清理并释放其DTO和 `服务.需求.ixx`，再机械匹配两个上游结果、路径强类型和构造签名。还需取得唯一代码段、工程和构建资源。03不直接等待 DATA 写服务；其 DATA 依赖全部经02结果间接满足。

任何把03改回DATA读取、把候选变成DATA内部写集、把新路径直接当冲突或绕过04、把无需补充解释为DATA幂等成功的漂移，固定具名 `DRIFT-DEMAND-SOURCE-PATH-MERGE-CANDIDATE-BOUNDARY`。
