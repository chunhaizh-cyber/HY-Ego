# 物理全局根与世界根挂接详细设计

标识：`PHYSICAL-GLOBAL-ROOT`；版本：v0.1（草稿）；日期：2026-11-05；状态：已定稿（第9节用户裁决全A）。

依据：0050 §1.3第6项、§11；1150 §2；4200 §2；4202 §2；8120 §初始化第2项；8121 §2—§3。代码基线：main `8190518f7`。

## 1. 目标与完成条件

建立唯一物理全局根，把每个世界的根场景以“世界根挂接”关系挂在其下，并按“全局根＋世界类型”唯一定位、完整读回；各世界内部结构、场景范围上界、成员与迁移逻辑不变。

完成条件：
1. 普通应用启动后存在恰一个全局根节点，由全局变量 `全局根场景节点` 持有受保护引用。
2. 现实、外设、自然语言、内部治理四个世界根在初始化中挂到全局根下；模拟世界根在首次 `确保根()` 时挂接。
3. 每个世界根恰有一个世界类型字段，同一类型在全局根下恰一个世界根；重复初始化精确复用。
4. 装配成功判定额外完整读回全局根与各世界根挂接；任一不一致保持停门。
5. 实际项目编译链接通过。

不在范围：世界根以外的场景层级；场景 `父场景节点` 语义；状态/动态/迁移；概念根（见 CONCEPT-ROOT-CHAIN）；模拟世界根改为场景节点（第9节Q3）。

## 5. 数据结构

- 全局根节点：`节点类型字段=全局根节点类型`（本模块私有类型节点，见Q2）。只允许出边：`全局根→世界类型节点`（父子，角色“世界类型登记”=1）与 `全局根→世界根`（父子，角色“世界根挂接”=2）。不持有成员、特征、状态、动态、专属概念字段。
- 世界类型节点：字段 `世界类型登记键字段=I64键`。
- 世界根：在其既有场景结构上追加字段 `所属世界类型字段→世界类型节点`。
- 私有结构节点（`全局根节点类型`、`世界类型登记键字段`、`所属世界类型字段`）由 `初始化()` 一次建立，与 `存在概念图根节点` 等现有模式一致。

## 6. 控制流与事务

`初始化()`（互斥内）：
1. 全局根已有效 → 完整核验（类型字段唯一、出边角色只属{1,2}、无其它字段）→ 无变化；不符 → 结构不一致。
2. 否则以一次 `原子追加节点组` 建立：私有结构节点、全局根、五个已知世界类型节点及其登记边与键字段。预期不符 → 结构不一致；资源不足 → 资源失败；成功后读回核验，读回不符为工程故障（`工程异常终止`，沿用现有 `正式定义故障` 处理方式）。

`挂接世界根(键, 根)`（互斥内）：
1. 前置：全局根已初始化；`根` 有效且节点存在；否则入口拒绝。
2. 读该键的世界类型节点（缺失 → 结构不一致）。
3. 读全局根“世界根挂接”出边中所属类型为该键者：恰为 `根` 且 `根` 的类型字段指向该类型 → 无变化；存在其它根 → 结构不一致；`根` 已挂在其它类型 → 结构不一致。
4. 否则一次 `原子追加节点组`：追加 `全局根→根` 挂接边 + `根.所属世界类型字段`。预期不符 → 结构不一致；资源 → 资源失败。
5. 读回核验同第3步。

`查询世界根 / 完整读回`：只读；按出边枚举，结果排序；发现同类型多根或类型字段缺失返回结构不一致，不猜测。

## 8. 非成功、生命周期与验证

- 业务非成功：入口拒绝、结构不一致、资源失败按上表映射到各世界初始化的既有失败状态，最终由装配停门；不吞错、不以其它根替代。
- 工程故障（读回不符、C++异常）：`工程异常终止`，与现有世界初始化一致。
- 生命周期：全局根、世界类型、世界根挂接只建立不删除（1150：全局根与世界根不可删除）；进程内常驻。
- 验证：默认只做静态复核和实际项目编译链接（AGENTS §7.1）。静态矩阵：全局根唯一；五类型唯一；四世界根初始化挂接、模拟按需挂接；重复初始化无变化；同类型第二根→结构不一致；根挂错类型→结构不一致；装配读回不符→停门。运行验证仅在用户给出测试指令时执行。
- 完成声明边界：只声明“已编译、未运行测试”；不声明世界逻辑隔离已被运行证实。
