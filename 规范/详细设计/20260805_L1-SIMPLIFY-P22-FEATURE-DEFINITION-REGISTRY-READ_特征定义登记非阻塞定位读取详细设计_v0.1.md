# L1-SIMPLIFY-P22-FEATURE-DEFINITION-REGISTRY-READ 特征定义登记非阻塞定位读取详细设计 v0.1

## 1. 身份、目标与完成边界

计划身份：`L1-SIMPLIFY-P22-FEATURE-DEFINITION-REGISTRY-READ`

版本：`v0.1`

创建侧正式代码基线：`6dfdd7f0f6383c1f308533e3b84b9616f0c67afd`

本叶是 SELF-GOV-CLOSURE STEP-4 在 P21 之后按当前能力矩阵发现的下一最早定位提供者。它只原位扩展唯一 `L1特征定义服务`，形成版本化、纯值式、一次 try-lock 的 `尝试读取当前登记`，向后继实例特征集合读取提供特征定义服务身份、定义标记属性类型、I64 下界属性类型和 I64 上界属性类型的不可变定位材料。

完成必须同时成立：

- 输入明确冻结 P2 合同/规则版本，输出复用唯一 `特征定义登记结果` 与 `特征定义登记`；
- 服务锁竞争立即返回 `许可拒绝`，不等待、不 sleep、不重试；
- 登记未加载、坏登记、资源失败和内部异常结构化分账，所有非成功均为空登记；
- 成功只复制已经由 P2 建立并验证的登记缓存，不扫描 L1、不查询 SQL、不猜测稳定编码；
- 新旧登记读取共用唯一私有已持锁复制/完整性判定，不建立第二登记缓存或第二解释逻辑；
- 登记中的 `事实截止代次` 只保留首次登记验证见证，不能冒充当前事实截止、P17 快照代次或后继 G0/G1。

本叶不读取特征定义节点、实例槽、当前值、材料或来源，不形成实例特征集合、状态、动态、完整世界快照或统一世界门面。

## 4. DTO、状态、公开函数与唯一私有实现

在 `L1特征定义.数据.h` 新增：

```cpp
struct 特征定义登记读取请求 final {
    std::uint32_t 合同版本 = L1特征定义合同版本;
    std::uint32_t 规则版本 = L1特征定义规则版本;
    friend bool operator==(const 特征定义登记读取请求&,
        const 特征定义登记读取请求&) = default;
};

inline bool 特征定义登记读取请求有效(
    const 特征定义登记读取请求& 请求) noexcept {
    return 请求.合同版本 == L1特征定义合同版本
        && 请求.规则版本 == L1特征定义规则版本;
}
```

在既有 `特征定义状态` 末尾追加稳定枚举值，既有 1—10 不重编号：

复用既有：

新增唯一公开函数：

```cpp
特征定义登记结果 L1特征定义服务::尝试读取当前登记(

```

服务内新增唯一私有函数：

```cpp

```

私有函数只在调用方已持有 `锁_` 时使用：缓存不存在返回 `登记未加载`；合同/规则/验证代次、四个稳定编码或两两唯一性损坏返回 `内部不一致`；完整时逐字段复制并返回 `已读取`。既有阻塞兼容入口 `读取当前登记()` 和新增非阻塞入口共同调用它，禁止复制两套未加载、完整性或唯一性判断。

既有 `特征定义登记完整` 的公开含义不删除；唯一私有复制函数在其基础上追加四个登记编码两两不同的 P2 写后不变量。旧入口在正常材料上的签名、阻塞兼容和结果不变；只有缓存已经损坏的情况由过去的假成功收紧为 `内部不一致`。

## 5. 固定读取算法与字段边界

`尝试读取当前登记` 固定执行：

1. 在锁外调用 `特征定义登记读取请求有效`；失败返回 `入口拒绝`、空登记，锁尝试为 0；
2. 用 `std::unique_lock<std::mutex>{锁_, std::try_to_lock}` 只尝试一次 P2 服务锁；
3. 未取得锁立即返回 `许可拒绝`、空登记；不等待、不 sleep、不循环；
4. 取得锁后调用唯一 `复制已持锁当前登记`；
5. 登记未加载返回 `登记未加载`；坏登记返回 `内部不一致`；完整登记返回 `已读取` 和不可变逐字段副本；
6. 返回前释放锁，不外泄锁、引用、指针、许可或可写缓存。

成功副本只包含 P2 已有字段：合同/规则版本、登记首次验证事实代次、服务身份、定义标记属性类型、I64 下界属性类型和 I64 上界属性类型。四个稳定编码必须有效且两两不同。

本入口不调用 L1，因此不判断四个节点当前或已退出，不读取定义，不形成当前事实截止，也不产生 `事实代次漂移`。后继必须在 P17 的同一快照中互证：服务身份是当前普通节点，三类属性类型是当前 I64 属性类型节点，定义节点具有唯一标记/上下界槽和值，值来源为服务身份；P17 快照代次才是领域结果截止。

## 6. 状态、异常、并发与生命周期

| 条件 | 状态 | 登记载荷 | 副作用 |
| --- | --- | --- | --- |
| 合同或规则版本错 | `入口拒绝` | 空 | 锁尝试 0 |
| 服务锁竞争 | `许可拒绝` | 空 | 零等待、零重试 |
| 登记未加载 | `登记未加载` | 空 | 不扫描、不补造 |
| 登记缓存不完整或编码重复 | `内部不一致` | 空 | 不返回部分登记 |
| 完整登记 | `已读取` | 完整副本 | 零写入 |
| 复制分配失败 | `资源失败` | 空 | 零写入 |
| 其它异常 | `内部不一致` | 空 | 零写入 |

`幂等冲突`、`事实代次漂移` 不是本读取入口的正常输出分支。登记首次验证代次在后续定义、实例、值、状态或动态发布时不更新，不得参与 G0/G1、当前排序或漂移裁决。

P2 建立登记、建立/读取定义或既有阻塞登记读取持锁时，新入口立即许可拒绝。多个新入口并发竞争普通 `std::mutex` 时至多一个成功，其余允许许可拒绝；调用方不得要求本服务内部重试。本叶无缓存新建、恢复装载、SQL 回源或默认登记。

为确定验证锁竞争与坏缓存，只在 `#ifdef _DEBUG` 下给类追加以下两个自检辅助成员；服务模块增加 `<semaphore>` 头依赖，自检以两个 `std::binary_semaphore` 建立确定屏障：

```cpp
void 调试持有登记锁直到(
    std::binary_semaphore& 已取得,
    std::binary_semaphore& 允许释放);

void 调试替换登记(std::optional<特征定义登记> 登记);
```

第一函数取得现有 `锁_` 后 release `已取得`，再 acquire `允许释放`；只允许由隔离自检的辅助线程调用。第二函数在内部阻塞取得同一 `锁_` 后替换隔离服务实例的 `登记_`。两者不得在 Release 出现，不返回锁/许可/缓存引用，不接受回调，不得成为生产调用入口。

## 7. 验证矩阵

执行至少验证：

1. 合同错、规则错在锁外入口拒绝，锁尝试 0；
2. 新服务实例登记未加载，返回 `登记未加载`，即使共享已含 P2 事实的 L1 也不扫描补造；
3. P2 登记建立后新入口返回完整副本，逐字段等于建立结果和既有阻塞读取结果；
4. 相同登记重复读取逐字段确定相等，L1 事实代次不推进；
5. Debug 同步夹具持有服务锁时立即 `许可拒绝`，零等待、零 sleep、零重试；释放后再次读取成功；
6. Debug 隔离服务坏登记覆盖错合同/规则、零验证代次、零编码和任意两编码重复，均返回 `内部不一致`、空登记；
7. 资源失败与其它异常准确映射，所有非成功无部分登记；
8. 既有 `读取当前登记()` 保持阻塞兼容语义，新旧入口复用唯一私有复制/完整性判断；
9. P2 登记、I64 定义建立、精确编码读回和运行期连续持有专项不退化；
10. 生产代码对 P17、P21、实例特征、状态、动态、SQL、材料、旧服务/句柄调用为 0；
11. Debug/Release x64 串行 Rebuild、两配置退出式完整自检、strict、MSVC 模块扫描和目标/cached diff check 全部通过。

本叶原位扩展既有 `海中鱼巣.领域.自检.L1特征定义`，不新增模块、工程项、启动自检单元或完整自检计数。
