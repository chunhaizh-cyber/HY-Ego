## 0. 用户目标与本文范围

用户要求继续完善自然语言模块设计，核心是：**自我内部世界中的信息**与**自然语言**之间的相互转换。

- **理解（NL → 内部）**：固定原文 → 词出现/结构匹配 → 经名称关系落到自我内部世界中的概念 →（按需）在自然语言世界树按概念实例化临时 E →（按需）绑定现实/自我成员 → 类型化含义 / 主张 / 可供认知消费的材料。

## 1. 模块定位与核心裁决

### 1.1 一句话定位

自然语言模块是 **DATA 外的内部治理功能**：在**不取得现实写权**的前提下，把自然语言材料与**自我内部世界**（含其中的概念树与自我场景/特征等认知材料）互相翻译；翻译结果是有来源、可回读、可缺口报告的**类型化信息**，不是“理解即采信”。

### 1.2 世界拓扑（非线性；v0.2 用户裁决）

v0.1 将①现实 / ②自我内部 / ③概念空间 / ④自然语言世界树 / ⑤语言材料画成近似线性五层，**不正确**。正确关系如下。

```text
                    ┌──────────────────────────────────────────┐
                    │           自我内部世界（认知整体）         │
                    │                                          │
                    │  ┌─ 概念树 / 概念空间（语言无关）────────┐ │
                    │  │  存在/特征/动态等概念、上下位、定义   │ │
                    │  │  ←── 2210 名称关系 ←── 词条/语种表达 │ │
                    │  └──────────────────────────────────────┘ │
                    │  ┌─ 自我场景视角与实例投影（7130）──────┐ │
                    │  │  E=C、特征采用、状态/动态投影、位置  │ │
                    │  └──────────────────────────────────────┘ │
                    │  （治理可读投影：需求/任务/方法等内容，   │
                    │    仍归各自 owner，自我可指称与查询）     │
                    └──────────────────────────────────────────┘
                         ▲ 实例化概念（按出现）        ▲ 可选绑定
                         │                            │
              ┌──────────┴──────────┐                 │
              │ 自然语言世界树       │                 │
              │ （实例级临时舞台）   │─────────────────┘
              │ 空白语言场景 +      │     可选再绑定到：
              │ 匿名概念实例 E      │       · 现实世界树成员
              └──────────┬──────────┘       · 自我内部已有成员
                         │ 含义/主张引用概念与出现
                         ▼
              ┌─────────────────────┐         ┌─────────────────┐
              │ 语言 owner 材料      │ 旁路并行 │ 现实世界树       │
              │ 知识·原文·解析·交互  │         │ （外部事实）     │
              │ 主张·学习关联        │         │ 只读查询 /       │
              │ 指向内部世界中的概念 │         │ 领域裁决写入     │
              └─────────────────────┘         └─────────────────┘
```

要点（相对 v0.1）：

1. **概念树属于自我内部世界的一部分**，不是悬在内部世界之上或之外的独立“层”。语言经 2210 名称关系映射到的，是内部世界里的概念身份。
2. **现实世界树在外部**：理解/表达可只读查询；写入必须经领域应用，语言器无捷径。
3. **自然语言世界树不是层**：它是把内部世界中的概念**按语言出现实例化**得到的临时实例舞台（空白语言场景 + 匿名 E）；可再与现实或自我成员做可选绑定。纯概念构式（如 S02/S09）甚至不需要建该舞台。
4. **语言 owner 材料与内部世界旁路并行**：保存怎样说、当次原文/解析/主张；通过名称与含义**指向**内部世界中的概念，不另造第二概念仓，也不把主张写成世界支持边。

**裁决 A**：内部世界信息进入语言，优先使用内部世界已有概念及所属 owner 正式只读投影（自我结构、特征、需求直接内容、任务阶段等），再用 7230/7240 组织为表达目标；禁止把私有字段表或稳定编码印成自然语言名称。

**裁决 B**：自然语言进入内部世界，名称先落到内部世界概念；需要谈论“某个（尚未绑定现实的）对象”时，才在自然语言世界树按出现实例化临时 E；是否绑定现实/自我成员、是否写入正式集合，必须另经所属应用入口。语言转换成功≠事实成立。

**裁决 C**：共享语义表示（7260 + SHARED-INFO 的 `正式直接内容项`）仍是双向转换的**认知枢纽**，其概念端点位于自我内部世界的概念树中。D/T/M 可作指称对象，但不并入普通 E 读取器。

**裁决 D**：六基础构式无交互路径（7240 §4.3 / BASIC-SIX）仍是最小可验证双向内核；扩展环不得破坏其零写/回读合同。

#### 1.2.1 与现行正式规范的显式冲突说明

用户裁决「概念树属于自我内部世界的一部分」是**本模块设计拓扑**。现行正式规范**并未**把概念空间写成 7130「自我内部世界」的子集；二者目前是不同表述，必须显式分账，不得假装规范已改。

| 来源 | 现行表述（摘要） | 与用户裁决的关系 |

**本模块处理方式（直至规范修订）**：

1. 在自然语言模块文档与编排语义中，采用用户拓扑：谈「内部世界信息」时**包含**概念树上的概念与自我场景投影。  
2. **不**借此改 DATA owner、把概念节点挂到自我场景成员边、或合并阶段 17/18 事务。物理写入仍走概念 owner / 世界 owner / 语言 owner 既有合同。  
3. 将「7130 用语是否扩写为包含概念树」列为 §12 开放问题，交用户/root 决定是否修订 7130/2220/4190，避免模块用语与根规范长期双轨。

### 1.3 非目标（本模块明确不做）

1. 任意中文/大模型式开放理解；只支持已发布、可双向核验的语言知识。  
2. 语言器直接写现实特征、组成边、因果、任务完成或方法调用。  
3. 用焦点首项、self、当前窗口或机器时钟补齐未决指代/时间。  
4. 第二套硬编码输出模板仓，与可学习知识分叉。  
5. 把「收到/明白了」自动升级为内容确认、求助授权或任务承接。  
6. 把自然语言世界树提升为与概念树或现实树同级的「世界层」，或在概念与语言材料之间插入必经中间层。

## 2. 处理分层与现有代码落点

### 2.1 处理管线分层（不是世界层）

下表是**转换处理步骤**（L0–L8），不得再解读为 v0.1 那种世界五层栈。世界拓扑只以 §1.2 为准。

| 处理步 | 职责 | 落在拓扑何处 | 现有/目标落点 |
| --- | --- | --- | --- |
| L0 接入 | 固定原文、语言选择、来源 | 语言材料侧 | `新_语言类`；外设消息只读保护 |
| L1 词法/名称 | 词条最长匹配；名称完整读回 | 名称关系 → **内部世界概念树** | `新_语言类`；`新_词类`；`概念_名称关系类` |
| L2 结构匹配 | 按已发布知识有序项匹配 | 语言知识（语言 owner）+ 指向内部概念 | `转换.语言场景共同`；各只读解释器 |
| L3 含义形成 | 7240 有限操作 → 含义项 | 认知枢纽；概念端点在内部世界 | BASIC-SIX；`表达.基础语言` |
| L4 实例舞台 | 按需：空白语言场景 + 按出现实例化匿名 E | **自然语言世界树（实例级）** | `新_自然语言世界树类` |
| L5 可选绑定 | 临时 E ↔ 现实成员 / 自我成员 | 跨现实树与内部世界实例投影 | `解释.基础语言` 现实候选；7130 投影 |
| L6 主张与交互 | 主张、需求描述/回应、交互上下文 | 语言材料侧（指向内部概念） | `新_语言类`；DEMAND-CONTENT |
| L7 认知接驳 | 含义 → 正式内容项 / 查询 / 领域提议 | 内部世界概念 + 各 owner 投影 | SHARED-INFO；需求/任务/方法 |
| L8 表达与学习 | 生成回读；样本→规则 | 语言材料 ↔ 内部世界概念 | `从基础信息生成可回读单句`；7250 |

语言解析/表达/学习属内部治理；外发通道结果与生成结果三分账（7240 §3.1）。

### 2.2 与自我内部世界的接驳面

```text
自我内部世界
  ├─ 概念树（定义、上下位、符合性）←── 名称关系（2210）
  ├─ 自我场景视角 / 特征采用 / 状态动态投影（7130）
  └─ 可指称的 D/T/M 等内容投影（各 owner）
        │
        ├─ 表达：取材 → 语言知识 → 文本
        │
        └─ 理解：名称落地概念 →（按需）自然语言世界树实例化
                 →（按需）绑定现实/自我成员 → InternalInfoBundle
```

反向理解需要现实对象时，经 7210 与 `解释.基础语言` 在**显式现实世界根**下只读枚举；**不得**把自然语言场景根伪装成现实根，也不得把匿名语言 E 直接当作现实成员。

## 3. 核心数据结构与接口（模块合同）

### 3.1 内部信息枢纽：类型化含义包

调用期（默认可随请求释放）统一载荷；需要留存时再按 7230 交语言 owner。

```text
内部信息包 InternalInfoBundle
  表达目的 / 作用域
  含义项有序组          // 7240；角色参数中的概念引用 ∈ 自我内部世界概念树
  来源对齐组
  实例舞台绑定组?       // 自然语言世界树：场景 + 匿名 E + 来源概念
  可选外部/自我绑定组?  // 临时 E 或指称 → 现实成员 / 自我成员
  指代实例组?
  未决/缺口组
  正式内容投影?         // vector<正式直接内容项>
  完整范围与阶段结果
```

`正式直接内容项` 形状以 SHARED-INFO 为准。语言理解引用指向语言材料/含义身份，不把理解结果假装成现实准确值。

| 对象 | 模块用法 |

### 3.3 已冻结的公开双向入口（内核）

仍以 BASIC-SIX 为准（签名不在本文重定义）：

- `转换单句基础语言到信息` / `从基础信息生成可回读单句`
- 六构式：S01、S02、S03×2、S05、S09；先只读全分支，唯一后再写场景/E；S02/S09 纯概念不建舞台

语义重述：这些入口里的「概念节点」读的是**自我内部世界中的概念树**（物理上仍经 `概念_*` owner）；「场景/实例」写的是**自然语言世界树实例舞台**，不是概念层，也不是现实层。

### 3.4 模块编排面（待具名叶实现）

```text
理解请求
  语言节点, 固定原文, 来源分支
  语境模式 = 无交互依赖 | 显式交互上下文
  允许范围（仅内部概念 | 允许建语言实例舞台 | 允许现实绑定 | 允许自我成员绑定）
  完整处理范围与旧额度适配字段

理解结果
  阶段状态；InternalInfoBundle?；完整候选组
  已取得语言场景/匿名 E（实例舞台部分写入如实回传）
  可选已保存语言内容身份

表达请求 / 表达结果
  同 v0.1：从 InternalInfoBundle 或等价强类型目标生成；回读；通道结果分立
```

编排规则：

1. 无交互依赖 → 只走 7240 §4.3 / BASIC-SIX；代词/未支持修饰 → 结构未支持。  
2. 显式交互上下文须可核验固定语境材料。  
3. **名称→概念**始终在内部世界概念树完成；**建匿名 E**仅当构式需要对象角色且候选唯一。  
4. **现实/自我绑定**是可选后继步，与实例舞台建立分账；不可互换身份。  
5. 持久主张/需求描述走语言 owner 显式保存（DEMAND-CONTENT），调用期 DTO ≠ 已保存。

## 4. 理解管线（NL → 内部）

### 4.1 总流程

```text
1. 固定材料与语言选择；记录来源；空输入≠解析成功
2. 句段边界候选
3. 词条最长匹配 → 词序/未知片段
4. 完整枚举适用语言知识 → 各构式只读匹配（不首命中即停）
5. 名称关系 → 自我内部世界概念树完整读回；按角色/句型收窄
6. 指代/量化/否定/条件/引述核验（有上下文时）
7. 合并候选：唯一 | 多义 | 缺规则/未知词/缺名称/…
8. 唯一后：
   - 纯概念构式 → 直接交付指向内部概念的含义（不建自然语言世界树）
   - 需对象角色 → 自然语言世界树：空场景 + 按出现实例化（来源=内部概念）
9. （可选）将匿名 E / 指称绑定到现实成员或自我成员
10. 形成 InternalInfoBundle；按请求可选保存语言材料侧主张
11. 后继领域提议只类型化交出，不自授写权
```

### 4.2 接地（grounding）策略

| 表层 | 接地目标 | 规则 |
| --- | --- | --- |
| 内容词词面 | 词条 → 2210 名称关系 → **内部世界概念** | 完整读回；指代名不进无上下文 E 槽 |
| 功能词 | 语言知识固定词项 | 不强制内部世界概念 |
| 类名（无上下文、需对象） | 内部概念 → **自然语言世界树**匿名 E（按出现） | 临时实例舞台；不查现实哪个对象 |
| 类名（现实解释） | 内部概念 → 现实树匹配候选 | 显式现实世界根；多候选保留；与匿名 E 分账 |
| 绑定到自我成员 | 指称/匿名 E → 7130 可读成员/自我 | 可选；不改概念定义 |

## 5. 表达管线（内部 → NL）

### 5.1 总流程

```text
1. 固定表达目标：区分内部概念、自我投影、现实已核验事实、语言主张、提问/请求
2. 从内部世界概念与正式投影取材；按目的/操作/角色召回语言知识
3. 排除不适用规则；同义多形按详略稳定选形
4. 名称/明确描述/合法指代/字面值/子含义绑定
5. 若目标含自然语言世界树匿名对象：用来源概念的当前名称表达（不要求现实专名）
6. 生成并对齐；不添加输入没有的因果/事件
7. 实际输出经同一理解管线只读回读（概念身份在内部世界；实例按出现映射）
8. 留存与发送分步
```

### 5.2 从自我内部世界到表达目标

取材算子仍限 7240 §2.3 闭集。来源明确为：

- 内部世界**概念树**（定义、上下位、名称）；  
- 内部世界**自我投影**（7130）；  
- 经合法绑定已关联的**现实**只读投影；  
- 语言材料侧已采用主张（复述时保留主张来源，不升格为已核验事实）。

### 5.3 回读核验

同 v0.1 闭环公理；补充：回读得到的概念节点必须仍落在内部世界概念树同一身份；匿名 E 不要求句柄与输出前相同，但来源概念与角色对应必须一致。
