# SELF-FORM 真实自我形成提供者详细设计 v0.1

日期：2026-08-13

## 1. 目标与完成条件

在 I2 已正式再读回现实世界树根、E-ROLE 和 S-HOST 均真实可用后，由 L5 之外唯一提供者形成项目唯一自我，并通过最终 L2 服务正式读回：

```text
一个角色化正式存在
+ 一个同树自我所在场景
+ 所在场景 -> 自我存在成员关系
+ 一个同树自我内部世界场景
+ 内部世界场景 -> 自我存在宿主关系
```

完成只在上述事实于一个声明的当前截止完整互证并发布值式材料后成立。请求、固定角色键、幂等键、上下文缓存和返回值均不是自我事实。

## 2. 资格、选择与禁止复用

项目唯一自我由 L5 提供者固定解释：

```cpp
inline constexpr L2存在单例角色键 海中鱼巣项目唯一自我角色{1};
```

该常量物理位于业务数据头，只能由本提供者使用；L2 不含该名称或含义。固定角色未绑定时原子建立新存在并绑定；已有绑定只有在它能由本 provider 保存的第一步首次完整请求精确重复结果互证时才收敛。provider 尚未形成第一步请求时已经存在的绑定固定拒绝，不按名称、位置、顺序、配置、线程或缓存选择或接纳；重复、复义或坏关系进入内部不一致。

禁止复用 `服务.L1自我结构登记`、`自我结构角色 = 21`、旧 `完整自我发布请求 / 结果`、P61/P62、旧世界登记、基础信息世界根、旧五身份五关系、资格属性、历史状态 / 动态登记或旧世界树门面。自我不兼任根场景、内部世界场景、概念或概念维度根。

## 4. 五步可恢复事务状态机

提供者完整持有自身发布锁。每次调用先经 A1 对 R1 当前登记与整树重新正式读回，并核对 I2 材料的树、根和首次根标记。首次合法调用在任何 L2 写前锁定完整 SELF-FORM 请求选择；即使随后第一步或任一步失败，该选择仍保留到 provider 析构，异请求固定在任何后继 L2 写前冲突。

跨 owner 不伪造成一笔事务。五步固定为：

1. `新增角色化存在`，角色固定为项目唯一自我；当第一步首次完整请求尚不存在时，必须先以与本轮 R1 复核相同的当前截止调用 `读取存在单例角色`。映射表固定为：L2 `未找到 ->` 形成并保存第一步完整请求后提交，L2 `已读取 ->` SELF-FORM `已发布选择冲突`，L2 `入口拒绝 ->` SELF-FORM `入口拒绝`，L2 `许可拒绝 ->` SELF-FORM `许可拒绝`，L2 `事实代次漂移 ->` SELF-FORM `事实代次竞争`，L2 `资源失败 ->` SELF-FORM `资源失败`，L2 `内部不一致 ->` SELF-FORM `内部不一致`；除未找到外全部零写且不保存第一步请求。第一步请求一旦保存，后继始终逐字段原样重放，从首次成功或精确重复结果重新取得自我存在身份，再按同截止正式读取该角色并互证；若新增返回引用冲突或幂等冲突，也必须正式补读角色：存在外部当前绑定映射 `已发布选择冲突`，不存在则保持原结构错误，读取坏形状映射 `内部不一致`，均不得接纳；
2. `新增树内场景(树, 根场景, 顺序=1)` 建立自我所在场景；
3. `新增场景成员关系(所在场景, 自我存在, 顺序=1)`；
4. `新增树内场景(树, 所在场景, 顺序=1)` 建立自我内部世界场景；
5. `新增场景宿主存在关系(内部世界场景, 自我存在)`。

每步只在对应首次完整请求尚不存在时，使用前一步首次成功 / 精确重复结果中重新取得的身份和当时最新正式事实代次形成并保存该请求；一旦保存，期望事实代次、端点、顺序、角色和幂等身份全部不可改变。一步发布后任一后继失败不得退出、回滚或换身份；返回具名阶段失败并保留已发布结构。原 SELF-FORM 请求每次重试都从第一步开始，依序逐字段原样重放已经保存的完整 L2 请求，从各步首次成功或精确重复结果重新发现自我存在、所在场景、成员关系、内部世界场景和宿主关系身份；尚未形成首次请求的下一步才用当前最新事实代次组装并保存。不得从结果缓存、上次返回值、参数附带身份或关系遍历猜测中间身份。

固定角色若已有当前绑定，只允许它是本 provider 保存的第一步完整请求之首次结果，并由该请求精确重复结果互证后收敛；如果 provider 尚无第一步请求而正式角色读取已经发现绑定，或同键结果与角色事实不一致，固定返回 `已发布选择冲突` / `内部不一致`，不得接纳外部建立的既有角色事实。进程重启后本 provider 不具备恢复首次完整请求的正式持久材料，因此跨进程恢复明确未实现，不得靠角色扫描接纳。

若某次 L2 调用返回 `事实代次漂移` 且该步尚未形成成功 / 精确重复，调用方可以丢弃该步尚未发布的首次请求副本，重新正式读回事实代次后以同一固定幂等身份形成新完整请求；但只有 L2 明确保证该次零变化且不存在未知发布时才允许。`资源失败`、异常或任何发布结果未知均保留原完整请求，只能原样重放。已经得到首次成功 / 精确重复的步骤永不重组请求。

E-ROLE 与 S-HOST 的替换 / 退出是业务中性 L2 能力，但本提供者及其生产入口永不调用这些接口。固定项目角色、自我存在、两个场景、成员关系和宿主关系不通过普通 SELF-FORM 请求退役或改绑；未来若需要退役，必须另立具名机器语义、设计和计划，不能扩展本状态机临场处理。

并发同请求由 provider 锁串行；外部并发推进 L1 使某步漂移时，本轮返回 `事实代次竞争`，后继按上一段的“明确零变化才可重组”规则收敛。提供者不循环忙重试，不 sleep，不持自身锁调用用户回调或 I/O。

## 5. 完整正式读回

五步成功后必须重新取得当前代次，并在同一个截止依次正式读取：

- R1 整树；
- E-ROLE 项目角色；
- 自我完整存在与身份来源；
- 两个场景树节点、树归属与直接父；
- 所在场景完整读取中的精确成员关系；
- 内部世界按场景及按存在双向宿主关系。

验证：两场景均在 I2 证明的树；所在场景直接父是根，内部世界直接父是所在场景；成员唯一指向自我；宿主唯一指向自我；自我不是内部世界成员；根 / 自我 / 两场景编码互异；无自包含环。任一缺项、混代、额外冲突或坏成功形状整体失败且不发布值式材料。

首次完整发布返回 `已形成`；同请求再次逐步精确重复并重新正式读回后返回 `精确重复`，可刷新截止。发布使用局部完整构造与无抛出交换；异常保留旧值。

## 6. 普通应用与启动

E-ROLE / S-HOST 不改普通应用。SELF-FORM 在 I2 适配器之后构造唯一 `std::unique_ptr<真实自我形成提供者>`，参数为同一 A1 聚合实例；上下文成员声明更晚、析构更早，增加 const / 非 const getter。构造失败追加专属连续装配状态。

`运行普通程序` 在 I2 成功后形成默认请求并调用 provider：

```text
失败 -> 初始化失败 / 真实自我形成 = 17
成功 -> 初始化失败 / 概念维度根生产初始化能力未实现 = 18
```

实施删除阶段 17 的“自我初始化能力未实现”固定成功后短路，但保留数值 17 并改为真实形成失败阶段；新增 18。阶段 18 之前不得调用方法根、自我线程、概念支持、投影、信号或宿主。4240 C1 仅是结构能力，不得冒充概念维度根生产初始化。
