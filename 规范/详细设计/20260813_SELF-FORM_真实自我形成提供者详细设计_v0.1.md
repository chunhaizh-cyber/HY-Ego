# SELF-FORM 真实自我形成提供者详细设计 v0.1

日期：2026-08-13

## 1. 目标与完成条件

在 I2 已正式再读回现实世界树根、E-ROLE 和 S-HOST 均真实可用后，由 L5 之外唯一提供者形成项目唯一自我，并通过最终 L2 服务正式读回：

```text
一个角色化正式存在
+ 一个同树自我所在场景
+ 所在场景 -> 自我存在成员关系
+ 一个同树自我内部世界场景
+ 内部世界场景 -> 自我存在宿主关系
```

完成只在上述事实于一个声明的当前截止完整互证并发布值式材料后成立。请求、固定角色键、幂等键、上下文缓存和返回值均不是自我事实。

## 2. 资格、选择与禁止复用

项目唯一自我由 L5 提供者固定解释：

```cpp
inline constexpr L2存在单例角色键 海中鱼巣项目唯一自我角色{1};
```

该常量物理位于业务数据头，只能由本提供者使用；L2 不含该名称或含义。固定角色当前已有合法绑定时必须收敛该存在；角色未绑定时原子建立新存在并绑定。重复、复义或坏关系进入内部不一致，不按名称、位置、顺序、配置、线程或缓存选择。

禁止复用 `服务.L1自我结构登记`、`自我结构角色 = 21`、旧 `完整自我发布请求 / 结果`、P61/P62、旧世界登记、基础信息世界根、旧五身份五关系、资格属性、历史状态 / 动态登记或旧世界树门面。自我不兼任根场景、内部世界场景、概念或概念维度根。

## 3. DTO 与模块

新建：

- `海中鱼巣/业务/真实自我形成.数据.h`
- `海中鱼巣/业务/提供者.真实自我形成.ixx`

模块为 `海中鱼巣.业务.提供者.真实自我形成`。数据头冻结：

```cpp
inline constexpr std::uint32_t 真实自我形成合同版本 = 1;

struct 真实自我形成请求 final {
    std::uint32_t 合同版本 = 真实自我形成合同版本;
    自我世界树根消费材料 根消费材料;

    L2结构幂等身份 所在场景幂等身份;
    L2结构幂等身份 所在场景成员幂等身份;
    L2结构幂等身份 内部世界场景幂等身份;
    L2结构幂等身份 内部世界宿主幂等身份;
};

enum class 真实自我形成状态 : std::uint8_t {
    已形成 = 1, 精确重复 = 2, 请求无效 = 3, 已发布选择冲突 = 4,

    L2场景宿主存在关系事实 内部世界宿主关系;

    真实自我形成状态 状态;

```

请求五个幂等身份必须非零、两两不同且不同于所有 E-ROLE / R1 / S-HOST 固定登记身份。正式生产使用五个固定业务值，具体数值在实现 S0 对最终 L2 全局幂等保留域扫描后冻结到数据头；不允许运行时生成、哈希或重试换键。

提供者唯一 ABI：

```cpp
class 真实自我形成提供者 final {
public:
    真实自我形成提供者(L2结构聚合服务& 聚合服务) noexcept;
    真实自我形成结果 形成(const 真实自我形成请求& 请求) noexcept;
    std::optional<真实自我事实> 读取已发布自我() const;
};
```

它只保存 A1 非 owning 引用、一个发布锁、固定请求选择和最后完整值式材料；不持有 L1、owner 端口、仓库、I2 引用或任何一步的中间身份缓存。最后完整值式材料只供成功后的副本读取，不参与失败恢复或下一次写请求组装。

## 4. 五步可恢复事务状态机

提供者完整持有自身发布锁。每次调用先经 A1 对 R1 当前登记与整树重新正式读回，并核对 I2 材料的树、根和首次根标记；异于已发布请求的完整请求在任何 L2 写前冲突。

跨 owner 不伪造成一笔事务。五步固定为：

1. `新增角色化存在`，角色固定为项目唯一自我；每次都先以同一固定幂等身份重放同义新增请求，从首次成功或精确重复结果重新取得自我存在身份，再按该角色正式读取并互证；
2. `新增树内场景(树, 根场景, 顺序=1)` 建立自我所在场景；
3. `新增场景成员关系(所在场景, 自我存在, 顺序=1)`；
4. `新增树内场景(树, 所在场景, 顺序=1)` 建立自我内部世界场景；
5. `新增场景宿主存在关系(内部世界场景, 自我存在)`。

每步请求使用前一步成功 / 精确重复结果中重新取得的身份和最新正式事实代次。一步发布后任一后继失败不得退出、回滚或换身份；返回具名阶段失败并保留已发布结构。原完整请求每次重试都从第一步开始，以五个固定幂等身份依序重放同义请求，从各步首次成功或精确重复结果重新发现自我存在、所在场景、成员关系、内部世界场景和宿主关系身份，再继续下一步；不得从 provider 缓存、上次返回值、参数附带身份或关系遍历猜测中间身份。异请求、异义幂等冲突或同角色不同存在固定失败，不能 adoption。

E-ROLE 与 S-HOST 的替换 / 退出是业务中性 L2 能力，但本提供者及其生产入口永不调用这些接口。固定项目角色、自我存在、两个场景、成员关系和宿主关系不通过普通 SELF-FORM 请求退役或改绑；未来若需要退役，必须另立具名机器语义、设计和计划，不能扩展本状态机临场处理。

并发同请求由 provider 锁串行；外部并发推进 L1 使某步漂移时，本轮返回 `事实代次竞争`，原请求重试。提供者不循环忙重试，不 sleep，不持自身锁调用用户回调或 I/O。

## 5. 完整正式读回

五步成功后必须重新取得当前代次，并在同一个截止依次正式读取：

- R1 整树；
- E-ROLE 项目角色；
- 自我完整存在与身份来源；
- 两个场景树节点、树归属与直接父；
- 所在场景完整读取中的精确成员关系；
- 内部世界按场景及按存在双向宿主关系。

验证：两场景均在 I2 证明的树；所在场景直接父是根，内部世界直接父是所在场景；成员唯一指向自我；宿主唯一指向自我；自我不是内部世界成员；根 / 自我 / 两场景编码互异；无自包含环。任一缺项、混代、额外冲突或坏成功形状整体失败且不发布值式材料。

首次完整发布返回 `已形成`；同请求再次逐步精确重复并重新正式读回后返回 `精确重复`，可刷新截止。发布使用局部完整构造与无抛出交换；异常保留旧值。

## 6. 普通应用与启动

E-ROLE / S-HOST 不改普通应用。SELF-FORM 在 I2 适配器之后构造唯一 `std::unique_ptr<真实自我形成提供者>`，参数为同一 A1 聚合实例；上下文成员声明更晚、析构更早，增加 const / 非 const getter。构造失败追加专属连续装配状态。

`运行普通程序` 在 I2 成功后形成默认请求并调用 provider：

```text
失败 -> 初始化失败 / 真实自我形成 = 17
成功 -> 初始化失败 / 概念维度根生产初始化能力未实现 = 18
```

实施删除阶段 17 的“自我初始化能力未实现”固定成功后短路，但保留数值 17 并改为真实形成失败阶段；新增 18。阶段 18 之前不得调用方法根、自我线程、概念支持、投影、信号或宿主。4240 C1 仅是结构能力，不得冒充概念维度根生产初始化。
