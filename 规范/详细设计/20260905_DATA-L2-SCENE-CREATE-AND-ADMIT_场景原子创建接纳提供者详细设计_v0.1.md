# 场景原子创建接纳提供者详细设计

日期：2026-09-05

身份：`DATA-L2-SCENE-CREATE-AND-ADMIT`

版本：v0.1

状态：提供者合同已冻结；可进入代码实施

代码事实基线：`f61aee960aad54b6cef1c5f05693c1ccd6b79c34`

## 1. 目标与归属

为新`数据服务.场景类`补充一个 scene owner 专用数据操作：在一个 L1 所有者范围中性写集中同时创建一个新场景结点，并用一条子场景关系把它接纳为已存在父场景的直接子场景。该能力是世界树后继“创建场景并纳入现实世界”的最早提供者，不是世界树公开语义，也不替代既有单独`新增场景`和`新增成员关系`。

正式依据：0050 的同代次事实、局部键引用、幂等与发布未知边界；4200 的纯场景树；4230 的 scene owner 唯一写边界；1140/1150 的内部世界仍须先成为场景子树。旧 `服务.L2*`、旧实现和聊天描述均不构成可调用依赖。

## 2. 当前事实与复用裁决

当前`场景类数据服务`已经具备：

- `新增场景`：一个写集只创建场景结点；
- `新增成员关系`：另一个写集只建立父场景到既有子场景的关系；
- scene owner 写端口、子场景关系类型、当前 / 历史节点和关系读取、首次写入材料、编码映射、状态映射与异常收口；
- L1 写集关系端点支持`稳定编码`或同写集`L1所有者范围写集本地键`。

连续调用前两项会留下“结点已创建、接纳尚未发布”的可见半结构，不能用于一个原子提供者。新入口必须直接形成一个写集，不能内部调用两个现有公开写入口，也不能失败后删除新结点补偿。

## 3. 机器不变量

1. 请求只提交父场景，不提交或预分配新场景编码；新编码由 owner 写集映射产生。
2. 父场景在请求 G0 必须是本 scene owner 当前普通场景；父场景可以是结构根或普通场景。
3. 一个写集包含且只包含：一个普通场景结点 N、一个`父场景 -> N`子场景关系 E；E 的角色固定为 1。
4. N 和 E 在同一提交代次创建，N 从出生起恰有一个父关系，因此本入口不能创建新的结构根。
5. N 是同写集局部新节点，出生时没有子场景或其它成员；形成环在结构上不可能，不增加形式化防环遍历或`形成场景环`状态。
6. 同一请求键精确重放返回原 N/E；同键异义、被其它场景入口占用或字段不同均为`幂等冲突`。
7. 提交成功后必须读回 N、E、父场景的子成员引用和 N 的父引用；不能闭合时返回`已可能发布`，不得补偿。
8. 精确重复证明原写集在原发布代次形成，不证明 N 当前仍位于原父场景；后继世界树应用必须 fresh 读取现实根闭包后才声称当前接纳完成。

## 4. 物理位置与依赖

只扩展既有：

- 文件：`海中鱼巣/领域/数据服务.场景类.ixx`
- 模块：`海中鱼巣.领域.数据服务.场景类`
- 类：`海中鱼巣::场景类数据服务`

不新增模块、工程项、owner、关系类型、写端口或 import。实现只调用当前场景类已经持有的 L1 事实基座 / scene owner 写端口和本类私有读取能力；不得调用世界树应用服务、存在类写入口、旧 L2 或其它数据类写入口。

## 5. 冻结 ABI

### 5.1 版本与状态

```cpp
inline constexpr std::uint32_t 场景类创建接纳合同版本 = 1;

enum class 场景类创建接纳状态 : std::uint8_t {
    已创建并接纳 = 1,
    精确重复 = 2,
    入口拒绝 = 3,
    父场景未找到 = 4,
    父场景已退出 = 5,
    子场景关系类型未找到 = 6,
    子场景关系类型已退出 = 7,
    事实代次漂移 = 8,
    幂等冲突 = 9,
    引用冲突 = 10,
    历史材料已清理 = 11,
    资源失败 = 12,
    内部不一致 = 13,
    已可能发布 = 14
};
```

数值是公开合同的一部分。`已可能发布`不是成功，只允许原请求原键重放。

### 5.2 请求、投影与结果

```cpp
struct 场景类创建接纳请求 final {
    std::uint32_t 合同版本 = 场景类创建接纳合同版本;
    std::uint64_t 期望事实代次 = 0;
    L1所有者范围写入幂等身份 幂等身份{};
    稳定编码 父场景{};
    friend bool operator==(const 场景类创建接纳请求&,
        const 场景类创建接纳请求&) = default;
};

struct 场景类创建接纳投影 final {
    稳定编码 父场景{};
    稳定编码 新场景{};
    稳定编码 接纳关系{};
    friend bool operator==(const 场景类创建接纳投影&,
        const 场景类创建接纳投影&) = default;
};

struct 场景类创建接纳结果 final {
    场景类创建接纳状态 状态 = 场景类创建接纳状态::入口拒绝;
    std::uint32_t 合同版本 = 场景类创建接纳合同版本;
    std::uint64_t 事实代次 = 0;
    std::optional<场景类创建接纳投影> 投影;

    bool 成功() const noexcept;
};
```

`成功()`只接受`已创建并接纳`或`精确重复`，并要求版本正确、非零代次、投影存在、三个编码有效、父场景 != 新场景且新场景 != 接纳关系、父场景 != 接纳关系。所有非成功结果的投影为空。

### 5.3 服务入口

在既有`场景类数据服务`公开区、`新增场景`之后新增：

```cpp
场景类创建接纳结果 创建并接纳场景(
    const 场景类创建接纳请求& 请求);
```

这是唯一新增公开函数。既有构造、合同版本、枚举数值、DTO 和函数签名不变。

## 6. 写集与局部键

复用现有局部键：

- `场景结点本地键{1}`：新场景 N；
- `成员关系本地键{2}`：接纳关系 E。

规范化写集必须精确为：

```cpp
L1所有者范围写集请求 写集;
写集.合同版本 = L1所有者范围CRUD合同版本;
写集.期望事实代次 = 请求.期望事实代次;
写集.写入幂等身份 = 请求.幂等身份;
写集.节点 = {{场景结点本地键, 节点种类::普通, std::nullopt}};
写集.关系 = {{成员关系本地键,
    请求.父场景,
    场景结点本地键,
    子场景关系类型_,
    1}};
```

`值`、`属性槽变更`和`退出事实`必须为空。不得把未发布的新场景编码预先写成稳定编码，也不得拆成两个写集。

## 7. 首次执行状态机

1. 请求必须满足合同版本、非零 G0、有效幂等身份和有效父场景，否则`入口拒绝`。
2. 先读取首次写入材料；存在时进入第 8 节重放，不能先按当前父场景短路。
3. 用本类场景本体读取在 G0 校验父场景。L1`未找到/已退出/事实代次漂移/历史已清理/资源失败`分别映射同义状态；坏 owner、坏节点种类或坏载荷映射`内部不一致`。
4. 形成第 6 节唯一写集，并调用一次`提交所有者范围中性写集`。
5. L1`成功/精确重复/入口拒绝/未找到/已退出/事实代次漂移/幂等冲突/引用冲突/资源失败`依次映射为`已创建并接纳/精确重复/入口拒绝/子场景关系类型未找到/子场景关系类型已退出/事实代次漂移/幂等冲突/引用冲突/资源失败`；许可拒绝和未知状态保守映射`内部不一致`。
6. 首次材料未命中后的提交若返回 L1`成功`，进入首次当前读回；若因并发竞态返回`精确重复`，不得再次提交，而是重读首次材料、逐字段证明同义后，直接使用本次`精确重复`结果进入原发布代次历史读回。不能直接跳过材料证明生成成功投影。

## 8. 幂等重放

每次公开调用最多提交一次。重放分成两条互斥路径：

### 8.1 预读已命中首次材料

读取同一 scene owner、同一幂等身份的首次写入材料：

- 未找到：继续首次路径；
- 历史已清理：返回`历史材料已清理`；
- 读取漂移 / 资源 / 其它失败：按合同映射，零投影；
- 已找到：首次规范化写集必须与第 6 节按本次请求形成的写集逐字段相等，首次结果必须为 L1`成功`且结果头完整；否则`幂等冲突`。

材料一致时以原写集提交一次；只有 L1`精确重复`才进入发布读回并最终返回`精确重复`。若返回新的`成功`，返回`已可能发布`；其它状态按第 7 节映射，不能形成第二组 N/E。

### 8.2 预读未命中、提交竞态返回精确重复

本路径不得再次提交。必须重新读取同一幂等身份的首次材料，并同时核对：首次规范化写集与本请求期望写集逐字段相等；首次结果为 L1`成功`且与本次`精确重复`结果的 owner、幂等身份、事实代次和两个编码映射一致。

- 重读返回`历史材料已清理/事实代次漂移/资源失败`时映射同名状态；
- 重读仍未找到、入口 / 许可失败、缺首次写集 / 结果或结果头不完整时返回`内部不一致`；
- 材料存在但请求、首次结果或本次重复结果不一致时返回`幂等冲突`；
- 全部一致时直接用本次 L1`精确重复`结果进入第 9 节历史读回并返回`精确重复`。

两条路径都恰有一次提交；材料重读是只读，不是自动重试。

## 9. 发布读回

两种成功路径共同要求写入结果的 owner、幂等身份、合同版本、非零原发布代次正确，且新编码映射恰有两个互异编码：局部键 1 映射 N、局部键 2 映射 E。结果头再按状态分别核对：

- L1`成功`必须`是否形成内存权威发布 == true`且重试边界为`不适用`；
- L1`精确重复`必须`是否形成内存权威发布 == false`且重试边界为`原幂等身份读回收敛`。

不得把首次发布头规则套到精确重复。任何头字段、映射缺失、重复、额外或无效均在 L1 已报告成功 / 精确重复的边界下返回`已可能发布`。

首次`已创建并接纳`在发布代次执行当前读回；`精确重复`在原发布代次执行历史截止读回。两者都必须证明：

1. N 是本 owner 普通场景结点，创建代次等于发布代次；
2. E 是本 owner 子场景关系，源=请求父场景、目标=N、类型=`子场景关系类型_`、角色=1、创建代次等于发布代次；
3. 父场景投影在该截止恰含一条指向 N 且编码为 E 的子场景引用；
4. N 的父场景引用恰为请求父场景且关系编码为 E；
5. 在该截止 N/E 尚未退出。

任一项不能闭合，提交已经报告成功时返回`已可能发布`；不补偿、不删除、不伪称零写。成功结果只返回薄投影 `{父场景, N, E}`。

精确重复的历史投影只证明原发布事实。若 N 后来迁移或退出，结果仍可为`精确重复`；当前业务语义必须由上层以 fresh G 另行确认。

## 10. 异常、诊断与完成边界

- 提交前 `std::bad_alloc` / `std::length_error`为`资源失败`，其它异常为`内部不一致`。
- L1 已报告成功后的编码提取、历史 / 当前读回或异常失败统一为`已可能发布`。
- 该 DATA-L2 模块不写最终业务日志；结构化结果向上送出。`成功()`纯谓词无诊断分支。
- 本计划只提供数据结构原子创建 / 接纳，不选择现实根、不验证新场景属于哪棵现实世界、不创建存在、不建立宿主存在、不接纳子存在、不生成状态 / 动态 / 特征，也不修改世界树应用 ABI。

## 11. 后继消费边界

提供者发布后，世界树应用后继可在其绑定现实根内先 fresh 验证父场景，再调用本入口；`已创建并接纳`后以发布代次重读绑定根闭包，只有新场景位于该闭包才返回世界语义完成。`精确重复`必须以 fresh 当前闭包确认；`已可能发布`只允许原键重放。该 ARCH-L3 消费合同不属于本 DATA-L2 代码切片。
