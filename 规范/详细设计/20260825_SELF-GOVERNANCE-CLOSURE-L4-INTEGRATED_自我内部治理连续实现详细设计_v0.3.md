### 2.1 COMPLETION-MESSAGE-RUNTIME-GENERATION-v2 增量合同

本条是执行侧具名漂移的计划支撑裁决，覆盖任何旧的消息版本 1、二元消息键或仅检查定位运行代次非零的表述：

```cpp

// 任务动作完成消息既有字段顺序保持；在“动作顺序”后追加：
```

`任务动作完成消息有效`必须要求运行代次非零；默认相等比较使运行代次进入逐字段同义。消息账唯一键为`{运行代次, 执行幂等身份.值, 动作顺序}`：首次为已发布；同三元键完整消息相等为精确重复；同三元键异义为幂等冲突；不同运行代次是不同账项；独立读取必须提供三元键，错误运行代次为未找到，零运行代次为入口拒绝。除已发布、精确重复和已独立读取外，全部状态空载荷且失败。

`收束待验证任务动作结果`只能从`任务动作待验证材料.运行代次`原样形成消息并按同一三元键独立读回；权威快照继续值式嵌入完整消息，不建立运行代次影子字段。manager 和上行桥必须在任务、三轮次、冻结、实例、方法和末动作顺序之外显式验证`完成消息.运行代次 == 工作结果定位.运行代次`，不相等不得形成成功、回执或 task-owner 写入。

### 3.3 验证算法

provider 固定执行：

```text
验证合同、许可、身份、幂等和共同截止
-> 独立读取正式结果、容量合同及冻结成员集合
-> 候选组按成员身份规范化，但不得据此生成业务顺序
-> 验证每个冻结成员恰有一项候选且没有额外成员
-> 验证优先级序号、同级顺序序号均非零
-> 同一优先级内同级顺序全局唯一
-> 每项理由证据非空、当前且绑定该成员和正式结果
-> 证明容量合同是争用形态；可重复引用不得进入本provider
-> 在自我 owner 单次写集中形成一个批次和全成员事实
-> 独立读回完整批次与成员组
```

同键同义读回首次结果；同键异义、成员漏项/多项、重复同级序号、来源规则或版本变化全部零新增拒绝。

### 4.2 原子形成算法

```text
交换前独立读取结果、冻结成员、容量合同和可选优先级批次
-> 完整验证所有候选、容量、量纲、规则和当前性
-> 可重复引用：按成员身份规范化输出并赋处理顺序1..N；每项共同引用、正式优先级空，最低/期望/分配前/实际/分配后全为0
-> 可分割：按正式全序；剩余=0则结果已耗尽；0<剩余<最低则未获分配且剩余不变；否则实际=min(期望,剩余)且状态已分配
-> 不可分割：初始1、每成员最低/期望1；正式全序首个合法成员分配1，其余结果已耗尽
-> 每一步分配后剩余成为下一步分配前剩余；验证“分配前 - 实际分配 = 分配后”且sum(实际)+最终=初始
-> result owner 一次提交完整记录、关系、成员、优先级引用、逐项链和幂等账
-> 独立读回完整记录
```

逐成员合法矩阵固定为：`共同引用`只允许可重复引用、优先级空且五个分配相关数值为零；`已分配`只允许两类争用且`最低<=实际<=期望、实际<=分配前、分配后=分配前-实际`；`未获分配`只允许可分割、`0<分配前<最低、实际=0、分配后=分配前`；`结果已耗尽`只允许两类争用且分配前/实际/分配后全为零。低于当前成员最低单位后仍继续处理后继成员，禁止把稳定成员身份、任务优先级、需求权重、预算、创建时间或列表顺序补成业务优先级。

禁止逐成员可见提交。任何交换前失败零写；已确认提交后的读回失败保留事实和账，以原键重放。可共用记录不依赖优先级；争用缺任一优先级、同级顺序、单维容量或成员证据时零写并阻断后继核算。

### 5.1.1 Task owner 当前任务与当前轮次机械读回 ABI

主阶段治理不得调用或暴露`L2任务结构服务::读取任务轮次机械事实(...)` private helper，也不得用初建幂等身份反推当前轮次。task owner 新增一个只读公开入口，唯一回答“指定任务在请求 G0 的正式当前轮次关系是否唯一并可形成完整轮次事实”；它跟随既有`任务 -> 当前轮次`关系，不裁决业务上哪一轮应该当前。

公开 DTO 位于`领域/L2任务结构.数据.h`，紧随现有任务读取 DTO；公开成员位于`L2任务结构服务`现有`读取任务(...)`之后。完整物理合同固定为：

### 5.1.2 Task owner 正式选择、冻结材料与路径 v2 动作组合同

`DRIFT-TASK-OWNER-PATH-STILL-BINDS-V1-ACTION-WHILE-UPLINK-CONSUMES-V2-ACTION`的根因不是身份比较错误，而是当前 task 正式选择仍把路径冻结为一个 v1 动作事实，而生产冻结和结果上行已经消费 method v2 完整动作组。v1/v2 动作由不同写集形成，禁止伪造两身份相等、把 v2 请求降回 v1、只投影第一个动作或在结果写入时重新读取当前方法覆盖历史路径。

#### 5.1.2.1 唯一权威与版本边界

v2 只新增 DTO、持久序列格式和投影，不新增第二条“任务当前正式选择”关系。v1/v2 必须复用现有`L2任务当前正式选择关系类型身份`、任务源端、选择记录目标端、角色1及同 task 至多一条活动关系的唯一性作用域。首次 v2 正式选择在 task owner 一个 L1 原子写集中形成选择记录、执行绑定冻结材料、路径、实例及当前关系迁移，最终共同事实代次为 G1；交换前任一失败整笔零写。

既有 v1 四类公开 DTO、成员名、布局和函数签名保留。v1 历史事实继续由 v1 读取入口读取；v1 `发布任务筹办正式选择(...)`在本切片后只作源码兼容拒绝入口，固定返回公共入口拒绝、零载荷、零写。v1 读取遇到 v2 持久格式固定返回入口拒绝且不得降级；v2 读取遇到 v1 格式同样不得伪造成 v2。`L2新增任务方法路径`只建立非当前 v1 路径，不取得当前正式选择权威，保持原合同。

#### 5.1.2.3 完整性、结果矩阵与成功公式

`方法动作组正式读回`必须是`读取完整有序方法动作入口组_v2(方法, 方法内容版本, G0)`的成功结果，截止等于请求 G0，组非空且物理顺序严格为1..N。`冻结材料.完整有序动作组`必须由该组逐项无损投影：动作身份、方法、内容版本、顺序、稳定动作键、作用范围、主体/场景约束、动作范围材料、技术许可版本、预期结果、验证合同、归因合同及来源生命周期全部相等；身份和稳定键各自唯一，全部来源动作在 G0 有效。条件、输入、参数、限制、主轴结果、验证和归因仍沿用 v1 逐字段闭包，但不得代替动作组。

写入矩阵固定为：坏专属版本/共同头/G0/基础材料/冻结闭包返回`入口拒绝`；method读回与请求方法、版本、G0或动作组错配返回`引用冲突`；当前代次变化返回`当前性漂移`；同来源幂等身份同完整请求返回`精确重复`和首次 G1；同键异义返回`幂等冲突`；许可、资源、内部异常分别映射。交换前所有非成功全部载荷空、截止0、零写。首次提交或精确重复完成正式读回时返回三份完整事实、四字段提交见证和 G1；`成功()`当且仅当状态为`已形成/精确重复`、三份事实及有效提交见证存在、截止非零、选择/冻结/路径/实例同 task、轮次、方法和版本闭合，且冻结动作组与路径动作组逐项相等。

L1 已确认提交但独立读回未收束时返回`已可能发布`：只保留四字段提交见证，三份事实、旧当前三身份及正式读回截止为空/0；不得回滚。调用方只以原来源幂等身份和原完整请求重放。精确重复零应用、零新代次，返回首次 G1、首次三事实及首次旧当前身份投影。

读取矩阵固定为：只有同一截止读到一份匹配格式的选择记录、冻结事实、v2 路径、实例及当前关系闭包才返回`已读取`；0条为`未找到`，当前关系>1为`关系多义`，v1/v2格式错配、路径序列破损、组不相等、端点/owner/生命周期错配为`引用冲突`；许可、G0、资源、内部各自映射。所有非成功载荷空、截止0。历史读取只返回选择时冻结的 v2 路径，不重新查询 method 当前动作定义。

#### 5.1.2.4 持久序列与事务

v1 正式选择完整请求的首值格式2保持不变。v2 完整请求首部固定为`[格式3, 专属合同版本2, 共同结构合同版本, G0]`；其后按 v1 现有编码器顺序保存来源分支及来源材料、任务身份来源、方法生命周期、选择/召回版本、来源需求组、稳定证据组、冻结 task/轮次/方法/版本、条件组、输入组、参数组和限制组；原单一动作事实位置替换为下述完整动作组序列，再保存主轴结果、验证合同、归因证据和失效截止。所有未替换嵌套段逐字段顺序与 v1 编码器一致，不保存对象内存或类型名。

动作组序列物理格式固定为：

```text
[格式2, N,
  对每个i=1..N:
    动作身份, 方法, 内容版本, 顺序, 稳定动作键, 作用范围, 作用主体,
    场景有值0/1, [场景],
    动作范围材料, 技术许可合同版本, 预期结果材料, 结果验证合同, 动作归因合同,
    创建事实代次, 退出事实代次有值0/1, [退出事实代次]]
```

N 必须非零；所有枚举和 bool 先转`std::uint64_t`；稳定编码保存其值；解码必须消费全部输入且重跑完整性。摘要只能作诊断，不能代替该完整序列。路径节点新增独立`路径完整有序动作组属性类型_v2`保存此序列，v2 路径不写旧`路径动作入口属性类型`；v2 private投影按新属性形成`L2任务方法路径事实_v2`，v1 private投影遇到 v2 格式确定性拒绝。

首次事务在同一 task owner 写集中形成冻结节点、选择记录、v2 路径、实例及其关系，原子退出旧当前选择/路径/实例关系并形成各一条新当前关系，全部创建/退出代次等于 G1。旧选择和旧路径事实永久可按历史截止读取。任何截止当前关系多于1条均为内部结构冲突，禁止任选。

`记录任务实际结果_v2`及目标未达成裁决只读取持久 v2 当前/历史路径：请求动作必须在`完整有序动作组`中恰好命中一项，并与同一任务、实例、方法、执行轮次闭合；不再比较旧单动作字段。`领域/组合.运行期只读查询.ixx`同样按持久格式分支：v1 历史维持单动作比较，v2 当前/历史做唯一成员匹配；不得用 method 当前定义改写选择时快照。

#### 5.1.2.5 planning 与主阶段顺序

唯一生产调用者为`任务筹办当前就绪与执行冻结提供者::形成当前可执行冻结_v2`。`任务筹办当前就绪请求_v2`增加一项强类型`L2任务筹办正式选择基础材料_v2 正式选择基础材料`；`任务筹办当前就绪结果_v2`保留现有来源 G0 和执行投影，并增加：

```cpp
std::optional<L2方法完整有序动作组读取结果> 方法动作组正式读回;
std::optional<L2发布任务筹办正式选择结果_v2> 正式选择结果;
```

provider 在 G0 完成现有需求、条件、输入、参数、限制、方法和完整动作组读回后，先无损形成 task v2 动作冻结组，再调用`发布任务筹办正式选择_v2`。正式选择首次/重复成功才返回`已就绪`；现有`共同事实截止`继续表示来源 G0，正式选择结果截止表示 task owner G1。提交后未知映射新增结论`正式选择待收束=6`；入口拒绝、许可拒绝、幂等冲突分别新增专用结论12、13、14，其余沿现有当前性/引用/资源/内部状态映射。任何选择非成功均不迁移阶段。

主阶段只在 planning 的 v2 正式选择成功后，以实际 G1 构造阶段迁移请求头并调用阶段端口，形成阶段 G2；禁止沿用原 planning G0，也禁止调用方预造 G1。`已可能发布`原样保存嵌套选择结果并映射主阶段`已可能发布`，零阶段调用；原键重放先收束 task G1，再以原阶段幂等身份收束 G2。

### 5.2 L4 主阶段治理公开合同

`治理当前任务阶段`只负责把 task owner、正式阶段读回、planning provider 和统一后继消费串成一个可重放的阶段选择入口。它不执行现实动作、不替代派发门控、结算 provider 或 self 决议，也不把任务管理线程的期望阶段保存成第二阶段事实。唯一阶段权威仍是阶段端口的正式当前选择和状态读回。

`任务主阶段治理请求`的`期望阶段`只是调用方期望，不取得事实权威。合同、请求头、G0、任务/轮次/正式存在/阶段特征实例必须有效。task owner 在 G0 独立读回的任务和当前轮次必须逐字段绑定请求；阶段端口随后用同一请求头、正式存在和阶段特征实例读取当前阶段。当前状态的精确值材料必须恰为`{主阶段, 状态段}`，时间值材料必须恰为`{当前阶段发生时间, 任务轮次序号}`，来源稳定编码必须绑定`当前任务轮次`；解码结果不等`期望阶段`返回`当前性漂移`。调用方不得把缓存、线程槽或请求期望当成阶段读回。

planning 分支所需迁移请求只能由 provider 在阶段读回后机械形成：复制请求头、任务正式存在、阶段特征实例、当前状态和完整旧当前选择；任务轮次序号与当前阶段发生时间取自正式状态时间材料；幂等身份、来源治理动作和目标阶段发生时间只取选中的`任务主阶段迁移材料`。`转入筹办等待材料`的目标固定为`{筹办,筹办等待}`，`转入可执行已冻结材料`的目标固定为`{筹办,可执行已冻结}`。调用方不得预造当前状态或当前选择。

调用顺序固定为：

```text
入口形状验证
-> task owner 调按任务读取当前任务与轮次，在请求 G0 一次形成两份事实
-> 阶段端口在同一 G0 独立读取当前阶段并解码九段之一
-> 筹办中/筹办等待：planning provider 形成当前可执行冻结_v2
   -> 已就绪：阶段端口发布到可执行已冻结
   -> 合法未就绪：筹办中发布到筹办等待；已在筹办等待则零写
-> 轮次已收束待自我决议：调用统一消费自我任务后继决议
   -> 该既有入口内部保持 self 正式读回 -> task owner机械写读
      -> 仅继续分支再做阶段当前读与阶段迁移
```

主入口不得绕过 planning provider 直接构造冻结，不得绕过`消费自我任务后继决议`直接调用 task owner，也不得在同次分支失败后尝试另一分支。

九阶段穷尽矩阵固定为：

| 正式当前阶段 | 必需分支材料 | 唯一调用与成功状态 | 结果载荷 |
| --- | --- | --- | --- |
| `{筹办,待初次筹办}` | 三类可选分支材料全空 | 零写返回`已选择阶段`；任务管理转初次筹办入口 | task/轮次/阶段正式读回；其它分支载荷空 |
| `{筹办,筹办中}` | 筹办请求、等待迁移材料、冻结迁移材料均存在；后继请求空 | planning 已就绪且冻结迁移成功为`筹办已冻结`；合法未就绪且等待迁移成功为`筹办已等待` | 筹办结果必有；发生迁移时阶段迁移结果必有 |
| `{筹办,筹办等待}` | 筹办请求和冻结迁移材料存在；等待迁移材料、后继请求空 | planning 已就绪且冻结迁移成功为`筹办已冻结`；合法未就绪零写为`筹办已等待` | 筹办结果必有；仅冻结成功带阶段迁移结果 |
| `{筹办,可执行已冻结}` | 所有分支材料空 | 零写返回`已选择阶段`；任务管理进入派发门控 | 仅 task/轮次/阶段正式读回 |
| `{筹办,待自我现实执行授权}` | 所有分支材料空 | 零写返回`已选择阶段`；任务管理继续授权/门控 | 仅 task/轮次/阶段正式读回 |
| `{执行,执行动作中}` | 所有分支材料空 | 零写返回`已选择阶段`；任务管理等待不可变完成定位 | 仅 task/轮次/阶段正式读回 |
| `{执行,执行结果待结算}` | 所有分支材料空 | 零写返回`已选择阶段`；任务管理进入结果消费与结算 | 仅 task/轮次/阶段正式读回 |
| `{结算,任务轮次结算中}` | 所有分支材料空 | 零写返回`已选择阶段`；任务管理继续轮次结算 | 仅 task/轮次/阶段正式读回 |
| `{轮次已收束,轮次已收束待自我决议}` | 仅后继消费请求存在 | 后继结果成功为`后继已消费` | 后继消费结果必有；planning/直接阶段迁移载荷空 |

planning 的`条件未满足、输入待绑定、限制待解释、方法结构待补齐、数量预算不足`均是合法筹办等待，不伪装成错误；`当前性漂移、引用冲突、资源失败、内部错误`映射同名主治理非成功。后继的`决议未找到/决议不适用`分别映射`后继决议未找到/后继决议不适用`；其余状态按同名映射。阶段无当前选择或 provider 待迁移映射`阶段待迁移`。未识别下游状态、状态材料形状错误、跨 task/轮次/G0 引用错配统一为`内部不一致`或`引用冲突`，不得降级等待。

载荷矩阵固定为：入口形状失败全部可选载荷空且截止0；task owner读回失败按第5.1.1节穷尽映射主治理状态，任务/轮次/阶段及分支载荷全部为空；task owner成功后才把两份事实复制到主治理结果。阶段读取失败只允许 task/轮次事实和`当前阶段读回`，当前阶段与分支载荷空；planning 非成功保留 task/轮次/阶段读回与`筹办结果`，阶段迁移和后继为空；阶段迁移非成功再增加`阶段迁移结果`；后继非成功只增加`后继消费结果`。嵌套`已可能发布`必须原样保留下游提交见证，主治理不制造第二见证，调用方只按原请求和原幂等身份重放。

`成功()`当且仅当合同版本正确，task/轮次/阶段三类正式读回完整且共同选择截止等于请求 G0，并满足下列一项：`已选择阶段`只对应第1、4、5、6、7、8段且三种分支结果全空；`筹办已冻结`具有`已就绪`筹办结果和成功的可执行已冻结迁移；`筹办已等待`具有合法未就绪筹办结果，且从筹办中进入时具有成功等待迁移、已在筹办等待时迁移结果为空；`后继已消费`具有成功的后继消费结果。其它组合失败。

`任务主阶段治理提供者`唯一构造和公开顺序改为：

```cpp
任务主阶段治理提供者(
    L2任务结构服务& 任务结构服务,
    任务筹办当前就绪与执行冻结提供者& 筹办提供者,
    自我任务后继决议提供者& 自我后继决议提供者,
    任务阶段结构消费端口& 阶段端口) noexcept;

任务主阶段治理结果 治理当前任务阶段(
    const 任务主阶段治理请求&) noexcept;
```

`治理当前任务阶段`是 class 首入口；既有统一后继消费紧随其后。不得新增按九段分别公开的入口。

### 5.3 L4 统一消费自我任务后继决议

四分支状态×载荷矩阵固定为：

| 结束当前任务 | `已结束` | `精确重复`且指令回显结束 | 决议引用、正常结束生命周期收口、非零task正式读回截止 | 新Rn、新Pn、继续动作、阶段证据、阶段截止、两类提交见证 |
| 保持等待 | `已等待` | 再调用仍返回`已等待` | 仅状态与指令 | 全部 optional 载荷、两个截止；task零写、阶段零调用 |
| 取消任务 | `已取消` | `精确重复`且指令回显取消 | 决议引用、取消生命周期收口、非零task正式读回截止 | 新Rn、新Pn、继续动作、阶段证据、阶段截止、两类提交见证 |

继续分支唯一事务顺序为：主阶段治理调用 task owner 机械写入口，以一个写集同次建立 R(n+1)、P(n+1)、继续治理动作和决议引用并正式读回；再调用阶段端口迁移到`{筹办,筹办中}`。两次提交各有自己的 G1，不宣称跨 owner 单 G1。task 提交已确认而读回失败只返回`已可能发布 + task提交见证`；task 已收敛而阶段提交已确认但读回失败返回`已可能发布 + 已读回task四事实 + 阶段提交见证`。原请求原双幂等身份重放时先经 task 机械入口收敛，完整复用首次四事实，再重放阶段请求；任何后段失败不得回滚前段事实、账或代次。

结束/取消由主阶段治理调用 task owner 生命周期机械写入口，以一个写集同次建立决议引用和相应生命周期收口；结束收口种类只能为`正常结束`，取消只能为`取消收口`。二者不建立新轮次、P、治理动作或阶段迁移，不把结束/取消伪装成筹办状态。精确重复直接返回首次事实投影，零应用、零新代次。幂等身份相同但决议、T、Rn、结算、停止证据、发生时间或规则版本不同返回`幂等冲突`；前态、引用或当前性不一致分别返回`当前性漂移/引用冲突`且交换前零写。

诊断责任固定为：预期的等待、决议不适用、入口/许可/当前性/幂等/引用/资源非成功只结构化返回，不写错误；task owner 只记录自身结构闭包矛盾和捕获异常；主阶段治理只记录自身组合不一致、task 机械结果非法或阶段端口非法状态×载荷。任务管理线程只调用本入口并路由结果，不复制四分支、不裸写 task 事实、不依据“目标未达成”自动继续。

### 10.3 任务管理唯一生产调用与11字段来源

### 11.2 fresh 目标 ABI 与矩阵

10. `CALL10 TD_INDEPENDENCE`：`T→D` 为 0 / 1 / N 均不证明发起调用，也不阻塞子轮次收束；
11. `CALL11 LEGACY_ZERO_PRODUCTION`：结果容量、共用 / 争用、成员优先级、消费分配、未获分配和结果耗尽生产调用归零；
12. `CALL12 VALUE_ATTRIBUTION_SEPARATE`：多个需求可分别满足，但价值 / 预算 / 奖励 / 归因不重复领取；
13. Debug / Release、工程模块唯一登记、普通应用唯一构造、首次 / 重放 / 冲突 / 漂移 / 资源 / 已可能发布，以及连续两轮端到端均在恢复完整分支后通过。

本节只冻结设计和施工合同，不声明任何上述 C++ 已实现。FRESH 调度适用场景的独立具名 DRIFT 仍只阻断 FRESH consumer，不阻断本结算切片的设计落盘。
