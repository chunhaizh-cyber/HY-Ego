# 执行许可按目标达成判定详细设计

标识：`CAUSAL-PERMIT-GOAL-CHECK`；版本：v0.1；日期：2026-11-07；状态：已定稿（用户2026-11-07确认开始施工）。

依据：
- 用户本窗口裁决（2026-11-07）：
  - 执行许可只需检查场景中目标状态是否已经达成，即再读取一次目标特征的值，和任务目标中的值比较；
  - 采纳建议：任务目标未达成，并且父链上每一层需求都未达成，才发许可。任一层已达成不发许可；任一层当前值认知不足，按未达成处理。
- 规范：5260（任务治理）、3100（需求）。
- 代码基线：main `2d1329c25`。

## 1. 目标与完成条件

1. `新_任务类::读取因果执行许可` 只判定任务需求及其父链各层的目标是否已经达成，不再重新逆推因果、核对来源前驱前端或采用依据。
2. 达成判定复用 `新_需求类::复核当前满足`（读取目标特征当前值，与目标比较）。
3. 实际项目编译、链接通过；完成声明只到“已编译、未运行测试”。

不在范围：执行方向核验与执行前判断（好坏判断，另有裁决）、因果子需求的筹办与采用本身、许可之外的场景核验批。

## 2. 当前事实（路径相对 `海中鱼巣/海中鱼巣/`）

- `读取因果执行许可`（`领域/新_任务类.cpp:15270`）：
  1. 读取任务需求准备保护批，读取任务，记录配置，沿父链收集各层治理信息与因果采用记录（`因果子需求依据_`），捕获各层需求节点保护；
  2. 对每条因果采用记录：
     - 来源前端采用：调用 `构造已采用来源前端当前请求`，重新逆推并核对前端；
     - 其余采用：调用 `构造自身发布后因果请求` 与逆推，或复核“当前子目标仍受支持”。

     任一不成立即返回空。
- 许可的使用者：
  - 开始执行（:10556 及 :23977 的有限重读）；
  - 确认进入待执行（:23851）；
  - 因果子需求承接后的子任务许可（:15600、:15831）。

  它们都在锁内调用 `核对因果执行许可`，核对配置、保护快照与采用记录未变。
- run-95：交互者任务 19552 每轮在第 2 步的来源前端分支返回空（67 次），任务零动作退出，未进入执行前判断。

## 3. 新规则

对任务需求 D0 及其父链 D1…Dn（直到根），逐层：

| 当前满足状态 | 处理 |
| --- | --- |
| 已满足 | 不发许可（该层目标已达成，不必执行） |
| 资源失败 | 资源失败，按现有路径送出 |
| 其余（需增加、需减少、未满足但无有向差值、当前值认知不足、需要执行前后比较、目标特征尚未形成、当前值不存在等） | 视为未达成，继续 |

另外：任一层需求活动状态为失活，不发许可（不再需要）。

全部层都未达成，发许可。

保护：每层捕获需求节点，以及 `复核当前满足` 返回的实际特征节点（目标特征当前值所在节点），并入许可保护。之后 `核对因果执行许可` 核同这些快照：任一层的目标值变化都会使许可失效，按现有路径重读。

### 3.1 被替代的旧口径

| 旧口径 | 当前裁决 |
| --- | --- |
| 许可要求每条因果采用记录的依据（来源前驱前端、自身发布后因果请求、逆推结果）在当前事实下仍成立 | 只看任务目标与父链各层目标是否已达成 |
| 有采用记录时要求因果筹办读取接口已装配 | 不再要求 |

代价（已告知用户）：因果规则本身变化而父需求仍未满足时，许可不再拦截，由重新筹办处理。
