## 1. 目标与边界

首版在已有网页保留消息交互、服务要求输入及结束入口，增加运行总览、需求—任务树、选中项详情、方法学习概况和时间线区域。只读正式 owner 数据，帮助区分系统在做什么、等待什么和哪些信息尚未接入。

不修改需求、任务、方法、筹办、学习、结算的机器语义，不从日志推导事实，不建立业务事件的第二权威；不提供直接完成任务、改服务值、强制执行或重学按钮。读取任务等待不等于线程卡死，待学数量不等于学习线程正在学习，采集时间不等于业务推进时间。

首叶真实覆盖：正式需求与任务、候选和已有条件缺口、self/manager 快照、self 已公开的学习反馈、消息交互。明确未覆盖：启动期间页面（现有页面在装配后开启）、全量方法枚举、学习队列逐项及学习线程本身状态、候选排除理由、完整因果搜索轨迹、正式业务历史事件源、跨 owner 同时点事务快照。未覆盖项显示“未接入”，不得显示零、空或正常。

## 3. 最小公开接口

唯一新增公开 UI DTO 位于 `海中鱼巣/界面/宿主.网页对话.h`，不依赖业务 owner 头：

```cpp
enum class 网页控制快照状态 : std::uint8_t {
    未接入, 采集中, 已取得, 采集失败, 已停止
};
struct 网页控制快照读取结果 final {
    网页控制快照状态 状态 = 网页控制快照状态::未接入;
    std::shared_ptr<const std::string> UTF8JSON;
    std::uint64_t 序号 = 0;
    std::uint64_t 距采集完成毫秒 = 0;
    bool 正在采集 = false;
};
struct 网页控制面板回调组 final {
    std::function<网页控制快照读取结果()> 读取;
};
```

增加 `<memory>`。结果为不可变 JSON 值副本的共享所有权，不包含 owner 指针、future、锁对象或写端口。序号只是本进程页面采集序号，不是 DATA 代次、业务版本或事实身份。

在现有五参数宿主入口后增加一个六参数重载，前五参数原样，第六为 `const 网页控制面板回调组&`。已有五参数入口转交六参数入口并传空回调，保持旧使用方行为；空回调不使宿主失败，控制面板明确未接入。

在 `装配.普通应用.h/.cpp` 增加：

```cpp
网页控制面板回调组 取得普通应用控制面板回调() noexcept;
```

工厂在宿主运行前只调用一次，按既有治理启停寿命门取得上下文并启动只读采集器，返回只持共享缓存的闭包；HTTP 请求不得每次调用工厂。工厂无法启动采集器应返回明确失败缓存，不得伪装已取得。基础业务不因 UI 采集不可用而改状态。

`启动.应用程序.cpp` 的普通控制面板分支将该工厂结果作为第六参数传入；无窗口模式不启动采集线程。

## 4. 采集与生命周期

采集器为 `装配.普通应用.cpp` 私有实现，唯一所有者为普通应用上下文；没有新代码文件/工程登记。私有缓存结构包含：互斥锁、`shared_ptr<const string>` 最后完整正文、最后状态/序号/完成 steady 时间和采集中标志。采集器持 `std::jthread`、可停止等待的 condition_variable_any 与共享缓存。字段顺序必须保证线程先停止/join 再销毁缓存及其读取的业务对象，不能只依赖成员逆序碰巧成立。

首次进入立即采集，此后每轮完整采集完成后等待 2000ms；同一时刻只有一轮，不重叠堆积。采集仅调用公开 const 读取，禁止调用 `查询任务方法候选并发布`、求值并写回、发布、确认、承接或任何维护接口。采集不得持 `上下文锁`、宿主锁或缓存锁调用 owner。业务服务内部短锁由其自己管理。

采集完成、序列化完成后一次交换共享不可变正文；旧正文由正在发送的 HTTP 读者自然延寿。缓存锁内只读写状态和 shared_ptr，不生成 JSON、不遍历 owner、不等待线程、不进行网络 I/O。各区块独立读取：成功区块发布本轮实际材料；正式读取非成功的区块发布“暂不可用”、原正式状态的原因名称和 `items:null`，不因某区块失败丢弃已取得的 overview 或其它成功区块。这份分区 JSON 仍完整发布，总体 envelope 标“采集失败”；整体不是跨 owner 同时点快照。只有 UI 内存分配/序列化失败、无法形成本轮有效正文时，才整份保留上一轮正文，并以总体失败状态和真实年龄标明旧材料，禁止冒充本轮新成功。

上下文裸指针仅采集线程在 app 存续期间借用。`停止并回收普通应用治理线程()` 在开始请求 self/manager 停止前先停止并 join 采集器；普通应用上下文析构开头再次幂等 stop/join，覆盖初始化失败和其它释放路径。禁止 detach；禁止持 `上下文锁` join。停止信号唤醒 2000ms 等待；已经进入 owner 读取的一轮允许返回后退出，尚不能证明其硬实时停止。关闭宿主后回调不得再触碰上下文；缓存可由闭包延寿，但读到状态为已停止。

`取得普通应用控制面板回调` 与停止/替换上下文使用同一已有治理启停门串行，防止在 teardown 中启动采集。不得同时持启停锁并调用反取启停锁的入口。允许相同存活 app 重复取得同一缓存，禁止建立第二采集线程。

## 5. JSON/HTTP 合同

路由：现有私有令牌 `base` 路径下的 `GET /api/control`。复用原 loopback、私有令牌路径认证、请求方法和空正文检查。只 GET，禁止接受任何业务写请求。返回 `application/json;charset=utf-8`、`Cache-Control:no-store`。

响应 envelope 固定为：

```json
{
  "status":"已取得",
  "sequence":"1",
  "ageMs":"40",
  "collecting":false,
  "stale":false,
  "snapshot":{
    "readStartedAt":"2026-10-27T18:00:00Z",
    "readCompletedAt":"2026-10-27T18:00:01Z",
    "consistency":"分项只读，非跨服务原子快照",
    "overview":{},
    "demands":{"status":"已取得","items":[]},
    "tasks":{"status":"已取得","items":[]},
    "learning":{},
    "timeline":{"status":"未接入","items":[]}
  }
}
```

正文没有快照时 `snapshot:null`，不是 `{}`。状态取：未接入、采集中、已取得、采集失败、已停止。轮询本身 HTTP 200 表示控制端点可达，不等于读取成功；工厂未装配同样可以 200 + 未接入。现有认证/非法请求错误沿原 4xx，宿主网络异常沿既有工程路径。`stale` 为 ageMs 大于 10000ms，只是显示采集新鲜度，不改变业务事实。年龄和 seq 用十进制字符串，避免 JS 丢失 64 位精度。

每个区块 status 只能是已取得、暂不可用、未接入、读取失败。成功区块 `items` 是本轮实际数组，成功空数组只表示“已取得且确实无材料”，不得替代未初始化、资源失败、结构不一致。owner 返回正式非成功时，该区块为 `status:"暂不可用"`、`reason` 为原正式状态名称、`items:null`；其它成功区块照常发布，总体 envelope 状态为“采集失败”。工程异常遵循原正式诊断；仅 UI 序列化/缓存分配等自身异常由本地采集边界记录一次独立工程诊断并置采集失败，不生成业务失败/子需求/学习样本。

页面分区保留各区块最近一次成功的 `items`，只作显示缓存；失败区块已有旧材料时明确显示 `retained:true`、`lastSuccessfulAt` 为该区块上次成功采集时间，并提示“本轮读取暂不可用，显示上次成功材料”。不得将旧项时间改为本轮时间，不能用总体序号冒充区块更新。无旧成功材料时保持 `items:null`、`retained:false`，显示未知/暂不可用，不显示零条；未接入与成功空数组仍分别处理。保留材料不进入世界，不形成业务事件，不改变任务或需求状态。

所有稳定节点身份、计数、int64值均编码为十进制字符串；空引用使用 null。状态枚举有穷分支逐一转名称，未知枚举显示未知并保留诊断，不靠 int 推导状态。

### 5.1 各区域字段与来源

`overview`：self/manager 生命周期名称、各自活动消息数、manager活动工作数/待反馈任务数/调度扫描在途、self停止/完成标志；`serviceValue` 首叶标未接入（禁止以服务目标或初值冒充实际值）；`lastBusinessProgressAt` 未接入；采集完成时间单列。self/manager源分别使用其 `读取快照()`，不 await `最近已消费检查结果`。

`demands.items`：从 `查询全部需求记录()` 的完整需求和待完善需求归一投影，保留 `id,parentId,subject,executionDomain,activity,weight,sourceType,sourceTaskId,complete,target`。target完整时包括 `existence,featureType,form,valueDomain,comparison,direction,referencedDemand,contentPath`；不完整时对缺字段留 null，展示待完善，不凭默认补齐。需求树只放自我执行域；被认知域作为独立只读列表/被引用详情，绝不挂入自我树。parent未在本轮快照中出现时放“本轮未定位父节点”，不改实际父关系；循环只在页面中检测并停止展开，报告结构问题，不删除/重组业务树。

`tasks.items`：一次 `读取任务调度材料()`，每项投影 `id,demandId,state,waitReason,schedulingStatus,lastMethodId,executionId,executionOrganizationId,candidates,conditionReview,execution`。完整零候选保留 `queryComplete:true,candidates:[]`；未有候选材料用 `queryComplete:null,candidates:null`。`conditionReview` 从既有 `条件核验` 取状态、候选已完整核验、方法选择状态、每方法筹办状态与缺口种类/参数位置/来源配对/条件序号，不重新核对条件。不存在条件核验显示尚无材料，不称条件已满足。执行只展示既有 X 状态、正式动作引用、实际状态引用、影响评估引用；方法返回不等于目标满足。

需求和任务按正式 demandId 关联，不从列表顺序、显示名称或任务数量猜父子；子需求关系来源依据 `来源类型`/`复合来源` 显示“复合目标分解”等真实已有字段。未有正式与/或组织字段时显示“关系未接入”，不能把所有树孩子默认成与或或。

`learning`：`threadStatus:{status:"未接入"}`；展示 self 的 `待学习方法数`、最近学习结束及最近学习运行异常的正式字段、manager最近学习结束和等待方法实例消费标志。来源标签写清是 self/manager 快照，不冒充学习线程队列全貌。全量方法/配对知识浏览标未接入，已经出现在任务候选闭包的 M 可展示其现有规格/配对数量（不能冒充全量方法目录）。

`timeline` 首叶未接入正式业务历史，显示明确解释，不插入根据本页两次快照差异猜出的执行/完成事件。允许另设“页面读取记录”显示采集序号/时间，不称业务事件，不持久化至世界。

### 5.2 名称与引用

每个显示引用使用 `{id,label}`；id为真实稳定编码字符串。概念经现行名称关系→词条只读取得全部正式名称并列显示，不取首项冒充首选名称；没有名称显示“特征概念（未命名）”“存在（未命名）”等类别+辅助ID。普通D/T没有正式名称不强造名称；需求摘要由真实目标字段拼接，不建立新的词条或概念。不得以硬编码编码字典、日志文本或首个数组元素猜词义。名称暂不可用不遮蔽原身份和目标字段。UI或名称读取失败只更新显示层独立工程状态，绝不写业务信息或派生需求。

## 6. 页面与交互不阻塞

保留原 messages/outbound 轮询和 send submit 处理、dialogueId及所有现有服务要求DOM ID。控制区拥有独立 `controlRefreshing`、独立超时 AbortController、独立状态元素，每 2000ms 最多一个请求；控制失败不改“本机服务取件异常”、不清输入、不禁用发送、不退出消息循环。fetch超时只取消本页控制请求，不关闭宿主。

布局为桌面总览顶部、左需求任务树、中选中详情、右保留交互/学习；窄屏改纵向，聊天输入始终可达。选择ID本地保持，下一快照对象消失时显示“本次快照未包含”，不选另一个对象冒充原对象。详情只来自同份已发布快照，点击选择不得实时执行筹办。

所有业务文字通过 textContent/createTextNode 插入；不得将消息、名称、原因或JSON字段交 innerHTML。内联固定模板不嵌入业务数据；JSON转义处理引号、反斜线、控制字符及UTF-8输入，body不放私有令牌/内部地址/裸指针。无第三方CDN和远程资源。
