## 1. 目的与边界

本能函数取得服务对象观察材料、主动／被动取得完整已确认服务需求包后，结果必须成为任务虚拟存在的正式材料特征，能够被后继条件、需求复核及治理世界因果使用。

修改的是任务 Vt 的材料 F；现实人类 E、网页窗口与结构化理解／确认只是来源，不被取得动作改变。目的不是生成正式需求或提高服务值，而是使真实返回材料有正式身份和可用内容。一个取得动作对应一次实际读取／组包，task 采用返回时不再登记第二动作。实际需求仍由 self 在收到 manager 消息后建立。

一并闭合两类材料：服务对象观察和已确认需求包。它们共享 task owner、材料域和需求目标 ABI，不拆成先发布字段、以后再找消费者的空提供者。

排除：自由文本理解、服务权限裁决、自动生成确认、方法头首用模拟学习、新建长期条件结果对、跨任务重复统计、完整自动方法编排。不因登记了方法头就声称已可执行。现行方法实例化仍要求已有合法配对；缺配对沿学习链处理，本叶不预造知识。

## 3. 执行任务与成果目标任务分账

父任务 P 的条件要求某材料时，在 P 的 Vt 建立该类材料槽。条件子需求 D 指向 `{P,VtP,材料F}`。D 对应的执行任务 T 调用取得方法，动作来源是 T 的 X，动作目标仍是 P 的材料 F。

允许两种情况：T 就是目标任务；或者 T 的需求是 P 所属需求的**直接子需求**，且由 P 当前合法条件提议确认建立，目标引用与该提议完全一致。两项都由 task 使用需求 owner 的正式父子关系和已有条件提议读回核验。禁止祖先任意跨层写、兄弟写、裸目标编码授权或本能函数自选目标。

父任务槽同一时刻只允许一个活动取得 X。槽锁定在开始执行前、写前最后核验之后建立；另一执行返回现有等待条件，不产生动作。锁为执行状态所派生的占用，不另建业务权限账。动作已发出尚未完成不得释放为可重做；完整结果消费结束后释放。进程恢复遇到不完整执行，沿现有恢复工程路径处理，不重执行现实读取冒充原次结果。

执行前和采用时重复核验完整引用、直接父子来源、当前方法实例、选中配对、X 及材料类型。不通过的正常来源变化回筹办且零动作；已通过后发现结构矛盾为工程终止。

## 4. 物理结构与不可变内容

### 4.1 中立身份和域

新增 `领域/任务材料.域类型.h`，只依赖基础编码及标准库：

```cpp
enum class 新任务材料种类 : std::uint8_t { 服务对象观察 = 1, 已确认服务需求包 = 2 };
struct 新任务材料特征引用 {
    稳定编码 任务节点, 虚拟存在节点, 材料特征节点;
    新任务材料种类 种类;
    friend bool operator==(const 新任务材料特征引用&, const 新任务材料特征引用&) = default;
};
struct 特征概念任务材料域 {
    新任务材料种类 种类;
    std::optional<稳定编码> 定义快照节点;
    std::optional<稳定编码> 实际存在节点;
    std::optional<稳定编码> 来源人类节点, 目标存在节点, 固定语义确认节点;
    friend bool operator==(const 特征概念任务材料域&, const 特征概念任务材料域&) = default;
};
```

服务对象域必须有定义快照，允许具体 E 限定；禁止包专属三字段。包域无定义快照、无实际 E，允许来源 E、目标 E、指定确认固定语义限定。无限定的包域表示任意完整已确认包，不表示空值。两种域禁止互用字段。

`特征概念值域` 追加上述独立 variant 分支，不能作为旧 `vector<稳定编码>` 中一个伪材料。所有其中的节点均为正式强引用。旧枚举节点仍表示准确完整特征值材料。

### 4.2 task 正式持有内容

新增 `领域/任务.取得材料.h/.cpp`；头声明值式 DTO，cpp 实现 `新_任务类` 新增成员，不能建立第二 task owner。task 头包含 DTO 头；DTO 不能反向 include task。

任务材料 FT 分别为“任务取得服务对象材料”和“任务取得服务需求材料”，U64 数组物理值，只允许 `[]` 或 `[材料记录节点]`；比较规则新增具名“任务取得材料内容”，不复用服务任务集合、轮廓或完整材料编码判等。材料槽与任务/Vt/种类一一对应。

正式节点分为：材料槽记录、服务对象内容、概念定义快照、定义项、观察特征项、需求包内容、材料取得来源。每一节点由 `原子建立节点组` 连同全部字段一次发布。内容不可变；不以字段直接值建立独立身份，不增历史版本／墓碑／公共幂等账。

| 记录 | 必需正式字段 | 可选字段与约束 |
|---|---|---|
| 材料槽 | T、Vt、F、种类 | 无；同 T/种类唯一 |
| 定义快照 | EC | 有序定义项引用组；空组为无约束，不补造人类特征 |
| 定义项 | FT、FC、材料类型、比较规则、固定域 | 可选单位；固定域逐字段保存当前内容，不只存可变 FC 编码 |
| 对象内容 | 实际 E、当时专属 EC、人类定义快照、匹配状态 | 完整观察特征项组；匹配时服务对象 E 必须等于实际 E |
| 观察特征项 | F、FT、FC、材料类型、比较规则 | 可选单位、准确 I64 或值材料引用（二选一）、固定实例域；不含命中统计 |
| 需求包内容 | 来源 E、目标 E、目标定义、代表确认引用、四分项引用 | 引用原确认固定语义；不复制可变确认权威 |
| 取得来源 | 执行 T、X、M、动作 A、目标 T/Vt/F、正式内容、结果 S | 对象来源窗口 C/E、公开会话、消息序号或本次包四分项和确认；可选 D |

固定域保存现行 `特征概念值域` 的值式内容，并对其全部引用建立正式字段引用；对于有限完整材料枚举，其正式值材料不可变，可直接持有引用。任务集合/存在引用等域的谓词定义按当前公开字段保存，不以查回当前 FC 重释旧定义。材料域本身不得递归成为对象定义的必需 FT；发现此循环定义属于工程错误。

内容同一排除 X/A、时间、会话、消息序号。对象内容按实际 E、定义快照的逐字段含义、观察项及匹配结果判等；排列按 FT/F 稳定排序，不能以哈希代替完整相等。包内容按来源 E、目标 E、目标定义及原确认 owner 的固定语义比较判等；确认编号不同仍可同义。每次取得来源保存实际使用的分项/确认，不能因复用内容丢失本次来源。

所有保留材料的 S/D、任务或方法对材料建立正式引用。删除 task 若仍被治理场景、来源或因果持有则拒绝；不因退出清理证据。没有本叶自动 GC 或全仓数据迁移。

## 5. 比较合同

在 `概念_特征类.h` 的比较 DTO 后声明 `特征任务材料读取接口`，task 实现；FC 只持非拥有借用，装配一次、锁外调用。签名：

```cpp
virtual 特征概念规则状态 验证任务材料域(const 特征概念任务材料域&) const noexcept = 0;
virtual 特征概念值域比较结果 比较任务材料域(
    const 特征概念任务材料域&, const 特征概念任务材料域&) const noexcept = 0;
virtual 特征概念值域比较结果 比较任务材料准确值与域(
    稳定编码 特征值材料节点, const 特征概念任务材料域&) const noexcept = 0;
virtual 特征概念值域比较结果 比较任务材料准确值(
    稳定编码 左特征值材料节点, 稳定编码 右特征值材料节点) const noexcept = 0;
```

沿用当前五关系和 int64 比较载荷，不返回浮点、业务 bool 或新的否定编码。provider 工程故障终止，不作为分离。

比较准确值：先读 U64，0 项表示未取得，1 项读完整正式内容，多项或失效引用工程终止。两个空准确值相等；空与非空分离。非空内容同义相等，否则分离。准确值与域匹配返回右包含左，否则分离。

对象域比较按捕获定义的所有必需 FT 约束逐项比较；少约束域包含多约束域；共同 FT 域全部相等／包含才能相等／包含；任何共同 FT 分离则域分离；其余为相交。具体 E 不同则分离，未限定 E 包含限定 E。多个独立 FT 的约束合取；单位、材料类型、比较规则冲突为域不合法，不伪装分离。定义 EC 身份本身不是额外历史归属判据。

包域比较按来源、目标、固定确认语义三个外层约束分别合取。未限定包含限定；两个指定身份不同分离；两个指定确认只有原 owner 固定语义相同才相等，否则分离。**包内需求目标值域包含不推出包内容同义。** 不按当前已出现包全集近似域包含。

精确有限枚举与材料域交叉比较逐项调用准确值匹配；精确枚举之间按内容消重后计算集合关系。`全材料域` 仍包含空值，不能替代“已取得”。FC 构造、读回、包含、交集关系、删除引用检查均识别新 variant；F 统一比较的三来源都转入同一能力。

历史内容比较只依固定快照，不调用“当前确认有效”改变过去含义。筹办与执行另作 fresh 校验：对象定义和当前来源与取得材料是否仍一致；包确认是否需重新确认。合法漂移为待补齐，不删除旧内容、不改写旧因果。

## 7. 生产方法与筹办接线

取得对象和主／被动取得需求均登记为内部治理方法，方法头涉及对应材料 FT，可能结果引用对应材料域 FC，作用存在为 task 的 Vt 类型。Vm 参数声明含唯一材料成果目标角色；旧窗口/五分项输入角色保留，不把声明当事实配对。

筹办定位的目标来自正式需求及父条件，不通过登记名选择业务成果。在已有合法条件结果对中，任务按结果材料 FT/域匹配当前目标；目标材料角色绑定完整引用。条件材料角色若无槽，由 task 为当前 T 准备；用统一值域比较核验，缺少则 `提议任务条件子需求()` 输出该 T 槽。self 按既有提议复核建 D，manager 承接 Tchild。不能由本能自己加子需求。

同步扩展：`选择任务方法结果()`、`筹办任务条件和参数()`、`核验任务条件和参数()`、`提议任务条件子需求()`、`复核条件子需求就绪()`、`承接已确认条件子需求()`、`核验任务执行方向()`、`确认任务进入待执行()` 和 `核验执行本能动作()`。材料域不参与 I64 线性反求；使用内容域包含/交集和当前值满足判断。值目标相交可选但临执行必须绑定满足目标的真实输入，不把未知包视为已满足。

执行前结果渠道为 task 材料读回，不是网页观察。`新任务结果获取目标`（及其持久化）追加材料强引用；作用对象和实际 F 从引用解析，只允许 task owner 渠道，与普通现实感知渠道互斥。动作前读取正式空/现值及 S，预测数据保存当前选中材料域，不经 I64 差值。

`服务需求本能运行服务::核验执行()` 以 `读取本次执行实例(场景)` 获取 X、task 读取 T/M/目标，替代必须由服务专用 `执行()` 建立的私有 map 门。保留专用入口仅为同一守卫包装，不能形成第二执行通道。服务对象运行服务同样验证材料目标。

## 8. 捕获、唯一动作与正式结果

执行顺序：条件 fresh 复核 → 冻结本次 X/材料目标 → 治理世界登记唯一取得动作 → 实际读取/组包 → task 采用内容 → 正式结果读回 → 结果获取/影响评估 → self 决议。

对象读取：捕获 E 与所列 F 以及人类必需 EC/FC 定义的值式投影；以这组材料逐 FT 用 F 统一直接域比较得到匹配/不符合/材料不足，不再调用会重新读取的 `匹配存在概念(E,EC)` 作为这组快照结果。前后重读 E/F/EC/FC 投影完全相同才返回这一组；合法并发变化不发布混合材料，结束此次获取为既有等待材料，不谎称匹配。这里只保证读前后稳定校验，不承诺跨 owner 原子快照。工程读取失败终止。

包在动作前核验五角色同一理解、来源/目标/FT/目标定义与当前确认一致；动作后按同一绑定组读取并再次核验。确认需重做是正常条件变化，保留动作但不造完整包；不能把工程故障称为信息不完整。

task 采用时核验动作的来源 X/M、执行主体 self、独立治理 C、材料目标完整引用、当前合法执行及返回种类。原子建立完整内容和来源的非结果部分；更新 F 由唯一 F owner 完成；建立 S 后完整发布最终来源记录，不把缺结果的来源记录暴露为成功。若同内容，不更新 F、不重复建立 S/D。无变化取得须使用独立的 task 当前读回渠道，不能为了 manager 当前只接受动作后 S 而伪造新状态；该渠道的公开 DTO 与完成消费尚待后继冻结，不能按本稿施工。

发生变化时由治理 world 关联材料前后 S、原子 D、唯一取得动作。不为同义重读人为增加变化因果次数。同 X 精确重放返回已完成来源/S/D，不再读现实；同 X 不同目标或内容属于工程错误。材料内容比较只有离散相等/不同，不能衍生大小、速度、单位时间变化量；后继必须同步冻结动态及动态概念对此比较规则的支持。

## 9. 内部治理世界与因果扩展

在中立协作接口追加：

```cpp
struct 新治理材料动作请求 {
    新任务材料特征引用 目标;
    稳定编码 执行任务节点, 执行实例节点, 执行主体节点;
    稳定编码 方法节点, 现实来源场景节点, 前状态节点;
    新状态强时间 动作时间;
};
struct 新治理材料结果 {
    稳定编码 治理场景节点, 动作节点, 前状态节点, 后状态节点;
    std::optional<稳定编码> 变化动态节点;
};
virtual 新治理动作登记结果 建立任务材料动作(const 新治理材料动作请求&) noexcept = 0;
virtual 新治理材料结果 完成任务材料取得(稳定编码 A, 稳定编码 前S, 稳定编码 后S) noexcept = 0;
```

动作以 X 为来源，方法 M 为动作定义；不要求虚构一个先发生的普通动作。旧状态结算仍使用真实普通来源动作，二者分支严格区分。

`新治理场景参与者` 追加材料引用组；同一 T/Vt 的状态 F 与两个材料 F 可以同时组织，参与者身份仍 T/Vt，不为每个 F 建第二 Vt。场景记录每一 F 的强引用，`属于内部治理组织()` 纳入材料 F、其 S/D 和动作。旧 `任务引用` 保留状态语义。

动作 DTO、持久字段、`新因果动作定义`、反查参与者/键/未绑定对象均追加 `optional<新任务材料特征引用>`，与旧状态目标及普通 E 互斥。排序、memo、环键和漂移重读保留完整类别和 T/Vt/F/种类。概念角色仍指治理任务 Vt，不把材料种类当现实 EC。

world 先核验 task 投影，在治理根组织前 S、自我引用和目标，再登记动作。结果完成后组织后 S、可选 D；有 D 时一次 `处理动作事实()` 交付，发生身份为唯一 A。没有 D 只保存真实观察动作/S，不作为新的材料变化发生。沿已发布同 C/同类 B 窗口规则取前提，不跨 Vt 拼次数。第一例可无 Q，重复交付不增次数。

概念抽象及反查统一通过 F/FC 语义域比较，不按材料节点 ID 判同义。结果材料的因果仍是参考，不自动授权执行；无后继配对或真实输入时返回未覆盖端点。

## 10. manager 正式结果消费与闭包

task 在 `执行任务本能方法()` 调用完成后检查两类返回字段（至多一个），调用采用入口。**采用后正式 S/D 必须在独立强类型采用结果中交付 manager，不可写回本能原始条件结果对冒充函数直接输出。**先核验来源，再交现有 `记录本能动作身份()` 和 `记录方法动作输出()`；这两个入口增加材料目标分支，不能继续普通 E 硬门。无变化结果渠道与该独立交付 DTO 尚待后继冻结。

`核验任务结果材料()` 核验 X 结果目标中的完整引用、正式 S 的被描述 Vt/F/FT、时间及动作关联；`查找任务结果材料()` 从治理世界组织读取而非现实世界查询；`获取任务本能结果()` 和 `评估方法执行影响()` 用材料域比较真实后 S。值目标按当前值满足，方向目标不适用于本叶两个材料 FT，不能计算单位时间变化量。

manager 保持通用 `获取本能结果` 工作：独立读回返回 S → 核验足够 → 派结果工作 → 影响评估后发 self。不得因包非空直接完成任务。`提交结果状态通知()` 触发既有条件子需求复核，使父任务重新读自己的材料槽；父任务不因子任务已完成自动认定所有条件成立。

此链获得的完整需求包仍由已有 manager→self 材料消息交付；若当前消息尚无该字段，追加正式材料记录编码及来源 X/A/S，而非重新传自由文本。self 通过 task 只读内容及确认 owner fresh 复核，沿现有正式服务要求采用入口生成/复用真实需求；本能不建立需求。重复包不重复建立需求，个人可信等级不在本叶实现。

## 11. 装配、并发及故障

普通应用在 task、共享 owner、结构化服务要求和内部治理世界就绪后，初始化两个材料 FT/域及明确角色概念，装配 FC 材料读取接口和需求治理读取接口，再持有两种运行服务。原服务对象配置追加材料 FT/FC/目标角色；服务需求配置追加对应材料 FT/FC/目标角色。初始域来自已发布人类定义快照和任意完整包，均无虚构取得实例。

生产 task 建参数场景时同时传已有结构化读取接口；目前只传 `this` 的调用须修正。同指针重复装配可复用，异指针拒绝。停止顺序：禁止新工作并等待活动执行/回调 → 关闭本能端口 → 解除 FC/需求借用 → 销毁运行服务、治理 world、task 和事实 owner。不得运行期替换。

所有跨 owner 比较先取得值式投影，锁外回调，回写前核验本地归属。特别禁止 task 持材料写锁→FC→task；材料内容比较在锁外完成，再锁内验证候选内容仍正式可读。正式节点不可变且被强引用保证寿命，不新造全局事务锁。

不承诺 task/F/S/D/scene/Q 整链原子。每个对象完整原子发布，按动作→F→S/D→组织→关联→来源完整记录→结果交付顺序完成。工程故障日志、弹窗后终止，保留事实；不返回 false、空包、业务失败或学习结论。合法条件变化零动作或保留已发生动作但无完成，不盲重试。
