# 所有者一致投影零守卫原子最新读取详细设计 v0.1

日期：2026-08-14

设计身份：`L1-OWNER-CURRENT-SNAPSHOT-LATEST-READ`

状态：设计就绪；不等于代码已实现

## 1. 目标与原因

扩展既有 `L1所有者范围一致当前读取请求` 的零守卫语义：`期望事实代次=0` 表示由 L1 仓库在取得本次共享锁后原子选择当前事实代次，并在同一锁域完成 owner、节点、关系、值、属性值及源 / 目标关系组投影。

当前实现于 `仓库.L1事实基座.ixx` 入口直接拒绝零守卫。C1 若先调用 `读取中性当前事实代次` 再发起非零一致投影，两次调用之间可发生任意 owner 发布，不能保证 4240 v0.4 的全组零请求成功语义。该缺口命名为 `DRIFT-C1-L1-ZERO-LATEST-ATOMICITY`。

本叶只补 L1 业务中性读取能力，不建立概念、owner、缓存、重试器或第二读取入口。

## 2. ABI 与结果形状

不新增或删除公开 DTO、函数、枚举、字段和模块。现有函数保持：

```cpp
L1所有者范围一致当前读取结果
L1事实基座服务::尝试读取所有者范围一致当前投影(
    const L1所有者范围一致当前读取请求&) const;
```

请求合同：

- 合同版本错误、七组选择全部为空或选择项非法仍入口拒绝；
- 非零期望代次仍是严格乐观守卫；
- 零期望代次为“锁内选择当前”，不是非法请求。

成功结果：

- `期望事实代次` 逐字回显请求值；零模式仍为 0；
- `读取事实代次` 等于取得共享锁后读取的唯一当前事实代次；
- 全部项目来自同一仓库状态和同一读取代次；
- 各项目继续独立返回成功、未找到、已退出、属性未设置或种类不匹配；空库代次可以为 0，L2 需要非零截止时由自身合同拒绝。

非零守卫不匹配仍返回 `事实代次漂移`、零项目载荷，并以 `读取事实代次` 回显当前代次。零模式不产生事实代次漂移；共享锁未取得仍许可拒绝，资源失败和内部不一致保持原状态。

## 3. 唯一代码改动

只修改 `海中鱼巣/核心/仓库.L1事实基座.ixx` 的 owner 一致投影函数：

```text
入口校验不再拒绝期望代次 0
-> try_lock 取得共享锁
-> 选择代次 = 请求为 0 ? 状态当前事实代次 : 请求期望代次
-> 非零请求且状态代次不等于守卫：事实代次漂移
-> 形成结果；结果.期望事实代次原样回显，结果.读取事实代次=状态当前代次
-> 在同一共享锁内完成全部选择项投影
```

不得先解锁后读取代次、不得调用公开 `读取中性当前事实代次`、不得循环重试、sleep、yield、缓存所选代次或改变锁种类。`服务.L1事实基座.ixx` 继续透明转发，无需修改。

## 4. 兼容与风险

所有现行生产调用均显式传入非零守卫；其成功、漂移、锁竞争和结果形状逐字不变。唯一行为变化是过去被入口拒绝的合法零守卫现在取得原子当前投影。调用方不能用零模式实施写入或绕过 owner，因为请求仍只有读取选择项且仓库只持共享锁。

本能力是业务中性 L1 服务，可供未来需要“调用时当前快照”的 L2—L5 读取复用；它不允许普通业务绕过具名 L2 服务直达 L1。

## 5. 验证

临时专项 `验证工具/L1所有者一致当前零守卫参数验证.{cpp,vcxproj,vcxproj.filters}` 只经正式运行包、签发器、owner 写端口和公开读取入口验证：

1. 空库零守卫对一个未找到节点成功，读取代次 0、期望回显 0、项目未找到；
2. 建立 owner / 节点后零守卫成功，读取代次等于调用时当前非零代次；
3. owner、节点、属性值、源 / 目标关系组在零模式共享同一截止；
4. 非零同代成功、非零陈旧漂移及零项目载荷保持原行为；
5. 错合同、全空选择、重复 / 零选择项仍入口拒绝；
6. 并发发布和零守卫读取循环中，每个成功结果内部同代、无混代；许可拒绝可以出现，零模式不得返回事实代次漂移；
7. 现有代表性六类服务根工程 Debug / Release fresh Rebuild 不回归。

生产代码不得增加验证 seam。无法稳定注入的 `bad_alloc`、内部状态损坏和共享锁饥饿分别 `NOT_RUN`。
