# TASK-CAUSAL-PREPARATION：因果动作触发方式提供者详细设计

日期：2026-10-17。版本：v0.1。范围：最早提供者代码叶；取代同名未发布的 W1/W2 查询等待草案。当前能力以代码为准。

## 1. 目标与依据

依据：[1190 v2.3](../1190_根规范_因果_20260720.md)、[4320 v1.2](../4320_子规范_因果链组织与应用.md)、[5260 v1.6](../5260_子规范_任务治理详细合同.md)。起点为 `a55b175101f315467d7eb396c8955963d84cf3c8`，1190 v2.3随本设计发布；代码基线为 `afe1fba86b7d9bb356b0b0bca6791db6c6a34606`，期间仅规范变化。本叶不实现预置规则初始化，不依赖尚待裁决的关系／事件条件与结构结果表达。

总目标是任务从所需结果反查方法或前置条件，不是仅查询后等待。本叶先闭合其缺失提供者：实际动作提供三态分类，因果写入、读取、共同抽象和反向查询完整传递，且将事实解释覆盖与筹办去向分账。暂不改任务、线程或装配，不宣称任务已经消费因果。

本叶不直接修改任务或现实存在特征值；只依据已有事实维护因果知识及只读投影。既有治理动作确实修改任务 Vt 状态，以记录服务结算结果；本叶不另执行该动作，不生成方法或假事实。

## 2. 类型与持久字段

在 `海中鱼巣/领域/新_因果公共类型.h` 定义：

```cpp
enum class 新因果动作触发方式 : std::int64_t {
    尚未确定 = 0, 主动调用 = 1, 被动触发 = 2
};
```

在 `新因果动作定义`、`新因果概念动作项` 的现有数据字段末尾各追加：

```cpp
新因果动作触发方式 触发方式 = 新因果动作触发方式::尚未确定;
```

既有字段顺序和聚合初始化实参含义不变。所有手动构造、投影、比较和来源重验均保留该值；默认相等比较自然包含新字段。已知/未知仍使用原 `新因果类型`，未知动作没有动作对象。

在 `海中鱼巣/领域/新_因果类.cpp` 的匿名命名空间增加唯一 schema 编码 `稳定编码 动作触发方式字段{}`，在 `架构编码组()` **末尾**追加并沿现行初始化、完整性核验、清理机制管理；不新建根，不改变其它编码位置。增加同文件内部纯函数 `bool 动作触发方式有效(新因果动作触发方式) noexcept`，只接受三种枚举值。

| 通路 | 冻结合同 |
| --- | --- |
| `动作定义有效` | 新枚举必须合法；不得按方法引用有无推导分类 |
| `写动作定义` / `读动作定义` | 具体因果动作子节点保存一个 I64 标量；新写显式保存 0/1/2；旧节点没有字段读为尚未确定 |
| `对齐来源` / 结构等价 / 共同抽象 | 复制触发方式；不同触发方式不能共同抽象，沿现有无结构共性结果返回，不统一降为尚未确定 |
| `发布概念` / `读取概念定义` | 概念因果节点有动作时保存同一个标量字段，无动作时不保存；保持既有概念形状数组布局；旧有动作无字段为尚未确定 |
| 既有来源重验、重复判定、形成分组 | 比较含触发方式的完整动作；来源分类实质改变时沿现行不相容/漂移处理，不静默复用旧投影 |

字段重复、错类型、越界，以及无动作却存有触发方式，均属于结构工程故障，沿现有因果工程保护路径处理；不能读成尚未确定或正常否定。继续使用现有事务、失败逆序清理、读回核验与锁；不引入历史重写、版本、迁移回填或计数变化。

## 3. 真实治理提供者

仅扩展 `海中鱼巣/业务/内部治理.世界.cpp` 中现有 `新_内部治理世界类::读取自我动作事实(稳定编码) const noexcept`，不改变签名和动态 ABI。

保留现有场景成员、动态种类、概念、强类型任务 Vt、执行主体与治理参与者检查。只有以下材料全部读回一致，才将当前返回动作的 `触发方式` 设为 `被动触发`：

1. 正式治理动作定义等于 `任务读取_->获取任务已结算动作定义()`。
2. 动作有合法来源普通动作和动作时间；经动态 owner 读取来源，确为动作、目标种类为普通存在、来源任务等于治理目标的任务节点、执行主体相同、普通动作时间严格早于治理动作。
3. 用已有只读 `读取任务状态变化(目标Vt, 来源普通动作)` 复核完整关联，其返回动作节点就是本次节点；其现有检查覆盖唯一来源、治理场景、两端同一 Vt 状态特征、已完成(9)到已结算(12)以及动作结果关联。该调用发生在完成关联后，不等待未来结果，不递归发布事实。

非本场景/非动作继续遵循原空返回合同；其它合法但不在本叶已确认路径内的动作保留尚未确定。已登记且声称属于本路径的材料损坏，进入现行工程异常终止，不伪装无匹配。

分类依据是唯一 owner 的已知真实收尾路径：`服务值结算.本能运行服务.cpp::确认并收尾` 先核验真实服务值结果，再调用任务 owner 标记已结算。**已结算状态就是已有结果，不新增重复确认特征，也不把已结算反用为产生已结算的前提。**

现有 `交付实际发生` 尚未把来源普通结算动作及其结果核验关系完整表达为治理因果前提。因此本叶的被动分类不等于完整触发条件已表达，不能推出“已完成自动导致已结算”。不修改该发生材料采集，也不创造跨世界桥接；后续消费者设计复用已有执行实例 X、影响评估 A、动作及结果关系补齐真实关联。

## 4. 反向查询投影与分账

在 `海中鱼巣/业务/因果.反向查询服务.h` 增加调用期枚举：

```cpp
    动作未知 = 1,
    动作触发方式尚未确定,
    追溯方法及条件,
    追溯被动触发条件
};
```

在既有 `反向因果图分支` 的数据字段末尾追加：

```cpp

std::optional<新因果动作触发方式> 动作触发方式;
反向因果筹办去向 筹办去向 = 反向因果筹办去向::动作未知;
```

在对应 `.cpp` 的具体/概念规则读取、内部规则值式投影、图分支构造及 fresh 比较中传递类型和触发方式。每个分支按下表生成一个去向，不持久化，不改查询入口：

| 规则材料 | 分支触发方式 | 本叶筹办去向 |
| --- | --- | --- |
| 未知动作 | 空 | 动作未知 |
| 已知动作、尚未确定 | 尚未确定 | 动作触发方式尚未确定 |
| 已知动作、主动调用 | 主动调用 | 追溯方法及条件 |
| 已知动作、被动触发 | 被动触发 | 追溯被动触发条件 |

后两项只指示下一步追溯方向，不声明方法可执行、完整触发前提已表达或本次机制已触发。原未知/未绑定等边界保留。保留方法引用等原证据，不能把本叶缺消费者的事实变成所有被动因果均不完整的分类。第3节具名来源的实际触发关联缺口由后续消费者按正式材料核验。

**原有事实图完全保留**：AND/OR、动作前提、角色绑定、环边、`起点已覆盖`、`完整覆盖` 和 `覆盖` 固定点算法均不变。新筹办去向不参与旧覆盖计算；不能为了阻止未来误用而降低事实覆盖，也不能因为动作被动而删除事实图中的动作节点。原治理世界 `查询因果链` 自动传递新增投影，无新装配、无任务消费旁路。

## 5. 完成边界与后继

本叶完成条件：三态从真实提供者进入新发生，随具体因果和概念因果完整保存/读回/比较；旧缺字段保持未确定；反查同时提供原事实覆盖及独立筹办去向；实际项目编译链接通过。

本叶不证明运行、旧库恢复或业务闭环。后续原目标仍须在任务筹办中反查所需条件、按主动方法/被动完整前提继续递归，并由自我确认正式子需求；这不是本叶的等待骨架，也不在本叶预登记未冻结消费者计划。真实触发关联须复用已存在材料，不新增冗余已确认标志。
