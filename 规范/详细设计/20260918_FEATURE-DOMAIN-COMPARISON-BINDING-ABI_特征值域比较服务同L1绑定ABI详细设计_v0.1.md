# 特征值域比较服务同 L1 绑定 ABI 详细设计

身份：`FEATURE-DOMAIN-COMPARISON-BINDING-ABI`

版本：v0.1

日期：2026-09-18

状态：可执行

## 1. 目标与完成条件

为已发布的、只读的 `特征值域比较数据服务` 增加一个调用期同底座核验：

```cpp
bool 绑定于(const L1事实基座服务&) const noexcept;
```

当且仅当该服务已保存的 `概念树类数据服务`、`特征类数据服务`、`特征值类数据服务` 三个引用都绑定传入的同一个 `L1事实基座服务` 时，返回 `true`；其它任何组合返回 `false`。

完成条件是：声明和定义位于既有比较服务模块；实现只组合三项既有 `绑定于` 谓词；不新增字段、构造参数、DTO、状态、端口或机器事实；同底座、三种单项混用和两项以上混用均由可复跑专项验证；主工程 Debug/Release x64 构建到该翻译单元。

该能力只证明比较服务与调用方能在调用期确认底座一致。它不读取值域、不改变 4180 比较结果、不确认 `Gread/H`、不建立概念定义，也不证明存在概念形成、恢复、运行或业务验收。

## 2. 依据与当前事实

- 4180 v0.13 §5.2：特征值域比较服务是唯一只读组合 owner；只组合概念、特征类型和值的已发布读取能力，零机器事实写入。
- `EXISTENCE-CONCEPT-DEFINITION-PROVIDER-REBUILD` v0.6 及其详细设计 §1、§9：其五个两组定义入口必须先调用此谓词；同截止 `Gread/H` 不足以证明概念 owner 与比较服务属于同一 L1。
- 当前 `数据服务.特征值域比较类.h/.cpp` 的构造器已保存上述三项 `const` 服务引用；三项被引用服务分别已有 `绑定于(const L1事实基座服务&) const noexcept`，其中特征服务还会核验其内部端口和值服务。

当前比较服务没有公开绑定谓词；其私有引用不能由下游读取。公开读取入口当前没有生产调用点，故本计划不修改任何消费者或装配顺序。该空白是上游 ABI 缺口，不是用读取回执、指针转型或临时缓存替代的许可。

## 3. 物理位置、唯一所有者与接口合同

唯一领域 owner 为既有 `特征值域比较数据服务`，物理位置固定为：

| 位置 | 变更 |
| --- | --- |
| `海中鱼巣/领域/数据服务.特征值域比较类.h` | 在三个既有只读公开读取/核验入口之前或之后声明上述 `const noexcept` 谓词。 |
| `海中鱼巣/领域/数据服务.特征值域比较类.cpp` | 给出唯一非 inline 定义。 |

实现精确为：

```text
return concepts_.绑定于(l1)
    && features_.绑定于(l1)
    && values_.绑定于(l1);
```

短路求值不改变语义；三项均为既有 `noexcept` 的身份/内部绑定核验。函数不得捕获并吞没异常以伪造 `true`，也不得读取 L1、构造服务、调用值域读取、申请端口、提交写集或修改成员。传入引用本身总是有效 C++ 对象，故没有 DTO、状态码、预算、失败载荷、`Gread/H` 或写后读回分支。

该 ABI 是数据服务内部的一次只读一致性判断，处于 `DATA-L2` 比较服务模块；其 L1 参数只用于判断既有服务的共同事实基座，不将比较服务降为 `DATA-L1`，也不改变 4180 的值域语义。

## 4. 使用与依赖方向

```text
概念树/特征/特征值 --各自已存在的绑定谓词--> 比较服务.绑定于(L1)
概念树两组定义未来调用期参数 -----------------------> 比较服务.绑定于(L1)
```

比较服务继续构造期单向依赖概念树、特征和特征值；概念树不保存、构造或注入比较服务。后继只在调用期短暂传入 `const 特征值域比较数据服务&`，先以概念树自己的 `l1_` 调用本 ABI；返回 false 时由后继映射其既定的 `入口拒绝` 与零载荷。本计划不实现该后继映射。

## 5. 施工步骤与范围

1. S0 核对 `main == origin/main`、index、目标两文件的实际 WIP、计划索引和无冲突构建活动；保护无关 WIP。
2. 在头文件声明唯一 `const noexcept` 公共谓词；不得移动构造器、改变私有三引用或变更既有读取 ABI。
3. 在 `.cpp` 以三项既有 `绑定于` 的逻辑与给出定义；不得把实现内联到头文件，避免不必要的消费者重编译表面积。
4. 在 `D:\TEMP\海中鱼巣\FEATURE-DOMAIN-COMPARISON-BINDING-ABI\` 生成仅验证用的隔离驱动与工程副本。驱动只为建立真实服务夹具而把 `装配.普通应用.cpp` 作为同一翻译单元的实现输入；原工程中该 `.cpp` 不与驱动重复编译。它以两个不同的受控持久根建立实际 A、B L1 上下文，构造比较服务并断言：
   - `{概念A, 特征A, 特征值A}` 对 A 为 true、对 B 为 false；
   - `{概念A, 特征B, 特征值A}` 对 A/B 均为 false；
   - `{概念A, 特征A, 特征值B}` 对 A/B 均为 false；
   - 调用前后 A、B 的当前事实代次均相同，证明调用本身零事实写入。
   驱动使用当前项目相同的源码清单，排除重复的 `main.cpp`、`装配.普通应用.cpp` 与比较服务 `.cpp`，由驱动各自提供；不得将测试入口、访问器或测试宏写入生产源码。
5. 以 `/m:1` 运行主工程 Debug/Release x64 构建，避免共享 PDB 争用；写本计划专属施工/验证记录。只有本模块 `.cpp` 已经工程登记才不得改工程，当前事实显示它已登记。

允许生产文件严格限于上述 `.h/.cpp`；允许本计划专属 `施工记录/FEATURE-DOMAIN-COMPARISON-BINDING-ABI_施工记录_v0.1.md`、`验证记录/FEATURE-DOMAIN-COMPARISON-BINDING-ABI_验证记录_v0.1.md` 和仓外隔离验证材料。禁止改 L1、概念树、特征、特征值、普通应用生产装配、工程登记、正式规范、规则、IF/R、世界树、线程和无关计划。

## 6. 非成功、验证与完成边界

此函数没有内部可报告失败：任何一个被引用服务对参数 L1 的既有绑定核验失败即返回 false；没有例外路径可转换为成功。构造时已接受的服务组合保持不变，故混用组合允许被构造但绝不能返回 true。无写入，因此无幂等、发布未知、撤销、恢复或读回成功分支。

验证至少包括：

1. `git diff --check`；
2. `python .\tools\check_specs.py --strict`；
3. 隔离驱动的 Debug/Release 编译、运行、退出码 0 与四组断言输出；
4. 主工程：
   ```powershell
   msbuild .\海中鱼巣.vcxproj /t:Build /p:Configuration=Debug /p:Platform=x64 /m:1 /v:minimal
   msbuild .\海中鱼巣.vcxproj /t:Build /p:Configuration=Release /p:Platform=x64 /m:1 /v:minimal
   ```
5. 静态巡检：精确一个公开声明、精确一个定义；函数体无 L1 读取、写端口、写集或比较入口调用。

若主工程先被本计划范围外错误阻断，记录首个错误和已完成的独立驱动结果，不能把阻断称为构建通过，也不得修改异主生产文件。计划完成只发布上述 ABI 和证据；其下游 `EXISTENCE-CONCEPT-DEFINITION-PROVIDER-REBUILD` 须以本计划精确提交重新 S0 后才可从待激活恢复为可执行。
