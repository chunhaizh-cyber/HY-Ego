# L1-SIMPLIFY-P2-FEATURE-DEFINITION 抽象特征定义登记详细设计 v0.1

## 1. 目标与边界

本叶是世界结构迁移后的首个特征领域迁移叶，只建立一个可由运行期长期持有、通过新 L1 三类事实基座发布和读取 **I64 区间抽象特征定义** 的领域服务。它证明 1120/4110 的“定义身份 + 值域”可以在不泄漏 L1 写机制的前提下成立。

不建立实例特征槽、当前值、关系22、特征批次、比较算法、旧特征体系兼容入口、持久恢复或旧实现删除。上述内容必须由后继独立叶处理。

正式依据：4015 v0.3、4030 v1.1、1120 v0.2、1130 v0.3、4110 v0.7、CODE-FILE-01 v2.4，以及正式结果 `ed1f09b7` 的 L1 公共/完整合同与仓库隔离接口。

## 2. 当前事实与复用裁决

- `L1事实基座服务` 已提供版本化提交、节点/值/属性/快照读取；服务只公开合同，不传播仓库。
- `运行期上下文` 已长期拥有唯一 `L1事实基座服务`。
- 旧 `服务.特征` / `数据操作.特征体系` 仍消费旧句柄、关系22和旧事务，不可原位复用为本叶实现；本叶不修改它们。
- `世界操作幂等身份` 只属于世界领域，不能复用为特征公开合同；新建 `特征操作幂等身份`。
- 新服务直接拥有特征定义领域事实，私有调用 L1；普通消费者不得直接取得 L1 请求、写集、仓库、锁或候选。

## 4. 公开合同

### 4.1 类型

```cpp
inline constexpr std::uint32_t L1特征定义合同版本 = 1;
inline constexpr std::uint32_t L1特征定义规则版本 = 1;

struct 特征操作幂等身份 final { std::uint64_t 值 = 0; };

struct 特征定义登记 final {
    std::uint32_t 合同版本;
    std::uint32_t 规则版本;
    std::uint64_t 事实截止代次;
    稳定编码 服务身份;
    稳定编码 定义标记属性类型;
    稳定编码 I64下界属性类型;
    稳定编码 I64上界属性类型;
};

struct I64特征定义事实 final {
    std::uint32_t 合同版本;
    std::uint32_t 规则版本;
    std::uint64_t 事实截止代次;
    稳定编码 特征定义;
    std::int64_t 下界;
    std::int64_t 上界;
    稳定编码 来源服务;
};
```

`特征操作幂等身份` 合法值域为 `1..0x00FF'FFFF'FFFF'FFFF`。它是 L2 操作身份，不是 L1 写集键。服务私有映射域固定：登记 `0x03`，定义创建 `0x04`；不得与世界领域 `0x01/0x02` 复用。

请求和结果：

```cpp
struct 特征定义登记请求 final {
    std::uint32_t 合同版本 = L1特征定义合同版本;
    std::uint32_t 规则版本 = L1特征定义规则版本;
    特征操作幂等身份 幂等身份;
    std::uint64_t 期望事实代次 = 0;
};

struct I64特征定义建立请求 final {
    std::uint32_t 合同版本 = L1特征定义合同版本;
    std::uint32_t 规则版本 = L1特征定义规则版本;
    特征操作幂等身份 幂等身份;
    std::uint64_t 期望事实代次 = 0;
    std::int64_t 下界 = 0;
    std::int64_t 上界 = 0;
};

struct I64特征定义读取请求 final {
    std::uint32_t 合同版本 = L1特征定义合同版本;
    std::uint32_t 规则版本 = L1特征定义规则版本;
    稳定编码 特征定义;
    稳定编码 定义标记值;
    稳定编码 下界值;
    稳定编码 上界值;
};

enum class 特征定义状态 : std::uint8_t {
    已提交 = 1, 幂等读回 = 2, 已读取 = 3, 未找到 = 4,
    登记未加载 = 5, 入口拒绝 = 6, 幂等冲突 = 7,
    事实代次漂移 = 8, 资源失败 = 9, 内部不一致 = 10
};

struct 特征定义登记结果 final {
    特征定义状态 状态 = 特征定义状态::入口拒绝;
    std::optional<特征定义登记> 登记;
};

struct I64特征定义结果 final {
    特征定义状态 状态 = 特征定义状态::入口拒绝;
    std::optional<I64特征定义事实> 事实;
    稳定编码 定义标记值;
    稳定编码 下界值;
    稳定编码 上界值;
};
```

非成功结果的 `事实` 为空；三个值编码仅在 `已提交/幂等读回/已读取` 时非零。公开 DTO 对 `写集幂等键、写集本地键、L1写集请求、L1事实基座仓库、候选、锁` 必须零命中。

### 4.2 服务函数和物理位置

唯一生产类：

```cpp
class L1特征定义服务 final {
public:
    explicit L1特征定义服务(L1事实基座服务& L1) noexcept;
    特征定义登记结果 建立登记(const 特征定义登记请求& 请求);
    特征定义登记结果 读取当前登记() const;
    I64特征定义结果 建立I64特征定义(const I64特征定义建立请求& 请求);
    I64特征定义结果 读取I64特征定义(const I64特征定义读取请求& 请求) const;
};
```

四函数均在 `服务.L1特征定义.ixx` 的类定义中声明和定义，为公开同步成员函数。构造函数诊断责任为“无适用错误分支”；其余四函数的合法非成功向上送出，`bad_alloc` 映射资源失败，未知异常映射内部不一致；服务是本叶最终责任边界，但本叶不新增文本日志或事件日志。成功与合法拒绝不记录错误。

允许调用方：运行期上下文、后继特征领域服务、专项自检。禁止普通调用方、组合服务和旧特征数据操作取得私有 L1 或写入口。

## 5. 运行期所有权

`运行期上下文` 私有成员顺序固定为：`L1事实基座服务_` 先于 `L1特征定义服务_`。构造列表以 `L1特征定义服务_(L1事实基座服务_)` 初始化，并公开同步借用访问器：

```cpp
L1特征定义服务& 读取L1特征定义服务() noexcept;
const L1特征定义服务& 读取L1特征定义服务() const noexcept;
```

上下文、服务及 L1 的生命周期一致；不保存外部请求引用。访问器诊断责任为“无适用错误分支”。本叶不把特征定义完整性并入 `运行期上下文::完整()`，避免未登记定义阻断现有运行期发布。

## 6. 写入、读回和状态映射

### 6.1 建立登记

入口先校验合同/规则、幂等身份和期望代次。若内存已有登记，同请求返回幂等读回，异请求返回幂等冲突。

单一 L1 写集建立四个普通/属性类型节点：服务身份、定义标记 I64 属性类型、I64 下界属性类型、I64 上界属性类型。不得建立业务节点、关系、值或索引。写后以四个新编码分别读取节点，要求同一非零事实代次、种类和 I64 表示准确，再保存值式登记。

### 6.2 建立 I64 定义

登记未加载时返回 `登记未加载`。校验 `下界 <= 上界` 后，以 `0x04` 私有域映射幂等键，形成一个原子 L1 写集：

1. 新建一个普通节点作为特征定义；
2. 新建定义标记值 `I64(1)`、下界值、上界值，所属均为该定义节点，属性类型分别来自登记，来源均为登记服务身份；
3. 同写集设置三个当前属性槽；
4. 成功/精确重复后从 L1 返回映射取得四个稳定编码；
5. 只通过 `读取I64特征定义` 再次读取事实，事实截止代次必须等于写入代次。

不得建立关系22、实例槽、当前特征值或旧特征节点。

### 6.3 读取

读取请求必须携带定义及三个值编码。服务依次读取：定义节点、登记的四个节点、定义的三个属性槽、三个值事实；全部结果的 `读取事实代次` 必须相同且非零。逐项证明节点种类、属性表示、槽指向、值所属、属性类型、来源、材料分支和值域。任一事实未找到映射未找到；代次不同映射事实代次漂移；形状或来源矛盾映射内部不一致。

写状态映射：成功→已提交，精确重复→幂等读回，幂等冲突→幂等冲突，事实代次漂移→事实代次漂移，资源失败→资源失败，其它拒绝→入口拒绝，内部不一致保持内部不一致。

## 7. 并发、锁与失败

服务仅用一个私有 `std::mutex` 串行保护登记和调用；持锁时只同步调用 L1 内存服务，不做日志、文件、SQL、网络、等待或回调。L1 自身负责事实事务；本叶没有第二仓锁、共享锁升级或候选权。

第一笔写前的合同、规则、身份、范围和登记检查失败必须零事实变化。L1 非成功原样映射；写后读回失败不得伪造成功。资源和未知异常均返回空业务载荷。
