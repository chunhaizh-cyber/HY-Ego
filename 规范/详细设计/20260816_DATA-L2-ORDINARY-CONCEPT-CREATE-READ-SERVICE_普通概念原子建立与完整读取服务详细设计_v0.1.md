# DATA-L2 普通概念原子建立与完整读取服务详细设计

日期：2026-08-16

版本：v0.1

身份：`DATA-L2-ORDINARY-CONCEPT-CREATE-READ-SERVICE`

状态：设计就绪

## 1. 目标与完成边界

在已经发布的 `L2普通概念结构.数据.h` v1 值式合同上，为 `DATA-EXT-08` 实现第一份普通概念真实服务能力：

```text
建立普通概念
+ 按概念身份读取当前完整普通概念
+ 按概念身份读取历史完整普通概念
```

服务继续是唯一 `L2概念结构服务`，继续持有唯一概念 owner 写端口。一次首次建立必须把独立概念节点、概念族归属、本体根归属、完整签名、至少一条直接上位、全部初始定义、至少一条来源证据、首次请求见证和初始活跃生命周期作为一份概念 owner 写集原子发布，并从首次事实截止完整读回。

本叶不修改四本体根 DTO、根建立 / 单根读取 / 全根组读取三项 ABI，不建立第二概念 owner、第二 C1、通用裸编码查询或直接 L1 公共写入口。不实现直接上下位、定义、支持关系的独立增改退，不实现生命周期迁移、概念不可逆退出、名称关系、按根展开、世界事实支持组 CRUD 或概念树投影。普通应用尚未持有不可变材料服务，因此本叶只实现完整构造和服务能力，不修改普通应用装配，也不宣称生产消费者已经接线。

## 2. 正式依据与当前事实

正式依据：0050 v1.3、2220 v1.5、4030 v1.9、4040 v1.5、4050 v1.4、4190 v0.6、4240 v0.6、7140 v1.2，以及 `DATA-L2-ORDINARY-CONCEPT-PUBLIC-DTO v0.1` 已发布合同。

当前代码事实：

1. `L2普通概念结构.数据.h` 已冻结普通概念建立、当前 / 历史读取 DTO、十三类世界关系引用、完整性 helper 和成功形状，但没有真实服务入口。
2. `服务.L2概念结构.ixx` 只有四本体根三入口，持有唯一概念 owner 写端口，并已经登记概念族、根角色、直接上位与根首次请求见证结构。
3. 不可变材料、场景、存在、特征、状态、动态、因果服务均有具名当前 / 历史读取；普通概念服务不得绕过这些服务读取其它 owner 的结构。
4. 普通应用已经持有唯一概念服务及概念聚合，但尚未装配不可变材料服务；本叶不能选择默认材料根、默认目录或隐式资源路径。
5. `TARGET-POSITIVE-GAP-CONFIRM-COMPOSE` 把无需求身份的目标候选比较留在 `DATA` 外的 `需求目标裁决服务`；本叶不读取目标差距、不建立需求，也不判断概念候选是否正确或有用。

## 3. 唯一公开服务与构造

### 3.1 保留根专用构造

下列现行构造逐字保留：

```cpp
explicit L2概念结构服务(
    const L1事实基座服务&,
    L2概念所有者交付&&);
```

它继续支持四本体根三入口。它也初始化普通概念所需的概念 owner 私有类型登记，但不取得其它结构服务；经该构造形成的实例调用普通概念两入口固定返回结构化 `未实现`、空负载和零变更。

### 3.2 新增完整构造

同一类增加唯一完整构造：

```cpp
L2概念结构服务(
    const L1事实基座服务& 第一层服务,
    const 不可变材料服务& 材料服务,
    const L2场景结构服务& 场景服务,
    const L2存在结构服务& 存在服务,
    const L2特征结构服务& 特征服务,
    const L2状态结构服务& 状态服务,
    const L2动态结构服务& 动态服务,
    const L2因果结构服务& 因果服务,
    L2概念所有者交付&& 概念所有者交付);
```

它只保存七份 non-owning `const` 服务指针，继续只移动取得一份概念 owner 写端口。完整构造委托根专用构造完成同一 L1、owner 与私有登记，再绑定只读依赖；不复制任何服务实例，不取得其它 owner，不形成反向世界依赖。

### 3.3 新增公开操作

```cpp
L2普通概念写入结果 建立普通概念(
    const L2普通概念建立请求& 请求);

L2普通概念读取结果 读取普通概念(
    const L2普通概念读取请求& 请求) const;
```

公开 DTO 只来自既有 `L2普通概念结构.数据.h`，不增加版本字段、业务操作标签、超时、锁、raw owner、缓存或事务对象。`L2概念结构聚合服务` 不改代码；它现有 getter 自动返回扩展后的同一实例。

## 5. 首次建立物理写集

### 5.1 固定和分区本地键

固定本地键：

| 本地键 | 写集事实 |
| --- | --- |
| `0x020A'2001` | 普通概念节点 |
| `0x020A'2002` | 概念族归属关系 |
| `0x020A'2003` | 本体根归属关系 |
| `0x020A'2004` | 签名规则关系 |
| `0x020A'2005` | 首次请求见证值 |
| `0x020A'2006` | 初始治理生命周期值 |

可变组按请求中已经严格排序的索引使用互异高位分区：

```text
0x1000'0000 + i  直接上位关系
0x2000'0000 + i  来源证据关系
0x3000'0000 + i  签名项节点
0x4000'0000 + i  签名项成员关系
0x5000'0000 + i  签名项键值
0x6000'0000 + i  签名项材料值
0x7000'0000 + i  定义项节点
0x8000'0000 + i  定义项成员关系
0x9000'0000 + i  定义项键值
0xA000'0000 + i  定义目标编码值
```

任一组数量不能使本地键跨出自身 `0x0FFF'FFFF` 容量；超过时在写前返回 `数量预算不足`，零变化。该限制只来自稳定本地键物理容量，不缩小概念业务语义。

### 5.2 写集事实映射

一次写集固定形成：

1. 一个普通概念节点；
2. `概念 -> 概念族锚点` 的族归属关系，角色固定为现行概念族归属角色；
3. `概念 -> 本体根` 的根归属关系；
4. `概念 -> 签名规则材料` 的签名规则关系；
5. `上位概念 -> 概念` 的全部直接上位关系，复用现行直接上位关系类型；
6. `概念 -> 来源证据材料` 的全部来源证据关系；
7. 每个签名值式项各一个内部项节点、一个 `概念 -> 项节点` 成员关系、一个 `[角色, 顺序]` 键值和一个类型匹配的材料值；
8. 每个定义项各一个内部项节点、一个 `概念 -> 项节点` 成员关系、一个 `[角色, 顺序]` 键值和一个定义目标闭合编码值；
9. 概念节点上的首次请求见证值 `[幂等身份, 首次期望事实代次, 普通概念合同版本]`；
10. 概念节点上的初始治理生命周期 I64 值 `活跃`。

首次请求见证和生命周期分别占用自己的属性槽。签名 / 定义内部项节点各有两个属性槽；签名材料的 L1 表示种类必须与 `L2原始值材料` variant 精确对应。独立材料引用的值来源为被引用材料节点，其它签名值来源为概念节点。定义目标编码值来源为概念节点。

首次映射数量必须精确等于：

```text
6 + 直接上位数 + 来源证据数
+ 4 * 签名值式项数 + 4 * 初始定义项数
```

多映射、少映射、重复键、零编码或编码复义均为内部不一致。

### 5.3 定义目标闭合编码

定义目标值只使用本合同私有、闭合且可逆的 U64 组，不是通用 U64 包：

| DTO 目标 | 编码 |
| --- | --- |
| 概念 / 场景 / 存在 / 特征定义 / 特征实例 / 状态 / 动态 / 因果 | `[目标标签, 稳定编码]`，标签依 variant 顺序为 `1—5、7—9` |
| 特征值 | `[6, 特征实例编码, 值稳定编码]` |
| 世界关系 | `[10, 关系类别, 关系稳定编码, 源端点标签, 源编码, 目标端点标签, 目标编码]` |

世界关系端点标签固定为：场景 `1`、存在 `2`、特征定义 `3`、特征实例 `4`、状态 `5`、动态 `6`、因果 `7`、动作引用 `8`。未知标签、长度不匹配、零编码或关系类别 / 端点方向不匹配均不能读成公开 DTO。

## 6. 建立前同截止校验

建立请求先通过现行 `L2普通概念建立请求有效`。随后在请求非零 `G0 = 请求头.期望事实代次` 完成以下只读校验，任何写入都发生在全部校验之后：

1. 经同一实例根入口读取全部当前本体根，指定根必须是四根之一且永久当前；
2. 每个直接上位必须是指定根本身或当前完整普通概念，全部归属同一根；新节点尚不存在，因此只要父项同根且现有图完整，不会形成回边；
3. 签名规则材料、全部来源证据材料和签名独立材料引用经 `不可变材料服务` 在 `G0` 当前完整读回；
4. 概念定义目标经本服务读取根 / 普通概念，或经对应场景、存在、特征、状态、动态、因果公开服务在 `G0` 完整读回；
5. 特征值引用必须由特征服务读回同一实例的当前值且值稳定编码精确匹配；
6. 世界关系引用必须从其源对象的完整公开事实中找到相同关系编码、类别、方向和两个端点；只命中编码或只命中端点都不成立；
7. 以本体根归属关系类型的 L1 同许可闭包读取全部当前普通概念，再以相同 `G0` 读取内部项属性，重建所有完整签名和首次请求见证。

所有公开依赖读取都必须成功回显 `G0`、零变更和完整负载。任一调用返回漂移、未找到、已退出、资源失败等合法非成功时保持原分类；依赖声称成功但截止、负载、强类型或关系不匹配时返回内部不一致。数据层只证明目标结构存在和形状完整，不判断定义、上位、来源或签名是否在业务上正确。

## 7. 签名唯一、幂等和并发

完整签名唯一键固定为：

```text
本体根
+ 签名规则材料
+ 确定排序的全部签名值式项
+ 确定排序的全部定义项
```

来源证据和直接上位不进入签名唯一键，但属于完整建立请求语义。写入前扫描按以下顺序裁决：

1. 任一现有概念首次见证使用本次幂等身份、但重建的完整首次请求不同：`幂等冲突`；
2. 找到同一完整签名且首次见证、直接上位、来源证据及完整请求都与本次相同：按该概念首次创建截止历史读回，返回 `精确重复`；
3. 找到同一完整签名但首次请求不同：`引用冲突`；
4. 未命中后形成确定写集，并以调用方幂等身份数值作为 owner-scoped L1 写幂等身份恰一次提交。

根建立与普通概念建立共用同一服务级写锁。锁只保护概念唯一性预读到 L1 提交的本实例序列，不替代 L1 事务域；最终期望代次和全部引用仍由 L1 在候选前复核。并发导致 `G0` 变化时返回事实代次漂移，调用方重读后自行决定是否重组请求。发布结果未知、资源失败或发布后读回失败只能重放原完整请求和原幂等身份。

## 8. 当前与历史完整读取

### 8.1 当前读取

当前读取要求非零 `G0`、历史截止为零。服务在 `G0` 用本体根归属关系闭包定位目标普通概念及其全部概念 owner 自有事实，再用同一 `G0` 读取内部项属性；随后按第 6 节经公开依赖逐项验证当前根、材料和世界引用。

成功固定返回 `已读取`、事实截止 `G0`、零变更和一个 `L2普通概念事实`。概念节点已退出返回 `已退出`；目标是本体根或在 `G0` 不存在普通概念根归属时返回 `未找到`；节点仍当前但自有结构缺项、重复、混代或引用损坏返回内部不一致。活跃、冷却、退役三种当前治理状态都可以成功读取。

### 8.2 历史读取

历史读取使用 `H = 历史截止事实代次`，要求 `0 < H <= 请求头.期望事实代次`。全部概念 owner 自有事实和外部强类型引用均按 `H` 的公开历史入口读取；结果头事实截止固定为 `H`，读取类别和历史截止回显 `H`。

目标在 `H` 尚未建立返回 `未找到`。目标在 `H` 已经不可逆退出时，若 L1 历史投影仍能返回截止内完整自有事实，则成功携带退出生命周期；若退出事务已经使截止内结构不完整则为内部不一致。历史读取不得用当前事实补齐缺项。

### 8.3 重建顺序

公开事实组稳定排序：签名和定义按 `(角色, 顺序)`，直接上位按上位概念编码，来源证据按材料身份编码。内部项节点、键值、材料值和首次见证不泄漏到 DTO；它们必须逐项互证后才形成公开事实。

## 9. 结果与错误映射

| 条件 | `L2结构状态` | 负载 / 变更 |
| --- | --- | --- |
| 首次提交并完整读回 | `已提交` | 首次完整概念；变更代次 = 首次截止 |
| 同幂等同完整请求 | `精确重复` | 首次历史概念；变更代次 = 首次截止 |
| 无效请求、保留幂等身份、根专用实例调用普通入口 | `入口拒绝` 或 `未实现` | 空 / 零变更 |
| 依赖或目标不存在 / 已退出 | `未找到` / `已退出` | 空 / 零变更 |
| 期望事实代次不再当前 | `事实代次漂移` | 空 / 零变更 |
| 同幂等异完整请求 | `幂等冲突` | 空 / 零变更 |
| 同签名异请求、父根不符、关系编码与端点不符 | `引用冲突` | 空 / 零变更 |
| 本地键物理容量不足 | `数量预算不足` | 空 / 零变更 |
| 内存分配、依赖资源或 L1 资源失败 | `资源失败` | 空 / 零变更；原请求重放 |
| 坏成功形状、半结构、重复当前、混代或读回矛盾 | `内部不一致` | 空 / 零变更；停止依赖路径 |

写成功只允许现行 DTO helper 接受的 `已提交 / 精确重复` 形状。读成功只允许 `已读取`。全部非成功 optional 为空、变更代次为空；事实截止只在可证明的漂移 / 冲突 / 资源边界回显，不被消费者解释为成功。
