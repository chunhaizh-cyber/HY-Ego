## 1. 目标、范围和完成边界

本叶子只补齐 P1A2 类型化结构事务对“具名强类型内部参与者”的业务中性桥接，使后继领域数据操作能在不向 L2 泄漏参与者、回调、许可、会话、锁或仓库的前提下，与核心写集在同一 4040 事务共同准备、确认、撤销和发布。

完成只证明核心桥接接口、真实生命周期和专项自检已实现。它不证明任何特征批次账、领域参与者、SQL 证据、恢复闭环或世界树特征写入已经实现。

### 3.1 参与者状态与结果

```cpp
enum class 节点直接类型化结构事务参与者状态 : std::uint8_t {
    已准备 = 1,
    已确认待发布 = 2,
    已撤销 = 3,
    已完成发布 = 4,
    入口拒绝 = 5,
    版本漂移 = 6,
    许可拒绝 = 7,
    资源失败 = 8,
    内部不一致 = 9
};

struct 节点直接类型化结构事务参与者结果 {
    节点直接类型化结构事务参与者状态 状态 =
        节点直接类型化结构事务参与者状态::内部不一致;
};
```

稳定值不得重排。准备只接受 `已准备`；确认只接受 `已确认待发布`；撤销只接受 `已撤销`；最后发布只接受 `已完成发布`。阶段不匹配按内部不一致处理。

### 3.2 局部身份见证与候选读回

```cpp
using 节点直接类型化结构计划稳定见证 = std::variant<
    节点稳定身份见证,
    关系稳定身份见证,
    类型化值读回>;

struct 节点直接类型化结构计划身份见证项 {
    节点直接写集局部身份 局部身份;
    节点直接类型化结构计划稳定见证 稳定见证;
};

struct 节点直接类型化结构候选读回 {
    std::vector<节点稳定身份见证> 节点组;
    std::vector<关系稳定身份见证> 关系组;
    std::vector<类型化值读回> 类型化值组;
    std::vector<可重建索引读回> 索引组;
};
```

形成规则：

1. 每个请求局部身份在见证组中恰有一项；种类必须与 variant 分支一致。
2. 节点、关系和类型化值记录见证来自本事务已经形成但尚未普通可见的真实候选，不得由参与者猜测高水位或版本。
3. 候选读回按请求 `读回规格.项目组` 原顺序形成；它是准备期借用的纯值视图，不是已发布结果。
4. 索引没有局部身份，只进入候选读回，不进入局部身份见证组。

### 3.4 新参与者协议

```cpp
class 节点直接类型化结构事务参与者 {
public:
    virtual ~节点直接类型化结构事务参与者() = default;

protected:
    节点直接类型化结构事务参与者() = default;

private:
    friend class 节点直接身份结构写入执行器;

    virtual 节点直接类型化结构事务参与者结果 准备提交(
        const 节点直接类型化结构提交准备只读视图& 视图) = 0;
    virtual 节点直接类型化结构事务参与者结果 确认待发布() = 0;
    virtual 节点直接类型化结构事务参与者结果 完成撤销() = 0;
    virtual 节点直接类型化结构事务参与者结果 完成发布() = 0;
};
```

四个生命周期函数均由执行器以 `try/catch (...)` 包裹。领域参与者只由后继计划实现；本叶子自检使用私有测试参与者。

`准备提交` 的撤销合同固定如下：执行器在调用第 k 个参与者前先把“已触及数量”推进到 k；从该调用开始，无论其返回成功、非成功或抛异常，第 k 个参与者都必须允许执行器调用 `完成撤销()`。`完成撤销()` 必须幂等地清除本次事务可能形成的全部私有候选；即使准备在第一笔私有候选后失败、尚未形成候选或此前已经撤销，也必须返回 `已撤销`。因此执行器不依赖“准备失败天然零候选”的隐含强异常保证。

### 5.1 现行分支重排的唯一机械规则

现行六个非空业务分支都把“业务候选确认”和“幂等候选形成+立即确认”交错在一起。实施必须原位拆开，但不得改变任何业务候选内部依赖顺序：

```text
形成全部业务候选（零确认）
-> 仅从候选和现行计划材料形成发布后读回/结果摘要
-> 形成核心幂等候选（零确认）
-> 构造准备只读视图并按登记序调用参与者准备
-> 按本节表中“核心确认顺序”确认业务候选与幂等候选
-> 按登记序确认全部参与者
-> 按本节表中“最后发布”完成发布
-> 推进事务域普通已发布代次
```

不得在参与者准备前确认任何业务候选或幂等候选；不得把幂等候选留到参与者准备后才形成。现有结果摘要如果依赖候选读回，只读取未发布候选已经给出的值式见证，不要求候选先确认。

六分支统一持有一个可选核心幂等候选。幂等候选形成失败时参与者调用数为0，直接按表中业务候选逆序撤销。参与者准备/确认失败时，顺序固定为：

```text
已触及参与者 k..1 逆序完成撤销
-> 撤销核心幂等候选
-> 按分支表逆序撤销业务候选
-> 仅当上述三类撤销全部成功，才调用现行持久端口标记已撤销未发布并清除临时侧账
```

任一参与者、核心幂等候选或业务候选撤销失败、抛异常或结果未知时，禁止写已撤销未发布见证、禁止清除临时侧账；执行器必须保留可恢复现场，隔离事务域并覆盖首次状态为 `内部不一致`。只有三类撤销全部成功才允许调用持久端口；持久见证失败、结果未知或清账失败时同样隔离并保留可恢复侧账。空域治理不允许非空参与者，继续使用现行幂等候选确认/发布/代次路径，不进入上述六分支重排。

## 6. 状态映射与异常合同

| 参与者状态 | 数据操作结果 | 是否尝试撤销 | 是否隔离 |
| --- | --- | --- | --- |
| 对应阶段成功值 | 继续 | 否 | 否 |
| `入口拒绝` | `入口拒绝` | 是 | 撤销完整则否 |
| `版本漂移` | `版本漂移` | 是 | 撤销完整则否 |
| `许可拒绝` | `许可拒绝` | 是 | 撤销完整则否 |
| `资源失败` | `资源失败` | 是 | 撤销完整则否 |
| `内部不一致`、错误阶段成功值或异常 | `内部不一致` | 发布前是 | 撤销完整且未显式进入最后发布则否 |
| 撤销失败 / 异常 | `内部不一致` | 已尽力逆序调用 | 是 |
| 最后发布失败 / 异常 | `内部不一致` | 否，撤销已关闭 | 是且代次不推进 |

首次非成功状态只在完整撤销和持久未发布见证成立时返回。任何后继收口失败覆盖首次状态为内部不一致。

## 7. 所有权、并发和生命周期

1. 执行器借用参与者对象，不拥有、不移动、不删除、不缓存。
2. 地址唯一性按指针值 O(n²) 检查；空组合法，任一空指针或重复地址在持久准备前拒绝。
3. 事务域独占许可仍由执行器唯一取得和释放；参与者管理自己的私有候选和内部锁。
4. 准备顺序和确认顺序严格等于 span 登记顺序；撤销覆盖所有已经开始调用 `准备提交` 的参与者（含返回非成功或抛异常的当前项），按已触及前缀严格逆序。
5. 核心候选和参与者完成发布都位于独占许可内；最后一步 `推进普通已发布代次` 是唯一普通读取线性化点。
6. 参与者不得在持有其内部锁时调用 L2、日志、SQL、外设、等待或反向进入核心事务；后继领域设计必须另行冻结其内部锁序。
