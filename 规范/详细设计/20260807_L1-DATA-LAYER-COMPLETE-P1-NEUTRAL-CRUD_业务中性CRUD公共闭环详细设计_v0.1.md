# L1-DATA-LAYER-COMPLETE-P1-NEUTRAL-CRUD 业务中性 CRUD 公共闭环详细设计 v0.1

日期：2026-08-07

## 1. 目标与两道门

本叶在现有唯一 `L1事实基座服务 / L1事实基座仓库` 上建立第一条符合 4015 v0.4 的业务中性普通 CRUD 公共闭环：调用方只提交节点、关系、值、属性槽、退出项、期望事实代次和不透明幂等键；L1 在同一内存权威仓内完成候选、原子代次发布和精确读回，并通过具名当前 / 历史入口返回不可变结构化结果。

两道门严格分开：

1. **L1 中性数据正确性门**：生产二进制外的验收者只经本叶公开入口证明创建、当前读取、更新、退出 / 历史读取、精确重复、同键异义、原子可见和非法请求零变化；这是本叶的外部黑盒门。
2. **后续数据服务充分性门**：L2—L5 合法消费者以后通过实际调用、结构化结果、权威状态读回和自己的合同判定 L1 是否足以完成领域目标；该判定不能修改、绕过或降低第一道门。

本叶不迁移任何既有领域消费者，不删除 legacy 接口或旧仓，不实现完整快照、审计、持久恢复、崩溃、重启、断电或跨进程恢复，不把业务标签、意图组、执行证据或领域结果见证换名带入新接口。

## 4. 公共 DTO 合同

`L1中性CRUD.数据.h` 只依赖 `L1公共事实.数据.h` 和标准库。全部新业务标识符使用中文，合同版本固定：

```cpp
inline constexpr std::uint32_t L1中性CRUD合同版本 = 1;
```

### 4.1 基础值式类型

为避免把 legacy 数据头公开给新消费者，边界 DTO 使用具名中性类型；它们只是不可变传输投影，权威状态仍唯一保存为现有仓库内部节点 / 关系 / 值事实，不能形成第二事实基座。

```text
L1中性写集本地键 { uint32 值 }
L1中性写集幂等键 { uint64 值 }
L1中性独立材料引用 { 稳定编码 编码 }
L1中性事实引用 = variant<稳定编码, L1中性写集本地键>
L1中性原始值材料 = variant<I64, I64组, U64组, L1中性独立材料引用>
L1中性值表示种类 = I64 / I64组 / U64组 / 独立材料引用
```

公开事实副本固定为：

```text
L1中性属性槽 = 属性类型节点 + 当前值
L1中性节点事实 = 编码 + 节点种类 + 可选值表示种类 + 创建事实代次 + 可选退出事实代次 + 升序唯一当前属性
L1中性关系事实 = 编码 + 源节点 + 目标节点 + 关系类型节点 + 角色或顺序 + 创建事实代次 + 可选退出事实代次
L1中性值事实 = 编码 + 所属节点 + 属性类型节点 + 原始值材料 + 来源节点 + 创建事实代次 + 可选退出事实代次
L1中性事实副本 = variant<上述三类事实>
```

### 4.2 写请求

```text
L1中性节点新建项 = 本地键 + 节点种类 + 可选值表示种类
L1中性关系新建项 = 本地键 + 源 / 目标 / 关系类型引用 + 角色或顺序
L1中性值新建项 = 本地键 + 所属 / 属性类型引用 + 材料 + 来源引用
L1中性属性槽变更项 = 所属 / 属性类型引用 + 新当前值本地键

L1中性写集请求 =
  合同版本
  + 期望事实代次
  + 非零不透明幂等键
  + 节点新建项组
  + 关系新建项组
  + 值新建项组
  + 属性槽变更项组
  + 退出事实稳定编码组
```

请求中不得出现摘要版本、操作标签、意图组、领域合同 / 规则、执行证据、提供者见证、领域结果见证、审计、恢复或调用方自定读回计划。读回项目由仓库根据规范化完整写集机械形成。

规范化顺序固定为：节点 / 关系 / 值按本地键升序，属性槽按所属引用、属性类型引用、新值本地键升序，退出事实按稳定编码升序；同组重复、跨三类重复本地键、重复退出编码和空写集均在锁前拒绝。幂等同义比较使用规范化请求除合同版本外的全部字段逐字段比较，摘要不得代替比较。

### 4.3 结果

```text
L1中性写入状态 = 成功 / 精确重复 / 入口拒绝 / 未找到 / 已退出 /
                   事实代次漂移 / 幂等冲突 / 资源失败 / 内部不一致
L1中性重试边界 = 不适用 / 原请求可重试 / 修正请求后可重试 / 原幂等键读回收敛

L1中性写入结果 =
  状态 + 合同版本 + 幂等键 + 事实代次
  + 是否形成内存权威发布
  + 重试边界
  + 按本地键升序的新编码映射
```

成功的 `事实代次` 是本次新代次且 `是否形成内存权威发布=true`；精确重复返回首次发布代次和首次映射且布尔值为 false；写前拒绝、未找到、已退出、漂移、冲突和资源失败均为 false。发布后读回矛盾返回内部不一致、新代次和 true，并使现有仓库隔离。普通结果不返回审计、恢复材料、执行证据、领域见证或全快照。

读取状态固定为成功、入口拒绝、未找到、已退出、属性未设置、资源失败、内部不一致；各结果显式回显合同版本、查询身份和适用读取事实代次，非成功不带事实副本。历史成功返回当前或已退出的一条完整事实，事实自身退出代次决定当前性。

## 5. 公开函数合同

全部函数归属 `L1事实基座服务`，在 `服务.L1事实基座.ixx` 类 public 区、legacy `提交写集` 之前声明并内联定义；服务只校验合同版本后转发 / 映射，不持有第二状态。

```cpp

L1中性节点读取结果 读取中性当前节点(const L1中性事实读取请求& 请求) const;
L1中性关系读取结果 读取中性当前关系(const L1中性事实读取请求& 请求) const;
L1中性值读取结果 读取中性当前值(const L1中性事实读取请求& 请求) const;
L1中性属性读取结果 读取中性当前属性(const L1中性属性读取请求& 请求) const;
L1中性历史读取结果 读取中性历史事实(const L1中性事实读取请求& 请求) const;
L1中性事实代次读取结果 读取中性当前事实代次(const L1中性事实代次读取请求& 请求) const;
```

仓库新增唯一写根：

```cpp
L1中性写入结果 提交中性写集(const L1中性写集请求& 请求);
```

中性读取由服务调用现有仓库精确读取后逐字段转换；不得调用完整快照、审计、恢复或索引。转换函数只可作为 `服务.L1事实基座.ixx` 匿名命名空间纯值辅助，不导出、不访问仓库。

## 6. 中性提交事务

仓库状态新增 `中性幂等账`，键为不透明 `uint64`，值为：规范化完整中性写集、首次发布事实代次、首次新编码映射和首次中性写入结果。它与 legacy 幂等账处于同一仓库状态、同一锁和同一次候选复制 / 交换中，不是第二事实仓或业务事实。

幂等键在两个账之间不得复用：中性请求命中 legacy 账、legacy 请求命中中性账均返回幂等冲突且不推进代次。legacy 入口除此交叉占用检查外保持原有行为、DTO、审计和结果。

事务顺序固定：

```text
锁前规范化和形状拒绝
-> 取得仓库唯一独占锁
-> 隔离 / 当前状态完整性
-> 双账幂等键占用与中性完整写集逐字段比较
-> 期望事实代次
-> 针对同一当前代次校验全部引用、类型、端点、槽和退出项
-> 复制同一仓库状态形成候选
-> 节点、关系、值确定分配全局不可复用编码
-> 应用退出和属性槽替换；旧值退出与新值 / 槽同代次
-> 候选完整性与机械读回
-> 在候选写入中性幂等首次结果
-> 一次交换状态并关闭撤销能力
-> 以原身份 / 映射 / 新代次从已发布状态逐项读回
-> 返回成功，或隔离并返回发布后内部不一致
```

所有可能分配内存的结果、映射和候选材料必须在最后交换前准备完成；交换后只做不分配的查找、比较、隔离标记和结果移动，避免产生“发布结果未知”。候选前失败和候选失败均丢弃局部值，当前事实代次、三类当前事实、历史、永久编码和两份幂等账零变化。

当前阶段不实现中性幂等账的恢复导出。为防止现有 legacy 管理入口伪造完整恢复，在中性幂等账非空时，`导出恢复材料`、`建立恢复候选` 和 `确认恢复候选` 必须结构化返回现有入口拒绝且零变化；`撤销恢复候选` 只允许清除进入中性发布前已经存在的候选。该守门只防假成功，不声明恢复能力。

## 7. legacy 共仓过渡

1. 现有 `提交写集` 三个带标签重载、无标签 legacy 重载、探测幂等、审计、恢复和领域结果见证类型不删除、不改签名；现有 10 文件 16 调用点零修改。
2. 新消费者只能 import 新中性合同并调用本设计七个入口；禁止新增 `提交写集(..., 操作标签)` 调用。
3. 两条入口共享同一 `仓库_`、锁、事实代次、稳定编码分配器、当前 / 历史事实和永久占用空间；禁止建立平行容器保存中性当前事实。
4. 旧节点仓库、关系仓库和节点直接五仓完全只读保留；本叶不迁移、不对账、不删除。
5. 后继逐个领域消费者迁移时，由领域服务负责把业务请求中性化并解释中性结果；L1 不拥有其业务充分性结论。

## 8. 生产二进制外黑盒验收合同

独立验收者绑定代码结果提交，在仓库外临时目录建立不进入 `海中鱼巣.vcxproj` 的驱动，只 import `合同.L1中性CRUD` 与 `服务.L1事实基座`，只构造公开 `L1事实基座服务` 并调用本设计七个入口。驱动不得访问仓库类、friend、锁、候选、内部状态、日志文本、完整快照、审计或恢复。

最小矩阵：

| 分支 | 外部动作 | 结构化结果 | 权威读回 |
| --- | --- | --- | --- |
| 创建 | 一笔建立属性类型、关系类型、宿主、子节点、来源节点、关系、值和槽 | 成功、代次 +1、映射完整 | 当前节点 / 关系 / 值 / 属性逐项同代次 |
| 当前读取 | 分别读取节点、关系、值、属性 | 成功且身份回显 | 字段逐项等于请求发布事实 |
| 精确重复 | 原幂等键和同一完整写集 | 精确重复、原代次 / 原映射、无新发布 | 当前代次不变 |
| 同键异义 | 原键改变任一中性字段 | 幂等冲突 | 当前代次及全部既有事实不变 |
| 更新 | 新值 + 槽替换，并以新关系 + 旧关系退出表达关系替换 | 成功、一次代次推进 | 新值 / 新关系当前；旧值 / 旧关系只在历史入口成功 |
| 退出 | 退出不再被当前端点 / 槽引用的事实 | 成功、一次代次推进 | 当前读取已退出，历史读取返回完整退出代次 |
| 非法请求 | 零合同、零键、空写集、重复本地键、错类型材料、缺端点、已退出引用、基线漂移 | 对应入口拒绝 / 未找到 / 已退出 / 漂移 | 每例前后中性当前事实代次相同 |
| 原子可见 | 更新期间并发公开读取 | 只允许完整旧代次或完整新代次 | 不出现半结构或混代字段 |
| 并发幂等 | 两线程提交同键同义 / 同键异义 | 同义一成功一精确重复；异义至多一成功另一冲突 | 每组至多一次事实代次推进 |

验收记录保存于 `验证记录/集成验收/`，由集成验收角色独立发布。Debug / Release 构建和外部驱动编译只是门禁；日志只供人读，不作为任何单元格通过条件。

## 10. 完成声明与下一缺口

代码切片完成最多证明：一个现有 L1 服务实例通过新中性公开合同在同一内存权威仓完成普通 CRUD，并通过本计划规定的构建与静态门禁。只有独立外部黑盒矩阵通过后，才能声明 **L1 中性 CRUD 局部正确性门通过**。
