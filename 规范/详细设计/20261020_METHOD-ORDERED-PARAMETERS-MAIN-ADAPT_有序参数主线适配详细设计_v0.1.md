## 1. 目标与边界

把已提交但未进入主线的通用有序参数及“获取服务对象”参数迁移接入当前主线，作为后续服务对象需求信息本能方法的基础。复用已有代码，不重新发明参数合同，也不扩大当前本能函数的业务动作。

本轮修改方法Vm的参数组织和任务Vt/X的内部治理应用信息，目的为让执行器按固定位置交付正式信息引用。现实世界目标和原获取对象动作不变；状态、动态、因果不作为本轮本能函数直接修改目标。此处不把需求集合提供者的存在冒充获取需求本能已经接通。

完成条件：14个生产文件的精确参数增量进入主线基线，保留主线需求主体和需求集合代码；新旧布局可区分，获取对象只迁移完整可识别的空头；实际项目编译链接通过。本轮不运行测试，不证明运行迁移或业务闭环。

## 4. DTO与物理合同

精确签名和物理增量以221源提交相应文件为机械施工输入，以下冻结公开新增部分：

```cpp
enum class 新方法参数信息类型 : std::int64_t {
    存在 = 1, 特征 = 2
};
struct 新方法有序参数规格 final {
    std::uint32_t 序号 = 0;
    新方法参数信息类型 信息类型 = 新方法参数信息类型::存在;
    稳定编码 范围概念节点;
    friend bool operator==(const 新方法有序参数规格&,
        const 新方法有序参数规格&) = default;
};
struct 新方法有序参数引用 final {
    std::uint32_t 序号 = 0;
    新方法参数信息类型 信息类型 = 新方法参数信息类型::存在;
    稳定编码 信息节点;
    friend bool operator==(const 新方法有序参数引用&,
        const 新方法有序参数引用&) = default;
};
```

上述三者归`领域/新_方法公共类型.h`，不另建公共上下文。新字段：

| 现有结构 | 增量 |
| --- | --- |
| `新方法参数规格` | `std::optional<新方法有序参数规格> 有序规格` |
| `新方法条件项定义`、`新方法结果项定义` | `std::uint32_t 参数序号 = 0` |
| `新方法参数角色绑定` | `std::optional<新方法有序参数引用> 有序引用` |
| `新本能函数条件角色材料` | 同名同类型`有序引用` |

`方法参数场景`在原头源新增：

```cpp
const 新方法有序参数引用* 查询参数(std::uint32_t 序号) const noexcept;
```

返回指针由场景容器持有，仅场景有效期内使用，不取得所指世界节点所有权。旧`查询角色`继续只匹配旧布局，不把空角色的新参数匹配为旧参数。

所有具有正式概念的信息类型可作参数是规范语义，本轮实际提供者仅E/F。其它家族不得临时装入E/F、裸稳定编码或私有封套；后续以独立具名范围扩展。未实现类别不被解释为业务否定事实。

### 4.1 新旧格式和位置

新规格分支与旧角色、存在概念、嵌套特征规格、集合约束互斥；`对象种类`维持普通世界默认，不能带旧业务语义。实际新引用只含有序引用及可选世界场景定位，旧业务封套为空。

1..N连续位置不可重号、缺位、排序、合并；同类型同概念可重复占位。序号不是节点身份，禁止写入稳定编码或新建角色概念。C/R参数序号0只指旧角色布局，非零不得同时携旧角色。

Vm只保存类型及范围概念；C保存实际条件约束，R保存结果约束。参数项与条件/结果项不要求一一对应。对象所属关系从正式关系读取，不由E/F邻接推导。

### 4.2 登记与生命周期

函数内部首次登记固定有序规格，后续核对复用。Vm、方法头、函数绑定经现有方法owner完整发布读回；不是从配置或学习改写接口。架构初始化只补缺失新字段键，再检查完整性，不因多字段缺失重建已有业务状态。

限定迁移仅针对来源实现中`是服务对象空头前代`完整识别的旧“获取服务对象”空头：无既有C/R，声明和旧规格完整匹配。用`发布方法结构`既有原子骨架新建有序M/Vm、父代关系并停用旧M；查询必须收敛到唯一启用身份。旧M/Vm、任务组织、已发生X及旧材料保留，不能原地改义或删除。旧冻结调用继续受已迁移身份保护，不能绕回停用旧M。

有既有知识、损坏、不能唯一识别或登记规格不符时，工程日志/弹窗后终止；不丢弃知识、不改编号、不填默认值、不伪装条件不足。不把新登记名用作绕过旧身份的入口。未知发布使用原请求/原结构读取恢复，不另造身份。

## 5. 任务、执行及获取对象

任务owner复用221的组织写器/读器、图和字段消费完整核验，交付规格固定位置及C来源到Vt，X保存同次采用与有序引用。反求、选择、条件比较和子需求消费者按位置定位，保留原线性算法与需求目标含义。

具体F经正式特征owner读取，并经正式关系取得唯一所属E；无所属或多义不任选。缺业务条件走原筹办，损坏、读取异常走工程终止。不得恢复对方被认知需求自动配任务的旧路径，main对主体和自我执行域的门禁必须保留。

“获取服务对象”固定为：

| 位置 | 类型及范围 | 本次来源 |
| --- | --- | --- |
| 1 | 存在＝窗口专属存在概念 | 已登记交互窗口E |
| 2 | 特征＝消息数量特征类型 | 该窗口的消息数量F |

`新_本能函数集::获取服务对象(const 方法参数场景&) noexcept`使用上述参数；`服务对象本能运行服务::核验执行`复核场景包含窗口、窗口持有F、数量正值、公开会话及已接纳消息来源、同次X/T/M和有效采用。配置只是来源及身份核验，不能替代绑定的业务输入。

首次登记仍只生成头和规格，不凭声明制造C/R、关系概念或成功经验。不因此取得完整方法或尝试准入。当前获取对象原动作及返回材料边界不扩大，本轮不声称已经形成“确认人类并追加交互对象/服务对象集合”的完整新闭环。

父任务完成通知不替代真实事实；动作前实际读取留在本次材料，后续fresh读取不能重写此前快照，不能写回Vm。

## 6. 动作、模拟与归档适配

动作只读投影含有序规格。`概念_动态类.cpp`的规范化/编码/解码支持新前缀`[-1,2]`，旧布局不插入字段、不重解释。main以下能力必须原样保留其精确语义：

```cpp
动态概念建立结果 概念_动态类::建立或取得动作概念(
    const 动作概念定义&, 新事实追加保护增量&) noexcept;
```

该签名已由当前`领域/概念_动态类.h`核对；新节点、字段、关系及字段前后值的精确回执不能退化为创建前后节点计数差，更不能删除头文件中仍被需求发布服务消费的重载。

方法问题归档启用`方法问题场景归档/3`，完整保存规格、C/R参数位置、实际引用和运行材料；格式1/2原布局继续读取。main需求集合变体序列化保留：

```cpp
std::tie(x.必含需求节点组, x.至少一个需求)
```

不能只加入新格式而删掉新主线变体分支；缺字段拒绝，不猜序号。

模拟保持参数位置与隔离引用，不能访问可写现实实例。未具备模拟owner的输入在真实端口访问前拒绝，不能用模拟触发网页/外设；不扩展通用模拟能力，不发布新知识或增加真实次数。

## 7. 原子性、所有权与错误

方法owner写M/Vm/C/R，任务owner写Vt及X，正式信息owner负责E/F事实。动作投影与归档不取得上述定义写权。沿用221已实现的锁域和现有组合原子发布，不建立跨owner新私锁、新事务或另一套恢复账。

迁移发布、停用及父代关系遵循同一方法发布边界；读取必须完整，不能暴露半规格。执行组织更新经原任务owner一致发布。场景临时绑定随调用释放，X/问题材料有独立保存寿命；不删除它们引用的旧方法和世界事实。

同义重复复用；业务不具备零动作回筹办；不兼容、部分读取、混合格式、损坏引用进入工程保障，不写成条件结果知识。动作开始后的工程失败保留已发生事实，不补造结果或自动重做动作。本轮不改变既有取消/退出语义。
