不是 R8、R9、事务参与者或原子发布者。

## 2. 目标与最大边界

唯一目标：在任何 R8/provider/当前事实读取前，只用 R4 的公开意图和 R5 的最终键形成正式
`L1幂等探测请求`，调用 P15 `探测幂等` 恰一次，并把未找到、同义已发布、异义冲突、已隔离、
入口拒绝、资源失败和内部不一致映射为方法领域强类型结果。

本叶不调用 R1/R2/R3/R4/R5/R6/R7/R8/R9 服务；R4/R5 结果均由调用方按值传入。本叶不读取
当前事实，不形成 provider 证据或执行证据，不构造写集，不分配稳定编码，不取得事务许可，不
提交、不发布、不读回、不写任何事实、幂等账、缓存或 SQL。日志只允许同一生产程序人读观察，
不是机器事实。

本叶不创建或解释方法登记根、方法首、条件、结果、动作入口、需求、任务、服务候选、安全或
因果事实；不设计崩溃、重启、断电或跨进程恢复。

## 3. 唯一所有者、物理位置与依赖方向

未来实现只新增：

```text

```

`海中鱼巣.领域.服务.L1方法登记根首次发布探测` 是方法领域首次发布正式 P15 探测调用边和
状态映射的唯一所有者。服务构造时只借用 `L1事实基座服务&`，不拥有或延长 L1 生命周期；调用
者必须保证借用覆盖服务和一次根调用。服务无缓存、无锁、无第二 P15 入口。

```text
后继方法登记根首次发布协调者
 -> R10 探测方法登记根首次发布
    -> R4 已形成意图结果（值）
    -> R5 已形成最终键结果（值）
    -> P15 L1事实基座服务::探测幂等（恰一次）

R10 未找到 -> 才允许 R8 -> R9
R10 同义已发布 -> 后继独立同义结果解释叶
R10 其它状态 -> 直接收口，R8/R9 调用0
```

R1—R9、P15 和 L1 核心不得反向依赖 R10。R10 不取得稳定 provider 身份，也不进入 R9 的
执行证据 provider 组。

## 5. 调用前机械互证

在调用 P15 前必须全部成立：

1. R10/R4/R5 合同和规则版本精确匹配；R4、R5 状态分别为 `已形成`；
2. R4 凭证存在且通过公共 `L1领域意图凭证完整`；组为 G10、格式1、操作标签
   `0x15001101U`、领域结果计划摘要全零；
3. 公开请求、R4 结果和 R5 结果中的公开幂等身份逐字段相等；
4. 身份位于 `1..0x00FF'FFFF'FFFF'FFFF`，R5 键非零、高8位为 `0x19`、低56位回到该身份；
5. R4 凭证请求意图摘要非零，且凭证就是本次探测唯一意图来源；
6. 不读取当前代次、R8 证据或日志补齐任一字段。

任一不成立返回 `入口拒绝`（调用方输入/版本不满足）或 `内部不一致`（成功载荷自身矛盾），
P15 调用次数为0，材料为空。不得把 R4/R5 非成功结果降级为 P15 未找到。

唯一 P15 请求逐字段固定为：

```text
合同版本 = L1事实基座合同版本（2）
摘要合同版本 = L1幂等摘要合同版本
幂等键 = R5.L1幂等键
请求意图摘要 = R4.凭证.请求意图摘要
领域意图凭证 = R4.凭证
```

形成后立即调用 `L1事实基座服务::探测幂等` 恰一次；不得先调用 R8、R9、P17 或任何当前
事实读取，也不得在返回非成功后换键、换摘要或重试。

## 6. P15 结果分账

| P15结果 | 必需机械形状 | R10状态 | 材料 | 后继 |
| --- | --- | --- | --- | --- |
| 未找到 | 回显键等于请求键；首次结果空 | 未找到 | 原请求+结果 | 才允许调用R8，随后R9 |
| 同义已发布 | 回显键相等；首次结果存在；非当前隔离；发布代次和执行/结果摘要非零 | 同义已发布 | 原请求+完整结果 | 交独立同义解释叶；R8/R9为0 |
| 异义冲突 | 回显键相等；首次结果空 | 异义冲突 | 空 | 零写收口 |
| 已隔离 | 回显键相等；首次结果可有可无 | 已隔离 | 空 | 零写收口 |
| 入口拒绝 | P15结构化入口拒绝 | 入口拒绝 | 空 | 零写收口 |
| 内部不一致 | P15结构化内部不一致 | 内部不一致 | 空 | 零写收口 |

任何未知枚举、未找到却携带首次结果、同义缺首次结果、同义显示当前隔离、异义携带首次结果、
应回显键却错键，均映射 `内部不一致` 且材料为空。`std::bad_alloc` 映射 `资源失败`；其它未分类
异常映射 `内部不一致`。P15 当前没有资源失败枚举，R10 不得伪造一个 P15 结果，只通过自身状态
表达复制首次结果时的资源失败。

同义分支只验证上述通用最小完整性。它不把 `首次新编码映射` 的本地键解释为方法角色，不验证
R2 的 `3节点/0关系/1值/1槽/5读回`，不调用 R1，也不返回“方法登记根已存在”。后继独立
同义结果解释叶必须冻结角色映射，并依据当时正式接口单独裁决是否需要 R1 当前复核。

## 7. 确定性、调用次数与并发

- 每次合法根调用对 P15 的调用次数精确为1；入口失败为0；不存在第二探测或重试；
- 同一个只读 L1 已发布状态下，相同输入结果逐字段相等；并发语义由 P15 共享锁和幂等账负责；
- R10 不承诺两个相隔调用之间状态不变化；调用方只能消费本次返回的同一请求/结果副本；
- 未找到只证明本次探测线性化点没有该键，不能保证随后提交前仍未找到；最终同键竞争由 P15
  提交事务重新裁决；
- 所有状态的 R8、R9、稳定编码分配、事务、提交和事实写入次数均为0。
