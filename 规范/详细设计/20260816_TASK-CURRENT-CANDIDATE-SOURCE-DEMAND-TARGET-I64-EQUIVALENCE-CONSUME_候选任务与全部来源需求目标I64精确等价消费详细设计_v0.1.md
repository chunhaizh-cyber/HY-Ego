# TASK-CURRENT-CANDIDATE-SOURCE-DEMAND-TARGET-I64-EQUIVALENCE-CONSUME 候选任务与全部来源需求目标I64精确等价消费详细设计 v0.1

日期：2026-08-16
版本：v0.1

## 1. 目标与完成边界

本设计实现 `BIZ-L4-004-02-02-07 v0.1`：

```text
02完整候选任务材料 + 06全部来源需求目标引用材料 + 同一非零G0
-> D个唯一来源目标各一次正式定义读取
-> T个候选任务目标各一次正式定义读取
-> 对每个任务逐项比较其单目标与全部当前来源目标的精确I64语义键
-> 全部相等时发布D份来源定义见证和T份任务等价见证
```

本叶裁决的是“目标定义是否精确相同”，不是“当前世界值是否满足目标”。它不调用 `L2特征结构服务::比较特征`，不读取目标宿主当前特征值，不推导区间包含、近似值或文本等价，不选择当前任务根，不读取拓扑 / 治理存在，也不复核活动路径、授权或任务化资格。

## 2. 正式依据与 S0 裁决

设计 S0 基线为 `main@2b6610de3dea8ca43e2ebb8dc96be7de5ffddbf4`：

1. 3100、3200 规定任务只有一个确定目标，但可以承接多个当前有效且目标语义等价的来源需求；任一来源目标不等价时不得放入同一任务。
2. 5100 v0.2 重申上述约束，但明确不定义目标等价算法；需求领域不得直接比较裸原始值。
3. 5200 规定任务目标宿主、目标特征和目标状态必须由全部来源需求与任务目标关系联合回读，任一来源不等价即拒绝。
4. 4180 已冻结 `L2特征比较I64合同材料`的完整字段和目标判断左右角色；该合同是目标定义的一部分。调用 `比较特征`只适合比较实际值与目标值，不能替代目标定义的逐字段等价。
5. `DEMAND-CURRENT-SAME-PARENT-TARGET-CONSUME v0.2` 已预冻结唯一 `目标状态语义键`：完整比较 I64 合同、目标 I64、允许关系位和目标状态合同规则版本。主体、父需求、来源、路径和目标场景不属于这枚内层语义键。
6. `TARGET-STATE-CONTRACT-DEFINITION-CONSUME v0.1` 已冻结 `需求目标事实提供者::读取目标状态合同与值域定义`，可在非零 `G0` 下返回完整目标合同、特征定义和目标判断比较注册；该计划当前仍待激活，生产 ABI 尚不存在。
7. 02 已冻结逐任务全部当前来源关系和唯一任务目标状态合同引用；06 已冻结全部唯一来源需求的目标宿主、目标特征和目标合同引用。两计划均待激活，最终 ABI 尚未发布。

裁决：02-07 不新增 DATA 接口，也不调用 DATA 比较算法。它只借入最终 `需求目标事实提供者`，对 `D` 个唯一来源目标和 `T` 个任务目标分别正式读回定义，再用共享 `目标状态语义键`做纯值精确相等。完整无失败路径调用次数恰为 `D + T`。

## 3. 精确等价键与权威边界

唯一等价键冻结为：

```text
L2存在身份
+ 目标特征定义身份
+ 目标状态语义键 {
     完整L2特征比较I64合同材料,
     目标I64,
     允许关系位,
     目标状态合同规则版本
   }
```

其中：

- `完整L2特征比较I64合同材料`逐字段覆盖用途、算法族 / 版本、原始类型、左右角色、差异方向、单位、维度、分量角色、允许结果位、边界、量化、误差合同 / 预算 / 容差；
- 比较合同的`允许结果位`与目标状态合同的`允许关系位`是两个不同字段，必须分别参与精确相等；
- `L2目标状态合同身份`和`L2特征比较注册身份`只作权威引用与读回见证，不参与内容等价；
- 来源需求主体、身份来源、目标场景、时间、生命周期、首次幂等身份、来源稳定编码、路径、授权和显示名称均不入键；
- 特征定义身份必须相同。本叶不按两个不同特征定义的正文相似性进行归一化；
- 不同键之间不得推导宽泛 / 细化、区间包含、容差近似或默认单位换算。

`目标状态语义键`必须机械复用 `DEMAND-CURRENT-SAME-PARENT-TARGET-CONSUME v0.2` 最终公开类型，不得在任务域复制同名或同义第二类型。若最终上游不导出该类型、字段或精确相等能力，必须先由计划支撑裁决共享物理归属，本计划不得临场复制。

## 4. 输入、调用次数与集合守恒

请求必须携带同一运行代次、同一非零 `G0` 下的：

1. `任务完整承接生命周期读取结果`：状态已读取，任务组非空；每项含任务身份、全部当前来源关系和唯一任务目标关系；
2. `候选任务来源需求目标读取结果`：状态已读取，目标材料组非空；每项含唯一来源需求、目标宿主、目标特征、目标合同、生命周期和逐项版本；
3. 一项非零 `最大目标定义读取数量`预算。

设：

```text
T = 02候选任务数量
D = 06唯一来源需求数量
R = checked(T + D)
```

必须证明：

- 02 全部任务来源关系中的需求身份并集恰等于 06 的 D 个唯一需求，零遗漏、零额外、零重复；
- 02 上游当前承接见证中的入口来源需求非零，并且出现在每个候选任务的全部当前来源关系中；
- 02、06 的合同 / 请求回显、运行代次、范围 / 规则版本、任务 / 来源预算、结果截止和每项截止完整；本叶只要求两结果共享同一运行代次和 `G0`，不发明两者不存在的同名规则版本；
- `R` 可表示且 `R <= 最大目标定义读取数量`。预算为零属于请求拒绝；R超预算或checked加法失败属于数量预算不足；两者都在provider调用前返回。

固定读取顺序：

```text
按需求稳定身份排序，对D个唯一来源目标各调用一次
-> 按任务稳定身份排序，以入口来源目标特征为局部候选，对T个任务目标各调用一次
```

每次都调用：

```text
需求目标事实提供者::读取目标状态合同与值域定义(
    当前合同版本,
    当前规则版本,
    G0,
    目标合同身份,
    目标特征定义身份)
```

`目标状态合同定义读取结果`不携带请求回显，本叶不得要求上游补字段。逐次互证固定为：结果合同 / 规则版本与本次请求一致，结果和成功材料的事实截止均等于 `G0`；成功材料中的目标合同身份、特征定义身份分别等于本次构造请求，比较注册身份等于该目标合同的正式引用，其余完整合同、定义和注册字段逐项守恒。

来源调用使用该来源自己的特征与目标合同。任务调用使用入口来源目标特征和该任务唯一目标合同；入口来源只提供局部候选特征，不形成权威。最终仍须对每个任务的全部来源逐项比较完整等价键。共享来源跨任务只读取一次；任务目标不因合同身份相同而跨任务跳读。零 DATA 直接调用、零缓存、零截止重选、零 retry / sleep。

## 5. BIZ DTO、物理位置与所有权

新增：

```text
海中鱼巣/领域/候选任务目标等价.数据.h
海中鱼巣/领域/服务.任务目标等价.ixx
```

预冻结语义形状：

```cpp
inline constexpr std::uint32_t 候选任务目标等价裁决合同版本 = 1;
inline constexpr std::uint32_t 候选任务目标等价裁决规则版本 = 1;

struct 候选任务目标等价裁决固定配置 final {
    std::uint64_t 运行代次;
};

struct 候选任务目标等价裁决请求 final {
    std::uint32_t 合同版本;
    std::uint32_t 规则版本;
    std::uint64_t 运行代次;
    任务完整承接生命周期读取结果 任务材料;
    候选任务来源需求目标读取结果 来源目标材料;
    std::uint64_t 共享事实截止;
    std::uint64_t 最大目标定义读取数量;
};

struct 目标定义读取值式见证 final {
    L2目标状态合同身份 目标状态合同;
    L2特征定义身份 目标特征定义;
    L2特征比较注册身份 目标判断比较注册;
    目标状态语义键 目标语义;
    std::uint64_t 事实截止;
};

struct 来源需求目标定义值式见证 final {
    来源需求目标引用值式事实 来源需求目标;
    目标定义读取值式见证 目标定义;
};

struct 候选任务目标等价值式见证 final {
    L2任务身份 任务;
    任务目标关系值式事实 任务目标关系;
    L2存在身份 共同目标宿主;
    L2特征定义身份 共同目标特征;
    目标定义读取值式见证 任务目标定义;
    std::vector<任务来源需求关系值式事实> 全部来源关系;
    std::uint64_t 事实截止;
};

struct 候选任务目标等价材料 final {
    std::vector<来源需求目标定义值式见证> 唯一来源目标组;
    std::vector<候选任务目标等价值式见证> 任务等价组;
    std::uint64_t 事实截止;
};

enum class 候选任务目标等价裁决状态 : std::uint8_t {
    已互证 = 1,
    请求拒绝 = 2,
    数量预算不足 = 3,
    目标异义 = 4,
    当前性漂移 = 5,
    提供者拒绝 = 6,
    资源失败 = 7,
    内部不一致 = 8
};

struct 候选任务目标等价裁决结果 final {
    std::uint32_t 合同版本;
    std::uint32_t 规则版本;
    候选任务目标等价裁决状态 状态;
    std::uint64_t 运行代次;
    std::uint64_t 事实截止;
    std::optional<候选任务目标等价材料> 等价材料;
};
```

只有 `已互证`携带有值、完整且非空的两组材料与非零 `G0`。`目标异义`是一次完整 `G0` 纯值裁决，可回显 `G0`但 optional 为空；请求、预算和运行失败的 optional 为空且事实截止为零。输出是调用方拥有的指定截止值式投影，不是任务或需求目标的第二权威。

新增服务：

```cpp
class 任务目标等价裁决服务 final {
public:
    任务目标等价裁决服务(
        const 需求目标事实提供者& 目标事实提供者,
        const 候选任务目标等价裁决固定配置& 固定配置) noexcept;

    候选任务目标等价裁决结果 复核候选任务与全部来源需求目标等价(
        const 候选任务目标等价裁决请求& 请求) const noexcept;

```

服务只保存 `const 需求目标事实提供者&`和不可变固定配置，不持有 `L2结构聚合服务`、任何 DATA 服务、需求 / 任务业务服务、L1、owner、仓库、写端口或缓存。引用有效期不得超过未来拥有目标事实provider的合法父组合器或普通应用上下文；本叶不决定普通应用持有 / getter / 装配状态。

## 6. 固定控制顺序与失败映射

```text
校验固定配置和provider借用
-> 校验请求合同/规则、运行代次、02/06成功形状、G0和非零预算
-> 互证02/06来源全集、入口来源、版本、G0和集合守恒
-> checked计算T+D并校验总读取预算
-> D个来源目标定义逐项正式读取和互证
-> T个任务目标定义逐项正式读取和互证
-> 对每个任务构造入口来源局部目标候选
-> 逐任务、逐来源比较宿主、特征和目标状态语义键
-> 全部相等后一次形成D组+T组完整候选
-> 无抛出交换并返回已互证
```

| 下层 / 本叶情形 | 本叶状态 | 载荷 / 截止 |
| --- | --- | --- |
| 固定配置无效 | 内部不一致 | 空 / 0；零调用 |
| 坏合同、坏02/06成功形状、零G0/预算 | 请求拒绝 | 空 / 0；零调用 |
| 两份各自合法结果的来源全集、入口来源、运行代次或G0互相矛盾 | 内部不一致 | 空 / 0；零调用 |
| T+D不可表示或超过总预算 | 数量预算不足 | 空 / 0；零调用 |
| 任一读取当前性漂移 | 当前性漂移 | 空 / 0 |
| 任一读取许可拒绝 | 提供者拒绝 | 空 / 0 |
| 任一读取资源失败 | 资源失败 | 空 / 0 |
| 来源自己的特征+合同读取返回上下文引用冲突，或任一当前引用未找到 / 已退出 | 内部不一致 | 空 / 0 |
| 任务合同用入口来源特征读取返回上下文引用冲突 | 目标异义 | 空 / G0 |
| 合法构造触发入口拒绝、坏成功形状、错身份/G0/生命周期、未知状态或内部不一致 | 内部不一致 | 空 / 0 |
| 任一任务与任一来源的完整等价键不相同 | 目标异义 | 空 / G0 |
| D+T定义完整且全部任务全量来源等价 | 已互证 | 完整D组+T组 / G0 |

任一读取失败立即清除局部候选，零结果前缀；失败前实际已发生的只读调用不构成缓存或业务材料。全部分配、复制、排序、映射与checked累计位于异常收口内；`std::bad_alloc`、`std::length_error`映射资源失败，其它异常映射内部不一致，函数 `noexcept`且不得终止进程。

## 7. 与写侧任务化闸门的唯一性

旧 `BIZ-L4-004-02-03-01`处理创建 / 扩展任务前的写侧准入，还必须读取活动路径、授权和任务化角色。02-07 只处理读取当前任务树时的目标定义一致性，不能调用旧03-01整函数，也不能承担其路径 / 授权职责。

两者重叠的纯值目标等价只能有一个算法：共享 `目标状态语义键`逐字段精确相等。03-01 后继重基线必须复用该类型和相等规则；不得按合同身份、比较注册身份、名称、裸 I64、容差、区间或第一来源另建第二算法。
