## 1. 当前实际阻断和直接操作

现新“获取服务对象新需求”仅从参数场景取需求操作接口，并使用同一正常核心读取H/F/Em、建立被认知D、更新服务对象需求F。该函数不读X/T/K/self，不作现实/模拟业务分流。其实际目标为普通认知世界中服务对象H的需求特征，原因是保存取得的完整需求，目的为后续治理提供可读材料；不修改任务/方法虚拟存在，不直接生成selfD/T或代替self承接。

现runtime参数provider只接受fresh direct K；任务W3建立scene时未注入provider，新函数实际任务调用必失败。当前叶只补**外层**X记录适配：仍由传入scene提供业务能力，X只用来合法绑定记录身份及显式动作来源，不成为本能函数隐藏业务输入。内部任务X/A绑定是已有执行治理，不冒充函数直接结果。

固定三参数仍为1人类H、2归H的需求F、3材料存在Em；方法头、Vm固定规格、条件、目标、登记名不修改。原direct K能力保留，模拟无需求writer时禁止调用真实工厂补能力，不新建真实任务或K伪装模拟。

依据：5360唯一参数场景和外层治理；5350固定规格；5260正式采用/执行实例；1190§9.5为后继规则来源和唯一直接结果边界。本叶不改正式规范，不因“完善因果链”省略真实运行提供者。

## 2. 当前叶物理合同（待实现）

### 2.1 外层任务工厂

在现`海中鱼巣/领域/本能需求.运行接口.h`末尾新增；需要前置声明`新_任务类`不作为接口依赖，参数引用已有类型来自现头，不包含task实现：

```cpp
struct 新本能需求任务参数请求 final {
    稳定编码 方法节点, 执行实例节点;
    std::vector<新方法参数角色绑定> 参数绑定组;
    std::optional<稳定编码> 执行分支节点;
};
class 新本能需求任务参数工厂 {
public:
    virtual ~新本能需求任务参数工厂()=default;
    virtual bool 支持任务方法(稳定编码 方法节点) const noexcept=0;
    virtual std::shared_ptr<新本能需求运行接口> 建立任务参数操作提供者(
        const 新本能需求任务参数请求&)=0;
};
```

接口只归外层任务执行器/装配使用，原函数和共同核心不调用。`支持任务方法`是当前工厂覆盖能力查询，不是方法适用性、业务条件或现实授权；不支持M返回false，不生成事实。对已支持M而结构读取失败、启用/来源/规格矛盾或服务已关属于工程/前提变化，禁止伪装为“不支持”绕过装配问题。工程读取错误沿已有工程诊断终止。支持返回true后工厂不得返回空成功stub。

需求工厂请求全部来自task正式执行请求与已发布X：M、X、同一完整绑定及冻结分支；没有self、目标H或补齐材料的第二套业务输入。动作主体与动作场景由外层运行服务从其既有正式初始化记录取得，仅用于动作记录；不得据此给H/Em增加未声明同场景条件或补取缺字段。

### 2.2 task端口和生存期

`新_任务类.h`前置声明工厂；public新增：

```cpp
bool 配置本能需求任务参数工厂(新本能需求任务参数工厂&) noexcept;
bool 卸载本能需求任务参数工厂(新本能需求任务参数工厂&) noexcept;
```

private增加非拥有指针，初值null。使用现任务互斥保护配置/读取/卸载；同一地址重复配置true，异主替换false；卸载仅接受同一地址，成功清null，空或异主false。配置不回调工厂、不创建X或scene。调用方保证从配置起到全部使用线程/worker join后卸载之前工厂存续；不能在worker仍执行时先释放runtime。task不拥有runtime，不形成shared引用环。

task只在W3外层执行使用该工厂；筹办、登记、学习、目标分解不调用。冻结后M/绑定都完整，X创建成功后，在任务锁内取得端口指针并固定请求；**释放任务锁再查询支持/调用工厂/建立scene**，禁止持任务锁调用runtime或world。

### 2.3 runtime任务adapter

现`服务对象新需求本能运行服务`增加继承`新本能需求任务参数工厂`，声明上述两override。构造函数在现参数末尾追加`新_任务类&`，私有实现保存非拥有task引用；只有app实际构造点需同步，task.h只在.cpp包含。该引用是外层记录核验owner，不给共同核心读取task的权限。

`支持任务方法`读取方法owner，支持已登记抽象新需求M以及由它合法形成、仍可用且沿正式来源可完整核同的实际M。核实际登记名/固定三参数规格/来源根/启用及结构一致；不得只比较`s.方法节点==请求M`而拒绝合法实例，也不得只按相同字符串收纳陌生M。方法实例资格仍受W3既有采用/安全门约束，本叶不放宽上游方法资格。当前M缺结构/来源环属于工程故障，不当成false。

建立任务provider顺序：

1. 在runtime锁下确认未关闭、已初始化、请求M由本工厂覆盖，登记source=X活动租约（同X最多一个）；释放runtime锁。
2. 经task公开`获取执行实例/获取任务/读取执行本能采用`读回真实T/X：X执行中、未结束、无既有普通动作A，T执行中且最近X/M正是该组；采用来源/参数绑定/任务成员/冻结分支与请求完全一致。不得裸查L1猜X，不调用direct K查询。
3. 用实际M和绑定经方法owner建立只读scene并核参数/分支，位置H/F/Em按既有正常合同。动作主体仍取现初始化唯一self，动作场景用现场景owner定位其所属正式场景；这仅是动作记录定位，不附加self与H/Em同场景业务门。
4. 生成本次shared provider，保存来源类别“任务X”、真实T、M、X及显式动作记录元信息。构造失败撤销本次活动来源计数，不能留阻塞close的租约。

fresh X当前位在工厂调用前后发生变化：不生成A；让W3以现有`复核执行本能输入`确定定位/条件已变化并恢复零动作。为避免把工程拒绝伪装条件不足，工厂对已不在当前位可抛现内部专属`前提变化`异常，由W3只在**正式task重新读回证明确已变化且仍零动作**时按现路径收口；其它异常不得吞掉。该异常类型在`本能需求.运行接口.h`新增`struct 新本能需求任务前提变化 final {};`，只表达正式X前提漂移，不是业务结果/学习样本。

同provider仍保持A前可读取/复核，A后禁止从核心首入口再次执行的工程保护。已带A的X不得重建新provider；不能用另建K/X掩盖旧A。direct K工厂原fresh约束和准确参数核验不变，来源类别必须在外层构造时固定，不由工具猜。

## 3. W3注入、动作和锁边界

现W3在发布X前已建立未注入scene并核验作用范围/冻结方案，该步骤保留。X成功创建后、`准备执行问题材料`及真实调用之前增加外层注入：

1. 读取工厂快照；空端口时其它方法保持现流程，新需求本能的缺provider仍是明确工程装配错误，不能回到固定现实端口。
2. 锁外`支持任务方法(实际M)`；支持时按同M/X/完整绑定/分支取得shared provider，然后再次调用现`方法服务_.建立参数场景`，保留this治理读取、服务要求材料读取（按provider所需合法owner）、任务成员绑定及执行分支，并在最后参数位置传provider。现M/绑定不变，不更改实参或来源。
3. 建立后的scene替换本次局部scene；不得写回Vm或Vt。随后按现路径fresh核验场景批、需求来源语义、执行输入及作用范围再执行；未动作漂移走现`恢复零动作`，provider在局部释放后租约计数归零。工程构造失败保留已发布X并终止受影响调用，不谎报X未存在。

因为重建scene需要服务要求读取接口，runtime工厂可用现`建立执行参数场景`不能套directK；本叶在工厂接口补充纯构造方法避免task取得具体reader：

```cpp
virtual 新方法参数场景结果 建立任务参数场景(
    const 新本能需求任务参数请求&,
    const 新内部治理对象读取接口* 治理对象读取,
    std::optional<新方法任务成员绑定> 任务成员绑定)=0;
```

该方法由runtime先调用上述`建立任务参数操作提供者`，再用自身已合法装配的材料reader和请求M/绑定/分支、显式治理owner/任务成员调用现方法owner工厂。task调用它不重复另建provider；公开provider方法供构造组合复用，不能为同X连调两次获取两租约。所有调用均在task锁外。新增返回类型`新方法参数场景结果`只在接口头forward声明，定义在现方法owner头；方法场景与工厂生命周期不反向持有task。

动作开始时，外层provider按已固定来源类别分派：

- direct K：继续原方法owner`绑定直接调用动作(K,A)`。
- task X：世界owner先建立真实A（主体self、定义实际M、来源X、目标H/F），随后经task公开`记录本能动作身份(T,X,A,动态服务)`正式关联；接收`已修改/精确重复`，其它结果工程中止并保留真实A。不得把X交给direct API，不把task来源写成K。

业务材料读取/复核仍只沿scene引用，不读X/T/K；X核验、一次动作记录和取消属外层工程治理。任务源A记录允许W3返回后按同A再幂等核验，不能生成第二A。发布H.F保持publisher原fresh CAS/两阶段D→F，不承诺跨owner全程原子。

临近X资格检查由W3沿现`复核执行本能输入(X,scene)`完成，工厂可复用这一公开检查核构造时资格，不先调用核心。provider不新增要求核心处理X漂移的分支。若A已建立后task动作关联发现身份变化，必须保留A并走工程记录失败路径，不能再声称零动作。原一次动作入口守卫沿现task记录入口合同，不凭TLS冒充业务授权。

## 4. app装配及close

app唯一持有shared runtime，构造注入其实际task owner；新需求初始化、空登记scene生成M及完整读回后，配置task工厂为该runtime。配置失败使本次装配明确失败，不报告已接入。不恢复旧服务需求runtime/旧M，不加初始化主动学习。

在`普通应用上下文`新增RAII清理器：成员声明在runtime之后、self/manager线程之前，保存task引用及runtime shared成员引用；逆序析构保证self/manager及worker已join后执行`卸载本能需求任务参数工厂(*runtime)`，再`runtime->关闭()`。删除析构体原在有界等待后立即关闭新需求runtime的一行，避免将等待超时当join完成；其它对象/连接已有生命周期不改。初始化中途失败runtime为空或未绑定时清理器只做已发生绑定的精确回收，不误关他人端口；需保存本app是否成功绑定bool，默认为false。runtime provider共享租约保活，close拒新且等待活动租约归零。

不增加root-owned task↔runtime shared环，工厂raw指针不跨owner销毁。所有任务W3及新provider停止/销毁均在runtime和task owner销毁前完成。不得为避免等待泄漏provider或提前强制销毁。显式stop无测试授权不运行，不改停止语义。
