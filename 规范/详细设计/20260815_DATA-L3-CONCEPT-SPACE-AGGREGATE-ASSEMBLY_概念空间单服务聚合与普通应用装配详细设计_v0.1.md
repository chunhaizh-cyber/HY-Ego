# DATA-L3 概念空间单服务聚合与普通应用装配详细设计

身份：`DATA-L3-CONCEPT-SPACE-AGGREGATE-ASSEMBLY`

版本：v0.1

日期：2026-08-15

状态：设计就绪、待激活；只有 C1 正式结果满足且共享装配文件释放后方可施工

## 1. 目标与完成边界

建立唯一 `L2概念结构聚合服务`，让普通应用上下文持有唯一 `L2概念结构服务` 和一份只引用该实例的概念空间聚合，并只向调用方公开 const / non-const `取得L2概念结构聚合服务()`。

本叶完成后只成立：

```text
普通应用唯一 L1 运行包
-> 唯一概念 owner 交付
-> 唯一 L2概念结构服务
-> 唯一 L2概念结构聚合服务
-> 普通应用 const / non-const 聚合 getter
-> 聚合 const / non-const C1 同实例 getter
```

聚合没有 owner、写端口、锁、缓存、DTO 映射、通用查询或世界结构转发。普通应用不增加直接 C1 getter；BIZ 只能经聚合取得 C1。

本叶不建立四个本体根，不接线 BIZ 阶段 18，不实现普通概念、语言、词条、名称或世界树聚合，也不改变现有六类世界结构服务及其 `L2结构聚合服务`。

## 4. 唯一聚合模块

新文件：`海中鱼巣/领域/服务.L2概念结构聚合.ixx`。

模块名：

```cpp
export module 海中鱼巣.领域.服务.L2概念结构聚合;
```

唯一公开类逐字为：

```cpp
export namespace 海中鱼巣 {

class L2概念结构聚合服务 final {
public:
    explicit L2概念结构聚合服务(L2概念结构服务& 概念结构服务) noexcept
        : 概念结构服务_(概念结构服务) {}

    L2概念结构聚合服务() = delete;
    L2概念结构聚合服务(const L2概念结构聚合服务&) = delete;
    L2概念结构聚合服务& operator=(const L2概念结构聚合服务&) = delete;
    L2概念结构聚合服务(L2概念结构聚合服务&&) = delete;
    L2概念结构聚合服务& operator=(L2概念结构聚合服务&&) = delete;

    L2概念结构服务& 取得L2概念结构服务() noexcept {
        return 概念结构服务_;
    }
    const L2概念结构服务& 取得L2概念结构服务() const noexcept {
        return 概念结构服务_;
    }

private:
    L2概念结构服务& 概念结构服务_;
};

}
```

该模块只 import `海中鱼巣.领域.服务.L2概念结构`。不得 import L1、六类世界服务、BIZ、材料、语言或名称服务。

## 5. 普通应用唯一装配

`普通应用上下文` 增加并按下列顺序声明：

```cpp
std::unique_ptr<L2概念结构服务> 概念服务_;
std::unique_ptr<L2概念结构聚合服务> 概念聚合服务_;
```

聚合成员必须声明在服务成员之后，使析构时聚合先于被引用服务销毁。上下文私有构造函数增加两份右值 `unique_ptr` 参数并按同序移动保存。

上下文只新增：

```cpp
L2概念结构聚合服务& 取得L2概念结构聚合服务() noexcept;
const L2概念结构聚合服务& 取得L2概念结构聚合服务() const noexcept;
```

不得新增 `取得L2概念结构服务()`、optional / pointer getter、第二聚合、统一服务查找或按枚举选服务入口。

`构造普通应用上下文` 在现有六类世界服务和世界结构聚合成功后，按以下顺序施工：

1. 经同一 `运行包.所有者范围签发器()` 以 `概念所有者建立身份` 建立独占 owner；
2. 只接受 L1 `成功 / 精确重复`、完整 owner 事实和有效写端口，否则返回状态 24；
3. 调用 `尝试形成L2概念所有者交付(运行包.读取服务(), std::move(原始交付))`，失败返回状态 25；
4. `make_unique<L2概念结构服务>(运行包.读取服务(), std::move(*概念交付))`，构造异常返回状态 26；
5. `make_unique<L2概念结构聚合服务>(*概念服务)`，分配 / 构造异常返回状态 27；
6. 将概念服务和概念聚合随既有服务一起移动进入上下文，只有全部完成才返回 `已装配`。

普通应用装配状态追加：

```cpp
概念所有者范围建立失败 = 24,
概念所有者交付形成失败 = 25,
概念服务构造失败 = 26,
L2概念结构聚合服务构造失败 = 27
```

失败候选依赖 RAII 释放已形成的服务和端口；不发布默认 C1、不返回半上下文、不缓存构造错误、不把缺少 C1 表达为阶段 18 运行结果。

## 7. 并发、生命周期与失败

- 聚合没有自己的并发状态；所有调用直接落到唯一 C1。
- 上下文、C1 和聚合均不可复制 / 移动，引用地址在上下文生命周期内稳定。
- 聚合不延长 C1 生命周期，普通应用成员顺序保证引用先失效、服务后销毁。
- owner 建立、交付形成和 C1 构造失败均使普通应用装配失败；不得退化为无概念能力的“成功上下文”。
- C1 运行结果、根不存在或根操作失败不属于装配失败，由后继合法消费者按 C1 结构化结果处理。
- 聚合分配异常只映射状态 27；不增加 DATA 运行状态、日志判定或重试循环。

## 8. 施工检查

本叶不建立独立验收、临时专项或生产 seam。施工只执行与风险相称的必要检查：

1. 根工程 x64 Debug / Release fresh Rebuild；
2. 工程 / filters 唯一登记、四配置 `/utf-8`、XML 可解析；
3. 静态证明聚合恰一引用、零 owner / 写 / 锁 / 缓存 / DTO 映射；
4. 静态证明普通应用恰一 C1 `unique_ptr`、恰一概念聚合 `unique_ptr`、成员析构顺序正确；
5. const / non-const 两级 getter 返回引用且 `noexcept`，没有直接 C1 getter；
6. 状态 0—23 不变，24—27 唯一连续；
7. strict、UTF-8、diff、白名单和生产零测试 / 自检 / 验收 / 注入痕迹。

真实普通应用运行、BIZ 阶段 18、四根建立、资源耗尽、恢复、跨进程和集成验收保持 `NOT_RUN`。聚合是否满足消费者，由后继实际使用经正式 getter 和 C1 结构化读回判断。
