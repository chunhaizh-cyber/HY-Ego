# INSTINCT-STAGE3-GSEED-ACTIVATION-CURSOR-COMPAT-MIGRATION Gseed 显式激活与维护游标兼容迁移详细设计 v0.1

代码事实基线：`4477a44e7bf9fe7a9ec4c9294f0ed1a6bb7fa708`

## 1. 目标与完成边界

本叶把 6170 的新维护纪元激活落实为一条可机械实现的安全边界：

```text
A：新格式权威事实明确证明从未成功维护
   -> 允许显式建立新维护纪元
B：新格式权威事实证明已有成功维护
   -> 禁止重置；本叶结构化 fail-closed，三水位不动
U：v1/v2/v3 旧格式或坏格式无法证明成功维护历史
   -> 结构化 fail-closed，三水位不动
```

本叶只实现 A 的生产激活、持久恢复、独立读回，以及 B/U 的结构化拒绝。B 的完整迁移依赖尚未冻结的五类服务事实正式秒序，不能在本叶实现或宣称完成。

## 2. 正式依据与当前差异

依据：0050、6170 第 503—528 行、服务历史边界快照 v0.2、INSTINCT-ROUTE v0.4。

当前代码事实：

1. `本能被动维护游标事实_v3` 只有三水位、运行 / 时间纪元和版本，没有维护纪元身份或成功维护提交事实；
2. `建立或恢复本能被动维护游标_v3` 会把 v1/v2 直接迁移并把服务水位设到旧覆盖起点，不能证明是否跳过成功维护后的未消费历史；
3. 普通启动仍读取 v1 覆盖起点并自动调用 v3 建立入口；
4. 当前没有成功维护提交入口，不能从游标存在、水位、形成代次、日志或调用历史反推零成功；
5. v2 服务历史边界公开入口已能返回 `v2覆盖登记事实代次`、`Gstart/G0` 和完整快照。

复用裁决：复用既有游标 owner、当前游标槽、L1 中性原子写集、v2 边界快照、主动安全永久账登记见证和现有独立读回。新增 v4 强类型合同；不新建第二 owner、第二游标槽或认知事实。

## 4. v4 权威事实与 DTO

```cpp
inline constexpr std::uint32_t 本能被动维护游标合同版本_v4 = 4;
inline constexpr std::uint32_t 本能被动维护纪元激活合同版本_v1 = 1;

struct 本能被动维护游标事实_v4 final {
    L2存在身份 自我{};
    std::uint64_t 运行代次 = 0;
    std::uint64_t 时间纪元身份 = 0;
    std::uint64_t 维护纪元身份 = 0;
    std::int64_t 上一已维护完整秒边界 = 0;
    std::uint64_t 已消费主动安全变化事实代次 = 0;
    std::uint64_t 已消费服务维护历史事实代次 = 0;
    std::uint64_t 服务历史v2覆盖种子事实代次 = 0;
    std::uint64_t 成功维护提交序号 = 0;
    std::uint32_t 时间源版本 = 0;
    std::uint32_t 服务时间维护规则版本 = 0;
    std::uint64_t 形成事实代次 = 0;
};
```

完整性：身份 / 版本 / 两个事实水位 / `Gseed` / 形成代次非零，完整秒非负；服务水位不得小于 `Gseed`。`成功维护提交序号 == 0` 明确表示从未成功维护；大于零时，该 v4 事实必须由未来成功维护原子提交形成，其 `形成事实代次` 是最近成功维护提交代次。旧 6/7/8 项材料不含该字段，绝不解释为零。

同一既有当前游标 U64 组槽使用 11 项持久材料（`形成事实代次` 由值事实创建代次取得）：

```text
self, 运行代次, 时间纪元, 维护纪元,
完整秒水位, 主动安全水位, 服务历史水位, Gseed,
成功维护提交序号, 时间源版本, 维护规则版本
```

维护纪元身份固定等于首次成功激活请求的 `幂等身份.值`；不是运行代次或时间纪元的别名。相同激活语义跨重启恢复同一维护纪元，不重新生成随机身份。

### 4.1 激活请求

```cpp
struct 显式激活或恢复本能被动维护纪元请求_v1 final {
    std::uint32_t 合同版本 = 本能被动维护纪元激活合同版本_v1;
    L2结构请求头 请求头{};                // G0
    L2结构幂等身份 幂等身份{};            // 同时提供新维护纪元身份
    本能根运行锚点_v1 本能根锚点{};
    std::uint64_t 运行代次 = 0;
    std::uint64_t 时间纪元身份 = 0;
    std::int64_t 当前完整秒边界 = 0;
    L2特征当前值变化账登记结果_v2 主动安全变化账登记见证{};
    服务维护历史边界读取结果_v2 服务历史v2边界见证{};
    std::uint32_t 时间源版本 = 0;
    std::uint32_t 服务时间维护规则版本 = 0;

```

服务历史见证必须成功，绑定同一 self/G0，且快照 `左边界事实代次 == 包含结束事实代次 == G0`；其中 `v2覆盖登记事实代次` 是唯一 `Gseed`。调用方可先以 `Gstart=G0` 读取 v2 边界快照；预算只限制实际成员，不按预算预分配或循环。

v4 读取遇到无游标返回`未建立`；遇到 6/7/8 项旧格式返回`旧格式待裁决`且零 v4 载荷；坏长度、坏版本、部分值或多当前槽返回引用冲突 / 内部错误，不降级成未建立。

既有 v1/v2/v3 读取 ABI 对 11 项 v4 当前事实继续提供只读兼容投影：v1 投影 self、运行 / 时间纪元、完整秒和两个版本；v2 再投影主动安全水位；v3 再投影服务历史水位；三者的形成代次均取 v4 值事实创建代次。旧投影不暴露维护纪元、`Gseed` 或成功维护序号，因此只能服务旧只读消费者，绝不能被激活入口用来证明 A/B。

## 5. 唯一分支与事务

### 5.1 A：首次激活

只在 owner 登记完整、当前游标槽从未产生过任何值，且不存在旧 v1/v2/v3 或坏格式材料时成立。不能把“当前值缺失”单独当作从未建立；首次写入历史、当前槽和 owner 定位必须共同证明这是全新实例：

```text
G0 读前守卫和锚点绑定
-> 验证主动安全登记见证与 v2 边界见证
-> 目标完整秒 = 请求当前完整秒
-> 目标主动安全水位 = 主动安全永久账首次登记代次
-> 目标服务历史水位 = Gseed
-> 维护纪元身份 = 幂等身份值
-> 成功维护提交序号 = 0
-> 一个 L1 owner 中性写集切换当前游标槽
-> v4 独立读回、G0 读后守卫
```

该提交只写游标 owner；A/V 当前值、状态、动态和其它 owner 写集必须为零。`Gseed` 前区间通过激活见证明示不补算，不伪装为空。

已存在 v4 且序号为 0 时，只允许同一维护纪元的同义恢复 / 精确重复；请求不同维护纪元不自动重置。若未来确需在首次成功维护前改换时间纪元，必须另有正式设计，不由执行者临场扩张。

### 5.2 B：已有成功维护

读取到完整 v4 且`成功维护提交序号 > 0`时固定返回`已有成功维护需完整迁移`。不得写入，不得改变完整秒、主动安全或服务历史水位。因正式秒序尚未闭合，本叶不设计迁移算法。

### 5.3 U：旧格式或证明缺失

当前槽为 v1/v2/v3、字段缺失、旧格式部分恢复或无法唯一解码时固定返回`旧格式成功维护历史不可证明`或更强结构错误。不得从水位等于登记起点、值为零、形成代次较新或当前运行首次启动推断 A。

### 5.4 幂等、漂移与已可能发布

1. 同键同规范材料：首次写集收敛，返回精确重复并读回原形成代次；
2. 同键异义：幂等冲突，零写；
3. 异键同义且当前 v4 完全相等：已恢复，不建立第二事实；
4. self/G0/锚点/登记见证/边界见证/时间版本任一漂移：结构化非成功；
5. `Gseed` 与当前 v4 记录不等：覆盖种子漂移，零写；
6. 提交返回不确定或提交后读回不闭合：已可能发布；调用方以同键首次写集和 v4 独立读回收束，不换键重试；
7. 进程恢复只接受首次规范写集、当前槽和 v4 解码逐项一致；部分发布、双当前或旧格式不得修补。

## 6. 生产装配

启动中删除“读取 v1 覆盖起点 + 自动建立 v3”的生产路径，改为：

```text
读取 G0、主动安全登记见证和当前完整秒
-> 以 Gstart=G0 读取服务历史 v2 边界完整快照
-> 调用显式激活 v1
-> 只接受已激活 / 已恢复 / 精确重复
-> 独立读取 v4 并逐字段绑定
-> B/U 或任一非成功：启动初始化失败，保留原事实
```

本叶不保留 v3 自动回落，不调用秒序 composer，不发布 A/V。

## 7. 验证矩阵

1. 全新实例 A 激活：三水位分别为当前完整秒、主动安全登记起点、`Gseed`，成功序号 0；
2. A/V、状态、动态和服务历史 owner 零写；
3. `Gseed` 前放弃边界等于 `Gseed`，不得以空组替代；
4. v1/v2/v3 各返回旧格式证明缺失且原值逐字段不动；
5. v4 成功序号 1/N 返回需完整迁移且三水位不动；
6. 同键精确重复、同键异义、异键同义恢复；
7. G0 读前 / 读中 / 读后漂移，self、锚点、时间、规则、Gseed 漂移；
8. 已可能发布后同键收束；
9. 进程重启后 v4 事实、维护纪元、成功序号和放弃边界逐字段恢复；
10. 坏长度、部分 v4、双当前、旧格式坏载荷 fail-closed；
11. 普通启动合法 A 成功，B/U 结构化初始化失败且无覆盖；
12. v4 当前事实对既有 v1/v2/v3 读取提供字段受限兼容投影，但生产启动不再调用旧迁移；
13. Debug / Release、外部 ABI consumer、定向 diff-check、strict；
14. 静态确认无秒序后继、无 A/V 写入、无第二 owner、无计划索引变化。
