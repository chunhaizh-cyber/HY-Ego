# SELF-THREAD-M1A-UPPER-SHELL 自我线程上层身份与配置修订详细设计

版本：v0.2

日期：20260923

状态：正式详细设计；替代同主题 v0.1 的当前施工解释，不追改其历史实现证据
对应目标：`GOAL-INSTINCT-ROOT-RUNTIME-PRODUCTION-CONSUMER-DESIGN`

## 1. 目的与完成边界

本设计按5260 v0.7、8100 v1.13、8110 v0.4、8120 v0.17和8200 v2.0校正已经发布的 self 隔离上层骨架。它只冻结后继代码计划必须采用的身份、DTO、邮箱、等待和停止合同，不在本文实现代码。

本次修订后的核心边界是：

```text
世界树正式存在 E
    = self 唯一业务身份
    -> 自我线程只作该 E 的进程内执行载体
    -> 不再建立 self 逻辑身份
    -> 不再记录 self 运行代次
```

任务、任务轮次、筹办轮次、执行轮次、工作包、消息和原请求仍保留各自强类型身份。删除 self 的第二身份不允许把这些业务身份压成 `E`、裸整数、线程 ID 或时间。

完成本设计与后继代码计划只证明施工合同已闭合；不证明阶段20生产接线、治理门开放、根需求复核、持续治理、构建、运行恢复或集成验收完成。

## 2. 当前事实与迁移裁决

当前 `线程_自我.h/.cpp` 已有单对象一次性创建、关闭治理门、受锁有界邮箱、独立停止信号、等待完成和 `join`。当前公开 DTO 同时含 `自我线程逻辑身份`、`自我线程运行代次`，并把两组读取预算放入创建请求；这些字段与现行正式规范冲突，必须原位校正。

当前骨架尚未登记根工程且没有生产消费者，因而后继计划直接修订现有 `_v1`，不保留伪兼容字段、不增加版本桥接层、不新增第二创建入口。枚举的已发布数值不重排；已删除的操作状态数值8保留空洞。

旧 v0.1 中下列口径退出当前施工资格：

- self 逻辑身份与运行代次类型及全部字段；
- 以运行代次参与创建选择、邮箱去重、迟到消息拒绝和端口回返校验；
- 创建请求内的上下文读取预算和根复核读取预算；
- 重启时建立新运行代次；
- 以运行代次证明旧工作不再当前。

## 4. 身份和公开 DTO

### 4.1 删除的类型和状态

从 `线程_自我.h/.cpp` 删除：

```cpp
自我线程逻辑身份
自我线程运行代次
```

从 `自我线程操作状态` 删除 `运行代次不匹配`，但不复用数值8：

```cpp
成功=1, 精确重复=2, 入口拒绝=3, 选择冲突=4,
依赖未就绪=5, 队列已满=6, 消息冲突=7,
// 8 退役，不复用
等待超时=9, 资源失败=10, 内部错误=11
```

### 4.2 创建请求

`自我线程创建请求_v1`精确收敛为：

```cpp
struct 自我线程创建请求_v1 final {
    std::uint32_t 合同版本 = 自我线程合同版本_v1;
    std::uint64_t 邮箱容量 = 0;
    自我线程世界启动材料_v1 世界;
    自我线程自我启动材料_v1 自我;
    自我线程本能根启动材料_v1 本能根;
};
```

`邮箱容量`由普通应用具名运行配置提供，是本次物理对象的工程配置，不是 self 身份、业务事实、持久恢复材料或治理消息。它参与同一对象重复创建的配置相等判断；不同容量请求属于选择冲突。创建等待和失败回收等待作为调用参数从同一具名配置传入，不进入请求和选择。

完整性固定为：合同版本正确、容量非零、三份启动材料完整、世界身份相等、世界根场景等于 self 所在场景、根锚点 self 等于正式 self `E`、本能根 `Gread` 不早于世界和 self 的读回截止。

### 4.3 停门见证

`自我线程停门见证_v1`只保留：

```cpp
入口序号
停门序号
治理运行门开启
已冻结批次数量
```

完整见证要求入口序号非零、停门序号严格大于入口序号、运行门关闭、冻结批次为零。见证不复制 `E`；调用方以锁定创建请求中的正式 `E` 和同一对象租约证明对象归属。

### 4.4 正式上下文和根复核请求

`自我线程正式上下文请求_v1`删除运行代次和逻辑身份，只保留：

```cpp
合同版本
锁定世界
锁定自我
锁定本能根
本次上下文读取预算
```

`自我线程根需求复核请求_v1`删除运行代次和逻辑身份，只保留：

```cpp
合同版本
正式上下文投影
触发根
正式需求定位
来源消息
原请求
本次根复核读取预算
```

两种预算仍是对应 provider 单次调用的覆盖控制，不属于 self 创建选择、普通应用线程运行配置或持久业务材料；只有真实调用发生时，调用该 provider 的设计才为本次请求明确给出预算。

### 4.5 邮箱消息

`自我线程根需求复核消息_v1`删除运行代次，只保留：

```cpp
合同版本
不可变消息身份
原请求身份
触发根
正式需求定位
```

消息只定位 fresh 读取，不携带当前值、满足结论、业务结果或线程身份。双根触发要求正式需求定位为空；单根触发要求需求定位等于锁定锚点中的相应根需求。

## 5. 单对象生命周期和创建选择

`自我线程`仍是一次性物理租约。首次合法创建尝试后，无论成功、启动失败、内部错误或停止完成，都不得在同一对象上建立第二物理线程。

创建选择仅比较：

```text
合同版本
+ 邮箱容量
+ 世界启动材料
+ self启动材料（其中self即E）
+ 本能根启动材料
```

同选择且停门见证完整时返回精确重复；异选择返回选择冲突；停止已锁存或线程已完成后返回入口拒绝。读取预算和等待时限不参与创建选择，允许调用方在不改变锁定对象的前提下采用新的调用预算或诊断等待值。

## 6. 邮箱去重、消息消费与迟到材料

单个 self 对象内，邮箱和当前处理项以 `自我线程消息身份` 为唯一工程去重键：

- 同消息身份且完整正文相同：精确重复；
- 同消息身份但正文不同：消息冲突；
- 新消息身份且邮箱已满：队列已满；
- 新消息身份且结构完整：入队并唤醒。

原请求身份属于消息正文和后续业务定位，不取代消息身份。消息处理完成后不建立持久处理账；重启不恢复内存邮箱。迟到或重复材料进入新进程时，只能按消息 / 原请求及分支业务身份重新定位正式事实，由 owner 的幂等和当前性合同收敛，不能依赖旧线程代次。

## 7. 端口调用和锁边界

持有 self 内部互斥时禁止调用 provider、日志、数据库、文件或用户回调。调用外部端口前复制最小值式请求并释放锁；返回后重新加锁时只核对：

```text
停止是否已锁存
+ 内部错误是否已锁存
+ 当前处理消息身份是否仍相同
+ 锁定 self E 是否仍等于请求 / 返回所定位的 E
```

不得恢复运行代次或逻辑线程身份校验。provider 非成功、当前性漂移、引用冲突、不可比较、资源失败和内部错误均不得开放治理运行门，也不得伪造根需求结论。

## 8. 等待、停止和析构

创建停门等待、开放门等待和停止回收等待均由调用方显式传入；普通应用生产调用只能从具名运行配置取得，不能使用散落裸常量。等待超时是工程诊断结果，不改变业务事实，也不得自动 detach。

停止固定使用独立进程内控制信号并与邮箱共享唤醒条件：

```text
锁存停止
-> 唤醒停门 / 邮箱 / provider等待边界
-> 工作线程形成完成见证
-> 调用方等待完成
-> join
```

析构必须无条件锁存停止并最终 `join`；禁止 detach、覆盖 joinable 线程、释放其依赖后再回收线程，或用等待超时伪装安全返回。

## 9. 8110 生命周期投影适配

一般线程可以由8110使用纯进程内会话身份形成只读投影。self 不新增该身份；self 生命周期适配器直接把正式世界树 `E` 作为投影定位引用，并可附带系统线程 ID 作为诊断绑定。

该适配器不得把生命周期投影送入 self 治理邮箱，不得把 `E` 解释为线程运行代次，也不得用投影状态裁决需求、任务、动作、结算或恢复。
