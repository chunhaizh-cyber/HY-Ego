# 语言词条与独立概念空间结构 CRUD 详细设计 v0.2

日期：2026-08-12

设计身份：`CONCEPT-SPACE-STRUCTURE-CRUD-REBUILD`

状态：设计完成；不等于代码实施完成

## 1. 目标和边界

在现有唯一 L1 事实基座和六类世界结构服务之外，增加一条正交的数据结构链：

```text
不可变材料
-> 语言 / 正式词性 / 词条
-> 概念身份 / 维度根 / 抽象签名
-> 维度内上下位 DAG 与定义约束
-> 世界事实支持概念
-> 概念名称关系
-> 生命周期、不可逆退出和可重建投影
-> 独立透明聚合与普通应用装配
-> 旧语素 / 旧概念模型清理
```

本设计不改变 4230 六类世界服务，不把概念并入 `L2结构聚合服务`，不实现分词、抽象、归类、同义判断、命名接受或语境消歧，不修改当前 DYN2 / C1 / C2 / S-ID / A1 施工顺序。

设计包和九个分叶计划可以全部先设计并登记；其状态按真实依赖保持 `待激活`。只有实施结果进入正式 Git、计划退出并满足下一叶 ABI 门禁后，下一叶才可被重新激活。设计完成不得表述为材料、语言或概念代码已实现。

### 1.1 与六类世界结构路线的整合门禁

今天交互智能体（2）的对话只作为设计输入；经 2220、4240、当前六类世界计划和真实代码重新裁决后，全局代码施工顺序冻结为：

```text
DYN2 动态换代退出
-> 世界 C1 因果新增查询
-> 世界 C2 因果换代退出
-> S-ID 场景身份来源迁移
-> 世界 A1 六服务聚合与唯一生产装配
-> 世界 A1 临时验证源码独立清理
-> 世界 A1 正式入口独立集成验收
-> CONCEPT-M1 不可变材料
-> CONCEPT-L1 语言 / 词性 / 词条
-> CONCEPT-C1 概念身份 / 维度根 / 签名
-> CONCEPT-C2 维度内多父 DAG / 定义约束
-> CONCEPT-C3 世界事实支持概念
   + CONCEPT-N1 概念名称关系
-> CONCEPT-C4 生命周期 / 退出 / 投影
-> CONCEPT-A1 语言概念透明聚合与唯一生产装配
-> CONCEPT-D1 旧语素概念枚举闭包清理
-> 语言概念服务独立集成验收
```

`CONCEPT-C3` 与 `CONCEPT-N1` 在 C2 后不存在彼此机器依赖，设计可以并行闭合；代码仍受唯一活动施工段约束，一次只实施一叶。C4 必须等待二者真实结果。任一概念叶都不得越过世界 A1 的清理和独立集成验收门禁，也不得因 M1 只直接依赖 L1 就提前抢占普通应用、根工程、构建或验证资源。

世界 A1 与 CONCEPT-A1 是两个并列的零写入聚合：前者只引用场景、存在、特征、状态、动态、因果六服务；后者只引用材料、语言、概念、概念名称四服务。二者不互相包含，不复制 CRUD，不形成全数据层中央门面。世界 A1 独立验收只证明六类世界结构聚合；CONCEPT-A1 独立验收只证明语言概念结构聚合。两项都不能证明抽象、识别、归类、词性判断或语境消歧业务完成。

### 1.2 对话裁决的保留与排除

本设计只保留已被正式规范和当前事实支持的最终口径：

- 概念具有独立身份；每个正式词性选择一个独立概念维度根，同维度按多父 DAG 组织；
- 世界事实不复制为概念节点，只通过“世界事实支持概念”关系成为叶级引用；
- 词面是不可变值材料，词条是“语言 + 规范化合同 + 规范化词面”的最小稳定身份；概念通过首选名称 / 别名 / 简称关系直接引用词条；词索引只作可重建加速；
- L1 当前已有“属性类型节点 + 值表示种类 + 原始值材料”三层合同，本路线不得再增加第二套业务值类型字段；词面经不可变材料身份承载；
- 未来若把世界、语言或概念拆成多个物理存储分区，必须保持统一 L1 合同、全局稳定编码、事实截止和跨分区引用校验，高层服务及本路线 DTO 不得感知物理分库；本路线不实施分库。

以下早期对话说法已被后续裁决替代，不得进入实施：概念复用存在身份、每个世界实例创建时同步新建概念、词性直接建立或唯一选择概念、词索引成为名称关系权威、把语言概念加入六服务 A1、复用旧语素入口或历史概念图代码。

## 6. 分叶函数合同

### 6.1 M1 不可变材料

公开函数：

```cpp
不可变材料写入结果 写入不可变材料(const 不可变材料写入请求& 请求);
不可变材料读取结果 读取不可变材料(const 不可变材料读取请求& 请求) const;
不可变材料退出结果 退出不可变材料(const 不可变材料退出请求& 请求);
```

写请求包含共同头、幂等身份、格式、调用方提供的隔离候选路径、字节长度、SHA-256、来源。服务在允许材料根下生成最终物理位置，拒绝越界路径；复读候选后以原子替换发布文件，再在 L1 发布材料节点和摘要 / 长度 / 格式 / 来源值。任何候选失败不产生 L1 事实；L1 发布后文件异常为内部不一致，不以日志补成功。退出只退出 L1 当前引用，仍被值事实引用时冲突；物理回收另由维护策略处理。

### 6.2 L1 语言 / 词性 / 词条

公开函数按三族固定：

```cpp
读取语言身份来源 / 读取词性身份来源 / 读取词条身份来源
新增语言 / 读取完整语言 / 退出语言
新增正式词性 / 读取完整词性 / 按语言读取全部当前词性 / 退出正式词性
新增词条 / 读取完整词条 / 按规范键读取词条 / 退出词条
重建当前词索引
```

语言和词性正式键使用非零 `稳定编码`，由上层登记合同解释。词条创建先在同截止读回语言、规范化合同材料和词面材料；词面材料必须为登记的严格 UTF-8 格式。词条 owner 写集建立节点、归属、语言关系和两个材料关系。规范键查找必须回源校验，索引可清空重建。

### 6.3 C1 概念身份、根和签名

公开函数：

```cpp
读取概念身份来源
建立概念维度根
新增概念
读取完整概念
按词性读取概念维度根
按完整签名读取当前概念
```

维度根写集建立概念节点、归属、词性维度关系、永久活跃生命周期和固定根角色；重复按词性精确读回。普通概念写集建立节点、归属、维度 / 词性关系、签名值、定义关系、至少一条上位关系和活跃生命周期。C1 只允许初始上位 / 定义，后续改变由 C2；签名、词性和维度不可换代。

### 6.4 C2 DAG 与定义约束

公开函数：

```cpp
替换概念直接上位组
替换概念定义约束组
读取概念直接上位组 / 直接下位组
读取概念祖先投影 / 后代投影
```

上位整组替换在提交前以当前图模拟，拒绝自环、跨维度、成环和根不可达；多父合法。定义目标逐项经闭合类型对应公开服务验证。替换退出旧直接边并建立新直接边；投影按概念身份稳定排序，不持久化。

### 6.5 C3 世界事实支持

公开函数：

```cpp
建立世界事实支持概念
退出世界事实支持概念
按世界事实读取当前支持概念组
按概念读取当前支持世界事实组
读取世界事实支持历史
```

端点按 variant 分派到对应公开服务；不得直达 L1 重演身份。支持关系由概念 owner 写入，多对多、跨维度合法；同对当前唯一。返回按“类别、端点稳定键、关系编码”排序。

### 6.6 N1 概念名称

公开函数：

```cpp
建立概念名称
退出概念名称
按概念读取全部当前名称
按词条和词性读取当前概念候选
重建概念名称反向索引
```

名称服务分别验证概念、词条、语言和词性；词性必须等于概念维度对应词性。首选名称按“概念 + 语言”唯一；其它角色允许多项。候选读取只返回该维度当前概念并稳定排序，不猜选。

### 6.7 C4 生命周期、退出和投影

公开函数：

```cpp
迁移概念生命周期
不可逆退出概念
读取概念生命周期历史
读取概念维度有限展开投影
```

迁移只接受 7140 合法边。退出只接受退役普通概念、零当前支持、零当前名称和零外部引用；在概念 owner 单写集中建立必要替代直接边并退出目标相关当前事实。有限展开请求固定最大深度和最大项目数，超限入口拒绝；结果只作同截止值式投影。

### 6.8 A1 聚合与生产装配

`L2语言概念结构聚合服务` 只保存四个非 owning 引用：材料、语言、概念、概念名称；提供 const / 非 const 一行 getter。普通应用唯一 provider 在既有六服务装配完成后按第 4 节顺序形成六个新 owner 和四服务，再形成聚合。现有 `L2结构聚合服务` 不修改职责和 getter；两个聚合并列持有。

### 6.9 D1 旧模型清理

新聚合和真实消费者发布后，从当前代码事实扫描旧枚举、模块、工程登记、控制面板路由和生成器。仅删除零消费者或已由新接口替代的闭包；无法确定语义的旧材料登记具名缺口，不自动转换。流程图和能力目录由维护智能体按发布代码更新，不在 D1 代码提交内手工改写。

## 7. 事务、错误与并发

每个公开写入口只提交本服务 owner 的一份 L1 写集；跨服务端点只读验证后释放读取，再提交并由期望代次防止竞态。不得跨服务同时持有写端口或内部锁。发布后读回失败不撤销已发布事实，返回内部不一致并允许同幂等请求收敛首次结果。

零身份、坏枚举、坏顺序、坏 UTF-8、错类别、错维度、跨维度上下位、自环 / 成环、根退出为入口拒绝；期望代次变化为事实代次漂移；当前引用未闭合为引用冲突；内部重复根、签名复义、错误 owner / 归属、索引与回源矛盾为内部不一致。

## 8. 验证和完成声明

每叶建立生产工程外的参数验证三文件，结果发布和计划退出后以独立清理提交删除。验证只走该叶公开入口，使用自定义参数，至少包含一个合法写后逐字段读回、一个非法零变化、精确重复、幂等冲突和适用的历史 / 退出路径。概念叶按 4240 增加 DAG、支持、名称和生命周期专项。

M1—C4 的单叶成功只证明该公开结构切片；A1 只证明透明装配；D1 只证明具名旧闭包退出。只有全部结果、独立集成验收和真实上层消费者分别成立时，才能声明语言概念结构链完成；仍不能声明抽象业务、自然语言理解或数字生命业务闭环完成。
