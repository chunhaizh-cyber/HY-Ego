## 1. 目标与裁决

本设计只闭合 G4-A 当前最早缺口：为 4242 二次关系求值建立一条不含底层资源预算、不会截断成功、不会跨 provider 累加物理用量的完整读取链，并实现当前请求材料能够完整证明的 4242 第 7 节 `二次关系求值应用服务`子集。同一代码切片内完成 RC 专属版本 1 ABI 的消费者迁移和物理退出。通用 EC、FC 及子概念组为空的具体 EC 继续真实求值；子概念组非空的具体 EC 在本版结构化返回`规则不支持`，不伪造递归材料。

本设计不实现 G4-A 双根业务复核、根治理意图 sink、治理门开放、4213/4340 业务合同、动态/因果自身读取 ABI、动态概念、因果概念或 4242 第 8 节形成应用。`数据服务.动态类.h`和`业务/计算.二次特征.h`只因它们是 4182 canonical K 读取 ABI 的真实生产消费者而做字段删除后的机械调用迁移；不得改变其 DTO、算法、状态、预算或业务语义。

冻结裁决如下：

1. 完整语义范围只由身份、`Gread/H`、显式来源组、RC 完整规范形及其必要引用闭包定义；任何节点、关系、值、材料、候选、深度或步骤计数均不进入新请求、成功谓词或重试语义。
2. 每个 provider 独立完整返回自己负责的载荷，或返回 `资源失败`并清空依赖完整性的载荷。没有共享读取会话、剩余预算传递或跨服务物理总账。
3. 4015、4180 和 4240 的旧预算 ABI 仍被本设计外消费者占用，本包新增版本 2 完整读取入口并只迁移 G4-A 直接消费者。4182 v0.4 则明确要求旧 canonical K 请求的声明、实现和消费者同次退出，因此本包还机械迁移`动态类.h`和`业务/计算.二次特征.h`中的 K 读取调用；禁止借此修改 4213/4340 或动态/二次特征机器语义。
4. 4242 RC 专属旧预算 ABI 的生产消费者只位于概念树服务、双根 RC 初始化、普通应用装配及两个 RC 专项。本包将它们同次迁移并删除 RC 专属 `二次关系预算`、`二次关系读取用量`、请求预算字段、结果用量字段和共享计量私有重载。
5. 现行存在 `读取当前采用`仍携`关系预算`。4242 已要求“完整当前采用读取”，7150 已固定同 `E+FT` 当前采用为 `0..1` 完整组；本设计只为该既有机器语义补充新的物理 v2 只读入口，不改变存在 owner、写入、基数或生命周期。
6. 4242 要求状态固定准确值中的引用分支经特征类核验和特征值完整材料读取取得 I64，但不要求求值器直接调用特征值服务。4110 又把内联 / 引用准确值的内容同一性归特征结构服务。现行特征服务已经用唯一私有`解析输入(特征准确值,Gread,H)`完成引用值生命周期、完整内容、身份 / 载荷一致性和尾部 G 守卫核验；本包只把该既有解析能力封装成无预算 v2 公开适配，并让原`核验正式特征类型准确值`共享同一解析核心。不得在求值器或特征值服务再实现第二套准确值解析算法。
7. 4242 v0.5 的 EC 请求只携一个参与者 E 及该 E 的一组 F 或 B 来源，没有子 E 身份、父子实例匹配、每个子 E 的独立 F/B 来源或子 B/S 观察材料。7100 又规定具体 EC 的第二组是每个真实子存在自己的概念组，实例结构为`父E -> 子E`且每个 E 独立形成`E -> EC`；父参与者的来源不能证明子参与者。故本版禁止把父参与者来源递归传给子 EC，也禁止临时扩充嵌套参与者 DTO、猜测父子选择或用子 E 当前采用替代父 B 同次观察。非空子概念组只能结构化返回`规则不支持`；完整递归须先由用户裁决并进入正式规范。

起点 HEAD 上：

- 4180 只有`特征值域*请求_v1`、`特征值域比较预算_v1`及共享`概念事实读取会话_v1`路径；

- pure v2 结构读取、存在概念两组读取和 RC 约束读取仍通过概念预算、物理预算或 RC 预算完成；
- 4242 RC 全部结构请求仍为版本 1并携`二次关系预算`，结果携`二次关系读取用量`；

- `业务/计算.二次关系求值.h/.cpp`及`二次关系求值应用服务`不存在；
- 普通应用已拥有 L1、概念、场景/B、状态、存在、特征、特征值和特征值域比较服务，但尚未拥有或公开 RC 求值应用服务。
- 当前只有根工程和三个专项工程直接编译`装配.普通应用.cpp`：根工程、`本能双根二次关系概念初始化专项验证.vcxproj`、`本能根运行生产消费专项验证.vcxproj`、`世界树根启动专项验证.vcxproj`。新增 non-inline `计算.二次关系求值.cpp`后，四个工程都必须登记该源；后两项回归工程若只编译普通应用而不登记求值源，会在链接阶段缺少定义。
- 4182 canonical K 旧读取的真实调用面不仅包括动态、二次特征和双根初始化，还包括`数据服务.概念树类.cpp`的 RC 私有完整性核验、`二次关系概念结构专项验证.cpp`及`本能双根二次关系概念初始化专项验证.cpp`；旧 ABI 物理退出前必须覆盖这些声明、实现和调用点。
- 正式 HEAD 的三类历史候选索引只包含当前或尚保留完整载荷的历史关系 / 属性值；物理清理会从索引删除编码并删除`历史`完整事实，`重建恢复索引`也只从`当前关系 / 当前值 / 历史`重建。因此 v1 既有“候选命中墓碑则返回`历史材料已清理`”分支在清理后和恢复后均可能失去候选，错误退化为空组成功；v2 若沿用该维护方式也不能满足 4015 v2.8。
- 持久权威载荷已保存普通中性 / owner 首次规范化写集、首次发布代次和局部键到稳定编码映射；跨 owner、三分区和有限 N 事务发布时同时形成对应 owner 的同值首次写账。关系组定位可由写集和映射确定性解析，属性候选组定位可由`属性槽变更`及映射确定性解析。物理清理墓碑保存稳定编码、种类、owner、创建 / 退出 / 清理代次。因此无需增加持久字段，只需从普通持久首次账重建“组定位＋是否只剩墓碑”。
- 正式 HEAD 的 L1、状态和动态创建入口只检查幂等身份非零，技术上曾允许调用方使用`0x4E43`创建关系或属性槽值；而持久编码会过滤命中该前缀的中性、owner和原子事务账，墓碑又不含组键。0050 v3.24、4015 v2.8 已裁决该域退出-only：实现必须在中性、owner、跨 owner v1、三分区 v2、有限 N v3 的候选前拒绝任何创建或属性槽变更，从源头保证可清理关系 / 候选值的定位具有普通持久首次账。
- 第二次执行退回中的六个 v2 读取草稿把`状态完整(状态_)`放在共享锁读取前置。该函数检查全库权威表、幂等账和索引，违反上层定义读取范围的正式口径；它只能保留在写入、物理清理和恢复候选的发布门，不能成为六个读取入口的每次调用成本。
- 第五次执行退回现场已有未提交`计算.二次关系求值.h/.cpp`：具体 EC 当前把父参与者`sources`递归传给每个子 EC；固定 K 未找到已映射证据不足、当前 K 零命中已映射规则不支持，概念适配的`退役命中`已由通用映射转成退役不可用，但 v0.4 没有把 FC/EC 退役和 K 四分支逐项冻结为执行合同；`二次关系判断结果::成功()`只在条件组非空时核对状态与条件合取，FC/EC 空条件结果没有请求概念完整性和求值后置条件门禁。该现场只作具名退回证据，不是正式实现基线。

上述只是静态实现事实，不证明旧入口运行正确，也不证明新入口已经实现。

实现规则：

1. 六个入口在同一共享锁内只检查入口字段、隔离标志、请求 G 守卫和请求局部闭包；禁止调用`状态完整(状态_)`，禁止遍历无关 owner / 节点 / 关系 / 值 / 历史 / 墓碑 / 幂等账，也禁止以全库计数决定成功。全局`状态完整`只用于写入、物理清理和恢复候选正式发布前；读取锁内消费已经通过该唯一发布门的状态，不重复证明整库。
2. 来源当前值组、属性类型当前值组、owner 空域和节点当前引用分别只访问请求 owner / 来源 / 属性类型 / 节点对应的局部索引、owner 局部账或局部引用桶，并逐项与权威当前事实互证。索引只负责定位，不替代事实；请求局部桶的额外项、非严格升序、重复、同编码复义及 owner / 端点 / 类型 / 生命周期矛盾返回`内部不一致`。
3. 三类既有历史候选索引的私有语义扩展为“历史定位候选索引”：桶键和编码向量物理类型可以保持不变，但成员同时覆盖可从`当前 / 历史`物化的候选，以及完整载荷已物理清理、只能由墓碑判定不可物化的候选。索引仍是非权威派生物，不进入快照，不新增持久二级索引。
4. 历史定位的唯一恢复来源是已持久的`中性幂等账`和各 owner 的`所有者范围幂等账`中的首次规范化写集、首次发布代次与首次新编码映射。跨 owner / 三分区 / 有限 N 事务的参与者首次写账已经归一化进入对应 owner 账，重建时只消费这些参与者账，不把外层事务账当作第二份定位来源。关系项解析本地 / 稳定引用后形成`源、目标、关系类型、关系稳定编码、owner、创建代次`；属性候选只从`属性槽变更`解析`所属节点、属性类型、新当前值稳定编码、owner、创建代次`，单独创建但从未采用到属性槽的值不得进入候选。
5. 同一稳定编码被多个首次账投影时，全部定位和创建见证逐字段相同才可去重；任一复义、映射缺失、种类错误或代次矛盾均为内部不一致。投影编码必须恰好命中当前事实、历史事实或同种类墓碑之一；命中墓碑时还必须互证 owner、首次发布代次等于墓碑创建代次以及墓碑生命周期合法。找不到载荷也找不到墓碑不得静默跳过。
6. 成功写入关系或采用属性槽值时按原逻辑插入定位，退出只改变生命周期而不删除定位。物理清理关系或属性候选值前，先从会持久恢复的普通首次写账唯一解析并互证其定位；无法解析时返回既有`内部错误 / 内部不一致`失败且不删除完整载荷、不写墓碑、不推进代次。验证通过后删除`历史`载荷并写墓碑，但保留三类定位索引中的编码；不得继续执行“清理同时删除候选索引项”的旧路径。
7. 恢复先解码全部权威字段，再清空全部派生索引；从当前 / 历史事实重建可物化索引，并从第 4 项首次账投影补入全部关系 / 属性候选定位。每个只剩墓碑的关系或候选值必须取得唯一组定位；任一墓碑无法定位、定位复义或与首次账不一致时，整批恢复候选按现行材料非法 / 内部不一致边界拒绝，不发布半索引。格式 1/2/3 共用该规则，不改变编码格式。
8. 两项历史组读取只访问请求端点＋关系类型桶或所属节点下的属性类型桶。候选可物化时逐项核验并按 H 选择；候选只剩墓碑且墓碑生命周期与请求 H 相交时返回`历史材料已清理`并清空组，不能当作空组。v1 使用同一定位索引恢复既有清理状态分支；v2 还必须回显完整请求头与 Gread/H。

## 5. 二次关系求值应用服务

### 5.1 文件、公开类型和构造

新增：

- `海中鱼巣/业务/计算.二次关系求值.h`
- `海中鱼巣/业务/计算.二次关系求值.cpp`

公开 DTO、`二次关系判断状态`、见证和四个求值请求逐字段采用 4242 v0.5 第 7.1、7.3 节：

- `二次关系求值请求`；
- `二次关系FC求值请求`；
- `二次关系EC求值请求`；
- `二次关系候选求值请求`；
- `二次关系判断结果`。

本包只实现上述求值服务，不实现第 8 节`二次关系概念应用服务`和形成请求/结果。

`二次关系求值应用服务`构造签名逐字采用 4242 第 7.2 节。对象保存八个 non-owning const 引用，构造核验同一 L1、概念服务与 B provider 绑定一致；无效装配抛`std::invalid_argument`，分配失败抛`std::bad_alloc`。对象不可默认构造、复制或移动。

为使“同一 L1”不被误当作“同一服务实例”，`概念树类数据服务`新增四个只读、`noexcept`、不泄漏指针的身份谓词：

```cpp
bool 使用特征服务(const 特征类数据服务&) const noexcept;
bool 使用存在服务(const 存在类数据服务&) const noexcept;
bool 使用特征值服务(const 特征值类数据服务&) const noexcept;
bool 使用状态使用绑定提供者(const 状态使用绑定只读提供者&) const noexcept;
```

四函数只比较构造时保存的 non-owning 引用地址，不访问仓库、不读取事实、不返回 owner。求值器构造必须同时通过`概念服务.绑定于(L1)`和四个谓词；状态服务、存在服务、特征服务和特征值服务仍各自按已有 L1 绑定守卫核验，缺少或不一致时构造拒绝，不能只凭同一 L1 推断同一实例。

### 5.2 来源解析

1. 请求版本 2、请求身份非零、`0<H<=Gread`、A/B 的 E 非零、来源组非空。
2. 同一参与者只允许全 F 或全 B，不得混用；来源身份无重复，同方同 FT 恰一份。A/B 角色不得交换。
3. F 路径：`读取准确特征事实({1,Gread,H,F})`成功；`读取当前采用完整_v2({2,Gread,H,E,FT})`成功且唯一采用正是 F；`读取存在身份来源历史见证(Gread,H,E)`成功。
4. B 路径：`读取状态使用绑定历史({1,Gread,H,B})`成功且 E 相同；`读取状态历史内容({2,Gread,H,S})`成功；状态值不分内联 / 引用，统一调用`解析正式特征类型准确I64_v2({2,Gread,H,FT,准确值})`取得 I64；存在历史见证成功。一个参与者的全部 B 必须具有相同 C 和强时间。求值器禁止直接调用`特征值类数据服务::获取完整值`、`获取特征值`或构造`世界结构预算_B1`。
5. 所有返回见证只保存已由 provider 完整核验的值式事实；不保存服务指针、仓库对象、预算或内部计数。

### 5.3 FC、EC、RC 和 K

1. RC 求值先用版本 2 RC 完整读取，定义截止固定`Gread/Gread`；冷却可求值，退役返回`退役不可用`。候选入口先调用现有公开`规范化二次关系定义`。
2. FC/EC 经`读取二次关系约束定义({2,{1,Gread,Gread},概念})`完整读取；返回`退役命中`统一映射`退役不可用`，不得降为历史材料不可用。FC 只接受 pure v2 I64 特征概念。通用 EC 只接受规则版本 1、`不预设特征`、空父的通用存在定义。
3. 具体 EC 必须完整读回两组定义。`已知子存在概念组`为空时，逐项按自身 FT→FC 约束核验同一参与者来源；自身组和子组同时为空仍是具体 EC，不冒充通用 EC，实际谓词为不命中。`已知子存在概念组`非空时立即返回`规则不支持`并清空三组载荷；不得忽略子组、不得把父参与者来源传给子 EC、不得只核子概念身份，也不得临时扫描父子关系、当前采用或 B/S 材料补造嵌套参与者。
4. 每个原子先`读取I64比较绑定_v2`固定 K，再`读取当前I64比较绑定_v2`确认同 FT+用途唯一当前路由为同一 K。固定 K 未找到映射`证据不足`；当前 K 零命中映射`规则不支持`，多命中`注册不唯一`映射`内部不一致`，唯一命中但身份或完整定义不是固定 K 映射`规则不支持`。不得选择其它 K，也不得把多项权威候选解释为普通规则缺失。
5. 物理输入固定左=B、右=A。只请求差异角色 4；调用唯一`有序I64特征比较提供者::比较`，不得复制算术。结果差异`r`映射域位：负=1，零=2，正=4。
6. 原子命中=`FC命中 && EC命中 && (D & 域位)!=0`；AND 必须执行并核验全部原子，即使已有一项不命中也不能短路技术失败。
7. 末尾再次核 Gread。只有全部必要项完成才返回`命中/不命中`和完整见证；任何非成功清空条件组、来源组和已核验概念。`二次关系判断结果::成功()`必须合取核验版本、成功状态、请求身份、`0<H<=Gread`、`定义H==Gread`、完整来源见证和已核验概念的非零去重；RC 结果还要求条件组非空、逐项定义/K/计算/来源完整且状态等于全部条件谓词的合取。FC/EC 结果要求条件组为空、请求 FC/EC 恰为已核验概念并保留全部实际读取的概念身份；服务构造路径必须以本节完成的实际 FC/EC 谓词设置状态。现行 DTO 不携完整概念定义或独立顶层谓词，故无参数`成功()`只能核验其可表示的结构，不能重新读取 provider 或伪称独立重算 FC/EC 真值；该真值一致性由同一求值过程的构造后置条件及专项变异测试证明。非成功结果三组载荷全部为空，只保留合法请求身份和已经确认的截止头。

### 5.4 失败映射

| 下层或条件 | 求值状态 |
| --- | --- |
| 版本、身份、重复/混合来源、错 E、角色或请求形状 | `入口拒绝` |
| 所需 F/B/S/E、当前采用、FC/EC、固定 K 缺失 | `证据不足` |
| 任一所需对象 H 时已退出、历史材料已清理 | `历史材料不可用` |
| G 守卫变化 | `事实代次漂移` |
| provider 资源失败、分配失败、长度不可表示 | `资源失败` |
| 规则/算法/表示未实现，具体 EC 子概念组非空，当前 K 零命中或唯一命中但不是固定 K，准确值解析返回`非I64` | `规则不支持` |
| FT 不同或输入类型不相容 | `类型不相容` |
| 单位、缩放、量化、输出合同不相容 | `单位量化不相容` |
| K 要求参照而来源无法证明 | `参照不相容` |
| 比较提供者差异不可表示 | `运算溢出` |
| 当前 RC、FC 或 EC 退役 | `退役不可用` |
| 旧材料明确回显旧预算状态 | `旧预算不足`，仅迁移识别；新链不得产生 |
| 当前 K 多命中，结构矛盾、重复权威项、成功谓词矛盾、未预期异常 | `内部不一致` |

任何 provider 的`资源失败`不得映射为不命中、证据不足或未找到。

2. 把 4182 canonical K 迁移面明确扩展到当前代码中全部真实声明、实现和调用点，包含概念树 RC 私有调用和二次关系结构专项；
3. 静态检查改用 PowerShell 可执行的显式根目录加`--glob`或显式文件路径，不再依赖 PowerShell 不展开的`文件.*`。

## 11. v0.3 pure 写链预算漂移裁决

执行期发现双根初始化虽然已删除请求预算，却仍只能通过携`概念树预算`的 pure v2 查询、创建恢复和创建入口收敛通用 EC。该字段实际裁剪创建前读取和发布后读回，不能作为“写合同预算”保留。现行 0050 v3.24 与 4240 v0.44 已唯一裁决预算自由完整范围，本次不改变 pure 定义、owner、写集、事务、生命周期、稳定幂等键、持久结构格式或双根业务语义，只补齐 pure v3 三入口及既有 v2 首次材料恢复规则。受影响代码继续在本计划原允许文件内，不需要修改正式根/子规范、先天特征概念交付或持久恢复格式，也不需要新的用户机器语义裁决。

## 12. v0.4 状态引用 I64 解析具名退回裁决

执行期发现 4242 求值器需要把状态固定准确值中的引用型值解析为 I64，而 v0.3 只写“经`核验正式特征类型准确值`取得 I64”。现行核验结果只回显原始`特征准确值`，没有暴露其内部已解析 I64；求值器直接调用带预算`获取完整值`或无截止`获取特征值`都不合法。

本次裁决不新增通用特征值 ABI。4242 第 7.1 节只要求特征类核验和完整材料读取，没有要求求值器直接拥有值读取算法；4110 第 2.1—2.2 节又把内联 / 引用准确值同内容归特征结构服务。当前特征服务的私有`解析输入`已经完成所需引用历史生命周期、完整内容和身份 / I64 载荷互证。因此 v0.4 仅将同一解析核心封装为第 3.6 节公开 v2 适配，并让旧核验入口共享该核心；owner、事务、生命周期、持久格式、状态内容、正式 FT 域和求值语义均不改变。`数据服务.特征值类.h/.cpp`仍禁止修改，执行者必须从新设计重新 S0。

## 13. v0.5 非空子 EC 与求值结果具名退回裁决

第五次执行退回证明，现行具体 EC 递归把父参与者来源组直接复用于子 EC。该实现与 7100 的父 E→子 E 实例关系、每个 E 独立 E→EC 使用关系，以及 4242 对 F 当前采用、B→E、同场景和强时间的逐参与者互证冲突。现行请求 DTO 又没有子 E、父子匹配和每个子 E 的 F/B/S 材料；预算化当前组成读取也不能证明 H 时或同次观察。故本次不增加嵌套 DTO、不猜测实例选择，收缩为第 5.3 节的安全子集：非空子概念组=`规则不支持`，空子组按自身 FT→FC 求值。

同时冻结第五次退回暴露的精确映射：固定 K 未找到=`证据不足`；当前 K 零项=`规则不支持`、多项=`内部不一致`、唯一但不是固定 K=`规则不支持`；FC/EC 退役=`退役不可用`。第 5.3 节还区分无参数`成功()`可独立核验的结果结构与求值服务必须保证的实际谓词后置条件，不扩充 4242 公开 DTO。

若后继要实现非空子 EC，必须先由用户裁决并进入正式规范：嵌套子参与者及逐层来源见证的请求形状；父 E 直接子组与子 EC 集合的匹配、数量和重复实例语义；每个子 E→EC 在`Gread/H`的读回；每层 F/B 的独立选择和禁止继承边界；子 B/S 与父、兄弟的场景和强时间关系；历史组成/发生期提供者，以及退出、清理、漂移、资源失败和多重失败优先级。在这些语义冻结前，计划和代码均不得宣称完整 4242 EC 递归。
