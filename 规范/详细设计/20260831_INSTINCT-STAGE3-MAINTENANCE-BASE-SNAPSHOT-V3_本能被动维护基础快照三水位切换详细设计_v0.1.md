# INSTINCT-STAGE3-MAINTENANCE-BASE-SNAPSHOT-V3 本能被动维护基础快照三水位切换详细设计 v0.1

日期：2026-08-31

状态：现行代码实施详细设计

## 1. 目标与边界

当前生产启动已经建立或恢复 `本能被动维护游标事实_v3`，其权威字段为完整秒边界、已消费主动安全变化事实代次和已消费服务维护历史事实代次。现有 `本能被动维护基础快照_v1` 仍承载 `本能被动维护游标事实_v1`，组合器也只调用 `读取当前本能被动维护游标_v1`，因此不能成为 6170 v0.9 后继维护的正式输入。

本切片新增兼容并行的基础快照 v2：在一个冻结 `G0` 下读取正式安全根定义与当前值、服务值当前事实、v3 三水位游标和完整秒观察，形成后继事实分段与维护事务可以直接消费的不可变快照。

本切片不修改 v1 ABI，不推进游标，不读取历史事实范围，不计算服务衰减或安全回归，不发布 A/V、状态、动态、合同或规则宇宙，也不改变当前生产定义版本 1 的：

```text
L = 2767011611056432742
H = 7378697629483820645
安全根定义版本 = 1
主动安全结算规则版本 = 1
```

“阈值未来可变”只通过后继新安全根定义版本表达；版本 1 当前实例保持不变。

## 2. 正式依据与当前事实

正式依据：0050 v2.1、6120 v0.10、6170 v0.9、4230 v0.20。

当前已发布能力：

- `本能被动维护游标服务::读取当前本能被动维护游标_v3` 返回完整三水位游标；
- 启动链已经以永久变化账登记代次和服务历史账登记代次建立或迁移 v3；
- 安全根定义与当前值、服务值当前事实和完整秒时钟均有现行正式读取入口；
- v1 基础快照及其三个 v1 下游组合器仍保留源码兼容，不在本切片改挂。

当前缺口不是阈值计算，也不是新的水位 owner，而是缺少消费 v3 游标的强类型基础快照 ABI。

## 4. 完整性与成功形状

请求必须满足：专属版本 2、共同 L2 请求头现行版本、非零 `G0`、完整本能根锚点、锚点截止不晚于 `G0`、非零期望运行代次。

v2 快照完整性必须逐项证明：

1. 锚点、安全根、服务值、游标均属于同一自我和对应根特征实例；
2. A/V 位于 `0..INT64_MAX`，安全根定义及 L/H 取正式读回值，不在组合器内重算；
3. v3 游标完整，两个事实代次水位均非零且不晚于 `G0`，游标形成代次不晚于 `G0`；
4. 时间观察的运行代次、时间纪元、上一已消费完整秒边界和时间源版本逐字段等于 v3 游标；
5. 当前完整秒不早于游标完整秒；无新完整秒时区间为空且两边界相等；有新完整秒时区间恰覆盖 `(上一已维护完整秒边界, 当前完整秒边界]`；
6. 全部正式读取截止等于同一 `G0`。

只有 `已读取` 和 `无新完整秒` 可以成功并携带完整快照和非零截止；`可维护()` 只对 `已读取 + 非空且非零待维护区间` 成立。其它状态快照为空、截止为 0。

## 5. 固定读取顺序与映射

```text
验证请求
-> 读取 v3 游标（G0）
-> 互证自我、运行代次和两个事实水位
-> 以游标运行代次/纪元/完整秒/时间源读取当前完整秒
-> 读取安全根定义与当前值（G0）
-> 读取服务值当前事实（G0）
-> 再读同一 v3 游标（G0）
-> 首末游标逐字段相等
-> 构造并运行 v2 完整性谓词
-> 返回已读取或无新完整秒
```

v3 游标状态固定映射：`未建立 -> 游标未建立`，`待迁移 -> 游标待迁移`，`当前性漂移 -> 当前性漂移`，`引用冲突 -> 引用冲突`，`资源失败 -> 资源失败`，`入口拒绝 -> 入口拒绝`，其它形状 -> 内部错误。其余 provider 状态沿 v1 已验证映射，仅把目标枚举替换为 v2。

读前或读后任一正式事实漂移、两次游标不等或截止不等于 `G0`，统一返回当前性漂移；禁止返回首次读取的旧载荷。

专项至少覆盖：v3 未建立、待迁移、已建立；两个水位逐字段保留；无新秒、1秒、多秒；错运行代次、错纪元、时间源漂移、时间倒退、旧 G、游标读中漂移；定义未发布、A/V 当前值缺失、坏锚点；Debug/Release、外部 ABI consumer 和 v1 回归。
