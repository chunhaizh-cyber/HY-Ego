## 1. 目标与完成条件

尝试执行一个结果为空的配对之后，学习用这次执行的实际结果补全该配对的结果节点，流程如下：

```text
任务执行结束 → 影响评估 → 方法问题归档（已有）→ 学习线程 方法问题学习（已有，现只收集）
  → 学习形成“尝试补全候选”（新）
  → 独立评审：复核后授权或拒绝（新）
  → 方法所有者消费授权，原地修订：条件不变，结果改为实际结果，来源记为“尝试”（新）
  → 完整读回 → 学习结束通知（已有，触发等待复核与重新筹办）
```

完成条件：
1. 采用配对结果为空的尝试执行，只要入档材料完整、实际结果全部能用参数位置表达，就形成候选。候选经独立评审授权后，由方法所有者以“条件相同、结果为实际结果、知识来源为尝试”的新配对替换方法对原配对的引用，并完整读回。
2. 候选不能自证授权。评审由独立组件执行，按第 5 节五项复核，只输出授权或具名拒绝。
3. 方法所有者只消费有效授权。原配对已变化（条件不同或结果已非空）时返回前提已变化，不覆盖后来的知识。
4. 实际写回值引用了非参数存在时，按用户裁决 3 记录逻辑错误日志，不形成候选。其它不能表达的情况保留具名缺口，不形成候选。
5. 原配对节点不物理删除（在途 X 和已冻结的任务采用仍引用它）。新配对真实命中次数按第 11 节 R-C 处理。
6. 全部既有消费者编译通过；模拟学习、配对融合语义不变。

完成声明边界：本设计只覆盖“空结果配对的首次补全”。不覆盖以下各项：
- 已有结果配对的验证与反例（同条件异结果按 5370 §5.4，另行设计）；
- 5350 §6.1 运行统计与可靠度；
- 尝试配对的融合；
- 其它学习修订种类的评审。

## 3. 对象

### 3.1 尝试补全候选（学习侧，可重建，不持久）

```cpp
struct 新尝试补全候选 final {
    // 同键同义复用、同键异义冲突（5370 §6）
    稳定编码 方法节点, 原配对节点, 归档节点;
    std::uint32_t 规则版本 = 1;               // “尝试补全空结果/1”
    新方法条件定义 原条件;                       // = 任务采用.原始条件（冻结）
    新方法结果定义 新结果;                       // 由实际结果导出
    std::vector<稳定编码> 来源执行分支节点组;     // = 任务采用.来源执行分支节点组
    std::vector<新尝试补全差异项> 差异项组;       // 种类：新增；本规则只允许“结果由空→新增项”
};
```

差异项按 5370 §6 区分新增、保留、移除、替换、未知、冲突。本规则下合法候选只含“新增”（结果项或结果参数关系）。条件全部为“保留”，不逐项列出。

## 4. 学习：形成候选

纯函数 `形成尝试补全候选(const 新方法问题反馈材料&, const 新方法信息& 当前方法)`，无写入。

### 4.1 前提（任一不满足 → 不形成候选，记具名缺口，学习照常结束）

1. `采用来源 == 任务执行组织` 且有 `任务采用`；
2. 有 `本次运行对`，且 `结果.结果取得状态 == 已取得`（待取得、部分取得不补全，留后续同次补齐，5350 §6.1）；
3. `任务采用.结果` 为空（结果项、结果参数关系、结果场景事实三项均空）；
4. 两份场景快照 `缺口组` 为空；
5. 当前方法中 `任务采用.来源配对节点` 仍被方法引用，其条件 == `任务采用.原始条件`，结果仍为空。否则不形成候选：已被并发补全，或已被修订。

### 4.2 结果导出

逐项处理 `实际状态组` 中的状态 s：

1. 定位参数：找到特征类参数位置 p，使本次运行条件中 p 的 `有序引用.信息节点 == s.来源实例特征节点`。找不到：s 不是本方法参数特征上形成的状态，记**逻辑错误**（同裁决 3，见 R-E），不形成候选。
2. 类型：`s.特征类型概念节点` 须为或从属于 p 的规格范围概念，且属于方法头可能结果概念组；否则记逻辑错误，不形成候选。
3. 值：
   - 存在身份精确型：取值 E。E 等于某个存在类参数位置 q 的实参，就形成结果项 `{参数序号=p, 特征类型}` 和结果关系 `特征引用存在(p,q)`；E 不是任何参数的实参，就**记逻辑错误**（裁决 3），不形成候选；
   - I64：结果项 `精确数值域=[v,v]`；
   - 其它材料：本版不支持，记缺口“结果材料类型未支持”，不形成候选（R-D）。
4. 同一 p 有多个状态时，取 `实际状态组` 中该特征最后形成的状态。顺序以已形成状态节点组为准，不按时间推定。
5. `实际状态组` 为空：不形成候选，记缺口“已取得但无实际状态”。不当作“明确无变化”（5350 §4）。

结果场景事实限定组本版保持空。未观察到的项不写，不当作无变化。

“逻辑错误”按用户裁决 3 记录：经调试日志（`PARAM_BINDING` / 诊断类别）和学习线程问题记录，写明方法、配对、归档、参数、值。不弹工程窗口，不抛 `新学习运行异常`，不形成候选。

## 5. 独立评审

新类 `方法学习评审服务`，文件 `业务/方法学习评审.服务.h/.cpp`。它独立于 `方法问题学习服务` 构造，不持有学习侧收集状态。只读依赖：`新方法问题归档接口`、`新_方法类` 只读读取，以及新增的方法所有者只读核验入口 `核验条件结果定义`（见 5.1 第5项）。

`新学习评审结论 评审尝试补全(const 新尝试补全候选&, 新尝试补全授权* 输出)` 依次复核：

1. **来源可重建**：按 `候选.归档节点` 重新读取归档，核同任务、执行实例、来源方法、任务采用中的来源配对。再以归档材料重新调用 `形成尝试补全候选`，结果须与候选逐字段相等（R-B）。
2. **差异完整**：候选只含“结果由空→新增”。原条件 == 归档中的 `任务采用.原始条件`。差异项与 `新结果` 一一对应，没有遗漏或多余项。
3. **安全与动作入口**：方法仍是启用的本能方法，登记名不变；`参数规格组` 与 `任务采用.参数要求组` 一致（固定规格未被修订，5350 §11）；执行分支仍属于该方法。
4. **重复消费 / 前提**：方法当前仍引用 `原配对节点`，条件不变、结果为空。不满足 → `已消费或前提已变化`（补全后结果非空，同一归档第二次评审必然落在这里）。
5. **新结构自足**：所有引用的概念节点存在；参数序号与关系在参数规格内；不引用模拟本地身份；经方法所有者只读核验入口 `核验条件结果定义(方法, 定义)` 通过。该入口复用 `条件结果有效`、`条件结果角色已声明`、`行为结果相容`、`配对分支来源有效`，不写入。

全部通过才输出授权。评审不写方法知识。

## 6. 方法所有者发布

`以尝试授权补全条件结果`，在 `新方法互斥` 下执行：

1. 读取方法；方法不可用 → `方法不可用`。
2. 再核授权第 3、4 项（方法入口与原配对当前状态）。不符 → `前提已变化`，零写入。本状态为新增，追加在 `新方法学习发布状态` 末尾；若已有同义状态则复用，S0 核对。
3. 以 `{条件=原条件, 结果=新结果, 来源执行分支=候选值}` 跑与追加相同的合法性校验，不按仅条件节点处理。不合法 → `条件结果不合法`。
4. `写入条件结果` 建新配对，`配对知识来源字段=2`，命中次数按 R-C。
5. 同一原子片段：追加“方法→新配对”，删除“方法→原配对”的字段关系。原配对节点保留。
6. 完整读回：配对总数不变；原配对不再被引用；新配对的条件、结果、来源、分支、线性关系与定义相同；其它配对不变。读回失败 → `发布结果未知`。

失败回滚只回滚尚未发布的已写字段和已建节点，与追加、融合相同。

## 7. 学习线程接线

`方法问题学习服务::学习` 收集成功后，若 `材料完整`：

1. 读当前方法，调用 `形成尝试补全候选`；
2. 形成了候选 → `评审服务.评审尝试补全` → 已授权 → `方法_.以尝试授权补全条件结果`；
3. 记录诊断：形成 / 缺口 / 逻辑错误 / 评审结论 / 发布状态；
4. 返回 `学习结束通知{方法节点}`。既有链路会据此唤醒等待复核与重新筹办（5260 §5.3）。

非成功处理：
- 评审拒绝、前提已变化：正常学习结束，不重试。
- 资源失败：按 `新学习运行异常原因::资源不足` 走既有重试。
- 发布结果未知：按工程问题上报（与模拟学习相同）。

收集组已有同一归档、消息相同时，直接返回，不重复候选。

构造与装配：
- `方法问题学习服务` 构造增加 `新_方法类&` 与 `方法学习评审服务&`；
- `装配.普通应用.cpp:376` 附近按依赖顺序建评审服务。

## 11. 待裁决

- **R-A 授权承载（会改变实现）**。5350 §11 写“晋级授权…是各自 owner 的权威事实”，但没有给出字段与 owner。
  - 选项一（建议）：授权是评审返回的一次性材料，同一次学习处理内交给方法所有者消费，不持久。重复消费由第 5 节第 4 项和第 6 节第 2 项的“原配对当前结果为空”保证，补全后自然失效。不新增持久结构，也不跨存储事务。
  - 选项二：授权持久化为模拟世界中的授权节点，状态为已授权 / 已消费 / 已拒绝，方法所有者消费后回写已消费。需要跨存储恢复，并要给配对增加授权来源字段，5350 需同步。
- **R-B 评审独立性**：评审重算候选时调用与学习相同的纯导出函数，以“来源可重建”方式核对。这是否满足“独立评审”？建议满足：评审另有第 2—5 项独立核对，且导出函数无状态、无写入。如需另写一套独立导出算法，工作量约翻倍。
- **R-C 新配对命中次数**：建议为 0。真实运行与成功次数归 5350 §6.1 统计路径，该路径尚未实现，配对命中次数不在本切片顺带计入。备选：计 1，即本次真实运行一次命中。
- **R-D 结果值类型范围**：建议本版只支持 I64 和“引用参数存在”的存在身份，其它材料（文本、集合等）记缺口。备选：同时支持材料值域。这需要在授权前建值域概念，或由所有者在发布时物化。
- **R-E 不在参数特征上的状态**：建议按裁决 3 同样记逻辑错误。裁决 3 原文只说到“值引用非参数存在”，本项是对它的扩展。
