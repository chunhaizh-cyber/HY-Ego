## 1. 目标与完成条件

一次尝试执行采用了结果为空的配对，其实际结果作为一条来源为“尝试”的配对进入方法知识。这条配对的条件只覆盖这次执行实际取得的条件。原空结果配对覆盖的其它范围继续保持未知，留给后续尝试。

```text
任务执行结束 → 影响评估 → 方法问题归档（已有）→ 学习线程 方法问题学习
  → 收集（已有）→ 处理：形成候选（新）→ 独立评审（新）→ 方法所有者凭授权发布（新）
  → 完整读回 → 处理结束 → 学习结束通知（已有，触发等待复核与重新筹办）
```

完成条件：
1. 满足 §4.1 前提且全部结果可表达时，形成“实际条件 → 实际结果”候选。经评审授权后由方法所有者发布：
   - 实际条件与原条件相同：原地替换原空结果配对；
   - 实际条件严格窄于原条件：追加一条尝试配对，原配对不变。
2. 授权只能由评审服务构造，并绑定完整候选与评审依据；方法所有者发布时核对这些依据。
3. 资源失败或发布结果未知后，同一归档能继续处理，不因“已收集”而跳过。
4. 不可表达的情况按 §4.4 分三类处理。值引用非参数存在时，经正式逻辑错误日志入口记录（裁决 3）。
5. 新配对命中次数为 0；原配对节点不物理删除。
6. 全部既有消费者编译通过；模拟学习和配对融合语义不变。

完成声明边界：
- 本设计只覆盖“空结果配对的尝试结果入知识”。
- 不覆盖：
  - 已有结果配对的验证与反例（5370 §5.4）；
  - 尝试配对的推广与融合；
  - 原空结果配对的竖向细分；
  - 5350 §6.1 统计；
  - 其它学习修订的评审。
- 动作已发生、归档已交接，不等于需求目标已满足。run-93 目标仍未满足，这两件事分开记录。

### 3.2 评审授权（进程内一次性，不持久）

```cpp
class 新尝试补全授权 final {
public:
    新尝试补全授权(新尝试补全授权&&) noexcept = default;
    新尝试补全授权(const 新尝试补全授权&) = delete;
    const 新尝试补全候选& 候选() const noexcept;
    const 新尝试补全评审依据& 依据() const noexcept;
private:
    friend class 方法学习评审服务;        // 只有评审服务能构造
    新尝试补全授权(新尝试补全候选, 新尝试补全评审依据) noexcept;
    新尝试补全候选 候选_;
    新尝试补全评审依据 依据_;
};
struct 新尝试补全评审依据 final {
    // 评审时从方法所有者 fresh 读取的材料副本，不是单个编码
    std::string 本能函数登记名;
    std::vector<新方法参数规格> 参数规格组;
    稳定编码 原配对节点; 新方法条件定义 原配对条件; 新方法结果定义 原配对结果;  // 原结果须为空
    std::vector<稳定编码> 方法现有配对节点组;    // 用于判断同条件冲突
};
```

授权合同：
- 构造器私有，只有评审服务能构造。外部可以构造候选，但构造不出授权。
- 授权只能移动、不能复制。方法所有者入口按右值接收，消费后授权失效。
- 授权类型放在领域层，以友元前向声明评审服务，领域层不包含业务头。
- 不持久：进程重启后授权消失，重新处理同一归档时重新评审。

## 4. 学习：形成候选

纯函数 `形成尝试补全候选(const 新方法问题反馈材料&, const 新方法信息& 当前方法)`，无写入。返回三种结果之一：候选、具名缺口、逻辑错误材料。

### 4.1 前提（不满足 → 具名缺口）

1. `采用来源 == 任务执行组织` 且有 `任务采用`；
2. 有 `本次运行对`，且 `结果.结果取得状态 == 已取得`；
3. `任务采用.结果` 的三组均为空；
4. 两份场景快照的 `缺口组` 为空；
5. 当前方法仍引用 `任务采用.来源配对节点`，其条件 == `任务采用.原始条件`，结果仍为空。

### 4.2 实际条件（不推广）

从 `任务采用.原始条件` 逐项导出：
- **I64 数值条件项**（区间）：取本次运行条件中对应参数的 `动作前准确值` v，收窄为 `[v,v]`。
  - v 不在原区间 → 逻辑错误：执行前核验应已保证。
  - 无动作前值 → 缺口“条件项实际值缺失”，不以原区间代替。
- **概念层条件项**（存在范围概念、集合的概念成员 / 子集约束、引用内容条件、参数关系、场景事实限定）：原样保留。
  - 这些项在执行前已核验为真，并且已经是概念层表达；实例身份不能进入知识（与模拟学习有结果样例的做法相同）。
  - 这一点见 R-1。
- **其它材料条件项**（材料值域）：本版不收窄，缺口“条件材料类型未支持”。

全部项都没有被收窄时，`与原条件相同 = true`。

本版不形成比实际条件更宽的条件，也不切分原空结果配对的剩余范围。推广、合并和细分另行设计。

### 4.3 实际结果（只取本次执行形成的状态）

1. **归因**：只取同时满足以下两条的状态，即本次函数调用正式报告形成、且仍在归档实际状态中的状态：
   - 状态节点在 `本次运行对.结果.已形成状态节点组` 中；
   - 状态在 `实际状态组` 中，内容一致。

   只在 `实际状态组` 中出现、本次未形成的状态属于同时观察，不进入结果，只记诊断。
2. **同一特征多个本次状态**：没有正式的顺序来源，记缺口“同特征多个本次状态”，不按编码或时间推定。
3. **定位参数**：找到特征类参数位置 p，使 p 的 `有序引用.信息节点 == s.来源实例特征节点`。
4. **类型**：`s.特征类型概念节点` 为或从属于 p 的规格范围概念，并属于方法头的可能结果概念组。
5. **值**：
   - 存在身份精确型，值为 E：E 是存在类参数 q 的实参，就形成结果项 `{p, 特征类型}` 和结果关系 `特征引用存在(p,q)`；
   - I64：`精确数值域=[v,v]`；
   - 其它材料：缺口“结果材料类型未支持”。
6. 归因后没有任何状态：缺口“已取得但本次无形成状态”。不当作“明确无变化”。

结果场景事实本版保持空。

### 4.4 不可表达情况的分类

| 类别 | 情形 | 处理 |
| --- | --- | --- |
| 合同违规 | 本次形成状态的特征类型不在方法头可能结果概念组中；4.2 中实际值不在已核验区间 | 见 R-2 |
| 裁决 3 | 本次形成状态写入的存在引用值不是任何参数的实参 | `记录逻辑错误日志(L"方法问题学习", L"尝试补全", 方法/配对/归档/参数/值)`，不形成候选，不弹窗，留待后续处理 |
| 表达能力不足 | 本次形成状态所在特征不是参数特征，例如存在参数的内部特征、新建对象上的特征 | 见 R-3 |
| 无关观察 | 不在本次已形成状态节点组中的状态 | 排除，只记诊断 |

## 5. 独立评审

新类 `方法学习评审服务`，文件 `业务/方法学习评审.服务.h/.cpp`。它独立于 `方法问题学习服务` 构造，不持有学习侧状态，自行读取全部来源。

`新学习评审结论 评审尝试补全(const 新尝试补全候选&, std::optional<新尝试补全授权>& 输出)`：

1. **来源可重建**：自行按 `候选.归档节点` 读取归档，核同任务、执行实例、来源方法、来源配对；自行读取当前方法。以这两份独立读取的材料调用 `形成尝试补全候选`，结果须与候选逐字段相等。
2. **依据独立核验**（不依赖导出函数）：
   - 原配对条件 == 归档 `任务采用.原始条件`；
   - 每个收窄项的点值 == 归档本次运行条件中对应参数的动作前准确值，且落在原区间内；
   - 每个结果项都能在归档中找到一个本次已形成、内容一致的状态，结果关系的右参数实参等于该状态的值；
   - 差异项与“条件收窄 + 结果新增”一一对应。
3. **方法入口**：方法启用且为本能；登记名不变；`参数规格组` == `任务采用.参数要求组`；执行分支属于该方法。
4. **前提与重复消费**：方法当前仍引用原配对，条件不变、结果为空。追加时，方法中不存在与实际条件同一学习条件的配对；已存在且结果相同、来源为尝试，则结论为 `已发布`。
5. **结构自足**：`方法_.核验条件结果定义` 通过；不引用模拟本地身份。

全部通过才构造授权，评审依据从第 3、4 项的 fresh 读取材料复制。评审不写方法知识。

结论枚举：`已授权=1, 已发布, 来源不可重建, 依据不符, 方法入口已变化, 前提已变化, 结构不自足, 资源失败`。

## 6. 方法所有者发布

`以尝试授权发布条件结果(授权&&)`，在 `新方法互斥` 下执行：

1. 读取方法，核对授权依据：登记名、参数规格组、原配对仍被引用且条件与结果同依据。追加时还要核对：没有新出现的同一学习条件配对。不符 → `前提已变化`（新增状态，末尾追加；S0 核对是否已有同义状态），零写入。
2. 对 `{实际条件, 实际结果, 来源执行分支}` 做与追加相同的合法性校验，不按仅条件节点处理。
3. `写入条件结果` 建新配对：知识来源=2，命中次数=0。
4. 同一原子片段：
   - 替换：追加“方法→新配对”，并删除“方法→原配对”；
   - 追加：只追加“方法→新配对”。
5. 完整读回，核对配对数、引用关系、新配对内容和其它配对不变。失败 → `发布结果未知`。

## 7. 学习线程：收集与处理分开

`方法问题学习服务` 的收集组项增加处理状态：

```text
已收集 → 待处理 → 已结束{已发布 | 评审拒绝 | 前提已变化 | 缺口 | 逻辑错误}
```

1. 收集（既有核验）成功：记 `待处理`。同一归档再次投递且消息相同时，不再跳过，按当前处理状态继续：
   - `待处理`：重新执行第 2 步；
   - `已结束`：直接返回。
2. 处理：
   - 读当前方法 → 形成候选 → 评审 → 发布；
   - 每次都从头重新读取与评审，不复用上次的授权。
3. 状态迁移：
   - 已授权并且发布 `已发布` → `已发布`；
   - 评审为 `已发布`（前次已落地）→ `已发布`；
   - 评审拒绝、前提已变化、缺口、逻辑错误 → 相应 `已结束`；
   - 资源失败 → 保持 `待处理`，抛 `新学习运行异常(资源不足)`，走既有重试；
   - 发布结果未知 → 用 `查找尝试配对` 按原请求查找：找到 → `已发布`；找不到 → 保持 `待处理`，按工程问题上报（与模拟学习相同）。
4. 处理到结束状态后返回 `学习结束通知{方法节点}`。

处理状态只在内存中。进程重启后收集组为空，归档如果被重新投递，会从头处理；评审第 4 项保证不重复发布。
