版本：v0.2
日期：20260821

状态：历史形成材料。目标裁决证据节点、任务 owner 私有治理状态以及“执行后目标未达成自动重筹办”生产链均已由 `20260831_COGNITIVE-EVIDENCE-BOUNDARY_认知证据与工程正确性分界详细设计_v0.2.md` 覆盖；旧事实和旧 ABI 仅作历史读取 / 已有幂等账精确重放，首次新写必须拒绝。

## 1. 目标与完成边界

本设计闭合已经发布的“任务目标未达成待重筹办”结构能力到真实生产线程边界：

```text
自我线程冻结目标未达成裁决
→ 形成不可变任务重筹办意图
→ 经异步提交端口交给任务管理线程
→ 任务管理线程冻结唯一处理槽
→ DATA 外任务业务提供者登记正式裁决首态
→ 迁移为目标未达成待重筹办
→ 同代退出旧当前实例关系与旧当前选择关系
→ 形成唯一下一筹办工作包
```

完成时只证明：真实自我线程能够把一条目标未达成裁决交给真实任务管理线程；任务 owner 能够保存正式裁决、失效旧执行当前性、保留全部历史并形成下一筹办工作包。

本设计不实现：

```text
新路径、新实例或新执行冻结
方法召回、六项能力匹配或筹办算法
目标已达成分支的路径验证与任务完成
需求满足、需求结算、价值、安全值、服务值或学习
真实方法动作执行
跨进程恢复
```

路径验证继续延后到“目标已达成 → 路径验证 → 任务完成”全流程；目标未达成分支不得调用路径验证。

## 3. 职责与依赖方向

### 3.1 自我线程

自我线程负责：

- 只在正式目标裁决为“未达成”时形成一次不可变重筹办意图；
- 原样冻结治理批次、治理输入、任务、实例、执行轮次、正式实际结果、共同事实截止、正式目标裁决和值式写入身份；
- 通过注入的 `任务重筹办意图提交端口` 异步提交；
- 队列满或资源等待时保留同一处理槽与同一意图重试，不重新取邮箱消息、不重新裁决目标、不生成新身份；
- 提交成功或精确重复后推进本批次路由并继续治理循环。

自我线程不得调用 `L2任务结构服务`、不得创建新路径或实例、不得解释筹办结果。

### 3.2 任务管理线程

任务管理线程实现唯一 `任务重筹办意图提交端口`，负责：

- 对不可变意图做协议准入、同键同义去重与同键异义拒绝；
- 冻结有界处理槽并唤醒现有管理循环；
- 在不持有队列锁时调用唯一任务重筹办业务提供者；
- 保存结构化结果和下一筹办工作包；
- 资源失败或合法等待时以原意图重排；
- 与既有结果上行队列按轮转规则公平消费；
- 停止阶段先拒绝新意图，再排空已接收意图和结果上行。

任务管理线程不得自己比较目标、直接调用 DATA 裸入口或形成新路径。

### 3.3 DATA 外业务提供者

新增 `任务目标未达成重筹办触发提供者`。它是本叶唯一业务入口，负责：

```cpp
任务重筹办触发结果
形成待重筹办与下一筹办工作包(
    const 任务重筹办意图& 意图) noexcept;
```

提供者逐字段解释已冻结目标裁决，映射到 DATA-L2 两个专用请求，调用正式写入口并独立读回。它不持有线程队列，不写需求，不执行筹办算法。

### 3.4 DATA-L2任务结构

`L2任务结构服务` 继续是唯一结构 owner。它只负责：

- 保存正式裁决证据和治理状态；
- 校验任务、路径、实例、结果、前态、当前关系和事实截止；
- 幂等、事务、当前/历史读回；
- 在目标未达成迁移的同一写集中退出三条旧当前关系。

DATA-L2 不判断裁决真实性，不形成下一筹办轮次，不决定方法或路径。

## 4. 不可变意图协议

### 4.1 物理位置

新增模块：

```text
海中鱼巣/线程/协议.任务重筹办意图.ixx
export module 海中鱼巣.线程.协议.任务重筹办意图;
```

模块只定义纯值 DTO、守卫和抽象提交端口，不导入任务管理线程或自我线程实现。

### 4.2 意图字段

```cpp
inline constexpr std::uint32_t 任务重筹办意图协议版本 = 1;

struct 任务重筹办意图 final {
    std::uint32_t 协议版本 = 任务重筹办意图协议版本;
    std::uint64_t 意图幂等键 = 0;
    std::uint64_t 治理批次身份 = 0;
    std::uint64_t 治理消息编号 = 0;
    L2任务身份 任务;
    L2实例方法身份 旧实例方法;
    std::uint64_t 旧执行轮次 = 0;
    L2任务实际结果身份 旧任务实际结果;
    std::uint64_t 原共同事实截止 = 0;
    std::int64_t 生命周期发生时间 = 0;
    std::uint64_t 运行代次 = 0;
    L2结构幂等身份 裁决首态写入幂等身份;
    L2结构幂等身份 待重筹办迁移写入幂等身份;
    任务目标达成裁决状态 裁决状态 =
        任务目标达成裁决状态::入口拒绝;
    任务目标达成裁决快照 目标裁决;
};
```

守卫要求所有身份、轮次、截止、时间和运行代次非零；发生时间必须能无损承载为 I64；`裁决状态` 必须为目标未达成，裁决快照的 `生命周期准备` 必须为目标未达成待重筹办；重复字段必须逐项相同。

`生命周期发生时间` 唯一来自原任务结果治理消息的 `发生时间戳`。任务结果回执和治理消息准入均要求该值位于 `1..INT64_MAX`；业务链只做无损 `U64 -> I64` 转换，不读取当前时钟，也不在首态与迁移之间自增时间。重复字段逐项相同固定包括：治理输入幂等键、任务、实例方法、执行轮次、任务实际结果和共同事实截止。

`意图幂等键` 使用原治理输入幂等键，只在任务管理意图槽命名空间内去重，不映射为 DATA 写入身份。

### 4.3 写入身份来源

两笔 DATA 写入身份必须由任务工作结果生产者预先给出，沿下列链路原样传递：

```text
任务工作结果材料
→ 任务结果回执材料
→ 任务结果复核载荷
→ 任务结果治理后继输入
→ 任务目标裁决处理槽
→ 任务重筹办意图
```

`任务工作结果材料` 和回执协议新增：

```cpp
L2结构幂等身份 任务治理首态写入幂等身份;
L2结构幂等身份 任务重筹办迁移写入幂等身份;
```

它们与现有 `任务实际结果写入幂等身份` 必须三者非零、两两不同，并由上游保证在任务 owner 写入命名空间中永久不复用。任何一层不得从消息编号、队列序号、稳定编码、摘要、哈希或位运算重新生成。

任务结果回执协议版本从 3 提升为 4；版本 3 回执不得静默补默认身份，只能结构化拒绝。

自我治理消息协议也从版本 3 提升为版本 4。`任务结果复核载荷` 在既有七个业务身份后增加：

```cpp
L2结构幂等身份 任务治理首态写入幂等身份;
L2结构幂等身份 任务重筹办迁移写入幂等身份;
```

两项必须与回执逐字段相同并参与载荷同义比较、必填准入和消息幂等比较。版本 3 治理消息不得补默认身份；其它消息类型继续使用版本 4 常量构造，不新增字段。

## 5. 业务提供者合同

### 5.1 DTO 与物理位置

新增：

```text
海中鱼巣/领域/内部治理/任务重筹办.数据.h
海中鱼巣/领域/内部治理/服务.任务目标未达成重筹办触发.ixx
```

`任务重筹办触发状态` 固定为：

```text
已形成、精确重复、合法等待、当前性漂移、引用冲突、
入口拒绝、资源失败、内部错误
```

`下一筹办工作包` 至少冻结：

```cpp
struct 下一筹办工作包 final {
    L2任务身份 任务;
    L2任务方法路径身份 旧路径;
    L2实例方法身份 旧实例;
    std::uint64_t 旧执行轮次 = 0;
    L2任务实际结果身份 旧实际结果;
    L2任务目标裁决证据身份 正式目标裁决证据;
    L2任务治理状态身份 正式待重筹办状态;
    std::uint64_t 原共同事实截止 = 0;
    std::uint64_t 迁移后事实代次 = 0;
    std::uint64_t 旧筹办轮次 = 0;
    std::uint64_t 新筹办轮次 = 0;
    std::uint64_t 运行代次 = 0;
    std::uint64_t 原重筹办意图幂等键 = 0;
};
```

`新筹办轮次` 只能等于正式旧实例的 `筹办轮次 + 1`；溢出返回内部错误，不能回绕。工作包是进程内强类型后继输入，不是新筹办事实，不创建新路径或实例。

### 5.2 裁决快照到 DATA 材料映射

业务提供者必须逐字段映射：

| BIZ 裁决快照 | DATA 裁决材料 |
| --- | --- |
| 治理输入幂等键 | 治理输入幂等键 |
| 任务、实例方法、执行轮次、任务实际结果 | 同名字段 |
| 任务目标来源、目标宿主、目标特征、目标状态合同 | 同名字段 |
| 实际状态、动态证据、方法 | 同名字段 |
| 路径预期结果、路径验证合同 | 同名字段 |
| 比较注册、算法版本、具名关系、允许关系位 | 同名字段 |
| 目标未达成、目标未达成待重筹办 | DATA 对应强类型枚举 |
| 共同事实截止 | 来源共同事实截止 |

禁止按内存布局转换、文本序列化或遗漏字段。

### 5.3 两步调用与重入

固定过程：

```text
按原共同截止读取任务、当前路径、当前实例和实际结果
→ 登记执行结果待验证首态与正式裁决证据
→ 取得首态发布代次、首态身份和裁决证据身份
→ 以原迁移写入身份提交目标未达成待重筹办迁移
→ 独立读回当前待重筹办状态和旧历史
→ 形成下一筹办工作包
```

首次调用的首态可能已成功、迁移尚未执行。相同意图重入时，首态必须以原写入身份读回精确重复，再继续原迁移；不得重新生成任何身份。

首态和迁移允许共享同一个业务发生时间。顺序由任务治理状态生命周期版本和两个事实发布代次确定；迁移时间只禁止早于前态。现有 DATA 检查由“必须严格晚于”改为“不得早于”，避免同一秒内两次合法结构发布被虚构未来时间阻塞。

DATA 结果到业务结果的映射固定为：

| DATA-L2 状态 | 业务状态 |
| --- | --- |
| 已提交 | 已形成 |
| 精确重复 | 精确重复 |
| 事实代次漂移 | 当前性漂移 |
| 幂等冲突、引用冲突、未找到、已退出、属性未设置 | 引用冲突 |
| 入口拒绝、许可拒绝、未实现 | 入口拒绝 |
| 资源失败、数量预算不足 | 资源失败 |
| 内部不一致或写入口意外返回已读取 | 内部错误 |

`合法等待` 只用于业务前置材料合法未形成；当前目标未达成链正常情况下没有该来源，不得把未找到或当前性漂移降级为等待。独立读回返回的已读取只表示读回成功；读回材料缺项按引用冲突或内部错误分账，不能冒充写入成功。

## 6. DATA-L2 原子迁移扩展

### 6.1 请求与结果

`L2提交目标未达成待重筹办迁移请求` 增加显式旧绑定：

```cpp
L2任务方法路径身份 旧当前路径;
L2实例方法身份 旧当前实例;
```

它们必须等于前态、正式当前选择和正式当前实例。结果增加退出后的历史投影：

```cpp
std::optional<L2任务方法路径事实> 旧路径;
std::optional<L2实例方法事实> 旧实例;
```

返回的是节点历史投影；节点本身不退出，只退出“当前选中路径”和“当前实例方法”关系。

### 6.2 单一原子写集

迁移写集必须同时：

```text
创建目标未达成待重筹办治理状态
建立新的任务当前治理状态关系
退出旧任务当前治理状态关系
退出旧当前实例方法关系
退出旧当前选中路径关系
保留旧路径节点、旧实例节点、旧实际结果、首态和裁决证据
```

不得依次调用三个公开写入口。任一当前关系缺失、多项、端点不符或代次漂移均零写拒绝。

通用 `退出当前实例方法`、`退出任务方法路径` 空壳不在本叶实现；它们不能替代本业务原子迁移。

### 6.3 读回

迁移成功或精确重复后必须互证：

- 当前治理状态唯一且为目标未达成待重筹办；
- 当前实例关系为空；
- 当前选中路径关系为空；
- 旧路径、旧实例、旧实际结果、首态和裁决证据仍能按历史截止读回；
- 原共同事实截止未被首态或迁移发布代次改写。

## 7. 任务管理处理槽

### 7.1 状态

新增 `任务重筹办处理槽阶段`，公开 ABI 固定为：

```cpp
enum class 任务重筹办处理槽阶段 : std::uint8_t {
    待处理 = 1,
    资源等待 = 2,
    合法等待 = 3,
    已形成 = 4,
    精确重复 = 5,
    当前性漂移 = 6,
    引用冲突 = 7,
    入口拒绝 = 8,
    内部终止 = 9
};
```

快照保存原意图、尝试次数、提供者结果和可选下一筹办工作包。槽以 `意图幂等键` 为键；同键同义返回精确重复，同键异义返回冲突且不覆盖原槽。合法等待槽只通过 `请求重试任务重筹办处理槽(意图幂等键)` 重新排队；重复调用在同一槽已排队时只返回真，不得复制队列项。资源等待由管理循环自动重排，不要求上游重新提交意图。

### 7.2 公平与锁

管理线程使用现有条件变量唤醒。结果上行队列与重筹办队列均非空时按轮转选择，禁止一侧长期饥饿。调用业务提供者、DATA 或自我线程时不得持有任一队列锁。

### 7.3 结果映射

```text
已形成 / 精确重复 → 槽终态，冻结唯一工作包
合法等待           → 保槽，等待相同意图显式重试
资源失败           → 原槽自动重排，短暂让出执行
当前性漂移         → 结构化终态，不自动升级原共同截止
引用冲突 / 入口拒绝 → 结构化终态，不进入筹办
内部错误           → 内部终止
```

## 8. 自我线程生产消费

`任务结果治理后继输入` 和处理槽快照增加两笔写入身份，并从治理消息载荷逐字段冻结：

```cpp
L2结构幂等身份 任务治理首态写入幂等身份;
L2结构幂等身份 任务重筹办迁移写入幂等身份;
```

`任务结果治理处理槽状态` 在既有 1..11 后增加：

```cpp
重筹办意图待提交 = 12,
重筹办意图已提交 = 13
```

`任务结果治理处理槽快照` 增加：

```cpp
std::optional<任务重筹办意图> 重筹办意图;
std::optional<任务重筹办意图提交结果> 重筹办提交结果;
```

内部处理槽同样必须缓存唯一 `任务重筹办意图`。队列满时发布“重筹办意图待提交”和原提交结果，沿现有 `请求重试任务结果治理处理槽()` 使用同一意图重试；不得从冻结裁决重新生成意图。

目标裁决形成后的分支：

```text
目标已达成
→ 保持“待验证后完成”快照
→ 不提交重筹办意图
→ 本叶仍以结构化退出等待后续路径验证计划

目标未达成
→ 形成一次任务重筹办意图
→ 提交端口已接收或精确重复
→ 发布“重筹办意图已提交”处理槽快照
→ 推进路由下标、清理内部当前槽并继续治理循环
```

提交端口未绑定属于内部不一致；停止产生新意图后不得再提交，但已提交意图由任务管理线程排空。

自我线程对提交结果的映射固定为：

```text
已接收 / 精确重复
→ 重筹办意图已提交，推进当前路由

已拒绝 + 队列已满
→ 重筹办意图待提交，保留同槽等待显式重试

已拒绝 + 协议拒绝 / 幂等冲突
→ 输入拒绝，不推进路由

已拒绝 + 端口未运行 / 已停止 / 内部状态冲突
→ 内部终止

内部错误
→ 内部终止
```

停止锁存与提交并发时，以停止函数的互斥收敛结果为准；已经被端口接收的意图不得回退成未提交。

## 9. 装配与生命周期

### 9.1 装配

`任务结果生产运行包` 持有：

```text
任务实际结果上行桥
任务目标未达成重筹办触发提供者
任务管理线程
任务工作线程
```

构造完成后把任务管理线程以 `任务重筹办意图提交端口` 一次绑定到自我线程。自我线程只依赖抽象端口模块，不能 import 任务管理线程。

普通应用启动顺序调整为：

```text
构造并停门自我线程
→ 构造任务结果生产运行包并完成端口绑定
→ 启动任务管理线程和任务工作线程
→ 开放自我治理运行门
```

### 9.2 停止

固定顺序：

```text
自我线程停止形成新的重筹办意图
→ 运行包拒绝新的任务派发和工作结果
→ 排空任务工作结果、结果上行和已接收重筹办意图
→ 解除自我线程端口绑定
→ 收口任务管理线程
→ 最后停止自我线程
```

解除绑定必须与正在进行的提交互斥，不能留下悬空端口。已经进入任务管理槽的意图不能因停止丢失；本叶不提供跨进程恢复。

## 10. 验证矩阵

生产级专项必须经过：

```text
任务结果生产运行包
→ 任务工作线程
→ 任务管理线程结果上行
→ 正式任务实际结果与治理消息
→ 自我治理邮箱、批次路由和目标裁决
→ 重筹办意图提交端口
→ 任务管理线程重筹办槽
→ 业务提供者
→ DATA-L2迁移与独立读回
→ 下一筹办工作包
```

最低矩阵：

1. 目标未达成首次链形成一个首态、一个待重筹办状态和一个工作包；
2. 精确重复工作结果、治理消息或重筹办意图不形成第二首态、第二迁移或第二工作包；
3. 三笔任务 owner 写入身份缺失、相同或同键异义时零新写；
4. 当前实例关系与当前选择关系在迁移代次同时退出，旧节点及全部历史可读；
5. 原共同截止保持不变，发布代次不倒灌为裁决截止；
6. 目标已达成只停在待验证后完成，不形成重筹办意图；
7. 队列满和资源失败保留原意图，重试不重新取邮箱、不重新裁决、不重新生成身份；
8. 当前性漂移、引用冲突、入口拒绝和内部错误分账；
9. 来源任务序号变化不改变正式执行轮次；
10. 停止阶段排空已接收意图且端口无悬空调用；
11. 双配置构建和真实线程专项通过；
12. 零新路径、零新实例、零任务完成、零需求满足、零结算、零价值或学习写入。

不新增生产故障注入入口；无法自然制造的资源失败分支保留为 `NOT_RUN`，不得用日志或返回码冒充机器事实。

## 11. 精确公开 ABI 与物理位置

执行者不得改变下列公开身份、签名、可见性或物理所有者。局部私有 helper 可以在同一所有者模块内按机械需要建立，但不得形成第二入口。

### 11.1 意图协议模块

文件 `海中鱼巣/线程/协议.任务重筹办意图.ixx` 是真实模块，工程以 `ClCompile` 登记，导出：

```cpp

bool 任务重筹办意图相同(
    const 任务重筹办意图& 左,
    const 任务重筹办意图& 右) noexcept;

enum class 任务重筹办意图提交状态 : std::uint8_t {

    精确重复 = 2,
    已拒绝 = 3,
    内部错误 = 4
};

enum class 任务重筹办意图提交拒绝原因 : std::uint8_t {
    无 = 0,
    端口未运行 = 1,
    已停止 = 2,
    协议拒绝 = 3,
    幂等冲突 = 4,
    队列已满 = 5,
    内部状态冲突 = 6
};

struct 任务重筹办意图提交结果 final {
    任务重筹办意图提交状态 状态 =
        任务重筹办意图提交状态::已拒绝;
    任务重筹办意图提交拒绝原因 拒绝原因 =
        任务重筹办意图提交拒绝原因::无;

};

    virtual ~任务重筹办意图提交端口() = default;

```

`成功()` 当且仅当状态为“已接收”或“精确重复”且拒绝原因为“无”。拒绝状态必须携带非“无”原因；内部错误固定携带“内部状态冲突”。

协议模块只负责纯值完整性、同义比较和抽象提交边界；不持有队列、DATA 服务或线程。

### 11.3 自我线程

现有 `任务结果治理后继输入`、`任务结果治理处理槽状态` 和 `任务结果治理处理槽快照` 按 §8 精确扩展；不得建立第二份同义快照。现有 `请求重试任务结果治理处理槽()` 同时允许“重筹办意图待提交”状态，且只重试内部槽缓存的原意图。

在现有 `海中鱼巣.线程.创建.自我线程` 的 `自我线程` 公共面增加：

```cpp
bool 绑定任务重筹办意图提交端口(
    任务重筹办意图提交端口& 端口) noexcept;

bool 停止任务重筹办意图生产并解除端口(
    任务重筹办意图提交端口& 端口) noexcept;
```

绑定只允许从空绑定到唯一端口；相同端口重复绑定返回真，不同端口返回假。停止函数先锁存“不得形成新意图”，等待或互斥收敛正在提交的调用，再只解除参数所指同一端口；不同端口返回假。它不停止治理邮箱或物理自我线程。

停止解除对同一已绑定端口幂等：首次成功解除后以保存的最后绑定端口身份识别同一参数，重复调用返回真；从未绑定、不同端口或停止锁存后再次绑定均返回假。自我线程析构前必须已经解除端口，析构不得调用悬空端口。
