## 1. 目标、基线和拆分裁决

当前代码基线须在发布前以届时 `main == origin/main` 的真实提交重核并写回。当前 main 不存在本设计目标的公共合同头、类型化记录仓 / 参与者、新域关系 22 写入、新域 4170 私仓或四个 NT-C2 读取 / 退役入口。历史对象 `e19ad70d` 只作规模与差距来源，不是当前接口或施工依据。

四个业务闭环：

1. 类型化记录基础；
2. 关系 22 单槽初始发布和当前值换代；
3. 4170 多槽批次发布；
4. 跨域读取和退役投影。

批次仓键仅为 `记录.批次身份.编号`，按无符号升序比较；同一键最多一条已发布记录。F-W105 在参与者私有单节点 `std::list<节点直接特征批次记录仓条目> 待插入条目组_` 中预分配候选，仓条目发布位固定为 false：新键先构造临时 list 节点和成功返回材料，全部成功后才无分配 splice，返回 `成功/无/记录副本`；私有同键同义先复制幂等返回材料，复制成功后不追加并返回 `幂等读回/无/记录副本`；同键异义返回 `入口拒绝/同键异义/空材料`。F-W106 在取得独占锁前保存唯一节点迭代器，逐项目分别调用准备视图的 `节点是本会话候选`、`读取候选节点类型`、`读取候选节点稳定主键`：每个新值必须是本会话特征值候选且主键命名域正确，初始项目的实例槽也必须是本会话特征候选且属于实例槽命名域，换代实例槽不作候选要求；随后持锁逐字段比较已发布同键，同义返回核心 `版本漂移`，异义返回核心 `身份冲突`，未找到才用 `list::splice` 无分配移入仓。F-W108 只把该仓条目发布位置 true、把仓结构版本加一并释放锁；F-W109 逆序 erase 未发布节点。版本溢出、候选分配失败或记录 / 返回材料复制失败返回资源失败且仓保持调用前状态。F-W112/F-W113 只在共享锁内扫描仓条目发布位为 true 的记录并复制自有结果；任何未发布条目被普通读取观察到均为内部不一致且零材料。F-W112 的按值筛选覆盖 `项目.新特征值 == 输入` 和 `项目.写前当前值 == 输入` 两个角色，恰一角色命中时同一项目只复制一次，两者同时命中为内部不一致。

三个写根不得在执行器释放独占许可后再调用“当前”组合读回来证明刚提交结果。回调在全部核心候选和领域候选读回完成后，直接用这些确切句柄与记录材料构造 `候选返回材料`；执行器返回 `已提交` 后调用同一栈上记录参与者的 F-A110 取得本事务确切结构版本，再返回 `成功/无/候选返回材料/本事务版本`。若核心结果不是已提交、F-A110 非成功或候选材料缺失，按第 8.2 节返回零材料；后继事务即使已推进当前槽，也不得改变本次结果。

F-W110 是历史批次读回，不调用 F-W103。它先取得一次节点直接结构读取许可，再调用 F-W113 取得不可变批次记录和 F-A109 固定类型化记录仓版本；随后一次读取全部关系审计，自有副本按每个项目保存的 `宿主关系/定义关系/发布后当前关系/来源关系` 四个完整句柄精确匹配关系编号与版本，并逐字段核对类型、顺序和端点。类型化记录通过 F-A107 按项目 `新特征值` 读取，再选择 `发布后原始值版本`；返回前末次 F-A109 必须仍等于固定版本。全部项目按 `项目顺序号` 形成自有材料后返回 `成功/无/材料/固定版本`；批次未找到返回 `合法未找到/无/空材料/固定版本`，重复、悬空、版本变化或任一关系 / 记录不一致返回零材料。槽后续换代、关系后续失效或节点后续退役不改变已保存的批次历史语义。

三个写根的事务外预读也受结构许可约束。F-W101 和 F-W102 各自先取得一次 `节点直接身份结构读取许可`，把该许可传给 F-W103，并在同一许可内完成端点、稳定主键、关系审计、记录和高水位的全部第一写前读取；进入独占执行器前明确释放。F-W104 在一次许可内完成批次账未找到、宿主/定义/来源/写前三元组、关系唯一性和两命名域高水位读取；账找到分支先释放，再由 F-W110 自己取得完整历史快照；真实分支也先释放再进入执行器。许可失败原样返回 `许可竞争/并发许可失败`。

F-A106/F-A107/F-A109 和 F-W112/F-W113 是单仓自有副本访问器，允许专项或单仓诊断在不持结构许可时独立调用，但该结果只证明该仓一次锁内状态。任何组合节点、关系、索引、记录或批次的业务完成声明必须由 F-W101—F-W104、F-W110、F-R101—F-R104 在同一结构读取或独占许可内消费这些访问器；禁止把多个无结构许可的单仓结果拼成同代次材料。

关系 22 反向角色 1 / 3 和历史关系读取使用 `正式关系仓库::读取全部关系审计()` 的自有副本，在数据操作层按关系编号、版本筛选最高当前记录。实例槽 / 特征值稳定主键的权威定位仍使用 `节点直接身份仓库::读取稳定主键当前身份()`；可重建索引只形成下列确定映射，不裁决存在、基数或幂等：

```cpp

inline constexpr std::uint32_t 实例特征槽索引命名域 = 0x50324101U;
```

槽索引键字段依次为 `{节点直接特征索引所有者身份, 实例特征槽索引命名域, 1, 1, 实例槽主键.键值}`；值索引键把命名域换为 `特征值索引命名域`、键值取特征值主键。两者目标种类固定 `索引目标种类::节点`，节点字段取同事务新节点完整句柄，关系字段为空。每个新槽形成槽、值两个索引；换代形成新值一个索引；批次逐初始 / 换代项目形成相应 2 / 1 个索引。创建后必须用 `会话.读取索引物理键(物理键)` 读回并逐字段等于候选；已有同键同目标只能在事务外 / 第一写前完整幂等路径收口，真实候选路径出现核心 `幂等读回` 为阶段不一致，已有同键异目标映射同键异义。该 O(R) 关系扫描和确定索引是本版本正确性实现；后继其它复杂业务身份索引必须另行冻结。

节点稳定主键还受当前核心“每命名域严格高水位 + 1”约束，但高水位校验只进入真实新建分支，不能先于幂等分类。F-W101 先读取两稳定主键当前身份：两键已占用时完成全结构同义 / 异义分类，只有两键均未找到才分别调用 `节点仓.读取命名域高水位(节点稳定主键命名域::实例特征槽身份)` 和 `读取命名域高水位(节点稳定主键命名域::特征值身份)`，请求两个键值必须各等于对应高水位 + 1。F-W102 先按新值稳定主键和写前三元组完成幂等 / 漂移分类，只有新值键未找到且当前仍为写前值时才复核值域高水位。F-W104 先按批次账完成同义 / 异义 / 未找到分类，只有账未找到才把全部初始槽键和全部新值键分别复制为自有 `(键值, 项目顺序号)` 组：每组键值不得重复，排序后必须恰为对应预读高水位后的连续区间。核心回调按命名域先创建全部槽键、再创建全部值键，每组按键值升序创建，并把产生的句柄按项目顺序号写回槽位数组，业务输出仍按项目顺序号。真实新建分支的请求间隙、重复或非连续返回 `入口拒绝/错版本`；预读后并发推进导致回调首个预期键被核心以 `入口拒绝/版本漂移/身份冲突` 拒绝时，保存 `写前漂移/读取期间版本变化` 并显式撤销；其它已经通过高水位与稳定主键预读的核心入口拒绝才是 `内部错误/事务阶段不一致`。不得在持有核心独占许可时直接调用仓的共享锁 `读取命名域高水位()`。

新槽业务唯一性必须同时扫描角色 1 与角色 2。F-W101 在第一次写前和执行器回调第一候选前，均从全关系审计中筛选“角色1源=请求宿主且有效”的全部槽，再为每槽筛选唯一有效角色2；若任何既有槽的角色2目标等于请求抽象定义，则仅当该槽和请求两主键指向的完整同义结构一致时走幂等，否则返回 `入口拒绝/同键异义`。角色1/2 悬空、多重或未知顺序在前置已通过后返回 `内部错误/基数不满足`。F-W104 对每个初始项目执行同一检查，并额外在批次内以 `(请求.宿主完整句柄, 项目.抽象定义完整句柄)` 去重；重复初始定义、与已发布槽重复定义、重复实例槽主键、重复新特征值主键或两个换代项目引用同一实例槽均在第一写前返回 `入口拒绝/同键异义`。上述集合在回调内使用锁内关系审计和已映射句柄再复核；漂移保存准确领域结果并显式撤销。

模块依赖固定为“公共头 -> #340 参与者 -> #382 数据操作 / 服务；公共头 + #340 访问器 + #382 批次访问器 -> #383 数据操作 / 服务”。预冻结合同只允许设计闭合，不冒充接口骨架或真实能力；消费者不得补同名 DTO、仓、服务或别名。

## 8. 核心状态映射与全分支事务矩阵

### 8.1 参与者阶段机和精确核心结果

两个领域参与者的内部阶段只允许：

```text
空 -> 已登记 -> 已准备 -> 已确认待发布 -> 已发布
 \       \          \             \
  +-------+----------+---------------> 已撤销
```

F-A102/F-W106 准备成功和 F-A103/F-W107 确认成功均精确返回 `{候选已确认, 0, 0, 0}`；F-A105/F-W109 撤销成功精确返回 `{候选已撤销, 0, 0, 0}`。准备阶段不返回 `已提交` 或 `幂等读回`；已发布同义必须在进入执行器或回调第一写前收口。`空`、`已登记`、`已准备`、`已确认待发布`、`已撤销` 的撤销均是成功幂等撤销；这保证执行器在回调早期失败时逆序撤销全部 span 参与者不会因尚未登记而隔离事务域。已发布后撤销、错阶段确认、候选反向位置损坏返回 `{内部不一致,0,0,0}`；仓许可竞争返回 `{许可拒绝,0,0,0}`；确定分配失败返回 `{资源失败,0,0,0}`；同键异义返回 `{身份冲突,0,0,0}`。

### 8.2 执行器到领域结果映射

| 核心状态 | 领域状态 / 原因 | 使用条件 |
| --- | --- | --- |
| `已提交` | `成功 / 无` | 仅执行器共同发布后；必须有回调捕获的确切候选材料和 F-A110 本事务版本 |
| `幂等读回` | `内部错误 / 事务阶段不一致` | #382 不调用核心幂等入口；出现即合同漂移 |
| `入口拒绝` | `内部错误 / 事务阶段不一致` | 公开入口校验已在执行器前完成；无效执行器/回调/span 属内部错误 |
| `许可拒绝` | `许可竞争 / 并发许可失败` | 事务域或领域仓许可竞争 |
| `版本漂移` | `写前漂移 / 读取期间版本变化` | 独占许可内重读与请求不再一致 |
| `候选已撤销` | 优先返回回调捕获领域失败；无捕获则 `内部错误 / 事务阶段不一致` | 显式 `请求撤销()` 后执行器成功撤销 |
| `候选已确认` | `内部错误 / 事务阶段不一致` | 只允许参与者内部阶段返回，不能作为执行器最终结果 |
| `身份冲突` | `入口拒绝 / 同键异义` | 稳定主键、记录键或批次键已占用且异义 |
| `资源失败` | `内部错误 / 资源失败` | 分配或容器操作失败，零半结构 |
| `内部不一致` | `内部错误 / 事务阶段不一致` | 若已具名为读回矛盾则改用 `权威读回不一致` |

三个写根在栈上持有 `std::optional<合同无值结果> 回调领域失败`。回调内 F-A101/F-W105 或任一领域准入失败时，先写入首个准确领域状态/原因，再调用公开 `会话.请求撤销()` 并立即结束回调；不得抛异常表达逻辑失败，也不得继续 `请求提交()`。执行器返回后，只有核心结果为 `候选已撤销` 才原样返回所捕获领域分类；核心撤销失败 / 隔离覆盖为 `内部错误 / 事务阶段不一致`。回调未捕获失败时只允许调用一次 `请求提交()`。

执行器外的高水位分组、排序、去重集合、规范化请求副本和参与者 / 临时结果构造全部在第一写前完成；捕获 `std::bad_alloc` 或等价确定资源失败后直接返回 `内部错误/资源失败`、零写、零材料。回调内形成候选返回材料、批次引用组、批次记录或项目映射数组的分配 / 复制也必须在各操作边界捕获资源失败，写入首个 `内部错误/资源失败`、调用 `会话.请求撤销()` 并结束回调。只有非资源未知异常允许透出到现行执行器 `catch (...)` 并映射为 `内部错误/事务阶段不一致`；不得把确定分配失败降级为阶段错误。

F-W104 的两个栈参与者和执行器实参顺序不是实现选择，唯一代码形态固定为：

```cpp
特征值类型化记录事务参与者 记录参与者{记录仓_};
节点直接特征批次记录事务参与者 批次参与者{批次记录仓_};
std::array<节点直接身份结构写入事务参与者*, 2> 参与者组{
    &记录参与者,
    &批次参与者
};
const auto 核心结果 = 执行器_.执行(
    回调,
    std::span<节点直接身份结构写入事务参与者* const>{
        参与者组.data(),
        参与者组.size()});
```

回调只借用上述两个栈参与者，执行器返回前 span 不得保存或越界。核心执行器按数组正序调用准备和确认，完成核心发布后仍按数组正序调用参与者最后发布；任一失败先按数组逆序调用批次参与者、记录参与者撤销，再由现行核心会话撤销核心候选。执行侧不得交换顺序、改用动态容器、拆成两个执行器调用或让 F-W105 自行提交。

### 8.4 专项确定故障注入合同

资源失败验证不得依赖真实内存耗尽、偶发 `bad_alloc` 或降低机器可用内存。三份计划隔离编译生产模块和专项模块时统一定义：

```text
HY_NT_P2A_DETERMINISTIC_FAULT_INJECTION=1
```

## 9. 当前真实接口行为核对

发布前当前接口复核基线必须与本文第 1 节记录的 `main == origin/main` 提交完全相同；该基线已核对：

- 会话具有创建节点 / 关系候选、失效关系、读取节点 / 关系 / 审计和请求提交；节点仓具有稳定主键当前身份读取。
- 执行器普通入口接收回调和参与者 span，按登记顺序准备 / 确认、逆序撤销、结构先发布后参与者发布。
- 参与者基类四阶段精确存在，`完成发布()` 为 `void noexcept`。
- 正式关系仓提供 `读取全部关系审计()` 与正向 `读取有效关系组()`；没有按目标反向关系入口，因此本设计明确使用全审计扫描，不虚构接口。
- 核心通用关系基数不能表达关系 22 逐角色基数，因此本设计把完整裁决固定在数据操作层。
- 旧特征路径依赖旧主信息 / 参与者 / 关系，不可直接复用或 import。
