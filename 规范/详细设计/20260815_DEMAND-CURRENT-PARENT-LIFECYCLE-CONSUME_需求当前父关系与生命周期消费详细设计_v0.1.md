# 需求当前父关系与生命周期消费详细设计 v0.1

日期：2026-08-15

计划身份：`DEMAND-CURRENT-PARENT-LIFECYCLE-CONSUME`

## 1. 目标与完成边界

实现单一业务叶：

```text
BIZ-L4-002-04-02-01 v0.2
需求业务服务::读取需求当前父关系与生命周期
-> DATA-EXT-12 按需求和非零共享截止读取完整当前需求、生命周期与可空唯一父关系
```

调用方给出需求身份、运行代次、父级共享事实截止 `G0`以及范围 / 规则版本。本叶一次调用 DATA-EXT-12，逐字段互证当前需求、可空父关系和有父时的完整父端点后，返回调用方拥有的不可变值式结果。无父是合法成功，只表示当前结构根。

本叶全程只读，不读取活动子关系、路径角色、权重、目标满足、任务或结算，不建立或修改需求。完成最多证明这个具名 BIZ provider 真实消费 DATA-EXT-12；不证明完整父链、活动路径、根需求组、当前任务树、父级 G0/G1 或自我治理业务闭环。

## 3. 基础数据公开消费合同

### 3.1 唯一 DATA 操作

DATA-EXT-12 必须提供具名操作：

| 操作 | 请求 | 成功返回 | 合法空与失败 |
| --- | --- | --- | --- |
| 按需求和指定截止读取当前父关系与生命周期 | 合同版本、非零需求身份、非零 G0、事实范围版本、需求范围版本、需求树规则版本、父关系规则版本、读取规则版本 | 完整当前需求事实、生命周期、可空唯一当前父关系、有父时完整父端点、全部版本回显、结果截止 G0 和零变更代次 | 无父为已读取成功；需求未找到 / 已退出分账；漂移、许可拒绝、资源失败和内部不一致分别返回 |

成功事实至少携带：

```text
当前需求：身份及来源、主体、目标宿主、目标特征、L2目标状态合同身份、来源证据、当前授权、生命周期
当前父关系 optional：关系身份及来源、子需求、父需求、关系生命周期、需求树版本、父关系版本
当前父端点 optional：身份及来源、主体、生命周期、需求树版本
目标、来源授权、需求生命周期、父关系和父端点各自结构版本
当前需求、父关系和父端点的单项事实截止 G0
```

父关系和父端点必须同时为空或同时有值。DATA 负责完整枚举当前父关系并保证成功形状至多一个；BIZ 不接收候选组后自行挑选。

### 3.2 版本和实例绑定

普通应用在构造 `需求业务服务` 时注入不可变 `需求当前父关系固定配置`：运行代次、事实范围版本、需求范围版本、需求树规则版本、父关系规则版本和读取规则版本。每次请求必须逐字段匹配有效固定配置；除运行代次外的全部范围 / 规则版本原样进入 DATA 请求并由成功结果回显。

DATA-EXT-12 必须与同一自我治理组合中的其它结构服务来自普通应用同一个 `L1事实基座运行包`。请求只使用父级给出的非零 G0，不请求最新，不使用 owner 子截止、发布见证或缓存版本。

### 3.3 目标状态合同门禁

当前需求中的目标状态引用使用 `DATA-L2-ABSTRACT-TARGET-STATE-CONTRACT-CRUD v0.1` 预冻结的独立 `L2目标状态合同身份`。它不得转换为实例 `L2状态身份`，也不得用裸值、字符串、默认目标或需求 owner 私有编码代替。真实接线必须等待该 DATA 计划结果和最终 ABI；本叶不读取合同正文、不比较目标。

## 4. BIZ 类型与物理位置

### 4.1 值式合同头

新增：

```text
文件：海中鱼巣/领域/需求当前父关系.数据.h
所有者：BIZ 需求当前父关系生命周期值式合同
可见性：只由需求业务服务、父链组合器和专属验证消费
```

冻结语义类型：

```cpp
inline constexpr std::uint32_t 需求当前父关系合同版本 = 1;

struct 需求当前父关系固定配置 final {
    std::uint64_t 运行代次;
    std::uint64_t 事实范围版本;
    std::uint64_t 需求范围版本;
    std::uint64_t 需求树规则版本;
    std::uint64_t 父关系规则版本;
    std::uint64_t 读取规则版本;
};

struct 需求当前父关系生命周期读取请求 final {
    std::uint32_t 合同版本;
    std::uint64_t 运行代次;
    std::uint64_t 事实范围版本;
    std::uint64_t 需求范围版本;
    std::uint64_t 需求树规则版本;
    std::uint64_t 父关系规则版本;
    std::uint64_t 读取规则版本;
    L2需求身份 需求;
    std::uint64_t 共享事实截止;
};

struct 当前需求值式事实 final {
    L2需求身份 需求;
    L2节点族身份来源事实 身份来源;
    L2存在身份 主体;
    目标宿主强类型身份 目标宿主;
    目标特征强类型身份 目标特征;
    L2目标状态合同身份 目标状态合同;
    需求来源证据值式组 来源证据;
    需求授权事实值式组 当前授权事实;
    需求结构生命周期 生命周期;
    std::uint64_t 目标结构版本;
    std::uint64_t 来源授权版本;
    std::uint64_t 生命周期版本;
    std::uint64_t 事实截止;
};

struct 当前父需求端点值式事实 final {
    L2需求身份 需求;
    L2节点族身份来源事实 身份来源;
    L2存在身份 主体;
    需求结构生命周期 生命周期;
    std::uint64_t 需求树版本;
    std::uint64_t 生命周期版本;
    std::uint64_t 事实截止;
};

struct 当前父需求关系值式事实 final {
    需求父关系强类型身份 关系;
    需求关系身份来源事实 身份来源;
    L2需求身份 子需求;
    L2需求身份 父需求;
    需求关系生命周期 生命周期;
    std::uint64_t 需求树版本;
    std::uint64_t 父关系版本;
    std::uint64_t 生命周期版本;
    std::uint64_t 事实截止;
};

struct 需求当前父关系生命周期值式结果 final {
    当前需求值式事实 当前需求;
    std::optional<当前父需求关系值式事实> 当前父关系;
    std::optional<当前父需求端点值式事实> 当前父端点;
};

enum class 需求当前父关系生命周期读取状态 : std::uint8_t {
    已读取 = 1,
    请求拒绝 = 2,
    未找到 = 3,
    已退出 = 4,
    当前性漂移 = 5,
    提供者拒绝 = 6,
    资源失败 = 7,
    内部不一致 = 8
};

struct 需求当前父关系生命周期读取结果 final {
    std::uint32_t 合同版本;
    需求当前父关系生命周期读取状态 状态;
    需求当前父关系生命周期读取请求 请求回显;
    std::uint64_t 事实截止;
    std::optional<需求当前父关系生命周期值式结果> 值;

```

其中目标、来源 / 授权、生命周期和关系身份均须在 DATA-EXT-12 最终 ABI 后机械匹配；执行者不得自造裸编码或布尔值。只有 `已读取`携带 optional 值；无父表示结果 optional 有值，而内部两个父 optional 同时为空。

### 4.2 需求业务服务

扩展上一叶建立的同一文件 / 模块：

```text
文件：海中鱼巣/领域/服务.需求.ixx
模块：海中鱼巣.领域.服务.需求
所有者：DATA 之外的需求读取业务解释
```

最终形态在上一叶构造基础上增加父关系固定配置：

```cpp
class 需求业务服务 final {
public:
    需求业务服务(
        const 需求结构服务& 数据服务,
        const 需求当前根组固定配置& 根组固定配置,
        const 需求当前父关系固定配置& 父关系固定配置) noexcept;

    需求当前父关系生命周期读取结果 读取需求当前父关系与生命周期(
        const 需求当前父关系生命周期读取请求& 请求) const noexcept;
};
```

服务保存同一个 DATA-EXT-12 const 稳定借用和两份不可变操作配置，不建立第二需求服务、owner、L1 / 仓库入口或缓存。两份配置的运行代次、事实范围版本和需求范围版本必须相等；否则两个读取入口均在 DATA 调用前返回内部不一致。

## 5. 固定读取和互证顺序

```text
校验服务两份固定配置共同字段一致且父关系配置完整，否则内部不一致
-> 校验 BIZ 请求自身字段，否则请求拒绝
-> 匹配父关系固定配置，否则当前性漂移
-> 一次调用 DATA-EXT-12 按需求、G0和范围/规则版本读取当前父关系与生命周期
-> 精确映射未找到、已退出和其它 DATA 非成功
-> 互证结果合同、版本回显、截止=G0、零变更和完整当前需求
-> 互证父关系 optional 与父端点 optional 同形
-> 有父时互证子端点、父端点、主体、需求树版本、生命周期、来源和各单项截止
-> 一次形成完整候选
-> 无抛出交换到结果 optional
-> 返回已读取；无父仍成功
```

禁止先读需求、再跨调用枚举父关系或读取父端点；该旧形态会放大漂移窗口并复制 DATA-EXT-12 的完整结构读取职责。

## 6. 非成功映射与异常

| DATA / BIZ 情形 | BIZ 状态 | 载荷 |
| --- | --- | --- |
| 服务固定配置无效或两配置共同字段不等 | 内部不一致 | 空；零 DATA 调用 |
| BIZ 请求自身坏合同或零字段 | 请求拒绝 | 空；零 DATA 调用 |
| 合法请求与有效固定配置版本不等 | 当前性漂移 | 空；零 DATA 调用 |
| DATA 未找到指定需求 | 未找到 | 空 |
| DATA 指定需求已退出 | 已退出 | 空 |
| DATA 事实代次漂移或结果 / 单项截止不等于 G0 | 当前性漂移 | 空 |
| DATA 明确许可拒绝 | 提供者拒绝 | 空 |
| DATA 资源失败、`std::bad_alloc`、`std::length_error` | 资源失败 | 空 |
| DATA 请求拒绝、运行态未实现 / 未装配、多个当前父、父关系 / 端点半结构、错端点、错主体 / 树版本、坏生命周期或未知异常 | 内部不一致 | 空 |

任何非成功都不携带可消费需求、父关系、父端点或事实截止。

## 8. 验证矩阵与完成声明

专项至少覆盖：

- 两份固定配置共同字段不等 / 零字段、请求坏字段、合法请求版本不等三类零 DATA 调用和精确状态；
- G0及全部范围 / 规则版本原样传递和成功回显；
- 无父合法成功；一个完整父成功；父关系 / 父端点单边缺失、多个父、错子端点、错父端点、跨主体、错需求树版本；
- 当前需求、父关系、父端点身份来源、生命周期、来源 / 授权、版本和单项 G0 缺失或矛盾；
- 未找到、已退出、许可、漂移、资源和坏成功形状独立映射；
- 并发发布只产生完整 G0 成功或漂移，零混代拼装；
- 源码零 L1、owner、仓库、DATA 写、历史读取、活动 / 权重 / 满足 / 任务 / 结算、缓存和日志裁决；
- 根工程 Debug / Release、专项双配置、UTF-8 / XML、模块和工程唯一登记、生产零专项痕迹。

验证证据必须分层：真实 `需求结构服务` 的公开黑盒路径负责证明合法无父、有父、未找到、已退出及正式公开入口可构造的其它非成功；BIZ 自身可在 DATA 调用前触发的固定配置、请求和版本拒绝由同一公开业务入口动态证明。若 DATA 最终公开 ABI 已把多个父、半结构或错端点封闭为不可构造的 `内部不一致`，专项不得通过修改 DATA、增加生产 seam 或伪造真实服务对象来宣称动态命中，只能以 DATA 结构化拒绝的真实黑盒证据加 BIZ 防御分支静态源码证据分账记录。只有最终 ABI 本身允许调用方合法构造返回结果替身时，才可在生产外专项中动态覆盖该类坏成功形状；该替身不得进入生产工程或公开 ABI。

真实资源耗尽、私有 DATA 损坏、跨进程恢复、普通应用装配、完整父链 / 活动路径、任务树、G0/G1 和独立集成验收保持 `NOT_RUN`。

本设计发布不证明上一 BIZ 叶、目标状态合同、DATA-EXT-12 或本叶代码已经实现；未来本计划结果也只证明单需求当前父关系生命周期读取 provider，不证明父链、活动性、主需求、任务树或系统闭环。
