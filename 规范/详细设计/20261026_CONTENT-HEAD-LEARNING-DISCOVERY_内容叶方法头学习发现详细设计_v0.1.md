## 1. 唯一交付和机器边界

交付“内容叶任务按正式头 FT 粗召回 → 独立形成学习兴趣 → self fresh 复核并复用通用按 M 学习 → 有真实配对后知识通知重新筹办”。解决现内容分支提前返回、未发表候选就不能发现学习的循环依赖，不先要求 R 定位才允许学习。

这是任务筹办和 self/manager 的内部控制逻辑：需要改变的是本次反馈的消费进度及知识变化后的重新筹办调度，不直接改变现实特征或方法/任务虚拟存在的业务目标。本包不实现本能方法，不修改 D 字段，不生成 M/C/R，不定义新实际结果。学习仍只更新方法；模拟调用继续由通用参数生成器和隔离原函数完成。

粗召回命中只是探索兴趣，不证明方法作用于 F.current 的 D、不证明能力、条件具备、效果相容、可执行或目标满足。禁止将其发表为适用候选、完整无候选、缺失方法、采用材料或需求完成。没有绑定根 F/实际 D0，没有将任务或目标传给模拟函数作为隐藏输入；学习仅接收抽象方法 M。

本包不增加初始效果/作用定位声明、M↔T等待账、新学习消息/队列、持久兴趣节点或结果定位。方法头仍只由正式头字段解释，不改为头与 R 的并集投影。已有配对但内容定位尚不支持的方法不重复学习。内容结果定位、真实 D 写方法和模拟写回抽取另留后继缺口，不登记远端库存。

## 4. worker、manager与self的独立消费

worker按原召回值完整传递新增optional，不扁平复制丢字段。manager `推进工作消费`的内容结果分支除原复合提议独立读回外，调用新只读入口，要求来源T=原工作T、D、完整目标、查询、粗召回及可学习组均与worker发现相同；新查询未完成/资源失败沿原延后；来源已变化或值不相同，将该原工作判任务状态已变化，不偷换新发现继续使用旧工作。已有配对刚产生导致可学习组减少，也是原工作变化，不能把变化后的 M再次当空头。

manager只在原 `工作结果→方法召回→内容学习发现`保存本次值，不新建等待账。其“最近筹办结果”已先于self接收存在；稳定反馈定位仍只携带原工作，self必须通过manager独立读取完整值。

self `处理筹办反馈`在内容提前返回之前：核最近原工作一致；对含发现的内容叶再调用唯一task入口，完整值不相同必须按第7.1节将原工作变化裁决交回manager后收束，不用新值重触发旧发现，也不能仅结束self消息遗留manager软阻塞；资源/查询暂未完成返回 `nullopt`延后。匹配才按可学习组逐个调用下节的状态式 `发现方法学习`。空组不提交学习，直接按内容叶未支持收束。不得从 `方法查询`裸列表直接学习，不把所有粗命中当候选。

全部M已可靠处理后仍调用现 `处理复合目标提议`的内容叶空采用收束；不进入普通分类、缺失方法登记、执行前判断或结算。它只表示本次学习兴趣已交付/无需再次提交，内容能力仍未支持。若已有复合子需求采用前缀，先沿原前缀交接规则收口，不因新兴趣覆盖原回执。

## 5. self逐M幂等、未接纳与停止

将self `实现::发现方法学习`从void改为私有强类型返回，枚举就在该实现类内：

```cpp
enum class 方法学习发现状态 : std::uint8_t {
    已接纳=1, 已在途, 已处理仍无配对, 已有配对,
    无需学习, 暂缓, 停止取消
};
方法学习发现状态 发现方法学习(稳定编码 方法节点) noexcept;
```

正常旧候选调用可显式忽略返回，不改变原候选业务。新内容调用必须消费返回：

- 当前抽象M已有配对→已有配对；不再提交。新反馈fresh发现因此已变时应在前节先结束旧工作。
- 当前合法空头已在途→已在途；已有处理标记且不在途→已处理仍无配对。保留已处理标记，不删除后重学；学习无新知识的结束/异常不产生新循环。
- 本次提交已完成/精确重复且有效future已装入原在途槽→已接纳；接纳后任何槽/承诺异常走原工程硬错误，绝不能回滚假装未接纳。
- 线程尚未装配/未启动、邮箱满、资源失败等未接纳→暂缓；仅撤销本次预留和本次标记，记录原工程/资源诊断。原消息不得被当处理完成，按现资源重试间隔延后。
- 已请求停止/接收已关闭→停止取消；不新提交、不伪学习结束，self原停止链收束消息和真实已接纳future。
- 不存在/非本能/历史结算/不合法目标等沿现函数已定义非学习分支→无需学习；坏结构不能借此吞掉工程错误。

在 `消息项`增加本消息局部 `std::set<稳定编码> 已处理内容学习方法;`（仅M身份，不新账、不持久、不缓存定义）。对已接纳/已在途/已处理仍无配对/已有配对/无需学习标记该M的本消息交付已处理；暂缓立即返回nullopt，已处理前缀保留不重复提交。每次重入仍先fresh核完整发现；若来源变化，保留已实际接纳学习，不取消它、不回写旧目标，结束旧消息。停止取消按原停止状态结束，不进入等待收束。

旧 `在途学习/已处理学习方法`仍是跨消息按抽象M去重唯一机制；新增局部集合仅避免同消息资源重试重复劳动。学习提交仍仅M，不向学习线程发送T、D、目标或模拟参数；初始参数生成与函数执行不按方法名增加分支。

## 7. 内容叶空采用收束的并发门

在manager `提交已确认复合子需求`的局部 `定位有效`及最终manager锁增加原 `学习占用或旧筹办已失效已加锁(定位)`检查；返回任务状态不允许而不复活旧反馈。非叶复合子D的逐项承接和前缀保留原义，不借本包扩写其旧事务。

对 **原提议为合法单段内容叶、采用组为空、子目标组为空** 单独分支：

1. 锁外调用原 `核验复合子目标采用`并读取父T，核同父D/完整目标/叶形状；不建立子D/T。
2. manager最终锁内重新核原工作最近定位、源提议、停止、学习占用/原工作失效门。失效立即返回，不写状态或等待。
3. 门通过后，只写原manager控制集合：筹办软阻塞、等待目标复核、等待来源及清该原工作待反馈；不再调用 `修改任务状态(等待条件)`。父T保持原 `待查找方法`，只是manager调度挂起，不是执行许可。
4. 登记等待来源沿原 `需求材料未到`原因和原工作，不新建学习等待账；manager已有阻塞/等待调度路径必须保留这些控制集合。该状态在第6节全T扫描安全集合中，学习后原准备函数可无变化读回再清阻塞重查。

该窄分支不持manager锁调用task/需求/方法服务，不新增跨owner原子承诺。最终锁与学习事件安装/清理共享同一manager互斥：旧等待先登记则后续学习清除；学习先占用/失效则旧等待被拒绝。即使事件已完成，原工作失效记录/最近结果清除也拒绝原回执，不能写回陈旧等待。

### 7.1 fresh发现失配的原工作收束（v0.2）

执行侧实读发现：manager已将内容W1放入`待反馈任务/筹办阻塞任务`，T仍`待查找方法`；self只返回定位变化不会清这些控制项，而通用`提交自我筹办裁决`的任务状态变化尾部会登记“需核查”等待，亦不解除阻塞。普通等待扫描排除该状态，故原v0.1“结束旧消息”不足以形成重筹办。不得将此错误当方法业务失败或恢复为初始化主动学习。

本节仅使用现 `新自我筹办裁决`与`提交自我筹办裁决`，不新增接口、DTO、等待账或消息类型。self fresh结果为`来源已变化/不涉及`，或`已形成`但完整发现不等于旧发现时，构造：`定位=原筹办反馈定位`、`状态=任务状态变化`，唯一方法/配对/结果、执行前判断、本能采用、条件/因果回执全部为空。调用manager提交该裁决，不以新发现替换旧发现，不取消已接纳学习。资源/查询未完成仍在self原消息中延后，不先交变化裁决。

manager在`提交自我筹办裁决`通用“可进入执行前判断/等待任务”处理之前增加具名窄分支，步骤冻结：

1. 入口只考虑`任务状态变化`、原工作种类`查找方法`及上述所有执行/回执字段全空；形状不合法返回`入口拒绝`。manager短锁读取该T的`最近筹办结果`，要求同一完整原W1、处理状态`内容结果定位未支持`，且`工作结果->方法召回->内容学习发现`存在；复制原发现为局部值。无此具名来源者仍沿原通用路径，不改普通任务语义；若最近结果已不存在/原工作不同或已有学习/等待占用/原工作失效，返回`定位已变化`，不能把新工作当旧内容反馈。
2. 释放manager锁调用`任务服务->查询内容叶方法学习发现(T)`独立重查。`资源失败/查询未完成`返回`新自我筹办裁决接收状态::资源失败`，self保留原消息按原资源间隔重试；`来源已变化/不涉及`或`已形成`且完整发现不同于复制的原发现，才证明当前独立读取确有失配。`已形成`却没有发现属于损坏，走原工程终止链。
3. 若fresh已恢复为与原发现完全相等，返回`资源失败`，零控制变更；self重入后重新fresh，匹配便继续原学习发现/正常软阻塞，不因曾短暂变化释放仍有效的W1。此返回只表示重读控制，不记录业务失败或错误学习知识。
4. 最终manager锁内再次核：停止/已完成；同T的最近结果仍是该完整原W1、仍内容未支持且完整原发现未变；`学习占用或旧筹办已失效已加锁(原定位)`为false；无同T活动工作。已被学习事件接管、等待复核接管、旧工作标失效或新W1替换，返回`定位已变化`且零清理。不得清学习复核/等待复核占用或失效标记来强行通过。
5. 清理前核带来源的控制项：`最近自我筹办裁决[T]`若存在，必须其`裁决.定位`为该原定位；`等待来源[T]`若存在，必须其`原工作`为该完整原W1；`筹办延后重入`实际类型为`std::map<std::uint64_t, 新任务工作请求>`，该T项若存在，其值必须等于完整原W1。任何明确异来源控制项返回`定位已变化`、零清理，不能仅因T编码相同删除。没有来源身份的派生集合仅在上述原工作当前性核同后按本T移除。
6. 全部核同后，同manager锁一次执行不分配的erase：`最近筹办结果`、`待反馈任务`、`最近自我筹办裁决`、`筹办阻塞任务`、该原工作`等待来源`、`等待目标复核`、`筹办延后重入`、`上次等待材料`。只移除本T该旧工作的控制进度；不修改Vt/需求/方法、不动`阻塞任务`、执行/结果/恢复/贡献/结算材料、活动工作、学习事件/占用/失效标记、其他T或新W1材料。不新增“已接收变化裁决”长期记录。
7. 置`调度待触发=true`并`变化.notify_all()`，返回`已接收`。T保留待查找方法，后续正常调度从fresh正式来源重查；此处不直接派发工作、方法、学习或执行。首次清理完成后的同原裁决重入，因为最近原W1已退出，返回`定位已变化`即可，属于幂等终态，不要求保存新回执账。

self对`已接收/精确重复`以本次筹办已裁决结束，对`定位已变化`以旧定位变化结束，对`资源失败`返回nullopt保留重试，对`已停止接收`沿停止取消结束；形状/身份拒绝及内部错误按现工程边界处理，不能报告已清理成功。此窄分支只释放已经被独立证实失配的内容头发现工作，**fresh仍匹配、空可学组或已处理仍无知识的正常未支持目标继续第7节软阻塞**，不得每次反馈均清阻塞形成忙循环。

锁外查询与最终锁之间目标还可变化，本节不声称跨owner原子快照：释放旧控制只是撤销陈旧工作、要求正常fresh重查，不授予任何执行事实。最终manager锁足以防止与同一manager学习接管/新工作控制交错；若内容在此期间又恢复，最多多一次正常查询，不重复学习或采用，原M去重和下次fresh门保持。
