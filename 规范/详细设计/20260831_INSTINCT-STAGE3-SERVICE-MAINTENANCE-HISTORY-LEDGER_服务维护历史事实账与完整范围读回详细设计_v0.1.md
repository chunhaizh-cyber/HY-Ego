# INSTINCT-STAGE3-SERVICE-MAINTENANCE-HISTORY-LEDGER 服务维护历史事实账与完整范围读回详细设计 v0.1

日期：2026-08-31

设计身份：`INSTINCT-STAGE3-SERVICE-MAINTENANCE-HISTORY-LEDGER`

## 1. 目标与完成边界

本设计扩展现有唯一 `服务合同事实权威服务`，为服务合同、合同状态、到期未满足事件、服务进展 v2 和服务准备 v2 建立同 owner、永久、版本化的历史成员账，并提供指定事实代次范围 `(Gstart,G0]` 的完整集合读回。后继多完整秒 composer 只能消费本入口的成功结果，不能以当前集合、线程缓存、日志或某个历史截止的单点快照代替区间完整性。

本叶只建立历史成员登记、生产发布同步入账和完整范围读回。它不裁决合同终态，不发布合同预支、余款、准备补回或衰减段，不形成单调秒事实段，不调用多完整秒批量内核，不推进维护游标，不写 A / V、状态或动态，也不接普通应用和线程。当前没有服务合同 / 状态 / 到期事件的生产发布入口；本历史账不会为这些事实补造生产者，后继发布者必须在与其业务事实相同的 owner 写集中同步写入历史成员关系。

完成最多证明：从历史账首次登记事实代次起，所有经现行唯一生产写入口形成的服务进展 / 准备版本，以及未来按同一登记合同形成的合同 / 状态 / 到期事件版本，可以由一个范围读回入口完整枚举。这里的完整性由“唯一 owner 的生产入口在同一写集中强制入账 + 登记恢复互证 + 永久账闭包读回”共同成立，不声称 L1 能从未知历史身份反向发现任意绕过 owner 写入口的漏账。登记前历史不猜测；调用方请求的排除起点早于登记代次时返回覆盖边界不可用。

1. `服务合同事实权威服务` 已是合同、到期事件、进展和准备的唯一物理 owner；已有五组结构登记与当前集合读取。
2. `发布服务进展事实_v2`、`发布服务准备事实_v2` 会退出旧当前成员关系并形成新当前事实，但没有永久历史成员根；旧版本不能从当前闭包完整枚举。

5. `L2特征当前值变化` 已有“登记代次 + 永久账扫描 + 范围过滤 + 完整见证”的成熟模式，可复用其覆盖边界和状态矩阵，但服务事实仍由服务合同 owner 自己承载。
6. 工作区存在大量无关 SELF-GOVERNANCE WIP；本设计和后继施工不得覆盖、删除、清理、暂存或带入。

因此裁决为：在现有 owner 内追加永久历史账，而不是让 composer 扫描当前集合、重复调用单点历史读取或建立第二服务历史 owner。

## 4. 数据合同

### 4.1 版本与历史项

```cpp
inline constexpr std::uint32_t 服务维护历史事实账合同版本_v1 = 1;
inline constexpr std::uint32_t 服务维护历史事实账结构登记版本_v1 = 1;

enum class 服务维护历史事实类别_v1 : std::uint8_t {
    服务合同 = 1,
    合同状态 = 2,
    到期未满足事件 = 3,
    服务进展 = 4,
    服务准备 = 5
};

struct 服务维护历史成员身份_v1 {
    服务维护历史事实类别_v1 类别;
    稳定编码 事实身份;
    std::uint64_t 事实版本;
    std::uint64_t 形成事实代次;
};
```

成员身份是完整见证键，不是新的持久节点身份。各类别映射固定为：合同使用合同身份 + 合同代次；合同状态使用合同身份 + 状态版本；到期事件使用事件身份 + 合同终态版本；进展 / 准备使用事实身份 + 形成事实代次。`形成事实代次`必须等于载荷形成代次和历史成员关系创建代次；同一四元组全组唯一。

五类公开历史投影固定为：

```cpp
struct 服务合同历史投影_v1 {
    服务合同事实_v1 事实;
    std::optional<std::uint64_t> 退出当前事实代次;
};
struct 服务合同状态历史投影_v1 {
    服务合同状态事实_v1 事实;
    std::optional<std::uint64_t> 退出当前事实代次;
};
struct 服务到期事件历史投影_v1 {
    服务到期未满足事件事实_v1 事实;
    std::optional<std::uint64_t> 退出当前事实代次;
};
struct 服务进展历史投影_v1 {
    服务合同关联进展事实_v2 事实;
    std::optional<std::uint64_t> 退出当前事实代次;
};
struct 服务准备历史投影_v1 {
    服务准备当前事实_v2 事实;
    std::optional<std::uint64_t> 退出当前事实代次;

```

它们是可重建只读投影，不取得第二事实 owner。合同 / 状态 / 进展 / 准备的退出当前边界来自其当前索引成员关系；到期事件是永久事件，退出字段固定为空。

结果字段顺序冻结为：

```text

```

五类历史投影均由“原业务事实 + optional<退出当前事实代次>”组成。退出代次只取对应当前成员关系的正式退出边界；永久事件等本来不使用当前成员关系的类别固定为空。退出代次若存在，必须大于形成代次且不晚于 `G0`。

各组只包含 `排除起始事实代次 < 形成事实代次 <= G0` 且绑定请求自我的事实。总成员数等于五组数量之和。每组按“形成事实代次、业务身份、版本”严格升序；见证组按“形成事实代次、类别、事实身份、版本”严格升序。

`数量预算`约束五组合计数量；0 非法。空范围命中是合法成功，但排除起点仍必须不早于历史账登记事实代次。

`服务维护历史事实范围读取结果_v1::成功()` 必须同时证明：合同版本正确、状态为`已读取`、五组全部历史投影完整、各组和见证顺序规范、五组总数等于见证声明数、见证身份组与五组逐项合并后完全相等、见证的自我 / 起点 / 终点 / G0 与请求及正式读回截止一致、`历史账登记事实代次 <= 排除起始事实代次 <= G0`。任何一项不成立都不得把状态码单独解释为成功。

## 5. 写入与生命周期

### 5.1 登记

构造顺序固定为：恢复基础、进展 v1、准备 v1、进展 v2、准备 v2 登记，再建立或恢复历史账登记。登记首次写集只创建 3050..305B 对应节点 / 类型和版本值，不修改已有登记或业务事实。

历史账登记首次事实代次是唯一覆盖起点。恢复必须逐项验证 owner、节点种类、版本、键映射和首次规范写集；损坏或同键异义使服务构造失败，不降级为空历史。

### 5.2 生产同步入账

`发布服务进展事实_v2` 和 `发布服务准备事实_v2` 在历史账登记完成后的同 owner 写集必须在形成新事实节点时同时追加：

```text
对应历史索引根 -> 新事实节点 的永久历史成员关系
```

历史关系顺序恒 1，创建代次与事实形成代次相同，永不退出。精确重复复用首次关系，不产生第二成员。更新当前事实时必须先按旧事实的形成代次和历史成员关系分账：

```text
旧事实形成代次 < 历史账登记事实代次
-> 该事实属于登记前兼容事实，不补账
-> 沿用现有完整闭包退出，避免形成无当前关系、无历史关系的永久孤儿

旧事实形成代次 > 历史账登记事实代次
-> 必须存在同形成代次的唯一永久历史成员关系
-> 只退出旧“当前成员关系”
-> 旧事实节点、载荷、业务引用关系和历史成员关系永久保留
```

登记写集自身不形成业务事实，因此生产事实形成代次不会等于登记事实代次；若恢复数据出现等代业务事实，固定为集合不闭合 / 构造恢复失败，不猜测归类。登记后的版本不得继续复用现有“退出旧事实完整闭包”的写集形状，否则永久历史根会指向已退出目标并失去当前完整枚举能力。

旧版本是否仍为当前只由当前索引成员关系裁决。历史读回将该关系的退出代次投影为事实版本的`退出当前事实代次`；不得用旧节点仍然存在推断它仍当前，也不得为了保存历史复制载荷。登记前已经按旧实现退出完整闭包的版本不在新账覆盖承诺内。登记前首次写入的精确重复继续按其不可变首次规范写集和首次历史闭包收敛，零新写、零补账；不得因新实现新增历史关系或缩小退出集而把旧合法请求误判为同键异义。登记后首次写入的精确重复则必须互证首次写集中已经包含历史成员关系。

未来合同建立、合同状态迁移、到期事件发布、结算和维护事务若形成前三类事实，必须在同 owner 参与者写集中同步写入对应历史成员关系；没有该关系的事实不得被后继历史范围读回视为完整生产事实。

当前基线没有前三类事实的公开生产发布入口，因此本叶不新增独立发布函数。验证 fixture 可以在测试宏下形成五类样本，但不能进入生产 ABI。

## 6. 读取算法

目标函数：

```cpp
服务维护历史事实范围读取结果_v1
服务合同事实权威服务::按事实代次范围读取服务维护历史事实完整组_v1(
    const 服务维护历史事实范围读取请求_v1&) const noexcept;
```

固定流程：

```text
请求版本 / 自我 / G0 / 排除起点 / 数量预算校验
-> G0 读前守卫
-> 同 owner 一致闭包读取五个永久历史根、全部仍活动的历史事实节点及永久业务引用
-> 逐项互证全部旧登记和历史账登记
-> 若排除起点 < 历史账登记事实代次，返回覆盖边界不可用
-> 按五类载荷唯一解码并验证关系、owner、形成代次、自我和版本
-> 对合同 / 状态 / 进展 / 准备，以事实形成代次为历史截止读取当时唯一当前成员关系，并投影该关系后来记录的退出代次
-> 拒绝漏历史关系、重复成员、同身份同版本异义和坏引用
-> 过滤 (排除起点,G0]
-> 规范排序并执行总数量预算
-> 形成完整集合见证
-> G0 读后守卫
-> 成功或结构化非成功
```

读取必须先验证整个永久历史账再过滤范围，不能因坏成员落在请求范围外而跳过损坏。对当前进展 / 准备根中形成代次晚于登记代次的每个成员，还必须反向互证其唯一历史成员关系；当前成员缺账固定为集合不闭合。当前成员关系只用于投影退出当前边界；登记后历史事实节点、业务引用关系或历史成员关系任一退出均为集合不闭合。

范围读回不能从一个已经完全绕过唯一生产入口、且当前关系也已不存在的未知事实身份反向发现漏账。生产完整性的机器边界因此固定为：模块外没有 raw owner 写端口、两个生产发布函数的新版本同写集必带历史成员、未来前三类 writer 只有满足同一合同才可进入生产、专项注入不进入生产 ABI。静态生产调用扫描和写集专项是完整性证据的一部分，不得把见证中的裸计数单独宣称为全 owner 扫描证明。

合同状态事实没有独立稳定身份，读取时以其所在历史节点编码作为成员关系目标，但公开见证仍使用合同身份 + 状态版本 + 形成事实代次。两项状态若四元组相同或同一合同状态版本对应不同载荷，整体内部错误 / 集合不闭合。

退出当前边界不得从事实节点是否活动、载荷中的旧生命周期、容器顺序或下一版本形成代次推断。读取必须按历史事实节点定位其在形成代次有效的唯一当前成员关系；关系事实记录的退出代次若存在即为正式退出当前边界。缺关系、多关系、退出不晚于形成或退出晚于 `G0` 都是集合不闭合。

## 7. 诊断责任

- 新公开范围读取：最终领域服务边界，诊断责任为`本地记录`；仅对捕获到的异常或结构内部错误经统一诊断出口记录一次，合法非成功不记录错误。
- 登记、解码、排序、闭包互证和见证辅助：`向上送出`，只返回结构化状态，不逐层记录。
- DTO 完整性和比较函数：`无适用错误分支`。

若当前日志模块依赖会制造循环依赖，本叶保留现有服务的结构化结果路径，不为满足日志形式新增反向 import；施工记录必须登记该工程裁决。
