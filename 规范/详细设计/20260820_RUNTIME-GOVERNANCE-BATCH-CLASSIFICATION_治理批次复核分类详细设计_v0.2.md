# 治理批次复核分类详细设计

日期：2026-08-20

身份：`RUNTIME-GOVERNANCE-BATCH-CLASSIFICATION v0.2`

替代：v0.1。v0.1 未按邮箱提交准入和冻结批次私有构造边界收窄 002-03 的可达状态，错误要求分类层再次分账重复材料、同键异义和空批次成功。

对应目标图：`BIZ-L2-002-03 复核并分类治理批次 v0.2`

## 1. 目标与完成边界

闭合正式主链：

```text
BIZ-L2-002-01 不可变治理批次
-> BIZ-L2-002-02 一致事实读取
-> BIZ-L2-002-03 复核时效并分类治理批次
```

本设计只实现治理批次完整消息交付、时效复核、稳定顺序分类、时效拒绝诊断和停止优先分流。它不读取消息引用的领域事实，不形成需求，不执行治理判断，不接入任务筹办。

## 2. 当前事实、具名漂移与裁决

当前邮箱在 `提交`持有队列锁期间完成：

```text
构造全局同幂等键既有消息上下文
+ 构造全局同任务最新序号上下文
-> 复核自我治理消息
-> 协议拒绝 / 重复材料 / 幂等冲突 / 顺序错误均不入队
-> 只有可准入消息记录索引并进入队列
```

`自我治理冻结批次`的批次序号和消息组均为 private，只有 `有界自我治理邮箱`是 friend；邮箱只在待处理队列非空时形成冻结批次。因此合法 002-03 输入具有以下不变量：

```text
消息全部曾通过邮箱静态协议、幂等和同任务顺序准入
同一幂等键最多一项
冻结消息组非空
冻结顺序由邮箱唯一确定
```

执行侧据此具名退回：v0.1 第 6、8 节要求在 002-03 形成重复材料和幂等冲突诊断，但合法消费者无法构造该输入。裁决固定采用 A：删除不可达普通分账和验收，不新增第二输入源，不修改邮箱协议。

同一不变量还使 `空批次`成功语义不可达，本版同步删除。入口空指针仍是合法可测的 `入口拒绝`。

## 3. 唯一所有权和依赖方向

```text
有界自我治理邮箱
  -> 唯一执行协议 / 幂等 / 顺序准入
  -> 值式交付非空完整冻结批次

自我治理批次路由
  -> 唯一拥有待完成完整消息组
  -> 形成不可变治理批次
  -> 只重检时间变化、完成分类和停止分流

自我线程
  -> 先读取一致事实
  -> 再调用同一路由实例分类
```

分类层不得从批内已处理消息重构 `同幂等键既有消息`或`同任务最新序号`。邮箱稳定优先级顺序不是提交顺序，不能被分类层误用为第二套任务序号账。

`L2治理函数骨架`退出 002-03 DTO 与全局函数。分类 DTO 和函数物理归属统一为 `海中鱼巣/线程/路由.自我治理批次.ixx`。不增加新模块，不让领域骨架反向持有线程消息。

## 4. 冻结批次合同

### 4.1 不可变治理批次

`不可变治理批次`固定包含：

```cpp
std::uint64_t 批次序号;
std::uint64_t 运行代次;
自我治理冻结批次 消息批次;
完整秒边界观察 完整秒;
std::optional<完整秒区间> 完整秒区间;
已发布共享事实截止 共享事实截止;
```

待完成槽保存完整 `自我治理冻结批次`和运行代次；成功冻结后直接 move 接管邮箱结果，重试只复用槽内对象，零再次读取邮箱。分类只经现有 `读取消息组()`取得 const 消息组，不增加邮箱写入口或可变引用。

消息组为空不能形成合法不可变治理批次。入口材料通过身份检查后仍观察到空组，固定归类 `内部错误`。

## 5. 分类 DTO

```cpp
enum class 治理批次分类状态 : std::uint8_t {
  已分类 = 1,
  停止优先 = 3,
  存在时效拒绝 = 4,
  内部错误 = 5,
  入口拒绝 = 6
};
```

删除 v0.1 的 `空批次 = 2`；其余尚未发布的状态保留原数值，避免无必要的 WIP 重排。

`治理输入类别`、`治理输入项`、`治理批次分类请求`保持 v0.1 字段。`治理输入诊断`只允许承载以下两类时效原因：

```text
材料已过期
发生时间仍晚于当前分类时间
```

`治理批次分类结果`继续值式拥有：

```cpp
治理批次分类状态 状态;
std::uint64_t 批次序号;
std::vector<治理输入项> 有序治理输入组;
std::vector<治理输入诊断> 逐项诊断;
```

结果不得把重复、冲突、静态协议错误或顺序错误包装为普通诊断。

## 6. 分类函数

物理位置和签名不变：

```cpp
治理批次分类结果 自我治理批次路由::复核并分类治理批次(
    const 治理批次分类请求& 请求) const noexcept;
```

固定流程：

1. 校验合同、非空批次指针、批次序号、当前单调时间、运行代次和协议版本；请求运行代次必须等于路由配置及批次运行代次。失败返回 `入口拒绝`。
2. 批次身份合法但消息组为空：返回 `内部错误`和空载荷。
3. 按冻结顺序逐项处理，不排序。
4. 对每项构造只含 `当前时间戳`的 `自我治理准入上下文`；`同幂等键既有消息`、`同任务目标`和`同任务最新序号`保持默认空值。
5. 调用 `复核自我治理消息`。返回 `可准入`时按消息强类型一一映射类别并追加值式消息；未知映射为 `内部错误`。
6. 到分类时已过期，或消息发生时间仍晚于当前分类时间：只追加时效诊断，不形成治理输入。
7. `重复材料`、幂等冲突、同任务顺序拒绝、其它静态协议拒绝或 `内部不一致`：返回 `内部错误`和空治理输入组，表示邮箱不变量被破坏。
8. 可准入停止消息追加后立即返回 `停止优先`，不处理其后普通输入。
9. 无停止且存在时效诊断返回 `存在时效拒绝`；无诊断返回 `已分类`。
10. `bad_alloc`、`length_error`或其它异常返回 `内部错误`和空治理输入组；本函数零业务事实写入。

本函数不得读取邮箱私有幂等索引，不得复制邮箱的完整准入账，不得新增另一批次构造者。

## 7. 自我线程接线

自我线程在 002-02 成功后构造请求，批次指向当前处理槽中的同一 `不可变治理批次`，协议版本使用 `自我治理协议版本`，并调用 `批次路由_->复核并分类治理批次`。

- `入口拒绝`或`内部错误`：保槽并领域治理终止；
- `存在时效拒绝`：保留诊断并领域治理终止，不伪造业务结果；
- `停止优先`：进入停止后继，不执行普通输入；
- `已分类`：进入后续治理输入事实复核。

本叶只证明分类结果进入线程控制流；002-04 绑定事实复核仍未实现，因此非空普通输入不得越过为机器事实。

## 8. 验证

使用现有 `--test-治理`合法消费者补充：

- 路由冻结后完整消息逐字段保留，批次运行代次一致；
- 正常多类型消息保持邮箱顺序并映射唯一类别；
- 到分类时已过期的消息形成时效拒绝诊断；
- 停止输入返回停止优先并截断后继；
- 坏合同、坏运行代次、空指针和坏协议版本入口拒绝；
- 分类零领域写入，共享事实截止不变。

明确不建立以下不可达验收：

```text
在合法冻结批次内注入同键同义重复
在合法冻结批次内注入同键异义冲突
构造合法空冻结批次并期待空批次成功
访问或修改冻结批次私有字段
建立第二批次输入来源
```

运行 Debug / Release x64 Rebuild 和两配置 `--test-治理`，并执行 strict 与 diff 检查。
