# INSTINCT-BOOTSTRAP-ROOT-ANCHOR 本能根运行锚点详细设计 v0.1

日期：2026-08-28

状态：设计候选，待创建侧验证与发布

计划身份：`INSTINCT-BOOTSTRAP-ROOT-ANCHOR`

## 1. 目标与边界

在自我线程创建前建立或恢复唯一自我的安全根与服务根材料，按同一事实截止完整读回，并形成值式运行锚点。

成功必须闭合：

```text
唯一自我
+ 安全值、服务值的一阶特征定义、实例、当前值和当前状态选择
+ 两份目标判断比较注册
+ 两份 I64_MAX 目标状态合同
+ 两份根需求、列表项、成员关系和父为空证明
+ 安全差值、服务差值的二次特征概念定义
+ 全部材料在同一 Gfinal 正式读回
```

本阶段不计算具体需求，不创建任务，不改变现实，不运行根需求展开算法，也不持久保存本次差值。

## 2. 数值和公式

```text
M  = INT64_MAX
   = 9,223,372,036,854,775,807

A0 = V0 = M / 2
        = 4,611,686,018,427,387,903

M % 2 = 1，余数舍弃
```

目标合同：

```text
安全根：A == M
服务根：V == M
```

按需二次特征：

```text
Delta_safe    = M - A
Delta_service = M - V
```

输入必须位于 `0..M`。禁止先转无符号、饱和、钳制或把非法值改写为边界值。两个差值不相加、不直接比较为优先级，不成为第二当前值权威。

具体差值只在调用栈局部按需形成，用完即弃；持久层只保存两份二次特征概念定义。

## 4. 角色恢复

不得按名称、创建顺序、稳定编码大小或列表位置猜测角色。

```text
特征定义
= 固定业务幂等身份首次完整读回
+ 阶次、直接来源、派生规则互证

特征实例
= 唯一自我下全部实例
+ 对应特征定义
+ 恰好一项

目标合同
= 固定业务幂等身份首次完整读回
+ 特征定义、比较注册、M、允许关系位互证

根需求
= 唯一自我当前根需求组
+ 精确目标四元组
+ 恰好一项

列表项
= 所属存在、目标宿主、目标特征、目标合同精确查询
+ 恰好一项
+ 当前成员关系互证
```

固定幂等身份只是业务恢复键，不建立角色节点、第二索引或第二事实 owner。


唯一事务语义：

1. 特征 owner 只形成“首值事实＋当前属性槽”参与者。
2. 状态 owner 只形成“初始状态＋主体/实例关系＋当前状态选择”参与者。
3. 两个写端口使用现行 L1 双参与者原子运输一次提交。
4. 首值、初始状态和当前选择同一共同事实代次。
5. 初始状态精确值逐字等于首值，时间为大于零的 UTC Unix epoch 纳秒。
6. 首次赋值不形成动态。
7. 任一预形成、提交、映射或读回失败时不返回部分成功。
8. 旧 L1 运输中的“状态/动态”字段名只作内部双槽兼容名，不得外露为本入口语义；本入口不形成动态 owner 写集。

`L2特征结构服务` 与 `L2状态结构服务` 各自验证自己的 private 写集，任何一方不得复制另一 owner 的写集逻辑。

### 5.3 `新增状态_v2`

移除固定入口拒绝壳并恢复生产实现。判断优先级固定为：

```text
同幂等身份首次材料存在
→ 精确重复或幂等冲突

无首次材料
→ 已有当前选择、已有状态、入口材料和当前性
```

不得因首次请求已经形成当前选择而先返回“已有当前选择”，遮蔽同键精确重复。首值首态组合可以复用首态 private 写集形成逻辑，但不得拼接两个独立公开写入口冒充原子提交。

## 8. 形成与恢复

固定顺序：

```text
验证唯一自我
→ 两份一阶定义
→ 两份 M-X 二次概念定义
→ 两份唯一自我特征实例
→ 缺失时分别执行首值首态单事务
→ 两份目标判断比较注册
→ 两份 I64_MAX 目标状态合同
→ 两份根需求、列表项和成员关系
→ 冻结 Gfinal
→ 全量正式重读
→ 形成锚点
```

顺序只用于可重复施工和故障注入，不赋予身份业务意义。

一阶定义：

```text
实际阶次=1；直接来源空；派生规则空
```

二阶概念定义：

```text
实际阶次=2
直接来源=对应安全值或服务值定义，顺序1，输入角色1
派生规则身份=本能根I64最大值减当前值规则
规则版本=1
```

二阶定义不得建立实例、当前值、状态或动态。

首次根值：

```text
当前值=M/2
初始状态精确值=当前值
初始状态时间=本次启动UTC纳秒
当前状态选择=初始状态
共同形成代次=G1
动态=无
```

重启不得重置当前值。若当前值和当前状态都存在，必须在 fresh `G0` 证明值域、主体、实例、精确值和绝对 UTC 时间一致。二者仅一边存在为 `材料未闭合`；正常原子入口不得产生该状态。

两份比较注册固定为：

```text
用途=目标判断
算法族=标量有序比较与安全差异
算法版本=1
原始类型=I64
左角色=当前事实
右角色=目标状态
差异方向=右减左
允许结果位=0b010
边界包含=不适用
量化规则=精确无量化
误差合同版本=1
误差预算=空
相等容差=0
```

两份目标合同均为 `目标I64=M`、`允许关系位=0b010`，分别绑定各自定义和注册。

每个根的目标四元组：

```text
所属存在=唯一自我
目标宿主=唯一自我
目标特征=对应根值定义
目标合同=对应I64_MAX合同
```

列表项缺失时调用 `新增需求并建立列表项`，父为空、父子顺序零。列表项已存在而需求缺失时调用 `新增需求并加入既有列表项`。最终根需求组包含该需求构成父为空证明；精确列表项和成员关系读回证明列表闭包。

最终取得 `Gfinal` 后，所有读取统一携带该截止。任何截止不同、漂移、0/N 或多义结果都丢弃本次组合结果，不得拼接不同截止材料。

## 9. 状态矩阵

| 情况 | 状态 | 锚点 |
| --- | --- | --- |
| 首次闭合并同 Gfinal 读回 | 已形成 | 完整 |
| 全部角色恢复，零新增事实 | 已恢复 | 完整 |
| 坏合同、零自我、UTC为零 | 入口拒绝 | 空 |
| 底层技术写端口拒绝 | 许可拒绝 | 空 |
| 当前代次变化或截止不同 | 当前性漂移 | 空 |
| 固定幂等键对应不同材料 | 幂等冲突 | 空 |
| 角色交叉、重复或绑定错误 | 引用冲突 | 空 |
| 单边当前值/状态或关系闭包缺失 | 材料未闭合 | 空 |
| 原子提交结果未知 | 已可能发布 | 空 |
| 分配或长度失败 | 资源失败 | 空 |
| 载荷、映射、代次自相矛盾 | 内部不一致 | 空 |

`已可能发布` 保留原组合幂等身份。同进程按原请求重试；跨进程先按正式当前事实恢复，不用日志、缓存或猜测判定提交结果。
