## 1. 本叶目标与完成边界

本叶建立一个独立、纯值式、零机器事实写入的 ARCH-L4 时序可达性裁决器。给定：

```text
当前时刻与当前位置 C
+ 两个需求 H、Y 的目标位置、时间窗口、最小保持时间、硬/软时间、损失和权重
+ C→U、C→I、U→I、I→U 等已经由上游形成的转换候选时间合同
+ 每个转换候选的安全硬门与方法保护约束前置结果
```

裁决器必须：

1. 分别计算 `H→Y` 与 `Y→H` 两种顺序是否能保证同时满足；
2. 区分“保证可达”“仅按预计耗时可达”“不可达”“材料不足/前置门未通过”；
3. 先穷尽输入中已有的替代转换候选，再认定时序冲突；
4. 同时满足不可行时，先按单需求可达性，再按安全硬约束、硬/软时间、错过损失、需求权重的词典序给出取舍；
5. 同一优先级仍相等时返回`无法裁决`，不得用稳定编码替代业务语义；
6. 输出只作为后续 self/manager 的正式输入材料，不修改需求、任务、方法、世界事实或任务状态，不产生执行授权。

本叶完成只证明值式算法和公开 DTO 已实现并通过本计划验证。它不证明时间约束已经进入需求 owner、方法耗时合同已经进入 method owner、manager 已消费裁决、任务已等待/重筹办、组合方法已经形成，或真实 C/U/I 场景已经运行。

## 2. 用户本轮冻结语义与既有规范关系

用户本轮已冻结：当前处于 C；需求 H 要在其时间点/窗口到 U，需求 Y 要在另一时间点/窗口到 I；若两个窗口之间不足以完成 U→I，则属于时序可达性冲突。可行性先于权重，安全硬门、硬/软时间、替代方法、错过损失、权重依次裁决。

本叶保持以下分账：

- 需求目标冲突：同一对象、同一特征、同一有效时间内目标值域无共同可满足范围；不由本函数判断。
- 方法保护约束：不同特征间的不利影响先由“主需求＋保护需求＋方法条件结果合同”处理；未通过保护约束的候选以具名前置状态进入本函数，不能被时间可达性重新放行。
- 时序可达性冲突：目标可先后成立，但当前地点、时间窗、保持时间与转换耗时不能组成可保证路径；这是本函数唯一业务职责。
- 已满足值目标仍需保护：由上游方法保护检查负责，不因本函数只处理时间而被跳过。

3100 v4.1 的持久需求字段目前没有时间窗口，3300/5350 当前公开 DTO 也没有转换保证耗时。本叶不私自增加或改义它们的持久字段，而只接受上游值式投影；对应正式生产者与 manager 消费接线是后继切片。本叶因此不修改正式规范，也不把临时投影伪装成需求/方法权威事实。

## 5. 冻结公开 DTO

全部时间使用非负 `std::int64_t` 纳秒。窗口使用同一绝对时间坐标；转换耗时是持续量。调用方负责把来源时间转换到同一坐标，本函数拒绝负值、倒置窗口和不可表示运算。时间点需求用`最早满足纳秒 == 最晚满足纳秒`表达。

### 5.1 枚举

```cpp
enum class 需求时间硬度 : std::uint8_t {
    硬约束 = 1,
    软约束 = 2
};

enum class 转换候选前置状态 : std::uint8_t {
    已通过 = 1,
    安全硬门否决,
    方法保护约束不兼容,
    材料不足
};

enum class 需求时序顺序 : std::uint8_t {
    第一后第二 = 1,
    第二后第一
};

enum class 时序路线状态 : std::uint8_t {
    可保证同时满足 = 1,
    仅按预计耗时可同时满足,
    不可同时满足,
    转换合同缺失,
    前置材料不足,
    安全硬门否决,
    方法保护约束不兼容,
    计算不可表示
};

enum class 需求时序裁决状态 : std::uint8_t {
    可保证同时满足 = 1,
    仅存在风险路线,
    时序冲突选择第一需求,
    时序冲突选择第二需求,
    时序冲突无法裁决,
    两个需求均不可保证,
    材料不足,
    输入不合法,
    计算不可表示
};
```

`仅按预计耗时可同时满足/仅存在风险路线`只作诊断，不能被 manager 解释为可承诺、待执行或现实执行授权。硬时间需求必须按保证最大耗时判定；预计耗时不升级硬时间可达性。

### 5.2 输入

```cpp
struct 需求时序约束投影 final {
    稳定编码 需求节点;
    稳定编码 目标位置节点;
    std::int64_t 最早满足纳秒 = 0;
    std::int64_t 最晚满足纳秒 = 0;
    std::int64_t 最小保持纳秒 = 0;
    需求时间硬度 时间硬度 = 需求时间硬度::硬约束;
    bool 安全硬约束 = false;
    std::int64_t 错过损失 = 0;
    std::int64_t 需求权重 = 0;
    friend bool operator==(const 需求时序约束投影&,
        const 需求时序约束投影&) = default;
};

struct 转换时间合同投影 final {
    稳定编码 方法节点;
    稳定编码 起点位置节点;
    稳定编码 终点位置节点;
    std::int64_t 最短耗时纳秒 = 0;
    std::int64_t 预计耗时纳秒 = 0;
    std::int64_t 保证最大耗时纳秒 = 0;
    转换候选前置状态 前置状态 = 转换候选前置状态::材料不足;
    friend bool operator==(const 转换时间合同投影&,
        const 转换时间合同投影&) = default;
};

struct 需求时序可达性裁决请求 final {
    std::int64_t 当前绝对时间纳秒 = 0;
    稳定编码 当前位置节点;
    需求时序约束投影 第一需求;
    需求时序约束投影 第二需求;
    std::vector<转换时间合同投影> 转换候选组;
};
```

完整输入要求：

1. 当前点、两需求、两目标位置和每个方法身份非零；两需求身份互异。
2. `0 <= 当前时间`，`0 <= 最早 <= 最晚`，保持时间、损失、权重非负。
3. 时间硬度和前置状态必须是封闭枚举值。
4. 转换合同满足`0 <= 最短 <= 预计 <= 保证最大`，起终点非零且不同；同一方法、起点、终点重复且内容不同为输入不合法，精确重复去重。
5. 起点等于终点时使用裁决器内部零耗时恒等腿，不要求伪造方法节点。
6. 输入候选只代表已经由上游 method owner/保护约束/安全服务形成的值式材料；本函数不从方法名或位置图猜测新路径，不做任意图搜索。多段或组合路线必须由上游作为一条具名组合方法转换合同提供。

```cpp
struct 需求时序可达性裁决结果 final {
    需求时序裁决状态 状态 = 需求时序裁决状态::输入不合法;
    时序路线评估 第一后第二;
    时序路线评估 第二后第一;

```

结果不返回“允许执行”布尔值。`采用顺序`只在`可保证同时满足`时存在；`优先需求节点/等待重新确认需求节点`只在时序冲突已经按正式词典序选出一个单需求时存在。其它状态三个选择字段均为空。

`第一需求满足时刻/第二需求满足时刻`始终对应请求中的`第一需求/第二需求`身份，不随路线先后交换含义。路线状态为`可保证同时满足`时，这三个可选计算字段保存保证最大耗时计算得到的两个满足时刻和最小窗口余量；状态为`仅按预计耗时可同时满足`时，保存预计耗时计算结果；其它路线状态三项必须全空。不得把预计时刻写进保证路线，也不得在不可达/材料不足时保留半份时刻。

## 7. 路线计算

对顺序`A→B`，分别以保证最大耗时和预计耗时计算：

```text
到达A = 当前时间 + 耗时(C→A)
满足A = max(到达A, A.最早满足)
离开A = 满足A + A.最小保持
到达B = 离开A + 耗时(A→B)
满足B = max(到达B, B.最早满足)

A成立 <=> 满足A <= A.最晚满足
B成立 <=> 满足B <= B.最晚满足
```

所有加法先检查`INT64_MAX`边界；溢出返回`计算不可表示`，不得钳制。允许提前到达并等待；只有满足时刻落入闭区间才成立。保持时间从满足时刻开始，完成保持前不得离开去满足下一需求。

每一条腿先在相同起终点的`已通过`候选中选择最优合同：保证计算按`保证最大耗时、预计耗时、方法稳定编码`升序；预计诊断按`预计耗时、保证最大耗时、方法稳定编码`升序。稳定编码只在所有业务结果等价、全部需求均被满足的路线表示中消除输出不确定性，不能决定牺牲哪个需求。

一条必需腿的候选状态解析顺序固定为：

1. 该起终点完全没有任何合同：`转换合同缺失`。
2. 只要存在至少一个`已通过`候选：使用通过候选计算；同腿其它材料不足、否决或不兼容候选不阻断合法替代。
3. 没有通过候选但至少有一个`材料不足`：`前置材料不足`。
4. 没有通过/材料不足候选但至少有一个`安全硬门否决`：`安全硬门否决`。
5. 剩余候选全为`方法保护约束不兼容`：`方法保护约束不兼容`。

整条路线有两条必需腿且不能进入计算时，路线状态按`转换合同缺失 -> 前置材料不足 -> 安全硬门否决 -> 方法保护约束不兼容`取最先命中的状态。该顺序只决定返回哪一个阻断摘要，不把后序阻断解释为通过；专项验证必须分别核对每条腿的输入构造。

路线分类：

1. 保证耗时计算使两需求均成立：`可保证同时满足`。
2. 保证不成立、预计耗时计算成立：`仅按预计耗时可同时满足`；不产生采用顺序。
3. 必需腿不存在任何合同：`转换合同缺失`。
4. 必需腿没有通过候选且至少有材料不足：`前置材料不足`。
5. 必需腿没有通过/材料不足候选且存在安全否决：`安全硬门否决`。
6. 必需腿剩余候选全为保护约束不兼容：`方法保护约束不兼容`。
7. 合法候选齐全但时间不满足：`不可同时满足`。

两顺序都可保证时，先选`最小窗口余量`较大者，再选保证总完成时间较小者。保证总完成时间固定为`保证计算中的第二个需求满足时刻 - 当前绝对时间`，因此包含第一腿、提前到达等待、第一需求最小保持、第二腿以及第二需求窗口前等待；它不是两条腿保证耗时的简单相加。仍相同可用顺序枚举稳定确定输出，因为两者均完整满足H和Y，不构成需求取舍。

## 8. 时序冲突取舍

只有两顺序都不能保证同时满足，且不存在材料不足/计算不可表示时，才计算从 C 单独满足 H、Y 的保证可达性。

1. 只有一个需求可保证：选该需求，另一需求进入`等待重新确认`材料。
2. 两者均不可保证：返回`两个需求均不可保证`；预计可达只保留在路线诊断，不选任务。
3. 两者都可保证但不能共同保证：按以下词典序比较，高者优先：

```text
安全硬约束 true
-> 时间硬度=硬约束
-> 错过损失较大
-> 需求权重较大
```

4. 全部相等：返回`时序冲突无法裁决`。不得以需求编码、输入顺序、容器顺序、线程号或方法编码决定牺牲谁。

权重只在可行性、安全、时间硬度和损失之后参与，不能让不可达需求压过可达需求，不能突破转换安全硬门或方法保护约束，也不能改写需求目标。

裁决器不直接把未选任务改成等待。后继 manager 必须 fresh 读回同一需求、任务、方法、安全与保护材料，再把结果交 self；self确认后才可请求合法任务状态迁移。目标/窗口/位置/转换合同任一变化都使旧值式裁决失效。

| 内存分配失败 | `材料不足`；保持零写 |
| 其它异常 | `输入不合法`；函数`noexcept`且零副作用 |
| 前置安全或保护否决 | 保留具名路线状态；不能被权重或预计耗时放行 |

本函数没有撤销路径，因为没有机器事实写入。返回对象构造失败也不得留下缓存或部分发布。

## 10. 验证矩阵

专项生产外验证至少覆盖：

1. C→U、H=10:00，Y=10:05，U→I保证10分钟：`H→Y`不可达；反向也不成立时进入冲突取舍。
2. 同一材料增加U→I保证4分钟替代方法：在权重比较前得到可保证共同满足。
3. 只有预计4分钟、保证10分钟：返回风险路线但不产生采用顺序。
4. 两顺序只有一个可保证；选择可保证顺序。
5. 两顺序都可保证；按最小余量、保证总耗时确定等义路线。
6. 提前到达等待、最小保持为0/正数、闭区间边界恰好命中。
7. 当前点等于目标点、两个目标点相同的内部零耗时腿。
8. 单需求只有H可保证/只有Y可保证/两个都不可保证。
9. 两个都单独可保证但不能共同保证时，依次证明安全、硬时间、损失、权重的优先级；低层字段不得覆盖高层字段。
10. 四项全部相等返回无法裁决，交换输入后仍不靠编码牺牲需求。
11. 安全硬门否决、保护需求不兼容、材料不足分别保留，已有可用替代时不阻断。
12. 重复合同精确去重、异义重复拒绝、候选输入重排结果不变。
13. 负值、倒置窗口、非法耗时序、零身份、重复需求、非法枚举。
14. 每一个加法位置的`INT64_MAX`边界与溢出。
15. 静态确认新文件零 DATA/需求/任务/方法写入口、零线程/锁/I/O/日志，现有`查找冲突需求()`和执行链零改动。
16. 根工程 Debug/Release x64 Rebuild；四配置`/utf-8`静态读回；专项 Debug/Release x64 运行均零失败。
