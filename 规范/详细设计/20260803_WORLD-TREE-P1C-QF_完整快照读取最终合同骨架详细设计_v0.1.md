## 1. 目标、范围与当前能力裁决

本叶子只建立 `世界树快照读取服务` 的最终公开 DTO、三引用构造和三个固定 `未实现` 读取函数体，使合法消费者可以编译接入并安全停止成功路径。它不建立 `世界树业务服务`，不读取世界结构、特征、状态或动态，不组合同代次材料，不访问 L0/L1，不写机器事实。

直接规范依据为 0050、4020、4030、4190、4200 v0.9、4201 v0.4。业务上游为 `流程图/20260802_WORLD-TREE-P1_世界树业务服务业务流程图_v0.1.md`，本叶子直接业务图为 `流程图/20260803_WORLD-TREE-P1C-QF_完整快照读取最终合同骨架业务流程图_v0.1.md`。

当前正式基线中：

- WORLD-TREE-P1A3F v0.3 结果提交 `3242c16640da898b546f294199c00c08032ba49c` 已建立 `世界树事实.数据.h`、`节点直接世界结构读取服务` 最终类型和顺序 180 / 19 项自检基线；真实世界结构读取仍未实现。
- WORLD-TREE-P1BF v0.2 尚未形成正式代码，`世界树特征事实` 与 `节点直接特征查询服务` 最终类型当前不可供编译消费。
- WORLD-TREE-P1B-F v0.2 已以设计提交 `c56376a690c492ca380bb15b1a8c54ee94ac0986` 冻结最终合同骨架和四个类型合同身份，但最终骨架代码尚未进入正式 main，状态/动态共享事实、查询合同与 `节点直接状态动态查询服务` 当前不可供编译消费。

因此 P1C-QF 设计可以冻结；在 P1BF 与 P1B-F 最终合同骨架代码及其精确接口进入正式 main 前，S0 必须零代码修改并返回具名依赖漂移。骨架依赖只为类型与构造引用可编译，不要求提供者具备真实成功查询行为，也不代表三个函数发生 provider 调用。FEATURE-W 不被本叶子消费，不构成依赖。

## 3. 最终公开状态与 DTO

### 3.1 稳定状态

```cpp
enum class 世界树业务状态 : std::uint8_t {
    已提交 = 1,
    幂等读回 = 2,
    已读取 = 3,
    未找到 = 4,
    入口拒绝 = 5,
    幂等冲突 = 6,
    版本漂移 = 7,
    许可拒绝 = 8,
    资源失败 = 9,
    内部不一致 = 10,
    未实现 = 11
};
```

`未实现=11` 来自 4201 v0.4，永久保留。骨架只返回未实现；不得返回已读取、未找到或入口拒绝。

### 3.2 请求

```cpp
struct 世界树读取请求 {
    世界树请求头 头;
};

struct 世界树对象读取请求 {
    世界树请求头 头;
    世界树节点身份见证 目标;

```

请求由调用方拥有。服务函数仅在同步调用期 const 借用；骨架不读取、不回显、不保存。后继真实实现才按 4200 校验合同版本、规则版本、世界根和目标见证。

## 4. 最终类、构造与三个根签名

```cpp
class 世界树快照读取服务 final {
public:
    世界树快照读取服务(
        节点直接世界结构读取服务& 世界结构,
        节点直接特征查询服务& 特征,
        节点直接状态动态查询服务& 状态动态) noexcept
        : 世界结构_(世界结构), 特征_(特征), 状态动态_(状态动态) {}

    世界树读取结果 读取完整世界事实快照(
        const 世界树读取请求& 请求) const noexcept;

    世界树存在读取结果 读取存在完整事实(
        const 世界树对象读取请求& 请求) const noexcept;

    世界树场景读取结果 读取场景完整事实(
        const 世界树对象读取请求& 请求) const noexcept;

private:
    节点直接世界结构读取服务& 世界结构_;
    节点直接特征查询服务& 特征_;
    节点直接状态动态查询服务& 状态动态_;
};
```

构造参数、初始化列表和成员顺序必须一致。装配宿主拥有三个 provider 和本服务，并保证 provider 长于本服务及全部同步调用。构造只绑定引用，不读取、不分配、不恢复、不访问外部资源；禁止默认构造、指针依赖、setter、可选依赖、运行期替换和兼容重载。

## 5. 三个固定函数体

三个函数均不命名或读取参数，不调用成员，不建立临时快照。固定代码为：

```cpp
世界树读取结果 世界树快照读取服务::读取完整世界事实快照(
    const 世界树读取请求&) const noexcept {
    return 世界树读取结果{
        世界树业务状态::未实现, 世界树请求头{}, std::nullopt, {}};
}

世界树存在读取结果 世界树快照读取服务::读取存在完整事实(
    const 世界树对象读取请求&) const noexcept {
    return 世界树存在读取结果{
        世界树业务状态::未实现, 世界树对象读取请求{}, std::nullopt, {}};
}

世界树场景读取结果 世界树快照读取服务::读取场景完整事实(
    const 世界树对象读取请求&) const noexcept {
    return 世界树场景读取结果{
        世界树业务状态::未实现, 世界树对象读取请求{}, std::nullopt, {}};
}
```

同一模块必须包含：

```cpp
static_assert(noexcept(世界树读取结果{
    世界树业务状态::未实现, 世界树请求头{}, std::nullopt, {}}));
static_assert(noexcept(世界树存在读取结果{
    世界树业务状态::未实现, 世界树对象读取请求{}, std::nullopt, {}}));
static_assert(noexcept(世界树场景读取结果{
    世界树业务状态::未实现, 世界树对象读取请求{}, std::nullopt, {}}));
```

任一断言不成立即编译失败并返回设计支撑；不得删除 `noexcept`、增加 try/catch、改为命名结果后读取请求、回显输入或临场改变字段。

### 7.2 零代码机械推演

```text
1. P1BF和P1B-F结果进入main并释放工程、启动和共享头。
2. 新建服务.世界树快照.ixx，按§2顺序include/import。
3. 在该模块依次声明状态、请求、三快照、三结果和服务类。
4. 构造函数只绑定三引用；三个函数体逐字使用§5固定prvalue。
5. 新建一个顺序240专项自检入口；记录S0顶层数量N并登记一项，结果必须为N+1。
6. 专项自检按固定构造链建立 `节点直接身份仓库、正式关系仓库、可重建索引仓库、节点直接类型合同仓库、节点直接类型化值仓库、节点直接身份结构事务域 -> 节点直接结构查询服务 -> 世界结构/特征/状态动态查询服务 -> 世界树快照读取服务`。只构造查询依赖，不建立执行器、提交服务、SQL端口或持久端口。
7. 分别以默认、非法、完整和边界字段请求调用三根。边界字段请求固定把合同版本、世界规则版本和身份版本置为各自 `UINT32_MAX`，把稳定主键命名域和键值置为 `UINT64_MAX`，世界根使用场景类型，存在/场景入口目标分别使用存在/场景类型；断言所有结果仍固定。用 AST 证明三根参数引用和项目内调用均为0，并比较调用前后五仓权威导出与事务域事实截止代次逐值相等。
8. 构建、自检、AST/文本静态门禁通过后，只声明合同骨架候选形成。
```

执行者无需决定 DTO 字段、模块、签名、构造顺序、返回表达式、错误映射、自检身份或依赖。

## 8. 自检、版本与后继替换

唯一自检身份：

```text
WORLD-TREE-P1C-QF-S01

```

S0读取届时正式顶层自检登记数量 `N`；施工只新增上述一个槽位，登记和执行数量必须精确为 `N+1`。顺序230空缺不构成依赖，禁止为了连续顺序人为依赖或实施 FEATURE-W。
