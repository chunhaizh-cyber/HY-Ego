## 1. S0 与最早缺口裁决

P63只冻结安全/服务双轴根定义的纯值角色、值域、目标、阈值、合法生产边和规则版本，明确把具体L1本地键、写集形状、读回、稳定编码、幂等和发布留给后继。6130要求正式根定义先于关系22实例槽；因此P64不能先设计实例槽、根当前值或根需求。

| 候选能力 | 当前正式或冻结能力 | P64裁决 |
| --- | --- | --- |
| 双轴根定义业务规格 | P63唯一纯值provider | 只消费，不重算阈值、目标或生产边 |
| 通用I64定义登记/读回 | P2登记含服务身份和三个属性类型；读回要求定义节点恰有三个当前属性 | 复用通用定义物理形状，不调用P2发布入口 |
| 根定义专用元数据承载 | 当前没有 | **当前最早真实缺口** |
| L1写集本地键和发布后读回计划 | 当前没有 | 本叶纯值冻结 |
| 幂等、领域意图编码、执行证据和一次提交 | P15仍有具名漂移 | 后继原子发布者拥有；本叶不复制编码 |
| 关系22实例槽、根值和根需求 | P36/P40等可供后继组合 | 必须等待根定义正式发布和稳定身份 |

不能把P63全部专用元数据直接追加到P2通用定义节点：正式P2读取要求该节点当前属性数量精确为3，额外属性会使既有通用读回稳定返回内部不一致。也不能只创建两个P2定义后以名称区分安全/服务，因为阈值、目标和规则版本将没有机器承载。

故P64采用唯一兼容形状：两个P2兼容的三属性通用I64定义节点；两个独立根定义类型化记录节点；一项根记录到通用定义的模板关系类型及两条关系。专用字段以I64属性类型和值承载，来源为本次建立的具名根定义服务节点。P64只形成草案，不读取事实、不发布或缓存登记。

## 2. 目标与最大边界

新增唯一公开根：

```cpp
自我双轴根定义L1草案结果 L1自我根定义写集数据操作::形成双轴根定义L1草案(
    const 特征定义登记& 通用定义登记,
    const 自我双轴根定义规格结果& 双轴结果) const;
```

固定流程：

```text
校验P2登记和P63双轴规格
-> 固定31个节点本地键
-> 固定42个值、42个属性槽和2条模板关系
-> 形成精确覆盖的117项发布后读回计划
-> 校验连续键、引用、数量、P2三属性兼容和专用记录分离
-> 返回不可变草案
```

本叶零provider、P2服务、P15、P37、P54和L1调用，零事实读取/写入、许可、锁、事务、提交、幂等探测、摘要、账和稳定编码分配。它不发布根定义，不建立运行期登记投影或事务参与者，不创建关系22实例槽、当前值、状态、动态、因果或根需求，不装配、恢复、删除旧栈或正式验收。

## 3. 物理位置、所有权与依赖

原位扩展P63共享头并新增两个模块：

```text
海中鱼巣/领域/L1自我根定义.数据.h
海中鱼巣/领域/数据操作.L1自我根定义写集.ixx
海中鱼巣/领域/自检.L1自我根定义写集.ixx
```

`L1自我根定义写集数据操作`属于抽象特征领域专用数据操作，无成员、可默认构造，根函数是同步纯值变换。依赖方向固定：

```text
后继双轴根定义原子发布者
-> P2 读取当前通用定义登记
-> P63 形成自我双轴根定义规格
-> P64 形成双轴根定义L1草案
-> 后继按P15替代真实接口绑定幂等/意图/证据并提交一次L1 v2事务
```

P2、P63不得反向依赖本模块。P64不持有登记或规格引用，不保存上次草案。后继实例槽只能消费发布后读回确认的两个通用定义稳定身份，不能消费根记录身份、本地键或草案对象。

## 5. 连续本地键与事实形状

### 5.1 节点键1—31

| 本地键 | 事实 |
| ---: | --- |
| 1 | 根定义服务身份，普通节点 |
| 2 | 根记录模板关系类型，普通节点 |
| 3—27 | 25项专用字段属性类型，均为属性类型/I64 |
| 28 | 生存安全通用I64定义，普通节点 |
| 29 | 服务通用I64定义，普通节点 |
| 30 | 生存安全根定义记录，普通节点 |
| 31 | 服务根定义记录，普通节点 |

键3—27由`自我根定义字段`枚举顺序唯一决定，不接收调用方本地键或字段集合。

### 5.2 通用定义值键32—37

键32—34依次为生存安全定义的定义标记1、I64下界0、I64上界`I64_MAX`；键35—37为服务定义的同三项。所属节点分别为键28/29，属性类型和值来源逐字段复用P2登记的三个稳定属性类型和服务身份，形成六个属性槽。

这两个通用定义节点当前属性必须各恰为3。P64专用字段不得挂到键28/29；后继P2读回只需定义及三值稳定编码即可复核值域。

### 5.3 安全记录值键38—52

按固定顺序写入：合同版本、规格版本、角色、生存安全目标比较、目标值1、L、H、生产者掩码、证据掩码、主动安全结算版本、被动服务维护版本、状态动态组织版本、因果组织版本、缺口需求版本、验证归因回写版本。

所属节点均为键30，属性类型对应键3、4、5、6、7、8、9、10、11、13、14、24、25、26、27，来源统一为本地键1。生产者和证据掩码按P63枚举值`1 << (值-1)`确定；安全固定为5，不接受自由掩码。

### 5.4 服务记录值键53—73

按固定顺序写入：合同版本、规格版本、角色、服务目标比较、目标值`I64_MAX`、生产者掩码、证据掩码、默认有效秒2,592,000、服务合同、默认有效期、预算、时间纪元、完整秒、衰减、准备补回、服务比例、生存安全回归、状态动态组织、因果组织、缺口需求、验证归因回写版本。

所属节点均为键31，属性类型对应键3、4、5、6、7、10、11、12、15—27，来源统一为本地键1。服务生产者和证据掩码固定为6。安全L/H和主动/被动安全专用字段不得出现在服务记录。

### 5.5 关系键74—75与槽

关系74为键30到键28、关系75为键31到键29，关系类型均为键2，角色或顺序固定0。它们只表达“根定义记录说明哪一个通用抽象定义”，不代替关系22实例模板。

42个值各有恰一属性槽变更；键28/29各3槽，键30有15槽，键31有21槽。退出事实固定为空。精确数量：

```text
新节点31；新值42；新关系2；属性槽42；退出0；首次新编码75。
```

## 6. 发布后读回计划

草案按P15冻结的通用读回语义形成117项：节点31、关系2、值42、属性槽42。顺序固定节点→关系→值→属性槽；同类按本地键，槽按所属节点及属性类型键排序。

节点、关系和值要求本次发布创建且当前；槽要求当前值精确为本草案对应值键。每项逐字段复制对应写项，不能用数量、摘要、首尾项或容器地址替代。计划必须精确覆盖全部75项新编码和42个当前槽，不多读、不漏读；退出读回0。

P15 v0.17只修订G7/G8真实写入口意图矩阵；其真实结果只约束后继把草案装入L1 v2请求时的DTO、领域意图、执行证据和同锁读回接口。P64生产函数不生成领域意图字节、不选择G组或操作标签、不计算G0/领域摘要，也不绑定P15内部编码。

## 7. 入口、完整性、并发与异常

入口验证P2登记合同/规则、非零截止、服务身份和三个属性类型均有效且四编码互异；验证P63结果状态为已形成且恰一携带安全/服务规格，两个规格的合同/规则、角色、值域/目标/阈值、生产者/证据有序组及十五项版本完整；P2登记截止成为草案事实截止，P63纯值规格不得携带事实截止或稳定编码。

构造后必须证明：

1. 本地键1—75连续唯一，字段键3—27逐枚举一一对应；
2. 所有本地引用指向草案已有键，稳定引用只来自P2登记；
3. 两个通用定义各恰三属性，专用记录分别15/21属性；
4. 六个通用值来源P2服务，36个专用值来源本地根定义服务；
5. 两条模板关系端点、类型和顺序精确，关系22事实为0；
6. 117项读回与写项/槽逐字段全等；
7. 草案无幂等、意图、摘要、操作标签、执行证据、事务或稳定编码。

函数不取得锁或读取时间，相同输入逐字段产生相同草案。并发调用无共享状态。入口格式失败返回`入口拒绝`；通过入口后的角色/数量/引用/P2兼容矛盾返回`内部不一致`；`std::bad_alloc`返回`资源失败`，任何非成功不携带部分草案。
