# RUNTIME-GOVERNANCE-T02-PARENT-REBASELINE T02 父治理循环重基线详细设计 v0.1

日期：2026-08-15

状态：待激活设计；本文件冻结父目标与消费合同，不证明下层 ABI、普通应用装配或循环代码已实现

## 1. 目标与完成边界

把 `BIZ-L1-T02` 从失效的 v0.1 三参数批次调用重基线为 v0.2：自我线程只经唯一 `自我治理批次路由`取得完整不可变治理批次，按结构化状态执行保槽重试、正常停止或终止分流，再在单一共享事实截止下读取一致事实并继续本轮治理。

本设计同时裁决此前未冻结的运行态所有权：

```text
普通应用上下文
  -> 持有完整秒服务、运行期事实版本服务及其它 BIZ provider
  -> 持有唯一自我线程对象并保证 provider 晚于线程析构

自我线程对象
  -> 私有持有唯一治理邮箱
  -> 私有持有绑定该邮箱的唯一自我治理批次路由
  -> 物理线程只调用自己的运行治理循环
```

本切片不实现 C++，不改 DATA provider，不重基线 `BIZ-L2-002-03`，不冻结永久 provider 失败下的完整停机时限，不声称需求—任务—方法全循环闭合。

## 2. 正式依据与当前事实

- 0050 v1.3：运行期结构化非成功、单一内存事实截止、DATA 外业务组合和停机未决边界。
- 4050：请求拒绝、资源失败、版本漂移和内部不一致分账。
- 8100、8200：自我线程负责治理编排但不直接写安全、服务、需求、任务、方法或世界事实；循环次数、消息数量和等待时长不产生业务变化。
- BIZ-L2-002-01 v0.2：邮箱批次进入路由私有待完成槽；重试只补缺失完整秒 / 共享截止，零再次读取邮箱；停止只来自邮箱正式结果。
- `RUNTIME-GOVERNANCE-CURRENT-BATCH-ASSEMBLY v0.1`：路由借用邮箱、完整秒服务和运行期事实版本服务，且必须在邮箱首次冻结前构造。
- 当前 `自我线程`代码已经私有持有 `std::unique_ptr<有界自我治理邮箱>`；普通应用尚未导入、持有或构造自我线程，也没有完整 T02 provider 组。运行门开放后的正文仍立即锁存停止，尚无治理循环。

### 2.1 v0.1 漂移裁决

| 旧口径 | 漂移 | v0.2 裁决 |
| --- | --- | --- |
| `冻结当前治理批次(邮箱, 完整秒, 停止阶段)` | 绕过新路由 DTO，恢复不存在的停止阶段事实 | 只调用 `冻结当前治理批次(组合请求)` |
| `void 运行治理循环()`且只靠生命周期消息退出 | 无法区分正常停止与批次 / 事实 / 领域失败 | 根函数返回值式 `自我治理循环退出结果`，线程入口私有保存 |
| 事实截止向量 | 已退出的多 owner 向量口径 | 批次携带单一共享截止；一致读取执行 `G0 == G1 == 全部子截止` |
| 普通应用或线程临场决定路由位置 | 可能形成第二邮箱消费者或悬空借用 | 邮箱与路由同属自我线程；普通应用只提供稳定 provider 借用 |
| 停止阶段变化唤醒并直接退出 | 可能丢弃已取出的待完成批次 | 仅当路由无待完成槽并返回邮箱 `已停止` 才正常退出 |

## 3. 运行上下文与生命周期

路由与邮箱必须在物理线程创建前完成构造。推荐且唯一合法的后继装配顺序为：

```text
普通应用先构造 BIZ provider
-> 构造唯一自我线程对象并交付稳定 provider 借用
-> 自我线程构造唯一邮箱
-> 立即构造绑定该邮箱的唯一路由
-> 验证邮箱零冻结批次和路由固定配置
-> 创建物理线程并停在关闭治理门
-> 其它线程准备完成后开放运行门
-> 线程入口调用运行治理循环
```

provider 借用不得进入创建请求的值式业务材料，也不得由 DATA getter 临场查询。它们属于普通应用运行上下文的构造依赖。析构顺序固定为：自我物理线程完成并 join，随后销毁路由 / 邮箱和自我线程对象，最后才销毁被借用 provider。

当前 `创建.自我线程.ixx`为取得 I2 材料而直接 import `装配.普通应用`；若普通应用再 import 自我线程将形成模块环。后继 `RUNTIME-GOVERNANCE-T02-RUNTIME-CONTEXT-ASSEMBLY`必须先完成唯一消环：

```text
新建真实模块：海中鱼巣/业务/合同.自我世界树根消费.ixx
模块：海中鱼巣.业务.合同.自我世界树根消费
唯一所有：现有 自我世界树根消费.数据.h 中的稳定请求 / 结果 / 材料类型
普通应用：import 该合同模块，不再在自身模块内 export include 该数据头
自我线程：import 该合同模块，删除 import 海中鱼巣.装配.普通应用
```

该共享合同模块只拥有 BIZ 值类型，不拥有普通应用、线程、provider、DATA 服务或业务编排。消环叶完成前，本计划不得激活。

## 4. 目标 ABI 与物理位置

### 4.1 值类型

退出结果和处理阶段只服务自我线程模块内部，不建立新的公开 ABI 或传统数据头；按 `CODE-FILE-01`直接在既有 `海中鱼巣/线程/创建.自我线程.ixx`模块域中保持最小可见性。预冻结语义：

```cpp
enum class 自我治理循环退出状态 : std::uint8_t {
  邮箱已停止 = 1,
  批次组合终止 = 2,
  一致事实终止 = 3,
  领域治理终止 = 4,
  下行提交终止 = 5,
  内部不一致 = 6
};

struct 自我治理循环退出结果 final {
  自我治理循环退出状态 状态 = 自我治理循环退出状态::内部不一致;
  std::uint64_t 最后成功批次序号 = 0;
  std::int64_t 最后已消费完整秒边界 = 0;
  std::optional<治理批次待重试见证> 路由待重试见证;
  std::optional<std::uint64_t> 未完成治理批次序号;
};
```

精确字段类型和 optional 归属必须在批次路由、完整秒、一致事实和线程完成结果最终 ABI 发布后机械匹配；不得把本段当作当前已存在声明。语义固定为：正常停止不携带路由见证或未完成批次；任何已取出但未完成的批次必须保留在对象私有处理槽并回显其非零序号，不能以空结果伪装正常退出。

### 4.2 根函数

| 函数 | 功能分类 | 唯一所有者 | 精确位置 | 形态 / 可见性 | 诊断责任 |
| --- | --- | --- | --- | --- | --- |
| `自我治理循环退出结果 自我线程::运行治理循环() noexcept` | 自我线程父级编排 | `自我线程`运行态 | `海中鱼巣/线程/创建.自我线程.ixx`，类私有成员；在线程入口函数附近定义 | 私有非 const 成员；不导出第二服务 | 向上送出；线程入口保存，顶层宿主为最终诊断责任边界 |
| `自我治理循环退出结果 自我线程::读取治理循环退出结果() const`（若后继收口确需） | 完成结果值式读回 | 同一对象 | 同上；必须在最终停机计划证明调用方后才允许公开 | 默认不建立；优先由现有 join / 收口结果承载 | 向上送出 |

不得新建 `自我线程.ixx`平行模块，不得把循环实现放入普通应用、入口.cpp、DATA 模块或全局工具。

## 5. 父循环状态机

父循环除路由自身待完成槽外，还私有持有一个 `当前治理批次处理槽`。路由返回 `已冻结`后必须先无抛出接管完整批次，再调用一致事实或任何领域函数。槽至少保存：

```text
完整已冻结治理批次
+ 当前处理阶段
+ 各已成功步骤的值式结果
+ 各可能写入步骤的原幂等请求与发布 / 读回见证
+ 当前有序输入游标
```

该槽不是第二业务事实或成功缓存，而是路由已经交付、父循环尚未完整处理的消息所有权。所有可能抛出的复制必须在接管或清槽前完成；处理槽存在时禁止调用路由取得下一批。

### 5.1 批次组合

父循环保存最后成功批次序号、最后已消费完整秒边界和 optional 待重试见证。每次调用只形成一个完整组合请求：

- `等待超时`：零业务处理，按运行期等待机制进入下一次调用；
- `已停止`：只有无待完成槽时可出现，返回正常停止；
- `已冻结`：清除本地待重试见证，进入一致事实读取；
- 携带待重试见证的版本漂移、资源失败或时间证据缺口：保存原见证，后继仍用同一冻结绑定调用；
- 请求拒绝、坏形状或内部不一致：返回批次组合终止；不得读取一致事实。

父循环不调用邮箱，不接触路由私有槽，不自行重排消息，不生成第二批次序号。路由成功后形成的是父处理槽，不得与路由待完成槽并存。

### 5.2 一致事实与本轮治理

已冻结批次只把其共享事实截止交给 `读取自我治理一致事实`。组合器必须在同一截止读取全部具名材料并以读前 / 读后 `G0/G1`互证；版本漂移重读同一批次，零邮箱重读。成功后依次执行：安全维护、服务与生存安全维护、任务权限、批次分类、逐项治理、需求父链重判、正差距确认、后继裁决和可选下行消息提交。

每个成功步骤把结果和完成阶段无抛出写入处理槽。合法资源失败、版本漂移或等待只恢复首个未完成步骤；已经成功的有副作用步骤不得重做，失败步骤必须复用原幂等身份和原请求。内部不一致可以使线程返回结构化终止，但处理槽仍由自我线程对象持有，后继宿主不得把它当作正常停止或销毁丢弃。

下层精确 DTO 和状态矩阵尚未全部重基线，因此本计划保持 `待激活`。执行者不得根据旧 v0.1 子图临场补字段或把合法非成功统一成 bool。

### 5.3 最后提交

只有本轮所有必需调用成功或精确重复后，才无抛出更新：

```text
最后成功批次序号
+ 最后已消费完整秒边界
+ 本轮值式运行见证
+ 清除已完成的待重试见证
+ 清空当前治理批次处理槽
```

消息提交失败、领域失败或一致事实失败不得推进上述游标，也不得清空处理槽。批次路由已经交付成功批次后，父循环不能把它退回邮箱；终止结果必须保留批次定位和必要诊断，后继恢复 / 审计不在本切片定义。

## 6. 停止与并发

1. 物理自我线程是根函数唯一调用者；不允许普通应用、测试或其它线程并发调用。
2. 邮箱锁只在邮箱内部持有；路由私有锁只在路由入口持有；父循环调用领域服务时不持有邮箱锁。
3. 正常停机应先关闭新治理输入并请求邮箱停止，随后允许已排队和路由待完成批次完成，最终由 `已停止`收口。
4. 若 provider 永久失败，消息守恒优先于超时丢弃。完整停机时限、升级原因和宿主处置仍属现行未决停机合同，保持 `NOT_RUN`；不得以本设计发明丢弃、回滚邮箱序号或 detach。

## 7. DATA 服务需求

本设计不新增基础数据服务接口。它只消费现行 `计划/数据服务最终需求清单.md`已经登记的运行期共享事实截止和各强类型只读能力，并统一经 BIZ 组合器 / DATA-L3 聚合服务进入；T02、路由和自我线程均不得直达 DATA-L1。

需要的调用形态只冻结为：

```text
输入：运行代次、事实范围版本和批次携带的非零共享事实截止
输出：同一截止下的强类型值式快照或具名结构化非成功
```

## 8. 激活门禁

本计划只有同时满足下列条件才可从待激活转为可执行：

1. 邮箱批次冻结、完整秒边界、共享当前事实截止和父组合路由均已有正式结果提交、接受、退出及临时专项清理；
2. 普通应用 / 自我线程运行上下文装配叶已完成，证明路由是邮箱唯一消费者且 provider 生命周期覆盖线程；
   该叶还必须通过共享 `合同.自我世界树根消费`模块消除 `创建.自我线程 -> 装配.普通应用`现有依赖，最终模块图无环；
3. BIZ-L2-002-02 的 G0/G1 一致事实组合最终 ABI 已发布；
4. BIZ-L2-002-03—08、003-01—04、004-01 / 06 的精确输入输出和非成功分流已重基线到当前规范；
5. 最终 `自我线程`、线程完成结果、路由及全部子 provider ABI 与本设计机械匹配；
6. 当前代码执行段、工程、构建资源和目标文件所有权均已释放。

## 9. 验证矩阵与声明边界

- 批次等待超时、正常停止、首次成功、时间失败后恢复、事实截止失败后恢复；
- 待重试见证缺失 / 错配零邮箱调用；
- 已取出批次遇停止仍先完成，下一调用才返回停止；
- G0/G1 漂移只重读一致事实，零再次冻结邮箱；
- 各下层失败不推进父游标、不清槽、不形成下行消息；恢复从首个未完成步骤继续，已成功写步骤零重复；
- 成功批次保持邮箱冻结顺序，零第二排序；
- 自我线程 / 路由 / provider 析构顺序和唯一所有权；
- Debug / Release 根工程、生产外专项、strict、UTF-8、工程唯一登记和生产零验证痕迹。

当前实际完成只包括目标图、映射、详细设计和待激活计划的文档门禁。C++、构建、动态线程、provider 故障恢复、普通应用装配、正式停止和业务闭环均 `NOT_RUN`。
