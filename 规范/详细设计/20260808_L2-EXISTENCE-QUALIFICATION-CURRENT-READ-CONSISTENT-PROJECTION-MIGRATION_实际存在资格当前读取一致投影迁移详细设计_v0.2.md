# 实际存在资格当前读取一致投影迁移详细设计 v0.2

日期：2026-08-08

状态：设计就绪；替代 v0.1，只冻结后续实施合同，不证明代码、运行或消费者合同完成。

## 1. 修订原因与目标

`L1实际存在服务::读取资格实现` 同时承接两种现行公开语义：

- `读取当前实际存在资格` 只按实际存在编码定位当前资格值；
- `读取实际存在资格` 还要求调用方显式给出的资格值编码本身是当前事实。

v0.1 把两种入口统一成 `3节点 + 0独立值 + 1属性值投影`。该形状无法区分“显式资格值编码不存在”和“显式资格值存在但不是当前资格值”，会把前者从旧合同的 `未找到` 改成 `内部不一致`。本版只修正这一设计漂移：一致读取的值选择组按是否存在显式资格值确定，公开请求、结果和旧状态映射保持不变。

本叶仍把旧分散当前读取迁移到 `L1事实基座服务::尝试读取中性一致当前投影`。第一层只返回同一事实截止下的业务中性事实；实际存在服务继续解释资格、类型、来源和领域状态。它来自第二层现有服务的真实读取需要，不是第一层自证或覆盖补格。

## 2. 保持不变的合同

- `L1实际存在合同版本 = 2`、`L1实际存在规则版本 = 1`；
- 两个公开资格读取请求、资格事实和资格结果的字段、有效性、全等与完整性规则；
- 两个公开函数的签名、服务锁边界和状态枚举；
- 当前资格仍由实际存在节点的资格属性槽唯一指向；
- 资格值材料必须为固定 I64 资格值，来源必须是实际存在登记服务身份；
- 登记建立、中性写入、幂等、稳定编码、场景关系和消费者调用关系；
- 首轮合法事实代次漂移完整重做一次、第二轮漂移返回版本漂移、许可拒绝零等待零重试。

不新增第一层 DTO、业务字段、缓存、锁、索引、写入口、自检、验收入口或专项驱动。

## 3. 正式依据与当前事实

- 4015：组合当前读取必须同代次；第一层不自证，只由第二至第五层真实数据服务运行自然累计使用证据。
- 4030：领域服务负责业务准入和结果解释；消费者只验证自身合同，不为第一层制造请求。
- 4050：未找到、许可拒绝、版本漂移、资源失败和内部不一致必须结构化分账。
- 4200：实际存在资格由实际存在领域服务唯一解释。
- ACCEPTANCE-01：禁止第一层独立验收和生产内验收代码；日志只供人观察。

当前公开显式入口先验证显式资格值编码有效，再把该编码交给 `读取资格实现`。旧实现会先读取属性槽，再按显式编码读取当前值：显式值不存在返回 `未找到`；显式值已退出返回 `内部不一致`；显式值存在但与当前槽不符返回 `内部不一致`。本版必须完整保留该分账。

## 4. 唯一目标与允许路径

唯一生产文件：

```text
海中鱼巣/领域/服务.L1实际存在.ixx
```

唯一目标私有函数保持：

```cpp
实际存在资格结果 读取资格实现(
    const 实际存在结构登记& 当前登记,
    稳定编码 存在编码,
    std::optional<稳定编码> 显式资格值) const;
```

允许在 `海中鱼巣::L1实际存在内部` 内通用化现有一致读取失败形状和状态映射 helper，并为资格项目建立最小纯值映射。登记读取根只允许机械更新共用 helper 名称，行为不得改变。

专属记录保持原稳定路径：

```text
施工记录/20260808_L2-EXISTENCE-QUALIFICATION-CURRENT-READ-CONSISTENT-PROJECTION-MIGRATION_施工记录.md
验证记录/20260808_L2-EXISTENCE-QUALIFICATION-CURRENT-READ-CONSISTENT-PROJECTION-MIGRATION_构建与生产消费验证.md
```

代码执行只可写上述三个路径。核心第一层、数据头、其它领域服务、组合服务、启动、运行期上下文、工程、filters、自检和集成验收均不在范围内。

## 5. 条件值选择请求

首轮期望代次唯一来自 `当前登记.事实截止代次`。两种请求共享：

```cpp
一致请求.合同版本 = L1中性一致当前读取合同版本;
一致请求.期望事实代次 = 本轮期望代次;
一致请求.节点 = {
    存在编码,
    当前登记.实际存在资格属性类型,
    当前登记.服务身份};
一致请求.关系 = {};
一致请求.属性值 = {
    {存在编码, 当前登记.实际存在资格属性类型}};
一致请求.源关系组 = {};
一致请求.目标关系组 = {};
```

值选择组唯一按公开入口语义形成：

```cpp
一致请求.值 = 显式资格值.has_value()
    ? std::vector<稳定编码>{*显式资格值}
    : std::vector<稳定编码>{};
```

因此固定形状为：

| 入口语义 | 节点 / 关系 / 值 / 属性值 / 源关系组 / 目标关系组 |
| --- | --- |
| 当前定位读取，无显式资格值 | `3/0/0/1/0/0` |
| 显式资格值读取 | `3/0/1/1/0/0` |

不得始终请求零值，也不得在无显式值时把属性投影当前值再重复放入值组。

## 6. 顶层控制流

1. 登记不完整、存在编码无效或显式资格值无效，返回内部不一致，零第一层调用；公开入口的原有请求校验保持。
2. 每轮恰一次调用一致当前投影。
3. 首轮合法事实代次漂移必须满足空六组、回显期望代次正确、实际代次非零且不同；丢弃整轮材料，以实际代次完整重做一次。
4. 第二轮仍漂移返回版本漂移；不得第三次调用、等待、休眠或局部补读。
5. 许可拒绝立即返回许可拒绝；资源失败返回资源失败；入口拒绝、内部不一致或坏失败形状返回内部不一致。
6. 顶层成功必须核对合同版本、期望代次、读取代次、六组长度和顺序。读取代次必须非零并等于本轮期望代次。
7. 任一项目成功却不带事实，或非成功却带事实 / 投影，返回内部不一致。
8. 任一内部项目错误优先于未找到；非成功不返回部分资格事实。

## 7. 项目状态与显式值语义

三个节点和属性投影的项目分账保持：

- 节点 `未找到`，或资格属性 `未找到` / `属性未设置`：`未找到`；
- `已退出`、`种类不匹配` 或坏载荷：`内部不一致`。

有显式资格值时，值项目必须参与同一轮判断：

- 值项目 `未找到`：`未找到`；
- 值项目 `已退出`、`种类不匹配` 或坏载荷：`内部不一致`；
- 值项目成功但其查询编码、事实编码、事实正文或生命周期不合法：`内部不一致`。

只有在所有项目都成功后才解释领域互证。若同时存在未找到和内部项目错误，返回内部不一致。

## 8. 成功互证

共同成功必须验证：

- 三个节点按实际存在、资格属性类型、登记服务来源的顺序返回，编码、种类、值表示、创建代次和未退出状态正确；
- 实际存在节点的资格属性槽恰一项，允许其它不同属性；该槽与属性投影中的槽逐字段全等；
- 属性投影查询键正确，槽当前值等于投影当前值事实编码；
- 当前值事实所属节点、属性类型、来源、I64 材料、创建代次和未退出状态正确；
- 无显式资格值时，直接采用属性投影当前值事实；
- 有显式资格值时，独立值结果查询编码和事实编码都等于显式编码，独立值事实与属性投影当前值事实逐字段全等，显式编码等于槽当前值；
- 全部事实创建代次非零且不晚于共同读取代次。

成功后形成 `实际存在资格事实`，事实截止等于共同读取代次。任何差异都返回内部不一致。

## 9. 验证与完成边界

实施至少验证：

- 目标根旧分散事实代次、节点、属性和值读取调用归零；
- 一致投影物理调用点恰一；两种请求形状分别为 `3/0/0/1/0/0` 与 `3/0/1/1/0/0`；
- 显式值未找到、已退出、非当前值及逐字段不等的映射按本版冻结；
- 登记读取根、公开 DTO、公开签名和调用者零语义变化；
- Debug / Release 完整重建、双配置模块扫描、strict、差异检查和两配置正式生产入口运行通过。

本叶只迁移真实第二层资格读取。第二至第五层通过自身数据服务真实使用第一层的增、查、改、退 / 历史等能力，并以结构化结果与权威读回完成各自合同；当当前全部下游数据服务均得到第一层正确支撑时，才可认定第一层对当前项目已完善。不得建立第一层自证、专项验收或补覆盖请求；当前不考虑崩溃、重启或跨进程恢复。
