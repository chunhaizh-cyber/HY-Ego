## 1. 目标与完成边界

本叶原位扩展 P29/P30 冻结的唯一 `世界树快照读取服务`，新增 `读取场景完整事实`。函数先校验指定世界根和目标场景见证，随后恰调用一次 P29 `读取完整世界事实快照`；整树成功后只在该不可变纯值快照上投影目标场景、直接父关系、直接子场景关系、直接存在成员关系，并为每个直接成员复用 P30 模块私有存在投影 helper 形成完整存在事实，闭合 4200 §4 的指定场景完整事实读取。

必须同时成立：

- 目标场景必须在 P29 完整世界快照的当前场景组恰一命中；指定根范围外、历史或任意非场景节点不得混入；
- 根场景合法无父，非根目标恰有一个当前直接父关系；全部直接子场景和直接成员关系双向闭合且无重复；
- 只纳入目标场景的直接存在成员，不递归纳入子场景成员；每个直接成员必须形成一份 P30 同口径完整存在子快照；
- 合法零子场景、零直接成员成功空组；直接成员为零时存在投影 helper 调用0；
- 结果沿用整树根、非零事实截止、合同/组合/完整性/排序/对象投影版本；场景关系保持 P28 稳定顺序，成员完整事实按存在稳定编码升序；
- 任一缺失、重复、端点矛盾、成员夹带或成员投影失败返回零部分场景子快照；
- 函数对 P19/P21/P17/P22/P24—P28 等直接 provider 调用均为0，只调用 P29 整树入口恰一次，不调用 P30 公开存在读根，不建立第二重试。

本叶不设计统一 `世界树业务服务`、递归子场景完整事实、写入口、比较、动作动态、因果、结算、恢复装配、生产线程接线、旧消费者迁移或 STEP-5。

## 4. 公开 DTO、稳定版本与函数

在 `L1完整世界快照.数据.h` 追加：

```cpp
struct 完整世界场景事实快照 final {
    std::uint32_t 合同版本 = 完整世界快照合同版本;
    std::uint32_t 世界规则版本 = 世界登记规则版本;
    std::uint32_t 组合规则版本 = 完整世界快照组合规则版本;
    std::uint32_t 完整性规则版本 = 完整世界快照完整性规则版本;
    std::uint32_t 排序规则版本 = 完整世界快照稳定排序规则版本;
    std::uint32_t 投影规则版本 = 完整世界对象快照投影规则版本;
    世界结构节点身份见证 世界根;
    std::uint64_t 事实截止代次 = 0;
    完整世界场景事实 场景;
    std::vector<完整世界存在事实快照> 直接成员完整事实组;
    bool 完整 = false;
};

struct 完整世界场景快照读取结果 final {
    世界树业务状态 状态 = 世界树业务状态::入口拒绝;
    std::optional<完整世界场景事实快照> 快照;
    std::vector<完整世界快照缺项诊断> 缺项组;
};
```

以上类型默认全等。场景对象读复用 P30 `完整世界对象读取请求` 和 `完整世界对象快照投影规则版本=1`，不得另建第二对象请求、场景专属投影版本、对象版本、句柄、地址、引用、指针、SQL/缓存标记、时间戳或显示名称。

`场景` 直接复用 P28 `完整世界场景事实`：其 `场景` 项携带目标场景身份，其可选直接父关系携带父场景端点，两个关系组分别携带直接子场景和直接存在成员端点。P31 不复制父/子场景详情，也不递归嵌套子场景快照。

在 P29/P30 类公开区原位追加：

```cpp
完整世界场景快照读取结果 读取场景完整事实(
    const 完整世界对象读取请求& 请求) const;
```

模块私有 helper 固定为无对象状态的纯值函数：

```cpp
完整世界场景快照读取结果 从完整世界快照投影场景完整事实(
    const 完整世界对象读取请求& 请求,
    const 完整世界事实快照& 世界);
```

公开函数唯一负责准入、调用 P29 整树入口一次、映射整树非成功和调用场景 helper；场景 helper 只可复用 P30 私有存在 helper，不得递归调用任何公开函数或 provider。

## 5. 请求准入与整树结果映射

调用 P29 前固定验证：

1. `请求.世界` 满足 P28/P29 合同、世界规则、组合规则和非零普通节点根；
2. `投影规则版本 == 完整世界对象快照投影规则版本`；
3. `目标.稳定编码` 非零且节点类型为普通节点；场景资格只由整树 `场景组` 命中证明，不能由名称、关系端点裸命中或 P18 登记猜测。

任一失败返回入口拒绝、空快照、空缺项，P29调用0。准入成功后以 `请求.世界` 恰调用一次 `读取完整世界事实快照`：

| P29状态 | P31结果 | 规则 |
| --- | --- | --- |
| 已读取且快照完整 | 进入纯值场景投影 | P29调用恰1 |
| 未找到/入口拒绝/版本漂移/许可拒绝/资源失败/未实现 | 同名返回 | 快照空、缺项空 |
| 内部不一致 | 内部不一致 | 快照空；P29稳定缺项原样复制 |
| 写入口状态、坏成功、未知枚举 | 内部不一致 | 快照空、缺项空 |

坏成功判断与 P30 完全同源：optional、`完整=true`、非零截止、根/版本与请求一致且缺项空必须同时成立。P31 不在 P29 版本漂移后再次调用 P29；P29 内部最多两轮是唯一重试边界。

## 6. 目标场景和直接结构闭合

场景 helper 固定按以下顺序处理：

1. 在 `世界.场景组` 按 `场景.场景.场景` 的完整节点见证查找请求目标；零命中返回未找到，多命中或同稳定编码异内容返回内部不一致；
2. 若目标等于世界根，`直接父关系` 必须为空；否则必须存在且方向为父场景到目标，父端在场景组恰一命中，目标场景项的父见证与父场景的直接子关系恰一全等；
3. 每条直接子场景关系必须源端为目标、目标端在场景组恰一命中，且子场景 `直接父关系` 与之全等；重复关系、重复子端点、反向或跨树端点均内部不一致；
4. 每条直接存在成员关系必须源端为目标、目标端在存在组恰一命中，且该存在的 `当前场景` 为目标、`当前归属关系` 与之全等；
5. 反向扫描存在组：所有 `当前场景 == 目标` 的存在必须且只能由目标直接成员关系组命中一次；关系有成员而存在组缺失、存在归属目标但关系遗漏、同成员多关系或夹带其它场景成员均内部不一致。

合法目标零子场景以空 `直接子场景关系` 表达；合法零直接成员以空 `直接存在成员关系` 和空 `直接成员完整事实组` 表达。P31 只返回目标的直接结构，不递归投影子场景，也不把子场景成员算作目标直接成员。

内部不一致缺项只复用 P28 既有种类：世界结构不完整、场景关系范围矛盾、实际存在范围矛盾、存在当前归属矛盾或稳定排序/唯一性错误；诊断按 P28 `(种类, 主身份, 关系身份, 相关身份)` 排序去重。不得新增文本诊断或第二缺项枚举。

## 7. 直接成员完整事实形成

目标直接成员身份集合经第6节双向闭合后，按成员存在稳定编码严格升序。对每个成员构造仅替换 `目标` 的 `完整世界对象读取请求`，世界请求与投影规则保持原值，然后调用 P30 模块私有 `从完整世界快照投影存在完整事实`：

- 输入始终是本轮同一份 P29 `完整世界事实快照`，不得调用 P30 公开根或重取整树；
- helper 必须返回 `已读取`、完整子快照、空缺项，且六个版本、世界根、截止逐字段等于场景读取上下文；
- 返回存在必须等于成员身份，当前场景必须等于目标场景，当前归属必须等于对应直接成员关系；
- helper 的宿主全特征和相关状态/动态按 P30 合同保留；同一动态若与多个直接成员相关，可分别出现在各自完整存在事实中，不在场景层去重或改写；
- helper 返回未找到、内部不一致、其它非成功或坏成功，均说明整树与直接成员合同矛盾，P31 映射内部不一致并销毁全部已形成成员子快照。

成员输出按存在稳定编码升序，禁止按直接成员关系编码、地址、容器插入序、显示名或时间戳排序。场景内部两个关系组继续保持 P28 已验证的关系稳定编码顺序；两种顺序各自独立，不强求同位。

## 8. 输出、异常、并发与生命周期

全部检查完成后才形成成功值：

- 六个版本来自正式常量/请求并与整树相等；
- 世界根、截止来自整树；
- 场景事实逐字段复制 P28 场景组唯一目标；
- 直接成员完整事实为同一整树上 P30 helper 形成的稳定有序全量组；
- `完整=true`，缺项空。

未找到、入口拒绝、版本漂移、许可拒绝、资源失败和未实现均为空快照、空缺项。内部不一致为空快照，可携带稳定缺项。任一失败先销毁临时 vector，不返回部分场景或部分成员。

函数不 `noexcept`；`std::bad_alloc` 映射资源失败，其它未预期异常映射内部不一致，异常不触发第二次整树读取。函数只借用请求和 P29 返回值，返回后不保存引用、索引、子快照、截止或缓存。多个线程并发调用只共享 P29 服务对象只读入口，P31 无新锁和共享状态。
