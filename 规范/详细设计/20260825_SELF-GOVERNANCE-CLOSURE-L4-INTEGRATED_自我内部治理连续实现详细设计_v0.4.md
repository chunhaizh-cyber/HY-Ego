## 2. 0x0306 逐需求核算合同

### 2.1 身份、结论与完整事实

下列类型唯一声明于`海中鱼巣/领域/L2需求结算结构.数据.h`，由`海中鱼巣.领域.服务.L2需求结算结构`公开可达：

```cpp
struct L2需求本轮核算身份 final {
    稳定编码 值;
};

struct L2需求满足记录身份 final {
    稳定编码 值;
    explicit L2需求满足记录身份(稳定编码 编码 = {}) noexcept
        : 值(编码) {}
    bool 有效() const noexcept {
        return ::海中鱼巣::有效(值);
    }
    friend bool operator==(const L2需求满足记录身份&,
        const L2需求满足记录身份&) = default;
};

enum class L2需求本轮核算结论 : std::uint8_t {
    已满足 = 1,
    未满足 = 2,
    未获分配 = 3,
    材料不足 = 4,
    不可比较 = 5
};

struct L2需求本轮核算事实 final {
    L2需求本轮核算身份 身份;
    L2需求身份 需求;
    L2任务身份 来源任务;
    L2任务轮次身份 来源任务轮次;
    L2任务实际结果身份 来源正式结果;
    L2任务结果消费分配记录身份 消费分配记录;
    L2成员消费资格材料 消费资格;
    L2成员消费分配状态 分配状态 = L2成员消费分配状态::未获分配;
    L2需求本轮核算结论 结论 = L2需求本轮核算结论::材料不足;
    std::optional<L2需求满足记录身份> 正式满足记录;
    L2状态身份 比较时实际状态;
    L2目标状态合同身份 目标状态合同;
    稳定编码 比较注册;
    std::uint64_t 来源共同事实截止 = 0;
    std::uint32_t 核算规则版本 = 1;
    L2生命周期 生命周期;
};
```

`L2需求满足记录身份`也唯一声明于该数据头，默认构造为零稳定编码，逐字段相等，有效当且仅当`::海中鱼巣::有效(值)`；它只引用 5160 正式满足记录，不拥有、发布或重判需求满足事实，不得成为第二满足权威。其它身份和事实按上述物理顺序逐字段相等。候选写入时`身份`与`生命周期`留空，其余字段全部参与幂等同义比较。`消费资格`必须等于完整分配记录冻结成员中的唯一对应项；`分配状态`必须等于该记录逐成员结果中的同成员状态，不允许 provider 复制或重算一套分配权威。

每次只核算一个当前 T→D。`共同引用`和`已分配`才允许进入该 D 的目标比较；`未获分配`和`结果已耗尽`分别只允许形成结论`未获分配`，不得伪造满足。目标、实际状态或比较注册不足形成`材料不足`；材料完整但当前比较合同不支持比较形成`不可比较`。仅`已满足`允许且必须携带经 5160 正式入口独立读回的`正式满足记录`；其余四种结论该字段必须为空。

### 2.3 状态、载荷与成功矩阵

| 入口 | 状态 | 完整事实 | 提交见证 | 正式读回截止 | `成功()` |
| --- | --- | --- | --- | --- | --- |
| 写 | `已形成`、`精确重复` | 必有且形状完整 | 空 | 非零 | 是 |
| 写 | `已可能发布` | 空 | 必有且四字段有效 | 0 | 否 |
| 写 | 其它状态 | 空 | 空 | 0 | 否 |
| 读 | `已读取` | 必有且形状完整 | 不适用 | 非零 | 是 |
| 读 | `未找到`或其它状态 | 空 | 不适用 | 0 | 否 |

任何交换前失败零写。L1 已确认提交而首次正式独立读回失败时，只返回`已可能发布 + 四字段提交见证`，不得伪造核算事实；以原请求和原幂等身份重放，精确重复零应用、零新代次，并在正式读回成功后返回首次完整事实。

业务入口`需求本轮核算结果 核算一个来源需求(const 需求本轮核算请求&) noexcept`继续属于 v0.3 的结算编排服务。其请求必须完整绑定`合同版本、settlement owner请求头与幂等身份、D、T、Rn、正式实际结果、完整消费分配记录身份、消费资格、分配状态、比较时实际状态、目标状态合同、比较注册、来源共同事实截止、核算规则版本`；业务结果只能投影上述结构写入矩阵，不建立第二核算事实。

## 3. owner 与事务边界

`L2任务结果消费结构服务`是 0x0305 result owner，完整消费分配记录及其逐成员结果在一个 result owner 写事务内形成。`L2需求结算结构服务`是 0x0306 settlement owner，登记区仍为`0x0306'2000..0x0306'20FF`，每个 D 的一条本轮核算在一个 settlement owner 写事务内形成。

两个 owner 的事实、幂等账、写端口和事实代次互不借用，不宣称跨 owner 同一 G1。普通应用按既有 L2 owner 模式从`L1事实基座服务::建立所有者范围(...)`取得各自唯一交付；结构服务只验证自身 owner/端口、登记固定类型并机械写读，不裁决消费关系、成员分配、目标满足或轮次结论。不得在编排服务、需求 owner、task owner或线程中建立第二 result/settlement owner。

编排顺序固定为：先独立读回 0x0305 完整记录，再对每个当前合格 T→D 分别调用 0x0306 写入口并独立读回。后一个 owner失败不得回滚前一个 owner 已确认的事实、账或代次。

## 4. 轮次结算与收束引用修订

v0.1 第 6.6 节除本节替换内容外继续有效。`L2任务轮次结算事实`中的旧字段：

```cpp
L2任务结果消费裁决身份 结果消费裁决;
```

唯一替换为：

```cpp
L2任务结果消费分配记录身份 结果消费分配记录;
std::vector<L2需求本轮核算身份> 需求核算结果组;
```

`需求核算结果组`按需求身份稳定排序。轮次收束请求必须绑定`合同版本、task owner请求头与幂等身份、阶段迁移幂等身份、T、Rn、可选正式实际结果、轮次结论、验证归因收口、完整消费分配记录身份、稳定排序需求核算身份组、稳定排序强类型适用后继结果组、执行冻结收口、互斥强类型授权收口、任务运行停止证据、阶段端口完整旧当前选择引用、来源共同事实截止、结算规则版本、轮次收束治理动作调用身份`。

`形成任务轮次结算并收束`必须先正式读回并验证：

1. 完整消费分配记录已经收束，且其 T、Rn、正式结果、冻结成员和来源截止与请求一致；
2. 每个当前合格 T→D 在稳定核算身份组中恰有一条 0x0306 正式核算，零缺项、零多项、零额外成员；
3. 任务运行停止、执行冻结和授权消费/撤回/无需授权均已收口，适用价值或学习引用均正式读回；
4. 阶段端口旧当前选择引用仍为正式当前，阶段迁移幂等身份与轮次收束治理动作调用身份有效。

task owner 写入轮次结算与阶段 owner迁移到`{轮次已收束,轮次已收束待自我决议}`是两个有序、独立提交，各自拥有 G1，禁止伪装成同一事务。完整成功必须轮次结算事实、轮次收束治理动作和阶段迁移三者独立读回。任一提交后读回失败保留对应提交见证；以原 task 幂等身份和阶段迁移幂等身份重放，禁止回滚前段已经确认的事实、账或代次。
