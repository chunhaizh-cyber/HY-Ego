# 完整存在概念定义提供者详细设计

身份：`EXISTENCE-CONCEPT-COMPLETE-DEFINITION-PROVIDER`
版本：v0.2
日期：2026-09-16
状态：用于同名可执行代码计划的冻结详细设计

## 1. 目标与边界

本叶让概念树类能够以“完整存在概念定义”为唯一键，完成定义规范化、精确查询、创建或复用及完整读回。它是 7100 第一条路径的最早提供者，不创建世界存在 E，不写真实特征、组成或关系事实，不写 `E→EC` 使用、世界事实支持、名称、直接上下位或主动归纳。

调用方在调用前已经裁决本次范围内的已知事实是否完整；概念树只保存这个声明和已裁决的抽象约束，绝不扫描世界、概念图、索引或缓存补齐定义。

## 2. 现状与复用裁决

现有 `纯概念定义` 仅有特征模板组，无法表达组成和关系约束，扩展其 `variant` 会改写旧纯概念消费者的意义。因此保留旧公开族、旧精确查询与旧存量读回不动，新增独立完整存在概念 DTO 与入口。

`概念树类数据服务` 已拥有概念 identity、生命周期、定义读回、原键幂等、Gread/H、预算和 owner-scoped 发布基础；本叶扩展其所有者私有布局和普通应用装配，不新建第二概念 owner、仓库、公共包装层或工程文件。

## 3. 公共 DTO 与函数

声明位置固定为 `海中鱼巣/领域/合同.相关概念添加参与.h`，定义位置固定为 `海中鱼巣/领域/数据服务.概念树类.h/.cpp`。下列名称、字段、版本和值域为最终合同：

```cpp
enum class 存在概念完整性声明 : std::uint8_t {
    未声明 = 0,
    本次定义范围已知事实完整 = 1
};

struct 完整存在概念自身特征约束 { 概念树概念身份 特征概念; };
struct 完整存在概念组成约束 {
    概念树概念身份 子存在概念;
    稳定编码 组成角色;
    std::uint64_t 精确数量;
};
struct 完整存在概念关系参与角色约束 {
    std::uint64_t 顺序;
    概念树概念身份 概念约束;
};
struct 完整存在概念关系约束 {
    稳定编码 关系类型;
    std::vector<完整存在概念关系参与角色约束> 有序参与角色;
};
struct 完整存在概念定义 {
    存在概念完整性声明 完整性;
    std::vector<完整存在概念自身特征约束> 自身特征;
    std::vector<完整存在概念组成约束> 组成;
    std::vector<完整存在概念关系约束> 关系;
};
```

四类请求的精确字段固定为：规范化/查询 `{版本=1,Gread,H,定义,预算}`，读取 `{版本=1,Gread,H,概念,预算}`，创建或复用 `{版本=1,G0,幂等身份,定义,预算}`。`预算`复用现有`概念树预算`，三个上限均为非零；读取、查询、规范化要求非零 `Gread/H` 且 `H<=Gread`，创建要求非零 `G0`且非`UINT64_MAX`。创建的首次材料/重放不新增第五公开入口：服务内部以同一原键调用现有 owner 端口的`读取首次写入材料`，将其规范化写集与本次完整定义写集逐项比较；缺首次材料才进入查询/创建，已有同键异写集返回幂等冲突。

规范化结果为 `{版本=1,状态,Gread,H,定义}`；读取/查询结果为 `{版本=1,状态,Gread,H,事实}`；创建结果为 `{版本=1,状态,发布,Gread,H,首次发布H,原请求,事实}`。`事实`固定包含概念身份、存在类别、生命周期、定义记录、三组约束以及每项定义关系/属性的生命周期。查询成功谓词要求状态已读取、同请求截止和非空事实；确认未找到谓词要求状态未找到、同请求截止和空事实。创建成功谓词要求状态已创建或精确重复、确认发布、`H=首次发布H=G0+1`、原请求等于请求及完整事实；任何发布未知都只保留原请求，零事实。

```cpp
完整存在概念规范化结果 规范化完整存在概念定义(
    const 完整存在概念定义规范化请求&) const noexcept;
完整存在概念精确查询结果 精确查询完整存在概念(
    const 完整存在概念精确查询请求&) const noexcept;
完整存在概念创建或复用结果 创建或复用完整存在概念(
    const 完整存在概念创建或复用请求&) noexcept;
完整存在概念读取结果 读取完整存在概念(
    const 完整存在概念读取请求&) const noexcept;
```

结果的成功载荷必须完整返回 `完整存在概念定义`、概念身份、类别、生命周期、定义记录及全部定义关系生命周期；精确查询未命中不带部分定义或候选身份。

## 4. 规范化与读回

1. 仅接受 `完整性=本次定义范围已知事实完整`；三组各自先按字段排序。自身特征按概念身份；组成按“子存在概念、组成角色、精确数量”；关系按“关系类型、参与角色序列”。
2. 全字段相同的重复项拒绝，不能静默去重。组成角色和关系类型只检查非零；它们是外部已裁决的稳定身份，不在本服务重新解释或登记。
3. 每个自身特征概念按同一 Gread/H 读回为当前特征类概念；其余概念引用读回为当前存在类概念。引用不当前、类别不符、读回漂移或预算耗尽分别失败。
4. 每个关系项的参与顺序必须恰为 `1..N`，无重复；N 为零时只表示该完整定义中该关系项没有参与角色记录。该形状是否符合特定关系类型的业务语义，由调用方已经裁决的正式关系合同负责；本提供者不新增或猜测角色基数规则。
5. 创建、查询和读取都以同一个规范化副本比较/重建；容器原顺序、名称、实例编码、来源、G、H、幂等键、缓存和物理节点编码均不进入签名。

## 5. 物理布局与事务

概念 owner 的私有初始化一次建立下列关系/属性类型，并在概念树私有结构交付中保存：

```text
C --完整定义(角色1)--> D(普通定义记录)
D --自身特征(顺序)--> FC
D --组成项(顺序)--> O(普通组成约束记录)
O --子概念(角色1)--> EC_child   [O属性：组成角色、精确数量]
D --关系项(顺序)--> R(普通关系约束记录) [R属性：关系类型]
R --参与角色(顺序)--> EC_role
```

`C` 是当前存在类别普通概念；`D`、`O`、`R` 是概念 owner 的普通定义记录，不是世界 E、概念、关系类型或第二身份。L1 的属性槽只属于节点而非关系，故组成角色/精确数量必须写入 O，不能附着于 `D→EC_child` 关系；关系类型写入 R。所有新节点、关系、属性和概念生命周期由 concept owner 在一个 owner-scoped 写集发布；C 首次发布即带 D 和全部三组约束，零直接上位合法。已发布后最终读回失败返回发布未知，重放只使用原 G0、原键和原完整定义。

精确索引键使用规范化定义的完整稳定序列，索引命中必须按同截止读回 C/D/全部项验证；索引未命中仅在索引覆盖当前完整键空间已被本服务确认时才返回“确认不存在”。同定义异原键只读复用，原键精确重复返回既有首次结果；同键异完整写集为幂等冲突。

## 6. 控制流

```text
规范化请求
 -> 入口/预算/引用类别核验
 -> 完整稳定排序和重复/顺序核验
 -> 精确索引召回 + 完整同截止读回
 -> 命中：返回复用概念
 -> 确认不存在：构造 C/D/R 全写集并发布
 -> 按原键完整读回
 -> 已发布读回失败：发布未知，禁止新键重建
```

每一步的非成功都零部分成功载荷；只有“确认不存在”是查询的正常无载荷结果。创建入口绝不降级为“局部概念”或旧纯概念入口。

## 7. 后继路线（非本叶）

此提供者发布后，下一消费者才能用一个已发布 EC 与存在类/世界树类共同原子发布 E、初始真实事实和 `E→EC` 使用；支持则在真实事实可核验后独立写入、独立读回。该事务仍缺完整多 owner 设计，故不登记为待激活计划。
