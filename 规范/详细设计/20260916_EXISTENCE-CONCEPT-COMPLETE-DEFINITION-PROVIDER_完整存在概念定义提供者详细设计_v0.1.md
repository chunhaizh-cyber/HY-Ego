# 完整存在概念定义提供者详细设计

身份：`EXISTENCE-CONCEPT-COMPLETE-DEFINITION-PROVIDER`
版本：v0.3
日期：2026-09-16
状态：执行期第二次 DRIFT 已裁决；等待执行者重新 S0

## 1. 目标与边界

本叶让概念树以“完整存在概念定义”为唯一键，完成定义规范化、精确查询、创建或复用、首次材料恢复和完整读回。定义包含自身特征、组成和关系三组约束。调用方在调用前已裁决本次范围内的已知事实完整；概念树只保存该声明和抽象约束，不扫描世界、概念图、索引或缓存补齐定义。

不创建世界存在 E，不写真实特征、组成或关系事实，不写 `E→EC` 使用、世界事实支持、名称、直接上下位或主动归纳；不建立第二概念族、第二 owner 或第二概念服务。

## 2. DRIFT 裁决与复用边界

当前 `纯概念定义` 是 `纯I64特征概念定义`、`纯合取存在概念定义`、`通用存在概念定义` 的 `std::variant`；`纯概念事实` 固定持有它，`pure_layout_`、概念族成员、类别、生命周期、精确查询、读回、首次材料和写集均以此为唯一 owner。若保持该 variant 不变，又不新建第二概念族，就没有物理承载完整定义的合法位置。

因此本叶只作兼容扩展：把 `完整存在概念定义` 加为 `纯概念定义` 的第四分支，由既有 `纯概念事实`、`pure_layout_`、概念族成员、类别为“存在”的身份、既有 `纯概念状态`、生命周期、精确查询、读回和首次材料机制直接承载。它是既有公开 DTO 的机械扩展，旧三分支的 DTO、函数、写集、读回和调用语义不得改变。旧消费者必须以 `std::get_if` 或 `std::holds_alternative` 处理已知分支，禁止假定 visitor 对 variant 穷尽；执行者发现现有穷尽 visitor 时，只将其补为对新分支显式拒绝或按本设计处理，不重新解释旧分支。

原 v0.2 的“独立完整定义 DTO 与四个独立入口”撤销。新分支只能经既有 `纯概念查询请求 / 精确查询纯概念`、`纯概念创建请求 / 创建或复用纯概念`、`纯概念读取请求 / 读取纯概念` 和 `纯概念创建恢复请求 / 读取纯概念创建首次结果` 进入；不得并存第二套同义入口或结果状态。

## 3. 新增 variant 分支与既有请求/结果映射

合同头 `海中鱼巣/领域/合同.相关概念添加参与.h` 新增下列值对象，并将末项加入 `using 纯概念定义 = std::variant<...>`：

```cpp
enum class 存在概念完整性声明 : std::uint8_t {
    未声明 = 0,
    本次定义范围已知事实完整 = 1
};
struct 完整存在概念自身特征约束 { 概念树概念身份 特征概念; };
struct 完整存在概念组成约束 {
    概念树概念身份 子存在概念;
    稳定编码 组成角色;
    std::uint64_t 精确数量;
};
struct 完整存在概念关系参与角色约束 {
    std::uint64_t 顺序;
    概念树概念身份 概念约束;
};
struct 完整存在概念关系约束 {
    稳定编码 关系类型;
    std::vector<完整存在概念关系参与角色约束> 有序参与角色;
};
struct 完整存在概念定义 {
    存在概念完整性声明 完整性;
    std::vector<完整存在概念自身特征约束> 自身特征;
    std::vector<完整存在概念组成约束> 组成;
    std::vector<完整存在概念关系约束> 关系;
    friend bool operator==(const 完整存在概念定义&, const 完整存在概念定义&) = default;
};
```

请求和结果不新增版本或字段。现有 `纯概念查询请求` 的 `{版本=2,Gread,H,定义,预算}`、`纯概念读取请求` 的 `{版本=2,Gread,H,概念,预算}`、`纯概念创建请求` 的 `{版本=2,G0,幂等身份,定义,组织,直接上位,预算}` 以及恢复请求仍为唯一 ABI。完整存在分支的创建只接受现有“显式顶层 + 零直接上位”；其它组织指定或上位输入拒绝。`纯概念事实.类别` 必须为现有“存在”类别，定义、定义记录、定义关系、生命周期与发布语义均沿用既有事实/结果。

## 4. 规范化、读取和精确签名

1. 仅接受 `完整性=本次定义范围已知事实完整`。自身特征按概念身份排序；组成按“子存在概念、组成角色、精确数量”排序；关系按“关系类型、参与角色序列”排序。全字段重复项拒绝，绝不静默去重。
2. 组成角色、关系类型和精确数量均须非零。自身特征概念按同一 `Gread/H` 读回为当前特征类概念；子存在概念及参与角色概念读回为当前存在类概念。引用不当前、类别不符、读回漂移和预算耗尽分别映射既有 `纯概念状态`，不创建新状态。
3. 每个关系项的参与顺序必须恰为 `1..N`、无重复。`N=0` 仅表示该定义的该关系项没有参与角色；关系类型的业务角色基数不由概念树判断。
4. `定义匹配`、概念实例私有规范化、精确查询和读回统一使用此稳定副本。容器原顺序、名称、来源、G/H、幂等键、缓存和物理编码不进入签名。命中索引仍须按同一截止完整读回 `C/D/全部项` 验证；未命中只有在既有索引覆盖已确认时才是正常“确认未找到”。
5. 创建路径继续以原幂等键读既有首次材料；同键同规范化写集精确重放，同键异写集为既有幂等冲突，发布后读回失败为既有可能发布/发布未知收口。不得增加第五公开恢复入口。

## 5. 同一 owner 的物理布局扩展

`纯概念结构类型_v2` 增加下列既有 concept owner 私有类型见证，并由同一 `登记纯概念结构_v2` 交付、初始化、恢复和 `pure_layout_` 承载：完整定义关系、定义自身特征关系、定义组成项关系、定义关系项关系、关系参与角色关系、组成角色属性、精确数量属性、关系类型属性。`纯概念定义关系种类` 增加相应定义关系种类，以便所有物理关系仍通过 `纯概念事实.定义关系组` 被读取。

```text
C --完整定义--> D(普通定义记录)
D --自身特征(顺序)--> FC
D --组成项(顺序)--> O(普通组成记录)
O --子概念--> EC_child
O 属性：组成角色、精确数量
D --关系项(顺序)--> R(普通关系记录)
R 属性：关系类型
R --参与角色(顺序)--> EC_role
```

`C` 是同一纯概念族的存在类别普通概念；`D/O/R` 是 owner 私有普通记录，均非世界 E、第二概念、关系类型身份或第二 owner。L1 属性仅属于节点，所以组成角色和精确数量写入 O，关系类型写入 R，禁止附着在 L1 关系上。首次发布在同一 owner-scoped 写集同时形成 C、D、O/R、关系、属性和生命周期；零直接上位合法。

## 6. 既有函数的分支实现

`概念树类数据服务` 不新增公开完整定义函数。其既有私有规范化、内部读回、精确查询、形成写集与创建/复用流程新增第四分支：

```text
既有查询/创建请求（定义为完整存在分支）
 -> 既有入口、预算、组织与引用类别核验
 -> 完整定义稳定排序、重复和参与顺序核验
 -> 既有精确索引 + C/D/O/R 同截止完整读回
 -> 命中：既有精确重复/查询成功结果
 -> 确认不存在：同一 owner 写集发布
 -> 既有首次材料恢复与完整读回
```

写集、读回与 `事实完整` 的第四分支必须核验：概念类别/生命周期、唯一 D、三组关系的关系种类与顺序、每个 O/R 节点生命周期、三项属性和值材料、全部目标概念类别及规范化定义；失败一律返回既有零载荷失败状态。旧 I64、合取、通用三个分支的成功谓词、写集数量、关系种类和读回形状保持不变。

普通应用仅继续构造并暴露同一概念树服务对象；是否需要源码改动由执行者按当前构造/公开服务口重新 S0 判断，不为新分支另设装配服务或消费者接线。

## 7. 后继与验收边界

发布后的唯一新能力是完整定义 EC 的 owner 内创建、复用与读回。E、初始真实事实及 `E→EC` 同原子发布仍缺多 owner 事务设计，仅保留为路线输入。

用户明确本轮不用测试：不要求构建、运行、专项、故障注入、恢复或集成验收；计划修订只做差异格式检查，不证明源码能力。
