# 完整存在概念定义提供者详细设计

身份：`EXISTENCE-CONCEPT-COMPLETE-DEFINITION-PROVIDER`
版本：v0.4
日期：2026-09-16
状态：可执行代码计划的冻结详细设计

## 1. 目标与范围

按 7100 v1.7 §2.1，概念树对“完整存在概念定义”提供独立的值式公共合同：规范化、精确查询、创建或复用、完整读回。定义只保存调用方已裁决完整的自身特征、组成与关系三组抽象约束。

公共合同独立，不代表建立第二物理概念族。本叶将完整定义作为既有 `纯概念定义` 的第四内部 `variant` 分支，由现有 `纯概念事实`、`pure_layout_`、概念族成员、存在类别、生命周期、原键首次材料恢复和 owner-scoped 写集唯一承载。不得建立第二 owner、第二概念身份、第二仓库、E、真实事实、概念使用、支持、名称、直接上下位或主动归纳。

## 2. 独立公共 ABI

在 `海中鱼巣/领域/合同.相关概念添加参与.h` 新增下列独立值对象：

```cpp
enum class 存在概念完整性声明 : std::uint8_t {
    未声明 = 0, 本次定义范围已知事实完整 = 1
};
struct 完整存在概念自身特征约束 { 概念树概念身份 特征概念; };
struct 完整存在概念组成约束 {
    概念树概念身份 子存在概念; 稳定编码 组成角色; std::uint64_t 精确数量;
};
struct 完整存在概念关系参与角色约束 {
    std::uint64_t 顺序; 概念树概念身份 概念约束;
};
struct 完整存在概念关系约束 {
    稳定编码 关系类型; std::vector<完整存在概念关系参与角色约束> 有序参与角色;
};
struct 完整存在概念定义 {
    存在概念完整性声明 完整性;
    std::vector<完整存在概念自身特征约束> 自身特征;
    std::vector<完整存在概念组成约束> 组成;
    std::vector<完整存在概念关系约束> 关系;
    friend bool operator==(const 完整存在概念定义&, const 完整存在概念定义&) = default;
};
```

独立请求/结果均为版本 `1`，预算复用 `概念树预算`，并且不得使用 `纯概念请求/结果` 作为公开字段：

```text
规范化请求  {版本,Gread,H,定义,预算}
规范化结果  {版本,状态,Gread,H,定义}
查询请求    {版本,Gread,H,定义,预算}
查询结果    {版本,状态,Gread,H,事实}
创建请求    {版本,G0,幂等身份,定义,预算}
创建结果    {版本,状态,发布,Gread,H,首次发布H,原请求,事实}
读取请求    {版本,Gread,H,概念,预算}
读取结果    {版本,状态,Gread,H,事实}
```

`事实`是独立完整存在概念事实：概念身份、存在类别、生命周期、定义记录、完整定义和全部定义关系/属性生命周期。公开状态与发布状态可枚举映射既有 `纯概念状态/纯概念发布状态` 的同义结果，但不得向调用方泄漏 `纯概念` DTO。四个函数固定声明于 `概念树类数据服务`：

```cpp
完整存在概念规范化结果 规范化完整存在概念定义(
    const 完整存在概念定义规范化请求&) const noexcept;
完整存在概念精确查询结果 精确查询完整存在概念(
    const 完整存在概念精确查询请求&) const noexcept;
完整存在概念创建或复用结果 创建或复用完整存在概念(
    const 完整存在概念创建或复用请求&) noexcept;
完整存在概念读取结果 读取完整存在概念(
    const 完整存在概念读取请求&) const noexcept;
```

规范化/查询/读取要求非零 `Gread/H` 且 `H<=Gread`；创建要求非零且非最大 `G0`。三种预算上限非零。查询成功必须同截止、非空完整事实；确认未找到必须同截止、空事实；发布未知仅保留原请求，零事实。

## 3. 规范化和内部映射

只接受完整性声明“本次定义范围已知事实完整”。自身特征按概念身份、组成按“子存在概念/组成角色/精确数量”、关系按“关系类型/参与角色序列”稳定排序；完全重复项拒绝。角色、关系类型和精确数量非零；关系参与顺序恰为 `1..N` 且无重复。三组可为空，完整性不得省略。

同一 `Gread/H` 下，自身特征引用必须是当前特征类别概念；子存在及关系参与引用必须是当前存在类别概念。概念树不解释关系角色基数或语义。引用不当前、类别不符、代次漂移、预算不足等按独立状态返回。

规范化成功后，服务仅在内部构造等值的 `纯概念定义{完整存在概念定义}` 第四分支，调用既有纯概念私有规范化、精确索引、读回、写集和首次材料恢复机制；再将返回事实双向无损映射为独立完整事实。旧 `纯概念` 三分支、其公开入口、请求/结果、写集、成功谓词和消费者语义不得改变。

## 4. 同一 owner 的物理布局

`纯概念结构类型_v2` 和同一 `登记纯概念结构_v2` 增加 owner 私有类型见证：完整定义、定义自身特征、组成项、关系项、参与角色关系，以及组成角色、精确数量、关系类型三种属性。交付与 `pure_layout_` 扩展这些类型。

```text
C --完整定义--> D(普通定义记录)
D --自身特征(顺序)--> FC
D --组成项(顺序)--> O(普通组成记录)
O --子概念--> EC_child；O 属性：组成角色、精确数量
D --关系项(顺序)--> R(普通关系记录)
R 属性：关系类型；R --参与角色(顺序)--> EC_role
```

`C` 是既有纯概念族的存在类别普通概念；`D/O/R` 都是同一 owner 的普通记录。L1 属性只属于节点，故组成角色/精确数量写 O、关系类型写 R，绝不写入 L1 关系。首次发布同一 owner-scoped 写集同时形成 C/D/O/R、关系、属性和生命周期；零直接上位合法。

## 5. 查询、创建和恢复

精确签名只使用规范化三组字段；容器原顺序、名称、来源、G/H、幂等键、缓存和物理编码不入签名。索引命中必须在同截止完整读回 C/D/O/R 后才成功；索引确认不存在才允许创建。

创建入口以独立原键读取既有 owner 首次材料，并将本次内部规范化写集逐项比较：同键同写集精确重放，同键异写集幂等冲突；未找到才创建；可能发布/读回失败只按原请求收敛。对外始终返回独立完整定义的请求/结果/事实。
