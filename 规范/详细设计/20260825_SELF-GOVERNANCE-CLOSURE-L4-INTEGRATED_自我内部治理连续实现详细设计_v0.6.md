```text

```

本版本只替换 v0.5 中“worker 直接执行后进入既有结果链”的不完整部分，冻结生产动作端口长期所有权、逐动作预计动态、动作前 fresh 全证据复核、不可变完成消息、动作后权威读回、worker 到任务管理的异步定位边界、task-owner v2 提交见证与同键收束。任务 owner 不变，任务轮次、主阶段、授权、安全硬否决、逐需求核算、轮次收束和自我后继语义不变。


## 2. method v2、强请求与预计动态

### 2.1 三项动作合同

`L2方法动作入口事实_v2`与`L2方法动作入口写入请求_v2`在 v0.5 已冻结字段尾部依次追加：

```cpp
稳定编码 预期结果材料;
稳定编码 结果验证合同;
稳定编码 动作归因合同;
```

三字段均必须非零，逐字段参与有效性、同义性、幂等与正式读回比较。`任务冻结动作项`同步携带相同三字段；从 method v2 读取、筹办冻结、派发门控、`任务强类型执行请求`到`任务动作待验证材料`逐项原值复制，任何缺项、换序、替换或零值均为材料不足，零动作。

`任务强类型执行请求合同版本`升级为 2；原字段尾部追加：

```cpp
std::uint64_t 运行代次 = 0;
```

运行代次由正式执行轮次材料形成，必须非零；不得使用线程编号、时间、随机数或进程内计数器补造。v1 请求不得进入新队列，确定性入口拒绝、零动作、零待验证材料。

`任务工作线程`以执行幂等身份维护唯一收束槽，槽值固定为`{原任务强类型执行请求, 原任务动作待验证材料, 原预计动态组, 最近收束状态}`。动作成功后先原值入槽；只有定位被任务管理槽精确接收后才清除。任何消息、读回、归因、资源或 manager 提交失败只重试收束/提交定位，不重做动作。worker 唯一顺序：确认取出 -> fresh 最终复核 -> 形成预计动态 -> 实例执行 -> 收束 -> 提交定位。

`任务管理线程`新增不可变定位槽入口：

```cpp

    const 任务工作结果定位&) noexcept;
```

### 7.2 manager 独立复核和上行桥 v2

任务管理从定位槽取出后，必须用消息端口按`{执行幂等身份, 最后动作顺序}`独立读取消息，再调用权威读回 provider；不得信任 worker 的`成功()`或`worker观察截止`。读取的任务、三轮次、冻结、实例、方法、最后动作顺序、运行代次必须与定位逐字段相等。独立复核成功后才调用`形成任务结果回执(定位, fresh权威快照)`；回执中的场景、主体、状态、动态只能来自 fresh 快照。

`线程/上行桥.任务实际结果.ixx`新增：

```cpp
任务结果上行形成结果 发布并形成治理消息_v2(
    const 任务工作结果定位&,
    const 任务动作权威结果快照&,
    std::uint64_t 最大来源需求成员数) noexcept;
```

桥只由任务管理线程调用；它以执行幂等身份值形成`L2结构幂等身份`，构造完整`L2记录任务实际结果请求_v2`并调用 task-owner v2。`已可能发布`只保留见证并按原定位、原请求、原幂等身份重放；不得重新调用 worker 或动作端口。正式读回成功后才形成治理消息、结果定位并推进后续结算。运行包删除旧外部`提交已形成任务工作结果`和调用方预填正式结果入口，只公开强请求提交、工作结果定位读取和收束状态读取。

## 8. 普通应用所有权

普通应用上下文唯一长期持有：

```text
vector<unique_ptr<实例方法稳定动作端口>> 生产动作端口组
unique_ptr<任务动作完成消息账> 动作完成消息账
unique_ptr<任务动作前最终证据读取提供者> 最终证据读取
unique_ptr<任务执行最终当前性复核提供者> 最终复核
unique_ptr<任务动作权威结果读回提供者> 权威结果读回
unique_ptr<任务动作结果收束提供者> 动作结果收束
```

`构造普通应用上下文`以值参数取得动作端口组唯一所有权。空组允许上下文建立，但任意动作确定性返回端口不存在；零键、重复键使构造失败。禁止临时 span、悬空引用、运行后注册或替换。消息账、最终证据读取、最终复核、权威读回和收束 provider 均由普通应用在依赖可见后按上述顺序构造；manager 持有消息/权威读回和上行桥引用，worker 持有最终复核、实例执行、收束和定位槽引用。

计划不制造万能、fake 或 no-op 成功端口。统一验收的现实改变路径使用真实 L2 状态动态迁移 provider；这不证明外设或外部系统副作用。
