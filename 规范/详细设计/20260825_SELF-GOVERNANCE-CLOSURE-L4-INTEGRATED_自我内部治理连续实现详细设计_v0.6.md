## 1. 唯一修订目标

来源漂移：

```text
DRIFT-L4-PRODUCTION-ACTION-PORT-FINAL-REREAD-AND-REALITY-ATTRIBUTION-UNFROZEN
```

本版本替换 v0.5 中“worker 直接执行后进入既有结果链”的不完整部分，并同步 2026-08-26 结算裁决：冻结生产动作端口长期所有权、逐动作预计动态、动作前 fresh 全证据复核、不可变完成消息、动作后权威读回、worker 到任务管理的异步定位边界、task-owner v2 提交见证与同键收束；任务结果容量 / 分配和全部 `T→D` 核算前置退出，改为任务先收束自身轮次、按 0..1 正式发起调用返回、其它任务按需 fresh 核算。

### 1.1 主阶段治理合同继承收束

本版本显式继承 v0.3 第5.2节的`任务主阶段迁移材料、任务主阶段治理请求、任务主阶段治理状态、任务主阶段治理结果`及`治理当前任务阶段(const 任务主阶段治理请求&) noexcept`完整合同。该合同是 v0.3—v0.6 唯一主阶段公开入口：九段阶段值、task owner与阶段同G0读回、planning后最多一次阶段迁移、收束后统一后继消费、嵌套发布未知原键收束均不得由 v0.4—v0.6 的动作执行合同覆盖。

task owner 的同 G0 前置只允许消费 v0.3 第5.1.1节`按任务读取当前任务与轮次(...) const noexcept`。它必须在同一 G0 快照完成任务、活动当前轮次关系和轮次事实读回，并以读前/读后代次守卫排除混合快照。任务/当前轮次未找到和事实代次漂移映射主阶段当前性漂移；关系多义映射主阶段内部不一致；入口/许可/引用/资源按同名主阶段状态映射。禁止改用初建幂等读取、private helper、筹办分区或线程缓存替代。

method v2 动作进入 task 路径只允许继承 v0.3 第5.1.2节合同。`形成当前可执行冻结_v2`必须保存 method-group 正式读回和无损 task动作冻结组，并在返回已就绪前调用`发布任务筹办正式选择_v2`；task G1 成功后主阶段才以 G1 迁移到阶段 G2。生产上行仍传 method v2 动作身份，task-result、目标未达成裁决与运行期只读查询必须在持久 v2 路径组内做唯一成员匹配。v1 正式选择写入口零写拒绝，v1 历史读保留；不得首项投影、身份伪等或重新查询 method 当前组覆盖路径历史。

v0.6 不新增另一组主阶段 DTO，不允许 worker、动作端口、上行桥或任务管理绕过主阶段治理直接改变正式阶段。生产动作端口只消费主阶段已选择的可执行已冻结/待授权/执行分支；动作完成消息只把正式定位交回任务管理，由主阶段下一次正式读回选择执行结果待结算分支。

## 2. method v2、强请求与预计动态

### 2.1 三项动作合同

`L2方法动作入口事实_v2`与`L2方法动作入口写入请求_v2`在 v0.5 已冻结字段尾部依次追加：

```cpp
稳定编码 预期结果材料;
稳定编码 结果验证合同;
稳定编码 动作归因合同;
```

三字段均必须非零，逐字段参与有效性、同义性、幂等与正式读回比较。`任务冻结动作项`同步携带相同三字段；从 method v2 读取、筹办冻结、派发门控、`任务强类型执行请求`到`任务动作待验证材料`逐项原值复制，任何缺项、换序、替换或零值均为材料不足，零动作。

`任务强类型执行请求合同版本`升级为 2；原字段尾部追加：

```cpp
std::uint64_t 运行代次 = 0;
```

运行代次由正式执行轮次材料形成，必须非零；不得使用线程编号、时间、随机数或进程内计数器补造。v1 请求不得进入新队列，确定性入口拒绝、零动作、零待验证材料。

### 7.2 manager 独立复核和上行桥 v2

## 8. 普通应用所有权

普通应用上下文唯一长期持有：

```text
vector<unique_ptr<实例方法稳定动作端口>> 生产动作端口组
unique_ptr<任务动作完成消息账> 动作完成消息账
unique_ptr<任务动作前最终证据读取提供者> 最终证据读取
unique_ptr<任务执行最终当前性复核提供者> 最终复核

unique_ptr<任务动作结果收束提供者> 动作结果收束
```

`构造普通应用上下文`以值参数取得动作端口组唯一所有权。空组允许上下文建立，但任意动作确定性返回端口不存在；零键、重复键使构造失败。禁止临时 span、悬空引用、运行后注册或替换。消息账、最终证据读取、最终复核、权威读回和收束 provider 均由普通应用在依赖可见后按上述顺序构造；manager 持有消息/权威读回和上行桥引用，worker 持有最终复核、实例执行、收束和定位槽引用。

计划不制造万能、fake 或 no-op 成功端口。统一验收的现实改变路径使用真实 L2 状态动态迁移 provider；这不证明外设或外部系统副作用。

## 8.1 FRESH 与结算身份交付覆盖

本版本完整继承 v0.3 第 10.3.1 节修订后的结算身份交付和第 11 节 FRESH 合同。`任务结果复核载荷`在任务后依次携带正式任务轮次和轮次结算身份；manager 只能从成功的`任务轮次收束结果.轮次结算`取得两身份，分别投影其`任务轮次`与`身份`，并以最终收束阶段正式读回截止形成消息。上行桥结算前直送 self 的旧边退出；self 按显式结算身份同截止独立读回。禁止 task+round 猜测、第二索引、线程缓存或 private helper。

FRESH 的安全规则 owner 与 hard-veto 强类型全集消费不再是独立 DRIFT，可按既有白名单继续施工；唯一新增持久权威仍是版本化封闭的`L2任务现实执行硬否决规则结构服务`。但`读取任务执行fresh权威证据_v2`的场景权限映射仍是独立零代码边界：动作范围必须先分账，只有现实改变直接目标受同层闭包约束；内部治理和纯观察场景不得混入写操作闭包。现行 L4 生产只要求单动作无角色场景和同层独立现实改变目标，多角色动作按材料不足拒绝；真正未闭合的是现行单场景权限键所需任务级安全调度适用场景的生产者、冻结载体和同 Gnow 正式读回。禁止形成自动键组、最小资格聚合或全空即零资格。既有硬否决 v2 只消费强类型宇宙、版本、事实身份组和完整见证；旧安全编码、旧门控复制和规则版本回退 1 归零。没有正式规则宇宙时 fail-closed；fixture 空宇宙不证明生产安全闭环。
