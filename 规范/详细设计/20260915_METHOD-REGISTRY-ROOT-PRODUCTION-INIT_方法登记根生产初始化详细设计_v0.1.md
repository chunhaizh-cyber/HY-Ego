# 方法登记根生产初始化详细设计

身份：`METHOD-REGISTRY-ROOT-PRODUCTION-INIT`
版本：v0.2
状态：已发布的施工设计；不修改正式逻辑规范。

## 1. 目标与依据

本叶实现 8120 阶段19：唯一自我已经成功后，建立或读回唯一方法登记根，并在同一普通应用上下文内把读回结果交给启动入口。成功后只允许入口到阶段21短路；不创建本能根、线程、任务、普通方法或动作。

直接依据为 0050 的根值/治理隔离、8120 第5节第7项、3300、5350、5360。3300 的普通方法头必须含 Vm、动作函数绑定和条件—结果树；方法登记根不是普通方法，故不得复用 `领域/数据服务.方法类.h` 的普通方法记录服务，也不得伪造 Vm、条件、结果、动作或生命周期。

持久仓为空时启动顺序固定为：世界根 → 唯一自我 → 方法登记根 → 安全根需求 → 服务根需求。持久仓已有前缀时按同序定点读回；只补真实缺口，冲突不替代、不重建。

## 2. 最小物理结构与所有权

方法登记根是一个独立普通节点，唯一物理事实为该节点本身：无 Vm、动作、条件/结果、生命周期、属性、关系和值。阶段19全组恰一个根。

它由普通应用创建的独占技术 owner 写入，owner 只属于 L1 技术分区，不是方法业务 owner；其端口只能由 `L2方法结构聚合服务` 持有。固定键如下，稳定编码不得由调用方指定：

```cpp
inline constexpr std::uint64_t 方法登记根初始化所有者建立键 =
    0x4D52'524F'4F54'4F31ULL;
inline constexpr L1所有者范围写入幂等身份 方法登记根首次写入幂等身份{
    0x4D52'524F'4F54'5731ULL};
inline constexpr L1写集本地键 方法登记根本地键{1};
```

首次写入的 L1 首次材料是唯一的稳定编码来源。后续启动只能读取该材料中的实际稳定编码映射，不得把上述键或本地键解释为稳定编码。

## 3. L2 公开合同

新增 `领域/数据服务.方法登记根.h/.cpp`，仅依赖 L1：

```cpp
struct 方法登记根身份 { 稳定编码 结点; };
struct 方法登记根事实 { 方法登记根身份 身份; std::uint64_t 创建事实代次; };
enum class 方法登记根结构状态 : std::uint8_t {
  已建立, 精确重复, 已读取, 尚未建立, 入口拒绝,
  首次材料冲突, 首次材料不完整, 当前根缺失, 当前根已退出,
  当前根形状错误, 所有者非空冲突, 事实代次漂移, 资源失败,
  已可能发布, 内部不一致
};
struct L2方法登记根初始化请求 {
  std::uint32_t 合同版本 = 1; std::uint64_t G0 = 0;
  L1所有者范围写入幂等身份 幂等身份{方法登记根首次写入幂等身份};
};
struct L2方法登记根读取请求 { std::uint32_t 合同版本 = 1; std::uint64_t Gread = 0; };
struct L2方法登记根全组读取请求 { std::uint32_t 合同版本 = 1; std::uint64_t Gread = 0; };
```

初始化结果严格包含状态、原请求回显、实际 `Gread`、写后 `H` 和可选根事实；读取/全组读取结果包含状态、实际 `Gread` 与可选根或根组。所有成功结果必须具有非零截止和完整根；全组成功还须仅一根。`L2方法结构服务`只提供该三项操作；`L2方法结构聚合服务`唯一拥有其技术 owner 写端口和同一服务实例，向启动 provider 只暴露该服务引用。

## 4. L2 算法及失败边界

1. 读取当前 `G0`，读取固定写入幂等身份的首次材料及技术 owner 空域。
2. 没有首次材料且空域为空：提交仅含本地键 `{1}` 的一个普通节点写集；节点、关系、属性、值、退出均只有该节点/为空。提交后以 `H` 重读。
3. 没有首次材料而空域非空：返回 `所有者非空冲突`，零写。
4. 有首次材料：验证 owner、写入幂等身份、首次规范化写集、本地键映射和映射总数均精确符合第2节；按映射的实际稳定编码读当前节点，要求未退出、普通、无属性。任一不符分别返回首次材料冲突/不完整、根缺失、根已退出或形状错误，零重建。
5. 建立或重复后，以实际 `H/Gread` 单根读回，并同截止全组读回；全组必须恰一且同一根。

代次变化返回 `事实代次漂移`；资源错误返回 `资源失败`；L1 发布未知返回 `已可能发布`，调用方只允许带原请求、原幂等身份重新读回，不换键、不猜编码。任何异常或不可能组合返回 `内部不一致`。根建立不改变普通方法、业务 owner、世界树、自我或本能根。

## 5. 启动 provider 与装配

新增 `业务/应用服务.方法登记根生产初始化.h/.cpp`：

```cpp
struct 方法登记根生产初始化请求 { std::uint32_t 合同版本 = 1; };
enum class 方法登记根生产初始化状态 : std::uint8_t {
  已初始化, 精确重复, 入口拒绝, 根结构失败,
  当前性漂移, 资源失败, 内部不一致
};
struct 方法登记根生产初始化结果 {
  方法登记根生产初始化状态 状态;
  方法登记根生产初始化请求 请求回显;
  std::uint64_t 最终Gread;
  std::optional<方法登记根事实> 根;
  bool 成功() const noexcept;
};
class 方法登记根生产初始化提供者 final {
 public: 方法登记根生产初始化结果 初始化(
     const 方法登记根生产初始化请求&) noexcept;
};
```

provider 非拥有地持有 `L2方法结构聚合服务&`，执行“零代次全组预读 → 缺失时建立/发布未知按原请求收敛 → 非零单根读回 → 非零最终全组恰一根读回”。已存在且完整时返回 `精确重复`；建立后返回 `已初始化`。成功仅接受这两态以及完整根、非零最终截止。

`普通应用上下文`增加：技术性 `L1所有者范围交付 方法登记根初始化结构所有者`、`unique_ptr<L2方法结构聚合服务>`、`unique_ptr<方法登记根生产初始化提供者>`。成员顺序为运行包/owner 先于聚合，聚合先于 provider。候选上下文装配用固定 owner 建立键取得独占技术 owner，随后构造聚合和 provider；构造不是建立根。

`装配.普通应用.h` 新增：

```cpp
方法登记根生产初始化结果 初始化普通应用方法登记根() noexcept;
```

它只使用已存在上下文及已成功自我，不重新形成自我。`启动.应用程序.cpp` 中 `初始化普通应用自我()` 成功后调用它：失败映射阶段19；成功后本叶只能仍返回阶段21 `本能根运行初始化`失败。
