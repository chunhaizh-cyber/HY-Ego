## 1. 模块定位与核心裁决

### 1.1 一句话定位

自然语言模块是 **DATA 外的内部治理功能**：在**不取得现实写权**的前提下，把自然语言材料与自我/概念/世界/需求/任务/方法等正式认知材料互相翻译；翻译结果是有来源、可回读、可缺口报告的**类型化信息**，不是“理解即采信”。

### 1.2 必须分账的五层世界

```text
① 现实世界树（新_世界树类 / 场景 / 存在）
     ↑ 只读查询、领域裁决写入（禁止语言器捷径）
② 自我内部世界（7130：E=C 同节点场景视角 + 特征采用 + 状态/动态投影）
     ↑ 正式投影读取；语言可指称 self，不另建第二宿主
③ 语言无关概念空间（存在/特征/… 本体根；名称经 2210 多语种挂接）
     ↑ 名称召回、上下位收窄、符合性判定
④ 自然语言世界树（新_自然语言世界树类：空白语言场景 + 匿名概念实例）
     ↑ 无上下文基础句型的局部对象舞台；≠ 现实对象
⑤ 语言 owner 材料（新_语言类：知识、原文、解析、交互、主张、学习关联）
     ↑ 当次含义、来源与采用；主张 ≠ 世界事实
```

**裁决 A**：内部世界信息进入语言，优先使用该信息所属 owner 的正式只读投影（自我结构、特征、需求直接内容、任务阶段等），再用 7230/7240 组织为表达目标；禁止把私有字段表或稳定编码印成自然语言名称。

**裁决 B**：自然语言进入内部世界，先落在 ④/⑤（语言场景与语言材料），形成含义项与可选主张；是否写入现实/自我/需求正式集合，必须经所属应用入口，语言转换成功≠事实成立。

**裁决 C**：共享语义表示（7260 + SHARED-INFO 的 `正式直接内容项`）是双向转换的**认知枢纽**：理解产出可映射到 FT→typed 内容或含义操作参数；表达从同一枢纽取材。D/T/M 可作指称对象，但不并入普通 E 读取器。

**裁决 D**：已落地的“六基础构式无交互路径”（7240 §4.3 / BASIC-SIX）是模块的**最小可验证双向内核**；带交互上下文、指代、现实绑定、需求确认、段篇组织是其上的扩展环，不得破坏内核的零写/回读合同。

### 1.3 非目标（本模块明确不做）

1. 任意中文/大模型式开放理解；只支持已发布、可双向核验的语言知识。
2. 语言器直接写现实特征、组成边、因果、任务完成或方法调用。
3. 用焦点首项、self、当前窗口或机器时钟补齐未决指代/时间。
4. 第二套硬编码输出模板仓，与可学习知识分叉。
5. 把“收到/明白了”自动升级为内容确认、求助授权或任务承接。

## 2. 架构分层与现有代码落点

### 2.1 逻辑分层

| 层 | 职责 | 现有/目标落点 |
| --- | --- | --- |
| L0 接入 | 固定 Unicode 原文、语言选择、来源（外设消息 / 本次生成 / 独立材料） | `新_语言类` 材料登记；外设 `读取消息`（DEMAND-CONTENT 扩展只读保护） |
| L1 词法/名称 | 已登记词条最长匹配；普通/指代名称完整读回；未知片段保留 | `新_语言类::按已登记词条最长匹配`；`新_词类`；`概念_名称关系类` |
| L2 结构匹配 | 按已发布知识有序项匹配；多候选完整保留 | `转换.语言场景共同`；各构式只读解释器；`解释.基础语言` |
| L3 含义形成 | 7240 有限操作 → 含义项/候选/作用域；纯概念 vs 场景对象分支 | BASIC-SIX 统一候选；`表达.基础语言` 参数/目标 |
| L4 场景与指代 | 空白语言场景匿名 E；交互指代实例；变量/未决候选 | `新_自然语言世界树类`；7230 §4 |
| L5 主张与交互 | 已采用集合条件主张、需求描述/回应保存、交互上下文 | `新_语言类`（DEMAND-CONTENT 待实现面）；7230 §3.4/§4 |
| L6 认知接驳 | 含义 → 正式内容项 / 需求待确认 / 只读查询骨架 / 领域提议 | SHARED-INFO；需求 owner；世界/任务/方法只读服务 |
| L7 表达规划 | 目标→知识召回→名称/指代→句段篇→回读 | `从基础信息生成可回读单句`；`表达.基础语言`；组织知识（7250） |
| L8 学习 | 样本对齐→规则候选→查重发布→限定试用 | 7250 §3；初始化种子 `初始化.语言知识` |

语言解析/表达/学习属内部治理，**不**因是函数就全部登记为现实动作方法；外发通道结果与生成结果三分账（7240 §3.1）。

### 2.2 与自我内部世界的接驳面

```text
自我内部可读投影（7130）
  ├─ 当前自我身份 / 位置 / EC 使用
  ├─ 当前采用特征（先读采用再读 F）
  ├─ 自我相关状态/动态投影
  └─ （经治理）活动需求/任务正式投影
        │
        ▼  L6 认知接驳：形成“表达目标”或“查询骨架”
自然语言模块（本设计）
        │
        ▼  L7 生成 / 或 L0←外部输入后的 L1—L5
自然语言材料 + 对齐 +（可选）发送通道实际结果
```

反向理解时，若含义需要现实对象，经 7210 路由与 `解释.基础语言` 的现实短语候选，在**显式世界根**下只读枚举；不得把自然语言场景根伪装成现实根。

## 3. 核心数据结构与接口（模块合同）

### 3.1 内部信息枢纽：类型化含义包

调用期（默认可随请求释放）统一载荷；需要留存时再按 7230 交语言 owner。字段是逻辑合同，不强制单 C++ 大结构，但任何公开入口必须能表达下列分支：

```text
内部信息包 InternalInfoBundle
  表达目的            // 陈述 | 提问 | 提出需求（2340）
  作用域              // 普通陈述 | 提问 | 请求 | 否定 | 条件假设 | 引述
  含义项有序组        // 7240 §2.1 操作 + 强类型角色参数
  来源对齐组          // 原文范围 ↔ 规则/角色/出现
  对象绑定组?         // 语言场景匿名 E 或已消解现实/自我引用
  指代实例组?
  未决/缺口组         // 多义、缺名称、缺规则、指代未决、提供者缺失…
  正式内容投影?       // vector<正式直接内容项> 可选；用于 D/查询接驳
  完整范围与阶段结果  // 已完成 | 部分 | 多义 | 资源失败 | …
```

`正式直接内容项` 唯一形状以 SHARED-INFO 为准：`特征类型 → 正式内容值{种类,状态,值}`；种类含 I64、存在/概念/需求/语言理解/内容确认引用。语言理解引用指向语言材料/含义身份，不把理解结果假装成现实准确值。

### 3.2 自然语言侧材料（7230 摘要，模块必守）

| 对象 | 模块用法 |
| --- | --- |
| 文本材料 + 文本范围 | Unicode 标量半开区间；禁止规范化后沿用旧范围 |
| 自然句/段落/文章组成 | 有序出现；同文不同位置不同出现身份 |
| 句子解析材料 | 词出现 / 未知片段 / 覆盖结果；子句用词出现索引 |
| 语言知识 | 目标描述 + 描述结构；固定词项 / 角色项 / 子规则 |
| 本次表达树 / 含义对齐 | 生成与解析共用；留存另办 |
| 交互上下文 | 说话者/受话者/焦点/时地/引语栈；无依赖须显式标记 |
| 集合条件主张等 | 有来源主张；≠ 世界支持边 |

### 3.3 已冻结的公开双向入口（内核，复用勿复制）

以 BASIC-SIX 为准，模块内核对外最小 ABI：

```cpp
// 已有：海中鱼巣/业务/转换.语言场景基础.h
语言基础统一输入结果 转换单句基础语言到信息(
    const 语言基础统一输入请求&, 新_自然语言世界树类&,
    const 新_语言类&, const 新_词类&, const 概念_名称关系类&,
    const 概念_存在类&, const 概念_特征类&, const 新_存在类&);

语言基础统一输出结果 从基础信息生成可回读单句(
    const 语言基础统一输出请求&, const 新_自然语言世界树类&,
    const 新_语言类&, const 新_词类&, const 概念_名称关系类&,
    const 概念_存在类&, const 概念_特征类&, const 新_存在类&);
```

六构式闭集（当前种子实际发布）：S01 归类、S02 上下位、S03 整数、S03 特征概念条件、S05 组成、S09 概念归类确认。统一入口**先只读全分支**，唯一后再写场景/E；S02/S09 纯概念不建场景。

### 3.4 模块编排面（本设计新增逻辑接口，待具名叶实现）

下列为**模块级编排合同**，实现时应落在 DATA 外业务头源（建议命名空间 `海中鱼巣::自然语言模块`），**不得**新建第二语言知识仓或第二概念 owner：

```text
理解请求
  语言节点, 固定原文, 来源分支（外设消息保护 | 生成来源 | 独立材料）
  语境模式 = 无交互依赖 | 显式交互上下文
  允许查询范围（现实世界根? / 自我投影? / 仅语言场景）
  本次完整处理范围与额度字段（仅适配旧 ABI，不得裁剪必要范围后冒充成功）

理解结果
  阶段状态（沿用/对齐 7240 §7 区分表）
  InternalInfoBundle?
  完整候选组（多义时含义为空）
  已取得语言场景/对象身份（部分写入如实回传）
  可选：已保存语言内容身份（仅当请求显式保存且 owner 合同就绪）

表达请求
  语言节点, InternalInfoBundle 或等价强类型目标
  语境模式, 详略/省略要求, 允许名称集合约束?
  送达通道?（生成成功≠发送成功）

表达结果
  阶段状态, 实际文本, 表达树与对齐, 所用知识
  未表达项及原因
  可选通道实际结果
```

编排规则：

1. `语境模式=无交互依赖` 时，只允许走 7240 §4.3 / BASIC-SIX 内核及纯概念分支；出现代词/未支持修饰 → 结构未支持，不猜。
2. `语境模式=显式交互上下文` 时，必须提供可核验的固定语境材料；缺参考中心的“这/那”保留指代未决。
3. 需要现实绑定的理解，另调现实只读候选（`解释.基础语言`），与语言场景匿名 E **不可互换**。
4. 需要持久主张/需求描述时，调用语言 owner 显式保存 API（DEMAND-CONTENT），不得把调用期 DTO 当作已保存。

## 4. 理解管线（NL → 内部）

### 4.1 总流程

```text
1. 固定材料与语言选择；记录来源分支；空输入≠解析成功
2. 句段边界候选（引号内标点不截断外层）
3. 词条最长匹配 → 词序/未知片段；不强制词性
4. 完整枚举适用语言知识 → 各构式只读匹配（缓存同状态，不首命中即停）
5. 名称→概念完整读回；按角色类别与句型约束收窄（7240 §4.3）
6. 指代/量化/否定/条件/引述作用域核验（有上下文时）
7. 合并候选：唯一 | 多义待解 | 缺规则/未知词/缺名称/…
8. 唯一后：纯概念交付含义；需对象则建空白语言场景并按出现实例化 E
9. 形成 InternalInfoBundle；按请求可选保存解析/主张/需求内容
10. 后继领域提议仅类型化交出，不自授写权
```

### 4.2 接地（grounding）策略

| 表层 | 接地目标 | 规则 |
| --- | --- | --- |
| 内容词词面 | 词条 → 名称关系 → 概念 | 完整读回；指代名不进无上下文 E 槽 |
| 功能词 | 知识固定词项 | 不强制世界概念 |
| 类名（无上下文） | 抽象概念 → 匿名语言 E（按出现） | 不查现实哪个杯子 |
| 类名（现实解释） | 概念 → 现实树匹配候选 | 显式世界根；多候选保留 |
| 代词/指示 | 1110 定义 + 7230 实例 | 作用域参数；不永久等同系统自我 |
| “我”（网页自我叶） | 已绑定说话者存在 | 仅有上下文/来源快照时 |
| D/T/M 指称 | 信息对象正式身份 | 经存在语义分类与领域 reader；不造镜像 E |
| 整数词面 | 规范十进制字符串 | 不经 int64 截断；≠ 已构造领域准确值 |
| 集合条件“有事” | 主张：主体满足固定 C | 不写任务集合、不证真伪 |

### 4.3 歧义处理（硬性）

1. **完整候选优先于唯一猜测**：跨构式/同构式多角色组合/多适用知识分别计数；任一支读取未完成 → 清空依赖完整性的候选并报读取失败。
2. **排序只用于稳定展示，不用于裁决真义**；输出侧同义多规则可按详略选形，含义不同必须返回歧义。
3. **条件 OR 只用于规则适用性**，不是话语“或”（7250 G01 仍为缺口）。
4. **图收窄失败退回全局候选**；无边不证明主张为假。
5. **部分理解**仅独立可完成项可返回；共享角色组不得拆成假完整事实。

### 4.4 与自我内部世界相关的理解特例

| 输入意图 | 模块行为 | 禁止 |

## 5. 表达管线（内部 → NL）

### 5.1 总流程

```text
1. 固定表达目标与当前可读材料；分清现实事实 / 语言主张 / 预期 / 规则 / 提问
2. 按目的、操作、角色类型、语言召回知识；精确读回定义与采用范围
3. 排除不适用规则；同义多形按详略与覆盖稳定排序选形
4. 绑定角色：名称 / 明确对象描述 / 合法指代 / 类型化字面值 / 子含义
5. 确定性指认须接收方可恢复；否则专名或更充分描述，仍不足则缺材
6. 自底向上生成并对齐；检查否定/条件/引语/来源；不添加输入没有的因果
7. 实际输出经同一理解管线只读回读；唯一且角色/作用域/规范值一致才成功
8. 留存与发送分步；通道结果独立记录
```

### 5.2 从自我内部投影到表达目标

建议固定取材算子（7240 §2.3，模块不得扩展为脚本）：

1. 绑定角色（调用方已核验的强类型输入，含自我 E）。
2. 读具名字段（公开投影签名允许的字段）。
3. 枚举具名关系（完整成员/组成，保留未覆盖范围）。
4. 过滤/分组（未知另列）。
5. 排序（源顺序 / 正式步骤 / 可比较事件时间 / 明确叙述序）。
6. 投影子目标并递归子规则。

任务过程典型组织（7250）：关联需求目标 → 起始条件 → 有依据实际步骤与结果 → 问题/调整 → 最终结果与未完成；无问题则略去，未知则明确未知，不编造成功故事。

### 5.3 回读核验（双向闭环公理）

任何宣称“完整表达成功”的路径，必须满足：

- 实际生成文本 → 同模式只读理解 → 构式/角色映射/概念或正式引用/作用域/规范值一致；
- 不要求字符串逐字等于某历史原文；
- 匿名对象按本次出现映射核验，不新建对照场景冒充成功；
- 多义、名称缺失、来源不可读、读取漂移 → 不得完整成功。
