## 6. 首次业务资格与同代次门禁

仅当 `首态账_` 不含该幂等身份时执行首次路径：

1. 要求 `登记_` 存在且完整，否则入口拒绝。
2. 调用 `读取中性当前事实代次` 得到 G；要求中性合同 / 状态正确、G 非零且 `G == 请求.期望事实代次`。新键旧代次返回 `版本漂移`，零 P7 / P8、零条件查询、零提交。
3. 调用 P8 `读取实际存在I64实例特征` 与 P7 `读取实际存在`；沿用当前完整性、宿主、实例槽、当前值、来源和事实截止代次校验。两者截止必须都等于 G。
4. 以 P8 当前值编码调用 `读取中性当前值`；要求合同、回显、读取代次均为 G，事实当前、所属实例槽、来源、I64 表示 / 材料与 P8 事实一致；属性类型编码有效。
5. 调用两次中性目标关系组：主体 + 登记关系 19 类型、实例槽 + 同一类型。要求合同、查询回显、状态成功、读取代次均为 G；只接受当前、未退出、源 / 目标 / 类型与请求一致的关系。
6. 分别筛角色 1 与角色 3，按状态源稳定编码求交集。对两组涉及的每个相关状态源精确读取当前普通节点，并读取该源的关系 19 组；全部读取代次必须为 G。
7. 每个相关状态源的关系 19 组必须只含角色 1—5、每角色至多一条、源 / 类型正确，端点均为当前普通节点；若该源进入主体 / 实例槽交集，则五角色必须恰一且角色 1 / 3 分别等于本请求 P7 存在 / P8 实例槽。结构矛盾返回 `内部不一致`；存在完整交集返回 `入口拒绝`，禁止建立第二个首态。
8. 无交集时按第 5 节形成完整不可变中性写集。此后不再重读或改写业务材料；提交时发生并发推进由 L1 最终返回事实代次漂移。

上述查询只触达主体、实例槽及相关状态源，不遍历其它关系类型或无关状态。空关系组是合法“尚无相关状态”，不是未找到或内部不一致。

## 7. 中性幂等、提交与首态账顺序

唯一控制顺序：

1. 公开请求非法直接入口拒绝，零账读取后的事实操作、零 provider、零 L1 提交。
2. 查 `首态账_`：
   - 同键异请求：`幂等冲突`，零 provider、零 L1 提交；这是 L2 公开业务请求语义裁决。
   - 同键同请求：复制记录中的完整中性写集和读取请求，跳过首次资格与同代次查询，继续到第 4 步。
   - 新键：按第 6 节形成完整中性写集，读取请求暂空。
3. 中性写集不得包含业务标签、意图、摘要、执行证据、provider 见证或领域结果见证。
4. 每个首次或精确重复请求物理调用 `L1_.提交中性写集(写集)` 恰一次。禁止调用 `探测幂等`、legacy `提交写集` 或完整快照。
5. 按 L1 中性状态映射：成功→`已提交`；精确重复→`幂等读回`；幂等冲突→`幂等冲突`；事实代次漂移→`版本漂移`；其余按中性枚举映射为入口拒绝、未找到、资源失败或内部不一致。
6. 成功类共同要求：合同精确、回显键相同、首次发布代次非零、12 项本地键映射完整唯一。成功要求发布标志 true、重试边界 `不适用`、首次路径 G 等于请求期望且发布代次等于 G+1；精确重复要求发布标志 false、重试边界 `原幂等键读回收敛`。
7. 从映射形成现有 12 编码读取请求。重复路径要求它与账内读取请求逐字段相同；矛盾返回内部不一致。
8. 首次成功类在发布后、精确读回前将请求、中性写集和读取请求建立为首态记录定位；不得保存部分业务成功载荷冒充读回。若已有同义记录则三者必须相同。
9. 调用第 8 节精确读取。成功后把结果状态改回本次写入业务状态，并把首次记录的 `首次结果` 固定为首个完整结果；重复不得覆盖首次结果，只核对事实身份一致。
10. 发布后读回失败不得补写、撤销、换键或返回缓存。保留 L1 已发布事实和账内定位，使同义重试仍可用原中性写集到达 L1 精确重复并重新读回。

若首态记录建立本身因资源失败而无法保存，而 L1 已成功发布，返回 `资源失败`；不得猜测回滚。该极端路径不授权新增核心恢复接口，后续治理只可按正式审计 / 恢复边界处理。

## 8. 具名 12 编码精确中性读回

`读取实际存在I64基准状态` 仍按请求稳定编码读取一份不可变状态，不查询 P7 / P8 当前投影，不选择相邻状态：

1. 校验合同、规则、12 编码有效且应互异者互异；要求 `登记_` 完整。非法返回入口拒绝。
2. 调用 `读取中性当前事实代次` 得到 G0；要求合同精确、状态成功、G0 非零。
3. 对状态节点、见证节点、五关系、五状态域值逐项执行中性“当前或历史”读取：当前成功要求合同、查询编码、事实编码与读取代次 G0 精确；`已退出` 时按同编码读取中性历史事实并要求种类正确、退出代次存在且不晚于 G0；未找到保持未找到，其它状态精确映射。
4. 由五具名关系核对源均为状态、类型为登记关系 19、角色 1—5 恰一；角色 4 目标为见证节点，角色 1 与 5 目标相同。对状态源再调用一次中性当前源关系组：结果代次必须为 G0；当前角色每个至多一条，若具名关系仍当前则必须等于查询返回关系，若具名关系已历史化则不得存在另一条当前同角色关系。
5. 按关系端点精确读取主体、场景、实例槽、来源存在节点；读取当前 / 历史规则同第 3 步。状态、见证、主体、场景、实例槽、来源存在均必须为普通节点。
6. 从状态 / 见证节点记录中的属性槽核对五种登记属性各恰一并指向请求具名值；不得调用完整快照或扫描其它节点槽。
7. 校验两个资格 I64 值为 `1`，发生时间为单项非零 U64 组，被采样引用为四项非零 U64 组，采样值为 I64；所属、类型和来源与登记及角色关系一致。
8. 从引用读取被采样 P8 值编码、创建代次、采样截止和来源，以中性当前 / 历史入口精确读取该值及其属性类型节点。要求值属于角色 3 实例槽、来源和创建代次等于引用、材料等于复制的采样 I64，属性类型节点为 I64；被采样值在采样截止时有效，后来退出合法。
9. 状态、见证、五关系和五状态域值的共同创建代次必须等于采样截止 + 1；主体、场景、实例槽、来源存在、被采样值和属性类型在采样截止时有效。
10. 再读中性当前事实代次 G1；仅当合同 / 状态正确且 G1==G0 时组装现有 `实际存在I64基准状态事实` 返回 `已读取`。一次完整重试仍漂移返回 `版本漂移`，无部分事实。

所有见证 DTO 继续由中性事实字段投影；不得返回 L1 中性 DTO、仓、索引、锁或缓存。当前 / 历史读取都按稳定编码精确访问；不存在固定完整快照、全仓扫描、审计或恢复材料成本。

## 9. 失败、并发与生命周期

- L2 锁保护 `登记_` 和 `首态账_`；L1 独占许可最终拥有中性写集幂等、代次、候选和原子发布。
- 新键必须在同一 G 完成 P7 / P8、当前值和相关关系条件查询；任何读取代次不等 G 返回版本漂移。最后一次查询后并发推进由 L1 最终裁决。
- 精确重复不重读后来变化的 P7 / P8 当前投影，复用首次中性写集；因此当前代次推进、场景移动或值换代不能把原请求误判为新键漂移。
- 同键异请求属于 L2 业务冲突；L1 中性幂等只比较完整中性写集，两层职责不得混合为业务意图字段。
- 状态自有事实或端点后来退出时，精确读回从历史入口取得；关系 19 的采样语义不被当前场景或当前值重解释。
- `std::bad_alloc` 映射资源失败；其它未知异常映射内部不一致。非成功结果无事实载荷。

## 10. 验证矩阵与完成声明

后续实施至少证明：

| 场景 | 固定结果 |
| --- | --- |
| 非法公开请求 | 入口拒绝；零 provider、零条件查询、零提交 |
| 新键旧代次 | G 不等期望即版本漂移；零 P7 / P8、零提交 |
| 首次合法首态 | P7 / P8、当前值和关系条件查询同代；固定 `2/5/5/5/0`；中性提交一次；精确读回后已提交 |
| 已存在同主体同实例槽完整首态 | 目标关系交集与源关系组确认后入口拒绝；零提交 |
| 相关状态关系缺角色、重复角色、错端点或错节点形状 | 内部不一致；零提交 |
| 原请求在代次推进后重复 | 复用账内中性写集；零 P7 / P8；L1 精确重复、零发布；精确读回后幂等读回 |
| 同键只改变任一公开请求字段 | L2 幂等冲突；不得因底层写集偶然相同返回重复 |
| 首次材料读取后竞争推进 | L1 事实代次漂移；零发布 |
| 映射缺项 / 重复、发布标志 / 重试边界矛盾 | 内部不一致 |
| 当前或历史具名事实缺失 / 错种类 / 生命周期矛盾 | 未找到或内部不一致；无部分事实 |
| G0、各当前读取代次、源关系组代次、G1 不同 | 版本漂移；一次重试仍漂移则失败 |

静态门禁必须确认：

- `L1首个基准状态幂等域=0x0D` 唯一；登记 `0x0C` 不变。
- 生产代码中 `形成G7首个基准状态发布意图凭证`、`0x15000602U` 和仅服务该意图的 G7 编码 helper 归零。
- 目标发布根内 `探测幂等`、legacy `L1写集请求`、`提交写集(`、`读取完整快照`、`L1领域意图凭证` 为零；`提交中性写集` 恰一。
- 固定写集 `2/5/5/5/0`，映射本地键恰为 1—12；五关系角色 1—5 和五槽精确。
- 首次路径 P7 / P8 各一、当前值中性读取一、目标关系组查询两类、相关源关系组精确核对；重复路径这些调用均为零并复用账内写集。
- `首态账_` 保留；同键异请求冲突、同键同请求不缓存直返而进入 L1 精确重复。
- `读取实际存在I64基准状态` 使用中性当前 / 历史与 G0 / G1，不调用完整快照、legacy 当前 / 历史、P7、P8、比较或缓存。
- 已完成状态登记根相对施工起点逐字相同；相邻前状态、后继状态、动态和因果函数零差异。
