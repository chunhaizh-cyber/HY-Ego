# DATA-L1 无合同版本、无事实代次与头源拆分详细设计

日期：2026-09-27

版本：v0.1

状态：已冻结施工输入

对应裁决：0050 v3.27、4010 v1.6、4015 v3.0、4040 v2.0、4070 v1.13、4080 v2.0

## 1. 目标

把现行DATA-L1从“强类型DTO+合同版本字段+全局事实代次”改为：

```text
强类型具名DTO
+ 锁内当前状态
+ 单锁私有候选
+ 整笔交换或整笔零变化
+ 完整请求幂等
+ current-only快照恢复
```

同时把L1核心非模板实现从`.h`移入`.cpp`，消除超大header-only核心。

## 2. 不可改变的边界

1. L1仍只保存owner、节点、关系、值、属性槽、当前索引、幂等首次完整请求/结果和编码高水位。
2. 稳定编码仍全局单调分配、非零、不透明且永不复用。
3. owner仍由实例绑定且不可复制的写端口隐式注入。
4. 写集仍只包节点新建、关系新建、值新建、属性槽切换和当前事实删除五类变化。
5. 单owner和多owner写入仍只有一个正式交换点，交换前失败整笔零变化。
6. 幂等仍以同L1实例、同owner或同组合域、同幂等身份和完整规范化请求判定精确重放/异义冲突。
7. 持久格式版本、快照序号、活动槽、长度和SHA-256继续存在；它们不是服务合同版本或事实代次。
8. L1仍不解释存在、场景、特征、状态、动态、因果、需求、任务或方法语义。

## 3. 整体删除集

### 3.1 服务合同版本

从L1公开数据面、服务、仓库、运行包和直接消费者删除：

- 全部`L1*合同版本*`常量；
- 请求、结果、配置和幂等账中的`合同版本`字段；
- 入口合同版本校验及相应`入口拒绝`分支；
- 持久编码/解码中的服务合同版本字节；
- 因版本号不同而猜测兼容的代码。

`_v1/_v2/_v3`若仅是历史服务合同身份，在没有同名并存必要时一并收敛为无版本名称。持久格式类型的格式版本名称可保留。

### 3.2 事实代次

从L1公开数据面、服务、仓库、持久载荷、恢复见证和全部直接消费者删除：

- `G`、`G0`、`G1`、`Gread`、`H`；
- `期望事实代次`、`共同期望事实代次`、`读取事实代次`、`事实代次`；
- `创建事实代次`、`退出事实代次`、`首次发布事实代次`；
- `事实代次漂移`状态和重试分支；
- `读取中性当前事实代次`公开函数；
- 仓库状态中的代次计数器、候选代次归一化、代次序列化/解序列化和恢复互证。

## 4. 新运行语义

### 4.1 读取

1. 单项读取在一次共享锁内读回当前状态并返回值式副本。
2. 组合读取在一次共享锁内完成全部组件解析、索引召回、权威回读、排序和完整性校验。
3. 多次独立读取之间没有共同快照承诺。上层需要原子联合材料时，必须使用一个已有组合入口或另行冻结一个业务中性组合读取；不恢复代次守卫。
4. 结果只携带状态、请求身份回显和成功载荷，不回显合同版本或事实截止。

### 4.2 单owner写入

```text
校验纯值请求形状
-> 取得仓库独占锁
-> 查幂等首次账
-> 以锁内当前状态复制私有候选
-> 分配编码并应用五类写项
-> 校验owner、类型、端点、属性槽、引用闭合和索引
-> 准备持久快照
-> 一次交换正式状态
-> 在同锁当前状态上精确读回
```

不执行基线代次检查。同槽竞争时，后取得锁的请求以当时当前槽为旧值继续并完成覆盖。

### 4.3 多owner原子写入

参与者顺序、局部键解析和只允许后序参与者引用前序参与者的规则保留。仓库只取得一次独占锁，在一个私有候选中解析所有参与者、应用全部写集、执行全局引用闭合和幂等校验，然后一次交换。不再通过多次单owner提交产生临时代次再归一。

### 4.4 发布未知与幂等

交换前异常返回零变化非成功。交换后返回或读回不确定时，仍返回`已可能发布`或现行等价状态，调用方用同幂等身份和原完整请求重放收敛。首次结果不保存发布代次，只保存状态、幂等身份、发布布尔值、重试边界和新编码映射。

## 5. 持久格式与恢复

1. 新权威载荷格式使用新的`格式版本`，不含合同版本和事实代次。
2. 清单保存清单格式版本、快照序号、活动槽、载荷长度和SHA-256，不保存事实代次。
3. 恢复见证只回显格式版本、快照序号和SHA-256。
4. 为彻底删除事实代次解码逻辑，新实现不再恢复携带事实代次的旧载荷格式；旧格式返回`格式不支持`，不删除原材料。
5. 空存储根可建立新仓；已有旧格式材料必须由后续具名移转工具转换，不在新L1生产入口中保留兼容解码。

## 6. 公开DTO变更矩阵

| 类别 | 删除 | 保留 |
| --- | --- | --- |
| 写请求 | `合同版本`、`期望事实代次`/`共同期望事实代次` | 幂等身份、五类写项、参与者局部身份 |
| 写结果 | `合同版本`、`事实代次`/`首次发布事实代次` | 状态、幂等身份、发布布尔、重试边界、编码映射 |
| 读请求 | `合同版本`、`期望事实代次` | owner、稳定编码、类型/端点/来源等定位键 |
| 读结果 | `合同版本`、`期望事实代次`、`读取事实代次` | 状态、请求身份回显、完整载荷 |
| 普通事实 | `创建事实代次`、`退出事实代次` | 编码、类型/端点/材料、owner、属性槽 |
| owner事实 | `合同版本`、创建/退出事实代次 | owner编码、范围种类 |
| 恢复配置 | `合同版本` | 受控根 |
| 恢复见证 | `事实代次` | 格式版本、快照序号、SHA-256 |

## 7. 头文件与实现文件拆分

### 7.1 核心仓库

| 文件 | 目标内容 |
| --- | --- |
| `海中鱼巣/核心/仓库.L1事实基座.h` | `L1事实基座仓库`公开/私有函数声明、必要内部类型前置声明、PIMPL持有和最小include |
| `海中鱼巣/核心/仓库.L1事实基座.cpp` | 仓库状态、索引、幂等账、序列化、快照、恢复、锁和全部非模板函数实现 |

`L1事实基座仓库`使用私有`实现`类和`std::unique_ptr<实现>`隔离大量容器、锁和持久实现。析构、移动构造和移动赋值在`.cpp`定义。仓库不可拷贝。

### 7.2 公开服务面

| 文件 | 目标内容 |
| --- | --- |
| `海中鱼巣/核心/服务.L1事实基座.h` | 公开类声明、函数签名、所需前置声明和最小成员 |
| `海中鱼巣/核心/服务.L1事实基座.cpp` | `L1事实基座服务`、写端口、签发器、运行包和工厂的非模板实现 |

DTO定义继续位于专用`.h`。简单比较、常量表达式和真正模板可保留在头文件；不得为避免`.cpp`登记而保留大型`inline`函数体。

### 7.3 工程登记

两个新`.cpp`加入`海中鱼巣.vcxproj`和`海中鱼巣.vcxproj.filters`的`ClCompile`；原`.h`保持`ClInclude`。所有专项工程继续链接根工程生产实现，不复制`.cpp`或恢复header-only实现。

## 8. 直接消费者迁移

1. 删除所有L1请求构造中的合同版本和事实代次实参。
2. 删除结果合同版本、`G0/G1/Gread/H`和代次漂移判断。
3. 一次业务裁决所需完整材料若原来由多次L1读取+代次比较拼接，必须改用已有组合读取；确无提供者的受影响业务分支返回`未实现`或现行等价非成功，不伪造原子快照。
4. 跨调用的`同G`、`共同截止`、`首次代次`成功谓词全部删除；成功只由具名状态、请求身份回显和完整载荷判定。
5. 应用层不得建立自己的代次、时钟或版本字段来替代已删除的L1事实代次。

## 9. 错误分支

保留：`成功`、`精确重复`、`未找到`、`入口拒绝`、`幂等冲突`、`引用冲突`、`资源失败`、`已可能发布`和`内部不一致`等对真实分支仍有意义的状态。

删除：`事实代次漂移`及仅因合同版本不符而形成的入口拒绝分支。删除枚举项时允许保留数值空洞，不必为连续编号重排其它状态。

## 10. 验证

### 10.1 静态必达条件

- L1生产源码中`L1*合同版本*`常量为零。
- L1公开DTO的`合同版本`、`事实代次`相关字段为零。
- L1公开枚举中`事实代次漂移`为零。
- `读取中性当前事实代次`声明、定义和生产调用为零。
- 仓库内部状态和持久载荷不包含事实代次。
- `仓库.L1事实基座.h`和`服务.L1事实基座.h`不再包含非模板大型函数体。
- 两个对应`.cpp`已加入根工程。

### 10.2 构建与行为

- x64 Debug和Release根工程Rebuild通过。
- L1新专项驱动覆盖节点/关系/值CRUD、属性槽后写覆盖、幂等重放/冲突、引用闭合、单owner原子写、多owner原子写、组合读取、空仓建立、新格式重启恢复和旧格式拒绝。
- 未执行崩溃、断电、介质故障、长时压力和全业务闭环时明确记为`NOT_RUN`。

## 11. 完成边界

该设计完成只证明L1及直接消费者已迁移到无合同版本、无事实代次的锁内current-only合同，且核心头源已拆分。它不证明自我治理、任务筹办、动态因果或全业务闭环完成。
