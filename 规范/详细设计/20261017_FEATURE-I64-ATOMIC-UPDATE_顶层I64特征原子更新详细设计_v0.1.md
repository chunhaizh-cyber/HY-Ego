# FEATURE-I64-ATOMIC-UPDATE 顶层I64特征原子更新详细设计

日期：2026-10-17；版本：v0.1；代码基线：`a67e5e8379b1942069fa0f5f61908502f61243ea`。

## 1. 目标、范围与依据

将现有`新_特征类::添加特征值`对**顶层I64实例特征**的核心写入改为一次原子发布，并继续完成原归组、聚合和概念同步。它是本叶真实生产消费者；不是只做一个无人使用的事务工具。为后续服务贡献消费留下不可变组合片段，但本叶不写服务消费记录、不改任务、自我、运行服务或人类资格。

正式依据为0050、4015、1130、CODE-FILE及AGENTS工程故障分离规则。当前L1字段删除已由`f8db7cc9`发布。1130旧“底座没有组合原子变化集”是过期实现描述，不否定0050组合发布合同；它的同值再调用仍增加命中语义保持不变。工程逻辑损坏及核心后无法安全继续的失败按用户工程终止裁决，不返回可被重调用的假零写失败。

修改对象是实例特征自身的当前值、历史命中及标准值；不判定其业务宿主属于现实还是治理，也不发明本能动作。目的为维护已有特征事实不变量和组合更新能力。状态、动态及因果仍由既有上层事实链形成，本叶不直接制造它们。

覆盖：顶层I64准确值的首次写入、已有值重复命中、新值、饱和命中、合法旧直接历史及既有归组子特征。**子特征被直接调用添加值、非I64材料仍走原路径**；不声称全体I64迁移，不借此修复其它模型。

## 2. 当前能力与复用裁决

- L1`原子追加节点组`已有新节点、追加/替换/删除字段和外部边同次发布，及完整联合快照、双字段索引和唯一交换点：复用，不新建事务引擎。
- feature旧函数前半段分步改命中/current/standard，后半段依赖调用前快照、活动命中记录、历史新增标志：拆成私有核心准备与一次收尾，不把修改后的getter结果冒充调用前快照。
- 旧直接历史按命中1读取，归组只消费命中记录：本F局部等价规范化须在同次核心发布完成，不能丢旧值。
- 归组子F可引用父F同一命中记录。其标准值必须仍为最高命中值，故本次共享记录计数改变时，已有持有子F的standard须同次维护；不能等后半段才补。
- 新值连接多个已存在区间时仍只选一个接收区间，不合并原区间。只在原算法规定首次分裂时形成两组，不重算全历史连通分量。
- 无当前HEAD完整函数用途卡；证据直接来自现行`基础数据集.h/.cpp`、`新_特征类.h/.cpp`及其公开调用，知识库只作导航。

## 3. L1中立封存合同

本叶精确采用[服务消费设计输入](20261017_SERVICE-CONTRIBUTION-CONSUME_服务值Q原子消费与收尾设计输入_v0.1.md) **§4.5**冻结的技术合同；其它章节不是本叶施工范围。该节与本设计/计划同次发布后不可在施工中单独变更。必要公开面全部归属`核心/基础数据集.h/.cpp`：

1. `基础封存追加片段`：无公开默认构造和内容解包，copy/move为值式不可变句柄，底座深复制请求，绑定不可变数据集实例令牌；只有同文件`基础数据集`构造友元。
2. `基础片段封存结果 { 基础节点组追加状态 状态; optional<基础封存追加片段> 片段; }`。
3. `基础片段发布回执`：同owner封闭构造，可copy/move；公开`bool 对应片段(const 基础封存追加片段&) const noexcept`，以及`const vector<稳定编码>& 新节点组() const noexcept`、`追加字段关系组()`、`追加外部关系组()`。私有保存sealed内容身份，不允许上层自造成功回执。
4. `基础片段组合结果 { 基础节点组追加状态 状态; vector<基础片段发布回执> 片段回执组; }`。
5. `基础数据集::封存原子追加片段(const 基础节点组追加请求&) noexcept`返回`基础片段封存结果`；`基础数据集::原子追加封存片段组(const vector<基础封存追加片段>&) noexcept`返回`基础片段组合结果`。

原子组合只接受完整联合快照，不接受弱预期。重复预期完全相同才去重；不一致为预期不符。局部引用逐片段偏移，只能引用本片段新节点，不提供跨片段新节点导入。跨片段同字段关系、同既有宿主/字段键及相同外部边写入拒绝；单片段多值和删旧加同键保留。所有偏移、结果容量、回执内部存储在发布前分配；一次调用原原子追加；发布后不再分配。失败无成功回执。不存业务owner、全局版本、持久流水或发布去重账。正式编码仅原子追加实际分配。

空写集不封存、不提交。feature饱和等空核心分支按§6用既有`查询节点组完整结构`进行完整预期只读复核，不伪造current重写，不新增L1无操作事务入口。

普通添加不需要业务来源编码。准备句柄的私有身份仅是本次工程操作，不写世界树、不成为方法/动作/来源；未来服务消费自己绑定正式source，不能强迫普通调用虚构source。公开准备只能读取F、old/new及核心是否有变化，**不能导出自有sealed片段**，否则取消后残留片段仍可被单独提交，绕过占用生命周期。没有可变写集、锁、callback或跨模块friend。

`提交`是本准备的唯一核心发布入口：feature把自有私有sealed片段放在输入首位，随后按参数顺序附加其它owner不可变片段，调用L1组合一次；不解包其它owner写集。它私存自己的精确回执及已发布状态，仅返回附加片段回执组（与附加输入一一对应）。附加结果容量和私存回执槽在发布前准备，发布后只进行noexcept句柄复制/移动。零发布结果也由feature直接接收并记录，不由caller回报布尔值或状态。核心为空且附加组也为空时按§6.3只读复核；核心为空而附加组非空在本叶明确入口拒绝、零发布，不增加只读封存片段或无操作事务能力。普通调用和未来Q>0服务增值均不需要该未提供组合。

`完成`只接受自身已成功提交/只读复核的准备，核验私有精确回执并从正式feature结构读回本次核心结果，再运行一次聚合收尾，不能由上层自造回执。`完成`成功后保留占用，供未来上层状态动态安全读current；普通添加立即`结束`。重复完成同一准备仅读回已完整成功结果，不再增命中、归组或换概念；调用方再次调用普通添加则是新运行，仍正常增命中。同一准备不允许第二次提交，不自动重放附加owner片段。

## 5. 生命周期、占用与锁

1. 准备私下形成只读调用前快照、历史/成员闭包、核心操作及预期结果，零事实写入；在`新特征互斥`内完整枚举参与F闭包并为所有节点登记同一私有凭据。重叠占用返回`联合更新占用`、无写入；不是业务等待条件。准备所需快照从一次L1联合读取取得，并与语义读取再次对应，不拼接不同时刻的半结构。封存或准备资源失败撤销本次占用。
2. 私有F→凭据表只由feature owner使用，不对外暴露，不持久化。各函数短持原递归互斥，不跨L1调用以外的task/world上层调用持锁；公开准备不携带线程锁。每个准备固定创建线程，move仅转移同线程C++所有权；跨线程调用或析构进入工程终止，不能异步队列转交、跨worker挂起。
3. `添加特征值`全部类型的入口先检查目标占用，遇占用返回新增工程状态零写；这不把子F/非I64的正常算法迁入新路径。`删除特征`在任何删除前先完整枚举待删子树并核对占用；有一项占用即整次false/零删除，不在中途遇阻后留半删。内部归组新建或写子F只允许当前凭据对应的私有收尾路径，创建的新子F在同一feature锁保护内纳入凭据后才释放锁。其它owner字段不在本叶猜测或接管。
4. 私有生命周期为`未提交→已证零发布`或`核心已发布/空核心已复核→已收尾→已关闭`；提交调用进行中不允许取消或重入。`取消`只允许未提交或本owner已收到L1明确零发布结果的准备，不要求原快照仍相等，故合法CAS漂移不会被误报为工程损坏。取消删除本次占用并关闭准备。成功发布（包括空核心成功复核后已进入收尾阶段）不能取消；自己的sealed片段从未导出，取消后不存在外部延迟提交路径。
5. `结束`只接受已经完整完成收尾的原凭据；核对自己的核心/current/历史/standard及所属关系读回后释放本闭包。它不读服务消费owner，不理解T/S/D；未来上层负责在状态/动态完成后才调用它。
6. 准备移动后源对象为空，析构不操作；正常取消/结束后析构无操作。未提交/已证零发布准备析构可安全取消；核心已发布或正在收尾却未完整结束，或私有状态不清，析构进入工程诊断终止，不悄悄释放占用。move赋值覆盖旧有效句柄前先执行相同退出规则。owner/相关数据集必须比准备存活更久；普通生产调用仅同栈作用域持有。
7. 完成前后所有工程资源/结构失败不得变成方法业务结果。核心发布前能证明零写则允许返回资源失败等工程状态并取消；核心发布后若不能正常完成收尾，不做任意恢复、不重跑全历史，日志/弹窗/终止进程。现无持久恢复，不声明失败后能重启读回内存事实。

## 6. 核心准备与原子不变量

### 6.1 新旧值及命中

先确认顶层（无上级F）、正式I64材料/比较/聚合定义及合法结构，读取准确当前值可空。首次记录为1；已存在记录加1且在INT64_MAX饱和；同当前值调用仍增加一次命中，不能按值相等跳过。new current仅值真的不同或从空开始时改；标准值首次建立，之后候选命中严格超过旧standard的实际次数才替换，并列保留。所有加法受检或使用原饱和规则，不回绕。

同次核心写集包括目标current、目标历史所有必要引用/命中记录、目标standard及受影响共享持有子F的standard。每个写入/删除目标和引用端点按L1完整预期合同捕获。回执读回后，各可读取参与F的current属于history、值去重、hit为正、standard无人严格超过四项必须立即成立，不能等待聚合才修复。

现有子F已持有活动记录时，核心按该子F原standard及更新后的成员命中重新检查严格多数，只在被严格超过时更新standard；不借此改变分组归属或子F当前值。其它持有者通过正式历史记录反向字段查询及feature归组闭包核对，不能从最近/名称/日志猜测；闭包外非法共享关系进入工程保障。准备占用覆盖全部实际受影响F，包含直接更新仍走旧路径的子F，故旧调用不能同时改变共享记录。

### 6.2 局部旧历史等价规范化

只处理本顶层F及其正式归组成员闭包，不扫描/迁移其它F。顶层剩余合法旧直接历史逐项转为父F命中记录：本次命中2，其它1；删除各旧直接字段，与新记录/current/standard在同次核心发布。已是命中记录的值不再次增加，历史业务集合不因表示转换变大。

旧归组子F若有已明确组归属的直接历史值1，且其父历史同值也是1，可同次转换为同一父记录成员引用；保留原分组。这里的次数相等核验严格使用更新前快照；本次命中使该父记录从1变2，子F共享它同步变2正是这一次命中，不因此拒绝转换或重复计数。不重新算相似度、归组或合并已有区间。更新前父已有hitN且N≠1而子只含隐含1、子值不在父历史、同值跨组重复或归属无法唯一解释，违反1130成员引用闭包，在核心前工程诊断终止，不把正常合法旧历史变为业务否定，也不猜测它应归哪组。读取器对单F旧字段的兼容不等于整个归组闭包合法。

局部规范化必须读回旧值/次数语义相等；不让旧值退出历史、不修改其它F的计数、不主动清除概念或历史值节点。新增记录由L1分配正式码，禁止占位稳定码。

### 6.3 空核心

当同值、命中已饱和、current/standard不变且无需要规范化/关联修正，核心可能为空。准备仍持完整语义/联合预期及占用，私有核心片段为空。`提交`在附加组为空时用既有一次`查询节点组完整结构`读取并完整比较预期，确认无漂移并记录空核心已复核后，由`完成`运行一次原聚合；不调用封存/追加空请求，不构造current自赋值。预期漂移按零发布返回并可取消。实际归组、聚合域或概念同步有变化仍应报告完成；只有1130列举各项均无变化才返回`无变化`。

## 7. 一次聚合收尾与真实消费者

feature提取私有I64收尾函数，输入为准备中冻结的调用前`新特征信息`、业务变化标志、按回执解析的新活动记录及完整后历史记录。禁止在收尾里调用`添加特征值`；它不增加任何命中，不重做核心current/standard，只按原算法选择/创建接收子特征、聚合、调整具体概念。标准值共享修正已经在核心完成；原收尾读到的是有效标准。

原算法的重要分支不变：无子组且新值不连接旧区间才首次分裂；已有组优先既有活动成员，否则按标准相似度/编码确定性选择一个，皆不匹配才建新组；不合并既有组。准备的old历史用于判断是否新增，new记录用于完整聚合；两者不能混用。

收尾可复用现有聚合/概念helper，但不能声称任意失败幂等。正常成功须严格读回F、原有及本次新增子F、历史覆盖、聚合域和所属概念。`同步实例所属概念`若在等域/父包含早退时按现合同仍需要兄弟整理，该正常成功链必须补齐，不用“以后重试”掩盖。聚合域相同则复用现有域身份，不为了本次无变化重建域。改挂引用计数仍遵循现owner合同，过程中无法安全完成则工程终止，不发布假成功。

`添加特征值`入口在短锁内判断是否顶层I64（包括new准确值确为I64），符合则退出该局部锁并走：

```text
准备顶层I64更新
→ 提交顶层I64更新（附加组为空；内部处理核心发布或空核心只读复核）
→ 完成顶层I64更新（核验私有回执/复核状态＋一次收尾）
→ 结束顶层I64更新
→ 返回原新特征值添加结果
```
