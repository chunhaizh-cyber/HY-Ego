## 1. 目标、范围与完成条件

### 1.1 当前设计停工点

路线 P02 要求统一闭合必要条件、正式因果或具名筹办材料证明的子目标，并允许满足正式门禁的学习/方法补齐子类进入同一个`子目标承接`分支。当前正式规范给出了共同根门禁，却没有唯一冻结下列机器合同：

- 正式因果与具名筹办材料进入本轮采用方案的强类型来源身份和读取 provider；
- `方法能力缺失`如何形成被本轮正式采用的学习方案、合法学习生产者和规范化学习目标合同；
- `方法结构待补齐`如何形成被本轮正式采用的补齐方案及规范化补齐目标合同；
- 如何用正式关系判断候选目标相对父需求及全部祖先目标“不相同、不等价且不更宽”。

HEAD 的`任务特征方法查找结果`只有`已采用且存在缺失条件`、`已采用且输入限制待绑定`和`已采用且无需条件提议`携带`采用方案`；`方法能力缺失`和`方法结构待补齐`的完整性合同反而要求没有采用侧载荷。现有`L2任务子目标来源材料`也只表达方法条件，不能表达学习、方法补齐、正式因果或具名筹办材料。

因此，不能把下文“直接缺失条件”最小叶冒充完整 P02，也不能靠新增布尔字段、opaque 稳定编码或第二证明账伪造缺失合同。计划索引在上述合同获得正式裁决前不得把本草案登记为`可执行`。下文保留两类已经能够唯一裁决的内容：用户本轮确认的唯一结果消息不变量，以及条件来源最小叶的候选 ABI，供后续裁决复用。

本设计只闭合父需求任务在一次具名筹办轮次中，把本轮已经采用方法的直接缺失条件准入为正式任务子目标承接记录，并把该次筹办的唯一闭合结果通过既有强类型结果消息交给任务管理线程的代码叶。

固定链路为：

```text
任务管理线程派发一个不可变筹办工作包
-> 任务工作线程只调用一次筹办 provider
-> provider 在同一 G0 裁决本轮采用方法的直接缺失条件
-> 全部合格子目标由 task owner 一次原子发布
-> provider 返回“子目标承接 + 有序记录身份组 + G1”
-> 工作线程形成该工作包唯一的结果消息
-> 通过既有结果提交端口发送给任务管理线程
-> 管理线程确认已接收 / 精确重复
-> 本次筹办处理结束
-> 管理线程以消息 G1 独立读回整组记录并进入 P03 前的等待终态
```

“每次筹办结束都有结果”在本设计中是协议不变量，不是日志约定：

1. 每个已消费工作包，无论闭合为可执行冻结、子目标承接、合法等待、目标已完成还是结构化非成功，均只形成一个结果消息；
2. provider 返回不等于本次筹办结束；只有同一不可变消息被任务管理线程确认`已接收`或`精确重复`后才结束；
3. 结果端口资源等待时只重投同一消息，不重调 provider、不再发布第二组记录；硬拒绝令工作线程进入内部错误，该工作包不得被标记为已结束；
4. `合法等待`和`结构化非成功`也是该次筹办的结果，必须发送消息，不能以无消息等待或本地槽状态代替；
5. 子目标记录是消息定位的正式 task-owner 事实，消息不是第二结果账，不持久化消息、工作包或准入证明副本。

完成必须同时满足：

- 只把满足本设计门禁的直接缺失方法条件发布为正式记录；其它来源继续 fail-closed；
- 记录绑定任务、任务轮次、筹办轮次、父需求、本轮采用方法材料、具体条件、规范化子目标和来源 G0；
- 同一工作包的全部记录一次原子提交，任一前置不成立时零写；
- provider 只返回现有`任务筹办结果分支::子目标承接`，不新增结果分支或第二消息；
- 管理线程按消息 G1 独立读回并逐项互证后，只进入`子目标待后继`终态；P02 不调用需求 owner、不建立子需求；
- 保持 P01 的一个工作包—一个结果消息闭环，不新增线程、队列、账、历史结果或通用语义比较器。

## 2. 正式依据与关键裁决

- `规范/3100_根规范_需求.md` §5.2、§7.1、§7.6：独立子目标必须来自本轮正式采用方案的必要材料，严格缩小祖先尚未闭合范围，具有明确且最终可判定的目标合同；每次筹办结束必须把唯一闭合结果通过强类型消息交给任务管理线程。
- `规范/3200_根规范_任务.md`：每个已消费筹办工作包恰好形成一个五类强类型结果消息，管理线程独立读回正式事实后推进。
- `规范/4260_子规范_L2任务核心方法路径与对外接口统一合同.md`：task owner 拥有任务、轮次、方法选择、子目标承接记录和原子发布；L2 只执行已裁决的结构写入。
- `规范/详细设计/20260901_INSTINCT-ROUTE-P01_筹办工作包与结果消息详细设计_v0.1.md`：既有进程内工作包、唯一结果消息、结果提交端口和重投规则。

本草案对可唯一裁决的条件来源作出以下最小裁决；这些裁决本身不解除 §1.1 的完整 P02 停工点：

1. P02 只支持`任务特征方法查找结论::已采用且存在缺失条件`；`方法结构待补齐`当前没有正式采用方案，不得伪造子目标承接，仍返回结构化`待实现能力`或合法等待；
2. 当前首叶只接受本轮唯一采用方法中，与该方法主轴结果存在正式条件—结果关系的直接缺失条件；正式因果、具名筹办材料和任意来源目标的通用准入不在本计划内；
3. “严格缩小”不建立通用语义范围比较器。本来源类只有在直接必要条件、独立 primitive 目标合同、与父及全部祖先目标合同不同这三个机械条件同时成立时才准入；不能由这些正式事实唯一证明时 fail-closed，不靠文本、命名、向量相似度或布尔证明字段补足；
4. `方法结构待补齐`、正式因果和具名筹办材料后续若要准入，必须另有正式来源/provider；P02 不建立占位 ABI。

## 4. v2 值合同

### 4.1 筹办推进请求和消息协议

`任务筹办当前就绪合同版本`升为 2，`任务筹办推进请求`增加：

```cpp
L2任务轮次身份 任务轮次;
```

请求完整性要求任务轮次非零。任务管理线程形成工作包时，从 P01 的`按任务读取当前任务与轮次`同 G0 读回取得该身份，同时写入外层`任务筹办工作包消息.任务轮次`和内层请求；`任务筹办工作包消息完整`必须互证二者相同。

嵌套请求 schema 改变，因此`任务筹办工作与结果协议版本`升为 2。该协议是进程内 ABI；v1 消息不得跨进程恢复或与 v2 混收，不建立兼容消息账。

### 4.2 子目标承接记录 v2

`L2任务子目标承接记录合同版本`升为 2。现有记录保留，仅增加：

```cpp
L2任务轮次身份 任务轮次;
L2方法用途身份 匹配用途;
```

`匹配用途`放入现有`L2任务子目标来源材料`，与方法、内容版本、规格版本、主轴结果、条件、作用对象角色、条件来源一起构成本轮采用方法的最小来源材料。

禁止增加：消息身份、工作包身份、G1 副本、祖先列表、owner/root 副本、采用账、必要性账、门禁账、`同 owner/单父/无环/严格缩小`布尔值或历史结果账。父链、owner、根、目标合同和采用事实均在 G0 从原 owner 读取；v2 记录合法存在表示准入门禁已经通过。

### 4.3 整组原子请求与结果

在`L2任务子目标承接记录.数据.h`冻结：

```cpp
struct L2任务子目标承接记录新增项_v2 final {
    L2任务子目标承接记录身份 预定记录;
    L2结构幂等身份 建立幂等身份;
    L2需求身份 父需求;
    L2任务子目标来源材料 来源;
    L2任务子目标目标材料 子目标;
};

struct L2新增任务子目标承接记录整组请求_v2 final {
    std::uint32_t 合同版本 = L2任务子目标承接记录合同版本;
    L2结构请求头 请求头;
    L2结构幂等身份 整组幂等身份;
    L2任务身份 任务;
    L2任务虚拟存在身份 任务虚拟存在;
    L2任务轮次身份 任务轮次;
    std::uint64_t 筹办轮次 = 0;
    std::vector<L2任务子目标承接记录新增项_v2> 项组;
};

struct L2新增任务子目标承接记录整组结果_v2 final {
    std::uint32_t 合同版本 = L2任务子目标承接记录合同版本;
    L2结构结果头 结果头;
    std::vector<L2任务子目标承接记录事实> 记录组;
    bool 成功() const noexcept;
};
```

`项组`非空、规范有序、记录身份和建立幂等身份均唯一。不同父需求可以出现在同一项组，以保证一个工作包的全部结果只发生一次原子发布；同一个父需求下同一规范化目标不得重复。整组身份由固定命名域、任务、任务轮次、筹办轮次、G0和规范有序项组的完整语义稳定形成；每项幂等身份由整组身份、父需求、记录身份和规范化目标稳定形成。

公开入口：

```cpp
L2新增任务子目标承接记录整组结果_v2
新增任务子目标承接记录整组_v2(
    L2新增任务子目标承接记录整组请求_v2 请求) noexcept;
```

业务结构服务完成全部外部引用验证后，只调用一次 task-owner 写端口。task owner 在一把 owner 锁和一次 L1 写集中发布全部记录；任一项失败零写。`已提交`和`精确重复`返回首次同序完整记录组及原 G1；同键异义为幂等冲突；发布结果未知只允许原键原请求重放。不建立持久“组记录”。

### 4.4 整组历史读取

新增：

```cpp
L2按任务轮次筹办轮次读取子目标承接记录整组结果_v2
按任务轮次筹办轮次读取子目标承接记录整组_v2(
    L2按任务轮次筹办轮次读取子目标承接记录整组请求_v2 请求)
    const noexcept;
```

请求绑定任务、任务轮次、筹办轮次、读取类别、历史截止和扫描/返回预算。管理端固定以消息 G1 做历史读取；返回必须是截至 G1 已建立且尚未退出的完整 v2 记录，按记录身份稳定排序。零条、预算不足、重复、多义或额外记录均不是子目标消息读回成功。

## 5. provider 准入算法

`推进下一筹办工作包`对`已采用且存在缺失条件`按以下顺序执行，全部读取固定在请求 G0：

1. 读回当前任务与任务轮次，互证任务、请求轮次、工作包筹办轮次和 G0；
2. 读回任务虚拟存在及全部当前`T→D_parent`来源需求关系；来源组必须非空、无重复；
3. 对每个父需求读取完整需求和当前父链：每级必须属于同一`E_owner`，父关系只能 0/1，禁止循环；链尾必须是该 owner 的当前根。当前自我实例只接受安全根或服务根，禁止跨树反挂；
4. 读回本轮唯一采用方法、内容版本、规格版本、匹配用途、主轴结果及正式条件—结果关系；只遍历 provider 已返回的直接缺失条件草案，不从文本或历史候选补材料；
5. 每个条件必须在 G0 仍为该采用方法主轴结果的正式直接条件，且当前确实缺失；条件来源、作用对象角色和可选场景完整；
6. 将条件解析为唯一完整 primitive 目标合同：目标宿主、目标特征、目标状态合同均为正式非零身份，目标状态合同具有最终可判定终态；解析为复合、开放式、无终态或多义目标即 fail-closed；
7. 对父需求及全部祖先读取完整目标合同。候选目标必须是采用方案的直接必要前置，且其目标三元组和完整状态合同不得与任何祖先相同；无法据正式直接条件关系和目标合同唯一证明为独立且更小的候选不准入；
8. 对每个`父需求 × 合格条件`形成一项；按父需求、方法、条件、目标合同、场景的强类型身份稳定排序并去重；同一目标跨两个合法父需求时保留两条记录，不合并父域；
9. 项组为空时不发布记录，返回合法等待或结构化`待实现能力`，仍由工作线程形成并发送唯一结果消息；项组非空时调用一次整组原子发布；
10. 只有写结果为`已提交/精确重复`、记录组与请求逐项相同且 G1 非零，才返回`子目标承接 {有序记录身份组}`和 G1。资源失败保留原整组请求供原键重放；其它冲突结构化非成功，禁止部分成功。

provider 删除`需求任务子目标承接服务&`构造依赖和成员。P02 不调用需求服务的写入口。

## 6. 唯一结果消息与管理端状态机

P02 不修改 P01 的结果生成原则：工作线程无条件把 provider 的完整返回转成一个`任务筹办结果消息`；provider 返回不完整时转成`结构化非成功/内部错误`消息。所有五类分支均走`提交任务筹办结果`，不得让子目标分支走回调、共享槽或直接调用管理线程私有方法。

管理线程接收消息后保持不可变原消息。对子目标分支：

1. 先复用 P01 守卫，互证消息与原工作包的消息身份、任务、任务轮次、筹办轮次和 G0；
2. 以消息 G1 调用 v2 整组历史读取；资源失败或可恢复读取波动只重试同一读回，不生成第二结果消息；
3. 读回记录身份组必须与消息有序身份组同序、同集合、无缺失、无多余、无重复；
4. 每条记录必须为 v2，且任务、任务轮次、筹办轮次、来源 G0与消息逐项相同；生命周期在 G1 已建立且未退出；任务虚拟存在归该任务；父需求属于该任务 G0 来源需求组；来源采用方法材料和目标材料完整；状态为`待绑定子需求`；
5. 管理线程不重跑必要性和严格缩小裁决，不从消息补正式记录；互证成功只把槽置为`子目标待后继`终态，保留 P03 消费所需的消息定位，不调用需求 owner；
6. 当前性漂移/资源失败保持同一消息和读回重试；身份、内容、数量或生命周期冲突进入内部终止，零 P03 派发。

“管理线程收到消息”是筹办线程完成的确认边界；“管理线程独立读回通过”是允许进入后继编排的事实边界，二者不得合并。

## 7. 错误映射与失败收口

| 情况 | provider / worker 结果 | 写入 |
| --- | --- | --- |
| G0、任务轮次或采用方法当前性漂移 | 结构化非成功/当前性漂移消息 | 零写 |
| 方法结构待补齐、来源不受 P02 支持、严格缩小无法唯一证明 | 合法等待或结构化非成功/待实现能力消息 | 零写 |
| 父链缺父、多父、跨 owner、循环、未终止于合法根 | 结构化非成功/内部错误消息 | 零写 |
| 数量预算不足 | 结构化非成功/数量预算不足消息 | 零写 |
| 整组写资源失败或发布未知 | 原键原请求重放；仍只形成最终一次消息 | 不允许可见部分写 |
| 整组写已提交/精确重复 | 子目标承接消息 | 一组正式记录 |
| 结果消息端口资源等待 | 重投同一消息 | 不重调 provider、不重写记录 |
| 结果消息硬拒绝/异义冲突 | 工作线程内部错误；本次不得标记结束 | 不生成第二消息 |
| 管理端 G1 读回资源失败 | 重试同一读回 | 零 P03 派发 |
| 管理端记录内容冲突 | 内部终止 | 零 P03 派发 |
