## 1. 目标与完成边界

本设计把任务来源权威从“需求列表项全部当前成员”改为“逐次任务承接形成的 `T→D` 正式关系”，并删除任务筹办 Stage C 的五类虚构授权安全材料。完成后必须成立：

```text
每次任务承接输入携带具体需求 D
-> 读取 D 所属列表项 L
-> 以 L 查询 0..1 个当前任务 T
-> 无 T：原子形成 T + T→L + T→D + 任务虚拟存在
-> 有 T：验证同锚点、同目标后幂等形成 T→D
-> 筹办 / 冻结 / 目标验证只消费当前 T→D 中的具体需求
```

本叶不实现任务完成后的结果共用 / 争用与正式分配，不实现 Release 测试隔离，也不接线自我线程向任务管理发送 D。6150 / 6170 的真实权限只允许在执行冻结后、真实派发前形成；本叶删除错误的筹办前置材料，不以虚构 provider 代替后继真实派发资格提供者。

## 2. 当前代码事实与差异

当前代码在基线上已经具备：

- `L2任务事实`、`L2新增任务请求`和`按需求列表项读取当前任务`，但字段仍名为`需求列表项`，没有 `T→D` 关系事实与公开读写接口；
- 任务核心能原子建立任务、任务族归属、`T→L`、任务虚拟存在和 `T→V`；
- 组合只读查询仍从列表项完整结构和列表当前成员形成任务目标 / 来源快照；
- 初次筹办、重筹办、冻结、执行请求和端到端测试仍传播列表项成员来源；
- `任务筹办当前就绪与执行冻结`仍定义并消费`授权安全材料`、缺失来源 provider 和`授权安全等待`，装配层默认注入缺失来源；

## 3. 权威数据模型

### 3.1 核心事实

```cpp
struct L2任务事实 final {
    L2任务身份 身份;
    L2需求列表项身份 同类任务查询锚点;
    L2任务虚拟存在身份 任务虚拟存在;
    L2生命周期 生命周期;
};

struct L2任务来源需求关系类型身份 final {
    稳定编码 值;
};

struct L2任务来源需求关系事实 final {
    关系句柄 关系;
    L2任务身份 任务;
    L2需求身份 来源需求;
    L2生命周期 生命周期;
};
```

`T→D`只证明承接关联，不复制 D 的目标、路径、权重、预算、当前性或结算事实。L 只证明同类查询锚点；不得把 L 的聚合键或全部成员解释为任务目标 / 来源集合。

### 3.2 本地键

```text
任务来源需求关系类型键值                 = 0x0301'2114
普通承接任务来源需求关系写入本地键值     = 0x0301'2219
新任务首次融合来源需求关系写入本地键值   = 0x0301'2613
复用任务新增来源需求关系写入本地键值     = 0x0301'2650
```

禁止使用：

```text
0x0301'2113  已属于任务虚拟存在归属关系类型
0x0301'2205  已属于任务虚拟存在归属关系写入键
0x0301'2641..2646  已属于初次融合轮次权威关系
```

## 4. 公开 ABI

### 4.1 查询锚点读取

```cpp
L2按同类任务查询锚点读取当前任务结果
按同类任务查询锚点读取当前任务(
    L2按同类任务查询锚点读取当前任务请求) const noexcept;
```

结果基数固定为：0 项=`已读取 + 空`；1 项=`已读取 + 当前任务`；大于 1 项=`内部不一致`。不得挑最新或最小身份。

### 4.2 来源关系读取

```cpp
L2按任务读取来源需求关系组结果
按任务读取来源需求关系组(
    L2按任务读取来源需求关系组请求) const noexcept;
```

请求携带共同请求头、读取类别、任务身份和历史读取时的非零历史截止。当前结果按`来源需求身份、关系身份`稳定升序且无重复。空组是结构读取成功，但不能形成任务当前目标；历史读取必须显式历史截止，禁止拿当前关系补历史。

### 4.3 承接具体来源需求

```cpp
L2承接具体来源需求结果
承接具体来源需求(L2承接具体来源需求请求) noexcept;
```

请求至少携带共同请求头、幂等身份、任务身份、具体来源需求和期望事实代次。写前验证任务、查询锚点、D 的当前成员关系和 D 的目标三元组。若 T 有 1..N 项当前有效关联 D，必须逐项验证其目标与新 D 完全相同；若显式关系为空，或全部关联 D 已失活，则由 DATA 外任务业务先验证 T 仍是 L 下唯一当前任务、生命周期允许复用且新 D 当前属于 L，再允许幂等写入 `T→D`。成功原子新增一条 `T→D`；同键同义 / 同一当前关系返回精确重复；同键异义返回幂等冲突；异目标、错锚点、错 owner、已退出和事实代次漂移分别具名收口。

### 4.4 新任务请求

`L2新增任务请求`保留共同请求头和幂等身份，业务字段固定为：

```text
L2需求列表项身份 同类任务查询锚点
L2需求身份 首个来源需求
```

新增成功必须在一个 task-owner 事务内形成任务节点、任务族归属、`T→L`、`T→D`、任务虚拟存在和 `T→V`。任何一项失败整体零发布；发布未知只用原幂等身份与原完整请求读账收敛。

## 5. DATA 外承接流程

业务入口输入为具体 D：

1. 当前读取 D 及其所属列表成员关系，取得 L；
2. 验证 D 当前、目标三元组完整；
3. `按同类任务查询锚点读取当前任务(L)`；
4. 无 T 时调用新增任务，首个来源为 D；
5. 有 T 时读取当前 `T→D` 组；有 1..N 项当前有效 D 时逐项验证目标等价，再调用`承接具体来源需求(T,D)`；
6. 显式关系为空或全部关联 D 已失活时，复核 T 仍为 L 下唯一当前任务、T 生命周期允许复用且新 D 当前属于 L，再先幂等写入 `T→D`；写后目标只能从新 D 与其它当前有效 D 形成，绝不从 L 聚合键形成；
7. T 生命周期不允许复用时返回具名非成功，由任务业务结束旧 T 后再建立新任务，不得偷偷复活旧 T；
8. 大于一个 T 或任一当前有效既有来源异目标均为内部不一致 / 引用冲突，零写停止；
9. 正式读回 T、身份来源、查询锚点、`T→D`和任务虚拟存在。

列表项新成员不会触发自动承接。旧列表目标格式和旧五类授权格式只读历史，不默认迁移；只有新的具名承接输入能够建立当前 `T→D`。

## 6. 目标、筹办、冻结与回流

### 6.1 目标投影

```text
T
-> 当前 T→D 关系组
-> 逐项当前读取 D
-> 验证目标宿主、目标特征、目标状态合同完全相同
-> 至少一项当前有效 D
-> 单目标值式投影
```

空组或全部 D 失活 / 退出时返回具名`无当前来源需求`；业务只能等待、结束或重判，禁止读取 L 聚合键兜底。

### 6.2 初次筹办与重筹办

初次准备记录、初次筹办工作包、重筹办工作包和来源冻结均改为保存实际消费的 `T→D` 关系 / D 身份与版本。目标解析、方法召回、条件提议、当前就绪、执行冻结、子目标回流和目标未达成重筹办都从该显式组读取；不得枚举列表全部成员。

### 6.3 删除 Stage C

以下事实、联合分支、provider、默认缺失实现、等待结论和装配参数全部退出当前生产 ABI：

```text
来源需求授权事实
安全图事实
安全阈值事实
权限规则事实
适用性分类规则事实
L2任务授权安全复判材料
任务筹办授权安全材料来源
任务筹办授权安全材料缺失来源
任务筹办当前就绪结论::授权安全等待
```

当前就绪与执行冻结只验证任务、来源关系、方法生命周期 / 内容、条件、输入、参数、限制、动作入口、验证与归因。权限为零不得阻断这些步骤。

### 6.4 派发边界

真实普通任务派发必须发生在执行冻结之后。6150 / 6170 权限投影、独立全局控制态和具体方法具名许可属于派发门控，不进入执行冻结材料。本叶只删除错误前置并清理执行请求对 Stage C 材料的依赖；不以 N16/N17 `材料缺失`骨架补造生产 provider，不宣称自我线程派发闭环已经完成。

## 8. 非成功、并发与生命周期

| 场景 | 结论 | 写入 |
| --- | --- | --- |
| D 不存在 / 已退出 / 不属于 L | 未找到、已退出或引用冲突 | 零变化 |
| L 无当前 T | 新建闭环 | 一笔原子写集 |
| L 有一个同目标 T | 幂等承接 D | 仅新增 `T→D` |
| T 显式关系为空或全部 D 已失活，且 T 唯一当前、生命周期允许复用、新 D 当前属于 L | 恢复来源承接 | 先幂等新增 `T→D`；写后仅从当前有效 D 形成目标 |
| T 显式关系为空或全部 D 已失活，但生命周期不允许复用 | 具名非成功 | 零变化；业务结束旧 T 后再建新任务 |
| L 有多个当前 T | 内部不一致 | 零变化 |
| T 既有来源与 D 异目标 | 引用冲突 | 零变化 |
| 同键同请求或关系已存在 | 精确重复 | 零变化并读回既有 |
| 同键异请求 | 幂等冲突 | 零变化 |
| 期望代次漂移 | 事实代次漂移 | 零变化 |
| T 当前来源组为空 / 全失活 | 无当前来源需求 | 不形成目标、路径或冻结 |
| Stage C 材料不存在 | 不适用，不形成等待 | 不阻断筹办 / 冻结 |

同一 L 的当前任务唯一性和同一 `(T,D)` 关系唯一性必须由 owner 事务与写后读回共同证明。任务退出同代退出当前 `T→L`、全部当前 `T→D`、`T→V`和任务节点；历史读取仍可回读。

## 9. 验证合同

至少覆盖：

1. 首个 D 原子建立 T、T→L、T→D、V 和身份来源；
2. 同 L 第二个同目标 D 复用 T，只新增关系；
3. 列表其它成员不自动进入来源组；
4. 异目标 D、错 L、第二当前 T、重复关系、同键异义和代次漂移分账；
5. 来源关系稳定排序、空组、当前 / 历史不混代；
6. 目标从 1..N 个当前有效 D 互证；承接前空组 / 全失活可在唯一当前、生命周期允许且新 D 属 L 时先写 `T→D`，写后不以 L 兜底；
7. 初次筹办、方法查找、冻结、回流、重筹办和任务执行请求全链不再读取 Stage C；
8. 权限为零不阻断筹办 / 冻结，且本叶不把缺真实派发资格误报为生产派发闭环；
9. 旧格式只读历史，不默认迁移；
10. `服务.L2任务子目标承接记录结构.ixx` 两处旧字段只发生机械改名，静态扫描无旧字段引用且 Debug / Release 编译通过；
11. 生命周期不允许复用时具名非成功、零写，结束旧 T 前不得新建或复活；
12. 全量构建和两份具名端到端测试通过。
