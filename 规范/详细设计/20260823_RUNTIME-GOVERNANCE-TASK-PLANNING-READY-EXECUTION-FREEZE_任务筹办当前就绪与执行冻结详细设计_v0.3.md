## 1. 本轮目标与完成边界

v0.2 已闭合同写集本地键表达。本轮只闭合执行期具名 DRIFT `TEST-MIGRATION-BOOTSTRAP-CYCLE`：

```text
fresh DB
-> 任务和初次筹办准备记录已存在
-> 当前选择 / 路径 / 实例均为空
-> 同一 task owner 正式选择入口以“初次筹办来源”形成首轮路径、选择、冻结和实例
-> 后续才能形成实际结果、目标未达成裁决和重筹办来源
```

现有五个专项原先依赖已删除的`发布当前选中路径`，而 v0.2 的正式选择请求只接受旧路径、旧实例、旧结果和待重筹办状态，形成循环。本轮禁止恢复旧入口、伪造旧结果、增加测试专用生产 API 或把初次材料填成全空重筹办材料。

未被本文件明确修订的 Stage C 九结论收束、当前就绪、冻结证据、路径兼容投影、线程协议、队列、装配、同写集本地键限制和完成声明，继续按 v0.2 执行；本文件与 v0.2 冲突时以本文件为准。

本轮不新增普通初次筹办 BIZ 编排入口。现有`任务筹办当前就绪与执行冻结提供者`和任务管理线程仍专门消费合法`下一筹办工作包`；初次模式先由同一 task owner 正式公开入口供合法消费者和专项使用，后继普通初次筹办 provider 必须另行设计接线。

## 2. 正式裁决依据

- 3200 §8.5：当前路径和当前实例合法为 0..1；第一次执行必须选择路径、形成实例和冻结。
- 3200 §23：路径、选择、实例、冻结保留历史；同强类型幂等身份同完整请求精确重复。
- 5210：`待初次筹办`明确禁止已有当前方法和执行冻结，后继才进入路径形成、选择和冻结。
- 5230 v1.0：同一 task owner 组合发布入口以判别联合区分初次与重筹办。
- 5250 v0.7：`下一筹办工作包`是目标未达成后的专门重筹办来源；普通新筹办语义仍保留。
- 4260 v0.4：`任务 -> 当前选中路径`只是派生投影，不能恢复独立发布入口。

因此，初次模式不是重筹办字段的空值特例；两者必须在类型层互斥。

### 4.1 选择记录和证据

`L2任务方法选择记录事实`把`原筹办工作包幂等身份`修订为：

```cpp
L2任务筹办来源幂等身份 原筹办来源幂等身份;
```

`L2任务选择稳定证据类别`固定为：

```cpp
初次筹办准备记录 = 1
目标裁决证据 = 2
任务治理状态 = 3
```

- 初次来源：稳定证据组必须且只能有一项`初次筹办准备记录`，身份等于来源记录；
- 重筹办来源：必须保存目标裁决证据与任务治理状态，不得混入初次准备记录；
- 排序只规范化，不表达优先级。

### 4.2 冻结归因

`L2任务执行绑定冻结材料提交项::归因证据`改为`L2任务筹办归因证据引用`：

- 初次分支必须持有同一首次准备记录身份；
- 重筹办分支必须持有同一正式目标裁决证据；
- 联合分支与来源模式错配为引用冲突，零写。

### 4.3 发布与恢复公开面

公开写函数保持唯一：

```cpp
L2发布任务筹办正式选择结果 发布任务筹办正式选择(
    L2发布任务筹办正式选择请求 请求) noexcept;
```

原`按筹办工作包幂等身份读取正式选择`按实际 ABI 改名为：

```cpp
L2按筹办来源幂等身份读取正式选择结果
按筹办来源幂等身份读取正式选择(
    L2按筹办来源幂等身份读取正式选择请求 请求) const noexcept;
```

读取请求携带`L2任务筹办来源幂等身份`。初次记录身份与重筹办整数即使底层稳定值相同，也因 variant 分支不同而不是同键。

## 5. 分支前置与原子事务

### 5.1 初次筹办来源

owner 在请求头共同事实截止 G 写前必须逐项证明：

1. 首次准备记录可由公开读取完整恢复，且其任务、列表项、轮次 1、G0、G1、运行代次与来源逐项相等；
2. 请求任务身份来源等于首次记录所指任务的公开身份来源；
3. 来源需求仍是该列表项当前有效成员，任务、需求、列表项和任务虚拟存在于 G 均有效；
4. 筹办轮次固定为 1；
5. 当前正式选择、当前路径、当前实例均为空；任一已存在都返回当前性漂移或引用冲突，不能幂等覆盖；
6. 来源需求组只能是本次实际消费且经当前互证的成员，至少包含首次来源需求；
7. 稳定证据和归因证据均指向同一首次准备记录；
8. 方法生命周期、冻结材料和任务身份来源满足 v0.2 全部守恒。

一次 owner 事务同代完成：

```text
创建执行绑定冻结材料
+ 创建筹办轮次 1 路径
+ 创建正式选择记录与六类拓扑
+ 创建派生任务->当前路径
+ 创建执行轮次 1 实例及任务侧当前实例关联
```

结果中的`旧当前选择`、`旧当前路径`、`旧当前实例`必须全部为空；不产生旧生命周期退出。

### 5.2 重筹办来源

保持 v0.2 的十三项机械映射和互证：旧路径、旧实例、旧执行轮次、旧结果、目标未达成裁决、待重筹办治理状态、G、新旧轮次与运行代次缺一不可。一次事务退出旧当前选择 / 路径 / 实例及旧路径 / 实例当前生命周期，再建立新冻结、路径、选择、派生投影和实例。新执行轮次固定为`旧执行轮次 + 1`。

### 5.3 共同事务限制

- 两分支共用一套 owner 类型登记、写端口、首次账和正式读回；
- 关系端点可使用本地键，路径条件 / 输入 / 参数 / 归因继续按 v0.2 从选择拓扑发布后派生；
- 不得把本地键包装成稳定编码，不得第二事务补写路径；
- 同强类型来源幂等身份 + 同联合分支 + 同完整请求才精确重复；
- 未知发布只以原来源幂等身份、原联合分支和原完整请求恢复；
- 换键、换分支、换首次记录、换旧结果或换冻结材料均为异义冲突。

## 6. BIZ Stage C 保持重筹办专用

`任务筹办当前就绪与执行冻结提供者`、`任务筹办推进请求`、`任务筹办等待合同`、`任务执行冻结形成材料`和线程协议继续携带`下一筹办工作包`。provider 只构造`L2任务重筹办规范化来源材料`分支；原`原重筹办意图幂等键`包装为`L2任务重筹办意图幂等身份`，其它十三项不变。

本轮禁止：

- 把`任务初次筹办工作包`转换成`下一筹办工作包`；
- 为初次模式伪造目标未达成、待重筹办、旧结果或旧实例；
- 泛化第一阶段 lookup provider；
- 在线程中增加初次工作包 union；
- 增加仅供测试调用的 seam 或私有状态出口。

每处固定迁移为：

```text

-> 读取首次准备记录 / 任务身份来源
-> 通过正式方法 owner 取得当前方法生命周期

-> 下一筹办工作包
```

测试不得直接构造首次准备记录身份对应的 owner 私有事实，不得跳过公开初次准备入口，不得先造旧结果，不得恢复`发布当前选中路径`。

## 8. 结果共用 / 争用排除边界

任务结果形成和任务完成均在本流程之后。任务完成后，每个需求成员必须单独读取目标合同与当前事实核算：结果可共用时不排序、不扣减；存在容量、范围、所有权或有效性扣减时才是争用，并按正式成员分配优先级逐项分配。

该优先级不得进入本次方法选择、初次 / 重筹办来源、执行冻结、线程队列或五处 bootstrap。工作区异主的结果消费关系与争用分配草稿不属于本计划，不修改、不登记、不提交。
