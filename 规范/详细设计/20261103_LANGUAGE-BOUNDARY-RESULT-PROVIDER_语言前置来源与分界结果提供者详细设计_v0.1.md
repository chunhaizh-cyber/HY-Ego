首版前置来源建立只处理真实接收M的**整条非空消息根出现**：起点0、终点为实际标量数、路径空。目标可取根内任意非空范围。非空根路径须从已有正式出现取得；main尚无可不依U确认该路径的提供者，本叶返回`未支持`，不猜路径。该限制是首叶支持范围，不把其它合法出现永久禁止，也不改变完整键形状。

原`新_外设世界树类`实现消息端口的同名`const override`，公开声明在其现有h，定义在现有cpp。只校验正式消息／方向／正文等结构；原始M须接收，依据中的询问须实际输出／发送，答复须接收。它不判断问题含义，不生成回答关联。

窄发布前提只投影正式M本身的不可变字段、正文材料实际内容及被引用身份存在；不能包含完整消息根集合、窗口消息计数、其它消息入边或全场景快照。其它入站追加不改变本消息内容，不得使本来源无谓冲突。精确字段和材料类型校验留原消息／材料owner内部，不把私有schema移入语言业务。读取使用原外设互斥，所需端点一次L1组合读取，失败按工程状态交付或进入既有工程终止链，不裸返回空消息。

依据端口的两条业务合同分别为：规则确实适用于本来源／范围并给出这套完整边界；或实际答复与该正式询问、目标明确关联且解释／对齐唯一给出这套边界。`已确定`须附覆盖真实必要前提的中性投影；不足／多义／不适用不得保存成有效结果。`不适用`表示依据已能确定不适用于本来源或作用范围，与必要材料尚不足、多套仍可能的解释分别返回。工程非成功时`判断`为空，不换成材料不足；工程已完成时恰有一项实际判读。端口不能靠调用者设置一个`true`完成这些判断，也不能仅因知识／消息节点存在就返回已确定。

**此依据端口及结果／采用DTO是后继接口候选，尚未冻结，更不是已有生产实现。** 它还缺语言选择及其正式来源／读取依据的完整输入合同；现main也缺两条实际判读算法及正式问答关联接口。不得从不带语种判断的前置source反推已取得语言依据，本文件不伪造reader，也不允许用测试替身冒充生产。第9节据此限制可实施范围及完成声明。

```cpp
新语言分界工程状态 新_语言类::停止采用分界结果(
    const 新语言分界停止采用请求&);
```

方法不声明`noexcept`：`bad_alloc`／`length_error`转资源失败；正式结构损坏、未知异常向上送至原工程边界，不能统一catch后伪装未找到。返回状态属于调用／工程控制，绝不写入语言业务结果、C/R或目标值域。`本次已发表身份`仅帮助调用方保留已发生事实／读回重试，不是业务证明节点。`读取分界结果`只读固定内容，不声称当前已采用或依据仍适用；只有`读取当前分界结果`进行fresh判定。

所有`新语言分界调用结果<T>`在工程`已完成`时恰有`信息`；工程非成功时`信息`为空，因此不得携带正常业务判读。若失败前已有发布，只可在独立工程字段`本次已发表身份`保留实际身份，不补造业务判断。保存、采用和当前读取分别通过上述三个明确载荷返回正常判读，不能从`optional`是否为空推断材料不足或多义。

## 5. 私有角色布局、引用与唯一性

扩展原语言cpp内私有`语言分界键`及schema句柄；不增加通用节点族枚举，不向调用者开放句柄。本首叶由独立公开的`初始化分界结构`只原子建立**来源及其登记所需**角色／字段键组，不建立语种字段／混合语段，不预建目标、结果、采用、分界项或回答对齐schema，不改原`新_语言类::初始化()`或普通装配，也不声称该新方法已有生产调用者；同一进程重复初始化复用，部分句柄／结构不完整是工程错误，不再建第二组补洞。来源角色编码为1；下表其它角色为同份设计的后继布局候选，不在首叶建立或声称物理合同已冻结。

| 角色 | 字段（除特别说明均恰一） |
| --- | --- |
| 来源（首叶） | 角色、原语言组织根引用、M引用、根范围U64[2]、根路径I64数组、正文材料引用；无任何语种判断字段或子项 |
| 目标 | 角色、来源引用、范围U64[2]；当前采用结果引用0..1 |
| 结果（后继候选） | 角色、目标引用、分界项引用1..N、依据种类I64；规则依据恰一知识引用及固定语境材料引用组；回答依据恰一Q／A消息引用及对齐引用组；两分支互斥；同来源语言选择与正式读取依据尚待补齐，当前布局不完整 |
| 分界项 | 角色、结果引用、顺序I64、范围U64[2]、用途I64 |

来源通过原语言组织根的专属登记字段引用，目标由来源的专属目标登记字段引用，结果由目标的专属结果登记字段引用；它们是各自唯一登记，不再复制第二权威map或反向成员列表。子项以有序引用保存，反向宿主仅用于结构核验。当前采用关联由目标上的**一条L1字段关系**承载，不另造采用证明节点；其目标必须为同目标已保存结果。

来源按完整来源键唯一，同M、固定正文材料、原根范围／空路径相同则复用，不因后续语种解释另建来源；同来源键若指向另一固定正文材料是来源不一致，不能用caller语种断言掩盖。后继目标按来源和范围唯一；结果的候选去重为目标＋完整分界项＋完整依据，正式语言读取依据补齐后仍须复核完整定义。当前采用只许0..1，多个互斥项是损坏，不当作业务歧义。U／D／T／时间戳和语种判断均不进入目标键。所有稳定身份只由L1分配，不能由哈希、M或范围派生。

首叶对正文材料、M及原组织保存真正节点引用，禁止只存U64编码数组冒充引用保活；根范围／路径为原定位直接值，不造语种对象或副本。后继的规则、固定语境、Q／A、目标与结果同样须有正式引用；语言选择的引用布局仍待其正式来源合同闭合。已保存固定材料不改写；修正保存新结果并显式比较替换当前采用的既定原则保留，原文／问题键不变。

## 6. 单调用一致性、原子发布与锁序

1. 外设端口／依据端口先在语言锁外执行，每个端口在自己的owner范围形成强类型材料及必要中性前提。语言owner不持锁回调，不在L1独占锁下执行业务判断；锁序为外部各owner读口结束→语言互斥→L1单次读取／发布。禁止外设锁与语言锁互持，不向调用方泄漏锁或可变容器。
2. 在语言锁下定位自己的来源／目标／结果及子项ID；分步遍历只用于发现闭包，不能拼成成功结果。最终一次`查询节点组完整结构`读取本次全部自有节点及端口列明依赖，按本schema重新构造并校验完整载荷；端口的中性投影须与该次读取的实际选定字段一致。无法形成完整闭包即工程失败，不截断或按预算返回半组。
3. 首叶建立来源只将来源节点、原M／正文材料／范围定位和组织登记一次`原子追加节点组`发布，不建语种字段或混合子项。后继保存结果拟将必要新目标、结果、所有项及登记一次发布；其正式语言依据等未闭合，不能提前施工。发布只携带M固定内容、依据实际必要字段及自有本次目标的前提，不携带无关消息根集合或历史保护全集。结果保存不顺便采用，调用方必须显式执行采用步骤。
4. 采用先核`预期当前结果`，再fresh核验目标结果和依据。已有采用相同则零写复用；不同且预期相等才替换当前字段；不存在且预期为空才首次添加。停止采用也须精确预期相等后删除该字段。当前L1 cpp889–917要求节点引用替换／删除的宿主及旧／新引用目标均具联合预期，因此替换时最小写许可集是**本次fresh读取的本语言目标、旧结果、新结果**，停止时为目标和旧结果，首次追加则按原追加合同处理；不能写成只保护目标即可。其它依赖采用窄只读投影，不沿原工作保存或恢复所有端点的整组旧快照，也不为减少此最小写许可集扩底座。原接口带来的真实前提不符保留工程控制，不能删除保护伪成功。
5. 读口的线性化点是最终单次L1完整读取。写口线性化点是L1一次独占交换；跨独立调用没有共同快照承诺。发布前提不符返回工程控制`前提已变化`且零本次写入，调用方同语义重读，不静默删保护、把它改成成功或业务未知。相同owner互斥防止并发同键双建，L1精确条件阻止外部引用发生真实变化时继续提交。
6. 已发表后如材料复制／后续读回失败，保留已发表身份与事实，原请求同键重读；不回滚其它owner、不重做询问／发送，也不声称动作效果已完成。能预分配的返回载荷在发布前准备；不得让可避免的发布后分配改变业务语义。

## 7. 正常分支、失败和生命周期

前置来源读取不调用解释器、词owner或需求owner；只核M真实、固定正文材料及原根范围／空路径与组织，不检查或确认语种。文字尚未理解、语种尚未识别时仍可建立来源，返回不携带“显式未知”等语种结论。后续解释改变语种判断不改变已保存的原文来源；首叶没有永久拒绝语种修正的字段或写入门槛。

以下是后继结果接口候选须保持的业务分账，尚须语言选择正式依据等补齐后才能冻结。结果形状须完整覆盖目标，范围有序不重叠；回答对齐须在实际答复／原文范围内，不把去标点当覆盖。形状不合法写前拒绝。保存入口的正常分流候选如下：

| 依据判读 | 保存调用返回 | 写入 |
| --- | --- | --- |
| 已确定 | 工程已完成；`信息.判断=已确定`，`已保存结果`恰一正式结果（新建或逐值复用） | 按同键保存合同，复用时零写 |
| 材料不足 | 工程已完成；`信息.判断=材料不足`，`已保存结果`为空 | 零写，包括零新目标／结果／采用；由调用方继续筹办 |
| 多义 | 工程已完成；`信息.判断=多义`，`已保存结果`为空 | 零写，不取首 |
| 不适用 | 工程已完成；`信息.判断=不适用`，`已保存结果`为空 | 零写，不把不适用误报材料不足 |
| 工程非成功 | `信息`为空，无业务判读 | 不伪装正常不足；本次若已有发布按独立工程字段保留事实 |

采用入口也返回实际依据判读。已确定且CAS成立才变更采用；正常不足／多义／不适用均零采用写入，`实际当前采用结果`保存实际未变的引用（可以为空），`本次采用后有效结果`为空，不能据该空值推断旧结果已失效或采用已被解除。旧当前材料是否有效另由fresh当前读口判定。

fresh当前读取在工程已完成时恰有`新语言分界当前信息`，业务判读及载荷固定为：

| `判读` | `当前采用材料` | `当前有效结果` | 含义 |
| --- | --- | --- | --- |
| 无采用 | 空 | 空 | 合法目标当前无采用（含尚无目标登记但来源／范围合法）；不是依据不足或多义 |
| 依据不适用 | 恰一原采用固定材料 | 空 | 依据明确不适用于当前范围／语境，保留材料，不自动解除采用 |
| 材料不足 | 恰一原采用固定材料 | 空 | 核验材料尚不足，不能确认当前有效 |
| 多义 | 恰一原采用固定材料 | 空 | 依据存在多套仍可能解释，不取首 |
| 有效 | 恰一原采用固定材料 | 与左栏同一结果 | 唯一当前采用、完整范围且依据适用 |

坏引用、重复当前字段、跨目标采用、损坏结果进入工程错误链，不能返回`无采用`或其它正常判读；读取工程非成功则`信息`为空，无业务判读。保存回执、任务通知或已有词条都不能替代fresh结果。

停止采用只解除精确预期的当前采用关联，保留所有已发布来源、目标、结果、分界项、对齐和依据引用。本首版不新增物理删除公开接口或删除实现范围，不因未采用、旧结果暂时无人消费或停止采用而清理材料；后续物理清理只按owner届时正式合同处理，不在本叶提出新删除授权。不设置TTL，不删除消息、规则、词条、概念或异主对象。

修正使用保存新结果→比较采用的两步，各步分别原子；若采用失败，新材料仍可读，不能声称修正已生效。一次修正不重建目标。资源／工程失败不改变需求、任务状态；等待／歧义只能来自真实业务材料，不来自捕获异常。

## 8. 启动、退出与恢复证据边界

`初始化分界结构`要求当前正常语言基础结构已就绪，否则返回工程控制`未初始化`；它不隐式调用原语言初始化，不开启业务线程，不创建伪造来源或结果。当前独立提供者没有生产调用者，未调用新初始化时其它新入口均返回`未初始化`，不得默认成功或偷偷建schema。接口依赖基础数据集及原语言结构活得更久。本叶不新建全局owner、不增加独立工作线程／磁盘文件。端口只在调用期借用，调用完成不留裸指针；进程退出依原应用join顺序释放。

main原`新_语言类::初始化()`（cpp256）的`bool noexcept`末尾有`catch (...) { return false; }`，不能把新初始化异常塞进去再按普通否定吞掉。本首叶选择不接该入口，故不经过这条吞没链；新方法按第4.3节独立工程控制／异常向上传播。未来生产接线须在原应用工程责任边界显式处理其状态与异常，不增启动入口；若届时选择纳入原bool初始化，应把受影响的工程诊断收口一并冻结，不能仅加一次调用。该接线属于第9节后续消费者，当前不宣称完成。

目前main的L1没有公开完整持久保存／恢复能力，原语言schema句柄又是进程全局。**本叶运行期发布不依赖尚无的持久机制，跨进程生产恢复保持未实现且不纳本轮代码范围。** 不新增schema重挂API或由本叶另存根身份。未来正式完整current-only恢复后，须由正式启动路径恢复原语言/schema身份，再完整核对来源／目标／结果／引用闭包、重建非权威索引及fresh采用；旧端口／缓存不得恢复为权威。无法确认原根或引用闭包时拒绝开放，不建新空根假装恢复。该未来条件不是已有恢复代码或本叶验收结果。
