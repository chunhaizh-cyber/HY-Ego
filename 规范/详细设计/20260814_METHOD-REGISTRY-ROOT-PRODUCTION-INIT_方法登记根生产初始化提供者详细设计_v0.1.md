# 方法登记根生产初始化提供者详细设计 v0.1

日期：2026-08-14

计划身份：`METHOD-REGISTRY-ROOT-PRODUCTION-INIT`

当前设计状态：BIZ 合同已冻结；DATA ABI 为预冻结需求，最终实现、工程登记、装配、启动接线、编译和动态验证均未发生。

## 1. 目标与完成边界

阶段 18 四个语言无关概念本体根生产初始化完整成功后，普通系统初始化必须先调用唯一 `方法登记根生产初始化提供者::初始化`。provider 经普通应用唯一 `L2方法结构聚合服务` 取得同一 `L2方法结构服务`，建立或幂等收敛唯一方法登记根；正式按角色读回并最终再次读取全部当前根，证明当前恰一根、角色正确、首次请求见证一致后，才值式发布调用方材料。任一非成功映射阶段 19；阶段 20 不预分配。

本叶不创建方法首、默认方法、治理虚拟存在、方法生命周期、条件、结果、动作入口或任务选择；不实现概念支持、二次特征、语言、词性、短语、投影、自我线程、信号、宿主或跨进程恢复。历史 `BIZ-L3-001-03-01` 及其三个 L4 永久冻结，不复活为本叶实现依据。

## 2. 权威依据与当前事实

机器语义依据：0050、3300、5300、8120 v0.9。

业务依据：`BIZ-L1-T01`、`BIZ-L2-001-03`、`BIZ-L3-001-03-10`。

当前正式主线只有方法登记根 DATA 内部准备链的部分设计与能力：`L1-SIMPLIFY-METHOD-ROOT-R1` 已退出，R2—R9 待激活；R10 计划与详细设计已跟踪但未登记计划索引。它们不构成 `BIZ-L3-001-03-10`，也没有提供本叶所需的完整 L2 生产服务或聚合 getter。本候选包同时形成两份未登记工程、未编译的 BIZ provider 源码；源码存在不等于 provider 已实现或可调用。

本设计把最终公开需求冻结给 DATA 所有者。BIZ 可以据此继续形成不编译、不登记工程、不装配、不接启动的候选；DATA 正式结果发布前，不得把预冻结类型或签名宣称为当前 ABI。

DATA 尚未实现不阻断本设计包发布，也不阻断自顶向下继续分解下一 BIZ 叶。它只阻断本叶的真实编译、工程登记、装配、启动接线和动态验收。DATA 真实 ABI 发布后，本叶返回机械匹配和验证，不重新发明业务合同。

## 3. 预冻结 DATA 公开合同

### 3.1 物理所有权和依赖方向

DATA 最终提供唯一 `L2方法结构服务` 及唯一 `L2方法结构聚合服务`。聚合只持一份 non-owning `L2方法结构服务&`，公开 const / non-const `取得L2方法结构服务()`，零 owner、零写入、零锁、零缓存、零 DTO 解释。

唯一消费路径为：

```text
方法登记根生产初始化提供者
-> L2方法结构聚合服务::取得L2方法结构服务()
-> 同一 L2方法结构服务
```

BIZ 不直达 L1，不复制 R1—R10，不建立第二方法登记根 owner、第二 provider 或兼容别名。DATA 可在职责匹配的最终方法结构模块中机械调整文件名，但最终类型、函数和 getter 必须与本合同逐项匹配后才能解除待激活门禁。

### 3.2 强类型根 DTO

预冻结语义形状：

```cpp
enum class L2方法登记根角色 : std::uint8_t {
    方法登记根 = 1
};

struct L2方法登记根角色事实 final {
    L2方法登记根角色 角色;
};

struct L2方法登记根事实 final {
    L2方法身份 根方法;
    L2节点族身份来源事实 身份来源;
    L2方法登记根角色事实 根角色;
    L2结构幂等身份 首次幂等身份;
    std::uint64_t 首次期望事实代次;
};
```

最终 DATA 必须按上述强类型角色事实完整公开：非零根身份、方法节点族来源、唯一方法登记根角色、非零首次幂等身份、非零首次期望事实代次，以及结果截止下的当前性。普通方法首、名称、生命周期、条件、结果和动作入口不得塞入根 DTO。

建立请求固定为共同请求头、非零幂等身份和闭合 `方法登记根` 角色。首次请求见证由方法结构 owner 与根事实同一次原子发布并永久读回；调用参数、固定常量、BIZ 缓存和方法名称都不是根权威事实。

请求、结果和纯值不变式 helper 的预冻结字段名与形态如下；底层共享头类型由 DATA 唯一拥有，本叶不重定义：

```cpp
struct L2当前方法登记根组读取请求 final {
    L2结构请求头 请求头;
};

struct L2方法登记根建立请求 final {
    L2结构请求头 请求头;
    L2结构幂等身份 幂等身份;
    L2方法登记根角色 角色;
};

struct L2当前方法登记根读取请求 final {
    L2结构请求头 请求头;
    L2方法登记根角色 角色;
};

struct L2当前方法登记根组读取结果 final {
    L2结构结果头 结果头;
    std::vector<L2方法登记根事实> 方法根;
    bool 成功() const noexcept;
};

struct L2方法登记根写入结果 final {
    L2结构结果头 结果头;
    std::optional<L2方法登记根事实> 方法根;
    bool 成功() const noexcept;
};

struct L2当前方法登记根读取结果 final {
    L2结构结果头 结果头;
    std::optional<L2方法登记根事实> 方法根;
    bool 成功() const noexcept;
};

bool L2结构幂等身份有效(L2结构幂等身份 身份) noexcept;
bool L2方法登记根建立请求有效(const L2方法登记根建立请求& 请求) noexcept;
bool L2方法登记根事实完整(
    const L2方法登记根事实& 事实,
    std::uint64_t 事实截止代次) noexcept;
```

三个 helper 只是 DATA DTO 所有者公开的确定性纯值不变式，不读写事实、不取得业务编排权，也不增加第四项服务操作。最终 DATA 若复用已有共享 `L2结构幂等身份有效`，必须保持同一实体所有者，不得在方法模块重复声明。

### 3.3 三项公开能力

```cpp
L2当前方法登记根组读取结果 L2方法结构服务::读取全部当前方法登记根(
    const L2当前方法登记根组读取请求& 请求) const;

L2方法登记根写入结果 L2方法结构服务::建立方法登记根(
    const L2方法登记根建立请求& 请求);

L2当前方法登记根读取结果 L2方法结构服务::按角色读取当前方法登记根(
    const L2当前方法登记根读取请求& 请求) const;
```

`读取全部当前方法登记根` 的 `期望事实代次 = 0` 表示在一个原子读取许可内选择调用时最新当前快照；成功必须返回非零事实截止和 0—1 个按角色稳定排序的根。非零值是乐观守卫，成功结果截止必须精确等于请求值；不相等只返回零变化、空根组的事实代次漂移。

建立与按角色读取必须使用非零期望事实代次。建立成功只允许 `已提交 / 精确重复`，必须携带完整单根、严格晚于该实际建立请求期望代次的事实截止及等值变更代次。单根读取成功只允许已读取、optional 有值，结果截止精确等于请求守卫。

写入结果和单根读取结果用 optional 承载根；全组读取结果用 vector 承载 0—1 根。任一非成功必须载荷空、变更事实代次空。成功空 optional、第二根、非法角色、重复角色、混代、错误首次见证、读入口返回写状态、写入口返回读状态、未知枚举或其它坏形状一律由 BIZ 映射内部不一致。

DATA 的资源失败和发布结果未知必须以可让 BIZ 保留原请求重放的结构化非成功返回；不得要求 BIZ 换幂等身份、猜测根已发布、从 L1/SQL/日志/缓存回源或把异常文本当事实。

公开请求只含合同版本和一个非零方法登记根幂等身份。阶段 18 成功结果是调用顺序门，不进入该请求，不取得方法登记根事实语义。首次合法请求在任何 DATA getter / 读 / 写之前锁定；异义请求零 DATA 调用。

成功状态只有 `已发布 / 精确重复`，并携带完整 `方法登记根发布材料`。其它状态至少分账：请求无效、已发布选择冲突、当前根组预读失败、方法登记根形成失败、单根正式读回失败、最终根组读回失败、事实代次竞争、根读回不一致、资源失败、内部不一致；非成功不得携带来源或已发布材料，但可保留实际调用证据，并且必须保持旧发布值。

结果证据必须保存初始与最终组读的实际请求和结果、零至两次实际建立请求和结果、一次实际单根请求和结果；漂移重读还保存调用前已知截止。进入时存在待重放请求时，以 optional 回显该完整请求，并要求本次第一次建立调用逐字段等于它。`成功()` 还必须从这些实际证据重新证明：无待重放的首次建立守卫等于初始预读截止；漂移重读调用前已知截止等于本轮当时截止；重组请求守卫等于漂移重读截止；单根守卫等于预读、成功写入或漂移重读收敛后的本轮最新截止；最终组读守卫等于单根读回截止。任何跨调用截止断裂都只能是内部不一致，不能拼成成功结果。

## 5. 编排顺序

```text
校验请求并锁定同上下文选择
-> 经方法结构聚合取得同一服务
-> 以期望事实代次0读取全部当前方法登记根
-> 有待重放请求：不受预读已有根影响，先原样重放
-> 无待重放且已有唯一根：跳过写入
-> 无待重放且缺根：按当前截止形成并保存完整建立请求
-> 建立已提交/精确重复：只在更晚时推进本地截止
-> 明确零变化、空载荷、无首次结果的漂移：以0正式重读全组
   -> 根已出现：进入单根读回
   -> 根仍缺失且尚未重组：同幂等身份按新截止重组一次
   -> 再次漂移：事实代次竞争
-> 资源失败、异常、坏非成功或发布未知：保持原完整请求和待重放标记
-> 按角色以本轮最新非零截止正式读回单根
-> 以同一非零截止最终读取全部当前根
-> 证明恰一根并与建立结果、单根读回、首次请求见证逐字段一致
-> 构造完整候选并以无抛出交换发布
```

零代次漂移重读结果截止不得早于调用前已知截止；非零单根和最终组读结果截止必须精确等于实际请求守卫。精确重复可能回显较早的首次提交截止，因此本地守卫只允许取更大值，禁止回退。

正常同请求重复调用预期零根写，但每次仍完整执行初始组读、单根读回和最终组读。发布槽只供调用方消费，不替代 DATA 正式读回。

## 6. 并发、异常和发布守恒

同一 provider 用一把调用 / 发布锁串行化完整调用；锁只保护 BIZ 选择、保存请求和发布材料，不取得 DATA 根事实权。普通应用上下文最终恰好拥有一个 provider，生命周期短于其方法结构聚合。

DATA 建立调用前先把待重放置真；只有明确成功、允许重组的零变化漂移或明确入口 / 许可 / 幂等 / 引用拒绝才能按合同清除。调用抛出、结果证据保存失败、资源失败、坏载荷或发布结果未知均保留原请求。已明确写成功后的后续读失败不重复写，下一调用由正式读回收敛，以保持正常重复零写。

`std::bad_alloc` 映射资源失败，其它未预期异常映射内部不一致。完整成功候选构造和自证之前不得修改已发布槽；最终只执行一次编译期证明无抛出的 optional 值式交换。

## 7. 阶段和后继

- 阶段 18 非成功时本 provider 调用次数必须为零。
- 阶段 18 成功后立即调用本 provider；任一非成功返回阶段 19。
- 只有方法登记根生产初始化真实成功并正式读回唯一根，才允许进入创建 / 开放自我线程等后继。
- 阶段 20 不预分配；后继失败阶段由后继独立设计冻结。

| 根工程双配置、生产外专项、strict、工程唯一登记、生产零验证痕迹 | NOT_RUN |

无法由最终公开接口稳定注入的资源耗尽、私有损坏或发布未知分支，必须逐项保留 `NOT_RUN` 或使用分层证据；禁止新增生产验证 seam、假 provider 或固定成功。

## 9. 激活与完成声明边界

计划保持待激活，直至：阶段 18 provider 真实实现、接线、接受、退出和清理；DATA 最终三能力与聚合 getter 发布并由 DATA 所有者交付；普通应用、启动、工程、构建和验证资源释放；从届时最新 `main == origin/main` 机械匹配全部 DTO、签名、字段顺序、状态、provider 构造和固定身份。

本设计不证明 DATA 服务、BIZ 源码、编译、装配、正式启动的非成功阶段19映射或方法登记根事实已经实现。即使未来代码和专项通过，也只证明唯一方法登记根初始化切片，不证明方法可执行、自我线程已启动、概念支持、语言形成、投影、宿主或完整业务闭环。
