## 1. 对象、原因、目的和范围

修改对象是任务虚拟存在 Vt 的任务状态特征 Fstate，属于内部治理；不是现实世界自我的服务值。本叶要把已经发生的任务状态修改完整组织成任务场景 C(T) 内的真实前状态、后状态和变化动态，使任务治理事实可被正式读取。附带提供 Vt 已有状态 F 和服务值 F 的中立只读身份，不迁移服务值余额、不增加服务值写入。

本叶交付：

1. 唯一任务 owner 对 Vt 正式持有的状态 F、可选旧服务值 F 提供严格只读合同。
2. 所有既有状态变更入口都经统一写入；真正发生变化才建立前后 S 和一个 D，归属唯一 C(T)。
3. 已有最终来源 `9→12` 保留原动作、来源、前后状态、动态及因果链，不再附加第二份无动作动态。
4. 初始化/重复初始化能核验含普通状态变化的 C(T)，不会误判为只能容纳 `9→12`。

排除：服务值 Q 的权威余额迁移和计值；普通子任务新增结算路径；self 直接调用结算；方法 Vm/C(M)；新增本能方法头；任务/需求业务状态表变化；任务参数场景；线程消息和装配对象；新被动动作概念；普通无动作变化的新增因果；持久化、崩溃恢复、自动重放和历史缺口补造。新任务状态初始化及已有 Ftq=0 初始化不是状态迁移，不伪造初始动态。


生产读取器在 task 锁下验证：T 是正式任务根登记的任务；T→Vt 及 Vt→T 唯一互认；输入三字段完全吻合；stateF 及已声明 serviceF 是顶层实例 F；各自 Vt 私有持有字段恰一且 F 不被其它 Vt 借用；同一 F 不同时冒充两种特征；当前值存在且为 I64，状态属于既有枚举、服务值非负；当前具体概念可归一到各自已初始化类型根。`新特征信息` 没有普通持有者字段，不发明 F→Vt 字段或把 `上级特征节点` 当存在 owner。

## 4. 世界和场景合同

### 4.1 世界窄接缝

在 `新任务治理世界协作接口` 和 `新_内部治理世界类` 增加：

```cpp
virtual 新治理任务特征变化结果 完成任务特征变化(
    const 新任务虚拟存在特征引用&, 稳定编码 前状态, 稳定编码 后状态) noexcept = 0;
virtual std::optional<新治理任务特征变化结果> 读取任务特征变化(
    const 新任务虚拟存在特征引用&, 稳定编码 前状态, 稳定编码 后状态) const noexcept = 0;
```

唯一生产调用者为 task 普通状态变更链。世界通过只读特征组确认 F 属于 Vt，取得唯一 Ct，调用状态/动态/场景 owner；不得直改 T/Vt/F、S/D 本体或它们的字段。新读回函数只在完整合法 Ct 中找不到该精确前后状态对时返回 `nullopt`；对应 D 重复、部分挂接、跨场景、坏结构和读取失败走工程终止。只读函数不要求历史后状态等于当前 F；完成入口在新发表前另行要求后 S 等于当前 F。

`完成任务特征变化` 在创建 D 前完整核验：S 前后不同；主体均为目标 Vt；来源实例 F 均为目标 F；两端具体概念可分别归一到相同正式类型根；固定值均为 I64 且不同；实际强时间合法且后大于前；后 S 固定值等于当前 F；两端无异场景挂接。已有精确完整 D 则只读回、不重复计数；已知部分发表不得自动重放或补造。新建路径通过 `添加治理状态` 挂前后 S，再由动态 owner 建立一个原子 D，最后 `添加治理动态` 并精确读回。普通 D 无动作关联，不调用 `交付实际发生`。

世界构造函数已经接收 `概念_特征类&`，本叶只增加私有成员 `概念_特征类& 特征概念服务_` 保存既有依赖，用于历史 S 的具体概念→类型根校验；不改变构造参数或装配 ABI。

### 4.2 场景中立扩展

`添加治理状态(C,S,读取器)` 签名不变。在场景锁外，经已有治理参与者和新特征组只读合同核验 S 的 Vt/F 正式归属，形成值式 `新任务虚拟存在特征引用`。私有 helper 改为：

```cpp
新场景操作状态 添加已核验状态(稳定编码 场景节点, 稳定编码 状态节点,
    bool 治理,
    std::optional<新任务虚拟存在特征引用> 治理特征 = std::nullopt) noexcept;
```

在场景锁内只重读自身正式场景拥有者/参与者及 S，核对传入三字段身份和 F 与 S 完全一致；治理模式必须提供该值式凭据，非治理模式不得提供。不能继续把 S 来源 F 强制等同 stateF。凭据不保存为新的正式事实，不新增 Ct→serviceF 镜像。

`添加治理动态` 签名不变；对普通原子 D 在场景锁外核验两端 S 及新特征组，确认同 Vt、同来源 F 且 F 由该任务正式持有，再进入现有私有动态挂接。历史 S 的具体概念→类型根核验属于 world 完成/读回，创建 D 时动态 owner 也已有同类型根检查；scene 不新增概念服务依赖，不调用 task 实现或发明投影接口。私有挂接保持两端 S 已属本 Ct、唯一列表和引用计数约束。动作分支仍按原 stateF 动作合同验证，不扩成任意特征动作。普通现实场景写入路径和中立 state 结构不变。

`添加已核验状态/添加已核验动态` 的治理分支必须同步调整既有工程失败收口：列表字段已发表后，增加引用或精确读回失败时保留字段、S/D 及已发生引用变化，立即工程终止，不沿旧分支撤边并减少引用，避免删除真实事实。只有在正式挂接前确证零发表时才允许原候选生命周期处理；未知发表同样保留。普通非治理场景分支的原合同不变。本叶不声称计数/列表跨调用原子；残留不完整组织由初始化严格拒绝，不能自动“修复”为正常历史。

## 5. task 唯一状态写入链

### 5.1 精确成员合同

在 `新_任务类.h` 的 private 区声明、同 cpp 定义下列成员；旧同名匿名 helper 删除，其现有调用均改为成员调用，不保留两条生产写法：

```cpp
新任务操作状态 写入任务状态(
    const 新任务虚拟存在信息&, 新任务状态) noexcept;
新任务操作状态 写入已核验任务状态值(
    const 新任务虚拟存在信息&, 新任务状态) noexcept;
void 提交已核验任务状态特征值(const 新任务虚拟存在信息&, 新任务状态,
    std::optional<稳定编码> 可撤销前状态) noexcept;
```

`写入任务状态` 保持既有合法迁移谓词，然后调用 `写入已核验任务状态值`。后者只允许同类已核验的普通/专用重新启用状态写入口；不向外公开。`提交已核验任务状态特征值` 是唯一不自行产生 S/D 的窄 F 提交函数，只供普通链及已存在的 `标记任务已结算` 动作链使用，不能供其它上层绕开事实组织。所有调用持有 `新任务互斥`；成员内部可以重入该递归锁作防护，不在下层 owner 锁内回调 task。

普通链固定顺序：

1. 重新读取正式 Vt/F，确认输入身份及原状态未漂移；组织已经就绪且唯一 Ct 存在。业务非法迁移保持既有拒绝。
2. 同状态立即返回 `无变化`；不建 S/D，不调用 feature 更新，不增加特征值命中。
3. 核验/确保当前 Vt 专属概念；取真实 UTC 强时间，由 task 调状态 owner 建立旧值前 S。本次前 S 先不挂 Ct、不给动作、不交其它消费者。
4. 调用窄 F 提交函数，传入该可撤销候选。必须先有前 S，后准备 F；因为 S→F 引用会改变 F 的入边快照，不能颠倒。
5. F 完整收尾及 Vt 专属概念刷新后，重新读回目标值，取真实后时间，严格大于前时间，再由 task 建后 S。不合成 `前时间+1`、不填未来时间。
6. 世界完成特征变化，建立/挂接/读回一个 D；确认目标、Ct、S 和 D 精确一致后返回 `已修改`。

每次真实状态变更使用本次观测的前 S，不新增“最近状态查询”API或时间并列选择规则。不同次变更前后值相同不等于同一次观测，不能仅凭数值复用历史 S；动态仍各对应唯一实际变更。初始化校验允许正式 D 共享合法端点，但本写入链无需制造共享。

### 5.2 F 提交和候选生命周期

`提交已核验任务状态特征值` 重新核对 F 当前值与输入旧值、目标确有变化，然后严格使用：

```text
准备顶层I64更新(F,目标)
→ 核验凭据 F/原值/新值/核心有变化
→ 提交顶层I64更新(凭据,{})
→ 完成顶层I64更新(凭据)
→ 结束顶层I64更新(凭据)
→ 确保任务虚拟存在语义(T)
→ 精确读回 F 和当前专属概念
```

空附加片段向量表示本叶没有伴随业务字段要原子修改；不得造空写封存片段。feature 凭据仅记录更新占用及 owner/线程/阶段，不跨函数持有互斥量；它必须由同线程同 feature owner 完成或取消，不能在线程间传递。

明确零发表的准备/提交失败：先取消已准备凭据、释放占用，再按状态 owner 删除本次未挂接且零消费的候选前 S，完整读回清理后工程终止。无候选的既有动作链不得删除已挂接 S/动作。若已有消费者、发表未知、核心已发表或完成/概念收尾出错，保留全部已发生材料并日志、弹窗、终止；不得调用取消/删除当回滚，不得仅因 F 新值可读便返回 `已修改`。不能让已提交凭据在正常栈退出时被当成未提交凭据销毁。

F 核心更新由既有封存提交保证原子；F 后续聚合、Vt 专属概念、S/D/Ct 组织不是同一个 L1 原子事务。本叶不伪称全链原子。task owner 锁覆盖整条链，使合法 task 读取者只在完成后读取；越过 task owner 的底层观察不由该锁保证。后半段故障保留实际 F/S/D 并停止受影响进程，不能补造成功；重启自动修复不在本叶。

### 5.3 `9→12` 与既有消费者

`标记任务已结算` 保持请求核验、普通动作来源、原动作时间、已结算精确幂等读回和状态资格。其已建立前 S/动作之后，只将旧裸 F 写入改为 `提交已核验任务状态特征值(虚拟,已结算,std::nullopt)`；不能调用普通 `写入已核验任务状态值`。F 收尾后刷新专属概念，再生成原合同后 S，调用原 `完成任务状态变化`，保留原因果发生身份和统计。不得再调用新无动作完成接口，不重复 S/D，也不把已有动作清空后作为“未知原因”。

| 生产写入点 | 本叶迁接 / 保持边界 |
| --- | --- |
| `修改任务状态` | 统一合法迁移成员，覆盖其全部线程和任务内部调用者 |
| `重新启用任务` | 清除候选及资格仍按原合同；替换直接 `添加特征值` 为已核验成员，不放宽终结状态谓词 |
| `开始方法执行` | 写执行结构后调用统一成员；实际 F 发表后故障终止，不返回让调用者回滚已对应的执行结构 |
| `撤销未进入动作执行` | 原恢复字段及待查找方法迁移保留，真实状态回退同样建立 S/D，不虚构方法动作 |
| `结束方法执行`、`评估方法执行影响` | 分别迁入待影响评估/等待自我决议的统一成员 |
| `标记任务已结算` | 上述专有一次动作链，不经过普通 S/D 组织 |
| 建立任务初始 F | 不变；不是“从未知值变化到初值” |
| `结算已完成任务/推进任务完成贡献` | 贡献 K/R/Q 算法不改；其已经调用状态入口者自然消费新的事实组织 |

## 6. 初始化、旧组织与因果边界

`迁移已有任务治理场景` 保持先全量预检后写入。分类处理：

- 旧治理根 Cg：仍只接受现有可完整追溯的 9→12 动作包；归属、动作、来源、强时间不齐停止报告，不猜测普通 D 应迁给谁。
- 已有 Ct：可为空；或者包含完整 9→12 动作包、普通原子状态 D，或两者混合。逐原始列表核验，无重复、跨 Ct 挂接或不属于 owner Vt 的 F。
- 每个普通 D 必须有同 Ct 的两个正式 S、同 Vt/来源 F/类型根、不同固定 I64 值、严格时间顺序；全部 S 必须被完整 D 覆盖，不接受孤立前 S/后 S。共享合法端点允许，不能用“状态被两个包见到”直接判坏。
- 动作仍必须完整满足原 9→12 合同，并且关联一个精确 D；动作包中的 D 同样计入总 D 覆盖集合，不能重复生成或统计。其它未知动作形式不因新增普通 D 支持而放行。
- 历史 D 只校验其冻结 S，不要求每个后 S 都等于当前 F，也不要求历史具体概念等于当前 F 概念。当前专属概念另按当前 F 核验，历史 S 保持不改。
- 新 task 特征组提供 F 归属；旧服务值 F 缺失可合法读回，但引用不存在服务值 F 的历史 S/D 属坏结构，不能补 0。
- 旧因果发生身份/计数及旧 Cg 范围沿用首叶合同；此次初始化不重放因果、不递增出现次数、不新增普通变化因果。

已知 task 代码自动改变状态，却尚未冻结对应动作定义和正式来源；1190 的未知动作不能代替已知自动执行动作。因此本叶只保留真实 S/D，暂不向因果 owner 交付普通无动作变化，不把它称为完整新增因果链。原带正式动作证据的 9→12 按现有能力继续交付。后续被动动作定义、发生身份及对应因果是具名缺口，不由本叶执行者临场创造。

## 7. 锁、所有权和依赖

任务状态只有 task 写；feature 独占 F 内容与历史聚合；state 独占 S；dynamic 独占 D；scene 独占场景挂接；world 仅组合和路由。不得在 world 用基础数据集写其它 owner 字段，也不得为本叶给 world 增加 state friend。

生产顺序为 task 锁→短时 feature/state/concept/scene 调用，各下层 owner 返回后才调用下一个。读取 task 的中立回调必须发生在 scene 等下层互斥锁外；scene 先读自身身份并释放锁，再回调 task，随后持锁复核自身身份。feature 凭据活着不等于 feature 锁仍持有；但占用期间不得添加新的 S→F 入边或其它 F 消费者。后 S 在完成并结束占用后才建立。无跨 owner 锁内调用 task 的新路径。

新增公开 ABI 只位于既有窄接口和对应实现，不新增文件或工程登记；scene 不 include task 实现；world 构造依赖不变。正式特征只读 DTO 是值式临时读回，不成为第二权威表、持久快照或长期材料缓存。

新增/修改的 `noexcept` 函数自行捕获其 owner 内工程异常，走现有日志、弹窗、终止函数，不依靠外层 catch 捕获越过 `noexcept` 的异常。task 的三项私有成员及生产特征组读取负责 task/feature 提交诊断；world 完成/读回/初始化负责组织及历史事实诊断；scene 两项治理挂接及私有 helper 负责场景归属/列表诊断。外层业务 wrapper 继续返回原有合法业务拒绝，但不能把内部工程故障再包装成资源不足、无变化或业务失败；内部已经执行工程终止时不返回 wrapper。已拒绝的非法公共请求不因此改成工程错误。
