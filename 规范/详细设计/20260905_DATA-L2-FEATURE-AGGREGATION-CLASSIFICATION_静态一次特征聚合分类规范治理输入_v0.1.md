# 静态一次特征聚合分类规范治理输入

日期：2026-09-05

身份：`DATA-L2-FEATURE-AGGREGATION-CLASSIFICATION`

版本：v0.1

状态：具名 DRIFT / 待正式规范治理 / 不可执行

## 1. 用户目标

用户要求特征类补全静态一次特征的聚合分类中间层，例如从大量具体轮廓材料形成“正面轮廓”“侧面轮廓”等类别。该层必须与二次特征分离；二次特征仍只承担行动方向型派生。特征类只负责数据结构和操作，实际分类算法、语义判定及类别是否成立由 `DATA` 之外的上层应用服务完成。

期望的数据操作输入包括：聚合分类结果节点或定义、来源成员关系、分类依据或算法见证的值式引用、当前 / 历史读回、成员添加 / 移除、分类退出或换代、幂等和来源追溯。

本文件只记录冲突和待治理结构，不修改正式规范、不冻结公开 ABI、不建立代码计划，也不授权代码实施。

## 2. 正式依据与当前事实

### 2.1 已成立边界

- 1120 冻结抽象特征由稳定特征定义身份、关系和值域承载，抽象特征不得承载实例当前值或运行期评估结果；定义内容变化必须保留版本和来源。
- 1130 冻结实例特征槽位、定义引用、唯一当前值事实及历史值来源；轮廓等大型材料由不可变材料身份承载，值事实只保存稳定引用。
- 4120 允许叶子、复合定义和定义视图，但复合组成子链只承载具名子特征槽位；判定规则、来源、统计和任务化不得塞入组成子链，来源应由关系、动态、因果样本或归纳记录追溯。
- 4150 把需求驱动的比较性、方向性、变化率和聚合性派生统一纳入二次至 n 次特征，并要求真实阶次、直接来源和派生规则可回查。
- 4180 允许形状距离这一算法族，但当前 v1 明确禁止在缺少不可变材料解析端口、形状材料和版本合同时建立当前有效注册。只凭引用编码、摘要、长度或字节数不得宣称轮廓比较或分类成立。
- 4230 冻结特征定义与特征实例两个 owner 范围。DATA-L2 只校验强类型结构，不解释轮廓或类别业务意义，也不得为“轮廓”等具体业务名称建立专用 CRUD。

### 2.2 当前新特征类复用裁决

当前 `数据服务.特征类` 已有普通特征节点 CRUD，以及派生定义的新增 / 查询 / 退出和 I64 比较注册。派生定义能力固定为：

- 恰两个直接来源特征定义；
- 结果实际阶次大于 1，阶次为来源最高阶次加一；
- 两个来源具有固定顺序和输入角色；
- 派生规则与当前 I64 比较注册共同写入；
- 只实现二元 I64 比较，不读取或解析轮廓不可变材料。

因此该能力只能复用 L1 owner 写端口、首次幂等材料、当前 / 历史关系和值读取、统一异常映射等机械基础，不能复用其“二源、阶次大于 1、I64 注册”合同表示本目标。把不定长样本聚合压成两条派生来源、把分类定义标成二次特征，或把引用编码比较冒充形状分类，都会改变用户目标或违反正式规范。

旧 `服务.L2*`、历史实现和旧 DTO 只能作差距证据，后继不得 import、调用、强转或复制其实现。

## 3. 具名冲突

现行 4150、4160 第 2—3 节明确规定：一阶特征只表达直接取得、测量、计数、引用或追溯的基础材料值；由多个事实、关系、评分规则或聚合推导的值不是一阶特征，“比较与聚合”进入二次特征。4230 同步冻结基础特征阶次为 1、派生特征阶次大于 1，且“二次特征”统一覆盖实际二次至 n 次派生。

用户本轮则明确要求“大量具体轮廓聚合分类”属于静态一次特征分类层，并明确否定二次特征身份。两者会直接改变结果定义的实际阶次、节点角色、来源结构和读取解释，不能靠函数命名或实现细节消解。

结论：`DATA-L2-FEATURE-AGGREGATION-CLASSIFICATION` 当前为正式机器语义 DRIFT。未经规范治理，不得登记为`可执行`或`待激活`，不得在特征类新增聚合分类公开 ABI，也不得以现有派生特征接口临时实现。

## 4. 推荐的待治理三层分账

### A. 静态特征类型归纳分类层

目标是表达“正面轮廓”“侧面轮廓”等稳定类别定义及其所属分类维度，而不是记录某次样本被判成哪一类。推荐把它治理为定义期的抽象特征归纳结构：

```text
分类维度 / 体系身份
+ 类别特征定义身份
+ 不定长归纳样本见证组
+ 归纳规则或算法身份及版本
+ 定义版本、来源和生命周期
```

该结构不得把来源、算法见证或统计写入 4120 的复合组成子链。若正式治理决定“类别定义仍属一次抽象特征”，必须明确：一次阶次描述类别实例所承载的直接材料类型；类别定义的归纳来源是定义形成证据，不参与 4230 的派生阶次公式。否则它按现行规范只能是派生特征。

分类维度 / 体系身份不可省略。没有该身份时，同一具体样本可能同时按朝向、形状、材质等不同维度分类，无法定义当前唯一性、重复、冲突或换代。

### B. 具体样本分类结果层

目标是表达“某个具体轮廓样本在某分类体系和规则版本下被判为某类别”。推荐与 A 分开记录：

```text
具体特征实例身份
+ 本次使用的不可变值事实身份或材料见证
+ 分类维度 / 体系身份
+ 类别特征定义身份及定义版本
+ 分类规则 / 算法身份与版本
+ 来源事实截止、适用范围和生命周期
```

绑定必须冻结本次实际使用的不可变值事实或不可变材料见证，不能只保存“实例当前值”指针后随值换代漂移。特征值换代后，旧分类只作历史；是否自动失效、需要重分类或允许继续作为历史证据必须由正式规范冻结。

B 是上层分类判定成功后的结构化记录，不是 DATA-L2 自己运行算法所得的结论。写前 DATA-L2 只验证引用、类型、owner、版本和同截止闭包；不得把引用存在、算法编码非零或来源数量达到阈值解释为分类正确。

### C. 行动方向型二次特征

现有二次特征的方向、差异、变化率和真实阶次链保持独立。A 的类别定义和 B 的分类记录不得复用 `特征类派生定义事实`、不得增加实际阶次、不得被 `二次特征类` 生成 / 计算 / 概念材料入口接受，除非未来正式规范明确某个后继业务从分类事实再次派生行动方向。

## 5. 正式治理必须先裁决的问题

1. 4150、4160 和 4230 是否新增“定义期归纳来源不决定实例材料实际阶次”的例外；若新增，1120 / 4120 的定义、组成、定义视图和归纳记录边界如何同步。
2. A 的分类维度 / 体系由现有抽象特征定义承载，还是需要新的值式角色结构；不得新增第三个特征节点族或新 owner。
3. A 的归纳成员究竟引用特征实例、特征值事实、不可变材料，还是由这些身份组成的完整样本见证；成员是否允许跨宿主、跨事实截止和重复材料。
4. B 是否属于特征实例的判断型值、状态 / 治理收束结果，还是特征 owner 内的归纳 / 分类见证；其节点族、owner、生命周期和对外读取必须唯一。
5. 同一分类体系下一个样本是否最多一个当前类别；类别定义之间是否互斥；多标签分类、层级类别和类别合并 / 拆分如何表达。
6. 添加 / 移除成员是修改同一分类定义、发布新定义版本，还是只换代归纳见证；不得原地改写历史来源关系。
7. 分类退出、类别替换、样本值换代、算法版本变化各自如何影响 A 与 B 的当前性和历史读回。
8. 算法见证最小合同至少应包含何种强类型身份、版本、输入角色、材料解析合同、结果种类和适用范围。4180 当前未开放形状距离，不能被本目标顺带启用。
9. 不定长来源的最大数量、排序、去重、分页 / 预算和发布后读回边界；空来源是否允许、最小样本数由谁裁决。
10. 当前 / 历史读取是按分类定义、分类体系、样本还是关系身份定位；完整历史时间线仍受 4230 的 L1 历史提供者边界限制，不得伪造。

## 6. 后续正式治理建议

由计划智能体按以下顺序承接新目标：

1. 先修订 1120、4120、4150、4160、4230，并在需要启用轮廓算法时另行修订 4180；不得只改详细设计绕过冲突。
2. 先冻结 A / B / C 的身份、owner、关系方向、阶次、版本和生命周期，再决定最小 DATA-L2 提供者叶。
3. 复用当前特征 owner 写端口和通用读写机制，但为分类合同建立独立、强类型 DTO；不得复用派生 / 二次特征 DTO 冒充。
4. 实际算法服务作为上层独立消费者 / 生产者设计；数据层计划只接受已经裁决的分类结果和完整见证，不实现轮廓识别、训练、相似度阈值或类别命名。
5. 规范目录、冲突断言和详细设计完成治理验证后，才允许形成并登记一份最早可执行代码计划。
