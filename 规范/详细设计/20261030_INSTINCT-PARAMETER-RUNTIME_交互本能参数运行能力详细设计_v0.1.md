## 1. 目标、修改对象与边界

本轮仅完善 `获取服务对象`、`建立连接` 两个本能函数及完成其参数交付必需的调用适配。两者实际改变的是现实认知场景中自我存在的“交互者”实例特征当前引用，不是任务虚拟存在 Vt 或方法虚拟存在 Vm 的特征值。原因是取得可用交互者/确认连接；目的分别是按正式人类与连接条件取得服务对象、以外设接收数量状态更新确认本次连接。动作发生在自我所在现实场景，自我不搬到外设场景。状态、变化动态继续由既有世界/特征服务根据实际写回自动形成，本能不直接修改它们。

函数唯一入口 `const 方法参数场景&` 不变。登记阶段可租用全局声明端口；非登记执行从场景取得操作提供者，不再从全局端口、TLS、固定真实自我或模拟/真实用途标志寻找运行材料。任务资格、来源和工程控制在场景提供者外层边界核验，不能简单删除保护，也不能把治理身份新增成 Vm 业务参数。

不改变四位/六位有序规格、已登记声明、所选分支、C/R、结果语义、人类匹配、交互者单引用结构、连接非零二次变化判据。既有“获取服务对象新需求”及其需求专属工厂不在范围。不开输出本能、独立单任务停止源、连接时效/重连、语言字段筹办、学习采样或新持久字段。

## 3. 不变的正常操作与必要条件

### 3.1 获取服务对象

四位依次仍为：现实场景、该场景自我、该场景目标存在、自我的交互者特征。正常分支仍要求自我/目标不同、目标正式人类匹配成立、已有正式已确认连接事实、特征归属于自我且定义正确。核心读取正式所选分支条件；不新增“确认类型”、隐藏条件或需求字段。

核心：读取必要条件与绑定环境→复核→采集真正使用的动作前条件→再复核→建立动作→按原世界公开函数写入交互者引用→重新读取目标特征和实际S/D→返回本次运行对。条件不足零动作返回原合法非成功；筹办由外层处理，本能不派生需求。动作后前提变化保留动作、返回部分/未知，不虚构未执行。

### 3.2 建立连接

六位仍为：现实场景、自我、对端、自我交互者特征、外设窗口、窗口接收数量特征。第五位绑定的世界场景是固定外设场景；第一位是自我所在现实场景，两者不能混用。

共享单步算法不变：第一次读最新接收数量状态只作基准；随后每步重读同一窗口/同一特征最新状态；同节点继续等；新节点必须来源一致、UTC时间严格前进，调用既有二次特征计算；差为0替换基准继续等，非0冻结本次关系发布许可；动作前fresh核验来源及必要材料→建动作→写交互者→读回S/D及连接事实引用。负向非零仍有效，不改为只接受增加。新状态身份不等于数量变化，不以历史已有消息直接确认本次连接。

最后许可点通过后，页面紧接着关闭不撤销已经核验的本次数量变化许可；仍须遵守既有调用停止及实际目标写入前提。不能在每个旧材料读取处重新加入“网页必须始终打开”的新硬门。

把 `开始内部`拆为私有“准备调用现场”和“调用注册入口”两个阶段；构造provider只建立/读回q和冻结绑定、来源，不执行本能、不回调注册函数。q身份：任务=X；直接=方法owner正式直接调用身份。服务保留调用表shared q及现有固定状态保护，不新增持久身份。

### 4.5 直调连接与模拟适配

公开 `开始/推进/取消/读取已确认连接事实/关闭` ABI与单步行为不变。开始：准备q及正式直接身份→构造单步provider→方法owner建立带provider场景→经`方法.调用本能函数`进入同一正式注册入口。推进重复相同顺序但复用q，不新建直接身份。provider等待返回false使函数本次交付暂停；旧接口不会突然无限阻塞。不能绕过正式注册函数直接调core。公开`推进(调用身份)`只接受`q.任务执行==false`；查到任务q时返回原`来源失效`且零推进/零动作，不允许把X伪装成direct身份或构造无控制的provider接管。任务q只经任务工厂与仍活动的原控制推进。取消仍在q锁下收束，不再增加TLS直接调用守卫；其原公开取消权限不扩大为执行权限。单步直接来源动作仍通过方法owner绑定/收束；不伪造task X。

必须删除旧`开始内部`（现场约777行）和`推进`（约851行）包住注册调用的外层`q.操作锁`：准备/取q仅短锁复制当前身份/绑定，方法建场景和`方法.调用本能函数`均在q锁外。业务推进、终态判断、收束统一由provider内部同一q锁完成；取消用同一锁，不增第二锁。注册调用结束后外层只短锁读回投影，不再把旧局部运行材料覆盖并发取消/终态。并发同一直调q的推进在provider内部串行，不锁住整个注册调用，避免新provider重复取得同一非递归锁自锁。

`业务/本能交互.执行核心.h/.cpp`新增：

```cpp
新本能函数本次条件结果对 执行参数连接核心(
    const 方法参数场景&, 新本能连接运行接口&);
std::shared_ptr<新本能连接运行接口> 建立隔离连接运行提供者(
    std::shared_ptr<新方法模拟运行接口>);
```

前者统一：`推进一次→终态返回→等待下一次推进→true继续/false交付当前待取得`。终态集合沿现有连接终态，不以“返回过一次”判成功。旧`执行隔离连接核心`退出，由本文件私有模拟适配持同一隔离owner shared_ptr及q，组合现有 `新方法隔离执行接口`、`推进模拟输入`和共享`推进连接核心`。同一参数场景重复进入复用provider/q及已消费动作；不重造q或动作。

`新_模拟世界类.h/.cpp`仅实现 `建立连接运行能力(shared_ptr<新方法模拟运行接口>)`：校验参数确为自身shared所有者及当前样例，委托上述工厂；非连接方法返回空，不改模拟字段/消息生成/取样算法。工厂与provider首次/后续推进均核对同一owner的样例M、全部绑定与执行分支；不能仅以裸this相等或场景用途为模拟归属依据。隔离owner已重置/取消/换样例则沿既有停止或前提变化，不回退现实服务。领域头不包含业务头；cpp包含既有核心公开头形成已存在的函数执行组合，不新增世界结构反向回调。模拟后端不获取任务控制/真实端口，输入耗尽只保持待取得，不造成功。样例取消由原隔离owner控制。

### 4.6 交互任务工厂与任务注入

新建 `业务/本能交互.任务参数工厂.h/.cpp`，一般代码/流程编排，不建立任何事实/算法。唯一公开类：

```cpp
class 交互本能任务参数工厂 final : public 新本能交互任务参数工厂 {
public:
    交互本能任务参数工厂(新_方法类&,
        std::shared_ptr<服务对象本能运行服务>,
        std::shared_ptr<连接本能运行服务>) noexcept;
    bool 支持任务方法(稳定编码) const noexcept override;
    新方法参数场景结果 建立任务参数场景(
        const 新本能交互任务参数请求&,
        const 新内部治理对象读取接口*,
        std::optional<新方法任务成员绑定>) override;
private:
    新_方法类& 方法_;
    std::shared_ptr<服务对象本能运行服务> 服务对象_;
    std::shared_ptr<连接本能运行服务> 连接_;
};
```

头只包含领域接口并前置声明所组合服务，cpp包含业务服务头。按正式登记方法/来源路由，两个服务同时声称支持同M是工程错误，不按首项选择。工厂核验控制适用于X、正式X的M/全部采用绑定/执行分支与请求完整相等，再创建对应运行能力，经`方法.建立参数场景`交付后核同场景M/全部绑定/分支及对应provider存在。每个provider的每次读取/动作/写回继续核同这些冻结身份和自己原服务/隔离owner；方法owner只做原规格/信息核验，不能声称凭sharedptr证明provider身份或资格。绑定、分支、M、任务成员不得改写。前提真实变化抛`新本能交互任务前提变化`；工程失败向上送出，不当“材料待齐”。不复制读取/动作/写回算法，不使用需求专属工厂。

`新_任务类.h/.cpp`新增：

```cpp
bool 配置本能交互任务参数工厂(新本能交互任务参数工厂&) noexcept;
bool 卸载本能交互任务参数工厂(新本能交互任务参数工厂&) noexcept;
// 私有非拥有成员；应用覆盖全部worker并在join后解除。
新本能交互任务参数工厂* 本能交互任务参数工厂_ = nullptr;
bool 本能交互任务参数工厂已解除_ = false;
```

配置/卸载只在任务互斥内修改上述工程绑定，不调用跨owner。返回合同固定：未配置且未解除时配置同意并返回true；同一已配置对象重复配置true且不变；异owner配置false且不替换；首次精确owner卸载清空指针、置已解除并true；空槽或异owner卸载false且不变；已解除代表本任务服务生命周期的关闭中/已关闭，后续配置一律false，不恢复旧工厂。该bool仅防止join后重入绑定，不是业务任务状态/持久字段。普通应用将配置false解释为既有装配失败，join后精确卸载false是工程所有权错误。初始化失败若尚未绑定，只销毁该app自有未绑定工厂/关闭自有服务；已绑定则按精确owner卸载，不尝试替换别人的工厂。工厂正常使用前服务未就绪/已关闭属于外层停止或明确依赖错误，不返回“方法不支持”伪空候选；目标方法无工厂由下一段工程边界拒绝。

任务W3边界在X发布后、旧需求工厂块旁独立处理本轮方法：锁内取工厂指针后释放任务锁；捕获worker现有停止token→新建active-X控制及RAII→交互工厂建场景→核同M/绑定/分支及对应provider。需求工厂及新工厂不得同时声称支持同M。工厂尚未配置而正式注册名是这两个目标方法时是装配工程错误，不能静默使用旧场景。

沿用现有来源语义fresh复核与`复核执行本能输入`。本轮两个方法实际调用不再进入旧TLS `本能执行守卫`，由同X显式控制保护；其它方法保持原守卫。`方法.调用本能函数`返回后立即`结束调用`再进入结果处理；调用未进入、前提变化及所有合法提前返回由同一局部RAII关闭控制。创建工厂前提变化须正式读回零动作后才允许原`恢复零动作`路径；已形成动作禁止恢复为未执行。调用返回后的任务结果记录、影响评估和self治理完全不改。

## 6. 并发、引用、重入与故障

1. active-X集合互斥仅登记/消费/释放工程能力，不持锁调用任何领域/世界服务；控制局部互斥与活动集合锁不嵌套。结束先关闭控制，待本次边界无在途操作后移除X；不允许同一控制结束与消费跨调用竞态。
2. 服务互斥只做配置/短票计数/关闭标志/q查找；释放后进入q锁。q锁保护同调用推进/取消/收束；等待必须释放q锁。领域公开函数各自取得其原锁，不把领域锁传入provider，不进行共享锁升级。现有单步q串行顺序保留，不能新增q→服务→q环。
3. provider存续保证服务及q的C++寿命，不等于取得永久业务资格。每次推进及临近动作fresh核验；过期场景/控制只能返回前提变化或停止，不能再次发布。
4. 基准/更新状态仍经状态owner增加引用后读回，检查内容与外设场景归属；新增保护失败撤销增加。替换基准及时释放旧引用。成功q保留恰需两状态至连接表关闭；失败/取消释放。provider析构不删除成功连接证据，active-X释放不等待q销毁。
5. 场景→provider→服务/q；服务→q；q不回指场景/provider，服务不缓存provider。直接身份和样例身份依既有owner合法收束，不从地址/时间/随机数造业务编码。
6. 同一q重复推进返回当前事实/继续未完成过程，不再建主动作；终态返回原运行材料。并发重复同X由共享活动集合工程拒绝；并发同q由q锁串行。新任务X只能经原task owner建立，本计划不定义自动重试。
7. 有停止且未动作：原零动作拒绝/未取得；已动作：原部分/未知；成功事实不撤销。关闭开始后拒绝新入口，已进入短操作完成或按原前提变化收束，最长50ms轮询观察关闭；关闭等待入口归零后统一释放q状态，再释放服务。
8. 工程异常唯一责任边界：本能函数catch与各正式服务noexcept边界本地诊断并终止；内部helper/工厂向上送出；纯getter、简单构造/析构（不变量成立时）无适用错误分支。不得异常转false、空材料、子需求、学习反例。动作已发布后出错不补造结果、不自动重做动作。
