# INSTINCT-STAGE3-PASSIVE-MAINTENANCE-BATCH-KERNEL 多完整秒被动维护批量内核详细设计 v0.1

日期：2026-08-31

## 1. 目标与完成边界

本切片把 6170 已冻结的“任意长待维护区间必须与按时间顺序逐秒执行等价、但不得使用无界逐秒循环”实现为现有本能被动维护纯算法模块的批量入口。

```text
完成 = 有限规范事实段输入
    + 服务衰减地板和 / 门禁跳跃
    + 服务比例边界跳跃
    + 生存安全根回归的有界收敛
    + 规范审计段输出
    + 与现有单秒内核的逐秒参考等价验证
```

本切片不读取或写入事实，不读取时钟，不发布服务合同终态或准备补回，不形成历史事实分段，不推进维护游标，不调用 L1 v3，不发布 A/V、状态或动态，也不接普通应用和线程。完成只证明“材料已经按事实边界闭合时，可以在与时间跨度无关的有界算法内算出批量候选”；不证明阶段三维护事务或生产闭环完成。

当前生产参数保持：

```text
值域 = 0..INT64_MAX
L = 2,767,011,611,056,432,742
H = 7,378,697,629,483,820,645
安全根定义版本 = 1
主动安全结算规则版本 = 1
被动服务维护规则版本 = 1
```

“阈值可浮动”只表示后继可以发布新的安全根定义版本；本批量内核消费请求中已经正式读回的整数阈值和版本，禁止按百分比、`UINT64_MAX`、启动参数或当前时间重新计算第二权威。

## 2. 当前事实与切片裁决

当前已经发布：

- `计算本能单完整秒被动维护候选_v1`：一个完整秒的 V 衰减、服务比例和 A 回归纯值规则；
- 基础快照：能够给出 `(上一已维护完整秒边界, 当前完整秒边界]`；
- 当前维护秒服务需求时间裁决：只证明当前观察边界这一秒，不证明历史逐秒集合；
- 服务合同、进展、准备、到期事件、T→D、主动安全来源和变化账的当前正式读回；
- v2 双水位维护游标；
- DATA-L1 有限 N 分区原子事务 v3。

直接把单秒内核循环 `N` 次存在两个错误：

1. `N` 可覆盖任意 I64 时间跨度，形成无界逐秒循环；
2. 当前秒 provider 不能替代区间内合同终态、准备补回、活动变化和到期事件的历史事实分段。

直接调用两次现有单特征发布再更新游标也不成立，因为这会形成公开可见的 A/V/游标半结构。

因此最早独立代码叶固定为纯批量内核。紧邻后继才负责：

```text
同 G0 历史事实完整读回
-> 在合同结算 / 准备补回等外部值变化边界切分被动区间
-> 对每个无外部 A/V 调整的区间形成规范有限事实段并调用本批量内核
-> 用 L1 v3 把特征 / 状态 / 动态 / 游标共同原子发布
```

## 4. 合同与类型

### 4.1 版本和固定算法边界

新增：

```cpp
inline constexpr std::uint32_t 本能多完整秒被动维护合同版本_v1 = 1;
inline constexpr std::uint32_t 本能批量跳跃等价证明版本_v1 = 1;
inline constexpr std::uint32_t 本能批量单比例安全收敛最大步数_v1 = 10'000;
inline constexpr std::size_t 本能批量最大输入事实段数_v1 = 65'535;
```

`10'000` 是算法内部固定安全上界，不是业务时间或线程循环次数。对 `0..INT64_MAX` 距离，低位和高位递推在距离 `>=100` 时每步至少减少 `floor(距离/100)`，距离 `<100` 时每步至少减少 1，因此在该固定上界内必然到达 L/H；超出只能返回内部错误，不得继续无界循环。

### 4.2 事实段来源形态

```cpp
enum class 本能批量维护需求来源形态_v1 : std::uint8_t {
    无有效未满足且无到期事件 = 1,
    最长未满足合同 = 2,
    同秒到期未满足事件 = 3
};
```

### 4.3 输入事实段

```cpp
struct 本能被动维护有限事实段_v1 final {
    稳定编码 事实分段键;
    std::int64_t 起始完整秒边界;
    std::int64_t 结束完整秒边界;
    本能批量维护需求来源形态_v1 需求来源形态;
    std::optional<std::int64_t> 最长需求提出完整秒边界;
    std::uint64_t 同秒到期未满足事件数量;
    服务活动裁决_v1 活动裁决;
    同秒主动安全裁决_v1 主动安全裁决;
    安全低位回升门禁_v1 低位回升门禁材料;
};
```

形状规则：

- 起止边界均非负，且 `起始<=结束`；
- `无有效未满足且无到期事件`：最长提出秒为空、到期数为 0；
- `最长未满足合同`：最长提出秒存在且不晚于起始边界、到期数为 0；算法按每个逻辑秒的 `t=当前秒-提出秒` 自动跨越 30 天门禁；
- `同秒到期未满足事件`：最长提出秒为空、到期数大于 0，且该事实段必须恰为 1 秒；
- 当前合同 v1 只接受 `主动安全裁决=未改变A`；当前生产来源规则版本 1 的变化账非空时上游继续 fail-closed，未来主动安全变化的事实秒归属与后值重放必须升级合同，不能在本入口猜测；
- `低位回升门禁材料`只接受`允许/禁止/材料不足`，表示该事实段内同一安全门禁材料。算法仅在逐秒实际进入 `V>0 && 0<A<L` 时把它传给单秒规则；其它分支派生为`不适用`，不得要求上游按 A 的派生边界预切事实段；
- 分段键非零、全组唯一。相邻且全部业务字段相同的段必须合并；需要在事实发生秒、合同终态、准备结果、活动状态、主动安全结果或门禁变化处切段。

本入口只覆盖没有合同预支 / 余款、准备补回、主动安全结算或其它外部 A/V 调整的最大被动区间。后继 composer 必须在这些有限事实边界先形成外部变化候选，再以变化后的 A/V 作为下一被动区间前值调用本入口；所有区间和外部变化最终仍在同一维护事务中提交。禁止把多次纯算法调用误解为多次事实发布。

审计段按时间严格升序、连续覆盖请求区间。事实段切换、服务需求分支、30 天门禁、活动保护、服务比例、A 分支、L/H/0/1 边界或 V 饱和边界变化时必须切段；不得跨不同语义合并。段内允许 A/V 逐秒变化，但必须由同一公式、同一比例和同一门禁决定，且保存前后值、请求减少饱和值、是否已经超过 `INT64_MAX` 的饱和标志、保护下界和实际变化。`事实分段键`只是不透明但稳定的完整来源材料引用，批量内核不解释或补造来源；后继持久审计仍须保存该键对应的强类型合同 / 活动 / 事件完整来源组。

## 5. 目标函数与确定性算法

```cpp
本能多完整秒被动维护结果_v1 计算本能多完整秒被动维护候选_v1(
    const 本能多完整秒被动维护请求_v1& 请求) noexcept;
```

算法固定为：

1. 验证版本、值域、阈值、边界、预算、主动安全规则版本 1 空覆盖形状和完整规范事实段覆盖；
2. 对每个事实段按下列最近边界切出算法子段：事实段结束、`t=T`、V 到达 0/1、服务比例改变、A 到达 0/1/L/H；
3. 无需求段的累计衰减使用 `N` 的饱和减法；最长未满足段使用与逐秒 `D0+floor(D0*t/T)` 完全相同的确定性地板和；到期事件段直接执行 30 天门禁；
4. 地板和只计算到“足以使 V 到达本子段保护下界”的饱和值，使用检查加法、欧几里得地板和或等价的最多 63 次二分；禁止逐秒求和；
5. V 每秒更新后再计算 P。算法只在最多 99 个服务比例区间切换，禁止按完整秒数量循环；
6. 对固定 P 和固定 A 分支，使用单秒递推的同一公式推进。未到 L/H 时最多执行固定 `10'000` 次安全收敛步骤；到达 L/H/0/1 后直接跳过该子段剩余秒；
7. 每个算法子段的第一秒和最后一秒都必须可用现有单秒函数复算，输出前后值、分支和规则版本一致；
8. 输出规范审计段；相邻段只有在全部语义字段相同且合并后仍不跨强制边界时才可合并；
9. 若所需审计段超过请求预算，返回`输出预算不足`且无载荷；若任一低位回升实际适用而门禁材料为`材料不足`，返回`材料不足`且无载荷；
10. 任何溢出风险、非法乘除或无法证明等价的边界返回`算术拒绝/内部错误`，不得退回逐秒无界循环。

实现复杂度必须只依赖：

```text
输入事实段数
+ 每段最多 99 个服务比例边界
+ 每比例最多 10,000 个安全收敛步骤
+ 每跳跃最多 63 次边界二分
```

不得依赖待维护完整秒总数。

## 6. 非成功与后继边界

- 入口、版本、分段、预算、材料、算术和内部错误严格分账；
- 本函数不产生`已可能发布`，因为没有持久副作用；
- 当前生产来源规则版本 1 下，主动安全变化账非空时上游必须在调用前返回来源未裁定，本函数不得把非空变化解释为普通被动秒；
- 准备补回、合同预支 / 余款和同秒终态必须由后继完整材料 provider 形成事实边界及正式变化候选；composer 以调整后的 A/V 启动下一最大被动区间，本函数不从审计段倒推出这些事实；
- 后继原子事务只能消费本函数成功载荷，仍须独立互证 G0、事实段完整性、当前 A/V、规则版本和游标双水位。

## 7. 验证矩阵

专项至少覆盖：

1. `N=0/1/多秒`，空段、缺口、重叠、乱序、重复键、可合并未合并；
2. V=`0/1/M`，无需求、最长未满足、跨 `t=T`、同秒到期事件、活动保护与解除；
3. P 的 0、1、2、98、99 及全部比例边界；
4. A=`0/1/L-1/L/H/H+1/M`，低位允许/禁止/材料不足、闭区间、高位回落；
5. 事实段边界、30 天边界、V 0/1、A L/H 与比例边界同秒重合；
6. 输出预算恰好、少 1、超预算零载荷；
7. 当前固定 L/H 与定义 / 规则版本 1；错误版本和请求阈值异义拒绝；
8. 对大量确定性短区间和随机短区间，逐秒调用现有单秒内核，逐项比较最终 A/V、每秒分支和批量审计段投影；
9. `N` 接近 I64 边界的无需求、持续需求和饱和场景，证明运行次数受固定算法边界约束而非 N；
10. Debug / Release 根工程 Rebuild、Debug / Release 专项、Debug / Release 外部 ABI consumer、`git diff --check`、`check_specs.py --strict`。
