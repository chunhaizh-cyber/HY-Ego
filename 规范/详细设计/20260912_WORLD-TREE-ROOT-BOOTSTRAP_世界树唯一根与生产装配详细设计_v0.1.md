# WORLD-TREE-ROOT-BOOTSTRAP 世界树唯一根与生产装配详细设计

日期：20260912
版本：v0.2
设计基线：`0076cbec0e64b16473bbd7b0159748b90e042409`

## 1. 目标与边界

本设计交付最早可独立运行的世界树代码叶：在空L1运行包中由生产合同原子建立唯一世界根场景，把正式读回的根身份发布到模块级受保护全局变量；世界树应用不再从构造参数接受任意根；场景和存在使用同一层级位置读回；既有创建、移动入口继续复用场景/存在公开能力；普通应用完成最小生产装配并在根读回成功后按8120停在`真实自我形成=17`。

本叶不实施特征三类父迁移，不修改概念树旧四根物理结构，不重构因果链，不生成自我、概念、需求、任务或治理动作。规范中的C046只作为后继合同。

## 2. 当前事实与复用裁决

v0.1计划（plan blob `2c39d3f060973c9d5660e71ab894258c4fd4b574`）在上述HEAD进入执行后发现两项设计漂移：父场景语境v4没有冻结结构交付、固定键、读回载荷和旧v3拒绝状态；候选`装配.普通应用.ixx`在同一模块单元承载完整五owner准备与全部服务构造时，MSVC 14.50于文件结束处稳定C1001。非导出上下文、private fragment、关闭JMC、同文件分阶段函数和raw pointer均未改变失败，删到只完成特征服务时Debug成功，根相关其余模块Debug为0错误。v0.2只补齐这两项原目标内合同，不接纳当前未提交候选为正式实现。

- `应用服务.世界树类.ixx`已有根验证、存在位置、场景/存在移动、场景/存在绑定创建六个入口，但构造函数接收调用方`稳定编码 root`，根是每实例字段；存在位置通过全树扫描只识别直接场景成员。
- `场景类数据服务::启用并建立场景树根`要求调用方先提供一个已存在E；生产没有建立无父根E的合法入口。验证代码用端口手工预置E，只是夹具。
- `绑定存在数据服务`已证明存在owner与场景owner可通过`提交有限N分区原子事务_v3`共同发布；其三种普通绑定合同保持不变，可复用参与者准备/读回模式，不能把无绑定根塞入普通创建枚举。
- `直接归属联合只读组合器`已经统一读取场景成员、父存在组成和直接子场景三类结构父；统一位置读取应复用它并沿唯一父链有界上行。
- `启动.应用程序.ixx::运行普通程序`当前直接返回`普通应用装配`失败；`装配.普通应用.ixx`不存在。当前知识用途卡已落后，不能当作实现。
- L1、特征、存在、状态、场景服务的当前构造方式可从现行构造函数和绑定专项夹具复用；生产装配必须在自己的私有初始化函数中完整校验元结构，不能调用验证工具。

## 3. 权威事实与全局变量

L1中以下事实共同构成世界根权威：根E的存在族身份、同码场景角色、四个实例组织锚及绑定、世界根标记、树归属证明、无联合结构父。根的首次建立由存在owner和场景owner一个v3有限N分区原子事务发布。

`应用服务.世界树类.ixx`模块内部新增进程级变量：

```cpp
std::mutex 世界树根节点锁;
struct 世界树全局根绑定 { const L1事实基座服务* 底座; 世界树全局根投影 投影; };
std::optional<世界树全局根绑定> 世界树根节点;
```

变量不export，不允许引用、写端口或发布函数逃逸。模块只公开值式读取：

```cpp
世界树全局根读取结果 读取世界树根节点() noexcept;
```

调用方不能提交根投影。`世界树应用服务`构造函数为私有，由公开工厂`建立世界树应用服务(场景类数据服务&,存在类数据服务&,世界树根验证请求)`创建。工厂先证明两个服务绑定同一L1，再经场景服务读取当前根闭集：必须恰有一个当前根；随后以该根读取完整场景树并经联合父证明根无父。只有三项在同一G0完整成功，模块内部私有`绑定已验证世界根`才可写全局变量并构造服务。

首次完整读回绑定成功；相同L1服务实例地址、根编码和首次H重复为精确重复；异L1或异根为`全局根冲突`，失败不替换，生产无reset。公开全局投影只保存`根编码、首次H、最近验证G`；L1服务地址只在模块内部绑定中用于防止不同运行包混用，不进入DTO、持久事实或人读身份。该变量是已读回权威的进程引用，不是第二根事实。每个世界树业务请求仍在请求G0重新调用场景/联合父读回验证根。

## 4. 根专用DATA合同

新增模块：

- `领域/合同.世界树根.ixx`：DTO、参与者接口、稳定状态和成功谓词。
- `领域/数据服务.世界树根.ixx`：两owner协调器，不拥有第三写端口。

公开请求：

```cpp
struct 世界树根初始化请求 {
  uint32_t 版本=1; uint64_t G0=0;
  L1所有者范围写入幂等身份 组合幂等身份,存在幂等身份,场景幂等身份;
  uint64_t 最大关系数量=0,最大场景数量=0;
};
```

结果状态固定包括：`已建立、精确重复、入口拒绝、已有不同根、事实代次漂移、幂等冲突、引用冲突、数量预算不足、历史材料已清理、资源失败、内部不一致、已可能发布`。成功载荷包含原请求、根E、首次H、Gread和完整`场景树节点当前事实`；成功谓词还要求无联合父、根标记、四根完整且当前、树只含该根。

`存在类数据服务`实现根参与者：准备根E节点和存在族归属边、读取首次材料和根E来源见证。`场景类数据服务`实现根参与者：在同一新E上准备场景登记边、四根/四绑定、根标记和树归属；预读当前根组，零根才能首次建立，同一原键重放才能重复，任何其它当前根返回`已有不同根`。两者均只返回自己owner的v3参与者写集，不导出端口。

协调器顺序：校验请求和预算 -> 读取组合首次账 -> 读当前根组与G -> 零根时取得两参与者片段 -> 同一G提交v3原子事务 -> 逐owner读首次材料 -> 以提交后G读取根场景树与联合父 -> 返回。提交前非成功零公开变化；提交后无法读回返回`已可能发布`并保留原请求/首次H，只允许原键原请求重放。

## 5. 场景父语境与统一层级位置

`场景角色组织合同版本`和既有只读/组织结果版本保持2；普通启用与普通退出请求升为版本4。`场景角色数据状态`使用现有空位固定增加`旧版本迁移拒绝 = 19`：只表示命中旧v3启退请求、旧v3首次账或六节点场景登记首次账，当前入口必须零写并走具名迁移。其它错误版本仍返回`入口拒绝`；禁止把旧材料补写、自动迁移或双读择一。

`父场景语境`是场景owner拥有的非结构投影关系，归入`场景角色结构交付`：

```cpp
struct 场景角色结构交付 final {
  状态使用绑定结构交付 绑定结构;
  稳定编码 根绑定关系类型,状态组织关系类型,动态组织关系类型,
      父场景语境关系类型;
};
```

场景结构登记仍为版本2并固定使用场景owner保留幂等身份`{1}`。首次规范化写集只含七个普通无属性节点，本地键1..7依次为场景族锚点、场景族归属关系类型、状态使用绑定成员关系类型、根绑定关系类型、状态组织关系类型、动态组织关系类型、父场景语境关系类型；首次映射、交付和真实节点owner/形状必须逐项相等。键1已有六节点旧材料时返回`旧版本迁移拒绝`，不得拼入第七节点或另键登记第二套结构。构造函数只接受完整七项交付。

最终启退ABI固定为：

```cpp
struct 场景角色启用请求 final {
  std::uint32_t 版本=4; std::uint64_t G0=0;
  L1所有者范围写入幂等身份 幂等身份;
  稳定编码 对象存在,父场景语境,预期结构父关系;
  std::uint64_t 最大关系数量=0,最大祖先数量=0;
};
struct 场景角色退出请求 final {
  std::uint32_t 版本=4; std::uint64_t G0=0;
  L1所有者范围写入幂等身份 幂等身份;
  稳定编码 场景,父场景语境,预期结构父关系;
  std::uint64_t 最大关系数量=0;
};
```

`预期结构父关系`的精确C++类型是`稳定编码`，值必须等于G0联合父读回`直接归属联合事实::关系`，不是关系类型、父节点或本地键。服务还必须核验该完整联合父的父、成员、来源和生命周期。直接场景成员或直接子场景的父语境等于结构父场景；存在组成的父语境等于父存在，且该父存在当前已启用同节点场景角色；根不走普通入口。

父语境值式读回合同固定为：

```cpp
struct 场景父语境投影事实 final {
  std::uint64_t Gread=0,H=0;
  稳定编码 场景,父场景语境;
  直接归属联合事实 结构父;
  场景组织边见证 投影边;
};
struct 场景父语境读取请求 final {
  std::uint32_t 版本=1; std::uint64_t G0=0;
  稳定编码 场景; std::uint64_t 最大关系数量=0;
};
struct 场景父语境读取结果 final {
  std::uint32_t 版本=1;
  场景角色数据状态 状态=场景角色数据状态::入口拒绝;
  std::uint64_t Gread=0;
  std::optional<场景父语境投影事实> 投影;
  bool 成功(const 场景父语境读取请求&) const noexcept;
};
```

`场景类数据服务::读取当前父场景语境`加入场景只读provider。它只按交付中的父语境类型有界读取，不加入联合父组合器。成功要求唯一当前投影边为`场景 -> 父场景语境`、角色1、场景owner，且载荷中的完整结构父与同G0联合父逐字段一致。

普通已有E的`启用场景角色`最终返回`场景角色写结果`，不再借用会暗示新增包含关系的`场景树角色写结果`。该结果保持版本2，字段固定为`状态、Gread、首次发布代次、角色、optional<直接归属联合事实> 结构父、optional<场景父语境投影事实> 父语境投影`，并同时提供v4启用/退出成功谓词。直接子场景出生仍返回`场景树角色写结果`，该结果只新增`optional<场景父语境投影事实> 父语境投影`。非根v4启用、直接子场景出生及精确重复必须有投影；v4退出成功返回H时有效且退出代次为退出G1的历史投影；世界根成功必须为空。非成功时角色、结构父和投影载荷为空，只有`已可能发布`可保留首次代次。

已有E启用首次写集的固定本地键为：1登记边，2..5四根节点，6..9四根绑定，10树归属证明，11父语境投影；键11固定为`C -> 父场景语境`、父语境关系类型、角色1，不含对象结构父写入。v4退出写集不含节点和新增关系，退出事实按稳定编码升序精确包含四根、四绑定、树归属证明和父语境投影共十项；登记边和原结构父保留。重放从原首次账恢复键11及十项退出集合，比较C、父语境、预期结构父关系及当前联合父；预算不参与幂等同义比较。

直接子场景出生与已有E启用必须走不同分支。`绑定存在场景参与者::准备场景绑定片段`的直接子场景片段固定为节点键1..4四根，关系键5登记边、6..9四根绑定、10树归属证明、11直接子场景结构边、12父语境投影。键11是`父场景 -> 新C`，键12是`新C -> 父场景`；两者同H发布。出生结果同时回显新直接包含、完整联合父和父语境投影。已有E启用只形成上一段键1..11并保留既有成员/组成/子场景结构父，严禁新增直接子场景边。

世界树应用合同升为v3，并新增统一层级请求/位置/结果：

```cpp
enum class 世界树节点视角 : std::uint8_t { 世界根场景=1, 场景=2, 存在=3 };
struct 世界树层级位置读取请求 final {
  std::uint32_t 版本=3; std::uint64_t G0=0; 稳定编码 节点;
  世界树节点视角 预期视角; 世界树读取预算 预算;
};
struct 世界树层级位置 final {
  稳定编码 节点,世界根; 世界树节点视角 视角;
  std::optional<直接归属联合事实> 直接结构父;
  std::optional<场景父语境投影事实> 父场景语境;
  std::vector<直接归属联合事实> 上行路径;

世界树层级位置结果 读取世界树层级位置(
    const 世界树层级位置读取请求&) const noexcept;
```

根的两个optional和路径均为空。普通节点先验证全局根，再沿唯一联合父有界上行；场景视角额外调用父语境入口并要求其结构父与位置直接结构父逐字段相等。断链返回对应不在现实树，双父、环或投影冲突返回内部不一致。原存在位置入口只作统一入口的兼容包装，不再扫描全树。

`世界树应用服务`构造函数改为私有`(场景类数据服务&,存在类数据服务&,已验证世界根令牌)`；只有工厂能形成令牌。服务每次从受保护读取函数取根，已有创建、移动和验证入口只替换根来源，不改变DTO业务含义。

## 6. 最小普通应用生产装配

`海中鱼巣/装配.普通应用.ixx`只作为主接口单元：全局模块片段只包含公开DTO所需`<cstdint>`，导出`普通应用装配状态`、`普通应用装配结果`和`构造普通应用上下文() noexcept`声明；禁止在接口单元import L1、特征、存在、状态、场景、世界树根或世界树应用，禁止定义owner、服务对象和函数体。

新增`海中鱼巣/装配.普通应用.cppcpp`作为同名模块实现单元，首个模块声明固定为`module 海中鱼巣.装配.普通应用;`，随后import根数据服务、世界树应用服务及其真实构造所需模块。五owner准备、元节点完整读回、服务生命周期对象和`构造普通应用上下文()`定义全部放在该实现单元；它不export任何符号，工程以普通`ClCompile`登记一次并依赖主接口IFC。该拆分保留完整五owner构造，只把实现从需要生成公开IFC的主接口单元移出；owner、幂等键、事务、公开ABI和机器事实不变。

实现单元中的`普通应用上下文`按声明顺序持有L1运行包、五个owner交付、特征值/特征/存在/状态/场景服务、根数据服务和世界树应用服务，使用`unique_ptr`确保逆序析构。元节点形状为特征定义16项、特征信息5项、存在3项、状态8项；场景基础登记v2七项及特征组织、直接包含扩展继续由场景类公开静态入口形成。每次元节点提交必须按首次账、映射、类型、owner和属性表示完整读回。禁止用关闭JMC/优化、raw pointer泄漏、删服务、返回桩或跳过读回规避C1001。若该实现单元在全新IFC/OBJ下仍复现同一EOF C1001，执行只回传精确编译证据，不再自行拆分或扩大白名单。

上下文形成后以固定项目根幂等键调用`世界树根数据服务::初始化世界树根`；成功后不直接发布全局变量，而是调用`建立世界树应用服务`。工厂独立读取当前根闭集恰一、完整场景树和根无联合父后，在模块内部绑定全局根并返回服务；普通装配再调用`验证现实世界根`。`运行普通程序`消费该结果：装配失败返回阶段2；根失败返回阶段14；根成功后当前无真实自我形成提供者，返回`初始化失败/真实自我形成=17`。不越过阶段17，不建立旧四本体根。

`程序失败阶段`将数值18名称改为`概念依附结构初始化`，保留旧数值不复用；数值14和17不变。

## 7. 并发、生命周期与失败

根协调器不在持自身锁时调用外部provider或L1。参与者先读材料，最终由L1 G0串行化；同G并发只有一个成功，另一方漂移或原键重复。全局根锁只保护短值拷贝，不包住领域读写。服务和全局投影在进程生命周期内不reset；测试每进程一个用例。

所有`bad_alloc/length_error`映射资源失败，其它异常映射内部不一致。任何已确认发布后的异常均返回已可能发布。诊断文本不改变状态。

## 8. 验证矩阵

1. 空L1首次初始化：一个根E、一个场景角色、四个实例锚、无父；工厂从当前根闭集恰一、完整树和联合父为空独立绑定全局根，世界验证成功。
2. 原键重复：零新增事实、同根同H、全局发布精确重复。
3. 不同键第二根：已有不同根、零写、全局不替换。
4. 同G并发：恰一首次成功，另一方可按原请求收敛；最终一根。
5. 故障/发布未知：提交前失败零写；提交后读回失败只原键重放。
6. 层级：根、直接子场景、场景成员、父存在组成链均读到同一根和唯一结构父；预算不足、断链、环、双父精确失败。
7. 新场景与双视角分账：普通新场景同一场景owner片段含直接子场景结构边和父语境投影；已有成员/组成E启用场景视角后结构父编码不变且没有新增子场景边，父语境正确；退出后结构父仍在。
8. 回归：现有绑定创建、场景/存在创建和两类移动结果保持。
9. 普通入口：根DATA成功后只能经工厂内部绑定全局根；不存在可调用发布函数。真实独立读回后稳定停在阶段17，不再停在阶段2或14。
10. 旧材料：v3启用/退出请求、其旧首次账以及六节点场景登记首次账均命中`旧版本迁移拒绝`且零写；其它错误版本仍为入口拒绝。
11. 物理拆分：主接口单元只导出DTO/声明，同名`.cppcpp`实现单元承载装配定义；MSVC 14.50/v145用全新IntDir/OutDir及`/m:1`重建，原接口单元EOF C1001归零。
