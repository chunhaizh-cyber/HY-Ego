# DATA-L2 四本体根结构新增与当前读取详细设计

身份：`DATA-L2-CONCEPT-ONTOLOGY-ROOT-STRUCTURE-CREATE-READ`

版本：v0.1

日期：2026-08-15

状态：设计就绪；只有计划索引正式登记为 `可执行` 后方可施工

## 1. 目标与完成边界

在新的唯一 `L2概念结构服务` 和独占概念 owner 内，建立存在、特征、动态、因果链四种语言无关概念本体根的强类型结构新增与当前读取能力。

本叶完成后，DATA-L2 能够：

```text
建立一个具名角色的永久本体根
+ 按角色读取当前本体根
+ 原子读取全部当前本体根
+ 从正式事实回显首次请求见证
+ 从正式直接上位关系类型证明根的直接上位组为空
```

本叶不是普通概念 CRUD，也不是完整概念空间。四个根不可修改、替换或退出，所以本叶只公开新增和当前读取，不伪造无意义的“改 / 删”入口。后继普通概念、上下位 DAG、定义、世界事实支持、概念名称、语言 / 词条、DATA-L3 概念空间聚合、普通应用装配和 BIZ 阶段 18 均不在本叶；语素和词性按现行规范不形成持久节点族。

三类结果分别保留前述 `bool 成功() const noexcept` 成员。建立和单根读取 helper 只接受合同版本 1、非零 `期望事实代次` 和闭合角色；建立请求另要求幂等身份非零。全组读取 helper 接受零或非零期望代次。两项内部登记保留值不进入公开数据头，也不扩大公共 helper 的可见合同；服务公开入口在调用公共 helper 后，再由模块私有 `是概念保留登记幂等身份` 拒绝这两值并返回 `入口拒绝`。

完整根必须满足：

```text
根概念非零
+ 身份来源完整、节点族=概念、节点编码=根概念
+ 根角色有效、根概念相同、关系编码非零
+ 身份来源五份生命周期均不晚于结果截止且全部没有退出
+ 根角色关系创建代次不晚于结果截止且没有退出
+ 首次幂等身份非零
+ 首次期望事实代次非零且严格早于根角色关系创建代次
+ 直接上位概念为空
```

`L2概念本体根角色事实完整` 只验证闭合角色、非零且一致的根 / 关系编码，以及根角色关系在截止内已创建且未退出；`L2概念本体根事实完整` 再验证身份来源、首次见证和直接上位空组。关系目标是否为精确角色锚点、族归属方向、属性类型和 owner 一致性仍由服务从 L1 正式投影逐字段证明，纯值 helper 不猜内部定位。

`L2概念所有者交付` 照现行七族交付形态保持 move-only、私有持有 `L1所有者范围写端口`、只能由形成函数和服务构造消费；服务只保存 `const L1事实基座服务&` 与唯一概念写端口。它不依赖不可变材料、语言、六类世界结构、BIZ、普通应用或 DATA-L3 聚合。

`尝试形成L2概念所有者交付` 只接受建立身份精确等于 `概念所有者建立身份`、状态为成功 / 精确重复且结果形状完整、owner 为未退出独占结构范围、写端口有效并绑定传入 L1 实例的 `L1所有者范围交付`；它还须从同一 L1 正式读取当前 owner 并与建立结果逐字段相等。任一条件或异常失败返回空 optional，只有全部成立才移动端口。服务构造再次验证交付端口有效、绑定同一 L1，再唯一消费；不得把普通 L1 服务引用、owner 编码或另一实例端口包装成概念交付。

服务私有持有一把 `std::mutex 概念本体根写入锁_`。`建立概念本体根` 从同截止全组预读开始直到 L1 提交结果完成解释为止持有该锁；它只串行化同一概念 owner 的根角色唯一性检查和写入，不承载机器事实。两个 const 读取入口不取得该锁，只依赖 L1 同锁一致投影。唯一活动概念写端口和不可复制服务共同保证不存在第二个绕过该锁的概念根写入口。

构造函数依次形成概念族来源和本体根内部类型；任一登记没有返回成功 / 精确重复、定位映射缺项、owner 不一致或正式读回坏形状时抛出构造失败，概念服务不形成。服务只缓存两份登记的不可变 owner / 稳定编码定位，不缓存根组、角色选择或任何当前事实。

不公开概念身份来源单读、根退出、根替换、普通概念、签名、直接上位写入、支持或名称入口。根事实的身份来源只作为三项根操作的正式负载返回；后继普通概念能力需要独立设计时再决定是否增加具名来源入口。

## 7. 私有结构登记与物理事实

概念 owner 构造期依次形成两份固定、可重放的 owner-scoped 登记。

### 7.1 概念节点族来源

```text
概念身份来源登记幂等身份     = 0x4C32'4944'5352'430A
概念族锚点本地键             = 0x020A'6001
概念族归属关系类型本地键     = 0x020A'6002
```

登记原子建立一个 `节点种类::普通` 的概念族锚点和一个 `节点种类::关系类型` 的概念族归属关系类型节点。公开概念节点必须与一条“概念节点 -> 概念族锚点、角色=1”的非自环关系同写、同创建代次。

### 7.2 本体根内部类型

```text
概念本体结构登记幂等身份     = 0x4C32'434F'5247'0001
本体根角色锚点本地键         = 0x020A'6101
本体根角色关系类型本地键     = 0x020A'6102
直接上位关系类型本地键       = 0x020A'6103
首次请求见证属性类型本地键   = 0x020A'6104
```

登记原子建立：

```text
本体根角色锚点       -> 节点种类::普通
本体根角色关系类型   -> 节点种类::关系类型
直接上位关系类型     -> 节点种类::关系类型
首次请求见证属性类型 -> 节点种类::属性类型，值表示种类::U64组
```

根角色关系方向固定为“根概念 -> 本体根角色锚点”，`角色或顺序` 固定为角色枚举值 1—4。直接上位关系方向固定为“上位概念 -> 下位概念”；本叶只登记关系类型，不建立任何直接上位关系。

首次请求见证属性固定为两项 `U64组`：

```text
[首次 L2结构幂等身份.值, 首次请求头.期望事实代次]
```

两项都非零，属性所属节点和来源节点均为根概念。该属性只用于正式读回首次请求见证，不向调用方暴露属性类型、值编码或修改入口。

两项内部登记幂等身份是概念 owner 的保留值。公开建立请求不得使用同值；公开请求向 L1 的写入幂等身份逐值无损映射，不增加操作前缀，从而维持概念 owner 全局幂等域并为后继概念写入保留同一身份空间。

### 7.3 单根建立写集

每次首次建立固定使用以下本地键：

```text
根概念节点                 = 0x020A'1001
概念族归属关系             = 0x020A'1002
本体根角色关系             = 0x020A'1003
首次请求见证值             = 0x020A'1004
```

一份概念 owner-scoped L1 写集原子包含：

```text
根概念节点
+ 根概念 -> 概念族锚点的族归属关系
+ 根概念 -> 本体根角色锚点的根角色关系
+ 首次请求见证 U64组值
+ 首次请求见证当前属性槽
```

节点、两关系和值事实同一提交代次创建；不存在独立根节点族、根 owner、语言 / 词条关系、语素 / 词性持久结构、名称或场景概念根。

## 8. 全组与单根读取

`读取全部当前概念本体根` 必须恰调用一次 L1 `尝试读取所有者范围一致关系类型闭包投影`，入口关系类型为本体根角色关系类型：

```text
所有者选择             = {概念 owner}
入口关系类型           = 本体根角色关系类型
源节点属性类型         = {首次请求见证属性类型}
源节点源关系类型       = {概念族归属关系类型}
源节点目标关系类型     = {直接上位关系类型}
其它普通选择和端点选择 = 空
```

结果必须恰有一个成功的概念 owner 项和一个成功的入口闭包项；owner、入口关系类型、每个闭包成员及其端点投影共享同一 `读取事实代次`。因此每个闭包成员在同一许可、同一事实截止内同时返回根节点、角色关系、角色锚点、族归属、首次请求见证，以及“根作为目标端”的直接上位关系组。服务必须逐项拒绝：

- 非概念 owner、错锚点、错关系类型、错方向、错角色或生命周期不当前；
- 重复角色、同一根多个角色、两个角色共用根身份、非法第五角色；
- 缺失 / 重复 / 非两项的首次请求见证；
- 任一本体根存在直接上位关系；
- 未排序、混代、部分载荷或闭包之外无法解释的额外根角色事实。

概念 owner 项必须回显精确 owner、独占结构范围、非零创建代次且未退出；它直接提供身份来源中的 owner 生命周期，禁止使用构造期缓存的 owner 事实替代同截止结果。直接上位关系方向为“上位概念 -> 下位概念”，所以根的直接上位组只能取闭包成员的 `源节点目标关系组`；不得误取根作为源端的下位组，也不得通过第二次关系读取拼接。

成功根组按角色枚举严格升序，允许 0—4 项。零守卫表示调用进入时原子最新；非零守卫不等于当前代次返回零载荷 `事实代次漂移`，成功截止必须等于非零守卫。

`按角色读取当前概念本体根` 复用一次全组读取的同一实现核心并只选择请求角色。由于该入口只接受调用方已经锁定的非零同代守卫，全组成功但角色不存在属于 `内部不一致`，返回空 optional、空变更代次，事实截止保留该次正式读取的非零截止；不得返回 `未找到`、不得二次读取、缓存或按名称猜测根。建立入口判断角色是否缺失只使用全组读取，不能调用单根入口承担预读。

## 9. 建立、幂等与并发

建立入口按以下顺序处理：

1. 先调用公开请求 helper，再以模块私有 helper 拒绝两项内部登记保留身份；随后取得 `概念本体根写入锁_`。
2. 以请求的非零期望代次执行一次全组读取。成功后先扫描全部根的首次幂等身份，再判断目标角色，顺序不得倒置：
   - 任一根的首次幂等身份等于请求身份，但角色或首次期望代次不同：`幂等冲突`；
   - 目标角色已存在，且首次幂等身份、首次期望代次和角色与请求逐字段相同：不再提交 L1，直接以该永久根形成 `精确重复`，事实截止与变更事实代次均为根角色关系的首次创建代次；
   - 目标角色已存在但首次幂等身份不同：`引用冲突`；
   - 请求身份未被占用且目标角色缺失：形成固定写集并恰提交一次。
3. 非零全组预读返回 `事实代次漂移` 时，仍把原固定写集恰提交一次，只用于收敛此前发布结果未知或晚到的同请求：若该身份已经绑定同一完整写集，L1 返回首次 `精确重复`；若身份尚未绑定，L1 仍返回零变化漂移。不得在此路径重组守卫、循环提交或越过 L1 幂等账创建第二根。
4. L1 写结果为成功或精确重复时，不得用其首次旧代次发起当前闭包读取。服务先逐项核对合同版本、owner、写入幂等身份、首次事实代次、发布标记 / 重试边界，以及四个本地键到根节点、族归属关系、根角色关系、首次见证值四个非零互异稳定编码的完整映射；属性槽没有独立新编码映射，不得虚构第五映射。
5. 随后以 L1 首次写入代次作为唯一解释截止完成 owner-aware 首次结果读回：调用 `读取历史结构所有者` 读取概念 owner；按稳定编码逐一调用 `读取所有者范围历史事实` 读取根节点、族锚点、族归属关系类型、族归属关系、角色锚点、角色关系类型、角色关系、直接上位关系类型、首次见证属性类型和首次见证值；再调用 `读取所有者范围历史关系组`，请求固定为“方向=目标、端点节点=根、关系类型=直接上位、历史截止=首次写入代次”，并要求成功空组。单事实 / owner 历史入口不带截止字段，因而必须以各事实的不可变创建代次和完整生命周期相对首次截止逐项校验；关系组入口显式携带该截止。全部事实必须来自概念 owner、创建代次不晚于该截止、生命周期未退出；根节点属性槽必须唯一指向映射得到的见证值，见证材料逐字段等于 `[请求.幂等身份.值, 请求.请求头.期望事实代次]`。整个算法不使用当前乐观守卫，因此后续任何 owner 的提交不会制造伪漂移。
6. 首次根结果固定使用该历史截止作为事实截止和变更事实代次；根角色关系创建代次等于该代次。新分配的根编码在本次写集发布前不可被其它写集引用，而本次写集不含直接上位关系；历史目标关系组进一步正式证明首次结果的直接上位组为空。后继普通概念能力仍必须永久拒绝让本体根成为下位。

这一区分两种证据：写结果回显的是“首次提交结果”，当前读取回显的是“调用守卫对应的当前快照”。精确重复可以在任意更晚当前代次返回首次旧截止；不得把它当作当前读守卫，也不得把本地已知较新截止回退。BIZ 或其它消费者若要证明调用时当前形状，必须随后用自己已正式取得的最新非零截止调用单根 / 全组读取。

同一角色、同一完整请求、同一幂等身份精确重复返回首次根和首次提交截止。相同幂等身份用于另一角色、另一期望代次或其它字段返回 `幂等冲突`。同角色不同幂等身份在当前守卫下返回 `引用冲突`；在陈旧守卫下可以先返回 `事实代次漂移`，调用方正式重读后观察角色已被另一首次请求占用。同一服务实例内的并发建立由私有锁串行；其它 owner 的并发发布只会使 L1 非零守卫漂移，不会形成第二概念根写入口。

资源失败、异常和发布结果未知统一返回 `资源失败`、空载荷、零变更形状；若 L1 已经提交但上述首次历史读回未完成，该结果明确属于“发布结果未知”，绝不能降级成 `事实代次漂移`。调用方只能原样重放同一完整请求；L1 精确重复会回显首次映射，服务再按同一首次截止完成历史读回。服务不 sleep、不忙重试、不生成新幂等身份，也不把异常当未找到。

## 10. 结果形状

写成功只允许 `已提交` 或 `精确重复`：

```text
事实截止非零
+ 变更事实代次存在且等于事实截止
+ 事实截止严格晚于首次请求期望事实代次
+ optional 本体根存在且完整
```

单根读成功只允许 `已读取`：

```text
事实截止非零
+ 变更事实代次为空
+ optional 本体根存在且完整
+ 角色等于请求角色
+ 非零守卫成功时事实截止等于请求守卫
```

全组读成功只允许 `已读取`：

```text
事实截止非零
+ 变更事实代次为空
+ 0—4 根按角色严格升序
+ 角色不重复、根身份互异、全部根同截止完整
+ 非零守卫成功时事实截止等于请求守卫
```

任一非成功的单根 optional / 根组 vector 必须为空，变更事实代次必须为空。未知枚举、错误成功状态、成功空 optional、第五根、错父关系或混代都映射 `内部不一致`，不得猜测成功或过滤坏事实。

状态映射固定为：

| 来源 / 条件 | L2 状态 |
| --- | --- |
| 请求纯值无效、保留幂等身份 | `入口拒绝` |
| L1 当前许可未取得 | `许可拒绝` |
| 请求非零守卫与当前代次不等 | `事实代次漂移` |
| L1 同幂等身份异完整写集 | `幂等冲突` |
| 当前角色已被另一首次幂等身份占用 | `引用冲突` |
| 单根同代正式全组中角色不存在 | `内部不一致` |
| L1 分配 / 资源失败、异常、发布结果未知 | `资源失败` |
| L1 或 C1 成功载荷坏形状、未知状态、混代或不变量破坏 | `内部不一致` |

`未找到`、`未实现`、`已退出`、`属性未设置` 不作为三入口的正常结果；底层出现这些形状统一视为 `内部不一致`。根不存在只由全组读取的成功空组或缺少该角色表达。

## 12. 施工检查与清理

施工期间可以在生产工程外临时建立一个 C1 参数检查程序，按风险覆盖：

1. 零守卫全组读取成功、空组和非零截止；
2. 四角色分别首次建立、按角色读回和最终全组恰四根；
3. 根身份互异、身份来源完整、首次见证对应、直接上位为空；
4. 每角色同完整请求精确重复；
5. 同幂等异角色冲突、同角色异请求冲突、陈旧守卫漂移；
6. 零幂等、零建立 / 单读守卫、非法角色入口拒绝且零变化；
7. 同角色并发同请求只形成一根；同角色并发异请求至多一个首次成功；
8. 首次提交与结果形成之间发生其它 owner 提交时仍返回首次结果，且不把首次截止冒充当前截止；
9. 首次提交后再有其它提交的晚到精确重复仍返回同一首次根 / 首次截止，随后以最新非零守卫正式单根读取成功；
10. 全组稳定排序、同截止 owner 事实、身份来源五生命周期均未退出、单根同代缺失映射内部不一致、零第五角色、根无退出入口。
