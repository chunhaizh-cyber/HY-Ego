## 1. 依赖闭合与问题归因

世界树根脚本的 `.h/.cpp` 探针已可独立迁移，但该脚本实际构建的专项在进入程序前有三个独立问题：D455 翻译单元的 SDK 头边界、专项 C++ 的 v3/v4 ABI 漂移、概念树对象的 `/bigobj` 缺失。前者由 D455 提供者独立消除；后两者都是本专项消费者的职责。故脚本路径计划不能把构建/运行失败作为自身失败或修改范围。

路径迁移已由 `d206ae9fc9da2ad21c517519acb80e9660d75d75` 发布，D455 条件编译已由 `b2c3b9034921c57f4020641f9f4c36f374b199fe` 发布。两项只闭合其各自的路径与翻译单元边界；专项 Debug/Release 成功仍须同时闭合 v4 ABI、`/bigobj` 和 D455 协议实现的链接提供者，才可归因于本消费者迁移。

`c5ef98486b02aaea84bc688de24cd2ac95ffc4f6` 是存在概念提供者的已发布安全中间结果，固定本专项 Fixture 所需的概念登记顺序；它不证明旧 pure variant 跨世界树/自我形成消费者已经退出，也不把该上游计划标为完成。

## 2. Fixture 的 v4 概念服务装配

在当前 Fixture 已完成特征、存在、状态、场景和世界根服务后，追加一个概念 owner。严格复用普通应用的结构登记顺序和同一 L1：

```text
登记纯概念结构_v2(key 0x1401)并真实读回
-> 登记特征概念出生使用结构(key 0x1402, 依赖纯结构)并真实读回
-> 登记存在概念两组结构_v1(key 0x1403, 依赖纯结构)并真实读回
-> 构造概念树类数据服务(features, existences, values, scenes, port,
                           pure, featureBirth, twoGroup)
```

专项使用自身不与既有 owner 冲突的稳定幂等身份；每一步仍以当前 `generation(l1)` 作为 `G0`，结构登记返回交付与成功谓词必须同时成立。概念服务保存为 Fixture 成员，其生命周期长于世界树应用服务。

## 4. 工程和验证

专项工程每个配置的 `AdditionalOptions` 追加 `/bigobj`，因为概念树实现已超过 COFF 节限制。这是局部编译器物理选项，不改变源码 ABI。不能把 `/bigobj` 写到脚本命令行或生产工程来规避专项工程合同。

专项工程当前仅以 `ClInclude` 登记 `协议.D455采样材料.h`，却编译 `采集器.D455相机.cpp`；而关闭宏的工厂会调用定义于 `协议.D455采样材料.cpp` 的 `D455采集配置有效`。因此该项目的唯一新增 `ClCompile` 项必须是 `..\\海中鱼巣\\适配\\协议.D455采样材料.cpp`，且只能出现一次。它提供既有协议函数定义以完成链接，不引入 SDK、真实设备、线程、缓存或新的 D455 业务路径。不得修改协议头/源、D455 宏、链接库或其它项目源项。

先作专项源的旧 v3 名称扫描、v4 字段静态审查和工程 `ClCompile` 清单核验（协议实现项恰一；四配置各恰含一次 `/bigobj` 并保留 `/utf-8`）。再以脚本做 Debug、Release 独立输出验证：每份 `result.json` 的五字段必须成功，core 最后一行必须为 `PASS-TOTAL 174`，ordinary 最后一行必须为 `PASS ordinary-entry-stops-at-stage-17`。后者是预期的普通入口在真实自我形成处停止，并非专项执行失败。任一静态清单、构建、链接、core、ordinary、JSON 字段或末行不符，均在该步骤失败、记录首个决定性错误且不得生成成功 `result.json`。若编译或链接越过 D455 后发现额外失配，不得以删除专项覆盖、减小概念树或改生产代码收口。成功的两个 JSON 与日志是唯一运行证据。
