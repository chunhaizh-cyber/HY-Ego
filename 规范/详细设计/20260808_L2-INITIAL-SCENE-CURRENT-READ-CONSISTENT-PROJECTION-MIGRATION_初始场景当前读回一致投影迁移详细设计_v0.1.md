### 2.3 当前偏差与复用裁决

## 4. 冻结目标函数、请求与数据所有权

唯一目标根保持现有内部签名和物理位置：

```cpp
// 海中鱼巣/领域/服务.L1场景结构.ixx
初始场景结果 L1场景结构内部::读取实现(
    const L1事实基座服务& L1,
    const 世界登记结果& 登记结果,
    const 初始场景读取请求& 请求);
```

输入登记由世界登记服务在本次业务轮次先行权威读回；输入请求由调用方或场景服务定位缓存拥有。L1 唯一拥有事实代次、共享许可和中性当前事实，场景服务唯一解释初始场景资格、标记和值式直接父关系。函数只返回调用方拥有的 `初始场景结果`，非成功不带部分事实。

在既有登记与请求校验通过后，形成唯一请求：

```cpp
L1中性一致当前读取请求 一致请求;
一致请求.合同版本 = L1中性一致当前读取合同版本;
一致请求.期望事实代次 = 登记.已验证事实代次;
一致请求.节点 = {请求.初始场景};
一致请求.关系 = {请求.直接父关系};
一致请求.值 = {};
一致请求.属性值 = {{请求.初始场景, 登记.场景标记属性类型}};
一致请求.源关系组 = {};
一致请求.目标关系组 = {};
```

场景标记值由属性值投影在同一许可内返回，必须与 `请求.场景标记值` 精确相等；不得再按值编码执行第二次读取，也不得把该编码加入直接值组制造重复业务请求。

## 5. 唯一控制流与跨服务同截止边界

1. 保持现有世界登记成功 / 完整性映射、`初始场景读取请求有效` 和请求世界根等于登记世界根校验；失败保持现有入口拒绝或登记非成功结果，零一致投影调用。
2. 期望代次唯一取本轮 `登记.已验证事实代次`。该登记已经由世界登记服务在自己的同一业务轮次取得权威当前截止。
3. 形成第 4 节 `1/1/0/1/0/0` 请求，物理调用 `尝试读取中性一致当前投影` 恰一次。
4. 顶层事实代次漂移立即返回 `世界结构状态::版本漂移`，不得在 helper 内改用回显实际代次重试。
5. 不局部重试的原因：按新实际代次只重读场景会使输入世界登记仍停留在旧截止，破坏世界登记与初始场景同截止合同。需要收敛时，调用方必须重新进入公开场景服务，从 `世界登记服务::读取当前登记` 开始重做完整业务轮；本叶不在内部循环调用外部服务。
6. 许可拒绝立即返回 `许可拒绝`，不等待、不重试；资源失败保持资源失败；入口拒绝、内部不一致和坏顶层失败形状返回内部不一致。
7. 成功只接受合同正确、期望代次回显精确、读取代次等于登记截止且非零、六组长度精确为 `1/1/0/1/0/0` 的完整结果。
8. 通过第 6 节业务形状验证后，按现有字段组装 `初始场景事实`，事实截止等于顶层读取代次，返回 `已读取`。

## 6. 成功结果的业务形状验证

### 6.1 初始场景节点

唯一节点项目必须满足：

- 查询编码、事实编码均等于 `请求.初始场景`；
- 项目状态为成功且事实存在；
- 节点种类为普通、无属性类型表示、未退出；
- 当前属性恰一项，属性类型为登记场景标记属性类型；
- 创建事实代次非零且不晚于读取代次。

节点项目未找到映射 `未找到`；已退出、种类不匹配、坏事实或字段矛盾映射 `内部不一致`。

### 6.2 场景标记属性值

唯一属性值项目必须满足：

- 节点为初始场景，属性类型为登记场景标记属性类型；
- 项目状态成功且投影存在；
- 投影属性槽与场景节点唯一当前槽逐字段相等；
- 槽当前值、投影值事实编码和 `请求.场景标记值` 三者相等；
- 值所属节点为初始场景，属性类型节点为登记场景标记类型，来源节点为登记服务身份；
- 值创建事实代次等于场景节点创建代次、不晚于读取代次，未退出；
- 材料为 `std::int64_t` 且精确等于 `1`。

项目未找到或属性未设置映射 `未找到`；已退出、种类不匹配、投影缺失或任一绑定矛盾映射 `内部不一致`。

### 6.3 直接父关系

唯一关系项目必须满足：

- 查询编码、事实编码均等于 `请求.直接父关系`；
- 项目状态成功且事实存在；
- 源节点为请求世界根，目标节点为请求初始场景；
- 关系类型节点为登记直接父场景关系类型；
- 角色 / 顺序为 `0`，未退出；
- 创建事实代次等于场景节点和值共同创建代次，且不晚于读取代次。

关系项目未找到映射 `未找到`；已退出、种类不匹配、坏事实或端点 / 类型 / 顺序矛盾映射 `内部不一致`。

### 6.4 坏成功

顶层成功但合同、代次、长度、顺序、项目状态或业务字段任一矛盾属于坏成功，返回内部不一致。不得挑选部分项目、重新排序、调用旧入口补齐或返回部分场景事实。
