# L1-SIMPLIFY-P9-BASELINE-STATE 实际存在 I64 首个关系19基准状态详细设计 v0.2

日期：2026-08-05

状态：设计就绪；代码未实现；计划必须待激活

替代关系：本版完整替代 v0.1。v0.1 的首态发布结构继续成立，但其读取重新依赖 P7 当前场景和 P8 当前值，无法在值换代或场景移动后读取不可变前状态，禁止执行。

## 1. 目标与边界

本设计只完成 SELF-GOV-CLOSURE STEP-3C：为 P7 实际存在及其 P8 存在宿主 I64 实例特征发布第一个关系19基准状态，并按状态自身稳定身份和完整见证读取一份不可变状态快照。

首态没有前状态，不调用比较，不建立关系20。发布写集仍为二节点、五值、五关系和五属性槽；角色4仍指向状态域特征值见证节点，不把 L1 值事实伪装成关系端点。

本入口不选择“当前状态”或相邻状态，不要求 P7 当前场景、P8 当前值或当前属性槽在读取时仍等于采样时事实。按主体、实例特征、时间和稳定状态身份选择状态属于后继查询能力。

本叶不实现第二状态、值换代、迁移动能、动作动态、因果、运行期装配、SQL、持久恢复或旧消费者迁移。

## 2. 漂移裁决与正式依据

- 4015 明确当前读取与历史读取分离；已退出事实只能从 `读取历史事实` 取得，当前入口不得返回历史副本。
- 1160 与 4190 要求状态创建后历史可追溯，当前性不能覆盖或改写历史状态。
- 4190/4210 要求状态冻结同一主体的精确特征、精确值、时间、场景和来源；关系19角色1—5由状态自身成立。
- 4015 规定端点退出不自动推导关系退出，事实的创建/退出代次是生命周期证据。
- P9 v0.1 重新调用 P7/P8 当前组合入口，并要求 P8 当前值等于采样值。P10 换代后旧值退出，或未来 P7 当前场景改变后，该入口必然拒绝原状态，因此 v0.1 退出。
- P7/P8 只在发布前提供采样材料和资格。状态发布后，状态领域通过自身关系19、值见证和 L1 当前/历史入口解释不可变状态；不得让比较服务解析关系19。

## 3. 保留的关系19与写集

关系19角色不变：

| 角色 | 目标 | 采样时来源 |
| --- | --- | --- |
| 1 主体 | P7 实际存在节点 | P7 当前读取 |
| 2 场景 | 采样时实际存在所属场景节点 | P7 当前读取 |
| 3 特征 | P8 存在宿主实例槽节点 | P8 当前读取 |
| 4 值 | 状态域特征值见证节点 | 本叶写集 |
| 5 来源存在 | 首态固定为角色1实际存在 | P7 当前读取 |

状态域特征值见证节点仍保存：

1. `状态特征值见证标记`：I64 `1`；
2. `被采样P8值引用`：U64组 `[被采样值编码, 被采样值创建事实代次, 采样事实截止代次, 原来源节点编码]`；
3. `状态采样I64值`：采样时 P8 I64 材料。

四项引用与复制的 I64 材料共同构成冻结见证。被采样 P8 值后来退出合法；其退出事实代次必须为空或严格大于采样事实截止代次。

## 6. 发布合同

登记、幂等域和发布前校验保持 v0.1：`0x0C` 建立七节点登记，`0x0D` 发布首态。发布前在同一请求期望代次取得 P8 当前组合、P7 当前实际存在/场景和 L1 当前值，核对宿主、实例槽、定义、来源与 I64 材料。

唯一写集保持本地键1—12：二普通节点、五类型化值、五关系和五属性槽。写集提交成功或精确重复后，用新读取请求填入映射得到的状态自有编码，并调用同一个 `读取实际存在I64基准状态`。立即读回时全部事实应走当前分支，且读取截止代次等于写入结果代次。

同键同义重试使用原完整读取请求重新读取状态，不重新解释后来 P7/P8 当前投影；同键异义为 `幂等冲突`。

## 7. 不可变状态读取算法

服务互斥量内按以下顺序读取；只读函数不写事实、不更新缓存：

1. 校验合同、规则和全部稳定编码非零且应互异的编码互异；非法返回 `入口拒绝`。
2. 调用 `L1事实基座服务::读取完整快照` 取得起始权威事实代次 `G0`。
3. 对请求具名的状态节点、见证节点、五关系和五状态域值逐项执行统一“当前或历史读取”：
   - 先调用对应 `读取当前节点/关系/值`；成功时要求读取代次为 `G0`；
   - 返回 `已退出` 时，以同一编码调用 `读取历史事实`，必须成功且种类正确；
   - `未找到` 不得扫描猜测编码，返回 `未找到`；
   - 其它状态按 §10 映射。
4. 从五关系自身验证：源均为请求状态，关系类型均等于登记关系19类型，角色1—5恰一；由关系端点确定主体、采样时场景、实例槽、特征值见证和来源存在。不得与 P7 当前场景比较。
5. 从状态节点和见证节点的当前或历史记录校验五个属性槽唯一指向请求具名值。节点已退出时使用历史节点记录中冻结的槽表，不调用当前属性入口补造。
6. 校验两个资格值为 I64 `1`、发生时间为单项非零 U64 组、引用为四项 U64 组、采样值为 I64；来源和所属节点与关系角色、登记完全一致。
7. 从引用组取得被采样 P8 值编码、创建代次、采样截止代次和原来源编码。以该编码先读当前值；若 `已退出` 则读历史值。禁止调用 P8 当前组合入口。
8. 被采样值必须是 I64，所属节点等于角色3实例槽，属性类型非零并作为结果 `特征定义`，来源等于引用原来源，创建代次等于引用创建代次，材料等于状态复制的采样 I64。其创建代次不得晚于采样截止；退出代次若存在必须严格晚于采样截止。
9. 状态、见证、五关系和五状态域值的创建代次必须相同，且等于首态写集发布代次；该代次必须是采样截止代次加一。主体、场景、实例槽、来源存在和被采样 P8 值必须在采样截止时已经创建且尚未退出。它们后来退出合法，不改写关系19角色。
10. 再次读取完整快照取得 `G1`。只有 `G0 == G1`，且所有当前读取代次均等于该值，才返回成功。一次完整重试仍漂移返回 `版本漂移`；历史记录本身不可变，但也必须处于同一首末代次观察窗口。

读取不得扫描当前 P7/P8 属性槽来证明状态，不得以请求回显、服务意图账、SQL、索引、日志或缓存补齐事实。

## 8. 生命周期与端点退出

- 状态快照由其稳定状态身份、五关系、五状态域值和被采样 P8 值共同成立。
- P10 换代后，被采样值从当前入口返回 `已退出` 时，必须从历史入口互证并继续成功读取原状态。
- P7 当前场景改变后，关系19角色2仍表示采样时场景；不得重新调用 P7 或返回版本漂移。
- 主体、场景、实例槽、来源存在或状态自有事实后来退出时，按各自稳定编码读历史记录。只要其在采样截止时有效且冻结结构一致，历史退出不使状态失真。
- 端点退出不自动退出关系；若状态关系或状态自有节点/值也退出，仍按历史入口取得。缺失、错误生命周期或冻结见证矛盾不是合法退出。
- 本入口只按具名状态读取一份快照，不裁决当前状态，不枚举状态集合。

## 9. 并发、幂等与发布后边界

多线程发布仍由状态服务互斥量、本进程意图账和 L1 幂等账串行裁决。读取以首末完整快照代次作为观察边界；不长期持有 L1 内部锁，不取得仓库或候选权。

发布后读回失败不补写、不删除、不回滚。已发布事实仍以 L1 为准，结果按错误映射返回。非成功结果业务载荷始终为空。

## 10. 错误映射

| 情况 | 结果 |
| --- | --- |
| 错合同/规则、零或非法编码、默认请求 | `入口拒绝` |
| 具名状态、关系、状态值、见证或被采样 P8 值从当前/历史均不存在 | `未找到` |
| 首末完整快照代次不同，或当前读取代次不等于观察代次 | `版本漂移` |
| L1 许可或等价拒绝 | `许可拒绝` |
| L1 资源失败、`std::bad_alloc` | `资源失败` |
| 角色/基数/端点/属性槽/表示/来源/材料/创建退出代次或当前历史副本互相矛盾 | `内部不一致` |

历史事实已退出本身不是 `未找到`、`版本漂移` 或 `内部不一致`。其它异常返回 `内部不一致`。生产服务不写事件、调试、运行或排错日志。
