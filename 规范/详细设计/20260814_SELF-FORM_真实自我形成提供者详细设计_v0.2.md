# SELF-FORM 真实自我形成提供者详细设计 v0.2

日期：2026-08-14

状态：同身份重基线候选；待设计提交与计划索引替换登记

## 1. 重基线结论

本版本替代 v0.1 作为 `SELF-FORM` 的后继候选，不改业务身份。v0.1 的五步状态机仍成立，但不能继续施工，原因是：

1. 已发布 E-ROLE 与 S-HOST 最终 ABI 需要机械绑定，不能继续按预冻结接口描述；
2. v0.1 仍写“概念维度根生产初始化能力未实现 = 18”，正式 8120 v0.8 已改为存在、特征、动态、因果链四个语言无关概念本体根；
3. `BIZ-L3-001-03-08` 尚未落盘，阶段 17 的唯一目标函数边不完整；
4. 普通应用当前没有独立 I2 适配器对象，I2 是普通应用上下文上的正式自由函数和值式发布槽；SELF-FORM 必须按真实物理结构装配；
5. S-HOST 三件临时专项已由 `c72be0f7` 清理，旧索引说明“仍待清理”是过期证据。

本候选最后一次 S0 基线 `c2d2443c1edcf2622cba4994483e3adaafe74f6e` 已具备 A1、R1、I1、I2、E-ROLE 与 S-HOST 的正式生产 ABI。I1/I2 已由 `运行普通程序` 真实调用；当前固定在 I2 成功后的阶段 17“自我初始化能力未实现”。同一基线的 DATA M1 v0.3 是当前唯一可执行计划并将占用共享工程、构建与验证资源，因此这些事实只证明 SELF-FORM 可完成设计，不证明当前可施工或阶段 17 已解除；发布前仍须从届时最新 `main == origin/main` 重做 S0。

## 2. 目标、完成条件与排除项

目标是在同一普通应用生命周期内，由唯一 L5 之外业务提供者消费本次 I2 正式再读回的现实世界树根材料，按固定幂等五步形成：

```text
一个项目固定单例角色绑定的正式存在
+ 一个位于现实世界树根下的自我所在场景
+ 所在场景 -> 自我存在的成员关系
+ 一个位于自我所在场景下的内部世界场景
+ 内部世界场景 -> 自我存在的宿主关系
```

只有上述事实在一个共同当前事实截止由最终公开 DATA 服务完整读回、逐字段互证，并以完整候选无抛出交换发布后，才返回成功。请求、固定键、上下文成员、provider 缓存、日志、线程或显示材料均不是自我事实。

本叶不实现：阶段 18 四本体根、概念、语言、词性、二次特征、方法根、自我线程、投影、运行宿主、普通自我退役、跨进程恢复或旧数据迁移。E-ROLE/S-HOST 的替换和退出是 DATA 中性能力，本 provider 永不调用。


`读取已发布自我()` 使用同一发布锁返回值式副本：首次成功前为空，成功后只返回最后一次完整交换值；它不调用 DATA、不刷新事实截止，也不取得自我事实权威。复制分配异常可向调用方传播，不得清空或改写已发布值。

## 5. 五步可恢复状态机

每次调用先在锁内校验请求选择，再经 A1 对 I2 材料重新读取 R1 当前登记与整树。首次合法请求在第一个 DATA 写前锁定；即使后继失败也保留到 provider 析构。异请求在任何 DATA 写前返回 `已发布选择冲突`。

固定步骤：

1. 第一完整请求不存在时，以本轮 R1 截止调用 `读取存在单例角色`。只有 `未找到` 才保存 `L2角色化存在新增请求` 并调用 `新增角色化存在`；`已读取` 是外部选择冲突。第一请求已保存时跳过外部接纳，直接原样重放保存请求。写返回 `已提交` / `精确重复` 且完整后，必须以该次写结果 `结果头.事实截止代次` 作为非零 `期望事实代次` 正式读取角色，并要求读回截止与写截止相等后互证；不得复用写前 R1 截止。
2. 保存并原样重放 `L2树内场景新增请求{同树, 根场景, 顺序=1}`，形成自我所在场景。
3. 保存并原样重放 `L2场景成员关系新增请求{所在场景, 自我存在, 顺序=1}`。
4. 保存并原样重放 `L2树内场景新增请求{同树, 所在场景, 顺序=1}`，形成内部世界场景。
5. 保存并原样重放 `L2场景宿主存在新增请求{内部世界场景, 自我存在}`。

### 5.1 L2 结果状态机械映射

执行者不得按调用点自行解释 `L2结构状态`。以下映射覆盖当前公开枚举的全部十四个值；“本步形成失败”分别指步骤 1—5 的 `自我存在形成失败`、`所在场景形成失败`、`所在场景成员形成失败`、`内部世界形成失败`、`内部世界宿主形成失败`。

| L2 结构状态 | 第一步首次角色预读 | 五个写入口 | 写后角色互证 / 最终正式读回 | R1 根材料重读 |
| --- | --- | --- | --- | --- |

第一步写返回 `幂等冲突` 或 `引用冲突` 时，必须用当前截止正式补读固定角色：读到完整当前绑定返回 `已发布选择冲突`；读到 `未找到`、`未实现`、`已退出` 或 `属性未设置` 返回 `自我存在形成失败`；入口拒绝、许可拒绝、事实代次漂移、资源失败和内部不一致按表映射；任何不属于读取入口成功合同的状态或坏负载返回 `内部不一致`。该补读不接纳外部事实，也不改变或丢弃首次完整请求。

所有非成功 SELF-FORM 结果的 `已形成自我` 必须为空。异常中的分配失败映射 `资源失败`，其它异常映射 `内部不一致`；异常和未知发布均不授权重组请求。

同一 provider 的调用由发布锁覆盖“请求选择校验 -> 五步收敛 -> 共同截止读回 -> 最终交换”，同请求并发串行执行并各自重新读回，异请求在任何 DATA 写前冲突。锁、线程号和到达顺序不是机器事实；实现不得 sleep、忙循环、调用用户回调或在一次调用内执行超过一次的漂移重组。

每一步只接受 `已提交` 或 `精确重复` 且其 DTO `成功()` 成立。新一步请求只用前一步本次成功/精确重复结果中的身份和当时最新正式事实代次形成；保存后不改变期望事实代次、端点、顺序、角色或幂等身份。

如果 DATA 返回 `事实代次漂移`，只有该步尚无首次成功/精确重复，而且状态明确保证零变化、无首次结果、幂等身份未绑定，才可丢弃该步请求副本，本次调用最多重新正式读回并用同一固定幂等身份重组一次；再次漂移返回 `事实代次竞争`，不得循环忙重试。资源失败、异常、发布未知、引用冲突或幂等冲突不授权重组。引用/幂等冲突时第一步按 5.1 的角色补读特例收口。

跨 owner 不回滚。后步失败保留已发布前步，下一次同请求从第一步开始逐个原请求重放并从正式返回重新取得身份。禁止通过结果缓存、关系扫描、名称或分配顺序猜中间身份。

## 6. 共同截止正式读回

五步完成后，先重新读取 R1 当前登记取得共同非零截止，再以该截止正式读取：

1. 现实世界整树；
2. 固定存在单例角色；
3. 自我存在节点；
4. 自我所在场景完整事实；
5. 自我内部世界场景完整事实；
6. 内部世界场景正向宿主关系；
7. 自我存在反向当前宿主场景。

逐字段证明：两场景属于 I2 的同一树；所在场景直接父为根；内部世界直接父为所在场景；所在场景有且仅有目标成员关系；内部世界宿主正反向一致且唯一；自我不是内部世界成员；根、自我、两场景编码互异；无自包含环；全部结果截止等于共同截止。

任一缺项、额外冲突、混代或坏成功形状返回 `完整读回失败`/`内部不一致`，不覆盖旧发布值。完整候选构造后一次无抛出交换；首次成功返回 `已形成`，同请求每次完整重放并重新读回后返回 `精确重复`。

## 7. 普通应用与阶段接线

当前普通应用依赖顺序为六个世界结构服务 -> A1 聚合 -> I1/I2 发布槽。v0.2 固定在 A1 聚合创建后构造唯一 `std::unique_ptr<真实自我形成提供者>`，并把它传入普通应用上下文；成员声明位于聚合服务之后，因而析构早于聚合。上下文增加 const/non-const getter。装配状态在现有 `L2结构聚合服务构造失败 = 23` 后追加：

```cpp
真实自我形成提供者构造失败 = 24
```
