# INSTINCT-STAGE3-MAINTENANCE-CURSOR-FOUNDATION 本能被动维护游标基础详细设计 v0.1

日期：2026-08-29

状态：设计完成；只闭合阶段三时间纪元与初始维护游标，不宣称安全 / 服务被动维护完成

## 1. 目标与完成边界

本设计建立唯一可恢复的本能被动维护游标 owner，使应用在本能根锚点形成后、创建自我线程前，能够用正式单调时间证据建立或恢复当前运行代次的维护起点。

完成结果固定为：

```text
本能根运行锚点已完整读回
-> 读取正式单调时间与当前完整秒边界
-> 建立 / 恢复维护结构登记
-> 建立当前运行代次与时间纪元的初始游标
-> 独立读回唯一当前游标
-> 只有读回完整才允许继续创建自我线程
```

本切片不推进同一纪元内的待维护秒，不改变 A 或 V，不生成状态 / 动态，不读取或假定服务合同、安全事件、活动集合及 L/H。后继被动维护必须把 A/V 变化、状态 / 动态和游标推进放入同一有限 N 分区事务；本入口不得被复用为事务外提前推进游标的捷径。

## 4. 数据合同

合同版本均为 1。

```cpp
struct 本能被动维护游标事实_v1 final {
    L2存在身份 自我;
    std::uint64_t 运行代次;
    std::uint64_t 时间纪元身份;
    std::int64_t 上一已维护完整秒边界;
    std::uint32_t 时间源版本;
    std::uint32_t 服务时间维护规则版本;
    std::uint64_t 形成事实代次;
};
```

完整性要求：身份均有效；运行代次、纪元、时间源版本、规则版本和形成代次非零；边界非负。结构登记固定包含登记锚点、当前游标节点、游标属性类型和当前属性槽。每次新纪元只新增一项不可变 U64 组值，并把当前属性槽切换到该值；旧值永久保留为历史，不建立第二当前关系或缓存权威。

```cpp
struct 建立或恢复本能被动维护游标请求_v1 final {
    std::uint32_t 合同版本;
    L2结构请求头 请求头;
    L2结构幂等身份 幂等身份;
    本能根运行锚点_v1 本能根锚点;
    std::uint64_t 运行代次;
    std::uint64_t 时间纪元身份;
    std::int64_t 当前完整秒边界;
    std::uint32_t 时间源版本;
    std::uint32_t 服务时间维护规则版本;
};
```

状态：`已建立`、`已恢复`、`已建立新纪元`、`入口拒绝`、`当前性漂移`、`幂等冲突`、`引用冲突`、`资源失败`、`内部错误`、`已可能发布`。

成功仅允许前三种状态，必须返回完整游标和非零正式读回截止。其它状态载荷空、截止零；`已可能发布`只保留原幂等身份和首次提交见证，不声明业务成功。

读取入口：

```cpp
本能被动维护游标读取结果_v1 读取当前本能被动维护游标_v1(
    const 本能被动维护游标读取请求_v1&) const noexcept;
```

读取请求只携带合同版本、`L2结构请求头(Gread)` 和自我身份；服务固定读取唯一当前属性槽，不允许调用方指定纪元值身份或从历史最大值猜当前。

## 5. 建立、恢复与新纪元规则

1. G0 读前守卫必须等于请求头期望代次。
2. 本能根锚点必须完整，锚点自我与请求自我一致，锚点截止不晚于 G0；服务正式读回 A/V 根实例仍属于同一自我，不能只信任值式锚点。
3. 首次没有结构登记时，先用固定登记幂等身份建立登记锚点、游标节点和属性类型；发布后正式读回。该登记提交不建立游标值。
4. 没有当前游标时，以本次 `运行代次 + 时间纪元身份 + 当前完整秒边界` 建立初始游标。该边界表示根锚点已形成后的维护起点，不补算根存在前的秒。
5. 当前游标与请求运行代次、纪元、边界、时间源和规则版本逐字段相同：返回 `已恢复`，零新写入。
6. 运行代次和时间纪元均相同但边界不同：返回 `引用冲突`。本入口不得推进同纪元游标。
7. 运行代次或时间纪元变化时，两者必须共同变化；建立新纪元游标并切换当前属性槽，返回 `已建立新纪元`。旧纪元到新纪元之间不补算停机秒。
8. 时间源版本或服务维护规则版本漂移不能静默切换；返回 `引用冲突`，由后继版本迁移合同处理。
9. 写后以 G1 读回当前槽和值，随后执行 G1 读后守卫。提交已发生但读回不完整返回 `已可能发布`，只能用原请求重放收束。

## 6. 生产接线

普通应用建立唯一 owner、形成服务并通过 `普通应用上下文` 暴露同一实例。启动顺序固定为：

```text
本能根运行锚点成功
-> 构造单调时钟适配器与完整秒时钟服务
-> 以“上一边界=0”读取当前完整秒边界观察
-> 调用建立或恢复本能被动维护游标_v1
-> 独立读取当前游标并逐字段互证
-> 成功后才构造自我线程锁定请求
```

`无新完整秒`仍携带合法观察，允许建立边界 0 的初始游标。时钟拒绝、纪元错配、版本漂移、倒退、不可表示或内部不一致均阻止自我线程创建。

## 7. 后继原子推进接口边界

本切片不导出推进入口。服务内部为后继保留“按当前游标形成维护 owner v3 参与者”的实现位置，但本版不得通过测试、普通应用或其它模块调用。后继只有在 A/V、状态 / 动态和本 owner 游标候选全部冻结后，才可公开一个聚合维护入口并使用 L1 v3。

## 9. 验证矩阵

- 首次结构登记与边界 0 / 正边界初始游标。
- 同请求精确重复及不同幂等身份下同义当前恢复零写。
- 同运行代次 / 纪元但边界不同拒绝，证明本入口不能推进。
- 新运行代次 + 新纪元建立新当前，旧游标历史可读且不补停机秒。
- 只变化运行代次或只变化纪元拒绝。
- 时间源 / 规则版本漂移、G0 前后漂移、同键异义、资源和内部错误。
- 提交后读回失败使用原键收敛为已恢复，不生成第二游标。
- 普通应用唯一服务实例；启动在自我线程前实际消费。
- Debug / Release v143 根工程、ABI consumer、专项、持久恢复重启。
