# 按所有者与属性类型读取当前值组详细设计 v0.1

日期：2026-08-16

设计身份：`DATA-L1-OWNER-ATTRIBUTE-TYPE-CURRENT-VALUE-GROUP-READ`

状态：设计就绪；不等于代码已实现

## 1. 目标与缺口

为 `DATA-L1` 增加一个业务中性的原子读取能力：调用方给出一个已知结构 owner、一个属性类型节点、非零事实代次守卫和非零数量预算，读取该 owner 下全部使用该属性类型的当前值事实。

现行仓库已经维护 `当前节点引用索引`，值事实的所属节点、属性类型、来源节点和独立材料引用都会进入该索引；公开 L1 目前只有按来源节点反向读取当前值组，没有按属性类型节点发现当前值的入口。L2 若为时间范围或其它属性条件先枚举全部本族对象再过滤，就不能证明资源有界，也会形成第二种隐式全仓读取。具名缺口为：

`DRIFT-DATA-L1-ATTRIBUTE-TYPE-CURRENT-VALUE-REVERSE-READ-MISSING`

## 2. 边界与后继关系

本设计只冻结 L1 中性值发现，不建立状态、动态或其它领域查询，不比较材料，不增加第二仓库、第二 owner、第二索引、缓存、通用节点引用枚举、分页游标或零守卫最新读取。

当前值组必须来自一次共享锁和一个事实截止。空组是成功；超出预算必须拒绝整组，不能返回前 N 项。L2 消费者仍须按自己正式登记的属性类型、材料表示、关系、基数、生命周期和完整读取合同验证所属对象，不能把值命中直接解释为状态、动态或时间范围命中。

该 provider 是后继显式 I64 状态时间范围读取的独立前置。后继只能查询状态服务正式登记的 `L2状态时间I64值类型身份`，并显式携带范围边界及候选 / 输出数量预算。现行四类时间材料没有统一排序合同，因此本设计不授权后继把 I64 叶宣称为四类材料通用时间范围，也不授权比较 I64 组、U64 组或独立材料引用。

## 4. 状态与载荷

| 条件 | 状态 | 读取代次 | 当前值组 |
| --- | --- | --- | --- |
| 错合同、零 owner、零属性类型、零守卫或零预算 | 入口拒绝 | 0 | 空 |
| 守卫不等于锁内当前代次 | 事实代次漂移 | 锁内当前代次 | 空 |
| 按 owner、属性类型节点顺序遇到首个从未存在对象 | 未找到 | 锁内当前代次 | 空 |
| 按 owner、属性类型节点顺序遇到首个已经退出对象 | 已退出 | 锁内当前代次 | 空 |
| 节点当前但种类不是属性类型或没有表示种类 | 入口拒绝 | 锁内当前代次 | 空 |
| 匹配数超过预算 | 数量预算不足 | 锁内当前代次 | 空 |
| owner 与属性类型当前且匹配数为 0—预算 | 成功 | 等于守卫 | 严格升序完整组 |
| 分配或长度耗尽 | 资源失败 | 安全取得则保留，否则 0 | 空 |
| 隔离、索引或事实互证失败 | 内部不一致 | 安全取得则保留，否则 0 | 空 |

守卫比较先于对象生命周期解释，保证陈旧调用统一得到事实代次漂移，不泄漏另一截止的对象状态。成功组中每项必须当前、owner 相同、属性类型相同、编码非零且严格升序；任何非成功结果不得夹带部分组。

属性类型节点可以由另一 owner 创建，但 owner-scoped 值合同禁止该节点成为请求 owner 下值的属性类型，因此合法结果只能是成功空组。该行为与按来源读取允许跨 owner 来源一致，不把属性类型节点所有权误当成查询许可；任何实际返回项仍必须由请求 owner 写入。

## 5. 仓库过程

1. 纯值校验失败直接入口拒绝，不加锁。
2. 取得一次 shared lock，记录锁内事实代次；隔离或全局状态不完整返回内部不一致。
3. 比较非零守卫；不等返回漂移。
4. 固定先验证请求 owner、再验证属性类型节点；首个对象历史存在映射已退出，否则映射未找到，后项不覆盖前项状态。
5. 属性类型节点必须是 `节点种类::属性类型` 且携带表示种类；其它当前节点返回入口拒绝。
6. 从 `当前节点引用索引[属性类型节点]` 读取已排序候选编码；逐项只接受当前值表中 `写入所有者==owner && 属性类型节点==请求属性类型` 的值事实。关系、所属节点角色、来源角色和独立材料引用角色仅作为索引中的其它合法候选跳过。
7. 匹配数超过预算立即清空并返回数量预算不足；否则转换为 owner-scoped 公共值事实并返回成功。
8. 现有 `状态完整` 必须继续证明索引由全部当前关系和值确定派生；本入口不维护第二索引。

## 6. 验证与完成边界

生产外临时检查至少覆盖：坏请求、空组、同 owner 多属性类型、同属性类型跨 owner 隔离、有序多值、精确预算、超预算零载荷、陈旧守卫、owner / 属性类型未找到与已退出、当前非属性类型拒绝、另一 owner 属性类型成功空组，以及既有来源 / 当前 / 历史 / 一致读取不回归。资源耗尽、私有索引损坏和跨进程恢复没有稳定公开注入时记 `NOT_RUN`，不得增加生产 seam。

结果只证明该 L1 原子属性类型读取 provider。它不证明状态或动态时间范围查询已实现，不定义四类材料的统一排序，也不证明 `DATA-EXT-04`、`DATA-EXT-05` 或最终需求清单整体完成。
