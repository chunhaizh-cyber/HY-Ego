## 1. S0 与最早缺口裁决

P53—P62已经把完整自我结构的登记、两域规格、一次L1 v2发布和无裸键初始化窄入口冻结完整，但P62明确没有建立安全/服务根定义、实例槽、当前值或根需求。6130规定抽象特征服务负责根定义，特征服务只在定义已经正式存在后建立关系22实例槽和当前值；因此“先建实例槽”会让关系22目标没有权威定义。

| 候选能力 | 当前正式或冻结能力 | P63裁决 |
| --- | --- | --- |
| 通用单项I64定义 | P2冻结下界、上界和来源服务 | 只能复用I64值域概念；没有双轴角色、阈值、合法生产者和维护版本 |
| 实际存在I64实例槽和值 | P36/P40冻结规格和发布者 | 必须先引用正式根定义；不能倒序调用 |
| 完整自我初始化入口 | P62冻结对P61的一次透明委托 | 只提供自我身份结果，不创建根定义 |
| 安全/服务双轴根定义规格 | 当前没有 | **STEP-5当前最早真实缺口** |
| 根定义写集、事务和发布 | 当前没有 | 必须消费本叶规格，后继另立叶 |
| 实例槽、当前值、根需求和生产装配 | 当前没有 | 依次后继，不进入本叶 |

P2的公开建立请求只有幂等身份、期望代次和I64上下界，同一个服务对象还只拥有一个首次定义请求语义。把P2直接调用两次既不能表达6130/6120/6170机器合同，也会迫使后继调用方以名称区分安全和服务。故P63不是P2门面，也不修改P2；它先建立抽象特征领域拥有的双轴零写规格，冻结两个强类型角色及其规则材料，后继再独立设计写集和唯一发布者。

## 2. 目标与最大边界

新增唯一公开根：

```cpp
自我双轴根定义规格结果 L1自我根定义规格服务::形成自我双轴根定义规格(
    const 自我双轴根定义规格请求& 请求) const noexcept;
```

本函数只验证版本和安全阈值并形成两个不可变纯值规格。它调用provider、P2、P15、P37、P54和L1均为0，不读取完整自我、仓库、配置、环境、SQL、名称或旧句柄，不分配稳定编码、本地键、幂等身份、摘要或操作标签，不取得事务、锁或许可。

本叶不建立根定义事实，不创建实例槽、当前值、状态、动态、因果或根需求，不调用P36/P40，不接线P62或旧初始化，不恢复、删除旧栈或执行正式集成验收。

## 4. DTO 与固定机器语义

共享头新增：

```cpp
inline constexpr std::uint32_t L1自我根定义合同版本 = 1;
inline constexpr std::uint32_t 自我双轴根定义规格规则版本 = 1;

enum class 自我根定义角色 : std::uint8_t {
    生存安全 = 1,
    服务 = 2
};

enum class 根目标比较种类 : std::uint8_t {
    大于 = 1,
    等于 = 2
};

enum class 根定义生产者种类 : std::uint8_t {
    主动安全结算 = 1,
    服务合同结算 = 2,
    服务生存维护 = 3
};

enum class 根定义证据种类 : std::uint8_t {
    主动安全结算事实 = 1,
    服务合同结算事实 = 2,
    服务生存维护事实 = 3
};
```

`自我双轴根定义规格请求`只携带合同/规格版本、安全低位阈值、安全高位阈值，以及以下非零`uint32_t`版本：主动安全结算、被动服务维护、服务合同、默认有效期、预算、服务时间纪元、完整秒、服务衰减、准备补回、服务比例、生存安全回归、状态动态组织、因果组织、缺口需求、验证归因回写。

`生存安全根定义规格`固定：

```text
角色 = 生存安全
I64值域 = 0..I64_MAX
目标 = 当前值 > 1
阈值 = 请求给出的L/H，且1＜L＜H≤I64_MAX
合法生产者 = [主动安全结算, 服务生存维护]
合法证据 = [主动安全结算事实, 服务生存维护事实]
主动安全结算/被动服务维护及四项组织版本 = 请求冻结值
```

`服务根定义规格`固定：

```text
角色 = 服务
I64值域 = 0..I64_MAX
目标 = 当前值 == I64_MAX
合法生产者 = [服务合同结算, 服务生存维护]
合法证据 = [服务合同结算事实, 服务生存维护事实]
默认有效秒数 = 2,592,000
合同、默认有效期、预算、时间纪元、完整秒、衰减、准备补回、服务比例、
生存安全回归及四项组织版本 = 请求冻结值
```

两个规格都只声明正式生产边和证据种类，不预置硬件、软件、环境、风险、服务对象、任务、方法或固定安全因素表。强类型角色不是名称、显示标签、L1本地键或稳定编码；规则版本不是规则正文的副本。

结果状态只含`已形成`和`入口拒绝`。仅`已形成`携带恰一安全规格和恰一服务规格；纯值固定结构不分配内存，不伪造资源失败或内部不一致分支。

## 5. 单函数执行合同

固定流程：

1. 检查合同版本和规格版本精确等于当前版本；
2. 检查全部规则/组织版本非零；
3. 检查`1＜L＜H≤I64_MAX`；
4. 构造安全规格，固定角色、值域、目标、生产者/证据有序组及版本；
5. 构造服务规格，固定角色、值域、目标、默认有效秒数、生产者/证据有序组及版本；
6. 逐字段确认两角色不同、值域相同但目标和生产边不混用，然后返回`已形成`。

任一入口条件失败立即返回`入口拒绝`和空规格。函数不补默认版本、不从显示名推断角色、不排序调用方集合，因为请求不接收集合；不把安全阈值用于服务值，也不把6140分层安全值模板冒充生存安全根定义。

相同请求必须逐字段返回相同结果，与线程、地址、调用次数和容器顺序无关。函数无锁、无缓存、无retry、无时间读取；并发调用互不共享状态。

## 6. 与通用特征及后继发布的边界

P2的`I64特征定义事实`仍是通用定义读取形状，P63不扩展或覆盖它。后继根定义写集必须把本叶两个角色分别映射为两个新的正式抽象定义，并在同一根定义领域合同中保存本叶全部专用版本材料；不能只发布两个P2上下界事实后用名称补语义。

后继发布者才有权裁决：具体L1本地键和值/关系形状、稳定编码分配、幂等身份/双摘要、操作标签、P15真实接口、事务提交、发布后读回和失败隔离。本叶对这些项目全部保持0，不预占P15未发布内部编码。

根定义发布后，后继实例槽叶才可复用P36/P40的I64实例能力，以P62返回的当前自我存在为宿主，分别建立安全和服务关系22槽。当前值、目标状态和根需求继续分叶；定义规格本身不得直接生需。
