## 1. 目标与裁决

本叶只交付 ARCH-L1/L2 中性公开能力：

- 无动态首态：状态 owner 在一个 G1 内形成永久状态、状态自有关系和唯一当前选择。
- 状态—动态迁移：状态 owner 只退出旧当前选择并形成新永久状态和新选择；动态 owner 形成引用旧状态与新状态的动态；正式事实最终同一 G1。
- 当前选择读取返回当前 0/1 闭包，历史选择读取返回具名截止 0/1 快照。
- 首次、精确重复、同键异义、G0、许可、引用、资源、交换前内部错误及提交后读回失败均结构化分账。
- 提交后读回失败不回滚，按原请求和原幂等身份重放，从首次 G1 的正式历史快照收束。

L4 的“应用顺序不改变正式映射或最终事实”按提供者边界落实为：公开请求没有参与者顺序参数；L1 固定按参与者序号状态 1、动态 2，再按本地键升序规范化。调用者无法改变应用顺序，同一完整请求始终形成同映射、同事实和同 G1。L4 不取得 private 候选、顺序开关或映射预分配器。

## 2. 公开 ABI

### 2.1 v1 兼容拒绝

以下既有类型名和布局继续代表 v1：

- `L2状态新增请求`、`L2状态写入结果`。
- `L2状态动态原子发布请求`、`L2状态动态原子发布结果`。

`新增状态(const L2状态新增请求&)` 与 `发布状态动态原子迁移(const L2状态动态原子发布请求&) noexcept` 只返回公共入口拒绝，零载荷、零写、零代次。v1 名字不得改绑 v2。

### 2.2 首态 v2

`L2状态首态请求_v2` 的物理顺序：

```cpp
L2状态首态请求头_v2 请求头;
L2结构幂等身份 幂等身份;
L2存在身份 主体存在;
L2特征实例身份 特征实例;
L2原始值材料 精确值材料;
L2原始值材料 时间值材料;
稳定编码 来源稳定编码;
```

首态专属版本为 2，共同 `L2结构请求头` 版本仍为 1。唯一写函数：

```cpp
L2状态首态结果_v2
L2状态结构服务::新增状态_v2(const L2状态首态请求_v2&) noexcept;
```

`L2状态首态结果_v2` 的物理顺序：

```cpp
L2结构结果头 结果头;
std::uint32_t 专属合同版本;
L2状态首态操作状态_v2 操作状态;
std::optional<L2状态事实> 状态;
std::optional<L2状态自有关系引用> 自有关系;
std::optional<L2状态当前选择关系引用> 当前选择关系;
```

首次和精确重复成功时三项载荷完整，`结果头.事实截止代次` 与 `变更事实代次` 均为首次 G1。提交后读回失败为公共内部不一致 + 专用已可能发布，保留非零首次 G1，三项载荷为空，成功否。

### 2.3 当前与历史选择读取

```cpp
L2状态当前选择读取结果
读取特征实例当前状态选择(const L2状态当前选择读取请求&) const noexcept;

L2状态历史选择读取结果
读取特征实例历史状态选择(const L2状态历史选择读取请求&) const noexcept;
```

当前请求含共同请求头和特征实例。历史请求另含非零历史截止，且历史截止不得超过请求头绑定的当前 G0。当前一条结果携带选择关系和状态；历史 0 条是成功空快照，1 条携带截止时选择和状态，晚于截止的未来退出不出现在快照中。

### 2.4 迁移 v2

`L2状态动态迁移请求_v2` 的物理顺序：

```cpp
L2状态动态迁移请求头_v2 请求头;
L2结构幂等身份 幂等身份;
L2存在身份 主体存在;
L2状态身份 旧当前状态;
L2特征实例身份 新状态特征实例;
L2原始值材料 新状态精确值材料;
L2原始值材料 新状态时间值材料;
L2原始值材料 动态起始时间材料;
L2原始值材料 动态结束时间材料;
稳定编码 来源方法稳定编码;
L2状态当前选择关系引用 旧当前选择;
```

唯一迁移写函数：

```cpp
L2状态动态迁移结果_v2
L2状态动态原子发布服务::发布状态动态原子迁移_v2(
    const L2状态动态迁移请求_v2&) noexcept;
```

结果依次包含公共头、专属版本、专用状态、新状态、新状态自有关系、新动态、新动态自有关系、新当前选择、已退出旧当前选择和共同事实截止代次。成功时六项载荷完整，公共变更代次和共同截止均为首次 G1；旧状态事实没有退出字段，也不得退出。

## 3. L1 原子事务

1. 外层状态写端口和动态写端口验证同一 L1 运行包、不同 owner 及请求 owner 绑定；普通 L1 服务引用不是写能力。
2. 仓库先验证合同、参与者、owner 和组合幂等身份。
3. 跨 owner 幂等账在 G0 比较之前裁决。同键同完整请求直接投影首次结果为精确重复，零候选、零应用、零新代次；同键异请求为幂等冲突。
4. 新请求必须满足共同 G0 等于当前代次。
5. 写集内部按本地键升序规范化。状态参与者先在候选形成 G1 和状态映射；动态参与者仅在候选内部以 G1 应用，并用状态映射解析后状态跨参与者引用。
6. 动态候选内部产生的 G2 在交换前统一投影为 G1；当前/历史事实、仓库当前代次及两份 owner 首次写入账的结果代次均统一为 G1。任何统一失败都不交换。
7. 全局闭包通过后写入跨 owner 幂等账并一次交换候选。公开 L1 结果只返回一个 `共同事实代次=G1` 和两份完整稳定编码映射。

L2 迁移组合幂等键使用域 XOR。若合法输入恰好映射为零，则映射为域常量；域常量原像是被拒绝的输入零，因此合法输入仍一一映射且结果永不为零。

## 4. L2 写前与重放

首次请求在 G0 读取登记、端点、旧状态和旧当前选择并形成完整 L1 请求。重放时当前代次已经超过原 G0，L2 只允许重构同一规范化请求并交给 L1 幂等账裁决；它不把旧选择再次当作当前事实验证。新幂等键携带旧 G0 时仍由 L1 返回事实代次漂移；同键任一字段变化由 L1 返回幂等冲突。

首态同理：首次写前验证当前选择为空；原请求重放时重构同一状态 owner 写集，由 owner 幂等账先于 G0 裁决。

## 5. 发布后正式读回

### 5.1 首次提交

首次提交后必须先以 G1 调用正式当前选择入口。只有状态和选择仍在同一 G1 当前闭合时，才继续读取 G1 历史状态/选择快照并返回成功。若此间出现并发代次推进或读回异常，返回已可能发布，不回滚。

迁移首次提交同样先以 G1 正式读取新当前选择，再以 G1 历史读取新状态、新选择、新动态、旧选择和旧状态。历史快照用于冻结本事务结果；调用者需要“现在仍当前”时必须另调当前选择入口。

### 5.2 精确重复

精确重复取得首次 G1 后，以本次当前代次作为历史读取请求头、以首次 G1 作为历史截止，重构首次状态/选择/动态证据。这样即使后续已发生合法迁移，原请求仍可按原键收束，但不会谎称首次选择现在仍为当前。

结果中的 `共同事实截止代次`、公共 `事实截止代次` 和 `变更事实代次` 在首态/迁移成功结果中均为首次 G1。

### 5.3 故障接缝

测试宏 `ARCH_L1_L2_STATE_SELECTION_VALIDATION` 只提供一次性故障开关。故障命中点是 L1 已提交后的第一次正式当前选择独立读取；开关命中后立即恢复。首次返回已可能发布，第二次同键调用必须走精确重复并从首次 G1 历史快照读回，事实代次不得推进。
