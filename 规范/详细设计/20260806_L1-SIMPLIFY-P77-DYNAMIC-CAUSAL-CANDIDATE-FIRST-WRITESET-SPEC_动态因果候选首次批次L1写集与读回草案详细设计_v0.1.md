# L1-SIMPLIFY-P77 动态因果候选首次批次 L1 写集与读回草案详细设计 v0.1

日期：2026-08-06

状态：待激活

## 1. 目标与最早缺口裁决

P76 已冻结 `动态事件因果候选键`、`待应用确认`、时间有向无环、材料不足跳过和合法空投影，
所以再建立一份候选身份规格会成为第二解释者。当前又没有候选稳定编码、L1 写集、发布后读回、
正式读取或应用确认事实；直接设计发布者会迫使它临场决定首次领域登记和候选事实形状。

因此 P76 后的最早独立叶是唯一纯值数据操作
`L1动态因果候选首次写集数据操作::形成动态因果候选首次批次L1草案`。它消费调用方已有的
P76 成功投影，把第一批非空候选确定映射为共享领域登记、连续本地键、L1 三类创建写项、
属性槽和精确发布后读回计划。合法空投影返回 `合法空`，不为“什么也不知道”预建登记。

本叶本身写入数为0，不取得 L1/P15 权限，不分配稳定编码，不形成幂等、摘要、操作标签、
事务或发布结果。后继原子发布者才可把该草案装入一次 L1 v2 提交；正式候选读取、应用确认、
已确认因果读取和 `安全直接因果图提供者` 均在其后。

## 2. 正式依据与能力复用

- 用户裁决：因果来自动态，动作不是来源或前提；材料不足跳过；候选与已确认因果分权；
  类型/对象层往复允许而事件级按时间 DAG。
- 用户工程裁决：仅一个生产程序/可执行目标；专项只可经该程序既有或正式冻结薄入口运行；
  只以正式日志做人读观察，日志不是机器事实。
- 用户范围裁决：当前不覆盖崩溃、异常终止、断电、重启或跨进程恢复/重放。
- 1190、4190、4210、4220、4310、4320、4015、4030—4050、6150 与 P76 正式合同。
- P15 v0.29 代码结果已进入 main、计划索引现已退出；本叶只复用当前 L1 v2 公开写项/读回
  DTO，不把 P15 计划状态当作可执行依赖，不复制其幂等、双摘要、证据或恢复内部语义。
- 旧 `轻量因果` 只记录轻量引用；旧 `因果完整结构键` 是概率模式身份，二者都不能承载
  P76 事件候选。
- `安全直接因果图提供者` 当前只有抽象和隔离替身，且只可消费后继已确认正式因果，不能
  反向成为候选来源。

正式刷新基线为 `main == origin/main == 11cf70334c5be37a9ea180ef909860b3a7f222cf`，
P76 plan blob 为 `253559d7c46106015d5212991162149f72076ffd`。本次增量精确只改变计划索引中
P14 v0.2 与 P15 v0.29 两行：P14 可执行、P15 已退出；P16 与 P76 状态未改。P14 八路径与
P77 三文档零路径、零语义重叠，故不阻断 P77 文档发布；P77 后续代码执行仍须等待 P14
释放工程、filters、启动、构建、自检和模块扫描资源。本设计不修改或重解释上述索引状态。

## 5. 首次登记与候选事实形状

设 P76 候选数为 `N`。本叶只接受 `N > 0` 的首次非空领域批次；后继发布者必须从当前正式
读取证明候选领域登记尚不存在，不能把本草案用于后续增量批次。增量候选写集与登记读取是
后继独立目标，不在本叶制造双模式解释。

节点本地键连续固定：

| 本地键 | 节点 |
| --- | --- |
| 1 | 动态因果候选服务，普通节点 |
| 2 | 动态因果候选结构关系类型，普通节点 |
| 3—6 | 合同版本、真实性、投影规则、排序规则属性类型，`I64` |
| 7—9 | 条件时间、结果时间、来源截止属性类型，`U64组` |
| 10—`9+N` | 按 P76 候选组顺序建立的候选普通节点 |

每个候选节点形成七个不可变值和七个当前槽：

1. 候选合同版本=`动态因果候选合同版本`，I64；
2. 真实性=`待应用确认(1)`，I64；
3. 投影规则版本，I64；
4. 排序规则版本，I64；
5. 条件发生时间，单元素 U64 组；
6. 结果发生时间，单元素 U64 组；
7. 来源事实截止代次，单元素 U64 组。

所有值的 `来源节点` 固定引用本地键1。不得以日志时间、系统时钟、字符串、裸字节或通用
I64 替代 U64 时间/代次材料。

每个候选形成八条同一关系类型的有向关系，源均为候选节点，目标依次为：本地候选服务、
P76 世界根、场景、主体、被改变目标、条件状态、结果状态、证据动态；角色固定1—8。
角色9/10为动作和方法运行保留，写入数必须为0。证据动态已经锚定 P76 来源链，不复制关系20
角色9材料。类型或对象后来反向变化可以形成新的较晚候选；不得合并、覆盖或因此判定事件环。

## 6. 连续键、数量与读回

本地键顺序固定为节点、值、关系：

```text
节点：1 .. 9+N
值：10+N .. 9+8N
关系：10+8N .. 9+16N
```

精确数量为：

```text
新节点 = 9 + N
新值 = 7N
新关系 = 8N
属性槽变更 = 7N
退出事实 = 0
首次新编码 = 9 + 16N
发布后读回 = 9 + 23N
```

读回计划版本固定为 `L1通用发布后读回计划版本`，按节点、关系、值、属性槽排序；同类按
本地键，槽按候选节点键与属性类型键排序。节点/关系/值均要求创建代次为本次发布且当前；
槽要求当前值等于对应值本地键。计划必须覆盖全部新事实和槽，不多读、不漏读，退出读回为0。

## 7. 输入互证与状态分账

入口在任何分配前验证请求合同/规则版本非零且精确、预期事实代次非零、P76 投影合同/投影/
排序版本精确、世界根非零、完整标记为真、事实截止等于请求预期代次，并满足
`已检查动态数 == 候选数 + 跳过数`。格式错误为 `入口拒绝`；P76 版本不等为 `版本漂移`。

空候选组且计数闭合返回 `合法空`。非空时逐候选复核：

- 真实性只能是待应用确认，动作身份和方法运行身份都为空；
- 候选键与条件事实、结果事实、动态证据、世界根和截止逐字段互证；
- `0 < 条件时间 < 结果时间`，创建代次均不晚于截止；
- 输入严格按 `(结果时间, 条件时间, 证据动态编码)` 升序且候选键不重复；
- 各事件边时间递增；类型/对象身份往复不作为事件环；
- 全部稳定目标有效，关系角色1—8唯一，9/10为0。

合法形状内互证失败、连续键溢出、数量公式破坏、悬空引用、读回不全或未知异常返回
`内部不一致`；`std::bad_alloc` 返回 `资源失败`。所有非成功都保证空草案和零外部写入。

## 8. 生命周期、事务与边界

P77 草案是调用方拥有的不可变临时纯值，函数返回后不保留缓存或可变引用。它不形成
`L1写集请求`，不拥有幂等键、领域意图凭证、执行证据、摘要、稳定编码映射、许可、锁、
候选确认/撤销、提交或发布结果。正常进程内事务边界完整留给后继发布者；后继必须一次提交
整个首次非空批次，不能把登记与候选拆成可见的两个代次。

本叶不覆盖崩溃与跨进程恢复；不设计恢复介质、启动扫描、跨进程重放或成功账。日志只观察
同一生产程序的输入分类、数量、状态与拒绝分支，不是候选事实或完成证据。
