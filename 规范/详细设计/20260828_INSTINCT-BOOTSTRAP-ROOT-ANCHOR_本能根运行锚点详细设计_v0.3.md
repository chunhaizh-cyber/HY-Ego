# INSTINCT-BOOTSTRAP-ROOT-ANCHOR 本能根运行锚点详细设计 v0.3

日期：2026-08-28

状态：设计候选，待创建侧验证与发布

## 1. 目标与边界

本设计实现阶段一本能根运行锚点。应用启动在唯一自我、四本体根和方法登记根成功后，自我线程创建前，建立或恢复两套根材料并按同一事实截止完整读回：

```text
唯一自我
+ 安全根：一阶特征定义、唯一自我实例、当前值、初始状态、比较注册、目标合同、根需求、列表项
+ 服务根：一阶特征定义、唯一自我实例、当前值、初始状态、比较注册、目标合同、根需求、列表项
+ 两份 M-X 二次特征概念定义
+ 两个根需求父为空证明
```

本阶段不实现根差值周期计算、具体需求形成、任务筹办、结果结算、动态迁移或治理循环算法。差值具体值按需形成并用完即弃；锚点不建立新的持久节点族、角色关系、第二 owner、第二索引或第二当前事实。

## 2. 冻结常量与业务语义

```text
M  = INT64_MAX = 9223372036854775807
A0 = V0 = M / 2 = 4611686018427387903
M % 2 = 1，余数舍弃
安全根目标 = M
服务根目标 = M
```

业务权威顺序：

```text
业务规则确定特征当前值
→ 当前值成为目标比较的唯一权威
→ 同一事务记录初始状态或后继状态
→ 有前后状态变化时才形成动态
```

首次赋值形成当前值、初始状态和当前状态选择，不形成动态。状态、动态只承担历史、来源和变化证据，不得反推或替代当前值。

## 3. 固定幂等身份命名空间

本合同为业务幂等身份保留显式 64 位命名空间：

```text
0x494E'5354'01RR'00KK

0x494E5354 = ASCII "INST"
01         = 本能根锚点语义纪元 v1
RR         = 01 安全根，02 服务根
KK         = 本表固定操作序号
```

所有值逐字写入代码，不在运行期通过加法、哈希、名称、路径、地址、时间或创建顺序生成：

| 用途 | 安全根 | 服务根 |
| --- | --- | --- |
| 一阶特征定义 | `0x494E'5354'0101'0001` | `0x494E'5354'0102'0001` |
| `M-X` 二次概念定义 | `0x494E'5354'0101'0002` | `0x494E'5354'0102'0002` |
| 唯一自我特征实例 | `0x494E'5354'0101'0003` | `0x494E'5354'0102'0003` |
| 首值 | `0x494E'5354'0101'0004` | `0x494E'5354'0102'0004` |
| 初始状态 | `0x494E'5354'0101'0005` | `0x494E'5354'0102'0005` |
| L1 双参与者组合 | `0x494E'5354'0101'0006` | `0x494E'5354'0102'0006` |
| 目标判断比较注册 | `0x494E'5354'0101'0007` | `0x494E'5354'0102'0007` |
| `I64_MAX` 目标合同 | `0x494E'5354'0101'0008` | `0x494E'5354'0102'0008` |
| 建需求并建立列表项 | `0x494E'5354'0101'0009` | `0x494E'5354'0102'0009` |
| 建需求并加入既有列表项 | `0x494E'5354'0101'000A` | `0x494E'5354'0102'000A` |

共享派生规则身份固定为 `0x494E'5354'0100'0031`，规则版本固定为 1。该身份是强类型派生规则身份，不是节点、关系或值的稳定编码。

碰撞约束：上述数值在所有 C++ 承载类型和 owner 间均不得复用；已发布或退役后永久保留。不兼容语义使用新纪元或新序号。固定幂等身份只恢复首次规范化请求，不决定任何事实稳定编码。每个结构请求的 `来源稳定编码` 必须引用已发布事实：一阶定义来源为唯一自我，二次概念、实例、首值、首态和比较注册来源为对应一阶根特征定义，目标合同来源为对应比较注册，根需求来源为对应目标合同；禁止填入本表常量、哈希或猜测编码。

## 4. 角色恢复与最终绑定

安全和服务角色分别由本表两组固定幂等身份恢复，禁止按名称、列表位置、创建顺序、稳定编码大小或目标值猜测。固定幂等身份不是角色节点、第二索引或第二事实 owner。

```text
特征定义 = 固定定义幂等身份首次完整读回 + 阶次/来源/派生规则互证
特征实例 = 固定实例幂等身份首次完整读回 + 唯一自我/定义互证
目标合同 = 固定目标合同幂等身份首次完整读回 + 定义/比较注册/M/允许关系位互证
根需求   = 固定需求幂等身份结果或精确目标读取 + 所属/宿主/定义/合同互证
列表项   = 精确目标读取 + 当前成员关系互证
```

初始化提供者最后冻结 `Gfinal`，按该截止重新读回全部材料；只有安全组逐项落入锚点安全字段、服务组逐项落入锚点服务字段且两组不交叉，才形成值式角色绑定。锚点不持久化，重启后由正式事实重新形成。

| 状态 | 语义 | 合同 | 截止 |

依赖方向固定为 `L2状态结构服务 -> L2特征结构服务 -> L1`。状态服务已经依赖特征服务；为该协作把构造参数和成员引用从 `const L2特征结构服务&` 收紧为 `L2特征结构服务&`，不得增加反向 import。内部协作合同固定为：

```cpp
// L2特征结构服务 private；仅 L2状态结构服务可调用
首值参与者预形成结果_v1 预形成首值参与者_v1(
    const L2特征首值初始状态原子形成请求_v1&) noexcept;

// L2状态结构服务 private

    const L2特征首值初始状态原子形成请求_v1&) noexcept;
```

两种预形成结果均为非导出、不可持久、不可复制到业务层的强类型闭包，分别只含本 owner 的 `L1跨所有者原子参与者写集`、本地键和自校验结果；不得暴露可变仓库、写端口或通用写集。实现可采用 private nested type、受限 friend 或模块私有协作函数，但公开 ABI 和依赖方向不得改变。

事务映射固定为：

```text
L1请求.状态写集 = 状态 owner 的初态参与者
L1请求.动态写集 = 特征 owner 的首值参与者
接收写端口       = 状态 owner 写端口
另一参与者端口   = 特征 owner 写端口
```

`状态写集/动态写集` 仅是现行 L1 双槽运输名称；本入口不形成动态。状态参与者可以引用特征参与者的首值本地键。特征 owner 唯一形成“首值事实 + 当前属性槽”；状态 owner 唯一形成“初始状态 + 主体/实例关系 + 当前状态选择”。两个参与者预形成完毕并证明同一 `G0` 后才调用一次 L1 原子运输。

| 状态 | 语义 | 三项载荷 | 共同代次 |
| --- | --- | --- | --- |
| 已提交 | 本次首次同 G1 发布 | 完整 | G1 |
| 精确重复 | 组合、首值、首态三键与完整规范化请求相同 | 首次完整投影 | 首次 G1 |
| 入口拒绝 | 坏版本、坏 G0、零身份、值域/时间/来源无效 | 空 | 0 |
| 当前性漂移 | 参与者或提交不再绑定请求 G0 | 空 | 0 |
| 幂等冲突 | 三键任一绑定异义完整请求 | 空 | 0 |
| 引用冲突 | 主体、实例、定义、材料类型或 owner 绑定错误 | 空 | 0 |
| 材料未闭合 | 当前值和当前状态仅一边已有，或首次账闭包不完整 | 空 | 0 |
| 资源失败 | 资源失败且零公开发布 | 空 | 0 |
| 内部不一致 | 端口、映射、载荷、代次或读回矛盾 | 空 | 0 |
| 已可能发布 | L1 发布结果未知，只允许原完整请求收敛 | 空 | 0 |

`成功()` 当且仅当状态为 `已提交` 或 `精确重复`，三项载荷都存在、逐项完整且 `共同事实代次` 非零。成功后必须证明当前值、初始状态和当前选择的形成代次均等于共同 G1，初态精确值等于首值材料，主体/实例/来源一致，动态新增量为零。所有非成功包括 `已可能发布` 均为三项空载荷、共同代次 0。

### 5.3 旧状态入口边界

本计划不恢复、不修改、不调用旧 `新增状态_v2`。锚点首值首态只消费本节新具名组合入口；旧入口继续服从 0050 的退役/禁止消费口径，不得通过修复其拒绝壳或拼接两个公开写入口实现本目标。

```cpp
        const L2存在结构服务&,
        L2特征结构服务&,
        L2状态结构服务&,
        L2需求结构服务&) noexcept;

    本能根运行初始化结果_v1 初始化并读取本能根运行锚点_v1(
        const 本能根运行初始化请求_v1&) noexcept;
};
```

provider 不直接持有或暴露 L1 服务。每一步 `G0` 从已装配的状态结构服务正式读取当前事实代次，全部写入只经各 L2 owner 的既有公开入口；这一依赖收窄避免为启动编排扩大 `普通应用上下文` 的 L1 公开面。

固定顺序：

```text
验证唯一自我
→ 两份一阶定义
→ 两份 M-X 二次概念定义
→ 两份唯一自我特征实例
→ 缺失时分别执行首值首态单事务
→ 两份目标判断比较注册
→ 两份 I64_MAX 目标状态合同
→ 两份根需求、列表项和成员关系
→ 冻结 Gfinal
→ 全量正式重读
→ 形成锚点
```

顺序只用于确定施工和故障收敛，不赋予身份语义。已有部分材料且本次至少发布一项缺失材料、最终全部闭合时返回 `已形成`；本次零新发布且全部材料正式恢复、最终闭合时返回 `已恢复`。已形成定义但实例未形成、已形成合同但需求未形成等可安全补齐阶段不是失败；值/状态仅一边存在、固定身份异义、角色材料已退出或最终关系不闭合才分别返回结构化非成功。

一阶定义实际阶次为 1、直接来源空、派生规则空。二次概念实际阶次为 2，直接来源为对应一阶定义，派生规则为共享 `M-X` 规则身份和版本 1；不得形成二次实例、当前值、状态或动态。

首次根值固定为 `M/2`，初态精确值相同，初态时间使用本次请求的大于零 UTC Unix epoch 纳秒。原组合请求必须保存完整时间；同进程重试复用原时间，跨进程已有首态账时按首次材料恢复，不以新启动时间重放同一首态身份。重启不得重置已经变化的当前值。

两份比较注册固定为目标判断、标量有序比较、I64、左角色当前事实、右角色目标状态、右减左、允许结果位 `0b010`、精确无量化、相等容差 0；单位、维度、分量角色均逐字绑定对应一阶根特征定义身份。两份目标合同均为 `目标I64=M`、允许关系位 `0b010`，分别绑定各自定义和比较注册。

根需求目标四元组固定为所属存在/目标宿主均为唯一自我、目标特征为对应一阶定义、目标合同为对应 `I64_MAX` 合同，父为空、父子顺序 0。列表项不存在时用“建需求并建立列表项”固定键；列表项已存在且需求不存在时用“建需求并加入既有列表项”固定键。最终根需求组和父关系读取证明父为空，精确列表项和当前成员关系证明闭包。

## 8. 初始化状态矩阵

| 情况 | 状态 | 锚点 |
| --- | --- | --- |
| 本次至少一次新发布且最终同 `Gfinal` 闭合 | 已形成 | 完整 |
| 本次零新发布且全部正式恢复 | 已恢复 | 完整 |
| 坏合同、零自我或 UTC 为零 | 入口拒绝 | 空 |
| 任一最终读取漂移或截止不同 | 当前性漂移 | 空 |
| 固定幂等键绑定异义材料 | 幂等冲突 | 空 |
| 两根交叉、重复、类型或绑定错误 | 引用冲突 | 空 |
| 值/状态单边存在或关系闭包不完整 | 材料未闭合 | 空 |
| 固定角色的当前合同或必要材料已退出 | 角色已退出 | 空 |
| 原子发布结果未知且尚未按原请求收敛 | 已可能发布 | 空 |
| 分配或资源失败 | 资源失败 | 空 |
| 端口、映射、载荷或代次自相矛盾 | 内部不一致 | 空 |

`已可能发布` 保留原组合、首值和首态身份及完整请求。同进程只按原请求重试；跨进程先从持久恢复后的正式首次账和当前事实收敛，不用日志、缓存或猜测判定。

## 11. 验证矩阵与完成边界

未来外部验收矩阵：空库首次形成；同进程精确重复；跨进程恢复；当前值变化后重启不重置；中点和余数；两根角色不交叉；比较注册和目标合同逐字段一致；首值/首态/选择同 G1 且零动态；每个非原子步骤后恢复；根实例 0/N 不任选；值/状态单边失败；合同退出；已可能发布原键收敛；final read 漂移；二次概念零实例/值/状态/动态；差值边界；初始化失败零线程创建/开门；Debug/Release 一致。

本阶段按用户要求不运行上述业务验收，全部记为 `NOT_RUN`。本轮只要求文档门禁、代码静态边界以及 VS 2022 `v143` 的 Debug/Release 隔离根工程 Rebuild；构建通过不升级为业务验收通过。

完成只证明本能根运行锚点公开能力已发布并进入停门中的自我线程，不证明根需求展开、具体需求、任务、方法、结果结算或整体自我治理闭环完成。
