# DATA-L2 抽象目标状态合同 CRUD 详细设计

日期：2026-08-15
版本：v0.1
身份：`DATA-L2-ABSTRACT-TARGET-STATE-CONTRACT-CRUD`

## 1. 目标与完成边界

在唯一 `L2状态结构服务` 内增加第一份可施工的抽象目标状态合同：把一个抽象特征定义、该特征用于目标判断的当前 I64 比较注册、不可变 I64 目标材料和允许命中的三态关系集合冻结为独立、可增改退、可当前 / 历史读取的强类型结构。

本叶只承接 `I64 + 标量有序比较与安全差异`。它不创建实例状态，不把目标合同包装成 `L2状态身份`，不判断当前事实是否满足目标，不写需求、任务、方法、动态、因果或结算事实，也不实现区间、枚举集合、向量、角度、空间、形状或时间序列目标。

完成只证明目标状态合同的 DATA-L2 结构和公开 ABI 存在；需求 owner 以后只引用本合同身份，不复制目标材料、比较注册或允许关系。

## 2. 正式依据与当前事实

- 0050：DATA-L2 可以保存带结构类型语义的状态和治理记录，但不得判断需求有效、任务完成或方法成功；每类结构只有一个写入服务。
- 1160：长期抽象状态模板材料由状态领域服务准入，必须归属于抽象特征及其值域，不得形成平行状态树。
- 3100、5100：单需求只绑定一个目标状态合同；目标比较由特征、状态或正式判断收束合同完成，需求领域不得直接比较原始值。
- 4130、4180：目标判断固定比较“左=当前事实、右=目标状态”，三态比较与允许关系命中分离；比较注册、算法版本、单位、维度、左右角色和误差合同必须正式读取。
- 4230：现行实例状态由 `L2状态身份`、主体、特征实例、精确值、时间值和来源构成；状态 owner 已有唯一写端口，状态服务已依赖特征服务。
- `DATA-L2-FEATURE-I64-COMPARISON-REGISTRY-AND-COMPARE v0.1` 已冻结 `L2特征比较注册身份`、目标判断注册当前 / 历史读取及 I64 比较 ABI，但代码尚未实现。

当前 `L2状态结构.数据.h` 与 `服务.L2状态结构.ixx` 只实现实例状态。普通应用和现有 DATA-L2 结构聚合已经持有同一个 `L2状态结构服务`，无需新增 getter、聚合或 owner。

## 3. 身份与所有权裁决

### 3.1 不新增节点族

目标状态合同不是已经发生的实例状态，固定使用独立：

```cpp
struct L2目标状态合同身份 final {
    稳定编码 值;
    explicit L2目标状态合同身份(稳定编码 编码 = {}) noexcept : 值(编码) {}
    friend bool operator==(const L2目标状态合同身份&,
        const L2目标状态合同身份&) = default;
};
```

它不加入 `L2结构公共.数据.h`，不新增 `L2节点族`，不取得状态族归属关系，也不得隐式或显式转换为 `L2状态身份`。因此 `读取状态身份来源(...)`、动态和因果的实例状态端点证明不能接受目标合同。

目标合同采用与特征比较注册相同的“owner 内专属登记结构”证明：状态 owner + 合同节点 + 两条专属关系 + 两个专属属性值 + 同截止生命周期共同成立时，`L2目标状态合同身份` 才成立。它不是第二 owner、内部缓存或平行状态树。

### 3.2 唯一 owner

- 节点、两条关系和两个值全部由现有状态 owner 一笔 owner-scoped 写集发布；
- 特征定义和比较注册只经 `L2特征结构服务` 的公开读取核对，状态服务不取得特征 owner 端口；
- 需求、任务或业务 provider 只能持有目标合同身份和完整值式读回，不取得目标合同写端口。

## 4. 公开 DTO

全部 DTO 和纯值 helper 定义在 `海中鱼巣/领域/L2状态结构.数据.h`。该头在普通包含模式下增加对 `L2特征结构.数据.h` 的单向包含；模块模式继续由 `服务.L2状态结构.ixx` 已有的特征服务 import 提供类型，禁止复制 `L2特征比较注册身份` 或相关枚举。

### 4.1 稳定常量与结构类型登记

```cpp
struct L2目标状态比较注册关系类型身份 final { 稳定编码 值; ... };
```

请求有效、登记完整和结果成功 helper 均为公开纯值函数。

### 4.2 合同事实

允许关系位固定为：当前低于目标=1、当前达到目标=2、当前高于目标=4。字段取值只能为 1—7，0 和未知位拒绝。它描述哪些比较关系满足目标，不是排序比较量、差异材料或永久满足 bool。

```cpp
struct L2目标状态合同事实 final {
    L2目标状态合同身份 身份;
    L2特征定义身份 特征定义;
    L2特征比较注册身份 比较注册;
    L2特征比较用途 比较用途 = L2特征比较用途::目标判断;
    std::int64_t 目标I64 = 0;
    std::uint8_t 允许关系位 = 0;
    std::uint32_t 规则版本 = L2目标状态合同规则版本;
    L2结构幂等身份 首次幂等身份;
    std::uint64_t 首次期望事实代次 = 0;
    稳定编码 来源稳定编码;
    稳定编码 特征定义关系稳定编码;
    稳定编码 比较注册关系稳定编码;
    稳定编码 目标值稳定编码;
    稳定编码 合同值稳定编码;
    L2生命周期 生命周期;
    friend bool operator==(const L2目标状态合同事实&,
        const L2目标状态合同事实&) = default;
};
```

`L2目标状态合同事实完整(事实, 截止)` 至少要求：

1. 身份、特征定义、比较注册、来源和四个自有稳定编码非零且互不复义；
2. 比较用途恰为目标判断，规则版本恰为 1，允许关系位为 1—7；
3. 首次幂等身份、首次期望事实代次非零，首次期望代次不晚于创建代次；
4. 生命周期在具名截止完整；当前读取时未退出，历史读取按历史截止投影；
5. 特征、注册、目标值和允许关系均来自同一合同读回，不用默认值或另一代次补齐。

### 4.3 请求与结果

```cpp
struct L2目标状态合同新增请求 final {
    L2结构请求头 请求头;
    L2结构幂等身份 幂等身份;

    L2特征比较注册身份 比较注册;
    std::int64_t 目标I64 = 0;
    std::uint8_t 允许关系位 = 0;
    std::uint32_t 规则版本 = L2目标状态合同规则版本;
    稳定编码 来源稳定编码;
};

struct L2目标状态合同替换请求 final {
    L2结构请求头 请求头;
    L2结构幂等身份 幂等身份;
    L2目标状态合同身份 旧合同;
    L2特征定义身份 特征定义;
    L2特征比较注册身份 比较注册;
    std::int64_t 新目标I64 = 0;
    std::uint8_t 新允许关系位 = 0;
    std::uint32_t 新规则版本 = L2目标状态合同规则版本;
    稳定编码 来源稳定编码;
};

struct L2目标状态合同退出请求 final {
    L2结构请求头 请求头;
    L2结构幂等身份 幂等身份;
    L2目标状态合同身份 合同;
    稳定编码 特征定义关系稳定编码;
    稳定编码 比较注册关系稳定编码;
    稳定编码 目标值稳定编码;
    稳定编码 合同值稳定编码;
};

struct L2目标状态合同完整读取请求 final {
    L2结构请求头 请求头;
    L2读取类别 读取类别 = L2读取类别::当前;
    L2目标状态合同身份 合同;
    std::uint64_t 历史截止事实代次 = 0;
};
```

新增、替换、退出分别使用独立结果类型，避免仅凭 `已提交` 猜测 optional 形状：

- `L2目标状态合同新增结果{结果头, optional<当前合同>, 成功()}`；
- `L2目标状态合同替换结果{结果头, optional<当前合同>, optional<已退出合同>, 成功()}`；
- `L2目标状态合同退出结果{结果头, optional<已退出合同>, 成功()}`；
- `L2目标状态合同完整读取结果{结果头, 读取类别, 历史截止事实代次, optional<合同>, 成功()}`。

四类请求有效、允许关系位有效、事实完整和四类成功谓词均公开。写成功只允许已提交 / 精确重复、非零截止、变更代次等于截止和精确 optional 形状；读取成功只允许已读取、非零截止、零变更和完整合同。全部非成功载荷为空、变更代次为空。

## 5. 物理结构与事务

### 5.1 结构类型登记

状态 owner 内使用全新私有幂等域建立 4 个类型节点：两种普通关系类型、I64 属性类型和 U64组属性类型。固定写集为 4/0/0/0/0，不改变现有实例状态结构类型登记及其规则版本。

服务构造时在现有状态 owner 内独立建立 / 精确重复收敛目标合同结构类型登记；定位缓存只作非权威加速，公开读取必须回到 L1 当前事实。

### 5.2 新增写集

一次状态 owner 事务固定形成：

- 一个普通目标合同节点；
- “合同 -> 特征定义”关系一条，专属关系类型，角色=1；
- “合同 -> 比较注册”关系一条，专属关系类型，角色=1；
- 一个 I64 目标值及当前槽；
- 一个 U64组合同值及当前槽。

合同节点不得形成状态族归属、实例状态主体 / 特征实例关系或实例状态精确 / 时间值槽。

U64组固定位置为：合同版本、目标合同规则版本、比较用途、允许关系位、首次幂等身份、首次期望事实代次。两个值的来源编码均为请求的非零来源稳定编码。

新增写前以同一非零守卫正式读取：结构类型登记、完整当前特征定义和“特征定义 + 目标判断”的唯一当前比较注册。读取注册身份必须逐字段等于请求，注册合同必须为 I64 标量算法、左右角色“当前事实 / 目标状态”、方向右减左，且允许输出具名关系。任一不满足在第一笔写前结构化拒绝。

### 5.3 替换与退出

替换在一笔状态 owner 写集中退出旧合同节点、两条关系和两个值，并建立全新合同节点、关系和值；旧合同身份永久保留，新合同获得新身份。不得原地改值、复活旧合同或只替换部分关系。

退出在一笔写集中退出具名合同节点、两条请求回显关系和两个请求回显值。仍被需求、任务、方法或其它当前关系引用时由 L1 当前引用保护返回 `引用冲突`，不得反向调用这些服务或扫描后代替调用方清理。

特征定义或比较注册的替换 / 退出同样受当前目标合同关系保护。跨 owner 更新不伪装原子；调用方必须先闭合旧引用，再更新被引用结构，再建立新合同。

新增、替换、退出均使用完整请求幂等：同键同义返回首次结果，同键异义返回幂等冲突；仅明确零变化且无首次结果的事实代次漂移允许保留幂等身份、正式重读后重组。资源失败、异常或发布结果未知只能原完整请求重放。

## 6. 当前与历史读取

当前读取在请求非零守卫的一次一致投影中取得合同节点、两条关系、两个值和各生命周期，并经特征服务当前读取证明特征定义和目标判断比较注册仍完整、当前且身份相等。缺失合同返回 `未找到`，已退出返回 `已退出`；半结构、错 owner、错类型、错端点、重复关系、坏向量、状态族归属混入、实例状态关系 / 值混入或混代返回 `内部不一致`，不得过滤坏项后伪装未找到。

历史读取使用显式历史截止重建合同节点、关系和值；特征定义和比较注册分别经其历史读取在同一截止互证。截止早于合同创建返回 `未找到`；截止达到创建后即使合同后来退出，也返回该截止投影和完整生命周期。不得用当前注册或当前特征补历史缺项。

本叶不增加按内容、特征或允许关系查询。需求写入已经持有具名目标合同身份时调用完整读取；若以后存在正式去重需求，应另行冻结条件查询，不得让执行者扫描全部状态 owner 节点。

## 7. 服务函数与控制流

全部入口原位增加到 `海中鱼巣/领域/服务.L2状态结构.ixx` 的现有 `L2状态结构服务`：

```cpp

    const L2目标状态合同结构类型登记请求& 请求);

    const L2目标状态合同替换请求& 请求);
L2目标状态合同退出结果 退出目标状态合同(
    const L2目标状态合同退出请求& 请求);

    const L2目标状态合同完整读取请求& 请求) const;
```

服务构造签名、现有实例状态入口、状态 owner 交付、普通应用 getter、聚合 getter、工程和 filters 不变。现有状态服务对特征服务的单向依赖被复用；不新增反向 import、第二状态服务、目标判断业务服务或通用 owner 选择器。

异常映射沿现有服务：`std::bad_alloc`、`std::length_error` 返回资源失败；其它异常返回内部不一致。入口不 sleep、不忙重试、不写日志证明成功，不引入 deadline 或生产 seam。

## 8. 验证矩阵

施工期最低验证：

1. 根工程 x64 Debug / Release Rebuild；
2. 两个现有状态生产文件之外工程零差异；
3. 目标合同身份与 `L2状态身份` 编译期不可互换，公共节点族闭集零变化；
4. 结构类型登记固定四节点，实例状态登记与规则版本零变化；
5. 新增固定 1 节点 + 2 关系 + 2 值 + 2 槽，零状态族归属；
6. I64 极值目标材料合法保存，允许关系位 1—7 全部准入，0 / 未知位拒绝；
7. 错用途、错左右角色、无具名关系输出能力、错注册身份、已退出注册和混代均零写拒绝；
8. 精确重复、同键异义、漂移、资源失败 / 发布未知原请求保留；
9. 替换后新合同当前、旧合同历史可读；退出受当前引用保护，闭合后当前不可见且历史完整；
10. 当前 / 历史读回逐字段、同截止，半结构和实例状态混入精确失败；
11. `git diff --check`、strict `113/113`、UTF-8、白名单和生产零验证痕迹。

不建立独立专项验收。真实资源失败、发布未知、跨服务引用竞争、需求合法消费者和满足判断由后继实际使用判断；未发生即记录 `NOT_RUN`，不得以构建或静态总数升级为业务闭环。
