## 1. 修改对象、原因、目的和完成边界

修改对象是任务虚拟存在 Vt 的服务值特征 Fq，属于内部治理；不是现实自我的累计服务值。本叶把已有任务贡献算法真正写入 Fq，并让 K 冻结该值、直接父接收 R 与父 Fq 同次原子发表，消除 T 上旧累计字段的第二余额。实际计值、接收、迁移操作必须有自己的正式阶段和治理动作；实际 F 变化随后形成 C(T) 内的 S/D，并显式关联动作。

本叶不增内部治理需求或方法头，不把普通结算 M/Vm 作为内部能力定义的替身。继续调用已有 `结算已完成任务()`、`推进任务完成贡献()`，不改其公开参数/返回 ABI，因此已有 self/manager 生产调用直接消费新实现，而非新增无人调用的提供者。

完成边界是：新建 T 原子具备 Fq=0 与权威接管事实；可证明的旧 T 完成迁接；真实 Q/K/R 生产改用 Fq；非零变更有独立动作与唯一 S/D；所有相关读回、初始化、optional-M 消费者和旧 +1 保护保持一致。以下均不在本叶：最终 U/Fself 按 Q 入账、self 统一本能编排、普通子任务 R 后状态 9→12、方法 C(M)、新增 Q/R 因果发生窗口、运行测试和跨进程恢复。

依据为上位设计第2、4、6、8、10节及本窗口裁决；[0050](../0050_项目通用机器逻辑与禁止性规则总纲_20260721.md)、[1130](../1130_根规范_特征节点_20260720.md)、[1150](../1150_根规范_场景节点_20260720.md)、[1160](../1160_根规范_状态节点_20260720.md)、[1170](../1170_根规范_动态节点_20260720.md)、[1190](../1190_根规范_因果_20260720.md)、[3200](../3200_根规范_任务.md)和[6190](../6190_子规范_服务值治理结算与时间衰减.md)中未被具名裁决替代的 owner、状态、事实与直属结算约束继续适用。不在本叶修改上述规范。

## 3. 权威、不变量及幂等身份

1. 每 T 的唯一 Vt 独占 Fq，Fq 的当前非负 I64 是当前贡献 Q 的唯一权威；K.Q 是完成时的不可变交接证据。不得继续新写 `任务已接收贡献字段`。
2. 服务叶子完成时 Fq 从0到1；合法治理/非服务链叶子为0；非叶子当前 Fq 为已合法接收的直接 R 之和。未知叶子分类仍沿现有等待分支，绝不降成0；不在本叶扩白名单。
3. **直接接收之和不是所有 T 的当前值定义。** 服务叶子无 R，Fq=1合法。K=直接子汇总时 K.Q 与其冻结 R 和一致；K=服务叶子时 K.Q=1且无 R。已有合法 R 不因子任务后续合法重启/失败消失。
4. 发布 K 前复核来源已完成、真实 X/A、完整结果 S 闭包及全部直属子需求。缺任务/待归集不按0；沿既有失败/取消子处理，但已有冻结合法 R 仍计入。发布 K 时 Fq 必须等于待冻结 Q。
5. 发布 R 必须由 D→父D→唯一P 确认直属；唯一子K只能有一个R；父已封口K时不得再接收。R.Q 等于子 K.Q 和已权威子 Fq，`父新Q = 父当前Q + R.Q` 受检相加。
6. 零Q是合法值而不是“未准备”。Q=0的K/R仍正式发表，参与唯一性与防重，但不调同值F更新、不增命中、不造动作/S/D。
7. K/R完成重复只读回原事实，不再累加。已有K属于固定T/D/X/A；重启不新增结算轮次、不替换K来源。新请求X/A与既有K冻结X/A不同，或fresh状态已变化，沿既有 `预期已变化` 返回、零新动作/写入；正式旧K/R的只读证据仍可读取。坏K/R不是此合法过期分支，必须工程终止。
8. task锁覆盖核验、组合发表及组织收尾；F占用/凭据不是跨调用持锁。不同来源向同一父F串行 fresh读、受检加并发表，不能按消息快照覆盖。

## 4. 正式能力、阶段和接管事实

以下均由 task 唯一拥有，存储在其正式结构；不是方法头、需求、任务副本或通用事件系统。新增字段键按 task 既有 schema 建立/读回规范登记，强引用用节点字段，不用字符串。

### 4.1 三个独立贡献动作定义

任务集合根以新的 `任务贡献动作定义字段` 登记三个不同节点，节点类型 `任务贡献动作定义类型`，分别冻结 `来源计值=1`、`直接接收=2`、`权威迁移=3`。每个定义保存唯一操作种类、正式任务服务值FT及独立参数角色节点（角色节点由该定义唯一拥有）。角色类别是任务虚拟存在，规格恰含任务服务值FT；不复制Vm规格，不要求普通结算M存在。

只允许已登记且结构完整的定义被投影。缺M不能推断为治理；定义必须明确分类且通过 task owner 正式读取。旧 `任务已结算动作定义` 及其M投影保持原合同，不在本叶改其机器含义。

### 4.2 阶段 J 与来源矩阵

每个确有 Fq 变化的实际操作先创建稳定阶段 J，再登记一个动作。J 通过目标T的 `任务贡献动作阶段字段` 唯一归属；不复用 T/X/K 作为动作来源。J→动作不新存镜像，统一用动态 owner 的 `按来源查询动作(J)`。

| J种类 | 冻结来源/去重键 | 原子核心结果 |
| --- | --- | --- |
| 来源计值 | 目标T+真实完成X+A+种类；目标就是来源T | 新K及T→K |
| 直接接收 | 目标父P+来源子K+种类；从K冻结子T/X/A | 新R、P→R、K→唯一R |
| 权威迁移 | 目标T+待接管身份+种类；冻结旧K/直接R和旧小计证据 | 新权威接管事实H、T→H及删除旧小计 |

J字段固定为：节点类型、种类、所属目标T、T/Vt/stateF/实际目标F、动作定义、现实自我E及其真实场景、真实UTC动作时间、前S、旧值、新值、来源T、可选来源X/A/K、直接R证据组、可选原旧小计、可选 `阶段发表结果`。来源计值必须X/A、无来源K；接收必须来源K/子T及该K原X/A；迁移仅按已冻结证明填写可有可无的K/X/A，不造完成来源。直接R证据组只保存本次值来源的正式引用，不长期复制场景内容。

`阶段发表结果` 在 Fq核心与K/R/H同时发表时才追加：计值指K，接收指R，迁移指H。阶段存在/动作存在不代表F已发表；发表结果存在也不代表S/D收尾已完成。不可用一枚“已完成”bool代替精确结果读回。零值/同值分支不建立J。

只有完全读回原J、核心结果、唯一动作及关联D，才是精确重复。已登记J但动作/核心/后续组织不完整属于工程中断现场，保留并终止；本叶不自动重新执行，也不删除或重新发号掩盖未知发表。

### 4.3 权威接管事实 H

每T有唯一 `任务贡献权威接管字段` 指向H，H保存类型、T/Vt/Fq、接管来源（新建0或存量证据）、接管时Q、可选旧K、直接R组、可选原旧小计。H只是证明权威迁接完成时的不可变事实，不是当前余额，后续Q变化不改H.Q。

新T的H与T/Vt/Fq=0/Ct联合发布；不允许新T先交付、再补标记。旧T只有没有H才有资格按第8节迁接，不能以“F已存在”判断已迁移，也不能每次启动把F覆盖成K/R计算值。已有H却缺F、归属不合或当前F与适用K/R证据矛盾，属于损坏而非旧数据。

world有动作完成固定为：读J/唯一动作→验证前后S→挂后S→建立一个原子D→挂D→`关联动作结果(动作,D,导致变化)`→精确读回。前S和动作由建立入口挂到同一Ct；不得再调用无动作 `完成任务特征变化`，以免孤立前S被其严格读回拒绝或重复产生D。S时间满足前S≤真实动作进入时间<后S；不合成未来或前时间+1。

## 6. task内部写入与事务顺序

task新公开读回仅第5.1节两个override。其余保持既有公开贡献ABI。新私有成员在 `新_任务类.h/.cpp` 固定为：

```cpp
void 初始化任务贡献特征权威() noexcept;
稳定编码 建立任务贡献动作阶段(const 新任务贡献动作阶段&) noexcept;
void 提交任务贡献特征变化(const 新任务贡献动作阶段&,
    const 基础封存追加片段& 任务片段) noexcept;
void 核验任务贡献特征权威(稳定编码 任务节点) const noexcept;
```

阶段建立输入的节点/发表结果必须空；从已核验T、X/A或K/旧证据构造，owner分配J并固定来源。提交成员只接受已正式登记并已建立动作的J；任务片段由调用成员针对K/R/H构造，不开放给外部任意写入。

### 6.1 有实际F变化

1. task锁下fresh读取完整映射、源X/A/K、R、F和权威事实；求出新值并受检。真实自我actor从正式服务根D的目标E读取，核根角色/目标FT，再经已有存在/现实场景owner查得唯一所属场景。不能依赖线程名、最近动作、调用者裸E或普通M已登记。
2. task建立本次候选前S，预留它被J消费的state引用；新建J并按task原子请求挂目标T。前S/S→F、J→F等全部新增引用及K结果S引用预留均在F准备**之前**完成。J发表后即为应保留事实，不再按未消费候选删除。
3. world建立动作并挂前S/动作到Ct；此前不修改F或发布K/R。重复阶段只允许完整原结果读回，不对半阶段执行下一次实际动作。
4. `准备顶层I64更新(F,新值)`；核凭据目标/原值/新值及核心确有变化。基于完成上述引用后fresh快照，构造封存task片段：K或R或H、反向引用、J→发表结果；以及完整贡献保护集合、F与归属/H保护。新片段不得与feature核心各自改同一字段/节点生命周期。
5. `提交顶层I64更新(凭据,{任务片段})` 共同原子发表F核心和K/R/H写集。K/R还未发表时不能让读取者看到它们指向未完成F；各完整读回由task锁隔离。
6. `完成顶层I64更新`→`结束顶层I64更新`→`确保任务虚拟存在语义(T)`→精确读回F。随后建立后S，world完成并读回唯一动作D。
7. 原公开函数只有整条事实链读回后才返回原 `已建立/已接收` 等成功状态。

### 6.2 零值或已相同

来源服务叶计值0→1走上节；治理叶0→0、新K冻结已归集非叶Q、接收子Q=0都只构造task原子请求。完整保护F归属/当前值/特征历史及H、完整D/T/K/R/X/A/S前置，并保留原K结果S引用的owner预约/撤销协议。**不建立J/动作/S/D，不准备feature凭据，不增加F命中**。原子发表K或R（以及必要反向边）；新K.Q仍必须等于F。若前提变化则重新核验合法过期，不能发布按旧值计算结果。

### 6.3 工程失败与锁

准备失败/明确零提交且已有动作：取消未提交feature凭据释放占用，保留J/动作/前S并工程终止，不删除已发生动作。首次J尚未发表且可证明零消费者的候选可由state owner撤销预留/删除，顺序为撤引用后删候选；未知发表一律保留。F+task核心已发表后不得取消作回滚；完成、EC、S/D、Ct任一步出错，保留事实并日志、弹窗、终止。成功返回不可仅依据F已新值。

本叶只承诺F核心+K/R/H片段原子，**不承诺**前动作、EC、状态/动态、引用计数/场景列表全链单事务。feature token必须同线程/同owner收尾；任何下层锁内不新回调task，task只在各owner调用结束后调用下一个。token占用期间不得再添加S→F等入边；后S在结束占用后建立。

## 7. 全部贡献消费者迁接

`读取父贡献` 改成只读R和及去重，旧小计核验移入迁移专用分支；生产当前Q均经正式F读取。`读取完成贡献` 保持冻结分类与R证据核验。`读取任务完成结算`、`读取任务完成贡献交接`、`获取完成结算`和两条生产写入必须补H/F一致性，正式坏结构不能吞成nullopt/0；非本类/合法没有K仍保留原缺失合同。权威核验调用task内部原始K/R和F读取，不得递归调用已加入权威门的高层读回，避免K→权威核验→K的循环。

`贡献保护节点` 加入全部被读任务的服务F、F归属、H、阶段及源正式证据；特征owner准备会产生的核心变更与task保护须按既有封存片段的兼容快照合并，不使用早于前S/J引用预留的旧快照。含F保护的同值task发布独立执行，不造空feature核心，既有API会拒绝“无核心+附加片段”。

本叶不得删除 `服务值结算.本能运行服务.cpp`、task、manager对 `K.服务贡献.has_value()` 的旧+1隔离闸门；Q=0同样属于新贡献来源，不能改成 `贡献值>0` 才保护。这些消费者无需新增代码分支；施工需全量静态核对，若原入口不能承接新实现先报告具名漂移，不扩大至最终普通增值。

## 8. 启动迁移、接管及恢复边界

### 8.1 顺序与全量预检

既有启动入口仍是 `初始化任务治理场景组织`。先完成正式D/T映射、Vt现有EC核验和已有Ct组织/旧9→12迁移，再调用 `初始化任务贡献特征权威`；新能力定义已在task初始化建立。贡献迁移先对所有T/K/R/H/J及旧小计做只读全量预检，形成不可变本次迁接方案，任何一项不能证明则在本次贡献迁移零写入下报告/终止。J须从每个正式T的阶段列表枚举，不能仅枚举Ct动作漏掉“J已发表、动作未建立”的中断现场。已有合法Ct前序迁移不宣称被回滚。

不依赖更晚装配的服务需求取得合同、不重跑旧叶子分类猜历史。所有新增内部能力均不依赖普通结算M存在。当前装配先调用 `初始化治理()` 再调用场景组织，不能声称 `治理已初始化_` 此时必为假；但 `读取任务完成结算()` 的高层入口将加入H/F门，并可能消费后续业务合同，不适合作为无H旧数据迁移的读取器。迁移必须直接使用task内部严格 `读取完成结算信息`、`读取完成贡献` 及已可用X/A/S owner材料，完整验证T/D/X/A所属、A允许完成、X→S或X→结果项→S闭包及K冻结S一致，不调用高层入口把其门禁返回空误解成无K，也不形成迁移→权威门→迁移的循环。迁移结束刷新每个受影响Vt专属概念并对Ct参与者/全部贡献事实读回，最后才置原场景组织就绪；就绪后的再调用只核验，不重迁。

### 8.2 可证明来源

| 无H的存量证据 | 可确定Q及处理 |
| --- | --- |
| 完整K已有贡献 | Q取K冻结值；分类/直属R闭包、T/D/X/A/状态结果证据必须完整 |
| 无K、有完整直接R | Q取无重复、正式直属R精确和；逐R验证子K冻结贡献 |
| 无K、无R | 只在完整任务结构、无旧小计或旧小计0、无任何贡献/接收/服务F变化证据，且现有F缺失或可证明为初始化0时判Q=0 |
| K存在但缺贡献字段 | 不从当前需求子树重新判历史叶子。只有原始冻结材料足以唯一复原既有类型/Q及当时直属接收时才可迁；本叶未提供这样的历史分类证明器，因此统一保留并报告停止，不伪造0或重算 |
| 旧小计存在 | 必须恰等完整直接R和（包括0），它本身不是独立Q来源；异常或重复字段停止 |

已有F=0不是“无需迁移”。旧生产曾只写K/旧小计，允许可证明的初始化占位F0与已冻结非零K/R并存：须检查F当前/历史只有初始0、无该F实际变化S/D或其它修改证据，才属于占位；不能把任意当前0当占位。已有非零F仅在其合法历史及当前值已与上述Q一致时采用；无法证明的差异停止。所有计算检查非负及I64溢出。

### 8.3 三种发表

1. **F缺失**：由feature owner建立值为已证明Q的未挂接候选F；task原子绑定Vt→F、发布H/T→H、移除旧小计字段。候选初始值不是历史变化，不造前S/动作/D。发表后刷新EC，再按正式特征组读回；零发表按owner清候选，未知/已发表保留。
2. **F存在且值需改变**：这是当前真实治理迁移，不是过去计值动作。建立“权威迁移”J/动作/前S；F核心+H/T→H+旧小计字段移除+J→H原子发表，随后EC/后S/D按第6节完成。J和H保留原K/R/旧小计证据，不改旧事实身份和Q。
3. **F已等Q**：不作同值更新；含完整F快照的task原子请求发布H并移除旧小计，零新动作/S/D/命中。接管后仍严格读回EC及事实。

旧小计的物理退役仅删除被证明且已冻结到H的T标量字段记录及其所属关系，使用现有基础原子请求删除能力；不删除共享字段键、K/R/T/F及历史事实。字段键保留迁移只读兼容，生产写入数必须0。新T初始化不建旧小计。

每T可独立完成接管，非全世界巨大回滚；完整预检后实际执行失败保留已完成H及未完成J。重入完整H只核验，已有半J停止，不重加。底层尚无本叶核定的持久快照生产闭环，**不能声称跨进程恢复、崩溃后恰一次**；本叶保证同进程正式重复收敛、可证明旧数据迁接及不明现场停止。任何启动发现阶段核心已发表而S/D等未闭合，同样拒绝启动；不静默补历史。

### 8.4 缺F迁移所需的严格状态枚举（修订1）

缺F分支必须确认该Vt没有旧服务FT状态，不能仅因字段缺失就把F当从未存在；读取返回的具体特征概念须按现有概念owner归一到服务FT。此证明依赖 `新_状态类::按存在查询状态(稳定编码) const noexcept`。当前该函数用 `筛选状态` 跳过不可读S，底层 `查询全部状态节点` 跳过登记指向的缺失节点，catch又返回空，均可能把工程问题当作“没有旧证据”。

本计划只在 `海中鱼巣/领域/新_状态类.cpp` 修改这个已有公开函数及所需标准头包含。签名、头文件、返回类型、查询对象及稳定编码匹配语义不变；不修改其它状态查询或扩大为全状态类重构，不建立新的查询入口。依据[1160第8节](../1160_根规范_状态节点_20260720.md)和[代码文件规范第4.4节](../代码文件建立归属与模块命名规范.md)，诊断责任为本地记录：
