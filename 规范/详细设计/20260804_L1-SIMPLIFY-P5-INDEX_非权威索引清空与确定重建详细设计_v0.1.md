# L1-SIMPLIFY-P5-INDEX 非权威索引清空与确定重建详细设计 v0.1

设计基线：`151ea6684bf62d519b197044b45409c78587dd8f`

方案步骤：`SELF-GOV-CLOSURE v0.2 / STEP-1A`

## 1. 目标与完成边界

本叶只建立新 L1 三类事实基座的业务中性、非权威、可丢弃索引：从调用方给出的 `L1完整快照`、显式来源事实代次和固定索引规则版本形成稳定编码候选视图，提供三态查询、清空、失效、确定重建、并发替换和命中后权威回读。

完成时必须成立：

1. 索引只保存当前节点、关系和值的稳定编码候选，不保存事实副本、属性槽副本、生命周期副本或领域结论。
2. 重建只消费与权威 `L1事实基座服务` 当前完整快照逐项相等的指定快照；候选完整验证后一次替换索引视图。
3. 公开查询不返回裸候选编码，而是用候选逐项回到同一个权威 L1 服务读取当前事实，并在首末事实代次一致后返回不可变事实副本。
4. 查询严格区分 `命中 / 确定未命中 / 索引不可用`；索引不可用不得冒充业务未找到。
5. 清空、失效、候选拒绝和并发冲突均不修改 L1 权威事实，也不污染或部分替换既有索引视图。
6. 现有 L2 数据头、DTO、服务签名和调用边零修改。

本叶不证明显式有向类型兼容、领域业务键、旧入口删除、生产装配、SQL 或持久恢复、旧消费者迁移、集成验收、方案 1B 或后继业务闭环。

```cpp

inline constexpr std::uint32_t L1可重建索引规则版本 = 1;

struct L1节点种类索引键 final { 节点种类 种类; };

struct L1当前属性值索引键 final { 稳定编码 所属节点; 稳定编码 属性类型节点; };

using L1结构索引键 = std::variant<

};

enum class L1索引维护状态 : std::uint8_t {

    精确重复 = 2,

    std::uint32_t 规则版本 = 0;
```

`来源事实代次 == 0` 是空仓初态的合法来源，但仅当指定快照事实代次为零且当前三表和永久占用均为空。

## 5. 索引内容与完整覆盖

规则版本 1 只生成四类业务中性映射：

| 键 | 候选稳定编码 | 完整覆盖含义 |
| --- | --- | --- |
| `节点种类` | 当前快照中同种类节点编码 | 覆盖该代次全部当前节点 |
| `关系源 + 关系类型` | 同源且同关系类型的当前关系编码 | 覆盖该代次对应全部当前出边 |
| `关系目标 + 关系类型` | 同目标且同关系类型的当前关系编码 | 覆盖该代次对应全部当前入边 |
| `所属节点 + 属性类型` | 同所属节点和属性类型的当前值编码 | 覆盖该代次对应全部当前值候选；不取得属性槽权威 |

每组候选按稳定编码严格升序、唯一。索引视图只保存：固定合同/数据版本、来源事实代次、规则版本、四类映射和模块私有索引视图序号；四种 `L1结构索引键` 变体分别构成查询命名空间与完整键，不另设可变字符串命名空间。视图不保存 `节点事实/关系事实/值事实`、属性槽、历史、审计、恢复材料、SQL 行、领域名称或业务键。完整视图是模块私有不可变对象：生产对象以 `std::unique_ptr<const L1索引视图>` 独占当前视图，局部候选在取得索引锁前完成分配和全部可失败验证，锁内只执行 `noexcept` 指针交换与序号赋值。

空组不物理存储。已加载视图覆盖上述完整键空间，所以完整键没有条目时可以返回 `确定未命中`；未加载、失效、规则不符或来源代次已变化时只能返回 `索引不可用`。

## 7. 确定重建算法

固定顺序：

```text
校验合同版本、固定规则版本和来源代次/指定快照一致
-> 在索引共享锁内只读取当前索引视图序号，立即解锁
-> 经 L1事实基座服务 读取第一次权威完整快照
-> 要求状态成功、快照存在、事实代次和内容逐项等于请求指定快照
-> 在局部独立容器按规则1生成候选映射
-> 验证候选键完整、编码非零、跨当前三表唯一、每组严格排序唯一、四类映射与指定快照逐项双向覆盖
-> Debug 一次性故障只在此处破坏局部候选并被验证拒绝
-> 再次经 L1事实基座服务 读取权威完整快照
-> 要求两次权威快照及指定快照逐项相等
-> 取得索引独占锁
-> 若当前已发布视图与候选身份和内容完全相等，返回精确重复
-> 否则若索引视图序号已变化，返回索引视图漂移
-> 确认序号可递增；计算新非零视图序号
-> 以 `noexcept` 指针交换一次发布已完整验证的不可变视图，并赋新序号
-> 仅执行不会失败的 Debug 不变量断言；成功返回重建已发布
```

候选构造、排序、验证、不可变视图分配和新序号溢出检查均在交换前完成。交换后不存在可能返回失败的校验、分配或外部调用；Debug 断言若失败表示实现违反本设计，不能被实现为“返回失败并保留半视图”的运行分支。任一拒绝、资源失败、内部异常、事实代次漂移或视图漂移都在交换前丢弃局部候选，既有视图逐项不变。索引发布不是 L1 事实发布，不推进事实代次、不写审计、不接触恢复候选。

同一权威快照和规则版本必须形成语义相同候选；当前视图已经相同返回 `精确重复`，不得重排后冒充新发布。

## 8. 查询与权威回读

固定顺序：

1. 校验合同版本、规则版本和键完整性。
2. 在索引共享锁内复制视图身份和该键候选组后立即解锁。
3. 无已加载视图或规则不符返回 `索引不可用`；已加载且无条目进入权威代次复核，不直接返回未找到。
4. 对每个候选按键种类调用同一 `L1事实基座服务` 的 `读取当前节点/关系/值`，要求成功、载荷存在、事实变体与键种类一致、事实字段与键字段匹配、每项读取代次等于索引来源事实代次。
5. 最后调用 `读取完整快照`，要求成功且事实代次仍等于索引来源事实代次。
6. 候选非空且全部成立，按编码顺序返回 `命中 + 当前事实`；候选为空且末次代次成立，返回 `确定未命中 + 空事实组`。
7. 权威代次变化时，按捕获的视图序号和身份条件失效旧视图，返回 `索引不可用 + 空事实组`；不得清除已被其它线程重建的新视图。
8. 候选与同代次权威事实字段不匹配属于索引内部不一致，条件失效旧视图并返回 `内部不一致 + 空事实组`。

非 `命中` 状态的 `当前事实` 必须为空。索引未命中、清空或失效不得查询 SQL、材料、旧仓或旧索引补判。

## 9. 清空、失效、并发和生命周期

- `清空`：合同有效时取得独占锁；已加载则删除整个视图并递增视图序号，返回 `已清空`；本来未加载返回 `精确重复`，不递增。
- `失效`：调用方以 L1 新代次发布证据触发，但请求必须携带其最后观察到的 `被失效来源事实代次` 和规则版本；仅当二者精确匹配当前视图时删除视图并递增序号。无视图返回 `精确重复`；身份不匹配返回 `索引视图漂移`，不得清除已经按新代次重建的视图。
- 视图序号是模块私有并发控制量，不是事实代次、对象版本或公开索引版本；只随本模块成功替换、清空或失效递增，溢出前返回内部不一致并保持原视图。
- 读使用共享锁，发布/清空/失效使用独占锁。不得共享锁升级。
- 调用权威 L1 服务时不得持有索引锁；索引模块不取得 L1 仓库锁，不形成跨仓锁序。
- 持索引锁期间禁止日志、I/O、回调、等待和 L1 服务调用。
- `L1事实可重建索引` 拥有索引视图；借用的 `L1事实基座服务` 必须覆盖其生命周期。索引对象销毁只丢弃非权威视图。

## 10. 错误与异常映射

| 情形 | 结果 | 视图变化 |
| --- | --- | --- |
| 合同/规则/键不合法，来源代次与指定快照不符 | `入口拒绝` | 零变化 |
| 指定快照与任一次权威快照不同，或两次权威快照不同 | `事实代次漂移` | 零变化 |
| 权威完整快照或逐项读取返回 `资源失败` | `资源失败` | 零变化；不因瞬时资源失败清除旧视图 |
| 权威读取返回 `内部不一致`、入口拒绝，或成功却缺少/返回错误变体载荷 | `内部不一致` | 零变化；不把权威服务错误误判为索引失效 |
| 权威逐项读取返回未找到、已退出或事实代次漂移 | `索引不可用` | 仅查询条件失效捕获的旧视图 |
| 权威逐项读取返回属性未设置 | `内部不一致` | 零变化；三类事实读取不应产生该状态 |
| 并发清空、失效或不同重建已改变视图序号 | `索引视图漂移` | 本调用零变化 |
| 局部候选不满足双向覆盖或内部结构不变量 | `内部不一致` | 零变化 |
| `std::bad_alloc` | `资源失败` | 零变化 |
| 其它未知异常 | `内部不一致` | 交换前零变化；异常不得逸出公开入口；交换后无可抛出步骤 |
| 查询时权威事实代次变化 | `索引不可用` | 仅条件失效捕获的旧视图 |
| 查询候选与同代次权威事实不匹配 | `内部不一致` | 仅条件失效捕获的旧视图 |

成功、精确重复、合法未命中、不可用和入口拒绝不记录错误日志。模块只向上送出结构化状态；最终业务责任边界另行决定诊断记录。

## 11. 专项自检矩阵

新专项身份：`L1-SIMPLIFY-P5-INDEX-S01`，顺序 `330`，完整自检总数 `28`。

至少覆盖：

1. 新索引未加载时四类查询均为 `索引不可用`，不访问旧索引。
2. 空 L1 代次 0 指定快照重建成功，完整键查询为 `确定未命中`。
3. 在隔离 L1 中一次写入多种节点、两条关系和两个当前属性值；重建后四类键均命中，返回事实来自权威服务且同代次、排序稳定。
4. 已加载完整键无候选返回确定未命中；不完整键入口拒绝。
5. 同快照同规则重复重建返回精确重复，视图序号和内容不变。
6. 清空后查询不可用而 L1 快照不变；重复清空精确重复；随后可由同一权威快照确定重建。
7. 显式匹配失效成功；旧身份不能失效新视图。
8. L1 发布新代次后，旧索引查询只能返回索引不可用并条件失效；重建后才可命中或确定未命中。
9. 错误合同、错误规则、来源代次不符、指定快照内容漂移均拒绝且旧视图逐项不变。
10. Debug 候选损坏返回内部不一致且旧视图不变；Release 静态证明入口零符号。
11. 重建与清空/失效并发时只允许精确重复、成功或索引视图漂移，不得发布半视图、丢失后发生的清空或返回混代事实。
12. 多线程读与重建期间，任何命中结果均为单一来源事实代次的完整权威事实组；其它只可为确定未命中或索引不可用。
13. 静态证明新模块不 import/include 旧 `仓库.可重建索引`、旧句柄、节点直接仓、SQL、材料或任一 L2 模块。
14. 静态证明现有 L1 公共数据头、L1 服务模块和全部 L2 目标文件 blob 不变。

## 12. 实施与声明边界

本设计允许声明的最大结果是：新 L1 具备一份可清空、可失效、可由指定权威快照确定重建的业务中性稳定编码候选索引，并且公开查询只有在权威 L1 同代次回读成立时返回事实。

不得据此声明：索引是权威事实、领域方法/合同/特征检索已接线、所有领域键已建立、类型兼容完成、生产恢复完成、旧索引或旧仓可删除、全部 L1 消费者已迁移、方案 1B 或自我内部治理闭环完成。
