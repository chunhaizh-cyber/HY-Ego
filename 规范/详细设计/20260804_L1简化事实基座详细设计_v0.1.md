# L1 简化事实基座详细设计

日期：2026-08-04
状态：4015 的实施设计；在对应计划登记并完成 S0 前，不证明新 L1 已进入运行期。

## 1. 目标与当前事实

目标是把 L1 收敛为一套事实基座，而非继续并列维护旧四仓库与“节点直接”五仓。

当前代码有两套实现：

```text
旧：主信息仓库 + 节点仓库 + 关系仓库 + 索引仓库
新：节点直接身份仓 + 正式关系仓 + 类型合同仓 + 类型化值仓 + 可重建索引 + 幂等账
```

两者并存会重复表达身份、关系、值、版本、事务与索引。`运行期上下文` 已完成入口收口，并已更正为 `读取L1事实基座()`；它仍是旧四仓的过渡聚合，不是最终模型。

本设计不把 SQL、材料文件、缓存、日志或控制面板设为运行期事实；它们继续分别作为持久证据、材料、非权威加速和人读投影。

## 2. 目标模型

### 2.1 三类事实记录

```text
节点：可独立存在、可被关系连接、可直接拥有属性值的对象
关系：两个节点之间的有向、类型化、带角色或顺序的事实
值：一个节点某个属性类型的不可变类型化载荷
```

节点之间的组成、归属、来源、引用和图结构一律用关系表达；不得同时保存第二份权威“子节点列表”。

普通属性由节点的唯一属性槽直接指向值：

```text
节点编码 + 属性类型编码 -> 当前值编码
```

这不是通用节点关系，也不与关系表重复。一个属性需要独立拓扑、来源角色、生命周期或被其它节点引用时，才把它提升为节点并用关系表达。特征定义、特征槽、状态、动态、需求、任务和方法均是节点；普通标量、向量、区间和材料引用均是值。

### 2.2 身份、时间与换代

1. 所有节点、关系和值共用一个非零、全局不可复用的 `稳定编码`。编码不包含类型、名称、内存地址、仓库号或版本。
2. 节点、关系和值不再具有独立的“身份版本 / 关系版本 / 值记录版本”。替换关系或属性值时，旧事实退出、新事实使用新的稳定编码发布。
3. 每次成功写集只推进一个全局 `事实代次`。它是原子发布、并发校验、快照一致性和恢复验证的唯一技术代次，不是对象版本。
4. `创建事实代次` 与可选 `退出事实代次` 是生命周期证据；业务时间（观察时间、状态发生时间、安全回归时间等）必须作为具名类型化属性值，不能用系统发布时间替代。
5. 属性类型本身是 `属性类型` 节点。改变类型值域或解释时建立新的属性类型节点；明确兼容性使用有向关系表达，不复用“合同版本”字段。

### 2.3 最小记录形状

```cpp
struct 稳定编码 { std::uint64_t 值; };

struct 节点事实 {
    稳定编码 编码;
    节点类型 类型;
    std::uint64_t 创建事实代次;
    std::optional<std::uint64_t> 退出事实代次;
    属性槽表 当前属性;
};

struct 关系事实 {
    稳定编码 编码;
    关系类型 类型;
    稳定编码 源节点;
    稳定编码 目标节点;
    std::int64_t 角色或顺序;
    std::uint64_t 创建事实代次;
    std::optional<std::uint64_t> 退出事实代次;
};

struct 值事实 {
    稳定编码 编码;
    稳定编码 所属节点;
    稳定编码 属性类型;
    类型化值材料 材料;
    稳定编码 来源节点;
    std::uint64_t 创建事实代次;
    std::optional<std::uint64_t> 退出事实代次;
};
```

`属性槽表` 以属性类型编码唯一排序，指向当前值编码；提交时与值事实一起校验。值事实的 `所属节点 + 属性类型` 必须与该槽一致。空来源只允许系统签发且由类型规则明确允许的值。

## 3. 事务、读取与索引

写请求以“期望基线事实代次 + 幂等编码 + 完整不可变写集”进入。基线不等时返回版本漂移；同幂等编码、同写集返回原结果；同键异写集返回冲突。候选形成、完整校验、确认、逆序撤销和最后一次事实代次发布继续保留。

读取只能返回调用方拥有的值式快照。组合读取以首末事实代次相等为条件；不相等时整体重试一次，仍不等返回漂移。索引只能由指定事实代次重建，命中后必须回读节点、关系和值，不形成第二权威。

## 4. 物理位置与唯一职责

| 文件 | 职责 |
| --- | --- |
| `核心/L1事实基座.数据.h` | 三类记录、稳定编码、写集和不可变读取 DTO |
| `核心/仓库.L1事实基座.ixx` | 唯一内存事实表、编码分配、候选、发布与恢复候选；不解释领域语义 |
| `核心/服务.L1事实基座.ixx` | L1 版本化值式读写、当前 / 历史 / 审计读取和事实代次读取 |
| `核心/自检.L1事实基座.ixx` | 原子写集、替换、撤销、幂等、漂移、快照和索引重建矩阵 |

不得新建节点 / 关系 / 值的平行仓库、兼容转发壳或第二份索引。`运行期上下文` 最终只持有这一个 L1 事实基座；领域服务只持有 L1 服务，不取得其可变仓、锁或候选。

## 5. 迁移顺序与完成条件

1. 先修订 0050、4010、4020、4040、4070，使“稳定编码 + 事实代次”成为唯一 L1 身份与并发口径；这一步完成前不删除现有代码。
2. 建立上述四个 L1 文件和自检，覆盖节点含多个值、节点图关系、属性替换、关系替换、撤销、幂等、代次漂移、恢复候选和索引重建。
3. 先迁移世界结构提供者，再迁移特征、状态动态、需求任务方法；每个领域只在其真实读取和写入均改用新 L1 后，删除对应旧入口。
4. 所有领域迁移并通过集成验收后，删除旧四仓、节点直接五仓、旧句柄、旧版本 DTO、兼容导入和工程登记。

完成不以“新文件存在”或“骨架编译”宣称；必须满足正式运行期和所有领域服务不再 import 旧四仓或节点直接五仓，搜索结果只允许历史记录与已退出文档，并且新 L1 自检、Debug/Release 构建和具名世界服务验收通过。
