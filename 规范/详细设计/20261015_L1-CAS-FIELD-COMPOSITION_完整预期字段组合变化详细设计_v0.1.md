## 1. 目标、依据与边界

本叶给唯一 `基础数据集` 增加**字段关系**的中性组合变化：对一组已存在节点，按完整当前联合快照比较后，在同一独占锁内删除、改内容和追加字段，候选全部就绪后一次交换。它不解释场景、存在、名称、序号或业务资格。成功只证明本次调用的字段变化在进程内一个线性化点完整发布。

正式依据是[规范目录](../规范目录.md)登记的 0050 §1.2、§4—6 和 4015 §3—8、§13—15；代码组织按 `CODE-FILE-01`。0050 要求跨基础操作共同成立的结构一次发布；4015 §14 已包含字段新增、修改、删除和必要前置条件，本设计只是其中**字段子集**，不修订 4015。4015 §14 第4项的跨进程结果未知查询/恢复以及 §15 的持久快照，本叶均不实现；完成后仍不得称 L1 通用组合变化集或可靠持久事实基座已完成。

现行 `基础数据集::添加字段值/添加字段节点/修改字段值/修改字段节点/删除字段` 各自单锁，只能分别写；`原子追加节点组`只追加；`原子删除节点结构`要求待删字段的所属节点也在待删节点集；`原子建立/删除互引节点`只服务其固定形状。它们都不能在一个锁内比较完整 E 入向归属，同时移除原场景成员字段、建立新成员字段和替换独立序号字段。现有 `查询节点组完整结构` 和 `读取联合快照已加锁/联合快照相等` 可以复用作预期证据与同锁复核；完整快照含节点自身字段、入/出外部关系和入向字段。代码基线见文首，施工前重新 S0。

本叶不修改节点表、外部关系表、编码规则、现有函数签名或行为，不创建/删除节点、关系，不接语言或场景调用方，不新增持久化、幂等账、历史、测试后门或第二底座。

## 2. 唯一物理承载与公开 ABI

声明、DTO 只加在 `海中鱼巣/核心/基础数据集.h` 的基础结构值类型与 `基础数据集` 公共成员区；定义及仅本入口用的私有辅助只加在 `海中鱼巣/核心/基础数据集.cpp`。沿用现有全局数据集、互斥锁、编码分配器和字段正反索引，不新建模块、工程项、服务或 owner。允许调用方是持有该精确 L1 实例并已获上层写权的数据类；L1 入口本身只作结构校验，不接受业务 owner、合同版本、事实代次或调用方指定的新编码。

```cpp
struct 基础字段组合替换 final {
    稳定编码 字段关系;
    基础字段内容 新内容;
};
struct 基础字段组合追加 final {
    稳定编码 所属节点, 字段节点;
    基础字段内容 内容;
};
struct 基础字段组合变化请求 final {
    std::vector<基础联合节点快照> 预期节点组;
    std::vector<稳定编码> 删除字段关系组;
    std::vector<基础字段组合替换> 替换字段组;
    std::vector<基础字段组合追加> 追加字段组;
};
enum class 基础字段组合变化状态 : std::uint8_t {
    已完成 = 1, 入口拒绝, 节点不存在, 引用不存在,
    预期不符, 编码耗尽, 资源失败
};
struct 基础字段组合变化结果 final {
    基础字段组合变化状态 状态 = 基础字段组合变化状态::入口拒绝;
    std::vector<稳定编码> 追加字段关系组;
};

基础字段组合变化结果 基础数据集::原子比较变更字段组(
    const 基础字段组合变化请求& 请求) noexcept;
```

`基础字段内容`仍只能是正式 `基础值` 或节点 `稳定编码`。替换只改变原字段的内容，保留其编码、所属节点和字段节点；跨宿主迁移必须删除旧字段并追加新字段。删除组用字段关系身份定位完整旧项，完整旧值与宿主从预期快照互证；追加项的字段身份由 L1 分配，结果按请求追加顺序一一回传。失败结果的追加编码组必须为空。追加重复的同宿主/同字段节点/同内容项按现行 L1 多字段语义分别建立，不能由底座猜业务去重；上层负责字段基数。

本入口不接受空变化集；`预期节点组`不能为空。预期组内每个节点身份非零且互异；调用方应从当前 `查询节点组完整结构` 的非空成功项取得完整快照，不可用缺失项、部分字段、裸编码或自报摘要替代。L1 不校验快照来源，只在锁内逐项全等比较，因此即使调用方自行构造了相同快照也不会取得额外权限。全部被删/被替换字段的宿主、全部新增字段宿主，以及这些变更的旧/新节点引用目标，均须在预期组；字段节点只需同锁确认为当前节点，不要求提交其高扇出完整快照。调用方可增加其它预期节点以守卫其入向或出向结构。每个删除/替换字段身份必须恰在一个对应宿主预期字段组中；同一既有字段身份在本次只能触碰一次，删除与替换不得重叠。预期的完整性以锁内实际联合快照逐项相等证明；向量排序沿用既有读回形态，调用方原样传递，不在此入口重新解释业务字段。

## 3. 状态与输入裁决

| 状态 | 精确条件 | 事实变化 |
| --- | --- | --- |
| `入口拒绝` | 空变化/预期、空或重复预期节点、重复触碰既有字段、触碰项缺宿主或旧/新引用目标预期、字段身份不在其预期宿主字段组、无效编码、空变体或参数结构矛盾 | 零发布 |
| `节点不存在` | 某一必需预期节点在提交锁内不存在 | 零发布 |
| `引用不存在` | 追加项使用的字段节点在提交锁内不存在；既有字段的字段节点缺失属于内部不变量破损；新旧节点引用目标都必须在预期组，故其缺失按`节点不存在` | 零发布 |
| `预期不符` | 预期节点存在，但任一自身字段、入向字段、入/出外部关系与锁内完整当前快照不同，包括目标字段已变化/删除 | 零发布 |
| `编码耗尽` | 所需新增字段身份无法从同一数据集继续分配 | 零发布，已占编码不回收 |
| `资源失败` | 候选、快照、索引或结果预分配发生 `std::bad_alloc`/`std::length_error` | 零发布，已占编码不回收 |
| `已完成` | 所有条件在一把独占锁内成立，候选整体交换完成；纯同值替换仍视为已完成 | 全部字段变化同时可读 |

参数问题不包装成业务否定；当前字段表/索引不变量破损、意外标准异常及未知异常进入 `CODE-FILE-01` 的工程异常终止链，不能返回 `入口拒绝`、`预期不符` 或空成功掩盖。`预期不符`只表示与调用方已知完整快照不同，不区分哪个业务解释正确。请求没有幂等身份，重复相同追加请求在首次成功后通常因预期不同而返回`预期不符`，不得换预期自动再追加。

## 4. 原子算法与所有权证明

1. 取得当前 `基础数据集::互斥_` 独占锁；做上述形状、非零、重复触碰和预期覆盖检查。用现有联合快照已加锁路径对每个预期节点读取**完整**当前自身字段、入向字段和入/出外部关系，先确认节点存在，再逐项全等比较。读取或索引校验中发现内部不变量破损进入工程异常终止。
2. 同锁检查每项新/替换内容的联合类型、节点引用非零与存在，字段节点存在，待删/替换的当前字段完整项恰等于预期对应项；不检查业务种类、字段基数或场景唯一归属。若某字段变化同时影响一个预期目标的入向集合，比较采用**提交前**快照，不能在逐项候选修改后再拿预期校验。
3. 复制当前 `字段关系_`、`所属字段索引_` 和 `目标字段索引_` 为局部候选；`节点_`、`外部关系_`只读。预先建立并预留完整成功结果。按请求组顺序在候选上先删除、再替换、再追加：删除精确移除字段表及所属索引、若原内容为节点引用则移除反向索引；替换保留字段编码/宿主/键，移除旧反向索引并按新目标增加反向索引；追加用 `分配编码()` 获新身份，同时写候选字段表、所属索引和节点引用反向索引。索引的三元键始终是现行头文件定义的 `(所属节点, 字段节点, 字段编码)` 或 `(字段节点, 目标节点, 字段编码)`；任何碰撞或缺失都视内部不变量错误，不以业务拒绝继续。
4. 全部可分配、可验证、可构造操作及成功 DTO 填充均在交换前完成。依现有标准容器/分配器对候选三容器执行不会抛出的 `swap`，且在持锁期间连续交换；这组交换是本叶唯一公开线性化点，读者只能在锁释放后看到全旧或全新字段状态。交换之后不执行可能分配、抛出、读回或业务回调的操作，`noexcept` 返回路径仅移动已就绪结果。编译期核对三次 `swap` 和结果移动的 `noexcept` 性质。若不能证明这一点，实施者不得把非成功返回放在交换后，须退回设计。
5. 发布前任一步失败均不交换候选；`分配编码()`可能推进高水位，已分配但未发布的编码不外泄、不复用，也不表示事实。发布成功后普通调用方可用现行 `查询节点组完整结构`独立读回，但那次读取可能看见后续并发变化；不能把它伪称同一事务的返回快照，更不能因读回漂移回滚已发布字段。

本叶不引入字段历史和删除后查询。字段修改保留原编码；字段删除后该编码永久失效，追加获新编码。该 ABI 不直接处理节点删除或外部关系；上层若要求节点退出与字段变化整体成立，不能将本叶与现有 `原子删除节点结构` 分步调用后宣称原子。当前场景迁移也是分步写，必须由后继场景 owner 明确改用本入口后，才可能对本次字段组合证明原子性。
