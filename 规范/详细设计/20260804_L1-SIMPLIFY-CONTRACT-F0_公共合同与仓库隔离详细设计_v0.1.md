# L1-SIMPLIFY-CONTRACT-F0 公共合同与仓库隔离详细设计 v0.1

创建侧代码基线：`6a48ba9d8d2d6f9d31c8a9a1ca764451d44882a9`。

状态：设计已冻结；代码计划等待 `L1-SIMPLIFY-P1-WORLD-STRUCTURE v0.4` 正式结果后激活。

## 1. 目标与完成条件

本叶把当前 `L1事实基座.数据.h -> 仓库模块 -> 服务模块` 的公开传播改造成两个具名合同和一个私有仓库依赖：

```text
海中鱼巣.核心.合同.L1公共事实
├─ 稳定编码
├─ 节点种类
└─ 最小有效性函数

海中鱼巣.核心.合同.L1事实基座
├─ export import L1公共事实
├─ L1事实基座合同版本
├─ 三类中性事实、写入、读取、历史、审计、快照、恢复 DTO
└─ 每个公开服务入口的版本化请求

海中鱼巣.核心.服务.L1事实基座
├─ export import 合同.L1事实基座
└─ private import 仓库.L1事实基座
```

完成条件：L2 领域服务只公开传播 `合同.L1公共事实`；完整 L1 写入/恢复合同和仓库类都不能经 L2 领域服务被调用方可见；全部 L1 服务入口在进入仓库前拒绝错误合同版本；保持 4015 的节点、关系、值、幂等、原子发布、读取、审计和恢复机器语义不变。

## 2. 公共事实合同

新建 `海中鱼巣/核心/L1公共事实.数据.h`，唯一拥有：

```cpp
struct 稳定编码 final;
enum class 节点种类 : std::uint8_t;
inline bool 有效(稳定编码 编码) noexcept;
```

结构和稳定值逐字保持当前实现：`稳定编码{std::uint64_t 值}`，零无效；`节点种类{普通=1, 属性类型=2}`。该头只需要 `<cstdint>`，不拥有写集键、事实记录、原始材料、仓库或服务。

新建模块 `海中鱼巣.核心.合同.L1公共事实`，物理文件 `海中鱼巣/核心/合同.L1公共事实.ixx`，只导出包含上述头。它是跨 L1/L2 身份和节点分类的唯一公共所有者。

## 3. 完整 L1 合同模块

现有 `L1事实基座.数据.h` 删除 `稳定编码`、`节点种类`和对应 `有效` 的重复定义；在没有预导入公共事实模块时包含 `L1公共事实.数据.h`。其余结构仍由该头唯一拥有。

新建模块 `海中鱼巣.核心.合同.L1事实基座`，物理文件 `海中鱼巣/核心/合同.L1事实基座.ixx`：

```cpp
export module 海中鱼巣.核心.合同.L1事实基座;
export import 海中鱼巣.核心.合同.L1公共事实;
export { /* 包含 L1事实基座.数据.h */ }
```

完整合同新增：

```cpp
inline constexpr std::uint32_t L1事实基座合同版本 = 1;

struct L1事实读取请求 final {
    std::uint32_t 合同版本 = L1事实基座合同版本;
    稳定编码 编码;
};

struct L1属性读取请求 final {
    std::uint32_t 合同版本 = L1事实基座合同版本;
    稳定编码 节点;
    稳定编码 属性类型;
};

struct L1审计读取请求 final {
    std::uint32_t 合同版本 = L1事实基座合同版本;
    写集幂等键 幂等键;
};

struct L1完整快照读取请求 final {
    std::uint32_t 合同版本 = L1事实基座合同版本;
};

struct L1恢复候选建立请求 final {
    std::uint32_t 合同版本 = L1事实基座合同版本;
    L1恢复材料 材料;
    std::uint64_t 期望事实代次 = 0;
};

struct L1恢复候选操作请求 final {
    std::uint32_t 合同版本 = L1事实基座合同版本;
};
```

`L1写集请求` 在首字段增加 `合同版本 = L1事实基座合同版本`。所有新增请求均默认全等。合同版本只识别精确值 1；0、2和其它值都必须在服务边界返回对应默认 `入口拒绝`，仓库调用次数为零。

版本字段属于服务 ABI，不是事实身份、幂等内容、对象版本、事实代次或类型兼容证据。合同语义不兼容变化必须建立新版本并显式迁移或拒绝；只改仓库存储、索引、锁、容器或算法且 v1 请求结果语义不变时不得要求 L2 修改。

## 4. 服务签名与仓库隔离

`L1事实基座服务` 的公开函数精确改为：

```cpp
L1写入结果 提交写集(const L1写集请求& 请求);
L1读取结果 读取当前节点(const L1事实读取请求& 请求) const;
L1读取结果 读取当前关系(const L1事实读取请求& 请求) const;
L1读取结果 读取当前值(const L1事实读取请求& 请求) const;
L1属性读取结果 读取当前属性(const L1属性读取请求& 请求) const;
L1历史读取结果 读取历史事实(const L1事实读取请求& 请求) const;
L1审计读取结果 读取审计(const L1审计读取请求& 请求) const;
L1完整快照结果 读取完整快照(const L1完整快照读取请求& 请求) const;
L1恢复结果 建立恢复候选(const L1恢复候选建立请求& 请求);
L1恢复结果 确认恢复候选(const L1恢复候选操作请求& 请求);
L1恢复结果 撤销恢复候选(const L1恢复候选操作请求& 请求) noexcept;
```

每个函数先比较合同版本；不匹配立即返回该结果类型默认入口拒绝。匹配后只解包业务字段并调用现有仓库函数。服务不得改变仓库的候选、确认、逆序撤销、发布、审计、历史或恢复算法。

服务模块把：

```cpp
export import 海中鱼巣.核心.仓库.L1事实基座;
```

替换为：

```cpp
export import 海中鱼巣.核心.合同.L1事实基座;
import 海中鱼巣.核心.仓库.L1事实基座;
```

仓库模块改为 `import 海中鱼巣.核心.合同.L1事实基座;`，不再文本导出数据头。仓库类为服务的实现依赖；任何 L2、启动、运行期或自检模块都禁止直接 import 仓库模块。仓库模块本身仍因 MSVC 命名模块实现需要导出仓库类，但不得由服务重导出，且静态依赖门禁保证唯一直接消费者是 L1 服务模块。

## 5. L2 依赖方向

`服务.世界登记.ixx` 与 `服务.L1场景结构.ixx` 改为：

```text
export import 海中鱼巣.核心.合同.L1公共事实
import 海中鱼巣.核心.服务.L1事实基座
```

第一条只让其公开 DTO 所需的 `稳定编码/节点种类` 可达；第二条只供模块内部形成 L1 请求和读取结果。两模块不得 `export import` 完整 L1 服务或完整 L1 合同。

`世界登记.数据.h` 与 `L1场景结构.数据.h` 的传统头 fallback 改为只包含 `L1公共事实.数据.h`。两个 L2 数据头对完整 L1 合同类型静态零命中。

运行期上下文作为 L1 服务所有者可以继续 `export import 海中鱼巣.核心.服务.L1事实基座`；它不属于 L2 业务门面。核心 L1 自检与运行期上下文自检按新请求 DTO 调用，不建立兼容重载。

## 6. 请求迁移规则

现有调用逐项机械迁移：

| 旧调用 | 新调用 |
| --- | --- |
| `读取当前节点(编码)` | `读取当前节点({版本, 编码})` |
| `读取当前关系(编码)` | `读取当前关系({版本, 编码})` |
| `读取当前值(编码)` | `读取当前值({版本, 编码})` |
| `读取当前属性(节点, 类型)` | `读取当前属性({版本, 节点, 类型})` |
| `读取历史事实(编码)` | `读取历史事实({版本, 编码})` |
| `读取审计(键)` | `读取审计({版本, 键})` |
| `读取完整快照()` | `读取完整快照({版本})` |
| `建立恢复候选(材料, 代次)` | `建立恢复候选({版本, 材料, 代次})` |
| `确认恢复候选()` | `确认恢复候选({版本})` |
| `撤销恢复候选()` | `撤销恢复候选({版本})` |

写请求只补合同版本字段；规范化写集和幂等比较必须包含同一精确版本。因为服务先拒绝非 v1，仓库幂等账中只出现 v1 写集。不得保留无版本兼容重载。

## 7. 错误、诊断与兼容边界

新增请求有效性检查是公开服务边界的合法非成功，不记录错误日志；诊断责任为结构化 `入口拒绝` 向调用方送出。服务转发和纯值辅助无新增异常分支。仓库已有资源失败、内部不一致和恢复隔离语义保持不变。

以下修改在 v1 合同兼容时不要求 L2 改动：仓库容器、索引、锁策略、查找算法、规范化实现、快照组装实现、恢复候选内部表示和性能优化。以下变化必须新合同版本：请求/结果字段语义、状态稳定值、幂等同义规则、事实身份、发布原子性、读取当前性、错误分类或恢复结果含义。

## 8. 验证矩阵

1. 两个合同模块、路径、工程登记和 import 方向一致；
2. 服务模块 `export import 合同.L1事实基座` 且只 `import 仓库.L1事实基座`；
3. 全仓除服务模块外直接 import 仓库为零；
4. 世界登记与 L1 场景结构模块只公开传播公共事实合同，完整 L1 合同为私有 import；
5. L2 数据头对 `写集幂等键|写集本地键|L1写集请求|L1恢复材料|L1事实基座仓库` 零命中；
6. 11 个错误版本请求分别入口拒绝且仓库快照、代次、审计和恢复候选零变化；
7. 当前 L1 自检、运行期所有权自检、世界登记和初始场景专项按 v1 请求全部通过；
8. Debug/Release Rebuild、两配置完整自检、strict、MSVC 模块扫描、diff check 通过；
9. 删除或改变仓库内部容器的测试替身不需要修改任一 L2 DTO（静态依赖证明，不要求本叶真实替换仓库算法）。

## 9. 完成边界

本叶只证明 L1 公共事实/完整服务合同、请求版本拒绝、服务到仓库单向依赖和 L2 公开面隔离。它不改变 4015 机器语义，不证明生产持久恢复、世界树完整业务、旧基座删除、性能、ABI 跨编译器稳定或集成验收。
