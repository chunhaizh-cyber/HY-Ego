## 1. 问题与候选裁决

连接调用记录需要持有self、目标存在和外设窗口引用。引用必须让存在身份保持可读，但不宣称这些对象已经建立连接，不修改世界特征，不生成S/D/C，不引入需求。

候选裁决是：由存在owner提供通用的显式强引用；只要来源尚持有引用，存在owner不得清空被引存在的类型、专属概念及特征组织。引用来源退出时显式解除；不以调用取消、超时或进程停止推定历史引用已经不存在。

此裁决尚待用户确认。拒绝用业务集合材料、虚构状态或隐藏永久引用实现技术保活。

## 2. 当前事实与复用结论

1. `新_存在类::清理存在节点内容`先检查状态及子存在，再准备特征清理；最终完整快照只特判`存在集合保护字段_`入向字段。普通来源字段能阻止L1节点删除，却不能阻止此前E身份字段被清空。
2. 存在类已有清理中门和完整节点快照CAS，集合成员接纳已有身份保护读取；可复用其读回和并发机制，不复用其业务字段含义。
3. 场景类有状态/动态引用计数，但没有通用存在强引用增减入口；场景成员关系不等于任意调用记录持有。
4. 1140第10节明确删除需外部引用条件满足，第13节仍未承诺持久恢复。候选需要正式补充1140生命周期合同，不能把本文当作已完成规范修订。

## 3. 候选最小物理范围与接口

唯一owner为`领域/新_存在类.h/.cpp`，不放到基础数据集、world或连接函数。提供者只增加技术保护字段及下述接口；不增加世界特征或概念。

```cpp
enum class 新存在强引用状态 : std::uint8_t {
    已建立=1, 已存在, 已解除, 不存在, 入口拒绝, 前提已变化
};
struct 新存在强引用信息 final {
    稳定编码 字段关系, 来源节点, 存在节点;
};
struct 新存在强引用结果 final {
    新存在强引用状态 状态=新存在强引用状态::入口拒绝;
    std::optional<新存在强引用信息> 信息;
};
新存在强引用结果 建立存在强引用(稳定编码 来源节点, 稳定编码 存在节点) noexcept;
std::optional<新存在强引用信息> 读取存在强引用(稳定编码 字段关系) const noexcept;
新存在强引用结果 解除存在强引用(稳定编码 来源节点, 稳定编码 字段关系) noexcept;
```

候选存储为`来源节点 --存在强引用字段--> E`，字段由E owner增量初始化、方法owner不能直接写。以来源/E配对唯一，不用容易漂移的冗余计数；字段关系编码就是引用凭据。不同来源独立保护，同来源重复建立精确复用，不累计次数。L1不鉴权，来源所属业务owner负责调用权限，不能把稳定编码当能力令牌。

清理状态枚举仅末尾追加`仍被强引用`，不重编号既有状态。方法调用记录创建、场景及其它消费者不属于本提供者代码范围；后继消费必须按本合同显式建立和解除。

## 4. 建立与清理竞态

建立在E owner锁下读来源完整结构及E身份保护，确认E仍为正式存在、专属概念准确绑定且无清理中门，再在同一完整快照CAS内追加引用字段；字段新增及E入向变化必须一起由L1可见并读回。使用已有原子字段变更请求，不先发布半引用。

清理在写清理中门前，对同一完整E快照检查强引用入向字段。存在强引用即返回`仍被强引用`，零身份清理；没有引用时CAS写门。引用抢先成功则清理CAS失败；清理门抢先成功则建立引用拒绝。不得仅靠一次检查后无保护地新增字段。

不得在持E锁时回调来源owner；跨owner后继通过冻结请求及结果读回交接。强引用只保护E身份与所属结构的清理，不冻结当前特征值、场景移动或业务状态。

## 5. 解除、退出及恢复候选

解除按来源/字段编码精确核验，不允许解除别人的来源。来源清理须先退出活动用途，再解除对应强引用，再清理来源自己的引用字段与节点；不得只删除来源类型然后遗留无法识别的保护。

解除用完整来源/E快照CAS删除恰一强引用字段，核验读回；CAS竞争正常返回前提变化，零额外删除。字段本来不存在返回不存在，不以故障冒充解除。来源历史仍明确引用E时保留保护是有意保留，不因连接取消而释放；历史记录正式删除后才解除。连接历史清理策略需要在后继计划冻结，不能默认永久历史又声称已完成资源回收。

当前基础数据是进程内实现，不承诺跨进程持久恢复。初始化仅核验仍存在的强引用结构，绝不在启动时按超时批量释放。发现字段损坏、来源存在但身份已非法清空、清理门残留等进入日志/弹窗/中止及调试修复，不将其当业务“无引用”。候选恢复原则是保留可追溯引用与被保护身份，来源owner提供退出证据后精确解除；不引入周期扫描或自动垃圾回收。

仍需裁决/冻结：来源退出由哪个正式owner接口提供可核验依据；历史方法调用记录何时允许删除。提供者不理解所有业务来源种类，不得靠通用层猜测。这些生命周期接口在裁决前保留为缺口，当前草案不可执行。
