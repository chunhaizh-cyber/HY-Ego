# L2-SELF-S-HOST 场景宿主存在关系详细设计 v0.1

日期：2026-08-13

## 1. 目标与边界

在最终 R1 `L2场景结构服务` 和同一场景 owner 内增加业务中性的场景宿主存在关系，使一个正式树内场景可以声明由一个正式存在持有。该关系与场景成员、父子、树归属分账；L2 不解释“内部世界”或“自我”。

这是 7130 真实自我三叶的第二叶。本叶不删除启动阶段 17。

## 2. 当前事实和依赖

设计基线尚只有 S-ID WIP；R1、A1、I1、I2 和 E-ROLE 均未实现。最终 R1 已预冻结树内场景、树归属、成员关系和整树读取。S-HOST 必须等待 R1 与 E-ROLE 的真实结果，从新 HEAD 复核场景 / 存在 DTO、键域、退出闭包和公开函数。

复用场景 owner、成员端点的存在来源校验、R1 树归属前置、owner-scoped 写集和当前 / 历史读取。禁止用成员关系代表宿主、用父子代表持有、恢复关系 21或增加自我业务判断。

## 3. 事实、方向、基数与生命周期

服务私有登记一个场景宿主存在关系类型节点；它属于场景 owner、无场景族归属、不取得公开场景身份且不退出。关系事实固定：

```text
正式树内场景 --场景宿主存在关系类型 / 角色 1--> 正式存在
```

一个当前场景至多一个宿主，一个当前存在至多被一个场景作为宿主目标。关系 owner 是场景 owner；存在只作跨 owner 端点，不由场景服务写。场景普通退出必须把当前宿主关系列入闭包；存在退出在当前宿主引用存在时由 L1 引用保护拒绝。

## 4. DTO 与公开 ABI

全部 DTO 放在 `海中鱼巣/领域/L2场景结构.数据.h`：

```cpp
struct L2场景宿主存在关系类型身份 final { 稳定编码 值; };
inline constexpr std::uint32_t L2场景宿主结构登记规则版本 = 1;
inline constexpr L2结构幂等身份 L2场景宿主结构登记固定幂等身份{
    0x4C32'5348'4F53'5401ULL};

struct L2场景宿主结构登记请求 final {
    L2结构请求头 请求头;
    std::uint32_t 规则版本 = L2场景宿主结构登记规则版本;
```

全部结构定义 `operator==`。请求有效性要求共同合同、非零期望代次、非保留业务幂等身份、有效端点和关系编码；替换要求新旧宿主不同。当前 / 历史截止规则与 4230 一致。非成功载荷为空；新增成功只含当前关系，替换成功含新当前与本代退出旧关系，退出成功只含本代退出关系；首次 / 精确重复的截止与变更代次均等于首次发布代次。按场景与按存在读取成功只允许一条同截止完整关系，零条为未找到，重复为内部不一致。

`L2场景事实` 新增单值字段 `std::optional<L2场景宿主存在关系事实> 当前宿主关系`，无宿主时为空；当前完整读取有值时必须是本场景、未退出且截止完整，历史完整读取按截止显示当时有效关系。`L2场景退出请求` 新增 `std::optional<稳定编码> 当前宿主关系`，必须与权威快照逐字段相等；`L2场景退出结果` 新增 `std::optional<L2场景宿主存在关系事实> 已退出宿主关系`。退出无宿主时两者均空；有宿主时请求精确携带唯一关系编码，场景节点、场景族归属、树归属、直接父、成员、属性和值及宿主关系在同一场景 owner 写集中同代退出，结果宿主生命周期退出代次必须等于结果变更代次。宿主字段是单值 optional，不参与向量排序；存在侧不增改退出 DTO，由 L1 当前引用保护拒绝仍被宿主关系引用的存在退出。

登记在 R1 树结构登记之后构造，固定写集只有一个普通关系类型节点，本地键为 `0x0201'1601U`，无场景族归属。实现 S0 只核对该冻结值和固定登记幂等身份在最终场景域仍无冲突；冲突退回计划支撑，不得自行改值。登记身份是场景 owner 全局幂等域保留值。

## 5. 写入、同截止与并发

新增 / 替换前用同一期望事实代次：

1. 正式读取场景来源与树归属，拒绝裸场景、内部元数据和已退出场景；
2. 经注入的 `const L2存在结构服务&` 正式读取存在来源；
3. 读取当前场景宿主和存在反向宿主，证明双向唯一；
4. 提交一条新关系，替换时同事务退出旧关系；
5. 在变更截止正式按场景与按存在双向读回。

前置读取后仍以原期望代次提交；任何并发发布由 L1 漂移裁决。历史入口以显式截止重建，不能由当前补项。关系错 owner、方向、类型、角色、端点、重复或双向复义为内部不一致。
