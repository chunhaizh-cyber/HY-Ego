# INSTINCT-STAGE3-SAFETY-ROOT-DEFINITION-CURRENT-PROVIDER 安全根定义与当前值提供者详细设计 v0.1

日期：2026-08-29

版本：v0.1

状态：正式设计候选；发布并登记计划后进入施工

## 1. 目标与边界

本切片建立 `DATA-EXT-15` 的第一项正式提供者：版本化保存安全根低位阈值 `L`、高位阈值 `H`、主动安全结算规则版本和被动服务维护规则版本，并在调用方冻结的同一 `G0` 下组合读取该定义与现有安全根特征实例的当前值 `A`。

权威分工固定为：

```text
安全根定义 owner
-> 只拥有 L / H、定义版本、两类规则版本、来源和当前定义选择

L2特征结构 owner
-> 继续唯一拥有安全根特征实例、当前属性槽和当前值事实 A

安全根定义与当前值服务
-> 在同一 G0 读取两边并逐字段互证，形成可重建值式快照
```

本切片不选择具体阈值、不自动发布默认定义、不改变 `A`、不生成状态 / 动态、不计算终止 / 休眠 / 主动控制态、不实现安全事件结算、服务回归、调度配额或 FRESH 消费者。普通应用装配后，未有合法发布者显式发布定义时，读取必须返回“未发布”。

## 2. 正式依据与当前事实

- 6120 已冻结 `1 < L < H <= I64_MAX`、定义版本、主动安全结算规则版本和被动服务维护规则版本，且禁止线程、服务合同、任务调度、显示层或执行者临时选择阈值。
- 6130 已冻结安全根角色由 `本能根运行锚点_v1` 具名绑定；当前值只经 `L2特征实例 -> 当前属性槽 -> 当前值事实` 读取，状态 / 动态不得替代。
- 6170 要求 `A`、阈值、规则版本和维护游标分账。
- 当前 `本能被动维护游标服务` 已证明专属 L1 owner 的固定登记、幂等重放、当前槽、独立读回和普通应用唯一装配模式可复用。
- 当前 `L2特征结构服务::读取特征当前值(...)` 是 `A` 的正式读取入口；`组合.运行期只读查询` 中按向量位置猜测 `A/L/H` 的占位逻辑不是本切片输入。


固定资源：

```text
L1 owner 建立幂等身份 = 0x494E'5354'5341'4645  // INSTSAFE
结构登记写入幂等身份 = 0x494E'5354'5341'4601
专属本地键段 = 0x0307'1201..0x0307'121F
```

键分配：`1201` 登记锚点、`1202` 当前定义节点、`1203` 当前定义属性类型、`1204` 每次发布的新定义值。`1205..121F` 只保留给同 owner 同合同后继。候选常量已在当前工作区零命中；不得复用游标 `0x0307'1001..1004`、安全硬否决 owner `0x0307'2001..201F` 或特征 / 状态 / 动态 owner。

定义的持久生命周期由“不可变定义值事实 + 当前定义属性槽选择”表达：定义值建立后永久可作历史证据；在某个读取截止是否为当前只由该截止的属性槽选择决定。不得增加第二 `A` 槽或把 `A` 编入定义材料。

## 4. 公共数据合同

所有专属合同版本均为 `1`，共同请求头继续使用现行 `L2结构合同版本`。

### 4.1 事实和快照

```cpp
struct 安全根定义事实身份_v1 final { 稳定编码 值; };

struct 安全根定义事实_v1 final {
    安全根定义事实身份_v1 身份;
    L2存在身份 自我;
    L2特征定义身份 安全根特征定义;
    L2特征实例身份 安全根特征实例;
    std::int64_t 低位阈值;
    std::int64_t 高位阈值;
    std::uint32_t 定义版本;
    std::uint32_t 主动安全结算规则版本;
    std::uint32_t 被动服务维护规则版本;
    稳定编码 来源稳定编码;
    std::uint64_t 形成事实代次;
};

struct 安全根定义与当前值快照_v1 final {
    安全根定义事实_v1 定义;
    L2特征值事实 当前值事实;
    std::int64_t 当前安全根值;
    std::uint64_t 本次正式读回截止;
};
```

事实完整要求：全部身份有效；角色与锚点逐字段相同；`1 < L < H <= 本能根I64最大目标_v1`；三个版本非零；来源有效；形成代次非零。快照还要求当前值事实属于安全根特征实例、材料恰为 `int64_t A`、`0 <= A <= I64_MAX`、生命周期在截止有效且截止与请求 `G0` 相同。

### 4.2 发布

```cpp
struct 发布安全根定义请求_v1 final {
    std::uint32_t 合同版本;
    L2结构请求头 请求头;
    L2结构幂等身份 幂等身份;
    本能根运行锚点_v1 本能根锚点;
    std::int64_t 低位阈值;
    std::int64_t 高位阈值;
    std::uint32_t 新定义版本;
    std::uint32_t 主动安全结算规则版本;
    std::uint32_t 被动服务维护规则版本;
    稳定编码 来源稳定编码;
};
```

首版 `新定义版本 == 1`；后继必须等于当前版本 `+1`。相同幂等身份和逐字段相同请求返回首次提交结果，零新发布；同键异义为幂等冲突。发布状态及固定数值：

```text
已发布=1，精确重复=2，入口拒绝=3，许可拒绝=4，当前性漂移=5，
版本漂移=6，幂等冲突=7，引用冲突=8，资源失败=9，内部错误=10，
已可能发布=11
```

结果字段顺序：合同版本、状态、幂等身份、可选定义、首次提交事实代次、本次正式读回截止。只有 `已发布/精确重复 + 完整定义 + 两个非零截止 + 首次提交<=读回截止` 成功；`已可能发布` 只保留提交见证，定义为空、正式读回截止为零。

发布顺序：入口验证 -> 幂等首次材料预检 -> `G0` 前守卫 -> 锚点安全角色与 L2 特征实例读回 -> 确保登记 -> 读取当前定义 -> 版本连续性 -> 紧邻写入前真实当前代次 -> 写入新不可变定义值并切换当前槽 -> 按提交代次正式读回 -> 后守卫和逐字段互证。交换后读回失败返回 `已可能发布`，不得重写或伪造失败。

公开入口：

```cpp
安全根定义发布结果_v1 发布安全根定义_v1(
    const 发布安全根定义请求_v1&) noexcept;
```

### 4.3 当前定义读取

```cpp
struct 安全根定义读取请求_v1 final {
    std::uint32_t 合同版本;
    L2结构请求头 请求头;
    本能根运行锚点_v1 本能根锚点;
};
```

读取状态：`已读取=1、未发布=2、入口拒绝=3、许可拒绝=4、当前性漂移=5、引用冲突=6、资源失败=7、内部错误=8`。

结果字段：合同版本、状态、可选定义、本次正式读回截止。只有 `已读取 + 完整定义 + 截止==G0` 成功；全部非成功载荷空、截止零。

公开入口：

```cpp
安全根定义读取结果_v1 读取当前安全根定义_v1(
    const 安全根定义读取请求_v1&) const noexcept;
```

### 4.4 同截止定义与当前值读取

请求布局与定义读取相同但使用独立类型 `安全根定义与当前值读取请求_v1`。状态：`已读取=1、定义未发布=2、当前值未设置=3、入口拒绝=4、许可拒绝=5、当前性漂移=6、引用冲突=7、资源失败=8、内部错误=9`。

固定算法：`G0` 读前守卫 -> 读取当前定义 -> 调用 `L2特征结构服务::读取特征当前值({共同头, 锚点.安全根特征实例})` -> 校验定义、锚点、当前值逐字段绑定 -> `G0` 读后守卫 -> 返回完整快照。任何一边非成功、截止不等或读前后漂移都不返回部分载荷。

公开入口：

```cpp
安全根定义与当前值读取结果_v1 读取安全根定义与当前值_v1(
    const 安全根定义与当前值读取请求_v1&) const noexcept;
```

## 5. 所有者交付与普通应用装配

服务模块公开移动专用 `安全根定义所有者交付_v1` 和：

```cpp
std::optional<安全根定义所有者交付_v1>
尝试形成安全根定义所有者交付_v1(
    const L1事实基座服务&, L1所有者范围交付&&) noexcept;
```

交付必须核对 owner 建立身份、独占结构范围、当前 owner 事实、绑定服务和写端口。`普通应用上下文` 是唯一生产装配点：建立 owner、形成交付、构造服务、保存唯一 `unique_ptr` 并提供 const / non-const getter。装配只形成空 owner 和登记按需能力，不调用发布入口，不选择 `L/H`。

测试 fixture 可以显式发布一组满足约束的阈值验证机制；fixture 值不取得生产定义地位。编译、静态接线或 provider 自测不证明安全事件维护、被动回归或阶段三完整业务闭环。

## 8. 后继边界

本切片完成后，下一步仍需由正式生产发布者提供具体 `L/H` 与规则版本，随后才能把安全事件或服务回归候选接到阶段二变化入口。若届时没有正式定义，所有阶段三消费者必须材料不足并 fail-closed；不得由启动、测试常量、调度器或 UI 自动补值。
