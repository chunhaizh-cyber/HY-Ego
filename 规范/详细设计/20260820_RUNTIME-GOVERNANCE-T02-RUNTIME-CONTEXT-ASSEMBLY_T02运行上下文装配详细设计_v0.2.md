## 3. 所有权与模块环裁决

### 3.1 共享合同模块

未来施工新建：

```text
文件：海中鱼巣/业务/合同.自我世界树根消费.ixx
模块：海中鱼巣.业务.合同.自我世界树根消费
```

该模块唯一导出 `系统世界树根初始化.数据.h` 与 `自我世界树根消费.数据.h` 的稳定值类型闭包；只为类型可见性 import 正式 L2 场景结构模块，零服务对象、零读取、零编排。普通应用和自我线程均 import 该合同模块，不再互相通过业务装配模块取得 DTO；不得复制 DTO、建立转发头或第二 export owner。

### 3.2 普通应用唯一 owner

`海中鱼巣/装配.普通应用.ixx` 是下列对象的唯一 owning context：

```text
L1/DATA-L2现有结构服务与结构聚合
-> 未启动的线程生命周期服务
-> 未启动的单调时间适配器
-> 完整秒服务（只借用单调适配器）
-> 运行期事实版本服务（只借用同实例结构聚合）
-> 唯一自我线程对象（只借用生命周期发布端口和两个最终provider）
```

自我线程、provider、适配器和生命周期服务不得由全局 singleton、`shared_ptr`、service locator 或启动函数第二次持有。成员声明顺序必须保证自我线程先完成停止/join，再销毁被借用 provider；真正关闭边界尚由后继计划承接。

## 4. 运行上下文接口与装配顺序

### 4.1 根装配函数

普通应用内部唯一根函数保持：

```cpp
自我治理运行上下文装配结果 装配自我治理运行上下文(
    const L2结构聚合服务& 结构聚合服务,
    const 普通应用配置& 配置) noexcept;
```

返回成功时恰一完整候选，非成功时候选为空。执行者必须使用最终 provider/SELF ABI 的真实类型、状态、`noexcept`、值式移动能力机械匹配；若上游签名不同，不能凭本设计临场兼容，须退回计划支撑。

固定顺序为：配置准入 → 进程内分配运行代次/时间纪元/线程逻辑身份 → 生命周期服务 → 单调适配器 → 完整秒 → 事实版本 → 唯一未启动自我线程对象 → 无抛出整体交付。构造阶段零时间读取、零事实截止读取、零邮箱冻结、零 DATA 写入。

身份是三个独立的非零、单调、不回绕进程内序列；允许失败跳号，不复用，不从 DATA、墙钟、地址、系统线程 ID、日志或调用次数取得。具名 `自我治理事实范围版本`是合同版本，不是动态事实代次。

### 4.2 自我线程构造边界

`创建.自我线程.ixx` 未来只保存最终 SELF-THREAD ABI 要求的稳定借用和值式配置。其构造/创建函数必须满足：

- 删除 `import 海中鱼巣.装配.普通应用`；
- 删除内部完整秒、事实版本和批次路由 provider 的第二所有权；
- 不在构造期调用 provider 读取、不建立第二邮箱或第二路由；
- 邮箱、路由和物理线程的实际创建顺序只能按 SELF-THREAD 正式结果机械匹配。

本设计不发明 SELF-THREAD 的最终请求/结果字段；仅冻结 owner、借用方向和零治理路由调用门。最终结果未发布或字段漂移时，本计划不得激活。

### 4.3 启动阶段 20 适配

`启动.应用程序.ixx` 纳入本叶未来白名单。阶段 20 不再局部声明 `自我线程`、不传入存在服务、不直接调用 `开放治理运行门()`。启动仅通过普通应用上下文的具名创建边界消费唯一自我线程：

```text
普通应用上下文::创建并使自我线程停在治理运行门(SELF最终请求)
-> 结构化创建/停门结果
-> 非成功映射程序失败阶段::自我线程创建并停门 = 20
```

上述函数的请求/结果类型和 `noexcept` 必须以 SELF-THREAD 正式 ABI 为准；不存在时执行停止，不由启动侧重造一套 DTO。成功只表示唯一线程已创建并停在关闭门，绝不调用 `开放治理运行门()`。BIZ-L2-001-08 后继在关闭边界完成后才有权开放治理门。

生产代码在本叶必须保持以下字符串/行为零新增调用：

```text

```

当前文件中的旧调用属于待施工的执行现场事实；执行者不得把它们复制进 v0.2 新接线。完成上下文装配或创建并停门，不等于父循环可启动。

必须另立且先完成后才能激活父循环的关闭边界计划：

```text
停止新输入
-> 停止邮箱并唤醒阻塞等待
-> 路由返回并排空 / 保留待完成见证
-> 父槽互斥收口
-> join
```

该边界未发布正式结果前，不得开放治理门、不得接入首个冻结调用、不得把本叶声明扩展为优雅停机或完整生命周期。
