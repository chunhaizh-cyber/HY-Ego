## 1. 目标、结果与完成边界

本设计只完成路线方案 A 包：从当前生产树物理删除一份已经退出现行身份体系的旧句柄头，以及仅依赖该头、没有组外生产消费者的五份旧安全候选源码；同步删除旧句柄头在主工程和 filters 中的登记。

完成必须同时满足：

1. 第 3 节六份源码从当前仓库物理消失；
2. `海中鱼巣.vcxproj` 和 `海中鱼巣.vcxproj.filters` 中旧句柄头登记精确消失，场景及其它工程登记不变；
3. 当前剩余生产 C/C++ 源码对六份文件、五个模块及旧句柄类型的真实消费归零；
4. XML、删除闭包、隔离 Debug/Release x64 根工程构建和差异检查满足第 8 节合同；
5. 施工记录、验证记录、提交与普通推送只包含本包获准产物。

本包不重建安全能力，不修改 6140/6150 的安全业务语义，不迁移旧 DTO，不建立兼容入口，也不宣称安全治理、运行、恢复、集成验收或业务闭环完成。

## 3. 冻结物理变更

### 3.1 六文件删除集

执行者必须且只能物理删除：

```text
海中鱼巣/核心/句柄.h

海中鱼巣/领域/算法.安全任务权限.ixx

```

删除后不得建立备份目录、同名空文件、转发头、别名模块、兼容 DTO、默认成功实现或复制到业务目录的旧实现。

### 3.2 工程文件的精确删除

`海中鱼巣.vcxproj` 只删除下列完整单行：

```xml
    <ClInclude Include="海中鱼巣\核心\句柄.h" />
```

`海中鱼巣.vcxproj.filters` 只删除下列完整块：

```xml
    <ClInclude Include="海中鱼巣\核心\句柄.h">
      <Filter>头文件</Filter>
    </ClInclude>
```

不移动相邻项，不格式化工程文件，不删除或新增任何 `ClCompile`。工程最终差异中若出现 `合同.场景角色组织.ixx` 或其它场景登记变化，说明夹带了异主 WIP，本包不得提交。

### 3.3 退出的公开身份与函数

本包不新增或修改函数、DTO、状态值、稳定编码或事务。六文件中声明的全部类型、常量、函数和模块随唯一所有者文件整体退出当前公开面；没有迁移后签名，也没有替代实现。

诊断责任裁决：删除对象不再承担运行期诊断；现行安全业务未来实现仍须按新设计建立自己的结构化失败和最终记录边界，不能复用本包退出函数作为诊断入口。

已经占用的稳定编码只停止由旧代码解释，不回收、不重排、不复义。Git 历史和历史验证记录保留原样，可用于追溯当时实现，但不再是当前提供者。

## 4. 组外消费者零门禁

删除前必须重新扫描以下三层：

1. 文件/模块依赖：六个文件名、相对 include、五个完整模块名；
2. 旧头公开身份：`记录状态`、`节点类型`、`关系类型`、`节点稳定主键命名域ABI版本`、`节点稳定主键命名域`、`节点稳定主键`、`节点句柄`、`主信息句柄`、`关系句柄`、`稳定主键有效`、`句柄有效`；
3. 工程/脚本依赖：全部跟踪的 `*.vcxproj`、`*.vcxproj.filters`、`*.props`、`*.targets`、`*.ps1`、`*.cmd`、`*.bat`。

允许的删除前命中只有：

- 六文件组内互相 include/import；
- 主工程和 filters 对旧句柄头各一项登记；
- 文档、知识卡、历史记录中的人读历史叙述。

若出现组外生产消费者，不得只删除六文件而留下悬空引用，也不得临场补造替代类型。受影响切片停止，回报精确消费者、依赖身份和所需迁移范围，由计划治理重新闭合。历史文档字符串不触发代码迁移，也不要求全仓文字归零。

执行者取得工程文件时须读回：两文件相对正式 HEAD 已无场景差异、A 目标旧句柄登记仍各存在一次。若场景工程差异仍在，A 只保持等待，不在混合工程文件上施工。

## 6. 删除事务与非成功收口

本包没有运行期数据事务。施工事务按以下顺序完成：

```text
S0与组外消费者扫描通过
-> 工程文件正式交接并确认零异主差异
-> 记录删除前隔离构建
-> 六源码同批物理删除
-> 两工程登记同批精确删除
-> 静态归零、XML、隔离删除后构建和差异验证
-> 施工/验证记录

```

任一环节失败均不得通过恢复旧壳、扩大删除集或夹带异主 WIP来取得成功。未提交阶段可以继续修复本包自身的纯编辑/验证错误；出现真实组外消费者、目标 blob 漂移、工程所有权冲突或正式依据变化时，具名退回计划治理。
