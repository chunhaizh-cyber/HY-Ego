# 运行期提供者与现有消费者 ABI 收口详细设计 v0.1

日期：2026-08-20

计划身份：`RUNTIME-PROVIDER-ABI-CLOSURE`

当前状态：执行期具名漂移的后继设计；上游单调时间适配器尚未形成真实代码结果，只可登记待激活。

## 1. 来源问题与裁决

执行前复核发现，正式代码已经提前建立并接入一套与既有设计不一致的运行期提供者：

- `组合.运行期事实版本.ixx`直接持有 `const L2存在结构服务&`，没有服务配置，成功只返回裸截止；正式设计要求持有同一 `const L2结构聚合服务&`、保存运行配置并返回完整绑定材料。
- `服务.完整秒时钟.ixx`直接读取 `steady_clock::now().time_since_epoch()`，没有消费独立单调时钟适配器，且把新完整秒区间错误构造成 `[上一, 当前]`；正式设计要求使用从本实例纪元起点经过的纳秒证据，并构造 `[上一+1, 当前]`。
- 两个服务的 DTO 被提前集中到 `运行期Provider.数据.h`，且字段、状态名、optional 形状和数值类型均与正式设计不同。
- 旧 ABI 已被 `路由.自我治理批次.ixx`、`创建.自我线程.ixx`和 `启动.应用程序.ixx`消费，原两份窄计划均禁止修改这些调用方，因而不能原样施工。

裁决为：

1. 保留 `RUNTIME-MONOTONIC-TIME-EVIDENCE-PROVIDER v0.1`，不重复设计或扩大其白名单。
2. `RUNTIME-FACT-CURRENT-CUTOFF-CONSUME v0.1`与`RUNTIME-COMPLETE-SECOND-BOUNDARY-PROVIDER v0.1`退出，由本计划一次完成两个最终提供者合同及现有消费者机械迁移。
3. 不保留旧 DTO 别名、fallback、双构造函数或双路兼容；同一提交内删除旧形状并修复全部当前生产调用点。
4. 本叶只让提供者合同与现有消费者形成单一可编译 ABI；批次路由自身的待完成槽、原因分账和值式交付仍由 `RUNTIME-GOVERNANCE-CURRENT-BATCH-ASSEMBLY`后继完成，T02 最终所有权仍由运行上下文装配计划完成。

## 2. 目标与完成边界

本叶一次闭合：

```text
单调时钟适配器真实结果
-> 完整秒时钟服务只读消费适配器
-> 运行期事实版本服务只读消费L2结构聚合
-> 当前批次路由按最终子提供者DTO取值
-> 当前自我线程与启动入口按同一配置完成机械装配
```

完成只证明两个子提供者最终 ABI 已实现并且现有生产消费者已迁移、工程能够在一个提交中保持一致。它不证明批次路由目标状态机、普通应用最终持有关系、自我治理循环、完整秒业务结算、G0/G1 一致事实或集成验收完成。

## 3. 最终模块、DTO 与服务合同

### 3.1 单调时间依赖

本叶只 import 已实现的：

```cpp
import 海中鱼巣.适配.适配器.单调时钟;
```

并机械消费其 v0.1 合同：`稳态时钟时间源版本`、`单调时钟适配器`、`单调时间证据读取请求/结果`和`可信单调时间证据`。不得复制其 DTO、直接调用 `steady_clock`或引入第二纪元起点。

### 3.2 完整秒服务

物理位置保持：

```text
海中鱼巣/领域/服务.完整秒时钟.ixx
海中鱼巣.领域.服务.完整秒时钟
```

公开合同以 `20260815_RUNTIME-COMPLETE-SECOND-BOUNDARY-PROVIDER...详细设计_v0.1.md`第3—6节为唯一字段和状态依据：

- 服务构造为 `完整秒时钟服务(const 单调时钟适配器&, 完整秒时钟服务配置) noexcept`；
- 时间纪元身份使用 `std::uint64_t`，上一边界和当前边界使用非负 `std::int64_t`；
- 结果中观察和区间均为 optional，非成功双空，`无新完整秒`有观察无区间；
- 当前边界为 `从纪元起点经过纳秒 / 1,000,000,000`；
- 只有 `当前 > 上一 >= 0`形成区间，范围严格为 `[上一+1, 当前]`，数量为 `当前-上一`；
- 零 DATA、零墙钟、零游标写、零缓存、零直接 `steady_clock`。

### 3.3 运行期事实版本服务

物理位置保持：

```text
海中鱼巣/领域/组合.运行期事实版本.ixx
海中鱼巣.领域.组合.运行期事实版本
```

公开合同以 `20260815_RUNTIME-FACT-CURRENT-CUTOFF-CONSUME...详细设计_v0.1.md`第4—6节为唯一字段和状态依据：

- 服务构造为 `运行期事实版本服务(const L2结构聚合服务&, 运行期事实版本服务配置) noexcept`；
- 服务保存聚合 const 引用和值式运行代次/事实范围版本；
- 请求与配置逐字段一致后，才经同实例 `取得L2存在结构服务()`调用无参数 `读取当前事实代次()`；
- 只有 DATA 合同匹配、状态已读取、截止非零且变更事实代次为空时返回 `optional<已发布共享事实截止>`；
- 资源失败独立映射，其它坏状态或坏成功形状为内部不一致；全部非成功载荷为空；
- 零 L1 直达、零 owner 枚举、零 DATA 写、零缓存和零第二见证。

### 3.4 DTO 物理所有权

`运行期Provider.数据.h`当前把三个不同 owner 的 DTO 混在一个传统头中，并造成两个子提供者互相依赖。目标固定为：

- 完整秒 DTO 由 `海中鱼巣.领域.服务.完整秒时钟`唯一导出；
- 共享事实截止 DTO 由 `海中鱼巣.领域.组合.运行期事实版本`唯一导出；
- 批次路由 DTO 后继由 `海中鱼巣.线程.路由.自我治理批次`唯一导出；
- 本叶删除 `运行期Provider.数据.h`及其工程登记，不建立兼容头、转发头或第二实体定义。

当前路由尚未达到自身最终 DTO 合同。本叶可在路由模块内保留现有批次 DTO 的最小机械形状，但其子提供者字段必须改为最终类型：保存完整 `完整秒边界观察`、可选 `完整秒区间`和完整 `已发布共享事实截止`，不得重新扁平化后丢失运行代次、纪元、来源版本或事实范围回显。

## 4. 当前消费者迁移

### 4.1 自我治理批次路由

`冻结当前治理批次`对子提供者的调用和分支机械迁移为最终状态名与 optional 守恒：

- 完整秒 `已读取`必须有观察和合法区间，`无新完整秒`必须有观察且区间为空；其它状态不得带载荷；
- 共享截止 `已读取`必须有完整截止，且运行代次、事实范围版本与路由请求相等、截止非零；资源失败保持可重试；
- 保存成功材料时保存完整值，不只保存裸标量；形成当前批次时同样值式携带完整材料。

本叶只允许为最终子 DTO 做机械迁移和形状复核，不借机宣称路由的锁、消息守恒、重试见证、原因枚举或停止边界已经符合其独立详细设计。

### 4.2 自我线程与启动入口

当前临时装配仍在自我线程内，直到 T02 运行上下文装配后继替换。为使最终事实版本服务取得同实例聚合：

- `自我线程`当前构造参数由可空 `const L2存在结构服务*`机械改为可空 `const L2结构聚合服务*`；
- `启动.应用程序.ixx`传入普通应用上下文的 `取得L2结构聚合服务()`；
- 自我线程临时构造一个单调时钟适配器，再构造借用它的完整秒服务，并以同一结构聚合与配置构造事实版本服务；
- 运行代次、时间纪元、时间源版本、事实范围版本在同一临时配置中逐字段一致；禁止再令时间纪元默认等于平台 epoch 或从完整秒服务内部推导；
- 当前路由和治理循环只改字段访问以消费完整材料，不扩大任何 L2 治理骨架授权。

这只是现有调用点的过渡编译闭包，不改变 T02 详细设计中“普通应用最终唯一拥有适配器和两个提供者、自我线程只借用”的目标所有权。

## 5. 文件与依赖方向

| 文件 | 本叶变化 | 边界 |
| --- | --- | --- |
| `海中鱼巣/领域/运行期Provider.数据.h` | 删除并移除工程登记 | 禁止兼容转发和重复 DTO |
| `海中鱼巣/领域/服务.完整秒时钟.ixx` | 替换为最终 L3 合同并消费 L4 | 禁止直接平台时钟 |
| `海中鱼巣/领域/组合.运行期事实版本.ixx` | 替换为最终 BIZ 包装 | 只经 L2 结构聚合读取 |
| `海中鱼巣/线程/路由.自我治理批次.ixx` | 子提供者 ABI 与完整材料机械迁移 | 不声明父路由完成 |
| `海中鱼巣/线程/创建.自我线程.ixx` | 临时装配与字段访问迁移 | 不声明最终所有权或 T02 完成 |
| `海中鱼巣/启动.应用程序.ixx` | 传入同实例 L2 结构聚合 | 不新增运行语义 |
| `海中鱼巣.vcxproj`、`.filters` | 删除旧头登记；消费已由上游登记的适配模块 | 不重复登记模块 |

依赖方向固定为：适配 -> 完整秒；DATA-L2 -> 结构聚合 -> 事实版本；两个子提供者 -> 批次路由 -> 自我线程 -> 启动。禁止反向 import。

## 6. 验证与完成声明

最低验证围绕公开服务和现有合法消费者：

1. 完整秒公开入口的坏请求、纪元/版本漂移、真实读取、连续读取和并发读取；区间静态/动态确认 `[上一+1, 当前]`。
2. 事实版本公开入口的坏请求、真实 DATA 成功、连续和并发读取；成功完整回显，全部非成功 optional 为空。
3. 当前批次路由在真实两个子提供者下只能保存完整材料；旧字段、旧状态和裸截止无残留引用。
4. 启动入口能够经普通应用同实例结构聚合构造当前自我线程；根工程 Debug/Release 通过。
5. 生产代码零直接治理 `steady_clock`、零旧 DTO 头、零兼容别名、零旧构造签名。

无法确定性触发的真实时钟倒退、I64 极限、DATA 资源竞争与私有坏形状保持 `NOT_RUN`，不新增生产 fake seam。批次路由完整状态机、最终普通应用所有权、治理门开放后的业务闭环、G0/G1、完整秒结算、停止恢复和独立集成验收均为 `NOT_RUN`。

本设计只解决执行侧发现的 ABI 漂移，不证明任一后继业务计划已完成。
