# WORLD-TREE-P1A2G 两级关系与目标当前类型化值同许可投影详细设计 v0.1

日期：2026-08-03

设计身份：WORLD-TREE-P1A2G

创建侧仓库基线：`2931333f3e445e6c79feafbfe21b04980588a8c5`

## 1. 目标、范围与完成边界

本设计为 L1 `节点直接结构查询服务` 增加一次共享许可内的业务中性组合读取：重新解析必须节点，从根节点按关系类型与第一跳角色读取中间节点，再读取中间节点同类型全部当前相关关系，并读取其中指定目标角色所指节点的全部当前类型化值。全部输出只携带一个非零事实截止代次。

本叶子只形成 L1 同许可值式投影，不解释关系22的宿主槽、定义模板、当前值、来源或特征业务基数。它是 WORLD-TREE-FEATURE-Q 的真实前置提供者，但不读取世界树、SQL、材料或旧特征栈，不写机器事实，不形成快照成功。

直接规范依据：4010 v1.2 候选修订、4020 v1.2、4030 v1.1、4200 v0.8。上游业务依据改为 `流程图/目标业务流程图/业务节点到能力与目标函数映射.md` 的“世界事实维护”领域归属、P1BF 查询骨架及其当前函数图；已删除的 BIZ-L1-02 v0.2 图不再构成依据。P1BF 的 `未实现` 不替代本函数真实成功行为。4010 修订在 P1A2 活动结果发布并释放共享规范消费前只属于本设计候选，不得提前改变 P1A2 执行依据。

## 2. 当前接口行为与复用裁决

| 当前能力 | 当前事实 | 裁决 |
| --- | --- | --- |
| `节点直接结构查询服务` | 已持事务域、节点、关系、索引、类型合同、类型化值六引用 | 原类扩展；不建第二查询服务 |
| `读取当前节点`、`读取按源当前关系组`、`读取所属身份当前类型化值组` | 每次函数各自取得/释放共享许可 | 单项读取继续保留；禁止在 L2 连续调用后拼接同代次 |
| `正式关系仓库::读取有效源关系组/读取有效目标关系组` | 可按具名关系类型在当前仓内读取；“相关关系”旧重载固定普通父子 | 在同一事务域许可内分别读源组和目标组、合并去重；不修改仓库 |
| `节点直接类型化值仓库::读取所属身份当前值组` | 返回调用方拥有的当前值副本并按合同/记录身份排序 | 在同一事务域许可内复用；L1只复核记录完整性 |
| `形成节点见证_` | 已有私有纯值助手 | 原位复用 |
| `形成关系见证_` | 只按内部端点记录形成见证，未复核端点仍为当前身份 | 不改变旧助手；新增本函数专用 `形成当前关系见证_` |

最终裁决：在共享合同头追加一个请求和一个结果；在既有查询服务追加一个公开根函数和一个私有见证助手。仓库、事务域、SQL、旧服务和现有公开函数零修改。

## 3. DTO、稳定状态与所有权

唯一共享声明位置：`海中鱼巣/核心/节点直接结构合同.数据.h`。

```cpp
inline constexpr std::uint32_t 节点直接两级关系值投影合同版本 = 1;

struct 节点直接两级关系值投影请求 {
    std::uint32_t 合同版本 = 节点直接两级关系值投影合同版本;
    std::vector<节点稳定身份见证> 必须节点组;
    std::vector<节点稳定身份见证> 根节点组;
    关系类型 关系种类 = 关系类型::普通父子;
    std::int64_t 第一跳角色 = 0;
    std::int64_t 类型化值目标角色 = 0;
};

struct 节点直接关系目标当前类型化值投影 {
    关系稳定身份见证 目标关系;
    std::vector<类型化值读回> 当前值组;
};

struct 节点直接两级关系值投影结果 {
    节点直接结构结果头 头;
    std::vector<节点稳定身份见证> 必须节点组;
    std::vector<关系稳定身份见证> 第一跳关系组;
    std::vector<关系稳定身份见证> 中间节点相关关系组;
    std::vector<节点直接关系目标当前类型化值投影> 目标值组;
    std::optional<节点稳定身份见证> 未满足节点;
};
```

状态复用 L1 `节点直接结构服务状态` 的既有稳定值，不新增领域状态：成功1、未找到2、入口拒绝3、版本漂移4、许可拒绝5、资源失败6、内部不一致7。

请求/结果均为调用期纯值。请求由调用方拥有并 const 借用；服务不保存。返回由调用方拥有，可复制/移动，不含句柄、锁、许可、仓库、会话、SQL、游标或引用。

请求约束：

1. 合同版本必须等于1；关系类型数值必须小于 `正式关系类型ABI数量`。
2. 每个节点见证必须稳定主键有效、类型非未分类、身份版本非零。
3. 两组分别以节点稳定主键唯一；同一组内同主键出现第二项，无论其它字段相同或不同，均在许可前入口拒绝。根节点组必须是必须节点组的完整见证子集。
4. 两组均允许为空；角色是业务中性 I64，允许0及负值，L1不解释其领域意义。
5. 服务内部复制并稳定排序，不要求调用方预排序。

## 5. 根函数唯一执行顺序

1. 在 `try` 内校验合同、关系类型、全部节点见证、组内重复和根子集；失败返回入口拒绝、代次0、全部载荷空。
2. 测试宏开启且当前实例 `自检下一次两级投影资源失败_` 为 true 时，先将其清为 false，再抛出 `std::bad_alloc`；该检查位于合法入口之后、任何复制或仓库调用之前。否则复制并按节点稳定主键命名域、键值、类型数值、身份版本排序必须节点和根节点。
3. 调用 `事务域_.取得读取许可()` 一次；无效立即返回许可拒绝、代次0、空载荷。
4. 调用许可的 `读取已发布代次()` 一次；为0返回未找到、代次0、无未满足节点。
5. 依稳定顺序逐个调用 `节点_.读取稳定主键当前身份(见证.稳定主键)`：
   - 未占用/历史占用：返回未找到、当前非零代次、`未满足节点=请求见证`、其它载荷空；
   - 当前有效但记录/内部身份缺失：内部不一致、代次0、全空；
   - 当前记录类型或版本与请求见证不同：版本漂移、当前非零代次、未满足节点为请求见证、其它载荷空；
   - 当前有效且逐字段相同：把仓库当前记录重新形成的见证加入结果，并保存主键到内部句柄的调用期映射。
6. 逐根使用上一步映射的内部句柄调用 `关系_.读取有效源关系组(根句柄, 请求.关系种类)`。请求已经在许可前完成关系类型和见证准入，因此仓库再返回 `入口拒绝`、缺记录载荷或其它非 `已读取` 均表示内部句柄/仓状态矛盾，统一映射 `内部不一致`、代次0、空载荷，不再归因调用方入口。
7. 只保留 `源端=根且顺序号=第一跳角色` 的关系；逐条调用 `形成当前关系见证_`，失败即内部不一致。以关系稳定主键为唯一去重身份：同主键全部字段完全相等只留一项；版本或任一字段不同均为同稳定身份异内容，返回内部不一致。
8. 收集第一跳目标为中间节点，按节点稳定主键去重；同主键全部字段相等只留一项，类型或版本不同为内部不一致。
9. 对每个中间节点分别调用同关系类型的有效源关系组和有效目标关系组；请求已准入且句柄来自本许可当前解析，因此任一仓结果不是 `已读取` 都映射内部不一致。合并后按关系稳定主键去重，自环在两组各出现一次且内容相同只留一项；任一字段不同返回内部不一致。
10. 对合并的每条关系调用 `形成当前关系见证_`；全部加入 `中间节点相关关系组`。只有“中间节点是源端且角色等于类型化值目标角色”的关系形成一个 `目标关系` 投影；按该关系稳定主键排序和去重，不把多个目标关系压成一个裸节点集合。
11. 对每个目标关系的目标节点调用 `类型化值_.读取所属身份当前值组(目标关系.目标端.稳定主键)`。空组合法，仍保留 `{目标关系, 当前值组={}}`，从而区分“没有目标关系”和“目标关系存在但零当前值”。
12. 每条值先调用本模块唯一 `类型化值记录完整_`，再要求所属身份逐字段等于目标端、`当前=true`、首次发布代次和当前状态发布代次均不大于本次事实截止。完整性谓词逐项覆盖：节点或服务来源联合完整；I64区间下界不大于上界；稳定身份组逐项见证完整；独立材料引用身份有效、格式版本/字节数非零且 SHA-256 至少一字节非零；合同身份/版本、值记录身份/版本和两个发布代次完整。任一失败返回内部不一致、代次0、全空。
13. 每个目标关系的值按所属身份、类型合同身份/版本、值记录身份/版本排序；值记录稳定身份是唯一去重身份，同身份全部字段完全相等只留一项，版本或任一字段不同均返回内部不一致。相同所属身份、类型合同身份和合同版本出现两个不同当前值记录身份也属于同合同键当前多解，返回内部不一致。
14. 关系组分别按关系稳定主键命名域、键值、关系版本排序；目标值组先按目标关系稳定主键排序，其内当前值按第13步排序；必须节点组沿第2步顺序。
15. 返回成功、当前非零事实截止、必须节点组、两个关系组、完整目标值组和空未满足节点。返回时许可析构；服务不把许可传出。
16. 进入 `try` 前分别以 `static_assert(noexcept(节点直接两级关系值投影结果{{节点直接结构服务状态::资源失败, 0}, {}, {}, {}, {}, std::nullopt}))` 和内部不一致同形表达式，冻结两种空失败结果为无分配构造。捕获 `std::bad_alloc` 和 `std::length_error` 时只返回前一完整聚合表达式；捕获其它异常时只返回把状态替换为 `内部不一致` 的完整聚合表达式。不追加字符串、向量或诊断载荷；函数 `noexcept`，任何异常不得越过 L1 服务边界。

不重试、不 sleep、不读取时钟、不查询 SQL。根函数只有一次事务域许可；仓库内部锁仍由各仓自行管理。

## 6. 私有纯函数唯一行为

### 6.1 `形成当前关系见证_`

1. 要求关系记录完整且状态为有效。
2. 分别调用 `节点_.读取节点(记录.源节点/目标节点)` 读取精确端点记录；任一不存在返回空。
3. 分别按端点记录稳定主键调用 `节点_.读取稳定主键当前身份`；必须是当前有效且同时有当前身份/记录。
4. 当前内部句柄必须等于关系记录端点句柄；当前记录稳定主键、类型、版本必须逐字段等于精确端点记录。
5. 形成关系稳定身份见证；其类型、版本、角色及两端见证全部直接来自已复核记录。

助手不取得事务域许可、不排序、不访问关系仓/值仓/SQL；只有根函数在持有许可时调用。节点仓读取取得内部共享锁时可能抛出，助手不标 `noexcept`、不自行吞并；异常上浮到根函数并统一映射内部不一致。正常空结果只由根函数映射内部不一致。

### 6.2 类型化值完整性谓词

三项谓词与 `节点直接结构查询服务` 同模块、非导出、无状态、无分配、`noexcept`：

1. `类型化值来源完整_`：联合为节点时调用 `节点稳定身份见证完整`；联合为服务时要求 `服务稳定身份完整`；不存在第三分支。
2. `类型化值材料完整_`：I64 区间要求 `下界<=上界`；稳定身份有序组逐项调用节点见证完整；独立材料引用要求材料稳定主键有效、格式版本非零、字节数非零且 SHA-256 至少一个字节非零；I64/U64 标量和 I64/U64 有序组的结构形状天然完整，业务值域由领域层裁决。
3. `类型化值记录完整_`：要求所属节点见证完整、类型合同身份完整、合同版本非零、值记录身份完整、值记录版本非零、来源与材料分别通过前两项、首次发布代次非零且当前状态发布代次不早于首次发布代次；是否当前、所属是否等于目标以及两个代次是否晚于本次事实截止由根函数另行复核。

正式仓库的同名 private 谓词只作等价事实证据，不能被查询服务调用。上述算法在查询模块只有一份实现；自检若需要覆盖非法材料，使用 §8 冻结的测试宏适配调用同一实现，不复制第二套判断。

## 7. 结果状态与完整性矩阵

| 状态 | 事实截止 | 四业务组 | 未满足节点 | 语义 |
| --- | --- | --- | --- | --- |
| 成功 | 非零 | 完整，可全空/部分组空；目标关系可携带空当前值组 | 空 | 全部请求节点有效且投影自洽 |
| 未找到 | 代次0或已取得的非零代次 | 全空 | 仅具名节点缺失时有值 | 代次0或请求节点未占用/历史占用 |
| 入口拒绝 | 0 | 全空 | 空 | 请求、关系类型、重复或根子集非法 |
| 版本漂移 | 已取得的非零代次 | 全空 | 第一个稳定排序后的请求见证 | 当前主键类型/版本不同 |
| 许可拒绝 | 0 | 全空 | 空 | 一次共享许可未取得 |
| 资源失败 | 0 | 全空 | 空 | 分配/容量异常 |
| 内部不一致 | 0 | 全空 | 空 | 仓、端点、重复身份异内容或值记录矛盾 |

合法零固定为两类：全部必须节点已重新解析但没有匹配第一跳关系时，返回成功、非零代次，必须节点组可非空，其余三业务组空；存在目标关系但其目标没有当前类型化值时，返回成功并保留该目标关系及空当前值组。两类不得合并，领域服务据此裁决业务缺项。

## 8. 工程、自检与验证

不新增自检模块、工程登记、启动适配或自检顺序。P1A2G 专项矩阵追加到现有 `海中鱼巣/核心/自检.节点直接身份结构写入.ixx` 的 `运行节点直接身份结构写入自检()`；`WORLD-TREE-P1A2-S01`、顺序170和完整自检登记数量均保持不变，避免人为建立 P1A2G 对 P1A3F/P1A2Q/P1BF 的计数依赖。

运行路径使用隔离真实事务域、六仓和查询服务，通过正式 P1A2 提交服务建立合法节点/关系/类型化值；不得伪造仓库子类、手写 provider 返回或接入正式 SQL。仅在既有 `HY_EGO_ENABLE_STRUCTURE_COMMIT_FAULT_SELF_TEST` 下，`服务.节点直接结构.ixx` 可以导出以下只供自检使用的适配：

```cpp
bool 自检验证两级投影类型化值完整性(
    const 类型化值读回& 值) noexcept;
void 自检注入下一次两级投影资源失败(
    节点直接结构查询服务& 服务) noexcept;
```

第一项必须调用生产根函数使用的同一三项完整性谓词；第二项把目标服务实例的宏内私有布尔值设为 true。下一次合法根调用在任何复制/仓库调用前先清零再抛出并由公开边界映射资源失败；入口拒绝调用不消费该注入。该注入只允许单线程隔离自检，不提供并发保证。宏关闭时两入口、friend 和故障状态均不存在。悬空端点、同稳定关系异内容等无法由正式仓库公开合同构造的防御分支，以 AST/源码机械证明“形成当前关系见证失败或稳定身份冲突必达内部不一致且清空载荷”，不得为了动态断言增加仓库损坏入口。

至少覆盖：空请求；必须节点合法但零第一跳；多根稳定排序；重复节点；根非子集；未知关系类型；节点未找到/历史占用/版本漂移；第一跳多目标；中间节点源/目标/自环合并去重；目标关系存在但零值仍保留；多值稳定排序；类型化值 I64 反向区间、坏身份组、坏独立材料、错所属、非当前和发布代次非法；许可竞争；一次资源失败注入；所有非成功零部分载荷；SQL关闭结果不变；前后六仓与代次逐值相等；Debug/Release、完整自检和 AST 调用边。关系/值去重键必须由静态检查证明只使用稳定主键/稳定记录身份，版本只参与排序和冲突检查，不参与身份分组。
