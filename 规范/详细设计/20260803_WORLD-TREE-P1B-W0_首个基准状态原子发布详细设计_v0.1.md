## 2. 范围与完成边界

输入是调用方拥有并在同步调用期间只读借用的 `世界树状态动态请求`。成功输出是调用方按值拥有的 `节点直接状态动态发布结果`，必须满足：

1. 状态为 `已提交(1)` 或 `幂等读回(2)`；
2. 发布代次非零，持久状态原样来自 L1；
3. 读回恰含完整后状态，迁移动能为空，缺项组为空；
4. 普通内存权威同一代次发布状态发生时间合同、状态节点、时间值及关系19角色1—5；
5. 失败发生在最后发布前时，普通可读事实零变化；隔离由 L1 原样承担。

本设计不证明 P1B-Q、FEATURE-Q、L1 混合创建提供者已经实现，不证明后继状态、动态、比较、世界树门面、生产装配、SQL恢复或上层服务验收完成。

## 3. 公开 ABI 与内部类型

公开 ABI 完全沿用 P1B-F，禁止增加字段、重载或状态值：

```cpp
节点直接状态写项形成结果
节点直接状态业务服务::形成完整世界实例状态写项(
    const 世界树完整状态请求& 请求) const noexcept;

节点直接状态动态发布结果
节点直接动态业务服务::发布状态并整理动态(
    const 世界树状态动态请求& 请求) const noexcept;
```

`节点直接状态写项形成结果::状态` 因既有 ABI 复用 `节点直接状态动态发布状态`。形成成功时固定使用 `已提交(1)` 作为“形成成功载码”；该值只允许外层继续组装事务，不证明任何机器事实已经提交。只有 L1 `提交` 成功后，外层才可返回公开 `已提交`。

在 `数据操作.节点直接状态动态.ixx` 内新增以下模块公开、业务内部值式合同：

```cpp
enum class 节点直接状态动态形成状态 : std::uint8_t {
    已形成 = 1,
    入口拒绝 = 2,
    版本漂移 = 3,
    资源失败 = 4,
    内部不一致 = 5
};

struct 节点直接状态动态摘要形成结果 {
    节点直接状态动态形成状态 状态 =
        节点直接状态动态形成状态::入口拒绝;
    std::array<std::uint8_t, 32> 摘要{};
};

struct 节点直接状态动态事务形成结果 {
    节点直接状态动态形成状态 状态 =
        节点直接状态动态形成状态::入口拒绝;
    std::optional<节点直接类型化结构事务请求> 事务;
};
```

全部结果由调用方按值拥有，不含引用、指针、句柄、许可、锁、事务视图、SQL身份或日志文本。默认值不是成功。

## 4. 请求准入与来源

`发布状态并整理动态` 在任何依赖调用前逐项验证：

- `请求.合同版本 == 节点直接状态动态发布合同版本 == 1`；
- 世界请求头完整且合同/规则版本符合 P1B-F；
- 世界根、场景、主体、特征、特征值、来源存在六个见证逐字段完整且节点类型符合现行世界事实合同；
- 整理幂等身份命名域固定为 `0x5754534400000001`，键值非零；
- `发生时间戳` 为任意 `std::uint64_t`，0合法；
- 不从名称、SQL、材料、日志、缓存、时钟或旧栈补字段。

任一非法返回 `入口拒绝(3)`、发布代次0、持久状态不适用、读回空、缺项组空；全部依赖调用数0。

## 5. 请求意图摘要

新增函数：

```cpp
节点直接状态动态摘要形成结果
节点直接状态动态数据操作::形成状态动态请求意图摘要(
    const 世界树状态动态请求& 请求) const noexcept;
```

唯一职责是形成确定性 SHA-256 摘要。编码顺序固定：

```text
格式版本U32=1
操作标签U8=1
节点直接状态动态发布合同版本U32
世界请求头合同版本U32
世界规则版本U32
世界根见证
场景见证
主体见证
特征见证
特征值见证
来源存在见证
发生时间戳U64
整理幂等身份命名域U64
整理幂等身份键值U64
```

节点见证固定编码为稳定主键命名域U64、键值U64、节点类型U32、身份版本U32。所有整数使用网络字节序。禁止编码结构体内存布局、padding、RTTI、`variant.index()`、显示名称或容器遍历偶然顺序。算法固定标准 SHA-256，并用空串和 `abc` 标准向量验证。

编码非法映射入口拒绝；分配或散列设施失败映射资源失败；产生全零摘要或内部长度不一致映射内部不一致。函数不写日志，不读取机器事实。

## 6. 状态写项形成

状态服务只做窄委托：

```cpp
节点直接状态写项形成结果
节点直接状态业务服务::形成完整世界实例状态写项(
    const 世界树完整状态请求& 请求) const noexcept {
    return 数据操作_.形成完整世界实例状态写项(请求);
}
```

数据操作新增同名函数：

```cpp
节点直接状态写项形成结果
节点直接状态动态数据操作::形成完整世界实例状态写项(
    const 世界树完整状态请求& 请求) const noexcept;
```

局部身份固定且不得由容器位置推导：

| 对象 | 局部身份 |
| --- | --- |
| 状态节点 | `节点:1` |
| 状态发生时间值记录 | `类型化值记录:2` |
| 关系19角色1—5 | `关系:101`—`关系:105` |

确定写项顺序恰为：

1. `状态发生时间类型合同` v1：L2领域命名空间键1、U64标量、值域0..UINT64_MAX、`状态服务身份`、当前可写、兼容组空；
2. 状态节点：局部 `节点:1`，使用 P1B-F 冻结的状态节点稳定主键命名域和节点类型；
3. 时间值：所属 `节点:1`、状态发生时间合同v1、局部 `类型化值记录:2`、无前版本、材料U64=`发生时间戳`、来源为请求的来源存在见证；
4. 关系19角色1：状态节点到主体；
5. 关系19角色2：状态节点到场景；
6. 关系19角色3：状态节点到特征；
7. 关系19角色4：状态节点到特征值；
8. 关系19角色5：状态节点到来源存在。

读回规格恰7项且顺序固定：当前节点 `节点:1` 预期版本1、当前类型化值 `类型化值记录:2` 预期版本1、当前关系 `关系:101`—`关系:105` 预期版本1。类型合同由 L1 在原许可内参与确认，但不进入公开提交结果的7项业务读回。

成功返回形成成功载码、状态局部身份、8写项和7读回；任何局部身份冲突、类型错误、数量错误或异常返回入口拒绝/资源失败/内部不一致并清空全部形成材料。

## 7. 查询、同代次与前状态裁决

幂等探测必须先于所有可变事实查询：

```cpp
提交_.探测幂等(请求.整理幂等身份, 请求意图摘要)
```

映射：未找到继续；同义已发布仅在原结果精确为1节点+1值+5关系且能还原同一基准状态时返回幂等读回；异义冲突、待发布或隔离、许可拒绝、内部不一致分别映射为公开同名状态或内部不一致。不得用普通查询补齐原结果。

未找到后：

1. 构造 `场景组={后状态.场景}`、`主体组={后状态.主体}`，调用 P1B-Q 恰一次；
2. 来源存在与主体逐字段相同时，来源验证复用该次结果代次；
3. 异源时第二次调用 P1B-Q，参数固定 `场景组={}`、`主体组={后状态.来源存在}`，只接受成功、非零代次且状态组/动态组/缺项组全部为空；
4. 调用 FEATURE-Q 恰一次，宿主组固定 `{后状态.主体}`；
5. 目标查询、来源验证、特征查询的事实截止代次必须完全相等且非零；不取最大值、不重试、不用时间代替；
6. 主体当前完整特征中，目标特征必须恰一且当前值见证等于请求特征值；零项/身份漂移为版本漂移，重复或矛盾为内部不一致；
7. 从目标状态组筛选同场景、主体、特征的前状态。非空立即返回 `未实现(14)`，比较调用0、提交调用0。

提供者合法非成功按其正式合同映射；提供者缺失或仍为未实现不得转成空成功。

## 9. 提交、发布与结果映射

动态服务最多调用一次：

```cpp
提交_.提交(*事务结果.事务)
```

不重试版本漂移，不等待许可，不拆分写集，不执行失败后补写。L1 状态逐项映射：已提交→已提交，幂等读回→幂等读回，入口拒绝→入口拒绝，幂等冲突→幂等冲突，版本漂移→版本漂移，许可拒绝→许可拒绝，资源失败→资源失败，内部不一致→内部不一致。

只有已提交/幂等读回可以解析通用读回。读回必须恰为1节点、5关系、1类型化值且：

- 状态节点类型、稳定身份和版本完整；
- 五关系均为关系19、角色1—5恰一，源端均为状态节点，目标端分别匹配请求五见证；
- 时间值所属状态节点、合同身份/版本、材料U64、来源存在及发布代次完整；
- 七项均由同一 L1 结果携带，发布代次非零；
- 不含索引或额外对象。

匹配后构造 `世界树状态事实`，迁移动能=`std::nullopt`、缺项组空。成功分类但读回矛盾返回内部不一致并保留 L1 持久状态，不二次查询或补写。非成功结果发布代次0、读回空；持久状态仅按 L1 原样保留。

## 10. 所有权、生命周期、并发与诊断

- 服务引用由运行期装配拥有并长于服务及全部同步调用；请求只读借用，结果按值返回；不保存调用参数引用。
- 数据操作是无状态确定性形成器，不取得许可、锁、代次、仓库或 SQL。
- 动态服务只通过 P1B-Q、FEATURE-Q、状态窄服务和 L1 服务函数交互；上层不得接触锁、许可、会话或参与者。
- 原子性、候选确认、逆序撤销、最后发布和隔离由 L1 独占；本层不建立第二事务控制器。
- `发布状态并整理动态` 为 `noexcept`，必须捕获摘要、容器、查询和提交边界逸出的异常。合法拒绝不记录错误；本层首次资源失败、内部不一致或未知异常由模块私有无抛诊断助手记录一次。下层已诊断时只映射。
- SQL仅用于存储、应急和交互，不是权威事实；本叶生产模块不得 import 或调用 SQL。

## 12. 验证合同与漂移收口
