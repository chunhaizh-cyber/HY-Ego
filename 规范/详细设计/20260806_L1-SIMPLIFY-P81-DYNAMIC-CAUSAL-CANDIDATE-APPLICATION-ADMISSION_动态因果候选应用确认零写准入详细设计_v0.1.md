## 1. S0、复用裁决与最早缺口

P76 是动态事实到事件级待应用确认候选的唯一解释者；P79 只发布首次候选；P80 只从一次
P17 非阻塞快照读取当前候选，并明确不回显完整状态和动态事实。三者均不得被后继第二解释。
P76—P80 当前仍待激活，本文只冻结待实现接口，不宣称代码能力存在。

应用确认不能只看 P79 发布结果，也不能把 P80 候选事件键直接当成跨事件模式身份：候选键
包含原证据状态、动态和事件时间，后继应用必须是不同且更晚的事件。当前旧
`动态模式结构键`又要求动作存在，与用户已裁决的被动因果和零动作前提冲突，不能复用。
旧轻量因果、概率候选、日志和用途观察也都不是应用事实来源或确认所有者。

正式 P27/P28/P29 已冻结同一完整世界快照中的状态、关系20迁移动能、状态采样 I64、事件时间
和共同截止。因此无需先造第二动态读取者或抽象模式账。P81 是应用确认之前最早可独立施工的
零写准入叶：只消费调用方取得的 P80 当前读取结果与 P29 完整世界快照结果，针对请求具名的
一个当前候选和一个更晚应用动态，形成未来确认发布者可消费的完整纯值规格。

本叶不发布确认事实，不分配稳定因果身份、幂等域、操作标签、意图编码或写集；原子确认发布、
候选退出、已确认因果读取、可信度/稳定度修订和安全直接因果图均为后继独立目标。

## 5. 入口、上游状态与共同截止

入口先验证两个版本、非零世界根/预期截止/候选/应用动态，失败返回入口拒绝且不检查载荷。
随后映射上游：

| 上游结果 | P81结果 |
| --- | --- |
| P80 `已读取`且完整集合 | 继续 |
| P80 `尚无候选登记` | 候选尚无 |
| P80 许可拒绝/资源失败/版本漂移 | 同名映射 |
| P80 其它状态或坏成功 | 内部不一致 |
| P29 成功且快照完整 | 继续 |
| P29 许可拒绝/资源失败/版本漂移 | 同名映射 |
| P29 未找到、入口拒绝、内部不一致、未实现或坏成功 | 内部不一致 |

成功材料必须同时满足：请求世界根等于 P80/P29 世界根；请求预期截止等于 P80结果、候选集合
和 P29 快照截止；合同、规则、完整性和排序版本精确兼容。两个成功结果之间仅截止不同返回
版本漂移；同截止下其它矛盾属于内部不一致。函数不等待、sleep、重试、改截止或重取快照。

## 6. 候选和应用动态选择

P80集合允许零、一个或多个候选；P81只按请求候选编码选择，不按排序位置、名称或最新项猜测：

1. 集合为空或目标候选零匹配：`候选尚无`；
2. 目标候选恰一：继续；
3. 同编码多项、同编码异内容、候选键重复或成功集合不完整：内部不一致。

P29动态组允许零、一个或多个动态；同样只按请求应用证据动态选择：零匹配为
`应用证据尚无`，恰一继续，多项或同编码异内容为内部不一致。P81不自动扫描其它动态替换请求
证据，也不只选有利结果；因此本叶不形成概率、可信度、稳定度或反例统计。

候选必须仍为`待应用确认`。按候选键的原证据动态、条件状态和结果状态在 P29 同截止动态组、
状态组各找到恰一事实，并逐项互证世界、场景、主体、被改变目标、时间、状态端点和来源链。
缺失、重复、半结构或候选引用与 P29 权威事实矛盾均为内部不一致，不降级为候选尚无。

## 7. 应用确认准入规则

请求具名应用动态先通过 P27/P29 已冻结的完整关系20合同：角色1—5/9各一、角色6—8为0，
前后状态完整、差异非零、来源链可回查且`0 < 前时间 < 后时间 <= 共同截止`。P81不要求、
读取或补造动作身份与方法运行身份。

随后按固定顺序比较：

1. 应用动态编码必须不同于原证据动态，且应用条件/结果状态身份不能复用原事件两端；
2. `应用条件时间 > 原结果时间`且`应用结果时间 > 应用条件时间`，否则拒绝`不是后继事件`；
3. 世界、场景、主体和被改变目标依次与候选相同，任一不同按对应原因拒绝；
4. 原条件状态采样 I64 等于应用前状态采样 I64，否则拒绝`条件值不相同`；
5. 原结果状态采样 I64 等于应用后状态采样 I64，否则拒绝`结果值不相同`；
6. 全部成立才形成一份完整规格。

比较的是同一对象、同一特征实例槽上的有向`A→B`应用，不要求状态事件身份相同。后续
`B→A`是允许的另一事件和另一方向候选，若被拿来确认`A→B`只返回方向/值不相同，不构成
事件级时间环或内部损坏。稳定编码仅作具名选择和平局身份，不赋予时间先后。

一次完整准入规格只证明“这一候选与这一后继实际动态满足未来确认发布的输入资格”。它不审查
其它机会或反例，不把一次匹配升级为抽象稳定因果，也不直接提供“准备因必得果”保证；只有
后继确认发布者把规格作为正式事实原子发布并经正式读取后，已确认因果消费者才可按其适用范围
承担保证。

## 8. 生命周期、零写与错误

P81返回调用方拥有的不可变纯值，不保存引用、缓存或上次结果。它不退出候选、不改变P80事实，
不发布已确认因果、样本计数、反例、用途观察或图边。全部节点、关系、值、槽、退出、事务、
幂等、稳定编码分配和锁调用数均为0。

`std::bad_alloc`映射资源失败；其它未预期异常映射内部不一致。业务拒绝不抛异常，内部损坏不
伪装成拒绝确认或尚无。当前只覆盖同一生产进程正常存活期间的调用；不设计崩溃、断电、重启、
恢复介质、启动扫描或跨进程幂等重放。
