## 1. 目标与完成边界

本叶为节点直接新域建立唯一简化 `4170` 运行期侧账的已发布记录值式形状、账所有权和按批次身份非阻塞读取 provider：

```text
强类型域内批次身份
+ 稳定编码 / 节点种类组成的不可变结构见证
+ 初始或换代项目的完整连续有序语义
+ 发布事实代次
+ 唯一领域账
+ try-lock 按身份读取
```

读取成功只返回调用方拥有的不可变已发布记录副本。它不读取 L1，不验证记录所引用事实的当前性，不计算幂等同义，不返回特征批次业务成功；后继特征数据操作必须再用 L1 权威读回互证全部结构。

本叶不实现 P37 附属事务参与者，不形成或发布候选记录，不消费 P36 规格，不分配稳定编码，不提交 L1，不形成初始特征批次，不提供全量冻结、恢复装配、SQL 持久证据、P32 第二写门面或运行期接线。

## 5. 完整性与唯一性

提供纯值 helper：

```cpp
bool L1特征批次发布记录完整(const L1特征批次发布记录&) noexcept;
```

完整性固定要求：

1. 两版本精确为1，批次身份、宿主和发布事实代次非零，项目组非空且不超过 `uint32_t`；
2. 宿主、特征定义、实例槽和来源均为当前合同中的非零普通节点见证；
3. 项目顺序恰为 `0..N-1`；宿主关系固定 `宿主 -> 实例槽`、定义关系固定 `实例槽 -> 特征定义`，两者顺序均为0，关系类型非零且互异；
4. 新当前值所属实例槽、属性类型和来源精确匹配项目见证；不复制原始材料；
5. 初始项 `写前当前值` 必为空；后继权威读回必须证明实例槽、宿主关系、定义关系和新当前值均创建于记录发布代次；
6. 换代项 `写前当前值` 必存在，所属槽和属性类型与新当前值相同且编码不同；后继权威读回必须证明旧值在记录发布代次退出、新值在同代次创建，实例槽和两结构关系保持当前；
7. 全组定义、实例槽、宿主关系、定义关系和新当前值分别唯一；来源可重复；任一稳定编码不得在不相容角色中复用；
8. 记录只解释本批次引用，不允许夹带其它槽位或以空 optional 表示损坏换代。

helper 只校验记录自身形状，不读取 L1，不证明见证当前有效。后继幂等读回必须逐项读取 L1 当前/历史事实并互证。

新模块导出：

```cpp

    L1特征批次身份 批次;
    std::optional<L1特征批次发布记录> 记录;
};

class L1实例特征批次数据操作 final {

    L1实例特征批次数据操作() = default;
    L1实例特征批次数据操作(const L1实例特征批次数据操作&) = delete;
    L1实例特征批次数据操作& operator=(const L1实例特征批次数据操作&) = delete;
    L1实例特征批次数据操作(L1实例特征批次数据操作&&) = delete;

```

数据操作内部按批次身份升序保存唯一记录项，并保留 `候选 / 已发布 / 已隔离` 内部状态与全账隔离标记；这些类型、容器、锁和状态不 export。P38 生产路径没有写入函数，候选/隔离状态只为后继参与者原位扩展预留，不得经测试 seam 形成生产能力。

返回结果始终回显调用方批次身份；仅 `已读取` 携带记录。`未找到` 是精确身份未命中，不是合法空成功；零身份为 `入口拒绝`。未知记录格式单独返回 `未知格式`，完整性损坏、重复身份、候选/隔离泄露或账已隔离返回 `内部不一致`。

## 7. 固定读取流程

`读取发布记录` 固定执行：

1. 回显输入身份；零身份立即 `入口拒绝`，不取锁；
2. 对唯一账执行 `std::shared_lock<std::shared_mutex>(..., std::try_to_lock)`；失败立即 `许可拒绝`，不等待、不循环；
3. 全账隔离返回 `内部不一致`；
4. 按升序容器二分精确查找身份；未命中返回 `未找到`；相邻重复身份为 `内部不一致`；不得线性扫描猜测或按最大身份推导；
5. 命中项必须是 `已发布`；候选或隔离项出现在可取得共享锁的普通读取中属于 `内部不一致`；
6. 格式版本非1返回 `未知格式`；业务规则版本非1或记录不完整返回 `内部不一致`；
7. 复制完整记录。`std::bad_alloc` 返回 `资源失败`，其它异常返回 `内部不一致`；
8. 复制结果批次必须等于输入且完整，再返回 `已读取`。

函数不读取 L1、P8、P36、P37、SQL、材料、缓存或旧账，不取得独占锁，不 sleep、不重试、不返回内部引用/span/迭代器。

## 8. 并发、生命周期与权限

账与数据操作同寿命、同运行期域唯一；记录发布后不可修改或删除。普通读取只持有一次 try-lock 共享许可并返回自有副本。未来参与者必须持独占许可覆盖候选准备、确认、最后发布、P15同锁读回及成功释放/失败隔离；因此普通读取不会看到候选，也不会在 L1 读回完成前看到已发布标记。

本叶不把数据操作装配进生产上下文。后继生产装配只能建立一个本域实例，并把其只读函数交给具名单领域消费者；不得向 L2 暴露数据操作对象、内部账、锁或测试注入 seam。

自检通过模块私有 friend 访问器注入已发布/损坏夹具；friend 不导出生产写函数，不得被其它模块调用。静态扫描必须证明生产模块对该访问器调用为0。

## 9. 后继 P39 参与者边界

后继简化 4170 参与者必须原位扩展同一 `L1实例特征批次数据操作`，不得新建第二账。它至少承担：

```text
消费完整记录草案及 P37 写前 / 候选见证
-> 在账独占许可内最终重检批次身份未命中
-> 形成排序位置确定的不可见候选
-> 准备、确认、逆序撤销
-> 关闭撤销后无失败发布并继续持有许可
-> P15读回成功释放或矛盾时标记隔离并释放
```

P39 才能 import P37 内部参与接口。本叶不定义记录草案、本地键到稳定编码映射、参与者状态机或提交函数。最终初始特征发布者仍需在 P39 之后另叶设计。
