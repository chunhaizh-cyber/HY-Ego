# 按来源读取当前状态组详细设计 v0.1

日期：2026-08-15

设计身份：`DATA-L2-STATE-CURRENT-GROUP-READ-BY-SOURCE`

状态：设计就绪；不等于代码已实现

## 1. 目标与当前缺口

为 `L2状态结构服务` 增加按来源稳定编码读取全部当前状态的强类型条件查询。调用方给出非零当前事实代次守卫、当前来源节点和状态数量预算；服务返回按状态身份稳定编码严格升序的完整当前状态组，全部状态与其身份来源、主体、特征实例、精确值、时间值和生命周期共享同一事实截止。

现行状态服务已经实现新增、完整当前 / 历史读取、身份来源、按主体 / 特征实例读取、引用替换、值换代和退出。现行 L1 已由结果提交 `8e0928671d3584d399ce4d796b890401073e5676` 发布 owner + 来源节点有界当前值组原子读取。真实缺口不是重新实现 CRUD，也不是让状态服务扫描全部状态，而是把该中性 L1 provider 收敛为状态强类型结果。

具名缺口：`DRIFT-DATA-L2-STATE-CURRENT-GROUP-READ-BY-SOURCE-MISSING`。

## 2. 边界与所有权

本设计只补当前来源查询，不补时间范围查询，不改变状态创建、替换、值换代、退出或历史读取，不建立缓存、第二索引、分页游标、零守卫最新读取或业务专用来源类型。

来源仍是不透明 `稳定编码`。状态服务只证明它是当前 L1 节点且当前状态值确实引用该来源；不判断材料来源是否可信、状态是否真实、来源属于哪个业务对象，也不主动形成状态。

唯一结构所有者仍为 `L2状态结构服务`。查询只使用：

```text
L2状态结构服务私有状态 owner
+ L1事实基座服务::按来源读取所有者范围全部当前值
+ L2状态结构服务::读取完整状态
```

禁止直达 L1 仓库、扫描全部值 / 状态、跨 owner 列举、调用缓存或从名称和本地键猜状态。

## 3. 精确公共 ABI

### 3.1 共同状态扩展

物理所有者：`海中鱼巣/领域/L2结构公共.数据.h`。

在不改变现有 1—14 数值的前提下追加：

```cpp
enum class L2结构状态 : std::uint8_t {
    // 现有 1—14 保持不变
    数量预算不足 = 15
};
```

该状态表示完整结果数量超过调用方预算，必须零对象载荷、零变更代次；不能折叠为入口拒绝、资源失败或截断成功。其它服务只有在各自后继设计明确接入数量预算时才使用该状态，本叶不改变其行为。

### 3.2 状态来源读取请求

物理所有者：`海中鱼巣/领域/L2状态结构.数据.h`。

```cpp
struct L2按来源当前状态读取请求 final {
    L2结构请求头 请求头;
    稳定编码 来源稳定编码;
    std::uint64_t 最大数量 = 0;
    friend bool operator==(const L2按来源当前状态读取请求&,
        const L2按来源当前状态读取请求&) = default;
};

inline bool L2按来源当前状态读取请求有效(
    const L2按来源当前状态读取请求& 请求) noexcept;
```

有效条件逐字冻结为：请求头合同有效、`期望事实代次 != 0`、来源稳定编码非零、最大数量非零。`最大数量` 以最终状态对象数计数，不以 L1 值事实数计数。

结果复用现有 `L2当前状态组读取结果`，不建立同义结果 DTO。成功形状保持：`已读取`、非零事实截止、零变更代次、状态组按身份严格升序、全部状态当前且完整。空组是成功。

## 4. 原子读取过程

1. 纯值请求无效时返回 `入口拒绝`、截止 0、空组。
2. 读取当前状态结构类型登记；登记非成功按现行映射返回，空组。
3. 形成 `L1所有者范围来源当前值组读取请求`：owner 固定为状态服务私有 owner，来源与守卫逐字段取自请求。L1 数量预算按一个完整当前状态恰有一个精确值和一个时间值，做饱和 `2 * (最大数量 + 1)` 换算；多取至多一个完整状态只为区分“恰好超出公共预算”与坏角色配对，不得溢出、截断或把公共预算改成值数量。
4. 调用 `L1事实基座服务::按来源读取所有者范围全部当前值`。必须逐字段互证合同版本、owner、来源、期望 / 读取事实代次和非成功零载荷。
5. L1 成功后，每项值必须属于状态 owner、来源等于请求来源、当前生命周期完整、所属节点非零，且属性类型恰属于登记中的四种精确值类型或四种时间值类型。任何其它同 owner 值、重复角色、同节点缺少精确 / 时间任一角色或一个角色多值均为 `内部不一致`。
6. 按所属状态节点去重并按稳定编码升序。候选数不得超过 `最大数量 + 1`；L1 已因更大原始集合返回预算不足时直接形成零载荷预算拒绝。
7. 对至多 `最大数量 + 1` 个候选以原非零守卫调用 `读取完整状态`。每项必须 `已读取`、截止等于 L1 截止、状态身份等于候选、来源等于请求、当前未退出，并通过 `L2状态事实完整`。任一项失败时整组为空：明确漂移 / 资源失败沿用；坏成功形状和其它结构矛盾映射内部不一致。只有候选均为完整同来源状态后，候选数超过公共 `最大数量` 才返回 `数量预算不足`，避免用预算拒绝掩盖已取得候选中的坏结构。
8. 数量不超预算且全部成功后返回 `已读取`、截止等于请求守卫、零变更代次和严格升序完整组。读取过程不推进事实代次。

每次 L1 调用和完整状态读回都使用同一非零守卫。并发发布导致任一步不再处于该截止时返回事实代次漂移；禁止重试、拼接不同截止或返回部分组。

## 5. 状态映射

| L1 / L2 条件 | L2 结果状态 | 截止 | 状态组 |
| --- | --- | --- | --- |
| 坏合同、零守卫、零来源、零预算 | 入口拒绝 | 0 | 空 |
| 来源未找到 | 未找到 | L1 安全截止 | 空 |
| 来源已退出 | 已退出 | L1 安全截止 | 空 |
| 守卫漂移 | 事实代次漂移 | L1 当前截止 | 空 |
| L1 值预算或 L2 状态预算不足 | 数量预算不足 | L1 安全截止 | 空 |
| 分配 / 长度耗尽 | 资源失败 | 安全取得则保留，否则 0 | 空 |
| owner、角色配对、完整读回或同截止互证失败 | 内部不一致 | 安全取得则保留，否则 0 | 空 |
| 当前来源无状态 | 已读取 | 等于守卫 | 空 |
| 当前来源有 1—预算项状态 | 已读取 | 等于守卫 | 严格升序完整组 |

所有非成功结果的 `变更事实代次` 为空，状态组为空。`数量预算不足` 不表示资源耗尽，也不绑定幂等身份；读取接口没有幂等写语义。
