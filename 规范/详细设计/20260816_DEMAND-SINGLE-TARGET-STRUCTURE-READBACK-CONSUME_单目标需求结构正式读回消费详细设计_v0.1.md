# DEMAND-SINGLE-TARGET-STRUCTURE-READBACK-CONSUME 单目标需求结构正式读回消费详细设计 v0.1

日期：2026-08-16
版本：v0.1

## 1. 目标、范围与完成边界

以 BIZ-L4-004-02-01-06 v0.2 替代旧 v0.1，并把父 BIZ-L3-004-02-01 增量更新为 v0.4。新06只负责：

```text
接收05已发布 / 精确重复返回的非零需求身份和原写后事实代次G1
-> 经既有运行期事实版本服务取得调用时当前读取守卫G读
-> 以G读守卫、G1历史截止恰一次调用DATA-EXT-12完整需求历史读取
-> 互证一个需求在G1下的目标、来源、授权、可空父、全部路径、生命周期和版本
-> 返回独立值式完整投影供父函数与05首次请求见证逐字段互证
```

06不接收或读取BIZ私有发布见证，不读取L1幂等账，不直达owner、仓库、SQL或内部写集，不分次拼装需求节点、目标、父关系、来源和路径。05写结果不能代替06正式读回；06读回也不能代替父函数对“首次规范化请求见证 vs 权威结构投影”的业务互证。

本设计只冻结BIZ消费合同和所需基础数据公开接口语义。DATA-EXT-12最终服务 / DTO / ABI尚未发布，运行期事实版本服务和05 BIZ代码也未形成正式结果，因此计划只能登记`待激活`。本设计不证明真实需求读回、需求提交整体、任务化或系统闭环。

## 2. 正式依据、当前事实与具名漂移

- 0050、4030、4050：BIZ只经公开强类型DATA服务消费不可变值式投影；成功写入后必须独立权威读回，半结构或读回矛盾属于内部不一致。
- 4015、4230的现行历史读取模式分离调用时当前守卫与历史截止：请求头使用非零当前守卫，历史截止不得晚于守卫，DATA在读取前后互证当前守卫未漂移。
- 3100、5100：一个需求只有一个主体、目标宿主、目标特征和目标状态合同；来源和路径不改变目标语义。
- 5110：同一需求可以保留多个来源和多条互异当前路径；父空时无父路径，父非空时路径角色和当前性必须显式存在。
- 3100、5110：需求结构还必须显式承载当前状态材料、满足关系，以及路径当前性、权重、AND份额 / 余量版本和预算来源；这些字段不能在读回时按默认值补造。
- 5150：内部读回矛盾进入开发诊断，不伪装普通入树拒绝；06本身零治理回执写入。
- 05 v0.2固定已发布 / 精确重复都返回非零需求身份、完整首次规范化请求见证、首次幂等身份、首次G0和原G1，并必须进入06。
- 当前正式代码只有公共`L2需求身份`和`L2节点族::需求`；不存在`L2需求结构服务`、需求DTO、普通应用取得路径、`服务.需求.ixx`或本叶函数。

旧 v0.1 同时存在四类失效方向：

```text
DRIFT-DEMAND-06-PRIVATE-WITNESS-OWNER-READBACK
DRIFT-DEMAND-06-SINGLE-PATH-SHAPE
DRIFT-DEMAND-06-CUTOFF-WITNESS-DUPLICATION
DRIFT-DATA-EXT-12-SINGLE-DEMAND-HISTORICAL-FULL-READ-ABI-MISSING
```

旧图把原幂等身份 / BIZ发布见证传入06，再分次读取目标、父、来源、路径和幂等账；它还把路径冻结为单数，并把G1直接当当前守卫。这些做法分别违反现行DATA边界、多路径结构和历史读取一致性。

## 3. G读与G1必须分账

`G1`是05首次成功写入形成的原写后事实代次，也是06要证明的历史结构截止；`G读`是06调用时新取得的当前全局事实守卫。二者不是同一字段：

```text
G1 = 原发布事务的历史截止；精确重复必须返回原G1
G读 = 本次06读取开始前取得的当前事实代次；必须非零且G读 >= G1
```

若精确重复发生在后续事实已经发布之后，`G1 < G读`是正常情况。把原G1直接放入单对象当前读取请求头会固定漂移，无法读回旧精确重复的原结果。因此06统一使用历史读：先调用既有`运行期事实版本服务::读取当前已发布共享事实截止(...)`取得G读，再请求DATA-EXT-12以`期望事实代次=G读`、`历史截止事实代次=G1`读取。

若在取得G读后又发生发布，DATA返回事实代次漂移；06返回当前性漂移、零业务载荷、零自动重试。后继可以用同一需求身份和原G1重新发起完整06调用，但不得改写G1或把当前结构冒充原发布结构。

预冻结合同：

```cpp
inline constexpr std::uint32_t 单目标需求完整读回合同版本 = 1;
inline constexpr std::uint32_t 单目标需求完整读回规则版本 = 1;

struct 单目标需求完整读回请求 final {
    std::uint32_t 合同版本 = 单目标需求完整读回合同版本;
    std::uint32_t 规则版本 = 单目标需求完整读回规则版本;
    std::uint64_t 运行代次 = 0;
    std::uint32_t 事实范围版本 = 0;
    L2需求身份 需求;
    std::uint64_t 发布事实代次 = 0; // 原G1
    std::size_t 来源授权总数量预算 = 0;
    std::size_t 当前路径关系总数量预算 = 0;
};

enum class 单目标需求完整读回状态 : std::uint8_t {
    已读取 = 1,
    请求拒绝 = 2,
    不存在 = 3,
    已退出 = 4,
    当前性漂移 = 5,

    提供者拒绝 = 7,

struct 单目标需求完整读回材料 final {
    std::uint64_t 读取守卫事实代次 = 0; // G读
    std::uint64_t 发布事实代次 = 0;     // G1
    当前单目标需求值式事实 完整需求;   // 复用02最终共享类型
};

struct 单目标需求完整读回结果 final {
    单目标需求完整读回状态 状态 =
        单目标需求完整读回状态::请求拒绝;
    std::uint32_t 合同版本 = 单目标需求完整读回合同版本;
    单目标需求完整读回请求 请求回显;
    std::optional<单目标需求完整读回材料> 读回材料;

单目标需求完整读回结果 需求业务服务::完整读回需求目标来源与路径(
    const 单目标需求完整读回请求& 请求) const noexcept;
```

`当前单目标需求值式事实`复用02最终代码结果；其中“当前”精确表示在结果截止G1下仍有效，不表示进程调用时最新。06不得复制一份字段相同但身份不同的完整需求DTO。若02最终名称机械变化，06只机械匹配同一共享值式类型。

同一`需求业务服务`必须借入同实例唯一`const L2需求结构服务&`、既有`const 运行期事实版本服务&`和两者所需不可变固定配置；构造不读取事实、不缓存截止。最终构造签名必须在02/05结果和DATA正式ABI发布后一次机械合并，不得建立第二需求服务或第二截止provider。

只有`已读取`携带材料，且`G读 >= G1 > 0`、完整需求全部事实截止为G1。其它状态optional为空；BIZ非成功不暴露可误用的部分投影或DATA内部结果对象。

## 5. 基础数据公开接口最终需求

### 5.1 读取守卫来源

复用既有BIZ `运行期事实版本服务::读取当前已发布共享事实截止(...)`。它经同一普通应用`L2结构聚合服务`的存在服务读取一个非零当前全局事实代次。06不新增DATA当前代次入口，也不直接调用L1。

### 5.2 DATA-EXT-12唯一完整历史读

DATA-EXT-12必须提供一个具名公开操作，语义名为：

```text
按需求身份与历史截止读取完整单目标需求结构
```

请求至少承载：

| 分组 | 必需语义 |
| --- | --- |
| 一致性 | 公共L2请求头，非零`期望事实代次=G读`；读取类别=历史；非零`历史截止事实代次=G1`且`G1<=G读` |
| 定位 | 一个非零`L2需求身份`；事实范围、需求范围、需求树、目标、父关系、来源授权、路径、生命周期和读取规则版本 |
| 预算 | 非零来源与授权总数量预算、非零当前路径关系总数量预算 |

成功必须是`已读取 + optional有值`，结果头截止、历史截止和每项事实截止都等于G1，变更事实代次为空。DATA在G读前后守卫一致的情况下，一次形成G1完整投影；不得分次让BIZ拼装，不得混入晚于G1的新增、替换或退出事实。

请求和结果不得携带BIZ“来源已准入”“路径合法”“需求合理”“目标已满足”等布尔或见证。DATA也不得开放L1幂等账读取、owner选择、内部写集、事务、撤销或缓存定位。精确C++模块、类型名、字段顺序和状态数值由DATA计划最终发布后机械匹配；本设计不把待实现语义冒充当前ABI。

### 5.3 完整G1投影

一个成功项至少完整携带：

```text
需求身份与需求族身份来源
需求主体、提出主体
目标宿主、可空目标场景、目标特征定义、独立目标状态合同身份
当前状态材料关系及其来源 / 时间 / 版本、目标满足关系
用于同父同目标唯一性的完整目标状态语义键
可空唯一父需求及父关系完整事实
全部G1下当前来源事实和当前授权 / 具名内在规则事实
全部G1下当前路径关系 {
  路径关系身份与身份来源,
  父需求与子需求端点,
  路径组身份、路径角色、顺序,
  路径权重、AND份额、余量规则版本、预算来源,
  当前性、活动版本、生命周期与结构版本
}
需求生命周期、全部结构版本、每项事实截止G1
```

来源 / 授权按正式强类型稳定键排序；路径至少按路径组身份、角色、顺序、关系身份稳定排序。零来源、重复来源、来源与授权错绑定、当前状态材料或满足关系缺失 / 复义、路径权重或AND份额 / 余量版本 / 预算来源缺失、重复路径、错端点、混代、截断、父空但路径非空、父非空但路径空、生命周期在G1不可见或任一预算回显不一致，均不是合法完整成功形状。

DATA完整读不需要返回BIZ私有发布见证，也不需要新增公开幂等账读取。父函数保留05结果中的完整首次规范化请求见证，并把它与06权威结构逐字段互证；结构事实自身的创建 / 替换 / 退出代次必须证明G1对应的建立或补充变化。

## 6. 固定控制流与状态映射

```text
校验合同、运行代次、范围版本、需求、G1、规则版本和两个预算
-> 调用运行期事实版本服务取得G读
-> 互证运行代次 / 范围版本且G读非零、G读>=G1
-> 构造一次DATA-EXT-12完整历史读取请求
-> 恰一次调用需求结构服务
-> 互证请求回显、历史类别、G读守卫、G1截止、版本、预算和optional
-> 互证需求身份、目标唯一、来源 / 授权完整、父与全部路径、生命周期和稳定排序
-> 一次值式复制共享完整需求事实
-> 返回已读取
```

状态映射固定为：

| 下层条件 | BIZ状态 | 结果守恒 |
| --- | --- | --- |
| 请求坏、零G1 / 身份 / 预算、版本不匹配 | 请求拒绝 | 零下层调用，optional空 |
| 当前截止provider资源失败 | 资源失败 | optional空 |
| 当前截止provider其它非成功或坏形状 | 内部不一致 | optional空 |
| DATA未找到 / 已退出 | 不存在 / 已退出 | optional空；父级05成功后必须升级内部不一致 |
| DATA事实代次漂移 | 当前性漂移 | optional空；零自动重试 |
| DATA数量预算不足 | 数量预算不足 | optional空、不截断 |
| DATA未实现 | 未实现 | optional空 |
| DATA许可拒绝 | 提供者拒绝 | optional空 |
| DATA入口拒绝 / 引用冲突 / 坏成功形状 / 未知状态 | 内部不一致 | optional空 |
| DATA已读取且完整 | 已读取 | 一次构造G读、G1和完整需求 |

`std::bad_alloc`、`std::length_error`映射资源失败，其它异常映射内部不一致。06零写、零锁、零等待、零重试、零缓存、零截止重选、零历史补缺和零日志裁决。

## 7. 父函数05—06互证

父 BIZ-L3 v0.4 在05返回已发布或精确重复后，必须把05发布材料完整保留到06成功。06请求不携带该见证；父函数在06返回后独立比较：

1. 05需求身份等于06需求身份，05原G1等于06历史截止G1；
2. 首次发布要求`G0 < UINT64_MAX`且`G1 == G0 + 1`；精确重复必须回显并沿用原G0 / G1，零代次推进；
3. 05首次规范化请求中的主体、提出者、目标、可空场景、当前状态材料、满足关系、父需求、来源 / 授权、路径权重 / 分配 / 预算、生命周期和版本，与06 G1完整投影逐字段一致；
4. 建立模式在G1形成完整新需求；补充模式保留既有不可变核心和旧结构，并完整出现本次新增 / 换代来源或路径；
5. 06的全部来源 / 授权 / 路径没有缺项、额外项、重复、混代或错端点；
6. 精确重复仍读取原G1投影，不改用调用时当前结构。

任一矛盾固定返回父级内部不一致并进入5150开发诊断边界，不形成普通拒绝回执。发布结果未知仍不调用06；只有05最终收敛为已发布 / 精确重复并取得原G1后才进入本叶。

## 8. 验证矩阵

1. 零需求、零G1、坏合同 / 规则 / 运行 / 范围版本、两个预算任一为零均在下层调用前请求拒绝；
2. G读=G1与G读>G1两种历史读均成功；G读<G1、零G读和当前provider坏形状内部不一致；
3. G读取得后发生并发发布，DATA漂移映射当前性漂移，零重试、零改G1；
4. DATA请求精确携带G读守卫、G1历史截止、需求、全部版本和两个预算，每次恰一调用；
5. 已读取完整互证目标、父、全部来源 / 授权 / 路径、生命周期、稳定排序和每项G1；空父 / 路径基数矩阵精确分账；
6. DATA未找到、已退出、预算、许可、未实现、漂移、资源和坏成功形状逐项唯一映射，全部非成功optional空；
7. 05首次请求见证不进入06 DATA请求；父图先验证首次发布`G1=G0+1`、精确重复沿用原G0/G1，再对建立、补充和精确重复逐字段互证，任何半结构内部不一致；
8. 源码静态证明零L1 / owner / 私有幂等账 / DATA写 / SQL / 缓存 / retry / 5150写，复用唯一运行期截止provider和唯一需求结构服务；
9. 根工程Debug / Release、生产外专项双配置、strict、diff、UTF-8、工程唯一登记和临时专项清理后复验通过。

专项可以替代待实现DATA provider验证BIZ纯逻辑、G读/G1和状态映射，但不能宣称真实DATA历史读、并发漂移、05—06生产接线或业务闭环。未真实运行的分支保持`NOT_RUN`。
