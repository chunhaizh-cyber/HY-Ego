# INSTINCT-STAGE3-ACTIVE-SAFETY-WINDOW-ADJUDICATION 主动安全 UTC 窗口裁决详细设计 v0.1

日期：2026-08-30

设计身份：`INSTINCT-STAGE3-ACTIVE-SAFETY-WINDOW-ADJUDICATION`

## 1. 目标与边界

在现有 `海中鱼巣.领域.组合.本能被动维护基础快照` 模块内增加一个只读组合器。调用方显式给出正的半开 UTC 窗口 `[起始,结束)`；组合器在同一非零 `G0` 下重新读取本能被动维护基础快照、安全根定义绑定的主动安全来源规则和安全根特征永久变化账完整组，形成当前生产规则版本 1 下可证明的窗口裁决。

当前生产规则版本 1 的完整来源方法集合显式为空。因此本版只有一项业务成功形状：永久变化账完整组也显式为空，返回“窗口内未发生主动安全结算变化”。任何非空变化组均返回来源未裁定，不能把未知来源解释为被动变化或非主动变化。

本叶不选择 UTC 窗口，不把单调完整秒换算为 UTC，不调用单秒规则内核，不裁决低位回升门禁，不推进维护游标，不写安全值 / 服务值 / 状态 / 动态。值域 `0..INT64_MAX`、`L=2,767,011,611,056,432,742`、`H=7,378,697,629,483,820,645` 和安全根定义版本 1 均保持不变；未来调整只能发布新定义版本。

## 2. 正式依据与当前事实

- 4230 v0.19 已提供 `按特征实例与UTC范围读取完整变化组_v2`，合法空组必须有账登记、全量扫描、完整见证和 G0 双守卫。
- 6100 v0.6 冻结主动安全来源方法版本化完整集合；规则 1 显式为空，非空变化组必须材料不足。
- 6170 v0.7 要求低位回升前先消费永久变化账和正式来源规则，禁止用动态扫描为空、最后动态、日志或缓存证明“本秒无主动安全变化”。
- 当前安全根 owner 已发布并正式读回定义版本 1 与来源规则版本 1；永久变化账 provider 已发布。
- 当前 `本能被动维护基础快照组合器` 已在同一 G0 读取本能根锚点、安全根定义 / 当前值、服务值、维护游标和完整秒材料；当前没有等价的主动安全窗口裁决入口。
- UTC 永久账窗口与单调维护秒的生产绑定尚未形成；本叶把窗口作为显式强类型读取键，绝不从完整秒、墙钟当前值、线程循环或日志补造。

组合器借用：

```cpp
const 本能被动维护基础快照组合器&
```

## 4. 公开 DTO

合同版本为 1。

```cpp
struct 本能主动安全UTC窗口裁决读取请求_v1 final {
    std::uint32_t 合同版本;
    本能被动维护基础快照读取请求_v1 基础快照请求;
    std::int64_t 包含起始UTC纳秒;
    std::int64_t 排除结束UTC纳秒;
    std::uint64_t 数量预算;
};
```

入口有效性：合同版本正确；基础快照请求完整；`0 < 起始 < 结束 <= INT64_MAX`；数量预算非零。窗口由调用方显式提供，只是读取键，不证明它已经与某个单调完整秒绑定。

```cpp
enum class 本能主动安全UTC窗口裁决_v1 : std::uint8_t {
    未改变A = 1,
    已改变A = 2
};
```

版本 1 的成功结果只允许 `未改变A`；保留 `已改变A` 枚举是单秒规则内核的强类型投影，不授权本合同在空生产规则下形成该值。

```cpp
struct 本能主动安全UTC窗口裁决快照_v1 final {
    本能被动维护基础快照_v1 基础快照;
    主动安全结算来源规则事实_v1 来源规则;
    L2特征当前值变化组读取结果_v2 永久变化账完整组;
    std::int64_t 包含起始UTC纳秒;
    std::int64_t 排除结束UTC纳秒;
    本能主动安全UTC窗口裁决_v1 裁决;
    std::uint64_t 本次正式读回截止;
};
```

完整谓词必须逐项证明：

1. 基础快照完整且 G0 非零；
2. 来源规则完整，规则版本等于基础快照中安全根定义冻结的主动安全结算规则版本；
3. 当前仅接受规则版本 1、空来源方法组；
4. 永久变化账结果成功，特征实例等于安全根特征实例，窗口和 G0 与请求逐字段相同；
5. 完整变化组为空、见证声明数为 0、身份组为空；
6. 裁决恰为 `未改变A`；
7. 三份正式读回截止均等于同一 G0。

读取状态：

```text
已读取
入口拒绝
定义未发布
当前值未设置
游标未建立
规则未发布
规则版本漂移
账未登记
当前性漂移
运行代次漂移
时间纪元漂移
时间源版本漂移
时间倒退
数量预算不足
集合不闭合
来源未裁定
引用冲突
材料不闭合
资源失败
内部错误
```

结果字段固定为：合同版本、状态、`optional<快照>`、本次正式读回截止。只有 `已读取 + 完整快照 + 截止=G0` 成功；其它状态全部快照空、截止 0。

## 5. 目标函数

```cpp
class 本能主动安全UTC窗口裁决组合器 final {
public:
    本能主动安全UTC窗口裁决组合器(
        const 本能被动维护基础快照组合器& 基础快照组合器,
        const 安全根定义与当前值服务& 安全根服务,
        const L2状态动态原子发布服务& 状态动态服务) noexcept;

    本能主动安全UTC窗口裁决读取结果_v1
    读取UTC窗口主动安全变化裁决_v1(
        const 本能主动安全UTC窗口裁决读取请求_v1& 请求) const noexcept;
};
```

固定过程：

```text
请求准入
-> 第一次读取基础快照，取得 G0 与安全根特征实例
-> 以同 G0 读取当前主动安全结算来源规则
-> 互证定义冻结规则版本与规则事实版本
-> 以同 G0、安全根特征实例和原窗口读取永久变化账完整组
-> 规则 1 且账组非空：来源未裁定
-> 规则 1 且账组空：形成未改变A候选
-> 第二次读取基础快照
-> 稳定权威字段逐项等于第一次快照
-> 完整谓词通过后返回已读取
```

基础快照读取状态按同名或最近语义映射。来源规则的未发布单独映射；规则版本不等于定义冻结版本映射规则版本漂移。永久账 `账未登记 / 数量预算不足 / 集合不闭合 / 当前性漂移 / 引用冲突 / 资源失败` 保持结构化分账，其它坏形状映射内部错误。异常中 `bad_alloc / length_error` 为资源失败，其它异常为内部错误。

## 6. 验证矩阵

- DTO：坏合同、坏基础请求、零 / 反向 / 溢出窗口、零预算；
- provider：定义或规则未发布、规则与定义版本错配、账未登记；
- 合法空集：规则 1 显式空 + 账完整空组，返回已读取 / 未改变A；
- 非空组：无论来源方法为空或非空，规则 1 均返回来源未裁定、空载荷；
- 完整性：窗口、特征实例、声明数、身份组、G0 任一错配不成功；
- 漂移：第一次 / 第二次基础快照之间推进事实或完整秒，返回当前性漂移；
- 下层状态：数量预算不足、集合不闭合、引用冲突、资源失败、内部错误映射；
- 不变量：A/V/L/H、定义版本 1、来源规则版本 1 和现有 ABI 不变；
- Debug / Release 根工程、现有专项扩展、仓库外 ABI consumer、strict 与精确差异检查。

## 7. 完成声明

本设计完成最多证明“调用方给出显式 UTC 窗口时，规则版本 1 的显式空来源集合可以与永久账合法空组在同一 G0 组合成未改变 A 的强类型裁决；非空变化组 fail-closed”。它不证明 UTC 窗口属于某个单调维护秒，不证明低位回升允许，不证明主动安全结算方法、被动维护事务或阶段三完成。
