# WORLD-TREE-P1A3F 世界结构合同骨架详细设计 v0.2

日期：2026-08-03

设计身份：WORLD-TREE-P1A3F

## 1. 修订范围与唯一现行身份

本文件以不可变 v0.1 详细设计 blob `e208c2bbb5ecfbc1ba06ad784eca0fa5136e7a24` 为基础，只替换 v0.1 §3.4 中 `节点直接世界引导服务` 的构造与依赖注入合同，并同步修正模块拓扑和骨架验证合同。v0.1 中其余 DTO、稳定枚举值、六个其它公开函数签名、七骨架安全 `未实现` 行为、顺序 180 及 19 项自检计数继续有效。

冲突时唯一顺序为：本 v0.2 → v0.1 未被替换段落 → 4201 v0.1 → 4200 v0.8。执行者不得在三依赖和四依赖构造之间二选一，不得保留旧构造重载。

## 2. 问题与能力裁决

P1A3 恢复成功分支必须以两个精确索引键调用 P1A2Q 的
`节点直接结构查询服务::读取当前索引(const 索引物理键&) const`。v0.1 的引导服务仅保存恢复、提交和世界结构三个引用，无法在不建立转发壳、不扩张世界结构服务职责的前提下消费该 L1 精确查询。

裁决为扩展现有引导服务构造依赖，不建立第二入口、不让 `节点直接世界结构读取服务` 转发物理索引读取，不修改 P1A2/P1A2Q 公开合同。

## 3. 最终构造、所有权与物理位置

唯一物理位置仍为 `海中鱼巣/领域/服务.节点直接世界引导.ixx`。模块必须显式 import `海中鱼巣.核心.服务.节点直接结构`。

```cpp
class 节点直接世界引导服务 final {
public:
    节点直接世界引导服务(
        节点直接结构恢复服务& 恢复,
        节点直接类型化结构提交服务& 提交,
        节点直接结构查询服务& 结构,
        节点直接世界结构读取服务& 世界结构)
        : 恢复_(恢复),
          提交_(提交),
          结构_(结构),
          世界结构_(世界结构) {}

    节点直接世界引导结果 确保现实世界已引导(
        const 节点直接世界引导请求& 请求) const;

private:
    节点直接结构恢复服务& 恢复_;
    节点直接类型化结构提交服务& 提交_;
    节点直接结构查询服务& 结构_;
    节点直接世界结构读取服务& 世界结构_;
};
```

参数顺序、成员声明顺序和初始化顺序必须与上述合同完全一致。四个引用对象均由装配宿主拥有并长于服务；禁止默认构造、setter、空指针、运行期替换或跨调用保存请求引用。

`结构` 必须与构造 `世界结构` 时传入的 `节点直接结构查询服务` 为同一对象，使两个服务消费同一事务域和六仓。自检和未来生产装配都必须显式传入该同一对象；不得在引导服务内重建查询服务。

## 4. 骨架行为不变合同

P1A3F 代码结果中 `确保现实世界已引导` 仍只构造并返回 `未实现`、零代次、空读回；禁止调用 `恢复_`、`提交_`、`结构_` 或 `世界结构_`。新增引用只冻结后继 P1A3 原位替换的最终构造合同，不是真实能力。

其余六骨架函数与 v0.1 §4 不变。所有骨架调用前后，事务域代次、六仓权威材料、幂等账和持久侧账必须逐值相等。

## 5. 工程、自检与验收补充

1. 不新建模块或公开类型；工程登记仍沿用 v0.1 的四服务、共享头和骨架自检。
2. 引导模块拓扑更正为依赖 P1A2 恢复、提交、查询服务与 P1A3F 世界结构读取服务。
3. 静态构造验证必须证明四参数构造成立，原二参数和三参数构造均不成立。
4. 骨架自检使用同一真实 `节点直接结构查询服务` 先构造世界结构读取服务，再与恢复、提交、该查询对象共同构造引导服务。
5. 静态调用边检查允许 import 和引用成员声明，但 `确保现实世界已引导` 函数体对四个下层成员的调用边必须为零。
6. `WORLD-TREE-P1A3F-S01` 仍为唯一自检身份和顺序 180；成功后自检总数仍为 19。

验证命令、安全未实现矩阵和完成声明边界继续使用 v0.1 §6—§8。完成 v0.2 仍最多证明合同骨架编译接入和入口巡检，不证明精确索引读取、世界引导或任何真实世界行为。
