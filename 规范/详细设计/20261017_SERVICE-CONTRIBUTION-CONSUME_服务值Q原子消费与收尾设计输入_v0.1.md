## 1. 修改对象与边界

最终服务值是唯一self的内部治理特征；本次把真实服务的正式Q一次计入该特征，并交付真实状态/动态及来源T的9→12收尾。子T→父T贡献交接、服务值增值、来源T已结算是三个不同事实，不能合成一个伪动作。

本窗口最新具名裁决替代本切片的上界业务设计：业务不考虑服务值达到上限，不新增上限需求、上限任务或上界零增量分支；本次按`Δ=Q，after=before+Q`计入，不截断Q。整数相加必须先检查I64溢出，溢出属于工程中断，动作前记录诊断并停止，不伪装为正常业务结果或条件结果知识。6190原上界截断条款仅作待清理冲突定位，本稿不修改正式规范。

来源完成结算是幂等键，不能用T、父累计小计、调用次数或日志当消费键。治理子结算Q=0继续按首叶贡献合同保存，但不能借其构造新的上界处理或“成功增值”分支；最终来源资格与是否有服务贡献仍按人类服务合同判断。

当前L1只证明存活数据集上的原子内存表交换，不具备磁盘恢复合同。本后继最多证明同一数据集存活期间的核心防重、已完整阶段读回以及尚未开始阶段的安全继续；不得声称任意半写阶段恢复、进程崩溃后恢复或持久金融账安全。聚合/概念阶段中途出现无法安全继续的资源故障或结构矛盾，按工程日志、弹窗及终止进程处理，不包装为业务等待，不为它新建通用修复平台。

## 2. 已核实缺口

- `新_特征类::添加特征值`分步写历史命中、current、standard、旧直接历史转换、归组、历史聚合域及所属概念。不能先调用它再写来源消费。
- 特征完整读取校验current属于历史、历史无重复、标准值匹配最高命中；仅current与消费原子交换仍会暴露非法特征。
- L1原子追加现已支持新节点、字段追加、替换及旧直接历史字段删除。经root复核，本后继feature提供者必须支持当前合法I64历史结构，不能把本次服务值递增推为特征永远无历史重访；命中旧直接历史时需要新命中节点与删除旧字段同次发布。已发布字段删除提供者不主动迁移或删除任何历史事实，只提供上层合法调用所需的组合能力。复杂概念归组还涉及旧域节点删除、概念父边调整，不宜伪装成一项字段替换。
- 当前没有“不增加命中而只完成聚合/概念”的特征owner入口，不能重调添加特征值实现恢复。
- 状态owner只能从当时current建立状态；无法在后续服务值已变化后从消费回执补造旧后状态。因此本来源全部收尾前，必须阻止服务值下一写入。
- 运行服务初始化仍从旧C/R反推冻结前值，首子D和预测均固定为前值+1。6190§2/§5明确根目标为INT64_MAX；现代码方向增加校验与之不符。用户排除上限运行结果，不等于撤销根目标表示；方向增加仍可作为方法效果，二者不得混同。
- self仅在结算T准备完成时确认效果，且结算X未导致T完成便工程停止；这阻断长期结算任务分多次消费来源。

## 4. 拟冻结的提供者合同

### 4.1 特征核心材料

拟公开只读、不可由业务构造的`新特征I64联合更新准备`，由feature owner唯一创建；其中包含F身份、old/new I64、严格完整快照及已检查的核心变化片段。调用方只能读取定位/数值，不能自行改片段后重投。

```cpp
新特征I64准备结果 准备I64联合更新(
    稳定编码 特征节点, std::int64_t 预期当前值,
    std::int64_t 新当前值, 稳定编码 处理来源节点) noexcept;
新特征I64收尾结果 完成I64联合更新聚合(
    稳定编码 特征节点, 稳定编码 处理来源节点) noexcept;
```

准备时零特征事实写入；命中记录首次1、旧直接历史转换按现有规则2、既有命中按现有饱和规则，standard仅在严格超过旧最高命中时改。核心必须包含current、命中/历史、standard及确实需要的旧直接历史字段删除，所有读回不变量在原子交换后立即成立。本稿不新建零增量执行分支，不通过无变化重写F增加命中，也不伪造特征变化。

`处理来源节点`只是具名本次处理定位，不是底座owner或许可。收尾必须核验本来源已联合发布，使用owner保留的本次只读准备材料执行原归组/聚合/所属概念算法，绝不再递增命中。不能重跑全历史连接分量归组：1130禁止新值自动合并已有区间。owner在单次受保护执行期间区分未开始、正在执行及完整读回；只有尚未开始阶段可执行、已经完成且完整读回阶段可复用，正在执行不允许第二调用并发重入。阶段中途失败且无法由现有事实无歧义证明安全继续时进入工程终止链，不假报幂等可恢复，不将临时阶段当作业务事实或持久恢复账。

合法旧直接历史命中转为命中记录仍是本次核心原子转换。为使原归组算法看到完整历史，本次目标F剩余合法旧直接历史一并等价规范化：本次命中项为2，未命中项仍为1；既有命中记录不因规范化增加次数。它们与本次current/standard/消费在同一次发布，逐值读回须保持历史集合和解释不变；不触及其它F，不合并已有区间，不全仓迁移。已归组子特征的成员引用必须保持原归属：若闭包中存在旧直接成员，按其现有准确值/正式归属映射到同一父历史记录，不重新推断分组；合法闭包不能被拒为业务结果，矛盾或多义归属进入工程保障。该局部兼容必须写入实际feature实施合同，不得只规范化父F后声称子成员均已完整。

### 4.2 联合消费

消费记录owner接受运行服务已核验的正式来源、动作、feature准备材料；它自行重读来源及全部防重引用，私下形成自身片段，交给feature的正式提交入口作为附加片段。feature不解包消费写集，只拼入自己的私有片段后调用§4.5的L1中立组合入口一次发布；自身片段不导出，取消后不能遗留延迟提交路径。对同一F/source只存在一个记录；通过source完成结算反向引用定位，不能扫描最近动作。

记录至少固定：source完成结算、sourceT、直接接收父T、对应结算X、self/F、普通动作、Q、Δ、before/after、动作前S可选、后S/结果D可选及明确收尾阶段。before/after仅是本次操作证据，current权威仍是F。

消费核心同次写入source→消费记录、记录完整核心字段以及feature值变化；若相同来源已存在则返回原回执，先核验后继续未完收尾，不重新计算Δ、不再次加值。新来源必须等待前一来源收尾完成。字段幂等/重放与源引用校验由该owner负责，运行服务不得直接写记录基础字段。

### 4.3 服务值通道冻结

仅在运行服务加mutex不足以防止其它正式feature/world入口修改同一F。冻结由feature owner签发的不可构造、不可复制会话凭据承载工程所有权；正常一次编排固定在同一工作线程、同一调用作用域中，凭据只能由该线程用于本F/source。owner以私有F→凭据占用保护目标F及本次参与归组闭包，既有递归互斥仅在各feature函数内部短持，不跨task/world调用持续持锁。其它对已占用F的写入走工程并发控制、零写拒绝；读取仍可用。删除必须在第一次实际删除前完整预检整个递归删除子树，任何节点被占用则整次零删除，不允许删一半才遇占用。普通feature不新增服务消费业务状态。会话不开放锁对象、可变写集、事务或callback；不得跨worker挂起或交异步队列，不探测或代写其它owner字段。

冻结从动作之前建立作用域会话，联合发布后延续至聚合、后状态、变化动态、动作关联及消费回执完整收尾。动作来源以source完成结算为键，复用`新_动态类::按来源查询动作`，不靠时间找最近动作。尚未建立动作或核心零发布时可正常释放；已开始动作只保留事实，不撤销已发生动作。核心发布后仅正常完成调用允许释放；无法证明安全继续的非成功部分按工程终止处理，不依赖跨调用恢复半成品。已有完整消费的重复请求只读回，不能重跑原算法。

feature核验自己签发的会话身份、F/source、精确核心发布回执以及自己的聚合完整读回后结束feature阶段，不反向读消费owner，也不理解T/S/D。运行服务负责在正式状态/动态及消费记录完整读回后结束整个作用域；不以传入`收尾成功=true`代替编排步骤。feature凭据的析构与失败处理不得静默把核心已发布但编排中断变成正常可重试释放。具体会话析构/结束函数及锁序仍须在代码计划中冻结；本段不授权跨owner反向friend。

### 4.4 已提交值的状态/动态

新world入口只消费正式消费回执和当前F；核验F仍等于after且通道仍由该source冻结，再调用existence/state正式能力获得后S，沿既有场景组织和动态发布链形成结果。前S取动作前正式状态；不能由before值凭空新建历史S。

后状态强时间在动作之后固定一次，按source固定时间和F精确查找，不能每次产生新S。无前S而确有变化时允许保存新S而无动态，服从6190，不把动态缺失一概报失败。不为已排除的上界情形新增变化S/D。完成关联后才解除通道；核心后无法安全继续的部分失败保留来源、动作与已提交内存事实并工程终止，不宣称可以任意重入收尾。

### 4.5 跨owner封存技术片段（本设计冻结，尚未实现）

**归属裁决**：0050要求上层owner形成各自已检查变化，L1执行中立原子发布；CODE-FILE§5.3禁止跨模块业务服务构造友元。因此不能让消费owner读取feature原始写集，也不能把feature的私有构造权授予消费服务。最小扩展放在现有`海中鱼巣/核心/基础数据集.h/.cpp`，由同一L1 owner拥有不可变封存类型及组合入口；feature和消费分别私下准备并封存，业务只转交不透明材料。它不另开事务引擎、数据仓、全局版本、业务owner注册表或持久请求账，也不改变当前原子追加提交点。

此技术扩展与首个feature/消费使用方同计划冻结，不单独建立“通用平台”计划；旧原子追加入口继续兼容，当前已发布字段删除ABI不在设计阶段修改。

最小公开面如下（省略私有PIMPL和普通值式读取器，不省略业务分工）：

```cpp
class 基础封存追加片段 final; // 无公开构造器、无内容解包/修改器；可复制只读句柄
struct 基础片段封存结果 final {
    基础节点组追加状态 状态;
    std::optional<基础封存追加片段> 片段;
};
class 基础片段发布回执 final; // 同L1 owner封闭构造；三组编码只读getter
struct 基础片段组合结果 final {
    基础节点组追加状态 状态;
    std::vector<基础片段发布回执> 片段回执组;
};
// 以下两个入口属于基础数据集；实现均在其现有.cpp内。
基础片段封存结果 封存原子追加片段(
    const 基础节点组追加请求& owner内部请求) noexcept;
基础片段组合结果 原子追加封存片段组(
    const std::vector<基础封存追加片段>& 片段组) noexcept;
```

1. **构造与寿命**。`基础封存追加片段`与`基础数据集`同头唯一声明；仅同owner的`基础数据集`为构造友元。封存入口深复制值式请求到私有`shared_ptr<const 内容>`，不保留调用方可变容器、裸指针、锁或callback。内容只能由L1读；句柄复制不开放修改。数据集拥有私有不可变运行期身份令牌，片段保留同一只读令牌；提交到另一个数据集（包括原对象销毁后地址复用）入口拒绝。令牌只比较同实例身份，不是稳定编码、owner、版本或可持久许可。封存不分配正式节点编码、不写任何事实；只完成结构检查，最终fresh一致性仍由提交点判定。
2. **owner边界**。feature公开准备类型的构造权仅授予同文件feature owner，只公开必要F、old/new值式读取器，不公开自有sealed片段或原始`基础节点组追加请求`；自有片段只由feature提交入口拼入一次组合，防止占用取消后外部延迟提交。消费owner只封存自己的字段，调用方不替其组装；feature只转交附加opaque片段，不解包消费内容。中立封存函数是DATA-L2 owner可调用的技术入口，不按调用者字符串判权限；本机制封闭的是材料可变性，不声称C++运行时能识别业务代码身份。不得为“唯一调用者”添加底座业务ACL或反向friend。
3. **当前闭包不需要跨片段新节点引用**。feature的新命中节点只在feature片段内引用，消费新记录及source反向字段只在消费片段内引用；两方通过既有F/source/动作稳定编码关联。各`基础组内节点引用`只指本片段新节点，封存时越界即拒绝。组合按输入片段顺序计算新节点前缀偏移，对新节点初始字段、既有节点追加字段以及外部边两端中的每个局部引用逐一重定位；不能把局部下标当稳定编码。现有替换字段类型仍不能指尚未发布的新节点；确需此能力时不能临场补强转。跨片段新节点引用、符号导入/导出和占位编码明确不提供。
4. **完整快照**。本新入口的每一片段只使用`预期联合节点组`，`预期既有节点组`必须为空；受写的既有宿主、旧/新引用目标及既有外部边端点按现有L1合同纳入完整联合快照。相同节点的快照按稳定编码规范排序后完整逐项比较，完全一致才合并一次，任何差异返回`预期不符`、零发布；不能把两个不完整字段子集拼成完整快照。非法重复字段/边编码属于入口拒绝。各owner可在不同时间准备，最终合并预期与实际现状仍在原子追加独占锁内整体复核，封存不保证材料仍新鲜。
5. **重叠写入**。同一sealed对象在输入组出现两次直接拒绝。不同片段写同一既有字段关系（删/改任意组合）拒绝；由联合快照解析物理宿主和字段键后，不同片段触碰相同`宿主+字段键`也拒绝，包括追加对追加、追加对删改及删改对删改。该规则是多owner片段组合的保守冲突规则，不改变L1允许一个owner在单个片段里维护多值字段或“删旧再加同键”的语义。不同字段键可共同写同一宿主。多个片段向同一目标增加不同引用不是冲突；共同端点的反向索引由唯一候选事务维护。跨片段相同`源、目标、类型、角色/顺序`外部边追加拒绝；不同边合法。不同片段局部新节点天然分域，不按局部下标误报重叠。
6. **唯一发布**。封存和合并的容器分配、溢出检查、偏移表、回执容器及全部容量准备在事实发布前完成。组合构成一个内部`基础节点组追加请求`，只调用既有`原子追加节点组`一次；不先执行任一片段、不分片提交、不回调业务、不再实现候选表或加第二事务锁。最后写入仍是该原入口的唯一表交换。零片段/空写集、格式、数据集身份或写冲突返回入口拒绝；过期快照返回预期不符；资源不足返回资源失败；底座内部不变量异常沿既有工程终止链。
7. **回执**。成功后按预先记录的三类前缀范围分回片段回执，顺序严格对应输入片段及其内部请求顺序。回执同样由L1封闭构造，私有保留原sealed内容的只读身份，公开`对应片段(const 基础封存追加片段&) const noexcept`及三组编码的const读取器；业务不能自行构造“成功回执”。新节点初始字段不在现有“追加字段关系组”回执内，不新增伪编码补足它。组合返回前只能进行已预分配容器的无分配填充/移动，禁止发布后内存分配失败被报成“零发布资源失败”。失败返回无成功片段载荷。回执是本次技术发布结果，不是消费资格/业务完成授权；消费owner随后依正式source反向引用严格读回。句柄没有持久一次性标记，重放防重由消费source完整预期和正式记录保证；不建第二请求账。

上述签名和规则仅冻结封存/组合技术合同。feature核心准备、消费资格与收尾仍由各owner合同决定；中立L1不能替它们判断Q或完成服务。

## 5. 长期任务与每次执行

6190§3.2不要求长期服务根先完成，§2/§5正式根目标仍为INT64_MAX。用户最新排除上限运行分支，不撤销此目标表示。初始化应按正式根目标建立，结算一级D是否同目标须在其正式定义范围内统一；不能因现代码方向增加而发明“目标已满足也永久不完成”的特例。长期结算控制与每个正式来源的一次消费分离：一次Q只证明本来源消费完成，self仍按实际D目标作后继判断，不因必须处理来源9→12而强制长期T先完成。方法效果方向增加与需求目标表示分别保存。本切片不设计达到上界后的任务或调度分支。

来源T的9→12以本次消费回执和效果独立核验为前提，发生在本来源收尾，不依赖长期结算T已完成。`确认并收尾(T,X,A)`需拆分“核验本次消费效果/标记来源已结算”和“决定长期T后继”；删除self的结算X只允许完成否则工程停止分支。

root/一级D初始化按现行正式目标定义，不从旧学习C/R倒推初始值。每个来源绑定保存source完成结算和Q，before由执行前fresh读取，不沿用初始化冻结值。预测为本次V与Q计算的after；参数场景承载所需引用/值域，不从全局宿主偷取Q。旧方向目标与新正式定义的冲突必须按§5.1不兼容检测或经冻结的同身份迁移处理，不能只改校验后继续使用旧目标。

### 5.1 旧记录处理

冷初始化生成新合法定义；已有方法/一级D/绑定若仍是旧固定+1语义，不静默当作新定义。默认本后继不物理迁移、不抹除学习对、不新建同D第二T：启动识别不相容旧定义后保留材料，明确工程诊断并停止该消费通道。需要迁移现存方法头/参数、D列表目标键与T绑定时，必须另冻结同身份原子迁移合同，不能只改新建路径后声称旧资料可用。

旧C/R并非天然错误经验，但缺Q维度的配对不能被新Q方法当作任意Q的执行依据。初始化只登记方法定义，不伪造新配对；模拟用隔离Q和V按同一公式产生新C/R，现实消费记录不得被模拟改写。

## 6. 治理汇总来源的人类资格

与已发布`TASK-DIRECT-CONTRIBUTION`严格对齐：其叶子分类与Q只定义计值，不证明最终现实人类服务资格。只有正式直接子任务完成结算可作为最终消费来源；来源为治理汇总也不得绕过6190§3.4的人类、明确确认、真实结果及观察归因门禁。来源必须能沿已冻结的逐级完成/接收记录追溯，不能用当前任意子链替代被冻结材料，不能仅凭Q>0认可服务。

人类资格按每一份正贡献沿同一冻结来源闭包的路径核验。所谓“服务锚”仅为已有已确认人类服务D/T/完成/观察归因合同的阅读简称，不新增节点类别或字段：某叶子的父路径上，必须有本来源闭包内已经正式完成、确认语义有效且通过真实结果/观察归因的对应人类服务任务，才可覆盖该任务实际派生的准备贡献。不凭任意祖先文本确认放行，不越过最终结算父任务到闭包外查找授权，不跨兄弟子树借资格。多个合格服务任务可分别覆盖各自贡献路径。

三个裁决例：治理汇总内一棵合格服务子树不能覆盖另一棵无确认正Q子树；纯准备来源不能借其兄弟的人类确认单独入账；已完成合格服务任务之下的准备叶可以随该任务正式归集一起入账。这直接落实6190§3.3/§3.4，不新增“Q正即合格”语义。剩余是task owner公开冻结完成/接收闭包读接口及复用既有资格读取的物理合同，不再笼统称作需用户裁决的人类资格问题。

对来源及下层贡献的防重仍必须实现；消费owner从冻结贡献闭包取得实际正贡献完成身份，阻止它被其它来源包装后重复消费。防重不产生人类资格，也不因Q=0自行豁免门禁。物理读取/校验合同与生产调用未闭合前，联合写入提供者不能声称最终服务值业务消费已接通。
