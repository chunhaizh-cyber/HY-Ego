## 1. 本次具名漂移与裁决

执行侧消费 v0.3 后，正式规范把场景中的状态使用绑定冻结为 `C/E/S`：`C` 是场景，`E` 是场景内存在，`S` 是中性状态；被描述特征类型从 `S.正式特征类型` 取得，因此取消独立 `P`，也不在绑定中复制 FT。

本次只把上述正式边界同步到既有状态施工包。以下合同全部不变：

1. 状态本体仍只有状态身份、正式 FT、固定准确值、强时间四字段；
2. 状态合同版本仍为2，4212 v0.4中的 DTO、枚举数值、公开函数、成功谓词和构造参数与 v0.3 相同；
3. L1物理布局、owner写入、幂等、退出、清理、历史守卫、旧格式拒绝和特征窄核验不变；
4. 生产白名单仍只有特征类、状态类和专属施工记录；不迁移任何消费者；
5. `C/E/S` 是4202拥有的后继场景绑定，不进入状态 DTO、状态节点、状态写集或本次实现。

## 6. 核心流程

### 6.1 创建与重放

校验请求与G0 → 查首次幂等材料 → 未绑定时调用特征窄核验 → 取得内部当前UTC → 形成固定写集 → 状态owner一次提交 → 按发布截止独立完整读回。精确重放按首次材料收敛；异请求冲突。

### 6.2 读取与查询

完整读取在同一 Gread/H 核对节点、族归属、FT关系、互斥准确值、互斥时间、首次UTC和生命周期。历史有效守卫是 `创建G<=H && (!退出G || H<退出G)`；future-exit 即 `H<退出G<=Gread` 仍成功。查询只召回候选，再按同G完整读取、排序和去重；FT召回还必须过滤状态owner、精确关系类型和精确目标FT。身份确认只读取节点与唯一族归属，不替代四字段内容读取。

### 6.3 退出与清理

退出在一个状态owner写集中退出状态节点、两关系和三值，不级联外部引用；退出结果以 `Gexit-1` 作为内容H、`Gexit`作为结果截止与共同退出代次。同步清理先查退出owner首次写入材料：未命中才扫描当前实例状态并首次退出；已命中则从首次规范写集和首次结果重建原有序六事实组及退出G，不再扫描。随后以原清理键和原完整L1请求调用物理清理；清理后原双键返回首次墓碑，改变清理键不得伪装无候选。

owner写回显与L1清理回显逐项核对合同、身份、代次、发布确定性、映射和墓碑；未知或矛盾一律内部不一致。L1墓碑不保存关系端点/类型，物理清理后的身份历史见证返回 `历史材料已清理` 和空见证。

## 7. 旧格式与消费者迁移

删除状态 v1 DTO、函数及快照编码/解析/查询；旧材料不删除、不回写、不双读、不转换。缺少新族归属、FT关系、互斥准确值、互斥强时间或仍是旧快照形状时返回 `旧格式不支持`。

本轮不迁移任何消费者。场景类必须等待4202边界下的 `C/E/S` 状态使用绑定物理合同与其消费的状态读取 ABI 后继，再从届时正式源码判断应调用完整读取、身份确认或其它正式入口。绑定以 `E + S.正式特征类型` 定位属性，不建立 P 或 FT 副本。存在类和因果类同样留待各自正式后继重新扫描，本设计不预判答案。
