## 1. 目标、依据与非目标

本包补齐 4010、4030、4040 已定义而新直接身份三仓当前未闭合的底层能力：

1. 关系按目标、任一端点及类型角色的普通/事务值式读取；
2. 关系失效/重挂候选期间写前发布版本对普通读取持续可见、本事务只见写后；
3. 索引移除候选的形成、事务读回、确认、撤销和最后发布；
4. 关系失效、索引移除、节点删除进入同一会话精确写集；
5. 事务外读取经统一读取服务取得一次共享许可，再读取节点、关系和索引的同一已发布可见点；
6. 专项矩阵接入正式完整自检运行器，并按现行日志系统提供可关闭的人读调试切片。

## 4. 数据结构与 ABI

### 4.1 关系条目

`正式关系记录` 和公开状态 ABI 不变。内部 `关系条目` 改为：

```cpp
正式关系记录 已发布记录;
std::vector<正式关系记录> 历史记录组;
std::optional<正式关系记录> 候选写后记录;
std::uint64_t 候选事务序号 = 0;
```

新关系候选在发布前没有 `已发布记录`，因此条目另保留 `bool 已有发布基线`。变更候选必须已有基线。确认前为历史组预留一个元素容量；最后发布不得分配。

可见性与审计合同固定为：

- 普通单句柄、枚举和普通审计只读取 `已发布记录`；没有发布基线的新建候选对普通读取不可见。
- 相同事务的单句柄和事务审计优先读取 `候选写后记录`；失效候选在只允许有效记录的读取中表现为未命中。
- 普通审计的“当前”为发布基线，“历史”为已经正式发布的历史组。
- 事务审计的“当前”为候选写后；“历史”为正式历史副本后追加本次候选对应的发布基线。该追加只存在于返回副本，不提前改写仓库正式历史。
- 确认只复核并预留容量；发布时才把旧发布基线追加到正式历史并以候选写后替换发布基线；撤销只丢弃候选写后。
- CR-F17 必须先裁决候选槽，再裁决发布基线版本：同事务同语义失效候选接受其写前句柄或写后审计句柄并回显同一写后；失效正式发布后，接受当前审计句柄或正式历史末项中与当前版本严格相邻且端点、类型、顺序号一致的本次写前句柄。其它旧版本拒绝。候选形成发生分配失败时按既有 `正式关系操作状态::内部不一致=15` 返回；与 CR-F18 撤销相同，只清候选写后/事务序号，保持 `已有发布基线=true` 及发布基线/历史原样。

### 4.2 索引候选

```cpp
enum class 可重建索引候选种类 : std::uint8_t { 创建 = 1, 移除 = 2 };

class 可重建索引候选 {
  const 可重建索引仓库* 仓库_;
  std::uint64_t 事务序号_;
  可重建索引候选种类 种类_;
  std::optional<可重建索引记录> 写前记录_;
  std::optional<可重建索引记录> 写后记录_;
  可重建索引候选阶段 阶段_;
};
```

创建：写前空、写后有；移除：写前有、写后空。`仓库_` 由 CR-F52/CR-F08 构造时绑定 `this`，移动后来源候选必须清空 `仓库_`、事务序号并进入 `已移动`；CR-F09—F11 只接受 `仓库_ == this`。现有阶段 `1—5` 不变。`可重建索引操作状态` 现有 `1—10` 不变，追加 `已移除候选=11`、`幂等不存在=12`。

索引条目追加：

```cpp
std::uint64_t 待移除事务序号 = 0;
bool 移除已确认 = false;
```

移除候选形成不删除正反绑定；普通读取仍命中，本事务读取过滤该键。CR-F08 对同事务已有待移除标记返回 `幂等不存在(12)+写前当前记录+空候选`，对物理键不存在返回 `幂等不存在(12)+空当前记录+空候选`；CR-F13 必须先从会话索引移除写集读回同键并返回原写前记录，若仓库回显同事务标记而会话无对应写集则为内部不一致。确认只置位；撤销清零；发布按精确写前记录删除正反绑定。CR-F13 在调用 CR-F08 前先执行 `索引移除写集_.reserve(索引移除写集_.size()+1)`；预留失败时仓库尚无候选，直接记录资源失败。预留成功后，候选形成与无分配移动严格分开。

本包的 CR-F07、CR-F08 和 CR-F13 只接受 `索引目标种类::节点`。当前代码虽声明 `关系=2`，但 4010 只正式授予节点候选定位；关系索引的新增、移除或恢复必须另有正式规范和设计，不得由本包顺手放行。

反向查询不接收完整索引记录，避免调用者为查询目标伪造物理键。值式目标 DTO 固定为：

```cpp
struct 可重建索引目标 {
    索引目标种类 目标种类 = 索引目标种类::节点;
    节点句柄 节点;
    关系句柄 关系;
};
```

`可重建索引目标完整` 对节点目标要求节点句柄有效且关系句柄无效，对关系目标要求相反；CR-F07/F30/F44/F56 仍额外只放行节点目标。CR-F12 唯一构造 `可重建索引目标{索引目标种类::节点, 节点, {}}`，不存在物理键来源字段。

### 4.3 会话写集

保留四组现有写集，新增：

```cpp
struct 索引移除写入项 { 可重建索引候选 候选; 可重建索引记录 写前记录; bool 已读回; };
struct 节点删除写入项 { 节点直接身份删除未发布候选 候选; 节点直接身份记录 写前记录; 节点句柄 写后节点; bool 已读回; };
std::vector<索引移除写入项> 索引移除写集_;
std::vector<节点删除写入项> 节点删除写集_;
```

CR-F12 在调用节点仓前先按写前节点查找 `节点删除写集_`：命中时调用 CR-F55 证明本事务节点视图不命中并置该项已读回，返回 `幂等读回 + 同一写后节点`，不得形成第二候选。未命中时先执行 `节点删除写集_.reserve(节点删除写集_.size()+1)`，预留成功后才调用节点仓形成删除候选，最后无分配移动。未命中写集而节点仓回显幂等时，只允许以普通 `读取节点审计(当前身份)` 证明该节点已正式删除、同仓同编号且版本严格 `+1`；若审计仍为有效节点，说明仓库存在本事务待删除标记但会话丢失写集，属于内部不一致。

`节点直接身份索引移除结果` 采用功能确认第 2 节合同。所有移动候选只在一次 `push_back` 成功后归会话拥有；容器分配失败时立即撤销局部候选。

### 4.4 事务外读取结果

```cpp
enum class 节点直接身份结构读取状态 : std::uint8_t {
    已读取 = 1,
    未命中 = 2,
    入口拒绝 = 3,
    许可拒绝 = 4,
    内部不一致 = 5
};

template <typename 值类型>
struct 节点直接身份结构读取结果 {
    节点直接身份结构读取状态 状态 =
        节点直接身份结构读取状态::入口拒绝;
    std::optional<值类型> 值;

    bool 成功() const noexcept {
        return 状态 == 节点直接身份结构读取状态::已读取
            && 值.has_value();
    }
};
```

节点不存在返回 `未命中 + 无值`；合法空关系组或索引键组返回 `已读取 + 含空 vector`；许可失败返回 `许可拒绝 + 无值`。上层不得从空 vector 反推许可是否成功。

读取服务构造函数固定为：

```cpp
节点直接身份结构读取服务(
    const 节点直接身份结构事务域* 事务域,
    const 节点直接身份仓库* 节点,
    const 正式关系仓库* 关系,
    const 可重建索引仓库* 索引) noexcept;
```

四个指针只借用且必须同时非空；由运行期装配保证其生命周期覆盖服务。服务不保存许可，不返回仓库引用、许可、令牌、会话或锁。

CR-F56 的关系读取种类、批量请求和批量结果字段精确采用函数功能确认 §2 第9项。单项 CR-F39—F44 只构造长度为1的相应批量组并调用 CR-F56，不另行取得许可。CR-F56 在入口校验完成后一次性为三组输出预留容量，再取得一次共享许可；许可内不得继续分配三组外层容器，子 vector 的仓库复制仍按仓库值式读取合同处理。任一异常清空全部输出并返回 `内部不一致`，不得返回半批。

```text

-> 普通审计目标节点
-> 若已删除：逐关系证明当前审计记录已失效、逐索引证明普通读取不命中，返回幂等读回和审计当前已删除句柄；不调用 CR-F12

-> 具名领域服务在同一执行器回调中确认领域参与者材料齐备后请求提交
```

CR-F58 是关系仓结果进入会话写集的唯一私有登记根。CR-F17 对同事务同种类、同请求语义的既有变更候选返回 `幂等读回 + 既有写后关系 + 空候选`；CR-F58 必须在新关系 / 关系变更写集中找到恰好一个同写后句柄项，或以 CR-F25 普通审计的当前记录证明它是有效或已失效的已发布事实幂等。两者皆否或多项命中属于孤立候选 / 重复写集内部不一致。新候选先按种类选定唯一目标写集并 `reserve(size()+1)`；预留失败时局部候选仍未移动，立即调用 CR-F18 撤销；预留成功后才无分配移动。CR-F53 同样先预留 `索引创建写集_`、再调用 CR-F52、最后无分配移动。禁止把容器分配和候选移动置于同一表达式。

确认：节点创建→新关系→关系变更→索引创建→索引移除→节点删除。
撤销：节点删除→索引移除→索引创建→关系变更→新关系→节点创建。
发布：与确认同序，索引移除先于节点删除。

事务外发布读回固定顺序：

```text
执行器完成最后发布并释放独占许可
-> CR-F56 读取服务取得一次共享许可
-> 在该许可生命周期内按请求顺序调用节点、关系和索引普通读取入口
-> 复制并对齐三组值式结果
-> 释放共享许可
-> 返回结构化读取结果
```

完整自检固定顺序：

```text
CR-F20 运行原27项
-> 依次调用 CR-F45、F46、F47、F48、F49、F50
-> 依次拼接47项到验收[27..73]
-> 计算失败数量与总通过
-> CR-F51 以顺序170、稳定编号 NODE-DIRECT-IDENTITY-P1 登记 CR-F20
-> 自检运行器登记数量与执行数量均精确为17
```

## 6. 锁、所有权与并发

1. 写执行器先取得事务域独占许可；会话只保存三仓引用和事务序号。
2. 每个仓库公开入口只持本仓共享锁或独占锁。关系仓复制记录后释放关系锁，再调用节点仓复核端点；索引仓在取得自身锁前完成目标权威读取。
3. 不允许共享锁升级、跨仓同时持锁、持锁日志/I/O/回调/等待。
4. 上层领域服务只通过执行器回调把值式 `节点直接身份核心退役规格` 传给 CR-F57；不得持有许可、令牌、仓库锁或把会话逸出回调。
5. 线程队列私有锁必须在调用执行器前释放；静态扫描禁止在队列锁作用域中调用 `执行`。
6. 候选期普通读取观察事务前已发布事实；仅持有相同事务序号的会话观察候选写后。其它事务不得看到候选。
7. 事务外读取必须经 `节点直接身份结构读取服务`；CR-F39—F44 全部委托 CR-F56。CR-F56 每批只取得一次共享许可并在许可内完成该批全部仓库值式读取。许可失败不调用仓库。
8. 关系枚举需要复核端点时，关系仓先在自身锁内复制候选记录并释放锁，再逐条调用节点仓普通读取；整个批次仍被 CR-F56 的事务域共享许可包裹，因此写事务不能在多仓读取之间发布。
9. 会话已经处于独占许可内，不得调用读取服务或再次取得共享许可；它调用仓库普通发布视图并叠加自己的精确写集。

## 7. 结果与失败分类

| 分支 | 结果 | 结构 |
| --- | --- | --- |
| 无效句柄、未知类型、无效键、事务零 | 入口拒绝 | 零写 |
| 空关系组、空反向键组 | 合法空组 | 零写 |
| 索引键不存在 | 幂等不存在→会话幂等读回 | 零写 |

| 删除前仍有有效相关关系或索引 | 入口拒绝 | 已有写集撤销 |

发布后读回失败是内部逻辑错误，不重新打开候选撤销。

只读返回函数的异常边界固定为：CR-F01—F03/F21/F25—F27/F30—F31 在分配、复制或排序中发生 `std::bad_alloc` / `std::length_error` 时原样抛出，零机器事实写入；前置成立后发现历史、排序、正反绑定或候选组合不变量破坏时抛出 `std::logic_error`，固定消息前缀为 `CORE-RETIRE-P1:`。事务内调用由现有写执行器 `执行(...)` 的 `catch (...)` 收口为 `内部不一致` 并撤销；事务外上层不得直调仓库，只能经 CR-F56，CR-F56 捕获全部异常、销毁共享许可、清空三组输出并返回 `内部不一致`。CR-F54 同样以 `std::logic_error` 拒绝导出半结构。日志、控制台或普通空组不得替代上述异常映射。
