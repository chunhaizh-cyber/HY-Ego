## 2. 当前事实与正式依据

4015 §4.2 要求审计结果显式携带幂等键，并与幂等账分账、互证；§4.3 要求恢复材料分为当前快照、历史事实、审计记录和幂等账，恢复不能从普通快照补造事实。4200 §7.6 要求幂等账持久保存请求意图摘要、执行证据摘要、首次执行证据、首次结果和确定性结果摘要；§7.7 要求发布后权威读回发生在发布代次推进后、许可释放前，读回不一致必须隔离，禁止二次改写或补救写入；§8.4 要求发布后见证未知时保留运行期事实权威并标记持久化未知。

当前真实 E01 顺序是：领域形成 G6 意图凭证并预探测 → 构造写集 → `L1_.提交写集(写集, 0x15000301U)` → L1 在仓库内部生成新编码映射并写双账/审计 → 返回后领域才从映射形成 `实际存在登记结果.登记.服务身份`。当前 `L1写集请求`、`L1写入结果`、`L1幂等账记录`、`L1审计记录` 与 `L1恢复材料` 没有领域结果见证段，领域缓存不能代替 L1 双账。

## 3. 冻结 DTO 与物理位置

### 3.1 结果计划（写前）

在 `海中鱼巣/核心/L1事实基座.数据.h` 新增值式 `L1领域结果见证计划` 及 `L1领域结果字段计划`。计划字段固定为：

```text
格式版本                 U32 = 1
业务操作标签             U32
领域合同版本             U32
领域规则版本             U32
入口变体                 U8
字段组                   按字段标签严格升序的非空数组
```

v1 **只支持节点结果字段**，不接受关系或值的 variant。C++ 强类型固定为：`节点种类 期望对象种类` 与 `std::optional<值表示种类> 期望属性类型表示`；`节点种类` 和 `值表示种类` 均使用现有枚举的 `std::underlying_type_t` 值。字段计划的 C++ 字段固定为：`std::uint32_t 字段标签`、`写集本地键 写集本地键`、`节点种类 期望对象种类`、`std::optional<值表示种类> 期望属性类型表示`。字段标签不得重复；本地键必须在本次写集节点本地键组中唯一；计划不携带稳定编码、不携带事实代次、不携带领域缓存地址。

E01 的唯一计划为：

| 顺序 | 字段标签 | 本地键 | 期望对象 | 期望类型 |
| ---: | ---: | ---: | --- | --- |
| 1 | `0x00000001`（服务身份） | `1` | 仅节点 | `节点种类::普通`，`std::nullopt` |
| 2 | `0x00000002`（实际存在资格属性类型） | `2` | 仅节点 | `节点种类::属性类型`，`std::optional{值表示种类::I64}` |

E01 计划头固定为：业务操作标签 `0x15000301U`、领域合同版本 `1`、规则版本 `1`、入口变体 `1`。领域 `形成G6实际存在登记意图凭证` 的公开请求编码必须在固定字段序列中编码该计划的 `RP` 摘要；计划摘要进入请求意图互证，但不含本次尚未产生的稳定编码。

`L1写集请求` 增加 `std::optional<L1领域结果见证计划> 领域结果见证计划`；同时在 `L1领域意图凭证` 增加 `L1确定性摘要 领域结果计划摘要`，非结果见证入口必须为全零摘要，E01 必须等于 `形成L1领域结果计划摘要(计划)`。使用结果见证的入口计划必须非空；不使用的既有 G0/领域入口保持空并沿用原合同。L1 在预探测后、候选生成前再次验证计划头、字段排序、写集本地键和凭证中的计划摘要绑定；任何不一致在第一笔候选前拒绝。

### 3.3 唯一编码与摘要

所有整数均使用现有 `L1确定性编码内部::写U8/写U32/写U64` 的大端序；ASCII 前缀是逐字节原始固定字节，不写长度或 NUL；数组先写大端 U64 数量，再按固定顺序逐项写入；无隐式填充、指针、地址、容器顺序或 locale。节点字段的 optional 编码固定为：先写大端 U8 `0` 表示 `std::nullopt`，或写 U8 `1` 后立即写一个大端 U8 的 `值表示种类` underlying 值；不得写其它标记或占位字节。唯一公共摘要函数在 `核心/L1事实基座.数据.h`：

```text
形成L1领域结果计划摘要(计划)
  原始字节 "HZY-L1-RP" → U32 格式版本 → U32 业务操作标签
  → U32 领域合同版本 → U32 领域规则版本 → U8 入口变体
  → U64 字段数量 → 每字段 U32 字段标签 → U32 本地键
  → U8 节点种类 underlying → U8 optional标记(0/1)
  → 标记为1时 U8 值表示种类 underlying

形成L1领域结果见证摘要(结果段)
  原始字节 "HZY-L1-RW" → U32 格式版本 → U32 业务操作标签
  → U32 领域合同版本 → U32 领域规则版本 → U8 入口变体
  → U64 发布事实代次 → U64 写集幂等键 → U64 字段数量
  → 每字段 U32 字段标签 → U32 本地键 → U8 节点种类 underlying
  → U8 optional标记(0/1) → 标记为1时 U8 值表示种类 underlying
  → U64 本次新编码
```

两者均使用现有 SHA-256 实现并返回 32 字节 `L1确定性摘要`。计划摘要只进入 G6 请求意图绑定；结果见证摘要进入 `L1写入结果`、首次幂等账、成功审计和恢复结果段。现有请求意图摘要、执行证据摘要、通用发布后读回摘要和确定性结果摘要的版本与含义不被偷换；确定性结果摘要必须额外校验结果见证摘要，不能只校验映射或领域缓存。

## 4. 单事务顺序和所有权

实现位置固定在现有 24 项白名单内：

1. `领域/服务.L1实际存在.ixx` 由 E01 请求形成上述计划，把计划摘要同时写入 `L1领域意图凭证.领域结果计划摘要` 和 G6 意图编码；领域只声明本地键与预期类型，不分配稳定编码。
2. `核心/服务.L1事实基座.ixx` 在 provider 前完成合同、计划和意图绑定校验，再执行既有 `探测幂等`、快照代次校验和执行证据准备；锁前发现的任何计划/绑定错误固定返回 `L1写入状态::入口拒绝`，不进入仓库候选。
3. `核心/仓库.L1事实基座.ixx` 在唯一锁内分配本次映射、构造候选事实，并对计划逐字段解析：恰有本地键 1、2 各一条映射，种类分别为 `节点种类::普通` 与 `节点种类::属性类型`，第二项表示恰为 `值表示种类::I64`，编码非零且互异。锁内映射缺失/重复、节点种类或 optional 表示不符固定返回 `L1写入状态::入口拒绝`，丢弃候选且不交换、不产生成功账/成功审计。通过后在同一候选中形成结果见证、通用发布后读回、领域结果见证摘要、确定性结果摘要、首次幂等账和成功审计。
4. 候选交换为已发布状态后，在独占许可释放前执行既有权威通用读回；交换后通用读回或领域结果见证不一致固定返回 `L1写入状态::内部不一致`，保留已交换代次、保留候选中已形成的首次账/成功审计，追加失败见证和隔离审计并置隔离；不进行二次账写、补记或普通快照补证。
5. `L1写入结果` 将同一结果见证返回给 `服务.L1实际存在.ixx`。领域只按字段标签读取 `服务身份` 和 `实际存在资格属性类型`，形成现有 `实际存在结构登记`；不得再调用 `查找映射` 作为独立事实来源。领域缓存只是非权威投影。
6. `核心/仓库.L1事实基座.ixx` 的 `状态` 增加按幂等键索引的 `std::unordered_map<std::uint64_t, L1领域结果见证记录> 领域结果见证状态组`，它与幂等账、审计组同属仓库权威状态。成功候选把同一不可变结果见证记录分别写入三份状态字段后才 `std::swap`：幂等账、成功审计和结果见证状态组；候选未交换时三者都不进入正式状态。仓库新增精确值式函数 `L1恢复材料 导出恢复材料() const`，在一个共享锁内从当前快照、幂等账、审计和结果见证状态组分别复制，按幂等键排序生成 `L1恢复材料.领域结果见证记录组`，不得从幂等账临时派生第三副本。`建立恢复候选` 在隔离副本中把三份状态副本和导出段逐字段互证，不改变当前状态。

方案 A 不增加第二次 `提交写集`，不增加发布后补记接口，不把 L1 锁/仓/事务令牌暴露给领域。

## 5. 失败、隔离与恢复拒绝矩阵

| 条件 | 入口/候选结果 | 是否写事实 | 恢复处理 |
| --- | --- | --- | --- |
| 缺少 E01 计划、头版本/标签/变体错误 | 入口拒绝 | 否 | 材料不完整，拒绝候选 |
| 计划摘要未绑定 G6 意图摘要 | 入口拒绝 | 否 | 错意图摘要，拒绝 |
| 字段重复、缺失、未知本地键或本地键重复 | 入口拒绝 | 否 | 缺字段/错映射，拒绝 |
| 映射缺失、重复、种类/属性表示不符（锁内） | 固定 `入口拒绝`，候选丢弃 | 否，不交换、不写正式成功账/审计 | 材料不完整，拒绝 |
| 结果见证摘要与字段不一致（交换前） | 固定 `入口拒绝`，候选丢弃 | 否，不交换 | 材料不完整，拒绝 |
| 结果见证或通用读回不一致（交换后） | 固定 `内部不一致`，隔离 | 已交换代次保留；首次账/成功审计保留，追加失败见证/隔离审计 | 内部不一致，禁止补记 |
| 账、成功审计、恢复结果段任一缺失或不等 | 恢复拒绝 | 不替换当前状态 | `材料不完整`，候选不存在 |
| P-E 错误稳定编码、来源种类/生命周期错误 | 恢复拒绝 | 不替换当前状态 | 不能接受领域缓存或 SQL 补造 |
| 已发布但持久结果见证未知 | 返回持久化未知/隔离 | 运行期已发布代次仍权威 | 不重写原幂等账；启动保持发布未知/损坏 |
| 同键同义重试 | 返回首次结果见证与首次读回 | 不新增事实/提交 | 三份结果见证必须继续等值 |
| 同键异义或结果计划不同 | 幂等冲突 | 否 | 审计冲突，不产生结果段 |

恢复候选必须同时满足：当前/历史事实完整；每个已发布幂等键最多一个成功见证；仓库状态中的幂等账、成功审计和结果见证状态组，以及导出的 `领域结果见证记录组` 的幂等键、版本、字段标签、本地键、节点种类、optional 标记和值、稳定编码、发布代次和两个摘要逐字段相等；通用读回摘要一致。任一缺字段、错版本、错摘要、重复记录或错误 P-E 均拒绝，不能从 `登记_`、普通快照、索引或 SQL 补齐。
