# DATA-L2 局部二值格规范化入口详细设计

身份：`LOCAL-BINARY-GRID-NORMALIZATION`

版本：v0.1

状态：待激活的直接后继设计

基线：`664c7fb9d3f2f92498cd9b7f2003bd4fada10e00`

## 1. 目标、依据与范围

本设计落实 2100 v0.19、4030 v3.11、4120 v0.15：DATA-L2 唯一具名入口接收**原始完整**局部二值轮廓或体素 `U64组`，核验类型、分辨率、完整层序、逐层 OR 与体素颜色。逻辑全零时返回 `[0,类型,N]`；其余成功输入按字节序不变返回原完整组。它不保存、读取、创建任何事实，也不建立 DATA-L3 或第二保存通道。

当前 `数据服务.局部二值格解析类.h/.cpp` 的 v2 纯解析器已在独立 `LOCAL-BINARY-GRID-U64-PARSER` 切片内重建，但该切片尚未发布且持有同一文件。因此本计划只在该解析计划发布后激活；不得修改其计划、施工记录或验证记录。

`rg` 当前生产路径未找到任何解析器调用者。不得臆造 DATA-L3、普通应用、设备或保存消费者。未来 DATA-L3 只负责：取得原始组 -> 调用本入口 -> 将成功载荷交给后续保存或解析调用；它不得自行做格式识别或改写，亦不得直达 DATA-L1。

## 2. 物理位置与唯一所有者

唯一模块为：

```text
声明与 DTO：海中鱼巣/领域/数据服务.局部二值格解析类.h
非 inline 定义：海中鱼巣/领域/数据服务.局部二值格解析类.cpp
```

该模块已经唯一拥有局部二值格的 4120 格式解析、受检算术、布局、OR 与颜色核验；规范化使用同一私有核验路径，避免新增第二格式解释器或复制逻辑。两个文件均已在主工程登记恰一次，故本计划不修改 `.vcxproj` 或 `.filters`。

新增公共实体是格式服务自己的纯值 DTO 与服务成员；私有布局/位访问/OR 辅助仅留在同名 `.cpp` 的匿名命名空间。所有新增或修改函数的诊断责任为“向上送出”：合法格式失败不记录日志，不新增弹窗、线程或全局状态。

## 3. 冻结公开 DTO

解析 v2 是未发布 WIP，本计划将它收束为下列 v3 公共面，不保留 v1/v2 兼容重载。

```cpp
enum class 局部二值格类型_v1 : std::uint8_t {
    轮廓 = 1, 体素 = 2
};

enum class 局部二值格规范化状态_v1 : std::uint8_t {
    已规范化 = 1,
    入口拒绝 = 8,
    格式不合法 = 9,
    数量超限 = 10,
    资源失败 = 26,
    内部不一致 = 27
};

struct 局部二值格规范化请求_v1 final {
    std::uint32_t 版本{1};
    局部二值格类型_v1 类型{};
    const std::vector<std::uint64_t>* 原始完整组{nullptr};
};

class 局部二值格规范化载荷_v1 final {
public:
    局部二值格类型_v1 获取类型() const noexcept;
    const std::vector<std::uint64_t>& 获取U64组() const noexcept;
private:
    friend class 局部二值格解析数据服务;
    局部二值格类型_v1 类型_{};
    std::vector<std::uint64_t> U64组_;
};

struct 局部二值格规范化结果_v1 final {
    std::uint32_t 版本{1};
    局部二值格规范化状态_v1 状态{局部二值格规范化状态_v1::入口拒绝};
    std::optional<局部二值格规范化载荷_v1> 载荷;
    bool 成功(const 局部二值格规范化请求_v1&) const noexcept;
};

struct 局部二值格解析请求_v3 final {
    std::uint32_t 版本{3};
    const 局部二值格规范化载荷_v1* 规范化载荷{nullptr};
};
```

`局部二值格规范化载荷_v1` 没有公共构造器、可变访问器或隐式转换；只有规范化服务可以形成它。解析请求不再携带裸 `vector`，从类型层保证解析入口只能消费本入口成功产物。它不承诺限制通用 `特征值U64组保存请求_B2::内容`：该通用保存服务依法不解释格式，且本设计不得改其 owner、DTO 或物理文件。

类公开成员固定为：

```cpp
局部二值格规范化结果_v1 规范化局部二值格(
    const 局部二值格规范化请求_v1&) const noexcept;
局部二值轮廓解析结果_v3 解析局部二值轮廓(
    const 局部二值格解析请求_v3&) const noexcept;
局部二值体素解析结果_v3 解析局部二值体素(
    const 局部二值格解析请求_v3&) const noexcept;
```

解析结果、格式结构与解析状态统一升为 `v3`，字段保持 v2 的 `N`、最高层位图块数、压缩层数、体素颜色项数与编码形态；唯一改动是输入从 v2 裸组请求换成 v3 规范化载荷请求。成功谓词同时核验版本、状态、相符类型、非空格式和正确编码形态。非成功时格式必为空。

## 4. 规范化算法与零副作用

1. `版本 != 1`、类型不是轮廓/体素、空指针或空原始组，返回 `入口拒绝`；不复制输入。
2. 原始组恰为三项 `[0,1,N]` 或 `[0,2,N]` 时返回 `格式不合法`。描述是已规范化产物，不能伪装成原始完整输入。
3. 按类型调用模块内部同一布局核验：
   - 轮廓：`N=8×2^k`，各层块数、层序、低位编号及相邻 `2×2` OR 完整一致；
   - 体素：`N=4×2^k`，最高层块、按升序占用位的一项 RGB、低24位范围和颜色数量正确，之后每层 `2×2×2` OR 完整一致；
   - 无法表示的受检乘法、加法、索引或 `size_t` 转换为 `数量超限`；其它布局/内容违例为 `格式不合法`。
4. 已验证的逻辑全零轮廓返回 `{轮廓,{0,1,N}}`；已验证的逻辑全零体素返回 `{体素,{0,2,N}}`。体素全零时颜色数量已经核验为零。
5. 已验证但非零的组仅复制一次，形成 `{请求.类型, 原始完整组}`。复制分配失败返回 `资源失败`；捕获其余意外异常返回 `内部不一致`。
6. 所有非成功均令 `载荷` 为空。函数不访问 L1、特征值服务、文件、日志、缓存、锁、线程或全局对象，因此全部分支零机器事实副作用。

## 5. 解析、保存与依赖边界

v3 解析先验证请求版本、非空载荷和载荷类型；轮廓入口只接收轮廓载荷，体素入口只接收体素载荷。然后复用第4节的同一内部核验：描述只校验三项类型/N；普通完整组重复核验完整格式并拒绝逻辑全零普通形式。解析只报告格式，不回写或分配展开零块。

解析“只接收规范化返回载荷”由 v3 强类型输入实现。保存的同一要求在本切片只能冻结为**调用顺序约束**：未来具名局部二值格保存协调者只能取 `成功结果.载荷->获取U64组()` 填入 `特征值U64组保存请求_B2::内容`，不能把原始完整组直接填入。由于 `U64-GROUP-VALUE-FACT-PERSISTENCE` 的 B2 保存合同尚未发布，且其服务必须保持通用中性，本计划不新建保存包装器、不修改特征值类，也不声称目前已有可执行保存消费者。

本计划直接依赖 `LOCAL-BINARY-GRID-U64-PARSER` 的已发布 v2 解析代码结果；它不依赖 B2 保存能力来编译。后续“局部二值格保存协调者”若需要建立，必须以已发布的 B2 保存 API 和本入口输出为依据另建计划，不能在本计划临场扩大。
