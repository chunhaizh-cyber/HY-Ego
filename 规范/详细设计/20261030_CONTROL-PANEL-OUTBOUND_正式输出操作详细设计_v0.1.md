这不是本能函数；直接修改的是既有外设输出队列信息，发送F/S/D仍由原正式链据事实形成。它也不是用户入站消息，不调用接收消息或服务要求接口。来源为操作员主动供稿，不能冒充自我自主表达。用户本次具名授权替代[原独立IO设计第7节](20261028_PERIPHERAL-INDEPENDENT-IO_外设独立收发模块详细设计_v0.1.md)“不得增加控制按钮”对本新产品操作的限制，除此之外原独立模块边界不变。

## 3. HTTP合同及安全边界

所有路径均在本次真实秘密前缀`/session/<秘密令牌>`下。该令牌不是服务端公开会话标识。目标`网页对话框目标`固定取`处理请求`已持有的服务端公开会话参数，加已验证的`X-HY-Dialogue-Id` UUIDv4；请求正文/查询参数不得指定会话、其它页面、占用身份、动作或来源角色。无默认页、无跨会话重定向。

### 3.1 请求

| 操作 | 精确协议 |
| --- | --- |
| 提交 | `POST <base>/api/control/output`；正文是未trim、未改写的UTF-8文本；`Content-Type: text/plain;charset=utf-8`；必需`Content-Length`、`X-HY-Dialogue-Id`、`X-HY-Control-Output: 1`、Host、Origin |
| 查状态 | `GET <base>/api/control/output/status?id=<规范非零uint64十进制>`；空正文；相同对话框header、操作header及Host；Origin若有必须相符，不强求浏览器同源GET必带Origin |

提交正文非空、严格UTF-8、最多现有`最大消息字节数`1 MiB；沿现有64 KiB请求头上限及拒绝Transfer-Encoding/重复Content-Length/重复Content-Type规则。内容类型使用现解析器的小写及首尾OWS处理后精确比较，不开放其它类型。GET的id禁止零、符号、溢出、前导零、空白、重复/未知查询项或额外后缀；不把稳定编码当提交序号。其它方法/不合法查询在新路由明确400、零入列，不处理OPTIONS授权，不发任何CORS许可头。完全错误的秘密路径仍由原404收束。

新增Host/Origin/操作header的采集只扩私有`HTTP请求`：`optional<string> 主机、来源、控制输出标记`及`bool 控制安全头无效=false`。大小写不敏感识别header名，去首尾OWS后保存；重复的上述安全header、控制字符或空值设置无效位。该位仅由新路由拒绝，不能借此改变旧路由的成功/拒绝协议；旧对话框标识的严格验证继续复用。私有正文长度存在性另保存bool供新POST检查，缺长度不是空白输出。

`运行本地网页对话宿主`在getsockname取得真实监听端口后构造一次`页面Origin = "http://127.0.0.1:" + 实际端口`，浏览器地址改以该值拼既有base，向私有`处理请求`传该值。不能用请求Host、Origin、URL查询或公开会话反推可信origin。新路由要求Host恰为该origin的authority，POST Origin恰等于该origin（拒绝缺失、null、多值、其它协议/端口/域名）；GET若携Origin同样核验。不是修改公开C++ABI或另建鉴权服务。

威胁边界：随机秘密路径+现页UUID+自定义非简单header、不开放CORS，加本叶新增严格Origin/Host校验，防外站表单/跨源fetch和DNS重绑定式Host使用。不能声称旧路由已有这套同源校验，也不声称隔离已获秘密URL的同源脚本、恶意扩展或本机特权程序。现CSP、no-store、nosniff、no-referrer、frame-ancestors继续沿用。正文及回执仅textContent显示，不插入innerHTML，不在URL/日志写正文、秘密令牌或公开会话密钥。

### 3.2 入列与回执

新POST绝不调用`确认传输页面`，不通过操作请求创建未知page。原页面refresh GET先完成既有登记，UI收到原GET messages成功后才开放提交按钮；服务端仍独立校验，未登记合法拒绝。构造`网页定向发送请求{目标, 原正文, std::nullopt}`，只调用一次正式提交，不调用队列回调入列、不取得/释放/猜测占用。现有原子校验中页面已被本能占用则409，不能抢占或绕过。

只有`已排队`且有非零正式提交序号才返回202。该回执是正式入列证明，不是发送完成、对方收到或自我生成意图。新HTTP响应不会成为发送完成事实；发送完成仍只由原outbound HTTP全部写出后的回调产生。

响应JSON固定包含：`status`（下表正式枚举中文名）、`submissionId`（非零十进制字符串或null）、`httpBytes`（十进制字符串）、`systemError`（int）、`accepted`（bool）、`automaticRetry:false`。POST成功accepted=true；拒绝false且id=null。状态GET成功accepted=true只表示该页正式提交记录存在，不声称来自本控制台；UI来源由本次POST回执与操作员正文对应保存。

| 分支 | HTTP及处理 |
| --- | --- |
| POST已排队 | 202，原非零id；正文已入正式队列 |
| GET找到已排队/正在写出/已完整写出/写出未完成/已取消 | 200，返回原查询结果及原id；枚举各自保留，不压成成功bool |
| 格式/header缺失/重复安全header/GET非法id或方法 | 400（Origin/Host/操作header权限不符为403）；零入列 |
| 正文过大/非允许内容类型/空或非法UTF-8 | 413/415/422；零入列 |
| 页面未登记/查询提交不存在 | 404；未登记不自动建页；没有找到不冒充已取消 |
| 页面被占用 | 409，零入列；不自动排等待重发 |
| 会话失效/宿主已停 | 410/503；不换会话或默认目标 |
| 正式提交返回未知枚举、已排队无id、查询id不符、内部异常/坏回执 | 工程诊断终止，不发accepted=false伪装业务拒绝，不重试 |

正常响应用原`发送响应`（已有no-store等），其socket写出不完整不撤销已经入列的输出、不重复调用提交。新路由没有exactly-once/跨请求幂等保证：同文两次明确操作是两条独立消息；断线、实际取消或2xx却JSON或id结构不符时，客户端必须标“提交结果不确定，可能已经入列”，不能假定未接纳。POST不设置自动等待超时。

## 4. 页面、来源分账与不确定性

原交互输入区保留，仍POST messages；新增独立`output-form`、`output-input`、按钮“控制台提交输出”、`output-receipts`列表和“不确定后新建”确认控件。输出区显著提示“操作员供稿，写入当前窗口正式输出队列；不是交互入站、不是自我自主意图，不生成需求或本能动作”。固定说明历史assistant仅表示出站方向、不证明内容自主生成；不得把所有assistant消息改标为控制台。

采用窄来源形状：不改公开消息DTO、消息JSON、`处理定向取件`、传输提交结构或world特征。只在当前页JS内保存每次明确操作的正文快照、202取得的submissionId及后续状态，列表标“控制台提交（操作员供稿）”。正文快照与该回执一一对应、创建后不随textarea编辑改变；它是当前UI操作显示，不是第二消息事实仓。状态GET不标注来源。刷新/重开页面会失去该非持久回执列表、生成新UUID，不删除正式事实，不自动恢复/重放提交，也不能据列表为空称未发送。

提交按钮在初始无UUID、页面尚未登记、POST在途、已关闭或有未确认的不确定提交时禁用。提交前JS以TextEncoder核正文UTF-8字节长度，非空且不trim；服务器校验仍是最终门。点击时先禁用并建立“处理中，不重复提交”条目，仅一次fetch；不设置自动POST超时，AbortController仅支持close/pagehide取消客户端等待，不取消正式队列。在途持续显示处理中并禁止重复提交。收到完整合法202才清空对应输入并显示“已入队”；明确拒绝保留正文及状态，不自动再次发送。未知结果保留正文/条目并锁住新提交，必须勾选“我已核对，知道新提交可能重复”后，由用户再次明确点击提交才作为新输出；该行为不称原请求重试或补偿。任一自动轮询/恢复/页面显示不得调用POST。

原750ms消息轮询继续GET outbound再GET messages；其成功完成现页登记后设置页面就绪。新增`outputRefreshStates()`只查询已有正式id且非终态的回执条目，可串行复用该轮询，不重入、不触发入列；只读查询允许客户端等待上限，查询超时或失败保留上次已知状态另示“本次查询失败”，不把已入队改为未发送。`已完整写出`显示“完整HTTP已写出；不证明对方阅读/理解”，`写出未完成`显示“可能部分写出，不自动补发”，`已取消`沿停止事实，不混淆失败/撤销。输出区不依赖业务快照是否已取得，不调用自然语言/服务认证。

状态查询和提交的AbortController在close/pagehide时取消、禁用输出操作、停查询/轮询；不得在pagehide/sendBeacon补发或取消队列。正常“结束”仍调用原close，由宿主正式停止接纳、清空已排队消息及正常收尾。仅取消浏览器请求不等于队列取消。网络断开/关闭可能使最后一次POST结果未知，原关闭链保留已发生事实。

新增JS函数精确为`outputRefreshStates()`（只读GET）、`renderOutputReceipts()`（只用textContent重绘本页回执）；`output-form`的submit/change处理器完成第4节单次提交和明确未知确认。直接修改的原`refresh/poll`只接就绪与只读状态轮询，原close/pagehide处理器只补输出停止/Abort，不能改输入业务含义。JS网络错误依第4节保留未知/上次状态；响应结构/DOM不变量异常显式显示控制操作界面错误并禁用受影响操作，不伪装正式入列/发送成功。没有本地文件写日志或后台隐式POST。

HTTP新handler不持任何宿主/队列锁调用既有公开提交或查询，避免再次锁同一非递归mutex。既有提交/查询的锁序仍为`队列操作互斥→共享状态.互斥`；入列回调期间释放共享锁，再进入模块锁→world外设锁。不能持共享锁跨回调、获取应用上下文锁或反调业务owner。正式提交原锁内同时核当前会话、停止指针/接纳、页面存在和null占用相等；之前的UI就绪/Origin校验不代替它。

宿主网络循环目前同线程串行处理HTTP，新handler不创建线程，不持页面指针跨调用/锁，也不创建新租约。停止若先于正式提交线性化则拒绝；提交若先完成则原关闭可能取消尚未领取项，已领取/已完整写出不重新排入。新状态读取借用现宿主租约，未运行/失效明确返回。回调和world寿命、queue清空、会话结束、上下文停止/join均沿原模块，无绕开join、detach或清除外设事实的路径。
