状态：合同已冻结；可进入代码实施

代码事实基线：`e8b463e33944d33c558956b87895a5a2d2d98905`

## 1. 目标与边界

在已有 `海中鱼巣.业务.应用服务.世界树类` 中增加一个 ARCH-L3 语义操作：向已经构造绑定并按指定事实代次验证的现实世界场景闭包内，在一个已有父场景下创建新场景并接纳。应用服务只组合新数据服务 `场景类数据服务::创建并接纳场景`，不直达 L1，不调用旧 `服务.L2*`，不拆分为两次写入，不做补偿删除。

本叶不把“构造时绑定的现实世界根场景”提升为 4200 第 3.1 节的持久唯一现实根、显式根标记或具名树归属。现有新场景模块只能验证“绑定候选根无父 + 可遍历闭包”；因此本叶只交付新旧并行数据操作下的应用根闭包语义。持久具名树身份仍是后继 provider 缺口，不是本叶隐含完成项。

不改动已有移动 ABI 及其历史语义；不实现存在创建、内部世界、需求/任务视图、状态/动态发布、特征事实集合或生产装配。

## 2. 当前能力与复用裁决

- `验证现实世界根` 是指定非零代次的 current-only 整树读；成功可证明绑定根闭包和父场景当前成员性。
- `场景类数据服务::创建并接纳场景` 先读同幂等身份的首次写材料；命中时按原始写集重放并按首次发布代次历史读回，未命中时才以创建期望代次读父场景并提交“新场景 N + 父接纳边 E”一个 owner 写集。这是本叶唯一写 provider。
- 应用请求分离 `创建期望事实代次 G0` 和 `观察事实代次 Gread`。初次只允许 `Gread == G0`，且必须验证整树、父场景在闭包中并为新节点预留一个数量配额。
- 重放只允许 `Gread >= G0`。`Gread > G0` 时，必须先通过同代次数据服务读结果证明 Gread 是本次 current 截止，才能把原 G0/幂等身份/父场景交给 provider。这利用代次单调性保证：若没有首次材料，provider 对旧 G0 的首次写必因代次漂移而不发布；若有材料，则能恢复原历史结果。
- “观察代次已证明”只有一个白名单：`验证现实世界根`返回头必须满足 `合同版本 == 世界树应用合同版本`、`事实代次 == Gread`，且（a）状态为 `已验证现实根`、`成功()==true`并有完整现实结构；或（b）状态恰为 `现实根未找到`、`现实根已退出`、`现实根不是结构根`、`世界结构预算不足` 四者之一，`成功()==false`且现实结构为空。其他任何状态，包括 `世界结构不一致`、`事实代次漂移`、`历史材料已清理`、`资源失败`、`内部不一致`或坏头，都不能证明 Gread。这一白名单直接依据当前 `世界树应用服务::验证现实世界根`：它把 `场景类数据服务::查询场景树` 的同代次头带回，并将未找到/已退出/非根/数量预算分别映射为上述四个确定性状态；而结构不一致分支可能来自坏版本、坏代次或坏载荷，所以明确排除。无法证明时不调用 provider，返回“无法确认”结果；不宣称没有历史发布。

不为本叶增加场景 provider 写入入口。全任意根损坏或根读资源失败下的无前置重放，仍需日后提供“当前代次可信读取”或“按幂等身份读首次结果”的公开数据服务能力；本叶不猜测、不直达 L1。

## 3. 冻结 ABI

保持 `世界树应用合同版本 = 1` 和现有数值不变，只追加：

```cpp
enum class 世界树应用阶段 : std::uint8_t {
    // 0..3 保持不变
    场景创建接纳 = 4,
    现实树创建确认 = 5
};

enum class 世界树应用状态 : std::uint8_t {
    // 1..27 保持不变
    已创建并纳入现实世界 = 28,
    既有创建已被后继事实覆盖 = 29,
    观察代次无法确认 = 30
};

struct 世界树场景创建请求 final {
    std::uint32_t 合同版本 = 世界树应用合同版本;
    std::uint64_t 创建期望事实代次 = 0;
    std::uint64_t 观察事实代次 = 0;
    L1所有者范围写入幂等身份 创建幂等身份{};
    稳定编码 父场景{};
    std::uint64_t 最大场景数量 = 0;
    friend bool operator==(const 世界树场景创建请求&,
        const 世界树场景创建请求&) = default;
};

struct 世界树场景创建重试材料 final {
    std::uint64_t 创建期望事实代次 = 0;
    L1所有者范围写入幂等身份 创建幂等身份{};
    稳定编码 父场景{};
    friend bool operator==(const 世界树场景创建重试材料&,
        const 世界树场景创建重试材料&) = default;
};

struct 世界树场景创建投影 final {
    稳定编码 现实根场景{};
    稳定编码 父场景{};
    稳定编码 新场景{};
    稳定编码 接纳关系{};
    std::uint64_t 首次发布事实代次 = 0;
    std::uint64_t 确认事实代次 = 0;
    friend bool operator==(const 世界树场景创建投影&,
        const 世界树场景创建投影&) = default;
};

struct 世界树场景创建结果 final {
    世界树应用状态 状态 = 世界树应用状态::入口拒绝;
    std::uint32_t 合同版本 = 世界树应用合同版本;
    世界树应用阶段 阶段 = 世界树应用阶段::无;
    std::uint64_t 请求观察事实代次 = 0;
    std::uint64_t 本次确认事实代次 = 0;
    std::optional<std::uint64_t> 已发布事实代次;
    std::optional<世界树场景创建重试材料> 重试材料;
    std::optional<世界树场景创建投影> 投影;
    bool 成功() const noexcept;
};
```

新公开入口：

```cpp
世界树场景创建结果 创建场景并纳入现实世界(
    const 世界树场景创建请求& 请求) noexcept;
```

`成功()` 仅接受 `已创建并纳入现实世界` 或 `精确重复`，阶段必须为 `现实树创建确认`；投影、已发布代次和重试材料必须完整有效，投影首次发布代次等于结果已发布代次，确认代次等于结果本次确认代次，且确认代次不早于首次发布代次。其他状态均不是成功。

## 4. 算法与事务边界

### 4.1 入口与初次守卫

1. 校验合同、两个非零代次、`Gread >= G0`、有效幂等身份/父场景和非零数量预算；失败为 `入口拒绝`。
2. 以 Gread 调用现有根验证路径取得一次观察。`Gread == G0` 是唯一允许首次写的分支：根必须成功，父场景必须恰好在闭包内，并且 `已读场景数 < 最大场景数量`，否则在写前返回对应根/场景/预算失败。
3. `Gread > G0` 是重放分支。不用“父场景当前仍在闭包”拦截历史重放；但必须按第 2 节证明 Gread 当前性。无法证明时返回 `观察代次无法确认`，阶段=`现实树预读`，带回原重试材料，不调用 provider。

### 4.2 唯一写提交

逐字段构造 `场景类创建接纳请求{场景类创建接纳合同版本, G0, 创建幂等身份, 父场景}`，只调用一次 `创建并接纳场景`。应用层不生成幂等键，不自动重试，不缓存意图。

- provider 确定拒绝且未报告发布：按同名语义映射为入口、场景不在现实世界、代次漂移、幂等/引用冲突、历史清理、资源失败或内部不一致，无成功投影。
- provider `已可能发布` 或调用抛异常而已进入 provider 提交时点：返回 `结果未知`，阶段=`场景创建接纳`，保留原重试材料；不宣称零发布或自行撤销。
- provider 返回 `已创建并接纳` 只能出现在首次分支；在已证明 `Gread > G0` 的重放分支出现该结果是不可信声称，返回 `结果未知`并保留其报告的发布代次和原意图。
- provider `精确重复` 必须返回与原父场景/幂等意图相符的完整历史投影，否则为 `内部不一致`。

### 4.3 fresh 确认与收敛报告

1. 首次发布成功后，以 provider 返回的首次发布代次 Gpublish fresh 验证现实根；新场景必须在闭包中，其父场景和接纳关系必须与 provider 投影精确相符。只有该读回完整闭合才返回 `已创建并纳入现实世界`。
2. 精确重复后，以本次 Gread 再做一次 fresh 根读，不复用 provider 前的预读当最终证据。若其成功且新场景仍在原父场景下，且 `Gread >= Gpublish`，返回 `精确重复`。
3. fresh 读成功但新场景已不在原父场景下，返回 `既有创建已被后继事实覆盖`；带历史投影、首次发布代次和本次确认代次，但 `成功()==false`。
4. provider 已返回确定首次/重复投影，但最终根读因代次漂移、预算、资源或结构问题无法闭合，返回 `已发布待复核`，阶段=`现实树创建确认`，保留已知首次发布代次、历史投影和原重试材料，确认代次为 0。调用方取得 fresh Gread 并放大纯读预算后，用原 G0/幂等身份/父场景重试即可收敛。
5. 首次写前已要求 `已读场景数 < 预算`，避免“当前刚好满预算”造成可预见的写后读失败。重放时预算只影响应用层纯读，不进入 provider 原始写入意图，允许调用方单独放大。

## 5. 状态映射与异常

14 个 `场景类创建接纳状态` 不允许执行者临场选择，固定如下：

| provider 状态 | 世界树结果 |
| --- | --- |
| `已创建并接纳` | 头和投影完整时进入 Gpublish fresh 确认，闭合后为 `已创建并纳入现实世界`；在 `Gread > G0` 分支为 `结果未知`。 |
| `精确重复` | 头和投影完整时进入 Gread fresh 确认，闭合后为 `精确重复`，被后继改变时为 `既有创建已被后继事实覆盖`。 |
| `入口拒绝` | `入口拒绝` |
| `父场景未找到` | `场景不在现实世界` |
| `父场景已退出` | `场景不在现实世界` |
| `子场景关系类型未找到` | `引用冲突` |
| `子场景关系类型已退出` | `引用冲突` |
| `事实代次漂移` | `事实代次漂移` |
| `幂等冲突` | `幂等冲突` |
| `引用冲突` | `引用冲突` |
| `历史材料已清理` | `历史材料已清理` |
| `资源失败` | `资源失败` |
| `内部不一致` | `内部不一致` |
| `已可能发布` | `结果未知`；带原重试材料，不设 `已发布事实代次`、不带投影。 |

对两个 provider 成功枚举再固定头/投影错误边界：若 `合同版本 == 场景类创建接纳合同版本` 且 provider `事实代次 != 0`，但 `成功()==false`、投影缺失/无效或父场景与原意图不符，返回 `已发布待复核`，保留该 provider 代次为 `已发布事实代次`和原重试材料，但不带不可信投影。若合同版本错误或 provider 代次为 0，则连发布代次都不可信，返回 `结果未知`，只保留原重试材料。漏列的未来枚举为 `内部不一致`，无发布声称。

进入 provider 调用前的异常按资源/内部失败且无发布声称；进入 provider 后无法知道提交结果的异常必须是 `结果未知`；已收到头完整的确定 provider 成功后发生的投影整理或读回异常必须是 `已发布待复核`。三者不得混同。
