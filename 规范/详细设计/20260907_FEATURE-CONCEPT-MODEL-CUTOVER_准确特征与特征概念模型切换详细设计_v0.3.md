## 1. 目标、继承与本轮边界

本版本是 v0.2 的原目标后继。v0.2 未被本文件明确改写的准确 F、I64 类型域、FT 共享观察、C/DAG、名称、旧 v1 派生治理、Gread/H 读取、错误映射、旧 ABI 物理删除边界全部继续有效；本文件只补齐名称历史读取边界、场景成员值式合同、EC 新依据绑定和漏消费者白名单。不得把这些补充解释为新增 L1 能力、跨 owner 原子事务或生产装配已完成。

完成条件仍是：准确 F、共享观察、C 与直接消费者在同一代码切片中形成可编译闭合；旧符号及直接调用清零；非成功保留原请求或具名零载荷；隔离 Debug/Release 编译通过。编译、计划登记或提交均不证明运行、恢复、生产接线或业务验收。

正式依据为 1130 v1.1、4110 v1.1、2100 v0.14、4120 v0.8、4180 v0.9、7160 v0.2、7140 v1.6、7150 v0.3、7110 v1.5、1140 v1.1、4230 v0.34、4240 v0.24、1120 v0.8、1180 v0.7、2220 v1.12、4015；不得以施工记录、验证记录或聊天事实扩大机器语义。

## 2. 当前事实和不变裁决

`特征类数据服务`仍是准确 F 与标量域唯一 owner；`概念树类数据服务`仍是 C、观察、名称、依据和治理唯一 owner；`特征概念应用服务`只做编排，不拥有 F/C/E 事实；`存在类数据服务`拥有 E 当前采用。准确 F 不含历史值、域、计数、宿主或 E 状态。F/C/E 不组成跨 owner 原子事务，各自发布自己的事实代次和读回 H。

`世界树类.ixx` 当前仍直接消费已退役的特征引用读取状态；它必须随本后继列入白名单，迁移为存在类自有历史读取状态映射，不恢复特征兼容别名。执行者必须先重新登记该文件并完成全部直接消费者扫描；发现其它消费者必须在同一白名单中完整列出，不能以编译失败逐个扩边界。

## 3. 共享名称读取：有限当前投影

名称读取不提供未界定的历史全枚举。公开请求与结果保持概念树读取头的 Gread/H 合同，选择只有以下两种 DTO，物理字段顺序固定：

```cpp
struct 特征名称按特征读取请求 final {
    std::uint32_t 版本 = 2;
    概念树读取头 读取头;
    特征信息身份 F{};
    概念树预算 预算;
    friend bool operator==(const 特征名称按特征读取请求&, const 特征名称按特征读取请求&) = default;
};
struct 特征名称按概念读取请求 final {
    std::uint32_t 版本 = 2;
    概念树读取头 读取头;
    概念树概念身份 C{};
    概念树预算 预算;
    friend bool operator==(const 特征名称按概念读取请求&, const 特征名称按概念读取请求&) = default;
};
```

概念树类唯一提供：

```cpp
概念树应用读取结果<std::optional<特征名称事实>>
读取特征当前名称(const 特征名称按特征读取请求&) const;
概念树应用读取结果<std::vector<特征名称事实>>
读取概念当前名称(const 特征名称按概念读取请求&) const;
```

按 F 在 H 视图中返回 0 或 1 条有效名称；按 C 返回 H 视图中全部有效名称关系，按关系稳定编码升序。每条回显其真实生命周期（包括已经在 H 后退出的退出代次字段），但本读取不扫描或推断 H 之前未指定关系的历史集合。空结果是成功空载荷；坏合同、零身份、G0 漂移、资源失败、许可拒绝和内部闭包错误均按现有概念树读取状态返回零载荷。多名称不得取首项，必须返回多义/内部不一致。删除旧的“包含退出项”请求字段、C 反查历史全枚举承诺、任何新 L1 入口、字段或账。

F、C、E 串行发布。C 或 E 未确认时，继续材料只能保存并重放完整 `场景成员概念请求_v2`；不得用临时推断字段、线程槽、日志或聊天恢复。失败分账为入口/合同、G/H 漂移、未找到、历史不可用、资源、许可、引用冲突、多义、预算不足、内部不一致、已可能发布；失败不得伪称跨 owner 零写，也不新增持久恢复账。

## 5. EC 抽象依据关系

新 24 角色中角色 16 是“C→形成依据记录”，角色 17 是“形成依据记录→目标”。EC→EC 依据不得复用旧共享角色槽。在 `概念树类数据服务` 的唯一可选装配交付中新增：

```cpp
struct 概念树存在扩展交付 final {
    稳定编码 抽象依据目标关系类型{};
    friend bool operator==(const 概念树存在扩展交付&, const 概念树存在扩展交付&) = default;
};
```

交付必须显式绑定关系类型，并由 EC 创建、读取、图展开、反向保护、退出、释放和原键恢复全链使用。基础来源成员、来源事实截止和依据记录仍复用现有 owner；每个依据记录单独保存来源 EC 与目标 EC，禁止从旧数组或旧位置推断。合法装配可以显式交付旧共享布局中的真实节点以保留存量 EC 布局，但不得将其解释为新角色，也不得恢复旧 FC 生产。缺少该交付时，相关 EC 能力返回具名“不支持”，不宣称生产装配已交付。

## 6. 预算、父组和错误边界

存在当前采用预算尾增固定为 `存在类数据状态::数量预算不足 = 29`，既有 1..28 不重排。预算字段物理顺序继续按 v0.2，超限返回数量预算不足、零采用写入；不截断、不丢旧事实。创建新 C 的 `子父替代[].新父组` 只列除本次新 C 外仍保留的已发布父；provider 同笔隐式加入本次新 C 身份；独立组织请求必须给完整已发布最终父组，禁止零身份占位。

所有旧错误映射继续逐项保留；F/C/E 分层错误不合并。可能已发布保留完整原请求和已确认见证，不能生成空稳定编码或伪造正式读回事实。
