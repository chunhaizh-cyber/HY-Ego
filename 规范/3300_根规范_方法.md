## 1. 根定位

方法是自我可执行动作及其用途，以及该动作在不同条件下会对相关对象的相关特征产生何种结果的长期能力知识。

方法不是：

```text
任务
一次执行
任务步骤列表
运行回执
日志摘要
名称
函数指针
本轮参数
本轮运行场景
本轮结果
正式结算记录
```

方法回答四个核心问题：

```text
做什么动作？
    → 方法动作

这个动作主要用来做什么？
    → 方法用途

在不同条件下会产生什么变化？
    → 条件结点 → 结果结点

这个方法自身现在处于什么状态？
    → 方法虚拟存在
```

全局架构中，方法的长期知识、任务路径、实例、结果和治理关系属于 `ARCH-L4` 业务治理；本规范中的现有 `L2方法结构` 仅是迁移期间保留的 ARCH-L4 结构记录面兼容实现名称。方法虚拟存在不是世界存在，也不是 ARCH-L2 通用状态/动态的第二 owner。方法状态、动态和虚拟宿主后继必须复用 ARCH-L2 公开结构，由方法业务 owner 只保存业务引用与治理关系；本规范不因此新增任务/方法业务判断到 DATA-L2。

方法结构记录面只保存、读取和校验调用方已经裁决的方法身份、动作绑定、用途、条件、结果、规格、版本、生命周期、幂等和引用闭合；方法业务应用面负责召回后的适用判断、方案选择、授权、执行、结果解释、生命周期推进和成功判定。记录面不得因方法结构存在、投影命中或结构写入成功推出方法适用、已授权、已执行或成功。

形式化表达：

```text
方法 M
├── 方法头 H
│   ├── 方法动作 A
│   ├── 方法用途 U
│   └── 方法虚拟存在 Vm
│
├── 条件 C1
│   └── 结果 R1
├── 条件 C2
│   └── 结果 R2
└── ...
```

方法长期知识只允许三类方法信息结点：

```text
方法头结点
条件结点
结果结点
```

其它内容只能作为：

```text
关系
引用
版本
当前性
方法 owner 的治理状态
动态证据
规格材料
动作入口
运行实例
学习候选
值式能力投影
```

存在，不得扩张成第四类方法长期知识结点。

## 2. 方法长期能力与运行实例分账

必须严格区分：

```text
长期方法
    = 可复用能力知识

任务方法路径
    = 某任务某一筹办轮次形成的具体可达方案

实例方法
    = 某任务某一执行轮次真正准备执行的不可变快照

方法运行事实
    = 某一次具体执行产生的运行记录和结果证据

练习材料
    = 从已有方法真实运行事实中提取的复验与稳定性材料

学习候选
    = 根据运行、尝试或因果反推证据形成的候选新知识

新方法代际
    = 通过正式学习晋级后发布的新的长期能力版本
```

禁止：

```text
把实例方法当长期方法
把一次运行结果直接写回长期方法
把任务参数写入方法头
把自我现实执行授权写入方法头
把任务状态写入方法虚拟存在作为共享任务状态
把练习统计直接当作稳定能力事实
```

一个长期方法可以被多个任务复用。

每个任务自己的：

```text
参数
自我现实执行授权（仅实例冻结含现实改变步骤时）
输入
条件冻结
运行态
结果
结算
```

必须留在任务方法路径、实例方法或任务运行结构中，不得污染共享方法长期知识。

## 3. 方法头结点

方法头结点是一个方法的稳定身份和组织入口。

方法头至少负责：

```text
方法身份
方法动作
方法用途
方法虚拟存在关系
内容版本
生命周期
条件结点关系组
结果结点关系组
```

方法头回答：

```text
这是哪个方法？
做什么动作？
主要用于改变什么？
```

方法头不得保存：

```text
某一次任务输入
某一次任务参数
某一次自我现实执行授权
某一次执行结果
某一次任务状态
某一次任务运行场景
某一次结算结果
```

具体能力和执行语义必须回到：

```text
方法动作
方法用途
条件
结果
条件结果关系
规格关系
当前版本
当前性
```

## 4. 方法动作

方法动作是该方法真正调用或组织的可执行动作。

动作必须使用稳定动作身份或正式动作入口引用，不得以：

```text
函数指针
显示名称
日志文本
局部枚举序号
语素文本
字符串
```

作为长期方法知识的唯一动作证明。

方法动作属于方法头的正式引用，但动作入口本身不构成第四类方法知识结点。

若动作域拥有独立动作入口结构，则方法头引用：

```text
正式动作入口身份
```

若当前工程仍使用稳定动作键，则稳定动作键只能作为：

```text
动作绑定合同中的稳定引用材料
```

不得因为动作键存在就跳过正式绑定、版本和当前性检查。

### 4.1 方法作用范围与现实副作用

每个方法内容版本必须按实际动作效果声明闭合的作用范围：

```text
仅内部治理
现实观察
现实改变
```

`仅内部治理`只改变自我内部治理事实；`现实观察`只读取现实并形成内部材料；`现实改变`包含任何预期或可能改变外部对象、外部主体、外部系统、物理环境或受保护资源状态的动作。一个方法可以包含多类步骤，但必须逐动作声明，不能用方法总标签隐藏现实改变。主动探测、设备运动、发射、外部通信、写外部系统或其它具有现实副作用的观察步骤，按现实改变步骤冻结。

作用范围是方法能力合同的一部分，不是本次执行授权。内部治理和纯现实观察不需要自我现实执行授权；含现实改变步骤的实例方法只有在任务筹办完成，并经过执行前选择、实例化和执行冻结后，才由任务管理向自我请求一份同时绑定任务、任务轮次、筹办轮次、执行轮次、冻结、实例方法和现实动作范围的授权。方法 owner 不发布该授权，也不声明第二份“方法授权”。

## 5. 方法用途

方法用途表示：

> 这个方法通常为了作用于什么对象、改变什么特征、朝什么方向形成什么类型结果而被召回。

最小用途语义：

```text
目标对象角色 / 类型
目标特征
期望变化方向
结果类型
```

用途是能力概括，不是某一具体条件下的实际结果。

用途主要用于：

```text
粗粒度方法索引
候选扫描范围缩小
目标特征 / 方向 / 结果类型初筛
```

用途不能替代条件结果知识。

不得仅因为方法用途与任务目标部分相符，就直接认定：

```text
当前方法是正式候选
当前条件成立
当前可执行
当前结果一定产生
```

## 6. 方法六项静态能力描述

### 6.1 定位

方法六项静态能力描述用于完整表达一份方法结果在其条件、输入规格和限制下的能力：

```text
输入条件
目标对象类型
可改变特征类型
变化方向
结果类型
限制条件
```

六项静态能力描述是从现有正式方法结构形成的值式复合投影，不是第四类方法长期知识结点。

### 6.2 六项来源

六项来源固定为：

| 能力项 | 正式来源 |
| --- | --- |
| 输入条件 | 条件结点、输入规格及其正式关系 |
| 目标对象类型 | 方法用途、条件和结果中的作用对象角色 / 类型约束 |
| 可改变特征类型 | 方法用途和结果结点的特征定义 |
| 变化方向 | 方法用途和结果结点的统一三态方向 |
| 结果类型 | 结果结点、目标状态 / 动态合同和正式结果规格 |
| 限制条件 | 条件、禁止项、适用范围、规格和安全限制的正式关系 |

不得把六项压成：

```text
方法名称
一个分类标签
一个万能能力字符串
一个无来源哈希
一个永久 bool
```

### 6.3 六项投影的使用边界

六项投影只证明该方法当前结构能够形成一份完整、可追溯的静态能力描述。它用于方法结构检查、候选适用性复核、后继当前就绪和学习证据；任务查找方法时不得预造输入条件或限制条件并与投影六项逐项相等。

不证明：

```text
当前条件成立
动作入口当前
输入和参数已经绑定
禁止项未命中
验证和归因合同完整
当前能够执行
当前一定达成目标
```

## 7. 条件结点

条件结点表示：

> 会使同一方法动作产生不同结果的状态条件或限制条件。

条件结点不是所有运行约束的杂物箱。

一个条件结点至少应能够表达：

```text
作用对象角色 / 类型
场景 / 适用上下文
特征
条件状态合同
输入角色
来源
版本
生命周期
```

条件核心职责是区分：

```text
相同动作
+
不同前置状态
=
不同结果
```

如果多个状态条件必须共同成立，应由正式组合条件关系表达。

不得把组合条件真实语义塞入：

```text
显示文本
名称
字符串
普通 bool
```

后再由运行期临时解释。

---

## 8. 结果结点

结果结点表示：

> 在对应条件下执行方法动作后，相关对象的相关特征形成的方向性结果。

结果结点最小语义：

```text
作用对象角色 / 类型
结果特征
变化方向
结果类型
来源
版本
生命周期
```

变化方向采用统一三态：

```text
小于 0
等于 0
大于 0
```

或者其等价强类型：

```text
负方向
无变化
正方向
```

第一层结果不应把每一个实例数值变化都制造成新的结果类型。

变化量、速度、持续时间、频率、单位变化对应量等进一步差异，应进入：

```text
动态
动态二次特征
其它正式二次特征关系
```

而不是无限制造新的长期结果结点。

---

## 9. 结果等价与差异

方法知识中的“结果相同”首先以以下四项判断：

```text
作用对象角色 / 类型相同
结果特征相同
变化方向相同
结果类型相容
```

四项均成立，才属于同类方向结果。

以下情况属于不同结果：

```text
作用对象角色 / 类型不同
或
结果特征不同
或
变化方向不同
或
结果类型不相容
```

以下情况不应仅因数值不同就制造不同结果类型：

```text
同一对象角色 / 类型
同一特征
同一方向
同一结果类型
但变化量不同
```

这些差异进入：

```text
动态二次特征
条件细分
运行实例证据
练习与学习统计
```

而不改变根级结果分类原则。

## 10. 条件结果关系

条件和结果必须通过正式关系绑定：

```text
条件 C
→ 结果 R
```

该关系表达：

> 在该条件结构成立时，执行方法头中的动作，会产生该结果。

条件结果关系不是第四类方法结点。

若一个条件对应多个结果，可以建立：

```text
C → R1
C → R2
```

若多个条件共同描述一个结果，应保留各条件身份及关系，不得压成不可审计摘要。

条件结果关系必须能够回到：

```text
方法
条件
结果
来源
版本
当前性
生命周期
```

并能够与真实运行证据、练习证据和学习证据关联。

## 11. 方法规格与场景身份分离

方法条件和结果若涉及规格场景、目标特征、状态合同、作用对象、输入或输出材料，必须通过正式强类型关系承载。

必须区分：

```text
方法长期规格场景
任务本轮场景
运行期临时场景
实际输出事实
```

它们不得共用一个身份或互相覆盖。

名称、动作文本、函数名、语素文本、显示标签、候选命中和方法头本身均不得替代：

```text
规格
条件
结果
动作绑定
场景身份
```

或证明当前可执行。

具体规格 DTO、运行账和场景绑定细节由 4270、5300—5330 等下位规范冻结。

## 12. 方法虚拟存在

### 12.1 定位

每个方法必须对应一个唯一方法虚拟存在。

固定：

```text
方法 M
→ 唯一方法虚拟存在 Vm
```

方法虚拟存在：

```text
不是世界 L2存在
不进入世界树
不能由多个方法共享
不能被任务运行实例共享
```

### 12.2 状态承载

方法虚拟存在是方法自身 ARCH-L4 治理关系的虚拟宿主引用；方法当前治理状态的结构唯一权威由 ARCH-L2 通用虚拟存在、状态和动态服务承载。方法 owner 不得建立第二状态/动态 owner，也不得把方法治理枚举直接当作 ARCH-L2 结构身份。

它可以承载后天形成的：

```text
当前可用状态
熟练程度
使用证据统计
成功与失败证据统计
最近使用时间
学习状态
可靠性裁决
适用范围认识
其它后天形成特征
```

但这些内容不是方法头长期知识字段。

统计值只作证据或投影，不能单独证明：

```text
能力真实
方法可靠
方法当前可用
方法应被选中
```

正式能力与可用性仍需结合条件结果、运行证据、当前性和治理裁决。

### 12.3 任务状态不得污染方法虚拟存在

多个任务可以复用同一方法。

下列内容不能写进共享方法虚拟存在作为任务运行事实：

```text
某任务参数
某任务的自我现实执行授权引用
某任务当前路径
某任务实例输入
某任务执行冻结
某任务执行结果
某任务结算
```

这些必须留在各自任务、实例方法和运行账中。

## 13. 方法事实来源与能力知识来源

方法长期知识只能来自：

```text
方法领域正式登记
正式动作绑定
正式条件 / 结果登记
真实运行证据
合法练习、尝试和因果反推证据
合法候选晋级
正式新代际发布
```

不得从以下材料直接制造长期能力事实：

```text
名称
文本
日志
显示标签
函数名
候选命中
任务临时判断
单次成功
单次失败
```

方法条件、结果和能力关系必须具有：

```text
来源
版本
当前性
生命周期
证据
```

真实运行证据只能作为：

```text
练习
复验
尝试
因果反推
候选晋级
```

材料，不能未经学习治理直接覆盖长期方法知识。

以下内容只能由方法领域服务及其专用数据操作层正式写入：

```text
方法登记
方法头
方法动作绑定
方法用途
条件
结果
条件结果关系
方法虚拟存在关系
内容版本
规格版本
生命周期
当前性
方法治理状态
运行账
学习证据
稳定能力知识
新方法代际
```

以下主体不得绕过方法服务直接改写方法长期结构：

```text
任务
需求
学习动作本身
世界结构服务
线程
调度器
显示层
外部调用方
```

任务、学习动作和运行实例只能提交：

```text
候选

练习证据
尝试证据
因果反推证据
更新输入
```

最终长期知识是否发布必须经方法领域正式治理。

## 15. 生命周期、版本与当前性

方法生命周期、内容版本、规格版本、条件结果版本和动作入口当前性必须可以正式回读。

必须区分：

```text
方法身份
内容版本
规格版本
动作绑定版本
当前发布版本
历史版本
```

失效方法不得被当前召回。

旧版本可以保留历史，但必须与当前发布关系隔离。

方法状态、能力知识和学习代际必须具备来源、版本、生命周期和当前性。

不得：

```text
覆盖旧内容后丢失历史
把旧版本继续冒充当前方法
把历史动作绑定冒充当前动作入口
```

## 16. 方法与任务

任务允许拥有多条任务方法路径。

一个任务目标可以粗召回多个方法，并形成：

```text
0..N 条任务方法路径
```

但一轮执行只能选择：

```text
0..1 当前选中路径
0..1 当前实例方法
```

方法本体不保存：

```text
当前任务
当前任务参数
当前任务的自我现实执行授权引用
当前任务执行冻结
当前任务结果
```

这些属于任务方法路径、实例方法和任务运行结构。

方法不能自行创建任务或正式需求。

无方法、方法补齐、等待和学习需求由任务筹办与需求治理共同裁决。

## 17. 方法召回、适用判断与就绪复判

### 17.1 第一层：粗召回

任务筹办粗召回只使用需求目标的特征定义，查询当前方法用途中声明的`可改变特征类型`并有界缩小扫描范围。ARCH-L4 结构记录面返回命中用途及其方法身份，不判断对象、方向、结果、条件或任务适用性。

粗召回只证明：

```text
可能相关
```

不得按名称、函数名或分类标签形成语义命中。

### 17.2 第二层：对象、方向与结果能力兼容判断

ARCH-L4 业务应用面任务筹办对粗召回项读取同截止完整方法投影，并按任务当前材料判断：

```text
用途 / 结果的对象类型是否兼容目标宿主全部当前合法概念
用途 / 结果的变化方向是否等于正式比较形成的所需方向
用途 / 结果的结果类型是否兼容目标状态合同
用途、结果、作用对象角色和内容版本是否互证
```

对象类型兼容必须依据当前概念支持及存在本体根下的当前上位闭包；零概念不猜默认，多概念按并集保留。当前首版目标状态结果能力要求状态合同身份精确相同；动态概念结果不冒充状态合同结果。任一项不兼容不得进入适用候选，但方法自身的结构缺口必须与“没有相关方法”分账。

### 17.3 第三层：全部候选的条件组核验

找方法范围完整且有候选后，任务筹办逐候选读取其条件、条件结果关系和条件组，并在 fresh 正式事实截止核验每组当前具备性。不得预选方法，不得只查第一条候选或第一组已具备条件，也不得由此扩张需求树。

### 17.4 第四层：执行前选择的当前复判

执行前选择对全部已完成条件核验的候选复判：

```text
方法生命周期和内容版本当前
真实动作入口当前
条件和条件结果关系完整
当前条件成立
输入与参数绑定闭合
禁止项未命中
作用范围、现实副作用和安全限制合同完整
验证和归因合同成立
相关状态与因果证据仍当前
```

只有某一执行选项全部闭合且在可比较候选中综合代价最小，才可形成一条当前任务方法路径。

### 17.5 禁止降级

不得：

```text
把特征粗召回命中当适用候选
把适用候选或方案采用当当前就绪
把当前就绪当已经选中
把已经选中当已经执行
```

### 17.6 C031 分阶段筹办与执行前选择分离

筹办先在找方法状态执行第 17.1 的有界查找；方法范围完整后，再在查条件状态逐候选读取条件组并核验当前是否具备。筹办不把任何候选命名为`已采用方案`，不比较代价，不形成路径或冻结。

条件组以方法内容版本中已声明的组合条件关系和绑定材料为唯一来源。组内共同成立、组间可替代或其它组合语义必须由该方法合同显式表达；任务侧不得以名称、顺序、哈希或条件数量补造语义。无法形成强类型组投影时是结构缺口，不是空候选、合法选择或新需求。

对象 / 方向 / 结果适用性、实际采用、禁止与风险、运行质量及总代价比较统一在执行前选择中针对一个`方法 + 内容版本 + 条件组 + 绑定`选项进行。该入口必须 fresh 复核筹办时的条件结果和当前可用性，不能把方法结构服务的稳定排序当成选择结果。

## 18. 无候选方法边界

无可匹配方法不得自动准入或补造：

```text
创建方法首
创建空方法
把通用底层原语直接冒充语义方法
把分类标签冒充方法
把任意动作入口包装成方法
建立长期能力缺口节点
```

固定分流：

```text
特征类型有界粗召回完整为空
→ 方法能力缺失裁决
→ 正式学习门禁全部满足时形成学习需求候选，否则合法等待

粗召回非空且对象 / 方向 / 结果能力判断完整结束、全部项均不适用
→ 当前无适用方法裁决并保留逐候选不兼容证据
→ 合法等待，不形成学习需求候选

已有候选但具体结构不完整
→ 方法补齐承接

条件、输入或外部事实暂时不满足
→ 合法等待或独立子目标候选
```

无候选方法时不得直接进入练习，因为练习必须具有既有方法和真实动作入口。

后继学习任务可以根据已有动作和因果材料选择：

```text
尝试
或
因果反推
```

```text
当前内容版本
方法动作
动作入口当前性
方法用途
特征粗召回、对象 / 方向 / 结果兼容判断和方法自身六项投影

必要规格

```

若执行前选择已经把某个选项判为可用并形成冻结后，执行期才发现冻结前已经存在的：

```text

```

则属于：

```text
执行前选择漏检
或

```

不得包装成：

```text

普通任务失败
合法等待
新需求
学习需求
```

## 20. 方法运行事实与长期知识分账

一次方法执行只能形成本轮运行事实和证据。

固定：

```text
方法运行成功
→ 本轮方法运行合同成功事实

方法运行失败
→ 本轮运行失败证据
```

二者都不能直接改写长期方法知识。

长期方法知识更新必须经过：

```text
运行证据
→ 练习 / 尝试 / 因果反推分析
→ 学习候选
→ 独立评估 / 晋级
→ 新代际发布
```

不得：

```text
一次成功 → 直接提高长期能力为事实
一次失败 → 直接删除长期方法
运行实例 → 原地修改旧方法
```

## 21. 普通任务天然形成练习材料

普通任务使用已有实例方法执行时，天然形成该方法的一次练习材料。

练习材料至少可以来自：

```text
任务与实例方法身份
方法内容版本
执行轮次
条件与输入
参数
动作入口
场景和上下文
实际状态
动态证据
目标达成裁决
验证结果
偏差与失败材料
共同事实截止
```

普通任务执行的第一目标仍是现实目标，不因形成练习材料而改为学习任务。

学习旁路只读消费这些材料，用于：

```text
条件结果复验
可靠范围分析
稳定性材料
参数范围材料
新用途候选
方法缺陷证据
```

练习旁路不得：

```text
阻塞普通任务结果治理
修改本轮任务目标
修改本轮实例方法
直接写长期方法
直接形成安全值或服务值结算
```

只有为了主动探索已有方法的参数范围、稳定性或适用范围而专门组织活动时，才建立学习任务或专门练习任务。

## 22. 学习类型

方法学习固定分为三类：

```text
练习
尝试
因果反推
```

不再把“定向学习”作为与三者并列的根级学习类别。外界未知现象的观察、确认和询问属于观察或信息获取能力，可以为尝试和因果反推提供材料。

### 22.1 练习

练习适用于：

```text
已有方法
已有真实动作入口
已有条件或条件结果结构
```

练习通过真实运行事实复验：

```text
条件
参数
结果
稳定性
可靠范围
适用范围
```

练习不创建动作，不建立空方法，不直接发布长期能力。

### 22.2 尝试

尝试适用于：

```text
已有自我动作或动作入口
但动作效果、参数范围或条件结果关系未知或不完整
```

流程：

```text
选择允许的参数 / 条件区间
→ 含现实改变步骤时经自我现实执行授权后真实执行；否则按冻结直接执行
→ 独立观察实际结果
→ 形成条件结果候选与参数材料
```

尝试不得执行无来源随机动作，也不得绕过任务冻结、安全硬否决和适用的自我现实执行授权边界。

### 22.3 因果反推

因果反推适用于：

```text
目标状态需要某种变化
当前没有可执行方法
但存在客观因果或可构造能力线索
```

流程：

```text
目标特征变化
→ 客观因果结果
→ 所需前置状态
→ 自我可产生状态或可借助工具
→ 可控动作链
→ 能力候选
→ 方法候选
```

因果反推只形成候选能力路径，不直接发布方法，不直接执行未经自我现实执行授权的现实改变动作。

工具能力可以进入组合能力候选，但必须保留：

```text
自我动作
工具身份
工具条件
环境因果
中间状态
最终结果
验证与安全边界
```

## 23. 方法候选晋级与新代际

方法学习必须严格区分：

```text
学习执行能力
学习候选
长期方法发布权
```

正式流程固定为：

```text
真实运行 / 练习 / 尝试 / 因果反推证据
→ 学习候选
→ 独立晋级判断
→ 发布不可变新代际
→ 新代际成为当前版本
→ 旧代际保留历史
```

新代际发布必须具备：

```text
来源证据
候选身份
方法身份
旧版本 / 新版本关系
版本
当前性
生命周期
幂等
```

具体晋级与同轮隔离由 5340 唯一冻结。

## 24. 新代际与任务回合同轮隔离

当方法学习产生新代际时：

```text
当前任务已经冻结的实例方法
```

不得在同一执行轮次被新代际偷偷替换。

固定：

```text
本轮实例继续遵守冻结版本
新代际只影响后续重新筹办 / 新实例化
```

如果任务需要利用新方法代际，必须：

```text
当前轮次结束 / 冻结失效
→ 重新筹办
→ 重新读取方法当前版本
→ 形成新路径
→ 形成新实例
```

不能原地修改已冻结实例。

## 25. 方法结果与任务、需求、结算边界

必须严格分账：

```text
方法运行成功
任务目标达成或未达成
任务轮次结算结果
任务轮次收束
任务生命周期结束
需求当前满足
需求正式结算
价值结算
```

固定：

```text
方法运行成功
    只证明本轮方法运行合同成功

任务目标达成
    必须由任务实际结果与目标三元组正式比较证明

任务轮次结果
    必须进一步具有验证、结果当前和轮次结算来源；目标未达成也是合法轮次结论

任务轮次收束
    必须由任务轮次结算完成证明；不等于任务生命周期结束

任务生命周期结束
    必须由轮次收束后的自我结束或取消后继决议及任务管理合法迁移证明

需求当前满足
    必须由当前世界事实与目标状态合同正式比较证明

需求正式结算
    必须由具体需求成员的来源、路径、证据、归因和预算规则形成

价值结算
    当前只承接正式主动安全结算；普通服务方法结果只形成任务结果、需求满足与状态 / 动态 / 因果证据，不形成服务值账
```

因此禁止：

```text
方法成功 → 任务轮次收束
方法成功 → 需求满足
方法成功 → 正式结算
学习完成 → 安全值或服务值变化
```

方法运行事实可以作为：

```text
任务结果证据
需求验证证据
练习与学习证据
结算归因证据
```

但不能替代这些上层裁决本身。

## 26. 事务、幂等与历史根原则

下位方法结构合同必须遵守：

1. 方法身份、方法头、方法动作绑定、方法用途、方法虚拟存在关系和必要基础关系必须按正式合同同代原子发布；
2. 条件、结果、条件结果关系按具名结构合同原子发布；
3. 方法当前版本只能有一个权威当前发布；
4. 旧版本退出当前后必须保留历史；
5. 当前组合读取必须共享共同事实截止；
6. 历史读取必须使用具名历史截止；
7. 同幂等身份 + 同完整请求返回精确重复；
8. 同幂等身份 + 不同完整请求返回幂等冲突；
9. 事实代次漂移必须零变化；
10. 发布未知只能用原幂等身份和原完整请求收敛；
11. 不得用名称、日志、缓存、当前线程、默认值补齐坏方法结构；
12. 身份复义、单例关系重复、错版本、跨代拼装或发布后读回矛盾属于内部不一致；
13. 新代际发布不得覆盖旧代际历史；
14. 已冻结实例不得被新代际原地改写；
15. 六项静态能力投影必须可由同一事实截止的正式方法结构重建，不得成为第二权威；
16. 精确重复运行证据不得重复发布同一学习候选或新代际。

- 把候选准入当当前就绪；
- 用最终实例数值替代方向性结果；

- 忽略作用对象角色 / 类型判断结果等价；
- 用方法用途替代条件结果；
- 仅凭方法用途证明当前可执行；
- 仅凭方法名称召回并认定可达；
- 无候选方法时自动创建方法首；

- 把底层原语直接冒充语义方法；
- 把分类标签冒充方法；
- 把任务运行参数写回长期方法头；
- 把任务状态写入共享方法虚拟存在；
- 用世界 L2存在 / 状态 / 动态身份承载方法治理状态；
- 把实例方法当长期方法；
- 用一次执行结果直接覆盖长期方法；
- 直接覆盖旧方法知识历史；
- 旧方法版本失效后继续作为当前版本召回；
- 执行冻结前不复核方法结构；
- 把筹办漏检包装成普通方法失败、需求或学习需求；
- 把外界信息获取单独固化成与练习、尝试、因果反推并列的学习根类别；
- 学习动作直接覆盖正式方法；
- 新代际原地替换已冻结实例；
- 用方法执行成功直接证明任务轮次收束或任务生命周期结束；
- 用方法执行成功直接证明需求满足；
- 用方法执行成功直接形成正式结算；

- 方法自行创建任务；
- 方法自行创建正式需求；
- 任务、学习、线程、显示层绕过方法服务直接改写长期方法。
