## 1. 定位

本规范冻结 `DATA-L2` 对场景、存在、特征、状态、动态和因果六类世界强类型结构的唯一所有权、共同 DTO、生命周期、依赖方向、事务、读取和退出边界。现行 C++ `L2*` 类型与服务名称保持真实 ABI，不因架构层显示名机械改名。六个公开服务内部共有场景、存在、特征定义、特征实例、状态、动态和因果七个节点族；每个节点族具有独立的 `DATA-L1` 技术 owner 和不可由普通节点形状替代的正式身份来源。

在全局命名空间中，六类结构属于 `ARCH-L2`，与 `DATA-L2` 一一映射；场景树和概念空间聚合属于 `ARCH-L3/DATA-L3`。ARCH-L2 不区分现实/虚拟调用者，后继任务、方法、概念和自我均经公开强类型接口引用本层。通用虚拟存在是本层新增的独立结构族；任务和方法现有私有虚拟存在、治理状态仅是迁移兼容事实，不能形成第二状态或动态权威。

六类世界结构不等于全部 `DATA-L2`。语言、词条和概念空间结构由 4240 另行承接；语素和词性当前不形成持久结构族。需求、任务和方法由其对象根规范及后继结构合同承接；这些结构既不改写本规范六服务职责，也不形成第七个“世界”数据服务。

六类名称具有结构类型语义：`DATA-L2` 知道节点和关系属于哪个正式世界结构族，并校验相应字段、端点、基数和生命周期；这不授予其判断现实世界、存在资格、特征意义、状态真实性、变化重要性、动作归因或因果真伪的权力。业务调用方位于 `DATA` 之外，先完成业务裁决，再提交本规范允许的完整强类型结构请求。

除4.4—4.5明确冻结的状态当前选择ABI外，其余结构不定义具体CRUD。后继实现只能细化本规范已经冻结的合同，不得建立第七个“世界”数据服务、第二写入入口或兼容业务解释层。

## 2. 共同身份、枚举与请求结果头

### 2.1 强类型身份

合同版本固定为 `1`。以下身份均为彼此不同的中文强类型，内部只承载一个非零 `稳定编码`，不得隐式转换、按名称推断或跨类型替换：

```text
L2场景身份
L2存在身份
L2特征定义身份
L2特征实例身份
L2状态身份
L2动态身份
L2因果身份
L2场景树身份
```

`L2场景树身份` 只在场景结构内使用，值等于该树根场景的稳定编码；它不增加第八节点族、独立树节点、独立 owner 或第七世界服务，也不得隐式转换为普通场景身份。建立根成功后由服务返回该身份，调用方缓存或函数参数本身不构成身份事实。

写请求使用独立强类型 `L2结构幂等身份`，其值为非零 `uint64`。它只标识一份完整 L2 结构请求，不是任一结构事实、业务对象或 L1 事实编码。

### 2.2 读取类别与结构状态

```text
L2读取类别：
  当前=1
  历史=2

L2结构状态：
  已提交=1
  精确重复=2
  已读取=3
  未实现=4
  入口拒绝=5
  许可拒绝=6
  未找到=7
  已退出=8
  属性未设置=9
  事实代次漂移=10
  幂等冲突=11
  引用冲突=12
  资源失败=13
  内部不一致=14
```

`已提交`、`精确重复` 和 `已读取` 通常是携带完整成功载荷的状态；登记读取 ABI 是明确例外：公共 `已读取=3` 与专用 `待迁移=4` 时载荷为空且成功否。其它状态不得携带部分结构、默认补齐结构或混代材料。任何单一公共状态都不得独立推出成功，成功性必须由公共结果头状态 × 专用状态 × 载荷组合共同判定。`未实现` 只供 4201 的最终合同骨架使用；真实入口完成后不得用它掩盖未覆盖分支。

合同版本不是兼容猜测字段。入口只接受版本 `1`；不兼容变化必须建立新的具名合同与 DTO 身份，并明确迁移或拒绝关系。

### 2.3 共同请求头与结果头

`L2结构请求头` 固定包含：

```text
合同版本
期望事实代次
```

写请求还必须包含绑定完整请求语义的 `L2结构幂等身份`。期望事实代次用于写前基线校验和同截止读取；不匹配时返回 `事实代次漂移`，不得返回混代载荷或产生数据变化。`事实代次漂移` 明确证明该完整请求没有取得首次结果、没有形成任何权威发布且没有绑定幂等身份；调用方重新正式读回后可以保留同一幂等身份并形成一份新完整请求。除此之外，资源失败、异常或发布结果未知均不能据此改写请求。

`L2结构结果头` 固定包含：

```text
合同版本
L2结构状态
事实截止代次
可选变更事实代次
```

成功读取的事实截止代次必须非零。成功写入的变更事实代次是本次原子发布的新代次；精确重复返回首次请求的原结果，不再次推进代次。交换前候选验证或提交失败才承诺整笔零写、零幂等账和零代次变化。L1 已确认提交或精确重复后的独立读回失败不得回滚；已形成事实、幂等账和变更事实代次必须保留，结果固定映射为专用“已可能发布”与公共 `内部不一致`，调用方以原幂等身份重放并经正式读回收束；登记 ABI 是例外：登记写/读回失败固定为公共 `内部不一致=14` + 专用 `内部不一致=9`，仅四字段提交见证、完整登记事实为空且成功否，不改回“已可能发布”。任何单一公共状态都不得独立推出成功，成功性必须由公共结果头状态 × 专用状态 × 载荷组合共同判定。没有发生变更的交换前结构化非成功不伪造变更事实代次。

### 2.4 七族 owner 与身份来源

七个节点族固定各有一个 `独占结构范围` 的 `L1结构所有者身份`，owner 两两不同：场景、存在、特征定义、特征实例、状态、动态和因果各一。场景、存在、状态、动态和因果服务各私有持有本族一份 `L1所有者范围写端口`；`L2特征结构服务` 是现行唯一的多结构公开服务，分别私有持有特征定义和特征实例两份端口。两端口 owner 必须不同；定义写函数只能使用定义端口，实例、宿主 / 定义关系和实例当前值写函数只能使用实例端口。不得合并成可选择 owner 的通用端口，不得交换、转签或形成跨两端口的混 owner 写集。

普通应用的唯一 provider 使用同一个 `L1事实基座运行包` 和唯一签发器，按“存在、特征定义、特征实例、状态、动态、因果、场景”的顺序建立 owner 并移动注入唯一服务实例。尚未进入有效实施范围的后继服务可以暂不构造，但已构造前缀不得改序、复用建立幂等身份或先交付服务再补 owner。该顺序只约束上层装配，不给 L1 核心增加 L2 枚举、分支、friend 或反向 import。

owner 是身份来源的第一层证明，但不能把同 owner 的关系类型节点、属性类型节点或内部登记节点冒充公开 L2 身份。每个节点族还必须在本族 owner 内建立一个不可变族锚点节点和一个不可变族归属关系类型节点。两者由本族服务的 provider 私有初始化路径在首个公开节点创建前建立并从 owner-aware 入口读回；定位副本只作非权威查找材料，丢失时不得扫描、猜测或补造。

每族初始化使用只属于该 owner 的固定非零建立幂等身份和完整写集幂等身份；七族数值域不得复用。精确重复必须回读首次锚点和关系类型编码，同键异写集返回幂等冲突。一个 owner 当前只能有一组来源登记；再次形成不同锚点、不同关系类型或第二活动登记属于内部不一致。锚点和关系类型的创建代次必须不晚于首个公开节点创建代次，生命周期覆盖全部本族公开节点及归属关系；它们不得在仍有当前公开节点、归属关系、未收敛幂等结果或历史 / 恢复引用时退出。

每个公开节点创建必须在同一 owner-scoped 写集内同时建立唯一族归属关系：

```text
源节点 = 本次公开节点
目标节点 = 本族族锚点节点
关系类型 = 本族族归属关系类型节点
角色或顺序 = 1
关系 owner = 节点 owner = 关系类型 owner = 族锚点 owner = 本族 owner
```

该关系不是节点到自身的自环，也不是业务拓扑、标签、索引、缓存或第二身份仓。L2 公开身份只在“精确本族 owner 事实 + 公开节点 + 指向精确本族锚点的唯一归属关系 + 精确本族关系类型 + 本族公开服务读回”共同成立时成立。普通稳定编码、强类型包装、节点种类、名称、本地键、属性 / 关系数量、节点到自身关系、缓存定位或 v1 无 owner 投影都不能单独证明任一 L2 节点族。

族归属关系固定只从公开节点指向锚点；锚点不反向指向成员，成员之间不因族归属增加边。场景、存在、特征、状态、动态和因果的业务 / 结构引用继续服从第 5 节单向依赖，因而身份来源不增加服务调用边、不形成同层循环依赖，也不要求低层服务反查全部消费者。

`L2结构公共.数据.h` 后继拥有闭合枚举 `L2节点族` 和值式 `L2节点族身份来源事实`。后者固定包含：节点族、节点稳定编码、`L1结构所有者身份`、族锚点稳定编码、族归属关系类型稳定编码、族归属关系稳定编码、角色或顺序，以及 owner、节点、族锚点、关系类型和族归属关系五份生命周期。共同 DTO 只表达证明材料，不公开端口、owner 选择、L1 本地键或写集，也不提供通用跨族读取服务。

每个专属数据头分别拥有本族强类型 `身份来源读取请求 / 结果`；特征数据头拥有定义和实例两套。请求包含 `L2结构请求头`、读取类别、对应强类型身份和历史截止，结果包含 `L2结构结果头`、读取类别、历史截止和可选 `L2节点族身份来源事实`。七个唯一公开 const 函数固定为：

```text
L2场景结构服务::读取场景身份来源
L2存在结构服务::读取存在身份来源
L2特征结构服务::读取特征定义身份来源
L2特征结构服务::读取特征实例身份来源
L2状态结构服务::读取状态身份来源
L2动态结构服务::读取动态身份来源
L2因果结构服务::读取因果身份来源
```

身份来源当前读取必须在一次 owner-aware 一致当前投影内核对 owner 事实、公开节点、精确锚点、精确关系类型和唯一归属关系，并使全部项目共享请求的非零期望事实代次。身份来源历史读取以具名历史截止读取 owner 事实、三个节点事实和归属关系事实，隐藏晚于截止的未来退出，在读取前后复核当前事实代次未漂移；owner 在节点创建截止无效、提前退出或复义均为内部不一致。截止早于节点创建返回 `未找到`，截止达到创建后返回 `已读取` 和截止投影，已经在截止前退出的事实仍通过历史入口携带完整退出生命周期。当前入口先按 L1 当前读取裁决生命周期；编码已退出时固定返回 `已退出` 且空载荷，不再补读历史判族，因此 `已退出` 优先遮蔽 wrong-family 判定。

对当前仍可读节点，目标属于另一 owner、属于同 owner 但没有本族唯一归属关系、是 v1 legacy / 裸 L1 普通节点、内部锚点或关系 / 属性类型节点时固定 `入口拒绝`、空载荷、零变化；历史入口在具名截止取得同类证据时采用相同拒绝。归属关系存在但重复、错 owner、错锚点、错类型、错角色或生命周期不闭合属于 `内部不一致`。这些状态不得降级为 `未找到`、合法空组或业务拒绝。七 owner 两两不同及同一稳定编码不能被两个族来源同时接受，属于 provider 装配与生产外集成不变量，不要求任一单族服务扫描其它族。

## 3. 共同值式 DTO

### 3.1 有序引用

`L2有序身份引用` 固定包含非零顺序和目标稳定编码。同一角色组按“顺序、目标稳定编码”升序形成唯一稳定投影；顺序相同且目标相同的重复项、零顺序和零目标在写前拒绝。

有序引用只表达结构角色和顺序，不证明目标的业务资格、动作成立或因果真实性。

### 3.2 属性提交项与属性事实

`L2属性提交项` 固定包含：

```text
属性类型身份
原始值材料
来源稳定编码
```

原始值材料只能是下列四类之一：

```text
I64
I64组
U64组
独立材料引用
```

不得接收通用 JSON、裸字节、字符串拼接、无类型联合容器或调用方指定的 L1 当前值编码。材料必须与属性类型允许的表示种类匹配；L2 只校验类型和结构，不解释单位、轮廓、颜色、位置、业务时间或其它业务意义。

`L2属性事实` 固定包含：

```text
属性类型身份
值稳定编码
类型化不可变材料
来源稳定编码
创建事实代次
可选退出事实代次
```

属性事实是调用方拥有的完整值式投影，不泄漏 L1 属性槽对象、内部材料路径或可变值对象。无显式顺序的属性组按“属性类型身份、值稳定编码”升序返回。

### 3.3 生命周期

`L2生命周期` 固定包含非零创建事实代次和可选退出事实代次。退出代次存在时必须大于等于创建代次；已退出事实不得复活、原地覆写或重新成为当前事实。当前入口不返回已退出事实，历史入口可以返回其完整生命周期。

### 3.4 完整投影边界

六类结果只返回本规范定义的完整值式事实。节点、关系和值的稳定编码、属性、来源和生命周期均须来自同一非零事实截止代次；不得用当前事实补历史缺项，也不得用默认值、缓存、SQL、材料目录或其它代次记录补齐结构。

L2 DTO 不得携带 L1 本地键、中性写集、仓库、锁、事务、候选、撤销权、SQL、缓存写权或材料内部路径。

## 4. 六服务、七族唯一所有权与事实形状

### 4.1 场景结构

唯一所有者为 `L2场景结构服务`，DTO 物理所有者为 `L2场景结构.数据.h`。场景节点族只使用场景 owner 和场景端口；全部完整读取必须在同一截止闭合场景身份来源。

`L2场景父子关系事实` 固定包含关系稳定编码、父场景身份、子场景身份、非零顺序和生命周期。一个当前子场景至多有一个当前直接父场景；父子关系不得形成结构环。没有当前父关系的场景只是结构根候选，不因此取得现实世界或业务根资格。

`L2场景成员关系事实` 固定包含关系稳定编码、场景身份、存在身份、非零顺序和生命周期。同一场景与同一存在之间至多有一条当前直接成员关系；该关系只表示结构成员，不证明所在场景或成员资格。

`L2场景事实` 固定包含场景身份、生命周期、完整固定属性组、完整直接子场景关系组和完整直接成员关系组。两个关系组均按共同有序引用规则稳定排序。

场景服务唯一负责场景节点、固定属性、父子关系和成员关系的创建、替换与退出，并公开按存在查询场景成员关系的反向值式投影。它不得判断现实世界、所在场景、成员资格或建立独立世界登记。

场景 owner 内另有一个不可变树登记锚点、一个根标记关系类型和一个树归属关系类型。三者都是场景服务私有结构元数据，不是公开节点族身份、树身份、业务节点或新 owner；其生命周期覆盖全部具名树、场景节点、根标记、树归属和历史 / 恢复引用。根标记固定为“根场景 -> 树登记锚点、角色 1”，树归属固定为“非根场景 -> 根场景、角色 1”。两类关系不得互换、反向、换端、单独退出或被普通父子 / 成员关系替代。

每个当前已登记场景恰有一份树归属证明：根场景恰有一条当前根标记且没有树归属关系，非根场景恰有一条当前树归属且没有根标记。`L2场景树身份` 等于根场景编码，因此一个底座可以有多个互异树身份；同一场景不得同时成为多树根、同时属于多树或既是根又是非根。根没有当前父关系，每个当前非根场景恰有一条直接父关系，且父、子、树归属目标必须落在同一树；整树从根沿父子关系可达且无环。

建立根必须在一笔场景 owner-scoped 写集中原子建立场景节点、场景族归属和根标记。新增非根场景必须在一笔写集中原子建立场景节点、场景族归属、树归属和指向同树当前场景的直接父关系。成功发布 R1 后，普通公开创建不得再产生缺少根标记 / 树归属的裸场景；旧裸场景在 R1 全部正式场景入口固定拒绝，读取、清退或保码迁移只能由未来独立 legacy 退役合同承接，不得由普通读取、恢复、创建或退出入口自动认领或接管。

场景服务必须公开根、单场景树归属和整树结构的当前 / 历史值式读取。每次成功读取都要在同一截止互证场景 owner、场景族来源、树登记锚点、精确关系类型、关系端点、角色、生命周期和父子同树约束；当前整树按场景身份和关系稳定编码排序，历史读取不得用当前事实补项。场景成员关系与存在端点只表达成员结构，不参与树归属裁决。

场景 owner 另行拥有业务中性的“场景宿主存在关系”结构。关系方向固定为“场景 -> 存在”，只表达该场景由哪个存在持有或作为其内部结构承载；它与“场景 -> 成员存在”不同，不表示该存在位于该场景中，也不改变场景树归属或父子拓扑。每个当前场景至多一个宿主存在，每个当前存在至多被一个场景作为宿主目标。新增、替换、退出、按场景当前 / 历史读取和按存在反向当前读取均由场景服务负责；写前必须以同一期望事实代次分别经场景来源 / 树归属和存在来源证明端点，关系由场景 owner 写入并在发布后同截止读回。L2 不解释哪个场景是“内部世界”、哪个存在是“自我”，也不以宿主关系证明场景成员或业务资格。

### 4.2 存在结构

唯一所有者为 `L2存在结构服务`，DTO 物理所有者为 `L2存在结构.数据.h`。存在节点族只使用存在 owner 和存在端口；全部完整读取必须在同一截止闭合存在身份来源。

`L2存在事实` 固定包含存在身份、生命周期和完整固定属性组。存在服务唯一负责存在节点与固定属性的创建、换代和退出，不写场景成员关系，也不判断存在真实性或业务资格。

存在 owner 另行拥有业务中性的“存在单例角色”结构。服务私有登记一个不可变角色登记锚点和一个角色指向关系类型；当前角色事实方向固定为“角色登记锚点 -> 存在”，关系角色字段承载非零且不大于 `INT64_MAX` 的不透明角色键。一个角色键至多指向一个当前存在，同一存在可以承载多个互异角色键。服务公开“原子建立新存在并绑定单例角色”“把既有存在绑定单例角色”、替换当前角色目标、退出当前角色和按角色键当前 / 历史读取；前者必须在同一存在 owner-scoped 写集中建立存在节点、存在族归属和角色关系，绑定只建立角色关系，替换必须同事务建立新关系并退出旧关系，退出只闭合具名当前角色关系。各写入口共享存在 owner 的全局幂等域，同键同完整请求精确重复、同键异义冲突；仍被当前角色关系引用的存在必须由 L1 当前引用保护拒绝退出。L2 只校验角色键、存在来源、唯一性、owner、生命周期和事务，不定义固定角色键，不把任何角色解释为自我、系统身份或项目资格，也不允许名称、配置、位置、顺序或缓存建立角色事实。

“被哪些场景成员关系引用”使用存在 DTO 定义的值式引用组，但只能由场景所有者的公开反向结构查询提供。存在服务不得反向 import 或调用场景服务；调用方需要该组合时分别消费存在事实和场景反向关系投影。

### 4.3 特征结构

唯一所有者为 `L2特征结构服务`，DTO 物理所有者为 `L2特征结构.数据.h`。特征定义与特征实例是两个独立 owner 范围：定义节点及其固定属性只由定义端口写；实例节点、宿主 / 定义关系、实例当前值和相应类型节点只由实例端口写。两族完整读取分别闭合自己的身份来源，不能用共享服务实例、相同节点形状或定义 / 宿主关系存在替代 owner 与族归属证明。

`L2特征定义事实` 固定包含特征定义身份、生命周期和完整固定属性组。后继统一特征合同还必须在同一特征定义身份上表达阶次与来源：基础特征阶次固定为 `1`；派生特征阶次大于 `1`，并保存非空、确定排序的直接来源特征定义关系、输入角色和派生规则身份。新派生特征的阶次固定为直接来源中的最高阶次加一。

“二次特征”是对实际二次至 n 次派生特征的统称，不增加第三个特征节点族、独立高阶特征服务或按阶次拆分的 owner。阶次、来源和派生规则缺失、压平来源链或形成来源环都属于坏结构；判断是否应该派生、规则是否有业务意义和结果是否解决当前需求位于 `DATA` 之外。

`L2特征实例事实` 固定包含特征实例身份、宿主存在身份、特征定义身份、生命周期和可选当前特征值事实。宿主与定义引用是结构关系，不授予业务适用性或值域解释。

`L2特征值事实` 固定包含值稳定编码、特征实例身份、类型化不可变材料、来源稳定编码和生命周期。一个当前特征实例至多有一个当前值；值换代建立新值、退出旧值并切换当前引用，旧值保留为历史。当前值也允许在不退出实例的情况下独立退出：同一特征实例 owner 写集只退出调用方具名的当前值，L1 同代移除该值占用的当前属性槽，实例、宿主关系、定义关系和族归属关系保持当前；成功后实例完整读回的当前值必须为空，已退出值仍可按历史读取。当前未设置值返回 `属性未设置`，具名值不是该实例当前值返回 `引用冲突`，不得扫描、猜测或退出其它值。

按存在读取的当前特征组必须返回该存在的完整当前实例组，并按特征实例身份稳定编码升序；每个实例的定义、宿主和当前值投影共享同一事实截止代次。

特征服务唯一负责定义、实例槽、宿主 / 定义引用、当前值新增 / 换代 / 独立退出以及实例 / 定义退出。当前值独立退出不退出实例或两条结构关系，也不建立空值、墓碑值或第二当前槽。它不得按轮廓、颜色、位置或其它业务名称建立专用 CRUD，也不得解释值的业务意义。

### 4.4 状态结构

唯一所有者为 `L2状态结构服务`，DTO 物理所有者为 `L2状态结构.数据.h`。状态节点族只使用状态 owner 和状态端口；状态创建前经存在、特征实例公开身份来源核对引用，完整读取在同一截止闭合状态身份来源。

`L2状态事实` 固定包含：

```text
L2状态身份
主体存在身份
特征实例身份
精确值属性事实
时间值属性事实
来源稳定编码
L2生命周期
```

主体与特征实例使用 L1 关系事实引用；精确值、时间值和来源使用状态节点的属性槽、值事实或具名结构引用承载。状态服务只保存调用方完整提交的状态记录及其引用替换 / 退出，不判断状态真实，也不从当前特征自动补造状态。

状态事实的节点、主体关系、特征关系、精确值、时间值、来源和版本事实均为永久事实。它们一旦成功发布即保持有效并可按事实或历史截止读取；状态失去当前性时不得退出这些事实、覆盖旧材料或建立第二状态身份。

旧状态当前选择 ABI 只表达“某引用上下文当前选中哪条状态记录”，不表达特征实例当前值。关系类型由状态结构类型登记提供，关系角色沿用状态端点角色；唯一键为 `(引用上下文身份, 当前选择关系类型)`。业务目标比较必须另行读取特征实例唯一当前属性槽和值事实；不得读取被选状态的值代替当前值。

状态服务必须新增具名当前选择读取入口和历史选择读取入口。按状态身份的事实 / 历史读取只说明状态事实本身，不自动声明当前性；当前选择入口必须最多返回一条当前选择关系，重复当前选择或端点 / 生命周期不一致返回 `内部不一致`。旧数据缺少当前选择关系时返回明确 `待迁移`，零载荷且不自动从主体关系、特征关系、时间、来源或版本推断。

首态由状态 owner 在同一写集中建立永久状态事实与当前选择关系，不建立动态。迁移由状态 owner 与动态 owner 的现有两参与者原子事务承载：只退出旧当前选择关系，建立新永久状态事实、新当前选择关系以及动态前 / 后状态关系。旧状态节点继续保持当前有效，A1 与动态前状态关系均可长期引用旧状态节点；不得材料化状态身份、建立第二见证节点或引入第三 owner 事务。

首态不形成第二写路径：既有 `新增状态` 是 v1 兼容拒绝 ABI，`新增状态_v2` 是唯一具有首态写能力的入口。v1 `L2状态新增请求` 继续是既有 7 字段布局；v2 使用独立具名 `L2状态首态请求_v2`，同样传递公共请求头、幂等身份、主体存在、特征实例、精确值材料、时间值材料和来源稳定编码，但其第一字段为专属请求头且专属版本固定为 2。当前选择关系的本地键、关系类型和角色由状态结构登记及 provider 内部固定合同取得，不得要求 L4 消费者提交 L1 本地键或存储层幂等材料。

`新增状态_v2(const L2状态首态请求_v2&) noexcept` 在状态 owner 的一个写集中形成永久状态、自有关系和唯一当前选择，不形成动态。`L2状态首态结果_v2` 固定包含公共结果头、专属版本、专用状态、optional 状态、optional 状态自有关系和 optional 当前选择关系。首次与精确重复成功时三项载荷完整，公共事实截止和变更事实代次均为首次 G1；L1 已确认提交后的独立读回失败返回公共内部不一致 + 专用已可能发布，保留首次 G1、三项正式载荷为空并以原键重放收束。无需向消费者公开 L1 private 提交见证 DTO。

状态—动态迁移 v1 兼容拒绝入口继续使用既有 10 字段 `L2状态动态原子发布请求` 和既有结果布局。唯一迁移写入口为 `发布状态动态原子迁移_v2(const L2状态动态迁移请求_v2&) noexcept`；v2 请求固定依次传递专属头、幂等身份、主体存在、旧当前状态、新状态特征实例、新状态精确值、新状态时间值、动态起始时间、动态结束时间、来源和完整旧当前选择引用。旧选择稳定编码包含在该强类型引用中，不再重复形成第十三字段。

迁移 v2 结果固定包含公共结果头、专属版本、专用状态、新状态、新状态自有关系、新动态、新动态自有关系、新当前选择、已退出旧当前选择和共同事实截止代次。成功时六项载荷完整且共同截止、公共变更代次均为首次 G1；迁移只退出旧当前选择，旧状态及自有关系永久有效。提交后独立读回失败固定为公共内部不一致 + 专用已可能发布，保留首次 G1、六项正式载荷为空；原请求重放从首次 G1 的正式历史快照恢复完整结果。

跨 owner 请求没有参与者顺序参数。L1 以状态参与者序号 1、动态参与者序号 2 和各写集本地键升序形成唯一规范顺序；状态候选先形成 G1 与映射，动态候选内部以该 G1 应用并解析后状态引用。交换前必须把动态候选内部代次以及两 owner 首次写入账统一投影为同一 G1，验证全局闭包后才一次交换。该固定规范化保证调用者及容器排列不能改变正式映射或最终事实；L4 不取得 private 顺序开关、候选或预形成 DTO。

精确重复由 L1 幂等账在 G0 比较之前裁决，直接返回首次 G1 与两份映射，零候选、零应用、零新代次。同键异请求返回幂等冲突。L2 在重放时可以重构原规范化请求，但不得用旧选择当前性重新裁决首次结果；新键携带旧 G0 仍返回事实代次漂移。

首次提交后先以 G1 调用正式状态记录选择读取，再以首次 G1 读取状态、选择和动态历史快照并逐字段互证；精确重复以本次当前代次作请求头、首次 G1 作历史截止收束。事务成功结果的公共事实截止、变更事实代次和共同事实截止均为首次 G1。调用方需要判断特征此刻的值时必须另调特征实例完整读取入口，不得把状态选择或首次历史快照冒充后继代次的当前特征值。

当前选择关系类型登记写入与登记读取是两个结果 ABI。写入结果包含公共 `L2结构结果头`、写入专用状态、规则版本、optional 整体提交见证和 optional 登记事实；提交见证精确四字段为 `提交确认、非零关系类型稳定编码、L1登记写入幂等身份、提交事实代次`，不含结果头、专用状态、局部键或其它字段。登记读取结果独立包含公共结果头、`L2状态当前选择关系登记读取状态` 和 optional 登记事实；读取状态固定为 `已读取=3、待迁移=4、入口拒绝=8、许可拒绝=9、事实代次漂移=10、资源失败=13、内部不一致=14`。读取函数固定为 `L2状态当前选择关系登记读取结果 L2状态结构服务::读取当前选择关系类型登记(const L2状态当前选择关系类型登记读取请求&) const`。读取矩阵穷尽为：未登记/缺当前选择→公共已读取=3+专用待迁移=4+空载荷+成功否；坏请求→公共入口拒绝=5+专用入口拒绝=8+空载荷+成功否；许可→6/9；G0→10/10；资源→13/13；完整一条正式登记事实→公共已读取=3+专用已读取=3+完整事实+成功是；多义/坏闭包→14/14+空载荷+成功否。写入请求头期望代次是交换前 G0；正式登记读取结果头事实截止代次固定为本次请求截止 Gread，结果头可选变更事实代次及登记事实首次登记事实代次固定为首次登记代次 Greg，登记事实本次正式读回截止固定为 Gread；即时写后允许 Gread=Greg，后续独立读取不强制恒等，精确重复写后同样按本次 Gread 与首次 Greg 返回。登记读取 `成功()` 必须同时检查完整登记事实、正式读回互证及 Gread/Greg 关系。

```cpp
    L2特征实例身份 新状态特征实例;
    L2原始值材料 新状态精确值材料;
    L2原始值材料 新状态时间值材料;
    L2原始值材料 动态起始时间材料;
    L2原始值材料 动态结束时间材料;
    稳定编码 来源方法稳定编码;
    L2状态当前选择关系引用 旧当前选择;
};
struct L2状态动态迁移结果_v2 final {
    L2结构结果头 结果头;
    std::uint32_t 原子发布合同版本 =
        L2状态动态迁移专属合同版本_v2;
    L2状态动态迁移操作状态_v2 迁移操作状态;
    std::optional<L2状态事实> 新状态;
    std::optional<L2状态自有关系引用> 新状态自有关系;
    std::optional<L2动态事实> 新动态;
    std::optional<L2动态自有关系引用> 新动态自有关系;
    std::optional<L2状态当前选择关系引用> 新当前选择关系;
    std::optional<L2状态当前选择关系引用> 已退出旧当前选择关系;
    std::uint64_t 共同事实截止代次 = 0;
    bool 成功() const noexcept;
};
```

首态和迁移的 `成功()` 均要求共同/专属版本正确、公共/专用状态成对、首次 G1 非零、成功载荷完整且状态、owner、关系角色、生命周期和截止逐字段互证。任何交叉状态、默认身份、部分载荷或混代结果均为非成功。

### 4.5 动态结构

唯一所有者为 `L2动态结构服务`，DTO 物理所有者为 `L2动态结构.数据.h`。动态节点族只使用动态 owner 和动态端口；动态创建前经存在、状态公开身份来源核对引用，完整读取在同一截止闭合动态身份来源。

`L2动态事实` 固定包含：

```text
L2动态身份
主体存在身份
前状态身份
后状态身份
起始时间值属性事实
结束时间值属性事实
来源稳定编码
L2生命周期
```

主体、前状态和后状态使用 L1 关系事实引用；时间和来源使用动态节点的属性槽、值事实或具名结构引用承载。主体、前状态和后状态是三个彼此独立的强类型结构引用：动态服务必须分别经存在结构公开读取证明主体引用是合法 `L2存在身份`，经状态结构公开读取证明前 / 后状态引用是合法 `L2状态身份`；错类型、坏引用或混代不得以普通节点、空载荷或默认身份补齐。

动态结构不要求主体等于前状态主体或后状态主体，也不要求前后状态彼此不同、值发生变化或时间有序。三者的业务一致性由 `DATA` 之外调用方裁决；`DATA-L2` 只校验各自强类型结构和共同截止。动态服务只保存调用方完整提交的动态记录及其引用替换 / 退出，不比较状态、不生成动态、不判断变化重要性，也不执行动作归因。

### 4.6 因果结构

唯一所有者为 `L2因果结构服务`，DTO 物理所有者为 `L2因果结构.数据.h`。因果节点族只使用因果 owner 和因果端口；因果创建前经状态公开身份来源核对条件 / 结果引用，完整读取在同一截止闭合因果身份来源。

`L2因果事实` 固定包含：

```text
L2因果身份
非空有序条件状态引用组
可空动作引用
非空有序结果状态引用组
来源稳定编码
L2生命周期
```

条件和结果项均使用 `L2有序身份引用` 指向状态身份。动作为空是合法结构；非空动作只是不透明稳定编码，L2 只经 L1 验证其当前节点形状，不依赖任务、方法或其它业务服务。

因果服务只保存调用方完整提交的因果记录及其引用替换 / 退出，不判断因果真实、必然、主动或被动，不推断动作，也不自动补条件或结果。

## 5. 关系归属与单向依赖

场景父子 / 成员、特征宿主 / 定义、状态主体 / 特征、动态主体 / 前后状态、因果条件 / 动作 / 结果均是 L1 关系事实。固定属性、精确值、时间值和原始材料均由属性槽和值事实承载。任何 L2 服务都不得复制关系成员为第二权威当前列表；完整组只是在一个截止代次内形成的值式投影。

依赖方向固定为：

```text
L2场景结构 -> L1事实基座
L2存在结构 -> L1事实基座
L2场景成员关系 -> L2存在结构公开读取 + L1事实基座
L2特征结构 -> L2存在结构公开读取 + L1事实基座
L2状态结构 -> L2存在结构公开读取 + L2特征结构公开读取 + L1事实基座
L2动态结构 -> L2存在结构公开读取 + L2状态结构公开读取 + L1事实基座
L2因果结构 -> L2状态结构公开读取 + L1事实基座
普通应用唯一 provider -> 同一 L1 运行包签发器 + 六个 L2 服务唯一实例
DATA-L3 世界树结构聚合 -> 六类 DATA-L2 服务公开面；零写入所有权
```

场景树根标记、树归属和父子同树约束仍属于 `L2场景结构 -> L1事实基座` 这一条边；不得增加独立树服务、树 owner 或场景对 A1 / 自我初始化的反向依赖。A1 只能透明返回同一个场景服务实例，不创建、选择或缓存根。后继自我初始化只能消费调用方已经明确并经正式读取证明的 `L2场景树身份` / 根场景，不得创建、扫描或猜测根。

不得增加反向 import、同层循环依赖、跨所有者仓库访问或不存在结构依赖的转发层。跨族引用必须调用目标族公开身份来源或完整读取，不能直达 `DATA-L1` 重演目标族证明。存在服务不依赖场景服务；场景反向关系查询由场景所有者提供。`DATA-L3` 世界树聚合只能持有并组合六类公开服务，不能形成第二写入入口、第二 DTO 解释、中央身份服务或业务门面。

## 6. 共同事务、幂等与读取

1. 每次创建、替换或退出由目标结构唯一所有者形成一份不可变 owner-scoped L1 中性写集，并恰一次提交。节点创建与本族归属关系必须同写；关系替换、值换代、旧事实退出和新当前引用必须在同一事实代次原子发布。跨 owner 结构不能塞进一笔写集，跨族原子业务操作不属于 L2 普通 CRUD。
2. 一份请求取得首次结果后，其 `L2结构幂等身份` 才与逐字段完整请求绑定；后继逐字段完全相同的请求返回 `精确重复` 和首次原结果，同一已绑定身份用于不同请求语义返回 `幂等冲突`，零变化。只有返回结构化 `事实代次漂移` 的未发布请求不绑定身份，调用方可在重新正式读回后保留该身份并重组期望代次及其派生请求字段；不得以记录已存在、摘要相同或业务同义冒充幂等。
3. 期望事实代次不符返回 `事实代次漂移`，仅交换前候选阶段承诺零变化、无首次结果且幂等身份未绑定。资源失败或异常若发生在交换前同样零写；L1 已确认提交或精确重复后的独立读回失败不得回滚，必须保留已形成事实、幂等账和代次，并使用原幂等身份与原完整请求读回收敛。当前源码没有无法取得 L1 提交结果的生产分支，本叶不新增另一种发布结果。
4. 当前组合读取只能使用 L1 一致当前投影；节点、关系、值、属性和引用组必须共享一个非零事实截止代次。一次允许的重试后仍漂移时返回 `事实代次漂移`，不得返回部分结构。
5. 历史读取必须显式使用具名历史入口和指定截止，只返回 0/1 个有效快照，不返回退出投影。不得声明完整演进版本集合、排序或退出时间线；完整历史能力登记为后续 L1 提供者缺口。不得使用当前事实补历史缺项，也不得把已退出事实重新标为当前。
6. 当前属性不存在返回 `属性未设置`；目标不存在返回 `未找到`；目标已退出且从当前入口读取时返回 `已退出`。三者不得互相折叠。
7. 任一成功结果缺项、身份复义、同一结果混代、关系角色矛盾、属性槽复义或发布后读回矛盾均返回 `内部不一致`，停止依赖路径；不得降级为未找到、资源失败或业务拒绝。
8. 原完整读取与条件查询必须复用同一身份来源判定，并把来源事实和本结构其它节点 / 关系 / 值放入同一当前一致投影或同一历史截止闭环；禁止先在一个代次证明身份、再从另一代次拼装结构。跨族写前读取均使用同一期望事实代次；其后本族提交仍以该代次为期望，期间任何发布由 L1 返回事实代次漂移。
9. 场景根创建的三项写集与非根创建的四项写集不可拆分；同键同完整请求返回首次树 / 场景 / 关系编码，同键异义冲突。父子新增或替换前必须从同一期望代次读回两端树身份相等，根作为子端或跨树端点固定入口拒绝，零变化。

## 7. 引用保护与退出

1. 退出请求必须显式处理本结构所有的当前附属关系和值，并包含本节点唯一族归属关系；不得按业务名称自动推断要退出的引用。
2. 目标仍被当前关系、属性、值来源或独立材料引用时，且这些引用未在同一合法写集中闭合，返回 `引用冲突`，整笔零变化。
3. 跨结构引用统一由 L1 当前关系和引用闭包保护；较低层服务不反向依赖全部消费者，也不得扫描上层业务服务补造退出项。
4. 退出成功只改变当前可见性并保留完整历史。物理回收、崩溃恢复、跨进程恢复和持久证据清理不属于六类普通 CRUD。
5. 节点与族归属关系必须同代退出；族锚点和族归属关系类型不随单个节点退出。归属关系不得单独退出、换锚点、复活或迁到另一 owner。旧未标记节点默认拒绝，不得在普通读取中补写；保码迁移必须另立具名合同并携带可审计原 owner 证据，否则由新 owner 重建新稳定编码并按独立 legacy 退出计划闭合旧事实。
6. 本族退役必须先用仍有效的本族端口退出全部公开节点、归属关系、锚点和关系类型并使当前事实归零，再释放端口；随后只有在幂等提交收敛且历史 / 恢复 / 审计引用闭合时，签发器才可按 4015 退出 owner。owner、锚点和关系类型历史永久保留，不得复活、转交另一族或用新的 owner 继续接受旧族身份。
7. 普通场景退出不得退出根，也不得让仍有当前子场景的非根退出后留下无父树成员。根退出只能由具名整树退出合同在闭合全部节点、场景族归属、根标记、树归属、父子、成员、属性和值以及外部当前引用后执行；没有该合同的实现阶段，根和树固定不可退出。树登记锚点及两种树关系类型不随单树退出。

## 8. 实际消费与施工检查边界

六类真实实现由合法消费者在实际使用时经正式公开强类型入口、结构化结果和权威读回判断是否满足当前需要。施工期间的临时专项可以按风险逐叶覆盖：

1. 合法创建后完整当前读回；
2. 零身份、错类型、坏引用、坏顺序、旧期望代次等非法请求返回结构化非成功且权威状态零变化；
3. 同键同完整请求精确重复、同键异请求幂等冲突；
4. 当前或条件查询结果完整、稳定排序且共享一个事实截止代次；
5. 替换后新事实为当前、旧事实可从历史入口读取；
6. 引用未闭合时退出冲突且零变化，引用闭合后退出成功、当前不可见且历史仍可查；
7. 适用的组合写原子性、并发漂移和发布后读回一致性。
8. 七个 owner 两两不同，特征服务两端口路由唯一；wrong-family、同 owner 元数据节点、v1 legacy 与裸 L1 普通节点均被拒绝且权威状态零变化。
9. 每族节点与非自环族归属关系同写、同创建代次；来源的当前 / 历史读回完整，退出时同代闭合，错锚点、错类型、错角色、重复关系和混代均精确失败。
10. 同一场景 owner 底座建立至少两棵树并分别证明恰一当前根；根创建三项原子，非根创建四项原子，场景恰一树归属、根无父、非根恰一父、同树父子成功、跨树父子和根作子端拒绝。
11. 无父旧场景不等于根，旧裸场景不能扫描 / 猜测 / 自动认领；根标记、树归属和整树当前 / 历史读取逐字段、同截止且稳定排序。普通成员关系、存在端点和 A1 getter 均不能建立或改变树归属。
12. 存在单例角色的登记、原子新存在绑定、既有存在绑定、当前 / 历史读取、角色唯一、同键重复 / 异义和并发竞争成立；专项只使用测试角色键，不把任何键解释为自我。
13. 场景宿主存在关系的新增、替换、退出、当前 / 历史与反向读取、场景与存在两端来源、双向唯一和并发漂移成立；宿主关系与成员关系、父子关系和树归属互不替代。

## 10. 20260827 无业务 owner 的状态动态与实例材料合同

本节是 4230 v0.16 当前最高优先级合同。前文 `2.4`、`4.4`、`4.4A`、两处 `4.5`、`6`、`7` 中与本节冲突的 owner 身份证明、许可分支、永久状态历史、特征实例当前选择、状态动态同 G1 或主体内嵌条款均降为旧 ABI / 迁移说明。

### 10.1 DATA 调用与七族身份

1. 六服务不判断调用者是谁或是否有权 CRUD；业务 / 治理层在调用前裁决。
2. 七族各有唯一权威结构服务。L1 owner、写端口和族内 owner 字段只作内部结构分区，不是节点族身份、数据归属或调用资格。
3. `L2节点族身份来源事实` 不得包含 `L1结构所有者身份`、端口或分区证明；公开身份只由节点族、节点身份、族锚点、族归属类型、唯一归属关系、角色 / 顺序及生命周期同截止互证。
4. `许可拒绝=6` 及专用许可值只供旧 ABI 解码，现行入口不得产生。端口异常、分区冲突、资源暂不可用分别编码为 `内部不一致=14`、`引用冲突=12`、`资源失败=13`。
5. 现行 DATA 路径只裁决结构、合同版本、事实代次、幂等、引用闭包与资源状态。旧原子发布 private 路径中的内部凭证无效映射为内部不一致，owner / 端口绑定矛盾映射为引用冲突；两者不得映射为许可拒绝。

### 10.2 状态事实与引用

`text
L2状态身份
L2状态材料类别：实例 / 抽象
L2特征类型身份
L2特征值材料或强类型引用
L2强时间
L2生命周期
`

实例状态只接受非负 UTC Unix epoch 纳秒，抽象状态只接受非负相对纳秒。类别、时间语义、特征类型、特征值和时间不可原地改写。

主体存在、场景、特征实例、任务、方法、用途和来源解释不进入状态本体，由引用方通过强类型关系提交。当前选择是引用上下文到状态记录的普通当前关系；被选实例状态清理时同代退出且不得回退旧状态。该关系不决定特征当前值，不得用于目标比较，也不得从被选状态或动态后状态反推当前值。

### 10.3 动态事实

动态包含身份、材料类别、至少两个状态的确定有序引用和生命周期。普通创建前在同一期望截止逐项读回既有成员，不得携带待创建状态。统一特征当前值变化组合入口是唯一例外：新值先由业务规则裁决，组合器先预形成新状态，再以既有前状态和新状态预形成动态，最终与特征当前属性槽切换原子发布。

动态允许混合特征类型。成员同为实例或同为抽象，时间语义一致且非递减；相同时间合法。`[S1,S2,S3]` 与 `[S1,S3]` 均合法，已有动态不得因成员退出或清理而静默删项、改序或压缩。

### 10.4 实例材料保留与清理

1. 保留策略包含四个独立非零边界：实例状态 TTL、实例动态 TTL、实例状态数量上限、实例动态数量上限。状态与动态分别判断，不形成共同总量。
2. TTL 只以各材料首次正式形成时记录的 UTC 纳秒为基准；状态事件时间、动态成员事件时间及最后读取时间均不得参与。数量候选按首次形成 UTC 纳秒、稳定身份升序选择。
3. 先退出动态及成员关系，再退出当前选择，最后退出不再被活动动态引用的状态；到期状态仍被引用时，相关动态先进入清理闭包。
4. 普通引用允许成为已过期引用，读取返回 `目标已过期`，不得改指、删动态成员或返回默认值。
5. 清理推进新事实代次并保留墓碑：结构类别、原身份、创建代次、清理代次、清理原因、原规范化请求摘要；紧凑幂等记录支持重复、异义和未知发布收敛。
6. 当前 / 历史读取命中墓碑返回 `历史材料已清理`、墓碑和清理代次，完整载荷为空；身份不得复用。抽象材料不受实例清理策略影响。
7. 状态 / 动态服务不创建线程。普通应用唯一宿主在上下文可用后立即调用公开清理入口一次，此后每 60 秒一次；空运行宿主不绑定维护回调。
8. 资源失败保留原 G0、幂等身份和完整请求；事实代次漂移换新 G0 与新身份并在本周期最多重试一次；第二次漂移等待下一周期；内部不一致或序列耗尽形成程序失败。
9. 周期维护身份固定使用 `0x4E43'0000'0000'0000` 前缀和进程内原子单调非零低 48 位。资源失败续用同键，漂移重组换键，抽象完成不得使用该前缀。

### 10.5 旧 ABI

既有 `新增状态`、`新增状态_v2`、`发布状态动态原子迁移_v2`、当前选择登记及“新状态 + 新动态同 G1”布局只用于旧 ABI 识别、拒绝或历史结果解码，不再产生新状态 / 动态。任务阶段消费者必须顺序调用中性状态、动态与当前选择入口，各笔写携带自己的正式代次与证据。

## 11. 20260828 特征当前值与变化记录权威

本节是 v0.17 最高优先级合同：

1. 特征实例唯一当前属性槽指向的当前值事实，是业务自检、需求满足和目标状态合同比较的唯一输入。
2. 状态记录某个强时间的特征类型和值；动态记录至少两个状态的有序变化及来源。状态、动态、状态当前选择和最后写入顺序都不是当前值权威。
3. 动态可以触发或定位重检，但消费者必须冻结 G0 后重新读取特征当前值和目标合同，不得直接消费动态前值 / 后值裁决。
4. 复合目标在同一 G0 读取目标涉及的当前特征值集合，再按目标合同的 AND、OR 或其它正式组合规则比较。值式当前状态投影只可重建，不形成第二当前值。
5. 任何正式当前值真实变化必须经唯一公开组合入口。首次赋值原子发布当前值、当前属性槽和初始状态，不形成动态；后继变化先裁决新值，再按新状态、前后状态动态的顺序预形成，最终原子发布当前值切换、新状态和新动态；值未变化时零写。
6. 前状态记录缺失、混代、值不对应，或者任一候选、交换、读回失败时，组合入口不得发布部分成功。历史补录状态 / 动态不得切换当前属性槽。
7. 现有六类公开 ABI 尚未闭合上述跨特征、状态、动态结构分区的统一组合入口。后继设计必须冻结请求、结果、幂等、原子发布、未知发布重放和三类正式读回后才能施工；本次规范修订不宣称该 provider 已实现。

## 12. 20260828 三分区统一变化 ABI

本节是 v0.18 最高优先级合同，闭合第 11 节的实现前缺口。与第 10.5 节“任务消费者分别顺序写入”冲突的部分退出；普通历史补录仍分别调用中性状态、动态和引用入口，真实当前值变化只能调用本节唯一组合入口。

### 12.1 唯一服务与固定参与者

唯一公开组合服务继续复用 `L2状态动态原子发布服务`，不新建第二 provider、owner 或事实仓。新入口固定为：

```cpp
L2特征当前值变化记录结果_v1 发布特征当前值变化与中性记录_v1(
    const L2特征当前值变化记录请求_v1&) noexcept;

L2特征当前值变化记录读取结果_v1 读取特征当前值变化记录_v1(
    const L2特征当前值变化记录读取请求_v1&) const noexcept;
```

写入只消费现行 `L1三分区原子事务_v2`，参与者顺序和 owner 永久固定为：`1=特征实例 owner、2=状态 owner、3=动态 owner`。调用方不得传参与者顺序、L1 owner、端口、本地键、映射或候选。组合幂等身份及特征、状态、动态三份参与者幂等身份均由公开请求显式携带，四者必须有效且两两不同；L2 不从线程、地址、容器位置或 `variant::index()` 补造。

### 12.2 请求与来源

`L2特征当前值变化记录请求_v1` 物理顺序固定为：专属合同版本 1、共同 `L2结构请求头(G0)`、组合幂等身份、特征参与者幂等身份、状态参与者幂等身份、动态参与者幂等身份、特征实例、完整预期旧当前值事实、新值材料、实例绝对 UTC 纳秒变化时间、主体存在、共同场景、来源存在、可选来源方法。

主体必须等于特征实例当前宿主；共同场景、主体和来源存在必须在 G0 是正式当前节点。来源方法缺省表示没有合法动作证据，只形成状态迁移动能；不得用线程、消息、调度器、日志或外部字符串补造来源动作。来源方法存在时，除状态迁移动能外再形成一条动作致变动态，并由关系 20 的角色 6、8 分别绑定来源方法和同源状态迁移动能。值事实来源固定取“有来源方法则方法，否则来源存在”，调用方不再提交第二来源编码。

### 12.3 状态、上下文与兼容基线

新状态继续使用中性状态本体“材料类别、特征类型、值、时间”。关系 19 只绑定主体、共同场景、特征实例和来源存在；当前值是值事实而不是节点，禁止为它建立关系端点。特征实例的中性记录当前选择固定使用现行中性状态当前选择结构：引用方等于特征实例，引用角色等于公开固定的“特征当前值记录状态”角色；该选择只定位记录，不决定当前值。

正常变化必须在 G0 读回恰一中性当前选择及其状态，并证明主体、共同场景、特征实例、特征类型和值与预期旧当前值一致。历史第一阶段数据没有中性选择时，允许一次受约束兼容：若恰有一条旧首态当前选择且其主体、特征实例和值与预期旧当前值一致，则在同一状态参与者写集中先形成一条以本次变化时间记录旧值的中性基线状态，再形成新状态；动态从该基线状态迁移到新状态。旧首态及旧选择只供历史兼容读取，不再参加后继当前性裁决。两类前状态都无法唯一证明时返回材料不足，禁止猜测。

### 12.4 原子状态机

写入顺序固定为：G0 读前守卫和端点读回；比较完整旧值；比较新旧材料；预形成特征值换代写集；预形成状态基线（仅兼容路径）、新状态、关系 19、新中性当前选择和旧中性选择退出；预形成状态迁移动能及关系 20；有来源方法时再预形成动作致变动态及同源关系；提交三分区原子事务；按首次 G1 通过正式当前/历史入口独立读回全部事实；Gnow 读后守卫。

新值材料与旧值完全相等时返回 `无变化`：共同截止为 G0，返回完整旧当前值，零三分区提交、零新值、零状态、零动态、零新选择。真实变化只退出旧当前值事实和旧中性当前选择；旧状态、旧动态及上下文关系按其保留策略继续存在。任何预形成、引用、交换或完整读回失败都不得返回部分成功。

### 12.5 结果、读取和状态矩阵

写状态固定为：`已提交=1、精确重复=2、无变化=3、入口拒绝=4、当前性漂移=5、幂等冲突=6、材料不足=7、引用冲突=8、资源失败=9、内部错误=10、已可能发布=11`。`已提交/精确重复` 必须返回新当前值、前后中性状态、新中性当前选择、状态迁移动能、完整状态/动态上下文以及非零首次 G1；只有首次兼容路径返回兼容基线标志，只有有来源方法时返回动作致变动态。`无变化` 只返回旧当前值和 G0。其它状态全部业务载荷为空、截止为 0；`已可能发布` 只保留四个幂等身份和可能的首次 G1 提交见证，不返回未经正式读回的业务载荷。

独立读取请求固定携带共同请求头、本次写结果中的特征实例、新当前值稳定编码、新当前选择身份、前/后状态身份、状态迁移动能身份、可选动作致变动态身份和首次 G1。读取以当前 Gread 作为读前/后守卫，以 G1 读取历史快照；逐项互证参与者 owner、生命周期、当前值槽历史、状态本体、关系 19、中性选择、动态成员和关系 20。读取状态固定为 `已读取、入口拒绝、当前性漂移、材料不足、引用冲突、资源失败、内部错误`；非成功零载荷/截止 0。

精确重复在 G0 比较前由 L1 三分区幂等账裁决，返回首次 G1 和首次映射，零新代次；同键异请求返回幂等冲突。提交后读回失败返回已可能发布，原完整请求与四个幂等身份必须原样重放，禁止换键猜测。首次 G1 的历史读回、后继当前读回和进程重启恢复都必须证明当前值、记录选择和状态/动态上下文闭合。

### 12.6 本能根恢复与完成边界

本能根初始化恢复先读取特征当前值，再读取固定角色的中性当前选择；存在中性选择时只按中性状态及关系 19 互证，不再要求旧首态选择值等于当前值。中性选择尚不存在且当前值仍为第一阶段初值时，才允许按旧首态兼容读取。该兼容不生成动态，不改变当前值，也不成为第二权威。

本节只授权统一变化基础能力及本能根恢复适配，不实现安全/服务被动规则、自检、需求、任务、方法执行或结算。没有真实普通应用消费者和独立读回，只能声明 provider 已实现，不能声明本能路线阶段二完成。

## 13. 20260830 特征当前值变化永久账与完整组读回

### 13.1 唯一 owner 与 v2 生产入口

```cpp
    const L2特征当前值变化组读取请求_v2&) const noexcept;
```

v2 写请求物理顺序与 v1 的业务字段一致：专属合同版本 2、共同 `L2结构请求头(G0)`、组合幂等身份、特征 / 状态 / 动态三个参与者幂等身份、特征实例、完整预期旧当前值事实、新值材料、变化 UTC 纳秒、主体存在、共同场景、来源存在、可选来源方法。v2 不允许调用方指定账身份、L1 owner、本地键、首次 G1 或新当前值身份。

### 13.2 登记和永久账事实

登记在特征实例 owner 内建立唯一变化账锚点。固定登记写入幂等身份为 `0x4E53'4356'4C45'4432`，固定本地键段为 `0x0203'1301..0x0203'1303`：`1301=账锚点、1302=变化记录节点、1303=变化记录载荷`。当前工作区候选常量零命中；后继不得复用该键段表达其它语义。

每次 v2 真实变化在特征参与者原写集中同时增加一个永久普通节点和一份以账锚点为来源的 U64 组载荷。载荷只保存可在提交前确定且用于独立恢复的材料：合同版本、特征实例、旧当前值身份、变化 UTC 纳秒、来源存在、可选来源方法、组合幂等身份和三个参与者幂等身份。新当前值身份与首次 G1 必须从首次正式写入结果映射和节点生命周期读回，不得预编码、回填或复制成第二当前值。

正式投影为：

```cpp
struct L2特征当前值变化账事实_v2 final {
    L2特征当前值变化账身份_v2 身份;
    L2特征实例身份 特征实例;
    稳定编码 旧当前值稳定编码;
    稳定编码 新当前值稳定编码;
    std::int64_t 变化UTC纳秒;
    L2存在身份 来源存在;
    std::optional<L2方法身份> 来源方法;
    L2结构幂等身份 组合幂等身份;
    L2结构幂等身份 特征参与者幂等身份;
    L2结构幂等身份 状态参与者幂等身份;
    L2结构幂等身份 动态参与者幂等身份;
    std::uint64_t 形成事实代次;
};
```

账节点和载荷不随实例状态 / 动态 TTL、数量清理或当前值换代退出。特征实例正式退出后的账仍按历史审计保留；当前组读回只接受在 `G0` 可证明目标特征实例身份来源的请求。

### 13.3 原子发布与读回

v2 的三分区参与者顺序仍固定为 `1=特征、2=状态、3=动态`。真实变化时，变化账节点 / 载荷与新当前值处于参与者 1 的同一规范化写集，和状态 / 动态参与者共享同一三分区提交 G1。无变化返回完整旧当前值且不写账。精确重复返回首次账、新当前值、状态和动态，零第二账；同键异义返回幂等冲突。

提交后必须通过四个幂等身份分别读回首次规范化写集与结果，证明三个参与者均为同一 G1；再以现有单项读取入口互证新当前值、前后状态、当前选择、状态迁移动能、可选动作致变动态和上下文。任一账、映射、参与者、状态或动态不闭合返回 `已可能发布`，原完整 v2 请求原键重放收束。

### 13.4 完整 UTC 范围组读回

组读取请求物理顺序固定为：合同版本 2、共同 `L2结构请求头(G0)`、特征实例、包含起始 UTC 纳秒、排除结束 UTC 纳秒、非零数量预算。必须满足 `0 < 起始 < 结束 <= I64_MAX`。

读取固定执行：G0 读前守卫；读回账登记；按唯一账锚点完整读取全部当前账载荷；逐项解码并验证 owner、节点、值、首次 G1、四幂等首次写入和三参与者共同 G1；筛选目标特征实例与 `[起始,结束)`；按 `变化UTC纳秒、账身份` 严格升序；数量预算；G0 读后守卫。任何锚点来源载荷坏形状、重复账身份、同一特征同一 G1 多账、首次写入缺失或三参与者不一致均为集合不闭合，禁止跳过坏项后返回部分成功。

完整集合见证字段固定为：账登记事实代次、特征实例、起始 UTC 纳秒、结束 UTC 纳秒、声明成员数、规范有序账身份组、G0。`0` 项只有在账已登记、全量来源读取成功、全部载荷均完成裁定且双守卫成立时合法。登记前历史和仍由 v1 入口形成的变化不在 v2 覆盖范围；消费者必须把登记代次作为生产切换边界，不得宣称其覆盖更早历史。

读取状态固定为：`已读取、账未登记、入口拒绝、当前性漂移、数量预算不足、集合不闭合、引用冲突、资源失败、内部错误`。只有 `已读取 + 完整事实组 + 完整见证 + G0` 成功；全部非成功为空组、空见证、截止 0。

### 13.5 完成边界

本节只建立永久变化账和完整组读回。它不判断某项变化属于主动安全、服务被动维护或其它业务，不计算低位回升许可，不改变安全 / 服务根值，不发布安全根定义，也不把变化账当成当前值。业务消费者仍须用来源方法、规则版本和正式领域合同解释账项，并重新读取特征当前值完成业务比较。

### 13.6 事实代次连续覆盖读回

UTC 范围只表达事件时间筛选，不能证明一个生产消费者从上次成功提交以后没有漏读新发布事实。永久变化账必须同时提供按形成事实代次的连续覆盖入口：

```cpp
L2特征当前值变化事实代次组读取结果_v2
按特征实例与事实代次范围读取完整变化组_v2(
    const L2特征当前值变化事实代次组读取请求_v2&) const noexcept;
```

请求物理顺序固定为：合同版本 2、共同 `L2结构请求头(G0)`、特征实例、排除起始事实代次、非零数量预算。排除起始事实代次必须非零且不大于 `G0`。服务读回账登记后还必须证明该起点不早于账登记事实代次；早于登记边界返回 `覆盖边界不可用`，不得把登记前历史解释为已覆盖。

读取固定执行：G0 读前守卫；读回账登记；按唯一账锚点完整读取全部当前账载荷；逐项执行第 13.4 节相同的 owner、节点、值、首次 G1、四幂等首次写入和三参与者共同 G1 验证；筛选目标特征实例与事实代次半开闭区间 `(排除起始事实代次, G0]`；按 `形成事实代次、账身份` 严格升序；数量预算；G0 读后守卫。不得只扫描命中区间后跳过区间外坏项，也不得以 UTC 顺序、容器顺序或最后一条记录代替事实代次覆盖。

完整集合见证字段固定为：账登记事实代次、特征实例、排除起始事实代次、包含结束事实代次、声明成员数、规范有序账身份组、G0；其中包含结束事实代次必须等于 G0。`0` 项只有在起点不早于登记代次、全部账载荷完成裁定且双守卫成立时合法。读取状态固定为：`已读取、账未登记、入口拒绝、当前性漂移、覆盖边界不可用、数量预算不足、集合不闭合、引用冲突、资源失败、内部错误`；只有 `已读取 + 完整事实组 + 完整见证 + G0` 成功，其它状态全部为空组、空见证、截止 0。

事实代次范围是生产连续消费和幂等水位的唯一依据；UTC 范围入口继续用于具名事件时间窗口读取、审计和未来已经冻结时间映射后的业务排序。两种范围不得互相推导。事实代次范围本身不把变化分配到某个单调完整秒，也不裁决业务来源；若业务规则需要把非空变化精确归属到单调秒，必须由后继版本另行冻结映射，不能由调用方用 `UTC_now-N秒` 补造。
