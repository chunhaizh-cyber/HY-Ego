# 4230 子规范 L2六类纯结构统一合同

编号：4230
日期：20260812
状态：正式子规范

直接上级规范：0050。

直接依赖规范：4015、4030、4190、4200。

相关边界规范：0500、1120—1190、2100、4201、4210、4220、ACCEPTANCE-01。

## 1. 定位

本规范冻结 L2 对场景、存在、特征、状态、动态和因果六类纯数据结构的唯一所有权、共同 DTO、生命周期、依赖方向、事务、读取、退出和生产外验证边界。

六类名称只标识强类型数据结构族，不授予 L2 判断现实世界、存在资格、特征意义、状态真实性、变化重要性、动作归因或因果真伪的权力。业务调用方必须位于 L5 之外，先完成业务裁决，再提交本规范允许的完整强类型结构请求。

本规范不定义具体 CRUD 函数、模块实现、骨架、装配或施工顺序。后继实现只能细化本规范已经冻结的合同，不得建立第七个“世界”数据服务、第二写入入口或兼容业务解释层。

## 2. 共同身份、枚举与请求结果头

### 2.1 强类型身份

合同版本固定为 `1`。以下身份均为彼此不同的中文强类型，内部只承载一个非零 `稳定编码`，不得隐式转换、按名称推断或跨类型替换：

```text
L2场景身份
L2存在身份
L2特征定义身份
L2特征实例身份
L2状态身份
L2动态身份
L2因果身份
```

写请求使用独立强类型 `L2结构幂等身份`，其值为非零 `uint64`。它只标识一份完整 L2 结构请求，不是任一结构事实、业务对象或 L1 事实编码。

### 2.2 读取类别与结构状态

```text
L2读取类别：
  当前=1
  历史=2

L2结构状态：
  已提交=1
  精确重复=2
  已读取=3
  未实现=4
  入口拒绝=5
  许可拒绝=6
  未找到=7
  已退出=8
  属性未设置=9
  事实代次漂移=10
  幂等冲突=11
  引用冲突=12
  资源失败=13
  内部不一致=14
```

`已提交`、`精确重复` 和 `已读取` 是携带完整成功载荷的状态。其它状态不得携带部分结构、默认补齐结构或混代材料。`未实现` 只供 4201 的最终合同骨架使用；真实入口完成后不得用它掩盖未覆盖分支。

合同版本不是兼容猜测字段。入口只接受版本 `1`；不兼容变化必须建立新的具名合同与 DTO 身份，并明确迁移或拒绝关系。

### 2.3 共同请求头与结果头

`L2结构请求头` 固定包含：

```text
合同版本
期望事实代次
```

写请求还必须包含绑定完整请求语义的 `L2结构幂等身份`。期望事实代次用于写前基线校验和同截止读取；不匹配时返回 `事实代次漂移`，不得返回混代载荷或产生数据变化。

`L2结构结果头` 固定包含：

```text
合同版本
L2结构状态
事实截止代次
可选变更事实代次
```

成功读取的事实截止代次必须非零。成功写入的变更事实代次是本次原子发布的新代次；精确重复返回首次请求的原结果，不再次推进代次。没有发生变更的结构化非成功不伪造变更事实代次。

## 3. 共同值式 DTO

### 3.1 有序引用

`L2有序身份引用` 固定包含非零顺序和目标稳定编码。同一角色组按“顺序、目标稳定编码”升序形成唯一稳定投影；顺序相同且目标相同的重复项、零顺序和零目标在写前拒绝。

有序引用只表达结构角色和顺序，不证明目标的业务资格、动作成立或因果真实性。

### 3.2 属性提交项与属性事实

`L2属性提交项` 固定包含：

```text
属性类型身份
原始值材料
来源稳定编码
```

原始值材料只能是下列四类之一：

```text
I64
I64组
U64组
独立材料引用
```

不得接收通用 JSON、裸字节、字符串拼接、无类型联合容器或调用方指定的 L1 当前值编码。材料必须与属性类型允许的表示种类匹配；L2 只校验类型和结构，不解释单位、轮廓、颜色、位置、业务时间或其它业务意义。

`L2属性事实` 固定包含：

```text
属性类型身份
值稳定编码
类型化不可变材料
来源稳定编码
创建事实代次
可选退出事实代次
```

属性事实是调用方拥有的完整值式投影，不泄漏 L1 属性槽对象、内部材料路径或可变值对象。无显式顺序的属性组按“属性类型身份、值稳定编码”升序返回。

### 3.3 生命周期

`L2生命周期` 固定包含非零创建事实代次和可选退出事实代次。退出代次存在时必须大于等于创建代次；已退出事实不得复活、原地覆写或重新成为当前事实。当前入口不返回已退出事实，历史入口可以返回其完整生命周期。

### 3.4 完整投影边界

六类结果只返回本规范定义的完整值式事实。节点、关系和值的稳定编码、属性、来源和生命周期均须来自同一非零事实截止代次；不得用当前事实补历史缺项，也不得用默认值、缓存、SQL、材料目录或其它代次记录补齐结构。

L2 DTO 不得携带 L1 本地键、中性写集、仓库、锁、事务、候选、撤销权、SQL、缓存写权或材料内部路径。

## 4. 六类唯一所有权与事实形状

### 4.1 场景结构

唯一所有者为 `L2场景结构服务`，DTO 物理所有者为 `L2场景结构.数据.h`。

`L2场景父子关系事实` 固定包含关系稳定编码、父场景身份、子场景身份、非零顺序和生命周期。一个当前子场景至多有一个当前直接父场景；父子关系不得形成结构环。没有当前父关系的场景只是结构根候选，不因此取得现实世界或业务根资格。

`L2场景成员关系事实` 固定包含关系稳定编码、场景身份、存在身份、非零顺序和生命周期。同一场景与同一存在之间至多有一条当前直接成员关系；该关系只表示结构成员，不证明所在场景或成员资格。

`L2场景事实` 固定包含场景身份、生命周期、完整固定属性组、完整直接子场景关系组和完整直接成员关系组。两个关系组均按共同有序引用规则稳定排序。

场景服务唯一负责场景节点、固定属性、父子关系和成员关系的创建、替换与退出，并公开按存在查询场景成员关系的反向值式投影。它不得判断现实世界、所在场景、成员资格或建立独立世界登记。

### 4.2 存在结构

唯一所有者为 `L2存在结构服务`，DTO 物理所有者为 `L2存在结构.数据.h`。

`L2存在事实` 固定包含存在身份、生命周期和完整固定属性组。存在服务唯一负责存在节点与固定属性的创建、换代和退出，不写场景成员关系，也不判断存在真实性或业务资格。

“被哪些场景成员关系引用”使用存在 DTO 定义的值式引用组，但只能由场景所有者的公开反向结构查询提供。存在服务不得反向 import 或调用场景服务；调用方需要该组合时分别消费存在事实和场景反向关系投影。

### 4.3 特征结构

唯一所有者为 `L2特征结构服务`，DTO 物理所有者为 `L2特征结构.数据.h`。

`L2特征定义事实` 固定包含特征定义身份、生命周期和完整固定属性组。

`L2特征实例事实` 固定包含特征实例身份、宿主存在身份、特征定义身份、生命周期和可选当前特征值事实。宿主与定义引用是结构关系，不授予业务适用性或值域解释。

`L2特征值事实` 固定包含值稳定编码、特征实例身份、类型化不可变材料、来源稳定编码和生命周期。一个当前特征实例至多有一个当前值；值换代建立新值、退出旧值并切换当前引用，旧值保留为历史。

按存在读取的当前特征组必须返回该存在的完整当前实例组，并按特征实例身份稳定编码升序；每个实例的定义、宿主和当前值投影共享同一事实截止代次。

特征服务唯一负责定义、实例槽、宿主 / 定义引用、当前值换代以及实例 / 定义退出。它不得按轮廓、颜色、位置或其它业务名称建立专用 CRUD，也不得解释值的业务意义。

### 4.4 状态结构

唯一所有者为 `L2状态结构服务`，DTO 物理所有者为 `L2状态结构.数据.h`。

`L2状态事实` 固定包含：

```text
L2状态身份
主体存在身份
特征实例身份
精确值属性事实
时间值属性事实
来源稳定编码
L2生命周期
```

主体与特征实例使用 L1 关系事实引用；精确值、时间值和来源使用状态节点的属性槽、值事实或具名结构引用承载。状态服务只保存调用方完整提交的状态记录及其引用替换 / 退出，不判断状态真实，也不从当前特征自动补造状态。

### 4.5 动态结构

唯一所有者为 `L2动态结构服务`，DTO 物理所有者为 `L2动态结构.数据.h`。

`L2动态事实` 固定包含：

```text
L2动态身份
主体存在身份
前状态身份
后状态身份
起始时间值属性事实
结束时间值属性事实
来源稳定编码
L2生命周期
```

主体、前状态和后状态使用 L1 关系事实引用；时间和来源使用动态节点的属性槽、值事实或具名结构引用承载。主体、前状态和后状态是三个彼此独立的强类型结构引用：动态服务必须分别经存在结构公开读取证明主体引用是合法 `L2存在身份`，经状态结构公开读取证明前 / 后状态引用是合法 `L2状态身份`；错类型、坏引用或混代不得以普通节点、空载荷或默认身份补齐。

动态结构不要求主体等于前状态主体或后状态主体，也不要求前后状态彼此不同、值发生变化或时间有序。三者的业务一致性由 L5 之外调用方裁决；L2 只校验各自强类型结构和共同截止。动态服务只保存调用方完整提交的动态记录及其引用替换 / 退出，不比较状态、不生成动态、不判断变化重要性，也不执行动作归因。

### 4.6 因果结构

唯一所有者为 `L2因果结构服务`，DTO 物理所有者为 `L2因果结构.数据.h`。

`L2因果事实` 固定包含：

```text
L2因果身份
非空有序条件状态引用组
可空动作引用
非空有序结果状态引用组
来源稳定编码
L2生命周期
```

条件和结果项均使用 `L2有序身份引用` 指向状态身份。动作为空是合法结构；非空动作只是不透明稳定编码，L2 只经 L1 验证其当前节点形状，不依赖任务、方法或其它业务服务。

因果服务只保存调用方完整提交的因果记录及其引用替换 / 退出，不判断因果真实、必然、主动或被动，不推断动作，也不自动补条件或结果。

## 5. 关系归属与单向依赖

场景父子 / 成员、特征宿主 / 定义、状态主体 / 特征、动态主体 / 前后状态、因果条件 / 动作 / 结果均是 L1 关系事实。固定属性、精确值、时间值和原始材料均由属性槽和值事实承载。任何 L2 服务都不得复制关系成员为第二权威当前列表；完整组只是在一个截止代次内形成的值式投影。

依赖方向固定为：

```text
L2场景结构 -> L1事实基座
L2存在结构 -> L1事实基座
L2场景成员关系 -> L2存在结构公开读取 + L1事实基座
L2特征结构 -> L2存在结构公开读取 + L1事实基座
L2状态结构 -> L2存在结构公开读取 + L2特征结构公开读取 + L1事实基座
L2动态结构 -> L2存在结构公开读取 + L2状态结构公开读取 + L1事实基座
L2因果结构 -> L2状态结构公开读取 + L1事实基座
未来 L2 聚合公开面 -> 六类服务；零写入所有权
```

不得增加反向 import、同层循环依赖、跨所有者仓库访问或不存在结构依赖的转发层。存在服务不依赖场景服务；场景反向关系查询由场景所有者提供。未来聚合公开面只能持有并转发六类公开服务，不能形成第二写入入口、第二 DTO 解释或业务门面。

## 6. 共同事务、幂等与读取

1. 每次创建、替换或退出由目标结构唯一所有者形成一份不可变 L1 中性写集，并恰一次提交。关系替换、值换代、旧事实退出和新当前引用必须在同一事实代次原子发布。
2. 同一 `L2结构幂等身份` 与逐字段完全相同的完整请求返回 `精确重复` 和首次原结果；同一身份绑定不同请求语义返回 `幂等冲突`，零变化。不得以记录已存在、摘要相同或业务同义冒充幂等。
3. 期望事实代次不符返回 `事实代次漂移`，零变化。发布结果未知时只能使用原幂等身份和原完整请求读回收敛，不得生成新编码或改写请求重试。
4. 当前组合读取只能使用 L1 一致当前投影；节点、关系、值、属性和引用组必须共享一个非零事实截止代次。一次允许的重试后仍漂移时返回 `事实代次漂移`，不得返回部分结构。
5. 历史读取必须显式使用 `历史` 类别，并从历史节点、关系、值和生命周期重建完整结构。不得使用当前事实补历史缺项，也不得把已退出事实重新标为当前。
6. 当前属性不存在返回 `属性未设置`；目标不存在返回 `未找到`；目标已退出且从当前入口读取时返回 `已退出`。三者不得互相折叠。
7. 任一成功结果缺项、身份复义、同一结果混代、关系角色矛盾、属性槽复义或发布后读回矛盾均返回 `内部不一致`，停止依赖路径；不得降级为未找到、资源失败或业务拒绝。

## 7. 引用保护与退出

1. 退出请求必须显式处理本结构所有的当前附属关系和值；不得按业务名称自动推断要退出的引用。
2. 目标仍被当前关系、属性、值来源或独立材料引用时，且这些引用未在同一合法写集中闭合，返回 `引用冲突`，整笔零变化。
3. 跨结构引用统一由 L1 当前关系和引用闭包保护；较低层服务不反向依赖全部消费者，也不得扫描上层业务服务补造退出项。
4. 退出成功只改变当前可见性并保留完整历史。物理回收、崩溃恢复、跨进程恢复和持久证据清理不属于六类普通 CRUD。

## 8. 生产外验证边界

六类真实实现分别由生产代码之外的验证者，经正式公开强类型入口输入可修改参数，并至少逐叶覆盖：

1. 合法创建后完整当前读回；
2. 零身份、错类型、坏引用、坏顺序、旧期望代次等非法请求返回结构化非成功且权威状态零变化；
3. 同键同完整请求精确重复、同键异请求幂等冲突；
4. 当前或条件查询结果完整、稳定排序且共享一个事实截止代次；
5. 替换后新事实为当前、旧事实可从历史入口读取；
6. 引用未闭合时退出冲突且零变化，引用闭合后退出成功、当前不可见且历史仍可查；
7. 适用的组合写原子性、并发漂移和发布后读回一致性。

验证驱动不得编译进生产目标，不得取得 L1 / L2 私有仓、锁、候选或事务权限，不得构造业务资格、真实世界、真实状态、动作成立或因果真伪剧本。生产日志、自检、编译、骨架、退出码和未观察到错误均不能裁决通过。

## 9. 完成边界与禁止事项

本规范生效只证明六类纯结构的正式所有权、DTO、依赖和验证边界已经冻结，不证明任一模块、函数、骨架、CRUD、聚合面、生产接线或业务闭环已经实现。

禁止：

- 在 L2 判断世界、存在、特征、状态、动态或因果的业务真实性；
- 建立第二世界登记、第二事实仓、第二当前值或第二关系解释；
- 为轮廓、颜色、位置、动作或业务场景建立专用结构 CRUD；
- 从特征自动形成状态、从状态自动形成动态或从历史统计自动形成因果；
- 直达 L1 仓库、锁、事务、SQL、材料目录、缓存或内部写集；
- 用 4210、4220 的上层业务解释覆盖本规范的 L2 纯结构合同；
- 用 `未实现`、编译、日志或单条成功路径宣称结构服务完成。
