## 1. 范围和能力边界

本规范规定二次关系概念（下称RC）的逻辑结构、规范化、读取、建立、来源与用途、图与生命周期治理，以及调用期RC、特征概念约束（FC）和存在概念约束（EC）求值的完整合同。C++类型、头文件、构造签名、物理编码与初始化写集属于施工内容，不在本规范内，见第10节。

1. RC是唯一概念owner内、类别为`特征`的概念，挂在特征根之下，遵守特征概念单父规则（2220、7160）。它不是新节点族、新根、独立仓库或二次特征实例。
2. 概念空间以四本体根为顶层，四根先天建立、各恰一（2220）。每个普通概念都有同类别上位链通到所属根；RC的上位链通到特征根。
3. 当次求值结果是调用方拥有的临时值。被状态或动态持有的二次特征按1180、4110、4211、4212建立和保存，不由本规范求值入口写入。
4. 二次特征的比较结果只能是具名I64（1180）。本规范的成功能力限定为已登记的有序I64差异、I64值域FC、以存在根为通用EC、由FC组成的具体EC，以及同一有序A/B的有限合取（AND）。非I64材料、未定义的非标量算法、非FC组成的EC、任意关系码判零、跨比较绑定无依据等价均有固定拒绝分支，不留给执行者临时决定；结构上不支持的算法或约束在建立前拒绝，不发布无法解释的半定义。
5. 本规范只承认当前事实：概念、定义、来源、用途和图均按当前状态维护，原地修订，撞同义直接复用（0050 §1.5）。不保存定义的旧内容，不按旧截止解释概念。

## 2. 定义和规范形

### 2.1 原子定义与合取定义

```text
结果方向D ∈ { <0, =0, >0, <=0, >=0, ≠0, 任意 }
约束角色 ∈ { 共同, A, B }
约束组 = FC约束项组 + EC约束项组（每项为：约束角色 + 概念身份）
原子定义 = D + 约束组 + 比较绑定K + 输出角色（本规范只允许“差异”）
合取项 = 子RC + 附加约束组
合取定义 = 共同约束组 + 合取项组（至少两项）
RC定义 = 原子定义 | 合取定义
规范形 = 非空原子定义组
```

1. 结果方向D取上述七种。方向按准确差异r判定：`r<0`、`r==0`、`r>0` 分别命中`<0`、`=0`、`>0`；`<=0`、`>=0`、`≠0`分别是对应两种的并，`任意`是三种的并（D为`任意`时仍须完成全部来源、FC、EC、K核验与实际计算）。空方向和未知方向拒绝。RC的D是概念层条件范围，与“同一持有者同类二次特征按结果方向唯一”（1180、4180 §9）是两回事，后者只约束实例持有，不限制RC可取的方向。
2. 输出只允许`差异`，不以排序码或具名关系码的符号冒充`A-B`。
3. 每个原子的A、B两方均至少有一个有效FC和一个EC。FC必须完整读回正式特征类型（FT）与I64值域，同一方的FC须约束K的同一输入FT。共同约束展开到双方，不覆盖单方附加约束。
4. 存在根可作为最通用EC，表示参与者只需是已成立的存在；它以真实存在根概念身份引用，不是空编码，也不是“直接上位为空的通用存在概念”。
5. K是正式I64比较绑定节点（4182），不是值、算法编号或函数地址。RC定义保存显式K；应用的省写输入须先经当前“FT＋用途”绑定解析为同一K，才进入查重。不得从可变化的当前路由反推已发布RC的K。

### 2.2 完整范围

每次操作的完整语义范围由请求中的RC或定义、全部FC/EC/K引用、全部合取子定义、显式来源与用途集合、组织方式和父概念共同确定。读取、规范化、查重、图核验、求值和删除都必须覆盖该范围的全部必要事实与依赖闭包；节点、关系、值、概念、原子、展开深度、候选、来源或用途的数量不得成为成功上限（0050）。

内部索引、缓存和分批只可降低执行成本，缓存只能复用同一调用内逐字段一致的当前事实。任何部分读取、无法继续展开、分配失败或计数溢出均返回`资源失败`或`内部不一致`，清空依赖完整性的业务载荷；不得截断成功或伪造`同义缺失`。

### 2.3 确定规范化

规范化同时用于建立、查找、读取互证和父子包含判定；只产生可丢弃的投影，不另存第二份定义权威。

1. 完整读取全部FC/EC/K和全部合取子定义，核验当前活跃性、类别、上位链和定义完整性。用灰集检查组成环；不因依赖数量或深度删减闭包。
2. 共同约束展开到A/B，再把外层与合取项附加约束同子定义每个原子的对应方合取。每方约束按概念身份排序、严格去重；双方完全相同的约束重新提取为共同项，其余保留具名A/B。不因已有通用约束而丢掉更窄的约束。
3. 合取无损展开为非空原子组。K、输出和完整角色化约束一致的原子合并为一项，其结果方向取交（例如`<=0`与`>=0`得`=0`，`>=0`与`>0`得`>0`）；交为空（如`<0`与`>0`）为`定义矛盾`。七种方向两两相交的结果仍为空或七种之一（例如`≠0`与`>=0`得`>0`，`任意`与X得X）。其余原子按完整键排序和严格去重。键序固定为`K、输出、FC项组、EC项组、D`，项组先比长度再按`角色、概念身份`字典序；A/B永不交换。
4. 每方同FT的多个I64域取精确交集；EC的FC组成逐项合取，可以机械证明域交集为空时拒绝。不同K或不同正式概念不从样本推定同义；没有正式跨K等价合同的转换不接受为等价请求。
5. 规范形只剩一项时按该原子查重；外层附加限制已并入原子，不能直接复用无约束的子RC。新建时存为原子，不建单项合取外壳；多项合取保存完整成员及附加约束，读取必须能无损还原同一规范形。
6. 查重比较完整规范形，摘要只用于候选定位，碰撞时逐项比较。一个规范形在概念owner内至多对应一个未退出的RC；出现重复为`内部不一致`。

### 2.4 组织方式

RC恰有一个直接上位（特征概念单父，2220、7160）：

1. **特征根下的顶层RC**：直接上位为特征根。
2. **具名上位RC**：直接上位为另一个RC，且有机械包含证明：子规范形包含父的每项判定量，子D是父D的子集，两方约束只增不减，额外条件只收窄。K不同不推定包含。

组织方式未指定、给出多个直接上位、跨类别、无包含证明、自环或成环均拒绝；数据层不替调用方选择上位。插入中间RC或删除中间RC时，下位改接按7140，替代边与目标变化在同一次组合发布中完成。组成边（合取项）不是上位边。

## 3. 结构保存和读取

1. RC复用概念owner的普通概念节点、不可变类别、定义成员、直接上位关系和生命周期（7140）；约束记录与合取项记录是概念owner内部的普通辅助节点，没有独立身份、owner或业务入口。
2. 一次结构写入只扩展概念owner，按4015以组合变化集一次发布：节点、类别、定义、定义引用、生命周期、直接上位边和请求中的合法形成来源同写同发布，零变化失败或完整成功。
3. 读取返回完整当前事实：RC身份、类别、完整定义、规范形、生命周期、直接上位，以及定义引用的全部目标身份。引用目标的内容由各自owner读取，本规范不复制。读取不返回半定义。
4. 读回必须逐项对应每个属性、约束、合取项和引用；缺边、多边、错owner、错格式或残留尾数据都不成功。

## 4. 结构操作

### 4.1 操作状态

| 状态 | 含义 |
| --- | --- |
| 已读取 | 完整读取成功 |
| 已创建 / 已变更 | 本次写入成功发布 |
| 已复用 | 命中活跃同义RC，零写 |
| 同义缺失 | 完整查找后无同义RC |
| 冷却命中 / 退役命中 | 命中冷却或退役的同义RC，携带完整定义供上层治理 |
| 未找到 | 给定身份不存在 |
| 入口拒绝 | 请求形状、角色或身份不合法 |
| 规则不支持 | 算法、输出、定义形状不在第1节能力内 |
| 来源不足 | 形成所需来源不完整 |
| 引用冲突 | 同一来源键内容不一致 |
| 定义矛盾 | 规范化后方向或域交集为空 |
| 形成环 | 组成或上位成环 |
| 资源失败 | 执行资源不足以完成完整范围 |
| 内部不一致 | 读回矛盾、重复同义身份等结构错误 |

`成功`只指本操作定义的成功状态：读取接受已读取、冷却命中、退役命中（调用方仍须判断能否采用，不能把读取成功等同于活跃可用）；建立接受已创建、已复用、冷却命中；治理接受已变更。其它状态成功恒为假，业务载荷为空。资源异常映射`资源失败`，其余未预期异常映射`内部不一致`；技术故障不当作`同义缺失`或`不命中`。

### 4.2 规范化、查找和建立

1. **规范化**：零写，只执行第2.3节算法并完整核验引用；不扫描同义、不建立RC。成功时返回非空完整规范形。查找、建立和候选求值复用同一概念owner内的这一能力，不在业务模块复制规范化器。
2. **查找**：在不可变特征类别中完整搜索全部RC定义。完整未命中为`同义缺失`；命中按生命周期返回`已读取`、`冷却命中`或`退役命中`。
3. **建立**：完整核验定义、来源、组织方式和上位→查找同义→未命中时构造一个概念owner组合变化集发布→完整读回。活跃同义返回`已复用`、冷却同义返回`冷却命中`，均零写，不把本次的上位或形成来源自动补写到既有RC，补写须走第4.3或4.4节的具名操作；退役同义返回`退役命中`且建立不成功，由上层按7140决定是否恢复为活跃，不另建新身份。
4. 并发写入在概念owner写锁内串行；后到的建立在锁内重新查找，命中先到者的RC即复用。

### 4.3 来源与用途

1. **形成来源**：可为实例特征F、状态S或概念（FC/EC/子RC）。来源不是定义，也不自动算作用途。F由特征owner完整读取并核验其持有者；S由状态owner按4212完整读取，取得S记录的F、准确值与强时间；概念由概念owner完整读取。普通世界支持与形成来源分开记录，不虚构临时二次结果节点。
2. 来源请求非空，按`来源种类、来源身份`规范排序；同一RC、同一来源至多一条，重复同内容复用原记录，不当作新增。全部已存在时返回`已复用`、零写；部分已存在时只创建缺项。
3. **用途**：角色固定为1=关系判断采用、2=识别选择采用、3=条件采用、4=语言采用，其它值拒绝。业务标识非零，业务依据必须是可核验的已发布业务节点，不是函数返回值、裸布尔或临时二次结果。结构服务只核验合法节点及引用，不替应用证明业务发生；调用者必须已经实际完成对应采用。去重键为`业务标识、RC、用途角色`，同键异内容拒绝。用途计数从用途记录重建，读失败不是0。
4. 来源和用途读取均返回完整记录组，合法空组可以成功；来源读取不混带用途，用途读取不混带来源。

### 4.4 图、生命周期、来源释放和删除

1. **图读取**：完整读取特征类别中全部未删除RC（含冷却、退役），按身份严格升序；直接边只包含RC→上位的真实直接边，不混入组成边。成功要求全部节点和边完整、无环、每个RC恰有一个直接上位。
2. **替换上位**：请求须精确给出当前直接上位边和新上位，新上位满足第2.4节；替换保持无环，与改接同次发布。
3. **生命周期**：只允许7140规定的迁移，治理依据必须是真实已发布节点；同态迁移或预期状态不符拒绝。
4. **来源释放**：只释放给定的完整预期来源记录；不能借此解除定义中的K/FC/EC/子RC或用途依据。
5. **删除**：RC须先为退役，且经引用闭包查询确认没有有保护力的引用——名称、其它概念的定义引用、因果与动态概念引用、需求目标引用、用途依据中的正式引用（0050 §1.5、7140）。引用计数只作快速判定，与闭包结果不一致按`内部不一致`。定义入边即使来源已释放仍阻止删除。删除时同时删除本owner的用途记录、来源记录和自有边与值；下位RC按7140改接，替代边与删除同次发布。不得删除F、值、S、存在或K。删除后的概念编码不复用；同义的新RC为新身份。

## 5. 调用期RC、FC、EC求值

求值位于DATA之外，没有写端口；所有结果是调用方拥有的临时值，不写入状态、动态或概念。

### 5.1 输入

```text
特征来源 = 实例特征F | 状态S | 本能根目标值
参与者材料 = 存在E + 非空特征来源组
RC求值请求 = 请求身份 + RC + A材料 + B材料
FC求值请求 = 请求身份 + FC + 参与者材料 + 来源下标
EC求值请求 = 请求身份 + EC + 参与者材料
候选求值请求 = 请求身份 + RC定义 + A材料 + B材料
```

1. 同一方来源组无重复，同方同FT只允许一份来源；同FT不同值不由服务挑选，返回`入口拒绝`。A、B可以是同一E（用于时间比较）；不得交换角色去迎合期待结论。有序角色由RC和K决定。
2. 同一方不得混用F、S与本能根目标值三类来源。
   - **F**：E当前持有的实例特征，取其当前值。由特征owner完整读取并核验F的持有者是E。
   - **S**：明确的观察端点。由状态owner完整读取S，取得S记录的F、准确值与强时间，并核验F的持有者是E。同一方的全部S必须属于同一场景状态列表且强时间相同，不能用读取时间相同冒充同时观察。不同方的时间可以不同。
   - **本能根目标值**：接受安全根或服务根。求值器以`根角色＋根需求D＋目标信息节点E＋目标FT`调用需求owner读取口，核验D与目标值（3100：目标由F承载）；目标I64只取需求owner的成功材料，请求不得自带值或FT。求值器再按E＋FT定位唯一实际F并完整读取。安全根与服务根不得交叉复用FT、F或目标。此类来源只用于既有RC的当前求值，不进入候选求值、形成来源、概念支持或用途登记。
3. S记录的值经特征值owner完整读取取得I64，不对值节点身份做运算。来源读取未找到为`证据不足`；已删除为`证据不足`；非I64或算法不支持为`规则不支持`；错E或来源冲突为`入口拒绝`或`内部不一致`。任何provider未实现都不能映射为空来源成功。

### 5.2 判断状态

| 状态 | 含义 |
| --- | --- |
| 命中 / 不命中 | 全部必需项完整计算后的结论 |
| 证据不足 | 缺来源、来源已删除，或饱和结果用于需要精确幅度的条件 |
| 规则不支持 | 非I64、算法或输出不在能力内、跨K无等价依据 |
| 入口拒绝 | 请求形状、角色、来源混用或反置 |
| 退役不可用 | 当前RC为退役 |
| 类型不相容 / 单位量化不相容 / 参照不相容 | 输入与K的正式要求不符 |
| 资源失败 / 内部不一致 | 技术故障与结构矛盾 |

结果不提供通用布尔成功捷径；消费者只按结构化状态和该入口的载荷合同判断。非成功时条件组、来源组和已核验概念全部为空，不把失败解释为不命中。

### 5.3 准确算法

1. 核验请求形状与请求身份非零。读取RC完整规范形或FC/EC定义；当前退役返回`退役不可用`；冷却可以求值，但不自动恢复、不记用途。
2. 完整解析全部显式来源，核验同方E、场景、强时间及FT唯一性，取得准确I64和来源见证。每个原子按K的输入FT在A、B各找唯一来源；缺项为`证据不足`，不得用另一FT或数值相同的来源代替。
3. **FC**：完整读取FC的正式FT与规范I64闭区间组，要求来源FT相同；按精确I64集合判定，0和I64端点合法，区间判定只做比较，不做可能溢出的相减。
   **EC**：存在根作为EC时，E是已成立的存在即命中；具体EC逐项读取其FC组成，对同一方对应FT的来源执行同一FC判定，并递归核验子EC。缺来源为`证据不足`；不同观察时间的S不得拼凑一个EC。
4. 对每个原子的K调用4182完整读取，核对算法族、输入FT、用途、左右角色、量化、输出与上下文要求；再按当前“FT＋用途”读取确认合法路由，并须唯一命中同一K。不同K在没有正式跨K等价合同时返回`规则不支持`。K已删除、路由缺失或已被替代时不另选规则。
5. 输入物理左=B、右=A，结果为`difference(B,A)=A-B`；只向比较提供者传递已核验的I64。上下文要求的参照由E/S完整材料满足，无法证明时返回`参照不相容`，不补零参照；FT、单位、量化不相容时不进入算法。
6. 差异溢出按4180第9节口径（0300 R30）饱和为`INT64_MAX`或`INT64_MIN`并带“已饱和”标记，方向保持正确。RC的结果方向D只依赖符号，饱和结果可以判定方向；FC等需要精确幅度的判定遇到饱和结果返回`证据不足`。
7. 准确差异r按第2.1节第1项得到方向，与D比较。原子命中=FC命中且EC命中且方向命中；合取须全部原子命中。
8. 即使某项已不命中，也必须完成其它必需项的来源核验和计算，不以假值短路掩盖缺源、资源或结构错误。全部项完整后才返回命中或不命中及全部逐项结果；失败时不返回可被视为整体成功的部分条件组。
9. 每个入口在返回前完成后置核验：请求身份、来源见证与已核验概念完整；RC与候选结果的条件组与规范形逐项对应，且返回状态与全部条件的合取一致；FC/EC结果条件组为空，状态与本次实际判定一致。任一矛盾映射`内部不一致`。

### 5.4 候选求值

首次形成时还没有RC身份。候选求值先调用第4.2节规范化，再执行第5.3节算法，不写，不自造FC/EC/K；它与RC求值只有定义来源的差别，不是第二套算法。

## 6. RC形成应用

1. 应用顺序：候选求值→完整查找同义→建立或复用→完整读回定义→添加真实F/S/概念形成来源。请求须提供已裁决的FC/EC/K；缺FC或EC由各自的形成应用先完成，不能临时用存在根掩盖不支持。
2. 只有候选命中且来源完整时才进入查找与建立；不命中不能作为成立依据。
3. 定义已发布而来源添加失败时，应用保留已发布的RC身份并报告“定义已发布、来源未完成”，不报告回滚；重试先查同义复用，不重复建立RC。
4. 形成成功仅指候选命中、定义与来源两步都成功且身份互证。名称由正式名称应用另行处理，不在形成成功之内。真实用途由实际消费方在完成业务采用后按第4.3节登记，形成本身不记用途。
5. 所有来源值和定义材料来自请求及正式provider，应用不自建概念仓，不直接持有概念owner的写端口之外的通道。

## 7. 消费者边界

1. 动态概念（7190、7191、7193、7194）只经本规范求值公开面使用RC；动态端点以状态S传入，不能只把裸I64送入计算。
2. 因果（4340）若接受RC作为条件约束，须调用RC完整读取，不能只看特征类别。
3. 6120/6130的根目标比较固定A为目标值、B为当前F，侧位反置在该业务入口返回`入口拒绝`。
4. 本规范不改变状态、动态对二次特征的持有口径（1180、4211、4212），也不改变场景组织。

## 8. 不在本规范能力内

非I64比较、无界全场扫描、跨K自动等价、语言命名策略、现实动作执行、动态概念生成和因果真伪判定不在本规范内。缺来源返回具名非成功，不开放任意I64入口补齐。
