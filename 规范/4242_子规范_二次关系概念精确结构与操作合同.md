## 1. 范围和能力边界

本规范冻结RC结构提供者、调用期RC/FC/EC求值、RC形成应用的源级C++合同及物理表示；不承诺跨工具链二进制布局，不以C++对象内存镜像持久化。本合同的发布不表示代码、生产装配或数据库恢复已经实现。

RC是唯一概念owner内的专属定义，不是新节点族、第五本体根、独立CRUD仓库或二次实例。结构写入只扩展`概念树类数据服务`。求值及形成位于DATA之外，前者没有写端口；所有当次准确比较结果均为调用方拥有的临时值，不扩大C038的实例持久化权限。

本版成功能力限定为已登记的有序I64差异、I64值域FC、存在根及由此类FC模板组成的EC、同有序A/B的有限AND。完整读取为I64的值事实引用与内联I64等价；非I64材料、未定义的非标量算法、非FC模板EC、任意关系码判零、跨K无依据等价均有固定拒绝分支，不留给执行者临时发明。结构定义不支持的算法或约束在建立前拒绝，不能发布本版永远无法解释的半定义。

## 3. 定义、规范形和预算

以下定义位于RC合同模块；使用的标准容器和值类型以所示签名为准，全部值式DTO的默认比较是逐字段比较。

```cpp
struct 二次关系结果域 final { std::uint8_t 掩码=0; };
enum class 二次关系约束角色 : std::uint8_t { 共同=1, A=2, B=3 };
struct 二次关系概念约束 final {

    概念树概念身份 概念;
```

D合法值恰为1至7，NEG=1、ZERO=2、POS=4；0与未知位拒绝。输出本版仅允许`差异`，不以排序码或具名关系码的符号冒充`A-B`。每个原子两方均至少有一个有效FC和一个EC，FC必须完整读回正式FT与I64域；每方FC须约束同一K输入FT。共同约束展开至双方，不能覆盖单方附加约束。合法存在根可作为最通用EC，但必须是真实根身份，不是空编码。

K使用正式I64绑定节点，不是值事实、算法编号或函数地址。当前FC没有不可变的FC→K唯一推导链，因此v1原生定义一律保存显式K；应用的省写输入必须先通过当前FT+用途绑定解析为此同一强身份，才进入定义查重。不能从可变化当前路由推断已发布RC的K，也不增加重复业务版本字段。

每个非零预算均为硬上限；所有字段均须非零，0不解释为无限。读取材料按真实节点/关系/值事实逐项计量，关系数是材料数子集，缓存只抑制同调用同截止同事实的重复读取。展开深度计最长依赖路径，不按缓存命中归零。首次材料计入原生首次写集完整数量。任何上限超过即失败，不能截断为成功；计数和本地序号使用检查加法，溢出按预算不足。

### 3.1 确定规范化

规范化同时用于建立、查找、读取互证和父子包含；只产生可丢失投影，不另存一套完整定义权威。

1. 读取全部FC/EC/K和所有AND子定义，固定同一Gread/H，检查当前用途所需活跃性、类型、根及定义完整性。DFS灰集检查组成环，黑集可复用完整读回；预算按实际读取、展开项数和深度计量。
2. 将共同FC/EC展开至A/B，再把外层和项附加约束与子定义每个原子的对应方合取。每方约束按`概念编码`排序，严格重复去重；双方完全相同的约束重新提取为共同项，其余保留具名A/B。不因已有通用根而丢掉更窄约束。
3. AND无损展开到非空原子组。K、输出、FC/EC完整角色化约束一致时，对D作按位与；得到0为矛盾拒绝。其它原子按完整键排序和严格去重。键序固定为`K编码、输出枚举、FC项组、EC项组、D掩码`，项组先长度再按`角色、概念编码`字典序；A/B永不交换。
4. 每方同FT的多个I64域取精确交集；EC模板逐项合取，能够机械证明其FC域交集为空时拒绝。不同K或不同正式概念身份不从少量样本推定同义；没有正式跨K等价合同的转换不接受为等价请求，也不因查重困难生成替代身份。
5. 规范形只剩一项时，完整含义按该原子查重；存在外层附加限制时已纳入原子，不能直接复用原无约束子RC。新建时存为原子，不建单项AND外壳；多项AND保存完整显式成员及附加约束，读取仍须能无损还原相同规范形。
6. 查重比较完整规范形，摘要只作候选定位；碰撞逐项比较。完整扫描前失败不是同义缺失。一个规范键至多一个活跃/冷却/退役未退出身份，重复事实为内部不一致。已不可逆退出的同键历史不阻止新身份建立。

新RC父边至少一条。允许特征本体根，或有机械包含证明的同根RC：子规范形必须包含父的每项判定量，子D是父D子集，两方约束只能增加、不能减少；额外谓词只收窄。相同K以外不猜测包含。首次未给父组时入口拒绝，不由数据层擅自选择父。中间插层及多父图仍按7140，组成边不当父边。

后三组是完整结构读回的无owner见证，不是可回写原始事实的请求。只包含RC定义和生命周期/根/父边所需结构，不包含可独立释放的形成来源或用途，引用目标由各自provider读取；归属和角色在服务内部核验，公开字段不含L1 owner或owner生命周期。节点见证只接受内部已核验的普通结构节点；关系和值见证从精确事实裁剪得到。所有见证组按编码升序无重复，不能拿节点存在代替领域完整性。

发布见证只由真实L1写入结果裁剪，禁止暴露其owner字段。版本1、非零幂等身份和发布H、已确认发布为true、L1成功/精确重复已在内部互证后，才是确认发布见证；新编码映射按本地键升序且键/编码均非零唯一。发布未知可以保留已取得的真实见证，但不能把未确认回执标成已确认。它不是独立发布账，清空不改变L1首次材料。

交付中锚点、规则及全部类型非零、同owner、当前有效，各具名类型两两互异；锚点只是格式登记节点，不是RC根。通过`扩展登记`从锚点到类型依声明顺序以角色1至22登记；锚点通过既有`规则归属`关系角色1指向规范化规则。锚点`定义格式`属性I64=1；规则使用既有格式版本/规则版本两项I64=1。规范化规则固定解释本节，不另复制算法K定义。所有类型必须使用已交付真实编码，不写死节点号。

初始化本地键固定：1=扩展锚点、2..23=声明顺序的22类型、24=规范化规则、25=锚点格式值、26=规则格式值、27=规则版本值、28=base登记边、29..50=22条扩展登记、51=锚点到规则的归属边。属性类型节点明确为：定义种类/定义格式/域掩码/输出角色/用途角色/用途时间采用I64；来源截止/用途业务标识采用U64组；其余关系类型由`节点种类::普通`节点承担，属性节点使用`节点种类::属性类型`及相应值表示，不能发明L1关系类型枚举。所有节点种类及属性表示依L1正式合同创建，不能把属性类型建成普通节点。

该51项同一写集创建，四根及base唯一签名规则关联不新增不替换。已有完整锚点则读回复用且零写；多锚点/半交付为内部不一致，不尝试补建。首次键依L1首次材料重放；同键异写集冲突；接受后不换键。成功只已创建/已复用/精确重放且交付及全部原生事实完整、截止精确；已复用无回执，创建/重放有无owner发布见证及H。派发后未知只保留真实见证及截止、交付为空；本函数不替调用方启动生产装配。

| RC共同头 | 既有`概念种类`I64使用新值5，旧1至4不改义（7191新DC为6）。RC具有`定义格式=1`、`定义种类`I64；种类1=原子、2=AND。既有根归属指向特征本体根，既有规则关系指向交付的规范化规则，生命周期初始活跃；初始直接父边同写。 |

| FC/EC约束 | 每个约束一个记录节点。所属RC或合取项经`约束成员`角色1起连续顺序指向记录；记录恰有一条`约束FC`或`约束EC`，角色1/2/3解释共同/A/B，目标为概念节点。两种目标不可同存。 |
| AND | RC经`合取成员`角色1起连续顺序指向合取项记录，记录经`子RC`角色1指向已发布子RC；项上附加约束按上一行组织。RC自身的约束成员保存共同约束。AND没有域、输出或K属性/边。 |
| 形成来源 | RC经`来源成员`角色1指向来源记录；记录由`来源F/来源B/来源概念`三者之一角色1指向正式来源节点，并有`来源截止`U64单元素组`[H]`。来源无持久位置次序，按记录身份读回，释放部分来源不制造非法序号洞。 |

U64材料恰为上述具名单元素组，不存整个C++DTO、裸句柄列表、JSON或内存字节。I64数值直接使用类型化I64材料；无宿主端序编码。缺项、多项、非连续顺序、未知位、错误材料种类/长度、串行角色、混合原子/AND、交付与owner不匹配，均拒绝完整读回。解码是编码的严格逆，不忽略尾部材料。`定义引用`中原子K使用RC为记录、所属关系为固定K关系自身、项/约束顺序为0；其它项按真实所属层和序号定位，不能把F或值事实身份当K/概念关系端点。

建立活跃/冷却同义复用分别返回`已复用/冷却命中`，零写、无新幂等绑定、无正式回执和首次H；退役命中返回退役命中且成功谓词为false，禁止换键重建。新建或技术精确重放要求正式回执成功、首次H非零、事实完整且`事实.H=首次H<=Gread`。已复用/冷却命中成功要求`事实.H=Gread`、无回执/首次H。其它状态成功恒false。

派发前任何非成功的事实、回执、首次H为空；退役命中允许完整事实但不允许建立成功。派发后已知提交但读回失败或回执不确定统一`发布未知`，保留原完整请求、已有真实回执和首次H，不携带成功事实，不得谎报零写。所有公开函数捕获资源异常为资源失败、其余未预期异常为内部不一致；派发后异常优先发布未知。读取非成功不返回半定义。

## 6. 发布、来源、治理与退出闭合

### 6.1 创建和幂等

建立先读取owner首次写入材料；已绑定相同键时按首次规范化写集重建业务定义、初始父组和来源，再与本次请求规范含义比较。预算不是业务语义，不持久化为RC字段；重放预算不足返回预算不足，不能变更首次写集。首次记录不保存C++请求或应用回执，恢复不依赖进程缓存。原写入头期望G及已接受写集按L1合同参与重放校验，不能用新G覆盖已接受请求。

首次创建顺序为：固定G0→全部定义/来源/父边完整核验→同键全候选检查→构造一个概念owner写集→L1 G0守卫提交→用`Gread>=Gpub,H=Gpub`独立完整读回。节点、不可变定义、定义引用、根归属、规则、活跃生命周期、初始父边、请求中的合法形成来源同写同发布。另一个写者改变G0时零副作用返回漂移，重读后复用已成立身份，不能无守卫重试。

同义复用不把本次初始父边或形成来源自动补写到旧RC；须由后继具名操作单独建立。完整定义查找、写集接受前失败和并发漂移不得绑定幂等身份；接受后重试必须保留原键，先收敛再处理新请求。退出和生命周期修改不使旧创建键取得新建资格。

### 6.2 来源和用途专属操作

### 7.3 准确算法

1. 先校验请求形状与全部预算、请求身份非零、`0<H<=Gread`，固定读取守卫。读取RC完整规范形或FC/EC模板；当前退役返回退役不可用，冷却允许真实求值但不自动恢复或记用途。
2. 对所有显式来源先完整解析，验证同方E/C/强时间及FT唯一性。取得对应准确I64和完整源见证。每项RC按K输入FT在A/B各找唯一来源；缺项为证据不足，不能取另一个FT或数值相同的来源代替。
3. FC求值：完整读取FC的正式FT与规范I64闭区间组，要求来源FT相同；按精确I64集合判定，0和INT64端点合法，区间命中只用比较不做可能溢出的相减。EC求值：存在根在E身份成立后命中；非根EC逐项读取其FC模板，对同一方材料中对应FT的来源执行同一FC判定。模板缺源为证据不足，模板为空的普通EC不冒充根；不同采样时间的B不得凑齐EC。
4. 对每个原子显式K调用`读取I64比较绑定({1,Gread,Gread,K})`，核对本版算法族/版本、输入FT、用途、左右角色、量化、输出存在性、差异方向及要求上下文。随后调用`读取当前I64比较绑定({1,Gread,K.输入FT,K.用途,剩余候选预算,剩余材料预算})`确认本次合法路由，必须唯一命中同一K；不同身份在本版没有已登记跨K等价证明时返回规则不支持，不仅凭同样几个样本或算法名认定相容。K用途允许识别区分、变化分析、场景关系、目标判断、概念材料，但必须使用该用途已登记的角色；不得把用途号当算法号。固定K不被最新路由替换，也不豁免当前路由准入；K已退出、路由缺失或已被替代均不重新选规则。
5. 输入物理左=B、右=A，不管用途枚举的名称如何；填K原有左右角色，要求结果位仅4（差异）。本版K须没有未被其正式类型/来源证明的额外参照要求；上下文要求中的参与者和时间由上述E/B/S完整材料满足，要求参照但来源无法证明时返回参照不相容，不补零参照。两个输入的FT及单位/量化必须与K相容；取值错误不进入算法。
6. 组装有序I64快照：来源为当前独立绑定，K及所有字段取刚读回的真实绑定，`Gread=H=请求Gread`，只向纯提供者传递已核验的I64。公开比较结果必须版本正确、成功、K/FT/角色/量化完整且唯一差异输出；`difference(B,A)=A-B`的溢出由提供者结构化拒绝映射运算溢出，不使用有符号未定义行为，不截断、不饱和、不改零。
7. 对准确差异r以`r<0 ? 1 : r==0 ? 2 : 4`得到域位，判断与D按位与非零。D=7也必须经过所有来源/FC/EC/K核验和实际计算。完整原子命中=`FC命中 && EC命中 && 域命中`，AND须全部原子命中。
8. 即使某项已不命中，也必须完成其它必需项的来源核验和计算，不以false短路掩盖缺源/溢出/资源错误。全部项均完整才返回命中或不命中及全部逐项准确结果；失败时不返回可被视为整体成功的部分条件组。最后再检查Gread守卫，漂移不重组部分输入。

`判断结果::成功()`仅状态命中/不命中且版本、请求身份、Gread/H、`定义H==Gread`、完整来源及用量正确；RC结果要求非空条件组与完整规范形逐项对应，每项计算成功。FC/EC结果条件组为空，来源组及已核验概念完整；返回状态与各谓词的实际合取一致。非成功三组载荷均为空、保留已确认截止及真实用量；资源异常映射资源失败，其余异常映射内部不一致，不把失败解释为不命中。

候选入口先调用`规范化二次关系定义`，再执行第7节算法，不写、不自造FC/EC/K；它与已有RC入口只有定义来源差别，不是第二算法。应用不修改通用性：请求提供已裁决的FC/EC/K，缺FC/EC由各自合法形成应用先完成，不能临时用根掩盖不支持。只有候选命中且来源完整时才查重/建立；不命中不能作为本次成立依据。

形成请求的`建立.写入头`用于定义阶段，`来源写入头`用于后阶段，不能从幂等数临时做加法派生。两键必须非零且不同；首次来源写入头的期望G允许由应用在派发前设置为定义发布后已读回的实际G，RC数据服务入口仍只接受非零准确G。各阶段保存自己的首次写集；接受后不能修改该阶段G、键或来源。

准备派发定义前保存其完整实际请求为`待收敛定义`；定义结果未知时，恢复入口必须先调用`收敛二次关系概念建立`，不能先用已经过时的G重新求值候选而永久卡住旧键。已接受记录按原键收敛；确认无首次记录时返回未发布，调用方可按新的真实G重新候选核验后再发尚未绑定的原键；首次材料读取失败不等于记录不存在。成功收敛后从完整RC读回继续来源阶段，不把旧定义成功回执当作本次来源成功。

每次准备派发来源前，将实际RC、准确G、原来源键、完整规范排序来源和预算组成`待收敛来源`，随恢复请求返回；派发后未知必须原样保存。恢复输入存在该项时，先核对其键与来源写入头一致、来源H/定义规范形与原形成请求一致，再调用原来源请求收敛，不先重新计算或新建定义。原始候选材料不是新的事实账，L1首次材料与完整读回仍是裁决依据；应用可以经上述数据服务收敛入口取得权威结果，不能为了恢复直接打开owner端口或另造持久恢复记录。

首次建立的来源可为空：FC/EC/K/子RC定义引用已作为完整定义依据，真实来源按后一阶段补入，但定义发布不宣称来源完成。不得为跨阶段凑一笔全局事务而伪造未分配身份。

应用先候选求值→完整查重→建立/复用→完整定义读回→添加真实F/B/概念来源，已发布定义后的任何失败保留阶段及真实身份；重试先查重复用，不重复建RC。应用构造校验两服务同一L1和同一概念owner，依赖不足拒绝构造；所有源值和定义材料来自请求及正式provider，没有自建仓。

形成成功仅来源已完成、候选命中、定义和来源阶段成功且身份互证。定义已发布但来源失败是可恢复部分阶段，不能报告回滚；名称由正式名称应用后置处理，不包含在形成成功谓词。真实用途由实际消费方在完成业务采用后调用第6节入口，形成成功本身不记用途。

## 9. 迁移和实现范围

1. 概念基础类型定义位置、RC新增公开面、owner内新编码分派和全部受影响消费者必须同次迁移；工程将新真实模块按`ClCompile`登记。不得保留一个写旧布局、另一个写RC新布局的相同概念入口。
2. 旧`概念树定义`、FC/EC原生格式和旧状态码含义不变；新RC专属入口及专属结果不用旧variant下标。旧FT+域、形成宿主、动态时间槽不得转成RC。没有完整D/角色FC/EC/K/AND的存量统一格式不支持，零补字段、零自动迁移、零双读双写。
3. 既有FC、EC和动态概念应用不能被改名冒充RC应用。动态消费者只使用本规范求值公开面；7191先经4213核验动态原子→B，再传入B来源，不能只把状态节点或I64送入计算。因果窄概念核验若要接受RC，须调用RC完整读回而不是只看特征根归属。
4. 本合同不改变L1合同、持久二次实例权限、状态字段、B角色、场景组织或C038。初始化严格服从第2/4节具名外部模块；数据服务不得自行初始化，业务应用不得持有第二owner。
5. 本版不实施非I64比较、无界全场扫描、跨K自动等价、语言命名策略、现实动作执行、动态概念生成和因果真伪判定。缺来源返回具名非成功，不开放任意I64入口补齐。
