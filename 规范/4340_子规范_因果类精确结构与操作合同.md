# 4340 子规范 因果类精确结构与操作合同

编号：4340
日期：20261105
版本：v1.1
状态：正式子规范

直接上级规范：1190。

直接依赖规范：1160、1170、2220、4180、4181、4242、4330。

相关边界规范：3300、4220、4310、4320、5350、7140、7170、7190。

## 1. 合同范围

本规范冻结因果类数据服务的逻辑合同：概念层因果定义结构、规范化与唯一键、匹配与包含规则、统计与代表实例字段、数据操作全集、成功不变量与非成功分类。它不冻结4310的发现、形成与修订策略，也不建立因果实例类；因果的实例是动态（1170）。

C++ 头源归属、DTO 声明、构造签名、物理关系类型交付、定义的 U64 组编码布局等属于施工内容，由对应详细设计承载；本规范只保留“定义以完整规范化键唯一，摘要只用于召回”的逻辑要求。

## 2. 组织根

因果信息组织根是全局基础数据集中的固定结构节点，由全局变量持有受保护引用。每个正式因果节点以外部父子关系挂在该根下，关系角色为“因果根成员”，恰一。该根不属于世界树、需求树、任务集合或方法组织根，也不是概念空间四本体根中的因果链根（因果链根组织因果链概念，见2220、4320）。

## 3. 概念层因果定义

```text
因果定义
  动作类型      未知动作 | 已知动作
  使用方式      尚未确定 | 主动 | 被动
  参与者        角色1..R → 存在概念（可为存在根）；角色同异约束（同一/不同，显式声明）
  条件组（AND） 条件项1..N：角色 + 特征类型 + 约束
                  约束 ∈ { 值域概念FC（含单点FC） | 二元关系概念RC(角色A, 角色B) | 前置动态概念DC(角色) }
  动作          已知动作时恰一；未知动作时无
                  动作概念 + 执行者角色 + 可选作用对象/作用部位角色 + 参数约束组
                  + 触发方式（尚未确定 | 主动调用 | 被动触发）+ 可选本能方法引用
  结果（恰一）  承担者角色 + 特征类型 + 约束（FC | 相对RC(基准条件序号)）+ 可选形成时限
  时序组        端点差分约束：端 ∈ {条件i, 动作开始, 动作完成, 结果}，最小间隔 ≤ t后−t前 ≤ 最大间隔
  定义来源组    简化 | 补完，目标为来源因果或因果链概念
  统计          见第7节
  代表实例组    具名角色 → 动态引用（4330）
```

规则：

1. **两个独立维度**：动作类型与使用方式正交（1190第4节）。不得用“没有动作项”推定被动，也不得用“有动作项”推定需要另行调用。未知动作因果无动作项；已知动作因果恰一动作项，其触发方式三态随定义保存、比较和共同抽象，共同抽象不得混合不同触发方式。
2. **结果恰一**：同一条件下的联合结果拆成多条共享条件的因果。
3. **只引用概念**：条件和结果约束只允许引用正式概念（FC、RC、DC）。精确值和区间一律用单点或区间特征概念表达；不内联准确值、裸 I64 区间、特征值节点或具体存在、状态、动态实例。
4. **动作概念**：动作概念由本能方法登记形成——每个本能方法头在动态根下关联一个动作概念（5350、5360）；外部存在的动作经动作证据提供者推断时也映射到动态根下的动作概念。动作动态本身不建立实例动态概念（1170）。“属于动态根”不足以证明是动作概念，须经概念窄核验确认其动作类别。
5. **角色**：角色概念只能是可共享的类别概念或存在根，不得是专属投影（4310第4.2节）。角色组非空、编号1..R连续；同异约束显式，未声明时不推定同或异，相等闭包不得与任一“不同”约束冲突。条件RC的被描述角色等于所属条件角色；相对结果RC的A为结果承担者的结果值、B为基准条件承担者的条件值。
6. **时序**：时序约束按差分约束图检查可满足性，禁止正长度自回路；动作端只在已知动作因果中可用；条件端对应条件成立的观察时刻，结果端对应结果首次观察成立时刻，动作端来自真实动作事实，不以函数返回时间代替。
7. **组成与序号**：条件与结果序号连续；重复的完整条件项拒绝，由应用先消冗余。

## 4. 规范化与唯一键

1. 角色编号在定义内有固定意义，不按概念身份任意重编号；角色组按角色、动作参数按参数角色、同异约束按（较小角色, 较大角色, 关系）排序去重。
2. 条件按显式序号排列；时序组与来源组排序去重。条件默认 AND，不列析取；不同成因形成不同因果。
3. 完整定义键由第3节除统计、代表实例之外的全部规范化内容构成，不含因果身份、名称或技术发布字段。逻辑键逐字段比较强类型目标；摘要只用于召回候选，碰撞后必须完整比较。
4. 同一完整定义键至多一个当前因果。新建前对同键候选有界完整读回；命中一个则复用，命中多个为内部不一致。
5. 原地修订（第6节）后定义键若与另一当前因果相同，按“合并到既有”处理，不得留下两个同义当前因果。

## 5. 匹配与包含规则

本节规则供4340查询、4310形成与登记、4320链连接共用。

1. **角色绑定**：实例存在E满足角色概念EC，当且仅当E的专属概念等于EC或是EC的下位，或者E尚无专属概念而EC为存在根。
2. **条件或结果满足**：绑定角色的实例特征F（类型为该特征类型）在对应端点的状态准确值落在FC值域内，包含判定使用4180/4181的正式算法；条件端点状态只取上层传入的前置窗口内状态，窗口内没有该F状态时该条件按依据不足处理，不以F当前值代替（长期背景条件不计入是已接受限制，4310第4.2节）；RC条件按4242求值；DC条件要求前置窗口内存在一个动态，其动态概念等于该DC或为其下位。
3. **定义包含**：定义P1比P2更具体（P1 ⊑ P2），当且仅当存在角色单射，使P2的每个条件都能在P1中找到约束包含于它的对应项（FC值域包含，或同一RC/DC的下位），P1结果约束包含于P2结果约束，且动作概念 P1 ⊑ P2（同为未知动作视为相容）。
4. **新发生登记的目标**：所有“条件满足且动作匹配”的因果中，取包含序上的全部极小者（互不可比的最具体者）；全部更新，不更新被它们包含的较宽者（1190第5节）。
5. **饱和差值**：比较中出现的 I64 有向差值溢出时饱和到 INT64_MAX/INT64_MIN 并带“已饱和”标记（4180）；依赖精确幅度的约束遇到已饱和差值时返回“证据不足”，不判满足或不满足。

## 6. 数据操作全集

因果类数据服务提供下列操作，均为 current-only 读写：

| 操作 | 语义 |
| --- | --- |
| 发布或复用因果 | 提交完整规范化定义；同键已有当前因果则复用、零写；否则创建并挂入组织根，统计按来源（经验/预置）初始化 |
| 原地修订因果 | 提交同一因果的新完整定义；与他者同键时返回“已合并到既有”，并在同一写集内把原因果的方法、链与代表实例引用改接到既有因果，统计按第7节第4项合并，动态一侧指向原因果的“已计入”关系同时改接，原因果退出；否则原地更新 |
| 登记发生 | 对一个动态与一条因果登记“符合 / 不符合 / 自我尝试符合 / 自我尝试不符合”，更新统计并按需维护代表实例；同一动态对同一因果至多计数一次 |
| 维护代表实例 | 设定、改标或解除具名代表实例，施加或解除删除保护（4330） |
| 读取因果 | 按身份读取完整定义、统计与代表实例 |
| 精确定义查询 | 按完整定义键查询，零或一项 |
| 按特征类型查询 | 按条件或结果方向、特征类型召回候选，再按第5节包含规则筛选 |
| 方法参考查询 | 返回结果约束包含目标、已知动作且绑定本能方法、使用方式为主动或尚未确定的因果，按“符合−不符合”降序再按稳定编码升序；这是简单排序，不是可信度公式 |
| 退出因果 | 无活动的方法、链或在途筹办引用时退出，解除全部代表实例保护，不级联退概念或来源因果 |

没有因果实例增删改查、任意字段写入、物理清理入口、应用确认入口、动作调用入口或因果链建树入口。

概念窄核验由唯一概念owner提供：只读取概念自身及必要的有界定义闭包，证明正确本体根、类别、FC/RC/DC相容及动作概念类别；不得回调因果服务展开原因果，不查语言、不创建概念；尚无正式读取实现的类别返回依赖未实现。

## 7. 统计与去重

1. 统计四项：符合出现次数、不符合出现次数、自我尝试次数、自我尝试符合次数，均为因果本体字段（4330）。
2. 登记规则：普通观察符合时“符合出现次数”加一，不符合时“不符合出现次数”加一；自我尝试（已知动作且绑定本能方法）总是“自我尝试次数”加一，符合时“自我尝试符合次数”与“符合出现次数”各加一，不符合时“不符合出现次数”加一。
3. 去重记在动态一侧：动态记录“已计入因果”的具名关系，随动态删除而消失；因果一侧不保存已计数动态集合。动态存活期间同一动态对同一因果重复提交返回“重复发生”；动态删除后不可能再被提交。
4. 合并两条因果时四项计数分别相加；同一写集内把动态一侧指向原因果的“已计入”关系改接到既有因果；两侧均已计入的仍存活动态只保留一条关系，并从合并后的对应计数中扣除一次。已删除动态无法识别重复时按相加结果保留，接受上界误差。代表实例按4330上限合并保留。修订后计数按当前定义继续解释，不追溯重算、不清零。

**统计不变量**（替代旧“已计数发生身份数量等于符合与不符合之和”）：

1. 四项计数非负；自我尝试符合次数 ≤ 自我尝试次数；自我尝试符合次数 ≤ 符合出现次数。
2. 经验归纳因果：形成时符合出现次数 ≥ 2，且“形成来源”代表实例 ≥ 2；修订后仍满足当前定义的形成来源不足2时，按4330第3节第6项补选，补不足时允许少于2并标注“来源不足”。内部治理预置因果：初始四项为0，代表实例可为空。
3. 代表实例数不超过4330上限；“最近反例”数 ≤ min(不符合出现次数, k)。
4. 同一动态对同一因果最多计数一次。
5. 每个代表实例引用的动态当前可读，且确实满足（形成来源、边界实例）或违反（最近反例）当前定义。
6. 计数加法受溢出保护；溢出是工程错误，按工程诊断链处理。

## 8. 成功不变量与非成功分类

成功读回的因果必须满足1190第10节，并且：定义可完整解码、全部概念引用当前可读且类别正确、规范化键唯一、统计满足第7节不变量、代表实例引用合法。任一不成立时不返回部分因果，按结构不一致处理。

操作结果至少区分：已建立、已复用、已修订、已合并到既有、已更新、已读取、已退出、无匹配、无共同条件、重复发生、入口拒绝、尚未初始化、状态不存在、动态不存在、动作证据不存在、依赖未配置、依赖未实现、概念不相容、约束不支持、角色冲突、时序冲突、引用冲突、计数溢出、结构不一致、资源失败。原“已记录首例”退出（首例即已保存的动态）。

“无共同条件”和“无匹配”是正常业务结果；资源失败、结构不一致、依赖未配置、依赖未实现和入口拒绝不得伪装成“没有因果关系”。失败清空载荷，不留下可读的半因果节点。

## 9. 并发与生命周期

1. 本服务的写入在一次锁内完成校验与修改；需要跨基础操作共同成立的写入（创建、修订合并、退出）提交一个组合变化集并一次发布（0050第1.2节）。
2. 动作证据提供者分为“读取自我动作事实”（来源为执行实例X对应的动作动态，4220）与“推断外部动作”；未装配时返回依赖未配置，不虚构动作、主体或方法。
3. 因果的淘汰与代表实例保护按4330；本规范不提供物理清理。

## 10. 迁移

旧实例级因果模式（被描述存在节点＋特征概念＋准确值的状态模式、主题存在＋动态概念的动态模式）、旧条件/结果状态实例布局、旧“主动=有动作、被动=无动作”一维类型、旧多结果组、内联准确值与裸区间约束、用途观察节点15/关系18都不被本合同解释。可识别的旧因果返回旧格式不支持，不自动抽象转换；代码迁移按对应施工计划进行。

## 11. 最低验证

两维类型的全部组合及“无动作不推定被动”；结果恰一；只引用概念、内联准确值拒绝；角色同异矛盾；时序不可满足；规范化唯一与摘要碰撞；原地修订与合并（引用改接、统计相加）；角色绑定含存在根；FC包含、RC求值、DC下位匹配；多个互不可比极小者全部更新；饱和差值遇精确幅度返回证据不足；去重随动态删除消失；统计六条不变量；方法参考查询过滤与排序；退出解除代表实例保护；预置因果零统计；旧格式零生产。
