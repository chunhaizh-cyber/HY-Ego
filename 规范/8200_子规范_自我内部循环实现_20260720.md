# 8200 子规范 自我内部循环实现

编号：8200
日期：20260903
版本：v1.5
状态：正式子规范

## 1. 定位

本规范规定自我在没有外部输入时，基于觉醒坐标和自身状态持续完成根特征检查、需求生长、任务承接、方法执行、结果回写和下一轮重判的最小运行链。

直接上级规范：3100—3300。

直接依赖规范：5100—5330、6100—6150、6340、8100、8210。

## 2. 核心闭环

```text
唯一自我正式形成并独立读回
-> 冷启动治理发布或幂等收敛 self 固有且已产生、确认的安全根需求与服务根需求角色
-> 两个角色分别绑定一个长期普通根 D
-> 更新正式完整秒与 UTC 时间证据
-> 安全事件、因素排除与有效未复发证据维护
-> 分层安全值被动维护和五级调度倍率投影
-> 冻结同一非零 G0
-> 分别读取两个根 D、目标合同和当前值
-> 分别形成当前满足 / 正差距 / 方向相反 / 不可比较 / 材料不足 / 当前性漂移 / 内部不一致
-> 正差距或新到达合法父任务材料建立、唤醒或复用根需求治理任务；材料只触发 fresh 重判与裁决
-> 任务管理按状态多次派发找方法 / 查条件工作包，任务工作线程每次发送一个结果消息
-> manager 独立读回筹办信息并推进状态；self 产生并确认独立必要目标后由 task owner 记录为正式子目标承接记录
-> 需求 owner 发布或复用具体子需求
-> 安全五级调度倍率投影与独立生存控制态门控
-> 具体需求统一入树及活动路径生长
-> 当前主需求
-> 任务发起和承接
-> 任务管理按筹办结果消息独立读回并推进找方法 / 查条件状态
-> 全部条件核验后进入待执行前选择，或方法 / 条件缺失处理
-> 方法执行和实际回读
-> 任务实际结果与目标裁决
-> 任务轮次结算与轮次收束
-> 有唯一发起上级调用时返回并结算该调用槽；根任务无调用槽
-> 上级 / 其它任务在实际使用时 fresh 复核自己的目标或条件
-> 自我继续 / 结束 / 等待 / 取消后继决议
-> 自我状态变化
-> 下一轮主需求重判
```

定义词条、初始化字段、方法首存在或一次循环成功都不能直接证明自我苏醒。

## 3. 分层职责

自我线程负责消息批次、正式时间证据更新、安全治理、需求、估权、主需求、任务发起和调度意图、需求满足复核、结算触发和下一轮决策。安全领域服务负责 6100 主动安全结算、6140 分层安全维护、6150 安全调度倍率与硬否决材料；外部服务请求只作为服务根治理任务材料，子需求必须由该父任务的正式子目标承接记录形成，再经普通需求、任务、方法和正式结果链治理。线程循环次数不参与正式时间事实、任何当前值或控制态计算。

任务管理负责任务创建请求、筹办 / 执行工作包、筹办触发、方法执行调度、结果消息消费、任务状态提交和结果上报。任务工作线程只执行具名工作包；筹办工作包和执行工作包使用强类型判别联合，不为筹办新增专用线程。

任务筹办是任务域内建最小方法，每次处理只形成当前找方法或查条件步骤的阶段性信息补全结果，并由任务工作线程通过强类型消息交给任务管理线程；不建立独立持久化筹办回执或第二结果账。普通方法负责具体动作；self 产生并确认需求，task owner 只记录，需求 owner 只发布或复用；其它领域提交入口分别负责任务、方法和世界事实的正式发布。

## 4. 任务层级和方法承接

每个任务必须有方法或任务结构承接，但上级任务和汇总任务不要求绑定单步业务方法。它们可以通过子目标、轮次级子任务调用、等待、调用返回和 fresh 重判推进；不得建立永久任务父子树或结果归并账。

普通可执行原子任务必须最终具备可执行方法和动作入口，其结果必须能与任务目标状态比较。复合需求优先按活动 OR 路径及其 AND 组分解和承接，不能只按有无子节点判定管理或执行角色。

## 5. 三类运行材料

```text
方法运行实例和运行场景
-> 保存本轮输入、输出、时间、执行报告和实际回读

任务虚拟存在
-> 保存任务状态特征、当前方法、冻结、结果和筹办历史

方法治理虚拟存在
-> 保存方法规格、运行账、学习证据和稳定能力
```

世界事实必须进入正式场景和对应基础信息领域。任务运行事实不得写进方法长期能力，方法运行账不得写入任务长期语义，输出结果场景不得被任务状态占用。

## 6. 主循环阶段

一轮主循环至少按以下职责顺序运行：

1. 冻结本轮允许消费的治理消息批次；
2. 规范化材料并由合法入口提交一次事实账；
3. 重算受影响二次特征和状态；
4. 刷新自我运行上下文；
5. 更新并读回正式完整秒与 UTC 时间证据，再调用一次安全治理评估：同轮新安全事件和复发先按 6100 主动结算，再处理因素验证排除、6140 分层安全维护以及 6150 安全调度倍率与硬否决材料；
6. 从已发布一致当前事实读取独立生存控制态；`A=0` 只开放正式恢复 / 重建与停止控制入口，`A=1` 只开放具名治理材料接收与正式承接、正式时间事实更新、安全事实接收、重新评估和停止控制入口，`A>1` 时才允许后续普通任务进入派发门控；本步不按来源存在的人类分类开放入口，也不为未冻结任务预造权限；
7. 整理需求、重判根缺口和活动路径；所有非根需求必须由父需求任务的正式子目标承接记录形成并能回溯到安全根或服务根。外部服务请求只进入服务根治理任务材料，不直接创建具体需求，不建立旁路账务或专用任务链；
8. 以具体需求 D 形成任务承接输入交任务管理；任务管理按状态推进承接和多次筹办，任务信息完整后由执行前选择入口完成选择与冻结；随后读取 6150 当前安全调度倍率并检查安全硬否决；冻结含现实改变步骤时，再在任务进入执行阶段前请求一份自我现实执行授权；内部治理和无现实副作用的纯观察不请求授权；
9. 执行低频自检和休眠期修复门控。

纯线程生命周期消息不进入主循环治理批次。

外设输入不是主循环的直接消息源。主循环只读取 6340 已承接材料经正式方法或领域入口形成的任务结果、结构化缺口、供 self 裁决的需求目标材料和世界事实变化。当前冻结方法需要外设材料时，只能从任务工作包取得已承接材料引用，不得直接读取物理报告队列。

因此内部循环在没有外设时仍可按本规范闭合；外设接入是在同一需求、任务、方法、结果和重判主链上增加受控材料来源，不建立旁路治理循环。

## 7. 需求层闭合

需求层至少完成：读取抽象安全 / 服务根特征，读取自我当前实例状态，形成具名缺口，建立或复用父需求治理任务，self 依据任务材料产生并确认需求目标，task owner 记录，需求 owner 消费正式子目标承接记录发布或复用子需求，发布前精确命中时复用既有 D，确定活动 OR 路径和 AND 组，继承与分配权重，选择当前主需求。

每条 OR 路径继承完整父权重；AND 必须属于确定 OR，并在该 OR 内平分。需求角色不能仅凭拓扑裁决。

具名缺口和具体需求用于需求选择；冻结后形成的 6150 安全调度倍率只用于普通排序，不建立通用“压力”机器类型，也不构成正向授权。生存安全根值主动变化只能来自真实安全事实和 6100 合法结算。6140 分层安全值可以由有效未复发证据和残余风险维护被动变化，但不得冒充生存安全根值、现实改善或任务收益。普通服务请求经服务根任务形成目标材料，由 self 产生并确认后形成子目标记录和普通子需求，再经后继任务、方法、正式结果、实际回读及状态 / 动态 / 因果证据闭合；对应特征当前值仍由其事实 owner 按现行规则裁决，不建立专用服务账务或专用调度机制。

## 8. 任务发起和筹办

自我线程只发送携带一个当前具体需求 D 的任务承接意图，不能只发送需求列表项或通用授权包。任务领域读取 D 所属列表项 L，以 L 查询 0..1 个当前任务：无任务时原子建立 T、`T→L`、`T→D` 和任务虚拟存在；有任务时验证同目标后幂等新增 `T→D`。列表其它成员不得自动承接，任务单目标只从当前显式关联 D 互证形成。

每次筹办必须先按任务身份取得唯一筹办执行权，并只执行当前状态指定的工作：找方法阶段更新候选和覆盖范围，查条件阶段更新逐方法条件组、核验结果和覆盖范围。manager 独立读回后迁移到继续找方法、待查条件、继续查条件、方法 / 条件缺失或待执行前选择。

资源 / 投递 / 发布未知与截止漂移不推进业务状态；ABI、引用、断言或内部代码错误停止受影响调用。它们都不是筹办业务出口。无候选方法时不创建方法首。

任务执行冻结完成后、真实派发前必须重读当前生存控制态。`A=0` 只保留正式恢复 / 重建与停止控制入口；`A=1` 只保留具名治理材料接收与正式承接、正式时间事实更新、安全事实接收、重新评估和停止控制入口；两者不派发普通任务。只有 `A>1` 才继续读取 6150 当前五级调度倍率快照。服务根治理任务只形成子目标，不直接执行现实动作；服务子需求对应的后继任务仍与其它普通任务一样经过控制态、安全倍率和硬否决门控。全局控制态和安全硬否决独立门控；技术能力许可或受保护资源访问许可不是第二正向业务授权。

执行冻结必须声明方法作用范围和逐动作现实副作用。仅内部治理或无现实副作用的纯现实观察直接进入执行；含现实改变步骤时，自我业务 owner 在任务进入执行阶段前发布一份同时绑定任务、任务轮次、筹办轮次、执行轮次、冻结、实例方法和现实动作范围的现实执行授权。任务和方法不得各自再建授权事实，安全服务也不得发布正向授权。

## 9. 方法可执行性和学习

方法首只作大范围召回入口。可执行性必须读取当前方法版本、条件、结果能力、条件结果对、动作入口、参数、禁止项和验证合同。

方法缺条件结果对、动作入口、参数或稳定证据时，必须形成精确能力缺口和合法生产者，不得用抽象“需要学习”兜底。学习方法只能补齐明确结构和能力证据，不能在任务执行期伪造动作入口。

## 10. 任务执行和目标验证

执行前重新验证任务冻结、普通调度资格、独立全局控制态和安全硬否决；含现实改变时还必须独立读回当前冻结唯一自我现实执行授权。执行调用当前方法后，必须读取实际结果和输出场景，再与当前显式关联 D 互证出的目标投影比较。

```text
目标已达成
-> 形成本轮目标已达成结论并进入任务轮次结算

结果相对执行前有推进但未达成
-> 记录推进量和剩余差距，形成本轮目标未达成结论并进入任务轮次结算

结果无推进、外部事实变化或证据不足
-> 形成强类型结果并进入任务轮次结算
```

方法运行成功不能替代目标达成。执行期才发现冻结前已有的缺方法、缺入口、缺条件结果对、目标不完整或任务结构缺失，属于筹办漏检和内部逻辑错误。

## 11. 任务轮次收束、调用返回与按需需求核算

正式实际结果形成并完成本轮验证 / 归因、停止与冻结收口后，每个已开始执行轮次由 task owner 恰好形成一个任务轮次结算并迁移到`轮次已收束`；重复结果只幂等读回首次结算，不等待结果分配或全部 `T→D`。任务结果不是容量，不建立共用 / 争用、成员分配优先级、消费分配或剩余扣减。

manager 随后按子任务轮次读取 0..1 条正式发起调用。恰一条时把正式结果返回并由 task owner 幂等结算唯一上级调用槽；零条按根任务收口；多条引用冲突。上级收到返回后只 fresh 读取自己的目标与任务状态；需要继续时由 manager 派发任务筹办重新补齐方法 / 条件，达到待执行前选择后才可继续。调用槽已返回不等于上级目标满足或条件已具备。

其它关联 / 受益任务只在自身实际调度或使用时 fresh 读取目标和当前事实。当前已满足时零动作并由需求 owner 发布自己的结论；未满足且重新经过筹办、执行前选择后才可继续自身执行。目标未达成不得自动产生下一筹办工作包；需求本体持续存在，self 根据需求当前满足状态、活动资格、等待条件和当前整体事实形成继续、结束、等待或取消后继决议。

任务权重不是结算额。价值增量必须来自目标达成、需求满足、任务路径份额、冻结预算和合法结算规则；同一状态满足多个需求不得自动重复领取价值、预算、奖励或归因。

I64 最大值只能作为合法满刻度上界或比例分母，不能表示未知、异常兜底或无证据满分。

## 12. 待机和修复

无有效主需求、当前任务合法等待或当前根缺口未形成可执行需求时，自我可以进入待机或低频自检。

自检只产生具名缺失和证据，不直接创建修复需求。该材料只能进入安全或服务父需求任务；没有活动任务时可以幂等建立、唤醒或复用该父需求治理任务，但只用于 fresh 重判与材料裁决。self 产生并确认修复目标独立必要、严格缩小祖先范围且目标合同最终可判定，task owner 记录为正式子目标承接记录后，需求 owner 才可发布或复用修复子需求。

## 13. 内部循环等级

| 等级 | 最低含义 |
| --- | --- |
| 0 | 未初始化 |
| 1 | 冷启动和自我定义域可读 |
| 2 | 根特征与需求层闭合 |
| 3 | 任务承接可用 |
| 4 | 状态驱动的多次筹办与任务信息补全可用 |
| 5 | 方法执行和实际结果可用 |
| 6 | 任务验证、需求回写和结算可用 |
| 7 | 连续多轮稳定 |

内部循环真正建立至少达到 6 级；工程稳定验收达到 7 级。单轮、夹具或字段初始化不能提升等级。

## 14. 内部逻辑错误

以下属于内部逻辑错误并停止依赖路径：非根需求缺父需求、缺父任务正式子目标承接记录、所属存在不是唯一自我、无法沿父关系回溯到安全根 / 服务根或目标缺失，任务缺当前 `T→D` 关系却用列表项或当前主需求兜底，任务虚拟存在缺失，筹办凭空生成学习方向，执行无实际结果却建议完成，自我直接写任务状态，任务管理直接写需求，自检或外部请求直接创建需求，以及执行期暴露冻结前结构缺口。

## 15. 验证边界

验证至少覆盖双根普通需求、全部非根需求的父任务子目标来源与双根有限回溯、6100 主动安全结算、安全事件优先、有效未复发证据、6140 分层安全被动维护、6150 五级安全调度倍率与硬否决、`A=0/1/>1` 独立控制态、普通服务请求作为服务根任务材料到子需求 / 后继任务 / 方法 / 正式结果的闭环、状态 / 动态 / 因果证据、需求路径和权重、任务承接、唯一筹办、方法作用范围、内部治理 / 纯观察零授权、现实改变冻结后一份自我授权、实际回读、逐需求核算、任务轮次结算、轮次收束后自我决议和连续多轮稳定。

## 13. 当前值、状态与动态的循环边界

安全值或其它已有合法写入语义的目标特征变化时，业务规则先裁决新当前值；统一变化入口原子切换当前值并形成对应状态 / 动态记录。服务根当前值只作普通根坐标，当前无新的自动写入来源，不得用循环、时间或普通结果补造变化。状态记录某一时刻的值，动态记录前后状态和来源，不参与当前值裁决。

自检无论由周期、消息还是动态触发，均先冻结 G0，再读取目标涉及的当前特征值和根需求目标状态合同。单一目标比较一个当前值；复合目标读取同 G0 的完整当前值集合并按合同组合。值式当前状态投影只方便传递，不能成为第二当前值。

禁止“最后动态 → 后状态 → 当前值”以及“当前状态选择 → 状态值 → 当前值”两条旁路。

## ARCH 五层运行边界（20260824）

自我循环是 ARCH-L4 业务消费者：任务特征、任务状态和状态迁移记录从 task owner 的 Vt 正式入口取得；执行所需世界材料和世界结果才通过 ARCH-L2 公开服务取得存在、状态、动态和因果结构。自我循环不直达 L1，不把 Vt 接入世界存在族或世界树，也不在任务 / 方法线程中构造第二 provider。普通任务、学习、价值回流和名称表达仍按各自后继合同分账。
