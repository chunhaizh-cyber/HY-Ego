## 1. 关系概念的来源

世界树关系概念（下称“关系概念”）从“节点、关系、值”中的**关系**生成。它抽象已有领域信息结构中可复用的连接方式，说明哪些种类的节点以哪些角色、经什么连接彼此关联。来源有两种：领域所有者定义的外部边；领域所有者定义的、以另一节点为目标的字段引用。字段引用从宿主指向目标；普通数值字段的值本身不能给出节点间的连接。

例如，“整体具有部分”由存在领域的组成连接定义。若实例读回为“车架是自行车的组成部分”，自行车绑定整体角色，车架绑定部分角色。“父需求含有子需求”使用需求领域的父子连接。即使底层承载均采用父子边，端点种类、领域角色和所有者也能区分这两种含义。“需求指向目标存在”则从需求的目标信息节点字段读取，仅当目标实际为存在时匹配该例；其它目标信息节点保持原有种类。

关系定义、一次具体关系事实和表达该事实的语言形式各自有独立依据。领域合同可作为先天种子的来源；登记种子不要求先造一对样例节点。断言一对具体端点满足关系时，必须从领域所有者正式读回。词面相似、节点名称、图中相邻以及数值比较成立，都不足以替代这项读回。对于“A与B的身高差大于零”，有序差值属于二次特征，判断该差值的条件由[7170](7170_子规范_二次特征概念.md)及其相关规范定义。

## 2. 定义、登记和身份

| 内容 | 约束 |
| --- | --- |
| 登记身份 | 以登记节点及其非空稳定种子键识别和复用。登记挂在自然语言组织根下，与概念名称关系根并列；四个本体根仍由2220管理。 |
| 端点组 | 至少两个端点角色，每个角色指定角色键和领域对象种类。实例绑定保持各对象原有身份与所属领域。 |
| 主连接 | 恰一个。外部边指定所有者、边类型、领域角色或顺序、源与目标角色键。字段引用指定所有者、字段键、宿主与目标角色键。端点和约束仅取自相应领域合同。 |
| 附加连接 | 零或多个，各自采用上述连接定义。各项都是适用条件，匹配时须与主连接同时成立；只有表达知识明确指定时才单独成句。 |
| 名称与表达关联 | 名称按目标语言引用词条和有效名称关联（7220）；表达关联指明目标语言、含义操作及角色槽，可以关联预置材料、后天语言知识和有序陈述段。 |

领域所有者维护连接及其实例事实；关系概念登记保存对这些合同的引用。语言所有者维护词条、表达知识、含义网和自然语言场景材料。7270的结构概念规定构式和槽位映射，同一关系概念可由不同构式、不同语言表达。

初始化根据静态种子表逐项查重。同键同义复用原登记；同键但端点、角色、连接方向或适用条件不同，须报告定义冲突并进入显式结构修订。只有表达形式不同的种子材料应关联到同一关系概念；表达键数、词条数和同义表达数不作为关系概念数。重启后须能读回同一身份、角色、连接和表达关联，保留后天学得或纠正的表达。

换词、换语序或增加语种只更新表达关联；一辆自行车换了车架，只改变相关实例事实。端点种类、连接方向、字段或适用条件有实质变化时，按显式结构修订办理，或登记不同关系定义，并查重以维持同义身份唯一。新连接缺少领域公开读取合同时，须先由该领域补齐合同。

## 3. 由内部表达需求生成语言

1. 任务管理按既有合同选择方法。执行出站本能时形成结构化的正式表达需求，指明目的、待表达内容和来源。字段询问中的这份材料在本次调用内使用（7240 第3.3节），需求树中的需求 D 仍须按需求治理合同建立。
2. 通过领域公开入口读取端点、主连接和适用的附加连接，按定义绑定角色。陈述只把已核验的事实作为成立内容；询问按7240保留被问位置。读取及端点准入条件由原领域合同决定。
3. 按7232和7240将待表达内容组织为具体含义网。表达关联将端点角色映射到含义参数，并指定每个槽的取材方式，例如取端点自身，或从需求端点依法取得所指存在。槽位、参数和投影须能分别读回；具体需求节点保留需求身份。
4. 按目标语言选择词条、构式、语序和表达知识。已指定陈述段组时按段组织，保留角色、方向、作用域及已知与待问的区别。实现复用同一转换流程；新增同结构措辞或语种通过知识登记，不增设逐句、逐种子成句分支。
5. 生成的候选话语须按7240整段唯一回读，与表达需求中的对象身份、角色、方向和作用域对应。缺关系登记、端点不合法、关系不成立、方向或角色错误、缺语言知识、缺名称、未支持连接或投影、请求不合法，分别返回可辨认的结果。读取或结构一致性故障按工程路径报告；缺目标语言知识时不静默换语种。发送、入列和回答写回分别按各自合同记录。

## 4. 由自然语言形成场景材料

1. 以原文、语言知识与可用上下文按7240解析含义，识别表达关联并把含义角色对应到关系端点。词序与语法由目标语言知识解释。例如“自行车有车架”和“车架是自行车的组成部分”，在“有”已解作组成、指称也已确定时，可以得到同一整体和部分绑定。仅凭“有”字还不能确定组成关系。
2. 在该自然语言场景中保存可回读的关系陈述材料：固定原文、关系概念的稳定种子键、所用知识、各端点角色及其指称材料、来源概念、已绑定的场景实例或对象、未确定标志。存在相关交互场景时保留其引用。语句含提问、否定、条件或引述时保留含义网中的相应作用域。
3. 匹配多项解释时保留候选或报告多义；角色未能确定时保留未确定状态。区分输入不合法、无匹配表达、依赖未就绪与结构不一致。同名、缺省值和遍历顺序不能决定指称；缺对象时不得为完成绑定而建立业务实例。
4. 此方向的完成点是场景材料可读回。领域边/字段的新增、需求建立，以及自我后续是否采纳该陈述，各归相应领域治理；解析器不执行这些操作。

## 5. 验收范围

1. 登记验收依正式读回核对稳定键、端点、连接和表达关联；重复初始化须复用原身份并保留后天表达。只扩展措辞时，检查同一概念读回新旧表达。
2. 对所验关系或同族表达，分别核验正向生成、入站角色、反向端点、非法端点、关系不成立、缺语言知识和歧义未决。以事先从领域或原文独立确定的角色、方向、身份、作用域和未决项为准；只比对词面或用同一错误映射往返均不足以证明正确。
3. 更换对象、措辞或语种，只能证明实际覆盖的绑定和表达知识；组合验收以已登记的结构与陈述段为界。新领域连接、多语种覆盖和篇章理解分别举证。
4. 转换验证、本能登记召回、显式候选执行、真实任务调度、队列与回答写回、正式持久库运行须分别记载结果。仅当取得该层实际证据时才可宣称通过。
