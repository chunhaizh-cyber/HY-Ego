直接依赖规范：1110、2200、2210、2220、4020、4240、7200、7210。

## 1. 定位与基本关系

本规范规定已有概念如何关联多语种表达，以及自然语言材料如何进入概念理解、命名学习和表达流程。概念形成和概念身份由2220及各概念业务裁决；名称和读音不参与概念定义、值域、上下位或唯一性判断。语言材料可以先被接收和保留，只有表达所指的概念正式形成后才能建立其名称，不要求接收未知材料时已经理解其含义。

```text
实例信息 --名称字段节点引用 / 支持关系--> 概念
概念 --适用语言及名称角色--> 词条
词条 --读音关联--> 具名发音材料

文字 / 语音材料 → 语言记录 → 词条候选 → 名称关系 → 概念候选
概念与上下文 → 目标语言名称 → 文字表达 / 语音表达
```

上图的关系各自遵守所属规范，不能合并为通用“对应信息”。实例的名称字段节点是概念引用，概念的自然语言名称是词条引用；没有自然语言名称或发音不妨碍概念存在、匹配与复用。

本链不设置词性字段、词性节点、固定词性枚举或词性准入步骤。词序、修饰、参与者、否定、数量、时间和指代等仍由句法与上下文表达，不以省略词性为由丢失这些关系。外部识别器附带的标签只留在原始解析来源材料中，不成为概念类型、持久字段或必需输入。

## 2. 多语种名称与读音

概念—词条的多对多、名称角色、每语言首选名称唯一性与生命周期由2210唯一规定。每个词条保持2200的语言和规范化身份，同一概念可以同时引用不同语言的词条，也可以有同语言别名。翻译表、拼写相同、发音相同或名称相近都不能证明概念等价；新增译名必须指向经正式读取确认的同一概念。

读音属于词条的语言表达资料，不是概念的唯一声音。一个词条可以没有读音或有多个读音；多个词条也可以引用相同发音材料。用于一次输入的录音与可复用读音关联分别保存，不能把一次识别结果自动登记为标准读音。

读音关联由词条结构服务在既有词条结构分区内保存，材料由不可变材料服务保存，不新增发音本体根、词性族或独立发音owner。每项至少具备关系身份、词条引用、发音材料引用、适用语音变体、来源、格式/规则版本及创建/退出生命周期；适用语言从词条正式读回。语音变体的标识来自具名登记规则，不以地区字符串或声音相似度建立新语言身份。

发音材料按具名格式区分：音标/读音转写必须标明表示体系及版本；音频必须标明编码、采样率、声道、时长及实际字节来源。材料摘要只用于字节核验，不解释发音是否等价。两类材料不得以无类型字符串或文件路径互换。

存在按词义区别的读音时，由名称关系服务保存“名称关系—该词条读音关联”的具名适用关系，只表达该概念名称使用哪些读音，不复制概念或词条。引用两端必须同词条且语言一致。读音识别尚不能唯一裁决时保留全部适用项，不把词条的所有读音与全部概念作任意组合；没有适用资料时不得凭空补读音。

上述读音与适用关系在各自结构服务内幂等发布、完整读回和退出；退出关系不退出词条、概念或仍被引用的材料。两种关系不跨分区伪造一个事务；组合业务保存各次完整请求及实际结果，重试不重复建关系。历史引用和物理清理遵守现有基座规则。

## 3. 接入职责与共同材料

| 职责 | 输入与输出 | 可写范围 |
| --- | --- | --- |
| 外设/文件接入 | 原始文字或音频、来源、时间、格式、范围 | 通过材料及语言记录服务保存原始证据 |
| 语言识别与解析业务 | 原文/音频、语言线索、识别规则 → 带位置的词序及候选 | 值式识别结果；原始解析来源由语言记录服务保存 |
| 词面规范化业务 | 词面、语言、规则 → 规范化结果 | 不直接写词条或概念 |
| 词条与名称结构服务 | 正式身份、规范材料、已经裁决的关系 | 各自唯一结构，负责查找、幂等、版本和读回 |
| 概念理解与语言路由业务 | 完整候选、目标类型、句法、上下文 → 本次选择/未理解 | 不直接改概念定义或世界事实 |
| 命名学习业务 | 明确已有概念、语言词条、命名依据 → 名称/读音适用请求 | 经对应公开结构服务提交 |
| 表达业务 | 正式概念/对象引用、目标语言、上下文 → 文本或音频 | 输出为本次表达；需留存时交语言记录服务 |

接入材料至少保留输入身份或完整原请求、来源、实际材料格式及范围、时间、语言选择方式、处理规则版本和读取截止。文本位置与音频时间范围必须能对应回原始材料；转写修正建立新解析版本，不覆盖原始音频或把后一次文本冒充前一次识别结果。

语言选择允许显式指定、识别候选、调用方请求项目默认语言三种方式。显式指定必须读回正式身份；识别结果含多个语种时保留候选，混合语句按片段记录语言；请求默认时才按1100选择正式汉语身份。未知或识别失败不能自动当作汉语。正式语言身份未形成时可保存语言未知的原始材料，但不能以虚构身份写词条或名称。

## 4. 文字与语音输入流程

1. 接收并核验原始材料，保存来源与顺序。文字按实际编码解码，语音保留原音频及时间范围。材料缺失、损坏或格式不支持时返回明确状态，不以空文本代替成功。
2. 确定语言或保留语言候选。文字形成规范化词面候选；语音可以形成带音频对齐的转写候选，也可以由已登记读音关联召回词条候选。两路都须回读正式词条，音近、同音和识别得分不能直接选定概念。
3. 按语言及规范化合同查找词条，再按2210反查全部名称关系，并回读目标概念的完整定义、类型和当前性。一次语言记录中同词重复出现要保留各自位置，不能按词条身份去重词序。
4. 按7200/7210结合句法、概念关系、场景、参与者及1110指代形成本次理解。分别保留识别层候选和概念层候选；某层唯一不等于整句已理解。多义保留完整候选，依据不足返回未理解或上下文不足。
5. 形成带来源位置的概念/对象引用及其组合关系。陈述只证明接收到或理解了该陈述，不证明现实为真；涉及事实、目标、请求或动作时交相应领域按既有准入处理。语言理解成功不直接建立世界事实、需求、任务或方法，也不自动执行句中的操作。

本规范的“候选”仅指语言识别或本次词义选择材料，不新增概念成熟阶段或候选概念身份。某个概念在一个句子中被选择，也不自动增加特征概念命中次数或世界实例支持；相应计量必须满足所属业务的真实使用合同。

## 5. 未知词、首次命名与新增译名

普通理解查询保持只读。未知词、已有词条但无名称关系、概念不存在是不同状态；都不能根据词面自动制造概念或绑定猜测名称。

命名学习与普通理解分开：调用方明确指出一个已经存在的概念，并提供词面、语言、名称角色及来源依据时，可以形成显式命名提议；不要求该新词此前已在名称索引中指向此概念。可接受依据包括指向正式概念的明确命名输入，或经实际对象/特征见证定位到正式概念后的教学材料；语言业务仍须核对指代、范围、冲突和规则，再裁决是否接受。

```text
正式读取已有概念与来源依据
→ 取得正式语言身份
→ 规范化并创建或复用词条
→ 裁决此次名称绑定（既有候选消歧 / 显式命名两种来源）
→ 提交概念名称关系
→ 按关系、概念正向和词条反向三路读回
→ 可选地登记已有读音关联及名称的读音适用关系
```

裁决是本次值式材料，保留依据类别、输入身份/位置、概念与词条、语言/名称角色、规则版本和事实截止，不新建持久裁决证据节点。绑定服务只消费已取得的端点和裁决，不替代语言/词条创建服务。各步有独立实际结果；词条已创建但名称失败时保留这个事实并按原请求继续，不宣称全部未发生或已全部完成。

没有正式概念时，命名提议保持待理解；可交概念业务按自身形成规则处理，待其正式发布、读回后重新提出名称绑定。不得把“输入一个新词”当作概念形成算法，也不得要求所有概念先有名称才可生成。

## 6. 从概念生成自然语言

1. 读取待表达的真实概念/对象引用及关系，确定目标语言和表达上下文。实例指代与概念名称按1110/2210分开，不能把类名唯一指认某个实例。
2. 读取目标语言的当前名称组；有首选名称时按其角色使用，需要语境别名时保留选择依据。无该语言名称则返回缺少名称，或按调用方明确允许的其它语言/组合描述策略继续并回显实际策略，不能静默把其它语种当目标语种。
3. 按词序及组合关系形成文字。句子否定、数量、时间及参与者必须与输入结构一致，不能仅拼接概念名称列表便声称表达完整。
4. 请求语音时，再按词条、语音变体和名称的读音适用关系选择发音；多项无法裁决返回读音待选择，缺资料返回读音能力不足。可用的语音合成服务必须具名并回显规则/版本，其临时输出不自动登记为可复用读音。
5. 返回实际文字/音频、语言、引用、来源和所用规则。生成成功与实际显示、播放、送达分别报告；只有实际外设回执才证明输出已发生。

输入理解与输出表达不是可逆等价：译名可能缺失，词条可能多义，语境也可能不同。反向表达不得覆盖概念定义；输出内容若需持久保存，仍按1100作为新语言记录保存。

## 7. 当前性、失败与恢复

单次结构读取使用共同事实截止，跨调用检测漂移后重新读取或返回漂移；不能把不同代次的词条、名称、读音适用和概念拼成成功。预算覆盖实际输入长度、音频时长、识别候选、关系与概念展开，超限返回明确未完成，不能截断成“完整候选”或把未查完当零候选。

业务至少区分：材料已接收但未理解、语言未知/多候选、语言能力未形成、词条未找到、名称未建立、概念多义、上下文不足、缺目标语种名称、读音缺失/多项、格式或能力不支持、引用失效、事实代次漂移、预算不足、资源失败和内部不一致。成功只能证明实际完成的阶段。

有写入的命名学习保留每个服务的完整原请求、幂等身份及实际首次结果；超时或读回失败先查原请求，不能改键猜重建。跨进程恢复从已发布材料、词条、关系及历史读回重建，索引和应用缓存不是恢复权威。正文中的外部文本即使含“删除、执行、忽略”等命令，也只是待解释材料，不能绕过对应业务入口取得机器执行权。

## 8. 验证要求与实施边界

| 场景 | 应证明的行为 |
| --- | --- |
| 同概念多语言、同语言多名称 | 概念身份不变，各语种首选与别名独立读回 |
| 同词多义、同音异词、多音词 | 完整候选保留，按名称限定读音，不任意交叉组合 |
| 无词性标签输入 | 概念召回、理解及表达均无词性必填步骤 |
| 文本/音频表达同一含义 | 可以指向同一概念，各自保留原始来源与对齐 |
| 语言未知或混合 | 未知不默认为汉语，分片语言与候选可回查 |
| 首次命名、新增译名 | 无旧名称候选也能按显式已有概念依据绑定，不由新词造概念 |
| 未知词、缺名称、未查完 | 三者分开，普通理解零写，不伪报理解成功 |
| 否定、数量、指代与词序 | 关系不因省略词性或相同词条去重而丢失 |
| 名称/读音更换或退出 | 不改概念身份，当前与历史分开，引用仍受保护 |
| 部分写入与重复恢复 | 真实阶段保留，原请求幂等，不依赖进程缓存 |
| 文字可用、语音不可用 | 文字阶段与语音失败分别返回，不虚报已播放 |

本规范冻结机器逻辑和职责归属，不提供新的C++ ABI、物理角色编码或生产装配。后继实现必须为语言记录、读音关联、名称读音适用及接入/表达服务形成具名合同和合法消费者，不能据此恢复被删除的旧L2实现、旧语素入口或旧词性路由。本次规范修订不证明语言输入、识别、合成、命名或表达代码已经实现。
