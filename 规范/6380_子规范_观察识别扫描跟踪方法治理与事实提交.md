# 6380 子规范 观察识别扫描跟踪方法治理与事实提交

编号：6380
日期：20261105
版本：v1.0
状态：正式子规范

## 1. 定位

本规范规定观察、识别、扫描、跟踪四类自我侧认知方法的治理位置、互不调用规则，以及方法执行后的事实提交与动作动态。四类方法之间的事实层级和写入边界由6300规定；外设到自我场景的分层与外设公开能力由6320规定；识别方法唯一性由6370规定。

直接上级规范：3300。

直接依赖规范：1170、3200、6210、6300、6320、6370。

相关边界规范：1160、1190、5260、6340、6360。

## 2. 扫描的治理位置

当前阶段由内部治理过程主动产生的主要场景维护入口是扫描。安全或服务治理为了确认当前状态、验证任务结果或维护当前场景，只能形成扫描目标材料并交给对应父任务；只有 self 产生并确认扫描需求后，task owner 才记录、需求 owner 才发布或复用。

扫描最小输入是：

- 自我内部场景稳定句柄；
- 已合法进入系统的外设当前数据集；
- 本轮扫描关注集合和应覆盖存在集合；
- 已有对应关系、当前特征值基准和比较规则。

扫描只比较本轮应覆盖的已确认存在。范围外、视野外、低频跳过、跟踪排除、优先级不足和条件不足的存在不得解释为消失或遮挡。

扫描可以更新当前特征值和当前状态并记录状态变化；不得从原始外设材料生成新的长期观察特征。需要补充一阶特征时，只能先形成观察目标材料，待 self 产生并确认需求后再由 task owner 记录、需求 owner 发布。

## 3. 四方法不得直接互调

四类方法之间的事实层级和写入边界由6300规定，本节只规定治理位置与互不调用。观察负责补充存在的一阶观察特征；识别只读已有特征并返回已有存在稳定句柄或空句柄；扫描维护当前特征值和状态；跟踪只返回指定目标的新空间坐标或空信息。

四者不能成为彼此的子函数。扫描过程中发现对应、坐标、当前值、质量或未归属缺口时，只能输出供 self 裁决的结构化目标材料：

```text
目标提议类型
目标提议内容
目标提议来源证据
```

该材料经需求统一入口、任务承接和筹办后，才可能再次选择观察、识别、扫描或跟踪。

## 4. 事实提交与动作动态

每个对自我可见的方法必须保持：

```text
输入特征和来源材料
-> 方法执行
-> 输出特征、状态或缺口
-> 动作动态或来源动态
```

线程不是动作来源。动作动态在执行实例X动作开始时形成、唯一来源为X，挂执行主体所在场景，关联执行方法、来源任务、输入材料、输出范围和发生时间。

空间坐标、轮廓、颜色和内部子结构只在其合法生产者、阈值和量化规则明确后提交。子存在、子结构、叶子特征块、内部未解释区域和冲突区域通过关系及场景零散事实目录承载，不堆入父存在普通字段。

## 5. 验证

验证覆盖扫描只形成目标材料不直接生成需求、扫描只比较本轮应覆盖的已确认存在、四类方法互不调用、缺口以结构化目标材料交 self 裁决，以及每个方法的动作动态来源与事实提交路径。
