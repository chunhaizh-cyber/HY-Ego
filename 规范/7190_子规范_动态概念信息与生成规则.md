# 7190 子规范 动态概念信息与生成规则

编号：7190
日期：20260908
版本：v1.0
状态：正式子规范

直接上级规范：2220。

直接依赖规范：1160、1170、1180、4210、7110、7140、7160、7170、7180。

相关边界规范：4000、4150、4151、4180、4240、4241、4310、4320、7150。

## 1. 定位与核心用途

动态概念是对多组相同或类似动态的共同变化结构及关键识别条件的抽象。它回答“这次变化符合哪种模式、与另一模式有什么可判定差别”，不是具体发生记录、动作函数、名称字符串或因果结论。

动态信息由场景组织，动态概念信息由既有动态概念树组织。概念树遵守2220的独立概念身份、唯一动态本体根和多父DAG；不增加新根、新概念仓或第二写入owner，也不按场景或具体存在复制一棵权威概念树。

核心用途包括动态区分与识别、保存可复用的变化条件、用关键阶段简化过程描述、组织上下位分类和支持自然语言命名。动态二次特征是提取区分条件的重要材料，不是概念的全部内容。概念命中不证明动作已实际执行、任务满足、方法可调用或因果成立。

## 2. 逻辑字段与关联结构

以下是完整概念信息的逻辑组成，不要求把全部关联内嵌为一个对象；对象联系用正式关系承载，必要非拓扑值用合法值或类型化定义材料承载。

| 组成 | 必要性 | 内容及边界 |
| --- | --- | --- |
| 概念节点身份 | 必需 | 独立稳定概念身份，不复用动态、存在、特征或词条身份 |
| 本体根归属及直接上位 | 必需关系 | 唯一归既有动态根；非根须可达根，允许多个合法直接上位；直接下位由边反查 |
| 主体与参与角色约束 | 必需定义 | 主体及必要子存在/参与角色由存在概念约束；通用优先，必要时收紧概念范围 |
| 关键变化条件集合 | 必需定义 | 可由状态/变化求值的特征概念、二次关系概念条件，或已成立的子动态概念；非根定义不得为空 |
| 组成及时间约束 | 必需定义 | 条件位置、角色绑定、先后/交叠/间隔以及必要重复要求；未限制之处明确为不要求，而非精确零 |
| 必要取值/规则引用 | 条件必需 | 已有概念不能唯一解释输入提取、计算或时间量时补充合法规则和参数；不得由调用点猜公式 |
| 自然语言名称 | 可选关系 | 概念按2210关联词条和别名；名称不参与语义身份，也不参与模式是否满足的判断 |

形成来源、实例支持、上下位形成依据、用途及治理记录分别保存。它们使形成过程、真实使用和淘汰有据，但不把支持次数、创建者、具体人、具体场景或绝对时间加入通用定义签名。本轮不新增版本、代次、幂等、批次等业务字段；概念既有发布可靠性、固定定义引用和7140治理仍有效。

场景是来源事实上下文，不是普通动态概念必填的精确场景身份。确实影响识别的环境条件用合法存在/特征/关系概念及角色表达；没有场景概念根，不把场景ID冒充概念。通用优先意味着先用足够宽的可用概念；宽定义不能区分目标模式时才收紧，不机械强制所有约束取根概念。

## 3. 条件位置、叶条件与多来源比较

1. 每个定义内条件都有可区分的位置，位置不是世界实例槽或新增世界身份。引用相同概念的`A₁…A₂`是两个条件位置，不能按概念ID去重为一个A。
2. 匹配时把本次具体主体、子存在、源状态/动态发生绑定到定义角色与位置；实例绑定不回写定义。要求两次发生时不得让同一次发生同时满足两次重复要求。
3. 不同条件可合法共享同一来源的不同属性，但共享必须符合定义；共享不增加发生次数，也不能绕过重复位置约束。
4. 最底层条件必须能由已成立状态、原子变化及其合法比较直接核验。可以引用已经成立的子动态概念，但不先要求待生成的普通动态概念存在；子概念展开、定义引用与上下位均不得自引用或成环。
5. 前后状态条件引用固定特征概念定义，不动态追随准确F后来的名称选择。来源值始终取原状态准确内容，不取目前的存在采用值替代。
6. 二次条件使用7170/7180概念及4150/4151合法求值材料。每项准确结果为具名I64；多个维度分别求值后组合，不把向量、文本或布尔命中冒充单项准确比较值。
7. 持续时间、周期、速度或步频等须明确输入角色、多个来源发生/条件位置或有限窗口，以及正式类型、单位、算法和参数。是否按单步或完整周期计数必须可回查，不仅保存一个无来源数值或自由文本公式。

## 4. 重复抽取与关键阶段抽象

重复抽取与选择性抽象是两个不同操作：

| 输入与目标 | 概念含义 | 不允许的解释 |
| --- | --- | --- |
| `ABABAB → AB` | 提取重复结构；必要周期、间隔和重复条件另由定义保留 | 原实例只发生过一次AB，或删除其它发生 |
| `ABCD → A…C` | A和C及其必要关系是当前识别定义所需条件 | A/C自动紧邻、B/D被禁止或现实中不存在 |
| `ABCD / AECF / AGCH → A…C` | 不同细节可以满足同一关键结构 | 只要包含A/C就必然同类，不再核验主体/时间/其它必要条件 |
| `A₁…A₂` | 同类条件在两个所需发生位置出现 | 用同一次A重复引用来满足两次发生 |

允许任意长度、多特征并行、交叠及不连续模式，不能把所有概念限定为AB。省略阶段不等于省略其对时间约束的影响；若识别依赖间隔、连续性、停止性或相对顺序，就必须把相应约束留在定义内。

动态实例仍保留4210规定的真实顺序、发生身份、间隔和来源。概念不是可回填的原事实压缩文件；抽象掉的条件只能表示“不要求”，不自动表示“不发生”。缺测不证明停止或不存在某阶段，首尾相等也不消除中间变化。识别中可以忽略的阶段，在因果分析中仍可能重要。

## 5. 形成过程

### 5.1 收集与暂配

从一个或多个场景目录读取多组实际动态，在一致读取边界内保留发生主体、时间、覆盖范围及合法来源。最小动态和基本动态组先按4210成立，不等待重复或概念命名。

尚无目标动态概念时，依据已成立的存在概念、特征/二次概念及可直接求值的变化条件进行暂配；可比较时间次序、幅度、节律、结构等。暂配只是可撤销的调用期候选，不生成“同类已被证明”事实，也不把相似样本的传递链自动视为整体同类。

### 5.2 提取候选条件

按同类或类似组对齐主体角色、条件位置和可比来源，提取共同结构及候选二次特征。区分稳定共现的条件与有实际区分作用的条件，尽量保留足以识别的简化结构，并保留必要适用范围。

候选至少有完整合法定义和真实来源依据。多组样本用于发现重复结构及检验可靠性；不引入固定三次命中、成熟度或观察天数作为发布门槛。2220允许一次完整来源形成可用定义，但一次来源不足以宣称已经证明跨实例可靠区分能力。

### 5.3 检验与反例

候选要在支持材料中逐项核验条件及角色，并尽可能与相近但不同的动态比较。仅把同一批数据按候选分组，再以该组命中率证明候选可靠，属于循环自证；后续独立发生材料和反例用于修正适用范围、补条件或淘汰。

删去B/D后，如果原来需区分的模式也普遍满足`A…C`，只能说明得到更宽概念；不能继续宣称保留原区分能力。增加或减少条件会改变定义，不原地覆盖旧概念含义。资料不足时保留候选及不足说明，不伪造验证成功。

### 5.4 查重、发布与支持

完整定义先规范化：主体/参与角色、条件位置及绑定、概念引用、组成关系、时间条件、取值规则和必要参数共同参与等价。位置标号本身不创造语义；角色重命名和存储顺序变化需按规范化合同消除，但不能合并重复发生位置或丢失先后条件。

在动态根内精确查重：完整定义同义则复用，不以名称相同、暂配相似或支持样本重叠判定同义。活跃/冷却概念可复用；退役命中按7140显式治理，不另造同义身份绕过；不可逆退出后的重新形成沿7140使用新身份。

业务准入通过后，经唯一概念树数据服务在同一owner写集中完整发布普通概念节点、规范化定义、根归属及至少一条合法初始直接上位边，不能先公开无父孤立概念。形成来源按正式发布合同同时绑定所需依据；实例支持、名称及后续合法增补父边可按各自合同分步完成并独立读回。已有发布和支持不因后续一步失败而被伪称未发生；跨owner或多次调用不宣称全流程原子，不增设第二持久意图账。技术失败、同义缺失和业务候选不成立分别报告。

## 6. 组织、完善与治理

动态概念组织在动态根下，以定义包含依据形成直接上下位。例如更细的`A-B-C-D`在主体、角色、时间条件均蕴含较宽`A…C`时可以作为其下位；单纯删列表元素不证明包含，收紧或改变时间条件还须核验。

允许根向叶细分、由多组模式形成共同上位，以及在已有层级中插入中间概念。保留合法多父关系，根可达、定义引用和来源形成链均须无环。没有非空合法约束时复用已有动态根，不创建无定义普通概念。

完善可补充来源、支持、语言名称和不改义的关系。若改变关键条件、参与角色、适用范围或时间约束，形成新的规范化定义并查重，而不是修改原概念的含义；原实例及原引用继续按其固定定义解释。

用途与治理按7140单独记录。形成、后台积累、结构引用或匹配命中次数本身不自证有用；真实识别、区分等合法消费可按既有用途合同提供材料，支持后续保留、冷却、退役和淘汰。概念退出不删除来源动态，来源材料依法清理也不把已经完整保存的概念定义自动判成不存在。

## 7. 结构映射与类能力

| 对象/能力 | 提供与写入责任 | 读取和验证责任 |
| --- | --- | --- |
| 实际动态及场景目录 | 4210动态应用组合，动态唯一数据owner保存，场景只组织引用 | 动态概念应用读取真实来源与覆盖，不扫描缓存造事实 |
| I64计算及RC求值 | 4150/4151的DATA外计算应用，使用合法比较提供者 | 概念应用消费具名结果、来源与非成功，不持久冒充世界实例 |
| 动态概念形成与匹配 | DATA外动态概念应用：暂配、提取、抽象、验证、完整定义查重和实例绑定 | 逐条件匹配，返回匹配/不匹配/证据不足及技术失败的区别 |
| 概念定义与图 | 4240唯一概念树数据服务：保存完整定义、根归属、直接上下位和合法关联 | 独立读回定义、关系、来源/支持；不在DATA内裁决识别正确 |
| 名称、用途与治理 | 既有概念/名称owner与7140业务路径 | 名称不代替定义，用途不混入签名，引用保护不绕过 |

动态概念类不是第二动态数据类，也不能复制概念CRUD。它应具备按模式召回候选、展开可求值条件、绑定实例角色、求值及区分、从多组来源形成候选、选择关键条件、规范化复用、组织上下位和提交合法治理材料的应用能力。

匹配结果可以有零个、一个或多个概念；多项成立不按名称或首项强选唯一。单名称采用是后续选择，不删除其它合法支持。展开和枚举均须有限预算，未展开、来源已清理、缺规则和资源失败不等于条件为假或不存在概念。

## 8. 旧定义退役与实施边界

4240旧第12节以精确场景、具体主体、完整固定相对时间槽定义动态概念，并仅允许每槽非空的删特征上位；这些限制退出本模型的新生产解释，当前动态概念逻辑唯一以本规范为准。旧宿主实例槽、共同F快照和完整时间骨架不重新成为新字段前置。旧载荷、接口及已形成定义仍按原格式读回和保护，不能原地按新义解码。

定义与来源/支持必须分开存储：概念定义自身完整，来源事实的历史引用按既有闭包保护；释放当前来源引用不自动释放历史原生关系对端点的保护。来源清理后需要原payload的审计、首次支持和恢复不得猜成功；墓碑不是完整动态。定义引用、父边、名称、来源和支持须按各自合同处理，不批量释放。

本版固定概念模型、逻辑字段、形成顺序与可验证边界，不冒称已有代码或新ABI。后继结构/算法子合同仍需确定类型化条件与时间约束编码、规范化规则、具体暂配/筛选算法及参数来源、预算、完整发布/读回、失败和旧格式转换；不能临场以字符串表达式、旧28项布局或旧精确时间DTO填补缺口。4240只负责结构承接，4151/4241既有二次计算/RC合同不因本版改义。

0300 C038保持未决：本规范不授权新增持久二次准确实例、二次当前值或由它们补造状态/动态。概念定稿也不自动激活旧动态概念设计或代码计划。

## 9. 验证合同

| 验证项 | 期望 |
| --- | --- |
| 动态信息与概念归属 | 实例由场景组织，概念归既有动态根，身份和owner不混同 |
| 无普通动态概念的初次输入 | 仍可由状态/变化叶条件形成完整候选，不循环依赖 |
| 多主体同类模式 | 用存在概念绑定角色，具体主体/场景不进入通用签名 |
| 同义定义与位置重命名 | 规范化复用；不同顺序、不同重复次数不能误合并 |
| ABCD抽象为A…C | B/D不要求也不禁止；仍核验必要主体、先后和间隔 |
| 重复位置和多来源步频 | 发生身份及角色/范围明确，同一次发生不充两次 |
| 相似暂配、自选样本及反例 | 暂配可撤销，不自证可靠；反例使定义/范围重新评估 |
| 支持与不匹配 | 逐条件读真实来源；缺测、已清理、预算不足不猜真或假 |
| 上位抽象和中间插层 | 定义包含有据、合法多父、唯一根可达、无引用环 |
| 名称、用途、退役与来源清理 | 分账且受引用保护，名称/次数不取代定义或可靠性 |
| 发布中断、旧格式、未实现编码 | 返回真实阶段或明确不支持，不伪称完整新能力 |
