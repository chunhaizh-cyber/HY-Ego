# 4202 子规范 场景字段与世界组织

编号：4202
日期：20261105
版本：v2.1
状态：正式子规范

直接上级规范：1150。

直接依赖规范：1130、1140、1160、1170、4015、4190。

相关边界规范：4200、4211、4212、6120、6220、6300、7130。

## 1. 范围

本规范展开1150的场景结构合同：全局根与世界根的承载、场景操作、成员与迁移、特征写入、状态列表、动态列表、同节点场景视角、世界位置投影和非成功边界。场景直接保存成员、边界、状态列表和动态列表引用；不设场景特征根、状态根、动态根、关系根等实例组织锚，也不设C/E/S状态使用绑定。

## 2. 全局根、世界类型与世界根承载

1. **全局根**：一个场景类节点，按固定结构身份登记；初始化先按固定身份恢复并完整核验，确认不存在时才建立。代码全局变量只持有其受保护引用，不是第二事实。全局根只有“世界根挂接”出边，不具成员、特征、状态、动态或专属概念。
2. **世界类型**：每种世界类型是一个登记节点（固定登记键，可附名称关系），不是代码硬编码枚举；新增世界类型只需登记新节点，不改既有结构。
3. **世界根**：普通场景节点，以“世界根挂接（全局根→世界根）”关系挂在全局根下，并以字段引用其世界类型节点。同一世界类型在全局根下恰一个世界根，按“全局根＋世界类型”唯一定位，不扫描、不按名称或无父节点猜测。
4. **初始化**：建立全局根及现实世界、自然语言世界、内部治理世界三个世界根；模拟世界根按需建立。重复初始化复用既有全局根、世界类型和世界根，缺失者按登记补建，不重建第二套。
5. **模拟隔离**：模拟世界只有一个世界根；每次模拟学习在其下建立隔离的子场景树，隔离由子树边界保证。
6. **世界归属**：任一场景或存在的所属世界由沿直接父链有界上行至世界根得到；可建非权威索引加速，与父链冲突时丢弃索引。
7. **守卫**：迁移、子场景挂接、范围查询的上行均止于世界根；跨世界的父子或成员关系一律拒绝。其它强类型引用可以跨世界，例如动作动态的目标引用与结果关系、实例特征准确值中的信息节点引用；跨世界引用不改变被引用节点的归属和写入权。
8. **坐标系**：每个空间世界（现实、模拟）以其世界根坐标系为绝对坐标系，场景坐标范围在同一坐标系中表达。存在离开场景时按第4节先置空绝对坐标、迁移后再写入，写入值仍是该世界根坐标系中的观察值。
9. **信息存在的场景**：需求、任务、方法、执行与动作治理材料等内部治理信息存在归内部治理世界的具名场景；词条、语言材料范围、指代实例、代词概念等语言信息存在归自然语言世界的具名场景。成员归属由各自owner显式写入，不按坐标判定；它们的实例特征F变化生成的状态挂入所在场景的状态列表，与普通存在相同。

## 3. 场景操作

1. 建立全局根与世界根只经系统引导入口；普通场景建立须给出直接父场景，可先建立为空场景，不要求初始特征或闭合边界。
2. 建立场景时在同一组合发布中写入场景身份、父子关系和存在身份；场景作为存在，有特征后派生专属存在概念（1140）。
3. 子场景可迁移到同一世界内的新父场景；世界根不可迁移，不得形成环。
4. 只删除非世界根的空场景：无直接子场景、直接成员存在、状态和动态；仍被其它场景边界引用时拒绝。

## 4. 成员与迁移

1. 普通存在只能直接属于一个场景，并归入当前能明确的最小场景。
2. 迁移在同一世界内进行，在一次组合发布中替换成员关系，稳定编码不变；存在有动态不阻止迁移。
3. 已挂接的状态和动态留在原发生场景列表，不随存在迁移、不复制。
4. 位置不能确认的存在由owner逐级迁往上位场景，最远到所属世界根（1140）。
5. 存在离开场景A的顺序：先由相关owner删除或修改该存在与A相关的关系信息（A的成员关系及依赖A的关系）；再将其绝对坐标F置空，置空形成的状态挂入A；然后迁移；在新场景B写入坐标，形成的状态挂入B（发现）。置空与写入都是F当前值的实际改变（4212第3节、6260）。

## 5. 场景与场景内存在的特征写入

场景owner提供场景自身特征及场景内存在特征的添加与更新入口：核验目标是该场景或其范围内存在，调用存在owner写入特征并同步专属投影；当前值实际改变时，在同一组合发布中生成状态并挂入发生场景状态列表。原子发布能力具备前，“特征已改变但状态挂接未完成”只作过渡状态返回，调用方保留原身份继续补偿，不得解释为零写入。

## 6. 状态列表

1. 挂入条件：状态可完整读回；其F的持有链上溯所得被描述存在属于该场景范围，或就是该场景节点；同一状态只挂一个场景；挂接在生成状态的同一组合发布中完成。
2. 挂接只在挂接时核验；之后存在迁移不改变已挂状态。
3. 移除：仍被该场景动态或其它正式事实引用时拒绝。
4. 定期定量删除：场景执行其状态列表的清理，规则与默认阈值按4190第7节；数量按本场景状态列表计数，可按世界类型配置覆盖值（例如模拟世界可更短）。保护性引用按4190第7节（动态引用、代表实例采纳、他人特征、需求、任务、方法、因果的正式引用），是否仍被引用以引用闭包查询为准。

## 7. 动态列表

1. 每个场景只记录发生在本场景的动态；同一动态只挂一个场景。挂接时核验：原子/复合动态的主题和全部成员状态属于该场景；动作动态的执行主体属于该场景。
2. 跨场景的变化记为各自场景的未融合动态（如“离开A”在A、“进入B”在B）。存在离开A时：先删改关系信息，置空坐标形成的状态与A内上一坐标状态构成“离开A”原子动态；迁入B写入坐标只生成首个状态（即发现），不构成原子动态。
2a. 动作动态挂入执行主体所在场景，只核验执行主体；目标信息节点在其它场景或其它世界不阻止挂接。
3. 融合动态由共同上位场景按需形成并挂入该场景动态列表；其成员引用该场景范围内子场景的状态和动态（范围包含），原状态与动态不搬迁、不复制、不重复挂接。子场景不得建立涉及兄弟场景的融合动态。
4. 动态列表是引用集合，不证明连续链或时间序列；时间顺序由状态强时间重建。定期定量删除同第6节第4项（数量按本场景动态列表计数），先动态后状态。

## 8. 同节点场景视角与内部递归

1. 普通存在可按需启用场景视角，与存在身份同一节点、同一稳定编码；启用不改变其直接所属场景，不使对象成为自身成员。该视角的场景父即其直接所属场景。
2. 对象作为整体观察时，其状态和整体变化由所在场景记录；把其组成部分或内部成员作为独立存在观察时，内部状态和动态记在该对象的场景视角列表中。例：道路上的汽车，整体位置与移动归道路场景；车轮、发动机的状态与动态归汽车场景视角。
3. 场景不是相机画面或观察者位置；一个画面覆盖多个场景不自动合并，观察者所在场景不吸收被观察场景的事实。
4. 外层场景可经范围包含读取内部事实，但不把后代状态重复挂到祖先；后续深入观察不迁移先前的整体记录。

## 9. 世界位置投影

统一位置投影为：节点、直接父、父关系种类（场景层级、场景成员、存在组成、特征持有）、所属世界根和有界上行路径。场景归属与父存在组成分别返回，不压成唯一结构父。

## 10. 非成功与发布边界

至少区分：场景/父场景/存在/状态/动态不存在、目标世界不明、跨世界拒绝、归属冲突、形成环、根不可操作、场景非空、引用阻止、结构不一致、资源失败。同一次场景业务变化整体发布；失败零变化。
