## 1. 范围与职责

本规范定义取得方法资格的函数如何声明自身、登记方法头、读取参数、执行动作及提供任务反馈。普通helper或底层CRUD不因是函数就成为方法。

一个方法的主执行体是正式注册函数。登记声明可以由函数内第一部分代码提供；统一方法执行器通过方法头中的正式注册引用解析并调用，不能按名称、裸地址、节点号或字符串反射任意函数。

方法四部分是流程，不是四类数据节点，也不要求新增四个独立服务：

```text
一、查询并确保自身方法登记
二、从任务实参赋值并核验必要执行条件
三、先登记动作动态，再执行真正改变或观察
四、由正式owner取得实际结果并显式关联，交付既有预测
```

本能方法函数的唯一入口参数是临时参数场景，不增加通用“上下文”参数。方法实例化时按5260第5.1节将所需条件信息传递到任务Vt；任务筹办根据Vt条件信息查找正式信息，再把本次条件及结果所需全部实际节点引用按5350第6节固定参数顺序装入该场景。容器绑定只读，引用的信息按声明及正式owner合同读写，不因“只读”禁止方法正常改变目标。纯调用治理信息由外层执行器持有。函数返回本次运行条件—结果对；执行后的效果验证归任务，方法不得兼任自身效果成功的最终裁决者。模拟执行与知识替代按第3.1节和5370处理。

本能方法只经任务链（查找方法→采用→执行）由任务工作池调用：任务工作池调用通用任务执行函数，依据已采用方法分派本能；self只承接与确认需求，不能自己满足自己的需求，也不直接调用本能方法函数。结算等内部治理函数不是本能方法，不进方法树，不受本条约束。

方法函数只声明本方法必须确认的结果要求和可供观察的对象 / 特征，不选择固定感知设备。任务在采用与冻结时依据自我当前感知能力形成具体结果获取方案；没有合法方案时第三部分不得进入，普通、探索和试验调用都保持零动作。

## 2. 预注册与第一部分：自身登记

### 2.1 启动入口与声明

动作函数必须先进入正式函数注册机制。注册表只保存稳定登记名到C++函数入口的映射；它不保存参数规格、作用对象、FT、条件、结果、安全约束、结果确认要求或声明版本，不成为第二方法仓。未有方法身份时，由函数内登记部分形成方法登记材料，经唯一方法记录面分配身份，不能自行用函数名、地址或哈希制造方法身份。

函数内登记材料至少能提交：所代表方法的正式来源、可改变特征类型声明（含关系型F，3100方案A）、对应的动作概念（挂动态根，5350）、作用对象角色和范围、Vm参数规格、全方法必要约束，以及结果确认对象、特征、允许结果、证据要求与多渠道组合语义。所用FT/概念/规则必须已合法成立；正式参数规格只写入唯一Vm，方法头和注册表不复制。结果要求不得绑定具体摄像头、传感器、线程或单一设备实例。

输出类方法（如询问）的可改变特征是输出材料的F；依赖他方回答的目标F只由写回类方法声明为可改变。完整目标、依据和所需来源必须以正式信息引用按固定顺序进入唯一参数场景，经各自owner读取，不以新增上下文绕过规格。

本能参数规格由函数内部确定，首次运行的登记阶段按5350第6节整体生成；外部装配只提供合法依赖，不另传一套参数角色或规格定义来决定函数接口。已有规格读回并与函数当前声明逐项核对，一致则复用，不一致按5350第6节由唯一方法owner在原方法身份下原地修订（参数规格允许修改，只来自函数自身声明的改变，R118）；具体已学条件归C；初步模拟输入限定归同Vm附属结构，不混入或改变有序规格构成。初始输入限定由原函数登记正式范围、关系及模拟事件范围，不自证效果或长期C/R。

第一部分在首次合法登记调用时检查方法树：

- 完整找到自身记录：核对参数规格及声明，一致则复用；函数声明的参数规格已改变时按5350第6节原地修订规格，不另建方法身份；不能用初始声明覆盖后来练习完善的配对或治理状态，也不改已登记的登记结果组（新结果经新条件结果对表达）。
- 完整查找确认没有：经唯一方法记录面建立方法头、函数绑定、唯一Vm及必要规格/组织，并完整读回。
- 重复/并发同义登记：收敛为同一记录；复义、查找未完成或读回失败明确拒绝，不当作“没有”再次创建。
- 已退出：依方法治理/迁移处理，不换名称或新键绕过退出。执行期参数场景与当前Vm参数规格不一致或正式结构缺损时，按5350第6节进入工程诊断与终止，不能解释为执行条件不足，也不在执行中重写规格。

既有方法尚无条件—结果对时，允许原函数经唯一方法owner，在同登记名、同一当前规格条件下补齐初始输入限定中尚空的声明项。分支域、参数位置关系、模拟事件范围等声明项分别判空；已有其它非空声明项不阻止补齐空项。非空项必须完整同义才可复用，异义拒绝，不追加、替换或重排其内容；补齐空项不改写参数规格及已有知识。

同一次登记请求先完整核验全部声明项及相互约束，再将本次待补空项作为一个原子变化发布并完整读回；有任一冲突或结构错误时不得留下部分补齐。已有条件—结果对的方法只允许同义复用，不通过此入口补齐声明。该准入不适用于其它结构损坏，不生成动作、效果或长期C/R；环境/页面来源不自动证明现实交互者身份。

“确保登记”在动作开始前具有独立的完成边界。头和必要规格不能完整读回时，不向普通调用方返回伪完整方法。

### 2.2 登记不是执行

登记模式只执行第一部分并返回，不落入第三部分，不移动身体、驱动外设、通信或执行其它方法动作。登记本身仅产生合法方法结构及必要内部记录。

没有条件—结果配对时，可以建立明确不完整的登记头；不得补造空结果、可靠性或预测，也不得因可调用函数存在就报告目标可达。具有正式初始知识时，配对仍经5350的完整来源/结构准入发布，不以注册声明自证经验效果。

完全懒登记意味着尚未触发函数的方法不可由方法树查到。需要提前发现时，调用方可以在具名启动/装配合同中安排只运行登记阶段；本规范不自动增加8120的初始化步骤，不以方法查找失败触发无界扫描或真实执行。

实际任务必须先取得已登记结构，再按5260采用并冻结。第二至四部分只校验本轮已冻结方法，不在执行期偷偷补造冻结前缺失的头、配对、入口或Vm；发现此类缺口返回不一致/缺结构，不继续动作。

## 3. 第二部分：参数赋值与执行前核验

Vm提供固定有序的参数信息类型及概念范围，具体条件来自C及共同约束，任务所需要求经实例化交付到Vt；任务据此在自我所在场景及其子场景查找实际信息并为本次调用构造临时参数场景。参数场景是调用期内存容器，不进入世界树，按固定位置保存实际信息节点引用，读取及修改均通过对应信息类型的正式owner；容器用完即释放，不持久化到Vt。Vt保存条件要求不等于保存实参容器，也没有“任务Vm”。函数只接收该参数场景并按完整调用合同读取：

- 外层执行器持有纯调度/冻结身份，不另组通用上下文传入函数；但任务、方法、规格或值域节点若本身是函数实际业务输入，必须在正式规格声明的位置引用放入场景，不得借外层持有之名绕过唯一入口；
- 核对参数数量、顺序、信息类型、所属概念范围、存在位置的必需特征类型、特征位置的所属存在位置及实际绑定引用；不把所有参数强制解释为F，需要特征值时才经绑定的特征读取内联值或合法值引用，不以裸值替代绑定；
- 按C核对值域、同一/不同/集合包含等跨位置值约束及共同执行约束；不能因参数相邻就认定所属，也不能因概念相同就合并参数；
- 涉及现实改变时，5260/6150要求的授权、安全与作用范围。

参数齐全仅证明材料能够读取，不等于条件具备、适用或已获现实授权。必须按已声明条件和类型规则检查，不在函数里暗设第二套所学条件。零参数须显式合法；部分读取、错误类型、位置错配、失效或缺值均不得猜补默认实参。业务条件变化与工程错误分账，后者不得作为函数业务结果或条件知识。

检查成功后将参数场景中的实际材料赋给本次调用局部参数，并在动作前固定本次实际读取和使用的条件材料；未读取或未使用的绑定不得为填满返回结构而写入条件侧。不把实际参数、当前观察或任务状态写回共享Vm。结果获取方案由外层执行器在进入函数前完整读回并核验；函数只执行其已冻结且当前仍合法的动作范围。必要条件或结果获取方案在临近动作时失效，应在合法作用边界内拒绝/停止，不能沿用较早“曾经具备”作为许可。

函数内部按方法实际需要使用参数（3300第5节）：读取参数所指节点信息；改变某些参数所指信息；或依据参数形成一组指令发给外设。改变哪些参数、改变与发指令的先后由函数实现决定，C不限定。外设信息不作参数，外部信息被动接收并存放在外设世界场景中，函数需要时经参数中的标识在内部读取。

条件核验可使用独立事实提供者，但只是执行前检查，不是执行后效果验证。只读或纯观察方法的执行权限仍按其原范围，不新增现实改变授权门槛。

### 3.1 模拟参数场景与同一函数执行

能够只操作参数场景所指数字信息的方法，模拟时仍调用同一注册函数；入口核验绑定属于模拟世界，读写和结果读回只指向该次隔离实例，不按函数名另设专用学习算法。概念可共享，实例必须重映射，不能借函数内部固定对象、宿主端口或可写引用旁路回到现实世界。条件和结果都必须从该场景的信息引用取得，不增加绕过场景的第二份输入/结果域。

只能直接影响现实、不能重定向到模拟实例的方法不得在模拟中真实调用。需要其结果时由学习按5370读取尝试学习已有的适用条件—结果知识，标明知识推演；无适用结果则保留未知，不伪造函数已执行、动作动态或实际观察。该规则也约束网络提交、设备控制等嵌套调用，不因顶层函数属于内部治理就允许隐藏现实副作用。

模拟动作、状态与结果只属于模拟世界；真实运行、登记、模拟运行与知识推演来源分开。模拟不要求伪造服务任务，不改变服务值或现实任务状态；真实执行授权、安全和独立结果获取合同原样保留。具体采样、重置、复测及结束统一按5370第5.3节。

## 4. 第三部分：真实动作

只在本次实例、参数、必要条件和安全门均合法时进入真实动作部分。实际动作严格限制在已声明对象、范围、参数和可用函数入口；函数返回成功不自动形成预期状态。

**出站本能（R110）**：

1. 经任务链执行的出站本能交给语言功能的是正式表达需求（在本能调用内派生），不是预先造好的标准句。
2. 出站本能已进入动作而留档或入列未完成时，按部分完成报告，不得报入口拒绝，也不得把生成成功记成发送成功。
3. 输入侧不匹配问与答：收到的信息只保存为场景信息；问题是否已有答案由询问方法在自然语言世界按结构比对确定（5380第3.6节、7240第5.5节），答案由提出补问的父任务经需求owner写入（5260第5.2节第7项）。
4. 各本能的具体合同见5380。

运行事实必须区分：尚未进入动作、已经进入/部分执行、已按函数合同返回或函数执行失败；动作效果是否成立仍待任务独立判定。这里是逻辑区别，机器枚举和异步回调合同由精确实施合同冻结。

本能方法进入第三部分时必须先以执行实例X为唯一来源建立动作动态并挂入执行主体所在场景（1170、3200），挂接只核验执行主体；动作动态对目标信息节点的引用可以跨场景、跨世界，不因此建立跨世界父子或成员关系。改变型本能方法随后改变目标，观察型（读取）本能方法随后读取并返回目标材料；两者都不得先执行后通过场景列表反猜动作。动作动态建立失败时不得进入真实动作。本次方法只建立这一个动作动态；函数内部为确认结果对内部特征的再次读取、对外设场景的读取及发给外设的指令不另建动作动态。观察本身是读取外设场景信息的本能方法，作为独立方法调用时按本条建立其动作动态。动作已经建立后发生的执行失败、结果未知或关联失败必须保留动作事实并返回部分完成，不得因记录不完整自动重做。

异步动作必须保留运行关联及真实已知进度，命令已接收不冒充动作完成。异常、取消或超时保留已经发生的事实；动作是否可停止、补偿或重试由既有任务/安全合同决定，函数不扩大作用范围补救目标。

## 5. 第四部分：本次运行条件—结果对

函数返回值固定为本次运行条件—结果对，而不是通用执行上下文或长期方法配对：

| 一侧 | 合同 |
| --- | --- |
| 本次条件 | 只保存函数在动作前实际读取并用于本次运行的固定参数序号、实际节点和必要准确值快照；零参数方法显式返回空条件组。 |
| 本次结果 | 保存控制到达位置、结果取得状态、动作动态身份以及本次已经形成的正式状态、动态、二次特征或待观察目标；读取型保存本次返回的读取材料（作用对象、F、读到的准确值、渠道），其取得时间即读取动作时间。 |

结果取得状态至少区分未取得、已取得、待取得、部分取得和无法取得。调用成功、命令已发送或函数已返回不能冒充实际结果；延迟结果保持待取得，由任务沿同一执行身份补齐。结果实际值经另外的观察途径取得：内部特征由owner再读一次确认，外部事实经观察外设场景确认；只有观察到结果才算本次执行结束，等待期间任务进入等待并释放工作线程，不阻塞worker。条件和值快照只作本次运行材料，不写回Vm，不直接发布为方法值域。结果读取同样依据参数场景声明的目标引用及正式owner；方法局部计算值不能代替正式结果读回，模拟也不例外。

实际结果按结果项所指特征类型（含关系型F）由对应owner读回。输出类本能只交付实际输出材料，不冒充依赖回答的目标已满足；写回类本能交付owner实际保存并采用的结果，任务经owner独立fresh读回目标F判断满足，不能把输出、发送、回答存在或函数回执当最终满足。规则与明确回答是同一写回本能的不同条件分支，实际不足时不执行。

第四部分分别形成或引用以下材料，不合并成一个“成功”布尔值：

| 材料 | 只证明什么 |
| --- | --- |
| 函数执行报告 | 本次控制流程到达何处，是否返回、拒绝、部分完成或异常。 |
| 真实动作执行材料 | 实际调用的入口、对象、参数来源、开始/结束或已知进度及动作范围。 |
| 动作动态材料 | 本次动作已经进入执行的主体、定义、来源、目标和时间；它不复制结果变化。 |
| 动作结果关系 | 改变型使用`导致变化`，只接受本次调用显式动作身份，可以跨世界。读取型的正常结果是返回材料，由后续治理消费，不要求为此生成状态或结果动态；读到的值确与F当前值不同时由事实owner另行生成状态，存在该结果动态时才以`观察取得`关联本次动作。 |
| 预测材料 | 动作前已有配对、实际条件及参数支持的预期结果、允许范围和观察时机。 |

第四部分可以在方法返回时交付预测，但预测依据、采用配对和绑定材料必须在动作前固定；不得从第二路线的实际效果反向改写预测再自证命中。没有足够预测依据时明确无预测，不返回默认零、空结果或虚构范围。

仅有命令已发、函数已返回或预期变化，不能生成目标变化动态。动作动态先记录真实动作已经进入执行；合法前后事实具备后，变化仍由事实owner发布为独立结果动态。调用方再按4220以显式动作节点建立关系，不增加第二变化记录。没有结果动态时动作独立保留；没有动作节点时结果动态不补造来源。

方法输出需要确认哪些对象 / 特征、允许结果和取得条件的声明，但不固定具体感知设备，也不因此自行裁决效果。外层执行器把返回的本次运行条件—结果对关联到其持有的执行实例；函数返回结构不重复携带任务、执行实例或冻结方法上下文，也不直接返回任务完成、需求满足或方法晋级结论。

## 6. 独立观察与任务验证

两条路径在任务中汇合：

```text
方法执行路线：冻结知识与实参 → 动作执行 → 执行材料/预测
独立结果获取路线：按冻结方案等待适用事件 / 条件 / 地点 → 通过当前合法感知渠道取得材料 → 正式事实读回
任务：核对同次执行和作用范围 → 二次特征比较 → 影响评估、验证与结果收束
```

独立表示事实来源不依赖方法自己的预测或成功声明；不强制另一个设备、线程或进程。结果可以立即取得，也可以在之后的事件、其它地点或后续观察步骤中取得；worker不得为此无限阻塞。读取内部治理对象或仓库时，必须经其正式事实owner重新读回，不能把执行函数的局部返回对象当独立效果。观察方法的正式输出本身是结果获取途径。观察动作与结果使用`观察取得`关系，只证明本次观察取得材料，不得误写为观察导致材料所描述的事实。

视觉、听觉、触觉、设备读回、网络反馈和他人陈述等渠道可以并用，但必须在方案中明确任一、共同满足、优先、备用及冲突处理。渠道与信息来源分账：例如“张三说门已关闭”直接证明张三作出陈述，只能作为门已关闭的间接证据；不得把陈述来源伪装为对门状态的直接感知。

结果材料充分后、任务完成前，任务分别评估：预计与实际、变化方向与幅度、缺失变化、计划外变化、不可比较、多渠道冲突、目标当前是否满足、禁止结果 / 副作用及必要归因。这些结论不能合成一个由方法自报的成功值，也不替self决定任务后继。无预测只表示不能评价预测符合度，不妨碍在独立目标合同和足够事实下判断目标。

执行前没有可实现结果获取方案时必须拒绝进入动作；动作已经发出后渠道失效时则保留“动作已发出、结果未知”，优先恢复或替换渠道，不判成功、不完成任务、不结算需求，也不自动重做动作。

增大/减小用明确前后来源，特定数值/轮廓用实际与目标来源，均按4151/4180及相应RC计算。目标/预测只作比较参照，不成为已发生状态。任务实际结果和验证结论由task owner收束，需求满足和方法更新仍由各自owner处理。

## 7. 反馈完善

任务反馈以函数返回的本次运行条件—结果对为起点，关联外层持有的同一次执行、所用方法/配对、原预测、动作、延迟补齐的实际观察和任务验证，交[5370](5370_子规范_方法学习与知识形成.md)按学习准入分析方向分支与精度细分。未执行或结果尚未补齐的运行对不形成正常效果反例。方法函数不自报“成功次数”或可靠性；唯一方法owner依据正式实际运行及独立方法结果核验按5350第6.1节去重维护Vm统计。成功的参照是执行前固定的方法声明结果要求，不是任务需求目标。模拟及知识推演不增加真实次数。

本规范负责运行材料取得与交付并保持来源分账；学习候选形成、评审及需求满足与预测偏差的分账读取5370。学习没有形成新知识或发生工程中断时，运行侧仍按第8节保护事实，不因学习引入自动任务、现实动作或原任务结论改写权限。

## 8. 失败、重入与恢复

| 失败阶段 | 必须保持的边界 |
| --- | --- |
| 注册/登记未完成 | 不进入动作，不冒充缺方法或已完整；发布未知按原登记请求读回。 |
| 参数或执行前检查失败 | 不执行动作，保留明确失败来源，不补默认参数。 |
| 动作中失败/取消/未知 | 保存已知执行情况及运行身份，不把未知包装为未执行。 |
| 动作后记录/动态关联失败 | 报告已发生动作和记录缺口，不为补记录自动重做动作。 |
| 执行前结果获取方案缺失 / 不可实现 | 零动作拒绝，不转为无预测、探索或试验特例。 |
| 动作后结果渠道失效或比较未完成 | 保留动作已发出、结果未知，恢复 / 更换渠道；不回填实际值、不把缺值当零差异、不重做动作。 |
| 学习结束未形成新知识或工程中断 | 原任务事实保留，不回滚现实动作、不改原预测或重复任务；工程故障独立诊断，不转为学习业务成败或方法结果。 |

登记、第二部分和第四部分的技术重入不能重新触发第三部分。即使同一函数提供四阶段，阶段进入权、运行关联和动作重试授权必须显式区分；普通幂等键不证明现实动作可安全重复。

## 9. 实施前物理合同与验证

本规范固定职责及逻辑输入/输出；实现前仍需冻结：

1. 预注册声明身份、登记模式、调用入口和函数解析合同。
2. 方法头/绑定/Vm规格及配对的完整发布、同义查重、原地修订与current-only完整读取。
3. 临时参数场景唯一入口、绑定只读与信息按合同读写、本次运行条件—结果对、执行实例外层关联、结构化状态、成功谓词及异步补齐路径；模拟实例隔离和现实副作用阻断。
4. 预测来源、动作记录、动态来源关联、任务独立读回的实际提供者及失败恢复。
5. 旧函数、消费者、持久布局和工程接线的同次迁移/物理删除清单。

不得将上述未冻结物理项说成现成能力。最低验证覆盖：首次登记去循环及规格完整生成、重复登记不覆盖练习知识、函数声明改变时规格原地修订、执行期规格失配工程终止、无配对显式不完整、零参数和多参数、不同信息类型正式读取、只记录实际消费参数、位置/类型失配、前置失败零动作、待取得/部分取得/无法取得分流、动作后记录失败不重做、无观察不补动态、无预测、预测不可事后改写、数值与轮廓二次判定、任务验证与学习不越权、方法原地修订与在途执行冻结材料隔离及重启恢复。

本规范不直接修改代码、初始化顺序、公开ABI或测试入口；规范发布不证明函数、任务或学习闭环已经实现。

模拟相关验证还须覆盖原函数与参数场景的实际消费、条件及结果的固定参数位置绑定、模拟结果正式读回、固定现实对象访问阻断、嵌套副作用零调用、尝试知识替代/未知分流，以及真实统计不被模拟和重复反馈增加；测试触发仍服从项目协作规则。
