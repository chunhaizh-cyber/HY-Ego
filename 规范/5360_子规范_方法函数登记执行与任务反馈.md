# 5360 子规范 方法函数登记执行与任务反馈

状态：正式子规范

直接上级规范：3300。
直接依赖规范：5350、5260、4151、4180、4220。
相关边界规范：0050、3200、4330、6150、6330、8120、8210。

## 1. 范围与职责

本规范定义取得方法资格的函数如何声明自身、登记方法头、读取参数、执行动作及提供任务反馈。普通helper或底层CRUD不因是函数就成为方法。

一个方法的主执行体是正式注册函数。登记声明可以由函数内第一部分代码提供；统一方法执行器通过方法头中的正式注册引用解析并调用，不能按名称、裸地址、节点号或字符串反射任意函数。

方法四部分是流程，不是四类数据节点，也不要求新增四个独立服务：

```text
一、查询并确保自身方法登记
二、从任务实参赋值并核验必要执行条件
三、执行真正动作
四、形成动作执行/动作动态材料并交付既有预测
```

执行后的效果验证归任务；方法不得兼任自身效果成功的最终裁决者。

## 2. 预注册与第一部分：自身登记

### 2.1 启动入口与声明

动作函数必须先进入正式函数注册机制。注册项提供稳定的函数/方法声明来源及可解析调用合同；这一入口不依赖待建立的方法头。未有方法身份时，由登记来源精确查找对应记录并由方法owner分配身份，不能自行用函数名、地址或哈希制造方法身份。

声明至少能读回：函数入口、所代表方法的正式来源、可改变FT声明、作用对象角色和范围、Vm参数规格及全方法必要约束。所用FT/概念/规则必须已合法成立；函数注册表不是第二方法仓。

第一部分在首次合法登记调用时检查方法树：

- 完整找到自身记录：核对声明并复用；不能用初始声明覆盖后来练习完善的配对或治理状态。
- 完整查找确认没有：经唯一方法记录面建立方法头、函数绑定、唯一Vm及必要规格/组织，并完整读回。
- 重复/并发同义登记：收敛为同一记录；复义、查找未完成或读回失败明确拒绝，不当作“没有”再次创建。
- 已退出或声明不兼容：依方法治理/迁移处理，不换名称或新键绕过退出。

“确保登记”在动作开始前具有独立的完成边界。头和必要规格不能完整读回时，不向普通调用方返回伪完整方法。

### 2.2 登记不是执行

登记模式只执行第一部分并返回，不落入第三部分，不移动身体、驱动外设、通信或执行其它方法动作。登记本身仅产生合法方法结构及必要内部记录。

没有条件—结果配对时，可以建立明确不完整的登记头；不得补造空结果、可靠性或预测，也不得因可调用函数存在就报告目标可达。具有正式初始知识时，配对仍经5350的完整来源/结构准入发布，不以注册声明自证经验效果。

完全懒登记意味着尚未触发函数的方法不可由方法树查到。需要提前发现时，调用方可以在具名启动/装配合同中安排只运行登记阶段；本规范不自动增加8120的初始化步骤，不以方法查找失败触发无界扫描或真实执行。

实际任务必须先取得已登记结构，再按5260采用并冻结。第二至四部分只校验本轮已冻结方法，不在执行期偷偷补造冻结前缺失的头、配对、入口或Vm；发现此类缺口返回不一致/缺结构，不继续动作。

## 3. 第二部分：参数赋值与执行前核验

规格来自方法Vm，本次值来自任务Vt下的专属实例；没有“任务Vm”。函数按完整调用合同读取：

- 本次任务、执行轮次、实例方法和动作前冻结的配对/规格引用；
- 参数显式数量、类别、顺序、类型及绑定的具体F，再由F读取内联值或强类型值引用；不以裸值替代绑定；
- 具体场景/对象角色、必要当前事实和执行约束；
- 涉及现实改变时，5260/6150要求的授权、安全与作用范围。

参数齐全仅证明材料能够读取，不等于条件具备、适用或已获现实授权。必须按已声明条件和类型规则检查，不在函数里暗设第二套所学条件。零参数须显式合法；部分读取、错误类型、角色错配、失效或缺值均不得猜补默认实参。

检查成功后将任务数据赋给本次调用局部参数；不把实际参数、当前观察或任务状态写回共享Vm。必要条件在临近动作时失效，应在合法作用边界内拒绝/停止，不能沿用较早“曾经具备”作为许可。

条件核验可使用独立事实提供者，但只是执行前检查，不是执行后效果验证。只读或纯观察方法的执行权限仍按其原范围，不新增现实改变授权门槛。

## 4. 第三部分：真实动作

只在本次实例、参数、必要条件和安全门均合法时进入真实动作部分。实际动作严格限制在已声明对象、范围、参数和可用函数入口；函数返回成功不自动形成预期状态。

运行事实必须区分：尚未进入动作、已经进入/部分执行、已按函数合同返回或函数执行失败；动作效果是否成立仍待任务独立判定。这里是逻辑区别，机器枚举和异步回调合同由精确实施合同冻结。

异步动作必须保留运行关联及真实已知进度，命令已接收不冒充动作完成。异常、取消或超时保留已经发生的事实；动作是否可停止、补偿或重试由既有任务/安全合同决定，函数不扩大作用范围补救目标。

## 5. 第四部分：动作材料与预测交付

第四部分分别形成或引用以下材料，不合并成一个“成功”布尔值：

| 材料 | 只证明什么 |
| --- | --- |
| 函数执行报告 | 本次控制流程到达何处，是否返回、拒绝、部分完成或异常。 |
| 真实动作执行材料 | 实际调用的入口、对象、参数来源、开始/结束或已知进度及动作范围。 |
| 动作动态材料 | 具有真实前后状态和合法场景/主体关联时，按1170、4220形成或关联的真实变化。 |
| 预测材料 | 动作前已有配对、实际条件及参数支持的预期结果、允许范围和观察时机。 |

第四部分可以在方法返回时交付预测，但预测依据、采用配对和绑定材料必须在动作前固定；不得从第二路线的实际效果反向改写预测再自证命中。没有足够预测依据时明确无预测，不返回默认零、空结果或虚构范围。

仅有命令已发、函数已返回或预期变化，不能生成目标变化动态。只有合法实际前后事实具备时才能形成动作动态；变化由事实owner发布，动作来源按4220分阶段关联，不增加动态本体字段或第二变化记录。

方法可输出需要观察哪些对象/特征及何时观察的声明，但不因此自行裁决效果。返回结构通过运行身份关联上述材料，不直接返回任务完成、需求满足或方法晋级结论。

## 6. 独立观察与任务验证

两条路径在任务中汇合：

```text
方法执行路线：冻结知识与实参 → 动作执行 → 执行材料/预测
独立观察路线：实际对象 → 合法状态/动态或其它事实读回
任务：核对同次执行和作用范围 → 二次特征比较 → 验证与结果收束
```

独立表示事实来源不依赖方法自己的预测或成功声明；不强制另一个设备、线程或进程。读取内部治理对象或仓库时，也必须经其正式事实owner重新读回，不能把执行函数的局部返回对象当独立效果。

任务分别判断：预测是否相符、目标是否达成、禁止结果/副作用是否可接受，以及必要归因是否成立。这些结论不能合成一个由方法自报的成功值。无预测只表示不能评价预测符合度，不妨碍在独立目标合同和足够事实下判断目标；无观察不能判定预测成功，也不能自动作为正常效果失败反例。

增大/减小用明确前后来源，特定数值/轮廓用实际与目标来源，均按4151/4180及相应RC计算。目标/预测只作比较参照，不成为已发生状态。任务实际结果和验证结论由task owner收束，需求满足和方法更新仍由各自owner处理。

## 7. 反馈完善

任务反馈应关联同一次执行的完整条件、实参、所用方法/配对、原预测、实际动作、实际观察和验证，供5350分析方向分支与精度细分。方法函数不直接累计“成功次数”并把它发布为可靠性。

学习可以复用普通任务反馈，专门练习任务可以按既有授权有目的地取样；本规范不赋予学习器自动生成任务、试探未知动作或绕过安全的权力。学习输出只供方法评审/更新，不改原任务结论，也不阻塞原轮次结算。

## 8. 失败、重入与恢复

| 失败阶段 | 必须保持的边界 |
| --- | --- |
| 注册/登记未完成 | 不进入动作，不冒充缺方法或已完整；发布未知按原登记请求读回。 |
| 参数或执行前检查失败 | 不执行动作，保留明确失败来源，不补默认参数。 |
| 动作中失败/取消/未知 | 保存已知执行情况及运行身份，不把未知包装为未执行。 |
| 动作后记录/动态关联失败 | 报告已发生动作和记录缺口，不为补记录自动重做动作。 |
| 观察或比较未完成 | 任务按相应分支处理，不回填实际值，不把缺值当零差异。 |
| 学习失败 | 原任务事实保留，不回滚现实动作、不改原预测或重复任务。 |

登记、第二部分和第四部分的技术重入不能重新触发第三部分。即使同一函数提供四阶段，阶段进入权、运行关联和动作重试授权必须显式区分；普通幂等键不证明现实动作可安全重复。

## 9. 实施前物理合同与验证

本规范固定职责及逻辑输入/输出；实现前仍需冻结：

1. 预注册声明身份、登记模式、调用入口和函数解析合同。
2. 方法头/绑定/Vm规格及配对的完整发布、同义查重、当前/历史读取。
3. 任务实例参数和运行关联的精确DTO、结构化状态、成功谓词及异步完成路径。
4. 预测来源、动作记录、动态来源关联、任务独立读回的实际提供者及失败恢复。
5. 旧函数、消费者、持久布局和工程接线的同次迁移/物理删除清单。

不得将上述未冻结物理项说成现成能力。最低验证覆盖：首次登记去循环、重复登记不覆盖练习知识、无配对显式不完整、零参数和多参数、角色/类型失配、前置失败零动作、动作后记录失败不重做、无观察不补动态、无预测、预测不可事后改写、数值与轮廓二次判定、任务验证与学习不越权、历史实例隔离及重启恢复。

本规范不直接修改代码、初始化顺序、公开ABI或测试入口；规范发布不证明函数、任务或学习闭环已经实现。
