## 1. 定位

本文件是 `规范/` 中逻辑规范与施工规范的唯一正式索引。只有本目录登记且状态为“现行”的文件取得对应类别的正式规范身份；待迁材料、说明、记录、实现材料和显示材料即使从本目录提供定位链接，也不得反向覆盖正式规范。

`D:\鱼巢\规范`、`D:\海鱼\规范\逻辑规范`、`D:\新海中鱼巣\规范` 及其它外部规则集合只作为本项目规范编制、边界比较和差距识别的来源材料；其中条款必须先经过海中鱼巣的结构映射、冲突裁决、分类和本目录登记，才能取得本项目正式规范身份。不得直接用外部规则集合授权本项目代码。

分类规则固定为：

- 逻辑规范回答“什么事实成立、必须满足什么边界、返回什么结果、如何解释证据”，可以定义机器逻辑和代码语义。
- 施工规范回答“规范、代码或证据放在哪里、按什么依赖组织、使用什么形式和检查步骤”，只约束工程方法，不产生机器事实。
- 同一文件不得同时冻结业务机器逻辑和具体施工方法；发现实质混合时必须拆分后再登记。
- 施工规范按实际工作职责读取，不按智能体名称读取；一项工作涉及多种职责时取相关施工规范并集。
- 分类以本目录登记为准。当前为保持既有稳定路径暂不物理搬迁文件；路径是否位于子目录不改变类别、状态或权威。

## 2. 权力和层级

```text
用户当前明确裁决
├─ 代理协作、角色和执行边界 -> AGENTS.md
└─ 规范目录
   ├─ 机器逻辑和代码语义 -> 逻辑规范 -> 0050 项目通用机器逻辑上级规范 -> 1xxx—3xxx 对象根规范 -> 4xxx—8xxx 主题子规范
   └─ 工程组织和实施方法 -> 施工规范
```

1. `AGENTS.md` 负责代理协作、角色权限、角色自主接管、停止条件和执行边界；本目录及其登记规范不反向定义代理权限。
2. 在逻辑规范内部，上级规范优先于下级规范。施工规范不得覆盖逻辑规范；逻辑规范也不得授予智能体权限或 Git 权限。
3. 根规范规定对象身份、事实来源、写入权、生命周期、相邻边界和原则性禁止事项。
4. 子规范展开特征类型、值域、状态组合、流程顺序、合法分支、错误分类和验证合同，不得改变根规范原则。
5. 0300 只登记当前未决机器逻辑冲突及其冻结范围；已经裁决的规则由目标根规范或子规范唯一承载。
6. 实现现状、人读输出和历史材料不得反向改写规范。
7. 已退出的过程规则、过期设计、过期计划、阶段记录和既有程序行为只作证据，不得替代本目录中的现行正式规范。
8. 代码语义必须回指本目录登记的现行正式规范；实际实施还必须具备有效设计材料、已登记现行计划与任务队列以及执行前实际接口复核。
9. 正式规范单独存在不构成代码修改授权；规范缺失、同级冲突、设计失效、计划不一致或接口漂移时必须停止实施并退回设计治理。
10. 正式规范体系完整只证明定义层成立，不证明代码已经实现、生产链已经接通或目标能力已经通过验收。
