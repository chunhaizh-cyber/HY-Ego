## 1. 定位

本规范按当前项目最新裁决，冻结 `L2需求结构服务` 作为 ARCH-L4 结构记录面兼容实现对以下正式结构的唯一所有权、结构不变量、事务边界和公开接口：

```text
需求节点
需求父子树
需求列表项
需求列表成员关系
```

当前项目对需求的核心定义固定为：

> **需求是某一个存在希望某一个确定目标状态成为事实的长期目标契约。只有存在才有需求；自我首先也是一个存在。**

需求本身就是目标，不是任务、方法、执行过程、状态枚举、日志或显示摘要。

形式化表达：

```text
需求 D
├── 所属存在 E_owner
│     └── 回答“这是谁的需求”
│
└── 唯一目标 G
      ├── 目标宿主 E_target
      ├── 目标特征 F
      └── 目标状态合同 S_goal
```

需求树是：

> **目标分解的唯一权威树。**

需求列表是：

> **按“所属存在 + 目标宿主 + 目标特征 + 目标状态合同”精确聚合当前需求成员的正式组织结构。**

需求树和需求列表是同一需求体系的两种正式组织状态：

```text
需求树
    管目标分解位置、父子结构和顺序

需求列表
    管相同精确目标的成员聚合、权重查询入口和任务查询键
```

二者必须同时成立，不得互相替代。

任务为了达成父需求目标，必须先正式选择一条当前有效的实现路径；只有该路径所必需、并能由自身目标状态合同独立验证的子目标，才能发布绑定父需求、任务、筹办轮次和子目标的正式任务子目标承接记录。需求领域只消费该记录建立或复用挂在父需求下的子需求。子需求随后可以独立形成自己的任务。执行中发现的材料必须回到父任务后继筹办，不得直接建需。

同一个任务存在多条可达方法路径时，**不因此生成多个需求**。替代方法属于任务 / 方法体系，独立子目标才属于需求树。

本规范固定：

```text
需求
    管“要什么”

任务
    管“为了目标组织一次活动”

方法
    管“怎样达成目标”

需求树
    管“一个目标需要分解成哪些独立子目标”

需求列表
    管“哪些当前需求共享同一个精确目标聚合键”

任务方法路径
    管“同一个目标有哪些可达手段”
```

## 2. 强类型身份与需求核心本体

### 2.1 强类型身份

除现有：

```text
L2需求身份
```

外，新增：

```text
L2需求列表项身份
```

需求列表项不是需求节点，不得冒充 `L2需求身份`。

需求列表项和需求节点使用同一需求结构 owner，但必须使用：

```text
不同结构子族证明
不同关系类型
不同公开读取入口
```

任何调用方不得使用名称、文本、本地键、节点地址或缓存推断二者身份。

### 2.2 `L2需求事实`

`L2需求事实` 固定包含：

```text
L2需求身份 身份
L2存在身份 所属存在
L2存在身份 目标宿主存在
L2特征定义身份 目标特征定义
L2目标状态合同身份 目标状态合同
L2生命周期 生命周期
```

这五类业务字段构成需求核心事实。

其中：

```text
所属存在
目标宿主存在
目标特征定义
目标状态合同
```

创建后均不可原地替换。

### 2.3 所属存在

每个当前需求必须恰好属于一个当前有效 `L2存在身份`。

`所属存在`回答：

```text
这是谁的需求？
```

规则：

1. 创建时必须明确；
2. 不允许为空；
3. 不允许由当前线程、名称、自我缓存、任务身份或父需求反推；
4. 创建后不可替换；
5. 若另一个存在拥有相同目标，应形成另一个需求身份；
6. `自我需求`不是第二结构类型；
7. 当 ARCH-L4 业务应用面确认某个存在为当前自我时，该存在拥有的需求可以被解释为自我需求；
8. `L2需求结构服务`不判断哪个存在是自我。

上述字段是 ARCH-L4 的通用需求结构合同，按 `所属存在` 参数化，但不因此授权任意调用者替某个存在创建需求。当前自我内部治理消费者只允许锁定的唯一自我：冷启动安全根与服务根的所属存在显式写为唯一自我，运行期子需求由第 14 节消费者从父需求取得并显式写回同一个所属存在。其它存在的需求必须由该存在的具名治理 owner 和正式根语义授权，不得借用当前自我消费者；现有 C++ `L2需求*` 名称只作兼容实现名。

### 2.4 唯一目标

一个需求只能有一个权威目标：

```text
目标宿主存在
+ 目标特征定义
+ 目标状态合同
```

不得形成：

```text
多目标需求包
```

复合目标必须拆成多个独立子需求。

### 2.5 目标宿主

目标宿主使用：

```text
L2存在身份
```

它回答：

```text
希望哪个存在发生变化？
```

`所属存在`和`目标宿主存在`是两个独立角色。

允许：

```text
所属存在 == 目标宿主
```

也允许：

```text
所属存在 != 目标宿主
```

### 2.6 目标特征

目标特征使用：

```text
L2特征定义身份
```

它回答：

```text
希望目标宿主的哪一方面发生变化？
```

需求结构服务只验证特征定义身份合法，不判断该目标是否合理。

### 2.7 目标状态合同

目标状态必须使用：

```text
L2目标状态合同身份
```

不得由：

```text
裸 I64
实例状态身份
显示文本
缓存值
布尔值
```

替代。

目标状态合同负责表达：

```text
目标值 / 目标集合 / 方向 / 区间
比较关系
规则版本
```

需求结构服务不直接比较原始值。

### 2.8 目标不可变原则

需求身份一旦建立：

```text
所属存在
目标宿主
目标特征
目标状态合同
```

均不得原地替换。

如果目标语义发生变化：

```text
建立新需求
保留旧需求历史
```

原因是：

> **需求本身就是目标。目标改变，本质上已经是另一个需求。**

## 3. 当前状态与满足不进入核心需求字段

需求不保存永久：

```text
当前状态
当前满足
是否已完成
满足比例
已结算
```

需求当前是否满足必须实时执行：

```text
读取需求目标
+
读取目标宿主当前事实
+
正式比较
=
当前满足裁决
```

因此：

```text
历史上满足
≠
现在满足
```

任务轮次结算完成也不自动等于需求永久满足。

需求结构只保存目标契约，不复制当前世界事实。

同一需求列表项中的成员目标完全相同，因此一次世界事实比较结果可以被多个成员消费；但每个成员的来源、路径、当前业务有效性、活动资格、权重和正式结算身份仍然独立，不得把列表项满足结果写成成员永久状态。

## 4. 需求树

### 4.1 唯一目标分解树

需求树固定为：

```text
目标分解的唯一权威树
```

例如：

```text
D0：完成目标 G0
├── D1：先满足独立子目标 G1
├── D2：先满足独立子目标 G2
└── D3：先满足独立子目标 G3
```

任务不得再建立一套平行任务父子树作为第二权威目标分解结构。

### 4.2 子需求生成条件

只有同时满足以下条件的目标，父任务才可发布正式子目标承接记录，并由需求领域据此形成或复用子需求：

```text
父任务已经正式选择一条当前有效的父目标实现路径
+
该目标是这条路径所必需
+
目标具有自身目标状态合同和可终止的权威验证方式
```

需要独立方法、筹办、状态或材料只可辅助证明，任一项单独成立都不取得子需求准入资格。

普通方法步骤不形成需求。

例如：

```text
抬手
移动机械臂
闭合夹爪
```

如果只是一个实例方法内部的固定步骤，则留在实例方法内部。

若某一步变成：

```text
必须先取得工具 X
且需要独立寻找方法、执行和验证
```

才形成：

```text
子需求：取得工具 X
```

### 4.3 替代方法路径不是需求分支

同一目标：

```text
G
```

若存在：

```text
方法路径 P1
方法路径 P2
方法路径 P3
```

则：

```text
需求树不变化
```

这些属于任务方法路径体系。

禁止建立：

```text
D
├── “使用 P1”需求
├── “使用 P2”需求
└── “使用 P3”需求
```

方法不是目标。

### 4.4 `L2需求父子关系事实`

固定包含：

```text
稳定编码 关系身份
L2需求身份 父需求
L2需求身份 子需求
std::uint64_t 顺序
L2生命周期 生命周期
```

结构规则：

1. 父需求 != 子需求；
2. 顺序 != 0；
3. 一个当前子需求至多一个当前直接父需求；
4. 同一父需求的当前直接子需求顺序不得重复；
5. 父子关系不得形成结构环；
6. 父需求和子需求必须属于同一个 `所属存在`；
7. 根需求没有当前父关系；
8. 没有父关系只证明结构根，不证明主需求、最高优先级或当前活动资格；
9. 父子关系与需求列表成员关系完全分账；
10. 改变父子位置不得改变需求列表归属。

### 4.5 父子关系允许换代

需求的目标本身不可变，但其目标分解位置允许按正式业务治理调整。

允许：

```text
根 -> 子需求
子需求 -> 根
子需求 -> 另一父需求
```

但必须：

```text
旧父关系退出
新父关系建立
同代原子发布
历史保留
```

不得原地覆盖旧关系。

## 5. 需求列表

### 5.1 定位

需求列表不是缓存，不是需求树副本，也不是第二套目标分解结构。

它是与需求树并存的正式组织结构，用于按精确目标聚合当前需求成员。

精确聚合键固定为：

```text
所属存在
+ 目标宿主存在
+ 目标特征定义
+ 目标状态合同
```

### 5.2 `L2需求列表项事实`

固定包含：

```text
L2需求列表项身份 身份
L2存在身份 所属存在
L2存在身份 目标宿主存在
L2特征定义身份 目标特征定义
L2目标状态合同身份 目标状态合同
L2生命周期 生命周期
```

列表项目标字段表示“聚合键”，不是第二份成员需求目标。

强不变量：

```text
每个当前成员需求的
所属存在 / 目标宿主 / 目标特征 / 目标状态合同
必须与列表项逐字段完全一致
```

列表项的：

```text
所属存在
目标宿主存在
目标特征定义
目标状态合同
```

创建后不可替换。

如果聚合键语义变化，应建立新的列表项，保留旧列表项历史。

### 5.3 `L2需求列表成员关系事实`

固定包含：

```text
稳定编码 关系身份
L2需求列表项身份 列表项
L2需求身份 需求
L2生命周期 生命周期
```

规则：

1. 一个当前需求恰有一个当前列表项成员关系；
2. 一个列表项允许 `0..N` 个当前成员；
3. 同一需求不得重复加入同一列表项；
4. 一个需求不得同时属于多个当前列表项；
5. 成员关系不改变需求树父子位置；
6. 列表项可以在当前成员归零后继续保留稳定聚合身份和历史；
7. “当前需求列表”只返回当前成员数 `> 0` 的列表项；
8. 成员需求退出时，其当前列表成员关系必须同代退出；
9. 列表项不得因单个成员退出而被隐式退役。

### 5.4 树与列表双态一体不变量

任何当前正式需求必须同时满足：

```text
需求节点当前有效
+
需求核心关系当前有效
+
恰有一个当前列表成员关系
+
其列表项聚合键与需求核心目标逐字段一致
+
父关系状态合法（根为无父，子为恰有一父）
```

禁止出现：

```text
只入树未入列表
只在列表存在但需求核心缺失
同一需求属于多个列表项
列表项聚合键与成员目标不一致
```

## 6. 根需求

### 6.1 根需求定义

ARCH-L4 结构记录面可以结构化读取：

```text
当前属于该存在
且
当前没有父需求关系
```

的需求并把它投影为当前无父需求结构项。

“根”只表示结构位置。

它不自动表示：

```text
当前主需求
最高权重需求
正在执行需求
安全根
服务根
```

这些业务解释位于 ARCH-L4 业务应用面。通用结构按所属存在承载父空根，但每个存在允许哪些根只能由该存在的正式根语义和具名治理 owner 决定。当前自我实例只允许唯一自我的安全根和服务根占据这一结构位置；当前自我出现第三根、角色未绑定无父需求或借用其它存在根均为内部不一致。不得由中性结构合同替其它存在猜测根类别。

### 6.2 根组读取与双根生产资格分离

`按所属存在读取当前根需求组` 保留 `0..N` 结构读取 ABI，用于冷启动前空集、双根读回、历史兼容和结构不一致诊断。`0..N` 是读取基数，不是创建许可。

当前生产业务必须满足：

```text
唯一自我
├── 安全根需求（恰一）
└── 服务根需求（恰一）
```

当前自我的两个父空 D 只能由唯一自我正式读回后的冷启动双根专用消费者建立或幂等收敛，并由 ARCH-L4 业务应用面角色绑定互证。普通运行期消费者不得调用无父写分支；当前自我第三个父空 D、当前自我消费者替其它存在写父空 D 或把子需求重挂为父空都必须拒绝或报告内部不一致。其它存在的父空根只能由其具名根治理消费者另行取得正式授权，本合同不授予也不否定其业务根类别。

根需求仍然必须属于一个当前需求列表项；“根”与“列表成员”是不同维度。

## 7. 需求来源

### 7.1 来源不是目标本体

需求来源回答：

```text
为什么产生这个需求？
```

它与：

```text
这是谁的需求？
目标是什么？
```

分账。

当前正式需求的合法直接来源只有：

```text
冷启动安全根 / 服务根专用消费者
父需求任务发布的正式任务子目标承接记录
```

自检、身体反馈、观察、外部输入、任务或方法缺口、因果反推和正式结算后的后继目标都只是父需求治理任务材料。它们不能直接成为需求来源关系，也不得另建通用来源类型、来源 registry 或请求账。

### 7.2 来源证据不进入核心 `L2需求事实`

运行期子需求来源由现有 `L2需求任务子目标来源关系事实` 承载，并必须引用正式任务子目标承接记录。冷启动双根来源由双根角色绑定和冷启动合同承载，不复用运行期子目标来源关系。

至少应能够回到：

```text
需求身份
子需求身份
任务子目标承接记录引用
同一记录稳定引用
关系生命周期与事实截止
```

同一父需求下的同目标活动子需求必须复用；多个正式任务子目标承接记录可以分别建立来源关系并指向同一个子需求。

来源关系增加不改变需求目标身份，也不改变列表项聚合键。

### 7.3 来源不能制造重复目标

是否为同一精确目标，首先由需求业务层使用：

```text
所属存在
目标宿主
目标特征
目标状态合同
```

调用 L2 精确目标列表项查询。

L2 只做逐字段精确匹配，不做语义近似。

来源记录不同不意味着建立新的列表项或子需求。同一父需求下的同一精确目标必须复用当前活动子需求；只有父需求不同，才允许在同一列表项中保留不同树位置的需求成员。

## 8. 原子入树与列表归并

### 8.1 总原则

正式需求节点不得以“只入树未入列表”的半结构存在。

当前自我需求业务层必须先区分冷启动双根与运行期子需求，再选择唯一合法写路径；其它所属存在的根写入必须由其具名根治理消费者另行授权。

固定流程：

```text
当前自我冷启动双根：唯一自我 + 固定根角色 + 固定目标合同
-> 双根专用消费者调用无父原子新增分支
-> 正式读回需求、列表成员和角色绑定

运行期子需求：正式任务子目标承接记录
-> 第 14 节消费者读回父需求和记录目标
-> 在同一父需求下查找同目标活动子需求
-> 复用子需求，或经带任务子目标来源的原子新增分支建立子需求
-> 原子形成列表成员、父关系和任务子目标来源关系
-> 绑定任务记录并正式读回
```

`新增需求并建立列表项`与`新增需求并加入既有列表项`是 ARCH-L4 结构记录面的中性记录原语。其无父请求当前只授权给冷启动双根专用消费者；其有父普通请求不构成运行期生产入口。运行期子需求必须使用 `为既有需求建立任务子目标来源`、`新增需求并加入既有列表项及任务子目标来源`或`新增需求并建立列表项及任务子目标来源`，并由第 14 节业务应用面统一编排。

### 8.2 情况 A：已有列表项

调用：

```text
新增需求并加入既有列表项
```

一笔 owner-scoped 写集原子形成：

```text
需求节点
需求族归属
需求 -> 所属存在
需求 -> 目标宿主
需求 -> 目标特征
需求 -> 目标状态合同
列表成员关系
optional 父子关系
```

结构门禁必须至少覆盖：

```text
所属存在合法
目标宿主合法
目标特征合法
目标状态合同合法
列表项身份合法且当前有效
列表项聚合键与需求四字段逐字段完全一致
父需求合法（如有）
父子同所属存在
单父
无环
同父顺序不冲突
需求不得已有当前列表成员关系
幂等合法
事实代次合法
```

### 8.3 情况 B：无列表项

调用：

```text
新增需求并建立列表项
```

一笔 owner-scoped 写集原子形成：

```text
需求列表项
列表项结构证明
列表项 -> 所属存在
列表项 -> 目标宿主
列表项 -> 目标特征
列表项 -> 目标状态合同
需求节点
需求族归属
需求 -> 所属存在
需求 -> 目标宿主
需求 -> 目标特征
需求 -> 目标状态合同
列表成员关系
optional 父子关系
```

结构门禁必须至少覆盖：

```text
所属存在合法
目标宿主合法
目标特征合法
目标状态合同合法
按精确目标不存在当前列表项
父需求合法（如有）
父子同所属存在
单父
无环
同父顺序不冲突
幂等合法
事实代次合法
```

### 8.4 禁止半结构写入

禁止：

```text
先建裸需求再补列表成员关系
先建列表成员关系再补需求核心
先建需求后异代补父关系（请求中已明确父需求时）
同一写请求跨多个事实截止拼装
```

原 v0.3 的单独 `新增需求` 写入口不再作为正式公开写接口；其合法性门禁全部由上述两个原子新增接口继承。

## 9. `L2需求结构服务`定位

`L2需求结构服务`属于 ARCH-L4 结构记录面兼容实现，不属于 DATA-L2 活跃 owner 或 frozen manifest。

它只负责：

```text
需求身份
需求列表项身份
所属存在
唯一目标
需求父子结构
需求列表结构
列表成员关系
结构生命周期
当前 / 历史读回
精确目标逐字段查询
幂等
事实代次
引用闭合
```

它不负责：

```text
需求是否合理
是否应该生成需求
是否是主需求
权重
活动资格
任务化资格
当前满足
目标比较
方法选择
任务创建
正式结算
语义近似目标去重
```

ARCH-L4 结构记录面不计算业务权重，也不拥有任务。

## 10. L2需求结构服务公开接口

所有写接口沿用统一的：

```text
L2结构请求头
L2结构幂等身份
事实代次 / 当前性合同
```

所有当前读取必须返回能够证明同截止读取的：

```text
共同事实截止
```

历史读取必须显式给出历史截止。

### 10.1 `读取需求身份来源`

请求：

```text
L2结构请求头
L2读取类别
L2需求身份
历史截止事实代次
```

返回：

```text
L2结构结果头
optional<L2节点族身份来源事实>
```

职责只证明：

```text
该身份是不是正式需求身份
```

### 10.2 `读取需求列表项身份来源`

请求与 `读取需求身份来源` 同构，但身份参数为：

```text
L2需求列表项身份
```

返回需求列表项结构子族的正式身份来源证明。

不得把需求节点族证明复用于列表项。

### 10.3 `读取需求`

返回完整核心结构：

```text
L2需求事实
身份来源
当前 / 截止父关系 optional
当前 / 截止列表成员关系
共同事实截止
```

其中 `L2需求事实` 已包含：

```text
所属存在
目标宿主
目标特征
目标状态合同
生命周期
```

当前读取若发现：

```text
需求当前有效
但没有当前列表成员关系
或存在多个当前列表成员关系
```

必须返回：

```text
内部不一致
```

不得静默修复。

### 10.4 `读取需求列表项`

返回：

```text
L2需求列表项事实
身份来源
当前成员数量
共同事实截止
```

`当前成员数量 = 0` 是合法状态，不代表列表项已经退役。

### 10.5 `读取需求目标`

这是面向任务、验证和显示层的窄读取接口。

返回：

```text
需求身份
所属存在
目标宿主
目标特征
目标状态合同
共同事实截止
```

不得返回：

```text
当前满足
完成状态
当前任务
当前方法
```

### 10.6 `按精确目标读取需求列表项`

输入：

```text
L2结构请求头
L2存在身份 所属存在
L2存在身份 目标宿主存在
L2特征定义身份 目标特征定义
L2目标状态合同身份 目标状态合同
历史截止事实代次（按读取类别）
```

DATA 只做四字段逐字段精确匹配，不做语义近似。

结果：

```text
0 项 -> 已读取 + 空
1 项 -> 已读取 + 列表项
>1 项 -> 内部不一致
```

### 10.7 `新增需求并建立列表项`

适用条件：

```text
按精确目标读取需求列表项 == 0 项
```

请求至少包含：

```text
L2结构请求头
L2结构幂等身份

L2存在身份 所属存在
L2存在身份 目标宿主存在
L2特征定义身份 目标特征定义
L2目标状态合同身份 目标状态合同

optional<L2需求身份> 父需求
父子顺序（有父时非零）
```

成功必须同代原子形成第 8.3 节规定的完整写集。

DATA 不判断该需求是否应该建立，只做结构门禁。

当前业务生产边界：无父请求只允许冷启动双根专用消费者；有父请求不得由普通业务直接调用，运行期子需求必须改用带任务子目标来源的原子入口并由第 14 节消费者编排。

### 10.8 `新增需求并加入既有列表项`

适用条件：

```text
按精确目标读取需求列表项 == 1 项
```

请求至少包含：

```text
L2结构请求头
L2结构幂等身份
L2需求列表项身份 列表项

L2存在身份 所属存在
L2存在身份 目标宿主存在
L2特征定义身份 目标特征定义
L2目标状态合同身份 目标状态合同

optional<L2需求身份> 父需求
父子顺序（有父时非零）
```

列表项四字段必须与请求目标四字段逐字段完全一致，否则拒绝。

成功必须同代原子形成第 8.2 节规定的完整写集。

当前业务生产边界：普通有父请求不取得直接调用资格；运行期子需求必须使用带任务子目标来源的原子入口并由第 14 节消费者编排。该普通入口只保留结构兼容，不得成为第二需求生产通道。

### 10.9 `按所属存在读取当前根需求组`

请求：

```text
L2结构请求头
L2存在身份 所属存在
数量预算
```

返回：

```text
0..N 个当前根需求
稳定排序
共同事实截止
```

排序按需求稳定编码升序，只用于确定性，不代表业务优先级。

合法空：

```text
已读取 + 空组
```

预算超限：

```text
数量预算不足 + 空载荷
```

### 10.10 `按所属存在读取当前需求组`

保留 v0.3 的结构辅助读取合同，用于完整需求节点扫描、审计和结构核验。

请求：

```text
L2结构请求头
L2存在身份 所属存在
数量预算
```

返回该存在全部当前需求的有界稳定组和共同事实截止。

该接口只做结构过滤，不判断：

```text
活动需求
主需求
可任务化需求
优先需求
```

业务层不得用它替代 `按所属存在读取当前需求列表` 的聚合语义。

### 10.11 `按父需求读取当前直接子需求组`

返回：

```text
0..N 条 L2需求父子关系事实
以及对应子需求核心事实
共同事实截止
```

稳定排序优先按：

```text
父子顺序
```

顺序相同属于结构不一致。

### 10.12 `按子需求读取当前父需求`

返回：

```text
optional<L2需求父子关系事实>
optional<L2需求事实> 父需求
共同事实截止
```

一个当前子需求出现多个父需求时：

```text
内部不一致
```

### 10.13 `按所属存在读取当前需求列表`

请求至少包含：

```text
L2结构请求头
L2存在身份 所属存在
数量预算
```

返回：

```text
当前成员数量 > 0 的 L2需求列表项事实组
稳定排序
共同事实截止
```

不得返回当前成员数为 0 的列表项。

排序只用于确定性，不表示权重或优先级。

### 10.14 `读取需求列表项当前成员组`

输入：

```text
L2需求列表项身份
数量预算
```

返回：

```text
0..N 条当前 L2需求列表成员关系事实
对应 L2需求事实
共同事实截止
```

所有返回成员必须与列表项聚合键逐字段一致；发现不一致必须返回内部不一致。

### 10.15 `按需求读取所属列表项`

输入：

```text
L2需求身份
```

返回：

```text
当前 L2需求列表成员关系事实
L2需求列表项事实
共同事实截止
```

当前需求：

```text
0 个当前成员关系 -> 内部不一致
1 个当前成员关系 -> 正常返回
>1 个当前成员关系 -> 内部不一致
```

### 10.16 `替换父需求`

请求必须包含：

```text
L2结构请求头
L2结构幂等身份
L2需求身份 子需求

optional<旧父关系稳定编码>
optional<L2需求身份> 旧父需求

optional<L2需求身份> 新父需求
新顺序
```

ARCH-L4 结构记录面原语能够表达：

```text
根 -> 子
子 -> 根
子 -> 另一父
```

但现行双根治理没有该原语的普通生产消费者：安全根与服务根必须永久保持父空，运行期子需求必须始终有父且能够回溯到双根之一，禁止 `根 -> 子`、`子 -> 根` 或跨树重挂。后继若因已证明的数据修复需要重挂，必须另有正式业务合同、具名计划和全链验证；本接口存在不构成授权。

结构门禁：

```text
同所属存在
单父
无环
顺序合法
当前关系精确匹配
幂等
事实代次
```

父关系换代只改变树位置，不改变列表归属。

业务层必须先判断是否应该重挂。

### 10.17 `退出需求`

需求退出表示：

```text
该需求被永久退役
```

不表示：

```text
当前满足
暂时失活
等待
任务轮次结算完成
```

退出前结构门禁：

```text
没有当前直接子需求
没有未闭合的本结构关系
后继强引用已按其合同闭合
```

成功必须同代退出：

```text
需求节点
需求族归属
所属存在关系
目标宿主关系
目标特征关系
目标状态合同关系
当前父关系（如有）
当前列表成员关系
```

列表项本身不因单个成员退出而退出。

历史仍可读取。

### 10.18 `退役需求列表项`

列表项退役不是普通需求退出的附带动作。

只有独立管理合同已经证明：

```text
当前成员 = 0
无当前任务引用
无恢复 / 历史 / 审计需要
```

时才允许退役列表项。

退役必须退出列表项节点及其当前结构关系；历史仍可读取。

不得因为“当前成员 = 0”单独推导必须退役。

## 11. 权重查询接口边界

L2需求结构服务不计算业务权重。

L2只提供：

```text
列表项 -> 当前成员需求完整组
```

需求业务层提供：

```text
读取需求列表项当前权重视图
```

业务接口必须读取每个成员的：

```text
路径
当前性
权重
活动资格
预算
```

返回：

```text
成员明细
+ 聚合投影
+ 规则版本
+ 共同事实截止
```

聚合值不得丢失成员来源。

禁止把多个成员的权重聚合成不可审计的单值后丢失成员明细。

---

## 12. 任务查询接口边界

L2需求结构服务不拥有任务。

需求列表项只可作为同精确目标任务的查询 / 防重锚点，不是自我现实执行授权、任务目标身份或来源需求集合。

任务结构服务提供：

```text
按同类任务查询锚点读取当前任务
```

需求业务可以组合形成：

```text
读取同类任务查询锚点当前任务视图
```

每次任务承接仍必须携带一个具体需求身份。该具体需求必须是需求树中的合法需求节点，任务以它引用的目标展开活动；业务层先验证该需求当前属于对应列表项，再用列表项查找 0..1 个候选当前任务。无候选时根据该具体需求建立任务，有候选时只有在机械验证目标和任务语义相同后才能复用并新增任务—需求正式关联。

需求与任务之间仍固定：

```text
每个任务对应一个需求体系中的目标承接
任务不得修改需求目标
```

列表项成员不得因进入同一列表项而自动成为任务来源。只有收到具体成员的承接输入才建立任务—需求正式关联。

## 13. ARCH-L4 需求业务应用面

需求业务服务负责：

```text
接收并独立读回正式任务子目标承接记录
复核父需求、任务来源、筹办轮次和子目标完整性
精确目标列表项查询
按父需求内精确目标复用或建立子需求
原子建立列表成员、父子关系和任务子目标来源关系
把子需求反向绑定到原任务子目标承接记录
需求当前满足裁决
活动 / 活动资格 / 权重治理
任务化
永久退役
列表项业务视图组合
```

它只能经 L2公开结构服务写入，不得直达 L1。

需求业务层可以做目标语义判断，但 L2 结构层只做精确字段合同。

---

## 14. 需求业务服务对外接口

至少固定：

```text
承接任务子目标记录
读取当前需求目标
读取存在当前需求列表
读取需求列表项当前权重视图
读取列表项当前任务视图
裁决需求当前满足
永久退役需求
```

### 14.1 `承接任务子目标记录`

该入口只消费任务 owner 已发布并能够独立读回的正式任务子目标承接记录，不接收外部请求、观察、自检、因果、条件、方法缺口或其它普通候选。请求至少包含：

```text
同一非零事实截止请求头
任务子目标承接记录身份
父子顺序
需求发布幂等身份
任务绑定幂等身份
```

记录自身必须提供并互证：

```text
父需求
来源任务及任务虚拟存在
筹办轮次
来源方法、条件和共同事实截止
目标宿主
目标特征
目标状态合同
```

子需求所属存在只能从父需求继承，不能由请求来源、目标宿主或调用者另行提供。任务子目标承接记录不是需求；只有本入口完成需求侧发布和双向读回后，结果中的子需求才是正式需求事实。

### 14.2 固定承接流程

固定流程：

```text
读取正式任务子目标承接记录及既有需求来源关系
-> 读取父需求、父需求所属列表项和共同事实截止
-> 在同一父需求下按目标宿主、目标特征、目标状态合同与满足关系查找活动子需求
-> 已有同目标子需求：复用子需求并建立本记录来源关系
-> 无同目标子需求但列表项唯一：加入既有列表项并建立父子关系与来源关系
-> 无同目标子需求且无列表项：建立列表项、子需求、成员关系、父子关系与来源关系
-> 绑定原任务子目标承接记录到子需求
-> 独立读回子需求、父需求、列表项、成员关系、父关系、来源关系和任务记录
```

任何分支都必须使用既有原子入口一次形成需求侧完整关系；不得先建立裸需求再补列表、父子或来源关系。精确重复必须读回与首次成功相同的完整事实；同一记录已经出现单边绑定、多个来源、目标冲突、父子顺序冲突或幂等冲突时拒绝，不得猜测修补。

### 14.3 结构化结果与部分失败

输出保持具名结果语义，至少区分：

```text
已承接
精确重复
入口拒绝
许可拒绝
记录不可承接
父域冲突
目标冲突
父子顺序冲突
需求已发布待任务绑定
事实代次漂移
幂等冲突
引用冲突
资源失败
内部不一致
```

需求侧事实已经原子发布、但任务记录绑定因事实代次漂移或资源失败暂未完成时，只返回 `需求已发布待任务绑定` 和值式重试请求；重试只能继续原绑定，不得重新建立需求或形成补账体系。

### 14.4 `读取当前需求目标`

业务入口在 L2 `读取需求目标` 之上组合必要当前性与活动资格材料。

输出：

```text
需求目标
目标版本
当前业务有效性
```

目标本身仍以 L2核心结构为权威。

### 14.5 `读取存在当前需求列表`

输入：

```text
L2存在身份
```

以 L2 `按所属存在读取当前需求列表` 为结构底座，可组合：

```text
列表项核心事实
当前成员数量 / 成员明细
当前权重视图
同类任务查询锚点当前任务视图
当前业务有效性
```

这是业务视图，不是第二事实仓。

### 14.6 `读取需求列表项当前权重视图`

必须按第 11 节读取成员级材料并返回：

```text
成员明细
聚合投影
规则版本
共同事实截止
```

不得以列表项本体字段替代成员权重事实。

### 14.7 `读取同类任务查询锚点当前任务视图`

组合：

```text
L2需求列表项
当前成员需求组
任务结构服务按同类任务查询锚点读取当前任务
共同事实截止 / 对应任务当前性材料
```

该视图只帮助查找和防重；不得从它推断任务已经承接列表全部成员。

### 14.8 `裁决需求当前满足`

固定流程：

```text
读取需求目标
读取目标宿主当前特征 / 状态
调用正式比较 / 判断收束
```

输出只能是具名裁决，例如：

```text
已满足
未满足
不可比较
证据不足
当前性失效
内部不一致
```

“已满足”是当前裁决，不写回需求节点永久 bool。

同一列表项成员目标相同，因此一次世界事实比较结果可以被多个成员消费；但每个成员的业务有效性、路径和正式结算仍独立。

### 14.9 `读取存在当前需求视图`

保留 v0.3 业务视图能力。

输入：

```text
L2存在身份
```

输出可组合：

```text
当前根需求
当前需求列表
当前活动需求
当前满足裁决
当前任务化状态
当前活动资格 / 权重
```

这是业务视图，不是第二事实仓。

### 14.10 `永久退役需求`

只有业务层确认：

```text
该目标契约不再需要保留为当前需求
```

时才可以请求 L2 `退出需求`。

当前满足不能自动触发永久退役。

需求退出后，若对应列表项当前成员归零，也不得自动退役列表项；是否退役由独立列表项管理合同裁决。

## 15. 任务与需求接口边界

任务与需求之间固定为：

```text
需求
    -> 提供唯一目标

需求列表项
    -> 提供相同精确目标任务的查询 / 防重锚点

任务
    -> 承接需求体系中的目标活动
```

任务业务读取：

```text
需求身份
需求目标
需求当前性
需求所属列表项
同类任务查询锚点当前任务视图
```

但任务不得修改需求目标。

任务证明某个目标是已正式选择且当前有效的父目标实现路径所必需、且可由自身目标状态合同独立验证的子目标时：

```text
发布正式任务子目标承接记录
```

而不是：

```text
直接建立子需求
直接写父子关系
直接写列表成员关系
```

任务轮次结算完成后：

```text
不能直接写需求已满足
```

必须重新调用需求当前满足裁决。

同一列表项中多个需求成员不得因为各自存在而直接推导多个重复任务；也不得自动吞并为任务来源。任务业务每次接收具体需求，基于列表项查询锚点查找候选任务并机械复核，随后由任务结构 owner 建立该具体需求的正式关联。

---

## 16. 方法与需求接口边界

方法不直接拥有需求。

方法路径回答：

```text
怎样达成任务对应需求目标？
```

同一个需求目标可以通过：

```text
P1
P2
P3
```

多条方法路径达成。

这些路径：

```text
不进入需求树
不形成需求列表项
不形成需求列表成员
```

方法执行发现前置材料时必须回到父需求任务的后继筹办；只有父任务证明该目标为已正式选择且当前有效的父目标实现路径所必需、并能由自身目标状态合同独立验证并发布正式任务子目标承接记录后，需求业务才可建立或复用子需求。

普通方法步骤不得制造需求。

## 17. 事务、幂等、事实代次与当前性

以下规则为代码生成硬合同：

1. 冷启动双根新增必须由双根专用消费者使用无父原子新增分支；运行期子需求必须由第 14 节消费者使用带任务子目标来源的三个原子入口，均不得使用裸需求新增或普通有父原语旁路；
2. 新增写集必须把需求节点、族归属、所属存在、三项目标引用、列表成员关系和可选父关系同代原子发布；
3. 新建列表项路径还必须把列表项节点、列表项结构证明及四字段聚合键关系同代原子发布；
4. 所属存在与三项目标引用创建后不可替换；
5. 列表项四字段聚合键创建后不可替换；
6. 父关系结构支持换代且旧关系保留历史，但现行双根治理禁止普通生产重挂；
7. 一个当前子需求至多一个父需求；
8. 同一需求树父子必须同所属存在；
9. 一个当前需求必须恰有一个当前列表成员关系；
10. 一个当前需求不得属于多个列表项；
11. 当前成员需求的四字段必须与所属列表项逐字段一致；
12. 当前读取必须同截止，不得跨代拼装目标、父关系或列表成员关系；
13. 历史读取必须显式使用历史截止；
14. 同幂等身份 + 同完整请求返回 `精确重复`；
15. 同幂等身份 + 不同请求返回 `幂等冲突`；
16. `事实代次漂移`必须零变化；
17. 发布未知只能以原幂等身份和原完整请求收敛；
18. ARCH-L4 结构记录面不得用空值、默认值或当前缓存补齐坏目标；
19. 精确目标查询只能逐字段匹配，不得做语义近似；
20. 精确目标查询出现多个当前列表项必须返回内部不一致，不得自动择一；
21. 退出需求必须同代退出当前列表成员关系；
22. 单个需求退出不得隐式退出列表项；
23. 列表项退役必须由独立管理合同证明成员、任务引用、恢复 / 历史 / 审计条件已闭合。

## 18. 禁止事项

禁止：

- 没有所属存在的需求；
- 把自我建立为第二种需求 owner；
- 一个需求包含多个目标；
- 修改既有需求的所属存在；
- 原地修改既有需求目标；
- 原地修改列表项聚合键；
- 在需求节点保存永久“已满足”布尔值；
- 在需求节点保存当前世界状态副本；
- 用任务轮次结算完成代替需求满足；
- 用方法成功代替需求满足；
- 把替代方法路径制造成子需求；
- 把普通方法步骤制造成子需求；
- 独立子目标不进入需求树；
- 任务直接写需求树；
- 任务直接写需求列表成员关系；
- L2需求结构服务自行做目标语义去重；
- L2需求结构服务判断主需求、权重、活动资格、任务化或满足；
- 建立需求树之外的第二套目标分解树；
- 用名称、文本、缓存、本地键或日志证明需求身份；
- 需求节点存在但没有当前列表成员关系；
- 一个需求进入多个列表项；
- 同一需求重复加入同一列表项；
- 列表项目标与成员目标不一致；
- 列表删除 / 覆盖树节点；
- 把需求列表当普通缓存；
- 把列表项当需求节点；
- 把权重聚合值写成不可审计单值并丢失成员；
- 从单个成员需求直接猜测唯一任务；
- 从单个成员需求直接创建重复任务；
- 先建裸需求再补列表成员关系；
- 以“当前成员为 0”单一条件自动退役列表项。

### 19.1 3100

```text

```

修订为更精确表述：

```text
需求属于某一个存在；
需求本身就是唯一目标契约。
```

补充：

```text
需求树是唯一目标分解树；
```

### 19.2 5100

保留单目标合同。

补充：

```text
所属存在是需求核心不可变关系；
目标宿主、目标特征、目标状态创建后不可替换；

```

### 19.3 5110

需要重新区分：

```text
目标分解路径
vs
任务方法替代路径
vs
同目标需求成员聚合
```

AND / OR 若继续存在，只能表达目标之间的逻辑组合，不得用来保存“多个可选方法”，也不得替代需求列表成员关系。

### 19.4 5120

修订：

```text
需求目标 -> 任务目标副本
```

为：

```text
任务通过其显式关联具体需求逐项读取并互证唯一权威目标；

任务查询以需求列表项作为相同精确目标的查询 / 防重锚点。
```

### 19.5 3200 / 4260

固定：

```text

父需求任务只把已正式选择且当前有效的父目标实现路径所必需、并能由自身目标状态合同独立验证的目标发布为正式任务子目标承接记录；
需求业务只消费该记录建立或复用子需求；
需求树推导目标层级；
一个任务可以有多条可达方法路径；
同一精确目标的多个需求成员通过需求列表项形成派生活动聚合，并以列表项作为任务查询 / 防重锚点；任务来源只由逐项正式关联形成。
```

## 20. 代码生成边界

本规范用于直接生成代码时，必须按以下顺序落地，不得依据名称猜测省略结构：

```text
1. 强类型身份
2. 需求事实 / 列表项事实 / 两类关系事实
3. 身份来源证明与读取
4. 精确目标列表项查询
5. 冷启动双根无父原子新增分支与运行期带任务子目标来源的三个原子入口
6. 树读取接口
7. 列表读取接口
8. 父关系换代结构原语及其当前零普通生产资格
9. 需求退出
10. 列表项退役
11. 事务 / 幂等 / 事实代次门禁
12. ARCH-L4 业务应用面组合接口
13. 权重视图与任务视图只做组合，不回写 L2 结构字段
```

生成代码时不得自行补造以下语义：

```text
主需求判定
业务权重算法
活动资格算法
任务唯一性业务规则
目标语义近似算法
满足比较算法
列表项自动退役策略
```

这些必须由对应上级 / 边界规范提供。

如果实现所需类型名、错误枚举、通用请求头字段或生命周期底层表示已由 4010、4015、4030、4190、4200、4230 等直接依赖规范定义，应引用正式定义，不得在 4250 内复制第二套类型。

## ARCH-L4 记录面与应用面边界

需求树/列表是 `ARCH-L4` 业务治理的结构记录；其字段、关系和读取仍经现有 `L2需求结构服务` 这一 ARCH-L4 结构记录面兼容实现，但服务不得解释需求真实性或目标业务结果。需求业务应用面负责为什么建立、选择、推进、结束和判定，包括需求成立、活动资格与当前满足；它只能把已裁决结果转换为记录面请求。需求目标可以引用 ARCH-L2 通用结构，列表聚合不得复制状态/动态权威；后继名称绑定由 ARCH-L5 公开服务完成。
