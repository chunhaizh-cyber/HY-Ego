# 7200 子规范 词条概念候选与上下文消歧

编号：7200
日期：20260814
状态：正式子规范

直接上级规范：2210。

直接依赖规范：1110、2200、2210、2220、7210。

相关边界规范：7140。

## 1. 定位

本规范规定从词条及其当前概念名称关系形成概念候选，并由 L5 之外业务层结合上下文完成消歧的边界。候选、排序和消歧过程不建立独立语素入口对象，也不把索引命中升级为概念事实。

## 2. 候选形成

标准候选链为：

```text
输入语言材料
-> 按 2200 规范化并召回词条
-> 在同一读取截止反查全部 2210 当前概念名称关系
-> 回读每个目标概念当前身份、本体根和名称关系
-> 名称结构服务返回未过滤的完整候选
-> L5 外业务可选调用 7210 形成任务局部的零个、一个或多个本体根 / 对象角色候选
-> 形成零个、一个或多个不可变概念候选
```

候选至少回显词条、名称关系、目标概念、本体根、可选任务局部词性路由结果、名称角色、语言和读取截止。词性路由只能在 L5 外缩小或排序完整名称候选；不得建立根、补造名称关系或把零路由解释为零概念。候选是值式计算材料，可以丢弃和重建，不取得独立稳定身份或生命周期。

## 3. 上下文消歧

候选多于一项时，业务层可以结合语言记录位置、指代、主体、时间、场景、任务、方法、相邻词和既有领域对象形成选择。数据层只提供结构材料，不判断词义正确性。

零候选表示当前没有已发布名称关系；单候选只表示当前结构唯一命中；多候选必须完整返回并确定排序。三者都不得由索引或数据层自动创建概念、实例、需求、任务、方法或其它业务对象。

消歧结果若只适用于一次语言位置，使用 1110 的指代或等价上下文引用，不得把一次语境选择永久写回词条或概念名称关系。只有名称本身经业务层正式裁决发生新增、退出或角色变化时，才修改 2210 名称关系。

## 4. 概念与实例边界

概念名称关系的目标只能是 2220 / 7140 当前独立概念。指向具体世界实例的专名、别名和一次指代不是概念名称关系：

```text
概念名称 -> 2210 概念名称关系
实例长期别名 -> 由实例对象所属领域另行定义的别名关系
一次语境指代 -> 1110 指代事实
未理解文字 -> 语言候选
```

不得用一个通用“对应信息”关系把概念、实例、特征值、状态、动态、需求、任务和方法混成同一目标集合。

## 5. 名称建立

名称建立顺序固定为：

```text
业务层取得当前概念及语言材料
-> 语言服务确保当前词条
-> 业务层裁决名称角色与适用语言
-> 名称关系服务提交概念—词条关系
-> 按概念正向和词条反向完整读回
```

名称关系服务不创建目标概念，不根据名称寻找“最像”概念，也不以当前无名称作为自动命名授权。

## 6. 非成功与内部不一致

- 词条未找到、概念未找到、已退出、候选为空、候选多项和上下文不足都是结构化正常结果或业务层待裁决结果，零结构变化。
- 索引命中后词条不存在、名称关系端点或角色矛盾、同语言多首选名称、同一当前关系重复或同截止材料混代属于内部不一致，停止依赖路径并回源审计。

## 7. 验证

验证至少覆盖零 / 单 / 多候选、一词多义、一义多名、一次指代不反写名称、概念与实例别名分流、索引清空重建和同截止完整读回。
