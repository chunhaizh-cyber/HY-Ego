## 1. 目的与核心原则

概念统一的首要目标，是建立自然语言与系统内部认知之间共享的语义表示。数据结构统一是基础；更重要的是语言表达的意义，与系统实际认识、查询和操作的信息采用同一套概念、实例及关系。

物理对象和信息对象均可被指称、限定、组合、查询和表达。理解结果本身对应正式概念、实例及关系，不先形成脱离对象含义的语言标签，再勉强转换成需求、任务、方法各自的私有意义。语言生成从同一内容及实际取得的信息出发，保持主体、目标、关系、条件、否定、时间、量词与不确定性。

统一表示的基本原则为：

> 概念定义范围，实例保存实际内容。基础概念直接定义材料范围或基础判定；结构型概念以“特征类型→范围概念”组织内容，保留数量、顺序、分支及关联约束。需求、任务和方法是具有先天共同结构的信息存在，相应类别概念在初始化阶段形成，不依赖实例归纳。语言所表达的内容与系统确认的事实分开，不因概念化理解取得承接或执行资格。

本规范统一逻辑表示，不把全部信息复制为普通世界对象，不产生第二业务账、概念仓或任意写端口。物理组织、公开接口及存量迁移须按本文边界另行设计；规范成立不代表代码完成。

## 2. 基本对象与身份区分

### 2.1 存在与信息存在

存在是可独立指认并以特征、关系描述的对象，不以物理形态或外部感官可观测为必要条件。具体需求D、任务T、方法M属于信息存在，保留其原有业务身份、内容和治理含义，不另造可独立修改的镜像存在。

信息存在不必具有位置、尺寸或颜色。纳入统一认知表示不等于纳入现实物理场景，不等于将其编码交给普通世界存在写入口，也不赋予执行资格。当前D/T/M与Vt/Vm的物理分工在专门迁移完成前保留，读取必须定位原正式承载，不维护两份同义状态。

### 2.2 特征类型、特征实例与实际值

```text
存在E
  持有特征F
    特征类型＝FT
    实际值＝基础材料或有类型的信息引用
```

FT说明哪一个方面，F说明哪个对象的该方面，实际值说明具体内容，被引用对象仍保有原身份和内部结构。稳定编码只负责定位，非零不证明合法，编码大小不表达业务意义。

### 2.3 概念、实例与符合关系

概念限定内容范围或共同结构；实例承载具体内容；符合关系表达对象是否满足定义。概念身份、实例身份和符合关系不得合并。

“定义已成立”“对象存在”“当前符合该概念”“具有操作资格”分别判断。“方法”特征类型、方法类别概念、具体M、Vm和一次执行也分别成立，名称相同不构成等价或授权。

## 3. 概念内容的统一表达

### 3.1 基础概念

基础概念直接定义材料范围或具名基础判定含义，例如整数区间、有限枚举、字符串或结构材料规则、合法对象类别的全域。定义必须说明材料类型、单位/参照及判定规则，不能只有名称。

“基础”指展开时有直接判定依据，不表示没有下位概念。数值、枚举及结构范围沿所属正式值规则表达，不借此引入浮点值、无类型业务bool或对引用编码作算术。

### 3.2 结构型概念

```text
概念C
  特征类型FT1 → 范围概念C1
  特征类型FT2 → 范围概念C2
  ……
  必要基数、顺序、互斥、分支、关联及阶段约束
```

每一项定位正式特征类型和范围定义；已有概念完整承载的范围直接引用，不复制第二定义。这里的内容项不强制等同于C++成员或底层字段，也不把锁、缓存、内部索引变成业务特征。

| 限定项 | 必须说明 |
| --- | --- |
| 特征类型 | 哪一方面的内容，使用正式身份而非显示名。 |
| 范围概念 | 允许什么内容；定义缺失不等于任意范围。 |
| 引用语义 | 基础材料、具体对象引用或概念定义引用，三者有类型地区分。 |
| 基数与组织 | 必需/可选、单项/集合/有序组、数量范围；不由容器默认推断。 |
| 关系与阶段 | 同一/不同、所属、包含、顺序、互斥、配对及各合法阶段要求。 |

结构型定义适用于物理对象和信息存在。信息存在的先天字段含义和具名关系可以进入结构定义；不能以普通观察对象的“仅特征值域共同点”规则排除这些必要结构约束。它们是存在类别内的定义形状，不因每种业务对象另建本体类别、根或owner。

### 3.3 范围与已知清单

概念范围不等于目前已知实例清单。后来建立的合法对象仍可能符合已有定义；符合判断不要求穷举全部实例，当前查不到实例也不否定概念定义成立。

## 4. 范围概念、实际值与概念引用

### 4.1 概念限定对象

任务概念中“对应需求→需求概念”限定允许引用哪类对象；具体T的对应内容为具体D，不能把需求概念本身填作D。

### 4.2 实际内容引用概念

D的目标范围可以实际引用“温度35～40℃”概念。这是范围定义，不表示水当前温度为某个概念节点。须核验目标特征类型、概念类别、单位和比较含义相容。

### 4.3 范围与基数

范围回答“有值时可以是什么”，基数及阶段约束回答“现在应有几项”。任意范围不等于可缺项，可选字段不允许任意类别。缺值、合法空集合、未知、未形成、确认不存在与读取故障分别处理。

### 4.4 合取、分支与跨项约束

同一必要分支的各项共同成立，可选分支分别组织。逐项合法不代替整体合法：目标特征为温度、目标范围却为颜色时，引用即使各自合法，需求整体仍不合法。同一目标的多条约束须作用于同一个实际对象，不能跨对象拼接。

## 5. 语义全域、分类与构成引用

### 5.1 任意合法存在

原草案“存在概念树根”所需的语义，是任意合法存在的全域，不是没有含义的组织节点。本规范以具名通用存在定义承接该语义；存在类别在四本体根布局中有恰一持久根（全局变量持有，不为根建词条），通用存在不是替代该根的隐藏总根，也不要求所有存在概念必经通用存在；其完整定义应能区分合法存在与任意底层节点。

引用全域不附加更具体类别限制，不表示空、未知或缺失定义。空字段专属概念不自动成为全域；普通类别概念零上位也不自动成为通用存在。

### 5.2 分类关系

分类表达范围包含，下位保持上位有效限制并进一步收窄。类别及所属范围按正式合同判断，不凭名称、字段数量或编码判断。存在概念保留合法多上位无环图，具体特征概念按7160保持同类型树合同，不把附件的树式简写外推成全仓单父。

### 5.3 构成引用

任务概念的采用方法内容引用方法概念，是构成限定，不是方法属于任务下位。分类、构成、实例归类、存在组成和一般引用分别表达；共享范围定义形成引用图，不增实例组织父，不复制被引用内容。

### 5.4 递归

定义可经具名内容项递归引用，但不得无限展开或因访问过同一节点就判符合。判定须依据当前对象、具体内容项和合法规则，落实到基础范围、合法身份或可判定结构。A引用B、B引用A但无基础依据，不足以证明定义完整。

一般递归方程、否定循环和不受限逻辑求解未获授权；规则不足报告未能判定，不默认成功。分类环始终拒绝，不能用内容递归为其辩护。

## 6. 需求、任务、方法的先天概念

### 6.1 先天性质

需求、任务、方法共同结构先天确定，必须在没有具体D/T/M时也能形成完整类别概念，不从样例归纳，不伪造经验。

先天固定内容含义、范围、基数及必要关系；实际主体、目标、参数、状态和方法知识由实例承载。概念初始化不表示方法已学会、任务已执行或需求已满足，不增加运行/成功/命中统计。

### 6.2 领域结构映射

下表规定概念化所需含义；精确字段及准入仍由对应领域合同唯一解释，不分配物理编码。

| 先天类别 | 内容 | 范围或关系 |
| --- | --- | --- |
| 需求 | 需求主体、目标存在 | 各为合法存在引用，角色不同，业务再限定主体及执行域。 |
| 需求 | 目标特征类型、目标形式 | 正式特征类型范围及目标形式枚举。 |
| 需求 | 值/值域及比较，或变化方向 | 依3100严格二选一，目标范围须与目标特征相容。 |
| 需求 | 权重、活动状态及来源关联 | 正式数值域、状态域及合法来源关系。 |
| 任务 | 对应需求 | 符合任务执行域要求的具体D，保留一D一T合同。 |
| 任务 | 当前状态 | 正式任务状态域，实际从任务状态宿主读取。 |
| 任务 | 采用方法 | 具体M引用及阶段基数，未采用不填假方法。 |
| 任务 | 子任务、执行及来源 | 正式组织、身份和当前有效关系，不复制方法树冒充任务。 |
| 方法 | 参数规格 | 有序的“信息类型＝范围概念”，结构定义不规定所有M参数相同。 |
| 方法 | 条件、结果 | 完整条件/结果内容及同一M内配对约束，正常与异常关系沿5350。 |
| 方法 | 操作定义/函数绑定 | 正式实现方式允许的操作范围，不是任意代码地址。 |
| 方法 | 启用状态、运行统计及可靠度 | 各正式状态域、数值域及推导规则，不用先天定义伪造统计。 |

任务尚未选方法、方法只有头而无C/R等合法阶段，由阶段约束及基数明确表达，不以预测或默认对象补齐。已登记本能的固定参数规格不因类别概念形成被学习或初始化改写。

### 6.3 挂接到存在的特征

自我的方法、需求、任务特征统一以当前完整同类别引用集合关联具体M/D/T，即使只有一个也仍是集合，零成员为空集，未知不等于空集。详细表示、成员约束及保护沿1130/7160，不再把单值或多同类型实例列为待选方案。

集合关联不改变业务身份、主体、树归属或写权；成员内容改变须重新读取，历史集合不得取并集冒充当前拥有对象。

## 7. 先天生成、专属投影与后天形成

### 7.1 初始化

```text
读取正式先天结构定义
→ 建立或取得基础范围、通用存在范围及必要特征类型
→ 按依赖准备需求、任务、方法等类别概念
→ 填入范围引用、基数、组织及关联约束
→ 核验全部定义和引用闭合
→ 经合法提供者完整发布并读回
→ 开放后续使用
```

存在互相依赖时可在提供者内部准备身份并闭合定义，不制造实例打破依赖；半定义不公开。具体是否支持成组发布须在物理合同证明，不将跨领域分阶段发布谎称为一个原子事务。

重复初始化核对并复用完整同义定义，不重建另一套同义全域/类别，不覆盖实例；同名异义显式报告。失败保留可核实的已完成阶段，重试按原材料核对，不将读取失败解释为查无后重复建点。

### 7.2 专属概念

实例专属概念描述该对象的具体特征，与先天类别分别成立。普通对象依已有实例信息形成专属投影；先天类别不替代该投影，投影也不替代类别。某任务当时完成不成为所有任务固有状态。

### 7.3 后天形成

根据真实实例或已确认知识抽取共同限制，来源、适用范围和未知须明确，不把偶然属性泛化为必然。先天定义、专属投影和多实例归纳分开；后天算法与门槛沿所属合同，不自动全图扫描或穷举组合。

## 8. 符合性与比较

### 8.1 完整判断

```text
读取对象及概念完整当前定义
→ 核对身份与内容类别
→ 核对必需项、基数、组织及合法阶段
→ 基础材料执行相应范围判断
→ 对象引用检查目标是否符合指定概念
→ 概念引用核验类别、所属范围及必要包含关系
→ 核对跨项关联、分支及递归判定规则
→ 返回有依据的判断及具体缺口
```

缺一必需限制不能判完整符合。明确符合、明确不符合、信息不足而未能判定、工程读取故障分别成立；不强定公开枚举或吞异常为false。

完整正式对象缺失其合同必需结构，按工程完整性问题处理；外部认知材料尚未补齐则保留内容缺口。两者不能都当作业务子需求。

### 8.2 事实与归类

真实观察值优先，不为符合旧描述范围截断、改写或丢掉事实。观测超旧范围时依领域规则重新判断目标身份、归类及范围。准确事实的可存储性与概念符合、合法引用及业务准入分别处理，不因实际值不受经验范围限制而放弃结构类型检查。

### 8.3 身份、内容与能力

同一节点引用只证明身份相同，不证明内容未变。任务状态、方法知识须通过领域服务读取。身份相等、定义等价、范围包含、当前符合及当前可执行分别比较；禁止对稳定编码求差或取样。

## 9. 生命周期、引用与写入职责

概念定义由概念合法唯一提供者维护；业务对象内容及状态由原领域维护；自然语言只维护材料、出现、知识、主张及解释。统一表示不另设第二概念或业务权威。

引用必须合法、可读并受所属合同保护；解除关联不自动删除目标。历史引用不冻结旧内容，不从名称、缓存或残存编码推断未保存的旧定义，不增加历史读取、事实代次或兼容接口。

先天结构不能被单实例聚合静默改义；细化和可变范围分别沿所属合同，不推导全部概念永不变或均可任意改。D/T/M信息存在化不授权合并、删除Vt/Vm，承载迁移须精确映射并保证无双重状态。

## 10. 参数与模拟生成

参数候选依据正式范围生成：基础范围用相应材料能力，结构范围按必需内容、基数及联合约束构造；不得按方法名称选择专用学习算法。

需求、任务、方法及其它对象引用不能按整数编码取样，须在模拟隔离环境建立或单向复制映射合法对象。能判符合与能生成是不同能力，仅有任意存在范围而缺构造依据时报告缺项，不任意造样例兜底。

候选联合约束不成立不调用原函数、不计方法失败。现实信息只能单向复制到模拟环境，不能反向传递写入；结果仅由方法实际写回抽取，临时对象释放后正式知识不得留悬空引用。不虚增真实统计、不预造C/R，具体三点、组合、细分、结束及发布沿5370。

## 11. 自然语言共同语义

### 11.1 对象、关系与作用域

词语关联统一概念，句法/构式确定角色、关系和作用范围。物理对象和信息存在共用“指认对象→确定特征/关系→领域读取→表达结果”的骨架，不能把全部名词归普通存在、全部动词归可执行方法。

“采用这个方法的任务”与“完成这个任务的方法”限定对象及关系方向不同；“采用M且未完成的任务”约束同一任务变量。此类限定可为临时查询，不必永久建立短语概念。

### 11.2 完整性与澄清

先天需求结构可定位主体、目标存在、目标特征及目标约束的缺项。上下文能唯一补足则复用，不能补足则定向澄清，不猜对象、温度、音量或固定增量。“调高一点”不因认识需求结构就自动获得词义和幅度；合法方向目标也不被强加数值幅度。

多句式可表达一个已消歧含义，“希望、想、需要”等依实际构式映射；语言学习可扩表达，但不合并不同请求身份。理解所得内容生成重述，确认具体内容，内容改变重新确认，不以原文回显代替理解确认。

### 11.3 内容与事实

“任务完成了”“我希望任务完成”“任务完成了吗”“如果完成就通知”“他说任务完成”共享任务和状态概念，但保留陈述、期望、提问、条件和引述的不同地位。主体、否定、时间、条件、指代、量词及来源不可丢。

“每个任务都有一个方法”不同于“有一个方法处理所有任务”。未知不等于否定，未观察不等于不存在，尚未取得结果不等于失败，未找到方法不等于永不可能。理解不等于确认事实、求助、承接或执行授权。

### 11.4 双向与往返

自然语言形成带角色、关系、范围及来源的概念化内容，查询或治理沿正式对象进行；生成使用同一内容和实际读值。生成后解析实际文字，保持对象、目标、关系、否定、时间、条件、量词及不确定性，不要求逐字相同，不为往返补造事实。

本节规定总体要求，语言专属组合、查询、澄清及验收由[7260](7260_子规范_语言与认知共享概念语义.md)展开，有限双向算法由7240、字段由7230、知识学习由7250唯一承接。内部往返不证明对方理解或内容真实。

## 12. 禁止、验收与实施边界

禁止以名称代定义、概念代实例、当前已知清单代范围、构成代分类、循环回访代符合、历史代当前集合、单项合法代整体合法；禁止伪造D/T/M、动作或经验形成先天概念；禁止通过普通特征写入口绕过业务治理。

| 场景 | 最低结果 |
| --- | --- |
| 无具体D/T/M | 三先天类别可完整定义、初始化和读回，不造实例。 |
| 重复初始化/同名异义 | 完整同义复用，异义明确拒绝，不覆盖原实例。 |
| 任意存在范围 | 接受合法对象，不接受仅有非零编码的组织锚。 |
| T对应需求误填M | 类型不相容，不因都是编码放行。 |
| 主体与目标不同 | 正确保留两个角色及其关系。 |
| 温度目标配颜色范围 | 跨项不相容，不判完整符合。 |
| T未选M/M尚无C-R | 保持合法阶段，不填假方法或预测配对。 |
| 两概念共享范围 | 引用同一正式定义，不复制可独立修改内容。 |
| 定义递归 | 不无限展开、不仅凭回访判符合。 |
| T引用不变状态改变 | 读取实际状态，不误判无变化。 |
| 只有全域缺生成依据 | 报构造缺项，不随机制造对象。 |
| 模拟对象释放 | 正式知识引用有效，无现实反写及悬空引用。 |
| 同内容不同句式/作用域 | 语义往返保持角色、量词、否定及事实地位。 |

原附件全文为来源，不是并列规范。与附件不同的适配已明确：语义全域由通用存在定义承接，四本体根布局保持且概念根为全局变量、不为根建词条，不另造隐藏总根；分类保留对象领域的树/多上位图合同；M/D/T特征一律集合而非未定；自然语言提升为首要目的。其余统一表示、先天生成、完整符合和职责边界由本文承接，不再只留下语言应用说明。
