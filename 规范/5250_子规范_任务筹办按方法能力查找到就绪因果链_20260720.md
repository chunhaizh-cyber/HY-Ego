# 5250 子规范 任务筹办按方法能力查找到就绪因果链

编号：5250
日期：20260901
版本：v0.10
状态：正式子规范

## 1. 定位

本规范定义普通可任务化原子任务如何按方法结果能力召回候选、读取就绪因果链、形成唯一当前活动方法路径并形成闭合筹办结果。

直接上级规范：3200、3300。

直接依赖规范：1190、3100、5230。

相关边界规范：4310、5240、5300。

## 2. 适用闸门

本规范只适用于目标完整、没有应先推进的活动子需求、目标特征定义允许普通任务化的原子任务。

管理、汇总、AND、OR、方法路径、因果支撑和结构治理节点即使当前没有子节点，也不得进入普通方法召回；必须先按对应展开与聚合规则处理。

## 3. 召回合同

1. 按任务读取当前 `T→D` 来源需求关系组，逐项读取当前具体需求的目标宿主、目标特征定义和目标状态合同并机械互证相同；以当前值为左、互证目标值为右，使用合同绑定的正式注册比较规则在同一事实截止判断目标是否已满足并形成未满足时的所需变化方向。空组或全部关联需求失活时不得以列表项兜底，必须显式等待、结束或重判；已满足直接返回目标已完成。
2. 只以目标特征定义执行有界方法用途粗召回。粗召回回答哪些方法声明能够影响该类型特征，不接收任务侧输入条件或限制条件，不证明适用或就绪。
3. 对粗召回项读取同截止方法投影，按目标宿主全部当前合法概念、所需变化方向和目标状态结果能力形成适用候选。零概念且判断需要对象类型时合法等待；多概念按并集保留，不猜默认、不任选、不合并。
4. 取得适用候选后才读取方法自己的条件、输入规格、限制条件和条件结果关系；任务不形成六项镜像，也不做任务六项与方法六项逐项相等。
5. 只有本轮实际采用的方法方案可以形成缺失条件草案；草案交需求统一入口，任务筹办不直接写需求树。条件回流后重新读取方法版本、来源需求关系和当前事实并重新筹办。
6. 采用方案后仍必须回读方法当前登记项、生命周期、动作入口、条件结果对、参数绑定、禁止项、验证和归因合同复判就绪性（见 §4 就绪链）。
7. 候选集可以为空、只有一条或包含多条；候选集是本轮召回和选择输入，不等于当前活动路径。多候选没有正式可比较选择证据时只稳定输出并合法等待，不为互斥候选同时提出条件。当前就绪且可直接达成目标的方法优先；稳定编码只消除输出不确定性，不表达能力优劣。
8. 方法名称、动作名称、函数名、分类标签和固定编号不得参与语义命中，只可作为可重建的非权威读取辅助索引。
9. 通用特征写入、状态创建、动态创建、任务筹办和其它底层原语不得仅因特征命中成为适用候选；仍须通过对象、方向、结果能力和方法自身结构判断。
10. `下一筹办工作包`、`目标未达成待重筹办`及其专用后继 provider 退出当前资格。目标未达成只进入任务轮次结算结论；轮次收束后由自我决定继续、结束、等待或取消。只有正式`继续`后继决议才能建立新任务轮次并重新进入本规范的普通筹办入口；不得把旧结果、旧冻结或旧授权映射为新筹办来源。

## 4. 就绪链

候选方法就绪必须同时满足：

```text
方法生命周期和内容版本当前
结果能力命中任务目标
真实动作入口当前
条件和条件结果对完整
输入与参数绑定闭合
禁止项未命中
验证和归因合同成立
方法作用范围与逐动作现实副作用声明完整
安全限制和硬否决合同完整
相关因果与状态证据仍当前
```

方法首只用于召回；执行必须回到条件、结果、动作入口和本轮参数。

候选集可以有多条，但当前活动路径只能有一条。当前路径必须绑定本轮任务、筹办轮次、被选方法、当前方法版本和就绪合同；候选召回、历史候选和未选方法不得被当作当前活动路径。

## 5. 因果链边界

同特征前置、跨特征联动和状态变化线索可帮助发现条件或间接路径，但不能单独证明某方法能产生目标。方法能力必须由动作动态、条件结果对和实际复现证明。

服务、观察、外设和学习前置只能通过正式因果、需求条件、方法条件或已入树子需求进入，不得由筹办器硬编码。需求活动资格、安全因果图、安全阈值、调度倍率规则和适用性分类规则不进入筹办就绪链。筹办形成冻结后，纯内部治理 / 纯观察不请求现实执行授权；含现实改变步骤的冻结才在任务进入执行阶段前请求一份自我授权。6150 只提供安全调度倍率与安全硬否决，不形成第二正向授权；服务根不产生调度资格。

## 6. 方法能力判断与筹办分流

| 当前事实 | 机器判断与合法筹办结果 |
| --- | --- |
| 特征粗召回完整为空 | 先形成具名“方法能力缺失”判断材料；仅当 3100 / 3200 的正式学习门禁全部满足时，经需求统一入口形成学习需求承接，否则形成带门禁缺项和重新触发条件的合法等待。不得预造未知方法输入条件，不得建立能力缺口节点、目标变化材料节点或方法首。 |
| 有特征粗召回但对象、方向或结果能力均不兼容 | 形成“当前无适用方法”判断结果并保留完整粗召回与逐候选不兼容证据；只形成合法等待，不得进入学习需求承接，也不得与方法结构缺口混账。 |
| 零对象概念支持 | 若适用判断需要对象类型，形成带概念支持生产者和重新触发条件的合法等待；不得猜存在根或默认概念。 |
| 多个适用候选但没有比较选择证据 | 稳定返回完整候选组并合法等待；不得按稳定编码选方法，也不得同时为多个候选提出条件草案。 |
| 候选方法已失效或不可用，但存在可修复的具体方法结构 | 形成方法补齐承接，指向方法状态或对应结构化补齐项；不得把该判断转换为独立缺口对象。 |
| 缺动作入口 | 形成方法补齐承接，指向目标方法动作入口的结构化补齐项。 |
| 缺条件结果对 | 形成方法补齐承接，指向目标方法条件结果契约的结构化补齐项。 |
| 缺输入或参数 | 形成方法补齐承接，指向具体参数宿主、特征和取得/绑定状态的结构化补齐项。 |
| 条件事实未满足 | 形成指向正式条件状态及合法生产者的合法等待或子目标，不改写为方法能力缺失。 |
| 证据不足 | 形成指向观察、验证、归因或因果证据的具名等待；若缺的是方法合同本身，则形成方法补齐承接。 |

`方法能力缺失`只表示特征粗召回完整为空；`当前无适用方法`只表示粗召回非空、对象 / 方向 / 结果适用判断完整结束且全部粗召回项均不适用。两者都不是持久节点、候选对象或承接类型，且必须保留各自完整扫描或逐候选不兼容证据。结构不完整、预算不足、当前性漂移、目标当前事实待形成、零对象概念和多候选缺选择证据不得伪装成任一无方法结论。

“无确认路径”只描述本轮召回尚未形成当前活动方法路径，不是筹办闭合结果、任务终态或上层回退。筹办结束前必须按事实收束为：特征粗召回完整为空时先形成“方法能力缺失”判断材料，再由正式学习门禁裁决为学习需求承接或合法等待；粗召回非空但适用候选为空的“当前无适用方法”只形成合法等待；已有粗召回或候选但就绪链存在具体结构化问题时形成方法补齐承接；其它分支形成带等待对象、合法生产者、重新触发条件和当前版本的合法等待。任何分流都不得建立能力缺口节点。

## 7. 直接达成与补齐推进

可直接达成目标且就绪的方法优先。多个就绪候选仍必须选择一条当前活动方法路径；其余候选只保留为本轮候选或历史选择材料。只推进方法结构、参数或状态的补齐方法属于方法补齐承接，不能冒充业务目标方法。

方法状态、执行入口、条件结果对、参数和前置条件是不同的判断维度，不得压成一个“无方法”布尔值。方法侧六项投影继续保存这些结构的完整描述，但不再作为任务侧六项精确相等门槛。

## 8. 回流和验证

方法补齐承接或等待事实经需求领域入树、被子任务承接并形成结果后，若父任务仍处于同一未收束任务轮次的筹办阶段，可以触发新的筹办轮次；父任务必须重新召回和复判，不能复用旧就绪结论。父任务轮次已经收束时，回流只进入自我后继决议材料，不能自动建立新任务轮次。

验证覆盖目标已满足短路、三态所需方向、特征粗召回空、对象零 / 单 / 多概念、对象 / 方向 / 结果不兼容、候选失效、多个候选缺选择证据、只为实际采用方案形成条件草案、参数缺失、条件回流后重新筹办、方法能力缺失判断材料在正式学习门禁满足 / 不满足时分别形成学习需求承接 / 合法等待、当前无适用方法只形成合法等待、结构缺口形成方法补齐承接，以及全流程不建立能力缺口节点、不保留任务六项精确相等旁路。

## ARCH-L4 方法筹办边界（20260824）

方法查找、条件提议和就绪判断属于 ARCH-L4；方法服务只提供结构与值式能力投影，任务/方法虚拟存在及治理状态不得成为 ARCH-L2 第二权威。无方法、学习需求和方法补齐均是业务判断结果，不建立能力缺口节点或通用状态/动态事实。
