# 5250 子规范 任务筹办按方法能力查找到就绪因果链

编号：5250
日期：20260720
状态：正式子规范

## 1. 定位

本规范定义普通可任务化原子任务如何按方法结果能力召回候选、读取就绪因果链、形成唯一当前活动方法路径并形成闭合筹办结果。

直接上级规范：3200、3300。

直接依赖规范：1190、3100、5230。

相关边界规范：4310、5240、5300。

## 2. 适用闸门

本规范只适用于目标完整、没有应先推进的活动子需求、目标特征定义允许普通任务化的原子任务。

管理、汇总、AND、OR、方法路径、因果支撑和结构治理节点即使当前没有子节点，也不得进入普通方法召回；必须先按对应展开与聚合规则处理。

## 3. 召回合同

1. 先按 5230 §5 执行目标状态解析：从任务来源需求读取目标对象类型、需改变的特征类型、变化方向、目标条件和限制条件。
2. 方法六项静态能力描述召回作为候选起点：必须匹配方法六项静态描述（输入条件 + 目标对象类型 + 可改变特征类型 + 变化方向 + 结果类型 + 限制条件），全部匹配才进入候选集。
3. 进入候选集后仍必须回读方法当前登记项、生命周期、动作入口、条件结果对、参数绑定、禁止项、验证和归因合同复判就绪性（见 §4 就绪链）。
4. 候选集可以为空、只有一条或包含多条；候选集是本轮召回和选择输入，不等于当前活动路径。一个任务在一个当前筹办轮次内最多保留一条当前活动方法路径；多候选必须经过就绪复判和选择后才能形成该路径，未选候选不得并列作为当前路径。
5. 方法名称、动作名称、函数名、分类标签和固定编号不得参与语义命中，只可作为可重建的非权威读取辅助索引。
6. 通用特征写入、状态创建、动态创建、任务筹办和其它底层原语不得作为语义候选方法，除非它们的六项静态能力描述能精确覆盖业务目标语义。

## 4. 就绪链

候选方法就绪必须同时满足：

```text
方法生命周期和内容版本当前
结果能力命中任务目标
真实动作入口当前
条件和条件结果对完整
输入与参数绑定闭合
禁止项未命中
授权、安全、验证和归因合同成立
相关因果与状态证据仍当前
```

方法首只用于召回；执行必须回到条件、结果、动作入口和本轮参数。

候选集可以有多条，但当前活动路径只能有一条。当前路径必须绑定本轮任务、筹办轮次、被选方法、当前方法版本和就绪合同；候选召回、历史候选和未选方法不得被当作当前活动路径。

## 5. 因果链边界

同特征前置、跨特征联动和状态变化线索可帮助发现条件或间接路径，但不能单独证明某方法能产生目标。方法能力必须由动作动态、条件结果对和实际复现证明。

安全、服务、观察、外设和学习前置只能通过正式因果、需求条件、方法条件或已入树子需求进入，不得由筹办器硬编码。

## 6. 方法能力判断与筹办分流

| 当前事实 | 机器判断与合法筹办结果 |
| --- | --- |
| 六项静态能力描述全量召回为空 | 形成“方法能力缺失”判断结果，并经需求统一入口形成学习需求承接；不得建立能力缺口节点、目标变化材料节点或方法首。 |
| 候选方法已失效或不可用，但存在可修复的具体方法结构 | 形成方法补齐承接，指向方法状态或对应结构化补齐项；不得把该判断转换为独立缺口对象。 |
| 缺动作入口 | 形成方法补齐承接，指向目标方法动作入口的结构化补齐项。 |
| 缺条件结果对 | 形成方法补齐承接，指向目标方法条件结果契约的结构化补齐项。 |
| 缺输入或参数 | 形成方法补齐承接，指向具体参数宿主、特征和取得/绑定状态的结构化补齐项。 |
| 条件事实未满足 | 形成指向正式条件状态及合法生产者的合法等待或子目标，不改写为方法能力缺失。 |
| 证据不足 | 形成指向观察、验证、归因或因果证据的具名等待；若缺的是方法合同本身，则形成方法补齐承接。 |

“方法能力缺失”只表示六项静态能力描述全量召回为空的判断结果，不是持久节点、候选对象或承接类型。该判断结果必须沿需求统一入口派生学习需求；学习需求不是由筹办器直接建立能力缺口节点。

“无确认路径”只描述本轮召回尚未形成当前活动方法路径，不是筹办闭合结果、任务终态或上层回退。筹办结束前必须按事实收束为：无候选时的“方法能力缺失”判断结果→学习需求承接；已有候选但就绪链存在具体结构化问题时的方法补齐承接；或带等待对象、合法生产者、重新触发条件和当前版本的合法等待。任何分流都不得建立能力缺口节点。

## 7. 直接达成与补齐推进

可直接达成目标且就绪的方法优先。多个就绪候选仍必须选择一条当前活动方法路径；其余候选只保留为本轮候选或历史选择材料。只推进方法结构、参数或状态的补齐方法属于方法补齐承接，不能冒充业务目标方法。

方法状态、执行入口、条件结果对、参数和前置条件是不同的判断维度，不得压成一个“无方法”布尔值；只有六项静态能力描述全量召回为空时，才形成“方法能力缺失”判断结果。

## 8. 回流和验证

方法补齐承接或等待事实经需求领域入树、被子任务承接并形成结果后，触发父任务新筹办轮次。父任务必须重新召回和复判，不能复用旧就绪结论。

验证覆盖空索引、索引陈旧、候选失效、结果不匹配、多个候选但只形成一条当前活动路径、参数缺失、条件突变、方法能力缺失判断结果→学习需求承接、已有候选具体结构缺口→方法补齐承接，以及全流程不建立能力缺口节点。
