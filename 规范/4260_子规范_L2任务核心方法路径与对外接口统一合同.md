
冲突裁决固定为：

```text
v0.5 最新结构模型
    >

    >

```

任何旧条款只要与以下最新口径冲突，固定失效：

```text

列表项全部成员不是任务来源需求集合

一轮执行只运行一个实例方法
独立子目标进入需求树
替代方法路径不进入需求树
```

## 1. 定位

当前项目对任务的核心定义固定为：

> **任务是任务领域按具体需求承接输入建立或复用、为了使其显式关联需求的同一确定目标成为事实，而组织可达方法路径、选择并执行具体实例方法、持续承载运行状态并验证实际结果的一次有身份活动。**

任务核心固定由四部分组成：

```text
目标
    = 至少一项当前有效的显式关联具体需求逐项互证形成的单目标投影

可选手段
    = 0..N 条任务方法路径

本轮执行手段
    = 0..1 当前选中路径
    + 0..1 当前实例方法

运行状态
    = 正式 T→E 所指任务专属存在上的 ARCH-L2 特征 / 状态 / 动态
```

形式化表达：

```text
任务 T
├── 同类任务查询锚点 L
│     └── 只用于查询 / 防重，不提供任务目标或来源集合
│
├── 当前任务来源需求关系组
│     ├── T -> D1
│     ├── T -> D2
│     ├── ...
│     └── T -> Dn
│           └── 至少一项当前有效 D，逐项互证同一目标
│
├── 方法路径体系
│     ├── P1
│     ├── P2
│     ├── ...
│     ├── Pn
│     └── 当前选中路径 -> 当前实例方法 Mi
│
└── 正式 T→E
      ├── E 为任务专属 L2存在身份
      └── E 上的 ARCH-L2 特征 / 状态 / 动态承载运行状态
```

任务必须能够回答：

```text
为什么现在有这个任务？
    -> 逐次承接形成的当前 T→D 正式关系

要做到什么？
    -> 当前显式关联 D 的目标三元组逐项互证形成的单目标投影

有哪些办法？
    -> 当前筹办轮次形成的 0..N 条任务方法路径

这一轮具体怎么做？
    -> 当前选中路径 / 当前实例方法

现在进行到哪里？
    -> 正式 T→E 所指 E 的当前阶段特征、状态与动态

这一轮实际消费了哪些显式关联需求和规则版本？
    -> 本轮筹办 / 调度 / 执行冻结材料

实际发生了什么？
    -> 独立结果事实和证据

目标是否达成？
    -> 显式关联 D 的目标投影与独立当前事实的正式比较 / 验证
```

任务不是：

```text
需求节点
需求列表项
方法
方法路径
实例方法
执行日志
世界存在
第二套目标分解树
```

## 2. 最新模型废止的旧结构

为防止代码生成时把旧版结构重新带回，本版明确废止 4260 v0.1 / v0.2 / v0.3 / v0.4 中与 v0.5 冲突的旧设计。

### 2.1 v0.4“列表项动态成员即来源”模型退出当前资格

v0.4 曾冻结：

```text
任务 -> 需求列表项 L -> 全部当前成员
```

v0.5 当前模型：

```text
任务 -> 同类任务查询锚点 L
任务 -> 逐项具体来源需求 D1..Dn
D1..Dn -> 逐项互证同一目标
```

L 只用于查找 0..1 个候选当前任务。不得自动承接 L 全部成员；不得从 L 的聚合目标形成任务当前目标。

### 2.2 不再保存任务目标副本

废止任务内：

```text
目标宿主
目标特征
目标状态合同
目标场景
当前状态副本
```

任务目标必须读取：

```text
任务
-> 当前任务来源需求关系组
-> 至少一项当前具体需求
-> 逐项互证目标
```

### 2.3 不再保存任务治理存在

v0.1 的：

```text
任务 -> 治理存在
```

不再属于当前任务核心。

当前需求所有者、路径、权重等业务来源通过：

```text
任务来源需求关系组
-> 已显式关联的具体需求业务视图
```

取得。

不得恢复：

```text
L2自我任务
自我任务 owner
自我任务服务
任务治理存在字段
```

### 2.4 不再保存任务运行场景作为任务核心引用

v0.1 的任务运行场景引用不属于当前 `L2任务事实`。

执行所需场景、观察材料或运行上下文应由：

```text
路径材料
实例方法冻结
执行冻结
来源事实
```

按各自正式合同承载，不得恢复为任务核心永久字段。

### 2.5 不再建立任务父子关系

废止：

```text
L2任务父子关系事实
任务父任务
任务子任务
任务树
替换父任务
按父任务读取直接子任务
按子任务读取父任务
```

唯一目标分解树固定为：

```text
需求树
```

### 2.6 不再允许替换任务目标引用

由于任务自身不保存目标副本，也不存在：

```text
替换目标宿主
替换目标特征
替换目标状态合同
```

任务绑定的 `同类任务查询锚点` 创建后不可替换。

某项来源需求目标语义改变应由需求体系形成新的需求事实；任务只能通过新的显式承接关系消费，不得原地改写既有来源需求或从查询锚点替换目标。

## 3. 强类型与身份边界

本版冻结或要求后继正式合同冻结以下强类型身份：

```text
L2任务身份
L2任务虚拟存在身份
L2任务来源需求关系类型身份
L2任务方法路径身份
L2实例方法身份
L2需求列表项身份
```

类型边界：

```text
L2任务身份
    != L2需求身份
    != L2需求列表项身份
    != L2任务方法路径身份
    != L2实例方法身份

L2任务虚拟存在身份
    != L2存在身份
```

禁止：

```text
普通稳定编码冒充强类型身份
名称 / 文本冒充身份
缓存定位冒充身份
本地键冒充身份
legacy 投影冒充身份
世界 L2存在身份冒充任务虚拟存在
任务虚拟存在隐式转换为 L2存在身份
```

如果当前正式 C++ ABI 已经冻结上述类型，则实现必须复用现有真实 ABI，不得再建立第二套包装类型。

若某一后继类型尚未在共同 ABI 中正式冻结：

```text
不得先用裸 I64
不得先用万能稳定编码
不得先用 void*
不得先用普通属性槽
不得先用字符串标签
```

临时占位后再“以后强类型化”。

## 4. L2任务事实

### 4.1 核心事实

`L2任务事实` 固定包含：

```text
L2任务身份 身份
L2需求列表项身份 同类任务查询锚点
L2任务虚拟存在身份 任务虚拟存在兼容投影
L2生命周期 生命周期
```

这是现有 ABI 的任务核心值式事实。对新任务，兼容投影必须包装正式 E 的稳定编码；消费资格还必须独立读回 `L2任务正式存在关系事实`，不能只读该字段。

### 4.2 不可变字段

任务创建后：

```text
同类任务查询锚点
正式 T→E；兼容投影随 E 固定且不可替换
```

均不可替换。

方法路径、当前路径、当前实例方法、任务轮次、筹办轮次、执行轮次和任务运行状态不属于任务身份不可变字段。

### 4.3 任务、筹办与执行轮次分账

任务创建后建立第一个任务轮次。一个任务轮次固定按`筹办 -> 执行 -> 结算 -> 轮次已收束`推进；一个任务轮次可以在尚未形成正式实际结果且尚未进入结算时包含多个筹办轮次，每个执行轮次只消费一个筹办轮次形成的执行冻结。

任务轮次、筹办轮次和执行轮次必须使用不同强类型身份并相互引用，不得用任务序号、路径序号、工作项序号或普通整数互相冒充。任务轮次收束后不得自动建立下一筹办工作包；只有自我后继决议为`继续`且经任务管理合法复核后，才建立新的任务轮次并从新的筹办轮次开始。

### 4.4 查询锚点唯一任务约束

固定：

```text
一个当前同类任务查询锚点
    -> 至多一个当前任务
```

一个任务只能绑定一个同类任务查询锚点；该锚点不是目标或授权。

列表项可以在当前成员归零后继续保留，因此：

```text
列表项当前成员 = 0
```

不由 L2任务结构服务自动推导：

```text
任务必须退出
任务已完成
任务应取消
```

是否继续保持当前任务由 DATA 外任务业务依据当前目标、引用、历史和治理规则裁决。

## 5. 任务目标

### 5.1 唯一权威目标来源

任务目标固定为：

```text
任务目标
=
任务.当前显式关联需求组逐项互证的单目标投影
```

每项当前关联需求都由 4250 的 `L2需求事实` 提供：

```text
所属存在
目标宿主
目标特征
目标状态合同
```

形成投影至少需要一项当前有效关联需求；全部关联需求失活或退出时不得读取查询锚点聚合键兜底，必须返回具名`无当前来源需求`。任务自身不得保存第二份目标副本。

### 5.2 任务目标读取

调用方需要任务目标时必须：

```text
任务
-> 按任务读取当前来源需求关系组
-> 逐项读取需求
-> 验证所属查询锚点与目标三元组一致
-> 取得单目标值式投影
```

不得：

```text
从任务节点属性读取目标
从同类任务查询锚点猜测任务目标
从列表项全部成员猜测任务来源
从方法预期结果反推任务目标
从当前实例方法反推任务目标
从日志或缓存还原任务目标
```

### 5.3 目标当前满足不进入任务核心

任务不保存永久：

```text
目标已满足
目标未满足
完成比例
最终成功
```

目标是否达成必须实时：

```text
读取任务当前显式关联需求单目标投影
+
读取目标宿主独立当前事实
+
正式比较 / 判断收束
=
本次任务目标验证结论
```

因此：

```text
方法成功
≠ 任务目标已达成

实例方法执行结束
≠ 任务轮次结算完成

历史曾达成
≠ 当前仍达成
```

## 6. 当前来源需求关系组与本轮消费冻结

### 6.1 任务正式保存逐项来源需求关系

任务 owner 必须持久化：

```text
L2任务来源需求关系事实
    = 任务 + 具体来源需求 + 生命周期
```

当前来源需求关系组固定由：

```text
任务
-> 当前任务来源需求关系组
-> 逐项具体需求
```

实时取得。该关系是任务承接关联事实，不复制需求目标，不构成第二需求权威。

### 6.2 列表成员变化不改任务来源关系

同一查询锚点允许列表成员需求加入或退出，但只有显式承接输入才能改变任务来源关系。

列表成员变化：

```text
不自动改变任务来源关系
不改变任务身份
不回写历史筹办轮次
不回写历史执行轮次
```

### 6.3 筹办 / 调度 / 执行必须冻结实际消费来源

当一次筹办、冻结、调度、排队或执行使用任务显式关联需求的：

```text
路径
当前性
优先级输入
预算输入
```

时，必须在对应本轮冻结材料中保留：

```text
本轮实际消费的来源需求身份与关系身份
来源需求版本 / 当前性依据
规则版本
共同事实截止
```

具体冻结 DTO 由任务状态 / 执行冻结 / 后继正式合同承载。

禁止把该快照反塞进 `L2任务事实`；长期关联由独立任务—需求关系承载。

显式关联需求后来新增或退出：

```text
不得反写历史冻结
不得改变历史选择依据
不得改变历史归因材料
```

### 6.4 v0.5 精确 ABI 与本地键

任务核心新增并固定：

```cpp
struct L2任务来源需求关系类型身份 final { 稳定编码 值; };

struct L2任务来源需求关系事实 final {
    稳定编码 关系稳定编码;
    L2任务身份 任务;
    L2需求身份 来源需求;
    std::uint64_t 来源顺序 = 0;
    L2生命周期 生命周期;
    friend bool operator==(const L2任务来源需求关系事实&,
        const L2任务来源需求关系事实&) = default;
};

struct L2任务正式存在关系事实 final {
    关系句柄 关系;
    L2任务身份 任务;
    L2存在身份 正式存在;
    L2生命周期 生命周期;
};

struct L2任务轮次事实 final {
    L2任务轮次身份 身份;
    L2任务身份 任务;
    std::uint64_t 轮次序号;
    L2生命周期 生命周期;
};

struct L2任务事实 final {
    L2任务身份 身份;
    L2需求列表项身份 同类任务查询锚点;
    L2任务虚拟存在身份 任务虚拟存在; // 新任务只作正式 E 的兼容投影
    L2生命周期 生命周期;
};
```

公开结构接口固定为：

```cpp
L2按同类任务查询锚点读取当前任务结果
按同类任务查询锚点读取当前任务(
    L2按同类任务查询锚点读取当前任务请求) const noexcept;

inline constexpr std::uint32_t L2按任务读取来源需求关系组合同版本 = 1;

struct L2按任务读取来源需求关系组请求 final {
    std::uint32_t 合同版本 = L2按任务读取来源需求关系组合同版本;
    L2结构请求头 请求头;
    L2任务身份 任务;
    friend bool operator==(const L2按任务读取来源需求关系组请求&,
        const L2按任务读取来源需求关系组请求&) = default;
};

struct L2按任务读取来源需求关系组结果 final {
    L2结构结果头 结果头;
    std::uint32_t 合同版本 = L2按任务读取来源需求关系组合同版本;
    L2任务身份 任务;
    std::vector<L2任务来源需求关系事实> 来源需求关系组;
    std::uint64_t 本次正式读回截止 = 0;
    bool 成功() const noexcept;
    friend bool operator==(const L2按任务读取来源需求关系组结果&,
        const L2按任务读取来源需求关系组结果&) = default;
};

L2按任务读取来源需求关系组结果 按任务读取来源需求关系组(
    L2按任务读取来源需求关系组请求 请求) const noexcept;

L2承接具体来源需求结果
承接具体来源需求(L2承接具体来源需求请求) noexcept;
```

`L2任务来源需求关系事实.来源顺序`是现行单边角色标记，完整值恒为 `1`，不承担组排序。请求有效当且仅当专属合同版本为 `1`、共同请求头合同版本为 `L2结构合同版本`、`请求头.期望事实代次` 即 `G0` 非零且任务身份有效。

结果成员 `成功() const noexcept` 不得引用请求参数。它只检查结果自身闭包：结果头合同版本正确、公共状态为 `已读取`、结果头事实截止代次非零、变更事实代次为空、专属合同版本为 `1`、结果任务有效、本次正式读回截止非零且等于结果头事实截止代次，以及组内每项关系 / 任务 / 需求有效、每项任务等于结果任务、来源顺序为 `1`、创建代次非零且不晚于结果头事实截止、退出为空；组先按来源需求身份稳定编码升序，再按关系稳定编码升序，关系稳定编码全组唯一且排序无重复。组允许 `0` 项。

公开函数的成功后置条件另行绑定请求：`结果.任务 == 请求.任务`，且 `结果.结果头.事实截止代次 == 结果.本次正式读回截止 == 请求.请求头.期望事实代次 == G0`。服务和专项必须显式断言这些等式，不得把请求或 `G0` 捕获进无参数成员谓词。

该入口只读取 `G0` 当前活动的显式 `T→D` 关系，不补查询锚点成员、不返回历史退出关系，也不得从需求身份组伪造关系事实。读前和读后当前事实代次都必须等于 `G0`，否则返回公共 `事实代次漂移=10`、无效任务、空组和截止 `0`。

状态矩阵固定为：`已读取=3` 是唯一成功，`0/N` 项均合法；坏专属版本、共同头、`G0` 或任务为 `入口拒绝=5`；底层许可拒绝为 `许可拒绝=6`；任务从未存在为 `未找到=7`；任务在 `G0` 前已退出为 `已退出=8`；读前或读后代次不等为 `事实代次漂移=10`；错任务、坏需求、重复关系身份、排序 / 生命周期 / 混代冲突为 `引用冲突=12`；`std::bad_alloc` 为 `资源失败=13`；其它异常或底层返回 / 载荷矛盾为 `内部不一致=14`。全部非成功只保留固定合同版本和对应公共结果头，结果任务无效、组空、截止 `0`。这是只读入口，重复调用仍返回 `已读取`，不使用 `精确重复`。

本计划已对当前源码做全仓精确字面冲突复核，冻结未占用本地键：

```text
任务来源需求关系类型键值                 = 0x0301'2114
任务正式存在关系类型键值                 = 0x0301'2115
普通承接任务来源需求关系写入本地键值     = 0x0301'2219
新任务首次融合来源需求关系写入本地键值   = 0x0301'2613
新任务正式存在关系写入本地键值           = 0x0301'2614
复用任务新增来源需求关系写入本地键值     = 0x0301'2650
R1 / 治理函数定义 / A1 登记键范围         = 0x0301'2180..0x0301'218E
治理函数定义材料值写入本地键             = 0x0301'218F
R1 写入键范围                            = 0x0301'2660..0x0301'2664
A1 写入键范围                            = 0x0301'2680..0x0301'2687
```

`0x0301'2180..0x0301'218E` 必须严格登记 15 个可计数角色：R1 族锚点、R1 族归属 / R1→T / T→当前 R1 三个关系类型、R1 轮次序号属性类型共 5 个；治理函数定义节点与定义材料属性类型共 2 个；A1 族锚点、族归属 / 被调用函数 / T / R1 / P1 / 触发前态六个关系类型、调用材料属性类型共 8 个。三组分别只服务于 R1、治理函数定义和 A1 的实际 owner 写集，不得合并角色、增加第二身份节点或把运行时事实节点计入登记键。

上述 15 项只统计登记节点 / 锚点、关系类型和属性类型，不包含值事实。治理函数定义登记写集还必须以独立本地键 `0x0301'218F` 建立一项 U64 组值事实，所属节点和来源节点均引用 `0x0301'2185` 的治理函数定义节点，属性类型引用 `0x0301'2186`，材料严格为有序 `{函数种类, 函数合同版本, 规则版本}`，并以该值键形成定义节点的当前属性槽。一个 L1 owner 写集中的节点、关系和值共用同一本地键命名空间，`0x0301'2185`、`0x0301'2186`、`0x0301'218F`不得复用；属性槽只引用 `0x0301'218F`，不另计新事实键。公开 `L2任务治理函数定义事实` DTO 不增加原始值身份字段；task owner 只有在按定义节点独立读回并互证值形状、所属、属性类型、来源、三个版本值和当前生命周期后，才可重建并返回既有强类型字段。

实现必须以 `static_assert` 固定：登记范围计数为 15，定义材料值键等于登记末键加一，定义登记写集的三个事实键两两不同，且 `0x0301'218F < 0x0301'2201`。当前生产 task owner 在该开区间内没有其它键；后继不得把 `0x0301'218F`重新分配给节点、关系或第二材料。

实现不得恢复已经冲突的 `0x0301'2113` 或 `0x0301'2205`；两者当前分别属于任务虚拟存在关系类型和写入键。不得占用 `0x0301'2641..2646`，该区间已经由初次融合轮次权威关系使用。

## 7. 手段模型：候选方法、任务方法路径、当前实例方法

任务的“手段”严格分成三层：

```text
候选方法
    ↓
任务方法路径
    ↓
当前选中路径 / 当前实例方法
```

### 7.1 候选方法

候选方法只表示：

```text
根据当前目标和事实召回到的可能能力
```

候选不证明：

```text
条件已闭合
输入已闭合
参数已绑定
动作入口可用
验证合同完整
当前可执行
```

### 7.2 任务方法路径

任务方法路径表示：

> **某个任务在某个筹办轮次中，为达成当前显式关联需求互证出的单一目标而形成的一条具体方案。**

一个任务允许：

```text
0..N 条当前方法路径
```

同一筹办轮次允许：

```text
0..N 条候选 / 可达路径
```

路径集合变化不得改变任务身份。

### 7.3 当前选中路径

任务当前：

```text
当前选中路径 = 0..1
```

合法空可能表示：

```text
尚未筹办
筹办未闭合
没有可达路径
等待输入
等待条件
等待子需求回流
需要重新筹办
```

合法空本身不等于任务失败。

### 7.4 当前实例方法

任务当前：

```text
当前实例方法 = 0..1
```

一次执行只能运行一个实例方法。

禁止：

```text
多条路径同时成为当前选中路径
同一执行轮次同时运行多个实例方法
```

## 8. 任务方法路径最小结构合同

### 8.1 路径必须能够回读

每条任务方法路径至少必须能够回到：

```text
任务
筹办轮次
来源方法
方法内容版本
条件绑定
输入绑定
参数绑定
动作入口
预期结果
验证合同
归因合同
路径当前性
生命周期
```

如为组合方法，还应能够回读：

```text
子方法组成
步骤顺序
终止条件
```

普通确定步骤仍属于方法 / 路径内部，不自动形成需求。

### 8.2 路径不是抽象方法

```text
L2任务方法路径身份
    != 抽象方法身份
```

同一个抽象方法可以在：

```text
不同任务
不同筹办轮次
不同输入
不同参数
不同条件
```

下形成不同任务方法路径。

### 8.3 路径结构服务不做业务评分

L2路径结构只负责：

```text
身份
强引用
结构完整
生命周期
当前 / 历史
幂等
事实代次
```

它不负责判断：

```text
该路径是否真的能达成目标
哪个路径最好
哪个路径风险最低
应该选哪一条
```

这些属于 DATA 外任务筹办 / 方法选择业务。

## 9. 当前选中路径与换代

### 9.1 当前关系

一个任务当前最多一条选中路径。

发布当前选中路径时必须做到：

```text
旧当前选中关系退出（如有）
+
新当前选中关系建立
=
同代原子发布
```

### 9.2 换代历史

新一轮筹办可以：

```text
再次选择相同抽象方法
再次选择历史上曾使用的路径语义
```

但不得覆盖旧历史。

必须保留：

```text
旧筹办轮次
旧路径
旧当前选择
旧实例方法
旧结果
旧验证 / 归因材料
```

### 9.3 结构选择与业务选择分账

`发布当前选中路径` 是结构写入口。

调用方必须已经在 DATA 外完成：

```text
评分
比较
风险 / 禁止项裁决
选择
```

L2不得：

```text
自动选择第一条
自动选择最新一条
按名称选择
按稳定编码大小选择
把稳定排序误当业务优先级
```

## 10. 实例方法

### 10.1 定位

实例方法是：

> **当前任务、本轮执行、当前选中路径的一份不可变执行快照。**

### 10.2 最小回读内容

当前实例必须能够回到：

```text
任务
当前选中路径
来源方法
来源方法内容版本
筹办轮次
执行轮次
冻结输入
冻结参数
冻结条件
动作入口
预期结果
验证合同
归因合同
实例生命周期
```

### 10.3 不可变原则

实例方法形成后，其本轮冻结内容不得原地修改。

输入、参数、条件或方法版本发生会影响执行语义的变化时：

```text
旧实例退出当前
保留历史
重新筹办 / 重新实例化
形成新实例
```

### 10.4 所有权边界

实例方法结构由方法 / 运行实例正式合同拥有。

4260 只冻结任务侧必须具备的关联和读取要求，不因此把实例方法所有权并入 `L2任务结构服务`。

## 11. 任务正式存在与兼容引用

### 11.1 一任务一正式存在

每个新任务必须引用唯一任务专属正式存在：

```text
任务 T -> 正式 L2存在身份 E
```

一个当前新任务恰一条当前 `T→E`；E 不得被多个任务共享。E 由唯一 `L2存在结构服务`建立和读回，task owner 只保存关系。

### 11.2 兼容引用不是第二存在

`L2任务虚拟存在身份`保留为迁移期强类型兼容投影。新任务可包装 E 的同一稳定编码，但该类型不等于 `L2存在身份`，不存在隐式转换，也不证明存在资格。旧历史私有节点保留历史，不得追认或复制成 E。合法世界存在消费必须读取正式 `T→E` 和 E 的存在身份来源。

### 11.3 状态承载

任务运行状态的业务解释挂载到正式 E；结构事实由 ARCH-L2 特征、状态和动态服务唯一承载。task owner 不拥有第二存在 / 特征 / 状态 / 动态写入口。

至少包括这些状态族：

```text
当前阶段 / 业务状态段
筹办轮次
筹办占用 / 当前性
候选形成状态
路径形成状态
当前选择状态
实例方法状态
等待状态
输入闭合状态
条件状态
执行冻结状态
执行轮次
执行状态
实际结果状态
目标达成状态
验证状态
归因状态
重新筹办状态
完成 / 失败 / 取消状态
```

精确特征和值域由后继任务状态规范冻结。

禁止为了方便把这些运行状态摊平到 `L2任务事实` 的普通 bool / I64 字段。

## 12. 需求树是唯一目标分解树

### 12.1 不建立第二任务树

本版固定：

```text
需求树
=
目标分解的唯一权威树
```

不持久化：

```text
任务父子关系
任务子任务关系
父任务字段
子任务字段
第二套任务树
```

### 12.2 独立子目标流程

任务筹办或执行发现独立子目标时：

```text
任务
-> 形成子需求候选
-> 提交需求业务
-> 需求业务裁决
-> 合法子需求进入需求树
-> 子需求进入 / 复用需求列表项
-> 以具体子需求承接 / 复用子目标任务
```

任务之间的层级只允许在运行期通过需求树、具体需求承接关系和查询锚点映射推导。

### 12.3 什么才是独立子目标

只有满足：

```text
是独立目标
+
需要独立方法
或
需要独立筹办
或
需要独立状态
或
需要独立完成验证
```

的前置目标，才进入需求树。

普通方法步骤：

```text
留在方法 / 路径 / 实例内部
```

### 12.4 替代方法不是子需求

同一目标存在：

```text
P1
P2
P3
```

时：

```text
需求树不变化
```

替代方法路径属于任务手段，不属于目标分解。

## 13. 唯一所有权与身份来源

本节吸收 v0.1 中仍与当前模型兼容的 DATA 工程门禁。

### 13.1 任务结构 owner

`L2任务结构服务` 是任务核心结构唯一公开 owner。

DTO 物理位置应继续遵守当前项目已冻结的 L2 结构数据文件 / 模块组织，不建立：

```text
第二任务结构服务
第二任务事实仓
兼容任务 owner
自我任务 owner
legacy 任务 owner
```

任务 owner 只拥有本规范赋予的任务核心结构职责。

方法路径、实例方法、执行冻结、结果、结算等后继结构按其正式合同拥有，不因引用任务而反向并入任务核心 owner。

### 13.2 任务族身份证明

任务 owner 必须保持唯一正式任务族来源登记。

公开 `L2任务身份` 必须能够由权威结构共同证明：

```text
精确任务 owner
+
公开任务节点
+
精确任务族归属证明
+
精确任务族关系类型
+
任务公开服务读回
```

不得仅凭：

```text
稳定编码
强类型包装
节点名称
本地键
节点形状
属性数量
关系数量
缓存位置
legacy 投影
```

证明任务身份。

### 13.3 owner 私有结构元数据

若现行 L2 技术底座以族锚点和关系类型证明节点族身份，则必须复用该机制。

任务 owner 的：

```text
族锚点
族归属关系类型
与当前模型相关的私有结构关系类型
```

均属于 owner 私有结构元数据，不是普通业务任务，不得由普通任务读取入口返回为任务。

具体关系类型身份和数值必须服从 4230、4250、5200—5340 及当前正式 C++ ABI。

本规范不得臆造第二套编号。

### 13.4 `读取任务身份来源`

必须公开：

```text
读取任务身份来源
```

当前读取至少应在同一 owner-aware 一致投影中证明：

```text
任务 owner
任务节点
任务族来源
任务族归属
任务生命周期
```

历史读取必须使用具名历史截止。

身份来源读取的当前 / 历史语义固定保持：

```text
当前任务仍有效
    -> 已读取 + 正式身份来源

当前任务已经退出
    -> 已退出 + 空当前载荷
    -> 不得偷偷补读历史来“证明仍是任务”

历史截止早于任务创建
    -> 未找到

历史截止达到任务创建之后
    -> 已读取 + 该截止下的历史身份来源

任务已经在历史截止前退出
    -> 历史入口仍可读出该截止下完整生命周期
```

对于：

```text
wrong-family
同 owner 内部锚点
关系类型节点
legacy 普通节点
裸 L1 普通节点
```

不得因为稳定编码可解析就冒充正式任务身份。

身份来源重复、错 owner、错锚点、错关系类型、混代等属于：

```text
内部不一致
```

## 15. `新增任务`

### 15.1 请求

请求至少包含：

```text
L2结构请求头
L2结构幂等身份
L2需求列表项身份 同类任务查询锚点
L2需求身份 首个来源需求
L2存在身份 任务专属正式存在
```

如当前共同结构合同要求：

```text
期望事实代次
合同版本
调用许可
```

则必须沿用共同请求头，不得在 4260 建立第二套字段。这里的调用许可只证明结构写调用方可以使用该 DATA 接口，不是业务上的自我现实执行授权。

### 15.2 写前结构校验

L2只校验：

```text
同类任务查询锚点身份合法
首个来源需求当前结构可读且当前属于该锚点
来源需求核心合同与锚点聚合键逐字段相同
正式存在经存在公开面证明当前且未被其它任务占用
同一查询锚点当前不存在第二个任务
请求结构完整
owner 合法
幂等合法
期望事实代次合法
```

L2不判断：

```text
列表项其它成员是否存在
目标是否合理
目标是否已满足
是否值得任务化
权重是否足够
自我现实执行授权是否允许本次现实改变
当前是否应该创建任务
```

这些属于 DATA 外任务业务。

### 15.3 原子形成

成功必须一笔 owner-scoped 写集原子形成：

```text
任务节点
任务族归属证明
任务 -> 同类任务查询锚点
任务 -> 首个具体来源需求
任务 -> 正式存在 E
首个任务轮次 R1、R1 -> T、T -> 当前 R1
任务事实中的 E 稳定编码兼容投影
```

不得出现：

```text
先建裸任务
以后再补查询锚点
以后再补首个具体来源需求
以后再补正式 T→E 或 R1
```

的半结构状态。

成功时：

```text
当前方法路径组 = 空
当前选中路径 = 空
当前实例方法 = 空
```

### 15.4 不允许旧字段回流

新增任务请求不得重新加入：

```text
治理存在
目标宿主
目标特征
目标状态合同
运行场景
来源需求组副本
父任务
任务父子顺序
```

这些均属于旧模型或由列表项 / 后继冻结材料承接。

### 15.5 失败分账

应沿用共同 `L2结构状态`，至少严格区分：

```text
入口拒绝
未找到 / 引用无效
已退出
引用冲突
幂等冲突
事实代次漂移
许可拒绝
资源失败
内部不一致
```

不得压成：

```text
false
nullptr
创建失败
未知错误
```

## 16. `读取任务`

### 16.1 请求

至少包含：

```text
L2结构请求头
L2读取类别
L2任务身份
历史截止事实代次（历史读取时非零）
```

### 16.2 当前读取

当前读取返回：

```text
L2任务事实
任务身份来源
共同事实截止
```

其中 `L2任务事实` 已包含：

```text
同类任务查询锚点
任务正式存在稳定编码的兼容投影
生命周期
```

不得自动把：

```text
全部路径
当前选中路径
当前实例方法
全部状态
全部结果
来源需求关系组
正式 T→E 关系和 E 身份来源
任务轮次 / 治理动作调用事实
```

拼进核心任务读取。

这些必须经各自公开接口在同一截止上组合。

### 16.3 历史读取

历史读取必须：

```text
显式 L2读取类别::历史
+
非零历史截止
```

不得：

```text
拿当前列表项关系补历史
拿当前 T→E 或兼容投影补历史
拿当前路径补历史实例
跨事实代次拼装
```

### 16.4 结构不一致

对于本应单例的：

```text
同类任务查询锚点引用
任务正式存在引用
当前任务轮次引用
任务族身份来源
```

出现：

```text
缺失
重复
错 owner
错类型
错端点
混代
```

属于 `内部不一致`，不得降级为合法空。

## 17. `按同类任务查询锚点读取当前任务`

### 17.1 输入

```text
L2结构请求头
L2需求列表项身份 同类任务查询锚点
```

### 17.2 结果语义

固定：

```text
0 项
    -> 已读取 + 空

1 项
    -> 已读取 + 当前任务

>1 项
    -> 内部不一致
```

该接口只做精确结构查询，不做：

```text

目标近似

权重判断
自我现实执行授权判断
```

### 17.3 唯一性

`>1` 不是“挑最新一个”或“挑稳定编码最小一个”。

它证明：

```text
同查询锚点当前最多一任务
```

的不变量已经被破坏，必须停止依赖路径。

## 18. 读取任务正式存在与兼容投影

新任务的权威读取返回任务、唯一正式 `T→E` 关系和 E 的存在身份来源，并保证三者在同一读取截止互证。一个当前新任务为 0 条或多于 1 条当前 `T→E` 都是内部不一致；不得从兼容字段、普通稳定编码或旧私有节点猜测 E。

旧 `读取任务虚拟存在` 只保留历史 ABI。对新任务，它只能在正式 `T→E` 已完整读回后形成 `L2任务虚拟存在身份{E.值}` 的值式兼容投影，不得要求 E 由 task owner 写入，也不得把该投影隐式转换回 `L2存在身份`。合法消费者需要世界存在资格时必须消费正式 `T→E` 和存在公开读回。

## 19. `退出任务`

### 19.1 定位

L2退出只表示：

```text
任务核心结构永久退出当前态
```

不表示：

```text
任务成功
任务失败
目标满足
目标不再需要
来源需求已退出
列表项已退役
```

业务层必须先完成退出资格裁决。

### 19.2 核心自有结构闭合

成功退出必须同代闭合任务核心 owner 自有的当前结构，包括：

```text
任务节点
任务族归属证明
任务 -> 同类任务查询锚点
任务 -> 当前来源需求关系组
任务 -> 正式存在 E
任务 -> 当前任务轮次
task owner 自有治理动作调用事实与关系
```

历史仍可读。E 的退出属于存在 owner，任务退出不得隐式退出 E；只有全部外部引用解除并经存在业务资格裁决后，才由独立后继请求存在 owner 退出。

### 19.3 后继强引用保护

若当前仍存在由正式后继合同管理的强引用，例如：

```text
当前任务方法路径
当前选中路径
当前实例方法
执行冻结
未闭合工作项
结果 / 验证 / 归因强引用
结算强引用
```

则：

```text
不得由任务核心退出入口隐式级联删除
不得反向 import 全部消费者自行修改
```

应由：

```text
后继结构合同
+
L1 当前引用闭包
```

共同阻止非法退出，或要求业务层先按对应合同闭合引用。

### 19.4 禁止隐式业务动作

退出任务不得自动：

```text
退出需求列表项
退出列表成员需求
生成需求
取消方法
结算任务
改写目标状态
```

## 29. `按具体需求承接或复用任务`

固定流程：

```text
读取具体需求 D 及其当前成员关系
-> 取得 D 所属列表项 L
-> 复核 D 当前性与目标完整性
-> 按同类任务查询锚点 L 查询 0..1 个当前任务 T
-> 0 项：存在 owner 先建立任务专属 E；task owner 再原子建立 T + T→L + T→D + T→E + R1
-> 1 项：复核 T 当前、查询锚点相同、至少一项既有来源目标与 D 完全相同
-> 幂等建立 T→D；已存在同关系返回精确重复
-> >1 项：内部不一致
-> 正式读回 T、身份来源、R1、T→D、T→E 和 E 身份来源
```

业务层可以判断：

```text
当前目标已经满足
当前没有活动资格
当前无需建立任务
```

L2结构服务不得把这些判断塞进 `新增任务`。

## 30. `筹办任务`

固定流程：

```text
读取任务
-> 按任务读取当前来源需求关系组
-> 逐项读取显式关联具体需求
-> 校验至少一项当前有效需求，且目标三元组完全相同
-> 形成单目标投影
-> 读取正式 T→E 和 E 上任务阶段特征 / 状态
-> 召回候选方法
-> 读取方法条件 / 输入 / 参数 / 限制
-> 形成 0..N 条任务方法路径
-> 判断路径当前可达性
-> 选择 0..1 当前路径
-> 形成当前实例方法
-> 形成执行冻结
-> 冻结本轮实际消费的来源需求关系、需求版本和规则版本
-> 经 ARCH-L4 provider 提交 E 上状态 / 动态变化
```

若当前来源需求关系组为空，或全部关联需求均已失活 / 退出，筹办不得改从查询锚点或列表成员补目标；必须输出具名等待、结束或重新判定结果。通用授权安全事实、授权安全 provider 和“授权材料缺失等待”均不是筹办输入，也不得阻断路径形成、实例形成或执行冻结。

筹办允许输出：

```text
0 条路径
1 条路径
多条路径
等待
缺口
需要子需求
需要重新观察
同一未收束任务轮次内需要新筹办轮次
```

不得为了让任务“有路可走”而伪造路径。

## 31. 路径选择原则

任务业务可以依据：

```text
目标匹配程度
条件完整性
输入可得性
动作可用性
风险 / 禁止项
成本
时效
历史成功证据
当前环境
显式关联需求的当前优先级输入
预算
```

选择路径。

但必须保持：

```text
可达
≠ 当前选中
≠ 正在执行
≠ 已成功
```

路径选择规则必须在 DATA 外保持可审计。

如使用显式关联需求的优先级或预算输入，必须记录：

```text
实际参与来源需求与关系明细
规则版本
共同事实截止
```

## 32. `提交任务子目标`

当筹办或执行发现：

```text
必须独立达成的子目标
```

时：

```text
形成子需求候选
-> 提交需求业务
-> 由需求业务裁决
-> 合法时进入需求树
```

任务不得：

```text
直接写需求树
直接建立子需求
直接建立任务父子关系
```

提交材料至少应能回到：

```text
来源任务
来源路径 / 实例
父需求语境
子目标
缺口 / 前置原因
回流条件
```

具体需求候选 DTO 以 4250 及其后继合同为准。

## 33. `执行任务`

执行前必须至少证明：

```text
当前实例方法存在
实例仍当前
当前选中路径仍当前
任务轮次 / 筹办轮次 / 执行轮次互证
执行冻结仍有效
正式 E 的任务阶段状态允许执行
本轮冻结材料仍可接受
全局控制态允许派发
冻结后形成的正常调度资格允许派发
没有当前安全硬否决
冻结仅含内部治理或无现实副作用的纯现实观察；或者，含现实改变时已经独立读回本冻结唯一自我现实执行授权
具体方法声明的技术能力 / 受保护资源访问许可已满足（适用时；它不是第二业务授权）
```

内部治理相当于“想”，不请求业务授权。纯现实观察只有在不主动探测、不驱动设备、不发射、不对外通信、不写外部系统且无其它现实副作用时，才可不请求业务授权直接执行；混合方法必须逐动作声明现实副作用，只要含现实改变步骤，就必须在筹办 / 冻结完成后、任务进入执行阶段前完成授权门禁。

唯一正向授权由自我业务 owner 的正式领域入口发布，同时绑定任务、任务轮次、筹办轮次、执行轮次、执行冻结、实例方法、现实动作范围、事实截止、授权规则版本和有效期。它同时覆盖本执行尝试和实例方法中的冻结现实动作，不再建立任务授权与方法授权两份事实。拒绝、等待、撤回和安全硬否决不是正向授权；安全服务只提供事实、调度材料和硬否决，不得成为第二正向授权者。

执行：

```text
实例方法
-> 动作
-> 独立事实回读
-> 实际结果
-> 验证 / 归因材料
-> 经 ARCH-L4 provider 提交 E 上状态 / 动态变化
```

方法返回：

```text
success
```

只能证明：

```text
方法调用 / 动作执行合同层面的成功
```

不得直接写：

```text
任务轮次结算完成
需求满足
目标达成
正式结算成功
```

---

## 34. `验证任务目标`

固定流程：

```text
任务
-> 当前任务来源需求关系组
-> 至少一项当前有效具体需求
-> 逐项目标互证形成单目标投影

独立当前事实
-> 正式比较 / 判断收束

=
本次目标验证结论
```

验证必须使用：

```text
独立当前事实
```

不得使用：

```text
实例方法返回值
任务状态缓存
上次验证结论
预测值
目标副本
```

替代当前事实。

一次世界事实比较结果可以被同一任务的多个显式关联需求消费，但各需求仍各自保有：

```text
业务有效性
路径
结算身份
来源
```

仍独立。

目标验证只形成本任务轮次的`已达成 / 未达成 / 不可比较 / 材料不足 / 其它具名结果`。它不决定任务是否继续，也不直接建立需求正式结算记录。

## 35. 同一任务轮次筹办重判与轮次收束后继续

同一任务轮次尚未形成正式实际结果、尚未进入结算且尚未收束时，新筹办轮次的触发可以包括：

```text
当前路径失效
当前实例方法失效
条件变化
输入变化
显式关联需求当前性、优先级或预算输入变化
子需求回流
外部事实变化
当前冻结过期
```

重新筹办必须：

```text
保留旧路径历史
保留旧实例历史
保留旧执行 / 验证 / 归因材料
形成新筹办轮次
重新读取当前来源需求关系组及其当前需求事实
重新生成路径集合
重新选择
重新实例化
```

禁止：

```text
覆盖前轮路径
覆盖前轮实例
修改旧冻结
```

正式实际结果一旦形成，任务必须进入结算阶段；目标未达成、执行结果要求换路或结果材料不足都只形成本轮结论，不得在同一任务轮次直接重筹办。结算必须先裁决结果共用 / 争用，争用时完成正式分配，再对每个合格 `T→D` 独立核算；任务轮次结算结果只引用各 owner 已发布的正式结果。

任务轮次结算完成后进入`轮次已收束`并等待自我后继决议。只有`继续`决议经任务管理复核后，才建立新任务轮次和首个筹办轮次；`结束 / 等待 / 取消`分别按其正式合同收口。旧路径、实例、执行冻结和自我现实执行授权不得跨任务轮次复用。

## 36. 调度、安全硬否决与现实执行授权边界

### 36.1 删除通用授权安全前置事实

任务筹办与执行冻结不得读取或等待以下通用事实：

```text
来源需求授权事实
安全图事实
安全阈值事实
调度规则事实
适用性分类规则事实
```

也不得建立对应 provider 或“授权材料缺失等待”。这些旧 Stage C 格式只保留历史只读资格，不参与当前路径、实例或冻结裁决。

### 36.2 来源需求投影必须可审计

优先级和预算输入只能从任务显式关联的当前需求及其正式业务规则形成。若业务层形成投影，必须同时保留：

```text
来源需求关系与需求身份明细
投影值
规则版本
共同事实截止
```

不得从列表项全部成员、任务永久单值或不可追溯聚合值取得，也不得把查询锚点升级为目标来源、调度来源或授权来源。

### 36.3 调度配额 / 倍率只形成冻结后的正常调度资格

6150 / 6170 所定义的安全调度倍率、服务值、时间维护和生存安全根调度配额，只能在执行冻结完成后、真实派发前形成正常调度资格与优先级投影：

```text
执行冻结完成
-> 读取当前调度投影输入
-> 形成正常调度资格 / 优先级
-> 结合独立全局控制态
-> 允许派发 / 不派发
```

调度配额 / 倍率为零不得阻断任务承接、筹办、路径选择、实例形成或执行冻结，只排除本次普通排序。全局控制态和安全硬否决是独立门控，不伪装成需求授权、自我现实执行授权或方法适用性事实。

### 36.4 技术许可不是第二业务授权

具体方法涉及受保护资源或受限技术能力时，可以声明技术能力 / 访问许可条件。该条件只证明调用能力或资源访问合法，不承担“是否要做”的业务裁决，不扩张为所有任务共有的授权安全材料，也不得与自我现实执行授权合并。

### 36.5 一份自我现实执行授权与安全硬否决

执行冻结完成后读取方法作用范围。仅内部治理或无现实副作用的纯观察不请求授权；含现实改变步骤时，在任务进入执行阶段前请求并独立读回一份自我现实执行授权，不得先执行混合方法中的观察前缀。冻结、实例方法、动作范围、事实截止、规则版本或有效期变化时旧授权失效；冻结变化必然使授权失效，授权失效不必然撤销冻结。

安全硬否决可以阻止已授权的现实动作，自我授权不得绕过；安全事实、调度材料和硬否决都不是第二正向授权。

排队、调度或执行选择实际使用的来源需求投影、调度投影、全局控制态、安全硬否决、适用的技术许可和自我现实执行授权定位必须进入本轮派发材料；后续变化只影响后续新裁决，不改写历史裁决。

## 37. 依赖方向

本节吸收 v0.1 的单向依赖原则，并按 v0.5 新模型更新。

### 37.1 任务核心结构依赖

基础任务核心结构只允许依赖：

```text
L2任务结构
    -> L2需求结构公开读取
        - 验证同类任务查询锚点身份
        - 读取具体来源需求及其当前成员关系

L2任务结构
    -> L1事实基座
```

如强类型共同身份来源位于公共 L2 结构层，可按正式共同合同读取。

禁止基础任务核心结构直接依赖：

```text
方法业务服务
动态业务服务
因果业务服务
安全治理服务
外设业务服务
任务执行器业务
需求结构写入口
```

### 37.2 路径结构依赖

任务方法路径结构可以单向依赖：

```text
任务路径结构
    -> L2任务结构公开读取
    -> 方法结构 / 方法版本公开读取
    -> 条件 / 输入 / 参数 / 动作 / 验证 / 归因相关正式结构
    -> L1事实基座
```

具体依赖由 5200—5250、5300—5340 后继规范冻结。

不得为了方便把这些依赖反塞回基础 `L2任务结构服务`。

### 37.3 实例方法依赖

实例方法结构单向依赖：

```text
实例方法结构
    -> 任务方法路径结构
    -> 任务结构
    -> 方法内容版本
    -> 执行冻结所需正式结构
```

### 37.4 子需求回流

任务业务发现独立子目标时：

```text
任务业务
-> 需求业务提交候选
```

不是：

```text
L2任务结构服务
-> L2需求结构写入口
```

基础 L2任务结构与需求结构保持无反向写入耦合。

## 39. 幂等

### 39.1 基本规则

一份请求首次取得结果后：

```text
L2结构幂等身份
+
逐字段完整请求
```

绑定。

固定：

```text
同幂等身份 + 同完整请求
    -> 精确重复
    -> 返回首次结果

同幂等身份 + 不同完整请求
    -> 幂等冲突
    -> 零变化
```

### 39.2 事实代次漂移

只有：

```text
结构化事实代次漂移
+
明确零变化
+
没有首次发布结果
```

时，调用方才可按共同合同继续收敛。

不得把：

```text
资源失败
异常
超时
发布结果未知
```

当成“肯定没写”后生成新幂等身份重试。

### 39.3 发布未知

资源失败、异常或发布结果未知时：

```text
只能用原幂等身份
+
原完整请求
```

正式读回 / 重试收敛。

不得：

```text
换新幂等身份
删字段重试
改变语义重试
先猜成功再补写
```

## 42. DATA 错误分账

适用于任务核心、路径、实例等正式结构入口的错误必须结构化。

至少区分：

```text
入口拒绝
未找到
已退出
引用冲突
幂等冲突
事实代次漂移
数量预算不足（若共同 ABI 已冻结）
许可拒绝
资源失败
内部不一致
```

典型归属：

```text
零身份 / 错类型强引用 / 合同版本错误
    -> 入口拒绝

引用目标不存在 / 已退出
    -> 对应正式引用读取结果

同查询锚点第二当前任务
    -> 引用冲突或本规范 / 共同合同冻结的唯一性冲突状态

同幂等身份异请求
    -> 幂等冲突

期望代次失效
    -> 事实代次漂移

L1 资源分配 / 提交资源问题
    -> 资源失败

发布后读回与已发布结构矛盾
单例出现多份
同一结果混代
身份复义
    -> 内部不一致
```

如果共同 `L2结构状态` 尚未冻结某一具名状态：

```text
4260 不得自行创建第二枚举值。
```

应先同步上级共同合同。

## 43. 施工与实际消费检查边界

本节只冻结应验证的工程事实，不声明代码已经实现。

### 43.1 任务核心最小检查

至少覆盖：

1. 合法具体需求可先建立任务专属 E，再经其所属查询锚点原子建立任务、首个 `T→D`、正式 `T→E`和 R1 并正式读回；
2. 任务、查询锚点引用、首个来源关系、正式存在关系、R1 和任务身份来源共享同一 task-owner 截止；E 另按同一组合读取截止证明存在身份来源；
3. 复用当前任务时只幂等新增具名 `T→D`，不自动吞并同列表其它成员；
4. 同一查询锚点不能形成第二当前任务；
5. `按同类任务查询锚点读取当前任务` 对 0 / 1 / >1 严格分账；
6. `按任务读取来源需求关系组` 当前结果按来源需求身份、关系身份稳定升序，无重复；空组结构读取成功但不能形成目标；
7. `L2任务虚拟存在身份` 是 ARCH-L4 迁移期兼容引用类型，不等于 `L2存在身份`、不存在隐式转换；新任务必须另有正式 `T→E` 关系证明其包装的稳定编码属于任务专属 `L2存在身份 E`；
8. 任务节点不复制目标宿主、目标特征、目标状态；
9. 任务节点不保存来源需求事实副本或列表成员集合；
10. 任务节点不保存治理存在；
11. 任务节点不保存运行场景核心引用；
12. 不存在任务父子关系或第二任务树；
13. 同键同完整请求精确重复；
14. 同键异请求幂等冲突；
15. 旧期望事实代次零变化失败；
16. 当前 / 历史读取不混代；
17. wrong-family、owner 私有锚点、关系类型节点、legacy / 裸 L1 节点不能冒充任务身份。

### 43.2 方法路径检查

至少覆盖：

1. 一个任务允许 0..N 当前路径；
2. 同一筹办轮次路径历史可回读；
3. 路径能回到来源方法及内容版本；
4. DATA 不自动评分或选择路径；
5. 当前选中路径最多 1 条；
6. 当前路径换代保留旧历史；
7. 已退出路径不能继续作为当前选中路径；
8. 替代路径不生成需求。

### 43.3 实例方法检查

至少覆盖：

1. 当前实例最多 1 个；
2. 实例能回到任务和当前选中路径；
3. 冻结输入 / 参数 / 条件不可原地修改；
4. 新轮次实例不覆盖旧历史；
5. 多路径不能同时执行；
6. 方法执行成功不能直接写任务轮次结算完成。

### 43.4 来源需求消费冻结与派发检查

至少覆盖：

1. 当前来源需求只从 `T→D` 当前关系组读取；
2. 列表成员变化不自动改变任务来源关系；
3. 筹办 / 调度 / 执行能记录本轮实际消费关系、需求版本和规则版本；
4. 需求后来承接 / 退出不改写历史冻结；
5. 通用授权安全事实及 provider 不参与筹办或冻结；
6. 调度配额 / 倍率为零不阻断筹办或冻结，只影响冻结后、派发前正常调度资格；
7. 全局控制态和安全硬否决独立门控；技术许可只在具体方法合同声明时检查，且不是第二业务授权；
8. 内部治理和无现实副作用的纯观察不请求授权；含现实改变时同一冻结只存在一份自我现实执行授权；
9. 正式结果形成后进入结算，结果先共用 / 争用再逐需求独立核算，目标未达成不自动建立下一筹办工作包；
10. 轮次收束后只有自我`继续`决议能够开启新任务轮次。

### 43.5 退出检查

至少覆盖：

1. 当前存在强引用时任务退出被正式阻止或要求先闭合；
2. 退出不级联删除列表项；
3. 退出不级联删除需求成员；
4. 退出后当前不可见 / 已退出，历史仍可读；
5. 发布未知用原幂等身份收敛。

### 43.6 临时检查驱动

施工临时检查不得：

```text
编译进生产目标
取得 L1 / L2 私有仓或私有锁
绕过公开接口直接造权威事实
构造“任务已完成”假业务剧本冒充闭环
```

构建成功、日志正常、未观察到错误只证明对应工程事实，不证明业务闭环完成。

## 50. 禁止事项

禁止：

- 任务只绑定具体需求却不保存其同类任务查询锚点；
- 每个同目标成员需求重复创建任务；
- 把列表全部成员自动并入任务来源；
- 任务复制来源需求目标或从列表项聚合键取得目标；
- 任务保存第二份目标宿主、目标特征、目标状态合同；

- 为新任务创建 task-owner 私有存在节点，或在正式 `T→E` 之外复制第二存在权威；

## 53. 首个任务轮次与正式存在迁移合同

### 53.1 新任务 task-owner 单次核心写集

新任务必须在一个 task-owner 原子写集中建立：

```text
T 与任务族归属
T→L 查询锚点
首条 T→D 正式来源关系
T→E 正式存在关系
R1、R1 族归属、R1→T 与 T→当前 R1
```

E 必须已由 `L2存在结构服务`建立并在共同写前截止完成身份来源读回。task owner 只保存引用，不创建、退出或修改 E。新任务的兼容 `L2任务虚拟存在身份` 可包装 E 的稳定编码以维持旧读 DTO，但该投影只有与正式 `T→E` 和存在身份来源联合读回时才可消费；旧历史私有虚拟存在不得被追认成 E。

### 53.2 首态、P1 和第一动态顺序

task owner 核心 G_T 后，由消费者经特征公开面幂等取得全局唯一“任务主阶段 / 业务状态段”基础特征定义，并为 E 建立唯一实例。状态 owner 随后建立绑定 E 与该实例的“筹办 / 待初次筹办”首态；首态不形成动态。task owner 只有在该首态读回完整后才以独立 G_P1 建立首次准备记录、P1 和初次筹办推进治理动作调用事实 A1。状态 / 动态两个 owner 最后经既有跨 owner provider 以 A1 为来源把首态迁移为“筹办 / 筹办中”，该迁移形成第一动态。

存在、task 核心、特征定义、特征实例、首态、P1/A1、状态 / 动态迁移各自具有独立 G0/G1、幂等账和发布未知恢复。外层工作包必须回显并逐项互证这些代次，不得把业务四检查点描述成一个跨全部 owner 的共同事务。

### 53.3 初次筹办推进治理函数与调用事实

task owner 是本叶治理函数定义和调用事实的唯一 owner。`初次筹办推进`函数定义必须是可独立读回的稳定身份事实，固定回显函数种类、函数合同版本 1、规则版本 1 和生命周期；不得以常量编码、函数名或 `L2治理函数骨架`的合同版本代替。

定义的持久形状固定为“定义节点 + U64 组属性值 + 当前属性槽”。定义节点、定义材料属性类型和定义材料值分别使用 `0x0301'2185`、`0x0301'2186`、`0x0301'218F`；值的所属和来源均为定义节点，材料严格为 `{初次筹办推进, 1, 1}`。15 项登记计数不因新增值键变成 16；但定义登记写集的新编码映射必须精确包含这三个互异键。按定义身份读取只有在原始值事实及当前槽完整互证后才能形成既有 `L2任务治理函数定义事实`，不得从常量补齐缺失材料。

A1 必须是独立强类型调用事实，绑定被调用治理函数、T、R1、P1、触发前态、来源共同事实截止、调用幂等来源、函数合同版本、规则版本和生命周期。A1 可与 P1 在同一 task-owner G_P1 建立，但两者是两个事实，P1 不能冒充 A1。第一动态的纯结构来源稳定编码填写 A1 身份；业务 provider 在提交前和读回后都必须经 task owner 独立读取 A1 并互证全部字段。P1、R1、普通方法身份、函数名、日志、文本、缓存或固定魔数均不是合法替代。

### 53.4 强类型和兼容禁止

任务核心公开面必须提供 `L2任务轮次身份/事实`、`L2任务来源需求关系事实`和`L2任务正式存在关系事实`，并支持按原建立幂等身份独立读取。字符串、普通整数、列表成员集合、兼容虚拟存在字段、旧任务治理状态和调用方缓存均不得替代这三类事实。旧融合入口可以为 ABI / 专项编译保留，但新的生产消费者不得调用，也不得继续通过它创建 task-owner 私有存在。

### 53.5 初次筹办六阶段幂等身份与恢复信封

初次筹办外层请求必须携带一份强类型六阶段幂等身份组：

```text
存在建立
任务核心建立
阶段特征实例建立
首态建立
P1 建立
首迁移
```

六键必须全部非零、两两不同，并逐字段进入完整请求的相等比较和持久编码。外层`准备幂等身份`固定等于`P1 建立`键，因为首次准备记录在 G_P1 形成，既有“按准备幂等身份读取首次记录”只能继续以该键定位；`任务核心建立`键不得再作为准备键或 P1 键。全局阶段特征定义继续使用固定 `TASKSTAG` 键，不进入本六键组。

六键由业务调用方在形成原请求信封时一次性分配，并随原请求跨重试、发布未知收敛和回流重判持久传递。不得从时间、运行代次、请求身份、需求 / 任务 / 回流记录身份、哈希、算术变换或某一阶段结果临场派生其它阶段键；不同 owner 的键空间隔离也不得作为跨阶段复用同一键的理由。

`需求初次筹办准备合同版本`固定升为 2。首次准备记录的完整请求材料必须保存外层合同版本、准备键、请求身份、运行代次、请求头、具体需求、六阶段键、治理函数合同版本和初次筹办推进规则版本。版本 2 持久 U64 组恰为 15 槽；历史版本 1 的 8 槽材料只能识别为`初次请求版本待迁移`，不得补造六键、升级原记录或调用版本 2 provider。

任务子目标回流重判请求同步携带原六阶段键组。当前无任务而进入新初次筹办时，必须满足`P1 建立键 == 回流记录身份的稳定编码`，其余五键来自回流请求所承载的原请求信封。已有首次记录时，先确认历史材料是完整版本 2，再逐字段比较当前六键与历史六键；相同则以历史原完整请求重放，任一异键为`幂等冲突`。版本 1 历史记录返回`初次请求版本待迁移`且零写。

发布未知只允许消费历史首次记录中的版本 2 原完整请求和原六键按既定阶段继续收敛；未确认当前阶段前不得换键、越段或用新请求覆盖历史信封。

## ARCH-L4 业务兼容与 ARCH-L2 引用边界（20260824）

任务、方法路径、实例、冻结材料和轮次属于 ARCH-L4。现有 L2 任务服务保留兼容 ABI，只保存业务结构和引用；`L2任务虚拟存在身份`是兼容引用类型，新任务必须以正式 `T→L2存在身份 E`和存在公开读回取得通用存在，不得新建第二节点。状态、动态不得成为第二权威，必须通过 ARCH-L2 通用公开结构服务取得。DATA-L2 不判断路径成功、目标完成或方法有效；ARCH-L4 provider 负责解释业务结果后提交纯结构迁移请求。
