## 0. 合并与裁决原则

本文件合并并收束以下三版 4260 中仍然正确且对工程实现有约束价值的信息：

```text
v0.5：
    作为最新任务模型的最高优先级裁决层。

v0.4：
    只保留与 v0.5 兼容的列表查询锚点、任务虚拟存在、路径和实例合同。

v0.3：
    补全任务本体、方法路径、实例方法、任务虚拟存在、
    DATA 外业务流程、事务、当前性、同步要求和完成边界。

v0.1：
    只吸收仍与 v0.5 模型兼容的 DATA 工程硬门禁：
        owner 与身份来源
        强类型身份证明
        原子写集
        幂等
        事实代次
        当前 / 历史读取
        发布未知收敛
        引用保护
        错误分账
        施工检查
        共同 ABI 同步

v0.1 中已经被 v0.3 / v0.4 / v0.5 明确废止的结构不得恢复。
```

冲突裁决固定为：

```text
v0.5 最新结构模型
    >
v0.4 / v0.3 仍兼容的详细合同
    >
v0.1 仍兼容的 DATA 工程门禁
```

因此，本文件不是三份规范的机械拼接。

任何旧条款只要与以下最新口径冲突，固定失效：

```text
任务 -> 同类任务查询锚点（值为 L2需求列表项身份），只用于查找和防重
任务 -> 1..N 条具体来源需求正式关系，只有逐次承接输入才能建立
任务不复制目标
任务目标从显式关联的当前具体需求逐项互证形成
列表项全部成员不是任务来源需求集合
任务不建立持久父子任务树；只允许轮次级 0..1 唯一发起调用事实
任务兼容虚拟存在引用不替代正式 T→E，也不产生 L2存在身份的隐式转换
任务允许 0..N 方法路径
当前选中路径 0..1
当前实例方法 0..1
一轮执行只运行一个实例方法
独立子目标进入需求树
替代方法路径不进入需求树
```

## 1. 定位

当前项目对任务的核心定义固定为：

> **任务是任务领域按具体需求承接输入建立或复用、为了使其显式关联需求的同一确定目标成为事实，而组织可达方法路径、选择并执行具体实例方法、持续承载运行状态并验证实际结果的一次有身份活动。**

任务核心固定由四部分组成：

```text
目标
    = 至少一项当前有效的显式关联具体需求逐项互证形成的单目标投影

可选手段
    = 0..N 条任务方法路径

本轮执行手段
    = 0..1 当前选中路径
    + 0..1 当前实例方法

运行状态
    = 正式 T→E 所指任务专属存在上的 ARCH-L2 特征 / 状态 / 动态
```

形式化表达：

```text
任务 T
├── 同类任务查询锚点 L
│     └── 只用于查询 / 防重，不提供任务目标或来源集合
│
├── 当前任务来源需求关系组
│     ├── T -> D1
│     ├── T -> D2
│     ├── ...
│     └── T -> Dn
│           └── 至少一项当前有效 D，逐项互证同一目标
│
├── 方法路径体系
│     ├── P1
│     ├── P2
│     ├── ...
│     ├── Pn
│     └── 当前选中路径 -> 当前实例方法 Mi
│
└── 正式 T→E
      ├── E 为任务专属 L2存在身份
      └── E 上的 ARCH-L2 特征 / 状态 / 动态承载运行状态
```

任务必须能够回答：

```text
为什么现在有这个任务？
    -> 逐次承接形成的当前 T→D 正式关系

要做到什么？
    -> 当前显式关联 D 的目标三元组逐项互证形成的单目标投影

有哪些办法？
    -> 当前筹办轮次任务信息中的 0..N 个候选方法及其内容版本

这一轮具体怎么做？
    -> 执行前选择形成的当前路径 / 当前实例方法

现在进行到哪里？
    -> 正式 T→E 所指 E 的当前阶段特征、状态与动态

这一轮实际消费了哪些显式关联需求和规则版本？
    -> 本轮筹办 / 调度 / 执行冻结材料

实际发生了什么？
    -> 独立结果事实和证据

目标是否达成？
    -> 显式关联 D 的目标状态合同与同截止当前特征值完整投影的正式比较 / 验证
```

任务不是：

```text
需求节点
需求列表项
方法
方法路径
实例方法
执行日志
世界存在
第二套目标分解树
```

## 2. 最新模型废止的旧结构

为防止代码生成时把旧版结构重新带回，本版明确废止 4260 v0.1 / v0.2 / v0.3 / v0.4 中与 v0.5 冲突的旧设计。

### 2.1 v0.4“列表项动态成员即来源”模型退出当前资格

v0.4 曾冻结：

```text
任务 -> 需求列表项 L -> 全部当前成员
```

v0.5 当前模型：

```text
任务 -> 同类任务查询锚点 L
任务 -> 逐项具体来源需求 D1..Dn
D1..Dn -> 逐项互证同一目标
```

L 只用于查找 0..1 个候选当前任务。不得自动承接 L 全部成员；不得从 L 的聚合目标形成任务当前目标。

### 2.2 不再保存任务目标副本

废止任务内：

```text
目标宿主
目标特征
目标状态合同
目标场景
当前状态副本
```

任务目标必须读取：

```text
任务
-> 当前任务来源需求关系组
-> 至少一项当前具体需求
-> 逐项互证目标
```

### 2.3 不再保存任务治理存在

v0.1 的：

```text
任务 -> 治理存在
```

不再属于当前任务核心。

当前需求所有者、路径、权重等业务来源通过：

```text
任务来源需求关系组
-> 已显式关联的具体需求业务视图
```

取得。

不得恢复：

```text
L2自我任务
自我任务 owner
自我任务服务
任务治理存在字段
```

### 2.4 不再保存任务运行场景作为任务核心引用

v0.1 的任务运行场景引用不属于当前 `L2任务事实`。

执行所需场景、观察材料或运行上下文应由：

```text
路径材料
实例方法冻结
执行冻结
来源事实
```

按各自正式合同承载，不得恢复为任务核心永久字段。

### 2.5 不再建立持久任务父子树

废止：

```text
L2任务父子关系事实
任务父任务
任务子任务
任务树
替换父任务
按父任务读取直接子任务
按子任务读取父任务
```

唯一目标分解树固定为：

```text
需求树
```

本条不禁止轮次级、不可变、唯一发起者的正式调用关系。该关系只回答“哪个上级任务轮次的哪个调用槽实际发起了本子任务轮次”，不表达目标分解、永久父子层级、任务所有权或当前目标满足。其强类型事实、返回和调用槽结算由第 12.5—12.6 节冻结。

### 2.6 不再允许替换任务目标引用

由于任务自身不保存目标副本，也不存在：

```text
替换目标宿主
替换目标特征
替换目标状态合同
```

任务绑定的 `同类任务查询锚点` 创建后不可替换。

某项来源需求目标语义改变应由需求体系形成新的需求事实；任务只能通过新的显式承接关系消费，不得原地改写既有来源需求或从查询锚点替换目标。

## 3. 强类型与身份边界

本版冻结或要求后继正式合同冻结以下强类型身份：

```text
L2任务身份
L2任务虚拟存在身份
L2任务来源需求关系类型身份
L2任务方法路径身份
L2实例方法身份
L2需求列表项身份
```

类型边界：

```text
L2任务身份
    != L2需求身份
    != L2需求列表项身份
    != L2任务方法路径身份
    != L2实例方法身份

L2任务虚拟存在身份
    != L2存在身份
```

禁止：

```text
普通稳定编码冒充强类型身份
名称 / 文本冒充身份
缓存定位冒充身份
本地键冒充身份
legacy 投影冒充身份
世界 L2存在身份冒充任务虚拟存在
任务虚拟存在隐式转换为 L2存在身份
```

如果当前正式 C++ ABI 已经冻结上述类型，则实现必须复用现有真实 ABI，不得再建立第二套包装类型。

若某一后继类型尚未在共同 ABI 中正式冻结：

```text
不得先用裸 I64
不得先用万能稳定编码
不得先用 void*
不得先用普通属性槽
不得先用字符串标签
```

临时占位后再“以后强类型化”。

## 4. L2任务事实

### 4.1 核心事实

`L2任务事实` 固定包含：

```text
L2任务身份 身份
L2需求列表项身份 同类任务查询锚点
L2任务虚拟存在身份 任务虚拟存在兼容投影
L2生命周期 生命周期
```

这是现有 ABI 的任务核心值式事实。对新任务，兼容投影必须包装正式 E 的稳定编码；消费资格还必须独立读回 `L2任务正式存在关系事实`，不能只读该字段。

### 4.2 不可变字段

任务创建后：

```text
同类任务查询锚点
正式 T→E；兼容投影随 E 固定且不可替换
```

均不可替换。

方法路径、当前路径、当前实例方法、任务轮次、筹办轮次、执行轮次和任务运行状态不属于任务身份不可变字段。

### 4.3 任务、筹办与执行轮次分账

任务创建后建立第一个任务轮次。一个任务轮次固定按`筹办 -> 执行前选择 -> 执行 -> 结算 -> 轮次已收束`推进；一个任务轮次可以在尚未形成正式实际结果且尚未进入结算时包含多个筹办轮次，每个执行轮次只消费执行前选择基于一个已完成筹办轮次任务信息形成的执行冻结。

任务轮次、筹办轮次和执行轮次必须使用不同强类型身份并相互引用，不得用任务序号、路径序号、工作项序号或普通整数互相冒充。任务轮次收束后不得自动建立任何后继筹办工作包；已退役的`下一筹办工作包`更不得因此复活。只有自我后继决议为`继续`且经任务管理合法复核后，才建立新的任务轮次并从新的初次筹办开始。

### 4.4 查询锚点唯一任务约束

固定：

```text
一个当前同类任务查询锚点
    -> 至多一个当前任务
```

一个任务只能绑定一个同类任务查询锚点；该锚点不是目标或授权。

列表项可以在当前成员归零后继续保留，因此：

```text
列表项当前成员 = 0
```

不由 L2任务结构服务自动推导：

```text
任务必须退出
任务已完成
任务应取消
```

是否继续保持当前任务由 DATA 外任务业务依据当前目标、引用、历史和治理规则裁决。

## 5. 任务目标

### 5.1 唯一权威目标来源

任务目标固定为：

```text
任务目标
=
任务.当前显式关联需求组逐项互证的单目标投影
```

每项当前关联需求都由 4250 的 `L2需求事实` 提供：

```text
所属存在
目标宿主
目标特征
目标状态合同
```

形成投影至少需要一项当前有效关联需求；全部关联需求失活或退出时不得读取查询锚点聚合键兜底，必须返回具名`无当前来源需求`。任务自身不得保存第二份目标副本。

### 5.2 任务目标读取

调用方需要任务目标时必须：

```text
任务
-> 按任务读取当前来源需求关系组
-> 逐项读取需求
-> 验证所属查询锚点与目标三元组一致
-> 取得单目标值式投影
```

不得：

```text
从任务节点属性读取目标
从同类任务查询锚点猜测任务目标
从列表项全部成员猜测任务来源
从方法预期结果反推任务目标
从当前实例方法反推任务目标
从日志或缓存还原任务目标
```

### 5.3 目标当前满足不进入任务核心

任务不保存永久：

```text
目标已满足
目标未满足
完成比例
最终成功
```

目标是否达成必须实时：

```text
读取任务当前显式关联需求单目标投影
+
冻结非零事实截止并读取目标涉及的当前特征值完整投影
+
正式比较 / 判断收束
=
本次任务目标验证结论
```

因此：

```text
方法成功
≠ 任务目标已达成

实例方法执行结束
≠ 任务轮次结算完成

历史曾达成
≠ 当前仍达成
```

## 6. 当前来源需求关系组与本轮消费冻结

### 6.1 任务正式保存逐项来源需求关系

任务 owner 必须持久化：

```text
L2任务来源需求关系事实
    = 任务 + 具体来源需求 + 生命周期
```

当前来源需求关系组固定由：

```text
任务
-> 当前任务来源需求关系组
-> 逐项具体需求
```

实时取得。该关系是任务承接关联事实，不复制需求目标，不构成第二需求权威。

### 6.2 列表成员变化不改任务来源关系

同一查询锚点允许列表成员需求加入或退出，但只有显式承接输入才能改变任务来源关系。

列表成员变化：

```text
不自动改变任务来源关系
不改变任务身份
不回写历史筹办轮次
不回写历史执行轮次
```

### 6.3 筹办 / 调度 / 执行必须冻结实际消费来源

当一次筹办、冻结、调度、排队或执行使用任务显式关联需求的：

```text
路径
当前性
优先级输入
预算输入
```

时，必须在对应本轮冻结材料中保留：

```text
本轮实际消费的来源需求身份与关系身份
来源需求版本 / 当前性依据
规则版本
共同事实截止
```

具体冻结 DTO 由任务状态 / 执行冻结 / 后继正式合同承载。

禁止把该快照反塞进 `L2任务事实`；长期关联由独立任务—需求关系承载。

显式关联需求后来新增或退出：

```text
不得反写历史冻结
不得改变历史选择依据
不得改变历史归因材料
```


`L2任务来源需求关系事实.来源顺序`是现行单边角色标记，完整值恒为 `1`，不承担组排序。请求有效当且仅当专属合同版本为 `1`、共同请求头合同版本为 `L2结构合同版本`、`请求头.期望事实代次`即 G0 非零且任务身份有效。

结果成员 `成功() const noexcept`不得引用请求参数。它只检查结果自身闭包：结果头合同版本正确、公共状态为`已读取`、结果头事实截止代次非零、变更事实代次为空、专属合同版本为 `1`、结果任务有效、本次正式读回截止非零且等于结果头事实截止代次，以及组内每项关系/任务/需求有效、每项任务等于结果任务、来源顺序为 `1`、创建代次非零且不晚于结果头事实截止、退出为空；组先按来源需求身份稳定编码升序，再按关系稳定编码升序，关系稳定编码全组唯一且排序无重复。组允许 `0` 项。

公开函数的成功后置条件另行绑定请求：`结果.任务 == 请求.任务`，且`结果.结果头.事实截止代次 == 结果.本次正式读回截止 == 请求.请求头.期望事实代次 == G0`。服务和专项必须显式断言这些等式，不得把请求或 G0 捕获进无参数成员谓词。

该入口只读取 G0 当前活动的显式 T→D 关系，不补查询锚点成员、不返回历史退出关系，也不得从需求身份组伪造关系事实。读前和读后当前事实代次都必须等于 G0，否则返回公共`事实代次漂移=10`、无效任务、空组和截止 `0`。

状态矩阵固定为：`已读取=3`是唯一成功，`0/N` 项均合法；坏专属版本、共同头、G0 或任务为`入口拒绝=5`；底层许可拒绝为`许可拒绝=6`；任务从未存在为`未找到=7`；任务在 G0 前已退出为`已退出=8`；读前或读后代次不等为`事实代次漂移=10`；错任务、坏需求、重复关系身份、排序/生命周期/混代冲突为`引用冲突=12`；`std::bad_alloc`为`资源失败=13`；其它异常或底层返回/载荷矛盾为`内部不一致=14`。全部非成功只保留固定合同版本和对应公共结果头，结果任务无效、组空、截止 `0`。这是只读入口，重复调用仍返回`已读取`，不使用`精确重复`。

本计划已对当前源码做全仓精确字面冲突复核，冻结未占用本地键：


## 7. 手段模型：候选方法、任务方法路径、当前实例方法

任务的“手段”严格分成三层：

```text
候选方法
    ↓
任务方法路径
    ↓
当前选中路径 / 当前实例方法
```

### 7.1 候选方法

候选方法只表示：

```text
根据当前目标和事实召回到的可能能力
```

候选不证明：

```text
条件已闭合
输入已闭合
参数已绑定
动作入口可用
验证合同完整
当前可执行
```

### 7.2 任务方法路径

任务方法路径表示：

> **某个任务在执行前选择成功时，基于某个筹办轮次的发现和 fresh 读回，为达成当前显式关联需求互证出的单一目标而形成的一条具体已选方案。**

一个任务允许：

```text
0..N 条当前方法路径
```

同一筹办轮次允许：

```text
0..N 条发现候选；它们是值式消息材料，不是任务方法路径
```

路径集合变化不得改变任务身份。

### 7.3 当前选中路径

任务当前：

```text
当前选中路径 = 0..1
```

合法空可能表示：

```text
尚未筹办
筹办未闭合
没有可达路径
等待输入
等待条件
等待子需求回流
需要重新筹办
```

合法空本身不等于任务失败。

### 7.4 当前实例方法

任务当前：

```text
当前实例方法 = 0..1
```

一次执行只能运行一个实例方法。

禁止：

```text
多条路径同时成为当前选中路径
同一执行轮次同时运行多个实例方法
```

## 8. 任务方法路径最小结构合同

### 8.1 路径必须能够回读

每条任务方法路径至少必须能够回到：

```text
任务
筹办轮次
来源方法
方法内容版本
条件绑定
输入绑定
参数绑定
动作入口
预期结果
验证合同
归因合同
路径当前性
生命周期
```

如为组合方法，还应能够回读：

```text
子方法组成
步骤顺序
终止条件
```

普通确定步骤仍属于方法 / 路径内部，不自动形成需求。

### 8.2 路径不是抽象方法

```text
L2任务方法路径身份
    != 抽象方法身份
```

同一个抽象方法可以在：

```text
不同任务
不同筹办轮次
不同输入
不同参数
不同条件
```

下形成不同任务方法路径。

### 8.3 路径结构服务不做业务评分

L2路径结构只负责：

```text
身份
强引用
结构完整
生命周期
当前 / 历史
幂等
事实代次
```

它不负责判断：

```text
该路径是否真的能达成目标
哪个路径最好
哪个路径风险最低
应该选哪一条
```

这些属于 DATA 外任务筹办 / 执行前方法选择业务。

## 9. 当前选中路径与换代

### 9.1 当前关系

一个任务当前最多一条选中路径。

发布当前选中路径时必须做到：

```text
旧当前选中关系退出（如有）
+
新当前选中关系建立
=
同代原子发布
```

### 9.2 换代历史

新一轮筹办可以：

```text
再次选择相同抽象方法
再次选择历史上曾使用的路径语义
```

但不得覆盖旧历史。

必须保留：

```text
旧筹办轮次
旧路径
旧当前选择
旧实例方法
旧结果
旧验证 / 归因材料
```

### 9.3 结构选择与业务选择分账

`发布当前选中路径` 是结构写入口。

调用方必须已经在 DATA 外完成：

```text
评分
比较
风险 / 禁止项裁决
选择
```

L2不得：

```text
自动选择第一条
自动选择最新一条
按名称选择
按稳定编码大小选择
把稳定排序误当业务优先级
```

## 10. 实例方法

### 10.1 定位

实例方法是：

> **当前任务、本轮执行、当前选中路径的一份不可变执行快照。**

### 10.2 最小回读内容

当前实例必须能够回到：

```text
任务
当前选中路径
来源方法
来源方法内容版本
筹办轮次
执行轮次
冻结输入
冻结参数
冻结条件
动作入口
预期结果
验证合同
归因合同
实例生命周期
```

### 10.3 不可变原则

实例方法形成后，其本轮冻结内容不得原地修改。

输入、参数、条件或方法版本发生会影响执行语义的变化时：

```text
旧实例退出当前
保留历史
重新筹办 / 重新实例化
形成新实例
```

### 10.4 所有权边界

实例方法结构由方法 / 运行实例正式合同拥有。

4260 只冻结任务侧必须具备的关联和读取要求，不因此把实例方法所有权并入 `L2任务结构服务`。

## 11. 任务正式存在与兼容引用

### 11.1 一任务一正式存在

每个新任务必须引用唯一任务专属正式存在：

```text
任务 T -> 正式 L2存在身份 E
```

一个当前新任务恰一条当前 `T→E`；E 不得被多个任务共享。E 由唯一 `L2存在结构服务`建立和读回，task owner 只保存关系。

### 11.2 兼容引用不是第二存在

`L2任务虚拟存在身份`保留为迁移期强类型兼容投影。新任务可包装 E 的同一稳定编码，但该类型不等于 `L2存在身份`，不存在隐式转换，也不证明存在资格。旧历史私有节点保留历史，不得追认或复制成 E。合法世界存在消费必须读取正式 `T→E` 和 E 的存在身份来源。

### 11.3 状态承载

任务运行状态的业务解释挂载到正式 E；结构事实由 ARCH-L2 特征、状态和动态服务唯一承载。task owner 不拥有第二存在 / 特征 / 状态 / 动态写入口。

至少包括这些状态族：

```text
当前阶段 / 业务状态段
筹办轮次
筹办占用 / 当前性
候选形成状态
路径形成状态
当前选择状态
实例方法状态
等待状态
输入闭合状态
条件状态
执行冻结状态
执行轮次
执行状态
实际结果状态
目标达成状态
验证状态
归因状态
重新筹办状态
完成 / 失败 / 取消状态
```

精确特征和值域由后继任务状态规范冻结。

禁止为了方便把这些运行状态摊平到 `L2任务事实` 的普通 bool / I64 字段。

## 12. 需求树是唯一目标分解树

### 12.1 不建立第二任务树

本版固定：

```text
需求树
=
目标分解的唯一权威树
```

不持久化：

```text
任务父子关系
任务子任务关系
父任务字段
子任务字段
第二套任务树
```

允许持久化的只有轮次级调用边：同一子任务轮次 `0..1` 条发起调用；同一上级任务轮次调用槽 `0..1` 条当前调用。调用边不参与任务查询锚点、`T→D` 来源组或需求树遍历。

### 12.2 独立子目标流程

self 依据正式任务材料 fresh 确认某个目标独立、必要、父域合法、严格缩小祖先范围且具有明确并最终可判定的自身目标状态合同时：

```text
父需求任务
-> 形成正式任务子目标承接记录
-> 需求业务消费记录
-> 建立或复用合法子需求并进入需求树
-> 子需求进入 / 复用需求列表项
-> 以具体子需求承接 / 复用子目标任务
-> 若本次确由当前任务轮次发起，则在子任务轮次执行前建立唯一轮次级发起调用
```

目标分解仍只从需求树读取；任务之间的实际调用来源只从轮次级发起调用事实读取。不得从需求树、具体需求承接关系、查询锚点、队列或线程缓存反推调用来源。

### 12.3 什么才是独立子目标

只有同时满足：

```text
具有独立目标三元组
+
正式任务材料能够定位该目标，且 self fresh 确认其独立、必要、父域合法并严格缩小祖先尚未闭合范围
+
能够独立筹办并由自身目标状态合同独立验证
```

的前置目标，才进入需求树。

普通方法步骤：

```text
留在方法 / 路径 / 实例内部
```

### 12.4 替代方法不是子需求

同一目标存在：

```text
P1
P2
P3
```

时：

```text
需求树不变化
```

替代方法路径属于任务手段，不属于目标分解。

### 12.5 轮次级发起调用事实

专属合同版本固定为 `1`，共同 L2 请求头沿用现行版本。强类型身份固定为：

```cpp
struct L2任务轮次发起调用身份 { 稳定编码 值; };
struct L2任务上级调用槽身份 { 稳定编码 值; };
struct L2任务调用结果验证合同身份 { 稳定编码 值; };
struct L2任务轮次调用返回身份 { 稳定编码 值; };
struct L2任务轮次调用槽结算身份 { 稳定编码 值; };
```

`L2任务轮次发起调用事实_v1` 的物理字段顺序固定为：

```text
身份
上级任务
上级任务轮次
上级调用槽
子任务
子任务轮次
结果验证合同
调用建立截止
生命周期
```

建立请求的物理字段顺序固定为：专属合同版本、L2结构请求头、L2结构幂等身份、上级任务、上级任务轮次、上级调用槽、子任务、子任务轮次、结果验证合同、正式发生时间、规则版本。只有在上级任务轮次和调用槽当前有效、子任务及子任务轮次已经正式建立且尚无发起调用时才可写入。

唯一约束固定为：同一子任务轮次最多一条生效发起调用；同一上级任务轮次的同一调用槽最多一条生效调用。根任务轮次显式允许零条，不建立空调用、虚拟父任务或默认槽。`T→D`、需求树父子、同类任务查询锚点和任务创建者线程都不能补造该事实。

公开入口固定为：

```cpp
L2建立任务轮次发起调用结果_v1 建立任务轮次发起调用_v1(
    const L2建立任务轮次发起调用请求_v1&) noexcept;

L2读取任务轮次发起调用结果_v1 读取任务轮次发起调用_v1(
    const L2读取任务轮次发起调用请求_v1&) const noexcept;

L2按子任务轮次读取发起调用结果_v1 按子任务轮次读取发起调用_v1(
    const L2按子任务轮次读取发起调用请求_v1&) const noexcept;
```

按子任务轮次读取对 `0 / 1 / >1` 分别返回`未找到 / 已读取 / 引用冲突`；成功必须返回完整事实且正式读回截止等于请求 G0。所有非成功空载荷、截止 0。

### 12.6 调用返回与上级调用槽结算

`L2任务轮次调用返回事实_v1` 的字段顺序固定为：身份、发起调用、子任务实际结果、规范有序状态引用组、规范有序动态引用组、返回截止、生命周期。`L2任务轮次调用槽结算事实_v1` 的字段顺序固定为：身份、发起调用、调用返回、上级任务、上级任务轮次、上级调用槽、结算截止、生命周期。

固定流程为：子任务发布并独立读回正式状态、动态和任务实际结果；收束自己的任务轮次；按子任务轮次读取发起调用；恰一条时按结果验证合同验证引用闭合，发布或精确重放调用返回；随后由 task owner 在上级任务轮次仍为调用所绑定轮次且调用槽仍有效时，幂等发布调用槽结算。调用槽结算只表示结果已经返回，不写上级目标满足、需求满足或下一阶段决定。

公开入口固定为：

```cpp
L2发布任务轮次调用返回结果_v1 发布或读取任务轮次调用返回_v1(
    const L2发布任务轮次调用返回请求_v1&) noexcept;

L2读取任务轮次调用返回结果_v1 读取任务轮次调用返回_v1(
    const L2读取任务轮次调用返回请求_v1&) const noexcept;

L2结算任务轮次上级调用槽结果_v1 结算或读取任务轮次上级调用槽_v1(
    const L2结算任务轮次上级调用槽请求_v1&) noexcept;

L2读取任务轮次调用槽结算结果_v1 读取任务轮次调用槽结算_v1(
    const L2读取任务轮次调用槽结算请求_v1&) const noexcept;
```

写状态共同覆盖：`已发布、精确重复、入口拒绝、许可拒绝、当前性漂移、调用失效、引用冲突、幂等冲突、资源失败、内部错误、已可能发布`。同调用身份同完整返回为精确重复；同调用身份任一字段不同为幂等冲突。上级取消、换轮或槽失效后的迟到返回不得改写当前上级任务，只返回调用失效 / 当前性漂移。已确认子任务结果的交付失败只重试返回和槽结算，不得重做子任务动作。

上级收到调用槽结算后，必须冻结新的事实截止，fresh 读取自己的目标状态合同、目标涉及的当前特征值完整投影或方法条件。子任务结果、状态记录和动态后状态只能作为来源 / 变化证据；历史返回不得替代当前特征值。其它关联或受益任务不由本入口枚举、唤醒或结算。

## 13. 唯一所有权与身份来源

本节吸收 v0.1 中仍与当前模型兼容的 DATA 工程门禁。

### 13.1 任务结构 owner

`L2任务结构服务` 是任务核心结构唯一公开 owner。

DTO 物理位置应继续遵守当前项目已冻结的 L2 结构数据文件 / 模块组织，不建立：

```text
第二任务结构服务
第二任务事实仓
兼容任务 owner
自我任务 owner
legacy 任务 owner
```

任务 owner 只拥有本规范赋予的任务核心结构职责。

方法路径、实例方法、执行冻结、结果、结算等后继结构按其正式合同拥有，不因引用任务而反向并入任务核心 owner。

### 13.2 任务族身份证明

任务 owner 必须保持唯一正式任务族来源登记。

公开 `L2任务身份` 必须能够由权威结构共同证明：

```text
精确任务 owner
+
公开任务节点
+
精确任务族归属证明
+
精确任务族关系类型
+
任务公开服务读回
```

不得仅凭：

```text
稳定编码
强类型包装
节点名称
本地键
节点形状
属性数量
关系数量
缓存位置
legacy 投影
```

证明任务身份。

### 13.3 owner 私有结构元数据

若现行 L2 技术底座以族锚点和关系类型证明节点族身份，则必须复用该机制。

任务 owner 的：

```text
族锚点
族归属关系类型
与当前模型相关的私有结构关系类型
```

均属于 owner 私有结构元数据，不是普通业务任务，不得由普通任务读取入口返回为任务。

具体关系类型身份和数值必须服从 4230、4250、5200—5340 及当前正式 C++ ABI。

本规范不得臆造第二套编号。

### 13.4 `读取任务身份来源`

必须公开：

```text
读取任务身份来源
```

当前读取至少应在同一 owner-aware 一致投影中证明：

```text
任务 owner
任务节点
任务族来源
任务族归属
任务生命周期
```

历史读取必须使用具名历史截止。

身份来源读取的当前 / 历史语义固定保持：

```text
当前任务仍有效
    -> 已读取 + 正式身份来源

当前任务已经退出
    -> 已退出 + 空当前载荷
    -> 不得偷偷补读历史来“证明仍是任务”

历史截止早于任务创建
    -> 未找到

历史截止达到任务创建之后
    -> 已读取 + 该截止下的历史身份来源

任务已经在历史截止前退出
    -> 历史入口仍可读出该截止下完整生命周期
```

对于：

```text
wrong-family
同 owner 内部锚点
关系类型节点
legacy 普通节点
裸 L1 普通节点
```

不得因为稳定编码可解析就冒充正式任务身份。

身份来源重复、错 owner、错锚点、错关系类型、混代等属于：

```text
内部不一致
```

## 15. `新增任务`

### 15.1 请求

请求至少包含：

```text
L2结构请求头
L2结构幂等身份
L2需求列表项身份 同类任务查询锚点
L2需求身份 首个来源需求
L2存在身份 任务专属正式存在
```

如当前共同结构合同要求：

```text
期望事实代次
合同版本
调用许可
```

则必须沿用共同请求头，不得在 4260 建立第二套字段。这里的调用许可只证明结构写调用方可以使用该 DATA 接口，不是业务上的自我现实执行授权。

### 15.2 写前结构校验

L2只校验：

```text
同类任务查询锚点身份合法
首个来源需求当前结构可读且当前属于该锚点
来源需求核心合同与锚点聚合键逐字段相同
正式存在经存在公开面证明当前且未被其它任务占用
同一查询锚点当前不存在第二个任务
请求结构完整
owner 合法
幂等合法
期望事实代次合法
```

L2不判断：

```text
列表项其它成员是否存在
目标是否合理
目标是否已满足
是否值得任务化
权重是否足够
自我现实执行授权是否允许本次现实改变
当前是否应该创建任务
```

这些属于 DATA 外任务业务。

### 15.3 原子形成

成功必须一笔 owner-scoped 写集原子形成：

```text
任务节点
任务族归属证明
任务 -> 同类任务查询锚点
任务 -> 首个具体来源需求
任务 -> 正式存在 E
首个任务轮次 R1、R1 -> T、T -> 当前 R1
任务事实中的 E 稳定编码兼容投影
```

不得出现：

```text
先建裸任务
以后再补查询锚点
以后再补首个具体来源需求
以后再补正式 T→E 或 R1
```

的半结构状态。

成功时：

```text
当前方法路径组 = 空
当前选中路径 = 空
当前实例方法 = 空
```

### 15.4 不允许旧字段回流

新增任务请求不得重新加入：

```text
治理存在
目标宿主
目标特征
目标状态合同
运行场景
来源需求组副本
父任务
任务父子顺序
```

这些均属于旧模型或由列表项 / 后继冻结材料承接。

### 15.5 失败分账

应沿用共同 `L2结构状态`，至少严格区分：

```text
入口拒绝
未找到 / 引用无效
已退出
引用冲突
幂等冲突
事实代次漂移
许可拒绝
资源失败
内部不一致
```

不得压成：

```text
false
nullptr
创建失败
未知错误
```


## 18. 读取任务正式存在与兼容投影

新任务的权威读取返回任务、唯一正式 `T→E` 关系和 E 的存在身份来源，并保证三者在同一读取截止互证。一个当前新任务为 0 条或多于 1 条当前 `T→E` 都是内部不一致；不得从兼容字段、普通稳定编码或旧私有节点猜测 E。

旧 `读取任务虚拟存在` 只保留历史 ABI。对新任务，它只能在正式 `T→E` 已完整读回后形成 `L2任务虚拟存在身份{E.值}` 的值式兼容投影，不得要求 E 由 task owner 写入，也不得把该投影隐式转换回 `L2存在身份`。合法消费者需要世界存在资格时必须消费正式 `T→E` 和存在公开读回。

## 19. `退出任务`

### 19.1 定位

L2退出只表示：

```text
任务核心结构永久退出当前态
```

不表示：

```text
任务成功
任务失败
目标满足
目标不再需要
来源需求已退出
列表项已退役
```

业务层必须先完成退出资格裁决。

### 19.2 核心自有结构闭合

成功退出必须同代闭合任务核心 owner 自有的当前结构，包括：

```text
任务节点
任务族归属证明
任务 -> 同类任务查询锚点
任务 -> 当前来源需求关系组
任务 -> 正式存在 E
任务 -> 当前任务轮次
task owner 自有 P1 首轮筹办锚点
```

历史仍可读。E 的退出属于存在 owner，任务退出不得隐式退出 E；只有全部外部引用解除并经存在业务资格裁决后，才由独立后继请求存在 owner 退出。

### 19.3 后继强引用保护

若当前仍存在由正式后继合同管理的强引用，例如：

```text
当前任务方法路径
当前选中路径
当前实例方法
执行冻结
未闭合工作项
结果 / 验证 / 归因强引用
结算强引用
```

则：

```text
不得由任务核心退出入口隐式级联删除
不得反向 import 全部消费者自行修改
```

应由：

```text
后继结构合同
+
L1 当前引用闭包
```

共同阻止非法退出，或要求业务层先按对应合同闭合引用。

### 19.4 禁止隐式业务动作

退出任务不得自动：

```text
退出需求列表项
退出列表成员需求
生成需求
取消方法
结算任务
改写目标状态
```

## 29. `按具体需求承接或复用任务`

固定流程：

```text
读取具体需求 D 及其当前成员关系
-> 取得 D 所属列表项 L
-> 复核 D 当前性与目标完整性
-> 按同类任务查询锚点 L 查询 0..1 个当前任务 T
-> 0 项：存在 owner 先建立任务专属 E；task owner 再原子建立 T + T→L + T→D + T→E + R1
-> 1 项：复核 T 当前、查询锚点相同、至少一项既有来源目标与 D 完全相同
-> 幂等建立 T→D；已存在同关系返回精确重复
-> >1 项：内部不一致
-> 正式读回 T、身份来源、R1、T→D、T→E 和 E 身份来源
```

业务层可以判断：

```text

当前没有活动资格
当前无需建立任务
```

L2结构服务不得把这些判断塞进 `新增任务`。

## 30. `筹办任务`

任务管理线程只生成并派发不可变筹办工作包；任务工作线程消费工作包、调用筹办 provider，并在每次处理结束时形成一个强类型筹办结果消息返回任务管理线程。现有任务工作线程按强类型判别联合承接筹办工作包和执行工作包，不新增专用筹办线程。任务管理线程不得直接同步调用筹办 provider，不得用内部槽或轮询结果替代消息消费。

筹办结果消息只携带不可变交接材料和正式事实定位，不建立 DATA / ARCH-L4 新节点、第二结果账或持久化筹办回执。消息至少绑定任务、任务轮次、筹办轮次、来源工作包、来源事实截止、结果事实截止和唯一分支；任务管理线程必须独立读回分支引用的任务 owner 正式事实后才可推进。

任务信息补全到执行前选择的固定流程：

```text
读取任务
-> 按任务读取当前来源需求关系组
-> 逐项读取显式关联具体需求
-> 校验至少一项当前有效需求，且目标三元组完全相同
-> 形成单目标投影
-> 读取正式 T→E 和 E 上任务阶段特征 / 状态
-> manager 按状态派发找方法工作，task owner 累计候选与覆盖范围
-> 方法范围完整后，manager 按状态派发查条件工作，task owner 累计逐候选条件组与核验结果
-> manager 独立读回全部任务信息并推进到待执行前选择
-> 执行前 fresh 复核适用性、当前可用性、安全硬门和正式成本
-> 从可比较候选中选择综合代价最小的 0..1 项
-> task owner 形成一条当前路径、当前实例方法和执行冻结
-> 冻结本轮实际消费的来源需求关系、需求版本和规则版本
-> 经 ARCH-L4 provider 提交 E 上状态 / 动态变化
```

若当前来源需求关系组为空，或全部关联需求均已失活 / 退出，筹办不得改从查询锚点或列表成员补目标；manager 必须保持当前业务状态并交目标治理链重新判定。通用授权安全事实、授权安全 provider 和“授权材料缺失等待”均不是筹办输入。

筹办每次处理只形成当前找方法或查条件步骤的阶段性信息补全结果。路径、选择、实例、冻结、目标已完成、子目标承接和技术非成功均不得冒充筹办业务出口。

不得为了让任务“有路可走”而伪造路径。

### 30.1 状态驱动的筹办工作包与独立读回

旧“五分支、单次纯发现、筹办形成路径 / 选择 / 冻结”和新建后继工作包类型全部退出。当前只复用一类既有筹办工作包，以强类型步骤区分`找方法`和`查条件`；工作包绑定任务、任务身份来源、来源需求、任务 / 筹办轮次、调用前状态、任务信息版本、G0、运行代次、幂等身份和本次范围，禁止 optional 拼盘。

task owner 的筹办信息是唯一正式承载：找方法步骤保存方法身份 / 内容版本和覆盖范围；查条件步骤保存逐方法条件组、核验结果和覆盖范围。它不建立候选账、条件账、结果账或 outbox。工作线程每次只发送一条不可变结果消息；manager 独立读回并校验当前状态、版本和范围后，经任务状态正式入口迁移，再决定下一次派发或进入执行前选择。

技术非成功保持原业务状态：资源 / 投递 / 发布未知按原键收敛，截止漂移在同一子状态重派，ABI / 引用 / 断言 / 内部错误停止调用。方法 / 条件缺失才是业务材料，但不直接建立需求；只有 self 确认后才能进入正式子目标承接链。

## 31. 路径选择原则

任务业务可以依据：

```text
目标匹配程度
条件完整性
输入可得性
动作可用性
风险 / 禁止项
成本
时效
历史成功证据
当前环境
显式关联需求的当前优先级输入
预算
```

选择路径。

但必须保持：

```text
可达
≠ 当前选中
≠ 正在执行
≠ 已成功
```

路径选择规则必须在 DATA 外保持可审计。

如使用显式关联需求的优先级或预算输入，必须记录：

```text
实际参与来源需求与关系明细
规则版本
共同事实截止
```

### 31.1 C031 执行前选择和单次原子发布

选择入口不是筹办 provider 的后置 helper。它取得独立的执行前选择工作项后，以 fresh 共同截止读取发现所定位的每个执行选项：`方法 + 内容版本 + 条件组 + 输入 / 参数绑定 + 动作范围`。先硬过滤目标 / 结果合同、方法版本 / 生命周期 / 动作入口、该选项自身条件组、输入 / 参数、范围、验证 / 归因、结构拒绝、禁止项、安全硬否决和生存安全根控制态；过滤失败不产生路径或选择记录。

只对剩余可比较选项使用第 31 节的分层原则。服务根当前值、服务合同 / 余额、预期服务收益、线程数、队列长度和未经正式定义单位 / 范围的时间不能进入自动比较。未知、不可比或并列最优返回具名待裁决定位，零选择、零冻结；不得按候选容器顺序、编码或哈希任选。

成功时由既有 task owner 组合入口一次性发布选择记录、具体任务方法路径、派生当前路径、实例方法和执行冻结，并以同一截止读回所有必需关系。选择记录绑定的条件来源是所选条件组，而不是任务级合并条件；任一绑定事实变化令整组失效。未选发现项不持久化为第二选择记录，也不被当作已拒绝或删除。

## 32. `提交任务子目标`

当 self 依据正式任务材料 fresh 确认：

```text
存在一个独立、必要、父域合法、严格缩小父需求及祖先尚未闭合范围，并具有明确且最终可判定自身目标状态合同的子目标
```

时：

```text
task owner 形成正式任务子目标承接记录；当前可执行路径、实例方法和执行冻结允许为空
-> task owner 将记录身份和精确 T→D_parent 定位发送给任务管理线程
-> 任务管理线程独立读回记录并编排需求业务消费
-> 需求 owner 建立或复用合法子需求
-> 进入需求树；子需求回流后以新事实截止重新筹办
```

任务不得：

```text
直接写需求树
直接建立子需求
直接建立任务父子关系
```

正式任务子目标承接记录至少应能回到：

```text
来源任务
来源任务轮次、相关筹办轮次与 self 确认来源；存在时可引用相关方法 / 条件材料
父需求语境
子目标
缺口 / 前置原因
回流条件
```

正式任务子目标承接记录及需求业务消费合同以 4250 及其后继合同为准。

子目标承接记录不是路径状态或执行权。它只证明 self 已确认的独立必要后继目标已由 task owner 记录，不得被任务管理线程直接复活为当前路径或执行冻结。

### 32.1 C031 自我确认后的既有承接记录

任务筹办不能调用本入口。只有 self 收到 manager 独立读回后的具名任务材料并 fresh 确认独立目标必要、父域合法、目标合同可最终判定后，task owner 才可发布或精确重放既有任务子目标承接记录。

该记录新增 / 重构为`自我确认来源`强类型联合，至少区别已确认条件目标、合法学习目标和其它后续正式冻结类别；方法 / 条件缺口、普通候选、消息文本和布尔门不得伪装成该来源。记录仍是需求领域服务的唯一运行期输入，manager 不能直接建立需求或子任务。它不产生路径、实例、选择或冻结，且旧筹办消息 / 记录不得被复活为执行权。

## 33. `执行任务`

执行前必须至少证明：

```text
当前实例方法存在
实例仍当前
当前选中路径仍当前
任务轮次 / 筹办轮次 / 执行轮次互证
执行冻结仍有效
正式 E 的任务阶段状态允许执行
本轮冻结材料仍可接受
全局控制态允许派发
冻结后形成的正常调度资格允许派发
没有当前安全硬否决
冻结仅含内部治理或无现实副作用的纯现实观察；或者，含现实改变时已经独立读回本冻结唯一自我现实执行授权
具体方法声明的技术能力 / 受保护资源访问许可已满足（适用时；它不是第二业务授权）
```

内部治理相当于“想”，不请求业务授权。纯现实观察只有在不主动探测、不驱动设备、不发射、不对外通信、不写外部系统且无其它现实副作用时，才可不请求业务授权直接执行；混合方法必须逐动作声明现实副作用，只要含现实改变步骤，就必须在筹办 / 冻结完成后、任务进入执行阶段前完成授权门禁。

唯一正向授权由自我业务 owner 的正式领域入口发布，同时绑定任务、任务轮次、筹办轮次、执行轮次、执行冻结、实例方法、现实动作范围、事实截止、授权规则版本和有效期。它同时覆盖本执行尝试和实例方法中的冻结现实动作，不再建立任务授权与方法授权两份事实。拒绝、等待、撤回和安全硬否决不是正向授权；安全服务只提供事实、调度材料和硬否决，不得成为第二正向授权者。

执行：

```text
实例方法
-> 动作
-> 独立事实回读
-> 实际结果
-> 验证 / 归因材料
-> 经 ARCH-L4 provider 提交 E 上状态 / 动态变化
```

方法返回：

```text
success
```

只能证明：

```text
方法调用 / 动作执行合同层面的成功
```

不得直接写：

```text
任务轮次结算完成
需求满足
目标达成
正式结算成功
```

## 34. `验证任务目标`

固定流程：

```text
任务
-> 当前任务来源需求关系组
-> 至少一项当前有效具体需求
-> 逐项目标互证形成单目标投影

同截止当前特征值完整投影
-> 正式比较 / 判断收束

=
本次目标验证结论
```

验证必须使用：

```text
同截止当前特征值完整投影
```

不得使用：

```text
实例方法返回值
任务状态缓存
上次验证结论
预测值
目标副本
```

替代当前特征值。状态记录、动态后状态、状态当前选择和任务结果同样不得替代。

一次世界事实比较结果可以被同一任务的多个显式关联需求消费，但各需求仍各自保有：

```text
业务有效性
路径
结算身份
来源
```

仍独立。

目标验证只形成本任务轮次的`已达成 / 未达成 / 不可比较 / 材料不足 / 其它具名结果`。它不决定任务是否继续，也不直接建立需求正式结算记录。

## 35. 同一任务轮次筹办重判与轮次收束后继续

同一任务轮次尚未形成正式实际结果、尚未进入结算且尚未收束时，新筹办轮次的触发可以包括：

```text
当前路径失效
当前实例方法失效
条件变化
输入变化
显式关联需求当前性、优先级或预算输入变化
子需求回流
外部事实变化
当前冻结过期
```

重新筹办必须：

```text
保留旧路径历史
保留旧实例历史
保留旧执行 / 验证 / 归因材料
形成新筹办轮次
重新读取当前来源需求关系组及其当前需求事实
重新生成路径集合
重新选择
重新实例化
```

禁止：

```text
覆盖前轮路径
覆盖前轮实例
修改旧冻结
```

正式实际结果一旦形成，任务必须进入结算阶段；目标未达成、执行结果要求换路或结果材料不足都只形成本轮结论，不得在同一任务轮次直接重筹办。任务结果不是容量或分配对象；正式结果及本轮停止 / 阶段收口材料完整后即可收束本任务轮次，不等待全部 `T→D` 或其它受益任务核算。

本轮收束后按子任务轮次读取 `0..1` 条发起调用：零条按根任务轮次收口；一条时发布 / 重放调用返回并幂等结算唯一上级调用槽；多条为引用冲突。上级收到返回后仍须 fresh 验证自己的目标或方法条件，禁止把子任务成功或调用槽已返回写成上级目标完成。

任务轮次结算完成后进入`轮次已收束`并等待自我后继决议。只有`继续`决议经任务管理复核后，才建立新任务轮次和首个筹办轮次；`结束 / 等待 / 取消`分别按其正式合同收口。旧路径、实例、执行冻结和自我现实执行授权不得跨任务轮次复用。

## 36. 调度、安全硬否决与现实执行授权边界

### 36.1 删除通用授权安全前置事实

任务筹办与执行冻结不得读取或等待以下通用事实：

```text
来源需求授权事实
安全图事实
安全阈值事实
调度规则事实
适用性分类规则事实
```

也不得建立对应 provider 或“授权材料缺失等待”。这些旧 Stage C 格式只保留历史只读资格，不参与当前路径、实例或冻结裁决。

### 36.2 来源需求投影必须可审计

优先级和预算输入只能从任务显式关联的当前需求及其正式业务规则形成。若业务层形成投影，必须同时保留：

```text
来源需求关系与需求身份明细
投影值
规则版本
共同事实截止
```

不得从列表项全部成员、任务永久单值或不可追溯聚合值取得，也不得把查询锚点升级为目标来源、调度来源或授权来源。

### 36.3 调度配额 / 倍率只形成冻结后的正常调度资格

6150 定义的安全调度倍率只在执行冻结完成后、真实派发前形成安全任务类内部的正常调度优先级投影。服务根当前值、时间经过和普通服务结果不产生任务调度资格：

```text
执行冻结完成
-> 读取当前调度投影输入
-> 形成正常调度资格 / 优先级
-> 结合独立全局控制态
-> 允许派发 / 不派发
```

调度配额 / 倍率为零不得阻断任务承接、筹办、路径选择、实例形成或执行冻结，只排除本次普通排序。全局控制态和安全硬否决是独立门控，不伪装成需求授权、自我现实执行授权或方法适用性事实。

### 36.4 技术许可不是第二业务授权

具体方法涉及受保护资源或受限技术能力时，可以声明技术能力 / 访问许可条件。该条件只证明调用能力或资源访问合法，不承担“是否要做”的业务裁决，不扩张为所有任务共有的授权安全材料，也不得与自我现实执行授权合并。

### 36.5 一份自我现实执行授权与安全硬否决

执行冻结完成后读取方法作用范围。仅内部治理或无现实副作用的纯观察不请求授权；含现实改变步骤时，在任务进入执行阶段前请求并独立读回一份自我现实执行授权，不得先执行混合方法中的观察前缀。冻结、实例方法、动作范围、事实截止、规则版本或有效期变化时旧授权失效；冻结变化必然使授权失效，授权失效不必然撤销冻结。

安全硬否决可以阻止已授权的现实动作，自我授权不得绕过；安全事实、调度材料和硬否决都不是第二正向授权。

排队、调度或执行选择实际使用的来源需求投影、调度投影、全局控制态、安全硬否决、适用的技术许可和自我现实执行授权定位必须进入本轮派发材料；后续变化只影响后续新裁决，不改写历史裁决。

## 37. 依赖方向

本节吸收 v0.1 的单向依赖原则，并按 v0.5 新模型更新。

### 37.1 任务核心结构依赖

基础任务核心结构只允许依赖：

```text
L2任务结构
    -> L2需求结构公开读取
        - 验证同类任务查询锚点身份
        - 读取具体来源需求及其当前成员关系

L2任务结构
    -> L1事实基座
```

如强类型共同身份来源位于公共 L2 结构层，可按正式共同合同读取。

禁止基础任务核心结构直接依赖：

```text
方法业务服务
动态业务服务
因果业务服务
安全治理服务
外设业务服务
任务执行器业务
需求结构写入口
```

### 37.2 路径结构依赖

任务方法路径结构可以单向依赖：

```text
任务路径结构
    -> L2任务结构公开读取
    -> 方法结构 / 方法版本公开读取
    -> 条件 / 输入 / 参数 / 动作 / 验证 / 归因相关正式结构
    -> L1事实基座
```

具体依赖由 5200—5250、5300—5340 后继规范冻结。

不得为了方便把这些依赖反塞回基础 `L2任务结构服务`。

### 37.3 实例方法依赖

实例方法结构单向依赖：

```text
实例方法结构
    -> 任务方法路径结构
    -> 任务结构
    -> 方法内容版本
    -> 执行冻结所需正式结构
```

### 37.4 子需求回流

self 依据正式任务材料确认该目标独立必要、严格缩小祖先范围且具有明确并最终可判定的自身目标状态合同时：

```text
任务业务
-> 发布正式任务子目标承接记录
-> 需求业务消费记录并建立或复用子需求
```

不是：

```text
L2任务结构服务
-> L2需求结构写入口
```

基础 L2任务结构与需求结构保持无反向写入耦合。

## 38. 共同事务与原子性

### 38.1 任务创建

```text
任务
同类任务查询锚点引用
首个任务来源需求关系
任务正式存在关系
首个任务轮次 R1 及当前关系
族归属证明
```

上述 task owner 自有事实同代原子发布；E 已由存在 owner 在前段独立发布，不属于该同代。

不得有半结构。

### 38.2 路径创建

路径节点及其正式最小强引用必须由路径 owner 按其合同原子发布。

### 38.3 当前路径换代

```text
旧当前选择退出
+
新当前选择建立
```

同代原子。

### 38.4 当前实例换代

当前实例变化必须：

```text
旧当前实例退出当前关系
+
新当前实例建立
```

按实例合同原子发布，历史实例保留。

### 38.5 不跨 owner 拼大事务

任务核心、路径、实例、结果、结算如属于不同正式 owner：

```text
不得为了“一次全写完”
绕过公开服务拼跨 owner 私有写集。
```

业务层通过：

```text
公开接口
+
事实代次
+
幂等
+
正式读回
```

收敛跨结构流程。

## 39. 幂等

### 39.1 基本规则

一份请求首次取得结果后：

```text
L2结构幂等身份
+
逐字段完整请求
```

绑定。

固定：

```text
同幂等身份 + 同完整请求
    -> 精确重复
    -> 返回首次结果

同幂等身份 + 不同完整请求
    -> 幂等冲突
    -> 零变化
```

### 39.2 事实代次漂移

只有：

```text
结构化事实代次漂移
+
明确零变化
+
没有首次发布结果
```

时，调用方才可按共同合同继续收敛。

不得把：

```text
资源失败
异常
超时
发布结果未知
```

当成“肯定没写”后生成新幂等身份重试。

### 39.3 发布未知

资源失败、异常或发布结果未知时：

```text
只能用原幂等身份
+
原完整请求
```

正式读回 / 重试收敛。

不得：

```text
换新幂等身份
删字段重试
改变语义重试
先猜成功再补写
```

## 40. 事实代次、当前性与历史读取

### 40.1 写前验证

跨族写前强引用校验应使用同一期望事实代次。

校验后到本族提交期间出现权威变化时，应由 L1 / 共同结构层以：

```text
事实代次漂移
```

阻止混代提交。

### 40.2 当前组合读取

当前组合读取必须使用：

```text
owner-aware 一致当前投影
```

同一次结果中：

```text
任务
任务身份来源
需求列表项引用
任务正式存在引用和 E 身份来源
当前任务轮次
当前选择（若组合读取）
当前实例（若组合读取）
```

必须共享明确共同事实截止。

### 40.3 历史读取

历史读取必须显式：

```text
L2读取类别::历史
+
非零历史截止
```

不得拿当前关系补历史缺项。

### 40.4 错误不得折叠

当前入口应严格区分：

```text
未找到
已退出
属性未设置
许可拒绝
入口拒绝
引用冲突
事实代次漂移
资源失败
内部不一致
```

不得为了调用方便统一折叠为 bool。

## 41. 引用保护

### 41.1 基础任务核心不反向依赖全部消费者

方法路径、实例、工作项、结果、结算等结构都可能引用任务。

基础任务核心不得为了退出扫描而：

```text
import 所有后继业务服务
直达后继私有仓
直达后继锁
直达后继事务
```

### 41.2 引用闭包

引用保护由：

```text
各后继正式结构合同
+
L1 当前引用闭包
```

承接。

### 41.3 退出顺序

业务层准备永久退出任务时，应先闭合：

```text
当前实例
当前选中路径
当前路径
执行冻结 / 工作项
必要结果 / 归因 / 结算当前强引用
```

然后请求任务核心退出。

不得靠任务核心入口偷偷级联删除。

## 42. DATA 错误分账

适用于任务核心、路径、实例等正式结构入口的错误必须结构化。

至少区分：

```text
入口拒绝
未找到
已退出
引用冲突
幂等冲突
事实代次漂移
数量预算不足（若共同 ABI 已冻结）
许可拒绝
资源失败
内部不一致
```

典型归属：

```text
零身份 / 错类型强引用 / 合同版本错误
    -> 入口拒绝

引用目标不存在 / 已退出
    -> 对应正式引用读取结果

同查询锚点第二当前任务
    -> 引用冲突或本规范 / 共同合同冻结的唯一性冲突状态

同幂等身份异请求
    -> 幂等冲突

期望代次失效
    -> 事实代次漂移

L1 资源分配 / 提交资源问题
    -> 资源失败

发布后读回与已发布结构矛盾
单例出现多份
同一结果混代
身份复义
    -> 内部不一致
```

如果共同 `L2结构状态` 尚未冻结某一具名状态：

```text
4260 不得自行创建第二枚举值。
```

应先同步上级共同合同。

## 43. 施工与实际消费检查边界

本节只冻结应验证的工程事实，不声明代码已经实现。

### 43.1 任务核心最小检查

至少覆盖：

1. 合法具体需求可先建立任务专属 E，再经其所属查询锚点原子建立任务、首个 `T→D`、正式 `T→E`和 R1 并正式读回；
2. 任务、查询锚点引用、首个来源关系、正式存在关系、R1 和任务身份来源共享同一 task-owner 截止；E 另按同一组合读取截止证明存在身份来源；
3. 复用当前任务时只幂等新增具名 `T→D`，不自动吞并同列表其它成员；
4. 同一查询锚点不能形成第二当前任务；
5. `按同类任务查询锚点读取当前任务` 对 0 / 1 / >1 严格分账；
6. `按任务读取来源需求关系组` 当前结果按来源需求身份、关系身份稳定升序，无重复；空组结构读取成功但不能形成目标；
7. `L2任务虚拟存在身份` 是 ARCH-L4 迁移期兼容引用类型，不等于 `L2存在身份`、不存在隐式转换；新任务必须另有正式 `T→E` 关系证明其包装的稳定编码属于任务专属 `L2存在身份 E`；
8. 任务节点不复制目标宿主、目标特征、目标状态；
9. 任务节点不保存来源需求事实副本或列表成员集合；
10. 任务节点不保存治理存在；
11. 任务节点不保存运行场景核心引用；
12. 不存在持久任务父子树或父 / 子任务核心字段；
13. 子任务轮次发起调用严格为 0..1，同一上级轮次调用槽严格为 0..1；
14. 根任务零调用成功收口，多调用引用冲突；
15. 调用返回、正式结果、状态 / 动态引用和父子两轮次逐字段互证；
16. 同调用同义返回 / 槽结算精确重复，同键异义幂等冲突；
17. 迟到返回不改写已取消 / 换轮的上级任务；
18. 旧期望事实代次零变化失败；
19. 当前 / 历史读取不混代；
20. wrong-family、owner 私有锚点、关系类型节点、legacy / 裸 L1 节点不能冒充任务身份。

### 43.2 方法路径检查

至少覆盖：

1. 一个任务允许 0..N 当前路径；
2. 同一筹办轮次路径历史可回读；
3. 路径能回到来源方法及内容版本；
4. DATA 不自动评分或选择路径；
5. 当前选中路径最多 1 条；
6. 当前路径换代保留旧历史；
7. 已退出路径不能继续作为当前选中路径；
8. 替代路径不生成需求。

### 43.3 实例方法检查

至少覆盖：

1. 当前实例最多 1 个；
2. 实例能回到任务和当前选中路径；
3. 冻结输入 / 参数 / 条件不可原地修改；
4. 新轮次实例不覆盖旧历史；
5. 多路径不能同时执行；
6. 方法执行成功不能直接写任务轮次结算完成。

### 43.4 来源需求消费冻结与派发检查

至少覆盖：

1. 当前来源需求只从 `T→D` 当前关系组读取；
2. 列表成员变化不自动改变任务来源关系；
3. 筹办 / 调度 / 执行能记录本轮实际消费关系、需求版本和规则版本；
4. 需求后来承接 / 退出不改写历史冻结；
5. 通用授权安全事实及 provider 不参与筹办或冻结；
6. 调度配额 / 倍率为零不阻断筹办或冻结，只影响冻结后、派发前正常调度资格；
7. 全局控制态和安全硬否决独立门控；技术许可只在具体方法合同声明时检查，且不是第二业务授权；
8. 内部治理和无现实副作用的纯观察不请求授权；含现实改变时同一冻结只存在一份自我现实执行授权；
9. 正式结果形成后收束本任务轮次，不建立结果容量、共用 / 争用或消费分配，也不等待全部 `T→D`；
10. 有唯一发起调用时只结算对应上级调用槽，其它任务在使用时 fresh 复核；
11. 轮次收束后只有自我`继续`决议能够开启新任务轮次。

### 43.5 退出检查

至少覆盖：

1. 当前存在强引用时任务退出被正式阻止或要求先闭合；
2. 退出不级联删除列表项；
3. 退出不级联删除需求成员；
4. 退出后当前不可见 / 已退出，历史仍可读；
5. 发布未知用原幂等身份收敛。

### 43.6 临时检查驱动

施工临时检查不得：

```text
编译进生产目标
取得 L1 / L2 私有仓或私有锁
绕过公开接口直接造权威事实
构造“任务已完成”假业务剧本冒充闭环
```

构建成功、日志正常、未观察到错误只证明对应工程事实，不证明业务闭环完成。

## 44. 与 4250 的同步要求

4260 必须以 4250 当前需求列表模型为前提。

固定：

```text
需求树节点
    = 独立目标及其目标分解身份

需求列表项
    = 需求树派生活动视图中的同类任务查询 / 防重锚点

需求列表成员
    = 同精确目标的当前需求成员

任务
    = 按具体需求逐次承接、并显式保存 `T→D` 关系的一次活动
```

因此：

```text
一个同类任务查询锚点当前至多一个任务；一个任务可以逐次承接多个同目标具体需求
```

而不是：

```text
每个成员需求各建一个重复任务，或把列表全部成员自动并入任务
```

当前满足仍按具体需求独立结算；任务目标验证使用当前显式关联需求逐项互证出的单目标投影。

## 50. 禁止事项

禁止：

- 任务只绑定具体需求却不保存其同类任务查询锚点；
- 每个同目标成员需求重复创建任务；
- 把列表全部成员自动并入任务来源；
- 任务复制来源需求目标或从列表项聚合键取得目标；
- 任务保存第二份目标宿主、目标特征、目标状态合同；
- 任务保存来源需求事实副本或列表成员集合；
- 把显式关联需求的优先级 / 预算输入压成不可审计单值并丢失来源；
- 恢复通用授权安全事实、provider 或“授权材料缺失等待”；
- 用调度配额 / 倍率为零阻断任务承接、筹办、路径选择、实例形成或执行冻结；
- 把全局控制态伪装成来源需求授权；
- 为内部治理或无现实副作用的纯观察索要业务授权；
- 为同一执行冻结分别建立任务授权和方法授权；
- 让安全服务发布第二份正向授权，或用自我授权绕过安全硬否决；
- 把替代方法生成需求；
- 把普通方法步骤生成需求；
- 独立子目标仍只作为普通步骤而不进入需求树；
- 建立持久任务父子树；
- 恢复父任务 / 子任务核心字段，或用轮次级调用事实表达目标分解 / 永久所有权；
- 从 `T→D`、需求树、查询锚点、队列或线程缓存推导轮次发起调用；
- 仅凭稳定编码相同、兼容字段或强制类型转换把任意世界 `L2存在身份` 当任务正式存在；
- 为新任务创建 task-owner 私有存在节点，或在正式 `T→E` 之外复制第二存在权威；
- 多任务共享同一正式 E，或把兼容虚拟存在投影当成可共享的第二存在；
- 把候选方法当成可达路径；
- 把可达路径当成当前选中路径；
- 把当前选中路径直接当成已执行实例；
- 同一执行轮次运行多个实例方法；
- L2自动召回、评分或选择方法；
- L2自动生成子需求；
- L2判断任务是否完成；
- 方法成功直接写任务轮次结算完成；
- 子目标完成直接写父目标完成；
- 把调用槽已返回写成上级目标满足，或用历史子任务结果、状态记录、动态后状态替代上级 fresh 当前特征值读回；
- 把任务结果解释为容量并建立共用 / 争用、成员优先级、消费分配、剩余量或结果耗尽；
- 用上次验证缓存替代同截止当前特征值验证；
- 重新筹办覆盖旧路径、旧实例或旧结果；
- 正式实际结果形成后因目标未达成直接重筹办；
- 任务轮次收束后未取得自我`继续`决议就建立任何后继筹办工作包，或以旧`下一筹办工作包`兼容面恢复自动重筹办；
- 成员需求变化反写历史冻结；
- 从单个成员需求直接猜测唯一任务；
- 任务成员为零时由 L2自动退出任务；
- 任务退出自动退出列表项；
- 任务退出自动退出需求成员；
- 任务核心服务反向依赖所有后继消费者私有实现；
- 直达 L1 私有仓、锁、事务、材料目录或缓存重演跨族身份证明；
- 用名称、本地键、普通稳定编码或节点形状证明任务身份；
- 用编译、日志或单条成功路径宣称任务业务闭环已完成；
- 在后继 DTO 未冻结时发布万能参数、临时 ABI 或动态编号。

## 51. 完成边界

本规范正式生效只证明以下合同已经冻结：

```text
任务最新本体
任务 -> 同类任务查询锚点
任务 -> 具体来源需求正式关系
当前来源需求关系组读取与目标互证
本轮来源需求消费冻结原则
一个目标 0..N 方法路径
当前选中路径 0..1
当前实例方法 0..1
```

## 53. 首个任务轮次与正式存在迁移合同

### 53.1 新任务 task-owner 单次核心写集

新任务必须在一个 task-owner 原子写集中建立：

```text
T 与任务族归属
T→L 查询锚点
首条 T→D 正式来源关系
T→E 正式存在关系
R1、R1 族归属、R1→T 与 T→当前 R1
```

E 必须已由 `L2存在结构服务`建立并在共同写前截止完成身份来源读回。task owner 只保存引用，不创建、退出或修改 E。新任务的兼容 `L2任务虚拟存在身份` 可包装 E 的稳定编码以维持旧读 DTO，但该投影只有与正式 `T→E` 和存在身份来源联合读回时才可消费；旧历史私有虚拟存在不得被追认成 E。

### 53.2 首态、P1 和待找方法状态

task owner 核心 `G_T` 后，消费者经特征公开面取得全局任务阶段特征定义并为 E 建立唯一阶段特征实例。状态 owner 先建立并读回无动态首态`{筹办, 待初次筹办}`。task owner 随后建立 / 读回首次准备记录和 P1；P1 绑定 T、R1、轮次序号、来源截止、幂等身份与生命周期，只作首轮筹办、重试和恢复锚点。

manager fresh 读回首态与 P1 后，根据任务状态经正式状态提交入口推进到`{筹办, 待找方法}`。任务筹办是否继续完全由后继当前状态裁决，不需要额外治理函数定义、动作调用事实、证明节点、专用角色或第二来源账。状态和动态仍由其通用 owner 按各自合同保存和读回；任何发布未知必须以原请求收敛，未确认前不得进入下一状态。

### 53.3 强类型和兼容禁止

任务核心公开面必须提供 `L2任务轮次身份/事实`、`L2任务来源需求关系事实`和`L2任务正式存在关系事实`，并支持按原建立幂等身份独立读取。字符串、普通整数、列表成员集合、兼容虚拟存在字段、旧任务治理状态和调用方缓存均不得替代这三类事实。旧融合入口可以为 ABI / 专项编译保留，但新的生产消费者不得调用，也不得继续通过它创建 task-owner 私有存在。

### 53.4 初次筹办六阶段幂等身份与恢复信封

初次筹办外层请求必须携带一份强类型六阶段幂等身份组：

```text
存在建立
任务核心建立
阶段特征实例建立
首态建立
P1 建立
首迁移（分步中性目标状态、第一动态与选择替换的共同外层来源键）
```

六键必须全部非零、两两不同，并逐字段进入完整请求的相等比较和持久编码。外层`准备幂等身份`固定等于`P1 建立`键，因为首次准备记录在 G_P1 形成，既有“按准备幂等身份读取首次记录”只能继续以该键定位；`任务核心建立`键不得再作为准备键或 P1 键。全局阶段特征定义继续使用固定 `TASKSTAG` 键，不进入本六键组。

六键由业务调用方在形成原请求信封时一次性分配，并随原请求跨重试、发布未知收敛和回流重判持久传递。不得从时间、运行代次、请求身份、需求 / 任务 / 回流记录身份、哈希、算术变换或某一阶段结果临场派生其它阶段键；不同 owner 的键空间隔离也不得作为跨阶段复用同一键的理由。这里的“共同外层来源键”不把三笔中性写合并为一个幂等操作：每个既有中性 public endpoint 仍以其操作域形成独立有效幂等键、独立 G 和独立结果。

首次准备记录的完整请求材料保存外层合同版本、准备键、请求身份、运行代次、请求头、具体需求和六阶段键；删除只服务于旧任务筹办调用证明的治理函数 / 推进规则版本字段。历史记录只按其原版本只读识别，不得补造已删除字段或恢复旧调用事实。

任务子目标回流重判请求同步携带原六阶段键组。当前无任务而进入新初次筹办时，必须满足`P1 建立键 == 回流记录身份的稳定编码`，其余五键来自回流请求所承载的原请求信封。已有首次记录时，先确认历史材料是完整版本 2，再逐字段比较当前六键与历史六键；相同则以历史原完整请求重放，任一异键为`幂等冲突`。版本 1 历史记录返回`初次请求版本待迁移`且零写。

发布未知只允许消费历史首次记录中的版本 2 原完整请求和原六键按既定阶段继续收敛；未确认当前阶段前不得换键、越段或用新请求覆盖历史信封。

## ARCH-L4 业务兼容与 ARCH-L2 引用边界（20260824）

任务、方法路径、实例、冻结材料和轮次属于 ARCH-L4。现有 L2 任务服务保留兼容 ABI，只保存业务结构和引用；`L2任务虚拟存在身份`是兼容引用类型，新任务必须以正式 `T→L2存在身份 E`和存在公开读回取得通用存在，不得新建第二节点。状态、动态不得成为第二权威，必须通过 ARCH-L2 通用公开结构服务取得。DATA-L2 不判断路径成功、目标完成或方法有效；ARCH-L4 provider 负责解释业务结果后提交纯结构迁移请求。
