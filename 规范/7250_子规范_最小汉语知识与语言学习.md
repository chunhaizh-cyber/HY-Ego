## 1. 冷启动与学习目标

先天语言知识提供最小可解释的含义—形式对应，后天学习扩展表达和组织。概念知识提供“是什么”，世界与治理信息提供“发生/需要/能做什么”，语言知识提供“怎样说”；三者不能互相替代。

首批范围是有限汉语文字，不要求语音、外部分词器或大模型存在。规则先形成语言域可读知识，再由相同解释器使用；不得硬编码一套输出模板并在学习时另造不兼容知识仓。

“最简句型可穷举”只对本节明确列出的操作和构式闭集成立，不代表全部汉语、全部词或全部含义可一次列全。陌生句可保存并转入理解中的归类学习（第3.3节），不以追求覆盖率为由猜造事实。**不设独立自然语言学习模块或线程**；学习在理解服务对象原话的过程中自然完成，写入语言知识模块，不直接写入自我内部世界。

## 2. 最小种子知识集合

本节及 2.2 节的构式示例统一使用“类型代码＋规则内序号”。显示序号按类型代码分别编号：同一规则内第二个普通存在写 `E2`，再次使用同一角色仍写 `E1`；因此同一规则中的 `E1` 与 `C1` 是不同显示角色，不能把两个“1”当成同一个正式编号。发布知识时，每个不同显示角色须一一映射到 7230 规则内**唯一的局部角色编号**，重复引用同一角色则复用该正式编号。每条规则、每个子规则各有独立编号空间，跨规则共享只能通过显式角色映射；显示序号和局部角色编号都不是业务节点身份。下表代码仅标注允许绑定的材料类别，不新增世界节点类型或持久词性：

| 代码 | 绑定类别或材料 | 边界 |
| --- | --- | --- |
| `E`、`SC` | 普通存在角色、场景角色 | 场景本身也是存在；这两个代码区分本规则要求的视角，不建立场景概念族。场景以存在身份参与时须在该规则内明确允许与核验 |
| `F`、`ST`、`DY`、`RL`、`CA` | 实例特征、状态、动态、关系、因果信息 | `F` 不是特征类型、特征概念或准确值；关系信息 `RL` 也不是关系概念 |
| `D`、`T`、`M` | 需求、任务、方法对象 | 三者直接绑定正式对象或提议材料，不因示例产生对应概念族 |
| `C`、`FT`、`V` | 概念引用、正式特征类型引用、准确值 | `C1:存在概念` 等后缀是类别或具名定义约束，不是新类别；关系用途须由现有概念类别中的正式定义证明，概念条件不得伪装为准确值 `V` |
| `TM`、`LM`、`H` | 时间、语言材料、含义子项 | `H` 是带作用域的子含义，不表示已绑定世界节点；查询/规则变量也须保留类型和作用域 |

同一位置允许多种**领域对象**类别时写 `R1:{E,F}`，表示一个角色可绑定普通存在或实例特征；`R` 只作复合槽位记号，不表示关系概念。`{E,F}` 是允许类别集合，不是一个新类型，也不是话语内容中的“或”。集合不能跨越 7230 的角色种类边界：例如 `SC`、`E` 与 `C` 不可合并为一个角色，须按含义拆成规则或使用子规则映射。多角色的类型配对还须写明完整条件，例如“`R1` 属普通存在且 `C1` 为存在概念，或 `R1` 属实例特征且 `C1` 为特征概念”；若分支的含义操作不同则必须拆规则，不能用复合槽位偷换。场景与普通存在组合可写 `R1:{SC,E}`，但绑定时仍须核验采用的视角。

下列“典型结构”只示意一个有类型的合法形态，不穷尽同一含义可适用的类别；`〔限制域1〕`、`〔比较表达1〕` 等中文标记是需另行定义来源和约束的含义材料，不是信息节点类型代码。每一行发布时仍须展开为 7230 的完整目标、角色约束、结构与来源，示例文字本身不是可执行数据。

同一行含多个形式时要建立不同基础结构并共用可共用目标，不能依赖斜线在运行时猜句法。类型槽位是目标角色，不是直接输出的文字；`FT`、`T`、`M` 等都须取得对应的合法表达，不能把代码、句柄或编号印成名称。关系概念、比较表达及对象/概念名称通过已有定义、比较规则与词条名称取得；缺名称时走7220命名路径，不用固定字面词绕过正式概念端点。固定功能词如“是、的、能”只要求合法词条及已知结构作用，不强制建立世界概念或概念名称关系。

初始组织知识至少覆盖：单项回答；对象的多个特征列举；目标—实际步骤—实际结果的任务过程；按主题/场景/事件时间分段的叙述。每项使用7230的取材和缺材合同。复杂连接、省略、转折、多段总结逐步学习；尚未覆盖的组织返回缺规则。

### 2.1 代词定义与组合种子

初始化可以批量建立经完整定义查重后的代词概念、所需正式特征类型及合法值域、名称关联和语言组合规则。概念定义按1110/2220归概念唯一写入方，名称归2210，含义—形式规则归语言知识；各阶段分别发布、读回，失败不得假称整批成功。初始化重复执行先复用已有完整定义，不能因词面或运行次数制造新身份。

首批基础定义至少覆盖本作用域说话者、受话者、受约束第三方、近指、远指及受类型限制的待求身份/内容；分别关联“我”“你”“他/她/它”“这”“那”“谁/什么”的相应用法。名称相近不要求定义相同，同一词面多用法也不强行并成一份含混定义；完整定义与实例字段遵守7230。

配套组合种子包括：

| 组合 | 用途与边界 |
| --- | --- |
| 指示词＋数量/量词＋目标描述 | “这个杯子”“那本书”按完整表达形成实例；杯子/书约束来自已有概念，具体目标不进入通用定义 |
| 已有实例＋后续合法回指 | “它”按作用域及约束选择兼容实例；实例复用不合并语言出现，也不重写此前目标 |
| 待求角色＋查询或条件结构 | “谁负责”与“谁先到谁先选”分别保留查询/条件用途及变量共享；识别“谁”不自动构成对外提问 |
| 群体、回指和量化限定＋目标描述/谓词 | 按7230/7240组合“我们”“这些”“自己”“彼此”“每个”等用法；群体整体、逐项与互指不互换 |

这些条目是起步材料，不是永久类别全集。后续新用法先复用特征、值域和组合规则；只有语义确实不能表达时才提出具名特征/操作合同扩展，不能每见一个词就加一种概念类或可执行操作。

初始化只建立定义和合法表达知识，不创建“当前说话者”“当前杯子”等虚构对象，不生成具体自然语言场景指代实例或绑定。具体参与者、参考中心、集合成员和最终指向必须来自实际材料/场景；教学样例若保存，只是有明确假设作用域的语言材料，不是初始化时的现实事实。


#### 2.1.1 代词与需求字段确定值（20261102）

代词概念定义仍按本节与1110初始化；**不建归类子需求**。判定「必需字段有确定值」时，代词须先完成指代消解并落到自然语言场景中的目标信息节点；仅有名称关系不算确定。未决时提出指代澄清补问子需求（例：「你说的『它』是哪个？」），与补问／归类同级。入站「帮我…」：「我」→调用期交互上下文当前说话者（服务对象），「你」→受话者。详见 LANGUAGE-PRONOUN-RESOLUTION。

### 2.2 功能词构式扩展目录

S01—S20 是含义种子，以下按**构式而非单个词面**扩展可复用的功能词用法。它们仍采用 7230 的目标描述、强类型角色、有序结构项及来源；每个不同词序或作用域是独立基础结构，能共享目标时才共享目标。此目录不是可执行规则本身，也不表示对应知识已初始化、解释器已实现或该词在所有语境中只有一种含义。固定功能词只须合法词条及结构作用，不因此成为世界概念。未在下表出现的功能词可继续按同一准入方法学习，不能以“表已齐全”推定可理解任意汉语。

表内类型代码沿用第 2 节的统一记号；同一行以斜线并列的不同形式是不同规则，编号在各自规则内重新起算，不靠斜线在运行时任选词替换。`〔限制域1〕`、`〔比较表达1〕` 等是有类型来源的含义材料，不是额外节点类型。“可组合”只表示 7240 已有含义操作或 7230 已有内容组织项能够承载具名范围内的目标，发布和运行仍须完成角色映射、准确语序、来源、指代、完整范围与双向核验。

| V23 | `E1` 能通过 `M1` 使 `H1` | S14 能力或方法预期 | 须区分能力主张、正式可行性与未来预期；函数存在不证明 `E1` 能使用 |
| V24 | `E1` 的 `FT1` 从 `V1` 变为 `V2` | S16 变化描述 | 没有合法场景、时间及前后端点时只能是语言主张，不造现实动态 |
| V25 | `H1`，但是 `H2`／`H1`，然而 `H2` | 7230 内容组织的转折衔接 | 仅在输入已有对应转折含义时采用；两项各有独立含义，不自动生成“违背预期”的事实 |
| V26 | `E1` 有事 | 7240 集合条件主张：`E1`满足固定引用的`C1:集合条件概念`，其活动任务集合基数`>=1` | `E1`可以是任意存在；“事”只限定集合元素为任务，不提供具体`T1`。输入完整采用后可按请求保存来源主张，不查询真伪、生成任务或写现实特征；输出保留主张来源，不能用3200自我任务全集证明第三方有事。V02的一般“有”候选不得吞并本构式 |

以下词面和构式也须被识别为**明确的知识缺口**，不能被上述相似结构或已实现函数吞并。它们进入可保存的原文/结构候选与学习目标；要成为可执行语言知识，必须先按 7240 增加或明确含义操作、角色、作用域、输入匹配、输出保持与非成功合同，并核对 2340 的表达目的边界。词面可能兼有上表中的已知用法，缺口只限制尚无合同的那个用法。

| 缺口 | 示例 | 尚未成立的含义区别 |
| --- | --- | --- |
| G01 析取与选择 | 或者、或、要么……要么、还是 | 话语内容的或、排他选择及问句选项不同；7240 的条件求值 OR 不能代替它们 |
| G02 认识模态 | 可能、或许、也许、大概、必然 | 说话者对命题的把握及依据不同于指代多候选、明确未知和工程失败 |
| G03 规范模态 | 必须、应当、允许、禁止 | 义务、许可及禁止的来源和适用对象不同于能力、需求和请求 |
| G04 通用时间与体 | 了、着、过、正在、将要、曾经 | 已发生、持续、经历和预期须有事件/时间作用域；S15 任务阶段及 S16 变化不能泛化代替 |
| G05 一般事件参与和语态 | 把、被、给、向、替、用、让 | 施事、受事、接受者、工具及主动/被动结构须绑定同一有类型事件含义或变量；假设/请求不要求现实事件已发生 |
| G06 一般目的与意图 | 为了、以便、用来 | 预期目标关系不同于实际结果或因果；已有任务/方法目标只可按其正式投影表达 |
| G07 焦点、排他与预设 | 只、才、也、还、连……都、是……的 | 焦点范围、附加项及预设不能压成普通并列或全称量化 |
| G08 程度、结果及趋向补语 | 地、得、起来、下去、完 | 修饰对象、程度、动作结果及方向须有类型化输入，不凭尾词补造变化 |
| G09 独立感叹与语气 | 啊、吧、呢、哎呀 | 语气形式可随已知目标学习；若新增独立情绪/态度目的，须先裁决 2340 的三种完整表达目的 |
| G10 一般关系从句与名词化 | 做过 `H1` 的 `E1`、正在 `H1` 的 `E1` | 子句限定目标和时间/事件范围须可恢复；不能把所有“的/所”当作 S03 的特征连接。已有 S19 引述的子句复用不归入本缺口 |
| G11 模糊数量与程度 | 许多、少许、约 `V1:数量`、很、太、最 | 须有类型化数量/程度值域、参照标准或完整比较域；不能凭字面补阈值或把“最”当两项比较 |
| G12 让步与同步 | 虽然 `H1` 但是 `H2`、即使 `H1` 也 `H2`、一边 `H1` 一边 `H2` | 让步所对的预期及事件时间重叠不能仅用并列或普通条件冒充 |
| G13 话题与证据来源 | 对于、至于、关于、据 `E1` 说、根据 `E1` | 话题范围和证据来源与被述事实分开；转述不能套直接引语的角色绑定 |
| G14 反问与省略续问 | 难道 `H1` 吗、`E1` 呢 | 反问立场及省略角色依赖受控前文，不等于普通确认问；缺前文不能猜补 |

扩展顺序是先把 V 项逐项展开为 7230 的完整、可双向核验的知识定义，再处理 G 项所缺的具名语义合同；不能为提高词面覆盖率直接给 G 项分配已有操作。输入遇见 G 项可返回部分理解或缺规则，输出若该区别属于必需含义则返回缺规则/能力缺失，不省掉区别后冒称完整表达。

### 2.3 首轮六种基础构式

以下六种变体固定本轮不使用交互上下文的单短语/短句转换范围，不把S01—S20或功能词目录整体认定为已支持。每个槽都是带类型的角色，实际文字须由正式概念名称或类型化字面值产生；示例中的`E1`等不是要求用户输入的字母。固定词按各自词条、有序结构项分别匹配，表中空格仅展示边界，不要求普通输入必须分好词。

| 构式 | 有序结构 | 类型化含义与本轮边界 |
| --- | --- | --- |
| S01归类 | `E1` `是` `C1:存在概念` | `E1`的描述词先对应一个存在概念，再在空白语言场景实例化为无专名E；交付E归类于C1的主张，不寻找同名现实对象 |
| S02上下位 | `C1` `是` `一种` `C2` | 两侧为同类别存在概念，或同FT根特征概念；按已知严格上下位关系收窄候选，不自动写上下位边 |
| S03整数 | `E1` `的` `FT1:I64标量特征类型` `是` `整数` `V1:语言整数材料` | FT按已登记类型角色核验；V保存原数字词面及规范十进制字符串，语言转换不构造领域准确值或实例特征 |
| S03概念条件 | `E1` `的` `FT1` `是` `概念` `C1:特征概念` | C1须在FT1根内；交付概念条件主张，不把概念区间改成准确值 |
| S05组成 | `E1` `是` `E2` `的` `一部分` | E1是部分、E2是整体，两个对象出现分别在同一空白语言场景实例化；来源概念相同也不合并，不自动发布现实组成事实 |
| S09概念归类确认 | `〔S02子句〕` `吗` | 只询问S02主张是否成立；共用子句的概念角色映射，受询者未给出仍可转换内容，不断言子句成立 |

表中的`整数`与`概念`是S03两种独立知识的固定分支词；不得省掉后凭值长相在两个含义间猜选。具体数字词法、图检索回退、候选保留、场景/E建立与实际输出回读统一由[7240第4.3节](7240_子规范_自然语言双向转换与组织规则.md#43-无交互上下文的基础句型相互转换)规定，所需材料字段由[7230第3.5节](7230_子规范_语言材料知识与交互字段.md#35-无上下文基础句型的转换材料)承载。

本轮不要求代词、焦点、临时专名、跨句同一对象识别或现实树对应；这些能力有各自合同，不能通过本表宣称已完成。S02/S09为纯概念含义，不创建空壳场景；其余四种在唯一解释后才建立所需匿名语言存在。六种变体共用知识和类型化角色，主函数按实际结构调用子转换函数，不能新增脱离语言知识的第二套词面含义表。

### 2.4 种子构式三对（归类主路径只用第一对）

首批先天构式须补齐下列三对询问/陈述；初始化与 INIT-LANGUAGE-KNOWLEDGE-SEEDS 同步登记。词条归类询问与写回**只使用第一对**。

| 对 | 询问构式 | 陈述/写回构式 | 本规范用途 |
| --- | --- | --- | --- |
| 1 | `X` 是什么？ | `X` 是一种 `Y` | **归类主路径**：询问词条归类 / 词条归类写回 |
| 2 | `X` 有什么？ | `X` 有 `Z` | 种子具备；非归类主路径 |
| 3 | `X` 能做什么？ | `X` 能 `W` | 种子具备；非归类主路径 |

`Y` 在写回中按概念类型理解；`X`/`Y`/`Z`/`W` 为受约束角色，不是自由字符串槽。第一对与 S01/S02/S10 族对齐：询问侧对应信息请求，陈述侧对应对象/概念归类主张，不得把回答直接写成自我内部世界事实。

### 2.5 类型已知、定义未知的概念合同（词条归类写回专属）

本条是「词条归类写回」在理解「X是一种Y」后新建概念的**专属合同**：

1. 在 **Y 下新建概念身份**；类别取 Y 所在类（存在／特征／动态）；经**概念名称关系**连接词条 X。
2. 新概念此时**类型已知**（位于 Y 的类／根树），但「有什么」「能做什么」等定义**待补**＝**定义未知**。
3. 可继续沿归类询问向上抽象或补定义，直至定义可发布，或**到达存在／特征／动态三类所属全局根**终止（根不为词条、到达全局根即停），或检测到未前进循环；不以因果链根为终点。
4. 此合同不是把语言变量冒充空挂的未知概念，也不是功能词入树；正式挂接必须落在存在／特征／动态三棵根树之一（四本体根布局仍含因果链根，但归类不挂入）。

## 3. 一条样本即可启动的学习过程

### 3.1 输入与分流

学习输入至少包括固定样本/范围、学习目标、可读含义依据、原语境、已有规则候选和本次完整处理范围。依据可以来自明确教学指向、已知对象/事实的同期描述、已理解的改述、纠正或独立反馈。外部说话者陈述本身只是语言材料；其事实真伪仍由领域裁决。

有三条合法起点：

1. 已知含义→观察怎样表达：从对象/角色与样本对齐，形成基础规则。
2. 已有语句→归纳结构→寻找含义依据：未找到前只保留结构候选，不凭句频补含义。
3. 已理解子句/事件→观察组合方式：学习选材、分组、顺序与衔接，不重新定义子句含义。

### 3.2 形成步骤

1. 保存样本和原始语境，定位已知词、角色、时间、否定与引语；区分不会分词、缺名称、缺概念、歧义、缺表达规则和缺组织规则。
2. 对齐样本片段与强类型含义。对齐多解则保存候选和差异；没有对齐依据不得发布可用于含义判断的规则。指代表达对齐须区分1110的概念定义、完整短语实例、语言出现与目标；可泛化的是特征/角色规则，不能把样本中恰好某人是说话者、某杯子被指到或某群体成员组成写成通用定义。
3. 在单个样本中，将已有对象/值对齐片段替换为受约束角色，保留尚无泛化依据的固定词和范围。不能仅因为A是存在就推广为所有存在；一例可用但范围应限于已证明类别或具体对象。
4. 多样本时比较已对齐含义和形式，抽取共同项、差异角色与可选组织项。差异可以产生多个规则，不强行取交集抹去否定、参与者或因果方向。
5. 生成7230/7240可解释结构，检查角色类型、必需项可恢复、作用域、选择器和子规则可用、定义无环及严格进展。不认识的操作保持候选，不生成脚本或默认调用。
6. 对完整定义做规范化查重：局部角色按首次结构出现顺序重编号；保留角色种类、约束、语序、固定词、作用域、子规则定义与映射；无序AND条件确定排序，顺序组成不排序。完整相等复用，摘要仅索引、内容须精确互证；同目标不同形式是不同知识。
7. 完整定义可经语言owner发布，并以学习关联记录样本/依据；首例按已证明范围限定试用。若仍只有结构候选，不建立正常采用关系。
8. 用新样本、独立反馈或明确教学检验，按实际结果继续采用、收窄、拆成多项、停止新用或发布修订定义。定义变化不得改写此前表达树的所用版本。

### 3.3 理解原话中的单句词条归类学习

本条闭合服务对象原话理解中的词条学习，不另开学习线程：

0. 若出现未登记原文，先按第3.3.1节在纯读之外确认词边界与规范化材料，再经词条owner建立或取得正式词条并读回，重新分词／解释及读取缺口。边界无依据时先询问分界，不伪造词条；不能把整块未命中或唯一分词候选直接当作确认。随后按本次用法分流，功能词与代词不送概念归类。
1. 「获取服务对象需求信息」要求必需字段有**确定值**＝字段词条已有对应**概念信息节点**；对不上则条件不满足（不新增前提）。
2. 通用筹办提出**归类子需求**（每个待归类的**普通内容词条**一条；功能词不归类，代词除外见 §2.1.1），与补问子需求同级，完整需求经自我确认进任务链。目标形状与专属求值合同见[LANGUAGE-LEMMA-CLASSIFY](详细设计/20261102_LANGUAGE-LEMMA-CLASSIFY_词条归类学习与本能详细设计_v0.1.md) §2／§2.1（目标=词条、满足=名称关系 fresh；不走普通存在+特征值）。
3. **归类方式**：按词条在已知句式中的位置归类。整句都未知时，用已知词条生成候选句式，候选句式成分类型亦未知。
4. 本能「询问词条归类」生成「X是什么？」（可多词条合成一句），经发送判断后入列。
5. 本能「词条归类写回」按「X是一种Y」理解并写入语言知识：固定词条类型、采用候选句式；可复用词条按规范化键整理，词／句的本次出现仍保留各自原文范围与来源，不因同文面合并不同出现。
6. 写回后按普通写回惯例：正式发布→fresh 读回互证→父方法重读确定值（不得用写回回执代替）；原句不作废，重述确认；失败保留已发布事实并结构化非成功、来源复用重试（见 LANGUAGE-LEMMA-CLASSIFY §5.3）。
7. 回答中再出现新词则继续追问，直至理解或检测到循环；理论上归到概念根类型。
8. 不回答或离线：等待或改用其它方法满足该需求，与其它需求相同。

详细方法头/规格/结果与字段询问对齐，见 LANGUAGE-LEMMA-CLASSIFY；字段补问写回本能同包补齐。

### 3.3.1 未知词面显式准入与归类衔接

具名规则：`LANGUAGE-LEMMA-CREATE-FROM-FRAGMENT`。本条补齐原文范围与正式词条之间的衔接，不放宽2200、2320的词条准入及未知范围规则，也不改变纯理解／纯读取缺口的零写职责。

1. **未登记不等于词边界确定。** 保留固定原文、语言、来源、范围与候选；词面最长匹配、整段未命中、唯一候选或字级回退均不能单独证明拟登记范围就是一个词。可依正式语言规则或本次明确分界回答确认边界，再按具名合同形成规范化材料；不得为凑归类目标先造词条。
2. **边界未定先询问。** 有充分正式规则依据时不强制人工；无充分依据或无法唯一确定时，允许先向服务对象询问如何划分。采用用户已确认的**原文范围分界澄清专属目标**，以语言模块正式保存的有效分界结果为满足条件；需求准入、完整目标键和fresh复核见[3100第3、5.2、6.5节](3100_根规范_需求.md)，材料与采用合同见[7230第2.4节](7230_子规范_语言材料知识与交互字段.md#24-原文范围分界结果材料)。目标保留来源出现定位＋固定文本材料＋标量范围，不先造词条、普通存在特征或指代实例；共享材料在不同消息／出现使用不能合并。来源不以完整含义U、词条或D为前置。回答须明确关联本次正式询问、目标范围和原理解工作；它只提供分界依据，不自动确立概念含义或现实事实。无结果、未答、部分依据或仍多解时保留缺口，不取首套切分、不循环登记；互斥的多个当前有效采用或工程故障不能伪装正常歧义／未满足。
3. **显式准入。** 边界与规范化材料具备且确需复用／稳定身份后，由纯读之外的语言应用编排调用词条owner的建立或取得能力。功能词／代词可以具有词条身份，“不归类”不等于“不登记”。不强制为此新增本能；若另需任务可召回能力，须先完成相应方法合同，不能让纯读函数隐式变为写入入口。
4. **身份与来源。** 沿用2200／4240的最小结构、稳定身份和生命周期，不新增“待归类”生命周期状态。唯一键仍为语言＋规范化合同＋规范化词面；同键复用，不因不同消息来源建立第二词条，不覆盖原创建来源。每次出现的位置、原文范围和顺序另按2320保存，不能拿单一创建来源代替出现全集。
5. **重读与分流。** 先行分界结果是有依据的原文范围材料，不是已确认词出现；取得正式词条并读回后，才按7230形成引用真实词条的新解析。规范化保留固定原文、原范围与对齐，不在变换后的文本上暗用旧坐标。登记并正式读回后，重新分词／解释及读取缺口，不沿用登记前的旧解释依据；以明确关联接回原M、原出现、原理解工作和已有同一待完善D，新U／解析不换问题键、不借回答重开原需求。功能词依本次构式固定词项，代词依正式指代知识及作用域处理，量词／数词按本次规则角色解释，不以字符串黑名单或整类策略判断；未决保持缺口。只有本次用法确为普通内容词且当前名称关系不足，才以正式词条为目标进入归类。分界满足不代替父工作fresh重读、原需求内容确认或self承接。
6. **工程与实施边界。** 数据读取／发布故障不是未知词义；沿既有工程合同处理，保留已发布事实，不伪装未命中、普通否定或成功。分界目标、来源与有效结果语义已按上述合同确定，不再列作待裁；分词本能的实际产物、必要参数场景／返回，语言结果公开读写、任务／消息／回答关联、正式表达知识及新U接回已有同D的实际API仍须形成提供者设计。询问、语言生成、发送、接收写回分账，函数只依本次参数场景取得实际材料；纯读不建D／T、不写词条，不恢复整组旧快照保护。不因此宣称现有只接受词条或指代实例的接口已支持本专属目标；本轮不强制接入外部词典，不授权按草稿改代码。

具体步骤、与归类／指代流程的分账及尚未可执行的提供者缺口见[CREATE-FROM-FRAGMENT v0.4第6、8节](详细设计/20261103_LANGUAGE-LEMMA-CREATE-FROM-FRAGMENT_未登记片段建立词条详细设计_v0.1.md)。

## 4. 从句到段到篇的组织学习

不只比较相同词序，也比较“表达目标→选了哪些信息→怎样分组/先后→用了哪些衔接”的对应。

例如已知任务确有目标、两次实际执行、一次纠正和最终结果；对方依此先说明目标、再叙述尝试、最后报告结果。可学习角色化组织规则，取材指向真实任务投影，步骤按本次必需的完整范围逐项展开，纠正为有依据的可选分支。不能把示例中恰好两次尝试写成所有任务必有两步。

文章组织进一步复用段落规则，学习主题维持、场景转换、时间跳转、前指和总结。按主题回叙不是实际事件逆序；语言省略不是事件不存在。输出选材完整性取决于用户表达目标，不要求列出全部历史。

## 5. 使用反馈、修订与淘汰

反馈至少区分：指错对象、名称不合适、句式/作用域误解、组织遗漏/顺序不清、来源事实错误、未送达。分别回到指代、名称、规则、组织、对应领域或输出通道；事实错不一定语法错，未送达不等于规则无效。

使用记录保留知识固定定义、实际方向/范围、源样本、对齐和反馈引用。能从关系统计的使用次数、成功率和最近使用不复制为核心字段；没有独立反馈不自动计为成功。“明白了”只保存其实际回应及可确认范围，不将整个知识库可靠性置真。

采用准则：限定试用只在已证明角色/范围内用；独立验证无已知反例且覆盖拟采用范围，才扩大为该范围的正常使用；新反例先定位是否违反规则前提，确属规则误判则收窄或停止受影响范围，不停止无关知识。

淘汰先停止新用，再按知识引用与来源保护退出采用关系；可用更简单规则覆盖同一目标且不损失必需含义时，旧规则可停止优先选择。低频只提供候选理由，不能删除仍有唯一用途或历史引用的定义。物理回收按0050/语言结构合同另行执行，不以“淘汰”直接擦除原始对话。

## 6. 不以自我循环证明学习

自生成→自解析→一致只检查往返合同；重复同一材料、复读、翻译再译回不算新的独立依据。必须另外保留来自真实对象对齐、教学修正、其它已解释材料或交互行为反馈的验证来源。

学习“能描述”的规则不建立“能执行”的方法。通过文章获取方法时只能产生条件/预期结果/步骤学习材料；真实函数注册、参数规格、任务执行验证和方法完善仍服从3300/5350/5360/8210。

“空作为有类型未知的正式概念”仍属概念侧合同，不是本规范新建的语言知识类型。理解服务对象原话时不得在返回`概念形成合同缺失`后直接结束：须按第3.3节转入归类子需求。类型已知、定义未知按第2.5节保留缺口并继续学习；不得宣布已完成从无到空，也不得把语言变量写成正式未知概念身份。

## 7. 验证与完成边界

至少覆盖种子每一独立构式的正例、近似反例与输入/输出；单例有依据可形成限定规则、无依据只存候选；相同形式多义；对象替换但类型不相容；否定/引语/条件保留；组织可选项缺失；自反馈不算独立验证；扩大范围遇反例收窄；同义查重不合并不同语序；规则退役后旧表达读回；缺概念/名称/提供者不假成功；完整范围的资源失败及发布失败分支。第2.3节的转换用例另按7240验证矩阵；是否运行测试按AGENTS第7.1节，不由本清单自动触发。

达到有限种子闭环、具名组织闭环和真实学习闭环分别报告，不以模板数量、解析成功率或一次回话证明通用语言、思考或自组织治理已经完成。机器函数和物理保存尚须具名实现合同，不由本规范虚报已有代码。
