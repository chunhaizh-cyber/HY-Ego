直接上级规范：1140、1150。

直接依赖规范：4010、4015、4110。

## 1. 定位与承载

本规范展开存在信息的字段、关系及数据操作，不定义存在识别、组成认知、空间计算或需求治理算法。节点、关系、值复用 L1；不建立存在专用事实仓、新结构 owner 或第二权威列表。

存在信息使用1140的三项逻辑信息：存在节点身份、自身特征引用集合、可选场景展开。后者按1150/4202在同一节点读取场景视角和四个实际根，不是另一对象身份。读回对象是调用方拥有的值式投影，修改它不修改事实；实际根与组织边不能被投影替代。

未关联特征时返回空集合，未启用场景视角时明确返回未展开；均不等于存在身份不存在。没有已知直接归属时如实返回无归属，不默认填入世界根、最近场景或自我场景，也不声称已完成现实定位。

## 2. 特征引用

1. 准确特征F按1130/4110与明确C/P位置共同成立，类型和值固定。出生事务由存在owner同时发布C已知F引用，不改变当前采用；其它存在仍按原接口引用已定位F。存在只引用其节点，不复制内容、不建立旧宿主实例槽，也不把概念名称关系纳入存在的第二写入口。
2. 一个存在可以引用同一特征类型的多个不同特征信息，保存不同轮廓、方向或其它识别信息；不能按特征类型强制覆盖为唯一一项。已知特征引用集合不等于当前观察集合，不能因同时保存正面和侧面轮廓就把两者都当成本次观察；当前观察以准确采用关联确定。同一关系角色下指向同一特征节点的重复引用不重复建立。
3. 特征值可以按其正式合同为内联 I64 或稳定值身份引用。存在类不改写值表示，也不从轮廓、坐标、名称等业务含义发明新字段。
4. 特征结构服务保存固定准确 F；存在类只维护本存在的已知特征与当前采用。新观察使用不同准确值时建立或复用另一 F，再改变采用；解除或替换引用不删除或改写旧 F。
5. 当前特征读回先取得该存在在本次一致读取范围内的当前采用关系，再读取目标 F 的准确类型和值。不同存在可以共享 F，但各自采用独立；仅缓存 F 或读取旧 F 不能证明当前采用。名称改变也不证明存在值发生变化。
6. 已知特征引用集合承接该存在已确认的不同准确特征，用于后续识别；它不等于每次观察的时间档案。需要范围概括时可引用7160共享概念，但须保留该范围适用于本存在的真实依据；全类型概念或其它存在支持的值不能反推为本存在历史。当前变化判断仍使用前后采用的准确内容及正式比较规则，不能只比较概念是否相同。

### 2.1 当前采用关系与完整性

1. 已知特征引用与当前采用使用不同的正式关系角色，均由存在结构服务唯一维护，目标都是独立准确 F。当前采用不是 F 的可变字段，也不是已知集合的排序、最后一项或缓存标志。
2. 在同一一致读取范围内，按“存在节点 E + 正式特征类型 FT”确定当前采用组，每组为 0 或 1 项。FT 从目标 F 的正式类型身份核验，不按名称、概念、相似内容或兼容类型混成一组；此唯一性不限制已知集合保存同 FT 的多个不同 F。同一对象不同部位以子存在区分，不同特征语义以不同正式FT区分；不另设属性身份来放宽同E同FT当前采用唯一性。
3. 每个当前采用目标必须同时属于本存在的已知特征集合，且准确 F 的类型与所操作 FT 相同。新增已知引用不隐式建立当前采用；当前为 0 项是合法的“未采用”，不等于值为 0、不存在该类型或对象不存在，也不得自动回退历史 F。
4. 建立采用须显式指定 E、FT 和目标 F；已有不同采用时，普通建立返回冲突，不偷偷替换。重复指向同一 F 不另建第二条当前采用。替换及解除须定位原采用，并在可靠提交时重验它仍匹配预期；并发变化不能覆盖另一请求的结果。
5. 替换采用默认保留旧 F 的已知引用；解除采用也只解除采用关系。直接移除或替换仍被采用的已知引用时拒绝，不隐式清空、改选或删除 F。调用方确需一并处理时，必须显式提交同笔结构组合，最终状态同时满足本节全部约束。
6. 原子组合可以包含新已知引用建立、原采用退出、新采用建立及明确要求的旧已知引用移除；唯一性和引用闭合按提交后完整状态共同校验，任何中间步骤不得单独公开。采用及必要已知引用的变更、预期匹配与并发守卫在同一可靠提交中闭合，复用0050 / 4230的关系替换与L1原子能力；不扩展为F创建、概念生成和名称绑定的全流程原子事务。
7. 改变采用关系不必然改变准确值：4110允许不同F身份表达相同完整内容，变化判断仍比较正式类型和准确内容。真实观察计量按7160，不由新F数量或采用关系是否变化推导。历史采用按具名历史读取回查，不作为本次当前采用；解除引用也不表示否定原观察事实。

## 3. 关系分类与唯一直接归属

| 关系 | 逻辑方向及用途 | 归属和操作边界 |
| --- | --- | --- |
| 存在已知特征引用 | 存在 → 已知准确特征。 | 存在类维护，允许同类型多项，不隐式采用。 |
| 存在当前采用 | 存在 → 本次采用的准确特征。 | 存在类按第2.1节维护，与已知引用分角色，按E / FT联合唯一。 |
| 存在组成关系 | 父存在 → 子存在。 | 存在类维护；反向查询同一事实取得直接父，不另存父列表。 |
| 场景成员关系 | 场景 → 成员存在。 | 场景类维护；反向查询取得存在的直接所属场景。 |
| 场景视角与实例根绑定 | 同一对象节点 → 各具名实际组织根。 | 场景类按4202维护，不另建宿主对象；旧宿主关系只限域兼容。 |
| 直接子场景关系 | 父场景 → 子场景对象。 | 场景类维护；与该对象的成员/组成归属联合唯一，角色投影不另建边。 |
| 其它具名存在关系 | 存在 → 存在，含义由正式关系类型定义。 | 由该关系所属数据类维护；不得以普通关系冒充组成或场景归属。 |
| 需求所属及目标引用 | 需求 → 所属存在，或需求 → 目标宿主。 | 需求类维护；存在相关需求通过这些事实查询，不复制为本体字段。 |

同一当前结构中，对每个对象，将指向它的组成、场景成员与子场景包含关系合计，数量只能为0或1；同一事实的多角色读取不重复计数。约束跨全部场景成立，不按树、内外视角或关系类型分别计数。关系尚未建立与已经建立的唯一关系必须分账。

组成与场景范围不等义。例如发动机可以组成汽车；乘客可以是车内场景成员，但不因此组成汽车。父存在的直接子存在只能由组成关系确定，不能把内部场景全部成员当作组成部分。墙面等被分别识别为不同存在时各有各自节点和唯一直接归属；不能以显示面不同让同一个节点取得两个直接父存在。

新模型的内部场景就是该对象的场景视角，不是另一个场景节点，不建立对象到自身的宿主或成员关系。根绑定与实例组织不是对象直接归属。已有成员/组成归属的存在启用场景视角后，子场景读取按4202投影原包含事实，不补第二条归属。

服务对象、协作、使用等具名引用不是容纳关系；空间远近、方向、相对位置按需要读取特征并经二次特征计算，不预存所有存在之间的两两空间边。

## 4. 递归、内部场景与无环

1. 直接归属与递归归属分别查询。螺丝直接组成发动机、发动机组成汽车、汽车直接属于车库时，螺丝间接处于汽车和车库；不为它补写越级组成或车库 → 螺丝的直接归属事实。
2. 内部完整存在视图可组合该对象的直接组成子存在、直接场景成员与直接子场景，标明来源并按节点去重；存在列表本身仍只表示直接场景成员。递归展开不把全部后代伪装为直接子存在。
3. 已组成宿主的子存在在内部场景中出现只是展开投影，不建立第二条场景成员边。未认定为组成部分的内部成员仍保存自己的唯一场景成员关系，不因展开自动形成组成边。
4. 普通存在的场景视角按应用需要启用，不因节点创建、名称或已知子关系自动预建。组成关系可以先于场景展开，数据层不能以尚未展开拒绝合法组成关系；自我初始化的旧ABI及迁移边界见7130。
5. 无环检查按对象包含方向联合执行：父存在→组成子存在、场景→成员存在、父场景→子场景。角色展开使用同一对象身份、同一事实，不新增宿主→内部场景或反向镜像边。任何混合路径回到原节点均拒绝；四根实例树的组织无环与内容引用按4202另行检查。
6. 未展开、没有子关系或某观察算法到达停止粒度都不等于客观不可分。具体观察的质量、掩码和像素停止条件由 6230 / 6240 管理，不成为存在类通用创建前置。

## 5. 状态、动态与需求关联

存在视角不保存自身状态和动态集合。状态/动态由对应数据类独立保存；自身整体状态及变化归发生所在场景，同节点作为场景时，通过4202实际状态根和动态根组织内部独立存在的事实，按4202第3.1节递归，不因整体观察精度提高自动展开。

具体状态沿4202第3.2节C/E/S完整使用绑定定位发生场景、被描述存在和中性状态，被描述特征由E与S内正式FT确定；按存在反查也是读取这些既有绑定，不保存第二权威列表。不能仅凭归根、同类型、共享状态或当前归属推断主体，也不给状态本体再加所属字段或副本。中性内容共享不合并不同存在或不同来源的观察，内部事实不自动成为父存在自身状态。

当前成员投影与已发生实例组织不是同一集合。存在离开、改挂或组成认知修正，不使其已发生状态/动态无效；不得依当前成员重写历史所属或自动删历史事实。解除使用引用不移走实例的既有组织归属，保留/清理由所属数据类合同及4202处理。

需求独立集中保存，已有需求按所属存在查询。所属存在回答“谁的需求”，目标宿主回答“希望谁的特征达到目标”，二者不能混用。当前自我确认的需求、他者表达的请求以及自我对他者的推测不是同等确定的需求事实；后两者先作为带来源的判断材料，正式需求产生确认仍按 3100。

当甲是服务对象，自我承接让甲达到某目标时，形成的自我需求仍属于自我，甲是目标涉及的存在。存在关系不能直接证明服务有效、任务完成或服务值增加。

## 6. 必须提供的数据操作

下面固定操作语义及责任，不以这些中文类别冒充已经存在的 C++ 函数或 DTO。

| 操作类别 | 定位和必要输入 | 成功后的事实 |
| --- | --- | --- |
| 绑定新建、读取、删除存在 | 新建须显式提交一种初始绑定及绑定节点：直接所属场景、直接组成父存在或直接子场景父场景；其它操作按存在节点定位。 | 先核验绑定节点，新存在身份与初始绑定同次发布并读回；缺失或非法绑定诊断且结构化拒绝；读取不隐式补建；删除服从第 7 节。 |
| 已知特征引用增、删、改、查 | 存在节点，加被操作已知引用及目标特征节点。 | 只改变本存在已知引用；仍被采用的目标按第2.1节保护，准确F不变。 |
| 当前采用建立、读取、替换、解除 | 存在节点、正式FT；建立 / 替换指定目标F，替换 / 解除指定原采用预期。 | 无采用明确返回；当前至多一项且属于本存在已知集合，替换及关联组合原子发布。 |
| 组成关系建立、解除、替换 | 父 / 子存在节点；替换须明确原关系与新父。 | 保持唯一直接归属、引用完整和无环，不复制子节点。 |
| 直接父、直接子与递归祖先 / 后代读取 | 存在节点；递归读取明确范围与预算。 | 依据同一关系事实形成投影，直接与间接不混淆。 |
| 场景归属建立、解除、替换、反向读取 | 按场景类合同传入存在、场景及被操作关系。 | 与组成关系联合唯一；不在存在类复制场景 CRUD。 |
| 场景视角启用、读取及受保护退出 | 场景类按该存在节点及4202操作。 | 同一身份与四根完整闭合，不补宿主对象、自包含或第二直接父；退出角色不删除对象。 |
| 本类其它具名关系增、删、改、查 | 存在节点、正式关系类型、方向及目标节点。 | 只操作所属关系，不替业务解释真实性或改变端点本体。 |

节点身份是定位起点，不是修改的全部参数：设置新引用仍要新目标，解除或替换仍须能指明原关系；不要求调用方传回整个旧存在对象，也不从名称、内存地址或缓存反推身份。

查询空集合、无可选引用、对象不存在、引用冲突、读取不完整和内部不一致必须分账。查询不能隐式新建或移动对象；索引只能召回，成功必须回读节点及准确关系。预算不足不得把部分组或被截断路径称为完整结果。

存在相关数据操作的完整性不要求存在类反向调用所有其它数据类。特征引用由存在类负责，特征内容由特征类负责；场景关系及其反向查询由场景类负责，需求由需求类负责；上层组合公开能力，不取得私有端口，也不新增纯转发层。依赖和唯一结构分区仍按 4030 / 4230。

## 7. 写入、移动与删除的可靠性

1. 归属写入联合检查组成、场景成员和子场景关系及完整包含路径。关系变更或角色启用须重验受影响的同对象展开；不能分角色检查唯一，也不能用应用层先查再分别写规避并发冲突。
2. 普通存在创建必须以一个明确初始绑定进入联合检查。绑定节点须在请求事实截止内已发布且当前有效，绑定种类与节点类型、目标树及无环约束一致；新存在节点、存在族结构和初始绑定关系使用一个组合幂等身份在同一可靠原子提交中发布。禁止先提交存在 owner 的孤立节点再调用场景或组成接口补挂。缺失绑定或字段不可解释时返回结构化入口拒绝；绑定未找到、错类、错树、已退出、包含冲突、事实代次漂移、资源失败、读取不完整或历史不一致时保留精确非成功。所有失败均保持零新身份、零新关系，并在最终责任边界调用一次统一调试诊断；调试宏关闭只移除人读诊断，不得改变机器结果。
3. 普通新增归属遇到已有不同直接归属时拒绝，不能偷偷改挂。移动是明确的原关系到新关系替换；场景到场景、场景到父存在、父存在到场景及父存在到父存在都保持同一存在身份。
4. 旧归属移除、新归属建立及必要唯一性 / 无环守卫必须在同一个可靠原子提交边界闭合。L2 形成所需结构组合，L1 执行可靠提交；涉及不同内部结构分区时复用已有中性原子能力，不新增 L1 领域入口，不向普通调用方暴露写集、锁或端口。
5. 提交前拒绝或失败时不产生公开半结构，旧归属保持不变；已确认提交后读回失败，不得宣称旧归属仍有效、回滚已发布关系或换新请求重做，按原请求可靠读回和非成功合同收敛。
6. 特征引用、场景视角/根绑定、普通关系和节点删除分别操作。解除关系或退出场景视角不删除对象；删除存在须闭合仍受保护的角色、根及其它引用，不能级联删除特征、组成子存在、场景实例树、需求或状态/动态。无法在许可范围闭合时拒绝删除。
7. 索引只是可重建投影，不与关系各存一份权威父、子或所属场景集合。持久保存及重建后仍必须满足同一唯一性和引用规则；可靠性材料不进入存在本体字段。
8. 存在族锚点、关系类型和其它固定系统结构使用既有具名初始化入口引导，不进入普通绑定新建合同；普通请求不得选择“系统初始化”种类、引用族锚点冒充业务绑定或据此创建无归属存在。
9. 尚无满足联合守卫与原子替换的提供者时，对应变更能力属于待实现，不得退化为两次普通 CRUD 或返回假成功。具体函数 / DTO、关系稳定类型与物理映射由后继正式设计落实本规范，不借旧存在 ABI 或旧内部成员合同产生继续写入授权。

## 8. 验证语义

验证至少覆盖：

1. 三类合法初始绑定分别在新建后按节点及关系双向读回；缺失、无效、错类、错树和已退出绑定均触发诊断并返回结构化拒绝，且零身份、零关系、零幂等首写账；诊断宏关闭后拒绝不变。特征或后续归属改变不换身份；明确解除后的无归属与对象不存在分账。

4. 四种归属替换逐项读回；并发争用最多一个成功，提交前失败保留旧关系，提交后读回失败不假装回滚。

## 4.1 同节点场景视角的父语境

已有存在启用场景视角时，请求必须显式给出父场景语境。若E直接属于场景C，父语境必须为C；若E直接属于父存在P，P必须已启用场景视角且父语境必须为P；若E原本就是直接子场景，父语境必须等于该父场景。服务在同一截止读回E的唯一结构父和父语境，匹配后只形成场景角色投影及四个实例组织锚，不改写或追加组成、成员或子场景边。
