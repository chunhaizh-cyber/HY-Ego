状态：正式子规范

直接上级规范：1140。

直接依赖规范：1130、1150、1160、4015、7100。

相关边界规范：2100、3100、4110、4200、4202、6220、6230、6240、7110、7130、7192。

## 1. 定位与承载

本规范展开存在信息的字段、关系及数据操作，不定义存在识别、组成认知、空间计算或需求治理算法。节点、关系、值复用基础数据集；不建立存在专用事实仓、新结构owner或第二权威列表。

存在信息由以下部分组成（1140）：

```text
存在身份
+ 概念引用（零特征时为存在根；有特征后为其专属存在概念，7100）
+ 实例特征（每个特征类型至多一个F，1130）
+ 直接所属场景（普通存在恰一）
+ 可选父存在
+ 直接子存在
+ 可选同节点场景视角（1150、4202）
```

读回对象是调用方拥有的值式投影，修改它不修改事实。没有特征时返回空特征组；未启用场景视角时明确返回未展开；均不等于存在不存在。世界根和物理全局根没有直接所属场景，读回时如实返回无归属；普通存在恰有一个直接场景，读回投影无法取得其归属时报告结构不一致，不默认填入世界根、最近场景或自我场景。

## 2. 实例特征

1. 存在内部持有实例特征，同一特征类型至多一项；同一对象不同部位以子存在区分，不同特征语义以不同正式FT区分。实例特征保存当前值、去重历史值及命中次数、标准值和聚合值域（1130），存在不再另设“已知特征引用集合”或“当前采用”结构。
2. 特征值按1130/2100为内联I64、特征值节点引用或有类型的正式信息节点引用。存在owner不改写值表示，也不从轮廓、坐标、名称等业务含义发明新字段。
3. 写特征时，存在owner必须使用该存在唯一的直接场景，在同一次发布中：写入特征值 → 当前值实际改变时生成状态并挂入该场景状态列表（1160）→ 同步专属概念（首个特征时派生，7100）。不提供“不知道发生场景”的公开写特征路径。
4. 当前特征读回即读该F的当前值；不同存在各持有自己的F，不共享实例特征。变化判断使用状态记录的F与准确值，不比较概念是否相同。

## 3. 关系分类与唯一直接归属

| 关系 | 逻辑方向及用途 | 归属和操作边界 |
| --- | --- | --- |
| 存在持有实例特征 | 存在 → 实例特征F | 存在owner维护，同FT至多一项 |
| 存在概念引用 | 存在 → 存在根或专属概念 | 存在owner维护，恰一；不等于组成边、上下位边或世界支持边 |
| 存在组成关系 | 父存在 → 子存在 | 存在owner维护，关系角色为“子存在”；反向查询取得直接父，不另存父列表；添加已有同一关系返回无变化；与子存在的“所属整体”F在同一次发布中维护 |
| 子存在持有“所属整体”实例特征F | 子存在 → F | 存在owner维护；值为直接父存在引用，无组成父时为空；组成建立、解除、替换时与组成关系同次更新，当前值实际改变时按1160生成状态并挂入子存在的唯一直接场景 |
| 场景成员关系 | 场景 → 成员存在 | 场景owner维护；反向查询取得直接所属场景 |
| 直接子场景关系 | 父场景 → 子场景 | 场景owner维护；与该对象的场景成员归属联合唯一 |
| 其它具名存在关系 | 存在 → 存在 | 由该关系所属数据类维护；不得冒充组成或场景归属 |
| 需求目标引用 | 需求 → 目标信息节点 | 需求owner维护；按目标查询，不复制为存在本体字段；需求主体与目标分别表达（3100） |

同一当前结构中，对每个对象：

1. 场景归属唯一：指向它的直接场景成员关系与直接子场景关系合计至多一（普通存在恰一）；
2. 组成父至多一；
3. 组成关系与场景成员关系是两种不同关系，可以同时存在（1140）；并存时父存在须直接属于同一场景。

同一事实的多角色读取不重复计数，约束在同一世界内全部场景成立。

组成与场景范围不等义：发动机可以组成汽车；乘客可以是车内场景成员，但不因此组成汽车。父存在的直接子存在只能由组成关系确定。服务对象、协作、使用等具名引用不是容纳关系；空间远近、方向、相对位置按需读取绝对坐标特征并经二次特征计算或由自我相对坐标表取得，不预存两两空间边。

## 4. 递归、内部场景与无环

1. 直接归属与递归归属分别查询；不为间接关系补写越级组成或越级场景成员事实。
2. 存在可以启用同节点场景视角（4202）：其父场景就是它的直接所属场景，内部成员的状态和动态记录在该视角中。内部完整视图组合直接组成子存在、直接场景成员与直接子场景，标明来源并按节点去重。已组成宿主的子存在在内部场景出现只是展开投影，不建立第二条场景成员边。
3. 场景视角按应用需要启用，不因节点创建、名称或已知子关系自动预建；组成关系可以先于场景展开。
4. 无环检查按对象包含方向联合执行：父存在→组成子存在、场景→成员存在、父场景→子场景；任何混合路径回到原节点均拒绝。
5. 组成归属只按当前关系判断，在状态或动态挂接时核验（1150）；不设组成关系的发生期历史证明。组成关系的变化由子存在的“所属整体”F承载：该F值变化生成的状态和动态即组成变化的发生期依据（7192），不另建组成证明提供者。
6. 未展开、没有子关系或某观察算法到达停止粒度都不等于客观不可分；观察停止条件由6230/6240管理。

### 4.1 同节点场景视角的父语境

已有存在启用场景视角时，请求必须显式给出父场景语境：若E直接属于场景C，父语境为C；若E直接属于父存在P，P必须已启用场景视角且父语境为P；若E原本就是直接子场景，父语境等于该父场景。服务读回E的唯一结构父和父语境，匹配后只形成场景视角，不改写或追加组成、成员或子场景边。

## 5. 状态、动态与需求关联

1. 存在视角不保存自身状态和动态集合。状态由发生场景的状态列表持有，记录实例特征F的值变化（1160）；动态按1170由发生场景记录。按存在反查状态是沿F持有者读取，不保存第二权威列表。
2. 存在迁移场景不搬迁已挂接的状态与动态，不改写其发生场景；不得依当前成员重写发生位置。
3. 需求独立集中保存，按目标信息节点查询。需求主体与目标分别表达：自我执行需求属于自我；服务对象的被认知需求属于该对象（3100）。他者请求与自我推测先作为带来源的判断材料，经自我确认后才形成自我执行需求。存在关系不能直接证明服务有效、任务完成或服务值增加。

## 6. 必须提供的数据操作

| 操作类别 | 定位和必要输入 | 成功后的事实 |
| --- | --- | --- |
| 建立成员存在 | 由场景owner发起：直接所属场景、可选父存在（须直接属于同一场景）、零到多个初始特征及初始状态时间 | 存在节点、成员关系、初始特征、初始状态挂接、概念引用（零特征为存在根，有特征派生专属概念）同次发布并读回；初始特征按特征类型根唯一 |
| 添加特征 | 存在、特征概念、初始值、实例绝对UTC强时间 | 建立F并写值，生成初始状态挂入唯一直接场景，同步/派生专属概念；同类型已存在则拒绝且零写入 |
| 更新特征值 | 存在、该存在持有的F、新值、强时间 | 当前值真正改变时生成状态并挂入唯一直接场景；同步专属概念；同值命中只更新统计 |
| 组成关系建立、解除、替换 | 父/子存在；替换须明确原关系与新父 | 保持组成父至多一、场景归属唯一、引用完整和无环；同次更新子存在“所属整体”F并按值变化生成状态 |
| 直接父、直接子与递归读取 | 存在；递归读取明确范围与调用方给定的执行资源上限 | 依据同一关系事实形成投影，直接与间接不混淆 |
| 场景归属迁移 | 由场景owner传入存在、原场景、新场景 | 先解除或修改依赖原场景的关系信息（原场景成员关系等），绝对坐标置空记录于原场景（形成“离开”），迁入后写入坐标生成状态挂入新场景（形成“进入”）（1140、6260）；场景归属唯一；同一世界内迁移，稳定编码不变，状态/动态不随迁 |
| 逐级迁往上位场景 | 位置不能确认的存在 | 由场景owner迁往上位场景，最远至所属世界根（1140） |
| 世界根硬删除 | 世界根中满足具名硬删除规则（超时、超量等）的存在 | 自身状态/动态随之清理；有外部正式引用（他方特征、需求、任务、方法、因果）则本轮跳过；专属概念随清理，共同上位只减引用计数 |
| 场景视角启用、读取 | 场景owner按4202操作 | 同一身份，不补宿主对象、自包含或第二直接父 |
| 查询 | 存在节点 | 获取存在、是否存在节点、查询全部特征、查询概念引用、查询直接子存在 |

不提供按名称、任意特征组合或全局相似度直接搜索实际存在的公开索引。存在概念的中间层归纳入口属于7110，本规范只引用。

查询空集合、对象不存在、引用冲突、读取不完整和内部不一致必须分账；查询不隐式新建或移动对象。

## 7. 写入、移动与删除的可靠性

1. 普通存在由场景owner在明确直接所属场景内建立；存在节点、成员关系、初始特征与状态、概念引用在同一可靠原子提交中发布。禁止先提交孤立存在节点再补挂。
2. 归属写入联合检查组成、场景成员和子场景关系及完整包含路径；普通新增场景归属遇到已有不同直接场景、或新增组成父遇到已有不同组成父时拒绝，移动必须是明确的原关系到新关系替换，并在同一原子提交内闭合唯一性与无环守卫。
3. 提交前拒绝或失败不产生公开半结构；已确认提交后读回失败，不宣称回滚或换新请求重做，按原请求读回收敛。
4. 存在实例没有逻辑删除。普通删除入口只允许对世界根中的存在按第6节硬删除规则执行；建立失败时的本次回滚不受限制。
5. 为7130唯一自我形成，存在owner提供业务中性的单例角色结构：角色锚点登记与角色锚点→E目标关系；角色当前至多一个E，角色目标未解除前E受引用保护。
6. 索引只是可重建投影，不与关系各存一份权威父、子或所属场景集合。
7. 尚无满足联合守卫与原子替换的提供者时，对应能力属于待实现，不得退化为两次普通写入或返回假成功。

## 8. 非成功状态

至少区分：入口拒绝、存在不存在、父存在不合法、特征概念不合法、特征类型重复、概念同步失败、形成环、归属冲突、外部引用阻止删除、结构不一致、资源失败。普通存在零特征建立合法，不返回“特征不足”。

## 9. 验证语义

1. 零特征存在以存在根实例化；添加首个特征后派生专属概念；
2. 同类型第二个特征拒绝且零写入；
3. 写特征时状态在同一次发布中挂入唯一直接场景，无零引用孤儿状态；
4. 两个直接场景、两个组成父拒绝；直接场景加同场景组成父合法，组成父与子存在不在同一场景时拒绝；
5. 组成自环、多层祖先环和场景父子/成员混合环均拒绝；
6. 内部场景展开区分组成子存在与非组成直接成员，不增加直接归属边；
7. 迁移后已挂接状态/动态的发生场景不变；
8. 位置不明逐级迁往世界根；世界根硬删除遇外部正式引用跳过；
9. 直接与递归查询区分，索引重建不改变关系。

## 10. 退役口径

退出：“已知特征引用集合 + 当前采用”双结构及允许同FT多项；4115 IF/R结构与R项材料；场景视角四个实际根/四个实例组织锚；C/E/S状态使用绑定定位；组成关系发生期证明提供者（改由“所属整体”F的状态承载）；“所有正式需求天然属于自我”；事实代次、同G0原子替换、按H联合读取；叶E/C删除旧规则与“特征不足”拒绝。
