## 1. 定位与总则

本规范规定自然语言中功能性结构（虚词、最小构式）的概念化方式，以及需求、任务、方法、特征值与自然语言之间的双向对应。

1. 实词对应“概念 + 多个词条”；虚词通过最小构式形成**结构概念**，挂在语言知识（2340）下，不建立第五本体根。
2. 最小即拆：填项问与是非问分立为不同结构概念。
3. 上层表达目的与结构概念的对应：陈述↔陈述；填项问与是非问↔提问；**指令↔提出需求**。不另设其它表达目的。
4. 结构概念固定**含义角色**（局部编号，如 `E1`、`H1`）。表达模式自有槽位（模式内局部字母），通过“槽位→含义角色映射”关联；映射只对应、不换算。
5. **语言结构对应表**是从结构概念、表达模式和映射确定重建的索引视图，只经语言领域服务维护；不是第二权威。

## 2. 结构概念与表达模式

### 2.1 身份与模式

结构概念由细目、含义操作和含义角色组构成。表达模式由自有槽位、组成项和槽位→含义角色映射构成。同一结构概念可以有多个表达模式。

### 2.2 需求压缩与修饰槽

口语核心模式只承载需求**核心内容** `H`（目标的可读投影）。3100 中除核心目标外的其它有值字段（如权重、活动状态，以正式需求投影为准）不进入核心模式字面；仅当对应字段**有值**时，经可选**修饰槽**展开，无值则不生成该段。

例：`E1+需要+H1`；对应字段有值时 `E1+需要+H1+（修饰）`。具体修饰词条与槽位随汉语模式登记，不得把空字段印成默认词。

### 2.3 需求指令

含义角色包含**受请求者**与 `H1`。模式可省受请求者（默认受话者）：`请+提供+H1` / `请+E1+提供+H1`。

### 2.4 请求执行方法与信息请求分立

| 结构概念 | 用途 | 汉语示意 |
| --- | --- | --- |
| **请求执行方法** | 仅请求执行动作 | `请+V+…`；同义模式 `请+用+M1`（零额外参数，参数从语境补全，不另立结构概念） |
| **信息请求**（指令细目） | 请求告知信息 | 特征值：`请+告诉+我+E1+的+FT1`；需求侧告知类同理 |

对应表必须分行，不得把信息请求并入请求执行方法。`V` 对应方法头 `M1`；其后槽位跟随该候选方法 Vm 的有序参数规格，规格多长跟多长，不设固定最大位。结果语义来自该方法 C→R 的 R。

理解时，请求执行方法经方法候选查询或因果查找形成任务筹办材料；不直写任务终态、不改 Vm。

## 3. 语言结构对应表

对应表按结构概念、细目、语言和表达模式组织，支持按结构概念、按模式、按含义角色和按语言查询；启动时幂等重建；只经语言领域服务读写。对应表的物理 DTO 由实施设计冻结。

## 4. 需求、任务、方法的双向转换

### 4.1 字段→含义角色

- **需求（3100）**：主体、目标信息节点及目标特征类型构成核心 `H`；目标与结果统一由目标信息节点持有的实例特征F承载，关系型目标同样以该节点持有的F表达（3100）。权重、活动状态等其它有值字段映射为修饰角色，有值才进入修饰槽。
- **任务（3200）**：`T1`、关联需求/`H`、状态 `ST1`、执行/进度投影。
- **方法（3300/5350）**：方法头 `M1`、Vm 参数位 `P_i`、C、R、C→R。

### 4.2 结构概念 × 汉语模式（种子）

#### 需求

| 细目 | 标识 | 模式 |
| --- | --- | --- |
| 陈述 | SC-需求-陈述 | `E1+需要+H1`（+可选修饰槽） |
| 填项问 | SC-需求-填项问 | `E1+需要+什么` |
| 是非问 | SC-需求-是非问 | `E1+需要+H1+吗` |
| 指令 | SC-需求-指令 | `请+提供+H1` / `请+E1+提供+H1` |
| 指令·信息请求 | SC-需求-信息请求 | `请+告诉+我+E1+需要+什么` 等（细模式待登记） |

#### 任务

| 细目 | 标识 | 模式 |
| --- | --- | --- |
| 陈述·进行 | SC-任务-进行陈述 | `我+在+做+T1` |
| 陈述·目的 | SC-任务-目的陈述 | `T1+是+为了+H1` |
| 陈述·完成 | SC-任务-完成陈述 | `T1+完成+了` |
| 陈述·进度 | SC-任务-进度陈述 | `T1+进行到+…+了` |
| 陈述·失败 | SC-任务-失败陈述 | `T1+失败+了` |
| 陈述·取消 | SC-任务-取消陈述 | `T1+取消+了` |
| 填项问·状态 | SC-任务-状态填项问 | `T1+的+状态+是+什么` |
| 是非问·完成 | SC-任务-完成是非问 | `T1+完成+了+吗` |
| 指令 | SC-任务-指令 | `请+做+T1` |

派生规则：对进度、失败、取消三类陈述，按统一规则派生填项问与是非问（如 `T1+进行到+哪里+了` / `T1+失败+了+吗`），写入对应表，不再手工各写一套无关种子；派生结果仍是独立结构概念行，可共享含义角色骨架。

#### 方法

| 细目 | 标识 | 模式 |
| --- | --- | --- |
| 陈述·条件 | SC-方法-条件陈述 | `做+M1+需要+C1` |
| 陈述·结果 | SC-方法-结果陈述 | `做+M1+会+得到+R1` |
| 填项问·条件 | SC-方法-条件填项问 | `M1+需要+什么+条件` |
| 填项问·结果 | SC-方法-结果填项问 | `怎么+得到+R1` |
| 是非问·结果 | SC-方法-结果是非问 | `做+M1+会+得到+R1+吗` |
| 指令·动作 | SC-请求执行方法 | `请+V+…`；同义 `请+用+M1` |

#### 特征值

| 细目 | 标识 | 模式 | 对应表种类 |
| --- | --- | --- | --- |
| 陈述/填项问/是非问 | SC-特征值-* | 按既有种子 | 特征值 |
| 指令·信息请求 | SC-特征值-信息请求 | `请+告诉+我+E1+的+FT1` | 信息请求，非请求执行方法 |

### 4.3 生成与理解

生成：节点投影 → 种类 + 细目 + 语言 → 对应表 → 模式（核心 + 有值修饰槽）→ 语法 → 材料。

理解：匹配 → 结构概念；信息请求与请求执行方法按对应表分行；方法侧查找；需求侧经 7240 的重述确认后再写。理解结果只形成带来源的提议，不直接确认需求或改变任务。

## 5. 语法与量词

首批语法规则：语序 12 项、形态 7 项、一致 7 项，共 26 项，由 7250 种子登记。

量词首批：`个`（回退默认）、`位`、`名`、`件`、`项`、`次`。生成遇未知搭配时回退“个”并回显。

理解未登记量词：按“数 + 未知量词 + 名”结构解析；将该量词登记为缺口；保存样例供学习；不因未知量词整句失败，其余已匹配结构仍可交付部分理解。

## 6. 其它最小结构

归类/拥有：陈述、填项问、是非问（无专用指令）。上下位：陈述、是非问。否定：分立为独立结构概念；否定与填项问或指令的组合登记为缺口。动作类指令一律使用请求执行方法。

## 8. 禁止

- 硬编码问句表；
- 信息请求与请求执行方法混行；
- 无值修饰槽强制输出；
- Vm 参数尾用固定最大位截断；
- 理解未知量词时丢弃样例；
- 为结构概念另建第五本体根或绕过语言领域服务写对应表。
