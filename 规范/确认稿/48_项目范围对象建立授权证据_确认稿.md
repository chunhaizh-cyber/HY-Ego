# 第 48 项：项目范围对象建立授权证据

状态：已确认机器语义输入；非正式规范。

## 已确认口径

1. 只有 `项目事实范围授权服务` 可以签发项目范围内对象的首次建立授权。L1、普通调用方、目标对象服务、配置、缓存和其它领域服务均不能自行形成该授权。
2. 建立授权分为两个身份严格不同的阶段：

```text
未发布的值式授权票据
-> 随目标对象在同一 L1 写集中发布的授权证据事实
```

3. 未发布授权票据是不可伪造、不可修改、单次消费的强类型值，只能由项目事实范围授权服务构造。它不是机器事实，不得持久保存、跨请求复用或作为对象已经建立的证明。
4. 授权票据至少绑定：授权服务稳定身份、项目事实范围稳定编码、资格规则稳定编码、被授权对象业务类型、目标事实所有者服务稳定身份、建立意图及其规范化摘要、L1 写集幂等键、目标对象写集本地键和授权时事实代次。
5. 授权不使用墙上时间过期。票据只对其绑定的事实代次、写集幂等键、目标本地键和完整建立意图有效；事实代次漂移即失效，必须重新执行授权裁决。
6. 目标对象的唯一事实所有者取得票据后，构造一个 L1 写集，同时包含：

```text
目标对象节点及其完整初始事实
+ 授权证据节点
+ 授权证据到项目范围、资格规则、签发服务和目标对象的具名关系
```

两者必须在同一个事实代次原子发布。不得先发布空对象再补授权，也不得只发布授权证据而不建立目标对象。
7. L1 为目标对象和授权证据分配正式稳定编码。写集本地键只用于同一写集内部引用，发布后不得进入公开身份、持久证据身份或跨合同 ABI。
8. 授权拒绝不产生票据，不产生授权证据节点，L1 零写入。
9. 同一幂等键、同一完整意图的重试返回原结果；同键异义返回冲突。发布结果未知时只能使用原写集和原幂等键读回收敛，不得重新签发另一张异义票据。
10. 写集发布成功后，值式票据立即失去作用。后续证明授权只能读取已发布授权证据节点、具名关系及其发布代次。
11. 已发布授权证据只证明对象首次建立曾获合法授权且与对象同代次发布，不自动证明对象仍然当前有效、资格永久有效或后续操作已经获得授权。
12. 对既有对象的修改、退出、迁移或重新取得资格使用各自独立授权合同，不复用首次建立授权。

## 适用边界

本项冻结首次建立授权的两阶段身份、绑定字段和同写集发布边界，不冻结 C++ 防伪实现、票据具体类型布局、各关系类型编码、建立意图摘要算法或其它操作授权。后续正式吸收时必须核对 0050、4015、4030、4040、6180 及各目标对象唯一事实所有者合同。

本确认不证明项目事实范围授权服务、票据类型、授权证据节点或同写集发布路径已经实现。
