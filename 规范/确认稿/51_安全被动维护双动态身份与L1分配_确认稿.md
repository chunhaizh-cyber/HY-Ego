# 第 51 项：安全被动维护双动态身份与 L1 分配

状态：依据正式材料和用户授权已裁决；非正式规范。

裁决依据：4015、4210、4220、6140。4210与4220已经要求状态迁移动能和动作致变动态为两个互异动态事实；4015已经改为同写集本地键引用并由L1分配正式稳定编码，因此旧6140“三个调用方稳定主键”无法承载双动态的问题不再需要新增第四调用方主键。

## 裁决口径

1. 分层安全被动维护发生实际值变化时，在一个 L1 写集中使用四个互异写集本地键形成：

```text
新的安全值事实
新的安全状态节点
状态迁移动能节点
被动动作致变动态节点
```

2. 四项正式稳定编码均由 L1 在写集发布时分配。调用方、安全纯值算法、安全领域服务和外部事实参与提供者均不得预分配或传入后值、后状态、迁移动能或动作动态的正式稳定编码。
3. 写集本地键只在本写集内建立引用，发布后通过 `新编码映射` 取得正式编码；本地键不得进入公开身份、持久证据身份或跨合同 ABI。
4. 状态迁移动能证明同一主体、场景和特征的前后状态真实变化。它的来源动作角色为空，同源状态迁移动能角色为空。
5. 被动动作致变动态证明本次变化由安全领域正式被动维护提交方法形成。它必须具有来源动作，并通过关系20角色8恰一指向本写集中的状态迁移动能。
6. 两个动态必须共享同一主体、场景、特征、前状态、后状态、来源存在和事实代次，但稳定编码及动态种类互异；不得自引用、复用同一本地键或把状态迁移动能改写成动作动态。
7. 新安全值、后状态、两个动态、全部角色关系、安全维护账和幂等记录在一个 L1 写集及一个事实代次原子发布。任一必需项失败时不得留下普通可读半结构。
8. 发布后按 L1 新编码映射和新事实代次联合读回四项事实及其关系。动作动态角色8必须精确指向本轮状态迁移动能。
9. 无实际值变化时不创建新值、状态或任何动态；只发布合法的安全维护游标、累计时间或维护账变化，不得为满足非空写集伪造哨兵事实。
10. 6140旧“调用方提供三个稳定主键”合同及目标图中的“等待第四稳定主键”门禁退出目标语义。正式修订前不得继续据此设计新接口。

## 边界

本项不改变安全值算法、事件因素裁决、残余风险或时间维护规则，只解决双动态身份和新L1写集编码分配。它不证明正式6140、目标图、详细设计或生产提供者已经修订和实现。
