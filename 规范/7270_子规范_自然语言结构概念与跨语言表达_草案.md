## 1. 问题与决策（摘要）

- 实词：概念 + 多词条。虚词：最小构式 → **结构概念**（挂**语言知识**，无第五本体根）。
- 最小即拆：填项问与是非问分立。
- 上层目的：陈述↔陈述；填项问∪是非问↔提问；**指令↔提出需求**。
- 结构概念固定**含义角色**（局部编号 `E1`/`H1`…）。表达模式**自有槽位**（模式内字母局部）+ **槽位→含义角色映射**（只映射、不换算）。
- **语言结构对应表**：索引视图；仅经 `新_语言类`。

## 2. 结构概念与表达模式

### 2.1–2.2 身份与模式

同 v0.3：结构概念（细目、含义操作、含义角色组）；表达模式（自有槽位、组成项、映射）。

### 2.3 需求压缩与修饰槽（已批准）

口语核心模式只承载需求**核心内容** `H`（目标可读投影）。  
3100 其它字段（如紧急度、期限等，以正式需求投影为准）**不进入核心模式字面**；仅当对应字段**有值**时，经可选**修饰槽**展开（模式侧可选项；无值则不生成该段）。

例：`E1+需要+H1`；有期限时 `E1+需要+H1+（在+期限修饰）` 等——具体修饰词条与槽位随汉语模式登记，不得把空字段印成默认词。

### 2.4 需求指令

含义角色含**受请求者**与 `H1`。模式可省受请求者（默认受话者）：`请+提供+H1` / `请+E1+提供+H1`。

### 2.5 请求执行方法 vs 信息请求（已批准）

| 结构概念 | 用途 | 汉语示意 |
| --- | --- | --- |
| **SC-请求执行方法** | 仅**请求执行动作** | `请+V+…`；同义模式 **`请+用+M1`**（零额外参数，参数从语境补全，**不另立结构概念**） |
| **信息请求**（指令细目） | 请求告知信息 | 特征值：`请+告诉+我+E1+的+FT1`（**S13**）；需求侧告知类同理 |

对应表**分行**：不得把 S13 并进请求执行方法。  
`V`→方法头 `M1`；其后槽位**跟随该候选方法 Vm 有序参数规格**（无固定最大位；规格多长跟多长）。结果语义来自该方法 **C→R** 的 R。  
理解：`新_方法类::查询候选方法` / 因果查找 → 任务筹办材料；不直写任务终态、不改 Vm。

## 4. 需求 / 任务 / 方法 双向转换

### 4.1 字段→含义角色

- **需求 3100**：主体/目标存在/`H` 核心；紧急度、期限等 → **修饰角色**（有值才映射进修饰槽）。
- **任务 3200**：`T1`、关联需求/`H`、状态 `ST1`、执行/进度投影。
- **方法 3300/5350**：方法头 `M1`、Vm 位 `P_i`、C、R、C→R。

### 4.2 结构概念 × 汉语模式（种子）

#### 需求

| 细目 | ID | 模式 |
| --- | --- | --- |
| 陈述 | SC-需求-陈述 | `E1+需要+H1`（+可选修饰槽） |

| 是非问 | SC-需求-是非问 | `E1+需要+H1+吗` |

| 指令·信息请求 | SC-需求-信息请求 | `请+告诉+我+E1+需要+什么` 等（与 S13 同族；**待**细模式登记） |

| 陈述·完成 | SC-任务-完成陈述 | `T1+完成+了` |

**派生规则（已批准）**：对进度/失败/取消三类陈述，按统一规则派生填项问与是非问（如 `T1+进行到+哪里+了` / `T1+失败+了+吗` 等），写入对应表，**不**再手工各写一套无关种子；派生结果仍是独立结构概念行（可共享含义角色骨架）。

### 4.3 生成与理解

生成：节点投影 → 种类+细目+语言 → 对应表 → 模式（核心+有值修饰槽）→ 语法 → 材料。  
理解：匹配 → 结构概念；信息请求 vs 请求执行方法按对应表分行；方法侧查找；需求侧 **7240§5.1 重述确认** 后再写。

## 5. 语法与量词（已批准）

语序 12 + 形态 7 + 一致 7 = **26**。

**H-AGR-02**：首批 `个`（回退默认）、`位`、`名`、`件`、`项`、`次`。生成未知搭配 → 回退「个」并回显。

**理解未登记量词**：按 `数+未知量词+名` 结构解析；将该量词登记为**缺口**；**保存样例**供学习；不因未知量词整句失败（其余已匹配结构仍可交付部分理解）。

## 6. 其它最小结构

归类/拥有：陈述·填项·是非（无专用指令）。上下位：陈述+是非。否定：分立；否定×填项/指令 → 缺口。动作类指令一律 SC-请求执行方法。
