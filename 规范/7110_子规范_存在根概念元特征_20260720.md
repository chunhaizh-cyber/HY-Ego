# 7110 子规范 存在概念主动归纳与归类

编号：7110

日期：20260916

版本：v1.8

状态：正式子规范

直接上级规范：2220。

直接依赖规范：1140、7100、7140、7150、7160。

相关边界规范：1130、1150、2210、4240。

## 1. 定位

存在概念形成有两条互相衔接、不能互相替代的路径：

```text
路径一：拟建立存在的完整已知事实
      -> 精确查找/创建其具体存在概念
      -> 建立世界存在

路径二：明确归纳需求选定多个已发布存在概念或存在
      -> 比较完整定义及真实见证
      -> 形成/复用共同上位概念
      -> 将满足严格包含条件的具体概念归类为其下位
```

路径一由7100规定；本规范只规定路径二。路径二是主动的归纳归类应用，不是概念树、世界树、存在类或概念树类在节点增加时自行扫描、枚举或写入的副作用。

## 2. 存在概念定义和概念图

存在概念的完整定义由以下抽象约束合取组成：

```text
自身特征约束：正式特征类型及已发布特征概念值域
+ 组成约束：子存在概念和组成角色
+ 关系约束：关系类型、参与角色及角色所需的概念约束
```

具体E、F、值、子存在节点、具体关系端点、场景位置、事实截止和名称词面是来源或支持证据，不是存在概念的签名成员。若某种材料需要成为定义约束，必须先由其正式类型或关系合同给出可规范化的抽象语义，不能把实例编码改名写入概念。

概念图的边方向固定为“上位概念 -> 下位概念”。没有直接上位的当前概念组成顶层投影；它不是持久概念总根、根链或默认父。一个概念可有多个直接上位；只保存必要直接边，层号、路径和兄弟列表都是投影。

## 3. 主动归纳请求

归纳只能由有明确目标的业务/认知应用发起。一次请求至少明确：

```text
有限且不少于两个的来源存在或来源存在概念
+ 本次归纳要比较的约束范围/目标
+ 同一读取截止和非零预算
```

“按需求”意味着请求选择哪些存在、比较什么约束以及为何需要该抽象；服务不得从当前所有顶层概念、同级显示项或整个世界树自行寻找组合。若需要形成多个不同组合概念，分别提交多个明确归纳请求；不得用一次请求穷举所有特征子集。

来源为E时，应用先读回E当前用于概念定义的事实和其已发布具体概念；来源为概念时，读回完整定义及其必要来源/支持见证。读取不完整、跨截止、来源退出、预算不足或类别不符不等于“没有共同点”。

## 4. 共同约束提取

归纳应用只保留能够对全部来源成立、且可组成完整存在概念定义的共同约束。它可以：

1. 保留完全等价的自身特征概念约束；
2. 在同一正式特征类型内，使用已证明存在的共同上位特征概念值域替换更具体值域；
3. 保留子存在概念和组成角色均可对齐的共同组成约束；
4. 保留已按正式关系角色合同完成规范化的共同关系约束。

不同类型不能因数值接近而合并；不同名称、相似度、共同场景位置、相同索引位置或仅一条图边均不构成共同约束。关系两端指向不同具体存在时，只有关系类型的正式角色合同允许将该端抽象为某个已发布概念约束或存在性角色时，才可以泛化；不得因为两个关系名称相似而把“有女儿李四”和“有女儿赵六”直接改写为同一关系定义。

若关系合同尚未提供这种角色泛化，关系只按精确规范化约束参与比较；该分支返回“关系泛化能力缺失”，零概念和零边写入。角色概念如“母亲、女儿”等只有在对应关系角色的定义、泛化和见证均已具名后才能形成，不能由自然语言名称猜测。

## 5. 形成、复用和归类

提取的共同约束为空，或不足以构成请求所声明的完整定义时，返回“未形成共同概念”；这是正常结果，零写入。

共同定义完整时，按以下过程执行：

```text
规范化候选定义
-> 在存在类别精确查询
   ├─ 命中：复用共同概念
   └─ 确认不存在：创建共同概念并完整读回
-> 对每个来源概念证明严格包含
-> 建立必要的 上位 -> 下位 直接边
-> 精简已被中间概念覆盖的冗余直接边
-> 完整读回定义和全部受影响直接边
```

候选概念必须比每个被归类的来源概念更宽：每个来源完整定义都蕴含候选定义，且至少有一项约束被合法删除或放宽。同义来源只复用，不新建父概念，也不建立自边。若已有中间概念已经表达所需包含关系，不重复增加传递边。

一个请求可能只使部分来源满足严格包含；只有通过完整核验的来源概念接边，其它来源保留原结构并在结果中逐项报告。创建共同概念及本次直接边的发布不得暴露环、跨类别边或断裂的定义引用；既有合法多父边不得因新归类被删除。

概念的上下位归类不自动建立或删除E到概念的世界事实支持。若请求同时需要为某个E建立共同概念支持，必须以该E的真实已发布事实逐项核验，并按7100/7140另行发布和读回。

## 6. 后续细化与组合边界

初始具体概念、主动形成的上位概念和后续更具体概念均不可原地改义。新的事实或新的归纳需求一律形成新的完整定义并精确复用或创建新概念；旧概念及历史支持保留。

概念图可以逐步拥有“教师”“母亲”“女教师”等不同组合概念，但只形成以下两类概念：

- 已由7100完整建点事实形成或复用的具体概念；
- 已由本规范的明确归纳请求、完整共同约束和严格包含证明形成或复用的抽象概念。

不得为数学上所有可能的特征子集、未出现的交叉值组合或未被请求的角色预建概念。没有共同定义、未声明关系泛化或未选定比较范围时，保持既有多个概念而不强求父概念。

## 7. 失败、生命周期与分工

概念查询未确认不存在、读取失败、退役同义概念、发布未知、代次漂移、预算不足和资源失败必须按各自合同返回，不能被改写成“可新建概念”。同义退役概念按7140治理恢复；不可逆退出的旧身份只作审计，新形成仍按完整定义重新查重。

概念树类只核验并保存已裁决的完整定义、类别、直接边、支持、生命周期和读回；它不选择来源、提取共同点、判定关系泛化或决定归纳目标。世界树类只执行7100的先概念后实例编排。任务、方法或其它应用可以提出归纳请求，但不因提出请求就证明共同概念成立。

## 8. 验证语义

验证至少覆盖：

1. 首次路径和主动归纳路径分离，节点增加不触发全局扫描；
2. 多个同定义实例复用同一具体概念，多个不同概念可形成共同上位；
3. 无共同完整定义是正常零写入；
4. 相同局部特征、名称或相似度不误建共同概念；
5. 同FT上位特征域、组成角色和已定义关系角色分别参与归纳；
6. 未定义的关系泛化拒绝零写，具名规则下的角色泛化完整读回；
7. 上位严格更宽、同义复用、多父保留、传递边不重复且无环；
8. 归类边与E支持关系分账；
9. 请求范围、预算和截止不完整时不伪报“无共同点”；
10. 不枚举全部组合，不为未观察或未请求组合创建概念。

## 9. 退役口径

下列旧口径退出新生产：

- 存在概念根、强制根可达或普通概念必须挂在固定根链；
- 实例先建立、后自动进行首次概念形成；
- 在每次实例增加后自动扫描同级概念并穷举全部合法组合；
- 用组成事实当作分类边，或把分类上下位当作世界组成；
- 用名称、词性、相似度或单条共有特征直接生成角色概念。
