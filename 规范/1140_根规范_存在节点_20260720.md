# 1140 根规范 存在节点

## 1. 根定位

存在是以一个稳定节点组织自身特征及外部关系的信息对象。每个存在对应一个存在节点；特征变化、移动、组成认知细化或内部场景展开都不自动更换该节点身份。是否仍是同一存在由认知应用判断，存在数据类不替代识别，也不从名称或相似特征自动合并节点。

存在节点本身不装入完整世界信息。特征、组成、场景归属及其它具名关系由节点、关系和值共同承载，索引只定位和加速查询，不构成第二事实来源。

## 2. 存在信息的固定逻辑字段

| 字段 | 含义 |
| --- | --- |
| 存在节点身份 | 定位该存在的唯一稳定节点。 |
| 自身特征引用集合 | 指向独立特征信息节点的关系集合；不复制特征字段或建立旧宿主实例槽。 |
| 可选内部场景引用 | 该存在需要作为场景展开时所关联的场景身份；未展开时允许没有引用。 |

名称和节点类型沿用通用节点结构，不另建存在专用字段。上述集合和引用是逻辑信息，不要求节点记录物理保存数组或指针；具体关系、读回和操作由 7150 展开。

版本、事实代次、幂等、批次、生命周期、认知程度、分类置信、是否自我及位置历史均不作为存在信息的新增本体字段。L1 负责可靠保存与读取；位置、姿态等对象属性仍由特征表达。

## 3. 直接归属与递归

1. 同一时刻，一个存在至多有一个直接归属对象：一个场景或一个父存在，两者互斥。不得按不同场景树、不同关系类型分别允许一次归属。
2. 父子存在表达组成从属；场景成员表达范围归属，二者不等义。一个父存在可以有多个直接子存在，但每个子存在只能有一个直接组成父存在，且不得同时另有直接所属场景。
3. 归属可以递归读取。子存在经父链间接处于更大存在或场景中，不增加直接归属关系；禁止自身包含以及组成、场景成员、子场景和内部场景展开共同形成的包含环。
4. 场景归属可以在能指认场景和存在时首先建立；组成关系随认知补充或修正。确认新的直接组成归属时必须替换原直接归属，不因认知细化复制存在节点。
5. 没有已知子存在只表示当前认知或观察粒度下不再展开，不证明客观上绝对不可分。

## 4. 场景视角与相邻对象

存在对外是存在，对内可以通过内部场景组织其组成子存在和场景成员。内部场景保留独立场景身份，宿主仍是原存在；场景视角不复制存在身份，不给组成子存在补第二条直接场景归属，也不把所有内部场景成员认作组成部分。

存在本体不保存自身状态或动态集合。状态、动态独立保存；场景可以组织有关存在的状态、动态引用，并准确关联到被描述的存在、特征及事实。不得因此给状态本体新增所属存在字段或复制事实。

需求独立保存并按所属存在关联，不作为无归属全局变量或存在内嵌治理系统；所属存在与目标涉及的存在分开，产生确认与他者表达 / 推测的边界服从 3100。存在数据类不承担需求产生、任务生成、方法选择或服务值结算。

世界存在身份与概念身份不得混用。自我就是一个世界存在，复用同一存在节点结构，其特殊业务身份由自我合同确定；ARCH-L4 的任务 Vt / 方法 Vm 由各自业务域治理，不因复用基础结构成为世界存在、组成子存在或场景成员。概念仍使用 2220 的独立身份。

## 5. 数据操作边界

存在类必须提供按存在节点定位的节点及本类字段 / 关系操作，而不是只定义记录。读取、建立、解除和替换关系不等于修改或删除被引用对象；跨类别归属替换必须保持直接归属唯一并可靠原子完成，不能以应用层先删后加冒充移动。

存在、特征、场景、需求及状态 / 动态各自保留唯一的数据操作责任，空间关系按需要由二次特征取得；存在类不得复制其它类的写入实现。删除必须保护合法引用，不默认级联删除特征、子存在、内部场景或需求。7150 固定具体语义，4230 承接结构分工；字段定义不等于代码已经实现或存量数据符合新结构。
