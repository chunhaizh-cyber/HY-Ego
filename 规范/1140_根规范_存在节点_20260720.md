# 1140 根规范 存在节点

相关边界规范：1130、1150、2100、2220、3100、3200、3300、4230。

## 1. 根定位

存在是以一个稳定节点组织自身特征及外部关系的信息对象。每个存在对应一个存在节点；特征变化、移动、组成认知细化或内部场景展开都不自动更换该节点身份。是否仍是同一存在由认知应用判断，存在数据类不替代识别，也不从名称或相似特征自动合并节点。

存在节点本身不装入完整世界信息。特征、组成、场景归属及其它具名关系由节点、关系和值共同承载，索引只定位和加速查询，不构成第二事实来源。

## 2. 存在信息的固定逻辑字段

| 字段 | 含义 |
| --- | --- |
| 存在节点身份 | 定位该存在的唯一稳定节点。 |
| 自身特征引用集合 | 分别表达已知特征和当前采用的独立特征节点引用；角色、基数及操作由7150展开，不复制特征字段或建立旧宿主实例槽。 |
| 可选场景展开 | 按1150/4202读取同一节点是否具备完整场景视角及四根；不是指向第二个对象的内部场景引用，未启用允许为空。 |

名称和节点类型沿用通用节点结构，不另建存在专用字段。上述集合和引用是逻辑信息，不要求节点记录物理保存数组或指针；具体关系、读回和操作由 7150 展开。

版本、事实代次、幂等、批次、生命周期、认知程度、分类置信、是否自我及位置历史均不作为存在信息的新增本体字段。L1 负责可靠保存与读取；位置、姿态等对象属性仍由特征表达。

## 3. 直接归属与递归

1. 同一时刻，一个存在至多有一个直接归属对象：一个场景或一个父存在。组成父、场景成员及同节点场景视角的子场景归属联合唯一；不得按不同场景树、关系类型或使用角色分别允许一次归属。
2. 父子存在表达组成从属；场景成员表达范围归属，二者不等义。一个父存在可以有多个直接子存在，但每个子存在只能有一个直接组成父存在，且不得同时另有直接所属场景。
3. 归属可以递归读取。子存在经父链间接处于更大存在或场景中，不增加直接归属关系；禁止自身包含以及组成、场景成员、子场景和内部场景展开共同形成的包含环。
4. 场景归属可以在能指认场景和存在时首先建立；组成关系随认知补充或修正。确认新的直接组成归属时必须替换原直接归属，不因认知细化复制存在节点。
5. 没有已知子存在只表示当前认知或观察粒度下不再展开，不证明客观上绝对不可分。
6. 创建普通世界存在节点前必须明确一个初始绑定节点及绑定种类：直接所属场景、直接组成父存在或作为直接子场景时的父场景。绑定节点必须是同一事实截止内已发布且类型、生命周期和目标树位置均合法的当前节点；新存在节点及其初始绑定关系必须在同一次可靠原子发布中成立。请求未给出绑定或绑定字段不可解释时返回结构化入口拒绝；绑定未找到、已退出、错类、错树、包含冲突、事实代次漂移、资源失败或历史不一致时保留各自精确的结构化非成功，不得统一改写成调用方错误。上述任一失败都不得分配或发布新存在身份，并须在最终责任边界触发一次项目统一调试诊断；诊断关闭不得改变机器结果。
7. 存在族锚点、关系类型等固定系统结构由具名初始化入口建立，不是普通世界存在创建，不要求先绑定到另一个普通存在或场景；该引导例外不得由普通创建请求选择，也不得用于产生无归属普通存在。

## 4. 场景视角与相邻对象

存在对外是存在，对内按需要启用同一节点的场景视角，组织组成子存在和场景成员；四棵实际实例组织树按1150/4202。内部展开不再建立第二对象身份或宿主绑定，不给组成子存在补第二条直接场景归属，也不把全部内部成员认作组成部分。旧双身份和宿主ABI只按4230/4202兼容待迁移，不得同码强转或自动合并旧节点。

存在视角不增加自身状态或动态集合；同节点的场景视角通过实际状态根、动态根组织其内部存在的事实。自身整体状态和变化由发生所在场景组织，内部成员作为独立存在被描述时递归使用对应场景；更高精度观察自身特征不自动要求内部展开。具体状态按4202完整使用绑定定位被描述存在及属性，不能只凭根或当前成员推定主体；不向状态本体新增所属字段或复制内容。

需求独立保存并按所属存在关联，不作为无归属全局变量或存在内嵌治理系统；所属存在与目标涉及的存在分开，产生确认与他者表达 / 推测的边界服从 3100。存在数据类不承担需求产生、任务生成、方法选择或服务值结算。

世界存在身份与概念身份不得混用。自我就是一个世界存在，复用同一存在节点结构，其特殊业务身份由自我合同确定；ARCH-L4 的任务 Vt / 方法 Vm 由各自业务域治理，不因复用基础结构成为世界存在、组成子存在或场景成员。概念仍使用 2220 的独立身份。

## 5. 数据操作边界

存在类必须提供按存在节点定位的节点及本类字段 / 关系操作，而不是只定义记录。读取、建立、解除和替换关系不等于修改或删除被引用对象；跨类别归属替换必须保持直接归属唯一并可靠原子完成，不能以应用层先删后加冒充移动。

存在、特征、场景、需求及状态 / 动态各自保留唯一的数据操作责任，空间关系按需要由二次特征取得；存在类不得复制其它类的写入实现。删除必须保护合法引用，不默认级联删除特征、子存在、场景实例树或需求；退出场景视角不等于删除共享的存在身份。7150固定操作，4202展开场景，4230承接结构分工与旧ABI隔离；字段定义不等于代码已经实现或存量数据符合新结构。
