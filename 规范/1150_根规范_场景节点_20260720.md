## 1. 权威边界

本规范是场景节点、场景层级、成员、坐标、边界、状态和动态组织的现行机器合同。

场景是世界树中的空间组织节点，也是一个实际存在。场景不是纯容器，也不额外建立“存在本体字段”；场景节点直接具有专属存在概念和零到多个实例特征。

### 1.1 替代裁决

1. 场景作为存在建立专属存在概念，不再另设场景概念类别。
2. 场景采用成员、边界、状态列表和动态列表直接组织引用；旧四个实例组织锚和C/E/S状态使用绑定退出。
3. 状态节点已经保存被描述存在，场景列表只补充发生场景组织位置，不建立第二份状态本体。
4. 场景成员归属、场景父子层级和存在父子组成分账，允许同一普通存在同时具有场景归属和父存在。

上述裁决不自动证明迁移、生产装配或世界树消费者已完成切换。

## 2. 世界树和场景层级

全局基础数据集中保存：

```cpp
稳定编码 场景树根节点;
```

世界树根节点就是根场景。规则如下：

1. 根场景没有父场景，重复建立返回同一根场景。
2. 普通场景建立时只需明确一个直接父场景，可以先建立为空场景。
3. 普通场景恰有一个直接父场景。
4. 一个场景可以有多个直接子场景。
5. 子场景采用外部父子关系，当前关系角色为`3`。
6. 场景可以迁移到新的父场景，但不得把根场景迁移，也不得形成环。

场景层级只组织场景，不组织普通存在。普通存在通过场景内部成员字段归属一个最小可确认场景。

## 3. 场景信息

一个可完整读回的场景包含：

| 信息 | 基数 | 含义 |
| --- | --- | --- |
| 节点 | 恰一 | 场景稳定编码，同时是该场景的存在身份。 |
| 父场景 | 根为零、普通恰一 | 场景层级直接上级。 |
| 专属存在概念 | 恰一 | 场景作为存在的专属概念。 |
| 实例特征 | 零到多 | 场景自身特征。 |
| 直接成员存在 | 零到多 | 直接归属该场景的普通存在。 |
| 边界存在 | 零到多 | 参与边界定义的存在引用。 |
| 直接子场景 | 零到多 | 场景层级直接下级。 |
| 状态列表 | 零到多 | 发生于该场景的状态引用。 |
| 动态列表 | 零到多 | 发生于该场景的动态引用。 |

成员、边界、状态和动态字段都保存节点引用，不复制被引用对象的内容。

## 4. 场景建立、迁移和删除

公开入口：

```cpp
新场景建立结果 建立根场景() noexcept;
新场景建立结果 建立场景(稳定编码 父场景节点) noexcept;
新场景操作状态 迁移子场景(
    稳定编码 场景节点,
    稳定编码 新父场景节点) noexcept;
新场景操作状态 删除空场景(稳定编码 场景节点) noexcept;
```

建立场景时写入场景身份、场景父子关系和存在身份，并为场景建立唯一专属存在概念。空场景不要求初始特征，也不要求已经形成闭合边界。

只有非根空场景允许删除。“空”至少要求没有直接子场景、直接成员存在、状态和动态；场景自身特征及专属存在概念由删除调用同步清理。场景仍被其它场景的边界字段引用时拒绝删除。

## 5. 成员存在和场景范围

普通存在只能通过场景类建立并立即写入直接场景成员字段。一个普通存在恰有一个直接所属场景；迁移成员时先建立目标场景成员字段，再删除原字段，稳定编码保持不变。

如果新存在声明父存在，则父存在必须直接属于同一场景。当前存在已有动态时拒绝迁移，避免动态发生场景和存在归属失配。

查询定义：

```text
直接成员存在：只包含当前场景成员字段中的普通存在
场景范围存在：当前场景及全部下级场景的直接成员并集
```

场景范围存在不包含场景节点本身。场景节点是否属于某场景范围按场景树判断；普通存在按唯一直接所属场景及其祖先判断。

删除成员存在前必须确认没有子存在、边界引用、状态引用或动态主题引用。

## 6. 场景自身特征和场景内存在特征

场景自身具有存在身份，因此特征操作复用存在类：

```cpp
添加场景特征(...);
更新场景特征值(...);
添加场景内存在特征(...);
更新场景内存在特征值(...);
```

场景类负责核验目标确实是该场景或其范围内存在，调用存在类完成特征写入、专属存在概念同步和状态建立，然后把新状态挂入场景状态列表。

特征事实已经改变但状态挂接失败时，不能回滚已成立的特征事实，返回`特征已改变但状态挂接未完成`。相对坐标矩阵不是场景或存在的实例特征，不走本入口。

## 7. 状态列表

状态列表是发生场景中的状态引用集合。添加状态必须满足：

1. 状态节点可完整读回。
2. 被描述存在属于目标场景范围，或被描述存在就是目标场景节点。
3. 同一状态不得同时挂入多个场景。
4. 成功挂入时增加状态引用计数。

移除状态时解除场景字段并减少状态引用。若状态仍被该场景动态引用，则拒绝移除。引用减到零时，状态类按自身生命周期规则删除状态。

## 8. 动态列表

动态列表是实例动态的发生场景组织位置。添加动态必须满足：

1. 动态节点可完整读回。
2. 动态主题存在属于目标场景范围，或主题就是场景节点。
3. 动态引用的全部状态已经挂入同一目标场景。
4. 同一实例动态只能挂入一个场景。
5. 成功挂入时增加动态引用计数。

移除动态时解除场景字段并减少动态引用。引用减到零时，动态类按自身生命周期规则删除动态。

当前场景动态列表是引用集合，代码未保存列表项的业务顺序。它不能单独证明“连续动态链”或时间序列；时间顺序必须从动态和状态强时间中重建。

## 9. 定位坐标和相对坐标

### 9.1 坐标语义

定位坐标属于场景定位坐标系，用于表达存在在该场景中的相对稳定位置。相对坐标以自我立脚点中心为原点，以自我局部朝向为轴；摄像头高度和姿态应由外部姿态提供者换算进自我姿态，而不是把摄像头点误作相对坐标原点。

场景不要求永久保存一个独立“坐标原点节点”。定位坐标可以由相对观测逐步固化，但当前场景类只消费定位结果，不负责识别、固化或修正定位事实。

### 9.2 输入合同

相对坐标刷新读取：

- 自我节点和目标场景；
- 自我在场景定位坐标系中的定位坐标；
- 将自我局部坐标旋转到场景定位坐标系的三维朝向矩阵；
- 直接成员存在的定位坐标；
- 定位、姿态和边界定义序号；
- 形成时刻和有效截止时刻。

朝向矩阵必须是有限、近似正交且行列式为`+1`的旋转矩阵。定位或姿态缺失、失效、矩阵不合法、换算溢出时返回对应状态，不伪造坐标。

### 9.3 刷新结果

```cpp
场景相对坐标刷新结果 刷新场景存在相对坐标(...);
场景相对坐标刷新结果 刷新单个存在相对坐标(...);
```

批量刷新只处理当前场景直接成员，结果容器随成员数量扩展。缺少定位坐标的成员进入`需要获取定位坐标的存在组`，其它成员仍可形成部分结果。

刷新结果是实时计算材料，不写入基础数据集，不保留变化历史。只有后续定位坐标作为实例特征发生变化时，才通过特征—状态链记录状态。

## 10. 边界存在组

场景边界表达自我限定和认知形成的空间范围，不等同于视野边缘。边界存在组保存“用于定义当前场景边界的存在”引用：

1. 边界存在不要求直接归属于当前场景。
2. 引用边界存在不改变其原有场景归属。
3. 当前代码只支持显式添加和移除，不自动选择最外边存在。
4. 边界几何在需要时从外部几何读取接口取得并即时计算，不持久化计算结果。

若边界存在属于当前场景范围，使用其相对于场景内部参考点的最外侧候选边或面；若不属于当前场景范围，使用离内部参考点最近的候选边或面。候选无法唯一确定时返回失败，不任意选择。

## 11. 二维边界计算

```cpp
场景二维边界计算结果 计算二维场景边界(
    const 场景二维边界几何读取接口& 几何读取,
    稳定编码 场景节点,
    const 二维毫米坐标& 场景内部参考点) const noexcept;
```

流程为：

```text
读取边界存在组
-> 为每个存在读取候选线段
-> 按是否属于场景范围选择外侧或最近线段
-> 按相同端点连接线段
-> 形成一个或多个闭合环
```

每条二维边界线段必须非退化，闭合环中每个顶点的邻接度必须为二，重复无向边或开放链均返回`边界未闭合`或几何不合法。

## 12. 三维边界计算

```cpp
场景三维边界计算结果 计算三维场景边界(
    const 场景三维边界几何读取接口& 几何读取,
    稳定编码 场景节点,
    const 三维毫米坐标& 场景内部参考点) const noexcept;
```

候选面必须至少三个顶点、非退化且共面。选定边界面后，顶点按提供顺序连接成无向边；闭合空间要求每条无向边恰好由两个边界面共享。少于四个面或任一边计数不等于二，均不得宣称空间闭合。

边界计算不补造缺失几何，也不把临时计算结果写回边界特征。

## 13. 一致性不变量

任一成功读回的场景必须满足：

1. 具有场景身份和存在身份，且恰有一个专属存在概念。
2. 根场景无父，普通场景恰有一个父场景，场景树无环。
3. 普通存在最多出现在一个直接成员字段中。
4. 边界、状态和动态列表保存有效节点引用，不复制内容。
5. 状态被描述存在与挂接场景一致。
6. 动态主题和全部状态与挂接场景一致。
7. 场景动态列表不冒充时间排序事实。
8. 实时相对坐标不作为持久特征、状态或历史保存。

## 14. 非成功和发布边界

场景操作区分场景/父场景/存在/状态/动态不存在、归属冲突、形成环、根不可操作、场景非空、结构不一致、引用阻止和资源失败。

基础数据集没有组合事务。建立和挂接在失败时尽力逆序回滚；但存在、特征或状态已经成立而后续场景挂接失败时，返回具名部分完成状态，不能虚构整链原子性。

## 15. 非权威实现差距

以下对话口径尚未形成完整代码：

- 根据新感知自动识别同一旧存在、合并误认新节点和修正定位坐标；
- 从相对坐标自动固化或覆盖定位坐标；
- 每次成员变化后自动重算并维护边界存在组；
- 场景相邻、遮挡、连通、门或其它连接存在的正式表达和判断；
- 从相邻子场景聚合更大父场景；
- 提高视野后的场景合并、旧场景覆盖和认知一致性处理；
- 动态列表的高效时间索引；
- 持久化、恢复、生产装配和完整集成验收。

这些能力不得由现有坐标刷新或边界计算函数代替宣称。

## 16. 验证边界

后续验证至少覆盖：

- 根场景唯一、普通场景单父、迁移及环拒绝；
- 空场景建立和非空删除拒绝；
- 普通存在唯一场景归属和最小场景迁移；
- 状态、动态引用计数与场景列表成对维护；
- 旋转矩阵校验、坐标换算、部分完成和时效边界；
- 二维多闭合环、开放链拒绝；
- 三维每条边恰好双面共享；
- 跨场景边界存在引用和删除阻止；
- 已发布事实后的部分完成结果不被误判为零写入。
