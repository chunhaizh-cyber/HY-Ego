## 1. 输入、输出和内部治理边界

语言知识有两条使用方向：结构化表达目标→描述结构→语言材料，以及语言材料→描述结构匹配→候选含义。两者共享类型化含义、角色约束和组合规则；解析搜索与输出取材不是同一个算法。

共享概念语义的目的、信息对象指称、组合限定、结构缺项澄清及事实地位按[7260](7260_子规范_语言与认知共享概念语义.md)执行。本文继续唯一展开有限解释、取材和双向转换算法；新增语义目标不代表现有解释器已覆盖全部表达，不授权私有对象格式、无类型查询或语言直接写业务状态。

代词两向使用共享1110规定、由语言owner在自然语言世界维护的代词概念定义（7233第3节）和7233的类型化约束；输入索引、输出索引与焦点缓存只帮助召回，不另存一套代词含义。自然语言场景承载描述/规则/问题及指代实例；现实场景中的事实仍由对应领域裁决。调用期解释与按请求保存语言场景是两个步骤，后者也不授权写入被描述的现实对象。

三场景分工（2026-11-12 用户裁决，R114）：外设场景由外设类管理，记录和执行事实（如窗口收到的消息、输出队列中的问话）；语言场景把自然语言转换为内部世界可以认知的信息（场景信息、问题及其答案，第5.5节）；内部场景读取外设场景与语言场景自动生成的事实信息，并按需求写入（如父任务把问题的答案写入被认知需求，5260第5.2节）。语言owner只维护语言场景中的信息，不写被认知需求。

第4.3节另行固定无交互上下文的基础句型路径：它可以将唯一解析与空白语言场景中的匿名存在组合交付；这是显式请求的语言信息转换，不是现实对象检索，也不意味着主张已持久保存。纯概念构式可以直接交付含义而不建立场景。一般交互的指代、共同知识和确定对象指认仍适用原规则，不作为该基础路径的前置条件。

自然语言解析、表达规划、名称选择、指代、匹配、规则学习是DATA外内部治理功能，不因是函数就全部注册为现实动作方法。外部发言、发送消息、设备播放等实际动作按0050/5360的调用与授权边界执行；语言生成器不直接发送或调用文中提及的方法。

本规范定义有限结构解释器，不定义任意中文理解能力。支持集合以可读的具名知识定义和已实现的语义操作为准；未知构式返回未理解/部分理解，不能交给无约束脚本执行。

## 2. 可执行解释的有限含义结构

### 2.1 引用、值和作用域

```text
含义网（一个语言场景一份，第2.2节）
  内容单元   = 静态单元 | 事件单元
  内容算子   = 否定 | 条件 | 引述 | 态度 | 量化     // 各作用于一个明确的内容引用，可嵌套
  篇章组合   = 文本顺序 | 时间顺序 | 并列 | 转折 | 因果 | 目的 | 说明
  表达用途   = 陈述 | 疑问 | 祈使 | 招呼           // 每个语言出现顶层一个
  跨场景引用 = 回应 | 引用

参数 = 已绑定强类型引用 | 指代实例 | 规则角色变量 | 查询变量 | 类型化值 | 明确未知
```

单元、算子内容和组合都可作为内容被引用；内容引用无环，局部编号唯一。表达用途说明说话者用这段话做什么，等价于说话者对顶层内容的态度：陈述是“说话者的陈述”，不是世界事实标记；疑问的受询者、祈使的受请求者默认是受话者。表达用途不替代内容内部的持有者、提出者、受请求者、原说话者等角色。否定必须指定否定哪个内容；“没有观察到”不能归并为“确定没有”。条件假设不发布为现实，引述保留原说话者与材料范围。

招呼是说话者向受话者发起、维持或结束交往的表达，如“你好”“嗨”“再见”。招呼的顶层内容可以为空或为招呼套语，不携带陈述主张，不提出询问，不构成请求；带有询问内容的说法（如“请问有什么可以帮到你吗？”）按其内容为疑问。输入侧收到招呼只保存为场景信息（对方在场并开始交往的信号），不形成需求；输出侧的招呼由出站本能（如建立连接，5380第3.2节）经表达组织知识产生（R110）。

查询变量标明待求的角色/内容；明确未知表示已确认此项尚无知识；规则变量在具名规则作用域内受约束并被共享使用。三者可作为自然语言场景内规则、查询或描述信息的内容，不取得虚构现实存在身份。变量以所属规则/查询和局部编号定位；复用规则必须重新映射局部变量，不能跨作用域串用。值使用原领域类型、单位、值表示与准确值合同，不能用字符串“红”“高”填充缺失准确值。第4.3节的规范十进制字符串是整数的精确表示，不是缺失领域值的文本替代；真正构造领域准确值仍走所属领域合同。

### 2.2 统一含义结构

下列结构是含义网的参数签名，不是DATA新关系类型表。正式写入必须由相应对象应用/owner裁决，不能将结构种类数值直接写成L1关系。

**静态单元**：主体、谓项，可选时间与范围。谓项三选一：

| 谓项 | 含义 |
| --- | --- |
| 特征值 | 正式FT及准确值、值域、概念条件或方向；准确赋值与概念条件互斥标记。复合特征条件主张（主体满足已发布复合特征类型CF的值域条件）属于此类 |
| 概念归属 | 对象属于某概念，或下位概念属于上位概念；实例归类与概念上下位由参数种类区分 |
| 同一指认 | 两个指称候选是同一对象；只表达同一性主张，不合并稳定身份 |

组成、场景包含、需求目标字段、任务与方法的特征等，在语言层统一表示为“特征值”谓项。**特征化只是语言层投影，不改变底层权威结构**：读取与采用映射到对应领域的正式结构和公开入口，例如“所属整体”F与组成关系共同维护而不替代组成关系（1140），场景成员走场景服务，需求字段走需求owner，概念归属走概念信息判定。

**事件单元**：由以下三部分组成，至少出现一个；不得为填满结构补造动作或因果。

| 部分 | 角色 | 说明 |
| --- | --- | --- |
| 动作发生 | 主体（可缺）、已登记动作概念、按动作定义的对象角色、方式（尝试/完成） | 尝试不蕴含结果；动作概念未登记时保留原文与缺口 |
| 状态变化 | 对象、FT、前值（可缺）、后值或方向（可缺）、时间 | 允许没有已知动作，例如“水温从三十降到二十” |
| 关联主张 | 动作发生→状态变化 | 只在原文给出依据时成立；是语言主张，不确认客观因果 |

**内容算子**：作用于一个明确的内容引用，可以嵌套。

| 算子 | 角色 |
| --- | --- |
| 否定 | 被否定内容 |
| 条件 | 前件内容、后件内容、共享角色映射；方向固定为前件成立时主张后件，不确认现实中前件或后件成立 |
| 引述 | 原说话者、被引述内容 |
| 态度 | 持有者、态度种类、内容；种类为：需要（持有者为需求主体）、期望、请求执行（提出者、受请求者、行为内容）、请求达成（提出者、受请求者、期望状态内容）、询问（询问者、受询者、含查询变量或疑问指代实例的被询内容、确认范围） |
| 量化 | 量化方式（全称/存在/任指）、变量、具名限制域、谓词内容、绑定范围；数量限制另带类型化值域（第2.4节） |

受请求者显式保存，不总等于受话者，例如“请让机器人拿杯子”。同一请求可以同时含请求执行与请求达成，两部分分别保存；“尝试连接一次”只有请求执行，不推出期望状态。

**篇章组合**：子项为单元、算子内容或组合，形成树。

| 组合 | 说明 |
| --- | --- |
| 文本顺序 | 只表示原文排列 |
| 时间顺序 | 事件先后，须有语言依据；叙述顺序不等于时间顺序 |
| 并列 | 不蕴含先后 |
| 转折 | 前项、后项；后项与前项预期相反或对比（但是、却），不蕴含因果 |
| 因果 | 原因、结果；语言主张，不是因果知识 |
| 目的 | 行动、目的 |
| 说明 | 被说明项、说明项 |

**跨场景引用**：带类型地指向其它语言场景的单元或指代实例。回应：回答、确认所指、赞同、纠正、拒绝请求，被回应项是另一场景的询问或请求内容；引用：如“刚才说的那杯”。

旧操作名与本结构的对应：

| 旧操作 | 本结构 |
| --- | --- |
| 概念归类 | 静态单元，谓项＝概念归属 |
| 特征描述、复合特征条件主张 | 静态单元，谓项＝特征值 |
| 对象指认 | 静态单元，谓项＝同一指认 |
| 组成描述、场景包含、关系描述、状态描述 | 静态单元（特征值投影，采用走领域正式结构） |
| 变化描述 | 事件单元的状态变化 |
| 因果描述 | 因果组合，或事件单元的关联主张 |
| 需求描述 | 态度“需要”（陈述某人的需求），或态度“请求达成”（说话者提出），按说话者与需求主体角色区分 |
| 任务描述、方法描述、能力描述 | 关于任务、方法、能力的静态单元；方法步骤用组合 |
| 信息请求 | 态度“询问” |
| 行动请求 | 态度“请求达成”或“请求执行” |
| 条件联系 | 条件算子 |
| 量化限定、群体作用 | 量化算子；群体作用的整体/逐项/互指规则保留在角色映射中 |
| 并列/顺序组合 | 并列、文本顺序或时间顺序组合 |
| 语言回应 | 跨场景回应 |

“是”至少可能对应归类或指认，“有”至少可能对应特征、组成或场景包含，“会”可能是能力或未来预期。必须由整个结构及强类型参数判断；没有唯一解释就返回候选，不建立一词一关系永久表。

“`E1 有事`”是单独构式，其含义为`E1`满足复合特征“有事”`CF1`的值域条件。`CF1`是由多个不同特征类型构成的复合特征，只在特征类实现（4120、7165）：分量至少包括“承担任务”（任务`T`→`E`的承担角色，不使`E`成为任务owner）与“任务活动状态”（参照时刻`T`未处于已完成、已失败、已取消），值域条件为满足组合的任务数`>=1`；具体分量和种子由4120与7250给出。复合特征不是存在，不与存在概念混同。`E1`可为任意存在；`CF1`的定义不含该存在身份，也不含某个具体任务。输入先确定或保留`E1`的指称，再按已登记规则形成带来源、陈述者和作用域的复合特征条件主张（7232第5节）；不为理解这句话核查对方是否真的有任务，不生成匿名任务，不在3200正式任务集合、现实存在实例特征或概念世界支持边写入肯定事实。`E1`未唯一绑定或`CF1`未能完整读回时保留相应未决/缺口，不能任取对象或临时拼造正式概念。

输出可以从已采用的这类语言主张复述“`E1 有事`”，但必须保留其主张来源和表达立场；若表达目标要求陈述已核验的现实事实，则需从相应主体的有类型任务集合提供者取得成立证据。现行3200的`查询活动任务()`只可作为自我正式任务的求值来源，不能借此证明任意第三方有事或没事；第三方无任务提供者时实际求值为未知，不影响其有来源主张的理解和保存。语言理解、主张保存、事实核验与任务建立是四个不同步骤。

以上结构用句法角色和强类型数据区分含义，不新增持久词性/信息入口类型。它们是受支持结构的有限集合，不是代词八分类或自然语言用法的永久全集。所有扩展必须具名增加参数签名、匹配与求值合同；学习算法只能组合已有操作，不能从新词面发明可运行操作。定义已正式化而对应解释器尚未实现时，返回能力缺失，不能宣称已有运行支持。

### 2.3 条件和取材的有限集合

条件只允许：角色已绑定、角色类别匹配、概念约束匹配、引用相同/不同、字段已知、字段精确相等、正式值比较、明确存在的关系、集合数量约束，以及这些项的AND/OR/NOT。每项求值为成立、不成立、未知或技术失败；NOT未知仍为未知，不把技术失败当不成立。构式示例的复合槽位须展开为这些有限类别条件；多角色的配对限制须按完整合取分支求值，不能分别命中各角色的允许集合就认定组合合法。条件 OR 只用于规则适用性，不等于自然语言内容中的“或”。输入若仍有多个合法绑定或含义须保留候选，不能按分支顺序选首项；输出须核验实际绑定所属分支，未知条件不能当作成立。

AND/OR子项均为非空有序组，先完整求值各项；不以逻辑短路隐藏技术失败或未覆盖范围。任一子项技术失败，整体返回技术失败并保留实际失败项；资源不能完成必要范围时返回资源失败，不继续计算逻辑结论。在全部子项无技术失败时：AND含不成立即不成立，全成立才成立，其余未知；OR含成立即成立，全不成立才不成立，其余未知。NOT交换成立/不成立，未知保持，技术失败原样传播。目标的适用条件组为空表示无附加条件，不用空AND/OR猜默认值。

正式值比较由所属特征比较应用返回结果；不在语言规则内重写坐标/颜色/轮廓算法。条件求值只读，不修改概念、特征或知识。

取材只允许以下具名算子，完整范围遵守0050第3.2节：

1. 绑定角色：取得调用方提供并核验的强类型输入。
2. 读具名字段：由对象公开内容读取投影选取签名允许的字段；字段缺失不得反射猜取。
3. 枚举具名关系：经相应只读服务取得完整成员、事件或组成，保留来源、顺序和未覆盖范围。
4. 过滤、按具名字段分组：按上述条件筛选；未知项另列，不丢弃后伪称完整。
5. 排序：源材料顺序、正式执行步骤顺序、可比较事件时间、调用方明确的叙述顺序。时间相等保持无先后，技术身份只用于稳定展示，不推导因果。
6. 投影与子目标：从已有字段/关系形成子含义，交子规则表达。

不得在知识中保存SQL、任意字段名路径、脚本、函数地址或网络调用。每个具名字段/关系选择器必须有静态的输入类型、输出类型、公开读取提供者和失败映射；提供者未实现就返回能力缺失，不静默返回空集合。

### 2.4 指代、量化与群体组合

1. 定指表达按定义、修饰和作用域求唯一对象或范围明确的集合；缺少指示/角色材料是指代未决，不自动转换成一个未知存在。焦点只提供候选或可核对依据，不能覆盖类型、限定词和来源。
2. 待求表达先建立有类型、有作用域的变量，再由整句确定是否构成信息请求。“我不知道谁负责”中的待求内容不自动变为向听者提问；“谁先到谁先选”在条件和结果中使用同一变量。所属构式缺少知识时返回缺规则，不因识别出“谁”就猜整句含义。
3. 量化限定的输入须给出变量、限制域、量化方式、谓词和绑定域。匹配先核对这些项并统一变量；缺项保留候选。解释完整时可保存规则而不枚举实例；实际对已知有限域求值才逐项代入，并按2.3先完成本次必要求值，工程失败或未完成不得被逻辑结论掩盖。在此前提下，全称有反例即不成立，存在有见证即成立；肯定全称或否定存在必须有完整域和全部必要结果。空域的全称成立、存在不成立，二者都不宣称域内有成员；未知成员、未知条件和工程失败不得被当作完整枚举。
4. 任指表示规则对满足限制的任意选取都适用，不是随便选一个候选便证明全部成立。开放域或未来成员可以参与规则描述，但缺少规则级证明时不能仅凭目前有限样本肯定全域。求值遵守2.3的技术失败独立传播和未完成边界；理解规则不要求现在完成求值。
5. 群体作用先核验集合范围与谓词输入类型：整体把群体作为共同参与角色；逐项才将谓词应用于每个成员；互指按具名构式规定参与方向、所需覆盖和自指限制。所有必需映射完成才解释成功，关系事实另由输入证据决定。没有具名互指规则不得推测边集合。
6. “所有学生一起搬桌子”中，全称限定群体成员，“一起”使搬桌子的参与方式为整体；不能推出每个人单独搬桌子。“三个人互相传球”也不默认每两人双向均有传球事实。语言含义成立和实际发生分开。
7. “自己”的绑定对象取所属构式允许的先行角色；多个合法先行项保留歧义。“我们”须包含本次说话者，是否包含受话者另按用法和语境判断；“咱们”也按采用定义核验，不能将两词设为全场景互斥的包含/排除开关。
8. 量化作为内容算子保存量化方式、变量、限制域、谓词内容与绑定范围，不压成角色属性；否定、引述、态度同样须指明作用的内容。

### 3.2 算法

0. **组织具体表达结构。** 正式表达需求先按7232第2.2节的表达组织知识组织成一份具体含义网，与语种无关；之后的各步只消费这份含义网选择表达知识、名称与指称，不再回到表达需求重新取材。
1. 固定表达目标与本次采用的当前可读材料；读取输入对象内容，分清现实事实、语言场景中的主张、预期、规则、提问与请求。需求/任务/方法直接从其正式对象取得可表达投影，不要求三类概念。
2. 按表达目的、含义操作、角色类型和语言从知识索引召回；精确读回全部候选定义及采用范围，匹配目标含义并求值条件。索引只召回。
3. 先排除不适用规则；多个可用规则若表达等价，按明确的详略要求、覆盖完整性、适用范围及定义身份稳定排序选择。排序只决定表达形式，不裁决真实含义；候选含义不同就返回歧义/缺材。
4. 基础结构绑定角色并选择名称/明确对象描述/合法指代；选择代词时，以目标、当前说话者/受话者、表达目的和参照条件求值同一份指代定义，形成完整表达及出现关联。内容组织结构按取材规则形成子表达目标并递归展开。请求详述任务时读取真实执行材料，不能用方法预测填补实际步骤。
5. 确定性实例指认须让接收方能够从角色、有效指示、前文或共同知识恢复同一目标；不能只凭系统自身焦点判断。代词不满足时使用已成立专名或更充分描述，仍不足就返回缺少指认材料；“桌子”等类名不能唯一定位多个同类实例。用于提问、条件或量化规则的变量则须恢复相同类型、限制、绑定域和共享关系，不要求已有具体答案。
6. 自底向上生成句段篇及范围对齐；检查必需含义覆盖、否定/条件/引语作用域、角色一致与来源，不添加输入中不存在的事件、原因或结果。
7. 返回生成结果。留存时作为新的语言材料经语言服务保存；发送/显示/播放由已授权通道执行并保留其实际结果。生成成功≠发送成功≠对方理解。

换说话者时重新依据角色选择“我/你”等表达，不交换所述参与者身份；引语内按引语角色表达，不能直接套用外层说话者。“杯子A/杯子B”等可恢复专名与代词可以并用；改用专名不改变目标，也不要求删除已有指代实例。

上述确定性指认要求用于表达某个既定对象。第4.3节输出的是空白语言场景中的局部角色结构，可以用来源概念名称表达匿名对象；回读须恢复相同构式、角色对应和主张，不要求靠类名找出某个现实E。输出仍须读取本次含义及场景中的已有绑定，不得借此省略角色、交换同类型的两个出现或虚构接收方已知的对象。

**文本单位与整段回读。** 输出以文本为单位：先把要表达的内容规划为含义网，确定组合及段落、句子划分，时间顺序只取自材料；首次提及用名称或描述，名称按7220取首选名称，后续指代须接收方可恢复。整段生成后按第4节整段回读，须恢复同一含义网；回读一致是必要条件，不能单独证明正确，正确性另须对照每个样例独立列出的对象、角色、作用域、单位与未决项。

### 3.3 正式表达需求与想/做分离

1. 语言功能接收的输入是经任务链执行的出站本能形成的正式表达需求（结构化表达目标、表达目的、来源关联），不是预先造好的标准句模板（3300）。现行代码中，字段询问的表达需求在出站本能本次调用内派生，不另建正式D或任务（`业务/字段询问.本能运行服务.cpp` `执行指定需求字段询问核心`，R109）。
2. 双向转换输出侧的产物是**候选话语**（可回读的文本材料），不等于已发送，也不等于对方已理解；语言生成器本身不发送、不入列。
3. **想／做不拆分**（用户2026-11-08裁决，R109按代码）：出站本能在同一次执行内完成组织→成文并唯一回读→fresh复核材料→建立动作→留档出站具体表达→入列（同上函数）。“发送判断”即任务执行前既有的执行冻结与执行许可核对，不另设发送本能。生成成功≠入列成功≠对方已读。
4. 对方回答的理解属于输入侧：语言模块形成带来源的理解材料，保存为场景信息；理解成立不等于字段已写回或需求已完善。字段询问的答案按第5.5节由结构比对确定，再由提出补问的父任务读取并经需求owner写入被认知需求（5260第5.2节），不是独立本能，也不由接收需求认知服务写回（R114取代R109所记现行代码写回路径）；指代澄清、归类、分界的写回本能按第5.3节及7250，代码尚未实现。

## 4. 输入操作

### 4.1 请求与结果

输入请求包含固定材料及范围、语言选择、当前交互上下文或明确无依赖、所允许的只读对象查询范围和本次完整处理范围。结果返回已覆盖范围、候选含义组、角色绑定/未决组、所用知识及来源对齐、可供后续应用处理的类型化提议，不包含语言器自授的现实世界或任务写入资格。基础句型按第4.3节可另返回实际建立的语言场景和匿名存在。

“理解成功”只指在当前受支持规则及完整查找范围内形成唯一、角色一致的含义；完整候选数不足以证明世界为真。唯一含义可以含合法查询/规则变量，尚未获得答案不等于未理解。确定性指认仍有多候选则保持待解；解析技术成功但含义多项，结果仍为多义待解。

### 4.2 算法

1. 保留原始材料并确定语言；先形成句段边界候选，标点只是边界线索，引号内标点不自动截断外层意义。
2. 通过已知词条/概念名称匹配形成词序候选；未知处可调用具名外部分词服务取得候选，或保留未知范围。外部服务是可选辅助，不取得词义裁决或执行权。分词不强制产出词性。
3. 召回结构规则并进行完整匹配：每个状态至少包含规则定义、结构项位置、原文位置、角色环境与作用域。固定词项匹配词条/标点，角色项匹配合法范围与类型候选，子规则项递归匹配；缓存相同状态避免重复搜索，不以首个命中结束所有歧义检查。
4. 按7200/7210读回词条名称全部候选及目标强类型；结构词可由知识固定词项识别，不强制每个“是、有、因为”都命中世界概念。
5. 按完整指代表达取得/组合1110定义与7233特征约束，将“这个杯子”“那本书”分别形成调用期场景实例材料。先核对是否能复用同一作用域内兼容的已有实例，再寻找强类型目标或保留合法变量/未决候选；后续“它”也须核验本次约束。同目标不强制合并实例，同词面不强制指向同一目标；一般泛指类名不强制实例化，第4.3节中由构式明确要求的匿名对象角色另按该路径办理。
6. 结合场景、参与者、指示依据、修饰、数量和来源消歧，核对比较方向、时间、否定、条件、量化和引述范围。近远取向只能按已采用中心/规则解释，不能猜固定距离或采用焦点首项。句法和指代可按新约束再次收敛，不能采用不可回退的一次流水。
7. 用组织知识组成句段篇含义；保留事件顺序与叙述顺序。段落可能混合陈述、提问和请求，不按首句目的覆盖全部子句。
8. 对已理解项形成对应查询、规则或领域提议；定指未决、缺数据或技术未完成项保留来源和缺口。按保存请求可将语言场景、实例和采用解释交所属结构服务发布与读回，不先造现实节点再纠错；世界、需求、任务、方法仍由其应用入口处理。需要新增可复用概念定义时另交概念业务，不能在只读查询中写概念。

9. **文本切分。** 输入以一条消息或一段材料为单位：形成自然句边界候选，标点只是线索，引号内标点不截断外层；段落按换行。逐句解析后再组合，不因整段不能当作一句匹配就整体失败。
10. **篇章组合。** 衔接词由语言知识中的组合规则识别；没有衔接证据时只建立文本顺序；多种可能保留候选，不补出文本没有说的内容。
11. **指称顺序。** 指代实例先在本语言场景找兼容的已有实例，再按带类型的跨场景引用在近期语言场景中找，最后按交互上下文和查询范围找所指目标；多候选保留未决。无交互上下文时只建立篇章内共指，所指目标保持待绑定。
12. **部分理解的交接边界。** 已理解片段可以保存；只有外层否定、条件、引述、态度、量化均已确定的完整内容才形成第5.4节的主张草稿。外层未解释清楚时只保留片段和缺口，例如“如果温度超过四十度，就停止加热”只理解后半句时不得交成无条件需求。

### 4.3 无交互上下文的基础句型相互转换

本路径处理7250第2.3节具名的六种构式（含义按第2.2节表示：S01、S02为概念归属，S03为特征值，S05为“所属整体”投影，S09为确认范围是主张成立与否的询问），每次以一个固定短语/短句为完整输入，不读取交互前文、焦点、现实场景成员或调用方预绑定的现实E。词条、概念、名称关系和语言知识是必要的共同基础，并不属于被禁止的交互上下文。含代词、修饰或复合句而所需结构未受支持时保留未支持范围，不在此路径猜所指或隐式扩展规则。

**输入及分派。** 主入口完整读取适用知识，按知识中的目标、角色类别和有序结构识别候选，再调用对应构式子函数；不能按“是/的”等单个字或知识标题选第一分支。内容词按已登记词条及正式名称关系召回对应类别的概念，功能词按知识中的固定词项匹配；词面最长匹配提供边界，不能替代整句结构及类别核验。各适用分支先只读形成完整候选，合并后核对构式、角色和来源；唯一前不建立场景，不因唯一词条而跳过概念或规则歧义检查。

**按句型收窄概念候选。** 限定范围由角色类别和另一已识别角色决定，不由焦点顺序决定：

1. `C1 是 一种 C2`中，两侧先限定为相同概念类别；特征概念还须属于同一FT根。`C1`多义时，以`C2`的严格下位范围过滤；`C2`多义时，沿`C1`的严格上位范围过滤；两侧多义则保留具有已知上下位支持的合法配对。完整召回名称后用已知图筛选与先检索限定范围等价，但须读完整必要范围。
2. 限定范围没有匹配时，退回对应类别的全局名称候选；全局仍有多个时，再用句型约束收窄。无已知图支持不能证明候选不存在或主张为假，须保留全局合法配对；仍有多个就一并返回，交后续交互消歧，不任选首项。完整全局也未找到时保留未知词/缺名称及来源，可交新概念提议；本次转换不自动创建概念或上下位边。
3. S03概念条件中，FT必须为正式特征类型，C须在该FT根内；S01按存在概念约束对象描述和归类概念；S05分别按两个存在角色的类别核验。各句型只能使用已有正式类型、定义和关系缩小范围，不能为消歧补造关系，也不能把S02的上下位筛选强套到组成或数值角色。

**匿名存在和含义交付。** 唯一解释形成后，写入前复核所用知识、名称、概念及候选仍一致；变化则停止本次组合，不用旧候选继续写。S01、两种S03和S05通过所属公开入口取得一个独立空白自然语言场景，按构式所需对象出现实例化已确认的存在概念：S01及S03各一个E，S05的部分槽和整体槽各一个E；同概念两次出现也分别建立，不因名称相同合并。E不要求专名，保留出现编号、来源概念和本次绑定即可。不查询它对应现实中哪一个对象，不生成临时专名或代词。概念归类、特征值描述和组成主张可以只作为调用期结构连接这些E；它们不自动发布现实特征、组成边或概念支持事实。S02及S09只组织纯概念含义，不为接口齐整强建场景。需要存储完整主张时再遵守7230的显式保存合同。

**整数槽。** S03整数的类型化字面值首版接受阿拉伯数字词法`[+-]?[0-9]+`，必须完整消费该槽；不接受小数、指数、分组分隔符或汉字数词。保留原词面；规范化时去正号和多余前导零，所有零写为`0`，非零负数保留一个负号，如`+0005→5`、`-000→0`。规范结果保存为十进制字符串，不经`int64`转换或机器整数范围截断。首轮FT采用现有知识中的I64标量特征类型角色；这只是FT类别约束，不把数字字符串宣称为已构造的领域准确值，也不在语言转换阶段按FT值域裁决真伪。数字由该类型化字面值规则识别，不要求每个整数先有独立概念节点；数码或位值的概念知识不由本条否定。

**确认问句。** 首轮S09仅在S02子含义外增加已登记的“吗”及提问作用域，不断言子含义成立。无交互上下文时受询者保持未给出，不从“吗”、默认self或当前窗口推断，也不为完成内容转换要求先绑定受询者。它不构成已发送问题或已经产生需求。

**反向生成与完成标准。** 从输入交付的类型化含义读取当前知识、名称及已有场景绑定，按同一有序结构生成实际文字；匿名对象以其来源概念名称表达，整数使用规范十进制字符串。将这份实际输出用同一基础结构解析器只读回读，须得到唯一且相同的构式、角色对应、概念/FT、规范值、作用域和主张；对象按本次出现映射核验，不新建场景/E，也不要求字符串逐字相同。多义、名称缺失、来源不可读、读取变化或含义不一致均不得返回完整成功。正向成功以完整唯一解释及所需场景/E正式读回为限；反向成功以实际文字唯一回读为限。两者都不证明现实采信、发送、对方理解或持久化恢复。多阶段写入失败保留已取得身份，清除依赖失败读取的候选，不能虚报原子回滚或交付假完整含义。

### 4.4 请求构式与语言证据

1. 入站“帮我…”是与“请你满足以下需求：”平行的**行动请求句式外壳（语言证据）**；它不是需求根，不建立需求，不改变3100父链规则。句面内嵌需求仍须走接收认知、资格与字段确定值合同。
2. “我”绑定调用期交互上下文当前说话者（获取服务对象需求信息路径上即服务对象；服务对象尚未正式确立时仍可按该说话者绑定），“你”绑定受话者；缺上下文不得默认自我、焦点或窗口。
3. 与7270的边界：7270规定虚词结构概念、表达模式与“指令↔提出需求”“请求执行方法／信息请求”的映射；本规范的态度“请求执行／请求达成”与“询问”分别对应7270的请求执行方法与信息请求，转换算法以本规范为准，结构概念形式以7270为准，两边不重复定义。

## 5. 提议转换与事实边界

| 语言所得材料 | 允许的后继 | 禁止的捷径 |
| --- | --- | --- |
| 指代、规则或查询变量 | 在自然语言场景中保存带作用域的实例/内容，合法目标经强类型引用关联 | 未绑定就虚构现实存在，或用活动目标槽改写此前出现 |
| 新词/概念说明 | 学习提议；按概念合同形成后再命名 | 词面或词性直接造概念，空定义冒充通用根 |
| 对象/特征/关系陈述 | 查找已有对象或交世界应用裁决来源与创建/更新 | 自动复制实例、用概念区间补准确值、写L1关系 |
| 状态陈述 | 同时交付C、E及FT/准确值/时间材料；不足就明确未完成 | 用self当前场景/时钟补未知C或事件时间 |
| 动态叙述 | 已有动态定位，或变化候选交动态应用验证合法端点/组成 | “走了”凭空生成两个状态；从叙述次序确认相邻 |
| 关系/比较 | 按现行RC/比较合同求值或形成关系主张 | 把语言中的比较主张直接持久化为二次特征实例；正式比较由特征比较应用求值，二次特征只按1180由状态/动态持有 |
| 因果句 | 已有因果引用或学习主张；按因果业务筛选证据 | “因为…所以…”一句话确认客观因果 |
| 外来需求/指令 | 服务/目标提议送self；处于父任务内的子目标按既有承接链 | 语言器确认需求、任务manager越权产生需求 |
| 任务过程 | 只读已有记录或形成带来源叙述 | 把叙述动作当成已执行，把“完成”词当正式任务完成 |
| 方法说明 | 与现有登记能力对齐后交方法学习治理 | 文本变成函数、预测当实际、句法顺序直接执行 |

正式“有类型未知概念”及原身份补全在2220/7140没有对应合同前，不得把语言变量当正式未知概念，也不得在语言转换器内直接建立概念身份。**不得以返回`概念形成合同缺失`后直接结束理解路径代替后续治理**：对字段理解中无法对应概念信息节点的**普通词条**，按3100统一形状提出归类子需求（目标信息节点＝该词条，目标特征＝“概念名称挂接”F，值目标＝已挂到存在／特征／动态根树下概念），与补问子需求同级，经自我确认进任务链；询问「X是什么？」、按「X是一种Y」写回语言知识、原句重述确认及循环检测见7250。**代词词条不走归类**：须指代消解落到自然语言场景目标；未决则按第5.3节提出指代澄清子需求。三种场景／上下文用语按1150唯一定义区分，不得裸称「交互场景」。类型已知、定义未知的概念合同见7250；该分支不阻断已有概念的输入、输出或规则学习。

提问不自动成为系统需求；只有self决定要解答并承接时才走需求/任务。接收、理解、同意、承接、开始和完成是不同事实，不由“收到”“明白了”等词自动互推。不得自动派生所有句子都需要一个任务。

### 5.1 服务需求的理解与重述确认

本节补充第5节提议边界，不把语言转换器变为需求或任务owner。服务需求描述须区分需求主体、目标信息节点、目标特征类型及目标约束（3100统一形状）；值/概念约束与比较关系或方向按需求目标合同表达，期望不得写成当前已成立的世界状态。

同一需求含义可以由多个句式表达；“希望”“想”“需要”等只有在相应语境下才可映射同一含义，由正式语言知识及角色约束确定，不在转换函数中硬编码同义词触发清单。后续学习可以增加表达知识，但不能改变含义或自行发明执行操作。多个候选须消歧及绑定后形成本次唯一理解；唯一理解不代表对方已确认，也不合并不同主体或不同请求身份。

流程为：外部文字→候选含义→消歧与现实对象绑定→由需求能力承载待确认内容→从该节点内容生成自然语言重述→交服务对象确认。不得只回显原文代替对内部理解的确认；确认必须对应具体节点和内容，内容改变后重新确认。确认后的需求引用关联服务对象需求特征；其物理字段组织与待确认生命周期由需求owner合同冻结，未具备时不得冒用“已确认需求”入口制造待确认节点。

需求目标子含义可为单值、闭区间、增减方向，或仅特征（目标形式未指定）。仅特征可先形成待完善被认知材料，但该材料本身不发布为服务对象需求特征当前引用、不建任务、不进查找方法；补形式经任务链补问取得：补问子需求的目标信息节点为该待完善D，目标特征为对应字段的“有确定值”关系（3100、5170），经自我确认后由任务推进，父方法不执行；不得因缺形式拒绝已合法的需求/行动请求结构。服务值是自我内部治理管理的特征值，只由6190的合法结算与时间衰减改变；外部需求无法使自我直接修改它，即使有人提出，自我也不会认可，至多只形成一个同名但不同的特征类型。

现有第4.3节S09仅为概念归类确认，不自动取得需求确认问句能力；语言场景匿名存在也不自动取得现实身份。内容确认、求助及自我承接分别处理，承接流程见[6120](6120_子规范_自我存在服务与生存基本因果闭环.md)。

### 5.2 无语义连接消息

6120的连接收发不要求语言理解。对同次连接过程的消息存在及收发顺序核验，不以本解释器解析成功为前提；也不能把无语义消息解释成人类身份、需求、确认内容或求助授权。

### 5.3 指代澄清问答

1. 需求必需字段要算“有确定值”，代词必须先完成指代消解并落到自然语言场景中的目标信息节点（或合法有界成员组）；仅有概念名称关系不算确定（1110）。
2. 指代未决时提出指代澄清子需求：目标信息节点＝该指代实例，目标特征＝该实例持有的“指代消解结果”F（7233第4节，语言owner维护；3100统一形状），与字段补问、归类子需求同级，经自我确认入任务链。
3. 消息种类另立“指代澄清”；询问与回答写回为两个本能，名称与登记见5360。澄清候选池只含自然语言场景中已提及的对象；多候选不得取首项。

### 5.4 主张草稿分派

转换只产出带来源的主张草稿，按“被谈论对象×主张类别”分派到对应owner的公开入口，不按单元种类一刀切：

| 内容 | 草稿 | 分派 |
| --- | --- | --- |
| 陈述：普通存在的特征值 | 值主张（说话者、来源、时间） | 存在owner（7232主张）；当前场景对象须先绑定现实存在 |
| 陈述：组成、场景成员 | 组成或成员主张 | 组成走存在owner组成入口，成员走场景服务 |
| 陈述：概念归属、同一指认 | 归类或同一性主张 | 概念信息判定或学习材料；同一性不合并稳定身份 |
| 陈述：某人需要 | 关于他人需求的主张 | 需求owner被认知需求入口；需求不按普通存在处理 |
| 陈述：任务、方法、能力、事件 | 对应主张；事件的动作、变化、关联三者分开 | 对应owner，只作材料 |
| 祈使：请求达成 | 需求目标（提出者、需求主体、目标信息节点、目标特征类型、目标形式与值） | 需求owner；目标对象未绑定时不交付可执行的具体对象需求 |
| 祈使：请求执行 | 需求目标＝该行为已执行（尝试或完成），附动作概念 | 需求owner；不推出结果状态 |
| 疑问 | 信息请求 | 内部按读取能力回答 |
| 回应 | 对被回应项的回答、确认、纠正或拒绝 | 输入侧不匹配问与答：回应与其它输入一样只保存为场景信息，不查出站询问、不判断在回答哪一问；问题是否已有答案按第5.5节由结构比对确定，补问的答案由提出补问的父任务写入被认知需求（5260第5.2节）。R109所记“字段询问回应关联自最近一条起逆序”由R110取代 |

| 条件、因果、目的组合 | 方法或因果学习材料；带条件的需求 | 方法、因果owner；带条件的需求由需求owner判断是否支持，不支持时保留材料 |
| 时间顺序＋多个请求 | 一个需求加有序子目标 | 需求owner；只有文本顺序时不建立有序子目标 |

请求只形成需求，经任务链查找方法、采用、执行；自我不直接执行本能。

### 5.5 问题与答案

2026-11-12 用户裁决（R114）：出站提问在语言场景中留下“问题”，答案按结构比对确定，不做文本匹配。

1. **建立问题。** 出站问句（如询问指定需求字段，5380第3.6节）留档时，问题就是提问方的补问需求（需求信息，可看作存在，不归属场景、不生成状态）。语言owner记录该补问需求与出站问句的对应及被问结构——被认知需求、主体、被问栏；不另建“问题”存在，不改写被认知需求。
2. **可作为答案的信息。** 由消息转换生成的值陈述等场景信息（接收来源语言场景，第5.4节），以及自我写入自然语言世界的信息。
3. **按结构比对。** 信息的主体与被问栏都与问题一致，且出现在提问之后，才作为该问题的答案。不做文本匹配，不以正文相似、最新一条或时间邻近代替结构比对；输入侧仍不查出站询问（第5.4节），比对由问题一方读取自然语言世界进行。
4. **写入答案。** 找到答案时，由需求owner在该补问需求上记“答案”项，引用该答案信息，并记录答案来源（不生成状态）：消息转换（交互者回答）或自我写入（自我找到）。多条信息都符合时均作为答案引用，是否采用由父任务判断（5260第5.2节第7项）。
5. **只确定答案，不写需求。** 答案写入被认知需求由提出补问的父任务在筹办中完成（5260第5.2节），语言owner不写被认知需求，也不判断该栏是否已完善。
6. **等待与唤醒。** 未找到答案时问题保持无答案；自然语言世界有新信息生成（消息转换完成或自我写入）时，唤醒以该问题或其所在交互为依赖键的等待检测，不轮询（5380第3.6节）。

## 6. 段落与文章组织

详述任务的典型组织为：关联需求目标→相关起始条件→有依据的实际步骤及实际结果→存在的问题/调整→最终结果与未完成事项。每项均可用7232组织项表达；无问题就略去可选项，实际结果未知就明确未知，不补造成功故事。

文章可以按主题或场景/时间分组，再调用段落规则。分组边界属于表达组织，不据此创建现实场景、移动现实存在或改变事件归属；需要保存自然语言场景时按其明确材料及结构合同办理，不把每个段落自动变成场景。相同事件被摘要和详述两次是两个表达出现，仍引用同一原始事件。

段落、文章的组织使用第2.2节的篇章组合：文本顺序只表示排列，时间顺序须有语言依据；只有文本顺序时不据此建立有序子目标或步骤。输入方向从局部已解含义和衔接证据反推组织候选，不能因某文章符合典型任务模板就补出遗漏步骤。输出规划不等于反向恢复完整现实；省略信息可以未知，不要求编造以实现字符串往返。

## 7. 完整执行范围与非成功

本次源文、适用规则、类型/关系范围、必要闭包、候选及表达目标共同确定必须完成的完整范围，遵守0050第3.2节。实现可以分批读取、缓存或统计用量，但不得以候选数、条目数、递归深度等资源额度裁剪必要范围并宣称成功。不能以极大额度冒充完整范围。

匹配递归必须前进原文位置或消费严格更小的有限子结构；组织递归必须消费尚未处理成员或严格更小的子目标。相同规则/输入范围/角色环境无进展再入立即返回循环错误，子规则静态引用环在发布前拒绝。资源不能完成完整范围时返回资源失败并清空依赖完整性的含义载荷，不能当未找到或通过缩小必要范围伪称完成。

结果至少区分：已接收未解析、完整已解、部分已解、多义待解、上下文不足、未知词、缺名称、缺规则、概念形成合同缺失（须接归类子需求，不得仅以此结束服务对象原话理解）、对象/读取提供者缺失、查询无匹配、格式失败、引用失效、读取漂移、资源失败、内部不一致。独立可完成项可返回明确部分结果；需要共同角色/范围的含义组不得部分提交为完整事实。

纯理解、输出规划和条件求值零领域写入。第4.3节的输入组合入口在只读候选唯一后显式建立所需语言场景/E，不属于纯解释器；其它语言场景/指代实例保存、概念定义形成、命名及现实事实裁决仍分别沿所属owner合同办理。已经保存原文或建立场景/E但后续失败不得说成零操作。下层失败保留原状态和来源，不包装成语言否定、无对象或代词特征值。

## 8. 验证矩阵

至少覆盖：同义不同句式、多义相同词面、同词多次出现、未知词与无名称分流、多人同类对象、引语内“我”、跨段省略、否定/条件/提问/引用不写事实；D/T/M直接表达而无新概念族；状态缺时间与动态缺端点；因果句只作主张；单句到段落到文章的源对齐；不同排序不造因果；查询空与未查完分开；循环与完整范围的资源失败；规则/名称已不可读时不猜旧定义；生成/送达/理解三分账。

第4.3节六构式另覆盖：不读取交互或现实对象上下文；多候选不建场景；S02限定/全局检索和无图支持回退；S03同FT根筛选及概念条件不补准确值；S05同概念两次出现建立不同E；整数正负号、前导零、负零及超机器整数长度；S09受询者空缺而内容可转换；反向只读解析实际输出、角色不交换、来源变化阻断成功。用例和运行结果分开，是否运行测试遵守AGENTS第7.1节。

指代专项至少覆盖：完整短语实例与后续“它”的复用；首次出现“你好/看那个人”；同词面不同实例、同目标不同实例；说话者互换和嵌套引语；缺参考中心的“这/那”；“我不知道谁负责”不自动向外提问；“谁先到谁先选”的同一变量；空域及开放域量化；集体搬桌子与互相传球不误推逐项/全配对；“我们/咱们”的不同包含用法；现实场景与语言场景分账；焦点更新、显式纠正与旧出现保真；接收方不能恢复时改用名称/描述或返回不足。

统一结构另覆盖：陈述某人需要、请求达成与引述三者的说话者、需求主体、受请求者区分；受请求者不等于受话者；无动作的状态变化不补动作；尝试不推出结果；外层条件、否定、引述未解时不交接内层内容；文本顺序不建立有序子目标；篇章内共指与所指目标待绑定分开；跨消息回应找回被回应项。

同一已知含义在输出后解析，比较的是角色映射、约束、作用域和明确省略项，不强求字符串一致。该往返用例与独立真实样本/反馈分别记录，不能自证语言能力可靠。
