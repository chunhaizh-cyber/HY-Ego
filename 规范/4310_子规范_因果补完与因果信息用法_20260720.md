# 4310 子规范 因果补完与因果信息用法

编号：4310
日期：20260901
版本：v0.5
状态：正式子规范

## 1. 定位

本规范定义从动态样本形成因果族、分支和模板的补完过程，以及因果在预测、筹办、学习、需求投影和结算中的权限。

直接上级规范：1190。

直接依赖规范：4210、4220。

相关边界规范：2220、4150、4240、4320、4330、5140、5250、5300、7140。

## 2. 主果变化锚点

新状态与相邻前状态形成状态迁移后，以主体、目标特征、初始/结果状态、比较模板、时间窗和版本建立主果变化锚点。锚点只说明“要解释哪个变化”，不直接说明原因、动作能力、任务完成或需求满足。

同一主果可以有多个并列因果分支，不得把全部样本求总交集后只剩背景条件。

### 2.1 动态序列分段与可比较组

自动因果发现先从已发布有序动态列表选择一个目标动态结构模式。模式匹配只使用可回查的主体角色、场景、特征类型、前后状态结构、动态规则版本和适用范围；具体动态实例身份彼此不同，名称、现有概念、词条、词性和显示相似都不能把多个实例判为“相同动态”。

目标模式的每次出现把有序动态列表分成一个带前置窗口、同窗和后置窗口的样本段；多个结构可比较的样本段形成目标动态正组。还必须取得在相同主体 / 场景 / 特征类型 / 版本范围内目标动态未出现的负组，避免把持续存在的背景状态或普遍动态误判为原因。可比较材料不足时只返回候选不足，不用已有概念或默认范围补齐。

每个样本段分别提取目标前已经成立的状态、前置动态、同窗动态和可选动作证据；跨正组与负组比较后，保留一个或多个前置候选组合、共同原因、替代原因、分化条件和反例。该过程只形成因果候选，不直接发布因果事实或因果链概念。

## 3. 候选条件收集

时间窗内材料按时序和来源分层：

- 结果前已成立：条件候选；
- 变化同窗：伴随原因、共同结果或分支候选；
- 结果后出现：后果或副作用候选；
- 时序不明：弱候选。

候选必须模板化为项目结构中的主体、场景、特征、状态、动态和动作关系，同时保留到原始证据的引用。地址、日志、字符串和 JSON 不参与交集。

## 4. 因果样本、分支和反例

自动分段得到的单个样本只是证据，不是已验证因果。样本加入因果族后，必须比较：

1. 多次正样本的共同条件；
2. 只在稳定子群出现的分化条件；
3. 条件出现而主果未出现的反例；
4. 禁止结果、副作用和不适用范围；
5. 时间、场景、主体和版本兼容性。

证据不足或反例多时保留并削弱、覆盖或淘汰候选，不删除历史证据，也不持久化“置信度”字段。稳定度、成功率和排序由基础计数和查询参数临时计算。

## 5. 两类因果

| 类型 | 最低结构 | 权限 |
| --- | --- | --- |
| 状态变化线索/因果 | 条件与状态迁移，动作未知 | 预测、前置、观察、学习和补证据线索；不能直接生成可执行方法 |
| 动作致变因果 | 条件 + 动作信息 + 结果状态 + 动态证据 | 主动动作且方法可回解时，可参与方法候选、执行前预测和归因 |

被动动作致变因果保留自动提交链关系，但不可主动召回。动作字段必须是可复现动态模式的动作身份，不是方法 ID、流程名或自由文本。

后补动作来源时新建动作致变动态和因果，并与原状态变化线索绑定同源证据组；不得改写旧线索类型。

### 5.1 因果链概念形成

一个或多个因果候选只有按 1190 完成条件、可选动作、结果、直接动态证据、适用范围和版本闭合并正式发布后，才取得直接因果事实身份。一次来源完整且角色闭合的证据可以形成实例因果；仅靠自动分段中的单个相关样本不能跳过该闭合。

概念抽象能力成立后，L5 之外因果抽象业务可以把一个或多个方向一致、版本兼容且连通的已发布直接因果事实组成因果链概念候选，并按 2220 / 4240 接入因果链概念根。持久链概念只引用直接因果事实和共享分支，不保存间接因果、固定层号或展开路径。应用给定目标、范围、版本和展开截止后，才按 4320 从直接拓扑取得本次分层投影；使用次数和投影命中不能反向改写链概念或原因果事实。

## 6. 因果使用权限

| 用途 | 状态变化线索 | 主动动作致变因果 |
| --- | --- | --- |
| 预测前置/后果 | 辅助 | 主要证据 |
| 反推方法 | 只能形成补动作/观察/学习缺口 | 条件、方法结构和证据通过后可形成候选 |
| 执行前审查 | 辅助 | 检查预期结果、风险和副作用 |
| 需求投影 | 形成候选草案 | 形成可干预路径候选 |
| 结算归因 | 不能单独结算 | 与同源结果状态、任务目标和副作用审查共同使用 |

因果只生成需求候选，不直接创建正式需求或任务；统一需求入口负责入树，任务领域负责承接和方法选择。

## 7. 被动因果

被动因成立后果应由提交/后处理/结算链自动出现。反推被动因果时只能得到需要的上游事实、条件和证据。因已具备而果缺失时形成被动链缺口，不创建“调用被动动作”任务。

## 8. 安全、服务和结算

安全因果距离只解释原因距离和需求优先级，不直接等于安全结算贡献。方法维护状态只说明处理安全任务的能力，不等于物理安全改善。

普通服务结果必须保留业务动作、结果状态、目标裁决、同源归因和副作用审查，并进入普通需求、任务、方法和正式结果链。它只形成需求满足及状态 / 动态 / 因果材料，不建立服务合同、支付阶段、准备补回或服务值账，也不得反向证明服务对象已受益。

结算因果验收至少输出可结算、仅候选、待补证据或禁止结算，并逐项列出目标结果、副作用、动作归因和同源证据。

## 9. 学习边界

学习层只能生成方法、动作、条件结果对、参数和证据候选或缺口，不能直接宣布方法好用、因果已验证、任务完成、需求满足或可结算。

尝试或练习必须有可验证收益链、真实动作入口和可观察后果；缺动作只能寻找动作、观察或外部信息。先天硬保护壳始终约束尝试，不是后天因果知识。

因果反推的动作节点必须落回具有明确输入、输出和动态落账的正式方法入口，否则只作为学习、观察、外部支撑或替代动作缺口。

## 10. 禁止事项

- 禁止单样本直接验证因果。
- 禁止状态变化线索伪装为动作能力。
- 禁止用置信度、解释词或文本作为因果本体字段。
- 禁止双账、双因果对同一变化重复满足或结算。
- 禁止因果直接建任务或越过需求/任务/方法领域权限。
