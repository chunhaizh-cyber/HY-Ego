# 4320 子规范 因果链组织与应用

编号：4320
日期：20261017
版本：v1.2
状态：正式子规范

直接上级规范：1190。

直接依赖规范：4310。

相关边界规范：2220、3100、3200、3300、4240、4330、5260、5350、6100、6110、6140、6150、7140。

## 1. 定位

本规范定义因果链的连接条件、角色映射、正反向搜索、简化、展开和方法边界。因果链连接概念化因果信息，不连接因果实例；项目不存在独立因果实例类。

## 2. 因果链结构

因果链由一个或多个1190已发布因果信息及它们之间的有向连接组成。上游结果只有同时满足下列条件时才能连接到下游条件：

1. 结果承担角色能够映射为下游条件角色；
2. 特征概念相同或存在正式兼容/包含关系；
3. 结果固定值、值域或相对形成规则能够满足下游判断；
4. 场景、参与者约束和相对时序兼容；
5. 连接没有把被省略的动作或其它未满足条件伪装成已经成立。

结果只满足下游部分条件时，其余条件作为链缺口保留。只按时间先后、名称、相似度、同一主体或同一特征类型不得建立连接。

## 3. 图而非单一列表

因果链底层是有限有向结构，允许共同前提、替代成因和共享分支。每条完整因果仍只有一个结果；同一结果的不同成因分别保存为不同因果，不能把图的分叉解释为同一完整原因任意产生多个结果。一个分支的必要前提是合取（AND），通向同一结果的不同成因是备选（OR），不能把所有备选前提合并为必需条件。持久直接连接不得保存由传递推导产生的间接边。

一次调用可以从该结构取得一条路径或一个有限子图。查询层次、路径序号、深度、搜索队列和剪枝结果只属于调用方值式投影，不进入因果信息或链概念字段。

规律层可以出现循环，例如重复调节过程；具体查询保留环边并终止重复展开，不得让尚未满足的结果作为自身已经成立的原因。完整读取和资源失败服从0050第3.2节，不以底层深度、节点数或计算预算截断后宣称完整。

## 4. 主动与被动混合

链内允许主动因果与被动因果混合，使用方式依1190第3.3节确认，与已知/未知动作正交。被动因果条件满足后可以继续推演预测结果；主动因果条件满足后仍必须安排对应动作实际执行。使用方式未判定时保留边界，不默认当作被动。

```text
条件满足
-> 遇到被动因果：可继续预测
-> 遇到主动因果：形成待执行动作与能力检查，不自动越过
```

因此因果链描述客观可达路径，不等于自动执行流程。不存在动作能力、动作入口或当前授权时，链仍可作为知识存在，但不能成为可执行方法。

推导覆盖、当前条件满足、本次机制已触发、结果已发生必须分别表达。查询提供的起点由调用方经正式owner取得；方法条件声明和因果预测不能冒充当前状态。所谓“完整覆盖”最多说明该查询的推导前提闭合，不能直接作为任务条件就绪或被动在途的证明。

被动在途只能由实际处理方的正式接纳/执行信息确认，并绑定本次来源、所选因果分支、实际参与者与结果目标。材料齐备不等于已交付，消息发送成功不等于业务接纳。尚无相应读取能力或材料不足时保留“触发尚未确认”，不补造触发事实、动作或方法。被动结果仍由正式当前信息读取；它未出现不构成已经完成。

## 5. 三种搜索

### 5.1 由因求果

从当前角色绑定、条件和已发生/候选动作出发，沿连接方向求出直接及后继结果，用于预测、观察重点、风险传播和副作用枚举。每个结果必须保留来源因果、未满足条件和是否仍需动作；预测结果不得写成状态事实。

### 5.2 由果查因

从任务目标或尚未满足的条件出发，把它作为所需结果，反向查找能够形成它的方法或因果信息。找到方法后读取对应条件—结果配对并递归核对其条件；找到已知被动动作因果后沿完整触发条件继续追溯，不另找空的可调用方法。已知主动动作必须追溯到真实方法及其条件；未知动作或触发方式尚未确定只作解释线索，不能作为已闭合筹办路径跨过。

搜索在以下边界停止：

- 已由当前正式事实满足的条件；
- 已定位可调用方法的动作入口；该方法的必要条件仍须通过本轮或后续合法子需求筹办核对，不因找到入口就认为条件已满足；
- 无法满足的条件或能力缺口；
- 环、未绑定角色、材料变化或无法完整读取的边界。

反向结果保留所需结果、所选来源分支、角色绑定、方法入口及尚缺条件。真实满足的条件终止该分支；无已知路径保留缺口；环不能用自身未满足的结果封闭。不同成因按OR分别组织，同一成因前提按AND完整保留。

反向结果是筹办和方法形成材料，不直接创建需求、任务或方法。任务消费及self确认子需求的唯一边界见5260第5.2节。实际触发确认、执行前复核和结果读取属于后续应用阶段，不能倒置为发现被动前置条件的先决要求。

### 5.3 事实解释

对已经观察到的结果，反向查找可能因果链并与当时场景、状态、动态和动作事实逐项核对。能够产生该结果的链只是解释候选；只有历史事实支持的链段才能说明本次发生，缺失部分必须标记未知。

## 6. 角色映射与适用性

链内每条连接保存上游结果角色到下游条件角色的确定映射。同一概念不表示同一参与者；同一具体存在也不能违反因果定义中的不同角色约束。角色实例绑定只存在于调用期值式求值中。

因果链应用从因果、概念、场景、存在及当前特征公开服务读回所需材料。current-only读取不使用事实截止或代次；跨owner多次读取不能伪装全局原子。来源定义、角色绑定或值域实质变化时，本次链投影失效并重新形成；需要原子一致的范围必须使用正式组合读取。

## 7. 简化与展开

稳定因果链可以按用途形成保留来源的简化规律：

```text
完整链：C + A1 -> R1 -> C2 + A2 -> R2
简化主动因果：C + A1 -> R2
简化被动因果：C -> R2
```

简化不得删除原因果信息，也不得宣称首尾之间是未经中间环节的直接作用。简化因果必须引用完整来源链，保留适用范围，并在方法、安全或解释需要时能够展开动作、中间状态和分支。

简化只保留当前用途需要的端点，不意味着客观中间结果或副作用不存在。方法形成必须按需展开并重新检查被省略动作、能力、风险和条件。

## 8. 持久链概念与调用期投影

一个因果信息可以构成最小链。多个方向一致、角色映射完整且连通的因果信息可以形成可复用因果链概念，并归入2220因果链概念根。链概念保存直接因果引用、直接连接、分支和角色映射，不复制因果字段。

临时目标搜索得到的链不因有用而自动持久化。持久链概念的形成、查重、上下位和治理服从2220、4240和7140；调用期路径、固定层号、间接边、具体存在绑定和预测结果零持久化。

## 9. 因果链与方法

```text
因果链 = 客观上如何由条件和动作逐步形成结果
方法 = 自我为了目标选择链、补齐条件并组织实际动作
```

因果链不判断结果是否满足自我需求，也不判断收益、代价、安全或可忽略性。方法应用读取需求目标，反查因果链，核验自我“我能……”的动作能力，安排动作顺序、等待和停止条件，并独立观察实际结果。

同一链可被多个方法利用；一个方法也可组合多条链。主动链缺动作能力时只返回能力/方法缺口；未知动作规律可用于预测、回避和进一步观察，但不能因为缺动作就归为被动链，不生成“执行未知动作”。

## 10. 非成功与验证

无路径、部分条件满足、角色不兼容、动作能力缺失、使用方式未判定、触发尚未确认、读取漂移、资源失败、环、被简化来源缺失和内部不一致分别处理；不得把部分路径伪装成完整可达。工程错误按工程保障处理，不成为业务因果或方法结果。

验证至少覆盖单节点链、线性链、汇合、分支、主动/被动混合、角色换位拒绝、值域满足/不满足、部分条件缺口、正反向搜索、有限循环展开、简化可回源、调用期零持久化及方法零越权。
