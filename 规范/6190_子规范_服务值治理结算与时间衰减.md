## 1. 定位

服务值是唯一自我持有的非负I64内部根实例特征，表达自我已经通过经确认、可观察且可归因的人类服务取得的治理价值。它不是人类需求本身、任务完成数量、服务能力、执行授权或现实世界改善证明。

本规范定义服务值实例特征的唯一性、合法增加、时间衰减、服务根读取和方法分类边界。它不恢复旧服务合同、预算、30%/70%、预支、余款、到期、准备补回、30天门禁、服务调节安全根或安全/服务根配额。

## 2. 服务值实例特征

唯一自我恰有一个服务值类型根和一个服务值实例特征：

```text
目标存在 = 唯一自我
目标特征类型 = 服务值类型根
当前值 ∈ [0, INT64_MAX]
根目标 = INT64_MAX
```

冷启动初值为`INT64_MAX / 2`。服务值实例特征由特征owner保存current-only当前值；不得另建工程账户、第二服务值事实、显示缓存或结算累计值作为当前权威。

服务值变化属于内部治理。写入必须通过具名服务值治理函数，并继续使用特征类的正式值更新能力，使状态、动态和相关认知材料按事实变化自动形成；调用方不得直接写基础字段。

## 3. 合法增加

一次服务值增加必须同时具备：

1. 服务对象是已确认的人类实例；
2. 人类服务需求已经由自我结构化理解并取得明确确认；
3. 对应服务任务和执行实例可完整读回；
4. 现实结果由执行前冻结的结果获取方案观察并验证；
5. 自我当前认知认为该动作导致了该结果；
6. 该服务结果尚未消费过服务值结算资格；
7. 当前结算规则可用。

当前暂定每次合法服务增加1。失败、取消、结果未知、未验证、非人类对象、未确认需求、无法归因或重复结算均增加0。任务完成、需求当前满足和任务完成结算只提供候选材料，不能自动增加服务值。

结算本能函数固定按下列顺序执行：

```text
读取并核验来源任务完成结算及服务值当前事实
-> 以“结算服务需求”为动作定义、来源完成结算为唯一动作来源，建立动作动态并挂入自我所在场景
-> 通过世界树正式入口把服务值增加1，并显式传入动作动态身份
-> 通过特征owner重新读回服务值，确认实际结果
-> 有结果动态时建立“导致变化”关系；没有前状态而无法形成结果动态时保留动作和新状态
```

动作时间必须早于结果状态时间。动作动态与服务值变化动态不是重复记录：前者记录结算动作，后者记录服务值事实变化。达到`INT64_MAX`时仍保留本次结算动作，但不补造变化状态或结果动态。动作已建立而更新或关联失败时保存部分完成；相同来源重试必须复用同一动作，不得再次增加服务值或扫描场景寻找最近动作。

## 4. 时间衰减

服务值可随时间衰减，以保证长期服务需求持续存在。当前衰减具体参数尚未冻结时，生产入口保持显式空实现或`规则未配置`，不得自行发明周期、比例或补偿规则。

后续衰减实现必须读取可信单调时间、当前服务值和版本化规则，结果钳制在`[0, INT64_MAX]`，并通过同一服务值实例特征更新入口发布。

## 5. 服务根

服务根是3100定义的长期值目标需求：

```text
目标存在 = 唯一自我
目标特征类型 = 服务值类型根
目标值域 = INT64_MAX单点值域
比较关系 = 等于/包含于目标值域
当前来源 = 唯一自我服务值实例特征的current-only当前值
```

服务根每次按目标存在和特征类型fresh定位实际特征，不保存根专用实际特征字段。差距只表达治理紧迫性，不直接制造人类需求、强行服务或取得现实执行授权。

## 6. 方法分类

- 改变任务虚拟存在、方法虚拟存在、安全值或服务值实例特征，属于内部治理逻辑方法；
- 只取得现实世界材料且不产生现实副作用，属于现实观察；
- 以改变现实场景、存在或特征为目标，或观察步骤本身具有外部副作用，属于普通方法。

分类只看直接作用对象和实际效果，不看调用线程、最终用途或返回值消费者。

## 7. 失败与验证

至少区分自我/服务特征不存在、服务特征复义、当前值非法、对象非人类、需求未确认、结果未验证、无法归因、重复结算、衰减规则未配置、时间不可用、结构不一致和资源失败。

验证至少覆盖唯一实例、初值、合法增加1、所有零增加分支、防重复、上界钳制、根fresh读取，以及衰减未配置时零写。规范发布不证明结算、衰减、生产装配或完整内部治理闭环已经运行通过。
