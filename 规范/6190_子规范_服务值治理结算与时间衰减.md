## 1. 定位

本规范定义服务值的工程治理账户、合法增加、时间衰减、根需求读取和方法分类边界。它不恢复已经退出的服务合同、预算、30% / 70%、预支、余款、到期、准备补回、30天门禁、服务调节安全根或安全 / 服务根配额。

服务值表达唯一自我持续为人类提供有效服务的治理结果，语义主体是唯一自我；它不是世界树中自我存在持有的普通实例特征。服务值目标和当前值由工程中的唯一服务值治理模块持有、解释和修改，自我线程、任务、方法、显示、日志和世界特征owner都不是第二写入方。

## 2. 服务值治理账户

全项目只有一个绑定唯一自我的服务值治理账户。账户至少包含：

```text
唯一自我身份
+ 服务值治理度量标识
+ 当前值 V
+ 目标值 M
+ 上次维护的可信单调时间
+ 当前衰减规则版本
+ 当前结算规则版本
```

规则固定为：

1. `M = I64_MAX`，`0 <= V <= M`；目标是工程冻结的治理常量，不是自我存在的特征值。
2. 冷启动首次值继续使用`M / 2 = 4,611,686,018,427,387,903`，由服务值治理模块建立或精确复用；它不形成自我实例特征、存在当前采用、世界状态或世界动态。
3. 服务值治理度量标识只解释账户数值，不是FT、特征概念或实例特征，不据此为自我补建服务实例特征。
4. 账户以唯一自我为语义主体，但物理持有者和唯一写入方是服务值治理模块。读取必须同时返回唯一自我绑定、当前值、目标值、上次维护时间和两项规则版本；部分返回不得冒充成功。
5. 服务值变化属于内部治理事实。服务值账户不能反向证明某个人类需求已经满足、现实世界已经改变或某个方法已经成功。

## 3. 合法增加

服务值只有在人类的真实服务需求已经实际满足后才能增加。一次增加必须同时具备：

1. 服务对象是已确认的人类存在；
2. 服务对象已经提出或确认具体服务需求，自我没有猜造、强加或替代其需求；
3. 该需求已经转换为自我的具体服务需求，并由唯一任务和实际采用的方法推进；
4. 现实观察或其它合法结果渠道取得服务前后事实，证明服务对象目标特征确实改善或达到目标；
5. 影响评估、权限、安全边界和动作归因均成立，且结果能够归因于本次服务；
6. 同一正式服务结果尚未被服务值治理模块消费。

任务完成、方法返回、消息发送、请求接收、服务对象存在、循环次数、任务数量或无反馈都不能单独增加服务值。缺少服务对象、确认需求、真实结果、改善证明、归因或防重复条件时，只能保留相应事实或缺口，服务值零增加。

每次合法服务结果的增加量由当前服务值结算规则给出。结算规则未冻结、无法完整读取或不能对本次结果求值时不得猜测`1`、权重、比例或默认增加量；只返回结算规则缺失。服务值增加不改变安全根值，也不取得新的现实执行授权。

## 4. 时间衰减

服务值随可信单调时间衰减，用来表达过去服务不能永久替代当前持续服务。对任一维护区间`[t0,t1]`，当前规则形成非负衰减量：

```text
D = 衰减规则(规则版本, t0, t1)
G = 本区间已合法结算的服务增加量
V1 = clamp(V0 + G - D, 0, M)
```

其中：

1. `t1 < t0`、时间来源不可信、规则版本缺失或规则无法求值时不得修改账户，也不得把衰减量猜成0。
2. 权威读取和结算在返回当前值前必须收敛到同一维护时点；可以按需惰性维护，不要求仅为衰减常驻轮询线程。
3. 当前值、上次维护时间和本次结算 / 衰减结果必须作为一个不可分割的账户变化发布。失败保持旧账户和旧维护时间，不允许只推进时间或只写数值。
4. 达到`M`只表示该维护时点当前满足；后续时间衰减可以再次形成正差距，不构成永久完成。
5. 某一时间窗中`G > D`只说明该时间窗净增加；它不是在没有合法人类需求时制造需求、强行服务或绕过安全边界的命令。
6. 具体衰减函数、时间单位和当前规则版本由工程运行配置冻结。在这些参数尚未冻结并完整读回前，时间衰减入口保持不可用，不得恢复旧完整秒、30天或服务合同算法作为默认实现。

## 5. 服务根需求

服务根是长期维护目标，不是一次完成后退役的普通任务目标：

```text
当前来源 = 服务值治理账户的current-only当前值
目标来源 = 工程冻结的M
差距 = M - V
```

`V == M`表示本维护时点当前满足；`V < M`表示存在增向差距。服务根永久保留，当前满足不删除根需求，时间衰减后重新读取即可再次发现差距。

服务根差距本身不能证明存在服务对象或具体服务需求，也不能授权接触、打扰或改变任何人。没有真实服务触发时，只能形成监听、服务机会检查、能力校准或等待材料；涉及外部通信、主动探测或其它现实副作用时仍须另有具体需求、普通方法和现实执行授权。

人类确认的具体需求经self裁决后形成服务根下的具体服务需求。服务任务完成后仍必须按第3节独立取得现实结果、改善证明和归因，才可提交服务值结算；服务值结算完成后由self fresh读取根账户决定下一步，不以任务完成状态代替账户当前值。

## 6. 方法与自动事实边界

方法按直接作用对象和实际效果分类，不按调用它的线程或最终用途分类：

- 读取内部正式owner事实通常是服务调用，不因被任务使用就自动成为方法；改变任务虚拟存在、方法虚拟存在或安全 / 服务治理账户属于内部治理逻辑方法或内部治理后处理。
- 仅取得现实材料且不造成可观察外部改变的是现实观察方法。观察结果供内部治理使用，不会因此变成内部治理方法。
- 预期或可能改变现实世界场景、存在、特征、外部系统或外部主体的是普通方法。发送探测消息、设备运动、外部通信和写外部系统即使目的是获取信息，也属于现实改变步骤。
- 普通方法不得直接改写世界树当前值来自证成功。现实结果由合法观察渠道取得，世界事实owner据此更新；状态、动态、因果和概念再由各自owner按事实变化自动形成或维护，不作为本能函数直接修改的目标。

## 7. 失败与验证

至少区分：账户不存在、唯一自我绑定错误、值域错误、目标错误、时间不可用、衰减规则缺失、结算规则缺失、非人类服务对象、需求未确认、结果未取得、改善未证明、归因失败、重复结果、资源失败和内部不一致。任何非成功都不得部分增加服务值、部分推进维护时间或补造现实事实。

最低验证覆盖：首次账户建立、重复精确复用、唯一自我绑定、当前值与目标值不进入自我实例特征、合法人类服务增加、任务完成但未验证零增加、非人类与未确认需求零增加、重复结果零第二增加、可信时间衰减、时间倒退零修改、规则缺失零修改、上限与下限钳制、同次增加与衰减原子发布、达到上限后再次衰减、无服务机会时不得强行服务，以及内部治理 / 现实观察 / 现实改变三类方法不混账。

本规范只冻结机器语义，不证明服务值账户、结算规则、衰减规则、时间提供者、代码、迁移、装配或运行闭环已经实现。
