## 1. 定位

服务值是唯一自我持有的非负I64内部根实例特征，表达自我已经通过经确认、可观察且可归因的人类服务取得的治理价值。它不是人类需求本身、任务完成数量、服务能力、执行授权或现实世界改善证明。

本规范定义服务值实例特征的唯一性、合法增加、时间衰减、服务根读取和方法分类边界。它不恢复旧服务合同、预算、30%/70%、预支、余款、到期、准备补回、30天门禁、服务调节安全根或安全/服务根配额。

## 2. 服务值实例特征

唯一自我恰有一个服务值类型根和一个服务值实例特征：

```text
目标存在 = 唯一自我
目标特征类型 = 服务值类型根
当前值 ∈ [0, INT64_MAX]
根目标 = INT64_MAX
```

冷启动初值为`INT64_MAX / 2`。服务值实例特征由特征owner保存current-only当前值；不得另建工程账户、第二服务值事实、显示缓存或结算累计值作为当前权威。

服务值变化属于内部治理。写入必须通过具名服务值治理函数，并继续使用特征类的正式值更新能力，使状态、动态和相关认知材料按事实变化自动形成；调用方不得直接写基础字段。

## 3. 逐级结算与合法增加

### 3.1 修改对象与职责

子任务结算改变父任务的内部治理结算材料；目的为记录直接子任务已经完成的贡献，供父任务完成后继续向上结算。最终“结算服务需求”方法改变唯一自我的服务值实例特征；目的为把已经核验的人类服务贡献计入服务根当前值。两者都是内部治理操作，不直接改变现实世界，不合并为一个动作。状态、动态及因果仍由正式事实变化自动形成。

任务结算值是任务治理材料，不是自我服务值的第二账户。需求分类按3100，任务完成及直接父任务交接按3200、5260；本节唯一规定服务贡献的计值和最终入账规则，不改变6100安全结算。

### 3.2 只结算一级

1. 任务的直接父任务由其需求的直接父需求及D-T唯一关联确定。不另建与需求树不一致的任务父子树，不跳过内部治理父任务寻找外部服务祖先。
2. 子任务正式完成后，只向直接父任务提交一次完成结算。父任务接收并汇总，不向更高祖先递归入账，也不直接增加自我服务值。
3. 父任务收到子任务结算后重新读取自身目标及条件；子任务完成或汇总值增加都不自动证明父任务完成。父任务只有自身正式完成且直接子结算完整归集后，才以自身任务身份向自己的直接父任务结算一次。
4. 没有父需求的根任务没有上级接收者，不虚构父任务。“结算服务需求”任务按第3.4节消费直接子任务的合法结算执行服务值更新，不要求长期服务根先完成，也不把该结算任务本身再计为服务贡献。

### 3.3 计值规则

对已经具备正式完成结算资格的任务T，服务结算值记为Q(T)：

```text
服务叶子任务：Q(T) = 1
内部治理叶子任务：Q(T) = 0
非叶子任务：Q(T) = Σ Q(C)，C为T的直接子任务且其合法完成结算已被T接收
```

服务叶子指服务需求派生链中直接目标属于外部特征、且没有子需求的已完成任务，包括符合条件的服务准备叶子。叶子资格按正式需求子链判定；已有子需求但尚缺对应任务、子任务尚未完成或尚未结算，都不能把父任务当作叶子加1。内部治理任务没有固有服务贡献，但可以汇总并逐级传递服务子任务的贡献。非叶子自身不再额外加1，也不能同时加直接子任务汇总值和其后代叶子值；没有合法子结算时汇总为0。

服务准备任务不必独立对应一句人类直接提出的要求，但必须是经self确认的服务需求派生任务，且自己的实际结果符合完成合同。准备贡献仅沿父链汇总，不能绕过最终人类服务门禁直接增加服务值。安全根下任务不因改变外部特征自动取得本节服务贡献资格。失败、取消、结果未知或未完成任务没有完成结算资格；不以0值结算伪装成已经完成。

父任务的正式完成与向上结算分开。发布其唯一完成结算前，必须fresh枚举直接子需求及对应任务：已完成子任务的结算须全部正式归集；尚缺任务、仍在推进、结算未交接或发布未知的项不能按0封口，保持待结算并在进度变化后复核。失败或取消的子任务不提供贡献，但不替代对父任务自身完成资格的判断。只以消息到达顺序计算已收小计不足以向上结算；正式来源应在发布时再次核验一致，避免迟到子结算永久漏算。

每次接收必须核验来源任务、来源完成结算身份、直接父子关系和数值来源；同一子任务完成结算只能接收一次。同义重投复用原接收结果，异义重投停止冲突输入。接收事实与父任务汇总必须一致发布、可完整读回；发布结果未知时先恢复和读取原结果，不重加。求和使用受检整数运算，不允许溢出、回绕或截断后继续。读取失败和结构不一致属于工程保障，不伪装成零贡献。任务已经完成结算后不通过重新启用获得第二次结算资格。

### 3.4 最终服务值增加

一次服务值增加必须同时具备：

1. 服务对象是已确认的人类实例；
2. 人类服务需求已经由自我结构化理解并取得明确确认；
3. 对应服务任务、执行实例及逐级完成结算来源可完整读回，且本次来源是“结算服务需求”任务的直接子任务完成结算；
4. 现实结果由执行前冻结的结果获取方案观察并验证；
5. 自我当前认知认为该动作导致了该结果；
6. 该服务结果尚未消费过服务值结算资格；
7. 当前结算规则可用。

本次合法服务的应增加量为该直接子任务结算携带的Q，不再固定为1。多个直接子任务分别按自己的完成结算身份消费，不反复消费结算任务的累计总额。内部治理汇总不创造新人类服务资格；来源必须能够追溯到满足上述门禁的人类服务结果。失败、取消、结果未知、未验证、非人类对象、未确认需求、无法归因或重复来源均不增加服务值。任务完成、需求当前满足和任务完成结算只提供候选材料，不能自动增加服务值。

消费某一个直接子结算，不以结算任务的其它直接子任务全部完成为前提。第3.3节的归集完整门约束来源任务自身向上结算，不能误作最终消费者等待全部兄弟任务的门禁。

设当前服务值为V、上界为M，则实际增加量为min(Q, M-V)，新值为V加实际增加量；先计算剩余空间再相加，避免溢出。Q为0不产生正向贡献。最终消费资格按来源完成结算防重；已消费的下层贡献不能又以祖先汇总或其它包装重复计入。合法来源达到上界后被消费，不保留超出部分供以后衰减后补发。

结算本能函数固定按下列顺序执行：

```text
读取并核验直接子任务完成结算、逐级来源、未消费资格、应增加量及服务值当前事实
-> 以“结算服务需求”为动作定义、来源完成结算为唯一动作来源，建立动作动态并挂入自我所在场景
-> 通过世界树正式入口按应增加量及上界更新服务值，并显式传入动作动态身份
-> 通过特征owner重新读回服务值，确认实际结果
-> 有结果动态时建立“导致变化”关系；没有前状态而无法形成结果动态时保留动作和新状态
```

动作时间必须早于结果状态时间。动作动态与服务值变化动态不是重复记录：前者记录结算动作，后者记录服务值事实变化。达到`INT64_MAX`时仍保留本次结算动作，但不补造变化状态或结果动态。动作已建立而更新或关联失败时保存部分完成；相同来源重试必须复用同一动作，不得再次增加服务值或扫描场景寻找最近动作。

来源消费与服务值更新必须保持一致，恢复时能够判断原来源是否已经生效；不得出现已加值但资格仍可再次消费的状态。方法声明及结果预测必须表达本次Q决定的增量和上界，而不是无条件固定加1。旧设计、计划或样例中的固定`+1`及`[A0+1,A0+1]`只作历史定位，重新施工须按本节复核；历史验证记录不改写为新算法证据。

## 4. 时间衰减

服务值可随时间衰减，以保证长期服务需求持续存在。当前衰减具体参数尚未冻结时，生产入口保持显式空实现或`规则未配置`，不得自行发明周期、比例或补偿规则。

后续衰减实现必须读取可信单调时间、当前服务值和版本化规则，结果钳制在`[0, INT64_MAX]`，并通过同一服务值实例特征更新入口发布。

## 5. 服务根

服务根是3100定义的长期值目标需求：

```text
目标存在 = 唯一自我
目标特征类型 = 服务值类型根
目标值域 = INT64_MAX单点值域
比较关系 = 等于/包含于目标值域
当前来源 = 唯一自我服务值实例特征的current-only当前值
```

服务根每次按目标存在和特征类型fresh定位实际特征，不保存根专用实际特征字段。差距只表达治理紧迫性，不直接制造人类需求、强行服务或取得现实执行授权。

## 6. 方法分类

- 改变任务虚拟存在、方法虚拟存在、安全值或服务值实例特征，属于内部治理逻辑方法；
- 只取得现实世界材料且不产生现实副作用，属于现实观察；
- 以改变现实场景、存在或特征为目标，或观察步骤本身具有外部副作用，属于普通方法。

分类只看直接作用对象和实际效果，不看调用线程、最终用途或返回值消费者。

## 7. 失败与验证

至少区分自我/服务特征不存在、服务特征复义、当前值非法、对象非人类、需求未确认、结果未验证、无法归因、重复结算、衰减规则未配置、时间不可用、结构不一致和资源失败。

验证至少覆盖唯一实例、初值、服务叶子1、治理叶子0、准备叶子沿父链贡献、非叶子仅汇总直接子任务、父任务未完成不得向上结算、缺任务不误判叶子、重复/乱序接收、无父根任务、失败/取消不结算，以及最终人类服务门禁、防重复消费、受检求和、上界钳制、根fresh读取和衰减未配置时零写。例如父任务的两个服务叶子各为1，父任务完成后只向其父结算2，不另加自身1，也不让两个叶子越级入账。规范发布不证明结算、衰减、生产装配或完整内部治理闭环已经运行通过。
