## 1. 定位

服务值是唯一自我持有的有符号I64内部根实例特征，表达自我的服务治理价值。它不是人类需求本身、任务完成数量、服务能力、执行授权或现实世界改善证明。合法结算读取同一来源任务的服务值Q，Q允许正、零、负；本规范不据此发明负贡献的产生方式、惩罚或扣分政策。

本规范定义服务值实例特征的唯一性、治理结算、时间衰减、服务根读取和方法分类边界。20261023具名裁决替代本规范旧非负域、上界钳制及结算方法树路径；不外推改变安全值、默认贡献计值或其它自我结束条件。它不恢复旧服务合同、预算、30%/70%、预支、余款、到期、准备补回、30天门禁、服务调节安全根或安全/服务根配额。

## 2. 服务值实例特征

唯一自我恰有一个服务值类型根和一个服务值实例特征：

```text
目标存在 = 唯一自我
目标特征类型 = 服务值类型根
当前值 ∈ [INT64_MIN, INT64_MAX]
根目标 = INT64_MAX
```

冷启动初值仍为`INT64_MAX / 2`，不因扩大合法数值域而重算初值。服务值实例特征由特征owner保存current-only当前值；不得另建工程账户、第二服务值事实、显示缓存或结算累计值作为当前权威。V允许小于1；`V < 1`只是自我结束的必要条件之一，不是充分条件，结算函数不因此终止自我或进程，不新增其它结束条件。

服务值变化属于内部治理。写入必须通过具名服务值治理函数，并继续使用特征类的正式值更新能力，使状态、动态和相关认知材料按事实变化自动形成；调用方不得直接写基础字段。

## 3. 逐级结算与有符号入账

### 3.1 修改对象与职责

子任务结算改变父任务的内部治理结算材料；目的为记录直接子任务已经完成的贡献，供父任务完成后继续向上结算。最终结算治理函数改变唯一自我的服务值实例特征；目的为把符合结算资格的同一任务服务值计入服务根当前值。两者都是内部治理操作，不直接改变现实世界，不合并为一个动作。任务状态收尾同样经任务owner处理，不能以函数返回替代正式读回。状态、动态及经验因果仍由正式事实变化自动形成。

任务管理线程在任务完成后把具名任务身份交给自我线程，自我核验正式事实后直接调用结算治理函数。该函数不进入方法树，不生成结算方法头M、方法虚拟存在Vm或方法条件结果配对C/R，不参与模拟学习，也不为调用自身创建结算需求或任务。筹办所需知识由[1190第9.6节](1190_根规范_因果_20260720.md#96-结算治理的先天被动因果)的先天被动因果提供；不得为接通筹办把既有需求D目标硬改成任务数量或其它目标。

任务结算值是任务治理材料，不是自我服务值的第二账户。需求分类按3100，任务完成及直接父任务交接按3200、5260；本节唯一规定服务贡献的计值和最终入账规则，不改变6100安全结算。

### 3.2 只结算一级

1. 任务的直接父任务由其需求的直接父需求及D-T唯一关联确定。不另建与需求树不一致的任务父子树，不跳过内部治理父任务寻找外部服务祖先。
2. 子任务正式完成后，只向直接父任务提交一次完成结算。父任务接收并汇总，不向更高祖先递归入账，也不直接增加自我服务值。
3. 父任务收到子任务结算后重新读取自身目标及条件；子任务完成或汇总值增加都不自动证明父任务完成。父任务只有自身正式完成且直接子结算完整归集后，才以自身任务身份向自己的直接父任务结算一次。
4. 没有父需求的根任务没有上级接收者，不虚构父任务。最终服务来源由自我按第3.4节核验并直接治理入账，不要求长期服务根先完成，不恢复“结算服务需求”任务作为必需接收者，也不把结算治理操作本身计为服务贡献。

### 3.3 计值规则

对已经具备正式完成结算资格的任务T，服务结算值记为Q(T)：

```text
服务叶子任务：Q(T) = 1
内部治理叶子任务：Q(T) = 0
非叶子任务：Q(T) = Σ Q(C)，C为T的直接子任务且其合法完成结算已被T接收
```

上述是当前默认计值规则，不是Q的合法值域。任务虚拟存在的服务值Q采用有符号I64，已由正式来源提供的负Q不得仅因负号被结算拒绝、取绝对值或钳成0；也不能因允许负Q而擅自改写服务叶子1、治理叶子0及直接子任务求和规则。结算不生成负Q政策，不把失败、取消或读取故障换算成负贡献。

服务叶子指服务需求派生链中直接目标属于外部特征、且没有子需求的已完成任务，包括符合条件的服务准备叶子。叶子资格按正式需求子链判定；已有子需求但尚缺对应任务、子任务尚未完成或尚未结算，都不能把父任务当作叶子加1。内部治理任务没有固有服务贡献，但可以汇总并逐级传递服务子任务的贡献。非叶子自身不再额外加1，也不能同时加直接子任务汇总值和其后代叶子值；没有合法子结算时汇总为0。

服务准备任务不必独立对应一句人类直接提出的要求，但必须是经self确认的服务需求派生任务，且自己的实际结果符合完成合同。准备贡献仅沿父链汇总，不能绕过最终人类服务门禁直接增加服务值。安全根下任务不因改变外部特征自动取得本节服务贡献资格。失败、取消、结果未知或未完成任务没有完成结算资格；不以0值结算伪装成已经完成。

父任务的正式完成与向上结算分开。发布其唯一完成结算前，必须fresh枚举直接子需求及对应任务：已完成子任务的结算须全部正式归集；尚缺任务、仍在推进、结算未交接或发布未知的项不能按0封口，保持待结算并在进度变化后复核。失败或取消的子任务不提供贡献，但不替代对父任务自身完成资格的判断。只以消息到达顺序计算已收小计不足以向上结算；正式来源应在发布时再次核验一致，避免迟到子结算永久漏算。

每次接收必须核验来源任务、来源完成结算身份、直接父子关系和数值来源；同一子任务完成结算只能接收一次。同义重投复用原接收结果，异义重投停止冲突输入。接收事实与父任务汇总必须一致发布、可完整读回；发布结果未知时先恢复和读取原结果，不重加。求和使用受检整数运算，不允许溢出、回绕或截断后继续。读取失败和结构不一致属于工程保障，不伪装成零贡献。任务已经完成结算后不通过重新启用获得第二次结算资格。

### 3.4 最终服务值治理结算

一次最终服务值结算必须同时具备既有服务资格：

1. 服务对象是已确认的人类实例；
2. 人类服务需求已经由自我结构化理解并取得明确确认；
3. 对应服务任务、执行实例及逐级完成结算来源可完整读回；本次明确消费同一最终服务来源任务T，不以结算任务或方法实例作来源；
4. 现实结果由执行前冻结的结果获取方案观察并验证；
5. 自我当前认知认为该动作导致了该结果；
6. 该服务结果尚未消费过服务值结算资格；
7. 当前结算规则可用。

本次Q从任务T的虚拟存在服务值特征读取，不从方法虚拟存在、消息自报值或另一任务读取。自我有效，自我的正式任务引用集合包含该T，且该T当前状态为完成，均须在执行前核验；同一T的资格、状态和Q必须关联一致。上述人类服务资格由正式完成来源读回，不以收到“完成”消息自证。内部治理汇总不创造新人类服务资格；失败、取消、结果未知、未验证、非人类对象、未确认需求、无法归因或重复来源不取得最终服务值结算资格。

消费某一个最终来源，不以其它服务任务全部完成为前提。第3.3节的归集完整门约束来源任务自身向上结算，不能误作最终消费者等待全部兄弟任务的门禁。

结算关系为`V后 = V前 + Q(T)`：Q正则增加、零则不变、负则减少；不钳零、不做上界饱和、不拒绝合法负Q。I64可表示性是工程边界，必须在写入前受检计算；上溢、下溢均进入工程日志、弹窗及调试修复路径，不发布回绕值、截断值或默认值，也不形成业务失败结果。最终消费资格按来源完成结算防重；已消费的下层贡献不能又以祖先汇总或其它包装重复计入。

自我直接调用的结算治理函数固定按下列顺序执行：

```text
读取并核验自我、任务集合中的同T、T完成状态、逐级来源、未消费资格、T的Q及V前
-> 受检计算V后；以结算动作概念为定义、来源完成结算为唯一动作来源，建立动作动态并挂入自我所在场景
-> 通过世界树正式入口按V后更新服务值，并显式传入动作动态身份，不要求结算M
-> 通过特征owner重新读回服务值，确认实际结果
-> 有结果动态时建立“导致变化”关系；没有前状态而无法形成结果动态时保留动作和新状态
```

动作时间必须早于结果状态时间。动作动态与服务值变化动态不是重复记录：前者记录结算动作，后者记录服务值事实变化。Q为0时仍保留本次真实结算动作和合法收尾，不补造数值变化或正向动态。动作已建立而更新或关联失败时保存部分完成；相同来源重试必须复用同一动作，不得再次入账或扫描场景寻找最近动作。

来源消费与服务值更新必须保持一致，恢复时能够判断原来源是否已经生效；不得出现已入账但资格仍可再次消费的状态。普通子任务在直接父任务正式接收贡献后标记已结算；最终服务来源在V实际入账并独立读回后标记已结算。已结算是收尾结果，不作为本次完成结算的循环前提。先天因果表达本次Q决定的结果关系，不是无条件固定加1；为正向服务目标逆推时必须保留Q正值条件，零、负Q不得冒充满足增加目标。

历史结算M/Vm/C/R及既有引用只读兼容，不删除、不改码、不冒充当前可召回或可模拟能力。旧设计、计划、样例中的结算方法登记、固定`+1`及上界饱和只作历史定位，重新施工须按本节复核；历史验证记录不改写为新算法证据。

## 4. 时间衰减

服务值可随时间衰减，以保证长期服务需求持续存在。当前衰减具体参数尚未冻结时，生产入口保持显式空实现或`规则未配置`，不得自行发明周期、比例或补偿规则。

后续衰减实现必须读取可信单调时间、当前服务值和正式规则，并通过同一服务值实例特征更新入口发布。不得由旧非负域推导钳零规则；本轮不确定衰减参数或扩大衰减实现范围，受检整数运算及工程故障分账继续成立。

## 5. 服务根

服务根是3100定义的长期值目标需求：

```text
目标存在 = 唯一自我
目标特征类型 = 服务值类型根
目标值域 = INT64_MAX单点值域
比较关系 = 等于/包含于目标值域
当前来源 = 唯一自我服务值实例特征的current-only当前值
```

服务根每次按目标存在和特征类型fresh定位实际特征，不保存根专用实际特征字段。差距只表达治理紧迫性，不直接制造人类需求、强行服务或取得现实执行授权。

## 6. 方法分类

- 改变任务虚拟存在、方法虚拟存在、安全值或服务值实例特征，属于内部治理逻辑方法；
- 只取得现实世界材料且不产生现实副作用，属于现实观察；
- 以改变现实场景、存在或特征为目标，或观察步骤本身具有外部副作用，属于普通方法。

分类只看直接作用对象和实际效果，不看调用线程、最终用途或返回值消费者。

## 7. 失败与验证

至少区分自我/服务特征不存在、服务特征复义、当前值非法、对象非人类、需求未确认、结果未验证、无法归因、重复结算、衰减规则未配置、时间不可用、结构不一致和资源失败。

验证至少覆盖唯一实例、初值、服务叶子1、治理叶子0、准备叶子沿父链贡献、非叶子仅汇总直接子任务、父任务未完成不得向上结算、缺任务不误判叶子、重复/乱序接收、无父根任务、失败/取消不结算，以及最终人类服务门禁、防重复消费、受检求和、根fresh读取和衰减未配置时零写。新增边界包括同T关联、Q正/零/负、V低于1仍完成合法入账且不直接终止、上下溢工程拒绝、零变化不伪造动态、无结算M/Vm/C/R或模拟调用、先天因果零发生统计及不改D目标的逆推。例如父任务的两个服务叶子各为1，父任务完成后只向其父结算2，不另加自身1，也不让两个叶子越级入账。规范发布不证明结算、衰减、生产装配或完整内部治理闭环已经运行通过。
