# 6260 子规范 场景边界与坐标范围

编号：6260
日期：20261105
版本：v1.1
状态：正式子规范

直接上级规范：1150。

直接依赖规范：1140、6220。

相关边界规范：1160、1170、6240、6250、6300。

## 1. 定位

本规范承接1150 v2.3第10—12节移出的场景边界存在组与二维、三维边界计算，并规定场景坐标范围及存在离开/进入的判定依据。场景字段与列表组织由4202规定，绝对坐标与相对坐标表由6220规定。

## 2. 边界存在组

1. 场景边界表达自我限定和认知形成的空间范围，不等同于视野边缘。边界存在组保存“用于定义当前场景边界的存在”引用。
2. 边界存在不要求直接归属于当前场景；引用边界存在不改变其原有场景归属。
3. 边界存在组只支持显式添加和移除，不自动选择最外边存在。
4. 边界几何在需要时从外部几何读取接口取得并即时计算，不持久化计算结果，也不写回边界特征。
5. 边界存在属于当前场景范围时，取其相对于场景内部参考点的最外侧候选边或面；不属于当前场景范围时，取离内部参考点最近的候选边或面。候选无法唯一确定时返回失败，不任意选择。
6. 场景仍被其它场景的边界字段引用时，不得删除该场景（4202）。

## 3. 二维边界计算

入口语义为“计算二维场景边界（几何读取接口、场景节点、场景内部参考点）”，流程：

```text
读取边界存在组
-> 为每个存在读取候选线段
-> 按是否属于场景范围选择外侧或最近线段
-> 按相同端点连接线段
-> 形成一个或多个闭合环
```

每条二维边界线段必须非退化；闭合环中每个顶点的邻接度必须为二。重复无向边或开放链返回“边界未闭合”或“几何不合法”。

## 4. 三维边界计算

入口语义为“计算三维场景边界（几何读取接口、场景节点、场景内部参考点）”。候选面必须至少三个顶点、非退化且共面。选定边界面后，顶点按提供顺序连接成无向边；闭合空间要求每条无向边恰好由两个边界面共享。少于四个面或任一边计数不等于二，均不得宣称空间闭合。

边界计算不补造缺失几何。

## 5. 场景坐标范围与离开/进入

1. 场景坐标范围由其闭合边界确定，使用所属空间世界的世界根坐标系表达（6220第6节）。边界未闭合时坐标范围未知，不能据坐标判定该存在仍在场景内；在预期场景观察不到该存在时，该存在位置未知，按第4项逐级向上迁移。
2. 存在的绝对坐标落在当前场景坐标范围之外，即为“离开”该场景；在某场景坐标范围内首次观察到该存在，即为“进入”该场景，进入即被该场景“发现”。
3. 离开与进入分别是两个场景各自记录的未融合事实（1150、1170）；融合动态由共同上位场景形成。离开的执行顺序：先由相关owner删除或修改该存在与原场景相关的关系信息（成员关系等）；再置空其绝对坐标F，置空状态挂入原场景，形成“离开”；然后按1140迁移；在新场景写入坐标，状态挂入新场景，形成“进入”（4202第4节、4212第3节）。已挂接的状态和动态不迁移。
4. 位置不明的存在（含边界未闭合场景中观察不到的存在）逐级迁往上位场景直至所属世界根（1140），不因边界计算失败而删除或复制存在。
5. 非空间世界（自然语言、内部治理）及无坐标场景不按坐标判定，成员归属由对应owner显式写入（4202第2节）。

## 6. 非成功

至少区分：场景不存在、边界存在组为空、几何读取接口未配置、候选不唯一、几何不合法、边界未闭合、坐标系不一致、换算溢出和资源失败。工程故障不得伪装为“不在范围内”。

## 7. 验证

覆盖：跨场景边界存在引用不改变归属；二维多闭合环与开放链拒绝；三维每条边恰好双面共享；边界未闭合时坐标范围未知、观察不到者按位置未知向上迁移；离开先删改关系信息再置空坐标；绝对坐标落在范围外判定离开、首次观察判定进入；离开/进入分记两个场景、状态与动态不迁移。
