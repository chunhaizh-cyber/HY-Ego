# 4020 子规范 类型化值、材料引用与组合读取投影边界

编号：4020
日期：20260802
状态：正式子规范

直接上级规范：0050。

直接依赖规范：4010。

相关边界规范：4030—4070、4110—4200。

## 1. 定位

本规范规定业务中性的类型合同、类型化值、独立材料引用和组合读取投影。旧领域记录枚举、固定 I64 / 向量槽和节点归属形状退出正式合同。

## 2. 类型合同

属性类型节点至少具有稳定编码、命名空间、表示 / 值域、所有者声明、生命周期、直接兼容关系和发布证据。

1. 类型节点候选在所属内存事实代次原子发布前不可见。
2. 同一编码同内容是精确重复；同一编码异内容是内部冲突。
3. 兼容性必须以关系声明方向、操作和直接类型节点对；不得从名称、版本大小、结构相似或 A—B—C 链传递推导。
4. 停止新写和退出普通使用不删除历史类型节点，也不允许恢复新写资格或复用编码。

## 3. 类型化值

完整值事实至少包含：

```text
值稳定编码
+ 所属节点编码
+ 属性类型节点编码
+ 内联小值或独立材料引用
+ 强类型来源、创建 / 退出事实代次和发布证据
```

1. 禁止主信息、万能 I64、任意 JSON、无类型联合或跨领域字节包。
2. 来源只能是一个已发布节点编码。无需先有普通业务来源即可成立的系统签发事实，必须先由签发服务建立具名系统签发者节点，再引用该节点；服务对象、空来源、显示名、SQL 行、线程、日志和调用方自报均不成立。普通观察、状态、动态、特征和用户材料仍必须引用其真实已发布节点来源。
3. 值类型由合同解释，L1 不按字段名或原始形状猜测业务意义。
4. 已发布值不可原地覆写；替换形成新值编码、旧值退出，并与所属节点的属性槽变化同一事实代次发布。
5. 编码引用集合只保存属性类型允许的编码值；对象拓扑仍由 4010 关系事实承载。

## 4. 独立材料文件

1. 大材料、原始采集或不适合 SQL 内联的值可以保存为不可变独立文件。
2. 材料只有在格式、长度、摘要、来源和类型校验通过，并被内存已发布值事实引用后，才参与运行期事实。SQL 可保存该材料引用的持久证据，但 SQL 行本身不能建立引用事实。
3. 文件路径只是定位材料，不是对象身份或业务事实；移动物理位置不得改变材料身份和摘要。
4. 未被内存已发布值记录引用的材料是孤立候选或待回收材料，不能反向创建对象、值或关系；恢复时也只能作为隔离输入重新准入。

## 5. 组合读取投影

1. 完整业务读取按需组合身份、类型合同、值、关系和发布证据，形成调用方拥有的不可变投影。
2. 投影必须声明事实截止代次、读取类别、缺失项和完整性；不得用默认值、空编码或隐式“最新”补齐。
3. 投影不是第二权威账，不得反向写入、参与恢复裁决或被缓存长期固定为当前事实。
4. 当前、历史、审计和恢复候选投影不得混用。

## 6. 非成功

未知类型、表示不支持、值域越界、材料缺失 / 摘要不符、错归属、事实代次漂移和投影不完整必须具名返回；前置通过后的编码复义、类型矛盾或读回不一致属于内部不一致。
