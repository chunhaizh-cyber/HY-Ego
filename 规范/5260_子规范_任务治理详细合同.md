## 1. 适用范围

本规范统一承接原4260与5200—5250中仍有效的任务结构、状态、轮次、筹办、冻结、执行、结算、事务、错误和验证合同。它不恢复这些旧文件、旧编号对应的分散权威或已经退出的旧模型。

方法定义原则读取3300，成组条件—结果配对树、Vm规格和方法治理读取5350，函数登记、实参核验、动作及反馈读取5360；需求产生确认和需求生命周期读取3100与5170；安全硬否决读取6150；线程编排读取8100与8200。本规范只冻结任务域自身必须维护的事实和相邻边界。

## 2. 任务核心、需求承接与目标读回

任务核心事实至少稳定证明：

```text
任务身份 T
同类任务查询 / 防重锚点 L
唯一任务虚拟存在 Vt
任务生命周期
```

任务身份、查询锚点、任务虚拟存在、来源需求关系、任务轮次、筹办轮次、执行轮次、任务方法路径、实例方法、轮次发起调用、上级调用槽、调用返回、调用槽结算、实际结果和任务完成结算必须分别使用具名强类型身份；不得用裸整数、名称、关系端点拆分值或其它身份互相冒充。

任务身份资格必须由 task owner 的任务族来源、任务节点、精确任务族归属关系及其生命周期共同证明。任务 owner 必须提供当前与具名历史截止下的任务身份来源读回；当前已退出只返回退出状态，历史读取仍须返回该截止下的完整生命周期。任务族登记、关系类型和 owner 私有结构元数据不是普通任务，不能由普通任务查询冒充。

任务以当前显式 `T→D` 关系逐项保存已经收到承接输入的具体需求。全部当前关联需求必须具有完全相同的需求核心契约；每条关系仍独立保留需求身份、来源、路径、当前性、权重、预算和结算来源。

任务目标读取固定为：

```text
T
-> 当前T→D关系组
-> 至少一个当前有效D
-> 逐项读取目标三元组
-> 机械互证全部相同
-> 形成本次值式单目标投影
```

一个当前查询锚点至多对应一个当前任务。承接时先以 D 的当前列表项 L 查询任务；没有则原子建立任务，有则验证目标一致后幂等增加 `T→D`。列表新增成员不得自动加入任务，全部关联需求失活时不得用 L 的聚合键兜底。

上述复用限于仍可治理的未完成、未失败、未取消任务。命中已经完成 / 失败 / 取消的T时，只处理其已有结果及适用的完成结算，不把新D承接为该T的新执行目标或重开轮次。需建立新的同目标任务时，先按task owner既有生命周期与引用保护合同退出旧T的当前调度 / 查询资格，保留历史和结算恢复来源，独立读回后再按唯一约束承接新T；不得隐式删除旧任务或需求。

task owner 的任务核心公开能力至少包括：读取任务身份来源、新增任务、读取任务、按查询锚点读取当前任务、承接具体来源需求、按任务读取来源需求关系组、读取任务轮次、读取任务虚拟存在和退出任务；轮次协作公开能力至少包括建立 / 读取轮次发起调用、按子任务轮次读取发起调用、发布 / 读取调用返回、结算 / 读取上级调用槽。公开读写必须返回结构化状态、事实截止和强类型载荷，非成功零业务载荷；这些入口不负责方法召回、路径评分、实例执行、目标完成裁决、需求产生或需求结算。

后继路径结构必须至少提供新增 / 读取 / 退出任务方法路径、按任务读取当前路径组、按任务与筹办轮次读取路径组，以及发布 / 读取当前选中路径；实例结构必须至少提供创建 / 读取实例方法、按任务读取当前实例、退出当前实例和读取实例历史。路径必须绑定任务、筹办轮次、来源方法及内容版本和完整条件 / 输入 / 参数 / 动作 / 验证材料；实例必须绑定任务、任务 / 筹办 / 执行轮次、当前选中路径、来源方法版本和执行冻结。各结构的 owner、当前唯一、历史保留、退出与读回不可因本次合并而弱化。

本次规范重组不改变合并前已经正式冻结并进入生产声明的公开ABI：既有接口名、合同版本、请求 / 结果强类型、字段顺序、状态值域、无参数成功谓词、非成功零业务载荷、当前 / 历史载荷形状、失败优先级、幂等和发布未知读回语义继续保持。5260只统一承载这些接口必须满足的任务语义，不在正文重复C++逐字段清单。任何字段增删、重排、改义、版本变化或旧入口物理删除都必须作为独立ABI迁移，经正式设计、消费者同步迁移和验证后另行登记；不得借“简化规范”静默改变现有ABI。

任务特征只允许来自任务领域固定治理特征、当前显式来源需求锚定特征，以及当前采用方法正式声明的任务业务特征。固定治理特征只覆盖本规范所需的来源当前性、基础优先级、筹办占用与覆盖、任务状态、等待与重触发、执行 / 结果 / 验证、失败 / 取消 / 停止等具名强类型语义；方法未采用前不得挂载方法开放特征。新增业务特征类型必须先由合法上级或方法合同声明并完成类型准入，不得因本轮临时需要自由造型。

筹办、调度、冻结、执行、验证和结算必须冻结本轮实际消费的 `T→D` 身份、成员需求、路径、权重、预算和共同事实截止。历史冻结不因后继成员变化而被改写。

任务基础优先级 `B` 是不含安全调度倍率的非负 `I64` 基础排序值。它只能由当前显式来源需求的正式优先级及具名任务治理规则形成，并同时保存全部来源需求、来源优先级版本、治理规则版本、共同事实截止和当前性。任一来源变化必须形成新版本并保留旧历史；不得由线程等待时长、队列位置、名称、日志或安全 / 服务根配额临时抬高。`B`只进入6150定义的调度投影，不是现实执行授权、结算预算、安全值或服务值。

## 3. 初始化、Vt与轮次身份

一个具体需求首次建立任务时，task owner 在同一核心写集中建立：

```text
任务 T
+ 查询锚点 L
+ 首条T→D
+ 唯一Vt
+ 首个任务轮次 R1
+ Vt首态
```

Vt首态表达任务已经建立但尚未进入找方法。上述核心全部正式读回后，才幂等建立首个筹办轮次 P1；manager再依据Vt首态和P1经正式状态入口推进到待找方法。P1只作首轮、幂等和恢复锚点，不证明是否应筹办，也不是筹办A1。

首次承接请求必须一次携带互不相同且非零的三项幂等身份：`任务核心建立`、`P1建立`、`Vt首迁移`；准备幂等身份固定等于P1建立身份。三项身份及原完整请求必须进入首次记录和精确重复比较，不得按时间、运行代次、哈希、需求 / 任务身份或中间结果临时派生。发布未知只能使用原身份与原请求逐段收敛；旧格式仅可按原请求历史重放或返回具名待迁移，不能猜测缺失身份或升级原记录。

身份和生命周期严格分账：

```text
任务生命周期
任务轮次
筹办轮次
执行轮次
```

一个任务可以有多个顺序保留的任务轮次；一个任务轮次可以有多次筹办调用，但至多建立一个执行轮次。执行轮次身份在执行前选择成功并形成冻结时建立；只有动作入口实际开始后才成为“已开始执行轮次”。

### 3.1 Vm 参数规格实例化与实参绑定

本节只补齐方法抽象参数到任务实际数据的关系，不改变执行前选择、路径、轮次和冻结合同。数据链固定为：

```text
方法 Vm 的有序参数特征规格
-> 任务 Vt 下的专属参数实例
-> 逐槽绑定本任务已存在的具体特征
-> 同截止完整读回有序参数和值
-> 应用执行入口按方法合同传入方法函数
```

1. 业务应用面先裁决采用，任务记录面才可请求实例化；登记方法引用或复制规格不是采用裁决。task owner 持有 Vt 下的参数实例和绑定，method owner 保留方法头、Vm 与源规格。复用存在类专用数据函数不转移此业务写入权。
2. 实例化复制参数类型引用、类别、顺序及其完整角色 / 取值要求和必要约束引用，建立任务自己的关系并保留来源方法、Vm 和源规格版本的可追溯性；可由源定义唯一读回的约束不复制第二定义。不复制源关系身份、具体参数值、方法治理状态或条件 / 结果知识节点，不合并 Vm、Vt 和任务实例身份。
3. 参数组与来源在同一事实截止完整读取；任务实例保留同长度、同顺序、同类别、同类型及同语义约束的规格。同FT在不同对象或参数位置不得合并。显式零参数合法，不得因使用固定数组截断不定长规格；预算不足或任一源读取失败时不得发布部分实例。
4. 实参按槽绑定已发布的具体特征身份 F，F 的正式特征类型必须与槽规格相等；不能用裸值、空节点或缺值特征替代。场景、存在参数通过 F 的正式值引用表达；外层特征类型相等不证明被引用场景 / 存在的业务资格，调用方仍须按方法合同核对。
5. 执行前在一个非零共同截止重新读回全部绑定及 F 的正式值，以参数顺序返回完整数据。槽位未绑定、错类型、重复绑定、节点退出、代次漂移或预算不足均不得返回伪完整可执行参数组；不得用 Vm 的默认数据填空。
6. 绑定固定具体特征身份；来源特征换代不得静默改绑到新节点，方法规格后继变化也不得修改既有实例。需要重绑或重新实例化时只能通过具名任务合同，已冻结执行快照继续不可变；历史实例按其冻结版本和截止追溯。
7. 规格实例化和逐槽绑定各自按 task owner 的具名原子写入合同发布及读回。写前失败零变化；已发布后的读回未知依原幂等身份和原完整请求收敛，不补偿删除、不把分步操作伪称整个任务原子初始化。
8. 数据函数只登记、复制、绑定和读取，不调用方法函数，不选择方法、不派发执行、不裁决授权、条件具备、目标达成或结算。“参数组完整”只证明本次数据读取条件成立；正式实例方法仍必须满足第 2 节的路径、任务 / 筹办 / 执行轮次、来源版本和执行冻结。

仅实现上述参数记录的提供者不得冒充正式实例方法或运行闭环；缺少完整来源版本、轮次或冻结的薄记录仍须由后继合同补齐，不能从已发布代码反推本规范要求已经满足。

### 3.2 方法知识与任务运行材料的归属

方法头、函数绑定、Vm规格、全方法共同约束及C/R配对树由method owner唯一提供；任务只保存对所用内容的明确引用与本轮绑定，不复制可独立变更的方法知识。C为一组AND条件，R为对应的一组联合结果，以C身份定位配对，不能用FT、遍历顺序或树深替代配对身份。

Vt下的任务专属实例承载本轮对象角色、实参和冻结来源；原预测、实际动作、观察、验证及结算按task owner与事实owner的既有合同关联，不回写共享Vm。方法配对树的父子是同一主动作的范围 / 精度细分；不沿父子边逐项执行动作，不把每个C/R当一个任务步骤，也不为配对增加第四类知识节点。

以上约束补齐逻辑来源与完整读取，不在现有DTO尾部自行增加字段；新物理映射与消费者迁移仍按第2节及第14节实施边界处理。

## 4. Vt状态与迁移权威

任务主阶段、业务子状态和状态迁移记录都由同一Vt承载。当前状态必须从task owner正式读回，不得从队列位置、线程局部变量、工作包、消息、日志或显示文字反推。

状态至少能够区分：

```text
待找方法 / 继续找方法
待查条件 / 继续查条件
方法或条件业务材料待self裁决
待执行前选择
已冻结待self综合判断 / 待授权或待派发
执行中
待结果收束
轮次已收束待self后继决议
业务等待
任务完成（任务结算可尚未形成）
任务失败
任务取消
```

状态名称不是任意枚举许可；具体迁移必须由前态、轮次、已发布任务信息版本、结果截止和幂等身份共同校验。manager只请求正式迁移，状态owner完成原子写入与读回。

## 5. 状态驱动的多次筹办

任务筹办是task owner内部治理函数，由manager根据Vt当前状态异步派发。任务是否首次筹办或继续筹办只由任务状态和已覆盖范围决定，不需要A1或其它证明节点。

同一任务同一时刻至多存在一个当前有效筹办占用和执行权，不同任务在所有权与资源不冲突时可以并行。占用必须绑定任务、任务轮次、筹办轮次、任务信息版本、工作包和当前运行代次，不得持久化裸线程编号；未取得执行权的调用在读取或补写本次筹办信息前技术拒绝并保持零业务写入。

重启后只恢复旧占用的历史，不继承其执行权。恢复方必须先重建任务、当前任务轮次和历史筹办事实，原子失效旧运行代次占用及旧冻结当前性，并证明前轮现实动作已经停止或已完成正式结果读回，才能以新恢复代次和新筹办轮次重新取得唯一执行权；无法证明动作收口时只能形成具名等待与重触发材料，不得重复现实动作。

恢复还须读取正式任务状态：完成任务只恢复适用结算和交接，失败 / 取消只恢复结果处理，均不得重新取得执行权。未完成轮次已经收束时，必须先有self合法继续决议，再建立新任务轮次与筹办；仅原轮仍处合法筹办状态且没有未收口动作时才能恢复该阶段。运行代次更新、停止读回或工程恢复本身不构成self后继决议。

筹办顺序固定为：

```text
先找方法
    按目标正式FT在明确范围内召回可改变其值的方法
    累计候选方法身份、内容版本、命中来源和覆盖范围，不以方向或区间作粗召回门槛
    完整覆盖且至少有一个候选后才进入查条件

后查条件
    逐候选读回其完整条件—结果配对，核验各条件组当前具备性
    全部候选和条件组覆盖完成后才允许进入执行前选择
```

筹办可以多次调用；每次只处理当前工作包覆盖范围。存在多个方法和多组条件时必须全部保留，不得找到第一种方法或第一组具备条件后提前停止。

方法候选读取须保留登记声明、完整配对和结构缺口的区别。只有登记头但无完整配对时，仍可作为FT命中候选及结构缺口材料，不报告方法不存在，不补造空条件或结果，也不能进入可采用集合。5350中的显式空条件组只免除该组额外条件，全方法共同约束和参数要求仍须核验。

遍历配对树只用于有界完整读取。父配对仍有效时与子配对分别保留；读取完整自足的C/R，不由任务临时补继承条件。预算不足、树未读全、多个配对命中或子域更细，不授权按第一项或最深项选择。

筹办不判断对象、方向和结果是否适用，不比较综合代价，不采用方法，不建立路径、实例或冻结，也不创建需求、学习需求或子任务。

每次调用经task owner唯一入口补全任务信息并取得结果版本，然后发送一条不可变结果消息给manager。消息至少定位任务、任务轮次、筹办轮次、工作包、调用前状态、预期 / 结果版本、来源 / 结果截止、已覆盖 / 剩余范围和结果分支。

消息不是第二业务账。manager必须独立读回任务、Vt、轮次、信息版本和覆盖范围，校验一致后才提交状态迁移；不得同步直调筹办provider、信任消息正文代替读回或重跑筹办。

## 6. 筹办业务材料与技术非成功

合法阶段结果只表达本次信息补全进度：继续找方法、方法查找完整且有候选、继续查条件、条件核验完整且至少一组具备，以及具名方法 / 条件业务缺失材料。

方法缺失当且仅当正式方法查找已经完整覆盖本轮明确范围且候选为零；条件缺失当且仅当全部候选及其全部条件组已经完整核验且当前具备组为零。无条件方法必须以显式空条件组表示，不能与条件结构缺失混同。合法生产者和重触发条件只决定后续等待或重判，不决定缺失事实是否成立。缺失只进入当前任务材料，由manager定位给self；self依据3100与5170决定等待或产生、确认独立后继需求。缺失分类不能自动决定学习、建需、失败或终态。

登记头无配对、C缺对应R、函数绑定 / Vm规格不可读及不完整结果定义是具名结构缺口，不是条件经核验后不满足；尚无完整候选材料时不得声称条件覆盖完成。候选非空但在第7节全部效果不适用，与本节完整查找零候选分开；读取、比较或资源非成功同样不得折成“没有可用方法”。

以下属于技术非成功，不得包装成方法缺失、条件缺失或业务等待：

```text
截止或版本漂移
投递失败或队满
资源失败
发布未知
ABI、引用或断言失败
结构不变量破坏
内部代码错误
```

漂移使本次结果失效并保持原业务子状态重派；投递或发布未知使用原幂等身份和原完整请求收敛；ABI、引用、断言、结构不变量和内部错误停止受影响调用。

## 7. 执行前选择、实例方法与冻结

进入待执行前选择后，任务业务应用面在manager编排下于新的共同事实截止重新读取全部候选、方法内容版本、完整条件—结果配对、当前输入和世界事实，并依次完成：

1. 按5350以二次特征判定对象、变化方向、目标值/区间及结果适用性，逐个保留`方法 + 内容版本 + C + 对应R + 本轮绑定`，同时核对结果时间要求与联合约束；
2. 当前可用性与条件复核；
3. 方法作用范围、逐动作现实副作用和安全硬门检查；
4. 安全值 / 服务值收益与付出、时间及其它正式成本比较；
5. 从完整、适用且可比较的候选配对及其绑定中选择综合代价最小的一项。

未知、不可比或并列最优时不选择，并形成具名非成功材料交task owner按正式状态处理；不得临场选第一项、最新项或名称匹配项。

选择结果经task owner校验后，同次形成一条当前任务方法路径、一个不可变实例方法和一份执行冻结。冻结至少绑定任务、实际消费需求组、目标版本、任务 / 筹办 / 执行轮次、来源方法与版本、输入、参数、采用的完整条件—结果配对、比较定义与角色绑定、动作前预测依据、动作入口、作用范围、现实副作用、安全边界、世界事实截止、验证和归因合同。不得跨方法或跨配对拼接有利条件与结果；无足够预测依据时显式记录该缺口，不补造预测。

普通目标执行不得仅凭无完整配对的登记头取得资格；无预测分支本身也不是探索未知动作的授权。试验或特殊调用必须有既有专项任务合同及安全边界。已形成的目标、预测及允许结果都只是约束，不得发布为已经发生的状态。

具体数值、轮廓等结构目标均按具名比较规则绑定真实来源；方向比较与目标匹配分开。一个结果组影响多个FT时逐项保留对象角色、FT、允许结果、观察时机与联合约束，不能把分别满足的不同执行或不同配对拼成一次联合成功。

冻结后实际输入、对象绑定、执行条件、授权或安全限制失效时，不得继续受影响动作；冻结内容不能原地修补。共享方法后来新增配对、提高精度或发布新知识，不自动使本轮原快照失效，也不重绑到新内容；明确退出、撤销或安全失效仍按相应合同处理。方法配对树不定义组合动作执行序列；本规范不从该树推导子方法、循环、任务树或新的多动作资格。

### 7.1 自我综合判断与派发资格

选择冻结不等于可以派发。manager把任务、三轮次、路径 / 实例 / 冻结及对应材料定位交self；self独立读回后综合核对当前需求活动资格、目标必要性、已选方法与条件、正式收益 / 付出、资源争用和安全约束，形成执行、暂缓、拒绝或重判分支。未知、不可比、材料不足或漂移不得当作准许。具体消息及消费算法由8200承载。

任何正式任务进入方法执行前均经过该判断；它是自我内部治理决策，不是第二现实执行授权。含现实改变时，由同一次判断编排唯一self现实执行授权；纯内部任务与无副作用观察不建立该授权。筹办、状态提交、结算等内建治理函数不因此递归创建审批任务。

判断绑定当前冻结与事实来源。manager必须独立复核后派发，工作线程临近动作再检查必要条件和硬否决；关键输入、冻结、活动资格或安全条件变化使旧判断失去本次可消费性，不得把self意见变成永久执行许可。冻结内容需改时按本规范停止 / 收束并重新筹办；只需重新判断时不重复动作或改写冻结。

## 8. 现实执行授权、执行与实际结果

执行冻结只含内部治理或纯观察时，不请求现实执行授权；含至少一个现实改变步骤时，必须在动作入口开始前读回一份由self业务owner发布的当前现实执行授权。授权绑定任务、任务轮次、执行轮次、冻结、实例方法和完整现实动作范围，不得拆成任务授权与方法授权两份。

安全控制态、设备许可和结构写许可只形成硬否决或技术可达性，不能代替self正向授权；self授权也不能越过硬否决。授权拒绝或等待不是任务失败。

执行过程固定为：

```text
已登记方法 + 冻结实例方法 + Vt任务实参
-> 解析冻结的正式函数注册引用
-> 方法第二部分赋值并临近动作复核必要条件与安全门
-> 方法第三部分执行真实动作
-> 方法第四部分交付执行报告、实际动作材料及动作前已有预测
-> 独立观察路线取得实际事实，两路线按同次运行关联
-> 动作后当前值完整投影及可选状态 / 动态证据
-> task owner收束正式实际结果
-> 目标验证、尝试收束及正式任务状态处理
```

5360的第一部分只负责独立登记，必须在任务采用 / 冻结前完成。执行器不能以查找失败为由运行未登记函数，也不能在第二至四部分补建缺失头、Vm、配对或函数绑定。正式注册引用用于机械解析入口，不以名称、裸地址或节点号任意调用。

任务区分参数 / 前置检查拒绝、实际动作已开始或部分发生、已按函数合同返回、异常 / 取消 / 结果未知。异步命令被接收不等于动作完成。登记重入、记录补交、读回重试和恢复都不能自动再次进入真实动作；动作后记录失败保留已发生动作与缺口，不能重做动作来补记录。

函数执行报告只证明控制流程；真实动作材料只证明实际执行情况。只有合法前后状态与场景 / 主体关联具备时才按1170、4220生成或关联动态，不用预测、命令或返回值补造目标变化。方法第四部分交付的是动作前已固定依据的预测，不从动作后观察重新拟合本次预测。

正式实际结果必须具有稳定身份、来源执行轮次、方法与冻结引用、实际输出、动作证据、读回证据、当前性和生命周期。函数返回、消息、日志、弹窗、线程退出码、状态记录或动态后状态都不能替代它。

## 9. 目标验证、结果收束与任务完成结算

### 9.1 目标验证

目标达成必须以同一非零事实截止读取任务显式关联需求的共同目标合同和目标涉及的当前特征值完整投影，再完成比较与验证。方法返回成功只说明函数合同返回，不证明目标达成。

任务按5360组织独立事实来源与方法执行路线汇合，分别判断原预测符合度、目标达成、禁止结果 / 副作用及必要归因。独立是事实来源不依赖方法预测或自报，不强制另一个设备、线程或进程；内部治理对象也须经其正式owner重新读回。验证服从允许延迟、观察时机、持续和质量要求；动作前后方向必须用同次执行来源，当前目标判断不得拿过时后状态代替。

无预测不妨碍按独立目标合同判断目标，但不形成预测残差；无观察、不可比或溢出不能形成成功比较值。预测相符而目标未达成、目标达成而预测不符、联合约束失败、禁止结果和归因不足分别记录。预测不符不自动等于任务失败；必要目标或验证不成立也不能以函数成功补足。

### 9.2 每次尝试的结果收束

manager独立读回正式结果后，编排任务业务应用面处理目标、验证、归因、实际停止和冻结收口，再由task owner记录并读回。每个已开始执行轮次必须留下自己的实际结果及收束材料；它们不是任务结算，不新增第二结果账或通用证明节点。

结果未达目标但有推进、没有推进、合法失败、取消、部分动作和结果未知必须区分。能够收束的失败 / 取消只记录并处理结果，不生成任务结算；尚不能确认动作停止或结果发布情况时保留具名未收口，不宣称任务完成。无执行的合法当前满足短路需保存目标比较及零动作来源，不伪造执行轮次或动作结果。

发布未知始终用原幂等身份和原完整请求独立读回收敛。无法确认时停止受影响调用，保留事实与恢复定位；不能另建“不确定结果”替代原请求、补造完成、重做现实动作或删除已发生事实。

### 9.3 完成状态和结算的唯一边界

任务业务应用面确认固定任务目标及必要验证成立、动作 / 停止材料已收束后，由manager请求task owner发布并独立读回任务正式完成状态。合法无执行短路也必须先按固定任务目标完成该裁决。任务完成是结算的前置事实，不以结算成功反向生成完成。

manager发送任务结果与完成状态定位到self。self独立读回后编排task owner执行一次任务完成结算；manager、工作线程不得自行触发任务结算。完成结算按任务身份T唯一，不按执行轮次、结果消息、来源需求或调用槽各结一次。结果汇总可引用同任务多个尝试，不能复制实际结果权威。

完成结算必须可读回：任务身份、正式完成状态 / 状态变更来源、固定目标及本任务实际消费需求关系来源、相关轮次与正式结果 / 验证 / 停止引用、必要成本及各owner已有结果、结算规则和形成截止。零动作完成使用明确零动作来源，不能填空执行身份。数据由既有owner提供，结算不临时制造数值、预算或价值。

任务状态为失败或取消时不做任务结算；等待、未完成或结果未知也不进入此入口。需求是否当前满足、需求是否已经结算、学习是否完成或价值是否准入，都不是任务结算的前置或再次触发条件。任务完成后需求后来不再满足，不撤回完成历史、不重开该任务或再次结算；新的治理按当前事实承接新的任务身份，并遵守同目标当前任务唯一约束。

task owner同时校验任务与完成来源、目标及结果闭包，并保证一个T至多一份完成结算。同T同完整请求返回首次结果；同T异义请求冲突，不因换幂等键而建立第二份。任务已完成但结算尚未成功时保持完成事实并重试原结算，不回退到执行阶段。结算发布后消息或进程丢失时，self从任务正式完成状态和该T的结算读回恢复，不以消息消费水位证明已经结算。

任务完成结算、执行结果收束、轮次调用槽结算、需求当前满足、需求结算、安全 / 价值结算、方法知识更新分别裁决。任务结算不直接改需求、安全值、服务值或方法知识，也不建立结果容量、分配或第二账。

## 10. 子目标、轮次调用返回与self后继决议

任务不持久化父任务 / 子任务树。self根据正式任务材料产生并确认独立必要子目标后，task owner只记录任务子目标承接，需求owner按5170建立或复用子需求；子需求再以自身身份承接任务。

只有本任务轮次实际调用另一个任务轮次时，task owner才建立轮次级发起调用事实。同一被调用任务轮次至多一个发起调用；根任务轮次允许没有。被调用轮次收束后只向唯一调用槽返回并结算该槽，上级必须fresh重读自己的目标事实；历史子任务结果不能直接证明上级目标满足。

任务轮次收束后等待self形成且task owner读回以下一种后继决议：

```text
继续：建立新任务轮次并从其首态推进
等待：记录合法生产者与重触发事实
结束：有正式完成事实则只结束调度；否则按合法取消 / 停止处理，不把“结束”当完成
取消：按取消合同停止并收束
```

本节后继决议用于尚未完成且可继续治理的任务，不要求已有任务结算。任务完成、失败或取消后不能靠继续消息重开同一任务。目标未达成、方法缺失、条件缺失或旧结果都不能自动代替self决议。

## 11. 普通任务、学习与练习材料

普通任务现实结果只作为目标验证、需求裁决、归因和适用主动安全结算的材料，不建立服务合同或服务值账。

普通任务执行方法时可以形成练习材料；该旁路不得阻塞尝试结果收束及适用的任务完成结算，也不得把普通任务改写为学习任务。学习任务结果只进入学习材料、方法候选或方法代际治理；只有后续普通任务实际使用能力并形成现实结果后，才可能进入价值结算。

反馈按同一次任务 / 执行轮次关联所用方法内容、C/R配对、实际条件与实参、原预测或无预测标记、动作进度、独立观察、验证、停止及结果收束来源；任务完成结算仅在存在时引用。只通过既有正式记录和引用读回，不在任务或Vm中增加第二样本权威仓；临时二次计算结果的承载继续服从4151和C038边界，不因反馈用途取得持久实例资格。

成功、合法失败、额外结果和有充分来源的反例均可供5350学习。未执行、未观察、材料不完整及技术失败不得作为某配对无效的正常反例，也不得重复消费同一次反馈冒充多次观察。横向方向分支、竖向精度细分及可靠性判断由学习 / 方法治理处理，任务不按树深或次数自动拆分，不直接发布新配对或晋级方法。

练习任务有目的地获取样本仍须由需求目标及既有任务 / 安全合同约束；观察到转向或精度不足只是候选与后继输入，不授权自动建立任务或试探动作。学习方法A用于完善方法B时，A、B各自方法身份 / Vm / 参数规格与本轮实例来源分开。方法知识评审或发布失败不回滚原任务、原预测或现实动作，后续知识只供新的合法选择使用。

## 12. 写入、事务、幂等与历史

当前组合读取共享共同事实截止；历史读取使用显式历史截止，不得以当前事实补历史缺项。重新筹办、新任务轮次、新实例和新冻结必须保留旧轮历史，不能原地覆盖。

## 13. 业务失败、取消与内部错误

业务失败只表示在合法任务合同内已经形成可验证的失败结果；它必须保留目标、实例、动作、读回、验证和归因证据。资源、投递、发布未知、漂移、ABI、引用、断言和内部不一致不是业务失败。

取消必须由合法self取消后继决议或具名紧急安全停止事实触发，不存在通用“外部授权来源”或第二取消授权。尚未执行时可以停止后继派发；执行中取消必须取得动作停止或不可停止的具名证据，再收束实际结果；失败 / 取消不生成任务结算。只改状态枚举不能证明取消完成。

内部错误不得触发需求、学习需求、方法首、任务失败、等待或下一轮次；只停止受影响调用并保留诊断与恢复材料。

## 14. 验证与完成声明边界

设计和实现验证至少覆盖：

- T、L、`T→D`、Vt、R1和首态的原子建立与读回；
- 任务族身份证明、任务核心公开入口及当前 / 历史读回；
- 一个L至多一个当前T、一个T恰一当前Vt；
- Vm 规格向 Vt 参数实例的完整复制、零参数 / 不定长顺序、逐槽类型匹配、未绑定 / 退出 / 混代拒绝，以及任务间绑定隔离和禁止自动改绑；
- 目标只由当前显式需求关系互证形成；
- Vt状态与任务 / 筹办 / 执行轮次分账；
- 多次找方法完整后才查条件，全部候选条件覆盖后才选择；

- 未完成轮次收束后等待self后继决议，完成 / 失败 / 取消不得重开同一任务；
