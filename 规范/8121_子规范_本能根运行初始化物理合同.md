# 8121 子规范 本能根运行初始化物理合同

直接上级规范：8100。
直接依赖规范：0050、4115、5170、6120、6130、7130、8120。
相关边界规范：4110、4120、4180、4212、4230、5260。

## 1. 范围

本规范只定义启动阶段21的物理发布与正式读回。它消费唯一自我正式读回和已成功的方法登记根；建立或恢复安全、服务两套根材料，返回不可变值式锚点。它不创建线程、任务、具体子需求、动态、因果或服务账。

## 2. 唯一 owner 与持久材料

对于安全 / 服务根特征，阶段21先消费普通应用系统初始化已经交付的双FT/完整域概念值式材料，再调用4115上游的存在类组合提供者`按存在持有特征变更并返回实际F`。调用以唯一自我为持有存在，并把对应FT、完整域概念及初值`I64_MAX/2`作为只读前置；提供者不得在实例路径形成或修复FT和完整域概念。特征owner提供准确F，概念owner建立单值概念并以上述完整域概念为直接上位，存在owner负责IF/R和当前采用。准确F固定准确值，R另行版本化；自我到实际F只按正式当前采用读取，不把F嵌入自我。

`ARCH-L4` 需求 owner 持有目标状态合同、普通需求、父子位置、需求列表项及成员关系。安全根与服务根 D 是独立根需求：各自只有独立需求身份、对应根特征、对应根目标合同、父为空和顺序为0；不得有`所属存在=自我`、`目标宿主=自我`、自我字段、自我关系或自我 owner。根列表项按各自固定初始化身份唯一定位，且当前成员恰为该根 D，不适用普通需求的“所属存在 + 目标三元组”聚合键。根角色不是节点、关系、owner或索引；双根对当前自我内部治理的逻辑归属只由阶段21入口与最终运行锚点表达。

安全 / 服务值的值域、值表示、区间语义、变更规则及任何状态材料属于特征类的上游合同，不由阶段21、自我或存在层决定。阶段21不创建二次概念、二次实例、状态或动态。

## 3. 原子发布、恢复与读回

双FT/完整域概念初始化的幂等、部分恢复和最终读回由其系统初始化合同收束；阶段21只接受完整且同截止的交付。根实例变更的幂等、原请求重放、发布未知、内部事务与最终读回由实例提供者收束；阶段21只消费其实际F或具名非成功，不得另建并行幂等账、状态账或兼容写入。各类固定业务幂等身份不得互相替代或充当节点编码。

初始化器按：验证自我→分别调用根特征变更提供者并取得实际F→目标合同→独立根D/根列表成员→冻结`Gfinal`→全部正式读回执行。阶段21不处理任务实体或任务物理关系。全量读回必须同一非零`Gfinal`，逐字段核验两根实际F不交叉、根父为空、根 D 无自我物理绑定和列表闭包，才返回锚点。首次有任何新发布返回`已形成`；零新发布且完整读回返回`已恢复`。部分但可继续的材料按各自原合同补齐；特征类返回的具名非成功、根材料退出、异义键、错误绑定或不闭合均不得由阶段21重建替代。

## 4. 公开业务合同

业务数据头定义`本能根运行锚点_v1`：阶段21已验证的唯一自我、每根的需求/列表项/实际F/目标合同及`事实截止代次`；其中唯一自我是运行入口上下文，不是任一根 D 的字段、关系或 owner。`完整()`仅作无I/O值式校验。初始化请求只含版本和唯一自我；根特征变更请求及其值 / 时间材料完全属于特征类提供者合同。结果状态仅为`已形成、已恢复、入口拒绝、当前性漂移、幂等冲突、引用冲突、材料未闭合、根材料已退出、已可能发布、资源失败、内部不一致`，非成功空锚点。

业务 provider 只能消费普通应用上下文内同一服务实例；普通应用仅在SELF-FORM与阶段19均成功后调用它，并以其非成功映射`程序失败阶段::本能根运行初始化=21`。成功后缓存本轮值式锚点供后继线程创建；缓存不参与跨进程恢复。发布未知只可用原完整请求/幂等身份收敛。

## 5. 禁止与验证

不得硬编码稳定节点编码、配置文件根编码、扫描创建顺序猜根、向根 D 写入自我字段 / 关系 / owner、在阶段21模拟或拼接特征类变更、复活`.ixx`或旧`L2*` ABI、创建线程或绕过特征类提供者直接操作根F。实施必须证明仅经特征类提供者取得实际F、首次、精确重复、完整重启、部分恢复、冲突、退出、未知发布、最终截止漂移、双根实际F不交叉及根 D 无自我物理绑定；构建不替代上述业务验证。
