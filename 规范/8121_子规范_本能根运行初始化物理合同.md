# 8121 子规范 本能根运行初始化物理合同

编号：8121
日期：20261106
版本：v2.2
状态：正式子规范

直接上级规范：8100。

直接依赖规范：0050、1150、3100、6130、6190、7130、8120。

相关边界规范：1130、1140、4015、4202、8200。

## 1. 范围

本规范规定self线程初始化时如何建立并读回物理全局根、各世界根、自我、安全值/服务值实例特征及双根。它只定义初始化物理顺序和结果，不建立运行锚点、初始化包、业务历史或第二当前权威。

## 2. 唯一结构

初始化完成后必须具备：

```text
全局基础数据集
├─ 物理全局根场景（只挂世界根）
│  ├─ 现实世界根
│  │  └─ 自我所在场景
│  │     └─ 自我存在节点
│  ├─ 自然语言世界根
│  └─ 内部治理世界根
├─ 需求树根
│  ├─ 安全根需求
│  └─ 服务根需求
└─ 方法根

唯一自我存在
├─ 安全值实例特征
└─ 服务值实例特征
```

模拟世界根按需由模拟学习首次使用时建立（4202），不在本初始化中建立。物理全局根不具成员、特征、状态、动态或专属概念（1150）。特征值组织、四本体概念根和自然语言组织按各自规范初始化，不因本规范另建第二份。

需求树根、方法根只是需求树、方法树的组织根，不替代场景归属。以后建立的T、Vt、方法、X、A是内部治理世界中的信息存在，作为内部治理世界场景的成员（具体场景划分由世界组织规范规定，未细分时为内部治理世界根的成员）；它们持有的F当前值变化时，状态挂入所在场景的状态列表。需求（含双根需求）不是存在，不建立场景成员关系，其F更新不生成状态（0050第1.4节）。

全局`全局根场景节点`、各世界根节点、`自我所在场景节点`和`自我节点`保存对应稳定编码；稳定编码本身是身份，但业务类型和结构仍须经各类完整读回确认。

## 3. 初始化顺序

1. 初始化基础数据集及持久单调编码高水位。
2. 初始化先天特征类型和四本体概念根；分别建立安全值FT（非负`0..M`完整域概念）、服务值FT（有符号I64全域完整域概念）。
3. 调用世界树类初始化函数建立或精确复用物理全局根，以及现实、自然语言、内部治理三个世界根，各世界根按“全局根＋世界类型”唯一定位（4202）。
4. 在现实世界根下建立或精确复用自我所在场景。
5. 在该场景内建立或精确复用自我存在（以存在根实例化，7130），并设置全局节点变量。
6. 为唯一自我建立或精确复用安全值、服务值两个实例特征及其冷启动当前值，并完整读回。
7. 初始化需求树；通过需求类一次建立或精确复用安全根与服务根。两根都保存目标存在=唯一自我和各自目标特征类型，不保存根实际特征字段。
8. 初始化方法根和本能函数登记。本能只有在方法职责、必要参数场景、结果取得及实现合同已冻结后，才登记方法头；未冻结者不因任何设计指针取得登记资格。
9. 分别完整读回全局根、各世界根、自我、双根目标及其各自权威当前值。
10. 全部成功后才允许self治理开门。

前一步未完成时不得越过建立后一步。普通初始化重复调用必须精确复用现有结构；发现同一角色多个节点、父关系不一致或定义异义时返回结构冲突。

## 4. 双根与根实例特征合同

双根需求固定为值目标初始化例外（目标存在＋完整值目标，3100）；不设专属需求种类。

安全根和服务根目标均固定为`INT64_MAX`，冷启动首次当前值均为`INT64_MAX / 2`，承载严格分开：

- 安全根拥有安全FT、完整域概念、自我安全值实例特征、目标合同、根需求和固定列表项；安全值读回须位于`0..M`，越界为内部不一致；
- 服务值由唯一自我的服务值实例特征持有，为有符号I64；读回不按非负核验，负值合法；服务根保存目标存在、服务值类型根和目标合同，实际特征每次fresh定位；根差`M-V`溢出时饱和为`INT64_MAX`即“需增加”（3100、6130），不得作为初始化或运行期工程异常；
- 两根由需求类按具名角色读取，不按顺序、名称、编码大小或目标值猜测；
- 读取采用current-only，不携带事实截止、业务合同版本或历史见证；6190的结算/衰减规则以规则标识区分；
- 双根共同建立失败时不得返回半成功。当前底座不能跨业务类崩溃原子发布时，已经合法发布的安全值/服务值特征结构保留，下一次按原定义精确复用并继续，但本次初始化整体仍返回非成功并保持停门。

根身份直接来自正式需求结构。不建立运行锚点、角色节点、角色关系、固定业务幂等身份、原请求账或第二需求账。

## 5. 结果与失败

初始化返回结构化状态，至少区分：

```text
已建立
已复用
入口拒绝
定义冲突
结构不一致
依赖未实现
资源失败
```

成功结果必须包含全局根、各世界根、自我所在场景、自我、安全值/服务值实例特征、安全根、服务根和方法根身份，并由调用方再次完整读回。

当前基础数据集没有跨多个业务类的崩溃原子事务时，初始化只能分阶段发布；后段失败保留已经合法发布的前段结构，下一次按current-only结构精确复用并继续。不得通过删除已发布世界、自我或根需求来伪造整体回滚。

## 6. 禁止与验证

禁止：

- 在应用入口或manager重复拼装世界根、自我或双根字段；
- 以线程创建成功代替初始化成功；
- 为初始化步骤建立任务；
- 使用事实代次、历史读回、运行锚点或初始化包证明当前结构；
- 只建立一个根却打开治理门；
- 用默认编码、名称或创建顺序猜测根角色；
- 以`0..M`核验服务值，或把服务根差溢出当作工程异常；
- 因后段失败删除已经合法发布的前段结构。

最低验证覆盖首次建立、重复精确复用、全局根与三个世界根唯一、两个FT/两个实例特征唯一、双根目标存在绑定唯一自我、单根或实例失败停门、角色复义、父关系错误、双根定义冲突、负服务值读回合法且根差饱和、后段失败再入、完整读回和治理门控制。
