# 5130 子规范 需求信息来源自检与身体反馈

编号：5130
日期：20260903
版本：v0.6
状态：正式子规范

## 1. 定位

本规范定义根特征自检、普通自检、身体反馈和方法自检如何形成父任务治理材料，以及它们与正式需求、任务、动作和结算的边界。

直接上级规范：3100。

直接依赖规范：5150。

相关边界规范：5100、6130。

## 2. 父任务材料生成

1. 根特征自检必须冻结非零事实截止，读取正式抽象特征定义、目标状态合同以及自我实例目标特征的当前值完整投影，并按合同比较当前特征值；不得先读取状态记录再把其中的值当作当前值。
2. 正常值、区间、目标状态合同和比较规则不得来自硬编码函数表、显示文本或控制面板。
3. 自检和身体反馈只生成缺口报告或强类型父任务材料，不得直接写需求树、刷新权重或创建任务。
4. 子存在只报送自身可观察特征和值；自我领域必须重新读取目标当前值，并根据主体、目标定义、目标状态合同和同截止当前值裁决是否形成父任务材料。
5. 若不能确定主体、目标特征、目标状态合同，或者不能完整读取同截止当前特征值，材料只能保留为报告或进入观察 / 诊断闭环。状态或动态存在不能补齐缺失的当前值。

## 3. 父任务承接与去重

父任务材料必须携带主体、目标宿主、目标特征、事实截止、当前特征值完整投影、目标状态合同、比较裁决、来源证据和合同版本，并提交给其应归属的安全或服务父需求。没有活动任务时可以据该材料幂等建立、唤醒或复用父需求治理任务，但只用于 fresh 重判与材料裁决，不等同根正差距、不改变根值，也不直接创建需求。self 只有在 fresh 产生并确认目标独立、必要、严格缩小父需求及祖先尚未闭合范围、父域合法且具有明确并最终可判定的自身目标状态合同后，才可要求 task owner 记录为正式子目标承接记录；需求 owner 随后据该记录在发布前精确匹配并发布或复用子需求。已发布需求身份不得合并、覆盖或删除。该分支不以筹办完成、已有可执行路径或方法已选择为前提，也不建立采用状态账。相关状态 / 动态身份可以作为历史与变化证据附带，但不能成为当前值字段或第二比较输入。

同一父需求下的同目标材料可以在进入 self 裁决前合并；正式发布前精确命中既有 D 时复用该 D，已发布需求身份不得合并。来源报告和归因差异不得作为新需求身份键。来源、自检类型和获取途径只作为父任务材料归因，不进入需求目标字段或需求来源关系。

## 4. 方法自检

1. 方法维护总目标收束为方法状态目标，不把动作、条件结果对、运行次数、成功次数和成熟度拆成无边界的平行需求。
2. “方法状态 = 好用”是维护目标；运行账和条件结果对是证据。第一轮不得仅按运行次数或成功次数宣布好用。
3. 执行学习或练习时发现最低可用性缺口，可形成“方法状态 = 可用”等结构化材料，提交给当前父需求任务作为筹办材料；不得直接进入需求树。
4. 自检不得直接修改方法状态、动作入口、条件结果对或运行账。
5. 代码缺陷、结构损坏和状态机非法只进入开发诊断，不得伪装成方法学习需求。

## 5. 安全与服务边界

1. 影响自我处理任务、学习、应急和安全行动可靠性的自检缺口可作为安全信号，但不等于物理安全已经变化或修复。
2. 安全信号只进入安全根域；服务信号只进入服务根域，二者不得互相兜底。
3. 服务对象的内在状态不可直接读取；服务反馈只能来自外在表达、确认、回执和外在状态变化。
4. 自检报告生成时不得提前结算安全或服务价值；只有问题解决、目标满足、验证和归因成立后才能走叶子任务结算链。
5. 未分类安全材料只能进入安全根或其后继安全父需求任务作为任务材料；在 self fresh 产生并确认目标独立、必要、严格缩小祖先范围、父域合法且具有明确并最终可判定的自身目标状态合同，并由 task owner 记录为正式子目标承接记录、需求 owner 发布需求前，不得挂入需求树。

## 6. 动作来源和任务去重

正式入树、合并、满足和结算若产生动作动态，动作来源必须是对应需求领域方法；线程只是调度者。

自检材料可以持续提交。同一方法同时只能有一个活动学习或补齐任务的约束，应在正式任务创建入口去重，不得让自检线程因已有任务而停止报送新事实。

## 7. 验证

最终验证必须证明：抽象定义和目标状态合同是目标来源；父任务材料不直接入树；只有经 self fresh 产生并确认独立、必要、父域合法、严格缩小祖先范围且目标合同最终可判定后，由 task owner 记录的正式子目标承接记录可被需求 owner 消费；该确认不依赖筹办选定方案；发布前同目标精确复用且已发布需求身份不合并；缺主体 / 目标合同 / 同截止当前值被拒绝；动态触发后重新读取当前值；状态记录不能替代当前值；代码缺陷进入诊断；安全与服务信号不互相兜底；自检完成不直接结算。该验证随整条链路完成后统一执行，不作为每个中间子目标继续推进前的独立验收停点。
