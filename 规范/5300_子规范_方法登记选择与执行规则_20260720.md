# 5300 子规范 方法登记选择与执行规则

编号：5300
日期：20260826
版本：v1.0
状态：正式子规范

## 1. 定位

本规范展开方法登记、角色、规格、能力、条件结果对、召回选择、运行事实、任务特征声明、动作动态和学习证据合同。

直接上级规范：3300。

直接依赖规范：1160、1170、1190、3200、4010、4020。

相关边界规范：4210—4230、5230、5310、5320、5340。

## 2. 方法结构角色

方法领域必须能够区分并验证：

| 角色 | 责任 |
| --- | --- |
| 方法登记根 | 管理方法登记项和当前生命周期集合 |
| 方法首 | 稳定方法身份、唯一治理虚拟存在和结构根 |
| 方法条件 | 输入、作用对象、目标特征、期望状态和来源版本 |
| 方法结果 | 输出、作用对象、目标特征、目标状态和来源版本 |
| 条件结果对 | 在确定条件下产生确定结果的样本、统计和稳定证据 |
| 动作入口 | 可调用能力、共同场景约束、直接作用主体、稳定动作键和当前状态 |

结果必须归属于具体方法并与适用条件保持可追溯关系。同一结果在不同条件下的统计不得混并。

动作入口的输入 / 输出场景使用 4010 锁定的关系类型 17。源必须是动作入口方法节点，目标必须是场景；顺序号 1 表示输入场景，顺序号 2 表示输出场景。同一完整源动作入口和同一角色至多一条有效关系，同一场景可以同时承担输入与输出两个不同角色。

方法领域服务是关系 17 的唯一业务写入与解释方。未知顺序号、错误端点类型或同源同角色第二条有效关系必须在写前拒绝；普通引用槽位即使同为 1 / 2，也不得替代专用关系 17 或据此裁决动作入口完整。

## 3. 方法治理虚拟存在

每个方法首拥有唯一治理虚拟存在，承载长期身份、能力、方法状态、允许召回/执行、任务特征声明、运行摘要、统计和学习证据。

治理虚拟存在不得承载某个任务的参数、自我现实执行授权、筹办结果、执行回执或本轮运行细账。不同方法必须以真实动作、目标、条件、结果或作用范围区分；语义完全等价时应复用或合并，而非只换主键重复建立。

## 4. 条件、结果和条件结果对

1. 条件项和结果项必须声明作用对象；需要保持同一对象时使用强类型绑定关系，不用文本绑定名作权威。
2. 条件和结果规格必须关联场景、目标特征、抽象状态、来源版本和当前性。
3. 方法可以有多个条件、多个结果和多组条件结果对；单个结果命中当前任务目标即可进入候选，其它结果仍按 5120 分类。
4. 条件或结果不可比较、作用对象不同、方向不同或规格版本不同的样本不得融合。
5. 候选条件结果对必须显式标记候选；只有真实运行反复验证后才能升格为稳定。
6. 方法动作的直接作用主体与条件 / 结果主体必须分账。方法可以通过改变共同场景中一个存在的特征，经正式因果链使另一个存在达到结果状态；此时必须显式冻结共同场景、直接作用主体、结果主体、直接变化、因果链和结果验证合同，不能把结果主体伪装成第二动作场景或以动作返回成功代替结果成立。

## 5. 方法状态和证据

方法状态必须是强类型方法特征，不使用“缺动作、缺条件、不可用”等自由文本作为状态值。结构缺口、运行次数、成功次数、连续成功、成熟度和条件结果对数量是判定证据或解释材料。

方法“可用”至少要求当前动作入口和最低执行规格成立；“好用”还要求稳定复现、质量和约束证据。具体值域、阈值和迁移矩阵必须在独立方法状态子规范形成后生效，不得由实现常量反向定义。

### 5.1 方法生命周期记录

方法生命周期由方法结构 owner 自己的强类型治理记录承载，不复用 4230 世界状态节点，也不使用固定数值“关系类型 23”作为公开或持久 ABI。方法治理虚拟存在不是 `L2存在身份`，不得为了形成生命周期而把它注册为世界存在、场景成员、特征宿主或 `L2状态事实`主体。

每份方法生命周期事实至少包含方法身份、从 `1` 连续递增的生命周期版本、发生时间、来源和结构创建 / 退出生命周期。同一方法恰有一份当前生命周期事实；迁移必须在方法 owner 的同一事实事务中建立新生命周期事实并退出旧当前事实，历史完整保留。内部可以使用由方法 owner 正式登记的关系和属性类型承载，但公开读取只返回强类型方法生命周期事实，不暴露固定关系编号、L1 关系类型、普通模板关系或无类型槽。

方法结构服务只校验方法身份、版本连续、发生时间、来源、当前唯一和历史完整，不判断方法是否可用、好用或应该被选择。方法业务层需要场景、状态或其它世界事实条件时，必须在同一非零事实截止经相应世界结构公开服务独立读回并组合裁决；这些世界材料不是方法生命周期字段，也不得被方法 owner 复制为第二权威事实。

方法内容版本、规格版本和生命周期版本彼此独立，三者都必须能够被 5230 的任务选择冻结精确读取。前置通过后出现当前生命周期复义、版本不连续、混代或读回矛盾属于内部不一致。

## 6. 任务特征声明

方法必须声明任务执行它时需要挂载的特征类型，包括输入、参数、阶段、共同场景、逐动作直接作用主体、直接现实副作用、预计因果后果、安全限制、禁止项、验证、归因、失败处理和输出路由。只有作用范围包含现实改变步骤的实例方法，才需要在执行冻结完成后、任务进入执行阶段前绑定一份覆盖直接动作和预计因果后果的自我现实执行授权；内部治理与纯现实观察不声明授权条件。

组合方法还必须声明跨方法协调、顺序、并行、回流和失败收束特征。任务只挂载这些正式声明，不得自行发明。

## 7. 召回与选择

1. 召回先按结果能力获取候选，再回读权威规格和生命周期复判。
2. 选择权属于取得任务筹办执行权的任务领域；方法服务和召回索引不提交任务选择。
3. 选择优先级依次是结果一致、条件与参数闭合、禁止和风险、运行质量与成本。
4. 无候选时不得创建方法首，不得使用通用写入、内核原语或名称匹配兜底。
5. 方法不可用或规格不完整时，只能形成具体缺口、等待或内部错误，不能伪装成已选择可执行方法。

### 7.1 C031 选择权和可比较边界

第 7 节中的“任务筹办执行权”改为“任务领域取得的执行前选择工作项执行权”。筹办 provider 只做粗召回和逐方法条件组发现；它不拥有对象 / 方向 / 结果适用判断、条件满足判断、实际选择或冻结权。

执行前选择先以 fresh 截止硬过滤目标 / 结果合同、方法生命周期和入口、选项自身条件组 / 输入 / 参数、范围、验证 / 归因、禁止、结构拒绝和安全硬否决，再按`结果一致 -> 条件与输入闭合 -> 禁止与风险 -> 运行质量`的现有顺序比较剩余选项。前两层与硬禁止已完成过滤时不得重复造一个总分或总成本账。

安全硬否决和生存安全控制态不可抵销；服务根当前值、服务合同 / 余额、预期服务进展、队列长度和线程状态不是选择维度。运行质量只有具有正式来源、单位、作用范围和规则版本且可比较时才能参与。未知、不可比或并列最优须返回具名待裁决定位，禁止以遍历、编码、名称或哈希打破平局。

## 8. 运行事实与返回账

每次真实方法运行必须具有独立运行身份，至少关联方法、任务或调用上下文、共同作用场景、直接作用主体、预计因果结果主体、开始与结束时间、动作动态、执行摘要和当前版本。

方法治理虚拟存在只同步长期统计和最近摘要；本轮前后值、参数和输出留在运行事实及场景中。

动作运行成功不等于目标结果符合；结果符合/不符合统计只有在目标、输出和验证合同可比较时才能更新。

## 9. 动作动态和因果

主动动作真实调用方法时必须生成动作动态；被动状态提交由具名提交方法生成被动动作动态；非业务派生整理不生成主链动作动态。

方法未执行、条件不满足、只形成候选或只收取消息时不得伪造真实动作动态。线程不是动作来源。

状态变化线索可帮助发现前置和联动，但只有直接作用主体的动作动态、间接结果主体的实际状态 / 动态、条件、正式因果链和复现证据共同成立时，才能支持完整动作因果和方法能力升格。执行函数和方法返回值不得直接写入或补造间接结果主体的权威状态。

## 10. 学习和写入权

方法可以输出候选结构、样本和结构化缺口，但不能自行创建需求或任务。目标方法长期账只由目标方法自身执行路径或方法领域正式提交入口更新。

方法领域服务是登记、规格、条件结果对、动作入口、生命周期和长期账的唯一业务写入方；外部模块不得直接写仓库关系。

方法内容版本必须与生命周期版本、规格来源版本和任务选择快照保持身份分离。学习候选或晋级服务不得直接改写方法；只有方法领域服务可以在独立晋级通过后发布不可变的新代际方法身份。新代际不得原地覆盖来源方法，具体晋级、父代、可见性和同轮隔离由 5340 唯一规定。

## 11. 验证

验证必须覆盖角色端点、唯一治理虚拟存在、方法 owner 强类型生命周期当前唯一、生命周期版本从 1 连续递增、历史完整保留、完整生命周期事实、生命周期和内容版本分离、索引复判、多条件多结果、不同条件下相同结果不混账、任务特征来源、动作动态来源、运行账分离和无候选边界。不得以固定关系 23、世界状态节点或普通模板关系代替该验证。
