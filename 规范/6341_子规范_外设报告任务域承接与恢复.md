# 6341 子规范 外设报告任务域承接与恢复

编号：6341
日期：20261105
版本：v1.0
状态：正式子规范

直接上级规范：5260。
直接依赖规范：3200、6340。
相关边界规范：5090、6300、6380、8100、8210。

## 1. 定位

本规范规定任务域怎样承接6340外设控制域生产的报告：承接步骤、一次承接竞争、正式提交隔离，以及跨重启时已承接材料的恢复。外设控制域、命令与报告合同、实时舍弃和队列重建由6340规定。

## 2. 任务域承接

任务域是外设报告队列的唯一正式消费者。任务域承接至少执行：

1. 验证报告来源、完整性、配置标识和时效；
2. 匹配当前任务、等待项、订阅项和活跃需求；
3. 更新非权威最新报告缓存；
4. 按产品类型形成绑定任务和工作项的已承接外设材料引用、供 self 裁决的目标材料 / 正式子目标记录定位、动作验证输入或结构化缺口；不得由外设或任务域生成需求；
5. 请求相应领域服务完成正式提交。

任务域不得直接改写存在、场景、特征、状态、动态、因果或价值事实。筹办与执行仍按任务域规范运行，外设报告不能绕过筹办成为当前方法或执行冻结。自我线程和普通任务工作线程不得绕过任务域直接读取报告队列；当前冻结方法只能读取本工作项已经承接的材料引用。

同一报告的一次承接以报告稳定身份作为唯一竞争键。消费窗口、任务、工作项、队列位置和消费代次只参与当前性、授权和绑定校验，不得与报告身份组成能够放宽唯一性的复合竞争键。任何两个窗口、任务或恢复代次都不得让同一报告稳定身份形成两个当前承接。

## 3. 已承接材料的恢复与一次承接

6340恢复流程中已正式承接的报告，由任务域只恢复任务侧已承接引用，不重新消费报告，不退回队列再次竞争；任务或工作项不再当前者形成强类型收束结果。

恢复后的再次投递不是第二份报告事实；同一报告稳定身份在全部代次中至多形成一次正式承接。已承接但工作未完成的材料由任务领域按任务恢复合同继续治理，不能退回队列再次竞争。生产代次、消费代次和重连代次必须使用稳定结构与单调序号互证，裸线程号、进程号、队列位置和日志序号不得参与一次消费裁决。

任何恢复候选、重新投递或已承接引用仍只是材料或任务治理事实，不得因跨重启保存而升级为世界事实。出现同一报告双承接、已消费报告重新入队、四索引与物理队列不一致或半恢复队列对消费者可见，属于内部恢复逻辑错误。

## 4. 禁止规则

1. 作用外设执行成功不得直接解释成需求或任务完成。
2. 任务域不得直接改写存在、场景、特征、状态、动态、因果或价值事实。
3. 自我线程和普通任务工作线程不得绕过任务域直接读取报告队列。

## 5. 验证边界

验证至少覆盖任务匹配、一次承接竞争键、正式提交隔离、跨重启已承接引用恢复和同一报告至多一次正式承接。

缺少真实报告、任务承接与正式事实提交证据时，不得宣称外设报告承接闭环已经实现。
