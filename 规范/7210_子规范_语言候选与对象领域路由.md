# 7210 子规范 语言候选与对象领域路由

编号：7210
日期：20260814
状态：正式子规范

直接上级规范：1100。

直接依赖规范：2200、2220。

相关边界规范：1110、2210、7200。

## 1. 定位

本规范规定语言材料、人类词性、候选对象角色和对象领域服务之间的路由边界。路由是业务层形成的不可变候选与请求，不建立长期“信息入口类型节点”或“语素入口节点”。

## 2. 四层分工

```text
语言材料和人类词性
-> 产生候选解释

候选对象角色
-> 指明可能需要哪类业务对象

上下文消歧
-> 选择已有对象或形成创建请求

对象领域服务
-> 裁决并写入正式对象结构
```

正式词性不决定概念本体根。它只能由 L5 外语言候选路由业务形成零个、一个或多个存在 / 特征 / 动态本体根和对象角色候选；它不直接决定具体概念、世界实例、节点类型、存储分区和是否可以发布。

## 3. 候选对象角色

候选对象角色可以表达存在 / 特征 / 动态本体根、独立概念、世界存在实例、特征定义、特征实例、二次特征、状态、动态、关系、因果、场景、需求、任务、方法和语言记录等已登记角色。

候选角色只存在于带来源语言位置、解析合同和上下文的值式材料中。只有系统确实存在相应对象领域服务时才能生成该角色；未知或证据不足保持未理解候选，不以默认角色补齐。

### 3.1 任务局部路由 provider

`语言候选路由业务` 是 L5 之外的唯一解释 owner。它只消费结构服务正式读回和值式上下文，不拥有语言、词条、词性、概念、名称关系或路由持久结构，也不被任何 L1—L5 服务反向调用。

任务局部 `词性候选路由请求` 至少包含：语言记录位置、显式语言身份或“使用项目默认语言”、零至多个正式词性候选身份、未过滤名称候选组、目标领域上下文、路由规则身份与版本、来源解析合同和事实读取截止。`词性候选路由结果` 至少包含：结构化状态、逐项回显、每个输入词性对应的零至多个本体根 / 对象角色候选、确定排序、使用的规则身份与版本和证据引用。

请求未显式指定语言时，只能选择 1100 已正式读回的项目默认汉语身份；尚无该身份时返回“默认语言能力未形成”，零对象写入。没有正式词性候选时返回“词性尚未形成”并保留未过滤名称候选，不生成默认词性。短语只能作为带位置和解析合同的语言材料参与候选，不得冒充词性身份。

路由结果是当前请求内的值式材料，以输入事实截止和规则版本限定当前性；调用结束后可以丢弃和重算，不取得稳定身份、生命周期或引用保护。若未来需要持久权威路由表，必须另行冻结 owner、DTO、发布、读回、换代、退出和恢复合同，不能从本任务局部结果推导。

## 4. 词条和概念名称

词条只保存语言、规范化词面和稳定身份。概念名称只由 2210 概念—词条名称关系表达；从词条反查的概念集合按 7200 消歧。

人类词性经任务局部路由形成零个、一个或多个本体根 / 对象角色候选，并据此缩小或排序完整名称候选集合；同一词性可以到多个根，同一根可以由多个词性表达。短语可以形成对象角色候选，但不是正式词性身份。路由不得修改词条、名称关系或概念本体。具体概念、上下位、抽象签名和世界事实支持关系仍由正式概念结构与业务裁决成立。

形容词、名词、动词、副词、介词或短语与本体根之间都不是一一对应。基础特征和二次特征可以由形容词、名词、副词或比较短语表达；语言表达方式不得改变概念属于特征根及其真实阶次。

## 5. 领域路由

消歧后需要查找或创建对象时，业务组合器把强类型请求提交给该对象唯一领域服务。语言服务和路由器不得代替目标领域创建对象，也不得直接写仓库。

原始语言材料继续进入语言记录；概念名称使用 2210；实例长期别名由实例对象领域定义；一次指代使用 1110；临时解析信号不发布为长期对象。

## 6. 标准流程

```text
接收语言记录
-> 形成词出现、词条和人类词性候选
-> 将外部词性形成正式词性候选
-> 经名称结构服务读回未过滤的完整当前名称候选
-> 形成包含完整名称候选、上下文、规则版本和事实截止的词性候选路由请求
-> 唯一 L5 外语言候选路由业务形成任务局部多对多根 / 对象角色候选
-> L5 之外业务层直接消费该结果完成概念召回缩小、消歧和准入
-> 调用目标领域服务查找或创建对象
-> 保存适用的名称关系、实例别名或一次指代
-> 完整读回
```

任何一步证据不足都停留在候选层，不得先创建对象再靠后续扫描修正。

## 7. 只读投影

任务局部语言路由投影至少回显语言记录位置、词条、词性候选、候选对象角色、候选对象组、规则身份与版本、来源解析合同、事实截止和上下文摘要。投影不具有独立身份，可以清空重建，不得反写词条、名称关系或对象事实。

## 8. 禁止规则

1. 不得用未登记的外部词性直接决定本体根、对象类型、场景或存储位置；正式词性只能由具名请求中的路由规则形成零至多个任务局部候选。
2. 不得建立持久化语素入口或通用信息入口节点。
3. 不得用一个通用对应信息关系连接所有对象领域。
4. 不得把未理解材料按默认表直接落入存在、需求、任务或方法领域。
5. 不得用显示名称、文本长度、外部词性编码或索引首项完成路由。
6. 不得让路由候选替代目标对象领域准入和事实裁决。

## 9. 验证

验证至少覆盖一词性多根、一根多词性、零路由、多词性候选、默认汉语身份存在 / 缺失、无词性不猜造、短语不冒充词性、形容词 / 副词 / 短语不决定基础或二次阶次、规则版本和事实截止回显、上下文消歧、概念 / 实例分流、未理解保持候选、目标领域二次准入、路由投影清空重建、L1—L5 零反向依赖和无路由持久结构。
