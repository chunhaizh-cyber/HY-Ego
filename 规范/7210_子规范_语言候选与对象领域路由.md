# 7210 子规范 语言候选与对象领域路由

编号：7210
日期：20260815
状态：正式子规范

直接上级规范：1100。

直接依赖规范：2200、2220。

相关边界规范：1110、2210、7200。

## 1. 定位

本规范规定语言材料、词条名称候选、候选目标强类型、候选对象角色和对象领域服务之间的路由边界。路由是业务层形成的不可变候选与请求，不建立持久词性、信息入口类型、语素或语素入口节点。

## 2. 四层分工

```text
语言材料和词出现
-> 召回词条及未过滤名称候选

候选目标正式强类型
-> 提供类型事实

候选对象角色
-> 指明可能需要哪类业务对象

上下文消歧
-> 选择已有对象或形成创建请求

对象领域服务
-> 裁决并写入正式对象结构
```

词条不保存类型，也不决定概念本体根。候选的本体根和对象类型只能从名称目标的正式强类型结构读取；`DATA` 外语言候选路由业务再结合本次句法和上下文形成零个、一个或多个对象角色候选。该值式结果不直接决定具体概念、世界实例、存储分区或是否可以发布。

## 3. 候选对象角色

候选对象角色可以表达存在 / 特征 / 动态本体根、独立概念、世界存在实例、特征定义、特征实例、二次特征、状态、动态、关系、因果、场景、需求、任务、方法和语言记录等已登记角色。

候选角色只存在于带来源语言位置、解析合同和上下文的值式材料中。只有系统确实存在相应对象领域服务时才能生成该角色；未知或证据不足保持未理解候选，不以默认角色补齐。

### 3.1 任务局部路由 provider

`语言候选路由业务` 是 `DATA` 之外的唯一解释 owner。它只消费结构服务正式读回和值式上下文，不拥有语言、词条、概念、名称关系、目标对象或路由持久结构，也不被任何 DATA 服务反向调用。

任务局部 `语言候选路由请求` 至少包含：语言记录位置、显式语言身份或“使用项目默认语言”、词出现和词条、未过滤名称候选组、逐候选目标强类型读回、句法关系、目标领域上下文、路由规则身份与版本、来源解析合同和事实读取截止。`语言候选路由结果` 至少包含：结构化状态、逐项回显、零至多个对象角色 / 对象候选、可选本次词性判断、确定排序、使用的规则身份与版本和证据引用。

请求未显式指定语言时，只能选择 1100 已正式读回的项目默认汉语身份；尚无该身份时返回“默认语言能力未形成”，零对象写入。名称候选为空、目标强类型尚未形成或上下文不足时，返回对应结构化状态并保留能够回显的完整材料，不生成默认类型或默认词性。短语只作为带位置和解析合同的语言材料参与候选。

路由结果是当前请求内的值式材料，以输入事实截止和规则版本限定当前性；调用结束后可以丢弃和重算，不取得稳定身份、生命周期或引用保护。若未来需要持久权威路由表，必须另行冻结 owner、DTO、发布、读回、换代、退出和恢复合同，不能从本任务局部结果推导。

### 3.2 L5 生产路由与默认语言 ABI

唯一生产路由入口为 `语言候选路由业务::形成候选`，唯一裁决入口为 `语言候选裁决业务::裁决`。两者均位于 `DATA` 外，不拥有 L2 语言、词条、概念、名称关系或目标对象事实。

默认语言不是字符串常量。`语言候选路由业务` 必须先经正式 L2 语言服务按登记键取得语言；首次缺失时提交正式 `L2语言新增请求`，然后独立按登记键和按身份读回，只有当前语言事实、登记键、来源和同截止材料逐字段一致时才可作为默认语言。进程内缓存只能加速重放，不能决定语言身份或成功。

候选路由请求必须携带语言身份、词条身份、未过滤名称关系组、逐项目标强类型读回、语言记录位置、句法关系、对象领域上下文、解析合同 / 路由规则身份与版本、期望事实截止和候选预算。结果必须回显完整输入、确定排序的零至多个候选、实际截止、规则版本和证据引用；不得因默认汉语、词面、索引首项或外部词性标签补齐候选。

唯一候选裁决必须由 `语言候选裁决业务::裁决` 产生具名证据。未理解、多义、上下文不足、候选已退出、坏引用、许可拒绝和资源失败均只返回值式结果，不得调用名称关系写入口。自然语言表达只能消费已裁决名称绑定和上下文形成值式表达，不写 L2 事实、不创造概念或名称。

## 4. 词条和概念名称

词条只保存语言、规范化词面和稳定身份。概念名称只由 2210 概念—词条名称关系表达；从词条反查的概念集合按 7200 消歧。

任务局部路由先保留完整名称候选，再逐项消费目标概念或对象的正式强类型，并据本次句法和上下文缩小或排序。相同词条可以命名多个不同类型目标，同一目标也可以有多个词条名称。可选词性判断只是本次使用方式的值式说明。路由不得修改词条、名称关系、概念本体或目标对象；具体概念、上下位、抽象签名和世界事实支持关系仍由正式概念结构与业务裁决成立。

形容词、名词、动词、副词、介词或短语等人类分类只描述本次表达方式，与本体根和对象类型都不是一一对应。基础特征和二次特征可以由多种词类或比较短语表达；语言表达方式不得改变目标概念属于特征根及其真实阶次。

## 5. 领域路由

消歧后需要查找或创建对象时，业务组合器把强类型请求提交给该对象唯一领域服务。语言服务和路由器不得代替目标领域创建对象，也不得直接写仓库。

原始语言材料继续进入语言记录；概念名称使用 2210；实例长期别名由实例对象领域定义；一次指代使用 1110；临时解析信号不发布为长期对象。

## 6. 标准流程

```text
接收语言记录
-> 形成词出现并召回当前词条
-> 经名称结构服务读回未过滤的完整当前名称候选
-> 逐项经概念或目标领域服务读回候选本体根和强类型
-> 形成包含语言位置、完整候选、目标类型、句法、上下文、规则版本和事实截止的语言候选路由请求
-> 唯一 DATA 外语言候选路由业务形成任务局部对象角色候选和可选词性判断
-> DATA 外业务层直接消费该结果完成概念召回缩小、消歧和准入
-> 调用目标领域服务查找或创建对象
-> 保存适用的名称关系、实例别名或一次指代
-> 完整读回
```

任何一步证据不足都停留在候选层，不得先创建对象再靠后续扫描修正。

## 7. 只读投影

任务局部语言路由投影至少回显语言记录位置、词条、完整名称候选、候选目标强类型、句法关系、候选对象角色、候选对象组、可选本次词性判断、规则身份与版本、来源解析合同、事实截止和上下文摘要。投影不具有独立身份，可以清空重建，不得反写词条、名称关系或对象事实。

## 8. 禁止规则

1. 不得用词面、词条、外部词性标签或本次词性判断直接决定本体根、对象类型、场景或存储位置；对象类型只能来自候选目标的正式强类型结构。
2. 不得建立持久化词性、语素、语素入口或通用信息入口类型节点。
3. 不得用一个通用对应信息关系连接所有对象领域。
4. 不得把未理解材料按默认表直接落入存在、需求、任务或方法领域。
5. 不得用显示名称、文本长度、外部词性编码、默认词到类型表或索引首项完成路由。
6. 不得让路由候选替代目标对象领域准入和事实裁决。

## 9. 验证

验证至少覆盖同词条多目标类型、同类型多词条、零 / 单 / 多名称候选、目标类型缺失、默认汉语身份存在 / 缺失、上下文不足不猜造、短语和外部词性标签不冒充类型、形容词 / 副词 / 短语不决定基础或二次阶次、规则版本和事实截止回显、上下文消歧、概念 / 实例分流、未理解保持候选、目标领域二次准入、路由投影清空重建、DATA 零反向依赖和无路由持久结构。
