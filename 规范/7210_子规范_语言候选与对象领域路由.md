# 7210 子规范 语言候选与对象领域路由

编号：7210
日期：20260812
状态：正式子规范

直接上级规范：1100。

直接依赖规范：2200、2220。

相关边界规范：1110、2210、7200。

## 1. 定位

本规范规定语言材料、人类词性、候选对象角色和对象领域服务之间的路由边界。路由是业务层形成的不可变候选与请求，不建立长期“信息入口类型节点”或“语素入口节点”。

## 2. 四层分工

```text
语言材料和人类词性
-> 产生候选解释

候选对象角色
-> 指明可能需要哪类业务对象

上下文消歧
-> 选择已有对象或形成创建请求

对象领域服务
-> 裁决并写入正式对象结构
```

正式词性决定首先进入哪个概念维度；它不直接决定具体概念、世界实例、节点类型、存储分区和是否可以发布。

## 3. 候选对象角色

候选对象角色可以表达概念维度、独立概念、世界存在实例、特征定义、特征实例、状态、动态、关系、因果、场景、需求、任务、方法和语言记录等已登记角色。

候选角色只存在于带来源语言位置、解析合同和上下文的值式材料中。只有系统确实存在相应对象领域服务时才能生成该角色；未知或证据不足保持未理解候选，不以默认角色补齐。

## 4. 词条和概念名称

词条只保存语言、规范化词面和稳定身份。概念名称只由 2210 概念—词条名称关系表达；从词条反查的概念集合按 7200 消歧。

人类词性经正式登记映射选择 2220 的概念维度，并在该维度缩小候选集合；不得修改词条、名称关系或概念本体。维度内部的具体概念、上下位、抽象签名和世界事实支持关系仍由正式概念结构与业务裁决成立。

## 5. 领域路由

消歧后需要查找或创建对象时，业务组合器把强类型请求提交给该对象唯一领域服务。语言服务和路由器不得代替目标领域创建对象，也不得直接写仓库。

原始语言材料继续进入语言记录；概念名称使用 2210；实例长期别名由实例对象领域定义；一次指代使用 1110；临时解析信号不发布为长期对象。

## 6. 标准流程

```text
接收语言记录
-> 形成词出现、词条和人类词性候选
-> 将外部词性映射到正式词性并选择概念维度
-> 按当前上下文形成候选对象角色
-> 在该维度通过名称关系或领域查询召回候选概念
-> L5 之外业务层完成消歧和准入
-> 调用目标领域服务查找或创建对象
-> 保存适用的名称关系、实例别名或一次指代
-> 完整读回
```

任何一步证据不足都停留在候选层，不得先创建对象再靠后续扫描修正。

## 7. 只读投影

语言路由只读投影至少保留语言记录位置、词条、词性候选、候选对象角色、候选对象组、来源解析合同和上下文摘要。投影不具有独立身份，可以清空重建，不得反写词条、名称关系或对象事实。

## 8. 禁止规则

1. 不得用未登记的外部词性直接决定维度、对象类型、场景或存储位置；正式词性只能选择其已登记概念维度。
2. 不得建立持久化语素入口或通用信息入口节点。
3. 不得用一个通用对应信息关系连接所有对象领域。
4. 不得把未理解材料按默认表直接落入存在、需求、任务或方法领域。
5. 不得用显示名称、文本长度、外部词性编码或索引首项完成路由。
6. 不得让路由候选替代目标对象领域准入和事实裁决。

## 9. 验证

验证至少覆盖多词性候选、上下文消歧、概念 / 实例分流、未理解保持候选、目标领域二次准入、路由投影清空重建和无语素入口持久结构。
