## 1. 定位

自我内部治理是唯一自我围绕需求组织任务、采用方法、取得真实结果并持续决定后继的ARCH-L4业务架构。它不建立新数据层、万能治理对象或第二事实仓。

内部治理代码本身不递归建立任务。需求识别、任务筹办、消息处理、状态推进、结果复核、self决议和完成结算编排是固定治理能力；只有已经由self确认的具体需求才建立任务。

## 2. 总闭环

```text
self读取当前事实和根需求
-> 产生或复核一个具体需求D
-> manager建立/复用唯一任务T及Vt
-> manager按状态筹办方法、条件、参数和结果获取方案
-> self执行前综合判断
-> worker执行W3-A动作
-> worker或后续观察执行W3-B结果获取
-> manager独立读回并形成执行结果与影响评估
-> T进入等待自我决议
-> self fresh读回并决定终态或后继
-> manager复核，由任务类发布状态
-> 正式完成的T由self编排唯一完成结算
```

任务没有任务轮次或筹办轮次。每次真实方法调用建立执行实例X；结果获取和影响评估绑定X。

## 3. 三个运行角色

| 角色 | 负责 | 禁止 |
| --- | --- | --- |
| self | 产生确认需求、选择治理目标、执行前综合判断、fresh结果复核、七类后继决议、完成结算编排 | 直接执行普通方法、裸写任务状态、用消息代替正式读回 |
| manager | 动态排序、建立/复用任务、形成工作包、独立读回、复核self决议、请求任务状态迁移 | 产生需求、代替self决定终态/后继、把队列当任务事实 |
| worker | 单次调用具名功能并返回结构化结果；W3-A和W3-B分别执行 | 长期持有等待、决定任务状态、重做结果未知的动作 |

线程是运行载体，不是业务事实来源。任务状态只在Vt当前特征中，需求目标只在需求树，现实当前值只在世界树相关业务类。

## 4. 业务对象和写入责任

| 对象 | 正式写入方 | 说明 |
| --- | --- | --- |
| 需求D和需求树 | 需求类 | self决定产生或确认，需求类建立、复用和判断当前满足 |
| 任务T、Vt、X、A和完成结算 | 任务类 | manager/self只编排公开入口 |
| 方法知识 | 方法类 | 任务反馈只提供材料，不直接改写方法 |
| 世界存在、特征、状态和动态 | 对应世界业务类 | 方法返回、预测和任务判断不能补造现实事实 |
| 安全值及安全限制 | 安全领域 | 普通任务结果、线程次数和消息数量不能直接改变安全值 |

基础数据集只提供节点、外部关系、字段关系和字段直接值。上层业务类用共享稳定编码组织对象，但不建立底层owner分区、事实代次或业务历史。

## 5. 需求先于任务

一个任务只解决一个需求，一个需求只表达一个状态改变；目标状态可以是复合状态。任务分解必须先形成子需求，不能建立任务树。

外部请求、观察材料、方法缺口、条件缺失和学习材料都不能直接创建D。self读取正式材料后，只有在目标独立、必要、父域合法且可最终判断时，才请求需求类建立或复用D。

## 6. 执行前结果途径硬门

任何普通、探索或试验动作在执行前都必须具有明确、合法、可实现的结果获取方案。方法定义“需要确认什么”，任务根据自我当前拥有的视觉、听觉、触觉、设备读回、网络反馈、他人陈述等渠道绑定“如何取得结果”。

结果可以延迟或异地取得；没有结果途径则零动作。动作后渠道失效时保持结果未知，可以恢复W3-B或更换冻结允许的备用渠道，但不得盲目重做W3-A。

## 7. 影响评估与self决议

影响评估说明本次执行发生的变化、偏差、副作用、材料缺失和当前需求满足材料，不决定下一步。manager只回流T、X、A和正式结果定位。

self fresh读取当前D、T、X、A、世界事实、资源和安全材料后，决定：完成、继续、重试、重新筹办、等待、失败或取消。manager只复核身份、当前状态和闭包，然后由任务类发布状态。

## 8. 完成、结算和重新启用

执行实例结束、影响评估形成、任务完成、任务完成结算、需求满足、需求结算和价值变化是不同事件。

- 只有正式完成任务可以按T结算一次；
- 失败或取消只处理真实结果、副作用和反馈，不做完成结算；
- 完成结算技术失败只恢复原结算，不重做方法；
- 已完成、失败或取消的T可以在self fresh确认同一长期需求再次需要治理后重新启用；
- 重新启用不撤销或重复既有完成结算。

## 9. 消息和恢复

消息按类型路由到不同处理函数，只携带不可变消息身份、原请求和必要业务定位。接收回执不等于业务完成，消费者必须current-only独立读回。

恢复以T、Vt状态、X、A、正式状态材料和完成结算为依据，不以线程生命周期、队列位置、日志或运行代次为依据。动作已发出而结果未知时只恢复W3-B；完成未结算时只补结算；已有结算时只读回确认。

## 10. 完成边界

本架构成立不等于完整生产闭环已经实现。至少还须分别证明：

- 一个具体方法的完整条件、参数、结果要求和本能函数绑定；
- 普通应用及网页交互端口装配；
- 外部观察能够形成正式状态并通知治理链；
- 延迟、多渠道和停止恢复；
- 方向、幅度、值域及副作用的完整影响评估；
- 组合方法和实际运行验收。
