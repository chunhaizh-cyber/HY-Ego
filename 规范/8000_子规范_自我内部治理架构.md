## 1. 定位与范围

自我内部治理是唯一自我围绕需求组织任务、利用方法改变目标状态、独立验证结果并持续调整自身活动的ARCH-L4业务架构。本规范固定模块、职责、事实归属及业务闭环，不建立新本体根、新数据层或统一万能治理类。8200展开详细逻辑操作、消息、分支、恢复和验证合同；8100固定线程边界。

内部治理不是所有运行函数都要先建立任务。产生确认需求、筹办、状态提交、消息消费、综合判断、结果收束和任务结算是内建治理能力；只有已经确认的具体需求才可成为新任务的目标。不能为这些内建函数递归建立审批、结算或自检任务。

## 2. 主链与两条反馈路径

```text
自我线程：读取当前事实 -> 产生并确认需求D -> 正式发布 / 精确复用D -> 发送任务承接意图
任务管理：经任务服务建立 / 复用T -> 筹办找方法和核验条件 -> 选择方法并按当前感知渠道形成结果获取方案 -> 冻结
自我线程：独立读回 -> 综合判断方法、结果获取方案及整体事实是否允许执行 -> 现实改变时发布唯一现实执行授权
任务管理：复核判断、冻结与硬门 -> 派发W3-A动作工作包；没有可实现结果获取方案则零动作
任务管理：动作完成后按条件等待并释放worker -> 事件 / 条件 / 地点或渠道就绪后派发W3-B结果获取工作包
任务管理：收束正式结果 -> 形成引用该结果的影响评估 -> 经任务服务推进到待self决议 -> 只把正式定位通知自我
自我线程：独立读回结果、影响评估和当前需求 -> 决定完成 / 继续 / 重试 / 重新筹办 / 等待 / 失败 / 取消
任务管理：复核self决议并经task owner发布对应状态；正式完成后self组织结算一次，失败 / 取消只记录处理
```

任务正式完成触发任务结算；需求当前满足另行判断，不能成为任务结算门禁或重复触发依据。方法完善是第二条治理反馈：任务实际条件、参数、采用配对、原预测、动作、独立观察和验证进入方法学习，method owner评审后更新知识，不能追改原任务的预测、冻结和历史结论。

## 3. 模块和唯一写入责任

| 模块 | 主要职责 | 正式事实归属 / 限制 |
| --- | --- | --- |
| 自我治理编排 | 根需求复核、产生确认后继需求、主需求选择、任务意图、执行前综合判断、结果处理、完成结算编排 | self决议归自我业务owner；调用他域服务不转移owner，不裸写任务状态 |
| 需求治理 | 普通D、树 / 列表、当前满足、活动资格、权重和独立需求结算 | 需求owner；不替代self产生或确认 |
| 任务管理编排 | 消费D意图、承接任务、按Vt派发筹办 / W3-A动作 / W3-B结果获取、独立读回、推进状态、通知self | manager只编排，任务记录归task owner；不自行产生需求或触发任务结算 |
| 任务业务应用与记录 | 目标读回、找方法 / 查条件、效果和代价选择、结果获取方案、路径与实例、冻结、影响评估、结果、状态及完成结算 | 应用面作业务裁决，记录面机械校验发布；Vt为唯一任务状态宿主 |
| 方法治理与执行 | 方法头和C/R配对树、Vm参数规格、函数登记、冻结实参调用、学习细分 | method owner独占方法知识；任务运行参数在Vt下，不回写共享Vm |
| 世界认知与事实服务 | 当前采用、准确F内容、状态、动态、场景和概念化因果 | 各自正式owner；消息、预测及任务结论不能补造世界事实 |
| 安全治理与调度投影 | 合法安全事件处理、分层维护、控制态和倍率、硬否决 | 6100 / 6140 / 6150各自负责；不提供第二正向现实授权 |
| 工程运行和支持 | 启停、队列、重投、资源管理、只读显示与日志 | 只保证交接和可恢复性，不构成业务事实或第二治理账 |

self线程、manager线程和工作线程是运行载体，不是存储层。业务应用通过具名公开服务取得数据，记录面只组合合法数据能力；跨owner不直取仓库、SQL、内部事务或可变对象。ARCH与DATA分层读取0050、4030，不按类名前缀推导层号。

管理性、上级或汇总任务可以通过正式子目标、轮次调用、等待、返回和fresh重判推进，不要求绑定单步业务方法，不建立永久任务父子树。只有真正进入方法执行的原子活动才必须具备完整方法 / 实例 / 冻结及执行前self综合判断；内建治理推进不因此伪造方法或递归任务。管理任务完成仍须正式目标与验证成立，按同一T结算规则处理。

## 4. 数据组织和定位

治理使用稳定身份和正式关系定位，不以线程内对象地址、消息序号或名称作为事实身份。

| 数据 | 组织方式 | 不得替代的边界 |
| --- | --- | --- |
| 需求D | 所属存在、固定目标；需求树组织目标分解，列表按精确同目标聚合 | 列表不是任务目标或结果容量；D不因满足被删除 |
| 任务T / Vt | T显式引用已承接D；Vt保存任务状态和治理信息，轮次 / 路径 / 实例 / 冻结 / 结果分别关联 | 不建立永久任务父子树，不进入世界树；列表成员不自动成为T来源 |
| 方法头 / Vm / C/R | 方法头供FT查找，Vm保存自身状态和参数规格，C与R成对组成范围 / 精度树 | C/R不是任务步骤树；实参属于任务专属实例 |
| 世界事实 | 存在当前采用准确F；状态与动态在发生场景组织，因果保存概念化规律 | 历史状态不代替当前值，预测不成为已经发生的状态 |
| 任务完成结算 | task owner保存按T唯一、引用正式完成来源与结果闭包的治理结果 | 不是逐轮结果收束，不是需求、安全、价值或调用槽结算 |

运行期队列、当前需求视图、方法候选投影和调度缓存均可从正式来源恢复，不新增持久候选仓、样本仓、消息账或第二当前状态。必要工程幂等、发布和恢复材料保留在所属服务内部。

## 5. 需求先于任务

当前self固有安全根与服务根按8120冷启动发布并读回，根身份不由缺口临时生成。后继需求只能由self依据父任务正式材料产生并确认；task owner记录确认，需求owner独立读回后发布或在发布前精确复用。外部请求、观察、自检、条件缺失和学习材料都不能直接创建D。

manager收到一个具体D后，由任务服务按D所属列表项L查找0..1同目标当前T：无则建立，有则验证目标相同后显式承接该D。不合并已发布需求，不自动承接L其它成员。任务完成后需求可能继续存在；需求再出现缺口时重新依据当前事实治理，不重开已经完成的T。

## 6. 执行前的自我综合判断

任务域负责完整召回、条件核验、效果 / 代价计算、按当前感知渠道形成结果获取方案和选择冻结；self在冻结后、真实派发前从当前整体事实判断是否真正执行。结果获取方案可以包含延迟、异地和多渠道步骤，但必须在动作前明确、可实现并完成绑定；普通、探索和试验任务均不得无方案执行。任何正式任务进入方法执行都需该判断，执行内部方法或无副作用观察也不能由manager自行跳过；仅通过子目标和调用治理推进的管理任务不伪造方法冻结。

综合判断是内部治理决策，不新增第二“任务授权”。仅现实改变需要一份绑定本冻结的正式自我现实执行授权；纯内部 / 纯观察不建立该事实。安全硬否决、生存控制态、技术许可和保护资源规则仍独立生效，self不能以收益抵销硬门。

筹办、结算等内建治理操作不是正式方法任务，不递归走此请求。暂缓、拒绝、重判、技术未知和任务失败分开；消息成功投递不证明判断已经形成或任务已经执行。

## 7. 任务状态与结果的分账

| 事实 / 状态 | 必须处理 | 是否任务结算 |
| --- | --- | --- |
| 已正式完成 | manager通知；self独立读回完成来源并调用task owner | 同一T一次，与需求当前满足无关 |
| 任务失败 | 保存真实结果、验证、停止、副作用和合法后继材料 | 不做 |
| 任务取消 | 停止 / 不可停止情况读回，保存实际已发生部分和处理结果 | 不做 |
| 轮次已收束待self后继决议 | self独立读回正式结果、影响评估和当前需求，决定完成、继续、重试、重新筹办、等待、失败或取消；manager复核后由task owner发布对应状态 | 只有正式完成后才进入同一T一次结算 |
| 等待 / 结果未知 / 发布未知 | 保持真实状态，按原请求恢复，不能自证完成 | 不做 |

动作已发出后结果渠道失效属于“动作已发出、结果未知”：不得判成功、完成任务、结算需求或盲目重做动作；优先恢复或更换结果获取途径。影响评估只描述预计 / 实际、方向 / 幅度、缺失 / 计划外变化、不可比 / 冲突及目标当前满足，不替self决策。manager结果回流只提供正式定位，self必须独立读回并fresh复核当前需求。

任务完成不等于函数返回成功，也不等于“线程结束”。task owner发布完成后，不等待结算成功再承认完成；结算技术失败只恢复原结算请求，不能回退并重新执行方法。完成任务不再开启新轮次。

调用槽返回、需求当前满足和独立结算、安全事件 / 损失处理、方法学习均不能因任务失败不结算而被一起取消。失败样本必须满足正式执行、独立观察及验证来源合同后才能学习，不以“失败”状态本身证明方法无效。

## 8. 安全、价值、学习和现实事实

1. 6100主动安全结算、6140分层安全维护和6150调度投影互不替代。6100当前来源规则版本1的生产方法完整集合为空，本架构不增加来源方法或自动价值写入。
2. 生存控制态A=0仅保留正式恢复 / 重建与停止；A=1仅开放具名治理材料承接、时间、安全事实、重新评估和停止；A>1才进入普通任务派发判断。任务完成通知、结果恢复与必要收口属于既有治理 / 停止处理，不可借此执行新的普通动作。
3. 服务根只保留普通需求坐标，不恢复服务合同、账户、配额、预支、时间衰减或服务值自动写入。
4. 状态 / 动态 / 因果用于认知；治理事实及工程材料不能复制为第四类认知证据。二次特征比较按正式算法调用，C038未决持久实例范围不因治理用途扩大。
5. 方法学习独立评审横向方向分支与竖向精度细分；任务结果不自动拆分配对、修改可靠性或完成方法晋级。

## 9. 恢复与完整性

消息只传不可变定位和受约束意图；接收方必须经owner独立读回后推进。发布前失败零业务变化，发布未知用原请求收敛，重投不重做动作。完成状态和结算记录共同提供恢复定位，不另造“是否已处理”业务账。

恢复要分别判断任务是否完成、该T是否已结算、动作是否停止、哪一请求发布未知。完成且未结算只补结算；已经结算只读回；失败 / 取消只恢复结果处理；动作未知不得恢复为可执行。跨owner不宣称整体原子。

## 10. 子规范路由与完成边界

8200规定详细逻辑算法与操作载荷；5260负责任务目标、状态、结果及完成结算；5170负责需求；5350 / 5360负责方法知识与函数；8100负责线程；8210负责两路线验证；8300 / 8310负责闭环证据；8120保留唯一启动顺序。

本规范不把代码中的薄记录、参数绑定或方向计算宣布为治理闭环。逻辑合同可供设计与逐项实现映射；C++模块、精确DTO、稳定编码、提供者装配及同次旧消费者迁移必须在对应实施合同中明确，不得由旧代码名或退役设计补造。本次不修改或激活旧计划，不恢复退役的整体关系稿。
