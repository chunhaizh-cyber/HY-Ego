# 1150 根规范 场景节点

编号：1150
日期：20261105
版本：v3.7
状态：正式根规范

直接上级规范：0050。

直接依赖规范：1140、1160、1170。

相关边界规范：1110、2220、4015、4200、4202、6120、6220、6300。

## 1. 权威边界

本规范是全局根、世界根、场景层级、成员、坐标、边界、状态和动态组织的根合同。

场景是世界中的空间或组织节点，也是一个实际存在：场景节点直接具有概念引用和零到多个实例特征。场景作为存在建立专属存在概念，不另设场景概念类别。

## 2. 全局根与世界根

1. 程序持有唯一的物理全局根场景，由代码全局变量实现，只用于挂接各世界根。全局根不是逻辑场景，不具有成员存在、自身特征、状态、动态和专属存在概念。
2. 现实世界、外设世界、自然语言世界、模拟世界、内部治理世界，以及今后新增的世界类型，各有一个世界根场景，直接挂在全局根下。外设世界承载外设类直接写入的外设场景事实，写入数据须符合内部世界的数据格式和要求，由代码保证（6120）。外设世界之外的世界称内部世界。
3. 各世界在逻辑上相互独立：场景范围查询、成员归属、存在迁移和一致性核验都以世界根为上界，不越过世界根；世界之间只通过强类型引用关联。跨世界只禁止场景父子关系、存在组成关系和场景成员关系；动作动态对目标的引用、“导致变化”关联等强类型引用可以在内部世界之间跨世界。内部世界不得直接引用外设世界的信息节点；需要外设信息时，由方法读取后复制一份作为内部世界的信息。外设节点的稳定编码可以作为标识数值复制进内部世界，只是普通值，不构成引用、保护或跨世界关系；按该值读取外设时由外设类核对，节点可能已不存在。
4. 普通场景恰有一个直接父场景，一个场景可以有多个直接子场景；场景层级无环，世界根不得迁移。场景层级只组织场景，不组织普通存在。

## 3. 场景用语

下列四种对象由本规范唯一定义，其它规范只引用，禁止混称裸“交互场景”：

| 用语 | 含义 |
| --- | --- |
| 现实交互场景 | 现实世界中自我与交互者进行交互的场景；外设交互场景建立后由自我线程自动建立为自我所在场景的子场景，建立时只含交互窗口的内部副本，交互者副本在外设交互者出现时由自我线程建立于其中，自我经通用本能“进入场景”迁入（6220）；外设信息只按复制进入，不引用外设节点 |
| 外设交互场景 | 外设世界中由外设类直接写入事实的交互场景，例如电脑网页对话；用户打开交互界面时由外设类自动建立并通知自我线程；交互窗口与交互者是其中的存在，其中没有自我；具有自己的场景特征、成员存在及其特征，不仅是消息通道 |
| 自然语言场景 | 自然语言世界中承载语言主张、描述、假设、请求与指代实例的场景 |
| 调用期交互上下文 | 一次交互调用中的说话者、受话者等角色取值，不是场景节点 |

自我与交互对象通过交互窗口传递信息。窗口、渠道或会话不自动等于对端存在；网页打开或收到消息不能直接证明人类身份。交互对象与连接语义由6120展开。

## 4. 场景信息

| 信息 | 基数 | 含义 |
| --- | --- | --- |
| 父场景 | 世界根为全局根、普通场景恰一 | 场景层级直接上级 |
| 概念引用 | 恰一 | 场景作为存在的概念引用 |
| 实例特征 | 零到多 | 场景自身特征 |
| 直接成员存在 | 零到多 | 直接归属该场景的普通存在 |
| 边界存在 | 零到多 | 参与边界定义的存在引用 |
| 直接子场景 | 零到多 | 场景层级直接下级 |
| 状态列表 | 零到多 | 发生于该场景的状态 |
| 动态列表 | 零到多 | 发生于该场景的动态 |

成员、边界、状态和动态只保存节点引用，不复制被引用对象内容。

## 5. 成员、迁移与挂接

1. 普通存在恰有一个直接所属场景，通过场景owner建立并写入成员关系。
2. 存在可以在同一世界内迁移场景，已有状态或动态不阻止迁移，稳定编码不变。迁移在一次组合发布中按顺序进行：先删除或修改该存在在原场景的成员关系等关系信息，再把绝对坐标置空并将这次变化记入原场景状态列表，然后建立新场景成员关系并写入坐标，状态记入新场景（第6节）。
3. 状态和动态不迁移场景，始终保留在挂接时的发生场景。挂接时核验其主体属于该场景范围；之后存在迁移不影响已挂接的状态和动态。
4. 场景范围存在是当前场景及全部下级场景直接成员的并集，不越过世界根，不包含场景节点本身。

## 6. 坐标与进出

1. 空间坐标是原始特征值，真实值由深度相机等外设取得。
2. 空间世界（现实世界、模拟世界）中每个存在的绝对坐标形成实例特征，坐标变化时生成状态。
3. 场景的坐标范围由其边界确定。存在的绝对坐标落在当前场景范围之外即为“离开”该场景：坐标置空记入原场景；在某场景范围内首次观察到即为“进入”该场景，也称被该场景“发现”：坐标写入记入新场景。离开与进入是两个场景各自记录的未融合事实。场景坐标范围不能确定，或在预期场景未观察到该存在时，其位置按不明处理，逐级迁往上位场景（1140，细则见6260）。
4. 相对坐标不形成特征，也不是二次特征，只是自我使用时计算的一张表，不写入数据、不生成状态。
5. 自然语言世界、内部治理世界没有空间坐标，成员归属由对应owner明确写入；需求、任务、方法、词条、语言材料范围、指代实例、代词概念等信息存在归属这两个世界的场景（0050第1.4节），其实例特征变化生成的状态挂入所属场景。

坐标换算、相对坐标表、边界几何与闭合计算由6220及6300系列规定。

## 7. 状态列表

状态列表持有并存储发生于该场景的状态，场景是状态的组织者和生命周期管理者。挂入状态须满足被描述存在属于目标场景范围，或被描述存在就是该场景；同一状态不得挂入多个场景。状态按1160的定期、定量规则删除；被因果概念或动态概念采纳为代表实例、被仍存在的动态引用，或仍在使用中的状态保留。

## 8. 动态列表

1. 每个场景只记录发生在本场景内的动态；同一动态只挂入一个场景。
2. 原子/复合动态的主题和全部状态须在挂接时属于该场景；动作动态挂在执行主体所在场景，只校验执行主体属于该场景，目标可以在其它场景或其它世界，以强类型引用记录。
3. 跨场景的变化记为各自场景的未融合动态，例如“杯子离开房间A”记在A、“杯子进入房间B”记在B；“杯子从A拿到B”这样的融合动态在需要时由其共同上位场景形成：该场景可以引用其场景范围内各子场景的状态和动态，原状态与动态不搬迁、不复制、不重复挂接；“属于该场景”指场景范围包含，而非必须直接存放于该场景列表。限于同一世界。
4. 动态列表是引用集合，不证明连续动态链或时间序列；时间顺序由状态强时间重建。

## 9. 一致性不变量

1. 场景具有场景身份和存在身份，恰有一个概念引用。
2. 世界根直接挂在全局根下；普通场景恰一父场景，场景层级无环且不越过世界根。
3. 普通存在至多出现在一个直接成员关系中。
4. 边界、状态和动态列表保存有效节点引用，不复制内容。
5. 状态、动态与挂接场景的一致性在挂接时成立。
6. 相对坐标不作为持久特征、状态或历史保存。

## 10. 生命周期

只有非世界根的空场景允许删除；“空”至少要求没有直接子场景、直接成员存在、状态和动态。场景仍被其它场景的边界引用时拒绝删除。场景自身特征及概念随删除清理。全局根与世界根不可删除。一次场景业务变化整体发布，不得把已成立的存在、特征或状态事实回滚为零写入。
