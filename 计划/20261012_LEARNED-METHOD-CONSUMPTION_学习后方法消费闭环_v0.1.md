## 1. 用户目标与职责边界

学习生成的方法条件—结果知识必须被后续任务筹办、条件子需求、方向判定、执行冻结和评估实际消费，不能因为采用精确I64直接值域而统一拒绝。已有任务后续可以纳入新增可选方法知识，不能因已绑定实例就永久停用新知识，也不能改写已经采用或执行的实例和原预测。

学习结束由self可靠交接给manager；manager定位相关任务，经self fresh复核同一需求仍需治理后重新筹办。不把学习通知解释为执行许可，不直接执行，不因学习而重开终结任务。学习算法本身不在本目标修改范围。

本次改变的是内部任务筹办与执行材料的消费、任务虚拟存在治理状态及线程交接，不新增改变现实特征的本能方法，不修改服务值/安全值结算。现实动作仍经原结果途径、安全、授权及W3-A/W3-B链，不因打通值域消费而放松硬门。

正式边界读取[3300方法](../规范/3300_根规范_方法.md)、[5370方法学习](../规范/5370_子规范_方法学习与知识形成.md)、[3200任务](../规范/3200_根规范_任务.md)、[5260任务治理](../规范/5260_子规范_任务治理详细合同.md)及3100、5350、8100/8200。方法预测不准的完善属于学习，真实结果满足目标由任务判定；两者不得重新耦合为同一成功标志。

## 3. 冻结实施合同

### 3.1 领域直接值域消费（root已裁决）

`新任务预计特征变化`尾部追加`std::optional<特征概念I64闭区间> 预期精确数值域`；`新任务禁止结果目标`尾部追加同型`禁止精确数值域`。各自持久字段只保存一个`vector<int64_t>{下界,上界}`，复用方法精确域存储模式；未出现字段表示无直接域，兼容旧材料。直接域与对应概念域严格互斥，区间有序，FT必须为I64且单位一致。

`新冲突需求项`尾部同样追加optional精确I64预期域证据，并贯穿冲突判断、根影响及父子方向；不能只在X存域而在执行前冲突检查中丢弃。无声明方向且I64结果域全部严格高于/低于当前准确值时，可判为增加/减少；单点等于当前值是不变；域跨越当前值则方向不明确，不编造趋势或线性知识。

任务owner在初始化字段、定义校验、预计/禁止写入、读回、回滚、结果方案冻结、执行开始重核、结果获取及评估中完整支持新字段。错误长度、值类型错误、重复字段、上下界倒置、非I64 FT、双域同时存在均为结构化非成功，不能当成无域。失败保留既有X/A与冻结内容，不能回写学习所得知识。

准确值与预计/禁止域比较复用`特征服务.比较特征值域`，输入为同次实际准确I64值以及直接域或概念域；父子方向、执行方向与冲突判断使用相同值式解析，不丢掉直接域。对象、FT、单位、方法结果对应和原方向参照仍完整核验。方向目标继续使用同次动作前后值，不能用方法预测替代；目标满足与预测命中分别保留。未知、不可比较和资源/结构失败不能判为通过。

条件子需求在task形成提议时，经概念owner建立或复用同FT根、同单位、同规则、精确等价区间的正式概念，并完整读回确认。继续使用原`新任务条件子需求项`必填概念字段，self仍按原入口确认并建立D，不改变需求公开合同，也不允许task建立D。合法概念已经形成而后续提议失败时可以保留概念；提议失败零部分数组，不将概念成功当作D已经存在。来源快照继续保存选定配对/参数并fresh核验，防止以旧条件建D。

九处入口保留方法闭包完整性与资源检查，移除合法精确I64域本身的拒绝；不以此扩大非I64直接域、未知联合耦合、状态/动态条件或复杂动作支持。

### 3.2 已有任务可选方法增量（root已裁决）

采用COW：完整复制旧实例图，在新图纳入新知识，原图不写不删；任务安全采用后只切换当前实例根，已有X及其方法/配对/原预测继续引用旧身份。不是在旧实例上修改已用配对，也不是抛弃旧候选后用最新抽象图覆盖。

`新_方法公共类型.h`的`新方法条件结果信息`末尾追加`std::optional<稳定编码> 来源配对节点`。抽象配对必须为空；新复制实例配对保存原抽象配对P身份；实例再复制必须传递原P，不能改为旧cloneP。私有schema新增`配对来源字段`并登记现有架构编码，读回核验其属于来源抽象M且唯一有效；复制字段白名单将其作为外部来源保留。老实例缺字段允许只读，增量时执行后述严格对齐，不回写旧图。

`领域/方法问题归档.模拟世界.cpp`保留`成员(新方法条件结果信息)`旧7字段布局，来源只作为问题头尾部扩展：来源空时新编码与旧格式1相同；非空追加3个U64字`0x4D50534F55524345ULL`（MPSOURCE）、扩展版本1、来源配对稳定码。解码先读取旧头全部字段，恰EOF则来源空；否则必须只剩3字、tag/version匹配且来源编码有效，读后必须EOF。未知tag/version、残缺或多余字一律结构拒绝。外层格式1及旧字段语义不变，旧资料仍可读回、新来源完整往返；不承诺旧二进制可读新扩展，不改学习算法或其它记录布局。

增量和去重精确规则：

1. 旧图`sourceM→cloneM`唯一，共同被调用方法只计一次；每M的`sourceP→cloneP`唯一。新图保持这些唯一映射，同sourceM不能复制出第二个候选而制造重复配对选择。
2. 源P已导入时仍核对完整R、线性关系及C非收窄字段，不仅比ID。命中次数不参与知识增量判断。头、参数规格、作用域、实现方式或登记函数变化返回`来源无法对齐`，不原地重释旧实例。
3. 旧无来源标记P必须与同源抽象M中的一个且仅一个P严格语义匹配：R完整相同、线性关系等价；无linear时C完整相同；有linear时只允许既有条件覆盖函数修改过的两种域表示字段不同，旧C域必须包含于原条件域，恢复源域表示后其它C字段必须相同。零/多个匹配拒绝，不按位置、数量、名称猜测。标记只补到新clone，旧图不写。
4. 同源本能M发现未导入P，只向新cloneM追加其完整C/R/线性关系/当前命中值并记录原P；保留旧clone原C收窄、旧R和转移。源P同ID改义返回`来源无法对齐`。
5. 组合M原样闭包可以复制；已有组合M配对、步骤、调用或结果转移发生变化时本叶不支持，返回`来源无法对齐`，不自动扩展组合知识迁移。
6. 新来源M按既有完整闭包能力导入，引用已经覆盖的sourceM时复用新图唯一clone；用sourceR→cloneR映射重写转移。某M原先仅为被调用方法而本次正式候选明确包含它时，为同一新clone新增候选入口，这也算增量；不新建第二clone。不在没有正式候选输入时把被调用方法误升为主方法。
7. 旧图与候选知识未产生合法新增时精确重复，不建立新图；学习通知重复及命中数变化不能无限复制。

任务公开`实例化候选方法(T)`保持签名：没有旧根走现有首次复制；有旧根读取完整当前候选后调用增补。任务持task锁进入方法owner，方法锁内完整生成/校验新图再调用采用回调。回调只能fresh核对T当前根等于预期旧根、处允许筹办态且无活动执行、新根未被其它T占用，随后通过task私有CAS辅助替换唯一`任务方法实例字段`。不放宽原公开`绑定方法实例`拒绝替换合同。

回调读回为新根才返回已采用；明确仍为旧根且未生效才返回未采用；其它结果为采用状态不明。方法owner只清理本批确定未采用图，清理失败返回结构不一致并保留已知新根定位；回调异常/采用不明返回发布结果未知及新root，保留新旧图，不伪装资源零写。回调不执行、学习或选C，不清旧X/A。任务对未知发布不重试为另一次无来源复制，而保留定位并返回具名结构非成功。

#### 3.3.1 学习结束可靠交接

`新_任务管理线程类.h/.cpp`将原bool提交改为具名结果，调用点同步迁移，不保留bool旁路：

```cpp
enum class 新方法学习接收状态 : std::uint8_t {
    已接收 = 1, 精确重复, 尚未启动, 已停止接收,
    入口拒绝, 身份冲突, 资源失败, 内部错误
};
新方法学习接收状态 提交方法学习结束(
    const 新学习结束通知& 结果, std::uint64_t 交接编号) noexcept;
```

self首次消费学习future时用既有`取得自动消息编号()`分配一次交接编号，连同原结束通知保留。0/溢出硬拒并具名报告，不换键重试。manager按编号保存通知来源方法，同ID同M精确重复、同ID异M身份冲突；只有接收存储完成才返回已接收。编号是进程内交接身份，不是方法版本、事实代次、业务节点或学习次数。

self在途学习项分为`等待结果/待交接manager/待确认worker`，保存原future、一次分配的编号、待交接通知及可交接时点。manager已接收/精确重复后锁存成功，只确认原worker，不再提交manager；worker已完成/无变化才释放在途项。尚未启动/资源失败保留原材料按既有资源间隔延后；停止或永久拒绝具名停止/异常，保留未交接诊断，不忙循环。确认失败不反向重交manager，不把未确认当已完成；依原worker确认状态区分可恢复资源与身份/停止硬失败。

ready future仅在等待结果阶段参与等待谓词；待交接截止并入self最早后台推进时点，避免ready future持续唤醒。停止仍沿原worker停止/join回收，并记录未交接或未确认状态，不承诺跨进程恢复。

manager对不同交接编号独立保留，哪怕同M也不能当精确重复。事件按编号串行推进，当前事件各T全部终结后再处理下一事件；事件内逐T推进，同T占用唯一。编号去重缓存保留至manager实例销毁，停止不伪造处理完成。

#### 3.3.3 批次、fresh复核及安全重筹办

manager收到学习通知后fresh读取抽象本能方法，再调用task的`查询受方法学习影响任务(M)`取得完整T集合；先完整构造批次再发布，不在资源失败时派发部分前缀。资源失败保留原事件延后，结构失败具名结束受影响事件，不清除其它阻塞。空集合即消费结束，不能把“等待方法实例消费”常置true。

各T阶段为`等待活动结束/待反馈self/等待self决议/准备再筹办/已终结`。发布定位后编号及内容不变，材料变化须终结旧定位后重新fresh形成新定位，不能原地换字段。已有W1/W2正在工作时保留待处理T，等真实完成后再读取T/D/候选/实例；此时若已进入待执行及之后或终态，则终结该项，不降级或重开。

为待学习复核T建立独立占用集合，W1/W2/W3普通派发均避开；不借用或整体清空原阻塞集合。旧W2反馈/裁决也必须拒绝已被学习占用或定位已失效的输入，不能使用旧许可派发W3。学习占用不取消已开始动作，不改结果获取/恢复工作。

manager反馈self：已接收/精确重复后等待同一决议；邮箱满、尚未启动、资源失败按间隔重试原定位；未配置、停止、身份冲突或其它硬拒绝具名终结，不忙循环。self读取manager记录确认同定位，再fresh获取T/D，核对T→D、状态、候选、实例均一致；只对`新需求活动状态::活动`考虑允许，等待/已满足/失活均返回需求非活动，不修改D活动状态。

| self当前满足材料 | 决议 |
| --- | --- |
| 值目标需增加、需减少、未满足但无有向差值 | 允许重新筹办，不代表执行 |
| 方向目标需要执行前后比较 | 允许重新筹办，不证明满足 |
| 已满足 | 当前已满足，不筹办 |
| 目标特征尚未形成、当前值不存在 | 等待材料 |
| 定位已不存在/字段已变化 | 定位已变化，零任务写入 |
| 结构、引用、入口、比较不适用等非法 | 需核查，不伪造未满足 |
| 资源失败 | 原消息/原定位保留并按间隔重试，不提前形成业务决议 |

manager收决议先核完整定位，已接纳同义决议精确重复、异义拒绝；读取不到固定大小定位表示已终结/过期，不伪装资源失败。接纳只锁存，不在消息回调里写任务。主循环在manager锁外调用`准备学习后重新筹办(T,M)`，调用前再次核T/D/候选/实例/状态及无线程工作/冻结占用；变化则终结旧定位，仍相关者重新fresh发定位。资源失败保留同项及已接纳决议，不重复self业务处理；状态变化、终态或不相关按过期零写结束；结构错误具名停止该项。

只有准备成功且独立读回T为待查找方法，才清该T旧最近筹办结果、待筹办反馈、旧self筹办裁决和可证明来源于被替代W1/W2的阻塞，再释放学习占用进入原W1管线。由于现有阻塞set无原因，本叶补私有筹办来源阻塞标记/分类，只清当前可追溯的W1/W2技术失败、完整无候选或条件结果暂不可执行阻塞；W3、结果读取、工程停止、终态、服务结算阻塞绝不清。不清X、执行结果、恢复执行或结算定位。完成/等待/过期时释放本学习项占用，不改变其它保护。

`等待方法实例消费`由尚未完成的交接/复核/准备项派生，只是进程内进度，不是知识有效性。停止取消未派发复核、完成原promise并回收局部进度，不取消已接纳owner写入或重复动作；真实依赖事件后可形成新复核，不靠定时重试等待材料变成功。
