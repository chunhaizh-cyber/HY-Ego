## 1. 唯一代码结果

在一个连续代码计划中实现完整 L4 自我内部治理闭环：任务初始化和首态、按 ARCH-L2 当前阶段治理、执行前一份自我授权与安全硬否决、实际结果到逐需求核算和任务轮次收束、自我后继四分支、新任务轮次，以及旧任务私有状态 / Stage C / 自动重筹办链退役。

叶1—叶6是本计划内部施工顺序，不形成六份计划、六次提交、六次测试或六次验收。完整 L4 代码候选形成并接入真实 ARCH-L2 提供者后，才统一编译、测试和连续两轮验收。

## 3. 待实现目标 ABI 施工规则

L4 先建立纯抽象`任务阶段结构消费端口`和详细设计冻结的请求 / 结果 DTO。连续实现只依赖该端口，不定义默认实现、模拟成功或第二结构存储。

真实提供者接入时，新增或完成一个无状态机械适配器：

```text
建立无动态首态
发布阶段迁移
读取当前阶段
读取历史阶段
```

适配器只能组合公开 ARCH-L2 服务和 DTO，不取得 L1 仓、写端口、候选、锁、事务凭证或 private seam。实际公开名字不同但语义完全等价时只做逐字段机械映射；任何所有权、单 G1、旧状态保留、当前 / 历史读取或故障收敛差异必须具名 DRIFT。

## 4. 连续实施顺序

### 4.1 叶1：任务初始化、R1、首态和第一动态

1. 清理纳入的六个旧 WIP：保留 T→D/T→E、R1、六阶段幂等、P1/A1候选；删除旧融合兼容桥、历史`初次请求版本待迁移`占位和对旧状态结果形状的字段。
2. 在`任务阶段治理.数据.h`冻结阶段值、目标端口请求 / 结果及当前 / 历史读取 DTO；在端口模块只声明纯抽象接口。
3. 重写`需求初次筹办准备提供者`：先读完整原请求记录；按 E、T/R1、TASKSTAG定义、E实例、无动态首态、P1/A1、第一迁移顺序逐段收敛。
4. 固定`TASKSTAG`定义键与六阶段请求键分账；删除隐藏的第七阶段键和任何时间 / 代次 / 哈希派生键。
5. 首态要求状态事实 + 状态自有关系 + 当前选择同 G1；第一迁移要求新状态 / 新选择 / 动态 / 旧选择退出同最终 G1；全部经公开入口独立读回。
6. 普通应用先保存 L4 初次筹办 provider的目标端口依赖位置，但真实适配器未接入时不装配 stub、不声明可运行。

叶1末只运行第 7 节机械检查，不构建、不测试、不形成“首叶完成”声明。

### 4.2 叶2：筹办治理和 Stage C 退役

1. 将任务治理函数种类升级为详细设计的 v2 全集，增加通用动作调用 v2、执行轮次、冻结及读回合同。
2. 重构正式选择和冻结，只保存条件、输入、参数、限制、验证 / 归因及有序动作作用范围。
3. 删除`L2任务授权安全复判材料`、授权安全来源接口、`授权安全等待`、冻结序列化字段和普通应用 Stage C 装配。
4. 建立`任务主阶段治理提供者`，每次从 T→E和目标端口独立读取当前阶段，再选择筹办 provider；线程槽不得保存阶段副本。
5. 同一未收束 Rn 的等待解除 / 冻结失效统一建立新 Pn；执行已开始或正式结果已形成后禁止该分支。
6. 把筹办闭合为等待、子目标承接、学习需求、方法补齐、目标已完成或可执行冻结；不得恢复无结构“无法解决”。

叶2末只运行第 7 节机械检查。

### 4.3 叶3：执行前授权、门控和执行到结算

1. 新建`L2自我治理结构服务`，登记自我授权、撤回 / 消费和后继决议结构；结构服务不作业务裁决。
2. 在方法数据 / 服务中为动作入口增加强类型有序作用范围；实现`实例方法执行提供者`，以稳定动作键映射普通应用登记的唯一动作端口，并公开只读技术许可与真实执行两入口。
3. 只在`领域/自我治理/自我现实执行授权.*`实现唯一`自我现实执行授权提供者`；`L2自我治理结构服务`是唯一授权 / 收口事实 owner。完整绑定自我、T/R/P/E、冻结身份 / 版本、实例 / 方法内容、逐项不筛选不重排的完整有序冻结动作范围、截止、规则和有效期；按详细设计第6.3节实现事实、读取、收口、结果及状态×载荷矩阵。内部治理目录不得建立第二套授权文件或 owner。
4. 实现只读`任务现实执行硬否决提供者`。按详细设计第6.4节实现请求、证据结果和唯一`复核任务现实执行硬否决`入口；它只返回未命中 / 命中 / 缺材料 / 漂移 / 资源 / 内部错误和证据，不发布正向授权。
5. 内部治理 / 纯观察零授权；动作组含任一现实改变时，整个冻结在任何步骤开始前取得一份授权。拒绝 / 等待不写任务失败。
6. 实现派发门控固定顺序：当前阶段和冻结 -> 6170控制态 -> 配额 / 6150倍率 -> 技术许可 -> 授权当前性 -> 只读安全硬否决 -> 派发前再次复核。
7. 只有门控全部成立才发布执行进入动作、迁移为`执行动作中`并确认执行请求队列；硬否决优先于授权。
8. 按详细设计第6.4节冻结的稳定动作端口、技术许可请求 / 结果、实例执行请求 / 结果、派发冻结、强类型执行请求和待验证材料原样实现；任务工作线程成为强类型执行请求唯一消费者，重新读回冻结 / 门控并调用实例方法执行 provider。动作返回只作待验证材料，随后执行实际世界回读和归因；退役外部预形成工作结果生产入口。
9. 更新执行请求、工作结果、结果回执和上行桥，使其携带 R/P/E、冻结、授权和动作运行定位；上行桥仍只发布实际结果和独立读回。
10. 实际结果形成后迁移为`执行结果待结算`，再以具名结算进入动作迁移为`任务轮次结算中`。

叶3末只运行第 7 节机械检查。

### 4.4 叶4：结果消费、逐需求核算和轮次收束

1. 新建`L2任务结果消费结构服务`和`L2需求结算结构服务`，注册独立 owner；按详细设计第6.5—6.6节原样实现强类型身份、请求、读取、结果、提交见证与状态×载荷矩阵。由`任务结果消费分配与轮次结算`provider统一编排，但不把结果关系、分配或需求核算写入任务线程槽。
2. 冻结本轮合格 T→D 关系集合及共同截止，发布可共用 / 争用裁决。
3. 可共用直接逐成员核算；争用先读取正式优先级，按稳定顺序逐项分配 / 扣减，再对获配或未获配成员分别核算。
4. 每个核算入口只读取一个 D 的当前结算前事实、目标合同、实际状态、消费裁决和适用分配，发布自己的满足 / 未满足 / 未获分配 / 材料不足 / 不可比较事实。
5. task owner新增轮次结算事实 / 读取入口；结算 provider逐项验证所有当前合格成员恰有一个核算结果及适用价值 / 学习后继引用。任务结算写和收束阶段迁移分别重放、分别独立读回；只有该次 ARCH-L2阶段迁移自身是一个G1。
6. 只有运行停止、冻结和授权消费已收口、全部结算引用正式读回，才发布任务轮次结算；随后发布收束动作和`轮次已收束待自我决议`迁移。
7. 目标未达成仅进入`任务轮次结论`，不形成重筹办意图或工作包。

叶4末只运行第 7 节机械检查。

### 4.5 叶5：自我后继四分支和新任务轮次

1. 自我线程在新治理批次只消费轮次结算定位，独立读取需求当前状态、优先级、安全事实、轮次结算和整体治理事实；按详细设计第6.7节的精确决议请求 / 事实 / 读取 / 结果合同调用自我 provider发布继续 / 结束 / 等待 / 取消决议。
2. 自我治理消息只携带决议身份、T/R和路由版本；任务管理独立读回决议。
3. 等待分支零任务写；结束正式结束任务生命周期；取消完成停止 / 取消收口；三者均不建新轮次。
4. 继续分支由 task owner同次建立 R(n+1)、新 P、继续治理动作及决议引用；随后从收束态迁移到`筹办中`并形成一条动态。task owner提交和这次 ARCH-L2迁移不是跨owner单事务；各自保留幂等账并独立读回，只有迁移自身是一个G1。
5. 新轮次不得复制旧路径、实例、冻结、实际结果或授权；重新进入叶2筹办。
6. 同键同义只读回首次分支结果；异义、旧决议、错任务 / 轮次或非收束前态零新增拒绝。

叶5末只运行第 7 节机械检查。

### 4.6 叶6：旧权威和自动重筹办物理退役

1. 删除任务数据 / 服务中的私有治理状态、`目标未达成待重筹办`、后继准备、自动迁移和旧读回入口。
2. 从工程和仓库物理整删`领域/内部治理/任务重筹办.数据.h`与`领域/内部治理/服务.任务目标未达成重筹办触发.ixx`；禁止保留所谓“不含自动继续的通用部分”，因为两文件身份本身就是旧自动重筹办权威。
3. 从工程和仓库物理整删`线程/协议.任务重筹办意图.ixx`，并删除其端口、邮箱绑定、任务管理处理槽、运行包 provider和自动执行队列路由的全部生产引用。
4. 从任务特征方法查找数据 / 服务、`L2任务子目标承接记录.数据.h`、两个任务子目标回流文件、当前就绪冻结、运行期只读查询、自我线程、普通应用和启动入口移除对旧状态 / 后继准备 / 下一工作包的依赖；两个子目标回流文件只保留“同一未收束Rn内新Pn定位”合同。
5. 保留初次筹办工作包；不得因名称相似删除。它只用于新任务 R1 初始化。
6. 统一修改现有端到端测试源码，使所有最终场景只走目标 ABI、正式授权 / 结算 / 后继入口；删除旧自动重筹办断言。

叶6末只运行第 7 节机械检查；随后等待真实提供者接入，不形成局部验收。
