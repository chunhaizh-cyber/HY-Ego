## 1. 目标与修订来源

v0.2 已冻结初次/后继共用同一 DATA-L2 来源联合、同一筹办 provider 和唯一结果消息，但执行侧确认后继规范化来源没有任务轮次字段，原始`下一筹办工作包`也不携带任务轮次，因此 v0.2 要求的“消息任务轮次等于来源任务轮次”无法机械实现。

本计划在原目标内完成最小修订：两个规范化来源分支都显式携带`L2任务轮次身份`；后继由 manager 现有`按任务读取当前任务与轮次`同 G 正式结果提供，不修改原始后继工作包，不增加新账、新端口或新线程。

完成链：

```text
E/M/D_service
-> 服务根任务 T/R1/P1
-> 初次规范化来源
-> P01 统一工作包
-> 一次 provider 调用
-> 一个五类结果消息
-> manager 接收/精确重复
-> 独立读回
-> 执行、等待或收束
```

筹办正常结束固定为“结果消息已被 manager 接收或确认精确重复”，不是 provider 返回或工作线程写入本地槽。

## 4. 目标 ABI 与函数合同

### 4.1 DATA-L2 来源联合

1. `L2任务初次筹办规范化来源材料`增加`任务轮次`与`本轮来源成员关系`。
2. `L2任务重筹办规范化来源材料`增加`任务轮次`，其余字段和生产资格不变。
3. 当前规范化来源的`L2任务方法选择合同版本`固定由 1 升为 2。
4. 新增纯值 helper：

```cpp
L2任务轮次身份 L2取得任务筹办任务轮次(
    const L2任务筹办规范化来源材料&) noexcept;
```

5. 完整性、相等、正式选择完整请求编码/解码、幂等比较、发布/读回及执行冻结都包含任务轮次。
6. 当前 v2 正式选择完整请求序列格式固定为 3，并从首次正式发布起包含两个分支的任务轮次；不新增格式 4。正式 HEAD 既有格式 2 只保留 legacy 读/审计资格，不能补造任务轮次、进入 current provider 或与格式 3 同键精确重复。

### 4.2 初次来源

`任务初次筹办工作包`补首次准备记录、任务轮次和本轮来源成员关系；`需求初次筹办准备`的首次/精确重复读回必须把同一正式事实放入工作包。初次纯值规范化不读仓，筹办轮次和执行轮次均为 1。

`需求初次筹办准备合同版本`保持 2。历史版本 1，或版本 2 记录缺服务请求 E/M/D、首次准备记录、R1/P1 或本轮来源成员关系时，返回具名`初次请求版本待迁移`并零写，不从当前事实或消息补齐。

### 4.3 后继来源

原始`下一筹办工作包`不变。manager 在 G=`迁移后事实代次`调用既有`按任务读取当前任务与轮次`。只有以下条件全满足才形成后继规范化来源：

```text
读回成功
本次正式读回截止 == G
读回任务.身份 == 工作包.任务
读回当前任务轮次.任务 == 工作包.任务
来源.任务轮次 = 读回当前任务轮次.身份
```

局部 pure-value helper 的显式输入为原工作包、读回任务、读回当前任务轮次和读回截止；不得自行读仓或读取线程槽。错任务、错轮次、缺失或 G 不等时使工作包形成阶段结构化失败，零新选择。完整筹办工作包尚未派发，因此不伪造筹办结果消息。

### 4.4 统一推进与结果消息

`任务筹办推进请求`保存一个规范化来源联合。P01 工作包和结果消息必须满足：

```text
消息任务 == 来源任务
消息任务轮次 == 来源任务轮次
消息筹办轮次 == 来源筹办轮次
消息G0 == 请求头期望事实代次
```

工作线程每个已消费筹办工作包只调用一次 provider，并形成可执行冻结、子目标承接、合法等待、目标已完成或结构化非成功之一。provider 不完整返回映射为结构化非成功/内部错误。结果队列满只重投同一消息。

manager 不直调 provider。结果消息首次接收或精确重复后必须进入现有结果待处理队列；只有按消息任务、任务轮次和 G 独立读回后才可进入执行、等待或收束。协议拒绝、同键异义和停止属于交接失败，不得标为正常筹办结束。

### 4.5 正式选择与执行冻结

task owner 在正式选择发布 G 独立读取当前任务轮次，并与来源联合逐项互证。管理端在`可执行冻结`结果 G1 读回正式选择、冻结、路径和实例时，再比较其任务、任务轮次和筹办轮次；全部一致后把同一来源联合放入`任务执行冻结请求`。

其它四类也必须先收到结果消息，再按正式事实收束。`合法等待`不自动重筹办，`目标已完成`不直接写任务完成，`结构化非成功`不伪装任务失败。

## 5. 实施顺序

1. 扩展 DATA-L2 两个来源 DTO、合同版本、完整性、helper和正式选择完整请求格式。
2. 按 v0.2 补齐初次工作包及 task owner 首次/精确重复读回映射。
3. 将查找、就绪、等待和统一 provider 请求改为消费同一来源联合。
4. manager 初次分支纯值形成初次来源；后继分支消费现有同 G 任务/轮次读回形成后继来源。
5. 升级 P01 协议完整性；保持工作线程一次调用、一个结果消息和队列满同消息重投。
6. manager 结果接收后统一排队并独立读回；形成执行冻结请求时互证任务轮次。
7. 无损合并装配、工程登记和异主 WIP，补施工/验证记录。

## 6. 失败收口

- 来源缺任务轮次或轮次不属于任务：引用冲突/入口拒绝，零写。
- G 漂移：结构化当前性漂移，零新选择。
- legacy 正式选择格式 2 缺任务轮次：只读/审计，不补造、不覆盖、不进入 current 生产。
- provider 不完整：唯一结构化非成功结果消息。
- 结果队列满：重投同一消息；不得重调 provider。
- 结果协议拒绝、同键异义或 manager 停止：交接失败；不得生成第二结果或静默当作成功结束。
