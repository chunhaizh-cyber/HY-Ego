## 1. 目标与完成条件

在阶段20已经创建并停驻唯一 self 的普通应用中，建立首个真实根治理批次：启动唯一 manager，提交固定首次安全/服务双根触发，由 self 工作线程在门关闭时完成 budget-free fresh 读回、G4-A 双根复核、按固定初始化意图恢复或签发不可变包并异步交给 manager；manager 恢复或承接根任务并独立读回任务核心和目标投影；self 侧整批成功后才开放治理运行门。

计划完成必须同时满足：

1. self 的 provider 调用、根复核、包恢复/签发和 manager 投递全部发生在 self 工作线程内且锁外；调用线程只提交开门控制请求并等待结果；
2. fresh 生产链使用详细设计冻结的 v2 budget-free ABI，目标链不再声明或调用旧预算 fresh、世界根、世界存在信息、当前自我、单例角色和概念使用入口；
3. task owner 可按稳定初始化意图只读恢复唯一原包，不新增业务账、不签发新编号、不改变任务高水位；
4. manager 是唯一、可 join、有界内存队列，只承接根任务初始化并独立读回核心和目标投影，不实现筹办、worker、执行或结算；
5. 当前满足且从未签包时零新意图；已有同意图包时恢复原包并重投；正差距且无包时只签发一个新包；
6. 无窗口普通应用完成真实开门后才进入宿主；失败按阶段13安全回收；普通控制面板仍不启动 manager、不开放门并返回阶段12；
7. 专项和根工程 Debug/Release x64 通过，专属实施记录形成代码知识变更清单。

本计划不实现普通 D、多 D 追加、任务筹办、任务工作线程、执行前选择、冻结、现实执行、任务结果、结算、安全值/服务值写入、后继子需求或整个自我治理闭环。

## 4. 冻结接口与所有权

完整字段、枚举稳定值、成功形状和失败映射以对应详细设计第3至7节为唯一施工合同。执行者不得改名、增字段或改变所有权。

### 4.1 self 消息与 fresh ABI

- 物理替换 `自我线程根需求复核消息_v1` 为 `自我线程根需求复核消息_v2`，字段固定为：`合同版本,消息,原请求,触发根,正式需求定位,安全根任务意图,服务根任务意图`。
- 物理退出 `自我线程上下文读取预算_v1` 和旧 fresh 请求/结果/端口；原位发布 `自我线程正式上下文请求_v2`、`自我线程正式上下文结果_v2`、`自我线程正式上下文端口_v2`。投影字段不变，成功只允许完整投影且 `写业务事实=false`。
- `自我线程::创建并停在治理运行门`一次锁定 fresh v2、G4-A、task owner 和 manager sink 四个非拥有端口；相同请求但任一端口地址不同为选择冲突。
- `复核前置并开放治理运行门`只提交控制请求并等待 worker；worker 冻结批次后锁外调用 provider，并在全批 self 侧成功后于锁内发布门开放和治理循环进入见证。
- `自我线程操作状态`只追加稳定值`根初始化代际已结束=12`；固定首次意图命中非`当前可治理`T时以该状态结束本次开门，生命周期保持已停门且不锁存内部错误。

### 4.2 最小 budget-free 下层入口

按详细设计第4.2节原位新增并实现：

1. `存在类数据服务::读取单例角色当前完整_v2`；
2. `概念树类数据服务::读取存在概念使用当前完整_v3`；
3. `世界树应用服务::读取当前现实世界根_v3`；
4. `世界树应用服务::读取世界存在信息当前完整_v5`；
5. `真实自我形成服务::读取当前自我_v2`。

五个入口均按已知身份和当前完整语义读回，遇环、引用冲突、G 漂移、资源失败或内部不一致时分别失败，不允许截断成功。旧预算入口可因本计划外尚未迁移消费者暂存，但本计划覆盖的 fresh/self 生产调用链对其声明与调用必须为零，私有 helper 也不得回调旧入口。

### 4.3 task owner 按意图恢复

在 `本能根任务核心端口_v1`和服务上新增：

```cpp
本能根任务初始化包按意图读取结果_v1
按初始化意图读取不可变包(
    const 本能根任务初始化包按意图读取请求_v1&) const noexcept;
```

请求、结果、状态和形状按详细设计第5节冻结。实现只查 task owner 私有当前预留记录与技术幂等首次材料：零命中为未找到，唯一完整命中为已读取，多命中或材料不闭合为内部不一致；不得写业务事实。self 对每根必须先按意图恢复，只有未找到后才根据 G4-A 当前满足/正差距决定零新意图或签发新包。

### 4.4 manager 线程与 sink

新建 `任务管理线程`、`自我到任务管理本能根承接消息_v1`、`根治理意图投递状态_v1`、`根治理意图投递结果_v1`和`自我线程根治理意图接收端口_v1`，签名及枚举稳定值按详细设计第6节冻结。共享消息、sink和10毫秒重试常量物理位于`线程_自我.h`；`线程_任务管理.h`单向包含self头并实现sink，self头不包含manager头，task owner不反向包含线程头。公开生命周期面固定为`任务管理线程创建请求_v1`、`任务管理线程操作结果_v1`、`任务管理线程诊断快照_v1`以及`创建并等待就绪(request,taskOwner,等待毫秒)`、`已就绪()`、`提交(message)`、`请求停止()`、`等待停止(等待毫秒)`、`读取诊断快照()`；不定义成功辅助谓词。

manager 非拥有 `本能根任务核心端口_v1&`，使用一个可 join 线程、一个 mutex/condition_variable 和有界 deque。容量与进入/停止等待复用普通应用现有具名治理线程运行配置。消费只允许：校验原包，调用 `恢复任务初始化`，必要时用原包一次恢复重试，再按返回 G 独立调用 `按任务读取核心`和`按任务读取目标投影`并核对。可恢复失败由manager保留原消息/原包并以固定10毫秒可中断等待自主重试，不依赖self回执；停止时进入有界排空。不得签包、换键、推进 `待找方法`之后状态或向 self 发送业务成功消息。

### 4.5 普通应用固定身份与接线

首次复核消息、原请求、安全意图和服务意图四个固定非零互异常量放在 `装配.普通应用.cpp`私有命名空间。普通应用上下文按依赖顺序唯一持有 task owner、manager、fresh provider、G4-A provider 和 self。无窗口路径在阶段20及停止信号安装后、进入宿主前启动 manager、提交固定首次消息并等待 self 开门；失败安全回收后返回 `宿主失败/无窗口常驻(13)`。普通控制面板仍返回阶段12且不启动 manager。

## 6. 失败收口与恢复规则

- self 邮箱同身份同正文精确重复，同身份异正文为消息冲突；首批缺固定首次双根消息或正文不一致时门保持关闭。
- manager 未就绪、队满、正在停止或资源失败时零新接收；self 保留当前消息定位，以固定10毫秒可中断等待自动从fresh重试并先按意图恢复原包，不依赖调用线程重新开门或外部重复投递。
- task owner 已签包但投递前中断、manager 接收后进程中断或发布未知，均只以固定意图和原包恢复，不使用新 G 另签、不换三项键。
- manager 对 `事实代次漂移/已可能发布`只允许同一轮消费用原包立即恢复重试一次；仍失败或遇资源失败时保留当前消息和原包，以固定10毫秒可中断等待自主开始下一轮，不依赖同义重投。非恢复性冲突具名失败并清除当前项，不迁移额外业务状态。
- self 全批失败或停止时不开放门；已经发布的包不回滚。普通应用停止顺序固定为停止并 join self，再令 manager 有界排空已接收项并 join。manager 停止后拒绝新消息，每项最多执行一轮正常消费及其一次原包恢复重试；仍可恢复但未完成的项记录停机诊断后退出，由下次固定首次触发按意图恢复，禁止无限等待重投。
- self只在尚未冻结邮箱、当前冻结批和当前处理项范围内保留有界消息指纹；该范围内同身份同正文精确重复、异正文冲突。收口后释放指纹，迟到同身份消息作为新消息完整重判，不建立已处理消息账。
- 固定首次意图若恢复到已退出当前资格或当前任务不可复用的T，锁存`根初始化代际已结束`、门保持关闭且禁止签第二包；后继任务的新意图来源不在本叶猜测。
- 任何不确定状态不得伪装成功；消息诊断、队列接收和构建成功均不能替代 owner 当前事实独立读回。
