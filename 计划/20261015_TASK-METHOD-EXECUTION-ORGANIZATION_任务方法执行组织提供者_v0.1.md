# 任务方法执行组织提供者

身份：`TASK-METHOD-EXECUTION-ORGANIZATION`；版本：v0.1；日期：2026-10-15。

本文件合并详细设计与施工计划；资格只由计划索引登记。创建侧代码基线为 `68540240`（执行前核对完整 HEAD）。

## 1. 目标与当前裁决

用户要求不再复制方法信息树；把成熟组合方法的条件、步骤、分支转换成任务内部执行组织，后续由任务根据实际结果选择下一步。本叶实现真实转换、原子发布、完整读回和结构核验，不只增加未实现 DTO。

转换出的节点是一个 T 内部的执行组织，不是新的 T 或 D；只有条件不足而形成独立子目标时，才通过现有筹办消息链派生子需求。T-D 一对一、任务状态、需求父子关系均不变。执行组织与 Vt 关联，条件保存为任务筹办要求，不保存现实事实副本或长期参数场景。

本次以当前用户裁决替代 3200/5260 中可能被理解为“禁止任务内部执行组织”的限制，及旧代码复制完整方法实例作为唯一任务组织的做法；不扩展为允许任务脱离需求或自动创建子任务。3300/5360 的方法知识、任务要求、临时实参和真实运行事实分账继续成立。

### 完成边界

- 新提供者能把本能、组合、复用调用及递归调用闭包转换为有限任务执行图。
- 正式任务读回能得到自己的执行组织定位，完整内容可经新入口读回。
- 首次一次原子发布；重复同义复用，来源/定义异义零覆盖。
- 不调用方法、不产生 X/动作、不修改任务状态或需求，不宣称生产 W2/W3 已使用新结构。
- 本叶不迁移或删除旧方法副本；旧消费者保持原状，不自动采用新组织，不双轨执行。

## 2. 当前代码与复用裁决

当前 `新方法信息` 已有参数规格、条件结果组、组合步骤组、入口步骤和结果转移。`新_方法类::获取方法()` 单方法锁内读取，尚无公开的整调用闭包同锁读取；不能由任务逐次调用拼成共同快照。扩展方法 owner 的只读提供者。

`新_任务类::实例化候选方法()` 当前调用 `建立并交付混合方法实例()`，选择函数会覆盖副本条件；任务信息持有 `方法实例节点`。新结构不用这三种入口。

复用 `基础数据集::原子建立节点组()` 的组内引用；该接口不能同时写既有 T 的反向字段。因此组织根保存唯一 `所属任务→T` 真源，任务 DTO 的组织根仅反查投影，禁止另写 T→根第二真源。根另引用 T 的唯一 Vt，表明这些要求的治理宿主。`查询字段引用节点结构()` 用于反查，`查询节点组完整结构()` 用于批量完整读取；不扩基座。

现有生产尚没有按 `结果转移组` 驱动下一步骤的调度消费者。旧副本依赖包括：任务类实例化、选择、条件覆盖、子需求、开始执行、学习重筹办、调度定位；任务工作线程 W2；管理/self 的定位检查；服务对象、服务需求、服务值结算运行服务的来源身份核验。不能仅新增结构便声称这些路径已迁移。结算函数以抽象方法登记身份核验而任务传副本身份的问题仍属于后继消费迁移，不在本叶删除核验掩盖。

知识库当前没有目标函数用途卡；上述复用裁决以当前头源和生产引用为据，不恢复旧用途卡。

## 4. 公开合同

### 4.1 方法 owner 只读闭包

在 `新_方法类` public 中声明嵌套类型与函数：

```cpp
enum class 执行结构读取状态 : std::uint8_t {
    已读取 = 1, 入口拒绝, 尚未初始化, 方法不存在, 来源不是抽象方法
};
struct 执行结构读取结果 final {
    执行结构读取状态 状态 = 执行结构读取状态::入口拒绝;
    std::vector<稳定编码> 根方法节点组;
    std::vector<新方法信息> 方法组;
};
执行结构读取结果 读取方法执行结构闭包(
    const std::vector<稳定编码>& 根方法节点组) const noexcept;
```

非空、非零根集合是入口条件；重复根按稳定编码去重排序，不表达优先级。方法 owner 一次持有 `新方法互斥`，按调用步骤遍历完整可达闭包，按 M 去重并最终排序；自调用和互相调用保留边，不再次展开，不按深度/数量截断。所有方法必须为抽象方法（`来源方法节点`、`实例根节点`均为空）。不存在的请求根返回 `方法不存在`；来源副本返回 `来源不是抽象方法`；正式闭包内断链或结构破坏走工程故障。非成功零载荷。

返回 DTO 可复用 `新方法信息`，但组织只消费下节列明的执行定义。方法头、启用状态、命中次数、登记名不写入任务组织；启用/调用资格由未来执行前 fresh 复核，不由此快照授权。只有方法头、尚无配对的来源可转换为明确空配对组，不能因此声称可执行；本叶不发明“成熟度”数字门槛。

同一组织内一个源 M 恰一个作用域；每个源步骤在其作用域恰一个调用步骤；同一源方法被多处调用时共享目标作用域定义，但不同调用位置保留不同步骤身份。递归保存图边，不展开调用栈。动作运行位置、调用栈、X、循环终止和分支命中不在此叶。

## 6. 转换与原子发布

1. 校验输入，先经方法 owner 一次取得完整闭包后释放方法锁，再取得任务锁；不让方法 owner 回调 task，不同时跨 owner 持锁。
2. task fresh 读取 T、D/Vt 及状态。允许首次创建的状态仅 `已建立/待查找方法/待检查条件/等待条件`；其余状态不创建。已有组织同义复用可以在任意状态只读进行，绝不重置运行状态。
3. 通过组织根所属任务字段反查已有结构：0为没有，1须完整核验，大于1为工程不变量破坏。所有组织宿主必须与该 T 唯一 Vt 相同。
4. 将闭包规范化为值式转换定义。保留参数规格全部成员、全部配对和明确转移，不筛选最优配对，不合并可选分支，不根据源顺序补造边。源本能有步骤/转移等正式矛盾走工程故障；合法未完备（例如空配对）按原状保存，不升级执行资格。
5. 已有组织与新定义做同义比较：排除新生成的组织内稳定编码，以来源身份和规范化结构对应；包括来源根集合、来源 M/Vm、作用域/实现方式、参数全部字段、配对源身份与全部条件/结果/确认/线性字段、步骤与入口、所有转移。命中次数、启用状态、方法头和登记名不参与。相同返回 `精确重复+完整既有组织`；不同返回 `已有组织不同`、组织载荷为空，既有图零写保留。
6. 首次在内存构建全部 `基础组内新节点` 及组内索引映射；根关联 T/Vt；其它内部引用全部为组内引用，来源和概念为既有外链。一次调用 `原子建立节点组`，不先公开空根，不逐条追加字段。
7. 发布后完整读回并逐字段对照转换定义；只有完全一致返回 `已建立+完整组织`。失败保留已发布事实，进入工程诊断，不能补建第二份、假报没有或回滚真实外部事实。

方法定义快照只证明本次转换采用的定义。源方法在闭包读取后发生学习更新不会自动改本组织；后续新调用会读到新定义并触发异义拒绝。共有概念仍用正式引用，不在任务树克隆概念；本叶不新增概念值域冻结机制或执行许可。

## 7. 完整读回、生命周期和非成功

读回在 task 锁内由根定位；首先获取根及所列作用域，再收集全部被列出的结构节点并用基础批读完整读取。没有 task 写端会修改已发布组织，故多次发现+批读不伪称跨 owner快照；此组织本身不可变。不得跨当前 M 重组已存定义，不按活源覆盖旧条件。

完整校验必须包括：类型/字段基数、未知字段拒绝、全体 owner与根闭合、无未列成员/重复成员、T/Vt反向一致、来源身份映射唯一、每个参数角色唯一且全部条件/结果角色可定位、集合角色引用存在于同一作用域、配对/线性索引闭合、序号连续或源步骤顺序唯一、入口属于本作用域、分支当前/后继步骤属于本作用域、分支结果要求属于当前步骤调用的作用域。同一 `(当前步骤,结果要求,匹配概念)` 不能指向不同后继；不同匹配概念可以共存，本叶不判定运行时多命中优先级。

校验构建图允许调用循环和结果转移循环，但结构包含关系（根→作用域→参数/配对/步骤等）必须有限且无跨根成员。来源概念和方法引用的类型由对应 owner已读回定义及现有类型入口确认；不得把任意现存编码当合法概念/方法。

组织随唯一 T/Vt 生命周期保留。没有替换、清空、增补、迁移或删除入口；不自动更新已采用定义，不写轮次/代际。未来消费迁移必须另行冻结改变组织和已开始 X 保护的合同。

正常入口非成功仅使用公开枚举所列情况，零新节点发布；没有组织用 `尚未建立`，不得伪空成功。资源异常、底座未按已验证请求完成、正式断链、读回不一致通过现有 `工程异常终止()` 日志/弹窗/终止路径，不转为缺业务条件、任务失败或学习材料；遵循 CODE-FILE-01 的锁内工程诊断规则。
