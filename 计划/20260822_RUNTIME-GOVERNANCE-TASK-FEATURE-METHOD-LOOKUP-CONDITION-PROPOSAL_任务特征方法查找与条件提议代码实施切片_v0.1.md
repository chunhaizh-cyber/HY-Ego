## 1. 目标与完成条件

在 DATA-L2 将旧“对象 / 特征 / 方向 / 结果四元组粗召回”迁移为“按目标特征粗召回”ABI，并在 BIZ-L3 内部治理形成首个只读提供者：消费由同一任务正式`目标未达成`裁决和`目标未达成待重筹办`状态形成的完整`下一筹办工作包`，在迁移后共同截止 G 互证任务目标与当前实际状态，按特征粗召回、对象 / 方向 / 结果合同判断适用性；仅当适用候选唯一时读取该方法自己的条件、输入规格和限制，形成值式缺失条件草案。

完成必须同时满足：

1. `L2普通方法结构合同版本`从 2 升至 3，旧四元组粗召回类型与函数零定义、零调用点；新粗召回只按目标特征命中，当前 / 历史、稳定顺序和双预算守恒通过；
2. 旧`方法静态能力准入*`数据头、模块、`读取匹配候选`及六项精确相等测试全部退出，方法侧六项投影仍作为方法完整描述可用；
3. 新 DTO、提供者、构造函数、结果守恒和详细设计 v0.3 完全一致，不让任务预造方法输入条件或限制；本 provider DTO 不保留合法工作包生产链上不可达的`目标已完成`或`目标当前事实待形成`业务结论；任务相对不兼容原因只保留对象、方向、结果种类和目标状态合同四类，方法用途 / 结果作用对象角色不等固定消费为`用途结果冲突`结构缺口；
4. 零概念不猜默认，支持概念就是存在根时直接进入闭包，多概念保留全部合法适用候选；多候选无选择证据不采用且零条件草案；只有唯一采用方案可以提出条件；
5. 普通应用持有唯一提供者并公开 const getter，端到端测试只经该 getter 消费；
6. 九种合法逻辑结论 required / forbidden 载荷、完整粗召回 / 不兼容证据、L2 状态映射和八项预算 / 结果上限守恒全部通过；同 G 的目标状态引用缺失或重算目标命中映射`引用冲突`，G 后事实变化映射`当前性漂移`；全链零机器事实写入，Debug / Release 重建与治理测试通过，专项施工和验证记录落盘。

## 4. 目标 ABI、所有权与依赖

### 4.1 DATA-L2

`L2普通方法结构.数据.h`把合同版本升至 3，删除：

```text
L2方法用途粗召回键
L2方法用途粗召回请求
L2方法用途粗召回结果
```

原位新增并严格采用详细设计第 4 节字段：

```text
L2方法特征粗召回请求
L2方法特征粗召回项
L2方法特征粗召回结果
```

`L2方法结构服务`删除`按用途读取方法粗召回组(const L2方法用途粗召回请求&) const`，新增：

```cpp
L2方法特征粗召回结果 按特征读取方法用途粗召回组(
    const L2方法特征粗召回请求& 请求) const;
```

该函数只负责特征命中、当前 / 历史可见性、严格排序、去重计数和预算；不得判断对象、方向、结果、条件或适用性。预算不足整项`数量预算不足`且候选为空；每个方法只消耗一次候选预算，同一方法全部命中用途仍返回。

### 4.2 BIZ-L3 内部治理

新数据头逐字采用详细设计第 5 节合同版本、两枚枚举及以下值式类型，不复用旧准入 DTO。`任务特征方法查找结论`只保留详细设计 v0.3 的九种合法结论，值从 1 到 9 连续；删除`目标已完成`、`目标当前事实待形成`和仅为后者服务的`逻辑来源读取状态`字段。`任务方法不兼容原因`只保留四项并连续编号：`对象类型不兼容=1`、`所需方向不兼容=2`、`结果类型不是目标状态合同=3`、`目标状态合同不相同=4`；旧第 1 项角色差异原因不再定义。`任务特征方法查找结果::成功()`只校验结果内在载荷守恒，不访问原请求；provider 必须另行保证已评估结果的工作包与请求工作包相同，且结果共同截止等于请求期望代次和工作包迁移后代次：

```text
任务筹办目标三元组
任务对象概念闭包项
任务方法适用候选
任务方法结构缺口项
任务方法不兼容原因
任务方法不兼容证据
任务未绑定材料类别
任务未绑定输入限制证据
任务输入规格绑定项
任务限制条件绑定项
任务缺失条件草案
任务特征方法查找请求
任务特征方法查找结果
```

新模块导出唯一 provider：

```cpp
class 任务特征方法查找与条件提议提供者 final {
public:
    任务特征方法查找与条件提议提供者(
        const L2任务结构服务&, const L2需求结构服务&,
        const L2状态结构服务&, const L2特征结构服务&,
        const L2概念结构服务&, const L2场景结构服务&,
        const L2方法结构服务&) noexcept;

    任务特征方法查找结果 评估下一筹办方法候选并形成条件提议(
        const 任务特征方法查找请求& 请求) const noexcept;
};
```

提供者只保存七个 const 引用，不可复制、不可移动、不拥有服务。唯一业务根函数严格执行详细设计第 5.1—8 节和配套单函数图：目标来源只取`任务.需求列表项`；旧实际结果的`实际状态`身份必须经`读取完整状态`和特征实例互证后才能比较；治理状态与正式裁决必须互证`目标未达成/目标未达成待重筹办`；重算关系 / 允许位必须与正式裁决一致且不得命中允许位。固定 G 的目标状态 / 特征实例`未找到/已退出/属性未设置`或重算命中均返回`引用冲突`，事实截止变化返回`当前性漂移`，两类均零载荷；不得返回不可达业务结论。存在根直达不读取普通概念；完整粗召回与不兼容证据不得丢失。`读取方法六项静态能力投影组`返回的投影已由 DATA-L2 完成用途 / 结果五项互证；角色不等只消费其`用途结果冲突`结构缺口，provider 不扩张投影 DTO、不生成任务不兼容证据、不额外读取完整方法重做结构配对。输入规格 / 限制的作用对象角色等于主轴结果角色时绑定目标宿主，否则绑定为空并形成具名未绑定证据。`bad_alloc` / `length_error`映射资源失败，其它异常映射内部错误；所有非`已评估`结果零业务载荷。

### 4.3 装配与消费者

`普通应用上下文`在七个依赖服务之后持有唯一 provider，提供：

```cpp
const 任务特征方法查找与条件提议提供者&
取得任务特征方法查找与条件提议提供者() const noexcept;
```

构造失败必须新增具名`普通应用装配状态`并结构化返回，不得退回空指针或日志判断。治理端到端测试必须由普通应用 const getter 取得 provider；删除直接构造旧 provider 的 18B 测试与 import。需求服务端到端测试把全部旧四元组调用迁移为按特征粗召回，并保留当前 / 历史、预算、替换和退出覆盖。工程文件和 filters 对旧两文件做精确一换一登记，不新增重复模块项。

八项限制按详细设计 §5.1 机械映射。只有方法用途、概念支持扫描 / 数量、概念祖先数量和主体状态数量是被调接口预算；`最大场景成员数`与`最大方法条件数`分别是无预算场景反读和无预算方法完整 / 投影读取成功后的结果上限，超限丢弃全部业务载荷并返回`数量预算不足`。不得为伪造“全扫描有预算”而扩大场景或方法 DATA-L2 ABI。
