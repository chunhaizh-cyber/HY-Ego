## 1. 目标与完成条件

按详细设计机械新建`数据服务.任务类.ixx`，以独立ARCH-L4新记录owner提供：

1. 不可变“所属存在 + 来源需求”任务类记录新增；
2. 按新记录身份读取；
3. 按所属存在和来源需求精确读取；
4. 只经需求类公开入口读取本次临时目标方向。

本计划没有具名上游计划；需求类四入口已由提交
`607de5032fc508762e6b954455a9d70ee853d99a`发布。完成只要求四个允许文件按冻结合同

最终替代只是隔离边界，不属于本计划完成条件。

用户当前不需要代码验证；不要求专项、构建、链接、运行、静态扫描、diff/strict或验证

## 3. 冻结 ABI 与依赖

公开服务入口固定为：

```cpp
任务类记录结果 新增任务记录(const 任务类新增请求& 请求);
任务类记录结果 查询任务记录(const 任务类身份查询请求& 请求) const;
任务类记录结果 按所属存在和来源需求精确查询(
    const 任务类精确查询请求& 请求) const;
任务类目标方向读取结果 读取任务目标方向(
    const 任务类目标方向读取请求& 请求) const;
```

完整DTO、19个稳定状态数值、成功谓词、构造签名和失败映射以详细设计第3—6节为准。
模块只`export import 海中鱼巣.领域.数据服务.需求类;`，直接调用只允许详细设计第3节
列出的L1七入口与需求类`查询需求记录`、`计算临时需求方向`。特征类、存在类和二次
特征类不建立第二直接调用链，旧`服务.L2*`调用为零。

## 4. 施工步骤

1. 新建真实模块，定义合同版本、稳定状态、结构类型、记录身份、记录、四类请求、两类
   结果、成功谓词、不可复制服务类和构造合同。
2. 校验专属写端口及两个非零、互异、当前、同owner普通关系类型；不创建类型、不导出
   owner或端口。
3. 实现来源需求同G0公开查询、所属存在一致性和冻结失败映射。
4. 实现首次写入幂等、精确二元组防重、一节点两关系单owner原子写集、提交后完整读回
   及已可能发布收口。
5. 实现按身份一致读取，严格证明本owner节点和恰两条关系闭包，再经需求类互证端点。
6. 实现两个目标关系组的预算门禁和源身份交集；零/一/多项分别收口。
7. 实现目标方向读取：任务身份读回后只把来源需求传给需求类临时方向入口，成功值式
   回显目标与比较，全部分支零事实写入。
8. 在工程与filters中于需求类之后唯一登记新模块；建立施工记录，列出实际ABI、函数级
   知识变更及全部未验证边界。

若实现需要调用白名单外函数、直接调用特征/存在/二次特征、复制目标、增加来源需求、
形成查询锚点/Vt/状态/轮次/业务判断、增加修改/退出入口、借用旧L2身份或改变稳定状态
数值，属于设计漂移，停止受影响范围并具名退回计划支撑。允许文件内普通C++错误由
执行者自行修复。
