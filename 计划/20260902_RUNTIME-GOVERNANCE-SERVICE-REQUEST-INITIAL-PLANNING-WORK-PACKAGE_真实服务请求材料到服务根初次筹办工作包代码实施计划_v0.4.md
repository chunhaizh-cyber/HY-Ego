v0.3 已冻结初次/后继共用同一规范化来源、同一筹办 provider、唯一五类结果消息和 manager 独立读回。用户再次明确的口径与该合同一致：每次筹办逻辑闭合都必须产生结果，并由任务工作线程通过消息交任务管理线程；manager 接收或确认精确重复后，本工作包处理才正常结束。

## 2. 继承合同

以下内容完整继承 v0.3，不在本修订重写：

- 两个规范化来源分支都显式携带 task owner 正式任务轮次；
- 后继轮次只来自 manager 在工作包 G 的`按任务读取当前任务与轮次`正式读回；
- `任务筹办推进请求.来源材料`、`任务特征方法查找请求.来源材料`和`结果.已互证来源材料`使用同一个强类型联合；
- 每个已消费工作包只调用一次 provider，形成五类之一的唯一结果消息；结果队列满只重投同一消息；
- manager 不直调 provider，收到消息后独立读回正式事实；
- 不新增服务合同、请求/结果账、持久回执、第二消息联合、第二端口、第二线程、Gseed、游标或替代账。

详细设计依据：同身份详细设计 v0.3 与 v0.4；流程图继续使用同身份 P01 初次筹办流程图 v0.3，业务节点未改变。
