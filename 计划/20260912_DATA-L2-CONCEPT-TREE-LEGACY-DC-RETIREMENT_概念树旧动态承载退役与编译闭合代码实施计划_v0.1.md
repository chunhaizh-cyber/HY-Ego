## 1. 目标和完成条件

在一个串行代码切片中：

1. 从`数据服务.概念树类.ixx`删除旧动态概念DTO、旧通用variant分支、旧扩展交付、旧构造、旧公开入口和全部旧场景/动态历史读取实现；
2. 删除旧动态专属构造/成员中的具体场景依赖、全部具体动态服务依赖及已退出状态枚举/历史入口；保留现行场景范围读取，不增加兼容壳；
3. 同次物理删除正式HEAD中唯一旧消费者`应用服务.动态概念树类.ixx`及其两个工程登记，避免只修提供者而破坏干净HEAD；
4. 保留四本体根及当前基础、特征、存在、共享概念能力；需要解码旧持久种类3的目标/动态根完整图显式返回`旧格式不支持`；
5. 通过Debug/Release目标模块专项和根工程隔离诊断证明目标文件编译错误归零；
6. 形成精确施工/验证记录并发布。

本计划只关闭旧模型并恢复当前合法能力的静态闭合，不实现4242 RC或7191新DC。后继依赖顺序是`概念公共合同与4242 RC -> 7191 DC合同/数据服务 -> 动态概念应用`，不登记为当前计划库存。

## 4. 实施步骤

### P1 冻结保留入口

以当前源码生成公开实体清单，标出基础、特征、存在、共享入口和不启用DC的构造；在施工记录记录其施工前后签名。保留四根、动态根身份getter和现行非DC事务语义。

### P2 删除旧类型与公开面

严格按详细设计第3.2节删除旧动态引用、定义、扩展、请求、结果、公开函数、成功谓词、旧动态构造组合和具体动态服务身份谓词。保留`概念树场景引用`、场景import及场景绑定谓词；场景引用历史验证改用当前`读取场景角色历史`及详细设计冻结映射。同步从所有variant删除旧动态分支并修正值式分派；不得保留别名、转发、注释代码、默认成功或`未实现`骨架。

### P3 删除旧实现闭包

删除`scenes_/dynamics_/dynamic_`及全部旧动态校验、模板、依据、审计、状态映射、历史读取、写集、重放、图和应用关联分支。保留`export import 数据服务.场景类`；特征/存在扩展校验去掉旧`dynamic_`互异分支，只保留现行布局的严格检查。`概念树应用模板事实`收口为`variant<特征概念事实>`，并在存在概念应用机械删除`holds_alternative<概念树动态模板事实>`拒绝分支；其它代码不改。

凡目标读取或动态根完整图需要解码旧概念种类3时返回`旧格式不支持`并清空载荷；不得跳过坏节点后返回完整图，也不得让未请求动态根的其它根读取被无关旧节点阻断。本片不冻结未来种类5/6的通用身份/图投影。其它请求的原key重放、G/H、owner、预算和发布阶段不改义。

### P4 退出唯一旧消费者

在异主WIP正式释放/交接后，物理删除`应用服务.动态概念树类.ixx`，并从主工程及filters精确删除其唯一登记。不得提交当前未知来源的3字节工作树内容作为实现，不修改场景成员概念WIP，不删除概念树模块登记。全仓正式源码重新扫描，旧公开面其它消费者必须为零。

### P5 编译修复与专项

先构建仓外最小模块工程，按编译诊断仅修复目标文件内删除闭包遗漏；不得以恢复旧类型或扩大白名单消错。Debug/Release均须构造并读回基础、特征、特征+存在、共享四类保留路径；验证四根和旧种类3显式拒绝。随后运行根工程隔离Rebuild，要求该文件诊断为零并分账其它错误。

### P6 记录与发布

施工记录列出所有删除/保留函数、旧调用闭包扫描、知识变更清单和未实现后继；验证记录保存命令、工具链、配置、退出码、诊断归属、探针结果和未覆盖范围。只暂存七个白名单文件，精确提交并普通推送`origin main`，复核远端、index和剩余WIP后释放登记。

## 5. 失败收口

- 单文件内普通编译错误、漏删分支或谓词不一致：在白名单内修复并重跑。
- 动态概念应用异主WIP未释放：保持现场并等待，不把计划降格为单文件发布。
- 发现除本片删除模块外的旧公开面正式消费者：停止并返回`CONSUMER-MIGRATION-DRIFT`，不扩大白名单。
- 发现保留FC/EC/共享能力必须改变公开DTO、owner、事务、生命周期或新增合同/工程模块：停止并返回`CONCEPT-BASE-ABI-DRIFT`。
- 只有恢复旧ABI才能编译：不得恢复，返回`LEGACY-ABI-DEPENDENCY-DRIFT`。
- 根工程仅剩异主WIP或其它文件错误：如实分账，不扩大计划。
- strict仍仅命中已知`acceptance_record`缺口：记范围外FAIL；本片新增错误必须修复。
