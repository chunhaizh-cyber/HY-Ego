# WEB-SEVEN-EXPRESSION 按需成文和新消息回读 v0.2

起点 `d3144161c7e189ff50e0ffd8813944024e814736`。本交互窗口唯一所有者，Windows main。用户要求按需成文与收件理解独立，先验原第 1、4、5、7 组，再沿同入口验证其余可独立组。依据 [7240](../规范/7240_子规范_自然语言双向转换与组织规则.md) 和 [已有验收](../验证记录/20261127_WEB-SEVEN_正式网页入站验收.md)。

1. 普通网页增加「生成文字」明确动作用最近一次本窗正式收件回执的序号。从 `POST /api/control/received?id=...` 空正文复用既有同窗源、Origin、Host、会话和入站身份核验。既有 GET 保持只读取；缓存键含请求用途，HTTP 线程不查业务 owner。成文只展示结果，不自动送信，不改变原图、需求、任务或语言所有者。
2. 业务接收认知服务提供同步只读的正式成文调用，输入已限定的原 M、正式接收根范围和原消息角色以及已装配现实根。读语言 owner 当前正式解释，以正式篇章采用走既有篇章成文，其他走既有正式部分结构成文。只有一个覆盖整句组的已成功结果，或一组连续不重叠且覆盖全原范围的成功结果，才返回全部生成文字；不得拼接原文字面或用已有缓存输出充当本次成文。未就绪、前提变化、资源失败与无完整表达分别保留。复用原函数的独立程序内解析，正式新 M 回读由 Chrome 另发验证。
3. 允许 `业务/接收需求认知.服务.{h,cpp}`、`装配.普通应用.cpp`、`界面/宿主.网页对话.{h,cpp}`、本计划、索引和专属记录。不改规范、R126、R131、恢复、任务、种子或外设写权。本验收不重跑既过治理前态，也不要求当前物理测值。
4. 实际 Release x64。普通 Chrome 可见操作：逐组正式提交未经修改的原文，明确点击「生成文字」，保存响应及 DOM 实际显示文本，送回输入框再正式提交获得新 M，对照正式来源、对象、角色、类型、数值、单位和适当的语气与变化时序。待完善或无完整成文时单列，不能用旧缓存或打印原文凑通过。复测关闭同 PID 自然退出。保留本次有证据组，不把历史治理 D 写回算已通过。
