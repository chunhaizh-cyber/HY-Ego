## 1. 目标与完成条件

实施 [v0.1 详细设计](../规范/详细设计/20260804_L1-SIMPLIFY-CONTRACT-F0_公共合同与仓库隔离详细设计_v0.1.md)：建立 `L1公共事实` 与完整 `L1事实基座` 两个合同模块，使服务公开完整版本化合同、私有导入仓库，使 L2 领域服务只公开传播安全公共事实类型。

## 3. 机械实施

1. 按详细设计第 2 节拆出公共事实头和模块，删除旧头中的重复实体所有权。
2. 建立完整合同模块并逐字新增合同版本及六类版本化请求；`L1写集请求` 增加版本首字段。
3. 仓库模块 import 完整合同，不再 export include 数据头；仓库函数签名与算法不变。
4. 服务模块 export import 完整合同、private import 仓库；11 个公开入口先拒绝错误版本，再机械转发。
5. 按第 6 节表格一次性迁移所有正式调用；禁止保留无版本兼容重载。
6. 两个 L2 领域服务只 export import 公共事实合同，并私有 import L1 服务；两个 L2 数据头 fallback 只包含公共事实头。
7. 工程登记两个新模块与一个新头；保持既有模块顺序闭包且不改变完整自检登记总数。
8. 新增错误版本专项并更新专属施工/验证记录。

## 4. 停工条件

若 MSVC 无法在既有模块模型下实现“服务私有 import 仓库 + 合同公开传播”，或 L2 公开 DTO 必须依赖完整 L1 写合同才能编译，停止并具名退回，不得恢复服务对仓库的 `export import`。若迁移要求改变状态编号、幂等、原子发布、读取或恢复语义，同样停止。

## 6. 完成边界

本计划只证明 L1/L2 接口隔离、显式合同版本拒绝和当前行为矩阵保持。它不证明 L1 内部已发生替换，也不证明持久恢复、世界完整业务、旧基座删除、生产接线、跨编译器 ABI 或集成验收。
