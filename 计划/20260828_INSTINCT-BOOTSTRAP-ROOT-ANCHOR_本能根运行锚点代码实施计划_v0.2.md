## 6. 实施顺序

### 6.1 目标合同恢复

1. 增加目标合同幂等首次完整读取 DTO、状态和成功谓词。
2. 从状态 owner 首次写入材料恢复合同身份。
3. 按请求 `G0` 读取当前合同；截止不同返回当前性漂移。
4. 非成功统一空载荷、截止零。

### 6.2 首值首态原子入口

1. 特征服务增加 private 首值参与者形成和闭包验证。
2. 状态服务增加 private 首态参与者形成和闭包验证。
3. 状态服务公开 `新增特征首值与初始状态_v1`。
4. 复用现行 L1 双参与者原子运输，旧运输字段名不外泄。
5. 验证值、状态、选择共同代次和零动态。
6. 修正 `新增状态_v2` 幂等优先级并移除固定拒绝壳。

### 6.3 业务 DTO 和 provider

1. 冻结 `M`、中点、规则身份、版本和业务幂等身份。
2. 实现锚点、初始化结果和纯值二次特征函数。
3. 实现定义、实例、值/状态、注册、合同、需求和列表项的形成或恢复；比较注册的单位、维度、分量角色均绑定各自根特征定义身份，不新增辅助节点。
4. 实现 `Gfinal` 全量正式重读。
5. 仅在全部互证后返回锚点。

### 6.4 启动和线程

1. 在方法登记根成功后、自我线程创建前构造 provider。
2. 捕获一次大于零的 UTC Unix epoch 纳秒。
3. 初始化非成功时返回失败阶段 21。
4. 自我线程创建合同升为 2，锚点进入有效性、相等和锁定请求。
5. 继续使用现有整请求锁定槽和治理运行门。
6. 所有启动阶段成功后才开放治理循环。

### 6.5 工程与测试

1. 工程和 filters 登记业务文件及专项测试模块。
2. 正式测试调度增加 `--test-本能根运行锚点`。
3. 数据、IntDir、OutDir 全部使用仓库外隔离目录。
4. 测试宏和故障注入不得进入普通生产构建。
