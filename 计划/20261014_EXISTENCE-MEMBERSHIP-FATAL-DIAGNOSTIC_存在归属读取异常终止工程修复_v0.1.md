## 5. 唯一致命工程出口合同

### 5.1 物理位置、签名与复用

在`核心/容错检查.h`同置一个工程诊断入口：

```cpp
[[noreturn]] inline void 工程异常终止(
    const wchar_t* 文件, int 行号,
    const wchar_t* 入口, const wchar_t* 原因,
    const char* 异常说明 = nullptr) noexcept;
```

形态为header-only普通inline函数，不新增.cpp/工程登记。调用者仅为本叶9个catch；文件、函数名及原因来自静态字符串，行号来自`__LINE__`。每个原catch改为`catch (const std::exception& 异常)`和`catch (...)`：前者同步传入`异常.what()`，后者不提供what。入口先将what复制进固定缓冲，再交给诊断线程；不保存异常对象或what指针。不得调用业务查询补材料，不保存领域对象地址或业务引用。`原因`明确为“此读取入口发生C++异常，原业务结果未形成”，不推测异常等同结构缺失。原字符串化/宽化宏必须移至条件编译块外供默认构建复用，既有容错宏开关行为不变。

复用`日志系统.h::记录逻辑错误日志()`及原容错检查的`OutputDebugStringW`、`MessageBoxW`形式。原`记录容错检查错误()`使用动态分配并直接弹窗，且关闭宏后不存在，不适合作为本叶的无返回入口。新入口独立于`HY_EGO_ENABLE_FAULT_TOLERANCE_CHECK`，默认构建始终成立。它是工程诊断出口，不是业务公开服务、事实owner或第二错误系统。

### 5.2 故障线程与诊断线程

内层catch退出自身try作用域后，外层调用栈仍可能持有`新存在互斥`、`存在概念图互斥`及更外层服务锁。因此故障线程不能直接日志/弹窗，也不继续返回或向外层throw。

固定处理：

1. 以一个header内ODR共享的原子标志争取首故障。后续故障线程永久停留在工程终止等待，不重复输出、不执行领域回调、不返回；首故障负责终止进程。
2. 首故障将文件、行号、入口、原因及可得的what复制到固定容量POD缓冲。冻结容量：文件512个wchar、入口256个wchar、原因256个wchar、what最多512字节，组合诊断文本2048个wchar；超长文本明确截断并保持终止符。what按有界字节先复制，UTF-8有效时转为宽文本；不是有效UTF-8时显示其受控十六进制字节摘要，不依赖本地代码页，也不丢弃原异常原因。复制和格式准备不使用堆分配，不取得业务锁。数据只用于本次人读诊断，不持久化为业务记录。
3. 使用`_beginthreadex`启动一次专用诊断线程，参数指向本次稳定固定副本；原子首故障保护保证副本不会被后续故障覆盖。诊断线程不调用存在、概念、任务、需求、方法服务，不要求故障线程持有的任何业务锁，也不读取或修改业务结构。
4. 创建成功后，故障线程关闭其持有的线程句柄并使用Windows等待原语永久停留；它不join、不经过业务展开/析构/结算。等待仅属于不可返回的工程终止路径，不占用正常任务调度工作。
5. 诊断线程用同一份受控文本先尝试逻辑错误日志，再发`OutputDebugStringW`，最后`MessageBoxW`；日志和弹窗说明同一原因及“修复代码后重新启动”。日志写入抛异常或返回失败不转成业务结果，也不阻止继续尝试弹窗；正常情况下弹窗关闭后终止进程。
6. 诊断线程顶层catch保证诊断自身异常也进入强制终止。线程创建失败时故障线程直接强制终止，诊断输出失败不得让程序返回原业务路径。无法完成弹窗/日志时不伪称完成诊断。

复制辅助、诊断线程入口与终止辅助仅放于本头内部具名命名空间，不增加业务可见材料类型。诊断责任统一为本地记录一次；辅助不形成其它日志出口。

### 5.3 终止与失败收口

终止辅助采用`TerminateProcess(GetCurrentProcess(), ERROR_UNHANDLED_EXCEPTION)`；如果API返回失败，立即`__fastfail(FAST_FAIL_FATAL_APP_EXIT)`。不使用`ExitProcess`、`std::exit`、`std::terminate`或`std::abort`来替代，以免进入其它终止处理程序、业务析构或结算。辅助必须`[[noreturn]] noexcept`，不允许在TerminateProcess之后返回。

无撤销、无发布、无补偿、无结算、无清空已有事实；故障前已经发生的事实不被补造为成功或失败。进程强制终止对尚未持久化材料的影响按现有存储能力处理，本叶不新增恢复保证。

正常弹窗需要操作者关闭；这是本次用户要求的人工诊断步骤。没有增加业务截止时间、重试次数或“等待确认”任务状态。诊断输出、用户交互及资源不足条件下的具体时序尚未运行验证，编译不能证明它们成立。
