# CURRENT-SNAPSHOT-A3-ROOT 全局根运行读取实施计划 v0.1

基线 `2dc25d50dcb5d88d4c1261f6f5594401c85dc4c6`，施工所有者为主工作区交互窗口。目标是持久权威绑定后，通过现有正式接口读回该权威的全局根和各世界根。此能力为正式世界与服务对象后续接入提供根身份。以启动准入前后的全局根编码和有序挂接组完全相等为本切片的读回判据。依据 [0050 §2](../规范/0050_项目通用机器逻辑与禁止性规则总纲.md)、[4200 §2、§5](../规范/4200_子规范_世界树上层应用与一致读取.md)、[4202 §2](../规范/4202_子规范_场景字段与世界组织.md)、[4015 §14–15](../规范/4015_子规范_基础数据集.md)、[4070 §4–5](../规范/4070_子规范_权威结构快照恢复候选与运行期原子发布.md)及[现行启动设计](../规范/详细设计/20261128_CURRENT-SNAPSHOT-STARTUP_当前事实持久启动详细设计_v0.1.md)。上游已发布的特征值恢复通过编译链接，冷建与重启运行待验。[上游验证记录](../验证记录/20261128_CURRENT-SNAPSHOT-A3-VALUE_特征值运行者恢复验证.md)

## 实施合同

1. 仅修改 `海中鱼巣/领域/世界挂接.全局根.cpp` 与 `海中鱼巣/启动.应用程序.cpp`。全局根所有权仍在 `新_全局根类`，复用 `全局根读回结果`、现有返回枚举、`基础持久运行包::读取已绑定会话(全局基础数据集)` 和 `读取恢复全局根(const 基础持久视图&) noexcept`。复用解码器对四个自键、五个登记节点及正常四项必需挂接的既有校验。模拟根可缺失。公开签名、存储格式、当前登记的类型范围及挂接基数均沿现状。
2. `完整读回() noexcept` 在进入原冷内存分支之前取得绑定会话。已绑定时从会话一次取得当前不可变视图，以局部共享引用持有至解码结束，直接返回 `读取恢复全局根(*视图)`。已绑定却无视图返回 `结构不一致`，不得回退冷内存分支。`查询世界根(世界类型登记键) noexcept` 继续经 `完整读回()` 查询，缺项或非成功沿原空结果。绑定分支仅访问已发布的内存权威，无磁盘访问、节点分配、缓存字段写入或领域回调。暖路径不更新 `全局根场景节点` 等冷建锚点。
3. `初始化() noexcept` 已绑定时使用同一读法校验合法根，读回 `已完成` 映射为 `无变化`，其余状态原样传递。`挂接世界根(世界类型登记键, 稳定编码) noexcept` 已绑定时先按原登记键规则和有效编码判定输入，在同一视图验证输入节点存在并读回挂接组。相同登记键和根编码已存在，返回 `无变化`。同登记键已指向其它根，或该根已挂到其它登记键，返回 `结构不一致`。有效的新挂接及无效输入返回 `入口拒绝`。正式读回失败原样传递。持久分支无事实写入，已有冷内存新建、挂接、写后确认和错误行为保持。
4. `检查普通启动持久准入` 只在原 `绑定恢复权威` 与既有自我、直接所属场景读回检查均成功之后，且在特征值运行探查之前，调用 `新_全局根类::完整读回()`。调用前后校验 `会话->读取()` 仍为准入时同一个 `视图`。视图变化使用 `持久根复核失败` 和 `前提已变化`。读回为资源失败使用同一失败阶段和 `资源失败`。其它非成功，或正式全局根节点及按登记键排序的完整挂接组不能与原 `根` 核同，使用同一失败阶段和 `结构冲突`。比较使用原 DTO 的节点和挂接组，禁止按部分字段、容器数量或日志认定相同。成功继续现有特征值探查，保留阶段 31 及业务关闭。已有空仓候选校验和绑定失败分支保持原行为。无需新增日志调用或枚举。

## 验证与边界

在主工作区以项目默认输出路径运行 `MSBuild.exe 海中鱼巣.vcxproj /t:Build /p:Configuration=Release /p:Platform=x64 /m`，编译链接通过后记录实际输入和结果。施工及函数知识变更写入 `验证记录/20261128_CURRENT-SNAPSHOT-A3-ROOT_全局根运行读取验证.md`。静态核对公开头文件未变、冷分支仍按原路工作、所有绑定分支均为零机器事实写入、正式读回只能使用一次取得的当前视图、暖启动的状态分流和后续业务仍关闭。

只有用户明确要求本切片的验收时，才用现有真实启动入口和获准受控数据根验证冷建后独立重启，核对两个进程的正式全局根与挂接身份及现有阶段 31。负例覆盖挂接缺失或复义，核对失败阶段及读后存储字节一致。未执行的运行用例记 `NOT_RUN`。此切片交付全局根运行读口，不授予持久写入、场景或外设 owner 就绪、普通宿主启动或服务需求任务闭环结论。
