## 6. 工程状态、动作和失败边界

| 来源调用结果 | 原接收流程处理 |
| --- | --- |
| 已完成且载荷相符 | 消费正式输入继续原逻辑，不根据它确认语种、词界或需求 |
| 资源失败 | 调原 `资源()`，仍为既有资源延后／非终结及500ms轮转，不新增重试政策 |
| 前提已变化 | 调原 `漂移()`，仍为既有前提变化控制 |
| 未找到、未初始化、输入拒绝、未支持 | 本调用已经具备完整保留接收记录选出的正式 M／合法整条范围／空路径及启动初始化；消息根以真实引用保留 M，M／正文无公开删除或改写路径。返回这些状态说明不变量、接线或正式输入合同错误，抛具名 logic_error，上送原 self 工程终止边界，不降为漂移或无限重试 |
| 成功缺信息、无效来源身份、来源／正文／材料不一致，或非成功携业务信息 | 抛具名 logic_error；错误材料包括可取得的 M、实际状态及本次已发表来源 ID，不补造业务解释 |

`推进一次`现有 bad_alloc／length_error 捕获和私有推进中断不变；非资源逻辑异常不得新增通用 catch 吞掉。唯一生产调用方 self 已在释放状态锁后调用它，并在原 std::exception／未知异常边界具名记录及 `工程异常终止`；不改 self、不重记来源 owner 已处理的故障。

此处“未找到”的消费前置不同于可接受任意节点的普通消息查询：原 `移除当前消息引用`只更新窗口当前引用集合，仍正式读回保留消息，不删除消息根登记或 M；来源 owner 对已登记来源的消息端点失效也直接工程终止。因此不能机械沿用旧消息保护 reader 的未找到→漂移映射。只有明确的 `前提已变化`状态继续走原漂移控制。

来源建立并不是方法执行动作，不生成动作、状态、动态、FT或需求结果。来源如已发表而随后载荷构造／原解析资源失败，保留实际来源；原 M、同键重试取得同身份，不撤销、不删材料、不改消息序号、不把它写成理解已完成。本次已发表身份只作工程已发生事实，不能升级 U／D／T状态。

## 7. 锁序、生命周期及诊断责任

普通应用上下文锁仍只按原构造串行化；辅助不保存依赖。首次来源初始化发生在线程开放前；重复复核按提供者自身语言锁运行，不持外设锁或反调应用。来源 API 的既有锁序为语言短预检释放→外设窄读释放→语言／L1，不改变。

接收认知读取会话时的 `impl.锁`在来源调用前已经释放；新调用禁止放入该锁范围。self在原推进调用前已经释放状态锁。来源调用结束后才进入原解析、资源读取或采用 reader，不能把外设锁／语言锁跨调用保存。依赖由普通应用持有，存活到 self最终join，退出及封存按原逻辑，无新增生命周期或线程。

逐函数诊断：初始化辅助为`本地记录`（仅资源返回，其它工程故障终止）；`完成装配`及构造重载新增接线部分的工程异常由辅助终结，资源按既有装配控制返回；`推进一次`新增部分为`向上送出`，终结于原self最终工程边界。原纯计算 `标量数`直接复用不改；不以新增日志或仅bool返回替代工程中断。
