## 1. 目标与完成条件

### 目标

为现有 ARCH-L2 状态/动态两参与者原子 provider 补齐中性底座闭环：

1. L1 在全部参与者候选写集应用并统一事实代次后，交换正式仓库和写幂等账前执行全局当前节点/关系端点闭包检查；
2. 状态事实及其主体、特征、值、时间、来源和版本材料永久保留；状态 owner 以唯一 `L2特征实例→L2状态` 当前选择关系表达当前性；
3. 首态、迁移、失败零写、幂等和独立读回均通过公开中性结构合同验证。

### 完成条件

- 无悬空当前关系、当前值槽或独立材料引用可以进入正式仓库；参与者应用顺序任一交换均拒绝悬空候选。
- 迁移后旧状态事实与旧选择历史可读，新选择唯一当前，动态前/后状态关系分别指向旧/新永久状态。
- 所有交换前非成功路径不交换正式仓库、不推进事实代次、不写跨 owner 幂等账，并返回结构化失败结果；交换后独立读回失败不得声称回滚或零写。
- 首态无动态；重复首态/重复迁移返回同义幂等结果，异义请求零写冲突。
- Debug/Release 根工程和 `D:\TEMP` 中性 harness 验证矩阵通过；独立读回与失败账断言均有记录。

## 4. 机器合同

### 4.1 L1 全局闭包

在 `核心/仓库.L1事实基座.ixx` 增加内部无异常检查函数：

```cpp
当前节点引用闭包检查结果 检查跨所有者原子候选全局引用闭包(
    const 状态& 候选仓库) noexcept;
```

调用顺序固定为：获取锁、校验 G0/幂等/参与者、复制候选、应用状态写集、应用动态写集并解析局部引用、统一候选事实代次、全局闭包检查、形成结果、写幂等账、交换正式仓库。

闭包检查覆盖当前关系三端点、当前值所属/类型/来源/材料端点、当前属性槽和候选索引一致性；历史事实不因退出当前而被当作悬空。请求悬空映射 `引用冲突`，候选索引/不变量损坏映射 `内部不一致`；G0 漂移、许可拒绝、资源失败和幂等冲突保持现有分账。闭包失败时零载荷、零写、零代次推进、零幂等账。

### 4.2 状态当前选择与永久事实

新增状态 owner 专属关系类型 `L2状态当前选择关系类型身份`，方向为：

```text
源：L2特征实例身份
目标：L2状态身份
唯一键：(特征实例身份, 当前选择关系类型)
```

宿主存在与状态主体在同一 G0 互证；当前范围等同于特征实例，不新增 L3 范围身份。状态节点、主体/特征关系、值、时间、来源、版本事实永久有效，当前性只由选择关系决定。

`L2状态结构.数据.h` 至少提供：当前选择关系引用、当前选择读取请求/结果、状态原子参与者局部键和旧/新选择证据，以及 `新增状态` 请求中的非零当前选择关系局部写入键 / 幂等材料。`服务.L2状态结构.ixx::新增状态` 是唯一首态入口；状态永久事实和当前选择关系必须同一状态-owner G1 形成，并在形成结果中同时返回完整状态事实与选择关系引用。缺键、零键、坏局部引用或只形成其中一项均拒绝并零写；缺选择关系的旧数据返回 `待迁移`，不推断、不写入。

### 4.3 两参与者原子迁移

首态：复用现有 `新增状态`，请求携带非零当前选择关系局部写入键 / 幂等材料；状态 owner 同一 G1 建立永久状态事实与唯一当前选择关系，无动态。精确重复返回原状态+原选择关系且不推进代次；同键异义为 `幂等冲突`；已有不同当前状态为 `已有异义当前 / 引用冲突`；旧状态无选择关系为 `待迁移`。交换前候选闭包或互证缺任一者为零写；交换后独立读回缺任一者返回 `已可能发布的内部不一致` / `发布未知`，不得声称回滚，允许同幂等键重放。
迁移：状态 owner 退出旧选择关系、建立新永久状态事实和新选择；动态 owner 建立动态主体、前态→旧状态、后态→新状态；两方候选写集由 L1 在同一 G0 全局闭包检查后一次交换。

旧状态节点保持普通关系可引用；A1 和动态前态都可长期引用旧状态。状态 owner 不解释业务成功性，动态 owner 不写状态选择关系。

## 5. DTO/API 与错误合同

### 公开结构 DTO

- `L2状态当前选择关系引用`：关系稳定编码、特征实例身份、当前状态身份。
- `L2状态当前选择读取请求`：L2 请求头、读取类别、特征实例身份、历史截止代次。
- `L2状态当前选择读取结果`：L2 结果头、当前/历史选择状态、可选选择关系引用。
- 状态原子参与者 DTO：当前选择关系局部键、旧选择稳定编码（首态为空）、新选择及退出证据。
- 状态动态原子结果：新选择和旧选择退出证据、动态前/后状态稳定身份。

### 错误与幂等

同一特征实例首态/迁移请求的同义重试返回首次成功结果；异义请求返回幂等冲突。G0 变化返回事实代次漂移。当前选择已被其它状态占用、局部引用无法在最终候选解析或候选闭包损坏分别返回引用冲突/内部不一致。交换前所有非成功结果为零载荷和零写；交换后独立读回异常返回 `已可能发布的内部不一致` / `发布未知`，保留幂等账并允许同键重放，正式读回不得用缓存、日志或方法返回值代替。

## 6. 实施顺序

1. 在 L1 既有跨 owner 候选交换前插入最终全局闭包函数，保留现有错误分账与公开 ABI/合同版本。

3. 在状态动态原子 DTO/服务接入旧/新选择证据，确保两参与者局部引用最终闭合；不增加第三 owner。
4. 用 `D:\TEMP\ARCH-L1-L2-STATE-HISTORY-CURRENT-SELECTION-REFERENCE-CLOSURE\` 中性 harness 依公开入口覆盖正反矩阵。

## 7. 验证合同

### 构建与专项

- Debug/Release 根工程 fresh Rebuild PASS。
- harness Debug/Release 覆盖：首态、迁移、状态→动态顺序、动态→状态顺序、参与者顺序反转拒绝、悬空引用拒绝、G0 漂移、许可拒绝、坏引用、精确重复、异义冲突。

### G1 五组正式读回

1. 旧状态事实和历史关系仍可读，且失去当前性不退出；
2. 当前选择关系唯一指向新状态，旧选择已退出当前；
3. 动态主体、前态→旧状态、后态→新状态关系端点与特征实例/主体一致；
4. 共同截止下参与者结果和事实代次一致，重复请求不产生第二代；
5. 交换前失败分支正式仓库不变、代次不变、幂等账无新条目；交换后读回失败明确“已可能发布/发布未知”，保留事实代次和幂等账并可同键重放。

### 首态公开 ABI 专项矩阵

以下均经现有 `服务.L2状态结构::新增状态` 验证，不得另建测试或生产首态入口：

| 场景 | 必要输入/判断 | 结果与写集 |
| --- | --- | --- |
| 首次首态 | 非零当前选择关系局部写入键 / 幂等材料、特征实例和状态永久材料同一 G0 | 同一状态 owner G1 形成状态事实+当前选择；结果同时返回二者；无动态 |
| 精确重复 | 同一幂等键且状态/选择材料全相等 | 返回原状态+原选择，不推进代次 |
| 同键异义 | 同一幂等键但任一材料不同 | `幂等冲突`，零载荷、零写 |
| 已有异义当前 | 特征实例已有不同当前状态 | `已有异义当前 / 引用冲突`，零写 |
| 旧数据待迁移 | 有旧状态事实但缺当前选择关系 | `待迁移`，不得自动补造 |
| 坏局部键 | 缺失、零值、坏引用或无法同 G0 互证 | 具名拒绝，零写、零代次 |
| G0/许可/资源失败 | 共同截止漂移、许可拒绝或资源失败 | 保持现有分账，零载荷、零写 |
| 交换前闭包 | 状态事实、当前选择、宿主/主体同截止互证 | 任一缺失为事务内内部不一致，零写、不推进代次、不写幂等账 |
| 交换后独立读回 | 状态身份事实、当前选择、宿主/主体同截止互证 | 全部通过才确认首态成功；缺失/未知返回 `已可能发布的内部不一致` / `发布未知`，不得声称回滚或零写，同幂等键重放 |

独立读回必须通过公开状态身份/历史 API、当前选择 API、动态 API 和 L1 代次/幂等查询互证；不得以日志、缓存、退出码或测试专用假对象替代。
