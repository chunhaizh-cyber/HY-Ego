## 1. 目标与完成条件

在七个既有生产模块内交付详细设计冻结的服务专属期望 G 核验、窄同底座互证、数据服务内部依赖构造闭合、三个应用移除 L1 依赖和需求来源公开 variant 递归。一次施工同时退出三个应用的旧 L1 构造、成员、直接调用及 `绑定于(L1)`，不保留双 ABI。

完成必须同时满足：

1. 三个期望 G DTO、入口、失败映射和成功谓词精确实现；
2. 同底座矩阵允许同底座不同服务对象，拒绝相同 G 的不同 L1；
3. 存在、任务内部依赖错绑在构造期拒绝；
4. 三应用仅依赖领域或同层业务公开合同，原业务请求/结果、算法、预算和 G/H 语义保持；
5. 需求模块对 `二次计算内部` 零引用；
6. 静态检查、ABI 探针及 Debug/Release 构建影响检查达到本计划门禁；
7. 只发布允许文件和专属记录，不带入异主 WIP。

## 5. 实施顺序

1. 执行 S0：核对本计划正式 blob/状态、HEAD、七文件 blob、WIP 所有权、index、当前生产消费者和构建资源；任一目标文件被他人占用则只等待该文件。
2. 在特征、需求、任务模块依次加入专属 DTO、成功谓词和期望 G 入口；使用既有 L1 引用和枚举，不改原私有读取语义。
3. 加入详细设计的窄同底座谓词；补存在构造的特征依赖核验、任务构造的四依赖核验。
4. 修改二次计算应用：删除 L1 成员/参数/入口，改由特征服务完成首尾 G 核验，增加与特征服务同底座谓词。
5. 修改需求方向应用：先用公开 variant 等值递归替换内部 pair 键；再删除 L1 依赖，以需求服务守卫并按三条件闭合构造，增加与需求服务同底座谓词。
6. 修改任务方向应用：删除 L1 依赖，以任务服务守卫并按两条件闭合构造。
7. 执行静态扫描、纯值/ABI 探针、两配置外置 fresh 构建影响检查；范围内失败由执行者修复，范围外既有失败严格分账。
8. 形成专属施工、验证记录，列出函数级知识变更清单；精确检查允许文件后申请唯一 Git 发布租约，只提交本计划切片并普通推送。

## 6. 非成功、迁移和停止规则

- G 入口严格按详细设计第4.2节映射；不得把失败压成 bool/optional，不得接受新 G 继续旧请求。
- 同底座只用于构造配置闭合；不同 L1 即使 G 相等也拒绝，同底座不同合法服务对象不得因地址不等拒绝。
- 构造失败仍抛原 `invalid_argument` 文本，不产生部分对象；运行入口保持 `noexcept` 并映射资源失败/内部不一致。
- 尾 G 失败继续沿原业务结果清空规则收口；已形成的结构化诊断子结果不升级为顶层成功。
- 旧应用构造、成员、直接 L1 调用和 `绑定于(L1)`同次物理退出；不保留兼容期。
- 新发现七文件外真实生产构造消费者、需要工程变更、公共合同文件、L1 新能力、枚举/DTO/owner/事务变化时，停止 B 并具名退回计划支撑。

### 7.2 ABI 与行为探针

在仓库外临时目录生成不进入生产工程的探针并编译链接运行，至少覆盖详细设计 B01—B12：

- `offsetof`/类型断言核对三个标准布局结果的字段顺序；
- 成员函数指针精确核对所有新增签名；
- `is_constructible` 核对新构造存在、旧 L1 构造不存在；
- `requires` 核对三个应用不再公开 `绑定于(L1)`；
- 两个独立 L1 设置相同 G 后仍互相拒绝；同一 L1 上不同合法服务对象组合接受；
- 0 G、匹配 G、漂移 G、资源/内部失败边界；资源失败严格按详细设计第9.1节，以仓库外并发探针和真实 L1 独占写锁/`try_to_lock` 竞争，使三个领域核验入口分别实际返回一次资源失败；
- 保存定义、本次节点、准确 F、共享子图、缺节点、重复和超深来源闭包；
- 调用前后读取 L1 G 和 owner 范围事实数量，证明新增只读入口与失败路径零写。

临时探针、构建根和日志不进入 Git；退出前记录路径与清理结果。资源失败探针必须冻结迭代上限和总时限，并保存三个入口各自实际命中的结构化结果；任一入口未命中、探针无法形成合法 L1 写竞争、或需要修改 L1/生产 ABI 时，B03 失败且本计划不得完成。禁止以 `NOT_RUN`、跳过或 catch 代码存在通过 B03。

### 7.3 外置 fresh 构建

从本计划起点分别建立 before 与“起点 + 七候选文件” after 的仓库外隔离根，使用独立 `IntDir/OutDir` 执行 canonical `Debug|x64`、`Release|x64` Rebuild。成功条件：

1. 若 before 为零，after 必须为零；
2. 若 before 因范围外既有错误非零，after 的规范化错误集合必须完全同构，不得新增、删除或移动删除相关错误；
3. after 中七目标模块均产生本轮新 IFC/OBJ；
4. ABI 探针在两配置均独立编译、链接和运行成功。
