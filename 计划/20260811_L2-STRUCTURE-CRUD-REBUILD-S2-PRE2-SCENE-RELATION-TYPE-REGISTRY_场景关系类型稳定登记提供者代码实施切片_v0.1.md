## 1. 目标、范围与完成条件

为 S2 补齐第二个具名前置提供者：由现有 `L2场景结构服务` 唯一建立、定位并正式读回“场景父子关系类型”和“场景成员关系类型”两个普通 L1 节点，使后继 S2 能在不硬编码稳定编码、不接受业务调用方指定关系类型编码的前提下形成两类关系写集和查询条件。

本叶只建立两类关系类型的稳定登记，不实现父子 / 成员关系实例、新增 / 替换 / 退出、任意场景完整结构查询、生产装配或启动接线。它不修改 L1 历史关系组提供者，不把场景关系类型塞入 `L1自我结构登记`，不建立第二事实仓、关系类型缓存表、SQL / 材料回源或全仓扫描定位。

完成条件固定为：

1. 两类关系类型都是 L1 分配稳定编码的当前普通节点，零属性、零关系、零值，创建事实代次相同且编码互异；
2. 场景服务以一个固定私有 L1 幂等域和固定登记身份形成唯一两节点中性写集，首次建立与完整原请求精确重复均从两项新编码映射取得同一定位；
3. 新服务实例默认明确返回 `登记未加载`，只有以完整原请求取得 L1 精确重复并正式读回两个节点后才能重建定位；换期望代次、换身份、换规则或换写集不能创建第二对类型节点；
4. 已加载定位每次读取都深复制后通过 L1 一致当前投影复核权威节点；一次事实代次漂移允许使用 L1 回显的实际代次完整重读一次，仍漂移或节点异常则结构化失败；
5. 定位只属于 `L2场景结构服务` 对象生命周期，不是权威事实；异常不清空定位、不降级为未加载，也不把缓存值直接返回为成功；
6. 后继 S2 只能由场景服务内部读取定位并机械使用两个编码，所有公开 S2 业务请求和结果均不增加“关系类型编码”输入；
7. 生产外验证覆盖首次建立、精确重复、并发同请求、新实例未加载与重建、错请求零重复创建、代次前进读回、节点异常和稳定编码非硬编码；主工程 Debug / Release x64 保持编译链接。

### 2.2 复用 / 新建裁决

不能硬编码两个稳定编码，因为 4015 的编码由 L1 运行期分配且不可复用；不能让 S2 调用方提交关系类型编码，因为这会把场景结构所有权和类型选择权交给业务输入；不能扩展 `L1自我结构登记`，因为其领域只拥有自我结构服务身份和自我结构关系类型；不能只持进程缓存，因为缓存不能证明当前节点仍有效；也不能按名称、显示文本、索引扫描或完整快照寻找类型节点。

裁决：原位扩展现有 `L2场景结构服务`。服务用一次中性写集建立两个普通节点，通过新编码映射按具名本地键区分父子类型与成员类型，保存只供定位的值式登记，并在每次读取时从 L1 正式复核。该方案新增事实最少、零新模块、零新工程登记、零第二所有者，且 S2 后继可在同一服务私有实现中消费定位。

## 4. 最终 DTO 与状态合同

`L2场景结构.数据.h` 增加：

```cpp
inline constexpr std::uint32_t L2场景关系类型登记规则版本 = 1;

struct L2场景父子关系类型身份 final {
    稳定编码 值;
    friend bool operator==(const L2场景父子关系类型身份&,
        const L2场景父子关系类型身份&) = default;
};

struct L2场景成员关系类型身份 final {
    稳定编码 值;
    friend bool operator==(const L2场景成员关系类型身份&,
        const L2场景成员关系类型身份&) = default;
};

enum class L2场景关系类型登记状态 : std::uint8_t {
    已提交 = 1,
    精确重复 = 2,
    已读取 = 3,
    登记未加载 = 4,
    入口拒绝 = 5,
    许可拒绝 = 6,
    事实代次漂移 = 7,
    幂等冲突 = 8,
    资源失败 = 9,
    内部不一致 = 10
};

struct L2场景关系类型登记请求 final {
    L2结构请求头 请求头;
    std::uint32_t 规则版本 = L2场景关系类型登记规则版本;
    L2结构幂等身份 幂等身份{1};
    friend bool operator==(const L2场景关系类型登记请求&,
        const L2场景关系类型登记请求&) = default;
};

struct L2场景关系类型登记 final {
    std::uint32_t 合同版本 = L2结构合同版本;
    std::uint32_t 规则版本 = L2场景关系类型登记规则版本;
    L2结构幂等身份 首次幂等身份{1};
    std::uint64_t 首次期望事实代次 = 0;
    std::uint64_t 建立事实代次 = 0;
    std::uint64_t 事实截止代次 = 0;
    L2场景父子关系类型身份 父子关系类型;
    L2场景成员关系类型身份 成员关系类型;
    friend bool operator==(const L2场景关系类型登记&,
        const L2场景关系类型登记&) = default;
};

struct L2场景关系类型登记结果 final {
    L2场景关系类型登记状态 状态 =
        L2场景关系类型登记状态::入口拒绝;
    std::uint64_t 事实截止代次 = 0;
    std::optional<L2场景关系类型登记> 登记;
    bool 成功() const noexcept;
    friend bool operator==(const L2场景关系类型登记结果&,

```

请求有效条件固定为：共同合同版本 1、规则版本 1、幂等身份精确为 `{1}`，首次期望事实代次允许 0 但必须小于 `UINT64_MAX`。固定登记身份不是关系类型稳定编码，也不是业务对象身份，只用于把一份唯一登记写集绑定到服务私有 L1 幂等键，调用方不得选择其它值。

登记完整条件固定为：版本正确、首次幂等身份 `{1}`、建立事实代次非零、`建立事实代次 == 首次期望事实代次 + 1` 且无回绕、事实截止代次不早于建立代次、两个强类型身份均非零且互异。只有 `已提交`、`精确重复`、`已读取` 可以携带完整登记；其余状态登记为空。结果成功时顶层截止等于登记截止，失败时只在 L1 安全回显当前代次的漂移 / 冲突分支保留该代次，其它分支为 0。

两种关系类型身份只出现在登记结果和场景服务内部，不加入后继 S2 父子 / 成员写请求。它们不能隐式互转，也不能替代关系实例稳定编码、父子顺序或成员顺序。

## 5. 固定幂等域、两节点写集与映射

场景模块内部冻结：

```cpp
inline constexpr std::uint64_t 场景关系类型登记幂等域 = 0x1DULL;
inline constexpr std::uint32_t 场景父子关系类型本地键值 = 0x0201'0101U;
inline constexpr std::uint32_t 场景成员关系类型本地键值 = 0x0201'0102U;
```

L1 幂等键固定为 `(0x1DULL << 56) | 请求.幂等身份.值`，且有效请求身份只允许 `{1}`。`0x1D` 只隔离本登记的 L1 幂等写集，不是稳定事实编码、第二幂等账或领域身份。首次生产装配必须在任何普通 L2 写请求前建立登记；全局 L2 幂等身份本就要求调用方唯一，后继不得把该私有完整键用作普通结构请求身份。

唯一 L1 写集固定为：

```text
合同版本 = L1中性CRUD合同版本
期望事实代次 = 请求.请求头.期望事实代次
幂等键 = (0x1D << 56) | 1
节点 = [
  { 本地键=0x02010101, 种类=普通, 属性类型表示=null },
  { 本地键=0x02010102, 种类=普通, 属性类型表示=null }
]
关系 = []
值 = []
属性槽变更 = []
退出事实 = []
```

形成后恰一次调用 `L1事实基座服务::提交中性写集`。不得预读编码、扫描现有节点、改写期望代次、换幂等键重试或建立模块侧幂等账。

首次成功必须是 L1 `成功`、形成权威发布、重试边界不适用；完整原请求重复必须是 L1 `精确重复`、未形成新发布、重试边界为原幂等键读回收敛。两者均要求合同 / 键回显正确、事实代次非零、新编码映射恰两项、本地键唯一、稳定编码非零互异。父子类型只取 `0x02010101` 映射，成员类型只取 `0x02010102` 映射；不得按映射顺序、数值大小或硬编码稳定编码区分。

L1 入口拒绝、事实代次漂移、幂等冲突、资源失败按同名登记状态映射；本两节点写集意外返回未找到 / 已退出或坏成功形状统一为内部不一致。

`L2场景结构服务` 保持现有构造函数，并增加：

### 6.1 建立

建立入口用 `lock_guard` 串行同一服务对象的登记：

1. 请求非法则入口拒绝、零 L1 调用；
2. 已有定位且请求的版本、固定身份或首次期望代次与原登记不一致，返回幂等冲突、零 L1 调用，禁止发布第二对节点；
3. 合法时形成第 5 节唯一写集并恰一次提交；
4. 从两项映射形成候选登记，建立代次取 L1 首次结果代次；
5. 通过私有正式读取辅助复核两个节点；只有完整成功才赋值 `关系类型登记定位_`；
6. 首次返回 `已提交`，完整原请求重复返回 `精确重复`。

新服务实例即使共享同一个已有 L1，`读取当前场景关系类型登记` 仍先返回 `登记未加载`，不扫描补造。它只能用固定身份和首次原期望代次重交完整原请求；L1 精确重复返回原两项映射，正式读回成功后重建同一定位。若新实例改用当前代次或其它字段，同一固定 L1 键绑定不同规范化请求，只能幂等冲突且保持未加载，不能建立第二对节点。

两个服务实例并发提交同一完整原请求时，由 L1 全局幂等账串行为一项首次成功和一项精确重复；两者必须取得相同两编码，权威事实代次只推进一次。

### 6.2 当前读取

当前读取先在登记锁内深复制定位，再释放锁并调用私有辅助。无定位精确返回 `登记未加载`、零 L1 调用。已有定位时：

```text
以定位.事实截止代次构造一致当前投影，只读取两个节点
-> 成功则逐字段验证两个普通节点并返回已读取
-> 首次事实代次漂移且失败形状完整：以回显实际代次完整重读一次
-> 第二次仍漂移：事实代次漂移
-> 许可 / 资源失败按同名状态
-> 节点未找到、已退出、种类不匹配、属性非空、创建代次不等、编码错位、混代或坏结果：内部不一致
```

成功节点必须为当前普通节点、属性类型表示为空、当前属性为空、创建事实代次都等于登记建立事实代次；成功登记的截止更新为本轮实际读取代次。读取成功不修改已保存定位；定位的旧截止只用于下一次首轮探测。异常也不清空定位，因为清空会把已知事实损坏伪装成未加载；后续继续返回真实异常，直到服务对象释放或正式事实恢复机制另行裁决。

`bad_alloc` / `length_error` 映射资源失败，其它异常映射内部不一致。服务不写日志、不 sleep、不无限重试。

未来独立生产装配计划必须：

1. 在 L1 服务可用后、任何 S2 场景关系操作或完整场景读取前，唯一拥有一个长生命周期 `L2场景结构服务`；
2. 以固定身份 `{1}` 和当次首次建立前真实 L1 事实代次形成一次不可变登记请求，并在该 L1 服务生命周期内保存完整原请求；

5. 当前阶段无 L1 崩溃 / 重启 / 跨进程恢复，因此不得宣称跨进程重建；未来恢复重新进入范围时，必须让恢复 / 装配材料保留完整原请求及两节点权威事实，不能仅保存进程定位。

## 7. S2 消费合同

S2 后继计划在本提供者真实结果进入 `main` 后，必须原位扩展同一个 `L2场景结构服务`：

- 父子关系写 / 查只在服务内部从 `读取当前场景关系类型登记` 取得 `父子关系类型.值`；
- 成员关系写 / 查只取得 `成员关系类型.值`；
- 公开父子 / 成员请求只包含场景 / 存在身份、旧关系身份、顺序、幂等和期望代次，不包含任一关系类型编码或关系类型身份；
- S2 在一次操作中取得登记后必须让登记截止与其 L1 一致读取 / 写前基线机械一致；漂移按 4230 返回事实代次漂移，不跨代次拼接；
- S2 入口若在未完成生产初始化的对象上观察到 `登记未加载`，视为场景服务装配内部不一致，不映射为未找到、空关系组或业务拒绝；许可、漂移、资源失败和内部不一致分别沿共同结构状态返回；
- S2 不 import `L1自我结构登记`，不访问本服务 mutex / optional，不复制登记为第二当前表。

本计划只冻结上述消费门禁，不实现 S2 函数或 DTO。

## 8. 生产外参数验证

### 8.1 验证项目

`L2场景关系类型登记参数验证.cpp` 只 import `海中鱼巣.核心.服务.L1事实基座` 与 `海中鱼巣.领域.服务.L2场景结构`，通过公开 L1 / L2 入口构造受控状态。不得 import 私有仓库模块、访问定位 mutex / optional 或解析日志作为判据。

入口解析：

```text
--合同版本 <uint32，默认1>
--规则版本 <uint32，默认1>
--首次期望事实代次 <uint64，默认0>
```

固定登记身份始终为 `{1}`，不提供自定义命令行参数。项目支持 Debug / Release x64、v145、C++20、Unicode、`/utf-8`，单独编译 L1 三个合同模块、L1 仓库 / 服务、L2 公共合同、场景模块和验证入口；不进入主工程或 solution。PowerShell 包装把输出 / 中间目录定向到系统临时目录。

### 8.2 必过矩阵

1. 新服务对象直接读取返回登记未加载，L1 事实代次不变；
2. 以自定义首次期望代次和固定身份首次建立，取得已提交、两个非零互异类型编码、同一建立代次和完整普通节点读回；
3. 同一服务重交完整原请求取得精确重复、同一两编码 / 建立代次，L1 当前代次不推进；
4. 两个新服务对象在一份新 L1 上并发提交同一完整原请求，结果恰为一项已提交、一项精确重复，两项编码全等且当前代次只推进一次；
5. 新服务共享已有 L1 时先返回登记未加载；重交完整原请求取得精确重复并重建同一定位；
6. 另一个未加载服务把首次期望代次改为当前代次时取得幂等冲突、保持未加载、当前代次与节点数形状不变；错误合同、规则和非 `{1}` 身份均入口拒绝、零 L1 调用；
7. 建立后通过不同幂等身份新增一个无关场景节点推进事实代次，登记读取首轮漂移后一次重读成功，截止更新而两类型编码 / 建立代次不变；
8. 通过公开 L1 写集在末尾退出一个尚无关系引用的类型节点，已加载服务再次读取返回内部不一致而不是登记未加载 / 未找到 / 空成功；
9. 静态与运行断言共同证明两节点、零关系、零值、零槽、零退出的建立写集，映射按本地键区分，源码和验证均未出现硬编码返回稳定编码、L1自我结构登记调用或关系类型扫描。

真实分配故障、长时间并发、崩溃、重启和跨进程恢复不做运行注入；不得虚报为验证通过。
