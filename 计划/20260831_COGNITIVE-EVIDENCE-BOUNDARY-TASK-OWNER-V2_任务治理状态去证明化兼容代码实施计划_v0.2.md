## 1. 目标和本叶结果

本计划交付认知证据边界纠偏的最早可独立代码结果：

```text
已有 legacy 幂等账
-> 仍可按首次规范化写集、首次映射和历史投影重建完整语义并精确重放
-> 返回首次 G1 和原 legacy 完整载荷

没有 legacy 幂等账
-> 两个旧治理状态写入口拒绝首次新写
-> legacy 重筹办来源拒绝首次正式选择新写
-> 零 L1 写集、零事实代次变化、空成功载荷

current 普通筹办
-> 只接受初次筹办来源
-> 形成既有初次正式选择、路径、实例和执行冻结
-> 动作执行完成后进入既有正式结果 / 轮次结算链
```

本叶停止以下对象的新生产：

- `L2任务目标裁决证据事实` 节点及其专用关系 / 材料；
- 由“执行结果待验证”或“目标未达成待重筹办”入口生成的证明型治理状态链；
- 以 legacy 目标裁决证据为来源的首次重筹办正式选择；
- 专用稳定证明节点、用途观察节点和同义证明节点。

旧编码、旧节点、旧关系、旧公开结构和旧幂等账仅保留历史读回、恢复审计和精确重复资格，不删除、不重排、不复义。

## 5. 冻结的兼容行为

### 5.1 两个旧治理状态写入口

目标函数：

```text
L2任务结构服务::新增执行结果待验证状态(...)
L2任务结构服务::提交目标未达成待重筹办迁移(...)
```

两者采用相同的“先账后拒绝”顺序：

1. 保留现有公开请求有效性检查；非法请求继续 `入口拒绝`。
2. 以现有幂等身份读取所属 L1 首次账。
3. 首次账已存在时：
   - 从首次映射和历史投影重建原业务语义，并与本次请求逐字段相同；L1 幂等账不另存这两个入口的完整请求 DTO；
   - 同义则提交首次规范化写集，且只接受 L1 `精确重复`；
   - 读回首次写入结果对应的完整 legacy 状态、目标裁决证据和其它既有载荷；
   - 返回 `L2结构状态::精确重复`、首次事实代次 G1、无新变更代次；
   - 首次请求异义返回既有 `幂等冲突`；
   - 首次账、首次写集、首次结果或 legacy 闭包损坏返回既有 `内部不一致` / `引用冲突`，不得补写缺项。
4. 首次账不存在时：
   - 在读取当前代次、构造证明节点、调用任何写端口之前立即返回 `L2结构状态::入口拒绝`；
   - 事实截止代次为 0、变更代次为空、所有 optional 成功载荷为空；
   - 不建立治理状态、目标裁决证据、后继准备记录、角色关系、材料值或当前关系；
   - 不消耗幂等身份，不建立“拒绝账”，后继相同首次请求仍按同样规则拒绝。

“已有账精确重放”只用于恢复、重试和历史消费者稳定性，不重新授权 legacy 业务生产。

### 5.2 任务正式选择 v2

目标函数：

```text
L2任务结构服务::发布任务筹办正式选择_v2(...)
```

固定顺序：

1. 请求和资源上限检查保持现状。
2. 先读取 `L2任务筹办来源幂等身份` 对应首次账。
3. 首次账已存在：
   - 初次筹办或 legacy 重筹办都允许按首次完整请求精确重放；
   - 同键异义仍返回 `幂等冲突`；
   - 精确重放返回首次正式选择、冻结材料、实例方法、首次 G1 和既有提交见证；
   - 读回失败保持 `已可能发布`，不得再次形成首次写集。
4. 首次账不存在：
   - `L2任务初次筹办规范化来源材料` 可以继续现有首次选择写入；
   - `L2任务重筹办规范化来源材料` 必须在构造写集前返回现有 `L2任务筹办正式选择状态_v2::入口拒绝`，所有载荷和正式读回截止为空 / 0；
   - 其它 variant 异常或未知形状继续 `入口拒绝`。

current 初次选择的稳定来源只能是既有首次筹办准备记录所代表的治理谱系。请求的 `稳定证据组` 不得包含 `目标裁决证据` 类别；不得因此新建任何专用稳定证明节点。若当前公开有效性允许异形组，服务必须在首次写前用现有 `入口拒绝` 收口，不修改数据头。

### 5.3 普通筹办组合器

目标函数：

```text
任务筹办当前就绪与执行冻结提供者::形成当前可执行冻结_v2(...)
```

该普通生产入口只接受初次筹办来源：

- 请求有效后、正式业务读回和冻结构造前，确认来源为 `L2任务初次筹办规范化来源材料`；
- 重筹办来源一律返回既有 `任务筹办当前就绪结论::入口拒绝`，快照 / 正式选择 / 冻结成功载荷保持空，正式截止按既有非成功合同为 0；
- `取得归因证据()` 的 current 可达分支只返回首次筹办准备记录；legacy 重筹办分支可以保留源码兼容，但普通入口不得到达；
- 初次筹办仍需完成现有目标、方法、动作、权限、条件、场景、当前性和正式选择检查；本计划不放宽任何门禁。

### 5.4 执行后进入结算

本计划不修改 manager 或轮次结算 ABI。执行者必须用静态调用核对与专项证明：

```text
current 初次正式选择 / 执行冻结
-> 既有动作执行
-> 正式任务实际结果读回
-> 既有任务轮次结算
```

执行完成后不得调用 `新增执行结果待验证状态()` 或 `提交目标未达成待重筹办迁移()` 形成 proof 驱动后继。若当前真实生产链仍必须依赖这两个入口才能到达结算，本计划判定 DRIFT，禁止修改 manager 或补造中间证明事实。

需求是否已经满足仍由需求在实际使用时 fresh 读取目标涉及的当前特征值并独立核算；任务结果和结算只作治理事实，不在本叶实现当前值比较。

## 6. 实施顺序

### P1 旧写入口先账后拒绝

在 `服务.L2任务结构.ixx` 中分别重排两个旧写入口：

- 保留完整 request validation；
- 把首次账读取与现有精确重复分支放在首次新写拒绝之前；
- 沿用首次映射和历史投影的逐字段同义性复核，不查找不存在的“首次完整请求 DTO”；
- 删除 current 可达的首次写集形成 / 提交路径，或使其在账不存在时不可达；
- 保留 legacy 私有形成、解码和读回辅助，仅供已有账重放与历史读取；
- 用局部注释说明“兼容重放，不授权首次新写”，不得把聊天或计划文本复制成运行时事实。

### P2 正式选择来源收口

在同一服务文件中：

- 保持首次账精确重复分支先于来源拒绝；
- 账不存在时只允许初次筹办来源继续；
- legacy 重筹办来源直接返回 `入口拒绝`；
- current 初次请求若稳定证据组包含目标裁决证据类别，在任何 L1 写入前拒绝；
- 不改完整请求编码 / 解码，不改旧记录格式，不退出旧当前记录。

### P3 普通组合器收口

在 `服务.任务筹办当前就绪与执行冻结.ixx` 中：

- 为普通入口增加初次筹办来源守卫；
- 保持初次来源的正式读回、条件裁决、冻结和发布顺序；
- 证明 current 路径不会调用 legacy 重筹办归因分支；
- 不改数据 DTO，不新建重筹办替代来源，不从状态 / 动态推导当前值。

### P4 专项和残留扫描

在既有端到端测试模块中扩展专项目录，不新建测试 module：

- 对三个首次新写拒绝边界和三个已有账重放边界形成独立断言；
- 对 ordinary composer 初次 / 重筹办分支形成断言；
- 对执行后结算可达性和旧写入口不可达性形成断言；
- 保留 legacy 历史读取和恢复 fixture，不自动发布新的 legacy proof fixture；测试准备既有账时必须使用已有兼容 fixture / 持久样本或明确隔离的预置历史写集，不得通过生产公开入口首次创建。

## 7. 精确验证矩阵

### 7.1 两个旧治理写入口

每个入口分别覆盖：

1. 合法请求、无首次账：`入口拒绝`，空载荷、截止 0、L1 当前代次不变；
2. 已有完整首次账，首次映射 / 历史投影与本次请求逐字段同义：`精确重复`，首次 G1、完整 legacy 载荷、零新应用；
3. 已有首次账、同键异义：`幂等冲突`，空载荷、截止 0、零新应用；
4. 已有账但首次映射 / 历史投影 / 写集 / 结果缺失：内部失败，零新应用；
5. legacy 节点或关系缺 / 多 / 重 / 异类型：引用冲突或内部不一致，不补写；
6. L1 重放不是 `精确重复` 或事实代次不等于首次 G1：映射既有错误，禁止成功；
7. 非法请求：保持既有 `入口拒绝`；
8. 资源异常：保持既有 `资源失败`；其它异常保持既有内部错误状态。

### 7.2 正式选择 v2

1. 初次筹办、无首次账、完整材料：首次形成成功；
2. 初次筹办、已有账、同请求：精确重复返回首次 G1；
3. 初次筹办、稳定证据含目标裁决证据类别：首次新写拒绝；
4. legacy 重筹办、无首次账：`入口拒绝`、空载荷、截止 0、当前路径 / 实例 / 选择不变；
5. legacy 重筹办、已有账、同请求：精确重复返回首次完整结果；
6. legacy 重筹办、已有账、同键异义：`幂等冲突`；
7. legacy 重筹办精确重放后正式读回失败：`已可能发布` 且只有既有提交见证；
8. 初次 / legacy 分支发生 G0 漂移、引用冲突和资源失败时保持现有结构化映射。

### 7.3 普通组合器与结算

1. 初次筹办来源完整：保持当前成功行为和正式读回截止；
2. 初次筹办来源不完整或门禁失败：保持既有分账；
3. legacy 重筹办来源：在正式选择和任何写入前 `入口拒绝`；
4. current 可达冻结归因只引用首次筹办准备记录，不引用目标裁决证据；
5. 一次执行完成后到达既有正式结果 / 轮次结算读回；
6. 执行后生产调用图对两个旧治理写入口为零调用；
7. 结算成功不生成用途观察、目标裁决证据、稳定证明节点或其它同义 proof；
8. 结算失败仍按既有许可、漂移、引用、资源和内部错误分账，不回退调用旧入口。

### 7.4 静态与恢复

- 公开 DTO、字段顺序、类型大小、枚举值、导出函数和模块依赖零变化；
- `L2任务结构.数据.h`、工程文件和禁止文件零 diff；
- 新生产写集扫描不包含目标裁决证据节点 / 关系、角色 `40..44`、用途观察节点 / 关系或新增 proof 键；
- legacy 解码、历史读回和恢复仍能读取既有材料；
- 重启后已有账仍精确重复，无账仍拒绝，拒绝不形成可恢复事实；
- 旧编码仍占用原值且无新生产调用，未删除、未复用、未改义。

> task owner 的两个证明型旧写入口和 legacy 重筹办首次选择已停止首次新生产；已有 legacy 幂等账仍可精确重放，普通 current 只形成初次筹办选择，执行后沿既有结算链继续。

不得声明：

- 任务治理状态格式 2 已实现；
- 同轮执行前重筹办已恢复；
- 目标比较已全部改为 current 特征值；
- 历史 proof 已迁移或删除；
- 需求结算、SELF、FRESH、学习或认知业务闭环已全部完成；
- 编译或工程见证证明系统已经形成新的认知事实。

## 9. 后继 DRIFT

### DRIFT-COGNITIVE-EVIDENCE-CURRENT-ROUND-REPLAN

同一任务轮次在执行前因当前值、方法适用性、授权、安全或版本漂移而需要重新筹办时，尚未冻结不依赖目标裁决证据的正式来源、幂等身份、轮次语义和选择 / 冻结更新合同。在正式合同形成前，current 重筹办保持结构化拒绝。

### DRIFT-COGNITIVE-EVIDENCE-CURRENT-VALUE-COMPARISON

筹办条件和任务目标仍有路径直接消费状态精确值。后继必须冻结同 G 的特征当前值完整投影、目标 / 条件合同、类型 / 维度 / 单位 / 值域、读前后守卫和失败矩阵；禁止从状态、动态后状态、任务结果、缓存或治理 proof 补造当前值。

这两个 DRIFT 不阻止本计划交付“停止首次 proof 新生产”的兼容止血结果，但阻止宣称 current 重筹办和目标比较业务闭环已经完成。

## 10. 执行期真实停工条件

仅在以下情况停止本叶并退回：

- 现有公开结果无法在不改数据头的条件下表达拒绝或 legacy 精确重复；
- 首次账读取发生在不可逆写入之后，无法仅在允许服务文件内安全前移；
- legacy 精确重放必须首次新建缺失 proof 才能成功；
- ordinary composer 无法在不改 DTO 的条件下区分初次 / 重筹办来源；
- 执行后结算当前真实生产链仍强依赖两个旧写入口；
- 必需专项只能通过修改禁止文件或新增测试 module 才能建立；
- 目标文件或语义存在未释放的活动所有者；
- Debug / Release、专项或恢复验证持续失败，且无法在允许文件内安全归因并修复。

普通格式问题、可在允许文件内修复的纯代码错误、无关 dirty 或一次性工具波动不构成扩大范围理由。
