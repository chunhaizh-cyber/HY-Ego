## 4. 实施步骤

### P1：对齐self ABI与实现

1. 删除self运行代次/独立逻辑身份类型和全部字段、比较、完整性判断及消息分支。
2. 创建请求保留合同版本、邮箱容量、世界/self/本能根三份业务材料；见证删除旧身份且不复制E。
3. 从创建请求删除两组读取预算；两组预算类型保留给未来provider请求；邮箱容量只从普通应用具名配置填入。
4. 创建入口维持请求加等待参数，完整请求锁定邮箱容量；等待参数继续只控制本次调用。
5. 消息按消息身份/原请求和分支材料判重；数值8的旧运行代次不匹配状态退役。
6. 保持门关闭、零provider调用、零消息消费、析构最终停止并join。

### P2：扩展普通应用配置和所有权

1. 配置升版并加入邮箱容量、进入停门等待和停止回收/诊断等待三个非零字段；更新默认、规范化和相等判断。默认值只由三个具名工程常量提供，其数值作为施工记录中的工程选择，不得解释为机器语义或性能上限。
2. 两组未来读取预算不得进入普通应用线程运行配置；它们只保留在未来对应provider的真实调用请求中。
3. 上下文按详细设计顺序加入锚点/fresh材料缓存和唯一self对象；阶段21 provider每次局部构造，不保存为上下文成员。
4. 新增阶段21、阶段20和停止回收三个窄公开入口；不暴露内部引用或裸指针。

### P3：接通阶段21

1. 接收阶段19成功结果并以其`最终Gread`正式验证世界根、读取self。
2. 每次尝试新建provider并只调用一次；完整保留原结果。
3. 仅成功缓存锚点；任一非成功清除候选缓存且禁止创建self。

### P4：接通阶段20

1. 以锚点截止fresh读回世界/self并按详细设计表逐字段构造请求。
2. 把配置容量写入创建请求，并使用配置的创建等待调用上下文唯一self对象。
3. 互证停门见证和诊断快照；任一失败按固定顺序停止、唤醒、等待、join。
4. 回收超时保留租约，不detach、不替换对象、不销毁上下文。

### P5：接通模式宿主

1. 启动共同前缀按装配、self、阶段19、阶段21、阶段20顺序推进，首个失败保持原阶段。
2. 普通控制面板安全stop/join后返回宿主失败/阶段12；回收失败优先阶段20。
3. 无窗口模式安装现有停止信号并调用现有无窗口宿主；宿主返回后无条件安全stop/join。
4. 生产运行期模式保持现状。

### P6：工程登记与记录

1. 根工程/filters唯一登记阶段21三文件和self两文件；不登记专项。
2. 专项工程直接编译所需生产源，使用独立临时根和子进程隔离全局上下文。
3. 施工记录保存精确代码基线、实际文件、知识变更清单和未验证范围；验证记录保存每项命令、结果和证据边界。

## 5. 失败收口

- 发现现行规范、修订M1A与详细设计字段不一致：停止受影响切片并退回计划支撑，不在代码中兼容两套ABI。
- RC-P1仍占用任一共享文件：保持`待激活`，不得开始P1—P6。
- 阶段21 provider或self公开接口在新HEAD漂移：重新S0并修订本计划，禁止机械适配改变语义。
- 任一线程回收无法在配置时限内完成：保留上下文和joinable租约，验证判失败；不得detach或用析构意外阻塞冒充成功。
- 根工程构建失败若由本计划范围内错误引起则修复；若来自异主WIP，只报告精确阻断，不修改其文件。
