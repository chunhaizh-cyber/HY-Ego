   ```cpp
   virtual 服务对象需求发生保护结果 读取当前需求发生保护(
       稳定编码 场景, 稳定编码 主体, 稳定编码 需求特征, 稳定编码 需求) const noexcept = 0;
   ```

2. `新_需求类.cpp` 的代理短持 `新需求互斥`，核 `结构已初始化()` 并复制已装配端口指针后解锁，再调用端口。未初始化或端口未装配返回 `依赖未就绪`，其它返回原样传递。提供者复读需求资格会回入需求所有者，调用方不得持任务锁或需求锁。复用现有普通装配的单实例绑定与所有者生命周期。普通应用先停止并回收线程，随后解绑，最后关闭发布服务。
3. 在 `海中鱼巣/业务/服务对象需求.发布服务.cpp` 实现四参数入口。输入须为有效场景、主体、需求特征及预期原需求。先经世界所有者的 `读取需求引用更新依据` 核同场景、H、F 和预期原 D，取 `前状态节点` 为候选 S；此时只是相对于下一次更新的当前状态，尚未证明正式发生。缺合法定位、D 不匹配或无候选保持 `发生不匹配`，世界依据已变化照传 `前提已变化`。不从历史、首次发布记录或当前值反推 S。
4. 四参数入口复用五参数 `读取当前需求发生保护(C,H,F,D,S)` 校验正式发生记录、状态、实际 A、正式动作来源、完整目标及当前引用。四参数入口不另持发布服务占用跨越五参数调用。五参数入口保持基线的 `前状态节点 == S` 检查。同 D 换 S 仍为前提变化。五参数入口已复读世界依据，并把当前引用、正式发生及需求资格的保护联合核同。四参数入口成功时原样返回这组保护。仅当五参数返回 `发生不匹配` 时，再读一次世界依据，若原 D 或当前 S 漂移，或世界读口返回 `前提已变化`，则返回 `前提已变化`。仍是同 D/S 且依据有效时保留 `发生不匹配`。五参数的 `内容未具备`、`资源失败`、`依赖未就绪`、`前提已变化` 原样返回。复用发布服务现有错误处理，稳定的非成功不携带候选。无新增数据写入或事务。

## 任务来源筹办分流

1. 在 `新_任务类::构造来源前驱查询上下文` 已有锁外候选循环中复用 `H当前需求特征引用本D` 判断。当前分支仅处理已核验的人类 H 和唯一 F 当前引用的本 D。先检查停止令牌。场景由现有场景所有者读取 H 的正式所在场景，随后调用需求类四参代理。不得采用入站 M 的临时窗、调度焦点或由名称推定场景。候选场景缺失保留业务缺口，已读取的世界依据及联合保护负责核验当前定位。现有 H 来源只证明当前交互对象和人类资格，本只读阶段不认定其已登记为服务对象。真实登记、原窗及正式明确求助的自我复核由已有承接入口执行。
2. `已读取` 时核结果为同一场景、H、F、D，目标等于候选的完整目标，S 有效且保护非空。把发生保护合入 `材料.完整保护` 并随既有批合入上下文和最终核同。此版只有发生方式为 `新需求`，且原 D 已有首次接收认知来源时，才使用该发生的 S 构造来源键。再经需求所有者的行动请求来源保护读取核验同窗明确请求、受请求者及目标。后续查询执行需求、复核筹办资格、变化后重读和唯一 T 保护全部共用这同一个键。已有执行结果按其正式来源回读，禁止把旧执行 D/T 归因为当前 S。
3. 当前候选的 `发生不匹配`、`内容未具备`、当前发生属于再次需要、缺首次接收来源或正式行动请求不适用时，仅保留已有内容/状态材料，缺席的请求、同源 D 和任务保持未取得。当前 D 的任何上述分支不得尝试按旧 U 查询。本次发生为再次需要时，原 D 的首次采用不能当作该次求助。非当前 D 仅沿既有不带 S 的旧 U 读回历史，保留原筛选及候选选择边界。该查询仍只匹配来源无 S 的执行 D；历史材料不能满足当前发生的关联。
4. `资源失败` 沿现有 `std::bad_alloc` 资源退避，`前提已变化` 或保护合并冲突沿 `因果读取来源变化信号` 撤回本轮结果并重筹办，`依赖未就绪` 沿现有来源依赖未就绪分支，保留具名阶段。中途停止沿现有可停止读取路径，禁止发布半套候选。任务所有者仍唯一拥有任务身份和候选选择，因果关系依赖沿原接口，S 只进入既有行动请求来源键。
