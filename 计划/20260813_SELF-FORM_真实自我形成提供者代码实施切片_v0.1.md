# SELF-FORM 真实自我形成提供者代码实施切片 v0.1

日期：2026-08-13

状态：待激活

## 1. 目标与门禁

按同名详细设计实现 L5 真实自我五步形成、原请求可恢复收敛、共同截止正式读回和生产接线。依赖 R1、A1、I1、I2、E-ROLE、S-HOST 均真实实施、接受、索引退出并清理临时源码。

S0 必须从最新 `main == origin/main` 核对最终 DTO / 函数、五个 owner 全局幂等保留域、普通应用成员顺序、阶段 14—17、index 和唯一代码段。任何会改变五步语义或无法按原幂等请求收敛的漂移退回计划支撑。

## 2. 允许路径

实施只允许：

1. `海中鱼巣/业务/真实自我形成.数据.h`
2. `海中鱼巣/业务/提供者.真实自我形成.ixx`
3. `海中鱼巣/装配.普通应用.ixx`
4. `海中鱼巣/启动.应用程序.ixx`
5. `海中鱼巣/程序运行结果.数据.h`
6. `海中鱼巣.vcxproj`
7. `海中鱼巣.vcxproj.filters`
8—10. 三份 `验证工具/真实自我形成提供者参数验证` 临时源码
11—12. 两份具名永久施工 / 验证记录。

清理提交只删除第 8—10 条。禁止修改 L1、六服务、I1 / I2、旧自我登记和线程代码。

## 3. 机械实施顺序

1. 实现 DTO、固定项目角色、状态与严格成功形状；
2. S0 扫描后冻结五个两两不同且不命中任何登记保留值的固定业务幂等身份；
3. 实现 provider 构造、发布锁和异请求写前冲突；
4. 每次先经 A1 对 I2 树材料正式复核；
5. 严格按“角色化存在 -> 所在场景 -> 成员 -> 内部世界场景 -> 宿主”五步调用最终 L2；每次重试都从第一步以相同固定请求重放，并从首次 / 精确重复结果重新取得中间身份，禁止依赖 provider 缓存或上次返回值恢复；
6. 每步只接受首次 / 精确重复，失败不回滚、不换键；SELF-FORM 永不调用 E-ROLE / S-HOST 的替换或退出接口；
7. 完成共同当前截止正式读回和全部反例校验后才发布值式材料；
8. 普通应用在 I2 后构造 provider 并增加 getter；
9. 启动调用真实 provider，失败映射阶段 17，成功新增阶段 18 无条件短路；
10. 保持方法、自我线程、概念、投影、信号和宿主不可达。

## 4. 验证矩阵

双配置至少覆盖：正常五步、每步失败后原请求重试收敛、同请求重复重新读回、异请求零新增写、角色竞争、代次漂移、同树拓扑、成员 / 宿主分账、自我非内部世界成员、值式副本、阶段 17 / 18，以及旧 P61/P62、旧完整自我、关系21、旧世界登记和历史状态 / 动态登记零生产引用。

运行根工程 Debug / Release Rebuild、专项双配置、strict、UTF-8 / XML、范围和生产工程隔离。生产代码不包含验证专用实体、接口、分支、计数器、故障钩子或 sleep。真实资源失败注入、恢复、跨进程、方法 / 线程 / 概念维度根初始化、宿主和独立集成验收未运行时记 `NOT_RUN`。

## 5. 发布、清理与完成声明

取得唯一发布租约后精确暂存允许路径并普通推送。交互接受、索引退出后独立删除临时三文件并发布。SELF-FORM 完成最多证明唯一自我、所在场景、内部世界、成员与宿主在生产入口正式形成和读回；阶段 18 仍证明概念维度根生产初始化缺失，不得宣称世界树完整生产闭环已完成。
