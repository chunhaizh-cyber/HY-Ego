## 1. 来源问题与修订结论

执行侧在 v0.1 S0 具名退回两个无法临场裁决的问题：

1. v0.1 把旧全量诊断读取固定为普通生产写入前置，违反 4015/4030 的精确 CRUD 边界；
2. 两个准入请求、规格和结果只有名称与摘要，没有字段、状态、完整性 helper 和构造来源，执行侧会被迫发明公开 DTO。

v0.2 的唯一修订结论为：

- 写前只用现有 `尝试读取中性一致当前投影` 一次复核已知世界、登记、成员、资格和已知端点竞争；
- 不新增 L1 接口，不调用旧全量诊断读取，不声称任意未知候选都不存在；
- 当前可执行性绑定空构造、无恢复导入、关系 21 无其它合法写者和本数据操作唯一发布者四项首跑门禁；
- 在 `L1完整自我.数据.h` 精确实现存在域与场景域共六个 DTO、两组状态、强类型本地角色以及六个完整性 helper；
- v0.1 的 7130 分责、`4/4/(5+N)/4/0`、0x1C、一次提交、正式读回、生产 N=1 和最大边界全部保持。

在 `L1完整自我.数据.h` 按 v0.2 详细设计精确声明：

```text

```

必须实现并只实现以下六个完整性 helper：

```cpp
bool 完整自我存在准入请求有效(const 完整自我存在准入请求&) noexcept;
bool 完整自我存在准入规格完整(const 完整自我存在准入规格&) noexcept;
bool 完整自我存在准入结果完整(const 完整自我存在准入结果&) noexcept;
bool 完整自我场景准入请求有效(const 完整自我场景准入请求&) noexcept;
bool 完整自我场景准入规格完整(const 完整自我场景准入规格&) noexcept;
bool 完整自我场景准入结果完整(const 完整自我场景准入结果&) noexcept;
```

两个结果各自实现 `成功() const noexcept`，其定义必须等价于对应结果完整且状态为已批准。DTO 直接复用正式 `世界结构登记`、`实际存在写入规格`、`实际存在资格事实`、`自我结构关系登记`、`世界结构节点身份见证` 和 `L1中性写集本地键`；不得复制 L1 节点/关系/值/属性槽/读取结果 DTO，不得引入裸键、待分配稳定编码、锁、许可、会话或仓库指针。

存在准入服务为纯值 `const noexcept`，不得保存引用、锁、缓存或可变状态。场景准入服务为纯值 `const`，只因成员 vector 复制允许资源失败；也不得保存引用、锁、缓存或可变状态。

## 6. 写前六组机械合同

数据操作必须按以下内容形成一个 `L1中性一致当前读取请求`：

| 组 | 内容 |
| --- | --- |
| 节点 | 世界根、三个服务、五个类型、全部出生期成员 |
| 关系 | 空 |
| 值 | 全部成员资格值编码 |
| 属性值 | 世界根场景标记、全部成员资格 |
| 源关系组 | 世界根及每个成员分别与自我结构关系类型组合 |
| 目标关系组 | 世界根及每个成员分别与自我结构关系类型组合 |

节点、值和组合键按稳定编码升序形成；业务上必须互异的身份若碰撞则不进入 L1。成功时节点/值/属性逐字段匹配上游正式事实，全部源/目标组为空。组非空只证明已知端点竞争，返回内部不一致；不得解释为已枚举全仓。

不得为了填充空的 `关系` 组伪造待分配编码。不得以世界根源父关系组扫描整个场景树。不得按返回节点继续递归扩展查询。写前 L1 调用精确一次。
