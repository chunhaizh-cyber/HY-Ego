# LEARNING-END-NOTICE 学习结束通知与运行异常分离

版本：v0.1

日期：2026-10-11

基线：`216cc8a38fe4fecb80c2e041c02da1fcde598d6d`，main与origin/main一致、index空。本文发布并登记精确blob后才可施工。

## 1. 最新语义和完成边界

用户明确：学习没有成功失败，学到什么是什么；学习函数只返回“学习结束”，方法知识保存在方法树。取消、资源及内部错误是运行工程异常，不能再伪装为学习结果。此裁决替代此前对外返回已形成知识/重复/输入不支持/样例失败等学习状态的合同。

正常新增知识、精确重复、合法同条件异结果冲突未写新知识，以及有效抽象本能方法暂无模拟适配，均返回同一种结束通知。是否有知识、具体条件结果及命中等只能读取方法树，不从通知判断。方法owner的发布/重复/冲突等内部结构操作状态保留，不属于对外学习判断。

当前结算单点模拟、原本能执行、同条件冲突零写、不自动扩域、旧配对及副本不变、模拟命中不增均保持。self仍只自动发现头空方法，不新增自主续学、轮询或失败重试。manager不以通知推进任务；私有域消费、实例刷新和实际计数不在范围。

本叶不增加本能改变目标。原函数仍只改变模拟世界服务值以取得学习材料，现实世界及任务Vt不变。

依据：[0050](../规范/0050_项目通用机器逻辑与禁止性规则总纲_20260721.md)、[方法治理](../规范/5350_子规范_方法治理详细合同.md)、[本能执行](../规范/5360_子规范_方法函数登记执行与任务反馈.md)、[代码归属](../规范/代码文件建立归属与模块命名规范.md)、[日志规范](../规范/日志系统规范.md)及当前用户具名裁决。不修改正式规范。前叶实际工程长期模式5继续复用，不新增工程。

## 2. 当前事实、复用及允许范围

服务当前`noexcept`返回`新模拟学习结果`，其中混合知识结论、场景/配对ID、取消和工程异常。worker依赖所有返回均为值，外层异常会停止整个worker；self对ready future直接get，异常会落入self大循环外层。manager以非空配对和命中0核验学习成功。因此必须同叶迁移服务、future生产/消费及通知，不仅改DTO。

方法owner已有完整新增/重复/冲突和发布未知合同，无需修改。模拟算法会捕获求值回调异常，所以服务必须保留回调异常再重抛，不能在算法返回求值失败后丢失取消/资源原因。知识库仍待重建，当前事实直接回读头源与前叶验证记录。

## 3. 唯一对外通知及工程异常

`业务/模拟学习.服务.h`删除旧`新模拟学习状态`、`新模拟学习结果`，不保留兼容别名。声明以下纯值通知和异常类型；异常方法定义在同cpp，不新建文件：

```cpp
struct 新学习结束通知 final {
    稳定编码 方法节点;
};
enum class 新学习运行异常原因 : std::uint8_t {
    停止取消=1, 输入不合法, 资源不足, 结构不一致,
    本能运行异常, 发布结果未知, 内部错误
};
struct 新学习运行异常记录 final {
    稳定编码 方法节点;
    新学习运行异常原因 原因=新学习运行异常原因::内部错误;
};
class 新学习运行异常 final : public std::exception {
public:
    新学习运行异常(稳定编码 方法节点, 新学习运行异常原因 原因) noexcept;
    const 新学习运行异常记录& 记录() const noexcept;
    const char* what() const noexcept override;
private:
    新学习运行异常记录 记录_;
};
新学习结束通知 模拟学习服务::学习(
    稳定编码 方法节点, const std::function<bool()>& 停止检查={});
```

通知只有方法ID，无状态、配对/场景ID、知识数量、成功标志。异常记录也只有方法ID和工程原因，不塞知识载荷；what返回与原因对应的静态英文诊断文本，不分配字符串。异常类构造/读取/what不抛。服务`学习`去掉noexcept，构造仍noexcept。

## 4. 同步服务精确分支

### 4.1 正常结束

1. 方法完整可读、是启用抽象本能、具备登记名，但没有本叶支持的模拟适配（非服务结算登记名）：直接返回`{方法节点}`，无样例/配对写入。不能去租外设或现实端口。
2. 支持结算且材料有效：保持每次实际生成fresh样例、调用原函数、fresh读回、按本次C/R交owner。新增或重复均按现有ID校验方法树，正常后仅返回`{方法节点}`。
3. 合法同条件异结果冲突：owner零配对写入，保留既有知识与已发表模拟材料；核验返回已有配对身份和同条件异结果事实后正常返回`{方法节点}`。不将其包装成学习失败，也不为满足结束通知而覆盖或扩大旧结果域。没有新增知识是允许的正常结束。

### 4.2 工程异常

| 来源 | 处理 |
| --- | --- |
| 无效方法ID、误投副本/实例/组合/停用对象 | 抛输入不合法；尚未作模拟或知识写入 |
| 获取方法为空（现接口不能区分缺失与内部读取失败） | 抛结构不一致；不得解释为无知识正常结束 |
| 已支持结算的登记身份不符、登记材料缺失、规格/类型/值域/方向不合法、负值/MAX或本叶不支持的登记输入形状 | 抛输入不合法或结构不一致：值/规格不支持为输入不合法，正式身份/字段缺失或不相容为结构不一致 |
| 停止检查返回true | 抛停止取消；已产生的合法样例保留；不制造正常结束通知 |
| 停止检查本身抛异常 | bad_alloc映射资源不足，其它映射内部错误，不再当作用户停止 |
| 直接bad_alloc或提供者明确资源失败 | 抛资源不足；不从含糊空optional推断资源失败 |
| 原本能运行非合同返回、样例动作/状态/动态不全或输出不符 | 本能本次运行状态错误→本能运行异常；正式物理读回不一致→结构不一致 |
| owner明确发布前非法/结构错误/资源失败 | 分别映射输入不合法/结构不一致/资源不足 |
| owner返回发布结果未知，或本次已发布以后读回/返回载荷无法确认 | 抛发布结果未知，保留已发表知识，禁止自动重试 |
| 未分类异常 | 抛内部错误；若本次已发布则抛发布结果未知 |

服务外层先`catch(const 新学习运行异常&) { throw; }`，防止自身typed异常被重新映射；然后处理bad_alloc和未知异常。发布进度必须在owner返回后、任何可能抛出的载荷处理前确定；已发表后不再执行停止检查，不能将已发表结果改报取消。

求值回调内捕获typed/标准异常，以局部`std::exception_ptr 求值异常`保存，再向算法返回求值失败；算法推进后若该exception_ptr非空先rethrow，再解释算法状态。取消、资源或内部错误不能被算法自身catch降成普通“学不到”。不修改算法ABI，不把exception_ptr放进通知或持久数据。

服务调用方直接catch异常或让worker保存；服务不写工程日志。所有owner原有状态仍为内部结构合同，禁止用对外结束通知替代必要的发布读回/真实性核验。

## 5. 学习worker：每工作异常与线程异常分离

`新学习接收结果::处理结果`改为`std::shared_future<新学习结束通知>`；内部promise同类型。保留既有启动/接收/去重/确认/停止操作枚举，它们只表示线程工程操作，不表达学习成功失败。去重一直持续到结果或异常被接收者确认。

每工作调用服务必须有局部try/catch：

- 正常返回：promise.set_value(通知)。
- 服务抛异常：promise.set_exception(std::current_exception())，不得逃至worker最外层导致其它工作停止。
- 两条路径都标已完成，清当前方法，先让future就绪，再锁外通知self；异常工作也能确认并释放去重项。通知回调异常继续隔离，不能改变已经就绪的future。

排队停止：每个未执行工作promise设置typed停止取消异常；活动工作在原有安全检查点观察停止；本能运行中不强杀，已发表后仍正常结束。不得set_value一个带取消状态的假结束通知。

停止收口不能再对全部future无保护get以打印状态；删除该读取或只依据已经持有的工程取消事实记录。worker最外层异常只代表线程调度/承诺不变量等设施故障：在安全锁下使所有未完成promise以同一exception_ptr异常就绪，停止接收、唤醒消费者后退出。合法每工作异常不修改生命周期为内部错误。

构造、销毁、join、回调weak桥寿命和不能等待自身保持。不新增后台轮询、detach、重试或知识缓存。promise只由worker单次履行；future_error表示程序不变量破损，不吞掉后继续假装该工作已完成。

## 6. self消费及manager通知

### 6.1 self

在途map改为shared_future新通知。快照字段及内部成员统一改名：

```cpp
std::optional<新学习结束通知> 最近学习结束;
bool 学习结束已交接管理=false;
std::optional<新学习运行异常记录> 最近学习运行异常;
```

不为旧字段保留别名。最近正常结束和最近工程异常是各自最后一次观察，可同时存在，不以其中为空判断另一项成功。

ready future消费要移出self状态锁后局部get/catch，禁止异常逃到self主循环外层。正常通知必须方法ID与在途key一致，然后保存最近学习结束、向manager提交结束通知；不检查通知中不存在的知识状态。typed异常提取工程原因并核验方法身份；bad_alloc映射资源不足，future_error/其它异常映射内部错误。异常只保存最近学习运行异常，不发送结束消息、不建需求、不改任务、不停止self消息线程、不自动重投。

正常/异常两条收口都将方法标为本生命周期已处理并调用worker确认接收，确认已完成/无变化后清在途。准备完成标记等可能分配的运行资源在提交工作前分配：可在提交槽成功时一并插入本生命周期已处理集合，提交后的正常/异常收口不再分配该集合。去重同时检查在途和已处理集合，不增加自动重试。

为避免确认失败重复get或忙循环，在self cpp私有定义占用`{shared_future<新学习结束通知> 处理结果; bool 已消费=false;}`替代在途map值；选择ready工作和等待谓词必须跳过已消费项。在局部get前标已消费，正常/异常均只消费一次。确认失败记录工程异常，保留已消费占用及方法ID至self停止析构，既不丢身份也不自动重发；worker析构最终释放已完成占用。快照待学习数量只计未消费项，不把工程回收现场当正在学习。不得新增对外知识状态或学习成功失败补丁。

提交工作本身被拒绝、资源不足或未启动也记录工程异常（分别输入不合法/资源不足/内部错误），不伪造结束通知。保持原先无自动重试策略。

### 6.2 manager

入口改名为`bool 提交方法学习结束(const 新学习结束通知&) noexcept`，原入口删除。邮箱按方法ID去重，内容仅通知。`绑定方法学习读取`、启动/停止门保持。

快照`最近方法学习结果`改`std::optional<新学习结束通知> 最近方法学习结束`，新增`std::optional<新学习运行异常记录> 最近学习运行异常`用于正式读回异常，不放任何学习知识结论。

消费消息必须锁外从方法owner完整fresh读方法。方法存在且为正确抽象本能即可记录结束通知；**0个CR和非零命中均不能成为拒绝结束的门**。方法不可读/身份结构不符另记录工程异常，不把通知判为学习失败。既有`等待方法实例消费`仅表示fresh方法有配对而等待后继消费：以该次读取是否有CR更新该布尔投影，不能作为接收/记录通知条件或任务执行许可。

manager不从消息取配对ID、不依赖单配对/命中0，不清任务阻塞、不改任务状态/副本、不重筹办。知识细节只在确有需求时调用方法owner，不新增第二方法知识账。

## 7. 日志职责

读取并遵守LOG-01，不修改规范。worker正常仅记录方法ID、接收/开始/结束等人读运行观察；服务不输出同链异常。self是其异步工作运行异常最终责任边界：停止取消记录运行观察，资源/输入/结构/内部异常记录一次逻辑错误；manager只记录自身读方法错误一次。合法无适配、重复和知识冲突正常结束，不输出逻辑错误。

日志全部锁外、忽略日志返回；不为日志新增查询或写事实。新日志不输出“学习成功/失败”、结果状态、配对/样例载荷；manager已持有方法快照可克制输出知识数量作人读观察，但不能以文本或输出成功判定学习结果。日志异常不可替代future异常传播，也不可改变线程继续或通知。

## 8. 实际工程验证

扩展现有模式5，不增加项目/入口/诊断后门。实际根工程VS18 MSBuild `/t:Build /p:Configuration=Debug /p:Platform=x64 /m:2`。独占输出`D:/TEMP/海中鱼巣/LEARNING-END-NOTICE/20261011-v0.1/Debug/`下bin/obj；保存实际输入、命令、退出码和NOT_RUN。

最低矩阵：

1. 新知识、再次实际模拟重复、同条件冲突及有效无适配方法均只返回同形方法ID通知；新/旧知识、命中与旧副本通过方法树读取验证。原每次实际重跑测试继续用登记读次数及合法模拟根新增关系/样例独立入口验证，不恢复通知载荷。
2. 无适配方法CR可为空；正常结束不调用现实端口、不发外设。冲突方法通过正式owner材料构造，运行后旧知识不变、返回结束，不能恢复冲突学习状态。
3. 无效/误投输入、结算错配、取消true、停止检查抛出分别catch精确typed原因；bad_alloc或内部错误若可通过已有停止检查/材料回调合法触发则检查精确传播，不造生产注入接口。明确停止检查自身抛bad_alloc视资源不足，其它抛内部错误。
4. worker已接收工作的服务异常从future.get抛出，仍唤醒、可确认释放；该异常后另一有效工作仍可执行。停止中活动及排队future都ready，get抛停止取消；异常不导致所有工作被学习失败封停。
5. 回调异常不破坏已返回通知或异常future；停止/join不因内部get重抛卡死。结果确认前重复共用future，确认后允许新请求。
6. manager接受零CR方法的结束通知并记录，等待实例消费为false；有CR时fresh读回并记录，零任务推进。取消/服务异常不向manager伪送结束通知。
7. self局部catch/确认释放/继续主循环进行静态逐分支检查；实际普通主入口启动应观察正常结束通知→manager读树及受控退出。工程异常穿越真实self若无合法公开触发入口列NOT_RUN，不以worker测试冒充self注入实测，不加测试后门。

模式3/4回归，模式5全通过退出0，重复/混合参数拒绝保持。物理发布未知/坏结构和真实资源不足无公开触发的分支静态核对、NOT_RUN。Release/Win32/恢复未跑不声明。生产主入口观察不是独立黑盒集成验收。

日志失败静态检查不参与返回/线程门；已有回调可抛路径验证观察失败不改变future。未实际注入日志设施失败时明确NOT_RUN，不能以吞catch证明已实测。

`git diff --check`、cached检查、旧DTO/状态/入口全量调用点检索必做；只剩历史文档可保留旧名称，生产源不得有旧学习状态分支。专属记录给出函数用途、调用边增量和证据层；不把方法owner内部发布状态列为违规。
