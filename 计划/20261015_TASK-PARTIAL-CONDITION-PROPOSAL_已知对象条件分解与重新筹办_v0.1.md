# TASK-PARTIAL-CONDITION-PROPOSAL：已知对象条件分解与重新筹办

版本：v0.1。代码事实基线：`2786984e624cca20bbba23f78b0ed92099014699`。执行状态只读[计划索引](计划索引.md)。本文件是独立施工合同，不证明代码已经实现。

## 1. 目标与边界

用户已授权的链为：本能方法声明必要条件 → 通用筹办报告缺口 → manager 独立读回并交 self → self 建立或复用正式子需求 → 子任务改变正式信息 → 父任务重新读取条件。此叶闭合其中“某些参数尚缺，但已能唯一证明适用结果分支时，先为已知真实对象的可行动条件建立子需求”的通用能力。

不修改本能函数的定义、方法头能力或 C/R 知识，不执行本能动作。改变的是任务筹办治理及其临时材料：目的是避免一个未知角色遮蔽同分支中已经明确的真实 E/F 条件，不是宣布父方法可以执行。子需求仍是既有真实存在/场景上的单 FT 值域目标。

用户本轮补充裁决：方法条件节点 C 保存完整条件信息。“部分”只指实际对象绑定和满足情况，不指条件知识残缺。筹办必须完整读取同一个正式 C；任务组织保存其完整来源定义，Vm参数规格只辅助对象定位和合法参数形状，不成为独立的第二份条件真相，不新增或重定义C中的业务条件。完整源读取失败/结构缺项属于工程问题，不能记成未解析业务条件。既有线性反求只形成任务所需输入域，不改变M原始C/R。

明确排除：未知对象的占位存在、任务 Vt 目标需求、自动选择结算来源、既有未完成任务等待依赖、新增集合成员的完整动态目标、获取服务需求方法直接增加任务数、复杂方法步骤/分支运行、学习、任何业务定义或初始化改动。服务任务集合非空不等于有真实人类服务要求；此叶不宣称获得服务需求或结算业务闭环。

完成条件：W2 对唯一可证明分支产生部分条件提议；manager/self 各自 fresh 复算；self 通过既有正式 D owner 幂等建立/复用 D，manager 承接一 D 一 T；方向链能够依据同一模型分支验证已知子目标；部分子目标完成或材料变化只触发 fresh W2，不越过父任务完整参数、完整条件、结果途径与执行前门。

### 3.1 新筹办证据（定义在 `新_任务类.h`）

新增以下值式结构，所有字段提供默认相等比较。结构不持久化、不产生新稳定编码、不带执行权限。

```cpp
struct 新任务条件分解依据 final {
    新任务本能采用定位 定位; // 只复用组织/作用域/配对要求定位，不复用采用材料
    稳定编码 来源方法节点, 来源配对节点, 来源条件节点, 来源结果节点;
    std::vector<新方法参数规格> 参数要求组;
    新方法条件定义 原始条件, 需要条件;
    新方法结果定义 结果;
    std::vector<新方法条件结果线性关系> 线性关系组;
    std::vector<新方法参数角色绑定> 已知参数绑定组;
    std::vector<std::uint64_t> 未解析条件序号组;
    bool 保证满足目标 = false;
    std::optional<std::int64_t> 有利结果端点;
};

enum class 新任务条件分解状态 : std::uint8_t {
    已确定 = 1, 等待材料, 匹配不唯一, 无适用分支,
    目标已满足, 任务状态已变化, 实例未建立, 幅度材料不足,
    结果定义暂不支持, 结构不一致, 资源失败
};
struct 新任务条件分解结果 final {
    新任务条件分解状态 状态 = 新任务条件分解状态::结构不一致;
    std::optional<新任务条件分解依据> 依据;
};
```

`新任务条件子需求提议`增加 `std::optional<新任务条件分解依据> 分解依据`。原 `全部条件项组`更名为 `已知条件项组`，含本次能够准确投影的全部已知真实 E/F 条件（包括当前已满足项）；完整要求保留在依据中，不能把部分列表伪称全部。原 `本能采用`字段为兼容现有消费者暂保留，但本入口新提议始终为空，消费者不得要求它存在。其它重复 M/C/R/绑定字段必须是依据的精确投影，矛盾作为工程错误，不能两份独立解释。

`新任务条件子需求就绪结果`的字段和语义不放宽。`全部需求已满足`只说传入子 D 的现状；`已就绪`仍要求父 `选择任务方法结果`返回完整 `已选定`。

另新增任务 owner 只读身份入口，不把父方法整体就绪当成已发布 D 的身份条件：

```cpp
enum class 新任务已发布条件子需求核验状态 : std::uint8_t {
    身份一致 = 1, 任务状态已变化, 材料已变化, 结构不一致, 资源失败
};
新任务已发布条件子需求核验状态 复核已发布条件子需求身份(
    稳定编码 父任务节点, const 新任务已确认条件子需求& 子需求) const noexcept;
```

声明在 `新_任务类.h` public，定义在同类 `.cpp`；允许 manager/self 的既有子需求交接调用。复用原就绪函数中的父 D/T 唯一关联、子 D 父链/来源T、E/FT/domain、条件包含比较和冻结域投影检查，再核验实际 F 仍属于该 E、FT及单位一致。父T终结或父/子D失活返回任务状态已变化；已有子T终结不影响其身份读回，不能据此重新启用。合法来源概念投影或F身份改变返回材料已变化；错误来源关系/错误身份返回结构不一致；资源失败独立返回，异常走工程终止。此函数不要求当前值满足、不要求父分支仍有效、不查父完整参数、不产生 D/T；原就绪函数可委托它后继续当前满足和严格选择。所有非身份一致均不得当成已发布合法前缀放行。

### 3.2 私有函数及复用

在 `新_任务类` private 声明、同类 `.cpp` 实现：

```cpp
新任务条件分解结果 选择任务结果分支内部(
    稳定编码 任务节点, bool 允许部分条件绑定) const noexcept;
```

唯一调用者：`选择任务方法结果`（false）、`提议任务条件子需求`（true）、`判断父子需求方向一致`（true）。不公开新执行 API。抽取现有结果兼容/排序/反求代码到此函数，严格选择在其结果上继续原完整绑定、固定采用 fresh 核验和执行门。true/false 只决定能否为筹办保留未解条件，不改变排序、结果语义、源定义读取、目标新鲜性或工程错误行为。

严格 public 状态无损映射：`等待材料→等待条件`、`无适用分支→无适用结果`；`匹配不唯一/目标已满足/任务状态已变化/实例未建立/幅度材料不足/结果定义暂不支持/结构不一致/资源失败`逐项同名映射，不合并为泛化等待。`已确定`只进入原完整采用与固定条件复核，之后才按原结果返回`已选定`或`等待条件`，不能直接映射为可执行。提议端按原提议状态独立映射：等待材料/实例未建立/幅度材料不足为材料未到，匹配不唯一/无适用分支/结果定义暂不支持为暂不支持，目标已满足为来源已变化，任务状态/结构/资源状态保留各自同名对应；未确定依据时不形成子项。不得为了消息兼容改变严格选择的公开状态区分。

现有 `任务执行组织存储::计算采用需要条件`的纯计算部分在原 `.cpp` 命名空间内提取为接受原条件、结果、线性关系、D及现有 owner 的普通辅助函数；原采用包装委托它，分解路径直接调用它。不得通过构造不完整 `新任务本能采用材料`复用计算。细小辅助函数保持文件内可见，不建立新领域模块。

## 4. 分支、绑定与条件投影算法

1. Fresh 读取 T/D、当前目标 F、当前任务执行组织及所有根方法候选；保持服务要求确认守卫、状态和存在身份约束。只支持当前本能根作用域，不处理复杂方法。源读取异常/不可能结构进入工程诊断终止，不包装成缺少业务条件。
2. false 模式保持原全部候选参数完整门。true 模式建立仅供筹办的角色视图：先取既有合格绑定；没有时只在同角色 `条件值不满足`缺口中取唯一真实对象的已知绑定，按 E/场景/F引用去重并核对规格。不可从多候选中挑一个，不用“参数特征值未取得”冒充准确值，不接受未知对象、缺特征或冲突的猜测。一个缺口可带其它角色的集合约束材料，必须按角色过滤，不能整组塞入该角色。
3. 对每个根候选的每个 C/R，用当前选择相同结果规则核对目标 E、FT、单位、值域/方向及线性关系。目标结果角色必须已唯一定位到父 D 的真实目标。任何可能竞争的目标结果角色尚不能唯一定位、关系未支持或幅度未定，保持原保守等待/暂不支持规则；不能因该候选条件难筹办就跳过它选择次优。已证明目标 FT/对象不相关的候选可排除。
4. 复用保证满足优先、否则同向最大有利端点及唯一最佳规则。零分支不提议，多最优分支不提议，不选择首个或默认分支。将唯一分支原条件按同一模型反求为 `需要条件`；原始 C/R 和线性关系不改写。完整参数规格保留，包括其它未找到角色。
5. 仅当需要条件关系为单项或全部成立时逐项投影。已知真实对象、唯一正式 FT/F、准确当前值、单位一致，且条件域可由既有 I64/任务集合比较消费时，进入 `已知条件项组`；其余业务未知或本叶未实现形状保留条件序号于 `未解析条件序号组`。不能为了生成目标伪造 F、准确值、集合成员、Vt身份或缺失观察事实。工程不一致不得当成未解析。
6. 对已知项调用现有 FT owner 比较；未满足项形成子需求目标。保留当前同 E/FT I64 交集、集合必含成员并集及至少一项约束的合并、单位检查、祖先等价目标循环检查。此处只消费已存在的集合目标语义，不定义新成员动态。`已知条件项组`记录稳定来源投影，`子需求项组`只含本次实际未满足目标。
7. 有子项即 `已形成`，即使还有未解析条件；无子项且仍有未解析条件为 `材料未到`，保留依据和已知投影；无子项且无未解析为 `无需子需求`。已形成/无需子需求/材料未到均不代表可执行。其它拒绝清空待发布子项，保留诊断不产生 D。

## 5. W2、self、方向链和重新筹办

### 5.1 消息与发布

W2仍只返回材料；manager 调用同一 `提议任务条件子需求(T)` fresh 独立复算，完整提议相等后才发送既有消息。self 再调用同函数，不信任消息中的结论。self 的来源等价比较包含 T/D目标、组织/作用域/配对定位、全规格/原始C/需要C/R/线性、已知角色和已知条件投影，不比较瞬时满足状态或未满足子项列表。可接受带有效同源依据的“已形成/无需子需求/材料未到”；逐目标重新判断还需不需要发布。

未解析序号变化、已知绑定变化、结果模型或竞争分支变化不能被忽略；self 收口为来源过期并保留已发布前缀，等 manager fresh W2。每次发布前重读；旧 D/T 不删除。仍用现行 D父链+来源T+目标精确语义查重与复用，一个 D 一个 T。不能因新 W2 重复发布同目标。

manager 收取回执和实际承接子D的两处入口分别执行身份核验，不能仅修改收取而保留实际承接对父完整就绪的依赖。若 fresh父分支与原分解依据同源，维持既有 `承接已确认条件子需求`。若父分支已经过期，但 `复核已发布条件子需求身份`仍为身份一致，对该前缀只调用既有 `建立需求任务关联(D)`：新T保持原建立状态/等待条件、既有T只读回而不重新启用，不发送执行许可；精确读回D-T后计该项交接已收口，再触发父fresh W2。即使旧整体就绪返回来源已变化/材料未到，也不能据此拒绝合法前缀；但绝不把这些状态整体视作通过，D/来源/FT/F/冻结域错误仍由独立身份核验拒绝。后续执行始终须fresh方向和执行门。

### 5.2 方向链

`判断父子需求方向一致`不再把“父/中间子任务完整参数尚未就绪”作为模型方向判定的必要条件。父、子两侧都 fresh 调用同一结果分支内核 true，取得唯一兼容分支；不可读取旧提议直接授权。

父侧要求子 D 的来源T、父D和真实 E/FT目标精确对应父分支的一个已知需要条件；沿用正式值域包含、同 E/FT 合并语义及概念约束。子侧要求其唯一结果分支满足或沿目标方向推进子 D，沿用方向相反、模型矛盾和未知结果的拒绝规则。全链继续逐级核验，不能跳过祖先。只返回既有方向一致性结果及明确 M/C/R证据，不填执行采用、不建立参数场景、不改任务状态。真正准备执行的任务仍由原 public严格选择、self执行前判断和本能入口 fresh 条件核验保障；中间父尚缺条件不因方向证明变为就绪。

### 5.3 旧回执与增量 fresh W2

manager `尝试复核条件子需求`在现有调度/条件复核事件及节流下，锁外同时读取旧子D现状、父完整就绪结果以及新的条件提议。记录保存原W2定位和原提议作为比较基线，比较实际值式结构，不新增事实代次或泛化轮次。

满足以下任一情况可以请求新的 W2：父严格选择已经完整就绪；fresh提议的分支依据/已知投影/可行动未满足目标组相对旧提议变化；self返回来源过期。仅子任务报告完成不够，必须 fresh读取真实信息。没有变化继续等待，不每轮重建子任务。变化后允许仍未齐备，但本次操作仅恢复筹办，不能直接执行父方法。

释放前重新加锁验证精确原W2、原裁决和全部子任务承接回执均已收口；不得有活动工作、执行保护、学习或等待复核占用、待排空结算来源。只清该原W2的待反馈/旧筹办/旧裁决/筹办软阻塞，保留所有正式 D/T、X、独立读回/执行保护及其它阻塞。T保持待检查条件，原调度产生新W2。来源过期不得与拒绝/结构错误合并为永久 `条件交接失败`；源过期且有已发布前缀先完成其既有承接再刷新。真正回执身份冲突、非法D或工程错误仍停止受影响操作，不无限重试。
