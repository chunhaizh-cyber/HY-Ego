## 2. 名称结构恢复

1. 普通未绑定冷建在 `概念_名称关系类::初始化()` 的原互斥内，紧接 `结构仍存在()` 成功后，以 `发表基础结构自键` 一组发表以下五个独立技术节点的角色。发表失败按原初始化失败返回，成功才继续原 `准备名称核验全集`。固定串由 `HY-Ego/2210/名称关系结构/`、下列源符号名和 `/v1` 拼接，顺序为 `节点类型字段、名称关系根类型、名称关系节点类型、被命名概念字段、目标词条字段`。这些角色当前由构造语句赋予，持久图中无法普遍从使用次序、关系存在或编码推知。名称根已可从类型和父边辨明。保持名称根仅一项原类型字段，普通关系项仍为原有三项字段。沿既有自键技术字段容纳角色标记，不增加根、词条、概念或关系的业务身份或字段。
2. `初始化指代名称结构()` 已对上述五个节点逐一检查空字段。将这一处改为校验该节点唯一字段正是其精确自键。指代使用的角色、语言、来源三字段键及现有空字段合同照旧。在已绑定会话，旧 `初始化()` 只允许本实例恢复已就绪返回 `true`，`初始化指代名称结构()` 返回 `依赖缺失` 并在进入旧创建分支前退出。将 `结构句柄完整() noexcept` 的固定键组改成 `std::array`，消除分配失败穿透 `noexcept` 的入口。
3. 在名称 owner 增加公开 `基础持久状态 恢复当前权威(const 基础持久视图&) noexcept` 和析构。由普通启动候选的实际名称实例调用。按既有会话身份守卫自键读回，用 `视图.结构().查询目标字段(名称关系根类型, 节点类型字段)` 定位唯一根。验证登记确为根本身的唯一类型字段，根的唯一外边入向是语言 owner 已恢复的 `自然语言组织根节点 → 名称关系根节点` 角色 0 父子边，两个端点的结构相符。技术键身份、根、语言组织根互异。技术节点须存在且各只有其声明的精确自键字段。此阶段只核原结构锚，根的全部成员边由下一节现有定向读统一核验一次。缺自键或根缺项映射 `材料不完整`，复义或形状错映射 `结构冲突`，底座资源失败和 `bad_alloc`、`length_error` 映射 `资源失败`。
4. 所有候选键和根留局部。在 `概念名称关系互斥` 内确认键组、根、指代键及待核验键均为空，且没有恢复所有者，同会话的当前视图仍为入参，才一起赋给原全局锚并登记本实例。重复或其它 owner 进入返回 `入口拒绝`。析构只清理本实例安装的五键、名称根和本实例恢复所有者标记。旧非持久实例析构不清理这些锚。暖恢复无事实写入，无持久索引。

## 3. 同一视图独立读回 W、N、H

1. 名称类头文件追加 `持久普通名称候选` 值式结果项，含 `概念名称关系信息 关系` 和 `std::optional<存在概念种类> 存在种类`。新增公开 `std::pair<基础持久状态, std::vector<持久普通名称候选>> 读取当前权威普通名称候选(const 基础持久视图&, 稳定编码 词条) const noexcept`。仅供普通暖启动以已被词条 owner 精确核同的稳定编码调用。候选按关系编码升序并保留该词条的全部普通候选。`存在种类` 为空只表示本次存在 owner 已辨明该目标无普通存在概念类型标记。此窄口交付普通名称结构及普通存在端点证明，原混合名称公开口继续承担全面正式语义核验。
2. 在 `概念名称关系互斥` 内验证恢复所有权，然后复用 `读取名称原始全集` 的指定词条、保护读取分支。给现有私有函数增加可选 `const 基础持久视图* 恢复视图 = nullptr`，普通路径沿全局数据集，暖启动传入指定视图。暖分支的首读、反查与联合读全部使用该视图的 `结构()`，同视图已读的根、W 快照直接参与核验。保留一次根成员遍历、按 `目标词条字段` 反查与 W 快照实有入向字段互证、关系三字段严格解码和类型检查。N 须有唯一角色 0 根父边和两个各恰一的有效端点引用，无其它入边和出边。同一 `(C,W)` 重复为 `结构冲突`。原始结果增加默认关闭的 `命中未恢复的指代结构` 标志，仅在暖分支遇定向候选具有六字段形状时设置，名称恢复读口在处理原状态前将其映射为 `格式不支持`，并清空候选。其它词条的指代关系不参与解码。资源和结构失败沿状态返回，禁止进入 `核名称原始保护状态` 的工程终止路径。
3. 释放名称锁后，将本次同序 `(C,N)` 交存在 owner。沿用现有 `friend class 概念_名称关系类`，在存在概念类头源私有区新增 `std::pair<基础持久状态, std::vector<std::optional<存在概念种类>>> 核验当前权威普通名称端点(const 基础持久视图&, std::span<const std::pair<稳定编码, 稳定编码>> 端点组) const noexcept`。输入每项先 C 后 N。存在 owner 验证绑定身份，使用自身已恢复的键，在同一批联合读取得各个 C 和一份存在概念图根快照，核对每个回执身份。只有同时缺少普通存在类型标记与本图根角色 1 挂接的真实 C 才返回空种类。有本图根角色 1 挂接而类型字段缺失、错误或重复，或有普通类型标记而无合法组织边，均为 `结构冲突`。普通 C 必须确有唯一一条来自本图根的角色 1 组织父边，与图根出向边互证。存在 owner 的名称关系字段必须恰好一次引用 N。抽象 C 不得有对应实际存在字段。专属 C 必须有唯一有效且存在的对应实际存在引用。缺根、端点缺失、错误边、反向持有缺失或复重为 `结构冲突`，底层资源错误保留为 `资源失败`。成功返回与输入同序且等长的种类组。此步不调用整树定义读取、归类或跨 owner 值域判断。
4. 全部核完且名称恢复所有权仍成立、会话当前视图仍等于入参，方返回候选。任何失败返回空候选，返回前视图变化优先。原始读取状态 `资源失败` 原样上送，定向读前视图未变且原始读取非成功时，除本节明确的 `格式不支持` 外映射 `结构冲突`。捕获 `bad_alloc` 和 `length_error` 为 `资源失败`，其余异常为 `结构冲突`。精确词条入口未找到 W 沿原语言词条阶段返回 `材料不完整`，定向读取成功而无普通名称候选则交装配判 `材料不完整`。同视图已经证明的 W 或已引用端点在结构上缺失属于 `结构冲突`。
5. `恢复普通应用基础事实` 将已复核的中文节点和 W 保存在未发布的普通应用候选，紧接原语言词条阶段调用实际名称 owner 的两个入口。从全部返回项仅以存在 owner 证明的抽象类型选择 H，零项 `材料不完整`、多项 `结构冲突`。按 W-反查、N-正向两字段和 H-反向持有独立互证后保存原 `中文语言节点、人类词条、人类名称关系、人类存在概念节点`。禁止按编码最小、显示名或特征值补选。在当前视图仍一致且该阶段成功后才将应用候选移动到现有 `上下文`。失败依现有候选析构清理，不将部分身份交下游。
6. 在 `普通应用恢复基础事实结果` 尾部增加 `基础持久状态 名称与人类 = 基础持久状态::入口拒绝`，在 `程序失败阶段` 尾部增加 `持久名称与人类复核失败 = 36`。`启动.应用程序.cpp` 在现有语言词条分支后映射该状态，全部通过才继续返回现有阶段 31。旧快照缺五键时保持原字节并拒绝本阶段。保留现行全局磁盘准入及首份保存流程，不补写暖库，不宣称普通世界、本能或线程可运行。
