## 4. 实施步骤

1. 从索引绑定的最新正式 HEAD 重做 S0，核对前两份需求 BIZ 结果、目标状态合同、DATA-EXT-12 最终 ABI、目标文件和资源。
2. 新建活动子关系值式合同头，复用上一叶父关系 / 父端点 DTO，逐字段机械使用最终强类型。
3. 扩展同一 `需求业务服务`构造，复用唯一 DATA-EXT-12 const 借用并保存第三份不可变操作配置；三配置共同字段及两个需求树规则版本必须一致。
4. 实现固定配置、请求和版本匹配三层调用前校验；坏合同、空 / 重复父链、零预算均零 DATA 调用；运行代次只在 BIZ 固定配置中匹配，不进入 DATA 请求。
5. 一次按父链、G0、范围 / 规则版本和单一当前子关系总数量预算读取逐父全部当前直接子关系及活动材料组，精确映射提供者状态；同 G0 父未找到 / 已退出收敛为内部不一致。
6. 互证请求回显、版本、预算、G0、零变更、逐父一一对应和完整父端点。
7. 逐项互证父子关系、完整子端点、路径角色、已发布活动结论、来源、生命周期、版本、G0、排序、唯一和全部当前直接子关系 checked 累计总数量；只按强类型活动结论选择，合法非活动项确定性排除但仍计入总预算，不重判活动。
8. 完整候选形成后无抛出交换发布；任一或全部父空组仍返回已读取。
9. 唯一登记生产头，运行计划矩阵并形成两份记录。
10. 只提交本计划白名单并普通推送；退出登记和临时专项清理由后续独立提交完成。

## 5. 失败收口

- 固定配置坏、请求坏、版本不等分别映射内部不一致、请求拒绝、当前性漂移；均零 DATA 调用。
- 同 G0 父未找到 / 已退出收敛为内部不一致；预算不足、许可、漂移、资源和内部错误精确分账；全部非成功零业务载荷。
- 逐父缺组 / 多组 / 乱序、错端点、关系 / 子端点 / 路径角色 / 活动结论半结构、重复、活动结论缺失 / 未知 / 复义 / 矛盾和坏生命周期均为内部不一致；合法非活动结论不是错误，必须被确定性排除。
- 任何截止、版本或预算矛盾整体失败，不返回前缀，不重读部分材料，不与缓存 / 历史拼装。
- 最终 ABI 改变单次返回全部当前直接子关系及活动材料、逐父一一对应、合法空组、DATA 零业务判断、BIZ 只按已发布强类型结论选择、稳定排序、范围 / 规则、预算、截止或失败分类时零写停止并具名退回计划支撑。
