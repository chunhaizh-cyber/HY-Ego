# 字段补问与疑问代词提问实施计划

标识：`FIELD-QA-ASK`；版本：v0.1；日期：2026-11-07；状态：待激活（详细设计第11节待用户裁决）。

完整施工合同：[字段补问与疑问代词提问详细设计](../规范/详细设计/20261107_FIELD-QA-ASK_字段补问与疑问代词提问详细设计_v0.1.md) v0.1。本计划只规定施工范围、顺序和门禁，不重复设计正文。

## 1. 目标与完成条件

缺字段的服务对象需求经正常筹办，依次提出补问、询问、发送三个子需求，分别经任务链执行；问题以疑问代词“多少”提出并入列；疑问指代实例与提问场景留档；补问任务进入等待回答。

完成条件：
1. 详细设计第4、5、6、7节的数据、方法、筹办与名称全部落地。
2. 实际项目 Debug/x64 编译、链接 0 错误；`git diff --check` 通过。
3. 专属施工记录列明：S0结论、选定槽号、改动函数清单、非成功映射、与设计的偏差、知识变更清单。

不在范围：回答解释（`FIELD-QA-ANSWER`）、写回执行（`FIELD-QA-WRITEBACK`）、代词定义迁到语言 owner、运行期三个守卫、结算与服务值。

## 2. 起点与所有权

- 起点：main `775554c94` 或之后不改动本计划写集的提交；S0 核对写集文件自起点以来的改动。
- 唯一代码所有者：本计划执行者。
- 若写集文件与其它活动切片重叠，停止受影响范围并交回交互窗口协调。

## 3. 写集

允许修改：详细设计第9节表中的文件，以及专属记录 `验证记录/20261107_FIELD-QA-ASK_施工与编译记录.md`。

禁止修改：规范、规则、计划、计划索引、知识库；第9节“不在范围”列出的模块。禁止任何改变 Git 状态的命令，由交互窗口提交。

## 4. 施工顺序

1. **S0**：
   - 读回详细设计第2节的全部代码事实，记录偏差；
   - 核实输入侧能否从“帮我调一下水温”形成“仅特征”的待完善需求（详细设计第11节第2项）；
   - 选定槽号，选定需求新增特征的键组方案。
   - 出现会改变实现的漂移时，停止受影响范围并在记录中写明。
2. **切片A 基础**，完成后成组编译一次：
   - 先天特征类型；
   - 初始化材料与名称；
   - 首选名称；
   - “多少”代词定义；
   - 提问场景与信息存在成员；
   - 指代实例结构；
   - 状态友元。
3. **切片B 链条**，完成后成组编译：
   - 需求的“有确定值”与候选，以及以需求为目标的已核验入口；
   - 筹办改造与条件分支；
   - 等待原因；
   - 三个本能与装配；
   - 模拟世界接口同步。
4. 撰写记录，运行 `git diff --check`。
