## 3. 设计

### 3.1 召回：接受只有条件、结果为空的配对

1. 模拟学习遇到模拟世界执行不了的本能（例如询问返回“定位未支持”）时，仍发布一条配对：条件节点按方法头与条件声明生成，结果节点为空。这条配对的来源为“模拟”。
2. 补问叶子召回改为接受学得的配对，结果为空也算，不再要求先天被动配对。召回时只看条件，不按结果比对。
3. 询问真实执行后，尝试学习按实际结果补全配对的结果。

### 3.2 询问：问完之后到自然语言世界等答案（v0.5 重写，用户 2026-11-12 裁决）

**三场景分工**：外设场景由外设类管理，记录和执行事实；语言场景把自然语言转换为内部世界可以认知的信息；内部场景读取外设场景与语言场景自动生成的事实信息，并按需求写入。

**询问合同（用户 2026-11-12 确认）**：
- 修改对象：现实世界——经窗口说出一句问话。原因：补问需求要求某被认知需求的某一栏有确定值，只能由交互者提供或由自我找到。目的：自然语言世界中出现该问题的答案。
- 参数：沿用4个（补问需求Q、自我、窗口副本、外设场景标识特征）。
- 条件：参数1为引用某被认知需求某一栏的补问需求（参数规格）；窗口副本具备外设场景标识（初始必要条件）；自我有交互者（执行分支）；**自然语言世界中该问题尚无答案**（初始必要条件，新增；已有答案则不问，返回目标已满足）。
- 结果：自然语言世界中出现该问题的答案——作用存在为“问题”概念下的存在，特征“答案”由无值变为有值（按“作用存在概念＋特征类型”表达，不绑具体节点）。答案来源随答案记录：消息转换（交互者回答）或自我写入（自我找到）。输出队列新增问话、出站语言场景留档属顺带，不入结果组。
- 业务结果值域：已取得（来自交互者 / 来自自我）；目标已满足（已有答案未问）；等待中；动作结果未知。
- 学习：模拟执行不了，只生成条件、结果为空；真实执行后按“问题的答案有值”补全结果。

**答案判定（用户确认：按结构比对）**：答案的主体与被问的那一栏都与问题一致，且出现在提问之后。不做文本匹配。

**运行**：
1. 提问时，语言owner在出站来源场景中建立“问题”存在：带被问结构（被认知需求、主体、被问栏）与“答案”特征（无当前值）。问话入列交外设执行。
2. 问话入列后进入“动作已发出、等待结果”。结果检测查询自然语言世界：按结构比对找该问题的答案（第3.3节值陈述、或自我写入的信息）。
3. 找到答案：语言owner把问题的“答案”特征写为引用该答案信息，并记录来源（消息转换 / 自我写入）；询问结束，结果为“问题的答案有值”，回报来源。
4. 未找到：保持等待，不轮询；自然语言世界有新信息生成（消息转换完成或自我写入）时唤醒检测（依赖键为问题节点或其所在交互）。

### 3.3 输入侧：对方的消息保存为场景信息

1. 值类构式（整数、特征概念条件、目标单值或闭区间、方向、字段填项等）不再判为“非支持输入”，而是在接收来源场景中保存为场景信息，包括说话者、来源消息、主体（存在节点或待定）、特征类型、值、原文范围。接收认知新增阶段“已保存场景信息”：不建立 D，消息到此结束。
2. 招呼也按注释所说保存为场景信息。
3. 与“前置输入待治理”路径分开：已有前置定位的消息仍走原路径。
4. 说话者改为取窗口当前交互者（“自我.交互者”的当前值）。
5. 退役问答匹配写回，删除 `查询出站字段询问`。
6. 语言 owner 提供只读查询：某交互场景范围内、某说话者在某时刻之后的场景信息（值陈述）。

### 3.4 写入：由父任务读取答案并写进需求

1. 询问任务结束后，父任务（分解出 Q 的任务）在重新筹办时读取该问题的“答案”所引用的信息（值陈述等），按 Q 所指字段写进被认知需求的该栏，字段内容来源记录指向该答案信息。
2. 答案有多条且值不同时不写，Q 保持未达成，记录日志。
3. 写入前复核：该栏仍然未知、答案仍未被采用。
4. 写入是父任务筹办中的内部治理操作，形成任务治理动作与因果（TASK-STATE-CAUSAL）。写入后 Q 经当前满足复核达成。
5. 答案来源为“自我写入”时是否先向交互者确认：暂不规定，按同样方式写入（自我意识事项）。

### 3.5 用户已确认的两项（2026-11-12）

1. **字段来源怎样记录**：建议需求 owner 新增“字段内容来源”记录，记下该字段的值来自哪条陈述；完善阶段按必需字段是否齐全自动维护（并入 INSTINCT-CONTRACT 阶段4）；首次接收认知的 D 也允许这样补字段。不复用现有表示显式确认的“认知来源”。
2. **“目标形式”这一栏怎样得到**：建议由值陈述推出。说了具体值（如“40度”）即“值”，说了方向（如“热一点”）即“变化方向”，同一次写入形式和载荷。

## 5. 非成功与工程边界

| 情况 | 处理 |
| --- | --- |
| 无新消息 | 询问停在等待结果，靠事实变化唤醒 |
| 回答里没有可用值、或多条值相互冲突 | 父任务不写，Q 保持未达成，记录日志 |
| 写入前复核不通过 | 不写，重新筹办 |
| 需求 owner 拒绝（值不相容） | 视为该陈述不可用，记录原因 |
| 读取、发布工程错误 | 走工程异常路径，不转成“无答案” |
