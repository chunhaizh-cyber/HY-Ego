- 设计依据：[CONV-INSTINCT 设计](../规范/详细设计/20261108_CONV-INSTINCT_交互获取服务对象需求本能方法族设计_v0.1.md) §6.6（询问方法4参数修订）、§6.7（两个方法、身份统一及补充裁决）

## 1. 目标、范围与完成条件

目标：补问叶子Q（目标：被认知需求D某字段有确定值）能由“对方说过的话”闭合，不依赖问答匹配。

范围：
1. 输入侧：受支持的值类陈述保存为接收来源场景中的场景信息，不再判为“非支持输入”。
2. 语言owner只读查询：列出某语言场景范围内、某说话者的未采用值陈述。
3. 新内部方法“从场景信息取得需求字段值”：取值、经需求owner写入D、记录来源。
4. 询问方法：增加“场景信息中尚无可取值陈述”条件；撤除先天被动结果配对（R110撤回）。
5. 新陈述到达时唤醒同一交互中等待的补问叶子任务。
6. 说话者取窗口当前交互者（“自我.交互者”当前值）。
7. 退役 §6.5 匹配写回。

不在范围：§6.6 询问方法4参数修订与身份统一默认值（代码窗口另行直接施工，本计划以其完成为上游）；“其它途径”识别窗口前实际对象（自报身份理解等）；请求确认需求内容；字段可答性（如“需求目标形式”由值推出还是另问）；多窗口取窗。

完成条件：实际项目编译链接通过；诊断运行中出现“询问已入列 → 对方值陈述保存为场景信息 → 补问叶子以‘取得’写入D该字段 → Q达成”，或在对方事先已陈述时不发出询问直接取得；无工程异常。测试只在用户发出测试指令时运行。

## 3. 目标函数、DTO、物理位置与依赖方向

依赖方向：任务侧（新方法运行服务）→ 语言owner只读查询、需求owner更新；输入侧（接收认知）→ 语言owner保存。语言owner不依赖任务与需求。

1. **值陈述（场景信息）**
   - 承载：接收来源场景内的采用含义，构式为值类构式；保存说话者、来源消息、主体（存在节点或待定）、特征类型、值（I64与单位，或值域概念）、原文范围。
   - S0 冻结：沿用 `建立或取得接收采用含义` 扩展接受值类图，或在语言owner新增“建立或取得接收值陈述”专用入口，二选一，以不改变现有需求陈述采用合同为准；选择结果写入施工记录。
   - 接收认知新阶段：`已保存场景信息`（不建立D、不交接行动请求，消息终结）。
2. **语言owner只读查询**：`查询未采用值陈述(语言场景范围, 说话者) → 列表{采用节点, 来源消息, 主体或待定, 特征类型, 值, 原文范围}`；“已采用”以D字段认知来源是否已引用该陈述判定（经需求owner只读），查询本身不写。
3. **新内部方法“从场景信息取得需求字段值”**
   - 登记名：`builtin.demand_field.take_from_scene.v1`（S0 可调整命名，须唯一）。
   - 参数：1 补问需求Q（需求根概念，正式参数指定）；2 自我（自我范围概念）。
   - 方法头：作用存在概念＝需求根；涉及特征类型＝支持字段类型组；可能结果＝被问字段类型。不声明先天配对（R110：条件由模拟学习依据方法头生成，结果按运行结果取得）；召回按方法头可能结果（R107）。
   - 必要条件：可取值陈述存在（§6.7 条件3）。条件判定由运行服务的同一读取函数提供，供筹办与执行入口共用。
   - 运行：读取 → 选值 → 复核 → `更新被认知需求信息`（已知目标补该字段；认知来源＝该陈述）→ 返回已写入。
4. **询问方法**：必要条件增“尚无可取值陈述”（共用第3项读取函数）；删除先天被动结果配对，执行后任务等待对方陈述。若条件项无法声明，在补问叶子方法选择中调用同一读取函数实现互斥。
5. **唤醒**：接收认知保存值陈述后，通知任务管理线程对“同一交互中处于动作已发出等待结果的补问叶子任务”立即复查；复查沿用现有结果检测。

## 4. 数据来源、控制分支、事务、版本、所有权与生命周期

- 值陈述由接收认知在消息处理事务内经语言owner一次发布；失败不留半成品（沿用来源场景已有的保留规则）。
- 取值判定只读；写入D由需求owner一次更新完成；更新前复核D该字段仍未知、陈述仍未被采用。
- 选值：只有一条可取值陈述时取它；多条且值相同时取任一并全部记为已采用；多条且值不同时不取（条件不成立），任务保持等待，不按时间推断。
- 主体待定的陈述：说话者为当前交互者且值属于被问字段值域时视为可取。
- 所有权：语言owner（值陈述与查询）、需求owner（D更新）、方法owner（登记）、任务owner（筹办/执行/复查）。
- 生命周期：值陈述随来源场景长期保留；被采用后不删除，只由D字段认知来源引用。

## 5. 非成功、内部错误、撤销、发布与读回

| 情况 | 处理 |
| --- | --- |
| 无可取值陈述 | “取得”条件不成立，询问方法适用 |
| 冲突陈述 | 两方法都不执行（询问因“已有陈述”不适用），任务等待；记录运行日志供后续“请求确认需求内容” |
| 写入前复核不通过 | 不写、不记动作，零动作返回，重新筹办 |
| 需求owner拒绝（不相容） | 视为该陈述不可取，记录原因，任务等待 |
| 读取/发布工程错误 | 工程异常路径（弹窗、日志），不转为“无答案” |
| 发布读回 | 写入后读回D该字段与认知来源，不一致按工程异常 |
