## 5. 实施步骤

1. 在`L2需求结构.数据.h`给根需求组请求增加非零`数量预算`，删除结果的`根父子占位组`，收紧成功谓词；保留并复用现有`按子需求读取当前父需求` DTO。
2. 在唯一`L2需求结构服务`实现并公开两个结构 provider：`按所属存在读取当前根需求组`负责同一 G0、完整需求、根筛选、稳定排序、空组成功和根输出预算；`按子需求读取当前父需求`负责 0/1/>1 当前父关系严格分账及完整父端点读回。先在`L2需求结构内部`新增不加锁的`按子需求读取当前父需求当前投影` helper，完整父事实直接复用已有 internal `读取需求完整当前投影`；两个 public 入口各自只取得一次`互斥体_`并直接调用 internal helper，严禁从根 provider 锁内回调 public 父 provider 或 public `读取需求完整`。根预算不得限制全部需求候选扫描，总节点预算仍只由组合器 BFS 裁决。两者都不得判断活动。
3. 在`运行期只读查询.数据.h`删除旧活动型 DTO，建立详细设计第 4.3 节的新合同、请求、结构项、列表任务项、快照和结果。
4. 在组合器删除旧固定材料缺失函数，按详细设计第 5 节实现根遍历、逐需求当前父互证、列表归属、列表项完整读取和任务反查；根预算只传根 provider，总节点与深度预算由组合器独立执行；不新增需求业务服务或活动字段。
5. 同步父治理 DTO 和请求构造：填写最大根数、最大总需求数和最大结构深度，结果字段改为需求结构任务快照。只允许机械适配 BIZ-L2-002-02 的 N04；不得顺带实现第三子快照、G1 后读、父级三子全成功或完整错误传播，也不得把现行“至少一个子成功即可形成”写成正式设计结论。
6. 调整现有治理端到端测试，复用其隔离合法消费者路径：从同一 L1 运行包公开签发器建立各 L2 owner 交付，经公开 L2 构造和公开写入/读取完成空结构、单根无任务、单根有任务、漂移和请求拒绝矩阵，再装配公开组合器读取；删除 DATA-EXT-12 缺失通过提示。不得增加私有 seam，也不得宣称使用了生产普通应用上下文/getters。
7. 形成函数级知识变更清单与专属施工/验证记录。

## 6. 状态映射与失败收口

- 请求无效：`请求拒绝`。
- 任一结果截止非零且不等 G0，或提供者返回事实代次漂移：`当前性漂移`。
- 根数、总节点数或深度超限：`数量预算不足`。
- 自我或入口必需结构事实未找到/已退出：`材料缺失`。
- 已枚举需求缺列表归属、根有父、非根无父/多父/父关系不等、列表或任务引用矛盾：`内部不一致`。
- 分配失败：`资源失败`。
- 以上任一非成功都必须保持 optional 快照为空。

执行发现隔离消费者中的公开签发、公开 L2 构造、需求/任务公开写入或当前 DTO 发生名称级机械漂移，可在白名单内匹配；若只能扩展白名单、增加第二服务/owner、直达 L1 或发明活动事实，具名退回计划支撑。
