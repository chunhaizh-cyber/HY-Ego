## 4. 施工合同

### 4.1 DATA DTO

按详细设计 §3、§5 精确增加两类身份、状态和值域、完整目标裁决结构材料、治理状态事实、目标裁决证据事实、两写请求/结果和当前/历史读请求/结果。

DATA 头不得包含 BIZ 的 `运行期只读查询.数据.h`。专项测试负责字段映射，后继 DATA 外业务 provider 才是正式生产映射 owner。

### 4.2 登记与持久化

使用详细设计 §6 固定的两个登记幂等身份、三个本地键区间、三个固定值类型和 22 个关系类型；不修改既有任务/路径/实例/结果登记幂等身份。

治理状态材料必须是 18 项 U64 组，目标裁决材料必须是 22 项 U64 组；顺序、格式版本、关系端点和强类型 DTO 逐项互证。未知键、未知枚举、错长度或任一重复单例按内部不一致或入口拒绝收口。

### 4.3 首态入口

实现 `新增执行结果待验证状态`：

1. 在裁决共同截止 `Gc` 读取任务、虚拟存在、路径、实例、当前路径和正式实际结果；
2. 逐字段复核完整目标裁决材料；
3. 要求任务尚无关系 14 当前项；
4. 一笔写集形成治理状态版本 1、正式裁决证据、关系 14、关系 15 40—44、全部引用和值；
5. 只使用 L1 返回的 `Gs` 读回首次结果；
6. 精确重复在后续代次仍返回首次 `Gs` 和首次历史结果。

### 4.4 目标未达成迁移

实现 `提交目标未达成待重筹办迁移`：

1. 在 `Gs` 读取唯一当前前态和同一正式裁决证据；
2. 要求前态为执行结果待验证、裁决未达成、后继准备为目标未达成待重筹办；
3. 要求正式结果仍当前、新发生时间晚于前态；
4. 关系 15 角色 42 指向方法节点，不指向动作入口；动作入口由路径与实际结果互证；
5. 一笔写集新增版本 `前态版本+1` 的目标状态并退出旧关系 14；不复制裁决证据；
6. 目标状态按 L1 返回 `Gr` 读回，前态按 `Gs` 历史读回；裁决材料仍保留 `Gc`。

### 4.5 重试和错误

当前代次高于原期望时，只能按原截止历史重建原写集并用原幂等身份重放；只接受 L1 精确重复及原代次/原编码映射。禁止自动升级截止。

沿用 `L2结构状态` 分账。发布后读回不一致返回内部不一致并保留已发布事实，不得伪装零写。
