# 任务筹办线性反求与实例条件覆盖

身份：`TASK-PREPARATION-LINEAR-INSTANCE-CONDITIONS`；版本：v0.1；日期：2026-10-12。

代码基线：`b88918bac8eeb226e33daf920e21d03c44438b1e`。状态只读取[计划索引](计划索引.md)。本文件承载本叶完整设计与施工合同。

## 1. 目标及具名裁决

用户要求“按照这个口径完善任务筹办”：选定任务方法实例的配对后，根据原条件/结果域及明确线性方向反求输入，直接覆盖该实例的条件值域；真实当前条件未具备时形成现有条件子需求提议。抽象方法不改变，任务不保存第二套同义所需域。再次反求使用实例冻结的原映射，不用收窄后的C和原R重新计算比例。

上轮`13f7890a`已发布纯值函数`新_任务类::按线性关系计算任务条件输入`，精确合同及边界见[验证记录](../验证记录/20261012_TASK-LINEAR-CONDITION-INVERSE_任务线性条件输入反求验证记录_v0.1.md)。本叶直接复用，不改其计算语义。

当前窗口进一步冻结：

1. 显式方法知识建立请求可以提供原线性关系；不要求本叶为现有服务结算方法制造关系、不要求运行成功。自动从学习样本生成关系留后续。
2. 没有关系仅在需要反求时明确不支持；结果全域已经满足目标时允许继续既有核验。
3. 模型逆像可达目标与原结果整域满足目标同属目标满足优先层，不人为降低线性候选的排序。既有`保证满足目标`只表示当前模型预测，不证明现实效果、学习验证或所有多条件组合的联合效果。
4. 所需窄域经既有特征概念owner建立/复用，实例条件保存该唯一概念引用并清空精确域；不增加任务所需域事实。允许此owner调用，不改特征概念合同或线程。
5. 预建完整新C后一次切换配对的条件引用；切换后清理失败属于“已生效、结构不一致”，不得回滚已发布C或伪报零写失败。

这些裁决仅替代[旧混合实例设计](../规范/详细设计/20261010_MIXED-METHOD-INSTANCE-SELECTION_混合方法实例与结果导向选择详细设计_v0.1.md)中本叶禁止线性反求、实例条件不可按本次任务收窄的相冲突口径，不扩大为自动学习或现实执行许可。

正式依据：[0050](../规范/0050_项目通用机器逻辑与禁止性规则总纲_20260721.md)、[3200](../规范/3200_根规范_任务.md)、[3300](../规范/3300_根规范_方法.md)、[5350](../规范/5350_子规范_方法治理详细合同.md)、[5370](../规范/5370_子规范_方法学习与知识形成.md)、[代码归属规范](../规范/代码文件建立归属与模块命名规范.md)及`AGENTS.md`。本叶不是本能函数，不改变现实存在或任务虚拟存在的特征值。

## 2. 当前能力与复用

- 方法公共类型当前没有条件—结果线性对应组；结果`变化方向概念节点`表示执行前后方向，不能复用为输入上升时输出方向。
- `建立方法知识/确保本能方法登记/追加模拟条件结果`、完整读回及复制闭包已存在。新增关系由这些唯一owner入口承载，空组保持缺失而不猜方向。
- `复制方法闭包`已复制完整内部结构并重映射内部节点；必须同步复制字段规格，不在任务建立第二模型仓。
- `筹办任务条件和参数`已能核验私有精确域；`选择任务方法结果`能比较结果概念域和精确域，但相交而非整域满足仍拒绝，尚未调用反求函数。
- `提议任务条件子需求`及self现有消费者要求正式目标值域概念身份；仅将该身份设零会制造假“已形成”。通过owner将所需域表达为实例条件概念，可继续完整现有链而不改self。
- `概念_特征类::建立或取得特征概念`给出父时只复用直接子域且要求严格子域；相等时直接复用父。概念可被修改，因此原线性端点必须保存数值，不能反求时重读原概念来恢复比例。
- `基础数据集::修改字段节点`可一次替换配对C引用。它不提供整个业务组合事务，本叶仅保证方法锁内普通owner读者看到完整旧C或新C，不宣称崩溃原子或跨进程恢复。

知识库三个现行入口已读，当前没有本基线完整用途卡，复用以上现行头源。裁决为扩展方法owner和任务owner同一闭环切片，不新建公共工具或工程。

## 4. 方法关系公开合同与存储

在方法公共类型头中`新方法条件结果定义`前新增下列值类型，并在`新方法条件结果定义`及`新方法条件结果信息`尾部均追加`std::vector<新方法条件结果线性关系> 线性关系组;`，默认空。精确字段：

```cpp
enum class 新方法条件结果线性方向 : std::int8_t {
    反向 = -1, 不变 = 0, 同向 = 1
};
struct 新方法条件结果线性关系 final {
    std::size_t 条件序号 = 0;
    std::size_t 结果序号 = 0;
    新方法条件结果线性方向 方向 = 新方法条件结果线性方向::不变;
    特征概念I64闭区间 原条件域;
    特征概念I64闭区间 原结果域;
    friend bool operator==(const 新方法条件结果线性关系&,
        const 新方法条件结果线性关系&) = default;
};
```

显式包含`<cstddef>`。线性方向是独立方法领域枚举，task调用纯值算法时显式转换，不能将方法头依赖任务头。位置都是完整C/R组内零起始原序号，禁止按FT/角色合并。关系是调用者已裁决的端点仿射知识，owner只验证，不学习。

### 4.1 初次发布验证

非空关系组须同时满足：

1. C/R规则仅单项或全部成立（结果还可主要结果及允许副作用）；不将OR、有序或条件选择解释为AND。
2. 同对不重复、位置有效且不超过I64_MAX，所有同条件引用的原C一致、所有同结果引用的原R一致。
3. 原域有限、闭区间合法，不接受I64_MIN/MAX哨兵；同/反向两域严格非单点，不变原R单点，原C可单点。
4. 关联项具有明确I64 FT；本项域须能由精确域或唯一单段概念域完整取得，两者互斥。端点与声明原域精确相等，材料类型/单位合法；多段、非数值、无域或只有状态/动态描述不能冒充数值模型。
5. 关系可仅覆盖部分条件/结果，作为明确部分知识存储；任务需要反求时若不足以覆盖本次全部条件则具名拒绝，不能补关系。

定义建立时验证上述全部材料。抽象方法完整读取保持形状/位置/类型合法性，实例完整读取允许当前C在原模型范围内改为任务所需域，不因域与原C不相等拒绝实例，也不能把此差异套回抽象方法允许任意知识篡改。

原模型不是任务当前需要域，其端点只在定义首次发布/实例复制时固定。后续反求不从当前C或后来修改的抽象方法补模型。旧空关系配对仍完整可读，但不是有关系。

### 4.2 精确物理承载

方法源文件新增字段类型节点`配对线性关系组字段`，在初始化类型登记及`结构仍存在`核对中登记。每个有关系的配对恰一该字段直接值，材料是`std::vector<std::int64_t>`，每七项为`条件序号,结果序号,方向,C低,C高,R低,R高`，按条件序号、结果序号升序规范化；空关系不写字段。多字段、错误variant、空载荷、长度非7倍、负序号、非法方向/域或重复位置为结构不一致，不当作空知识。

同步`写入条件结果`、`读取方法信息`、`方法复制字段规格`与涉及`新方法条件结果定义{配对.条件,配对.结果}`的重建，保证模型不在复用、登记、复制或学习追加读回时丢失。复制字段登记为直接值，绝不重映射其中序号或端点。现有条件/结果节点和枚举编码不变，不扫描改写既有空关系方法。

同C判重必须把R及线性关系组一并比较：初次请求先按同一顺序规范化，或用等价的顺序无关语义比较，禁止因调用者关系组排列不同产生冲突。同C/R但关系不同不报精确重复，沿现有同条件结果冲突返回。现有模拟学习默认空关系，不自动生成关系，也不允许它悄悄覆盖已有关系。

## 5. 实例条件覆盖provider

方法类现有`private:`、`friend class 新_任务类`范围内新增以下私有成员合同，不增加任意调用者可写实例的入口：

```cpp
enum class 新方法实例条件覆盖状态 : std::uint8_t {
    已覆盖 = 1, 无变化, 入口拒绝, 来源已变化,
    值域不支持, 资源失败, 已生效但结构不一致, 结构不一致
};
struct 新方法实例条件覆盖结果 final {
    新方法实例条件覆盖状态 状态 = 新方法实例条件覆盖状态::入口拒绝;
    bool 已生效 = false;
    std::optional<新方法条件结果信息> 当前配对;
};
新方法实例条件覆盖结果 覆盖实例配对条件值域(
    稳定编码 实例根节点,
    稳定编码 方法节点,
    const 新方法条件结果信息& 预期配对,
    const std::vector<特征概念I64闭区间>& 所需条件域组) noexcept;
```

声明置于现有friend后，定义置于`查询实例条件结果`邻近。锁序为task锁→方法锁→既有概念/基础数据公开入口；provider不反调task，不取得其它线程资源。调用方已在task锁内确认任务唯一实例和待检查条件状态。

### 5.1 前置和概念形成

持方法递归锁验证root为合法混合/单实例、方法属于该root且有来源抽象方法、配对身份和完整值与`预期配对`一致。禁止抽象方法写入、跨实例引用或部分条件组。所需域数量等于完整条件数量，每项在相应原模型C内；所有非值域字段保持完全相同，R、原关系、命中数、方法/实例根、参数规格不变。

每个条件的FT根、单位和I64表示先完整读取；新域若与当前条件解析出的域相同且已是正式概念域，则复用原引用。否则新域等于FT根域时用根；严格子域时，以FT根作为固定父调用`建立或取得特征概念`，定义沿用根材料类型、单位、比较规则等语义，只替换值域，不带名称。必须正式读回且域/FT/单位一致，失败不切换C。由此构造每条件`特征值域概念节点=所得节点`、`精确数值域=nullopt`的新完整条件定义。

如果新完整定义与当前C相同，返回`无变化/已生效=false/当前配对`，不换C身份。新建立的合法共享概念在后来实例替换失败时保留，它不是待回滚私有垃圾；不擅自减少实例引用计数或删除共享概念。

### 5.2 一次切换、读回和清理

1. 在任何实例写入前准备完整新C/各项写集、所有回传容器和旧C精确节点/字段清单。旧C必须只归当前配对，不存在其它正式owned持有或未知外部引用；不能证明独占时零切换拒绝。
2. 使用现有方法字段写入helper创建完整新C子树，复制所有非值域条件信息，仅修改域表达。未接到配对前，普通完整方法读取看不到它。写失败仅逆序清理本次新树，清理失败为结构不一致，不触碰旧C。
3. 对已核实唯一`配对条件字段`关系执行一次`修改字段节点(关系编码,新C)`。这是实例条件可见切换点，不更换配对/R身份。失败前旧C保持原样，新树清理；成功后禁止再回滚为旧C。
4. 正式读回配对，核对新C全定义、原模型、R和归属；成功回传必须来自该读回。切换后读回失败或分配异常返回`已生效但结构不一致`、`已生效=true`，不伪报资源失败零变化。
5. 只清理已脱离当前配对的旧C及其owned条件项，先删其精确字段后逆序删节点，不删参数角色、FT、概念或其它共享引用。清理失败同样返回已生效结构不一致并停止依赖；新C仍为当前。此时证据必须记录已切换及残留清单，不能把孤立旧材料称为新当前，也不自动重做覆盖。

`已覆盖`返回`已生效=true`和新配对；`无变化`返回当前配对；其它未生效非成功无配对载荷。已生效结构不一致可返回已成功读回的新配对供诊断，但task不得继续推进。该结果只说明进程内方法owner写入，不宣称跨owner事务、持久恢复或崩溃一致性。

## 6. task选择、覆盖与重新核验

继续使用既有`选择任务方法结果(任务节点) const noexcept`公开入口；`const`只表示任务对象成员不变，本轮新增的方法实例条件写入必须在头注释明确，不伪称纯读。

将现`筹办任务条件和参数`的纯读主体等义提取为task私有`新任务治理条件筹办结果 核验任务条件和参数(稳定编码 任务节点) const noexcept;`。公开筹办在已有实例时先调用选择/反求/覆盖，再调用此私有纯读核验；选择内部及覆盖后只调用私有核验，不回调公开筹办，从而消除递归。无实例时公开筹办直接调用私有核验保持原行为。worker现有公开筹办调用自然触发新链，不另改线程。

公开筹办头注释明确可能收窄实例和创建/复用域概念，但不改变任务状态、不执行动作。选择成功或等待条件时返回对当前C的完整核验；选择资源失败映射筹办资源失败，任务状态已变化对应原状态，其余选择非成功必须让`候选已完整核验=false`并保留结构化选择状态，不能返回旧C完整具备而让worker继续。为此`新任务治理条件筹办结果`尾部追加`std::optional<新任务方法选择状态> 方法选择状态;`，将现有`新任务方法选择状态`枚举声明移动到该结果之前，枚举值不变。正常候选核验完成但选择未收口时外层状态仍为`已完成`，消费者以已有`候选已完整核验`门禁停在筹办待核查，调用者可从新字段区分缺关系、无适用、非唯一和目标已满足；不把这些分支伪报成内部故障。

现有需求fresh读取、唯一目标结果定位、参数角色到实际对象绑定、候选完整核验、禁止任取多个候选等保持。本叶仅处理值/值域包含目标下的有限单段I64目标；多段、非数值、非包含比较、方向目标的反求不臆造新算法，保留既有支持边界。

对每个候选：

- 整个结果域已经满足目标：沿既有路径列为模型目标满足候选，无关系不阻断，不强制无意义收窄。
- R与目标相交、但R不全在目标内：从该实例配对不可变线性材料取得完整原C，建立上轮纯值请求。只加入本次唯一目标结果对应关系，原结果序号保持；每条件必须都有这个目标的明确关系，不能把其它结果关系当作目标约束。结果原域和目标域经同FT/同单位确认，调用已发布静态反求函数。
- 无关系、缺条件覆盖、多段或非数值原域：返回明确`结果定义暂不支持`，不得猜同向、丢条件或退化为全域已满足。
- 反求`目标无交集`：该候选不适用；资源失败向上传递；非法模型属于结构不一致。成功只暂存此候选值式需要域供选择，不写任何实例。
- 原结果与目标分离时保留原方向推进候选及有利端点排序，不因此自动运行本轮反求。范围外目标不通过线性外推变成成功。

保持两级优先：模型目标满足层（包括整域满足与反求成功）优先于原方向推进层；目标满足层有多个候选则匹配不唯一，不自行按域宽选一个。方向推进层仍按原有利端点规则。任何完整性/未支持材料继续按既有保守规则显式返回，不漏掉未知候选后宣称唯一最优。

只有唯一最终候选需要反求时才调用第5节provider；如果provider无变化则保留C身份，若已覆盖则采用返回的新C定位。随后必须重新调用私有`核验任务条件和参数`并重新定位同一方法/配对/新C/R，得到真实当前条件核验。禁止复用覆盖前筹办结果、旧C身份或旧“条件具备”结论。

返回`已选定`只在新条件真实具备；否则返回`等待条件`并携带当前配对定位。`保证满足目标`为两类目标满足模型候选置true，仅解释为模型预测，不授权动作、不证明联合耦合模型或实际成功。任务本身不新增持久需要域、第二配对或目标快照。

覆盖结果映射：`入口拒绝/来源已变化/结构不一致/已生效但结构不一致`→选择结构不一致且不交付已选定；`值域不支持`→结果定义暂不支持；切换前资源失败→资源失败。返回失败不自动再次执行覆盖。已生效失败由执行证据保留准确边界。
