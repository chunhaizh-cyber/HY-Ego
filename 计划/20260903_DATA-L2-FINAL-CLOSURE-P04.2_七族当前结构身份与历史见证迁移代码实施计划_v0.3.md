## 2. 正式裁决：历史 H 回显与结果头截止分账

依据 `规范/0050_项目通用机器逻辑与禁止性规则总纲_20260721.md`第 3 节第 13 项、`规范/4230_子规范_L2六类纯结构统一合同.md`第 2.4 节、C032 与 P04.2 详细设计 v0.4：七族历史身份来源见证共享同一规则，不能为因果或任何单一族另立第六种行为。

`历史截止事实代次`是历史响应的 H 回显字段；它与结果头的事实截止代次在成功时必须相等，但非成功不能把“结果头截止的阶段性规则”误写成“H 回显归零规则”。唯一裁决如下：

| 阶段 / 结果 | `结果头.事实截止代次` | 历史结果的 `历史截止事实代次` | 见证 / 变更 |
| --- | --- | --- | --- |
| 历史请求形状失败（版本、Gread、H、H>Gread 或身份不合法） | 零 | 零 | 空 / 空 |
| 历史请求形状已通过、但在一致性守卫前发生资源失败或内部异常 | 零 | 精确回显输入 H | 空 / 空 |
| 历史请求形状已通过，但一致性守卫发生 `事实代次漂移` | 严格按 4230 第 2.4 节仅回显实际已观测代次 | 精确回显输入 H | 空 / 空 |
| 历史请求形状已通过、守卫后发生任何非成功 | 严格按 4230 第 2.4 节的阶段规则；守卫已完成时为 H | 精确回显输入 H | 空 / 空 |
| 历史成功 | H | H，且与结果头截止相等 | 完整见证 / 空 |

因此，形状通过是 H 回显的唯一门槛；守卫漂移、资源失败、内部不一致、未找到、入口拒绝或其它后续非成功都不得清除已接受的输入 H。只有成功才以 `H == 结果头.事实截止代次`与完整见证构成历史见证成功；非成功仍必须空见证、空变更、零写入。v0.2 §4 的“守卫前截止/H为零，守卫后回显已确认的 G0 或 H”由本节替代。

## 3. 影响范围与代码裁决

受影响的是七族历史见证路径的共同验证口径：场景、存在、特征定义、特征实例、状态、动态、因果。当前实现已统一在形状检查通过后保留输入 H；该行为符合正式合同，不得为使 v0.2 的错误文字看似成立而只修改因果或改造任何其它族。

本漂移不要求代码修改。若重新 S0 后发现某一族实际未在形状通过后回显 H，那是本计划既有范围内的代码实现缺口，应由执行智能体按本节和 4230 修复；不得等待新的机器语义裁决，也不得引入兼容壳、别名、转发器或第二历史入口。

## 4. 重新 S0 与验证期望

v0.3 发布后，执行智能体必须以本文件精确路径 / blob、v0.2 基础计划 blob、届时 HEAD、index、文件登记、交接 WIP 指纹和验证资源重新 S0。除 v0.2 §7.1 的旧函数 / 旧 DTO 精确扫描与宽模式说明性核查外，新增下列七族共同专项断言：

1. 形状失败：历史结果 H 为零，结果头截止为零，见证与变更均为空；
2. 形状通过、守卫前资源失败或内部异常：H 精确等于输入 H，结果头截止为零，见证与变更均为空；
3. 形状通过后发生 Gread 守卫漂移：结果为`事实代次漂移`，H 精确等于输入 H，见证与变更均为空，结果头截止只按实际已观测代次断言；
4. 形状通过且守卫完成后的历史非成功：H 精确等于输入 H，见证与变更均为空；守卫后的结果头截止按 4230 对 H 的规定断言；
5. 历史成功：H、结果头截止与完整见证的截止三者精确相等；
6. 上述断言必须覆盖七族，特征定义与特征实例分别计入，不得只以因果实现或单个服务代替全族验证。

施工 / 验证记录必须明确分账：本次 v0.3 是计划口径校正；七族实现若已符合，不能虚报为新代码修复。原有旧 ABI 零命中、首次/幂等重放分流、需求 index-only 迁移、端到端测试不入 index、隔离 Debug / Release 构建和普通应用后续验收准备仍按 v0.2 执行。
