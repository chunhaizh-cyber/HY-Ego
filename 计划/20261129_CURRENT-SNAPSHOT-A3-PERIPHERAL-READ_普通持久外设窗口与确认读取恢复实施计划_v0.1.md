## 2. 外设实际运行者的只读绑定

1. 在 `新_外设世界树类` 增加 `基础持久状态 恢复当前权威只读(const 基础持久视图&, 稳定编码 原外设根, 稳定编码 词典批次类型根, 稳定编码 正式中文) noexcept`，由同一普通候选的 `外设世界树` 对象调用。以上三个编码依次取实际启动已核全局根外设挂接、既有特征概念恢复结果内的原词典批次类型根、候选现有的中文节点。`恢复普通应用基础事实` 追加 `稳定编码 原外设根, 稳定编码 词典批次类型根` 两个末尾参数，由唯一启动调用点传入。仅使用绑定于 `全局基础数据集` 且当前仍等于入参的会话。外设只读候选局部构造，成功后在现有外设互斥下安装到该实例的私有 `std::optional<外设持久只读结构>`。该私有结构含当前会话地址、外设根、按原位置的 24 键、九个窗口类类型根及词典分类根。持久绑定不安装原匿名命名空间冷建变量，不调用 `初始化()`，生命周期随该实例自然释放。无持久事实写入。重复同实例安装或已有冷建外设根时返回 `入口拒绝`。
2. 提取 `核验外设消息持久自键` 的现有读取和根形状校验为 cpp 内同一私有助手，成功交回原顺序 24 个码。两条已发布调用继续保留原核验行为。17 消息字段、6 确认字段、1 消息根依原定义拆分，精确自键和根字段保持原有合同。实际场景 owner 以第 3 节读口核外设根和挂接，两类根保持互异并且场景逻辑父边不承接物理全局根边。
3. 六项窗口 FT、接收与发送消息集合 FT、输出队列 FT 复用 `确保具名类型` 使用的九个明确名称和三组定义构造。按中文和严格 UTF-8 合同经 `按规范化词面查询` 精确取 W，调用 A3-NAME 的 `读取当前权威普通名称候选`。每个名称必须恰有一个普通 N。经 `读取特征概念定义保护` 确认 N 的目标为正式 FT 根，定义的反向名称列表含 N 恰一，并精确核材料、值域、单位、比较和聚合字段。四项文本是 UTF-8 全材料、完整材料精确和完整材料精确集合，两计数是 I64 的 `[0, I64_MAX]`、I64 数值和 I64 连续值归组，两消息集合是 U64 全材料、消息集合身份判等和完整材料精确集合，队列是 U64 全材料、完整材料精确和完整材料精确集合。均无单位。九个角色和词典分类根互异。选择 `FT` 只依据正式名称与原定义。旧名称全集初始化、词典记录装配、消息成员集合读取器及正式消息正文读取留后继。本片只绑定已有窗口/确认的读取材料。

## 3. 指定视图的现存窗口与确认读回

1. `新_场景类.h` 增加 `新持久外设场景结构`，含 `基础联合节点快照 场景快照`、`std::vector<稳定编码> 子场景,成员存在`。实际外设场景实例公开 `std::pair<基础持久状态,std::optional<新持久外设场景结构>> 读取当前权威外设场景结构(const 基础持久视图&, 稳定编码 外设根, 稳定编码 场景) const noexcept`。沿已经发布的 `读取恢复服务场景结构` 和其内部具名用途、身份、成员及角色 3 键，核指定根/场景的类型、根用途为 `普通`、根无场景父边。根读出直接子场景身份。指定场景不在根直属组时成功返回空，根指向的子节点缺失、类型错或无唯一同边反指为结构冲突。成员为正式字段稳定引用且无重复。使用同视图快照，无需安装共享场景静态键或初始化新场景。外设仅枚举根直属场景，网页子场景不能有直接子场景。
2. 在 `新_存在类.h` 增加 `新持久外设存在顶层`，含 `std::vector<稳定编码> 特征组`、`bool 有存在父子边`。新增 `std::pair<基础持久状态,std::optional<新持久外设存在顶层>> 读取当前权威外设存在顶层(const 基础持久视图&, 稳定编码 E, bool 允许根占位) const noexcept`。从现 `读取当前权威专属存在顶层` 提取共有的视图与存在身份核验，保留原专属入口原样约束。场景和窗口要求专属 EC，EC 反指 E，无清理门。对端可用旧有合法专属 EC，也可按 1140/6120 为同视图语义存在根的零特征占位。后一分支复用 `读取恢复存在概念结构` 已核的根，校验零实例特征，不进入旧 `获取存在` 或根占位的全量定义终止路径。存在角色的外部父子边单独报告，原场景父边由场景 owner 判定。两种 E 均不创建或改写概念。
3. 在 `新_特征类.h` 增加 `新持久外设特征头`，含 `稳定编码 特征,类型根` 及 `std::optional<稳定编码> 文本值`。公开 `std::pair<基础持久状态,std::vector<新持久外设特征头>> 读取当前权威外设顶层特征(const 基础持久视图&, 稳定编码 持有者, std::span<const 稳定编码> 顶层, std::span<const 稳定编码> 文本类型根) const noexcept`。一次联合读取指定 E 的顶层，复用现 `解码恢复顶层特征头`、私有 `读取恢复特征类型头` 和 `核验恢复自我服务特征持有` 的唯一持有语义。只对入参点名单一身份文本类型核当前字段恰一有效稳定编码，返回文本 V。定位其它窗口 F 只确认头和所属真实类型，不读取其当前、历史、聚合或消息成员。外设用已恢复实际值 owner 的 `读取特征值保护` 从 V 验证 UTF-8 物理类型和非空精确文本，所有结果均在入参当前视图下核同。
4. 外设 owner 增加私有 `std::pair<基础持久状态,std::vector<新外设交互场景读取>> 读取当前权威外设窗口组已加锁(const 基础持久视图&, const 外设持久只读结构&, std::optional<稳定编码> 指定场景) const`，接受局部待装配或已安装的只读结构。对每个受查直属子场景调用三个窄 owner。场景身份字段恰好两项分别为两个正式文本 FT 时判为网页窗，同时禁止命中词典批次类型。无网页身份类型且恰有一个词典批次类型时跳过，半套或重复身份、并列网页与词典及无来源分类返回结构冲突。网页窗要求一个带接收数量的窗口，至多一个同场景外设对端，其余成员形状错误。窗口必有接收数量与接收正文类型，发送数量与正文成对出现，收发集合与输出队列仍按当前读口为可选。窗口类型不可重复，不接受位于窗口上的其他类型。窗口实体须有专属 EC 且无存在父子。对端不能持有窗口类型。复用原 `新外设对话框定位` 和 `新外设交互场景读取`，将旧位置选择、重复和可选成对规则提取为同一纯判定，从现有冷路径或本次持久解析分别供料。读取整组时同一公开会话与对话框键只能匹配一窗，按场景编码排序。指定稳定场景仅验所选一窗及其根直属，非网页场景按未找到收口。
5. `读取窗口确认` 提取为接受明确的确认六键和 `const 基础数据集&` 的共享私有解码器，保持旧路径缺省使用原键和全局数据。用现存窗口快照读取唯一窗口确认引用，按同视图核其五字段、场景和窗口、严格字节会话/对话框、时间 `>0`，不得用零或取最早确认消解冲突。无确认引用为 `未找到`，已确认且对端未形成时 `读取已确认临时场景来源` 返回 `未就绪`，现存窗和对端身份一致后才组装结果。暖恢复先用局部结构读完根、已有窗口及确认，再安装；无窗可通过，未确认窗不阻堵恢复。根子场景的成员和特征事实不写回。
6. 已绑定会话时，现有 `查找对话框场景`、`读取对话框来源`、`列出交互场景`、`按场景读取交互场景`、`读取本次网页交互确认`、`读取已确认临时场景来源` 走同一温读接口。只读类型 getter `获取接收消息特征类型` 与 `获取输出队列特征类型` 从已经核验并仍属于本会话的实例绑定取原码。普通读每次以会话当前视图为权威，绑定仅留 schema 和角色身份，不缓存窗口和确认。一次请求前后核原视图指针。资源分流 `资源失败`，视图变化分流 `前提已变化`，其它工程异常 `结构冲突`，不按无窗与未确认吞掉。老带状态接口以 `未就绪` 投影视图变化。旧 optional/vector 接口缺少工程状态时，尚未绑定可返回空，已绑定读取失败沿其现行工程边界，正常不存在才返回空。启动局部核验只使用结构化结果。不改变写入口，持久分支仍无写能力。

## 4. 生产装配及证据

`恢复普通应用基础事实` 在服务对象 F 阶段成功后，持同一会话视图调用真实候选的外设只读恢复。追加 `基础持久状态 外设读取 = 基础持久状态::入口拒绝`，`程序失败阶段` 尾追加 `持久外设读取复核失败 = 38`。失败不发布上下文，只在整个绑定成功后移动候选，启动保持阶段 31。旧首份快照发表及程序模式原样保留。持久根、角色及窗口读取运行者可复用的结果由更新后的真实候选提供，仍无新的客户端或诊断入口。

使用主工作区正式项目默认目录完成 `MSBuild.exe 海中鱼巣.vcxproj /t:Build /p:Configuration=Release /p:Platform=x64 /m`，记录实际输入、退出状态、错误告警和产物。静态核对根及类型来源、24 键、当前视图、读取结果分流、空仓无窗、未确认、已确认、两个入口使用同一读者、部分失败释放和阶段 38/31。获具名运行授权后才核冷建与独立重启、旧窗同码定位和确认时间、零特征根占位对端、混合词典/网页场景、异常缺键错误视图及原快照零写。已有窗口的正例须用实际已发表的正式材料，缺可用旧窗时记录相应运行场景未验，不伪造生产首窗。普通持久新窗与确认写入、同源入站、服务登记及原需求到任务仍待后继。
