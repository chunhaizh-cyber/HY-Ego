# FEATURE-TYPE-R-INTERVAL-RULE-PROVIDER 代码实施计划 v0.3

状态：可执行。基线：`0e0aad858590394792445cc5535fae83d15df418`。

## 目标与完成条件

在 `特征类数据服务` 实现 v0.3 详细设计冻结的 FT R 规则物理事实、I64 默认规则、已发布 I64 FT 补齐入口，以及三个只读规则调用；物理删除“当前采用基准 F + 候选 F”的旧归组 ABI。完成条件是 I64 FT 在规则完整时能给出确定归组/代表/可选域归并结果，非 I64 严格未启用，且旧 ABI 零源码引用。`F/FCv` 仅作为概念 owner 已核验投影被消费，特征类不读取或验证 `F→FCv`。它只解除 IF/R 的 FT 规则阻断，不实现 IF/R、概念写入、普通应用或本能运行。

## 依据、范围和禁止

依据为 4115 v0.6、4120 §3.3、7160 及[详细设计 v0.3](../规范/详细设计/20260918_FEATURE-TYPE-R-INTERVAL-RULE-PROVIDER_特征类型R区间规则提供者详细设计_v0.3.md)。允许改动 `海中鱼巣/领域/数据服务.特征类.h/.cpp`、必要项目登记、专属施工/验证记录。禁止修改 L1、特征值、存在、概念树、世界树、自我线程、普通应用；禁止 IF/R 写入、FCr 写入、非 I64 规则或规则更新入口。

## 冻结实施顺序

1. S0 核对 HEAD、两个目标源码、旧 ABI 五处消费者、定义端口、工程和构建资源。
2. 扩展特征定义结构初始化，登记四项 R 规则结构角色；实现 DTO 形状/预算/同截止守卫。
3. 使新 I64 FT 与两条默认规则、可选归并规则同写集出生；实现已发布 I64 FT 的补齐幂等入口及半结构零写拒绝。
4. 实现三个 `noexcept` 读取函数：严格单点 I64 归组/代表、有域才归并、非 I64 未启用。
5. 删除旧 DTO、成员函数及私有实现，按五处消费者清单验证零命中。
6. 建立专属验证，完成两配置隔离构建；发布后 IF/R 计划才可重新 S0。

## 验证与边界

执行 `git diff --check`、`python .\\tools\\check_specs.py --strict`、旧 ABI 搜索零命中、独立翻译探针、详细设计列出的行为矩阵和 Debug/Release 隔离构建。通过不证明 IF/R 或 FCr 已保存、跨进程恢复、生产装配或阶段21。
