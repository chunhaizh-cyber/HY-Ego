## 4. 机械施工

1. `服务.节点直接结构` 唯一拥有查询服务及查询请求/包装结果，构造借用事务域和 P1A1 六类仓；它只为现有事务域/读取许可类型 import 执行器模块，不构造或调用写入执行器。每个入口内部取得 try-lock 共享许可，成功/未找到携带同一非零代次，其它状态代次为零。`节点直接结构合同.数据.h` 增加公开业务中性写项/端点引用/读回规格；合法 L2 可 include 该公开合同头并 import 提交服务构造公开请求，但不能取得内部能力。`服务.节点直接类型化结构提交` 唯一拥有提交/探测/见证重试服务请求和包装结果；`服务.节点直接结构恢复` 唯一拥有安装实例恢复请求/结果。新内部头 `节点直接类型化结构事务.数据.h` 唯一声明提交服务/恢复服务—数据操作—执行器共享的中性请求/规格/结果、恢复 DTO 和计划身份映射项，四个 L1 模块在全局模块片段 include 同一头且按值复用公开写项原语、不复制声明；L2 禁止 include。`数据操作.节点直接类型化结构` 唯一拥有数据操作类和恢复解码，执行器唯一拥有许可内计划身份形成、确定性持久编码/SHA-256 和固定事务。
2. 完整执行器借用事务域、节点、关系、索引、类型合同、类型化值、幂等和持久端口八项。服务→数据操作→执行器依次调用；普通提交参与者固定为类型合同→节点→类型化值→关系→索引→删除→幂等。类型化值仓补齐稳定记录身份高水位、永久占用和权威导出，普通新值记录只能采用执行器在许可内形成的连续计划键，撤销恢复高水位，发布后永久占用。准备成功必须保存端口返回的非零尝试序号并建立临时侧账；临时侧账建立失败时不建业务候选，直接尝试同一序号的明确未发布见证。候选建立/确认失败先逆序撤销，撤销完整后仍须以同一尝试序号写入明确未发布见证，只有成功/精确同义才清除可能存在的侧账并恢复首次失败分类，其它结果隔离。最后发布部分失败立即隔离。
3. 普通真实提交要求非零预期代次；L2 形成双摘要，L1 只验证非全零并原样持久。独占许可内完成幂等、计划身份、写前准备、尝试侧账、候选、撤销未发布见证或最后发布、代次 `N->N+1`、通用读回与同尝试发布见证；幂等读回不推进代次、不查 SQL。撤销见证的 `写集材料摘要` 唯一为 `SHA-256(准备时完整写集材料字节)`，不得重编码或拼接其它字段。
4. `SQL节点直接持久证据适配` 同一实例实现写入/恢复两端口，只借用 `SQL数据库适配&`，每次调用短连接。事务证据主键含正 U64 `尝试序号`；同一安装实例/事务身份按 `1..最大值` 无空洞递增，`UINT64_MAX` 后拒绝且不回绕。DDL、同义/冲突/未知、明确撤销、同事务唯一已见证、状态侧账转移和错误映射按函数确认；普通查询无 SQL 依赖。普通事务的内存幂等未找到而准备结果为 `已见证` 时必须隔离并返回内部不一致，不得继续候选或映射幂等成功。
5. 编解码使用冻结的 variant 标签和网络字节序；单事务上限 `67,108,864` 字节、任一 vector 上限 `1,048,576` 项。解码分配前完成 `DATALENGTH`、U64→`size_t`、剩余字节和乘加溢出检查；超限新请求零写入拒绝，损坏证据保持隔离。
6. 恢复先按 `(事务身份, 尝试序号)` 审计全部持久尝试，再只重放唯一已见证尝试：已撤销尝试只保留审计，已准备/发布未知、断序/回绕、多个已见证或已见证后的更高尝试均拒绝并隔离。持久审计可读取 `已隔离` 幂等记录，但发现任一此类记录必须在形成聚合恢复 DTO 前拒绝整批，只保留隔离审计，不调用六仓执行器；进入执行器的请求只含 `已发布` 幂等记录。生产恢复显式以事务域 `等待恢复` 模式构造，普通读写许可在开放前均拒绝；恢复执行器取得专用独占许可后建立六仓批量恢复候选，故障隔离域永不恢复开放。六仓按 `节点→类型合同→类型化值→关系→索引→幂等及侧账` 建立/确认/发布，失败逆序撤销；全部仓发布后才用事务域私有 `从零设置恢复事实截止代次并开放` 一次设置最大连续代次并开放普通入口。全部尝试均明确撤销且无发布见证时才可确认从未发布；此时仅恢复服务可调用数据操作的空域治理入口，先建立只含治理幂等记录的代次 1；计划身份映射、四类通用读回和业务读回全空，结果摘要显式覆盖空集合。若恢复材料仅含该固定治理事务且代次为 1、业务仓为空，返回 `已恢复治理空域`，允许 P1A3 以预期代次 1 继续普通世界根提交；任何其它已发布但无根历史拒绝。普通提交无代次 0 例外。
7. 六仓恢复不复用普通逐记录候选。共享 `节点直接恢复仓操作状态` 唯一放在 `节点直接结构合同.数据.h`；每个仓按函数确认 §2.3 在对应 move-only 候选完整定义之后声明本仓结果，再声明建立/确认/撤销/完成发布四函数，结果用 `optional::emplace` 或移动构造，不实例化不完整类型。局部影子容器先全量分配和去重，仓内只暂存/交换，普通读取不可见。节点稳定键并集按 `(命名域,键值)` 排序，秩 `1..N` 同时确定节点编号和创建序号，两个 next 值均为 `N+1`；`N==UINT64_MAX` 拒绝，仓库编号只取当前空仓非零编号。每个稳定键的身份版本必须从 1 严格连续到唯一最大版本，类型恒定，只有最大版本可以 `当前有效=true`；节点仓只安装最大版本为唯一运行期记录，低版本仅留持久审计，最大版本 false 安装为已删除。所有历史占用 `曾发布=true`，仅历史占用保留编号但不建立节点记录。内部编号只属本次运行期；发布后只与本次确定性映射逐值比较，不与 SQL/持久材料作为跨重启事实比较。关系内部编号同理按冻结稳定排序确定；索引只安装当前可重建项，移除历史仅作证据互证；幂等恢复只接收已发布记录及一一对应的正尝试序号侧账。任一仓最后发布非成功或代次开放失败立即故障隔离，不尝试跨仓伪回滚。
8. 诊断责任：提交/恢复服务是本地记录边界；数据操作、执行器、仓库、端口向上送出；确定性编码、SQL、恢复校验不得标为无适用错误分支。
9. `启动.应用程序.ixx` 只允许增加 P1A2 专项自检的真实登记边：无条件 import `海中鱼巣.核心.自检.节点直接身份结构写入`，以新适配函数 `运行节点直接类型化结构事务合同自检()` 调用 `运行节点直接身份结构写入自检()`，映射为编号 `WORLD-TREE-P1A2-S01`、名称 `节点直接类型化结构事务合同`、验收数量 `报告.验收.size()`、失败数量 `报告.失败数量`；在 `运行完整自检模式()` 以顺序号 `170` 登记，并把完整自检登记/执行期望从 `17` 精确更新为 `18`。不得改变其它 17 项编号、顺序、函数或分支，不建立新运行模式。
