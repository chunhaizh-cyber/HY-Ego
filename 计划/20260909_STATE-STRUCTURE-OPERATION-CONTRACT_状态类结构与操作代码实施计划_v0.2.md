## 1. 具名退回与修订裁决

执行侧退回两个无法按 v0.1 机械施工的问题：

1. 4212 v0.1冻结 `const L1事实基座服务&`，但同步清理必须调用唯一非 const `L1事实基座服务::执行L1物理清理`；owner写端口没有此入口，且禁止 `const_cast`。
2. 因果规范和因果代码正在独立重建，执行已停止并释放因果类文件，状态计划不能继续拥有该消费者。

4212 v0.2和详细设计 v0.2已裁决：状态服务持有同一实例的 `L1事实基座服务&`，只用其调用既有物理清理入口；普通创建和退出仍唯一走状态owner写端口，不修改L1。因果消费者迁移从本计划完全移除，等待因果正式合同发布后由后继重新扫描。

## 2. 目标和完成条件

按4212 v0.2与同名详细设计 v0.2，把现行状态类从旧“时间+多特征快照”整体切换为状态身份、正式FT、固定准确值、强时间四字段合同；补齐特征类窄只读核验；把存在、场景两个身份消费者迁移到窄入口。

完成条件：状态合同版本2、精确DTO和十一项公开函数实现；两种值表示、两种强时间及0成立；创建/重放、当前/历史读取、三项字段查询、退出、同步实例清理和共同身份读回闭合；旧v1生产声明/定义及存在/场景调用零命中；状态服务合法调用 L1 物理清理且零 `const_cast`；根工程Debug/Release x64隔离Rebuild成功；施工记录包含知识变更清单。

因果类、因果消费者旧调用和因果新合同不是本计划完成条件，不能因其未迁移判定本计划失败，也不能把本计划通过外推为因果接线完成。

## 5. 冻结接口和实现边界

4212 v0.2第2—6、11节全部C++名称、字段、枚举数值、签名、成功谓词和构造参数逐字实施；执行者不得改名、增加字段或兼容 overload。

- 特征类新增 `特征类型准确值核验请求/事实` 与 const `核验正式特征类型准确值`，物理位置为现有特征模块公开准确读合同附近；只复用现有私有读类型、解析值、值域和G/H守卫，零写。
- 状态类原文件整体替换为版本2；物理布局固定为普通节点、族归属关系、FT关系、互斥准确值、互斥时间、首次形成UTC技术值。
- 构造和成员使用 `L1事实基座服务&`。该引用唯一获准的写调用是 `执行L1物理清理`；创建、退出及其它普通状态写必须通过 `L1所有者范围写端口`，禁止 `const_cast`、禁止调用 `L1事实基座服务::提交中性写集`、禁止修改L1增加代理入口。
- 存在/场景只把旧 `查询状态` 调用改为 `确认当前状态结构身份`，不读取状态内容、不改变本类DTO或其它语义。
- 因果类不修改；其后继消费者合同不得在本计划中推测或兼容。
- 状态类公开函数全集和逐字段增查改退映射以详细设计第4.1、5节为准；不可变字段不建立失败setter。
- 所有新增/修改公开边界诊断责任为“向上送出”；不得加生产日志或测试入口。

5. 同步清理先通过状态owner写端口逻辑退出候选，再由持有的同一实例非 const L1引用调用唯一物理清理入口；不得把非 const L1引用扩展到普通写入。
6. 将存在、场景两个消费者迁移到窄当前身份确认并核对结果头；不触碰因果消费者。
7. 静态扫描旧符号和禁止依赖；隔离构建Debug/Release x64；只在允许文件内修复代码错误。若必须改变4212字段、DTO、错误映射、L1布局、生命周期或文件范围，返回计划支撑，不临场设计。
8. 更新施工记录，列出实际函数知识变化、验证、未覆盖边界和结果提交；精确提交并普通推送。

## 7. 非成功和收口

- 坏版本、零G/身份/预算、负时间或未知语义：入口拒绝、零载荷、零写。
- FT/值来源问题：按4212映射；不得默认0或创建F补救。
- 事实代次漂移：交换前零写；调用方重读。
- 同键异请求：幂等冲突；同请求按首次材料和首次截止收敛。
- 提交已确认后读回失败：保留事实和原键，返回内部不一致，不补写第二身份。
- 旧v1形状：旧格式不支持；不回退、不转换、不删除。
- 外部引用：退出/清理引用冲突；不级联跨owner。
- 因果独立切片导致的文件、语义或验证输入冲突：保留本切片现场，使用合法隔离输入或等待安全提交；不得修改因果材料求过编译。
- 构建错误属于本切片则修复；需要触及禁止文件、改变公开合同或受异主WIP影响时返回具名DRIFT。
