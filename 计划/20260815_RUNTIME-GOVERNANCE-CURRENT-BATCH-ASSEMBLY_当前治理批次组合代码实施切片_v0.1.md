## 4. 实现合同

模块固定 `export module 海中鱼巣.线程.路由.自我治理批次;`，只 import 详细设计第3节四个模块。按第4节精确导出配置、请求、见证、状态、原因、成功批次、结果和不可复制/不可移动服务；成功批次使用私有字段与 const getter，消息组不得公开可写。公开函数为非 const `noexcept`。

内部只保存三个 provider 引用、值式配置、一个路由互斥锁、固定从 0 开始的最后已完成序号和一个待完成槽；不接受非零恢复起点或调用方注入序号。后继装配必须保证路由在邮箱第一次冻结前构造并成为唯一冻结消费者，T02不得直调邮箱。槽保存完整邮箱状态、原因和批次。顺序固定：路由锁 -> 锁内静态准入 -> 无槽首次邮箱读取/有槽见证匹配 -> 任何邮箱载荷先无抛出接管完整邮箱结果 -> 每次补证前复核 `已冻结+原因无+合法严格后继批次` -> 只补缺失完整秒 -> 只补缺失共享截止 -> 按原顺序完整复制消息并形成成功候选 -> 候选逐字段互证 -> 无抛出推进序号、清槽、移动返回。

必须静态确认邮箱批次可无抛出移入待完成槽、成功候选可无抛出移动返回，消息析构和 optional 清槽不抛出。消息复制及其它可能抛出的构造全部发生在清槽前；`bad_alloc/length_error`返回资源失败/结果候选构造资源失败，其它异常或候选互证失败返回内部不一致/结果候选构造异常，均保留原槽并回显见证。路由锁覆盖全部校验和状态机；加锁异常是唯一允许双 optional 空且无法回显既有见证的内部不一致。邮箱锁在子调用返回前已经释放，禁止写“父级释放邮箱锁”。后到并发请求必须在锁内重新校验，陈旧上一序号不得读取邮箱。邮箱状态、原因、序号、消息组必须完整配对；任何携带载荷的坏邮箱结果先入槽，首次及全部重试都停在内部不一致、零时间/截止调用，不能因重试绕过形状复核；空载荷坏配对直接内部不一致且不伪造见证。

入口状态严格按详细设计第6节唯一映射：路由配置无效→内部不一致；请求形状无效→请求拒绝；固定配置/上一序号/见证不等→版本漂移；序号耗尽→内部不一致。父已预检非负等待，邮箱再返回请求拒绝固定为内部不一致，不得归责调用方。`无新完整秒`是合法成功。完整秒纪元/源漂移映射版本漂移，时间倒退/不可表示映射时间证据缺口，坏形状映射内部不一致；共享截止资源失败映射资源失败，其它非成功/坏形状映射内部不一致。所有锁内确认有槽的非成功都回显同一见证并保槽，无槽失败不伪造见证；加锁异常是双 optional 空的唯一例外。

删除 v0.1 的停止阶段版本字段，不建立停止 provider、缓存或调用方自报停止状态。待完成槽先完成；无槽后才能把邮箱已停止映射为父级已停止。

### 5.3 诊断责任

- 构造函数、getter、无抛出移动与删除的路由特殊成员：`无适用错误分支`；构造只借用并保存，不把配置有效性伪装成构造成功，实际准入由公开入口结构化返回。
- `已冻结自我治理批次`复制特殊成员：`向上送出`；标准容器复制异常原样交给显式复制调用方。本模块形成成功候选时不依赖该公开复制入口，而在 `冻结当前治理批次` 的具名异常映射内完成消息复制。
- `冻结当前治理批次`：`向上送出`；全部合法非成功和内部异常通过状态、原因及 optional 形状送给后继 T02，模块内不写日志、不弹窗、不重复记录。后继 T02 的最终责任边界另行重基线，本计划不接线也不伪造本地记录。
