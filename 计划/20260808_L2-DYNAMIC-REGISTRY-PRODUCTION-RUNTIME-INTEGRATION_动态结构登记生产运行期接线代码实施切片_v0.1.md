状态：设计就绪；登记后可执行。

## 1. 目标与完成条件

把现有 `L1动态服务` 接入唯一生产运行期上下文，并让 `生产运行期会话::启动` 在真实候选构造期间完成动态结构登记及公开权威读回：

- 上下文恰一动态服务成员，复用现有第一层服务；
- 固定生产配置提供动态登记幂等身份；
- 启动在状态登记成功后恰一次初始化动态登记；
- 动态登记非成功时停止后续初始化和候选发布；
- 上下文完整性重新读取动态登记，并与此前全部当前材料共同截止互证；
- 生产运行期结果回显动态登记结构化业务状态；
- 不新增第一层测试、自证、专项消费者或日志判定。

## 4. 实施合同

1. 在运行期上下文导入现有动态服务模块，并在状态服务之后构造唯一动态服务成员。
2. 新增初始化、当前读取、完整判断和 const / 非 const 服务访问器；全部只委托同一成员。
3. `完整()` 恰一次读取动态登记，要求已读取、登记完整，并与世界、场景、实际存在和状态登记的当前共同截止一致。
4. 固定配置新增动态登记幂等身份 `{1}`，同步等值和有效性；不接受外部覆盖。
5. 配置头与模块导入使用显式动态数据宏边界，避免重复声明动态 DTO。
6. 启动状态枚举新增动态登记初始化错误；启动结果新增动态登记业务状态。
7. 状态登记成功后，以其事实截止形成动态登记请求并恰一次调用上下文初始化入口。
8. 动态登记必须为已登记且携带完整登记，才能继续系统角色和概念活动；其它结果立即结构化失败。
9. 已有当前上下文返回已读取；未执行动态登记的早期失败保持入口拒绝；执行后的所有分支回显真实领域状态。
10. 最终成功只在候选完整、宿主发布成功且租约指向同一候选时返回。

## 5. 明确排除

- 修改 `L1动态服务`、动态 DTO、状态服务或第一层中性 CRUD；
- I64 特征定义、实例特征、首个 / 后继状态、动态事实、比较或因果；
- 自检模块、专项驱动、独立第一层验收、第二目标和覆盖补格；
- 日志 PASS、控制台文本、退出码或默认状态替代结构化领域结果；
- 崩溃、重启、断电和跨进程恢复；
- 普通应用旧栈迁移或旧世界树删除。

## 6. 验证

至少保存：

1. 五个允许路径的差异清单和 `git diff --check`；
2. 动态服务成员、构造和访问器唯一性；
3. 动态初始化在状态登记成功后、系统角色前恰一次；
4. 固定身份参与配置形成、等值和有效性；
5. 候选完整性对动态登记的公开读回和共同截止互证；
6. 生产代码新增 `自检`、`验收`、`PASS`、独立驱动或第二目标零命中；
7. Debug x64 完整重建；
8. Release x64 完整重建；
9. 双配置正式模块依赖扫描全部通过；
10. `python tools/check_specs.py --strict`；
11. Debug / Release 正式生产程序以生产运行期模式运行，结构化启动成功并自行退出零。

生产运行成功只证明本第二层动态登记服务完成自身初始化合同，并自然累计其实际中性新增、原子可读和当前查询使用。不得把构建、日志或本叶成功升级为第一层整体完善。
