## 1. 目标与完成条件

让生产运行期真实初始化现有特征定义服务的四节点结构登记，并经同一公开服务读回后才发布候选：

- 复用上下文现有唯一特征定义服务，不新增成员或代理；
- 固定生产配置提供登记幂等身份；
- 启动在动态登记成功后恰一次初始化特征定义登记；
- 非成功停止后续初始化和候选发布；
- 上下文完整性公开读回登记并与此前材料共同截止互证；
- 生产结果回显结构化特征定义状态；
- 不创建具体特征、实例或状态，不新增第一层测试、自证或日志判定。

从正式新 HEAD 完整重做 S0，核对：

1. 本计划精确 blob、设计提交和唯一可执行状态；

3. 特征定义服务一引用构造、四节点登记、公开读回及状态合同未漂移；
4. 上下文继续唯一拥有该服务和现有访问器，且尚无登记初始化或等价入口；
5. 动态登记生产接线结果仍存在，启动顺序和聚合结果与设计一致；

## 4. 实施合同

1. 在运行期上下文新增特征定义登记初始化、当前读取和完整判断，全部只委托现有唯一成员。
2. 保持现有特征定义服务构造、成员和 const / 非 const 访问器数量不变。
3. `完整()` 恰一次读取登记，要求已读取、登记完整，并与世界、场景、实际存在、状态和动态登记的当前共同截止一致。
4. 固定配置新增登记幂等身份 `{1}`，同步全等和有效性；不接受外部覆盖。
5. 配置头与模块导入使用显式特征定义数据宏边界。
6. 启动状态新增特征定义登记初始化错误；启动结果新增特征定义登记业务状态。
7. 动态登记成功后，以其事实截止形成请求并恰一次调用上下文初始化入口。
8. 只接受已提交 / 幂等读回且登记完整；其它结果立即结构化失败。
9. 已有当前上下文返回已读取；早期失败保持入口拒绝；执行后的分支回显真实状态。
10. 最终成功只在候选完整、宿主发布成功且租约指向同一候选时返回。

## 5. 明确排除

- 具体 I64 特征定义、值域、实例特征、实例值或首个状态；
- 修改特征定义服务、实例特征服务、状态 / 动态服务或第一层中性 CRUD；
- 自检、专项驱动、独立第一层验收、第二目标和覆盖补格；
- 日志 PASS、控制台文本或退出码替代结构化领域结果；
- 崩溃、重启、断电和跨进程恢复；
- 普通应用旧栈迁移或旧世界树删除。

## 6. 验证

至少保存：

1. 五个允许路径差异清单和 `git diff --check`；
2. 特征定义服务成员 / 构造 / 访问器数量不变，初始化与读取委托各一；
3. 初始化调用位于动态登记成功后、系统角色前且恰一次；
4. 固定身份参与配置形成、全等和有效性；
5. 候选完整性公开读回特征定义登记并互证共同截止；
6. 生产代码新增 `自检`、`验收`、`PASS`、独立驱动或第二目标零命中；
7. Debug / Release x64 完整重建；
8. 双配置模块依赖扫描全部通过；
9. `python tools/check_specs.py --strict`；
10. Debug / Release 正式生产运行期模式结构化成功并自行退出零。

生产运行成功只证明本第二层特征定义登记服务完成自己的初始化合同，并自然累计四节点中性新增、原子可读和当前查询；不得升级为具体特征、实例特征或第一层整体完善。
