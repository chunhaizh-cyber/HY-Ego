# 数据服务最终需求清单

日期：2026-08-15
版本：v0.1
身份：`BIZ-DATA-EXTERNAL-SERVICE-REQUIREMENTS`
状态：当前目标业务所需公开服务需求基线

## 1. 文件用途

本文件是 BIZ 向基础数据系统提出的唯一总清单。它只回答四件事：

```text
调用哪个公开服务
+ 根据什么参数读取或提交
+ 返回什么结构化数据
+ 空结果和失败怎样区分
```

“最终”表示本文件是当前目标业务范围内的最终汇总入口，不再通过聊天消息维护另一份接口清单。它不表示所有 C++ ABI 已实现，也不规定基础数据系统的内部架构、实现或施工顺序。

本文件中的“公开服务”均指 BIZ 可以通过普通应用上下文取得并调用的强类型服务。BIZ 不直达通用事实仓，不传入内部路由选择，不根据裸稳定编码猜测对象类型。

## 2. 所有公开服务的共同合同

### 2.1 读取请求

读取请求按能力需要包含：

- 合同版本；
- 当前或历史读取类别；
- 一个或多个强类型稳定身份；
- 期望事实代次或事实截止；
- 需要完整枚举时的数量预算、分页限制或继续游标；
- 业务已经冻结的范围、规则或版本身份。

只有具名“读取全部当前组”入口可以把 `期望事实代次=0` 定义为“选择调用时最新当前快照”。单对象读取、条件读取和全部写请求必须使用非零事实代次守卫。

### 2.2 写请求

新增、替换、迁移、退出或发布请求按能力需要包含：

- 完整强类型提交材料；
- 非零期望事实代次；
- 非零幂等身份；
- 全部引用对象的强类型身份和合同版本；
- 发生时间、来源身份或规则版本（仅当目标结构本身需要保存这些字段时）。

同一幂等身份和逐字段相同请求必须收敛为首次结果；同键异义必须结构化拒绝。资源失败或发布结果未知时，调用方只会使用原幂等身份和原完整请求收敛，不会换键重试。

### 2.3 结构化结果

每个结果至少能够区分：

```text
已读取 / 已提交 / 精确重复
未找到 / 已退出 / 属性未设置 / 合法空组
事实代次漂移 / 幂等冲突 / 引用冲突 / 请求拒绝
资源失败 / 发布结果未知 / 内部不一致
```

成功结果必须带一个非零事实截止以及完整值式事实或完整事实组。失败结果不得夹带可被误当成成功的对象、变更代次或部分事实。一次组合读取中的节点、关系、值、生命周期和身份来源必须来自同一事实截止。

## 4. 本清单不要求的基础数据公开服务

当前目标业务没有冻结语言、语素、词条、词性或概念名称的数据消费接口。概念本体根和普通概念必须保持语言无关；后续高级思维或语言表达目标出现真实业务叶时，再向本文件增加相应公开服务需求，不能因“未来可能需要”提前制造现行 ABI。

线程生命周期、线程队列、控制面板投影、事件日志、缓存统计、外设采集、外设原始材料、持久证据和纯值算法不属于基础数据公开服务，不得列入或通过一个万能 DATA 查询口转发。

| DATA-EXT-10—14 | 业务所需服务边界已经由目标业务叶识别；精确 DTO 字段、C++ 名称和 ABI 尚需对应详细设计逐项冻结，不能宣称当前已实现 |

DATA 未实现或 ABI 尚未发布不阻断 BIZ 继续细化和编写消费端占位代码。占位代码只能显式返回“接口待接线”或保留注释，不得生成机器事实或把空结果当成功。真实接线时以本清单的能力语义和 DATA 最终公开 ABI 逐项机械匹配并验证。

## 6. 维护规则

1. 新的 BIZ 详细设计若需要基础数据，必须先在本文件新增或复用一项公开能力，再在详细设计中引用编号。
2. 若现有服务能够通过参数化操作满足需求，不新增同义服务或业务专用快捷入口。
3. 若新需求会改变强类型对象、写入结果、合法空、失败语义或事务边界，必须修订本文件版本；只改变 DATA 内部实现不修订本文件。
4. DATA 完成接口后，只更新“ABI 与实现状态”和精确公开类型链接，不复制其内部实现与过程记录。
5. 本文件只维护公开需求，不自动创建实现任务或改变其它任务的执行状态。
