## 3. 冻结ABI

存在类新增`任务方法实例投影专用合同版本=1`、23个状态、八个DTO：结构类型、来源、关系
项、投影、规格请求、组查询请求、规格结果、组结果，并新增两个const入口：

```cpp
任务方法实例投影写集规格结果 形成任务方法实例投影写集规格(
    const 任务方法实例投影写集规格请求&) const;
任务方法实例投影组结果 读取任务方法实例投影组(
    const 任务方法实例投影组查询请求&) const;
```

`任务方法实例投影结构类型`精确包含任务Vt关系类型、方法Vm关系类型和五个I关系类型。
来源DTO继续强制保存M→Vm关系编码；存在类以显式方法Vm类型调用现有专用查询，精确证明
并返回该编码，禁止未知类型反查、伪造编码或新增重复来源锚点。

任务类合同升至3，原31状态数值不变并追加10状态；构造新增方法类只读引用，结构类型追加
五个I关系类型和一个方法Vm关系类型，新增实例化请求/读取请求/单项结果/组结果四DTO和
两个公开入口：

```cpp
任务类方法实例投影结果 实例化方法虚拟存在到任务虚拟存在(
    const 任务类方法实例化请求&);
任务类方法实例投影组结果 读取任务方法实例投影组(
    const 任务类方法实例投影组读取请求&) const;
```

完整字段顺序、成功谓词、固定本地键、关系角色、稳定排序、唯一键和失败优先级以详细设计
第3—7节为唯一施工合同，执行者不得临场删减或改义。

## 4. 施工步骤

1. 在存在类实现独立DTO、完整性谓词和失败构造；不import方法/任务，不碰普通存在写端口。
2. 实现组读取：证明T↔Vt、重建Vt→I→M/Vm/C/R；从M取得method owner，以显式方法Vm
   类型调用`查询方法虚拟存在`并精确恢复M→Vm关系编码；执行owner、当前性、唯一、连续
   顺序、预算和稳定排序检查，任一缺口零载荷。
3. 实现规格形成：验证任务侧六类型和方法侧方法Vm类型/跨owner端点，规范化C/R，排除同Vt+M重复，
   形成task owner的一节点、`3+n+m`关系无权限原子写集，零值/属性/退出。
4. 任务类import方法类，升级版本/状态/构造/结构类型而不改变原状态数值和原字段顺序；
   结构配置显式接收与方法类构造相同的方法Vm类型编码，但不读取方法类私有成员；加入四
   DTO、成功谓词和两个入口。
5. 实现写入口固定流水：首次材料、任务/Vt/登记M、方法完整读回、规范化、规格、自有端口
   提交、Gend组读回与精确比较；发布未知只接受原请求重放。
6. 实现只读组入口及全部状态映射；施工记录列出实际ABI、函数级知识变更、白名单零调用
   证明和全部未验证边界。

## 5. DRIFT与停工

以下任一出现即保留现场并具名退回计划支撑：需要method owner改Vt；需要Vm/Vt身份合一、
移动节点或以简单Vt→Vm替代I；需要复制特征值、当前参数/状态/授权/运行结果；需要路径、
采用、选择、轮次、冻结或正式实例方法语义；存在类必须反向import方法/任务；任务类无法以
当前方法类同G0读全M/Vm/C/R；L1不能用稳定跨owner端点形成同task owner原子写集；需要
旧L2、普通存在新增、第二task owner端口、额外生产文件或改变既有owner。若实现试图删除
来源DTO的M→Vm关系编码、在未知类型下反查、只凭I→Vm推断抽象Vm资格，亦为DRIFT。

纯C++实现错误、状态映射遗漏或允许文件内辅助函数不足由执行者在本切片修复，不构成DRIFT。
