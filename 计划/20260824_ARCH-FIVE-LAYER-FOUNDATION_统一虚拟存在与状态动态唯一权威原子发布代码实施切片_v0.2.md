## 1. 目标与完成条件

在不建立第二状态/动态权威的前提下，提供通用虚拟存在，并提供一个 ARCH-L2 专用状态动态组合迁移入口。状态和动态继续各自拥有唯一技术 owner；双参与者迁移经 L1 中性事务凭证一次发布一个事实代次。执行者不得临场选择 owner 合并、联合/桥接 DTO、串行提交、失败映射或重试策略。该入口只消费调用方已完成筹办/冻结并取得一份自我现实执行授权后的结构请求；不实现想/看治理、授权签发、安全硬否决、活动资格、调度配额、轮次结算或后继决议。

完成条件：强类型 ABI 与稳定身份已落地；普通应用只装配一套 L1 运行包、状态 owner、动态 owner、通用虚拟存在服务和组合 provider；首次/重复/异义/漂移/许可拒绝/内部不一致均按合同返回；成功后五组结果同一截止完整读回。任务、方法、L3/L5 和业务消费者不在本计划。

## 2. 依据、当前事实与唯一裁决

- 0050、4030、4230 及 ARCH 层级规则：ARCH-L2/DATA-L2 是强类型结构，L3/L4/L5 不直写 L1；七结构 owner 两两不同，跨族操作不属于普通 CRUD。
- 当前状态/动态服务各持独占 L1 写端口，现有 API 只有单 owner 提交；不得把两次提交冒充一次原子发布。
- 动态主体固定使用 `L2存在身份`，前/后状态固定使用 `L2状态身份`；通用虚拟存在服务返回同一存在身份，来源方法只是不透明稳定编码。
- 唯一补齐是 L1 中性双参与者事务和跨参与者本地引用，不修改普通 owner-scoped CRUD 语义。
- 新正式治理语义只作为调用方前置：`想`/`看`不请求业务授权；现实改变步骤须在执行前取得一份现实执行授权；安全硬否决、活动资格、调度配额和授权分账不进入本 provider。目标未达成由上游形成轮次结算，轮次收束后等待正式后继决议。

## 4. 实施顺序

1. 在 L1 CRUD 数据合同中加入合同版本 1 的双参与者序号、事务内跨 owner 本地引用、请求/结果和 move-only 事务凭证；仓库在同一独占锁内完成两 owner 候选校验、幂等绑定、单代次发布和零写失败。
2. 为通用虚拟存在新增 DTO、唯一 owner、增/读/退及身份来源；返回 `L2存在身份`，不含名称、不进入场景树。
3. 为状态/动态服务增加仅供组合 provider 的参与者写集形成函数；只读共同 G0，构造本 owner 写集和局部键，不提交、不推进代次。
4. 新增组合 provider，固定请求字段、组合幂等域、状态参与者序号 1、动态参与者序号 2；以 L1 凭证一次提交旧状态退出、新状态、动态主体/前后状态/来源及值。
5. 普通应用按存在、特征、状态、动态顺序建立 owner；凭证绑定状态/动态端口的非拥有引用，provider 通过公开服务 getter 交付，禁止任务/方法另建实例。
6. 成功后按同一 G1 读回新状态、动态、主体来源和旧状态历史；不成功五组载荷为空，不等待、不重试、不吞错。

## 5. 失败、幂等、发布未知与兼容

完整请求同键同义返回首次原结果，不推进代次；任一公开字段不同返回幂等冲突。期望代次、参与者许可、端点、引用解析、资源、内部不一致均零载荷零变化。发布未知只用原组合幂等身份读取首次材料收敛，禁止拆分提交或生成新身份。组合入口无撤销；旧普通 CRUD、owner 身份、稳定编码和历史读取保持兼容。旧任务/方法事实只有在后继迁移计划完成后才可退出。

## 6. 验证矩阵与完成边界

- 通用虚拟存在增、精确重复、异义、当前/历史、引用保护、退出；
- 状态/动态现有 CRUD 全回归，动态主体为存在身份，前/后为状态身份；
- 双参与者首次成功、同义/异义、G0 漂移、任一 owner 许可拒绝、跨参与者本地键、引用坏形状、零写和发布未知收敛；
- 成功后五组结果同 G1 完整读回；普通单 owner 入口不能形成半提交；
- Debug/Release、D:\TEMP 隔离专项、strict、diff-check、生产目标无专项痕迹。
