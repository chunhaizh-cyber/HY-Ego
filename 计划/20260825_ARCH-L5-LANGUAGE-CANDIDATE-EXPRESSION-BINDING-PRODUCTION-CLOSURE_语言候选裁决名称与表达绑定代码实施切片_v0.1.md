## 3. 实施步骤

1. 按现有 L2 DTO / service 实现正式语言准备，首次调用 `新增语言`，随后按登记键和按身份双读回；精确重复使用正式结果，不使用硬编码语言字符串。
2. 实现 `语言候选路由业务::形成候选`：按词条读取完整名称关系，逐项取得目标正式强类型，按冻结排序和预算返回结果。
3. 实现 `语言候选裁决业务::裁决`：只在唯一候选和完整上下文下形成具名证据；其余状态不调用名称写入口。
4. 实现 `概念名称绑定业务::提交裁决后绑定`：校验证据，调用 L2 名称新增，取得 G1 后按名称 / 概念 / 词条三路读回；精确重复原结果，异义冲突零写。
5. 实现 `自然语言表达业务::形成表达`：只读绑定、上下文和已登记表达材料，返回值式表达。
6. 由普通应用只装配一份 L2 / L5 provider；加入真实端到端消费者，禁止测试假写入口。

## 5. 失败、幂等与读回

L5 业务错误必须使用详细设计冻结的状态闭集；所有非成功结果清空对应业务载荷。L2 名称写入前的证据、G0、候选和引用失败必须零写；L2 已返回提交后只按正式 L2 结果报告，不声称回滚。相同绑定幂等键和同义裁决返回原关系及三路读回，不推进新代次；异义键、异义当前和多首选冲突零写。
