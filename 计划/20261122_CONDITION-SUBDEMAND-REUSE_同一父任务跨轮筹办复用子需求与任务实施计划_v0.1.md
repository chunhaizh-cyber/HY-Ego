# 同一父任务跨轮筹办复用子需求与任务实施计划

版本 v0.1。起草于 2026-11-22，2026-11-23 完成评审。施工状态和精确版本以计划索引为准。目标为 [任务消费模拟学习完善的方法](../目标/活动/GOAL-TASK-LEARNED-METHOD-CONSUMPTION.md)。机器语义沿用 [5260 §5.1](../规范/5260_子规范_任务治理详细合同.md)、[3100](../规范/3100_根规范_需求.md) 和 [3200](../规范/3200_根规范_任务.md)，本计划承载私有交接设计。

## 1. 目标及已确认事实

模拟学习或必要材料变化后，同一父任务按正式条件重新筹办。若它再次提出原父需求下的同义条件目标，自我使用需求所有者返回的同一子 D，管理线程通过任务所有者读回同一子 T。新筹办依据服务新一轮交接。子任务已具备执行组织、在途执行或终结时保留事实及任务身份，后续启用沿正式资格和状态迁移。

核对起点为 `c4837e1103b52b4bf96caf58eef7e9c9863b06aa` 及本目标独立候选。现行值目标复用由 `新_需求类::建立或取得普通需求已核验` 进入 `建立或取得普通需求来源可抛内部` 的正式发布链以父需求、来源父任务及完整目标裁决。`新_任务类::核同方法条件准备静态批已加锁`、`接收已确认方法条件准备依据` 与管理线程的 `待交付条件准备组` 把整轮提议固定在子 D 下。新一轮可能仍需要同一个目标，同时实际配对、条件项序号或其它已知条件已经不同；此时需求可复用，任务交接会因为旧凭据比较失败。旧设计约束位于已退出的 `SERVICE-ACQUISITION-SOURCE-PREDECESSOR` §9.19.3。当前源码中凭据表的消费者仅为条件准备身份、接收、承接三个环节，没有跨进程恢复或祖链历史查询消费者。窄候选 run-11 已通过普通入口验证首次子需求分解、父任务执行和正常退出。尚未触发同一父任务再次提出同义缺口，不能用该轮数据证明复用。

## 2. 交接设计

1. **业务身份。** 自我和需求所有者照常形成正式成功回执。复用仍由需求所有者裁决。任务所有者仍以已有唯一 D/T 关联入口处理，父任务、目标、来源类型、来源父任务及需要的单位、域或引用内容继续按正式对象读取。准备凭据的键不参与 D/T 去重。
2. **筹办身份。** 以已存在的父任务节点、父筹办工作号及子 D 形成请求键，使用 `新任务筹办反馈定位.原工作.工作编号`，工作号只在同一个管理线程实现实例内唯一。普通装配每次建立成对的任务服务和管理线程。若同一任务服务有管理所有者替换入口，任务侧凭据须在旧管理线程停止、等待其交付和后台工作结束后，依据既有管理所有权交接清理该实例的投影，再让新实例接管。不得把新实例从 1 起的工作号解释为旧回执。管理线程继续用完整 `新任务筹办反馈定位` 判当前记录；私有任务交接接收该工作号，原提议继续给出父 T，确认项给出子 D。任务所有者的 `方法条件准备承接凭据` 增加本次工作号。其静态读回校核正式父子目标及本轮来源，已有其它工作号的凭据不参与比较。同一工作重复传递必须携同一个正式确认项及原提议，同工作异义仍走既有结构冲突。
3. **投递与确认。** 在 `提交自我筹办裁决` 保留原定位、正式 self 回执、每个成功子 D 在这一回执内唯一以及预分配后整体提交记录的边界。预备、待交付、取项和回收均用同一请求键。`尝试交付条件准备依据` 解锁调用，回锁只精确移除实际完成投递的键和指针。只有该完整原定位仍是当前记录，才置对应项交付位。同一次原工作等待补交时按原节奏重试。停止信号可以阻止尚未开始的调用，已经发表的成功依照原键收尾。因来源变化而保留的旧待项，只有当前正式记录已明确进入更新的工作、且本次返回确定没有交付，才按相同键与指针去掉；不按快照指针推断调用已经启动，也不新增提前清理或认领流程。仍是当前定位时，交付非成功不置为已交付。合法来源变化沿原重筹办路径，资源或依赖暂缺按原节奏重读，不嵌套持有两个所有者的锁。
4. **任务承接。** 管理后台从当前 `已确认子需求组` 取得原项，以同一工作号调用 `承接已确认条件子需求`。该私有入口取得同次不可变凭据，再按现行代码读当前目标、准备必要性、唯一子任务身份和任务状态。待材料或底层前提已变化由原调度重新读正式事实；没有许可时保持等待。严格的正式写入和现有 L1 联合提交保留。直接消费任务所有者既有的关联或承接结果中的正式读回。管理线程不额外扫描任务全集或重读同一关联。保留实际已建立的 D/T 前缀；没有成功的 T 回执时按已取得的正式事实记录。
5. **生命周期及收束。** 两张表都使用请求键；同一 D 的旧条目不得覆写新工作。任务侧已接收凭据在过程内随任务服务保留，以容许同一已接收工作的补交和迟到确认。管理侧对已确认交付的待项按原键与指针精确收尾，不根据新记录把旧交付改报为新回执。同工作同值已经交付时从已有不可变凭据返回「已复用」，无需再全量比对正式定义；实际承接按当前信息判必要性。旧 W2 的承接调度走已有定位保护。竞争中已经建立的唯一 D/T 关联仍可供新 W2 读回；旧工作回执不发布新的执行许可。保留在途或终结任务，新一轮确认不会重放动作、结算或状态生成。完成后再次需要，仍按 `3200` 的现行任务复核和状态迁移办理。

## 3. 写集、依赖及顺序

允许范围为 `海中鱼巣/领域/新_任务类.h`、`海中鱼巣/领域/新_任务类.cpp` 和 `海中鱼巣/线程/新_任务管理线程类.cpp`。只改上述私有 DTO、重复身份、交接和实际回执的调试投影；配对、目标语义、公开 DTO、L1 读写、需求 owner、本能方法及语言转换合约均沿用当前实现。后台日志延用现有 `PARAM_BINDING` 的「管理处理条件子需求承接」，取已持有的父工作号和返回的实际子 T。按现有日志开关输出。

1. S0 核对当前分支、依赖和唯一写入所有者。先证明正式工程基线或经核准的最小候选能从普通入口启动。以该实际基线核对工作号在同一管理线程实现实例内单调分配、任务服务与管理线程实例的正常装配和所有权交接，及三个现行凭据消费者。任何活跃写入重叠按项目协作规则交接。
2. 一次实施私有的请求身份、两侧容器和后台承接消费者；先核旧键的每个读取、写入、精确重试和退出分支，再整体编译。不允许按子 D 回退查任意历史凭据，也不新增新旧双路径。
3. 使用实际工程 Release/x64 正常入口、正式网页或外设材料复验。发生身份变化或未取得合法材料时保存该轮停点。同一运行中继续观察原父任务定向复核和执行。启动代码、候选迁移和本修复分别留具体输入清单及源码摘要。

## 4. 取证与完成判据

- 首次遇到实际缺口：读回父 D/T、工作号、配对和实参，正式子 D 建立后读回其唯一子 T；条件未齐期间父任务保持具名等待且无动作。
- 同一 W2 重试：原定位和正式回执身份可重入，核对同一子 D/T 及不存在重复动作。由真实配对或条件来源变化所引起的下一轮独立取证，记录变化前后的实际配对或条件值。
- 第二个 W2 持有同义目标：自我回执须为「已复用」，子 D 与首次一致；任务后台从正式任务接收结果取得相同子 T。旧回执晚到不推进新记录。停止或过期与实际关联相遇时按正式结果保留已发生的前缀。已执行或终结子任务保留原执行、动作、状态和贡献记录。未从正常入口发生某反向分支时如实记未触发，不使用定时重复提交、直接造任务或旧日志证明该分支。
- 当真实材料满足原条件，原父任务根据最新事实复核并执行。保存实际动作、正式状态、评估、读取的采用配对和实参、网页关闭回执与实际退出码。候选正常退出与精确主线构建验收分别举证。
