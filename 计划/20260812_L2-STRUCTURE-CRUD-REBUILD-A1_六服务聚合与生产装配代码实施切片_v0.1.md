## 1. 目标、范围与完成条件

在 T1 / T2、DYN1 / DYN2、C1 / C2 与 S-ID 的最终真实结果之上，新建唯一 `L2结构聚合服务`，只按非 owning 引用持有并公开场景、存在、特征、状态、动态、因果六个现有唯一服务；再由唯一普通应用 provider 在六服务全部构造成功后形成该聚合，并由同一 `普通应用上下文` 唯一持有其生命周期。

完成必须同时成立：

1. 唯一新模块为 `海中鱼巣/领域/服务.L2结构聚合.ixx`，模块名为 `海中鱼巣.领域.服务.L2结构聚合`，唯一导出类型为 `L2结构聚合服务`；
2. 聚合内部六个成员严格是现有服务对象的非 owning 左值引用，顺序为 `场景、存在、特征、状态、动态、因果`；零指针、零智能指针、零 owner、零 raw 写端口、零仓库、零事务、零缓存和零生命周期延长；
3. 聚合不可默认构造、不可复制、不可移动；构造只保存六个引用且为 `noexcept`，不构造、替换或销毁任一服务；
4. 唯一公开面是六组 const / 非 const 服务访问器；每次都直接返回同一成员引用，零缓存、零代理对象、零 DTO 映射、零状态映射、零 CRUD 包装和零中央分派；
5. 普通应用保持 G2 的真实 provider 构造顺序 `存在 -> 特征定义 / 实例 -> 状态 -> 动态 -> 因果 -> 场景`，六服务成功后才构造聚合；聚合构造参数的六类公开顺序不得反向改变 provider 依赖顺序；
6. `普通应用上下文` 继续唯一 owning 同一 L1 运行包、六个服务 `std::unique_ptr` 和一个聚合 `std::unique_ptr`；聚合成员声明在六服务之后，按 C++ 逆序析构先于六服务销毁；
7. 普通应用只从最终最大状态值后连续追加 `L2结构聚合服务构造失败`，具体数值在激活时绑定七个前置结果的最终 provider ABI，不按当前未实现前缀猜测；聚合分配或构造异常返回该状态且不发布半上下文；
8. 根工程与 filters 只增加该一个新模块登记；不新增数据头、`.cpp`、仓库、索引、缓存、恢复、日志、SQL、L1 依赖或第二 provider；
9. 专项验证证明普通应用直接 getter 与聚合六组 getter 逐一同址、const / 非 const 同址、重复读取同址、聚合零拥有和零包装；结果与永久记录发布后，三份临时验证文件由独立清理提交精确删除；
10. A1 实施只证明唯一生产装配形成六服务聚合及透明取回，不证明启动入口已有业务消费者、不证明完整 L2 业务闭环，也不替代后继独立集成验收。

`L2结构聚合服务` 不是第七数据服务、中央身份服务、旧世界树门面、业务协调器、装配者或第二写入口。非 const 访问器允许调用方取得原服务的原公开面，但写入函数、DTO 解释、owner 和事务仍唯一属于被返回的原服务；A1 自身没有写函数，也不复制任何服务函数签名。

## 6. 普通应用唯一装配与生命周期

`海中鱼巣/装配.普通应用.ixx` 在六个服务模块 import 之后追加聚合模块 import。普通应用 provider 保持最终六服务真实构造代码和顺序不变；场景服务成功后执行：

```cpp
std::unique_ptr<L2结构聚合服务> 聚合服务;
try {
    聚合服务 = std::make_unique<L2结构聚合服务>(
        *场景服务, *存在服务, *特征服务,
        *状态服务, *动态服务, *因果服务);
} catch (...) {
    return {普通应用装配状态::L2结构聚合服务构造失败, nullptr};
}
```

这里的参数顺序表达 4230 六类公开顺序，不改变六个局部服务此前按 G2 依赖顺序形成的事实。A1 不调用 owner 签发器，不接收运行包、L1 服务或任何交付，不创建六服务，也不拥有 provider 职责。

`普通应用上下文` 私有构造参数在最终六个服务 `unique_ptr` 后追加 `std::unique_ptr<L2结构聚合服务>&& 聚合服务`。成员声明保持运行包在前、六服务严格按最终 provider 顺序在中、`std::unique_ptr<L2结构聚合服务> 聚合服务_` 最后；构造初始化顺序与声明一致。因为成员逆序析构，聚合先销毁，随后场景、因果、动态、状态、特征、存在和运行包按最终声明逆序销毁，聚合引用在其整个存活期始终有效。

上下文新增且只新增：

```cpp
L2结构聚合服务& 取得L2结构聚合服务() noexcept;
const L2结构聚合服务& 取得L2结构聚合服务() const noexcept;
```

两者直接返回 `*聚合服务_`。不得删除六服务既有直接 getter，不得令聚合替代其存储，也不得让上下文或聚合复制服务实例。上下文最终发布仍只发生一次：聚合形成失败时局部智能指针按逆序清理，不返回上下文；成功时一次移动同一运行包、六服务与聚合进入上下文。

`普通应用装配状态` 只从七个前置结果最终最大状态后连续追加：

```cpp
L2结构聚合服务构造失败 = 最终最大状态值 + 1
```

执行者必须在 S0 将表达式替换为真实连续整数，不在生产枚举中保留伪表达式。不得占用、重排或改义前置状态，也不得用通用 `构造失败` 吞并聚合阶段。聚合引用构造自身为 `noexcept`；该专属状态主要封闭 `make_unique` 分配异常，并保留最终 ABI 对聚合阶段的精确诊断。真实分配失败若未做无侵入故障注入，记录为 `NOT_RUN`，禁止添加生产测试钩子。
