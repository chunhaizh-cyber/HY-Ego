## 白名单与正式结构

1. 保留 79 个既有结构自键、字面及校验顺序，保持两种单位、九分量角色和既有 `1503/1513` 槽不变。新增九个**定位已有概念角色**的恢复标记，仍用同宿主同键的直接字符串和 4015 现有 `发表基础结构自键` / `读取基础结构自键`。固定前缀 `HY-Ego/7160/先天角色/`、后缀 `/v1`，中间按 `先天特征概念集合` 的现有根成员顺序分别取 `三维空间坐标`、`三维空间尺寸`、`RGB颜色`、`二维轮廓`、`三维体素`、`服务任务集合`、`服务对象需求集合`、`交互对象集合`、`需求`。只在九根沿原冷建与定义核验全部成功后，一批为现有九 C 发表。根间、两组间和与 `1503/1513` 槽目标均互异。没有字段键分配、槽编号分配或第二份关系。旧暖库缺项拒绝并保留原字节；对已绑定权威不补键或造根。
2. 九根只允许同根自己的这一个新标记，保持 `获取特征概念`、`读取特征概念定义保护` 的原语义和读取路径。不得把自键加到先天槽记录、`1503/1513` 槽目标或类别根。修正 `尝试删除零引用叶概念`，唯一父已核验后，若父为 `特征概念树`，沿 `尝试回收零引用值域` 的既有根保留原则返回 `无须删除`。自键不进入删除白名单，保留子域叶和其它已有清理行为。

### 九根定义核验

三种结构化根分别是三维坐标（X/Y/Z、毫米、有符号 I64 全域）、三维尺寸（X/Y/Z跨度、毫米、`[0, INT64_MAX]`）和 RGB（三色角色、无分量单位、`[0,255]`）。三种均为 I64数组、`完整材料精确`、`完整材料精确集合`，根无单位。分量引用恰三项且互异，分量节点类型正确，顺序恰 0–2，物理类型恰 I64标量，角色/单位及展平区间按恢复的 79 键精确核对。其它六根均使用整数 1 的全材料域标志、无单位。二维轮廓和三维体素使用各自维度的物理类型、`完整材料精确`、`完整材料精确集合`，服务任务集合为 U64数组、`服务任务集合身份判等`、`不自动聚合`，旧服务对象需求集合为 U64数组、`需求集合身份判等`、`完整材料精确集合`，交互对象集合为 U64数组、`存在集合身份判等`、`完整材料精确集合`，需求为直接需求节点引用、`需求身份精确`、`不自动聚合`。对每根核对类型、材料、比较、聚合、非负唯一实例计数、与其定义一致的唯一值域表示，保留正式名称引用且不借其判定身份。概念类型、材料、值域结构、比较、聚合和单位必须完整匹配，实例计数与名称沿独立结构校验。读回不能用空对象或默认定义补齐。

## 暖路径及持有周期

1. `概念_特征类.h/.cpp` 增加仅由 `新_世界树类` 访问的私有 `特征概念规则状态 恢复当前权威(const 新_特征值类&, const 基础持久视图&) noexcept`，将绑定视图与 `全局基础数据集` 的已绑定会话核同，重新读回完整候选。取得原 `特征概念树互斥` 后再次检查视图。按 79 表恢复现有结构锚点，并从九根候选装入现有 `先天概念`，值读口只注入同一世界持有者的已恢复值服务地址。可将表的节点指针由 `const 稳定编码*` 调为 `稳定编码*` 以共用原映射。安装前留存现有锚点和每实例的值服务指针，在同一递归锁下用 `获取先天特征概念`、`读取特征概念定义保护` 核对九 C 的 `定义.节点`、完整定义和保护组中的直属父边，再核同当前视图。现有回执中名为 `类型根` 的投影不作独立 FT 核验依据。任何失败或异常均在解锁前恢复原进程引用，不产生事实写入。仅空锚点可首次安装，安装成功时在原互斥下写入唯一进程内恢复持有者指针（类型 `const 概念_特征类*`）；已就绪只允许同实例和同一值地址的完全匹配复用，非空或部分不同返回 `内部不一致`。`初始化` 已绑定时只认可已由本实例和所传值地址恢复的结构，不走旧冷建或结构补齐；原未绑定分支不变。
   概念所有者的 `~概念_特征类() noexcept override` 只在本实例等于该恢复持有者时，持原互斥清空 79 个进程引用、九根集合、值读口与恢复持有者。候选在外层校验失败时析构也走此路径，常规冷建实例析构沿旧行为。实际世界按成员声明顺序先回收依赖再回收概念，值服务随后销毁。无底座事实清理。
2. `新_世界树类.h/.cpp` 增加启动专用 `特征概念规则状态 恢复已绑定特征概念(const 基础持久视图&) noexcept`，只转交本实例字段 `特征概念服务_` 和 `特征值服务_`，不置世界 `已初始化_`。现有 `新_世界树类()` 内构造值服务的 `make_unique` 可报告资源失败，声明与定义取消阻止分配异常外传的 `noexcept`，普通既有装配 catch 和暖装配 catch 统一处理。各其它 owner 沿原构造注入接口，不调用其业务初始化。
3. `装配.普通应用.h/.cpp` 增加启动专用 `普通应用恢复基础事实结果 恢复普通应用基础事实(const 普通应用配置&, const 基础持久视图&, const 新特征值信息& 空集合) noexcept`，结果字段为 `新特征值运行恢复状态 值`、`特征概念规则状态 概念`，分别默认 `未绑定`、`读取接口未装配`。在 `上下文锁` 下只接受合法配置及尚无 `上下文` 的启动阶段，配置或上下文不符时值阶段报告 `结构不一致`。前提是该视图仍是全局已绑定会话的当前视图，已绑定但视图不同报告 `前提已变化`。用实际 `普通应用上下文` 类型构造局部候选，从它的 `世界事实.特征值服务` 调用 `恢复当前权威`，用原 `读取特征值保护` 和 `查询特征值` 核空 U64 身份与材料（结构化保护返回资源失败时原样上送，其余不符沿现有值探查的结构不一致），再调用同一候选世界的 `恢复已绑定特征概念`。两提供者均成功且当前视图未变时，以无抛出移动交给现有 `上下文` 指针，`装配结果` 保持空。值/概念阶段遇到 `bad_alloc` 或 `length_error` 各归所属阶段的 `资源失败`，其它未预期异常不伪造成功或正常空读。未完成时解锁后回收候选，已有普通回收路径维持工作线程、宿主和回调的析构先后。不得在此调用 `完成装配`、读取初始化种子、组织启动线程、开放宿主或设置正式普通装配成功。暖入未成与退出阶段 31 均不得留下静态析构顺序依赖。
4. `检查普通启动持久准入` 保留隔离候选前置校验及绑定后的根核同，值栈探查替换为上述实际上下文入口，沿普通应用配置和同一原准入视图传参。用已有 `普通上下文作用域回收` 在该分支保证阶段 31 返回前销毁已发布的暖上下文。值阶段失败用 `持久特征值复核失败` 和既有值状态映射；概念依赖缺键映射 `持久特征概念复核失败` 与 `材料不完整`，资源失败与当前视图变化分别用 `资源失败` 和 `前提已变化`，其余不符用 `结构冲突`。两个 owner 均读回成功才保留 `持久业务运行者未重绑`，业务门仍关。冷持久首份以扩展后同一 reader 独立核验，旧库无自动迁移。普通默认入口未绑定时保持原装配。
