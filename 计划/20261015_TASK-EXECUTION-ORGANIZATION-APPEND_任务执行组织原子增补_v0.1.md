# 任务执行组织原子增补

身份：`TASK-EXECUTION-ORGANIZATION-APPEND`；版本：v0.1；日期：2026-10-15。

代码基线：`ad8ac59b6d93f68c5b8580ee515df3a89cae6abe`。本文件合并本叶设计与施工合同；资格只由计划索引登记。

## 1. 目标、依据与边界

用户已经明确：方法转换为任务内部执行节点，不再复制方法树；后续学习只增加可选方法，不能破坏既有任务执行材料。T-D仍一对一，内部执行节点不是新任务或需求。3300关于稳定方法/配对定义不得原地重释、旧执行依据不得被后来学习改写的约束继续成立。

已发布提供者 `TASK-METHOD-EXECUTION-ORGANIZATION` 能建立不可变任务执行组织，但再次遇到新方法或新配对只返回 `已有组织不同`。直接让W2消费它会阻断学习后增补。本叶补齐唯一紧邻提供者：基座一次原子新增节点并追加既有节点字段，task owner通过真实公开入口消费它，为既有组织追加新根方法、新作用域与新配对，不替换根、不重编旧节点、不覆盖旧要求。

该入口是真实转换/发布/读回实现，不是空DTO或假成功；本叶没有W2/W3生产接线，不宣称任务已使用新组织执行。下游调用迁移在取得本叶代码结果后再形成计划，不提前登记库存。

当前依据：0050组合原子发布与单调用一致性；3200任务/Vt/X分账；3300方法稳定定义与学习隔离；5260任务条件筹办要求；已发布方法闭包与任务组织源码。现行源码事实优先于旧规范中的“基座尚无组合原子发布”描述，但不降低原子目标合同。

### 明确不做

- 不改W2/W3、当前方法采用/输入计划、X、三个本能运行服务、反馈持久codec或学习消费；不新增本能函数。
- 不实现组合方法运行位置、调用栈、循环、分支优先级或完成条件。
- 不替换、删除、排序重编已有组织成员；不改方法、概念或真实世界事实。
- 不迁移旧方法副本、不删除现存记录、不建立任务轮次/方法版本或第二组织。

## 2. 当前事实与复用裁决

`基础数据集::原子建立节点组()`只能新建节点及它们的字段，不能同次为既有组织根/作用域追加成员引用。先建节点再逐条追加根字段会公开半结构；把新成员只挂反向字段、却留下旧正向完整成员表不更新会形成两个不同完整集合，均不采用。

扩展基座一个纯结构入口，复用当前独占锁、隔离候选表及所属/目标字段索引，保持一次交换。`查询节点组完整结构()`已能单锁读取附加字段宿主；从其结果提取 `基础节点结构` 作为精确前置快照，不使用代次、计时或业务版本。

复用 `新_方法类::读取方法执行结构闭包()`，不改方法owner。复用task组织规范化、角色/概念核验、完整读回及T/Vt根反查；增补仍由task owner唯一发布。知识库没有目标函数现行用途卡，本裁决经当前头源和直接调用点核对。

## 4. 基座公开合同

在基础数据集头文件声明以下纯结构值式类型，使用已有 `基础组内新节点/基础组内字段内容/基础节点结构`，不加入task/method业务类型：

```cpp
struct 基础既有节点追加字段 final {
    稳定编码 所属节点, 字段节点;
    基础组内字段内容 内容;
};
struct 基础节点组追加请求 final {
    std::vector<基础组内新节点> 新节点组;
    std::vector<基础既有节点追加字段> 追加字段组;
    std::vector<基础节点结构> 预期既有节点组;
};
enum class 基础节点组追加状态 : std::uint8_t {
    已完成 = 1, 入口拒绝, 节点不存在, 引用不存在,
    预期不符, 资源失败, 内部不一致
};
struct 基础节点组追加结果 final {
    基础节点组追加状态 状态 = 基础节点组追加状态::入口拒绝;
    std::vector<稳定编码> 新节点组;
    std::vector<稳定编码> 追加字段关系组;
};
基础节点组追加结果 原子追加节点组(
    const 基础节点组追加请求& 请求) noexcept;
```

完整规则：

1. 请求必须至少有一个新节点或一个追加字段。允许只追加既有引用字段，例如把已有被调用作用域增加为根候选；不要求为了凑节点数创建空节点。`追加字段关系组`与请求追加字段顺序一致，新节点返回顺序与请求一致。
2. 每个追加字段的宿主必须是请求前已存在的节点，且恰有一份预期结构。预期节点可额外包含只读守卫节点，但不得重复、零编码或引用缺失。无追加字段的纯新节点请求可用空预期组。
3. 预期结构使用完整节点身份和全部所属字段（字段关系编码、字段类型编码、值或引用内容）。按字段关系稳定编码排序后比较；输入字段不得重复编码/错宿主/变体无效。预期字段中的非零引用必须仍存在。预期不是“筛选所关心字段”的部分快照。
4. 在同一基础独占锁内先验证入口、当前节点存在和引用，再读取全部预期宿主当前完整结构，与规范化预期逐字段比较。不相等返回 `预期不符`，零发布、零成功载荷；并发追加同宿主由该比较阻止陈旧请求覆盖。不使用全局代次或调用者owner许可。
5. 新节点字段与追加字段内容均可为直接值、既有节点引用或本请求新节点的组内索引。校验字段节点、既有引用、索引边界和变体；任何无效项使整次拒绝。基础层不理解“根成员唯一”等业务基数，也不自动去重/合并合法重复字段；调用owner负责其业务唯一性。
6. 请求只新增节点/字段，不更新/删除既有字段，不改变外部关系，不向其它上层发回调。隔离候选节点表、字段表、所属/目标字段索引全部准备成功后一次交换；新字段引用旧节点和新节点均更新两侧索引。
7. 基座资源分配失败返回 `资源失败`，没有半发布或部分返回；编码高水位即使已增加也不回退。内部表/索引不变量异常遵守现有工程终止链，不吞为正常拒绝。显式 `内部不一致`只保持当前基座可报告的结构不一致分类，不授权业务继续当正常否定。
8. 旧 `原子建立节点组/原子建立节点/原子建立互引节点` 公开合同不变。可以提取同文件私有候选写入helper共享实现，不复制公开入口、重入锁或创建第二存储层。不在本叶优化全表候选拷贝策略。

## 5. task公开合同及追加语义

在 `新任务执行组织状态` 尾部追加 `已增补`、`增补结构暂不支持`，不改已有枚举数值。新增：

```cpp
新任务执行组织结果 增补任务方法执行组织(
    稳定编码 任务节点,
    const std::vector<稳定编码>& 来源方法节点组) noexcept;
```

本函数接受“本次希望加入或刷新知识的抽象根方法集合”，不是替换整个候选集合。参数根去重排序，无优先级含义。未在本次输入出现的旧根/作用域/配对全部保留。没有旧组织时，复用既有首次建立合同，从同一次闭包值式材料建立；不另行重读方法产生混合快照。

原 `建立或取得任务方法执行组织()`保持其精确同义/异义合同不变，既有调用方不被静默改义。两入口可提取私有首次建立helper复用，不能让新入口在持task锁时重新调用方法owner。

### 5.1 可以唯一裁决的增补

| 来源情况 | 操作 |
| --- | --- |
| 输入根已经为候选，完整执行定义与已有相同 | 原根与全部节点不变；无其它增补时返回 `精确重复`。 |
| 输入根已是组织内部被调用作用域，但尚未是根候选 | 仅向组织根追加 `根作用域`引用，复用已有作用域。 |
| 来源 M 尚无作用域 | 增加该 M 的完整任务作用域、参数要求、配对要求、步骤与分支；调用闭包内已有 M 复用其作用域，新 M完整建立。 |
| 同 M 新增来源Pair，既有参数及组合控制结构未变 | 增加该Pair及全部条件/结果/确认/线性子节点，在原作用域追加配对成员引用。既有Pair内容及编码完全不变。 |
| 新 M 调用已存在 M，或新 M/新步骤形成递归调用 | 复用既有作用域，保留有限图边；不递归复制M或展开运行栈。 |
| 方法头、启用状态、命中次数、登记名改变 | 不属于task冻结执行结构增补内容；仍不保存到组织，不据此改变旧要求。 |

同 M 的来源 Vm、作用域/实现方式、已有参数规格（含顺序/集合约束）或已有Pair完整定义（来源C/R、条件/结果/确认/线性）发生改变，以及已有Pair从当前源定义消失，违反现有稳定定义合同，走工程诊断；不得覆盖、并列伪造相同来源身份、换名或转成子需求。不存在以“新旧哪个更好”为理由任取的分支。

组合方法的已有步骤/入口/转移内容改变或删除同样不得覆盖。对**合法纯新增**步骤/转移，或原来无入口而新增入口，本叶返回 `增补结构暂不支持`，零整体写入并保留原组织；这是具名提供者能力拒绝，不表示现实条件缺失，不发送任务/需求消息。首次/新M的完整组合结构仍按已发布提供者保存；本叶不猜旧执行应怎样采用新增分支。

`增补结构暂不支持`只允许上面的合法组合控制结构追加。已有步骤身份异义、转移键相同却改后继或其它正式结构破坏必须工程诊断，不能被能力拒绝掩盖。

### 5.2 状态、锁和执行隔离

- 方法闭包单锁完整读取后释放方法锁，再取得task锁。task锁内fresh读取T、唯一Vt、现有组织及任务状态，整个比较/增量规划/发布/读回期间保持task锁。
- 首次建立、实际增补只允许 `已建立/待查找方法/待检查条件/等待条件`。已进入执行链及终结状态不能实际增补。若完全同义，允许任意状态只读返回 `精确重复`。非同义请求在不允许状态返回 `任务状态不允许`，不尝试发布。
- 没有自动重新筹办、当前方法切换、X更新、子需求、动作或状态写入。将来W2采用本入口时自行处理任务状态，不由本叶越权推进。
- 原根、T/Vt反向真源、全部旧节点及旧定义保持。新Pair并不自动替代旧Pair，双方保留为可选知识；实际选择仍须未来任务采用算法。本叶不新增最新优先、窄域优先或命中次数优先。

## 6. 增量规划、完整性与原子边界

1. 以已有组织的 `来源M/Pair/步骤/转移` 规范化映射识别旧身份，禁止按名称、内容哈希或新增稳定编码冒充来源身份。新方法闭包不是task图，转换时只输出task节点和共享来源引用。
2. 先在内存构造**完整预期合并图**并运行现有结构/类型核验；旧方法不在本次闭包中仍完整保留。对本次重读到的已有M按第5节检查稳定内容及允许增量。不把不同可选方法/配对合并为一个条件AND组。
3. 完整预期图需要保存旧真实task节点编码；新节点暂用专用内部映射，不泄露为正式编码。新/旧作用域之间调用边、分支配对定位及角色关联必须在组内索引/既有引用两种来源间准确映射。
4. 新建作用域时沿已发布布局写完整成员引用；**既有节点可追加字段的白名单仅为：组织根的作用域成员、组织根的根作用域候选、既有作用域的Pair成员引用。** 禁止补写旧参数/条件/结果值、角色或其它定义字段，禁止将旧元数据字段重新解释为“不完整索引”。同一旧成员不能重复追加。“旧节点不变”指其编码和既有定义字段不变，只允许上述成员追加。
5. 读取已有组织时，在持task锁的原始读取中保存用于规划的完整 `基础节点结构`；读取helper可新增私有可选输出承载原始结构。请求中的预期组覆盖每个追加字段宿主，并包含组织根的原始完整结构作为T/Vt所属关联及根成员守卫。后续不得先完成规划，再读取一个更新后的快照直接当作预期；若实现另用一次 `查询节点组完整结构()`批量取得宿主结构，必须逐字段与规划所用原始读取一致后才能采用，否则进入工程诊断。task锁排除其它task写入，基座锁内expected检查阻止其它基础写入造成陈旧发布。根→T的唯一关联仍由task owner在持锁读取中核对，不改为另一个正向真源。
6. 一次调用 `原子追加节点组` 发布全部新节点和全部既有成员字段，不按M或Pair逐个提交。合法组合控制追加不支持、工程结构问题或任一规划失败都必须发生在该调用前，使本次不出现“部分支持方法先发布”的半成功。
7. 基座返回 `预期不符`：本task锁下没有合法同owner竞写，不能盲重试、缩小预期或称精确重复；按工程诊断处理。其它基座结构失败/资源失败在task入口也进入工程诊断，不变成业务缺条件。
8. 发布后完整读回组织并核对预期合并图、全部旧身份/定义不变和新增映射；成功返回 `已增补+完整组织`。读回失败或不一致保留已发布事实进入工程终止，不能重建第二根、回退高水位或删除旧X依据。

允许复用既有组织写器，增加仅私有增量模式：旧根/作用域/Pair/步骤映射为真实既有编码，不重新序列化旧定义；新节点使用内部占位，最终压缩组内索引并将旧引用转换为既有节点引用，一次提交原子追加。所有对既有宿主的新增字段必须经过上述白名单检查；这只是实现复用，不新增公开模式或改变首次建立合同。完整读回可将原始既有字段作为不变子集核对，同时另核对白名单追加后的完整预期图；不得只检查子集而遗漏多余字段或重复成员。当前X、已采用Pair和具体输入不读取重选、不改写、不重建。

读回继续使用完整正向成员表与反向全成员核验。新增配对按来源Pair稳定编码确定返回顺序；参数/条件/结果序号及线性索引语义不变。来源概念证明边界沿已发布提供者：可用owner确认存在/普通或复合特征/二次概念类别；状态动态、等待/匹配概念仅保留方法owner具名引用，不声称完整求值。读回不从当前方法重新生成已存定义。
