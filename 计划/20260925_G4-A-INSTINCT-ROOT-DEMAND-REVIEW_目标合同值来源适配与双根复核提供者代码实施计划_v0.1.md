## 4. 实施步骤

### P1 目标来源 ABI

1. 在求值头实现第三来源、专属见证、来源联合和内容联合；加入需求服务声明/包含和构造依赖。
2. 在求值源把来源身份、形状、解析、见证和后置检查全部改为显式三分支。
3. 按详细设计调用唯一`读取本能根材料`，以根创建截止核验历史采用，以请求截止核验 E 身份；不把根形成 F 的准确值用作目标。
4. 目标来源仅准入`求值二次关系`；候选/FC/EC入口在读取前明确拒绝。
5. 保持比较方向、K/RC通用算法和普通需求语义不变；不恢复`二次关系判断结果::成功()`。

### P2 v2 根复核合同与 provider

1. 从线程头源删除详细设计列明的旧预算、旧二态 DTO、旧端口及专属谓词；保留消息与邮箱合同。
2. 新建 provider 头源，逐字落实详细设计第4—5节 DTO、端口、构造、绑定谓词和算法。
3. 每根先读根材料，再按 self+锁定FT+G0读取当前采用 F；A使用根目标来源，B使用本轮当前 F。
4. 只把“正差命中”和“零差且仅正域不命中”解释为业务成功；任一技术失败清空双根投影。
5. 双根完成后做 G0 尾守卫；全调用零事实写入。

### P3 普通应用和工程

1. 求值器唯一构造增加既有需求服务。
2. 在求值器之后构造唯一 provider并保存；新增只读 getter，不注入 self。
3. 根工程登记新头源；三个直接编译普通应用的专项工程登记新 provider 源。
4. 不更改普通应用配置、启动阶段、治理门或线程创建签名。

### P4 验证与记录

1. 在既有双根专项中补齐详细设计第7节全部目标来源与 provider 矩阵，保留原回归。
2. 运行静态零引用/唯一构造/禁止路径检查、专项、回归和双配置构建。
3. 记录真实命令、结果、提交前状态和未验证边界；施工记录包含函数级代码知识变更清单。

## 5. 失败收口

- 纯代码、编译、链接或测试错误：在白名单内修复并继续。
- 任一 provider 需要新需求/存在/L1 接口：停止；现行设计只允许复用既有公开入口。
- 根形成 F 无法用于目标来源历史采用，或当前 F 无法由现有采用读取取得：具名退回，不用缓存、消息值或根形成 F替代。
- 发现普通需求方向语义受影响：停止并修复为只在 G4-A provider解释双根结果。
- 远端推进或同文件/同语义 WIP：只停止受影响切片，保护现场，重新 S0。
