## 1. 目标和完成条件

在一个串行复杂代码切片中完成：

1. 为存在/场景两侧增加组成、包含及当前C角色/树位置窄读，以仓库既有provider绑定模式的无owner final组合器形成同G0联合读取；全部组成/场景包含写路径共同维护联合单父无环，并使存在侧无需反向import场景合同即可识别未启用、未纳树、根和非根C；
2. 为场景owner增加同节点树锚点、根标记、树归属、直接存在成员、直接子场景、角色投影递归树读取、同owner迁移及场景角色启用接纳；
3. 清空并按v2重构世界树六个保留入口，使其只消费新存在/场景公开服务；
4. 物理删除旧世界树DTO、helper、状态映射和全部已删除场景接口依赖；
5. 以Debug/Release专项证明联合归属、具名树、角色投影递归、字段操作、跨owner分阶段收敛和六个世界树入口；世界树错误归零。

本计划是同一公开ABI、同一场景owner生产文件和首个消费者的单一计划，不拆成提供者/消费者并行切片。

## 5. 实施步骤

### P1 两侧窄读与联合provider

按详细设计第4节在既有两个合同中追加存在组成窄provider、场景包含窄provider和无owner联合只读接口。共同抽象接口只放在存在窄合同；唯一生产`final`组合器完整定义在场景合同并持两侧普通provider引用，不跨named module重复定义。它沿用仓库既有`provider + 绑定于(L1)`信任边界，不新增恶意非生产实现防伪模型；组合器构造不接收L1，`绑定于(candidate L1)`同时核对两侧provider，各L2入口只用自身L1核对绑定，不增加`dynamic_cast`、具体final类型、底层provider地址或函数指针防伪层；世界树不需要L1 getter。两侧各自只读本owner强类型事实，组合器只组合两侧公开结果，不直达L1、不写事实。共同接口另有一条由场景窄provider委托的当前C角色/树位置读取，成功空角色表示当前E未启用C；非空分别严格互证未纳树、根标记或非根树归属。覆盖合法空、唯一父、多父复义、三类稳定子组、四种角色位置、漂移、预算、坏实例和资源失败。

修改存在类：实现组成父/子窄读；旧`新增成员关系/删除成员关系`只允许特征分支，子存在固定入口拒绝零写；新增具名子存在增删入口并强制显式联合provider。全仓生产调用点必须保持为零，唯一验证工具特征调用保持原签名可编译。provider不匹配、读取失败或联合多父均在候选写前返回。两个具名子存在入口保持既有请求ABI，不增加预算字段；联合父链、联合子闭包和逐项C角色位置读取共用服务内部固定关系预算4096，超限返回`数量预算不足`且零写，固定预算不参与幂等比较，不得在多个helper硬编码不同上限。

### P2 场景包含扩展和六函数所需字段操作

1. 追加树/包含扩展登记，一个树锚点和根标记、树归属、成员、子场景四关系类型及v1 DTO；保持既有全部数值不变。
2. 场景构造接收并核验五项交付；实现场景包含窄provider和同一存在provider身份谓词。
3. 实现直接存在成员增/退/迁移/当前/反向/历史；实现子场景原子启用接纳、同树迁移、当前/反向/历史。迁移使用能同时表达旧事实退出与新事实建立的专属结果；不新增独立子树退出/拆树入口。
4. 存在与场景全部归属新增/退出/迁移及角色启用统一按“纯校验→短锁查幂等并释放→无锁联合读取→重取本owner锁并二次查幂等→不再回调provider而以原G0提交”执行；既保证后继代次下旧G0精确重放，也不在持锁时重入本服务窄读。幂等同一性只比较L1首次规范化写集可恢复的持久语义；三类角色启用请求的`最大关系数量/最大祖先数量`仅控制本次准入、读取、路径展开和读回，不进入请求相等比较，现有用于幂等判定的三个`operator==`须删除这两个预算字段的比较。重放时先恢复首次持久语义，再使用本次合法预算核验；预算不足返回`数量预算不足`且不改变原幂等事实，预算足够才返回`精确重复`。禁止增加请求指纹、预算账、内存旁账或L1字段。所有作用于普通E的组成或成员增/退/迁移先有界扫描完整联合子闭包并逐项读取C角色位置：含当前C投影的普通新增/退出固定拒绝；成员同树迁移仅在全部后代C树证明同根时允许，跨树固定拒绝。该限制只表示本片未提供C承载组成结构的跨owner树证明协调，不宣称C语义上不可移动。
5. 只收紧既有`退出场景角色(const 场景角色退出请求&)`的引用保护，不新增provider参数或安全重载：根标记、非根树归属、以C为源的直接成员/子场景及F/S/D/B组织引用闭合前拒绝；把C仅当普通E指向的存在组成或场景成员父关系不依赖C角色，不误拦退出，也不让场景服务反向import存在写合同。

### P3 原子启用接纳和树读取

实现`启用并建立场景树根`、`启用并接纳直接子场景`、`启用并纳入既有归属树`的三种独立请求、scene-owner单写集及专属角色写结果；建根无父字段，直接子场景显式父C，既有归属显式请求直接父并另行返回计算所得最近上游C。当前树读取先证明根标记/树归属，再沿联合三类包含边递归；遇到非C普通E继续沿组成子链下钻，遇到当前C才建立场景投影并保存从最近上游C开始的完整连续来源路径。成员/组成角色投影不补第二关系。不得形成持久树投影、第二列表或越级成员关系。

### P4 世界树清空重构

1. 删除详细设计第10节全部旧实体和旧调用。
2. 发布v2 DTO、结果谓词、两服务构造及六个同名入口。
3. 构造内部建立绑定当前存在/场景窄provider的联合组合器；根/位置只读使用同G0具名树投影；移动只调用对应scene-owner同类原子迁移，跨组成类别统一返回`引用冲突`而不分步；本片没有跨类别迁移入口或`未实现`状态。
4. 两种创建使用完整第二阶段请求；场景创建的第二阶段精确使用直接子场景启用请求。交换前漂移允许fresh验证后更新G0形成续跑请求，发布/未知后冻结原请求。存在创建阶段发布未知允许E进度为空；场景阶段发布未知保留E与冻结请求；移动发布未知或发布后读回失败保留专属移动进度。存在创建成功投影只返回E身份与成员位置，不要求拼接另一截止的完整存在DTO。部分发布、最终读回失败和后继覆盖按阶段严格分账，不补偿删除。

## 6. 失败收口

- 正式规范、现行接口或消费者集合改变并影响DTO/事务/所有权：具名DRIFT，保留现场，不改规范或计划。设计已经冻结且正式规范能够唯一裁决的L2缺口函数可在本计划白名单内补齐，不因“当前代码尚无该函数”单独退回；不得借此私增字段、改变公开请求ABI、幂等范围、事务、owner或生命周期。
- 普通编译错误、映射遗漏或专项失败：在白名单内修复后重跑。
- MSVC IFC内部错误：先用相同源码隔离复现并记录；不得恢复旧接口、复制实体或扩大生产文件。连续稳定且无法在白名单内机械规避时返回工具链DRIFT。
- 根工程只剩既有概念树错误：按完成边界分账；不得修改概念树。
- strict仍仅命中已知acceptance_record缺口：记录范围外FAIL；出现本片新增错误必须修复。
