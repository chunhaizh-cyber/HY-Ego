## 1. 可执行闭环及真实依赖

只有已正式发送的网页 Send 可回链到原提问的语言 owner 101 留档。原出站具体表达和它的含义网是提问权威，稳定身份为出站节点及网内所求项。按原 Send 可以读回同一原提问、完整原句 Unicode 标量范围、询问内容/被询内容/疑问实例网内编号、正式待求类型概念、所求角色、原询问者及受询者、被询特征类型（载荷栏有）。保持原留档完整，不另设问题包装节点或并行答案口径。已有 Q 只供 O→原出站留档定位和结果核验。D 字段、回复标记、词面、最近句均不派生关系身份。

前置 ROLE-LANGUAGE 随 4e3854eda8fa4c0cd58ca66ed4b9be1c2764168d 交付正式 Send 读取与宿主传输终态后的被动钩子。当前关系概念 schema 只接受 E/D 端点和已有边/字段；当前正式短答只能依回复标记，旧 Q 不支持更正版本。问答关联和更正必须先有原提问稳定回链，再形成接受语言对象的正式关系合同。本片不把已有 E/D 架构关系冒充答复关系。现行需求信息的关系成文只支持目标存在缺口；载荷水温的正式关系成文不宣称已实现。

## 2. 精确合同

1. 普通装配在现有正式消息角色读口中，为 Send 读取真实对应 O，验证方向、编码、源场景、窗口、会话/对话框、序号和正文全同，O 时间不得晚于发送。合入真实 O 节点字段快照；正文和 Send 已由同次已有保护取得；无 O 的正式发送可无原提问材料。不使用网页回复标记，O 的 Q 是查找定位提示。
2. 语言 owner 提供两个具名入口 同步正式发送原提问(Send M)、读取正式发送原提问(Send M)。新 DTO 位于 新_语言类.h，结果区分已完成、未找到、范围未支持、输入拒绝、前提变化、资源失败、结构不一致。传送关系先走 配置正式消息角色读取 的现有正式取材端；同步从 O 提示 Q 重新读同 Q 的正式出站场景和来源，以及其唯一类型 101 留档。核原留档 UTF-8 与实际正文完全相同。双方在原图具名 询问者/受询者 的合法 E 为上下文；本次 Send 已确认的角色与图冲突时前提变化，未知时仍可读原图身份。
3. 只支持已唯一归档的顶层单句填项疑问。根须为顶层疑问的询问态度，确认范围为填项，引用同网唯一被询内容项。其值载荷疑问或需要态度的目标存在疑问可投影，核唯一疑问实例身份、父询问内容、已绑定正式待求类型及关联的被询特征类型。完整原句范围用已成文唯一回读的原文标量全长；已知内部分句或其它复杂形态返回范围未支持，不退取首项。只读 DTO 同时返回真正原出站留档，保留原结构和角色，不从旧 Q/D 制造语义关系。
4. 新增语言组织键 已发原提问证据。直接在原 101 节点持有发送/输出/外设场景/窗口的五项数值标识（含方向），UTC、原文标量范围和所求三项网内编号，同一 101 最多一个正式 Send，Send 不可被其它原提问抢占。记录 L1 附加时使用内锁读取、原留档同次预期以及正式 Send/O 的窄预期；无跨外设真实引用。精确重放读取相同绑定，不写第二条。旧留档无字段则无已发绑定。读时沿登记内的稳定 101 节点和该实际 Send 数值键核回原图，不要求任一当前窗口尚在；同一写后直接读回核收据。
5. 宿主原 发送后投影 钩子在已发布实际 M 后调用该入口。一般发送无 Q 则正常继续。正式结构明确超出本片支持的图仍可保留正式 Send 和其它角色投影；工程问题不伪称已关联。禁止提前从出站排队产生绑定。
