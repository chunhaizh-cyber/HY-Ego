- 标识：INSTINCT-CONTRACT；版本：v0.8；日期：2026-11-10；状态：可执行（阶段1—5）；阶段6门禁见第4节
- 依据：[5380 本能方法函数合同](../规范/5380_子规范_本能方法函数合同.md) v1.9；5350 v2.4；3300 v4.6；0300 R110；5170 v3.6 §2.2；6120 v1.11；7240 v2.6

## 1. 目标、范围与完成条件

目标：使链路上各本能的代码达到 5380 合同：必要条件写入方法头（模拟学习据此生成先天条件），运行时只复核已声明条件，结果按实际运行取得，推导状态由owner自动维护，结果状态与执行阶段一致。

范围：阶段0—6（第2节）。不在范围：网页对话三项处置（5380 第6节未决）；世界事实类条件的声明机制（5380 第4节第1项，暂按运行时复核）；“属于人类”的事实依据与概念自动维护触发（5380 第6节未决，本计划只移除本能内的概念修改）；请求确认需求内容、内容确认F（R106，未实现）。

完成条件（每阶段）：实际项目 Release x64 编译链接通过；按代码窗口现行做法诊断运行（默认240秒，见到结果即停），观察到该阶段“验证”栏所列现象且无工程异常；施工记录写明实际改动、诊断结论与偏差。测试只在用户发出测试指令时运行。

## 3. 各阶段施工内容

### 阶段0 在制改动收尾

- 文件：`领域/新_本能函数集.cpp`、`领域/本能字段询问.运行接口.h/.cpp`、`业务/字段询问.本能运行服务.cpp`、`装配.普通应用.cpp`、`领域/新_任务类.cpp`（删补问叶子收窄补丁）、`业务/服务对象.本能运行服务.cpp`、`领域/服务对象.材料合同.h`、`领域/新_方法类.cpp`。
- 改动：按 CONV-INSTINCT §6.6 完成询问方法4参数；删除询问声明中的先天被动配对（`passive` 条件结果）与 `初始模拟关系 不同(2,3)`；获取交互者不提交先天配对；获取交互者按 5380 §3.3 取值规则：交互对方已有对应存在（如678）即以它为交互者并同次登记为现实交互场景成员与参与交互者，尚无时新建对应存在；窗口已有交互对方以参与交互者有值判定。
- 登记时生成结果组（R110，阶段0阻塞项）：方法owner登记接口接受方法函数随方法头提交的结果组（作用对象与被改变特征类型），登记即建立该结果组并据其结果项索引召回；链路各本能（询问指定需求字段、获取交互者、获取服务对象、获取服务对象需求节点、进入场景）在登记声明中按 5380 各节“修改对象”提交结果组；召回改为按结果组结果项判定，取消“无结果项方法效果未知仍保留”（5350 §8）；参数汇总的涉及特征类型只作粗索引；仅有登记结果组时选择回执注明“尚无运行经验”。结果组与模拟学习、尝试学习的衔接：运行结果完善同一结果组（具体取值、方向、关系），不另建第二份。
- 旧代码删除（用户规则，阶段0）：停用并删除旧建立连接 v4（登记、`业务/连接.本能运行服务.*`、`领域/连接.本能合同.h` 中仅为它服务的部分、接收数量基准与引用计数、装配注册），阶段6按 5380 §3.2 新建出站本能；删除网页对话三项（5380 §3.8）。施工记录写明删除清单。
- 不得改变：回答写回现行行为（由 ASK-READ-SCENE 退役）；其它本能。
- 验证：诊断中询问方法以4参数绑定，交互者为678，说话者、D主体、交互者同一节点。

### 阶段1 获取服务对象

- 文件：`领域/服务对象.材料合同.h`（`获取服务对象有序规格`）、`领域/新_本能函数集.cpp`（获取服务对象声明）、`业务/服务对象.本能运行服务.cpp`（读取族参数、复核、执行）、`装配.普通应用.cpp`（配置：现实交互场景概念、参与自我/参与交互者类型，已有字段复用）。
- 改动：
  1. 参数规格改为六个：1 自我｛服务对象｝；2 服务对象特征/1；3 现实交互场景｛参与自我、参与交互者｝；4 参与自我特征/3；5 参与交互者特征/3；6 人类。
  2. 初始模拟关系：特征引用存在(4,1)、特征引用存在(5,6)、不同(1,6)。
  3. 初始必要条件：参数6属于人类；执行分支必要条件：参数5有值（取代原“参数2交互者有值”）。
  4. 运行：目标判定（服务对象已引用参数6 → 目标已满足，零动作）；动作前复核已声明条件；建立动作 → 写自我“服务对象”＝参数6；删除动作后的“属于人类”判定分支与“归入上位存在概念”调用。
  5. 旧v4按旧代码处置规则（AGENTS §5）直接停用并删除，新登记名升为 v5。
  6. 参数1改为 自我｛服务对象、交互者｝，增参数7 交互者特征/1；初始模拟关系增“参数7引用参数6”；执行分支必要条件改为“参数7有值”（取代“参数5有值”），不满足时形成“有交互者”子需求由获取交互者满足（5380 v1.15 §3.4）。
  7. 现实交互场景、窗口副本及交互对方成员随获取交互者执行顺带建立或复用，不入结果组；获取交互者结果组只含自我“交互者”；自我线程不自动补建（6120 v1.14，保持现行代码）。
  8. 参数关系联合核验（5260 §5.1）：绑定前按“同一、不同、特征引用存在”等已声明关系联合收窄候选，不先取编码最小者再核验。
- 不得改变：获取交互者；概念owner接口（`归入上位存在概念` 保留，不再由本能调用）。
- 验证：模拟学习不再产生“特征引用存在(2,1)”，新配对条件含“参数5引用参数6”；“有服务对象”形成“有交互者”子需求，获取交互者执行后现实交互场景随之出现；真实执行写服务对象＝交互者（678）。

### 阶段2 获取交互者收尾

- 文件：`业务/服务对象.本能运行服务.cpp`、`领域/新_本能函数集.cpp`。
- 改动：交互者已有当前值且等于按取值规则应取对象时零动作返回目标已满足，不覆盖；“外设有可选窗口”按运行时复核（5380 第4节第1项）；写入时前提变化在已进入动作后报动作结果未知（第2.5节）。
- 验证：同一会话重复筹办不重复写交互者、不生成多余状态。

### 阶段3 询问指定需求字段状态一致

- 文件：`业务/字段询问.本能运行服务.cpp`、`领域/本能字段询问.运行接口.cpp`、必要时 `新_本能函数集.h`（返回原因枚举）。
- 改动：字段已有值或不适用 → 零动作返回目标已满足，不报“已取得”；已进入动作后留档或入列未完成 → 动作结果未知/部分取得，不报入口拒绝；结构类“定位未支持”在召回与正式参数保证下改为工程断言（若S0核对发现仍有合法业务来源则保留并写入施工记录）。
- 验证：诊断中无“入口拒绝且已进入动作”的组合。

### 阶段4 需求完善阶段自动维护

- 文件：`领域/新_需求类.h/.cpp`（建立被认知D、`更新被认知需求信息` 及补问写回路径）、`业务/服务需求.本能运行服务.cpp`、`领域/新_本能函数集.cpp`（获取服务对象需求节点声明）。
- 改动：
  1. 需求owner在建立D与每次字段更新的同一次发布中，按必需字段（需求主体、目标信息节点、目标特征类型、目标形式及载荷）是否全部确定设置信息完善阶段；字段齐全的首次接收认知D建立时即为已完善。
  2. 获取服务对象需求节点删除 `完善接收认知需求信息` 调用及其前后基线读取；“D已完善”写为声明条件（可声明则入执行分支必要条件，否则运行时复核并记施工记录）。
  3. `完善接收认知需求信息` 若无其它调用方则删除（AGENTS §5 旧代码处置）。
  4. 获取服务对象需求节点删除“必要时新建空需求特征”；改由需求owner在建立以服务对象为主体的被认知需求时同次确保其“需求”特征存在（无当前值）（5380 §3.5）。
- 不得改变：补问链路（询问、回答写回）的现行外部行为。
- 验证：字段齐全的接收需求不再停在待完善；获取服务对象需求节点不再产生完善阶段写入。

### 阶段5 进入场景

- 文件：`领域/新_本能函数集.cpp`（进入场景声明）、`业务/进入场景.本能运行服务.cpp`。
- 改动：删除声明中不符实际的“不同(1,3)”；初始必要条件“参数1属于自我概念”；自我已在目标场景 → 目标已满足（零动作）；写入返回前提已变化时按进入动作前后区分入口拒绝与动作结果未知；补齐方法节点、执行实例与任务状态复核（同服务对象族做法）。空间分支不在本阶段（待6220细化）。
- 验证：重复进入同一场景零动作；诊断无工程异常。

### 阶段6 建立连接（门禁满足后激活）

- 文件：`业务/连接.本能运行服务.cpp`、`领域/连接.本能合同.h`、`领域/新_本能函数集.cpp`、表达组织知识种子、`装配.普通应用.cpp`。
- 改动：按 5380 §3.2 改为出站本能：参数3个（自我、窗口副本、外设场景标识）；条件：有交互者、窗口有效、语言知识齐备（是否重复招呼属于自我意识，不设条件）；对方已发消息 → 目标已满足；复用询问方法出站时序；删除写交互者、迁移自我、接收数量基准与引用计数及执行内等待；对方消息到达由场景信息唤醒（ASK-READ-SCENE 机制）。
- 验证：交互者开窗未发消息时入列一句招呼；对方先开口时不招呼。

## 4. 门禁与依赖

1. 阶段1—5：合同已由 5380 v1.5 冻结，可依次施工。
2. 阶段6：须先完成 ASK-READ-SCENE。是否重复招呼属于自我意识，不作规则。“请问有什么可以帮到你吗？”已裁决不冲突，可作招呼话语。
3. 每阶段 S0：按当时 HEAD 复核文件、函数与行号；合同与代码无法对应或需新的机器语义时停止该阶段，报交互窗口裁决，不自行补设计。
