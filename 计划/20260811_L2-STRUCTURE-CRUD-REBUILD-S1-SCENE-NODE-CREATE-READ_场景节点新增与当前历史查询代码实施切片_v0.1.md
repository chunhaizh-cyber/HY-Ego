## 1. 目标、范围与完成条件

作为 L2 六类纯结构重建的首个代码叶，在 4230 合同版本 1 下建立公共 L2 结构 DTO 的唯一模块所有者，并实现 `L2场景结构服务` 的场景节点新增、当前单节点读取和历史单节点读取。

本叶只建立一个无属性、无父子关系、无成员关系的普通场景节点。S2 才拥有场景父子 / 成员关系新增、替换、退出和完整结构查询；S3 才拥有场景固定属性换代、场景退出和引用保护。本叶不得提前形成两者的写集、函数体、验证或装配。

完成条件固定为：

1. 公共 L2 合同类型、七种强类型身份和场景 DTO 取得唯一中文实体与物理所有者；
2. `新增场景节点` 把一份合法请求机械映射为恰一个普通 L1 节点、零关系、零值、零属性槽变更、零退出项的不可变中性写集，并恰一次提交；
3. 首次成功从唯一新编码映射返回 `L2场景身份`，精确重复返回同一身份和首次变更代次，同键异义返回幂等冲突；
4. `读取场景节点` 按显式当前 / 历史类别返回完整 S1 场景事实，当前读取经一致当前投影，历史读取由同一事实代次的前后探测夹住；
5. 生产外自定义参数验证覆盖合法新增、精确重复、同键异义、当前读、历史读、非法请求零变化和事实代次漂移；
6. 新模块进入生产工程但不接入启动、普通应用上下文或聚合面，Debug / Release x64 保持完整编译链接。

## 6. 新增场景节点的精确 L1 写集

### 6.1 写前与幂等

入口先校验合同版本 1 和非零 L2 幂等身份。L2 幂等身份完整 64 位原样映射为 `L1中性写集幂等键`，不得截断、哈希或另建进程内幂等账。

场景节点固定使用家族专属本地键 `0x0201'0001U`。本地键只参与 L1 请求规范化和新编码定位，不是公开稳定编码；它使未来其它结构族即使误用相同 L2 幂等身份，也会因完整 L1 写集不同而返回冲突，而不会把一个 L1 节点复用为两个结构族。

### 6.2 唯一写集

```text
合同版本 = L1中性CRUD合同版本
期望事实代次 = 请求.请求头.期望事实代次
幂等键 = { 请求.幂等身份.值 }
节点 = [ { 本地键=0x02010001, 种类=普通, 属性类型表示=null } ]
关系 = []
值 = []
属性槽变更 = []
退出事实 = []
```

形成后恰一次调用 `L1事实基座服务::提交中性写集`。不得预探测、预分配稳定编码、调用当前代次读取后改写请求、重试提交或在 L1 之外保存候选。

### 6.3 成功形状与读回

首次成功必须同时满足：L1 状态成功、合同版本与幂等键回显一致、事实代次非零、形成权威发布、重试边界不适用、新编码映射恰一项且本地键为 `0x02010001`。

精确重复必须同时满足：L1 状态精确重复、合同版本与幂等键一致、事实代次非零、未形成新发布、重试边界为原幂等键读回收敛，并返回同一唯一映射。

两类成功均用该编码调用 `读取中性历史事实`，核对其为同编码普通节点、创建事实代次等于 L1 首次结果代次、属性类型表示为空；在 S1 基线下当前属性必须为空。成功形成：

```text
结果头.状态 = 已提交 或 精确重复
结果头.事实截止代次 = L1 首次结果事实代次
结果头.变更事实代次 = L1 首次结果事实代次
场景 = 新身份 + 创建生命周期 + 三个空组
```

读回缺失、类型不符、映射重复、映射错键、代次矛盾或成功形状不完整统一返回 `内部不一致` 且不携带场景。

## 7. 当前与历史读取

### 7.1 当前

当前读取构造一份 `L1中性一致当前读取请求`：期望事实代次取 L2 请求头，只选择场景身份对应的一个节点，关系、值、属性值、源关系组和目标关系组全部为空，并恰一次调用 `尝试读取中性一致当前投影`。

成功必须满足合同 / 期望 / 读取代次一致、节点结果恰一项、其余五组为空、项目查询编码一致、项目状态成功、节点为普通、属性类型表示为空、生命周期合法且当前属性为空。返回 `已读取`、非零事实截止代次、无变更代次和完整 S1 场景事实。

顶层入口拒绝 / 许可拒绝 / 事实代次漂移 / 资源失败按同名 L2 状态映射；顶层内部不一致以及项目种类不匹配映射内部不一致；项目未找到 / 已退出分别映射同名状态。失败材料必须为空。

### 7.2 历史

历史读取不把当前入口伪装成历史，固定顺序为：

```text
读取中性当前事实代次并精确比较请求期望代次
-> 读取中性历史事实(场景稳定编码)
-> 再次读取中性当前事实代次并精确比较请求期望代次
-> 两次当前代次相同且历史为普通节点时形成结果
```

任一前后代次不等于请求期望值返回 `事实代次漂移`，不携带场景；许可 / 资源失败映射资源失败，入口拒绝、未找到和内部不一致分别分账。历史事实必须是同编码普通节点、创建代次非零且不晚于请求截止，退出代次为空或不晚于请求截止，属性类型表示为空；S1 基线下属性组仍必须为空。

成功返回 `已读取`，结果截止代次精确等于请求期望代次，生命周期保留创建与可选退出代次，三个结构组为空。该双代次夹取只保证 S1 单节点历史读取，不替代 S2 / S3 对关系和值历史的完整重建。

## 8. 状态映射与失败收口

| L1 来源 | L2 状态 |
| --- | --- |
| 写入成功 / 精确重复 | 已提交 / 精确重复 |
| 写入入口拒绝 / 事实代次漂移 / 幂等冲突 / 资源失败 / 内部不一致 | 同名 L2 状态 |
| S1 一节点写入出现 L1 未找到或已退出 | 内部不一致 |
| 一致读取入口拒绝 / 许可拒绝 / 漂移 / 资源失败 / 内部不一致 | 同名 L2 状态 |
| 当前项目未找到 / 已退出 | 同名 L2 状态 |
| 当前项目属性未设置或种类不匹配 | 内部不一致 |
| 历史读取成功 / 入口拒绝 / 未找到 / 资源失败 / 内部不一致 | 已读取 / 同名状态 |
| 历史入口意外返回已退出或属性未设置 | 内部不一致 |

所有非成功返回合同版本 1、能安全取得的事实截止代次、空变更代次和空场景；不得抛出到调用方、记录成功日志或用默认身份补齐。`未实现`、`属性未设置`、`引用冲突` 在 S1 公开操作中没有合法产生路径。

## 9. 生产外自定义参数验证

### 9.1 验证入口

### 9.2 必过矩阵

在一个新 L1 / L2 服务实例中按顺序验证：

1. 以自定义期望代次和幂等身份合法新增，取得 `已提交`、非零场景身份和三个空组；
2. 原请求精确重复，取得同一身份、`精确重复`、同一截止 / 变更代次且当前代次不推进；
3. 同一幂等身份改用当前代次形成异义请求，取得 `幂等冲突`、空场景且当前代次不推进；
4. 以首次返回截止读取当前场景，取得逐字段一致 `已读取`；
5. 以同一截止读取历史场景，取得相同身份和创建生命周期；
6. 零幂等身份新增返回入口拒绝，零场景身份读取返回入口拒绝，两者前后当前代次不变；
7. 以当前代次加一读取当前场景，取得事实代次漂移、空场景并回显实际截止；
8. 合同版本错误返回入口拒绝且零变化。

验证项目只支持 Debug / Release x64，使用 v145、C++20、Unicode、`/utf-8`，编译前述七个模块源和一个验证 `.cpp`；不得引用主程序入口、启动、装配、线程、D455 或任何业务模块。
