## 4. P01：L2 收口单位与穷尽范围

### 4.1 原问题

现行材料同时使用“节点族”“结构族”“公开服务”和“owner”描述 L2。只按节点族收口会遗漏只有关系 owner 的结构；只按服务名收口又会把名字仍为 `L2*` 的 ARCH-L4 兼容服务误算进 DATA-L2。

因此，收口前必须先确定唯一计数单位：L2 冻结的是节点类型、C++ 服务名称，还是拥有独立事实写权的结构 owner 及其公开面。

### 4.2 已核实事实

1. 4230 声明六个世界公开服务内部有七个节点族：场景、存在、特征定义、特征实例、状态、动态、因果。
2. 4240 增加语言、词条、概念三个节点族，形成现行规范所称十族。
3. `不可变材料服务` 已经拥有独立身份、owner、生命周期、写入、读取、退出和物理材料发布，不是单个裸值；但它没有进入现行十族清单。
4. `L2概念名称结构服务` 拥有独立关系 owner 和公开增查改退，但概念名称关系不是节点族。
5. 当前 `L2节点族` 公共枚举还包含方法、需求、任务；现行架构规则却把其业务结构归入 ARCH-L4，`L2*` 仅是兼容 C++ 名称。
6. 二次至 n 次特征复用特征定义身份和特征结构服务，不形成独立节点族或 owner。
7. 世界树和概念空间聚合属于 DATA-L3；聚合 getter 或装配门面不取得 L2 结构写权。

### 4.3 推荐口径

推荐以“独立结构 owner + 唯一公开服务面”为 L2 收口单位，而不是按文件名、服务名前缀或仅按节点族计数。

在该口径下，候选穷尽范围为：

```text
节点 owner（11）：
  场景、存在、特征定义、特征实例、状态、动态、因果、
  语言、词条、概念、不可变材料

关系 owner（1）：
  概念名称关系

并入既有 owner、不独立计数：
  二次至 n 次特征、当前特征值、状态当前选择、
  场景父子 / 成员 / 宿主、概念上下位 / 定义 / 支持等关系

排除 DATA-L2 冻结面：
  需求、任务、方法的 ARCH-L4 业务结构；
  语素、持久词性；
  世界树与概念空间聚合；
  名称接受、表达和消歧等 ARCH-L5 裁决；
  日志、缓存、线程、外设和其它非基础结构能力
```

`L2结构聚合服务`、普通应用 getter 等装配面应在最后作为“唯一可达性和同实例证明”检查，但不增加结构 owner 或第二写入口。

### 4.4 推荐理由

1. 它与“节点表 + 关系表 + 值表”的基础模型一致：节点型结构与关系型结构都可以拥有强类型 owner，不能强迫所有关系服务伪造节点族。
2. 它能解释不可变材料为什么不是裸 L1 值：材料身份同时承载摘要、格式、来源、生命周期和受控物理内容，需要独立结构 owner。
3. 它把“架构归属”与历史 C++ 名称分开，避免 `L2需求结构服务` 等兼容名反向扩张 DATA-L2。
4. 它允许二次特征、当前值和当前选择继续作为既有结构内部事实，不为每个子结构建立新服务。

### 4.5 不推荐口径及反例

- 只冻结现行十个 `L2节点族`：会漏掉不可变材料和概念名称关系两个已经拥有独立写权的结构面。
- 把所有 `L2*` C++ 服务都算入 DATA-L2：会把 ARCH-L4 的需求、任务、方法业务权威混入基础结构层。
- 每种关系都建立节点族：会把关系事实重复节点化，增加第二身份和第二生命周期。
- 把不可变材料退回 L1 裸值：无法由一个裸值身份表达摘要复核、来源、受控物理发布和退出引用保护。

### 4.6 用户裁决

用户于 2026-09-01 明确回复“确认 P01”，确认采用以下口径：

```text
DATA-L2 的最终收口单位 = 独立结构 owner + 该 owner 的唯一公开服务面；
当前穷尽候选 = 11 个节点 owner + 1 个概念名称关系 owner；
需求 / 任务 / 方法排除出 DATA-L2，另按 ARCH-L4 兼容 ABI 管理；
二次至 n 次特征不独立，DATA-L3 聚合与 ARCH-L5 裁决不进入 L2 冻结面。
```

P01 已转为“已落实”。正式规范、冲突清单、规范目录、层级规则、公共枚举分类、静态门禁和施工 / 验证记录已经同步；发布事实由承载本文件的提交与 `origin/main` 读回证明。P02 只继续裁决旧枚举 / 服务 ABI 的兼容、迁移和禁止新增规则，不得反向改写 P01 的 11+1 穷尽范围。

### 4.7 P01 落实分层

P01 本身只冻结范围分类，不越过后续问题预先改变其机器语义：

1. 正式规范必须把 DATA-L2 从“至少包括”改成穷尽范围，登记 11 个节点 owner、1 个概念名称关系 owner，以及纳入 / 并入 / 排除规则。
2. 公共代码必须为 `不可变材料` 分配不复用既有编码的新节点族值，并提供“当前 DATA-L2 活跃节点族”与“ARCH-L4 兼容节点族”的纯值分类；不得把方法、需求、任务继续误判为当前 DATA-L2 活跃族。
3. P01 不删除方法、需求、任务现有枚举和值式 ABI；其兼容保留、迁移和最终退出由 P02 裁决，避免本项破坏当前 ARCH-L4 WIP。

5. P01 不改变不可变材料既有写入、读取、退出和物理发布行为；只把其 owner / 服务纳入最终 L2 收口范围。

## 5. P02：`L2节点族` 与需求 / 任务 / 方法的 ARCH-L4 兼容边界

### 5.1 原问题

P01 已裁决需求、任务、方法不属于当前 DATA-L2 活跃结构 owner，但公共枚举仍保留 `方法 = 11`、`需求 = 12`、`任务 = 13`，生产代码中也仍存在 `L2需求结构服务`、`L2任务结构服务`、`L2方法结构服务`。因此必须区分三件事：

1. 架构归属是否退出 DATA-L2；
2. 旧枚举编码、DTO、服务名和调用 ABI 是否立即删除；
3. 兼容保留期间是否还允许以 DATA-L2 名义新增业务 owner、公开操作或事实语义。

如果不冻结这一区分，后续既可能因“已退出 DATA-L2”而误删生产 ABI，也可能因“代码名仍叫 L2”而把 ARCH-L4 业务治理重新扩张进 DATA-L2。

### 5.2 当前事实

1. `L2节点族` 的显式数值已经固定为 `方法 = 11`、`需求 = 12`、`任务 = 13`；P01 新增的分类谓词明确把三者判为 ARCH-L4 兼容族，并拒绝把它们判为当前 DATA-L2 活跃族。
2. `L2节点族::方法` 除公共头外仍被方法 DTO 与方法服务用于身份来源读写；`L2节点族::需求` 仍被需求 DTO 与需求服务使用；任务结构当前主要使用独立的 `L2任务身份来源事实`，但公共枚举值 `任务 = 13` 仍构成公开源码 ABI。
3. 以当前源码文件计，`L2需求结构服务`、`L2任务结构服务`、`L2方法结构服务` 分别可达 19、19、15 个源码文件，并已进入普通应用装配、启动、运行期只读查询及治理消费者。
4. 当前受限搜索未发现把 11—13 直接序列化为持久字节的入口；这不能证明不存在外部源码消费者，也不能据此安全重排或复用公开枚举值。
5. 4030 和规范目录已经把三类业务治理归入 ARCH-L4，并明确现有 `L2*` 类型、服务和文件名只作兼容 ABI / 实现名；部分下级规范和代码仍保留旧层名，属于兼容迁移输入，不能反向扩大 P01 的 11+1 范围。
6. 方法、需求、任务现有代码正被另一项活动自我治理施工广泛修改；P02 不得借收口覆盖该异主 WIP，也不能在未冻结迁移合同前机械重命名或删除服务。

### 5.3 推荐口径

```text
1. L2节点族::方法 = 11、需求 = 12、任务 = 13 永久保留为 ARCH-L4
   兼容编码；禁止删除、重排、改值或复用。
2. 三者永久不进入当前 DATA-L2 活跃分类，也不进入最终 DATA-L2
   frozen manifest 的结构 owner / 公开操作清单。
3. 需求、任务、方法在 ARCH-L4 内部分为结构记录面和业务应用面：现有
   L2需求结构服务、L2任务结构服务、L2方法结构服务及相关 DTO、getter、
   文件名和调用 ABI 在迁移完成前只作结构记录面兼容实现；名字中的 L2
   不取得 DATA-L2 架构权威。
4. 兼容实现不得再以 DATA-L2 名义增加新 owner、新公开业务操作或新的
   需求有效性、任务完成性、方法成功性等业务事实语义。
5. 兼容记录面只机械保存、读取和校验调用方已经裁决的身份、关系、
   生命周期、版本、幂等、当前 / 历史和引用闭合；为什么建立、选择、推进、
   结束或判定统一由 ARCH-L4 业务 provider / application 裁决。兼容面只允许
   既有消费者使用、计划内缺陷修复、恢复 / 读回补全及显式迁移。
6. P02 只冻结编码与兼容边界，不修改身份来源 DTO 的 owner、生命周期
   或事实截止字段；这些共同 ABI 留给 P03、P04 裁决。
7. 即使未来全部生产消费者完成迁移，数值 11—13 仍保持永久保留，
   后续可以退出实现可达性，但不得回收为新的 DATA-L2 节点族编码。
```

### 5.4 推荐理由

1. 架构层级由正式职责和 owner 决定，不由 C++ 名称决定；保留旧名字不等于保留错误层级。
2. 11—13 已进入公共枚举并被现有 DTO / 服务消费。立即删除或重排的破坏面远大于保留三个禁复用值的成本。
3. 永久保留编码可以避免旧记录、旧二进制、外部源码消费者或审计材料在未来被同值新语义误读；是否已发现直接持久化不是复用安全性的充分条件。
4. 禁止新增而允许兼容修复，能阻止债务继续扩大，又不会要求在 L2 收口期间同时重写整个 ARCH-L4 生产链。
5. 把 DTO 字段形状留给 P03 / P04，可避免在尚未裁决 owner、生命周期和事实截止时先做局部不一致迁移。

### 5.5 不推荐口径及反例

## 6. P03：身份来源 DTO 是否公开 L1 owner 与生命周期

### 6.1 原问题

P03 施工前，公共 `L2节点族身份来源事实` 同时承载结构身份材料和 L1 技术分区材料：

```text
节点族、节点稳定编码
L1结构所有者身份
族锚点、族归属关系类型、族归属关系、角色或顺序
owner、节点、族锚点、关系类型、归属关系五份生命周期
```

必须裁决：L2 公开调用方是否需要看到 L1 owner 及 owner 生命周期；如果不需要，哪些字段仍属于公开身份来源，哪些只能由服务内部校验。

### 6.2 当前事实

1. P03 施工前，`L2结构公共.数据.h` 的公开 DTO 直接包含 `写入所有者` 和 `所有者生命周期`，共同完整性函数强制两者有效。
2. 场景、存在、特征、状态、动态、因果、语言、词条、概念等 DATA-L2 公开结果复用该 DTO；方法、需求等 ARCH-L4 兼容记录面也有复用，影响不是单一服务私有实现。
3. 4030 v2.6 已冻结：L1 owner 与写端口只作内部结构分区和确定路由，不进入 L2 公开合同；外部调用方不得取得 owner 选择或按 owner 重建服务的能力。
4. 4230 的早期共同 DTO 段仍列出 `L1结构所有者身份` 和 owner 生命周期，但同规范后置第 10.1 节明确规定 `L2节点族身份来源事实` 不得包含 `L1结构所有者身份`、端口或分区证明。按规范内部后置条款优先，当前正文存在待同步矛盾。
5. 4240 第 10 节进一步明确：L2 公开身份、请求、结果、图节点、图边和成功谓词不得包含 L1 owner、写端口或分区证明。
6. 服务内部仍必须用 owner 核对节点、关系和值来自本族唯一结构分区；“不得公开”不等于“内部不再校验”。
7. `所有者生命周期`依附技术 owner，属于内部结构分区证明；节点、族锚点、关系类型、归属关系的生命周期则参与当前 / 历史 / 退出和同截止互证，是否全部公开或压缩为更小合同属于 P04，不应在 P03 顺带删除。

### 6.3 推荐口径

```text
1. `L2节点族身份来源事实`公开 DTO 永久移除 L1 写入 owner 和 owner 生命周期；
2. 唯一结构服务继续在内部读取并校验 owner，不向调用方返回、接受或允许选择 owner；
3. 不为该身份来源 DTO 建立 owner 摘要、owner 见证编码、分区证明或其它换名公开字段；
4. P03 只裁决 owner 与 owner 生命周期，节点及身份来源关系的生命周期留给 P04；
5. 旧身份来源 ABI / 旧持久材料若含 owner，只允许内部解码、恢复校验和审计，不得重新发布为现行身份来源 DTO；其它具名 L2 结果的旧 owner 兼容字段不由 P03 一并裁决。
```

### 6.4 推荐理由

1. 调用方确认“是不是某一存在 / 是否变化”只需要稳定结构身份、类型、当前 / 历史事实和一致截止，不需要知道底层由哪个 L1 分区写入。
2. 暴露 owner 会让上层开始按物理分区判断身份、权限或数据归属，破坏 L2 服务替换内部 owner / 存储布局而不改变公开合同的能力。
3. 删除外露 owner 不削弱唯一写入证明：该证明仍由唯一服务、内部 owner 核对、公开结构读回和原子发布共同完成。
4. 把其它生命周期留给 P04 可避免把“内部 owner 泄漏”和“当前 / 历史 / 退出是否必要”两个不同问题混成一次裁决。

### 6.5 不推荐口径及反例

- **继续公开 owner，声称只读无害**：调用方仍会形成 owner 分支、缓存键或资格判断，公开合同被物理布局绑死。
- **把 owner 改名为来源编码继续公开**：只换名称不改变分区证明泄漏，也可能形成第二身份。
- **连同全部生命周期一起删除**：会抢先裁决 P04，并可能破坏当前 / 历史 / 退出和同截止引用闭合。
- **服务内部也停止 owner 核对**：无法证明节点、关系和值来自本族唯一结构分区，会削弱而不是加强封装。

## 7. P04：生命周期、当前 / 历史 / 退出及事实截止的统一必要边界

### 7.1 已确认的原则口径

用户在核对当前代码实际用途后，于 2026-09-02 明确回复“好，按照这个口径开始执行”，确认以下原则：

```text
1. 事实代次保留为 DATA-L1 内部工程机制，用于事务提交顺序、乐观并发守卫、
   同截止快照读取和恢复校验；它不是现实时间、状态时间、真实性或认知证据。
2. “当前”必须来自明确槽位、明确当前选择关系或该结构 owner 的当前查询视图；
   禁止按最大时间、最大事实代次、首次命中或未退出集合自行推断当前值。
3. “历史”只表示已经换代或退出的旧事实。一个仍有效、但未被本次观察选择的
   特征值不因此成为历史；例如正面轮廓和侧面轮廓可以同时是有效事实，本次采用
   哪个轮廓属于当前观察选择。
4. DATA-L1 可以继续使用当前事实区、历史事实区和派生索引作为内部物理组织；
   DATA-L2 不得把该物理分区机械复制为所有公开 DTO 的固定业务字段。
5. 事实截止只在需要证明多次读取来自同一一致快照、完成写后同代读回、并发守卫
   或恢复互证时公开；不得把事实截止解释成对象在现实中的发生时间或有效时间。
6. 已换代 / 已退出事实可以为变化、动态、因果、引用保护、恢复和审计保留；
   高频临时材料是否 TTL / 数量上限回收，必须由对应事实族的正式保留合同裁决，
   回收后仍服从墓碑和永久编码占用规则。
```

### 7.2 当前代码事实与不能直接删除的原因

1. 事实代次已经用于 L1 写集提交推进、并发漂移拒绝、一致投影和恢复索引重建；它不是闲置字段。
2. DATA-L2 结构服务使用同一事实截止完成多次投影互证、写后读回、幂等重建、退出重建和跨结构端点校验。
3. 当前读取是正式生产消费者的主线入口；历史读取仍被结构服务内部的退出 / 重建 / 恢复校验消费。
4. 当前正式提交树之外的活动 ARCH-L4 WIP 还直接使用状态、动态、存在和场景的历史读取形成任务动作结果快照；该 WIP 不能作为 DATA-L2 永久 ABI 的唯一依据，但也禁止在未交接时覆盖或机械删除其依赖。
5. 因此本项不接受“事实代次、当前和历史全部删除”的整体处置；后继只能逐结构族证明某个公开字段或历史入口无合法消费者后再收缩。

### 7.3 尚待逐族裁决的公开边界

已确认原则还不能自动给出最终公开 ABI。P04 后继必须对 P01 的 11+1 owner 逐项回答：

1. 哪些读取必须接受调用方给定事实截止，哪些只需要服务内部取得一次 Gread；
2. 哪些结果必须返回事实截止以支持上层同快照组合，哪些不应公开内部代次；
3. 哪些结构确实需要公开历史读取，哪些历史只保留给 owner 内部退出、恢复和审计；
4. 哪些“当前”是节点生命周期当前，哪些是属性槽或专用当前选择关系，禁止混为一个字段；
5. 每族的退出保留、旧格式解码、恢复后重建、TTL / 数量上限和墓碑矩阵。

### 7.4 P04.1：公共身份来源的结构生命周期载荷（方向已确认）
