## 4. P01：L2 收口单位与穷尽范围

### 4.1 原问题

现行材料同时使用“节点族”“结构族”“公开服务”和“owner”描述 L2。只按节点族收口会遗漏只有关系 owner 的结构；只按服务名收口又会把名字仍为 `L2*` 的 ARCH-L4 兼容服务误算进 DATA-L2。

因此，收口前必须先确定唯一计数单位：L2 冻结的是节点类型、C++ 服务名称，还是拥有独立事实写权的结构 owner 及其公开面。

### 4.2 已核实事实

1. 4230 声明六个世界公开服务内部有七个节点族：场景、存在、特征定义、特征实例、状态、动态、因果。
2. 4240 增加语言、词条、概念三个节点族，形成现行规范所称十族。
3. `不可变材料服务` 已经拥有独立身份、owner、生命周期、写入、读取、退出和物理材料发布，不是单个裸值；但它没有进入现行十族清单。
4. `L2概念名称结构服务` 拥有独立关系 owner 和公开增查改退，但概念名称关系不是节点族。
5. 当前 `L2节点族` 公共枚举还包含方法、需求、任务；现行架构规则却把其业务结构归入 ARCH-L4，`L2*` 仅是兼容 C++ 名称。
6. 二次至 n 次特征复用特征定义身份和特征结构服务，不形成独立节点族或 owner。
7. 世界树和概念空间聚合属于 DATA-L3；聚合 getter 或装配门面不取得 L2 结构写权。

### 4.3 推荐口径

推荐以“独立结构 owner + 唯一公开服务面”为 L2 收口单位，而不是按文件名、服务名前缀或仅按节点族计数。

在该口径下，候选穷尽范围为：

```text
节点 owner（11）：
  场景、存在、特征定义、特征实例、状态、动态、因果、
  语言、词条、概念、不可变材料

关系 owner（1）：
  概念名称关系

并入既有 owner、不独立计数：
  二次至 n 次特征、当前特征值、状态当前选择、
  场景父子 / 成员 / 宿主、概念上下位 / 定义 / 支持等关系

排除 DATA-L2 冻结面：
  需求、任务、方法的 ARCH-L4 业务结构；
  语素、持久词性；
  世界树与概念空间聚合；
  名称接受、表达和消歧等 ARCH-L5 裁决；
  日志、缓存、线程、外设和其它非基础结构能力
```

`L2结构聚合服务`、普通应用 getter 等装配面应在最后作为“唯一可达性和同实例证明”检查，但不增加结构 owner 或第二写入口。

### 4.4 推荐理由

1. 它与“节点表 + 关系表 + 值表”的基础模型一致：节点型结构与关系型结构都可以拥有强类型 owner，不能强迫所有关系服务伪造节点族。
2. 它能解释不可变材料为什么不是裸 L1 值：材料身份同时承载摘要、格式、来源、生命周期和受控物理内容，需要独立结构 owner。
3. 它把“架构归属”与历史 C++ 名称分开，避免 `L2需求结构服务` 等兼容名反向扩张 DATA-L2。
4. 它允许二次特征、当前值和当前选择继续作为既有结构内部事实，不为每个子结构建立新服务。

### 4.5 不推荐口径及反例

- 只冻结现行十个 `L2节点族`：会漏掉不可变材料和概念名称关系两个已经拥有独立写权的结构面。
- 把所有 `L2*` C++ 服务都算入 DATA-L2：会把 ARCH-L4 的需求、任务、方法业务权威混入基础结构层。
- 每种关系都建立节点族：会把关系事实重复节点化，增加第二身份和第二生命周期。
- 把不可变材料退回 L1 裸值：无法由一个裸值身份表达摘要复核、来源、受控物理发布和退出引用保护。


5. P01 不改变不可变材料既有写入、读取、退出和物理发布行为；只把其 owner / 服务纳入最终 L2 收口范围。

## 5. P02：`L2节点族` 与需求 / 任务 / 方法的 ARCH-L4 兼容边界

### 5.1 原问题

P01 已裁决需求、任务、方法不属于当前 DATA-L2 活跃结构 owner，但公共枚举仍保留 `方法 = 11`、`需求 = 12`、`任务 = 13`，生产代码中也仍存在 `L2需求结构服务`、`L2任务结构服务`、`L2方法结构服务`。因此必须区分三件事：

1. 架构归属是否退出 DATA-L2；
2. 旧枚举编码、DTO、服务名和调用 ABI 是否立即删除；
3. 兼容保留期间是否还允许以 DATA-L2 名义新增业务 owner、公开操作或事实语义。

如果不冻结这一区分，后续既可能因“已退出 DATA-L2”而误删生产 ABI，也可能因“代码名仍叫 L2”而把 ARCH-L4 业务治理重新扩张进 DATA-L2。

### 5.2 当前事实

1. `L2节点族` 的显式数值已经固定为 `方法 = 11`、`需求 = 12`、`任务 = 13`；P01 新增的分类谓词明确把三者判为 ARCH-L4 兼容族，并拒绝把它们判为当前 DATA-L2 活跃族。
2. `L2节点族::方法` 除公共头外仍被方法 DTO 与方法服务用于身份来源读写；`L2节点族::需求` 仍被需求 DTO 与需求服务使用；任务结构当前主要使用独立的 `L2任务身份来源事实`，但公共枚举值 `任务 = 13` 仍构成公开源码 ABI。
3. 以当前源码文件计，`L2需求结构服务`、`L2任务结构服务`、`L2方法结构服务` 分别可达 19、19、15 个源码文件，并已进入普通应用装配、启动、运行期只读查询及治理消费者。
4. 当前受限搜索未发现把 11—13 直接序列化为持久字节的入口；这不能证明不存在外部源码消费者，也不能据此安全重排或复用公开枚举值。
5. 4030 和规范目录已经把三类业务治理归入 ARCH-L4，并明确现有 `L2*` 类型、服务和文件名只作兼容 ABI / 实现名；部分下级规范和代码仍保留旧层名，属于兼容迁移输入，不能反向扩大 P01 的 11+1 范围。
6. 方法、需求、任务现有代码正被另一项活动自我治理施工广泛修改；P02 不得借收口覆盖该异主 WIP，也不能在未冻结迁移合同前机械重命名或删除服务。

### 5.3 推荐口径

```text
1. L2节点族::方法 = 11、需求 = 12、任务 = 13 永久保留为 ARCH-L4
   兼容编码；禁止删除、重排、改值或复用。
2. 三者永久不进入当前 DATA-L2 活跃分类，也不进入最终 DATA-L2
   frozen manifest 的结构 owner / 公开操作清单。
3. 需求、任务、方法在 ARCH-L4 内部分为结构记录面和业务应用面：现有
   L2需求结构服务、L2任务结构服务、L2方法结构服务及相关 DTO、getter、
   文件名和调用 ABI 在迁移完成前只作结构记录面兼容实现；名字中的 L2
   不取得 DATA-L2 架构权威。
4. 兼容实现不得再以 DATA-L2 名义增加新 owner、新公开业务操作或新的
   需求有效性、任务完成性、方法成功性等业务事实语义。
5. 兼容记录面只机械保存、读取和校验调用方已经裁决的身份、关系、
   生命周期、版本、幂等、当前 / 历史和引用闭合；为什么建立、选择、推进、
   结束或判定统一由 ARCH-L4 业务 provider / application 裁决。兼容面只允许
   既有消费者使用、计划内缺陷修复、恢复 / 读回补全及显式迁移。
6. P02 只冻结编码与兼容边界，不修改身份来源 DTO 的 owner、生命周期
   或事实截止字段；这些共同 ABI 留给 P03、P04 裁决。
7. 即使未来全部生产消费者完成迁移，数值 11—13 仍保持永久保留，
   后续可以退出实现可达性，但不得回收为新的 DATA-L2 节点族编码。
```

### 5.4 推荐理由

1. 架构层级由正式职责和 owner 决定，不由 C++ 名称决定；保留旧名字不等于保留错误层级。
2. 11—13 已进入公共枚举并被现有 DTO / 服务消费。立即删除或重排的破坏面远大于保留三个禁复用值的成本。
3. 永久保留编码可以避免旧记录、旧二进制、外部源码消费者或审计材料在未来被同值新语义误读；是否已发现直接持久化不是复用安全性的充分条件。
4. 禁止新增而允许兼容修复，能阻止债务继续扩大，又不会要求在 L2 收口期间同时重写整个 ARCH-L4 生产链。
5. 把 DTO 字段形状留给 P03 / P04，可避免在尚未裁决 owner、生命周期和事实截止时先做局部不一致迁移。

### 5.5 不推荐口径及反例

- **立即删除 11—13 和三个旧服务**：普通应用装配、启动、只读查询和治理消费者会同时失去依赖，P02 会越权变成一次未设计的 ARCH-L4 全链迁移。
- **重排枚举，让不可变材料占用 11**：旧源码或旧材料会把同一数值解释成不同节点族；节省三个枚举槽没有实际收益。
- **因为服务名带 `L2` 就继续算 DATA-L2**：这会直接推翻 P01 的穷尽闭集，并允许需求有效、任务完成、方法成功等业务裁决重新进入数据层。
- **永远保留全部旧实现且允许继续扩张**：兼容会变成第二套长期权威，ARCH-L4 永远无法形成清晰 provider / service 边界。
- **现在就统一改名但不迁移消费者**：会产生双入口、转发壳或半迁移状态，既没有缩小公开面，也增加了身份歧义。
- **等找到持久序列化证据后才保留编码**：公开源码 ABI 本身已足以要求不重排；没有命中内部序列化不等于外部消费者和历史材料不存在。
