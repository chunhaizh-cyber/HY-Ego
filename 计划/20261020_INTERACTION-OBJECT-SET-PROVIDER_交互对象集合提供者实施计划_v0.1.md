## 1. 目标和起点

交付正式存在引用集合、引用生命周期保护和生产自我交互对象特征初始化/读回，为获取服务对象提供最早底层能力。成员不限人类。生产基线`baaf7f03f9ef18717466898236d9d802297fd849`，设计时main为`8bc81cc9`；发布后执行者按计划精确版本重新S0。

先天集合类型、需求集合更新事务、二次派生和归档既有能力可复用，但没有存在集合规则和成员保护。本计划合并DTO、保护、消费者及生产装配为一个代码切片，不拆分交给多个所有者。

## 3. 实施及失败收口

1. 核对所有权、main/head、实际集合相关分支、成员生命周期/锁路径和正式公开类型；记录blob。
2. 按设计第3—5节实现尾追加类型、窄身份读、G保护和E清理前原子技术门；第5.3节整组F清理令牌先检查既有联合占用、再持F锁跨E门与整组消费，正常占用必须门前零写拒绝。成员不能以U64裸码逃过删除保护。
3. 实现FC所有域/比较/聚合/保护分支、F/E/world两规则消费及零附加片段提交，不改变需求集合合同。
4. 实现算法11、无变化率派生与归档格式兼容；按详细设计第7.1节为执行场景采集补新域边界未展开，为结构化服务固定语义补规则6/新域显式不支持，禁止静默略过或扩大模拟/业务支持。
5. 在真实普通应用装配提供者，真实自我建立后确保唯一交互对象F并正式读回，失败阻止启动线程。
6. 从实际diff复核所有variant访问者、规则switch和读取/保护路径；统一编译一次，形成专属记录和知识变更清单。

材料/结构/工程错误不成为不满足、空集或业务失败。并发前提变化返回明确技术状态不自动覆盖；G先发布后业务写失败可保留合法保护。E清理阶段故障保留清理门并工程终止，重启拒绝残留，不自动恢复。详细设计规定的公开合同、保护或归档无法机械实现时具名退回设计，不现场决定新机器语义。
