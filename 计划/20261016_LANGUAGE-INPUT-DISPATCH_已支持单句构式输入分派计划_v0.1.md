# LANGUAGE-INPUT-DISPATCH 已支持单句构式输入分派计划

日期：2026-10-16。版本：v0.1。状态由`计划/计划索引.md`唯一维护。设计及代码事实基线：`a9cc24c497541aa6796e2b2f7c572b497845f8f6`。

## 1. 目标、闭环和正式依据

用户长期目标是按正式语言知识的句型生成双向转换函数，再由主函数分派。本叶只交付**输入侧**一个公开的、只读的单句分派入口：对当前已实现的 S01 对象归类、S02 概念上下位、S09 概念归类确认问句，先枚举已发布语言知识并按完整定义识别可调用构式，再分别调用现有解释函数，汇集带类型、来源和原文范围的候选及每一分支的非成功。主函数不按“是”“吗”等词面、规则枚举顺序或第一条候选裁决含义。

本叶的成功只表示**该三种已支持构式闭集内**的输入解释。`7250`的 S01—S20/V01—V26 是构式示例目录，不是已经发布的可执行规则；同一行内以斜线分开的形式必须成为不同知识定义。V26“有事”虽已有逻辑规范，但集合条件概念的物理字段、知识初始化、输入解释及任意存在的任务求值提供者尚不存在。本叶不实施它们，不把“甲有乙”统一变为归属，不扩展句段篇或世界事实写入。

依据：[0050](../规范/0050_项目通用机器逻辑与禁止性规则总纲_20260721.md)、[2340](../规范/2340_根规范_自然语言知识.md)、[7230](../规范/7230_子规范_语言材料知识与交互字段.md)、[7240](../规范/7240_子规范_自然语言双向转换与组织规则.md)、[7250](../规范/7250_子规范_最小汉语知识与语言学习.md)、[代码归属规范](../规范/代码文件建立归属与模块命名规范.md)。现行 S01/S02/S09 详细设计和专属验证记录只用于核对已发布代码的合同与边界；施工以当前源码复核为准。

## 2. 当前事实与复用裁决

`海中鱼巣/业务/解释.基础语言.h/.cpp` 已有 `解释单句基础归类`、`解释单句概念上下位`、`解释单句概念归类确认`。S01 只接受单个 `A`—`Z` 技术占位主体，默认/显式现实根，主体绑定由调用方提供；S02 解释同类别概念上下位；S09 解释由 S02 子规则和“吗”形成的确认问句，内部会调用 S02。三者均只读，返回各自状态、知识身份、词/名称来源和原文范围，未直接保存或采信现实事实。三入口现在互不形成公开输入总分派；搜索生产调用点未发现这三个解释函数的普通应用调用。

`海中鱼巣/业务/表达.基础语言.h/.cpp` 已有 `生成基础语言表达`：它枚举知识，按表达目的、含义操作、作用域和角色类别匹配后生成文本；S02/S09 的唯一回读包装也已存在，S01 输出受可恢复对象指称限制。本叶**复用**该输出方向，不建第二输出主入口，不改表达文件。`新_语言类::枚举语言知识候选`提供调用期完整知识列表；当前 C++ 目标/结构 DTO 只覆盖有限的陈述/提问、四种含义操作及基础表达。S03/S05 等知识存在不等于其输入解释函数已经实现。本叶用现有三种解释函数组合复用，新增的分派本身归同一个语言解释业务 owner，不向 DATA 层下沉业务句意判断。

本叶不需要先建设新的知识/角色读取提供者：完整知识枚举和三个分支所需的当前公开只读提供者已经存在。也不修改 `海中鱼巣/装配.普通应用.cpp`，避免与现行 `PARTIAL-SERVICE-DEMAND` 的生产装配范围冲突。输入总入口作为独立可编译 ABI 交付，生产消息接入另行设计。

## 3. 公开合同与物理位置

唯一新增公开入口定义在 `海中鱼巣/业务/解释.基础语言.h`，实现及必要私有辅助定义在同名 `.cpp`。工程已经登记该头源，不新增文件或工程登记。下列新类型均置于现有 `海中鱼巣` 命名空间；沿用现有 `稳定编码`、`解释目标世界根`、`解释已绑定主体`及三种子结果，不复制概念、词条或世界事实。

```cpp
enum class 基础单句构式种类 : std::uint8_t {
    S01对象归类 = 1, S02概念上下位 = 2, S09概念归类确认 = 3
};
struct 基础单句分支预算 final {
    std::size_t 最大名称候选数 = 0;
    std::size_t 最大组合候选数 = 0;
    std::size_t 最大确认候选数 = 0;
};
struct 基础单句分派请求 final {
    std::string 固定原文;
    稳定编码 语言节点;
    std::optional<稳定编码> 未核验来源语言记录节点;
    std::optional<解释目标世界根> 显式所述世界根;
    std::optional<解释已绑定主体> 主体绑定;
    std::optional<稳定编码> 受询者存在节点;
    std::size_t 最大原文标量数 = 0, 最大知识条目数 = 0;
    基础单句分支预算 S01预算, S02预算, S09预算;
};
enum class 基础单句分派状态 : std::uint8_t {
    闭集唯一已解, 闭集唯一待绑定, 闭集多义待解,
    无已实现知识, 无闭集句面匹配, 分支未完成,
    输入拒绝, 格式失败, 知识读取未完成, 读取漂移, 内部不一致
};
using 基础单句分支载荷 = std::variant<基础语言输入结果,
    基础概念上下位输入结果, 基础概念归类确认输入结果>;
struct 基础单句分支结果 final {
    基础单句构式种类 构式;
    基础单句分支载荷 结果;
};
struct 基础单句分派结果 final {
    基础单句分派状态 状态 = 基础单句分派状态::输入拒绝;
    std::string 固定原文;
    std::optional<稳定编码> 未核验来源语言记录节点;
    std::optional<新语言查询状态> 语言读取状态;
    std::optional<新语言知识状态> 知识读取状态;
    std::vector<基础单句分支结果> 已调用分支组;
    std::vector<稳定编码> 尚无输入解释器的知识节点组;
};
基础单句分派结果 解释已支持单句构式(
    const 基础单句分派请求&, const 新_世界树类&,
    const 新_场景类&, const 新_存在类&, const 新_语言类&,
    const 新_词类&, const 概念_名称关系类&,
    const 概念_存在类&, const 概念_特征类&);
```

`最大原文标量数`和`最大知识条目数`是共享额度，非空输入须非零；每个分支只消费自己的预算：S01 要求名称额，S02 还要求组合额，S09 还要求确认额。对应分支预算为零由该子入口返回`输入拒绝`，不阻止其它分支。`显式所述世界根`和`主体绑定`只转给 S01；`受询者存在节点`只转给 S09。S02/S09 不读取世界根，S01 的现实根不可读、非现实根未支持或主体不属于世界都只是 S01 分支结果，不阻止纯概念解释。来源节点仍是**未核验**引用，分派不升级其真实性。

本入口只借用只读服务引用，不拥有对象，不写 L1/语言材料/概念/任务，不建立事务、迁移或持久生命周期。调用方只能依现有装配拥有服务；本叶不添加生产调用点。三种分支结果为原 DTO 完整按值载荷，候选的强类型身份、名称关系、知识节点、作用域及原文范围均不改写。S09 载荷内的 S02 子含义只属于其外层确认候选，不另加一个顶层 S02 候选。`尚无输入解释器的知识节点组`只是已读知识身份提示，不表示它们匹配本句，也不得据此证明全语言唯一。

## 4. 分派与状态算法

1. 严格解码固定 UTF-8 原文并按 Unicode 标量核对非空、共享额度和语言节点；格式错误返回`格式失败`，其它共享输入非法返回`输入拒绝`。不增删空格/标点，不改变子入口的句面闭集。
2. 调用 `新_语言类::获取语言`确认语言可读，再以共享 `最大知识条目数`调用 `枚举语言知识候选`。非完整枚举、资源失败、结构错误或额度不足均返回`知识读取未完成`，在结果的语言/知识读取状态字段保留所遇原状态，不得把不完整列表当“无规则”；工程异常沿原有工程处理路径上抛，不转换为正常语言判断。此处不预读现实世界根。
3. 对每个同语言知识定义，依次使用本 `.cpp` 现存私有 `是S01结构`、`是S02结构`、`是S09结构`判断目标目的、含义操作/作用域、角色种类/类别、结构项形态及子规则映射。三形态分别对应三调用分支；若一个定义竟落入多形态，返回`内部不一致`，不按顺序选一种。其它知识节点按稳定编码去重放入`尚无输入解释器的知识节点组`。不得从来源标签、词面、S/V 示例编号或标点猜分支。正式知识定义在 `.cpp` 里只供分派判断；词条、名称、对象的完整文本匹配和消歧仍由子入口负责。
4. 每种至少有一项知识的已实现形态至多调用对应解释函数一次。构造子请求时原文、语言、来源及共享预算原样传入，按 §3 精确附加分支材料与额度。三个子入口会自行枚举该形态的所有知识并返回完整候选；不能每知识调用一次后取首个成功。调用顺序可固定 S01、S02、S09 以便结果稳定，但顺序不具语义优先级；即使前一分支待绑定、失败或匹配，也继续处理其它已选分支。若某子入口返回`缺规则`而预读确认该形态存在，应按知识读取变化标记`读取漂移`，不得误报无已实现知识。
5. 末尾重新完整枚举当前语言知识，按稳定知识身份和完整定义与起始列表比较；不一致或再读失败返回`读取漂移`或`知识读取未完成`。已调用分支组可留作诊断，但不得将其候选采用为完整解释。各子入口自己的读回/漂移规则继续生效；两次枚举不是跨服务原子快照，不声称与世界事实同一时刻。
6. 只统计**顶层**三分支实际返回的候选数。一个分支的`多规则待解`或`概念多义待解`即使候选去重后只剩一项，仍为待解。所有已调用分支均完成、候选恰一且相应子状态是`已形成唯一含义`或`已形成唯一信息请求`时为`闭集唯一已解`；候选恰一且相应子状态是`主体待绑定`或`受询者待绑定`时为`闭集唯一待绑定`；多分支/多候选或任一多义子状态为`闭集多义待解`。任一已调用分支有未知词、缺名称、角色不相容、额度不足、引用不可读、世界不支持/不可读、工程或内部错误等非完整状态时，顶层为`分支未完成`，**仍保留**其它完整分支结果与候选，不把工程失败说成无候选或业务否定。没有此类未完成且所有分支为`结构未支持`时为`无闭集句面匹配`。没有可分派知识时为`无已实现知识`。这里的“唯一”始终受三构式闭集限制，不能被调用方表述为全语言唯一或现实主张已成立。

第6步的`分支未完成`优先于“唯一/多义”，但它只标记总入口未闭合，不改变其它分支的原有成功状态。若 S01 因现实根失败而 S02 完整命中，S02 候选仍完整返回，调用方可继续使用该独立结果；不得因 S01 的世界状态清空它。未支持知识的列表即使非空，也不把当前句机械标成歧义，因为本叶没有证明这些规则能匹配原文；反过来，闭集唯一也不能证明它们不能匹配。对外要明确这是一项阶段性已支持解释结果。
