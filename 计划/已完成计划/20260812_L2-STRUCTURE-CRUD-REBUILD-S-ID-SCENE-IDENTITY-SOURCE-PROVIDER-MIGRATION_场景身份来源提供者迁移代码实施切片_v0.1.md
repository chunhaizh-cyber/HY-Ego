## 1. 目标、范围与完成条件

在 4230 v0.3、G2 和现有 S1 / S2-PRE2 / S2 / S3 真实结果上原位迁移唯一 `L2场景结构服务`：把场景节点、父子 / 成员关系、固定属性和退出从 L1 中性写面迁入场景独占 owner，建立场景身份来源和场景四表示属性类型正式登记，并把所有公开场景读写统一收敛到该来源。

完成必须同时成立：

1. `L2场景所有者交付` 是不可默认构造、不可复制、只可移动且不公开 raw 端口的强类型交付；
2. 场景 owner 内先建立不可变族锚点、族归属关系类型和四种固定属性类型；
3. 新场景节点和唯一非自环族归属关系由同一 owner-scoped 写集同代发布；
4. 公开 `读取场景身份来源` 同时支持当前 / 历史，场景节点、完整场景、关系 CRUD、属性写入、反向成员读取和退出均复用该来源；
5. 父子两端都证明为正式场景来源，成员场景端证明场景来源、存在端消费 E-ID `读取存在身份来源`，不再接受弱普通节点形状；
6. 固定属性类型必须来自场景 owner 的正式四类型登记且与材料表示匹配，禁止普通 L1 属性类型、旧世界登记或调用方任意类型；
7. 场景退出显式闭合族归属关系、节点、当前父子 / 成员关系和当前属性值，全部同代退出；
8. wrong-family、legacy、裸 L1、旧未标记和场景内部锚点 / 类型节点精确拒绝且零变化；
9. 普通应用按最终 G2 provider 前缀发布唯一场景服务并提供同实例 getter；
10. 根工程双配置、专项双配置、严格规范检查和临时文件独立清理完成。

这是现有场景 CRUD 的身份来源与 owner 原位迁移，不新建第二场景服务、不重做 S1—S3 业务合同，也不恢复世界登记、世界树门面或“现实世界根”。本叶不判断现实世界、根资格、所在场景、成员资格或业务准入，不实施 A1。

## 3. 依赖与激活门禁分账

### 3.1 直接机器依赖

### 3.2 路线顺序与共享资源门禁

按用户指定路线和 4230 的普通应用顺序，S-ID 当前登记 `待激活`。激活前必须同时确认：

1. T1 / T2、DYN1 / DYN2、C1 / C2 的最终结果已进入正式 `main` / `origin/main` 并释放唯一活动代码段、普通应用、主工程、共享构建 / 验证资源；
2. 普通应用最终已形成并保持 `存在 -> 特征定义 / 实例 -> 状态 -> 动态 -> 因果` 前缀，场景只能后继追加，不能重排、复用 owner 建立身份或改写既有状态值；
3. E-ID 当前 / 历史来源 ABI、场景三个生产文件和 L1 owner 行为仍逐字段匹配本计划；
4. 从新 HEAD 重新计算普通应用下一组装配状态值、生产 blob、文件所有权、index 和验证资源。

前序计划实现差异只在它改变普通应用追加位置、共享资源或直接 L1 / E-ID / 场景 ABI 时构成 S-ID 漂移；不得把路线顺序写成虚假的服务依赖。任一真实合同漂移必须保持 `待激活` 并具名退回计划支撑。

## 6. 来源、属性类型和当前 / 历史读取合同

### 6.1 来源初始化与节点同写

`初始化场景身份来源` 用场景端口和固定来源幂等身份同写一个普通族锚点与一个普通族归属关系类型节点，逐项核对 owner、映射、首次 / 重复重试边界和 owner-aware 当前读回，形成只读定位 `{owner, 锚点, 归属类型, 建立代次}`。锚点与类型永久当前，不作为公开场景。

`新增场景节点` 的 owner-scoped 写集精确为：

```text
节点 = [{场景节点本地键, 普通}]
关系 = [{场景族归属关系本地键,
         源=新场景本地键,
         目标=场景族锚点稳定编码,
         类型=场景族归属关系类型稳定编码,
         角色=1}]
值 / 属性槽 / 退出 = []
```

首次 / 精确重复必须读回节点和归属关系同 owner、同创建代次、非自环、精确角色 1；返回现有 `L2场景节点写入结果` 的场景骨架，不向该结果新增内部关系字段。归属关系稳定编码只由后续 `读取场景身份来源` 返回。

### 6.2 当前来源

当前先按 L1 当前生命周期裁决：已退出优先返回 `已退出` 空载荷，不补读历史判断族；当前可读时用 owner-aware 一致当前投影一次核对 owner 事实、请求节点、锚点、归属类型和以请求节点为源的精确关系组。成功要求唯一关系指向锚点、角色 1、关系 / 节点 / 类型 / 锚点同场景 owner 且共同截止等于请求期望代次。

目标非普通节点、属性类型节点、owner 不是场景 owner、legacy、裸 / 未标记、锚点、归属类型、关系类型或四属性类型内部节点固定 `入口拒绝`。目标已是场景 owner 但来源定位后出现关系 owner 错、重复、错锚点、错类型、错角色、混代或提前退出固定 `内部不一致`。期望代次变化为漂移；许可 / 资源同名映射。

### 6.3 历史来源

历史以请求期望代次前后夹取保证稳定，在 `min(历史截止, 节点退出前一代)` 的判定截止读取节点、锚点、类型和源关系组；空组再以节点创建代次回退区分从未登记与提前退出，随后读取节点 / 归属关系完整生命周期并投影到请求历史截止。所有项目必须由场景 owner 覆盖、关系非自环、角色 1、创建代次一致且生命周期覆盖截止。

历史截止早于创建返回未找到；截止等于或晚于退出返回已退出；旧未标记或错误族不 adoption、不扫描、不从当前补项。两次当前代次变化为漂移；结构矛盾内部不一致；成功结果的 `事实截止代次` 和 `历史截止事实代次` 均等于请求历史截止。

### 6.4 属性类型读取和写入

`建立场景属性类型登记` 只以场景端口和固定幂等身份同写四个属性类型节点，逐项核对 owner、表示、四映射唯一及首次 / 重复边界。`读取当前场景属性类型登记` 必须用 owner-aware 一致当前投影读回四节点；不能只更新定位截止或借普通 L1 类型。

`新增场景固定属性` / `换代场景固定属性` 提交前先读取当前场景来源和当前属性类型登记，要求两者截止均等于请求期望代次；按 `std::variant` 活动类型唯一选择对应场景强类型，且 `请求.新属性.属性类型身份` 必须等于该登记编码。随后由场景端口提交现有值 / 槽 / 退出形状。wrong owner 类型、普通 L1 类型、其它族类型、登记类型与材料表示不匹配均入口拒绝且零变化；定位 / L1 读回矛盾为内部不一致。

`来源稳定编码` 仍是不透明既有稳定编码并受 L1 引用闭包保护；S-ID 不解释来源类别，也不要求来源属于场景 owner。

## 7. 现有 CRUD 原位迁移

### 7.1 统一写面

现有 `建立场景关系类型登记`、节点 / 属性、父子新增 / 替换 / 退出、成员新增 / 替换 / 退出和场景退出全部改用 `L1所有者范围写集请求` 与唯一场景端口；状态、首次 / 重复、编码映射、读回和引用冲突映射到现有 L2 DTO。禁止保留可达 `L1中性写集请求`、raw L1 写服务或第二幂等账。

关系类型登记在场景 owner 内同写父子 / 成员两个普通类型节点并 owner-aware 读回。现有公开 DTO、规则版本和 `{1}` 调用形状保持，但底层固定幂等身份、owner 与读回来源改为本节合同。

### 7.2 父子关系

父子新增、替换和退出必须在同一期望代次对涉及的每个场景端点调用当前 `读取场景身份来源`；替换中旧父、新父、子三端点分别证明，允许旧父等于新父但仍按完整请求幂等裁决。保留 S2 的一个当前直接父、无环、非零顺序、原子替换和引用保护语义。

读回的关系、源 / 目标场景和关系类型必须全部属于场景 owner；来源、关系、节点或登记任一混代 / 矛盾均内部不一致。退出旧关系不退出场景来源关系。

### 7.3 成员关系

成员新增、替换和退出在同一期望代次证明场景端点的当前场景来源，并调用 E-ID `读取存在身份来源(当前)` 证明存在端点；不得以 `读取完整存在`、普通节点形状或 L1 当前节点替代存在来源。替换时旧 / 新场景分别证明，存在端点只证明一次且与两场景来源共享请求期望代次。

历史完整场景和历史关系读回对成员存在端点以同一历史截止调用 E-ID 历史来源；场景服务不重演存在 owner / 归属证明。反向成员读取先证明请求存在的 E-ID 当前来源，再读场景 owner 下的成员目标关系组；每个源场景必须逐项证明当前场景来源，不再只看普通场景骨架。

### 7.4 场景节点和完整读取

`读取场景节点` 当前 / 历史先读取场景来源，再从同一截止形成现有场景骨架。`读取完整场景` 把场景来源、场景节点、属性槽 / 值、父子 / 成员关系、关系端点来源和存在来源纳入同一截止闭环；当前两轮投影与历史前后夹取可继续复用 S3 结构，但不能用当前补历史或用 owner + 节点形状代替来源。

当前成功要求所有当前属性类型属于场景四类型登记、全部父 / 子场景端点有当前场景来源、全部成员存在端点有当前 E-ID 来源。历史成功对每个在截止有效的场景 / 存在端点传同一历史截止；晚于截止的未来退出在 DTO 投影清空，截止时已退出的自有关系 / 属性不进入当前组。合法空属性 / 子场景 / 成员组仍为成功空组。

### 7.5 场景退出

退出前以当前 `读取场景身份来源` 取得唯一归属关系并核对请求字段；再取得同截止完整场景快照。owner-scoped 退出写集精确包含：

```text
请求.场景
+ 请求.族归属关系稳定编码
+ 可选当前直接父关系
+ 全部当前直接子关系
+ 全部当前直接成员关系
+ 全部当前固定属性值
```

集合排序唯一，必须与权威快照逐项相等；漏项、多项、错归属、错关系或错值返回引用冲突且零变化。成功 / 精确重复读回节点、归属、父子 / 成员和属性全部在同一变更代次退出；锚点、族归属类型、父子 / 成员类型和四属性类型不退出。外部当前引用继续由 L1 返回引用冲突，不自动级联退出存在或其它消费者事实。

`L2场景退出结果::成功()` 必须同时验证已退出场景投影和新增的归属关系退出证明；为保持结果自证，在 `L2场景退出结果` 的 `已退出场景` 后新增 `std::optional<L2节点族身份来源事实> 已退出身份来源`，成功要求其节点族为场景、节点编码匹配、节点 / 归属关系退出代次等于结果变更代次，而 owner / 锚点 / 类型生命周期仍覆盖截止。非成功两载荷均空。

## 8. 普通应用 provider

执行 S0 必须从最终前缀计算下一状态值，不得把本计划形成时的 0—10 当成未来最终编号。机械追加三项状态，语义顺序固定为：

```text
场景所有者范围建立失败
场景所有者交付形成失败
场景服务构造失败
```

既有全部状态数值和意义保持，三项从当前最大值加一连续追加。普通应用使用同一 `L1事实基座运行包` 和签发器，以 `场景所有者建立身份` 建立独占 owner，形成 `L2场景所有者交付`，在存在、特征、状态、动态、因果服务全部构造成功后构造唯一场景服务。上下文最后追加 `std::unique_ptr<L2场景结构服务>`，构造参数和成员顺序与 provider 一致；新增 const / 非 const `取得L2场景结构服务()`，重复 getter 必须返回同一实例。

任一阶段失败不发布半构造上下文；场景 service 必须晚于因果 provider，但只接收 const L1、const 存在和场景交付，不接收特征 / 状态 / 动态 / 因果实例。

## 9. 状态、幂等、并发与异常

非成功优先级固定：纯值非法 / 保留幂等身份 -> 入口拒绝；内部登记未加载 -> 入口拒绝；登记其它失败 -> 同名；既有幂等 -> 精确重复 / 幂等冲突；新键旧期望 -> 漂移；场景 / 存在来源未找到、已退出或拒绝 -> 同名；属性未设置 / 引用冲突保留现有语义；许可 / 资源 -> 同名；事实矛盾 -> 内部不一致。

提交前所有非成功必须空载荷、无变更代次、零普通事实变化。L1 已成功发布后读回分配失败 / 矛盾返回资源失败 / 内部不一致，可回显已安全取得的首次代次，但不得宣称零变化、补偿退出或二次提交；只允许原完整请求和原幂等身份收敛。精确重复必须回读首次完整结果，不推进代次。

来源、关系类型和属性类型登记分别使用私有锁；CRUD 不持登记锁跨 L1 / E-ID 调用，只复制完整定位后释放。构造期初始化串行完成后才发布服务。公开场景操作不得持场景内部锁调用存在服务；L1 owner 端口自身串行化提交。本叶不新增仓锁、全局锁、缓存、后台线程、恢复或公平性承诺。

`std::bad_alloc` / `std::length_error` 映射资源失败，其它未处理异常映射内部不一致。纯值辅助标注“无适用错误分支”，调用 L1 / E-ID、提交、读取和业务前置标注“向上送出”。

## 10. 实施顺序

1. 新增来源 DTO、四属性类型登记 DTO、退出字段 / 载荷和纯值完整性；

4. 把关系类型登记迁到场景端口，再建立四属性类型登记和 owner-aware 读回；
5. 把节点新增改为节点 + 族归属同写，节点读取改为消费来源；
6. 把固定属性写 / 换代迁到场景端口并冻结四类型选择；
7. 把父子 CRUD 迁到场景端口和场景端点来源；
8. 把成员 CRUD 迁到场景端口、场景来源和 E-ID 存在来源；
9. 把当前 / 历史完整读取与反向成员读取闭合到正式来源；
10. 把场景退出改为显式归属 + 全部现有闭包同代退出；
11. 在最终 G2 前缀末尾追加普通应用场景 provider、状态和 getter；
