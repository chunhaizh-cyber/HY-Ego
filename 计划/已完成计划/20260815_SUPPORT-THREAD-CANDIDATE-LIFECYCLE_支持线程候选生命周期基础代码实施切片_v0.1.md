# SUPPORT-THREAD-CANDIDATE-LIFECYCLE 支持线程候选生命周期基础代码实施切片 v0.1

## 1. 目标与完成条件

实现 BIZ-L4-001-04-00-01—03 的共享支持线程候选生命周期：一个移动租约唯一拥有一个 `std::jthread`，真实线程入口发布内部进入/完成见证，启动失败或调用方回收时固定请求停止并完成后 `join`。生命周期 provider 只接收最佳努力投影，不决定物理成功。

完成必须同时满足：

1. 请求、结果、入口结果和见证值类型只有一个所有者；事件日志、缓存统计和持久证据后继不重复声明共享 DTO。
2. 候选租约不可复制、只允许移动构造、零 detach；入口端口和生命周期端口的借用生命周期覆盖租约。
3. 创建、进入等待、超时后回收、入口故障和析构安全网均零悬空 joinable 线程。
4. 进程级权威守卫保证同一 `(运行代次, 线程逻辑身份)` 最多形成一次候选；8110 发布失败只形成投影降级计数，不能替代防重复守卫或反向裁决物理结果。
5. 根工程双配置和生产外公开面专项通过；具体支持线程、装配和完整启动链保持 NOT_RUN。

## 4. 物理实现和函数合同

1. 新建 `支持线程候选.数据.h`，只声明详细设计第 3.1 节的稳定值类型；按 `SUPPORT_THREAD_CANDIDATE_NO_INCLUDES` 分开传统头自带依赖与模块 purview 展开，因无独立实现不建立 `.cpp`。
2. 新建真实模块 `海中鱼巣.线程.候选.支持线程`，`export import` 生命周期 provider 后唯一导出数据头正文，并声明 `支持线程入口端口`、移动租约、三个结果和三个公开函数；不得文本重复生命周期实体。
3. 模块内部以进程级 `(运行代次, 线程逻辑身份)` 墓碑守卫原子拒绝并发重复和历史重用；三组允许类别—模块配对以外的请求一律拒绝。守卫不读取 8110，身份保留后不因创建失败、回收或析构释放；有效请求创建失败后的重试使用新身份。
4. 候选见证使用一把 mutex、一个 condition_variable；生命周期发布另用不与见证锁嵌套的唯一串行器分配物理状态、前态和事件序号，并在该串行器内只调用一次正式 8110 发布端口。端口不得长期阻塞或回调本候选入口。`std::jthread` 为唯一线程资源 owner；真实系统线程 ID 由 `GetCurrentThreadId()` 取得，禁止哈希 `std::thread::id`；等待使用 `steady_clock`，毫秒值先按冻结上限校验再转换。
5. `创建支持线程候选` 完成请求校验、身份保留、共享控制块、最佳努力创建投影、物理线程构造和入口包装；创建成功后线程包装唯一负责启动与终态链，创建失败才由创建方收束“故障 -> 收尾中 -> 退出前 -> 异常退出”完整异常链。启动中/运行中在同一生命周期串行区完成；若停止先锁存则跳过两项启动投影但仍先发布内部进入见证再调用入口。入口抛出、坏枚举、零故障原因或未请求停止却提前返回均由包装映射入口内部故障；整条终态链在一个串行区完成，终态发布尝试完成后才发布内部完成见证。创建结果不带异步即过期的降级布尔值，全部发布非接受只累计到租约见证。
6. `等待支持线程进入见证` 只等待内部见证，不读 8110 投影；合法结果只有已进入或等待超时，完成未进入防御性返回内部不一致；诊断责任为向上送出。
7. `停止并连接支持线程启动候选` 移动消费租约；空/已移动/已连接租约直接返回内部不一致。有效租约锁存 stop、调用 `request_stop()` 后经唯一串行器检查物理态；仅在尚未停止且未终态时立即发布一次停止请求中，已停止或已终态则零发布、零序号、零未接受计数。随后等待包装完成终态发布与内部完成见证并 join；故障链不重复发布正常停止链。最终状态按“安全/见证不一致 > 请求拒绝但已安全连接 > 入口故障已安全连接 > 超预算已安全连接 > 已安全连接”固定优先级形成。
8. 租约只允许移动构造，移动赋值删除；移动源为空、析构零操作、读取返回默认见证。有效租约析构是无抛出安全网，不作为正常回收成功证据；其诊断责任为无适用错误分支，必须保持零 detach。

函数名、变量名和新增项目标识符必须使用中文；标准库和平台 API 原名除外。

生产外专项 Debug/Release 至少覆盖：

- 坏版本、零运行代次/身份、未知或非支持线程类别—模块配对拒绝；
- 同运行代次身份并发重复，以及成功回收或可注入入口故障回收后的历史重用均零第二线程；
- 真实线程、真实入口、真实系统线程 ID 和进入见证；
- 生命周期已接受、暂不可用和拒绝时物理结果相同；
- 创建后异步投影非接受只更新租约见证累计值，创建结果不存在过期降级快照；
- 等待已进入、超时后租约仍可回收；完成未进入只作内部不一致防御，不增加生产触发 seam；
- stop_token 唤醒、入口正常响应停止、入口故障、预算内与预算外完成；
- 入口先故障并完成异常终态后再显式回收，停止守卫零发布、零额外序号和零额外未接受计数；
- 创建返回后立即回收所得投影序列只能是“完整启动对后停止”或“先停止并整体跳过启动对”，禁止停止插入启动中/运行中之间；若调度实际命中早停，入口仍形成已进入见证并接收已请求停止令牌；
- 入口抛出、未知退出枚举、零故障原因和停止前提前返回均结构化收束，零异常越过线程边界；
- 只允许移动构造的租约单 owner、移动赋值编译期删除、显式回收和析构安全网均 join；
- 空/已移动租约内部不一致，以及请求无效、入口故障、预算超出并存时的结果优先级；
- 并发读取见证、候选见证锁内零外部调用、生命周期串行器内仅一次非回调8110发布、零生产测试 seam。

创建资源失败墓碑及其同身份重试只作生产源码静态核对；无法确定性触发的 `std::jthread` 资源创建失败、其失败墓碑重试和无限操作系统调度延迟保持 NOT_RUN。立即回收若未实际命中“先停止”调度分支，只能证明观察序列未插入，不得宣称该分支动态覆盖。专项不得通过生产故障开关、友元、私有状态出口、调度让行或测试宏补覆盖。
