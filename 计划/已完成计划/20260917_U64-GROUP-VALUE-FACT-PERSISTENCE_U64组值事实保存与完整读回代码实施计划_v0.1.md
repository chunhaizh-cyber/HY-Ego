# U64组值事实保存与完整读回代码实施计划

身份：`U64-GROUP-VALUE-FACT-PERSISTENCE`
版本：v0.4
状态：可执行
基线：`19998557df45d28db2bade7a67b11d9e07555a6d`

## 1. 目标、范围和完成条件

按同名详细设计实现 2100 v0.17 的永久 `U64组` 全局精确复用、保存与完整读回。完成必须含专属 owner 初始化、B2 保存/读取合同、普通应用装配迁移、专项验证、Debug/Release 构建尝试及施工/验证记录。

允许：

```text
海中鱼巣/领域/数据服务.特征值类.h
海中鱼巣/领域/数据服务.特征值类.cpp
海中鱼巣/装配.普通应用.cpp
海中鱼巣.vcxproj
海中鱼巣.vcxproj.filters
施工记录/20260917_U64-GROUP-VALUE-FACT-PERSISTENCE_施工记录_v0.1.md
验证记录/20260917_U64-GROUP-VALUE-FACT-PERSISTENCE_验证记录_v0.1.md
```

禁止：L1、2100/4120、局部二值格解析器、I64/I64组/材料、特征/概念/比较/世界树/场景/状态/动态/因果源文件及任何业务 ABI。4120已冻结局部格式的硬拒绝：不能逐层压缩到8×8或4×4×4必须由后续解析器返回`格式不合法`及零结果；本叶只存完整U64载荷，严禁把该格式判断临场加入保存入口。

## 2. 施工步骤

1. 按详细设计建立B2保存、登记、交付和构造DTO；落实固定的B1结果式`读取完整U64组_B2`、L1状态映射、首次材料重放和唯一映射失败的`已可能发布`收口。保存请求的空内容必须在调用 L1 前返回`入口拒绝`并零写；不得将“当前值组读取成功为空”误作空内容值事实成功。
2. 以 L1 owner 签发器在普通应用中建立特征值 owner、登记 B2 三项内部结构并移交端口；不添加特征或概念初始化。保留无owner构造仅用于现有B1只读消费者：本计划不修改白名单外的`验证工具/世界树根启动专项验证.cpp`和`验证工具/相关概念窄参与专项验证.cpp`，也不让无owner对象取得B2保存能力。
3. 更新工程文件，使 `.cpp` 恰好一次编译；仓外建立专项驱动，验证矩阵逐项断言成功零误载荷及失败零身份。
4. 静态确认没有 `退出U64组`、没有N键/摘要键/FT/F调用，也不调用局部二值解析器。

## 3. 失败与发布

执行 S0 重核2100/4120、计划、占用、当前构造与L1签名。任何需改 L1、格式解析器或业务服务的需求均停在范围外。使用隔离 `D:\TEMP\海中鱼巣\U64-GROUP-VALUE-FACT-PERSISTENCE\<id>` 验证根。最低运行 `git diff --check`、`python .\tools\check_specs.py --strict`、专项 Debug/Release 和主工程 Debug/Release；主工程被既有错误阻断时如实记录首错。

仅精确暂存允许文件，取得发布租约后普通提交推送。发布仅证明该值事实叶已落地，不证明局部二值格新格式解析、非I64特征出生、比较或概念已完成。

## 4. 本轮计划支撑修订

2100、4020 均未规定空 `U64组` 内容必须合法；4015 §4.2 明定空材料写前拒绝，4015 允许的是读取“没有匹配值”的结果组成功为空。且本计划禁止修改 L1。因此 v0.4 删除空组成功验证，冻结 B2 空内容为调用 L1 前的`入口拒绝`、零写入。此修订不改变正式规范。
