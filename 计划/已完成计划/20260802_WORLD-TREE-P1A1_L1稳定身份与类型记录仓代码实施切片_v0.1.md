正式依据固定为 4200 v0.7、WORLD-TREE-P1 函数功能确认 v0.1 的 §2.1、§2.2 仓库合同、§3、§4，详细设计 §2、§4、§9，逐节点分析 C01-C02/W01-W02 的仓库部分。预冻结合同不证明当前代码已经实现。

## 5. 机械施工

1. 按函数确认稳定字段和 ABI 建立只有声明与 inline 纯谓词、无需独立实现文件的 `节点直接结构合同.数据.h`。从索引仓机械迁移 `索引物理键`、完整性与相等函数，原字段顺序/行为不变；索引仓、节点仓、关系仓、三个新仓、会话和自检凡直接使用共享类型者，都必须在全局模块片段直接 `#include "节点直接结构合同.数据.h"`，不得依赖 index 模块重导出或复制声明。会话文件只允许增加该 include 并保持现有 export import 与行为不变。
2. 给正式关系记录增加永久 `关系稳定主键`；按函数确认 2.2 增加命名域高水位读取、接受 L1 计划稳定主键的关系仓创建候选签名，并同步把会话创建关系签名改为按值转交该计划键。计划键必须恰为正式关系命名域当前高水位加一且从未占用，候选建立才推进临时高水位/占用，未发布撤销恢复，完成发布后永久占用；失效/退役不复用。现有专项自检在进入会话创建前读取关系高水位并形成测试计划键，生产计划键留给 P1A2 固定执行器在独占许可内形成。关系仓的 `正式关系仓库权威材料/导出权威状态` 保存并稳定排序高水位、历史占用和记录组，P1A1 不修改冻结聚合模块。实现稳定主键读取，以及源、目标、节点相关三组结构化枚举的普通重载和带事务序号重载；本事务重载只投影自身创建/失效/重挂候选。所有成功组复核同一视图内两端当前身份并按稳定主键/关系版本排序，合法零项与入口拒绝、内部不一致必须可区分。
3. 建立类型合同、类型化值和事务幂等仓。每仓完整实现 `结构化候选 -> 候选对象值副本读回 -> 确认 -> 逆序撤销 -> 完成发布`；三个候选读回函数的完整签名和阶段合同以函数确认 2.2 为准。普通读取不可见候选，错事务/阶段/矛盾返回内部不一致或候选读回 `nullopt`。类型合同同键异内容拒绝；类型化值保留当前与不可变历史；幂等记录和持久状态侧账物理分离。
4. 逐函数落实诊断责任：仓库候选、普通/审计读取和排序向上送出；纯完整性/相等谓词才可无适用错误分支。仓库不成为最终日志记录点。
