### 2.1 引用替换、时间换代与退出裁决

4230 v0.3 保留 v0.2 冻结的动态主体、前状态和后状态三个彼此独立的强类型结构引用，并以 G2 身份来源补齐强类型证明；三者不要求满足等式或共同业务解释。因此一个角色替换完成后，另外两个角色保持原值仍是合法完整动态；本叶选择“一个请求只换代一个角色”的最小原子边界。强制三腿整体换代会无理由退出两个未变化关系；允许一个请求携带可选多角色则会引入新的组合幂等和部分变更语义，均不属于 4230 已冻结合同。

主体目标只接受 `L2存在身份`，并以请求原期望事实代次调用 E-ID `读取存在身份来源(当前)` 验证；前 / 后状态目标只接受 `L2状态身份`，并以同一期望事实代次调用 T1 / T2 后续按 G2 实现的 `读取状态身份来源(当前)` 验证。引用角色与目标使用封闭变体逐字段绑定，不接受裸稳定编码、通用节点、字符串标签或运行时名称推断。新目标与该角色当前目标相同是无变化请求，返回 `引用冲突` 且零提交；DYN2 不对存在主体与状态端点作跨强类型等式判断，仅同为 `L2状态身份` 的前状态与后状态允许相同。

起始 / 结束时间使用一个强类型角色枚举选择，但每次只换代一个角色。动态顶层来源由两值共同互证，DYN2 不提供来源换代；请求必须显式回显当前来源，新值继续引用该来源。起止材料相等、数值逆序或跨表示均合法，L2 不解释时间。

## 6. 共同写前、幂等、提交和首次结果

三个写函数的共同顺序固定为：

```text
纯值校验
-> 读取当前动态结构类型登记
-> 形成完整不可变 L1 owner-scoped 写集
-> 登记结果的 owner-aware 事实截止 != 请求期望：恰一次直提原写集，由 L1 裁决重复 / 冲突 / 漂移
-> 登记结果的 owner-aware 事实截止 == 请求期望：调用 DYN1 读取完整动态(当前)并完成本函数专属前置
-> 恰一次提交同一写集
-> 从首次事实代次历史节点、关系、属性值和端点重建首次结果
```

`读取当前动态结构类型登记` 不得再调用旧 `读取中性当前事实代次`。它以已缓存且非零的登记事实截止为首次 `L1所有者范围一致当前读取请求::期望事实代次`；owner-aware 投影成功即以其读取截止返回登记，首次返回事实代次漂移时只用该结果回显的实际截止再发一次相同登记选择请求，第二次仍漂移则返回漂移。任何一次许可拒绝立即原样返回，不在函数内重试；资源失败只来自投影分配 / 转换或本函数分配异常。不得 sleep、轮询、退回阻塞锁、调用旧代次探测、把许可拒绝改写为资源失败，或为了验证增加调度让行。

登记未加载映射 `入口拒绝`，许可拒绝、漂移、资源失败和内部不一致精确映射。三条 DYN2 写函数不得再在登记读取后调用旧 `读取中性当前事实代次`；登记结果的 owner-aware `事实截止代次` 就是当前前置的实际截止。该截止已经偏离请求期望时不得先用当前事实重建或改变写集：L1 对原幂等键先比较完整请求，精确重复返回首次结果，同键异义返回幂等冲突；新键只返回漂移。截止相等时，`读取完整动态(当前)` 自身的 owner-aware 一致投影成为完整当前事实唯一权威，并把锁竞争、后续推进、分配 / 转换和矛盾分别保持为许可拒绝、事实代次漂移、资源失败和内部不一致。不得换幂等身份、改期望、替换旧编码或二次提交。

普通 DYN2 幂等身份完整 64 位原样映射为 `L1所有者范围写入幂等身份`，不进入动态来源登记固定身份或类型登记私有 `0x21` 域。所有写入只经 DYN1 已持有的动态 owner-scoped 端口提交并核对结果 owner 等于动态 owner；不得调用旧 `提交中性写集`。DYN2 写集可按角色复用以下五个业务新建本地键；族归属关系 `0x0205'1002U` 不在替换 / 换代中新建，但作为第四自有关系进入六编码退出闭包：

```text
动态主体关系本地键    = 0x0205'1101U
动态前状态关系本地键  = 0x0205'1102U
动态后状态关系本地键  = 0x0205'1103U
动态起始值本地键      = 0x0205'1201U
动态结束值本地键      = 0x0205'1202U
动态端点角色          = 1
```

首次结果只从首次发布代次的 owner-aware L1 历史事实重建，并以 DYN1 正式动态身份来源互证 owner、族锚点与族归属。后继关系 / 值再换代或动态退出后，原请求重复仍返回首次关系、值、动态截止和首次退出事实；不得把未来退出代次、未来端点或未来值混入原结果。

提交前出现的入口、登记、端点、漂移、幂等、引用、许可、资源或内部非成功必须零普通事实变化，结果头不携带变更事实代次。L1 已返回成功后，若首次历史重建发生 `std::bad_alloc` / `std::length_error` 或读回矛盾，公开结果为空载荷并映射资源失败 / 内部不一致，可以回显已安全取得的首次变更事实代次，但不能宣称零变化；实现必须保留原幂等身份和原完整请求作为唯一收敛路径，不二次提交、不改变请求、不补偿已发布事实。

## 7. 单角色引用原子替换

按请求角色唯一选择关系类型、本地键、当前目标和新目标 provider：

- `前状态`：使用前状态关系类型与 `0x0205'1102U`，新目标必须是 `L2状态身份` 并调用 `读取状态身份来源(当前)`；
- `后状态`：使用后状态关系类型与 `0x0205'1103U`，新目标必须是 `L2状态身份` 并调用 `读取状态身份来源(当前)`。

唯一写集为：

```text
节点 = []
关系 = [
  {所选关系本地键, 源=请求动态, 目标=请求新目标,
   类型=所选登记关系类型, 角色=1}
]
值 = []
属性槽变更 = []
退出事实 = [请求旧关系稳定编码]
```

请求期望代次匹配时，先调用 DYN1 `读取完整动态(当前)` 与 `读取动态身份来源(当前)`，要求返回一个完整动态、四条自有关系和同截止正式来源；所选角色当前关系编码必须等于请求旧关系，族归属关系保持不变，随后以原请求期望事实代次验证新目标：主体调用 E-ID `读取存在身份来源(当前)`，前 / 后状态调用 T1 / T2 最终 `读取状态身份来源(当前)`。角色 / variant 不匹配在纯值层入口拒绝；新目标未找到 / 已退出、许可、漂移、资源按同名状态；新目标等于所选当前目标或旧关系编码不符返回引用冲突；owner / 来源 / 当前完整动态形状矛盾返回内部不一致。

成功 / 精确重复必须取得所选本地键到一个非零新关系编码的唯一映射。首次代次 owner-aware 历史读回必须证明旧关系在该代次退出、新关系在该代次创建，关系 owner、类型、源、新目标和角色正确；并以同一首次变更事实代次为历史截止调用动态、存在和状态身份来源接口，互证动态 owner / 族归属以及三个端点来源。族归属和另两条业务关系、动态节点、两值、来源和创建代次保持首次截止有效且不变，端点晚于该截止的未来退出不得混入首次结果。任一缺项、多项、错 owner / 来源 / 端点 / 类型、混代或非预期事实变化返回内部不一致，不二次提交。

DYN1 当前读取在替换代次之后只能返回所选新端点 / 新关系，历史截止早于替换代次返回旧端点 / 旧关系，截止等于替换代次返回新关系；对应当前条件查询从旧端点移除并加入新端点，另外两类条件查询不变。主体替换不要求前 / 后状态主体随之改变；前 / 后状态替换也不要求动态主体或另一状态改变。

```text
退出事实 = [请求旧值稳定编码]
```

请求期望代次匹配时，DYN1 当前完整动态及动态身份来源必须存在、完整、同截止，并证明节点、族归属、四关系和两值属于动态 owner；所选旧值编码必须等于请求，动态顶层来源、起始值来源和结束值来源必须三者相等并等于请求来源。另一个未换代角色必须保持当前、完整且同截止。旧值不符或来源回显不符返回引用冲突；错 owner / 来源、缺槽、多槽、两值来源矛盾、所属 / 表示 / 生命周期矛盾返回内部不一致。

新材料可以与旧材料逐字段相同，也可以跨 I64、I64 组、U64 组和独立材料引用表示；显式换代仍建立新的值稳定编码。L1 在同一候选中退出旧值并移除旧槽，再建立新值和新槽，因此一个角色始终至多一个当前值，另一个角色零变化。DYN2 不比较起止材料，也不按数值或单位拒绝逆序。

成功 / 精确重复必须取得所选唯一新值编码。首次 owner-aware 历史属性值组只证明在首次截止所选角色唯一有效值为新值、另一角色仍唯一有效；该提供者候选来自成功属性槽变更，但不返回历史槽对象。旧值另以 `读取所有者范围历史事实(旧值编码)` 证明在首次代次退出且 owner 等于动态 owner。即时首次提交后若仍位于同一代次，可以用 owner-aware 一致当前属性投影补充核对槽指向新值；后继事实已经推进后的精确重复不得依赖不存在的历史槽投影。结果的 `当前动态` 是首次代次完整动态，`已退出值` 保留完整退出生命周期。所属、owner、角色类型、材料表示、来源、唯一有效值、编码或生命周期任一矛盾返回内部不一致。

## 9. 动态显式闭包退出与外部引用保护

退出前调用 DYN1 `读取完整动态(当前)` 与 `读取动态身份来源(当前)`，取得动态事实和四关系编码，并验证节点、族归属、四关系、两值全部属于同一动态 owner。把四关系和起始 / 结束两值共六个编码形成全局升序唯一集合，必须与请求自有事实闭包逐项相等；任一漏项、错项或多项闭包返回 L2 `引用冲突`，零提交。

唯一 L1 写集为：

```text
节点 = []
关系 = []
值 = []
属性槽变更 = []
退出事实 = 全局升序唯一[
  动态节点编码,
  请求自有事实闭包的六个编码]
```

请求不得携带或退出主体存在、前 / 后状态、来源锚点、族归属关系类型、十一项类型节点或其它外部事实。L1 对最终写集执行二次当前引用闭包保护：任一其它当前关系、任一闭包外当前值以动态为所属节点、值来源或独立材料仍引用动态节点，且未由其合法所有者先行退出时，返回 `引用冲突=9`；DYN2 精确映射为 `L2结构状态::引用冲突=12`，不扫描消费者、不返回引用者列表、不补造退出项，也不把外部所属值追加到“节点 + 四关系 + 两值”七事实闭包。

调用方必须先经外部结构所有者闭合当前引用，再使用新的期望代次和新的幂等身份重试；不得用原引用冲突请求身份改变闭包。动态节点、四条当前自有关系与两值七事实已经显式位于本写集，因而闭合动态自身不会被自身引用伪阻断。

成功 / 精确重复要求空新编码映射和首次发布 / 重试边界正确；按首次事实代次 owner-aware 历史读取动态节点、族归属、三业务关系和两值，并以同一首次事实代次为历史截止调用动态、存在和状态身份来源接口。节点、四关系和两值七项自有事实的 owner 必须等于动态 owner，退出代次必须全部等于首次变更代次；来源锚点、族归属关系类型、十一项类型节点、主体和状态端点保持其自身生命周期。`已退出动态` 保留节点和两值退出生命周期，`已退出自有关系` 返回族归属、主体、前状态、后状态四编码；任一读回矛盾为内部不一致，不补偿已经发布的事实。

退出后 DYN1 当前单项返回 `已退出` 空载荷，三条件当前组不再包含该动态；退出前历史截止返回当时完整投影，截止等于或晚于退出代次必须返回 `已读取` 及节点、族归属、三业务关系、两值的完整退出生命周期，且四关系投影与 `退出动态` 首次结果逐字段一致。该运行验证是 DYN1 唯一 `NOT_RUN` 的强制接续门禁。DYN2 不提供复活、物理删除或持久证据清理。

## 10. DYN1 读取兼容、状态、幂等和异常收口

DYN2 不改变 DYN1 八个函数签名。DYN1 当前 / 历史完整读取必须自然消费关系 / 值历史：

- 引用替换前截止返回所选旧目标，替换截止及之后返回新目标；另两角色不变；
- 时间值换代前截止返回旧值，换代截止及之后返回新值；
- 退出前历史截止返回当时完整动态；退出截止及之后的历史读取返回完整退出生命周期，只有当前读取返回已退出空载荷；
- 当前三条件查询只随对应当前关系变化，按动态身份升序且不复制第二权威列表。

同一幂等身份只绑定完整请求。引用替换的角色 / variant / 旧关系和动态退出的公开闭包进入 L1 前已经具名或严格升序；精确重复返回首次动态、关系、值和首次代次，零推进；同键异动态、角色、旧事实、新目标、材料、来源或闭包为幂等冲突。发布结果未知只以原请求重提，不换键、不重构材料。

非成功顺序固定为：

```text
纯值非法或角色 / 目标类型不匹配 -> 入口拒绝
登记未加载 -> 入口拒绝
登记其它失败 -> 对应共同状态
既有幂等 -> 精确重复 / 幂等冲突
新键旧期望 -> 事实代次漂移
动态或新端点未找到 / 已退出 -> 同名
引用替换无变化 -> 引用冲突
旧关系 / 旧值 / 来源回显 / 退出闭包不符 -> 引用冲突
L1 外部当前引用未闭合 -> 引用冲突
owner-aware 一致投影锁竞争 -> 许可拒绝
分配 / 转换失败 -> 资源失败
事实形状矛盾 -> 内部不一致
```

所有 L1 owner-scoped 写入状态 switch 必须完整覆盖 `引用冲突=9` 并映射 L2 `引用冲突=12`。DYN1 完整动态必有族归属、三业务关系和两值，DYN2 不把缺失角色包装成 `属性未设置`；缺项是内部不一致。全部非成功载荷为空；提交前失败不伪造变更代次，提交后读回失败只回显 L1 已安全取得的首次代次并遵守第 6 节收敛边界。

## 11. 临时生产外验证矩阵

临时验证 cpp 必须构造一个普通应用上下文，并从同一上下文依次取得存在、特征、状态和动态四个公开服务。合法夹具的唯一建立链为：E-ID `新增存在节点` 建立主体 / 宿主存在身份 -> F-ID `新增特征定义` 建立正式定义 -> F-ID `新增特征实例(宿主存在, 特征定义)` 建立正式实例 -> T1 / T2 `新增状态(主体存在, 特征实例, 值 / 来源)` 建立状态身份 -> DYN1 / DYN2 公开动态入口消费状态身份。每一层必须经本族公开身份来源入口读回后才能交给下游：F-ID 定义 / 实例分别经 `读取特征定义身份来源` / `读取特征实例身份来源`，状态经 `读取状态身份来源`；不得用裸编码、包装普通节点或验证器自造身份替代。F-ID 调用只属于生产外夹具准备，DYN2 两个生产文件仍为 F-ID 零 import、零调用、零服务引用。不得直接构造独立 L2 服务，不得 import 私有仓库、访问原始 owner 交付、写端口、登记定位 / 锁 / 索引 / 幂等账、解析日志或复用历史状态 / 动态实现。
