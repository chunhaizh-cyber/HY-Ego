## 1. 修订定位

本版完整继承同名v0.1计划的目标、允许文件、不变合同、存在族实现步骤、验证矩阵和完成边界；只修复具名DRIFT `EXISTENCE-NARROW-CONTRACT-L1-SERVICE-TYPE-OWNERSHIP`。本版与v0.1冲突时以本版为准，v0.1不再提供执行资格。

本修订不增加生产文件，不修改L1、4203 ABI、状态/动态模型、owner、事务、迁移或完成声明。

## 2. 精确实施替换

v0.1实施顺序第2步替换为：

1. 新建 `海中鱼巣/领域/合同.存在结构身份只读.ixx` 时，在模块声明后精确写入：

   ```cpp
   export import 海中鱼巣.核心.服务.L1事实基座;
   ```

2. 删除候选中的 `class L1事实基座服务;`；禁止改成模块内前置声明、别名、包装类或头文件声明。
3. 新窄合同不再直接import或export-import `海中鱼巣.核心.合同.L1事实基座`。其所需L1公开类型统一由服务模块的既有导出面取得。
4. `存在结构身份只读提供者::绑定于(const L1事实基座服务&)` 的名称、参数、cv/noexcept、虚函数形态和4203语义逐字不变。
5. 工程登记顺序保证 `核心.服务.L1事实基座` 先于新窄合同，新窄合同先于绑定合同和存在类；不得修改L1工程项或源码。

其余v0.1实施步骤顺延并保持不变。执行者从本版重新S0后可在已保留的白名单WIP上作上述窄修复，不得扩大范围。

## 3. 允许与禁止范围

允许文件仍精确等于v0.1七项：新窄合同、绑定合同、存在类、`.vcxproj`、`.filters`、原施工记录和原验证记录。禁止修改L1、规范、详细设计、计划、索引和其它WIP；计划支撑发布的本v0.2文件不属于执行者代码提交范围。

禁止方案：

- 继续只依赖 `核心.合同.L1事实基座`；
- 在新合同模块内前置声明 `L1事实基座服务`；
- 采用普通 `import 核心.服务.L1事实基座` 并把额外import责任转嫁给每个消费者；
- 移动或复制L1服务类型、修改L1、增加第三个类型owner；
- 改4203签名绕过服务类型。

## 4. 验证增量

除v0.1第5节全部验证外，必须满足：

- 新窄合同中精确一处 `export import 海中鱼巣.核心.服务.L1事实基座`；
- 零 `class L1事实基座服务;`，零直接 `核心.合同.L1事实基座` import；
- Debug/Release均形成L1服务、新窄合同、绑定合同、存在类IFC/OBJ和探针exe，且链接成功；
- 最小消费者只import新窄合同即可用同一 `L1事实基座服务` 类型实现provider，C4430与LNK2019均不得出现；
- L1源码和工程项不在diff、staged路径或提交树中。

`python .\tools\check_specs.py --strict` 的既有FROZEN acceptance_record阻断继续分账，不借本计划修复。
