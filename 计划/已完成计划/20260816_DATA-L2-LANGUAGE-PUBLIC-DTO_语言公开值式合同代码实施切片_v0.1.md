## 4. 生产实体与函数

数据头按详细设计第 4 节逐字段实现下列实体，不得合并、改名或重排：

```text
L2语言结构合同版本
L2语言登记键
L2语言登记键事实
L2语言来源事实
L2语言事实
L2语言新增请求 / L2语言新增结果
L2语言替换请求 / L2语言替换结果
L2语言退出请求 / L2语言退出结果
L2语言读取请求 / L2语言读取结果
L2语言按登记键读取请求 / L2语言按登记键读取结果
```

实现下列纯值 helper：

```text
L2语言登记键有效
L2语言事实完整
L2语言新增请求有效
L2语言替换请求有效
L2语言退出请求有效
L2语言读取请求有效
L2语言按登记键读取请求有效
五个结果类型各自的 成功()
```

全部 helper 为 `inline bool ... noexcept`，诊断责任均为“无适用错误分支”。它们只判断内存值式形状，不读取材料或事实、不加锁、不分配稳定编码、不写日志、不抛异常。

## 5. 施工步骤

1. 从正式 `main` 重做 S0：核对精确计划版本和 blob、目标三生产路径 clean、index / Git 发布租约、唯一代码段和构建资源可用；无关 dirty 原地保留。
2. 新建数据头：使用 `#pragma once`、与现有数据头一致的 no-includes 宏边界、最小标准头和两个正式数据头依赖；按设计逐字实现实体、请求有效、事实完整和结果成功形状。
3. 复核事务形状：新增只回显新当前语言；替换同时回显不同身份的新当前语言与旧退出语言；退出只回显旧退出语言；非成功不由 `成功()` 误判。
4. 在根工程和 filters 中唯一登记新头；不改变四配置 `/utf-8`，不登记临时检查源码。
5. 在仓库外编译运行专属临时检查，覆盖合同版本、零 / 非零守卫、当前 / 历史互斥、替换异义、生命周期一致、关系身份互异、三种写结果、两种读结果和坏载荷拒绝；完成后清理临时源码和构建产物。
6. 使用独立输出路径执行根工程 x64 Debug / Release Rebuild；失败仅在本计划范围内修复纯代码或工程登记错误，真实规范 / ABI / 所有权漂移具名退回计划支撑。
7. 形成两份永久记录，运行静态门禁，只暂存允许文件并精确提交、普通推送；结果发布后由计划索引所有者独立登记退出。

## 6. 成功条件

- 新头是语言 DTO 的唯一实体所有者，生产代码中无第二份同名声明；
- 所有字段、默认值、相等运算、请求 helper 和结果成功形状与详细设计一致；
- 登记键使用 `不可变材料身份`，没有字符串、路径、区域设置、裸编码或默认汉语常量；
- 语言完整事实把语言身份、族身份来源、登记键、来源和同步生命周期闭合；
- 替换建立不同新身份并在同一截止退出旧完整结构；当前 / 历史读取字段互斥且截止一致；
- 语素、词性、词条和概念名称 DTO / 服务零新增；
- 根工程 x64 Debug / Release Rebuild、仓库外 C++20 检查、工程 XML、唯一登记、UTF-8、diff、strict、白名单和生产零测试痕迹通过；

- 目标文件或语义出现另一所有者、index / Git / 构建资源被占用：只停止受影响发布或构建，保留现场并协调。
