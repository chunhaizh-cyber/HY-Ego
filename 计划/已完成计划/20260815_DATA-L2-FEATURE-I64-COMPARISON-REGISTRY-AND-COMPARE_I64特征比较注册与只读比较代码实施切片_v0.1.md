完成条件：公开 DTO、helper 和八个服务入口存在；注册由特征定义 owner 单事务发布；同一特征定义 + 用途至多一个当前注册；比较严格服从 4130/4180 的三态、右减左、状态 / 拒绝 / 载荷矩阵并保持零事实写入；根工程双配置构建和静态合同检查通过；专属记录发布。

## 4. 精确施工合同

逐字段实现详细设计第 3—7 节冻结的：

1. 4180 稳定枚举与 I64 合同 DTO；
2. 比较结构类型登记三节点固定写集和当前权威读回；
3. 比较注册新增、替换、退出、当前读取和历史读取；
4. 特征定义退出前的当前比较注册引用保护；
5. `L2特征结构服务::比较特征(...) const` 的只读路由、输入复核、安全 I64 算法和结果矩阵；
6. 所有公开纯值 helper、成功谓词、异常映射和中文命名。

只实现算法族 `标量有序比较与安全差异`。其它 4180 算法族不得进入当前注册，不得以默认减法、向量词典序、材料字节或 `未实现` 事实占位。

## 5. 实施步骤

1. 在 `L2特征结构.数据.h` 追加稳定枚举、类型登记、注册 CRUD、输入 / 回执 / 差异 / 结果 DTO 和纯值 helper。
2. 在 `服务.L2特征结构.ixx` 私有区域追加结构类型登记映射、固定向量编解码、注册投影组装、状态映射和安全 I64 helper。
3. 原位实现比较结构类型登记建立 / 当前读取；缓存只保存定位，公开读取回到 L1。
4. 原位实现注册新增、替换、退出、当前 / 历史读取，确保唯一 key、单 owner 事务、历史保留和特征定义退出引用保护。
5. 原位实现 `比较特征(...) const`，严格分离排序三态与差异，按请求结果位一次返回，零 L1 写入。
6. 运行根工程 Debug / Release 构建、静态合同、UTF-8、diff、strict、白名单和生产零验证痕迹检查。
7. 写施工与施工检查记录，只记录实际执行证据和 `NOT_RUN` 边界。

## 6. 验证与成功门禁

至少运行：

```powershell
git diff --check
git diff --cached --check
python .\tools\check_specs.py --strict
```

另须完成根工程 x64 Debug / Release Rebuild。静态检查至少覆盖：

- 4180 状态、拒绝原因和结果要求精确数值；
- 只允许 I64 标量当前注册；
- 结构类型登记固定 3/0/0/0/0；
- 注册固定 1 节点 + 1 关系 + 2 值 + 2 槽；
- 同特征定义 + 用途唯一当前路由；
- 替换 / 退出闭包和特征定义退出引用保护；
- 当前 / 历史读取同截止完整性；
- 目标判断、状态迁移左右角色不反转；
- 排序不做减法、差异为右减左且先检查可表示性；
- 容差命中不做可能溢出的有符号减法 / 绝对值，精确排序方向与容差具名关系分账；
- 请求结果位与成功载荷逐位相等；
- 比较入口零写集、零发布、零重试；
- 后继持久写入必须正式回读输入来源，比较 DTO / 成功结果不取得事实权威；
- 旧比较模块、第二服务、工程变更和生产验证 seam 为零。

不专门建立验收工程或永久专项。允许在仓库外临时源码中做纯值 I64 极值检查，但完成后必须移出仓库；若执行期共享资源不允许，则真实分支由后继合法消费者实际使用判断并在记录中诚实写 `NOT_RUN`。
