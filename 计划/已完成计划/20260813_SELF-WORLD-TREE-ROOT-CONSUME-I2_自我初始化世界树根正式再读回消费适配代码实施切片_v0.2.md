## 1. 目标与完成条件

基于 `f5eff1bd64f82f56d2246cf3e458a25e0afa42b1` 的最终 I1/R1/A1 ABI，实现 I2 provider 和正式启动连续链：同次 I1 成功结果形成值式请求，I2 每次经 A1 同实例 R1 重新读取当前登记与整树，完整互证后发布材料。

## 5. 机械实施合同

### 5.1 DTO 与单源编排

新建 `业务/自我世界树根消费.数据.h`，逐字实现详细设计第5节 DTO、枚举数值、字段顺序和 `成功()` 形状。

新建 `业务/消费.自我世界树根.inl`，归属普通应用模块，只含私有辅助和编排模板；零模块声明、零 `export`、零验证逻辑、零公开 ABI、零独立 TU。模板接收 I2 锁、发布槽、请求和 A1访问表达式，不接收上下文，不保存访问器。

模板签名、四个参数和访问器可调用合同逐字遵守详细设计第6节：访问器左值调用 `noexcept`，返回覆盖本次调用的非 owning 左值引用；服务类型提供两个同名读函数并返回精确 R1 结果 DTO。生产访问器只经 A1 getter返回 final R1，脚本访问器返回无需继承 final R1 的脚本服务；访问器和引用均不得保存。

模板固定执行：请求校验 -> 异请求冲突 -> 每次 A1 getter -> 当前登记读取 -> 以本轮截止形成当前整树读取 -> 逐字段互证 -> 局部完整候选 -> `noexcept swap`。重复不得缓存成功，任一失败保留旧值。

### 5.2 普通应用与启动

普通应用模块导出 DTO 和薄 wrapper：

```cpp
自我世界树根消费结果 消费并发布自我世界树根(
    普通应用上下文&, const 自我世界树根消费请求&) noexcept;
std::optional<自我世界树根消费材料>
读取自我世界树根消费材料(const 普通应用上下文&);
```

上下文只新增 I2 发布锁和值式材料槽；精确 friend授权 wrapper，不新建适配器对象或 provider getter。wrapper 每次用 A1 getter取得同实例 R1。

`运行普通程序` 在模式分支前固定：装配 -> I1 -> 同次结果形成 I2 请求 -> I2。程序失败阶段新增 `现实世界树根初始化=14`、`自我世界树根消费=16`、`自我初始化能力未实现=17`；不声明15。I1失败不调用I2，I2成功固定返回17；所有初始化失败路径宿主调用零。
