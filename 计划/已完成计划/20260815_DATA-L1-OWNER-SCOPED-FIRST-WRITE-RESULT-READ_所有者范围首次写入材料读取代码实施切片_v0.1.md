## 1. 目标与完成条件

在现行 `DATA-L1` owner-scoped v2 内，为有效活动 `L1所有者范围写端口` 增加本 owner 私有首次写入材料读取：按一个非零写入幂等身份返回首次规范化完整写集和原始首次成功结果，供合法结构所有者收敛未知发布、固定登记恢复和晚到精确重复。

完成必须同时满足：

1. 精确公共 ABI、六种状态子集和双 optional 形状逐字实现；
2. 入口只属于 raw 写端口，普通 `L1事实基座服务`、签发器和其它 owner 无同义查询能力；
3. 仓库在一个 shared lock 内精确读取 `(实例, owner, 幂等身份)`，局部互证首次写集、首次结果、代次和映射；
4. 读取不写事实、不推进代次、不列举、不读取 legacy / owner 建立账、不增加全仓扫描；
5. Debug / Release 根工程构建、风险相称临时检查、静态 ABI / 范围 / 生产零检查痕迹检查通过；
6. 临时检查三件套在结果提交前删除，正式生产目标零测试 seam；
7. 永久施工与检查记录如实记录实际运行项和 `NOT_RUN`，不形成独立验收结论；
8. 最终结果只包含本计划白名单，不带入 BIZ、C1 候选、流程图、路线、历史删除或 `.codex-build` WIP。

## 5. 状态与载荷矩阵

| 条件 | 状态 | 双 optional | 代次 |
| --- | --- | --- | --- |
| 合同版本错误、幂等身份为零 | `入口拒绝` | 空 | 0 |
| 端口移动源 / 失效 / 实例销毁 / 租约不存在 | `许可拒绝` | 空 | 0 |
| 有效 owner 下身份无记录 | `未找到` | 空 | 锁内当前代次 |
| 记录及双材料完整互证 | `成功` | 同时存在 | 锁内当前代次 |
| 分配 / 长度资源耗尽 | `资源失败` | 空 | 安全取得则保留，否则 0 |
| owner、请求、结果、代次、映射、仓库隔离或相关不变量矛盾 | `内部不一致` | 空 | 安全取得则保留，否则 0 |

全部状态回显读取合同版本、请求幂等身份和端口调用开始时绑定的 owner；移动源 owner 可以为零。请求纯值校验优先于 capability 校验，坏请求与失效端口同时出现时固定入口拒绝。

成功中的首次写入结果固定为原始 `成功 + 是否形成内存权威发布=true + 不适用`，不得改写为精确重复。读取当前代次不覆盖首次代次；首次普通事实后续退出不使幂等记录消失或把读取映射为已退出。

1. S0 记录最新 HEAD / origin、index、目标文件 blob、owner、唯一代码段 / 构建 / Git 资源释放事实及全部重叠 WIP。
2. 在公共数据头按第 4.1 节增加常量与两个 DTO，不改现有枚举数值、结构字段或函数。

4. 在 raw 写端口增加 const 入口：先确认实例与活动租约，释放端口锁后调用仓库；不让端口锁与仓库锁重叠。

6. 建立生产外临时检查三件套，运行详细设计第 11 节中实际可触达的风险矩阵；检查失败时只修本计划代码或具名退回设计。

10. 取得唯一 Git 发布租约后，只提交五个白名单结果文件并普通 push；回读远端、index 和剩余异主 WIP后释放租约。

### 7.2 风险矩阵

1. 空 owner 指定非零身份未找到；
2. 代表性五类写项首次提交后双材料逐字段读回；
3. 精确重复前后原始首次结果不变；
4. 后续其它 owner 提交后读取仍返回原首次代次 / 映射；
5. 同 owner 另一身份未找到；
6. 两 owner 相同数值身份严格隔离；
7. 错版本、零身份、移动源和已释放端口分别入口 / 许可拒绝；
8. 读取前后事实代次不推进；
9. 公共 L1 服务、签发器和数据请求零 owner 选择 / 列举入口；
10. 现行 owner 提交与代表性当前 / 历史读取不回归。

正式资源耗尽、私有幂等账损坏、跨进程恢复和不合法并发销毁没有公开稳定注入时记录 `NOT_RUN` 或静态证据；不得增加生产 seam、friend、故障选择器、公开 operator 之外的比较扩张或第二可执行目标。

## 8. 失败收口

- 纯代码、编译或施工检查错误：在三个生产文件和临时检查白名单内修复，重跑受影响门禁。
- 当前幂等账无法无损转换为 owner-scoped v2 公共写集 / 结果：固定 `DRIFT-DATA-L1-FIRST-WRITE-MATERIAL-LOSSY`，停止代码施工并退回设计，不删字段、不返回内部 DTO。
- 需要普通 L1 服务代查、跨 owner 搜索或列举才能满足消费者：拒绝扩大；该需求违反 owner capability 边界。
- 另一活动代码计划仍占用代码、构建或 Git 资源：等待正式释放；不得并行施工、构建、stage、commit 或 push。
- 远端或目标文件前进：从新 HEAD 重做 S0；不自动 merge、rebase、cherry-pick、stash 或 reset。
- 普通推送结果未知：保留提交与 index 事实，先只读核对远端，再决定是否普通重试；禁止 force。
