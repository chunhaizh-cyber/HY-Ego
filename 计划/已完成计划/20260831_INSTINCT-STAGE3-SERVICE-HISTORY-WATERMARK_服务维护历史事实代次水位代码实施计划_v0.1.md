# INSTINCT-STAGE3-SERVICE-HISTORY-WATERMARK 服务维护历史事实代次水位代码实施计划 v0.1

日期：2026-08-31

计划身份：`INSTINCT-STAGE3-SERVICE-HISTORY-WATERMARK`

## 1. 目标与完成条件

按同名详细设计实现服务维护历史覆盖起点正式读回、唯一维护游标 v3、v1/v2 迁移和生产启动接线。完成必须同时满足：

1. 服务合同事实权威 owner 能在 `G0` 正式读回自身历史账登记事实代次；
2. 游标 v3 永久保存完整秒、主动安全事实代次、服务历史事实代次三个独立水位；
3. v1/v2 只能在两个 owner 的登记见证完整时迁移，不能把服务历史水位补成当前 `G0`；
4. 生产启动建立 / 恢复并独立读回 v3 后才创建自我线程；
5. 当前 `0..INT64_MAX` 值域、L/H 和规则版本保持不变。

本计划不实现事实段 composer、历史事实解释、维护水位推进、A/V 写入或阶段三闭环。

## 4. 目标接口与实现步骤

1. 在服务合同数据头增加覆盖起点请求、快照、状态、结果和完整谓词。
2. 在服务合同服务增加 `读取服务维护历史事实账覆盖起点_v1`；复用现有历史登记定位和只读完整性 helper，固定读前 / 读后 `G0` 守卫。
3. 在游标数据头增加 v3 事实、建立 / 读取请求与结果、状态和完整谓词；请求同时携带两个登记见证。
4. 在游标服务增加八字段编码 / 解码和 v3 建立 / 读取；v1 解码兼容 6/7/8，v2 兼容 7/8，v3 只接受 8。
5. 实现无当前、v1 迁移、v2 迁移、v3 恢复 / 新纪元、精确重复和已可能发布收束。
6. 启动改用 v3：正式读回服务历史覆盖起点，分别确定两个目标水位，建立 / 恢复后用新 `Gread` 独立读取并逐字段互证。
7. 增加专项、持久恢复和外部 ABI consumer 覆盖；记录实际验证边界。

## 5. 非成功和安全收口

- 覆盖起点非成功全部空快照 / 截止 0；
- 任一登记见证、self、G0 或水位错配零写；
- v3 读取旧载荷返回待迁移；
- 写入确定失败映射 v3 结构化状态；提交后读回失败只返回已可能发布见证；
- `bad_alloc` / `length_error` 映射资源失败，其它异常映射内部错误；
- 不得因启动需要继续而把服务历史水位设为 `G0` 或主动安全登记代次。
