## 4. 目标 ABI 与物理实现

### 4.1 公共数据头

在现有类型顺序中机械加入详细设计第 3 节的六类新 DTO 和 `L1所有者范围一致关系类型闭包读取合同版本=1`。既有 `L1所有者范围CRUD合同版本=2`、`L1所有者范围一致当前读取合同版本=2`、请求 / 结果字段和函数签名全部保持不变。

不得改变现有字段顺序、枚举数值、函数签名或其它合同版本；不得把闭包字段追加到既有 v2 DTO。

### 4.2 仓库状态与辅助

仓库私有状态增加 `当前关系类型索引`。新增私有中文辅助：

- `插入当前关系类型索引`；
- `删除当前关系类型索引`；
- `读取一致关系类型闭包`；
- `尝试读取所有者范围一致投影内部`。

关系创建 / 退出候选必须与源 / 目标索引一起维护该索引；`状态完整` 必须验证索引覆盖且只覆盖全部当前关系。新旧公开仓库包装函数把各自 DTO 规范化交给同一私有投影核心；核心只加一次共享锁，闭包辅助不再次加锁、不调用公开入口、不返回内部引用。

入口成员只可使用关系类型索引；端点一跳关系组只可使用已发现端点的现有源 / 目标索引，不得按一跳关系类型全仓扫描后过滤。

### 4.3 公开入口

新增具名函数：

```cpp
L1所有者范围一致关系类型闭包读取结果
L1事实基座服务::尝试读取所有者范围一致关系类型闭包投影(
    const L1所有者范围一致关系类型闭包读取请求&) const;
```

服务只透明转发到同一仓库实例。既有 v2 函数继续存在且 ABI 不变；仓库新旧包装共用一个私有核心，在各自一次调用的一次锁内完成对应投影。
