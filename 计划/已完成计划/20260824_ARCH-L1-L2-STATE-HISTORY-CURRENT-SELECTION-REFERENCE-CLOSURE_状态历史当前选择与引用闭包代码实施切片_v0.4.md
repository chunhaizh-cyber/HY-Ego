## 3. 实施步骤

1. 保持四个 v1 类型原名和布局；旧函数只返回入口拒绝。
2. 首态 v2 在状态 owner 单写集中建立状态、自有关系和当前选择，首态不形成动态。
3. 当前选择读取穷尽未登记、已登记 0 条、1 条、多条/坏闭包、许可、G0、资源和内部错误。
4. 历史选择读取穷尽坏请求、G0/截止、0/1 快照、多条/坏闭包、许可和资源；隐藏未来退出。
5. L1 跨 owner 幂等账先于 G0 裁决，精确重复零候选、零应用、零新代次。
6. L1 固定规范参与者顺序并按本地键升序；状态候选先形成映射，动态候选引用该映射。
7. 动态候选内部期望状态候选 G1；交换前把动态内部 G2 的事实、仓库代次及 owner 首次写入账统一为 G1。
8. 迁移只退出请求具名旧当前选择，不退出旧状态、自有关系或动态前态引用。
9. 首次提交后先正式读当前选择；随后以首次 G1 读取完整历史快照。精确重复直接以首次 G1 历史快照收束。
10. 一次故障宏只命中提交后的第一次当前选择独立读，命中后恢复；同键第二次调用必须精确重复并保持首次 G1。
11. 组合幂等 XOR 的零输出映射到域常量，保持合法输入一一且非零。
12. `L2状态动态迁移结果_v2::成功()` 保持 out-of-line，规避 MSVC 对超长 inline 模板路径的 ICE，不改变 DTO 布局。

## 5. 构建与运行

根工程使用实际目标 `D:\海中鱼巣\海中鱼巣.vcxproj`，输出、IntDir 和 OutDir 全部隔离到 `D:\TEMP\海中鱼巣\ARCH-L1-L2-STATE-CURRENT-v0.4\`。普通 Debug/Release 不定义测试宏；专项构建只定义 `ARCH_L1_L2_STATE_SELECTION_VALIDATION`。

focused harness 必须调用真实公开服务，不得复制生产事务算法。它至少断言：

- `RUN_INITIAL` 全矩阵通过。
- `RUN_MIGRATION` 首次单 G1 和旧状态永久通过。
- `RUN_MIGRATION_REPLAY` 精确重复、冲突、漂移通过。
- `RUN_BAD_CLOSURE` 当前/历史坏闭包分账通过。
- `RUN_POSTCOMMIT` 首态和迁移提交后故障均能同键收束。
- 最终输出 `ARCH_PROVIDER_MATRIX_PASS`。
