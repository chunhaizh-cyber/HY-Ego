## 1. 目标与完成条件

在不增加任何 L1 上层用途入口的前提下，使 DATA-L1 实现候选与 4080 v1.0 已 `FROZEN` 的通用操作 / 目标公开合同一致，并在精确提交树完成机器接口检查、三类事实恢复、权威载荷格式 1 / 2 / 3 和统一黑盒。代码阶段完成后 DATA-L1 整体状态仍为 `PENDING_ACCEPTANCE`；必须继续通过独立集成验收和第二次治理发布，才能完成用户要求的整体 `FROZEN`。

完成必须同时满足：

1. 43 项公开操作与冻结清单完全相等，服务模块及四个公开数据面的整文件指纹与冻结基线相等；领域专用标识只剩双参与者 v1 精确限定兼容例外；
2. 非服务生产代码不能直接 import L1 仓库模块，旧 `许可拒绝` 不产生新结果；
3. 未知权威载荷版本返回 `格式不支持`，不误报 owner 冲突；
4. 节点、关系、值的当前 / 历史 / 墓碑、属性槽、组读取、幂等和恢复公开黑盒通过；
5. 从 `db65bc99...` / `ff2366d9...` 的合法公开路径生成的格式 1 / 2 固定样本与新格式 3 全部恢复、读回并继续 v3 提交；
6. fail-closed 损坏矩阵、双配置构建、严格规范检查和统一 driver 在精确 index 导出的提交树通过；
7. 专属记录精确声明通过项与 `NOT_RUN`，并纠正旧记录关于恢复审计实现的过度声明；
8. 代码候选 commit 提交并推送后，集成验收与回归智能体以同一精确 commit 完成具名独立验收并返回 `PASS`；
9. 独立验收 `PASS` 后，规范 / 计划索引所有者以第二次治理发布将 4080、规范目录、冻结 manifest 和计划索引同步升级：`data_l1_status=FROZEN`，具名验收 commit / 记录，本计划退出。

第 1—7 项是执行智能体的代码候选交付边界；第 8 项是独立集成验收所有者边界；第 9 项是规范 / 计划索引所有者边界。三者不得合并为执行智能体的自证。

## 8. 失败收口

- 公开面多项：修正本计划允许范围内的检查器错误；若真实服务公开面漂移，停止并退回设计，不更新 allowlist。
- 历史格式样本不能生成 / 恢复：保留证据和临时根，停止发布，不手工修字节。
- 专项失败且原因位于允许核心 / 专项：在原合同内修复并全量重跑。
- 必须修改公共 DTO、服务 ABI、工程 XML、入口或上层消费者：设计漂移，零扩大范围。
- 环境或一次构建波动：在同一独立树定位；只有持续且无法在范围内归因时才停止。
