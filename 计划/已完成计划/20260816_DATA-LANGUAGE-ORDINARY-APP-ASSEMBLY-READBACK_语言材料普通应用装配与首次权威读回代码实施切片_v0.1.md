## 4. 冻结目标合同

### 4.1 函数与返回

```cpp
bool 普通应用配置::有效() const noexcept;

普通应用生产配置结果 形成普通应用生产配置() noexcept;

    普通应用上下文::取得L2语言结构服务() const noexcept;

    const 普通应用配置& 配置);
```

生产配置无参数，成功返回固定 `LocalAppData/海中鱼巣/数据/不可变材料` 的强类型配置；非成功配置为空并按详细设计六状态分账。`普通应用配置::有效()` 只做合同 / 路径纯值校验。四个 getter 无失败分支且返回上下文持有的同一实例。装配和启动既有公开签名不变。

### 4.2 owner、服务和成员顺序

材料服务模块公开现有值不变的 `不可变材料所有者建立身份`，内部不保留同值副本。普通应用在同一 L1 中分别签发材料、语言、词条固定 owner，构造唯一材料服务和唯一双 owner 语言服务；现有概念服务改用材料 + 六世界完整构造。

上下文成员和私有构造按 `L1 -> 材料 -> 语言 -> 六世界 -> 概念 / 聚合 -> 方法 / 聚合` 声明与移动，保证反向析构。装配状态只在现有 31 后追加详细设计固定的 32—38，不得重排旧值。

## 5. 实施步骤

1. 在材料服务模块把既有材料 owner 建立身份原值提升到唯一公开位置，并让内部交付验证使用它。
2. 在普通应用模块增加材料 / 语言 import、生产配置类型与形成函数；使用 Windows `LocalAppData` 已知目录和固定相对位置，不新增启动参数或新模块。
3. 扩展普通应用上下文成员、私有构造和四个 getter；同步配置校验、装配状态和成功路径。
4. 在装配函数中建立材料、语言、词条 owner 和服务；继续复用现有 provider、现有双 owner 构造及现有完整概念构造，不复制 helper 或建立第二服务。
5. 让 `运行普通程序` 先取得结构化生产配置，再执行现有普通应用装配；后继阶段顺序和失败映射不变。
6. 建立仓库外合法消费者，按详细设计第 6、8 节完成 getter 同实例、材料写读、语言增读、词条增读及当前 / 历史权威互证。可以使用调试器断点观察参数和返回；生产源码零验证增量。
