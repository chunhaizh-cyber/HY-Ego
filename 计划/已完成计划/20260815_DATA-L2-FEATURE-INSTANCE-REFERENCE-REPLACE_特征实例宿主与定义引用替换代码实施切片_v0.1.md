## 1. 目标与完成条件

按同名详细设计，在唯一 `L2特征结构服务` 中增加实例宿主 / 定义完整引用对的原子替换公开 ABI，并修正完整实例读回对合法替换关系代次的识别。

完成必须满足：请求、结果、纯值 helper、成功谓词和服务函数逐字实现；一笔特征实例 owner 写集同代退出两条旧关系并建立两条新关系；实例身份、族归属、生命周期和当前值保持；当前 / 历史读回跨替换截止正确；根工程双配置和风险相称的生产外检查通过；全部临时验证代码和输出已清理。

写前拒绝与 L1 明确零发布非成功必须空对象载荷、空变更代次。若 L1 已确认首次发布或精确重复的首次结果，但发布后正式读回发现内部矛盾，则返回空对象载荷的 `内部不一致`，同时保留已知首次变更代次；不得把已发布事实伪装成零变化。

## 5. 实施步骤

1. 从最新正式 HEAD 重做 Git、index、目标文件、接口和所有权 S0。
2. 在特征数据头追加详细设计冻结的 DTO、helper 和结果成功谓词。
3. 在特征服务内部追加空载荷失败结果与旧关系历史投影所需私有辅助。
4. 修正 `形成F2特征实例事实(...)` 的关系代次合同，保持首次新增、当前 / 历史读取和实例退出兼容。
5. 在公开服务原位实现 `替换特征实例引用(...)`：写前强类型互证、一次写集、成功 / 重复边界、同截止当前与历史读回、未改字段守恒。
6. 根工程 x64 Debug Rebuild 通过后运行 Release Rebuild。
7. 建立生产工程外临时公开入口检查，覆盖第 6 节矩阵；失败仅在白名单内修复。
8. 运行 strict、diff、UTF-8、范围、ABI 和生产零验证痕迹检查。
9. 删除临时三件套及全部专属二进制 / 中间文件，重跑根工程双配置和静态清理门禁。
10. 写两份永久记录，只提交两个生产文件和两份记录，普通 push 并远端读回。
11. 单独登记本计划退出，再重扫 `DATA-EXT-01—16` 的下一最早可施工缺口。

## 6. 检查矩阵

1. 错合同、零守卫、零幂等、零实例、坏旧关系对、零新端点分别入口拒绝且零载荷；
2. 只换宿主、只换定义、两端同时替换均首次成功；
3. 当前实例身份、族归属、生命周期和可选当前值逐字段保持；
4. 两条新关系同代当前，两条旧关系同代退出且历史端点完整；
5. 替换截止之前历史读回旧引用，达到替换截止读回新引用；
6. 按旧宿主读取不再命中、按新宿主读取命中同一完整实例；
7. 同完整请求精确重复返回首次截止和相同投影，不推进事实代次；
8. 旧关系编码错配、完全相同端点对、已退出实例 / 新端点、陈旧守卫和同幂等异义精确分账；
9. 另一实例、特征定义和特征当前值不受影响；
10. 结果成功谓词拒绝空载荷、错截止、混关系、未退出旧关系和完全同端点对等坏成功形状；
11. 既有实例新增、完整读取、按存在读取、当前值增改退和实例退出不回归。

真实资源耗尽、私有 owner / 关系组损坏、发布结果未知、跨进程恢复、共享锁长期公平和正式 BIZ 消费没有合法稳定注入时如实 `NOT_RUN`，不得增加生产故障 seam。

## 7. 停工与声明边界

若 L1 一份 owner-scoped 写集不能同时建立两条新关系并退出两条旧关系，或历史关系组无法按指定截止选择唯一当时引用对，具名返回 `DRIFT-DATA-L2-FEATURE-INSTANCE-REFERENCE-REPLACE-L1-CONTRACT-CHANGED`。普通编译、算法和检查错误由执行者在白名单内修复。

本计划完成只证明实例引用替换 provider 实现和发布，不证明 DATA-EXT-03 整项、DATA-L3 聚合、正式消费者适用性或《数据服务最终需求清单》整体完成。
