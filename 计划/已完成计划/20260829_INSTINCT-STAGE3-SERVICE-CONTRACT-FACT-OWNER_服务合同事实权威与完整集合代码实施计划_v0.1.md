## 4. 目标接口与实现步骤

### 4.1 数据合同

在 `服务合同事实权威.数据.h` 实现同名详细设计第 4 节的身份、状态、合同事实、状态事实、到期事件事实、两类完整集合见证、请求、结果、成功谓词和完整性谓词。

所有公开值类型支持逐字段相等；结果状态数值固定。成功谓词必须复核事实组、见证、规范顺序和截止，不得只看枚举。

### 4.2 owner 与登记

在 `服务.服务合同事实权威.ixx`：

1. 形成固定 owner 交付并验证同一 L1；
2. 幂等登记 `0x0307'3001..301F` 内实际使用的锚点、索引根、关系类型和属性类型；
3. 构造期完整读回登记；冲突或恢复损坏必须构造失败；
4. 不在构造期建立合同、状态或事件。

### 4.3 完整集合读取

两个公开读取均执行：

```text
请求 / G0 守卫
-> L1 一致关系类型闭包
-> owner / 登记 / 关系类型互证
-> 逐成员节点、外部引用、载荷和当前状态重建
-> 业务结构不变量复核
-> 规范排序与身份投影一致
-> G0 读后守卫
-> 成功载荷或结构化非成功
```

数量不设置调用方预算；完整集合 owner 必须返回全部当前成员。若底层资源无法形成全集，返回资源失败或集合不闭合，不能截断成功。

### 4.4 验证 fixture

仅在专项验证宏中提供 module 内 fixture，建立合法 1 / N 合同、终态干扰、到期事件和故意损坏候选。fixture 不导出到普通应用，不形成生产调用点；非验证构建必须不存在可调用写入口。

### 4.5 装配与工程

普通应用上下文唯一持有服务，提供 const / mutable 取得函数；构造顺序位于 L1 运行包之后、阶段三消费者之前。工程与 filters 精确登记三个新模块 / 专项；不得带入其它 WIP。

## 5. 失败与收口

- owner / 登记建立失败：普通应用构造返回具名失败阶段；不降级为空集合。
- G0 漂移：`当前性漂移`，空载荷、截止 0。
- 关系、载荷、状态或外部引用复义：`集合不闭合`或`引用冲突`，不得跳过坏成员返回部分成功。
- L1 资源失败：`资源失败`；异常捕获为资源失败或内部错误。
- 读后失败：不保留首次载荷，不缓存、不重用旧结果。
- fixture 故障不进入生产构造和运行路径。
