## 1. 目标与完成条件

在现有唯一 `L2特征结构服务` 和特征定义 owner 内实现统一特征定义结构，使基础特征和实际二次至 n 次派生特征都能正式创建、完整当前 / 历史读取、使用现有固定属性新增 / 换代、被实例引用并显式退出。

完成必须同时满足：

1. 新增统一 DTO 和四个唯一公开入口；
2. 基础定义固定阶次 1，派生定义固定为来源最大阶次加 1；
3. 直接来源、输入角色、派生规则身份 / 版本与定义同事务发布并同截止读回；
4. 现有固定属性和实例入口只接受完整统一定义；
5. 零消费者旧定义创建 / 完整读取 / 退出 ABI 物理退出且无兼容转发壳；
6. 退出同代闭合全部自有结构并服从当前引用保护；
7. 生产文件中不存在专项、假成功、默认阶次或第二特征服务 / owner / 节点族；
8. 临时专项完成后清理，保留人读施工 / 检查记录；
9. 不宣称独立验收或后继业务可用，实际可用性由合法消费者以后正式使用判断。

## 5. 实施步骤

### S1 DTO 和纯值合同

在数据头新增详细设计第 4 节全部 DTO、比较和纯值 helper；以新具名 DTO 取代旧定义创建 / 完整读取 / 退出 DTO。保留身份来源、固定属性、实例和值 DTO。

检查所有非成功结果空载荷、成功头 / 截止 / 变更代次和基础 / 派生形状互斥。

### S2 私有结构登记

在服务实现内部新增三种私有类型、本地键、固定幂等身份、定位结构和构造期登记：实际阶次 `I64` 属性、派生规则见证 `U64组` 属性和直接来源关系类型。登记只使用特征定义 owner，不公开定位和写端口，不改变普通应用构造签名。

### S3 创建和读回

实现 `新增统一特征定义`：

- 纯值请求检查；
- 同截止来源定义预读以及规则身份 / 版本纯值校验；
- 阶次、顺序、输入角色和 pair 唯一性检查；
- 基础 / 派生不可拆分 owner-scoped 原子写集；
- 首次 / 精确重复映射；
- 提交截止完整读回。

### S4 当前 / 历史读取

实现 `读取完整统一特征定义`，闭合节点、身份来源、两种私有属性、直接来源关系和固定属性；稳定排序并拒绝未知结构、混代和坏形状。历史入口只使用具名历史截止，不以当前事实补项。

实现 `读取全部当前统一特征定义`：零守卫由一次 L1 关系类型闭包许可原子选择最新快照，非零守卫严格匹配；空组成功并返回非零截止，非空组按定义身份严格升序且不得过滤坏成员。

### S5 固定属性、实例和退出

- 固定属性新增 / 换代写前改为验证统一定义；
- 实例新增写前改为验证统一定义；
- 实现 `退出统一特征定义`，逐项匹配调用方显式闭包并同代退出；
- 依赖 L1 当前引用保护拒绝仍被实例或派生定义引用的目标；
- 删除旧定义三个入口和专属内部辅助，确认零残留符号。

### S6 记录、检查和临时资源清理

形成两份永久记录，写清实际变更、实际运行分支、NOT_RUN 和完成边界。临时专项完成后精确删除三件套；不得把专项代码、宏、seam、测试 key 或 PASS 文案留在生产文件或工程。

## 6. 施工检查矩阵

临时专项至少逐项输出请求摘要、预期状态、实际状态、截止 / 变更代次、定义前后投影和当前 / 历史读回：

1. 基础定义首次、精确重复、同键异请求；
2. 二阶定义由两个基础来源形成；
3. 三阶定义由基础与二阶来源形成；
4. 同来源异角色和同角色异来源允许；重复 `(来源, 角色)`、零角色、零 / 缺口 / 乱序拒绝；
5. 声明阶次不等于最大来源阶次加一拒绝；
6. 规则零身份、零版本、溢出或坏见证材料拒绝；
7. 来源未找到、已退出、事实代次漂移；
8. 当前 / 历史读取同截止、稳定排序和基础 / 派生互斥；
9. 全组零守卫原子最新、非零守卫同代 / 漂移、空组成功、坏成员整组失败；
10. 固定属性新增 / 换代不改变阶次、来源和规则；
11. 实例引用完整统一定义成功，坏 / 旧定义拒绝；
12. 被实例或派生定义引用时退出冲突且零变化；引用闭合后退出成功、当前已退出、历史完整；
13. 同请求和异请求并发竞争只形成一个权威结果；
14. 全部非成功载荷为空且无变更代次；
15. 旧定义 API 符号、第二服务 / owner / 节点族、生产验证痕迹均为零。

真实分配耗尽、私有仓损坏、跨进程恢复、长期公平和正式 BIZ 消费若没有合法公开注入路径，精确记录 `NOT_RUN`，不得增加生产 seam 或另立验收计划补格。
