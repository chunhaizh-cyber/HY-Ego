## 1. 目标与完成条件

在新`数据服务.场景类`内实现 scene owner 的原子“创建并接纳场景”数据操作：以一个中性写集同时创建新场景 N 和父场景到 N 的子场景关系 E，并以首次 / 历史读回闭合幂等、发布未知和根边界。

完成必须满足：

- 合同版本 1、14 个稳定状态、请求 / 投影 / 结果和`创建并接纳场景`完整实现；
- 一个请求只提交一次 owner 写集，写集恰含一个节点和一条以局部键 N 为目标的子场景关系；
- 新场景从出生起有且仅有一个父关系，本入口不能创建根；父场景可为现实根或普通场景；
- 首次成功和精确重复都完成对应截止读回，读回不闭合返回`已可能发布`；
- 同义重放返回原 N/E，同键异义冲突，无补偿删除或第二写集。

## 2. 当前事实与复用

起点基线已具备 scene owner 写端口、`场景结点本地键{1}`、`成员关系本地键{2}`、子场景关系类型、父 / 子关系读回、首次写入材料、写入结果头和编码映射工具。L1 的`L1所有者范围事实引用`允许关系目标引用同写集本地节点，因此无需扩展 L1。

既有`新增场景`和`新增成员关系`必须保留，但不能由新入口串行调用；两次提交不能满足本计划原子合同。旧`服务.L2*`不是依赖或备选。

正式依据：0050、1140、1150、4200、4230及同名 v0.1 详细设计。

## 5. 实施步骤

1. S0 复核索引中的计划 blob、起点以后提交、文件占用、场景类当前 ABI、L1 局部键关系端点能力和知识条目基线；会改变冻结合同的漂移退回计划支撑。
2. 加入版本、14 状态、三个 DTO、默认相等性和严格`成功()`；非成功结果零投影。
3. 实现请求校验和父场景 G0 当前本体读取；映射未找到、退出、漂移、历史清理、资源与内部失败。
4. 形成精确写集：节点局部键 1；关系局部键 2，源=父场景稳定编码，目标=节点局部键 1，类型=现有子场景关系类型，角色=1；其它四组为空。
5. 实现首次执行：首次材料未找到后只提交一次中性写集，不调用`新增场景`或`新增成员关系`。
6. 实现两条互斥重放：预读命中材料时比较完整写集后提交一次并要求`精确重复`；预读未命中而提交竞态返回`精确重复`时只重读 / 比对首次材料，不得第二次提交，直接使用已有重复结果做历史读回。
7. 实现提交收口：按 L1`成功`与`精确重复`分别核对“形成内存权威发布 / 重试边界”结果头，严格提取两个本地键映射；首次成功当前读回，精确重复原发布代次历史读回；核对 N、E、父子双向投影、owner、类型、角色、代次和生命周期。
8. 提交已报告成功后的任何映射 / 读回 / 异常缺口返回`已可能发布`；不补偿、不自动重试、不换键。
9. 写施工记录，登记 ABI、写集形状、重放与读回路径、复用能力、未修改边界和未验证范围。

## 6. 状态与事务门禁

- 父场景预读失败在写前确定收口，零事实写入。
- L1`未找到/已退出`在父场景已经同 G0 验证后只映射子场景关系类型失效；并发推进应由 L1 返回`事实代次漂移`。
- L1`许可拒绝`或未知状态保守映射`内部不一致`，不得增加临场状态。
- 首次材料预读未命中而提交竞态得到 L1`精确重复`时，只允许重读并证明首次材料与本次重复结果一致；不得在同一公开调用再次提交。重读历史清理 / 漂移 / 资源、仍未找到、材料缺失和异义分别按详细设计 8.2 收口。
- 结果头按状态分账：首次`成功`必须报告形成内存权威发布且重试边界不适用；`精确重复`必须报告未形成新发布且重试边界为原幂等身份读回收敛。
- L1 报告`成功`后不论编码提取、当前读回或异常为何失败，均只能返回`已可能发布`。
- 精确重复是原发布事实证明，不是当前仍在原父场景的承诺。
