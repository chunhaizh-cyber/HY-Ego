## 1. 目标与完成条件

在现有特征 owner 和三分区统一变化服务中实现 v2 永久变化账、登记和按特征 / UTC 范围完整 `0/N` 读回。

完成必须同时满足：

1. v2 真实变化的账与新当前值、状态、动态共享同一 G1；
2. 无变化零账，精确重复零第二账，同键异义拒绝；
3. 登记前不允许合法空集；登记后 `0/1/N` 完整组和见证成立；
4. 状态 / 动态清理不删除永久账；
5. v1 ABI 与专项回归不变，生产 v1 调用保持 0；
6. 两配置、专项、ABI consumer、strict 和 diff-check 通过；
7. 当前安全根定义版本 1、L/H 及相关生产文件 blob 零变化。


DTO、状态数值、载荷顺序、固定键、成功公式、原子顺序和完整见证以详细设计第 4—9 节为准，执行者不得换型、改 owner、回填新当前值身份或用动态扫描替代永久账。

现有 `执行中性实例材料清理_v1` 公开 ABI 不变。只在状态 / 动态 owner 的 private 闭包与枚举中增加关系式记录兼容：关系式动态由上下文角色 `4/5` 恢复成员；关系式状态 / 动态退出和物理清理必须包含全部上下文关系，旧式载荷路径保持不变。

现有 `L1所有者范围写端口::读取首次写入材料` 公开 ABI 和结果布局不变。仓库私有 `所有者范围首次记录完整` 对每个首次稳定编码映射接受且只接受一种权威存续形态：当前事实、历史事实或匹配物理清理墓碑。墓碑必须与首次写集本地键的节点 / 关系 / 值种类、owner 内部结构分区和首次创建 G1 全等；不得用墓碑恢复完整事实载荷，也不得跳过原规范化写集和首次结果互证。

现有 `本能根运行初始化提供者::初始化并读取本能根运行锚点_v1` 公开 ABI 不变。其 private `验证已存在根值记录` 在已有值分支只验证当前值事实同截止完整、生命周期当前、实例一致、I64 类型及 `0..I64_MAX` 值域；不得要求等于冷启动初值、固定来源或仍有当前状态选择。无值分支仍按原合同建立固定首值与初始状态。

## 5. 实施步骤

1. 在两个数据头增加 v2 登记、请求、结果、账事实、组读取和成功谓词。
2. 在特征服务增加固定账锚点登记、首次材料读回、v2 特征参与者写集和按锚点来源完整账扫描 helper。
3. 在统一变化服务实现登记入口和 v2 三分区发布；v1 代码路径保持行为不变。
4. 实现提交后四幂等首次写入、共同 G1、单项状态 / 动态和账事实互证。
5. 实现 UTC 半开区间完整读回、规范排序、数量预算、集合见证和双守卫。
6. 在状态 / 动态 owner 的 private 枚举、闭包、退出和物理清理路径补齐三分区关系式记录兼容，不新增公开入口或 DTO。
7. 在 L1 仓库私有首次记录互证中增加墓碑分支，并保持当前 / 历史 / 墓碑恰一命中；坏种类、坏 owner、坏首次 G1 或多形态命中必须失败。
8. 修正本能根已有当前值恢复验证，保留无值冷启动首值首态路径；最终 Gfinal 仍独立读回完整根锚点。
9. 在现有安全根专项中增加隔离 v2 场景；验证宏故障注入不得进入生产对象。
10. 形成施工 / 验证记录，执行两配置、专项、ABI consumer、strict 和差异门禁。
11. 只精确暂存本计划白名单差异；提交、普通推送后归档计划并清空索引。
