
目标：实现一份具名任务子目标回流记录的实时父需求重判 consumer，并补齐 task owner 的子目标回流专用统一后继提交，使同一记录只能稳定收敛到“不筹办 / 初次轮次 1 / 原来源任务统一 N+1 / legacy 待迁移”之一。

实施完成必须证明：

1. 入口不扫描任选记录，只读取调用方具名记录和`记录.父需求`；
2. 父需求、当前成员、完整列表项、当前任务和当前满足裁决共享 G0；
3. 当前已满足零任务写；
4. 无当前任务复用既有初次 provider，并产生版本 1 统一轮次 1；
5. 只有当前任务等于记录来源任务且为统一 population 时，task owner 才原子推进 N→N+1；
6. legacy 返回`轮次权威待迁移`且零 legacy / 统一写；
7. 处理键只由`回流记录.值.值`唯一派生；初次或后继写结果一旦存在，同记录只能恢复原结果而不能换任务 / 换分支；零写结果只绑定本次 G0，后续新 G 可实时重判；

9. 施工记录形成函数级代码知识变更清单，验证记录逐项保留 PASS / FAIL / NOT_RUN；
10. 只发布本计划白名单文件和专属记录。

## 7. task-owner 事务与恢复门禁

新 DATA 函数的顺序不可调整：

```text
按准备键恢复首次结果
-> 无首次结果才检查当前 G
-> 同 G 读具名回流记录
-> 按触发事实反查既有后继 0..1
-> 同锁读统一分区与当前 N
-> 校验推进材料和 UINT64_MAX
-> 单一写集创建 N+1 + 换代当前关系
-> 按 G1 读回
```

写集必须满足：

- 触发类型固定`子目标回流`，触发事实固定为具名记录；
- `幂等身份.值 == 回流记录.值.值`，且准备幂等身份 / 触发业务幂等身份与其完全相等；
- 记录.任务、请求.任务、权威.任务、当前任务同一；
- `新轮次 = 前一轮次 + 1`；
- N=1 时前一后继为空，N>1 时引用当前后继；
- 旧路径、旧实例、实际结果、目标裁决和正式状态关系全空；
- 同记录反向触发全局最多一份；同键同义精确重复，同键异义幂等冲突，同记录伪造换键入口拒绝，同记录换任务引用冲突；
- 发布未知只用记录身份派生的稳定键恢复，不能生成新键或刷新 N 后重放。

## 8. BIZ 分支与结果形状

入口不接收调用方键，先从`回流记录.值.值`派生唯一处理键，再固定先读后继结果：后继存在即恢复并停止，后继为空才读初次结果；初次存在即恢复，两次都空时才：

```text
读取具名记录
-> 记录.父需求
-> 父需求 / 当前成员 / 完整列表项
-> 列表项当前任务
-> 父需求当前满足裁决
```

分支固定：

| 条件 | 结果 | 载荷 |
| --- | --- | --- |
| 已满足 | 目标已满足不筹办 | 仅已满足裁决 |
| 未满足 + 无当前任务 | 初次已形成 / 精确重复 | 仅初次工作包 |
| 未满足 + 当前任务不同 | 当前任务冲突 | 无成功载荷 |
| 未满足 + 同任务 legacy | 轮次权威待迁移 | 无成功载荷 |
| 未满足 + 同任务统一 | 后继已形成 / 精确重复 | 仅后继工作包 |
| DATA 同记录伪造换键 | 入口拒绝 | 无成功载荷 |
| 已有写结果后换任务 / 换分支 | 回流触发冲突或幂等冲突 | 可选既有后继身份，不携带工作包 |

恢复顺序不得颠倒或无条件并列调用：当前后继 reader 能把初次写判为空，但初次 reader 会把后继写的未知事务形状判为内部不一致。任何分支不得把当前最新 G、当前最新 N 或新的处理键拼入首次结果恢复。初次 / 后继写结果一旦存在，同记录稳定键只能恢复原分支；已满足、legacy、当前任务冲突等零写结果只绑定本次 G0 与输入，后续新 G 允许重新实时裁决，不建立第二决策账。

## 11. DRIFT 与停工条件

只在以下情况停止受影响切片并退回计划支撑：

- 当前 ABI 无法按详细设计唯一构造请求或恢复首次结果；
- 记录来源任务与当前任务的关系需要改变本计划分支语义；
- 同记录跨任务唯一性无法在 task owner 现有触发关系下证明；
- 子目标回流后继必须同时迁移其它 task-owner 正式状态才能保持规范一致；
- 现有轮次键、类型或模块名发生碰撞；
- 必需验证持续失败且无法在白名单内安全归因。

普通编译错误、格式问题、无关 dirty、一次工具波动和可在白名单内修复的机械实现问题不构成设计 DRIFT。
