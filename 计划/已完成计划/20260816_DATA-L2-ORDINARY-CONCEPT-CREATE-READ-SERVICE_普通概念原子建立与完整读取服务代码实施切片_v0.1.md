## 3. 固定 ABI 与所有权

保留现行根专用构造和根三入口。新增详细设计第 3.2 节完整构造，并精确新增：

```cpp
L2普通概念写入结果 建立普通概念(
    const L2普通概念建立请求& 请求);

L2普通概念读取结果 读取普通概念(
    const L2普通概念读取请求& 请求) const;
```

类继续不可默认构造、不可复制、不可移动。完整构造只借入七份 const 服务引用并移动同一概念 owner 交付；根专用实例的普通入口固定 `未实现`。根与普通建立共用同一服务级概念写锁，最终原子性和期望代次仍由 L1 owner-scoped 事务裁决。

## 4. 实施合同

1. 以详细设计第 4 节固定键和 `0x4C32'434F'5247'0002ULL` 登记普通概念私有结构；首次 / 重复均严格读回，编码与既有概念登记互异。
2. 普通概念建立前完成根、全部直接上位、材料、定义目标、特征值和十三类世界关系的同 `G0` 公开服务验证；不得直读其它 owner 的 L1 私有事实或判断业务正确性。
3. 写集严格按第 5 节形成：6 个固定事实映射、每父 / 每证据一关系、每签名项和每定义项各四映射；本地键分区、属性表示、来源节点和闭合定义编码不得临场改变。
4. 以首次请求见证持久区分同幂等异义、同签名异请求和精确重复；唯一键只由根、规则材料、签名值式项和定义项组成。直接上位和来源证据属于完整请求但不进入签名键。
5. 当前读取使用非零守卫同截止两阶段读取；历史读取按具名截止逐项投影。公开负载排序、生命周期、身份来源和所有引用必须完整，缺项 / 重复 / 混代不得过滤或猜成功。
6. 首次成功和精确重复都返回首次历史负载与首次截止。全部非成功空负载、零变更；资源失败或发布后结果未知只允许原完整请求重放。
7. 不建立普通概念缓存、签名权威索引、第二 owner、第二服务、通用关系查询、业务准入、默认材料路径、测试 seam 或生产自检。
