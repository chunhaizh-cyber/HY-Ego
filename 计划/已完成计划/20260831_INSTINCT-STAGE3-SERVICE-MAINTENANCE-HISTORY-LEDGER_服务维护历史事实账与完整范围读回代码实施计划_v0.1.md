## 1. 目标与完成条件

扩展现有唯一 `服务合同事实权威服务`，建立五类服务维护事实的永久历史成员账，修改现行进展 / 准备 v2 发布使每个新版本同步入账，并实现 `(排除起始事实代次,G0]` 的 0/N 完整范围读回。

完成必须同时满足：

1. 历史账在同 owner 内以独立登记幂等形成 / 恢复，既有五组登记及业务事实不改写；
2. 历史账登记后的进展 / 准备 v2 首次和更新均在同一 owner 写集中形成永久历史成员，精确重复无第二成员；登记前事实保持兼容而不补账；
3. 五类事实范围结果、规范排序、数量预算、登记覆盖边界和完整见证成立；
4. 任一坏成员、漏账、重复、错引用、漂移或资源失败整体非成功且零载荷；
5. Debug / Release、专项、ABI consumer、持久恢复、diff-check 和 strict 通过；
6. 形成专属施工 / 验证记录并精确提交、普通推送；
7. 完成后计划归档并从当前索引删除。

## 5. 实施步骤

### 5.1 DTO 与成功谓词

逐字段实现请求、历史成员身份、见证、结果和完整性 / 成功谓词。成功必须复核五组总数、形成代次范围、规范顺序、事实完整性、请求自我、登记覆盖和见证逐项相等；不能只看状态码或 vector 数量。

### 5.2 历史账登记

在现有 owner 内增加 `0x494E'5354'5348'5631` 登记和 `0x0307'3050..305B` 定位。构造期在五个已有登记之后建立 / 恢复历史账登记，逐项验证首次规范写集和当前投影。候选常量必须再次做全仓零命中扫描。

### 5.3 生产同步入账

修改 `发布服务进展事实_v2` 与 `发布服务准备事实_v2` 的写集形成辅助，使历史账登记后的每个新事实节点同时取得永久历史成员关系。旧事实形成代次早于登记代次时沿用完整闭包退出且不补账；旧事实形成代次晚于登记代次时必须互证其历史成员关系并只退出旧当前成员关系，旧事实节点、载荷、业务引用关系和历史关系保持。登记代次与业务事实等代固定拒绝。历史结果以当前成员关系退出代次投影`退出当前事实代次`，节点继续存在不等于仍当前。

精确重复必须按首次提交代次分账：登记前旧请求按不可变旧首次写集 / 历史闭包收敛，零补账；登记后请求必须互证首次写集已含历史成员。不得用新写集形状重组旧请求并误报幂等冲突。当前性漂移、资源失败和发布后读回失败继续沿用现行状态矩阵。

合同 / 状态 / 到期事件没有生产发布入口，本计划只为它们建立历史根和读取合同，不新建独立 writer。测试 fixture 必须在测试宏内同步形成历史成员，生产扫描应为零 fixture 出口。

### 5.4 完整范围读取

实现五根一致闭包、登记 / owner / 成员 / 载荷 / 引用 / 自我 / 版本互证；对四类有当前索引的事实按其形成代次历史读取唯一当前成员关系并投影正式退出代次；对当前进展 / 准备根中登记后成员反向互证历史关系；随后执行整个账先验证后过滤、范围和数量预算、规范排序、见证和 G0 双守卫。覆盖起点早于登记代次必须返回`覆盖边界不可用`，不得回退为合法空组。

运行时不声称能从未知身份反向发现已经绕过唯一入口且不再当前的历史漏账。完整性必须同时由 raw 写端口不外泄、生产发布同写集强制入账、当前成员反查、永久账闭包、生产调用扫描和专项证明；禁止只凭见证计数宣称全 owner 扫描完成。

### 5.5 故障与恢复专项

只在既有 `ARCH_INSTINCT_SERVICE_CONTRACT_FACT_AUTHORITY_VALIDATION` 下扩展五类样本、坏账和漂移注入。生产源码不得为专项新增公开 fixture、友元、模式或第二写入口。

## 6. 失败收口

- 历史登记建立 / 恢复损坏：服务构造失败，不降级为空账。
- `Gstart < Greg`：覆盖边界不可用，零载荷；不猜测登记前历史。
- 历史成员关系退出、当前成员缺账、重复、坏载荷或引用：集合不闭合 / 引用冲突，零载荷。
- 预算不足：整体数量预算不足，不截断、不分页冒充完整。
- G0 漂移：当前性漂移，丢弃候选。
- 资源与异常：资源失败或内部错误；不得返回部分组。
