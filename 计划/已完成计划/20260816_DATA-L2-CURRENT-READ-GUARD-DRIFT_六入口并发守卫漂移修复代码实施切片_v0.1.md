## 1. 目标与完成条件

按同名详细设计，在现有两个 DATA-L2 结构 owner 内完成兼容修复：

1. `读取场景树`、`读取存在单例角色`、`读取完整存在`、`读取存在当前场景成员引用`、`读取场景宿主存在关系`、`读取存在当前宿主场景` 六个公开当前读取入口共同遵守非零 `G0` 守卫。
2. 任一影响载荷的当前子读取正式观察到非零 `G1 != G0` 时，公开结果返回 `L2结构状态::事实代次漂移`、截止 `G1`、零变更代次和零载荷。
3. `读取场景树` 正式基线约 3715、3798 的两处无守卫关系组读取不再把合法并发推进折为 `内部不一致`。
4. 另外五入口的登记、来源、端点和同截止后续读取完成漂移优先传播回归。
5. 六个公开签名、全部 DTO、枚举、owner、历史读取、正常成功和其它合法非成功语义保持。
6. Debug / Release 根工程及六入口仓库外并发矩阵闭合，生产代码零验证专用增量。

完成只证明本计划具名 DATA provider 修复，不证明 WORLD-SELF、BIZ 组合器、自我形成、普通应用或整个 DATA-L2 完成。

## 4. 机械施工合同

1. 保持详细设计 §3 六个公开签名及全部 DTO blob 不变；只修改两个现有服务模块内的当前读取实现和必要私有状态解释。
2. 每个当前入口固定一次调用方 `G0`；影响成功载荷的每项当前依赖都携带 `G0`，或在解释载荷前把正式返回截止与 `G0` 互证。
3. `读取场景树` 具名处理两处缺口：树归属目标关系组和各场景目标父关系组的无守卫当前读取。它们观察到非零异截止时返回漂移，不进入树闭包或父子坏形状判断。
4. 六入口遇到直接 / 嵌套子服务 `事实代次漂移`时先传播状态与观察截止，再检查 optional、空组、项目数、owner、端点或生命周期。
5. 守卫式一致投影声称成功但回声 / 读取截止不等于 `G0`仍为 `内部不一致`；无守卫子读取合法成功观察到 `G1 != G0`才按详细设计映射漂移。不得用宽泛的“所有错截止都算漂移”掩盖坏成功形状。
6. 漂移统一经既有或调整后的失败形成路径返回：合同版本正确、状态漂移、截止 `G1`、变更代次空，六类载荷按详细设计 §3 全空。
7. 许可、资源、未找到、已退出、属性未设置、入口拒绝及真正坏形状保持现行映射；历史分支零语义变更。
8. 实现可以复用、拆分或调整两个文件内部现有 helper，但不得新增公开 helper、跨 owner 通用模板或第三服务，也不得让执行者改写公开机器语义。
9. 直接修改函数诊断责任登记为 `向上送出`；不新增生产日志。施工记录列出六公开函数及所有直接修改私有 helper 的完整签名、用途 / 非职责、调用边、并发与验证变化。

## 5. 实施顺序

1. S0 核对计划身份 / blob、正式规范、两个源码 blob、知识用途卡、计划索引、index、代码段与构建资源；确认 WORLD-SELF 和其它异主 WIP 零路径 / 零语义覆盖。
2. 先修复 `L2场景结构服务::读取场景树` 的两处已证实错分支，并静态证明所有失败载荷为空。
3. 逐一复核其余五入口从登记 / 来源到最终载荷的当前调用链；只补齐会吞掉漂移的分支，不做无关格式化或重构。
4. 在专属 `D:\TEMP` 本轮目录建立生产外参数化驱动，按详细设计 §7 完成六入口 Debug / Release 的 S0—S3 矩阵；不得修改生产代码提高窗口命中率。
5. 运行根工程 x64 Debug / Release fresh Rebuild、diff、strict、UTF-8、公开 ABI / DTO blob、白名单和生产零验证痕迹检查。
6. 写专属施工 / 验证记录；只记录实际观察值，未命中并发窗口写 `NOT_OBSERVED` 并视为验证未通过。
7. 只提交允许的两个生产文件和两份记录，普通推送；结果由交互侧核验并路由计划索引退出及 WORLD-SELF 重新 S0。

- 六入口 × Debug / Release 的稳定控制均保持现行成功 / 合法非成功；
- 六入口 × Debug / Release 的读前失效均精确返回漂移、`G1`、零载荷；
- 六入口 × Debug / Release 的读中失效均实际观察至少一次漂移，合法 writer 推进导致的 `内部不一致`、部分载荷和零截止均为 0；

- 公开函数签名、三个 DTO blob、枚举数值、历史分支和工程登记不变；

任何入口或配置未观察到目标并发窗口、返回漂移但载荷非空、截止为 0 / 等于 `G0`、合法并发仍产生内部不一致，均为失败，不得降级为记录说明后发布。
