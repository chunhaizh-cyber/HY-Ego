## 4. 第 16 项最终验证合同

v0.1 第 9.2 节第 16 项整体替换为：

1. 先在调用前确定性推进 L1 事实，再以旧期望代次分别调用当前 / 历史完整读取；二者
   必须返回 `事实代次漂移` 和空场景。该步骤只证明确定性旧基线拒绝，不冒充并发窗口；
2. 再用 `std::barrier` 让一个公开当前完整读取线程与一个公开写入线程同起步，固定最大
   轮数；验证代码不得 sleep、`yield`、忙循环、重复放大某线程优势或使用调度优先级；
3. 每轮写者必须经公开入口成功形成新场景并推进一代；读者结果只允许下表三种形状：

| 读者状态 | 截止 | 场景载荷 | 必须满足 |
| --- | --- | --- | --- |
| `已读取` | 等于该轮请求期望代次 | 存在 | `L2场景事实完整`，全部字段共享该截止 |
| `事实代次漂移` | 合同允许的安全实际代次 | 空 | 不含变更代次或任何部分场景 |
| `许可拒绝` | 0 | 空 | 不含变更代次或任何部分场景 |

4. `内部不一致`、资源失败、入口拒绝、未找到、已退出或其它状态均为 FAIL；成功但场景
   缺项 / 混代，漂移 / 许可拒绝携带场景、许可拒绝截止非零、写者失败或代次形状错误
   也均为 FAIL；
5. 逐配置统计实际出现的 `已读取 / 事实代次漂移 / 许可拒绝` 轮数，并写入验证记录。
   三类是合法集合，不要求每次运行强制命中全部三类，也不得以缺少某类把合法实现判错；
6. 公开结果不能证明代次推进恰好发生在当前两次内部投影之间，或历史前后代次夹取之间。
   验证记录只写本次实际观察到的公开状态；没有独立可判别证据时必须写“内部窗口未证明”，
   不得写成已覆盖。不得为取得窗口证据增加测试钩子、私有访问、生产时序后门或人工让行。

固定最大轮数只是终止边界，不是覆盖次数。即使全部并发轮次均为完整成功、全部为许可
拒绝或只观察到其中两类，只要逐轮形状合法，矩阵仍通过；未出现的状态和不能定位的内部
窗口必须保留为未覆盖，不得用 `NOT-OBSERVED` 文本替代实际计数和边界说明。

## 5. 受影响文字的统一替换

v0.1 第 2.2 节“任一次漂移”的当前两投影描述补充为：任一一致投影许可拒绝时也立即
返回 L2 许可拒绝 / 截止0 / 空场景；只有两次都成功才能组合。

v0.1 第 7.1 节补充：登记读取、第一次节点投影、第二次完整投影是同一公开调用链的三个
非阻塞许可点；许可拒绝在任何一点都不自动重试，也不能保留此前取得的节点 / 槽材料。

v0.1 第 7.2 节“历史属性值组无许可拒绝”只描述该 provider 自身，不能覆盖外层关系类型
登记的许可拒绝。历史完整读取仍可在登记前置竞争时返回 L2 许可拒绝 / 截止0 / 空场景；
登记成功后历史夹取的原状态映射不变。

v0.1 第 8 节非成功边界补充：许可拒绝必须零截止、空场景、空变更代次；事实代次漂移
只能回显合同允许的安全实际代次并保持空场景。二者均不是内部不一致。

v0.1 第 9.2 节矩阵后说明与第 11 节完成边界继续保留未观察窗口，但改为按公开结果计数
和“内部窗口未证明”表述。Debug 1—15 的现有输出可作定位参考，不能代替 v0.2 下从头
运行；含 4096 次 `yield` 的运行与其 Release 结果全部不进入最终验证记录的通过证据。
