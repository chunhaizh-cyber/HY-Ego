## 1. 目标与完成条件

按详细设计机械实现自我治理消息 v3、九类唯一分类后路由和线程合法等待。完成必须同时满足：

1. 生产代码中治理消息和任务结果回执不再包含或别名引用 legacy `节点句柄`；
2. 九个消息类型各自使用唯一强类型载荷 alternative，错载荷、零身份、错运行代次/G0具名拒绝；
3. 002-03 九类一一映射到已冻结后继，停止截断；
4. 未实现后继保留原消息和路由目标并返回合法等待/NOT_RUN，同批其它项继续路由；
5. 自我线程不再把所有输入无差别送入 002-04，且没有任务结果可消费时不调用 002-06；
6. 双配置构建与治理专项通过。

## 2. 正式依据和当前事实

- 0050 §3/4/8/9：公开合同使用稳定编码强类型，业务结果必须独立权威读回，合法等待是协议内结果。
- 6340 §7：原始外设报告不能进入治理事实，只有任务域正式承接材料可以后继消费。
- 8100、8200：自我线程只消费不可变治理批次，任务结果后才能重判需求，支持旁路不写业务事实。
- `BIZ-L2-002-03 v0.3`与`002-04 v0.2`；详细设计 `RUNTIME-GOVERNANCE-INPUT-V3-ROUTING v0.1`。
- 当前六个代码 blob依次为：`633ed50c`、`1b01e113`、`fb653ae6`、`2cfa0054`、`38458c40`、`1438a7b2`。S0 必须按正式 Git 重取并确认目标接口未发生语义漂移。

## 4. 禁止范围

- 禁止修改 `协议.任务执行请求.ixx`、L2治理函数骨架、DATA-L1/L2服务、普通应用、任务筹办或任务执行代码；

- 禁止实现或伪造任务实际结果、6340承接事实、002-04/05/06成功；

- 禁止把合法等待改为成功，也禁止因一个未实现类别终止其它类别的路由。

## 5. 实施顺序

1. 将自我治理协议升 v3，建立九个强类型载荷和完整纯值校验/相等函数，删除句柄组及句柄 helper。
2. 将任务结果回执升 v2，改为强类型身份，不再嵌套或推断 legacy 任务执行冻结请求。
3. 机械修复邮箱的同任务索引键、幂等比较和批次值式保存，身份键只能来自强类型任务身份的稳定编码。
4. 在批次路由新增唯一九类后继表和 `复核分类并路由治理批次`；等待项保留原值式输入。
5. 修改自我线程逐项分流；本叶能力表下普通项只形成等待，停止仍优先；零可消费时不得推进批次成功游标。
6. 更新治理端到端测试，删除所有 legacy 句柄构造，覆盖九类和非成功分支。
7. 形成施工/验证记录并运行验证。

## 7. 失败与收口

- 纯编译、自检或局部实现错误在白名单内修复；
- 若公开强类型身份无法从现有模块无环导入，固定模块与最终 ABI 无法按本设计成立，具名退回计划支撑，不得改用裸编码或句柄；
- 若任务结果或 6340 provider 被证明已存在且 ABI 与设计不同，只停止对应后继接线，本叶 v3/路由不扩大；
- 任一验证失败不得声明完成。
