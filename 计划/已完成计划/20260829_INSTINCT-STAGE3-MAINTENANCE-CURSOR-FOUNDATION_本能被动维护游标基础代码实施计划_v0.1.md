## 4. 实施步骤

### S0 当前事实与所有权

核对计划精确 blob、main/HEAD/origin/index、白名单 dirty hunk、工程工具链和知识用途。对三个混合 WIP 文件记录本计划开始前 patch，禁止覆盖。

### S1 DTO 与 owner 服务

新增合同版本、状态、请求、结果、游标事实和完整谓词。实现固定 owner 登记恢复、当前属性槽读取、首次游标建立、新纪元切换、同义恢复和发布后独立读回。owner 建立身份固定为 `0x494E'5354'4355'5253`，本地键限于 `0x0307'1001..101F`。

### S2 普通应用装配

建立唯一 owner 交付，构造唯一服务实例，增加 const / non-const getter。装配失败新增具名结构化状态，不复用其它 owner 失败值。不得公开 L1 服务或写端口。

### S3 启动消费

在本能根锚点成功后构造单调时钟与完整秒服务，读取当前边界；形成幂等请求调用建立 / 恢复，再调用公开读取入口逐字段互证。任一非成功返回具名程序失败阶段，不创建自我线程。不得从循环次数或系统墙钟形成完整秒。

### S4 专项与恢复

专项通过普通应用合法构造和公开服务覆盖首次、恢复、新纪元、拒绝、漂移、同键异义、历史保留和进程重启。禁止测试宏、生产故障注入和私有状态出口。

### S5 记录与发布

施工记录列出函数级知识变更清单；验证记录分账静态、编译、专项、恢复和 NOT_RUN。精确暂存白名单 hunk，cached diff-check，提交树复验，普通推送。

## 5. 失败收口

- 计划 / 接口漂移：只停止受影响切片，保留现场。
- 纯编译或实现错误：在白名单内修复。
- 同 owner 同键异义、同纪元边界变化或版本漂移：结构化拒绝，零写入。
- 发布后读回不完整：返回 `已可能发布`，只用原完整请求重放。
- 持久恢复无法证明完整当前槽：装配 / 读取失败，不扫描历史最大值补当前。
- 混合 WIP 文件发生新异主重叠：停止该文件 hunk，不扩大到全仓。
