## 1. 目标、范围与完成条件

现行 L1 公开 `提交中性写集` 允许任何持有 `L1事实基座服务&` 的调用者提交结构合法写集；写请求、节点 / 关系 / 值事实和公开读取均没有机器可验证的结构所有者来源。关系类型编码、自环、名称、本地键、私有缓存或模块约定因此都不能证明 0050 要求的“合法写入方”。

本治理叶在不引入业务授权、业务见证、第二事实仓或持久 token 的前提下，修订 L1 正式规范，冻结一套新的具名 `L1所有者范围CRUD` 合同：

```text
同一 L1 实例内的持久结构所有者事实
+ 只由该实例唯一装配期签发器建立 / 重入 / 退出
+ 与实例、所有者范围绑定且公开不可构造的 move-only 写端口
+ 由端口隐式注入的事实所有者来源
+ 节点 / 关系 / 值 / 属性槽变更 / 退出的逐项所有权校验
+ owner-aware 当前 / 历史 / 一致投影
+ 与旧 v1 明确隔离的幂等、拒绝和迁移边界
```

本叶只治理正式规范，不写生产代码、工程、验证程序、施工 / 验证记录，不恢复暂停的 G2、T1、DYN2 或 A1。治理实施完成条件固定为：

2. 结构所有者身份成为同一 L1 内存已发布代次中的技术机器事实；它不是业务主体、业务资格、领域见证、服务名称或运行期 token；

## 3. 最终事实模型与所有权规则

### 3.1 同仓技术所有者事实

L1 仍只有一个 `仓库.L1事实基座`、一个内存状态、一个全局稳定编码空间、一个事实代次和一个原子发布点。新增的 `L1结构所有者事实` 是同一仓库、同一代次、同一永久编码占用中的技术治理事实，不得实现为第二仓、缓存、SQL 权威、名称表或模块静态变量。

共同强类型和事实固定为：

```text
L1结构所有者身份：内部只承载一个非零稳定编码，不可由调用方指定。

L1所有者范围种类：
  旧共享范围=1
  独占结构范围=2

L1结构所有者事实：
  所有者身份
  范围种类
  创建事实代次
  可选退出事实代次
```

`旧共享范围` 只标记 v1 兼容写入口的共同来源，明确不证明唯一结构服务；`独占结构范围` 才能绑定一个 owner-scoped 写端口。所有者事实不是节点、关系或值，不取得业务对象解释；它与三类数据事实共仓，不建立业务树、关系拓扑或属性槽。

owner-aware 三类事实新建独立 DTO 身份：

```text
L1所有者范围节点事实 = v1 节点全部字段 + 写入所有者
L1所有者范围关系事实 = v1 关系全部字段 + 写入所有者
L1所有者范围值事实   = v1 值全部字段 + 写入所有者
```

内部 `节点事实`、`关系事实`、`值事实` 同样保存非零 `写入所有者`。现有 v1 读取 DTO 保持原字段形状，只作 legacy 投影，不静默加字段。

### 3.2 各写项的所有权

owner-scoped 端口提交时，owner 不由请求 DTO 传入，而由端口隐式绑定；仓库在候选前执行：

| 写项 | owner 绑定与允许引用 |
| --- | --- |
| 新节点 | 新节点事实 `写入所有者 = 端口所有者`；普通请求不得新建所有者事实 |
| 新关系 | 新关系事实 `写入所有者 = 端口所有者`；关系类型节点必须当前且 `写入所有者 = 端口所有者`；源 / 目标允许跨 owner，只作引用，不转移端点所有权 |
| 新值 | 新值事实 `写入所有者 = 端口所有者`；所属节点与属性类型节点必须当前且均由端口所有者拥有；来源节点可跨 owner，只作来源引用 |
| 属性槽变更 | 所属节点、属性类型和新当前值必须均由端口所有者拥有；槽 owner 唯一继承所属节点，不建立第二槽 owner 字段或第二槽表 |
| 退出事实 | 每个被退出节点 / 关系 / 值必须由端口所有者拥有；混 owner、owner 不符或包含所有者事实均在候选前拒绝 |

引用闭包继续负责“是否仍有当前关系 / 值引用”；它不能替代 owner 校验。端口无权退出其它 owner 的事实，即使调用方给出的退出闭包在结构上完整。

关系类型节点的普通稳定编码、名称、本地键或被某条关系引用都不授予权限。只有“该类型节点 owner 等于端口 owner + 仓库验证端口有效”共同成立时才能创建该类型关系。身份来源自环若未来恢复设计，还必须逐项证明：节点 owner、关系 owner、关系类型节点 owner 和 provider 端口 owner 四者相同；自环本身不证明写入方。

### 3.3 owner 不可原地替换

三类事实的 `写入所有者` 与稳定编码、类型、端点 / 材料和创建代次共同不可变；不得原地换 owner、复制 owner、从关系形状反推 owner，或把一个 owner 的事实重新标为另一个 owner 当前事实。

owner 退出只由签发管理面执行，并要求：无活动写端口、无该 owner 当前节点 / 关系 / 值、无当前幂等提交待收敛、无恢复 / 审计所需引用。退出保留完整历史；owner 稳定编码永久占用，不得复活或发给另一服务。

## 4. 信任根、签发与运行期能力

### 4.1 唯一 L1 实例运行包

后继 provider 必须在 `海中鱼巣.核心.服务.L1事实基座` 中建立 move-only `L1事实基座运行包`。唯一工厂 `建立L1事实基座运行包()` 每次只创建一个全新、彼此隔离的 L1 实例，并同时创建恰一个与该实例内部状态绑定的 `L1所有者范围签发器`。

固定边界：

- `L1事实基座服务` 不再允许 public 默认构造；普通服务引用不能创建签发器；
- 工厂可以被测试用于建立独立 L1 实例，但任何新工厂结果都不能签发既有生产 L1 实例的端口；
- `普通应用上下文` 后继只拥有一个运行包，签发器只在装配期由上下文持有；领域 / 结构服务只得到 const L1 读取服务和一份已签发写端口；
- “端口不可伪造”不禁止外部调用者通过公开 L2 工厂合法构造 / 取得对应 L2 服务并调用其公开 CRUD。后继各族公开工厂只能返回已由装配面绑定正确 owner 端口的合法服务；raw `L1所有者范围写端口`、owner 选择、签发器和“按 owner 重建服务”的入口均不得导出；
- 不按服务 enum、名称、关系类型编码或 owner 稳定编码公开“领取端口”；任何调用者不能为既有 owner 请求第二端口；
- owner 注册幂等身份只用于签发器内部的确定重放，不是权限；没有精确实例签发器时，同一数值无效。

### 4.2 签发器与写端口生命周期

`L1所有者范围签发器` 和 `L1所有者范围写端口` 都禁止复制。签发器绑定精确 L1 实例且不允许脱离运行包；写端口可移动一次以注入唯一服务实例，移动源立即失效，服务不公开取回、复制或转签入口。

签发器职责固定为：

1. `建立所有者范围`：以新具名幂等请求在同一 L1 事实事务中创建一个 `独占结构范围` 所有者事实，返回事实和唯一活动端口；
2. `重新签发所有者范围写端口`：只在恢复 / 明确重入路径、目标 owner 当前、属于同一 L1 实例且当前没有活动端口时重新签发；它不创建新 owner、不改变历史；
3. `退出所有者范围`：端口已经失效且全部当前事实闭合后，使 owner 事实退出；
4. 跟踪“同一 L1 实例 + 同一 owner 至多一个活动端口”。重复签发返回 `许可拒绝`，不返回第二能力。

写端口绑定：精确 L1 实例内部身份、owner 身份和不可公开构造的运行期租约。租约 / nonce / 指针 / 内部句柄不得出现在请求 DTO、事实、幂等账、审计、SQL、恢复材料、日志或界面中。端口析构、移动源、owner 退出或 L1 实例销毁后失效；失效端口提交固定 `许可拒绝`、零变化。

重启 / 恢复只持久化 owner 事实和三类事实中的 owner 身份，不持久化端口。恢复材料经 4070 在同一 L1 实例重建并发布后，装配期签发器按具名重入请求、当前 owner 事实和“无活动端口”重新交付能力；SQL 行、缓存、名称或旧 token 不能重建能力。当前阶段不实现恢复管理面，但正式合同必须保留此边界。

## 6. 事务、幂等、读取与错误

### 6.1 原子事务和幂等域

owner 建立 / 退出与普通 owner-scoped 写都使用同一仓库、同一事务域许可、同一候选 / 确认 / 逆序撤销和同一代次最后发布，不建立旁路 owner 表提交。

普通 owner 写的规范化幂等身份为：

```text
(L1实例内部身份, owner稳定身份, L1所有者范围写入幂等身份)
```

同 owner 同键同完整新合同写集返回首次结果；同 owner 同键异写集返回幂等冲突；不同 owner 的相同数值键互不复用。端口 / nonce 不进入幂等语义，因此恢复后同 owner 新端口可以用原请求收敛未知发布。v1 幂等账保留原身份域，与新合同不碰撞或互相返回精确重复。

owner 建立也有独立幂等域：同一实例签发器、同键同义返回同一 owner 事实；已有活动端口时只回显 owner 事实并返回 `许可拒绝`，绝不交付第二端口。同键异义冲突；调用另一 L1 实例的相同数值键只属于另一实例。

所有权、端口有效性、owner 当前性、关系类型 owner、所属节点 / 属性类型 owner 和退出项 owner 必须在取得事务域独占许可后、第一笔候选前针对同一代次最终复核。任一失败零候选、零代次推进。

### 6.2 当前与历史读回

owner-aware 当前读返回三类事实的 owner 字段；历史读返回事实完整创建 / 退出生命周期和不可变 owner。当前 / 历史 owner 事实使用独立具名入口。owner-aware 一致当前投影中节点、关系、值、属性槽、关系组、owner 事实与结果头共享一个非零截止；不允许用 v1 投影、私有登记或当前 owner 补历史缺项。

成功写后必须以新 owner-aware 入口从首次代次读回：全部新事实 owner 等于端口 owner，关系类型 / 所属节点 / 属性类型 owner 约束成立，退出事实 owner 不变。v1 读取可以继续返回旧字段投影，但不能作为新 owner 证明或 provider 验收。

### 6.3 状态分账

新合同至少分账：

```text
成功 / 精确重复 / 已读取
入口拒绝
许可拒绝
未找到 / 已退出
属性未设置
事实代次漂移
幂等冲突
引用冲突
资源失败
内部不一致
```

- 非法合同、零身份、坏请求形状：`入口拒绝`；
- 端口失效 / 跨实例、owner 已退出、第二活动端口、writer owner 与关系类型 / 所属 / 属性类型 / 退出事实 owner 不符：`许可拒绝`；
- 目标编码未占用 / 已退出：`未找到 / 已退出`，但不能覆盖 owner 不符；
- 期望代次不符：`事实代次漂移`；
- 同键异义：`幂等冲突`；
- owner 正确但外部当前引用未闭合：`引用冲突`；
- 已通过前置后 owner 事实缺失、owner 复义、同一事实 owner 读回变化、活动端口计数矛盾或发布半结构：`内部不一致`并停止依赖路径。

现行 v1 状态枚举没有 `许可拒绝`。v1 触碰任何独占 owner 事实、独占关系类型、独占节点属性槽或独占退出项时固定映射 `入口拒绝`、零变化；不能静默映射为未找到、精确重复或资源失败。新合同才返回精确 `许可拒绝`。

## 7. v1 共存、不可伪造窗口与迁移

### 7.1 v1 legacy 隔离

后继 owner provider 首次进入 main 时不能让 18 个正式调用点全部退化，因此旧 `提交中性写集(v1)` 暂时保留原 DTO、函数名、幂等和成功行为。仓库为所有 v1 新事实隐式绑定同一 `旧共享范围` owner；该 owner 首次需要时与首笔 v1 数据在同一代次内部建立，v1 不返回、指定或控制其编码。

v1 写入规则固定为：

1. 只能创建 `旧共享范围` 节点、关系和值；只能使用 legacy owner 的关系类型 / 属性类型；
2. 只能修改 legacy owner 节点的属性槽；
3. 只能退出 legacy owner 三类事实；
4. 任一独占 owner 事实 / 类型进入写集，在候选前 `入口拒绝`；
5. v1 可以按原读取合同看到 legacy 投影，但其 DTO 不含 owner，不能被新 provider 作为 owner 证明；
6. 新 owner-aware 读取会如实回显 legacy owner 和 `旧共享范围`，任何要求唯一写入方的 provider 固定拒绝。

因此，旧入口即使知道新关系类型稳定编码，也不能用它创建同型关系；即使创建自己的 legacy 自环，也因节点、关系、类型 owner 与目标 provider owner 不同而不能被新身份读取接受。引用保护只负责外部引用闭包，所有权校验独立阻止 v1 修改 / 退出独占 owner 事实。

### 7.2 调用者迁移顺序

后继代码路线固定为：

```text
本治理计划实施并退出
-> L1-OWNER-P1：实现 owner 事实、运行包 / 签发器 / 写端口、新具名 CRUD、v1 隔离和 owner 黑盒验证
-> 逐结构迁移正式写入调用者；一次只迁一个唯一结构 owner
   - 存在 provider（与后继 E-ID 合并裁决）
   - 特征 provider（与后继 F-ID 合并裁决，并回归存在 wrong-family）
   - 状态首次正式实现直接使用新端口；T1 草稿不迁移
   - 动态 / 因果首次正式实现直接使用新端口
   - 场景 provider；同时删除两处临时 `L2存在结构服务{L1}`，改注入唯一存在公开服务
   - `L1自我结构登记服务` 独立迁移
-> 全部正式生产 v1 提交调用归零后，另立 v1 写入口退役计划
```

每个迁移 provider 必须同时冻结该族公开服务取得路径：外部调用者可从公开工厂取得合法服务并调用 CRUD；工厂内部消费装配面签发的唯一端口，公开面不暴露 raw 端口或 owner 选择。此要求是能力边界，不等于本计划授权提前实现 A1 生产装配。

具体顺序仍须由当时顶层路线、依赖和所有权重新 S0；本列表冻结完整调用闭包和必需迁移，不授权本轮创建任何 provider 代码计划。

### 7.3 legacy 数据策略

现存 v1 节点 / 关系 / 值不原地 adoption：

- 不扫描 L1 全仓猜 owner；
- 不按形状、名称、本地键、历史调用模块、关系类型编码或缓存把 legacy 编码标给新 owner；
- 不修改原稳定编码、创建代次、退出代次或幂等账；
- 新 provider 默认从正式入口创建 owner-scoped 新事实和新稳定编码；
- 需要退出旧事实时，另行具名迁移 / 清理计划用原 v1 完整请求和 legacy owner 规则显式闭合，之后才可退役 v1 写入口；
- 如果未来存在必须保留稳定编码的持久存量，必须另建 owner adoption 正式规范、隔离材料、原写入方证据和原子迁移合同；在该合同形成前一律拒绝，不能由 provider 临场实现。

这条策略保证新 owner 身份没有“旧事实被 v1 继续改写”的窗口：legacy 事实从未取得新 owner；新 owner 事实从创建开始即拒绝 v1 修改和退出。

本治理实施退出后，下一最早代码缺口 `L1-OWNER-P1` 必须另建一份代码计划，并至少冻结 / 验证：

1. 一个工厂结果只有一个 L1 实例和一个签发器；另一工厂不能为前一实例签发；普通 `L1事实基座服务&` 不能取得签发器；
2. 两个独占 owner 建立取得不同稳定编码、同键同义收敛、同键异义冲突；同 owner 至多一个活动端口；
3. 写端口不可复制，移动后源失效；跨实例、析构后、owner 退出后和第二活动端口均许可拒绝、零推进；
4. 新节点 owner 自动绑定；请求中不存在可篡改 owner 字段；当前 / 历史 owner-aware 读回一致；
5. 关系类型 owner 等于端口 owner 时允许关系创建；源 / 目标跨 owner 合法；错 owner 类型、v1 使用独占类型均拒绝；
6. 新值的所属节点 / 属性类型 / 新值 owner 相等，来源可跨 owner；错 owner 值和属性槽变更拒绝；
7. 退出混 owner、v1 退出独占事实、独占端口退出别的 owner 事实均拒绝；同 owner 但外部引用未闭合才进入引用冲突；
8. owner-scoped 同键同写集精确重复、同键异写集冲突、不同 owner 同数值键互不复用；未知发布以同 owner 新合法端口和原请求收敛；
9. owner 当前 / 历史、事实当前 / 历史、关系组、属性值组和一致投影全部回显同截止 owner；任何混 owner 或 owner 复义为内部不一致；
10. v1 现有代表性创建 / 关系 / 值 / 属性 / 退出回归保持原 DTO 和行为，事实只落 legacy owner；v1 不能制造任何会被新 owner provider 接受的类型、关系、值或退出；
11. legacy 事实不能通过新端口原地改 owner；没有具名迁移合同则拒绝保码 adoption；
12. owner 退出需要端口失效、当前事实归零和引用闭合；退出前历史仍可读、owner 不复活；
13. 恢复材料静态合同包含 owner / 幂等域但不包含 token；当前 provider 不伪装已实现恢复；
14. `rg` 证明生产事实 / DTO / 记录零 token、nonce、地址、模块名、服务 enum、名称推断、第二仓和测试专用权限；
15. L1 核心零六类 L2 反向 import / friend / enum 分支；代表性公开 L2 工厂允许普通外部调用者取得合法服务并调用 CRUD，同时编译期 / 黑盒证明其不能取得 raw 端口、指定 owner、重复领端口或绕过服务制造该族可接受事实；
16. Debug / Release x64 主工程、具名双配置黑盒矩阵、strict、UTF-8 / 工程隔离和真实当前 / 历史终态通过；未运行恢复、生产 L2 装配或上层业务时如实声明。

provider 计划必须以当时真实模块 ABI、工程登记、调用点和构造链重新 S0；本治理计划不得被直接交给执行智能体写代码。
