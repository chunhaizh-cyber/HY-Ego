# DATA-L1-N-PARTITION-ATOMIC-V3 代码实施计划

## 1. 目标与依赖

目标：实现有限 `2..255` 个中性结构分区在同一 L1 实例中共同发布一个事实代次的 v3 原子事务，为本能路线阶段三的维护 / 合同 / 特征 / 状态 / 动态联合写集提供中性底座。

直接依赖：`DATA-L1-THREE-PARTITION-ATOMIC-V2` 已发布结果、4015 v2.2、4040 v1.8，以及同名详细设计 v0.1。v1/v2 行为不得改变。

## 2. 完成条件

1. v3 DTO、固定数值、写端口入口、仓库入口和格式3恢复与详细设计逐字段一致。
2. N 份写集在一个私有候选中按身份顺序应用，全部临时代次和首次账归一为共同 G1 后一次交换。
3. v3 独立幂等 / 持久账、同义重放、异义冲突、已可能发布和格式1/2兼容闭合。
4. 2/3/4/8/255 正常矩阵、非法 N / 端口 / 身份 / 引用 / owner / 幂等 / G0 矩阵取得正式读回证据。
5. v1/v2 回归、Debug/Release、ABI consumer、strict、cached diff-check 通过；无法取得的旧格式样本明确 NOT_RUN。
6. 代码、专属施工 / 验证记录精确提交并普通推送；不得宣称阶段三业务完成。

## 3. 允许范围

生产白名单和可选编译闭包严格等于详细设计第8节。专项只新增同节第6—10项。禁止修改 L2、普通应用、启动、线程、本能根、阶段二专项、正式规范、详细设计、路线和计划索引。

共享 `海中鱼巣.vcxproj`、`海中鱼巣.vcxproj.filters` 当前含异主 WIP；只允许加入新专项模块的精确 hunk，发布时不得整文件暂存。

## 4. 实施步骤

### S0

- 核对 main、HEAD/origin、index、计划 blob、dirty 所有者和 Git 租约。
- 重读 v2 DTO、服务入口、仓库事务、持久编码/解码/完整性检查和当前函数用途知识；源码新于知识时以源码及调用点为准。

### S1 DTO 与服务入口

- 增加 v3 顶层请求 / 状态 / 结果和中性写项 alias。
- 写端口入口验证 N、端口数量、空 / 重复 / 跨实例 / 失效和 owner 逐项绑定，然后唯一调用仓库 v3。

### S2 仓库事务

- 从 v2 算法机械提取可变 N 实现，不修改 v2 函数。
- 将固定 array / 上界 / 临时代次处理改为有界 vector 和 N 循环。
- 规范化、引用检查、候选顺序应用、全局闭包、共同 G1、首次账和结果逐项互证全部覆盖 N。

### S3 持久恢复

- 新增 v3 组合账及稳定编码/解码；内部格式升3并保留格式1/2解码。
- v3 使用专属顶层账编解码，逐字段复用中性写项布局但不得调用或放宽 v2 的 `1..3` 参与者解码守卫。
- 扩展状态完整性验证，拒绝非规范 v3 账和坏请求结果配对。

### S4 专项与记录

- 新增公开端口 consumer 专项，禁止 friend 仓库和内存地址断言。
- 形成施工记录中的函数级知识变更清单，验证记录逐项列矩阵、命令、结果与 NOT_RUN。

### S5 发布

- 精确暂存白名单，执行提交树构建和专项；普通推送结果提交。
- 由当前目标模式核验后退出本计划并立即形成阶段三业务计划。

## 5. 失败收口

- 纯代码 / 编译错误在白名单内修复。
- v2 持久格式或恢复事实与设计不一致：停止受影响实现并修订本计划，不改写旧账。
- 异主 WIP：保留现场，使用精确 hunk；不能分离时只暂停重叠文件。
- 交换后不确定：只返回已可能发布并用原 v3 请求收敛，不生成新键。

## 6. 验证命令与边界

最低验证：

```powershell
git diff --check
python .\tools\check_specs.py --strict
MSBuild.exe .\海中鱼巣.vcxproj /t:Rebuild /p:Configuration=Debug /p:Platform=x64 /p:PlatformToolset=v143
MSBuild.exe .\海中鱼巣.vcxproj /t:Rebuild /p:Configuration=Release /p:Platform=x64 /p:PlatformToolset=v143
```

再运行专属专项和 ABI consumer。编译不等于运行，provider 专项不等于阶段三合法业务 consumer，提交 / 推送不等于本能路线完成。
