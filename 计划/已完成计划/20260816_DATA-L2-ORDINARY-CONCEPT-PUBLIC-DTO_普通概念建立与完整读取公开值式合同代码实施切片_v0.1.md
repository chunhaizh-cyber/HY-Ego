## 3. 实施合同

1. 严格按详细设计字段顺序、默认值、枚举数值、`final` 和相等合同实现全部类型。
2. 世界关系 helper 必须按 13 类闭集校验 variant 端点方向；因果动作只能使用独立强类型 `L2概念动作引用` 包裹现行非零动作稳定编码，不得猜成方法身份；定义目标只接受非零强类型身份或完整关系引用。
3. 建立请求必须校验非零期望代次 / 幂等 / 根 / 材料；值式项与定义项分别允许空组，但联合键必须唯一且组内严格排序；直接上位和来源证据非空、严格排序且无零值。
4. 每项概念自有事实必须显式携带所属概念；完整事实逐项校验概念一致性、稳定编码、排序、生命周期和治理状态闭集，只做纯值校验，不把材料 / 根 / DAG / 世界事实存在性伪装为已证明。
5. 写成功额外固定首次治理状态为活跃和全部初始事实当前；当前读取允许活跃 / 冷却 / 退役但要求全部当前事实未退出；历史读取允许返回截止内已经退出的完整事实。写 / 读成功 helper 与详细设计形状一致；全部非成功空负载零变更。
6. 工程与 filters 各唯一登记新头，不引入新模块、库或工程配置。
