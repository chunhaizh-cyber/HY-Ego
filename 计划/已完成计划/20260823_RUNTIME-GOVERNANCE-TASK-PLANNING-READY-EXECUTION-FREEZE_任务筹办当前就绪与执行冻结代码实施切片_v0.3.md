## 4. 实施顺序

### S1 DATA DTO 联合化

按详细设计 §4 实现：

- `L2任务重筹办意图幂等身份`；
- `L2任务筹办来源幂等身份` variant；
- `L2任务筹办归因证据引用` variant；
- 初次 / 重筹办两份规范化来源结构及总 variant；
- 选择记录的`原筹办来源幂等身份`；
- 初次稳定证据类别；
- 冻结归因证据联合；
- `按筹办来源幂等身份读取正式选择`请求 / 结果。

全部中文命名；DATA-L2 零引用 BIZ DTO。

### S2 owner 初次 / 重筹办分支

保持一个`发布任务筹办正式选择`函数。公共校验后以`std::visit`或等价穷尽分支：

- 初次：公开读回首次记录与当前事实，证明轮次 1、成员当前、旧当前三项为空；同写集只创建新结构；
- 重筹办：保持十三项与旧事实互证；同写集退出旧当前三项后创建新结构；
- 两分支共用类型登记、首次账、路径拓扑派生、提交、正式读回与未知发布恢复；
- 不允许默认 visitor、遗漏分支后补成功、跨分支比较裸数值键。

### S3 Stage C 重筹办机械适配

现有 provider 仍接收`下一筹办工作包`，只构造重筹办联合分支；线程和冻结请求继续携带原工作包。改名和类型适配不得引入初次 BIZ 分支，也不得改动第一阶段 lookup。

### S4 五处测试 bootstrap 迁移

实时定位设计锚点 1339、3189、4976、6062、6523 附近的五处旧入口。每处必须走：

```text
正式初次准备
-> 公开读取首次记录 / 任务身份来源
-> 正式方法生命周期
-> task owner 初次来源发布
-> 正式读回
-> 实际结果
-> 目标未达成 / 待重筹办
-> 下一筹办工作包
-> Stage C
```

不允许共享一个隐式全局夹具掩盖逐案前置，不允许调用私有 owner 写口，不允许伪造旧结果。

### S5 记录、验证与发布

施工记录必须列出联合类型、owner 两分支、调用边、五处迁移、知识变更清单和未实现的普通初次 BIZ provider。验证记录逐项写 PASS / FAIL / NOT_RUN，不用总数替代矩阵。

## 5. 幂等与事务硬门禁

1. 初次记录身份与重筹办数值键属于不同 variant 分支，不得串账；
2. 同来源键、同分支、同完整请求精确重复；任一变化冲突；
3. 初次旧当前选择 / 路径 / 实例必须全空，结果旧三项也全空；
4. 重筹办旧三项必须完整且同代退出；
5. 初次新筹办轮次 / 新执行轮次均为 1；重筹办新执行轮次为旧值加一；
6. 初次稳定证据与归因只接受首次记录；重筹办只接受目标裁决 / 治理状态；
7. 发布未知只能原键、原分支、原完整请求恢复；
8. 新本地键只进入合法关系端点，路径四项继续发布后派生；
9. 不恢复`发布当前选中路径`，不增加第二 owner 入口或第二事务；
10. 结果可共用 / 争用分配优先级不进入任何选择请求或测试 bootstrap。

## 8. DRIFT 与停止条件

仅在以下情况具名退回计划支撑：

- 初次当前性或旧当前三项为空无法由现有 task owner 公开事实唯一证明；
- 必须修改禁止文件或新增普通初次 BIZ provider 才能实现 owner 分支；
- variant 会破坏现有持久 ABI 且无法在白名单内迁移；
- 必须恢复第二入口、第二事务或伪旧结果；
- v0.2 / v0.3 的正式规范与当前代码存在会改变机器语义的冲突；
- 必需验证持续失败且无法在白名单内归因。

普通编译适配、字段改名和五处夹具迁移由执行侧在白名单内完成，不是 DRIFT。
