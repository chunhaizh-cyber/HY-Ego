# INSTANCE-FEATURE-IFR-L2-PROJECTION-READ 代码实施计划 v0.2

状态：已完成。代码与验证记录：`12e678f7`、`664e1fe7`、`0c326f0a`；直接依赖 `8d79cf4f` 的 v2 IF/R 布局。

## 目标

在 `存在类数据服务` 实现 IF/R 的同截止完整只读投影 `读取IFR结构`，供后续目标提交和 L3 分类使用。它只读取存在 owner 已有事实，不创建、退出或改写节点、关系、值、属性槽或当前采用。

## 冻结合同

新增纯值 DTO：节点/关系时态、R项身份及投影、完整 IF/R 投影、读取请求/结果。请求固定 `{版本=1,Gread,E,FT,F成员上限,R项上限,关系上限}`；成功为 `已读取`，要求 `Gread=H=请求Gread`、完整形状、关系和成员预算均未超。未找到、已退出、数量预算不足、事实代次漂移、引用冲突、资源失败、内部不一致均清空投影。

读取顺序固定：同截止核验 E；唯一 `E→IF`；IF 的成员 F 和唯一 `IF→R集合`；R集合的唯一当前 `R集合→版本`；版本的 R项；每项唯一材料属性槽和唯一材料值、R项形成成员。所有节点、关系和值必须属于存在 owner、类型/方向正确且在 H 活动。

关系 `角色或顺序` 是完整投影的一部分，读取必须逐条核验并以固定顺序回显：

1. 唯一 `E→IF`、唯一 `IF→R集合`、唯一 `R集合→版本` 的 `角色或顺序` 均为 `1`。
2. `IF→F` 先按目标 F 的稳定编码严格升序排列；第 `i` 条关系的 `角色或顺序` 必须恰为 `i`（从 `1` 起）。
3. `版本→R项` 先按目标 R项的稳定编码严格升序排列；第 `i` 条关系的 `角色或顺序` 必须恰为 `i`。投影中的 R项沿此顺序排列。
4. 每个 `R项→F` 先按目标 F 的稳定编码严格升序排列；第 `i` 条关系的 `角色或顺序` 必须恰为 `i`。投影中的形成成员沿此顺序排列。

上述任一数量、顺序或角色偏离都是 `引用冲突`，不得由底层返回顺序补正。所有形成成员的并集恰等 IF 成员 F。

每个 R项的材料属性值必须唯一、使用 v2 `R项材料属性类型` 的 U64组，且值的来源节点恰为该 R项自身；来源节点偏离、属性类型错误或多值均为 `引用冲突`。其 U64组必须能反序列化为规范化 `特征R区间材料`，否则为 `内部不一致`。
