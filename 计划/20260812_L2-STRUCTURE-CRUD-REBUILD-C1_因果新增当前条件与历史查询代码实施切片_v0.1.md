## 6. 新增因果的一份同代次写集

本地键固定：

```text
因果节点本地键       = 0x0206'1001U
因果族归属关系本地键 = 0x0206'1002U
条件关系本地键基值   = 0x0206'2000U + 项序号(1..n)
动作关系本地键       = 0x0206'3001U
结果关系本地键基值   = 0x0206'4000U + 项序号(1..n)
来源值本地键         = 0x0206'5001U
```

条件 / 结果单组项数各不得超过 `0x0FFF`，防止本地键域重叠；超过为入口拒绝。项序号只用于本写集本地键，关系的 `角色或顺序` 精确使用请求 `L2有序身份引用::顺序`。族归属角色固定 1，动作关系角色固定 1。

流程固定为：

```text
纯值校验 -> 读取当前因果结构登记 -> 形成完整不可变写集
-> 探测当前事实代次
-> 代次不同：恰一次直提原写集，让 L1 先裁决重复 / 冲突 / 漂移
-> 代次相同：逐项读取状态身份来源(当前)
-> 若有动作，以同一期望一次一致当前投影证明当前普通节点
-> 恰一次 owner-scoped 提交
-> 从首次代次历史来源、节点、关系、属性值和端点重建首次结果
```

写集固定为：

```text
节点 = [{因果节点本地键, 普通}]
关系 = [
  {族归属本地键, 源=因果节点, 目标=因果族锚点,
   类型=族归属关系类型, 角色=1},
  每个条件项 {条件本地键, 源=因果节点, 目标=项.目标,
               类型=条件关系类型, 角色=项.顺序},
  可选动作 {动作本地键, 源=因果节点, 目标=动作,
             类型=动作关系类型, 角色=1},
  每个结果项 {结果本地键, 源=因果节点, 目标=项.目标,
               类型=结果关系类型, 角色=项.顺序}
]
值 = [{来源值本地键, 所属=因果节点,
       类型=来源属性类型,
       材料=L2独立材料引用{来源}, 来源=来源}]
属性槽变更 = [{因果节点, 来源属性类型, 来源值本地键}]
退出事实 = []
```

节点、族归属、全部角色关系、来源值和槽在同一事实代次发布。来源不能等于新建因果本地节点，因为请求只接受既有稳定编码；动作 / 来源仍被 L1 引用闭包保护。C1 不要求动作等于方法或动态，不要求来源等于动作、状态、动态或证据。

成功 / 精确重复必须取得全部本地键的一一非零唯一映射。首次历史读回证明因果节点与族归属、全部条件 / 动作 / 结果关系、来源值同创建代次，关系端点 / 类型 / 顺序、来源材料和值来源精确匹配；以首次事实代次为历史截止逐项调用 `读取状态身份来源(历史)`。任一缺项、多项、错端点、错顺序、错类型、错来源或混代返回内部不一致，不二次提交。

## 7. 当前 / 历史完整读取

当前读取先取得登记，用一次 owner-aware 一致当前投影读取因果 owner、因果节点、锚点、归属类型、唯一归属关系、三类源关系组和来源属性值。要求：

- 因果身份来源完整；条件 / 结果关系组非空，动作关系组 0 或 1；
- 关系源均为因果，类型匹配；条件 / 结果角色为正，投影按 `(角色, 目标)` 严格升序无重复；动作角色 1；
- 来源槽唯一，值所属因果、类型为来源属性、材料是与值来源相同的非零独立材料引用；
- 以同一期望逐项调用 `读取状态身份来源(当前)`，并对可选动作 / 来源用 L1 当前事实证明可引用；
- 再读取同一因果投影，前后逐字段相等且截止等于请求期望。

历史读取固定为：

```text
读取当前代次并等于请求期望
-> 读取因果 owner / 节点 / 锚点 / 类型历史
-> 按因果为源读取归属、条件、动作、结果历史关系组(历史截止)
-> 读取因果历史属性值组(历史截止)
-> 逐项读取状态身份来源(历史截止)
-> 读取动作 / 来源历史事实
-> 再读当前代次并等于请求期望
-> 重建截止投影，隐藏晚于截止的未来退出
```

创建前返回未找到；当前入口已退出返回已退出；C1 未实现退出，因此首次实现的合法因果在创建及之后截止应完整。历史不得以当前关系、槽、状态、动作或来源补项。身份来源、关系、属性、端点或生命周期矛盾返回内部不一致；两次代次变化返回漂移；非成功载荷为空。

## 8. 三类当前条件查询

按条件 / 结果状态查询先调用 `读取状态身份来源(当前)` 验证请求端点，再以同一期望从对应关系类型的目标关系组取得源因果。按动作查询先用 L1 一致当前投影证明动作是当前普通节点，再读取动作类型目标关系组。

每条关系类型、目标、角色必须匹配；条件 / 结果角色必须正，动作角色固定 1。对每个唯一源调用 `读取完整因果(当前)`，要求同一截止且完整结果含对应查询项。按因果身份严格升序返回；重复源、关系与单项读回矛盾、部分成功或混代均内部不一致。

三个入口都允许合法空组，不返回“最可能”“最新”“必然”“主动 / 被动”或动作召回结果。空动作因果不会出现在任何动作条件查询中；C1 不提供“按无动作查询”。

## 9. 状态、幂等与异常收口

非成功优先级固定：纯值非法 -> 入口拒绝；登记未加载 -> 入口拒绝；登记其它失败 -> 同名；既有幂等 -> 精确重复 / 幂等冲突；新键旧期望 -> 漂移；条件 / 结果状态未找到、已退出或入口拒绝 -> 同名；动作 / 来源未找到或已退出 -> 同名；许可 / 资源 -> 同名；结构矛盾 -> 内部不一致。

普通 C1 幂等身份完整 64 位原样映射 L1 因果 owner 写域，不进入身份来源或登记私有常量。同键同完整请求返回首次节点、归属、关系、来源值和代次；同键异请求冲突。发布未知只能以原身份、原请求、原期望重提，不得换键或刷新期望。

提交前非成功零普通事实变化且无变更代次。L1 已发布后首次读回分配失败 / 矛盾返回空载荷资源失败 / 内部不一致，可回显安全取得的首次代次；事实已经形成，不得宣称零变化，不补偿回滚，只以原请求收敛。

C1 不增加锁、仓、缓存、索引、SQL、恢复、日志、材料解析器或第二幂等账。来源和动作均为不透明引用。

--条件二顺序 <uint64，默认20>
--结果一顺序 <uint64，默认10>

6. 条件与结果完全相同合法；不做真实性、必然性、主动 / 被动、时间或无环判断；
