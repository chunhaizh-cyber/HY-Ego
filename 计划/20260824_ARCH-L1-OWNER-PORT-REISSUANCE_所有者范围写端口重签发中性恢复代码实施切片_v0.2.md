## 1. 目标与唯一 ABI 裁决

实现 4015 §5.1 的 `L1所有者范围签发器::重新签发所有者范围写端口`。固定返回类型为既有 `L1所有者范围交付`，不得改为 variant、新交付类型或建立结果降装。扩展该 DTO 为：

```cpp
struct L1所有者范围交付 final {
    L1所有者范围建立结果 建立结果{};
    L1所有者范围重入结果 重入结果{};
    std::optional<L1所有者范围写端口> 写入端口;
};
```

字段追加保持所有现有建立消费者读取 `建立结果` 与 `写入端口` 的源码合同不变；本计划不宣称跨编译单元二进制布局兼容，受影响生产文件必须按同一头文件重建。建立函数只填建立结果；重签发函数只填重入结果；端口只有成功时非空，所有非成功为空。

本计划只实现同一 L1 运行包内 owner 当前、独占、建立账互证且无活动端口时的中性重签发，不建立/退出 owner、不发布事实、不推进代次、不产生 G1，不处理崩溃、重启、快照或跨进程恢复。

## 3. 实施步骤与填充规则

1. 数据头仅复用现有重入请求/结果和状态枚举；不新增状态或请求字段。
2. 仓库增加模块内只读 owner/建立账互证辅助：返回安全当前 owner 事实、建立账互证状态和非零当前代次，不暴露仓库、锁、候选或 token。
3. 服务扩展 `L1所有者范围交付` 并新增重签发函数；建立函数现有填充规则零迁移。重签发按“请求守卫→端口锁→仓库管理验证→活动 owner 登记→构造 move-only 端口”执行。
4. 失败映射固定为：参数错误 `入口拒绝`；运行包失效/活动端口 `许可拒绝`；账或 owner 不存在 `未找到`；owner 已退出 `已退出`；范围/账互证错误 `引用冲突`；owner/账异义 `幂等冲突`；零代次/隔离/仓库不变量错误 `内部不一致`；非材料异常 `资源失败`。失败均 `写入端口=nullopt`、零事实变化。
5. 成功只填 `重入结果`，回显完整安全 owner 事实和当前代次，`是否形成内存权威发布=false`，交付唯一端口；不推进事实代次。已有活动端口不返回 `精确重复` 或第二端口。

## 4. 验证矩阵

- DTO 形状：建立函数既有消费者零源码迁移；重签发结果只在 `重入结果`；建立结果保持默认；所有失败端口为空。
- 状态映射：合同/owner/幂等身份错误、运行包失效、owner/账缺失、退出、非独占、账异义、零代次、隔离、活动端口、资源异常。
- 并发与生命周期：不同 owner 可并行；同 owner 重签发与退出互斥；成功端口绑定同实例/owner；移动源、析构、owner 退出、运行包销毁后失效。
- 回归：建立成功/精确重复、退出、普通 owner 写入及既有 L2 建立消费者 ABI 不变；成功不推进代次、不产生 G1。
- 运行门禁：Debug/Release 根工程、`D:\TEMP` 专项、strict、diff-check、UTF-8/no-BOM、生产零专项痕迹。

完成只证明中性端口重签发合同和实现门禁，不证明崩溃/跨进程恢复、快照恢复、L2 G1、L4 消费者或业务闭环。
