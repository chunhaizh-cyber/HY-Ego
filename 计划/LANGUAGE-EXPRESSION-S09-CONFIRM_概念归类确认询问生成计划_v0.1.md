# LANGUAGE-EXPRESSION-S09-CONFIRM 概念归类确认询问生成计划

日期：2026-10-15。版本：v0.1。计划身份：`LANGUAGE-EXPRESSION-S09-CONFIRM`。当前状态只由[计划索引](计划索引.md)维护。

## 1. 目标、依据和前置

在已发布 S02 与特征概念扩展的基础表达入口上，从正式知识生成“X 吗”形态的**概念归类确认询问**：X 仅限两个正式存在概念，或两个同 FT 根的正式特征概念。外层信息请求决定提问目的、范围与“确认主张是否成立”，X 是类型化归类子含义；子规则只借用 S02 的固定措辞与两端角色映射，不把 X 当作已成立陈述。返回完整 UTF-8 文本及顶层/子层规则、词条、名称、标量范围对齐。缺任一正式材料不产生残句。

正式依据：[详细设计](../规范/详细设计/20261015_LANGUAGE-EXPRESSION-S09-CONFIRM_概念归类确认询问详细设计_v0.1.md)、[2340](../规范/2340_根规范_自然语言知识.md)、[7230](../规范/7230_子规范_语言材料知识与交互字段.md)、[7240](../规范/7240_子规范_自然语言双向转换与组织规则.md)、[7250](../规范/7250_子规范_最小汉语知识与语言学习.md)、[7220](../规范/7220_子规范_概念多语种表达与自然语言接入.md)、[代码归属规范](../规范/代码文件建立归属与模块命名规范.md)。设计事实基线 main `ea15dc7f59dd0b6dff6614baa7381731d0484c1a`：S02 和特征概念生成的生产源码已发布，实际项目 Debug|x64 编译链接通过，未运行测试、无生成入口生产调用者。执行前须 S0 核对当前 main/索引 blob、文件与语义所有权、index/dirty、实际调用点及隔离构建资源。

## 2. 唯一切片、公开合同和文件

一个代码所有者负责语言知识 provider、初始化种子及消费函数的共同公开 ABI，不把 DTO、持久字段、种子和生成拆给不同施工切片。允许修改 `海中鱼巣/领域/新_语言类.h/.cpp`、`海中鱼巣/业务/初始化.语言知识.cpp`、`初始化材料/最小语言知识种子.txt`、`海中鱼巣/业务/表达.基础语言.h/.cpp`，并新增专属 `验证记录/20261015_LANGUAGE-EXPRESSION-S09-CONFIRM_施工与编译记录_v0.1.md`。不新建 C++ 文件，不改装配、vcxproj/filters、概念/名称/词/存在 owner、共享知识索引、正式规范、S02 原定义或其它所有者 WIP。只借用现有 `新_存在类::获取存在`验证受询者；若 S0 发现新增生成入口生产调用者或需要改白名单外文件，暂停受影响切片并退回计划支撑修订设计、白名单及索引，发布后重做 S0。

公开合同按详细设计 §2—3 冻结：语言知识追加提问/提问范围/信息请求/确认范围、类型化被询子含义、固定子知识强引用与完整角色映射；原陈述知识在旧字段下保持可读且不改义。表达请求追加受询者、被询操作和确认范围；公开生成函数追加只读存在服务尾参；结果追加受询者和嵌套项来源路径。新字段的缺省/不适用形状须显式拒绝，不用词面、S 标签或默认参数猜出信息请求。

## 3. 施工顺序、非成功和读回

1. 语言 owner 先扩规范化、私有 schema 尾部字段、完整原子发布、查重、已知知识及候选读回、固定词与子知识读回/复核。S09 根信息请求仅有一个归类子含义，子规则仅引用同语言已发布且无子规则的 S02 定义形状；外层角色到子角色完整双射。读回拒绝坏字段、悬空/循环引用、不同语言、错误操作或方向和子知识漂移。旧知识的读取与复用不能回退。锁内不调用词 owner；工程故障和内部不一致分别传递。
2. 初始化元格式只新增详细设计 §3 的 S09 块与受控声明，保留五个旧块；整批先预检标签、依赖、映射和 UTF-8/额度，再按现有词→完整来源→知识顺序发布并逐项读回。S02 正式身份发布/读回后才替换局部标签作为 S09 子规则强引用；重复只读按相同顺序查得身份和完整定义，不以文本标签充当节点。新原文来源与旧定义的来源补充各保留真实阶段，无跨 owner 假回滚。
3. 业务仅在完整匹配 `提问/信息请求/提问范围/概念归类子含义/成立与否` 时消费 S09。核验受询者、同类别概念及特征同根；沿子规则的正式结构和映射复用名称/固定词展开，再展开外层“吗”的正式词条。子规则不作为独立已完成陈述输出。按知识身份和结构路径回传来源对齐，末次复读所用范围与端点，失败清空全部输出载荷。已发布 S02 陈述成功路径不回退。
4. 在本工作树实际项目统一编译链接并记录输入基线。只有用户对本切片明确发出测试/自检/验收指令时，才运行相应实际项目测试；不得把编译或静态检查称为运行通过。

受询者编码无效、概念类别不合或特征跨根为 `输入拒绝`；编码有效而存在内容、概念、子知识或固定词引用不可读为 `引用不可读`。规则零/多分别为 `缺规则`/`多规则待选`，名称零/多为 `缺名称`/`名称待选`，候选或输出超额为 `额度不足`；完整读回变化为 `读取漂移`，资源失败为 `工程未完成`，已存坏结构为 `内部不一致`。现有存在读取的工程异常沿其工程终止链传播，不能由问句生成器降格为不存在。任何非成功均零文本、知识、受询者、绑定与对齐。调用方的归类主张仍是主张，生成器不查询其真假、不建归类事实、不发送问题。

默认验证为 `git diff --check`、精确 staged 差异和实际项目 `msbuild .\海中鱼巣.vcxproj /p:Configuration=Debug /p:Platform=x64 /m` 编译链接；检查生产种子与项目复制输出字节一致、标签依赖及正式链接有效。获本切片测试指令后，优先以实际工程覆盖旧 S02、S09 两端存在概念/同根特征概念、跨根/混合类别、受询者不可读、子规则坏引用或角色交换、名称零/一/多、候选/输出额度、来源与读回漂移；仅报告真实运行项。专属记录写清编译结果、`未运行测试`或实际范围、代码知识变更清单、提交/推送事实及未覆盖风险。
