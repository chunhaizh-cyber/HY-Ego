# INSTANCE-FEATURE-IF-R-CONCEPT-FOUNDATION 代码实施计划 v0.3

状态：待激活。基线：`9f6375c3b899819d0d41cfcac400a8d11cf07292`。

## 目标、已保留现场与唯一门禁

目标仍是实现4115的 `IF(E,FT)`、F成员、R集合版本、I64精确分组及一次同步 R→FCr 概念汇聚；不改变当前采用语义。执行侧复核发现：准确 F 的出生必须同时形成对已发布 FCv 的概念 owner 使用引用，但当前定位特征服务只有特征、存在、场景三个参与者的原子事务，概念 owner 的现有入口只接受已发布 F。因此本计划唯一直接上游依赖是**四 owner 原子特征出生提供者**：概念先独立发布 FCv 后，以特征、存在、场景、概念四个 owner 在同一 G 发布 F内容、holder已知F、P→F 与 F→FCv 使用引用，并可按原键读回。

该提供者尚未设计、实现或发布；它不得由本计划以 L1 ABI 扩展、定位服务越权写概念关系、顺序补写名称/用途，或临时无 FC 的 F 代替。当前 `海中鱼巣/领域/数据服务.存在类.h`、`海中鱼巣/领域/数据服务.特征类.h/.cpp` 与 `海中鱼巣/装配.普通应用.cpp` 中保留的异主低层 WIP 不是已发布能力；跨服务编排、IF/R读写、当前采用变更和汇聚施工已经停止。

## 已冻结的后续施工边界

1. 新的显式入口只属于 `特征概念应用服务`。它在任何 FCv 查询/建立、F定位、IF/R、当前采用或汇聚写前，以同一 `Gread/H` 读取 `E+FT` 的当前采用与 IF/R。读取失败、事实代次漂移、预算不足、退出或不完整必须保留原具名结构化结果并零业务写，不能压缩成结构异常。
2. 只有两类成功读取后的结构可继续：`当前采用为空且IF/R全空`为首次；`IF/R完整且当前采用F同时属于IF成员及当前R成员`为后续。其它可读结构一律返回`结构异常`，并零 FCv、F、IF/R、当前采用和汇聚写。L2存在类只提供中性 IF/R 读回、一次写集与引用/形状/预期快照核验；它不判断首次/后续/结构异常。若写前快照已改变，L2返回具名漂移或引用冲突，零本次写，不重新分类。
3. 结构异常由普通应用私有的 `noexcept` 诊断回调处理，经构造注入特征概念应用服务。回调只使用调用点已持有的最小身份与原因摘要，在所有 L3 mutex 和普通应用上下文锁释放后，尝试一次 `记录逻辑错误日志` 与同因摘要的调用线程 `MessageBoxW`；两者任一失败、异常或未显示均不改变已经固定的结构化结果、零写承诺或线程继续条件。不得启用既有全局容错宏、把日志/UI依赖放入L2，或建立全局诊断体系。该回调只保证尽力同步调用，不保证无窗口或非交互会话中的可见性。
4. 上游提供者发布后，本计划重新 S0；概念应用先取得 FCv，再调用该提供者建立/复用完整 F。仅在完整 F 读回后，L3向存在 owner 提交中性 IF/R 目标写集；R真实变化后才同步尝试一次汇聚。概念汇聚失败保留已发布 R，不写回执、不自动重试或回滚。
