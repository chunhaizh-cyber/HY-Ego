# INSTANCE-FEATURE-IF-R-CONCEPT-FOUNDATION 代码实施计划 v0.9

状态：待激活。v0.9 记录用户已裁决 I64 单点 R 零 FCr 输出；须等待 FEATURE-TYPE-R-I64-NO-FCR-RULE-CORRECTION 发布后重新 S0。

## 目标、已保留现场与唯一门禁

目标仍是实现4115的 `IF(E,FT)`、F成员、R集合版本、I64精确分组及一次同步 R→FCr 概念汇聚；不改变当前采用语义。`ea195241` 已发布 I64 范围内的四 owner 原子准确 F 出生：FCv 先行发布，特征、存在、场景、概念四个 owner 同次发布 F内容、holder已知F、P→F 与 F→FCv 使用引用，并可按原键完整读回。它是本计划可复用的既有提供者，不再构成门禁。

4115 v0.5 已冻结 IF/R 的 L2 读取、目标写入、预算、预期快照、规范化R项组、幂等、原子发布和读回边界，并明确当前采用不参与R归组。本计划的唯一直接上游 `FEATURE-TYPE-R-INTERVAL-RULE-PROVIDER` 已由 `3b474a66eca01a56de6ca167c661eb02c92a5435` 发布：它提供 `候选值+R区间材料*` 的唯一命中/区间更新/代表值读取与 `R→FCr` 归并的 FT 同截止 ABI。v0.2 启用既有 I64 FT 的严格相等、点代表和既有域形成归并；非I64未注册规则必须结构化返回未启用，不能伪造比较或概念结果。该合同不能由本计划以 L1 ABI 扩展、定位服务越权写概念关系、顺序补写名称/用途，或临时无 FC 的 F 代替。

## 已冻结的后续施工边界

1. 新的显式入口只属于 `特征概念应用服务`。它在任何 FCv 查询/建立、F定位、IF/R或汇聚写前，以同一 `Gread/H` 读取 `E+FT` 的完整 IF/R；当前采用不是该入口的读取前置或输入。读取失败、事实代次漂移、预算不足、退出或不完整必须保留原具名结构化结果并零业务写，不能压缩成结构异常。
2. 成功读取后，IF/R均未找到表示首个 R；完整 IF/R 表示将候选值交给 FT R归组规则。IF/R半结构、空R项、缺区间材料、重复或多个命中 R项均为结构异常，并零 FCv、F、IF/R、当前采用和汇聚写。L2存在类只提供中性 IF/R 读回、一次写集与引用/形状/预期快照核验；它不判断首个R、命中、形成新R或结构异常。若写前快照已改变，L2返回具名漂移或引用冲突，零本次写，不重新分类。
3. 结构异常由普通应用私有的 `noexcept` 诊断回调处理，经构造注入特征概念应用服务。回调只使用调用点已持有的最小身份与原因摘要，在所有 L3 mutex 和普通应用上下文锁释放后，尝试一次 `记录逻辑错误日志` 与同因摘要的调用线程 `MessageBoxW`；两者任一失败、异常或未显示均不改变已经固定的结构化结果、零写承诺或线程继续条件。不得启用既有全局容错宏、把日志/UI依赖放入L2，或建立全局诊断体系。该回调只保证尽力同步调用，不保证无窗口或非交互会话中的可见性。
4. 已完成上游发布后的重新 S0 通过后，首个R或规则返回形成新R时，概念应用先取得 FCv，再调用既有四 owner 提供者建立/复用完整 F。唯一命中R时零F写入；两条路径都由L3向存在 owner 提交中性 IF/R 目标写集。R真实变化后才同步尝试一次汇聚。概念汇聚失败保留已发布 R，不写回执、不自动重试或回滚。

## 允许与禁止范围

允许继续本计划原有的 `海中鱼巣/领域/数据服务.存在类.h`、`海中鱼巣/领域/数据服务.特征类.h/.cpp`、`海中鱼巣/业务/应用服务.特征概念类.h/.cpp` 与 `海中鱼巣/装配.普通应用.cpp` 切片，以及必要施工/验证记录。概念 tree owner 只消费归并结果建立/复用 FCr 及其上下位，不保存或解释 FT 规则。普通应用只持有定位服务、特征概念应用服务及私有诊断适配，不在装配时调用新入口、启动线程或进入阶段21。

本计划禁止实现或修改既有四 owner 出生提供者、L1 ABI、定位特征原子事务、特征类型规则持久结构、`.ixx`、F原地值、I64误差域/相邻合并、当前采用语义、概念汇聚回执/自动重试、线程、启动或阶段21。FT 规则公开 ABI 只由直接上游计划实现；本计划只消费其已发布 ABI。

## 具名设计漂移

v0.7 已确认当前 `存在类数据服务` 只有六关系类型登记/交付，`特征概念应用服务` 只有既有 I64 原子出生入口。v0.8 由 4115 的 L2 语义和现有 L1 写集模型冻结了读写 DTO、投影、预算、材料编码、写集和 L3 入口形状；执行者不得再临场设计这些合同。仍有一项影响机器语义的上游漂移：当前 I64 R 归并输出的 FCr 域与成员 FCv 域相同，7160 规定同 FT、同规范域只能是一个概念，因此无法建立“FCr 是 FCv 上位”的自环禁止关系。该项保留为本计划唯一未裁决门禁。

## v0.8 L2 IF/R 合同

存在类新增 `实例特征R项身份`、`实例特征节点时态`、`实例特征关系时态`、`实例特征R项投影` 和 `实例特征IFR投影`。投影回显 `E、FT、IF、R集合、当前版本、成员F、R项、各R项材料和形成F`；所有节点与关系都携带编码、创建H和可选退出H，并回显六项 `实例特征结构交付_v2` 关系类型。成员F、每项形成F按编码严格升序；R项按R项编码与成员序列稳定排序；形成F并集恰等 IF成员F。

`读取IFR结构(const 实例特征IFR读取请求&) const noexcept` 的请求固定为 `{版本=1,Gread,E,FT,F成员上限,R项上限,关系上限}`。成功仅为 `已读取`，且 `Gread=H=请求Gread`、投影完整且未超过三项预算；未找到、已退出、数量预算不足、事实代次漂移、引用冲突、资源失败和内部不一致均清空投影。

`提交IFR目标结构(const 实例特征IFR提交请求&) noexcept` 的请求固定为 `{版本=1,G0,E,FT,optional<预期完整投影>,规范化目标R项组,幂等身份,F成员上限,R项上限,关系上限}`。目标项为 `{特征R区间材料 材料, vector<特征信息身份> 形成成员}`；项按最小形成F编码升序，成员非空严格升序且跨项全局不重复。首次只允许空预期和不存在 `E→IF`；后续预期逐字段等于 `G0` 的当前投影。新增 F 必须在 `G0` 已是 E 已知的同 FT 准确 F；目标成员并集覆盖全部 IF成员。成功状态仅为 `已提交、精确重复、目标已满足`，逐字段回显原请求和完整投影；`目标已满足` 不写 L1 且无首次H。

R项材料固定用结构登记扩展的 `实例特征结构交付_v2.R项材料属性类型` 保存为 R项当前属性。该类型节点的 L1 表示为 `U64组`；材料值编码固定为 `{格式版本, static_cast<uint64_t>(类别), 规范化U64组...}`，读取时先反序列化为 `特征R区间材料` 再参与规范化、相等和规则调用。结构登记仍创建既有六个关系类型节点，并额外创建此唯一属性类型节点；它不是第七条关系，也不改变六关系的身份或方向。

目标不同才以存在 owner 单次写集发布：按“首建 IF、首建R集合、新版本、按目标序的新R项、首建E→IF、新增IF→F、首建IF→R集合、R集合→新版本、新版本→R项、新R项→形成F、新R项材料值及属性槽”严格顺序分配从1起的全局唯一局部键。材料与形成F均相同的旧R项复用；其它R项新建。只退出旧 `R集合→版本` 关系，旧版本、R项和其成员保留历史。交换后逐项读回当前投影与退出关系；同幂等键同完整请求只按首次写集和原键读回，异请求冲突。派发后或读回失败返回 `已可能发布` 并保留原键，禁止回滚、换键或假称零写。

## v0.8 L3 入口与未裁决上游漂移

特征概念应用新增 `处理存在特征R` 入口，输入固定为 `{版本=1,G0,E,定位特征位置(C/P),FT,候选准确值,FCv概念键,F出生键,IFR结构键,FCr概念键序列,L2读写预算,R规则预算,既有I64出生预算,FCr概念预算}`；当前采用不进入请求。结果固定区分 `已发布且汇聚完成、已发布且汇聚未完成、R未变化、读取IFR失败、结构异常、归组失败、FCv/F出生失败、提交IFR失败、入口拒绝`，并保留原请求、L2读写、规则、可选F出生、FCr写入组及汇聚失败原因。前两项均表示R发布成功；“汇聚未完成”绝不表示汇聚成功，也不回滚或重试R。

构造器新增 `存在类数据服务&`，普通装配传入现有存在服务。形成新R时只复用既有 I64 原子出生入口取得 FCv/F；R发布后对完整新版本每项先由概念owner同截止核验 `F→FCv`，再调用 `归并特征R概念`。`已归并零输出` 为汇聚完成零写；非零输出应以 `子父替代` 建立 FCr 到 FCv 的上位关系，不能把 FCv 填为 FCr 的直接上位。

当前 I64 规则实现却以成员F的单点域输出 FCr，而 FCv 的身份同样是 `FT+同一单点域`。7160 的唯一同义规则迫使概念服务复用 FCv，随后上位写入成为自环。此缺口必须先裁决 I64 R 归并应产生零 FCr，还是应由正式规则生成严格包含 FCv 的 FCr 域及其父组；在裁决和新的上游提供者结果发布前，IF/R 不得恢复为可执行。

## v0.9 I64 归并裁决

用户已明确裁决：I64 单点 R 不应产生严格包含其 FCv 的独立上位概念。因而 I64 R 归并的目标是成功零输出；FCv 保持原有事实，既不创建 FCr，也不建立 FCr→FCv 关系。已登记的 FEATURE-TYPE-R-I64-NO-FCR-RULE-CORRECTION 负责把该语义落实到特征类 R 规则提供者，并保留 DTO 外壳和旧用途3历史关系的只读边界。它发布后，本计划的 L3 汇聚只把已归并零输出映射为汇聚完成零写；其余 L2/L3 合同不变。
