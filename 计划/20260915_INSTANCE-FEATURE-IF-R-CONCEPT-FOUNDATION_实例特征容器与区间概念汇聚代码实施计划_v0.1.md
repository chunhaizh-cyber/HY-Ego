# INSTANCE-FEATURE-IF-R-CONCEPT-FOUNDATION 代码实施计划 v1.1

状态：可执行。重新 S0 基线：`b3fef3ef` 已是当前 `main` 祖先；I64 R 规则已发布为成功零 FCr 输出。

## 目标与已完成上游

实现 4115 的 `IF(E,FT)`、F 成员、R 集合版本和 I64 精确分组的中性 L2 持久结构，以及其 L3 编排入口。R 真实变化后，L3 调用特征类既有归并 ABI；对当前唯一启用的 I64 FT，`已归并零输出` 是汇聚完成零写：不创建 FCr、不读写概念 owner、不建立 FCr 到 FCv 的关系。

`ea195241` 已发布四 owner 原子准确 F 出生，提供 FCv 先行、F 内容/位置/已知/F 到 FCv 同次发布及完整读回。本计划复用它，不重写定位特征事务。`3b474a66` 已提供 R 区间材料归组 ABI；`b3fef3ef` 已将 I64 归并固定为零输出。非 I64 当前未启用，必须结构化返回且零 IF/R 写入；它不在本计划中创建 FCr 或概念汇聚能力。

## 冻结合同

1. `存在类数据服务` 新增 `实例特征结构交付_v2`、完整 IF/R 投影与读/写 DTO，及 `读取IFR结构`、`提交IFR目标结构` 两个中性公开操作。唯一新增结构类型是 R 项材料属性类型；六条既有关系类型的身份与方向不变。
2. L2 读取只按 `{版本=1,Gread,E,FT,F成员上限,R项上限,关系上限}` 回显同截止完整投影。L2 写入只按 `{版本=1,G0,E,FT,可选预期完整投影,规范化目标R项组,幂等身份,三项上限}` 提交目标；不分类首个 R、命中、新 R 或结构异常，不读取当前采用，也不写当前采用。
3. `特征概念应用服务` 新增 `处理存在特征R`：先同截止读取 IF/R，分类首个 R、唯一命中、形成新 R、结构异常和原具名读取失败；仅在形成新 R 时调用既有 I64 四 owner 出生，再向 L2 提交目标。R 真实变化后只尝试一次归并；I64 零输出映射为“已发布且汇聚完成”。
4. 普通应用只构造并注入同一存在服务和私有 `noexcept` 结构异常诊断适配；不在装配时调用新入口、预建 IF/R、启动线程或进入阶段21。诊断在 L3 与上下文锁都释放后尽力记录日志和显示同因 `MessageBoxW`，任何失败不改变结构化结果。
