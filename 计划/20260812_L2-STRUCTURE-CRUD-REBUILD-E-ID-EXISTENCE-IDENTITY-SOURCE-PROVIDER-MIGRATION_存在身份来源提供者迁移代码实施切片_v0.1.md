## 5. 硬性 ABI 与算法门禁

### 5.1 强类型 owner 和初始化

- `存在所有者建立身份` 固定 `0x4C31'4F57'4E45'5231ULL`，由存在服务模块 export，普通应用不得再私有复制；
- `存在身份来源登记幂等身份` 固定 `0x4C32'4944'5352'4301ULL`，只由存在服务内部使用；
- `L2存在所有者交付` 不可默认构造 / 复制，只可移动，不公开 raw 端口；
- 形成函数核对建立合同、幂等身份、成功 / 重复形状、独占 owner、端口 owner 和同实例绑定；
- 服务构造收到失效 / 已移动包装抛 `std::invalid_argument`，来源初始化任一结构化非成功抛 `std::runtime_error`，实际分配异常传播；普通应用统一映射 `存在服务构造失败` 且不发布上下文；
- 初始化同写锚点 `0x0202'1001U` 和类型 `0x0202'1002U`，首次 / 重复回同两个不同编码；失败不发布服务；
- 来源定位只保存 owner、锚点、类型、建立代次，不保存成员或关系缓存，不提供恢复 / 扫描。

### 5.2 来源 DTO 和读取

- 公共来源事实字段、存在请求 / 结果和函数签名逐字匹配同版详细设计第 4、7 节；
- 来源结果截止固定为当前事实判定回显期望代次、历史事实判定回显历史截止、漂移回显实际当前代次、快照前入口 / 许可 / 资源失败回显 0，且永无变更代次；
- 当前一次一致投影核对 owner、目标、锚点、类型和精确源关系组；已退出优先返回 `已退出`；
- 历史在前后当前代次夹取内，先在请求截止或节点退出前一代的判定截止读取精确源关系组；空组再以节点创建代次回退区分从未登记与提前退出，随后读关系完整生命周期并投影到请求截止；
- 非节点事实编码、属性类型节点、目标节点自身 owner 不是存在 owner、legacy、无正式来源和内部节点返回 `入口拒绝`；目标节点属于存在 owner 但已定位关系事实自身 owner 不是存在 owner，以及定位后的重复 / 错锚点 / 类型 / 角色 / 混代 / 生命周期返回 `内部不一致`；
- 所有非成功空来源、零普通事实变化，单族不扫描其它族。

### 5.3 创建、属性、完整读取和退出

- 新增节点写集恰为 1 节点 + 1 非自环关系，回显两个不同映射；首次 / 精确重复都按首次事实代次闭合来源；
- 全部存在公开写拒绝把内部来源登记幂等值当公开幂等身份；
- 当前完整读取第二段投影必须同时含来源项目和全部属性值；历史完整读取把来源和属性放进同一前后代次闭环；
- `读取存在节点` 继续委托完整读取，不能保留弱身份旁路；
- 固定属性新增 / 换代前置必须验证正式当前来源；
- 退出请求显式携带唯一归属关系编码，写集包含节点 + 该关系 + 完整当前属性值；发布后节点 / 关系同代退出，锚点 / 类型不退出；
- 场景 / 特征外部引用未闭合继续由 L1 返回引用冲突，不自动级联退出消费者事实。

### 5.4 provider

- 普通应用只使用同一 L1 运行包和签发器，顺序保持“存在 owner -> 存在交付 -> 存在服务”；
- 装配状态固定 `已装配=0、配置无效=1、构造失败=2、所有者范围建立失败=3、存在所有者交付形成失败=4、存在服务构造失败=5`；任一阶段失败不发布半构造上下文；
- 两种 getter 返回同一服务；普通上下文不公开 owner、端口、定位或初始化。
