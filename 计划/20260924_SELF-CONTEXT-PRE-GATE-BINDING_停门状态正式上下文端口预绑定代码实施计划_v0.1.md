## 1. 目标、范围和完成条件

本计划把普通应用唯一持有的 G2-A 正式上下文 provider 以现行抽象端口视图预绑定到唯一 self 线程对象，同时保持治理门关闭、零 provider 调用、零邮箱消费和零业务写。

完成条件：

1. `自我线程::创建并停在治理运行门`唯一公开签名增加`自我线程正式上下文端口&`工程参数；旧两参数签名、重载和兼容转发为零。
2. PImpl只保存一个非拥有端口指针；请求和端口地址在首次创建临界区原子锁定，不新增第二 owner、注册表、getter、setter或热替换。
3. 活动对象上，同请求加同端口精确重复；异请求或异端口选择冲突；停止或完成后继续保持入口拒绝和一次性对象语义。
4. 普通应用在调用前要求其唯一 provider 已存在，并把该同实例传给 self；provider 声明在 self 之前，析构时 self 先结束。
5. `线程_自我.cpp`零调用`读取正式上下文`和`复核双根当前需求`；门、邮箱、冻结批次、成功批次和业务写保持原停门形状。
6. 专项 Debug/Release 覆盖端口选择、并发、零调用、邮箱和停止；根工程 Debug/Release x64 隔离 Rebuild 通过。
7. 专属实施记录给出函数级代码知识变更清单，专属验证记录准确分账已运行和未运行范围。

完成只证明停门状态的正式上下文端口物理预绑定，不证明 self 已消费 fresh 上下文，不证明 G3、G4-A、RC、sink、任务线程或治理门开放。

## 4. 精确函数和私有结构变更

### 4.1 公开签名

在`线程_自我.h`原位替换声明；全仓只能保留：

```cpp
[[nodiscard]] 自我线程创建结果_v1 创建并停在治理运行门(
    const 自我线程创建请求_v1& 请求,
    自我线程正式上下文端口& 正式上下文端口,
    std::uint64_t 等待毫秒) noexcept;
```

不增加默认实参、指针重载、旧两参数重载或转发函数。该参数是非拥有工程依赖，不进入 `自我线程创建请求_v1`、`operator==`、业务幂等或持久材料。

### 4.2 PImpl承载

在`自我线程::实现`中增加：

```cpp
自我线程正式上下文端口* 正式上下文端口 = nullptr;
```

不得改为拥有型智能指针，不增加锁、注册表或外部释放逻辑。`运行()`、`复核前置并开放治理运行门`、邮箱、停止、等待、析构和诊断函数不得解引用该指针。

### 4.3 创建函数控制分支

实现严格按以下顺序：

1. `!请求.完整()`：返回现有默认`入口拒绝/未创建`，零锁定、零线程、零端口调用。
2. `实现_ == nullptr`：`资源失败/启动失败`。
3. 加`状态互斥`；若已经停止或线程完成，`入口拒绝`。
4. 已尝试创建时，锁定请求或锁定端口任一缺失均锁存`内部错误`，不得补写。
5. 已尝试创建时，请求不同或端口地址不同均返回`选择冲突`；二者都相同且停门见证存在则`精确重复`并返回原见证；见证尚未形成则进入既有等待。
6. 首次创建在同一临界区设置`创建已尝试=true`、锁定请求、锁定端口地址和`创建中`，再建立唯一工作线程。
7. 线程构造失败保持当前一次性失败语义：锁存停止/完成、生命周期`启动失败`、返回`资源失败`；不得清空端口后用另一个端口重试。
8. 等待超时、内部错误、停门成功和其它后置判断保持现有状态；所有分支零端口调用。

已有`创建选择相同`继续只比较值式请求。端口地址必须在创建函数中独立比较；不得把地址混入 DTO、哈希、日志或诊断载荷。

### 4.4 普通应用调用

`创建并停门普通应用自我线程()`：

- 前置条件增加`上下文->自我线程正式上下文`非空；缺失时返回现有入口拒绝形状且 self 保持未创建；
- 唯一调用传入`*上下文->自我线程正式上下文`作为第二参数；等待值顺移为第三参数；
- 保留现有世界/self/锚点复核、请求形成、创建后停门后置条件和失败安全回收；
- 不新增 getter、重构上下文、改变成员顺序或构造第二 provider。

### 4.5 专项适配

在`自我线程上层骨架专项验证.cpp`增加一个最小假`自我线程正式上下文端口`实现；其`读取正式上下文`只增加线程安全调用计数并返回结构化非成功。全部创建调用显式传入端口，不使用空指针或派生类下钻。

现有生命周期、邮箱和析构用例保留；在此基础上增加同/异端口、同/异请求和并发竞争验证。专项结束前逐端口断言调用数为零。

## 5. 生命周期、并发和失败收口

普通应用字段顺序固定为 provider 在前、self 在后，因而 self 先析构。创建开始后直到 self 析构完成，普通应用不得重置 provider。self 不负责释放、停止或恢复 provider。

并发创建的线性化点仍在 `状态互斥` 内首次写入创建选择。请求和端口地址作为一个物理选择判断：

| 当前状态 | 本次请求/端口 | 结果 |
| --- | --- | --- |
| 未尝试创建 | 完整请求 + 任意合法引用 | 首次锁定并开始创建 |
| 创建中/已停门 | 同请求 + 同地址 | 等待首见证或精确重复 |
| 创建中/已停门 | 异请求或异地址 | 选择冲突 |
| 已停止/线程完成/停止已锁存 | 任意 | 入口拒绝，不重启 |
| 已尝试但请求或端口丢失 | 任意 | 内部错误并锁存，不修补 |

引用在语言层不可为空，不新增空端口分支。资源、等待和异常状态沿现有枚举返回；本计划不重排状态数值。任何非成功都不得打开治理门、出队消息、增加批次或调用端口。

### 7.2 自我线程上层骨架专项

使用仓库外独占根：

```text
D:\TEMP\海中鱼巣\SELF-CONTEXT-PRE-GATE-BINDING\<本轮目录>
```

分别对`验证工具/自我线程上层骨架专项验证.vcxproj`执行 x64 Debug/Release Rebuild，显式设置互异`OutDir`和`IntDir`，然后运行两个产物。两次均要求退出码0、`fail=0`，并覆盖：

- 无效请求零锁定、零线程、零端口调用；
- 同请求同端口首次成功与精确重复；
- 同请求异端口、异请求同端口选择冲突；
