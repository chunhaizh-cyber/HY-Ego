## 1. 目标和完成条件

实现概念唯一 owner 的无总根窄参与合同，使后继场景/存在/特征 L2 添加函数能够提交存在或特征概念方案并取得概念 owner 的原子参与片段，再按实际截止独立读回概念及世界挂接。状态只引用已有特征概念，动态等待7191专属定义，因果沿4340独立合同；该叶不修改六类数据类和世界树应用。

完成必须同时满足：新合同可编译；概念服务实现准备/读回；创建与复用均不依赖四总根；请求缺挂靠、类别冲突、签名冲突、跨类上位、成环、漂移、预算和幂等分支有结构化结果；专项 Debug/Release 通过；根工程两配置至少完成构建差异归因。

## 4. 目标接口和实现

严格实现详细设计第5节的 `相关概念类别`、方案、挂靠、预算、状态、请求、片段、完整读回及 `相关概念添加参与者`。C++ 精确字段顺序按详细设计；签名和定义使用当前真实 `概念树定义`，概念和直接上位使用 `概念树概念身份`，挂靠使用 `概念树形成世界引用`，不得引用不存在的材料身份。参与片段固定使用 `L1有限N分区原子参与者写集_v3`，不得改变语义或新建事务协议。

把详细设计具名的基础纯值声明从 `数据服务.概念树类.ixx` 移到新合同模块；数据模块改为 `export import` 新合同，所有原名、字段、分派和值语义保持不变。新合同模块声明后固定`export import 海中鱼巣.核心.服务.L1事实基座;`，不再以只导入`海中鱼巣.核心.合同.L1所有者范围CRUD`代替服务类实体来源；核心服务已经再导出所需owner-scoped DTO。不得在全局模块片段、本合同模块或头文件中前置声明同名`L1事实基座服务`，不得依赖消费者偶然先导入服务模块。依赖方向为本领域合同到核心服务，核心服务不反向导入本合同，因此不形成六类数据服务与概念实现的模块环。

`概念树类数据服务`公开继承参与者并实现：

```cpp
相关概念参与片段 准备相关概念片段(
    const 相关概念参与请求&, std::uint64_t Gread,
    L1有限N分区原子参与者身份_v3) const noexcept override;
相关概念组合提交结果 提交相关概念组合事务(
    const 相关概念组合提交请求&,
    std::span<L1所有者范围写端口* const> 外部端口组) noexcept override;
相关概念参与读回 读取相关概念结果(
    const 相关概念参与请求&, std::uint64_t Gread,
    std::uint64_t H) const noexcept override;
```

参与者基类中的物理绑定签名保持`virtual bool 绑定于(const L1事实基座服务&) const noexcept = 0;`，其中参数必须是核心服务模块导出的同一类实体。不得改成`void*`、模板参数、owner端口或其它替代类型。只显式导入本合同的最小翻译单元必须能够解析该签名和全部参与DTO。合同全局模块片段增加`<span>`，端口span只作调用期非拥有借用。

准备顺序固定为：入口/预算 -> 当前 G -> 世界挂靠强类型历史见证 -> 类别与定义联合一致 -> 复用目标或按规范化 `概念树定义` 查找 -> 上位同类及无环 -> 形成概念 owner 局部写集。精确复用不建立新概念，只在缺少相同挂接时准备挂接；完整相同返回无写集的 `精确重复`。创建方案命中同义概念时收敛为复用，未命中才使用局部新编码；顶层允许零直接上位，非顶层保留调用方提交的完整父组；禁止从名称、旧根或遍历位置选择类别。

读取按 `Gread/H` 返回请求对应的概念完整事实和该请求世界事实对应的唯一当前形成挂接；H 必须非零且不晚于 Gread。提交产生写集时使用 L1 返回的实际 H；`精确重复`无提交，使用 `H=Gread`。所有直接上位边稳定排序并全部回显，顶层空组是完整成功。失败载荷为空。
新增`相关概念组合提交请求`字段顺序固定为`版本=1、Gread、组合幂等身份、概念请求、前序参与者写集组`；`相关概念组合提交结果`固定为`版本=1、概念状态、Gread、已进入L1、L1有限N分区原子事务结果_v3`。请求不含任何端口；结果不含端口。提交方法的第二参数仅为`std::span<L1所有者范围写端口* const>`调用期借用。

前序写集数量M固定1..254，按vector位置使用参与者1..M；概念准备函数第三参数固定传M+1，概念写集使用参与者M+1。身份必须连续覆盖1..M+1，禁止当前WIP固定为2、提交时临场重排或留空。外部端口组长度等于M，端口i严格对应参与者i+1；端口有效、同L1、owner匹配且两两不同，概念owner与全部外部owner不同。组合键、owner键均有效且互异，全部期望代次和概念请求G0等于Gread。

提交方法先按概念owner键读取首次材料。未找到才以M+1重新准备并要求`已准备`且owner/编号/代次/键一致；已找到则严格核验首次owner、键、H、结果及请求概念权威读回，把首次规范化owner写集机械转换为参与者M+1的v3写集：稳定引用保持稳定，本owner本地引用使用v3事实引用联合中的plain `L1所有者范围写集本地键`分支并保持同一本地键，禁止标记为参与者M+1。L1 v3只有指向前序参与者1..M的跨参与者引用合法；概念新写集不消费前序参与者本地事实，所以禁止生成全部带编号引用。反向规范化把plain本地键恢复为同一本owner本地引用并逐字段等于首次材料。该转换支持发布后原组合键重放而不依赖新当前代次重新准备；不能无损转换、残缺或异义的首次材料在提交前返回内部不一致。随后由外部端口1调用L1 v3，其余端口按“外部2..M、概念端口最后”传入。概念端口只在函数内部取址并传给该次L1调用，不保存、不返回、不增加public/protected访问器。若首次材料未找到且概念准备为`精确重复`或失败，`已进入L1=false`、精确回显概念状态且零写；后继对已存在稳定概念的外部写入沿自身合法单owner/多owner协调，不伪造空概念参与者。

进入L1后原样回显L1九种状态、组合键、共同H、发布标志、重试边界和参与者结果；首次提交概念状态为`已准备`，L1精确重复时为`精确重复`。提交前失败零写；发布未知只能以原Gread、组合键、概念请求、相同前序规范化写集和端口owner顺序重放，不回滚。L1已提交或精确重复后，调用者必须按共同H独立读回全部外部owner，并调用`读取相关概念结果`；任一读回缺失由后继L2归为已可能发布，原子提交结果不能直接充当业务成功。

新 `相关概念结构交付` 的字段、21项类型登记角色及 owner 写入映射严格采用详细设计第5节：`概念族锚点 -> C`、`C -> 定义记录`、`上位C -> 下位C`、`C -> 形成记录 -> 世界端点`及类别/定义/证据/生命周期值。每项使用交付中的具名类型编码，禁止复用旧根归属关系表达类别。概念、定义、直接上位和首次形成挂接必须进入同一概念 owner 的 `L1有限N分区原子参与者写集_v3`；精确复用缺挂接时该片段只新增形成记录及其关系和值。所有新身份由参与写集本地键产生，调用方不得预分配稳定编码。

`概念树类数据服务`新增详细设计第5节冻结的纯新构造与迁移构造。纯新构造接收 L1、特征、存在、特征值、场景、唯一概念 owner 端口和新交付；迁移构造再依次接收旧 `概念树结构交付` 与新交付。旧布局、新布局均在内部保存为 `optional`：纯新实例只含新布局，迁移实例两者均含，保留旧构造只含旧布局。新参与方法没有新布局时精确返回`相关概念参与状态::旧格式不支持 = 18`；旧入口没有旧布局时仍返回`概念树数据状态::旧格式不支持 = 35`。两侧不得读对方布局。这样同一个服务实例和同一个概念 owner 端口承载迁移两侧，不建立第二服务、第二端口或第二概念身份来源。

## 5. 非成功、事务与并发

执行者按详细设计枚举逐项映射，不得把未找到、读取失败和格式不支持合并。`相关概念参与状态`只在原1—17后追加`旧格式不支持 = 18`，其它值不变。新参与两入口缺新布局均返回18并回显调用截止`Gread`：准备结果无写集且该DTO没有H字段，读回结果`H=0`且无概念，L1零写入。旧入口缺旧布局仍返回其自身枚举值35。内部旧格式状态进入新参与边界时只允许以穷尽`switch`显式映射为18，禁止`static_cast`、底层整数复制或同名枚举代入；成功谓词不得接受18。准备函数零提交，不持有跨调用裸指针；结果写集只属于概念 owner 且不暴露端口。读回只读。

专项测试以一个合法假世界owner作为前序参与者1，通过概念参与者的受限提交方法把概念片段作为参与者2交给现有L1 v3；测试不得取得概念端口。另以两个假外部owner验证1、2与概念3的连续顺序、端口顺序和owner核验。覆盖同键同请求、同键异请求、同G竞争、错误参与者编号、端口缺失/错序/异L1/重复owner、提交前失败、提交后读回和原键重放。真实发布未知和故障注入不能执行时明确`NOT_RUN`，不得记通过。
