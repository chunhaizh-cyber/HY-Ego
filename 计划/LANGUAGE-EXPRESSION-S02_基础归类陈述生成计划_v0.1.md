# LANGUAGE-EXPRESSION-S02 基础归类陈述生成计划

日期：2026-10-15。版本：v0.1。执行身份：`LANGUAGE-EXPRESSION-S02`。状态由[计划索引](计划索引.md)唯一维护。

## 1. 目标与执行资格

以已发布代码 `42d925ad2c48740a8388662dd4573bfbeb7e4fe4` 为设计事实起点，按[详细设计](../规范/详细设计/20261015_LANGUAGE-EXPRESSION-S02_基础归类陈述生成详细设计_v0.1.md)实现一个真实可调用的汉语基础表达入口。调用方给定归类陈述含义、两侧正式存在概念和各自明确选中的同语言正式名称关系时，入口从已发布语言知识定义选择结构，生成完整文字及标量位置对齐。首叶成功只覆盖该合同；生成不是事实确认、保存或送达。

现行依据：[2340](../规范/2340_根规范_自然语言知识.md)、[7230](../规范/7230_子规范_语言材料知识与交互字段.md)、[7240](../规范/7240_子规范_自然语言双向转换与组织规则.md)、[7220](../规范/7220_子规范_概念多语种表达与自然语言接入.md)、[0050](../规范/0050_项目通用机器逻辑与禁止性规则总纲_20260721.md)及[代码归属规范](../规范/代码文件建立归属与模块命名规范.md)。现行候选/名称接口和已有五条规则只以 S0 当前源码为准；历史验证不证明本叶运行。无上游未实现接口依赖。计划发布并在 main 登记后，执行者仍须重新核对 HEAD、索引精确 blob、当前接口、所有权、index/dirty 与构建资源；若接口漂移，停止受影响范围交计划支撑。

## 3. 冻结施工合同

完整签名、DTO、状态、物理位置和算法以详细设计 §3—4 为准，不在计划正文复制第二份。实现步骤：

1. 扩展 `新_语言类` 只读全候选读取。复用现有完整结构/词端点快照读回与漂移检查，按正式语言枚举全部定义；额度到限不截断。不要在 DATA owner 进行含义解释或句子拼接。
2. 建立业务头源及工程登记。业务按请求的目的、操作、作用域、参数类别匹配定义与角色约束，不以种子编号、固定文本或稳定编码顺序代替知识。无匹配、歧义和未支持各有独立状态。
3. 仅对两个存在概念及其明确选择的名称关系完成强类型读回和同语言校验；将正式结构项逐项展开为 UTF-8 文字。每个输出项生成半开标量范围与规则/词条/参数/名称依据，全部完成后一次返回。错误零领域写入、零残句。
4. 做静态复核与实际工程统一编译链接；只在用户对本切片明确下达测试指令时运行实际项目专项测试。形成专属验证记录和函数知识变更清单，不直接修改共享知识库。

执行时特别区分：调用方给定主张 ≠ 正式概念上下位事实；给定名称关系 ≠ 可以脱离正式读回使用自由文本；固定词项 ≠ 硬编码语义。两次跨服务读回不保证共同事务，必要时再读核验，不一致返回读取漂移。任何工程故障不能变成 `缺规则` 或 `缺名称`。
