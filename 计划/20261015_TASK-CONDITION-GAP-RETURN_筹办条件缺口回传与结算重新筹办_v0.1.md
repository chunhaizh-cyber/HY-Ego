## 1. 目标及本叶完成边界

按本轮用户明确裁决：服务根初始化只建立结算子需求；结算任务不得在尚未核对方法条件前被预置硬阻塞。普通筹办读取方法及当前条件，缺失材料通过 worker → manager → self 交付；self 判断是否可以形成正式子需求。子任务完成或相关材料变化后父任务重新读取事实、重新筹办，不直接执行。

本叶闭合的是**条件缺口完整传递、self 显式判断及安全重新筹办**，不是未知结算来源到完整服务需求获取链的自动分解。本叶不改变本能函数，也不改变真实世界人物、服务值或动作事实；改动对象是任务内部治理状态和进程内消息材料，目的是恢复正常筹办并避免旧材料放行或重新阻塞任务。

不得把下列状态当成本叶完成条件：已经运行服务结算、自动生成获取服务需求子需求、服务闭环、运行或恢复验证通过。

## 4. 缺口 DTO 与传递合同

在 `新_任务类.h` 的候选筹办类型旁追加纯值类型：

```cpp
enum class 新任务方法条件缺口种类 : std::uint8_t {
    参数对象未取得 = 1, 参数匹配不唯一, 参数特征值未取得, 条件值不满足
};
struct 新任务方法条件缺口 final {
    新任务方法条件缺口种类 种类;
    新方法参数规格 参数规格;
    std::vector<新方法参数角色绑定> 已知绑定组;
    std::vector<新方法条件结果信息> 相关条件结果组;
    friend bool operator==(const 新任务方法条件缺口&,
        const 新任务方法条件缺口&) = default;
};
```

在 `新任务候选方法筹办项` 追加 `std::vector<新任务方法条件缺口> 条件缺口组`。外层已包含方法、候选及任务定位，无须新增另一个事实 owner 或消息通道。

合同：

1. 规格来自本次真实读取的实例方法 Vm；相关条件结果保存该角色实际参与的配对定义，不伪造配对。只有方法头时可为空，继续走现有学习发现逻辑。
2. 未知 Vt 来源返回 `参数对象未取得`、完整角色/对象种类/FT/值域规格，绑定组为空，不能放入空稳定编码冒充已知存在。
3. 普通角色匹配为零、多于一、合法对象但缺少当前值分别保留对应缺口；已知绑定只保存合法来源引用。已知值不满足时保留条件定义及合法绑定。
4. 一个角色缺失不得使后续合法角色缺口被无故吞掉；按方法参数顺序，配对按原读取顺序稳定输出。参数未到不是结构错误；规格声明或条件结果结构本身读取失败、读取损坏、内存异常等继续独立工程路径，不包装为参数对象未取得等业务缺口。
5. 本材料不是需求、事实快照库、执行许可或原因推断，只随当前筹办反馈生命周期存在。manager 独立重新调用条件筹办并完整比较（含新增数组），匹配后发送既有筹办反馈；不因 `材料未到` 在独立核验前截断交付。
6. 材料在两次核对间变化时是旧筹办失效，不得将旧缺口交 self 创建 D；回当前筹办，不用缺口 DTO 吞掉资源/结构失败。

## 5. self 判断及既有子需求复用

`新_自我线程类.cpp` 的筹办处理先消费 manager 已独立核验的条件材料：

- 目标 E、FT 和目标域已正式确定且既有 `提议任务条件子需求` 形成提议时，沿现有 `处理条件子需求提议` 建立/复用 D；self 发布前继续 fresh 比较完整提议。
- 有完整缺口但没有可确定目标 E/FT/域时，显式形成“等待条件”的筹办裁决，并保留原缺口供读取；不创建 D、不造未知 Vt、不调用父本能函数。不把这种等待标记工程失败。
- 未知来源 Vt 缺口不等价于“任意任务集合非空”。现有集合域的 `至少一个任务` 会被筹办子任务满足，不能代替有服务要求来源的候选任务。
- 必要前置子目标无需等价于父方法的全部条件；本叶不否定这种分解。将“任意已确认服务要求对应任务存在”表达成正式目标仍需新增集合谓词和方法头消费合同，本叶明确排除，不擅自选一个任务编码。
- 无结果途径、不具备必要条件和工程失败仍不能获得执行许可。

## 6. 结算来源事件及防竞态

### 6.1 收存入口

保持 `新_任务管理线程类::接纳服务值结算来源(稳定编码) noexcept` 签名。在 `新服务值结算协作状态` 尾部追加 `已接收待筹办 = 10`，只表示 manager 已收存来源事件，不表示已绑定、已执行或已结算。self 的来源交接分支把该值认作已交接；本能执行和结算确认分支不得把它认作操作成功。

入口在 manager 锁内收存来源 T 编码并唤醒，禁止锁外直接绑定来源或改目标 T 状态。相同待办编码幂等；不同来源按已收存顺序串行处理，继续保留当前单来源结算限制，不覆盖已有绑定。收存完成后不丢失事件；资源失败未收存时走工程控制。禁止复用本能动作业务返回表示消息收存。

### 6.2 manager 唯一推进

在 manager 实现私有新增 `void 推进服务结算来源事件() noexcept`，由已有管理循环调用，新增事件容器、当前事件及结算筹办占用保护也仅属于 manager 实现。处理顺序：

manager 唯一线程是工作派发与来源事件消费的唯一执行方。来源消息入队前已选定且正在锁外向 worker 提交的请求视为在途工作；管理循环回到来源事件消费前，该请求必须完成活动工作登记，然后按下列流程排空。无需取消已经提交给 worker 的请求，不新增任务业务版本或筹办轮次。消息入口只收存，不与 manager 循环并发执行事件消费。

1. 有已取得执行授权/活动执行或结果收束材料时不得改变来源；按现有不具备/冲突结果收束或等待安全点，绝不覆盖执行材料。
2. 与既有学习复核、等待复核互斥。同一 T 已被学习/等待复核占用时先让现有占用完成，来源事件保留。待来源事件不能加入通用 `任务有执行保护已加锁` 判定，避免旧学习/等待复核也被阻止而互等；独立门控该 T 的新 W1/W2/W3 派发、新 W0 等待复核占用、新学习占用扩展及旧筹办 self 裁决，已有学习/等待复核继续完成。
3. 取得来源重筹办占用后使该 T 的旧筹办反馈、待发送反馈、待派 W1/W2 和调度快照选择失效。已发 W0 调度工作及本 T 的 W1/W2 必须等结果可读，确认 worker 收回后移除；不能凭擦除 manager 向量假装 worker 已停止。旧工作完成不得进入正常状态消费/写入新阻塞或执行授权；旧 W0 结果也不得覆盖新来源之后的调度快照。
4. 在途 self 消息按原工作编号和当前材料匹配拒绝；不能只删除最近结果却允许旧裁决重新放行。既有学习/等待复核的失效检查同步覆盖来源占用。
5. 排空后锁外 fresh 读取来源 Vt 状态、结算需求当前满足、服务值和配置；只在条件合法时调用领域 `接纳服务结算来源`。不同已绑定来源、来源不再完成、目标已满足保持原有语义，不直接产生任何 +1。
6. 调用 `准备服务结算筹办`，清理仅属于被替代旧筹办的材料与筹办阻塞，释放来源占用并触发普通调度。**不能无条件清除硬工程阻塞**、执行结果保护或其它所有者的恢复状态。
7. 任何工程错误保留已确认事实、记录并走已有工程停止诊断；不得作为业务条件或方法结果。停止时不新派工作，排空/保留事件按现有线程收束语义，不承诺跨进程恢复。

### 6.3 领域安全态

`新_任务类::接纳服务结算来源` 保留原签名及源/冻结值校验；允许未绑定时在 `已建立`、`等待条件`、`待查找方法`、`待检查条件` 接纳，其它执行/收束态拒绝。精确重复只读且必须同一绑定，不改变源。

`新_任务类::准备服务结算筹办` 保留签名：不存在来源时仍可进入方法查找；存在来源时继续 fresh 核对来源及服务值，绝不因此绕过 W2。允许上述四个筹办安全态；`待查找方法` 无变化；`待检查条件` 失效旧筹办后回 `待查找方法`。只清理筹办私有材料，不删除历史执行、动作、结果或需求。不能从 `待执行`、`执行中` 或终结态直接走此入口。

启动只删结算硬阻塞预置并通过已有准备入口使结算 T 进入普通查找，不强制绑定方法、不添加后续子 D。保留安全根现行初始化。
