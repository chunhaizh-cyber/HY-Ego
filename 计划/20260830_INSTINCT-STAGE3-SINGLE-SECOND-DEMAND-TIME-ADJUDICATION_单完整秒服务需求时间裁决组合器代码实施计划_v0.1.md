日期：2026-08-30

计划身份：`INSTINCT-STAGE3-SINGLE-SECOND-DEMAND-TIME-ADJUDICATION`

## 1. 目标与完成条件

在现有基础快照模块中实现 `本能单完整秒服务需求时间裁决组合器::读取当前维护秒服务需求时间裁决_v1`，从同一 `G0` 的基础快照、当前有效未满足合同完整集合和到期事件合同终态完整集合，形成单秒规则内核所需的需求裁决字段及可重算完整证据。

完成必须同时满足：

1. 当前有效需求按唯一需求身份计数，数量等于当前有效合同数；
2. 等待严格按当前维护秒减提出完整秒计算，保留全部规范排序的并列最长来源；
3. 只统计同一时间纪元且边界等于当前维护秒的到期事件；
4. `T=2,592,000` 的 `T-1/T` 边界和三类 `服务维护需求裁决_v1` 精确；
5. 两次基础快照相同，两个集合完整且共同截止为 `G0`；
6. 两配置、专项、ABI consumer、strict 和 diff-check 通过；
7. 当前生产定义版本 1 的 L/H 保持不变，零业务事实写入。

## 4. 实施步骤

1. 在基础快照数据头新增请求、最长等待来源、裁决快照、状态、结果、完整性和 `成功/可维护` 谓词。
2. 在现有组合模块导入服务合同 owner 和单秒规则数据，新增组合类与公开函数；不改变原基础快照组合器 ABI。
3. 固定执行两次基础快照、两个同 `G0` 集合读取、时间 / 版本 / 唯一性检查和派生字段计算；所有非成功零载荷。
4. 只在验证宏内扩展服务合同 fixture，覆盖同纪元 N 合同、不同等待、并列、到期边界和损坏输入。
5. 扩展现有基础快照专项；不得用裸 DTO 或 provider-only 自测替代真实组合入口。
6. 补齐施工 / 验证记录，执行全部门禁并精确发布白名单。

## 5. 失败收口

- 基础快照错误按具名状态映射；单调秒在两次读取间推进也返回 `当前性漂移`。
- 合同 provider 的结构未登记、集合不闭合、引用冲突、漂移和资源失败不降级为空集合。
- 活动合同时间纪元不同、未来提出 / 生效 / 最后结算、当前纪元未来事件返回 `时间纪元漂移`或`时间材料不闭合`。
- 未支持的合同或事件规则版本返回 `版本漂移`。
- 重复需求、重复合同、本秒事件重复合同或事件合同仍有效返回 `集合不闭合`或`引用冲突`。
- 本计划是纯读取组合，无发布未知、撤销或业务写入分支。
