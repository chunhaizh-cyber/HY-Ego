## 1. 目标与完成条件

保持两个公开资格读取入口及其结果语义，把 `L1实际存在服务::读取资格实现` 迁移到业务中性一致当前投影：

- 无显式资格值时请求 `3节点 + 0关系 + 0值 + 1属性值 + 0源关系组 + 0目标关系组`；
- 有显式资格值时请求 `3节点 + 0关系 + 1值 + 1属性值 + 0源关系组 + 0目标关系组`；
- 显式值未找到返回未找到；显式值已退出、种类错误、坏载荷、非当前值或与属性投影事实不等返回内部不一致；
- 旧分散事实代次、节点、属性和值读取在目标根归零；
- 首轮合法代次漂移完整重做一次，第二轮漂移返回版本漂移，许可拒绝零等待零重试；
- 构建、静态和正式生产运行门禁成立。

## 2. 修订依据与执行前事实

v0.1 固定零值选择，无法保留显式资格值定位入口的未找到语义。现行旧实现明确先读取资格属性，再按显式编码读取当前值，因此本版必须把显式编码作为同一一致请求中的独立值选择项，并与属性投影当前值事实互证。

正式依据为现行 4015、4030、4050、4200 和 ACCEPTANCE-01。第一层不自证；本计划只服务第二层现有消费者的真实资格读取。

执行开始前从正式新 HEAD 重做 S0，核对：

- 本计划 blob、设计提交和计划索引状态；
- 目标生产文件、私有函数、两个公开入口和现有 WIP；
- 一致当前投影 DTO 的值结果和属性投影字段；
- v0.1 已退出且本版是唯一可执行计划；
- Git index、所有权和异主 WIP。

任何会改变公开 DTO、状态枚举、请求语义、白名单或调用关系的漂移必须停工退回。

## 4. 实施合同

1. 保留现有入口校验；私有根先核对登记、存在编码和可选显式值。
2. 首轮期望代次取登记事实截止；每轮只调用一次一致当前投影。
3. 三节点顺序固定为实际存在、资格属性类型、登记服务来源；属性选择固定为实际存在与资格属性类型。
4. 无显式值时值组为空；有显式值时值组恰一项且为调用方显式编码。
5. 顶层成功长度必须按显式值条件核对，不能把两种入口压成同一固定值长度。
6. 对三个节点、可选独立值和属性投影逐项验证“成功必带材料、非成功必无材料”。
7. 内部项目错误优先；显式值 `未找到` 映射未找到，`已退出` / `种类不匹配` 映射内部不一致。
8. 有显式值且全部项目成功时，独立值结果的查询编码、事实编码和完整事实必须与显式编码及属性投影当前值事实逐字段全等；存在但不是当前值返回内部不一致。
9. 无显式值时直接采用属性投影当前值事实，不做第二次值读取。
10. 按设计互证节点、槽、当前值、来源、材料、创建代次和未退出状态；成功事实截止取共同读取代次。
11. 首轮合法漂移丢弃整轮材料并重做一次；第二轮漂移、许可、资源和其它顶层失败按设计分账。
12. 登记读取根仅机械使用共用 helper；公开签名、数据头和调用者零变化。
