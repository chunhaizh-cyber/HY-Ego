## 4. 实施顺序

1. 在任务数据头追加实际结果身份、事实、登记类型、记录/双键读取 DTO、守卫和成功形状；既有 ABI 不删除。
2. 在任务服务以新的两个固定登记幂等身份建立追加登记，禁止改写旧登记写集。
3. 实现发布当前选中路径和读取当前选中路径的真实原子关系投影。
4. 实现创建实例方法、按身份读取和按任务读取当前实例方法；筹办轮次、方法和内容版本从路径读回，执行轮次由实例方法属性承载。
5. 实现记录任务实际结果：先读任务/实例/路径和同轮槽，再按详细设计形成唯一写集；精确重复读回首次结果，异义零写冲突。
6. 实现两个实际结果读取入口，当前/历史均从 L1 权威投影重建，不从请求回显伪造。
7. 扩展运行期 DTO和组合器动态服务引用，实施同G0独立读回与字段矩阵互证；修复治理骨架和测试中的现有构造调用，不接业务分支。
8. 更新治理专项，全部案例只走公开 DATA-L2 与公开组合器。
9. 形成施工/验证记录和函数级知识变更清单。

## 5. 关键机械门禁

- `任务+执行轮次`唯一性只由任务结果槽关系及其正数顺序表达；不得扫描日志或用幂等键代替业务唯一键。
- 场景、来源材料版本和运行代次直接冻结于结果事实；场景只验证当前场景及主体成员关系，不猜输入/输出方向。
- 方法和动作入口必须与实例方法及其路径完全一致；状态和动态必须同主体，动态后状态必须等于实际状态。
- 每笔组合读取的结果头事实截止必须精确等于请求 G0；不得自动重取新 G0。
- 来源需求读取从任务的需求列表项开始，读取列表项全部当前成员并逐项完整读取；超过预算返回数量预算不足，不截断。
- v3 的来源任务序号不得当作执行轮次。本叶公开 provider 使用显式执行轮次；002-04 定位来源留给后继。

- 若当前任务 owner 无法用独立追加登记扩展、L1 不支持任务槽顺序唯一或公开状态/动态/需求读取 ABI 已实质漂移，具名退回计划支撑；不得改旧登记、增加第二 owner或退化为内存表；
- 若 v3 到执行轮次的定位在后继仍不存在，只阻断后继 002-04，不阻断本叶独立 DATA/provider 交付；不得把任务序号猜成执行轮次；
- 任一必需验证失败不得声明完成。
