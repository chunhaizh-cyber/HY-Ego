## 1. 目标与唯一结果

按`规范/详细设计/20260901_INSTINCT-ROUTE-P01_筹办工作包与结果消息详细设计_v0.1.md`机械实现一个进程内消息闭环：任务管理线程派发不可变后继筹办工作包，现有任务工作线程每个工作包只调用一次 provider 并形成五类之一的唯一结果消息，管理线程幂等接收、在自身循环独立读回正式分支事实后推进；删除管理线程同步直调筹办 provider 的生产路径。

完成条件不是 provider 返回，而是对应不可变结果消息被管理端确认`已接收`或`精确重复`。队列满只保留并重投同一消息，禁止重调 provider；硬拒绝必须令线程/运行包失败。

## 5. 机械实施顺序

1. 按详细设计 §3.1 在 task owner 数据文件补齐`L2任务轮次事实`、完整性守卫和专属读取 DTO；实现 public const `按任务读取当前任务与轮次`，覆盖 0/1/>1、读前读后 G0、引用和资源矩阵，零写入。
2. 新建纯值协议 module，按详细设计 §4 原样实现身份、工作包、五类结果、variant 载荷、完整性/相等守卫、统一提交状态和两个抽象端口；零服务调用、零持久化。
3. 将`任务筹办收束类别`和`任务筹办推进结果`收紧为五类顶层分支与一一对应载荷；学习/方法补齐退出顶层。无正式子目标记录的旧草案映射为等待或`待实现能力`，不得伪造定位。
4. provider 所有返回点均形成一个完整结果；可执行返回选择/路径/冻结/实例定位，子目标只返回正式记录定位，等待/完成/非成功各返回自身载荷。HEAD 中记录后直接建立需求的旧生产分支退出；在 P02/P03 未形成正式记录发布与需求编排前返回`待实现能力`或合法等待。
5. `任务工作线程`输入改为`variant<任务工作结果材料, 任务筹办工作包消息>`，保持一个线程和一个有界队列；实现工作包提交端口、provider 单次调用、当前处理中槽和待上交消息槽。
6. 结果提交`已接收/精确重复`才清槽；队列满只重投同消息；协议拒绝、幂等冲突、已停止和内部错误置线程内部错误。待上交期间不得越过处理后项。
7. `任务管理线程`移除筹办 provider 构造依赖和同步调用，绑定工作包端口并实现结果端口；派发前以工作包 G0 调用 task owner 新入口取得正式任务轮次；首次消息入槽、精确重复和同键异义按完整值裁决。提交调用栈只准入排队，分支处理只在管理循环执行。
8. 管理循环按详细设计 §6 的五分支矩阵独立读回。只有可执行分支读回成功才构造既有执行冻结请求；其它分支进入各自终态，不直接建需求、完成任务或自动开启新轮次。
9. 运行包把 provider 借给工作线程并在启动前绑定端口；复用现有工作容量，不新增配置或线程。按“停新派发—派发排空—工作排空及结果确认—管理消费排空—join”收口。
10. 工程与 filters 精确登记新 module；在既有本能路线阶段二测试中加入专项矩阵；形成施工/验证记录及函数级知识变更清单。

## 6. 失败收口

| 失败 | 固定处理 |
| --- | --- |
| 工作队列满 | 管理槽保留同一包，稍后重提；未接收不调用 provider |
| 结果队列满 | 工作线程保留同一消息重提；不再次调用 provider |
| 同键同义 | 精确重复，等同确认接收 |
| 同键异义/协议拒绝/错槽 | 管理端拒绝；工作线程和运行包内部错误，保留诊断快照 |
| 管理端提前停止 | 收口失败；不得把待上交消息算作结束 |
| 正式读回漂移/冲突 | 零后继派发，槽进入具名非成功或等待；消息不补造事实 |
| provider 资源/内部错误 | 仍形成结构化非成功消息；外层只能按同一工作身份恢复 |
| 进程崩溃 | 不承诺持久消息投递；恢复以同幂等工作重放和正式事实读回收敛 |
