## 1. 修订来源与范围

执行智能体第四次退回确认：v0.1 要求共享子图同次只读一次，但冻结的保存定义读取只有单根入口；两个保存根共享定义 C 时，每次建立新递归上下文，会重复读取 C 并重复扣预算，计算应用事后合并无法修正真实用量。

本计划新增批量共享闭包读取 DTO/入口并迁移二次计算应用的保存定义预取，同时只澄清既有方向前置核验与任务尾 G 失败回显，不新增方向字段或业务步骤。v0.1—v0.4 的生产白名单、其它 DTO、建立幂等、当前绑定读取、准确 F、provider、K、上下文、退役、记录和完成声明继续有效；执行必须同时读取五个版本，冲突处以 v0.5 详细设计和本计划为准。

禁止修改规范、规划、详细设计、计划、索引、L1、持久结构、单根读取 ABI、非计算消费者、RC、持久二次实例、算法和生产装配。代码结果提交不得包含本次计划支撑文档。

## 2. 实施增量

### A1 特征 owner 批量读取

在`海中鱼巣/领域/数据服务.特征类.ixx`：

1. 按 v0.5 详细设计第 3 节增加批量合同版本、请求、根回执、含完整原请求回显的结果及`批量读取标量派生定义`；原单根 DTO/入口字节不变。
2. 复用一个既有`标量读取上下文`、一个 mutex 作用域和同一 G/H，依严格升序唯一根组逐项调用现有递归展开；定义、关系、叶、值均按稳定编码联合去重和增量计费。
3. 展开全部根后为每根形成左右叶闭包，统一形成严格升序的完整定义组、基础叶组和联合用量；成功谓词按设计逐项互证全部根、闭包、来源、预算及 G 守卫。
4. 任一根失败整批清空成功载荷并保留真实用量；禁止部分成功、跨调用缓存、逐根内部回退或新增持久事实。

### A2 计算应用单次预取

在`海中鱼巣/业务/计算.二次特征.ixx`：

1. 在任何来源读取前，从全部局部图输入和根输出收集直接保存定义身份，排序去重；非空时按设计机械预算恰调用一次批量入口。
2. 批量成功后令 N 为联合定义数，先检查 N 个图项、`2*N`条来源边及乘法溢出、联合叶和联合材料四类剩余额度；再分别只扣一次并填充 saved/leaves。
3. 后续保存定义展开必须命中 saved，未命中为内部不一致，不再调用单根入口，也不重复扣图项、来源边、叶或材料；本次局部项仍各扣一个图项和两条来源边。显式准确 F 已在 leaves 时不再读取或计费。
4. 共享定义只计算和回执一次，但每条来源边和从各根/局部前缀出发的深度继续独立核验；任何失败不回退逐根读取。

其它施工步骤全部沿 v0.1—v0.4。

### A3 方向文字收口

1. 需求方向继续在请求 G 下权威核验目标宿主、全部基础叶宿主成员关系和当前采用，并在计算后尾守卫；这些是入口控制前置，不新增 DTO 字段。`成功()`只互证原请求及结果包已有字段，不声称离线重证未回显的 L1 快照。
2. 任务方向在需求子调用完成后尾 G 漂移时，顶层返回`事实代次漂移`并保持非成功，完整保留方向子结果作诊断；不得清空、改写子结果状态或继续消费。调用前失败仍无方向子结果。

## 3. S0 重新门禁

执行从索引登记的 v0.5 plan/design 真实 blob 重新 S0，并核对：

- `main == origin/main`、index 空闲、正式 HEAD 不早于 v0.5 发布提交；
- 原白名单 WIP、现有递归上下文和单根读取尚可安全复用，没有异主文件/语义冲突；
- 当前计算应用确为每个新保存根调用单根入口，且 saved/leaves 缓存无法阻止 DATA 内部重复读；
- 新增批量 DTO/入口只修改特征 owner 与计算应用，不要求 L1、持久结构、工程登记或非计算消费者变化。

若实现要求改变 L1、持久字段、owner、单根 ABI或白名单外消费者，再次退回计划支撑；普通代码、编译和白名单内机械错误由执行智能体处理。
