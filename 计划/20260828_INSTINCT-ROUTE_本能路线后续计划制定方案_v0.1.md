## 1. 用途与权威边界

本文件用于在第一阶段发布后，按真实代码结果逐阶段形成后续规范、业务流程图、详细设计和叶子代码计划。它保存本能路线的目标、依赖顺序、阶段边界、激活门禁和不得复活的旧方向，避免后续窗口各自从聊天或过期材料重新推导整条路线。

本文件：

```text
是：路线输入、阶段依赖和后续计划制定约束

不是：机器逻辑规范
不是：详细设计
不是：代码实施计划
不是：计划索引当前项
不是：对任何代码切片的施工授权
```

本文件不进入 `计划/计划索引.md`，不产生 `待激活` 或 `可执行` 状态。任何阶段在成为正式计划前，必须重新读取届时的 `HEAD`、计划索引、正式规范、有效设计、当前接口、生产调用点、代码知识和所有权；本文件与届时正式事实冲突时，以正式事实为准。

阶段一、阶段二的已发布代码和归档材料只作为当前路线前置，不得由后继计划改写或复活；后继必须从届时当前 `HEAD` 重新核对其公开 ABI 和验证边界。

## 2. 路线目标

本能路线的目标是形成第一条不依赖高级思维、因果反推、候选世界、自然语言推演或后天学习的确定性生命运行链：

```text
本能根运行锚点
-> 根特征发生真实变化并留下状态 / 动态证据
-> 安全与服务被动维护
-> 双根需求 fresh 自检
-> 根差距展开为具体现实需求
-> 活动需求取得任务承接
-> 任务筹办、执行、正式结果和结算
-> 自我形成继续 / 结束 / 等待 / 取消决议
-> 下一治理轮重新读取当前事实
```

四组本能能力的职责固定为：

| 本能能力组 | 职责 | 是否创建普通任务 |
| --- | --- | ---: |
| 被动维护本能 | 按正式时间、事件和规则维护安全值、服务值及维护游标 | 否 |
| 自我治理本能 | 双根自检、根差距展开、活动需求重判和后继决议 | 否 |
| 任务治理本能 | 任务承接、筹办、执行编排、结果读回和轮次收束 | 否，它们治理任务 |
| 现实与外设本能 | 观察、扫描、跟踪、识别、设备检查、控制和使用 | 是，由普通需求和任务组织 |

```text
+ 比较注册和根目标合同
```

因此，附件中的 R0 规范纠偏和 R1 出生基座不再建立第二套后继计划。后续第一项必须消费第一阶段的已发布结果，不得重造根身份、角色关系、第二 owner、第二索引或另一份线程出生材料。

### 3.2 根参数已经固定

```text
M = INT64_MAX
A0 = V0 = M / 2 = 4611686018427387903
安全根目标 = M
服务根目标 = M
```

安全和服务角色由固定幂等身份组恢复，并由值式锚点具名绑定。角色不建立角色节点、角色关系、持久 owner 或查找索引。

### 3.3 当前值、状态和动态严格分工

```text
特征当前值
= 自检和目标比较的唯一权威输入

状态
= 某事实截止下特征值的正式记录

动态
= 前后状态变化及其来源的正式记录
```

状态和动态可以用于历史、解释、审计、因果材料和自检触发，但不得代替当前值参加需求比较，也不得通过“最后一条动态”反推当前值。

除第一阶段的首值、初始状态、零动态特殊入口外，真实值变化必须经统一变化入口形成一致提交语义。附件提出的“先发布当前值，状态 / 动态失败后补写”不属于当前授权方向；后续设计必须先证明如何原子形成当前值选择切换、状态和动态，不能把部分发布包装成成功。

### 3.4 候选结构必须先做复用裁决

附件中的下列内容只表示职责需要，不冻结物理实现：

```text
在状态事实中追加特征值身份字段
新增本能被动动作 owner
新增动作实例 DTO
新增特征变化服务名称
新增跨 owner 事务形状
```

后续计划必须先审计现有特征值事实、状态 / 动态关系、方法动作事实、L1 事务能力和公开服务。已有正式关系或强类型载体能表达时直接复用；只有现行机器语义确实不可表达时，才在正式规范中建立最小新合同。

### 3.5 A、V、阈值和游标分账

```text
A = 安全根当前值
V = 服务值当前值
L / H = 安全根定义或规则中的阈值材料
时间纪元 / 上一已维护完整秒 = 维护游标
```

不得把 A、V、L、H和时间游标塞入同一个 `variant` 当前值，也不得让维护游标参加根需求目标比较。

### 3.6 任务结果不是可分配资源

本路线永久退出通用结果容量、结果争用分配、冻结成员分配版本、结果消费分配记录和 self 结果争用优先级。

```text
正式任务结果
= 某次方法执行、动作后状态 / 动态及归因的事实线索

需求是否满足
= 该需求在自己的裁决时点 fresh 读取目标合同和当前特征值后形成的结论
```

若当前任务明确由某个上级任务调用，则该直接调用关系对应的结果可以在本轮正式读回后结算；其它可能因同一现实变化受益的需求或上级任务，不抢占、不分配该结果，在自己使用或再次获得执行机会时重新 fresh 裁决。现实中的数量、所有权、独占和冲突仍由真实事实 owner 在动作执行前通过授权、安全和原子事务处理。

### 3.7 轮次收束后不自动重筹办

```text
本轮目标未达成
-> 形成结构化核算结论
-> 当前轮次收束
-> 交给自我形成继续 / 结束 / 等待 / 取消决议

只有“继续”
-> 建立新轮次
-> fresh 重读
-> 重新筹办
```

旧“目标未达成直接生成下一筹办包 / 重筹办意图”不能进入后续计划。

## 5. 分阶段计划制定方案

### 5.1 阶段一：本能根运行锚点

状态：已发布并退出执行队列。

正式输出：

```text
可恢复的唯一根身份组
+ 首值 / 初态
+ 根目标合同
+ 两个长期根需求
+ 值式本能根运行锚点
+ 自我线程创建前锁定
```

本阶段排除：动态迁移、周期自检、被动维护、具体现实需求、任务、任务结果和结算。

路线后继激活门禁：第一阶段精确提交和普通推送；发布后按新 `HEAD` 证明锚点真实进入启动及自我线程创建链，并明确实际 ABI、未运行矩阵和遗留边界。

### 5.2 阶段二：真实当前值变化与状态 / 动态原子记录

状态：已发布并退出执行队列；提供 `发布特征当前值变化与中性记录_v1`、`读取特征当前值变化记录_v1` 及特征 / 状态 / 动态三 owner 的 L1 v2 原子发布。

目标：建立真实特征值变化的唯一业务入口，使一次实际变化在同一正式提交语义下形成新值事实、当前选择切换、新状态和前后状态动态；无值变化不得伪造状态或动态。

直接前置：阶段一已发布；现行 L1 事务能力、特征 / 状态 / 动态 owner 和公开 ABI 已按新 `HEAD` 完成可达性审计。

必须形成的正式输出：

```text
旧当前值与请求绑定
+ 新值裁决
+ 新当前值选择
+ 记录新值的状态
+ 前状态到后状态的动态
+ 来源动作 / 方法的正式引用
+ 独立读回和完整非成功矩阵
```

明确排除：部分发布成功、事后猜测补写、从动态反推当前值、第二当前值 owner、为本阶段顺带实现被动维护规则。

激活门禁：三类 owner 的一致提交语义、来源身份、重放、已可能发布、失败回收和读回合同全部在正式设计中冻结；执行者不需要临场决定跨 owner 事务形状。

### 5.3 阶段三：安全 / 服务被动维护

目标：以阶段二统一变化入口实现安全事件维护、服务值完整秒维护和必要的生存安全被动回归，同时把 A、V、L/H和维护游标彻底分账。

直接前置：阶段二已发布；6120、6150、6160、6170 的届时有效规则和版本语义一致。

当前代码前置补充：有限 N 分区中性原子事务、被动维护游标、单调完整秒、绝对 UTC 时间证据、安全根定义、永久变化账事实代次完整读回和规则版本 1 空覆盖裁决已经分别发布。UTC 不能由单调完整秒倒推；生产连续覆盖必须使用永久账形成事实代次。当前最早缺口是把已消费事实代次水位加入唯一维护游标，并在生产启动以账登记代次建立首次水位；同纪元推进仍留给后继完整维护原子事务。

必须形成的正式输出：

```text
正式时间 / 事件输入
-> 规则版本绑定
-> A / V 新值候选
-> 维护游标推进
-> 统一变化入口
-> 状态 / 动态和动作来源读回
```

同一完整秒内的安全事件、服务维护、回归和游标推进顺序必须在设计中唯一冻结。循环次数、线程 Tick、消息到达次数和等待超时不得冒充完整单调秒。

明确排除：需求自检、具体现实需求、任务、把 L/H 写入 A 当前值、把游标写入 V 当前值。

激活门禁：被动规则、数值边界、同秒次序、断点恢复、重复维护和无值变化行为均已冻结并可由真实读回验证。

### 5.4 阶段四：两拍读取与双根 fresh 自检

目标：在每轮自我治理中先维护、后冻结新截止，并分别复用现有需求当前满足裁决读取 A、V 当前值，与两个根目标合同比较。

固定时序：

```text
冻结 Gpre
-> 读取维护输入
-> 执行阶段三被动维护
-> 冻结 Gpost
-> 按 Gpost 读取本能根锚点和当前值
-> 裁决安全根需求当前满足
-> 裁决服务根需求当前满足
-> 形成两个独立结构化结果
```

直接前置：阶段三已发布；根需求锚点可在 Gpost 完整读回；现有需求当前满足裁决的生产入口和结果矩阵经新基线核对可复用。

明确排除：用 Gpre 读取维护后的值、读取动态后值代替当前值、为双根另造比较器、在本阶段创建具体需求。

激活门禁：Gpre/Gpost 的来源、漂移处理、双根独立结果、触发与正式读取分工已经冻结。

### 5.5 阶段五：双根差距到具体现实需求

目标：当根需求存在正式正差距时，通过出生本能方法形成具体现实需求候选，并经统一需求入口建立或精确复用正式需求。

直接前置：阶段四已发布；安全根和服务根各自的候选产生条件、来源材料、目标合同映射和去重身份已冻结。

必须保持：

```text
安全根满足 -> 不生成安全子需求，根需求继续存在
安全根有差距 + 正式安全因果 / 风险材料 -> 生成安全候选

服务根满足 -> 不生成服务子需求，根需求继续存在
服务根有差距但无有效人类服务触发 / 合同 -> 不虚构服务候选
服务根有差距 + 有效服务触发 / 合同 -> 生成服务候选
```

明确排除：直接调用 L2 CRUD 冒充需求准入、从根值数值机械生成任意现实目标、把根需求退出、顺带创建任务。

激活门禁：两类本能展开方法的输入、输出、幂等、冲突、材料不足、统一准入和独立读回全部冻结。

### 5.6 阶段六：活动需求选择与任务承接

目标：从正式活动具体需求形成当前处理对象，并通过统一任务承接入口建立或复用任务、轮次及必要关系。

第一版边界：先闭合 `0` 或 `1` 个合法活动具体需求。多个合法活动需求之间的唯一选择规则未由届时正式规范冻结时，必须结构化停止，禁止按创建时间、消息顺序、稳定编码或容器位置任选。

直接前置：阶段五已发布；需求活动集读取、当前选择、任务承接和完整 T→D 关系读取的正式 provider 已存在或在本阶段设计中作为同一 owner 的直接闭环形成。

必须形成的正式输出：

```text
活动需求重判
-> 0 / 1 / 多项结构化裁决
-> 对唯一需求建立或复用任务
-> 正式任务轮次和任务关系
-> 独立读回
```

明确排除：任务结果、方法动作、结果容量、多需求优先级的临场发明。

激活门禁：任务承接的 owner、幂等、首轮次、关系闭包、0/1/N 和历史兼容边界已经冻结。

### 5.7 阶段七：任务筹办、执行、正式结果和按关系结算

目标：让一个由具体需求承接的任务完成筹办、方法选择、执行前 fresh 复核、授权 / 安全、动作执行、结果与状态 / 动态读回，并按明确调用或使用关系形成结算。

固定业务顺序：

```text
读取任务、轮次、T->D 和目标合同
-> fresh 判断当前目标是否已满足

已满足：
    零动作
    -> 形成该需求自己的满足核算

未满足：
    方法选择和冻结
    -> 授权、安全、当前性复核
    -> 动作执行
    -> 正式当前值 / 状态 / 动态 / 任务结果读回
    -> 按明确上级调用关系结算直接调用者
    -> 其它相关需求或上级任务延后到自己使用时 fresh 结算

全部本轮必结项有结构化结果
-> 当前任务轮次收束
```

直接前置：阶段六已发布；阶段二变化入口可被真实方法动作复用；方法动作、任务工作包、完成消息、结果读回和结算关系的来源全部可达。

明确排除：结果容量、结果分割或争用、把任务 / 方法优先级当作结果归属、一次性结算所有可能相关需求、旧结果缓存替代 fresh 当前值、目标未达成自动重筹办。

激活门禁：直接上级调用关系、延后结算触发、0/N T→D、执行前已满足零动作、逐关系失败矩阵、轮次收束条件和价值 / 预算 / 归因防重复边界已经正式冻结。

### 5.8 阶段八：自我后继决议与连续两轮

目标：消费已收束任务轮次和明确结算结果，由自我形成继续、结束、等待或取消决议，并证明至少连续两轮不会绕过 fresh 读取。

直接前置：阶段七已发布；self 复核载荷携带正式任务、轮次、结算身份和共同截止，可由 self 独立读回。

必须形成的正式输出：

```text
轮次收束
-> self 独立读回
-> 继续 / 结束 / 等待 / 取消
-> 新轮次或终态
-> 下一轮 fresh 自检
```

明确排除：manager 替 self 猜决议、线程缓存代替正式结算身份、上行桥直送未读回结果、自动重筹办。

激活门禁：四种决议的来源、优先序、幂等、漂移、消息代次、读回和线程停止边界全部冻结。

### 5.9 阶段九：现实 / 外设本能接入

目标：在确定性进程内本能闭环已经通过后，以新计划身份接入 D455 等现实观察和设备能力。

每一种本能方法必须具名冻结：

```text
作用对象
读取或改变的特征类型
观察上下文与直接作用范围
前置条件和授权
输入和正式材料来源
结果和失败语义
状态 / 动态记录方式

```

旧过期外设计划只作参考，不得原地恢复，不得用设备日志、UI或一次成功码代替正式事实与独立读回。

激活门禁：阶段八服务验收通过；目标设备能力的当前生产接口、权限、安全、场景和验证边界已经按新基线重新设计。

## 6. 后续叶子计划的统一形成规则

每次只为当前最早阶段建立一份能够独立施工的叶子计划。计划至少必须回答：

```text
1. 本阶段消费哪个已发布提交和公开 ABI？
2. 哪些已有能力直接复用，哪些需要扩展，哪些确认缺失？
3. 唯一 owner、数据来源、当前选择和历史事实分别是谁？
4. DTO、函数、物理文件、依赖方向和装配点在哪里？
5. 首次、精确重复、同键异义、漂移、资源失败、内部错误和已可能发布怎样分账？
6. 写入事务、生命周期、退出、恢复和独立读回怎样闭合？
7. 由哪个真实生产消费者证明，而不是 provider-only 自测？
8. 哪些结果仍为 NOT_RUN，哪些证据只证明静态 / 编译 / 运行 / 集成？
9. 哪些文件和语义属于其它活动所有者，必须保持零写？
10. 完成声明最多能到哪一层，尚未证明什么？
```

若仍需执行者决定机器语义、字段来源、事务形状、失败映射或正式消费者，计划不得登记为 `可执行`。

## 7. 跨阶段不变量

```text
当前值始终是需求比较权威
状态 / 动态始终是记录和证据，不是第二当前值
根需求长期存在，满足时不退出
本能治理方法不包装成普通任务
普通现实动作必须经过任务、授权、安全和 fresh 当前性复核
同一事实裁决中的多项读取必须具名绑定共同截止
动态只能触发重读，不能携值替代重读
根角色不建立第二 owner、角色节点或查找索引
任务结果不具备通用容量或所有权
多个需求可被同一现实状态分别满足，但价值 / 预算 / 奖励 / 贡献不得重复领取
现实稀缺性在动作执行前由真实 owner 裁决
轮次未达成不自动重筹办
无正式规则、材料、场景、权限或完整集合时 fail-closed
旧计划、聊天、日志、UI和过期代码图不产生施工授权
```

## 8. 端到端完成场景

本能路线最终至少需要以下独立运行场景，且每项必须通过正式入口、结构化结果、权威终态和独立读回证明。

### 8.1 纯被动服务值变化

```text
完整秒到达
-> V 当前值真实变化
-> 状态 / 动态形成
-> 服务根自检重新读取 V 当前值
-> 有差距但无有效人类服务触发
-> 不虚构具体现实服务需求
```

### 8.2 服务本能连续两轮

```text
有效人类服务触发 + 服务根差距
-> 具体服务需求和任务
-> 第一轮执行后仍未满足
-> 轮次收束
-> self 决定继续
-> 第二轮执行后目标满足
-> 正式服务结算改变 V
-> 下一轮服务根自检读取新 V
```

### 8.3 安全本能闭环

```text
安全事件
-> 被动维护使 A 下降
-> 状态 / 动态形成
-> 安全根自检发现差距
-> 具体安全需求和任务
-> 安全动作改变现实
-> 正式安全结算改变 A
-> 下一轮重新读取 A 并比较
```

### 8.4 共享状态、独立结算

```text
任务 A 改变当前状态
-> A 的明确直接调用关系完成结算
-> 相关任务 B 获得执行机会
-> B fresh 读取自己的目标和当前值
-> 已满足则零动作形成 B 自己的结论
-> 不分配 A 的结果，不扣减结果容量，不重复领取价值或贡献
```

共同回归范围至少覆盖：精确重复、同键异义、旧 G 漂移、无值变化不造动态、部分材料失败、已可能发布、进程重启恢复、动态缺失不改变当前值比较、执行前目标已满足零动作、目标未达成不自动开下一轮、多活动需求未裁决时不任选。

## 9. 当前下一步

阶段一、阶段二、有限 N 事务、时间 / 双水位游标、安全根定义、生产阈值、单秒规则内核、服务时间裁决、服务活动 v2、永久变化账、主动安全来源规则、UTC 窗口裁决和事实代次空覆盖裁决均已形成正式代码结果。当前代码与 4230 / 6170 已确认：待维护区间可以覆盖任意 I64 时间跨度，但现有需求时间裁决只证明当前观察边界这一秒，单秒内核不得被无界循环调用；因此当前唯一叶子顺序修订为：

```text
发布并登记 INSTINCT-STAGE3-PASSIVE-MAINTENANCE-BATCH-KERNEL
-> 以有限规范事实段覆盖待维护完整秒区间
-> 用地板和、比例边界和安全阈值的固定边界跳跃形成 A/V 候选
-> 与现有单秒内核逐秒参考结果等价
-> 禁止算法复杂度依赖待维护完整秒总数
-> 后继由同 G0 历史事实完整读回形成事实段
-> 再把双水位、A/V 候选和统一变化记录放入完整维护原子事务
```

当前新 `HEAD` 审计确认：事实代次完整覆盖、规则版本 1 空覆盖、双水位游标、与任意长时间跨度无关的批量纯算法，以及服务合同 owner 内的服务维护永久历史账和 `(Gstart,G0]` 完整范围读回已经闭合。历史账读取要求排除起点不早于其登记事实代次；现有游标只保存完整秒和主动安全变化事实代次，无法为服务历史提供可恢复增量覆盖边界。若从当前集合、当前 `G0` 或启动顺序猜起点，会漏掉已经退出的合同、状态、进展和准备。

`INSTINCT-STAGE3-SERVICE-HISTORY-WATERMARK` 与 `INSTINCT-STAGE3-HARD-DENIAL-RULE-UNIVERSE` 已分别形成正式代码结果。当前生产启动已建立/迁移 v3 三水位游标，但现有 `本能被动维护基础快照_v1` 仍承载并读取 v1 游标，无法把已消费主动安全变化事实代次和已消费服务维护历史事实代次共同交给后继维护。
