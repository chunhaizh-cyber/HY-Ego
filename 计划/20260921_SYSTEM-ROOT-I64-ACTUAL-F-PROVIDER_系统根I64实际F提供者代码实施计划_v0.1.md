## 1. 目标、范围和完成条件

本计划实现6130双根的系统根I64定义 provider，及8121所需的“按存在持有特征变更并返回实际F”组合 provider。前者形成或恢复安全、服务两个FT和各自根专用目标判断规则；后者只为指定存在取得或补齐该根的初始准确F、IF/R和当前采用，并返回正式读回的实际F。

完成条件：双根定义和实际F提供者均按第4—6节的固定原请求、首次材料、恢复、读回和失败合同实现；专项探针和隔离Debug/Release构建达到第8节要求；只发布本计划允许文件和专属记录。

明确排除：8121阶段21、根目标合同/根D/根列表项、线程、运行门、普通应用启动接线、根值后续修改、状态/动态/因果、需求、FCr归并、非I64类型、外设先天和后天类型的迁移或行为改变。

## 2. 正式依据与当前事实

- 1120 v0.9、4120 v0.16：系统根初始化来源只给明确系统根FT使用；固定版本化原请求和首次写入材料是来源见证；不建立外设、根角色节点或通用第三来源登记。
- 6130 v0.16 §2—§3、§13：双根均为`0..I64_MAX`、缩放`1/1`、初始值`I64_MAX/2`、目标`I64_MAX`的无外部物理单位标量；比较量化的单位/维度/分量角色均为各自FT；根定义 provider 与后续根冷启动 provider 分工。
- 4115、7150、8121：准确F不可原地改写，R不是F；当前采用必须显式写入并正式读回；阶段21只消费成功提供者返回的实际F。
- 当前`数据服务.特征类.cpp`的`创建先天I64特征类型`和`读类型`强制一条外设来源关系，不能承载系统根来源；`特征类数据服务`已有同owner首次材料读取、固定幂等写入收敛、I64比较绑定和准确F核验能力。
- 当前`特征概念应用服务::处理实例特征R观察`在形成新R时可形成F/IFR，唯一R命中不出生F，且从不写当前采用；`存在类数据服务::变更当前采用`已经是唯一当前采用写入入口。

## 4. 系统根 I64 定义 provider

### 4.1 公开值式合同和固定身份

在`数据服务.特征类.h`新增以下根专用值式身份和结果，不修改`先天I64特征类型规格`及`创建先天I64特征类型`：

```cpp
enum class 特征类型来源 : std::uint8_t { 外设先天 = 1, 后天派生 = 2, 系统根初始化 = 3 };
enum class 系统根I64角色 : std::uint8_t { 安全 = 1, 服务 = 2 };
struct 系统根I64定义请求 { std::uint32_t 版本; std::uint64_t G0; 系统根I64角色 角色; };
struct 系统根I64目标判断规则 { 特征类型身份 FT; 稳定编码 单位, 维度, 分量角色;
  std::int64_t 初始值, 目标值; std::uint32_t 规则版本; };
struct 系统根I64定义事实 { 特征类型来源 来源; 特征类型身份 FT; 系统根I64目标判断规则 规则;
  std::uint64_t 首次H, Gread; };
struct 系统根I64定义结果 { 状态、原请求、首次写入回执、定义事实、发布确定性; };
```

入口固定为`特征类数据服务::形成或读取系统根I64定义(const 系统根I64定义请求&)`。安全和服务的固定写入身份分别为`0x524F4F5446545331`和`0x524F4F5446545631`；它们只用于该请求重放，不能作为FT、规则或任何节点编码。请求版本仅接受`1`，`G0`非零且等于定义owner当前G。调用者不提交任意值域、名称、外设、单位或规则；角色唯一决定下表完整原请求：

`特征类型来源`是本入口及其值式读回的带标签来源合同：系统根成功结果恒为`系统根初始化`；旧先天入口的成功结果只可为`外设先天`，后天入口（未来另行实现）只可为`后天派生`。该枚举不充当FT身份、持久节点、关系、来源索引或实例事实字段。根规则读回中的来源类别属性必须为`系统根初始化`，否则根入口返回具名非成功；不得仅由函数名、角色、名称或缺少外设关系推断来源。

| 字段 | 安全 / 服务根的固定值 |
| --- | --- |
| 来源 | `系统根初始化来源`；无外设来源关系 |
| 表示、缩放、允许域 | I64、`1/1`、单一闭区间`[0,I64_MAX]` |
| 单位/维度/分量角色 | 同一新FT的本地引用；三项均等于该FT但字段语义不合并 |
| 初始/目标与规则 | `I64_MAX/2`、`I64_MAX`、规则版本`1`、非负精确`目标-当前` |

### 4.2 物理写集、恢复和读回

定义owner初始化一个根规则内部结构，使用独立固定初始化身份建立“根规则归属关系、规则版本属性、初始值属性、目标值属性、来源类别属性、来源角色属性”六个元结构节点；这些是特征定义内部元结构，不是外设、单位、维度、分量角色或根角色节点。首次材料和交付必须完整读回；冲突、退出、漂移、资源失败或发布未知均零交付。

每个根的固定写集同笔建立FT、定义归属、FT到自身的单位关系、一个根目标判断规则节点及其归属/属性关联。规则节点保存版本、来源类别`系统根初始化`、角色、初始值、目标值；来源和角色都是规则内容而非独立节点。写集不得含`外设来源关系`，也不得创建任何实例F、IF/R、当前采用或需求事实。现有默认R规则可按当前定义结构附着，但它不是根目标判断规则，也不能替代它。

首次材料已存在时，入口必须只读该固定身份的原首次规范化写集和首次写入结果，逐项比对角色派生的完整写集、owner和映射；不同即`幂等冲突`。首次不存在时才派发同一写集。派发后或跨进程恢复均从首次材料取得映射，在当前`Gread`读回FT、规则节点、所有关系和值并二次守卫。任何多关系、外设关系、非自引用量化、错误值域/初始/目标、退出、缺项、异义映射或截止漂移都是具名非成功；`已可能发布`只保留原完整请求供重放。

根专用`系统根I64目标判断规则`是6130的目标判断规则，不调用现有`建立I64比较绑定`：后者要求输出FT集合，而6130 §7.1已冻结根判断为无持久输出类型的即时`I64_MAX-当前值`。规则结果不得持久化为FT、F、R、状态或动态。执行者不得把未具名的通用比较输出类型补造为系统根来源。

### 4.3 旧入口隔离

`创建先天I64特征类型`、`读取先天I64特征类型`及其截止读保持外设先天的既有ABI和行为；系统根FT进入它们必须结构化拒绝，不能以空、FT自身或虚构外设填充`外设提供者`。新根入口只能读取自己的固定首次材料；普通调用方不得传任意固定身份或用该入口建立第三个根。

## 5. 按存在取得初始实际F provider

### 5.1 DTO、位置和成功结果

在`应用服务.特征概念类.h/.cpp`新增`本能根I64实际F请求`、`本能根I64实际F结果`和专用状态，入口为：

```cpp
特征概念应用服务::形成或读取本能根I64实际F(
    const 本能根I64实际F请求&) noexcept;
```

请求包含版本`1`、`G0`、根角色、唯一持有存在`E`、`定位特征位置`、独立的IFR/F出生/FCv/当前采用幂等身份，以及既有IFR/R规则/候选/组织/概念/当前采用读取预算。`G0`只是在调用根定义前的初始当前性门：首次根定义可以合法推进事实代次，后续跨owner步骤绝不得继续把旧`G0`作为读取或写入截止。角色只用于向第4节取得固定FT和初始I64；不得进入节点、关系或当前采用键。调用前核验位置的存在等于`E`、全部键和预算有效、四类键互异；安全和服务一次调用不得共享任何写键。

成功结果必须回显完整原请求、根定义读回、同一成功路径中的IFR结果、当前采用结果、准确F事实和`实际F`。`成功()`要求：根定义和规则完整；实际F有效且为读回的根FT、I64内容等于该根初始值；当前采用事实的`E/FT/F`完全一致；IFR完整且实际F是其已发布成员；`首次H <= Gread`；最终双重读取事实代次不变。非成功不交付实际F。

### 5.2 顺序、部分恢复和幂等

1. 调用第4节根定义入口并正式读回FT/规则；失败直接映射，不能使用名称、顺序或旧先天读入口猜FT。其成功`定义事实.Gread`是第一个连续截止`G定义`；调用`概念服务_.读取当前事实代次()`并要求其成功且`Gread == G定义`，否则为当前性漂移。
2. 在`G定义`读取`存在类数据服务::读取当前采用(E, FT)`。若已有采用，读取并核验准确F、IFR成员和根初始I64；三者均一致才进入第5步。当前F类型、值或IFR成员不符属于引用/材料冲突，绝不替换、删除或原地改F。
3. 无当前采用时，只调用既有`处理实例特征R观察`形成或恢复IF/R，并把其成功结果`Gread`作为`G_IFR`。再次调用`概念服务_.读取当前事实代次()`并要求成功且等于`G_IFR`；不等于即当前性漂移。若其形成新R，必须成功取得F出生；若唯一命中，必须从正式IFR成员和准确F读回中唯一解析同FT、同根初始值的F，不能因唯一R重新出生F。零或多个候选、非I64、F已退出、IFR半结构、规则未启用、预算/漂移或出生失败均为具名非成功。
4. 取得唯一F后，以`G_IFR`、请求的当前采用键、`存在关联已知并采用{F, 预期为空}`调用现有`变更当前采用`。其成功`Gread`为`G采用`；再要求`概念服务_.读取当前事实代次()`成功且等于`G采用`。其精确重放仍只使用原完整请求；不得新建第二采用入口或用IF/R写入代替采用。
5. 以无写入路径的`G定义`、或采用路径的`G采用`作为最终`Gread`重读当前采用、IFR和准确F；所有成功读回须指向同一F且最终事实代次稳定。IF/R已形成而采用未形成是可恢复中间态；重试只按原请求从第1步重新取得连续截止，不得复用旧`G0`执行第2—5步。采用已形成而IFR/F不闭合、或同键首次材料异义，必须失败而非补造平行事实。

该入口只形成初始根F，不授权后续根值改变。已有不同当前根F、任何动态/状态驱动值、服务事件、任务结果或外部观察都不得借该入口替换当前采用。

## 6. 失败映射、所有权和调用边

根定义失败精确区分入口拒绝、当前性漂移、幂等冲突、首次材料缺失/不一致、定义或规则退出、引用冲突、已可能发布、资源失败和内部不一致。实际F入口还区分当前采用读取/写入失败、IFR读取/结构失败、R规则未启用、唯一R无可验证F、F出生失败、准确F类型/内容不符与最终读回漂移。只有`bad_alloc`、`length_error`映射资源失败；不可证明的一般异常映射内部不一致。

特征服务是FT/规则唯一写入方；原子出生服务写F；概念服务写FCv使用；存在服务写IF/R及当前采用；应用服务只排序调用和组合值式结果。没有跨owner原子写集，也不把任一服务的幂等身份复用到另一owner。阶段21以后仅消费该入口成功结果，仍不得在本计划实现其调用、缓存或错误映射。
