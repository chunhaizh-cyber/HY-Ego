## 1. 目标、范围和完成条件

本计划完成两个连续但分责的闭环：

1. 在普通应用系统初始化中形成或恢复“安全值”“服务值”两个先天定义I64 FT，并由概念唯一owner分别形成或恢复引用对应FT完整域`[0,I64_MAX]`的显式顶层特征概念；
2. 实际F提供者只消费上述初始化交付，为指定存在形成或恢复初值`I64_MAX/2`的单值概念、准确F、IF/R和当前采用，并正式读回唯一实际F。

完成条件：旧强制外设的I64类型创建/读取公开入口退出且合法调用方迁移；双FT和双完整域概念进入普通应用初始化并可跨进程恢复；存在类按`(holder,F)`精确读取已知关系并按`(E,FT)`选择唯一IF/R，使同一存在的安全值与服务值两组实际F、IF/R和当前采用可以独立读写；实际F provider不写FT或完整域概念；第8节专项探针、隔离Debug/Release构建和静态检查通过；只发布允许文件及专属记录。

明确排除：阶段21根目标合同、根D、根列表项、线程、运行门、需求产生、根值后续换代、状态/动态/因果、非I64类型和后天派生算法。

## 2. 正式依据与当前事实

- 1120 v0.10、4120 v0.17、6130 v0.17：类型来源是外设能够获取、先天定义、后天派生；安全值/服务值属于先天定义，初始化不要求外设提供者。
- 2220 v1.23、7160 v0.8：FT与完整域概念身份独立；完整域概念是普通零上位顶层概念，可在规范明确的先天FT初始化阶段形成。
- 8120 v0.16：双FT/完整域概念必须在普通应用系统初始化、世界实例与自我产生前交付；实例路径不得补建。
- 4115、7150、8121 v0.6：准确F不可原地改写；单值概念、IF/R和当前采用分别由概念/存在/特征owner处理，阶段21只消费实际F provider成功结果。
- 当前`创建先天I64特征类型`和`读取先天I64特征类型事实`把全部基础I64类型绑定到唯一外设关系；当前概念服务和比较服务只需读取正式I64类型及完整域，不应依赖外设来源。
- 当前纯概念API已支持`纯I64特征概念定义{FT,域}`、`显式顶层`、固定幂等创建、首次材料恢复和正式读回；当前`确保FCv`会从同FT概念组计算单值概念直接上位，缺完整域上位时返回规则缺失。
- 执行期专属探针确认：`存在类数据服务::读取实例特征IFR(E,FT)`当前把`E→IF`组强制为全局唯一，并直接把唯一IF的全部F与请求FT比较；同一E已有安全值IF/R后读取服务值IF/R返回`引用冲突`。这违反4115“同一`(E,FT)`至多一个当前IF”，不是特征概念层可以合法绕过的业务失败。
- v0.6修正后的专属探针继续确认：服务值F的四owner原子事务已以共同事实代次发布，但发布后`读取原子I64holder(holder,F)`把同一holder的全部已知F关系强制为全局唯一；安全值F已经存在时无法精确读回新服务值F，结果降为`已可能发布`。这违反1130、4110和7150允许同一存在保存多个正式准确F的现行模型。
- v0.7首次完整路径通过后，第二进程在普通应用U64组元结构恢复处失败。精确证据为：固定键首次请求G0=14、首次发布H=15、重启当前G=33，`登记U64组结构_B2`取得精确重复后错误要求当前截止等于原G0，因而返回`已可能发布`；合法后继事实使当前截止前进不应破坏固定首次材料重放。
- v0.8修正后，第二进程已经恢复U64组元结构、特征结构、存在结构、场景结构和纯概念结构；随后`登记特征概念出生使用结构`在固定键首次请求`G0=25`、重启当前`G=33`时返回`旧格式不支持`。当前代码在读取该扩展的首次材料前，先以旧`G0`调用`已发布纯概念结构_v2`；同文件`登记存在概念两组结构_v1`也有相同前置判断。纯概念结构仍在当前截止正式可读，错误来自把扩展首次写集基线与依赖结构当前读回截止混为一体。

## 4. 通用I64基础FT合同与旧入口退出

### 4.1 DTO与来源

删除`先天I64特征类型规格/信息`、`创建先天I64特征类型`、`读取先天I64特征类型`和`读取先天I64特征类型事实`公开入口，替换为：

```cpp
enum class 特征类型来源 : uint8_t { 外设能够获取=1, 先天定义=2, 后天派生=3 };
struct I64基础特征类型规格 {
  特征类型来源 来源;
  optional<稳定编码> 外设提供者;
  稳定编码 单位;
  uint64_t 缩放分子, 缩放分母;
  vector<特征I64闭区间> 允许集合;
  optional<I64特征域形成参数> 域形成;
};
enum class I64基础特征单位绑定 : uint8_t { 既有稳定单位=1, 新FT自身=2 };
struct I64基础特征类型形成规格 {
  特征类型来源 来源;
  optional<稳定编码> 外设提供者;
  I64基础特征单位绑定 单位绑定;
  optional<稳定编码> 既有单位;
  uint64_t 缩放分子, 缩放分母;
  vector<特征I64闭区间> 允许集合;
  optional<I64特征域形成参数> 域形成;
};
struct I64基础特征类型信息 { 特征类型身份 身份; I64基础特征类型规格 规格; optional<特征比较规则身份> 规则; };
struct I64基础特征类型定义请求 { uint32_t 版本; uint64_t G0; L1所有者范围写入幂等身份 幂等身份; I64基础特征类型形成规格 规格; };
struct I64基础特征类型定义结果 { 状态、原请求、首次发布H、Gread、正式回执、类型事实、发布确定性; };
```

公开入口为`形成或读取I64基础特征类型`、`读取I64基础特征类型`和`读取I64基础特征类型事实`。形成入口只接受`外设能够获取`和`先天定义`；后天派生继续走既有派生定义合同。外设来源必须有且只有一个有效外设提供者；先天定义必须无外设提供者。两者都要求I64表示、明确单位绑定、最简非零缩放和非空规范域。`既有稳定单位`必须携带唯一有效且在`G0`可读的单位身份；`新FT自身`不携带既有单位编码，由特征owner在同一写集中以临时引用建立`FT -> FT`单位关系，正式读回的`I64基础特征类型规格::单位`必须是新FT稳定身份。不得用空编码、固定猜测编码、业务幂等身份或额外单位节点代替自身单位；该显式绑定只解决形成请求如何引用尚未取得稳定身份的新FT，不改变单位机器语义。

### 4.2 物理来源与恢复

特征定义owner以独立固定扩展初始化身份登记“类型来源属性”。所有新基础FT在同笔写集保存来源枚举；外设来源另有唯一外设关系，先天定义必须零外设关系。旧已发布基础FT若没有来源属性但有唯一合法外设关系，只读兼容为`外设能够获取`；零来源属性且零外设关系不得推断为先天定义。

形成入口使用调用者给定的固定幂等身份保存首次规范化写集和首次结果。首次存在时逐项比对完整规格、owner、键和映射；首次不存在才发布。发布未知保留原请求，重试只按同键同义收敛。成功必须从当前截止读回来源、完整规格、规则和首次H。固定键不是FT身份；不得按创建顺序或角色名称猜FT。

现有概念服务、特征值域比较服务和两份验证工具只迁移到通用读取/形成DTO；除来源字段外不改变原业务语义。旧函数符号必须在生产源码与验证源码中零引用。

## 5. 安全值/服务值先天特征概念初始化

### 5.1 固定交付

在`应用服务.特征概念类.h/.cpp`增加独立`本能先天特征概念初始化提供者`；它只持有特征服务和概念服务引用，不持有存在、场景或原子出生服务。公开DTO为：

```cpp
enum class 本能值角色 : uint8_t { 安全值=1, 服务值=2 };
struct 先天I64特征概念交付 { 本能值角色 角色; I64基础特征类型信息 类型; 纯概念事实 完整域概念; uint64_t FT首次H, 概念首次H, Gread; };
struct 本能先天特征概念初始化结果 { 状态、原请求、安全值交付、服务值交付、Gread; };
```

安全值与服务值均固定为：来源`先天定义`、I64、缩放`1/1`、完整域`[0,I64_MAX]`、无外设提供者、单位绑定为`新FT自身`；正式读回的单位使用各自FT自身作为无外部物理单位的正式解释。两者使用互异的FT首次键和概念首次键。概念定义严格为对应FT加其完整域，组织为`显式顶层`、直接上位为空；概念身份与FT身份必须不同。

### 5.2 顺序、恢复和普通应用接线

初始化按“安全值FT→安全值完整域概念→服务值FT→服务值完整域概念→共同当前截止全量读回”执行。每一步成功截止成为下一步G0；任一步发布未知或失败都保留真实前缀并返回具名非成功。重试从当前首次材料重新读回，禁止缓存旧G继续写。最终读回核验两个FT互异、两个概念互异、概念各自引用正确FT/完整域、零上位、活跃且四个事实同一`Gread`可见。

普通应用在概念服务已构造后建立临时`本能先天特征概念初始化提供者`并立即调用初始化，再以完整交付构造`特征概念应用服务`；结果作为上下文值式缓存，并由`读取普通应用本能先天特征概念初始化()`只读返回，供后续阶段和生产外验证消费。初始化失败映射普通应用装配失败，不建立世界树实例、自我或后继根材料。缓存不参与恢复，重启仍从首次材料正式读回。

## 6. 初始实际F provider

`形成或读取本能根I64实际F`保留为应用组合入口，但删除其“形成系统根定义”职责。服务构造或请求必须携带第5节已经完整验证的初始化交付；调用只选择`本能值角色`，不得提交任意FT、完整域、初值或目标值。

顺序固定为：

1. 在当前截止只读核验角色交付，FT来源为先天定义、完整域为`[0,I64_MAX]`、完整域概念与FT匹配；不完整直接失败且零写入。
2. 读取`E + FT`当前采用。已有采用时读取准确F、IF/R、单值概念使用及该概念直接上位；必须全部闭合且值为`I64_MAX/2`、上位包含对应完整域概念。
3. 无采用时调用既有`处理实例特征R观察`，由现有原子出生路径形成或复用单值概念和准确F；单值概念必须直接挂在对应完整域概念下。唯一R命中时从正式IF/R成员唯一解析同FT同值F，不重新出生F。
4. 以IF/R成功截止写当前采用，随后取得新当前截止。
5. 在最终截止重读当前采用、IF/R、准确F、概念使用、单值概念及直接上位；全部指向同一F和对应完整域概念才交付。

实际F provider不得调用任何FT/完整域概念形成入口。IF/R已形成但采用未形成是可恢复前缀；采用存在但F、IF/R、概念或上位不闭合必须失败，不得替换或补造平行事实。初值固定`I64_MAX/2`；目标`I64_MAX`由阶段21后继合同消费，不在本入口持久化。

### 6.1 同一存在多FT的IF/R读取修正

`存在类数据服务::读取实例特征IFR`继续保持原公开请求和结果不变。它读取`E→IF`当前关系组后，不再要求该组全局恰一项，而是按调用方既有关系预算有界检查候选IF：每个候选IF必须是有效普通节点且具有非空`IF→F`成员；从成员正式准确F读回其FT，同一IF全部成员必须同FT。只选择成员FT等于请求FT的候选IF；零个匹配返回`未找到`，一个匹配继续按既有合同完整读取，多个匹配返回`内部不一致`。候选关系、成员关系和后续六关系共同计入现有关系预算，禁止无界扫描、按创建顺序取第一项或忽略同E其它FT。

未匹配的其它FT之IF不进入目标投影，也不与目标FT成员交叉；空IF、同IF混合FT、同一`(E,FT)`多IF或目标IF成员未被E正式知道仍是结构错误。`提交实例特征IFR目标结构`继续复用该读取入口，因此首次服务值IF/R在安全值IF/R已存在时仍应得到目标FT的`未找到`，并按原合同新建独立IF；既有安全值IF/R不得改写、退出或并入服务值IF/R。不得修改幂等绑定、预算DTO、六关系结构、当前采用或F出生合同。

### 6.2 同一holder多F的精确已知关系读取修正

`存在类数据服务::读取原子I64holder`继续保持原公开请求和结果不变。它按请求历史截止读取holder的已知F关系组后，不再要求整个关系组全局恰一项，而是只选择`源=holder、目标=F、类型=既有特征关系类型、角色=1`的当前历史关系。零个匹配返回`未找到`，一个匹配按既有见证合同交付，多个相同端点匹配或目标关系形状异常返回`内部不一致`；其它F的合法已知关系不进入目标投影，也不构成冲突。

该修正只解除错误的holder全局单F假设，不新增预算、入口、关系类型或写入，不改变原子F四owner事务、已知关系写集、出生H、候选读取和当前采用合同。服务值F在安全值F已存在时发布后必须能按自身`(holder,F)`读回；安全值关系不得被替换、退出或误当作服务值关系。

### 6.3 U64组元结构跨进程精确重放修正

`特征值类数据服务::登记U64组结构_B2`继续使用原公开请求、固定幂等键和两节点首次写集。精确重复时，必须核验首次保存事实代次仍为`原G0+1`，当前截止不早于该首次H，并在当前截止正式读回同一承载节点与U64组属性类型节点；不得要求当前截止退回或等于原G0。首次新发布仍要求发布H为`G0+1`且发布后当前截止等于该H。

该修正不改变首次材料、稳定身份映射、结构交付或后继值事实，只允许仓库在元结构发布后已有合法后继事实时恢复同一结构。异键、异写集、首次H错误、当前截止早于首次H、节点退出或节点形状不符仍失败。

### 6.4 概念扩展结构跨进程精确重放修正

`概念树类数据服务::登记特征概念出生使用结构`和`登记存在概念两组结构_v1`继续使用原公开请求、固定幂等键和原首次规范化写集。读取首次材料后，未找到分支仍要求当前截止等于请求`G0`，并在该截止验证依赖的纯概念结构；精确重复分支则以首次材料读取交付的当前`Gread`验证同一纯概念结构仍正式可读，同时继续以原`G0`重建并逐项比较首次规范化写集、核验首次发布H为`原G0+1`。

两个分支最终都必须在不早于首次H的当前截止读回原稳定身份、节点、关系和值；不得把当前`Gread`写回请求、首次写集或首次H，不得因合法后继事实使当前截止前进而拒绝精确重放。依赖纯概念结构退出、物理清理、身份或形状变化、异键、异写集、首次H错误及当前截止早于首次H仍失败。

## 7. 失败、所有权和实施顺序

状态至少区分入口拒绝、初始化交付不完整、当前性漂移、幂等冲突、首次材料不一致、类型/概念已退出、引用冲突、概念失败、IF/R失败、当前采用失败、已可能发布、资源失败和内部不一致。仅`bad_alloc/length_error`映射资源失败。

实施顺序：

1. 重新S0并确认本计划blob、当前HEAD、现有WIP文件和其余异主dirty；
2. 重构特征服务，删除旧外设强制入口并迁移读方；修正U64组元结构及两个概念扩展结构在当前截止已前进时的精确重放核验；
3. 实现双FT/完整域概念初始化和普通应用接线；
4. 修正存在类按`(holder,F)`读取已知关系和按`(E,FT)`选择唯一IF/R，再重构实际F provider为只读消费初始化交付并补完整最终读回；
5. 运行第8节仓外探针、隔离构建和静态检查，形成施工/验证记录与函数级知识变更清单；
6. 精确提交并普通推送，交互智能体按目标完成条件收口。
