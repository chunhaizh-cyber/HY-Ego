## 1. 具名退回与修订裁决

正式规范已把场景中的状态使用绑定冻结为 `C/E/S`：`C` 是场景，`E` 是场景内存在，`S` 是中性状态；被描述特征类型从 `S.正式特征类型` 取得，取消独立 `P`，也不复制 FT。

本次计划支撑只同步后继边界。4212 v0.4的 C++ 合同与 v0.3 相同，因此状态本体四字段、合同版本2、公开 DTO/ABI、L1物理布局、owner与生命周期、特征窄核验、非 const L1清理边界、生产白名单和验证门禁全部不变。

## 2. 目标和完成条件

按4212 v0.4与同名详细设计 v0.4，把状态类旧“时间+多特征快照”整体切换为状态身份、正式FT、固定准确值、强时间四字段合同，并补齐特征类窄只读核验；不迁移任何消费者。

完成条件：状态合同版本2、精确 DTO 和4212 v0.4规定的公开函数实现；两种值表示、两种强时间及0成立；创建/重放、当前/历史读取、三项字段查询、退出、同步实例清理和共同身份读回闭合；状态类旧v1生产声明/定义零命中；状态服务合法调用L1物理清理且零 `const_cast`；施工记录包含实际知识变更清单和验证边界。

存在、场景、因果消费者旧调用及 `C/E/S` 场景状态绑定均不是本计划完成条件，也不能把本计划结果外推为这些后继已接线。

## 5. 冻结接口和实现边界

4212 v0.4第2—6、11节全部 C++ 名称、字段、枚举值、签名、成功谓词和构造参数逐字实施；执行者不得改名、增加字段或兼容 overload。

- 特征类只增加4212冻结的窄核验 DTO 和 const `核验正式特征类型准确值`，零写。
- 状态类整体替换为版本2；物理布局固定为普通节点、族归属关系、FT关系、互斥准确值、互斥时间及首次形成UTC技术值。
- 构造和成员使用 `L1事实基座服务&`；该引用唯一获准的写调用是 `执行L1物理清理`。创建、退出及其它普通状态写必须通过状态owner写端口。
- 状态本体和状态服务不得保存或拼装 `C/E/S`；不得建立 P，也不得在绑定中复制 FT。
- 存在、场景、因果类均不修改；其后继不得在本计划内推测或兼容。

## 6. 实施步骤

1. 以本计划发布提交重新核对 HEAD、origin、index、占用表、三个允许文件、4212 v0.4、详细设计 v0.4、4230状态条款和当前调用点。
2. 复核特征类计划内 WIP，按4212 v0.4补齐窄核验 DTO 和函数，保留 FT 与值失败来源。
3. 复核并完成状态类 v2 结构交付、DTO、创建、读回、查询、身份、退出和清理；旧 v1 不保留双轨。
4. 创建遵循先重放后首次核验、写后独立读回；历史读取严格按 `创建G<=H<退出G`；FT查询先过滤 owner、关系类型和目标，再同G完整读回。
5. 退出结果按 `Gexit-1` 读回完整内容。同步清理先读退出 owner 首次材料，命中则重建原退出事实组和退出G；未命中才扫描并首次退出。原双键必须收敛到首次墓碑，改变清理键不得伪装无候选。
6. 不读取或修改存在、场景、因果消费者；场景后继仅记录为 `C/E/S` 绑定物理合同 → 其消费的状态读取ABI，不在本计划实施。
7. 完成静态扫描；仅当不改工程、不消费异主 WIP 的合法隔离输入存在时编译特征/状态模块。根工程 Rebuild 不作为本计划完成门禁。
8. 更新施工记录，只提交三个允许文件。

## 7. 非成功和收口

- 坏版本、零G/身份/预算、负时间或未知语义：入口拒绝、零载荷、零写。
- FT/值来源按4212映射，不创建F或默认0补救。
- 事实代次漂移在交换前零写；同键异请求为幂等冲突；精确重放按首次材料收敛。
- 提交已确认后读回失败保留事实和原键，不补写第二身份。
- 旧v1形状返回旧格式不支持，不回退、不转换、不删除。
- 外部引用导致退出/清理引用冲突，不级联跨owner。
- 未知状态、owner/L1回显矛盾或试图从墓碑重建关系均为内部不一致。
- 若必须改变4212字段、DTO、错误映射、L1布局、生命周期或文件范围，再次具名退回计划支撑。
