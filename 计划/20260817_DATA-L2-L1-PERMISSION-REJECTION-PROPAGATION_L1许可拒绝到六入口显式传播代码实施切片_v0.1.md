## 1. 目标与完成条件

按同名详细设计完成一个兼容的 DATA 状态传播修复：

1. `L1中性读取状态` 尾追加 `许可拒绝=8`，旧 1—7 数值和语义不变。
2. `L1事实基座服务::读取中性当前事实代次` 把仓库 `许可拒绝, 0` 保留为中性 `许可拒绝, 0`，不再压成资源失败。
3. 场景 / 存在两个事实代次失败映射 helper 显式返回 `L2结构状态::许可拒绝`。
4. 六个公开当前读取入口在锁竞争时返回许可拒绝、零截止、零变更代次和零载荷，不误分类为资源失败、漂移或内部不一致。
5. 公共枚举的八个其它直接消费服务完成机械兼容闭包，不出现新枚举默认落入内部不一致。
6. 真实资源失败、已发布异截止漂移、成功、入口拒绝和坏形状语义保持。
7. 根工程 x64 Debug / Release fresh Rebuild 和六入口仓库外并发矩阵闭合，生产代码零专项验证痕迹。

本计划的完成不能被用作 WORLD-SELF、BIZ 或 DATA-EXT-01—14 整体完成证明。

## 4. 机械施工合同

1. 在 `L1中性CRUD.数据.h` 枚举尾部追加 `许可拒绝=8`；不改 1—7、合同版本或任何结构字段。
2. 在 `映射中性读取状态` 中分开仓库许可拒绝与资源失败；`L1读取状态::许可拒绝` 唯一映射到中性许可拒绝。
3. 在场景 / 存在两个事实代次映射 helper 中增加中性许可拒绝分支。复核六入口的登记、来源、前 / 后代次和失败形成链，确保该状态在解释载荷形状前返回。
4. 对详细设计 §7 的八个兼容文件逐个复核全部 `读取中性当前事实代次` 非成功收口；只加入许可拒绝的现有 L2 / 材料状态映射，不修改任何其它分支。
5. 关键结果统一使用现有空载荷失败形成函数。不得为许可拒绝返回已收集的场景、存在、关系、引用或身份来源。
6. 锁竞争结果的事实截止为0。只有取得锁并正式读到非零 `Gobs != G0` 才返回事实代次漂移。
7. 真实资源失败继续返回资源失败；坏合同、坏回声、坏 owner、坏端点或坏成功形状继续返回内部不一致。
8. 修改函数诊断责任保持纯值映射或向上送出，不增加生产日志。
9. 施工记录列出新增枚举、全部直接修改函数、六个公开入口和全仓直接消费者清单，形成函数级知识变更清单；不直接修改共享知识库。
