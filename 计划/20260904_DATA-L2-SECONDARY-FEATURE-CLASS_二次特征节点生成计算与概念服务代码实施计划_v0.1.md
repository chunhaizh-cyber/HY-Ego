## 1. 目标和完成条件

按详细设计机械扩展新 `数据服务.特征类.ixx`，使其以现有唯一 owner 写端口原子承载派生定义、直接来源、可选宿主引用和 I64 比较注册，并新增无 owner 的`数据服务.二次特征类.ixx`门面，完成派生节点生成、完整读取、退出、同截止只读计算和概念侧值式材料读取。

本计划没有具名上游计划。正式规范、当前 L1 公共能力、特征类 owner 写端口和存在类公开查询均已存在；代码实现不得 import、调用、强转或复制任何旧 `服务.L2*` 身份、DTO 或函数体。

完成只要求五个允许文件按冻结合同实现、施工记录形成并精确发布。用户当前不需要代码验证，本计划不要求专项、Debug / Release 构建、静态扫描、`git diff --check`、strict、运行或验证记录。

## 3. 施工顺序

1. 在特征类追加详细设计第 3、4 节全部 DTO、稳定枚举、成功谓词和构造配置；保持现有普通特征 DTO 与函数签名不变。
2. 实现基础 / 派生定义辨识与完整读取。既有普通特征节点只能经当前公开闭包归一为基础阶次 1；派生定义必须由新结构闭包显式证明阶次、来源、规则和注册。
3. 实现派生定义请求规范化、来源递归阶次读回、来源环保护、固定单 owner 写集、首次幂等重放、提交、完整读回和已可能发布。
4. 实现派生定义退出：退出全部自有事实，保留来源、宿主和输入事实，传播引用冲突，历史读回证明同代退出。
5. 实现 I64 注册读取和`比较派生特征`，逐项服从 4180 状态 / 拒绝 / 结果位矩阵；比较代码只读，安全处理 I64 极值，不复制旧 L2 函数体。
6. 新建二次特征门面，实现 L1 前后 G0 守卫、可选宿主存在查询、五个公开入口及概念值式投影；不得持有 owner 或写端口。
7. 在工程和 filters 中于特征类之后唯一登记新模块。
8. 建立施工记录，写明实际变更、精确文件、函数级知识变更和所有未验证边界。

实施中若发现需要改变 owner、增加第二写端口、修改存在类 / L1、调用旧 L2、改变稳定状态数值、把计算结果持久化、扩展非 I64 算法或修改允许文件，属于设计漂移，停止受影响范围并具名退回计划支撑。普通 C++ 错误和允许文件内的实现遗漏由执行者修复。

## 4. 代码完成检查边界

本轮完成不以专项断言、构建、静态扫描、`git diff --check`、strict、故障注入、运行或独立验收为前置，不建立验证记录。

执行者仍须通过源码和 staged diff 核对以下交付形状：

- 特征类是唯一 owner / 写端口持有者，二次特征类无 owner 和写端口；
- 旧 L2 import、类型强转和函数调用为零；
- 派生定义、来源、可选宿主关系和注册事实属于一次 owner 写集；
- 二次特征所有操作使用同一 G0，存在类只读；
- 比较只支持已注册二元 I64，零事实写入；
- 概念材料只是值式投影，不创建概念。

这些源码边界核对不等于构建或运行验证。未执行的检查不得写成通过。
