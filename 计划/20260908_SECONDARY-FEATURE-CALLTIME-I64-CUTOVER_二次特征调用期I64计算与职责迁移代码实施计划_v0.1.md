## 1. 目标和完成条件

按详细设计机械完成规划闭环 A：建立特征 owner 的独立 I64 比较绑定；新增有序 I64 纯算法提供者和 DATA 外二次计算应用；实现准确 F、保存定义输出、本次局部输出三来源 DAG 和有界高阶复算；把需求/任务方向计算移到业务应用；让方法直接读取派生定义；物理删除旧二次 DATA 门面及 DATA 内计算 ABI。

完成条件为：

- 详细设计第 3—9 节的全部 C++ 类型、签名、依赖、失败、原子性、G/H和零写边界逐项实现；
- 旧声明、实现、import、成员和消费者扫描零命中；
- DATA 模块零反向 import 业务模块；
- 主工程与 filters 精确登记一致；
- Debug/Release x64 隔离 Rebuild 均成功，专属记录写明静态与编译证据及未验证范围；
- 结果只发布本计划白名单文件并普通推送。

## 2. 正式依据和当前事实

执行 S0 必须重新读取 1180 v0.9、4150 v0.12、4151 v0.1、4180 v0.11、4181 v0.1、4182 v0.1、规划 v0.1、本计划详细设计、计划索引、Git/远端/index/dirty、WIP登记、目标源码和工程登记。任一正式版本、公开接口、所有权或文件状态发生会改变实现的漂移，停止受影响范围并具名退回计划支撑；普通编译错误在本计划内修复。

创建侧核对的当前事实：

- 特征类同时承担定义结构和 `标量复算/比较派生特征`；
- 二次特征类为五入口转发门面，没有独立 owner 或生产构造点；
- 需求类直接计算，任务类经需求类间接计算，方法类只读取派生材料；
- 当前没有调用期局部图、独立比较提供者或业务计算应用；
- 当前有效计划表在本计划登记前为空；本计划与 SELF 线程 WIP 不共享生产文件、ABI 或验证资源。

## 4. 实施顺序

### S0：冻结现场

1. 核对本计划精确版本/blob和`可执行`登记，确认 `main == origin/main`、起点、index、dirty 与占用。
2. 在 `D:\TEMP\再用文件\再用文件列表.md` 的执行所有者模块逐文件登记第 3.1/3.2 节实际要写的目标；验证根使用计划专属目录。
3. 重扫旧 API 全部声明和消费者，确认没有超出白名单的新调用；记录正式 HEAD 下各目标 source blob。

### A1：建立独立 I64 比较绑定

1. 在特征类按详细设计第 4 节加入全部 DTO、稳定枚举、显式操作种类、逐操作成功谓词和四个结构入口。
2. 扩展 definition owner 初始化角色；建立请求逐项携带已经正式成立的输出 FT，原子写集只建立绑定节点、U64/I64 属性、输入/输出 FT 引用关系和绑定归属，严禁创建、改写或退出输入/输出 FT；建立/退出均使用同 owner 幂等读回、发布确定性和 L1 引用保护。
3. 当前读取严格按 `输入FT+用途` 和请求内非零候选/材料上限增量解析，返回零或唯一活动绑定；预算不足不暴露候选，多项为 `注册不唯一`，不按编码任选。身份读取按 H，返回前守卫 Gread。
4. 保留 v2 保存定义和旧 v1 历史解释，不迁移存量。删除结构建立准入中的实际复算，只保留来源、K/合同、量化、阶次和引用闭合检查。
5. 为需求、方法、任务三个既有 DATA 服务补充公开只读 `绑定于(const L1事实基座服务&)`；需求方向应用也导出同名只读组合查询供任务应用构造核验。查询只核验既有 L1 引用，不改变 owner、构造或数据。

### A2：迁出纯算法

1. 新建有序 I64 比较模块，逐值实现4180稳定算法状态/拒绝原因/结果位和详细设计第5节签名；明确其为计算应用内部纯执行器，完整 G/H、来源、上下文和 DAG 由计算应用返回。
2. 实现安全排序、容差关系三码和右减左；差异溢出使整个已请求集合无载荷，只请求排序不受影响。
3. provider 不持有 L1、容器或 owner，不选择当前绑定，不创建任何事实；所有异常在 `noexcept` 边界收口。

### A3：实现调用期 DAG

1. 新建二次计算模块和第6节全部 DTO/谓词；构造只保存 L1、特征服务、provider 引用并核验绑定。
2. 请求形状、上下文要求位、局部编号、两类根来源、角色和六维预算先校验；任何分配/读取前做溢出与余额检查。
3. 按详细设计具名 DTO 扩展特征派生读取预算和结果：新增材料总额、完整递归定义组与六字段实际用量；DATA 在追加每项材料前同时扣分类和总额，结果成功谓词互证定义闭包与用量。
4. 准确 F 按 H 完整读取；保存定义按 H 展开并保留固定 K，每个递归保存定义生成独立计算节点回执；本次局部输出按局部编号/角色连接；裸值、裸节点、上轮编号拒绝。
5. 检查悬空、环、重复和每路径深度，按拓扑执行；本次局部项以 `FT+用途` 在 G 读取唯一 K，`预期K`只作漂移门禁；保存定义固定 K 必须再与 G 下当前绑定逐字段兼容，身份可不同但输出 FT 等任一语义字段不同即拒绝，不能替换 K。
6. 按详细设计机械换算调用预算、派生读取预算和当前绑定候选/材料上限并据真实用量扣减；组装基础叶、统一节点身份计算项和两类根结果，使每个根都可沿同包 DAG 追到基础 F。真实阶次固定为直接特征输入最高阶次+1；尾 G 漂移或任一根缺失时清空全部成功载荷。

### A4：迁移业务消费者

1. 新建需求方向应用：移入现有需求方向业务选择、宿主/采用、定义左右闭包和结果互证；以保存定义输出直接构造根请求，按详细设计状态表逐项映射并冻结成功谓词；计算失败保留结构化计算子结果。
2. 新建任务方向应用：完整读取任务和来源需求后委托需求方向应用，不复制计算核心；按详细设计状态表映射，需求方向失败保留完整子结果并互证来源需求所属存在。
3. 从需求 DATA 删除旧方向 DTO/入口/helper及二次门面依赖；保留记录结构、目标宿主、目标 F 和方向定义引用。
4. 从任务 DATA 删除旧方向 DTO/入口/helper；保留任务结构和需求引用。
5. 方法 DATA 删除二次门面 import/构造参数/成员，将`验证二次特征`改为`验证派生定义`并直接调用特征 owner 的完整定义读取；保留旧 v1 治理回退。

### A5：物理退役和工程闭合

1. 从特征 DATA 删除旧比较请求/结果、计算回执、计算缓存、`标量复算`、`比较派生特征`和只为旧计算存在的 helper。
2. 删除 `数据服务.二次特征类.ixx`，不保留转发、alias或 deprecated 声明。
3. 更新 `.vcxproj/.filters`：删除旧模块，按详细设计第9节登记四个新模块。
4. 全仓扫描旧 ABI 和 DATA→业务反向 import；命中生产源码即未完成。

### A6：记录、验证和发布

1. 施工记录列出实际函数变更、source blob、消费者迁移、知识变更清单、未实施项和所有与计划差异。
2. 编译记录写出隔离根、命令、配置、退出码、错误/警告、实际模块、静态扫描和未运行范围。
3. 精确暂存白名单，核对 staged diff，取得唯一 Git 发布租约后提交并普通推送 `origin main`；不修改索引状态，由交互智能体核验结果后另行路由退出。

## 5. 失败收口

- 写绑定在派发前失败：确认未发布且无成功事实；派发后未知：`已可能发布`并保留原请求，由原 owner 原键收敛。
- 计算非法请求、来源缺失、历史清理、无注册、固定 K 不相容、算法未实现、错型/量化、溢出、预算、G漂移、资源及内部错误按详细设计稳定状态返回；全部非成功清空成功载荷。
- 保存定义或局部图有环为内部不一致；调用者提交的悬空局部编号为入口拒绝；不能把任何一项降格为合法不满足或零值。
- 编译错误和白名单内机械缺陷由执行者修复；规范/ABI/所有权/持久化语义漂移退回计划支撑。
- 禁止 force/reset/clean/stash/merge/rebase/cherry-pick，禁止覆盖或带入异主 WIP。
