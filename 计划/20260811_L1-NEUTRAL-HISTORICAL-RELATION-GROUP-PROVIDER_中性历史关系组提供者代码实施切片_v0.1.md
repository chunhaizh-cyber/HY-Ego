## 1. 目标、范围与完成条件

为 L2 场景结构 S2 的历史完整结构读取补齐一个业务中性的 L1 提供者：调用方给出源 / 目标端点方向、端点节点、关系类型节点和非零历史截止事实代次，L1 在一次共享许可内枚举该截止时仍有效的完整关系事实组，按关系稳定编码升序返回，并同时回显请求截止和实际读取时当前事实代次。

本叶只增加有界历史关系条件查询，不实现 L2 场景父子 / 成员写入、替换、退出或完整场景投影。它不建立整库历史枚举、分页、审计、恢复、缓存、SQL 回源、领域关系解释或验收专用入口。

完成条件固定为：

1. 公开 DTO 唯一表达端点方向、端点、关系类型、历史截止、实际读取代次和有序完整关系组；
2. 仓库只增加保存稳定编码的可重建全生命周期源 / 目标关系候选索引，关系创建时登记、退出时保留，索引不保存第二份关系事实；
3. 查询在一次共享锁内从候选索引定位，并逐项回读 `当前关系` 或 `历史` 中的权威完整 `关系事实`，按 `[创建事实代次, 退出事实代次)` 过滤；
4. 空组成功、非法请求入口拒绝、未来截止事实代次漂移、隔离 / 索引矛盾内部不一致和分配失败资源失败均有唯一结构化结果；所有非成功关系组为空；
5. 关系创建、替换和退出后，当前关系双索引语义不变，全生命周期候选双索引与全部当前 / 历史关系精确互证；
6. 生产外公开接口验证覆盖源 / 目标方向、旧截止、替换、退出边界、空组、稳定排序、非法请求、未来截止漂移和当前查询不混入历史；
7. 主工程 Debug / Release x64 保持完整编译链接，生产入口、L2 模块和工程登记不因本叶改变。

### 2.2 复用 / 扩展裁决

单事实 `读取中性历史事实` 只能按调用方已知的稳定编码返回一条事实；当前源 / 目标关系索引在关系退出时删除编码，不能回答旧截止下的关系组。扫描 `当前关系` 只能漏掉已退出关系，扫描 `历史` 或整库快照违反 4015 的普通 CRUD 有界访问边界。

## 4. 最终公开 DTO 合同

`L1中性CRUD.数据.h` 增加：

```cpp
enum class L1中性关系端点方向 : std::uint8_t {
    源 = 1,
    目标 = 2
};

enum class L1中性历史关系组读取状态 : std::uint8_t {
    成功 = 1,
    入口拒绝 = 2,
    事实代次漂移 = 3,
    资源失败 = 4,
    内部不一致 = 5
};

struct L1中性历史关系组读取请求 final {
    std::uint32_t 合同版本 = L1中性CRUD合同版本;
    L1中性关系端点方向 方向 = L1中性关系端点方向::源;
    稳定编码 端点节点;
    稳定编码 关系类型节点;
    std::uint64_t 历史截止事实代次 = 0;
    friend bool operator==(const L1中性历史关系组读取请求&,
        const L1中性历史关系组读取请求&) = default;
};

struct L1中性历史关系组读取结果 final {
    L1中性历史关系组读取状态 状态 =
        L1中性历史关系组读取状态::入口拒绝;
    std::uint32_t 合同版本 = L1中性CRUD合同版本;
    L1中性关系端点方向 方向 = L1中性关系端点方向::源;
    稳定编码 端点节点;
    稳定编码 关系类型节点;
    std::uint64_t 历史截止事实代次 = 0;
    std::uint64_t 读取事实代次 = 0;
    std::vector<L1中性关系事实> 关系组;
    friend bool operator==(const L1中性历史关系组读取结果&,
        const L1中性历史关系组读取结果&) = default;
};
```

合同版本复用 `L1中性CRUD合同版本=1`，不建立第二版本轴。请求有效条件为：合同版本正确、方向精确为源或目标、端点节点非零、关系类型节点非零、历史截止事实代次非零。枚举经非法底值构造时必须入口拒绝。

结果始终逐字段回显方向、端点、关系类型和请求历史截止。成功时 `读取事实代次` 是持共享锁读取时的权威当前事实代次，允许大于历史截止；事实代次漂移时回显安全取得的实际当前代次；入口拒绝、资源失败和不能信任仓状态的内部不一致不伪造读取代次。所有非成功关系组为空。

空组是合法成功：未知组合、该截止尚未创建任何匹配关系或全部匹配关系已在截止前退出均返回成功、非零实际读取代次和空组。端点 / 类型非零但未命中不折叠为未找到，因为本入口查询的是关系条件集合而不是端点节点当前性。

## 5. 仓库状态与候选索引合同

`L1事实基座仓库::状态` 增加两个非权威字段，形状与当前双索引一致：

```cpp
历史源关系候选索引[源节点编码][关系类型节点编码]
    -> vector<关系稳定编码>
历史目标关系候选索引[目标节点编码][关系类型节点编码]
    -> vector<关系稳定编码>
```

名称中的“历史”表示支持任意已发布历史截止的全生命周期候选集合；它同时包含仍当前和已退出关系的稳定编码。索引不得复制关系端点、角色、生命周期或完整事实，不是第二权威历史表。

更新顺序固定为：

1. 新关系写入候选 `当前关系` 后，按关系稳定编码有序且无重复地插入当前源、当前目标、历史源候选、历史目标候选四项索引；任一插入失败则候选发布失败，不改变权威状态；
2. 关系退出时只从当前源 / 目标索引删除，在完整关系写入 `历史` 后保留历史双候选索引原项；
3. 节点和值创建 / 退出不修改历史关系候选索引；关系事实不可原地改变端点、类型或编码；
4. 不增加从 `历史` 或整仓热路径重建索引的普通提交步骤；进程内状态从空仓开始，所有关系均经同一创建更新点登记。

新增最小私有辅助固定为：

```text
插入历史源关系候选索引(状态&, const 关系事实&)
插入历史目标关系候选索引(状态&, const 关系事实&)
```

辅助只校验非零关系 / 端点 / 类型编码和创建代次，按 `lower_bound` 插入稳定编码并拒绝重复；不读当前关系、不复制事实、不记录日志。现有当前索引插入 / 删除 / 派生辅助保持当前语义和名称。

`状态完整` 增加全生命周期双索引互证：

- 每个候选组非空、键非零、关系编码严格升序且全局无重复；
- 每个编码必须在 `当前关系` 或 `历史` 中恰一命中完整 `关系事实`，不得指向历史节点或历史值；
- 权威关系的编码、源 / 目标、关系类型与索引键逐项相同，生命周期完整且不晚于当前事实代次；
- 当前关系和历史关系的稳定编码全集必须分别被历史源 / 目标候选索引各覆盖一次；
- 历史候选索引矛盾使候选发布失败或现行状态读取返回内部不一致，不扫描修复、不降级为空组。

## 6. 仓库查询与公开服务函数

仓库 public 增加：

```cpp
L1中性历史关系组读取结果 读取中性历史关系组(
    const L1中性历史关系组读取请求& 请求) const;
```

服务 public 增加同名唯一入口：

```cpp
L1中性历史关系组读取结果 L1事实基座服务::读取中性历史关系组(
    const L1中性历史关系组读取请求& 请求) const;
```

仓库算法固定为：

```text
纯值校验请求
-> 一次取得阻塞式 shared_lock<shared_mutex>
-> 隔离则内部不一致
-> 当前事实代次小于请求历史截止则事实代次漂移并回显实际当前代次
-> 按方向选择历史源或历史目标候选索引
-> 无端点或无类型候选组则成功空组
-> 按候选稳定编码顺序逐项从 当前关系 或 历史 回读权威完整关系
-> 验证编码、端点、类型、生命周期和唯一来源
-> 仅保留 创建事实代次 <= 截止 且
   (无退出事实代次 或 截止 < 退出事实代次) 的关系
-> 形成成功、请求截止、实际读取代次和稳定有序完整关系组
```

历史适用区间唯一冻结为半开区间 `[创建事实代次, 退出事实代次)`。截止等于创建代次时关系已有效；截止等于退出代次时关系已无效。没有退出代次的当前关系从创建代次延续至实际当前代次。请求截止可以等于实际当前代次；大于实际当前代次一律返回事实代次漂移，不返回部分组。

回读当前关系要求退出代次为空；回读历史关系要求退出代次存在且完整。一个候选编码同时命中、两处均未命中、命中历史非关系事实、端点 / 类型不匹配、编码不递增、生命周期非法或截止过滤后输出失序均返回内部不一致并清空关系组。

服务入口先做相同纯值校验，再调用仓库一次；不另取事实代次、不重试、不排序、不扫描。`std::bad_alloc` 和 `std::length_error` 映射资源失败，其它异常映射内部不一致；异常结果回显请求条件、读取事实代次为 0、关系组为空。函数不写日志、不取得业务解释权。

## 7. 创建、替换、退出与并发边界

本叶不新增写入口，完整复用 `提交中性写集`：

- 创建关系：在发布候选中登记四项索引，新关系从其创建代次起可被历史查询选中；
- 替换关系：调用方仍以同一中性写集创建新关系并退出旧关系；旧关系的适用区间在新代次结束，新关系从同一新代次开始，不产生空洞或双当前；
- 退出关系：退出代次是第一个不再适用的事实代次，历史候选编码永久保留；
- 写候选仍在独占锁内复制、验证并一次交换；历史查询只在一次共享锁内读取，不可能返回候选、混合发布前后状态或把索引命中冒充事实；
- 本叶不把阻塞式共享锁改成 try-lock，不增加 `许可拒绝` 状态。长时间并发、公平性和性能不属于本叶验证范围。

### 8.2 必过矩阵

在一个新 L1 服务实例中按有记录的事实代次顺序验证：

1. 创建关系类型、两个源端点和两个目标端点，再创建至少三条同类型关系；分别按源 / 目标方向读取，核对端点、类型、完整关系和稳定编码严格升序；
2. 在关系创建前截止查询同组合得到成功空组，在关系创建截止得到完整创建组；
3. 用一个原子写集创建替代关系并退出旧关系；替换前截止只含旧关系，替换截止只含新关系，二者生命周期逐字段正确；
4. 后续退出替代关系；退出前最后截止仍包含，截止等于退出代次时不包含，历史单事实仍能读取其完整退出生命周期；
