# 通用零动作恢复筹办

身份：`TASK-ZERO-ACTION-REPREPARE`；版本：v0.1；日期：2026-10-15。

设计代码基线：`e96a3b1a24173b4ba36a9ead473a2ddf3a96d3ab`。本文件合并本叶设计与施工合同；执行资格只由计划索引维护。

## 1. 用户裁决、目标和范围

用户已明确：确认未发生动作时，清理无动作X、撤销旧就绪并重新筹办；已经动作只查结果；工程故障记录日志、弹窗并终止。该裁决替代本叶旧“撤销空X后回待执行”和“仅结算任务回筹办”的行为，不扩展为失败动作重试。组合方法逐步分支执行已经暂停，本叶禁止涉及。

本叶修改对象是任务虚拟存在的治理状态及本次无动作执行结构，原因是普通任务在合法零动作后滞留待执行或被manager硬阻塞，目的为由通用筹办重新取得真实条件及新self决议。不改变现实世界特征，不运行本能函数补偿，不生成动作、状态结果或方法经验。

目标闭环：W3-A明确零动作 → task owner恢复原最近M/X并删除本次空X（如已建立）→ T回待查找方法 → worker返回具名恢复材料 → manager独立读回并精确作废旧请求的筹办/执行材料 → 确认并释放原工作 → 正常调度重新筹办。新执行仍须走既有self判断，不重放旧W3-A。

## 2. 当前事实与依据

- 依据0050、3200、5260、5360和8100中的唯一T/D、task owner状态、条件变化零动作、已动作不重做、消息独立读回；最新用户裁决替代本叶旧撤销目标，不修改正式规范。
- `撤销未进入动作执行`当前只有`执行任务本能方法`一个生产调用者，无其它代码或测试调用。保留签名及请求字段，直接修改成功状态为待查找方法，不新增旧行为兼容参数。
- 该撤销入口已核验当前T/X、执行中、无结束/状态/动作/A，恢复开始前最近M/X并删除本次空X；现成功读回和精确重复只认待执行。
- `执行任务本能方法`在X前复核变化、X后来源重新确认、临近输入变化及函数明确未进入动作时存在多个返回口；只有结算参数不匹配分支另行回筹办。
- `复核执行本能输入`当前把筹办的工程错误和合法条件缺口统一折成条件已变化，推广前必须区分。
- 方法owner的`调用本能函数`在实际函数调用之后也可能捕获异常并返回资源失败/内部错误且清空运行对。`!已调用`不证明未执行，不能据此撤销X。
- manager当前结算恢复分支以T键清理过宽；已有定位失效分支按原执行请求和原筹办请求相等清理，可在本叶收敛复用。
- 知识库没有覆盖本链当前代码的有效用途卡；以上以现行头源及全仓调用点为准。

## 4. 精确返回合同

在任务头中追加值式DTO：

```cpp
struct 新任务零动作恢复信息 final {
    std::optional<稳定编码> 已撤销执行实例节点;
    std::optional<稳定编码> 原最近方法节点;
    std::optional<稳定编码> 原最近执行实例节点;
    friend bool operator==(const 新任务零动作恢复信息&,
        const 新任务零动作恢复信息&) = default;
};
```

`新任务治理本能执行状态`末尾追加`零动作已回筹办`；`新任务治理本能执行结果`末尾追加`std::optional<新任务零动作恢复信息> 零动作恢复`。不改变旧枚举值。此DTO只描述本次工作的治理收束，不持久化、不授予执行权；T从`原请求`取得。

- 原最近M/X同空或同非空，必须来自本调用在task锁内的开始前fresh读取，不猜测。
- X尚未建立：撤销X字段空，`执行开始`不能含X，`方法调用`空；T经同一前定位守卫回待查找方法。
- 已建立X：撤销X准确等于`执行开始.执行实例节点`；撤销状态为已修改/精确重复；函数若被调用，只有第6节认可的完整零动作运行对。
- 仅当task owner读回T待查找方法、最近M/X准确恢复、被撤销X确实不存在后才返回该状态和材料。其它状态不得携带该DTO。

## 5. task owner恢复及生命周期

### 5.1 已建立空X

直接修订`撤销未进入动作执行(const 新任务未进入动作撤销请求&) noexcept`：

1. 保留原请求完整性、当前T/X归属、无动作/实际状态/结束/A和原最近定位合法性核验；空字段不是单独的零动作证明，调用方仍须满足第6节。
2. 成功目标统一改为待查找方法。最近M/X仍恢复为开始前定位；删除仅限本次X及其现有专属预计/采用结构，沿既有删除helper；不删旧X、共享方法、组织或状态。
3. X已不存在时，仅T当前待查找方法且原最近M/X逐项相等才能返回精确重复。T已前进或出现新X不能伪称重复，更不能倒退它。
4. 成功后读回同样要求待查找方法、精确原最近M/X、X不存在；不再通过“先恢复待执行，外层再改状态”两套逻辑收束。头注释同步。
5. 首次副作用前的非法请求/合法当前位变化保留结构化拒绝；部分恢复、状态发布、删除或补偿失败与抛异常必须工程终止，不能继续重试删除、返回正常零动作、重建空X或反向改变已发生世界事实。沿当前顺序完成，不声称新增跨owner原子事务或跨进程崩溃恢复。
6. 成功后仅清理本次X的`方法问题暂存组_`，不归档零动作效果样本。

### 5.2 X尚未建立

在`执行任务本能方法`内部以局部helper实现，不增加公开数据owner入口：首次读取T时冻结前状态/最近M/X；合法前置变化时，在task锁内重新读取并核验同T、同前定位，且当前状态仍属于本次动作入口可拥有的待检查条件/待执行。通过现有任务状态写入口转待查找方法并读回；已经待查找且定位相同可收敛。其它状态或新定位返回既有任务状态已变化，不清理新执行，不生成恢复成功材料。

原开始入口拒绝的具名零动作路径也使用此helper。原始请求不完整、源结构损坏不属于合法前置变化；不能统一走该helper。

## 6. 分支分类：确认未动作，不猜未动作

| 来源 | 本叶处理 |
| --- | --- |
| X前方向/目标复核的合法定位变化、目标已满足、方向冲突、安全/服务限制或等待材料；当前条件缺失/变化；正式方法合法停用 | 零动作；同前定位仍当前则回筹办。重新筹办会fresh决定等待/零动作满足等，不直接完成任务或批准新动作。 |
| X后来源语义需重新确认；临近输入复核确认条件已变化 | 明确尚未调用函数，撤销空X并回筹办。 |
| 函数返回完整运行对，动作阶段未进入，状态参数不匹配，结果未取得，动作节点、状态组、动态组、二次观察组、建议观察特征组、服务需求信息包、服务对象观察材料均为空 | 明确零动作，撤销空X并回筹办，普通与结算任务同路；条件侧已读取的输入快照可以保留，不等于输出或动作。 |
| 方法调用返回方法停用，且无运行对 | 当前方法包装层此分支位于函数调用前；正式方法仍完整可读且确已停用时允许按明确未调用恢复。 |
| X前检查可用返回函数未登记、依赖未装配；X后函数或包装层返回未登记/未装配 | 这是登记指针、端口或接纳装配条件的工程问题，不是正式条件值；工程终止。已经建立X则保留X，不借确定零动作推导业务可重试。显式停机取消沿原生命周期，不推测为恢复。 |
| 方法调用资源失败/内部错误；已调用却缺运行对；未进入却带动作或任何输出；返回工程停止/资源失败/内部错误/其它不合法组合 | 工程终止，保留X和已知事实；不能先撤销再终止，不能以X缺动作字段推断未执行。 |
| 方法入口拒绝、不是本能方法、参数场景身份不符、损坏引用/读取错误 | 本执行链的工程错误，终止；不能生成业务条件缺口。 |
| 已进入/部分执行/结果未知/已按函数合同返回且已经动作 | 保留X及动作材料，沿既有结果检测；不得清理X、重筹办或重放动作。工程失败仍终止，但保留事实。 |
| 当前T/X已被合法其它推进取代 | 只返回定位/状态已变化，保留新事实；manager只按原请求清理旧运行材料。 |

`建立参数场景`或`调用本能函数`返回“方法不存在”须依据正式节点存在性区分：本轮不把它默认当业务零动作；执行中的源方法不可读、缺类型/登记规格按工程错误终止。可读取的正式停用单独按合法失效处理。

本叶不通过函数名称猜测默认`入口拒绝`的原因。现有`获取服务对象`的缺来源/消息数零仍使用默认拒绝，未形成明确参数失效返回；这些生产者缺口保留为未覆盖项，不能据本叶宣称所有本能方法均已规范化。后续具名修订生产者前，默认拒绝在本执行链中按工程合同缺口终止，不自动重试。

`复核执行本能输入`必须用switch区分：筹办已完成且结构完整时，条件具备返回仍具备，条件不具备/材料未到/参数缺失返回条件已变化；资源失败、结构不一致/结构缺口、大小/方法定位不符合冻结合同进入工程终止。场景与X身份不一致为工程错误；真实当前位变化保留执行不在当前位，调用者不得将它一概当条件变化撤销。既有X不存在与存在却不可读须按基础存在性区分，后者工程终止。

筹办返回`任务状态已变化`存在两种现行来源：真正T位置已变化，以及固定采用需要条件重新计算后不再相等/无法保持。消费时在同一task锁内重读T/X：T/X当前位已变化返回执行不在当前位；同T/X仍当前且处于合法执行位置时，后者按条件已变化处理，不得当工程错误。X前消费同类状态也须核验本调用的前定位后再选择恢复或过期，不单看枚举。

同样核对`确认任务进入待执行`及`执行任务本能方法`本次消费的条件筹办分支：不得将资源失败/结构不一致折成定位已变化。无需批量治理无关owner错误枚举或修改本能实现。

## 7. manager独立复核与精确失效

`处理已完成执行工作`消费新状态前必须：

1. 工作future的原请求完整相等，外层种类为执行本能动作；task执行结果的`原请求`与外层`本能执行请求`逐字段相等；新恢复DTO形状符合第4节。
2. 锁外fresh读T；T待查找方法，最近M/X与恢复DTO逐项相等。存在撤销X时，正式`读回任务执行(T,X)`必须为任务或执行不存在、包含同T且无X，并用已有基础存在性/读回合同确认X确实不存在。不得以最近X不等于旧X代替原定位相等。
3. 当前T合法前进则只终结旧回执，不倒退T、不清新裁决、不覆盖新最近执行结果；存在却不可读、DTO异义、回执自相矛盾进入工程终止。
4. 复核仍为本次恢复位置时，在manager锁内仅当`最近自我筹办裁决[T].执行工作 == 原工作`才使该裁决失效；原筹办结果仅当其原工作等于该裁决中的原筹办定位才清理，并撤销该结果对应的待反馈/筹办阻塞。保留其它原因的阻塞、学习等待、结果等待、后继反馈、新X与其它工作。
5. 删除结算零动作恢复特例，通用恢复不能沿其旧T-only整组清空逻辑。新分支不再插入`阻塞任务`；已有无归属的T级阻塞不得盲删。正常活动动作原本不应兼有结果等待/待反馈；确有冲突时按独立正式定位核查，不猜归属。
6. 标记已在途调度读取工作失效，丢弃本次旧就绪调度快照，清未派调度请求并置调度待触发。未派筹办工作只有原请求定位确属旧筹办时才能清除；不能按T删一个新工作。沿既有调度工作号失效集合复用，不新建调度账。
7. 先预分配所需容器/失效标记、保留完整回执，再确认worker结果。确认须成功后才移除活动工作并开放新调度；停止取消沿旧生命周期确认，不冒充零动作业务恢复。确认失败工程终止，不能丢future或释放同T排他。
8. `最近执行结果`不得被迟到旧零动作回执覆盖一个新X/新原请求；仅保存仍对应本次活动工作且尚未被新结果替代的返回。无恢复DTO的旧定位变化分支同样只撤销匹配原请求，不借其触发新动作。

本叶不恢复/复用旧self执行工作，重新筹办之后由正常既有self入口重新决议。无需给self增加消息或复制恢复状态；manager唤醒普通调度即可。
