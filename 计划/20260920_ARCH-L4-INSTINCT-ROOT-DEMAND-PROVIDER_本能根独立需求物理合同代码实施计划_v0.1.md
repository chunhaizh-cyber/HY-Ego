计划身份：`ARCH-L4-INSTINCT-ROOT-DEMAND-PROVIDER`

状态：待激活

关联目标：`GOAL-INSTINCT-ROOT-DEMAND-PROVIDER-IMPLEMENTATION`

计划支撑来源：执行 S0 在`b1d93cd48d91900a802d5c03d5270b723a6b7fbd`发现，现有`需求类数据服务`构造强制普通四关系类型，而v0.3只登记根专用3+1类型，不能合法构造服务。后续执行在`54682cadf`确认正式`数据服务.存在类.h`的 IF/R ABI 缺少`存在信息身份`定义，导致本计划合法包含链不能编译；先由`EXISTENCE-IDENTITY-CONTRACT-REPAIR`修复并发布，再重新 S0。

## 1. 目标、范围与完成边界

本计划为`ARCH-L4`唯一需求结构 owner 建立阶段21所需的根材料 provider，并在同一 owner 的首次元结构登记中补足现有`需求类数据服务`强制需要的普通四关系类型。每个安全/服务根角色独立建立或读回根目标合同`T`、独立根需求`D`、根列表项`L`、`D -> 实际F`、`D -> T`、`L -> D`，及属于`T`、受 I64 属性类型约束且当前值恒为`I64_MAX`的目标值材料。

根角色只是强类型请求值，不是节点、关系、owner 或索引。`F`是8121上游返回的实际特征，可随当前采用改变，只能由`D -> F`引用；`T`固定承载`I64_MAX`，不得关联实际`F`。安全、服务的`T/D/L/关系/值`全部独立，不得交叉或共用。

完成条件：需求结构登记、需求服务构造/受限取得和根材料 provider 已按本计划实现、发布，专项验证覆盖第7节。成功结果只交付同一非零截止读回的完整根材料。本计划不实现8121阶段21、不构造或写入实际`F`、不比较根值、不开线程，也不证明持续运行。

## 2. 正式依据与执行 S0 事实

- 8121 §2—§5：阶段21只消费4115上游返回的实际`F`；根`D`只含根特征、根目标合同、父空、顺序0和根列表闭包；双根材料必须同截止读回。
- 5170 §3、§4、§6、§11：需求 owner 持有目标合同、需求、列表项和成员；双根不带`所属存在`、`目标宿主`或自我物理绑定，不使用普通需求聚合键。
- 6120 §2.1：安全和服务目标分别是`A == I64_MAX`、`V == I64_MAX`，目标、树和当前满足均独立。
- 当前`数据服务.需求类.h`第203—245行：构造函数强制接收4个非零、互异、同 owner、未退出且无属性的普通节点，作为`所属存在/目标宿主/静态目标特征/方向二次特征`关系类型；空编码、根类型替代或延迟初始化均会抛出无效配置。
- 当前`装配.普通应用.cpp`：未建立需求 owner 或需求服务；既有`建立并读回元节点(...)`已可按固定首次写入身份登记普通节点与`属性类型/I64`节点并完整读回。特征和存在服务在构造需求服务前已经可用。
- L1 owner 范围写集可原子承载节点、关系、I64值和属性槽变更；同一写入身份只允许精确重放，不能用不同写集修补已发布半结构。
- 直接上游：`EXISTENCE-IDENTITY-CONTRACT-REPAIR`只在存在类头补齐已被4115和IF/R DTO使用的`存在信息身份`值式声明；其未发布或独立头编译未通过前，本计划不得取得代码切片。

## 3. 冻结的需求结构登记与装配

### 3.1 唯一 owner、DTO和首次结构写集

在`海中鱼巣/领域/数据服务.需求类.h`新增`需求结构登记请求`、`需求结构登记结果`和`需求结构交付`；交付由既有`需求类结构类型 普通结构`和新增`本能根结构类型 根结构`组成。静态入口固定为：

```cpp
需求类数据服务::登记需求结构(
    const L1事实基座服务&, L1所有者范围写端口&, const 需求结构登记请求&)
```

它是需求 owner 的唯一元结构登记入口，合同版本`1`、非零期望截止、固定写入身份`0x415243484C345244`。首次以一个写集建立下表8个节点；精确重复只读取原首次规范化写集、映射和当前节点。任何键、顺序、种类、表示、owner、首次材料、退出或截止异常均结构化失败、零交付。

| 本地键 | 交付字段 | 节点种类 / 表示 | 唯一用途 |
| --- | --- | --- | --- |
| 1 | `普通结构.所属存在关系类型` | 普通 | 既有普通需求：`N -> 所属存在` |
| 2 | `普通结构.目标宿主关系类型` | 普通 | 既有普通需求：`N -> 目标宿主` |
| 3 | `普通结构.静态目标特征关系类型` | 普通 | 既有普通需求：`N -> 静态目标特征` |
| 4 | `普通结构.方向二次特征关系类型` | 普通 | 既有普通需求：`N -> 方向二次特征` |
| 5 | `根结构.根实际特征关系类型` | 普通 | 根：`D -> F` |
| 6 | `根结构.根目标合同关系类型` | 普通 | 根：`D -> T` |
| 7 | `根结构.根列表成员关系类型` | 普通 | 根：`L -> D` |
| 8 | `根结构.根目标值属性类型` | 属性类型 / I64 | `T`的固定目标值 |

普通4个类型只恢复现有`需求类数据服务`构造与普通入口的既有前提，绝不改变其请求、关系方向、聚合、生命周期或公开语义；根4个类型只用于本计划根入口。构造`需求类数据服务`固定接收`需求结构交付`，并分别验证两个子结构的所有节点完整、互异、同 owner且未退出；不得空结构、借用其它 owner或另建 registry。

### 3.2 普通应用装配、持有和取得

`普通应用上下文`增加需求 owner 交付、`需求结构交付`和`std::unique_ptr<需求类数据服务>`。在既有 owner 建立序列中以固定建立键`0x1007`建立需求 owner；不得改变其它 owner 键。

在既有`特征`和`存在`服务构造完成后，且在场景/概念/世界树/自我/线程初始化之前，装配以`定位首次(需求 owner端口, l1, 0x415243484C345244).G0`调用`登记需求结构`，成功交付后才把该端口移动进`需求类数据服务`构造函数。登记或构造失败一律映射为既有`普通应用装配状态::服务建立失败`，候选上下文不得发布。

`装配.普通应用.h/.cpp`新增`需求类数据服务* 读取普通应用需求服务() noexcept`。它在上下文锁内仅取得当前上下文持有的同一服务指针；无已成功上下文或服务时返回`nullptr`，不创建上下文、不登记结构、不调用根 provider、不暴露写端口或裸 L1。调用方不得跨普通应用上下文生命周期持久保存该指针。此入口是后续阶段21唯一普通应用取得路径，不是阶段21调用或机器事实入口。

## 4. 根材料 provider 合同

### 4.1 DTO、固定身份与入口

新增`本能根角色 { 安全, 服务 }`、`本能根材料请求`、`本能根材料`、`本能根材料结果`和根专用状态。请求仅含合同版本`1`、非零期望截止、根角色和4115输出的实际`F`稳定编码。内部固定业务写入身份为：安全`0x415243484C345341`，服务`0x415243484C345356`；调用方不能传入、替换、组合或复用它们。

公开入口固定为`需求类数据服务::建立或读取本能根材料(const 本能根材料请求&)`。它仅使用构造期验证的需求 owner 和`根结构`；拒绝所属存在、目标宿主、自我、方向二次特征、状态、动态、来源、父、顺序、目标值和外部幂等键。它在请求`G0`读取`F`并确认是未退出普通节点；“实际特征”的来源与当前采用语义由8121调用方持有的4115结果证明，根 provider 不重复解释其首值、当前采用、状态或动态。

成功只允许`已形成`、`已恢复`、`已读取`，并交付根角色、`T/D/L`、三关系、目标I64值事实、实际`F`、父空、顺序0和同一非零`Gfinal`。失败至少区分入口拒绝、实际F未找到/已退出/类型不匹配、事实代次漂移、幂等冲突、引用冲突、根材料未闭合、根材料已退出、已可能发布、资源失败和内部不一致；失败绝不交付可消费材料。

### 4.2 每角色原子布局、重放与读回

完全缺失的一个角色以一个需求 owner 写集在同一`G0`建立下列事实；所有关系`角色或顺序`恒为0：

| 本地键 | 新事实 | 固定内容 |
| --- | --- | --- |
| 1 | 节点`T` | 普通节点，根目标合同 |
| 2 | 节点`D` | 普通节点，独立根需求 |
| 3 | 节点`L` | 普通节点，根列表项 |
| 4 | 关系 | `D -> 请求.实际F`，根实际特征关系类型 |
| 5 | 关系 | `D -> T`，根目标合同关系类型 |
| 6 | 关系 | `L -> D`，根列表成员关系类型 |
| 7 | 值 | 所属`T`、根目标值属性类型、材料`std::int64_t::max()`、来源`T` |
| 槽变更 | 属性槽 | 所属`T`、根目标值属性类型、新当前值为本地键7 |

禁止`T->F`、`F->T`、普通需求四关系、父关系、自我关系、目标宿主/所属存在/方向二次特征关系、文本/浮点/综合分数目标值或其它列表成员。父空、顺序0由根 DTO 固定表达，不写节点或关系。

相同角色、相同`F`、同版本请求必须精确重放；同角色同身份而`F`、角色、合同版本、结构交付或目标值语义不同为`幂等冲突`。安全与服务任一节点、关系、值或属性槽交叉为内部不一致。首次材料存在或提交可能发布时，只能以原身份、原规范化写集和原完整请求读回收敛；同身份不允许不同写集补建，任一缺项或不符均`根材料未闭合`或内部不一致，禁止覆盖、退出、扫描或另建第二根。

最终在同一非零`Gfinal`一致读取`T/D/L`、三关系、`T`属性槽与当前值、请求`F`；核验owner、种类、创建/退出、端点、类型、角色/顺序、`I64_MAX`材料与来源、`L`唯一成员等于`D`、`D`无普通需求物理绑定以及双根不交叉。任何预读、写后或组合读回跨代均`事实代次漂移`。`本能根材料::完整()`仅作无I/O值式核验，不替代正式读回。

## 6. 错误收口

无效/退出/错型`F`、结构不完整、同键异义、引用冲突、根间交叉、重复成员、非`I64_MAX`、槽值不一致、owner错配或不可证明材料损坏均零新写并具名失败。资源失败保持资源失败；断言/映射/不变量错误保持内部不一致，禁止伪装为等待。提交前截止变化或组合读回跨代零成功交付；提交未知只以原请求/原身份读回收敛。不得创建平行恢复账、扫描全库、猜测根身份、退出/覆盖/清理/迁移既有事实。
