# ARCH-L4 本能根独立需求物理合同代码实施计划 v0.3

计划身份：`ARCH-L4-INSTINCT-ROOT-DEMAND-PROVIDER`

状态：可执行

关联目标：`GOAL-INSTINCT-ROOT-DEMAND-PROVIDER-IMPLEMENTATION`

设计修订来源：`GOAL-INSTINCT-ROOT-TARGET-CONTRACT-REPAIR`

代码基线：`a966ecdac4f06d48451cbd7ea3ab4b2bc0ea18ae`

## 1. 目标、范围与完成边界

本计划为`ARCH-L4`需求结构 owner 建立阶段21所需的根材料 provider。它先在该 owner 下幂等登记根结构类型，再按安全、服务两个根角色分别建立或读回：根目标合同`T`、独立根需求`D`、根列表项`L`、`D -> 实际F`、`D -> T`、`L -> D`，以及属于`T`、受 I64 属性类型约束且当前值恒为`I64_MAX`的目标值材料。

根角色只是一项强类型请求值，不是节点、关系、owner 或索引。`F`是由8121上游返回的实际特征；它可随当前采用改变，只能由`D -> F`引用。`T`是目标合同，固定承载`I64_MAX`，不得关联实际`F`。安全和服务的`T/D/L/关系/值`全部独立，不得交叉或共用。

完成条件：公开 provider 和普通应用装配均已按本计划实现、发布，专项验证已覆盖第7节；成功结果只能交付同一非零截止读回的完整根材料。它不实现8121阶段21、不构造或写入实际`F`、不比较根值、不开线程，也不证明持续运行。

## 2. 正式依据与当前事实

- 8121 §2—§5：阶段21只消费4115上游返回的实际`F`；根`D`仅有根特征、根目标合同、父空、顺序0和根列表闭包；双根材料必须同截止读回。
- 5170 §3、§4、§6、§11：需求 owner 持有目标合同、需求、列表项和成员；双根不带`所属存在`、`目标宿主`或自我物理绑定，不使用普通需求聚合键，且由阶段21专用入口发布。
- 6120 §2.1：安全和服务的目标分别是`A == I64_MAX`、`V == I64_MAX`；两根的目标、树和当前满足独立。
- 当前`海中鱼巣/领域/数据服务.需求类.h`的普通`需求类记录`强制四条普通关系，故不能复用于根`D`；当前`需求类结构类型`也没有根关系或目标值属性类型。
- 当前`海中鱼巣/装配.普通应用.cpp`已提供`建立并读回元节点(...)`：能在指定 owner 写端口按固定首次写入身份登记普通节点和`属性类型/I64`节点，并完成首次材料与当前节点读回。当前普通应用尚未建立需求 owner 或持有`需求类数据服务`。
- L1 owner 范围写集已具备普通节点、关系、I64 值与属性槽变更；它能原子承载本计划所需结构，但不替代本计划的强类型边界和读回核验。

## 3. 冻结的结构登记合同

所有下列类型节点均由唯一需求 owner 建立，定义于`海中鱼巣/领域/数据服务.需求类.h`，并在`需求类数据服务`的静态登记入口形成；不得由存在、特征、概念、自我或阶段21另建 registry。

### 3.1 DTO、固定身份与交付

新增强类型：`本能根角色 { 安全, 服务 }`、`本能根结构登记请求`、`本能根结构登记结果`、`本能根结构类型`和`本能根结构交付`。登记请求固定为合同版本`1`、非零`期望事实代次`和固定写入幂等身份`0x415243484C345253`；该身份只登记结构，不能用于任一根材料写入。

`本能根结构类型`恰有下列四个稳定编码，交付前逐一当前读回、同 owner、未退出且种类正确：

| 写集本地键 | 交付字段 | 节点种类 / 表示 | 作用 |
| --- | --- | --- | --- |
| 1 | `根实际特征关系类型` | 普通 | `D -> F` |
| 2 | `根目标合同关系类型` | 普通 | `D -> T` |
| 3 | `根列表成员关系类型` | 普通 | `L -> D` |
| 4 | `根目标值属性类型` | 属性类型 / I64 | `T`的固定目标值 |

登记入口为`需求类数据服务::登记本能根结构(...)`：只接受同一`L1事实基座服务`绑定的需求 owner 写端口；首次以一个写集建立上述四节点，精确重复只能读回原首次材料。任何结构缺项、类型错配、owner错配、退出、首次材料损坏、截止变化、同键异请求或资源失败，必须结构化失败，零交付。构造`需求类数据服务`时同时接收既有普通`需求类结构类型`和已验证的`本能根结构交付`；不得修改普通结构的语义，也不得以空结构延迟初始化。

### 3.2 普通应用装配

在`海中鱼巣/装配.普通应用.cpp`的`建立上下文`中，继既有 owner 建立后建立唯一需求 owner，建立键固定为`0x1007`。装配使用该 owner 的写端口和`定位首次(...).G0`调用`登记本能根结构`，只有`成功(请求)`且有交付时才构造`需求类数据服务`。

`普通应用上下文`必须持有需求 owner 交付、根结构交付和`std::unique_ptr<需求类数据服务>`；普通应用头文件新增只读/可调用的受限 accessor，使后续阶段21能取得同一已装配服务，不暴露 owner 写端口、结构登记入口或裸 L1 写入。装配不得调用根材料 provider、不得构造实际`F`、不得创建自我关系、不得改变启动阶段、线程或任何现有 owner 的建立键。

## 4. 根材料 provider 合同

### 4.1 公共 DTO 与入口

在`需求类数据服务`中新增`本能根材料请求`、`本能根材料`、`本能根材料结果`及根专用状态枚举。请求仅含：合同版本`1`、非零期望截止、`本能根角色`和已由4115形成的实际`F`稳定编码。每个角色的业务写入身份由服务内部唯一导出：安全为`0x415243484C345341`，服务为`0x415243484C345356`；调用者不能替换、组合或复用它们。

公开入口固定为`需求类数据服务::建立或读取本能根材料(const 本能根材料请求&)`。它使用构造期已验证的需求 owner 写端口与根结构交付；不接受所属存在、目标宿主、自我、方向二次特征、状态、动态、来源、父、顺序、目标值或外部幂等键。该入口只在请求`G0`以现行 L1 当前节点读取确认`F`为未退出普通节点；`F`作为“实际特征”的业务来源和当前采用语义必须由8121调用方已获得的4115结果证明，根 provider 不重复解释其首值、当前采用、状态或动态。

成功结果状态只允许`已形成`、`已恢复`或`已读取`，并交付根角色、`T/D/L`、三条关系、目标 I64 值事实、实际`F`、父为空、顺序`0`及同一非零`Gfinal`。失败状态至少区分：入口拒绝、实际F未找到、实际F已退出、实际F类型不匹配、事实代次漂移、幂等冲突、引用冲突、根材料未闭合、根材料已退出、已可能发布、资源失败和内部不一致。失败绝不交付可消费材料。

### 4.2 原子写集与精确物理布局

对一个完全缺失角色，服务以一个需求 owner 写集在同一`G0`创建下列本地键；所有关系`角色或顺序`固定为`0`：

| 本地键 | 新事实 | 固定内容 |
| --- | --- | --- |
| 1 | 节点`T` | 普通节点，根目标合同 |
| 2 | 节点`D` | 普通节点，独立根需求 |
| 3 | 节点`L` | 普通节点，根列表项 |
| 4 | 关系 | `D -> 请求.实际F`，`根实际特征关系类型` |
| 5 | 关系 | `D -> T`，`根目标合同关系类型` |
| 6 | 关系 | `L -> D`，`根列表成员关系类型` |
| 7 | 值 | 所属`T`、属性类型`根目标值属性类型`、材料`std::int64_t::max()`、来源`T` |
| 槽变更 | 属性槽 | 所属`T`、属性类型`根目标值属性类型`、新当前值为本地键7 |

不得建立`T -> F`、`F -> T`、普通需求四关系、父关系、自我关系、目标宿主关系、所属存在关系、方向二次特征关系、文本/浮点/综合分数目标值或其它列表成员。根材料不写父和顺序事实；父为空、顺序0是根 DTO 的固定语义，不得临时补节点或关系表达。

### 4.3 首次、重放与同身份读回

相同角色、相同`F`、同版本请求必须精确重放；同角色同固定身份而`F`、角色、合同版本、根结构交付或目标值语义不同，返回`幂等冲突`。安全与服务之间的任一节点、关系、值或属性槽交叉均为`内部不一致`。

首次材料不存在时才允许完整八项写集。首次材料存在或提交可能已发布时，必须用原角色身份读取原规范化写集和映射，再用同一请求、同一身份读回收敛；不得换键另建第二根。L1 的同一身份只允许精确重放，因此本计划不允许用同一角色身份提交不同写集修补半结构：任一缺项、端点、类型、值、槽、owner、角色、F或创建代次不符均为`根材料未闭合`或`内部不一致`，返回失败而非覆盖、退出或补建。

最终以同一非零`Gfinal`一致当前读取：`T/D/L`、三关系、`T`的目标属性槽和当前值、请求`F`；验证每项 owner、种类、创建/退出状态、端点、关系类型、角色/顺序、`I64_MAX`材料与来源均正确，`L`当前成员恰一且等于`D`，`D`只具备本计划根核心关系，两个根无交叉。任一预读、写后或组合读回跨代即`事实代次漂移`；不得以缓存、部分投影或跨代材料成功返回。

`本能根材料::完整()`只作无 I/O 值式核验，必须覆盖上述身份、角色、端点、值和`Gfinal`不变量；它不能替代正式读回，也不能将值式失败降为业务等待。

1. 执行者先重新S0：核对本计划状态/blob、`a966ecd`后的正式规范和当前接口、需求 owner 唯一所有权、Git/index、需求/装配文件和验证资源；若计划或接口再漂移，停止并退回计划支撑。
2. 在`数据服务.需求类.h`实现根结构 DTO、登记、交付校验、构造注入、根材料 DTO/状态、根入口、写集构造、原身份读回和同截止完整核验；普通需求 DTO、入口和语义保持不变。
3. 在`装配.普通应用.cpp/.h`建立并登记需求 owner、构造并保有需求服务、提供受限 accessor；不调用根入口。
4. 仅在需要独立编译/运行专项时新增并登记专属验证源及工程条目；施工与验证事实仅写入`施工记录/ARCH-L4-INSTINCT-ROOT-DEMAND-PROVIDER/**`和`验证记录/ARCH-L4-INSTINCT-ROOT-DEMAND-PROVIDER/**`。

允许修改：`海中鱼巣/领域/数据服务.需求类.h`、`海中鱼巣/装配.普通应用.h`、`海中鱼巣/装配.普通应用.cpp`、`海中鱼巣.vcxproj`、`.vcxproj.filters`（仅新增专项文件时）及本计划专属记录。

禁止修改：8121阶段21入口、启动入口、线程、特征/存在/状态/动态/概念 owner、任务 owner、普通需求与任务公开 DTO 语义、旧`.ixx`、任何现有 owner 建立键或普通应用既有装配顺序。

## 6. 错误收口与恢复边界

入口参数错误、无效/退出/错型`F`、根结构不完整、同键异义、引用冲突、根间交叉、重复成员、非`I64_MAX`值、槽与值不一致、owner错配和不可证明的材料损坏，全部零新写并返回具名非成功。资源失败保持资源失败；内部断言、映射损坏或本不变量破坏保持内部不一致，禁止伪装为普通拒绝或等待。

提交前截止改变或组合读回跨代返回事实代次漂移、零成功交付；提交返回未知只允许原请求/原身份重放读回收敛。恢复不创建平行恢复账、不扫描全库、不按节点编码排序猜测根身份，也不退出、覆盖、清理或迁移任何既有事实。

## 7. 验证矩阵与完成声明

- 静态：关系方向只为`D->F/D->T/L->D`；`T`只经I64属性槽持有`I64_MAX`；不存在普通四关系、自我绑定、线程/启动调用、旧L2引用或`T->F`。
- 结构登记：首次、精确重复、同键异请求、节点种类/owner/首次材料损坏、截止漂移与资源失败；四节点均同 owner 正确读回。
- 根 provider：安全与服务各自首次、精确重复、原身份发布未知/重启读回收敛、同角色异F、F未找到/退出/错型、两个根交叉、不完整根材料拒绝、重复`L->D`、普通关系污染、目标值或属性槽错误、写后截止漂移、资源失败和内部不一致。
- 装配：需求 owner 固定建立、根结构登记、服务持有/accessor；装配不调用 provider、不写F、不生成自我关系，既有装配回归通过。
- 构建：新增专项 Debug/Release 通过；根工程 Debug/Release Rebuild 仅证明编译/链接，不取代运行、恢复或集成验证。

本计划完成只证明冻结范围内的根材料 provider 代码、专属记录及规定验证已发布；不证明4115实际F provider、8121阶段21、根值比较、启动、线程、跨进程恢复、连续运行或本能系统集成能力。
