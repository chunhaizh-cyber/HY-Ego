## 4. 冻结公共合同和物理位置

### 4.1 公共纯值头

在`合同.相关概念添加参与.h`、`namespace 海中鱼巣`中新增：

```cpp
struct 概念树读取头 final {
    std::uint32_t 合同版本 = 1;
    std::uint64_t Gread = 0, H = 0;
    friend bool operator==(const 概念树读取头&,
                           const 概念树读取头&) = default;
};
struct 概念树写入头 final {
    std::uint32_t 合同版本 = 1;
    std::uint64_t 期望事实代次 = 0;
    L1所有者范围写入幂等身份 幂等身份{};
    friend bool operator==(const 概念树写入头&,
                           const 概念树写入头&) = default;

```

读取头合法形状为合同版本1、`Gread>0`、`0<H<=Gread`；当前读取由调用方显式令`H=Gread`，不把H=0解释为当前。写入头合法形状为合同版本1、期望代次和幂等身份均非零。守卫由RC合同/服务私有实现，不恢复旧通用CRUD。

## 5. RC结构、数据操作和失败闭合

### 5.1 53项初始化

`初始化二次关系结构`位于独立初始化文件，只借尚未移交的概念owner端口。固定本地键和事实数严格采用4242第4节：1个扩展锚点、23个类型、1个规范化规则、3个值、1条pure v2定位边、23条类型登记边、1条规则归属边，共53项。

普通应用使用施工层具名固定初始化键`0x1404`，请求预算至少53。该值只属于同一概念owner的结构初始化首次重放，不进入RC定义、结构交付或世界机器语义；当前生产源码已使用`0x1401`、`0x1402`、`0x1403`且全仓受跟踪生产代码无`0x1404`，因此本计划冻结下一互异值。S0若发现同owner已有`0x1404`或键域规则变化，属于计划DRIFT，必须退回计划支撑，不得临场改键。不得在数据服务构造或读取中隐式初始化。已有完整交付零写复用，首次键精确重放恢复原结果，半交付/多锚点/错owner/错误节点种类、表示、角色或生命周期均返回具名非成功且零修补。

### 5.3 规范化、查重和写集

规范化按4242第3.1节执行：共同约束展开、A/B角色保留、AND无损展平、D按位与、矛盾拒绝、确定排序去重、FC域交集和完整规范形查重。摘要只召回，完整定义裁决；未完成扫描不返回同义缺失。

建立在同一个概念owner写集中发布普通概念节点、不可变特征类别、RC定义、规范化规则、生命周期、显式完整父组和本次合法形成来源。新建/重放独立读回；不同键同义零写复用；退役命中不换键绕过。原写入头、规范含义、父组和来源按首次材料恢复，预算不进入业务键。

### 5.4 来源、用途、图、治理和退出

F/B/概念来源分别走正式provider并按原H核验；B只经同实例窄provider，不复制B解析器。用途只有4242规定的四种角色，业务依据必须是已发布节点；结构层只核验引用，不替业务证明采用。

图只返回RC→RC直接边，允许多个空父顶层，完整无环；父组替换精确比较全部当前父边并同事务变更。生命周期只按7140合法迁移。来源释放不解除定义引用和用途。退出要求退役、无活动外部引用，并同事务处理必要替代父边；不删除F、B、S、E、K、FC、EC或子RC。

### 5.5 FC/EC约束读取适配

`读取二次关系约束定义`复用现有pure v2 I64特征概念、通用存在概念及存在概念两组的真实读取过程，汇出实际计量。FC仅接受完整`纯I64特征概念定义`；通用EC仅接受规则版本1、`不预设特征`、存在类别和空父顶层；具体EC仅接受现行`存在概念两组事实_v3`。其它分支规则不支持，失败定义为空。
