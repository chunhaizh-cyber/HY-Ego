# TASK-SET-CONDITION-DECOMPOSITION 任务集合条件分解

日期：2026-10-13；版本：v0.1。本文合并详细设计与施工合同，状态只由计划索引登记。

起点：`c70de6daa0e1a83accdec2f21bd1ba28c939fe77`，共享 `main`。来源：用户本轮确认集合包含、指定成员/任意真实成员/符合条件成员、未知编码不造假、fresh绑定核对，并明确要求开始实现。计划所有者为交互任务下 `set_condition_plan`；代码所有者由顶层交互任务统一指定，本计划整体只占一个代码切片。文档发布由顶层持唯一Git租约完成。

## 1. 目标与边界

将已有I64条件子需求通路扩展到服务任务集合：正式概念表达目标 → 筹办检查 → 缺条件提议 → self发布需求 → manager关联任务 → fresh复核。集合成员语义无序，规范表示按稳定编码排序去重，满足使用包含，不把数组一律当集合。

本轮不实现获取服务任务本能方法、结构化服务要求采用、结算前置业务、消息发送或自然语言谓词。成员条件首版仅支持“任务恰好对应指定正式需求节点”，是用户确认的“符合条件成员”的有限强类型实现；不支持任意脚本、回调谓词、任务状态组合及人类要求自动转需求。本轮不修改正式规范或规则。

依据：[0050](../规范/0050_项目通用机器逻辑与禁止性规则总纲_20260721.md)、[3100](../规范/3100_根规范_需求.md)、[3200](../规范/3200_根规范_任务.md)、[3300](../规范/3300_根规范_方法.md)、[5260](../规范/5260_子规范_任务治理详细合同.md)、[7160](../规范/7160_子规范_特征概念形成组织与名称关联.md)及本轮具名用户裁决。7160旧的封闭值域枚举在本切片由用户已确认集合目标扩展替代，其他类型和生命周期不变。

## 2. 已核对事实与复用

- `概念_特征类`已有`服务任务集合身份判等`，材料为U64数组；已有`vector<稳定编码>`值域是完整特征值材料身份列表，不能改义为集合成员。
- `新_任务类::提议任务条件子需求`与`新任务条件子需求项`目前只消费I64区间；self采用、就绪复核与祖先循环检查重复该假设。
- 需求目标已经使用值域概念和比较关系概念，不增加第二份持久集合目标；方法条件和结果也已有概念引用，不另设平行字段。
- 方法结果保证满足逻辑已有非I64值域关系分支，可复用；集合新variant必须贯通值域比较。
- `查找冲突需求`当前仅接收需增加/需减少，集合的未满足但无有向差值必须成为合法输入，不得虚构增减方向。
- 需求、任务、概念、特征各有递归锁；不能在概念或需求锁内调用取得任务锁的查询。现有`是需求节点`也取得需求锁，不可用作反向provider。
- 复用现有参数绑定、提议消息、self受限需求发布、manager建任务、比较概念建立与当前满足复核。不新建任务树、独立二次特征实例或集合事实缓存。

## 3. 冻结值域与接口

### 3.1 唯一表达

在`海中鱼巣/领域/概念_特征类.h`新增并加入`特征概念值域`：

```cpp
struct 特征概念任务集合值域 final {
    std::vector<稳定编码> 必含任务节点组;
    bool 至少一个任务 = false;
    std::vector<稳定编码> 必含需求任务组;
    friend bool operator==(const 特征概念任务集合值域&,
        const 特征概念任务集合值域&) = default;
};
```

三个约束AND：全部指定任务必须存在于当前集合；至少一个要求真实成员非空；每个指定需求必须有其对应任务出现在当前集合。无占位编码。每个组规范排序去重；非空组已经蕴含至少一个，规范化时该布尔置false。三个约束全空表示不要求成员，不表示空集合相等。不存在的指定任务是错误引用；真实需求尚无任务是合法未满足。

仅`U64数组 + 服务任务集合身份判等 + 无单位`接收该variant。现有轮廓、普通数组、完整材料有限域、精确集合判等0/10000不变。约束域表示“所有满足要求的集合”的范围；不是一份具体当前集合。

### 3.2 只读成员身份端口

同一头文件新增：

```cpp
enum class 特征任务成员读取状态 : std::uint8_t {
    已读取 = 1, 未装配, 节点不存在, 结构不一致, 资源失败
};
struct 特征任务成员读取结果 final {
    特征任务成员读取状态 状态 = 特征任务成员读取状态::未装配;
    std::optional<稳定编码> 需求节点;
};
class 特征任务成员读取接口 {
public:
    virtual ~特征任务成员读取接口() = default;
    virtual 特征任务成员读取结果 读取任务所属需求(稳定编码) const noexcept = 0;
    virtual 特征概念规则状态 验证正式需求(稳定编码) const noexcept = 0;
};
```

`特征概念规则状态`追加`读取接口未装配`，不重排既有值。`概念_特征类`新增：

```cpp
void 装配任务成员读取接口(const 特征任务成员读取接口*) noexcept;
特征任务集合条件比较结果 比较任务集合值域(
    const 特征概念准确值& 当前值,
    const 特征概念任务集合值域& 目标,
    const 新_特征值类& 特征值服务) const noexcept;
```

`特征任务集合条件比较结果`同置概念头文件：`特征概念规则状态 状态`；`optional<int64_t> 比较值`（1满足、0不满足，非成功为空）；`vector<稳定编码> 命中任务节点组/缺少任务节点组/缺少需求节点组`；`bool 缺少任意任务=false`。输出组规范排序。命中为本次值式定位，不取得持久绑定事实身份。

`新_特征类`新增同名结果型包装：

```cpp
特征任务集合条件比较结果 比较任务集合条件(
    稳定编码 特征类型概念节点,
    const 新特征准确值& 当前值,
    const 特征概念任务集合值域& 目标) const noexcept;
```

包装核验类型根、比较规则与无单位，然后唯一委托概念入口，不复制集合算法，不直接取得端口。概念入口读取U64材料，规范化副本，逐成员读取真实任务来源；坏成员、错误引用和资源失败不是未满足。全部验证后再返回语义数值，非成功清空所有部分输出。

### 3.3 provider所有权和无反序锁

`新_任务类`实现`特征任务成员读取接口`。`读取任务所属需求`仅使用任务owner自身schema与L1完整节点/引用结构查询，核验真实任务类型、唯一需求引用、任务集合根成员登记及Vt不可变回指；不调用`获取任务`，不取得任务互斥，不读取任务状态，不进入需求/特征/方法服务。对来源需求调用下述只读身份验证。必须再按任务需求字段反向查询该需求的任务，完整核验候选任务类型、唯一需求引用与根登记，恰好一个且等于当前任务才返回已读取；多个对应任务是结构不一致，不任取一个。此反向检查也是由需求条件推导具体任务身份的必要前置。初始化完成前返回结构化非成功，不访问未稳定schema。

`新_需求类`新增公开：

```cpp
特征概念规则状态 校验集合成员需求身份(稳定编码 需求节点) const noexcept;
```

只经一次L1完整节点结构读取并用需求owner自己的schema核验正式需求类型、必要唯一身份/目标引用形状，不取得需求互斥，不复核目标值，不遍历父树，不查任务。schema只在现行初始化阶段建立，运行前冻结；并发重新初始化不在现行生命周期合同内。task的`验证正式需求`委托此函数，不复制需求私有schema。读取不得把分步材料声称成跨owner原子快照，最后使用时仍fresh复核。

`装配.普通应用.cpp`在需求和任务初始化成功、线程启动前注入任务服务；清理器位于线程成员之前、任务服务之后，线程全部析构join后、任务服务析构前解除端口。概念类不拥有接口，不反向包含任务类。未装配不是空集合或比较不满足。独立调用方可以显式注入现行正式task owner，无新增CLI、自检模式或测试provider生产接线。

## 4. 概念存储、关系与生命周期

概念owner新增互斥值域字段：集合域标记I64，至少一个I64，必含任务节点引用多项，必含需求节点引用多项。不得把稳定编码写成I64占位或裸字符串；持久结构只引用正式节点。初始化、完整读取、定义规范化、建立/复用、更新、字段互斥检查、删除与子域校验全部同步新variant。

新域创建/修改先验证所有指定身份，随后走既有概念owner发布/回滚入口；失败不发布假概念。持久读回必须恢复相同规范DTO。所有字段属于概念的唯一owner，不创建新世界事实、需求或任务。实际集合仍由既有服务任务同步生成；本轮不改自动同步政策。

值域关系的方向以“允许的集合范围”为准：要求越多，允许范围越窄。A约束蕴含B约束时，B包含A。固定任务可通过其正式需求来源证明一个需求成员约束。对应需求的唯一任务若已存在，可证明同一指定成员约束；没有时不能生成假的编码。所有引用和唯一关系都经正式端口核验。两组正向成员要求合并为AND，其成员组取并集，任意成员条件按冗余规则规范化；不发生数值区间求交。

全材料域包含新域。新域彼此通过约束蕴含判相等/包含；互不蕴含但可共同成立为相交，不以成员列表不交判分离。与既有完整材料有限域比较时，逐个完整U64材料代入同一条件算法：全部命中为约束域包含有限域，部分命中为相交，零命中为分离；有限枚举不能证明对开放正向约束域的反向包含或等价。不得混淆完整材料身份与成员身份。现有`比较值域`没有特征值参数，可在实现中使用该owner的现行全局材料读取能力或增加私有纯读取helper，不改变公开签名、不新增数据owner。

## 5. 任务、自我、需求消费者

`新任务条件子需求项`保留既有I64区间字段与单位，在末尾追加`optional<特征概念任务集合值域> 集合目标`。I64分支有区间无集合目标；集合分支区间为空且有集合目标。完整目标仍是值域概念引用，DTO只是冻结读回投影。错误双载荷拒绝。

`提议任务条件子需求`保留I64行为，集合分支fresh定位当前特征，调用基础比较；不满足才提议。缺少指定成员通过差集确定，但正式子需求保留完整集合目标，防止原本已满足的成员消失后被忽略。未知任务只保留正式需求成员条件。零目标合法已满足；缺当前特征/值仍是材料未到，不推断空集合。

同一目标存在/FT的集合条件合并为一个AND集合域，调用概念owner建立或复用合并目标；I64仍按既有区间检查。提议的`全部条件项组`保存稳定条件源投影；缺失/命中证据不参加来源同义键，世界值变化不能伪装成条件定义变化。

`是条件包含目标`扩大到该集合variant，集合关系概念仍表达当前值落在目标约束值域内；不是把U64集合当I64差值。self采用对集合建立现有`二次特征算法::特征材料相似度`的参照结果域关系（包含于参照值域），输入类型均为同一FT；旧I64仍用有向特征差值。此处沿用既有非I64目标域关系定义：包含结果域映射到精确命中10000；基础包含函数的1/0是本次满足标志，不作为10000相似度载荷持久化或冒充该算法运行结果。本轮不改变二次算法定义，也不把`服务任务集合判等`标签改义为包含。

self的正式需求一致、来源二次读取、创建前fresh校验、幂等重投、失败后续读回和manager承接全部保留；新增variant投影一致检查，不保存独立二次特征实例。

需求`复核当前满足`识别集合目标，调用基础比较；1映射已满足、0映射未满足但无有向差值，数值差异为空；资源/结构/未装配分别非成功。无序包含不导出大于小于方向。`复核条件子需求就绪`核对同一目标域投影并复用该需求入口，执行前通过既有选择逻辑再次核对真实成员。

任务需逐项同步：筹办条件检查、结果选择及`结果域保证满足需求`、祖先循环检查、父子方向一致性、`查找冲突需求`及`*需求方向`使用点、结果实际满足复核。`承接已确认条件子需求`基线约10010行的I64域硬限制必须改为对应载荷核对，否则self已建集合需求不能由manager承接。基线约5393与5500行的实际预计结果、禁止结果值域匹配必须将同次执行冻结的准确集合值代入统一基础比较，不读成当下其他集合，也不因非I64跳过禁止结果校验。集合前置/结果使用值域保证关系，不强制提取I64方向。不能证明时返回现有材料不足/不支持分支，不假定增加。对只有正向包含要求的两个集合目标，成员不相交不构成冲突；任意成员存在不代表本次业务目标已取得。集合方向目标不在本轮范围。

祖先循环检测使用同目标存在/FT/规范集合约束与比较关系，等价祖先目标不可重新生成；不把约束更强/更弱未经证明当等价。实例、概念或角色绑定变化按既有来源已变化处理，不能继续采用旧提议。
