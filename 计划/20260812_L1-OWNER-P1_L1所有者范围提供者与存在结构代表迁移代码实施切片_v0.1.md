## 5. 硬性算法与 ABI 门禁

- owner 请求没有可写 owner 字段；owner 只由端口注入。
- owner 事实和普通事实必须同仓、同代次、同候选 / 确认 / 撤销 / 发布；不得建第二仓或旁路表。
- owner 校验在第一笔候选前；owner 不符为许可拒绝，owner 正确后的未闭合引用才是引用冲突。
- v2 幂等域固定为实例内 `(owner, 写入幂等身份)`；v1 / v2 账不碰撞。
- raw 端口 private 构造、不可复制、移动源失效；服务不返回 / 借用 / 转签端口。
- L1 核心零 L2 import / friend / 枚举 / 名称分支。
- 存在服务 owner-aware 读回必须验证 owner；v1 读取不能冒充 owner 证据。
- 场景服务不得再临时构造存在服务；不建立无写权影子类型或兼容旧构造。
- 固定属性成功路径不得通过测试专用属性类型冒充正式身份来源；未具备正式来源时保留未覆盖声明。
- 恢复、重入、未知发布收敛不实现空壳或固定未实现入口。
