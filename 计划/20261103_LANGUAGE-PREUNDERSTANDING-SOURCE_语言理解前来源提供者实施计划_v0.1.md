## 4. 私有 schema、字段和初始化

在 `新_语言类.cpp` 现有匿名命名空间、接收含义私有键组邻近新增：

```cpp
enum class 语言分界键 : std::size_t {
    角色, 所属语言组织, 来源消息, 来源根范围, 来源根路径,
    来源正文材料, 来源登记, 总数
};
std::array<稳定编码, static_cast<std::size_t>(语言分界键::总数)>
    语言分界句柄{};
稳定编码 分界键(语言分界键) noexcept;
```

七个句柄均是没有自有字段的真实键节点，`来源登记`也是字段键；**不新建组织根**，直接复用 `语言组织根节点`。这些键不作为类型名节点，不新增通用节点族枚举。来源节点恰有六字段：

| 键 | L1 内容 | 基数／约束 |
| --- | --- | --- |
| 角色 | `基础值{int64_t{1}}` | 恰一，来源角色固定 1 |
| 所属语言组织 | 真实节点引用 `语言组织根节点` | 恰一 |
| 来源消息 | 真实节点引用 M | 恰一，必须是正式接收消息 |
| 来源根范围 | `基础值{vector<uint64_t>{0,N}}` | 恰一，N 为整条非空原文 Unicode 标量数 |
| 来源根路径 | `基础值{vector<int64_t>{}}` | 恰一，本叶只支持根空路径 |
| 来源正文材料 | 真实节点引用 M 的正文材料 | 恰一，不另存字符串字段 |

组织登记唯一为 `语言组织根节点 --来源登记字段--> 来源节点`，每个来源恰一，不另建权威 map／父子外边／反向登记。来源唯一键就是既有完整来源键（M＋根范围＋路径）；同 M 同键同材料复用，不同 M 即使共享材料或文字相同也不能合并。同键材料不同、重复登记、同键两个来源均为结构损坏。

`初始化分界结构()`在 `新语言互斥` 下执行：

1. 原语言基础结构尚未就绪时返回 `未初始化`，不调用原初始化、不建立语种身份。原结构一旦已被本叶使用却丢失／损坏，转工程异常，不降格为普通未初始化。
2. 七句柄全零：预分配七个空 `基础组内新节点`，一次 `原子建立节点组`。资源失败保留全零；成功必须返回七个不同且有效身份，以无分配复制同时填满数组；其他状态／不完整结果转工程异常。
3. 全有效：复用同组；部分有效／重复句柄是工程异常，不补建、不删除、不建第二组。
4. 一次读取原组织和七键，确认节点存在、键自有字段为空，原组织仍有效。资源失败返回 `资源失败`，但已获得的完整七句柄保留，下次只复核，不能重复分配。键存在时允许其具有被来源字段使用形成的入向引用，不要求完整联合快照仍等于初始空快照。
5. 全部核验通过才返回 `已完成`；来源入口每次也复核句柄和原组织，不能把“有句柄”直接当结构有效。

键组原子建立不含任何使用新键的字段，故不违反“字段键必须为既有真实稳定编码、不能使用组内引用”的 L1 限制。没有两阶段 typed-root 半结构，也没有失败清理／恢复重挂步骤。

### 5.1 复用链的可见资源状态修正

现有 L1 的 `查询完整节点结构`、`查询节点组完整结构`均为 noexcept，并将 bad_alloc／length_error 转成 `基础结构操作状态::资源失败`；当前外设私有辅助却将其统一抛为 runtime_error。若不修正，新窄口仅捕获 bad_alloc 无法取得该资源状态。因此在同一个外设 cpp 内直接修改以下两个既有私有辅助，不新增或改变签名、默认参数及公开接口：

```cpp
基础联合节点快照 读取消息快照(稳定编码 节点);
std::optional<新外设消息信息> 读取正式消息(
    稳定编码 节点, std::vector<基础联合节点快照>* 保护 = nullptr);
```

精确改动只有三个 L1 结果分支：

1. `读取消息快照`的单节点 `查询节点组完整结构` 返回后，先判断 `状态==资源失败` 并 `throw std::bad_alloc{};`，随后保持原完成状态、数量及快照检查。
2. `读取正式消息`入口 `查询完整节点结构` 返回后，先作相同资源状态上送；原 `节点不存在`→nullopt 和其余结构检查顺序／语义保持不变。
3. `读取正式消息`最终五端点 `查询节点组完整结构` 返回后，先作相同资源状态上送，再执行原完成状态、数量、端点及消息字段一致性检查。

外设 cpp 显式包含 `<new>`。这里 bad_alloc 只作为本 owner 内部的资源控制异常传递，准确对应 L1 已给出的资源状态（含其已归并的 length_error）；不凭异常文本、what() 或日志判型，不把其他状态重标资源失败，不改变正常未找到／消息身份／保护投影。两辅助都不捕获或本地记录，统一向既有调用边界上送；直接复制快照、字符串或容器时可传播的分配异常亦循原调用链，不增加重试或回滚。

旧调用者的现行收口逐项保持合法，无须改其函数体：

| 既有最终调用边界 | 修正后的资源去向及保持项 |
| --- | --- |

### 5.2 新窄口的资源与材料边界

新窄口只对**已传播到本口**的 bad_alloc／length_error 返回 `资源失败`；它不是“所有底层资源失败均可返回并恢复”的保证。正文经 `消息值服务->获取特征值`取得，该材料 owner 的 noexcept 读取对其内部异常按既有工程终止边界记录并终止，不能跨该终止恢复为外设资源状态。本叶保留该终止职责，不扩写材料 owner，不换原始 L1 旁路读材料，不以正文空值掩盖故障，也不再次重复记录材料 owner 已终结的异常。

合法分流：未初始化→`未初始化`；无效 M→`输入拒绝`；节点不存在或不是正式消息→`未找到`；正式但方向不是接收→`未支持`；正常接收→`已完成`且消息恰一。正式类型已命中却缺字段、登记损坏或正文损坏不是未找到。非成功时消息为空、前提为空。

成功前提由私有读取的**最后一次五端点联合读取**投影，不复制整组快照：

- `节点组`恰为去重后的 M、消息根、场景、窗口、正文材料的 `基础节点`，只保护必要端点存在。
- `字段集合组`恰一项：`节点=M`、`字段节点=nullopt`、排除键组空、字段组为该次 M 的全部十个自有字段。L1 支持这个不指定键的全集选择器，不要求把十个私有字段键加进节点组；若未来改用显式键选择器，则须按 L1 合同将键身份纳入，但本叶不改选型。
- `外部关系集合组`为空。不携带消息根登记全集、场景／窗口自有字段、收发计数、M／材料的入向引用或无关历史节点。

正文值由原材料 owner 的不可变正式字符串及真实材料引用保证，不在语言域解释其私有字段。正式消息没有公开删除／改写口；本叶也不增加这类口。故其它消息追加、计数变化、M 增加入向来源引用均不会使本前提过期。

语言入口只核强类型消息与请求一致、方向接收、正文非空、材料引用有效及端口前提通用结构；它可按中性选择器比较最后联合读取的字段，但不能识别消息私有字段位置。端口“成功但缺消息／缺必要 M、正文端点／前提形状违反本节”属于工程合同破坏，不接受空保护继续写。

## 6. 来源输入、闭包读取和锁序

输入必须 M 有效、`原文起点=0`、`原文终点>0`、空根路径；无效 M、空／逆范围、起点非零返回 `输入拒绝`，非空路径返回 `未支持`。正文只沿用既有 `严格UTF8字节串有效`，再复用私有 `读取已校验码点` 按 `string::size()` 推进并计数；非 BMP 算一个标量，NUL 保留并计一个，不使用 strlen，不去标点、不折叠空白、不做 NFC/NFKC 或编码修复。既有校验拒绝非法 UTF8、代理区、U+FEFF、U+FFFD；正式消息违反该保证是工程错误。计数超 U64→`输入拒绝`，终点不等于完整 N→`输入拒绝`。源只支持整条正文，不把子范围或未知非根路径猜成根出现。

锁序固定：语言锁短预检并释放→调用外设端口（内部外设锁释放）→语言锁→L1读取／发布。禁止持语言锁回调端口，禁止两个 owner 锁互持。进入最终语言锁后必须重新核初始化和输入关联。端口失败零本次写；资源失败返回工程控制，不产生业务否定。

在匿名命名空间固定以下内部辅助形态，均不对外开放：

```cpp
struct 分界来源记录 final {
    稳定编码 节点, 正文材料;
    新接收认知来源键 来源;
};
struct 分界来源闭包 final {
    基础节点结构 语言组织;
    std::vector<分界来源记录> 来源组;
};
std::uint64_t 计数分界原文标量(const std::string&);
分界来源记录 解析分界来源(const 基础节点结构&);
分界来源闭包 读取分界来源闭包已加锁(const 基础只读预期&);
bool 分界消息投影相符(const 基础只读预期&,
    const 基础联合节点查询结果&);
```

`基础联合节点查询结果`为已核对的当前 L1 真实结果类型，不创建同义底座类型。`计数`只接已严格校验文本，纯计算；`解析`只读六字段，逐键和 variant 类型精确校验，不用返回空记录掩盖损坏。

闭包读取先用原组织登记字段发现全部来源 ID，再在同一次最终 `查询节点组完整结构` 中读取组织、七键、所有已登记来源，以及端口 `发布前提.节点组`，去重 ID。初步定位只是发现闭包，不构造成功载荷。最终组织登记集合须等于发现集合；本 owner 互斥内发生无法解释的登记变化是工程不变量破坏。逐条校验来源六字段、唯一登记和完整键唯一性；原组织的其他合法字段仍保留，不因本叶不认识而删改。没有登记是正常空集合，登记悬空／坏类型／多条相同键是工程错误，不取首、不截断。

在该最终批中逐选择器复核消息中性投影。存在但前提不符返回 `前提已变化`；端口所确认的正式端点无故消失属于工程破坏。读口以这次最终批为线性化点，不再进行一次脱离该批的字符串读取；返回正文取端口已核不可变值。已登记目标来源的 M、材料、范围必须与该消息一致，否则工程错误。

如果端口返回 `未找到`，仍在语言锁下读取本域登记闭包：未登记该键可正常返回 `未找到`；若已登记，意味着正式来源端点失效，转工程错误。不能把坏的已登记引用伪装成尚无来源。

## 7. 建立、复用与正式读取

### 7.1 建立或取得

1. 完成第 6 节预检、锁外消息读取、范围计数及最终闭包核验。
2. 同键来源已存在且材料／范围逐值一致：返回 `已完成`、正式信息、`本次已发表身份`空，零写。不得因语种未识别、无 U、无词条或无 D 拒绝保存或修改身份。
3. 不存在：发布前构造完整返回载荷及请求容器，减少发布后分配。`基础节点组追加请求`精确为：一个新来源节点，六个初始字段按第 4 节；一条追加登记字段，其宿主为原语言组织、键为来源登记、内容为 `基础组内节点引用{0}`；`预期既有节点组`只放最终批取得的原组织 `基础节点结构`；`只读预期`放本次消息窄前提及七键存在／空自有字段投影；`预期联合节点组`、替换、删除和外边组均空。
4. 单次 `原子追加节点组`检查消息前提及根写资格并同时发布来源和唯一登记。新节点的角色／范围／路径为直接值，组织／M／正文为真实节点引用。不能先建空来源后补字段，不能通过额外调用分别登记。
5. 成功须恰一新节点、六个初始字段关系、一条追加登记；先以无分配方式保存已发表来源 ID，再读回正式来源与组织登记，复核完整六字段、同键同材料和恰一登记。成功信息只从正式读回重构，禁止仅凭请求返回成功。读取失败不撤销来源；同键下次取得同身份。
6. `本次已发表身份`只在本调用确实新发表后填该 ID，包括后续读回／复制资源失败；初次成功也携带该真实 ID。调用前已有来源的复用／读取不填此字段。不用此字段证明语义效果或形成业务结果知识。

写线性化点是 L1 一次独占交换。`预期不符`→`前提已变化`且本次零写；`资源失败`→同名工程控制。L1 入口拒绝、内部不一致、已保证的键或引用不存在都转工程错误，不把施工错误包装成 caller 输入拒绝。发布后资源失败返回信息空、真实已发表身份保留，不重发、不删除、不假成功。

### 7.2 读取

使用相同输入、锁外消息和最终闭包核验；无本键登记→`未找到`且零写；有且一致→`已完成`、完整信息且发表身份空。读取不初始化、不补登记、不修复损坏、不调用词条／解释／需求 owner，不确认语言选择。
