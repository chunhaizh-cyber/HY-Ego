## 5. 实施步骤

1. 数据头导入 task owner 数据合同，新增 v2 类型、别名、完整性、见证和结果谓词；不修改 v1 布局。
2. 现有服务模块公开导入 L2任务结构模块，新增两个 v2 登记和独立键段。
3. 实现 v2 编解码、关系闭包验证、规范排序、读前 / 读后守卫和两个公开读取入口。
4. 构造函数幂等登记 v2 结构；登记失败时服务构造 fail-closed。服务成功构造后，v1 读取不得依赖 v2 是否有业务成员。
5. 仅在验证宏内扩展 fixture，形成 v2 0/N、损坏绑定、跨版本污染、漂移和资源失败矩阵。
6. 扩展现有端到端专项，真实调用 v2 公开入口；不得只测 DTO 谓词或 private helper。
7. 形成施工 / 验证记录，执行全部门禁并精确发布白名单。

## 6. 失败与兼容收口

- v2 合同 / 请求非法：入口拒绝，空载荷、截止 0。
- v2 登记缺失 / 版本不符：结构未登记，不读取 v1。
- 成员、载荷、选择 / 冻结 / 实例 / 状态 / 动态关系缺失、多义或错端点，或者筹办 / 执行轮次无效：集合不闭合或引用冲突；不得跳过坏成员。
- L1 许可、漂移、资源和内部错误按现有 owner 状态映射；全部非成功空载荷。
- v1 读取结果不能投影为 v2 成功；v2 空集合也不能证明活动不存在。
- 本计划没有生产业务写入口、提交后未知或撤销分支；验证 fixture 写入仅在验证宏内可见。
