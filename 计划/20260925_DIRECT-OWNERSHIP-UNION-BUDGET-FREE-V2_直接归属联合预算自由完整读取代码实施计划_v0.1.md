## 1. 目标与完成条件

在不修改 L1 的前提下，发布存在组成、场景直接包含及直接归属联合三层预算自由版本2当前完整读取合同和真实实现，使后继场景树 v2 可以在同一 G0 下读取完整直接父/子组而不调用任何旧预算入口。

完成必须同时满足：

1. 三组 v2 DTO、成功谓词和公开入口与详细设计一致；
2. 实现只以端点节点、事实代次和正式关系类型定义范围，无最大数量、材料、候选或深度字段；
3. 使用 L1 `读取节点全部当前引用_v2`，不调用 v1 组成/包含/联合读取，不以极大值模拟无预算；
4. 联合父唯一、子组完整、确定排序和非成功零载荷全部成立；
5. 专项 Debug/Release 构建运行及根工程 Debug/Release 隔离 Rebuild 通过；
6. 本轮文件精确提交并普通推送。

## 2. 正式依据与当前事实

## 5. 施工步骤

1. 在`合同.存在结构身份只读.h`按详细设计新增组成 v2 与联合 v2 的版本、状态、请求、结果、成功谓词，并为两个提供者接口追加 v2 纯虚入口。
2. 在`数据服务.存在类.h`实现组成父/子组 v2：先预算自由确认存在身份，再调用 L1 节点全引用 v2，过滤并验证组成关系，形成完整结果。
3. 在`合同.场景角色组织.h`新增场景包含 v2 DTO、成功谓词，并为场景提供者和联合组合器声明 v2 入口；场景子组端点使用中性字段`父`，当前有效普通父存在无场景包含边时合法成功空组。
4. 在`数据服务.场景类.h/.cpp`实现场景包含父组/子组 v2，直接消费 L1 节点全引用 v2，禁止转调 v1。
5. 在`合同.场景角色组织.cpp`实现联合父/子组 v2的失败映射、联合单父校验、全子组合并、去重与确定排序。
6. 新增专项验证；成功、未找到、已退出、代次漂移和结构冲突路径使用真实 L1 运行包和真实两族服务，不用伪 provider 冒充生产成功。当前L1无确定性资源失败注入钩子，因此资源失败只做状态映射/catch分支静态核查和直接构造非成功结果的零载荷谓词核查，不用实际内存耗尽冒充稳定运行用例。
7. 运行静态核查、专项 Debug/Release、根工程 Debug/Release 隔离 Rebuild，回写专属实施记录。
8. 精确暂存允许文件和记录，确认未带入异主 WIP，普通提交并推送。

## 6. 失败收口

- 若当前代码无法在允许文件内取得正式关系类型或 L1 v2 引用事实，停止并具名退回计划支撑，不得修改 L1或扩大到世界树。
- 若纯代码编译错误或谓词错误，可在允许文件内修复。
- 若发现联合直接父语义与1140/4202冲突，停止受影响切片；不得用任取一父或固定优先级掩盖。
- 正式关系类型命中但owner、角色、方向或生命周期错误时固定返回`内部不一致`；不得忽略。错类型关系不属于本合同范围，忽略后继续完整处理正式类型关系。
- 任一验证失败必须保留非成功状态和零载荷语义，不得降低断言、恢复预算或删除失败分支。
