## 5. 实施合同

### 5.1 先补齐current-only读口

目标39个逻辑操作固定为：

```text
普通中性10：提交中性写集、读取中性写入首次结果、读取中性当前节点、读取中性当前关系、读取中性当前值、读取中性当前属性、读取中性当前源关系组、读取中性当前目标关系组、读取中性当前事实代次、尝试读取中性一致当前投影
owner当前读取14：读取所有者范围当前节点、当前关系、当前值、当前事实、所属节点当前完整值组、来源当前完整值组、属性类型当前完整值组、当前源关系组、当前目标关系组、尝试读取所有者范围一致当前投影、尝试读取一致关系类型闭包投影、读取当前结构所有者、读取所有者范围完整空域、读取节点全部当前引用_v2
端口事务8：所有者身份、有效、绑定于、提交所有者范围中性写集、读取首次写入材料、提交跨所有者原子事务、提交三分区原子事务_v2、提交有限N分区原子事务_v3
管理运行包7：建立所有者范围、重新签发所有者范围写端口、退出所有者范围、读取服务、所有者范围签发器、建立L1事实基座运行包、建立L1事实基座持久运行包_v1
```

`读取服务`的const/non-const两个签名按一个逻辑操作计数，但机器清单冻结两个签名。所有既有保留操作的签名、`const/noexcept`、请求字段和非历史状态以开工HEAD现行公开头为基准保持不变；只删除历史/清理字段和状态，不借迁移追加owner或期望G。两项新增入口固定实现为：

```cpp
L1所有者范围当前事实读取结果_v2 读取所有者范围当前事实(
    const L1所有者范围当前事实读取请求_v2&) const noexcept;
L1所有者范围所属节点当前完整值组读取结果_v2 读取所有者范围所属节点当前完整值组(
    const L1所有者范围所属节点当前完整值组读取请求_v2&) const noexcept;
```

两请求字段顺序均为`合同版本, owner, 主键, 期望事实代次`；主键分别为`事实编码`和`所属节点`。结果字段顺序均为`状态, 合同版本, owner, 主键, 期望事实代次, 读取事实代次, 载荷`；载荷分别为可选节点/关系/值联合和按值编码升序的完整值组。状态数值固定为`成功=1,入口拒绝=2,未找到=3,事实代次漂移=5,资源失败=7,内部不一致=8`，4和6保留空洞；合同版本均为2。两项新结果不定义成功辅助谓词；`状态==成功`的结果形状必须满足请求逐字段回显且`读取G==期望G`，所属节点合法但零当前值返回成功空组。

据此实现：

- `读取所有者范围当前事实`：已知owner、事实编码、非零期望G；同锁返回节点/关系/值恰一分支；
- `读取所有者范围所属节点当前完整值组`：已知owner、所属节点、非零期望G；按值编码严格升序，合法空组成功。

既有来源、属性类型、空域和节点引用v2全部预算自由。所有读取只核请求范围和同G当前事实，不调用全仓`状态完整`；局部事实/索引互证、owner隔离和G漂移仍必须保留。

### 5.2 迁移全部生产消费者

- 旧历史调用若实际只读取仍当前且`H==Gread`的事实，改用39项中的current-only入口；
- 退出后读回、历史复盘、过去样本和历史身份见证能力直接从公开ABI、实现、结果传播和业务分支删除，不以首次账替代；
- 物理清理流程改为一个原子变化集中的当前引用闭包直接删除；删除前所需信息必须先从当前态取得；
- 旧owner空域改`读取所有者范围完整空域`，旧节点引用改`读取节点全部当前引用_v2`；
- 发布未知、首次稳定编码和原请求恢复只使用原技术幂等身份、首次完整规范化请求/结果与事实代次。

### 5.3 切换L1内存与公开面

- 当前状态只保留G、下个稳定编码高水位、当前owner、当前节点/关系/值/属性槽、当前索引和普通/owner/v1/v2/v3技术幂等首次账；
- 删除历史owner/事实/索引、永久占用集合、墓碑、物理清理账和全部历史/清理入口；
- 所有现行事实DTO删除`退出事实代次`，读取结果删除清理代次和墓碑；现行枚举删除4015指定旧项但保留数值空洞；
- 物理删除所有L1公开结果DTO、运行包和恢复结果上的`成功()`、`成功(request)`、`确认空域()`等辅助谓词；全部生产消费者改为显式检查状态、请求回显、事实代次、载荷和原合同精确重复形状，不把未找到、漂移、资源失败、已可能发布或内部不一致当成功；
- 写集字段`退出事实`保留拼写，唯一语义是直接删除当前编码集合；同次核验完整当前引用闭包；
- `状态完整`保留为候选发布、恢复和迁移完整性门禁，普通读取不得重复执行全仓证明；同一候选在持久准备前后不得重复全量核验。

### 5.4 格式4和旧格式一次迁移

- 格式4字段严格按4070：合同/格式、G、下个稳定编码、当前owner/三类事实/槽、技术幂等首次材料和摘要；
- 格式1/2/3旧布局和旧稳定枚举仅存在于恢复实现私有类型；先完整验证旧载荷和高水位，再丢弃历史/墓碑/清理/永久占用，投影current-only候选；
- 写入格式4并切换清单后必须独立二次恢复；旧槽、临时迁移材料删除失败则拒绝交付运行包；编码器此后只产生格式4。

## 6. 失败收口
