## 6. 实施顺序

### 6.1 目标合同恢复

1. 增加目标合同幂等首次完整读取 DTO、状态和成功谓词。
2. 从状态 owner 首次写入材料恢复合同身份。
3. 按请求 `G0` 读取当前合同；截止不同返回当前性漂移。
4. 逐项实现 `已读取/未找到/已退出/入口拒绝/当前性漂移/引用冲突/资源失败/内部不一致`；仅 `已读取` 成功。
5. 非成功统一空载荷、截止零；新 DATA 合同不声明 `许可拒绝`，端口或装配错误映射内部不一致。

### 6.2 首值首态原子入口

1. 特征服务增加 private 首值参与者形成、闭包验证和受限写端口协作；状态服务增加 private 首态参与者形成和闭包验证。
2. 状态服务对特征服务引用改为非 const，依赖只允许 `状态 -> 特征 -> L1`，不得形成反向 import。
3. 状态服务公开 `新增特征首值与初始状态_v1`，固定 L1 状态槽承载初态 owner、动态槽承载首值 owner。
4. 复用现行 L1 双参与者原子运输，旧运输字段名不得外泄为动态语义。
5. 实现 `已提交/精确重复/入口拒绝/当前性漂移/幂等冲突/引用冲突/材料未闭合/资源失败/内部不一致/已可能发布` 全矩阵；仅前两项成功且必须返回三项完整载荷和共同 G1。
6. 验证值、状态、选择共同代次和零动态；所有非成功空载荷、共同代次 0。
7. 不修改、不恢复、不消费旧 `新增状态_v2`。

### 6.3 业务 DTO 和 provider

1. 逐字实现详细设计 `0x494E'5354'01RR'00KK` 常量表；禁止运行期派生、跨用途复用或把幂等常量当稳定编码。
2. 实现锚点、初始化结果和纯值二次特征函数。
3. 实现定义、实例、值/状态、注册、合同、需求和列表项的形成或恢复；比较注册的单位、维度、分量角色均绑定各自根特征定义身份，不新增辅助节点。
4. 各请求来源逐字采用正式已发布身份：一阶定义取唯一自我；二次概念、实例、首值、首态、比较注册取对应一阶定义；目标合同取比较注册；根需求取目标合同。
5. 实现 `Gfinal` 全量正式重读；具名安全/服务字段是值式角色绑定，不新增角色节点、关系、owner 或索引。
6. 仅在全部互证后返回锚点。本次有新发布为已形成；零新发布且完整恢复为已恢复；所有非成功空锚点且不产生许可拒绝。

### 6.4 启动和线程

1. 在方法登记根成功后、自我线程创建前构造 provider。
2. 捕获一次大于零的 UTC Unix epoch 纳秒。
3. 初始化非成功时返回失败阶段 21。
4. 自我线程创建合同升为 2，锚点进入有效性、相等和锁定请求。
5. 继续使用现有整请求锁定槽和治理运行门。
6. 所有启动阶段成功后才开放治理循环。

### 6.5 工程与外部验收边界

1. 工程和 filters 只登记两个新增生产业务文件。
2. 不修改 `海中鱼巣/入口.cpp`，不增加生产专项参数、测试模块、测试宏或故障注入。
3. IntDir、OutDir 全部使用仓库外隔离目录。
4. 18 项业务矩阵由生产二进制之外的调用者在实际使用阶段经公开入口和权威读回执行，本轮全部记为 `NOT_RUN`。
