# 方法问题场景归档与学习接收

身份：`METHOD-PROBLEM-SCENE-FEEDBACK`；版本：v0.1；日期：2026-10-12。
代码起点：`c876673d1f410201d1764fdcf6b2434648b64b19`，`main`。执行资格只由计划索引登记的精确 blob 决定。

## 1. 目标、依据与完成边界

用户当前裁决：任务取得真实执行反馈，判断是否提供方法问题新信息；有用才把当时场景的完整已知材料保存在模拟世界树，再通知学习线程。原始样本不可变，后续模拟只能使用另行生成的工作副本。本叶只闭合现实执行阶段；不实现未执行的筹办问题、工作副本生成、方法自动细化、知识发布或重筹办。

机器依据为[5370](../规范/5370_子规范_方法学习与知识形成.md)、[5360](../规范/5360_子规范_方法函数登记执行与任务反馈.md)的同次执行完整材料、学习所有权与任务独立判定边界；本轮仅保留问题材料，不进入上述规范的候选评审及发布阶段。编译与测试遵守 AGENTS 7.1，本轮没有测试授权。

完成：生产 W3-B 能判别本次问题、归档原始首后场景；self 只转发轻量消息；同一学习工作线程按 FIFO 读取归档并形成只读收集结果；任务目标满足与结算不等待归档或学习。代码编译链接通过不证明运行或业务闭环。

## 2. 当前事实与复用裁决

- `新_任务类.cpp` 执行参数场景已确定后运行本能函数；函数返回完整本次条件结果对，但现有执行回流主要消费结果。新增旁路捕获，不改变函数入口及任务结果判定。
- `评估方法执行影响` 已产生方向/域验证、预计但未发生项和计划外状态。复用这些事实，不新增预测算法。幅度验证当前等同域验证，不独立计数。
- `读回任务执行` 受任务最新执行与治理状态约束，不能当历史学习读取入口；新增按 T/X 保存的运行期材料与轻量回执。
- `新_模拟世界类` 只有结算专用样例，不能复用固定 64/256 容量保存任意场景。扩展该 owner 的通用不可变归档，内部可委托独立编解码文件。
- `新_学习线程类` 只有按方法去重的模拟工作；扩展一种真实问题消息，沿用同一 OS 工作线程和结束通知，不新建学习线程。
- `新_自我线程类` 现有任务结果回流、学习 future 消费和资源重试等待可复用；禁止在 self 上采集、复制或写入整个场景。

## 6. 模拟世界不可变归档

`新_模拟世界类` 实现 `新方法问题归档接口`。内部编码/读取由模拟 owner 的`方法问题归档.模拟世界.h/.cpp`承载；不暴露现实写接口，不被现有练习写入口接受。

物理结构：模拟世界根 → 归档样本 → 动作前/结果取得时场景快照 → 各类内容节点。样本存 T/X、方法/实例/配对、问题与评估、实际运行对；快照存采集元信息和类型分组。使用基础数据节点及字段显式 schema 编码完整 typed DTO（含各 variant 判别、optional 有无、长度/成员顺序与嵌套值）；禁止用对象内存布局、裸地址、仅进程 map 或稍后回读源节点代替。schema 标识为`方法问题场景归档/1`，首版无迁移；未知版本拒绝结构读取。具体字段常量和编解码私有分解属于实现，不改变上述值合同。

容量按实际内容计算并检查整数溢出，分配失败显式返回；先建齐私有样本并独立解码值相等，再以唯一根链挂接发布。挂接是唯一可见点；发布前失败只回收本次未发布节点，发布后读回失败保留已发布样本并返回发布未知。原 ID 存为来源数值，不形成现实引用/RC，不回写源树。原始样本不提供修改/删除公开入口。

同 T/X、同完整不可变材料返回同归档 ID；同 T/X 不同材料是身份冲突。不同 X 即使内容相似也分别归档，禁止跨执行“无新信息”推断。查询和读取通过树验证完整归属/身份/schema；进程缓存只能加速，不能成为唯一归档。归档 provider 内串行互斥，禁止同 T/X 双重发布。

## 7. 学习消息、服务与线程

新`方法问题学习服务`仅持有`const 新方法问题归档接口&`，公开：

```cpp

    bool 材料完整 = false;

explicit 方法问题学习服务(const 新方法问题归档接口&) noexcept;
新学习结束通知 方法问题学习服务::学习(

optional<新方法问题学习收集结果> 方法问题学习服务::读取收集结果(
```

读取归档独立验证归档/T/X/方法身份、非空问题、首后采集阶段、对象去重、缺口标记和结构引用。缺口可保留为不完整材料，不改写成缺失对象为空；未知外部定义不能当冻结内容。收集结果只表达结构可读和已收集，不能声称事实、因果或方法预测被独立证明。归档读取失败及身份/结构错误使用现有`新学习运行异常`原因；正常只返回既有`新学习结束通知{方法节点}`，不增加成功/失败业务语义。学习不修改方法树、命中、任务或需求。

学习线程保留旧构造函数，另增接收模拟服务与问题学习服务的构造函数（两服务存活到线程 join 后）。新增：

```cpp
新学习接收结果 提交方法问题学习(const 新方法问题学习消息&) noexcept;
新学习操作状态 确认方法问题结果已接收(稳定编码 归档节点) noexcept;
```

两种工作共用 FIFO 入队，不再按方法 map 编码决定执行顺序。模拟工作仍按方法去重；问题工作按归档去重并严格核对完整消息身份，同一归档身份不同拒绝。同一完成工作的确认只释放交付占用，保留进程期紧凑已处理回执及同一结果，不因确认后重放重复处理。技术异常不形成已收集事实。停止取消未开始工作；promise 和回调遵守现有锁外通知纪律。只读收集结果由服务持有到销毁。

## 8. self 与生产装配

self 新增`bool 绑定方法问题学习(方法问题学习服务&) noexcept`，启动前唯一绑定；保留旧模拟绑定兼容旧实际项目调用。构造学习线程时两服务同时注入；原模拟路径不变。
