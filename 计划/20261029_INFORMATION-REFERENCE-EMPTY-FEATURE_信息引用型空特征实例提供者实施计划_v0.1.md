## 4. 冻结合同与步骤

1. S0：核对实际源、全部相关调用、用户口径、详细设计、相关知识候选及发布/构建租约。将本叶新增、修改、未改变入口写入专属记录。
2. `概念_特征类` 私有区新增 `friend class 新_特征类` 及 `基础片段组合结果 联合发布新增空实例引用(const 特征概念信息&,const 基础封存追加片段&) noexcept`；仅空F创建分支调用，保持 ARCH-L2 同层协作与 DATA-L1中性发布，不反向回调、不解F schema。
3. helper持概念锁重读模板、锁内当前计数并受检加一；只按正式模板字段比对，不要求名称或旧计数不变。用本owner FC完整预期及计数字段生成自己的封存片段，与F片段一次共同提交，成功读回计数后返回绑定回执。锁序及错误映射按详细设计第4、6节。
4. `建立特征强类型`仅对 `信息节点引用 + 实际值缺省`进入新分支；Fowner封存恰一空F的类型/FC/可选单位，调用helper，读绑定回执和真实F。wrapper不复制实现。`准备特征初值保护`对应空分支完成但不建节点。其它类型保持旧路径；非空值继续拒绝。
5. `获取特征`、`捕获特征匹配实例`显式核info-ref所有值位置皆空，合法空F可读取；非法非空材料按工程链中止，不当正常未知。比较、区间、归组及赋值未支持分支不假成功，不添加目标身份reader。
6. 仅在 `删除特征` 的信息引用型空F普通分支补原清理准备前置：任何删除或计数变化前调用 `准备特征组清理({F},{})`；受外部引用或联合占用时零写拒绝，其它工程异常不降为普通否定。成功凭据保持在函数作用域，持已有F递归锁直到原分步清理结束，禁止立即释放、跨线程、进入删除中阶段或递归调用整组执行。原其它类型/需求引用删除路径不扩改；仍不声称分步删除和计数减少原子，不宣称所有跨owner新引用竞争已解决。详细边界见设计第6节。
7. 汇总相关变更后统一实际工程编译/链接；补知识变更清单、完成层次及剩余项；无测试指令不运行测试或程序。生产WIP不提交，计划状态退出仅由 root按索引规则处理。
