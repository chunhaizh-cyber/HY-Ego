## 4. 禁止范围

## 5. 机械施工步骤

### S0

核对 `main`、`origin/main`、计划 blob、clean state、唯一写入占用和实际接口。运行 fresh Debug x64 baseline build 与清理前模式基线；不得复用旧二进制。

### S1

按现状扫描第 9 节一次精确删除第一删除集。提交候选 diff 必须能逐范围回指删除矩阵。

### S2

运行 fresh build。对每条编译 / 模块 / 链接错误：

1. 记录文件、行、符号和错误号。
2. 判断符号是否由生产合同或结构化自检合同要求。
3. 是则恢复最小表达式或按详细设计提取到唯一具名函数。
4. 否则保持删除。
5. 再 fresh build，直至通过。

编译通过只完成 S2，不得据此完成计划。

### S3

建立 F01—F12、模式路由、应用上下文和最小健康检查。普通 UI / headless 调用图不得包含自检模式函数。

### S4

把真实自检迁入对应模块，核对清理前后 ID 覆盖；隔离生产初始化和测试数据。删除固定伪验收，机械项转真实静态检查。

### S5

接通四个具名调试宏与统一日志投影，删除所有验收 / 自检 / 基准 / 专项控制台、弹窗、UI 和旁路文件输出。

### S6

运行详细设计第 12 节 V01—V15。行为失败只能按真实合同修复，不得重新加入旧冗余。

## 6. 失败收口

出现基线漂移、无关 dirty、范围外接口需求、真实自检 ID 无法映射、生产初始化语义不明确、日志宏影响结构化结果、构建或行为验证失败时，停止并保留现场。只有计划 / 设计缺口才请求计划支撑修订；纯代码错误继续在允许范围内修复。
