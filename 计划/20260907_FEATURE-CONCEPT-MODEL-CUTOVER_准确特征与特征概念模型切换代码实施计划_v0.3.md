## 4. 冻结合同与实施步骤

### 4.1 名称读取

删除名称 DTO 的旧退出筛选字段。实现 `读取特征当前名称(const 特征名称按特征读取请求&) const` 与 `读取概念当前名称(const 特征名称按概念读取请求&) const`；两者均使用显式 Gread/H。按 F 返回 0/1 条有效名称，按 C 返回 H 时全部有效名称并按稳定编码排序；不提供未界定历史全枚举。单条结果可回显真实退出代次，不能把退出历史推断成当前。所有坏合同、零身份、许可、漂移、资源、多义和内部错误具名返回并零载荷。

### 4.2 场景成员与恢复

在场景成员模块新增并仅使用详细设计中的 `场景特征概念观察请求_v2`、`存在当前采用意图`、`场景成员概念请求_v2`、`特征概念处理结果_v2`、`存在当前采用结果_v2`、`场景成员概念结果_v2`。字段顺序、默认值、比较、`成功()`和错误边界逐字依设计 §4 落入。

`场景成员概念应用服务`持有可写 `存在类数据服务&`，不取得 owner 写端口；删除失效的特征服务/存在服务绑定调用。F/C/E 串行发布并分别回显 G/H；最终投影只做共同 G 投影，不重写任何子结果。C/E 未确认时只重放完整原请求。多匹配不得取首项；不扩跨 owner 原子事务或持久恢复账。

场景合同的机械字段顺序固定为：`场景成员概念请求_v2 { 版本, 写入头, S, E, Gread, H, 观察, 采用, 特征预算, 场景关系预算 }`；采用意图固定为 `{ 版本, 幂等身份, optional<原采用预期>, 期望F, 关系预算 }`；结果固定分报 `{ 版本, 状态, Gread, H, S, E, 特征概念结果, optional<存在当前采用结果_v2>, optional<完整场景原请求>, optional<最终投影> }`。特征概念结果必须有 `optional<特征信息身份> 已确认F`，其 `成功()` 只在 F/C 读回互证成立时为真；场景结果的 `成功()` 还要求各自 G/H、采用结果（若请求要求）和共同投影逐字段成立。失败只保留完整原请求，不制造临时恢复材料。

### 4.3 EC 依据关系

在概念树唯一装配合同中新增 `概念树存在扩展交付{稳定编码 抽象依据目标关系类型;}`。EC 创建、读取、图展开、反向保护、退出、释放和原键恢复均使用该字段对应的角色 17；角色 16 仍保存 C→形成依据记录。旧共享布局中的真实节点仅可由合法装配显式交付为存量节点，禁止自动推断；缺交付返回不支持，不宣称生产装配完成。

### 4.4 预算、父组和世界树

保留 `存在类数据状态` 1..28，尾增 `存在类数据状态::数量预算不足 = 29`。新 C 的 `子父替代[].新父组` 排除本次新 C，provider 同笔隐式加入；独立组织请求给完整已发布父组，不用零身份。世界树只把旧特征引用读取状态映射迁移为存在类自有历史读取状态，保持业务语义，删除特征兼容别名；完成后扫描全部直接消费者。
