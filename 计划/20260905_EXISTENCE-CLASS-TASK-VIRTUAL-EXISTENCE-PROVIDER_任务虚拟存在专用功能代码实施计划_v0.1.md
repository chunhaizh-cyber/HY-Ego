## 1. 目标与完成条件

在既有`数据服务.存在类.ixx`新增两个任务Vt专用入口：

```cpp
任务虚拟存在写集规格结果 形成任务虚拟存在写集规格(
    const 任务虚拟存在写集规格请求& 请求) const;
任务虚拟存在查询结果 查询任务虚拟存在(
    const 任务虚拟存在查询请求& 请求) const;
```

提供者只形成task owner的一节点一关系L1写集规格并专用读回；不接收或借用task owner
端口，不提交写集，不调用普通新增/查询存在，不使用世界存在owner。完成要求两个允许文件
按详细设计发布并形成施工记录。

## 2. S0、范围和依赖

5260、代码文件规范、知识库入口、当前存在类与L1公开接口，并确认本计划是唯一可执行、
plan blob匹配、接口未漂移、目标文件无其它所有者。

允许文件：

1. `海中鱼巣/领域/数据服务.存在类.ixx`；
2. `施工记录/20260905_EXISTENCE-CLASS-TASK-VIRTUAL-EXISTENCE-PROVIDER_施工记录_v0.1.md`。

只允许详细设计第3节五个L1读取入口。禁止任何L1写、普通存在函数调用、旧`服务.L2*`、
任务类修改、工程/装配/知识库/验证文件修改。

## 3. 施工步骤

1. 在存在类模块新增版本、16个稳定状态值、五个DTO、成功谓词与固定本地键。
2. 新增规格形成const成员，校验G0、task owner、任务节点、关系类型和零当前Vt，返回固定
   一节点一关系L1写集规格。
3. 新增专用查询const成员，按零/一/多关系收口并同G0完整互证T、Vt、关系和owner。
4. 确认两个入口均不读取/使用任何写端口字段，不调用普通存在入口，不返回普通存在结点。
5. 建立施工记录，列出ABI、调用边、知识变更和未验证边界。

若实现需要借用task端口、使用存在owner、调用普通新增存在、让Vt进入存在族/世界树、
修改普通存在ABI、扩大L1白名单或调用旧L2，属于DRIFT并具名退回计划支撑。
