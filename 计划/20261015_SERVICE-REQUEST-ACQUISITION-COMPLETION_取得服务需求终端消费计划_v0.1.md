### 4.1 二次定义和输入

`二次特征算法` 追加 `服务任务来源新增数 = 9`，不重用集合判等。输入仍为两个 `特征准确值`，左右输入 FT 均为先天 `服务任务集合`，材料 U64 数组；输出 I64、无量纲、不自动聚合、根域 `[0, INT64_MAX]`，合法结果子域 `{0}` 与 `[1, INT64_MAX]`。

```cpp
// 新任务承接消息追加：
std::optional<新服务需求取得反馈定位> 服务需求取得来源;
```

不新增第二套 self→manager 采用回执：复用现有承接消息、异步`处理结果`及承接接收接口。新依据要求 X 定位和正式 D，来源状态为空；其它依据要求新增字段为空。新依据只确保 D/T 唯一关联，不重新启用既有终结 T，不把“已承接”当作取得任务完成。

manager→self精确回调：在manager private区新增`using 服务需求取得反馈接收函数 = std::function<新任务结果反馈接收状态(const 新服务需求取得反馈定位&)>;`，复用该接收枚举的已接收/精确重复/邮箱满/停止/工程状态。在现有`绑定自我筹办反馈`签名的`等待复核接收函数 等待接收`后、结算配置前，增加必需参数`服务需求取得反馈接收函数 服务需求接收`。self原绑定点传入投递对应消息的lambda，解除绑定同步清空该回调；禁止调用时持manager锁。完整定位要求T/X均非零，无包正文、确认快照或业务布尔。

`新自我消息类型`追加`服务需求取得反馈`，`新自我治理消息`追加可选定位；非此类型该字段必须为空；此类型除定位外普通事实/筹办/结果载荷均为空。

时序：

1. manager 消费 W3 结果，独立读回 X 有实际确认和动作后，把定位提交 self；不依赖临时包副本；此时 X 保持等待正式结果，不转完成。
2. self 从 task/确认/需求 owner 独立 fresh 读取，核验活动需求及准确取得目标，调用专用 D 采用入口；没有返回包证据、定位已变化不采用。当前确认失效只等待重新确认，不按旧含义扩大服务。
3. self 提交 `自我服务需求采用`承接消息（D+T取得/X定位），manager 再核对 X/确认/D。以现有 `建立需求任务关联/建立或取得任务` 确保该 D 唯一 T，同步由既有被动回调完成；不根据回执 bool 推断事实。manager 仅在该专用承接完成后解除此 X 的采用交接等待，开放 W3-B；丢失回执重送精确同一消息可读回既有处理结果。
4. manager 调 `读回服务需求取得结果(T取得,X)`。后者 fresh 读取 D 出生 X、确认身份、D/T双向唯一关系、真实集合 F 和正式集合派生查询，确认唯一新 T 当前同时在二者中。集合未完成同步可等待真实事件；集合 owner 读写失败必须工程中止。
5. 读回取得真实集合 S，沿原 `获取任务本能结果()`执行结束/评估→原结果反馈消息→self 后继决议→原任务完成及完成结算；完成结算仍保存真实 S 引用。
6. self/manager 完成回执只唤醒取得任务的父任务重新读条件；新服务 D/T 独立继续，不等它完成才完成取得任务。

通知丢失/邮箱满：manager 保留 X 定位在现有等待工作中重送；self/manager 停止接收不误报业务失败。轮询发现 X 已有真实返回确认而无终端处理时可重新交付，绝不再次调用同 X 本能。仍用现有工作并发上限10，不新建专用线程。调用外部 owner/投递邮箱时不得持有 manager 状态锁，复用现行先定位、解锁工作、fresh 回执模式。

## 6. 真实结果、归因、零结果和完成守卫

本轮保留真实 S 方案，不增加 X/A/完成结算闭包种类：真实集合 S 已由被动同步形成，足以承载结果观察；只需让 task 将它与 X 取得来源关联，瞬时求值。`动作输出状态节点组`始终不加入该下游 S。

同源 Q 精确定义：在 C 中枚举满足下列全部条件的 T：T 对应 D 恰有出生 X；D 的确认包含 X 实际返回确认且含义仍固定有效；D 为结算 D 的正式服务子需求；D/T唯一互指；T 在动作前 B 中不存在。当前只允许0或1个；多个是结构冲突，不得截取一个。

具名结果复核必须分别验证：

- 真实 F/S 的 E/FT/当前选择和值与正式任务服务集合相符；不能把无当前 S 当空集合。
- 本次 X/动作/采用/确认仍匹配；D 来源不是根据时间推测。
- `来源新增数`由正式二次算法计算且落在目标 `[1,MAX]`才满足。复用其他 X/无来源 D 为0，不完成。
- Q 非空时，当前真实集合 S 必须确已包含新 T、T 不在 B；动作后集合曾增加但 T 后来不在当前集合时不满足。其他 X 删除旧 T 不影响本 X 的贡献1。
- 读取到既有 D/T但Q为空时，只能得出来源贡献0、不完成；不得为让X结束放宽W3-B动作后状态时间规则，不创建虚假S。

任务 A 的具名分支：值域验证基于来源计数；归因验证基于 X→实际确认→D出生→T→集合 S；多渠道验证基于正式 owner 读回；方向/幅度在值目标下为不适用；禁止结果沿原方案实际核验；副作用不得把全局集合中其他执行变化归给本 X，当前方法直接操作只返回包，正常下游贡献仅已核验的 T。已有禁止约束不可默认通过，缺必需材料仍等待。A 中真实命中 S/实际 S 保持现有闭包，缺失/冲突不升级通过。

`复核任务当前需求()`与 self 发布前都重新计算当前贡献，不能只信冻结 A 的满足 bool。完成发布前 D/T或集合被删除、确认被要求重确认、X不在当前位，均不发布完成。已结算闭包不因后续学习改写；原恢复/读回按原合同处理。

Q为空的0分支保留 X 的既有结果等待，不发布完成、不重新调用同 X、不建立第二D/T。manager 从最近 X 返回确认及采用关系识别“已采用但没有本次新增”，不反复提交无变化采用工作；事实变化后可重新只读复核该 X。同 X 已首建但回执丢失不属于0，应恢复其本来贡献。当前确认失效而尚未完成采用，保留动作和返回事实，等待重新确认，不伪造0/1。本叶不定义“已执行但未新增”X的取消及换新X合同，不因此自动重新执行；这一明确非完成分支不算成功闭环。

`读回服务需求取得结果()`在已采用0时返回`已找到`及`来源新增数=0`，但结果S组为空；这不是W3-B请求。manager必须先读该结果，只有来源新增数为1、非空合法动作后S且所有核验通过才调worker；0/等待/确认变化都不开W3-B，不生成A、不改写X确认，不把新确认替换到旧X。新的确认可以进入其他合法获取执行，本叶不自动把当前未结束X换为新X。

## 7. 服务值来源隔离

将下述同一只读准入复用于 self 完成来源发送、manager `接纳明确完成来源`、task 结算来源绑定/执行前复核：来源 T 不是结算 T；对应 D 的父为结算 D且来源承接为结算 T；D 持正式服务要求确认，确认语义当前有效且与 D 目标相符；T 已真实完成并有合法完成结算闭包；现有幂等结算规则仍成立。

`新_任务类.h/.cpp`新增唯一public只读守卫，三个消费者均调用它，不各自复制条件：

```cpp
enum class 新直接服务结算来源状态 : std::uint8_t {
    允许结算=1, 非直接服务, 尚未完成, 需重新确认,
    尚未配置, 结构不一致, 资源失败
};
struct 新直接服务结算来源结果 final {
    新直接服务结算来源状态 状态 = 新直接服务结算来源状态::尚未配置;
    std::optional<稳定编码> 需求节点;

新直接服务结算来源结果 核验直接服务结算来源(
    稳定编码 来源任务节点) const noexcept;
```

`非直接服务`是正常不入结算队列；`尚未完成/需重新确认`正常等待；缺初始化、结构或读取故障进入工程诊断链，不混为正常不服务。守卫复用task已配置结算D/T与需求owner正式读回及`复核需求服务要求语义()`，不改D owner源接口。self新完成T可能尚未建立完成结算闭包时返回尚未完成，manager在原完成结算后通知/扫描重读，不提前占用结算来源。

取得治理任务 D 没有正式人类服务确认，因此只向父任务完成通知，不进入加服务值队列。准备子任务即便同属服务根、也不因自身完成直接加1。来源 T 完成状态本身不再足够；非法来源是未获准结算，不变成结算业务失败结果。工程读取失败仍按工程故障链处理。
