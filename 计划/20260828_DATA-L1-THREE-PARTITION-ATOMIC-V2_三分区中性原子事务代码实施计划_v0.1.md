## 4. 实施步骤

### P1 公共 DTO

在 `L1所有者范围CRUD.数据.h` 紧邻旧跨所有者 v1 合同增加详细设计第 3 节全部 v2 类型：参与者身份、引用、四类写项、写集、参与者、请求、状态和结果。全部固定默认值、逐字段比较和数值状态；不得修改旧类型或让 v2 alias v1 请求 / 结果。

### P2 三端口公开入口

在 `L1所有者范围写端口` 增加 `提交三分区原子事务_v2`：

- `noexcept`；
- 接收者 / 两参数绑定参与者 1/2/3；
- 校验同一 L1 实例、三个有效端口、owner 互异和请求逐项绑定；
- 端口 / 实例错误映射内部不一致，分区绑定错误映射引用冲突；
- 只把完整请求交给同一仓库私有入口，不泄漏仓库或端口。

### P3 仓库规范化与候选事务

在仓库内新增独立 v2 规范化、引用解析、幂等记录和提交函数：

1. 完成纯值有效性和唯一规范化。
2. v2 幂等查找先于 G0 比较。
3. 在候选副本中按 1、2、3 依次复用 owner-scoped 普通写算法。
4. 只解析向后跨参与者引用，拒绝前向、同参与者跨引用和缺失键。
5. 把临时三代次、全部新建 / 退出生命周期和三份首次写入账统一为 G1。
6. 重建并核对当前索引，执行具名全局闭包后才形成首次结果。
7. 将 v2 组合幂等账写入候选、准备持久快照后一次交换。
8. 捕获分配、文件、未知和其它异常，严格按矩阵返回；不得产生部分正式状态。

### P4 持久格式兼容

新增 v2 请求 / 结果固定编码和解码，增加独立 v2 幂等账：

- 内部权威状态编码格式改为 2；
- 解码同时支持格式 1 和 2；
- 格式 1 的 v2 账为空；格式 2 完整读写 v1 账和 v2 账；
- 外层清单版本及公开持久恢复 ABI 不改；
- `状态完整` 必须验证 v2 账规范化请求、首次结果、三 owner、三幂等身份、共同 G1 和三份映射互证；
- 旧进程维护键过滤规则不得误滤普通 v2 账。

### P5 记录和知识清单

施工记录写明实际修改函数、复用函数、持久格式、异常边界和未修改 consumer；验证记录逐项保存命令、精确基线 / 候选提交、结构化结果和正式读回。施工记录列出受影响知识卡及建议变化，发布后交由知识库维护职责处理。
