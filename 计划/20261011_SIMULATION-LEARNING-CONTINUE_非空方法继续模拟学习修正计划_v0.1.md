## 1. 目标与冻结边界

用户指出“已有任何条件结果对就停止学习”错误。本叶改为：每次正式请求学习已支持的方法，都先实际运行本次模拟，再将本次C/R交方法owner与全部既有配对比较；完全相同才返回重复，否则在不存在同条件冲突时追加全新配对。命中次数不因模拟增加；旧配对和已复制方法实例不改写。

同条件不同结果继续遵守同条件唯一结果：本叶返回具名冲突、零写配对，不新增第二结果、不擅自扩域。当前确定性单点结算正常不会产生此冲突；通用扩域需处理方向/结果项/确认要求等合同，不在本叶临场合并。

只纠正显式学习请求的处理和owner追加。self仍只自动发现头空方法；不增加轮询、自主继续学习或任务/manager消费，不宣称完成整个数值域的续细分。登记时的两个单点输入范围、模拟隔离、原本能函数、现实零写、失败保留、停止检查均沿已发布实现保持。

本次没有新本能行为：仍只修改模拟自我服务值以取得方法输入输出样例，不修改现实服务值或任务Vt；用途为完善待现实验证的方法知识。

依据为本轮用户具名裁决及[0050](../规范/0050_项目通用机器逻辑与禁止性规则总纲_20260721.md)、[方法治理](../规范/5350_子规范_方法治理详细合同.md)、[本能执行](../规范/5360_子规范_方法函数登记执行与任务反馈.md)、[代码归属](../规范/代码文件建立归属与模块命名规范.md)。前叶“仅头空可学/已有配对即可重复”在本文范围内被明确替代，不修改正式规范。

## 4. 方法owner判重、冲突与追加

整个读取/核验/判重/构造/发布在既有方法互斥内执行；不得锁内调用本能、模拟或日志。

1. 维持启用抽象本能方法、登记、角色/类型/合法域检查，先验证本次完整定义，再判断重复，不能让非法请求因方法非空获得成功。
2. 条件同一以所有字段一致为基础，不能只比较FT或准确数值。新增同cpp私有`bool 同一学习条件(const 新方法条件定义&,const 新方法条件定义&)`：关系规则必须一致；规则为全部成立/任一成立时用完整条件项值式相等的`is_permutation`比较，保持重复项数量；其它规则包括有序成立、条件选择保持现有顺序敏感的完整`operator==`。不做概念同义、区间重叠或包含推断。
3. 扫描全部已有配对，找与本次条件同一者。0个继续追加；1个且完整结果定义`operator==`（包括关系、所有结果项、方向、主要结果、确认要求、禁止结果等）相同→精确重复，返回已有ID，零配对/计数写入；1个但结果不同→同条件结果冲突，返回已有ID，零配对/计数写入。发现多个同条件旧配对→结构不一致，不能随意挑一个、更不能再加。不得仅因某个其他CR存在便返回重复。
4. 新配对顺序不能写死0：从既有配对物理`顺序字段`完整读取最大值，新序号为空组时0，否则max+1。缺失、负值、重复或MAX无法安全递增返回结构不一致且零写，不依赖向量数量假定旧序号连续。复用现有唯一字段读回与排序校验。
5. 复用私有构造器创建全新CR及C/R/项，明确命中0；构造完读回本次定义及计数，然后挂唯一方法所属关系。发布前失败回滚本次未发布结构，旧配对不动。挂接后读回不确定保留现场返回发布结果未知，不重跑。
6. 发布后要求方法CR数量=发布前数量+1；按新ID唯一定位新增配对、定义匹配且计数0；对所有旧ID验证完整`新方法条件结果信息`与发布前相同，包括其计数。禁止再要求总数1或front是新配对。新返回材料在所属关系写入前预分配，保持现有异常安全。

精确重复和冲突均不修改已有结果域。这是安全拒绝，不宣称已完成“同条件结果扩大值域”的学习能力。

## 5. 服务每次实际求值及读回

移除“方法CR非空”提前返回，余下入口准入、登记材料检查及两个单点范围不动。每个接受的学习请求仍创建新的物理样例、运行原函数、fresh读结果，然后组装本次定义。已有知识不能替代本次求值，不复制旧样例或旧输出充数。

owner返回后：

- 已发布：新组恰1且已有ID为空；按该IDfresh查询方法全部CR，唯一匹配本次定义且命中0→已形成知识。
- 精确重复：新组空且已有ID有效；按该IDfresh读唯一配对，完整条件/结果必须匹配本次定义（条件使用与owner相同的关系规则；服务本次构造顺序固定，但不得因旧全部成立项顺序不同误报）；命中保持原值，不要求所有旧配对命中必为0。返回精确重复、本次模拟场景ID及匹配配对ID。
- 同条件结果冲突：返回同条件结果冲突和已有ID，保留本次样例，不自动学习循环或扩大旧域。
- 已发布后读回不确定：发布结果未知，保留新配对/样例；精确重复后的读回失败没有本次发布，返回发布失败，不伪称新知识已写。
- 其它状态沿现有失败映射；取消检查仍在原函数前/算法推进/发布前，发布后不改报取消。

条件比较helper的公开所有者仍是方法owner；不为服务暴露新的通用语义API。服务读回可同cpp实现完全相同的小型值式比较，或把本次条件项按旧配对条件顺序逐项核对；两者不得放宽定义。规范性相同条件逻辑以第4节为准。

4. 同一完整条件、不同结果单点/方向或确认要求→具名冲突，方法前后完整相等、命中不变；把全部成立条件项反序仍判断同条件，不能绕过唯一结果保护。有序条件反序不错误合并（正式owner合法请求测试）。
