## 1. 目标与边界

用户要求单步执行、每步重读真实条件、正常下一步不重复请求授权、意外重新筹办、长期等待释放线程，10上限只统计激活工作。本叶闭合其中已有单次本能执行X的结果检测、挂起与恢复调度：将当前manager/通知线程中的正式结果状态查询迁入固定worker池，结果不够立即返回并保留同一T/X；结果足够在同一个worker调用中继续既有W3-B获取及评估；manager独立读回后交回原治理链。

本叶不新建挂起任务状态、任务轮次、执行轮次、执行授权、第二结果账或感知动作。不修改现实世界特征，不通过轮询制造状态。结果检测仅调用正式状态owner读取已经形成的S；不是驱动摄像头、网络或其它观察方法取得新事实。

明确排除：复杂方法步骤游标/栈、分支匹配、父子角色映射、步骤局部目标、正常后继授权范围、动作重新执行、长期线程抢占、外设主动观察、未知结算来源子需求、服务要求材料装配、跨进程数据恢复提供者。复杂步骤运行仍是用户总目标的后继缺口，不能以本叶完成冒称已支持；在其合同未冻结前不登记远端后继计划。

## 4. 线程DTO与唯一结果检测路径

在`新_任务工作线程类.h`追加，不改变既有枚举数值：

```cpp
struct 新任务结果检测请求 final {
    稳定编码 任务节点;
    稳定编码 执行实例节点;
    friend bool operator==(const 新任务结果检测请求&,
        const 新任务结果检测请求&) = default;
};
enum class 新任务结果检测状态 : std::uint8_t {
    等待结果材料 = 1,
    已完成影响评估,
    定位已变化,
    正式记录不存在
};
struct 新任务结果检测结果 final {
    新任务结果检测请求 原请求;
    新任务结果检测状态 状态;
    新任务治理执行读回结果 正式读回;
    std::optional<新任务治理结果材料核验结果> 材料核验;
    std::optional<新任务治理结果获取结果> 结果获取;
};
```

`新任务工作种类`追加`检测本能结果=6`；工作请求末尾追加`std::optional<新任务结果检测请求> 本能结果检测请求`；工作处理状态末尾追加`本能结果检测已返回`；工作处理结果末尾追加`std::optional<新任务结果检测结果> 本能结果检测`。完整性及重复相等比较同步：检测请求T/X均非零、外层T相同，且无动作请求/旧结果获取请求。其它工作不能携带检测请求。新DTO只是单次工作返回，不是持久业务状态。

现有`获取本能结果=4`及非空S请求合同保留供已有调用/测试源编译，新manager不再生产此种工作；即时、周期、通知、恢复全部生成第6种。不能把`状态节点组={}`传给旧W3-B来隐式要求扫描。

worker私有成员定义在其`实现`中：`void 处理结果检测(const 新任务结果检测请求&, 新任务结果检测结果&)`，由一次`处理工作`调用，不启动线程、不循环等待、不回调manager。其调用顺序：

1. `读回任务执行(T,X)`。确认同一正式T/最近X/M。正式不存在返回`正式记录不存在`；合法旧X返回`定位已变化`；结构或读取错误工程终止。读回已评估直接返回`已完成影响评估`，不重复评估。
2. 等待观察时调用`查找任务结果材料(T,X)`。`与本次执行无关/已接受但仍不足`返回`等待结果材料`，保留已核验材料仅作本次观察；`任务或执行已变化`重新读回并按第7节分类，不伪造不足。
3. `材料已足够`时，以核验给出的同T/X及非空S构造原`新任务治理结果获取请求`，在**当前worker同一工作/同一执行槽**调用`获取任务本能结果`。没有第二派发窗口；该函数仍须fresh复核，不能沿用足够快照跳过检查。
4. 初始读回为`已读回等待评估`时，只用X的正式`实际状态节点组`调用同一获取入口；不重新扫描S、不改结束事实。
5. 获取返回`已完成影响评估`后再正式读回，必须是同X及完整A；返回对应状态。合法`等待结果材料`再读回仍等待观察时返回等待；`任务状态已变化`按新的正式读回分类。若已转待评估但尚未形成A，则保留同X并返回等待供下次续评估，不能重结束为另一组S。
6. 所有`结构不一致/资源失败/执行结束失败/影响评估失败`和抛出异常进入现有工程异常终止（日志、弹窗、终止进程），不作为等待结果/学习材料返回。此为本叶新检测路径错误边界，不批量删除旧错误枚举。提交前邮箱暂满与内存接纳失败仍是工程背压，可延后原请求；与执行中owner读取失败严格区分。

返回`正式读回`为本次最后一次正式读取。manager仍须独立读取，不以此副本取代权威。返回等待只允许正式读回`已读回等待观察/已读回等待评估`；返回完成必须含同T/X/A；返回不存在或定位变化不得带入其它T/X的材料。

## 5. manager唯一挂起记录与唤醒

将现有`恢复等待结果执行/恢复结果工作/等待结果状态组`三套调度位置统一到manager私有`结果等待任务`，键为T稳定值；每条仅保存：

```text
X稳定编码
下次检测的steady_clock时点
待检测(bool)
在途期间再次唤醒(bool)
可选的原检测工作请求
已派发(bool)
```

本表是从正式T/X重建的运行期调度位置，不裁决T状态。`最近执行结果`继续承载已返回材料及self反馈，但不再是等待检测的第二派发源；`最近自我筹办裁决.执行工作`只承载W3-A，检测不依赖旧self裁决存在。禁止保存长期S副本以弥补后来查询不到；正式状态通过owner重读。

结果等待保护只由`结果等待任务`承载，已评估等待self反馈只由`待结果反馈任务`及同X正式定位承载；不得再同时为这两种原因向仅T键的`阻塞任务`插入。迁移W3-A返回、旧W3-B返回、恢复和结果消费分支时一起去掉对应插入/删除，`阻塞任务`保留其它原有原因，不作全量清空。任务执行保护查询同时读取唯一等待表和待反馈集合。原W3-A裁决记录保持`执行工作已派发=true`，挂起、重新检测或清除结果等待均不得复位该标志或重新派发原动作。

同T不得有两个X等待记录。收到另一X时，必须先在manager锁外正式读回当前T最近X；仅当旧记录已不在当前位且无未确认工作时清旧并登记当前X。若旧工作仍在途，先保留其future并消费/确认，不覆盖原请求。稳定编码不复用；旧回执只能清理匹配的T/X/工作号，绝不能删掉同T新X记录。

### 5.1 动作返回与即时结果

W3-A返回后，manager保留现有独立读回、动作事实和零动作处理。正式读回等待观察则登记同T/X为立即待检测；即使函数返回正式S也走同一路径，不再在manager中同步核验S并生产旧W3-B。登记是任务位置转换，必须在确认W3-A回执前预备好所有可能分配失败的容器位置；确认成功后释放该工作占用，再让检测可派发。重复W3-A回执不重复登记/造工作号。无动作分支不登记等待。

### 5.2 周期与事件

周期沿现行`资源重试间隔毫秒`及既有`等待时长`clamp；只决定工程重查时点，不是结果截止时间或任务失败条件。到期把挂起记录置为待检测；忙碌时保留，不轮询等待worker、不新增物理线程。

`提交结果状态通知(S)`不读取task/state/world owner，不遍历正式S，不验证S是否属于任何X。非零S且服务可接收时在锁内只设置一个全局“结果通知待处理”布尔并唤醒manager；同时保留原条件子需求复核触发。通知是线索，不是正式结果材料，可以合并。`新任务结果状态接收状态`末尾追加`已接收待异步检测`，生产正常接收返回此值；旧“已接收并触发结果获取/已接收等待更多材料/与等待执行无关”不再用于同步证明。停止返回原`已停止接收`；非法S返回原错误；异常按工程路径，不伪称接纳。

self唯一调用方继续把回执写入处理结果，不因`已接收待异步检测`推断任何需求已满足。不得把通知改造成等待检测完成的同步future。

manager消费通知布尔时，在锁内清除它并将所有已登记等待T设为待检测：有已派发请求的记录只置`在途期间再次唤醒`。在清除和标记期间通知无法插入；之后到达的通知重新置全局布尔。首次W3-A登记和启动恢复本就立即待检测，所以通知先于登记也不会漏查。事件发生在检测扫描之后、结果回传之前时，完成交接后依再次唤醒位立即再查一次；不能无条件清掉该位。周期兜底仍保留。

### 5.3 接纳、结果消费与挂起

待派时为该T/X创建一个工作号，并保存不可变请求；提交未获接纳时沿原请求重试，不重复加号。`已接收/精确重复`后保住future、在活动工作登记并置已派发；任何后置分配失败不得丢future或释放同T保护。各容器分配/reserve均在调用worker接纳前完成，接纳后的状态安装只做不分配移动和已存在项赋值。

检测完成，manager先核对原工作、T/X、DTO形状，再锁外独立`读回任务执行(T,X)`。检测的等待/完成结论与当前合法变化可以不同，按当前正式读回决定：

| 当前正式读回 | 收件后的调度处理 |
| --- | --- |
| 等待观察/等待评估 | 保留同T/X等待记录；清除本次请求/已派发；有在途唤醒则立即待检测，否则设置下次周期时点并挂起 |
| 已读回影响评估 | 形成现有`已完成影响评估`返回及T/X/A反馈定位；清除同X等待记录；不自动批准下一动作 |
| 执行不在当前位 | 只清理原T/X记录，不写Vt，不覆盖新的X；当前新X按正常生产/恢复入口登记 |
| 任务或执行不存在 | 明确终结该工作及原等待位置，不包装为结果不足；不建立替代T/X |
| 结构不一致/资源失败 | 工程终止，不吞错后轮询 |

过期/不存在清理只作用于原请求的精确T/X：匹配的等待记录可删除；`最近执行结果`仅在其独立读回或原检测请求明确指向该X时删除。只有已确认最近结果反馈来源也为该X时，才删除对应T的待反馈标记或后继决议暂存；无法证明来源相同则保留并工程核查，不按T泛清。不得顺带删除新X等待/反馈、其它筹办或学习等待材料、其它原因的`阻塞任务`。旧结果等待不再写该阻塞集合，因而不存在为了清旧X而盲删T级保护的需要。

先预分配等待/反馈所需容器及完整值式结果，再调用`确认结果已接收`；确认必须`已完成`，否则工程终止。确认后才删除manager活动工作/替换原请求记录。挂起保留T/X但没有worker活动工作或待确认条目；未被manager确认的已完成工作仍保持同T排他，不能提前接受该T下一项。停止收束也走同一确认链。

旧`获取本能结果`回执消费如因已有入口仍保留，必须把`等待结果材料`导入同一等待记录，不再写`工作未完成`后丢失等待；新生产则不派发它。

## 6. 容量、同T排他与调度公平

固定物理池仍是10，不改变启动/所有者/join合同，也不按等待任务数量创建线程。

worker接纳在同一互斥锁内顺序检查：工作号相同且请求全等返回原future；同号异义拒绝；同T已有任何未确认记录（包括已完成）拒绝；全部未确认记录数达到`配置.邮箱容量`则邮箱背压；**未结束记录数**达到10则无激活槽；否则接纳。未开始但已被接纳的短期排队项预占激活槽，防止10个线程同时领取时超发；长期挂起T不在活动vector中。无需新增生产计数器，直接计数现有`!已结束`；`执行中工作数`继续只表示当前真正运行的线程。

`发布结果已加锁`兑现future并将项置为已结束时立即释放激活额度；记录仍保留到manager确认，继续占邮箱容量和同T排他，不计入10槽。不能靠删除已结束项释放容量而丢掉原请求/结果/精确重复。停止取消未开始项同样释放槽、保留待确认回执。

manager全部`活动工作.size()>=10`闸门退出，最终激活限额由worker原子接纳保证；manager仍按真实邮箱资源做提交背压，不重复维护可能漂移的10槽计数。manager预留活动工作容器容量时以本次`size()+1`或已验证邮箱容量为上限安全增长，不再假定永远最多10条未确认记录。快照原活动/运行/待处理/待确认字段含义保持，不能将挂起T计成执行中工作。

主循环先消费所有当前可消费的完成回执（保留既有资源延后时点），再派发。新增结果检测类与原“调度扫描→执行→筹办”类采用简单轮转：上次接纳检测后先试原类，上次接纳原类后先试检测；首轮先原类。任一类无就绪项则尝试另一类，接纳成功才移动轮转位；全池或邮箱背压即等待完成通知/现有重试时点，不忙循环。原类内部现有方法/任务顺序不改，不发明新的业务权重。

检测类内部按T编码的环形游标找下一到期且无活动工作项，接纳成功才推进游标；这是公平遍历，不赋予T新的业务优先级。重复事件不让同一T在其它已到期T前无限重跑。检测失败于同T占用时跳过该T继续寻找；全池/邮箱满才阻断本次派发。任务筹办保护函数改读统一等待表，动作已发出的T不得混入W1/W2/W3-A。

## 7. task当前身份与错误边界

`新任务治理执行读回状态`末尾追加`执行不在当前位`，不改变旧值。`读回任务执行`先完整读取T/X，现存但读不完整为结构错误；X所属T不等于请求T为结构错误；存在合法T/X但T最近X已经是另一个有效X，或同X已依法离开等待观察/待评估/待反馈范围，返回`执行不在当前位`。在T仍处于执行/待评估/等待决议状态时缺最近X、最近M不符或T/X状态组合矛盾仍是结构错误，不能泛化为过期。

保留现有`已完成`但尚无`完成结算节点`的特判：同X已评估且A完整时仍为`已读回影响评估`，属于待反馈/补结算可恢复范围，不归类为过期。已有完成结算的收束仍走原确认链，不因检测重新结算。

`核验任务结果材料/查找任务结果材料/获取任务本能结果`在现有task锁内补齐当前T最近X及M身份检查：合法旧X返回各自既有`任务或执行已变化/任务状态已变化`；损坏引用、存在却读不完整、X归属异义维持结构错误。`获取任务本能结果`对待评估分支同样先核验当前位，不能结束/评估旧执行。输入非法与工程错误不可伪装成材料不足。

新检测消费者对上述结构/资源错误调用现有工程异常终止，不把它们转成正常等待。结果正式不存在必须依据基础数据集确认节点确已不存在，不能仅凭optional空就作不存在；沿既有`读回任务执行`存在性区分实现。当前task错误枚举仍保留，禁止顺带治理全仓错误合同。

结果匹配、冻结渠道、证据质量、禁止结果及影响评估算法不变。本叶不能因只找到某个S就声称多渠道均验证；继续消费现有方案核验与影响评估的未验证/不适用边界，未完成渠道能力不靠新调度补造。

### 7.1 v0.2执行期支撑：状态查询错误不能变为空材料

执行侧在`b01e2688af226993259d156046f007209891d180`及本叶七文件WIP发现：`新_状态类::按实例特征查询状态`捕获异常后返回空vector；其调用的`获取状态`捕获后返回nullopt，筛选忽略不可读S。这使worker无法区分“没有结果”与工程读取失败，违反第4/7节已冻结合同。本修订只闭合此实际提供者链，旧WIP保留，按新blob重新S0后再继续相应函数及构建；不新建结果算法或状态服务。

两个签名保持不变，正常空返回合同也不扩大：

1. `获取状态`的异常捕获改用既有`工程异常终止`。其入口当前经`是状态节点()`检查，而后者会吞异常返回false；因此在`获取状态`自身try中直接使用已有基础查询做节点和唯一类型字段识别，不再通过该吞错bool读取入口。无效编码、正式节点不存在或确为其它类型仍返回nullopt。完整S的字段读取及成功DTO不变；已识别S但字段缺失/非法仍可按现有optional合同返回空，由调用者区分，不为此新增公开状态。
2. `按实例特征查询状态`异常捕获改用同一工程终止；其筛选lambda取得的是按正式S类型字段枚举的登记节点，在持有现有状态递归锁期间若`获取状态(S)`为空，立即工程终止，不得返回false跳过该S。合法读取且来源F不同才是正常不匹配。不存在的查询目标F保持现行空查询合同，不伪造状态。
3. 为避免元结构丢失被解释为空结果，两入口在本owner结构尚未初始化时保持原空返回；若已有任一初始化字段而结构不完整/相关类型与字段节点已损坏，进入工程终止。该核验只读当前状态owner字段，不恢复旧schema、不自动初始化、不修改基座。
4. 工程诊断复用现有头及`工程异常终止`，日志/弹窗/终止责任只执行一次；不在catch后返回空，不继续业务，不修改结果等待或学习材料。无公开ABI/DTO变化、无其它owner修改。其它`是状态节点`及查询函数本轮不批量治理，但它们直接调用`获取状态`时不可再吞掉已经致命终止的异常。

## 8. 恢复、停止与反馈定位

启动仍调用一次`查询等待结果任务执行`恢复正式T/X/A枚举。禁止在启动调用线程继续逐X扫描S。等待观察和待评估只登记统一等待表立即待检测；已评估且仍待self处理的记录也可进入同一检测入口，由worker只读返回现有A，再按正常结果消费恢复反馈。所有恢复请求只有T/X，不借旧self裁决重新授权，不建立新X。

`新任务结果反馈定位::完整()`必须接受新`检测本能结果`原工作，要求内外T/X一致且A非零；旧第4种工作读取分支保留。self接收/读取最近执行结果沿该定位，不因检测工作号不同猜业务轮次。恢复、重复通知和迟到工作都以T/X/A及原请求完整相等收敛。

停止后拒收新通知、停止新派发；已提交工作由现有池停止/取消/同步返回，manager继续取出所有ready future并确认结果后join。运行中检测不等待外部条件，也不轮询停止完成；调用返回后保留已发布X/A。未接纳检测请求可丢弃其工程队列，正式T/X不变；已接纳项必须兑现并确认，不能只清map。`停止取消`是工作取消，不是任务取消。停止期间不得因结果不足再次派发；挂起位置可以随线程销毁，下一次启动从正式T/X重建。不得detach或调用方法动作补偿。

worker对未开始项产生的`停止取消`回执不带检测DTO；manager必须先核验原请求完整相等并识别这个分支，再做通常的检测DTO完整性检查。该分支只确认并释放该工作/future及同T工程占用，不要求结果读回、不判任务取消、不清除正式T/X/A，也不形成self业务反馈；停止中不再派发后继。不可把合法取消缺DTO诊断为结构故障。

若检测读回已经形成A而停止正在发生，允许保存正式反馈定位待下次恢复，不丢A、不结算、不强制通知已停止的self。池接收结果和manager安装future之间的停止竞态仍必须保住已接纳项，归入停止收束。
