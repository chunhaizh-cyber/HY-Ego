## 3. 实施合同

### 3.1 v1/v2 登记

保留 v1 `0x20` 与十项本地键；当前 `0x21` 为动态、`0x22` 为因果，新增 v2 登记使用唯一未占用域 `0x23`，规则版本 `2`，当前选择关系类型本地键 `0x02040103`，稳定编码公式 `((uint64_t)0x23 << 56) | 0x02040103`，写集局部键 `0x02041103`。登记 DTO 字段顺序、首次/精确重复/同键异义/G0/许可/恢复读回和零写规则按 v0.3 详细设计实现；不得把 v1 登记表追加第十一项。

### 3.2 首态与迁移 DTO

在现有 `L2状态新增请求` 七字段末尾追加 `当前选择关系局部写入键`、`当前选择关系幂等材料`；缺省、零值、非 v2、角色错误、G0 不一致均入口拒绝。`L2状态写入结果` 在结果头后追加 `当前选择操作状态`、状态、自有关系、当前选择关系，首次/重复必须三载荷齐全。

`L2状态动态原子发布结果` 在既有动态字段后追加 `当前选择操作状态`、新当前选择关系、已退出旧当前选择关系。迁移一次提交并返回共同截止；状态 owner 只写选择关系，动态 owner 只写动态事实。

共享 `L2状态当前选择操作状态` 数值固定：`已提交=1、精确重复=2、已读取=3、待迁移=4、已有异义当前=5、已可能发布=6、发布未知=7、入口拒绝=8、许可拒绝=9、事实代次漂移=10、幂等冲突=11、引用冲突=12、资源失败=13、内部不一致=14`。公共结果头按详细设计的唯一组合表生成，不得出现互相矛盾的通用/专用状态。

### 3.3 当前选择读与 L4 边界

新增具名当前选择读请求/结果，固定字段顺序和最多一条返回；当前读是唯一当前性权威。按特征实例读取全部当前状态仅兼容包装。P1/A1 只持久化状态身份，恢复时当前选择读回并互证。`待迁移` 不映射 L4 的 task owner v1 `初次请求版本待迁移=15`；`已有异义当前`、`已可能发布`、`发布未知` 的后续处理按设计逐项执行，不改 L4 业务枚举。当前工作包不含选择证据，完整性登记留给底座结果后的独立 L4 计划支撑事项。`TASK-ROUND-INITIAL-STATE-ARCH-L2-MIGRATION v0.3` 继续待激活，后续只能由 L4 同身份 v0.4 取得新 blob 后再登记。

## 4. 固定实施顺序与失败收口

1. 在 L1 既有两参与者候选交换前完成 G0、幂等、局部引用和全局闭包检查；候选失败零载荷、零写、零代次、不写幂等账。
2. 在状态 DTO/服务登记 v2、实现首态请求/结果和当前选择读取；状态事实永久保留，旧数据缺选择只返回待迁移。
3. 在状态动态 DTO/服务接入新/旧选择证据和共同截止；生产顺序固定状态→动态，不增加 owner 或第二权威。
4. 以同一生产 ABI 进行首态、迁移、重复、异义、G0、许可、坏键、旧数据、唯一当前读和兼容包装矩阵。
5. 逆序矩阵必须由 `D:\TEMP` 内部顺序无关 helper 的合法专项接缝实际调用；禁止静态阅读冒充。
6. 交换后读回故障只由专项 seam 在交换后、读回前注入；不进入生产合同。无法机械注入时收窄完成声明，不添加生产钩子。

交换后失败不可回滚：结果只能为已可能发布或发布未知，保留幂等账/事实代次，以同一幂等键重放并正式读回收束。
