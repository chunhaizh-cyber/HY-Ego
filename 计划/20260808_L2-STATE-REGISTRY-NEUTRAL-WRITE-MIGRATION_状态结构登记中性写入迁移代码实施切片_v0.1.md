## 5. 实施步骤

1. 保持公开 DTO / 枚举 / 构造不变；如迁移常量，只新增 `L1状态登记幂等域=0x0C` 并移除服务内同义定义，绝不改变 `0x0D`。
2. 删除仅服务首个登记根的 `形成G7状态登记意图凭证`、`0x15000601` 使用和 `首次登记请求_`；保留第二根使用的共享 G7 编码、`形成G7首个基准状态发布意图凭证` 和全部 legacy helper。
3. 新增状态登记专用中性键映射、中性状态映射、七项映射校验、中性节点形状和共享精确读回 helper；不得改写第二根使用的旧状态映射、旧映射查找或旧当前 / 历史读取。
4. 重写建立登记：公开请求校验后预读一次中性当前事实代次 P，只验证入口健康、合同和非零；禁止在提交前因 `P != 请求.期望事实代次` 返回。
5. 形成中性合同 1、原期望代次、`0x0C` 键和固定七节点，其它四类写项为空；物理调用 `提交中性写集` 恰一次。不得调用旧探测、完整快照或 legacy 提交。
6. 以 L1 状态最终裁决：成功→已提交并要求 P 等于期望；精确重复→幂等读回且允许 P 高于原期望；同键异义→幂等冲突；新键旧代次 / 竞争推进→版本漂移。P 不得覆盖 L1 的重复、冲突或漂移。
7. 成功类共同核对合同、键、非零首次代次和七项唯一映射；成功 / 重复分别核对发布标志与重试边界。
8. 用七编码和首次发布代次执行 G0 + 七节点 + G1 当前读回；七节点创建代次一致且等于首次代次，当前读截止允许更晚。已有缓存只比较七编码；成立后更新当前截止并保留原写入业务状态。
9. 重写读取当前登记：无缓存返回未找到；有缓存只复制七编码并复用同一精确读回，成功返回已读取。禁止缓存直返。
10. 从施工起点逐字 / 结构化比较排除的第二发布根及后续状态 / 动态路径；只清理能够证明由首个登记根唯一消费的代码。
11. 写两份专属记录，记录实际范围、顺序门禁、验证、未运行范围和 L1 不自证边界。

## 6. 固定结果与失败收口

| 场景 | 固定结果 |
| --- | --- |
| 非法公开请求 | 入口拒绝；零预读、零提交 |
| 预读非成功 / 合同矛盾 / 零代次 | 对应结构化非成功；零提交 |
| 首次新键同代 | L1 成功；P 必须等于期望；精确读回后已提交 |
| 原请求精确重复且当前代次已推进 | 不被 P 阻断；L1 精确重复、零发布、复用首次七编码；幂等读回 |
| 同键只更换期望代次 | L1 幂等冲突，不得映射为重复或漂移 |
| 新键旧期望，或 P 后发生竞争推进 | L1 事实代次漂移；领域版本漂移 |
| L1 返回成功但 P 不等于期望 | 内部不一致 |
| 成功类合同、映射、节点形状、创建代次或缓存定位矛盾 | 内部不一致 |
| 当前节点未找到 / 已退出 | 未找到 |
| 读回节点代次 / G0 / G1 漂移 | 版本漂移；无混代登记 |

发布后读回失败不得撤销、补写、换键或伪装未发布；保留 L1 实际事实状态。
