## 4. 定义键、运行时键和编译边界

```text
15 项登记键                              0x0301'2180..0x0301'218E
治理函数定义节点                         0x0301'2185
治理函数定义 U64 属性类型                0x0301'2186
治理函数定义材料值                       0x0301'218F
R1 运行时五项                            0x0301'2660..0x0301'2664
A1 运行时八项                            0x0301'2680..0x0301'2687
```

定义登记写集精确使用互异的 2185 / 2186 / 218F；值所属和来源均为定义节点，材料为`{1,1,1}`，槽引用 218F。登记计数仍为 15。增加等价`static_assert`固定计数、相邻、互异和`218F < 2201`。

公开定义 DTO 不含 L1 键或原始值身份；只有所属、类型、来源、U64 三值、当前槽和生命周期全部互证才成功。不得从编译期常量补齐。

## 5. 六键来源与两个生产调用算法

六键是业务请求输入，不是 provider 中间数据。当前计划不负责创建生产六键分配服务。

历史首次记录分支：

```text
按 P1 / 准备键读取
-> 无记录：进入正常新初次判断
-> 合法 v1：初次请求版本待迁移，零写
-> 当前 v2：当前回流请求与历史六键 / 请求身份 / 运行代次 / 父需求逐项比较
-> 相同：只用历史原完整请求重放初次 provider
-> 不同：幂等冲突
```

无当前任务分支：

```text
准备键 = 回流请求六键组.P1建立
P1建立.值 == 回流记录.值.值
其余五键 = 回流请求六键组原值
治理函数合同版本 = 1
规则版本 = 1
```

`重判父需求并准备筹办`没有生产上游不是本计划的阻塞：公开请求和专项先冻结最终合同；未来消费者必须自行提供合法原信封，不能让本 provider 临时补键。

## 6. 分阶段恢复与失败收口

固定顺序为：准备键版本化历史读回；G0 裁决 D；存在键建立 / 恢复 E；任务核心键建立 / 恢复 T/R1/关系；`TASKSTAG`建立 / 恢复阶段定义；实例键建立 / 恢复 E 实例；首态键建立 / 恢复无动态`{1,1}`；P1 键同次建立 / 恢复 v2 首次记录、P1、A1；独立读回 A1 / 定义；首迁移键建立`{1,2}`和第一动态；各 owner 最终独立读回。

任一段非成功但带截止时，只以该段原键、历史 v2 原完整请求和该 owner 公开读回收敛，未确认不得越段。已发布前段保留，不跨 owner 回滚、不换键。合法 v1 历史记录零写待迁移；损坏材料内部错误；同键异义幂等冲突；当前性漂移要求新业务请求；许可 / 资源失败原样上送。非成功不得携带可冒充完整工作包的载荷。
