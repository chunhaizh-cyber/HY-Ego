# INSTINCT-ROUTE 本能路线后续计划制定方案 v0.6

日期：2026-09-01

材料身份：目标模式下的后续计划制定路线输入

替代关系：本文件完整替代 `20260901_INSTINCT-ROUTE_本能路线后续计划制定方案_v0.5.md`；v0.5 及更早版本只作历史形成材料，不再提供当前阶段或施工依据。

状态边界：本文件不是机器规范、详细设计、代码计划或计划索引项，不产生施工授权。

## 1. 顶层目标

以最少机制连续闭合当前唯一自我的安全根与服务根后继治理：

```text
唯一自我
-> 安全根需求 / 服务根需求
-> 父需求治理任务
-> 筹办工作包
-> 一个筹办闭合结果消息
├─ 子目标承接 -> 子需求 -> 普通任务 -> 新一轮筹办
├─ 可执行冻结 -> 安全门禁 -> 现实动作
├─ 合法等待 / 目标已完成
└─ 结构化非成功
-> 正式任务实际结果
-> 需求 owner fresh 当前满足裁决
-> 状态 / 动态 / 因果记录
-> 任务轮次收束与自我后继决议
```

路线连续推进到整条生产链闭合；中间代码叶不设置独立业务验收停点，也不等待用户逐段确认。每次进入 `main` 前仍保持可构建、规范一致、精确白名单和 Git 基线等最低工程门禁；完整业务与集成验收在整条链完成后统一执行。

## 2. 唯一需求来源

当前唯一自我只有两个允许父空的普通根需求：

- 安全根需求；
- 服务根需求。

除双根外，所有自我需求都必须由父需求所承接任务的筹办结果衍生。外部服务请求、观察、自检、条件、因果投影、方法缺口和其它事实只作为父任务材料；它们不直接创建需求，也不取得需求所有权。

父任务形成子目标必须同时满足：

```text
精确绑定当前 T→D_parent
+ 本轮筹办闭合结果正式采用包含该子目标的方案
+ 子目标对该方案必要
+ 子目标严格缩小父需求及祖先尚未闭合范围
+ 子目标具有明确且最终可判定的自身目标状态合同
+ 父子同 E_owner、单父、无环、不跨安全树 / 服务树
```

`子目标承接`允许当前可执行路径、实例方法和执行冻结为空。正式采用由本轮闭合结果和正式任务子目标承接记录共同证明，不建立“已采用方案”状态、半成品路径或第二结果账。子需求回流后必须用新事实截止重新筹办，旧消息和旧记录不取得执行权。

## 3. 筹办与任务管理消息边界

固定边界为：

```text
任务管理线程
-> 形成并派发不可变筹办工作包
-> 任务工作线程消费筹办工作包并调用筹办 provider
-> 每次处理结束恰好形成一个强类型筹办结果消息
-> 任务管理线程消费消息并独立读回正式分支事实
-> 按分支推进后继
```

复用现有任务工作线程和有界消息队列，不新增专用筹办线程。筹办 / 执行工作包使用强类型判别联合，不混用载荷。任务管理线程不得在自身循环内同步直调筹办 provider，也不得用内部槽、轮询、日志或返回值推断筹办已经结束。

筹办结果消息至少绑定：

```text
协议版本
消息 / 幂等身份
任务、任务轮次、筹办轮次
来源工作包身份
来源事实截止 G0
结果事实截止 G1
唯一结果分支
分支正式事实定位
```

顶层分支只保留：

```text
可执行冻结
子目标承接
合法等待
目标已完成
结构化非成功
```

学习和方法补齐不是并列顶层分支：满足统一子目标准入时作为`子目标承接`子类，否则作为当前任务材料或`合法等待`。消息只承担不可变跨线程交接，不建立持久化筹办回执或新的业务事实。

## 4. 连续实现顺序

### P00：退出旧服务合同生产链

停止服务合同、服务进展 / 准备、Gseed、时间维护和服务根自动写入；保留旧格式只读识别，但不得恢复业务解释或新写入。不得建立同义替代账。

### P01：筹办工作包与结果消息

建立强类型筹办工作包、结果消息、提交端口、任务工作线程消费和任务管理线程幂等接收；删除任务管理线程同步直调筹办 provider 的生产路径。先覆盖所有闭合分支，不在本叶引入第二持久事实。

### P02：父任务子目标正式准入

在筹办结果中闭合精确 `T→D_parent`、本轮采用方案、必要性、目标合同、祖先严格缩小、同 owner、单父、无环和不跨根门禁。只发布正式任务子目标承接记录，不直接写需求树。

### P03：子需求与普通任务后继

任务管理线程按子目标消息独立读回记录，编排需求 owner 建立或复用 `D_child` 并回绑记录；子需求使用既有普通入口形成或复用任务、任务轮次和初次筹办工作包，再进入同一消息化筹办链。

### P04：可执行冻结、安全门禁与现实动作

可执行分支完整冻结当前方法、路径、实例、动作范围、输入、条件、验证 / 归因合同和共同事实截止；现实改变动作在进入执行阶段前取得唯一自我授权并接受安全硬否决，纯内部治理和无现实副作用观察不请求现实授权。

### P05：结果、fresh、认知证据与轮次收束

形成正式实际结果，需求 owner 以新事实截止读取目标合同和当前特征值完整投影并裁决当前满足；状态记录事实、动态记录变化、因果记录变化关系。任务轮次完成结算和收束后，只消费自我`继续 / 结束 / 等待 / 取消`后继决议，不因目标未达成自动重筹办。

## 5. 禁止恢复或新增

- 服务合同、服务值账、预支 / 余款、进展 / 准备账、Gseed、游标或替代账；
- 通用请求节点、来源 registry、通用 `R→D`、UTC 接受账或真实性 provider；
- 专用筹办线程、持久化筹办回执、方案采用账或半成品路径状态；
- 任务管理线程同步直调筹办 provider；
- 任务、消息、日志、状态或动态直接写需求树；
- 学习 / 方法补齐与子目标承接并列的第二生需入口；
- 为中间证明制造生产事实，或把编译 / 静态接线夸大为整条链完成。

## 6. 完成条件

整条路线完成至少必须证明：

1. 服务合同及同义记账生产链已退出，普通服务只走服务根后继普通治理链；
2. 每次筹办处理都有且仅有一个结果消息，任务管理线程不存在生产同步直调或轮询替代入口；
3. 子目标精确绑定 `T→D_parent`，同 owner、单父、无环、不跨根且严格缩小祖先范围；
4. 子目标记录可被需求 owner 幂等建立 / 复用子需求并形成普通任务，回流后 fresh 重筹办；
5. 可执行分支完整经过冻结、自我授权 / 安全硬否决、现实动作和正式结果；
6. 需求满足只由 fresh 当前值与目标合同裁决，状态 / 动态 / 因果各守职责；
7. 任务轮次按正式结果、结算、收束和自我后继决议闭合；
8. 最后统一通过整链业务与集成验证，且未引入本文件第 5 节禁止体系。

完成单个阶段、提交、编译、静态调用图或消息收发，不得单独声明本能路线、服务闭环、自我治理或项目已经完成。
