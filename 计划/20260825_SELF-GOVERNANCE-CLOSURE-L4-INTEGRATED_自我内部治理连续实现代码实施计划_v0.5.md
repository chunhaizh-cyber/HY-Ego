## 5. 机械实施步骤

### 5.1 method v2

1. 在`L2普通方法结构.数据.h`按 v0.5 详细设计第 3 节声明作用范围、v2 事实、写/读请求、状态、四字段提交见证与结果；全部字段顺序、默认值、相等和成功谓词原样落地；
2. `作用主体约束`只接受非零`L2存在身份`；`L2概念身份`不出现在运行时主体字段；`L2任务结构.数据.h`删除重复作用范围枚举并以单向`using`复用 method 枚举；
3. 在`服务.L2方法结构.ixx`实现两个 v2 入口；同方法内容版本内按 1..N 追加，顺序和稳定动作键分别唯一；
4. 将内部`动作入口V2`改为真实 v2 负载，不再按旧五字段解析；v1 事实和旧普通方法 ABI只作历史/源码兼容，不升级、不猜字段；
5. 首次、精确重复、交换前失败、提交后读回失败和原键重放严格按矩阵分账。

### 5.2 技术许可与稳定动作端口

1. 在`实例方法执行.数据.h`只声明技术许可请求/见证/状态/结果；门控数据头单向包含它，不得反向包含门控 DTO；
2. 旧`实例方法技术许可读取请求/结果`名称不建立别名；只保留`实例方法技术许可请求/结果`；
3. 在`任务执行派发门控.数据.h`的派发冻结之后声明动作调用、动作键返回和动作返回；在`服务.实例方法执行.ixx`两个数据头均可见后声明唯一抽象端口；`实例方法执行提供者`构造时一次登记动作端口，拒绝空端口、零键、重复键，构造后不允许覆盖；
4. `读取动作技术许可`逐项比对 T/R/P/E、冻结、实例、方法版本、当前 v2 动作入口、完整有序范围与截止；只有已许可携带完整见证；
5. 动作端口返回的顺序、入口、稳定键和时间必须与调用一致，返回材料只进入待验证链。

### 5.3 控制态、调度资格与派发门控

1. 在`任务执行派发门控.数据.h`声明当前阶段、控制态、调度来源、调度资格、派发冻结及门控请求/结果；
2. 控制态证据只投影 6170 当前快照；调度证据只投影当前 T→D 实际来源、根配额和适用 6150 倍率；技术许可证据按完整冻结动作范围逐项覆盖，不形成第二许可、调度或授权事实；
3. 在门控服务按固定顺序消费阶段、冻结、实例、控制态、调度资格、逐项技术许可、授权前硬否决请求/结果、适用授权、动作前最终硬否决请求/结果；两次硬否决阶段回显和共同绑定必须精确一致；
4. 内部治理/纯观察必须零授权，现实改变必须绑定唯一当前授权；最终硬否决仍可阻断已授权未开始动作；
5. 只有`可派发`返回完整派发冻结；其它状态载荷空，门控零业务写。

### 5.4 强类型队列与 worker

1. 在`任务执行派发门控.数据.h`按冻结后的单向依赖声明`任务强类型执行请求`、唯一`实例方法执行请求`同义名、待验证材料和实例执行结果；
2. 任务管理线程队列从旧`任务执行冻结请求`迁移为完整`任务强类型执行请求`，两阶段准备/确认语义保持；未确认请求不可消费；
3. 任务工作线程改为唯一取出强类型请求，重新读回门控所需当前证据，随后调用`执行已冻结实例方法`；
4. provider按冻结顺序逐项定位稳定动作端口并调用；结果聚合为等长、连续、有序的动作键返回组；
5. 删除工作线程和运行包的`提交已形成任务工作结果`生产入口，删除调用方预形成正式工作结果路径；
6. 待验证材料只进入既有回执、现实独立回读、归因和正式结果发布链；禁止直接声明任务成功、需求满足或触发后继。

### 5.5 非成功与恢复

1. method v2 的交换前失败零写；提交后独立读回失败返回四字段见证，以原键重放；
2. 技术许可、门控或 worker 当前性失败均零真实动作；已开始动作后的返回只记录待验证材料，不伪造正式结果；
3. 动作端口抛出异常在 provider 边界收束为`内部错误`，不越过`noexcept`；
4. 精确重复返回首次同义证据，零新动作、零新事实代次；幂等异义结构化拒绝；
5. 任一部分成功不得回滚已发布事实；后继只沿原幂等身份和正式读回收敛。

## 6. 逐入口完成矩阵

| 入口 | 必须覆盖 | 完成形状 |
| --- | --- | --- |
| `发布或读取方法动作入口_v2` | 首次、重复、幂等/顺序/动作键/引用冲突、许可、漂移、资源、提交后读回失败 | 仅首次/重复有完整事实；已可能发布仅四字段见证 |
| `读取方法动作入口_v2` | 已读取、未找到、坏请求、许可、漂移、资源、内部错误 | 仅已读取有事实与非零截止 |
| `读取动作技术许可` | 八个专用状态 | 仅已许可有见证与非零截止 |
| `实例方法稳定动作端口::执行动作` | 九个动作状态、键/序/时间回显 | 仅动作已结束/重复有单项键返回 |
| `裁决任务执行派发` | 十一个门控状态 | 仅可派发有完整派发冻结 |
| `提交任务执行请求`及队列两阶段 | 准备、确认、撤销、重复、异义、容量、停止、取出 | 未确认不可取出；队列不裁决业务 |
| `执行已冻结实例方法` | 九个动作状态、逐项端口、异常、重复 | 仅动作已结束/重复有完整待验证材料 |
| 回执/上行桥 | 待验证材料准入、现实读回、正式结果发布/重放 | 动作返回本身永不成为正式结果 |
