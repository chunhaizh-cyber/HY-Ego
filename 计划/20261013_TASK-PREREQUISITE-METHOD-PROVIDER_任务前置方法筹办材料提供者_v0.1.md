## 1. 用户裁决与本叶目标

用户已明确：结算任务自身必须能够找到“获取服务任务”的方法头；结算任务目标保持服务值增加，但可另外持有并调用补齐前置条件的方法；取得服务任务只推进筹办，不代表结算任务完成，也不增加服务值。不得退回“只有另一个子任务才能找到该方法”的旧方案。

本叶实现任务类自身的独立前置筹办入口：输入原需求定位和目标快照，以及完整前置目标，按前置特征类型查询方法，并在该任务的进程内槽位暂持完整查询投影；可fresh读回、比较并显式刷新或清除。原需求、原目标候选、已采用方法实例、执行和结算全部零变化。

修改对象是任务域非权威、可重建的筹办投影，不是现实世界特征，不是方法知识，也不是任务虚拟存在状态。理由是原目标为服务值的任务需要查找可补齐“服务任务”条件的方法。目的只到“任务自身具备独立前置方法召回与当前材料交接能力”，不包含实际本能动作。

## 4. 精确公开值式合同

所有新增DTO置于`新_任务类.h`既有`新任务治理方法召回结果`附近，命名空间不变，均`final`并提供默认`operator==`。不改变既有枚举的编号。

```cpp
struct 新任务前置方法目标 final {
    稳定编码 任务节点;
    稳定编码 需求节点;
    稳定编码 原需求目标存在节点;
    新需求目标定义 原需求目标;
    稳定编码 前置目标存在节点;
    新需求目标定义 前置目标;
};

struct 新任务前置方法材料 final {
    新任务前置方法目标 目标;
    std::vector<稳定编码> 候选方法节点组;
};

struct 新任务前置方法请求 final {
    新任务前置方法目标 目标;
    std::optional<新任务前置方法材料> 预期现有材料;
};

enum class 新任务前置方法状态 : std::uint8_t {
    已暂持 = 1, 精确重复, 已读回, 未暂持, 已清除,
    尚未初始化, 入口拒绝, 任务不存在, 需求不存在,
    任务状态不允许, 原需求已变化, 槽位已变化,
    候选已变化, 方法查询未完成, 结构不一致, 资源失败
};

struct 新任务前置方法结果 final {
    新任务前置方法状态 状态 = 新任务前置方法状态::入口拒绝;
    std::optional<新任务前置方法材料> 槽位材料;
};
```

`槽位材料`是当前进程内完整投影的副本，没有节点身份，不具有执行许可。成功暂持/重复/读回返回材料；`原需求已变化`、`候选已变化`可返回旧槽位材料，只供后续CAS刷新/清除，不能据此执行。其它非成功及`未暂持/已清除`不返回材料。

三个公开成员声明置于既有`查询任务方法候选并发布`之前，定义置于其实现之前：

```cpp
新任务前置方法结果 查询并暂持任务前置方法(
    const 新任务前置方法请求& 请求) noexcept;
新任务前置方法结果 读取任务前置方法(
    稳定编码 任务节点) const noexcept;
新任务前置方法结果 清除任务前置方法(
    稳定编码 任务节点,
    const 新任务前置方法材料& 预期材料) noexcept;
```

允许调用方：后续正式筹办编排和获准实际项目验证入口。禁止让这些入口充当方法采用、self执行决议、动作调用或完成判定入口。首叶不新接生产调用者，不宣称结算已实际召回具体获取方法。

私有成员置于任务现有筹办辅助附近：

```cpp
std::map<稳定编码,
    std::shared_ptr<const 新任务前置方法材料>> 前置方法筹办材料组_;
```

map受已有`新任务互斥`保护。shared_ptr只用于不可变值的异常安全替换，不公开指针，不形成新owner，不保存函数地址或方法信息副本。完整目标和候选ID之外不保存状态/时间/版本/轮次。

## 5. 输入合法性与fresh核验

全部入口首先要求治理已初始化、正式任务存在。槽位写入和清除仅允许`已建立、待查找方法、待检查条件、等待条件`；其它状态返回`任务状态不允许`。若有最近X，必须能完整读回且属于T、状态为`已评估`，否则拒绝变更；不得清除待观察或尚未评估X所依赖材料。

查询请求还必须满足：

1. 所有必需编码非零；`T.需求节点 == 请求.目标.需求节点`。
2. fresh D存在，D的目标存在和完整`新需求目标定义`分别等于请求原需求快照；不符返回`原需求已变化`，不修改任何槽位。
3. 前置目标存在必须经存在服务确认是存在节点（场景作为存在沿原公开口径）；本叶不支持把裸任务或方法编码当世界存在。
4. 前置FT必须是特征类型根：用现有类型根读取helper核验“取得的根 == 请求FT”。
5. 目标形状严格二选一：值形态含合法非零域与关系节点、不含方向；方向形态只含合法增加/减少、不含域与关系。其它枚举值拒绝。
6. 值形态域必须是同FT的正式特征概念，关系必须是正式二次特征概念；本叶只负责结构和类型归属，**不求值、不声称该关系可以执行或满足**。完整关系适用性、实际值、方向和条件在后续选择合同中核验。方向形态同样不读取当前值作为已变化证据。
7. 仅构造`新方法候选查询`的`涉及特征类型概念组={前置FT}`；其它字段为空。不按名称、返回字符串、方向或C/R数量筛掉方法头。

查询必须返回`新方法操作状态::已找到`才算完整（空组合法）。`资源失败`映射资源失败，`结构不一致`映射结构不一致，其余映射方法查询未完成。逐项fresh读取方法，要求是启用抽象方法，头FT包含查询FT，编码唯一有序；仅头方法合法。失效/停用返回候选已变化，不发布不完整组；结构无法解释返回结构不一致。

现行查询已经排除实例方法根；仍核验`来源方法节点/实例根节点`为空，禁止把另一个任务的私有副本作为候选。

## 6. 三个入口的机械流程

### 6.1 查询并暂持

1. 在任务互斥下fresh核验T、D、状态、X及前置目标形状。
2. 对现有map槽位进行完整值CAS：无槽对应请求空预期；有槽必须与请求预期全字段相等。不同返回槽位已变化。旧材料来源可以已经过期，但只能被其完整预期值精确替换。
3. 通过方法owner执行第5节完整召回并核验，形成完整值式材料。再次确认原D、T及CAS仍一致（使用相同task锁，不释放后盲写）。
4. 内容相同返回精确重复；不同则先完成返回材料拷贝、不可变shared_ptr及新map项所需分配，再一次替换共享指针。新键使用强异常保证的map插入；替换现有指针不分配、不抛异常。
5. 发布后只使用已准备好的返回值移动返回，不再执行可能失败的领域写、分配或日志。异常发生于发布前时旧槽位保持不变。

允许一个任务逐次处理不同前置目标，但同一时刻只有一个槽位。不建立前置任务树，不改变原正式需求。无候选也保存完整空组，不能等同查询失败。

### 6.2 读取

1. 读取任务、槽位完整副本；没有槽返回未暂持。
2. fresh校验原D、前置对象/概念及状态；原D已变化返回原需求已变化和旧槽位材料，零写。
3. 按同一FT重新完整查询并逐项读方法；与槽位编码组比较。增加、移除、停用或头FT不再匹配均返回候选已变化及旧槽位材料，**不得悄悄删掉旧候选后返回成功**。
4. 当前集合相同返回已读回；只投影身份，不冻结方法内容。以后C/R变化必须由后续消费者fresh读方法，本叶不复制配对或引入内容代次。

读取不是持续快照：方法owner释放锁后知识可继续变化，调用方后续必须再次fresh选择。完整查询当前结果不证明未来仍不变。

### 6.3 清除

核验T和允许状态、X，随后按完整预期材料CAS。无槽返回未暂持；不同返回槽位已变化；相同只erase此T的map项，返回已清除。原D或候选变更不阻止精确清除过期投影，不写任何基础数据字段或删除正式节点。

## 7. 生命周期、锁与诊断

- 任务类实例销毁时map自然释放；重启不恢复、不补造，后续需要时重新筹办。
- 非筹办状态不允许替换或清除；读取可返回任务状态不允许，不因旧槽位存在宣称可执行。终结后的槽位只是不可消费投影，任务正式重新启用后可CAS替换/清除。
- 不新增持久身份、技术幂等账、公共版本或X。CAS按完整语义值，不加“第N轮”。
- 只复用现有task锁到只读需求/方法/存在/概念入口的方向；这些只读调用不回调task。禁止持锁调用外设、函数注册入口、消息投递、日志I/O或等待。
- helper归任务源文件匿名命名空间或任务私有成员，不另建工具模块。至少明确实现“允许前置筹办状态检查”“前置目标结构核验”“前置候选完整查询”；错误均向上返回本叶状态，不改成业务失败、不写任务失败状态。
- 没有多节点持久写事务，所以不涉及L1组合发布。本叶只有任务锁内的内存值原子替换，不声称提供跨进程恢复或跨owner原子快照。
