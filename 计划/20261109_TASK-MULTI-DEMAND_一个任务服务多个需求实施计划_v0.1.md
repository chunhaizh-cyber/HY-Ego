**目标：** 同一需求列表项（完整目标相同）的需求由同一任务服务；每轮执行前确定本轮服务的需求；结算按本轮服务需求交接；任务按轮续行与重新启用，按轮再结算。

### 2.3 服务需求集与选择

- **S(T)** = {T.D} ∪ {d：d 与 T.D 同列表项且无直接任务}；同项两个直接任务为结构损坏。
- **C** = {d ∈ S(T)：活动 ∧ fresh 未满足}，各 d 独立判定（方向目标、来源守卫、被动满足材料按各自 d）。
- **选择 Ds**（X 出生前，`开始方法执行内部` 锁内，以场景批 fresh 材料）：① C 中去掉“在 C 中有后代”者（后代优先）；② 余下含 Dr（T.最近重启 存在、依据结算 == T 最新 K，含两者皆空）→ Dr；③ 否则含 T.D → T.D；④ 否则节点编码最小（需求锁内串行分配，代表首次出生先后）；C 空 → 不开始执行，返回“无可服务需求”（非工程错误）。
- **当前满足需求**（新子需求挂接）：存在进行中 X → X.Ds；否则按同一规则计算；C 空不提议新子需求（不删旧子需求）。

### 2.4 结算需求

K.D = 被结算 X 的 Ds。结算时刻 S(T) 无活动需求 → 走 2.11 放弃；Ds 已失活但 S(T) 仍有活动需求 → 照常按 Ds 结算。

### 2.5 交接与归集

- **交接目标**：P = 查询需求服务任务(父需求(K.D))；父需求空 ⇒ 无直接父；P 无 ⇒ 等待直接父。P 可等于 T 自身（2.10）。
- **封口错位**：P ≠ T，P 已有来自本 T 更早 K 的 R，且 P 已终结（有最新 K 且 最新K.X==P.最近X，或状态为已结算/放弃结算）→ `工程异常终止`（裁决Q4）。P 未终结时允许接收本 T 的又一份 R（R 唯一性按来源 K）。
- **本轮直接子集** = {d：父需求(d) == 本轮 Ds}。
- **归集（逐子任务 t，按 K 计一次）**：
  1. t 的 K 链中 K.D ∈ 本轮直接子集 的每份 K：已有 R 到 P → 计入，除非该 R 已在 P 更早 K 的 `结算贡献子接收字段` 中；无 R 且 t 自该 K 后已重启或续行 → 零贡献收束；无 R 且 t 未重启 → 等待。
  2. 本轮直接子集的 d：其服务任务 t 已终结且 t 的 K 链无 K.D==d → 零贡献收束；t 状态“放弃结算”→ 零贡献。
  3. t 进行中（含因 d 重启/续行）→ 等待；但 t == P（同 T）时按 2.10。
  4. 失败/取消/已清理沿用现规则。
  5. 本轮贡献 = Σ 本轮计入 R；K.`结算贡献子接收字段` 只列本轮计入的 R。
- 同一 R 只被一份 K 计入；计值与遍历顺序无关。

### 2.6 活动性

- 任务继续 ⇔ C 非空；调度、筹办资格、学习唤醒、结果分支、复核任务需求、自我活动门统一。
- 终结判定：“已完成 且 最新K.X == T.最近X” 或 状态 ∈ {已失败, 已取消, 已结算, 未执行目标已满足, 放弃结算} ⇒ 终结；“已完成 且（最新K 缺失 或 最新K.X ≠ T.最近X）” ⇒ 完成待结算（8617、25019/25053）。

### 2.7 重新启用与轮次续行

- **重新启用**：请求 Dr → 自我确认（`自我新鲜自动决议` 或显式）→ manager 复核（T 终结、Dr ∈ S(T)、Dr ∈ C）→ owner 原子发布：状态→`待查找方法` + 重启记录 + T.最近重启 替换。覆盖终结态 9/10/11/12/13/14；Dr 可为 T.D。
- **轮次续行（用户裁决：按重新启用走自我确认）**：本轮完成时序固定为 ① Ds 满足 → 本轮完成（已完成）→ ② 发布本轮 K → ③ 交接 R（含同 T 自接收，2.10）→ ④ 直属收尾 9→12（T 终结）→ ⑤ 若 S(T) 仍有活动未满足需求：管理线程据任务状态变化生成重启请求（Dr=按2.3选出的下一 Ds，来源种类=同T续行，依据结算=本轮 K）交自我确认，再走重新启用。
- **无直接父分支**：父需求(Ds) 为空时无第③步；本轮 K 发布即为本轮正式完成点（2.6 判终结），第④步由既有最终消费路径（最终结算收尾 J5）按既有消费资格独立处理（不新增无 R 的最终消费通道）；第⑤步触发点为“K 发布完成”：管理线程在 K 发布回执后复核 S(T)，有活动未满足需求即生成重启请求交自我确认（不等待最终消费）。Ds 已满足而其它成员仍在 C 时，**先完成并结算本轮**，不得直接重新筹办（2.13）。
- **唯一与幂等**：以 T 严格快照为预期；并发第二请求预期不符 → 重读：T 已非终结 ⇒ 精确重复；迟到旧完成消息只认 X == T.最近X。
- **未完成结算**：外部重新启用越过的未建 K 完成、已建 K 未交接的旧 K 放弃不续办（2.1.1第4项）；推进入口只处理最新 K。续行按上面①–⑤顺序，本轮 K 已交接后才可能重启，不产生放弃。
- **旧入口兼容**：`重新启用任务(T)`（10429）唯一调用者 `承接需求任务`（25358）已知请求 D，改为调用 `重新启用服务任务(T, 请求D, 来源=承接请求)`；旧签名删除。

### 2.9 最终消费证明

现状按任务建唯一映射（12870–12909），递归取子任务当前最新 K（13417–13471），准备保护批把重复子任务判为环（25791–25799），历史消费核验子任务当前 F（12863–12865）。多轮后同一子任务可经 K₁、K₂ 两次出现，会被判损坏或错配。冻结：证明与锚点按 **K** 建键（去重键=K）；递归沿 R.`接收来源结算字段` 取来源 K；准备保护批按 K 判重复与环；历史消费与来源 K 的贡献值比较。

### 2.10 同 T 跨轮自接收

- **合法条件（建立与历史读取同一判据，只用已存在材料）**：R.父任务 == R.子任务 == T，且 查询需求服务任务(父需求(来源K.D)) == T（来源 K 所服务需求的父需求由 T 自身服务）。不引用后续 X/K/Ds。同列表项成员关系由完整目标决定，历史读取以同一判据 fresh 复核。
- **时序**：2.7 第③步交接时 P == T；封口错位检查对 P == T 豁免；R(T→T) 在第④步直属收尾之前建立（K 发布后 T 处于“已完成且有本轮K”，2.6 视为终结；交接仍在该状态下进行）。
- **新轮归集**：重新启用后某轮 Ds′ == 父需求(来源K.D) 时，本轮直接子集含 来源K.D（其服务任务即 T），2.5 第1步按 K 计入（该 R 未被更早 K 计入）；若 Ds′ 选为其它成员，该 R 留待服务 父需求(来源K.D) 的那一轮计入。

### 2.12 任务贡献特征 F 与每 K 贡献

- **F**：T 的贡献特征当前值（有符号，允许合法负贡献，6190:60）；= T 全部已接收 R 的贡献值之和 + T 全部叶子 J 的增量之和（与 K 无关）。写入者不变：接收 R 时增加 R.贡献值（17166–17179）；服务叶子 J 增加叶子贡献。
- **K.贡献值**：= 本轮计入的 R 之和（K.`结算贡献子接收字段` 所列，2.5 按 Ds 归属）+ 本轮叶子 J 增量（叶子任务）。不由 F 差额推出；不新增累计字段。
- **待用 R**：已接收但尚未被任何 K 计入的 R；只在其来源 K.D 的父需求 == 某轮 Ds 时被该轮计入（按 Ds 归属，不跨 Ds 转移）；放弃轮不计入任何 R，待用 R 留待对应 Ds 的轮次，若此后再无对应轮则不入账（属用户允许的特殊漏结算）。
- **叶子 J**：由仅 `0→1`（12644–12654）推广为 `n→n+叶子贡献`（n = 写入时 F，原值不作为基线核验）；读回（9851、9856）改为核验 J 增量（新值−原值）== 该 K 的叶子贡献部分；历史 J（0→1）增量为 1，兼容。
- **一致性核验**：`读取完成贡献`（4993–5002）沿用“K 贡献 == 所列 R 之和（+叶子 J 增量）”；`核验任务贡献特征权威` 与 `读取结算候选资格核心` 13308 “当前F==本K贡献”改为“当前 F == Σ T 全部 R + Σ T 全部叶子 J 增量”与“本K贡献 == 所列 R 之和 + 本K叶子J增量”两条；13385 “当前F==本R贡献”改为 R.贡献值 == 来源K.贡献值。
- **入账**：最终入账与来源核验一律使用 K.贡献值 / R.贡献值，不使用 F（`服务值结算.本能运行服务.cpp` 509 来源贡献改取 K.贡献值并按该值入账）；防重复消费按 K（2.9）。
- **旧 R 权威核验**（9933–9935）：与来源 K.贡献值比较。
- **施工覆盖**：9867、17167、17215 处把 F 当作纯 R 小计的用法，按本节公式区分 F（含叶子 J 增量）与 R 小计（Codex 六审提醒）。
- 动作发生后的错误处理沿 12655–12671 现有区分。

### 2.13 集合复核与本轮完成

- `复核任务需求`（25075 起）返回集合：成员组 [{D, 活动, 满足状态}]、C、本轮 Ds 状态。
- **成员进入 C**：活动且满足状态 ∉ {已满足}；来源待确认、信息待完善、需执行前后比较等非满足状态均计入 C（各成员的就绪由其被选为 Ds 时的筹办处理）；前提已变化 → 汇总为 前提已变化（重读）；资源失败 → 资源失败；结构损坏 → 结构不一致。
- **本轮完成判定**：只看本轮 Ds：Ds 已满足 → 本轮完成（进入 2.7 ①–⑤，先结算）；Ds 未满足 → 按现单需求逻辑继续或重新筹办。其它成员状态不影响本轮完成，只影响第⑤步是否续行。
