## 1. 用途与权威边界

本文件用于计划智能体在没有更高优先级的新目标、当前设计切片已经安全收口或存在可并行空闲能力时，继续形成后继设计包和叶子计划。它只保存已经达成共识的项目方向、设计原则、依赖顺序和待规划目标，不保存聊天过程。

本文件不是机器逻辑规范、详细设计、施工计划或计划索引，不产生 `待激活` / `可执行` 状态，也不授权执行智能体施工。每次消费前必须重新读取当前 Git、`计划/计划索引.md`、正式规范、当前代码、有效设计和真实接口；与届时正式事实冲突时，以正式事实为准并修订新设计，不得复活本文件中的过期快照。

计划智能体可以把本文件中的后继目标继续细化为正式规范、流程图、详细设计和叶子计划；正式计划仍须完成创建侧验证、提交、推送、索引登记和执行通知。本文件不替代这些步骤，也不要求另建状态台账。

## 2. 已确认的项目总体方向

当前总路线固定为：

```text
节点直接稳定身份、类型记录和事务恢复底座
-> 现实世界引导与世界结构服务
-> 特征、完整状态和动态提供者
-> 同代次完整世界快照与世界树统一门面
-> 唯一生产装配、旧世界入口退出和服务级验收
-> 自我内部治理纵向闭环
-> 分层安全、服务生存维护及后续学习 / 因果闭环
```

不得跳过世界树统一事实入口，直接让自我治理复制第二套世界读取、旧句柄初始化或 SQL 回源路径。

### 2.1 运行期事实与分层服务

正式项目口径已经确定：

- 内存已发布代次是唯一运行期机器事实权威。
- SQL 和独立材料只承载持久证据、隔离恢复输入、应急审计和交互投影，不是普通运行期回源或裁决入口。
- 缓存和可重建索引是非权威加速结构。
- L1—L5 及同层不同事实所有者只经具名、版本化、强类型服务合同交互；按真实依赖直接调用，不建立无事实责任的逐层转发。
- 公开跨层 DTO 只承载稳定身份和强类型值。内部节点 / 关系句柄、许可、仓库、事务参与者和 SQL 材料不得泄漏到 L2 及以上合同。

上述口径以 `规范/0050_项目通用机器逻辑与禁止性规则总纲_20260721.md`、4010—4070、4190 和 4200 的现行版本为准。

### 2.2 世界树统一门面

世界树业务服务是统一对外门面和跨领域编排者，不是取得全部底层写权的万能 CRUD 服务。存在、场景、特征、状态、动态仍由各自事实所有者负责；门面只通过其公开强类型服务完成：

- 世界引导和世界结构读取；
- 创建存在并接纳到场景；
- 初始特征和特征换代；
- 发布状态并整理动态；
- 移动或移除场景归属；
- 整树、存在、场景三类同代次完整值式读取。

“移除归属”“业务退役”和“物理删除”必须分账；不得把统一门面解释为任意物理删除入口。

## 3. 计划与执行协作共识

### 3.1 计划智能体

计划智能体负责新目标范围内的项目规范、目标流程图、详细设计、叶子计划和对应索引项。它可以根据现行正式材料自主补齐普通工程选择和可唯一裁决的规范内容，但不能修改智能体协作规则，也不能自行发明会改变用户目标、机器语义、公开合同、数据权威或安全边界的新裁决。

计划验证只证明“执行智能体可以不临场补设计地施工”，不证明代码已经实现、编译、接线或通过业务验收。验证至少核对目标、真实接口、允许范围、依赖、字段来源、分支、事务、错误和可执行的成功条件；不建立固定文档数量、形式矩阵或第二套终审。

独立只读审计只是一种可选的创建侧查漏方法，不是计划支撑终审、审批权或索引登记人。普通计划可以由计划智能体换新上下文从头复核；复杂高风险计划才按需使用独立只读审计。

### 3.2 计划支撑智能体

计划支撑智能体不预审、不终审、不正常登记计划智能体的新包。它只在执行智能体已经固定具名计划、当前基线和无法裁决的计划 / 设计问题后介入，在来源计划原目标内：

- 依据现行规范和当前事实给出唯一施工裁决；或
- 修订受影响计划、详细设计、目标流程图、接口合同和索引项；
- 发布新版本并要求执行智能体重新 S0。

纯代码错误、编译错误、环境波动和普通验证失败仍由执行智能体在合法范围内处理。只有必须改变机器语义、扩大原目标或建立独立新目标时，计划支撑才停止并等待用户裁决。

### 3.3 并行闭合和逐叶子释放

计划智能体始终优先闭合最早能够独立施工的叶子计划。存在文件和语义互不重叠的工作时，使用同类型子智能体并行完成；主计划智能体独占共享规范 / 接口合同、计划索引和 Git 发布。

```text
最早叶子设计闭合
-> 创建侧验证
-> 独立提交并登记
-> 立即通知执行智能体
-> 不等待同包后续叶子全部完成
```

计划过大时在原目标内继续拆分。条件允许时维持“一份执行中、一份可执行、若干设计中”的缓冲，但不得为了填充队列降低设计、依赖或执行门禁。

## 5. 世界树后继计划顺序

### 5.1 当前执行：闭合 P1A2

P1A2 已经满足“真实无法裁决的计划 / 设计漂移”退回条件。当前下一动作不是执行智能体直接续写，而是计划支撑智能体吸收 `9e2383ed2dcc51a215c08c86940908abcd36ee98` 的安全 WIP和具名漂移，在原目标内冻结稳定主键命名域来源及恢复解码合同，发布新的精确计划 / 设计版本并同步索引。随后执行智能体从正式新基线重新 S0，再完成固定事务、持久证据、恢复、完整验证和专属记录；不得选择其它计划覆盖当前 WIP，也不得把 WIP 当作已完成提供者。

### 5.2 下一叶子：P1A3 现实世界引导与结构提供者

计划智能体应在 P1A2 执行期间并行闭合 P1A3。P1A3只消费 P1A2 正式 L1 服务，提供：

- 恢复后读取既有世界根；
- 确认全新空域后建立唯一世界根和初始场景；
- 世界结构值式读取；
- 存在创建与场景接纳；
- 场景 / 存在移动和归属移除；
- 单根、单父、无环和存在单位置验证。

P1A2结果进入正式基线后，P1A3必须按真实接口更新基线和合同，验证通过即独立发布、登记并通知执行，不等待 P1B—P1D。

### 5.3 P1B 前置提供者核对

P1B除 P1A2 / P1A3 外，还需要：

1. 节点直接特征查询提供者：按稳定身份返回完整当前特征和值及同次非零事实截止代次；
2. 4180 当前唯一注册比较提供者：比较结果携带注册稳定身份、比较合同版本、算法版本和同次事实截止代次。

### 5.4 P1B 完整状态动态提供者

P1B消费世界结构、完整特征和唯一比较提供者，闭合合法零状态、首基准状态、等价后继和差异动态，并通过 P1A2 单事务最后发布。P1B完成只证明状态 / 动态提供者候选，不证明世界快照、生产接线或自我循环。

### 5.5 P1C 同代次完整快照与统一门面

P1C消费 P1A3、P1B和节点直接特征提供者，形成整树 / 存在 / 场景三类专属读取结果及世界树统一业务门面。跨提供者读取必须以同一内存已发布代次见证闭合；版本漂移只允许按正式设计重试，不能返回部分成功或用 SQL 补缺。

只有服务级验收通过，才能声明世界树生产闭环成立。

## 6. 世界树之后：自我内部治理纵向闭环

`SELF-GOV-LAYERED-01` 必须消费世界树最终正式合同，不复制第二套世界事实读取。计划智能体按 `规范/5090_子规范_需求任务方法运行闭环与独立结果回读.md`、`规范/6180_子规范_自我稳定身份项目资格与具名事实范围.md`、8300及届时现行规范重新设计。

施工模式采用已经确认的“合同先行、框架分级、纵向逐步闭合”：

1. 先选一个真实、无伪数据、可独立验收的最小业务闭环，不先铺满全项目空函数。
2. 按真实依赖把 G01—G12 拆成当前事实 / 差距到需求、需求到唯一任务与方法冻结、单方法执行到独立回读与任务 / 需求裁决、缺口 / 重新筹办 / 等待与循环继续等纵向叶子；最终分段由当前事务所有权裁决。
3. 只为当前叶子必需的接口建立骨架。骨架必须返回结构化“未实现”，零机器事实写入、零默认成功；编译接入不等于能力完成。
4. 验收按 ACCEPTANCE-01 分级：`编译接入通过`、`入口巡检通过`、`局部可继续`、`服务验收通过`。只有正式入口、真实结果和权威终态独立读回闭合，才能升级到服务验收。
5. 提供者和消费者计划分开；真实提供结果不足时消费者保持待激活。

G01不得仅凭自我身份直接建立系统级根需求；必须按 6180 建立 / 验证治理坐标和具名事实范围，并经需求统一入口形成真实需求。

## 7. 分层安全与服务生存维护的后继设计输入

相关对话共识已经进入正式规范，后续计划不得重新从聊天补造公式，应直接读取 6100、6120、6140、6150、6160、6170、4320及其引用规范。

计划设计时保留以下核心边界：

- 生存安全根值、分层安全值、服务值和任务执行优先级权限是不同机器量，必须分账。
- 分层安全身份由“来源因果信息 + 目标安全结果 + 当前因果图版本”成立。持久图只保存直接因果；精确路径深度使用非负 I64且不设业务上限。
- 五级只用于任务执行优先级投影，不截断、删除或持久化超过五层的因果信息。
- 分层安全被动维护依据单调实际时间、有效未复发证据和残余风险，在低 / 高阈值间维护注意资源与潜在风险；线程循环次数、Tick或等待超时不能成为来源动作。
- 服务合同绑定真实人类提出者、需求、目标、范围和有效期。同一来源需求有效期内只有一个当前合同；合同成立冻结预算并预支 30%，完整完成支付余款，取消、到期、无法完成或终止不追回预支且不支付余款。
- 服务准备不建立额外预算，只能在完整、可验证完成后补回唯一归属的同期实际衰减。
- 服务值采用完整单调秒维护和 30 天门禁；无有效需求时每秒最小衰减 1。服务活动、未满足需求和到期事件必须按 6160 / 6170正式合同处理，不使用循环次数或任务数量代替时间。
- 生存安全根值 `0` 是终止态、`1` 是可唤醒休眠态、`>1` 允许主动运行。服务值为零只能按 6170 把仍可维持的根值收敛到 1；新的有效人类需求必须先形成唯一合同和 30% 预支，再按完整秒门禁形成唤醒候选。
- 安全值低于相应服务门禁时，普通服务任务不得取得执行权限；直接解除真实安全问题的人类需求可以按真实因果进入安全任务分类，但仍保留服务合同和结算身份。
- “压力”作为额外调度量已经明确延后讨论，不得在当前计划中用待服务数量、待任务数量或线程负载反写安全值、服务值或合同预算。

这些规则应在世界树和自我治理底座稳定后，按提供者—聚合治理入口—自我线程触发—独立读回—服务验收的顺序形成叶子计划。自我线程每轮只负责以完整单调秒输入触发具名治理服务，不直接写安全值、服务值、合同、状态或动态。

## 9. 计划智能体空闲续作算法

计划智能体没有新的用户消息时，按以下顺序继续：

```text
重新读取 Git、计划索引、当前执行回执和所有者
-> 当前计划执行中：闭合其最早后继叶子及必要提供者
-> 已有叶子设计通过：立即发布、登记并通知执行
-> 后继存在未冻结合同：用子智能体并行扫描，主智能体裁决共享合同
-> 世界树全部服务验收通过：启动 SELF-GOV-LAYERED-01
-> 自我治理底座闭合：按正式 6140—6170 形成安全 / 服务维护叶子
```

任一时刻不得：

- 从本文件、未提交草稿、历史聊天或旧实现直接选择施工；
- 因同主题或同总目标人为串行本可并行的设计工作；
- 等待整个设计包完成后才释放已经独立闭合的叶子；
- 把计划验证、独立审计或计划支撑重新扩大成重复终审；
- 为保持执行智能体忙碌而降低真实接口、依赖、事务或验收门禁；
- 把图谱、能力候选、编译或入口存在写成服务完成。

## 11. 多线程目标业务图重新校准

2026-08-03 已把目标业务图校准为“六类核心线程各自运行一个所有者函数”。计划智能体后续只使用 `流程图/目标业务流程图/README.md` 登记的当前有效图，不从聊天、删除文件或旧编号补造线程主干。

当前有效分层为：

```text
L0 运行海中鱼巣：只做模式路由
-> L1-T01 程序主线程：装配、启动、等待停止和分阶段收口
-> L1-T02 自我线程：安全/服务维护、主需求、许可、实际结果治理和结算触发
-> L1-T03 任务管理线程：任务树、筹办、状态推进、异步派发、回执回读和上行
-> L1-T04 任务工作线程池：每线程消费一个不可变工作包、执行、冻结并重发回执
-> L1-T05 控制面板线程：UI 消息循环、只读投影和程序停止消息
-> L1-T06 外设线程组：采集、时间对齐和不可变外设材料发布
```

事件日志、缓存统计、持久证据和 SQL 审计只作支持线程旁路。世界树、安全、需求、任务、方法、因果和观察均为线程在队列锁外调用的领域能力，不单独拥有隐含线程。

计划拆分时必须显式标明每条连接属于：

```text
直接函数调用
异步消息后继
只读投影
支持线程旁路
```

跨线程消息至少携带稳定消息身份、运行代次、业务对象身份、轮次 / 尝试、材料版本、来源事实截止版本和幂等键。队列锁内只入队、出队、移动 / 复制和维护队列自身状态；领域调用、方法动作、独立回读、事务提交和持久化适配必须在锁外。

停止设计不得采用“简单设置停止标记后逐线程 join”。必须冻结：先禁止控制面板与外设新输入，自我停止产生新任务意图，任务管理停止新派发，工作线程完成或合法收口在途工作，任务管理排空回执，自我排空最终治理消息，支持线程刷新，最后由程序主线程完成 join 和结构化结果映射。线程退出不能替代任务结果或需求结算。

各领域能力的目标归属直接读取当前映射表与 L2 图。删除旧目标图不表示删除领域服务；它只消除重复的目标设计入口。
