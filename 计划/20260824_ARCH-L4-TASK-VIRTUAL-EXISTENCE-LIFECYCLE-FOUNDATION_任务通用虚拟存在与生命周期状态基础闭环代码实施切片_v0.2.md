## 1. 唯一目标和依赖

把真实任务轮次结算作为已发布 ARCH-L2 状态/动态原子 provider 的首个生产消费者。前置依赖是 `ARCH-FIVE-LAYER-FOUNDATION v0.3` 的代码结果与正式装配；其组件施工计划在本计划登记时退出。不得把路径验证候选、目标未达成待重筹办旧链或任何测试假消费者当作依赖或结果。

本计划可执行的最低条件：任务实际结果、目标裁决和轮次结算公开读取入口在执行 S0 中仍存在且能以共同 `G0` 互证；通用存在、特征、状态、动态 provider ABI 与普通应用 getter 未漂移；工程文件和启动装配没有他主 dirty 冲突。任一条件不满足，停止受影响切片并回报具名漂移。

## 2. 执行者不得临场决定的合同

### 2.1 任务通用存在

- 业务键：`L2任务身份`；L2 宿主引用：任务稳定编码；一任务仅一当前 `L2存在身份`。
- 幂等身份：固定域下由任务身份、合同版本和宿主引用摘要组成；同义重复返回原存在，异义返回幂等冲突。
- 顺序：共同 G0 读任务 → `L2通用虚拟存在结构服务::新增` → 按返回身份当前读取 → 写入任务通用身份引用 → 再读回任务和存在。写入失败只能按原幂等身份收敛，不得重新新增。
- 新状态/动态请求的主体必须是该通用 `L2存在身份`；旧 `L2任务虚拟存在身份` 仅历史兼容。

### 2.2 最小生命周期特征

复用 5200/5210 已冻结状态集合，不新增状态机。建立唯一 `任务生命周期阶段` 特征定义、任务宿主实例和唯一当前值槽。值稳定键固定为：

```text
ARCHL4-TASK-LIFECYCLE/ROUND-SETTLED-WAITING-SELF-SUCCESSOR
ARCHL4-TASK-LIFECYCLE/EXECUTION-RESULT-PENDING-VALIDATION（只读前态）
```

定义、实例和值必须分别通过 L2 特征结构的新增/完整读取/当前值换代入口完成；稳定值事实身份、类型化材料、来源稳定编码、创建/退出代次和历史值必须逐字段读回。执行者不得以 `L2任务业务状态段` 或日志文本替代。

### 2.3 首个消费者入口

新增唯一 L4 业务模块：

```text
L4任务轮次结算状态消费者::提交轮次结算并发布当前状态(
    L4任务轮次结算状态请求) -> L4任务轮次结算状态结果
```

请求必须携带任务/实例方法/执行轮次/实际结果/目标裁决/轮次结算身份、通用存在、旧状态、共同 G0 和安全硬否决；业务 provider 只解释这些已形成的 L4 事实是否可提交，L2 provider 只接收结构 DTO。目标已达成转入待验证后完成；目标未达成转入本轮已收束/等待自我后继决议；不写任务完成、失败或下一轮筹办。

## 3. 固定实施顺序

1. 在任务数据中增加通用 `L2存在身份` 引用和必要的迁移见证字段；保留私有身份与治理状态历史，不新写旧入口。
2. 在任务服务中新增“取得或建立通用任务存在”适配，仅调用公开 L2 通用存在服务；完成同一 G0、幂等和正式读回。
3. 在特征服务中登记固定生命周期特征定义、任务宿主实例和初始当前值；不得添加第二状态服务或裸枚举属性。
4. 新建 L4 任务轮次结算状态消费者 DTO/服务；只读取任务公开事实、特征当前值和 L2 provider getter，不持有 raw L1 端口。
5. 将结算后的后态材料映射到既有 `L2状态动态原子发布请求`，恰调用一次；完成 G1 五组生产读回。
6. 普通应用只装配一个消费者实例并公开 getter；启动文件仅接线，不提前开放治理门、不调用冻结治理批次。
7. 施工记录、验证记录和工程登记只更新本白名单，完成后通知集成验收；不得顺手归档旧事实或实现后继筹办。

## 4. 事务、失败和历史不变量

- 全部前置读取绑定同一非零 G0；G0 漂移、许可拒绝、未找到、已退出、引用冲突、资源失败和内部不一致均零 L2 发布。
- L2 原子 provider 成功只允许已提交/精确重复，变更代次为同一 G1，载荷完整；失败不得携带部分身份或猜测性截止。
- 同一任务+实例方法+执行轮次+实际结果+目标裁决+轮次结算的同义请求返回原结果；异义请求幂等冲突且零写；不自动重试。
- G1 五组读回必须证明新状态当前、新状态关系、新动态当前、新动态关系和旧状态历史退出，且主体/前后状态/特征/值/来源字段一致。
- 任务旧路径、旧实例、旧实际结果、旧目标裁决、旧结算和旧状态历史不可删除；本计划只停止新轮次结算写入旧治理状态。
