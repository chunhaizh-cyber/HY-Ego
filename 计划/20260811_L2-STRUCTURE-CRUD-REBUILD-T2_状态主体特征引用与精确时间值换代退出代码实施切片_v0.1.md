### 2.1 规范与事务裁决

以 4230 为状态结构机器语义直接依据：状态主体 / 特征实例由 L1 关系事实承载，精确值 / 时间值由属性槽和值事实承载；关系替换、值换代、旧事实退出和新当前引用必须在同一事实代次原子发布。1160、4210、旧状态 / 动态代码和历史计划中的场景归属、状态业务准入、自动当前性选择、状态比较或动态生成口径均不得进入 T2。

主体和特征实例不是两个可以独立落盘的更新入口。若旧状态为 `主体A + A的实例`，目标为 `主体B + B的实例`，任何单腿更新都会制造主体与实例宿主不一致的公开中间态。因此本计划只建立一个原子引用对替换函数；请求至少改变主体或特征实例之一，但实现始终同时退出两条旧关系并新建两条关系，使结果形状、幂等语义和历史边界唯一。

精确值与时间值使用一个强类型角色枚举选择，但每次只换代一个角色。状态顶层来源由两值共同互证，T2 不提供来源换代；请求必须显式回显当前来源，新值继续引用该来源。若调用方确需改变来源，那是会改变状态完整记录语义的新目标，不能伪装成一次单值换代。

## 4. 最终 T2 DTO

在 T1 数据头中新增：

```cpp
enum class L2状态值角色 : std::uint8_t {
    精确值 = 1,
    时间值 = 2
};

struct L2状态引用替换请求 final {
    L2结构请求头 请求头;
    L2结构幂等身份 幂等身份;
    L2状态身份 状态;
    std::vector<稳定编码> 旧自有关系闭包;
    L2存在身份 新主体存在;
    L2特征实例身份 新特征实例;
};

struct L2状态引用替换结果 final {
    L2结构结果头 结果头;
    std::optional<L2状态事实> 当前状态;
    std::optional<L2状态自有关系引用> 当前自有关系;
    std::optional<L2状态自有关系引用> 已退出自有关系;
    bool 成功() const noexcept;
};

struct L2状态值换代请求 final {
    L2结构请求头 请求头;
    L2结构幂等身份 幂等身份;
    L2状态身份 状态;
    L2状态值角色 值角色 = L2状态值角色::精确值;
    稳定编码 旧值稳定编码;
    L2原始值材料 新值材料;
    稳定编码 来源稳定编码;
};

struct L2状态值换代结果 final {
    L2结构结果头 结果头;
    std::optional<L2状态事实> 当前状态;
    std::optional<L2状态自有关系引用> 自有关系;
    std::optional<L2属性事实> 已退出值;
    bool 成功() const noexcept;
};

struct L2状态退出请求 final {
    L2结构请求头 请求头;
    L2结构幂等身份 幂等身份;
    L2状态身份 状态;
    std::vector<稳定编码> 自有事实闭包;
};

struct L2状态退出结果 final {
    L2结构结果头 结果头;
    std::optional<L2状态事实> 已退出状态;
    std::optional<L2状态自有关系引用> 已退出自有关系;
    bool 成功() const noexcept;
};
```

全部 DTO 提供逐字段默认比较。共同有效性固定为合同版本 1、非零期望事实代次、幂等身份和状态身份。

引用替换另要求旧自有关系闭包恰为两个非零、严格升序且无重复的稳定编码，新主体 / 新实例非零。请求不复制旧主体 / 实例或给两个旧编码附加角色；实现从正式当前状态取得角色化关系并比较其排序编码集合，因此 L1 对退出集合的规范化不会把“同键异角色排列”误判为另一种公开请求语义。“新引用对与当前引用对完全相同”只能在当前读回后裁决为 `引用冲突`。请求不携带关系类型身份或 L1 本地键。

值换代要求角色恰为精确值 / 时间值、旧值和来源非零、新材料满足共同材料规则：I64 任意，I64 组 / U64 组非空，独立材料编码非零。来源是当前状态来源的显式回显和新值来源，不是来源换代入口。

退出要求自有事实闭包恰为四个非零、严格升序且无重复的稳定编码；实现把当前两关系和两值编码形成同样的排序集合后逐项比较。状态编码不得出现在闭包中。请求不携带角色标签、主体、实例、来源、类型节点或外部引用编码；闭包的公开语义就是一个集合，从而与 L1 规范化幂等语义一致。

成功结果只接受 `已提交 / 精确重复`、非零且相等的事实截止 / 变更代次。引用替换成功同时携带一个截止完整当前状态、一对当前关系和一对在本次代次退出的旧关系编码；值换代成功携带截止完整当前状态、当前两关系和一个同代次退出的旧值；退出成功携带节点、两值均在本次代次退出的状态和两条已退出关系编码。所有非成功载荷为空；提交前失败不携带变更事实代次，L1 已成功发布后的资源 / 内部读回失败可以回显已安全取得的首次变更代次，但不得伪造成功载荷。

三个 `成功() const noexcept` 只核对结果头、可选载荷组合、身份 / 生命周期和排序等不依赖私有登记的形状。精确 / 时间值是否属于登记八类型、材料表示、所属状态、来源互证和关系类型角色，必须由服务使用已加载登记在返回前验证；执行者不得把无登记参数的 `成功()` 当成完整业务预言机。

三个函数均由 `海中鱼巣.领域.服务.L2状态结构` 唯一拥有并导出。不得增加 `替换状态主体`、`替换状态特征实例` 两个单腿入口，也不得把精确值 / 时间值拆成业务名称专用函数；强类型 `L2状态值角色` 已把两个结构角色封闭为可穷举集合。

服务构造、不可复制属性和成员顺序继续精确保持 T1：L1、存在服务、特征服务、私有状态登记定位。T2 不增加 provider、仓库、锁、缓存、索引、序列化、恢复或第二服务。

公开函数及调用 L1 / L2 的内部辅助诊断责任为 `向上送出`，只返回结构化状态，不新增日志。角色映射、请求有效性、编码排序、截止生命周期投影和结果完整性等纯值辅助为 `无适用错误分支`。`std::bad_alloc` / `std::length_error` 映射资源失败，其它未处理异常映射内部不一致。

函数名、变量名、类型和业务成员名全部中文；技术边界 `L1`、`L2`、`I64`、`U64` 和标准库名可保留。生产文件零测试 / 验证命名、零计数器、零 sleep、零故障注入。

## 6. 共同写前、幂等、提交和首次结果

三个写函数的共同顺序固定为：

```text
纯值校验
-> 读取当前状态结构类型登记
-> 形成完整不可变 L1 中性写集
-> 探测当前事实代次
-> 实际代次 != 请求期望：恰一次直提原写集，由 L1 裁决重复 / 冲突 / 漂移
-> 同期望：调用 T1 读取完整状态(当前)并完成本函数专属前置
-> 恰一次提交同一写集
-> 从首次事实代次历史节点、关系、属性值和端点重建首次结果
```

登记未加载映射 `入口拒绝`，许可拒绝、漂移、资源失败和内部不一致精确映射。实际代次已经偏离时不得先用当前事实重建或改变写集：L1 对原幂等键先比较完整请求，精确重复返回首次结果，同键异义返回幂等冲突；新键只返回漂移。不得换幂等身份、改期望、替换旧编码或二次提交。

普通 T2 幂等身份完整 64 位原样映射为 L1 幂等键，不进入状态登记私有 `0x20` 域。T1 四个写集本地键按每份写集局部作用域合法复用：

```text
状态主体关系本地键      = 0x0204'1101U
状态特征实例关系本地键  = 0x0204'1102U
状态精确值本地键        = 0x0204'1201U
状态时间值本地键        = 0x0204'1202U
状态端点角色            = 1
```

首次结果只从首次发布代次的 L1 历史事实重建。后继关系 / 值再换代或状态退出后，原请求重复仍返回首次关系、值、状态截止和首次退出事实；不得把未来退出代次、未来端点或未来值混入原结果。

提交前出现的入口、登记、端点、漂移、幂等、引用、许可、资源或内部非成功必须零普通事实变化。L1 已返回成功后，若首次历史重建发生 `std::bad_alloc` / `std::length_error` 或读回矛盾，公开结果为空载荷并映射资源失败 / 内部不一致，但不能宣称零变化；实现必须保留原幂等身份和原完整请求作为唯一收敛路径，不二次提交、不改变请求、不补偿已发布事实。

## 7. 主体 / 特征实例引用对原子替换

引用替换写集固定为：

```text
节点 = []
关系 = [
  {状态主体关系本地键, 源=请求状态, 目标=请求新主体,
   类型=登记主体关系类型, 角色=1},
  {状态特征实例关系本地键, 源=请求状态, 目标=请求新特征实例,
   类型=登记特征实例关系类型, 角色=1}
]
值 = []
属性槽变更 = []
退出事实 = 全局升序唯一[
  请求旧自有关系闭包的两个编码]
```

请求期望代次匹配时，先调用 T1 `读取完整状态(当前)`，要求返回一个完整状态及两条自有关系；把主体 / 特征实例关系编码排序后必须与请求旧自有关系闭包逐项相等。随后以同一期望代次调用 E2 最终 `读取完整存在(当前)` 和 F3 最终 `读取完整特征实例(当前)` 验证新端点；新实例宿主必须等于新主体。

新主体和新实例都等于当前状态端点时是无变化请求，返回 `引用冲突` 且零提交。只改变主体、只改变实例或同时改变两者都允许，但结果始终新建两条关系并退出两条旧关系；这保证引用对历史形状一致，也避免可选半替换 DTO。新端点未找到 / 已退出、许可、漂移、资源按同名状态；实例宿主与新主体不符或旧关系编码不符返回引用冲突；当前完整状态形状矛盾返回内部不一致。

成功 / 精确重复必须取得两个本地键到两个不同非零新关系编码的一一映射。首次代次历史读回必须证明两旧关系在该代次退出、两新关系在该代次创建、关系类型 / 源 / 新目标 / 角色正确，状态节点和两值未退出且来源、材料、生命周期保持原样。任一缺项、多项、错端点、错类型、混代或非预期值变化返回内部不一致，不二次提交。

T1 当前读取在替换代次之后只能返回新端点 / 新关系，历史截止早于替换代次返回旧端点 / 旧关系，截止等于替换代次返回新对；两条件查询随关系权威变化，不复制第二条件索引。

## 8. 精确值 / 时间值跨表示换代

按请求角色唯一选择旧属性和值类型组：

- `精确值`：旧值必须等于当前状态精确值编码，新材料只映射到四个精确值登记类型之一，使用 `0x0204'1201U`；
- `时间值`：旧值必须等于当前状态时间值编码，新材料只映射到四个时间值登记类型之一，使用 `0x0204'1202U`。

唯一写集为：

```text
节点 = []
关系 = []
值 = [{所选本地键, 所属=请求状态,
       类型=按角色和新材料选择的登记类型,
       材料=请求新材料, 来源=请求来源}]
属性槽变更 = [{请求状态, 所选登记类型, 所选本地键}]
退出事实 = [请求旧值稳定编码]
```

请求期望代次匹配时，T1 当前完整状态必须存在且完整；所选旧值编码必须等于请求，状态顶层来源、精确值来源和时间值来源必须三者相等并等于请求来源。另一个未换代角色必须保持当前、完整且同截止。旧值不符或来源回显不符返回引用冲突；缺槽、多槽、两值来源矛盾、所属 / 表示 / 生命周期矛盾返回内部不一致。

新材料可以与旧材料逐字段相同，也可以跨 I64、I64 组、U64 组和独立材料引用表示；显式换代仍建立新的值稳定编码。L1 在同一候选中退出旧值并移除旧槽，再建立新值和新槽，因此一个角色始终至多一个当前值，另一个角色零变化。

成功 / 精确重复必须取得所选唯一新值编码。首次历史属性值组只证明在首次截止所选角色唯一有效值为新值、另一角色仍唯一有效；该提供者的候选来自成功属性槽变更，但不返回历史槽对象。旧值必须另以 `读取中性历史事实(旧值编码)` 证明在首次代次退出。即时首次提交后若仍位于同一代次，可以用一致当前属性投影补充核对槽指向新值；后继事实已经推进后的精确重复不得依赖不存在的历史槽投影。结果的 `当前状态` 是首次代次完整状态，`已退出值` 保留完整退出生命周期。所属、角色类型、材料表示、来源、唯一有效值、编码或生命周期任一矛盾返回内部不一致。

## 9. 状态显式闭包退出与外部引用保护

退出前调用 T1 `读取完整状态(当前)`，取得状态事实和两关系编码。把两关系和精确 / 时间两值共四个编码形成全局升序唯一集合，必须与请求自有事实闭包逐项相等；任一漏项、错项或多项闭包返回 L2 `引用冲突`，零提交。

唯一 L1 写集为：

```text
节点 = []
关系 = []
值 = []
属性槽变更 = []
退出事实 = 全局升序唯一[
  状态节点编码,
  请求自有事实闭包的四个编码]
```

请求不得携带或退出主体存在、特征实例、来源、十个类型节点、未来动态 / 因果关系或其它外部事实。L1 对最终写集执行二次当前引用闭包保护：任一未来动态前 / 后状态关系、因果条件 / 结果关系、值来源或其它当前事实仍引用状态节点，且未由其合法所有者先行退出时，返回 `引用冲突=10`；T2 精确映射且不扫描消费者、不返回引用者列表、不补造退出项。

调用方必须先经外部结构所有者闭合当前引用，再使用新的期望代次和新的幂等身份重试；不得用原引用冲突请求身份改变闭包。当前自有关系与两值已经显式位于本写集，因而只闭合状态自身不会被自身引用伪阻断。

成功 / 精确重复要求空新编码映射和首次发布 / 重试边界正确；按首次事实代次历史读取状态节点、两关系、两值，五项退出代次必须相等。端点、来源、类型节点及外部已先行闭合事实不由 T2 退出。`已退出状态` 保留状态和两值退出生命周期，`已退出自有关系` 返回两编码；任一读回矛盾为内部不一致，不补偿已经发布的事实。

退出后当前单项返回已退出，两条件当前组不再包含该状态；退出前历史截止仍完整，截止等于或晚于退出代次返回已退出。T2 不提供复活、物理删除或持久证据清理。

## 10. 状态、读取兼容、幂等和异常收口

T2 不改变 T1 六个函数签名。T1 当前 / 历史完整读取必须自然消费关系 / 值历史：

- 引用替换前截止返回旧主体 / 实例，替换截止及之后返回新主体 / 实例；
- 值换代前截止返回旧值，换代截止及之后返回新值；
- 退出前截止返回完整状态，退出截止及之后返回已退出；
- 当前按主体 / 实例查询只随当前两关系变化，按状态身份升序且不复制第二权威列表。

同一幂等身份只绑定完整请求。引用替换与状态退出的公开闭包在进入 L1 前已经严格升序，公开请求语义与 L1 规范化集合语义一致；不得为闭包编码附加可交换的隐含角色。精确重复返回首次状态、关系、值和首次代次，零推进；同键异状态、旧闭包、新端点、角色、旧值、材料或来源为幂等冲突。发布结果未知只以原请求重提，不换键、不重构材料。

非成功顺序固定为：

```text
纯值非法 -> 入口拒绝
登记未加载 -> 入口拒绝
登记其它失败 -> 对应共同状态
既有幂等 -> 精确重复 / 幂等冲突
新键旧期望 -> 事实代次漂移
状态或新端点未找到 / 已退出 -> 同名
引用替换无变化 -> 引用冲突
新主体与实例宿主不符 -> 引用冲突
旧关系闭包 / 旧值 / 来源回显 / 退出闭包不符 -> 引用冲突
L1 外部当前引用未闭合 -> 引用冲突
许可 / 资源 -> 同名
事实形状矛盾 -> 内部不一致
```

所有 L1 写入状态 switch 必须完整覆盖 `引用冲突=10`。T1 完整状态必有两关系和两值，T2 不把缺失角色包装成 `属性未设置`；缺项是内部不一致。全部非成功载荷为空；提交前失败不伪造变更代次，提交后读回失败只回显 L1 已安全取得的首次代次并遵守第 6 节收敛边界。
