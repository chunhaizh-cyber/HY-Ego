# 通用特征值域读回与比较提供者代码实施计划

身份：`FEATURE-DOMAIN-COMPARISON-PROVIDER`

版本：v0.1

状态：可执行

基线：`02b60d5b`

## 1. 目标与完成条件

按同名详细设计 v0.1 实现 4180 §5.2 的唯一只读 `特征值域比较数据服务`：提供 FC 值域读取、FC/FC 相等与包含、F/FC 命中三个强类型入口；I64 真实复用既有域能力，I64组/U64组/独立材料引用通过同一 ABI 返回结构化 `未实现` 或 `规则缺失`。

完成条件是：新 DTO、状态、预算、成功谓词、概念 owner 窄读取、I64 三条真实路径、三类非 I64 空实现、工程登记和施工记录全部形成；空实现声明与紧邻定义均含“待实现”，零事实写入、零关系写入、零假成功；编译与计划验证通过。非 I64 专用规则、材料解析、存在概念业务成功、运行、恢复和集成验收不属于完成条件。

## 2. 正式依据与前置

依据 2100 v0.14、4120 v0.11、4130 v0.4、4180 v0.13 §5.2、4182 v0.1、7100 v2.0、7110 v2.0、4240 v0.42 及同名详细设计 v0.1。

已验证当前能力：`数据服务.特征类` 有 I64 完整域、规范化与包含；`数据服务.特征值类` 有四表示同截止完整值读取；`数据服务.概念树类` 有 I64 FC 结构但缺按已知 FC 的窄公共读回，也没有非 I64 成功域。该缺口由本计划闭合，不新增 L1 功能、第二规则仓或第二概念 owner。

执行 S0 必须重新核对正式规范版本、当前接口签名、计划索引、占用表、Git/index、`.vcxproj/.filters` 自动包含状况及所有新文件/语义所有权。若正式基础读接口漂移、异主占用或 L1/概念/特征 ABI 不能按设计组合，停止本切片并退回计划支撑；不得临场修改存在概念计划、IF/R 或机器语义。

## 3. 允许与禁止范围

允许：

- `海中鱼巣/领域/数据服务.特征值域比较类.h`（新建）
- `海中鱼巣/领域/数据服务.特征值域比较类.cpp`（新建）
- `海中鱼巣/领域/数据服务.概念树类.h/.cpp`
- `海中鱼巣/领域/数据服务.特征类.h/.cpp`，仅在 I64 类型/规则窄读实际缺失时
- 当前工程 `.vcxproj/.filters`，仅登记新文件
- 本计划专属 `施工记录/FEATURE-DOMAIN-COMPARISON-PROVIDER_施工记录_v0.1.md` 与验证记录。

禁止：L1、特征值持久模型、概念/存在完整定义生产 ABI、世界树、存在类、IF/R、动态、因果、线程、装配业务逻辑、旧 D/O/R 退役、非 I64 专用算法/材料格式、规则/规范、`.ixx` 和不相关 WIP。不得改变已发布 I64 比较 DTO/稳定数值编码。

## 4. 施工步骤

1. 在概念树类增加 `特征概念值域基础读取请求/事实/结果_v1`：按指定 FC 和 `Gread/H` 读取当前 I64 FC 的 FT、表示、规范化 I64 域和读取见证；不得扫描所有概念。非 I64/未有可读域的分支声明与紧邻定义均添加 `待实现`，返回 `未实现` 或 `规则缺失`，清空成功事实。
2. 新建值域比较服务头/源，固定所有 v1 DTO、组合预算、状态/关系枚举与严格 `成功()` 谓词；构造器仅接收概念、特征、特征值三项只读服务，禁止拥有写端口。
3. 实现 `读取特征值域` 与 I64 分派：委托概念窄读和既有特征 I64 域能力，逐次核对实际 Gread/H、FT、表示、规则及用量；不得实现本地区间运算。
4. 实现 `核验特征值域关系`：两端均完整 I64 时以既有 I64 包含双向核验映射相等/左右包含/不包含；任一非成功清空关系和成功见证。
5. 实现 `核验实例值域命中`：准确 F 同截止读回、FT/表示核验、I64 单点域与 FC 域包含；不得把 F 的值身份、节点身份或名称当实际值。
6. 对 I64组/U64组/独立材料引用各写一个结构化空适配器。**声明处与紧邻定义处均必须含“待实现”**；FT 无专用规则返回规则缺失，规则可读但实现未交付返回未实现。不得调用任何 L1 写端口/写集，不得返回 bool 默认值、关系枚举或成功事实。
7. 登记工程；只删除本计划新服务所替代的、已证实存在的非 I64 假比较代码。若无命中，施工记录声明“无旧代码可删除”；不为形式扩大删除集。
8. 写专属施工与验证记录，逐函数列出读依赖、状态、零写入边界、I64复用、非I64待实现标注和知识变更清单。

## 5. 失败与恢复收口

所有入口/预算失败为入口拒绝；FC 非特征概念为类别冲突；FT/表示/解释不一致为类型不相容；FT规则缺失为规则缺失；专用函数未实现为未实现；读取代次变化为事实代次漂移；退役、历史清理、资源与内部错误严格映射来源。非成功不返回域、关系、规则或成功见证。

本服务不写入，所以没有幂等重放、发布未知或部分提交的成功状态。遇到底层不一致必须原请求收敛并保留只读诊断；不得重试写入、创建 FC、更新注册或改变调用方概念选择。

## 6. 验证与发布

必须运行：

```powershell
git diff --check
python .\tools\check_specs.py --strict
```

并以当前工程做 Debug/Release x64 编译。专项验证覆盖：I64 相等/左右包含/不包含和实例命中；FT/表示不符；截止、预算、退出、历史清理、资源失败；三类非 I64 的未实现/规则缺失分账、`待实现` 双位置文本、零写入口静态巡检及调用前后事实代次不变。验证记录必须明确：这些检查不证明非 I64 专用成功比较、运行、恢复、外设/材料解析或业务闭环。

取得唯一发布租约后，精确暂存本计划允许文件和专属记录，普通提交并推送；不得带入异主 WIP。提交只证明提供者代码和记录发布。

## 7. 完成声明与下游

完成后，存在概念两组定义提供者可重新 S0 并由其自身所有者标记为可执行：它得到统一且不缩窄类型范围的值域核验接口，I64 可真核验，非 I64 仍会安全返回未实现/规则缺失并阻止定义写入。

本计划不宣称非 I64 FC 已能成功参与存在概念匹配；每一实际 FT 专用适配器和真实消费者仍需后续独立设计、实现与验证。
