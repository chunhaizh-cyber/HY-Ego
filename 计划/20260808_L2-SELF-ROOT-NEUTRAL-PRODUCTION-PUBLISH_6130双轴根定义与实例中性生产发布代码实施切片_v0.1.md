## 4. 实施步骤

### 4.1 数据合同

按详细设计精确建立版本、请求、双轴枚举、单轴事实、双轴事实、状态、结果及完整性函数。所有函数和变量使用中文；不得添加业务操作标签、意图组、执行证据、恢复材料或日志判定字段。

### 4.2 双轴根服务

按流程图实现唯一服务：

1. 从完整自我机械形成 `实际存在读取请求`；
2. 固定安全/服务定义为 `0..I64_MAX`；
3. 固定安全实例 `A=1`、服务实例 `V=0`，来源均为自我；
4. 顺序调用两个既有 const 服务，任何非成功立即结构化返回；
5. 在私有锁内保存首次请求、逐步成功定位和最终事实，使同请求部分失败重入从最早未完成步骤继续；
6. 完整成功后，同请求直接返回幂等读回，异请求或异自我返回幂等冲突；
7. 正式读取只能使用缓存定位和两个既有公开服务，四项共同截止且逐字段一致才返回成功。

不得取得 `L1事实基座服务`、仓库、完整快照、审计、恢复、日志、自检或旧系统角色引用。

### 4.3 生产配置与上下文

- 配置新增一份 `自我双轴根发布请求`，安全/服务定义身份固定 2/3，安全/服务实例身份固定 2/3；有效性和等值比较同步覆盖。
- 上下文构造唯一双轴根服务，新增初始化与读取窄入口；不得复制底层服务或建立第二发布者。
- 工程与 filters 登记两个新生产模块。

### 4.4 生产启动

在完整自我发布和正式读回成功后、旧系统角色初始化前：

1. 调用双轴根初始化；
2. 要求状态为已提交或幂等读回、事实完整；
3. 调用双轴根正式当前读取；
4. 要求已读取、事实完整且与发布事实逐字段相等；
5. 任一失败返回 `自我双轴根初始化错误`，候选上下文不发布；
6. 成功后才继续旧系统角色 legacy 初始化。

启动结果增加双轴根业务状态，但不输出 PASS，不把日志或退出码作为机器事实。

### 4.5 记录

施工记录写实际修改、接口和边界；验证记录写精确命令、结果、提交基线和未验证范围。两记录不得声称第一层自证、第一层完善或旧根已退出。
