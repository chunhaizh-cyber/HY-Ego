完成条件固定为：

1. `替换因果状态引用组` 每次只选择 `条件` 或 `结果` 一组，以一份 owner-scoped L1 写集退出该组全部当前关系并建立一个新的非空有序状态引用组；另一组、动作、来源、因果节点与创建代次不变；
2. 新条件 / 结果组逐项以原请求期望事实代次调用 T1 / T2 最终 `读取状态身份来源(当前)`，保持非空、顺序 / 目标非零、按 `(顺序, 目标)` 严格升序无重复和每组最多 `0x0FFF` 项；
3. 不提供单项条件 / 结果增加、删除、移动或覆盖入口；调用方必须提交完整新组，避免半组机器事实和第二权威列表；
4. `替换因果动作引用` 以一份写集覆盖空到有、有到空和有到不同动作三种变化；新动作非空时只是不透明非零稳定编码，由 L1 一致当前投影证明当前普通节点；
5. 动作当前为空且新动作仍为空、或当前动作与新动作相同，固定为无变化 `引用冲突`，零提交；C2 不把空动作解释为被动，也不把非空动作解释为主动、方法或可执行动作；
6. `换代因果来源` 以新来源建立新的独立材料引用属性值、退出具名旧来源值并切换唯一当前来源属性槽；旧值保留历史，新来源由 L1 验证当前可引用；
7. 来源换代是显式值版本动作，新来源可以等于当前来源，仍建立新值编码；它不解释来源类别、质量、完整性或业务证据；
8. 条件 / 结果关系替换、动作关系替换和来源值换代均在一个事实代次原子发布；旧事实编码必须与当前完整因果精确匹配，否则 `引用冲突` 且零提交；
9. `退出因果` 显式闭合因果节点、唯一族归属关系、全部条件关系、可选动作关系、全部结果关系和唯一来源值；全部自有事实在一个事实代次退出，状态端点、动作、来源、类型节点、锚点保持不变；
10. 闭包外任一当前关系、所属值、值来源或独立材料仍引用因果节点时，由 L1 二次当前引用闭包返回 `引用冲突`；C2 不扫描消费者、不返回引用者列表、不补造外部退出项；

12. 同一幂等身份同完整请求返回首次完整结果且零推进，同键异因果、角色、旧闭包、新组、动作、旧值、新来源或退出闭包返回幂等冲突；
13. 入口、登记、许可、未找到、已退出、漂移、幂等、引用、资源和内部错误精确分账；提交前非成功为空载荷且零普通事实变化，发布后读回失败不补偿，只允许原请求收敛；

## 5. 共同写前、幂等、提交和首次结果

四个写函数共同顺序固定为：

```text
纯值校验
-> 读取当前因果结构类型登记
-> 形成完整不可变 owner-scoped L1 写集
-> 探测当前事实代次
-> 实际代次 != 请求期望：恰一次直提原写集，由 L1 裁决重复 / 冲突 / 漂移
-> 同期望：调用 C1 读取完整因果(当前)并完成本函数专属前置
-> 恰一次提交同一写集
-> 从首次事实代次历史节点、关系、属性值和端点重建首次结果
```

实际代次偏离时不得先读当前因果、改变排序或重构写集。L1 先以完整幂等请求裁决：原键原请求精确重复，同键异义幂等冲突，新键旧期望漂移。不得刷新期望、换幂等身份、替换旧编码或二次提交。

普通 C2 幂等身份完整 64 位原样映射 L1 因果 owner 写域，入口继续拒绝 C1 冻结的来源登记和结构登记两个保留值。C1 本地键在每份写集局部作用域复用：

```text
条件关系本地键基值 = 0x0206'2000U + 项序号
动作关系本地键     = 0x0206'3001U
结果关系本地键基值 = 0x0206'4000U + 项序号
来源值本地键       = 0x0206'5001U
```

首次结果只从首次发布代次历史事实重建。后继再次替换、换代或退出后，原请求重复仍返回首次当前因果、首次新 / 旧关系或来源值和首次代次；不得混入未来退出、未来端点或未来来源。

提交前非成功零普通事实变化。L1 已成功发布后，首次重建资源失败 / 矛盾返回空载荷并可回显安全取得的首次代次，但事实可能已形成；只允许原幂等身份和原完整请求收敛，不补偿、不回滚、不二次提交。

事实代次探测使用中性读取 ABI；该枚举没有许可拒绝。精确映射固定为：`成功 + 非零代次` 继续；`入口拒绝` 返回入口拒绝；`资源失败` 返回资源失败；`内部不一致` 返回内部不一致；中性探测若出现未找到、已退出、属性未设置或成功零代次，均为当前非空运行包下不可能形状并返回内部不一致。不得为中性探测虚构许可拒绝。完整历史首探 / 尾探同样先按上述映射处理非成功，只有探测成功且代次与请求期望不等才返回事实代次漂移。

## 9. 因果显式闭包退出与外部引用保护

退出前调用 C1 `读取完整因果(当前)`，先验证当前分组投影为族归属一条、条件 / 结果各非空、动作 0 或 1、来源值一条且全部编码全局不同，再展平为全局升序集合并与请求闭包逐项比较。任一漏项、错项或多项返回引用冲突；闭包纯值非法入口拒绝。

唯一写集为：

```text
节点 = []
关系 = []
值 = []
属性槽变更 = []
退出事实 = 全局升序唯一[
  请求因果节点,
  请求自有事实闭包]
```

请求不得携带或退出条件 / 结果状态、动作、来源、锚点、关系 / 属性类型或外部事实。L1 对最终写集二次执行当前引用闭包：任一闭包外关系、所属值、值来源或独立材料引用因果节点且未由合法所有者先退出时返回引用冲突；C2 不扫描、不补项。

这里的四类是生产保护语义，不是要求一个因果专项绕过 owner 边界构造全部夹具。C2 因果专项只直接构造公开 ABI 合法可达的跨 owner 外部关系，并证明 C2 对 L1 `引用冲突` 的透传；所属值、值来源和独立材料三类底层判断绑定 L1 通用自有节点七角色专项的已发布证据。公开 ABI 下不可直接构造不等于生产不保护，底层 L1 专项也不能替代 C2 的跨 owner 关系透传用例。

调用方必须先经外部所有者闭合引用，再使用新期望代次和新幂等身份重试；不得以原引用冲突请求身份改变闭包。因果自有关系和值已在写集内，不被自身引用伪阻断。

成功 / 精确重复要求新编码映射为空。按首次截止历史读取因果节点；因果在 C2 退出前必为当前，所以退出代次必须严格大于创建代次。以 `退出代次 - 1` 读取族归属、条件、动作、结果历史关系组和来源历史属性值组以发现退出前最后有效的全部自有编码，再按首次退出截止逐编码调用 L1 单事实历史读取，证明全部自有事实退出代次等于因果退出代次。以首次退出截止逐项历史验证状态端点，并历史读取动作 / 来源；端点、来源、类型、锚点与外部事实不由 C2 退出。不得直接以退出截止调用历史组后把空组解释成合法退出，也不得用请求闭包代替 L1 历史发现和逐项互证。

退出后 C1 当前单项返回 `已退出` 空载荷，三类当前组不含该因果；退出前历史返回当时完整结构，历史截止等于或晚于退出代次仍返回 `已读取` 和完整退出生命周期。`退出因果` 成功 / 精确重复结果也携带同一首次退出投影；不提供复活或物理删除。

## 10. C1 读取兼容、状态与异常收口

C2 不改变 C1 八个函数签名。C1 当前 / 历史读取必须自然消费关系 / 值历史：

- 状态组替换前截止返回旧组，替换截止及以后返回新组；
- 动作替换前 / 后分别返回旧 / 新可空动作；
- 来源换代前 / 后分别返回旧 / 新来源；
- 退出后当前入口返回已退出空载荷；历史退出前截止返回当时完整结构，退出截止及以后返回带完整退出生命周期的已读取投影；
- 三类当前查询只随对应当前关系变化，按因果身份升序，不复制索引。

`读取因果身份来源(历史)` 与 `读取完整因果(历史)` 的退出后取数顺序固定为：

```text
读取前当前事实代次并等于请求期望
-> 读取因果节点单事实历史，校验 owner / 普通节点 / 编码与创建代次
-> 创建代次晚于历史截止：未找到
-> 节点退出代次存在且 <= 历史截止：要求退出代次 > 创建代次，结构发现截止 = 退出代次 - 1
-> 否则：结构发现截止 = 历史截止
-> 身份来源入口以结构发现截止读取唯一族归属关系组
-> 完整入口以结构发现截止读取族归属、条件、动作、结果历史关系组与来源历史属性值组
-> 以原历史截止逐编码读取节点、关系和值单事实历史，验证 owner、类型、端点、角色 / 顺序、材料、值来源和生命周期
-> 若节点已在原截止退出，全部自有事实必须携带与节点相同的退出代次；若节点尚未在原截止退出，隐藏所有晚于原截止的未来退出代次
-> 状态端点、动作和来源仍以原历史截止调用其合法历史入口
-> 读取后当前事实代次仍等于请求期望
-> 返回事实截止 = 原历史截止的唯一完整投影
```

结构发现截止只用于发现该历史时点有效的角色编码，不改变公开截止，不把退出前一代伪装成返回事实截止。组读取和每次单事实读取报告的当前事实代次都必须等于请求期望；任一组空缺 / 多项、编码在结构发现截止无效、单事实不存在、退出代次不闭合、字段不匹配或前后代次漂移均返回对应漂移 / 资源或内部不一致，禁止回退请求闭包、扫描历史索引或猜测编码。该顺序与已发布 T2 状态历史退出投影使用的 `退出代次 - 1` 发现机制一致，但不得复制状态业务 DTO 或调用状态私有实现。

非成功顺序固定为：

```text
纯值非法 -> 入口拒绝
登记未加载 -> 入口拒绝
登记其它失败 -> 对应共同状态
既有幂等 -> 精确重复 / 幂等冲突
新键旧期望 -> 事实代次漂移
因果或新状态 / 动作 / 来源未找到、已退出或入口拒绝 -> 同名
状态组 / 动作无变化 -> 引用冲突
旧关系闭包 / 旧动作关系 / 旧来源值 / 退出闭包不符 -> 引用冲突
L1 外部当前引用未闭合 -> 引用冲突
许可 / 资源 -> 同名
事实形状矛盾 -> 内部不一致
```

所有 L1 写入状态 switch 完整覆盖 `引用冲突`。C1 完整因果必有非空条件 / 结果、0—1 动作和唯一来源值；缺项不包装成属性未设置，固定内部不一致。全部非成功载荷为空；提交前失败不伪造变更代次，提交后失败只回显已安全取得的首次代次。

v0.4 对读取状态再冻结以下唯一分账：

| 发生点 | L1 / 下游事实 | C2 状态与头 |
| --- | --- | --- |
| 写前中性代次探测 | 成功且等于请求期望 | 继续专属前置与恰一次提交 |
| 写前中性代次探测 | 成功但不等于请求期望 | 不在服务侧刷新期望；恰一次直提原写集，让 L1 裁决精确重复 / 幂等冲突 / 事实代次漂移 |
| 发布后中性代次探测 | 资源失败 | `资源失败`、空载荷、事实截止 / 变更代次均为 L1 首次写入代次 |
| 发布后中性代次探测 | 入口拒绝 / 内部不一致或不可能枚举 | 分别 `入口拒绝` / `内部不一致`，空载荷并保留首次写入代次 |
| 历史首探 / 尾探 | 成功且等于请求期望 | 继续或返回完整历史投影 |
| 历史首探 / 尾探 | 成功但不等于请求期望 | `事实代次漂移`、空载荷，回显实际探测代次 |
| 历史首探 / 尾探 | 资源失败 / 入口拒绝 / 内部不一致 | 同名状态、空载荷；不得误报事实代次漂移 |
| owner-aware 一致 / 历史读取 | 许可拒绝 / 资源失败 / 事实代次漂移 | 同名状态、空载荷；发布后路径保留首次写入代次 |
| L1 成功但结果缺项、复义、错类型、错生命周期或前后矛盾 | 权威形状矛盾 | `内部不一致`、空载荷；不得降级为资源、漂移或未找到 |

`映射历史失败` 必须穷尽 `许可拒绝 / 资源失败 / 事实代次漂移`；中性代次映射必须穷尽其真实枚举但不发明许可状态。状态组、动作、来源和退出四写的发布后读回使用同一分账，不允许四份漂移实现。修复只位于现有因果服务私有纯映射 / 辅助和四写 / 历史读取调用点，不改变 DTO、公开签名、写集、事务、幂等域或 L1。

## 11. 临时生产外验证矩阵

临时 cpp 只 import L1、T1 / T2 最终状态服务和 C1 / C2 因果服务。状态、动作、来源、因果和外部引用夹具全部经正式公开入口建立；不得 import 私有仓 / 端口 / 锁 / 定位 / 幂等账，不解析日志，不复用旧因果、动态模式或历史状态 / 动态代码。

入口参数固定：

```text
--幂等基值 <uint64，默认101000>
--条件一顺序 <uint64，默认10>
--条件二顺序 <uint64，默认20>
--结果一顺序 <uint64，默认30>
--结果二顺序 <uint64，默认40>
```

必过矩阵：

1. 经 T1 / T2、C1 正式入口建立至少五个状态、动作、两个来源和两个完整因果；C2 不直造状态或因果；
2. 把一个因果的两项条件组整体换成另一非空有序组，只推进一个代次，旧条件关系同代退出、新组同代创建，结果、动作、来源、节点不变；条件查询从旧端点移除并加入新端点；
3. 整体替换结果组，条件 / 动作查询保持不变；替换前 / 后历史分别返回旧 / 新完整组，不出现空组、半组或双当前组；
4. 新组与当前组完全相同、旧闭包漏 / 错 / 多分别引用冲突且零推进；空组、零顺序 / 目标、重复项、未升序、超 `0x0FFF` 项或闭包非法入口拒绝；
5. wrong-family、legacy、裸 L1 和同 owner 无状态来源端点由最终状态服务结构化拒绝，C2 原样映射且零变化；
6. 状态组替换原请求立即及后继代次重复返回首次结果；同键改角色、新组或旧闭包幂等冲突；
7. 动作空到有、有到异值、有到空各只推进一个代次；动作查询准确增删，条件 / 结果 / 来源不变；
8. 空到空和同动作替换引用冲突；旧动作关系空 / 有形状或编码不符引用冲突；非当前 / 非普通动作精确非成功且零推进；
9. 动作替换原请求重复返回首次新 / 旧可选关系，同键改旧关系或新动作幂等冲突；
10. 来源换代到不同来源只推进一个代次，旧来源值退出、新值成为唯一当前，材料和值来源均等于新来源；条件 / 动作 / 结果不变；
11. 来源换代到同一来源仍建立不同新值；错旧值引用冲突，新来源未找到 / 已退出精确非成功；原请求重复和同键异来源分别精确重复 / 幂等冲突；
12. 退出闭包漏 / 错 / 多任一族归属、条件、动作、结果或来源值分别引用冲突；闭包含零、重复、未全局升序或因果节点入口拒绝；
13. 经独立外部 owner 的合法公开写端口建立目标指向因果的当前关系；`退出因果` 必须透传 L1 `引用冲突`、载荷为空且事实代次零推进。随后由该外部 owner 退出关系，并以新期望代次 / 新幂等身份继续矩阵 14。所属值、值来源和独立材料三类不在因果专项直接构造或运行：验证记录必须绑定 L1 通用专项提交 `962154927fc37ed85f6b72807cc6bbc1644264b4`、源码 blob `57e0fd7e7ad6164c9494c51da09126470bbac690` 和记录 blob `fdc7e2e64b8f1184cece1dbf7b3d3ae223a187cd`，据其七角色公开中性矩阵证明底层判断；不得把该底层证据写成 C2 三类端到端通过，也不得冒充 A1 或业务消费者；
14. 外部关系闭合后以新代次 / 新幂等身份退出因果，节点与全部自有事实同代退出，状态、动作、来源和类型仍当前；
15. 退出原请求重复返回首次载荷，同键改闭包幂等冲突；当前单项已退出，三条件组不含该因果，退出前历史完整，退出截止及之后历史仍为已读取并带完整退出生命周期；
16. 错合同、零期望 / 幂等 / 身份、已退出因果、新键旧期望和发布后原请求收敛取得精确状态；提交前非成功均零变化；
17. `std::barrier` 同起步、固定最大轮数、无 sleep 的四类写者与单项 / 三条件读者并发，只接受完整同截止成功、许可、漂移或已退出，不接受空条件 / 结果、部分关系、双当前来源、混代或内部不一致；
18. 根工程 Debug / Release x64、临时项目双配置、strict、UTF-8、工程隔离、范围与临时生命周期检查通过。

v0.4 不接受把多条未逐叶断言的行为合并成一个粗检查；上述 1—18 继续有效，并按以下直接运行账逐项落入专项输出和验证记录：

1. **状态组替换与三查询**：条件替换前后分别读取条件、动作、结果三类当前查询，证明旧条件端点移除、新端点加入且另两查询不变；结果替换前后证明结果查询变化、条件 / 动作查询不变，并分别读取结果替换前 / 后完整历史。
2. **状态组拒绝叶**：当前组原样提交；旧闭包缺项、错项、多项；新组为空、零顺序、零目标、重复、未严格升序、超过 `0x0FFF`，逐项结构化非成功并证明零推进。wrong-family、v1 legacy、裸 L1、同 owner 无状态来源四类端点分别经状态公开身份来源拒绝，C2 原样映射。
3. **状态组幂等**：原请求立即重复和后继代次重复均返回首次载荷；同一幂等身份分别改变角色、新组、旧闭包均返回幂等冲突且零推进。
4. **动作替换与查询 / 历史**：空到有、有到异值、有到空三种写各自推进一代；每步直接读取动作当前查询和替换前 / 后完整历史，证明条件 / 结果 / 来源不变。空到空、同动作、旧关系形状或编码不符、动作节点未找到 / 已退出 / 非普通逐项返回精确状态。原请求立即 / 后继重复返回首次可选关系；同键改旧关系、改新动作分别幂等冲突。
5. **来源换代**：不同来源与同来源新版本都直接证明新值、旧值退出、槽唯一、材料和值来源；错旧值引用冲突；新来源未找到、已退出分别同名非成功；原请求立即 / 后继重复返回首次新旧值，同键改新来源幂等冲突。
6. **退出请求与三查询**：闭包分别漏、错、多族归属 / 条件 / 动作 / 结果 / 来源值；闭包含零、重复、未升序、含因果节点逐项运行。退出成功后当前单项为已退出，条件 / 动作 / 结果三类当前组均排除该因果；退出前、退出截止和更晚历史逐字段完整；原请求重复与同键改闭包分别精确重复 / 幂等冲突。
7. **四公开入口共同参数与漂移**：状态组、动作、来源、退出四入口分别运行错合同、零期望、零幂等、零因果身份、已退出因果和新键旧期望；每项非成功载荷为空，提交前失败零变化。同键异义必须按第 3—6 项分别命中四入口，不得只用一个入口代表。
8. **外部引用分账**：继续直接运行跨 owner 关系的建立、C2 退出阻断、外部 owner 关闭和新代次 / 新幂等退出；所属值、值来源、独立材料三类仍只绑定第 13 项具名 L1 七角色证据，并明确未在 C2 因果专项直接触发。
9. **四个独立并发窗**：分别以状态组替换、动作替换、来源换代、退出为唯一写者，各自配一个当前完整单项读者与条件 / 动作 / 结果三个当前查询读者；每窗使用独立当前因果夹具、`std::barrier` 同起步、固定最大轮数、无 sleep、无失败重试。逐次只接受同截止完整成功、许可拒绝、事实代次漂移或退出窗允许的已退出；资源失败若实际发生立即计数且最终必须为零，内部不一致、空条件 / 结果、部分关系、双来源、混代、重复身份均必须为零。竞争后以最新静止截止直接证明目标写的唯一完整终态。

功能、非法、幂等、查询、历史和并发九组全部能从现有公开入口合法构造，必须由 C2 专项 Debug / Release 直接端到端运行；不得绑定 C1、T2、DYN2 或编译结果替代。C2 公开面没有资源故障注入和私有损坏入口，因此发布后代次探测资源失败、owner-aware 许可 / 资源及成功坏形状只允许绑定既有 L1 公开 / Debug 故障证据与 C2 生产穷尽映射静态闭包；验证记录必须明确这些状态未在 C2 端到端注入，不得写成 C2 运行通过，也不得为补证增加友元、生产钩子或测试夹具入口。

验证完成声明必须分账：已直接证明因果被合法跨 owner 关系引用时 C2 透传 `引用冲突`，以及外部关系闭合后因果成功退出；由 L1 通用专项证明底层关系三角色和值四角色判断；未直接证明因果专项对所属值、值来源和独立材料三类的端到端触发。未覆盖因果真实性、必然性、主动 / 被动、动作成立 / 执行、动态证据、概率、模板、业务用途、A1、生产装配、真实消费者、长期公平、真实分配失败、私有损坏、恢复、跨进程或独立集成验收。
