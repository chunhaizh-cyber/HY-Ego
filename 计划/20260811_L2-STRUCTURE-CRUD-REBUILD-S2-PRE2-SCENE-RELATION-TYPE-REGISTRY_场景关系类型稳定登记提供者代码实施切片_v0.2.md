未加载，线程汇合后只以完全相同原请求再次调用，依靠同一 L1 幂等键的
`精确重复` 和正式一致当前投影读回收敛同一定位。

## 3. 目标、范围和完成条件

目标不变：由唯一 `L2场景结构服务` 使用私有幂等域 `0x1D`、固定登记身份 `{1}`
和两个具名本地键，一次 L1 中性写集建立父子 / 成员两个普通关系类型节点；稳定编码
只取自新编码映射，每次成功返回前经 L1 一致当前投影正式读回。

完成条件按以下精确语义替换 v0.1 第 1 节第 3、4、7 项和第 6.1 节并发末段：

1. 顺序首次建立必须返回 `已提交`；完整原请求重复必须返回 `精确重复`；二者成功时
   均携带正式读回后的同一完整登记。
2. 两个新服务实例在隔离的新 L1 上并发提交相同完整原请求时，L1 权威事实只发布一次，
   两节点编码唯一、互异且当前代次只推进一次。
3. 并发首调允许出现两种公开结果形状：`已提交 + 精确重复`，或一个成功结果加一个
   `许可拒绝`。`许可拒绝` 必须截止 0、登记为空、服务实例保持未加载；不得伪装成
   资源失败、内部不一致或成功。
4. 首调许可拒绝的实例在线程全部汇合、没有验证者并发写后，只能重交相同合同版本、
   规则版本、固定身份和首次期望事实代次的完整原请求；该次必须由 L1 返回精确重复，
   正式读回同一两编码后返回 `精确重复` 并加载定位，当前代次不推进。
5. 并发收敛不是换键重试、写入重放或读取函数内部重试。不得改变期望代次、幂等身份、
   写集、本地键或服务对象；不得 sleep、轮询、无限重试或增加全局 / 静态 / 跨实例锁。
6. 事实代次漂移仍只按 v0.1 执行一次完整重读；许可拒绝不消耗该漂移重读额度，也不在
   `按定位读取当前场景关系类型登记` 内自动重试。
7. 其它完成条件不变：新实例未加载与精确重复重建、错请求零重复创建、代次前进后
   一次漂移重读、节点异常、稳定编码非硬编码、Debug / Release 主工程及双配置外验。

服务实现必须保持：

```text

         -> 恰一次调用私有正式读取辅助 -> 完整成功才保存定位
许可拒绝：返回许可拒绝/截止0/空登记 -> 不保存候选定位；已有定位原样保留
后继收敛：调用方稍后对同一服务对象重交完整原请求
         -> L1精确重复/原映射 -> 正式读回 -> 保存并返回同一定位
当前读取：锁内深复制定位 -> 锁外正式读取；许可拒绝立即向上送出
漂移读取：只允许按 L1 回显实际代次完整重读一次
```

`yield`、sleep、忙循环或验证专用生产入口。跨实例互斥会把独立 L1 实例无谓串行，
并用第二协调状态掩盖正式 `许可拒绝`；不属于本叶所需最小事实。

## 5. 状态与重试边界

| 阶段 | 允许状态 | 定位 | 事实代次 | 后继 |
| --- | --- | --- | --- | --- |
| 顺序首次建立并读回 | 已提交 | 加载 | 推进一次 | 可读取 / 原请求重复 |
| 完整原请求重复并读回 | 精确重复 | 加载 | 不推进 | 可读取 |
| 新实例提交后读回许可竞争 | 许可拒绝 | 保持未加载 | 本次提交若为首次则权威可能已发布，但结果截止为 0 | 只能稍后重交完整原请求 |
| 已加载实例重复提交后读回许可竞争 | 许可拒绝 | 保留原定位 | 不推进 | 调用方以后重交完整原请求或重新读取 |
| 许可竞争后的原请求收敛 | 精确重复 | 加载 | 不推进 | 可读取 |
| 已加载当前读取许可竞争 | 许可拒绝 | 保留原定位 | 不推进 | 调用方以后重新读取 |
| 首轮事实代次漂移 | 漂移后一次完整重读 | 不改保存定位 | 不写 | 第二次仍漂移则返回漂移 |

`许可拒绝` 是一次非阻塞读取没有取得共享许可，不表示 L1 提交失败或事实不存在。
服务不得在失败结果中携带未正式读回的候选登记。调用方收敛使用相同公开建立函数，
因此仍受原 L1 幂等账、完整请求比较和一次写集恰一次提交合同约束。

## 6. 生产外验证矩阵修订

v0.1 第 8.2 节第 1—3、5—9 项保持不变；第 4 项替换为：

1. 在隔离的新 L1 上建立两个新场景服务对象，以同一完整原请求并发调用后 join；
2. 读取公开 L1 当前代次，必须恰为首次期望代次加一；两个普通关系类型节点必须完整、
   编码非零互异，不得观察第二次发布；
3. 初始结果若均成功，必须恰为一项 `已提交`、一项 `精确重复`，两登记核心相同；
4. 初始结果若有许可拒绝，只允许恰一项，且该项截止 0、登记为空、直接读取仍为
   `登记未加载`；另一项必须成功并携带完整登记；
5. join 后对许可拒绝的原服务对象恰一次重交完整原请求，必须返回 `精确重复`、正式读回
   完整登记并加载定位；其两编码 / 建立代次与成功实例相同，L1 当前代次仍不推进；
6. 任一其它状态、两项许可拒绝、许可拒绝后改变请求、收敛仍许可拒绝 / 漂移 / 失败、
   编码不一致或代次二次推进均为 FAIL。

外验不得通过 sleep 扩大时序窗口，不得访问 L1 / L2 私有锁或幂等账。并发项证明的是
公开非阻塞结果与原请求收敛合同，不证明公平调度、长时间竞争或生产编排自动重试。
