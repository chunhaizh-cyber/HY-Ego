# CURRENT-SNAPSHOT-A2B-COMPOSITION 持久封存组合首片 v0.1

基于 14caccec3、[当前事实持久启动详细设计](../规范/详细设计/20261128_CURRENT-SNAPSHOT-STARTUP_当前事实持久启动详细设计_v0.1.md)、4070 §3–5/8、4015 §14–15 与 CODE-FILE-01 §6.5。本交互窗口独占代码与发布。本片只接底座现有封存组合的候选与持久运行包，维持普通宿主和现有业务写门。

## 合同

运行包 `封存追加` 只用现有封存正规化，镜像不写。由运行包独占生成一个进程内组合封存标识；同包不同视图共享，另一包或新进程必须重新取得，不作为跨启动业务身份。 `提交追加(预期视图, 已封存片段组)` 先以同一非阻塞提交资格判定未决和视图身份。已有数据集才允许追加。私有候选复制运行包当前的三组权威、六个索引和分配高水位，持包封存标识，调用现有 `原子追加封存片段组` 合并、复核现场预期并取得预分配回执。现有底座锁在返回时均已释放；片段所有者不得跨本入口持有仓库锁。本片不修改全局数据集 API 或现有锁序。

组合拒绝经 `结构拒绝` 携原结构状态，无回执也无磁盘写。成功候选从原三组编码产生 P1 输入；按数据集身份、高水位及旧码保护校验，零变化不提交。冻结不可变视图；持久存储提交成功后才由运行包统一一次无抛出交换。只向成功或零变化返回既有正式组合回执；发布结果未知或其他失败一律无回执。发布未知封住该会话后续写入，旧内存视图保留，结果只可在新会话重读确认。运行包原整快照提交与封存组合共用实际发表入口和资格。

允许修改 `核心/基础数据集.持久运行包.h/.cpp`、`核心/基础数据集.持久存储.h`、`业务/自检.当前快照存储.cpp` 和专属验证记录。普通装配、世界/特征 owner、真实存储、第一组及其它工程文件均不改。

## 验证与结束边界

正式 Release x64。具名受控临时目录使用实际现存自检入口。验证真实封存片段组合、旧预期与错误片段拒绝、同组候选新增编码回执、当前内容和独立重启读回；物理阻断清单的替换权限以取得真实发布未知，分别读回旧内存、空回执、同会话停止、清单所指结果和重新启动，撤阻后再走合法提交。无权限回执不宣称业务登记。后继仍须接正式服务 owner、认证原认知跨重启来源并保留 A→B 后重提 A 的原回执；A3 还要重绑真实上层所有者并复核，不允许跳过。
