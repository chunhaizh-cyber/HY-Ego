# 存在概念两组定义提供者代码实施计划

身份：`EXISTENCE-CONCEPT-DEFINITION-PROVIDER-REBUILD`

版本：v0.4

状态：可执行

原开工基线：`8a7ba623`；本次重新 S0 基线：`23db3c5d`（`c433ebc9` 已发布 v0.3 两组提供者，`23db3c5d` 保存专项验证发现的本计划内结构登记漂移）

## 1. 目标与完成条件

按同名详细设计 v0.4，将概念 owner 的旧 D/O/R 完整存在概念 ABI 整体替换为“自身 FT→FC 值域组 + 已知子 EC 组”的定义提供者。完成以新 ABI、12 项独立结构登记、完整有界读取、精确创建/复用/读回和旧生产符号零残留为准；不实现世界树的最具体选择或归纳。

## 2. 正式依据与前置

依据是 2220 v1.22、7100 v2.0、7110 v2.0、4240 v0.42 与同名详细设计 v0.4。L1 有界 owner 关系/事实/属性读取已存在，无额外 L1 provider 依赖。本计划不依赖 `INSTANCE-FEATURE-IF-R-CONCEPT-FOUNDATION`；后者也不得把本计划的两组定义 provider 当作 IF/R ABI 或 R→FCr 汇聚的替代。

`8a7ba623` 已发布唯一只读的 `特征值域比较数据服务`：其 I64 路径真实复用同截止域/包含；I64组、U64组及独立材料引用均具有同一公开入口、声明和紧邻定义的“待实现”标识，并以 `未实现`/`规则缺失`、零写入、零成功载荷收束。4180 v0.13 §5.2 因而已闭合详细设计 §9 的四项提供者合同；4240 §12 的非 I64 仍不允许本计划收窄为 I64-only，且结构化失败必须阻止定义发布，不能被误作匹配成功。非 I64 的真实专用适配器不属于本计划。

执行 S0 必须重新核对：本计划及详细设计 v0.3、`8a7ba623` 的比较服务头/源/工程登记、现行四份正式依据、`概念族锚点→成员` 关系及当前 L1 读取接口、所有旧符号命中、计划索引、占用表、Git/index 和其他写入者。正式依据或真实接口漂移时停止本切片并退回计划支撑。

## 3. 允许与禁止范围

允许：

- `海中鱼巣/领域/合同.相关概念添加参与.h`
- `海中鱼巣/领域/数据服务.概念树类.h`
- `海中鱼巣/领域/数据服务.概念树类.cpp`
- 旧完整存在概念符号实际命中的 `海中鱼巣/装配.普通应用.cpp`、`海中鱼巣/业务/计算.二次特征.h`、`海中鱼巣/领域/数据服务.特征类.h/.cpp`
- 必需工程登记和本计划专属施工/验证记录。

禁止：L1 ABI、正式规范、世界树/存在类的首次形成编排、特征比较算法、IF/R、主动归纳策略、启动线程、`.ixx`、测试语义以外的无关迁移。

## 4. 施工步骤

1. 在合同头删除所有旧 `完整存在概念*`、D/O/R DTO、旧 pure variant 和结构登记 DTO；按详细设计 §3 建立 v3 两组 DTO、预算、状态、请求、结果和完整事实。两个组的“已完整声明”标志是空组合法性的唯一值式见证；所有比较默认值式相等，不暴露 L1 owner/端口。
2. 修复 v1 两组结构登记，保持固定 6 节点、5 类型登记关系、1 格式值。`C→D` 使用“两组定义成员”，`D→IFItem` 使用“自身特征值域项”，`IFItem→FT/FC` 分别使用两个自身项类型，`D→子EC` 使用“已知子存在概念”；五个新类型均进入每项实际写集。严格执行详细设计 §4.1：首次性只按 `{owner, 原幂等键}` 的首次材料裁决；该键未找到且 `G0` 对齐时直接提交独立 12 项写集，绝不调用 owner 空域读取或把已登记 pure v2/特征概念出生使用误作旧格式。仅同键同规范化写集重放为精确重复，异写集为幂等冲突；pure v2 交付另行核验其真实同 owner 布局，预算不进入首次写集；发布未知保留原请求，首次材料形状确实不受 v1 识别时才报旧格式不支持。
3. 替换概念树构造交付和私有布局：实现规范化、锚点成员有界枚举、逐候选完整展开、精确查询、创建/复用、读回、定义引用保护和状态映射。删除旧“存在概念必须有直接上位”的诊断；空上位合法。
4. 删除旧 D/O/R 物理写集、读回、注册、辅助函数和所有旧符号消费者。消费者不能构造完整两组时，删除旧功能路径并保留结构化能力缺失/旧格式不支持，不添加兼容层。
5. 以当前真实调用点核对构造/装配需要；只有工程未自动编译已存在 `.cpp` 时才最小修改工程。写施工记录，逐项列明旧符号删除、替代入口、实际未覆盖范围和知识变更清单。旧 D/O/R 的物理删除必须先覆盖 `合同.相关概念添加参与.h:729` 的不可比较默认比较式，再以**同一实际基线**编译已发布的 `数据服务.特征值域比较类.cpp` 与本计划的新概念定义实现；不得单独把比较服务 WIP 的既有阻断称为已验证。

若 `8a7ba623` 的上游 ABI 在执行 S0 中缺失或与 4180 §5.2 漂移，步骤 1--5 不得开始；不得为使其可编译而新建 I64-only DTO、骨架、非 I64 降级分支或对现有 ABI 作未经裁决的扩展。

## 5. 失败收口

入口、引用/类别、规范化、预算、L1 状态、代次、幂等、读取完整性和发布未知均按详细设计 §3/§5 的专属状态返回。任何非成功不得写入部分定义、概念边、来源、支持或世界事实；发布未知只保留原请求以原键续行。候选读取错误不允许映射为零候选或新建。

## 6. 验证与发布

运行 `git diff --check`、`python .\tools\check_specs.py --strict`，对本切片运行全量旧符号 `rg` 零命中检查，并按当前工程进行 Debug/Release x64 编译。两配置均须从包含 `8a7ba623` 比较服务的同一实际基线到达其翻译单元及本计划翻译单元；旧 D/O/R 删除后若仍先失败，记录首个真实错误并按范围修复或退回。最小专项验证覆盖详细设计 §7 的八类场景，且必须首先在同一 owner 顺序成功登记 pure v2、特征概念出生使用和两组结构；后者的首次成功、原键精确重放、异请求幂等冲突均不得依赖 owner 空域。若环境或异主 WIP 阻断，保留证据并不修改对方文件。

仅在验证后取得发布租约，精确暂存本计划允许文件和专属记录，普通提交并推送。提交不证明世界树闭环、主动归纳、恢复、运行或业务验收。

## 7. 完成声明

计划完成后可向世界树后继提供“已裁决两组定义”的 DATA-L2 创建、精确查询、候选读取和完整读回能力。世界树必须另行设计特征实际值/FC 域比较、唯一最具体选择和先概念后实例；它们不是本计划的隐含产物。

当前前提已满足：`8a7ba623` 提供统一值域比较 ABI 和安全非 I64 未实现收束。本计划开始后仍不证明非 I64 比较成功、世界树闭环、主动归纳、恢复、运行或业务验收。
