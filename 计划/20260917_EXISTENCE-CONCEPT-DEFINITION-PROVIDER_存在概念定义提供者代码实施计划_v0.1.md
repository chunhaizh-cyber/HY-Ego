# 存在概念两组定义提供者代码实施计划

身份：`EXISTENCE-CONCEPT-DEFINITION-PROVIDER-REBUILD`

版本：v0.8

状态：待激活；直接上游 `FEATURE-DOMAIN-COMPARISON-BINDING-ABI` 已由 `0e8e2db9` 发布，但旧 pure 消费者迁移与退出合同尚未冻结。

原开工基线：`8a7ba623`；v0.8 重新 S0 必须以含直接上游发布提交 `0e8e2db9` 的当前正式 HEAD 为基线（`c433ebc9` 已发布 v0.3 两组提供者，`23db3c5d` 保存专项验证发现的本计划内结构登记漂移）。

## 1. 目标与完成条件

按同名详细设计 v0.7，将概念 owner 的旧 D/O/R 完整存在概念 ABI 整体替换为“自身 FT→FC 值域组 + 已知子 EC 组”的定义提供者。完成以新 ABI、12 项独立结构登记、完整有界读取、精确创建/复用/读回和旧生产符号零残留为准；不实现世界树的最具体选择或归纳。

## 2. 正式依据与前置

依据是 2220 v1.22、7100 v2.0、7110 v2.0、4240 v0.42 与同名详细设计 v0.7。L1 有界 owner 关系/事实/属性读取已存在，无额外 L1 provider 依赖。本计划不依赖 `INSTANCE-FEATURE-IF-R-CONCEPT-FOUNDATION`；后者也不得把本计划的两组定义 provider 当作 IF/R ABI 或 R→FCr 汇聚的替代。

`8a7ba623` 已发布唯一只读的 `特征值域比较数据服务`：其 I64 路径真实复用同截止域/包含；I64组、U64组及独立材料引用均具有同一公开入口、声明和紧邻定义的“待实现”标识，并以 `未实现`/`规则缺失`、零写入、零成功载荷收束。4180 v0.13 §5.2 因而已闭合详细设计 §9 的四项提供者合同；4240 §12 的非 I64 仍不允许本计划收窄为 I64-only，且结构化失败必须阻止定义发布，不能被误作匹配成功。非 I64 的真实专用适配器不属于本计划。

比较服务构造时已只读依赖概念树，故不得把它作为概念树的成员或构造参数反向注入。v0.5 曾发现公开 ABI 只有构造与三项读取/核验函数，私有引用不可访问；`Gread/H` 只表示某个 L1 的代次，不能证明与概念 owner 同一基座。因此本计划不允许以同截止读取代替绑定核验。

直接上游 `FEATURE-DOMAIN-COMPARISON-BINDING-ABI` 已由 `0e8e2db9` 完成：`数据服务.特征值域比较类.h/.cpp` 已发布 `bool 绑定于(const L1事实基座服务&) const noexcept`，且既有公开 `特征值域比较预算_v1` 固定承载值与材料预算、概念预算和最大域项数；专项矩阵证明任一单项或双项混用 L1 均为 false 且零事实写入。本计划五个两组入口调用期接收 `const 特征值域比较数据服务&` 与 `const 特征值域比较预算_v1&`，先执行 `绑定于(l1_)`，false 映射`入口拒绝`与零载荷，true 才以原样比较预算对每项 `FT→FC` 调用统一值域读取。两组预算不复制或默认填造比较预算。该决定不新增机器字段、owner、事实或规则，也不需要新的上游计划。

直接上游条件已经满足。执行 S0 必须重新核对：本计划及详细设计 v0.7、上游精确提交 `0e8e2db9` 及比较服务头/源/工程登记、`特征值域比较预算_v1` 的三段实际字段、现行四份正式依据、`概念族锚点→成员` 关系及当前 L1 读取接口、所有旧符号命中、计划索引、Git/index、目标文件实际 WIP、活动切片及构建资源。正式依据或真实接口漂移时停止本切片并退回计划支撑；文件占用表不再是门禁或检查项。

## 4. 施工步骤

1. 在合同头删除所有旧 `完整存在概念*`、D/O/R DTO、旧 pure variant 和结构登记 DTO；按详细设计 §3 建立 v3 两组 DTO、预算、状态、请求、结果和完整事实。两个组的“已完整声明”标志是空组合法性的唯一值式见证；所有比较默认值式相等，不暴露 L1 owner/端口。
2. 修复 v1 两组结构登记，保持固定 6 节点、5 类型登记关系、1 格式值。`C→D` 使用“两组定义成员”，`D→IFItem` 使用“自身特征值域项”，`IFItem→FT/FC` 分别使用两个自身项类型，`D→子EC` 使用“已知子存在概念”；五个新类型均进入每项实际写集。严格执行详细设计 §4.1：首次性只按 `{owner, 原幂等键}` 的首次材料裁决；该键未找到且 `G0` 对齐时直接提交独立 12 项写集，绝不调用 owner 空域读取或把已登记 pure v2/特征概念出生使用误作旧格式。先用同一端口、同一 `G0` 从 L1 真实读回并重建 pure v2 的完整物理布局；伪造、跨 owner、退役或形状不符的交付均不得进入写集。仅同键、同规范化写集、同原 pure 交付重放为精确重复，异写集或 pure 交付不相等均为幂等冲突；预算不进入首次写集；发布未知保留原请求，首次材料形状确实不受 v1 识别时才报旧格式不支持。
3. 替换概念树构造交付和私有布局：实现规范化、锚点成员有界枚举、逐候选完整展开、精确查询、创建/复用、读回、定义引用保护和状态映射。五个两组入口以调用期比较服务引用和同一 `特征值域比较预算_v1` 引用先执行已发布的 `绑定于(l1_)`，false 固定返回`入口拒绝`与零载荷，true 才原样传递预算并核验每个 `FT→FC`；不得从两组预算推导比较预算。概念树不持有比较服务或比较预算，头前置声明、源文件包含比较头。独立拒绝同 FT、同 FC、同 EC；每一个两组入口和私有读取链先同时防护 `pure_layout_`、`two_group_definition_layout_` 两个 optional，缺任一个返回旧格式不支持、零载荷。删除旧“存在概念必须有直接上位”的诊断；空上位合法。
4. 删除旧 D/O/R 物理写集、读回、注册、辅助函数和所有旧符号消费者。消费者不能构造完整两组时，删除旧功能路径并保留结构化能力缺失/旧格式不支持，不添加兼容层。
5. 以当前真实调用点核对构造/装配需要；普通应用固定按“owner 端口→pure v2登记及真实读回→出生使用登记及真实读回→两组登记及真实读回→移动端口构造概念树→构造比较服务→调用期传入比较服务及完整比较预算”的顺序，逐步刷新 `G0`。调用方负责提供完整的 `特征值域比较预算_v1`，概念树不保存它。只有工程未自动编译已存在 `.cpp` 时才最小修改工程。写施工记录，逐项列明旧符号删除、替代入口、实际未覆盖范围和知识变更清单。旧 D/O/R 的物理删除必须先覆盖 `合同.相关概念添加参与.h:729` 的不可比较默认比较式，再以**同一实际基线**编译已发布的 `数据服务.特征值域比较类.cpp` 与本计划的新概念定义实现；不得单独把比较服务 WIP 的既有阻断称为已验证。

若执行 S0 中缺失 `0e8e2db9` 发布的绑定 ABI、或其与 4180 §5.2 漂移，步骤 1--5 不得开始；不得为使其可编译而新建 I64-only DTO、骨架、非 I64 降级分支或对现有 ABI 作未经裁决的扩展。

## 5. 失败收口

入口、引用/类别、规范化、预算、L1 状态、代次、幂等、读取完整性和发布未知均按详细设计 §3/§5 的专属状态返回。任何非成功不得写入部分定义、概念边、来源、支持或世界事实；发布未知只保留原请求以原键续行。候选读取错误不允许映射为零候选或新建。

## 6. 验证与发布

运行 `git diff --check`、`python .\tools\check_specs.py --strict`，对本切片运行全量旧符号 `rg` 零命中检查，并按当前工程进行 Debug/Release x64 编译。两配置均须从包含 `0e8e2db9` 比较服务绑定 ABI 的同一实际基线到达其翻译单元及本计划翻译单元；旧 D/O/R 删除后若仍先失败，记录首个真实错误并按范围修复或退回。最小专项验证覆盖详细设计 §7 的八类场景，必须从干净源码快照可复跑，并随验证记录保存驱动、命令、退出码和结构化断言输出。必须在同一 owner 顺序完成 pure v2 真实读回、特征概念出生使用真实读回、两组结构真实读回；后者的首次成功、原键精确重放、异请求幂等冲突均不得依赖 owner 空域。必须额外覆盖伪造 pure、跨 owner pure、同 FC 重复、旧构造缺两组 layout、零/不足比较预算的入口拒绝及“比较服务由另一 L1 构造而五个两组入口在域读取前返回入口拒绝”的结构化拒绝。若环境或异主 WIP 阻断，保留证据并不修改对方文件。

仅在验证后取得发布租约，精确暂存本计划允许文件和专属记录，普通提交并推送。提交不证明世界树闭环、主动归纳、恢复、运行或业务验收。

## 9. v0.8 具名设计漂移

2026-09-18 的当前源码 S0 已确认旧 pure 存在定义不只由本计划允许文件的概念树和普通装配消费：世界树 v4 请求、查询、创建和恢复路径仍持有 `纯概念定义`；自我形成固定建立旧通用存在定义；`数据服务.绑定存在.h` 的请求、恢复和投影也返回旧 pure 合同。当前计划禁止世界树/存在类首次形成编排，因而不能在本切片中删除这些消费者，也不能以兼容分支绕过它们。

计划支撑必须先形成同一正式 HEAD 的前置迁移裁决：逐项列出这些生产消费者及唯一 owner，冻结每项的两组定义替代或历史读取/删除合同、结果状态和迁移顺序，并与 `WORLD-TREE-STRUCTURE-B` 的 `.h/.cpp` 重设计确定共享概念树和普通装配的所有权。该前置设计须给出新生产旧符号零命中范围、两组读写、历史恢复和定义引用保护的验证矩阵。前置结果发布后，本计划才可重新 S0；不得把 IF/R 当作此缺口的上游。
