# 存在概念两组定义提供者代码实施计划

身份：`EXISTENCE-CONCEPT-DEFINITION-PROVIDER-REBUILD`

版本：v0.2

状态：待激活（等待通用非 I64 特征值域核验/比较提供者合同）

基线：`f7390cc9`

## 1. 目标与完成条件

按同名详细设计 v0.2，将概念 owner 的旧 D/O/R 完整存在概念 ABI 整体替换为“自身 FT→FC 值域组 + 已知子 EC 组”的定义提供者。完成以新 ABI、12 项独立结构登记、完整有界读取、精确创建/复用/读回和旧生产符号零残留为准；不实现世界树的最具体选择或归纳。

## 2. 正式依据与前置

依据是 2220 v1.22、7100 v2.0、7110 v2.0、4240 v0.42 与同名详细设计 v0.2。L1 有界 owner 关系/事实/属性读取已存在，无额外 L1 provider 依赖。本计划不依赖 `INSTANCE-FEATURE-IF-R-CONCEPT-FOUNDATION`；后者也不得把本计划的两组定义 provider 当作 IF/R ABI 或 R→FCr 汇聚的替代。

但本计划依赖一个尚未冻结的通用非 I64 特征值域核验/比较提供者：当前 `数据服务.特征类.h` 只有 I64 类型规格、`特征规范I64域`、I64 域判定和包含合同；`特征值类`可完整读出 I64、I64组、U64组或独立材料，却没有将非 I64 FC 值域与 FT 比较合同连接为“类别/完整读回/相等/包含”的同截止 ABI。4240 §12 反而明确非 I64 FC 可使用真实值或材料，故不得把此计划实现为 I64-only。详细设计 §9 的四项合同必须先由正式规范和提供者计划闭合、发布；该计划才可重新标记为可执行。

执行 S0 必须重新核对：本计划及详细设计已发布 blob、现行四份正式依据、`概念族锚点→成员` 关系及当前 L1 读取接口、所有旧符号命中、计划索引、占用表、Git/index 和其他写入者。正式依据或真实接口漂移时停止本切片并退回计划支撑。

## 3. 允许与禁止范围

允许：

- `海中鱼巣/领域/合同.相关概念添加参与.h`
- `海中鱼巣/领域/数据服务.概念树类.h`
- `海中鱼巣/领域/数据服务.概念树类.cpp`
- 旧完整存在概念符号实际命中的 `海中鱼巣/装配.普通应用.cpp`、`海中鱼巣/业务/计算.二次特征.h`、`海中鱼巣/领域/数据服务.特征类.h/.cpp`
- 必需工程登记和本计划专属施工/验证记录。

禁止：L1 ABI、正式规范、世界树/存在类的首次形成编排、特征比较算法、IF/R、主动归纳策略、启动线程、`.ixx`、测试语义以外的无关迁移。

## 4. 施工步骤

1. 待依赖发布后，在合同头删除所有旧 `完整存在概念*`、D/O/R DTO、旧 pure variant 和结构登记 DTO；按详细设计 §3 建立 v3 两组 DTO、预算、状态、请求、结果和完整事实。两个组的“已完整声明”标志是空组合法性的唯一值式见证；所有比较默认值式相等，不暴露 L1 owner/端口。
2. 新建 v1 两组结构登记，固定 6 节点、5 类型登记关系、1 格式值。`C→D` 使用“两组定义成员”，`D→IFItem` 使用“自身特征值域项”，`IFItem→FT/FC` 分别使用两个自身项类型，`D→子EC` 使用“已知子存在概念”；五个新类型均进入每项实际写集。沿既有 owner 首次材料和原键重放机制实现同 owner 核验、精确重复、冲突、可能发布与首次材料读回。
3. 替换概念树构造交付和私有布局：实现规范化、锚点成员有界枚举、逐候选完整展开、精确查询、创建/复用、读回、定义引用保护和状态映射。删除旧“存在概念必须有直接上位”的诊断；空上位合法。
4. 删除旧 D/O/R 物理写集、读回、注册、辅助函数和所有旧符号消费者。消费者不能构造完整两组时，删除旧功能路径并保留结构化能力缺失/旧格式不支持，不添加兼容层。
5. 以当前真实调用点核对构造/装配需要；只有工程未自动编译已存在 `.cpp` 时才最小修改工程。写施工记录，逐项列明旧符号删除、替代入口、实际未覆盖范围和知识变更清单。

在详细设计 §9 的上游合同没有发布前，步骤 1--5 不得开始；不得为使其可编译而新建 I64-only DTO、骨架、非 I64 降级分支或对现有 ABI 作未经裁决的扩展。

## 5. 失败收口

入口、引用/类别、规范化、预算、L1 状态、代次、幂等、读取完整性和发布未知均按详细设计 §3/§5 的专属状态返回。任何非成功不得写入部分定义、概念边、来源、支持或世界事实；发布未知只保留原请求以原键续行。候选读取错误不允许映射为零候选或新建。

## 6. 验证与发布

重新激活后运行 `git diff --check`、`python .\tools\check_specs.py --strict`，对本切片运行全量旧符号 `rg` 零命中检查，并按当前工程进行 Debug/Release x64 编译。最小专项验证覆盖详细设计 §7 的七类场景；若环境或异主 WIP 阻断，保留证据并不修改对方文件。

仅在验证后取得发布租约，精确暂存本计划允许文件和专属记录，普通提交并推送。提交不证明世界树闭环、主动归纳、恢复、运行或业务验收。

## 7. 完成声明

计划完成后可向世界树后继提供“已裁决两组定义”的 DATA-L2 创建、精确查询、候选读取和完整读回能力。世界树必须另行设计特征实际值/FC 域比较、唯一最具体选择和先概念后实例；它们不是本计划的隐含产物。

当前未完成：详细设计 §9 的非 I64 特征值域核验/比较合同尚无正式提供者，故本计划未获施工授权。
