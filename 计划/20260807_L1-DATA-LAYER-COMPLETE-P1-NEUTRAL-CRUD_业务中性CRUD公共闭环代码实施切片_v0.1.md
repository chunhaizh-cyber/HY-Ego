## 1. 目标与完成条件

按配套详细设计，在现有唯一 L1 服务和内存权威仓上实现业务中性普通 CRUD 公共闭环。本计划不迁移领域消费者；完成条件是六个代码 / 工程文件严格施工，生产 Debug / Release x64 构建通过，静态门禁通过，且代码结果具备由独立验收者在生产二进制外执行公开黑盒矩阵的条件。

代码实现发布不自动等于 L1 黑盒正确性通过；必须由后续独立验收提交给出对应结论。

## 4. 机械实施步骤

1. 新建 `L1中性CRUD.数据.h`，逐项实现详细设计第 4 节的中性 DTO、相等比较和最小有效性辅助；不得 include legacy `L1事实基座.数据.h`。
2. 新建 `合同.L1中性CRUD.ixx`，唯一导出模块与新数据头；工程和 filters 各登记一次。
3. 在仓库状态内新增同锁 `中性幂等账`，完善状态完整性和与 legacy 账交叉占用；不得新增第二当前事实、第二稳定编码分配器或第二锁。
4. 按单函数图实现唯一 `提交中性写集`；规范化、所有引用拒绝、候选、编码分配、退出 / 槽替换、幂等、最后交换和发布后读回顺序不得改变。
5. 在服务中 `export import` 新合同并实现七个公开入口；中性读取只精确调用现有仓库读取并逐字段转换，调用完整快照 / 审计 / 恢复次数为 0。
6. 对中性幂等账非空后的 legacy 恢复管理入口增加详细设计第 6 节的保守入口拒绝；不实现或宣称恢复。
7. 保持所有 legacy 公开签名和现有 16 个写调用点不变；静态确认没有新增带操作标签调用。
8. 写入两份专属记录，执行第 6 节验证；发布代码结果后由交互侧派发独立外部黑盒验收。

## 5. 失败收口

- 若新中性写入必须复制第二当前事实表、第二事实代次或第二编码空间才能实现，停止并回传 `L1-NEUTRAL-CRUD-DRIFT-SECOND-AUTHORITY`。
- 若不能在同一锁内同时保证 legacy / 中性幂等键交叉唯一和旧调用行为不变，停止并回传 `L1-NEUTRAL-CRUD-DRIFT-IDEMPOTENCY-COEXISTENCE`。
- 若现有状态完整性无法在不改领域消费者的条件下接纳中性候选，停止并回传具名字段 / 不变量，不放宽 4015。
- 若外部黑盒只能通过私有仓、friend、自检模式、日志解析或完整快照触达，验收必须 FAIL；不得增加验收专用生产入口。
- 构建错误只修复本白名单内由本计划造成的问题；需要扩展文件或改变机器语义时停止。

静态门禁：

1. 新 DTO / 合同对 `业务操作标签|意图组|领域结果|执行证据|提供者见证|审计|恢复材料` 零命中。
2. 新提交函数对完整快照、SQL、材料、日志、索引调用零命中。
3. 当前事实、事实代次、稳定编码分配器和仓库锁仍各唯一；新中性事实容器命中 0。
4. 现有 10 文件 16 个带标签写调用点内容零修改，且没有第 17 个调用点。
5. 新模块 / 数据头在工程和 filters 各唯一登记，生产工程不存在验收驱动、自检模块或第二目标。

独立外部黑盒验收严格执行详细设计第 8 节矩阵，只经七个公开入口；结果保存到 `验证记录/集成验收/`。只有其结论达到 ACCEPTANCE-01 L2，才能声明本叶的 L1 中性 CRUD 局部正确性门通过。
