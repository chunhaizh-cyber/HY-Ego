## 1. 暂停裁决

v0.1 原拟作为全仓 `.ixx -> .h / .h + .cpp` 路线的第一叶：退出四个低依赖 L1 合同模块、建立同基本名传统头、同步其消费者和工程项。

执行期已证明这个“合同孤岛”不能在“不保留任何 `.ixx` 消费者”的终态目标下独立成立。原合同以 `export import` 传递 L1 声明；若只将其替换为 global module fragment 的传统头，则仍为 `.ixx` 的服务直消费者不能获得这些声明。临时为它们加入头 include 虽能解释可达性，却继续保留八个 `.ixx` 消费者，因此既不满足终态，也不是允许的过渡施工。

本计划暂停，不得按 v0.1 或本文件进行生产、工程或验证改动；不得标为可执行或待激活。不得恢复四个旧合同 `.ixx`，也不得用兼容模块壳、global-fragment include 桥、前置声明、别名、宏或第二套 DTO 规避问题。

## 2. 具名 DRIFT 与事实

执行者在基线 `74597df7a2fefa6d5660db0ad7f681da30a667a6` 的首个隔离 Debug 构建中，把 `服务.L1事实基座.ixx` 的旧合同 `export import` 改为 global module fragment 的 `#include`。下游 `合同.存在结构身份只读.ixx`、`数据服务.特征值类.ixx` 等出现 157 个未声明 / 不可达错误。执行现场已恢复，未保留生产改动。

根因是语言可达性，不是 include 次序：global module fragment 的声明属于全局模块，不会作为服务命名模块接口向 import 者传递。v0.1 只桥接仓库、服务、状态类，遗漏五个服务模块的直接命名模块消费者。

正式依据仍是 [代码文件建立归属与模块命名规范](../规范/代码文件建立归属与模块命名规范.md) v4.0 和 [0050 项目通用机器逻辑与禁止性规则总纲](../规范/0050_项目通用机器逻辑与禁止性规则总纲_20260721.md) v3.22。它们不授权用未迁移模块作为终态消费者。
