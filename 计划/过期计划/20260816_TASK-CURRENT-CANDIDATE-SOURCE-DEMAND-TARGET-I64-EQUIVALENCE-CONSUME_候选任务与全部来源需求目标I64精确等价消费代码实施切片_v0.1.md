## 4. 实施合同

1. 从最新正式 HEAD 重做 S0，核对02、06、目标定义 provider、共享 `目标状态语义键`的真实结果 / 退出 / 清理、最终 ABI、目标文件所有权和构建资源；任一门禁不成立不得施工。

3. 新建 `任务目标等价裁决服务`；只保存一份 `const 需求目标事实提供者&`和不可变运行代次配置，不持有任何 DATA 服务、业务服务、L1、owner、仓库、写端口或缓存。
4. 在 provider 调用前完整校验请求、02 / 06 成功形状、同一运行代次 / `G0`、来源全集、入口来源和非零预算；checked 计算 `T + D`，超预算返回数量预算不足且零调用。
5. 按需求稳定身份对 D 个来源目标各恰一次读取定义，再按任务稳定身份以入口来源特征作为局部候选对 T 个任务目标各恰一次读取定义；全部调用使用同一 `G0`，零截止重选、重试或跳读。
6. `目标状态合同定义读取结果`没有请求回显，不得要求上游扩张 ABI。逐项互证结果合同 / 规则版本与本次请求一致、结果及成功材料截止等于 `G0`；材料中的目标合同 / 特征定义身份分别等于本次构造请求，比较注册身份等于合同正式引用，其余完整目标合同、特征定义和比较合同逐字段守恒。来源上下文引用冲突归内部不一致；任务上下文引用冲突归目标异义；当前引用未找到 / 已退出归内部不一致。
7. 对每个任务逐来源比较 `L2存在身份目标宿主 + L2特征定义身份 + 目标状态语义键`；合同 / 注册身份不同但完整键相同仍等价，任一键字段不同返回目标异义。
8. 全部 D+T 读取与全量互证成功后一次构造完整不可变候选并无抛出交换；任一失败清除全部局部候选，零成功前缀。
9. 精确映射当前性漂移、许可拒绝、资源失败、目标异义和内部不一致。`std::bad_alloc`、`std::length_error`映射资源失败，其它异常映射内部不一致，函数 `noexcept`且不得终止进程。
10. 不调用 `比较特征`；该函数只做目标定义的纯值精确等价，不比较实际值与目标值。03-01 后继写侧任务化闸门必须复用同一目标语义键，不能在本计划复制或实现第二套算法。
