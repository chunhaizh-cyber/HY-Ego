## 3. 机械实施

1. 新建纯值头，逐字落实详细设计第 3 节 DTO、稳定状态编号、全等和完整性函数；不引入句柄、对象版本、名称或旧类型。
2. 新建 `海中鱼巣.领域.服务.L1场景结构`，只导出构造、`创建初始场景`、`读取初始场景`。按详细设计第 5 节形成固定本地键 1—3 写集，只调用一次 L1 提交。
3. 创建入口必须先读取 P1B 登记；同代次首次请求必须核对 P1B 精确基线。代次不等时不得自行猜测重试结果，只允许 L1 幂等账裁决精确重复 / 冲突 / 漂移。
4. 成功或精确重复后，按本地键解析三个编码并调用独立读取路径；不得把写入映射、预计状态、日志或缓存直接包装成成功事实。
5. 独立读取逐项读取根、场景、属性类型、服务来源、属性、值、父关系和关系类型；统一事实截止、类型、来源、方向和顺序任一矛盾都整体失败。
6. 新建专项自检并精确实现详细设计第 8 节 12 项；工程登记三新文件，应用程序增加唯一顺序 `300`，完整自检总数从 24 改为 25。
7. 只写本计划专属施工 / 验证记录，记录 S0、精确差异、验证和未覆盖边界。

## 4. 非成功与停工

- 请求错误、登记未加载、错误世界根或同代次非 P1B 基线：入口拒绝，零提交。
- 同键异义、旧代次新键、L1 资源 / 内部错误：按详细设计稳定映射，禁止换键、第二次写入或补造事实。
- 写入已发布而独立读回漂移 / 矛盾：返回版本漂移 / 内部不一致；不回滚、不补写、不宣称成功。
- 若实现需要新增存在服务身份、改变 P1B 登记、修改 L1 API、加入运行期 / 恢复 / 状态动态 / 旧入口，或无法在七文件内闭合，停止并具名退回设计漂移。
