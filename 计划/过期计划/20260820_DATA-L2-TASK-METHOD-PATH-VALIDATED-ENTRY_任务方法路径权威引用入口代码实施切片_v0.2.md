## 4. 目标合同

### 4.1 任务模块 capability

在 `服务.L2任务结构.ixx`内完成：

1. 删除任务模块内 `L2任务方法路径结构服务`前置声明和 friend。
2. 新增不可默认构造、不可复制、可移动的 `L2任务方法路径写入能力交付`。
3. `L2任务所有者交付`新增一次性 `提取任务方法路径写入能力交付()`；无效、移动后或重复提取返回 `nullopt`。
4. 新增不可默认构造、不可复制、可移动的 `L2任务方法路径写入端口`；移动后来源失效。
5. 新增 `尝试形成L2任务方法路径写入端口(L2任务结构服务&, L2任务方法路径写入能力交付&&)`；只有 owner 精确一致、凭据未消费、任务写端口有效才成功，成功或失败均消费凭据。
6. `写入已验证任务方法路径`保持 private，唯一 friend 为同任务模块的写入端口。
7. 写入端口失效调用固定返回 `内部不一致`、零变更，不得回退到公开任务服务入口。

### 4.2 路径服务与装配

1. 路径服务构造改为接收 `const L2方法结构服务&`与 `L2任务方法路径写入端口&&`，不再持有任务服务引用。
2. 方法当前读取、内容版本比较和错误传播保持 v0.1 设计；成功分支只调用能力端口。
3. 普通应用在移动任务所有者交付前提取一次性能力交付，任务服务与方法服务形成后再绑定端口。
4. 普通应用分别映射能力交付提取失败、端口形成失败和路径服务构造失败；不提供能力或端口 getter。
5. 路径服务成员先于任务服务析构；const / non-const getter 均返回路径模块拥有的同一实体。
6. 任务筹办的路径新增继续只走路径服务，不修其它筹办缺口。

## 5. 实施步骤

1. 在执行侧现有 v0.1 WIP 上删除跨模块 friend 方案，保留已经完成的路径写入正文降私有、方法读取、普通应用 getter、调用迁移和工程登记。
2. 按第 4.1 节在任务模块建立 capability 交付、端口和 owner 绑定形成函数。
3. 按第 4.2 节改造路径服务构造与普通应用装配，确认模块依赖只有“路径 -> 方法 + 任务 capability”。
4. 修复现有 `--test-需求`测试材料的纯 C++ 初始化错误后，完成真实方法、错误版本零写、正确版本路径读回。
5. 形成函数级代码知识变更清单和 v0.2 施工 / 验证记录。

## 7. 失败收口

- capability 端口仍因模块身份无法链接：保留现场并回传新的精确修饰名，不得公开基础承载入口。
- owner 无法精确绑定或必须增加 L1 / 方法写语义：属于新设计漂移，停止受影响切片。
- 普通方法读取或路径权威读回暴露与本计划无关的既有语义缺口：记录精确状态和代次，禁止扩大到其它任务入口。
