## 1. 单一施工目标

以一份单线程代码迁移闭合：

```text
E_source + M + D_service 同 G0 互证并冻结来源绑定材料
-> 建立/复用服务根治理任务 T_root、R_root1、P1 与携带同一绑定材料的同一首包
-> T_root 多次筹办，只形成治理材料
-> self fresh 确认子目标，task owner 发布承接记录
-> 需求 owner 建立/复用普通服务子需求 D_child
-> 普通执行任务 T_exec 独立建立并多次找方法/查条件
```

## 3. 冻结实施合同

执行者必须按详细设计实现，不得临场改变以下机器语义：

- 详细设计 §3—§7 的物理文件、常量值、类型名、字段名、字段类型、枚举值、函数签名、合同版本、幂等键、完整相等和错误映射全部是冻结 ABI；禁止改名、删字段、加 optional、用别名兼容或自行增加结果分支。
- 服务请求承接只接收 `E_source + M + D_service + 适配幂等身份 + 请求身份`及冻结键；不接收任何附加承接记录。E 当前性必须由已发布`读取存在节点({G0, 当前, E})`的成功结果头、E 载荷、精确 G0 截止和无变更代次共同证明；已发布`读取存在身份来源({G0, 历史, E, G0})`只作历史来源证据。P04.2 已取消，不恢复其 DTO 或入口。E/M/D_service 在同一 G0 独立读回并互证，形成`L2服务根任务来源绑定材料`。
- `L2服务根任务来源绑定材料`必须贯穿 task owner 的`L2任务筹办信息`、P1 首次完整请求、P1 锚定首包、后续工作包和每次筹办结果消息；根治理链各处逐字段相同，普通执行任务对应 optional 固定为空。
- 同一完整请求精确重复返回首次相同的 T、R1、P1、来源绑定材料和同一统一工作包；已有不同请求的当前根治理任务返回`已有当前任务`且零写。
- task owner 提供服务根任务承接 / 复用、首次锚点读回和版本化筹办信息；执行前选择组合发布只允许普通执行任务。
- P1 只作首轮、重试和恢复锚点；只退役初次筹办推进 A1 / 筹办调用证明及专用函数、关系和读写，保留执行 / 结算合法通用治理动作结构。
- `任务筹办工作包`只有找方法 / 查条件两个强类型互斥步骤；不得 optional 拼盘。
- 来源需求只使用`L2任务来源需求关系事实 + L2需求事实 + 本轮消费快照`；条件组只使用`L2方法六项静态能力投影 + L2方法生命周期事实`，禁止裸需求身份、条件组身份或稳定编码集合替代。
- `查找任务候选方法`保持纯找方法；`查找并核验任务候选方法条件`覆盖全部已登记候选及其全部条件组。
- 两类 provider 请求必须携带`调用前任务信息版本`，其`来源事实截止G0`就是正式读回截止；worker 调用前按这两个值独立读回完整任务信息，根治理任务必须重新互证绑定材料中的 E/M/D，失败则不调用 provider。
- 每个已消费工作包恰好一条不可变消息；重投不重跑 provider 或重复补全。
- manager 只派发、独立读回，并以任务正式存在 E 调用 ARCH-L2 通用状态 owner 的现行`L2状态动态迁移请求_v2`；不增加任务私有状态提交 DTO，不同步调用 provider、不裸写状态、不选择方法。
- 筹办只产生六种阶段性业务结果；技术非成功与业务结果互斥，路径 / 实例 / 冻结 / 目标已完成 / 子目标承接不是筹办出口。
- 根治理任务完整筹办后只到`待自我确认材料`；self 确认并由需求 owner 建立普通服务子需求后，后继普通执行任务才能进入选择 / 冻结 / 现实动作。
- 仅普通执行任务的执行前选择独立 fresh 复核适用性、可用性、安全和正式成本；未知、不可比、零可用或并列最优时零选择。
- 成功选择只直接调用 5230 现行`发布任务筹办正式选择_v2`，并直接使用`读取任务方法选择_v2`、`按任务读取当前方法选择_v2`、`按筹办来源幂等身份读取正式选择_v2`收敛；未选候选不形成第二记录，不新增选择包装入口、公共 DTO 或文件。
- 根治理材料经 self fresh 确认后才可走既有任务子目标承接；普通子需求建立自己的任务，不复用根任务轮次 / 工作包 / 信息。回流不得调用旧初次筹办；新任务轮次只来自 self 正式继续决议。

## 5. 单线程机械步骤

1. **重新枚举。** 从开工 HEAD 记录所有旧 DTO、模块、函数、关系、owner 读写、import、调用、装配、工程登记和测试命中；按详细设计 §9.3 对阶段治理、执行派发、结果消费 / 轮次结算及每个传递消费者逐项确认迁移 / 保留 / 退出。
2. **按冻结 ABI 建立 task owner 新底座。** 严格实现详细设计 §3.1—§3.2 的精确 DTO、枚举、版本、签名、完整相等、幂等读回与错误映射，并按 §7 改造现行 v2 选择基础材料；来源需求、方法投影、冻结材料和状态 owner 均复用正式强类型，根任务发布选择固定拒绝。
3. **接通 6120 承接。** 用已发布的`读取存在节点`当前分支和`读取存在身份来源`历史分支（H=G0）在同 G0 互证 E、M、D_service 并冻结来源绑定材料；不恢复 P04.2。该材料逐字段贯穿任务信息、P1 首次完整请求、首包、后续包、结果消息和精确重复读回。不同请求遇已有当前任务零写；精确重复返回同 T/R1/P1/来源绑定材料/首包/G1。按存在 → task 核心 → 阶段特征 → 无动态首态 → P1 / 首包 → manager 待找方法迁移实现。
4. **建立固定筹办 ABI。** 新建固定名称的统一筹办模块，将工作包改为找方法 / 查条件互斥联合；两类请求携带调用前任务信息版本并以 G0 作为正式读回截止，纯方法查找与全候选条件核验按详细设计精确错误映射，禁止 manager 预设结果。
5. **迁移 worker。** 按“验包 → 按版本和 G0 独立读回任务信息并互证根任务 E/M/D → 单分支 provider → task owner 补全 → 独立读回 → 单消息 → 原消息重投”实现，确保互证失败不调用 provider，发布未知不形成第二消息。
6. **迁移 manager 与两类任务。** 按 §6 使用任务正式存在 E 和 ARCH-L2 通用状态 owner 的现行读取 / 迁移 ABI：根任务完成材料后只到 self 确认，普通服务子需求建立独立普通任务后才接 §7 现行 v2 选择 / 冻结。
7. **逐项迁移外围消费者。** 按 §9.3 迁移阶段治理、执行请求、运行包、自我线程 / 协议 / 回执 / 上行桥、结果消费 / 轮次结算、启动与装配；保留执行 / 结算通用治理动作及安全硬门。
8. **删除全部 E2E 并收口工程。** 在 9 个 E2E 和工程文件全部交回后，物理删除测试文件及 vcxproj / filters 登记；不新增替代 E2E，生产链仍必须保持可构建。
9. **整体退役。** 全部合法消费者已替换后，物理删除详细设计 §9.2 文件；只删除初次筹办推进 A1 / 调用证明的专用函数、关系、读写，保留执行 / 结算通用治理动作。删除旧 import、装配、工程和测试引用，不留兼容壳。
10. **编译与纠错。** 在隔离目录依次执行 Debug x64、Release x64 `/m:1` Rebuild；本切片内编译、链接、import 和工程登记错误修至通过。
11. **非 E2E 专项/黑盒验证与记录。** 执行详细设计 §11 矩阵，从生产入口观测结构化结果、权威终态和独立读回；验证材料只放在仓库外隔离目录，不建立或恢复 E2E 代码。保存旧符号扫描、编译输出、未验证范围及精确 diff；运行 `git diff --check`。

步骤 9 不能提前到新消费者接通之前。最终提交必须同时包含替代链和物理删除，不能提交不可编译中间状态，也不能用兼容层分两次发布。
