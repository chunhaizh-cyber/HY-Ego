## 4. 机械实施顺序

1. 建立中文 DTO、固定角色/五幂等身份、完整性函数、严格成功形状与 provider 模块；禁止导出 owner、仓库、锁或内部请求账。
2. provider 只保存 A1 引用、发布锁、已锁定请求、五份 optional 首次完整 L2 请求和值式已发布材料；禁止缓存一步结果或身份。
3. 每次先经 A1 同实例 R1 重新读取登记与整树，逐字段互证 I2 材料；异请求在任何 DATA 写前冲突。
4. 第一请求不存在时先正式读取固定单例角色；只有未找到才保存并提交角色化存在完整请求，已有外部绑定零写拒绝。第一请求已保存时原样重放；每次写成功后都以本次写结果 `结果头.事实截止代次` 作为读请求期望事实代次正式读角色，并要求读回截止相等，不得复用写前 R1 截止。
5. 严格按“角色化存在 -> 根下所在场景 -> 所在场景成员 -> 所在场景下内部世界 -> 内部世界宿主”保存并原样重放五个完整请求，从本次正式返回重新取得中间身份。
6. 严格按详细设计 5.1 的十四种 `L2结构状态` 机械映射；每步只接受已提交/精确重复及完整成功形状，坏成功形状为内部不一致。后步失败不回滚、不退出、不换键。零变化且无首次结果的事实代次漂移在一次调用内最多同键重组一次；资源失败、异常和未知发布保留原请求。
7. 五步完成后在共同当前事实截止重读整树、角色、存在、两场景、成员和宿主正反向，完成拓扑、唯一性、自包含和同截止互证；完整候选后一次无抛出交换。
8. 普通应用在 A1 聚合后唯一构造 provider，增加 const/non-const getter和连续装配失败状态24；不得创建虚构 I2 适配器对象。
9. `运行普通程序` 使用本次 I2 成功材料形成固定 SELF-FORM 请求并调用 provider；真实失败映射17，成功固定进入阶段18能力未实现。保持15缺号、16语义不变。
10. 工程登记两个生产文件与三件临时专项；生产模块不得包含测试宏、故障钩子、计数器、sleep、友元、访问器、替代 provider或验证分支。

## 5. 验证矩阵

| 类别 | 必须覆盖 | 结论边界 |
| --- | --- | --- |
| 请求/选择 | 版本、I2坏形状、零/重复幂等身份、异请求首写前冲突 | 零 DATA 写，旧发布值守恒 |
| R1重读 | 每次重读登记与整树；树/根/根标记漂移 | 不用缓存或上次结果补齐 |
| 第一角色步 | 未找到首次建立、同请求精确重复、外部已有绑定、冲突后补读、写后按本次写截止读角色 | 外部角色不得被接纳为自我；写/读截止必须相等，不得复用写前R1截止 |
| L2状态映射 | 十四种 `L2结构状态` 在角色预读、五写、写后互证、最终读回和R1重读中的逐项映射 | 非成功负载为空；坏成功形状固定内部不一致，执行者不得临场归类 |
| 五步中断 | 每一步成功后令下一步结构化失败，再次调用从第一步原请求重放 | 已发布前步不回滚、不换键 |
| 漂移/未知 | 零变化漂移同键重组；资源失败/未知发布原请求重放 | 无法公开触发的分支记NOT_RUN |
| 拓扑 | 根->所在场景->内部世界；成员与宿主分账；宿主正反向一致 | 自我不是内部世界成员，无自包含环 |
| 共同截止 | 树、角色、存在、两场景、成员、宿主同一非零截止 | 任一混代整体非成功、空新负载 |
| 重复/并发 | 同请求串行精确重复仍完整重读；异请求零后继写 | provider锁不取得DATA事实权 |
| 阶段链 | I1失败14、I2失败16、SELF-FORM失败17、成功后固定18 | 15永久缺号；阶段18后继NOT_RUN |
| 生产隔离 | 旧完整自我/P61/P62/关系21零生产引用；零验证实体 | 不恢复旧兼容链 |

必须运行：

1. 根工程 x64 Debug/Release fresh Rebuild；
2. 专项 x64 Debug/Release独立构建和运行；
3. `git diff --check`、严格 UTF-8、工程 XML/filters与精确文件范围；
4. `python .\tools\check_specs.py --strict`；
5. 逐项对账验证矩阵、全部 `NOT_RUN` 和临时清理清单；
6. 生产源码/工程零专项入口、测试宏、故障钩子和验证痕迹。
