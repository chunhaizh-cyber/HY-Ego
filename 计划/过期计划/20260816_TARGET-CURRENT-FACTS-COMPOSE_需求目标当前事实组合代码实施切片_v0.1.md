## 4. 实施步骤

1. 在现有数据头追加父合同 / 规则版本、稳定状态值、请求 / 材料 / 结果、请求 helper 和成功谓词。当前值继续嵌套在子材料中，不复制第二字段；所有非成功 optional 为空。
2. 在同一 provider 追加 `读取需求目标当前事实(...) const noexcept`。纯值拒绝版本、零 G0和五个零身份后，按当前子合同版本恰一次调用 `读取目标状态合同与值域定义`。
3. 第一叶成功后逐字段互证版本、G0、合同 / 定义 / 注册身份、I64目标判断注册和当前生命周期；以正式回显定义构造第二叶请求，恰一次调用 `读取目标宿主同截止当前特征事实`。
4. 第二叶成功后互证版本、G0、树 / 场景 / 宿主 / 定义 / 实例 / 当前值和当前生命周期；当前值非 I64 映射当前值类型不兼容。两叶完整后一次构造候选并返回已形成。
5. 按详细设计逐项映射两叶非成功；入口拒绝回显原始截止，漂移优先回显首个非零实际截止，其它进入子调用后的失败回显 G0。捕获 `std::bad_alloc`、`std::length_error`为资源失败，其它异常为内部不一致。
6. 保持零锁、零 sleep、零重试、零截止重选、零缓存、零 DATA 直达、零写。新增函数诊断责任按详细设计登记。
7. 以生产外专项从普通应用现有聚合 getter 构造 provider，通过公开 DATA 写入建立合法材料并覆盖验证矩阵；不得增加生产 seam、友元、故障选择或测试分支。
8. 填写永久记录；结果提交后由计划索引所有者登记退出，再独立删除三件临时专项并重做根工程 / strict 清理后验证。
