5. 实现同一只读现实执行硬否决 provider，支持预检和最终复核；请求绑定阶段、完整动作范围、现实影响分类、截止和规则版本，结果分开作用范围证据、安全读回见证与命中证据；不适用只允许零现实改变。

### 5.4 叶4：任务轮次收束、调用返回和按需核算

1. 在 task owner 实现 4260 v0.11 的轮次级发起调用、按子轮次 0 / 1 / >1 读取、调用返回和上级调用槽结算 ABI。

## 附录：主阶段治理公开合同施工补充

本计划按同身份 v0.3 详细设计第5.2节实施唯一 `任务主阶段治理提供者::治理当前任务阶段(const 任务主阶段治理请求&) noexcept`，不得按九段新增第二组公开入口。

生产修改只落入既有白名单中的 `领域/内部治理/任务阶段治理.数据.h`、`领域/内部治理/服务.任务主阶段治理.ixx`、任务管理线程和普通应用装配。数据头在治理尾段依次声明 `任务主阶段迁移材料`、请求、状态、结果及默认相等性；服务 module 导入 `任务筹办当前就绪与执行冻结提供者`，构造依赖固定为 task owner、planning provider、self 后继 provider、阶段端口。任务管理是唯一调用者。

实现顺序固定为：

```text
入口形状
-> task owner 调按任务读取当前任务与轮次，在 G0 一次形成两份事实
-> 阶段端口同 G0 读回并解码九段
-> 筹办中/筹办等待调用 planning，按结果最多一次阶段迁移
-> 轮次已收束调用统一后继消费
```
