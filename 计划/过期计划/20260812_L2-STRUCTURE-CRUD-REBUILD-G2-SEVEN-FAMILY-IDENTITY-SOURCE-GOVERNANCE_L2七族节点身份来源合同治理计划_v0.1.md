## 3. 唯一治理裁决

### 3.1 owner 数量和服务边界

固定七个两两不同的 `独占结构范围` owner。场景、存在、状态、动态、因果服务各一端口；特征服务分别持有定义、实例两端口。七个 raw owner 端口必须先经对应服务模块核对建立幂等常量、独占范围、owner 事实、端口 owner 和同一 L1 实例绑定，再形成七套不可复制、可移动的族专属 `L2{族}所有者交付`；六服务构造函数只接收对应强类型交付，不直接接收同型 raw 端口。一个端口只能写一个族；特征服务分别接收 `L2特征定义所有者交付` 和 `L2特征实例所有者交付`，定义函数与实例函数静态路由到不同端口，不提供 owner 参数，两个交付互换必须在编译期失败。

普通应用唯一 provider 使用同一运行包和签发器，最终签发顺序固定为：

```text
存在 -> 特征定义 -> 特征实例 -> 状态 -> 动态 -> 因果 -> 场景
```

代码按依赖逐叶实现该前缀；未实现后缀不伪装成已签发能力。

### 3.2 非自环身份来源

owner 证明技术写入方，但不能区分同 owner 内部元数据节点。每族另在同一 L1 仓、同一 owner 建立一个不可变族锚点和一个不可变归属关系类型。公开节点创建时同写一条 `节点 -> 族锚点`、角色 `1` 的归属关系。

禁止：

- 节点到自身关系；
- 仅凭 owner、节点形状、名称、本地键、强类型包装或缓存判定；
- 中央身份服务、第二仓、第二成员表；
- 读取时静默补关系或 legacy adoption。

### 3.3 初始化、生命周期与退出

七族 owner 建立幂等身份和来源登记写集幂等身份均固定非零且互不复用。精确重复回读首次锚点 / 类型；同键异义冲突；第二登记属于内部不一致。

锚点 / 类型创建不晚于首个公开节点，生命周期覆盖全部成员。节点退出同代退出其归属关系，锚点 / 类型保留。族退役必须先由有效端口退出成员 / 归属和锚点 / 类型并使当前事实归零，再释放端口；幂等和历史 / 恢复 / 审计引用闭合后才由签发器退出 owner。历史不可复活或转族。

### 3.4 读取与拒绝

七族各有专属 `身份来源读取请求 / 结果` 和公开 const 函数。当前读取一次 owner-aware 一致投影；历史读取按具名截止重建并在前后复核当前代次。完整读取和条件查询必须把来源证明纳入同一截止，跨族消费者调用目标族公开来源而不是直达 L1 重演。

当前入口先裁决生命周期，已退出固定 `已退出` 且不补历史判族。对仍可读节点或历史截止可判定事实，wrong-family owner、v1 legacy、裸 L1 节点、同 owner 锚点 / 类型 / 登记节点和旧未标记节点固定 `入口拒绝`；malformed 来源固定 `内部不一致`；历史截止达到退出仍返回 `已读取` 和完整生命周期。七 owner 互异和同一编码不被两族同时接受由 provider / 集成矩阵证明，不要求单族扫描其它族。

## 5. 后继迁移顺序

```text
G2 治理发布并退出
-> E-ID 存在身份来源迁移
-> F-ID 特征定义 / 实例双 owner 身份来源迁移
-> T1 按真实 ABI 重新 S0
-> 状态、动态、因果首次实现直接采用 G2
-> S-ID 场景迁移
-> A1 聚合公开面
```

E-ID 复用当前存在 owner-scoped 服务，增加非自环来源登记、同写归属、同截止读取和旧未标记拒绝。F-ID 在存在之后建立定义 / 实例两个新 owner，把定义和实例全部写 / 读迁入 owner-scoped v2；原 v1 特征事实不改 owner、不保码。

场景不前置 T1，因为 T1 只依赖存在与特征；场景为 A1 硬前置。状态、动态和因果不能先造弱身份再迁移。
