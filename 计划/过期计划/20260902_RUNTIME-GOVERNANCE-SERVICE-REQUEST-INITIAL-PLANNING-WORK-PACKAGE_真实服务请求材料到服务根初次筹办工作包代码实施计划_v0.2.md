## 4. 目标 ABI 与函数合同

### 4.1 初次工作包与 task owner

1. `任务初次筹办工作包`新增并完整性校验`首次准备记录`、`任务轮次`；服务请求来源 E/M/D 保持可选兼容，但本入口的新请求必须存在且完整。
2. `需求初次筹办准备提供者`的首次 / 精确重复结果都从 task owner 正式读回填入同一个首次准备记录身份；不得由请求键、线程消息身份或旁路结果推断。
3. `L2任务初次筹办规范化来源材料`补齐`任务轮次`与`本轮来源成员关系`，完整性、编码、发布前互证和历史读回全部逐项覆盖；其幂等身份仍是首次准备记录。

### 4.2 统一推进请求

`任务筹办推进请求`、`任务特征方法查找请求 / 结果`、`任务筹办当前就绪请求`和`任务筹办等待合同`均使用`L2任务筹办规范化来源材料`。公共 helper 必须提供来源任务、任务轮次、筹办轮次、运行代次、来源幂等身份和执行轮次，所有 helper 按 variant 分支返回，禁止裸整数比较后猜分支。

公开 provider 使用：

```cpp
任务筹办推进结果 推进筹办工作包(
    const 任务筹办推进请求&) noexcept;
```

旧后继入口若保留，只允许是无业务状态的薄适配。不得建立独立初次业务实现或固定待实现返回。

### 4.3 初次分支的 fresh 互证

在请求头事实截止 G：

1. 读取任务、任务身份来源、任务轮次、首次准备记录、本轮来源成员关系和列表项；
2. 互证任务 / R1 / P0 / D / 关系 / 列表项 / G0 / G1 / 运行代次；
3. 证明筹办轮次为 1，任务轮次仍在筹办阶段，当前选择 / 路径 / 实例为空；
4. 不读取或伪造旧实际结果、旧路径、旧实例、目标未达成治理状态；
5. 进入现有目标当前值读取、方法粗召回、适用性与当前就绪公共链；
6. 发布正式选择时来源与冻结归因均绑定首次准备记录，实例执行轮次固定为 1；按原来源身份和原完整请求独立读回。

后继分支现有旧结果 / 治理来源互证保持，不因本计划放宽。

### 4.4 P01 与管理端

1. `任务筹办工作包消息`协议版本递增，继续携带一个统一推进请求；其`来源材料`本身区分初次 / 后继，不再套同义外层联合。
2. `提交初次筹办工作包`只负责原始工作包验证、机械规范化、填入管理端既有有界预算、登记同一处理槽和提交同一工作端口。
3. 工作线程每次只调用一次统一 provider，并对所有五类分支形成一个结果消息。
4. manager 不直接调用筹办 provider，不通过槽状态或同步返回值判断筹办结束。结果消息首次接收或精确重复后，必须把初次槽与后继槽同样排入现有结果待处理队列。
5. 结果队列满只重投同一结果消息，不再次调用 provider；工作队列满只重投同一工作包消息，不重新建立任务 / 记录。

### 4.5 执行冻结来源

`任务执行冻结请求.来源工作包`改为 DATA-L2 规范化来源联合，协议版本递增。管理端仅在收到结果消息并独立读回正式选择、冻结、路径和实例后形成请求：

- 初次分支：来源 = P0，任务 / R1 / 筹办轮次 1 同源，冻结归因 = P0，实例执行轮次 = 1；
- 后继分支：保持原来源、任务、新筹办轮次与`旧执行轮次 + 1`。

初次`可执行冻结`必须进入现有执行冻结队列，不能因来源分支不同被跳过；其它四分支按同一结果消息正常等待 / 收束。

## 5. 实施顺序

1. 扩 task owner 初次记录 / 工作包读回及 DATA-L2 初次规范化来源字段、谓词与发布互证。
2. 扩方法查找 DTO / provider 的来源联合与初次 fresh 前置；复用既有召回和适用性后半段。
3. 扩当前就绪、等待、冻结发布和读回为统一来源；删除候选中的初次固定未实现断点。
4. 把 P01 消息改为一个统一推进请求；worker 单调用；manager 初次槽进入同一结果待处理排队。
5. 扩执行请求协议来源联合与分支校验，让初次可执行结果进入现有执行队列。
6. 完成服务请求 E/M/D provider、普通应用 / 运行包 / 启动装配和工程登记；不新增第二线程、队列或账。
7. 在纯 HEAD 仓库外候选完成最低构建 / 静态门禁，形成施工与验证记录；无损合并到共享工作区后精确发布。

## 6. 失败收口

- 原始工作包或规范化来源不完整：结构化入口拒绝，零写；不得切换 variant 分支。
- G 漂移、任务轮次 / P0 / 来源关系读回不一致：结构化当前性漂移或引用冲突，零新选择。
- 正式选择发布未知：只用原强类型来源身份、原分支和原完整请求读回收敛。
- 工作 / 结果队列满：保留同一不可变消息重投；provider 调用次数不增加。
- 结果消息协议拒绝、同键异义或管理端停止：内部收口失败；不得补写第二结果或静默结束。
