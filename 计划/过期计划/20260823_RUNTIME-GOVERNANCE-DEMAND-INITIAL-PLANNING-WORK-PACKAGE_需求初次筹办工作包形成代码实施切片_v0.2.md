## 5. 冻结目标合同

### 5.1 外层完整请求与同义边界

在`任务初次筹办.数据.h`增加强类型`初次筹办准备幂等身份`；`需求初次筹办准备请求`完整字段固定为：

```text
合同版本
准备幂等身份
请求身份
运行代次
L2结构请求头（合同版本、G0）
需求身份
任务建立幂等身份
```

双幂等身份必须非零且底层值相同；融合提交只使用这一唯一值。原键下任一完整请求字段变化均为`幂等冲突`。不得沿用 v0.1“请求身份 / 运行代次不参与冲突”的外层裁决。

外层结果新增`幂等冲突`和强类型`首次准备记录身份`。成功 / 精确重复都必须携带完整首次未满足裁决、首次记录身份和首次工作包；两者除状态外逐字段一致。

“首次结果”只指已经发布任务和首次记录的首次成功结果。写前入口拒绝、目标已满足、证据不足、漂移、许可或资源失败保持零写且不消费准备幂等身份；只有发布是否未知时必须原键原完整请求先查记录，禁止把未知发布当作已确认零写。

### 5.2 task owner 强类型记录

按详细设计 §5 机械增加：

```text
L2任务初次筹办准备记录身份
L2任务初次筹办准备完整请求材料
L2任务初次筹办首次需求裁决材料
L2任务初次筹办准备记录事实
对应请求、结果、读取类别与完整性函数
```

首次裁决材料必须完整保存 v0.1 `需求当前满足裁决快照` 的全部来源值：裁决规则版本 / 请求身份、需求事实、当前成员关系、完整列表项、当前特征实例和值、目标合同、比较注册、算法版本、具名关系、允许关系位和 G0。事实身份和版本使用已发布强类型 / 生命周期，不降级为裸号猜测。

记录还固定任务身份、任务虚拟存在、列表项、轮次 1 和 G1；G1由融合写的共同创建代次取得，不接受调用方输入。

### 5.3 融合原子写

新增 task owner 公开 ABI：

```cpp
L2新增任务与首次初次筹办准备记录结果
L2任务结构服务::新增任务与首次初次筹办准备记录(
    L2新增任务与首次初次筹办准备记录请求 请求) noexcept;
```

一笔 owner-scoped 写集原子建立：任务、任务虚拟存在、首次准备记录三个节点；任务族、任务—列表项、任务—虚拟存在、记录族、记录—任务、记录—虚拟存在、记录—列表项关系；完整请求 / 首次裁决 / 轮次 1 值。所有创建代次必须同为 G1。

记录—虚拟存在关系是任务运行状态承载边界。记录中的上游事实是不可变首次快照，不是第二当前权威。

原`新增任务`保留既有 DATA-L2 结构 ABI；新外层 provider 禁止调用原入口。融合入口与原入口共用同一 task owner 锁和列表项 0/1 基数守卫，不能并发形成第二当前任务。

### 5.4 前置读回与历史读回

新增：

```cpp
L2任务结构服务::按初次筹办准备幂等身份读取首次记录(...)
L2任务结构服务::读取首次初次筹办准备记录(...)
```

按准备键读取必须跨记录生命周期得到 0/1，>1 内部不一致；返回首次记录、首次任务和任务身份来源的 G1 历史投影。按记录身份读取支持当前 / 历史和非零具名历史截止，严禁以当前任务、当前列表项或当前特征补历史缺项。

任务退出时，记录到任务 / 虚拟存在的强关系与任务核心同代闭合，记录历史及值保留；前置键读仍必须定位原记录。

### 5.5 provider 固定顺序

```text
完整请求纯值守卫
-> 按准备幂等身份前置读回首次记录
-> 有记录：完整请求同义/异义裁决
   -> 同义：按记录G0/G1历史重构首次结果
   -> 异义：幂等冲突
-> 无记录且观察截止=G0：正式裁决需求当前满足
-> 未满足：一次调用融合写入口
-> 已提交：G1直接读回并组包
-> 精确重复：转首次记录历史重构
```

禁止先重裁决后查记录、刷新到新 G、换幂等键、撤销 G1、以当前替代首次或调用重筹办路径。

## 7. 失败收口

- 写前入口、裁决、读取、许可、资源、当前性失败：具名结果，零事实写入；
- 原键异完整请求：幂等冲突，首次记录不变；
- G1 已发布后任一读回 / 组包失败：内部错误，不撤销、不退出、不删除；
- 发布未知：原键原请求从前置记录收敛；不得换键；
- 任务已退出或当前任务已变化：返回首次历史结果，不复活、不替换；
- 纯代码 / 编译错误：白名单内修复；
- 环境波动：保留证据后重试，不改机器语义；
- 必需验证持续失败且无法安全归因：保留现场并停止受影响切片。
