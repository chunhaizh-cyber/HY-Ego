## 4. 机械实施步骤

1. 新建 `L1中性CRUD.数据.h`，逐项实现详细设计第 4 节 DTO、相等比较和最小有效性辅助；不得 include legacy `L1事实基座.数据.h`。
2. 新建 `合同.L1中性CRUD.ixx`，唯一导出模块与新数据头；工程和 filters 各登记一次。
3. 在仓库状态内新增同锁 `中性幂等账`，完善状态完整性和与 legacy 账交叉占用；不得新增第二当前事实、第二代次、第二编码分配器或第二锁。
4. 按 v0.2 单函数图实现唯一 `提交中性写集`；规范化、引用拒绝、候选、编码分配、退出 / 槽替换、幂等、最后交换和发布后读回顺序不得改变。
5. 在服务中导入新合同并实现七个公开入口；中性读取只精确调用现有仓库读取并逐字段转换，完整快照 / 审计 / 恢复 / 索引调用为 0。
6. 对中性幂等账非空后的 legacy 恢复管理入口增加设计第 6 节保守拒绝；不实现或宣称恢复。
7. 保持所有 legacy 公开签名和现有 16 个写调用点不变；静态确认没有新增带操作标签调用。
8. 写入两份专属记录，完成第 6 节施工验证并精确发布代码结果。不得创建 L1 专用验收驱动、验收模块、第二程序或集成验收结论。

## 5. 失败收口

- 若实现必须复制第二当前事实表、第二事实代次或第二编码空间，停止并回传 `L1-NEUTRAL-CRUD-DRIFT-SECOND-AUTHORITY`。
- 若不能同锁保证 legacy / 中性幂等键交叉唯一和旧调用行为不变，停止并回传 `L1-NEUTRAL-CRUD-DRIFT-IDEMPOTENCY-COEXISTENCE`。
- 若现有状态完整性不能在不改领域消费者的条件下接纳中性候选，停止并回传具名不变量，不放宽 4015。
- 若七入口必须引入业务标签、意图组、执行证据、领域见证、完整快照或全仓扫描，停止并回传 `L1-NEUTRAL-CRUD-DRIFT-NON_NEUTRAL`。
- 若为了证明完成需要专用 L1 驱动、私有仓、friend、日志解析或验收入口，删除该方案并保持代码完成声明收窄；不得扩大生产合同。
- 构建错误只修复白名单内由本计划造成的问题；需要扩展文件或改变机器语义时停止。
