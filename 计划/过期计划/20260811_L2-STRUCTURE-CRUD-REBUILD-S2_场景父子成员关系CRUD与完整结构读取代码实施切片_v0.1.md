2. 每次新增形成一条新关系，每次替换在同一中性写集中“新建新关系 + 退出旧关系”，每次退出只退出具名旧关系，均恰一次提交；

## 4. 最终 DTO 合同

### 4.1 父子关系请求

```cpp
struct L2场景父子关系新增请求 final {
    L2结构请求头 请求头;
    L2结构幂等身份 幂等身份;
    L2场景身份 父场景;
    L2场景身份 子场景;
    std::uint64_t 顺序 = 0;
};

struct L2场景父子关系替换请求 final {
    L2结构请求头 请求头;
    L2结构幂等身份 幂等身份;
    稳定编码 旧关系稳定编码;
    L2场景身份 旧父场景;
    L2场景身份 子场景;
    std::uint64_t 旧顺序 = 0;
    L2场景身份 新父场景;
    std::uint64_t 新顺序 = 0;
};

struct L2场景父子关系退出请求 final {
    L2结构请求头 请求头;
    L2结构幂等身份 幂等身份;
    稳定编码 关系稳定编码;
    L2场景身份 父场景;
    L2场景身份 子场景;
    std::uint64_t 顺序 = 0;
};
```

父子“替换”唯一表示：保持同一子场景，退出具名旧父关系并建立新父关系；新父可以与旧父相同，但此时新顺序必须不同。改变子场景不是替换，调用方须分别退出旧关系并新增另一关系。

### 4.2 成员关系请求

```cpp
struct L2场景成员关系新增请求 final {
    L2结构请求头 请求头;
    L2结构幂等身份 幂等身份;
    L2场景身份 场景;
    L2存在身份 存在;
    std::uint64_t 顺序 = 0;
};

struct L2场景成员关系替换请求 final {
    L2结构请求头 请求头;
    L2结构幂等身份 幂等身份;
    稳定编码 旧关系稳定编码;
    L2场景身份 旧场景;
    L2存在身份 存在;
    std::uint64_t 旧顺序 = 0;
    L2场景身份 新场景;
    std::uint64_t 新顺序 = 0;
};

struct L2场景成员关系退出请求 final {
    L2结构请求头 请求头;
    L2结构幂等身份 幂等身份;
    稳定编码 关系稳定编码;
    L2场景身份 场景;
    L2存在身份 存在;
    std::uint64_t 顺序 = 0;
};
```

成员“替换”唯一表示：保持同一存在身份，退出具名旧成员关系并建立指向新场景的新关系；新旧场景相同时表示只换顺序。改变存在身份不是替换，必须分别退出旧成员和新增新成员。这样旧 / 新关系的连续主体唯一，不把两个不同存在误称同一关系换代。

### 4.3 写入结果

```cpp
struct L2场景父子关系写入结果 final {
    L2结构结果头 结果头;
    std::optional<L2场景父子关系事实> 当前关系;
    std::optional<L2场景父子关系事实> 已退出关系;
};

struct L2场景成员关系写入结果 final {
    L2结构结果头 结果头;
    std::optional<L2场景成员关系事实> 当前关系;
    std::optional<L2场景成员关系事实> 已退出关系;
};
```

新增成功只携带 `当前关系`；替换成功同时携带新 `当前关系` 与旧 `已退出关系`；退出成功只携带 `已退出关系`。成功状态只允许 `已提交` / `精确重复`，结果头事实截止和变更事实代次都等于首次写入事实代次。所有非成功载荷必须全空，变更事实代次为空。

关系生命周期按结果截止投影：创建代次不得晚于截止；底层退出代次晚于截止时在该截止投影为无退出，等于或早于截止时保留。这保证后继退出之后重交原新增 / 替换请求仍能返回首次原结果，而不是把未来退出混入首次幂等结果。

### 4.4 完整场景读取

```cpp
struct L2场景完整读取请求 final {
    L2结构请求头 请求头;
    L2读取类别 读取类别 = L2读取类别::当前;
    L2场景身份 场景;
    std::uint64_t 历史截止事实代次 = 0;
};

struct L2场景完整读取结果 final {
    L2结构结果头 结果头;
    L2读取类别 读取类别 = L2读取类别::当前;
    std::uint64_t 历史截止事实代次 = 0;
    std::optional<L2场景事实> 场景;
};

```

当前请求要求非零 `请求头.期望事实代次`、有效目标且历史截止为 0；历史请求还要求 `历史截止事实代次` 非零且不大于请求头期望事实代次。当前成功的结果头截止等于期望代次；历史成功的结果头截止和回显历史截止都等于请求历史截止。漂移失败的结果头截止回显能安全取得的实际当前代次，仍回显请求读取类别和历史截止。

新增纯值辅助为六个写请求有效性函数、完整场景读请求有效性函数、两种关系事实截止投影完整性函数、`L2场景S2事实完整` 和两个写结果 `成功()`。顺序有效域固定为 `1..INT64_MAX`，以便无损映射到 L1 `角色或顺序`；零身份、零关系编码、相同父子、自相同且顺序未变的替换、非法类别 / 截止均在进入事实读取前返回入口拒绝。

## 6. 共同写前门禁、幂等与提交顺序

六个写入口固定执行：

```text
纯值请求校验
-> 读取当前场景关系类型登记，取得具名关系类型稳定编码
-> 读取 L1 当前事实代次
-> 若实际代次 != 请求期望代次：跳过业务事实预检，直接提交完整规范化写集
-> 若实际代次 == 请求期望代次：在该代次完成全部端点 / 旧关系 / 基数 / 环预检
-> 恰一次提交完整中性写集
-> 只从 L1 新编码映射和历史事实入口做首次截止读回
-> 返回完整结果或内部不一致
```

登记只接受 `已读取` 且登记完整；登记截止与请求期望不一致时不改变登记编码，但后继由代次探测进入旧期望路径。登记未加载映射 `内部不一致`；许可拒绝、事实代次漂移、资源失败按同名 L2 状态返回；其它登记状态在读入口出现均为内部不一致。

旧期望路径不是绕过门禁：L1 对新幂等键先比较期望代次，只能返回漂移且零变化；对既有键先比较完整规范化写集，只能返回精确重复或幂等冲突。业务预检若在读取中观察漂移，也转入同一“直接提交原写集”收敛路径，不改期望、不改幂等身份、不重建请求、不二次提交。

当前代次匹配时，所有一致投影请求都使用同一请求期望代次。任一许可拒绝、漂移、资源失败或矛盾立即零写返回；多个读取之间若发生发布，后继读取或最终提交必然由 L1 代次门禁拒绝。不得加场景全局锁、轮询、sleep 或第二事务。

L2 幂等身份完整 64 位原样映射为 L1 幂等键。新关系本地键固定：父子 `0x0201'0201U`，成员 `0x0201'0202U`；只参与同一写集引用和新编码定位，不是稳定编码。登记私有 `0x1D` 域保持不变，普通 S2 请求不得进入该域或改变调用方幂等身份。

## 7. 父子关系精确事务

### 7.1 新增

在请求期望代次：

1. 一致读取父场景、子场景和子场景的父子类型目标关系组；两节点必须是当前完整普通场景节点；
2. 目标组必须为空，非空即多父 `引用冲突`；
3. 从子场景沿父子类型源关系组广度优先遍历当前直接子关系。每轮仍用同一代次一致投影；命中新父场景即成环 `引用冲突`，命中已访问节点说明现存结构已有环，返回内部不一致；
4. 写集节点 / 值 / 属性槽变更 / 退出为空，关系恰一项：本地键 `0x02010201`，源=父场景，目标=子场景，类型=登记父子类型，角色或顺序=请求顺序。

### 7.2 替换

一致读取旧关系、旧 / 新父场景、子场景及子场景父子目标组。旧关系必须当前、类型为登记父子类型，端点和旧顺序逐字段等于请求；目标组必须恰一项且就是旧关系。随后从子场景遍历后继，检查新父不在其后继闭包。

写集关系恰一项新父关系，`退出事实` 恰为旧关系编码，其它三组空；两者在同一事实代次发布。新父等于旧父时只允许顺序改变。不得先退出、后新增，不得以两次提交实现移动。

### 7.3 退出

一致读取具名关系和父 / 子场景；关系必须当前、类型、端点、顺序逐字段匹配，并在子场景目标组中恰为唯一父关系。写集只有 `退出事实=[关系稳定编码]`；不得级联退出子场景、子关系、成员或节点。

## 8. 成员关系精确事务

### 8.1 共同端点

场景端点必须由场景当前节点路径在请求期望代次返回完整 S1 节点；存在端点必须由临时 E1 服务公开 `读取存在节点(当前, 同一期望代次)` 返回完整 E1 节点。未找到 / 已退出 / 许可拒绝 / 漂移 / 资源失败按同名状态；成功载荷形状矛盾为内部不一致。

### 8.2 新增

一致读取场景的成员类型源关系组；组内若已有目标为请求存在的关系，返回引用冲突。写集关系恰一项：本地键 `0x02010202`，源=场景，目标=存在，类型=登记成员类型，角色或顺序=请求顺序；其它项全空。

### 8.3 替换

一致读取具名旧关系、旧 / 新场景的成员源关系组，并验证同一存在端点。旧关系必须当前、类型、旧场景、存在和旧顺序逐字段匹配；旧组必须恰含该旧关系。新组中不得有同一存在的其它当前成员关系；新旧场景相同时允许组内旧关系但不得有第二项。

写集关系恰一项新成员关系，`退出事实` 恰为旧关系编码。新旧场景相同只换顺序；场景变化表示同一存在的成员关系原子迁移。不会自动退出该存在在其它场景的其它合法成员关系，因为 4230 只限制同一场景 / 存在对唯一。

### 8.4 退出

一致读取具名关系、场景、存在和对应源关系组；类型、端点、顺序必须逐字段匹配，组内必须恰含该关系且同对无第二关系。写集只有具名关系退出，不退出场景 / 存在节点，不扫描或级联其它场景关系。

## 9. 写入状态、读回与失败边界

| 来源 / 条件 | L2 状态 |
| --- | --- |
| L1 成功 / 精确重复 | 已提交 / 精确重复 |
| L1 入口拒绝、事实代次漂移、幂等冲突、资源失败、内部不一致 | 同名状态 |
| L1 写入未找到 / 已退出 | 未找到 / 已退出 |
| 当前端点未找到 / 已退出 | 未找到 / 已退出 |
| 多父、成环、同对重复、旧关系字段与请求不符、新关系目标已占用 | 引用冲突 |
| 当前关系编码不存在 / 已进入历史 | 未找到 / 已退出 |
| 关系类型登记未加载、成功形状缺项、现存环、组索引和具名关系矛盾 | 内部不一致 |

L1 成功必须核对合同、幂等键、事实代次、发布标记、重试边界和新编码映射：新增 / 替换恰一项且为对应本地键，退出零映射；首次成功必须形成发布且重试边界不适用，精确重复不得形成发布且重试边界为原幂等键读回收敛。

新增 / 替换的新关系和替换 / 退出的旧关系都通过 `读取中性历史事实` 正式读回。以 L1 首次写入事实代次形成截止投影：新关系创建代次等于该代次且该截止无退出；旧关系退出代次等于该代次。编码、类型、端点、顺序、生命周期或载荷形状任一不符返回内部不一致，不携带部分关系。

关系事实目前不能作为 L1 关系 / 值端点，因此本叶关系退出没有可由当前 ABI 表达的“关系被其它事实引用”路径。S2 的 `引用冲突` 只裁决父子 / 成员结构基数、成环和请求所指关系不一致；场景 / 存在节点退出时的跨结构引用闭包属于 S3 / E2，不在本叶偷偷实现。

## 10. 当前完整场景读取

取得完整登记后构造一份 L1 一致当前投影：

```text
期望事实代次 = 请求头.期望事实代次
节点 = [目标场景]
源关系组 = [(目标场景, 父子类型), (目标场景, 成员类型)]
关系 / 值 / 属性值 / 目标关系组 = []
```

成功必须有一个当前普通场景节点、两个按请求顺序回显的关系组和共同非零截止。父子组每项必须是“目标场景 -> 当前子场景”的登记父子关系；成员组每项必须是“目标场景 -> 当前存在”的登记成员关系。关系与对端节点逐字段互证；每个成员存在再经 E1 公开当前读取在同一代次验证。任何对端退出、类型 / 方向 / 生命周期矛盾或同子 / 同成员重复均返回内部不一致。

形成 `L2场景事实` 时保留 S1 节点生命周期，固定属性仍为空，直接子场景与直接成员按“顺序、子场景 / 存在稳定编码”升序。相同顺序允许不同目标；相同目标的第二关系不允许。成功结果只携带一个完整场景，无父关系、递归子孙、成员完整存在事实或业务资格。

一致投影顶层入口拒绝、许可拒绝、漂移、资源失败按同名状态；目标节点项目未找到 / 已退出按同名状态；其它项目状态和所有成功形状矛盾为内部不一致。显式请求期望代次不自动改写；漂移直接返回实际代次和空载荷。

## 11. 历史截止完整场景读取

历史读取固定顺序：

```text
读取当前事实代次并精确等于请求头期望代次
-> 读取目标场景历史事实
-> 读取父子类型历史源关系组(目标场景, 历史截止)
-> 读取成员类型历史源关系组(目标场景, 历史截止)
-> 按关系端点逐项读取必要的历史节点事实并验证在截止时有效
-> 再次读取当前事实代次并精确等于请求头期望代次
-> 形成一个历史截止完整结果
```

目标场景必须满足 `创建 <= 历史截止 && (!退出 || 历史截止 < 退出)`；否则分别返回未找到或已退出。两历史关系组必须回显方向、端点、登记类型和请求截止，状态成功，且 `读取事实代次` 等于请求头期望当前代次。每条关系同样按半开区间在截止有效；关系源必须是目标场景，目标历史节点必须在该截止存在并满足相应 S1 / E1 空属性普通节点形状。

历史结果只使用历史事实和历史关系组；不得调用当前关系组补项，不因当前已经退出而丢弃截止时有效关系。返回生命周期按历史截止投影，晚于截止的退出不进入该快照；关系组按共同排序重排。两组原始 L1 稳定编码排序不是 L2 业务排序，不能直接透传。

### 12.2 必过矩阵

1. 顺序建立关系类型登记并创建场景 / 存在夹具；所有身份非零、代次逐次推进且公开当前读取完整；

4. 替换父关系取得新当前 / 旧退出同代次；旧关系当前不可见、历史可读，新父完整场景含新关系，旧父不含旧关系；原替换请求在后继退出后仍精确重复首次结果；
5. 退出父关系只退出具名关系；重复原退出请求精确重复；以错父、错子、错顺序、成员类型关系编码冒充父关系分别引用冲突或已退出 / 未找到，零变化；
6. 新增成员关系并验证场景完整读；同一场景 / 存在第二关系引用冲突，但同一存在在另一场景的独立成员关系合法；
7. 替换成员关系保持存在不变，覆盖同场景换序和跨场景迁移；新 / 旧关系同代次，旧场景 / 新场景当前组一致；改变存在身份须由入口请求形状拒绝，不能伪装替换；
8. 退出成员关系后当前场景组消失，历史截止在退出前仍命中、退出截止及之后不命中；原退出请求重复零推进；
9. 同一场景至少两个子场景和两个成员以乱序写入，当前完整场景按“顺序、目标编码”稳定排序，重复读取逐字段相同且共享同一截止；
10. 记录父子 / 成员替换前后多个截止；历史完整场景分别重建各截止有效关系，不混入未来新关系、不丢失后来退出但截止时有效的旧关系；
11. 当前 / 历史合法零子、零成员均已读取且空组；目标未找到、目标当前已退出的适用夹具按未找到 / 已退出分账；
12. 零身份、零 / 超 `INT64_MAX` 顺序、同父子、无变化替换、错合同、历史截止 0 / 大于期望和坏读取类别均入口拒绝且当前代次不变；
13. 旧期望代次的新幂等键返回事实代次漂移；同一旧期望下原完整写集返回精确重复，同键异写集返回幂等冲突，三者零新发布；
14. 并发推进造成当前组合读取或历史前后夹取漂移时返回漂移和空载荷；非阻塞许可竞争允许许可拒绝，不改判资源失败 / 内部不一致，不用 sleep 或轮询掩盖；
15. 每次成功写后核对 L1 当前代次只推进一次；失败 / 冲突 / 重复均不推进。专项入口不解析日志，不用输出文本替代结构化断言。
