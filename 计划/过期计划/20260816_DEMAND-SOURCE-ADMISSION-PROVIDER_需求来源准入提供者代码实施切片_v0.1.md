## 4. 实施步骤

1. 在真实服务模块的导出命名空间内先定义带语义版本的来源种类 / 对象稳定绑定、完整目标语义键及权威引用、强类型时间见证、来源对象见证、正式授权事实 / 来源内在规则分型见证、已存在冲突事实引用 / 带强类型缺口种类且无虚构身份的待补事实定位、拒绝证据、来源专用结果、公共结果及纯值 helper；依赖模块只作普通 `import`，只导出本模块公开面，不建立传统 DTO 头。
2. 公共目标语义键逐字段复用 `目标宿主 + 目标特征定义 + 完整L2特征比较I64合同材料 + 目标I64 + 允许关系位 + 目标状态合同规则版本`；目标合同 / 比较注册身份只作权威引用。
3. 新建服务模块，声明来源专用 provider 抽象协议以及结构化装配 factory；输入顺序无语义，factory 先校验注册版本、必需组非空和必需来源身份有效，再恰一次读取 provider 身份并拒绝无效回显，随后按详细设计的“必需重复→provider重复→额外错种类→必需缺失→成功”优先级检查完整组；冻结装配结果 optional，失败零服务，成功交付唯一移动服务。
4. 服务保存按来源种类稳定排序的不可变 provider 引用组；统一入口在首个 provider 调用前校验公共字段和来源种类 / 对象绑定，未登记返回未实现，禁止广播 / 回退 / 缓存。
5. 原请求恰一次调用匹配 provider；专用请求拒绝映射提供者拒绝，许可拒绝单独映射，其它业务拒绝 / 待定 / 结构化非成功按详细设计逐项映射。
6. 专用成功材料逐字段互证来源、主体、完整目标语义键 / 引用、时间见证、G0、版本和非空采用授权见证；正式授权事实要求当前事实与非零授权方，来源内在规则要求同种类具名规则且零虚构授权方；任何错配固定内部不一致，不降级业务拒绝。
7. 一次形成统一值式见证；保持零 DATA / L1 直达、零写、零锁 / 等待 / 重试 / 缓存 / 截止重选。
8. 完成专项、根工程双配置和永久记录；结果退出后独立删除临时专项并清理复验。

## 5. 验证与成功标准

- 装配 factory 覆盖成功、空 / 缺失、必需零身份、provider零身份、必需重复、provider重复、额外错种类、错版本、资源失败及完整多错误优先级；乱序等义输入产生同一排序结果，任何失败不交付半配置服务；
- 每个已登记来源只调用匹配 provider 一次；空种类、来源对象错绑定和未登记来源均在调用前结构化返回；
- 来源专用13状态与公共15状态映射闭合，提供者拒绝、许可拒绝、业务来源拒绝和观察 / 材料待定分账；每个状态的截止回显与零截止矩阵闭合；
- 专用和公共结果 optional 合法组合逐项验证；业务拒绝必须有来源/G0/类别/阶段/重提形状完整的拒绝证据；冲突事实只引用已存在事实，待补定位以非零强类型缺口种类区分且零虚构事实身份；逐行验证类别 × 阶段 × 证据组 × 角色 × 生命周期 / 版本矩阵，表外组合固定内部不一致；成功必须有完整材料 / 见证且采用授权见证非空；
- 成功见证与原请求及 provider 材料的来源、主体、完整目标语义键 / 引用、时间、G0、版本和授权范围逐字段相等；
- DATA合法空授权事实组不由统一服务猜成通过；内在授权也必须形成具名可审计BIZ规则见证且不得伪造L2授权方或生命周期；坏 optional / 错G0 / 错来源 / 半结构固定内部不一致；
- 源码零 DATA 服务函数 / L1 / owner / 需求写 / 根 / 路径 / 任务化 / 日志裁决，零 sleep / retry / cache；
- 根工程 x64 Debug / Release Rebuild、生产外专项双配置、diff、strict、UTF-8、工程唯一登记和生产零专项痕迹通过。

## 6. 激活与完成边界

本计划待激活不授权施工。当前必需来源专用 provider 未全部冻结前继续设计后继来源叶，不得用测试替身、非权威消息、封闭枚举或无种类裸编码提前激活。

若来源种类身份协议、目标语义键、专用 / 公共结果、装配 factory、授权见证、G0或文件所有权漂移，固定 `DRIFT-DEMAND-SOURCE-ADMISSION-PROVIDER-BOUNDARY`退回计划支撑。代码完成也不证明任何真实来源已能准入。
