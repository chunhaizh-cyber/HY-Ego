## 1. 目标与完成条件

接通 Stage C 结构化收束链：任务管理线程取得合法`下一筹办工作包`后，经普通应用唯一 provider 完成九结论收束；当前普通启动在授权安全材料缺失时形成合法等待，同时实现可注入真实强类型授权安全来源后的方法当前就绪复判、task owner 正式选择 / 路径 / 实例原子换代、权威读回、L2 强类型执行冻结形成和两阶段队列确认合同路径。

完成必须同时满足：

1. 九种方法查找结论均形成执行冻结候选或具名非成功承接，不留裸状态；
2. 强类型授权 / 安全或限制解释材料缺失时合法等待，不默认不适用；
3. 同一`下一筹办工作包.原重筹办意图幂等键`只驱动一次 task owner 原子写；
4. 正式选择记录及六类拓扑是唯一选择权威，执行绑定冻结材料只走独立一对一拓扑，`task -> path`只有派生投影；
5. 发布未知按原键和原完整请求收敛；正式读回后才形成冻结；
6. 队列容量等待只重试同一冻结请求，不重写 task owner 事实；
7. 重启不恢复旧运行代次执行权；
8. Debug / Release 重建与治理专项验证按本计划矩阵闭合。

本计划不执行方法，不进入结果共用 / 争用分配、任务完成、需求结算或价值回流。

## 4. 目标 DTO、函数与物理位置

### 4.1 task owner 正式选择

在`L2任务结构.数据.h`逐字实现详细设计 §4、§5.3 的强类型身份、关系类型身份、选择记录、完整选择、稳定证据联合类型、纯 DATA-L2 规范化来源材料、强类型冻结证据、执行绑定冻结材料、组合发布和三个读取请求 / 结果。现有公开依赖保持，只允许新增`L2存在结构.数据.h`与`L2普通方法结构.数据.h`两个 DATA-L2 数据头；零 include / import `领域/内部治理/**`。`L2任务结构服务`同样零引用内部治理模块和无`L2`前缀 BIZ DTO，并新增：


删除旧`发布当前选中路径`公开写入口；保留`读取当前选中路径`作为派生兼容读，并改为从当前正式选择读回路径。`新增任务方法路径`可保留为候选 / 专项入口，但不得发布当前选择。

### 4.2 强类型路径兼容投影

不允许调用方构造七个裸编码。组合发布入口内部按详细设计 §5.4 唯一映射形成`L2完整路径材料`：条件 / 输入 / 参数均指向同一执行绑定冻结材料身份，动作指向动作入口身份，预期结果指向主轴结果身份，验证指向目标状态合同，归因指向正式选择记录。正式读取必须反向验证映射，任一不一致为内部不一致。

### 4.3 Stage C provider

新数据头和模块逐字实现详细设计 §5、§7、§9 BIZ DTO 与：

```cpp
任务筹办当前就绪结果 复判任务筹办当前就绪(
    const 任务筹办当前就绪请求& 请求) const noexcept;

任务筹办推进结果 推进下一筹办工作包(
    const 任务筹办推进请求& 请求) noexcept;
```

唯一公开类为`任务筹办当前就绪与执行冻结提供者`。它复用普通应用的 lookup provider，不复制方法查找算法；依赖方向和构造参数严格按详细设计 §9。成功发布前按详细设计 §5.3 把工作包和 BIZ 当前就绪证据逐字段机械映射为 task owner 的 L2 规范化请求，禁止 DATA 反向 import BIZ、类型别名和转型绕过。所有异常映射为结构化资源失败或内部错误，非成功不得携带执行冻结材料。

九结论按详细设计 §7 固定分流。缺失条件通过现有子目标记录服务与需求统一承接服务；学习需求和方法补齐只形成值式承接草案和具名生产者 / 处理方，不直接写需求树或方法结构。限制非空且无解释证据、授权安全材料缺失、权限为零均合法等待。

### 4.4 普通应用与授权安全来源

普通应用上下文持有唯一 Stage C provider 并提供：

```cpp
任务筹办当前就绪与执行冻结提供者&
取得任务筹办当前就绪与执行冻结提供者() noexcept;

const 任务筹办当前就绪与执行冻结提供者&
取得任务筹办当前就绪与执行冻结提供者() const noexcept;
```

`普通应用配置`精确新增：

```cpp
任务筹办等待合同登记 等待合同登记;
任务筹办授权安全材料来源* 授权安全材料来源 = nullptr;
```

普通应用上下文值式只读拥有`等待合同登记`副本；Stage C provider 构造参数显式增加`const 任务筹办等待合同登记& 等待合同登记`。每个登记项的`方法查找结论`和`当前就绪结论`必须恰一非空；双空、双非空、零值、重复键、未知结论和缺项均在构造时拒绝，provider 只读登记，不生成等待身份。授权安全来源非空时上下文只保存非拥有引用；空时构造具名`任务筹办授权安全材料缺失来源`，其唯一合法返回是`材料缺失`。启动代码不得把空来源升级为不适用，不得接 legacy 句柄算法。构造失败新增具名`普通应用装配状态`。

### 4.5 线程协议与状态机

`协议.任务执行请求.ixx`升至 v2，删除 legacy 三组材料，按详细设计 §8 实现 L2 强类型`任务执行冻结请求`及完整性 / 相同性检查。字段映射固定为`请求编号 = 来源工作包.原重筹办意图幂等键`、`幂等键 = 来源工作包.原重筹办意图幂等键`、`任务序号 = 实例方法.执行轮次`；v2 删除 v1 请求编号与幂等键互异检查，禁止哈希、位运算、换键或墙钟 / 线程号派生。队列的同任务序号 map 键由`节点句柄`迁移为`L2任务身份`。

`任务管理线程`构造新增 Stage C provider 引用；`任务重筹办处理槽快照`扩展为详细设计 §8 阶段并保存完整`任务筹办推进结果`、`任务执行冻结请求`和非成功承接。工作包形成后离锁调用 provider；取得冻结形成材料后构造协议请求、准备 move-only 候选并确认。

队列满 / 容量暂不可用：槽进入`队列容量等待`，只保存并重试完全相同请求，不再次调用 provider。确认失败必须撤销仍有效候选；候选析构兜底撤销。停止 / 排空必须把等待槽作为可收口状态处理，但不得丢弃已确认请求。

### 4.6 运行包与启动

`任务结果生产运行包`不再自行构造 Stage C provider；构造参数新增普通应用 getter 返回的唯一引用并传给管理线程。`启动.应用程序.ixx`在现有运行包构造点注入同一 getter。现有启动 / 逆序收口顺序不变。

工程和 filters 精确登记两个新文件。端到端测试全部经普通应用 getter和运行包生产入口消费，不直接构造第二 Stage C provider。
