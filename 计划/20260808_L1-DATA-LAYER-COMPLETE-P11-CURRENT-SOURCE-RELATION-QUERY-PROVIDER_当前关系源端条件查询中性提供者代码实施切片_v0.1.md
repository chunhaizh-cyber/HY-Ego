本叶不实现第二层场景服务，不建立第一层自检或独立验收。代码发布只形成待消费候选；后继必须立即建立或修订真正的第二层场景完整事实服务，经该服务实际运行累计证明本查询。

正式依据：0050、4015 v0.5、4030 v1.3、4200 v1.2、ACCEPTANCE-01 v0.3、CODE-FILE-01，以及：

- `规范/详细设计/20260808_L1-DATA-LAYER-COMPLETE-P11-CURRENT-SOURCE-RELATION-QUERY-PROVIDER_当前关系源端条件查询中性提供者详细设计_v0.1.md`

## 4. 实施步骤

### 4.1 中性 DTO 与服务入口

1. 在 `L1中性CRUD.数据.h` 按详细设计 §4.1 新增 `L1中性源关系读取请求` 和 `L1中性源关系读取结果`，默认全等；不修改现有 DTO 或合同版本。
2. 在 `L1事实基座服务` 新增唯一 const `读取中性当前源关系组`；无效版本或零编码返回入口拒绝、代次零、空组。
3. 有效请求只委托仓库同名入口；`bad_alloc` 映射资源失败，其它异常映射内部不一致。所有非成功结果保持请求回显、代次零和空组。

### 4.2 源端派生索引

4. 在仓库 `状态` 中并列新增源 + 关系类型到当前关系稳定编码有序组；只保存编码，不复制关系事实。
5. 新增 `插入当前源关系索引`、`删除当前源关系索引`、`派生当前源关系索引` 三个私有 helper，规则与 P10 目标索引对称。
6. 中性提交候选的新关系加入权威表后，依次插入源索引和目标索引；任一失败返回内部不一致且不交换候选。
7. 中性退出当前关系时，在删除权威关系前依次从源索引和目标索引删除；任一失败不交换候选。
8. legacy 提交候选的新关系和退出关系执行同样顺序；不得遗漏任一路径，不得建立第二仓或第二发布。
9. 扩展 `状态完整`，使用独立已索引集合分别验证源索引和目标索引都恰覆盖全部当前关系；两个索引不能共用一个覆盖结论。
10. 状态材料转当前状态时，在权威当前关系已形成后分别纯派生源、目标索引；不修改材料、恢复入口、状态、SQL或测试。

### 4.3 仓库查询

11. 新增仓库 const `读取中性当前源关系组`；有效请求后取得一次既有共享锁，只查请求源 + 类型桶。
12. 桶不存在返回成功空组和当前事实代次；桶存在则按稳定编码逐项回读 `当前关系`。
13. 验证编码非零、严格升序、权威关系存在、编码 / 源 / 类型全等且无退出代次；任一矛盾清空临时组并返回内部不一致、代次零。
14. 全部完整后返回成功、当前事实代次和完整中性关系组。不得调用 `状态完整`、任一全量派生、目标查询、完整快照、历史、审计、恢复、SQL、旧管理索引或日志。

### 4.4 记录

15. 专属施工记录只记录五路径实际改动、两个索引不变量、异常和未覆盖范围。
16. 专属构建验证记录只记录真实构建、模块扫描和静态门禁；不得写“第一层验收通过”“生产消费者通过”或“第一层已完善”。

## 5. 状态与不变量矩阵

| 场景 | 第一层结果 | 权威变化 |
| --- | --- | --- |
| 无效合同或零源 / 类型 | 入口拒绝、代次零、空组 | 零 |
| 合法源 + 类型零命中 | 成功、当前代次、空组 | 零 |
| 一项当前关系 | 成功、有序一项 | 零 |
| 多项当前关系 | 成功、按关系编码严格升序的完整组 | 零 |
| 索引空桶、悬空编码、字段或生命周期矛盾 | 内部不一致、代次零、空组 | 零 |
| 分配异常 | 资源失败、代次零、空组 | 零 |
| 候选索引维护失败 | 写入内部不一致，不交换候选 | 零普通可读变化 |

每次成功新建 / 退出关系后，权威当前关系、源索引和目标索引必须通过同一次既有状态交换可见。
