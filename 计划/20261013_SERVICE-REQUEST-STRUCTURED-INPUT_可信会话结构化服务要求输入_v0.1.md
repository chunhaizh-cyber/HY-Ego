## 1. 目标、裁决与完成边界

实现一条实际可调用的输入路径：可信本机启动者显式指定既有人类 → 本次网页会话绑定 → 人类填写结构化目标 → 自我按结构重新表达 → 同一会话明确确认该份表达 → 正式、可重新读取的服务要求材料。

它为后继“获取服务任务”本能函数提供真实条件材料；本叶不发布自我需求、不创建任务、不增加服务值、不调用现实改变方法，也不伪造方法条件结果对。输入人类服务要求不是已经成立的自我需求。服务对象固定为要求的目标存在。

用户已明确：本轮采用结构化输入和明确绑定、确认，不实现自由文本理解；不得将任意访客视作第一权限人。六字段沿既有需求目标合同：目标存在、特征类型、目标形式、目标域、比较关系、方向；值目标和方向目标严格二选一，不强迫六项同时非空。

本叶不是本能方法：它观察并组织人的要求材料，不执行需求满足，不主动修改服务对象目标特征。浏览器展示预览仅服务用户发起的输入交互，不构成服务任务完成证据。

## 5. 服务要求结构及 owner 合同

文件 `业务/服务要求.结构化.h/.cpp`，类名 `结构化服务要求服务`。不新建需求树/请求注册表/第二事实仓。初始化取得一个普通自然语言场景，作为本次网页表达材料的容器；owner 的类型/字段锚采用基础数据集节点，按本项目当前类型字段惯例初始化，只缓存锚引用。空场景在初始化阶段合法，初始化失败不允许接收要求。

物理结构：

目标核验机械步骤沿当前`新_需求类.cpp::目标形状合法/比较关系适用于目标`：

1. FT非零；值形式恰有非零域与比较概念、方向为空；方向形式域与比较均空且方向为增加/减少。缺必填返回目标不完整，多余分支字段/非法枚举返回目标不合法。
2. 调用`概念_特征类::比较单特征概念(FT,FT)`，状态已完成且返回特征类型根等于FT，才是合法目标FT。资源失败映射资源失败，其余不可读取映射结构不一致，不能自动创建类型。
3. 值目标对域调用同一函数`比较单特征概念(域,域)`，要求返回根为FT；不等返回目标不合法。域必须由`获取特征概念(域)`完整读回，空值失败关闭为结构不一致。
4. 用`概念_二次特征类::获取二次特征概念(比较编码)`获取完整比较定义；空值失败关闭为结构不一致。其`参照特征概念节点`必须恰等于目标域；遍历输入定义组，每个`来源种类==特征准确值`项必须有特征类型引用，且用`比较单特征概念(输入类型,输入类型)`取得的根为FT；至少存在一个这样的特征准确值输入。其它来源种类按既有需求适用性函数不参与本项核验，不凭名字补推测。此步骤不扩张/改变既有需求的比较算法准入语义。
5. 每次确认及确认查询重新核验上述资格。来源不属于人类返回来源不合法；合法结构中的目标不匹配返回目标不合法；底层读取/结构错误不得当作人类否认。不开放需求受限建立入口，不建立任何需求节点。

以上核验在新owner私有纯验证函数实现，直接复用公开概念读取和比较，不为调用现有私有helper而改变需求类可见性。

每次写在 owner 唯一进程互斥中读取完整语言场景材料、核验、查重、调用L1原子建立（上级节点为空）。相同来源+公开会话+完整目标返回同一理解；相同来源+会话+理解返回同一确认。若读到两份应唯一的结构、缺字段、多字段、错误类型或引用不闭合返回结构不一致，不随意选一份。查询以语言场景+owner所属字段的一次L1反向引用结构快照同时取得理解及确认，重建类型和完整关联；缺失引用不当作无确认。跨概念owner不宣称公共快照，确认前重新核验概念资格，底座发布再次核验引用端点。

已确认材料保持到普通应用数据生命周期结束；关闭会话不删除已存在确认事实，但新会话不能以旧会话名继续确认。没有“确认自动建需”或“确认自动增加服务值”。不增加持久历史、撤回/删除API及TTL；后继若需取消，应另行冻结取消语义。

### 5.1 固定语义、原子快照与重新确认

`新_特征类::新特征信息.实例区间值`已有固定区间表达，应复用其`特征概念值域`类型及现行域物理编码。但现有区间特征建立是分步发布，且单位/材料/比较语义仍依赖可变概念，不能直接调用它再挂理解来冒充联合原子快照。因此本叶只在服务要求owner内保存**语言理解的具名语义组成节点**，不建新特征概念或世界特征，不改现有实例特征生命周期。

公开快照DTO（位于理解信息之前声明，均有默认值相等运算）：

```cpp
struct 服务要求特征语义快照 {
    稳定编码 概念节点;
    特征概念材料物理类型 材料类型;
    std::optional<稳定编码> 单位;
    特征概念比较规则 比较规则;
};
struct 服务要求值域语义快照 {
    服务要求特征语义快照 特征语义;
    特征概念值域 值域;
};
struct 服务要求比较语义快照 {
    稳定编码 比较概念节点;
    稳定编码 类型根节点;
    二次特征算法 算法;
    std::vector<二次特征概念输入定义> 输入定义组;
    std::optional<稳定编码> 参照概念节点;
    服务要求值域语义快照 输出语义;
    std::vector<二次特征结果域种类> 结果域种类组;
};
struct 服务要求目标语义快照 {
    服务要求特征语义快照 目标类型;
    std::optional<服务要求值域语义快照> 目标域;
    std::optional<服务要求比较语义快照> 比较;
};
```

快照来源：目标类型的材料类型/单位/比较规则来自FT完整概念；值目标的目标域及其材料、单位、比较规则来自目标域完整概念；比较来自完整二次概念（算法、有序输入、参照、类型根、输出概念及输出域、结果域种类）。方向目标仅保存目标类型语义及原方向，不虚造域/比较。名称关系、引用次数、聚合规则和无关上位区间不参与语义相等；类型根及输入类型根身份参与。材料集合项只引用现有不可变特征值节点；单位/分量角色按当前正式身份语义比较，不复制它们的显示名称。

物理编码统一用owner字段锚，以下为完整封闭schema：

| 节点类型 | 恰一/可选字段及内容 |
| --- | --- |
| 目标语义 | 目标类型快照引用恰一；目标域快照引用和比较快照引用随值分支成对存在 |
| 特征语义 | 来源概念引用、材料类型I64、比较规则I64各一；单位引用0..1 |
| 值域语义 | 特征语义引用恰一；域种类I64恰一；域内容按下一段 |
| 比较语义 | 来源比较概念引用、类型根引用、算法I64、输出值域语义引用各一；参照概念引用0..1；输入项引用多项；结果域种类I64数组恰一 |
| 比较输入项 | 顺序I64、角色I64、来源种类I64各一；特征类型引用0..1，沿原输入定义合法性 |
| 结构化域分量 | 顺序I64、角色引用、I64区间端点数组各一；单位引用0..1 |

所有组成节点还有类型字段和所属语言场景字段各一；理解新增目标语义引用恰一。域种类固定：1=I64闭区间组，2=全材料，3=不可变特征值集合，4=结构化I64；不存在5的伪降级。1保存专用区间端点I64数组，下上交替、偶数长度、按原域规范化顺序；2不带其它内容；3每个值用独立节点引用字段、按编码规范化去重；4每分量用独立引用字段，分量自身顺序保存维度次序。不得把节点编码写到I64/U64数组、JSON、文本或哈希中。二次输入顺序必须完整无重复；结果域枚举数组只保存枚举，不承载身份。

全部快照组成及理解一次`原子建立节点组`发布；确认只需单节点原子建立并引用已有理解。理解生成前捕获概念语义；发布后若再次fresh读取已变化，返回需重新确认，不把新理解显示为已确认。确认时fresh捕获当前语义，与固定语义逐字段值相等且六字段资格仍合法才能发布确认；不同返回需重新确认、零新确认。只读`读取理解`返回固定内容供页面重新显示；不得重新从可变概念拼出不同重述却沿用旧理解身份。

显式材料枚举逐项通过注入的`新_特征值类::获取特征值`确认是现有不可变值节点，空optional失败关闭结构不一致；不接受任意存在/概念编码冒充材料。语义快照编码/解码属于本owner私有函数，严格验证上述类型、字段基数和分量/输入次序；任何节点缺失、重复字段或跨语言场景拼接均拒绝。概念元信息读取失败不发布理解，即使六字段编码表面合法。

`查询已确认要求`返回项增加`bool 需重新确认`（位于`服务要求确认信息`）。查询同时保留旧确认事实与固定目标语义，并按当前概念fresh比较设置该标记；标记不是持久状态或新版本，不修改原确认。所有后继消费者必须拒绝标记项并重新获取预览/确认，不能把它用作建需输入。任一底层读取失败返回具名失败且空组，不将失败简化成语义变化。确认入口结果状态需重新确认时信息为空，客户端要求重新预览，不自动点击确认。概念变化后即使域只收窄也重新确认，不自行认定“更安全所以沿用”。

不宣称跨概念owner公共快照或无限期有效：确认和消费各自fresh核验，当时读到的语义不等于未来不会变化；此时保存的确认始终只指固定材料。消费者不允许仅凭曾经确认而跳过当前语义检查。存在引用域在目标域、FT材料为存在引用、输出域任一位置出现均返回语义快照暂不支持，零理解/确认写入；这项明确能力缺口记录到施工结果。

## 6. 可信会话与启动合同

`启动选项`新增 `std::string 本次网页会话服务对象登录名`，默认空。参数固定为 `--web-service-object-login=<UTF8登录名>`；只在普通控制面板模式合法，拒绝空、重复和其它模式组合。解析保留 noexcept，字符串分配异常返回新增 `资源失败`，不能进程终止。仅语法解析不访问人类节点；装配按既有登录名特征值精确解析，要求唯一既有人类。本轮只有已初始化第一权限人可匹配，不创建新登录人、不把未知名回退为第一权限人。

普通应用配置加入同名默认空字段，参与原配置等值比较；`运行新版普通程序`传完整配置，禁止中间丢参数。配置匹配失败返回明确装配失败，不启动带错误身份的服务端。

宿主保留系统随机 URL 令牌作为私有 bearer secret；再独立生成公开会话标识，回调只传后者。两者不可相等、不能相互推导，不能把secret写日志、世界特征、语义节点或JSON响应。现有文本入口也改收公开标识；默认未绑定时继续原匿名消息能力，但不准访问结构化服务要求写入口。

宿主新增配对开始/结束回调：在会话租约开始成功后、打开浏览器前通知开始；成功开始后全部退出分支（浏览器启动失败、正常关闭、异常、停止）由RAII恰好结束一次。装配按配置保存公开会话→既有人类的进程绑定；默认空为匿名，不能自动绑定。结束原子失效并清空会话缓存；刷新网页不新建会话。

可信已绑定文本会话引用同一既有人类，不能再新建匿名替身或把公开会话FT写到该人身上。匿名文本路径保留既有行为；两路径都继续真实消息观察与消息数更新。若既有匿名会话关闭后装配仍保留拒绝新会话的槽位，同步按结束通知清理仅本会话投影，不删除既有存在/状态/动态。

本合同是“可信本机启动者指定身份”，不是密码认证；持有URL的本机浏览器/进程共享该身份。页面输入的姓名、登录名、目标人ID不能改变绑定。不添加HTTP身份绑定端点，不开放非loopback监听，不声称可防止已获得URL者冒用。

状态映射：owner已建立/已读取→网页已完成，已复用→已复用；目标不完整→输入不完整；目标不合法→输入不合法；来源不合法/确认对象不匹配→对象不匹配；理解不存在、会话失效、资源失败、结构不一致、需重新确认、语义快照暂不支持对应同名；未初始化→结构不一致；会话未绑定→未绑定。失败清空信息/提示载荷，成功时编码非零、信息完整。装配空上下文返回结构不一致，不把它当匿名。

网页增加明确的结构化表单：目标人只读；FT、域、比较概念填写正式概念编码，形式/方向使用固定枚举选择，禁止将标签字符串作为概念。options仅提示既有人类当前特征上的FT及当前采用概念，不是全概念库下拉；表单允许输入其它已知正式编码，服务端完整核验。提示生成先`存在服务.获取存在`取得完整特征节点组，逐项`特征服务.获取特征`及概念owner核验，去重排序FT+采用概念；空optional失败关闭结构不一致，异常资源失败，禁止用失败的空vector当成功无特征。此提示不裁决目标合法性、不承诺跨owner公共快照，不因提示未包含某正式概念而拒绝该目标。表单可以先不完整，但仅完整合法目标可生成预览；字段缺失明确标为未完整，不能填0或任意默认代替。

HTTP 使用当前完整私有令牌路径下的新路由：GET `/api/service/options`，POST `/api/service/preview`，GET `/api/service/preview?id=...`，POST `/api/service/confirm`。POST采用严格 `application/x-www-form-urlencoded`、重复字段拒绝、未知字段拒绝、整数用from_chars完整消费、不接受负编码/0/溢出；UTF8校验沿现有宿主。preview只接 `ft,form,domain,comparison,direction`，值分支拒绝direction，方向分支拒绝domain/comparison；confirm只接 `preview`。服务对象与会话从可信回调取，不能从正文接入。

装配新增相应具名入口：`预览普通应用服务要求`、`读取普通应用服务要求预览`、`确认普通应用服务要求`、`查询普通应用服务目标选项`，均在上下文锁内检查活跃会话绑定，调用owner，返回有类型的状态和数据。预览响应包含正式理解节点编码及服务器重述：“目标人/目标FT/达到目标域并采用比较关系”或“目标FT沿指定方向变化”，并明确“尚未确认”。概念名称可经词类获取；无词条时显示稳定编码，不猜词义。浏览器用textContent显示，不插入HTML。

服务器重述必须从理解返回的固定语义生成，并列明FT材料型、单位身份、比较规则、目标域的完整区间/不可变材料/结构化分量、二次算法及输入和结果域。不得只显示可变概念名称而隐藏本次确认的具体语义；材料集合可读取其不可变值正文辅助展示，节点身份同时保留。所有数值/身份的JSON传输均用十进制字符串，避免浏览器Number损失uint64/int64精度；JS原样传回字符串，不做概念编码算术。名称仅作标签，不进入固定语义判等。

确认按钮绑定最后成功显示的预览编码；编辑表单立即取消本页按钮绑定，但服务端安全性不依赖JS。确认服务端重新读理解，确认所属语言场景、同一会话、同一人及完整目标后才原子建立确认。正文中“是/好/可以”不调用确认，不靠自然语言无序场景相等自发产生确认。返回已确认编码及原理解。

重试preview使用完整内容查重，重试confirm使用理解身份查重；HTTP回执丢失不新建第二事实。编辑后是新理解，确认旧理解只确认旧内容而非新内容；UI明确显示最终确认内容。不存在同一编码内容变化的版本号问题。

HTTP非成功：语法/目标不完整400；未绑定或会话失效403；身份/理解不匹配或需重新确认409；无此理解404；语义快照暂不支持422；结构不一致/资源失败503。没有失败返回“已确认”。新GET响应也继承no-store/no-referrer/CSP；读取端点不能跨会话读取他人理解。不要把工程读取错误包装成“用户拒绝”。

## 8. 实施顺序与失败收口

1. 读取本叶相关规范、源码、知识条目并确认独占工程/装配/L1资源，记录S0。
2. 实现最小L1单节点/节点组原子入口及两种完整查询，确保原子强保证和完整读取；不动其它领域旧写路径。
3. 实现服务要求owner、类型/字段初始化、不可变理解及确认，连接语言场景与既有概念验证。
4. 实现CLI穿透、会话公开/私有标识分离及RAII生命周期；确认默认匿名未被升级。
5. 接通网页表单、装配回调及正式材料读回，保持旧文本功能及消息统计。
6. 集中编译实际工程、静态检查及证据；没有当前测试指令，不启动应用、不运行专项自检。
