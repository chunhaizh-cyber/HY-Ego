# WEB-TEMP-SCENE-SOURCE 临时交互场景同窗来源提供实施计划

版本 v0.1，基线 main 9a0ae25a0378da96688a73515cf3d846251f666f。唯一所有者为本指挥窗口，主工作区 D:/海中鱼巣。上游是 7eb061b9acb19fd508cb3959bddd3f4a9b433962 正式确认事实与 9a0ae25a0 身份边界。规范见 [6120 §11.1](../规范/6120_子规范_自我存在服务与生存基本因果闭环.md)、[7241 §1](../规范/7241_子规范_句子转换与交互场景同步.md) 与[确认实证](../验证记录/20261127_WEB-INTERACTION-CONFIRM-FACT_普通网页明确交互确认事实验证.md)。

## 目标及交付

先闭合外设所有者给内部治理的正式材料。完整只读材料必须同时含同会话、同对话框、正式窗口、确认为本窗的回执及外设场景中独立的局部交互者。现行 读取本次网页交互确认 已核确认和窗口，但只返回确认、场景、窗口、时间；按场景读取交互场景另一次提供匿名端点。将两者置于现行正式确认 GET 所实际调用的外设 owner 只读路径，不改变既有确认回执语义、网页响应形状和写口。材料只能供核验本窗匿名端点，无内部身份、现实采信或跨窗等同。

## 目标函数、合同及顺序

1. 在 新_外设世界树类.h/.cpp 定义 新外设网页临时场景来源结果，包含原确认结果及可选本窗外设对端。新增 读取已确认临时场景来源(公开宿主会话, 对话框标识)。新旧两条读取复用一个既有定位合同及原确认读取实现，不新增存储字段或事实。
2. 新入口在外设互斥内取正式窗口定位、核原确认（仍用 读取窗口确认），只在已确认时读取同场景并以 区分窗口与交互者 复核窗口与真实的场景成员键。已确认但没有该窗对端为未就绪；不凭登录状态、名称、其它窗口或消息重填。窗口及对端结构错配为结构不一致。资源失败与未确认分开。已有成功材料同源重读不写入；任何一步失败不返半个对端。
3. 装配.网页外设.cpp 的普通确认 GET 在已核活跃会话和页面后消费新入口，仅投影现行 HTTP 回执，禁止暴露外设对端裸编码。POST 仍只记录原确认事实，因此材料未就绪不回滚已发生的确认。内部后继将调用同一读口；不在网页回调中建内部场景。
4. 精确允许三源码文件和本片专属 Markdown 验证。禁止修改 scene 成立、真实成员、任务、需求、语言角色、真实关系/可信度、账号验证、工程或测试专路。选择本片是外设 owner 与场景/自我 owner 的真实合同边界；两个候选 E、原子发布和现实扫描隔离由直接后继统一闭合。

## 创建侧核验和验收

已有普通网页创建时在对应外设场景建立匿名交互者（新_外设世界树类.cpp:895），现行正式 区分窗口与交互者 已保证窗口与至多一个对端（:616）；现行 GET 会话范围见 装配.网页外设.cpp:169。静态反查原接口，不能影响确认 POST、已有 HTTP 状态、读取零写入或旧资料。实际 Release x64 完整工程，核编译输入；普通网页在隔离库开两窗，均未确认；只确认 A，A GET 成功、B GET 未确认，错会话拒绝，同窗重投同一确认；再确认 B 而各窗仍独立。借原正式隔离数据库只读证据核两个外设匿名端存在且不同、各属各自外设场景；不能宣称内部临时场景已建立。保留 HTTP、正式拥有者读口、源码摘要、同 PID 自然退出 0。实际失败按 AGENTS §7.1。运行后确认事实仍各自独立，无新增内部场景、身份、需求或采信。七组完整验收不计入。
