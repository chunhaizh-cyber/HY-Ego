## 1. 目标、范围与完成条件

在 4230 v0.3、G2、E-ID / F-ID 与 T1 / T2 已发布真实 ABI 之上，新建唯一 `L2动态结构服务`：建立动态专属 owner、身份来源与十一项结构类型登记，以一份 owner-scoped L1 写集原子新增动态节点、族归属、主体 / 前状态 / 后状态三关系和起始 / 结束两值，并完成单项当前 / 历史完整读取及按主体、前状态、后状态三类当前条件查询；同时把动态 owner / 服务作为普通应用唯一 provider 的下一个前缀装配。

完成必须同时满足：

1. `L2动态所有者交付` 不可默认构造、不可复制、只可移动且不公开 raw 写端口；唯一形成函数只接受绑定同一 L1 实例和精确动态 owner 的交付；
2. 服务构造先移动并验证动态 owner-scoped 端口，再建立动态族锚点、族归属关系类型和十一项结构类型；任一初始化失败抛出，普通应用不发布半构造服务；
3. 新动态以一份 owner-scoped 写集同代建立一个普通节点、唯一非自环族归属关系、主体 / 前状态 / 后状态三关系、起始 / 结束两值及两个属性槽变更，共七个权威事实编码；
4. 主体以 E-ID `读取存在身份来源` 证明，前 / 后状态分别以 T1 / T2 最终 `读取状态身份来源` 证明，三个来源与本族提交共享同一期望事实代次；
5. 主体、前状态、后状态是三个独立强类型角色；不要求动态主体等于任一状态主体，不要求前后状态不同、状态值变化或起始时间早于结束时间；
6. 动态当前 / 历史身份来源、完整动态、四条自有关系、两值、属性槽和三个外部端点在一个当前一致投影或一个历史截止闭环；零混代、零当前补历史；
7. `新增动态`、`读取完整动态`、`按主体读取全部当前动态`、`按前状态读取全部当前动态`、`按后状态读取全部当前动态` 以及登记 / 来源接口的非成功状态精确分账，非成功空载荷；
8. 三类条件查询允许合法空组，返回组按动态身份稳定编码严格升序、无重复且共享请求截止；不选最新、不按时间排序、不合并材料相似动态；
9. 普通应用保持 `存在 -> 特征定义 / 实例 -> 状态 -> 动态` provider 前缀，唯一持有动态服务并提供同实例 const / 非 const getter；
10. 根工程只新增一个动态模块和一个数据头，临时验证三文件不进入主工程；结果与永久记录发布、交互接受、计划退出后，三份临时文件由独立清理提交精确删除；
11. 生产代码零旧中性写面、零验证实体、零历史状态 / 动态复用、零业务状态比较、零自动动态生成、零第二服务 / 仓 / 索引 / 缓存 / SQL / 日志。

本叶不实现 DYN2 的引用替换、时间值换代、动态退出和外部引用闭包，不实现因果、场景迁移、A1 或世界树业务解释。

## 4. 动态 owner、身份来源与结构类型登记

### 4.1 owner 交付

动态服务模块公开：

```cpp
inline constexpr L1所有者范围建立幂等身份 动态所有者建立身份{
    0x4C31'4F57'4E45'5235ULL};

class L2动态所有者交付 final;

std::optional<L2动态所有者交付> 尝试形成L2动态所有者交付(
    const L1事实基座服务& 第一层读取服务,
    L1所有者范围交付&& 原始交付) noexcept;
```

`L2动态所有者交付` 删除默认构造、复制构造、复制赋值和移动赋值；移动构造 `noexcept = default`，只能由 `L2动态结构服务` 友元消费。形成函数证明交付合同、owner 建立身份、独占结构范围、同一 L1 绑定及端口有效；不公开 raw 端口、owner 选择或转签。


`建立动态结构类型登记` 使用动态 owner-scoped 端口，以一份只有十一节点的新建写集建立登记；关系、值、属性槽变更和退出事实均为空，十一节点 owner 全部等于动态 owner，禁止调用旧 `提交中性写集`。`已提交` / `精确重复` 必须取得十一项本地键到十一项不同非零稳定编码的一一映射，并从首次代次 owner-aware 历史入口逐项证明节点种类和八种属性表示；同一完整请求精确收敛，同身份异合同 / 规则 / 期望代次或异写集返回幂等冲突。完整登记要求合同与规则正确、首次身份 `{1}`、首次期望事实代次非零、建立事实代次非零、截止不早于建立代次、十一身份非零且两两不同。

`读取当前动态结构类型登记` 只消费服务私有值式定位，经 owner-aware 一致当前投影读回十一节点；允许一次完整漂移重读，不扫描全仓、不猜测稳定编码。只有 `已提交`、`精确重复`、`已读取` 携带完整登记并可使 `成功()` 为真；其它状态登记为空。构造在来源初始化之后以当前事实代次调用 `建立动态结构类型登记`，登记失败抛出；私有定位不是身份仓、缓存权威或恢复入口。

## 6. 七事实原子新增、幂等与首次读回

七事实写集的全部本地键固定为：

```text
动态节点本地键         = 0x0205'1001U
动态族归属关系本地键   = 0x0205'1002U
动态主体关系本地键     = 0x0205'1101U
动态前状态关系本地键   = 0x0205'1102U
动态后状态关系本地键   = 0x0205'1103U
动态起始值本地键       = 0x0205'1201U
动态结束值本地键       = 0x0205'1202U
动态端点角色           = 1
```

流程固定为：纯值校验 -> 读取已加载动态类型登记 -> 按材料选择两类型 -> 构造不可变 owner-scoped 写集 -> 探测当前事实代次 -> 同期望时分别调用 `读取存在身份来源(当前)` 与两次 `读取状态身份来源(当前)` -> 核对三来源截止等于请求期望 -> 恰一次提交 -> 从首次代次 owner-aware 历史事实重建首次结果。

唯一写集：

```text
节点 = [动态普通节点]
关系 = [
  动态节点 -> 动态族锚点，类型=动态族归属关系类型，角色=1，
  动态节点 -> 请求主体，类型=主体关系类型，角色=1，
  动态节点 -> 请求前状态，类型=前状态关系类型，角色=1，
  动态节点 -> 请求后状态，类型=后状态关系类型，角色=1
]
值 = [起始值，结束值]
属性槽变更 = [起始角色槽 -> 起始值，结束角色槽 -> 结束值]
退出事实 = []
```

节点、四关系、两值的 owner 都必须等于动态 owner；动态节点与族归属关系同代创建，族归属非自环。成功 / 精确重复取得七个本地键到七个不同非零编码的一一映射。首次历史读回证明七事实、两槽发布、类型 / 材料 / 来源、三端点来源及首次代次完整；不得用调用时当前事实替代首次结果。

普通 DYN1 幂等身份完整 64 位映射为 owner-scoped L1 写入幂等身份，不进入来源或类型登记私有域。同键同完整请求返回首次载荷；同键异任一字段为幂等冲突；新键旧期望为漂移；发布结果未知只允许原键、原请求、原期望重提。提交前非成功零变化，提交后读回失败不得宣称零变化或补偿回滚。

## 7. 当前、历史与条件读取

### 7.1 当前完整读取

以一次 owner-aware 一致当前投影读取动态节点、族归属 / 主体 / 前 / 后四个具名源关系组及起始 / 结束两槽和值。投影同时闭合 `读取动态身份来源` 所需 owner、锚点和归属材料，或用相同截止的来源结果互证；不得跨代拼装。

随后在同一期望代次调用存在来源和前 / 后状态来源，第二次复核动态当前投影未漂移。四关系各恰一项、owner / 源 / 目标 / 类型 / 角色正确；两值各恰一个角色、所属动态、owner、表示、来源和生命周期正确；所有结果截止相等。未找到、已退出、许可、漂移、资源精确映射，结构缺项 / 复义 / 混代为内部不一致。

### 7.2 历史完整读取

固定流程：当前事实代次等于期望 -> 读取动态 owner、节点、来源、四类历史关系组、历史属性值组 -> 以同一历史截止调用存在来源和两次状态来源 -> 再次确认当前代次未漂移 -> 重建截止投影。

截止早于动态创建返回未找到。截止达到创建后返回完整动态；如果未来 DYN2 使动态在截止前退出，历史入口仍返回 `已读取` 和节点、四关系、两值的完整退出生命周期，不能返回 `已退出` 空载荷。选择截止有效结构时可按退出前一代选取，再把实际退出生命周期投影到请求截止；当前入口才返回 `已退出` 空载荷。DYN1 专项没有合法动态退出入口，因此该后继兼容分支由 DYN2 修订后的专项强制验证。

### 7.3 三类当前条件查询

每个查询先调用对应身份来源证明端点，再从动态 owner 的一致当前投影读取对应目标关系组；每条关系的源必须是具有正式动态来源的当前动态节点。对唯一源编码逐项调用 `读取完整动态(当前)`，要求同截止且目标角色等于请求。合法端点无动态返回已读取空组；不存在、已退出、wrong-family、许可、漂移、资源或内部失败返回对应非成功与空组。组按动态身份升序，无部分返回。
