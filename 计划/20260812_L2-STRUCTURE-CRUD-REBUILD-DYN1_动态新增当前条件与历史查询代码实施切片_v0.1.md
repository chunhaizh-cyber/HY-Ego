`建立动态结构类型登记` 用一份 L1 写集建立十一个类型节点，关系 / 值 / 槽 / 退出为空。成功 / 精确重复必须取得十一个不同非零稳定编码映射，并按首次代次历史读回节点种类和八种属性表示；服务私有保存只读值式定位。

`读取当前动态结构类型登记` 只按私有定位用一致当前投影读取十一节点，允许一次完整漂移重读；未加载返回登记未加载，不扫描全仓、不猜测稳定编码。登记建立必须在动态 CRUD 并发使用前单线程完成；DYN1 不允许登记写与 CRUD 并发，也不为此新增服务锁。普通操作遇到登记未加载映射为 L2 `入口拒绝`，登记许可 / 漂移 / 资源 / 内部失败映射同名共同状态。

十一个节点只标识动态内部结构角色和材料表示，不解释主体资格、状态差异、时间单位、变化重要性或动作归因。

全部 DTO 提供逐字段默认比较。新增要求合同、非零期望代次 / 幂等 / 主体 / 前状态 / 后状态 / 来源，两份材料分别满足共同材料形状：I64 任意，I64 组 / U64 组非空，独立材料编码非零。前状态与后状态相同合法。单项当前要求历史截止为 0；历史要求 `0 < 历史截止事实代次 <= 期望事实代次`。条件请求只接受非零期望代次和对应端点身份。

`L2动态事实完整` 以登记和具名截止为输入，要求动态、主体、前后状态、来源和生命周期完整；起始时间只匹配起始四类型之一，结束时间只匹配结束四类型之一；两值材料表示与登记节点表示一致、值编码不同、来源相等且等于顶层来源、在同一截止有效。两值所属动态只能在 L1 正式读回形成 DTO 时核对，不能由不含所属字段的 `L2属性事实` 纯值投影伪造证明。动态当前投影不携带退出代次；历史旧截止不得暴露未来退出。

两个 `成功() const noexcept` 只核对结果头、载荷组合、身份 / 生命周期、非零编码和稳定排序等不依赖私有登记的值式形状。起始 / 结束时间是否属于登记八类型、材料表示、值所属动态、两值来源互证和三关系类型 / 角色，必须由服务使用已加载登记在返回前验证；执行者不得把无登记参数的 `成功()` 当成完整结构预言机。

写入成功只接受 `已提交 / 精确重复`、非零且相等的截止 / 变更代次、一份完整动态和三关系引用。组成功只接受 `已读取`、非零截止、无变更代次、严格按动态身份升序且无重复的完整当前动态；空组合法。所有非成功的动态、自有关系和组均为空。

## 7. 新增动态的一份 L1 写集

本地键和角色固定：

```text
动态节点本地键        = 0x0205'1001U
动态主体关系本地键    = 0x0205'1101U
动态前状态关系本地键  = 0x0205'1102U
动态后状态关系本地键  = 0x0205'1103U
动态起始值本地键      = 0x0205'1201U
动态结束值本地键      = 0x0205'1202U
动态端点角色          = 1
```

流程固定为：

```text
纯值校验
-> 读取当前动态结构类型登记
-> 按两份材料选择起始时间角色 / 结束时间角色的登记类型
-> 构造不可变 L1 写集
-> 探测当前事实代次
-> 实际代次 != 请求期望：恰一次直提原写集，由 L1 裁决重复 / 冲突 / 漂移
-> 同期望：读取完整主体存在(当前)、读取完整前状态(当前)、读取完整后状态(当前)
-> 核对三个端点身份、当前性和同一截止；不比较状态内容或主体字段
-> 恰一次提交
-> 从首次代次历史节点、关系、属性值和端点重建首次结果
```

唯一写集为：

```text
节点 = [{动态节点本地键, 普通, 无属性类型表示}]
关系 = [
  {动态主体关系本地键, 源=动态节点本地键, 目标=请求主体,
   类型=登记主体关系类型, 角色=1},
  {动态前状态关系本地键, 源=动态节点本地键, 目标=请求前状态,
   类型=登记前状态关系类型, 角色=1},
  {动态后状态关系本地键, 源=动态节点本地键, 目标=请求后状态,
   类型=登记后状态关系类型, 角色=1}
]
值 = [
  {动态起始值本地键, 所属=动态节点本地键,
   类型=按起始材料选择的登记类型, 材料=请求起始材料, 来源=请求来源},
  {动态结束值本地键, 所属=动态节点本地键,
   类型=按结束材料选择的登记类型, 材料=请求结束材料, 来源=请求来源}
]
属性槽变更 = [
  {动态节点本地键, 起始登记类型, 动态起始值本地键},
  {动态节点本地键, 结束登记类型, 动态结束值本地键}
]
退出事实 = []
```

DYN1 不比较前 / 后状态的主体、特征、精确值、时间值或生命周期，也不比较起始 / 结束材料；调用方可提交同一状态作为前后端点。主体只经存在服务公开读取证明其为完整 `L2存在身份`，不取得存在业务资格解释。

成功 / 精确重复必须取得六个本地键到六个不同非零编码的一一映射，首次事实代次和发布 / 重试边界正确。首次历史读回必须证明普通动态节点、三条同代次关系，以及历史属性值组中起始 / 结束角色各恰有一个首次截止有效值；两个值必须同代次、类型 / 材料匹配、共同来源且三个端点在首次截止有效。历史属性值组候选来自成功属性槽变更，但不返回历史槽对象；首次提交后若当前仍处于首次代次，可以用一致当前投影补充核对槽指向，后继事实已经推进后的精确重复不得依赖当前槽。不得用调用时当前端点或属性替代首次结果。任一缺项、多项、错类、错端点、错角色、错来源、混代或材料表示不符返回内部不一致，不二次提交。

## 8. 单项当前与历史完整读取

### 8.1 当前读取

先读取当前动态结构类型登记。第一轮 L1 一致当前投影请求目标动态节点和主体 / 前状态 / 后状态三个具名源关系组；节点必须是当前普通节点，关系组各恰一项、源为动态、类型匹配、角色 1、目标分别形成主体 / 前状态 / 后状态身份，三关系当前且同截止。节点当前属性槽必须恰有两项：一项属于起始时间四类型，一项属于结束时间四类型。

随后以同一期望代次调用存在服务公开入口读取主体完整当前投影、调用状态服务公开入口读取前 / 后状态完整当前投影，再用第二轮 L1 一致当前投影重读同一动态节点、三关系组和两项具名属性值。前后节点 / 关系 / 槽逐字段相等；两值所属动态、类型角色、材料表示、来源和生命周期同截止，形成完整动态和三关系编码。存在 / 状态服务只分别证明三个强类型端点完整，不要求状态主体或值与动态其它字段相等。

目标动态未找到 / 已退出按同名返回；登记、许可、漂移、端点失败和资源精确收口；多槽、少槽、错类型、错关系、端点复义、来源不一或任一部分载荷均内部不一致。全部失败清空动态和自有关系。

### 8.2 历史读取

历史读取固定为：

```text
读取当前事实代次并等于请求期望
-> 读取动态历史节点
-> 按动态为源读取三种历史关系组(历史截止)
-> 读取动态历史属性值组(历史截止)
-> 以同一历史截止调用主体存在、前状态和后状态公开历史读取
-> 再次读取当前事实代次并等于请求期望
-> 重建截止投影
```

截止有效关系必须分别恰一项，截止有效属性必须恰为一个起始角色和一个结束角色；节点当前槽不得补历史。关系、属性、主体节点或状态端点晚于历史截止的未来退出代次在返回投影中清空。动态在截止前未创建返回未找到；截止等于或晚于动态退出代次返回已退出；截止前的完整历史动态返回已读取。

两次当前代次任一变化返回事实代次漂移；历史组入口 / 许可 / 资源失败精确映射；关系、属性、端点、来源或生命周期矛盾返回内部不一致。历史读取不扫描其它动态、不选择最新时间、不比较状态、不生成因果。

## 9. 按主体、前状态与后状态的当前条件查询

按主体流程固定为：

1. 调用存在服务公开完整当前读取，确认请求主体在期望代次是完整当前 `L2存在身份`；
2. 用 L1 一致当前投影同时请求主体节点和 `目标关系组={主体编码, 动态主体关系类型}`；节点必须与存在公开读取身份、当前性和截止一致；
3. 每条关系必须目标为请求主体、角色 1、类型匹配、源为当前普通动态节点；
4. 对每个唯一源动态调用 `读取完整动态(当前)`，要求同一期望代次且主体逐字段相等；
5. 按动态身份编码严格升序返回，重复源、关系与单项读回不一致或混代均内部不一致。

按前状态和按后状态流程同构：先调用状态服务公开完整当前读取确认请求端点完整且当前，再请求对应目标关系组；逐项单读必须返回相同的前状态或后状态。三个查询都允许合法空组，不筛选时间、不比较状态、不返回“最新”动态。

如果任一逐项读取返回许可拒绝、漂移、未找到、已退出、资源或内部不一致，整个组返回对应非成功和空载荷；不得返回部分动态组。所有成功项目的事实截止必须精确等于请求期望代次。

## 10. 状态、幂等、异常和非目标收口

非成功优先级固定为：纯值非法 -> 入口拒绝；登记未加载 -> 入口拒绝；登记其它失败 -> 对应共同状态；既有幂等 -> 精确重复 / 幂等冲突；新键旧期望 -> 漂移；主体 / 前状态 / 后状态未找到或已退出 -> 同名；许可 / 资源 -> 同名；事实矛盾 -> 内部不一致。

普通 DYN1 幂等身份完整 64 位原样映射为 L1 幂等键，不进入动态登记私有 `0x21` 域。同一幂等身份只绑定完整请求。精确重复返回首次动态、两值、三关系和首次代次，零推进；同键异字段冲突。发布未知只能以原幂等身份、原完整请求和原期望代次重提；L1 必须先裁决同键同写集为精确重复、同键异写集为幂等冲突，新键旧期望才是漂移。不得换键、刷新期望或重构材料。

提交前入口、登记、端点、漂移、幂等、许可、资源或内部非成功必须零普通事实变化，结果头不携带变更事实代次。L1 已返回成功后，若首次历史重建发生 `std::bad_alloc` / `std::length_error` 或读回矛盾，公开结果为空载荷并映射资源失败 / 内部不一致，可以回显已安全取得的首次变更事实代次，但不得伪造成功载荷，也不能宣称零变化；只允许以原幂等身份和原完整请求读回收敛，不二次提交、不补偿已发布事实。

DYN1 不引入新锁、仓库、缓存、索引、序列化、恢复、SQL、材料读取器或第二幂等账；服务不持 L1 / 状态内部锁。来源只作为不透明稳定编码由 L1 值事实引用保护，不解释来源类别。

本叶不实现动态引用替换、时间值换代、动态退出、状态比较、主体一致性判断、时间排序、变化重要性、动作归因、因果生成、世界树聚合或生产装配。

## 11. 临时生产外验证矩阵

临时验证 cpp 只 import L1 公开服务、E2 存在服务、F1—F3 特征服务、T1 / T2 状态服务和 DYN1 动态服务。存在、定义、实例、状态、动态登记、来源和材料夹具全部经正式公开入口建立；不得 import 仓库、访问私有定位 / 锁 / 索引 / 幂等账、解析日志或复用历史状态 / 动态实现。

入口参数固定为：

```text
--幂等基值 <uint64，默认71000>
--前状态精确I64 <int64，默认11>
--后状态精确I64 <int64，默认22>
--起始I64 <int64，默认101>
--结束I64 <int64，默认202>
--结束U64一 <uint64，默认303>
--结束U64二 <uint64，默认404>
```

必过矩阵：

1. 建立动态十一类型登记，十一编码唯一非零、三关系节点种类和八种表示精确；原请求重复、同键异规则冲突、未加载、错合同 / 规则 / 身份分账；
2. 经 E2 / F1—F3 / T1—T2 正式入口建立两个主体和至少三个完整当前状态；DYN1 不直造状态端点；
3. 以主体 A、前状态 A、后状态 B 新增动态成功，三关系、两值、两槽、来源和生命周期同代次；状态材料不同只作输入，不由 DYN1 比较或解释；
4. 以前后状态相同、动态主体不同于状态内部主体的受控强类型请求新增成功，证明 DYN1 不擅自增加主体相等、前后不同或变化成立条件；
5. 起始值与结束值相同、结束材料数值小于起始材料仍按结构成功，证明不解释时间顺序；
6. 原新增请求精确重复返回首次完整载荷且零推进；同幂等身份改主体、前状态、后状态、任一时间材料或来源均幂等冲突；
7. 不存在 / 已退出主体或状态端点、零身份 / 来源、空数组、零独立材料、错合同和旧期望新键均取得精确非成功且零变化；
8. 经 L1 公开入口建立一个当前普通但不是存在服务所拥有的节点，把其编码包装为 `L2存在身份` 后，动态新增与按主体查询都必须由存在公开读取拒绝且空载荷、零变化，不能因 L1 节点种类为普通而通过；
9. 单项当前读取返回节点、三关系、两值、来源和端点同截止；单项历史在创建截止返回相同创建投影；
10. 再建立动态，分别覆盖起始 / 结束的 I64组、U64组和独立材料引用，使八个角色表示登记全部被真实写入 / 读回；
11. 同一主体、前状态或后状态建立多个当前动态合法；三条件查询分别返回稳定升序完整组，不选择时间较大项或合并重复语义；
