# CURRENT-SNAPSHOT-A3-STATE 普通持久状态读回实施计划 v0.1

基线 `51188dd7ee54cb926489b7d4dce877f2ba7777de`。主工作区本交互窗口独占。让正式状态所有者在普通持久启动和后续读取中从绑定权威取得原状态身份和快照内容。服务登记后的状态和需求发生 S 都需要这个读口。先以普通引导已有的自我状态互证，保持阶段 31 关门。

依据 [0050 §2](../规范/0050_项目通用机器逻辑与禁止性规则总纲.md)、[1160 §3–7](../规范/1160_根规范_状态节点.md)、[4015 §14–16](../规范/4015_子规范_基础数据集.md)、[4070 §4–5](../规范/4070_子规范_权威结构快照恢复候选与运行期原子发布.md)、[6120 §12–13](../规范/6120_子规范_自我存在服务与生存基本因果闭环.md)和[普通持久启动设计](../规范/详细设计/20261128_CURRENT-SNAPSHOT-STARTUP_当前事实持久启动详细设计_v0.1.md)。既有值和特征概念在实际普通世界恢复，当前状态八键只在隔离准入中被检查。状态所有者的 `获取状态` 和 `按存在查询状态` 仍依赖冷建写入的进程锚点。复用 `读取恢复服务状态结构` 的固定表和已有状态字段解码。持久读取每次使用同一份不可变视图。

## 施工范围

允许 `海中鱼巣/领域/新_状态类.{h,cpp}`、`海中鱼巣/装配.普通应用.{h,cpp}`、`海中鱼巣/启动.应用程序.cpp` 和 `海中鱼巣/程序运行结果.数据.h`。证据路径为 `验证记录/20261128_CURRENT-SNAPSHOT-A3-STATE_普通持久状态读回验证.md`。不新增业务事实、逻辑类型、持久标记、存储格式、状态写口或冷初始化顺序。保持先天 FT 缺口、其它事实所有者及普通业务准入的现有边界。

## 状态所有者

1. 在 `新_状态类.h` 增加 `新状态持久读取状态`，依次为 `已读取 = 1, 未绑定, 前提已变化, 材料不完整, 状态不存在, 结构不一致, 资源失败`，以及 `新状态持久读取结果` 和 `新存在状态持久读取结果`。两个结果首成员为 `状态`（默认 `未绑定`），尾成员分别为 `std::optional<新状态信息> 信息`、`std::vector<新状态信息> 信息组`。公开 const noexcept 成员 `读取当前权威状态(稳定编码 状态节点) const noexcept` 和 `读取当前权威存在状态(const 基础持久视图& 预期, 稳定编码 E) const noexcept` 分别用于精确读取和启动核验，后一入口只允许普通启动装配调用。前置声明 `基础持久视图`。
2. 从全局基础数据集取得绑定会话。无会话为 `未绑定`，已绑无视图为 `结构不一致`。存在组入口先验证当前视图即传入预期，读取结束后再次比较当前视图，视图漂移返回 `前提已变化`。两入口均从同一视图通过原八键读口定位字段；缺键为 `材料不完整`，资源失败原样上送，其余失败为 `结构不一致`。分配失败和长度异常映射资源失败，其它例外映射结构不一致。所有非成功结果不返回部分材料。
3. 文件内部抽取单状态字段解码，传入 `const 基础数据集&`、八键和状态编码。冷路径与持久路径复用该解码，保留冷路径的类型检查和已有失败处理。用已有唯一字段读取和强时间解码，令前者可传数据集及具体键；仅维护一份时间与准确值转换。状态节点存在且节点类型字段与八键类型匹配后，读取 E、来源 F、类型引用，各字段必须唯一且引用仍存在。固定准确值缺字段表示未知，唯一有效节点引用或 I64 为已知，重复或其它物理值错误。复用强时间现有时间语义及非负检查，引用次数须唯一且非负。单读中节点不存在、无状态类型字段或持有其它合法节点类型返回 `状态不存在`，格式错误返回 `结构不一致`。使用公共八键表顺序，禁止从节点编码推断身份。
4. 存在组在同一视图按被描述存在字段反查 E，将候选编码排序去重。遍历时跳过确属其它类型的节点，已登记为状态但不符字段合同、同一状态重复登记或读回 E 不同，整组报 `结构不一致`。无状态合法返回 `已读取` 与空组；已有自我却没有引导状态在启动层判为拒绝。先确认 E 节点存在，缺 E 返回 `材料不完整`。不据场景列表或当前特征的值选历史状态。
5. 正常 `获取状态` 先尝试同一所有者的绑定读口。成功投影原 DTO，`状态不存在` 返回空，`未绑定` 继续原冷路径；其余作为原 `获取状态` 的工程读取故障进入现有工程终止调用点。复用原诊断入口，无新增日志。后续正式来源读回可经同一个状态所有者调用 `获取状态`。其它读写口暂不开放持久模式，避免把该结果外推为状态 owner 全部写路径就绪。

## 普通装配

1. `普通应用恢复基础事实结果` 尾部增加 `新状态持久读取状态 状态`，默认 `未绑定`。给 `恢复普通应用基础事实` 增加末参数 `稳定编码 自我`，用原启动准入取得的 `登记.自我` 传入。复用实际候选的 `世界事实.状态服务`，在值与概念成功后调用该实例的存在组入口。存在组必须非空且至少有一条实例绝对 UTC 状态；逐项用同实例的结构化单状态读口按原编码独立重取并比对整份 `新状态信息`。任一读取失败按原状态上送，内容不符与无引导状态返回 `结构不一致`；当前共同视图改变优先返回 `前提已变化`。状态失败时按现有候选回收顺序销毁，成功且最终视图核同才移交上下文。异常映射继续按值、概念、状态各自阶段。无需安装第二套状态锚点或新增 teardown。
2. 暖路径新增 `持久状态读回复核失败 = 32`，保留此前编号。若两上游成功且状态失败，按 `材料不完整`、`前提已变化`、`资源失败` 映射同名底座持久状态，其余用 `结构冲突`。状态阶段完成才仍返回 `持久业务运行者未重绑`（31）。冷持久首份保留已有八键校验、发布与退出路径。工程写门、线程与网页宿主均继续关闭。

绑定前的旧五组准入保持原失败阶段 30 和原状态映射。状态八键缺失在该门就被拒绝。阶段 32 表示通过旧准入后，状态所有者在已绑定权威上的运行期读回复核失败。
