## 4. 实施步骤

### S1 DTO和服务骨架

1. 在共享头按详细设计追加合同/规则版本、请求、状态、阶段、目标状态事实、单根事实、双根

2. 新增`L1自我根需求读取服务`，构造函数保存三个非拥有provider引用并深复制P72定位。
3. 服务不可默认构造、复制或移动；公开根为同步const函数，不保存任何当前材料。

### S2 provider调用与同截止

1. provider前完成全部请求和稳定定位校验。
2. 固定P56→P69→P17直接调用顺序，各最多一次；任一非成功立即按矩阵返回。
3. 成功后比较世界根、自我、P56当前场景和三个非零截止；不等返回版本漂移。
4. 不直接调用P18/P19/P21，不新增重试、sleep、锁或缓存。

### S3 当前需求结构读取

1. 在P17快照互证P72服务、关系类型、十三字段类型当前有效且发布代次不晚于截止。
2. 按八字段和值槽筛选活动冷启动双轴根，安全/服务各唯一；双空和结构损坏分账。
3. 每根校验角色1—7各一、角色8为0及全部端点；禁止按数组位置或最小编码挑选。
4. 当前槽和值原样绑定P69对应根事实；出生值证据只与P72定位互证。
5. 读取目标五字段，校验安全大于1、服务等于I64_MAX，不执行当前满足比较。

### S4 自检、工程登记和启动专项

1. 按详细设计第8节逐项实现确定性自检夹具和静态边界检查。

3. 启动专项顺序固定573，保持572—550既有登记和顺序不变。
