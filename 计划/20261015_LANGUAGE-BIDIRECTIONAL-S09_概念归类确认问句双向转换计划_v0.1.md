# LANGUAGE-BIDIRECTIONAL-S09 概念归类确认问句双向转换计划

日期：2026-10-15  版本：v0.1  设计基线：`cd9dc5ec`（S02 已集成的 main）

## 1. 目标、依赖与完成边界

本计划是 `LANGUAGE-BIDIRECTIONAL-S02` 的唯一紧邻后继。现行 S09 知识为 `X 吗`，其中 X 是 S02 两个概念的归类含义；S09 外层含义固定为`提问/信息请求/提问范围/主张成立与否`，不是对子句 S02 陈述的事实采信。本叶给实际文本建立带来源的确认询问提议，并为已有 S09 输出生成增加调用期唯一回读入口。输入、输出共享正式外层 S09 知识、其强引用 S02 子知识和角色映射，不能仅凭词尾“吗”推断问句。

**依赖核验**：S02 计划 blob `24f27f9302ee7fd81cc16192f1d38dd738a87675` 所约束的 `解释单句概念上下位` 已由代码提交 `0c8c27ba` 经 main `37cfdda1` 发布；施工记录载明实际项目编译链接通过、未运行测试。已按该提交的公开头文件核对请求四项预算、输入状态、候选的概念/名称/知识/范围字段及可逆包装，符合下文消费合同。S09 登记和执行前仍须核对现行索引、实际接口、唯一代码所有者与构建资源；若这些事实改变并影响合同，受影响切片停止并交计划支撑修订。本计划发布本身不表示 S09 代码已实现。

成功范围限已有存在概念两端或同 FT 根特征概念两端的确认问句。受询者 E 必须由调用方显式绑定且经 `新_存在类::获取存在`正式读回；文本没有“你”也不允许自动从当前会话猜出 E。缺绑定时即使句式和概念唯一，也只能返回`受询者待绑定`，不能返回完整信息请求。已绑定只证明当前 E 可读且本次调用指定它为受询者，不证明问句已送达 E、E 理解或回答。提问不自动形成 self 需求/任务，不将被询归类写入概念树或现实认知。

不覆盖 S01/S03/S05 的实例对象、谁/什么填项问句、任意 X、感叹/祈使、句末标点省略、多轮受询者推断、现实/故事世界选择、消息生产调用及持久语言场景。当前 S09 生成器的成功仍是一向生成；本叶可逆包装回读成功后，才允许把该表达称为本次 S09 双向含义一致。

## 2. 正式依据及已核现状

依据：0050 §1—3、2340、7230 §2—3、7240 §2/3/4/7、7250 §2 的 S02/S09、2210/2220/7220，以及现行 S02 计划。`初始化材料/最小语言知识种子.txt` 中 S09 目标为提问、信息请求、提问范围、确认主张成立与否；被询子含义是概念归类；角色0/1均为概念引用；第一结构项强引用 S02 并以 `0:0 1:1` 双射映射角色，第二固定项是“吗”。编号和词面只作为该已发布知识的一次形式；执行按完整正式定义匹配，不按来源标签或一个字面开关分派。

主线现有 `生成基础语言表达` 已支持 S09：核验受询者 E、从外层知识展开 S02 子规则和尾项、输出外层知识、子项路径/所属知识、已核验受询者及名称/词条对齐；不查词条→全部概念，因此其文本不保证可唯一反解。`新_语言类` 提供最长词条匹配及完整知识候选，词、名称、概念服务提供只读端点；`新_存在类::获取存在` 返回可读 E 的完整值式信息，异常走现行工程终止链，空结果不能冒充受询者已绑定。已发布的 S02 正向解释返回完整候选及状态，S09 只消费其公开入口，不另建第二 S02 解析器或语言知识 owner。

## 3. 代码 owner、物理位置与公开合同

唯一代码 owner 为 DATA 外语言解释业务，使用既有 `海中鱼巣/业务/解释.基础语言.h/.cpp`。只追加下列公开 DTO 和两个自由函数；现有 `表达.基础语言.h/.cpp`、`新_语言类`、词/名称/概念/存在服务、初始化种子、工程登记、装配及规范均只读。S02 已在 main 发布；本叶开工前须取得解释文件唯一所有权，不能通过另一文件绕开同 ABI 写冲突。原 S01/S02 入口、S02 可逆包装与既有输出生成 ABI 不改。

```cpp
struct 基础概念归类确认输入请求 final {
    std::string 固定原文;
    稳定编码 语言节点;
    std::optional<稳定编码> 未核验来源语言记录节点;
    std::optional<稳定编码> 受询者存在节点;
    std::size_t 最大原文标量数, 最大知识条目数;
    std::size_t 最大名称候选数, 最大组合候选数, 最大确认候选数;
};
enum class 基础概念归类确认输入状态 : std::uint8_t {
    已形成唯一信息请求, 受询者待绑定, 受询者不可读,
    概念多义待解, 多规则待解, 未知词, 缺名称, 缺规则,
    角色不相容, 结构未支持, 能力未支持, 输入拒绝, 格式失败,
    引用不可读, 额度不足, 内部不一致, 工程未完成
};
struct 基础概念归类确认候选 final {
    稳定编码 外层知识节点, 子知识节点;
    基础概念上下位候选 被询归类;
    std::optional<稳定编码> 受询者存在节点;
    解释原文范围 子句范围, 确认词范围;
};
struct 基础概念归类确认输入结果 final {
    基础概念归类确认输入状态 状态;
    std::string 固定原文;
    std::optional<稳定编码> 未核验来源语言记录节点;
    std::vector<基础概念归类确认候选> 候选组;
    std::vector<解释原文范围> 未覆盖范围组;
};
基础概念归类确认输入结果 解释单句概念归类确认(
    const 基础概念归类确认输入请求&, const 新_语言类&,
    const 新_词类&, const 概念_名称关系类&,
    const 概念_存在类&, const 概念_特征类&,
    const 新_存在类&);
struct 基础概念归类确认可逆表达请求 final {
    基础表达请求 表达;
    std::size_t 最大回读原文标量数, 最大回读知识条目数;
    std::size_t 最大回读名称候选数, 最大回读组合候选数;
    std::size_t 最大回读确认候选数;
};
enum class 基础概念归类确认可逆表达状态 : std::uint8_t {
    已生成且可唯一回读, 输入拒绝, 表达未生成,
    回读语义未闭合, 回读技术未完成, 含义不一致
};
struct 基础概念归类确认可逆表达结果 final {
    基础概念归类确认可逆表达状态 状态;
    std::optional<基础表达状态> 原始表达状态;
    std::optional<基础概念归类确认输入状态> 回读状态;
    std::optional<基础表达结果> 可用表达;
};
基础概念归类确认可逆表达结果 生成可唯一回读的概念归类确认表达(
    const 基础概念归类确认可逆表达请求&, const 新_语言类&,
    const 新_词类&, const 概念_名称关系类&,
    const 概念_存在类&, const 概念_特征类&,
    const 新_存在类&);
```

请求与结果均为调用期值式材料；`未核验来源语言记录节点`只原样回显，不冒充正式记录。子候选的原文范围沿前缀零起点标量坐标使用，`子知识节点`必须等于其中`所用知识节点`。受询者缺省时候选只表达尚待绑定的查询形式，不能交应用当成已完成信息请求。失败包装不公开候选生成文本，`可用表达`只在完全核验成功时有值。

## 4. 输入解释、额度、非成功及复核

1. 校验语言节点、原文非空、五项正预算、受询者若提供则编码有效；严格 UTF-8 解码并固定 Unicode 标量/字节映射，不清洗、归一或吞标点。提供了受询者时先以 `获取存在` 读回同身份完整 E，空结果为`受询者不可读`，工程异常沿提供者终止链。未提供受询者仅记录缺项，不在此步退出，仍解析完整句子以保留可用候选。
2. 一次读取**整句**最长匹配及全部语言知识候选，按外层目的/操作/作用域/确认范围、子含义签名、两个概念角色、S02 子规则强引用及不交换方向的双射映射、两项有序结构和固定“吗”的正式词条端点筛选 S09。不能用来源标签、单个“吗”或词面正则确定语义。完整候选读回或固定词损坏导致技术非成功，不过滤成零规则。只接受恰好一个末项词条与正式固定项同身份，其标量范围紧贴完整前缀末端并覆盖全句；更长词条遮住“吗”、标点或其它尾部导致`结构未支持`，不私拆词。
3. 对 `[0,确认词起始)` 的**原样字节前缀**调用已发布 `解释单句概念上下位`，以同语言、来源线索及前四个预算形成子候选；同时核对前缀解释所见最长片段与整句匹配去掉“吗”后的片段完全相等，防止截断后词条边界变化导致假成功。子解释的多规则/多概念候选不能选第一项；按每条外层 S09 知识的**正式子知识节点与映射**筛出相应 S02 候选，未被任何外层规则引用的 S02 候选不构成本问句歧义。子解析的格式、引用、额度、内部和工程失败按原原因上抛，不降格为缺规则。
4. 在形成外层×子候选前，按完整候选数用无溢出先除后乘核对 `最大确认候选数`；超限`额度不足`，不截断。每个候选保存外层和子知识、两个概念与名称关系、准确原文范围。若零相容规则，按已有 S02 子结果及外层匹配阶段确定`缺规则/未知词/缺名称/角色不相容/结构未支持`；不同概念组合为`概念多义待解`，多个外层或子知识含义路径为`多规则待解`，同时存在时优先多规则并完整保留候选。只有规则与概念语义均唯一后，若未提供受询者返回`受询者待绑定`；提供且 E 读回有效才返回`已形成唯一信息请求`。问句含义为“向该 E 请求确认 `(主体C,归类C)` 主张是否成立”，不宣称主张成立。
5. 成功前重读受询者完整 E、整句匹配、外层/子知识全集、实际固定词及 S02 已用概念/名称完整候选，必要时重跑子解释并比较结构化结果。变化使唯一性或来源失效时返回`引用不可读`，不凭旧缓存成功；不恢复事实代次或伪称跨 owner 原子快照。函数全程零领域写入，无发布、撤销或消息发送。

未覆盖范围：完整结构但多义、受询者待绑定或成功时为空；S02 内容词未知/缺名称时沿用其左/右槽范围；尾项或外层结构不合法、缺外层规则、能力/额度/技术未完成时整句范围；无法合法解码或输入拒绝时为空。技术失败不携可供后继消费的完整候选；受询者缺失时可保留已解释的候选，明确其 E 字段为空。

## 5. 反向唯一回读与施工验证

包装入口只接 `基础表达请求` 的 S09 合同：`目的=提问/操作=信息请求/作用域=提问范围/被询操作=概念归类/确认范围=主张成立与否`，两概念参数同类别，受询者 E 有效，不带指代或网页自我来源；五项回读预算均正。先调用已有 `生成基础语言表达`，失败保留原 `基础表达状态` 且不给文本。成功后把实际文本、语言和**同一个已核验受询者**交本叶输入解释；只有`已形成唯一信息请求`且外层知识身份、S02 子知识身份、目的/操作/作用域/确认范围、两概念类别及身份、两名称关系、受询者和嵌套来源路径/范围均与输出对齐相等，才返回`可用表达`。语义缺项/多义与能力/引用/额度/工程未完成分别归`回读语义未闭合`、`回读技术未完成`，回显精确回读状态；不把工程故障称作语言歧义。原生成器可继续一向使用，但不因此取得可逆保证。

代码步骤：①以 main 已发布的 S02 ABI 核对唯一所有权与实际接口；②在现有解释头源追加 S09 DTO/入口，复用 S02 解释器及结果，不复制名称或概念匹配算法；③按外层正式知识与整句词条匹配组合候选并核验受询者；④以现有生成器及 S09 解释器完成唯一回读包装；⑤形成知识变更清单及专属 `验证记录/20261015_LANGUAGE-BIDIRECTIONAL-S09_施工与编译记录_v0.1.md`。白名单仅上述解释头源及专属记录；输出生成器、知识 owner、种子、工程、装配、正式规范、S02 计划和计划索引只读。如开工时实际 ABI 与冻结合同不符，或 S09 需要改输出/知识公开合同，停止受影响切片并交计划支撑，不扩大施工范围。

默认在独立工作树的正式 `海中鱼巣.slnx` 用 MSBuild `Debug|x64` 编译链接；文档和差异做 `git diff --check`，无本轮明确测试指令不运行程序、自检或测试。获用户另行测试指令后可验证：唯一 S09 与受询者绑定、受询者缺/失效、同词多概念、S02 多子规则但仅一个被外层引用、S09 多外层规则、长词遮挡“吗”、更长词遮挡子句固定词、额度溢出、概念跨 FT 根、运行期读取变化、输出文本回读与嵌套对齐。编译与静态检查不证明真实运行、提问送达、理解、回答或通用问句能力。
