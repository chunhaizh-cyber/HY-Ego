## 1. 目标和选择理由

实现 4015 §5.1 已冻结但当前缺失的 `L1所有者范围签发器::重新签发所有者范围写端口`。它是当前最早基础层代码缺口：不需要 L2/L3/L4 业务输入，不新增机器语义，不重复 ARCH-L2 provider 施工。

当前索引无可执行计划。ARCH-L2 原子 provider 的单 G1/五组读回已经是代码合同但尚无独立运行矩阵；特征独立材料和四类值表示已有基础准入，而向量/形状比较仍缺少冻结算法。因此本计划只登记 L1 重签发。

## 2. 固定公开入口和 DTO

唯一新增公开函数：

```cpp
L1所有者范围交付 L1所有者范围签发器::重新签发所有者范围写端口(
    const L1所有者范围重入请求& 请求);
```

复用 `L1所有者范围重入请求/结果`，不新增 owner/token/进程字段。成功交付一份 move-only 端口；失败结果不带端口。`成功`不推进事实代次；已有活动端口返回 `许可拒绝`，不得返回 `精确重复`或第二端口。

## 3. 实施顺序

1. 在数据头保留现有重入 DTO，并补齐纯值有效性守卫测试所需的静态断言；不增加字段或枚举值。
2. 在 `仓库.L1事实基座.ixx` 增加模块内只读验证：检查隔离状态、owner 当前/未退出、独占范围、建立幂等账存在且首次请求/结果/owner 逐字段一致，并返回安全当前事实代次。
3. 在 `服务.L1事实基座.ixx` 的签发器中按“端口锁→仓库验证→活动 owner 原子插入→构造端口”实现公开入口；与现有退出顺序一致，消除退出/重签发竞态。
4. 重用现有端口 RAII、owner 当前读取、建立账和端口活动集合；不得复制账、事实或端口。
5. 仅更新两个工程文件登记已有生产文件或本计划记录；不得接线普通应用或任何 L2/L4 消费者。

## 4. 状态、重试和读回合同

| 条件 | 状态/载荷 | 事实变化 |
| --- | --- | --- |
| 参数/版本错误 | 入口拒绝，空载荷，代次0 | 零变化 |
| 运行包失效 | 许可拒绝，空载荷 | 零变化 |
| owner/建立账缺失、退出、错范围、互证失败 | 未找到/已退出/引用冲突/内部不一致 | 零变化 |
| 活动端口存在 | 许可拒绝，空端口 | 零变化 |
| 当前独占 owner、账互证且无活动端口 | 成功，交付唯一端口，owner事实可选完整投影 | 不推进代次 |
| 仓库/分配异常 | 资源失败或内部不一致，空端口 | 零变化 |

成功后必须使用新端口完成一次受控 owner-scoped 首次写入或既有首次账读取，证明端口绑定同一 L1 实例和 owner；不得把这次验证写入生产代码。旧端口移动源、析构、owner 退出、运行包销毁后提交继续许可拒绝。重试只在没有活动端口且原请求逐字段相同、owner 仍当前时重新签发；不使用新幂等键掩盖冲突。

## 6. 验证矩阵与完成边界

必须运行 Debug/Release 根工程、`D:\TEMP` 专项、strict、diff-check、UTF-8/no-BOM、生产零专项痕迹：

- 参数、owner 当前/历史/退出、建立账缺失/异义、非独占范围、隔离状态；
- 同 owner 活动端口拒绝、不同 owner 并行重签发、退出与重签发竞态；
- 成功端口首次写入/首次账读回、移动源/析构/运行包销毁失效、重复重签发；
- 所有拒绝零事实代次推进、owner/账/永久编码不变，成功不形成 G1；
- 旧建立、退出、普通写入和 L2 provider ABI 回归。

本计划不验证崩溃/跨进程恢复材料、快照恢复候选、L2 G1 五组读回、任何 L4 任务/方法/需求消费者或业务闭环。代码发布后仍需基础层具名验收；当前不登记后继计划。
