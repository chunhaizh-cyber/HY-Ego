## 1. 目标、对象及边界

用户要求：通过交互窗口取得存在及相关特征，判断该对象是存在且属于人类概念；符合时返回服务对象材料。

直接操作是观察读取，不改变现实存在的特征值，不修改任务或方法虚拟存在的业务特征值；登记阶段只由方法owner形成合法方法头和Vm。目的为后续主动获取服务需求提供已知人类材料。按0050第8.1节属于现实观察，不能因材料供内部治理使用而冒充内部治理改变。

本叶实现本能函数、独立端口、业务运行服务、实际普通应用初始化登记/装配及任务通用调用期X守卫。它不建立正式服务关系、不采纳服务对象、不创建服务需求或任务、不赋予权限，不把任意访客认定为第一权限人。不实现视觉/自由文本人类识别。

判断只使用两项：实际节点确为存在，且严格`匹配存在概念(E, 人类C)`核对概念全部FT及值域。不能靠专属概念上位标签自证。匹配、不符合、材料不足分账；空特征组合法且表示无特征约束。当前人工人类C为空，因此此定义不能区分不同种类的E；这是明确的当前认知范围，不补造生物学事实。服务对象身份复用已有E，不复制存在。既有bool `存在节点属于概念()`继续保留结构上位归属合同，本叶不暗改全部旧存在引用域消费者。

新增实际人的描述材料：名字复用既有姓名FT，“名字”词条关联同一概念；性别建立UTF8全材料域FT/词条，给已知第一权限人增加全域区间描述、准确当前值空。两项不自动成为人类C必需条件，不推断周春海实际性别，不把其姓名当人类唯一判定定义。不造第二样本人；后续真实多个存在共同抽象复用现有抽象函数，不在本叶执行。

方法头声明返回人类材料，不能宣称改变`自我.服务对象`FT。当前任务按FT粗召回，不因本叶的`可能结果概念组={人类C}`自动接通主动获取需求子任务；任务侧采用与自我治理消费留待后继。本叶完成不证明服务需求闭环。

## 5. 登记和Vm声明

2. 执行参数必须恰一窗口角色，场景/E/F准确匹配配置；通过场景读取绑定F并确认I64非负消息数量，作为本次条件快照。失配、缺合法来源或条件在动作前不具备时零动作，返回未进入/未取得；工程违约不能伪装缺条件。
3. 读取源，port核验来源及同一场景地址的守卫X；task owner读回X执行中、未结束、对应M，T执行中且当前X，实例M来源链归属于本服务登记头。复制声明一致性不因包含已学习C/R失效。
4. 再临近动作读取源：公开会话、窗口E、交互者E、场景均相同，序号不得倒退。允许序号增加，不能要求正好相等导致活跃对话饿死。来源变更时零动作拒绝，不造归属否定。
5. 以X唯一显式来源建立观察动作，主体自我E、定义实际调用M、目标源E、目标F可空，按6.1核验并挂入共同动作场景（不能固定挂入窗口源场景）；采用现行UTC强时间。先查询X动作，已有动作拒绝本次重入，不再次观察或创建。发布成功和发布未知均须通过动态owner同源读回，仅交付当前仍存在动作；建立失败不能继续观察。
6. 释放服务锁后从存在owner取得E及专属C，读取E持有的每个F为当前快照；先确认是存在，再严格匹配人类C全部特征。既有E/F读取catch用工程异常终止，配置/保持来源却引用断裂等工程违约同样终止，不能空材料或false掩盖。

特征快照来自逐项current-only owner读取，不承诺跨owner原子快照；材料是本次所知，不替代正式世界事实。动作后源变化不自动重做动作、不回填第一次结果。实际源/条件快照保留明确位置，不以字符串文字决定语义。

新方法只取得E及特征，没有改变准确值，不新建结果状态/变化动态。动作事实独立保留，本次typed材料和X关联；现有`关联动作结果`只在有正式结果动态时才能调用，本叶不把E强塞动态端点、不为日志/证明复制动态。不在函数中建立长期C/R，学习完善留给对应owner。

### 6.1 动作共同场景与通用X收束

源场景是窗口材料发生位置，不保证第一权限人E与selfE直接同场景。具体运行服务动作建立私有辅助`std::optional<稳定编码> 取得共同动作场景(稳定编码 主体E, 稳定编码 目标E) const`，物理位于服务对象运行服务cpp实现体，组合世界owner公开入口：本叶跨直接场景时固定使用世界根场景作为共同祖先，先核验正式根和两E均在其合法场景范围；同场景可用该场景。零合法共同场景拒绝，不假造成员关系，不为了方法移动存在。

`新_任务类.cpp`新增匿名namespace只读辅助`bool 核验执行本能动作(const 新任务执行信息&, const 新任务信息&, const 新动态信息&, 稳定编码 自我E, const 新_存在类&, const 新_场景类&)`。通用动作来源为X、定义为X.M、主体为双根正式需求目标同一selfE、目标为合法普通E；目标F允许空，有F时必须属于目标E；时间与X开始语义相同且不早于开始，有结束时不晚于结束。沿self当前所属场景向上，只以已知动作节点查合法动态列表挂靠，不扫描列表推断来源；该挂靠场景范围同时包含self和目标E才接受。源/定义/目标仍逐项核验，不能仅凭列表包含代替来源身份。

`记录本能动作身份()`有服务结算来源时保留原结算专用严格分支；无结算来源时使用新通用X分支。不用普通分支绕过结算来源要求。当前T/X执行中及T当前X/M定位仍在记录时核验，读取既有X不因T后来推进而强制当前M相同。`读取执行信息()`普通动作字段不再必须具有服务结算来源，但仍要求有效唯一动作节点；不改公开ABI，不让记录入口递归调用自身。使用既有增加引用/字段写入/owner读回/失败回滚，不制造第二动作字段或来源副本。

### 6.2 现实描述初始化

装配cpp内部新增`bool 建立人类描述特征(普通应用上下文&) noexcept`，调用锚点第一权限人建立成功后、人工humanC初始化前。复用词owner“名字”词条→既有姓名概念名称关系。性别FT为UTF8全材料域、完整材料比较、全域概念；只用区间值入口为第一权限人增加全域描述，当前值保持空，无准确值就不建立准确状态。通过已有存在/场景公开入口，专属概念投影随合法添加自动维护。重复装配读回已有同FT而不重复添加。不得改变humanC特征组、生成新人工人实例、猜测性别、自动变更服务权限。

## 7. 并发、工程失败与生命周期

port自身mutex只保护配置、初始化/关闭、方法身份及动作一次进入控制；不得持锁跨领域owner、源回调、日志或弹窗。manager mutex只保护注册/端口引用，租出shared_ptr后释放再调用。源回调锁内只复制值，锁外再读取owner；不得让源回调在初始化登记锁内被调用。

各领域owner仍独立持锁，本叶不构造跨仓事务，不通过层层快照假装共同版本。执行守卫为线程局部，task通用调用外层RAII持有，异常处理不得继续使用污染身份。

运行服务的非拥有owner和来源回调必须覆盖所有调用寿命。管理类的shared_ptr租约覆盖函数调用；关闭拒绝新租约、不替换仍活动的port；已租用调用保活，业务owner不能早于其释放。普通应用先停止/回收治理工作，再关闭并释放服务。失败初始化若已装配端口必须关闭并解除可用状态，不留下半就绪方法供执行；构造和初始化资源错误按既定日志/弹窗/终止链处理，不创建业务失败配对。

普通应用内部新增专用`std::mutex 治理启停锁`，启动和停止入口串行持有；锁序仅治理启停锁→短期上下文锁。source回调只拿上下文锁，不拿启停锁。私有`普通应用上下文* 读取治理启停上下文(bool 要求成功装配) noexcept`在ctx锁内检查并快照指针，立即释放；当前上下文不销毁，指针覆盖启停寿命。所有启动、请求停止、等待停止、join、失败清理和端口关闭/卸载在ctx锁外，完成后ctx锁内只修改启动标志。构造/初始化不能形成ctx锁→启停锁逆序，不因失败进入ctx锁内等待worker。保留公开启动/停止结果ABI；新工程错误不伪装业务失败。

新代码捕获std::exception及未知异常均进入`工程异常终止()`，不得将工程错误返回为业务非人类、未取得或条件不足。仅上述四个existing读取入口迁移catch（获取存在、获取特征、获取存在概念、获取特征值），不改其它正常非成功分支，不清理全类工程策略。实际动作已经成立时终止前不补造结果、不重复动作；致命终止不提供业务清理或恢复保证。
