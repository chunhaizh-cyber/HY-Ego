## 5. 冻结目标合同

### 5.1 L2 结构收紧

按详细设计 5.3 机械实施：

1. `L2新增任务结果::成功()`接受`已提交/精确重复`；
2. `读回新增任务`原样保存这两个状态；首次提交要求五项新事实在 G1 当前，精确重复按原 G1 验证并重构首次结果，允许任务核心后来同代退出；
3. 当前代次等于 G0 时，在任务 owner 锁内调用现有当前任务投影，0 项才写、1 项引用冲突、多项内部不一致；
4. 旧 G 的`直接提交`只交给 L1 原幂等见证收敛，不以旧投影猜当前，不允许新键形成第二任务；
5. 不新增第二任务写入口，不把“需求未满足”判断放入 L2。

### 5.2 DTO 与 provider

严格按详细设计 5.1 / 5.2 创建：

```text
需求初次筹办准备请求（携带需求身份、G0、非零运行代次和任务建立幂等身份，不接受调用方自造裁决值）
需求初次筹办准备状态
任务初次筹办工作包
需求初次筹办准备结果
需求初次筹办准备提供者
需求初次筹办准备提供者::形成唯一任务与初次筹办工作包(...)
```

字段、枚举顺序、默认值、完整性、签名、模块和物理路径不得改名或省略。工作包不得包含请求身份或完整未满足裁决，只能包含新任务及身份来源、来源需求、当前成员、完整列表项、轮次 1、G0、G1 和运行代次；完整裁决只留在 provider 结果。`需求初次筹办准备结果::成功()`只接受`已形成/精确重复`且裁决与工作包载荷完整。函数名、变量名和业务成员名必须使用中文。

请求身份只用于本次裁决调用关联，运行代次只作调用方提供的协调材料；二者均不进入 DATA 写集。任务建立幂等同义边界是现有`L2新增任务请求`的同一列表项：同键换列表项必须冲突；只换请求身份或运行代次不得伪装为 L1/L2 幂等冲突，后继仍须验证运行代次当前性。

### 5.3 固定调用顺序

```text
纯值守卫需求身份、G0 与幂等材料
-> 调用正式需求当前满足裁决入口
-> 只有未满足裁决继续，已满足 / 证据不足 / 不可比较 / 许可等具名返回
-> 一次调用 L2新增任务
-> 映射漂移 / 幂等 / 引用 / 许可 / 资源；引用冲突只在以返回 G0 公开读回恰一当前任务时映射已有任务
-> 成功或精确重复时以 G1 按列表项读回唯一当前任务
-> 互证任务、来源、生命周期和 G0/G1
-> 形成轮次 1 工作包
```

禁止在 provider 内刷新到新截止重试、换幂等键、调用旧结果重筹办 provider 或直接进入方法查找。

### 5.4 依赖生命周期与工程

- provider 构造函数借用`const 运行期只读查询组合器&`和`L2任务结构服务&`；
- 调用方保证两者生命周期覆盖 provider；
- 本叶不增加普通应用 getter，不伪造生产消费者；
- 新模块在`.vcxproj`与`.filters`各登记一次；
- 不新增第二 export/include 面或测试专用生产入口。

## 7. 失败收口

- S0 漂移：零代码写入，具名退回计划支撑；
- 写前入口 / 引用 / 当前性 / 许可 / 资源问题：结构化结果，零事实写入；
- 任务 G1 已发布后读回或组包失败：内部错误，不撤销、不退出任务；
- 原任务后来退出或当前任务改变：L2 精确重复可以回显原 G1 建立结果，但 provider 必须在当前读回处分流，禁止返回旧工作包；
- 验证发现纯代码错误：执行者在白名单内修复；
- 一次构建或环境波动：保留证据、排除环境后重试，不自动改设计；
- 必需验证持续失败且不能安全归因：保留现场并停止受影响切片；
- 不得用降低唯一性、删除失败分支、伪造动态 PASS 或扩大白名单收口。
