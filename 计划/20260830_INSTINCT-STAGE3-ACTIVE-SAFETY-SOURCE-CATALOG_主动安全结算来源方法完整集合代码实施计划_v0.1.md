## 1. 目标与完成条件

在现有安全根定义 owner 内实现主动安全结算来源规则的版本化完整集合发布 / 读回，并让生产安全根初始化发布和互证当前规则版本 1 的显式空集合。

完成必须同时满足：

1. 规则 1 空集合具备独立登记、当前槽、历史事实、幂等重放和同截止正式读回；
2. 规则未发布与合法空集严格分离；规则 1 非空、未知 / 重复 / 乱序方法拒绝；
3. 生产初始化只有定义与来源规则在同一最终截止下完整且版本一致时成功；
4. 安全根值域、定义版本 1、L/H 和既有定义 ABI 语义不变；
5. Debug / Release、专项、ABI consumer、strict 和精确差异门禁通过。

## 5. 实施步骤与失败收口

1. 增加 DTO、规范排序 / 完整性和成功谓词。
2. 增加来源规则独立登记定位、编码 / 解码和首次材料互证。
3. 实现发布入口：入口、重放、G0、登记、当前版本、写入、写后读回和读后守卫。
4. 实现当前读取入口：G0 双守卫、唯一当前槽和完整事实。
5. 扩展生产初始化：定义成功后发布 / 恢复空规则，最终同截止双读回。
6. 扩展两份现有专项，覆盖 S00—Sxx 的首次、重复、冲突、漂移、坏材料、已可能发布和生产恢复。
7. 形成施工 / 验证记录与函数级知识变更清单。
8. 在隔离提交树执行两配置、专项、ABI consumer、strict 和差异检查；只发布本白名单。

任何发布非成功必须空业务载荷；已可能发布只保留原幂等身份和 G1，使用原请求重放。当前定义存在但来源规则缺失不是成功恢复，生产初始化必须补发或失败。

## 6. 验证矩阵

- DTO：空集合法、非空 v1、零身份、乱序、重复、声明数 / 长度错误；
- 登记：首次、重复、坏首次材料、定位复义、owner / 来源 / G1 错配；
- 发布：版本 1 首发、同键重复、同义异键、同键异义、0/跳跃/回退版本；
- 读取：未发布、合法空集、G0 前后漂移、坏当前槽、资源和内部错误；
- 已可能发布：提交后读回失败、原键恢复、零第二事实；
- 生产：定义新建 / 恢复 + 规则补发 / 恢复，同截止版本互证；
- 不变量：值域 `0..I64_MAX`、定义版本 1、L/H 精确常量与定义匹配函数零变化；
- Debug / Release 根工程和专项；Debug / Release `/GL + /LTCG` ABI consumer；
- `python .\tools\check_specs.py --strict`；工作区、切片与 cached `git diff --check`。
