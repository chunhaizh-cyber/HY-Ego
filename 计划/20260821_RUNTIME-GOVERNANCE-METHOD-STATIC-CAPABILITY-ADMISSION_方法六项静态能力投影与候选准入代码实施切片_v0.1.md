## 4. 实施合同

### 4.1 方法结构原位升级

1. 把 `L2普通方法结构合同版本` 提升为 2，按详细设计 §4—§6 增加全部强类型、枚举、提交项、事实、六项签名、投影、结构缺口、用途粗召回和投影读取 DTO。
2. 删除合同版本 2 公开事实中的旧作用对象绑定、参数、禁止项和适用范围独立节点式组；参数合同进入输入规格关系，运行参数值留给任务路径/实例。
3. 条件和结果提交使用连续本地顺序；条件结果、条件级输入规格和条件级限制只通过本次局部映射转换为正式端点。
4. 版本 1 写请求结构化拒绝；旧事实不补默认值、不从目标合同、场景、名称或旧索引键反推方向和结果类型。
5. 新增、替换和退出继续使用现有方法 owner 单一原子写集；成功和精确重复后独立历史读回完整方法并重建投影。
6. 目标对象类型直接使用 `L2概念身份`，写前经概念服务同截止确认属于存在本体根；不建立方法专属对象类型身份。
7. 结果类型使用 `std::variant<L2目标状态合同身份, L2概念身份>`：状态合同分支经状态服务同截止读回，概念分支经概念服务确认属于动态本体根；不建立方法专属结果类型身份。
8. `L2方法结构服务` 构造函数增加 `const L2概念结构服务&` 只读借用，普通应用把已经构造的唯一概念服务同实例传入；禁止取得概念写能力。
9. 结果类型分支机器序号固定为状态合同 `1`、动态概念 `2`；持久负载、幂等材料、索引和稳定排序统一使用 `[分支机器序号, 身份稳定编码值]`，禁止依赖 `variant::index()`、内存布局、类型名或哈希值。

### 4.2 值式投影

1. 每个当前结果作为一份投影主轴，只选择作用对象角色和用途四元组完全相同的用途；禁止无关系笛卡尔组合。
2. 输入条件组由当前条件结果关系、条件语义、条件级和全方法输入规格形成；限制条件组由条件级和全方法限制形成。
3. 组按详细设计字段字典序排序，语义重复稳定去重；跨方法引用、混代、当前唯一复义返回内部不一致。
4. 有当前条件但主轴结果无条件结果关系时同时返回 `条件结果关系缺失`；空条件组不证明当前就绪。
5. 当前和历史读取都使用调用方指定截止，禁止自动升级。
6. 结果类型联合的比较与排序必须使用正式分支机器序号和稳定编码，不得使用 C++ 实现细节。

### 4.3 用途粗召回

1. 用目标对象类型、可改变特征类型、变化方向和结果类型建立可重建用途索引。
2. 实现 `按用途读取方法粗召回组`，当前与历史读取均受扫描用途事实数和粗召回方法数双预算限制。
3. 结果按方法与用途身份稳定升序；预算不足返回空载荷的 `数量预算不足`。
4. 删除 `按结果规格读取当前方法候选`，不保留同义第二入口。

### 4.4 DATA 外候选准入

1. 新建详细设计 §7 的数据头和唯一模块，公开 `方法静态能力候选准入提供者`。
2. 构造函数只借入 `const L2方法结构服务&`；不得取得任何写服务或线程。
3. `读取匹配候选` 严格按目标函数流程图执行：请求准入、用途粗召回、逐方法投影读取、六项精确比较、结构缺口合并、稳定排序和四态结论。
4. 任一中途非成功不得返回部分候选；原共同截止原样返回。
5. `L2方法六项静态能力签名相同` 只做完整签名逐字段相等；不提供相似度、通配、子集或名称兜底。

### 4.5 删除过期筹办空壳

删除详细设计 §3.3 的两个旧筹办文件及工程登记。删除前通过全仓调用搜索再次证明模块外正式消费者为零；出现消费者即停止删除并具名返回，不得用兼容空壳掩盖漂移。

### 4.6 工程与命名

- 新模块登记到 `海中鱼巣.vcxproj` 和 `.filters`，删除旧筹办登记；
- 函数名、变量名使用中文；
- 不新增第二方法结构服务、持久六项投影、能力缺口节点、日志裁决或生产故障钩子；
- 只在施工记录形成函数级知识变更清单，不直接修改共享知识。
