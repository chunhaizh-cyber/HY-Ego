## 2. 已证明当前事实

1. `6120` 只冻结 `1 < L < H <= I64_MAX`、定义版本、主动安全结算规则版本和被动服务维护规则版本；它禁止线程、服务合同、任务调度和显示层临时配置阈值，没有冻结具体 `L / H`。
2. `6170` 已冻结服务时间维护规则版本和生存安全回归规则版本为 `1`，但没有给出具体 `L / H`，也没有把“主动安全结算规则版本”与某个已实现生产 provider 等同。
3. `普通应用配置` 当前只承载 L1 持久恢复根、不可变材料根及其它既有装配依赖；不存在已发布的安装级安全根定义配置合同。
4. 正式启动参数当前只有无参数、`--headless` 和 `--runtime-context` 三种模式选择；命令行没有且不应临时携带安全阈值。
5. 生产启动在本能根运行锚点之后直接建立完整秒与被动维护游标，尚未调用 `发布安全根定义_v1`。
6. `100 / 1000`、`2 / 5 / 10` 等仓库数值只出现在专项 fixture、旧占位或其它值域中，不能升级为生存安全根生产定义。

## 3. 已裁决生产定义

```text
来源 = 版本化内建生产定义，不使用命令行或每次启动临时配置
M = I64_MAX = 9,223,372,036,854,775,807
L = floor(M * 30 / 100) = 2,767,011,611,056,432,742
H = floor(M * 80 / 100) = 7,378,697,629,483,820,645
安全根定义版本 = 1
主动安全结算规则版本 = 1
被动服务维护规则版本 = 1
```

“浮动”只表示比例可以在后继定义版本中调整；版本 1 发布后其 I64 数值不可变。计算使用安全整数算法，不使用 `float` / `double`，也不使用 `UINT64_MAX`，因为根值域正式上界是 `I64_MAX`。定义中记录主动规则版本只声明本定义期望的合同版本，不证明对应主动安全结算生产 provider 已经实现；缺少正式主动事实完整性见证的消费者仍须 fail-closed。

以下候选不推荐：

- 每次启动从 CLI 读取会把长期版本定义退化为临时启动参数，并扩大现行 L0 参数合同。
- 自动使用测试数值没有生产语义来源。
- `UINT64_MAX` 的 80% 超出 I64 根值域和现有 ABI，不能作为 H。
- 新增安装配置 owner 会引入第二配置来源、版本和迁移合同，当前首版不采用。

## 4. 裁决后可机械形成的生产合同

生产初始化唯一顺序：

```text
本能根运行锚点完整读回
-> 冻结当前 G0
-> 读取当前安全根定义
-> 未发布：以固定生产幂等身份和裁决后的内建定义调用 发布安全根定义_v1
-> 已发布：逐字段互证定义、版本、来源和本能根锚点
-> 发布结果未知：只按原幂等身份回读收束
-> 冻结 Gread
-> 调用 读取当前安全根定义_v1 独立读回
-> 逐字段一致后才建立完整秒和被动维护游标
```

已有定义与当前内建定义异义、版本非 `1`、来源不同或锚点不同均启动失败；首版生产初始化不得自动迁移、覆盖或退出已有定义。后继版本迁移必须另行冻结版本切换原因、兼容边界和发布者。

生产定义发布成功只证明安全根定义可正式读回，不证明主动安全结算、被动服务维护、双根自检或整体本能闭环已经完成。
