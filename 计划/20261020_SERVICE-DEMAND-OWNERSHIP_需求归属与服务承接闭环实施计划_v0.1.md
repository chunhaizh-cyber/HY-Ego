## 4. 结构合同

### 4.1 新增公共DTO

均声明在`海中鱼巣/领域/新_需求类.h`，不新建工程文件。

```cpp
enum class 新需求执行域 : std::int64_t {
    自我执行 = 1, 被认知 = 2
};
struct 新需求认知来源 final {
    稳定编码 理解节点;
    std::optional<稳定编码> 来源要求节点;
    std::optional<稳定编码> 内容确认节点;
    friend bool operator==(const 新需求认知来源&,
                          const 新需求认知来源&) = default;
};
struct 新被认知需求建立请求 final {
    稳定编码 需求主体存在节点;
    稳定编码 目标存在节点;
    新需求目标定义 目标;
    新需求认知来源 认知来源;
};
struct 新需求记录全集结果 final {
    新需求操作状态 状态 = 新需求操作状态::入口拒绝;
    std::vector<新需求信息> 需求组;
};
```

在`新需求信息`与`新需求治理信息`各增加必需`需求主体存在节点`、必需`执行域`和可选`认知来源`，默认枚举不得代替持久字段读取校验。`新需求操作状态`追加`执行域不适用`、`认知来源不合法`、`同来源目标冲突`，保留已有枚举值；错误结构和资源失败不映射成这些正常业务拒绝。

`新需求记录全集结果`放在`新需求信息`定义之后；引用`新需求操作状态`的DTO放在该枚举之后，执行者不得通过重复类型解决声明次序。

### 4.2 物理组织

继续使用同一`需求节点类型`，在需求owner私有schema增加以下字段节点：`需求主体字段`、`需求执行域字段`、`认知理解字段`、`认知来源要求字段`、`认知内容确认字段`、`被认知需求登记字段`、`需求归属格式字段`。字段节点由现有初始化方式取得稳定编码，不硬编码全局数值。

自我执行D：主体为双根共同指向的唯一自我；根/父/来源/权重/列表保持现有合同；认知来源为空。旧外部服务来源自我D仍是自我需求，其目标E不能被迁成主体。

被认知D：主体和目标E分别合法；保存完整现有值/方向目标；无根角色、无需求父子边、无`来源承接节点`、无取得X、无自我需求列表项；`权重=0`，首次活动状态为活动，认知来源恰一。由`需求树根节点`的`被认知需求登记字段`引用，但该字段不是目标分解父子关系。保留治理状态不等于该存在获准被服务。

该记录不是世界树存在，不给D建立虚拟存在，不把D编码放进目标存在。主体关联唯一事实为D的主体字段；反向查询命中后完整读回，不在E再保存可独立修改的副本。

### 4.3 来源与查重

首段生产来源仅复用已有正式理解/要求/内容确认owner，不从字符串、私有类型键、同名人或登录信息猜主体。两条生产入口均须重新读取该owner材料。本段发布入口必须有有效内容确认；`内容确认节点`为空时返回认知来源不合法且零写，不承诺未确认理解发布能力。该可选载荷只保留形状表达，并非建立未确认D的旁路。确认读取接口返回的主体、目标、U和可选R必须与请求逐项一致；没有独立未确认理解读取提供者时不得凭调用方填值发布。

被认知D幂等键固定为`主体E + 理解节点`；同键目标、来源要求或确认定义异义返回`同来源目标冲突`且零写，不覆盖既有目标。相同目标但不同主体或理解身份不自动合并。重复同材料返回同D；新理解身份可形成新D，不据相似内容推断旧D已撤回。

自我执行列表键和同父同来源复用不变，因为此域主体只能是唯一自我。被认知D不加入原列表，因此不会因目标相同污染自我列表或合并不同主体。未来S使用自己的请求/承接键，不提前把本键作为服务请求身份。

## 6. 原子发布、迁移与工程失败

需求owner继续独占自身互斥，不建立新owner分区。来源读取通过既有业务owner接口，联合预期引用现有`基础联合节点快照`；通过`基础节点组追加请求/原子追加节点组`一次提交D全部字段及根登记，发布后完整读回。禁止先发布裸D再补主体、登记或目标。预期不符重新读取同一语义输入，不把竞争当业务失败；资源失败零成功载荷，结果未知先按来源查重读回，不盲建第二D。

迁移在`新_需求类::建立或取得本能双根`内部旧双根复用分支完成：使用局限该迁移入口的旧形状读取校验共同自我后，调用`迁移既有自我需求归属`，成功才返回双根复用；不能先用要求新字段的通用读回把旧D误判损坏。其唯一生产上游为`新_自我线程类.cpp::建立或取得自我本能双根`，在工作线程启动前调用。新库建双根时直接写主体及执行域。`需求归属格式字段=1`仅为一次迁移完成形状标识，不是业务版本、事实代次或授权事实。

旧库未有该标识时：先按旧结构完整校验双根可达D、列表、父子和全部同类型节点，确认每条旧D都能归入旧自我执行树，再在单个组合变化集中追加全部主体/域字段和根格式标识。保留每个D/T/X、列表项、来源、确认、权重、活动状态、完成和结算身份；不复制新D/T、不清除旧来源。无法归属或已有部分新字段异义时零本次迁移写入，工程诊断列出节点后停止受影响初始化，不猜修孤立节点。已完整迁移再次调用读回复用，标识存在而必需字段缺失视为损坏，禁止永久“主体空则默认自我”。

新外部记录不迁自我树；旧服务来源D不自动变对方D或S。旧服务执行资格按第7节守卫，旧完成事实和已结算账不回滚、不新增计值。物理删除不在本计划范围。

所有结构不一致、读取异常、ABI误用按现有日志、弹窗及工程终止路径处理；业务未求助、旧授权无法证明与工程错误区分。正常待求助不得触发终止；真实读取故障不得冒充待求助。

### 7.2 获取服务需求执行后收束

`服务要求.材料合同.h::新服务需求执行控制`追加`已记录待求助`；`新服务需求执行回执`追加`std::optional<稳定编码> 被认知需求节点`。`服务需求本能运行服务::执行服务需求采用`将上述self回执映射到该控制，校验D及来源但不要求D/T一一承接。`新_本能函数集.cpp`明确处理该控制：返回`新本能函数执行状态::已按合同返回`、`新本能函数动作阶段::已按函数合同返回`、`新本能函数结果取得状态::待取得`，保留已发生动作，结果状态组为空，不补集合变化，不将其写成经验上的“任务数+1”。它不等于任务完成。

任务端在`新任务执行信息`与`新任务服务需求取得读回结果`中追加`std::optional<稳定编码> 被认知需求节点`，X私有字段为`执行被认知需求字段`；新增`新任务操作状态 记录服务需求认知结果(稳定编码 T, 稳定编码 X, 稳定编码 D) noexcept`，声明在`新_任务类.h`的服务运行friend私有区，定义在其cpp。只允许同X服务取得依据完整且D的理解/确认与之相符，原子保存或精确复用，异义走结构错误；运行服务收到self结果后、返回本能控制前调用。不是另造信息包或新的执行轮次。

`读回服务需求取得结果`新增认知记录分支，优先完整读回X/D/确认关联：返回已找到、被认知D、来源新增数0、空结果状态组，`采用需求节点/采用任务节点`为空；禁止把外部D送入旧服务根D/T形状核验。新字段为空的旧X仍走原读取，不改写历史含义。

已经进入动作的X沿现有W3-A返回`动作已发出等待结果`并保留等待观察，不凭空结束X或生成A，也不硬走需要影响评估的self后继决议。manager释放worker；`尝试派发结果检测`读到最近X的被认知D且没有新增自我服务任务时，不为它周期派发观察工作，不占10个活动槽。正式结果通知`提交结果状态通知`仍可使其重新读取现有事实；停止/取消通知继续既有收束，普通时钟扫描及内容重复不是重做动作的唤醒依据。不存在可解除门槛的事实时保持挂起，后继承接能力实施后再冻结其专用唤醒。

尚未开始X的获取服务需求候选，本段直接操作仅为认知并记录对方D，不是代为满足D，不能要求先求助才允许首次记录。任务筹办、执行前复核及等待复核从候选正式参数取得确认C，经内容确认owner核验其当前含义并读取理解U，再调用`查询被认知需求来源(U)`。没有对应记录时，允许继续核验该认知方法其余必要条件；符合条件才进入首次真实调用。已有记录且主体、目标、U和C全部一致时，说明本份内容已经记录：返回现有`新任务方法选择状态::等待条件`，不重派同内容方法、不生成缺失方法。相同U却主体、目标或确认异义时按来源冲突/需重新确认处理，不任选记录、覆盖旧D或擅自假设新的帮助请求。

`复核服务要求承接资格(C)`只用于真正代为满足对方D的服务任务准入：复用内容确认owner核验身份及当前含义，本段没有正式帮助请求提供者，有效内容确认仍返回待明确求助，不能被解释为已承接；首次认知方法不调用该承接门。服务取得专用完成判断仍只认可本次合法新增自我服务任务数量；外部D新增不满足数量目标，零新增不作为工程故障。不同材料可重新核对和记录，但不得据此自动建立满足对方目标的任务。

### 7.3 扫描、直接承接与旧在途

自我工作线程的D/T双向检查、任务类服务任务集合投影、冲突检查均只消费自我执行全集。反向T→D检查必须确认每个T的D为自我执行域；若已有T引用被认知D，报告结构错误，不删除T、不静默忽略。

`建立或取得任务/承接需求任务`入口在任何节点写入前显式检查执行域；被认知D返回新增`新任务操作状态::需求非执行域`并零T/Vt/场景/状态写入。manager即使收到误投外部D也不能绕过此门；对新合法记录回执不得重投旧承接消息。

`新服务要求执行守卫状态`追加`待明确求助`，新函数`复核需求服务承接资格`先复用既有内容语义复核，再检查自我D父链旧外部服务来源；存在此来源即调用其每项确认的`复核服务要求承接资格`，没有独立求助/承接依据时阻止开启新的X和新现实动作，包括准备子需求。无外部来源沿既有不涉及/当前有效结果，不影响普通安全治理。manager筹办/执行前复核和self重新启用改用新门，映射为等待；本能调用前复核同样不准绕过。原`复核需求服务要求语义`保留内容有效性职责，旧完成/结算读取仍使用它，不把待求助冒充结算工程错，不在结算入口统一套新动作门。已开始X只允许既有观察、事实收束和记录；已完成/已结算身份及既有贡献不改写，新入账仍须既有结算门槛合法，不凭迁移补造授权或回滚已入账事实。
