## 3. 数据与物理合同

在`新_需求类.h`新增：

```cpp
enum class 新需求执行域 : std::int64_t { 自我执行 = 1, 被认知 = 2 };
struct 新需求认知来源 final {
    稳定编码 理解节点;
    稳定编码 内容确认节点;
    std::optional<稳定编码> 来源要求节点;
    friend bool operator==(const 新需求认知来源&, const 新需求认知来源&) = default;
};
struct 新被认知需求建立请求 final {
    稳定编码 需求主体存在节点;
    稳定编码 目标存在节点;
    新需求目标定义 目标;
    新需求认知来源 认知来源;
};
struct 新需求记录全集结果 final {
    新需求操作状态 状态 = 新需求操作状态::入口拒绝;
    std::vector<新需求信息> 需求组;
};
```

`新需求信息/新需求治理信息`增加必需`需求主体存在节点`、必需`执行域`、可选`认知来源`。DTO声明在其依赖类型之后。`新需求操作状态`末尾追加`执行域不适用/认知来源不合法/同来源目标冲突/需重新确认`，旧值不变。不得用枚举默认值掩盖持久字段缺失。

继续同一需求节点类型；私有schema增加`需求主体字段/需求执行域字段/认知理解字段/认知内容确认字段/认知来源要求字段/被认知需求登记字段/需求归属格式字段`，初始化动态取得稳定编码，不硬编码全局编码。

自我执行D：主体由双根共同目标确定为唯一自我；根、父、来源、权重、列表和目标合同不变；认知来源为空。旧外部服务来源D仍属自我执行，不能由其目标E推断主体。

被认知D：主体E和目标E分别合法；保存完整现有值/方向目标；无根角色、需求父子边、来源承接任务、取得X和自我列表项；权重0、初始活动状态为活动；认知来源恰一。需求组织根用`被认知需求登记字段`引用D，不将登记冒充父子分解。D不是存在，不建立需求虚拟存在；E不增加双向可写需求镜像。认知者为自我，内容确认不代表求助或承接。

新D幂等键为主体E+理解U。同键目标、C及可选R完全一致复用；同键异义零写返回同来源目标冲突。不同主体或U不因目标相同合并；新U不自动撤回旧D。原自我列表键和同父同来源复用不变，新D不加入自我列表。

## 4. 函数合同与来源

公开声明在`新_需求类.h`、定义在其cpp：

```cpp
新需求建立结果 建立或取得被认知需求(const 新被认知需求建立请求&) noexcept;
新需求记录全集结果 查询全部需求记录() const noexcept;
新需求记录全集结果 查询主体需求(稳定编码 主体存在, 新需求执行域 域) const noexcept;
新需求记录全集结果 查询被认知需求来源(稳定编码 理解节点) const noexcept;
```

建立入口只保存被认知D，不调用self/manager、不创建自我执行D/T。需求owner经既有`新服务要求确认读取接口::复核服务要求确认语义`重新核验C当前有效，并核对其主体来源人、目标E、目标、U、可选R与请求一致。主体不能由目标E推断；调用者填值不能代替来源读取。

本段只支持现有完整已确认来源，缺C或来源不符返回认知来源不合法、零写；C过期返回需重新确认；未装配接口明确入口拒绝，不假成功。没有未确认理解提供者，不承诺该分支。既有来源DTO已有独立目标E字段，新结构不得强制主体=目标；当前生产输入能提供哪些目标不由本段扩大。

读取范围：

- `获取需求/读取需求治理信息/是需求节点`覆盖两域，完整校验域内形状。
- `查询全部需求/查询全部需求列表/按完整目标查询/查询目标存在需求`保留自我执行范围，注释明确；原调用无需改成全部记录。
- `查询全部需求记录`完整核验双根可达自我D与被认知登记D：互斥、无重复，并集覆盖全部需求类型节点；孤立未知节点仍报错。
- 主体/来源查询对完整记录过滤、按编码排序去重；有效主体无记录为已找到+空组；非法主体/域明确拒绝；失败不返回部分成功载荷。
- 合法被认知D无子需求；普通建立入口拒绝将其作为父D。集合成员身份仍仅表达是合法需求，不证明可配任务。
- 被认知D活动状态只是治理标签，修改不分配权重或创建T。当前满足仍按E/F复核；方向目标单点仍返回需要执行前后比较，不任取历史X。

## 5. 原子发布与迁移

新D使用现有联合预期及`基础节点组追加请求/原子追加节点组`一次发布全部字段与根登记，完整读回后返回。禁止先裸D后补字段。预期不符重新读取，未知结果按主体/U查重读回，不盲建第二D；不新增基础ABI、业务版本或第二账。

私有新增`新需求操作状态 迁移既有自我需求归属(稳定编码 唯一自我) noexcept`，由`建立或取得本能双根`旧双根复用分支调用：用仅供迁移的旧形状读回确认双根共同自我后，在返回self之前迁移；不改self初始化调用。新库双根与全部普通D出生路径直接写主体/域，包括旧服务采用原子出生路径，但不改变其业务流程。

根`需求归属格式字段=1`只标记形状迁移完成。无标识时完整核验旧双根、父子、列表及全部D，确认都属于旧自我树后，单组合变化集补齐全部主体/域和根标识。保留D/T/X、列表、确认、权重、状态及结算编码。孤立、无法归属、部分新字段异义时零本次迁移写入，保留并报告，不猜测、不删除。

有标识重复迁移完整读回复用；标识存在而字段缺失为损坏，不长期默认自我。旧服务D不自动变对方D或S，不暂停或重新授权旧任务，不改结算账。工程异常沿日志、弹窗及工程终止链，不伪装为正常未命中；合法来源过期不当工程故障。

## 6. 最小消费者闭合

1. 自我工作线程D/T双向检查只使用自我执行全集；外部D无T正常。T反查D必须为自我执行域，已有T引用外部D视为结构错误，不删除或忽略。
2. 任务`建立或取得任务/承接需求任务`在任何T/Vt/场景/状态写入前核验域；新增`新任务操作状态::需求非执行域`，合法外部D零任务写入拒绝。
3. manager对该拒绝映射既有入口拒绝回执，不报告已承接，不自动重试创建T。正常扫描不会提交外部D。
4. 任务集合、服务集合投影及冲突扫描保持原执行全集/列表范围；不改服务计值和源身份识别。所有自我D出生路径必须写新字段，不能留下旧入口产半结构。

这些是数据域变化直接必要消费者，不涉及新服务治理。两self采用入口继续现有流程，不发新认知回执，不新增X字段和等待状态。
