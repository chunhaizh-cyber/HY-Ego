## 1. 目标、裁决及完成边界

本叶修改任务内部治理的筹办要求、执行采用及身份核验，目的为让已经形成的任务执行组织真正进入W2→self/manager→W3单次本能调用及反馈链。它不改变本能函数的现实操作，不预造动作、状态、动态或因果，也不直接新增服务需求。

用户已裁决不复制方法树：抽象方法的条件、参数与组织转换为task-owned执行组织；一D一T不变，内部组织节点不形成新D/T；新增学习知识只增加选项，不覆盖旧执行依据。该裁决取代5260中“完整方法复制”的旧物理要求，其它结果途径、动作硬门、任务状态、正式子需求和owner边界保留。采用材料必须指明真实抽象M，不能把task组织、作用域或Pair要求编码冒充M/C/R。临时参数场景只保存实际节点引用并实时读取，仍用完释放。

本叶闭合：候选交付组织、组织条件筹办、结果选择与反求输入、缺口/方向/self/manager一致性、W3抽象M调用、X不可变采用证据、三种本能运行服务身份核验，以及有用问题反馈的新旧格式隔离。一个共同身份合同在一份计划中迁移，不只修改W2。

明确排除：组合方法的运行栈/角色传递/真实分支匹配/循环；新服务对象确认算法；服务需求材料角色的查找和运行服务生产装配；服务需求包转正式D；结算来源自动选择；方法学习发布；新比较/优先级策略；全部旧方法副本物理删除；全仓工程错误治理和全仓事务改造。生产支持本能根作用域，不能把组合内部本能子作用域当整体根执行。

## 5. W2与选择：唯一输入来源迁移

### 5.1 候选交付

将生产`实例化候选方法(T)`替换为明确的`交付候选方法执行组织(T)`，返回`新任务执行组织结果`；W2直接消费其状态。该入口fresh读T和当前候选材料，从完整候选M集合调用已发布增补入口；不得跨task锁取得方法闭包，复用既有方法锁释放后取得task锁顺序。交付后再次核对T状态、D目标和候选材料身份未变。新建立/已增补/精确重复/已读取可继续；合法组合控制增量不支持保持明确能力拒绝，不产生子需求或假条件不足。

旧`实例化候选方法`若因既有测试仍需声明，只保留已明确标记的legacy能力，不得由任何生产W2调用。`绑定方法实例`及方法owner复制API本叶不删除，也不得被新生产链回退调用。

组织全部根候选保留；本次仅对实现方式为本能且属于根候选的作用域进行单调用筹办。组合根明确能力不支持，沿现有不支持分支零动作，不把其内部本能节点独立晋级。混合候选不因此发明跳过不支持候选的新排序策略；维持现行完整核验和保守返回行为。

### 5.2 条件筹办和结果选择

`核验任务条件和参数`只从task组织中的参数要求、Pair条件/结果/关系读取业务定义；源方法owner仅核验M是否仍存在、启用、为本能及函数可用，不能用当前M重新生成已存要求。保持现行场景范围、存在/特征匹配、集合包含、虚拟任务成员同一性、参数不足及多候选处理策略。

提取同文件私有值式helper，输入单作用域、配对要求及可选有效条件，供筹办、选择后复核、执行前复核使用；不能构造“假新方法信息”后交给method owner当正式方法。可构造明确的本次来源投影DTO供既有纯比较算法消费，来源身份只能是真实抽象M/Pair/C/R。

具体复用形态冻结为task私有成员`新任务治理条件筹办结果 核验任务条件和参数内部(稳定编码 T, const 新任务本能采用材料* 固定采用, bool 允许当前执行中) const noexcept`：公开原入口传`nullptr,false`，沿原条件核验函数体复用对象查找/参数绑定/集合关联及各状态分支；固定采用非空时，仅核对其指定的本能根作用域和Pair，不重新选择其它候选，条件读取使用`需要条件`override。固定模式从采用中的绑定验证明确对象/特征及相同角色关系，不重新全场景搜索替换对象，亦不因世界后来多一个同类对象而把既有明确绑定变成候选不唯一。内部先比较组织原始定义与采用的原始条件/参数/结果/关系，不能直接信任override；固定模式无需重新消费当前粗召回列表作为定义来源。固定模式允许执行前的`待检查条件/待执行`；`允许当前执行中=true`只由第8节当前X输入复核入口在证明当前T/X后调用，绝不放宽写状态。组织到算法的私有适配器返回真实来源M及task要求的值式视图，不能新建节点或调用method复制/覆盖API。不得重写整套约800行参数查找算法来建立第二规则。

`选择任务方法结果`复用现行算法：能达到目标域优先；否则方向一致且有利端点最大；同档多项维持`匹配不唯一`。不新增最窄、新增、命中数或稳定编码优先。每候选独立反求各条件输入，选定后形成完整`本能采用`，再按其`需要条件`fresh查正式值；不再写方法副本或组织原始Pair。不因返回有效条件值域就宣称真实条件具备。

`提议任务条件子需求`以同一采用的`需要条件`生成全部条件投影及缺口项；未知对象依旧只有缺口材料，不造占位T/E。父子方向匹配、需求冲突检查、预计变化和结果获取方案从task Pair读取，保留所有既有硬门。父任务收到子任务完成后仍重读正式事实。

方法新Pair只能在合法重新筹办时加入并重新选择。self已经给出某次采用后，W3核验该采用自身的源定义、D、参数、条件、预计和结果途径，不因后来出现更好候选自动改选。若采用仍合法，新候选不会使它失效；若自身前提变了，零动作回筹办。W3不得继续调用无参`选择任务方法结果(T)`重新挑选另一方法。

### 7.2 X存储与读回

新增X唯一可选`本能采用`子节点引用。新生产本能X必有该子节点；旧X无此字段就是legacy，不能依据最近T字段推造采用。子节点持有三项task定位、有效条件要求及完整角色绑定；源M由X现有方法字段保存，原始参数/Pair定义通过不可变task组织投影，不重复形成第二方法定义。禁止删改仍被X引用的组织定义。X读回据此填充完整`新任务本能采用材料`，只能读取task组织，不能读取当前method Pair来补旧证据。

采用子节点、有效条件子项和绑定子节点分别使用task owner新私有类型/字段，布局如下：

- 采用：所属X、组织/作用域/Pair要求引用，各恰一；有效条件关系规则及按序条件项；按序角色绑定。
- 条件项：沿现有task条件要求字段布局完整保存全部定义，序号连续且无重复；没有反求也完整保存本次有效要求。
- 绑定：角色、顺序；世界场景/实际存在/实际特征引用组，或任务虚拟存在三元引用，或服务要求分项引用，或确认引用；合法组合与`新方法参数角色绑定`完全一致，不另创通用“材料ID”。服务要求引用逐字段保存其现有合同成员，不序列化C++布局。
- 沿现行开始函数建立处于task锁内构造阶段的X及其基础/预计/结果方案结构；在更新T最近定位或Vt状态之前，用`原子追加节点组()`一次建立采用子节点及全部子项，并向该构造中X追加唯一采用引用。请求预期绑定规划时读取的X完整结构，新节点之间用组内引用。X与采用的连接、采用内容作为一批共同发布，不能逐项追加。随后在仍持task锁时完整读回X及采用，与请求逐字段一致后才允许更新T定位/状态。不要把现有裸X分步构造宣称成全X原子创建。

task锁覆盖建立前核验、完整新X发布、现行T最近M/X更新、Vt状态推进及读回。T最近字段及Vt状态仍沿既有owner更新/读回边界，本叶不宣称基座已有“新X＋既有T字段修改＋特征状态”全域原子事务。新X证据必须完整后才允许T进入执行中；若T状态已经前进，保留X并诊断，不盲删；状态未前进且确认零动作，沿现有回滚边界清理本次新结构。不能用全域事务尚缺为理由省略新X内部原子建立。

绑定物理成员依据：`新方法实际特征绑定`只含`特征节点`；`新任务虚拟存在引用`含`任务节点/虚拟存在节点/状态特征节点`；`新服务要求分项引用`含`理解节点/分项`（分项合法枚举来源人类、目标存在、目标特征类型、目标定义）；`新服务要求确认引用`只含`确认节点`。绑定容器保存全部角色及上述optional判别；不把分项的当前读取值、确认结果或整个需求包持久化进X绑定。字段缺少、多个互斥分支同时存在、序号间断/重复是结构错误。

X存储仅在`新_任务类.cpp`现有私有组织空间实现，签名为`void 建立执行采用已加锁(稳定编码 X, const 新任务本能采用材料&)`、`std::optional<新任务本能采用材料> 读取执行采用已加锁(稳定编码 X, 稳定编码 T, 稳定编码 M)`和`void 清理执行采用已加锁(稳定编码 X)`；未带`noexcept`的私有异常由当前公开入口工程终止链收束。现有`读取执行信息`在解析T/M后调用新读器，保证所有内部和公开读回都包含采用，不只在`获取执行实例`外层补字段。写器只消费已校验材料；读器按完整字段基数/类型/序号及task引用闭包读回；清理器先枚举X独占子结构再删除，不遍历来源引用。组织写器当前`新节点()`隐含组内根0为组织，**不能原样复用来建立X采用**；允许提取条件字段写入helper或加明确独立X模式，重新指定owner/root索引，禁止把X标成组织根或给X挂组织成员字段。不另建公共持久codec服务。

`开始方法执行`对新本能请求要求采用存在且完整，逐字段核验同一T组织和M；不能因T仍有历史`方法实例节点`拒绝合法新采用。旧请求无采用不允许产生新生产本能X。旧X/A/归档可读，旧尚在途X只恢复结果获取，不补发W3-A。

X采用读回、清理、`撤销未进入动作执行`及任务删除引用保护覆盖全部新子结构；撤销只删本次未入动作X独占节点，不删组织、方法、概念和世界节点。现行状态推进/预计/结果方案/服务结算来源合同不变。

## 8. 三个运行服务身份与一次调用

新增task公开只读入口：

```cpp
std::optional<新任务本能采用材料> 读取执行本能采用(
    稳定编码 执行实例节点) const noexcept;
enum class 新任务本能输入复核状态 : std::uint8_t {
    仍具备 = 1, 条件已变化, 场景不一致, 执行不在当前位
};
新任务本能输入复核状态 复核执行本能输入(
    稳定编码 执行实例节点, const 方法参数场景&) const noexcept;
```

无X或legacy X返回空；存在新采用结构却损坏走工程终止，不伪装空。该入口在task锁内完整读取X和其采用定义，不重新选方法，不要求T仍在X当时状态；运行服务另外核验当前T/X状态和最近定位。只能用其返回证明X采用来源，不能把“可读取旧X采用”当再次执行许可。

`复核执行本能输入`只用于动作前：task锁内读当前T/X，确认X为当前执行中且没有结束、采用存在，然后比较`场景.M == X.M == 采用.来源M`及`场景.全部角色绑定() == 采用.参数绑定组`（使用相同规范化规则），再以固定采用/允许当前执行中调用上述私有核验helper检查有效条件。没有当前位/legacy为`执行不在当前位`，合法条件变化为`条件已变化`，替换场景绑定为`场景不一致`；工程读失败或结构异义一律工程终止，不进入这些正常控制值。

服务对象和服务需求的动作前核验必须调用此入口，公开服务需求`执行`包装也不能绕过。仅同M/X及泛化参数规格成立不足以授权换另一对象或另一确认要求。结算的普通动作发布端口没有场景参数，沿task W3动作前复核及结算本能自身角色检查；其事后`确认并收尾`只读冻结采用身份，**不得复核动作前条件仍成立**，因为服务值和来源任务状态已合法改变。

服务对象：删除新路径对副本根/来源链的依赖，要求`场景.M == X.M == 登记抽象M == 采用.来源M`，X/T当前执行状态和最近定位不变，task采用归属完整。继续核对同一窗口来源与真实角色。

服务值结算：执行和收尾的新X分支按上述真实M与采用核验；旧X仅在收尾读取分支沿原来源核验。保留结算来源T、前值、目标值域及动作幂等合同，**不把结算动作来源从已完成服务T强行改为X**。M身份修正不改结算+1或结算资格。

服务需求：以`新_本能函数管理类::读取本次执行实例(场景)`作为唯一调用身份入口，移除私有`调用组`及其第二执行登记。核验方式由正式登记M映射，参数场景材料读取接口必须仍为同一owner；使用task采用证明。公开`执行(M,场景,X)`可保留，但只建立现有通用守卫后调用方法owner，不再持有独立调用表；不存在同时嵌套两套守卫。普通W3已有守卫可直接调用，不能再调用该包装入口重入。

一次动作保护不能随调用组丢失：在`新_本能函数管理类`增加`static void 标记本次动作入口(const 方法参数场景&) noexcept`。它只核验当前线程同一场景及X并设置调用期“入口已消费”，无守卫或重复消费进入工程终止；不是现实授权、业务状态或历史账。执行守卫构造时在私有全局互斥下登记活动X，跨线程/不同场景的同X并发守卫同样工程终止；构造失败不留下登记，析构精确核对并移除本租约，线程局部身份清空。不保存已结束X集合，不改变X稳定身份或重新执行许可。

服务需求`建立动作`在完成可正常失效的确认复核后、第一次动作查询/发布前调用`标记本次动作入口`。服务互斥保护同X查重与动作发布这个区间，阻止绕过容器身份重复发起；查询已有同X动作先核对定义M/目标/场景及来源，再拒绝重复进入（工程错误），不能直接返回已有动作冒充本次新执行。动作发布尝试后任何工程失败必须终止，不返回可重试的无动作业务结果。动作已经成立则保留，不回滚重做。通用守卫并发保护及正式动作来源共同承担原调用组的一次性保护。

三个服务的关闭/租约和登记生命周期保持，不能因消除调用表去掉已有端口共享保活。生产装配尚缺的服务需求运行服务仍不宣称已可达，本叶只让合法已装配消费者使用统一调用合同。

## 9. 真实问题反馈与持久格式隔离

`新方法问题反馈材料`追加`新方法问题采用来源 采用来源`及`std::optional<新任务本能采用材料> 任务采用`；新增枚举`旧方法副本=1,任务执行组织=2`，旧默认取前者。来源是明确结构种类，不是服务版本。旧`实例方法节点`明确legacy-only：新材料为零且`任务采用`存在；旧材料实例M非零且无任务采用。种类与载荷不一致、两者同时存在或同时缺失拒绝，不靠实例M是否为0猜新格式，不把抽象M填旧实例字段凑合法。

新材料`采用配对`字段保留旧用途，不承载task Pair。新格式中该字段不写入载荷，也不作为新材料业务依据；新完整条件/结果/线性及来源身份取`任务采用`。旧解码/学习继续取legacy采用配对。新反馈的`来源抽象方法节点 == 任务采用.来源方法节点 == X.M`。

`准备执行问题材料`从X读采用证据，固定原始预测和有效输入，不再到当前M查Pair；动作前场景采集仍采正式绑定引用。收束时核对同一X/M/采用，不能因方法学习新增或当前候选变化重新生成反馈。只保留现行判定为有用的问题；不扩大为保存全部执行。

持久格式：

1. 保留`方法问题场景归档/1`的原编码、原四元身份键和原来源Pair尾扩展解码，禁止改既有嵌套布局。
2. 新材料使用`方法问题场景归档/2`；解码由外层归档格式字段选择，不用首个稳定编码猜魔数。`方法问题归档.模拟世界.h`的内部编码/解码入口增加显式格式参数或分别命名格式2函数，调用者必须传外层判别，未知格式工程诊断。
3. 格式2问题头固定顺序：T、X、抽象M、任务采用、可选本次运行对、A、原方向验证值、原值域验证值、问题组、符合预测组、预计未发生组、计划外组、实际状态组；解码明确设置采用来源为任务执行组织。场景快照仍沿现有两阶段组织，类型化逐字段编码。
4. 任务采用按第4节声明顺序编码，绑定按现有角色结构逐字段编码。格式2支持任务集合概念值域及参数集合约束，完整保留其现有判别/成员字段；格式1当前对该类拒绝的字节合同不变。**外层格式判别必须同时传入问题头和动作前/结果场景快照编解码**，否则快照中的服务任务集合特征概念仍会走格式1拒绝。不得以未知variant序号默认成空集合。
5. 格式2身份键为`{T,X,抽象M,组织,作用域,Pair要求}`；同T/X已有另一格式或不同身份视为冲突，不建立第二归档。相同键完整材料异义也冲突，不覆盖旧材料。
6. `问题入口有效`、完整读回、去重、保存和`方法问题学习.服务`同时区分新/旧材料。学习新材料只分析冻结的采用和场景副本，不重新向当前M取旧预测；保留“只保存反馈、不自动发布细化”的现行边界。

归档格式是持久字节判别，不是服务合同版本或任务版本。旧归档不批量重写，旧X不强制迁移。

## 10. 生命周期、并发、错误及迁移界限

- 方法闭包在方法锁内读完释放后进入task组织增补；不在task锁下重入增补的源闭包读取。任务采用/执行读回维持task owner独占发布。
- 调用本能函数、外部端口及场景采集时不持task结构锁；调用前冻结X和守卫，调用后按同X收束。
- 新X完整采用不受后续组织增补影响；角色/源Pair同身份异义按既有稳定定义工程规则处理，不择优覆盖。
- T历史方法副本字段保留读取；新生产完全不消费其条件、不新建副本、不回退旧路径。旧记录不因此次迁移删除。`开始方法执行`、服务收尾和反馈明确按新采用有无区分，不用“字段可能碰巧有效”猜分支。
- 工程读取/编解码/原子发布/引用一致性错误：记录日志、弹窗后工程终止，不转为条件不足、需求失败、学习反例或默认false。合法条件变化和明确能力不支持保持业务控制，不升级成工程故障。
- 当前流程的跨进程执行恢复仍不在本叶宣称完成；新字段必须能通过正式读回完整重建，不能只存在进程map。
