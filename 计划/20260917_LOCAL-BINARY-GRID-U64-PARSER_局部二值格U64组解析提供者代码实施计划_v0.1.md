# 局部二值格 U64 组解析提供者代码实施计划

身份：`LOCAL-BINARY-GRID-U64-PARSER`

版本：v0.2

状态：可执行

基线：`c452d5a4`

## 1. 目标、完成条件与正式依据

按同名详细设计 v0.2 实现 4120 §3.1.1、§3.2 的两个局部二值格 `U64组` 纯解析入口。完成条件是：冻结的 DTO、轮廓/体素格式核验（含全零占用体素的成功）、严格非成功清空、主工程登记、仓外专项驱动实际运行、施工记录与验证记录均已发布。

依据为 2100 v0.15、4120 v0.12、4180 v0.14、4181 v0.2 和同名详细设计。代码实现解析合同，不创建特征类型或值事实，也不启用比较。

## 2. 当前事实与范围

当前 `数据服务.特征值类.h` 可完整读取 `U64组`，但没有独立写入；当前特征类的准确特征路径仅支持 I64。现有 `数据服务.特征值域比较类.*` 的 U64 组分支仍为明确的待实现，不得在本计划中改动。新提供者是无依赖、无状态的纯格式叶，可独立施工。

## 3. 施工合同

执行者逐字实施详细设计第 4—6 节的 DTO、两个成员函数、成功谓词与状态映射。特别要求：

1. 轮廓只能由平方组长度得到 `N=8*sqrt(L)`；体素只能由首项得到 `N`。不得以同一入口自动猜测两者之一。
2. 所有 `N²`、`N³`、块数、颜色数、总长度和 `size_t` 转换均先做受检算术；不得溢出绕回。
3. 体素颜色尾项的高 40 位必须为零，且颜色项数必须与全部占用位的 `popcount` 精确一致。
4. 解析回执不保留输入地址/引用或材料副本；不产生坐标、节点、值身份、比较关系或任何事实写入。
5. 所有非成功清空 optional 格式；不得把非法格式变为空结构、未知、未占用或比较不包含。
6. 全零占用位图在每个合法 `N` 下均可成功，颜色项数为零且颜色尾段为空；成功谓词不得要求颜色项数非零。解析器不规范化输入、没有幂等键、也没有幂等冲突分支。

## 4. 实施步骤

1. 新建头文件，声明 v1 DTO、状态、成功谓词及无状态服务类；只包含标准库头，不引入 L1 或领域服务。
2. 新建 `.cpp`，实现受检乘法、整数平方根、popcount 累计及两个解析函数；禁止浮点平方根作为合法性判断。
3. 将两个生产文件登记到主工程 `.vcxproj/.filters`，各恰好一次。
4. 在 `D:\TEMP\海中鱼巣\LOCAL-BINARY-GRID-U64-PARSER\<本轮唯一标识>\` 新建隔离专项驱动，覆盖详细设计第 7 节矩阵（明确覆盖全零占用体素）。以新头/源直接编译、运行；驱动不得进入仓库或生产工程，完成后按 CODE-FILE-01 清理或记录残留。
5. 记录每一公开函数、无写依赖、格式矩阵、编译/运行退出码、主工程两配置尝试及范围外边界。
