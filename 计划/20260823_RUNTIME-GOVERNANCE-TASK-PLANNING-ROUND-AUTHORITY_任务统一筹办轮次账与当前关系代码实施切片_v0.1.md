## 5. 冻结实现合同

### 5.1 版本化权威和分区

机械实现详细设计 §5—§8：

- 新增不可变 `L2任务筹办轮次权威记录事实`，版本固定 1，引用任务、虚拟存在、列表项和现有首次记录；
- 新增 `L2任务筹办轮次分区`：`统一轮次权威 / 遗留实例轮次 / 内部不一致`；
- 恰一版本 1 权威登记 + 恰一合法当前关系才是统一；
- 0 权威 + 0 统一当前关系 + 0 后继记录才是 legacy；
- 其它组合为内部不一致，不 fallback；
- legacy 读取不返回推测统一轮次。

### 5.2 唯一统一链

- 轮次 1 直接使用现有 `L2任务初次筹办准备记录事实`；
- 轮次 2 及以后使用 `L2任务后继筹办准备记录事实`；
- `任务当前筹办准备端点`关系只指向同权威的首次或后继记录；
- 后继记录永久引用权威和首次锚点；轮次大于 2 再引用直接前一后继；
- 后继记录历史不退出，只有当前关系换代；
- 同一正式触发事实全部历史唯一，换准备键返回`触发已消费`。

DATA-L2 至少新增：

```text
L2任务筹办轮次权威记录身份 / 事实
L2任务后继筹办准备记录身份 / 事实 / 触发类型
L2任务筹办轮次分区
L2任务当前筹办准备事实
L2按任务读取筹办轮次分区请求 / 结果
按权威身份、后继身份和后继准备幂等身份读取 DTO
L2提交统一轮次推进材料
```

### 5.3 新初次筹办融合写扩展

扩展现有 `新增任务与首次初次筹办准备记录` 同一 G1 写集：在原任务、虚拟存在、首次记录旁创建版本 1 权威登记及其四条引用关系，并建立任务指向首次记录的当前关系。发布后读回必须互证。

原准备键命中没有权威登记的旧首次结果时，继续返回旧首次结果及 legacy 分区，零补写、零冲突。不得按创建 G 区分，也不得把精确重复变成迁移。

扩展 DATA 融合结果携带分区和可选权威：新结果为统一且权威必有，旧结果为 legacy 且权威为空。既有 BIZ 初次筹办公开 DTO 不变，不修改其数据头或 provider 文件。

### 5.4 实际结果入口双分区

保留单一公开 BIZ provider。扩展现有第二段 DATA 请求为强类型联合：

```text
统一轮次权威 + 必有统一轮次推进材料
遗留实例轮次 + 统一轮次推进材料必须空
```

DATA 取得现有 task-owner 互斥体后重读同 G 分区；请求形状与事实不一致固定引用冲突。

统一分支的原第二段写集同代：

```text
原正式待重筹办状态迁移
+ 实际结果触发的 N+1 后继准备记录
+ 旧统一当前关系退出
+ N+1 统一当前关系建立
```

后继记录以旧任务实际结果为唯一正式触发事实，并引用正式状态、旧路径、旧实例和目标裁决证据；保存原业务幂等与 DATA 准备幂等。同一实际结果换任一键不得重复推进。统一工作包旧 / 新轮次只从后继记录读回，禁止使用实例加一作为权威。

`任务重筹办触发结果`增加可选已消费后继记录身份：同触发换键返回`触发已消费`和记录身份，不携带工作包且不算成功；同键同完整请求才返回精确重复工作包。legacy 分支不产生该状态或记录身份。

legacy 分支仅在 0 权威 / 0 统一关系 / 0 后继时执行原写集，保持现有实例轮次工作包和全部错误 / 幂等语义，零统一写。这是显式分区，不是 fallback。

### 5.5 并发和未知结果

- BIZ G0 读分区；第一段首态沿现有 G CAS；第二段同一 task-owner 锁内再读分区和所有旧当前关系；
- 未来迁移若先提交权威，legacy 的旧 G / 无权威前提失效；legacy 若先推进，未来迁移必须重审并拒绝暗补；
- 已有权威的任务任何 legacy 形状永久拒绝；
- 同一 N 的不同统一触发只有一个 CAS 成功；失败者不得自动形成 N+2；
- 统一提交未知时按准备幂等身份和历史 G 恢复本次后继及工作包；
- 发布后读回失败不撤销已提交事实。

## 10. DRIFT 与退役条件

以下情况退回计划支撑：

- 现有首次记录不能继续作为唯一轮次 1；
- 无法在原第二段 task-owner 写集原子发布后继和换代当前；

- 必需验证持续失败且无法在白名单内安全归因。

legacy 退役必须另立计划，并等待：初次筹办生产接线、既有任务具名迁移或正式闭合、无法裁决任务不回填、生产不再创建无权威任务的集成证据。上述条件不属于本计划完成条件。
