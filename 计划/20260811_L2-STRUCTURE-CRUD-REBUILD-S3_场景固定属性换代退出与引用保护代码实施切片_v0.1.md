## 1. 目标、范围与完成条件

在已发布的 S1 场景节点、S2 父子 / 成员关系、L1 历史关系组、L1 历史属性值组和 L1 当前引用闭包保护之上，完成 `L2场景结构服务` 的场景固定属性初始发布、值换代、场景整体退出、L1 `引用冲突` 精确映射，并把当前 / 历史完整场景投影扩展为同时包含完整固定属性、直接子场景和直接成员的最终 S3 形状。

本叶只扩展现有场景唯一所有者，不建立第二场景服务、属性仓、反向引用查询或业务资格门面。它不实现“按存在查场景成员关系”的反向公开投影，不实现存在 E2、其它四类结构或 A1 聚合面。

完成条件固定为：

1. 新增一个固定属性初始函数、一个固定属性换代函数和一个场景退出函数，全部位于现有 `L2场景结构服务`；
2. 固定属性初始以一份 L1 写集同时建立新值和当前槽；换代以一份 L1 写集同时建立新值、切换槽并退出具名旧值；
3. 场景退出请求显式给出本结构当前直接父关系、直接子关系、成员关系和固定属性值编码闭包；L2 只核对并提交该显式闭包，不自动补造退出项；
4. 请求闭包与场景所有者当前事实不一致时返回 `L2结构状态::引用冲突`、零变化；仍有跨结构当前引用时由 L1 在候选前返回 `L1中性写入状态::引用冲突`，L2 逐值映射且不降级为内部不一致；
5. 场景退出成功时，场景节点、显式父子 / 成员关系和固定属性值在同一 L1 事实代次退出，其它场景 / 存在端点不退出，历史仍完整可读；
6. 当前完整场景在同一期望代次内返回权威节点、全部当前属性槽及值、全部直接子关系和全部直接成员关系；属性组按“属性类型、值编码”升序；
7. 历史完整场景在现有前后代次夹取中加入 L1 历史属性值组，只使用目标历史截止有效的节点、值和关系，不用当前属性补历史缺项；
8. S1 节点新增结果仍只在创建代次形成空属性 / 空关系的完整初始场景；关系端点核对可接受有属性普通场景节点，但不把节点骨架对外返回为完整场景；
9. 现有 `读取场景节点` 收敛为完整场景兼容入口，当前读取与 `读取完整场景(当前)` 逐字段一致；历史读取以请求期望代次同时作为历史截止，不再返回空属性的 S1 部分投影；
10. 新增三个写入入口均保留完整幂等语义、旧期望代次直提收敛、恰一次 L1 提交、首次事实代次读回和非成功空载荷；
11. 生产外参数验证覆盖初始属性、多类型、换代、完整当前 / 历史投影、场景完整退出、请求闭包缺项、L1 跨结构引用冲突映射、幂等 / 漂移 / 非成功和并发代次边界。

### 2.2 复用 / 扩展裁决

复用现有 `L2属性提交项`、`L2属性事实`、`L2场景事实`、S2 关系 DTO，不增加场景私有属性类型、通用 JSON 或第二值容器。初始与换代分为两个具名请求，因为两者的当前槽前置和成功载荷不同；不用一个含糊 `设置属性` 函数隐式决定创建还是换代。

场景退出不能只提交场景节点编码；这会把本结构附属关系 / 值的选择责任偷偷下推给 L1。裁决为公开退出请求显式携带按稳定编码排序的本结构闭包清单；L2 从同代次完整场景和父关系投影核对“不少、不多、不错类”。仍有其它结构引用时，不向 L2 暴露全部引用，只由 L1 对最终写集返回引用冲突。

当前属性类型只能先从节点当前槽发现，因此当前完整场景读取使用两次 L1 一致当前投影：第一次只在请求期望代次读场景节点并发现有序槽类型；第二次在同一期望代次重读节点，并一次取得全部具名属性值与两个源关系组。任一次漂移都返回事实代次漂移和空场景；两次都成功才能组合。这不是全仓扫描，也不允许混代。

现有 `读取场景节点` 仍以 `L2场景事实` 作为成功载荷，因此它不能在属性形成后继续返回空属性骨架。裁决为保留公开签名作兼容入口，内部转换为 `读取完整场景`；场景关系类型登记因而成为该兼容入口的真实前置。S1 的旧私有部分读取路径退出，不建立新的“节点简读”结果。

所有 DTO 补齐逐字段默认比较。不为初始 / 换代增加属性类型版本、显示名或业务值域。换代请求以 `旧值稳定编码` 精确绑定旧不变事实；旧值的所属、类型、材料和来源由稳定编码权威回读，不在请求重复。

新增五个头文件内联纯值辅助，签名固定为：

```cpp
inline bool L2场景固定属性新增请求有效(
    const L2场景固定属性新增请求& 请求) noexcept;
inline bool L2场景固定属性换代请求有效(
    const L2场景固定属性换代请求& 请求) noexcept;
inline bool L2场景退出请求有效(const L2场景退出请求& 请求) noexcept;

    const L2场景事实& 场景, std::uint64_t 截止) noexcept;
```

属性提交项有效性固定为：属性类型身份非零、来源稳定编码非零；I64 任意值合法，I64 组 / U64 组非空，独立材料引用编码非零。两个属性写请求还要求合同、期望代次、幂等身份和场景身份非零；换代的旧值编码非零。

退出请求要求合同、期望代次、幂等身份和场景身份非零；可选父关系若存在则非零；三个编码组分别严格升序、无重复、项全非零，并且父关系与三组之间全局无重复。空父关系和三组全空是无附属场景的合法闭包。

`L2属性事实截止投影完整` 要求类型、值、来源非零，材料完整，创建代次非零且不大于截止，退出代次若存在则不小于创建代次且不大于截止。最终 `L2场景事实完整` 扩展现有 S2 完整性：固定属性每项在截止投影完整、必须当前可见且按“类型、值”严格升序，同一属性类型不得出现两项；两个关系组继续按 S2 规则核对。`L2场景S2事实完整` 保留为调用最终完整性的兼容包装，不再强制固定属性为空。

`固定属性写入结果::成功` 仅接受 `已提交 / 精确重复`、非零且相等的事实截止 / 变更代次和一个无退出的当前属性；可选旧属性若存在，其值编码必须不同且退出代次等于变更代次。函数级成功形状再收紧为：`新增场景固定属性` 的 `已退出属性` 必须为空，`换代场景固定属性` 的 `已退出属性` 必须存在；两条路径都要逐字段核对请求场景、请求属性类型、新值及可选旧值的所属 / 类型、材料、来源和生命周期。非成功两载荷必须为空。

`场景退出结果::成功` 仅接受 `已提交 / 精确重复`、非零且相等的事实截止 / 变更代次、一个退出代次等于变更代次的完整已退出场景；场景内每个固定属性、直接子关系和成员关系的退出代次都等于变更代次；可选父关系若存在也同代次退出并且子场景等于 `已退出场景.身份`。这里的退出载荷完整性由 `场景退出结果::成功` 独立检查：字段、端点和稳定排序规则与完整场景相同，但所有载荷必须是本次退出态；不得调用要求“当前可见”的 `L2场景事实完整` 冒充退出态检查。`退出场景` 的函数级读回还必须核对 `已退出场景.身份 == 请求.场景`，并将请求四组编码与结果场景 / 父关系逐编码互证。非成功两载荷必须为空。

两个属性写入固定使用与 S2 一致的“代次探测 + 旧期望直提”路径：

```text
纯值请求校验
-> 构造完整不变 L1 写集
-> 读取 L1 当前事实代次
-> 实际代次 != 期望代次：恰一次直提原写集
-> 实际代次 == 期望代次：用同代次一致投影核对场景节点和具名属性槽
-> 恰一次提交原写集
-> 从 L1 新编码映射取得新值编码
-> 以首次写入代次读取 L1 历史属性值组，并按编码读回可选旧值
-> 形成完整成功结果或内部不一致
```

初始写集精确为：`节点=[]`、`关系=[]`、`值=[{本地键,场景,属性类型,材料,来源}]`、`属性槽变更=[{场景,属性类型,本地键}]`、`退出事实=[]`。初始前置必须得到当前普通场景节点，具名属性项必须为 `属性未设置`；已存在当前值返回 `引用冲突`，不暗中执行换代。

换代写集与初始唯一差异是 `退出事实=[旧值稳定编码]`。换代前置必须得到当前普通场景节点、具名属性成功投影且当前值编码精确等于请求旧值；属性槽未设置返回 `属性未设置`，旧值编码不符返回 `引用冲突`。当前值所属、类型、材料、来源、当前槽或生命周期矛盾均返回内部不一致。

新材料只做 L2 形状校验和 L2 -> L1 强类型变体转换；属性类型节点表示、材料匹配、来源节点和独立材料节点当前性继续由 L1 写前结构校验裁决；L2 不解释业务值域、单位或来源资格。

## 6. 场景退出显式闭包与 L1 引用保护

场景退出使用同一旧期望直提边界。进入同代次前置时，以两次 L1 一致当前投影形成私有 `场景退出快照`：

```text
场景完整当前事实
+ 可选唯一当前直接父子关系
```

第一次投影只读场景节点以发现属性槽类型。第二次投影在同一期望代次重读场景节点，请求全部具名属性值、父子 / 成员两个源关系组和父子目标关系组。目标组最多一项，必须是“父场景 -> 当前场景”的登记父子关系；多项是现存结构内部不一致。所有场景端点骨架允许有属性槽，但只有目标场景的属性值进入完整输出。

将快照实际编码投影为四个排序清单：可选父关系、直接子关系编码升序组、直接成员关系编码升序组、固定属性值编码升序组。任一清单与请求不逐字段相等，返回 L2 `引用冲突`和空载荷，不提交写集。

闭包相等后形成唯一 L1 写集：节点 / 关系 / 值 / 槽变更全空，`退出事实` 为场景节点、可选父关系、全部直接子关系、全部直接成员关系和全部固定属性值编码的全局升序唯一合并。请求闭包不允许带入其它事实。

L1 对最终写集再做一次业务中性当前引用闭包裁决。若目标场景还被本 S3 不拥有的关系、值来源或独立材料引用，L1 返回 `引用冲突=10`，S3 返回 `L2结构状态::引用冲突`。S3 不根据业务名称查找、退出或报告这些外部事实；外部所有者须先使它们退出，再以新期望代次和新幂等身份提交场景退出。

写入成功 / 精确重复必须得到空新编码映射、首次事实代次和正确发布 / 重试边界。随后按请求显式编码从 `读取中性历史事实` 读回场景节点、父子 / 成员关系和属性值，核对类型、端点、属性、材料、来源和全部退出代次。结果中 `已退出场景` 按 S3 稳定排序包含已退出固定属性、直接子关系和成员关系；可选父关系单独返回。任一缺项、多项、角色矛盾或生命周期矛盾返回内部不一致，不降级为引用冲突或成功。

## 7. 当前 / 历史完整场景与 S1 兼容读取

### 7.1 当前完整场景

修改 `读取当前完整场景`，使用第 2.2 节固定的两次一致投影：

1. 第一次只请求目标场景节点，必须为当前普通节点；其 `当前属性` 槽组必须类型编码严格升序、槽值编码非零且无重复；
2. 第二次在同一期望代次重读节点，`属性值` 选择组与第一次槽组逐项对应，同时请求登记父子 / 成员两个源关系组；
3. 第二次节点槽组必须与第一次逐字段相等；每个属性值项必须成功，回显目标场景 / 属性类型，槽与值编码相等，值事实的所属 / 类型一致、当前且生命周期完整；
4. 将每个 L1 值事实转换为 `L2属性事实`，只从权威值取得类型、值编码、材料、来源和生命周期；不从请求或槽补材料 / 来源；
5. 父子 / 成员组继续按 S2 核对端点、关系类型、存在公开读取和排序；有属性的子场景节点只核对身份 / 生命周期 / 普通节点形状，其属性不进入目标场景结果。

当前组合不循环重试、不 sleep。第一次或第二次漂移均返回实际代次和空载荷；一致投影或属性投影缺项、复义、混代、错所属 / 类型、错槽或排序矛盾均内部不一致和空载荷。

### 7.2 历史完整场景

在现有“前代次 -> 场景历史节点 -> 两历史关系组 -> 端点历史节点 -> 后代次”夹取内加入：

```cpp
L1.读取中性历史属性值组({
    L1中性CRUD合同版本,
    请求.场景.值,
    请求.历史截止事实代次
});
```

属性组必须回显所属场景和历史截止，`读取事实代次` 必须等于请求期望当前代次。每个值必须真实所属目标场景，在历史截止的半开区间有效，同一属性类型最多一项。转换为 L2 投影时，晚于历史截止的退出代次清空，不把未来退出暴露到旧截止。

场景历史节点的 `当前属性` 只是该节点被读取时 / 退出时保存的槽快照，不能补历史截止。历史组合只使用历史属性值组形成 `固定属性`；节点槽仅做普通节点结构完整性校验，不决定旧截止的属性内容。

属性组返回入口拒绝、代次漂移、资源失败或内部不一致时，分别映射同名 L2 状态（其中 L1 历史属性值组无 `许可拒绝`）并清空整个场景；不返回“只有关系、没有属性”的部分结果。

### 7.3 S1 兼容入口与节点骨架

`形成S1场景事实` 仅保留给 `新增场景节点` 的创建后读回；创建时新场景确实没有属性和关系，该结果是创建截止的完整场景。

新增私有“场景节点骨架”只包含强类型身份和生命周期；它接受当前属性槽非空的普通节点，但必须检查槽类型 / 值编码非零、类型升序且值编码无重复。它只供关系端点、完整场景组合和退出快照私有使用，不放入任何公开成功载荷。

`读取场景节点` 保留签名，但实现只构造 `L2场景完整读取请求` 并调用同一公开 `读取完整场景`。当前类别令历史截止为 0；历史类别令历史截止等于请求期望事实代次。它只将完整读取的结果头和完整场景逐字段透传到现有结果 DTO，不改写状态、不降级登记失败、不保留旧私有部分读取。

## 8. 状态映射、幂等、读回与非成功边界

所有与 `L1中性写入状态` 相关的 switch 必须显式覆盖新枚举值：

- `映射场景S2写入状态`：`L1::引用冲突 -> L2::引用冲突`，供 S2 / S3 普通写入共用；
- `映射场景写入状态`：S1 节点新建不含退出，该状态不应到达，若到达则映射内部不一致；
- `映射场景关系类型登记写入状态`：登记只新建节点，该状态不应到达，若到达则映射登记内部不一致。

新增写入的非成功优先级固定为：

```text
纯值非法 -> 入口拒绝
登记未加载 / 登记失败 -> 对应登记映射
既有幂等键 -> L1 精确重复 / 幂等冲突
新幂等键旧期望 -> 事实代次漂移
同期望场景未找到 / 已退出 -> 同名状态
属性前置未设置 / 旧值不符 -> 属性未设置 / 引用冲突
场景退出本结构闭包不符 -> 引用冲突
L1 发布前跨结构引用未闭合 -> 引用冲突
资源异常 -> 资源失败
成功形状 / 索引 / 权威事实矛盾 -> 内部不一致
```

登记定位只为关系读取 / 场景退出和完整场景组合所需；固定属性新增 / 换代不使用关系类型，不得为属性写入强制读登记。场景退出和两个完整读取必须已加载完整登记；兼容 `读取场景节点` 因转入完整读取而具有同一前置。

写入成功与精确重复都必须用 L1 首次结果的事实代次和新编码映射重建首次载荷；不以调用时当前槽或当前场景替换首次结果。属性写入使用历史属性值组的首次截止投影核对新值当时已取得当前槽，并用单事实历史读取核对新 / 旧值生命周期。场景退出按请求清单逐编码历史读回。

非成功结果不携带当前 / 已退出属性、已退出场景或父关系，不伪造变更代次。事实代次漂移可回显安全获得的实际当前代次；引用冲突回显裁决时当前代次。任一公开函数的 `std::bad_alloc` / `std::length_error` 映射资源失败，其它未处理异常映射内部不一致，不新增日志。

## 9. 生产外参数验证

### 9.1 验证项目

`L2场景固定属性与退出参数验证.cpp` 只 import L1 公开服务、L2 存在结构和 L2 场景结构；通过 L1 公开写集建立属性类型、来源、独立材料与跨结构引用夹具，通过 L2 公开入口建立登记、场景、存在和关系，并只以结构化结果和 L1 权威读回断言。不 import 仓库、不访问登记私有定位 / 幂等账 / 索引 / 锁，不解析日志。

入口参数：

```text
--幂等基值 <uint64，默认 5000>
--初始I64 <int64，默认 11>
--换代I64 <int64，默认 22>
--父子顺序 <uint64，默认 10>
--成员顺序 <uint64，默认 20>
```

参数只构造正式强类型请求。验证项目支持 Debug / Release x64、v145、C++20、Unicode 和 `/utf-8`，单独编译现行 L1 合同 / 仓库 / 服务、L2 公共 / 存在 / 场景模块及验证入口；不登记进主工程或 solution。PowerShell 包装把输出 / 中间目录定向到系统临时目录，不在工作区生成构建物。

### 9.2 必过矩阵

1. 建立场景关系类型登记、至少三个场景、一个存在、I64 / U64 组 / 独立材料引用三个属性类型、来源节点和独立材料节点；全部身份非零、代次逐次推进；
2. 为目标场景初始 I64 固定属性：已提交、唯一新值、槽与值同代次；原请求精确重复返回首次载荷且零新发布，同幂等身份改材料幂等冲突；
3. 以新幂等身份对已设置的同类型再执行初始返回引用冲突；对未设置类型执行换代返回属性未设置；以错旧值编码换代返回引用冲突，全部零变化；
4. 为目标场景增加 U64 组与独立材料引用两个不同属性，当前完整场景返回三个完整值，按类型 / 值编码稳定排序；原始材料、来源、创建代次和当前生命周期逐字段正确；
5. 换代 I64 属性：新值、槽切换、旧值退出只推进一个代次；当前完整场景只含新值，换代前历史截止只含旧值，换代截止只含新值，无空洞、无双当前；
6. 在有属性场景上新增 / 替换 / 退出父子与成员关系，S2 端点不因属性槽非空返回内部不一致；关系语义、幂等和排序保持；
7. `读取场景节点(当前)` 与 `读取完整场景(当前)` 对有属性 / 关系目标逐字段相同；两者都不返回空属性部分投影；
8. 为另一场景构造可选直接父关系、至少两条直接子关系、一条成员关系和两个固定属性；生成严格升序的完整退出请求闭包；
9. 对上述退出请求分别漏父关系、一条子关系、一条成员关系、一个属性值，以及多带一个其它事实；每次均返回 L2 引用冲突、空载荷和零代次推进；
10. 以 L1 公开写集另建一条非场景父子 / 成员类型的当前关系，使其目标指向待退出场景；场景闭包与全部本结构事实一致后提交，必须由 L1 返回引用冲突并由 S3 精确映射，不返回内部不一致；
11. 通过 L1 公开写集先退出外部关系，以新期望代次和新幂等身份提交完整场景闭包；场景、父关系、全部子 / 成员关系和固定属性值恰在一个新代次退出，其它场景 / 存在端点仍当前可读；
12. 场景退出成功结果的节点、属性、父关系、子关系和成员关系逐字段与 L1 历史读回一致；原请求精确重复在后继代次仍返回首次载荷且零推进，同幂等身份改闭包幂等冲突；
13. 退出前历史截止仍能完整重建当时属性 / 关系；截止等于退出代次时返回已退出且空场景，当前读取也已退出；
14. 合同错、零幂等 / 场景 / 类型 / 来源 / 旧值、空数组材料、零独立材料引用、未升序 / 重复退出清单均入口拒绝，零变化；
15. 新幂等身份旧期望在属性写入 / 场景退出均返回漂移；原成功请求在旧期望精确重复，同键异义幂等冲突；
16. 先在调用前确定性推进 L1 事实并用旧期望代次调用当前 / 历史完整读取，证明漂移状态与空载荷；再用 `std::barrier` 同起步、固定最大轮数且无 sleep 的公开写入线程并发读取，逐次断言结果只能是同代次完整成功或事实代次漂移空载荷，绝不接受混代 / 部分场景。公开接口不能确定性暂停在两次内部投影之间，因此并发轮次是否实际命中该窗口须记入验证记录；未命中不伪报已覆盖，也不得增加测试钩子、私有访问或生产代码时序后门。

本矩阵不注入私有登记 / 索引破坏、真实分配失败、长时锁公平性、崩溃、恢复或跨进程场景；若有界并发未实际命中两次内部投影 / 历史前后夹取之间的代次推进，该调度窗口也属于未观察边界。这些未覆盖边界必须记入验证记录。
