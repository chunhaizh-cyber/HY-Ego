# LANGUAGE-EXPRESSION-FEATURE-CONCEPT 特征概念归类陈述生成计划

日期：2026-10-15。版本：v0.1。计划身份：`LANGUAGE-EXPRESSION-FEATURE-CONCEPT`。当前状态由[计划索引](计划索引.md)唯一维护。

## 1. 目标和前置

在已发布 S02 基础表达入口上，支持用同一正式知识结构表达“两个特征概念之间的归类陈述”。给定目的=陈述、操作=概念归类、两端各为已登记且属于同一 FT 类型根的特征概念、目标语言和名称选择材料，调用现有入口得到完整 UTF-8 语句、实际规则和词/角色/名称标量对齐。生成器用概念比较结果核验**同根类型约束**，只表达本次主张，不用“左/右为上位”或值域结果判断主张真伪。

正式依据：[详细设计](../规范/详细设计/20261015_LANGUAGE-EXPRESSION-FEATURE-CONCEPT_特征概念归类陈述生成详细设计_v0.1.md)、[2340](../规范/2340_根规范_自然语言知识.md)、[7230](../规范/7230_子规范_语言材料知识与交互字段.md)、[7240](../规范/7240_子规范_自然语言双向转换与组织规则.md)、[7160](../规范/7160_子规范_特征概念形成组织与名称关联.md)、[代码归属规范](../规范/代码文件建立归属与模块命名规范.md)。设计事实基线：已发布 main `60f6fb067600b89c272f83c20f8eaa9e18f2cca0`；S02 代码与专属验证记录已发布，实际项目 Debug|x64 编译链接通过，未运行测试。无未实现上游依赖；执行前仍须 S0 核对当前 HEAD、精确索引 blob、生产调用点、文件/ABI 所有权、index/dirty 和构建资源。

## 2. 切片与接口

唯一代码所有者允许修改 `海中鱼巣/业务/表达.基础语言.h/.cpp`，并新增专属 `验证记录/20261015_LANGUAGE-EXPRESSION-FEATURE-CONCEPT_施工与编译记录_v0.1.md`。公开函数 `生成基础语言表达` 的参数尾部追加 `const 概念_特征类&`；结果 DTO、状态、名称选择和标量对齐保持不变。两个业务文件和新参数的完整签名、概念快照形状、读回顺序、失败映射与验证边界已由详细设计 §2—4 冻结。无新增工程文件或装配变更。现行代码搜索仅命中此函数的声明与定义；若 S0 发现新增生产调用方，须暂停受影响切片，退回计划支撑修订详细设计、计划允许文件白名单与索引精确版本。修订发布并重新 S0 后，执行者才能迁移已确认调用点；不得自行扩大原白名单，也不能保留旧签名转发壳。

禁止改动语言知识 owner、概念/名称/词结构服务、正式规范、初始化文本、世界和 D/T/M、交互通道、工程项目/filters、共享知识库或其它所有者文件。本计划不写概念上下位事实；只把 `比较单特征概念` 用于同 FT 根类型核验与最终复读，不以其上下位关系判真，不创建第二生成入口、缓存或自动名称。

## 3. 施工顺序和失败收口

1. 复用当前候选读取、角色匹配、名称选择、固定词展开和对齐逻辑；确认 S02 知识对特征概念角色的允许类别。把当前“两端非存在概念=能力未支持”扩大为“两端同为存在概念或同为特征概念”两个成功分支；混合类型保留非成功。
2. 读取两个正式特征概念后调用 `比较单特征概念`，仅核验同 FT 根：跨根返回 `输入拒绝`，同根即使仅“具有共同上位”也可继续表达调用方主张；读取技术故障不包装为跨根。业务私有名称快照保存强类型存在/特征概念完整信息，按角色类别读相应正式概念；复用当前 `查询概念名称`→`获取名称关系`→`获取词条`完整链和名称数量规则。名称无/多、额度、错误端点、工程失败不得降格为成功或空文本。
3. 生成后重新核对本次选中知识、相应概念、同根比较结果、完整名称组、关系和词条；漂移及技术故障返回空文本、空绑定、空对齐，保留现行结构化状态。记录新/修改函数及直接调用边的知识变更清单，不写共享用途卡。
4. 统一进行实际项目编译链接并记录实际输入基线与结果。只有用户明确下达当前切片测试指令时，才使用实际项目承载专项测试，不自行运行程序、自检或回归。

无正式特征概念、跨根、缺名称、多名称未选、缺/多规则、额度到限、读取漂移及工程失败的状态按详细设计和现有 DTO 原义处理；绝不因规则可读而补造名称、归类事实或真实输出事件。
