## 1. 目标与完成条件

建立独立、纯值式、零事实写入的任务时序可达性裁决器，机械计算两个需求的两种先后顺序、保证/预计可达性、替代转换合同及无法同时保证时的词典序取舍。

完成必须同时满足：

1. 详细设计第5—9节的 DTO、唯一公开函数、算式、状态和错误映射逐项实现；
2. 使用保证最大耗时形成可承诺结果，预计耗时只形成风险诊断；
3. 可行性和替代方法先于需求取舍；需求取舍固定为安全硬约束、硬/软时间、错过损失、权重；实质并列返回无法裁决；
4. 新提供者无机器事实写入、无锁、无I/O、无线程、无日志、无动作与状态迁移；
5. 根工程和独立专项验证满足第8节；
6. 专属验证记录包含实际命令、结果、未覆盖范围和代码知识变更清单；
7. 只提交并推送本计划切片，异主WIP原地保留且不进入暂存集。

## 2. 正式依据与当前事实

- 用户本轮裁决：C、U、I及H/Y时间窗口不足时属于时序可达性冲突；可行性先于权重；安全硬门、硬/软时间、替代方法、损失、权重依次裁决。
- `AGENTS.md`：用户具名裁决优先；复杂公开 DTO 变更必须先由设计和计划闭合；计划优先选择最早可独立施工叶。
- 3100 v4.1、5170 v2.0：需求仍是一D一目标，权重只提供治理份额；当前持久字段没有时间窗。
- 3200 v3.2、5260 v1.2：任务优先级动态计算且不写回T/Vt/X/A；执行前要核验安全、方法和结果闭包。
- 3300 v3.4、5350 v1.3、5360 v0.7：方法结果时间约束不能自证动作耗时；候选方法必须完整读回并通过条件/保护边界。
- 5090 v2.2、8000 v0.5、8100 v1.17：self决议、manager调度、worker动作分账；值式裁决不能直接执行或改状态。
- 6150 v0.16：安全硬门、时间证据、损失/严重度和动态优先级分账；安全事实不能被普通排序覆盖。
- 当前代码没有语义等价的时序裁决入口；`新_任务类::查找冲突需求()`处理同特征预计方向，不得扩展为时序/保护/调度混合入口。
- 当前无覆盖HEAD的用途卡，执行S0必须直接核对现行源码、工程登记与调用点。

## 4. 函数、DTO与物理合同

唯一公开函数：

```cpp
class 任务时序可达性裁决器 final {
public:
    static 需求时序可达性裁决结果 裁决(
        const 需求时序可达性裁决请求& 请求) noexcept;
};
```

完整公开 DTO、枚举值与字段顺序逐字读取详细设计第5节；执行者不得改名、合并状态、增加默认成功、删除风险状态或把输出改成单布尔值。所有业务标识符使用中文，文件为UTF-8。

所有者与生命周期：

- 输入、输出均为调用期值式材料；调用结束由调用方按值管理；
- 裁决器不保留引用、指针、缓存或第二事实账；
- `稳定编码`只用于定位与等义路线稳定输出，不证明业务类型；
- 本函数不取得需求、任务、方法、世界、安全或调度写入权；
- 无锁、无事务、无撤销、无恢复、无幂等键；同请求依值相等得到同结果。

## 5. 实施步骤

### S0：重新冻结现场

1. 核对`main`、HEAD、`origin/main`、index和dirty；起点漂移时重读本计划涉及的现行头源、工程登记和正式规范。
2. 确认四个生产允许文件及专属记录没有其它所有者WIP；工程文件若被其它活动切片占用，只停止本计划。
3. 读取知识库三入口并搜索同义函数；若出现现行等义能力或公开合同漂移，停止并退回计划支撑。
4. 确认详细设计与计划 blob 精确等于计划索引登记值，计划状态为`可执行`。

### S1：建立公开头

1. 新建`任务时序可达性.领域服务.h`，只包含`<cstdint>、<optional>、<vector>`与`../核心/基础数据集.h`。
2. 按详细设计第5节建立封闭枚举和DTO；默认状态必须是非成功或保守状态。
3. 声明唯一静态函数；不得 inline 实现，不导出可写全局对象。

### S2：实现纯值式算法

1. 私有辅助仅置于 `.cpp` 匿名命名空间；分别承担：枚举/字段校验、checked add、同义合同去重、单腿选择、单需求计算、顺序计算、优先级比较。
2. 对精确重复转换合同去重；同一`方法+起点+终点`异义重复返回输入不合法。
3. 起终点相同时形成内部零耗时腿，不伪造方法身份。
4. 每条必需腿严格按“完全无合同→合同缺失；存在通过候选→使用替代；否则材料不足→安全否决→保护不兼容”的顺序解析；整条路线按详细设计固定的跨腿阻断摘要顺序返回。
5. 分别以保证最大耗时和预计耗时执行详细设计第7节公式，任何加法溢出返回计算不可表示。
6. 路线状态为保证时只写保证满足时刻/余量；状态为仅预计时只写预计满足时刻/余量；其它状态三项全空，且两个字段始终对应请求中的第一/第二需求。
7. 先形成两个顺序的完整评估，再按详细设计第7节选保证路线；两者均保证时第二比较项使用`第二个需求保证满足时刻-当前时刻`，包含等待和保持。没有保证路线时才进入第8节单需求与词典序取舍。
8. `仅预计可达`不得产生`采用顺序`；实质取舍并列不得使用编码打破。
9. `std::bad_alloc`映射材料不足，其它异常映射输入不合法；所有路径零副作用。

### S3：工程登记

1. 在根 `.vcxproj` 现有领域文件组加入精确两项；不改配置、工具集、入口或其它文件顺序语义。
2. 在 `.filters` 分别加入`头文件/源文件`；XML保持UTF-8且可解析。
