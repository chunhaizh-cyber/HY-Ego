## 1. 结论和完成目标

采用“DATA之外的二次特征计算应用 + DATA之外的二次关系概念形成应用 + 既有概念树数据服务扩展”，不增加数据owner、第五本体根、第二概念仓或持久二次实例CRUD。

现有代码不是从零开始：特征服务已经有准确I64读取、来源展开、预算、环检测和高阶复算；真正需要改造的是职责位置、调用期输入、完整来源返回、RC结构承接及实际消费者。

目标完成时应能证明：

1. 无须预先保存一份绑定具体输入的派生根定义，即可合法计算准确I64二次/高阶结果，失败不带成功值，计算零持久写入。
2. 需求、任务等业务所需的方向计算从结构记录面迁到业务应用；方法仍可经结构接口核验它引用的合法派生定义。
3. 唯一概念服务可以完整保存、查重、读取和保护原子/AND关系概念；概念形成应用负责通用性、形成和治理，计算应用负责既有RC求值。
4. 使用同一有序A/B的多维准确结果可以形成或命中RC；同义重复不另建身份，失败不会留下对外成功的半定义。
5. 旧被替换计算入口、声明、实现和消费者同次迁移后退出；保留仍合法的结构定义读写及旧格式历史解释。

不包括：裁决C038、新建持久二次结果实例、所有外设算法、全场穷举、自动找因果、恢复旧普通应用装配、恢复端到端测试、重建L1、重写全部特征/存在概念应用。本方案也不把文档发布当作这些能力已实现。

## 5. 临时计算的实现路径

### 5.1 输入及内存组织

采用请求拥有的有限值式计算图，不给图项分配L1身份。逻辑合同建议以下具名DTO，在设计包中落实为完整C++声明：

| 拟定合同 | 内容来源 |
| --- | --- |
| `二次计算来源` | 三分支联合：准确F；已保存定义+输出角色；本次局部编号+输出角色 |
| `二次计算项` | 局部编号、正式FT/用途、可确定K、有序输入、所需输出角色；规则可读回信息不重复成为F字段 |
| `二次计算请求` | 非零G/H、非空根输出组、有限图项、用途必要上下文和显式预算 |
| `二次计算预算` | 图项、边、基础叶、材料量、深度、结果项；固定计数口径与溢出处理 |
| `二次准确结果` | 结构状态、完整具名I64输出、类型/角色/量化/K/阶次、请求对应及来源闭包 |
| `关系概念求值请求/结果` | 固定RC及A/B绑定；完整适用性、满足/不满足、必要结果与来源，不承载概念写入成功 |

内存可使用连续项数组、局部编号到索引表、带角色的邻接表、访问状态及拓扑序。容器是本次计算缓存，不是第二数据表；同FT不同角色保留不同输入位置，来源去重只共享载荷，不消除角色边。

### 5.2 调用流程

1. 校验请求、非空根组、编号唯一、角色及预算；先确认实际注册和输出能力，不在失败时尝试默认算法。
2. 从根按显式来源展开：准确F经公开接口读取；已保存定义展开完整输入；局部输出定位本次图项。预算在读取/分配前逐步扣除。
3. 检查悬空边、环、重复角色及每条使用路径深度；共享子图可以只算一次，最长路径不能因已缓存而漏检。
4. 按依赖顺序解析值并复算；真实阶次为直接输入最高阶次加一，计数溢出失败。直接输入必须继续可追到合法准确来源。
5. 形成所需具名输出；每项准确I64、FT、单位量化及输出种类完整。任一必需项失败整次无成功载荷，不暴露部分值供下游继续。
6. 复核G并返回完整来源闭包；调用结束释放工作缓存，不发布结果节点、幂等账或长期观察计数。

G/H严格按4151映射：本次RC/FC/EC与当前规则读G，具体来源按H及其显式历史来源读取，已保存K不换义。H<G是当前定义分析历史来源；要复现过去系统判断，必须另外具备当时完整判断合同，不由本入口推定。

### 5.3 多用途接入

目标比较读取实际采用和明确目标，状态比较读取具名旧/新来源，场景比较绑定有序A/B，高阶比较使用真实上游图，关系概念求值读取固定定义。用途在绑定步骤分流，后续复用同一计算核心，不能复制五套派生存储。

A须分别交付并验证两条路径：直接经调用期图计算，不建立派生根定义；业务应用读取合法需求/任务记录中的既有方向定义，再经新计算应用求值。后一条不把结构必需引用改成可选，前一条不借需求创建前置重新强制存根；实际调用方必须按各自目的选择，不能凭一条路径证明另一条已可用。

首段只实现合同已完整的有序I64路线及其高阶组合。坐标按距离/角度具名输出、颜色、形状和后天槽位随后依4182逐用途启用；“所有输出都是I64”不证明所有输入解释和算法已经实现。

## 6. RC结构、形成和求值的实现路径

### 6.1 结构扩展

复用现有概念身份与根，定义联合新增原子关系和非空AND分支。D使用4241专用掩码1/2/4及合法并集，不是节点号，不复用旧算法/关系数值。FC/EC使用共同、A、B角色；D与有效K、输出角色及FC配对。

原生定义引用保护FC/EC、必要K和子RC；类型化值保存定义种类、域掩码及必要非拓扑参数。内容和引用同事务发布且逐项对应，不成为两份能分别更新的权威。缺边、多边、错角色或定义内容不符，完整读回失败。

后续结构合同须具名交付：定义分支标记、参数属性、角色化引用类型、AND成员关系、对应排序/配对规则、确定字节格式、请求/结果及每一状态的载荷谓词。已有类型身份通过初始化交付，不能在构造中写死节点号或自动注册。

### 6.2 形成流程

1. 取得同次成功准确计算及有序来源；判定量必须合法适用于符号域，关系编码不能仅按正负归类。
2. 查找合法FC/EC前置；有依据地通用优先。确实缺失时委托所属概念应用先形成并完整读回，错误和资料不足不当查无。
3. 提取原子D/FC/EC/有效K；多个维度仅在同A/B下组成AND。多人比较拆成对象对，不靠AND改变参与方。
4. 作有界规范化：保留全部共同/单方/子定义约束，展开可证明等价的子AND，确定排序、严格去重。单项AND只有完整语义与子项相同时直接复用；新增EC等限制必须保留。
5. 用完整规范化定义查找；摘要仅召回。区分精确复用、真正同义缺失、冷却/退役命中、漂移和资料不足。
6. 真正缺失才请求唯一owner原子建立完整定义、根归属、必需引用及初始直接边；发布守卫内重检同键，收敛并发同义创建。
7. 完整读回实际身份、定义、引用和根可达关系；名称、后续支持和真实用途另阶段处理，分别保留回执及失败。

局部结果没有稳定身份。形成依据必须来自合法准确F、既有定义/规则及正式证据，不新增“临时结果持久节点”规避C038。定义引用、形成支持、组成和上下位四类边不得混用。

### 6.3 求值与治理

求值由计算应用完成：完整读取固定RC及治理状态，逐项核验适用性，再计算每个必要条件并判域。全部完成后才给满足/不满足；某项不满足不能掩盖另一必需项未完成、缺源或失败。

真实业务采用后，形成/治理应用提交具名用途依据。普通FC的准确F命中入口不能充当RC用途；扫描、计算和同请求重放不增加用途。退出保护定义入边、支持和采用，中间层退出维持合法根可达，不删除世界事实；复用7140治理，不新增另一套生命周期。

派发前失败无写入；派发后未知保留原请求和实际发布信息，沿原owner恢复，不换身份重建。名称后阶段失败报告RC已发布及名称未完成，不虚构跨owner原子回滚。
