# 世界树信息操作与概念自动完善方案

日期：2026-09-13

版本：v0.2

性质：用户目标对应的总体完善方案；作为后续规范、详细设计和代码计划的统一输入。

路线初始扫描基线：`1a4a5e51fbdf94b5af4c1a5a21643522b87a9223`；当前A代码结果基线：`8ed1c1335f5cfba714602f12aca1e3c7fdcd87a6`；后续具名R1独立证据提交：`d0c2b315b516adb401743a3e806b390f18b31412`。

完成目标：自我通过实际生产入口使用世界树类，完成各类信息的增、查、语义修改和受保护删除，并在世界信息建立、修订过程中自动建立或复用相关概念、保存引用和完善有事实依据的概念信息。

本文中的“拟议函数”是能力与逻辑合同名称，不是已经存在的函数，也不是冻结后的 C++ ABI。本文不登记执行队列、不恢复旧 P1，不声明代码能力已经完成。当前未提交旧 P1 文件仅保留现场；本文的源码判断以 `git show HEAD:路径` 为准，不把旧共同出生实现计为新口径能力。

## 1. 总体判断与完成范围

现有 DATA-L2 并非需要全部重写。场景角色、存在组成、准确特征、状态内容与使用绑定、动态来源和因果证据等已有真实实现。主要缺口有五组：

1. 各类添加函数还没有统一闭合“明确挂靠 + 已发布概念引用 + 本类完整结构”；查询、迁移和删除也存在跨 owner 的关系闭包缺口。
2. 概念树存在定义、组织和支持操作，但旧合同仍有依赖已出生世界对象、总根或旧名称关系的限制，不能直接承担“先概念、后世界节点”的完整流程。
3. 世界树当前只实现一部分场景、存在位置及创建移动，缺少特征、状态、动态等完整语义入口和概念前置编排。
4. 普通应用没有装配完整的概念、动态、因果服务及其提供者，也没有向实际自我消费方交付世界树能力的有效入口。
5. 普通启动目前固定停止于“真实自我形成”；只补 DATA-L2 或世界树函数无法达成本方案的最终目标。

完成范围包含场景、存在、特征、状态、动态的世界信息操作，以及独立因果信息的合法访问、证据关联和概念依赖完善。因果链按独立结构处理，不挂为场景子树。概念组织成长也要包含定义查重、上下位关系和真实支持维护，不能仅以“保存一个概念编号”宣称完成。

自我的需求决策、任务筹办执行结算和因果归因算法不在本方案中重做；本方案须交付这些业务可以实际调用的数据能力和生产接线。CRUD 不自动执行现实动作，不因记录动态而改变现实特征，也不因记录先后关系而确认因果。

## 2. 固定架构与信息归属

| 层面 | 承担能力 | 本方案固定边界 |
| --- | --- | --- |
| DATA-L1 | 中性节点、关系、值、生命周期及可靠发布读取 | 不识别世界树业务，不判断概念意义 |
| DATA-L2 场景、存在、特征、状态、动态、因果类 | 各自信息与关系的完整数据操作 | 输入必须显式携带本操作需要的挂靠或上下文、已发布相关概念及版本依据；不负责缺概念时创建概念 |
| DATA-L2 概念树类 | 概念定义、查询、组织、引用/支持、生命周期 | 提供概念数据函数；世界事实支持、可选名称、定义和使用引用分别处理 |
| 世界树应用类 | 从受保护的全局根确定范围，编排概念和各数据类 | 不直接访问 DATA-L1 或 owner 写口，不复制领域 CRUD，不保存第二份权威父关系 |
| 自我及其合法业务调用方 | 提供真实操作目标、内容和依据，消费结构化结果 | 不绕过世界树拼装底层世界信息，不用测试入口替代实际业务入口 |

世界树主体由多层场景组成；场景内有存在和特征，存在内可有子存在或特征，特征可有子特征。场景和存在视角切换使用同一对象身份；场景成员、存在组成、直接子场景归属合计保持唯一结构父，不为视角增加第二条父边。普通非根场景必须有明确父场景语境。

状态和动态按其合同组织于场景：状态另有发生场景、被描述存在及状态使用绑定；动态有发生场景、主体及来源。引用关系不等于结构父。场景使用存在概念，不另立场景概念类别；状态使用合法特征概念或规则，不增设一个未经定义的状态概念树。存在、特征、动态概念不恢复独立总根，概念图的真实世界依附与因果链的独立性分别核验。

所有普通操作从唯一全局根确定范围，再把直接父交给 DATA-L2。当前操作核验当前根内位置；历史读取依据请求截止 H 下的根、角色、父链和组织关系，不能因为对象当前已退出或换父而拒绝合法历史，也不能拿当前父替代历史父。只有具名系统引导入口创建唯一世界根；普通添加不得以缺父为由造根。根事实仍由现有世界树根/场景 owner 持有，全局变量只发布经正式读回验证的根引用。

## 4. DATA-L2 相关类的函数完善

### 4.1 共同函数合同

不要求每类照抄相同函数数目。按实际信息结构提供“合法添加、完整读取、语义允许的变更、受保护退出”，组合数据操作留在对应类或既有窄协调器。

拟议添加请求至少表达：明确挂靠的强类型分支、完整内容、已发布概念身份及类别、预期事实代次 G0、原请求身份和预算。普通存在的父场景/父存在二选一，特征的场景/存在/父特征三选一，不能用数个可空参数临场猜分支。缺少应有父节点等调用错误返回结构化拒绝并进入项目统一调试报错；合法未找到、预算不足或并发冲突与程序错误分别处理。

成功读回须包含本体、挂靠关系、概念引用、实际发布截止 H 和读取代次 Gread。概念定义在进入本次 DATA-L2 添加前已经发布；本次原子数据操作只闭合新世界信息、必要关系和对现存概念的合法引用。涉及多个 owner 时复用 DATA-L1 已有多 owner 发布及窄参与合同，不让一个 owner 代写另一 owner，也不把概念定义重新并入出生事务。

读请求明确目标、位置、当前/历史截止及预算；只有完整、同截止且引用闭包成立才返回完整结果。多义、截断、超预算、退出、结果未知不得转译为不存在。写后无法证明结果时按已发布或可能发布返回，保留原请求重读/重放，不报告零变化。

准确值是信息事实；“修改存在现在的某特征值”是采用关系的变化。场景以存在视角描述其宏观特征时也遵守同一规则。

### 4.5 状态类

复用 `创建状态`、`读取当前状态`、`读取状态历史内容`、按正式特征类型/固定准确值/强时间范围查询、`退出状态`、`同步清理实例状态材料`、身份当前/历史核验。

补 `添加并挂靠状态`：世界树提供根内发生场景 C、被描述存在 E、组织父、FT、固定准确值、强时间和合法特征概念/规则。返回 S 内容、C/E/S 使用绑定、组织位置及概念引用。状态内容 owner 保持中性；场景 owner 通过窄参与能力维护绑定与组织，避免状态类反向 import 场景类形成依赖环。

补位置内状态组读取、明确绑定/组织退出以及纠正状态的组合入口。状态固定值和时间不能原地改写；纠正产生新 S，旧历史保留。`读取当前状态`表示该 S 在当前截止有效，不能当成“存在当前真实值”。退出与材料清理分开：先解除本次允许处理的活动引用，再退出；清理仍遵守保留期、数量预算、墓碑与稳定身份。

### 4.6 动态类

复用 `创建原子动态`、`创建组合动态`、当前/历史读取、按主体/绑定/子动态反查、来源展开、退出、清理和身份核验。

补 `添加并挂靠原子动态`、`添加并挂靠组合动态`：接收已发布来源、发生场景、主体、动态组织父及动态概念；闭合来源核验、D 本体、组织与概念引用。补位置内完整查询和受保护退出；来源/主体纠正建立新 D，不修改旧 D，不顺带改变当前特征值。

已有实现对原子变化核验同场景同主体、同 FT、时间递增、前后值不同及 I64 比较；非 I64 和组成存在发生期来源不能用固定成功开放。完整方案需补正式类型比较提供者、组成关系在发生期的历史核验、组合动态逐来源闭包。后续验收逐项声明支持范围，不以“原子/组合函数存在”代替这些分支。

### 4.7 因果类与独立因果链

复用 `发布或复用因果`、当前/历史读取、精确定义/按特征概念查询、`关联因果证据`、`读取因果证据`、`退出因果证据`、`退出因果`及身份核验。因果本身是概念化规律，不能再机械生成一个重复的“因果实例概念”。

补概念 owner 的真实只读 `因果概念核验提供者`，核验各槽概念身份、完整定义、生命周期和相容条件；现有必需总根见证迁移为合法类别、来源/依附和定义见证，不能伪造总根。世界树为因果操作只转换合法世界证据引用；因果组织父或链位置由调用方显式提供。

因果定义纠正发布另一完整定义；证据独立增读退，证据变化不能偷偷重写规律。主动证据须先补真实治理动作来源与历史读取、持续引用保护；非内联值等当前禁止分支须在保护提供者实际完成后开放。因果链节点、连接、角色映射及退出需要具名独立数据合同，不能从普通 CRUD 推导因果成立，也不能强行增加场景父。

类别是已发布概念事实中的不可变类别信息，不是新的类别节点或类型总根，不另有独立生命周期。概念 owner 内要保证“类别 + 规范化完整定义”的唯一性，不能只依赖一个应用对象的互斥锁。不同请求键并发竞争时，发布边界检测同义冲突，竞争方据实际提交截止精确重查并复用；同签名不同完整定义按碰撞处理。已退役同义项按正式生命周期合同返回，不绕过去再造身份或自动复活。

出生引用表示世界信息对应的已发布概念，是 DATA-L2 完整添加不可缺少的关系，与新世界信息和必要挂靠一起发布。事实支持则是在世界事实成立后，基于真实证据另行维护的多对多、可历史化记录。出生引用不证明适用或匹配，支持不能补齐出生引用；完整定义概念可以在两者都为零时独立存在。

这里的“引用函数”是需要完整冻结的关系能力，不预先把现有关系迁到另一个 owner。第一份设计须逐关系登记第 8 节所列物理映射，保留合法既有 owner；需要改变 owner 的部分与提供者、消费者和迁移同批设计，不由世界树直接写概念关系。

进一步形成更一般的概念时，先由应用层按完整定义给出包含证明，再查重并发布/复用上位，刷新截止后调整下位父组。上位已发布而接边失败必须保留上位并返回阶段；不能删除其它合法父来绕过冲突。真实样本发现、独立支持、反例和机械匹配结果分别保留，不能用同一批发现材料宣称独立验证。

自动完善不意味着无边界递归。每次调用指定涉及的信息范围、规则/算法、预算及必要后置条件；必需概念引用未完成时整个世界操作不得成功。额外抽象缺少充分材料时返回未形成及其原因，不杜撰概念，不把普通记录次数升级为可靠性或因果结论。

### 6.1 新增流程

```text
自我提交实际位置目标与完整内容
→ 世界树从唯一全局根读回并形成明确挂靠
→ 核验材料及概念完整定义
→ 概念树精确查询：完整命中复用 / 完整未找到才创建
→ 读回已发布概念；刷新截止并再核验父位置、概念当前性
→ DATA-L2 完整添加：本体 + 必要挂靠 + 已发布概念引用
→ 世界树同截止完整读回
→ 按实际已发布事实维护允许的支持、观察和概念组织
→ 返回真实完成阶段与全部必要证据
```

此图只表示目标逻辑顺序，不是当前代码调用图或已冻结施工图。前置节点不合法时不进入概念写入。概念已成功而世界失败时保留概念；重试精确复用。世界已发布而支持完善失败时，世界添加子结果成功、自动完善子结果非成功，顶层组合不得使用“全部完成”的成功谓词。后续设计须冻结结构化阶段、续行材料和各阶段权威读回；按原请求继续，不再次造节点，不用日志文字代替阶段结果。

### 6.2 查询、修改、删除流程

查询：先根内定位，再按同截止读取本体、必要关系、概念定义/引用和请求范围内子组。历史使用固定历史截止。结果区分完整未找到、已退出、当前有效、多义、预算不足和读取失败；查询不制造概念或增加观察次数。

修改：核验预期旧值/关系，判断修改的是采用、组织、角色、引用还是历史材料纠正。含义改变时先取得新概念；事实不可覆写时建立新事实，再用所属 DATA-L2 合同替换当前关系。调用方与其它使用者共享的旧 F、S、D、概念均保持合法历史；位置移动只有确实改变概念定义材料时才需要重新确定概念。

删除：先读取目标及完整依赖闭包，区分退出单条关系、退出角色、退出世界使用和退出对象本身。有活动子存在、子特征或子场景时默认拒绝；如需保留并删除原父，必须先显式迁移子项到合法新父，可靠发布并读回，不能仅断边留下活动孤立节点。不默认递归删除，不删除共享概念，不释放他方活动证据。允许退出的关系交其 owner 处理；要求原子的归属替换或完整节点退出不能拆成半成功。允许分阶段的清理必须有具名恢复合同，返回已完成阶段。全部条件闭合后独立读回本次指定对象/关系的退出及明确保留的事实。

### 6.3 并发、重复与生命周期

- 概念与世界写入各自具有可恢复的原请求身份，阶段组合可由原请求和正式读回重建，不额外建立一份权威“世界事务进度树”。
- 查询与提交间出现相同概念的并发创建，按完整定义和发布结果重查收敛；不能选择索引第一项或容忍两个等义当前定义长期并列。
- 概念查询截止、概念发布截止、世界写入 G0 和最终读回截止分别记录其含义；创建概念后不得继续使用旧 G0。
- DATA-L2 添加/改引用与概念退出应通过真实引用保护及发布条件协调，避免“校验时存在、提交时已退出”的悬空引用。
- 原键重试不重复节点、支持、命名或观察；发布结果未知时先读回/重放，不能换键重做。
- 预算不足和引用闭包不完整保持非成功。持久恢复尚未实现时只声明进程内恢复；跨进程能力须按第 10 节另行验收。

## 7. 自我实际应用与生产装配

### 7.1 装配完整服务图

沿现有 `海中鱼巣/装配.普通应用.cppcpp` 增补概念、动态、因果及必要窄提供者，保留一组真实 owner 和服务实例。DATA-L1 生命周期长于 DATA-L2，DATA-L2 长于世界树和自我消费对象；上下文负责持有，析构反序。不能为世界树再造一套概念库或世界根，也不把 owner 端口暴露给自我。

当前 `装配.普通应用.ixx` 只导出构造结果，应补冻结后的世界树消费交付合同，交付同一上下文内的有效服务租约或受控引用。此合同须同时带实际自我调用方和生命周期验证进入一个实施切片，不能以“增加 getter”作为服务接线完成。

### 7.2 解决启动依赖与真实自我入口

A已同步8120 v0.15的前置概念结构及普通持久装配，下述原扫描中的顺序冲突已解决，不再作为B未决前置。

初始路线扫描时普通程序在世界装配后固定返回阶段17。A已发布真实自我形成、概念前置出生及普通持久恢复，当前成功后到阶段19方法门。以下保留完整生产目标：

1. 建立/读回唯一世界根后，先完成不造普通概念、不设概念总根的概念服务及结构合同就绪；让自我形成能够合法使用概念前置的世界树添加。
2. 由真实自我形成提供者，经同一世界树建立/复用唯一自我存在及其同节点场景视角，完整读回内部世界、位置和角色。根场景不能冒充自我，不能选取第一个存在当成自我。
3. 普通上下文持有真实自我与世界树能力，实际自我信息处理函数按真实请求调用世界树，并处理各非成功阶段。缺失自我模块时按代码归属规范建立唯一业务实现位置，禁止恢复被退役的旧包装链。
4. 真实形成和读回失败仍返回实际失败；A成功仅推进到现行阶段19方法门。B增加同一self/world实例的真实结构操作入口及合法后继恢复，禁止在初始化运行演示CRUD；方法、本能锚点和线程运行门仍按后续目标完成。

初始扫描时8120把概念结构初始化安排在真实自我形成之后，且旧 I1/I2/A1/R1 名称已经与当前实现不同，必须同步修订。建议将“概念结构服务就绪”前移为世界树普通写入的依赖，将原阶段 18 的真实结构核验纳入同一就绪合同；不为兼容旧成功谓词造总根，也不在初始化中运行 CRUD 负例测试。

自我实际操作入口必须在正式业务运行中可达。若现存完整自我线程启动链仍有提供者缺口，纳入本方案的生产接线依赖并逐项交付；不得以外部测试直接调用世界树替代自我调用，也不得把这个目标扩大解释成已经完成全部自主治理算法。

| C：状态与动态完整操作 | S+绑定+组织、DC 完整定义发布/查询/核验及其直接依赖的 RC 结构与求值、D+来源+组织、概念关联、组织迁移退出、比较和发生期来源提供者 | 先补本批次需要的全部概念提供者，再由自我记录与查询真实前后状态和动态；纠正保留历史，退出不破坏证据，逐值表示/组合分支有覆盖 |
