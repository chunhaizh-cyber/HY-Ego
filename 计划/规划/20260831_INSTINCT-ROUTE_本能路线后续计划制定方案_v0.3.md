## 2. 路线目标

本能路线的目标是形成第一条不依赖高级思维、因果反推、候选世界、自然语言推演或后天学习的确定性生命运行链：

```text
本能根运行锚点
-> 根特征发生真实变化并留下状态 / 动态证据
-> 安全与服务被动维护
-> 双根需求 fresh 自检
-> 根差距展开为具体现实需求
-> 活动需求取得任务承接
-> 任务筹办、执行、正式结果和结算
-> 当前轮次收束
-> 自我形成继续 / 结束 / 等待 / 取消决议
-> 只有“继续”建立新轮次
-> 下一治理轮重新读取当前事实
```

四组本能能力的职责固定为：

| 本能能力组 | 职责 | 是否创建普通任务 |
| --- | --- | ---: |
| 被动维护本能 | 按正式时间、事件、业务事实和规则维护安全值、服务值及维护游标 | 否 |
| 自我治理本能 | 双根自检、根差距展开、活动需求重判和后继决议 | 否 |
| 任务治理本能 | 任务承接、筹办、执行编排、结果读回、结算和轮次收束 | 否；它们治理任务 |
| 现实与外设本能 | 观察、扫描、跟踪、识别、设备检查、控制和使用 | 是；由普通现实需求和任务组织 |

本路线不是把全部生命能力一次性写入代码，而是先形成一条可以在正式事实、结构化结果和独立读回下连续运行的最小确定性链。

## 4. 已冻结事实与纠偏

### 4.1 第一阶段已经覆盖出生锚点

正式第一阶段 `INSTINCT-BOOTSTRAP-ROOT-ANCHOR v0.4` 已经覆盖：

```text
唯一自我
+ 安全 / 服务根特征定义和实例
+ A0 / V0 当前值与初始状态
+ 比较注册和根目标合同
+ 两个长期根需求及列表项
+ 两个值式二次特征概念
+ 值式本能根运行锚点
+ 自我线程创建前锁定
```

后继不得建立第二套根身份、角色关系、持久 owner、查找索引或线程出生材料。

### 4.2 根参数保持固定

```text
M = INT64_MAX
A0 = V0 = M / 2 = 4611686018427387903
安全根目标 = M
服务根目标 = M

L = 2767011611056432742
H = 7378697629483820645
安全根定义版本 = 1
主动安全结算规则版本 = 1
```

未来阈值变化只能通过新的安全根定义版本发布；后继不得在组合器、算法或任务里重算并覆盖当前版本 1 的 L/H。

### 4.3 认知事实、治理事实和工程机制严格分层

```text
【认知事实】
存在 -> 特征 -> 特征当前值 -> 状态 -> 动态 -> 因果

【业务治理事实】
目标、需求、任务、方法、合同、授权、所有权、轮次、结果、结算及结构化结论

【工程正确性材料】
事实代次、G0、CAS、幂等、事务、索引、水位、恢复、预算、集合完整性和线程同步
```

约束：

1. 当前值是“现在是什么”的唯一权威，也是自检和目标比较的唯一输入。
2. 状态和动态用于历史、解释、审计、因果材料和触发重读，不得代替当前值。
3. 不得从“最后一条动态”反推当前值。
4. 工程完整性快照只证明指定 owner 和范围没有漏读、重复、混代次或部分发布，不得持久化为认知节点。
5. 业务治理事实不能压缩进状态 / 动态 / 因果，也不能用 G0、幂等键或成员数量替代业务裁决。
6. 跨服务消费完整有限集合时，低层 provider 应把范围、成员和强类型载荷收束成不可拆分快照；上层只调用公开成功谓词并消费业务结论，不复制完整性算法。

### 4.4 当前任务治理必须去证明化

下列旧事实只允许历史读取、旧格式解码和已有首次账精确重放：

```text
L2任务治理状态事实
L2任务目标裁决证据事实
L2任务重筹办规范化来源材料
执行结果待验证旧治理状态
目标未达成待重筹办旧治理状态
```

它们不得：

```text
首次新建
复义为 current v2
取得 current 任务阶段权威
成为新方法选择来源
成为目标未达成后的自动重筹办入口
```

当前任务主阶段和业务状态必须由任务专属正式存在上的 ARCH-L2 特征实例、当前特征值、状态 / 动态以及任务轮次正式事实表达。

当前首次正式方法选择只允许消费已经存在的：

```text
任务轮次初次筹办来源
-> L2任务初次筹办准备记录身份
```

不得为了“证明已经选择”“证明目标未达成”或“证明可以重筹办”新建同义证据节点。

### 4.5 真实值变化必须保持原子记录

除第一阶段首值、初始状态和零动态特殊入口外，真实值变化必须经统一变化入口，在同一正式提交语义下形成：

```text
旧当前值请求绑定
+ 新值裁决
+ 新当前值选择切换
+ 记录新值的状态
+ 前状态到后状态的动态
+ 正式来源动作 / 方法引用
```

无值变化不得伪造状态或动态。禁止“先发布当前值，状态 / 动态失败后补写”和任何事后猜测修复。

### 4.6 候选结构必须先做复用裁决

本路线中的语义名称不自动等于新 C++ `struct`、新节点类型或新 owner。后继必须先审计：

```text
现有强类型 DTO
现有特征 / 状态 / 动态关系
现有任务轮次事实
现有方法动作事实
现有 L1 / L2 事务能力
现有公开 provider / composer
```

能表达时直接复用；只有现行机器语义确实不能表达时，才在正式规范和详细设计中建立最小新增合同。

普通 `bool` 不得成为需要历史、来源、版本或上下文解释的一阶业务事实；判断结果应由明确值域、复合特征或结构化结果承载。

### 4.7 A、V、L/H 和维护游标分账

```text
A = 安全根当前值
V = 服务值当前值
L / H = 安全根定义或规则材料

维护游标 v3 =
    上一已维护完整秒边界
  + 已消费主动安全变化事实代次
  + 已消费服务维护历史事实代次
  + 运行代次 / 时间纪元 / 时间源版本 / 规则版本
```

不得把 A、V、L、H 和时间 / 事实水位塞入同一个当前值；维护游标不得参加根需求目标比较。

### 4.8 `Gseed` 是兼容覆盖边界，不是认知起点

```text
Gseed = 服务维护历史 v2 覆盖登记首次提交事实代次
Gstart = 本轮排除起始事实代次
G0 = 本轮冻结读取截止
```

固定规则：

1. `Gstart < Gseed` 必须 fail-closed，不追溯猜测。
2. `Gseed` 前形成且已退出的服务历史事实不宣称可恢复。
3. `Gseed` 时仍当前的合同 / 状态、进展和准备由种子承接。
4. `Gseed/Gstart/G0`、成员身份、预算和排序只属于维护工程边界。
5. 后继不得把边界快照原样透传给自我推理、需求比较、因果学习或方法效果统计。
6. 在维护游标完成显式激活前，事实段 composer 不得消费本入口。

### 4.9 任务结果不是可分配资源

```text
正式任务结果
= 某次方法执行、动作后当前值 / 状态 / 动态及归因的事实线索

需求是否满足
= 该需求在自己的裁决时点 fresh 读取目标合同和当前特征值后形成的结论
```

若当前任务由某个上级任务直接调用，则该明确调用关系可以在本轮正式读回后结算。其它可能因同一现实变化受益的需求或上级任务，不抢占、不分配该结果；它们在自己获得使用或执行机会时重新 fresh 裁决。

现实数量、所有权、独占和冲突仍由真实事实 owner 在动作执行前通过授权、安全和原子事务处理。

### 4.10 轮次收束后不自动重筹办

```text
本轮目标未达成
-> 形成任务轮次结构化结论
-> 执行后进入结算 / 停止材料读回
-> 当前轮次收束
-> 交给自我形成继续 / 结束 / 等待 / 取消决议

只有“继续”
-> 建立新轮次
-> fresh 重读
-> 重新筹办
```

旧“目标未达成 -> 新增执行结果待验证状态 -> 迁移待重筹办状态 -> 直接生成下一筹办工作包”不能进入 current 路线。

## 5. 总体依赖路线

```text
阶段一：本能根运行锚点【已发布】
  |
  v
阶段二：真实当前值变化与状态 / 动态原子记录【已发布】
  |
  v
阶段三：安全 / 服务被动维护与三水位游标【当前阶段】
  |
  v
阶段四：两拍读取与双根 fresh 自检
  |
  v
阶段五：双根差距到具体现实需求
  |
  v
阶段六：活动需求选择与任务承接
  |
  v
阶段七：任务筹办、执行、正式结果和按关系结算
  |
  v
阶段八：自我后继决议与连续两轮
  |
  v
阶段九：现实 / 外设本能接入
```

横向治理门禁：

```text
COGNITIVE-EVIDENCE-BOUNDARY
    ├─ 已完成：两个 legacy 写入口停止无账首次生产
    ├─ 未完成：旧生产调用移除 / 替换
    ├─ 未完成：current 正式选择与冻结的真实 ABI 闭合
    ├─ 未完成：执行后 current-value 验证、结算和轮次结论闭合
    └─ 未完成：已有 legacy 持久样本恢复矩阵
```

该横向门禁不改变阶段三的 A/V 维护机器语义，也不得被塞进阶段三计划；但阶段六至阶段八不得在旧任务治理状态、旧目标裁决证据或旧自动重筹办路径上继续扩展。

同一依赖链原则上只形成当前最早可执行计划和最多一个合同已冻结的紧邻待激活后继。不得一次性把阶段三至阶段九全部登记到计划索引，也不得用远端下游设计替代当前最早代码缺口。

## 6. 分阶段计划制定方案

### 6.1 阶段一：本能根运行锚点

状态：已发布并退出执行队列。

正式输出：

```text
可恢复的唯一根身份组
+ 首值 / 初态
+ 根目标合同
+ 两个长期根需求
+ 值式本能根运行锚点
+ 自我线程创建前锁定
```

本阶段排除：周期自检、被动维护、具体现实需求、任务、任务结果和结算。

后继必须消费已发布 ABI，不得重造出生材料。

### 6.2 阶段二：真实当前值变化与状态 / 动态原子记录

状态：已发布并退出执行队列。

已形成：

```text
发布特征当前值变化与中性记录_v1
读取特征当前值变化记录_v1
特征 / 状态 / 动态三 owner 的 L1 v2 原子发布
永久变化账和事实代次完整读回
```

本阶段固定边界：

```text
无值变化 -> 不造状态 / 动态
真实变化 -> 当前选择、新状态和动态同一提交语义
状态 / 动态 -> 记录和证据
当前值 -> 唯一比较权威
```

后继不得建立第二当前值 owner，也不得用动态后值替代 current provider。

### 6.3 阶段三：安全 / 服务被动维护

状态：进行中；基础 provider、历史输入和纯算法已发布，维护纪元、事实段、完整事务和生产消费尚未闭合。

#### 6.3.1 已发布前置

```text
有限 N 分区中性原子事务
单调完整秒与绝对 UTC 时间证据分账
三水位维护游标 v3
安全根定义、A 当前值与 V 当前值正式读取
生产 L/H 与规则版本 1
单秒规则内核
与待维护秒数无关的批量纯算法
主动安全变化永久账及事实代次完整读取
服务维护历史永久账及范围读取
服务维护历史 Gseed 左边界快照 v2
本能被动维护基础快照 v2（计划身份 V3）
硬否决规则宇宙及既有服务活动 / 时间裁决材料
```

#### 6.3.2 当前最早待设计叶：`Gseed` 激活 / 新维护纪元迁移

目标：在不猜测 `Gseed` 前历史的前提下，把当前维护游标显式切换到服务历史 v2 覆盖范围，使后继事实段 composer 获得合法的服务历史排除起点。

该叶的详细设计必须冻结：

```text
1. 激活请求消费哪个正式 v2 边界读取结果和哪个 v3 游标读回。
2. 新维护纪元身份由谁生成、怎样幂等恢复、何时允许建立。
3. 三个水位分别继承、推进或重置到什么边界；禁止笼统写“全部迁移到 Gseed”。
4. 对 Gseed 前不可恢复服务历史的明确放弃边界和结构化结果。
5. 完整秒水位与新纪元当前边界怎样闭合，避免对不完整旧秒区间执行维护。
6. 未消费主动安全变化怎样处理；不得因服务历史切换静默丢失安全材料。
7. A/V 当前值是否保持不变；本叶原则上不得发布 A/V、状态或动态。
8. 同键精确重复、同键异义、已可能发布、持久恢复和独立读回。
9. 激活前 / 中 / 后 G0 漂移和边界种子变化怎样 fail-closed。
10. 旧 v1/v2/v3 游标、同纪元恢复和新纪元切换各自允许的唯一分支。
```

在上述语义未冻结前，不得把该候选登记为 `可执行`。

#### 6.3.3 紧邻后继：五类服务事实正式秒序映射

`Gseed` 激活合同和最终公开 ABI 冻结后，可以准备一份紧邻的秒序映射设计包。只有直接上游 `Gseed` 代码计划已经登记为 `可执行` 或正在施工、最终 ABI 与所有权已经冻结，且上游结果是唯一剩余门禁时，对应后继代码计划才可登记为 `待激活`；其转为 `可执行` 和实际施工必须等待 `Gseed` 激活代码结果正式发布。设计对象为：

```text
合同
合同状态
到期未满足事件
服务进展
服务准备
```

到下列时间语义的唯一映射：

```text
生效完整秒
+ 同秒阶段
+ 正式发布序
```

必须回答：

- 业务发生时间、形成事实代次、UTC 时间和单调完整秒分别承担什么职责；
- 同一秒多个事件如何确定唯一顺序；
- 只有形成代次、没有合法业务发生时间时怎样停止；
- 到期事件为何只属于区间变化、不进入左边界当前组；
- 合同 / 状态、进展和准备的前驱 / 后继怎样映射为有限事实段；
- 不得用容器顺序、消息到达次序、线程 Tick 或等待超时冒充正式秒序。

#### 6.3.4 后继：同 G0 有限事实段 composer

事实段 composer 必须消费：

```text
同一 G0 的维护基础快照
+ 主动安全变化完整范围
+ 服务维护历史边界完整快照
+ 正式秒序映射合同
+ 硬否决 / 活动 / 数值来源正式材料
```

输出只允许是有限、规范有序、可由纯算法消费的业务事实段；不得把 G0、成员身份组、预算、索引或完整性算法透传到认知层。

#### 6.3.5 后继：批量候选与完整维护原子事务

批量纯算法已经发布，后继不得再次设计第二内核。它只负责：

```text
有限事实段
-> 调用已发布批量算法
-> 形成 A/V 候选和目标三水位
-> 无值变化分流
-> 在有限 N 分区事务内发布必要的 A/V 当前值选择、状态 / 动态和游标推进
-> 独立读回并互证
```

事务必须保证：

```text
A 变化、V 变化、主动安全水位、服务历史水位、完整秒水位
要么按合同共同成功
要么不把部分发布包装成成功
```

A/V 任一无变化时，不得为了凑齐事务伪造状态或动态；仍需明确游标是否可推进以及如何由同一事务证明输入已消费。

#### 6.3.6 阶段三完成门禁

阶段三只有在以下全部成立后才能声明完成：

```text
Gseed 激活 / 新纪元迁移已发布并恢复可读
+ 五类事实正式秒序唯一
+ 同 G0 有限事实段已形成
+ 已发布批量算法被真实 composer 消费
+ A/V 与三水位原子事务完成
+ 普通应用或正式维护消费者接线
+ Debug / Release 专项与外部 consumer
+ 进程重启后的水位、A/V、状态 / 动态精确读回
+ 无新秒、无值变化、长跨度、资源失败和已可能发布矩阵
```

明确排除：需求自检、具体现实需求、普通任务、把 L/H 写入 A、把水位写入 V、用线程循环次数冒充完整秒。

### 6.4 阶段四：两拍读取与双根 fresh 自检

目标：每轮自我治理先完成阶段三维护，再冻结新的共同截止，并分别复用现有需求当前满足裁决读取 A、V 当前值，与两个根目标合同比较。

固定时序：

```text
冻结 Gpre
-> 读取并闭合维护输入
-> 执行阶段三正式维护
-> 独立读回维护结果
-> 冻结 Gpost
-> 按 Gpost 读取本能根锚点和当前值
-> 裁决安全根需求当前满足
-> 裁决服务根需求当前满足
-> 形成两个独立结构化结果
```

禁止：

```text
用 Gpre 读取维护后的值
用动态后值代替当前值
为双根另造比较器
把维护完整性字段透传给自我判断
在本阶段创建具体需求
```

激活门禁：阶段三完整发布；Gpre/Gpost 来源、漂移处理、双根独立结果和正式读取分工已冻结。

### 6.5 阶段五：双根差距到具体现实需求

目标：根需求出现正式正差距时，由正式规范裁决其在当前事实下应进入哪一类具体现实需求候选，再经统一需求入口建立或精确复用正式需求。

本路线输入只冻结以下共同边界：

```text
安全根满足
-> 不生成安全子需求，根需求继续存在

服务根满足
-> 不生成服务子需求，根需求继续存在

根存在正差距
-> 进入对应根的候选分流裁决
-> 正差距本身不足以虚构场景、风险、合同、服务对象、授权或完成性事实
```

安全根候选分流仍是正式设计缺口。阶段五规范与详细设计至少需要裁决：

```text
根目标合同、A 当前值、比较关系和已冻结安全规则是否构成首版最小输入；
当前风险、事件、观察材料或直接因果证据分别在哪些候选类型中必需；
在正式规范完成裁决前，不得预设“正式安全因果 / 风险材料”是所有安全候选的通用前置；它们是否构成特定候选的必要材料，由阶段五正式规范裁决；
材料不足时形成何种缺口、观察候选、准备候选或停止结果。
```

服务根候选分流同样未取得正式机器语义。阶段五规范与详细设计至少需要裁决：

```text
没有有效人类触发或合同来源时，是否以及如何形成监听、机会检查、能力校准或服务准备候选；
存在有效人类触发或合同来源时，怎样进入合同绑定的服务候选分支；
任何分支都不得虚构人类合同、服务对象、授权、需求已被承接或服务已完成；
不同候选类型的来源材料、目标合同、幂等身份、去重和准入边界。
```

上述内容只是待正式规范裁决的候选分流，不是当前机器合同。禁止直接调用 L2 CRUD 冒充需求准入，禁止从根值数值机械生成任意现实目标，禁止顺带创建任务。

激活门禁：安全与服务两类候选的类型宇宙、最小来源、材料不足、合同 / 非合同分流、统一准入、幂等、冲突和独立读回已由正式规范与详细设计唯一冻结。

### 6.6 阶段六：活动需求选择与任务承接

目标：从正式活动具体需求形成当前处理对象，并通过统一任务承接入口建立或复用任务、轮次和必要关系。

当前已知设计缺口是：同一共同截止存在 `N>1` 个合法活动具体需求时，尚无正式唯一选择、排队、并行承接或其它分流规则。路线文件不得替代阶段六规范提前冻结最终行为。

在正式选择规则形成前，可以把下列方案作为第一版 fail-closed 候选：

```text
活动需求 fresh 重判
-> 0 / 1 / N 结构化裁决
-> 0：形成无活动需求结果
-> 1：对唯一需求建立或复用任务、轮次与 T->D 关系
-> N：形成“选择规则缺失 / 多项未裁决”结果，不按创建时间、消息顺序、稳定编码或容器位置任选
```

候选方案中的“N 分支是否整体停止、是否暂不建立任务”尚未取得正式资格；最终可以是结构化停止、正式排队、受规则约束的单选、并行承接或其它合法行为，必须由阶段六正式规范和详细设计裁决。任何实施计划在该裁决前都不得把候选写成现行机器合同。

阶段六最终必须形成：

```text
活动需求集合的同截止完整读取
+ 0 / 1 / N 的正式分流规则
+ 被选需求或被承接需求集合的权威身份
+ 任务、首轮次和 T->D 关系
+ 幂等、冲突、漂移、恢复和独立读回
```

认知证据横向门禁：任务 current 阶段不得读取旧 `L2任务治理状态事实` 裁决；任务承接和首轮次必须落在 current ARCH-L2 特征 / 状态 / 动态与任务轮次正式事实上。

激活门禁：多活动需求的最终选择 / 排队 / 并行语义、任务承接 owner、幂等、首轮次、关系闭包、历史兼容和失败矩阵均已正式冻结。

### 6.7 阶段七：任务筹办、执行、正式结果和按关系结算

目标：让由具体需求承接的任务完成筹办、方法选择、执行前 fresh 复核、授权 / 安全、动作执行、正式结果读回、结算和轮次收束。

固定业务顺序：

```text
读取任务、轮次、T->D 和目标合同
-> fresh 判断当前目标是否已满足

已满足：
    零动作
    -> 形成该需求自己的满足核算

未满足：
    读取任务轮次初次筹办准备记录
    -> 正式方法选择和冻结
    -> 授权、安全、当前性复核
    -> 动作执行
    -> 正式当前值 / 状态 / 动态 / 任务实际结果读回
    -> 当前值目标裁决
    -> 按明确上级调用关系结算直接调用者
    -> 形成任务轮次结论

全部本轮必结项有结构化结果
-> 当前任务轮次收束
```

必须冻结：

1. 当前首次方法选择只能由任务轮次初次筹办准备记录提供来源。
2. 不新建目标裁决证据节点、稳定证明节点或 current 私有治理状态。
3. 正式实际结果形成后进入 current-value 验证、结算和轮次结论，不进入旧“执行结果待验证”状态迁移。
4. 目标未达成只形成轮次结论，不调用旧“待重筹办迁移”生产路径。
5. 旧两个 legacy ABI 只为历史已有账精确重放保留；current 生产调用必须移除或替换。
6. 其它相关需求 / 上级任务延后到自己的使用时点 fresh 结算。
7. 价值、预算、奖励、服务贡献和归因防重复必须按明确关系与结算身份冻结。

禁止：结果容量、结果争用、一次性结算所有可能相关需求、旧结果缓存替代当前值、manager 直接打开下一筹办轮次。

### 6.8 阶段八：自我后继决议与连续两轮

目标：消费已收束任务轮次和明确结算结果，由自我形成继续、结束、等待或取消决议，并证明至少连续两轮不会绕过 fresh 读取。

```text
轮次收束
-> self 独立读回任务、轮次、结算和共同截止
-> 继续 / 结束 / 等待 / 取消

继续
-> 建立新轮次
-> 下一轮 fresh 自检 / 筹办
```

## 9. 端到端完成场景

本能路线最终至少需要以下独立运行场景；每项必须通过正式入口、结构化结果、权威终态和独立读回证明。

### 9.1 `Gseed` 激活与重启恢复

```text
当前 v3 游标的服务历史水位早于 Gseed
-> 读取 v2 边界登记与当前 v3 游标
-> 显式建立新维护纪元 / 激活结果
-> 独立读回三个水位和新纪元
-> A/V、状态 / 动态零变化
-> 进程重启
-> 同一激活事实精确恢复
-> 第一条 Gseed 后服务变化可被事实段读取
```

必须证明未消费主动安全材料没有被静默丢弃，且 `Gseed` 前不可恢复服务历史被明确排除而非伪装为空。

### 9.2 纯被动服务值变化

```text
完整秒到达
-> 同 G0 形成有限服务事实段
-> 批量算法形成 V 候选
-> V 当前值真实变化
-> 状态 / 动态和三水位原子形成
-> 服务根自检重新读取 V 当前值
-> 发现服务根正差距
-> 进入阶段五正式候选分流
-> 没有人类合同来源时不得虚构合同、服务对象或合同绑定服务需求
```

该场景当前不预定“无合同即完全不生成候选”。监听、机会检查、能力校准、服务准备、材料不足或其它合法分支，必须以阶段五后续正式规范为准。

### 9.3 服务本能连续两轮

```text
阶段五正式规范确认的有效人类服务触发 / 合同来源 + 服务根差距
-> 进入合同绑定服务候选分流
-> 经统一准入形成具体服务需求和任务
-> 第一轮执行后目标仍未满足
-> 形成轮次结论并完成本轮结算
-> 不写旧目标裁决证据 / 待重筹办状态
-> self 决定继续
-> 建立第二轮并 fresh 重读
-> 第二轮执行后目标满足
-> 正式服务结算改变 V
-> 下一轮服务根自检读取新 V
```

### 9.4 安全本能闭环

```text
安全事件
-> 被动维护使 A 下降
-> 状态 / 动态形成
-> 安全根自检发现差距
-> 按阶段五正式候选分流读取目标合同、当前值、比较关系和该候选所需材料
-> 经统一准入形成具体安全需求和任务
-> 安全动作改变现实
-> 正式安全结算改变 A
-> 下一轮重新读取 A 并比较
```

### 9.5 共享状态、独立结算

```text
任务 A 改变当前状态
-> A 的明确直接调用关系完成结算
-> 相关任务 B 获得执行机会
-> B fresh 读取自己的目标和当前值
-> 已满足则零动作形成 B 自己的结论
-> 不分配 A 的结果
-> 不扣减结果容量
-> 不重复领取价值或贡献
```

### 9.6 旧 proof 入口退役

```text
current 任务执行形成实际结果
-> 当前生产链不调用两个 legacy proof 写入口
-> 无目标裁决证据节点
-> 无旧 task-owner current 治理状态
-> current-value 验证、结算和轮次结论闭合

历史已有账请求
-> 原请求精确重复时只读恢复 / 精确重放
-> 同键异义或历史损坏结构化失败
-> 不取得 current 权威
```

### 9.7 多活动需求选择规则缺口

```text
同一截止存在多个合法活动具体需求
-> 当前没有正式唯一选择 / 排队 / 并行规则
-> 第一版可验证候选：返回“选择规则缺失 / 多项未裁决”
-> 不按容器位置、消息顺序或稳定编码擅自选择
```

是否整体停止、是否暂不建立任务以及后续采用单选、排队还是并行承接，均由阶段六正式规范和详细设计裁决；本场景只验证未冻结规则不能被临场发明。

共同回归范围至少覆盖：

```text
精确重复
同键异义
旧 G 漂移
Gseed 前边界
无值变化不造状态 / 动态
部分材料失败
已可能发布
进程重启恢复
动态缺失不改变当前值比较
执行前目标已满足零动作
目标未达成不自动开下一轮
多活动需求分支按阶段六正式合同执行，正式合同形成前不临场任选
旧 proof 无账首次零写
旧持久样本缺失时明确 NOT_RUN
默认工具链失败不伪装为业务通过
```
