## 1. 拟裁决的具体增量

建议只增加两项 L1 中性只读能力：

1. 对一个已知技术 owner，证明在指定事实代次下没有当前事实、历史事实、物理清理墓碑和既有 owner 写入账。它用于判断首次登记是否可以进入一个未使用的独占范围。
2. 对一个已知当前节点，完整读取仍引用它的关系和值。它用于由上层逐项判断保护引用，不能让不认识的关系类型漏过检查。

两项都不生成事实，不推进代次，不返回写端口，不引入新 owner、概念根、登记仓库、持久字段、持久格式或业务枚举。第二项复用当前反向引用索引；第一项在账未命中时须在预算内核验现有权威表。只检查一个已知 owner 是否为空，不开放全库事实枚举。

另澄清 A 已有的单例角色唯一登记槽：本批登记键固定为 `0x1202`，不能换一个键再登记第二槽。该项不需要新增 L1 能力。

## 3. 提议合同一：单 owner 空域完整读取

### 3.1 物理位置、类型和签名

纯值类型置于既有 `海中鱼巣/核心/L1所有者范围CRUD.数据.h`，由现有合同模块重导出；服务成员置于既有 `服务.L1事实基座.ixx`，仓库实现置于既有 `仓库.L1事实基座.ixx`。不新建文件。

```cpp
inline constexpr std::uint32_t L1所有者范围空域读取合同版本 = 1;

enum class L1所有者范围空域读取状态 : std::uint8_t {
  成功=1, 入口拒绝=2, 未找到=3, 已退出=4,
  事实代次漂移=5, 数量预算不足=6, 资源失败=7,
  内部不一致=8, 范围不支持=9
};
struct L1所有者范围空域读取请求 final {
  std::uint32_t 合同版本=L1所有者范围空域读取合同版本;
  L1结构所有者身份 所有者{};
  std::uint64_t 期望事实代次=0;
  std::uint64_t 最大核验事实数=0;
  friend bool operator==(const L1所有者范围空域读取请求&,
                         const L1所有者范围空域读取请求&)=default;

struct L1所有者范围空域读取结果 final {
  L1所有者范围空域读取状态 状态=L1所有者范围空域读取状态::入口拒绝;
  std::uint32_t 合同版本=L1所有者范围空域读取合同版本;
  L1结构所有者身份 所有者{};
  std::uint64_t 期望事实代次=0;
  std::uint64_t 读取事实代次=0;
  std::optional<bool> 空域{};
  bool 成功(const L1所有者范围空域读取请求&) const noexcept;
  bool 确认空域(const L1所有者范围空域读取请求&) const noexcept;

                         const L1所有者范围空域读取结果&)=default;

// L1事实基座服务的public const成员；没有写端口参数。
L1所有者范围空域读取结果 读取所有者范围空域(
  const L1所有者范围空域读取请求&) const noexcept;
```

`空域=true`严格表示：在本次完整、健康的已发布状态下，该独占 owner 没有 owner 写入账，且无归属于它的当前节点/关系/值、历史事实或清理墓碑。owner 自己的建立事实、建立幂等账和端口签发不算 owner 数据。`空域=false`表示找到了至少一种上述使用证据，不区分业务类型或布局，不返回任何幂等键、事实列表或跨 owner 计数。

`成功(r)`只验证版本1、有效 owner、非零期望G和预算、状态成功、请求头相等、读取G等于期望G、空域载荷存在；`确认空域(r)`还要求载荷为true。谓词是结果内在校验，不能脱离服务证明空域。所有非成功清空载荷；未找到、已退出、范围不支持、预算不足都不是空域成功。

### 3.2 同锁算法与预算

1. 公开服务先拒绝版本、owner、G或预算为零等非法请求。仓库在一次共享锁内读取当前状态；结果回显请求身份和期望G。隔离或结构头不一致返回内部不一致。先检查当前G与请求G相等，漂移时不返回空域结论。
2. 按已知 owner 编码读取当前 owner；仅历史中存在为已退出，均无为未找到。当前 owner 身份和生命周期必须完整。旧共享范围返回范围不支持；本口只支持独占结构范围。禁止从旧共享中性账推算独占空域。
3. 查询该 owner 的既有 `所有者范围幂等账`：存在非空内账即成功且空域false；空内账属于不一致，不当作未使用。不返回键，不递归检查其它 owner 账，不以账缺失直接成功。
4. 账未命中时，必须覆盖当前节点、当前关系、当前值、历史和物理清理墓碑五张既有权威表。先用逐项减剩余预算的方式检查五表条目数之和不超过`最大核验事实数`，防止U64加法溢出。超预算立即返回数量预算不足，零载荷；不能返回“扫描到目前没有”。
5. 在预算内逐项核验：当前三表和历史事实以`写入所有者`比较；墓碑以`内部结构分区`比较。命中本 owner 后核验该证据身份、种类和生命周期与所在表相容，完整则成功false，损坏则内部不一致。所有表遍历完成且均未命中才成功true。无须复制表、排序全库或输出其它 owner 数据。
6. 共享锁释放前形成结果；整个读取零写、零代次变化。分配失败和长度失败映射资源失败，其它异常映射内部不一致。服务不留空域缓存；后续登记仍由同一个G作为写集并发守卫。

该算法有明确成本：常见已使用 owner 可O(1)拒绝；首次未使用 owner 的完整证明最多检查预算内的现有事实条目。需在4015和4080精确允许这个“对已知单 owner 的有界空域谓词”内部遍历。该例外不开放任意条件查询、跨 owner 枚举、无预算扫描、二级持久索引或业务类型判断。若后续要改用派生 owner 索引，须另经合同内性能维护证明完整性；本草案不引入该索引。

### 3.3 概念登记的合法消费

提议在 A 的`纯概念结构登记请求_v2`末尾增加`std::uint64_t 最大空域核验事实数=0;`，作为本次限额，零值入口拒绝；版本轴仍为尚未完成实施的纯布局v2。普通装配显式填入`1048576`。该数只限制本次核验成本，不是布局身份、不写入任何节点或幂等材料，也不以其推断世界规模。原请求回显中的限额来自本次请求；同键重放不能声称从首次账恢复了该预算。

登记顺序固定：

1. 校验本次请求和port同底座；先按本次登记键读取owner首次材料。
2. 原键有完整首次材料：按 A v0.3 已定物理布局、原G0、映射和正式读回恢复；不要求owner现在为空。更换原G0/写集是幂等冲突；增加本次核验限额不改变首次布局身份。
3. 原键确认未找到：以`G0`调用本节新读口。false或范围不支持映射为纯概念旧格式不支持；true才允许形成原有登记写集。空域读与正式提交之间若有其它写入，全局G0守卫使本请求漂移，不能刷新G后沿用旧空域结果。
4. 空域读取的入口拒绝、漂移、预算、资源和内部不一致按同名纯概念状态返回；owner未找到/已退出映射内部不一致，因为装配port应绑定一个活动独占owner。此阶段确认未发布，清空交付。
5. 之后仍用既有owner提交和首次材料正式读回，不改布局写集。发布未知时保留原键/G0，不重新新建owner或换登记键。

异键已存在v2布局仍返回旧格式不支持，不把“形状相同”当另一键的精确重放；后续真需要跨键发现布局，应另有明确合同。本方案只承诺防止在既有域重复登记。

## 4. 提议合同二：已知节点当前全引用读取

### 4.1 物理位置、类型和签名

与第3节共用三个既有L1文件，不增加独立模块。

```cpp
inline constexpr std::uint32_t L1节点当前引用读取合同版本 = 1;
enum class L1节点当前引用读取状态 : std::uint8_t {
  成功=1, 入口拒绝=2, 未找到=3, 已退出=4,
  事实代次漂移=5, 数量预算不足=6,
  资源失败=7, 内部不一致=8
};
using L1节点当前引用事实 = std::variant<
  L1所有者范围关系事实, L1所有者范围值事实>;
struct L1节点当前引用读取请求 final {
  std::uint32_t 合同版本=L1节点当前引用读取合同版本;
  稳定编码 节点{};
  std::uint64_t 期望事实代次=0;
  std::uint64_t 最大数量=0;
  friend bool operator==(const L1节点当前引用读取请求&,
                         const L1节点当前引用读取请求&)=default;
};
struct L1节点当前引用读取结果 final {
  L1节点当前引用读取状态 状态=L1节点当前引用读取状态::入口拒绝;
  std::uint32_t 合同版本=L1节点当前引用读取合同版本;
  稳定编码 节点{};
  std::uint64_t 期望事实代次=0;
  std::uint64_t 读取事实代次=0;
  std::vector<L1节点当前引用事实> 引用{};
  bool 成功(const L1节点当前引用读取请求&) const noexcept;
  friend bool operator==(const L1节点当前引用读取结果&,
                         const L1节点当前引用读取结果&)=default;

// L1事实基座服务的public const成员。
L1节点当前引用读取结果 读取节点全部当前引用(
  const L1节点当前引用读取请求&) const noexcept;
```

本口按已知节点读取，与端点定向关系组一样允许返回不同owner的真实引用；返回每项事实原有`写入所有者`，不重标owner。关系端点/关系类型、值所属/属性类型/来源/独立材料引用均算引用。一个事实同时在多个位置引用同节点，只返回一次。结果按事实稳定编码严格递增，零项可以成功；节点本身不是引用项。接口没有任意owner筛选、关系类型筛选或忽略集合，避免L1替上层漏掉引用。

### 4.2 完整性、同锁与失败

1. 校验版本1、节点、期望G和最大数量非零。共享锁内先确认健康状态和G相等，再确认目标是当前节点；只有历史或节点墓碑为已退出，完全不存在为未找到；编码实际为关系/值则入口拒绝，不能把非节点解释成空引用。
2. 在同锁内按已知节点查`当前节点引用索引`。无候选即成功空组；存在空候选或非递增/重复/零编码为内部不一致。候选总数超过最大数量时数量预算不足，清空组；不能截断为成功。
3. 逐候选查权威`当前关系/当前值`，必须恰好命中一个表，身份、创建代次、未退出状态及节点真实引用位置均相符；复用现有`检查当前节点引用闭包`的七位置判定。每项转换成既有owner-aware纯值事实。索引是派生候选，不能只把索引编码作为事实返回。
4. 全部候选验证后才成功。内部错误、版本/身份错误、漂移、数量预算、资源异常均清空整个引用组，不返回可被误用的部分完整结果。不得提交空写集或试退出节点来获取引用裁决。

`成功(r)`要求版本/请求头相同、G相同、状态成功、非零预算且组大小不超限；逐项验证编码非零递增、owner有效、创建G在`(0,G]`且未退出、至少一个真实引用位置相符。它不能独自证明枚举没有遗漏；完整性由服务同锁索引维护、恢复重建和权威读回保证。此口仅支持当前读，不增加历史全引用语义。

### 4.3 概念退役与退出消费规则

L1只返回事实。准许哪些引用由概念owner根据 A 纯v2完整布局和已有生命周期规则解释。不能在L1增加“支持、来源、名称、退役”分支。

新进入退役或退出前，在共同G0完整读回目标概念C及其定义记录D，再分别调用本口。每次`最大数量`取本次概念预算`最大关系数+最大特征属性数`，溢出或任一必需预算为零均入口拒绝；两节点共返回的关系总数和实际值总数还须分别不超上述两种预算，超限全部失败。重复出现在C/D两次结果中的同一事实按编码去重，材料必须完全相同；不能重复扣成两项机器事实。
