## 1. 当前结论

`c1cba465d` 已经发布安全根、服务根所需的通用 EC、双目标判断 K、双 `D_POS` RC 的生产初始化、稳定定位、共同截止读回及普通应用值式交付。旧计划 `INSTINCT-ROOT-RC-PRODUCTION-INIT` 已完成，应从执行索引和当前计划目录退出。该结果没有实现 RC 求值、G4-A 双根复核、根治理意图 sink 或治理门开放。

G4-A 当前最早阻断已经收敛到 4242 求值合同：现行 4242 既要求求值器跨 E/B/S/F/K/概念 provider 建立统一的节点、关系、值和总材料精确计量，又调用多个没有共同读取会话 ABI 的既有公开入口。现有代码和公开 DTO 不能在不新增合同的情况下证明这份跨服务总账精确成立。

此前只读讨论形成了“取消求值阶段跨服务统一物理总账、保留各 provider 局部有界读取”的候选修订方向，但用户尚未确认，4242 与其直接转引也尚未修订。因此该方向当前只是待审输入，不是机器事实、正式规范或实施许可。

## 3. 现行正式合同与接口缺口

### 3.1 现行 4242 仍要求跨服务统一总账

4242 第3节当前把 `二次关系预算/二次关系读取用量` 的物理四项解释为一次读取会话内按 `owner身份 + 事实种类 + 稳定编码 + Gread/H` 去重的精确用量；第7节又要求把固定 K、当前 K 及来源读取的物理用量逐项合入同一求值结果。

### 3.2 求值链没有共同读取会话 ABI

4242 第7节实际转调的公开入口包括准确 F、当前采用、存在身份历史见证、状态使用绑定历史、状态历史内容、固定 K、当前 K 以及 FC/EC/RC 概念读取。当前只有以下局部计量能够被各自 owner 精确证明：

- 准确 F provider 自己的有界读取与真实用量；
- 固定 K、当前 K 各自独立公开调用的四维预算与真实用量；
- FC/EC 及其嵌套值域读取在概念 owner 内部共享的单次调用会话；
- RC 结构 owner 自身的结构、图、治理和规范化读取用量。

E/B/S 等既有公开入口没有接受求值器共同读取会话的合同；独立结果也没有暴露足以让上层按事实键跨 provider 去重的完整材料。因此上层不能在下一次物理读取前判断统一剩余量，也不能把各 provider 汇总数相加后声称完成精确去重。

### 3.3 当前不存在可迁移的求值器实现

现行生产代码尚无 4242 第7节的 `二次关系求值应用服务`、`二次关系求值请求`、`二次关系判断状态/结果`实现。已有 `合同.二次关系概念`、概念 owner、K provider、特征值域 provider 和 E/B/S/F 入口分别服务结构与局部读取，不应因本阻断先行修改。

## 4. 待用户确认的候选修订

候选方向只删除“求值应用跨多个 provider 汇总一份精确物理总账”的要求，不删除任何 owner 已经能够证明的局部合同：

1. 保留 `二次关系预算` 和 `二次关系读取用量` 现有字段与 DTO 形状，继续服务 RC 结构、规范化、图、治理及概念 owner 的局部读取。
2. 保留概念数、原子数、展开深度、候选数、来源数、用途数等求值层语义工作预算；所有必要项仍须完成，不得因已有不命中而短路。
3. 保留准确 F、K、FC/EC/4180 以及其它 provider 各自已经公开的有界读取、真实用量和预算不足状态；求值器只校验每个子调用自己的合同，不跨服务相加或伪造去重。
4. 任一下层 provider 返回预算不足时，求值结果映射为独立的 `二次关系判断状态::预算不足`，不得降格为不命中、证据不足或空来源成功。
5. 求值结果中的语义工作用量继续准确报告；节点/关系/值/总材料四项只允许报告单一 owner 会话能够精确证明的用量，否则为零。不得把多个 provider 的局部用量相加成含义不明的“部分总账”。
6. 若用户确认该方向，最小正式同步范围是 4242 的预算通则及第7节求值计量文字、修订记录，以及 7191 对“4242用量按其返回扣减”的直接转引。4015、4180、4182 的单 owner / 单 provider 局部预算合同保持不变。

上述六项在正式规范完成审查、批准和发布前全部属于候选，不得写入代码计划的冻结合同。

## 5. 若不采用候选修订

若现行跨服务精确总账保持不变，则必须先设计并正式冻结一份跨服务共享读取会话 ABI，使所有相关 provider 在同一事实键空间内于读取前检查剩余预算、复用完整事实并返回可验证增量用量。该路径会新增或改变公开接口、依赖方向和装配合同，不能由执行者临场补造，也不能伪装成局部代码切片。
