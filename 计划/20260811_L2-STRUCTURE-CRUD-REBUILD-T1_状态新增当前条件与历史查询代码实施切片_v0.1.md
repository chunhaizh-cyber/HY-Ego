`建立状态结构类型登记` 用一份 L1 写集建立十个类型节点，关系 / 值 / 槽 / 退出为空。成功 / 精确重复必须取得十个不同非零稳定编码映射并按首次代次历史读回节点种类和表示；服务私有保存只读值式定位。

`读取当前状态结构类型登记` 只按私有定位用一致当前投影读取十节点，允许一次完整漂移重读；未加载返回登记未加载，不扫描全仓、不猜测稳定编码。登记建立必须在状态 CRUD 并发使用前单线程完成；T1 不允许登记写与 CRUD 并发，也不为此新增服务锁。普通操作遇到登记未加载映射为 L2 `入口拒绝`，登记许可 / 漂移 / 资源 / 内部失败映射同名共同状态。

十个节点只标识状态内部结构角色和材料表示，不解释状态真伪、值域或时间单位。

## 7. 新增状态的一份 L1 写集

本地键和角色固定：

```text
状态节点本地键          = 0x0204'1001U
状态主体关系本地键      = 0x0204'1101U
状态特征实例关系本地键  = 0x0204'1102U
状态精确值本地键        = 0x0204'1201U
状态时间值本地键        = 0x0204'1202U
状态端点角色            = 1
```

流程固定为：

```text
纯值校验
-> 读取当前状态结构类型登记
-> 按两份材料选择精确值角色 / 时间值角色的登记类型
-> 构造不可变 L1 写集
-> 探测当前事实代次
-> 实际代次 != 请求期望：恰一次直提原写集，由 L1 裁决重复 / 冲突 / 漂移
-> 同期望：调用完成身份来源迁移后的读取完整存在(当前)与读取完整特征实例(当前)
-> 按最终 provider ABI 核对两端及实例定义端点的同截止、当前性和正式身份来源，且实例宿主等于请求主体
-> 恰一次提交
-> 从首次代次历史节点、关系、属性值和端点重建首次结果
```

唯一写集为：

```text
节点 = [{状态节点本地键, 普通, 无属性类型表示}]
关系 = [
  {状态主体关系本地键, 源=状态节点本地键, 目标=请求主体,
   类型=登记主体关系类型, 角色=1},
  {状态特征实例关系本地键, 源=状态节点本地键, 目标=请求特征实例,
   类型=登记特征实例关系类型, 角色=1}
]
值 = [
  {状态精确值本地键, 所属=状态节点本地键,
   类型=按精确值材料选择的登记类型, 材料=请求精确值材料, 来源=请求来源},
  {状态时间值本地键, 所属=状态节点本地键,
   类型=按时间值材料选择的登记类型, 材料=请求时间值材料, 来源=请求来源}
]
属性槽变更 = [
  {状态节点本地键, 精确值登记类型, 状态精确值本地键},
  {状态节点本地键, 时间值登记类型, 状态时间值本地键}
]
退出事实 = []
```

T1 不要求特征实例 `当前值` 存在，也不比较精确值材料与实例当前值；调用方可以提交与当前特征值不同的状态记录，数据层只保存结构。主体与实例宿主不等返回 `引用冲突`，零提交。未找到 / 已退出 / 许可 / 漂移 / 资源按端点公开读取精确映射；端点载荷、截止或宿主矛盾为内部不一致。

成功 / 精确重复必须取得五个本地键到五个不同非零编码的一一映射，首次事实代次和发布 / 重试边界正确。首次历史读回必须证明普通状态节点、两条同代次关系、两个同代次值、两个属性槽角色、共同来源和两个端点在首次截止有效；不得用调用时当前端点或属性替代首次结果。任一缺项、多项、错类、错端点、错角色、错来源、混代或材料表示不符返回内部不一致，不二次提交。

## 8. 单项当前与历史完整读取

### 8.1 当前读取

先读取当前状态结构类型登记。第一轮 L1 一致当前投影请求目标状态节点和主体 / 特征实例两个具名源关系组；节点必须是当前普通节点，关系组各恰一项、源为状态、类型匹配、角色 1、目标分别形成主体 / 实例身份，两关系当前且同截止。节点当前属性槽必须恰有两项：一项属于精确值四类型，一项属于时间值四类型。

随后以同一期望代次读取存在 / 特征实例公开当前投影并核对宿主，再用第二轮 L1 一致当前投影重读同一节点、两关系组和两项具名属性值。前后节点 / 关系 / 槽逐字段相等；两值所属状态、类型角色、材料表示、来源和生命周期同截止，形成完整状态和两关系编码。

目标状态未找到 / 已退出按同名返回；登记、许可、漂移、端点失败和资源精确收口；多槽、少槽、错类型、错关系、端点复义、来源不一或任一部分载荷均内部不一致。全部失败清空状态和自有关系。

### 8.2 历史读取

历史读取固定为：

```text
读取当前事实代次并等于请求期望
-> 读取状态历史节点
-> 按状态为源读取两种历史关系组(历史截止)
-> 读取状态历史属性值组(历史截止)
-> 以同一历史截止调用存在 / 特征实例公开历史读取
-> 再次读取当前事实代次并等于请求期望
-> 重建截止投影
```

截止有效关系必须分别恰一项，截止有效属性必须恰为一个精确角色和一个时间角色；节点当前槽不得补历史。关系、属性或端点晚于历史截止的未来退出代次在返回投影中清空。状态在截止前未创建返回未找到；截止等于或晚于状态退出代次返回已退出；截止前的完整历史状态返回已读取。

两次当前代次任一变化返回事实代次漂移；历史组入口 / 许可 / 资源失败精确映射；关系、属性、端点、宿主、来源或生命周期矛盾返回内部不一致。历史读取不扫描其它状态、不选择最新时间、不自动形成动态。

## 9. 按主体与按特征实例的当前条件查询

按主体流程固定为：

1. 调用存在公开完整当前读取，确认请求主体在期望代次完整且当前；
2. 读取当前状态结构类型登记；
3. L1 一致当前投影同时请求主体节点和 `目标关系组={主体编码, 状态主体关系类型}`，防止不存在端点被空组误报成功；
4. 每条关系必须目标为请求主体、角色 1、类型匹配、源为当前普通状态节点；
5. 对每个唯一源状态调用 `读取完整状态(当前)`，要求同一期望代次且主体逐字段相等；
6. 按状态身份编码严格升序返回，重复源、关系与单项读回不一致或混代均内部不一致。

按特征实例流程同构：先调用最终特征公开完整当前读取，再请求特征实例节点和对应目标关系组；逐项单读必须返回相同特征实例。两个查询都允许合法空组，不筛选时间、不比较精确值、不返回“最新”状态。

如果任一逐项读取返回许可拒绝、漂移、未找到、已退出、资源或内部不一致，整个组返回对应非成功和空载荷；不得返回部分状态组。所有成功项目的事实截止必须精确等于请求期望代次。

## 10. 状态、幂等、异常和非目标收口

非成功优先级固定为：纯值非法 -> 入口拒绝；登记未加载 -> 入口拒绝；登记其它失败 -> 对应共同状态；既有幂等 -> 精确重复 / 幂等冲突；新键旧期望 -> 漂移；主体 / 实例未找到或已退出 -> 同名；主体与实例宿主不符 -> 引用冲突；许可 / 资源 -> 同名；事实矛盾 -> 内部不一致。

同一幂等身份只绑定完整请求。精确重复返回首次状态、两值、两关系和首次代次，零推进；同键异字段冲突。发布未知只能以原幂等身份和原请求重提；不得换键或重构材料。

T1 不引入新锁、仓库、缓存、索引、序列化、恢复、SQL、材料读取器或第二幂等账；服务不持 L1 / 存在 / 特征内部锁。来源只作为不透明稳定编码由 L1 值事实引用保护，不解释来源类别。

本叶不实现状态引用替换、值换代、状态退出、场景归属、最新状态、状态真实性、采样时间单位、状态自动形成、特征比较、动态生成、因果判断、世界树聚合或生产装配。

## 11. 临时生产外验证矩阵

临时验证 cpp 只 import L1 公开服务、E2 存在服务、激活后的 F3 特征服务和 T1 状态服务。存在、定义、实例、特征值、状态登记和来源夹具全部经正式公开入口建立；不得 import 仓库、访问私有定位 / 锁 / 索引 / 幂等账、解析日志或复用历史状态 / 动态实现。

入口参数固定为：

```text
--幂等基值 <uint64，默认51000>
--精确I64 <int64，默认11>
--时间I64 <int64，默认101>
--时间U64一 <uint64，默认202>
--时间U64二 <uint64，默认303>
```

必过矩阵：

1. 建立状态十类型登记，十编码唯一非零、节点种类和八种表示精确；原请求重复、同键异规则冲突、未加载、错合同 / 规则 / 身份分账；
2. 经 E2 / F1—F3 正式入口建立两个主体、特征定义、一个空值实例和一个有当前值实例；T1 不直造端点；
3. 对空值实例新增状态成功，证明 T1 不要求实例当前值；精确值 I64 与时间值 I64 写入同代次，来源、两槽、两关系、主体 / 宿主一致；
4. 对有当前值实例提交不同于当前特征值的精确材料仍按结构成功，证明不自动复制 / 比较 / 判断状态真实；
5. 原新增请求精确重复返回首次完整载荷且零推进；同幂等身份改主体、实例、精确材料、时间材料或来源均幂等冲突；
6. 主体与实例宿主不符返回引用冲突；不存在 / 已退出主体或实例、零身份 / 来源、空数组、零独立材料、错合同和旧期望新键均精确非成功且零变化；
7. 单项当前读取返回节点、两关系、两值、来源和端点同截止；单项历史在创建截止返回相同创建投影；
8. 再建立状态，分别覆盖精确 / 时间的 I64组、U64组和独立材料引用，使八个角色表示登记全部被真实写入 / 读回；
9. 同一主体与特征实例建立两个不同当前状态合法，按主体与按实例查询均返回稳定升序完整组，不选择时间较大项；
10. 合法无状态主体 / 实例查询返回已读取空组；不存在端点不得误报空成功；
11. 人为经 L1 公开入口推进后，以旧期望执行当前、历史和两条件查询，全部返回漂移和空载荷；
12. `std::barrier` 同起步、固定最大轮数、无 sleep 的状态新增写者与两条件读者并发，只接受完整同截止已读取、许可拒绝或漂移，不接受部分组、混代、重复状态或内部不一致；实际窗口命中如实记录；
13. 经正式公开入口建立空场景、空存在、特征定义 / 实例和状态正常对照组，并经 L1 公开入口建立原始普通节点；把空场景 / 原始普通节点作为存在、空存在 / 原始普通节点作为特征定义或实例，再传入 T1 主体 / 实例入口，全部按最终 provider 合同结构化拒绝、空载荷且权威普通事实零变化，不能误报未找到对象的合法空组；
14. 主工程 Debug / Release x64、双配置临时项目、strict、UTF-8、工程隔离和临时生命周期检查通过。

未覆盖 T2 替换 / 退出、动态、因果、世界树聚合、生产消费者、业务状态真实性、时间排序、长期公平、真实分配失败、故障注入、恢复、跨进程或独立集成验收。
