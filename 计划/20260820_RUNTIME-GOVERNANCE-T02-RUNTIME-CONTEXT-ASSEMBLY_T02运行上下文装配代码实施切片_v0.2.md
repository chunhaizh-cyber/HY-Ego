## 2. 现状与正式依赖

- `启动.应用程序.ixx` 当前阶段 20 局部构造 self-thread，向其传入存在服务并立即开门；必须纳入迁移。
- `创建.自我线程.ixx` 当前 import `装配.普通应用`，内部构造完整秒、事实版本和批次路由，并在线程入口调用 `冻结当前治理批次`；这些调用不能复制到本叶新接线。
- `装配.普通应用.ixx` 当前已有结构服务装配，但不是完整运行上下文 owner。
- 合并后的 `RUNTIME-PROVIDER-ABI-CLOSURE v0.2` 当前承接单调适配器、完整秒、事实截止及现有消费者的单一代码闭环；其结果与 `RUNTIME-GOVERNANCE-CURRENT-BATCH-ASSEMBLY v0.1`、SELF-THREAD 最终结果仍须正式发布、接受和释放后机械匹配。

激活前必须从最新 `main==origin/main` 重做 S0，确认上述依赖的真实模块、DTO、状态、`noexcept`、工程登记和调用方 ABI 无漂移；任一改变所有权、身份来源、生命周期或关闭语义的漂移退回计划支撑。

## 4. 机械施工步骤

1. 新建合同模块，唯一导出 I1/I2 稳定 DTO；普通应用和 self-thread 只 import 合同模块，零复制/转发 owner。
2. 在 `装配.普通应用.ixx` 扩展配置、三个进程内身份序列、生命周期服务、单调适配器、完整秒、事实版本及唯一未启动 self-thread 的成员链；固定构造顺序和反向析构。
3. self-thread 删除反向 import 和 provider `unique_ptr`；只保存最终 SELF ABI 规定的不可空借用/值式配置。邮箱、路由和物理线程的具体顺序以 SELF 正式结果机械匹配。
4. 启动文件删除阶段 20 局部 self-thread、存在服务参数和直接 `开放治理运行门()`；改为调用普通应用上下文的具名创建/停门边界，非成功仍精确映射阶段 20，成功保持门关闭。
5. 同一提交更新工程与 filters 的唯一模块登记，清理旧反向 import/重复 provider 接线；不迁移为第二服务、缓存或兼容别名。
6. 对照最终关闭边界计划，确认本叶不新增首个路由冻结、父循环或开门调用；关闭边界未完成时阻断后继激活。

## 5. 失败、生命周期与结果合同

配置无效、身份耗尽、任一 provider/self-thread 构造失败、资源异常和内部异常均返回结构化 T02 装配/阶段 20 失败，候选为空；已形成的成员按逆序释放。self-thread 先停止/唤醒并 join，之后才析构其借用 provider。不得 detach、伪造成功、用日志或退出码代替结构化结果。

启动阶段 20 的成功仅表示 self-thread 创建并停在关闭治理门（如最终 SELF ABI定义的成功）；不表示治理门开放或治理循环运行。若最终 SELF 请求/结果与本文不同，停止施工并退回支撑，不由执行者临场补 ABI。

执行时至少验证：

- 合同模块唯一 owner、普通应用/线程无环、工程登记唯一；

无法安全注入的真实耗尽、资源故障、关闭竞争、跨进程恢复、治理循环、业务闭环保持 `NOT_RUN`，不得新增生产故障 seam。
