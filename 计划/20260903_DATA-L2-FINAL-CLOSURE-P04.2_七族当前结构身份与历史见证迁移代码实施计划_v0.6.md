## 4. 七族静态白盒审计与闭合的 NOT_RUN

以下不是动态造错义务。它们必须在同一 `archive-source` 的 candidate 源码上完成静态白盒审计：

- 已接受本族身份后的 private owner、族锚点、关系类型、唯一归属关系、端点方向、角色、生命周期和同截止闭包的缺失、重复、错配或混代；
- 强制 `std::bad_alloc`、`std::length_error` 或等价资源耗尽；
- 强制未预期异常、L1 返回形状 / 合同矛盾、provider 路由或装配矛盾；
- 裸 L1 节点、私有锚点或私有关系类型节点在不存在既有正式公开构造 / 取得路径时的拒绝分支；
- N05：当前确认与历史见证 private helper 的读前 / 读后守卫之间发生事实代次漂移。

审计矩阵必须对下列七族各形成一行：

| 族 | 服务源码 |
| --- | --- |
| 场景 | `海中鱼巣/领域/服务.L2场景结构.ixx` |
| 存在 | `海中鱼巣/领域/服务.L2存在结构.ixx` |
| 特征定义 | `海中鱼巣/领域/服务.L2特征结构.ixx` |
| 特征实例 | `海中鱼巣/领域/服务.L2特征结构.ixx` |
| 状态 | `海中鱼巣/领域/服务.L2状态结构.ixx` |
| 动态 | `海中鱼巣/领域/服务.L2动态结构.ixx` |
| 因果 | `海中鱼巣/领域/服务.L2因果结构.ixx` |

每一行必须记录：

1. archive candidate 的文件 blob、公开当前 / 历史入口、私有 current / historical helper 的精确符号和行范围；
2. 请求形状、读前 / 读后守卫、L1 读取结果形状的判定点；
3. owner、锚点、关系类型、唯一归属关系、端点方向、角色、生命周期、G0 或 H 同截止闭包的逐项判定；
4. 入口拒绝与已接受身份后的`内部不一致`分支边界；
5. `bad_alloc` / `length_error` 到`资源失败`的映射；
6. 未预期异常、L1 形状 / 合同、provider / 装配矛盾到`内部不一致`的映射；
7. 守卫前截止为零、守卫后保留已确认 G0 或 H、非成功空 payload / 空见证 / 空变更、零公开写入的源码证据；
8. 与 4230 §2.4 的逐项对应结论。

N05 固定为 `NOT_RUN`，原因是当前不存在可控、确定且只经正式公开入口制造“恰在两次守卫之间推进事实代次”的路径。N05 的每族审计行还必须记录：读前 / 读后守卫源码位置、两次观测不一致时返回`事实代次漂移`的分支、守卫前零截止与守卫后已确认 G0 或 H 的结果形状、空 payload / 空见证 / 空变更 / 零公开写入，以及不存在合法确定性构造路径的公开入口扫描结论。

`NOT_RUN` 只允许用于本节列出的 private 闭包、强制资源 / 未知异常、无正式公开构造路径的保留节点及 N05。每一项必须同时记录不可达原因、已检查的正式公开入口、对应静态审计行、映射结论和 `NOT_RUN` 状态。不得因 N05 或其它 `NOT_RUN` 增加调度让行、计数器、测试配置、friend、故障注入或任何生产出口。

`NOT_RUN` 不是动态通过，不是异常行为已运行，也不能以 `PASS`、覆盖率或集成验收通过表述。静态审计可单独记录为“静态审计通过 / 失败”，不得改写其动态状态。

D06 的源码审计还必须明确：`发布状态动态原子迁移_v2` 无条件`入口拒绝`的 candidate 源位置；`发布特征当前值变化与中性记录_v1` 中 `Gnow == G0` 的当前确认分支，以及 `Gnow > G0` 的 H 历史见证分支；不得把 v2 的拒绝实现误表述为 v1 的首次 / 重放能力。
