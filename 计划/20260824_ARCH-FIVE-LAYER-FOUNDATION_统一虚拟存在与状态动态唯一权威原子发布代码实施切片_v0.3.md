## 1. 目标和执行前提

在已发布 v0.2 目标内补齐参与者写集 ABI：状态/动态服务各自形成绑定 owner 的不可变参与者材料，动态后状态通过类型化状态局部引用指向本次新状态，L1 在一个候选和一个 G1 中发布，组合 provider 以五组正式读回闭合结果。不得合并 owner、串行真实提交、保留无位置引用列表或让 provider 永久返回骨架 `内部不一致`。owner 是写权限范围，节点是中性身份/存在锚点而非 owner；代表节点可在 owner/端口建立后由结构写入，二者不要求原子。

本计划不实现想/看治理、授权签发、安全硬否决、活动资格、调度配额、轮次结算、后继决议或业务解释；这些是调用方/ARCH-L4 前置和后继边界。

## 2. 当前 WIP 与正式依赖

当前执行 WIP 已有 L1 双参与者类型、组合提交骨架、通用虚拟存在、组合 DTO/服务、装配和工程登记；Debug/Release 构建、strict 116/116 和 diff-check 已通过，但 G1 五组读回未执行。v0.3 是唯一允许执行侧继续该现场的设计版本。

### 3.1 基础数据层不变量与接口复用

- 节点引用节点必须形成关系；标量、文本、材料必须形成属性槽和值。内部/向外/外来不新增字段，而按观察 owner O 从源/目标节点 owner 推导；跨 owner 关系不得固化 owner 视角属性。
- 父/子由关系方向、兄弟由共享父推导；L1 不决定单父/多父。成环按稳定节点编码判断，不按节点类型重复判环；没有证据不得新增祖先回连或错误删除。局部键和跨参与者引用不得把 owner 等同节点。
- 不新增全 owner 扫描、递归图读取或内外分类接口；复用现有 owner-aware 节点读取及源/目标关系组读取，由组合 provider 组合。已满足 L2 的 L1 对外服务 ABI 保持稳定，纯内部能力不公开。
- 代表节点口径只写入相应 L2 结构规范/设计，不能扩张 L1 owner DTO。最小空结构允许只含代表节点。

## 4. 实施切片

1. L1：把跨 owner 引用嵌入事务关系/值/属性槽事实引用，保留参与者序号、owner 绑定、组合幂等和状态/动态编码映射；普通 owner-scoped API 拒绝该类型。仓库必须在同一锁内校验、应用两个候选写集、归一到单 G1、一次交换；禁止先真实提交状态再提交动态。
2. 状态服务：增加 `形成状态原子参与者写集(const L2状态原子参与者请求&) const noexcept`，按固定六个新建局部键和旧状态六项退出闭包形成绑定状态 owner 材料；任何来源/截止/闭包错误不提交。
3. 动态服务：增加 `形成动态原子参与者写集(const L2动态原子参与者请求&) const noexcept`，固定七个动态局部键；主体用 `L2存在身份`，前状态用已发布身份，后状态使用状态参与者局部引用或已发布身份二选一。
4. 组合 provider：用同一 G0 依次形成两份材料，动态后状态引用必须指向状态节点局部键；调用 L1 凭证恰一次；按状态/动态映射取得正式身份后完成五组 G1 读回。
5. 装配：保留状态/动态不同 owner 和单一 L1 运行包；组合 provider 只能持有绑定凭证与 const 服务引用，不向普通调用方导出 raw 端口。通用虚拟存在仍返回 `L2存在身份`。

4015 的 `重新签发所有者范围写端口` 仅用于恢复/明确重入，不是本次首次建立状态/动态 owner、形成参与者或单 G1 提交的直接前置；本次不考虑崩溃、重启、断电或跨进程恢复，因此不扩大白名单。它作为紧邻后继缺口登记，后继必须单独证明 owner 当前性、无活动端口及恢复幂等收敛；执行侧不得在本计划内补实现。

## 5. 结果、幂等、错误与读回门禁

成功/精确重复必须返回完整新状态、新状态关系、新动态、新动态关系和旧状态退出投影；五组截止均为同一 G1。任一参与者失败、owner/参与者错配、引用位置错误、局部键冲突、G0 漂移、资源失败、幂等冲突或读回断言失败均零载荷零变化；发布未知只用原组合幂等身份读回收敛，不重试猜测。旧状态当前入口必须已退出，历史入口完整；新状态唯一当前；动态主体、前状态、后状态关系与来源/时间值逐字段一致。

## 6. 验证矩阵

- 状态/动态参与者材料成功、输入拒绝、来源缺失、旧状态非当前、G0 漂移、owner 错配；
- 局部键表六项/七项完整、重复/未知键拒绝，后状态跨参与者引用位置正确，第三参与者和无位置列表拒绝；
- L1 单候选/单 G1 可见性、首次/同义/异义、任一失败零发布、发布未知收敛；
- 五组 G1 正式读回：新状态、新状态关系、新动态、新动态关系、旧状态当前/历史退出闭包；
- Debug/Release、D:\TEMP 专项、strict、diff-check、生产目标无专项代码；日志只做人读观察。
- 基础数据层矩阵：owner 先建立/端口后由结构写代表节点、节点/关系/属性槽和值类型归类、跨 owner 观察推导、稳定编码成环判断、无全 owner 扫描；失败均零载荷零变化。
