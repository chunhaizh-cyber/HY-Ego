## 2. 实际施工

1. 在服务合同事实权威数据合同中增加历史账覆盖起点请求、快照、状态、结果和强 `成功()` 谓词；非成功统一空快照、截止 0。
2. 在现有唯一服务合同 owner 中增加 `读取服务维护历史事实账覆盖起点_v1`。入口固定 `G0`，读取并互证历史账登记锚点、自我、登记版本和登记事实代次，执行读前 / 读后当前性守卫。
3. 游标数据合同增加 v3 三水位事实、建立 / 读取请求与结构化结果。第三水位是“已消费服务维护历史事实代次”，请求同时冻结主动安全变化账登记见证和服务历史覆盖起点见证。
4. 游标持久载荷扩为八字段；v1 兼容读取 6 / 7 / 8 字段，v2 兼容读取 7 / 8 字段，v3 只接受 8 字段，禁止把旧版本缺失的服务水位补成当前 `G0`。
5. `建立或恢复本能被动维护游标_v3` 实现无当前建立、v1 / v2 迁移、v3 恢复、异键同义恢复、新纪元、精确重复、同键异义、引用冲突、确定失败和提交后读回不确定收束。迁移时主动安全水位来自旧 v2 或正式登记起点，服务水位只来自服务 owner 覆盖起点。
6. 启动初始化改为读取两个 owner 的登记见证和当前 v3；旧 v1 / v2 只作为迁移输入。v3 建立 / 恢复后，以新的 `Gread` 独立读取并逐字段互证三水位，成功后才进入线程创建。
7. 服务合同专项增加 H-1 覆盖起点矩阵；游标专项增加 C07—C11，覆盖 v1 / v2 迁移、v1 / v2 兼容投影、重复 / 冲突 / 恢复、新纪元、服务水位推进拒绝和三水位持久恢复。


- 覆盖起点读取用途：从唯一服务合同 owner 在 `G0` 读取永久历史账首次合法排除边界；只读，不枚举历史事实、不推进游标。
- v3 建立 / 恢复用途：保存完整秒、主动安全变化事实代次、服务维护历史事实代次三个独立水位；负责旧载荷迁移和幂等收束，不解释历史事实、不推进维护结果。
- v3 当前读取用途：只接受完整八字段当前载荷并返回权威三水位；旧 v1 / v2 返回待迁移，不猜第三水位。
- 直接调用边：生产启动调用三个入口；专项和仓库外 ABI consumer 独立消费。
- 用途卡动作：发布后为三个公开入口新建用途卡，并把启动 `运行普通程序` 的本能根初始化段标记为待复核。
