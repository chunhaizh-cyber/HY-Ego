实现结果：

1. 新增合同版本 3、参与者上下限 `2..255`、v3 顶层请求、固定九态结果和逐字段相等；五类中性写项、参与者身份和参与者结果复用 v2 值式布局，不改变 v1/v2 ABI。
2. `L1所有者范围写端口` 新增有限 N 分区入口。接收者固定绑定参与者 1，其余端口依序绑定参与者 2..N；在进入仓库前拒绝数量不符、空/重复端口、跨实例、失效端口和 owner 错配。
3. 仓库新增动态 N 参与者事务：规范化完整请求，在唯一写锁内检查 v3 独立幂等账和共同 G0，以私有候选按参与者身份顺序复用普通 owner 写入，只解析向后跨参与者引用。
4. N 次候选临时代次、事实创建/退出代次、N 份 owner 首次写入账和首次结果统一为第一参与者形成的共同 G1；候选全局完整性、持久准备和独立 v3 账全部通过后只交换一次正式状态。
5. 内部权威载荷格式由 2 升为 3；格式 1/2 解码分支保持，格式 3 在 v2 三分区账后追加规范有序 v3 账。v3 使用专属参与者/请求/结果编解码与 `1..N` 守卫，不放宽 v2 的 `1..3` 语义。
6. `状态完整` 增加 v3 请求、首次结果、N 份 owner 首次规范化写集、映射、共同 G1、引用闭包、局部键和属性槽的逐项互证。
7. 新专项只通过公开运行包、签发器、move-only 写端口和正式读服务验证；不使用 friend 仓库、生产故障入口、内存地址或日志作为结果裁决。
