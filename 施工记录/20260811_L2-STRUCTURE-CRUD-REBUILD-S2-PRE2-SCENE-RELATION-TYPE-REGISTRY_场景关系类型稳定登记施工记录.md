## 2. 实际施工

### 2.1 场景登记 DTO

在 `海中鱼巣/领域/L2场景结构.数据.h` 原位增加：

- 父子关系类型身份与成员关系类型身份两种不可混用的强类型；
- 登记状态、完整原请求、稳定登记和结构化结果；
- 请求、登记与成功状态的纯值完整性辅助。

登记固定合同版本、规则版本、首次幂等身份与首次期望代次，并分别保存建立代次、事实截止代次和两个强类型编码。失败结果不携带候选登记。

### 2.2 唯一场景服务登记能力

在既有 `海中鱼巣/领域/服务.L2场景结构.ixx` 原位扩展唯一 `L2场景结构服务`：

- 使用私有幂等域 `0x1D`、固定身份 `{1}` 和本地键 `0x0201'0101U` / `0x0201'0102U`；
- 一次 L1 中性写集只建立两个普通、零属性、互异编码的关系类型节点，关系、值、属性槽变更和退出项均为空；
- 只以 L1 正式回显映射取得两个稳定编码，不预探测、不预分配、不建立第二幂等账、不重试提交；
- 服务实例以普通 mutex 保护值式 optional 定位，未加载实例直接读取返回 `登记未加载`；没有模块级、静态或跨实例锁；
- 首次成功和精确重复都经过 L1 正式一致当前投影读回；仅事实代次漂移允许按 L1 回显实际代次完整重读一次；
- 许可拒绝立即结构化上送，且不保存尚未正式读回的候选定位；无 sleep、yield、自旋、轮询或读取内许可重试。

### 2.3 生产外验证

新建独立 Debug / Release x64、v145、C++20、Unicode、`/utf-8` 外验项目、入口和 PowerShell 包装。验证输出与中间目录位于系统临时目录，不进入主工程或 filters。

v0.2 只修订并发项：两个新服务并发首调后接受“已提交 + 精确重复”或“一项成功 + 一项许可拒绝”两种公开形状。许可拒绝分支先证明原服务仍未加载，再用完全相同原请求恰一次调用公开建立函数，要求精确重复、正式读回并加载同一登记，且 L1 事实代次不再推进。最终仍以完整登记对两个普通节点做权威投影核对。

## 4. 范围与完成边界

本施工只实现一个 L1 服务生命周期内两个场景关系类型普通节点的唯一幂等建立、正式读回、实例定位重建和许可竞争后的原请求收敛。没有实现 S2 父子 / 成员关系 CRUD、生产装配、自动重试策略、跨进程恢复、集成验收、其它结构族、A1 或完整 L2。

提交和推送由顶层唯一 Git 发布者在复核精确七文件、index 与剩余 dirty 后完成；本记录不把当前未提交 WIP、构建或外验升级为 Git 结果提交、生产接线或业务闭环。
