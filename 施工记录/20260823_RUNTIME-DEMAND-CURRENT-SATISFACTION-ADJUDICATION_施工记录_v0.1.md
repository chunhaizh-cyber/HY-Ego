## 2. 实际施工

### 2.1 DTO

在 `运行期只读查询.数据.h` 增加：

- `需求当前满足裁决规则版本`；
- `需求当前满足裁决请求`；
- `需求当前满足裁决状态`；
- `需求当前满足裁决快照`；
- `需求当前满足裁决结果`及其值式成功谓词。

结果只有 `已满足`或`未满足`且携带裁决快照时才成功。其它状态均返回零裁决。

### 2.2 公开只读 provider

在 `运行期只读查询组合器`增加 `裁决需求当前满足(...)`。正常链固定为：

```text
读取需求完整
-> 读取需求成员列表，只消费当前成员关系
-> 按当前成员关系.列表项读取需求列表项完整
-> 按目标宿主读取全部当前特征
-> 读取完整目标状态合同
-> 读取当前特征比较注册
-> 比较特征
-> 按具名关系与允许关系位返回已满足或未满足
```

六次公开读取与一次正式比较共用请求中的同一 `G0`。函数不刷新截止、不重试、不读取任务实际结果、路径或实例方法，不写需求、任务或结算事实。

### 2.3 执行期 DRIFT 与裁决

v0.1 误把 `读取需求成员列表`返回的`所属列表项`当成完整列表项；当前源码实际只保证它是身份投影。V02 首次运行因此返回`引用冲突`。

计划支撑以 v0.2 正式裁决 A 路径：从`当前成员关系.列表项`取得唯一身份，在同一 G0 复用公开`读取需求列表项完整`。B 路径“修改 L2 provider 返回形状”被排除，因为它会扩大 owner、白名单和公共合同。执行侧按 A 路径机械修复，成功快照的列表项只来自完整读取载荷。

### 2.4 专项验证

新增 `验证需求当前满足实时裁决()`，通过普通应用公开 L1/L2 写入口建立需求、成员、列表项、特征当前值、目标合同和比较注册。V02 失败诊断同步增加完整列表项读取，打印六次读取状态与截止；成功断言核对需求/成员/列表项四字段、列表项完整谓词、生命周期、当前值、合同和比较回执。

测试继续逐项保留无法经合法公开 API 注入的场景为 `NOT_RUN`。V10/V11 的夹具原先尝试退出仍被当前需求引用的合同和比较注册，公开写入口以`引用冲突`正确拒绝；修正后把该拒绝作为不可合法制造的证据，并用独立合法存在写入形成 V13 的旧 G0 漂移。

## 4. 完成边界

本施工只形成“单个具名需求在同一 G0 下当前是否满足”的只读 provider。它不读取或消费任务结果，不分配结果，不形成父需求回流、任务筹办或逐成员结算。

任务结果后续必须先区分可共用与争用：可共用时各需求分别核算；争用时才依据尚待正式实现的成员分配优先级顺序分配。本切片没有实现该后继语义。
