## 3. 实施细节

### 3.1 生产配置

`形成普通应用生产配置()` 使用 `SHGetKnownFolderPath(FOLDERID_LocalAppData, KF_FLAG_CREATE, ...)` 取得每用户已知目录，拼接固定三段相对路径并建立目录。已知目录、目录建立、纯值配置、资源和内部异常分别映射六种结构化状态；失败配置不携带 optional 值。

`普通应用配置::有效()` 只检查材料合同版本、非空绝对路径和 `.` / `..` 路径分量，零文件系统 I/O。

### 3.2 owner、服务与析构

装配函数在既有唯一 L1 中按材料、语言、词条顺序签发三个独占结构 owner。材料服务使用公开固定身份形成的 owner 交付；语言服务使用同一 L1、同一材料服务及语言 / 词条两份强类型 owner 交付。任一步失败均返回新增的 32—38 具名状态和空上下文，已经形成的局部对象由 RAII 清理。

上下文成员固定为 L1、材料、语言、六世界、世界聚合、概念、概念聚合、方法、方法聚合的依赖顺序，反向析构时依赖者先释放。上下文不保存 raw owner 端口。

### 3.3 合法消费者首次读回

仓库外专项只导入正式普通应用、材料、语言和概念模块。它先从材料登记的结构化 `事实代次漂移` 回显收敛当前代次，再经普通应用 getter：

1. 写入语言登记键、共享来源、规范化合同、规范化词面四份严格 UTF-8 材料；
2. 建立一项语言结构，并按身份和登记键进行当前 / 历史读取；
3. 建立一项词条结构，并按身份和规范化键进行当前 / 历史读取；
4. 互证材料、语言、词条身份、来源、生命周期和事实截止；
5. 经概念聚合取得同一概念服务并完成零根当前读取；
6. 销毁上下文后清除专项材料根。

专项未直达 L1、owner 写端口、内部 helper 或生产验证分支。
