## 2. 实际施工

### 2.1 公共合同与存在 DTO

- 在 L2 公共数据合同增加 `L2节点族` 与 `L2节点族身份来源事实`，并由公共合同模块唯一导出 owner 范围合同，供存在族强类型交付与来源事实复用。
- 在存在数据合同增加当前 / 历史身份来源读取请求与结果，完整冻结节点、族锚点、归属关系类型、唯一关系及生命周期投影。
- 退出请求新增调用方显式提供的族归属关系稳定编码；零值、错关系和遗漏闭包不再由服务猜测或扫描补齐。

### 2.2 强类型 owner 交付与唯一 provider

- 新增 move-only、不可默认构造和不可复制的 `L2存在所有者交付`；只有正确建立幂等身份、正确 owner、同一 L1 实例且有效的写端口才能形成交付。
- `L2存在结构服务` 删除 raw `L1所有者范围写端口` 构造入口，只接受存在族强类型交付。
- 普通应用装配先形成存在 owner 交付，再构造唯一存在服务；两个公开 getter 返回同一实例，普通上下文不公开 raw 端口、owner 或内部来源定位。
- 装配失败映射按冻结设计扩展为六值状态，不把 owner 形成失败伪装成普通配置失败。

### 2.3 来源初始化、创建、读取与退出

- 服务构造期使用固定内部幂等身份原子登记存在族锚点和族归属关系类型；重复构造读回首次编码，固定编码不依赖进程缓存或第二权威。
- 新存在以一份 L1 owner 写集同代写入普通节点和指向族锚点的唯一非自环归属关系；首次成功与精确重复都核对两项编码映射和正式历史来源。
- 当前来源以单次 owner 范围一致投影核对 owner、目标、锚点、类型和精确源关系组；历史来源以前后事实代次夹取、判定截止与创建截止回退区分未登记、提前退出和畸形关系。
- wrong-family、legacy、裸节点、属性类型和内部节点固定入口拒绝；已定位来源后的重复、错锚点、错角色、混代与生命周期不闭合固定内部不一致。所有非成功结果为空来源且不产生普通事实变化。
- 当前 / 历史完整读取、属性写入前置和兼容节点读取统一消费正式来源闭环；退出要求显式闭合唯一来源关系、节点和当前属性，节点与来源关系同代退出，锚点与类型继续保持当前。
- 删除零调用的旧单映射、当前弱节点读取和历史弱节点读取 helper，避免以后绕过正式来源闭环复用。

### 2.4 生产外专项验证

- 新建独立 Debug / Release x64、C++20、Unicode、`/utf-8` 临时参数工程与 PowerShell 包装；输出和中间目录全部落在系统临时目录，未登记进主工程或 filters。
- 临时驱动只使用公开 L1 DTO / 运行包、公开 E-ID DTO / 服务和普通应用 provider，覆盖 15 组 owner、初始化、创建、读写、畸形注入、退出和并发矩阵。
- 首轮并发用例错误地忽略了前置代次探测的资源 / 许可失败并继续提交零期望代次；修正为先取得有效代次再调用完整投影，完整投影的允许集合仍严格保持 `已读取 / 事实代次漂移 / 许可拒绝`，未放宽为入口拒绝。

## 3. 范围与完成边界

本施工只实现 E-ID 的存在族强类型 owner 交付、唯一 provider、身份来源初始化与读回、新节点同写来源、来源约束下的完整读写和显式关系闭合退出。它不实现或证明 F-ID、T1、DYN2、S-ID、A1、业务消费者闭环或独立集成验收。

关系事实 owner 与正式类型 owner 不一致、私有索引损坏、资源分配故障、崩溃恢复、长时公平性和跨进程行为没有通过公开正常 API 注入或运行，均保持 `NOT_RUN`。提交与推送仍由顶层唯一 Git 发布者在精确十路径复核和发布租约后完成；本记录不把未提交 WIP、构建或专项结果升级为生产能力闭环。
