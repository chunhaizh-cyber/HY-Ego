## 3. 已实现内容

- 按冻结字段顺序建立不可变材料 DTO、move-only 构造输入、构造结果、唯一 provider 构造和四个公开 CRUD / 读取入口。
- 以固定材料 owner、固定登记幂等身份和六个固定本地键建立系统签发者、严格 UTF-8 / 通用字节格式及三种 U64 组属性类型，并逐项正式读回。
- 显式接受非空绝对普通目录；用 Windows 句柄、最终规范路径、卷序列和重解析点检查建立 `候选/`、`对象/sha256/` 受控结构，不读取默认路径或环境变量。
- 用 BCrypt / CNG 计算 SHA-256；用同卷临时文件、复读、不可覆盖 `MoveFileExW` 和目标复读裁决发布摘要对象。
- 严格 UTF-8 拒绝空内容、BOM、无效序列和 `U+FFFD`；通用字节不解释内容。
- 来源只经 `L1事实基座服务::读取中性当前节点` 读取系统签发者或调用方给出的正式节点；保存来源截止用于 L1 提交条件。
- 材料写集固定建立一个普通材料节点、格式 / 长度 / 摘要三值和三个当前槽；当前 / 历史读取从 L1 三槽与三值逐字段重组，不从路径或缓存猜编码。
- 请求账和内容索引只在服务实例内作为非权威协调；同键重放、同内容收敛、异来源冲突和并发 leader / waiter 均在短临界区协调，文件系统和 L1 调用时不持服务锁。
- 退出从当前三槽取得三值编码，一次 L1 写集退出材料节点与三值；引用冲突保持零变化，成功后正式读回历史四事实和当前不可见状态。

## 4. 施工中发现并修复的计划内代码错误

1. 初次 Debug 编译引用了最终 L1 枚举中不存在的 `事实代次漂移` / `许可拒绝` 分支；删除错误枚举分支后根工程双配置通过。该问题未改变合同。
2. 专项首次链接出现模块析构 `LNK2005`；把同一模块接口单元中的析构定义改为 `inline`，没有增加公开函数、文件或验证入口。
3. 扩展专项发现同 owner 同根第二次构造返回 `登记失败`。根因为固定登记重放使用当前全局代次，导致同一登记幂等身份的请求形状变化。实现改为从正式材料 owner 事实读取其创建事实代次，原样重放固定登记请求；二次构造随后为精确重复且登记首次截止不变。
