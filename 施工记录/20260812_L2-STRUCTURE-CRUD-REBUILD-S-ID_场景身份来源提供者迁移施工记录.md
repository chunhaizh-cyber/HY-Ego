## 1. 实际范围

本次只修改计划允许的三条生产路径，并建立三条生产外专项路径及本记录、配对验证记录。未修改 L1、公共 L2、存在 / 特征 / 状态 / 动态 / 因果生产代码、根工程、filters、规范、详细设计、计划、索引、流程图或路线输入。

## 2. 实际实现

- 在 `L2场景结构.数据.h` 增加场景身份来源当前 / 历史请求结果、场景四种强类型属性身份及登记 DTO；退出请求增加族归属关系编码，退出结果增加已退出身份来源。
- 在 `服务.L2场景结构.ixx` 增加场景独占 owner 交付、场景族锚点 / 归属类型初始化、四属性类型登记和 owner-aware 正式读回。场景节点与族归属同写，全部关系、属性和退出均只经唯一 owner-scoped 端口提交。
- 父子三入口逐端点消费 S-ID；成员三入口消费场景 S-ID 与存在 E-ID；属性入口先核场景 S-ID，再按材料变体唯一匹配场景 owner 的四属性类型。
- 当前 / 历史完整场景逐项复核主场景及父子场景 S-ID、成员存在 E-ID 和四属性类型登记；反向成员读取先复核请求存在 E-ID，再复核每个源场景 S-ID。
- 场景退出把节点、族归属、可选父关系、全部子关系 / 成员关系 / 当前属性值纳入一个退出写集；成功后历史读回节点与族归属同代退出，owner、族锚点和归属类型继续当前。
- 普通应用在存在、特征、状态、动态、因果 provider 之后建立场景 owner 和唯一场景服务，追加状态 20—22，并提供 const / 非 const 同实例 getter。

## 3. 固定身份与键域

- 场景 owner 建立身份：`0x4C31'4F57'4E45'5237`。
- 场景来源登记身份：`0x4C32'4944'5352'4307`。
- 场景属性类型登记身份：`0x4C32'5343'4154'5201`。
- 场景族锚点 / 族归属类型及四属性类型使用计划冻结的 `0x0201'1001` 起本地键域；业务 CRUD 继续把公开 `L2结构幂等身份` 映射到场景 owner 的唯一幂等域。
