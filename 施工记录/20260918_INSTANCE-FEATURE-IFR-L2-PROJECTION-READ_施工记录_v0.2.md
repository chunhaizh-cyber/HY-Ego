# INSTANCE-FEATURE-IFR-L2-PROJECTION-READ 施工记录 v0.2

结果提交：`12e678f744d13d3540f222eb8e6a17e1775dbc95`、`664e1fe7`。

## 实际变更

- 在 `存在类数据服务` 新增 `读取IFR结构` 及完整投影 DTO。它只读 L1 的当前事实代次、历史节点、历史关系组和历史属性值组；每次读取后都核验 `Gread`，不调用写端口。
- 读取固定核验三条单值关系 role `1`，三类成员关系按目标稳定编码升序的 role `1..N`，并将任一重复、角色错位、生命周期、owner、方向、类型、属性槽或来源偏离返回为 `引用冲突`。
- R项材料只接受 v2 `U64组 {格式版本,类别,载荷...}`，要求值来源为 R项自身；I64 闭区间还核验两个载荷端点的顺序。投影保留节点、关系、角色和生命周期，并检查所有形成成员并集等于 IF 成员。
- 运行夹具暴露前置 v2 布局登记结果未回填 `版本=2`，导致其状态虽为“已登记”却永不满足 `成功()`；以一行回填修复并回归夹具。该修复不改变布局语义或写集。

## 代码知识变更清单

- 新增 `存在类数据服务::读取IFR结构(const 实例特征IFR读取请求&) const noexcept`（公开只读服务，`领域/数据服务.存在类.h`）：输入是 `{Gread,E,FT,F成员上限,R项上限,关系上限}`；成功返回同截止完整投影，失败清空投影；不负责 IF/R 写入、退出、L3 分类、特征出生或当前采用。
- 新增 `实例特征IFR读取请求/结果`、节点/关系时态、R项身份及投影 DTO（同文件，公开纯值合同）：承载完整形状和固定角色顺序，不引入新 owner 或 L1 ABI。
- 修改 `存在类数据服务::登记实例特征结构`（同文件，公开静态登记）：仅回填既有 v2 结果版本，使已登记结果可通过既有 `成功()`；不改变写入内容、幂等键或装配。
- 已发布结果需要知识库维护者为以上新增/修改身份建立或更新用途卡；本切片未修改共享知识索引。

## 未验证边界

夹具是进程内 L1 内存结构，未覆盖持久库、跨进程恢复、并发代次漂移、错误材料的逐类注入或完整普通应用启动。全工程 `ClCompile` 仍被当前 `数据服务.概念树类.cpp` 的既有声明/定义失配阻断，详见验证记录；该阻断不来自本切片。
