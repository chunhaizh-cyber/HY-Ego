## 1. S0 与设计漂移收敛

v0.1 执行中首次由外部模块真实调用路径服务后，MSVC 稳定报告两个 `LNK2019`。根因是任务模块中的 friend 前置声明和路径模块中的同名定义附着于不同 C++20 named module。执行侧未把基础承载改为 public；计划支撑形成并发布 v0.2，改用任务模块自有 move-only capability 端口。v0.2 正式登记可执行后重新 S0，代码和语义范围均未扩大。

工作区其它未跟踪规范、详细设计、计划草稿、`.codex-build/`和异常名称临时文件均原样保留，未读取为机器事实、未清理、未纳入本切片。

## 2. 实际施工

1. 在任务模块增加一次性写入能力交付、move-only 写入端口和 owner 精确绑定形成函数；私有路径承载只授权同模块端口。
2. 新路径服务先读取同代次当前普通方法并精确验证身份和内容版本，成功后只经 capability 端口进入唯一原子写集。
3. 普通应用在任务 owner 交付移动前提取凭据，任务服务形成后绑定唯一端口，再移动给路径服务；上下文只公开路径服务 const / non-const getter。
4. 任务筹办的路径写调用迁移到路径服务，但未装配筹办服务、未修筹办其它缺口。
5. 需求端到端测试建立真实普通方法、第二需求和任务，验证错误版本 `引用冲突`且代次不变，并验证合法路径从任务结构公开入口完整读回。
6. 真实读回暴露并修复两项既有路径实现错误：写后读回返回局部读取结果内部的悬空值指针；当前投影误用身份初始化关系类型查询路径结构关系。两项均位于本计划首次权威读回范围。

## 3. 代码知识变更清单

### 新增函数 / 特殊成员

- `L2任务方法路径写入能力交付(L2任务方法路径写入能力交付&&) noexcept`：移动一次性 owner 凭据并使来源失效；不读写事实。
- `L2任务所有者交付::提取任务方法路径写入能力交付() noexcept`：从唯一任务 owner 交付一次性提取路径写 capability；重复或失效返回空。
- `L2任务方法路径写入端口(L2任务方法路径写入端口&&) noexcept`、`有效() const noexcept`：移动并检查非拥有任务服务绑定。
- `尝试形成L2任务方法路径写入端口(...) noexcept`：消费凭据、精确核对 owner，并形成唯一端口；失败零事实写入。
- `L2任务方法路径写入端口::写入已验证任务方法路径(...) noexcept`：唯一调用任务服务私有原子承载；失效端口返回`内部不一致`。
- `L2任务方法路径结构服务`构造与`新增任务方法路径(...) noexcept`：持有方法读服务和 capability 端口，完成方法当前事实/内容版本门禁。
- `普通应用上下文::取得L2任务方法路径结构服务()` const / non-const：返回上下文持有的同一服务实例。

### 修改函数

- `L2任务结构内部::读回新增任务方法路径(...)`：值事实改为按值持有，消除局部读取结果析构后的悬空指针。
- `L2任务结构内部::读取任务方法路径当前投影(...)`：统一使用路径结构关系类型读取并验证族归属。
- `L2任务结构服务::写入已验证任务方法路径(...)`：由原公开新增正文改为 private 原子承载，写集和幂等语义不变。
- `普通应用上下文`私有构造、`构造普通应用上下文(...)`：增加路径服务所有权、三项装配失败分账和 capability 装配顺序。
- `任务筹办编排服务`构造与私有路径形成调用：新增路径服务依赖，路径写改走权威门禁入口；其它筹办行为不变。
- `运行需求服务端到端测试()`：增加真实方法、错误版本零写、合法路径写入和权威读回场景，并修正需求退出后的测试代次推进。

### 退出身份与调用边

- 退出公开 `L2任务结构服务::新增任务方法路径`调用身份；其实现收缩为 private `写入已验证任务方法路径`。
- 删除“任务模块 friend 路径模块同名类”的跨模块边。
- 新增 `普通应用 -> capability形成 -> 路径服务`、`路径服务 -> 方法公开读取`、`路径服务 -> 写入端口 -> 任务私有承载`调用边。

上述函数用途卡与调用图在结果提交发布后均应标记待增量复核；本记录不直接修改共享知识索引。
