# F-ID 特征身份来源提供者迁移施工记录

日期：2026-08-12

## 实际实施

- 为特征定义、特征实例增加强类型 owner 交付和不可交换形成函数；服务只持有两个互异 owner 写端口。
- 构造顺序固定为定义来源、定义四属性类型、实例来源、实例关系类型、实例值类型；任一步失败不发布半构造服务。
- 定义与实例共用一条参数化来源初始化、当前来源和历史来源算法；族专属参数只有节点族、owner、锚点、归属类型和固定本地键。
- 新定义同写节点和归属关系；新实例同写节点、归属、宿主和定义三关系。
- 实例写前分别消费 E-ID 存在来源与 F-ID 定义来源；定义/实例完整读取、定义属性、实例值、具名历史值和退出消费正式来源。
- 定义 owner 内登记 I64、I64 组、U64 组、独立材料四种属性类型，并按材料表示拒绝错类型。
- 普通应用追加状态 6—10，建立双 owner，持有唯一特征服务并提供 const / 非 const getter。

## 边界

- 未修改 L1、公共 L2、存在服务、根工程、filters、其它族、T1、DYN2、S-ID、A1、流程图和路线。
- 未引入恢复、adoption、第二仓、成员表、缓存权威、测试友元或生产验证实体。
- 三个专项验证文件只用于生产外验证，实施发布后按独立清理提交删除。
