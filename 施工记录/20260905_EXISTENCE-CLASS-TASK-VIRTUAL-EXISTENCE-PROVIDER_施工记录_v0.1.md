## 2. 实际变更

- 在既有 `数据服务.存在类.ixx` 增加任务虚拟存在专用合同版本、冻结状态、写集规格
  请求/结果、查询请求/结果和只读投影 DTO；保留普通存在 ABI 与构造方式不变。
- 新增 `形成任务虚拟存在写集规格` const 入口：校验调用方提供的 task owner、任务
  节点和专用关系类型处于同一 G0、同一独占 owner 且为无属性普通节点；确认尚未初始
  化后，仅返回固定本地键的一节点一关系 owner 写集规格，不获取写端口、不提交写集。
- 新增 `查询任务虚拟存在` const 入口：按任务节点和专用关系类型读取唯一当前关系，
  再以 owner 一致当前投影读回 T、Vt、类型和关系，验证同 owner、角色 0、无属性普通
  节点及 Vt 与关系同创建代次；零条返回未初始化，多条或结构不符返回结构冲突。
- 两入口均在首尾读取当前事实代次并收口漂移；非成功结果不携带写集或投影。
- 专用实现只调用 L1 当前代次、当前结构 owner、当前节点、当前源关系组和一致当前投影
  五类只读入口；不调用 L1 写、不调用普通存在函数、不使用本服务世界 owner 写端口。

## 3. 公开 ABI

新增两个专用 const 入口：

1. `存在类数据服务::形成任务虚拟存在写集规格(const 任务虚拟存在写集规格请求&) const`；
2. `存在类数据服务::查询任务虚拟存在(const 任务虚拟存在查询请求&) const`。

写集规格的 owner 和幂等身份完全来自请求；本服务不拥有 task owner，不负责提交、重试、
退出、恢复或业务治理。普通存在的新增、查询、成员增删和退出入口均未改变。
