## 2. 实际代码变更

### 2.1 task owner 强类型来源与原子发布

- `海中鱼巣/领域/L2任务结构.数据.h`
  - 增加初次 / 重筹办来源幂等身份、归因证据和规范化来源的判别联合。
  - 正式选择记录改持`原筹办来源幂等身份`；稳定证据增加`初次筹办准备记录`类别。
  - 增加完整任务身份来源、方法生命周期、条件 / 输入 / 参数 / 限制、授权安全和冻结材料强类型合同。
  - 增加唯一正式选择发布、按来源幂等身份读取和完整结果 DTO / 谓词；删除旧独立当前路径发布 DTO / 谓词。
- `海中鱼巣/领域/服务.L2任务结构.ixx`
  - task owner 私有登记选择记录、冻结材料、首次账、六类拓扑和完整请求属性类型。
  - 唯一`发布任务筹办正式选择`以判别联合分流初次 / 重筹办：初次创建轮次 1 结构且不退出旧事实；重筹办退出旧当前选择 / 路径 / 实例后原子换代。
  - 同一 owner 写集提交新冻结、路径、正式选择拓扑、派生当前路径和实例；发布后权威读回完整选择、冻结和实例。
  - 增加按强类型来源键的首次账定位、完整请求编码 / 解码和未知发布恢复；底层值相同但联合分支不同不会串账。
  - 路径四个兼容值从已发布选择拓扑派生；新本地键不包装为稳定编码。
  - 删除旧`发布当前选中路径`公开写入口；既有读取和历史投影继续由 task owner 解释。

### 2.2 Stage C、协议和线程

- 新增`海中鱼巣/领域/内部治理/任务筹办当前就绪与执行冻结.数据.h`，定义当前就绪、九结论收束、等待合同、非成功承接和冻结形成 DTO。
- 新增`海中鱼巣/领域/内部治理/服务.任务筹办当前就绪与执行冻结.ixx`：
  - 只消费合法`下一筹办工作包`，机械构造重筹办来源联合，不泛化初次 BIZ provider。
  - 复判任务、方法、来源需求成员、条件、输入、限制和授权安全当前性；九种方法查找结论形成冻结候选或具名非成功承接。
  - 成功分支调用 task owner 唯一组合发布入口并权威读回；失败、资源和当前性分支不携带冻结材料。
- `海中鱼巣/线程/协议.任务执行请求.ixx`升级为 v2 强类型冻结请求，删除 legacy 任务 / 方法 / 动作三组材料；请求编号和幂等键同源于重筹办意图键，任务序号来自实例执行轮次。
- `海中鱼巣/线程/任务管理线程.ixx`接入 Stage C，槽快照保存完整推进结果、冻结请求和非成功承接；容量等待只重试相同冻结请求，不重写 task owner。队列同任务键改为`L2任务身份`。
- `海中鱼巣/线程/运行包.任务结果生产.ixx`、`海中鱼巣/装配.普通应用.ixx`和`海中鱼巣/启动.应用程序.ixx`完成构造签名和唯一 provider / getter 的机械接线。普通配置使用授权安全材料缺失来源，因此正常形成合法等待而不是假冻结。

## 3. 计划内问题修复

1. `L2任务选择稳定证据组完整`原先未接受初次准备记录，补齐初次稳定证据分支。
2. 原子发布路径的`预期结果`改保存并复核`主轴结果.来源稳定编码`，与既有任务完成裁决语义一致。
3. 方法查找夹具原先没有未满足当前值，无法经正式初次准备形成任务；补入公开特征服务写入和退出，不绕过初次筹办。
4. 大治理专项目标特征实例建立后缺当前值，导致“形成单根正式初次筹办工作包失败”；补入值 3（目标 2、允许关系位 3）的真实未满足当前值并推进事实代次。
5. 特征夹具幂等键调整到`0x7D90`—`0x7D92`，避免与既有夹具键冲突。

以上均为白名单内实现 / 测试错误修复，不改变计划合同。
