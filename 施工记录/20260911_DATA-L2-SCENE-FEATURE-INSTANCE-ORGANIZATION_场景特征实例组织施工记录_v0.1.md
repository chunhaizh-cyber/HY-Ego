## 1. 实际施工

1. 在`合同.存在结构身份只读`追加版本1的存在已知准确特征当前/历史请求、稳定状态、见证、结果成功谓词及两个只读 virtual；既有存在身份版本2和三个 virtual 不变。
2. `存在类数据服务`实现`确认当前已知准确特征`与`读取已知准确特征历史`。当前读规范化为同截止历史读；历史读组合存在身份见证、存在历史结构核心和有界准确特征读取，保持固定预算、唯一7150成员关系、生命周期、结束守卫、失败零载荷和C/F回显。
3. 将原`读取存在历史事实`主体抽为私有`读取存在历史事实核心`：原公开入口传入“包含当前采用”，新增组合窄读传入“不包含当前采用”，从而保证当前采用不参与C已知F证明；不新增公开 ABI。同步修正形状通过后的H回显及能够观察到的漂移Gread。
4. 在`合同.场景角色组织`追加场景特征组织版本1 DTO、固定扩展登记键和成功谓词；既有场景协议v2、六编码、四根和状态数值不变。
5. `场景类数据服务`追加扩展结构登记、显式C/P/F组织写入、当前/历史准入与完整路径读取、单父无环、路径预算、幂等重放、发布未知读回和退出保护。场景类只持有既有`存在结构身份只读提供者`，不持有具体存在类、特征类或第二 provider。
6. 场景特征实现并回接口单元；未发布的`数据服务.场景已知特征读取桥.ixx`、`.impl.cpp`和`数据服务.场景类.impl.cpp`已物理不存在，工程和代码引用为零。三者本来未受 Git 跟踪，因此不形成删除 blob；工程/filters相对HEAD无内容差异。
7. 新增互斥双探针专项工程、源和运行脚本。ExistenceProvider模式编译真实存在类且不编译场景类；SceneOrganization模式编译场景类和严格合同桩且不编译具体存在类。
