## 2. 实际变更

### 2.1 特征窄核验

新增专用 `特征类型准确值核验状态/结果` 及 const `核验正式特征类型准确值`。入口分别读取正式 FT 与引用特征值，保留 FT 未找到/已退出和值未找到/已退出的来源，核验表示和值域，零写入、零创建特征信息。

### 2.2 状态 v2

状态公开合同整体切换到四字段：状态身份、正式 FT、固定准确值、强时间。物理结构固定为一个普通节点、两条关系和三个值；支持内联 I64 / 特征值身份两种准确值，以及实例绝对 UTC / 抽象相对两种非负强时间。

实现创建、当前/历史完整读取、按 FT/准确值/时间查询、共同身份确认与历史见证、整体退出和实例状态同步清理。主要保护包括：

- owner 写结果精确核验合同、身份、发布确定性、`Gwrite = 期望G + 1`、映射和回显；
- FT 反向召回先过滤状态 owner，再核对目标、关系类型、角色和生命周期；
- 历史读取允许 `H < Gexit <= Gread`，退出内容以 `H = Gexit - 1` 完整读回；
- 墓碑只产生 `历史材料已清理`，不伪造内容或身份见证；节点墓碑核验种类、owner、创建、退出、清理代次和外层回显；
- 身份见证中的身份、族锚点、族关系类型和族关系编码两两不同；
- 同步清理从退出首次材料恢复固定有序集合和 `Gexit`，不重扫、扩集或换集；首次退出后的同次清理使用 `Gexit` 作为 L1 期望，后续重试校验 `请求G0 >= Gexit` 并使用本次 G0；L1 成账前不绑定清理键，成账后由 L1 幂等账和墓碑裁决精确重放或冲突；
- 清理回显核验 `Gclean = 请求G0 + 1`、`创建G < Gexit < Gclean`、同 owner、每状态聚合比例 `1节点/2关系/3值`；状态层未增加 pair 持久账、内存键账、L1 接口或第二清理入口。

旧 v1 类型和入口未保留兼容 overload；存在、场景、动态和因果旧消费者留待后继计划迁移。
