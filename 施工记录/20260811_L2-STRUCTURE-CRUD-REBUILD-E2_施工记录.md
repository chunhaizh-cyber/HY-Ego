## 2. 实际施工

### 2.1 共同属性合同

- 把 `L2属性提交项有效` 与 `L2属性事实截止投影完整` 从场景数据头唯一迁移到 `L2结构公共.数据.h`，场景和存在数据合同共同复用，不保留重复实现。
- 公共辅助保持四类材料、来源、类型、创建 / 退出代次的既有 S3 完整性语义；没有引入新的机器事实口径。

### 2.2 存在 DTO 与服务

- 在存在数据头增加固定属性新增 / 换代、退出、完整读取和场景成员反向引用所需十个值式 DTO，并补齐请求有效性、成功形状、失败空载荷和稳定排序完整性。
- `新增存在固定属性` 与 `换代存在固定属性` 使用本地键 `0x0202'0301U`，把一个新值与属性槽变更放入同一 L1 写集；首次成功和精确重复均通过 L1 正式结果及历史事实读回核对，引用冲突显式映射为 L2 结构状态。
- `退出存在` 只消费调用方显式给出的、严格升序且无重复的当前固定属性闭包；存在节点与全部当前属性值在一个 L1 写集中退出，不扫描场景关系、值来源或独立材料引用。
- `读取完整存在` 的当前路径先读取存在节点及属性槽，再在同一期望代次读取完整属性投影；历史路径以当前代次前后夹取节点历史和历史属性值组。兼容 `读取存在节点` 收敛到完整读取，不再形成第二套存在读取语义。
- 存在服务只消费 L1 正式公开服务，不 import 或调用场景服务，不建立第二仓、第二幂等账、缓存、SQL、日志、重试循环或测试钩子。

### 2.3 场景服务与反向查询

- 场景成员新增 / 替换的存在端点检查改为消费最终完整存在读取，使带固定属性的当前存在继续是合法成员端点。
- 新增 `读取存在当前场景成员引用`：通过 L1 当前目标关系组读取存在被引用的当前场景成员关系，再读取场景端点事实；成功结果按“顺序、场景、关系”稳定排序，并核对全组场景身份与关系身份唯一。
- 反向 DTO 物理定义在存在数据头只用于冻结值式调用合同；存在服务未因此取得场景关系查询或写入职责。

### 2.4 专项验证

- 新建独立 Debug / Release x64、v145、C++20、Unicode、`/utf-8` 专项项目，编译八个正式模块和一个验证入口，不进入主工程或 filters。
- PowerShell 包装把输出和中间目录定向系统临时目录；专项覆盖计划列明的 18 项参数矩阵，并以 `std::barrier`、固定轮数和无 sleep 并发读取检查可接受公开结果形状。
- 本轮新增函数和变量使用中文名；类型名、协议名和人读说明中保留正式 `L1` / `I64` / `U64` 名称。
