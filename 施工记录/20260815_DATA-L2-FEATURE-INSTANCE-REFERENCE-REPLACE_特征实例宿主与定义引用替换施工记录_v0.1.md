## 2. 实际生产修改

### `海中鱼巣/领域/L2特征结构.数据.h`

新增：

- `L2特征实例旧引用退出投影`；
- `L2特征实例引用替换请求`；
- `L2特征实例引用替换结果`；
- `L2特征实例自有关系引用有效(...)`；
- `L2特征实例旧引用退出投影完整(...)`；
- `L2特征实例引用替换请求有效(...)`；
- `L2特征实例引用替换结果::成功()`。

成功谓词要求两条旧关系同代退出、两条当前关系编码与旧关系完全分离、新旧端点对至少一项变化，并保持当前实例完整。

### `海中鱼巣/领域/服务.L2特征结构.ixx`

新增 `L2特征结构服务::替换特征实例引用(...)`。一次特征实例 owner 写集：

```text
建立 实例 -> 新宿主 关系
+ 建立 实例 -> 新定义 关系
+ 退出具名旧宿主关系
+ 退出具名旧定义关系
```

写前以同一守卫读取当前实例、存在身份来源和完整统一特征定义；提交后以首次写入代次读回当前实例及两条旧关系历史事实。实例身份、生命周期和可选当前值逐字段守恒。首次提交与精确重复分账；已确认发布后读回矛盾保留已知变更代次，不伪装为零变化。

同时修正 `形成F2特征实例事实(...)`：当前宿主 / 定义关系必须同 owner、同创建代次，创建不早于实例且不晚于读取截止；不再错误要求替换关系仍等于实例首次创建代次。首次新增行为保持。

补齐现有 L1 写状态到 `L2结构状态` 的 `许可拒绝` 映射，使本入口及复用该映射的特征写入口不再把许可拒绝误报为内部不一致；没有新增状态或改变其它状态数值。

## 4. 施工中问题与处理

1. 发现原设计把全部非成功结果机械写成空变更代次，会掩盖“L1 已确认发布但发布后读回矛盾”的已知变更。先修订设计、计划和索引绑定，再继续施工；公开 ABI 与事务范围未改变。
2. 临时驱动首次因标准头位于 module import 之后触发 MSVC 标准库重复声明，随后因临时 targets 未正确排除生产 `入口.cpp` 触发双 `main`。两项均为验证工程错误，生产根工程当时已双配置通过；修正临时驱动后才运行动态矩阵。
3. 发布前复核发现现有特征写状态映射遗漏 `许可拒绝`；在同一服务白名单内补齐机械映射，并重新执行静态门禁。该修正不改变公开 ABI、写集或完成边界。
