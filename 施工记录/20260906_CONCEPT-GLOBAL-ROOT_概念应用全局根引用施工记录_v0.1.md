## 2. 实际代码变化

三个应用类各自新增私有 inline static 根身份：特征概念根节点、存在概念根节点、动态概念根节点。每类用独立 mutex 保护根身份、实际 provider 地址和活跃实例计数；地址只比较，不解引用。每个实例保存不可变 root_，特征原两处直接读取 provider 根的父根使用点已改为 root_。

构造从已注入数据服务取得对应根，在同一 G 正式读回角色、身份、生命周期和根形态后才绑定。存在、动态删除 root 构造实参；特征签名不变。同 provider 同根共享计数，另一 provider 冲突拒绝，计数溢出 length_error；所有数据调用位于全局锁外。构造绑定是最后一步，前置失败不修改槽。

三个类增加只读 optional 根副本查询；没有实例时为空，不返回可写引用。禁止默认、复制和移动；析构只释放本类引用计数，最后实例清空引用，不退出任何持久根。调用方仍须保证应用先于其借用 provider 析构，同一实例操作不得与其析构并发。

场景成员类继续组合特征与存在应用；不建立场景根，也不新增因果应用。数据服务、L1、世界服务、工程和原概念算法未修改；真实根的持久创建及恢复不在本次实现内。
