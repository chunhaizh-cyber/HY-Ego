## 3. 实际变更

### 3.1 回执和真实工作线程

- 回执协议升级为版本 3，新增显式来源材料版本和任务实际结果写入幂等身份；两项进入完整相等、准入和拒绝分账。
- 新增纯值 `任务工作结果材料`及回执形成结果；无效材料在工作线程内被结构化拒绝，不建立管理上行槽。
- 新增最小物理任务工作线程，只排空已形成工作结果、形成回执并提交任务管理线程，不执行任务方法或生成业务结果。

### 3.2 上行桥和任务管理线程

- 新增唯一任务实际结果上行桥：按回执 G0 读取当前实例方法、取得正式执行轮次、恰一次调用结果发布入口、在 G1 独立读回并只从读回形成治理消息。
- 任务管理线程新增结果上行容量、唯一槽、正式结果身份去重、消息冻结、邮箱提交重试、停止新派发和排空收口。
- 正式结果一旦发布，槽永久进入消息提交阶段；邮箱满只重试同一消息，不回退并重新发布任务结果。
- 不同回执编号或来源任务序号指向同一正式结果时，只复用首次消息槽，不形成第二治理批次或第二后继。

### 3.3 生产运行包、启动和专项

- 新增任务结果生产运行包，固定管理消费者先启动、工作生产者后启动；停止时先停新派发，再排空工作结果与管理上行，最后才允许自我线程停止。
- 普通应用启动删除任务工作线程池、任务管理线程和结果上行排空的五个空桩函数，改为构造、启动和收口唯一运行包；失败继续进入结构化程序运行结果。
- 工程和 filters 各唯一登记三个新模块。
- 治理专项的成功路径从运行包的工作结果入口进入真实物理工作线程；覆盖首次、精确重复、不同来源序号、同轮异义、邮箱满恢复、停止排空、当前性漂移和协议拒绝。

### 4.1 `海中鱼巣.线程.任务结果回执协议`

新增：

- `bool 任务结果回执形成结果::成功() const noexcept`：只判断已形成且存在回执；纯值，无事实读写。
- `任务结果回执形成结果 形成任务结果回执(const 任务工作结果材料&) noexcept`：逐字段准入并机械形成 v3 非权威回执；不读取 DATA、不生成执行轮次。
- `operator==(const 任务工作结果材料&, const 任务工作结果材料&)`：完整纯值相等比较。

修改：

- `bool 任务结果回执材料相同(const 任务结果回执材料&, const 任务结果回执材料&) noexcept`：把来源材料版本和任务实际结果写入幂等身份纳入相等合同。
- `任务结果回执准入结果 复核任务结果回执材料(const 任务结果回执材料&, const 任务结果回执准入上下文&) noexcept`：增加版本 3 两项非零准入及具名拒绝。

待更新用途卡：`知识库/函数用途/任务协议与运行宿主/任务结果回执协议函数组.md`和该目录 README；旧卡的 7 个身份、版本 2 与生产 `NOT_RUN`结论已过期。

### 4.2 `海中鱼巣.线程.上行桥.任务实际结果`

新增：

- `bool 任务结果上行形成结果::成功() const noexcept`：只判断状态已形成且轮次、G1、实例方法、正式结果和治理消息齐全。
- `任务实际结果上行桥::任务实际结果上行桥(L2需求结构服务&, L2任务结构服务&, L2状态结构服务&, L2特征结构服务&, L2存在结构服务&, L2场景结构服务&, L2动态结构服务&) noexcept`：借入正式服务并装配同实例只读组合器；不取得所有权。
- `任务结果上行形成结果 任务实际结果上行桥::发布并形成治理消息(const 任务结果回执材料&, std::uint64_t) noexcept`：按 G0 读取正式实例方法、恰一次发布任务实际结果并转入独立读回。
- `任务结果上行形成结果 任务实际结果上行桥::继续独立读回并形成治理消息(const 任务结果回执材料&, const L2实例方法事实&, const L2任务实际结果事实&, std::uint64_t, std::uint64_t) noexcept`：在 G1 独立读回并确定性形成治理消息。
- `std::uint64_t 任务实际结果上行桥::计算正式结果摘要(const L2任务实际结果事实&, std::uint64_t) noexcept`：形成非权威 FNV-1a 摘要；不替代任何正式身份。

调用边：新增对当前实例方法读取、唯一任务实际结果发布、G1 独立读回的直接调用；结果消息交由任务管理线程提交，不直接调用自我线程。

待新建用途卡：本模块全部稳定身份。

### 4.3 `海中鱼巣.线程.任务管理线程`

新增：

- `任务管理线程::任务管理线程(std::uint64_t, std::uint64_t, std::uint64_t, std::uint64_t, 任务实际结果上行桥&, 自我线程&) noexcept`：建立生产结果上行容量并借入唯一桥和自我线程。

- `std::optional<任务结果上行槽快照> 任务管理线程::读取任务结果上行槽(std::uint64_t) const noexcept`：锁内复制槽快照。
- `任务管理线程操作结果 任务管理线程::请求停止新派发() noexcept`：停止强类型任务请求准入但保持结果上行运行。

- `bool 任务管理线程::结果上行终态(任务结果上行槽阶段) noexcept`：纯值识别终态。
- `bool 任务管理线程::全部结果上行可收口_已锁定() const noexcept`：锁内确认所有槽终态且待处理队列为空。
- `void 任务管理线程::重新排队结果上行_已锁定(任务结果上行内部槽&)`：锁内幂等重新排队。
- `void 任务管理线程::应用上行形成结果_已锁定(任务结果上行内部槽&, const 任务结果上行形成结果&)`：冻结正式身份、轮次、G1、消息和结构化阶段。

修改：

- `任务管理线程::~任务管理线程()`：通知结果条件变量并保证物理线程可收口。
- `任务管理线程操作结果 任务管理线程::启动()`：校验桥 / 自我目标成对存在，启动条件变量驱动的管理线程。
- `任务管理线程操作结果 任务管理线程::请求停止并发送停止消息(std::uint64_t, std::uint64_t)`：兼容旧入口并同时唤醒结果上行循环。
- `任务管理线程操作结果 任务管理线程::收口等待()`：兼容结果排空后的终态收口。

未改变：既有强类型任务执行请求准备、确认、撤销和取出合同仍由原 owner 负责。
