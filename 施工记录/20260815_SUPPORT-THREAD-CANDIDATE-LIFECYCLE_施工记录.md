## 2. 实际生产改动

1. 新建 `海中鱼巣/线程/支持线程候选.数据.h`：唯一声明创建 / 等待 / 回收请求、状态、入口结果和值式见证；传统包含自带依赖，模块 purview 通过 `SUPPORT_THREAD_CANDIDATE_NO_INCLUDES` 只展开正文。
2. 新建真实模块 `海中鱼巣.线程.候选.支持线程`：
   - 导出一个具名 `支持线程入口端口`、仅移动构造且禁止移动赋值 / 复制的 `std::jthread` 租约、三个结构化结果和三个公开函数；
   - 进程级 `(运行代次, 线程逻辑身份)` 墓碑在控制块和物理线程创建之前原子保留，成功、入口故障、回收和析构均不释放；
   - 候选见证 mutex / condition_variable 与生命周期发布串行 mutex 分离，生命周期端口调用不持有见证锁；
   - 物理状态、前态和事件序号在唯一串行区单调推进；投影非接受只累计到租约见证，不反向改变物理结果；
   - 真实入口使用 `GetCurrentThreadId()`，包装捕获全部入口异常并复核未知退出枚举、零故障原因和停止前提前返回；
   - `request_stop()`、停止投影、启动对和终态链按同一生命周期串行器消除交叉；早停只允许完整启动对后停止，或先停止并整体跳过启动对；
   - 回收诊断预算到期后仍等待完成并 `join`；终态后显式回收零新增停止投影、零新增事件序号和零新增未接受计数；
   - 物理线程构造前失败由创建方形成异常终态链；线程一旦形成，后续异常只安全请求停止并连接，由线程包装唯一收束终态；
   - 包装发布最终完成见证时从停止锁存原子同步 `已请求停止`，再发布 `已完成`。
3. `海中鱼巣.vcxproj` 与 `海中鱼巣.vcxproj.filters` 各唯一登记新模块为 `ClCompile`、数据头为 `ClInclude`；四配置 `/utf-8` 保持不变。

未修改 8110 provider、具体事件日志 / 缓存统计 / 持久证据入口、普通应用装配、计划索引或其它所有者 WIP。

## 3. 实施期复审修正

独立源码复审发现并在原计划范围内修正三项实现问题：

1. 控制块构造不再错误标记 `noexcept`；控制块形成期 `bad_alloc` / `system_error` 结构化返回资源失败，已保留身份墓碑不回退。
2. `std::jthread` 构造期与线程已形成后的代码严格分段，禁止创建方在线程形成后重复发布异常终态。
3. 最终完成见证同步读取停止锁存，消除入口已经响应停止而值式见证仍显示未请求停止的并发窗口。

修正不改变冻结公开 ABI、允许文件或机器语义。
