# 真实服务请求材料到 P01 初次筹办流程图 v0.2

```mermaid
flowchart TD
    A[真实服务请求 E + M + D_service + 幂等键] --> B{E/M/D 同一 G0 强类型互证?}
    B -- 否 --> X[结构化非成功\n零写]
    B -- 是 --> C[task owner 读取首次准备记录]
    C -->|同键同请求| D[读回原 P0 / T / R1 / W0]
    C -->|同键异请求或旧记录缺来源| X2[幂等冲突或待迁移\n零写]
    C -->|无记录且无其它当前任务| E[原子建立 T / R1 / P0\n独立读回 W0]
    C -->|已有不同当前任务| X3[已有当前任务\n不建立第二任务]
    D --> F[W0 显式携带 P0 与 R1]
    E --> F
    F --> G[机械规范化为\nL2初次筹办来源 S0]
    G --> H[任务管理登记同一 P01 槽\n形成统一筹办推进请求]
    H -->|工作队列满| H1[保留同一消息重投\n不重建任务/记录]
    H --> I[同一任务工作线程消费一次]
    I --> J[统一筹办 provider\n按 S0 初次分支 fresh 查找/就绪/冻结]
    J --> K{五类唯一结果}
    K --> K1[可执行冻结]
    K --> K2[子目标承接]
    K --> K3[合法等待]
    K --> K4[目标已完成]
    K --> K5[结构化非成功]
    K1 --> L[形成一个结果消息]
    K2 --> L
    K3 --> L
    K4 --> L
    K5 --> L
    L -->|结果队列满| L1[重投同一结果消息\n不得重调 provider]
    L -->|已接收/精确重复| M[管理端把槽排入结果待处理队列]
    M --> N[管理端独立读回正式分支事实]
    N -->|可执行冻结| O[执行冻结请求携带同一个 S0\n完整性复核后进入现有执行队列]
    N -->|其它四类| P[等待或分支收束\n不自动建任务/需求/完成事实]
    O --> Q[本次筹办处理结束]
    P --> Q
```

统一不变量：初次与后继工作都只能由任务工作线程调用筹办 provider，并且每次处理恰好形成一个结果消息交任务管理线程。任务管理线程不得直接调用筹办 provider，不得从线程槽或返回值推断结束；初次`可执行冻结`也必须经过结果消息接收、结果待处理排队和正式事实独立读回，不能绕过消息直接形成执行请求。

P01 消息中的筹办推进请求使用 DATA-L2 `L2任务筹办规范化来源材料`判别联合。初次来源以首次准备记录为来源幂等身份并显式绑定 R1；后继来源保持自己的强类型分支。两个分支不得互相构造或压成裸整数。
