# ARCH-FIVE-LAYER-FOUNDATION 统一虚拟存在、状态、动态原子发布提供者流程图

版本：v0.1
性质：设计合同图，不是当前代码调用图

```mermaid
flowchart TD
    A[ARCH-L4业务provider提交强类型迁移请求] --> B[读取通用虚拟存在与旧当前状态]
    B --> C{同一共同事实截止且引用完整?}
    C -- 否 --> X[结构化非成功: 漂移/拒绝/内部不一致; 零写]
    C -- 是 --> D[形成候选写集]
    D --> E[旧状态退出 + 新状态/当前关系]
    E --> F[动态节点 + 前后状态/主体/来源关系]
    F --> G{所有owner事务确认?}
    G -- 否 --> X
    G -- 是 --> H[ARCH-L1原子发布新事实代次]
    H --> I[按同一截止逐项读回全部写集]
    I --> J{读回完整?}
    J -- 否 --> Y[内部不一致; 停止依赖路径]
    J -- 是 --> K[返回不可变结构化结果]
```

图中业务 provider 只提交已裁决的结构请求；DATA-L2/ARCH-L2 不解释目标达成、方法成功或任务完成。执行入口、DTO 和跨 owner 事务必须以详细设计和代码计划为准。
