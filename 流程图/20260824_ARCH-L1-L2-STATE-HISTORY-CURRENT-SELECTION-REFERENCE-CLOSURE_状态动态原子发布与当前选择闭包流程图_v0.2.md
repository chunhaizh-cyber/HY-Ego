# ARCH-L1-L2-STATE-HISTORY-CURRENT-SELECTION-REFERENCE-CLOSURE

## 状态动态原子发布与当前选择引用闭包流程图 v0.2

> 设计基线：`main@c6e2431e612a13a4e8aa277cd94b31e06a12431c`
> 本图是中性 L1/L2 施工图；不表达任务、方法、需求或结算业务。

### 1. 两参与者原子发布总流程

```mermaid
flowchart TD
    G0[读取共同事实截止 G0<br/>锁定 L1 仓库与幂等账] --> H{请求头、参与者、期望代次与幂等身份合法?}
    H -- 否 --> R0[许可拒绝/资源失败/事实代次漂移/幂等冲突<br/>零载荷、零写、零代次推进]
    H -- 是 --> C[复制候选仓库]
    C --> S[应用状态 owner 候选写集<br/>永久旧状态事实不退出]
    S --> D[应用动态 owner 候选写集<br/>解析前态/后态局部引用]
    D --> N[统一候选事实代次<br/>解析所有跨 owner 稳定身份]
    N --> K[全局当前节点/关系端点引用闭包检查]
    K --> Q{全部当前关系、值、槽和材料引用闭合?}
    Q -- 否: 请求悬空/引用冲突 --> RC[引用冲突<br/>不形成结果账、不交换正式仓库]
    Q -- 否: 候选索引/不变量损坏 --> RI[内部不一致<br/>不形成结果账、不交换正式仓库]
    Q -- 是 --> E[形成结构化成功结果<br/>状态、当前选择、动态证据]
    E --> I[写入跨 owner 幂等账]
    I --> X[交换正式仓库并推进一个事实代次]
    X --> V[交换成功后公开 API 独立读回五组事实]
    V --> V1[状态事实/历史关系仍可读]
    V --> V2[当前选择关系唯一且指向新状态]
    V --> V3[动态前态指向旧状态、后态指向新状态]
    V --> V4[参与者、代次、主体/特征/值一致]
    V --> V5[确认成功：五组事实一致]
    V --> U[读回缺项/混代/未知<br/>已可能发布的内部不一致/发布未知<br/>保留幂等账，允许同键重放]
```

### 2. 状态 owner 先应用、动态 owner 后应用

```mermaid
sequenceDiagram
    participant L1 as L1事实基座
    participant S as 状态owner
    participant D as 动态owner
    participant R as 候选仓库
    L1->>R: 复制 G0 候选
    L1->>S: 应用旧当前选择退出 + 新永久状态 + 新当前选择
    S-->>R: 状态写集与稳定身份
    L1->>D: 应用动态主体、前态关系、后态关系
    D-->>R: 动态写集解析旧/新状态稳定身份
    L1->>R: 代次归一化
    L1->>R: 全局闭包检查
    alt 旧状态事实仍有效且全部端点闭合
        L1->>R: 写幂等账并交换正式仓库
    else 动态前态悬空或其它端点不闭合
        L1-->>S: 引用冲突/内部不一致
        L1-->>D: 引用冲突/内部不一致
        L1->>R: 丢弃候选，不写幂等账，不推进代次
    end
```

### 3. 动态 owner 先应用、状态 owner 后应用

```mermaid
sequenceDiagram
    participant L1 as L1事实基座
    participant D as 动态owner
    participant S as 状态owner
    participant R as 候选仓库
    L1->>R: 复制 G0 候选
    L1->>D: 应用动态前态/后态局部写集
    D-->>R: 保留稳定状态身份引用，暂不交换
    L1->>S: 应用旧选择退出 + 新永久状态 + 新选择
    S-->>R: 完成状态写集并解析局部引用
    L1->>R: 代次归一化与全局闭包检查
    alt 所有关系端点均在最终候选仓库有效
        L1->>R: 写幂等账并交换正式仓库
    else 任一端点在最终候选仓库无效
        L1->>R: 引用冲突/内部不一致，整笔零写
    end
```

### 4. 首态、迁移与当前/历史读取

```mermaid
flowchart LR
    F[现有 新增状态 请求<br/>特征实例 + 状态材料 + G0<br/>当前选择局部写入键/幂等材料] --> FK{局部键非零且引用可互证?}
    FK -- 否 --> FR[具名拒绝<br/>零载荷、零写、零代次]
    FK -- 是 --> FE{已有当前选择?}
    FE -- 同状态且完整材料相等 --> FD[精确重复<br/>返回原状态+原选择<br/>不推进代次]
    FE -- 不同状态 --> FC[已有异义当前/引用冲突<br/>零写]
    FE -- 无当前但有旧事实 --> FM[待迁移<br/>禁止自动补造]
    FE -- 无当前且无旧事实 --> F1[状态 owner 同一 G1<br/>永久状态事实 + 当前选择关系]
    F1 --> F2[形成结果同时返回<br/>完整状态事实 + 选择关系引用]
    F2 --> F3{交换前候选闭包与宿主主体<br/>同截止互证均通过?}
    F3 -- 否 --> FI[事务内内部不一致/资源失败<br/>零写、不推进代次、不写幂等账]
    F3 -- 是 --> FX[写幂等账并交换正式仓库]
    FX --> FR[公开 API 独立读回状态事实+当前选择+宿主主体]
    FR -- 通过 --> FOK[首态确认成功；无动态]
    FR -- 缺项/未知 --> FU[已可能发布的内部不一致/发布未知<br/>不得声称回滚或零写<br/>同幂等键重放收束]
    T[迁移请求<br/>旧选择 + 新状态材料 + G0] --> T1[退出旧当前选择关系]
    T1 --> T2[建立新永久状态事实]
    T2 --> T3[建立新当前选择关系]
    T3 --> T4[动态前态→旧状态<br/>动态后态→新状态]
    T4 --> T5[全局闭包检查后统一交换]
    T5 --> H1[状态身份读取：事实/历史材料]
    T5 --> H2[当前选择读取：唯一当前状态]
    H1 --> M[缺选择关系的旧数据：待迁移<br/>不推断、不写入]
    H2 --> M
```

图中“失败零写”仅适用于正式仓库交换前的候选闭包/互证失败；交换后独立读回是确认与验收，不得声称回滚或零写。“历史可读”不等于继续当前，当前性只由状态 owner 的选择关系表达。
