P14 继续使用 G7、入口变体3、`0x15000F01U`、幂等域 `0x0F` 和既有 L1 v2 合同；P78/P16

## 1. 登记、规格和读取流程

登记、纯值规格和十五项读取的三个根函数流程与 v0.3 完全保持：

```mermaid
flowchart TD
    N00[进入P14统一登记规格读取与组件观察流程] --> N01{选择合同路径}
    N01 -- 登记 --> N02[读取请求合同/规则/幂等身份/期望事实代次]
    N02 --> N03{锁前字段与G7变体3是否合法?}
    N03 -- 否 --> N04[返回入口拒绝；provider/提交0/0]
    N03 -- 是 --> N05[形成HZY-L1G7摘要并探测幂等恰一次]
    N05 --> N06{同义、异义、隔离或未找到?}
    N06 -- 同义 --> N07[返回首次登记幂等读回；0/0]
    N06 -- 异义 --> N08[返回幂等冲突；不形成候选；0/0]
    N06 -- 隔离/未知 --> N09[返回对应拒绝；不形成候选]
    N06 -- 未找到 --> N10[读取非空快照并构造L1 v2十节点事实互证候选]
    N10 --> N11[提交写集恰一次并逐项读回]
    N11 --> N12{十项、类型、代次、互异性一致?}
    N12 -- 否 --> N13[内部不一致并隔离；保留已发布事实；禁止补写]
    N12 -- 是 --> N14[返回结构化登记结果]
    N01 -- 规格 --> N20[读取P13值式结果]
    N20 --> N21{已形成且动态准入允许?}
    N21 -- 否 --> N22[返回无需形成/禁止/非成功；零规格]
    N21 -- 是 --> N23[校验共同截止、P12选择和P11迁移证据]
    N23 --> N24{增加/减少、差异非零、证据完整?}
    N24 -- 否且矛盾 --> N25[返回内部不一致；零规格]
    N24 -- 是 --> N26[形成0x44一节点八值六关系八槽]
    N26 --> N27[返回纯值规格；不调用L1]
    N01 -- 读取 --> N30[读取十五个稳定编码]
    N30 --> N31[按当前/历史入口读回]
    N31 --> N32{角色1—5/9、八槽、来源和生命周期完整?}
    N32 -- 否 --> N33[返回对应非成功；空事实]
    N32 -- 是 --> N34[读取G1并校验共同截止]
    N34 --> N35{G0/G1同代次?}
    N35 -- 否且未重试 --> N30
    N35 -- 否且已重试 --> N36[返回版本漂移；空事实]
    N35 -- 是 --> N37[返回完整状态迁移动能事实]
    N01 -- 组件观察 --> N40[--self-test-exit进入同一海中鱼巣.exe]
    N40 --> N41[顺序390调用运行L1动态专项自检]
    N41 --> N42[运行L1动态自检；结构化返回报告]
    N42 --> N43{未分类异常?}
    N43 -- 是 --> N44[向上送出异常标记与失败数量]
    N43 -- 否 --> N45[向上送出通过/失败与失败数量]
    N44 --> N46[启动边界写逻辑错误日志恰一次]
    N45 --> N47[启动边界写运行日志恰一次]
    N46 --> N47
    N47 --> N48[返回自检单元结果；日志失败不改变机器返回]
    N48 --> N49[统一运行器汇总；正式生产运行期仍无P14调用边]
```

日志固定写入现有 `日志/运行.log`，模块为 `L1-SIMPLIFY-P14-DYNAMIC-SPEC`，入口为
`运行L1动态专项自检`，内容含 S01、结果、28项数量、失败数量、未分类异常和“正式接线/读回
不适用”。只有未分类异常进入现有 `逻辑错误.log`；合法拒绝、重复、漂移和资源失败不被
伪造为逻辑错误。两个日志 API 均为
`bool(std::wstring_view 模块, std::wstring_view 入口, std::wstring_view 内容)`，返回值只表示
观察写入是否成功，不进入机器结果。日志是人读诊断，不能替代结构化结果或 L1 事实。

## 3. 诊断责任与观察范围

32个可执行函数的责任逐项以详细设计 §4 为唯一表；责任备注物理落在各自
`L1动态.数据.h`、`服务.L1动态.ixx`、`自检.L1动态.ixx` 和 `启动.应用程序.ixx` 的函数合同
附近。P14 内部只向上送出，`运行L1动态专项自检` 是当前 P14 自检的唯一本地记录边界；
`运行完整自检模式` 只汇总并向程序顶层送出。不得在锁内日志、不得改日志系统、不得建立
第二自检解释者。

当前没有生产消费者，正式接线和正式读回不进入本图的组件观察路径；后继 P16 必须另行从
自己的新 HEAD 复核真实消费者和服务导向验收。

本图只冻结 v0.4 设计合同，不证明代码、构建、日志已实际产生、正式接线、正式读回、恢复、
跨进程恢复、P16 原子发布或治理闭环完成。
