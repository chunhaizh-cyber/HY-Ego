# ARCH-FIVE-LAYER-FOUNDATION 统一虚拟存在、状态、动态原子发布提供者流程图

版本：v0.3
性质：设计合同图，不是当前代码调用图

```mermaid
flowchart TD
    A[ARCH-L4调用方完成筹办冻结与现实执行授权后提交组合请求] --> B[确认状态 owner 与动态 owner 已由装配建立并各持有效端口]
    B --> C[读取共同事实截止 G0 与主体/旧状态来源；代表节点可随后由结构写入创建]
    C --> D{状态来源、旧当前和输入材料完整?}
    D -- 否 --> X[结构化失败；零写；五组载荷为空]
    D -- 是 --> E[状态服务形成状态参与者写集与六项局部键；节点不等于 owner]
    E --> F{状态参与者已绑定 owner 且 G0 有效?}
    F -- 否 --> X
    F -- 是 --> G[动态服务形成动态参与者；后状态指向状态局部键]
    G --> H{类型化跨 owner 引用/幂等/两 owner 合同有效?}
    H -- 否 --> X
    H -- 是 --> I[L1 候选中同时应用两写集并单次交换发布 G1]
    I --> J{已提交或精确重复?}
    J -- 否 --> X
    J -- 是 --> K[按状态/动态编码映射取得正式身份]
    K --> L[公开服务以 G1 读回新状态、关系、动态、关系与旧历史]
    L --> M{五组均同 G1 且旧退出/新当前/前后关系断言成立?}
    M -- 否 --> Y[内部不一致；停止依赖路径；不重试]
    M -- 是 --> N[返回完整不可变组合结果]
```

状态参与者局部键由状态服务声明，动态后状态关系使用带参与者序号的类型化引用；L1 不接受无位置引用列表。节点引用节点只走关系，标量/文本/材料只走属性槽和值；内部/向外/外来由源/目标节点 owner 对观察者推导，不写入关系属性。owner 与代表节点可先后建立且不要求原子，局部键不得冒充 owner。provider 只复用 owner-aware 节点与源/目标关系组读取，不做全 owner 扫描、递归图读取或内外分类。`想`/`看`、安全否决、资格、配额、现实授权和轮次后继均不在 provider 图内推导，日志不参与机器断言。4015 重签发端口属于恢复后继，不是本图的首次运行前置。
