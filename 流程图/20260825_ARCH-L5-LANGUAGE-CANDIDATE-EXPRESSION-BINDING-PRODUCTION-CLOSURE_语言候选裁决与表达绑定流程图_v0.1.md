# ARCH-L5-LANGUAGE-CANDIDATE-EXPRESSION-BINDING-PRODUCTION-CLOSURE 语言候选裁决与表达绑定流程图

版本：v0.1
状态：设计就绪、等待 L4 代码资源释放；不代表当前代码已接线

```mermaid
flowchart TD
    A[语言候选请求] --> B[正式 L2 语言准备\n新增或精确重复]
    B --> C[按登记键与按身份独立读回\n形成正式语言 G1]
    C --> D{语言双读回闭合?}
    D -- 否 --> F1[语言未找到/漂移/许可/资源\n零 L5 写]
    D -- 是 --> E[按词条读回词条与完整名称关系组]
    E --> F[逐项读回目标概念/对象强类型\n稳定排序候选]
    F --> G{候选完整且预算通过?}
    G -- 否 --> F2[未找到/类型缺失/预算\n值式失败]
    G -- 是 --> H[语言候选裁决业务::裁决]
    H --> I{唯一候选且上下文有效?}
    I -- 否 --> F3[未理解/多义/坏上下文\n不写名称]
    I -- 是 --> J[形成具名裁决证据]
    J --> K[概念名称绑定业务::提交裁决后绑定]
    K --> L[调用 L2 名称关系写入口\n得到 G1]
    L --> M[按名称、按概念、按词条三路 G1 正式读回]
    M --> N{三路一致且当前唯一?}
    N -- 否 --> F4[冲突/漂移/内部不一致\n按 L2 结果分账]
    N -- 是 --> O[自然语言表达业务::形成表达]
    O --> P{绑定、上下文、表达材料完整?}
    P -- 否 --> F5[表达失败\n零事实写]
    P -- 是 --> Q[返回值式自然语言表达\n不创建概念/名称]
```

规则：候选和裁决均不写事实；名称关系写入只发生在具名唯一裁决之后；表达阶段永不写事实。任何进程缓存、词索引首项、字符串默认值、旧语素或对应信息都不得绕过正式 L2 读回。
