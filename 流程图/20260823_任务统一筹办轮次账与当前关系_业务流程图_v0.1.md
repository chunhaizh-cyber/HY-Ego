输入、输出和完成条件：

| 项 | 合同 |
| --- | --- |
| 统一初次输入 | 合法未满足需求、无当前任务、完整初次筹办请求、G0 |
| 实际结果输入 | 任务、路径、实例、实际结果、正式目标裁决、请求 / 幂等 / 运行代次、G0 |
| 统一输出 | 版本 1 权威、唯一当前端点、不可变后继记录、由记录形成的工作包 |
| legacy 输出 | 原正式待重筹办状态和原实例轮次工作包；统一写集为零 |
| 非成功 | 入口拒绝、引用冲突、当前性漂移、触发已消费、资源失败、内部错误 |
| 完成 | 同一任务只命中一个显式分区；统一事务原子，legacy 行为回归不变 |

## 2. 分区与实际结果未达成流程

```mermaid
flowchart TD
    A([实际结果未达成入口]) --> B[按 G0 互证任务、路径、实例、实际结果]
    B --> C[task owner 同 G0 读取权威登记、统一当前关系和后继记录]
    C --> D{显式分区形状}

    D -->|版本 1 权威登记 + 唯一合法当前关系| E[统一轮次权威分区]
    D -->|零权威登记 + 零统一关系 + 零后继记录| F[legacy 实例轮次分区]
    D -->|其它组合| X([内部错误；零写；不 fallback])

    E --> G{实例轮次是否等于当前 N}
    G -->|否| H([当前性或引用冲突；零后继写])
    G -->|是| I[按现有第一段事务登记执行结果待验证首态]
    I --> J[第二段 task owner 取得同一互斥体]
    J --> K[同锁重读版本 1 权威、当前端点 N 和旧业务关系]
    K --> L{统一前提仍成立}
    L -->|否| H
    L -->|是| M[单一 owner 写集]
    M --> N[退出旧当前治理、路径、实例关系]
    M --> O[发布正式待重筹办状态]
    M --> P[创建实际结果触发的 N+1 后继准备记录]
    M --> Q[退出旧统一当前关系并建立 N+1 当前关系]
    N --> R[同一提交 G1]
    O --> R
    P --> R
    Q --> R
    R --> S[按提交结果或准备幂等身份历史读回]
    S --> T[从后继记录取得 N 和 N+1]
    T --> U([返回统一下一筹办工作包])

    F --> V[按现有第一段事务登记执行结果待验证首态]
    V --> W[第二段 task owner 取得同一互斥体]
    W --> Y[同锁重读零权威、零统一关系、零后继记录]
    Y --> Z{legacy 前提仍成立}
    Z -->|否| AA([引用冲突；零 legacy 推进；不切统一分支])
    Z -->|是| AB[执行原 legacy 治理迁移写集]
    AB --> AC[保持旧路径和实例退出、正式状态与原幂等语义]
    AC --> AD[工作包保持实例轮次和实例轮次加一]
    AD --> AE([返回 legacy 下一筹办工作包；零统一写])
```

## 3. 新初次筹办建立统一 population

```mermaid
flowchart TD
    A([合法调用既有初次筹办 provider]) --> B{准备幂等身份是否已有首次结果}
    B -->|旧首次结果且无权威登记| C[返回原首次结果和 legacy 分区]
    C --> D([零补写；不是迁移])
    B -->|无首次结果| E[正式裁决需求未满足且无当前任务]
    E --> F[task owner 单一融合写集]
    F --> G[创建任务、虚拟存在和既有首次准备记录]
    F --> H[创建版本 1 权威登记并引用首次记录]
    F --> I[建立任务指向首次记录的唯一当前关系]
    G --> J[同一 G1]
    H --> J
    I --> J
    J --> K[直接读回首次记录、权威版本和轮次 1 当前端点]
    K --> L([返回统一 population 的轮次 1 工作包])
```

## 4. 唯一统一链与禁止跨区

```mermaid
flowchart LR
    A[版本 1 权威登记] -->|唯一首次锚点| R1[既有首次准备记录：轮次 1]
    T[统一任务] -->|唯一当前关系| C{当前端点}
    C -->|轮次 1| R1
    C -->|轮次 N| RN[后继准备记录 N]
    R2[后继准备记录 2] -->|权威| A
    R2 -->|首次锚点| R1
    R3[后继准备记录 3] -->|直接前驱| R2
    RN -->|逐项回溯| R3
    RN -->|权威| A
```

禁止形状：

```text
统一请求失败 -> fallback legacy
legacy 请求失败 -> 顺手创建权威登记
缺当前关系 -> 猜轮次 1
按创建时间、编码或调用来源 -> 猜 population
统一分支按实例轮次 + 1 -> 产生轮次权威
迁移与 legacy 推进 -> 同任务并发双写
```

## 6. 节点与事务合同

| 节点组 | 输入绑定 | 输出绑定 | 事实读写 | 事务 / 后继条件 | 验证 |
| --- | --- | --- | --- | --- | --- |

## 7. 退役边界

初次筹办生产接线、既有任务具名迁移和 legacy 删除必须由后继独立计划完成。本图只冻结未来迁移必须使用同一 task-owner 锁与 G CAS；它不表示迁移或 legacy 退役已经实现。
