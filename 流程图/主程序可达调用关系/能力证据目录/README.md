# 当前能力证据目录

本目录把 `main` 当前可达代码中的公开业务、组合、仓库和会话入口整理为“当前能力证据”。它回答：

```text
当前代码中有哪些可能供设计复用的实现入口？
这些入口的输入、输出、状态读写、副作用和已知风险是什么？
证据来自哪一个冻结提交、函数身份、调用关系、流程图、规范和验证入口？
```

本目录不回答“某项新业务一定可以复用哪个函数”。复用、组合、适配、扩展或新建的裁决，仍由目标业务设计包逐项比较能力合同后形成。

## 文件

| 文件 | 用途 |
| --- | --- |
| `当前能力证据目录.schema.json` | 机器可读字段、状态和值域合同 |
| `当前能力证据目录.json` | 当前冻结基线下的机器可读能力条目 |
| `当前能力证据目录.md` | 供设计和审查人员阅读的投影 |
| `能力候选队列.json` | 已发布图谱基线下的候选身份、去重关系、状态、覆盖统计和续点 |

## 状态含义

| 状态 | 含义 |
| --- | --- |
| `候选待复核` | 找到 main 可达入口和源码，但单函数图、规范符合或验证证据尚不够完整 |
| `部分实现` | 代码只覆盖能力合同的一部分 |
| `已实现待验证` | 源码、可达关系和当前静态实现证据已形成，但没有足够的运行验收证据 |
| `已验证` | 具名专项验证已在同一代码基线执行并有可回查结果 |
| `接口骨架` | 只有最终接口或显式未实现定义，不具备真实业务能力 |
| `已退出` | 当前代码或正式治理已经退出该入口 |

`已实现待验证` 不等于规范符合、可以复用、已经接入生产、构建通过或业务能力完成。

## 首批选择口径

首批只登记：

1. `main` 当前可达；
2. 能作为业务、组合、仓库或会话入口理解；
3. 可以从冻结源码、函数身份和调用关系形成稳定描述；
4. 有现状单函数流程图时优先采用；
5. 没有图或存在旧结构边界时只登记为 `候选待复核`。

构造函数、简单访问器、运算符、lambda、自检辅助函数和纯内部算法默认不单独登记。它们仍留在函数身份表、调用边表和代码流程图中。

## 设计侧使用方法

```text
业务流程节点
-> 形成所需能力合同
-> 按领域、输入、输出、状态读写搜索本目录
-> 取得一个或多个候选能力
-> 回读冻结源码、正式规范和验证证据
-> 在目标设计包中形成“业务能力复用裁决表”
-> 裁决直接复用 / 组合复用 / 适配 / 扩展 / 新建 / 证据不足
```

目录中的 `复用边界` 只提示风险，不是复用结论。尤其不得因为函数名相似、签名存在、调用图有边或状态为 `已实现待验证` 就直接宣布可复用。

## 增量维护

代码基线变化后：

1. 找出直接修改的函数和文件。
2. 沿调用边向上查找受影响能力根。
3. 将受影响条目标为 `候选待复核`。
4. 重新核对签名、输入输出、状态读写、副作用、事务、错误和验证入口。
5. 只有同基线验证结果存在时才允许进入 `已验证`。
6. 未受影响条目保持能力编号不变。
7. 发布前重新生成条目数和状态统计。

如果函数身份表的内嵌代码事实版本落后于目标提交，必须逐文件证明差异为零，或重新生成调用图后再更新条目；不得把旧调用关系静默写成当前事实。

## 完成边界

本目录只是当前代码能力证据投影：

- 不定义新的机器逻辑；
- 不修改正式规范；
- 不授权代码实施；
- 不修改计划或计划索引；
- 不证明任一候选适合某项新业务；
- 不证明项目整体能力、业务阶段或生产闭环已经完成。
