# INSTINCT-STAGE3-CURRENT-VALUE-CHANGE-LEDGER 特征当前值变化永久账函数流程图 v0.1

日期：2026-08-30

执行期修订：2026-08-30 R3。补齐合法当前值变化及状态 / 动态清理后的本能根恢复路径。

## 1. v2 发布

```mermaid
flowchart TD
    A["接收 v2 当前值变化请求"] --> B{"合同、G0、四幂等身份和材料完整？"}
    B -- "否" --> X1["入口拒绝，零载荷"]
    B -- "是" --> C["读回永久账登记"]
    C --> D{"登记已成立？"}
    D -- "否" --> X2["材料不足，零写"]
    D -- "是" --> E["G0 读取特征旧当前值、主体、场景和来源"]
    E --> F{"新旧值相同？"}
    F -- "是" --> R0["无变化：返回旧当前值，零账零状态零动态"]
    F -- "否" --> G["参与者1：新当前值 + 永久账节点/载荷"]
    G --> H["参与者2：新状态 + 当前选择切换"]
    H --> I["参与者3：状态迁移动能 + 可选动作动态"]
    I --> J["三分区原子提交"]
    J --> K{"提交成功或精确重复？"}
    K -- "否" --> X3["结构化失败；未知提交保留见证"]
    K -- "是" --> L["按四幂等身份读回首次写集与共同 G1"]
    L --> M["独立读回当前值、状态、动态和永久账"]
    M --> N{"逐字段闭合且读后守卫成立？"}
    N -- "否" --> X4["已可能发布；原请求原键重试"]
    N -- "是" --> R1["已提交/精确重复 + 完整账与变化记录"]
```

## 2. 完整组读回

```mermaid
flowchart TD
    A["接收特征 + UTC 半开区间 + 数量预算"] --> B{"请求有效且 G0 读前守卫成立？"}
    B -- "否" --> X1["入口拒绝或当前性漂移"]
    B -- "是" --> C["读回唯一账登记锚点"]
    C --> D{"账已登记？"}
    D -- "否" --> X2["账未登记，禁止合法空集"]
    D -- "是" --> E["按锚点来源完整读取全部当前账载荷"]
    E --> F["逐项验证 owner、节点、值、十字段载荷"]
    F --> G["按四幂等首次写入互证三参与者共同 G1"]
    G --> H{"存在坏项、重复或不闭合？"}
    H -- "是" --> X3["集合不闭合，空载荷"]
    H -- "否" --> I["筛选目标特征与 UTC 区间"]
    I --> J["按 UTC、账身份规范排序"]
    J --> K{"成员数超过预算？"}
    K -- "是" --> X4["数量预算不足，空载荷"]
    K -- "否" --> L["形成成员身份逐项一致的完整见证"]
    L --> M{"G0 读后守卫成立？"}
    M -- "否" --> X5["当前性漂移，空载荷"]
    M -- "是" --> R["已读取：0/N 完整变化组 + 见证 + G0"]
```

## 3. 关系式材料清理兼容

```mermaid
flowchart TD
    A["现有实例材料清理入口"] --> B["按族索引枚举状态 / 动态"]
    B --> C{"旧式载荷还是三分区关系式载荷？"}
    C -- "旧式" --> D["复用原载荷成员与原物理闭包"]
    C -- "关系式动态" --> E["同 G 读取上下文关系并由角色 4/5 恢复前后状态"]
    C -- "关系式状态" --> F["同 G 验证上下文角色 1..4"]
    E --> G["闭包加入全部动态上下文关系"]
    F --> H["闭包加入全部状态上下文关系"]
    D --> I["按 TTL / 总量形成候选"]
    G --> I
    H --> I
    I --> J["逻辑退出完整闭包"]
    J --> K["物理清理完整闭包并形成墓碑"]
    K --> K1["同原幂等身份读取首次写集与首次映射"]
    K1 --> K2{"每项恰命中当前、历史或匹配墓碑之一？"}
    K2 -- "否" --> X1["内部不一致，不得跳过参与者证明"]
    K2 -- "是" --> L["新 G 重新读取永久变化账"]
    L --> M{"账组与清理前逐项相同？"}
    M -- "否" --> X["专项失败，不得把清理冒充完成"]
    M -- "是" --> R["证明永久账不依赖可清理状态 / 动态"]
```

## 4. 本能根重启恢复

```mermaid
flowchart TD
    A["按固定幂等身份恢复根定义与实例"] --> B["同 G 读取根特征当前值"]
    B --> C{"当前值是否已设置？"}
    C -- "否" --> D["冷启动：建立固定首值和初始状态"]
    C -- "是" --> E{"当前值完整、活动、实例一致且位于 0..I64_MAX？"}
    E -- "否" --> X["材料未闭合或引用冲突"]
    E -- "是" --> F["不读取状态或动态代替当前值"]
    D --> G["同 Gfinal 复核根合同、需求和当前值"]
    F --> G
    G --> R["形成已恢复的值式本能根锚点"]
```

## 5. 边界

本图只表达永久变化账的 v2 发布、完整读回、现有清理入口对三分区关系式状态 / 动态和 L1 首次材料墓碑互证的内部兼容，以及根身份对合法当前值变化的恢复兼容。它不新增清理 ABI 或 L1 / 本能根公开 ABI，也不从墓碑恢复完整事实。来源业务解释、主动安全裁决、低位回升、服务维护事务和 `A/V` 写入均不在本图内。
