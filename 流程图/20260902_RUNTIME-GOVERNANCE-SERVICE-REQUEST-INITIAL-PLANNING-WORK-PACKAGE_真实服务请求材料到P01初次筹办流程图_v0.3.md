# 真实服务请求材料到 P01 初次筹办流程图 v0.3

```mermaid
flowchart TD
    A[服务请求 E + M + D_service] --> B[需求初次筹办准备]
    B --> C[task owner 正式形成/读回 T R1 P1]
    C --> D[初次工作包\n含首次记录 任务轮次 来源成员]
    D --> E[初次规范化来源]

    H[下一筹办工作包] --> I[manager 按任务同 G\n读取当前任务与轮次]
    I -->|任务 轮次 G 完整一致| J[后继规范化来源\n显式绑定任务轮次]
    I -->|缺失/漂移/冲突| X[结构化非成功\n零新选择]

    E --> K[P01 统一工作包消息]
    J --> K
    K --> L[任务工作线程消费一个工作包]
    L --> M[统一 provider 恰好调用一次]
    M --> N{五类闭合结果}
    N --> N1[可执行冻结]
    N --> N2[子目标承接]
    N --> N3[合法等待]
    N --> N4[目标已完成]
    N --> N5[结构化非成功]
    N1 --> O[形成一个强类型结果消息]
    N2 --> O
    N3 --> O
    N4 --> O
    N5 --> O
    O --> P{提交任务管理线程}
    P -->|队列满| P1[重投同一结果消息\n不得重调 provider]
    P1 --> P
    P -->|已接收/精确重复| Q[本次筹办处理结束]
    P -->|协议拒绝/同键异义/停止| Y[交接失败\n不得伪装正常结束]
    Q --> R[manager 按消息任务/轮次/G\n独立读回正式事实]
    R -->|可执行冻结| S[形成执行冻结请求]
    R -->|合法等待| T[进入合法等待]
    R -->|其余分支| U[按正式事实收束]
```

统一不变量：`消息.任务轮次 == 来源材料.任务轮次 == task owner 同 G 正式读回任务轮次`。初次和后继只共享一个规范化来源联合、一个工作包端口、一个工作线程处理路径和一个结果端口。结果消息是跨线程定位，不是正式业务事实；任务管理线程不得直接调用筹办 provider。

后继原始工作包保持不变，任务轮次只来自 manager 已有的`按任务读取当前任务与轮次`正式读回。禁止从筹办轮次、执行轮次、线程槽、消息身份或裸整数推断。
