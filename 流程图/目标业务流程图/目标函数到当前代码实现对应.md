## 1. 定位

本表把目标函数设计与当前已发布代码事实连接起来。目标业务流程图规定“应当怎样”，代码流程图和源码冻结事实记录“当前怎样”；本表只裁决对应状态，不把目标设计说成已实现，也不以当前代码反向覆盖规范。

对应状态固定为：

```text
一致：当前函数合同和行为满足目标合同
部分实现：存在合法可复用片段，但未闭合全部目标合同
未实现：当前没有满足目标身份和语义的函数
实现漂移：当前存在相邻入口，但行为顺序、事实来源、职责或错误语义违反目标合同
证据待刷新：源码已进入正式main，但代码图谱或能力目录尚未刷新到该代码基线
```

R1 与 A1 发布后，I1 仍不能自动升级为可执行。至少必须重新核对：

```text

-> 场景树 DTO 字段顺序、optional 形状、当前 / 历史语义和退出闭包
-> 场景服务构造、owner 交付与树结构登记顺序

-> 普通应用六服务 / A1 成员、构造、析构、失败状态与同址关系
```

任一签名、构造、装配、状态、生命周期或资源项漂移，I1 保持未实现 / 待激活并退回计划修订；不得增加别名、直接 getter 旁路、兼容 DTO 或第二根入口临场吸收差异。

## 9. 使用方法

每完成一条目标业务链，按以下顺序追加：

```text
目标函数完整签名
-> 查询能力目录取得候选
-> 回读当前正式源码和代码流程图
-> 比较输入、输出、事实来源、线程、事务、非成功和版本
-> 裁决一致 / 部分实现 / 未实现 / 实现漂移 / 证据待刷新
-> 只对仍隐藏非平凡过程的目标函数继续分解
```

本表不是代码实施许可。代码修订后由代码流程图维护智能体刷新当前事实图谱，再由设计或验收侧复核对应状态；不得直接把“未实现”改成“一致”。
