# 目标业务流程图目录

## 1. 定位

本目录保存 `BIZ-*` 目标业务函数设计图。它把正式逻辑规范逐层转换为可实施的函数调用树；每一张图唯一冻结一个根函数，并最终确认函数规格、物理位置和组合关系。

推导顺序固定为：

```text
正式逻辑规范
-> 高层目标根函数
-> 下一层被调函数
-> 逐层细化函数内部过程
-> 冻结每层函数规格与物理位置
-> 函数组合闭合证明
-> 计划智能体制定并登记实施计划
```

## 2. 与现状代码图的边界

| 身份 | 表达内容 | 维护依据 | 能否证明代码已存在 |
| --- | --- | --- | --- |
| `BIZ-*` | 目标业务应如何成立 | 正式逻辑规范 | 不能 |
| `CODE-*` / `CF-*` | 当前代码实际如何调用 | 已发布源码与静态图谱 | 只能证明静态事实，不能证明运行成功 |

目标业务图不是当前代码图，但必须是一张目标单函数图。每个执行节点只能是具名下一层函数调用，或本根函数内的具体判断、顺序、构造、读写、事务和返回指令。当前函数证据必须标明 `当前复用`、`适配扩展`、`待新增` 或 `待核`，不能用目标函数名证明代码已经存在。

## 3. 分层方法

- L0：一张图冻结唯一项目级总编排函数；图中函数调用节点指向 L1 根函数。
- L1：每张图冻结唯一一级业务编排函数；图中复杂函数调用节点指向 L2 根函数。
- L2 及以下：每张图同样只冻结一个根函数；复杂被调函数继续向下一层展开。
- 最深层：图内只剩下一层已冻结函数调用和本函数内具体指令时停止展开。

每个层级都必须冻结根函数中文名、完整签名、参数、返回结果、物理位置、现有或待新增状态、事实读写、事务和被调函数。高层图必须有正式规范依据；细层图可以由已确认父函数推导，但不得产生规范未覆盖的新机器语义。

禁止只为层级对齐建立无职责包装函数。一个层级只有在根函数独立承担至少一项编排顺序、错误映射、事务、事实截止版本、生命周期或跨能力结果聚合时才成立。

## 5. 使用规则

1. 计划智能体先选定一个 `BIZ-*` 根函数，再沿图中的具名被调函数读取下一层图、映射表和相关正式规范。
2. 映射为 `当前复用` 的函数仍须按当前代码和能力证据重新核对真实签名、生命周期和验证状态。
3. `适配扩展` 与 `待新增` 必须先补齐目标函数图和详细设计，冻结 DTO 字段、错误枚举、事务和版本后才能制定可执行代码计划。
4. `待核` 只表示现状证据不足，不授权执行窗口临场选择接口。
5. 本目录不登记计划状态，也不构成执行许可。

## 6. 参考使用边界

`流程图/鱼巢流程/**` 仅用于检查业务覆盖是否遗漏。旧线程写事实、SQL/日志/UI 承担机器事实、外设报告直接成为世界事实、旧主信息和双路兼容等旧语义不得迁移。
