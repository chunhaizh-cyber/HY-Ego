# 目标业务流程图目录

## 1. 定位

本目录保存 `BIZ-*` 目标业务设计图。它把正式逻辑规范逐层转换为可实施的业务能力边界，最终用于确认目标函数规格、物理位置和组合关系。

推导顺序固定为：

```text
正式逻辑规范
-> 高层目标业务流程图
-> 逐层细化业务节点
-> 业务叶子能力合同
-> 目标函数规格与物理位置
-> 函数组合闭合证明
-> 计划智能体制定并登记实施计划
```

## 2. 与现状代码图的边界

| 身份 | 表达内容 | 维护依据 | 能否证明代码已存在 |
| --- | --- | --- | --- |
| `BIZ-*` | 目标业务应如何成立 | 正式逻辑规范 | 不能 |
| `CODE-*` / `CF-*` | 当前代码实际如何调用 | 已发布源码与静态图谱 | 只能证明静态事实，不能证明运行成功 |

目标业务节点不得写成代码行、局部变量、`if/for/switch` 或当前调用栈。当前函数只能出现在能力映射中，并必须标明 `当前复用`、`适配扩展`、`待新增` 或 `待核`。

## 3. 分层方法

- L0：项目总体业务生命周期，只确认一级业务闭环和业务间依赖。
- L1：每张图只描述一个一级业务闭环，确认输入、输出、事实读写、事务边界和目标函数组。
- L2 及以下：仅在 L1 节点仍不能直接冻结单一函数职责时继续展开；不为形式完整机械制图。
- 叶子节点：必须能够映射为一个公开领域函数，或一组有明确编排者的公开函数；私有机械辅助函数不成为业务节点。

高层图必须有正式规范依据。细层图可以由已确认父节点推导，但不得产生规范未覆盖的新机器语义。

## 5. 使用规则

1. 计划智能体先选定一个 `BIZ-*` 闭环，再读取映射表和相关正式规范。
2. 映射为 `当前复用` 的函数仍须按当前代码和能力证据重新核对真实签名、生命周期和验证状态。
3. `适配扩展` 与 `待新增` 必须先形成 L2 或函数规格设计，冻结 DTO 字段、错误枚举、事务和版本后才能制定可执行代码计划。
4. `待核` 只表示现状证据不足，不授权执行窗口临场选择接口。
5. 本目录不登记计划状态，也不构成执行许可。

## 6. 参考使用边界

`流程图/鱼巢流程/**` 仅用于检查业务覆盖是否遗漏。旧线程写事实、SQL/日志/UI 承担机器事实、外设报告直接成为世界事实、旧主信息和双路兼容等旧语义不得迁移。
