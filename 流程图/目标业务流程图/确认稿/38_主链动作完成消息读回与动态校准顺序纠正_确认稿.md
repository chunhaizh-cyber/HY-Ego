# 第 38 项：主链动作完成、消息、读回与动态校准顺序纠正

状态：已确认设计输入；非正式规范。

当前 `BIZ-MAIN-001` A14 及对应 L2 图存在“根据动作返回先提交状态 / 动态，再发布完成回执”的表达，与已确认第 22 项冲突，后续目标业务图治理必须统一纠正。

主链固定顺序为：

```text
冻结动作前状态与执行身份
-> 调用具体方法动作
-> 动作执行结束
-> 形成不可变预计动作动态
-> 发布动作完成消息
-> 经另一途径验证消息身份与动作绑定
-> 从权威状态所有者重新读取动作后实际状态
-> 比较动作前状态、预计动态和实际状态
-> 形成校准结果
-> 发布能够证明的正式状态动态和动作致变动态
-> 重新比较任务目标
-> 提交任务结果
```

动作执行过程中由合法领域服务产生的实际业务写入可以正常发生，但方法返回对象、动作结果对象和完成消息都不能直接充当任务实际状态。预计动作动态必须在完成消息返回前形成，但它不是正式动态，也不得原地改写成正式动态。

完成消息发布失败时只重发同一消息，不重新执行动作。实际状态无变化时不伪造状态动态；预计与实际不一致时保留校准差异。状态已经改变但动作归因不足时，保留真实状态，动作致变动态保持待补证据，任务不得冒充完成。

后续修订 `BIZ-MAIN-001` A14—A15、`BIZ-L2-004-07/08`、详细设计和施工计划时，必须保持该顺序一致；本确认稿不证明目标图或代码已经完成修订。
