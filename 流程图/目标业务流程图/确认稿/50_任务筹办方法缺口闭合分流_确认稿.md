# 第 50 项：任务筹办方法缺口闭合分流

状态：依据正式材料和用户授权已裁决；非正式规范。

任务筹办的方法缺口后继固定为：

```text
取得结构化方法缺口
-> 是否为本应存在的结构、代码、服务或状态机缺失/损坏
   -> 是：开发诊断并隔离来源路径
-> 是否存在具名事实或材料生产者及重新触发条件
   -> 是：来源任务闭环、观察、外设材料、授权或合法等待
-> 是否已定位既有方法的具体缺口宿主、角色和处理方
   -> 是：能力缺口承接
-> 是否有可证明的因果或方法知识缺口且学习领域是合法处理方
   -> 是：经需求正常准入进入学习闭环
-> 否：无确认路径合法等待
```

无候选方法不得自动建立方法首、学习需求、能力开发任务或通用写入兜底。代码和正式结构缺失不能业务需求化；学习只处理可定位知识缺口。所有分支形成强类型回执，回流后开启新筹办轮次并重新读取当前事实。

后续修订任务筹办目标函数时必须保持单一分流顺序，不允许同一缺口同时建立学习、开发和等待三套后继。本裁决不证明正式目标图、详细设计、计划或代码已经完成修订。
