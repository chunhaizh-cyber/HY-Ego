# 第 43 项：人类服务需求的主链入口与预支连接

状态：已确认设计输入；非正式规范。

人类服务需求必须作为主业务链的明确入口，不得从自我、任务或服务值自行生成。只有由提出者提出、并经 T02 在冻结治理批次内复核后，才可建立服务合同和预支；任务链消费的是已获准入的需求事实。

固定顺序为：

```text
人类提出有效服务需求
-> T02 冻结为治理输入并复核提出者、有效期、法规与生存控制条件
-> 建立唯一服务合同并原子结算 30% 预支
-> 再进入显式需求核算父链回流、正差距确认和任务意图派发
-> 后续任务完成后才经需求结算形成 70% 余款或服务准备补回输入
```

固定边界：

```text
同一来源、同一有效期内只能存在一个服务合同。
合同建立和 30% 预支是独立原子事务；预支不因后续服务无法完成、终止或取消而追回。
服务值、70% 余款和服务准备补回不在合同建立或需求结算时直接写入；需求结算仅形成值式服务结算输入，后续仅由服务—生存维护事务与同秒衰减和安全根回归共同结算。
```

后续修订 `BIZ-MAIN-001` 时，必须补入该人类需求入口及其到 T02、合同建立、父链重判和任务意图的顺序连接。本确认稿不证明目标图、详细设计、计划或代码已经完成修订。
