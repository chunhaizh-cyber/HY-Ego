# 第 31 项：线程生命周期真实事件的身份、顺序与当前投影

状态：已确认设计输入；非正式规范。

每次线程运行必须绑定“逻辑线程身份 + 运行代次”。逻辑线程身份用于跨重启和跨系统线程实例定位同一职责；系统线程 ID 只作当前运行的诊断绑定，不作为稳定身份、业务身份或路由依据。

创建事件由线程创建者生成。线程入口取得运行权后，由线程自身生成启动、运行、等待、恢复、停止请求中、收尾和正常退出等真实事件。线程来不及上报的故障或异常退出，只能由具名管理者在通过 `join`、系统线程状态或等价独立途径确认线程确已退出后补充，不能根据消息超时或日志缺失直接伪造退出事件。

每个生命周期事件至少绑定稳定事件身份、逻辑线程身份、运行代次、前一事件版本、当前版本、发生时间、事件类型和结构化原因。精确重复事件幂等接收；同一事件身份但内容不同属于内部不一致，必须隔离且不得任选一份覆盖。

当前线程投影按逻辑线程身份和运行代次建立。创建、退出、故障和异常退出等已经确认的不可逆事件，不得被迟到的旧运行、等待或恢复事件覆盖。新运行代次可以形成新的当前投影，但不得删除、改写或伪装旧代次已经确认的真实事件。

状态事件先于创建事件到达时，只能保存“来源不完整”的临时投影和实际收到的事件，不得补造创建事件。长时间没有新消息只能形成“状态未知、投影落后或可能失联”候选；必须经另一途径确认后，才能认定线程故障、退出或需要宿主接管。

线程生命周期消息丢失、重复、乱序、投影缺失、投影落后或材料损坏，均不得反向改变线程实际运行、任务状态、需求状态或业务结果。控制面板显示的当前线程状态始终是只读投影，不是线程控制事实。
