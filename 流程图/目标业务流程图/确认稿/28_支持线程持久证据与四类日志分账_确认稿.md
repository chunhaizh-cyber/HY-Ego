# 第 28 项：支持线程、持久证据与四类日志分账

状态：已确认设计输入；非正式规范。

运行期机器事实只以正式内存已发布代次为准。SQL 当前行、日志、缓存、统计、控制面板投影、导出文件、支持线程位置和持久化成功消息均不得成为第二权威。

日志必须按现行 LOG-01 分为四类并隔离：

- 事件日志：记录自我运行过程中观察到或生成、并已由正式结构确认成立的真实事件，形成可选的人读审计观察投影。这里的“真实”约束被记录对象，不把日志副本升级为事件事实源；事件身份、内容和结果仍以其所属领域的正式结构与再次读取为准。事件日志不作为恢复输入，不反写领域结构。
- 运行日志：启动、关闭、装配、材料接收和入口调用等普通运行观察；“成功/失败”文本不构成业务状态。
- 调试日志：只服务具名排查假设和调试切片，默认关闭，可独立启停；开启后的运行不能单独证明并发、性能或实时性。
- 排错日志：本文按用户用语记录；对应 LOG-01 的正式类别“逻辑错误日志”，只在正式结构化错误已经成立后记录最终责任边界的人读诊断。合法等待、未找到、重复、漂移和合同内拒绝不能统一写成排错错误。

四类日志不得混写或复制同一输出制造多个事实来源。机器错误必须先经结构化结果传播，不能只写排错日志后吞掉错误。日志参数求取不得新增业务查询、写入、锁顺序或副作用。任何日志写入失败均不得改变业务结果、事务结果、线程继续条件或验收结论。

事件日志、运行日志、调试日志、排错日志、缓存统计、显示投影及发布后的普通证据追写都属于非权威旁路。失败只能形成旁路降级、待刷新、材料落后或故障状态，不撤销已发布业务事实。

若正式业务合同明确要求“没有可验证写前持久材料不得发布”，则该准备属于业务事务发布前门禁，不是可忽略旁路：先准备并验证持久候选，成功后才继续内存候选；失败时零内存事实发布。支持线程不得把它降级为稍后补写。

内存事实发布后的持久状态至少区分已一致、待持久化、结果未知、证据落后、证据损坏和不适用；这些状态绑定内存代次、事务或幂等身份及后继责任，但不改变业务代次。SQL 不得在内存未找到、漂移、许可拒绝、内部不一致、缓存未命中或入口未实现时回源补判成功。

支持线程启动按合同分级：可选日志或统计旁路失败允许结构化降级；当前业务合同要求的持久证据端口未就绪时，相关普通业务写入口保持关闭。停止时冻结各线程接受截止并尽力刷新，未刷新材料形成具名剩余、持久化未知或接管责任；刷新失败不否定已完成业务事实，但最终程序结果必须报告旁路降级。

恢复只能从隔离持久材料建立候选，完整验证后原子发布新内存代次；恢复完成后 SQL 立即退回非权威证据身份，不持续覆盖运行期事实。
