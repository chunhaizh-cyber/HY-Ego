# 第 41 项：外设报告承接后的主链分流纠正

状态：已确认设计输入；非正式规范。

当前 `BIZ-MAIN-001` P02 把“已承接外设材料或结构化缺口”统一连接到 A06“建立或复用需求任务树”，容易让 T03 因任意外设报告直接创建任务。后续目标业务图治理必须改为互斥分流。

固定主链为：

```text
T06 发布强类型外设报告
-> T03 按稳定报告身份取得唯一消费责任
-> 匹配当前任务、等待项或订阅项
   -> 命中既有任务 / 工作项：绑定材料引用，唤醒原任务重新裁决工作阶段
   -> 不可舍弃但无匹配项：形成结构化事实或能力缺口，交 T02 下一治理批次复核
   -> 普通过期、重复或无命中材料：按正式策略舍弃或保留摘要
```

命中既有任务时，不重新建立任务树，只恢复或推进原任务。T03 不得根据无匹配报告自行创建需求或任务。

T02 收到结构化缺口后仍须重新读取正式材料、当前正差距和准入条件；缺口消息本身不等于需求候选已经通过，更不等于正式需求或任务。

报告需要形成世界事实时，只能由已绑定工作项调用合法领域方法，再由事实所有者提交并独立读回。报告、承接结果和队列状态都不是世界事实。

同一报告稳定身份继续保持跨任务、窗口、线程和运行代次最多正式承接一次。

后续修订 `BIZ-MAIN-001` P01—P02、对应 T03 / 6340 图、详细设计和施工计划时，必须删除 P02 无条件连接 A06 的表达；本确认稿不证明目标图或代码已经完成修订。
