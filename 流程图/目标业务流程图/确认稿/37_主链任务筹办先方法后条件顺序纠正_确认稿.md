# 第 37 项：主链任务筹办先方法、后条件顺序纠正

状态：已确认设计输入；非正式规范。

当前 `BIZ-MAIN-001` 的 A11 节点及验证点把任务筹办写成“先反推条件，再召回方法”，与已确认第 21 项冲突，后续目标业务图治理必须统一纠正，不保留相反表述。

每轮任务筹办的固定主链顺序为：

```text
读取任务目标
-> 按目标结果能力查找候选方法
-> 核对方法登记、生命周期和结果规格
-> 根据每个候选方法读取其所需条件
-> 将条件绑定当前事实、输入和参数
-> 复核权限、风险、禁止项和动作入口
-> 排除不可用候选
-> 排序并冻结本轮方法候选
```

因果信息可以帮助定位可能的方法，但不能越过“先得到候选方法”直接决定条件。零候选方法时形成能力缺口或合法等待，不继续凭空寻找条件；存在候选但条件不满足时，才进入补条件、等待、子任务或下一轮筹办。

每一轮筹办都必须重新从按目标结果能力查找方法开始，不继承上一轮的候选当前性、条件满足结论或就绪判断。

后续修订 `BIZ-MAIN-001`、A11 对应目标函数图、详细设计和施工计划时，必须保持该顺序一致；本确认稿本身不证明目标图已经修订或代码已经实现。
