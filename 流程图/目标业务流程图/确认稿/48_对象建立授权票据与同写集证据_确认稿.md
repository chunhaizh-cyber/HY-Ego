# 第 48 项：对象建立值式授权准入与原子发布

状态：原“对象与授权证据节点同写集”口径已被认知证据边界替代；本稿是已确认设计输入，不是正式规范。

项目范围内对象的首次建立流程固定为：

```text
目标对象事实所有者提交完整建立意图
-> 项目事实范围授权服务复核范围、资格规则、对象类型、事实所有者、幂等键和当前事实代次
-> 拒绝则零写入返回具名结果
-> 接受则返回不可伪造、单次消费的未发布值式授权票据
-> 目标对象事实所有者在目标事务准入时消费票据
-> 形成目标对象及其成立所必需的完整初始业务事实写集
-> L1 在同一事实代次原子发布目标对象及必要初始事实
-> 按新稳定编码读回目标对象及必要初始事实
```

未发布授权票据必须绑定授权服务、项目范围、资格规则、对象业务类型、目标事实所有者、完整建立意图、写集幂等键、目标写集本地键和授权时事实代次。事实代次漂移后票据失效；不得按墙上时间续期，也不得把票据持久化为第二权威或认知事实。

目标写集不得仅为事后证明票据或授权过程而建立授权证据节点、证明关系或同义审计事实。若某项资格 / 授权结果对后继业务具有独立作用、独立生命周期和合法消费者，只能由其正式治理 owner 按强类型合同发布；没有独立业务作用时零授权持久事实。它即使发布也是治理事实，不是认知证据。

授权接受不等于对象已经发布。发布结果未知只能按原幂等键和原写集收敛；G0 / G1、事务、幂等账、发布读回和恢复材料留在所属工程边界，不进入对象、世界或认知事实平面。后续目标函数图不得画成“先建立对象、以后补授权”，也不得让 G01、L1 或普通调用方签发首次建立授权。
