# 第 39 项：任务结果到需求结算的跨线程交接纠正

状态：已确认设计输入；非正式规范。

当前 `BIZ-MAIN-001` A16 把 T03 上行内容写成“实际结果、父等待变化和需求满足证据”，会让任务管理线程提前拥有需求满足判断，与已确认第 23 项冲突，后续目标业务图治理必须统一纠正。

主链固定顺序为：

```text
T03 独立读取实际状态
-> 任务领域发布正式任务结果
-> T03 独立读回任务结果
-> 向 T02 发布任务结果定位消息
-> T02 在新治理批次重新读取正式任务结果
-> T02 重新读取来源需求、目标合同和当前状态
-> 需求领域独立裁决并发布需求结算
-> 需求结算读回成功后，才形成可选服务结算输入
```

T03 上行消息只携带任务结果身份、正式版本和必要的路由身份，不复制实际状态，也不携带“需求已满足”结论。父任务等待变化属于任务领域，可由 T03 在任务树内部重判，不能冒充父需求或来源需求结论。

任务完成不等于需求满足，任务未完成也不允许 T02 根据消息摘要直接判断需求失败。T02 必须重新读取任务结果、需求和当前目标状态，不能直接消费消息中的预计结果或实际状态副本。

只有需求领域正式发布并读回“需求已满足”，才可形成服务合同终态输入或服务准备完成输入。

后续修订 `BIZ-MAIN-001` A16、对应 L2 / L3 图、详细设计和施工计划时，应删除“需求满足证据”上报，改为正式任务结果定位消息；本确认稿不证明目标图或代码已经完成修订。
