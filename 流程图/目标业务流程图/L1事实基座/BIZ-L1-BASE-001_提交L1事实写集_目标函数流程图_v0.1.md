# BIZ-L1-BASE-001 提交L1事实写集目标函数流程图 v0.1

状态：目标业务流程图；当前复用发布源码中的
`L1中性写入结果 L1事实基座服务::提交中性写集(const L1中性写集请求& 请求)`，冻结其业务中性原子提交闭环。

正式依据：当前发布规范 4015；冻结发布提交 `047859f555afd45c70182929403dee78b6506bc4`。

发布源码证据：

- `海中鱼巣/核心/服务.L1事实基座.ixx`，blob `bc28af783286708afedaa0fed79b44c24912b9fe`：公开服务先校验合同版本，再调用同实例仓库。
- `海中鱼巣/核心/仓库.L1事实基座.ixx`，blob `651b314ae8fd7d63c3bbc20a82d9518d54f087b9`：规范化、幂等、候选、最后发布、发布后读回与隔离的唯一实现。

输入：期望事实代次、幂等键、节点 / 关系 / 值新建项、属性槽变更和退出项。

输出：结构化 `L1中性写入结果`。成功返回新发布事实代次及本地键—稳定编码映射；精确重复回显首次结果且不再次发布；其它状态不交付部分候选。发布后精确读回矛盾是唯一“已经发布但返回内部不一致”的形状，并使仓库进入隔离。

```mermaid
flowchart TD
    A["服务接收不可变 L1 中性写集"] --> B{"合同版本正确？"}
    B -- 否 --> R1["入口拒绝；零候选、零发布"]
    B -- 是 --> C["仓库规范化请求并校验非空写集、非零幂等键、局部键与五类写项形状"]
    C --> D{"规范化与请求结构有效？"}
    D -- 否 --> R1
    D -- 是 --> E["取得仓库独占锁并检查隔离状态与仓库完整性"]
    E --> F{"仓库可继续提交？"}
    F -- 否 --> R2["内部不一致；零候选、零发布，按原幂等键读回收敛"]
    F -- 是 --> G["解析调用入口绑定的内部结构所有者分区"]
    G --> H{"同所有者域、同幂等键已有首次记录？"}
    H -- 同规范化写集 --> R3["返回精确重复的首次结果；本次不发布"]
    H -- 异规范化写集 --> R4["幂等冲突；零候选、零发布"]
    H -- 无记录 --> I{"期望事实代次等于锁内当前代次？"}
    I -- 否 --> R5["事实代次漂移；零候选、零发布"]
    I -- 是 --> J["校验逐项所有者、稳定引用、退出集合和当前引用闭包"]
    J --> K{"所有权、引用与退出闭包成立？"}
    K -- 否 --> R6["按入口拒绝、未找到、已退出、引用冲突或内部不一致返回；零发布"]
    K -- 是 --> L["复制完整仓库为候选，分配永久稳定编码并确定新事实代次"]
    L --> M["仅在候选中建立节点、关系和值，应用退出与属性槽替换并同步派生索引"]
    M --> N{"候选按规范化写集、编码映射、所有者和新代次完整读回？"}
    N -- 否 --> R7["丢弃候选并返回结构化拒绝；正式仓库零变化"]
    N -- 是 --> O["把首次成功结果和完整规范化写集写入候选幂等账"]
    O --> P{"候选整体不变量完整？"}
    P -- 否 --> R2
    P -- 是 --> Q["以一次 swap 最后发布完整候选"]
    Q --> S{"按同写集、映射、所有者和新代次发布后精确读回？"}
    S -- 否 --> R8["锁存仓库隔离；返回内部不一致、已发布新代次与已形成发布见证"]
    S -- 是 --> R9["返回成功、新事实代次、发布见证和确定编码映射"]
    C -. 分配或长度异常 .-> R10["资源失败；未发布时零部分载荷"]
    M -. 未知内部异常 .-> R11["内部不一致；未发布时零部分载荷"]
```

节点约束：`L—P` 只操作候选副本；运行期当前事实只能在 `Q` 后可见。幂等裁决固定早于事实代次漂移。关系引用节点；普通属性只通过节点属性槽引用值；节点关系成员不得复制进属性槽或子节点表。所有请求可归因拒绝、资源失败和交换前内部错误都不发布半结构。

完成边界：该图证明发布源码已实现 v1 legacy 中性提交闭环，不证明上层结构可以绕过各自 DATA-L2 强类型 owner 直接使用 v1 写入，也不证明 owner-scoped v2、跨 owner 事务或任一业务闭环已经完成。
