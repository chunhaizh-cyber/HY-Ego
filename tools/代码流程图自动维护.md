# 代码流程图自动维护入口

`维护代码流程图.py` 用于在源码、工程配置或正式图谱输入变化后，自动生成一份不可覆盖的增量维护候选。它不会修改 `流程图/代码流程图/**` 或 `流程图/主程序可达调用关系/**` 的正式材料。

## 使用

```powershell
python tools/维护代码流程图.py --模式 event
python tools/维护代码流程图.py --模式 daily
python tools/维护代码流程图.py --模式 full
python tools/维护代码流程图.py --self-test
```

三个模式的区别：

| 模式 | 调用者影响闭包 | 图谱端点检查 | 适用时机 |
| --- | ---: | --- | --- |
| `event` | 1 层 | 否 | 单次源码保存或代码提交后的快速候选 |
| `daily` | 4 层 | 是 | 日常维护批次 |
| `full` | 全部入向闭包 | 是 | 正式图谱发布前的完整影响扫描 |

运行状态默认写入 `.codex/运行状态/代码流程图自动维护/`，该路径不进入 Git。每个成功或失败批次都是新目录；已有批次永不覆盖。相同输入和相同分析结果只返回原候选路径，不重复生成。

## 自动形成的信息

每个候选批次包含：

- 相对正式 `code_commit` 的新增、修改、删除源码和工程配置；
- 精确落在已登记函数源码范围内的直接影响函数；
- 按项目调用边向入口传播的调用者影响闭包；
- 已制图但需要复核的函数与原图、逐行映射路径；
- 尚未制图或尚无稳定函数身份的新增候选；
- 因源码删除而需要复核退出条件的函数候选；
- `.cpp` 与 `.ixx` 对应的 Clang/MSVC AST 候选扫描入口；
- `daily/full` 模式下的悬空调用边和队列集合问题。

## 保护边界

工具在运行开始和候选发布前各计算一次输入身份，身份由正式代码基线、观察路径内容哈希、维护工具与配置哈希和四份正式图谱输入哈希共同组成；当前提交只作为追溯标签，不让无关文档提交制造重复候选。相关输入中途发生变化时，结果进入不可覆盖的失败批次，并返回 `INPUT-DRIFT`。

同一时刻只允许一个实例持有本地维护租约。异常退出不会修改正式图谱；若进程被强制终止并留下租约，必须先核对租约中的进程和现场，不得自动删除。

自动结果只属于机器候选。AST、行范围和调用边可以帮助定位，但 Mermaid 节点语义、逐行行为解释、非成功分类、稳定身份和调用分派仍需流程图与知识图谱维护智能体读取当前源码后复核。候选生成成功不等于正式图谱已更新，也不等于能力完成。
