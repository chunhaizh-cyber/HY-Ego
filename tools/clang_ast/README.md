# Clang AST / MSVC 模块候选流程图工具

本目录是开发期只读分析工具，不属于 `海中鱼巣.vcxproj`，不修改生产代码、正式规范、计划索引或正式知识图谱。

工具链分为四层：

```text
MSVC /scanDependencies
-> 冻结 .ixx 模块提供 / 需求关系和拓扑顺序
-> Clang 按顺序建立独立 PCM
-> Clang AST JSON 抽取 .ixx 函数、调用和语句级候选
-> PowerShell 生成仓库外 Markdown 草稿
```

所有输出均是候选证据，脚本强制只写系统临时目录；相对输出路径也解析到系统临时目录。只有编译参数、提交基线、模块闭包和诊断经过核对，并由计划智能体逐函数读取源码、完成稳定身份对齐和规范裁决后，才可以更新正式 `流程图/代码流程图/`。

## 1. 构建候选抽取器

构建目录默认位于系统临时目录：

```powershell
.\tools\clang_ast\构建.候选流程图工具.ps1
```

默认工具路径：

```text
%TEMP%\海中鱼巣-clang-ast-build\提取_候选流程图.exe
```

## 2. 扫描 MSVC 模块依赖

扫描当前配置中实际参与构建的全部 `.ixx`，输出默认位于系统临时目录。工程中 `ExcludedFromBuild=true` 且当前条件成立的文件不会被伪报为扫描失败：

```powershell
.\tools\clang_ast\扫描.MSVC模块依赖.ps1 `
  -配置 Debug `
  -平台 x64
```

也可以先验证两个具名文件：

```powershell
.\tools\clang_ast\扫描.MSVC模块依赖.ps1 `
  -源文件 '海中鱼巣\适配\协议.D455采样材料.ixx', `
            '海中鱼巣\线程\缓存.D455帧材料.ixx' `
  -输出路径 "$env:TEMP\海中鱼巣-D455模块依赖.json"
```

输出包含：

```text
模块逻辑名
提供模块的 .ixx
直接 import 需求
拓扑顺序
循环模块
当前仓库内无提供者的外部模块需求
每个文件的 MSVC 诊断
```

扫描只运行编译器依赖扫描，不生成生产对象或正式 IFC；中间材料位于独立临时目录并在结束后删除。

## 3. 抽取 `.ixx` 候选流程图

以模块依赖 JSON 为输入。指定目标模块时会自动建立其仓库内依赖闭包：

```powershell
.\tools\clang_ast\扫描.Clang模块候选流程图.ps1 `
  -模块依赖路径 "$env:TEMP\海中鱼巣-D455模块依赖.json" `
  -目标模块 '海中鱼巣.线程.缓存.D455帧材料' `
  -输出路径 "$env:TEMP\海中鱼巣-D455候选流程图.json"
```

Clang PCM、AST JSON 与单文件中间 JSON 都写入独立临时目录。MSVC `.ifc` 与 Clang `.pcm` 不兼容，本工具不会尝试混用。libclang C Index 当前不暴露命名模块接口中的函数定义，因此 `.ixx` 使用 `clang -ast-dump=json`；普通 `.cpp` 继续使用 libclang。

一次可以传入多个目标模块；工具会合并它们的依赖闭包，只为仍被其它目标或依赖项消费的模块建立 PCM，避免重复预编译顶层目标。每个模块只传入其直接依赖 PCM，减少大批次参数量。

Clang 与 MSVC 对跨命名模块声明归属的兼容性并不完全一致。例如，一个类在模块 A 前置声明、在模块 B 定义的代码可能被 MSVC 接受，却被 Clang 以“definition follows declaration in another module”拒绝。工具不会把这类失败误报成项目代码错误，也不会让一个不兼容闭包吞掉同批其它独立目标：

- PCM失败和后继不可用模块写入 `pcm_builds`。
- 每个目标分别写入 `成功 / 存在诊断 / 依赖PCM不可用 / AST导出失败 / AST候选转换失败`。
- 混合批次保留已成功目标并标记顶层 `部分成功`，同时以非零退出提醒人工复核。
- 失败或部分成功 JSON 仍保留在指定输出路径，可据此拆小批次；不得把 Clang 模块兼容性失败直接裁决为正式接口漂移。

候选 JSON 记录：

```text
函数 USR、名称、签名、参数和返回类型
函数与语句源码范围
条件、循环、返回、调用、异常和表达式候选节点
直接调用候选
无法唯一解析的调用
Clang 诊断
```

## 4. 扫描普通 `.cpp`

```powershell
.\tools\clang_ast\批量扫描.Cpp候选流程图.ps1 `
  -源文件 '海中鱼巣\界面\控制面板窗口.cpp'
```

省略 `-源文件` 时扫描当前配置中实际参与构建的全部 `.cpp`，不扫描 `.ixx`。`成功`表示没有错误级诊断；`存在诊断`表示仍生成了候选但当前编译参数或Clang兼容层存在错误，不能把这些候选当成完整调用事实；`解析失败`表示没有可用翻译单元。

## 5. 生成仓库外 Markdown 草稿

```powershell
.\tools\clang_ast\生成.候选流程图草稿.ps1 `
  -候选JSON "$env:TEMP\海中鱼巣-D455候选流程图.json" `
  -最多函数 5
```

草稿是 AST 父子结构视图，不是已经裁决的控制流。正式化时仍须：

1. 与正式函数 `Fxxxx` 身份对齐。
2. 逐行覆盖全部有效源码。
3. 把节点裁决为具名函数调用或本函数内具体指令。
4. 拆开真实分支、短路、循环回边和资源释放路径。
5. 核对输入、返回、所有权、生命周期、事务和异常。
6. 对照正式规范记录符合、证据不足或偏差。

## 禁止边界

- 禁止把候选输出写入 `流程图/代码流程图/`。
- 禁止把 AST USR 当成正式 `Fxxxx` 身份。
- 禁止把动态调用、函数指针、回调或虚调用猜成唯一目标。
- 禁止把解析成功、PCM生成成功、流程图草稿数量写成机器能力完成。
- 禁止把不同提交或不同编译配置的候选合并成同一当前状态。
