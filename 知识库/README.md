# 海中鱼巣代码知识库

本目录保存帮助设计者、实施者和维护者理解当前代码、查找既有能力、判断函数合法用途并形成复用裁决的工程知识。

知识库是绑定 Git 代码基线的工程知识投影，不产生机器事实，也不替代正式规范、详细设计、计划或当前代码。某条知识与当前代码不一致时，以正式规范和当前代码为准，并把知识条目标记为待复核或过期。

## 2. 权威边界

使用知识时按下列顺序裁决冲突：

```text
用户本轮明确目标
-> AGENTS.md 与 .codex/rules
-> 规范/规范目录.md 登记的正式规范
-> 有效流程图、详细设计和现行计划
-> 当前代码与 Git
-> 本知识库
-> README、日志、界面、记录和聊天
```

知识库中的“用途”“候选能力”“已实现待验证”等文字，只说明某一冻结代码基线上的工程理解或证据状态，不自动证明：

- 当前代码仍与该条目一致；
- 目标业务可以直接复用该函数；
- 函数符合全部正式规范；
- 构建、运行、集成或业务闭环已经完成；
- 缺少知识条目的函数不存在或不可使用。

## 3. 目录结构

```text
知识库/
├─ README.md
├─ 代码编写与既有函数复用知识.md
├─ 代码证据导航.md
├─ 当前代码知识状态.md
└─ 函数用途/
   ├─ README.md
   ├─ 当前生产源码覆盖账.md
   └─ 后续按稳定函数身份形成的用途卡或聚合索引
```

能力证据目录继续回答“已有哪类候选能力”，代码流程图继续回答“函数怎样执行和调用”。本目录的函数用途知识回答“某个函数负责什么、不负责什么、在什么条件下可以合法调用”。三者分账维护，不相互冒充。

## 4. 当前性规则

每份函数用途知识必须绑定至少一个可定位的 Git 提交或源码 blob。使用时先比较该基线与当前目标代码：

- 目标函数及其合同、直接调用者、直接被调者均无变化，才可以继续把条目作为当前候选证据；
- 任一相关内容发生变化，条目降为“待复核”；
- 已确认条目描述与当前代码冲突，标记“过期”，不得继续据此写代码；
- 尚未形成用途卡时，直接读取当前源码、调用点、正式规范和有效设计，不得凭名称或记忆补造用途。

## 5. 写入与更新

代码实施结果应提供新增、修改、退出函数的知识变更材料，包括稳定函数身份、签名、文件、用途变化、调用边变化、正式依据和验证状态。共享用途卡及聚合索引由取得该知识切片所有权的维护者基于已发布代码更新，不能把未提交 WIP 或计划目标写成当前实现事实。

当前完整度和已知滞后统一记录在 [当前代码知识状态.md](当前代码知识状态.md)，不得仅根据本 README 宣称知识库已经覆盖全部函数。
