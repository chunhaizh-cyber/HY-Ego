# 代码知识库

本目录保存可复核的代码用途知识和使用方法。它是绑定代码基线的工程投影，不定义机器语义，不授予施工权限，也不证明构建、运行、恢复、集成验收或业务闭环已经完成。

## 1. 当前入口

| 文件 | 用途 |
| --- | --- |
| [代码编写与既有函数复用知识.md](代码编写与既有函数复用知识.md) | 查找、复核和复用现行函数的统一方法 |
| [代码证据导航.md](代码证据导航.md) | 按问题选择正式规范、当前源码、计划、验证或知识入口 |
| [当前代码知识状态.md](当前代码知识状态.md) | 当前知识是否覆盖现行头源代码及已知缺口 |
| [函数用途/README.md](函数用途/README.md) | 剩余用途卡的候选性质和使用门禁 |

## 2. 当前状态

本次治理前既有的能力证据目录、主程序可达调用关系、知识图谱、代码流程图、逐行映射和候选队列已经全量退出。历史施工计划、施工记录，以及绑定旧模块路径、旧模块行号或已删除施工记录的函数用途卡已经删除。

剩余用途卡只可作为查找候选。使用者必须直接回读现行 `.h/.cpp`、工程登记、生产调用点和正式合同；不得用用途卡、旧函数名、Git 历史或记忆替代当前代码核对。

## 3. 权威边界

- 机器语义、DTO、所有权、事务和生命周期读取 `规范/规范目录.md` 及其登记规范；
- 当前复杂代码施工资格和范围读取 `计划/计划索引.md` 与目标计划；
- 当前实现事实读取现行源码、工程登记和生产调用点；
- 目标业务需求读取 `流程图/目标业务流程图/`，但目标图不证明代码已经实现；
- 具名验证读取 `验证记录/` 和 `验证记录/集成验收/`，并核对代码基线与覆盖范围；
- Git 历史只用于追溯，不直接产生当前实现事实或施工许可。

## 4. 当前性规则

每份用途卡必须绑定可定位的现行文件和代码基线。使用时：

1. 文件、函数、DTO、直接调用者和直接被调者均未变化，才可继续作为候选证据；
2. 任一相关内容变化，立即降为待复核；
3. 卡内路径不存在、仍使用旧模块承载或与当前代码冲突时，直接删除或标记过期，不得迁移旧结论；
4. 没有用途卡时，直接读取当前源码、调用点、正式规范和有效设计，不得凭名称补造用途。

## 5. 写入与重建

代码结果应提供新增、修改、退出函数的知识变更清单。共享用途卡和后续辅助投影只能基于已发布代码更新；不得把未提交 WIP、计划目标或目标流程写成当前实现。

重新建立能力目录、知识图谱或代码流程图时，必须从现行 `.h/.cpp` 和工程登记机械枚举，并绑定明确冻结提交。完整门禁见 [当前代码知识状态.md](当前代码知识状态.md)。
