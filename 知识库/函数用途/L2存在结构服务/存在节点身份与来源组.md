## 1. `新增存在节点`

### 用途、输入和输出

`新增存在节点`在唯一存在 owner 内原子建立一个普通存在节点及其“存在族归属”关系。它是建立无固定属性普通存在身份的基础写入口，不要求调用方预先提供节点稳定编码；稳定编码由 L1 owner-scoped 写集产生并在返回前正式读回。

输入 `L2存在节点新增请求` 只包含：

- `请求头`：必须满足 L2 结构合同版本与事实代次形状；其`期望事实代次`原样传给 L1 写集。
- `幂等身份`：必须是有效的 L2 结构幂等身份，且不得占用存在身份来源登记的保留幂等身份。

输出 `L2存在节点写入结果` 包含 `L2结构结果头` 和可选 `L2存在事实`。只有 `已提交`或`精确重复`的完整成功形状才可作为写入成功；返回的存在事实包含新存在身份、生命周期和空固定属性组。入口还核对 L1 合同版本、owner、幂等身份、首次发布 / 精确重复重试边界、节点读回及同次历史身份来源，任何矛盾映射为结构化非成功且不携带可冒充成功的存在载荷。

### 事实、事务、幂等和生命周期

- 一份 owner-scoped 写集必含一个`节点种类::普通`节点和一条“存在节点 -> 存在族锚点”的族归属关系；两项同事务提交。
- 首次成功必须形成内存权威发布；精确重复不得形成第二次发布，并通过原幂等身份读回收敛。相同幂等身份的异义请求由底层幂等域拒绝。
- 提交成功后先按节点稳定编码读取 L1 历史节点事实，再以写入事实代次读取存在身份来源，互证节点和族归属关系均在同一代建立。
- 本入口只创建初始活跃生命周期，不建立固定属性、场景成员、单例角色、业务资格或名称。

### 合法调用与当前调用点

合法调用者是通过普通应用上下文或`L2结构聚合服务`取得同一 `L2存在结构服务` 实例、并确实需要建立普通存在身份的上层结构 / 业务编排。调用方不得直达 L1 复制节点与族归属写集，也不得自选第二 owner。

在绑定提交上未发现本函数的外部生产调用点。E1 的生产外专项证明了具名新增 / 重复 / 读取矩阵，不等于普通应用或业务入口已经真实调用。

## 2. `读取存在身份来源`

### 用途、输入和输出

`读取存在身份来源`证明一个稳定编码在指定截止属于当前唯一存在 owner 和存在节点族。它是其它 L2 结构验证“这个端点确实是存在身份”的正式公开边界，不能由节点名称、调用方缓存、普通 L1 节点读取或请求参数替代。

输入 `L2存在身份来源读取请求` 包含：

- 非零 `请求头.期望事实代次`，作为本次读取允许使用的事实范围上界。
- `读取类别`：`当前`或`历史`。
- `存在`：待证明的 `L2存在身份`。
- `历史截止事实代次`：当前读取必须为 0；历史读取必须非零且不大于请求头的期望事实代次。

输出 `L2存在身份来源读取结果` 包含结果头、原读取类别、历史截止和可选 `L2节点族身份来源事实`。成功读取必须返回同截止的节点稳定编码、owner、节点族、族锚点、族归属关系类型 / 稳定编码以及节点与归属关系生命周期；当前读取不能接受已退出来源，历史读取只投影指定历史截止内成立的来源。

### 事实与副作用

- 当前分支只消费 L1 当前权威事实；历史分支只消费 L1 历史权威事实。
- 本函数不写事实、不推进事实代次、不建立幂等记录、不修复来源，也不缓存结果替代下一次正式读取。
- 分配失败映射为`资源失败`，其它异常或来源矛盾映射为`内部不一致`；非成功不得携带伪成功来源。

### 合法调用与当前生产调用点

合法调用包括同层单向依赖中需要验证存在端点的场景、特征、状态和动态结构服务，以及需要直接证明存在身份来源的上层消费者。依赖方向固定为“消费者 -> 存在结构公开读取”，不能直达 L1 重演来源证明。

绑定源码中的明确生产调用点包括：

- `服务.L2场景结构.ixx`：场景成员、树 / 宿主等结构写入与读取前验证存在端点。
- `服务.L2特征结构.ixx`：特征宿主的当前 / 历史来源验证。
- `服务.L2状态结构.ixx`：状态主体的当前 / 历史来源验证。
- `服务.L2动态结构.ixx`：动态主体的当前 / 历史来源验证。
- `服务.L2存在结构.ixx`：`退出存在`在退出前互证本 owner 的族归属关系。

这些调用点证明公开读取边界已被生产源码复用；它们不自动证明每条上层业务路径已经运行或通过独立集成验收。

## 3. `退出存在`

### 用途、输入和输出

`退出存在`在唯一存在 owner 内关闭具名存在节点、它的存在族归属关系，以及调用方显式提交并经当前快照互证的全部当前固定属性值。它采用“闭包材料由调用方列全、服务按权威当前快照复核”的删除合同，不按猜测扫描或级联删除其它 owner 的事实。

输入 `L2存在退出请求` 包含：

- 非零 `请求头.期望事实代次`和有效、非保留`幂等身份`。
- 待退出的`存在`身份。
- 当前存在族归属关系的具名`族归属关系稳定编码`。
- `当前固定属性值`：必须严格升序、无重复且每项为有效稳定编码；空组表示调用方声明当前不存在固定属性。

输出 `L2存在退出结果` 包含结果头和可选`已退出存在`。成功结果应携带已经在同一次变更代次关闭生命周期的存在值式材料；代次漂移、闭包漏项 / 多项、族归属不匹配、仍被当前事实引用、底层拒绝或读回矛盾均不能形成成功载荷。

### 退出闭包、事务、幂等和生命周期

- 退出写集包含：存在节点稳定编码、具名族归属关系稳定编码、请求列明的全部当前固定属性值编码，并在提交前排序形成规范化写集。
- 服务先探测当前事实代次；在可稳定读取的同期内，正式读取存在身份来源并互证族归属编码，再读取完整存在并把权威当前固定属性值组与请求闭包逐项比较。
- 闭包互证后，由一份 owner-scoped 写集退出上述事实并正式读回。首次提交与精确重复共享同一存在 owner 幂等域；发布未知必须保留原完整请求重放，不能改幂等身份或缩减闭包。
- L1 当前引用闭包保护仍是退出的最终硬边界：场景关系、状态 / 动态 / 特征或单例角色等当前引用未解除时，服务不得靠只退出自身属性绕过`引用冲突`。
- 退出只关闭存在 owner 内列明的事实，不级联删除场景成员、宿主、状态、动态、概念或其它 owner 的事实，也不代表从业务世界中“抹除”对象。

### 合法调用与当前调用点

合法调用者必须先在同一预期事实代次取得当前身份来源和完整存在快照，形成精确退出闭包，并负责先解除其它 owner 的当前引用。调用方不得把过期属性列表、缓存或名称当成退出材料。

在绑定提交上未发现本函数的外部生产调用点。E2 的生产外退出矩阵只证明具名服务切片，不证明真实业务删除、长时竞争、崩溃恢复或跨进程重放已经运行。

## 4. `读取存在节点`

### 用途、输入和输出

`读取存在节点`是面向 E1 节点读取合同的公开兼容投影。它不另建读取逻辑，而是把 `L2存在节点读取请求`转换为`L2存在完整读取请求`，调用`读取完整存在`，再只返回其结果头和 `L2存在事实`。

输入 `L2存在节点读取请求` 包含非零请求头期望事实代次、当前 / 历史读取类别和存在身份。该 DTO 没有独立历史截止字段：

- 当前读取转为`历史截止事实代次 = 0`。
- 历史读取把`请求头.期望事实代次`同时作为历史截止，因此调用方是在该明确截止读取，而不是“从某上界中自动选择一个更早快照”。

输出 `L2存在节点读取结果`包含结果头和可选`L2存在事实`。由于正文委托完整读取，成功载荷不只是裸节点句柄，而是同一截止闭合的存在身份、生命周期和固定属性组。资源异常与内部异常分别映射为结构化状态；非成功返回空存在载荷。

### 事实、副作用和生命周期

- 当前读取要求存在及其来源在调用截止仍为当前；历史读取按指定截止投影当时成立的生命周期与固定属性。
- 读取不写事实、不推进代次、不建立幂等账，也不把历史值恢复为当前值。
- 它不读取场景成员、宿主、角色、状态、动态或其它 owner 的反向引用；需要这些组合的调用者必须分别调用相应所有者的公开服务。

### 合法调用与当前调用点

本函数适合只需要一个存在完整值式事实、但沿用 E1 节点读取 DTO 的消费者。新代码若需要显式控制独立历史截止或表达“完整存在”语义，应优先复核是否直接调用`读取完整存在`更清晰。

在绑定提交上未发现本函数的外部生产调用点；当前可见调用仅由函数正文委托`读取完整存在`。因此只能声明公开读取能力存在，不能声明已有生产消费者。
