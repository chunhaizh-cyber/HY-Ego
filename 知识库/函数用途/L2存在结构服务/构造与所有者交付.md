## 服务取得用途

`尝试形成L2存在所有者交付`把 L1 已建立的独占结构 owner 交付收束为只能供存在结构服务装配消费的移动交付：

1. 验证 L1 管理结果合同版本、固定 `存在所有者建立身份`、非零事实代次，以及首次成功或精确重复的完整重试边界；
2. 验证 owner 事实存在、范围种类为独占结构范围、创建代次非零且未退出；
3. 验证原始交付持有有效写端口，端口 owner 等于结果 owner，并绑定输入的同一个 `L1事实基座服务`实例；
4. 再经 `读取当前结构所有者`正式读回 owner，并要求当前事实逐字段等于建立结果；
5. 全部成立后才移动原始写端口，形成 `L2存在所有者交付`；任一失败或异常返回 `std::nullopt`。

### 输入、输出、事实和生命周期

- 输入的 `第一层读取服务`是非 owning 借用；其生命周期必须覆盖取得校验及后续服务实例。
- `原始交付`按右值传入。只有成功返回时其写端口被移动；失败路径不形成 L2 交付。
- 函数只正式读取当前 owner 事实，不创建 owner、不写事实、不建立存在节点。
- 输出交付是一次性装配能力，不是通用服务 getter，也不是可复制凭据；只能移动构造，不能默认构造、复制或赋值。

## 服务装配用途

`L2存在结构服务`公开构造按固定顺序完成：

```text
验证交付端口有效且绑定同一L1实例并移动
-> 初始化存在身份来源定位
-> 读取非零当前事实代次
-> 建立或精确复用存在单例角色结构登记并正式读回
-> 构造成功
```

构造保存同一 `L1事实基座服务`的 const 引用和唯一 owner 写端口。`初始化存在身份来源`先正式读回 owner，再以固定幂等身份在一份 owner 写集中建立存在族锚点和族归属关系类型节点；首次成功形成新事实，精确重复不形成第二份发布，随后按写入代次历史读回两个节点并冻结定位。构造最后调用公开 `建立存在单例角色结构登记`，因此构造不是纯引用绑定，而是带固定登记引导的服务装配。

### 失败、事务与副作用

- 无效交付或跨 L1 实例交付由私有 `验证并移动交付`抛出 `std::invalid_argument`。
- owner、存在身份来源登记、编码映射或正式读回不完整时抛出 `std::runtime_error`。
- 当前事实代次不可取得，或单例角色结构登记建立 / 读回失败时抛出 `std::runtime_error`。
- 身份来源登记和单例角色登记各自使用独立的 owner 范围写集，不构成跨两次写入的单一原子事务；任一构造失败都不能倒推前一固定登记未曾发布。
- 成功服务持有写端口至自身生命周期结束；复制构造和复制赋值删除，避免复制 owner 写能力和登记锁状态。

## 合法调用语境

- `尝试形成L2存在所有者交付`只能消费用固定存在 owner 建立身份形成、绑定同一 L1 实例且仍有效的 `L1所有者范围交付`。
- 公开移动构造只用于把成功交付转交给最终服务构造；不得把已移动交付再次使用。
- `L2存在结构服务`构造必须接收同一 L1 实例和与之绑定的存在交付；上层装配负责保证 L1 服务先于存在服务构造并后于其析构。
