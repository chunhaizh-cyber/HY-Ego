## 当前生产边界

- 两个源码均登记在根工程；普通应用从同一L1运行包形成动态owner交付，构造唯一`L2动态结构服务`，上下文与`L2结构聚合服务`返回同一实例。
- `L2概念结构服务`在普通概念事实和关系引用校验中实际调用`读取完整动态`。其它公开写入、组查询和来源入口没有模块外正式生产调用点。
- 服务保存调用方已经裁决的强类型动态结构，不比较前后状态、不判断变化真实或重要、不要求主体等于状态主体，也不执行动作归因。

## 正式合同缺口

1. 当前公共枚举与本服务有界组查询使用`L2结构状态::数量预算不足 = 15`，但4230第2.2节共同状态仍只列到`内部不一致 = 14`。
2. 1170要求动态保存场景、被改变目标、可选来源动作、低层动态及业务一致性验证；更新且更具体的4230第4.5节和当前ABI只固定主体、前后状态、起止时间、来源和生命周期，并明确业务一致性由DATA之外裁决。
3. 动态服务9处构造/装配异常文本误写为`L2 state ...`，会把动态owner、来源登记和类型登记故障显示成状态服务故障；结构化公开结果不受该文本影响，但异常诊断归属当前不准确。

知识库只登记这两项正式口径缺口，不自行增加字段、删除要求或判定哪份机器语义应被修改。
