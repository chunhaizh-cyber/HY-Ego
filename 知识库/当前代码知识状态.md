## 4. 当前使用要求

在用途卡全量形成前，查询任一函数时至少执行：

```text
查能力目录和函数身份
-> 查现状图或调用边
-> 回读当前源码与生产调用点
-> 对照正式规范、有效设计和现行计划
-> 形成用途、非职责、输入输出、副作用、生命周期和复用结论
```

发现目标函数自知识基线后发生变化时，保留旧条目作为历史证据并标记待复核；不得静默沿用旧签名、旧调用点或旧职责。

## 5. 下一步知识建设

知识准备完成后，后续治理应把知识读取接入代码实施入口，并建立发布后增量维护机制。优先顺序为：

1. 从后续新发布或修改的函数开始形成用途卡，避免继续产生新知识欠账；
2. 按覆盖账补下一批高复用公开服务及其内部实现；
3. 逐步处理仍在使用的内部函数；
4. 对测试钩子、旧兼容路径和当前不可达函数分账登记，不与生产能力混用；
5. 每次代码或图谱发布后刷新本状态文件的正式基线和已知差异。
