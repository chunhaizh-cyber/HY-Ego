# 多工作树并发与集成规则

日期：2026-10-14
状态：现行代理协作 / Git 工程规则

用户已允许 Git / Codex 工作树模式。本文件规定工作树创建、分支、集成与退出；通用所有权、并发额度、验证资源、WIP保护和发布租约统一读取[工作区串行发布规则](单工作区串行执行与发布规则.md)及`AGENTS.md`，不在此另设一套权限。旧工作树记录仅供追溯，不自动成为活动切片。

## 1. 创建与复用

1. 用户已授权的任务可以在主工作区施工，也可以按隔离需要使用独立工作树；本次允许模式不要求立即创建工作树，不自动迁移既有WIP。
2. Git / Codex任务工作树统一放在`D:\worktree`下，使用互不重叠的任务子目录，例如`D:\worktree\<任务标识>\海中鱼巣`；`D:\worktree`本身只作父目录，不作为某一任务的检出或删除目标。创建或复用前核对`git worktree list --porcelain`、仓库共同Git目录、当前分支/HEAD/index/dirty、切片所有者和资源，声明并验证工作树绝对路径位于该根内，以及任务身份、来源提交、分支及允许文件。路径不能扩大语义所有权。创建工具必须支持该目标路径；不支持时使用能指定目录的Git工作树方式，不在其它目录落地后自动搬移。目录外的历史工作树不自动迁移，另行核对所有权与现场。
3. 主工作区保留`main`。新任务分支默认使用`codex/<任务名>`；已有分支只能由其所有者继续使用。同一分支不得同时在多个工作树检出，禁止用`--force`或`--ignore-other-worktrees`绕过。
4. Git/Codex创建的detached工作树可先只读核验；施工前为该HEAD建立具名任务分支。不得因建立分支而重置、覆盖或复制其它工作区未提交改动。
5. 工作树规则可能落后于主线。开工同时核对已发布main上的现行协作规则和当前切片冻结材料，代码事实仍绑定本工作树精确HEAD；不得把不同工作树的代码、规范或验证结果混成同一个基线。

## 2. 施工与验证

每个工作树使用自己的文件和index，可以独立精确暂存、提交本切片。子智能体仍受顶层授权边界约束，不因独立index取得提交或推送权。共享分支引用、main、聚合入口、文件/语义所有权和验证资源按通用规则协调。

实际项目可在本工作树构建；获用户明确测试指令时，可在本工作树使用正式工程及登记入口测试。输出目录、数据库、日志、端口和外设必须具名隔离或取得独占资源。工作树验证只证明该HEAD及声明WIP；main集成后的证据是否仍适用，要按实际集成差异复核，不能自动升级为集成验收通过。

## 3. 集成与发布

工作树切片完成后，其所有者交付：来源基线、分支、精确提交范围、允许文件、差异、实际验证及剩余WIP。主工作区唯一集成所有者取得发布租约后执行：

1. `fetch`并核对main/origin/main及待集成提交，确认提交只包含获准切片，没有混入异主WIP或无关提交。
2. 核对主工作区index和dirty。集成不得带入、覆盖或改变其它所有者现场；不能证明安全时保留工作树提交，等待具名交接。
3. 优先普通`git merge --ff-only <精确提交>`。main已经前进且不能快进时，允许对已审核的获准提交执行普通`git merge --no-ff <精确提交>`。这项授权只用于已获准工作树切片集成，不允许任意分支合并，不授权force、reset、clean、stash、rebase或cherry-pick。
4. 出现冲突时停止发布，保留现场；仅在已获准范围、所有权明确且语义可裁决时解决冲突。涉及异主文件或未冻结合同则协调所有者，不能择一覆盖。
5. 检查集成差异、范围和证据。代码按`AGENTS.md`第7.1节在实际项目完成所需编译链接，规则/文档做静态检查；本流程不自动触发运行测试。
6. 普通推送`origin main`，读回提交、远端关系、index及剩余dirty，释放租约。分支提交完成、分支推送和main集成发布必须分别报告。

## 4. 退出与清理

移除或归档前核对确切工作树路径、所有者、dirty、未集成/未推送提交和必要忽略文件。只处理本切片自建、已交付且无待保留内容的工作树；存在WIP、未交付提交或所有权不明时保留并报告，不强制删除。Codex托管工作树优先使用应用的可恢复归档机制；其它工作树使用Git正常移除，不递归删除仓库目录。任务分支只有确认提交已安全保留且无人使用时才可正常删除，禁止强制删除。
