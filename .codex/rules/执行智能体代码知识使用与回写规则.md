# 执行智能体代码知识使用与回写规则

日期：2026-08-16

状态：代理协作 / 代码实施规则；不是项目机器规范

本规则规定执行智能体怎样使用 `知识库/` 理解既有函数、完成能力查重和复用裁决，以及怎样把代码结果产生的知识增量交给知识库维护者。机器语义仍由 `规范/规范目录.md` 登记的逻辑规范定义，实施范围仍由现行计划冻结。

## 1. 生效边界

本规则从其正式发布后的下一次执行 S0 起生效。已经取得活动代码段并开始施工的计划，不因本规则发布而中途扩大代码白名单、记录白名单或验证范围；该执行者只需在原计划允许的专属施工记录中尽量保留可取得的函数知识增量。

本规则不授权执行智能体修改共享知识索引、能力目录、代码流程图、正式规范、详细设计、计划或计划索引。

## 2. S0 必读知识

执行智能体除读取 `AGENTS.md`、协作规则、单工作区规则、计划索引和目标计划外，还必须读取：

```text
知识库/README.md
知识库/代码编写与既有函数复用知识.md
知识库/当前代码知识状态.md
目标函数已有的知识库/函数用途/** 条目
```

同时按目标代码职责读取 `规范/规范目录.md` 登记的 0600 和 CODE-FILE-01。知识条目不存在时继续读取当前代码，不得把“缺知识”解释为“缺函数”或机械停工。

## 3. 当前性核对

每个用途条目必须有代码提交或源码 blob。使用前比较条目基线与本次正式 HEAD：

1. 核对完整签名、DTO、可见性和物理位置；
2. 核对直接生产调用者、直接被调者和依赖方向；
3. 核对事实读写、副作用、事务、并发和生命周期；
4. 核对正式规范、有效设计、现行计划和已发布验证证据。

相关代码无变化且合同仍一致时，条目可以继续作为候选证据。相关代码有变化时按当前源码重新判断，并把条目列入待复核知识变更清单。已确认冲突的过期条目不得用于施工。

未发布 WIP、聊天摘要、函数名、注释、日志和界面文字不能替代当前源码与调用点。

## 4. 实施前复用裁决

执行智能体必须先固定计划已经冻结的目标函数参数、结果、事实来源、错误、副作用、事务、生命周期和合法调用方，再按以下顺序查重：

```text
函数用途知识
-> 当前能力证据目录
-> 当前函数身份与调用图
-> 当前源码和调用点
-> 正式规范、有效设计和现行计划
-> 直接复用 / 组合 / 适配 / 扩展 / 新建 / 证据不足
```

计划已经精确冻结新建或扩展结论时，S0 只核对其与当前代码是否漂移，不由执行者重做机器语义设计。发现当前已有等价能力、第二 owner、第二事实入口、循环依赖或公开合同冲突时，按真实设计漂移退回计划支撑；不得复制实现或临场改接口。

## 5. 施工记录中的知识变更清单

代码结果的专属施工记录必须包含“代码知识变更清单”，逐项列出：

```text
新增、直接修改和退出的稳定函数身份
完整签名、模块、文件和可见性
用途和明确非职责的变化
参数来源、结果形状和错误边界的变化
事实读写、副作用、事务、并发和生命周期的变化
新增、删除或改变的直接调用边
相关正式规范、设计、计划和验证证据
结果提交；提交形成前标记待填
需要新建、更新、标记待复核或标记退出的用途卡
```

没有函数知识变化时明确写“无”，并给出本切片只改工程、记录或其它非函数产物的事实依据。不能省略该节，也不能用提交文件清单代替函数级变化。

## 6. 发布后的维护交接

代码结果正式发布后，执行智能体在完成回传中附上知识变更清单的位置、结果提交和待更新函数身份。共享知识由“能力证据目录维护智能体（兼代码知识库维护）”只基于已发布代码更新：

- `知识库/函数用途/**`；
- `知识库/当前代码知识状态.md` 中的基线、覆盖和滞后状态；
- 受影响时再按各自所有权更新能力证据目录或代码事实图谱。

知识维护没有完成前，代码结果可以按原计划完成条件独立收口，但相关知识状态必须保留“待复核”，不得对外宣称知识闭合。执行智能体只有在计划明确把某个独立知识文件列入白名单时才能修改它；不得直接争抢共享聚合索引。

## 7. 禁止事项

1. 禁止依赖智能体对旧代码的会话记忆代替证据读取。
2. 禁止按短名称或参数可转换性认定语义等价。
3. 禁止用过期用途卡跳过当前代码和调用点核对。
4. 禁止把能力目录的候选状态写成复用完成或业务完成。
5. 禁止因知识缺失自行新建函数、公共工具、第二服务、第二 owner 或第二数据入口。
6. 禁止把计划目标、未实现声明、空函数或注释写成当前能力。
7. 禁止在代码提交中顺带修改未获所有权的共享知识索引。

## 8. 完成边界

本规则只建立代码知识的读取、当前性核对和增量交接闭环，不证明当前全部函数已经具备用途卡，不证明知识条目对应能力已通过构建、运行或集成验收，也不改变任何代码计划的机器语义和完成条件。
