# 海中鱼巣服务导向集成验收

## 边界

服从仓库根目录 `AGENTS.md`、`.codex/rules/设计执行双窗口交互规则.md` 和 `.codex/rules/单工作区串行执行与发布规则.md`，并完整读取 `规范/运行期服务导向代码验收与全函数入口巡检规范.md`。只验收交互智能体具名交付的、已经提交并推送的精确基线；只写 `验证记录/集成验收/**`，不得修改代码、工程、自检、规范、设计、计划、索引或计划状态，不得验收未提交 WIP。

把验收主对象定义为“向合法消费者提供完整结果的具名服务切片”，不要把函数数、流程图数、源码行、编译成功、无崩溃、无日志或自检 PASS 累计成能力完成。

## 开始前冻结

先完整确认并记录：

```text
精确候选提交与远端可达性
+ 适用规范、设计、计划及其输入 blob
+ 上级目标和最小允许声明范围
+ 服务名称、合法消费者与正式入口
+ 输入前提、结构化成功 / 非成功和禁止假成功
+ 合同规定的权威终态或零改变
+ 独立读回与安全继续条件
+ 运行配置、真实外部资源、专用测试命名域
+ 最小风险矩阵、命令、证据路径与资源租约
```

当前项目的运行期权威事实由现行正式规范裁决，不能默认照搬其它项目的 SQL 权威口径。SQL、独立材料、缓存、日志和界面分别只能按本项目现行规范承担持久证据、恢复输入、非权威加速或人读诊断职责。

目标提交、正式输入、环境或资源不明确时返回 `INTEGRATION-ACCEPTANCE-DRIFT` 或 `INTEGRATION-ACCEPTANCE-BLOCKED`，不得自行补造验收标准。

## 选择验收深度

从合法消费者或等价正式边界发起真实请求，沿真实装配取得结构化结果，再从合同规定的权威读取边界独立读回。优先覆盖会决定上级服务能否安全继续的事实。

下列路径必须按风险加深，不能等待偶然暴露：

- 稳定编号、版本、幂等和高水位；
- 事务提交、提交未知、回滚和最终条件；
- 内存已发布代次与持久证据、材料或恢复候选的跨介质边界；
- 并发竞争、租约、唯一责任和跨进程崩溃恢复；
- 当前、历史、审计和恢复候选隔离；
- 任何可能暴露半结构、默认对象或错误事实的路径。

每次验收先冻结新增 / 修改函数影响闭包、具名服务闭包或全项目函数清单，并分账记录编译接入、入口巡检和逻辑异常检测。空函数正常编译时可以形成 `编译接入通过`；在安全输入下实际进入并退出且未观察到逻辑异常时可以形成 `入口巡检通过`。两者都不能证明业务后置条件或服务完成。

普通低风险局部还需证明当前调用前提、可消费结果、结构化非成功、无越权副作用和上级路径可继续，结论最多为 `局部可继续`。只有参数合法、正常返回、未崩溃或没有日志时，结论最多为 `未观察到错误`。

新增或直接修改函数必须逐项核对 CODE-FILE-01 的 `本地记录 / 向上送出 / 无适用错误分支` 诊断责任。逻辑异常必须沿唯一结构化传播链到达最终责任边界；合法非成功不记为异常，日志失败不改变业务结果。

## 执行最小矩阵

验收清单必须显式列出以下八类场景。相关场景执行并保存证据；确实不适用的场景标为 `NOT_APPLICABLE` 并写明合同级理由，不得留空或默认通过。

| 场景 | 核对重点 |
| --- | --- |
| `成功` | 完整结构化结果与合同规定的权威终态 |
| `精确重复` | 原身份 / 版本 / 序列 / 结果，不形成第二事实 |
| `合法拒绝` | 具名非成功，零未授权事实改变 |
| `外部失败` | 无普通可见半结构，可安全重试或进入具名后继 |
| `并发` | 只有合法结果越过发布点，最终条件成立 |
| `崩溃恢复` | 新进程只依赖合法持久证据继续，最终结论唯一 |
| `正式读回` | 经独立读取或冷启动读回相同事实 |
| `正式构建` | 自检关闭后的正式目标不携带自检入口或故障分支 |

写入权威事实的服务至少必须通过 `成功` 和 `正式读回`；其它风险项根据合同与实际路径裁决为必需或不适用。自检直接调用、仅自检可达或仅编译进正式目标都不构成正式接线。

## 记录与机器检查

每次验收在 `验证记录/集成验收/<具名目标>/` 中至少保存：

1. 人读 Markdown 记录；
2. 一个 JSON 验收清单，字段合同可用下列命令输出；
3. 清单引用的命令、退出码、读回和运行证据。

```powershell
python .\tools\check_integration_acceptance.py --print-template
python .\tools\check_integration_acceptance.py --manifest <清单.json> --verify-git --strict
```

检查器只验证身份绑定、字段完整性和结论升级门禁，不证明证据真实。验收智能体仍须亲自核对命令、结构化结果、权威终态和独立读回。

## 结论

只使用下列最小结论：

- `服务验收通过`：合法消费者经正式边界取得符合合同的服务，所需权威终态和独立读回成立；
- `自检通过`：仅证明具名自检及其明确覆盖范围；
- `编译接入通过`：目标函数身份、归属、编译和链接成立；允许空函数通过，但不证明运行或业务结果；
- `入口巡检通过`：目标函数实际进入并退出且未观察到逻辑异常；不证明业务后置条件或服务完成；
- `局部可继续`：足以继续施工或更高层验证，未证明正式服务完成；
- `未观察到错误`：尚未核对足以支持更强结论的合同结果；
- `未正式接线`：实现或自检存在，但合法消费者的正式入口不可达；
- `事实失败`：结果、权威终态、隔离、不变量或恢复继续性不符合合同；
- `环境阻断`：必须的真实资源不可用，不能形成产品通过。

对外结构化返回只使用 `INTEGRATION-ACCEPTANCE-PASS`、`INTEGRATION-ACCEPTANCE-FAIL`、`INTEGRATION-ACCEPTANCE-DRIFT` 或 `INTEGRATION-ACCEPTANCE-BLOCKED`，并绑定候选提交、输入 blob、命令、退出码、证据路径、允许声明、禁止声明和未覆盖范围。

发现旧记录把编译、自检、日志、局部运行或不完整矩阵扩大成服务完成时，保留历史事实并明确撤回过强结论；不得用新记录静默覆盖。
