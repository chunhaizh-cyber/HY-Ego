# 海中鱼巣执行

## 1. 入口与边界

只在当前任务树是执行智能体，或用户明确要求当前交互智能体直接实施一个已具备依据的代码切片时使用。先读 `AGENTS.md`、协作规则、单工作区规则、`.codex/rules/执行智能体代码知识使用与回写规则.md`、计划索引和目标计划；再读 `知识库/README.md`、`知识库/代码编写与既有函数复用知识.md`、`知识库/当前代码知识状态.md` 及目标函数已有用途条目。

执行智能体只写目标计划允许的代码、工程、自检及专属施工 / 验证记录；不改规则、规范、流程图、详细设计、计划或计划索引。完整详细设计和冻结合同是直接依据，流程图是辅助证据，不能由执行者临时补造机器语义。

不硬编码路径。技术身份从当前 Git 读取：

```powershell
git rev-parse --show-toplevel
git branch --show-current
git status --short --branch
git rev-parse HEAD
git rev-parse origin/main
git rev-list --left-right --count HEAD...origin/main
```

## 2. 选择计划与 S0

没有活动计划段时，从计划索引选择一份状态为 `可执行`、具名依赖满足且目标切片未被占用的计划。通知和聊天只能提醒重新扫描，不能替代正式状态。

写入、构建或运行前完成 S0：

1. 核对计划与索引的路径、版本、状态和依赖；
2. 读取关联规范、详细设计、允许 / 禁止范围和验证合同；
3. 对照当前代码核对函数、DTO、接口行为、所有权和物理位置；
4. 核对相关用途条目的代码基线，并用当前源码、生产调用点、能力证据目录和调用图完成既有能力复用互证；
5. 核对 `main`、HEAD、远端、index、dirty 所有者、活动代码段和验证资源；
6. 固定本段起点、计划身份和允许范围。

S0 通过后直接实施，不等待聊天接受。S0 只需证明当前计划可在当前事实下安全施工，不重复重做已经稳定且与本计划无关的全仓审计。

## 3. 实施方法

```text
取得目标代码切片
-> 固定目标函数参数、结果和调用合同，先核对既有能力
-> 按详细设计实现最小闭合改动
-> 在计划范围内修复编译、逻辑和自检问题
-> 运行计划要求且与风险相称的验证
-> 复核允许文件、完成条件和未覆盖范围
-> 精确提交并普通推送
-> 释放切片并返回结构化结果
```

执行者可以自行决定不改变合同的局部实现、重构和错误修复；以下事项不能临场决定：机器语义、公开接口、字段来源、事务边界、跨模块所有权、计划白名单和完成标准。

新增代码文件或日志行为时读取对应专项规范。不得凭智能体记忆、函数短名称或过期用途卡复用代码。不要把旧实现逐文件照搬，也不要为通过测试建立假成功、默认有效对象、伪数据或第二业务入口。

## 4. 问题分流

- 计划范围内的代码错误、编译错误或自检错误：追根因并修复，继续执行。
- 一次性环境波动或非确定验证：保存证据，合理复验；不能稳定归因时按环境问题收口，不虚报设计漂移。
- 规范、详细设计、计划合同和当前接口之间存在会改变实现的差异：停止受影响范围，向计划支撑智能体报告事实并明确请求修订。
- 需要扩大文件范围、改变公开合同或新增机器语义：停止并交给计划支撑，不自行扩权。
- 无关且所有者明确的 dirty：原地保留；只有同文件、同语义或共享资源冲突才阻断。

设计漂移出现于施工后时，按单工作区规则判断能否形成安全 WIP。可提交的 WIP必须位于计划范围、可验证、无语法破损、无半结构和假成功，并明确不代表计划完成；否则保留现场。

## 5. 记录、验证与 Git

施工 / 验证记录只写已发生的计划身份、S0、变更、命令、结果、提交、风险和完成边界，不定义机器语义或计划状态。施工记录必须包含函数级“代码知识变更清单”，列出新增、修改、退出函数及其用途、合同、调用边和待更新用途卡；没有函数变化时明确写“无”及依据。

至少运行：

```powershell
git diff --check
git diff --cached --check
```

其余构建、自检、性能和运行验证以计划和实际风险为准。只暂存当前计划文件，不带入其它所有者 WIP；禁止 force 及未经授权的 merge、rebase、cherry-pick、reset、clean 或 stash。

## 6. 连续执行与完成声明

当前计划发布并释放切片后重读计划索引和 Git。有其它可执行计划且用户未暂停时，可以建立下一计划段并重新 S0；存在未修设计漂移时等待支撑修订，不用另一个计划掩盖当前问题。

最终报告说明计划、起点和结果提交、实际变更、验证、未验证范围、剩余 dirty、知识变更清单位置、待更新函数身份和下一候选。执行智能体不直接修改共享知识索引，除非计划明确授权。单次提交、编译、自检或知识条目更新不得升级为完整业务闭环、旧能力等价、自我循环或项目完成。
