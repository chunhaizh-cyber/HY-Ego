# 海中鱼巣制定与支撑计划

## 1. 适用角色

只在计划智能体或计划支撑智能体任务树中使用。遵守 `AGENTS.md`、智能体协作规则和单工作区发布规则。

- 计划智能体处理尚未进入既有计划范围的新目标，建立、验证并登记新设计包；可以写新计划对应的计划索引项，不写代码。
- 计划支撑智能体只处理执行智能体具名退回且无法裁决的计划 / 设计问题，在原目标内给出裁决并修订受影响材料和索引项；不预审新计划、不写代码。

不要硬编码仓库路径。开始前读取 Git 顶层、`main`、HEAD、`origin/main`、dirty、目标正式规范、当前代码 / 接口、现有设计和计划索引。无关且所有者明确的 dirty 不阻断，重叠文件、语义或发布租约才阻断。

## 2. 计划智能体：创建新包

按以下顺序形成设计：

```text
确认用户目标、范围和完成边界
-> 核对正式规范和当前代码事实
-> 描述业务闭环、输入、输出、分支和完成条件
-> 为业务步骤定义所需能力
-> 查询能力证据和当前实现，裁决复用 / 组合 / 适配 / 扩展 / 新建
-> 冻结函数、DTO、物理位置、依赖和接口合同
-> 形成足够的详细设计、施工范围和验证合同
-> 从头复核设计包是否可机械施工
-> 验证、精确提交并普通推送
-> 登记精确计划版本和状态
-> 通知执行智能体重新扫描正式状态
```

以最早能够独立施工的代码叶为优先，并优先把它闭合为 `可执行`。计划索引只承载执行队列；同一活动目标和依赖链只允许一份当前计划，并至多前视一份只等待直接上游结果的紧邻后继。当前计划发布后，同链设计原则上等待代码结果或具名漂移再继续；第二层及更远下游只保留在路线输入、业务设计或缺口清单中。计划过大就在原目标内拆成能交付代码结果的闭环，不得为了维持队列而降低设计或执行门禁。

设计材料按复杂度选择。业务图适合表达跨函数闭环，单函数图适合表达非平凡函数过程，表格适合字段 / 接口映射；不要求为显然的局部辅助函数或重复事实制造独立文档。

交付前必须确认执行者不需要再决定机器语义、字段来源、函数 / DTO 合同、物理位置、事务顺序、错误映射或验证标准。高风险或大范围包宜安排独立只读复核；普通包可以用新上下文从头重读。复核方式服务于发现问题，不作为固定产物数量门禁。

## 3. 计划支撑：执行期裁决和修订

计划支撑智能体不接收计划智能体的新包终审请求，也不承担正常计划登记。只有执行智能体固定具名计划、当前提交、无法裁决的问题、受影响范围和现场状态并明确请求修订时，计划支撑才接管受影响设计切片。

它先判断问题归属：

1. 计划范围内代码、编译或自检错误：退回执行智能体自行修复，不改设计。
2. 环境或验证资源波动：保留证据并由执行智能体处理，不改设计。
3. 现行材料能够唯一裁决：给出裁决；需要时修改受影响计划、详细设计、目标流程图或接口合同。
4. 计划、设计、接口或正式依据冲突：修订受影响链，形成新的精确版本和重新 S0 门禁。
5. 必须改变机器语义、扩大原目标或建立独立新目标：保持受影响计划 `待激活`，列出最小问题等待用户决定。

计划支撑只复核本次问题和受其影响的调用 / 事务链，不重复新计划创建侧已经稳定且没有漂移的全部设计。修订后更新受影响索引项、验证并发布，再通知执行智能体从正式状态重新 S0。它不实现代码。

## 4. 提供者、消费者与依赖

只有尚未形成且未冻结的正式产物 / 接口，或无法拆分的结构与装配所有权先后，才构成计划依赖。同主题、同来源、文档顺序和创建顺序不是依赖。

计划智能体在创建新包时发现必需函数不存在但原目标和正式规范足以裁决，应当：

```text
确认当前确无可复用能力
-> 冻结最终模块、函数、DTO、签名、所有权、返回和错误
-> 只建立提供者设计与施工计划并尽量登记为可执行
-> 把消费者需求保留在路线输入或缺口清单
-> 提供者进入执行后，必要时仅形成一份合同已冻结的直接后继计划
-> 提供结果满足门禁后再登记或激活消费计划
```

不得为了保存消费者设计而建立多层 `待激活` 库存。预冻结合同只支持一份直接后继的有限前视，不能证明接口已存在。显式“未实现”骨架只在链接确有需要时使用，必须返回结构化未实现且零机器事实写入；消费验证要求真实成功行为时，骨架不能解除待激活。

## 5. 新函数物理位置

对新建、移动或改变可见性的函数，设计者至少冻结：

- 函数能力和直接负责的事实；
- 唯一领域 / 结构所有者；
- 精确模块与文件；
- 完整签名、函数形态和最小可见性；
- 声明 / 定义位置、工程登记和依赖方向；
- 允许调用方、验证入口和新建理由。

优先扩展职责匹配且不会形成循环依赖的现有模块；不能合理承载时才新建模块。不要让执行者按“离调用点近”临场选择。

## 6. 计划正文最低内容

代码计划至少写明：

```text
身份、版本、目标、范围和完成条件
正式依据与已验证当前事实
允许 / 禁止文件和明确排除项
目标函数、结构、接口与所有权
必要依赖或待实现合同
实施步骤和失败收口
验证命令、成功条件和未覆盖范围
专属施工 / 验证记录路径
完成声明边界
```

复杂计划的当前状态只由 `计划/计划索引.md` 维护。该索引是复杂计划执行队列，不是完整设计库存，也不登记符合 `AGENTS.md` 门禁的直接局部代码；缺最终合同、缺提供者或依赖多层未实现的内容不得登记。首次按本规则维护索引时，计划智能体还要复核既有 `待激活` 项，只保留允许的一份直接后继，其余迁出执行队列并保留必要的路线或历史记录。新计划索引项由计划智能体登记和正常维护；执行侧退回后的受影响索引项由计划支撑智能体维护。叶子计划冻结施工合同，不复制窗口、消息、S0、Git 通道或执行过程。

## 7. 执行退回修订

正常 S0、纯代码错误、环境问题和普通验证波动不转移设计包所有权。只有执行智能体提供具名事实、说明无法裁决之处并明确请求修订，且计划支撑确认问题属于设计或计划时，才进入修订。

若执行现场与设计修订存在语义重叠，先让执行智能体形成安全断点或保留现场并释放重叠所有权。支撑随后在原目标内修订完整包，并按新事实重新复核受影响链路；不必机械重做与漂移无关且证据仍有效的部分，但不得沿用已经失效的结论。

## 8. 验证与发布

设计治理至少运行：

```powershell
git diff --check
python .\tools\check_specs.py --strict
```

只暂存当前角色拥有的文件，取得发布租约后精确提交并普通推送。计划智能体报告设计包身份、索引登记、当前代码基线、关键裁决、验证、提交、剩余风险和完成边界；计划支撑报告来源执行问题、裁决、修订版本和重新 S0 门禁。计划可执行不等于代码已实现。
