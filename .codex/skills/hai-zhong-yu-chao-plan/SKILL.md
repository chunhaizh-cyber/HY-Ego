# 海中鱼巣制定计划

## 智能体类型与权威入口

只在当前顶层任务树为计划智能体或计划支撑智能体类型时使用本技能。遵守 `AGENTS.md`；设计包所有权、消息边界、执行智能体自主 S0 和智能体切换读取 `.codex/rules/设计执行双窗口交互规则.md`；单工作区写入占用、`main` 基线、发布与验证读取 `.codex/rules/单工作区串行执行与发布规则.md`。

计划任务树只能把互不重叠的设计包切片交给同类型 / 只读子智能体，不得让后代切换为其它写类型。顶层统一复核差异并串行完成设计 Git 收口。

- 计划智能体只接收自身沿既有总目标推导的目标、交互智能体发送的目标或计划支撑智能体正式发布的 `DERIVED-REQUIREMENT-NOTICE`，负责创建新计划以及创建该计划所需的现状扫描、规范治理、流程图、逐节点分析、详细设计、接口冻结和计划拆分，不直接处理执行消息、不修改计划索引；收到派生需求时只创建一份新的提供者设计包，不改写来源消费包；每份完整新设计包验证、提交并推送后，只向唯一登记的计划支撑智能体发送 `PLAN-PACKAGE-READY-NOTICE` 并停写。
- 计划支撑智能体独占维护计划索引：收到 `PLAN-PACKAGE-READY-NOTICE` 后复核正式设计包，可在当前包原目标和登记范围内按需新建或修改必要设计文件；所需接口真实存在时登记为 `可执行` 并发送 `PLAN-AVAILABLE-NOTICE`；所需函数不存在但可精确合同化时冻结合同、建立派生需求、登记消费计划为 `待激活`，发布后发送 `DERIVED-REQUIREMENT-NOTICE`；同时只读接收配对执行智能体的结构化事实，只有具名计划 / 设计问题明确请求修订且复核成立时才接管既有设计包修订。

不得硬编码仓库盘符或旧仓库名。先用 Git 顶层、当前分支、HEAD、`origin/main` 和 dirty state 解析唯一主工作区事实；当前工作区不是 `main`、远端已经前进或存在其它写入占用时停止受影响切片并报告 DRIFT。

本技能只做项目设计包治理：可以读取代码事实。计划智能体按所有权建立或修订正式规范、规范目录、冲突登记、流程图、详细设计、知识图谱和新计划，但禁止修改计划索引；计划支撑智能体独占计划索引登记，可在接管的新计划登记包或执行问题复核成立的既有设计包内按需新建、修改必要设计文件，但不得独立发起无关新计划或扩大用户目标。不修改 C++ / 工程 / 自检、施工记录或验证记录，不运行 C++ 构建、程序或业务自检，也不修改 `AGENTS.md`、`.codex/rules/` 或 `.codex/skills/`。

## 前置读取

先读取 `AGENTS.md` 要求的共同入口，再按任务读取：

```text
目标正式规范与相邻边界
有效流程图与详细设计
代码差距或现行流程图 / 详细设计审查材料
当前代码 / 接口 S0 事实
计划/计划索引.md
当前 Git / 单工作区事实
计划支撑智能体追加读取配对执行智能体的最新结构化执行消息
```

聊天、旧项目规则、过期计划和旧函数只能作为来源证据。代码实施单位必须来自现行规范定义的业务对象、领域服务、结构闭环和有效设计，不能按旧函数一对一迁移。

缺少正式规范、有效设计、当前接口事实或必要差距记录时，在当前智能体拥有的设计包内补齐必要产物；当前目标必需函数不存在但正式规范足以裁决时，计划支撑智能体只冻结待实现合同并建立派生需求，不把缺失接口写成已实现。无法补齐或合同化时停止，并登记具名缺口，不能凭假设生成可执行代码计划。计划支撑智能体不得借补齐之名扩展到原目标外的新设计包。

## 计划形成算法

按以下顺序工作：

```text
确认当前智能体类型、设计包所有权、目标规范与完成边界
-> 若为计划智能体创建新计划：
   接收 INTERACTION-GOAL、自主后续目标或 DERIVED-REQUIREMENT-NOTICE
   -> 派生需求只创建新的提供者设计包，不修改来源消费包和计划索引
   建立或修订该计划所需的正式规范、规范目录、冲突登记、单函数流程图组、逐节点分析、详细设计、知识图谱和计划正文
   -> 核对当前代码、实际接口、双向覆盖、依赖、所有权和验证合同
   -> 验证、精确提交并非强制推送设计结果
   -> 发送 PLAN-PACKAGE-READY-NOTICE 后停写
-> 若为计划支撑智能体登记新计划：
   只读复核 PLAN-PACKAGE-READY-NOTICE、正式提交、plan blob、范围、依赖和验证
   -> 在当前包原目标和登记范围内按需新建 / 修改必要设计文件
   -> 若设计包变化，形成、验证、提交并推送新的精确版本 / blob
   -> 实际接口完整：把最终版本登记为可执行，验证、提交并推送计划索引
      -> 发送 PLAN-INDEX-RESULT 和 PLAN-AVAILABLE-NOTICE
   -> 必需函数缺失但可精确合同化：冻结合同、建立派生需求并登记消费计划为待激活
      -> 验证、提交并推送，发送 PLAN-INDEX-RESULT 和 DERIVED-REQUIREMENT-NOTICE
   -> 不合格时不改索引，发送具名 PLAN-INDEX-RESULT 并退回同一设计包修正权
-> 若为计划支撑智能体处理执行退回：
   确认具名修订请求和缺口归属成立
   -> 只在原目标内修订必要设计包与对应计划索引项
   -> 验证、提交、推送并发送 PLAN-SUPPORT-NOTICE
-> 执行 clean 终止后，计划支撑智能体发送 PLAN-WRITE-RELEASE
-> 计划智能体重新核对 Git 后才形成下一份新目标计划
```

流程图的最小正式单位是一个函数，但计划范围仍由现行规范与有效设计裁决。一个计划可以包含多个函数；必须使用单函数流程图组和调用图表达，不得把多个函数的内部过程合并为一张图。

## 从流程图形成详细设计

严格执行 `.codex/rules/设计执行双窗口交互规则.md` 第 6.1 节。流程图只定义单个函数的过程，不是执行智能体直接写代码的依据；先固定函数清单、每图唯一根函数、完整参数 / 结果和调用图，再把每个节点转换成被调函数分析或本函数内指令分析，最后写入完整详细设计。

形成详细设计时依次完成：

```text
固定函数清单、调用图和每份流程图的唯一根函数
-> 冻结根函数完整签名、参数、返回结果和节点类型
-> 读取每个函数 / 节点的规范、相邻边、当前代码和合同
-> 对函数调用节点写清参数 / 结果绑定，对指令节点写清具体操作、事实读写、状态变化、分支、事务、结果和验证
-> 裁决现有函数复用或新增，并冻结根函数与被调函数完整合同
-> 归并共享函数、DTO、事务和版本合同，冻结唯一所有者
-> 写入数据、调用、事务、失败、文件和验证合同
-> 建立根函数流程图到节点（被调函数 / 指令）、结构 / 验证及其反向引用
-> 覆盖全部流程边和终止路径
-> 通过当前接口或预冻结合同复核
-> 通过无需执行智能体继续作设计裁决的可实施性审查
```

详细设计必须完整记录第 6.1 节列出的文档身份、函数流程图合同表、节点实现表、函数合同表、数据合同、调用与事务、失败合同、代码映射、验证矩阵和空未决项。凡仍需执行智能体决定字段、类型、签名、参数 / 结果绑定、判断条件、版本、所有权、调用顺序或错误处理的设计，保持 `待激活`。

流程图与详细设计生产可以按无重叠根函数组交给同类型子智能体。顶层先冻结函数清单、调用图、每图唯一根函数、共享合同和唯一所有者；子智能体只写分配的单函数流程图、节点分析或独立详细设计切片；共享合同、跨函数去重、调用图闭合、双向覆盖和设计包 Git 收口由计划顶层串行完成。计划索引由计划支撑智能体另行独占登记。不得让两个子智能体分别定义同一函数、节点、DTO、事务、版本或同一文档切片。

### 真实依赖

只有下列情况可以登记依赖：

- 当前切片必须消费尚未形成、且尚未冻结为精确待实现合同的具名正式产物或接口。
- 文件、结构、公开接口或装配所有权无法通过拆分隔离，存在不可消除的先后。

同主题、同总计划、生成顺序、文档顺序、目录或验收顺序都不是依赖。仅共享工程、入口、统一运行器或装配文件时，优先拆成私有实现切片和唯一共享接线切片。

提供者实现尚未形成，但模块 / 文件、公开 DTO、完整签名或等价行为、ABI / 规则版本、输入输出所有权、逻辑内返回、内部错误、提供计划、消费计划和漂移退回点已经冻结时，该关系改记为“预冻结待实现接口合同”，不再作为继续完成消费设计的等待条件。该合同不能代替执行前真实接口骨架，消费计划在骨架验证前保持 `待激活`。代码实施仍由唯一执行智能体在同一主工作区按所有权和真实依赖串行推进；消费者不得补造同名接口或修改提供者文件，最终真实接线验证前不得宣称真实能力完成。

### 派生需求与接口骨架

计划支撑智能体在当前登记或修订包中发现必需函数不存在时，依次执行：

```text
确认当前代码确实没有语义、签名和所有权匹配的函数
-> 确认需求没有扩大当前用户目标
-> 用正式规范裁决该函数可以实现
-> 冻结最终模块 / 文件、函数名、DTO、完整签名和版本
-> 冻结输入输出所有权、生命周期、逻辑内返回、内部错误和漂移点
-> 建立唯一派生需求记录及提供者 / 消费者关系
-> 当前消费设计按合同继续闭合，但消费计划登记为待激活
-> 验证、精确提交并推送派生需求、消费合同和索引
-> 工作区 / index clean 后发送 DERIVED-REQUIREMENT-NOTICE
```

`DERIVED-REQUIREMENT-NOTICE` 至少列明目标来源计划任务及平台任务 ID、由来源消费 plan blob + 派生需求编号 + 派生需求记录 blob 组成的幂等关联键、来源消费计划与 blob、派生需求编号与正式路径、最终接口合同、提供策略、骨架形式、提供者 / 消费者、消费计划解除待激活的条件、验证矩阵和漂移退回点。目标任务必须沿来源通知的正式平台身份路由，不得按标题猜测；同一幂等关联键只创建一份提供者设计包。提供者设计可以直接实现真实能力；需要先解开编译 / 链接或设计链时，才建立接口骨架。

接口骨架必须使用最终模块、函数名、DTO 和签名：

- 仅声明足以完成目标时，不增加定义；验证最终声明、DTO / ABI、模块导入 / 头文件消费及不需要链接定义的编译边界。
- 完整链接确需定义时，只返回结构化“未实现”；验证追加全工程链接、调用返回“未实现”和零机器事实 / 结构变化。
- 禁止假成功、有效句柄、默认业务对象、伪数据、仓库 / 关系 / 索引 / 数据库写入和可读半结构。
- 消费者必须显式传播或收口“未实现”，不得转换成成功。
- 消费者必须显式传播或收口“未实现”；消费验证矩阵要求真实成功行为时，骨架不得解除待激活。
- 骨架计划完成只证明接口和链接边界存在；真实能力正文与最终接线另由具名计划和验证证明。

依赖门控计划必须写明：

```text
已验证当前事实
具名前置计划和产物
待消费的文件、符号、签名与行为
无法隔离的原因
解除条件
执行前复核命令
接口漂移的精确退回点
```

依赖未满足或接口漂移时，只登记受影响计划的精确门禁，不冻结无关计划，不把预期产物写成当前事实，也不生成泛化的“等待后续处理”。

### 串行实施与所有权

无未合同化真实依赖的计划独立登记。多个计划即使文件 / 结构 / 接口所有权互斥，也只表示可独立设计，不授权并行写代码；唯一执行智能体按计划状态、具名依赖和共享所有权串行消费。涉及共享工程、入口、统一运行器或装配面的计划必须明确唯一所有者和实施顺序。

代码计划必须冻结计划编号、版本、预期 `main` 基线、文件 / 结构所有权、接口证据、验证矩阵和必要的串行顺序；实际仓库顶层、分支、HEAD、`origin/main`、dirty state 和远端事实由执行智能体在 S0 直接读取 Git。

连续消费多份计划时，执行通道只由 `.codex/rules/` 绑定：一个长期执行顶层任务、唯一主工作区、`main` 和多个串行计划段，不写入计划索引。每个计划段分别使用计划编号 / DQ、计划版本和 blob、中央设计提交、当前 `main` HEAD、允许 / 禁止范围、合同和验证矩阵；结果 / WIP 断点由 Git 提交与结构化消息证明。同一时刻只能有一个活动计划段，段间必须恢复工作区 / index clean；不得为每份计划重复建立派发状态或执行许可。

## 计划正文

完整计划放在 `计划/`。代码实施切片至少包含：

```text
计划身份、版本和稳定设计状态；当前计划状态只在计划索引维护
依据：正式规范、流程图、详细设计、差距 / S0 记录
已验证前置事实
实施范围与明确排除项
目标服务、结构和公开接口
预冻结待实现接口合同、提供者与消费者（适用时）
派生需求、接口骨架形式、结构化未实现、零机器事实写入 / 零半结构 / 零假成功合同及分支验证（适用时）
允许文件与禁止文件
唯一专属施工记录与验证记录路径
机械步骤 S0/S1/...
入口拒绝、内部错误和失败收口
验证命令与成功条件
实施后证据
完成声明边界
```

面向常规执行模型的每一阶段明确区分：已验证前置事实、待实施目标、实施后可核对证据、只有前置成立后才能判断的完成 / 退回条件。

新增或改名代码文件时，读取 `规范/代码文件建立归属与模块命名规范.md`，列出文件分类、项目项类型、`include` / `import` 路径、工程登记、生产 / 自检依赖方向和 `入口.cpp` 不恶化边界。

涉及验收、自检、基准或专项检查时，设计包必须把人读过程信息和结果展示统一路由到现行日志系统，禁止控制台、弹窗、界面文本或另建文件旁路；冻结具名预编译宏及宏开 / 关验证，保证关闭后不求值仅供日志使用的参数，且不改变自检执行、结构化结果、失败计数、退出码、机器事实或生产行为。不得把“日志可关闭”设计成“自检随日志关闭”，也不得让验收裁决依赖日志写入成功。

计划、流程图和详细设计必须互相列明路径且范围一致。纯规则或只读治理确实不需要流程图 / 详细设计时，写明不适用原因和替代正式依据。

## 登记与设计发布

计划形成后，叶子正文冻结为不可变施工合同，只写计划身份、版本、稳定设计状态、目标、依据、允许 / 禁止范围、唯一专属施工 / 验证记录路径、失败收口和验证合同，不复制当前 `待激活 / 可执行 / 已退出` 状态，也不写当前派发、S0 或执行过程。计划支撑智能体复核后在计划索引中登记路径、版本、具名依赖和唯一计划状态 `待激活 / 可执行 / 已退出`；计划智能体只读该索引。执行通道由 `.codex/rules/` 管理；唯一工作区、`main`、HEAD、提交、dirty state 和远端直接读取 Git。

计划智能体每次只创建一份新计划及其前置设计产物。完整设计包通过治理验证、精确提交并非强制推送 `origin/main` 后，只向唯一登记且用户未撤销的计划支撑智能体发送一次幂等 `PLAN-PACKAGE-READY-NOTICE`，随后停写。登记拒绝时只修正该包；登记为可执行后必须等待执行 clean 终止和 `PLAN-WRITE-RELEASE`；登记为待激活且收到 `DERIVED-REQUIREMENT-NOTICE` 时，只能创建通知指定的一份新提供者设计包。已经发布但尚未交回提供者设计包的派生授权优先于普通下一计划，计划支撑不得同时发送 `PLAN-WRITE-RELEASE`。不得与计划支撑或执行智能体同时写入。通知目标只取正式登记的平台任务身份，不得按标题或名称猜测。正式发布和正常执行期间设计包冻结。

计划支撑智能体收到 `PLAN-PACKAGE-READY-NOTICE` 后先只读核对正式设计提交、plan blob、范围、具名依赖、验证合同和工作区占用。取得登记轮次唯一写权后，可以在该计划原目标和登记范围内按需新建或修改必要设计文件；若设计包发生变化，必须先形成、验证、提交并推送新的精确版本 / blob。实际接口完整且足以满足消费验证矩阵时，把最终版本登记为 `可执行`，验证、提交并推送，然后发送 `PLAN-INDEX-RESULT` 和 `PLAN-AVAILABLE-NOTICE`。必需函数缺失但可精确合同化时，建立派生需求、把消费计划登记为 `待激活`，验证、提交并推送，然后发送 `PLAN-INDEX-RESULT` 和 `DERIVED-REQUIREMENT-NOTICE`，不得通知执行智能体。提供者实施后，只有真实能力满足消费合同，或消费计划当前阶段明确允许“未实现”且骨架足以通过其验证矩阵时，才把消费计划转为 `可执行`；否则保持 `待激活`。无法在原目标内补齐或合同化时不得修改索引，只发送具名 `PLAN-INDEX-RESULT`。收到执行事实后，没有明确的“请求设计包修订”，或问题属于代码实现、环境、权限或通道问题时，不取得设计文件写权。只有请求成立且确属计划 / 设计缺口时，才在原目标内形成修订版本；修订所需文件不存在时可以新建，完成后发送 `PLAN-SUPPORT-NOTICE`。

具有执行写范围的计划同时满足下列条件后，计划智能体可以发布待登记设计包；只有计划支撑智能体复核并写入计划索引后，该计划才成为 `可执行`：

```text
依赖已满足；消费计划只有预冻结合同时只允许待激活登记，派生需求提供者计划可以把该合同作为直接实现真实能力或接口骨架的待实现目标
单函数流程图组、根函数 / 被调函数合同、节点指令、详细设计和计划范围一致且双向覆盖
详细设计必填内容完整、未决项为空，执行智能体无需继续作设计裁决
实际接口复核通过；消费计划若只有预冻结待实现接口合同，必须存在派生需求并登记为待激活；派生需求提供者计划按合同复核待实现目标
计划正文已冻结具名依赖、所有权与预期 Git 合同；计划索引登记由计划支撑智能体在后续独立步骤完成
文档治理验证通过
中央治理精确提交完成，且以非强制方式推送成功
```

设计包推送后，计划智能体发送：

```text
PLAN-PACKAGE-READY-NOTICE
来源计划任务
正式设计提交
新计划路由、路径、版本和 plan blob
具名依赖和影响范围
治理验证
计划智能体已经释放单工作区写入权
请求计划支撑智能体复核并登记计划索引
```

计划智能体不得发送该通知之外的跨智能体消息，不直接通知执行智能体，也不得在发送后自行继续下一份计划。计划支撑智能体接管登记后可在当前包原目标内按需新建或修改必要文件；复核失败时发送 `PLAN-INDEX-RESULT` 并退回同一设计包修正权；复核成功且接口完整时登记为可执行并发送 `PLAN-AVAILABLE-NOTICE`；存在派生需求时登记消费计划为待激活并发送带目标任务身份和幂等关联键的 `DERIVED-REQUIREMENT-NOTICE`。执行 clean 终止、工作区无其它写入者且不存在尚未消费的派生授权时，计划支撑智能体才能发送普通下一轮的 `PLAN-WRITE-RELEASE`。

## 验证与停止

设计治理至少运行：

```powershell
git diff --check
python .\tools\check_specs.py --strict
```

只暂存当前智能体拥有的本轮设计包文件，按 `AGENTS.md` 精确提交并非强制推送。目标分支、主线发布占用、远端前进、同文件 WIP、验证或推送任一不安全时停止，不扩大范围。

本技能只形成、登记或修订当前智能体拥有的设计治理事实；`PLAN-PACKAGE-READY-NOTICE` 不等于计划已登记，`DERIVED-REQUIREMENT-NOTICE` 不证明接口骨架或真实能力已实现，`PLAN-AVAILABLE-NOTICE` 只由计划支撑智能体在可执行索引提交推送后发送，也不证明代码已修改、构建通过或能力已闭环。
