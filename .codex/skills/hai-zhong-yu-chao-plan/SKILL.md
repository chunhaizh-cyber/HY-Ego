# 海中鱼巣制定计划

## 智能体类型与权威入口

只在当前顶层任务树为计划智能体或计划支撑智能体类型时使用本技能。遵守 `AGENTS.md`；设计包所有权、消息边界、执行智能体自主 S0 和智能体切换读取 `.codex/rules/设计执行双窗口交互规则.md`；单工作区写入占用、`main` 基线、发布与验证读取 `.codex/rules/单工作区串行执行与发布规则.md`。

计划任务树只能把互不重叠的设计包切片交给同类型 / 只读子智能体，不得让后代切换为其它写类型。顶层统一复核差异并串行完成设计 Git 收口。

- 计划智能体只接收自身沿既有总目标推导的目标或交互智能体发送的目标，负责创建新计划以及创建该计划所需的现状扫描、规范治理、流程图、逐节点分析、详细设计、接口冻结和计划拆分，不接收执行问题；每份完整新设计包验证、提交并推送且计划状态成为 `可执行` 后，只向唯一登记的既有执行智能体发送 `PLAN-AVAILABLE-NOTICE`。
- 计划支撑智能体只读接收配对执行智能体的结构化执行事实；只有执行侧在实施既有计划时报告具名计划 / 设计问题、明确请求修订，且支撑侧复核确认缺口属于设计包后，才接管受影响包并在原目标内形成修订版本，只向来源执行智能体发送 `PLAN-SUPPORT-NOTICE`。选择、S0 PASS、正常完成、纯代码问题和环境问题不触发写入。

不得硬编码仓库盘符或旧仓库名。先用 Git 顶层、当前分支、HEAD、`origin/main` 和 dirty state 解析唯一主工作区事实；当前工作区不是 `main`、远端已经前进或存在其它写入占用时停止受影响切片并报告 DRIFT。

本技能只做项目设计包治理：可以读取代码事实，并按所有权建立或修订正式规范、规范目录、冲突登记、流程图、详细设计、知识图谱、计划和计划索引项；不修改 C++ / 工程 / 自检、施工记录或验证记录，不运行 C++ 构建、程序或业务自检，也不修改 `AGENTS.md`、`.codex/rules/` 或 `.codex/skills/`。

## 前置读取

先读取 `AGENTS.md` 要求的共同入口，再按任务读取：

```text
目标正式规范与相邻边界
有效流程图与详细设计
代码差距或现行流程图 / 详细设计审查材料
当前代码 / 接口 S0 事实
计划/计划索引.md
当前 Git / 单工作区事实
计划支撑智能体追加读取配对执行智能体的最新结构化执行消息
```

聊天、旧项目规则、过期计划和旧函数只能作为来源证据。代码实施单位必须来自现行规范定义的业务对象、领域服务、结构闭环和有效设计，不能按旧函数一对一迁移。

缺少正式规范、有效设计、当前接口事实或必要差距记录时，在当前智能体拥有的设计包内补齐必要产物；无法补齐时停止，并登记具名缺口，不能凭假设生成可执行代码计划。计划支撑智能体不得借补齐之名扩展到原目标外的新设计包。

## 计划形成算法

按以下顺序工作：

```text
确认当前智能体类型、设计包所有权、目标规范与完成边界
-> 计划智能体确认本任务是在创建新计划；计划支撑智能体确认具名执行问题修订请求与缺口归属成立
-> 建立或修订正式规范、规范目录与冲突登记
-> 建立函数清单、调用图和单函数流程图组，冻结每图完整签名、参数 / 结果、节点身份、分支和终止路径
-> 按 `.codex/rules/设计执行双窗口交互规则.md` 第 6.1 节逐函数、逐节点完成实现分析
-> 确认、归并所需函数和共享数据 / 事务 / 版本合同
-> 形成可直接编码的详细设计与知识图谱
-> 核对当前代码和实际接口
-> 核对流程图函数—节点（被调函数 / 指令）—结构—返回—验证双向覆盖和范围一致性
-> 按业务对象、文件、结构、公开接口和装配面拆分
-> 判断真实依赖与所有权隔离
-> 形成计划正文及机械阶段
-> 在计划索引列表中登记计划路径、版本、计划状态和具名依赖
-> 验证、精确提交并非强制推送设计结果
-> 每完成一份计划就发布该精确版本 / blob 的 `可执行` 设计事实
-> 计划智能体向唯一登记的既有执行智能体发送 PLAN-AVAILABLE-NOTICE 后继续形成下一份新目标计划
-> 计划支撑智能体完成执行问题修订后向来源执行智能体发送修订事实；没有修订请求或不是设计包缺口时保持只读
```

流程图的最小正式单位是一个函数，但计划范围仍由现行规范与有效设计裁决。一个计划可以包含多个函数；必须使用单函数流程图组和调用图表达，不得把多个函数的内部过程合并为一张图。

## 从流程图形成详细设计

严格执行 `.codex/rules/设计执行双窗口交互规则.md` 第 6.1 节。流程图只定义单个函数的过程，不是执行智能体直接写代码的依据；先固定函数清单、每图唯一根函数、完整参数 / 结果和调用图，再把每个节点转换成被调函数分析或本函数内指令分析，最后写入完整详细设计。

形成详细设计时依次完成：

```text
固定函数清单、调用图和每份流程图的唯一根函数
-> 冻结根函数完整签名、参数、返回结果和节点类型
-> 读取每个函数 / 节点的规范、相邻边、当前代码和合同
-> 对函数调用节点写清参数 / 结果绑定，对指令节点写清具体操作、事实读写、状态变化、分支、事务、结果和验证
-> 裁决现有函数复用或新增，并冻结根函数与被调函数完整合同
-> 归并共享函数、DTO、事务和版本合同，冻结唯一所有者
-> 写入数据、调用、事务、失败、文件和验证合同
-> 建立根函数流程图到节点（被调函数 / 指令）、结构 / 验证及其反向引用
-> 覆盖全部流程边和终止路径
-> 通过当前接口或预冻结合同复核
-> 通过无需执行智能体继续作设计裁决的可实施性审查
```

详细设计必须完整记录第 6.1 节列出的文档身份、函数流程图合同表、节点实现表、函数合同表、数据合同、调用与事务、失败合同、代码映射、验证矩阵和空未决项。凡仍需执行智能体决定字段、类型、签名、参数 / 结果绑定、判断条件、版本、所有权、调用顺序或错误处理的设计，保持 `待激活`。

流程图与详细设计生产可以按无重叠根函数组交给同类型子智能体。顶层先冻结函数清单、调用图、每图唯一根函数、共享合同和唯一所有者；子智能体只写分配的单函数流程图、节点分析或独立详细设计切片；共享合同、跨函数去重、调用图闭合、双向覆盖、计划索引和 Git 收口由顶层串行完成。不得让两个子智能体分别定义同一函数、节点、DTO、事务、版本或同一文档切片。

### 真实依赖

只有下列情况可以登记依赖：

- 当前切片必须消费尚未形成、且尚未冻结为精确待实现合同的具名正式产物或接口。
- 文件、结构、公开接口或装配所有权无法通过拆分隔离，存在不可消除的先后。

同主题、同总计划、生成顺序、文档顺序、目录或验收顺序都不是依赖。仅共享工程、入口、统一运行器或装配文件时，优先拆成私有实现切片和唯一共享接线切片。

提供者实现尚未形成，但模块 / 文件、公开 DTO、完整签名或等价行为、ABI / 规则版本、输入输出所有权、逻辑内返回、内部错误、提供计划、消费计划和漂移退回点已经冻结时，该关系改记为“预冻结待实现接口合同”，不再作为等待上游实现完成的设计启动依赖。代码实施仍由唯一执行智能体在同一主工作区按所有权和真实依赖串行推进；消费者不得补造同名接口或修改提供者文件，最终真实接线验证前不得宣称接口已实现、代码已编译或能力已完成。

依赖门控计划必须写明：

```text
已验证当前事实
具名前置计划和产物
待消费的文件、符号、签名与行为
无法隔离的原因
解除条件
执行前复核命令
接口漂移的精确退回点
```

依赖未满足或接口漂移时，只登记受影响计划的精确门禁，不冻结无关计划，不把预期产物写成当前事实，也不生成泛化的“等待后续处理”。

### 串行实施与所有权

无未合同化真实依赖的计划独立登记。多个计划即使文件 / 结构 / 接口所有权互斥，也只表示可独立设计，不授权并行写代码；唯一执行智能体按计划状态、具名依赖和共享所有权串行消费。涉及共享工程、入口、统一运行器或装配面的计划必须明确唯一所有者和实施顺序。

代码计划必须冻结计划编号、版本、预期 `main` 基线、文件 / 结构所有权、接口证据、验证矩阵和必要的串行顺序；实际仓库顶层、分支、HEAD、`origin/main`、dirty state 和远端事实由执行智能体在 S0 直接读取 Git。

连续消费多份计划时，执行通道只由 `.codex/rules/` 绑定：一个长期执行顶层任务、唯一主工作区、`main` 和多个串行计划段，不写入计划索引。每个计划段分别使用计划编号 / DQ、计划版本和 blob、中央设计提交、当前 `main` HEAD、允许 / 禁止范围、合同和验证矩阵；结果 / WIP 断点由 Git 提交与结构化消息证明。同一时刻只能有一个活动计划段，段间必须恢复工作区 / index clean；不得为每份计划重复建立派发状态或执行许可。

## 计划正文

完整计划放在 `计划/`。代码实施切片至少包含：

```text
计划身份、版本和稳定设计状态；当前计划状态只在计划索引维护
依据：正式规范、流程图、详细设计、差距 / S0 记录
已验证前置事实
实施范围与明确排除项
目标服务、结构和公开接口
预冻结待实现接口合同、提供者与消费者（适用时）
允许文件与禁止文件
唯一专属施工记录与验证记录路径
机械步骤 S0/S1/...
入口拒绝、内部错误和失败收口
验证命令与成功条件
实施后证据
完成声明边界
```

面向常规执行模型的每一阶段明确区分：已验证前置事实、待实施目标、实施后可核对证据、只有前置成立后才能判断的完成 / 退回条件。

新增或改名代码文件时，读取 `规范/代码文件建立归属与模块命名规范.md`，列出文件分类、项目项类型、`include` / `import` 路径、工程登记、生产 / 自检依赖方向和 `入口.cpp` 不恶化边界。

计划、流程图和详细设计必须互相列明路径且范围一致。纯规则或只读治理确实不需要流程图 / 详细设计时，写明不适用原因和替代正式依据。

## 登记与设计发布

计划形成后，叶子正文冻结为不可变施工合同，只写计划身份、版本、稳定设计状态、目标、依据、允许 / 禁止范围、唯一专属施工 / 验证记录路径、失败收口和验证合同，不复制当前 `待激活 / 可执行 / 已退出` 状态，也不写当前派发、S0 或执行过程。计划索引以列表形式登记路径、版本、具名依赖和唯一计划状态 `待激活 / 可执行 / 已退出`；计划之间只登记具名依赖，不另建层级结构。执行通道由 `.codex/rules/` 管理；唯一工作区、`main`、HEAD、提交、dirty state 和远端直接读取 Git。施工过程只允许写入计划冻结的专属施工 / 验证记录，不另建共享 Markdown 状态台账。

计划智能体按总目标逐份创建新计划及其前置设计产物，不等待上一份计划执行或整批设计完毕。每份计划的完整设计包通过治理验证、登记为 `可执行`、精确提交并非强制推送 `origin/main` 后，只向唯一登记且用户未撤销的既有执行智能体发送一次幂等 `PLAN-AVAILABLE-NOTICE`；随后停止修改该精确设计包并继续形成下一份新计划。通知目标只取用户在计划任务自身窗口明确指定的平台任务身份，或 `INTERACTION-GOAL` 携带的精确平台任务身份；标题、分支或名称不能建立登记，也不得自行猜测或创建接收任务。该绑定可在同一计划顶层任务后续自推导目标中复用，直到用户撤销、替换或平台证明不可达。正式发布和正常执行期间设计包冻结；执行智能体选择计划、首次发送 S0、S0 PASS、正常施工或完成都不产生支撑接管。

计划支撑智能体收到执行事实后先只读核对结构化消息与 Git。没有明确的“请求设计包修订”，或问题属于执行智能体可在现行白名单和设计内解决的代码实现错误、环境、权限或通道问题时，不取得设计文件写权。只有请求成立且缺口确实要求修改计划、规范、流程图、详细设计、知识图谱、接口合同、范围、依赖或验证合同时，才把受影响计划版本改为 `待激活`，不改写不可变旧版本；在原目标内同步修订必要产物，形成新版本 / blob 后恢复为 `可执行`，再只向来源执行智能体发送 `PLAN-SUPPORT-NOTICE`。如果必须改变用户目标、修改智能体协作规则或无法裁决机器语义，停止并在自身用户可见窗口列出问题，等待用户直接消息。

具有执行写范围的计划同时满足下列条件后，当前设计包所有者即可发布 `可执行`：

```text
依赖已满足，或提供者—消费者关系已经合法合同化
单函数流程图组、根函数 / 被调函数合同、节点指令、详细设计和计划范围一致且双向覆盖
详细设计必填内容完整、未决项为空，执行智能体无需继续作设计裁决
实际接口或预冻结待实现接口合同复核通过
计划索引已列明具名依赖和计划状态，计划正文已冻结所有权与预期 Git 合同（适用时）
文档治理验证通过
中央治理精确提交完成，且以非强制方式推送成功
```

设计发布后，计划智能体发送：

```text
PLAN-AVAILABLE-NOTICE
来源计划任务
正式设计提交
计划索引路径和 blob
新计划路由、路径、版本和 plan blob
计划状态必须为可执行
具名依赖和影响范围
通知只触发执行智能体重读正式仓库和候选扫描
不构成计划选择、执行许可、S0 PASS、开始、继续或停止命令
```

计划智能体不得发送该通知之外的跨智能体消息，不向多个执行任务广播，也不自行创建或选择新的执行任务。没有唯一可识别接收方时，在自身窗口报告通知不可达，但不回退已正式发布的计划状态。计划支撑智能体只发送正式修订事实，不发送开始、继续、停止、恢复、S0 接受或下一项指令。不得把通知、`可执行`、目标标题或任务 active 状态解释为已经实施。执行智能体仍从正式计划索引自主选中计划，只修改当前计划段允许的代码、工程、自检及专属施工 / 验证记录，并只向配对计划支撑智能体返回结构化消息。

## 验证与停止

设计治理至少运行：

```powershell
git diff --check
python .\tools\check_specs.py --strict
```

只暂存当前智能体拥有的本轮设计包文件，按 `AGENTS.md` 精确提交并非强制推送。目标分支、主线发布占用、远端前进、同文件 WIP、验证或推送任一不安全时停止，不扩大范围。

本技能只形成、修订并发布当前智能体拥有的设计包事实；`PLAN-AVAILABLE-NOTICE` 只唤醒既有执行智能体重新读取正式状态，不指挥其选择或实施，也不证明代码已修改、构建通过、任务已集成或能力已闭环。
