# 海中鱼巣继续路由

## 1. 固定语义

裸 `继续` 表示继续当前顶层任务树已经明确的角色和切片，不自动切换角色、扩大范围、建立工作树或选择一个与当前上下文无关的新目标。

遵守 `AGENTS.md`、协作规则和单工作区发布规则。不要硬编码仓库路径；从 Git 顶层和当前正式文件读取事实。

## 2. 识别方法

按以下顺序识别当前工作：

```text
用户最近明确的目标和角色
-> 当前任务树及已声明所有权
-> 尚未收口的工作和最新证据
-> 计划索引、目标计划或维护队列
-> Git 分支、HEAD、远端、index 和 dirty
```

任务标题、窗口名称、模型和旧消息不能覆盖当前正式事实。

若角色和切片可以唯一判断，用一句话说明判断后直接继续。可逆的小缺口自行处理；只有角色、目标、关键语义或所有权确实无法裁决时，才保持只读并请求最小澄清。

恢复交互智能体任务时，同时核对当前顶层任务树内已实际创建的子智能体状态和回执；可复用的子任务继续复用，仍存在合格独立切片时按协作规则补充分派。不得把任务树内子智能体回执当成正式事实，也不得因等待子任务而停止推进不重叠主线。

## 3. 各角色的继续方向

- 交互智能体：继续用户直接交付的当前切片，或继续已明确的讨论 / 审查；跨产物工作不视为切换角色，并按协作规则复用或创建合格子智能体切片。
- 计划智能体：继续尚未交付的新目标设计包、创建侧验证和索引登记；已经交给执行智能体且发生具名退回的受影响切片不与计划支撑并行修改。
- 计划支撑智能体：只继续执行智能体已具名退回的无法裁决问题、裁决和受影响设计修订；没有执行退回时保持待命，不终审或登记新计划。
- 执行智能体：重读计划索引和 Git；有活动计划就继续该计划，没有活动计划就按正式状态选择一份可执行计划并 S0。
- 流程图 / 能力目录维护智能体：沿正式队列和已发布基线继续各自专属目录。
- 集成验收智能体：只继续已冻结提交和验收矩阵，不把新 WIP 纳入输入。
- 只读模式：继续指定对象的事实、差异、风险和建议，不产生写权。

## 4. 中断恢复

上一轮被中断时先核对本任务启动的进程、HEAD、dirty、已有产物、验证结果和精确续点。用户已暂停或改向时停止旧动作。只恢复当前顶层任务树及其已派发子智能体，不自动恢复任务树之外的其它任务、智能体或计划。

`继续` 不免除重新读取可能已经变化的正式状态，也不要求重复已经稳定且未漂移的全部历史检查。
