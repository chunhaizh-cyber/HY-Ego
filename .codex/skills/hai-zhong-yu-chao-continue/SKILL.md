# 海中鱼巣继续路由

## 固定语义

裸 `继续` 只表示：

```text
继续当前顶层任务树已明确的智能体类型与当前切片
```

不得解释为切换智能体类型、建立额外工作区或跨过当前权限边界。交互智能体可以沿用户已经明确交给本窗口的任意项目切片继续；计划智能体不据此处理执行问题或修改计划索引，但收到正式 `DERIVED-REQUIREMENT-NOTICE` 后可以继续该通知唯一指定的提供者设计包；执行智能体可以按计划索引中的计划状态、具名依赖和自身执行通道自主选中计划；计划支撑智能体继续新计划索引登记、当前包派生需求治理，或执行侧已经具名请求修订且复核成立的设计包。遵守 `AGENTS.md`、`.codex/rules/设计执行双窗口交互规则.md` 和 `.codex/rules/单工作区串行执行与发布规则.md`。

不得硬编码仓库路径。用 Git 顶层、当前分支、HEAD、`origin/main`、dirty state、远端事实和 `.codex/rules/` 中的执行通道合同解析当前技术身份。

## 识别顺序

按以下事实识别当前智能体类型，不按任务标题或“下一步”猜测：

```text
用户最近一次明确智能体声明
-> 平台顶层任务 / 协作代理关系
-> 当前任务是否在创建新计划，或是否存在执行侧明确的设计包修订请求
-> 计划索引中的计划列表、计划状态和具名依赖
-> `.codex/rules/` 与 Git 中的执行通道身份
-> Git 顶层、分支、HEAD、origin/main、dirty state 和远端事实
-> 当前计划、最新结构化消息或只读问题集
```

聊天声明与计划合同或 Git 事实冲突、任务树同时出现两种写类型、目标无法唯一识别或 Git 身份漂移时，保持只读，报告具名 DRIFT；不得先行动再补规则。

执行动作前用一句话说明：

```text
当前识别为 <智能体类型 / 技术模式>，本轮继续 <当前切片>，不切换类型。
```

## 智能体路由

### 交互智能体

继续用户已经明确交给本窗口的当前切片。交互智能体拥有完整仓库权限，可以继续规则、项目规范、流程图、详细设计、知识图谱、计划、计划索引、代码、工程、自检或记录工作，也可以只讨论或把目标交给计划智能体。继续前核对文件与语义所有权；无关 dirty 不阻断，同文件或同语义切片已有所有者时先完成交接。发布仍须取得唯一 Git 发布租约。

### 计划智能体

继续创建新计划及其所需的完整设计包：现状扫描、正式规范及目录、冲突登记、流程图、逐节点分析、详细设计、知识图谱、接口冻结和不可变计划合同。收到 `DERIVED-REQUIREMENT-NOTICE` 时，只创建通知指定的一份新提供者设计包，不修改来源消费包。不得修改计划索引、代码 / 工程 / 自检、施工 / 验证记录或智能体协作规则，也不直接处理执行消息。完整设计包通过治理验证、精确提交并推送后，只向唯一登记的计划支撑智能体发送 `PLAN-PACKAGE-READY-NOTICE`，随即停写。登记拒绝时只修正该包；登记为可执行后等待执行 clean 收口及 `PLAN-WRITE-RELEASE`；登记为待激活且收到新的 `DERIVED-REQUIREMENT-NOTICE` 时，只继续该派生提供者包，不得自行选择其它下一计划。

### 执行智能体

重读计划索引，根据计划状态、具名依赖和自身执行通道自主选中一份计划；先核对计划版本与 blob、当前 `main` / `origin/main`、计划段起点和 S0 结果，再按计划修改允许的代码 / 工程 / 自检 / 唯一专属施工记录 / 验证记录，完成计划要求的集成级验证，精确提交并非强制推送 `origin/main`。

除计划冻结的专属施工 / 验证记录外，不得写其它 Markdown、计划、索引、规范、流程图或详细设计。计划段选择、S0、完成、漂移或失败只向配对计划支撑智能体发送结构化消息；正常结果或普通合法 WIP 使工作区 / index clean 后可以继续检查列表中的其它无关 `可执行` 计划。规则允许的 `DESIGN-DRIFT-WIP` 推送并 clean 后进入 `DESIGN-DRIFT-WAIT`，等待计划支撑修订，不选择其它计划。

### 计划支撑智能体

收到 `PLAN-PACKAGE-READY-NOTICE` 时，先复核正式提交；取得当前包和索引切片所有权后，可在原目标和登记范围内按需新建或修改必要设计文件。提供结果足以满足消费计划当前阶段验证矩阵时形成最终精确版本并登记为可执行，取得发布租约提交推送，再发送 `PLAN-INDEX-RESULT` 和 `PLAN-AVAILABLE-NOTICE`。必需函数不存在但可精确合同化时，冻结合同、建立派生需求、登记消费计划为待激活，发布后发送 `PLAN-INDEX-RESULT` 和 `DERIVED-REQUIREMENT-NOTICE`。执行侧具名设计缺口仍先形成安全 `DESIGN-DRIFT-WIP`，再修订关联设计包。无关 dirty 和无关写入者不阻断支撑工作；同文件、同语义、索引或发布租约冲突才停止。不得修改代码、施工记录或智能体协作规则，不得自行设计派生需求提供者，也不得独立发起无关新计划或扩大用户目标。

### 验证或只读技术模式

集成级验证属于执行智能体当前计划段的技术步骤，只继续当前计划合同和 Git 事实共同指向的身份核对、验证和授权发布，不建立独立集成工作区。只读模式不改变所属智能体类型，只继续指定提交、对象和问题集上的事实、差异、证据、风险与建议核对，不产生写权。

## 智能体类型切换

裸 `继续` 永远不构成计划、执行或计划支撑智能体的类型切换。这些窗口切换必须由用户明确要求，并在受影响切片完成交接后整体切换；交互窗口沿用户既有目标跨项目产物继续不构成类型切换。切换后重新读取 Git、计划索引、目标计划 blob、最新结构化消息和实际接口。

计划、执行和计划支撑任务树默认不跨写类型。交互任务树可以把不重叠的明确切片分配给写入子智能体，但子智能体不得自行取得 Git 发布租约。

## 中断恢复

上一轮被中断时先核对当前智能体启动的进程、唯一工作区、分支、HEAD、dirty state、已形成证据和未完成门禁。用户已经暂停或改向时停止本窗口启动的相关动作。只恢复当前智能体当前切片，不自动恢复其它智能体或其它计划。
