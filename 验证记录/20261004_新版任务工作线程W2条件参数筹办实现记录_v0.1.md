## 1. 直接代码切片

本片沿用户持续目标，在已发布 W1 方法宽召回之后实现首个受限 W2：

```text
待检查条件任务
→ manager取得单任务工作占用
→ worker逐候选筹办参数和条件
→ manager使用同一正式世界树入口独立重算
→ 两份current结果完全一致
→ 发布运行期筹办结果
→ 任务保持待检查条件，等待self后继判断
```

冻结边界：W2只形成当前运行期筹办材料，不持久化第二份事实，不批准或执行
方法，不建立子需求，不把线程状态写成任务状态。实际对象只有唯一匹配时才形成
参数绑定；不按顺序随意选取首个候选。二次特征条件、状态或动态概念条件、
`有序成立`和`条件选择`没有现行唯一求值语义时明确返回`结构缺口`。

安全值、服务值当前值维持既有不变量：`0 <= 当前值 <= INT64_MAX`，根目标为
`INT64_MAX`，差距直接计算为`INT64_MAX - 当前值`，该减法不会溢出。通用有向
计算若理论结果越界，须在运算前分别饱和为`INT64_MAX`或`INT64_MIN`；不能让
C++有符号溢出实际发生。本片复核现有根需求代码已经按该口径执行，无需改动。

允许修改新版世界树、任务管理线程、任务工作线程及本验证记录。旧世界树、旧
self、流程图、规范、计划清理、根目录 obj 和数据目录等其它所有者 WIP 均原地
保留，没有纳入本片。

## 2. 实际代码结果

1. 世界树增加`查询可检查条件任务()`，只向manager返回当前处于
   `待检查条件`的任务。
2. 世界树增加`筹办任务条件和参数()`。入口重新读取任务、current候选材料和
   唯一需求，核对任务状态、材料绑定、查询完整性及候选方法身份。
3. 普通需求直接使用目标宿主；根需求通过根实际特征反查唯一持有对象。随后确定
   目标场景，枚举该场景、子场景、成员存在和子存在，形成本次只读匹配范围。
4. 参数规格按存在概念、特征类型及可选值域逐项匹配。只有一个实际对象和一个
   实际特征满足同一规格时形成绑定；多候选、缺材料和结构错误分别保留，不用
   首项顺序代替选择规则。
5. 参数绑定形成后调用现有`建立参数场景()`再次验证方法、角色、存在、特征和
   场景关系。参数场景只在本次调用栈内存在，不持久化。
6. 条件结果配对逐项核验。当前仅实现`单项`、`全部成立`和`任一成立`；条件项
   可核对存在概念、特征类型和当前准确值是否落入要求概念值域。每个配对保留
   条件节点及其对应结果节点，但结果侧不在 W2 被执行。
7. worker新增`检查条件`工作种类，调用世界树 W2 入口并将结构化结果交回
   manager；活动容量、同任务占用、精确重复和确认释放合同沿用 W1。
8. manager优先扫描 W2 任务；没有 W2 时继续派发 W1。W2完成后manager再次
   调用世界树入口独立重算，只有两份完整结果完全相同才发布
   `条件筹办已完成`。
9. W2无论得到可用条件、材料缺口还是结构缺口，均进入manager运行期阻塞集合，
   等待self后继判断或新材料，不在相同current事实上空转重派。
10. manager派发下一工作时先清除该任务旧的最近筹办结果；新结果携带原工作种类
    和阶段状态，读取者不会把旧 W1 结果误认为 W2 结果。

## 4. 函数级代码知识变更清单

| 函数或类型 | 变化、用途与明确非职责 |
| --- | --- |
| `新世界任务条件筹办结果`及其子DTO | 新增 W2 运行期值式结果，表达候选参数绑定和条件核验；不形成持久事实，不批准方法 |
| `新_世界树类::查询可检查条件任务() const` | 新增manager专用current任务窄视图；只返回`待检查条件`任务 |
| `新_世界树类::筹办任务条件和参数(稳定编码) const` | 新增 W2 组合只读入口；读取任务、需求、候选材料、方法、场景、存在、特征和概念，形成可复核筹办材料；不写任务状态、不执行方法 |
| `新任务工作种类`、`新任务工作处理结果` | 扩展`检查条件`工作及结构化结果；不新增第二工作线程所有者 |
| `新_任务工作线程类::实现::运行()` | 在既有单次工作消费中增加 W2 调用和结果分流；不重试结构缺口、不批准执行 |
| `新_任务工作线程类::提交工作(...)` | 接受 W1 与 W2 两种合法工作，继续执行工作号、任务占用和容量校验 |
| `新_任务管理线程类::实现::尝试派发筹办工作()` | 由原 W1 专用派发扩展为优先 W2、其次 W1；不改变任务优先级和执行许可 |
| `新_任务管理线程类::实现::处理已完成工作(...)` | 新增 W2 独立重算、精确互证、结果发布及运行期阻塞；不把技术缺口写成任务失败 |
| `新_任务管理线程类::实现::运行()` | 调用统一筹办派发入口，保持既有承接消息、停止和join边界 |
| `新任务筹办处理结果`及状态 | 增加 W2 worker结果、独立结果和`条件筹办已完成`状态；仍是有界运行期current材料，不是历史账 |

上述函数和类型在结果提交发布后需要由代码知识维护者按结果提交新建或更新用途

## 5. 完成边界与下一步

本片证明的是“W1已有候选 → worker逐候选筹办 → manager独立重算”的 W2
运行链。它没有证明完整自我内部治理闭环，也没有实现方法选择、执行许可、方法
执行或结果复核。

下一步应把 W1 完整零候选以及 W2 条件/参数结果具名反馈给self；self fresh读回
后决定等待、缺口后继或进入执行前判断。没有明确求值语义的条件继续保持结构
缺口，不能用默认成功或首项选择绕过。
