## 1. 直接代码切片

用户已经明确：自我安全值和服务值的当前值范围是
`0 <= 当前值 <= INT64_MAX`，目标值固定为 `INT64_MAX`；当前值不足时由
self 自动承接对应长期根需求；同一需求复用唯一任务；已完成、已失败、
已取消任务可在新的当前需求复核仍为正向缺口时重新启用。

本片实现：

```text
self首次或事实变化后fresh复核双根
→ 需增加的根形成self内部自动决议
→ manager异步承接
→ 建立或复用唯一任务
→ 若为终结任务，世界树再次fresh复核当前需求
→ 仍需增加才把原任务重新置为“待查找方法”
→ 正式读回任务与任务虚拟存在
```

本片没有实现任务工作线程、候选方法查询、方法实际执行、外设效果、影响
评估或结果后继，因此不声明完整内部治理闭环已经成立。

允许修改的生产文件为新版self、manager、世界树、任务领域头源；另新增本
专项记录。现有旧self、旧世界树、规范、流程图、计划清理、obj及数据目录
WIP均原地保留，没有纳入本片。

## 2. 实际代码结果

1. 世界树初始化双根时核验两个目标概念均为I64单点
   `[INT64_MAX, INT64_MAX]`，两个实例当前值均为非负I64。
2. 世界树每次根复核后核验通用需求服务结果：
   - 当前值等于`INT64_MAX`时必须为已满足且准确差异为0；
   - 当前值小于`INT64_MAX`时必须为需增加，准确差异必须等于
     `INT64_MAX - 当前值`。
   该减法在已核验范围内不会溢出；没有复制下层通用饱和差值算法。
3. self首次复核或事实变化复核得到“需增加”时，为安全、服务根分别保留
   至多一个内部自动承接项。它不是外部邮箱消息，不占外部接纳容量；manager
   尚未启动时保留原决议并按应用配置时点重试。
4. 自动决议区分首次复核和正式状态变化复核。状态节点稳定编码作为根决议
   次序；manager每根只保留最近一次已完成自动决议的共享结果。相同状态精确
   重放返回原结果，更旧状态拒绝为过期决议，不建立永久历史消息账。
5. 显式旧承接沿用原合同，只建立或复用任务，绝不隐式重新启用终结任务。
   只有自动决议可以请求重新启用；世界树仍在同一串行区内重新读取需求，
   不信任self传来的旧满足结果。
6. 任务领域新增专用重新启用入口，只允许已完成、已失败、已取消进入
   `待查找方法`；通用`修改任务状态`的终结态禁止迁移规则没有放宽。

- 目标不是I64单点`INT64_MAX`、根当前值为负数时，初始化分别拒绝；
