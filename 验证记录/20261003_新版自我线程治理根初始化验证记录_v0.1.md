## 2. 实际实现

自我线程初始化顺序固定为：

```text
新版领域基础与世界树根
→ 自我所在场景
→ 唯一自我存在
→ 独立需求树结构
→ 按特征类型根唯一定位安全/服务实例特征
→ 建立或精确复用安全/服务需求双根
→ 独立方法组织根
```

实现结果：

1. `新_世界树类`持有新版需求服务和方法服务，但需求树、双根和方法根只由自我线程按上述顺序调用；双根编排入口不是普通应用公开入口。
2. 安全、服务选择器必须是特征类型根；每个类型根在唯一自我的实例特征中必须恰好命中一个特征节点。
3. 双根结果要求两个实际特征、两个需求根和两个需求列表项均存在、有效且分别互异。
4. 自我线程初始化结果和快照读回需求树根、安全根需求、服务根需求和方法组织根。
5. 初始化请求比较包含完整双根定义；精确重复返回无变化，异义请求或第二活动线程对象返回唯一自我冲突。
6. 双根或方法根失败后保留已经建立的世界、自我前缀，同一请求可继续完成后续阶段，不建立第二个正式自我。
7. 若场景服务返回“存在已建立但初始状态未全部挂接”，当前底层没有合法续挂入口；自我线程保存该未完成前缀并拒绝再次创建，避免产生多个自我候选，但不伪装为初始化成功。

## 3. 验证

仓库外隔离目录：

```text
D:\TEMP\海中鱼巣\NEW-SELF-ROOTS
```

执行并通过：

1. 主工程 Debug x64：`MSBuild 海中鱼巣.vcxproj /t:Build /p:Configuration=Debug /p:Platform=x64`，退出码 0。
2. 主工程 Release x64：`MSBuild 海中鱼巣.vcxproj /t:Build /p:Configuration=Release /p:Platform=x64`，退出码 0。
3. 隔离验证程序直接编译新版基础数据、领域、世界树和自我线程所需源文件，退出码 0。
4. 隔离成功分支输出：

```text
NEW_SELF_ROOTS_OK scene=375 self=384 safety=486 service=499 method=516
```

5. 以下四个独立进程分支均退出码 0：

```text
成功
缺特征
非类型根
同类型根
```

成功分支覆盖：世界树、需求树、方法根、自我场景、自我存在、双根建立；精确重复初始化；第二线程对象冲突；常驻等待、停止、join；快照四根读回。

拒绝分支覆盖：自我不含目标类型特征、选择器不是特征类型根、安全/服务使用同一类型根。

## 4. 证据边界与剩余风险

- 主工程构建证明当前工作树可编译链接；其它所有者 WIP未纳入本片提交，也不能由本记录宣称完成。
- 隔离运行证明本片具名进程内初始化与线程生命周期分支，不证明持久化、跨进程恢复、生产装配或完整内部治理闭环。
- 新版基础数据集仍是进程内底座。需求类和方法类在极端分配异常中的完整事务回滚不属于本片四文件范围；本片没有验证资源耗尽后的底层可恢复性。
- 邮箱、消息分流、任务管理、因果消费及普通应用正式入口仍未实现或未接线。
