## 2. 公开入口施工检查

Debug 与 Release 均逐项通过：

1. 请求纯值 helper 区分错合同并允许组读取零守卫；
2. 已装配且零树时返回非零截止成功空组；
3. 坏合同返回入口拒绝、空树组和空变更代次；
4. 两棵树及一个非根场景建立成功；
5. 零守卫读回两棵完整树，树身份严格升序且共用截止；
6. 非零同代守卫返回同一树闭集；
7. 陈旧守卫返回事实代次漂移与空树组；
8. 结果成功谓词拒绝乱序、重复树和读结果携带变更代次；
9. 并发新增只产生完整旧快照、明确漂移或资源竞争失败之一，不产生部分成功或内部不一致；本次 Debug 实际命中资源失败，本次 Release 实际命中完整旧快照；
10. 并发结束后零守卫最新读取完整取得三棵树。

设计修订前对旧并发断言连续运行 10 轮，10 轮均实际命中 L1 非阻塞许可竞争形成的资源失败，证明 v0.1 的“必定漂移”不是一次性调度波动。该证据用于修订设计，不作为额外验收总数。
