# PRE1 v0.1 修复后第二轮日志观察

## 1. 双配置增量

Debug和Release分别运行隔离候选构建出的同一生产目标 `海中鱼巣.exe --self-test-exit`。每次运行前后只比较固定日志中PRE1具名身份的行数。

| 配置 | 进程退出码 | 运行日志新增 | 逻辑错误日志新增 |
| --- | ---: | ---: | ---: |
| Debug | 0 | 2 | 0 |
| Release | 0 | 2 | 0 |

每次精确两行分别为模块/入口行和摘要行。两配置摘要内容一致：

```text
观察标识=L1-SIMPLIFY-P16-PRE1-STATE-SPEC-PROVIDER-EVIDENCE-S01；结果=通过；验收项数=24；失败项数=0；提供者身份=0x4C31535000000001；直接调用次数=1；去重提供者数量=1；写前事实见证数量=34；当前副本=33；历史副本=1；成功状态=增加/等价/减少/精确重复；拒绝状态=无前状态/入口拒绝/未找到/不可比较；拒绝载荷=全空；正式接线=不适用；正式读回=不适用
```

## 2. 日志非机器事实

专项先计算并冻结24项结构化布尔结果及失败数，随后在独立 `try/catch` 中形成日志；`记录运行日志` 和条件性 `记录逻辑错误日志` 的返回值均被显式丢弃。日志形成或写入失败不会改变数组、失败数、函数返回或进程机器结果。

成功运行只写运行日志。只有失败数非零才尝试写逻辑错误日志；本轮两配置失败数均为0，因此逻辑错误日志新增0。日志只供人读确认自检是否符合预期，不承担provider身份、L1事实或正式读回职责。

## 3. 消费边界

顺序360包装继续使用原P9结构化身份；PRE1日志由其调用链内的P13专项最终汇总边界产生。当前生产调用为0，P16 v0.3仍待激活，因此正式消费者、正式业务入口和正式独立读回按原计划均为 `NOT_APPLICABLE`。这不构成第二轮失败，也不构成服务验收通过。
