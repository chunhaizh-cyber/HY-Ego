# PRE1 v0.1 日志与消费边界

## 1. 日志观察

Debug与Release分别运行同一 `海中鱼巣.exe --self-test-exit`。运行前后在固定日志目录检索下列身份：

```text
P16-PRE1
STATE-SPEC-PROVIDER-EVIDENCE
后继状态规格提供者证据
```

| 配置 | 运行日志增量 | 逻辑错误日志增量 | 进程退出码 |
| --- | ---: | ---: | ---: |
| Debug | 0 | 0 | 0 |
| Release | 0 | 0 | 0 |

顺序360包装函数 `运行L1状态专项自检` 只把70项聚合报告映射到旧身份 `L1-SIMPLIFY-P9-BASELINE-STATE-S01`，没有调用 `记录运行日志` 或 `记录逻辑错误日志`。候选施工验证记录写有“核对正式日志中的专项身份、计数、状态和拒绝分支”，但独立源码和运行日志均没有实现该PRE1观察面。

退出码0只能证明整个受控自检批次没有汇总失败，不能按用户冻结口径单独证明PRE1七项新增矩阵符合预期。日志仍只属于人读观察，不能成为provider身份或L1事实。

## 2. 消费边界

候选中 `形成实际存在I64后继状态规格` 的调用命中为：一个生产定义和 `自检.L1状态.ixx` 内九处调用。排除定义和自检后，生产调用为0。`读取后继状态规格提供者身份` 也只由同模块内部校验和自检消费。

P16 v0.3只有设计、流程图、计划和待激活索引项，没有生产代码。因而当前没有合法生产消费者、正式业务入口或正式独立读回。它们按合同标为 `NOT_APPLICABLE`，不能因为自检编入生产exe而视为正式接线。

## 3. 排除项

本叶零L1写、零外部资源、零P16发布。崩溃、重启、断电和跨进程恢复由用户与目标合同明确排除，均为 `NOT_APPLICABLE`。
