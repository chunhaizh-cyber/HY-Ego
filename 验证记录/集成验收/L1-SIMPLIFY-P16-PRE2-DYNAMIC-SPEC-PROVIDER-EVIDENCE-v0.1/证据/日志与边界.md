# PRE2 v0.1 日志与边界

## 1. 双配置日志增量

Debug和Release分别运行候选归档构建出的同一生产目标 `海中鱼巣.exe --self-test-exit`。每次运行前后只比较固定日志中 `L1-SIMPLIFY-P14-DYNAMIC-SPEC` 的行数。

| 配置 | 进程退出码 | 运行日志新增 | 逻辑错误日志新增 |
| --- | ---: | ---: | ---: |
| Debug | 0 | 2 | 0 |
| Release | 0 | 2 | 0 |

每次两行分别为模块/入口行和摘要行。两配置摘要一致：

```text
观察标识=L1-SIMPLIFY-P14-DYNAMIC-SPEC-S01；结果=通过；验收项数=48；失败项数=0；未分类异常=0；正式接线=不适用；正式读回=不适用
```

固定逻辑错误日志中保留一条2026-08-06旧P14 28项自检失败记录；它早于本候选和本轮运行。本验收不删除历史记录，只依据每次运行的增量0说明本轮没有新增未分类异常日志。

## 2. 日志责任与机器结果

顺序390包装先取得 `L1动态自检报告`，再形成并写入人读日志，最后原样返回报告字段。日志函数返回值被显式丢弃。日志不是provider身份、L1事实、规格、共同截止或正式读回；本轮不能仅凭“无错误日志”证明正确，结构化依据仍是48项报告和源码合同复核。

## 3. 零写与消费边界

`L1动态服务::形成状态迁移动能规格` 的函数体只调用两次 `读取完整快照`，直接 `.提交写集(`、P15和P16调用均为0。自检为了建立隔离夹具会使用既有L1写入口，但该夹具写入不是P14规格根的生产副作用。

除定义外，P14规格根只有 `自检.L1动态.ixx` 七处调用。P16尚无生产代码，因此合法生产消费者、正式业务入口和正式独立读回均为 `NOT_APPLICABLE`。崩溃、重启、断电和跨进程恢复按当前用户边界同样不适用。
