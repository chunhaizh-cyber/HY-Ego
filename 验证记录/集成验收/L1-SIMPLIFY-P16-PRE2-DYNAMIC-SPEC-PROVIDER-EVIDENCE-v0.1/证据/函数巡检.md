# PRE2 v0.1 函数巡检

## 1. 影响闭包

候选相对唯一父的函数影响闭包为21个函数：18个新增函数、3个直接修改函数。Debug/Release重建证明21个函数进入编译和链接；顺序390自检静态闭包和两配置退出0证明这些函数在受控路径中进入并退出。目标21、排除0、编译21、入口21、逻辑异常0。

## 2. 新增函数与诊断责任

18个新增函数包括：固定规格提供者身份、副本种类、副本身份、副本已退出、唯一当前副本查找、四类状态见证逐字段比较、前状态比较、后当前比较、前态选择比较、比较结果比较、PRE1凭证完整性、写集引用覆盖、形成规格提供者证据、公开读取提供者身份、PRE2证据组有效。

- 其中17个为纯常量、纯值、有限只读谓词或身份读取，分类 `无适用错误分支`。
- `形成规格提供者证据` 可能分配，失败以空optional送到公开P14根，分类 `向上送出`。

三个直接修改函数继续由紧邻原P14诊断责任覆盖：

- `形成P13夹具`：`向上送出`到自检报告；
- `运行L1动态自检`：`向上送出`到顺序390最终责任边界；
- `L1动态服务::形成状态迁移动能规格`：`向上送出`到当前自检边界或未来合法消费者。

最终 `本地记录` 责任仍由未修改的 `运行L1动态专项自检` 承担。合法拒绝不记逻辑异常；日志写入结果不改变自检报告。

## 3. 48项专项覆盖

独立源码复核确认新增专项覆盖：

- 固定身份 `0x4C31445000000001`、合同/规则1、直接调用1、去重provider 1；
- 增加、减少成功同时返回规格与证据；
- P13规格、PRE1凭证、P14规格、G0/G1共同截止一致；
- 十项动态登记当前节点、PRE1传递当前节点/关系/值及合法历史副本；
- 身份/副本一一对应、严格排序、精确数量和同身份同副本去重；
- 坏身份、坏合同、错截止、缺provider、缺副本、乱序、错种类、当前来源携带退出副本均内部不一致且全空；
- 等价、无前状态及上游非成功规格与provider证据均空。

顺序390两配置日志均报告48项、失败0、未分类异常0。P14规格根仅由自检模块调用，当前没有生产P16消费者。
