# P17 v0.2 消费者、并发与配置边界

## 调用边

两个公开服务入口的定义和仓库转发之外，候选中的全部调用都位于：

```text
海中鱼巣/核心/自检.L1事实基座.ixx
```

既有启动路径为：

```text
海中鱼巣.exe --self-test-exit
-> 启动.应用程序::登记完整自检
-> 顺序270 L1-SIMPLIFY-P0-S01
-> 运行L1事实基座专项自检()
-> 运行L1事实基座自检()
```

没有生产业务模块调用 `尝试读取完整快照` 或 `尝试读取当前事实代次`，也没有 P17 具名生产日志。顺序 270 是既有 L1 聚合自检，不是 P17 生产装配或合法业务消费者。

## 非阻塞与并发

- `尝试读取完整快照()` 与 `尝试读取当前事实代次()` 各有且仅有一处 `std::try_to_lock`。
- 两函数体没有 sleep、wait 或循环重试。
- 搜索到的唯一 P17 新增 `wait`/等待循环位于 Debug 专用独占许可屏障，用来确定性占锁，不属于生产读取入口。
- Debug 实际执行两个共享读取线程和一个独占许可竞争场景；竞争入口必须在 100ms 内返回许可拒绝，释放后恢复成功。
- Release 仍执行两个共享读取线程；独占竞争、损坏、资源失败和未知异常四项使用 `记(true)` 占位，Debug 故障辅助和标志不进入 Release。

## 纯读边界

两个入口只返回调用方拥有的纯值副本，不写 L1、不推进事实代次、不建立幂等账、审计、恢复候选或第二仓库。精确重复只比较同状态读取结果，不形成第二事实。

P15 v0.29 只提供 P17 所需的 L1 合同与实现基线；本轮不改变也不升级 P15 的 `INTEGRATION-ACCEPTANCE-FAIL / 未正式接线` 结论。
