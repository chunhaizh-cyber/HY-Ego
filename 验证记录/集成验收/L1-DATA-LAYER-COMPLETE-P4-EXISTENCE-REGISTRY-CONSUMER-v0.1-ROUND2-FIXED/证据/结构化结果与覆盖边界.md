# 第二轮结构化结果与覆盖边界

Debug与Release的消费者驱动均退出0，且stdout逐字节相同：

```json
{"通过":true,"启动状态":1,"世界登记启动状态":1,"初始场景启动状态":1,"实际存在登记启动状态":1,"实际存在读回状态":3,"初始场景读回状态":3,"世界登记读回状态":3,"发布状态":1,"合同版本":2,"规则版本":1,"首次幂等身份":1,"事实截止":3,"服务身份":10,"资格属性类型":11}
```

## 实际消费路径

1. 驱动只导入生产运行期模块，构造 `生产运行期会话`。
2. `启动` 返回已启动、世界登记/初始场景/实际存在登记各已提交、候选已发布，并提供有效上下文租约。
3. 租约公开 `读取实际存在登记`、`读取初始场景`、`读取世界登记`，三项均连续读取两次。
4. 各项两次状态和公开事实分别全等；三项共同当前截止为3。
5. 实际存在登记为合同2、规则1、首次幂等身份1，服务身份10和资格属性类型11非零互异，且 `实际存在结构登记完整` 成立。
6. 驱动不导入、不直调L1事实基座、私有仓、锁或内部事务；未使用日志决定结果。

## 八类场景

| 类型 | 结果 | 边界 |
| --- | --- | --- |
| 成功 | PASS | 双配置结构化启动成功，三项业务启动状态为已提交，候选已发布 |
| 精确重复 | NOT_APPLICABLE | 本消费者生产合同固定只首次建立一次登记；连续读回不是重复写 |
| 合法拒绝 | NOT_APPLICABLE | 本具名消费者没有需要非法输入才能完成的业务合同，不为补表造请求 |
| 外部失败 | NOT_APPLICABLE | 本路径只使用进程内中性事实基座，无本消费者外部资源 |
| 并发 | NOT_APPLICABLE | 固定生产会话启动合同未要求并发调用，不补造第二业务请求 |
| 崩溃恢复 | NOT_APPLICABLE | 用户明确当前不考虑程序崩溃和跨进程恢复 |
| 正式读回 | PASS | 三项公开读回各两次全等，共同截止3 |
| 正式构建 | PASS | 原生产目标Debug/Release完整重建及 `--runtime-context` 均成功 |

## 逐函数门禁

23个新增或直接修改函数全部登记正式诊断责任；本轮合法消费者路径进入18个，另5个依法只做编译接入和静态检查。首轮15项诊断责任缺口已经消失，未发现新的未收口逻辑异常。

本结论只覆盖本消费者实际使用的业务维度和具名服务切片，不升级为L1整体完成。
