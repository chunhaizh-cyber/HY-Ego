## 3. 服务边界

具名服务切片：消费一份已发布且处于待父需求重判状态的任务子目标回流记录，按显式父需求和同 G0 当前事实裁决，并收敛到本次不筹办、初次统一轮次 1、来源任务统一 N+1 或 legacy 待迁移。

期望合法消费者是普通应用中取得一份具名回流记录并继续自我治理的编排者；正式服务入口应是：

```text
普通应用回流记录消费者
-> 任务子目标回流重判提供者::重判父需求并准备筹办
-> L2任务结构服务::提交任务子目标回流后继筹办准备（统一分支）
-> 按后继幂等键 / 轮次分区 / 权威 / 后继历史独立读回
```

候选只存在第二、三行的实现和治理专项调用，第一行普通应用消费者不存在。因此后继读回入口虽然存在，也没有一份由正式消费者先形成的成功终态可供验收。

结构化合同：

- 成功：目标已满足且零任务写，或初次 / 后继已形成、精确重复并携带唯一合法工作包；统一后继必须在 task owner 同一写集形成 N+1 并换代当前关系。
- 具名非成功：legacy 待迁移、当前任务冲突、记录不可消费、证据不足、当前性漂移、幂等冲突、引用冲突、入口 / 许可拒绝、资源失败或内部错误；不得携带成功工作包。
- 禁止假成功：源码存在、工程登记、Release 重建、`--test-治理`、日志和施工 PASS 均不能替代普通应用请求、权威终态和独立读回。
