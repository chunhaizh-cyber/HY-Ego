# 结构化场景与双向读回

动态消费者位于`海中鱼巣/端到端测试.自我治理一致事实.ixx:731`，先通过`形成普通应用生产配置`和`构造普通应用上下文`形成真实普通应用上下文，再在第 748 行经正式 getter 取得服务。该路径没有直构第二个结构服务、取得 raw 端口、增加 friend 或制造私有坏结构。

| 计划项 | 动态事实 | 结构化结果与权威观察 |
| --- | --- | --- |
| V01 | 七类坏入口请求 | 均返回`入口拒绝`；前后当前事实代次相同 |
| V02 | 无精确列表项、无同目标子需求 | `新建列表项与子需求`；需求 owner 来源与任务 owner 绑定后同 G 读回 |
| V03/V05 | 有精确列表项、显式父下无同目标子需求 | `复用列表项并新建子需求`；不跨父复用其它父下同目标需求 |
| V04 | 同父同目标子需求已存在 | `复用当前子需求`；身份与既有子需求一致 |
| V06 | 同父已有异目标子需求 | 忽略异目标需求，仍复用正确同目标需求 |
| V08 | 请求父子顺序与既有关系不一致 | `父子顺序冲突`，不形成新来源或任务绑定 |
| V09/V12/V14 | 完全相同请求、需求 owner 和任务 owner 重试 | `精确重复`；已有双向事实零写读回，原身份不变 |
| V10 | 相同需求幂等键改为其它来源记录 | `幂等冲突`；首次来源未被替换，随后仍可按首次事实恢复 |
| V11 | 需求 owner 来源已发布、任务记录待绑定 | `需求侧事实已存在`；跳过需求写，以原任务绑定键完成绑定 |
| V15 | 任务记录已绑定但需求来源缺失 | `内部不一致`；不反向补写来源 |
| V18 | 成功结果独立读回 | 经任务记录读取与需求来源反查得到唯一相同子需求，并读取父需求、子需求、列表项、成员和父关系 |
| V19 | mutable/const getter | 多次取得同一服务地址 |

成功不是由单个写结果裁决。`需求任务子目标承接结果::成功()`要求`已承接/精确重复`、完整父子需求/列表/关系/任务记录载荷、无待重试绑定，并要求全部载荷绑定`最终共同事实截止`。`最终读回`分别调用任务 owner 的记录读取和需求 owner 的按记录来源反查，再读取完整需求侧材料；任务记录和来源关系必须在同一 G 指向同一子需求。

不可合法注入项保持：

- V07：当前公开需求 API 不能形成同父同目标当前子或精确列表项复义；`NOT_RUN`。
- V13：没有确定性资源耗尽或任务绑定期间 G 漂移 seam；`NOT_RUN`。源码只在该分支形成`需求已发布待任务绑定`和原绑定请求。
- V16：来源关系指向其它子需求或复义不能由公开 API 合法构造；`NOT_RUN`。
- V17：记录父需求、目标或子需求在同次调用中的并发漂移无确定性公开 seam；`NOT_RUN`。
- V21：普通应用装配没有 DATA 许可拒绝注入 seam；`NOT_RUN`。

上述动态结果属于自检消费者范围。由于没有生产非自检调用点，它们不能升级成正式接线。
