# 任务统一筹办轮次权威独立集成验收

日期：2026-08-23

## 1. 结论

对外结果：`INTEGRATION-ACCEPTANCE-FAIL`。

最小结论：`未正式接线`。候选 `e385585aef3c2d0d676b282ee16a62e9983749b8` 中，`任务目标未达成重筹办触发提供者::形成待重筹办与下一筹办工作包` 已由 `任务管理线程` 调用，并由普通应用的 `任务结果生产运行包`装配；这证明 legacy 重筹办 provider 的生产 wiring 存在。它不使本具名完整服务切片通过验收，原因是：

1. 统一 population 的唯一创建入口 `需求初次筹办准备提供者::形成唯一任务与初次筹办工作包` 在候选中仍只有治理专项调用，没有普通应用生产消费者；普通应用无法从正式路径形成统一任务，因此无法从普通应用合法消费者实际验证统一 `N -> N+1`。
2. 统一 `N -> N+1`、统一独立读回、精确重复、同键异义、同触发换键、并发与恢复的动态证据来自 `--test-治理`；本验收只把它们保留为施工分账，不升级为正式服务证据。
3. 候选正式工程无条件编译 `端到端测试.自我治理一致事实.ixx`，`入口.cpp` 无条件导入该模块并暴露 `--test-治理`。精确候选归档的 Release fresh Rebuild 日志也实际列出该模块，正式构建隔离为 `FAIL`。
4. 施工 V01—V27 为 `20 PASS + 7 NOT_RUN`；总数不能替代普通应用统一分区成功、正式独立读回、并发、崩溃恢复和正式构建隔离。

因此，只允许声明候选已经实现并编译了统一轮次代码、legacy provider 有生产调用边、施工专项形成了具名分账；不得声明统一轮次服务通过普通应用集成验收，也不得声明完整双分区服务、跨进程恢复或任务运行闭环完成。

## 3. 服务边界

具名服务切片：任务统一筹办轮次权威、`任务目标未达成重筹办触发提供者`和 task owner 统一推进。

合法消费者与正式入口：

```text
普通应用启动
-> 任务结果生产运行包装配
-> 任务工作线程提交已形成工作结果
-> 任务管理线程形成并消费重筹办意图
-> 任务目标未达成重筹办触发提供者::形成待重筹办与下一筹办工作包
-> L2任务结构服务::提交目标未达成待重筹办迁移
-> 按任务读取筹办轮次分区 / 读取权威 / 读取后继 / 按准备键读取
```

候选确有上述 provider 消费调用边；但统一人口的生产来源缺失，导致普通应用实际可形成的任务仍只有 legacy 路径。统一分支在源码中存在，不等于普通应用已能取得并消费该分支。

结构化合同：

- 成功：`已形成`或`精确重复`，携带完整工作包；统一分支必须把正式待重筹办状态、N+1 后继记录和当前关系换代同代提交。
- 具名非成功：`合法等待 / 触发已消费 / 当前性漂移 / 引用冲突 / 入口拒绝 / 资源失败 / 内部错误`；`触发已消费`只携带既有后继身份，不携带工作包。
- 禁止假成功：工作包、日志、构建成功、治理专项通过和源码存在均不是权威终态或正式服务通过。
