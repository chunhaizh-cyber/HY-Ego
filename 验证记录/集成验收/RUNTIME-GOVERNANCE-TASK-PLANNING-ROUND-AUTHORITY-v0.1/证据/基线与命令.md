# 基线与命令

## 1. Git 冻结

执行并核对：

```powershell
git rev-parse HEAD
git rev-parse origin/main
git rev-list --left-right --count HEAD...origin/main
git merge-base --is-ancestor e385585aef3c2d0d676b282ee16a62e9983749b8 origin/main
git merge-base --is-ancestor dd8a7810693b7892b3265333f762b7c1c3bcd4d8 origin/main
```



`9f0f10bd` 只发布 22 个任务统一筹办轮次权威图谱文件，不修改候选代码、设计、计划 blob 或本验收语义。manifest 的远端提交按检查器要求绑定当前 `origin/main`；归档后验收 live 语义基线仍冻结为 `dd8a7810`。

其它未跟踪 WIP 未读取为候选、未修改、未暂存、未进入验收提交。

`dd8a7810` 的精确差异为计划文件 rename 与计划索引删除；候选代码身份保持 `e385585a`。

## 3. 精确候选归档与 Release fresh Rebuild

隔离根：

```text
D:\TEMP\海中鱼巣\RUNTIME-GOVERNANCE-TASK-PLANNING-ROUND-AUTHORITY\20260823-integration-acceptance-01\
```

第一次 `git archive --output=(Join-Path ...)` 因 PowerShell 参数解析失败，退出 `128`，没有生成归档或构建产物。改用显式 `$archivePath` 后：

```powershell
git archive --format=tar "--output=$archivePath" e385585aef3c2d0d676b282ee16a62e9983749b8
tar -xf $archivePath -C $sourceRoot
git hash-object <归档>/海中鱼巣/领域/服务.L2任务结构.ixx
git rev-parse e385585a:海中鱼巣/领域/服务.L2任务结构.ixx
```

两个 hash 均为 `6e28721b63e27f96abc2abb6e9335c40484b9afc`，证明归档目标源码绑定候选。

Release 命令：

```powershell
MSBuild.exe .\海中鱼巣.vcxproj /t:Rebuild /m:1 /p:Configuration=Release /p:Platform=x64 /p:OutDir=<隔离根>\Release\bin\ /p:IntDir=<隔离根>\Release\obj\ /v:minimal
```

验收驱动等待 180 秒后返回超时 `124`，所以不把该次驱动退出码写成构建 PASS。随后只读核对显示 MSBuild、cl、link 进程均已退出，日志末尾已完成全量代码生成并产生：

```text
海中鱼巣.vcxproj -> ...\Release\bin\海中鱼巣.exe
build error count = 0
build warning count = 0
stderr bytes = 0
exe sha256 = D46391891F9C2DC2F49C74D03687E31F789396040623528545CDBB63FCDBF680
```

同一 Release 日志明确列出 `端到端测试.自我治理一致事实.ixx`，因此即使编译完成，正式构建隔离仍为 `FAIL`。

## 4. 清单检查

发布前执行：

```powershell
python .\tools\check_integration_acceptance.py --manifest .\验证记录\集成验收\RUNTIME-GOVERNANCE-TASK-PLANNING-ROUND-AUTHORITY-v0.1\manifest.json --verify-git --strict
git diff --check -- .\验证记录\集成验收\RUNTIME-GOVERNANCE-TASK-PLANNING-ROUND-AUTHORITY-v0.1
```

最终退出码与输出在发布前复核后补记于 Git 提交事实中；检查器只证明清单门禁完整，不证明运行事实真实。
