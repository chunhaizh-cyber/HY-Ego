# 正式接线与构建隔离证据

## 1. 普通应用正式路由

候选的正常程序路由为：

```text
海中鱼巣/入口.cpp::main
-> 解析并验证启动选项
-> 运行海中鱼巣
-> 运行普通程序
```

`启动.应用程序.ixx::运行普通程序`负责普通应用生产配置、普通应用上下文、系统世界树根、自我世界树根、真实自我、四本体根、方法登记根、自我线程和任务结果运行包装配。该文件没有 import、构造或调用`需求初次筹办准备提供者`。

针对四个普通入口文件扫描`形成唯一任务与初次筹办工作包`，退出码为 1、输出为空。候选全生产源码对 provider 模块 import 的唯一命中为：

```text
海中鱼巣/端到端测试.自我治理一致事实.ixx:35:
import 海中鱼巣.领域.内部治理.服务.需求初次筹办准备;
```

provider 的全部动态调用也位于该自检模块（主要调用行 2986—3150）；生产普通路由没有调用点。

结论：`正式接线 = FAIL`。公开类和公开成员存在，但没有普通应用合法消费者的真实装配。

## 2. 自检与正式目标隔离

候选 `海中鱼巣/入口.cpp` 无条件包含：

```cpp
import 海中鱼巣.端到端测试.需求服务;
import 海中鱼巣.端到端测试.自我治理一致事实;
```

并在正式参数解析前直接分流：

```cpp
if (参数组[索引] != nullptr
    && std::string_view{参数组[索引]} == "--test-治理") {
    return 海中鱼巣::运行自我治理一致事实端到端测试();
}
```

候选 `海中鱼巣.vcxproj` 的普通 `ItemGroup` 无条件登记：

```xml
<ClCompile Include="海中鱼巣\端到端测试.自我治理一致事实.ixx" />
<ClCompile Include="海中鱼巣\领域\内部治理\服务.需求初次筹办准备.ixx" />
<ClCompile Include="海中鱼巣\入口.cpp" />
```

没有 Release 条件、禁用宏或独立测试目标把治理自检模块与生产目标分开。

结论：

- `自检隔离 = FAIL`；
- `正式构建隔离 = FAIL`；
- 八类矩阵中的`正式构建 = FAIL`。

候选施工记录中的 Release Rebuild PASS 只证明含自检模块的目标能够构建，反而不能证明“自检关闭后的正式目标不携带自检入口”。

## 3. 结构化结果和错误传播边界

provider 公开入口返回`需求初次筹办准备结果`，合法非成功使用具名枚举；`bad_alloc/length_error`映射为`资源失败`，其它异常映射为`内部错误`。task owner 融合写和读回入口同样以结构化结果向上送出。

这符合 CODE-FILE-01 对非最终责任边界的`向上送出`形状，但候选没有普通应用最终消费者接收并继续传播该结果。因此只能证明 provider 内部返回形状存在，不能证明逻辑异常已沿唯一正式传播链到达最终责任边界。
