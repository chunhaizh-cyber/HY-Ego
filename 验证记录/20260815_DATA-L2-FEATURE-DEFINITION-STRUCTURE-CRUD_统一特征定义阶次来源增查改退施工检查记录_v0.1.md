## 2. Debug / Release 动态矩阵

两配置均为 `18/18 PASS`、`failures=0`，覆盖：

1. 全组零守卫在零定义时成功返回空组和非零截止。
2. 基础定义首次、精确重复、同键异请求幂等冲突分账，非成功为空载荷且无变更代次。
3. 两个基础来源形成二阶定义；相同输入角色可用于不同来源。
4. 基础与二阶来源形成三阶定义。
5. 同一来源使用不同输入角色合法。
6. 重复 `(来源, 角色)`、零角色、顺序缺口、错阶次、零规则身份和零规则版本均在写前拒绝。
7. 超出 `uint32_t` 的规则版本见证材料由纯值完整性 helper 拒绝。
8. 来源未找到与旧守卫事实代次漂移保持不同状态，均零变更、空载荷。
9. 全组零守卫原子最新、非零同代读取、身份严格升序和非零守卫漂移成立。
10. 固定属性新增 / 换代不改变实际阶次、直接来源和规则，且公开固定属性保留不同于定义身份的正式来源编码。
11. 实例能引用完整统一定义；不存在定义返回未找到和空载荷。
12. 并发同请求至少形成一个成功结果；双成功时逐字段收敛到同一权威定义，没有两个不同定义。
13. 并发同幂等身份异请求只有一个权威成功，另一请求被许可 / 漂移 / 幂等边界拒绝。
14. 定义仍被实例或其它派生定义引用时退出返回引用冲突且零变化。
15. 实例闭合退出后，派生定义按反向依赖顺序退出，再退出基础定义。
16. 已退出定义的当前读取返回 `已退出` 和空载荷。
17. 历史读取逐项证明定义、实际阶次属性、规则见证、全部直接来源关系和公开固定属性在退出截止同代退出；公开固定属性的外部来源编码保持不变。
18. 已退出来源用于新派生请求时返回 `已退出`，没有降格为 `未找到`。

Debug 的并发同请求观察到 `精确重复` 或零载荷并发状态，Release 观察到成功收敛；异请求竞争两配置都只有一个成功。该结果只记录本次调度，不证明长期公平或所有线程交错。

## 4. NOT_RUN 与结论边界

以下没有合法稳定公开注入路径，精确记为 `NOT_RUN`：

- 真实内存分配耗尽和 `bad_alloc`；
- 私有仓、私有类型定位或关系闭包损坏；
- 在全组读取中注入重复定义、未知第五类私有结构或其它坏成员；
- 通过已删除旧公开 API 形成真实旧定义节点；
- 跨进程恢复、长时公平、故障恢复、正式 BIZ 消费和生产启动。

坏成功形状、规则坏见证和退出同代不完整由公开纯值 helper 负向检查；没有为补齐不可注入分支增加生产 seam。

本记录只证明具名 DATA-L2 统一特征定义施工在所列构建、动态矩阵和静态范围检查下通过。它不证明独立 DATA 验收、业务可用、状态 / 动态 / 因果、世界树 / 概念树、生产装配或完整 DATA-L1—L5 已完成。
