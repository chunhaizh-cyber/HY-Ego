## 3. 实际代码

1. 通过既有 `建立特征强类型(FC,nullopt)` 建立信息引用型空F；wrapper继续转调，不建立第二入口。实际值非空仍明确拒绝。
2. F owner封存自己的完整空F身份/类型/FC引用及合法可选单位；概念owner私有友元协作接口持原概念锁读取当前模板及计数、受检加一，封存自己的计数字段替换；两个片段一次提交，不先建F再改计数。
3. helper不比较名称和旧计数，不把统计变化当模板变化；正式模板/值域/规则变化或节点消失在发布前分流，计数溢出或坏结构走工程错误链。
4. 核两个原片段绑定回执、唯一新F及实际F读回；发布后故障保留已成立事实并工程中止，不返回资源失败诱发重新建点。
5. `准备特征初值保护`允许未知值通过，仅表示无目标值待保护，不表示已建立F。
6. `获取特征`、`捕获特征匹配实例`检查真实F类型、FC、单位与模板及基数；当前/标准/历史/命中记录/区间/聚合/归组材料都必须为空。非法非空或坏结构不读成正常未知；不装配目标值reader，不走字符串/数组材料读取。
7. 赋值、区间、归组及其它非空信息引用guard保留；普通材料分支不扩改。
8. 信息引用空F退出前复用 `准备特征组清理({F},{})`；不豁免任何外部持有字段，已有外部引用或联合占用时零写拒绝。成功准备凭据保持在函数作用域，持原F递归锁到原删除路径结束，始终为未开始阶段；不递归调用整组执行，不跨线程或提前释放。

未新增删除ABI，也未把旧分步删除和计数减少改成原子事务；任意跨owner新增引用的共同发布门不由本叶证明，后续持有者迁移必须单独闭合。

## 4. 审查与修正

独立F侧审查发现getter/capture可能接受缺单位或错单位的空F，已在共享空实例核验函数中补类型/FC/单位的精确基数与值核对。概念helper由root回读，核C锁贯穿模板、计数、封存、共同提交及计数读回，没有解析F私有字段。

root另发现原普通删除会在最终删点遇外部引用之前先拆F字段。将该具名缺口退回计划支撑，v0.2允许复用现有清理准备前置后再实施；未通过临时扩大DATA-L1删除能力解决。成功凭据正常析构只释放原锁，不进入删除中析构故障分支。

静态检查覆盖空F创建、非空值拒绝、两片段同次提交、计数分流、绑定回执、真实读回、全部空值位置、原类型路径、删除前置及保持锁的调用关系；这些是代码审查，不是运行证据。
