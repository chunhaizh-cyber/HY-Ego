## 1. 本段范围

本段沿已经发布的需求承接、W1 方法召回、W2 条件参数筹办和 self 执行前判断继续，实现：

1. manager 向 worker 派发一次本能动作工作；
2. worker 经世界树综合入口重新核验任务、方法、条件、参数、方向及结果获取方案；
3. 每次真实方法调用建立一个执行实例，不建立任务轮次或筹办轮次；
4. W3-A 只发出动作并记录“等待结果”，W3-B 只消费正式状态定位、结束原执行并形成影响评估；
5. manager 独立读回执行及评估定位后通知 self；
6. self fresh 复核当前需求并形成后继决议，manager 复核定位后由 task owner 发布状态；
7. 正式完成状态发布后由 self 组织一次任务完成结算；结算失败保留原定位恢复，不重做动作；
8. manager 启动时恢复等待结果、等待评估、等待 self 决议，以及已完成但尚未结算的原执行。

结果获取当前只实现“世界树正式状态通知”这一种具名渠道。方法没有明确可实现的该渠道时保持零动作；不以空状态、函数返回或预测冒充实际结果。

## 2. 关键纠正

- W3-B 在结束执行前重新核验请求中的全部状态定位；不接受调用方已过期的核验结论。
- 状态材料同时核对作用对象、特征类型根和实际实例特征所引用的精确特征概念，避免同对象同根下的兄弟特征被误接纳。
- 动作结果返回后主动从状态 owner 的正式集合查找已经形成的状态，关闭“状态通知先于 manager 登记等待到达”的窗口；不建立第二状态账。
- manager 运行期间按具名资源重试间隔周期复制等待中的 T/X 定位，释放 manager 锁后从状态 owner 正式集合补查；因此状态通知缺失、先到或容量失败不会成为唯一恢复路径，且补查永不重做 W3-A。
- 完成决议发布后，manager 保留原执行与评估定位，直到 self 的正式结算已经读回并确认；线程重启可恢复已完成但未结算任务。
- 完成结算除 T/D/X/A 外，固定保存`自我后继决议`完成来源及最后相关 X 已接纳的完整正式状态闭包；重复结算按该完整闭包判定同义或异义，世界树读回再次核验 X/A/闭包。
- 当前影响评估尚未完整证明方向、幅度和值域，因此目标仍未满足时 self 一律重新筹办，不因只命中同对象同类型状态就盲目重复原动作。
- 本能函数明确报告“未进入动作”时，task owner 只在执行尚无结束、实际状态或评估材料且定位未漂移时撤销空执行；已进入动作不允许走该回退。

## 3. 代码知识变更清单

### 新增或扩展的稳定能力

- `新_世界树类::执行任务本能方法(...)`：W3-A 综合入口；释放世界树聚合锁后调用本能函数；不负责结果获取或任务完成。
- `新_世界树类::核验任务结果材料(...)`：按正式执行方案核验外部给出的状态定位。
- `新_世界树类::查找任务结果材料(...)`：从状态 owner 正式集合补查执行开始后已存在的结果材料，仅用于关闭通知竞态。
- `新_世界树类::获取任务本能结果(...)`：W3-B 综合入口；重新核验状态、结束执行并形成影响评估，不重入动作。
- `新_世界树类::读回任务执行(...)`、`查询等待结果任务执行()`：为 manager 独立读回及线程内恢复提供正式定位。
- `新_世界树类::发布自我任务后继决议(...)`：复核 self 决议与执行/评估绑定后发布任务状态。
- `新_世界树类::结算已完成任务(...)`、`读取任务完成结算(...)`：由 self 组织完成结算并支持恢复读回。
- `新_任务类::撤销未进入动作执行(...)`：只撤销已建立但函数明确未进入动作的空执行。
- `新_任务类::结算已完成任务(...)`、`获取完成结算(...)`：按任务唯一保存 T/D/X/A、self完成来源及完整结果状态闭包。
- `新_本能函数集::检查可用(...)`：只读检查登记入口及其宿主依赖，不执行动作。
- `新_任务管理线程类::提交结果状态通知(...)`：把正式状态通知路由到等待中的执行，不保存第二状态事实。
- `新_任务管理线程类::实现::取得到期结果补查组()`：周期复制等待 T/X 定位；不持锁查询世界树，不保存状态副本或第二事实账。
- `新_任务管理线程类::提交自我任务后继决议(...)`：复核 self 决议定位并调用世界树发布。
- `新_任务管理线程类::确认任务完成结算(...)`：fresh 读回完成结算后释放运行期结果定位。
- `新_自我线程类` 的任务结果反馈分支：独立读回执行/评估、fresh 复核需求、形成后继决议并组织完成结算。
