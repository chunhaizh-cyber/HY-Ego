## 1. 目标与边界

本片只实现任务动作发生前的只读冲突需求查找：

```text
方法结果绑定实际对象并形成预计变化
→ 读取任务唯一需求和需求全集
→ 排除当前任务需求
→ 只比较同一作用对象、同一特征类型根的活动或等待需求
→ 值目标按当前事实重新取得所需方向
→ 预计值域保证命中目标时不判冲突
→ 预计方向与需求方向相反时返回冲突材料
→ 方向或当前事实不足时返回等待材料
→ 自我线程拒绝冲突执行
→ 工作线程在动作前重新执行同一核验
```

本片不在需求建立时拦截，不新增需求账，不修改需求持久结构、任务管理消息、方法知识、规范、流程图或工程入口。

## 2. 实际代码变化

- 新增`查找冲突需求(任务节点, 预计变化阶段组)`公开只读入口。
- 新增无冲突、发现冲突、等待材料、任务不存在、结构不一致和资源失败的结构化结果状态。
- 冲突材料保存正式需求身份、实际作用对象、归一后的特征类型根、阶段顺序、双方方向、预计值域及必须出现标志，不形成第二需求事实账。
- 查询使用需求owner的可判错全集读取；读取失败不解释为无冲突。
- 已满足和失活需求跳过；活动和等待需求参与；当前任务唯一需求被排除。
- 特征概念先归一到类型根，再判断是否属于同一特征类型。
- 值目标在每次核验时重新读取当前满足结果；预计值域完全保证进入目标时不判冲突，值域与反向声明并存则判结构不一致。
- 所有预计阶段均参与检查；允许副作用也参与保守判断，冲突材料保留`必须出现`标志。
- 冲突结果和等待材料结果按稳定编码及阶段稳定排序、去重。
- `核验任务执行方向()`在确认当前任务目标可推进后调用冲突查找；冲突、等待、资源和结构结果分别进入现有状态分流。
- 自我线程将冲突映射为拒绝执行；任务工作线程临近动作复核将冲突映射为定位已变化并保持零动作。
