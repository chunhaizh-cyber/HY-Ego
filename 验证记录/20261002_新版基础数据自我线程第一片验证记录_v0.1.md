# 新版基础数据自我线程第一片验证记录

日期：2026-10-02

起点：`81e548c366aca1090749d9d6c2b8e11b3cd873c8`

切片：用户直接授权的“用新版基础数据开始实现自我线程类”第一片

## 1. 实际范围

本片新增 `新_自我线程类`，只实现：

```text
初始化新版世界树
-> 建立或精确复用自我所在场景
-> 在该场景建立唯一自我存在
-> 创建 OS 工作线程
-> 常驻等待
-> 接收独立的进程内停止信号
-> 安全 join
```

本片没有接入普通应用，没有实现需求、任务结果、安全、服务或其它治理消息，也没有建立运行代次或第二逻辑 self 身份。世界树中自我存在节点的稳定编码就是本片采用的唯一业务身份。

## 3. 验证

### 3.1 独立编译

使用 Visual Studio 2026 x64 工具链，以 `/std:c++20 /utf-8 /EHsc /bigobj` 单独编译 `新_自我线程类.cpp`，通过。

### 3.2 隔离运行验证

验证源码、对象和可执行文件位于：

```text
D:\TEMP\海中鱼巣\NEW-SELF-THREAD
```

运行覆盖：

1. 初始化新版世界树；
2. 建立一个 I64 特征概念；
3. 用该概念和一个准确值初始化唯一自我；
4. 读回自我所在场景、自我存在及场景成员关系；
5. 精确重复初始化返回“无变化”；
6. 第二线程对象争用唯一自我返回“唯一自我冲突”；
7. 工作线程进入“等待治理消息”；
8. 进程内停止信号使线程退出并完成 join；
9. 重复停止和重复等待均返回“无变化”，不误报内部错误。

实际输出：

```text
NEW_SELF_THREAD_OK scene=259 self=268
EXIT=0
```

### 3.3 主工程构建

主工程输出和中间文件均定向到 `D:\TEMP\海中鱼巣\NEW-SELF-THREAD`：

- Debug x64：通过，生成 `msbuild-debug/海中鱼巣.exe`；
- Release x64：通过，生成 `msbuild-release/海中鱼巣.exe`；
- `git diff --check`：通过。

未运行普通应用生产装配；因此本记录不证明新版自我线程已成为程序入口实际使用的线程，也不证明任何治理消息闭环。

## 4. 代码知识变更清单

### 新增函数

| 稳定函数身份 | 用途与边界 | 直接调用边 |
| --- | --- | --- |
| `新自我线程初始化请求::完整() const noexcept` | 校验第一片初始化请求；不验证业务特征值是否满足概念规则 | 只读请求字段 |
| `operator==(新自我线程初始化请求, 新自我线程初始化请求)` | 锁定初始化请求并拒绝异义重复 | 无事实写入 |
| `新自我线程初始化结果::成功() const noexcept` | 判断结果状态及两个正式稳定编码是否完整 | 无事实写入 |
| `新自我线程操作结果::成功() const noexcept` | 判断已完成或无变化 | 无事实写入 |
| `新_自我线程类::新_自我线程类(新_世界树类&) noexcept` | 绑定唯一新版世界树服务；服务必须比线程对象存活更久 | 不初始化世界事实 |
| `新_自我线程类::~新_自我线程类() noexcept` | 请求停止并 join，释放进程内线程所有权 | 调用 `请求停止()` |
| `新_自我线程类::初始化(...) noexcept` | 完成世界树、场景、唯一自我存在的建立和正式读回；不创建 OS 线程 | 调用新版世界树初始化、场景/存在建立与查询入口 |
| `新_自我线程类::启动(uint64_t) noexcept` | 创建 OS 线程并等待其进入常驻态 | 调用内部 `实现::运行()` |
| `新_自我线程类::请求停止() noexcept` | 设置独立进程内停止信号 | 唤醒内部条件变量 |
| `新_自我线程类::等待停止(uint64_t) noexcept` | 有界等待线程退出并 join；重复调用返回无变化 | 不写业务事实 |
| `新_自我线程类::读取快照() const noexcept` | 返回生命周期和两个正式节点身份 | 不读写第二份业务事实 |
| `新_世界树类::删除空场景(稳定编码) noexcept` | 上层失败回滚包装；只允许删除非根空场景 | 调用 `新_场景类::删除空场景()` |

### 待知识维护者处理

上述函数均为新增用途卡候选。当前未修改共享 `知识库/函数用途/**` 或知识状态聚合文件；应在结果提交发布后，以该提交为基线再建立或更新用途卡。

## 5. 完成边界

本片证明新版基础数据能够支撑“世界树 + 自我所在场景 + 唯一自我存在 + 常驻线程 + 独立停止/join”的最小运行链。后续至少仍需：普通应用装配、具名运行配置，以及按具体消息类型逐项增加处理函数。
