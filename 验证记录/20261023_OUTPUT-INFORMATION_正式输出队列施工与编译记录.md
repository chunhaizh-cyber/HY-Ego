1. 外设窗口新增正式“外设对话框输出队列”特征。当前值是保序 U64 消息引用数组；首次窗口及已有窗口补齐空 F 和初始 S，不伪造入列事实。

4. 正式消息/root 完整发布与队列 F 更新是两阶段，不宣称联合原子；第二阶段失败保留已发生事实并工程终止，不报成功、不自动重发。同来源已领取或取消的消息不重新入列。
5. 宿主私有提交 vector 只保留目标、序号、正式消息编码和传输技术状态，不再保存待发正文或裁决队首。提交调用正式入列，GET/outbound 调用正式领取。
6. 完整 socket 写出后才记录方向2发送事实；部分写出不生成完成事实、不自动重排或重发。取消只删除未领取引用，停止关闭接纳后逐页清空待发 F，保留已领取现场收口。
7. 装配取得四个正式队列回调，闭包直接借用外设 world；启动层真实五参数宿主调用已接线。旧四参数入口拒绝，不回退私有待发队列。

## 3. 并发与生命周期核对

- 宿主统一锁序：队列操作锁 → 短暂共享状态锁 → 释放共享锁后 world 回调 → 短暂共享状态锁收口。socket 写出不持队列操作锁。
- 回调执行不重新取得应用上下文锁，避免连接持上下文调用宿主后反向再取上下文；world 不回调宿主。
- 提交的技术 vector reserve、目标和正文复制在正式入列之前；入列后收口仅移动或改标量。world 领取/取消先准备完整回执再改 F。
- 独立审查发现：原实现完整写出后临时复制目标/正文构造发送事实，分配异常可能阻止正式发送事实记录。已修为写出前构造 `网页定向发送事实`，完整写出后只传引用。
- 宿主是同步 HTTP 请求处理，不新增线程/join。正常停止、关闭请求、会话租约析构及已开始会话的提前退出统一清空待发 F；析构不持共享锁调用 world。
- 回调借用寿命覆盖宿主及其会话租约析构；宿主返回后才回收应用上下文。输出消息 root 保留消息/正文引用，出列不删除消息；不承诺跨进程恢复。

上述为源码和独立静态审查结论，不是并发、停止或恢复实测结果。
