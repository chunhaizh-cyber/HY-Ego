## 2. 统一语义

### 2.1 当前事实，不提供历史

L1 当前公开面只读写当前事实。请求和结果中不再存在合同版本、期望事实代次、读取事实代次、共同事实代次、`G/G0/Gread/H`。一次独立读取只对本次调用负责；多个独立读取之间不构成共同快照。需要同一次观察的一组材料时，应使用“一致当前投影”入口。

技术幂等的首次请求和首次结果仍会保留，用于同一幂等键重试收敛；这是写入正确性材料，不是业务历史，也不提供任意历史查询。

### 2.2 稳定编码与事实种类

`稳定编码`是非零 `uint64_t` 身份，用于 owner、节点、关系和值。新编码由 L1 全局单调分配；事实退出后编码不复用。

L1 保存三类当前事实：

| 事实 | 主要字段 |
| --- | --- |
| 节点 | `编码`、`种类`、可选的`属性类型表示`、`当前属性`；owner-aware 形式另含`写入所有者` |
| 关系 | `编码`、`源节点`、`目标节点`、`关系类型节点`、`角色或顺序`；owner-aware 形式另含`写入所有者` |
| 值 | `编码`、`所属节点`、`属性类型节点`、`材料`、`来源节点`；owner-aware 形式另含`写入所有者` |

节点种类由公共事实 DTO 定义；值材料可为：

- `int64_t`；
- `vector<int64_t>`；
- `vector<uint64_t>`；
- 独立材料引用。

L1 只执行通用事实约束，不解释“特征、存在、场景、状态、动态、因果”等 L2 业务含义。

### 2.3 owner 与写端口

`L1结构所有者身份`是 L1 结构分区身份，不等于业务主体或访问权限。owner 范围当前有`旧共享范围`和`独占结构范围`两种。建立或重入成功后交付唯一活动写端口；写端口把 owner 身份注入写入，L2 不能在普通 owner 写请求中任意指定写入 owner。

### 2.4 写集

中性写集和 owner 写集均可一次提交：

- 新建节点；
- 新建关系；
- 新建值；
- 改变节点属性槽的当前值；
- 退出现有事实。

写集本地键只在本次写集中引用待分配的新事实；成功结果用`新编码映射`返回其稳定编码。幂等键必须绑定完整规范化请求：同键同请求返回`精确重复`，同键不同请求返回`幂等冲突`。

### 2.5 常用状态族

| 状态族 | 主要状态 |
| --- | --- |
| 中性读取 | 成功、入口拒绝、未找到、属性未设置、资源失败、内部不一致、许可拒绝 |
| owner 读取 | 成功、入口拒绝、许可拒绝、未找到、属性未设置、资源失败、内部不一致 |
| 中性写入 | 成功、精确重复、入口拒绝、未找到、幂等冲突、资源失败、内部不一致、引用冲突 |
| owner 写入/管理 | 成功、精确重复、入口拒绝、许可拒绝、未找到、幂等冲突、引用冲突、资源失败、内部不一致 |
| 多分区事务 | 已提交、精确重复、入口拒绝、幂等冲突、引用冲突、资源失败、内部不一致、已可能发布；固定双 owner 另有许可拒绝和未找到 |

写入结果中的“是否形成内存权威发布”和“重试边界”用于判断是否已经发布以及应原请求重试、修正后重试还是按原幂等身份读回收敛。

## 6. L2 的合法使用方式

### 6.1 写入

1. 由装配层持有一个`L1事实基座运行包`。
2. 需要独立结构写入能力时，通过签发器建立或重入 owner，取得唯一活动写端口。
3. L2 把领域操作翻译为节点、关系、值、属性槽变更和退出事实组成的写集。
4. 单 owner 使用`提交所有者范围中性写集`；需要跨 owner 全有或全无时使用固定双 owner、三分区或有限 N 分区事务。
5. 以结果中的状态、发布见证、重试边界和编码映射为准；结果不确定时使用原幂等身份收敛，不另造新键猜测重试。

### 6.2 读取

- 已知一个事实身份时，使用按节点/关系/值读取。
- 已知关系端点和关系类型时，使用源关系组或目标关系组读取。
- 已知 owner 和值的归属、来源或属性类型时，使用对应完整值组读取。
- 一次业务判断需要多项彼此一致的当前材料时，使用一致当前投影或关系类型闭包投影；不要用多个独立读取自行假定共同快照。
- L1 不提供按“特征、存在、场景”等业务类型搜索。业务类型的关系编码、查找入口和完整性判断由 L2 定义。

### 6.3 删除/退出

L1 的物理动作是把事实加入写集的`退出事实`。L2 在退出节点前应按其合同检查属性、关系和值闭包；需要全局当前引用证据时使用`读取节点全部当前引用`。L1 不保存可供上层读取的墓碑或历史版本。
