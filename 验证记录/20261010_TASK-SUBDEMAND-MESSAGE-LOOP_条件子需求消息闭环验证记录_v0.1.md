## 2. 实际变更

八个生产文件发生本轮变化：`新_任务类.h/.cpp`、`新_需求类.h`、`新_任务工作线程类.h/.cpp`、`新_任务管理线程类.h/.cpp`、`新_自我线程类.cpp`。需求cpp及self头未产生本轮增量；未新增工程项。

1. task提供纯读条件子需求提议，保存完整父目标、M/P/C/R、角色绑定、全部条件域与单位快照。缺口单独去重；当前值不进入来源快照。支持普通I64单项及AND，拒绝不支持条件、矛盾交集和祖先同语义循环。
2. 删除task公开`建立子需求`声明/定义，需求受限写入口friend改为self；全生产源码搜索旧入口无命中。
3. worker只在W2完成后返回提议。manager独立重算并精确比较；非W2携带提议拒绝。
4. self按完整原工作读回，逐项fresh核验来源，建立包含关系概念，再经需求owner添加/复用D。资源重试保留首次采用状态、回执及future；后项失败不删除已发布前项。ready future永久错误不伪装成资源重试。
5. manager收存回执即预置全部成功D承接槽；公开承接入口拒绝新受限依据。self在回执接收后经原邮箱发送带父原工作定位的受限消息，扫描仅补唯一D-T关联。子T承接支持需增/需减/多区间空洞，不重启终结T。
6. 回执收存与就绪分开：成功D逐项验证，来源变化/材料未到可以收存前缀，不把它当可执行；来源变化D禁止按旧裁决启动，父路径保持阻塞。真正承接前再次fresh核验。
7. 首次收执、事实通知、正式完成结算才触发父依赖重核；承接尚未收口时仅合并事件。全部正式子D满足且当前方法明确已选定，才清阻塞并重新W2，绝不直接W3。

## 5. 明确未验证和完成边界

- NOT_RUN：确定性内存分配失败、邮箱满、回执提交故障、第一D发布后第二D发布故障的注入矩阵；实现有资源重试及前缀保存分支，但不以静态审查冒充这些故障运行证据。
- NOT_RUN：所有不支持类型组合、缺当前值、单位不一致、需减少及多区间空洞承接的逐项专项；受限实现范围以代码及设计为准，9模式不等于全部分支覆盖。
- 不证明复合需求拆分、全部条件类型、组合方法解释执行、动态废弃旧D、世界通知自动装配、普通父T自动启动、真实普通动作、跨进程恢复或崩溃exactly-once。
- 无任务树；D-T一一关联沿原需求树组织。当前旧D未满足时不会因换方法自动解除依赖。
- 验证前缀、构建、提交和推送都不代表自我服务总闭环完成。
- 临时材料在发布核验阶段保留于上述唯一目录；进程和句柄释放后按CODE-FILE-01清理，最终清理结果由完成回传说明。既有异主WIP及其它TEMP任务目录不在清理范围。
