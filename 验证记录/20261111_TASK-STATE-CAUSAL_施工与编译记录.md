## 2. 切片1：统一入口与迁移动作

- 公开入口 `迁移任务状态(任务, 后状态, 迁移原因)`。迁移原因种类为追加式枚举，值 1–29。
- 一次迁移的执行顺序：
  1. 校验迁移表和原因约束；
  2. 写因素状态；
  3. 建前状态；
  4. 原子发布治理迁移记录；
  5. 建治理动作（主体为 self，定义取前后配对的迁移定义）；
  6. 提交状态特征；
  7. 建后状态；
  8. 完成迁移：形成原子动态和“导致变化”关联，同步交付实际发生。
- **原因约束**：已结算只能由结算收尾进入；放弃结算只能由放弃结算进入；其余收束状态只能经重新启用离开；“未执行但目标已满足”只能由执行前收束进入；执行中→待查找方法只能由撤销触发；进入子需求不合法只能由对应原因触发。
- 内部治理世界：`读取自我动作事实` 新增迁移定义分支；场景校验和启动迁移都认可迁移动作。
- 动作方法投影服务：新增迁移定义的投影。

## 3. 切片2：因素特征

- 任务虚拟存在新增七个因素特征：
  - 承接依据，取值 1..8；
  - 候选结论，取值 1..2；
  - 条件结论，取值 1..3；
  - 执行进入结论，取值 1..2；
  - 影响评估结论，取值 1..21，照搬需求当前满足状态的取值；
  - 后继决议，取值 1..5；
  - 不合法子需求，U64 数组，存子需求编码。
- 新建任务时这七个特征一并建立，此时无值；旧任务在启动时幂等补齐。
- 六个数值型特征有先天镜像：基础枚举槽 421–426，“允许未知当前值”约束槽 813–818，以及结构301 条目。装配阶段传入这些特征类型。
- **迁移前形成因素状态**：凡是与本次原因种类对应的因素，都会形成状态。值没有变化时也新建一个同值状态，保证因素落在本次前置窗口内。
- 原因种类到因素的对应：
  - 各类承接 → 承接依据；来源前端子需求记为因果子需求。
  - 消费方法候选 → 候选结论。
  - 确认进入待执行 → 条件结论“具备”。
  - 开始执行 → 执行进入结论“已进入动作”；零动作恢复、撤销 → “零动作”。
  - 影响评估完成 → 影响评估结论。
  - 自我后继决议 → 后继决议。
  - 子需求不合法、恢复合法 → 不合法子需求。

## 6. 偏差与未决项

1. **服务值结算动作的来源未按 R113 修改**，与规范存在漂移。现行流程是先建服务值结算动作，后建最终结算收尾阶段；而且 `新_动态类::按来源查询动作` 规定同一来源只能有一个动作。修改需要动 新_动态类.cpp 和 服务值结算.本能运行服务.cpp，两者都不在本计划写集内，需另立切片。
2. **重启后排除集为空**：被排除的候选可能被再次提出，自我会重新判定；仍不合法时会重新挂起并补回缓存。结果正确，只是多走一轮。要彻底解决，需要持久事实带上候选身份，或改为按子需求节点排除，这需要机器语义裁决。
3. **旧“已结算”定义的读取分支保留**：启动迁移和历史已结算任务的读回仍在引用它。
4. **保护前提的复核位置**：原来在状态特征提交时核验，现在改在迁移记录发布时核验，前提变化时不留下记录和动作。开始执行时，X 改为与迁移记录同次发布。
5. **原因材料只存编码值，不做硬引用**：材料可能早于记录被删除，只用于追溯。
6. **因素未决**：
   - 条件结论的“等待条件”“需子需求”、承接依据的“复合子需求”都还没有写入点。
   - “不合法子需求”没有先天镜像，因为没有能表示数组内容的概念原语。
   - 任务专属存在概念未纳入因素特征。
   - 模拟世界不填因素组。
7. **需求就绪通知只接了两个字段更新入口**。其它需求字段写入目前没有外部调用者。
8. **4340 第118行、7190 第24行**（R113 列为待本计划复核）：没有改规范。代码中 `读取自我动作事实` 已能读取迁移动作，规范措辞待后续同步。
9. **耗时记录未做**：计划要求记录各类迁移的耗时，但没有运行，所以没有数据。需要在用户发出测试指令后的诊断运行中补上。
