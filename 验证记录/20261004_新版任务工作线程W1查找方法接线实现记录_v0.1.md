## 1. 直接代码切片

本片沿用户持续目标实现首个真实任务工作线程链：

```text
已建立或待查找方法的任务
→ manager取得单任务工作占用
→ worker按任务定位fresh读取任务及唯一需求
→ 只用需求目标特征类型执行方法宽召回
→ 任务owner发布current-only候选方法材料
→ worker回传材料定位
→ manager独立读回并消费
   ├─ 有候选：进入待检查条件
   └─ 完整零候选：进入等待条件
```

冻结边界：目标值域和比较关系不映射成“可能结果概念”；作用域、实现方式、
作用存在概念组和可能结果概念组保持空条件。W1只完成宽召回，不选择首个候选，
不判断条件或参数，不批准或执行方法，也不建立方法、需求或子任务。

本片允许修改新版任务类、世界树、任务管理线程及VS工程登记；新增新版任务
工作线程和本验证记录。现有旧self、旧世界树、流程图、规范、计划清理、根目录
obj及数据目录WIP均原地保留，没有纳入本片。

## 2. 实际代码结果

1. 任务owner增加current-only候选方法材料。材料保存任务、需求、完整需求目标、
   实际查询条件、查询状态、完整性和候选方法组；精确重复复用原材料，不形成
   第二份候选账，不同当前结果替换旧材料。替换或清除前先用直接值字段登记
   待回收材料编码；该定位不引用材料节点，不阻止物理删除，失败重试仍可定位，
   不再形成不可达旧材料。任务重新启用时先收口旧材料。
2. 任务owner不接受调用者自证的候选结果。W1发布必须准确满足“唯一查询条件
   等于需求目标特征类型”，任务owner重新调用方法服务取得权威候选并逐项相等
   后才允许发布；伪造、漏报或多报候选均拒绝且不改变当前材料。
3. 世界树增加W1窄综合入口：读取任务和需求，只把
   `目标特征类型概念节点`写入`查询.涉及特征类型概念组`，调用现有方法召回，
   核验候选方法身份后由任务owner发布材料。
4. 世界树增加manager专用独立读回和消费入口。完整零候选与方法查询失败分开；
   有候选只进入`待检查条件`，完整零候选只进入`等待条件`，技术错误不写成
   `已失败`。
5. 新增`新_任务工作线程类`，首个用途仅为查找方法。活动容量覆盖排队、处理中
   及已完成但尚未确认交付的工作；同工作号精确重复复用共享结果，同号异义拒绝，
   同一任务同时只允许一个工作。manager完成独立读回后显式确认，worker才释放
   对应容量。
6. worker在自身锁内只完成状态和promise发布；所有完成通知均在解锁后调用，
   通知可以安全重入worker公开快照入口，不携带业务事实。
7. manager持有并启动一个worker，扫描`已建立/待查找方法`任务，先将新任务推进
   至`待查找方法`再异步派发。manager独立消费worker定位，保存每个任务最近一次
   运行期筹办结果；技术失败进入运行期阻塞集合，避免在没有新条件时空转重派。
8. manager将全局扫描结果区分为已派发、无任务、资源暂不可用、停止和内部错误。
   资源失败可中断等待后重试；未初始化、结构不一致和未分类异常进入受控内部
   错误并停止，不再静默定时空转。运行循环异常出口同样先停止、join并收束
   worker及活动工作，再发布manager已完成。
9. manager停止时先停止新增派发，再停止并join worker，消费在途终结结果、确认
   交付，最后终结承接消息并报告停止。worker和manager均不`detach`。
10. 新worker头源已登记到`海中鱼巣.vcxproj`和`.filters`。

运行覆盖：

- 安全根登记一个真实方法后，任务候选材料精确包含该方法并进入`待检查条件`；
- 服务根没有匹配方法时，发布完整空材料并进入`等待条件`；
- 两类结果均由manager经世界树重新读取任务owner材料，不消费worker自报vector；
- 同一工作精确重复复用共享结果，同号异义被拒绝，同任务第二工作被占用拒绝；
- worker结果在manager确认前持续占用容量，确认后释放；
- manager重做同一完整查询时复用原候选材料节点，没有生成第二份候选材料；
- 连续两次替换候选材料后，每次前一材料均不能再读回，任务始终只有一个权威
  当前材料；待回收编码定位完成物理退出后同步删除；
- 调用者伪造“完整零候选”时，任务owner经方法服务重读发现候选不一致，返回
  `结构不一致`且当前材料保持不变；
- worker完成通知会重入`读取快照()`，运行完成且未发生自锁；
- 任务终结后重新启用会清除旧候选材料；
- self、manager、worker均可停止和join，最终活动消息数、活动工作数均为0。

另执行`git diff --check`、工程XML解析、四配置`/utf-8`静态检查和切片差异检查。
manager扫描内部错误及运行循环异常收束完成代码审查与编译，但未做异常注入运行。
未执行全仓构建、生产宿主装配、分配失败注入、跨进程恢复或长时间压力验证。

## 4. 函数级代码知识变更清单

| 函数或类型 | 变化、用途与明确非职责 |
| --- | --- |
| `新任务候选方法材料`及发布DTO | 新增任务owner current-only候选材料；不表达业务优先级、条件成立或方法可执行 |
| `新_任务类::发布候选方法材料(...)` | 新增完整查询结果发布、精确重复复用和当前材料替换；发布前按唯一目标特征类型重新调用方法服务，拒绝调用者自证结果 |
| `新_任务类::获取候选方法材料(...)`、`获取当前候选方法材料(...)` | 新增正式读回；校验材料物理结构和任务关联 |
| `新_任务类::清除候选方法材料(...)` | 用可重试编码定位清除任务当前候选引用和材料节点；不删除候选方法本体 |
| `新_任务类::重新启用任务(...)` | 在终结任务重新进入待查找方法前清除旧候选材料 |
| `新_世界树类::查询可查找方法任务()` | manager专用活动任务窄视图；只返回已建立或待查找方法 |
| `新_世界树类::准备任务查找方法(...)` | 将已建立任务合法推进至待查找方法；其它状态不回退 |
| `新_世界树类::查询任务方法候选并发布(...)` | worker专用W1组合入口；只按目标特征类型宽召回并由任务owner发布 |
| `新_世界树类::读回任务方法候选(...)` | manager专用fresh读回；验证任务、需求、查询范围、完整性和候选身份 |
| `新_世界树类::消费任务方法候选(...)` | 根据正式读回把任务推进至待检查条件或等待条件；查询失败不写业务失败 |
| `新_任务工作线程类::*` | 新增W1线程生命周期、接纳、去重、单任务占用、处理、交付确认、停止和快照 |
| `新_任务管理线程类::实现::尝试派发查找方法()` | 新增活动任务扫描、工作编号分配和单任务派发；区分资源暂不可用与必须停止的内部错误 |
| `新_任务管理线程类::实现::停止工作线程并收束()` | 新增统一worker停止、join、在途结果确认和活动容量收束；供正常停止与异常出口共同调用 |
| `新_任务管理线程类::实现::处理已完成工作(...)` | 新增worker结果定位核验、正式消费、交付确认和技术阻塞分流 |
| `新_任务管理线程类::实现::运行()` | 在既有承接消费循环中接入W1异步派发、结果消费和worker关闭顺序 |
| `新_任务管理线程类::读取最近筹办结果(...)` | 新增运行期current结果读取，供后续self反馈接线；不是永久历史账 |

## 5. 完成边界与下一步

本片证明的是“self已有根需求承接 → manager派发 → worker真实查找 → 任务候选
材料 → manager独立消费”的W1运行链。它尚未把完整零候选或技术缺口主动发送给
self，也未实现W2条件/参数筹办、候选比较、执行前判断、真实方法调用、实际效果
复核和生产宿主装配。因此总目标仍未完成。

下一步应从已有候选材料进入W2：逐候选读取条件结果配对和参数规格，建立明确的
条件/参数缺口结果并回传manager；同时为完整零候选建立manager到self的具名反馈，
不得把空候选当成任务失败。
