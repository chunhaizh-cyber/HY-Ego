## t211u / t212u 机制验收要点

- **统一入口数据流**：`生成关系陈述` → 读关系概念 → 核验主连接+附加连接（边/字段）→ 选目标语言表达关联 → 解析表达根知识（后天节点优先，否则预置尾词）→ 按 `角色槽组` 取材/投影 → `按表达槽构造含义图` → `从基础信息生成可回读单句`（`允许根知识节点组` 真过滤）。
- **已删除专用构图**：`构造组成描述图` / `构造组织隶属图`；不成文按概念 id 分派。
- **知识合同**：角色槽 + `预置知识尾词` + `表达知识节点组`；`附加连接组`；字段 `新_需求类/目标存在`。
- **期望句形（夹具，以 CI 为准）**：组成`…一部分`；属于`…属于…`；需求父子`…子需求`；字段引用含`要`；多连接仍为组成句。
- **不作核心验收**：事实倒置的 slot_swap。
- **仍须代码扩展的边界**：其它 owner/字段键；任意多边图式语言构图；全 1150；正式用户库 E2E。
