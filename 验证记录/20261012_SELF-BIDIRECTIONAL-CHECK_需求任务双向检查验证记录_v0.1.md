## 2. 实际变更

1. 删除数量核对工作种类及相等快捷路径，首次和后续均完整读取需求/任务并双向比对；数量只用于诊断。
2. 任务全集增加根登记与类型全集严格相等核验，不以根登记的子集冒充全部任务。
3. 完整多T/孤立T使用追加状态`已完成但关联异常`，保留完整定位；self整批零补建，确认结果后回空闲，等待后续事件。未完成结果清空数组和数量。
4. 保留shared_future可靠结果通道；self快照追加`最近已消费检查结果`，只保存身份匹配且未作废的最近报告句柄，不复制大数组或累计第二事实账。
5. D/T单订阅通知在三个首次结构写尝试处以RAII触发；复用、任务状态和需求权重变化不触发。回滚/异常也通知“可能变化”，不假称建立成功。
6. 弱桥先置atomic再取桥/self锁唤醒；检查及承接期间合并变化。提交前消耗先前信号，提交后的信号不清除。结果身份先验，再按已知变化作废竞争读结果。
7. 去除无条件收尾复核；无变化时停止扫描，新增任务只合并一次后续检查。
8. 启动前绑定D/T，部分绑定失败撤销；停止join/析构在self锁外断桥、解绑。析构显式回收worker，避免完成回调晚于self状态资源销毁。
9. 日志在self锁外记录有界数量和首个异常定位，不输出整个数组。资源、依赖、硬失败和原承接等待事件政策保持不变。

## 3. 静态核对

以下都是源码及差异审查，不是运行测试：

| 场景 | 源码核对结果 |
| --- | --- |
| D/T总数相同但关联错配 | 不存在数量门；仍构造D→T映射并检查T→D归属 |
| 类型声明T没有根登记、重复声明/根成员、任务不可读 | 全集返回非成功并清空；worker不派发部分缺项 |
| 完整重复/孤立关联且同时存在缺T | self保存报告并整批零补建；不随意修复 |
| 只有缺T | 承接批次完整构造后swap；由self发manager消息 |
| 在途变化、通知等待self锁 | atomic先置位，消费检查pending及atomic；旧报告ack后重查 |
| 没有结构变化 | 完成承接仅在pending/atomic存在时再查，不自激活 |
| 资源/依赖/硬失败 | 继续既有分类；身份不符不能被dirty豁免，ack失败不释放活动身份 |
| 绑定、启动失败、停止、析构 | 解绑不持self锁或桥锁调用owner，弱桥晚到通知安全；通知不得反入owner |
