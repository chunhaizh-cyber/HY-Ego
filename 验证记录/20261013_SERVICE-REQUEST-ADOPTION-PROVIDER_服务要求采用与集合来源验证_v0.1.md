## 2. 实际变更与静态复核

1. 结构化确认提供固定身份、固定语义同义比较和当前语义复核三个入口。固定读取只读 L1/schema，不取业务锁或概念锁；当前语义改变与结构/资源错误分别返回。
2. 需求持有正式确认引用组。受限采用只供 self 使用，父需求与来源任务固定为已核验的结算 D/T；已有普通 D 不追加确认冒充服务要求。同义确认追加、同 C 重复采用、改义拒绝均在同 owner 内处理。
3. 新服务 D 的目标/来源/活动状态/初始权重/确认字段一次原子出生，父链、列表和权重沿现有 owner 发布边界处理。失败清理本次字段/关系并恢复已尝试权重；回滚失败保留实际 D 定位，不伪报成功。发布后的 fresh 失败保留正式身份。
4. 确认 C→采用 D 查询检查唯一来源、父链、列表与结算 T→D 唯一对应；未知 D 是合法空结果，不虚构任务或需求编码。
5. 集合新增必含确认来源任务组，参与排序去重、定义校验、持久读写、更新回滚、零引用清理、值域蕴含和条件 AND 合并。满足要求当前集合中的真实任务指向已采用 D，而不是集合非空。一次左右值域比较复用同 C 的来源读取，避免并发采用导致自比较不等。
6. 新动作入口沿需求祖先链 fresh 核验。方法选择、方向核验、进入待执行、开始执行和实际本能调用前均接入；已经建立 X 尚未进入动作时复用撤销并清理问题暂存。已发生动作的结果收集路径未加此拒绝，不能追溯撤销事实。
7. self 绑定 manager 时配置精确结算 D/T；确认读取端口在线程启动前注入、全部线程 join 后解绑。来源回调不获取任务/需求锁，不引入概念锁到领域锁的反序调用。
8. 独立复核发现的“开始语义拒绝被结算工程失败覆盖”和“同次比较两次读 C 来源”均已在代码中修正。未建立 X 的入口拒绝保持定位已变化；工程结构失败保持独立状态。顶层复核补充修正：运行期采用复核已有来源配置时只读返回，不再次写同值指针/编码，避免与无锁读取竞争。

静态读取不能证明并发运行无死锁或失败注入通过。多次 L1 读取不是跨 owner 原子快照，最后 fresh 检查不锁住之后发生的概念变化。

最终独立快审：两处修复、四文件提供者锁序/来源/祖先检查/失败边界与重复配置无写复核通过，未发现阻断本叶发布的问题。计划所有者仅对第6节消歧，明确定位失效允许沿既有 manager 路径阻塞任务，不承诺自动恢复；不改变生产白名单或机器合同。该段随代码发布保留历史。
