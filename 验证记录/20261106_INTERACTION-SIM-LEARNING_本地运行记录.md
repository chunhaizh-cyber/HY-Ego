结论：不是死锁，是全局任务锁 `新任务互斥`（`领域/新_任务类.cpp:307`）上的长持有与争用。
- `查询服务任务`（:7664）经 `获取因果读取任务锁` 持锁后执行 `读取需求列表任务对应`（:7781），整段完整读取全部需求。
- `读取任务调度材料`（:8243）对每个任务调用 `读取本次场景核验批` → `复核筹办资格`/`读取新增成员目标组` → `判定新增成员来源` → `查询服务任务`，即每次调度读取在任务锁下把全部需求读 N 遍（N 为任务数）。
- 控制面板后台采集线程（`装配.普通应用.cpp:1448 采集完整材料` → `读取任务调度材料`）自行反复走同一路径；两轮最后一次抓栈中它都在该路径内运行。
- 管理线程的因果等待复核与调度扫描都要取同一把锁，`获取因果读取任务锁` 以10毫秒轮询 try_lock，长期抢不到时表现为调度停滞。
