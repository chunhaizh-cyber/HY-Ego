## 定位证据

已发布计时见 `验证记录/20261113_DICT-LANG-SCENE_验证报告.md`：转换区段 128 行 2.09047 秒，1024 行 155.127 秒。行数 8 倍，时间约 74 倍。下面按调用链给出代码结论。整体二次项来自前三项；后几项不是按全库规模的 O(n)。

1. **主因：`基础数据集::原子追加节点组`（`海中鱼巣/核心/基础数据集.cpp`）每次成功发布都复制整库。** 校验之后原实现执行 `候选节点 = 节点_`、`候选字段 = 字段关系_`，并复制所属/目标/入向/字段键四套索引；有外部边时再复制关系表和两套关系索引。然后在副本上插入，最后 `swap`。`std::map` / `std::set` 的复制按当前元素数分配红黑树节点，是 O(当前节点+字段+索引项)。`新_语言类::保存词典语言材料` 每行调用一次该函数。行数增加时库也变大，合计 O(n²)。失败路径丢弃副本，所以这份复制只为异常时不留下半结构；读者本来就被同一把独占锁挡住。
2. **`组织写入现场::保护` 与读回把共享节点的入向边整表拷走。** `保护` 对每个引用调用 `组织读取现场::读` → `查询节点组完整结构` → `读取联合快照已加锁`。后者用 `入向字段索引_` 把目标节点的全部入向字段推进 `入向字段组`。词典材料里的 `说话者词典` 每行都引用同一个存在节点，入向边数随已保存材料增长。保存前保护、追加时再读一遍做 `联合快照相等`、写后 `组织读值`、以及 `读取词典语言材料`（验证入口还会再读一次）都走这条路。这是另一段 O(n) 每次、合计 O(n²)。来源场景的入向只随该义项行数增长，不是全库 n。
3. **`概念_存在类::建立专属存在概念` 每次新建场景都扫描概念图根的全部父子边。** `建立空场景` → `初始化存在节点` → 本函数。循环是 `查询源关系(存在概念图根节点, 父子)`，再对每个子节点读种类和 `对应存在字段`。每个转换调用新建一个场景，场景数随已处理义项增加，合计按场景数二次。空场景本身的 `新建节点` / `添加字段` / `添加关系` 是单次索引插入，不是这段扫描。
4. **`读取词典语言材料` 的 `std::count` 不是全库二次项。** 原代码 `r.字段(来源场景, 词典材料登记)` 只扫该场景节点自己的字段，再数本材料出现一次。登记写在当次 `转换词典义项到语言场景` 新建的场景上，次数是该义项的行数，不是 31758。它仍是该义项内的 O(k²)，规模远小于整表复制。本次仍改成反向索引，避免顺手把场景字段表再走一遍。
5. **`新_词类::按规范化词面查询` 与 `建立或取得词条` 不是线性扫词条。** 两者都走 `词条索引.find`（`海中鱼巣/领域/新_词类.cpp`）。命中后 `读取词条信息` 只对该词条做 `查询字段` / `查询目标关系`。未找到也是一次 map 查找。
6. **`离线词典数据源::精确查询` 不是按行扫包。** `实现_->索引.find`。`转换词典义项到语言场景` 在行循环外调用一次；验证入口每个词头再调用一次。
7. **`基础数据集::查询字段` 不是扫全库。** `所属字段索引_.lower_bound`，复杂度是 O(log N + 该节点该字段的命中数)。变慢的读回没有用它，而是把整个联合快照拷出来再过滤。

## 改动

数据语义不变：仍在独占锁内发布；失败不留下本次插入；预期不符仍拒绝；写后仍把材料解码出来与入参比较。`按结构世代核验` 为假的旧调用者仍做完整联合快照比较。

- `基础数据集::原子追加节点组` 改为就地插入，并用撤销项在失败时抹掉本次节点、字段、关系和替换。分配顺序与原先一致：先新节点，再删字段、替换字段、新节点字段、追加字段、外部边。编码耗尽仍返回资源失败且不回退已分配编码。
- 每个节点增加只存在于 L1 的结构世代（不写入业务字段）。本体字段、入向字段引用、两端外部关系的已提交变化都会推进世代。`查询节点结构世代` 供调用方读取。节点不存在返回空；未登记为 0。
- `基础联合节点快照` 增加 `结构世代` 与 `按结构世代核验`，默认 0 / false。为真时，`原子追加节点组` 只比较世代，不调用 `读取联合快照已加锁`。世代为 0 则预期不符，避免用空边表冒充“无入向”。
- 语言侧 `组织写入现场::保护` 对已登记世代的引用只提交节点身份和世代。世代为 0 时仍退回完整快照。词典材料的写后读回和 `读取词典语言材料` 设 `只读所属字段`：被引用的说话者、场景、词条只 `查询节点` 确认存在，不复制其入向边。登记核对改为 `查询目标字段(材料, 词典材料登记)` 后只数所属节点等于来源场景的项，仍要求恰好一条。
- `建立专属存在概念` 用 `查询目标字段(存在, 对应存在字段)` 找已有概念，再确认它是概念图根下、组织归属角色、种类为专属。新存在没有这种字段时，反向查询为空。重复则仍返回结构不一致。

`原子建立节点组`、`原子比较变更字段组`、`原子建立互引节点`、`原子删除互引节点` 仍复制候选表。它们不在逐行保存路径上；建立节点组只在表达组织句柄初始化时整组调用一次。这些路径在发布成功后补写世代，避免世代核验漏掉它们的结构变化。

## 复杂度

设已提交结构规模为 N，本行新增节点和字段为 Δ（一条释义材料的编码树，不随历史行数增长），词条数为 W。

| 步骤 | 修改前每次 | 修改后每次 |
| --- | --- | --- |
| `原子追加节点组` | O(N) 整表复制 | O(Δ log N) |
| 保护 / 写后读回说话者入向 | O(已保存材料数) | O(log N) 读世代或确认节点存在 |
| `建立专属存在概念` | O(已有专属概念数) | O(log N)，新存在无命中 |
| 场景上 `词典材料登记` 计数 | O(本义项行数) | O(log N + 指向本材料的登记数) |
| 词面查询 / 精确查询 | O(log W) / O(log 词头) | 未改 |

n 行合计从 O(n²) 变为 O(n log n)，再加释义解读和每行固定次数的索引写入。整包是否落在分钟级，要在 Windows 上用真实包重跑，这里不能报一个新秒数。
