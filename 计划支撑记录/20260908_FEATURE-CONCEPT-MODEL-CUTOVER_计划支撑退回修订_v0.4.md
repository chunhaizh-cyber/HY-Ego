## 2. v0.4 裁决

1. 保留 v0.2 特征应用模块的唯一 `特征概念观察请求`；场景模块只引用它，删除同名别义和未定义预算。
2. 场景 owner 只新建自己的 `_v2` 采用意图、请求、F/C/名称分报、新投影、总结果与继续材料；存在结果直接使用现有 provider DTO。
3. 继续材料保存完整场景请求、唯一阶段以及已派发的精确概念/存在 provider 原请求；仅 F 创建 pending 保留 v0.2 已明示的同应用实例限制。
4. 特征概念预算为每个 provider 调用的单次上限，不跨阶段全局累计，不新增剩余预算或用量 DTO；继续重放原预算和原幂等请求。
5. 名称窄读只使用 `概念树预算`：按 F 扣一个世界成员和当前名称关系，按 C 扣一个概念、全部当前名称关系和不同 F 端点；不转发旧共享入口。
6. `概念树存在扩展交付` 只作为两个新 24 角色构造的独立末参数；EC 抽象依据关系与 C 形成依据角色 16/17 及其它角色全部分离。旧 `shared_[15]` 真实节点可被显式交付，但禁止自动推断或重释为新角色。
7. 新最终投影只含 S/E 直接成员、完整 F、C、F→C 名称和可选当前采用，彻底删除旧共享特征实例和联合阶段机。
